# Learnings

- When adding new settings in `Settings.cpp`, you must also add `extern` declarations in every `.cpp` file that uses them via `Setting::name` (e.g., in the `namespace Setting` block in `executeQuery.cpp`, `ClientBase.cpp`).
- Rust crate build targets in ninja have the form `rust/workspace/cargo-build__ch_rust_<name>`, not just `_ch_rust_<name>`.
- In a worktree created by the `create-worktree` skill (submodules hardlinked from the main repo), a plain `git submodule update --init --recursive` can leave submodule working trees **empty** - only the `.git` file remains, and the submodule index records every file as deleted. `git submodule status` still reports everything as up to date, so the damage only surfaces later as `CMake Error: File contrib/<x>/... does not exist`. Repair with `git submodule foreach --recursive 'git checkout -f HEAD'`. The same event also deleted 200+ tracked files from the superproject working tree; `git checkout-index -a -f` restores those.
- The std-container style check is `ci/jobs/scripts/check_style/check_cpp.sh`, check `08`. It enforces per directory via the `directories_to_lint_std_containers_usages` array, matched as `grep "/$dir/"` - so an entry is **recursive** and a parent directory can only be added once every subdirectory is clean. It covers all of `deque list map multimap multiset queue set unordered_map unordered_multimap unordered_multiset unordered_set vector`, not just `vector`, and `STYLE_CHECK_ALLOW_STD_CONTAINERS` on a line exempts it.
