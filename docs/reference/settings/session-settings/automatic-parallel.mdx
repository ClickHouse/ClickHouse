## automatic_parallel_replicas_ignore_thresholds {#automatic_parallel_replicas_ignore_thresholds}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "New setting: for testing, ignore the reading-thread cap of the automatic parallel replicas cost model so that small reads are decided by the comparison rather than short-circuited by the cap."}]}]}/>

For testing of the automatic parallel replicas cost model - ignore the cap on how many threads a read can usefully occupy (derived from `merge_tree_min_bytes_per_task_for_remote_reading`), which otherwise clamps both sides of the comparison to the same value for a read too small to occupy `max_threads`, so that the comparison collapses to `0 > output_bytes / replicas` and the query is decided before the cost model is consulted.

It deliberately does NOT touch `automatic_parallel_replicas_min_bytes_per_replica`: set that to 0 to disable that gate, which is what it is for. Nor does it change read task sizing, or suppress the recollection of statistics that have drifted - a decision made on stale statistics is not a decision made by the cost model.

## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "Automatic parallel replicas now declines a query that would repeat more than half of its reading on every replica. Previously there was no limit, which is what 1 still asks for."}]}]}/>

How much of a query's read volume may be read by every replica instead of being split between them, as a
fraction of the whole, before automatic parallel replicas declines the query.

Only the read parallel replicas coordinate is split; every other read of the same subtree runs on each
replica in full. Those reads take the same wall-clock time either way, so the cost-model comparison is blind
to them, but the cluster performs `max_parallel_replicas` times as much work for them. This setting is the
limit on that waste: at the default 0.5 a query whose coordinated read is less than half of what it reads
keeps running on one node, however the time comparison turns out.

Set to 1 to accept any amount of duplicated reading, which restores the behaviour of only comparing times.

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "New setting"}]}]}/>

Enable automatic switching to execution with parallel replicas based on collected statistics. Requires `enable_parallel_replicas = 1`, `parallel_replicas_local_plan = 1` and providing `cluster_for_parallel_replicas`. With `enable_parallel_replicas = 2` parallel replicas are forced and the automatic mode is not applied.
0 - disabled, 1 - enabled, 2 - only statistics collection is enabled (switching to execution with parallel replicas is disabled).

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "New setting. Automatic parallel replicas now remembers the boundary of the replicas' share of the work per query plan; previously every query built the plan with parallel replicas to find it."}]}]}/>

Lets automatic parallel replicas remember, per query plan, where the replicas' share of the work ends, so that a
repeated query whose statistics decline parallel replicas is decided without building the plan with parallel
replicas.

Disable it to make every query pay the full cost of the decision, e.g. when benchmarking that cost.

## automatic_parallel_replicas_statistics_drift_ratio {#automatic_parallel_replicas_statistics_drift_ratio}

<SettingsInfoBlock type="Float" default_value="1.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1.5"},{"label": "New setting. The ratio was 2 and could not be changed; statistics are now recollected sooner as the data changes."}]}]}/>

How much the rows a read selects may differ from the rows it selected when automatic parallel replicas collected its
statistics, as the ratio of the larger to the smaller, before the statistics are considered stale and collected again
instead of being decided on.

The rows are the ones the initiator's index analysis selects, so pruning that only the replicas do while reading (for
example by their own query condition caches) is not seen. A lower ratio recollects the statistics sooner as the table
changes. Should be greater than 1.
