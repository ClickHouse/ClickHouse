## Syntax {#dictionary-sources}

<CloudDetails />

A dictionary can be connected to ClickHouse from many different sources.
The source is configured in the `source` section for configuration file and using the `SOURCE` clause for DDL statement.

<Tabs>
<Tab title="DDL">

```sql
CREATE DICTIONARY dict_name (...)
...
SOURCE(SOURCE_TYPE(param1 val1 ... paramN valN)) -- Source configuration
...
```

</Tab>
<Tab title="Configuration file">

```xml
<clickhouse>
  <dictionary>
    ...
    <source>
      <source_type>
        <!-- Source configuration -->
      </source_type>
    </source>
    ...
  </dictionary>
  ...
</clickhouse>
```

</Tab>
</Tabs>

<br/>

- [HTTP(S)](/reference/statements/create/dictionary/sources/http)
- DBMS
  - [ODBC](/reference/statements/create/dictionary/sources/odbc)
  - [MySQL](/reference/statements/create/dictionary/sources/mysql)
  - [ClickHouse](/reference/statements/create/dictionary/sources/clickhouse)
  - [MongoDB](/reference/statements/create/dictionary/sources/mongodb)
  - [Redis](/reference/statements/create/dictionary/sources/redis)
  - [Cassandra](/reference/statements/create/dictionary/sources/cassandra)
  - [PostgreSQL](/reference/statements/create/dictionary/sources/postgresql)
  - [YTsaurus](/reference/statements/create/dictionary/sources/ytsaurus)
- [YAMLRegExpTree](/reference/statements/create/dictionary/sources/yamlregexptree)
- [Null](/reference/statements/create/dictionary/sources/null)

For source types [Local file](/reference/statements/create/dictionary/sources/local-file), [Executable file](/reference/statements/create/dictionary/sources/executable-file), [HTTP(s)](/reference/statements/create/dictionary/sources/http), [ClickHouse](/reference/statements/create/dictionary/sources/clickhouse)
optional settings are available:

```sql highlight={2}
SOURCE(FILE(path './user_files/os.tsv' format 'TabSeparated'))
SETTINGS(format_csv_allow_single_quotes = 0)
```

</Tab>

```xml highlight={7}
  <file>
    <path>/opt/dictionaries/os.tsv</path>

  </file>
  <settings>
      <format_csv_allow_single_quotes>0</format_csv_allow_single_quotes>
  </settings>
</source>
```

## Column order of a custom query {#custom-query-column-order}

The [ClickHouse](/reference/statements/create/dictionary/sources/clickhouse),
[MySQL](/reference/statements/create/dictionary/sources/mysql),
[PostgreSQL](/reference/statements/create/dictionary/sources/postgresql) and
[ODBC](/reference/statements/create/dictionary/sources/odbc) sources accept a `query` field that
replaces the query ClickHouse would otherwise build from `table` and `where`.

A dictionary expects the columns of that result in a fixed order, which is not the order the
attributes are written in the `CREATE DICTIONARY` statement:

1. the key column(s), in `PRIMARY KEY` order;
2. for a [`range_hashed`](/reference/statements/create/dictionary/layouts/range-hashed) or
   `complex_key_range_hashed` dictionary, the `range_min` column, then the `range_max` column;
3. the remaining attributes, in the order they are declared.

The ClickHouse source matches the result to that order by column name, so with it the order of
the `query` does not matter as long as every column is named after the attribute it fills. The
MySQL, PostgreSQL and ODBC sources take the columns by position, so with those a `query` whose
columns are in any other order loads values into the wrong attributes. Depending on the types
involved, the dictionary either fails to load with a conversion error or stores wrong values, so
write the `query` in the order above:

```sql
CREATE DICTIONARY contracts (
    meter_no String,
    id Int64,
    contract_time Date,
    end_date Date
)
PRIMARY KEY meter_no
-- The key comes first, then the range columns, then the remaining attributes.
SOURCE(POSTGRESQL(... query 'SELECT meter_no, contract_time, end_date, id FROM contracts'))
LAYOUT(RANGE_HASHED())
RANGE(MIN contract_time MAX end_date)
LIFETIME(300)
```
