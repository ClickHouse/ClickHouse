## Description {#description}

Contains information about the databases that are available to the current user.

## Columns {#columns}

{/*AUTOGENERATED_START*/}
- `name` ([String](/reference/data-types/string)) — Database name.
- `engine` ([String](/reference/data-types/string)) — Database engine.
- `data_path` ([String](/reference/data-types/string)) — Data path.
- `metadata_path` ([String](/reference/data-types/string)) — Metadata path.
- `uuid` ([UUID](/reference/data-types/uuid)) — Database UUID.
- `engine_full` ([String](/reference/data-types/string)) — Parameters of the database engine.
- `comment` ([String](/reference/data-types/string)) — Database comment.
- `is_external` ([UInt8](/reference/data-types/int-uint)) — Database is external (i.e. PostgreSQL/DataLakeCatalog).

**Aliases:**

- `database` — Alias for `name`.
{/*AUTOGENERATED_END*/}

## UDT authority diagnostics {#udt-authority-diagnostics}

For an Atomic database with user-defined type (UDT) authority, the `udt_verification_*`, `udt_quota_*`, and `udt_root_*` columns expose bounded database-owned diagnostics. Other database engines return the documented unavailable state and zero or empty values.

`udt_verification_last_root_*` identifies the last exact authority root observed by the scheduler. `udt_verification_last_successful_root_*` identifies the last root accepted by either a clean scheduled batch or quarantine-release re-verification; it does not by itself assert that one scheduled batch covered every object in the root. An anchor is meaningful only together with its catalog epoch.

When `udt_verification_last_repair_provenance_available` is `1`, the repair transaction, source counts, damaged-artifact manifest digest, and previous/repaired root identities come from authenticated schema-WAL provenance and survive restart and WAL compaction. Digest columns never contain canonical metadata or normalized literal payloads.

Effective verification limits report the exact scheduler configuration owned by the active database scheduler. They are zero when scheduler status is unavailable. The `udt_quota_verification_*` values paired with `udt_quota_limit_verification_*` are instead the exact immutable-root requirements and their admission ceilings for targets, buckets, indivisible-target canonical bytes, work, transient bytes, I/O, and deterministic-planner work, scratch, and retained bytes. Quota values and admission limits come from one immutable current authority-root snapshot.

The paired quota suffixes have the following meanings:

| Suffix | Exact immutable-root quantity |
|---|---|
| `targets` | Inventory targets in the database |
| `buckets` | Deterministic verification buckets |
| `canonical_bytes` | Canonical-byte execution requirement for one indivisible rooted target |
| `work_units` | Verifier-work requirement for one indivisible rooted target |
| `transient_bytes` | Transient-byte requirement for one indivisible rooted target |
| `io_bytes` | I/O-byte requirement for one indivisible rooted target |
| `planner_work_units` | Deterministic planning work |
| `planner_scratch_bytes` | Deterministic planning scratch bytes |
| `retained_bytes` | Canonical bytes retained by resumable planning |

After a quota decrease, the snapshot and bucket topology, rooted-target, and deterministic-planner execution domains can be widened only to the requirements encoded by the already-published immutable root, so that the root remains verifiable; aggregate batch ceilings remain lowered. This process-local execution escape does not change the rooted quota usage or admission ceilings: `OVER_QUOTA` blocks net growth without discarding that root.

Rows retain the ordinary `system.databases` access rule: the user must be able to see the database. These diagnostics expose bounded counters, states, identities, and digests, not object names, type definitions, sidecars, SQL text, or repair bytes.

The `name` column from this system table is used for implementing the `SHOW DATABASES` query.

## Example {#example}

Create a database.

```sql title="Query"
CREATE DATABASE test;
```

Check all of the available databases to the user.

```sql title="Query"
SELECT * FROM system.databases;
```
