## Description {#description}

Contains experimental [user-defined type](/reference/statements/create/type) definitions from Atomic databases. Rows are visible only when the current user has `SHOW TYPES` for the database.

The table reads one immutable lifecycle snapshot per database. A normally recovered definition has status `ACTIVE`, `QUARANTINED`, or `OVER_QUOTA`. If startup cannot publish a complete executable authority root, diagnostic-only rows can instead have status `CONFLICTED`, `INVALID`, or `INCOMPLETE`. Such rows never make the definition executable.

`last_error` contains only a bounded stable diagnostic. It does not expose canonical metadata, literal values, or parser error payloads.

Database-wide verification and quarantine state, cooperative scheduler counters, the last observed root and last root accepted by a clean verification outcome, effective resource limits, and authenticated durable provenance for the last exact repair are exposed by [`system.databases`](/operations/system-tables/databases). The current table-level verification-stamp root and object revision are exposed by [`system.tables`](/operations/system-tables/tables). Their column references are generated from the registered system-table sources.

## Example {#example}

```sql
SELECT
    database,
    name,
    uuid,
    revision,
    underlying_type,
    status,
    last_error
FROM system.user_defined_types
ORDER BY database, name, uuid, revision;
```
