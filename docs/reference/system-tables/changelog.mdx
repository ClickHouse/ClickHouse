## Description {#description}

Contains the entries of the curated ClickHouse changelog (the repository's `CHANGELOG.md`), one row per entry, so release notes can be queried with SQL.

## Columns {#columns}

{/*AUTOGENERATED_START*/}
- `version` ([Tuple(major UInt16, minor UInt8, patch UInt16)](/reference/data-types/tuple)) — Version of the release the entry belongs to, as a comparable tuple. The curated changelog describes feature releases, so `patch` is 0.
- `release_date` ([Date](/reference/data-types/date)) — Date of the release.
- `is_lts` ([UInt8](/reference/data-types/int-uint)) — 1 if the release is a long-term support release.
- `category` ([LowCardinality(String)](/reference/data-types/lowcardinality)) — Changelog section the entry belongs to, e.g. 'New Feature', 'Performance Improvement', 'Bug Fix'.
- `description` ([String](/reference/data-types/string)) — Text of the changelog entry.
- `pull_requests` ([Array(UInt32)](/reference/data-types/array)) — Numbers of the pull requests the entry references.
- `authors` ([Array(String)](/reference/data-types/array)) — Authors of the referenced pull requests.
{/*AUTOGENERATED_END*/}

## Example {#example}

Find recent JSON-related changes, newest release first:

```sql
SELECT version, category, description
FROM system.changelog
WHERE description ILIKE '%JSON%' AND version >= (26, 1, 0)
ORDER BY version DESC
LIMIT 3
```
