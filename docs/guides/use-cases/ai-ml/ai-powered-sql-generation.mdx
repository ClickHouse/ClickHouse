[ClickHouse Client](/concepts/features/interfaces/client) and [clickhouse-local](/concepts/features/tools-and-utilities/clickhouse-local) include an [AI assistant](/concepts/features/interfaces/client#ai-sql-generation) that turns questions in natural language into SQL queries, runs them on your connection, and answers from their results. You ask a question by prefixing it with `?` at the interactive prompt.

The assistant is an agent: rather than generating one query blindly, it works towards the answer step by step with the help of the following tools:

* `list_databases` - list the databases of the server
* `list_tables` - list the tables of a database
* `show_create_table` - read the `CREATE TABLE` statement of a table
* `consult_documentation` - look an entity up in the embedded documentation (the `system.documentation` table)
* `read_query_log` - read your earlier queries from `system.user_query_log`
* `run_readonly_query` - run a read-only query without asking, under a sandbox (`readonly = 1`, a 30-second and a 10 GiB limit)
* `run_query` - run any other query, after you confirm it

It is also given the last queries you ran in the session, with their results truncated and their error messages, so you can ask about "my last query" or "that error". The queries it runs are displayed and executed in your terminal exactly as if you typed them. See the [reference](/concepts/features/interfaces/client#ai-sql-generation-usage) for what exactly each tool is allowed to do.

## Prerequisites {#prerequisites}

The assistant needs a model provider. The quickest way is an Anthropic or OpenAI key in an environment variable:

```bash
export ANTHROPIC_API_KEY=your_api_key
# or
export OPENAI_API_KEY=your_api_key
```

Alternatively, you can [provide a configuration file](/concepts/features/interfaces/client#ai-sql-generation-configuration). When neither is set, the assistant uses the [`aiGenerate`](/sql-reference/functions/ai-functions) function of the server you are connected to, if its administrator has enabled AI functions - see [providers](/concepts/features/interfaces/client#ai-sql-generation-providers).

## Connecting to the ClickHouse SQL playground {#connecting-to-the-clickhouse-sql-playground}

We're going to explore this feature using the [ClickHouse SQL playground](https://sql.clickhouse.com/).

We can connect to the ClickHouse SQL playground using the following command:

```bash
clickhouse client -mn \
--host sql-clickhouse.clickhouse.com \
--secure \
--user demo --password ''
```

<Note>
We'll assume you have ClickHouse installed, but if not, refer to the [installation guide](/get-started/setup/install)
</Note>

## Asking ClickHouse questions in natural language {#asking-clickhouse-questions-in-natural-language}

Now it's time to start asking some questions!

### Finding expensive housing markets {#finding-expensive-housing-markets}

Let's start by asking a question about house prices. The SQL playground contains a UK house prices dataset, which the assistant discovers on its own:

```sql
? Can you tell me the most expensive place to buy a house in 2021?
```

Once we press enter, the assistant prints its tool calls and its thoughts as it works. The output looks like this (shortened):

```text
⚙ list_databases

⚙ show_create_table (database: uk, table: uk_price_paid)
  ✓ CREATE TABLE uk.uk_price_paid (`price` UInt32, `date` Date, `postcode1` LowCardinality(String), ...
The uk_price_paid table has the prices and the locations. Let me average the prices per town for 2021.

:) SELECT town, district, county, round(avg(price), 2) AS avg_price, count() AS total_sales
```

The assistant followed these steps:

1. Schema discovery - it explored the databases and the tables of the relevant one
2. Table analysis - it read the structure of the `uk_price_paid` table
3. Query execution - it ran a query built from your question and the schema it discovered. The query only reads an ordinary table, so it ran as a read-only query without asking, and its result is displayed as if you had typed it
4. Answer - it read the result and answered the question

### Asking follow-up questions {#finding-expensive-properties-in-greater-london}

The conversation keeps its context between questions in the same session, so a follow-up does not have to repeat what was already said, and the assistant does not have to discover the schema again:

```sql
? What about Greater London, across the years?
```

```text
The same table has the county. Let me break the Greater London prices down by district and year.

:) SELECT district, toYear(date) AS year, round(avg(price), 2) AS avg_price, count() AS total_sales
   FROM uk.uk_price_paid
   WHERE county = 'GREATER LONDON'
   GROUP BY district, year
   HAVING total_sales >= 10
   ORDER BY avg_price DESC
   LIMIT 10
```

### Queries that change data {#queries-that-change-data}

The assistant runs only read-only queries on its own. Anything else - writes, DDL, `SET`, or a read that can reach outside of the server, such as a table function or a table of an external engine - is shown at the prompt first, and runs only after you confirm it:

```text
Run this query? [Y/n]
```

The assistant acts with the permissions of your connection, so it cannot do anything you could not do yourself. On the SQL playground the `demo` user is read-only, so such queries fail there even when confirmed.
