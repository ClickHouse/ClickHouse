# Keeper `ListWithOptions` pagination {#keeper-listwithoptions-pagination}

ClickHouse Keeper `ListWithOptions` can resume a direct-child listing from a lexicographic cursor.

Set `start_after` on `ListOptions`, including to an empty string for the first page. The response contains names strictly greater than the cursor, in lexicographic order, truncated to `max_results` when that limit is set. `truncated` is computed after the cursor and the filter.

Leave `start_after` unset to keep the previous unordered `max_results` prefix.

## Constraints {#constraints}

- `shuffle` or `recursive` together with `start_after` is rejected.
- On a paginated listing, `with_data` and `with_stat` are filled only for the names on that page.
- The listing is not a snapshot: creates at or below the cursor, and deletes between pages, can be missed.
- Cursor pagination requires every Keeper replica to support it. Upgrade the whole Keeper cluster first, then enable `list_with_options_v2`. Until then, leave `start_after` unset. The ClickHouse client rejects the cursor if the cluster does not advertise the feature.

## Example {#example}

```cpp
Coordination::ListOptions options;
options.max_results = 1000;
options.start_after = ""; // first lexicographic page

while (true)
{
    auto page = zookeeper.asyncListWithOptions(path, options).get();
    // use page.names
    if (!page.truncated)
        break;
    options.start_after = page.names.back();
}
```
