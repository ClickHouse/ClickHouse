Use this overview as the entry point for diagnosing and optimizing ClickHouse queries. It introduces the optimization framework, explains the recommended workflow, and links to guides for finding slow queries, isolating bottlenecks, and applying measured improvements.

## When to optimize queries {#understand-query-performance}

The best moment to think about performance optimization is when you're setting up your [data schema](/guides/clickhouse/data-modelling/schema-design) before ingesting data into ClickHouse for the first time.

But let's be honest; it is difficult to predict how much your data will grow or what types of queries will be executed.

If you have an existing deployment with a few queries that you want to improve, the first step is understanding how those queries perform and why some execute in a few milliseconds while others take longer.

ClickHouse has a rich set of tools to help you understand how your query is getting executed and the resources consumed to perform the execution.

In this section, we will look at those tools and how to use them.

## How ClickHouse processes a query {#general-considerations}

To understand query performance, let's look at what happens in ClickHouse when a query is executed.

The following part is deliberately simplified and takes some shortcuts; the idea here isn't to drown you with details but to get you up to speed with the basic concepts. For more information you can read about [query analyzer](/guides/clickhouse/performance-and-monitoring/analyzer).

From a very high-level standpoint, ClickHouse processes a query in four stages:

<Steps>
<Step title="Parse and analyze the query" id="parse-and-analyze-the-query">
ClickHouse parses and analyzes the query, then creates a generic query execution plan.
</Step>

<Step title="Optimize the query plan" id="optimize-the-query-plan">
ClickHouse optimizes the query execution plan, prunes unnecessary data, and builds a query pipeline from the plan.
</Step>

<Step title="Execute the query pipeline" id="execute-the-query-pipeline">
ClickHouse reads and processes data in parallel, including filtering, aggregation, and sorting.
</Step>

<Step title="Prepare the result" id="prepare-the-result">
ClickHouse merges, sorts, and formats the result before sending it to the client.
</Step>
</Steps>

In reality, many [optimizations](/get-started/about/why-clickhouse-is-so-fast) are taking place, and we will discuss them a bit more in this guide, but for now, those main concepts give us a good understanding of what is happening behind the scenes when ClickHouse executes a query.

With this high-level understanding, let's examine the tooling ClickHouse provides and how we can use it to track the metrics that affect query performance.

## Optimization framework {#optimization-framework}

Approach query optimization in three layers:

1. Start with efficient fundamentals, including appropriate data types and avoiding unnecessary `Nullable` columns.
2. Filter efficiently so that ClickHouse reads only the data required by the query.
3. Move repeatable work from query time to ingestion time when appropriate, for example with materialized views.

The diagnostic guides in this section focus primarily on the second layer. They help you identify how much data a query reads and which part of the query warrants further investigation before you choose an intervention.

## Optimization workflow {#optimization-workflow}

Use the following workflow when investigating a slow query:

1. Identify a recurring slow query.
2. Record a reproducible baseline.
3. Compare simplified forms of the query to isolate expensive execution stages.
4. Select an optimization that addresses the measured bottleneck.
5. Apply one change.
6. Run the same measurement again and compare the results.

Query optimization starts with understanding where a query spends its time. Instead of applying several changes at once, establish a baseline, isolate the dominant source of work, apply one targeted change, and measure again.
