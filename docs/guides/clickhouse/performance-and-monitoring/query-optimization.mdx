Use this overview as the entry point for diagnosing and optimizing ClickHouse queries. The guides in this section follow a common workflow: identify a recurring slow query, isolate the work responsible for its latency, and validate a targeted optimization.

## When to optimize queries {#understand-query-performance}

Consider query performance when designing a schema, but expect workloads and data volumes to change. For an existing deployment, begin by measuring how a recurring query performs before changing the query or schema.

## How ClickHouse processes a query {#general-considerations}

At a high level, ClickHouse processes a query in four stages:

<Steps>
<Step title="Parse and analyze the query" id="parse-and-analyze-the-query">
ClickHouse parses and analyzes the query, then creates a query execution plan.
</Step>

<Step title="Optimize the query plan" id="optimize-the-query-plan">
ClickHouse optimizes the plan, prunes unnecessary data, and builds a query pipeline.
</Step>

<Step title="Execute the query pipeline" id="execute-the-query-pipeline">
ClickHouse reads and processes data in parallel, including filtering, aggregation, and sorting.
</Step>

<Step title="Prepare the result" id="prepare-the-result">
ClickHouse merges, sorts, and formats the result before returning it to the client.
</Step>
</Steps>

For more detail, see the [query analyzer](/guides/clickhouse/performance-and-monitoring/analyzer) and [query execution](/guides/clickhouse/performance-and-monitoring/understanding-query-execution-with-the-analyzer) guides.

## Optimization framework {#optimization-framework}

Approach query optimization in three layers:

1. Minimize the data footprint with appropriate data types and schema design.
2. Filter efficiently so that ClickHouse reads only the data required by the query.
3. Move repeatable work to ingestion time when appropriate, for example with materialized views.

## Optimization workflow {#optimization-workflow}

1. Identify a recurring slow query.
2. Record a reproducible baseline.
3. Compare progressively simpler forms of the query to isolate the likely bottleneck.
4. Select an optimization that addresses the measured bottleneck.
5. Apply one change.
6. Repeat the measurement and compare the results.
