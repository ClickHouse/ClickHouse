## How it works {#how-it-works}

Understand what `system.query_log` records, where query history is stored, and how query logs and `EXPLAIN` provide different evidence about a slow query.

## Diagnose a slow query {#diagnose-a-slow-query}

### Find recurring slow-query patterns {#identify-candidate-queries}

Query local or cluster-wide history to find patterns with high duration or resource usage.

### Choose a representative run {#choose-a-representative-query-run}

Compare several runs of the same normalized query pattern and select one that represents its typical behavior.

### Review duration and resource usage {#review-duration-and-resource-usage}

Compare duration, rows and bytes read, and memory usage across runs of the same query pattern.

### Compare rows read with table size {#compare-rows-read-with-table-size}

Use rows read as an initial indication of whether the query scans more data than expected.

### Inspect the query plan {#explain-statement}

Use `EXPLAIN` to validate the initial hypothesis before changing the query or schema.

#### Inspect index use {#inspect-index-use}

Review the parts and granules selected by the query.

#### Inspect the query pipeline {#inspect-query-pipeline}

Review the pipeline shape and parallelism used to execute the query.

## Interpret the evidence {#interpret-the-evidence}

Combine query-log measurements with the query plan to decide which part of the query warrants a controlled comparison.
