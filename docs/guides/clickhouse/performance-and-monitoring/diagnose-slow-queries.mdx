## How it works {#how-it-works}

This section will introduce `system.query_log`, cluster-wide and single-node query history, representative query runs, and `EXPLAIN`.

## Diagnose a slow query {#diagnose-a-slow-query}

### Identify candidate queries {#identify-candidate-queries}

Find recurring queries with high duration or resource usage.

### Choose a representative query run {#choose-a-representative-query-run}

Compare several runs of the same normalized query pattern and select one that represents its typical behavior.

### Compare rows read with table size {#compare-rows-read-with-table-size}

Use rows read as an initial indication of whether the query scans more data than expected.

### Inspect the execution plan {#explain-statement}

Use `EXPLAIN` to validate the initial hypothesis before changing the query or schema.

#### Inspect index use {#inspect-index-use}

Review the parts and granules selected by the query.

#### Inspect the query pipeline {#inspect-query-pipeline}

Review the pipeline shape and parallelism used to execute the query.
