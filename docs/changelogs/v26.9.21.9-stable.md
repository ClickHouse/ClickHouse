# 2026 Changelog

### ClickHouse release v26.9.21.9-stable (2a96c27fd3b) FIXME as compared to v26.9.20.23-stable (579d61a37c0)

#### Backward Incompatible Change
* Backported in [#126379](https://github.com/ClickHouse/ClickHouse/issues/126379): `CREATE TABLE x AS src` inherits the credentials embedded in the engine of `src`, which are masked in `SHOW CREATE TABLE`. It now requires the `SELECT` privilege on `src` when the inherited definition can carry credentials, instead of only `SHOW COLUMNS`. [#118866](https://github.com/ClickHouse/ClickHouse/pull/118866) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Improvement
* Backported in [#126382](https://github.com/ClickHouse/ClickHouse/issues/126382): Reduced the memory usage of incremental `BACKUP`: the base backup keeps only the sizes and checksums of its files instead of the full information about each file. For a base backup of millions of files this saves gigabytes. [#125717](https://github.com/ClickHouse/ClickHouse/pull/125717) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#126324](https://github.com/ClickHouse/ClickHouse/issues/126324): Compare TOTP codes and `plaintext_password` passwords in constant time, so that the response time does not depend on how many leading characters are correct or on which time window matched. [#125785](https://github.com/ClickHouse/ClickHouse/pull/125785) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#126256](https://github.com/ClickHouse/ClickHouse/issues/126256): The nodes in the output of `EXPLAIN AST graph = 1` are numbered sequentially instead of being identified by memory addresses, so the output is the same on every run. [#126031](https://github.com/ClickHouse/ClickHouse/pull/126031) ([Raúl Marín](https://github.com/Algunenano)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126281](https://github.com/ClickHouse/ClickHouse/issues/126281): Requesting SSH-key authentication over the native protocol no longer reveals whether the named user exists, or how it authenticates, before its signature is checked. [#121704](https://github.com/ClickHouse/ClickHouse/pull/121704) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Backported in [#126401](https://github.com/ClickHouse/ClickHouse/issues/126401): Reject CR and LF characters in values sent as HTTP headers or in the request line of outgoing HTTP requests (BigQuery, YTsaurus, `url`, DataLake catalogs, GCP OAuth, AI functions, S3 storage class), which could be used to inject headers or additional requests. [#124905](https://github.com/ClickHouse/ClickHouse/pull/124905) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#126351](https://github.com/ClickHouse/ClickHouse/issues/126351): The setting `http_zlib_compression_level` now applies only to the `gzip` and `deflate` HTTP response compression. The level of other methods (`zstd`, `lz4`, `br`, `xz`, `bz2`) is controlled by `output_format_compression_level`. Previously, a level suitable for zlib was passed to every method, which could make `lz4` unexpectedly slow or make `xz` fail. [#125899](https://github.com/ClickHouse/ClickHouse/pull/125899) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#126276](https://github.com/ClickHouse/ClickHouse/issues/126276): Use node ids instead of addresses in pipeline diagnostics. [#126029](https://github.com/ClickHouse/ClickHouse/pull/126029) ([Raúl Marín](https://github.com/Algunenano)).
