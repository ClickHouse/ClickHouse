# 2026 Changelog

### ClickHouse release v26.8.20.9-lts (68170c6e704) FIXME as compared to v26.8.19.9-lts (2ea9c3c9e37)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124151](https://github.com/ClickHouse/ClickHouse/issues/124151): `ALTER TABLE ... MODIFY SETTING disk = disk(...)` could register a disk defined in SQL whose local path is outside `custom_local_disks_base_directory`, and create its directory, bypassing the check that `CREATE TABLE` applies. Now it is rejected the same way, and a statement rejected this way leaves no disk and no directory behind. [#119850](https://github.com/ClickHouse/ClickHouse/pull/119850) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#124182](https://github.com/ClickHouse/ClickHouse/issues/124182): Rewriting the body of a view with `ALTER TABLE ... MODIFY QUERY` now needs the same grants as creating it with its SQL security: `SET DEFINER` on the definer of a `SQL SECURITY DEFINER` view, or `ALLOW SQL SECURITY NONE` for a `SQL SECURITY NONE` view. An `ON CLUSTER MODIFY QUERY` fails with `UNKNOWN_TABLE` unless it runs on a host that has the view. [#121629](https://github.com/ClickHouse/ClickHouse/pull/121629) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#124190](https://github.com/ClickHouse/ClickHouse/issues/124190): Put "WRITE" operation in delta lake catalog. [#123543](https://github.com/ClickHouse/ClickHouse/pull/123543) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#124311](https://github.com/ClickHouse/ClickHouse/issues/124311): Fix `Found patch part ... that intersects mutation with version ...` on lightweight updates in a table created with `CREATE TABLE ... CLONE AS` or `ATTACH PARTITION ALL FROM` a table with lightweight updates. [#123620](https://github.com/ClickHouse/ClickHouse/pull/123620) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#124336](https://github.com/ClickHouse/ClickHouse/issues/124336): Fix `UNKNOWN_IDENTIFIER` in the analyzer when a table is referenced as `database.table` in `FROM` or `JOIN` and another table expression in the same query uses that database name as its alias, for example `FROM db.t1 AS db INNER JOIN db.t2 AS t ON ...`. Closes [#122239](https://github.com/ClickHouse/ClickHouse/issues/122239). [#124262](https://github.com/ClickHouse/ClickHouse/pull/124262) ([Dmitry Novik](https://github.com/novikd)).
* Fix `iceberg_tolerate_conflicting_manifest_schemas` being reverted to `false` by `compatibility` settings of 26.8 or 26.9 on 26.8 servers, which made Iceberg reads fail with `ICEBERG_SPECIFICATION_VIOLATION` on tables whose manifest schemas conflict with `metadata.json`. [#124317](https://github.com/ClickHouse/ClickHouse/pull/124317) ([Asya Shneerson](https://github.com/asya-ch)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#124253](https://github.com/ClickHouse/ClickHouse/issues/124253): Fix container existence check during `RESTORE` of a lightweight snapshot from Azure Blob Storage by parsing the saved namespace into container name and prefix. [#122697](https://github.com/ClickHouse/ClickHouse/pull/122697) ([Garrett Thomas](https://github.com/garrettthomaskth)).
* Backported in [#124204](https://github.com/ClickHouse/ClickHouse/issues/124204): Reduced the setup of the `04510_distributed_final_many_partitions` test from 150 to 65 partitions. [#124088](https://github.com/ClickHouse/ClickHouse/pull/124088) ([Groene AI](https://github.com/groeneai)).
