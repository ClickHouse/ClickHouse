# 2026 Changelog

### ClickHouse release v26.8.50.9-lts (f20c662da75) FIXME as compared to v26.8.49.6-lts (9c34133c0b8)

#### Performance Improvement
* Backported in [#134980](https://github.com/ClickHouse/ClickHouse/issues/134980): Reduced CPU usage when many threads schedule jobs into a full thread pool, for example while loading many tables at server startup. [#129010](https://github.com/ClickHouse/ClickHouse/pull/129010) ([Nikolay Degterinsky](https://github.com/evillique)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134626](https://github.com/ClickHouse/ClickHouse/issues/134626): Fixed silent row loss when a `MergeTree` table with a projection is read with a `WHERE` in which an `AND` is used with negative polarity, under a `NOT`, as an operand of a comparison, or as the branch condition of `if`/`multiIf`/`CASE`, and one of that `AND`'s conjuncts references a column the projection does not store. [#120286](https://github.com/ClickHouse/ClickHouse/pull/120286) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135191](https://github.com/ClickHouse/ClickHouse/issues/135191): Fixed a bug where `REVOKE GRANT OPTION FOR` was accepted but then omitted from `SHOW GRANTS`, from `system.grants`, and from the persisted access metadata whenever another revoked database, table, column, or named-collection name shared a prefix with it. The grant option therefore came back after a server restart, and the user could pass it on with `GRANT CURRENT GRANTS`. [#122078](https://github.com/ClickHouse/ClickHouse/pull/122078) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135214](https://github.com/ClickHouse/ClickHouse/issues/135214): Fixed an exception (`BAD_GET` or `NOT_IMPLEMENTED`) when a filter on a table with a `_part_offset` projection had a `Float` or `Nullable(Nothing)` condition over a column the projection does not store. [#124568](https://github.com/ClickHouse/ClickHouse/pull/124568) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135037](https://github.com/ClickHouse/ClickHouse/issues/135037): Fix abrupt server termination when MongoDB returns malformed query results. [#132506](https://github.com/ClickHouse/ClickHouse/pull/132506) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#135142](https://github.com/ClickHouse/ClickHouse/issues/135142): Fixed background merges and `OPTIMIZE` of a table that has a column TTL on an `ALIAS` or `EPHEMERAL` column: once the TTL was due, they failed with `There is no physical column ... in table. (NO_SUCH_COLUMN_IN_TABLE)` and the merge was retried forever. Closes [#134006](https://github.com/ClickHouse/ClickHouse/issues/134006). [#134279](https://github.com/ClickHouse/ClickHouse/pull/134279) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135085](https://github.com/ClickHouse/ClickHouse/issues/135085): Fix dictionaries with a remote ClickHouse source over `Distributed` with a cluster secret. [#134753](https://github.com/ClickHouse/ClickHouse/pull/134753) ([Azat Khuzhin](https://github.com/azat)).

#### Build/Testing/Packaging Improvement
* Backported in [#135080](https://github.com/ClickHouse/ClickHouse/issues/135080): Alpine-based `clickhouse-server` and `clickhouse-keeper` images now run `apk upgrade` at build time, so they pick up security fixes for packages that are already in the alpine base image, such as OpenSSL. [#124094](https://github.com/ClickHouse/ClickHouse/pull/124094) ([Joel Bandi](https://github.com/joelbandi)).
