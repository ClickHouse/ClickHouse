# 2026 Changelog

### ClickHouse release v26.8.16.41-lts (4ede48259fe) FIXME as compared to v26.8.15.10-lts (3c6755634c2)

#### Performance Improvement
* Backported in [#123476](https://github.com/ClickHouse/ClickHouse/issues/123476): Faster planning of queries to Iceberg tables with many manifest files: when a manifest file header has the `schema-id` key and that schema is already known from metadata.json, the schema copy stored in the manifest header is no longer parsed and compared with it. ClickHouse now also writes the `schema-id` key into the headers of manifest files it creates. [#122574](https://github.com/ClickHouse/ClickHouse/pull/122574) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#123213](https://github.com/ClickHouse/ClickHouse/issues/123213): Build Iceberg min/max hyperrectangles only for columns the filter uses. [#122681](https://github.com/ClickHouse/ClickHouse/pull/122681) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Improvement
* Backported in [#123258](https://github.com/ClickHouse/ClickHouse/issues/123258): Hide the HTTP headers in the definition of `HTTP` dictionary sources in `SHOW CREATE DICTIONARY`, `system.tables` and query logs, the same way as passwords. They can be shown with the existing `display_secrets_in_show_and_select` mechanism. [#122673](https://github.com/ClickHouse/ClickHouse/pull/122673) ([Matheus Nerone](https://github.com/Manerone)).
* Backported in [#123029](https://github.com/ClickHouse/ClickHouse/issues/123029): Parse some (geo) parquet metadata lazily. [#122693](https://github.com/ClickHouse/ClickHouse/pull/122693) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#123665](https://github.com/ClickHouse/ClickHouse/issues/123665): Preserve execution limits and resource lifetimes when deriving `QueryPlan` instances for internal query execution. [#109722](https://github.com/ClickHouse/ClickHouse/pull/109722) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123574](https://github.com/ClickHouse/ClickHouse/issues/123574): Fixed `SYSTEM SYNC TRANSACTION LOG` (local, non-`ON CLUSTER` form) not checking the `SYSTEM_SYNC_TRANSACTION_LOG` privilege. The `ON CLUSTER` form already required it via `getRequiredAccessForDDLOnCluster`, but the local execution path skipped `checkAccess`, so a user without the grant could run the command when experimental transactions were enabled. [#112441](https://github.com/ClickHouse/ClickHouse/pull/112441) ([Azhar Izzannada E](https://github.com/azharizz)).
* Backported in [#123520](https://github.com/ClickHouse/ClickHouse/issues/123520): Fix a `text` or `ngrambf_v1` index silently dropping matching rows when the indexed column is compared for equality against a `FixedString` value, or searched with `hasAny` or `hasAll` over `FixedString` needles. Happens at default settings, since `use_skip_indexes` and `enable_full_text_index` are both on. [#117314](https://github.com/ClickHouse/ClickHouse/pull/117314) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#123374](https://github.com/ClickHouse/ClickHouse/issues/123374): Fixed an `ssl_certificate` authentication bypass where an embedded NUL byte in a certificate's Common Name (for example `john\0.evil.com`) was truncated server-side to `john`, letting a holder of such a certificate authenticate as a different user. [#117403](https://github.com/ClickHouse/ClickHouse/pull/117403) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#123460](https://github.com/ClickHouse/ClickHouse/issues/123460): Fixed `max_memory_usage` and `max_server_memory_usage` not being respected when reading a `JSON` column with the `FLATTENED` serialization version from the `Native` format. [#117730](https://github.com/ClickHouse/ClickHouse/pull/117730) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123467](https://github.com/ClickHouse/ClickHouse/issues/123467): Fixed out-of-bounds reads when reading a `JSON` or `Dynamic` column from a malformed `Native` block or a corrupted data part. A truncated stream, a duplicate type in a flattened `Dynamic` column, a duplicate or typed-colliding path in a `JSON` column, and a serialization version that is only ever written into a data part but sent over the wire, all made the server read past the end of a deserialized column, which could crash it or store unrelated heap contents in the inserted data. All of them are now rejected. [#117765](https://github.com/ClickHouse/ClickHouse/pull/117765) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123501](https://github.com/ClickHouse/ClickHouse/issues/123501): Prevent asynchronous inserts that only need to buffer data from being blocked by another insert waiting for a flush worker while holding their shared queue lock. Ensure a global forced flush waits for batches removed from the queue that are still waiting for a worker. [#118352](https://github.com/ClickHouse/ClickHouse/pull/118352) ([RJ](https://github.com/VrtxOmega)).
* Backported in [#122964](https://github.com/ClickHouse/ClickHouse/issues/122964): Kafka producer and consumer trace logs now show the value of secret librdkafka properties, such as sasl.password, as [HIDDEN] instead of the cleartext value. [#119244](https://github.com/ClickHouse/ClickHouse/pull/119244) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#123349](https://github.com/ClickHouse/ClickHouse/issues/123349): Skip indexes (`text`, `tokenbf_v1`, `ngrambf_v1`) are now used when the indexed column or the searched constant is wrapped into `LowCardinality`, `Nullable` or an equivalent `CAST`. For example, `m['key'] = 'value'` on a `Map(String, LowCardinality(String))` column and `hasToken(s, toLowCardinality('x'))` previously scanned all granules. [#120220](https://github.com/ClickHouse/ClickHouse/pull/120220) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#123455](https://github.com/ClickHouse/ClickHouse/issues/123455): `EXPLAIN AST` printed secret function arguments, such as the key of `encrypt`, in clear text, and with `optimize = 1` it did so for the body of a view the user may only `SELECT` from. The dump now prints `'[HIDDEN]'` in their place, under the same gate as `SHOW CREATE`. [#120313](https://github.com/ClickHouse/ClickHouse/pull/120313) ([Harikrishnan Prabakaran](https://github.com/harikrishnan94)).
* Backported in [#123221](https://github.com/ClickHouse/ClickHouse/issues/123221): Column-level `SELECT` privileges are now enforced for columns used only inside `indexHint` and for `ALIAS` columns referenced in `PREWHERE`. As in `WHERE`, referencing an `ALIAS` column in `PREWHERE` requires the grant on the alias name; a grant on its source columns is no longer sufficient. A metadata-only `ALTER` that changes a subcolumn read by a `MATERIALIZED` column through an `ALIAS` is now refused like a direct reference. [#120516](https://github.com/ClickHouse/ClickHouse/pull/120516) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Backported in [#123569](https://github.com/ClickHouse/ClickHouse/issues/123569): Fix a server crash (SIGSEGV) when a `CREATE TABLE ... PROJECTION` / `ALTER TABLE ... ADD PROJECTION` statement is restored from a `clickhouse_json` AST whose projection `query` subtree contains a function node without an `arguments` list. The malformed payload is now rejected with `BAD_ARGUMENTS` during AST JSON deserialization. [#121113](https://github.com/ClickHouse/ClickHouse/pull/121113) ([Ilias](https://github.com/iliasabk)).
* Backported in [#123231](https://github.com/ClickHouse/ClickHouse/issues/123231): Fixed a row policy bypass: a direct `JOIN` with an `EmbeddedRocksDB`, `KeeperMap` or `Redis` table in the legacy analyzer (`enable_analyzer = 0`) ignored the row policy of the right table and returned hidden rows, and `joinGet` on a `Join` table ignored its row policy in both analyzers. Such a table is now joined through its query plan, which keeps the filter, and `JOIN` or `joinGet` against a `Join` table under a row policy throws `ACCESS_DENIED`. [#121398](https://github.com/ClickHouse/ClickHouse/pull/121398) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#123202](https://github.com/ClickHouse/ClickHouse/issues/123202): Fix `NO_COMMON_TYPE` in case of `use_variant_as_common_type=0` for jemalloc fragmentation dashboard. [#121621](https://github.com/ClickHouse/ClickHouse/pull/121621) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#123499](https://github.com/ClickHouse/ClickHouse/issues/123499): Fix the Kafka and NATS table engines ignoring `remote_url_allow_hosts`: broker addresses from `kafka_broker_list`, `nats_url`, and `nats_server_list` are now checked against the remote host filter. A forbidden address is rejected at `CREATE TABLE` with `UNACCEPTABLE_URL`, as the RabbitMQ engine already does. [#121825](https://github.com/ClickHouse/ClickHouse/pull/121825) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#122722](https://github.com/ClickHouse/ClickHouse/issues/122722): Now statistics parts pruning will not work if table has row level policy. [#122035](https://github.com/ClickHouse/ClickHouse/pull/122035) ([alesapin](https://github.com/alesapin)).
* Backported in [#122865](https://github.com/ClickHouse/ClickHouse/issues/122865): Now clickhouse masks credentials in system.query_log even for wrong URLs for external table engines. [#122057](https://github.com/ClickHouse/ClickHouse/pull/122057) ([alesapin](https://github.com/alesapin)).
* Backported in [#123518](https://github.com/ClickHouse/ClickHouse/issues/123518): Fix filesystem cache accounting when the directory for a new cache key cannot be created, for example because the cache disk is out of space or inodes. The failed reservation stayed counted in the cache until the query released the file segment. [#122211](https://github.com/ClickHouse/ClickHouse/pull/122211) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#123356](https://github.com/ClickHouse/ClickHouse/issues/123356): `CREATE OR REPLACE` in a `Replicated` database or with `ON CLUSTER` now requires the drop privilege for the kind of the table it replaces, so a user without `DROP DICTIONARY` can no longer replace a dictionary. [#122272](https://github.com/ClickHouse/ClickHouse/pull/122272) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#123252](https://github.com/ClickHouse/ClickHouse/issues/123252): Fix `LOGICAL_ERROR` `Cannot capture column N because it has incompatible type` when a materialized view with a lambda over an `Array(Tuple(...))` column receives a block while the source table's column type is being changed by `ALTER TABLE ... MODIFY COLUMN`. [#122345](https://github.com/ClickHouse/ClickHouse/pull/122345) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Backported in [#122969](https://github.com/ClickHouse/ClickHouse/issues/122969): The value of 'role_session_name' as of now is hidden in `query_log`. [#122423](https://github.com/ClickHouse/ClickHouse/pull/122423) ([Alexey Bakharew](https://github.com/alexbakharew)).
* Backported in [#123472](https://github.com/ClickHouse/ClickHouse/issues/123472): Fix a server crash caused by unbounded recursion when decoding a deeply nested value inside a binary encoded type, for example an `AggregateFunction` parameter in a `Dynamic` value read from `RowBinary` or `Native`. [#122667](https://github.com/ClickHouse/ClickHouse/pull/122667) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123015](https://github.com/ClickHouse/ClickHouse/issues/123015): Fix Keeper silently giving a new session to a ZooKeeper client (for example the Java client or kazoo) that reconnects and asks to continue its session. Such a client now gets `SessionExpired`, ZooKeeper's answer for a session that cannot be continued, instead of losing its ephemeral nodes later without notice. Keeper still does not restore sessions. Closes [#116690](https://github.com/ClickHouse/ClickHouse/issues/116690). [#122767](https://github.com/ClickHouse/ClickHouse/pull/122767) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123022](https://github.com/ClickHouse/ClickHouse/issues/123022): Fix validation of Iceberg manifest-list entries during writes. [#122829](https://github.com/ClickHouse/ClickHouse/pull/122829) ([Arsen Muk](https://github.com/arsenmuk)).
* Backported in [#123412](https://github.com/ClickHouse/ClickHouse/issues/123412): Fixes a server crash on `CREATE TABLE` or `ALTER TABLE ... MODIFY TTL` with a TTL expression that uses the result of `arrayMap` with a constant lambda, such as `toString(arrayMap(x -> CAST(1, 'Dynamic'), arr))`. [#122868](https://github.com/ClickHouse/ClickHouse/pull/122868) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123119](https://github.com/ClickHouse/ClickHouse/issues/123119): Fixed secret settings of `S3Queue` and `AzureQueue` tables written with the legacy `s3queue_` prefix, such as `s3queue_after_processing_move_secret_access_key`, being shown in cleartext in `SHOW CREATE TABLE`, `system.tables`, `system.query_log` and the server log. They are now hidden as they are without the prefix. [#123060](https://github.com/ClickHouse/ClickHouse/pull/123060) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123384](https://github.com/ClickHouse/ClickHouse/issues/123384): Add more path validations. [#123099](https://github.com/ClickHouse/ClickHouse/pull/123099) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#123149](https://github.com/ClickHouse/ClickHouse/issues/123149): S3 client check initial url in backup client. [#123114](https://github.com/ClickHouse/ClickHouse/pull/123114) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#123482](https://github.com/ClickHouse/ClickHouse/issues/123482): Fix missing rows in `hasAllTokens` and `hasAnyTokens` searches over a text index when an earlier query with the same predicate read a narrower key range of the same part and `use_text_index_postings_cache` was enabled. [#123228](https://github.com/ClickHouse/ClickHouse/pull/123228) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#123443](https://github.com/ClickHouse/ClickHouse/issues/123443): Fix a crash when reading an ORC file whose root type is not a struct (for example, a file written with a `bigint` or `array<bigint>` root type). Such files are now rejected with an `INCORRECT_DATA` error. Closes [#123305](https://github.com/ClickHouse/ClickHouse/issues/123305). [#123337](https://github.com/ClickHouse/ClickHouse/pull/123337) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123616](https://github.com/ClickHouse/ClickHouse/issues/123616): Fixed a crash and wrong results with `convert_query_to_cnf = 1` when `WHERE` or `HAVING` references the same `SELECT` alias more than once. [#123414](https://github.com/ClickHouse/ClickHouse/pull/123414) ([Groene AI](https://github.com/groeneai)).
* Fix a possible crash when querying the view over `Distributed` with `enable_analyzer=0`. [#123431](https://github.com/ClickHouse/ClickHouse/pull/123431) ([Mikhail Koviazin](https://github.com/mkmkme)).
* Fix a bug where using aliases and row policies with `enable_analyzer=0` could error out. [#123436](https://github.com/ClickHouse/ClickHouse/pull/123436) ([Mikhail Koviazin](https://github.com/mkmkme)).
