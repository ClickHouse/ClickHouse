# 2026 Changelog

### ClickHouse release v26.3.34.136-lts (4c1242ee175) FIXME as compared to v26.3.33.24-lts (211b7286fd9)

#### Backward Incompatible Change
* Backported in [#121228](https://github.com/ClickHouse/ClickHouse/issues/121228): Outbound TLS connections now verify that the server certificate names the host that was connected to. This affects `clickhouse-client --secure`, `remoteSecure()`, `Distributed` over the secure native protocol, secure Keeper connections, and HTTPS clients such as `s3()`, `url()`, HTTP dictionaries and JWT token endpoints. Connecting to an endpoint whose certificate does not name it, for example an IP address with no matching SAN, an S3-compatible gateway fronted by a different name, or an internal CA with missing SANs, now fails with `Unacceptable certificate`. Set `openSSL.client.extendedVerification` to `false` to restore the previous behaviour, or pass `--tls-sni-override` to name the host the certificate was issued for. Loopback addresses stay exempt unless `verificationMode` is `strict`, and the default for `openSSL.server.extendedVerification` is unchanged. [#116724](https://github.com/ClickHouse/ClickHouse/pull/116724) ([Groene AI](https://github.com/groeneai)).
* Backported in [#122174](https://github.com/ClickHouse/ClickHouse/issues/122174): A MySQL dictionary source created with a `CREATE DICTIONARY` query can no longer enable `enable_local_infile`, at the source or at one of its `REPLICA` entries; loading such a dictionary fails with `BAD_ARGUMENTS`, which with the default `dictionaries_lazy_load` is on first use rather than at `CREATE`. A `REPLICA` that does not set the key inherits the source's value, as the connection pool does. To keep the option, define the dictionary in a server configuration file; `enable_local_infile 0`, and a `SOURCE(MYSQL(NAME ...))` reference to a named collection where the key was never read, are unaffected. [#120972](https://github.com/ClickHouse/ClickHouse/pull/120972) ([Groene AI](https://github.com/groeneai)).

#### New Feature
* Backported in [#121586](https://github.com/ClickHouse/ClickHouse/issues/121586): You can now disable reading through the `executable` table function and from `Executable`/`ExecutablePool` tables with the new `allow_executable_tables` setting, for a deployment that must not run arbitrary server-side scripts. It defaults to `true`, so existing behavior is unchanged. [#120713](https://github.com/ClickHouse/ClickHouse/pull/120713) ([Hanzi Jiang](https://github.com/HanziJiang)).

#### Performance Improvement
* Backported in [#117529](https://github.com/ClickHouse/ClickHouse/issues/117529): Avoid eager JSON serialization of Iceberg manifest entries when iceberg_metadata_log_level is below the call site's threshold. [#110437](https://github.com/ClickHouse/ClickHouse/pull/110437) ([Andy Bradshaw](https://github.com/andybradshaw)).
* Backported in [#120624](https://github.com/ClickHouse/ClickHouse/issues/120624): Parsing an HTTP request that carries many query parameters or headers with the same name (for example thousands of repeated `role=` parameters) no longer takes quadratic time. [#114410](https://github.com/ClickHouse/ClickHouse/pull/114410) ([James](https://github.com/sanjams2)).

#### Improvement
* Backported in [#120627](https://github.com/ClickHouse/ClickHouse/issues/120627): Treat `max_size = 0` and `max_elements = 0` in `IFileCachePriority::check` as "no limit", consistent with how `canFit` interprets these values. This silences spurious `Cache limits violated` logical errors on priorities created with zero limits (such as the per-query filesystem cache priority used when `enable_filesystem_query_cache_limit` is on). [#101428](https://github.com/ClickHouse/ClickHouse/pull/101428) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120571](https://github.com/ClickHouse/ClickHouse/issues/120571): More security validations for biglake catalog. [#105117](https://github.com/ClickHouse/ClickHouse/pull/105117) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#119903](https://github.com/ClickHouse/ClickHouse/issues/119903): Write partition field summaries into the Iceberg manifest list. [#118796](https://github.com/ClickHouse/ClickHouse/pull/118796) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#119966](https://github.com/ClickHouse/ClickHouse/issues/119966): Bump the internal libssh from 0.12.0 to 0.12.2. [#119262](https://github.com/ClickHouse/ClickHouse/pull/119262) ([Robert Schulze](https://github.com/rschu1ze)).
* Backported in [#122371](https://github.com/ClickHouse/ClickHouse/issues/122371): Iceberg partition pruning now uses the partition value of a `day`, `month`, `year` or `hour` transform for a filter that wraps the partition source column in a monotonic function, such as `WHERE toDate(ts) = '2024-01-20'`, including for partition values from before 1970. [#119302](https://github.com/ClickHouse/ClickHouse/pull/119302) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
