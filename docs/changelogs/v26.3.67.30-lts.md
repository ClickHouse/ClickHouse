# 2026 Changelog

### ClickHouse release v26.3.67.30-lts (25234505df3) FIXME as compared to v26.3.66.4-lts (20beaefbaee)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132651](https://github.com/ClickHouse/ClickHouse/issues/132651): `ATTACH TABLE ... AS REPLICATED` and `ATTACH TABLE ... AS NOT REPLICATED` now check the `TABLE ENGINE` grant on the engine the table is converted to before changing anything. Previously a query refused for this grant had already rewritten the stored definition of the detached table, so a later `ATTACH TABLE` loaded it with the new engine. [#128995](https://github.com/ClickHouse/ClickHouse/pull/128995) ([Nikolai Ovchinnikov](https://github.com/kolsha)).
* Backported in [#132302](https://github.com/ClickHouse/ClickHouse/issues/132302): A `Merge` table and the `merge` table function no longer count the matched tables the user cannot see (no `SHOW TABLES`) when `count()` is answered from metadata or in `system.tables` `total_rows`/`total_bytes`, and their `system.columns` sizes include only the columns the user can see (`SHOW COLUMNS`) on each matched table. Before, these disclosed the row count and size of tables the user has no access to, while reading the same data skipped them. [#129818](https://github.com/ClickHouse/ClickHouse/pull/129818) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132644](https://github.com/ClickHouse/ClickHouse/issues/132644): When `http_forbid_headers` forbids `Authorization`, Basic credentials that would be sent in that header are now refused too: the userinfo of `url`, `urlCluster` and `URL` table URLs (including url wildcards and `web` disks), `credentials` of `HTTP` dictionaries created by DDL, the userinfo of `format_avro_schema_registry_url`, and `user`/`password` of the `Elasticsearch` engine. Before, only an explicit `Authorization` header was refused. [#129850](https://github.com/ClickHouse/ClickHouse/pull/129850) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132546](https://github.com/ClickHouse/ClickHouse/issues/132546): Prevent impersonation via forged SECONDARY_QUERY on secret clusters. [#130362](https://github.com/ClickHouse/ClickHouse/pull/130362) ([Vitaly Baranov](https://github.com/vitlibar)).
* Backported in [#132616](https://github.com/ClickHouse/ClickHouse/issues/132616): Fixed a type confusion (possible crash or out-of-bounds read) triggered by a client sending a column with a `Sparse` or `Replicated` serialization kind, or a `Tuple` with a `Replicated` element, in data over the native protocol. [#130895](https://github.com/ClickHouse/ClickHouse/pull/130895) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#132855](https://github.com/ClickHouse/ClickHouse/issues/132855): Check the scale of a `Decimal` value before formatting it as text, so a value with an out-of-range scale produces an exception instead of undefined behavior. [#131366](https://github.com/ClickHouse/ClickHouse/pull/131366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132769](https://github.com/ClickHouse/ClickHouse/issues/132769): Fixed parsing of decimal text with an exponent close to the `Int32` limits: values such as `1e2147483647` were read as `0` instead of being rejected as too big. [#131373](https://github.com/ClickHouse/ClickHouse/pull/131373) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132129](https://github.com/ClickHouse/ClickHouse/issues/132129): Fixed `DROP WORKLOAD` removing a resource with the same name and `DROP RESOURCE` removing a workload with the same name when workload entities are stored in Keeper (`workload_zookeeper_path`). A user with only one of the two privileges could remove the other kind of entity. [#131688](https://github.com/ClickHouse/ClickHouse/pull/131688) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132985](https://github.com/ClickHouse/ClickHouse/issues/132985): Fixed `CREATE WORKLOAD`, `DROP WORKLOAD`, `CREATE RESOURCE` and `DROP RESOURCE` with `workload_zookeeper_path` overwriting definitions written by other replicas when the query was the first to use a renewed Keeper session. [#131719](https://github.com/ClickHouse/ClickHouse/pull/131719) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132074](https://github.com/ClickHouse/ClickHouse/issues/132074): Fix a server abort when merging a malformed serialized state of a `-Map` aggregate function with a `FixedString` key. Now such a state is rejected with `INCORRECT_DATA`. [#131732](https://github.com/ClickHouse/ClickHouse/pull/131732) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132257](https://github.com/ClickHouse/ClickHouse/issues/132257): Fix a possible crash when an exception (for example, a memory limit) is thrown during the short-circuit evaluation of a function returning an `AggregateFunction` state. [#131733](https://github.com/ClickHouse/ClickHouse/pull/131733) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132202](https://github.com/ClickHouse/ClickHouse/issues/132202): Fix a possible crash of the `PostgreSQL` table engine, table function and database engine when the remote server reports an absurd number of array dimensions. [#131734](https://github.com/ClickHouse/ClickHouse/pull/131734) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132269](https://github.com/ClickHouse/ClickHouse/issues/132269): Fix a stack overflow in the `ParquetMetadata` format for files with a very deeply nested schema. The depth is now limited by `max_parser_depth`, as in the `Parquet` format, and never exceeds 1000. [#131735](https://github.com/ClickHouse/ClickHouse/pull/131735) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132284](https://github.com/ClickHouse/ClickHouse/issues/132284): Fix out-of-bounds reads when deserializing a query plan with a step lacking some of its inputs or having extra children. Now such a plan is rejected with `INCORRECT_DATA`. [#131736](https://github.com/ClickHouse/ClickHouse/pull/131736) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132228](https://github.com/ClickHouse/ClickHouse/issues/132228): Fix a crash of the `DWARF` input format on an ELF file with a malformed attribute length. [#131787](https://github.com/ClickHouse/ClickHouse/pull/131787) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133077](https://github.com/ClickHouse/ClickHouse/issues/133077): Fix out-of-bounds memory access with an aggregate state containing a `JSON` value with a repeated path. Now such a state is rejected with `INCORRECT_DATA`. [#131791](https://github.com/ClickHouse/ClickHouse/pull/131791) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132275](https://github.com/ClickHouse/ClickHouse/issues/132275): Fix a possible out-of-bounds read in the `Parquet` reader when `PREWHERE` filters out a whole page of a `PLAIN`-encoded string column read through a conversion (e.g. to `Geometry`). [#131797](https://github.com/ClickHouse/ClickHouse/pull/131797) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132093](https://github.com/ClickHouse/ClickHouse/issues/132093): Fix a possible crash when restoring a backup from a zip archive with a password if an encrypted entry of the archive is smaller than the encryption header. [#131806](https://github.com/ClickHouse/ClickHouse/pull/131806) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132377](https://github.com/ClickHouse/ClickHouse/issues/132377): `SYSTEM SYNC DATABASE REPLICA` without `ON CLUSTER` now requires the `SYSTEM SYNC DATABASE REPLICA` grant on the database. Before, any user could run it. [#131893](https://github.com/ClickHouse/ClickHouse/pull/131893) ([Lazizbek Ergashev](https://github.com/lazerg)).
* Backported in [#133008](https://github.com/ClickHouse/ClickHouse/issues/133008): The `/binary` web UI now displays the symbol name and source line in the popup as text instead of interpreting the server response as HTML. [#131895](https://github.com/ClickHouse/ClickHouse/pull/131895) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132733](https://github.com/ClickHouse/ClickHouse/issues/132733): The `URL ... is not allowed in configuration file, see <remote_url_allow_hosts>` error now shows only the host and port of the URL, so secrets in its path or query string are no longer exposed. [#132160](https://github.com/ClickHouse/ClickHouse/pull/132160) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#132413](https://github.com/ClickHouse/ClickHouse/issues/132413): Fix an asynchronous `INSERT ... FROM INFILE` sent directly to the server opening the file on the server before the query was rejected. [#132305](https://github.com/ClickHouse/ClickHouse/pull/132305) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#132464](https://github.com/ClickHouse/ClickHouse/issues/132464): Fix a server crash when deserializing a malformed aggregate state that contains a `LowCardinality(String)` value. [#132322](https://github.com/ClickHouse/ClickHouse/pull/132322) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#132933](https://github.com/ClickHouse/ClickHouse/issues/132933): Fixed a memory leak in queries answered by `_minmax_count_projection` that compute `min` or `max` of a `Tuple`, `Array` or `FixedString` primary key or partition column: every part read leaked one aggregate state. [#132557](https://github.com/ClickHouse/ClickHouse/pull/132557) ([Groene AI](https://github.com/groeneai)).
