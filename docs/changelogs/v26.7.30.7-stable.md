# 2026 Changelog

### ClickHouse release v26.7.30.7-stable (b5e66588b74) FIXME as compared to v26.7.29.12-stable (a178cd3046b)

#### Improvement
* Backported in [#125602](https://github.com/ClickHouse/ClickHouse/issues/125602): Add ability to select jemalloc 4K/16K page size on aarch64 (default 64K). [#115424](https://github.com/ClickHouse/ClickHouse/pull/115424) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#125540](https://github.com/ClickHouse/ClickHouse/issues/125540): Added a server setting `access_control_improvements.readonly_restricts_set_role`, `false` by default. When enabled, `SET ROLE` is refused with error code `READONLY` in a session or query whose `readonly` setting is not zero. Previously `SET ROLE` was the only identity-changing statement that `readonly` did not refuse. [#118021](https://github.com/ClickHouse/ClickHouse/pull/118021) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125629](https://github.com/ClickHouse/ClickHouse/issues/125629): Fix a credential written in cleartext to `system.query_log` and the server log when a `key = value` argument precedes the positional arguments of the `mongodb`, `redis`, `remote`, `arrowFlight` and `ytsaurus` table functions or the `MongoDB`, `Redis`, `Remote`, `ArrowFlight`, `ExternalDistributed` and `YTsaurus` table engines. A positional argument after a named one is now always hidden, and the value of a named-collection override whose key is written as an expression is hidden for every such engine. [#122770](https://github.com/ClickHouse/ClickHouse/pull/122770) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#125480](https://github.com/ClickHouse/ClickHouse/issues/125480): Fixed a heap use-after-free in the `s3`, `azureBlobStorage`, `hdfs` and other object storage table functions and engines when an exception (for example `MEMORY_LIMIT_EXCEEDED`) was thrown while creating the reader of a file in a row input format such as `CSV`. [#125090](https://github.com/ClickHouse/ClickHouse/pull/125090) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125484](https://github.com/ClickHouse/ClickHouse/issues/125484): Fixed a server crash, wrong results or a rejected query in `ORDER BY ... WITH FILL ... INTERPOLATE` when one `INTERPOLATE` expression has to be converted to its target's type and another item reads the same column or literal, for example `INTERPOLATE (a AS b, b AS a)` with targets of different types. [#125129](https://github.com/ClickHouse/ClickHouse/pull/125129) ([Groene AI](https://github.com/groeneai)).
