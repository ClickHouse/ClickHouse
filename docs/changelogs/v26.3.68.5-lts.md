# 2026 Changelog

### ClickHouse release v26.3.68.5-lts (e595b9ecc65) FIXME as compared to v26.3.67.30-lts (25234505df3)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133193](https://github.com/ClickHouse/ClickHouse/issues/133193): Check access rights before loading a dictionary or reading its definition in the `dictionary` table function, `dictGet`-family functions, `naiveBayesClassifier`, `Dictionary` tables and `CREATE TABLE ... ENGINE = Dictionary`. Queries without the required grants no longer trigger the dictionary load, and queries or DDL that reference a dictionary now require access to it even when they do not read it, e.g. `DESCRIBE`, `CREATE VIEW` or a `DEFAULT dictGet(...)` column. [#122678](https://github.com/ClickHouse/ClickHouse/pull/122678) ([Matheus Nerone](https://github.com/Manerone)).
* Backported in [#133207](https://github.com/ClickHouse/ClickHouse/issues/133207): Fix a possible crash of the `RabbitMQ` table engine when the broker confirms a message with an unknown delivery tag. [#131731](https://github.com/ClickHouse/ClickHouse/pull/131731) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133216](https://github.com/ClickHouse/ClickHouse/issues/133216): Fix type confusion when deserializing a query plan whose aggregate functions do not match the types of their input columns. Now such a plan is rejected with `INCORRECT_DATA`. [#131789](https://github.com/ClickHouse/ClickHouse/pull/131789) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* The `url` of an `HTTP` dictionary source is hidden in `SHOW CREATE`, `system.tables` and the query log, and its userinfo in `system.dictionaries`. [#133045](https://github.com/ClickHouse/ClickHouse/pull/133045) ([George Larionov](https://github.com/george-larionov)).
