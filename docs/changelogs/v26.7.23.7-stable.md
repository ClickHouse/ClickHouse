# 2026 Changelog

### ClickHouse release v26.7.23.7-stable (2d9e1dc973a) FIXME as compared to v26.7.22.4-stable (b1273b7dc8d)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#123980](https://github.com/ClickHouse/ClickHouse/issues/123980): Fix `SYSTEM REFRESH` on a stopped `RabbitMQ` table sometimes failing to consume the queued backlog. A REFRESH grants exactly one out-of-order streaming cycle, but that cycle could return immediately with zero rows because the AMQP delivery loop had only just been started asynchronously, wasting the single permit and leaving the messages unconsumed until the next `SYSTEM START`. [#111480](https://github.com/ClickHouse/ClickHouse/pull/111480) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124064](https://github.com/ClickHouse/ClickHouse/issues/124064): Fixed a transient Azure Blob Storage error on the read or merge path — an RBAC permission-propagation `403 Forbidden`, a credential authentication failure, or a connect timeout surfaced as `408` — being misclassified as non-retryable and reported as `POTENTIALLY_BROKEN_DATA_PART` (Code 740), raising a false critical alert for a healthy part. These transient failures are now treated as retryable, and a genuinely persistent one surfaces as a plain Azure error instead of a phantom broken data part. [#112871](https://github.com/ClickHouse/ClickHouse/pull/112871) ([Arsen Muk](https://github.com/arsenmuk)).
* Backported in [#124082](https://github.com/ClickHouse/ClickHouse/issues/124082): Fixed asynchronous TLS connections occasionally failing with an unrelated OpenSSL error left by another connection on the same OS thread. This could terminate distributed queries with a misleading network exception. [#116692](https://github.com/ClickHouse/ClickHouse/pull/116692) ([Dmitriy Borisenko](https://github.com/otselnik)).
* Backported in [#123973](https://github.com/ClickHouse/ClickHouse/issues/123973): Add more path validations. [#123099](https://github.com/ClickHouse/ClickHouse/pull/123099) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#123987](https://github.com/ClickHouse/ClickHouse/issues/123987): Fixed a segmentation fault or `std::length_error` when reading `TSV` formats with `input_format_tsv_crlf_end_of_line = 1` if an escape sequence ended exactly at the end of a read buffer. [#123861](https://github.com/ClickHouse/ClickHouse/pull/123861) ([Groene AI](https://github.com/groeneai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Revert backport of [#116335](https://github.com/ClickHouse/ClickHouse/issues/116335) to 26.7: Check for timeouts and KILL QUERY while covering a polygon with H3 cells. [#124014](https://github.com/ClickHouse/ClickHouse/pull/124014) ([Nikita Fomichev](https://github.com/fm4v)).
