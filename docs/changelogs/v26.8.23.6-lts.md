# 2026 Changelog

### ClickHouse release v26.8.23.6-lts (4ba605fc98d) FIXME as compared to v26.8.22.13-lts (cc72af4d4e9)

#### Performance Improvement
* Backported in [#124997](https://github.com/ClickHouse/ClickHouse/issues/124997): Faster sorted-stream processing on a multi-column key whose leading column has long runs, in `LIMIT BY`, negative `LIMIT BY`, `DISTINCT` in order, window functions (peer groups and `PARTITION BY` boundaries), `full_sorting_merge` and `partial_merge` `JOIN`, and `ReplacingMergeTree` `FINAL` without vertical `FINAL`: the run of a key prefix is now found once instead of again for every group in it. The query from [#123700](https://github.com/ClickHouse/ClickHouse/issues/123700) is about 3.5x faster. [#123808](https://github.com/ClickHouse/ClickHouse/pull/123808) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124276](https://github.com/ClickHouse/ClickHouse/issues/124276): Comparing an `Enum` column with a string literal that is not one of its elements no longer throws `UNKNOWN_ELEMENT_OF_ENUM` when `validate_enum_literals_in_operators` is disabled (the default) and the column is part of the primary key, the partition key, or a `bloom_filter` index. `!=` with such a literal now returns true for every row instead of throwing. Closes [#122235](https://github.com/ClickHouse/ClickHouse/issues/122235), [#111545](https://github.com/ClickHouse/ClickHouse/issues/111545). [#122672](https://github.com/ClickHouse/ClickHouse/pull/122672) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#124895](https://github.com/ClickHouse/ClickHouse/issues/124895): Fix corrupted shared data of nested `JSON` objects after a failed attempt to parse a value during insert. It could lead to errors like `Unexpected version of JSON type binary encoding` or `Unknown type code` when reading the data after merges or when serializing it in binary formats. [#123898](https://github.com/ClickHouse/ClickHouse/pull/123898) ([Rory Shanks](https://github.com/rorylshanks)).
* Backported in [#125017](https://github.com/ClickHouse/ClickHouse/issues/125017): Fixed a query failing with an exception like `Cannot parse UInt64 from String` on a table with a text index on `mapKeys` or `JSONAllPaths`, when the predicate cannot be evaluated on the value of a missing map key or JSON path. [#124612](https://github.com/ClickHouse/ClickHouse/pull/124612) ([Anton Popov](https://github.com/CurtizJ)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#124948](https://github.com/ClickHouse/ClickHouse/issues/124948): Use `castStorage` for the `Join` row policy check in the legacy analyzer. [#124441](https://github.com/ClickHouse/ClickHouse/pull/124441) ([Vladimir Cherkasov](https://github.com/vdimir)).
