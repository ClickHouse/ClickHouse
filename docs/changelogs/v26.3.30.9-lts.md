# 2026 Changelog

### ClickHouse release v26.3.30.9-lts (a7132c33074) FIXME as compared to v26.3.29.7-lts (9d44dc7ea69)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#117557](https://github.com/ClickHouse/ClickHouse/issues/117557): Fix a server crash in predicate pushdown (`enable_optimize_predicate_expression`, legacy analyzer) when a `UNION` subquery appears inside a `JOIN ... ON` condition. [#107930](https://github.com/ClickHouse/ClickHouse/pull/107930) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117458](https://github.com/ClickHouse/ClickHouse/issues/117458): Fixed `parallel_view_processing` setting being ignored when inserting into a table with materialized views — since 25.10, views always ran in parallel regardless of the setting. [#109170](https://github.com/ClickHouse/ClickHouse/pull/109170) ([Antonio Andelic](https://github.com/antonio2368)).
* Backported in [#117748](https://github.com/ClickHouse/ClickHouse/issues/117748): Fixed reading a corrupted `Native`-format stream whose `Dynamic` type count or `JSON`/`Object` path count is close to `SIZE_MAX`: such malformed input is now rejected with a clear `INCORRECT_DATA` error instead of an uncaught `std::length_error`. [#110590](https://github.com/ClickHouse/ClickHouse/pull/110590) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#117691](https://github.com/ClickHouse/ClickHouse/issues/117691): Fixes memory leaks of abandoned nested aggregate states. [#113926](https://github.com/ClickHouse/ClickHouse/pull/113926) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117750](https://github.com/ClickHouse/ClickHouse/issues/117750): Fixed silently incorrect results and undefined behavior when reading a malformed `AggregateFunction(uniq, ...)` state. The `skip_degree` field of the serialized state was used as a shift exponent without validation, so an out-of-range value produced an arbitrary cardinality instead of an error. Such states are now rejected with `INCORRECT_DATA`. [#115276](https://github.com/ClickHouse/ClickHouse/pull/115276) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115751](https://github.com/ClickHouse/ClickHouse/issues/115751): Fix `read_rows`, `read_bytes`, `written_rows` and `written_bytes` in `system.query_thread_log` reporting a thread lifetime running total instead of the values for the logged query. Rows of long-lived pooled threads, in particular the query's initiating `HTTPHandler` thread, were affected. [#115596](https://github.com/ClickHouse/ClickHouse/pull/115596) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117656](https://github.com/ClickHouse/ClickHouse/issues/117656): Fixed wrong results from `sumKahan` when the aggregated batch does not start at the first row of the block. `sumKahanIf`, and `sumKahan` over a `Nullable` argument, tested each row against the wrong element of the condition or null map, returning silently incorrect sums inside window frames such as `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`, in parallel `GROUP BY`, and under `optimize_aggregation_in_order = 1`. [#116990](https://github.com/ClickHouse/ClickHouse/pull/116990) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117889](https://github.com/ClickHouse/ClickHouse/issues/117889): Check the overflow when allocating a block of aggregate function states on deserialization: a malformed `Native` block could make the server write out of bounds. [#117370](https://github.com/ClickHouse/ClickHouse/pull/117370) ([Raúl Marín](https://github.com/Algunenano)).
