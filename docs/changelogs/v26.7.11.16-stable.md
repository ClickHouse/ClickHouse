# 2026 Changelog

### ClickHouse release v26.7.11.16-stable (717876c9cef) FIXME as compared to v26.7.10.6-stable (15a4ffd2bea)

#### Performance Improvement
* Backported in [#120626](https://github.com/ClickHouse/ClickHouse/issues/120626): Parsing an HTTP request that carries many query parameters or headers with the same name (for example thousands of repeated `role=` parameters) no longer takes quadratic time. [#114410](https://github.com/ClickHouse/ClickHouse/pull/114410) ([James](https://github.com/sanjams2)).
* Backported in [#120392](https://github.com/ClickHouse/ClickHouse/issues/120392): `LEFT` and `FULL JOIN` with `join_use_nulls = 1` use less memory when the right join key is selected in the query: the key is no longer stored twice on the build side. [#119001](https://github.com/ClickHouse/ClickHouse/pull/119001) ([Vladimir Cherkasov](https://github.com/vdimir)).

#### Improvement
* Backported in [#120427](https://github.com/ClickHouse/ClickHouse/issues/120427): Added `output_format_arrow_record_batch_size` and `output_format_arrow_record_batch_size_bytes`, which make the `Arrow` and `ArrowStream` output formats combine consecutive blocks that are individually smaller than the target into a single record batch. A selective `SELECT` produced one small record batch per scanned block, and the fixed metadata and buffer padding of each batch then dominated the payload. Both settings default to `0`, which keeps the previous behavior of one record batch per block. Closes [#119815](https://github.com/ClickHouse/ClickHouse/issues/119815). [#119873](https://github.com/ClickHouse/ClickHouse/pull/119873) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#120603](https://github.com/ClickHouse/ClickHouse/issues/120603): Fix a race between a `ReplicatedMergeTree` mutation and the removal of old temporary directories that could publish a mutated part with some of its files missing, making reads of that part and all its later mutations fail. [#111992](https://github.com/ClickHouse/ClickHouse/pull/111992) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120301](https://github.com/ClickHouse/ClickHouse/issues/120301): Fix reading a column that has two streams whose names differ only by escaping, for example a `Tuple` element named `size0` inside an `Array`, or a `JSON` typed path named like a substream of a sibling path. Such columns returned wrong values, failed with `CANNOT_READ_ALL_DATA` or a logical error, and made the table unmergeable. [#115670](https://github.com/ClickHouse/ClickHouse/pull/115670) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#120641](https://github.com/ClickHouse/ClickHouse/issues/120641): Fix `LOGICAL_ERROR: GroupingAggregatedTransform pushed bucket N twice` when `make_distributed_plan` picks the `Shuffle` aggregation strategy while the aggregation must produce results in bucket order (for example with `distributed_aggregation_memory_efficient`). It is now planned as a partial aggregation plus a merge. [#116446](https://github.com/ClickHouse/ClickHouse/pull/116446) ([Groene AI](https://github.com/groeneai)).
* Backported in [#120430](https://github.com/ClickHouse/ClickHouse/issues/120430): Make `mergeTreeTextIndex` stricter with row policies: reading the text index is now denied whenever a row policy applies to the table, regardless of which columns the policy uses. [#119032](https://github.com/ClickHouse/ClickHouse/pull/119032) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#120668](https://github.com/ClickHouse/ClickHouse/issues/120668): Fixed ClickHouse Keeper terminating when a client sent a `multi` request with no subrequests. Such a request was written to the changelog before it failed, so the termination repeated on every restart. [#119847](https://github.com/ClickHouse/ClickHouse/pull/119847) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120620](https://github.com/ClickHouse/ClickHouse/issues/120620): Fixed `PARALLEL WITH`, `EXECUTE AS` and the `QueryRunner` table engine skipping the access checks of the `CREATE` statements they execute, which allowed creating tables and databases without the corresponding privileges, and defeated the `readonly` and `allow_ddl` settings. [#119848](https://github.com/ClickHouse/ClickHouse/pull/119848) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120330](https://github.com/ClickHouse/ClickHouse/issues/120330): Iceberg tables recovered from stored metadata no longer enable background compaction or old-file cleanup unless those settings are explicitly stored in the table definition. [#119977](https://github.com/ClickHouse/ClickHouse/pull/119977) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#120357](https://github.com/ClickHouse/ClickHouse/issues/120357): Fixed a `NATS` table whose settings all come from a named collection (`ENGINE = NATS(collection)` with no `SETTINGS` clause) being written to its metadata file with a dangling `SETTINGS` keyword. The stored definition could not be parsed again, so the table failed to load and aborted the load of its whole database, making unrelated tables in it inaccessible. Closes [#119120](https://github.com/ClickHouse/ClickHouse/issues/119120). [#120025](https://github.com/ClickHouse/ClickHouse/pull/120025) ([Groene AI](https://github.com/groeneai)).
* Backported in [#120568](https://github.com/ClickHouse/ClickHouse/issues/120568): Now ClickHouse reject relative paths in `checksums.txt`. [#120356](https://github.com/ClickHouse/ClickHouse/pull/120356) ([alesapin](https://github.com/alesapin)).
* Backported in [#120560](https://github.com/ClickHouse/ClickHouse/issues/120560): Fix S3 client refresh overwriting static authentication settings and breaking subsequent queries. [#120433](https://github.com/ClickHouse/ClickHouse/pull/120433) ([alesapin](https://github.com/alesapin)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#120541](https://github.com/ClickHouse/ClickHouse/issues/120541): Not required (CI only). [#119999](https://github.com/ClickHouse/ClickHouse/pull/119999) ([Groene AI](https://github.com/groeneai)).
