# 2026 Changelog

### ClickHouse release v26.10.15.10-stable (a08335fbe1a) FIXME as compared to v26.10.14.14-stable (9536e07cbf5)

#### Performance Improvement
* Backported in [#134729](https://github.com/ClickHouse/ClickHouse/issues/134729): The statistics of data parts are loaded in parallel (up to `max_threads` threads) for part pruning by statistics, the ordering of `PREWHERE` conditions and `min`/`max`/`count` from statistics. This speeds up the first queries over tables with many parts on a cold disk. [#126625](https://github.com/ClickHouse/ClickHouse/pull/126625) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#134908](https://github.com/ClickHouse/ClickHouse/issues/134908): The hash tables of large hash `JOIN`s no longer switch to the Robin Hood mode by default (it was enabled in 26.10). This makes joins with random keys up to 1.8 times faster, but the hash table takes up to 1.75 times more memory and joins on dense keys can be up to 1.3 times slower. The new setting `enable_robin_hood_hash_for_joins` turns the mode back on. [#128012](https://github.com/ClickHouse/ClickHouse/pull/128012) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134843](https://github.com/ClickHouse/ClickHouse/issues/134843): A `WHERE` condition on the only column of `ORDER BY ... LIMIT`, like in `SELECT s FROM t WHERE s != '' ORDER BY s LIMIT 10`, is now moved to `PREWHERE` next to the top-K filter, which reads that column anyway, so the query condition cache remembers the granules the condition rejects. Repeated runs of ClickBench Q25 are about 2x faster. [#129882](https://github.com/ClickHouse/ClickHouse/pull/129882) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134828](https://github.com/ClickHouse/ClickHouse/issues/134828): Fixed `NOT_FOUND_COLUMN_IN_BLOCK` for a `SELECT` whose first join is a `FULL JOIN ... USING` on keys of different types, followed by another `USING` join and a `WHERE` over the second join's key. The equi-key filter push-down substituted the coalesced `USING` key by a name the join computes instead of materialising it, so a valid query was rejected. [#120342](https://github.com/ClickHouse/ClickHouse/pull/120342) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134890](https://github.com/ClickHouse/ClickHouse/issues/134890): Fixed a heap-use-after-free in text index queries over overlapping parts, for example in a `FINAL` query with `use_skip_indexes_if_final_exact_mode = 0`. [#134226](https://github.com/ClickHouse/ClickHouse/pull/134226) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134873](https://github.com/ClickHouse/ClickHouse/issues/134873): Fix join orders changed by floating-point rounding when `query_plan_join_order_use_interesting_orders` is enabled, which made some TPC-DS queries slower. [#134792](https://github.com/ClickHouse/ClickHouse/pull/134792) ([Fisnik Kastrati](https://github.com/fkastrati)).

#### Build/Testing/Packaging Improvement
* Backported in [#134748](https://github.com/ClickHouse/ClickHouse/issues/134748): Update `krb5` from 1.22.2-final to 1.22.3-final. [#133845](https://github.com/ClickHouse/ClickHouse/pull/133845) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#134798](https://github.com/ClickHouse/ClickHouse/issues/134798): Update `zstd` to v1.6.0. [#134248](https://github.com/ClickHouse/ClickHouse/pull/134248) ([Actuele AI](https://github.com/actueleai)).
