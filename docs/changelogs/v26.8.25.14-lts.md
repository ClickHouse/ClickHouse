# 2026 Changelog

### ClickHouse release v26.8.25.14-lts (fe4c23110e1) FIXME as compared to v26.8.24.9-lts (575872da1f0)

#### Improvement
* Backported in [#125258](https://github.com/ClickHouse/ClickHouse/issues/125258): Restore min/max pruning of Iceberg data files for a `Decimal(38, 38)` column. A manifest bound of magnitude above roughly 0.7 cannot be widened inside `Int128` and was dropped, which left the column without a min/max condition; it is now saturated at the largest magnitude the precision allows, which is still outside every value the file can hold. [#119712](https://github.com/ClickHouse/ClickHouse/pull/119712) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125242](https://github.com/ClickHouse/ClickHouse/issues/125242): Fixed wrong results and a server abort when a `JOIN ON` condition evaluated during an `ie_join` join contains `arrayJoin`. Such a condition is now rejected with `INVALID_JOIN_ON_EXPRESSION`. Previously `SEMI`/`ANTI`/`LEFT`/`RIGHT`/`FULL` joins using the `ie_join` algorithm could return duplicated or missing rows, or abort the server. [#114325](https://github.com/ClickHouse/ClickHouse/pull/114325) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125270](https://github.com/ClickHouse/ClickHouse/issues/125270): The collections of the Native protocol — the settings and the query parameters of a query, the client information, the granted roles and the table-status lists — are now bounded, so a small packet can no longer make the server allocate memory for data that has not arrived. [#117015](https://github.com/ClickHouse/ClickHouse/pull/117015) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125213](https://github.com/ClickHouse/ClickHouse/issues/125213): Fix the default-enabled `query_plan_merge_expression_into_join` returning rows that violate the query's own `JOIN ON` condition when a subquery computes a non-deterministic expression that is then used as a join key. The merged expression was computed twice from the raw inputs, drawing independently for the match and for the output column. [#117250](https://github.com/ClickHouse/ClickHouse/pull/117250) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125108](https://github.com/ClickHouse/ClickHouse/issues/125108): Fix a vector search returning fewer rows than its `LIMIT`, and missing true nearest neighbours, after a lightweight `DELETE` (or with a delete mutation applied on the fly): the vector index is no longer used for a part while it still holds deleted rows. [#119371](https://github.com/ClickHouse/ClickHouse/pull/119371) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125372](https://github.com/ClickHouse/ClickHouse/issues/125372): Fixed a crash on a query with a deeply nested `Dynamic` or `JSON` constant. [#120885](https://github.com/ClickHouse/ClickHouse/pull/120885) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#125308](https://github.com/ClickHouse/ClickHouse/issues/125308): Fixed excessive memory usage when loading a data part with a corrupted `columns_substreams.txt`; such a part is now detached as broken. [#124157](https://github.com/ClickHouse/ClickHouse/pull/124157) ([Murphy](https://github.com/murphy-4o)).
* Backported in [#125265](https://github.com/ClickHouse/ClickHouse/issues/125265): Fix `NOT_IMPLEMENTED` for an outer `JOIN` with `join_algorithm = 'full_sorting_merge'` when `optimize_and_compare_chain` derived a condition on the preserved side of the join from the `ON` clause. [#124233](https://github.com/ClickHouse/ClickHouse/pull/124233) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#125359](https://github.com/ClickHouse/ClickHouse/issues/125359): Update `mongo-c-driver` to 2.5.5, fixing an out-of-bounds write during MongoDB connection monitoring reconnects (CVE-2026-96746). [#124282](https://github.com/ClickHouse/ClickHouse/pull/124282) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#124459](https://github.com/ClickHouse/ClickHouse/issues/124459): Fixed wrong results when a `WHERE` clause mixing `AND` and `OR` was evaluated with skip indexes (`use_skip_indexes_for_disjunctions`, enabled by default). If a `minmax` or `set` index could not evaluate one atom of the predicate for a granule, the per-atom verdicts recorded for that granule were shifted, so one atom's verdict was applied to another and granules holding matching rows were skipped. [#124303](https://github.com/ClickHouse/ClickHouse/pull/124303) ([Groene AI](https://github.com/groeneai)).

#### Build/Testing/Packaging Improvement
* Backported in [#125337](https://github.com/ClickHouse/ClickHouse/issues/125337): Update `thrift` to v0.25.0. [#124280](https://github.com/ClickHouse/ClickHouse/pull/124280) ([Actuele AI](https://github.com/actueleai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#125364](https://github.com/ClickHouse/ClickHouse/issues/125364): Integration-test harness: tolerate non-UTF-8 bytes when decoding captured container output, so a single bad byte no longer aborts cluster teardown and the sanitizer scan, and honor `shutdown(ignore_sanitizer=True)` in the `docker.log` fallback scan. [#118195](https://github.com/ClickHouse/ClickHouse/pull/118195) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125174](https://github.com/ClickHouse/ClickHouse/issues/125174): Fixed a crash on `INSERT` into a `MergeTree` table when a materialized view over it reads the same table from a correlated subquery, `IN <table>` or a non-leftmost table of an `IN` subquery. [#124740](https://github.com/ClickHouse/ClickHouse/pull/124740) ([Groene AI](https://github.com/groeneai)).
