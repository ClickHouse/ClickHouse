# 2026 Changelog

### ClickHouse release v26.6.4.55-stable (27ca7c373d6) FIXME as compared to v26.6.3.62-stable (c40659002db)

#### Performance Improvement
* Backported in [#117027](https://github.com/ClickHouse/ClickHouse/issues/117027): Push a `WHERE` condition on a `USING` column through a `RIGHT JOIN` so the left `MergeTree` input can use it as a primary-key index condition, also when the two join keys have different types. Applies when `enable_analyzer = 1`. [#103478](https://github.com/ClickHouse/ClickHouse/pull/103478) ([Manuel](https://github.com/raimannma)).
* Backported in [#116312](https://github.com/ClickHouse/ClickHouse/issues/116312): Bounded the cost of estimating the selectivity of `col IN (...)` from column statistics, which could add hundreds of milliseconds to the planning of a single query. The estimator no longer runs the subquery behind `col IN (subquery)` to fill a set it only needs one selectivity number from — an unbuilt set is skipped instead. For a set larger than the new `statistics_max_set_size_for_exact_selectivity_estimation` setting (default 10000), the selectivity is now derived from the size of the set and its bounding range. [#114389](https://github.com/ClickHouse/ClickHouse/pull/114389) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#116282](https://github.com/ClickHouse/ClickHouse/issues/116282): Fixed a CPU regression for queries that issue many independent small reads against the same `MergeTree` part when the table has `LowCardinality` columns. The check deciding whether a part has a single shared dictionary scanned every mark of the whole part on each read task; it now finds each run of equal marks by binary search instead. Queries of this shape on tables with a small `index_granularity` were up to several times slower since 26.6. [#116134](https://github.com/ClickHouse/ClickHouse/pull/116134) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117080](https://github.com/ClickHouse/ClickHouse/issues/117080): Fixed a performance regression since 26.6: a query filtering a `Nullable` column with `IN (subquery)` read the whole table instead of skipping the read when the subquery returned no rows. Closes [#116450](https://github.com/ClickHouse/ClickHouse/issues/116450). [#116538](https://github.com/ClickHouse/ClickHouse/pull/116538) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#117290](https://github.com/ClickHouse/ClickHouse/issues/117290): Sped up SQL function `formatDateTime` with non-const timezone arguments. [#116851](https://github.com/ClickHouse/ClickHouse/pull/116851) ([Robert Schulze](https://github.com/rschu1ze)).

#### Improvement
* Backported in [#116507](https://github.com/ClickHouse/ClickHouse/issues/116507): A `bloom_filter` skip index on an `Array` column is now used for `arrayJoin(column) IN (set)`, `arrayJoin(column) GLOBAL IN (set)` and `arrayJoin(column) = const`, the same way it was already used for `hasAny(column, set)` and `has(column, const)`. Previously these `arrayJoin ...` forms fell back to a full scan. [#109536](https://github.com/ClickHouse/ClickHouse/pull/109536) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116297](https://github.com/ClickHouse/ClickHouse/issues/116297): Use the `bloom_filter` skip index for `IN` predicates on a directly indexed column when `transform_null_in = 1` and the `IN`-set contains no `NULL` value. Previously the index was skipped for such queries, forcing a full scan. [#111329](https://github.com/ClickHouse/ClickHouse/pull/111329) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115793](https://github.com/ClickHouse/ClickHouse/issues/115793): Added a new MergeTree setting `text_index_version` that controls the on-disk format version of text indexes: `v0_initial`, `v1_with_codec`, or `v2_with_positions`. During a rolling upgrade or before a downgrade, set it to an older version so that newer servers keep writing text index parts in a format older servers can still read; the compatibility setting automatically adjusts it. [#111803](https://github.com/ClickHouse/ClickHouse/pull/111803) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#113852](https://github.com/ClickHouse/ClickHouse/issues/113852): Added fs cache download wait timeout configured by `filesystem_cache_wait_for_concurrent_download_timeout_milliseconds`. This timeout defined only the wait for a single chunk (buffer bytes of ~1mb) of data, not the whole file segment. [#113322](https://github.com/ClickHouse/ClickHouse/pull/113322) ([Kseniia Sumarokova](https://github.com/kssenii)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#117052](https://github.com/ClickHouse/ClickHouse/issues/117052): Fix a `LOGICAL_ERROR` ("Different order of columns in UNION subquery") when the old analyzer (`enable_analyzer = 0`) reads a subset of columns from a subquery whose `UNION` children are `INTERSECT`/`EXCEPT` set operations. [#107511](https://github.com/ClickHouse/ClickHouse/pull/107511) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116683](https://github.com/ClickHouse/ClickHouse/issues/116683): Fix an out-of-bounds write when reading a `Variant` column from a malformed Native block whose discriminators reference a variant index that does not exist. [#107991](https://github.com/ClickHouse/ClickHouse/pull/107991) ([uwezkhan](https://github.com/uwezkhan)).
* Backported in [#117051](https://github.com/ClickHouse/ClickHouse/issues/117051): Fix a `LOGICAL_ERROR` (`Different list of shards in child plans`) when running a query with `make_distributed_plan = 1` over a `MergeTree` table that has a normal/aggregate projection. [#108256](https://github.com/ClickHouse/ClickHouse/pull/108256) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115452](https://github.com/ClickHouse/ClickHouse/issues/115452): Fixed `CREATE OR REPLACE MATERIALIZED VIEW ... POPULATE` leaving the new view unsubscribed from its source table, which silently dropped every row inserted after the replace. [#108728](https://github.com/ClickHouse/ClickHouse/pull/108728) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116984](https://github.com/ClickHouse/ClickHouse/issues/116984): Fixed `parallel_view_processing` setting being ignored when inserting into a table with materialized views — since 25.10, views always ran in parallel regardless of the setting. [#109170](https://github.com/ClickHouse/ClickHouse/pull/109170) ([Antonio Andelic](https://github.com/antonio2368)).
* Backported in [#117049](https://github.com/ClickHouse/ClickHouse/issues/117049): Constant folding during query planning no longer executes a function whose argument type differs from the type the function was resolved for during analysis. Such a mismatch used to raise a `LOGICAL_ERROR` while the output header was being computed, which is an assertion failure in debug and sanitizer builds. Folding is now skipped instead, and a genuinely invalid query still reports a recoverable `ILLEGAL_TYPE_OF_ARGUMENT` error from the normal execution path. [#109747](https://github.com/ClickHouse/ClickHouse/pull/109747) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117305](https://github.com/ClickHouse/ClickHouse/issues/117305): Fixed partition pruning returning no rows for Iceberg tables partitioned by a timestamp (DateTime64) column. [#109764](https://github.com/ClickHouse/ClickHouse/pull/109764) ([Den Kalantaevskii](https://github.com/Diskein)).
* Backported in [#114799](https://github.com/ClickHouse/ClickHouse/issues/114799): Fixed a use-after-free when a `JOIN` with `join_algorithm = 'direct'` onto a dictionary was given a join key that is stored with sparse serialization. `getColumnVectorData` returned a reference to a temporary column, so the dictionary lookup read freed memory: release builds could return wrong results and debug or sanitizer builds aborted. [#112327](https://github.com/ClickHouse/ClickHouse/pull/112327) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116654](https://github.com/ClickHouse/ClickHouse/issues/116654): Fixed `Logical error: 'Files metadata is empty'` when reading from, altering, or flushing an `S3Queue`/`AzureQueue` table whose metadata handle is gone: concurrently with a `DROP`/`DETACH`, after a failed `startup`, or after a failed `DROP`. Such a table now reports `TABLE_IS_DROPPED` instead. `SYSTEM FLUSH OBJECT STORAGE QUEUE` on such a table no longer crashes the server. [#113695](https://github.com/ClickHouse/ClickHouse/pull/113695) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115594](https://github.com/ClickHouse/ClickHouse/issues/115594): Fix `Logical error: No set is registered for key ...` when reading through a `Merge` table whose child declares an `ALIAS` column containing `IN`, and the children disagree about that column's default. [#113757](https://github.com/ClickHouse/ClickHouse/pull/113757) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115410](https://github.com/ClickHouse/ClickHouse/issues/115410): Reject corrupted/malicious dictionary where `lcp` exceeds the previous token or `lcp + data_size` overflows, before the buffer write. [#114155](https://github.com/ClickHouse/ClickHouse/pull/114155) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#116961](https://github.com/ClickHouse/ClickHouse/issues/116961): Fixes `ORDER BY ... LIMIT` queries on `Tuple()` columns raising a `NOT_IMPLEMENTED` exception when top-K dynamic filtering is enabled. Direct empty tuples now skip the optimization, while supported nested composite types continue to use top-K filtering. [#114182](https://github.com/ClickHouse/ClickHouse/pull/114182) ([Langning Zhang](https://github.com/Boulea7)).
* Backported in [#116097](https://github.com/ClickHouse/ClickHouse/issues/116097): Register Iceberg namespace in the catalog before writing table files (needed for SeaweedFS). [#114285](https://github.com/ClickHouse/ClickHouse/pull/114285) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#114894](https://github.com/ClickHouse/ClickHouse/issues/114894): Fixes a bug where an access entity carrying a `Map`-valued setting, such as a settings profile with `http_response_headers` or `additional_table_filters`, is stored in a form that ClickHouse cannot read back, leaving the entity permanently unloadable after a restart. [#114620](https://github.com/ClickHouse/ClickHouse/pull/114620) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115712](https://github.com/ClickHouse/ClickHouse/issues/115712): Fixes `has`, `indexOf`, `countEqual`, `mapContainsKey`, `mapContainsValue` and `Map` subscript returning "not found" for a constant `LowCardinality` needle equal to the element type's default value, such as an empty `String` or a zero number. [#114624](https://github.com/ClickHouse/ClickHouse/pull/114624) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116864](https://github.com/ClickHouse/ClickHouse/issues/116864): Fixes a server abort (`Logical error: Part patch-... doesn't exist`) when a `DROP TABLE` runs concurrently with a lightweight `UPDATE` on a `ReplicatedMergeTree` table. The update now holds the table's shared lock until its patch part is committed, so the `DROP` waits instead of removing it. [#114826](https://github.com/ClickHouse/ClickHouse/pull/114826) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116166](https://github.com/ClickHouse/ClickHouse/issues/116166): The AI-function quota settings (`ai_function_max_api_calls_per_query`, `ai_function_max_input_tokens_per_query`, `ai_function_max_output_tokens_per_query`) were enforced per block rather than per query, letting a query exceed the configured limit in proportion to the number of blocks and threads processed. They now bound the whole query per server: the API-call limit is an exact cap (atomic reservation), and the token limits are best-effort. A distributed query enforces the limits independently on each participating server / fragment. [#114885](https://github.com/ClickHouse/ClickHouse/pull/114885) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#115538](https://github.com/ClickHouse/ClickHouse/issues/115538): Fix propagation of query settings and NULL handling in `accurateCastOrDefault`. [#114912](https://github.com/ClickHouse/ClickHouse/pull/114912) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#115858](https://github.com/ClickHouse/ClickHouse/issues/115858): Fixed a hang when dropping a `TimeSeries` table whose name sorts lexicographically below its inner tables' names, for example `` DROP TABLE `-ts` `` or dropping a materialized view declared with `ENGINE = TimeSeries`. The drop self-deadlocked on the DDL guard and could not be cancelled with `KILL QUERY`. [#114953](https://github.com/ClickHouse/ClickHouse/pull/114953) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115369](https://github.com/ClickHouse/ClickHouse/issues/115369): Disable distributed index analysis with projections (wrong results). [#115132](https://github.com/ClickHouse/ClickHouse/pull/115132) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#116535](https://github.com/ClickHouse/ClickHouse/issues/116535): Fixed an out-of-bounds read while deserializing corrupted posting lists of a text index. [#115222](https://github.com/ClickHouse/ClickHouse/pull/115222) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#115471](https://github.com/ClickHouse/ClickHouse/issues/115471): Fixed wrong results for `SELECT count(arrayJoin(arr))` with the default `optimize_trivial_count_query = 1`. The stored row count was returned instead of the number of array elements, and on `file()` and `url()` the query returned `0`. Closes [#115123](https://github.com/ClickHouse/ClickHouse/issues/115123). [#115227](https://github.com/ClickHouse/ClickHouse/pull/115227) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115814](https://github.com/ClickHouse/ClickHouse/issues/115814): Fixed a row policy bypass where the mergeTreeIndex table function exposed primary key and minmax index values of the rows hidden by a SELECT row policy on the source table; reading mergeTreeIndex for a table with a row policy is now denied. [#115304](https://github.com/ClickHouse/ClickHouse/pull/115304) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#116265](https://github.com/ClickHouse/ClickHouse/issues/116265): Fixed a bypass of settings constraints: `SET <name> = DEFAULT` reset a setting without checking the constraints from the user's profile, so a `MIN`/`MAX`/`CONST` constraint could be escaped by resetting the setting instead of assigning to it, and a session could leave readonly mode with `SET readonly = DEFAULT`. [#115334](https://github.com/ClickHouse/ClickHouse/pull/115334) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#117155](https://github.com/ClickHouse/ClickHouse/issues/117155): Fixed a settings-constraint bypass: a `SETTINGS` clause inside a subquery, a CTE or a view's inner query was applied without checking the settings constraints, so it could be used to leave readonly mode or to override a `CONST`, `MIN` or `MAX` constraint (for example `additional_table_filters`, breaking row-level isolation). The nested clause is now clamped to the constraints: violating changes are dropped, out-of-bounds values are clamped into their bounds, and the rest of the clause applies. Existing views whose inner query carries such a clause keep working, with the constraints enforced; a clause on the outer query still throws, as before. [#115397](https://github.com/ClickHouse/ClickHouse/pull/115397) ([Itamar Tempelhof](https://github.com/tempel-it)).
* Backported in [#116403](https://github.com/ClickHouse/ClickHouse/issues/116403): Validate Variant discriminator in ColumnVariant arena deserialization. [#115443](https://github.com/ClickHouse/ClickHouse/pull/115443) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#115601](https://github.com/ClickHouse/ClickHouse/issues/115601): Fixed `uniq`, `uniqExact`, `uniqHLL12` and `uniqTheta` returning a wrong result for an argument wrapped in an injective function that hides nullability, such as `uniqExact(tuple(x))` over a `Nullable` column. The `optimize_injective_functions_inside_uniq` optimization removed the wrapping function, after which NULL rows were skipped instead of counted. [#115466](https://github.com/ClickHouse/ClickHouse/pull/115466) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#115753](https://github.com/ClickHouse/ClickHouse/issues/115753): Fix `read_rows`, `read_bytes`, `written_rows` and `written_bytes` in `system.query_thread_log` reporting a thread lifetime running total instead of the values for the logged query. Rows of long-lived pooled threads, in particular the query's initiating `HTTPHandler` thread, were affected. [#115596](https://github.com/ClickHouse/ClickHouse/pull/115596) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115844](https://github.com/ClickHouse/ClickHouse/issues/115844): Allow KeeperMap readers to accept shared metadata when equivalent primary keys differ only by redundant outer parentheses. [#115642](https://github.com/ClickHouse/ClickHouse/pull/115642) ([Sergey Kuznetsov](https://github.com/skuznetsov-clickhouse)).
* Backported in [#115730](https://github.com/ClickHouse/ClickHouse/issues/115730): Fixed a bug in the function `formatRowNoNewline` that could produce incorrect results or a logical error when a row is formatted to an empty result. [#115669](https://github.com/ClickHouse/ClickHouse/pull/115669) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#115954](https://github.com/ClickHouse/ClickHouse/issues/115954): Fix server crashes on deeply nested input in `readWKB`, `JSONMergePatch`, the address parser of the `url`/`remote`/`cluster`/`mysql`/`postgresql` table functions, the `CURSOR` clause parser and the CapnProto schema parser. Fix a crash in the parser of the `EXECUTE` statement when an argument is not a literal. [#115700](https://github.com/ClickHouse/ClickHouse/pull/115700) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116352](https://github.com/ClickHouse/ClickHouse/issues/116352): Validate the states of the `stochasticLinearRegression`, `stochasticLogisticRegression`, `groupUniqArray`, `groupArrayIntersect` and `topK` aggregate functions and of the `Resample` combinator on deserialization: a malformed state could be read out of bounds. [#115701](https://github.com/ClickHouse/ClickHouse/pull/115701) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#115929](https://github.com/ClickHouse/ClickHouse/issues/115929): Do not return uninitialized memory in the result of a binary string literal whose length is not a multiple of eight, and from the LZ4 decompressor when a compressed block has no body. [#115704](https://github.com/ClickHouse/ClickHouse/pull/115704) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116003](https://github.com/ClickHouse/ClickHouse/issues/116003): Bound the size of the startup message of the PostgreSQL wire protocol, which is read before authentication. [#115708](https://github.com/ClickHouse/ClickHouse/pull/115708) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116752](https://github.com/ClickHouse/ClickHouse/issues/116752): Reject unsupported and mixed read/write operations in ZooKeeper multi requests. [#115768](https://github.com/ClickHouse/ClickHouse/pull/115768) ([Antonio Andelic](https://github.com/antonio2368)).
* Backported in [#116862](https://github.com/ClickHouse/ClickHouse/issues/116862): Mask the `aws_external_id` setting of the `DataLakeCatalog` database engine in `SHOW CREATE DATABASE` and `system.databases.engine_full`. It was previously printed in plaintext, unlike the other AWS credential settings. Closes: [#114999](https://github.com/ClickHouse/ClickHouse/issues/114999). [#115791](https://github.com/ClickHouse/ClickHouse/pull/115791) ([Groene AI](https://github.com/groeneai)).

The function now reports the certificate that is actually served, also after a certificate reload. [#115976](https://github.com/ClickHouse/ClickHouse/pull/115976) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

Such children are now always read, and the condition filters their rows. [#116371](https://github.com/ClickHouse/ClickHouse/pull/116371) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#117150](https://github.com/ClickHouse/ClickHouse/issues/117150): Sizes declared by a server in the Native protocol no longer make the client allocate memory for data that has not arrived: exception strings are read as they arrive, the decompressed size of a block is bounded, and the maximum number of rows in a `Native` block is now a billion. [#117011](https://github.com/ClickHouse/ClickHouse/pull/117011) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
