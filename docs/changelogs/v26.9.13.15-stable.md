# 2026 Changelog

### ClickHouse release v26.9.13.15-stable (4b131779967) FIXME as compared to v26.9.12.8-stable (142137457b0)

#### Performance Improvement
* Backported in [#124219](https://github.com/ClickHouse/ClickHouse/issues/124219): A `WHERE` that no row passes is pushed to every `JOIN` input again, including the non-preserved side of an `OUTER JOIN` and a side with no column used above the join, so that input is no longer read and hash-built for nothing. For example, a `UNION ALL` branch whose constant column fails the outer `WHERE` is skipped as in 26.6. Closes [#123702](https://github.com/ClickHouse/ClickHouse/issues/123702), closes [#123878](https://github.com/ClickHouse/ClickHouse/issues/123878). [#123829](https://github.com/ClickHouse/ClickHouse/pull/123829) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124429](https://github.com/ClickHouse/ClickHouse/issues/124429): Hash joins with many matches per key are faster when they output a `LowCardinality` column whose blocks have different dictionaries (several parts, `FINAL`, or a `LowCardinality` value computed per block): short ranges from another dictionary are now inserted key by key instead of through temporary columns. Such joins run 4-9x faster, at the 26.6 level or better. [#123900](https://github.com/ClickHouse/ClickHouse/pull/123900) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#123439](https://github.com/ClickHouse/ClickHouse/issues/123439): Added the setting `query_plan_filter_push_down_below_limit_by` (default `1`), controlling whether filters on `LIMIT BY` key columns are pushed below the `LIMIT BY` step. Setting it to `0` restores the plan shape used before 26.7, for queries where the pushed predicate makes index analysis costlier than the scan it saves. [#121675](https://github.com/ClickHouse/ClickHouse/pull/121675) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124416](https://github.com/ClickHouse/ClickHouse/issues/124416): Mask secrets in the queries that a cluster-mode `QueryRunner` table writes to `system.query_log` as well as in queries executed as startup scripts. [#118978](https://github.com/ClickHouse/ClickHouse/pull/118978) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#124506](https://github.com/ClickHouse/ClickHouse/issues/124506): Tables in a database with `lazy_load_tables` were missing from `system.parts`, `system.replicas` and related system tables, and refused by replica commands, after a restart. [#121332](https://github.com/ClickHouse/ClickHouse/pull/121332) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#124400](https://github.com/ClickHouse/ClickHouse/issues/124400): Fix a server abort when reading an Iceberg table whose sort order names a transform ClickHouse cannot parse (e.g. `bucket[xyz]`); ClickHouse now ignores that sort-order hint and keeps the table readable. [#121687](https://github.com/ClickHouse/ClickHouse/pull/121687) ([Ilias](https://github.com/iliasabk)).
* Backported in [#124245](https://github.com/ClickHouse/ClickHouse/issues/124245): Comparing an `Enum` column with a string literal that is not one of its elements no longer throws `UNKNOWN_ELEMENT_OF_ENUM` when `validate_enum_literals_in_operators` is disabled (the default) and the column is part of the primary key, the partition key, or a `bloom_filter` index. `!=` with such a literal now returns true for every row instead of throwing. Closes [#122235](https://github.com/ClickHouse/ClickHouse/issues/122235), [#111545](https://github.com/ClickHouse/ClickHouse/issues/111545). [#122672](https://github.com/ClickHouse/ClickHouse/pull/122672) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#124312](https://github.com/ClickHouse/ClickHouse/issues/124312): Fix `Found patch part ... that intersects mutation with version ...` on lightweight updates in a table created with `CREATE TABLE ... CLONE AS` or `ATTACH PARTITION ALL FROM` a table with lightweight updates. [#123620](https://github.com/ClickHouse/ClickHouse/pull/123620) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#124337](https://github.com/ClickHouse/ClickHouse/issues/124337): Fix `UNKNOWN_IDENTIFIER` in the analyzer when a table is referenced as `database.table` in `FROM` or `JOIN` and another table expression in the same query uses that database name as its alias, for example `FROM db.t1 AS db INNER JOIN db.t2 AS t ON ...`. Closes [#122239](https://github.com/ClickHouse/ClickHouse/issues/122239). [#124262](https://github.com/ClickHouse/ClickHouse/pull/124262) ([Dmitry Novik](https://github.com/novikd)).
* Backported in [#124460](https://github.com/ClickHouse/ClickHouse/issues/124460): Fixed wrong results when a `WHERE` clause mixing `AND` and `OR` was evaluated with skip indexes (`use_skip_indexes_for_disjunctions`, enabled by default). If a `minmax` or `set` index could not evaluate one atom of the predicate for a granule, the per-atom verdicts recorded for that granule were shifted, so one atom's verdict was applied to another and granules holding matching rows were skipped. [#124303](https://github.com/ClickHouse/ClickHouse/pull/124303) ([Groene AI](https://github.com/groeneai)).
* Fix `iceberg_tolerate_conflicting_manifest_schemas` being reverted to `false` by `compatibility` settings of 26.8 or 26.9 on 26.9 servers, which made Iceberg reads fail with `ICEBERG_SPECIFICATION_VIOLATION` on tables whose manifest schemas conflict with `metadata.json`. [#124319](https://github.com/ClickHouse/ClickHouse/pull/124319) ([Asya Shneerson](https://github.com/asya-ch)).
