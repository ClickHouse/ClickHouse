# 2026 Changelog

### ClickHouse release v26.7.17.7-stable (7abaef160ce) FIXME as compared to v26.7.16.2-stable (92c4ed09b4b)

#### Performance Improvement
* Backported in [#122649](https://github.com/ClickHouse/ClickHouse/issues/122649): Chained `ARRAY JOIN`s no longer materialize the whole block of a lazily replicated array column before expanding it, which cuts their peak memory by several times. [#121397](https://github.com/ClickHouse/ClickHouse/pull/121397) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#122732](https://github.com/ClickHouse/ClickHouse/issues/122732): Fixed silently empty tables when more than one `ENGINE = Backup` database is created from the same backup, or when such a database is recreated under a different name. The storage policy that backs a `Backup` database is now identified by a name that also covers the local database name, so each database gets the disk built for its own data path. [#113378](https://github.com/ClickHouse/ClickHouse/pull/113378) ([Groene AI](https://github.com/groeneai)).
* Backported in [#122641](https://github.com/ClickHouse/ClickHouse/issues/122641): `ALTER DATABASE ... MODIFY COMMENT` on a database with `ENGINE = Backup` no longer writes a definition the server cannot read back, which made it refuse to start; metadata already written in that form now loads too. Backward incompatibility: a backup taken by an older server of a database with `ENGINE = Backup` stores the locator quoted into a string literal, and such a definition is no longer accepted from a `RESTORE`. Restoring it onto a missing database fails with `Expected function`, and onto an existing one with `CANNOT_RESTORE_DATABASE` because the live definition now spells the locator as a function; use `SETTINGS allow_different_database_def = 1` for the latter, or recreate the database with the function form. [#118674](https://github.com/ClickHouse/ClickHouse/pull/118674) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#122639](https://github.com/ClickHouse/ClickHouse/issues/122639): Fixed settings constraints from a settings profile not being enforced against the other setting assignments in the same statement. `SET profile = 'p', <setting> = <value>` could override a `CONST`, `MIN`/`MAX` or `readonly` constraint that profile `p` installs. The same escape existed through an in-query `SETTINGS` clause, HTTP URL parameters and Arrow Flight session options. [#120376](https://github.com/ClickHouse/ClickHouse/pull/120376) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#122581](https://github.com/ClickHouse/ClickHouse/issues/122581): Fix a segmentation fault in Keeper when preallocating space for a changelog file fails because the disk is full. [#122337](https://github.com/ClickHouse/ClickHouse/pull/122337) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#122734](https://github.com/ClickHouse/ClickHouse/issues/122734): Link with `--icf=safe` instead of `--icf=all`, so the linker keeps functions whose address is taken distinct. gRPC queries with transport compression (`gzip`, `deflate`) no longer crash the server, as they could in official builds since 26.4. Closes [#115121](https://github.com/ClickHouse/ClickHouse/issues/115121). [#122668](https://github.com/ClickHouse/ClickHouse/pull/122668) ([Groene AI](https://github.com/groeneai)).
