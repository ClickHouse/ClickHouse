# 2026 Changelog

### ClickHouse release v26.10.14.14-stable (9536e07cbf5) FIXME as compared to v26.10.13.11-stable (f3cdd2bf78e)

#### Performance Improvement
* Backported in [#134439](https://github.com/ClickHouse/ClickHouse/issues/134439): Reduced CPU usage when many threads schedule jobs into a full thread pool, for example while loading many tables at server startup. [#129010](https://github.com/ClickHouse/ClickHouse/pull/129010) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#134576](https://github.com/ClickHouse/ClickHouse/issues/134576): With parallel replicas, every replica now applies its own query condition cache to the ranges the coordinator assigns it. Previously only the replica whose index analysis drove the assignment benefited from the cache. [#129375](https://github.com/ClickHouse/ClickHouse/pull/129375) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#134148](https://github.com/ClickHouse/ClickHouse/issues/134148): Reads from encrypted disks on remote storage no longer open an extra S3 request for every column file when reading the encryption header. [#133724](https://github.com/ClickHouse/ClickHouse/pull/133724) ([Christoph Wurm](https://github.com/cwurm)).
* Backported in [#134671](https://github.com/ClickHouse/ClickHouse/issues/134671): Wake idle ThreadPool thread after releasing the pool mutex. [#134433](https://github.com/ClickHouse/ClickHouse/pull/134433) ([Azat Khuzhin](https://github.com/azat)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134401](https://github.com/ClickHouse/ClickHouse/issues/134401): Fix `tupleElement` with a default argument over an `ARRAY JOIN`-ed `Nested` column, when the default references another subcolumn of an `ARRAY JOIN`-ed column. [#129581](https://github.com/ClickHouse/ClickHouse/pull/129581) ([Henry Su](https://github.com/hsusul)).
* Backported in [#134450](https://github.com/ClickHouse/ClickHouse/issues/134450): `CREATE`, `ALTER`, `DROP` and `MOVE ROW POLICY ... ON CLUSTER` with a table name without a database now apply to the table in the current database, the one the privileges are checked against. Previously every host applied them to the table with that name in the server's default database. [#130673](https://github.com/ClickHouse/ClickHouse/pull/130673) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134549](https://github.com/ClickHouse/ClickHouse/issues/134549): The `Kafka` table engine no longer accepts `librdkafka` properties that refer to files on the server (for example, `kafka.ssl_ca_location`, `kafka.ssl_key_location`, `kafka.sasl_kerberos_keytab`) from a named collection created with `CREATE NAMED COLLECTION`. Such a table fails with `BAD_ARGUMENTS`, and an existing table stops consuming and producing until the collection is changed. Define the collection in the server configuration file, or pass the contents of the file with the `.pem` properties (for example, `kafka.ssl_ca_pem`). [#132488](https://github.com/ClickHouse/ClickHouse/pull/132488) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#134533](https://github.com/ClickHouse/ClickHouse/issues/134533): `ATTACH MATERIALIZED VIEW` with a full definition now validates the `SELECT` query the same way as `CREATE MATERIALIZED VIEW`. [#133025](https://github.com/ClickHouse/ClickHouse/pull/133025) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Backported in [#134418](https://github.com/ClickHouse/ClickHouse/issues/134418): Fix a segfault in a `SELECT` from a `MergeTree` table with the old analyzer (`enable_analyzer = 0`) when `query_plan_optimize_prewhere` or `query_plan_enable_optimizations` is disabled. [#133157](https://github.com/ClickHouse/ClickHouse/pull/133157) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#134519](https://github.com/ClickHouse/ClickHouse/issues/134519): With `access_control_improvements.readonly_restricts_set_role` enabled, `SET DEFAULT ROLE` is now refused in `readonly` mode as well as `SET ROLE`. Previously a readonly session could change its own default roles and so start the next session with another role. [#133762](https://github.com/ClickHouse/ClickHouse/pull/133762) ([Vadim Skipin](https://github.com/vadimskipin)).
* Backported in [#134414](https://github.com/ClickHouse/ClickHouse/issues/134414): Fix substring conditions (`LIKE`, `endsWith`, ...) on a `String` column of the sorting key ignoring a lightweight `DELETE` or `UPDATE` that is not merged into the part yet (deleted rows were returned, updated values were not seen), when `apply_string_filters_during_scan` is enabled (the default). Closes [#133917](https://github.com/ClickHouse/ClickHouse/issues/133917). [#134050](https://github.com/ClickHouse/ClickHouse/pull/134050) ([Groene AI](https://github.com/groeneai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#134386](https://github.com/ClickHouse/ClickHouse/issues/134386): Fix TOO_SLOW in external aggregation overflow any tests. [#131034](https://github.com/ClickHouse/ClickHouse/pull/131034) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#134290](https://github.com/ClickHouse/ClickHouse/issues/134290): When a MergeTree table was created with table_disk=1, it stores all data (parts/tmp files/detached directory) in the root of this disk, and when this table is dropped, dropAllData calls remove-recursive on the root folder. When this table was located on the encrypted disk, this call would, in fact, remove the root folder of that disk. The problem is that if other normal tables (without table_disk) were created there, this call would remove their data as well. [#134192](https://github.com/ClickHouse/ClickHouse/pull/134192) ([Mikhail Artemenko](https://github.com/Michicosun)).
