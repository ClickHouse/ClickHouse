# 2026 Changelog

### ClickHouse release v26.8.24.9-lts (575872da1f0) FIXME as compared to v26.8.23.6-lts (4ba605fc98d)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125101](https://github.com/ClickHouse/ClickHouse/issues/125101): Fixed wrong results for a comma or `CROSS` join whose `WHERE` compares columns of two tables through a non-deterministic expression such as `rand`. Such a query could return rows that contradict its own `WHERE` clause, because rewriting the join into an `INNER` join moved the expression into the join key, where it is evaluated again per row of each side. [#112938](https://github.com/ClickHouse/ClickHouse/pull/112938) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125086](https://github.com/ClickHouse/ClickHouse/issues/125086): Fixed `TRUNCATE TABLE` of an `Alias` table whose target is a `MergeTree` failing with `DEADLOCK_AVOIDED` when the alias is being read concurrently, while the same statement against the target table succeeds immediately. The lock for `TRUNCATE` is now chosen and taken on the table that executes the truncate, so an `Alias` follows its target's engine. [#119105](https://github.com/ClickHouse/ClickHouse/pull/119105) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125096](https://github.com/ClickHouse/ClickHouse/issues/125096): Fixed wrong results, or an `ILLEGAL_COLUMN` error, of a `JOIN` whose condition equates both a column and an expression of that column (for example `ON t1.k = t2.k AND intDiv(t1.k, 2) = intDiv(t2.k, 2)`) when a filter on that expression is pushed down to the other side of the join: the pushed-down copy applied the expression twice. Closes [#122613](https://github.com/ClickHouse/ClickHouse/issues/122613). [#122686](https://github.com/ClickHouse/ClickHouse/pull/122686) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124491](https://github.com/ClickHouse/ClickHouse/issues/124491): Fixed parallel replicas not being used when reading a `Distributed` table whose underlying table is another `Distributed` table and every shard of the outer cluster has a single replica. [#123566](https://github.com/ClickHouse/ClickHouse/pull/123566) ([Igor Nikonov](https://github.com/devcrafter)).
* Backported in [#125061](https://github.com/ClickHouse/ClickHouse/issues/125061): Fixed duplicated rows returned by `ANY RIGHT JOIN` with `any_join_distinct_right_table_keys = 1` when parallel replicas are enabled. [#123683](https://github.com/ClickHouse/ClickHouse/pull/123683) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125113](https://github.com/ClickHouse/ClickHouse/issues/125113): Fixed slow planning of queries with skip indexes on tables with many parts and pending patch parts of lightweight updates. [#124931](https://github.com/ClickHouse/ClickHouse/pull/124931) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#125056](https://github.com/ClickHouse/ClickHouse/issues/125056): Fixed a crash (stack overflow) when reading an Avro file with an explicit structure that does not read a field nested through a long chain of named types, or a field of a recursive type holding deeply nested data such as a long linked list. Such a file now fails with `TOO_DEEP_RECURSION` instead. Closes [#124925](https://github.com/ClickHouse/ClickHouse/issues/124925). [#124964](https://github.com/ClickHouse/ClickHouse/pull/124964) ([Groene AI](https://github.com/groeneai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#125059](https://github.com/ClickHouse/ClickHouse/issues/125059): Do not use parallel replicas for `clusterAllReplicas`. [#124724](https://github.com/ClickHouse/ClickHouse/pull/124724) ([Igor Nikonov](https://github.com/devcrafter)).
