# 2026 Changelog

### ClickHouse release v26.3.40.16-lts (7a43e67d13f) FIXME as compared to v26.3.39.7-lts (4277fab4705)

#### Performance Improvement
* Backported in [#123474](https://github.com/ClickHouse/ClickHouse/issues/123474): Faster planning of queries to Iceberg tables with many manifest files: when a manifest file header has the `schema-id` key and that schema is already known from metadata.json, the schema copy stored in the manifest header is no longer parsed and compared with it. ClickHouse now also writes the `schema-id` key into the headers of manifest files it creates. [#122574](https://github.com/ClickHouse/ClickHouse/pull/122574) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Improvement
* Backported in [#123276](https://github.com/ClickHouse/ClickHouse/issues/123276): Hide the HTTP headers in the definition of `HTTP` dictionary sources in `SHOW CREATE DICTIONARY`, `system.tables` and query logs, the same way as passwords. They can be shown with the existing `display_secrets_in_show_and_select` mechanism. [#122673](https://github.com/ClickHouse/ClickHouse/pull/122673) ([Matheus Nerone](https://github.com/Manerone)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#123524](https://github.com/ClickHouse/ClickHouse/issues/123524): Fixed a transient `Code: 499 ... InvalidPart` (`S3_ERROR`) failure on S3 multipart uploads (for example `INSERT INTO ... hits_s3`). MinIO can briefly report a just-uploaded part as missing on `CompleteMultipartUpload`; this error is now retried like the already-handled `NoSuchKey`, bounded by `s3_max_unexpected_write_error_retries`. [#109364](https://github.com/ClickHouse/ClickHouse/pull/109364) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123458](https://github.com/ClickHouse/ClickHouse/issues/123458): Fixed `max_memory_usage` and `max_server_memory_usage` not being respected when reading a `JSON` column with the `FLATTENED` serialization version from the `Native` format. [#117730](https://github.com/ClickHouse/ClickHouse/pull/117730) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123465](https://github.com/ClickHouse/ClickHouse/issues/123465): Fixed out-of-bounds reads when reading a `JSON` or `Dynamic` column from a malformed `Native` block or a corrupted data part. A truncated stream, a duplicate type in a flattened `Dynamic` column, a duplicate or typed-colliding path in a `JSON` column, and a serialization version that is only ever written into a data part but sent over the wire, all made the server read past the end of a deserialized column, which could crash it or store unrelated heap contents in the inserted data. All of them are now rejected. [#117765](https://github.com/ClickHouse/ClickHouse/pull/117765) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123453](https://github.com/ClickHouse/ClickHouse/issues/123453): `EXPLAIN AST` printed secret function arguments, such as the key of `encrypt`, in clear text, and with `optimize = 1` it did so for the body of a view the user may only `SELECT` from. The dump now prints `'[HIDDEN]'` in their place, under the same gate as `SHOW CREATE`. [#120313](https://github.com/ClickHouse/ClickHouse/pull/120313) ([Harikrishnan Prabakaran](https://github.com/harikrishnan94)).
* Backported in [#123504](https://github.com/ClickHouse/ClickHouse/issues/123504): Column-level `SELECT` privileges are now enforced for columns used only inside `indexHint` and for `ALIAS` columns referenced in `PREWHERE`. As in `WHERE`, referencing an `ALIAS` column in `PREWHERE` requires the grant on the alias name; a grant on its source columns is no longer sufficient. A metadata-only `ALTER` that changes a subcolumn read by a `MATERIALIZED` column through an `ALIAS` is now refused like a direct reference. [#120516](https://github.com/ClickHouse/ClickHouse/pull/120516) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Backported in [#123280](https://github.com/ClickHouse/ClickHouse/issues/123280): Fixed a row policy bypass: a direct `JOIN` with an `EmbeddedRocksDB`, `KeeperMap` or `Redis` table in the legacy analyzer (`enable_analyzer = 0`) ignored the row policy of the right table and returned hidden rows, and `joinGet` on a `Join` table ignored its row policy in both analyzers. Such a table is now joined through its query plan, which keeps the filter, and `JOIN` or `joinGet` against a `Join` table under a row policy throws `ACCESS_DENIED`. [#121398](https://github.com/ClickHouse/ClickHouse/pull/121398) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#123497](https://github.com/ClickHouse/ClickHouse/issues/123497): Fix the Kafka and NATS table engines ignoring `remote_url_allow_hosts`: broker addresses from `kafka_broker_list`, `nats_url`, and `nats_server_list` are now checked against the remote host filter. A forbidden address is rejected at `CREATE TABLE` with `UNACCEPTABLE_URL`, as the RabbitMQ engine already does. [#121825](https://github.com/ClickHouse/ClickHouse/pull/121825) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#123516](https://github.com/ClickHouse/ClickHouse/issues/123516): Fix filesystem cache accounting when the directory for a new cache key cannot be created, for example because the cache disk is out of space or inodes. The failed reservation stayed counted in the cache until the query released the file segment. [#122211](https://github.com/ClickHouse/ClickHouse/pull/122211) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#123554](https://github.com/ClickHouse/ClickHouse/issues/123554): `CREATE OR REPLACE` in a `Replicated` database or with `ON CLUSTER` now requires the drop privilege for the kind of the table it replaces, so a user without `DROP DICTIONARY` can no longer replace a dictionary. [#122272](https://github.com/ClickHouse/ClickHouse/pull/122272) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#123470](https://github.com/ClickHouse/ClickHouse/issues/123470): Fix a server crash caused by unbounded recursion when decoding a deeply nested value inside a binary encoded type, for example an `AggregateFunction` parameter in a `Dynamic` value read from `RowBinary` or `Native`. [#122667](https://github.com/ClickHouse/ClickHouse/pull/122667) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123484](https://github.com/ClickHouse/ClickHouse/issues/123484): Fix validation of Iceberg manifest-list entries during writes. [#122829](https://github.com/ClickHouse/ClickHouse/pull/122829) ([Arsen Muk](https://github.com/arsenmuk)).
* Backported in [#123512](https://github.com/ClickHouse/ClickHouse/issues/123512): S3 client check initial url in backup client. [#123114](https://github.com/ClickHouse/ClickHouse/pull/123114) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#123445](https://github.com/ClickHouse/ClickHouse/issues/123445): Do not dereference a null `logs_queue` in `OwnSplitChannel::log`. [#123336](https://github.com/ClickHouse/ClickHouse/pull/123336) ([Groene AI](https://github.com/groeneai)).
