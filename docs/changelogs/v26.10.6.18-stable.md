# 2026 Changelog

### ClickHouse release v26.10.6.18-stable (68f652e0c11) FIXME as compared to v26.10.5.57-stable (25ea79f784e)

#### Performance Improvement
* Backported in [#132356](https://github.com/ClickHouse/ClickHouse/issues/132356): Fix cubic complexity of enumerating subcolumns of deeply nested `Array` types. [#126554](https://github.com/ClickHouse/ClickHouse/pull/126554) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132391](https://github.com/ClickHouse/ClickHouse/issues/132391): Parsing row-based input formats and `Native` into tables with nested `Tuple` columns is faster for small blocks (streaming engines, async inserts): the per-block columns are now created once per nested element instead of once per nesting level. Closes [#127427](https://github.com/ClickHouse/ClickHouse/issues/127427). [#127859](https://github.com/ClickHouse/ClickHouse/pull/127859) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132496](https://github.com/ClickHouse/ClickHouse/issues/132496): `SELECT ... FINAL WHERE <filter> LIMIT n` on a `ReplacingMergeTree` table with `enable_vertical_final` (the default) now stops reading early when the rows that pass the filter come from a small part, instead of reading the whole table. Closes [#131381](https://github.com/ClickHouse/ClickHouse/issues/131381). [#131560](https://github.com/ClickHouse/ClickHouse/pull/131560) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132482](https://github.com/ClickHouse/ClickHouse/issues/132482): Fixed queries and merges on encrypted disks over remote storage discarding the first prefetch of every column and reading it again synchronously. [#132015](https://github.com/ClickHouse/ClickHouse/pull/132015) ([Christoph Wurm](https://github.com/cwurm)).

#### Improvement
* Backported in [#132329](https://github.com/ClickHouse/ClickHouse/issues/132329): Range conditions such as `x < 100` on a column with `tdigest` statistics are now estimated correctly on tables with several parts. Previously the estimate depended on the order of the parts and could be zero, so the planner could pick a worse join order, PREWHERE order or distributed plan. [#126385](https://github.com/ClickHouse/ClickHouse/pull/126385) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132455](https://github.com/ClickHouse/ClickHouse/issues/132455): Improved logic of matching read steps between single-node and parallel replicas plans. This fixes a potential wrong query result in case of an incorrect matching and also makes the automatic parallel replicas optimization applicable to more queries. [#125687](https://github.com/ClickHouse/ClickHouse/pull/125687) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#132537](https://github.com/ClickHouse/ClickHouse/issues/132537): Fix a valid `JOIN ON` query rejected with `CANNOT_CONVERT_TYPE` by `optimize_extract_common_expressions` when the extraction removes the only `Nothing`-typed operand, for example a comparison with an `ARRAY JOIN []` alias. Closes [#124771](https://github.com/ClickHouse/ClickHouse/issues/124771). [#129148](https://github.com/ClickHouse/ClickHouse/pull/129148) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132509](https://github.com/ClickHouse/ClickHouse/issues/132509): Prevent impersonation via forged SECONDARY_QUERY on secret clusters. [#130362](https://github.com/ClickHouse/ClickHouse/pull/130362) ([Vitaly Baranov](https://github.com/vitlibar)).
* Backported in [#132386](https://github.com/ClickHouse/ClickHouse/issues/132386): Projections no longer provide `_block_number`, `_block_offset` and `_row_exists` unless they store them, so queries reading these columns use the main table. Previously the values came from the projection part, which caused wrong results and made incremental refreshable materialized views (`APPEND INCREMENTAL`) silently skip source rows. [#130515](https://github.com/ClickHouse/ClickHouse/pull/130515) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Backported in [#132490](https://github.com/ClickHouse/ClickHouse/issues/132490): Fix server termination when outdated data parts cannot be scheduled for loading, e.g. when the global thread pool is exhausted. [#130816](https://github.com/ClickHouse/ClickHouse/pull/130816) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#132081](https://github.com/ClickHouse/ClickHouse/issues/132081): Fix the logical error `Context has expired` when the Kusto `*` operator (`kqlMultiply`) is used in a query with parallel replicas. [#131363](https://github.com/ClickHouse/ClickHouse/pull/131363) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132472](https://github.com/ClickHouse/ClickHouse/issues/132472): The error of AI functions for an insecure endpoint no longer contains the endpoint of the named collection, which could carry a secret not visible to the user. [#131438](https://github.com/ClickHouse/ClickHouse/pull/131438) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#132374](https://github.com/ClickHouse/ClickHouse/issues/132374): `SYSTEM SYNC DATABASE REPLICA` without `ON CLUSTER` now requires the `SYSTEM SYNC DATABASE REPLICA` grant on the database. Before, any user could run it. [#131893](https://github.com/ClickHouse/ClickHouse/pull/131893) ([Lazizbek Ergashev](https://github.com/lazerg)).
* Backported in [#132403](https://github.com/ClickHouse/ClickHouse/issues/132403): Fix an asynchronous `INSERT ... FROM INFILE` sent directly to the server opening the file on the server before the query was rejected. [#132305](https://github.com/ClickHouse/ClickHouse/pull/132305) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#132462](https://github.com/ClickHouse/ClickHouse/issues/132462): Fix a server crash when deserializing a malformed aggregate state that contains a `LowCardinality(String)` value. [#132322](https://github.com/ClickHouse/ClickHouse/pull/132322) ([Raúl Marín](https://github.com/Algunenano)).

#### Build/Testing/Packaging Improvement
* Backported in [#132051](https://github.com/ClickHouse/ClickHouse/issues/132051): Update `wasmtime` to v50.0.1. [#128834](https://github.com/ClickHouse/ClickHouse/pull/128834) ([Konstantin Bogdanov](https://github.com/thevar1able)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#132425](https://github.com/ClickHouse/ClickHouse/issues/132425): Keep the identity of a set in the cache key of an expression. [#132104](https://github.com/ClickHouse/ClickHouse/pull/132104) ([Nikita Taranov](https://github.com/nickitat)).
