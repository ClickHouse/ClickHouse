# 2026 Changelog

### ClickHouse release v26.10.8.34-stable (6e92eea6c05) FIXME as compared to v26.10.7.24-stable (55d02f6a03f)

#### Performance Improvement
* Backported in [#133026](https://github.com/ClickHouse/ClickHouse/issues/133026): The `dpsub` join order algorithm is now aware of the sort order of the joined tables: for each inner equi-join it chooses between a hash join and `full_sorting_merge` by cost, and keeps join results sorted by a join key when a later join can use that order. Joins of large `MergeTree` tables on their sorting key use much less memory and run faster. Controlled by the new setting `query_plan_join_order_use_interesting_orders`, enabled by default. [#128519](https://github.com/ClickHouse/ClickHouse/pull/128519) ([Fisnik Kastrati](https://github.com/fkastrati)).
* Backported in [#132944](https://github.com/ClickHouse/ClickHouse/issues/132944): A `JOIN` executed with the `ie_join` algorithm (by default, a `JOIN` whose `ON` section has only inequality conditions) no longer slows down quadratically when one side is much larger than the other: a range join of 1 million rows against a 16-row table now takes 0.1 seconds instead of 3.6 seconds. Closes [#131229](https://github.com/ClickHouse/ClickHouse/issues/131229). [#131335](https://github.com/ClickHouse/ClickHouse/pull/131335) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#133072](https://github.com/ClickHouse/ClickHouse/issues/133072): Add AI function request time, retry backoff time, and prompt-cache token counts to `ProfileEvents`. Include cached Anthropic input tokens in total input usage and query quotas. [#122559](https://github.com/ClickHouse/ClickHouse/pull/122559) ([Ravi Kumar L](https://github.com/upman)).
* Backported in [#133034](https://github.com/ClickHouse/ClickHouse/issues/133034): Add the `allow_ai_functions` setting, which disables AI functions when set to `0`. [#131120](https://github.com/ClickHouse/ClickHouse/pull/131120) ([George Larionov](https://github.com/george-larionov)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132956](https://github.com/ClickHouse/ClickHouse/issues/132956): Fixed projections returning rows removed by a lightweight `DELETE` after `ALTER UPDATE`, `MATERIALIZE PROJECTION` or `CLEAR COLUMN` rebuilt them on a Wide part. A query with `apply_deleted_mask = 0` no longer uses projections when the table has lightweight-deleted rows, since projections do not store them. On release branches this also fixes a normal projection without a `WHERE` keeping the rows removed by a `rebuild`-mode lightweight `DELETE`, which [#118375](https://github.com/ClickHouse/ClickHouse/issues/118375) fixed on master. [#111809](https://github.com/ClickHouse/ClickHouse/pull/111809) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133002](https://github.com/ClickHouse/ClickHouse/issues/133002): Fix a server abort in `ORDER BY ... WITH FILL ... INTERPOLATE (...)` when the same column is named as an `INTERPOLATE` output more than once, for example `INTERPOLATE (b AS b, b AS b)`. Such a query is now rejected with `INVALID_WITH_FILL_EXPRESSION` during query analysis instead of aborting the server as soon as a row is filled. Closes [#120645](https://github.com/ClickHouse/ClickHouse/issues/120645). [#120748](https://github.com/ClickHouse/ClickHouse/pull/120748) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133001](https://github.com/ClickHouse/ClickHouse/issues/133001): Fix a server crash when a `RIGHT JOIN`/`FULL JOIN` is planned for parallel replicas (`parallel_replicas_plan_based=1`) and the join output header declares a column by type only — e.g. the residual column of a constant `NULL` conjunct in the `ON` clause. Type-only header columns are now materialized as an empty column of the declared type instead of being dereferenced as null. [#122128](https://github.com/ClickHouse/ClickHouse/pull/122128) ([Ilias](https://github.com/iliasabk)).
* Backported in [#132966](https://github.com/ClickHouse/ClickHouse/issues/132966): Check access rights before loading a dictionary or reading its definition in the `dictionary` table function, `dictGet`-family functions, `naiveBayesClassifier`, `Dictionary` tables and `CREATE TABLE ... ENGINE = Dictionary`. Queries without the required grants no longer trigger the dictionary load, and queries or DDL that reference a dictionary now require access to it even when they do not read it, e.g. `DESCRIBE`, `CREATE VIEW` or a `DEFAULT dictGet(...)` column. [#122678](https://github.com/ClickHouse/ClickHouse/pull/122678) ([Matheus Nerone](https://github.com/Manerone)).
* Backported in [#133055](https://github.com/ClickHouse/ClickHouse/issues/133055): Fixed an exception (such as `Division by zero` or `Cannot parse input`) when a `_part_offset` projection used as an index evaluated the query filter on rows the query does not read. [#124971](https://github.com/ClickHouse/ClickHouse/pull/124971) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133036](https://github.com/ClickHouse/ClickHouse/issues/133036): Fix `ALTER TABLE ... DROP PARTITION` for Iceberg tables. When the parent snapshot was an `overwrite`, the command failed with `Duplicate key in SnapshotSummary`, or it copied the delete counters of the parent snapshot to the new snapshot. [#126023](https://github.com/ClickHouse/ClickHouse/pull/126023) ([Den Kalantaevskii](https://github.com/Diskein)).
* Backported in [#132998](https://github.com/ClickHouse/ClickHouse/issues/132998): Fixed `Reading in parallel from replicas is enabled but cluster to execute query is not provided` (`CLUSTER_DOESNT_EXIST`) when selecting from a `Distributed` table whose cluster is not declared in `remote_servers` - the cluster of a `Replicated` database, or one found by cluster discovery - with parallel replicas enabled. [#126032](https://github.com/ClickHouse/ClickHouse/pull/126032) ([Igor Nikonov](https://github.com/devcrafter)).
* Backported in [#132978](https://github.com/ClickHouse/ClickHouse/issues/132978): Fixed the primary key and `minmax` indices skipping matching rows when a `Decimal` column was compared with a float constant under a key expression such as `toFloat64(d)`, for example `WHERE d = toFloat32(1)`, or with the floats of an `IN` subquery. Such a comparison with a `BFloat16` value no longer fails with "Conversion from BFloat16 to Decimal is not implemented". [#126584](https://github.com/ClickHouse/ClickHouse/pull/126584) ([sz-kristof](https://github.com/sz-kristof)).
* Backported in [#132997](https://github.com/ClickHouse/ClickHouse/issues/132997): Fixed a heap-buffer-overflow when merging a corrupted `uniqCombined`, `uniqCombined64` or `uniqHLL12` state. Such states, and states whose rank counts or stored number of zero registers don't add up, now throw `INCORRECT_DATA`. [#126840](https://github.com/ClickHouse/ClickHouse/pull/126840) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133007](https://github.com/ClickHouse/ClickHouse/issues/133007): Fixed a server abort or a `LOGICAL_ERROR` ("Invalid number of rows in Chunk") in `ORDER BY ... WITH FILL ... INTERPOLATE` when the alias of an `INTERPOLATE` target is the name of another column of the query, for example when `count()` is aliased to its own name so that it can be interpolated. Such queries return the same result as in 25.12 again. Closes [#126941](https://github.com/ClickHouse/ClickHouse/issues/126941). [#127012](https://github.com/ClickHouse/ClickHouse/pull/127012) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132995](https://github.com/ClickHouse/ClickHouse/issues/132995): Fix a server crash (stack overflow) when a query in the `clickhouse_json` dialect or a call to `formatQueryFromJSON` contains very deeply nested JSON. [#127210](https://github.com/ClickHouse/ClickHouse/pull/127210) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#132994](https://github.com/ClickHouse/ClickHouse/issues/132994): Fixed a skip index whose type was written in uppercase (e.g. `TYPE TEXT(...)`) not getting the default granularity the lowercase form gets. For a text index this made its mark-cache prewarm throw (wedging a `SharedMergeTree` replica's startup) and could make queries using the index silently return fewer rows than a full scan. [#127407](https://github.com/ClickHouse/ClickHouse/pull/127407) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Backported in [#133027](https://github.com/ClickHouse/ClickHouse/issues/133027): Fixed `EmbeddedRocksDB`, `KeeperMap` and `Redis` tables with a `Decimal`, `DateTime64` or `Time64` primary key returning no rows for a float constant such as `WHERE key = 19.99` or `key IN (SELECT 19.99)` when the key holds the matching value, and `ALTER TABLE ... DELETE` / `UPDATE` with such a condition changing nothing. Such a condition now reads the whole table unless it is a `Float32` or `Float64` constant proven to match only its cast to a `Decimal32` or `Decimal64` key (`key = 12.5`); a constant written in the key's type (`key = '19.99'`) still uses the key lookup. [#128086](https://github.com/ClickHouse/ClickHouse/pull/128086) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132993](https://github.com/ClickHouse/ClickHouse/issues/132993): Fixed a server abort while reading files from a `zip` archive (for example with `s3`) when the query reaches its memory limit. [#128325](https://github.com/ClickHouse/ClickHouse/pull/128325) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132992](https://github.com/ClickHouse/ClickHouse/issues/132992): A user defined in the server configuration (`users.xml`) can no longer escape its own settings constraints by selecting another settings profile with `SET profile`, a `SETTINGS profile = ...` clause or the HTTP `profile` parameter. Since 26.10 such a switch replaced settings pinned with `CONST` or bounded by `MIN`/`MAX`, while a user created by SQL got `SETTING_CONSTRAINT_VIOLATION`. Closes [#128370](https://github.com/ClickHouse/ClickHouse/issues/128370). [#128657](https://github.com/ClickHouse/ClickHouse/pull/128657) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132991](https://github.com/ClickHouse/ClickHouse/issues/132991): Fixed an exception (for example from `throwIf`) in a query whose `PREWHERE` had several substring conditions on one `String` column, pushed into the scan by `apply_string_filters_during_scan`, when the result of one of them was also used elsewhere in `PREWHERE`. [#128734](https://github.com/ClickHouse/ClickHouse/pull/128734) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132963](https://github.com/ClickHouse/ClickHouse/issues/132963): Fixed the `compatibility` setting restoring the old default of a setting whose new default was backported to the pinned release. With `compatibility` set to that release, `iceberg_tolerate_conflicting_manifest_schemas`, `backup_s3_expired_token_retry_timeout_ms`, `azure_validate_etag_on_read`, `use_text_index_postings_cache`, `filesystem_cache_wait_for_concurrent_download_timeout_milliseconds`, the `ai_function_*` limits, the `http_*` header limits and the MergeTree setting `enable_row_mask_update_coalescing` now get that release's default. Closes [#129014](https://github.com/ClickHouse/ClickHouse/issues/129014). [#129348](https://github.com/ClickHouse/ClickHouse/pull/129348) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132926](https://github.com/ClickHouse/ClickHouse/issues/132926): Fixed a filtered source grant (e.g. `GRANT WRITE ON S3('https://bucket/allowed/.*')`) authorizing a location outside the filter. `BACKUP`/`RESTORE` and table functions like `s3`, `url` and `azureBlobStorage` with `.`/`..` or empty path segments, a fragment, escapes that change the name, a query in an S3 URI (where `?` is a wildcard) or `url` alternatives outside the path now need the grant on the whole source. A glob character (`*?{}|`, and `,` in `url`) must match the filter both as written and percent-encoded. [#129899](https://github.com/ClickHouse/ClickHouse/pull/129899) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132976](https://github.com/ClickHouse/ClickHouse/issues/132976): Fixed missing rows when reading an Iceberg table partitioned by several columns with a filter such as `a = 2 AND b IS NULL`: manifest-list partition pruning (`use_iceberg_manifest_list_partition_pruning`, enabled by default since 26.9) skipped manifests that hold a `NULL` partition value, as PyIceberg and Spark write them. Closes [#129913](https://github.com/ClickHouse/ClickHouse/issues/129913). [#129929](https://github.com/ClickHouse/ClickHouse/pull/129929) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132974](https://github.com/ClickHouse/ClickHouse/issues/132974): Fixed a server crash and wrong results of a `JOIN` onto a `COMPLEX_KEY_DIRECT` or `COMPLEX_KEY_CACHE` dictionary when the left join key is a constant (for example `SELECT 'a' AS k`), comes out of an `ARRAY JOIN`, or is stored with sparse serialization. [#130203](https://github.com/ClickHouse/ClickHouse/pull/130203) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132988](https://github.com/ClickHouse/ClickHouse/issues/132988):. [#130778](https://github.com/ClickHouse/ClickHouse/pull/130778) ([Melvyn Peignon](https://github.com/melvynator)).
* Backported in [#133087](https://github.com/ClickHouse/ClickHouse/issues/133087): Fixed `count()` counting rows with a `NULL` key value that the filter rejects, when the filter has `NOT IN` (or `NOT (... IN ...)`) over a `Nullable` primary key column that the in-memory primary index does not load (it follows a high-cardinality key prefix), with `allow_nullable_key = 1` and `use_lightweight_primary_key_index_analysis = 1` (the default). [#131390](https://github.com/ClickHouse/ClickHouse/pull/131390) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133060](https://github.com/ClickHouse/ClickHouse/issues/133060): Fix out-of-bounds memory access with an aggregate state containing a `JSON` value with a repeated path. Now such a state is rejected with `INCORRECT_DATA`. [#131791](https://github.com/ClickHouse/ClickHouse/pull/131791) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

[#131895](https://github.com/ClickHouse/ClickHouse/pull/131895) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132984](https://github.com/ClickHouse/ClickHouse/issues/132984): Fixed a constant column of a subquery returning the type default (`0`, `''`, `[]`) instead of its value for the unmatched rows of an outer join, or failing with `ILLEGAL_COLUMN`, when join reordering merges the subquery's projection into the join (`query_plan_merge_expression_into_join`). Closes [#131590](https://github.com/ClickHouse/ClickHouse/issues/131590). [#131961](https://github.com/ClickHouse/ClickHouse/pull/131961) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133080](https://github.com/ClickHouse/ClickHouse/issues/133080): Fix a crash in the `Arrow` and `ArrowStream` input formats when a requested type changed how a nested field was decoded while another requested column read that field with a type that does not describe it: a struct column together with a dotted subcolumn of it, such as `t String, "t.s" IPv6` (including dictionary-encoded `UUID` children), or an Arrow union with a struct child named like another requested column. [#132416](https://github.com/ClickHouse/ClickHouse/pull/132416) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#132970](https://github.com/ClickHouse/ClickHouse/issues/132970): Fixed wrong results and a possible server abort of queries using the query condition cache when a `MergeTree` table was attached again (`DETACH`/`ATTACH TABLE` or `ATTACH DATABASE`) after `TRUNCATE` or `ALTER TABLE ...
