# 2026 Changelog

### ClickHouse release v26.8.43.13-lts (d7fd1bf9ae8) FIXME as compared to v26.8.42.13-lts (e54ce2d338d)

#### Backward Incompatible Change
* Backported in [#133253](https://github.com/ClickHouse/ClickHouse/issues/133253): `CREATE HANDLER`, `ALTER HANDLER`, `DROP HANDLER` and `SHOW HANDLERS` now form the new `HANDLER ADMIN` privilege group and are no longer part of the `CREATE`, `ALTER` and `DROP` groups. Previously `GRANT CREATE ON *.*` or `GRANT ALTER ON *.*` was enough to define or rewrite an HTTP handler, whose query runs with the privileges of the user who calls it. Users who manage handlers must now be granted `HANDLER ADMIN` or the individual handler privileges, including users whose stored grants name only the old groups: for example, `GRANT CREATE, CREATE HANDLER` is stored as `GRANT CREATE`, and `GRANT ALL` followed by `REVOKE SYSTEM` is stored as a list of groups. Revoking `CREATE`, `ALTER` or `DROP` no longer revokes them, so a configured grant list that revokes one of these from `ALL` should also revoke `HANDLER ADMIN`. [#129033](https://github.com/ClickHouse/ClickHouse/pull/129033) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133257](https://github.com/ClickHouse/ClickHouse/issues/133257): Fixed `KILL QUERY` and `max_execution_time` having no effect on a query reading from PostgreSQL when the remote host stops sending data, and `DROP` of a refreshable materialized view whose refresh reads from PostgreSQL hanging for the same reason. [#118995](https://github.com/ClickHouse/ClickHouse/pull/118995) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#133194](https://github.com/ClickHouse/ClickHouse/issues/133194): Check access rights before loading a dictionary or reading its definition in the `dictionary` table function, `dictGet`-family functions, `naiveBayesClassifier`, `Dictionary` tables and `CREATE TABLE ... ENGINE = Dictionary`. Queries without the required grants no longer trigger the dictionary load, and queries or DDL that reference a dictionary now require access to it even when they do not read it, e.g. `DESCRIBE`, `CREATE VIEW` or a `DEFAULT dictGet(...)` column. [#122678](https://github.com/ClickHouse/ClickHouse/pull/122678) ([Matheus Nerone](https://github.com/Manerone)).
* Backported in [#133294](https://github.com/ClickHouse/ClickHouse/issues/133294): Fixed geometry functions such as `wkt`, `svg`, `polygonAreaCartesian` and `polygonsIntersectionCartesian` returning an empty result for a `MultiPolygon` or `MultiLineString` value that follows an empty one in the same block. Closes [#126843](https://github.com/ClickHouse/ClickHouse/issues/126843). [#128606](https://github.com/ClickHouse/ClickHouse/pull/128606) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133208](https://github.com/ClickHouse/ClickHouse/issues/133208): Fix a possible crash of the `RabbitMQ` table engine when the broker confirms a message with an unknown delivery tag. [#131731](https://github.com/ClickHouse/ClickHouse/pull/131731) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133174](https://github.com/ClickHouse/ClickHouse/issues/133174): Fix type confusion when deserializing a query plan whose aggregate functions do not match the types of their input columns. Now such a plan is rejected with `INCORRECT_DATA`. [#131789](https://github.com/ClickHouse/ClickHouse/pull/131789) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133058](https://github.com/ClickHouse/ClickHouse/issues/133058): Fix out-of-bounds memory access with an aggregate state containing a `JSON` value with a repeated path. Now such a state is rejected with `INCORRECT_DATA`. [#131791](https://github.com/ClickHouse/ClickHouse/pull/131791) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133197](https://github.com/ClickHouse/ClickHouse/issues/133197): Fix a crash (double free) when an allocation failed, e.g. because of the memory limit, while an aggregate function used as a window function moved to a new partition or frame, or while an aggregate function with the `-ArgMin` / `-ArgMax` combinator reset its state for a new extreme value. [#132755](https://github.com/ClickHouse/ClickHouse/pull/132755) ([Raúl Marín](https://github.com/Algunenano)).
* Fix a segfault in a `SELECT` from a `MergeTree` table with the old analyzer (`enable_analyzer = 0`) when `query_plan_optimize_prewhere` or `query_plan_enable_optimizations` is disabled. [#133157](https://github.com/ClickHouse/ClickHouse/pull/133157) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
