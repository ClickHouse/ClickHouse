# 2026 Changelog

### ClickHouse release v26.11.4.11-stable (60a00ce41cf) FIXME as compared to v26.11.3.10-stable (140ed394689)

#### Performance Improvement
* Backported in [#134834](https://github.com/ClickHouse/ClickHouse/issues/134834): A `JOIN` whose input repeats the join key under the same name, for example `(SELECT id, id FROM l) AS s JOIN r ON r.l_id = s.id`, now removes unused columns as for any other join and supports lazy materialization for `LIMIT` queries over joins (`query_plan_lazy_materialization_for_join`). [#134483](https://github.com/ClickHouse/ClickHouse/pull/134483) ([Vladimir Cherkasov](https://github.com/vdimir)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134964](https://github.com/ClickHouse/ClickHouse/issues/134964): Fix `ALTER DELETE`/`ALTER UPDATE` silently skipping rows when the predicate contains `IN <table>`. The default-enabled `optimize_mutations_with_partition_pruning` evaluated that set at submission time and narrowed the mutation's `block_numbers`, so a partition matching only the execution-time set was left out while the mutation still reported `is_done = 1`. [#117272](https://github.com/ClickHouse/ClickHouse/pull/117272) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#134955](https://github.com/ClickHouse/ClickHouse/issues/134955): Fix incorrect results from multi-block `INSERT` queries into order-sensitive table engines when `max_insert_threads` enables parallel writes. Plain inserts and single-stream `INSERT SELECT` preserve input order for `CollapsingMergeTree`, `CoalescingMergeTree`, `GraphiteMergeTree`, `ReplacingMergeTree` (including replicated variants), and `EmbeddedRocksDB`, including through materialized views or `Alias` tables. Multistream `SELECT` input can retain parallel sinks; `KeeperMap` stays single-stream for all inserts. [#128833](https://github.com/ClickHouse/ClickHouse/pull/128833) ([Ashish Kumar Choubey](https://github.com/aschoube)).
* Backported in [#134687](https://github.com/ClickHouse/ClickHouse/issues/134687): Reading a Parquet variant column whose `metadata` or `value` field has a logical or converted type annotation now gives an `INCORRECT_DATA` error. Such a field could previously be decoded as a non-string column and read incorrectly. A Parquet file whose schema needs more elements than the file has now gives an `INCORRECT_DATA` error and does not abort the server. [#132931](https://github.com/ClickHouse/ClickHouse/pull/132931) ([Antonio Andelic](https://github.com/antonio2368)).
* Backported in [#134958](https://github.com/ClickHouse/ClickHouse/issues/134958): Fixed wrong results of a join stacked above a `RIGHT` or `FULL` hash join with `query_plan_join_shard_by_pk_ranges`: the rows that only the right table has were not matched by the join above. Joins above a `RIGHT` or `FULL` hash join are no longer sharded by primary-key ranges. Closes [#125323](https://github.com/ClickHouse/ClickHouse/issues/125323). [#133614](https://github.com/ClickHouse/ClickHouse/pull/133614) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134864](https://github.com/ClickHouse/ClickHouse/issues/134864): This patch adds a guardrail for disk declaration. It will no longer be possible to set up 2 disks with a shared underlying directory. [#134111](https://github.com/ClickHouse/ClickHouse/pull/134111) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Backported in [#134760](https://github.com/ClickHouse/ClickHouse/issues/134760): Fixed `UNKNOWN_IDENTIFIER` for a qualified column when the qualifier also matches the name or the alias of another table in the `JOIN` that has no such column, e.g. `SELECT one.x FROM (SELECT 1 AS x) AS one JOIN system.one AS o ON o.dummy + 1 = one.x`, or two tables with the same name from different databases. [#134510](https://github.com/ClickHouse/ClickHouse/pull/134510) ([Dmitry Novik](https://github.com/novikd)).
* Backported in [#134874](https://github.com/ClickHouse/ClickHouse/issues/134874): Fix join orders changed by floating-point rounding when `query_plan_join_order_use_interesting_orders` is enabled, which made some TPC-DS queries slower. [#134792](https://github.com/ClickHouse/ClickHouse/pull/134792) ([Fisnik Kastrati](https://github.com/fkastrati)).
* Backported in [#134872](https://github.com/ClickHouse/ClickHouse/issues/134872): Fix a server crash, a logical error, or an `ILLEGAL_COLUMN` exception when a query to the `url` table function or the `URL` table engine reads the `_headers` virtual column together with another virtual column requested after it, such as in `SELECT _headers, _size FROM url(...)`. Fix an empty `_headers` when such a query reads only virtual columns and the number of rows of the file is in the cache. [#134815](https://github.com/ClickHouse/ClickHouse/pull/134815) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Build/Testing/Packaging Improvement
* Backported in [#134749](https://github.com/ClickHouse/ClickHouse/issues/134749): Update `krb5` from 1.22.2-final to 1.22.3-final. [#133845](https://github.com/ClickHouse/ClickHouse/pull/133845) ([Actuele AI](https://github.com/actueleai)).
