# 2026 Changelog

### ClickHouse release v26.7.24.8-stable (47aaf76ac61) FIXME as compared to v26.7.23.7-stable (2d9e1dc973a)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124150](https://github.com/ClickHouse/ClickHouse/issues/124150): `ALTER TABLE ... MODIFY SETTING disk = disk(...)` could register a disk defined in SQL whose local path is outside `custom_local_disks_base_directory`, and create its directory, bypassing the check that `CREATE TABLE` applies. Now it is rejected the same way, and a statement rejected this way leaves no disk and no directory behind. [#119850](https://github.com/ClickHouse/ClickHouse/pull/119850) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#124181](https://github.com/ClickHouse/ClickHouse/issues/124181): Rewriting the body of a view with `ALTER TABLE ... MODIFY QUERY` now needs the same grants as creating it with its SQL security: `SET DEFINER` on the definer of a `SQL SECURITY DEFINER` view, or `ALLOW SQL SECURITY NONE` for a `SQL SECURITY NONE` view. An `ON CLUSTER MODIFY QUERY` fails with `UNKNOWN_TABLE` unless it runs on a host that has the view. [#121629](https://github.com/ClickHouse/ClickHouse/pull/121629) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#124194](https://github.com/ClickHouse/ClickHouse/issues/124194): Put "WRITE" operation in delta lake catalog. [#123543](https://github.com/ClickHouse/ClickHouse/pull/123543) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#124310](https://github.com/ClickHouse/ClickHouse/issues/124310): Fix `Found patch part ... that intersects mutation with version ...` on lightweight updates in a table created with `CREATE TABLE ... CLONE AS` or `ATTACH PARTITION ALL FROM` a table with lightweight updates. [#123620](https://github.com/ClickHouse/ClickHouse/pull/123620) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#124060](https://github.com/ClickHouse/ClickHouse/issues/124060): Fix a possible hang of a query under workload CPU scheduling with `cpu_slot_preemption` enabled: when all its threads were preempted, the query could keep CPU slots it had already used and wait forever for one of them. [#123640](https://github.com/ClickHouse/ClickHouse/pull/123640) ([Sergei Trifonov](https://github.com/serxa)).
* Backported in [#124160](https://github.com/ClickHouse/ClickHouse/issues/124160): Respect `iceberg_metadata_staleness_ms` in metadata parsing. [#124113](https://github.com/ClickHouse/ClickHouse/pull/124113) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#124252](https://github.com/ClickHouse/ClickHouse/issues/124252): Fix container existence check during `RESTORE` of a lightweight snapshot from Azure Blob Storage by parsing the saved namespace into container name and prefix. [#122697](https://github.com/ClickHouse/ClickHouse/pull/122697) ([Garrett Thomas](https://github.com/garrettthomaskth)).
