# 2026 Changelog

### ClickHouse release v26.8.42.13-lts (e54ce2d338d) FIXME as compared to v26.8.41.14-lts (f380d224f9a)

#### Performance Improvement
* Backported in [#133050](https://github.com/ClickHouse/ClickHouse/issues/133050): Fix cubic complexity of enumerating subcolumns of deeply nested `Array` types. [#126554](https://github.com/ClickHouse/ClickHouse/pull/126554) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133074](https://github.com/ClickHouse/ClickHouse/issues/133074): Parsing row-based input formats and `Native` into tables with nested `Tuple` columns is faster for small blocks (streaming engines, async inserts): the per-block columns are now created once per nested element instead of once per nesting level. Closes [#127427](https://github.com/ClickHouse/ClickHouse/issues/127427). [#127859](https://github.com/ClickHouse/ClickHouse/pull/127859) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132954](https://github.com/ClickHouse/ClickHouse/issues/132954): Fixed projections returning rows removed by a lightweight `DELETE` after `ALTER UPDATE`, `MATERIALIZE PROJECTION` or `CLEAR COLUMN` rebuilt them on a Wide part. A query with `apply_deleted_mask = 0` no longer uses projections when the table has lightweight-deleted rows, since projections do not store them. On release branches this also fixes a normal projection without a `WHERE` keeping the rows removed by a `rebuild`-mode lightweight `DELETE`, which [#118375](https://github.com/ClickHouse/ClickHouse/issues/118375) fixed on master. [#111809](https://github.com/ClickHouse/ClickHouse/pull/111809) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132924](https://github.com/ClickHouse/ClickHouse/issues/132924): Fixed a filtered source grant (e.g. `GRANT WRITE ON S3('https://bucket/allowed/.*')`) authorizing a location outside the filter. `BACKUP`/`RESTORE` and table functions like `s3`, `url` and `azureBlobStorage` with `.`/`..` or empty path segments, a fragment, escapes that change the name, a query in an S3 URI (where `?` is a wildcard) or `url` alternatives outside the path now need the grant on the whole source. A glob character (`*?{}|`, and `,` in `url`) must match the filter both as written and percent-encoded. [#129899](https://github.com/ClickHouse/ClickHouse/pull/129899) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132972](https://github.com/ClickHouse/ClickHouse/issues/132972): Fixed a server crash and wrong results of a `JOIN` onto a `COMPLEX_KEY_DIRECT` or `COMPLEX_KEY_CACHE` dictionary when the left join key is a constant (for example `SELECT 'a' AS k`), comes out of an `ARRAY JOIN`, or is stored with sparse serialization. [#130203](https://github.com/ClickHouse/ClickHouse/pull/130203) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132986](https://github.com/ClickHouse/ClickHouse/issues/132986): Fixed `CREATE WORKLOAD`, `DROP WORKLOAD`, `CREATE RESOURCE` and `DROP RESOURCE` with `workload_zookeeper_path` overwriting definitions written by other replicas when the query was the first to use a renewed Keeper session. [#131719](https://github.com/ClickHouse/ClickHouse/pull/131719) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132270](https://github.com/ClickHouse/ClickHouse/issues/132270): Fix a stack overflow in the `ParquetMetadata` format for files with a very deeply nested schema. The depth is now limited by `max_parser_depth`, as in the `Parquet` format, and never exceeds 1000. [#131735](https://github.com/ClickHouse/ClickHouse/pull/131735) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133009](https://github.com/ClickHouse/ClickHouse/issues/133009): The `/binary` web UI now displays the symbol name and source line in the popup as text instead of interpreting the server response as HTML. [#131895](https://github.com/ClickHouse/ClickHouse/pull/131895) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133089](https://github.com/ClickHouse/ClickHouse/issues/133089): Fix a crash in the `Arrow` and `ArrowStream` input formats when a requested type changed how a nested field was decoded while another requested column read that field with a type that does not describe it: a struct column together with a dotted subcolumn of it, such as `t String, "t.s" IPv6` (including dictionary-encoded `UUID` children), or an Arrow union with a struct child named like another requested column. [#132416](https://github.com/ClickHouse/ClickHouse/pull/132416) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#132934](https://github.com/ClickHouse/ClickHouse/issues/132934): Fixed a memory leak in queries answered by `_minmax_count_projection` that compute `min` or `max` of a `Tuple`, `Array` or `FixedString` primary key or partition column: every part read leaked one aggregate state. [#132557](https://github.com/ClickHouse/ClickHouse/pull/132557) ([Groene AI](https://github.com/groeneai)).
* The `url` of an `HTTP` dictionary source is hidden in `SHOW CREATE`, `system.tables` and the query log, and its userinfo in `system.dictionaries`. [#133044](https://github.com/ClickHouse/ClickHouse/pull/133044) ([George Larionov](https://github.com/george-larionov)).

#### Build/Testing/Packaging Improvement
* Backported in [#133085](https://github.com/ClickHouse/ClickHouse/issues/133085): Update `postgres` to 18.6. [#124281](https://github.com/ClickHouse/ClickHouse/pull/124281) ([Actuele AI](https://github.com/actueleai)).
