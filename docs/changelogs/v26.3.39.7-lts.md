# 2026 Changelog

### ClickHouse release v26.3.39.7-lts (4277fab4705) FIXME as compared to v26.3.38.2-lts (45e426c4f52)

#### Performance Improvement
* Backported in [#123211](https://github.com/ClickHouse/ClickHouse/issues/123211): Build Iceberg min/max hyperrectangles only for columns the filter uses. [#122681](https://github.com/ClickHouse/ClickHouse/pull/122681) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#123224](https://github.com/ClickHouse/ClickHouse/issues/123224): Fix an out-of-bounds read (a crash in release builds) in insert deduplication when an `INSERT` flows through a materialized view whose inner query changes the number of rows and the deduplicating target table is partitioned. `DeduplicationInfo::filterToPartition` attributed each deduplication token to partitions by walking the token's source-row range over a partition selector sized to the (smaller) view-output block, reading past its bounds. It now keeps every token in every partition for any materialized-view target — where the source-row-to-partition mapping no longer exists after the row count changed — instead of the out-of-bounds walk (and instead of the `NOT_IMPLEMENTED` that a later guard raised for the same insert). [#112649](https://github.com/ClickHouse/ClickHouse/pull/112649) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#123372](https://github.com/ClickHouse/ClickHouse/issues/123372): Fixed an `ssl_certificate` authentication bypass where an embedded NUL byte in a certificate's Common Name (for example `john\0.evil.com`) was truncated server-side to `john`, letting a holder of such a certificate authenticate as a different user. [#117403](https://github.com/ClickHouse/ClickHouse/pull/117403) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#123218](https://github.com/ClickHouse/ClickHouse/issues/123218): Now clickhouse masks credentials in system.query_log even for wrong URLs for external table engines. [#122057](https://github.com/ClickHouse/ClickHouse/pull/122057) ([alesapin](https://github.com/alesapin)).
* Backported in [#123117](https://github.com/ClickHouse/ClickHouse/issues/123117): Fixed secret settings of `S3Queue` and `AzureQueue` tables written with the legacy `s3queue_` prefix, such as `s3queue_after_processing_move_secret_access_key`, being shown in cleartext in `SHOW CREATE TABLE`, `system.tables`, `system.query_log` and the server log. They are now hidden as they are without the prefix. [#123060](https://github.com/ClickHouse/ClickHouse/pull/123060) ([Groene AI](https://github.com/groeneai)).
* Fixed a server crash on `CREATE TABLE` or `ALTER TABLE ... ADD CONSTRAINT` when a constraint contains a `less` or `lessOrEquals` comparison with the wrong number of arguments, for example `CHECK less(a)`. [#123080](https://github.com/ClickHouse/ClickHouse/pull/123080) ([Antonio Filipovic](https://github.com/antoniofilipovic)).
