# 2026 Changelog

### ClickHouse release v26.8.39.19-lts (ed6dc0f3556) FIXME as compared to v26.8.38.9-lts (71391c9b2bb)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132031](https://github.com/ClickHouse/ClickHouse/issues/132031): Fixed `NOT_FOUND_COLUMN_IN_BLOCK` (`Not found column _row_exists in block`) that permanently blocked all further mutations of a `MergeTree` table after a lightweight `DELETE` run with `lightweight_delete_mode = 'lightweight_update'` was followed by a heavyweight `ALTER TABLE ... UPDATE` and then by another mutation rewriting all columns. Closes [#115570](https://github.com/ClickHouse/ClickHouse/issues/115570). [#115665](https://github.com/ClickHouse/ClickHouse/pull/115665) ([Groene AI](https://github.com/groeneai)).
* Backported in [#131987](https://github.com/ClickHouse/ClickHouse/issues/131987): With `analyzer_compatibility_join_using_top_level_identifier = 1`, a `JOIN USING` identifier is resolved from an alias of the query only for the outermost `JOIN`; an inner `JOIN` of a query with several joins resolves it from its left table, as the old analyzer did. This fixes `UNKNOWN_IDENTIFIER` for queries such as `SELECT if(m.symbol = '', b.symbol, m.symbol) AS symbol FROM m FULL JOIN b USING (symbol) FULL JOIN dttm ON 1 = 1`, and a `USING clause expected identifier` error when an inner `USING` join is placed below an aliased outermost `USING` key. [#123103](https://github.com/ClickHouse/ClickHouse/pull/123103) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#132303](https://github.com/ClickHouse/ClickHouse/issues/132303): A `Merge` table and the `merge` table function no longer count the matched tables the user cannot see (no `SHOW TABLES`) when `count()` is answered from metadata or in `system.tables` `total_rows`/`total_bytes`, and their `system.columns` sizes include only the columns the user can see (`SHOW COLUMNS`) on each matched table. Before, these disclosed the row count and size of tables the user has no access to, while reading the same data skipped them. [#129818](https://github.com/ClickHouse/ClickHouse/pull/129818) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132287](https://github.com/ClickHouse/ClickHouse/issues/132287): Fix a wrong order of rows for a query like `SELECT ... WHERE toDate(ts) = '2024-01-01' ORDER BY toDate(ts), b LIMIT 5` over a table with the sorting key `(ts, b)` when `optimize_read_in_order` is enabled. A query that filters a leading sorting key column by equality and lists it in `ORDER BY` (`WHERE a = 1 ORDER BY a, b`) is read in order through an `INNER JOIN` again. [#130893](https://github.com/ClickHouse/ClickHouse/pull/130893) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#131557](https://github.com/ClickHouse/ClickHouse/issues/131557): Fixed a use-after-free on reading a Delta Lake table with column mapping in which a column is stored under the name of another column (for example, after column mapping is enabled on an existing table and columns are renamed), when the columns are requested in a particular order, such as `SELECT k_old, k`. [#131029](https://github.com/ClickHouse/ClickHouse/pull/131029) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131881](https://github.com/ClickHouse/ClickHouse/issues/131881): Check the scale of a `Decimal` value before formatting it as text, so a value with an out-of-range scale produces an exception instead of undefined behavior. [#131366](https://github.com/ClickHouse/ClickHouse/pull/131366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132210](https://github.com/ClickHouse/ClickHouse/issues/132210): Fixed a memory leak when the merge of the per-thread hash tables of `GROUP BY` failed with an exception, for example on `max_memory_usage`: the states of aggregate functions such as `uniqExact` or `quantileExact` that waited to be merged were never freed. [#131595](https://github.com/ClickHouse/ClickHouse/pull/131595) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132130](https://github.com/ClickHouse/ClickHouse/issues/132130): Fixed `DROP WORKLOAD` removing a resource with the same name and `DROP RESOURCE` removing a workload with the same name when workload entities are stored in Keeper (`workload_zookeeper_path`). A user with only one of the two privileges could remove the other kind of entity. [#131688](https://github.com/ClickHouse/ClickHouse/pull/131688) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132075](https://github.com/ClickHouse/ClickHouse/issues/132075): Fix a server abort when merging a malformed serialized state of a `-Map` aggregate function with a `FixedString` key. Now such a state is rejected with `INCORRECT_DATA`. [#131732](https://github.com/ClickHouse/ClickHouse/pull/131732) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132207](https://github.com/ClickHouse/ClickHouse/issues/132207): Fix a possible crash when an exception (for example, a memory limit) is thrown during the short-circuit evaluation of a function returning an `AggregateFunction` state. [#131733](https://github.com/ClickHouse/ClickHouse/pull/131733) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132203](https://github.com/ClickHouse/ClickHouse/issues/132203): Fix a possible crash of the `PostgreSQL` table engine, table function and database engine when the remote server reports an absurd number of array dimensions. [#131734](https://github.com/ClickHouse/ClickHouse/pull/131734) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132289](https://github.com/ClickHouse/ClickHouse/issues/132289): Fix out-of-bounds reads when deserializing a query plan with a step lacking some of its inputs or having extra children. Now such a plan is rejected with `INCORRECT_DATA`. [#131736](https://github.com/ClickHouse/ClickHouse/pull/131736) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132230](https://github.com/ClickHouse/ClickHouse/issues/132230): Fix a crash of the `DWARF` input format on an ELF file with a malformed attribute length. [#131787](https://github.com/ClickHouse/ClickHouse/pull/131787) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132235](https://github.com/ClickHouse/ClickHouse/issues/132235): Fix out-of-bounds memory access with a state of `mergedJSONPatch` containing a repeated path. Now such a state is rejected with `INCORRECT_DATA`. [#131792](https://github.com/ClickHouse/ClickHouse/pull/131792) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132240](https://github.com/ClickHouse/ClickHouse/issues/132240): Fix a possible out-of-bounds read in the `Parquet` reader when `PREWHERE` filters out a whole page of a `PLAIN`-encoded string column read through a conversion (e.g. to `Geometry`). [#131797](https://github.com/ClickHouse/ClickHouse/pull/131797) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132096](https://github.com/ClickHouse/ClickHouse/issues/132096): Fix a possible crash when restoring a backup from a zip archive with a password if an encrypted entry of the archive is smaller than the encryption header. [#131806](https://github.com/ClickHouse/ClickHouse/pull/131806) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
