# 2026 Changelog

### ClickHouse release v26.9.16.11-stable (1cb9dbb0c11) FIXME as compared to v26.9.15.5-stable (968d6e50d95)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125089](https://github.com/ClickHouse/ClickHouse/issues/125089): Fixed `TRUNCATE TABLE` of an `Alias` table whose target is a `MergeTree` failing with `DEADLOCK_AVOIDED` when the alias is being read concurrently, while the same statement against the target table succeeds immediately. The lock for `TRUNCATE` is now chosen and taken on the table that executes the truncate, so an `Alias` follows its target's engine. [#119105](https://github.com/ClickHouse/ClickHouse/pull/119105) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125109](https://github.com/ClickHouse/ClickHouse/issues/125109): Fix a vector search returning fewer rows than its `LIMIT`, and missing true nearest neighbours, after a lightweight `DELETE` (or with a delete mutation applied on the fly): the vector index is no longer used for a part while it still holds deleted rows. [#119371](https://github.com/ClickHouse/ClickHouse/pull/119371) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125097](https://github.com/ClickHouse/ClickHouse/issues/125097): Fixed wrong results, or an `ILLEGAL_COLUMN` error, of a `JOIN` whose condition equates both a column and an expression of that column (for example `ON t1.k = t2.k AND intDiv(t1.k, 2) = intDiv(t2.k, 2)`) when a filter on that expression is pushed down to the other side of the join: the pushed-down copy applied the expression twice. Closes [#122613](https://github.com/ClickHouse/ClickHouse/issues/122613). [#122686](https://github.com/ClickHouse/ClickHouse/pull/122686) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124492](https://github.com/ClickHouse/ClickHouse/issues/124492): Fixed parallel replicas not being used when reading a `Distributed` table whose underlying table is another `Distributed` table and every shard of the outer cluster has a single replica. [#123566](https://github.com/ClickHouse/ClickHouse/pull/123566) ([Igor Nikonov](https://github.com/devcrafter)).
* Backported in [#125062](https://github.com/ClickHouse/ClickHouse/issues/125062): Fixed duplicated rows returned by `ANY RIGHT JOIN` with `any_join_distinct_right_table_keys = 1` when parallel replicas are enabled. [#123683](https://github.com/ClickHouse/ClickHouse/pull/123683) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125170](https://github.com/ClickHouse/ClickHouse/issues/125170): Fixed excessive memory usage when loading a data part with a corrupted `columns_substreams.txt`; such a part is now detached as broken. [#124157](https://github.com/ClickHouse/ClickHouse/pull/124157) ([Murphy](https://github.com/murphy-4o)).
* Backported in [#125069](https://github.com/ClickHouse/ClickHouse/issues/125069): Fixed `CREATE MATERIALIZED VIEW ... POPULATE` and `CREATE TABLE ... AS SELECT` in a `Replicated` database with parallel replicas enabled: each replica sent its population to other replicas, so its rows landed in other replicas' tables (duplicated there, missing on the replica itself), or the query failed with `UNKNOWN_TABLE`. The population now ignores the query's parallel replicas and `parallel_distributed_insert_select` settings, so each replica fills only its own table. Closes [#124446](https://github.com/ClickHouse/ClickHouse/issues/124446). [#124477](https://github.com/ClickHouse/ClickHouse/pull/124477) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125114](https://github.com/ClickHouse/ClickHouse/issues/125114): Fixed slow planning of queries with skip indexes on tables with many parts and pending patch parts of lightweight updates. [#124931](https://github.com/ClickHouse/ClickHouse/pull/124931) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#125057](https://github.com/ClickHouse/ClickHouse/issues/125057): Fixed a crash (stack overflow) when reading an Avro file with an explicit structure that does not read a field nested through a long chain of named types, or a field of a recursive type holding deeply nested data such as a long linked list. Such a file now fails with `TOO_DEEP_RECURSION` instead. Closes [#124925](https://github.com/ClickHouse/ClickHouse/issues/124925). [#124964](https://github.com/ClickHouse/ClickHouse/pull/124964) ([Groene AI](https://github.com/groeneai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT
