# 2026 Changelog

### ClickHouse release v26.7.8.15-stable (5cf8a36253e) FIXME as compared to v26.7.7.92-stable (e525f3a6cf7)

* Backported in [#119340](https://github.com/ClickHouse/ClickHouse/issues/119340): Support parallel replicas for object storage writes. [#119214](https://github.com/ClickHouse/ClickHouse/pull/119214) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#119733](https://github.com/ClickHouse/ClickHouse/issues/119733): Fixed a `LOGICAL_ERROR` (`Type mismatch when building statistics for column`) during a `MergeTree` mutation of a table whose column type was changed by a metadata-only `ALTER MODIFY COLUMN` (for example `Enum8` to `Int8` or `DateTime` to `UInt32`) while the column carries statistics. The mutation now recomputes only the statistics of columns it actually rewrites and carries the rest over unchanged, and a column rewritten by `MATERIALIZE COLUMN`, by an `UPDATE` of a column a `MATERIALIZED` column depends on, or by `CLEAR COLUMN` now gets its statistics recomputed instead of keeping stale content. [#112009](https://github.com/ClickHouse/ClickHouse/pull/112009) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119874](https://github.com/ClickHouse/ClickHouse/issues/119874): Fixed a crash when reading a subcolumn of a `Variant`, `Dynamic` or `JSON` column whose own type is `Nullable` or `LowCardinality(Nullable)` from a `MergeTree` table, for example ``SELECT value.`Tuple(a Nullable(UInt32), b String)`.a`` over a `Dynamic` column. Previously such a read hit a `LOGICAL_ERROR` in debug builds and crashed in release builds. [#112338](https://github.com/ClickHouse/ClickHouse/pull/112338) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119458](https://github.com/ClickHouse/ClickHouse/issues/119458): Fixed Iceberg `INSERT` writing manifest-wide aggregate column statistics into every `data_file` entry when a partition produced more than one data file. Each entry's `null_value_counts`, `column_sizes`, `lower_bounds` and `upper_bounds` now describe only the data file it points at. Previously an entry could report more nulls than the file had rows, so a spec-conforming external reader pruned files that contained matching rows. [#112414](https://github.com/ClickHouse/ClickHouse/pull/112414) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119668](https://github.com/ClickHouse/ClickHouse/issues/119668): Fixes a server abort in debug and sanitizer builds when inserting into a materialized view whose `TO` target is another materialized view. Such an insert already failed on released versions, with an uninformative `Code: 1001 STD_EXCEPTION`; it now reports `NOT_IMPLEMENTED` naming the offending view. [#115985](https://github.com/ClickHouse/ClickHouse/pull/115985) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119690](https://github.com/ClickHouse/ClickHouse/issues/119690): Fixed a server that refused to start after the directory backing a `Filesystem` database had been removed. Such a database is now loaded without tables and can be inspected and dropped, while a `CREATE DATABASE` or `ATTACH DATABASE` issued by a user is still rejected when the path does not exist. [#118684](https://github.com/ClickHouse/ClickHouse/pull/118684) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119418](https://github.com/ClickHouse/ClickHouse/issues/119418): Don't use backoffs on concurrent inserts conflicts (when we use Iceberg + catalog, for example). [#119238](https://github.com/ClickHouse/ClickHouse/pull/119238) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#119856](https://github.com/ClickHouse/ClickHouse/issues/119856): Fixed a crash and a `LOGICAL_ERROR` for statements that write `trim(BOTH '' FROM x)` (or the `LEADING`/`TRAILING` spelling) where a function is expected: a column's `STATISTICS(...)` or `CODEC(...)` list, `INDEX ... TYPE`, `ALTER TABLE ... ADD STATISTICS`, `auto_statistics_types`, a table function, a named collection and `SETTINGS`. The parser folded it into its operand instead of building a `trimBoth` call, and those places cast or dereference the result as a function. The fold also bypassed the function's own checks, so `trim(BOTH '' FROM <non-string>)` now raises `ILLEGAL_TYPE_OF_ARGUMENT` and a `FixedString` argument now yields `String`, as every other `trim` spelling does. [#119317](https://github.com/ClickHouse/ClickHouse/pull/119317) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119753](https://github.com/ClickHouse/ClickHouse/issues/119753): Fixed a stack buffer overflow when reading a `BIT` column from MySQL, reachable through the `mysql` table function, the `MySQL` table and database engines, and MySQL dictionaries. The length of the value sent by the server was copied without being validated. [#119680](https://github.com/ClickHouse/ClickHouse/pull/119680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
