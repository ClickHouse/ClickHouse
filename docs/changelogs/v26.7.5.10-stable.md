# 2026 Changelog

### ClickHouse release v26.7.5.10-stable (c7d5ecce0dd) FIXME as compared to v26.7.4.58-stable (9c16c358cd7)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#115566](https://github.com/ClickHouse/ClickHouse/issues/115566): Serialize a `Nullable(Tuple(...))` column as a single CSV field instead of flattening it into separate columns. Previously a non-null value was written as several CSV fields while a `NULL` was a single `\N`, giving a row-dependent column count that broke `CSVWithNames`/`CSVWithNamesAndTypes` headers and round-trips. [#108959](https://github.com/ClickHouse/ClickHouse/pull/108959) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115500](https://github.com/ClickHouse/ClickHouse/issues/115500): Fix a theoretical data race in profile events when using the `trace_profile_events_list` setting to write stack traces of certain profile events to `system.trace_log`. [#113553](https://github.com/ClickHouse/ClickHouse/pull/113553) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#115595](https://github.com/ClickHouse/ClickHouse/issues/115595): Fix `Logical error: No set is registered for key ...` when reading through a `Merge` table whose child declares an `ALIAS` column containing `IN`, and the children disagree about that column's default. [#113757](https://github.com/ClickHouse/ClickHouse/pull/113757) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115411](https://github.com/ClickHouse/ClickHouse/issues/115411): Reject corrupted/malicious dictionary where `lcp` exceeds the previous token or `lcp + data_size` overflows, before the buffer write. [#114155](https://github.com/ClickHouse/ClickHouse/pull/114155) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#114895](https://github.com/ClickHouse/ClickHouse/issues/114895): Fixes a bug where an access entity carrying a `Map`-valued setting, such as a settings profile with `http_response_headers` or `additional_table_filters`, is stored in a form that ClickHouse cannot read back, leaving the entity permanently unloadable after a restart. [#114620](https://github.com/ClickHouse/ClickHouse/pull/114620) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115713](https://github.com/ClickHouse/ClickHouse/issues/115713): Fixes `has`, `indexOf`, `countEqual`, `mapContainsKey`, `mapContainsValue` and `Map` subscript returning "not found" for a constant `LowCardinality` needle equal to the element type's default value, such as an empty `String` or a zero number. [#114624](https://github.com/ClickHouse/ClickHouse/pull/114624) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115628](https://github.com/ClickHouse/ClickHouse/issues/115628): Fix propagation of query settings and NULL handling in `accurateCastOrDefault`. [#114912](https://github.com/ClickHouse/ClickHouse/pull/114912) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#115472](https://github.com/ClickHouse/ClickHouse/issues/115472): Fixed wrong results for `SELECT count(arrayJoin(arr))` with the default `optimize_trivial_count_query = 1`. The stored row count was returned instead of the number of array elements, and on `file()` and `url()` the query returned `0`. Closes [#115123](https://github.com/ClickHouse/ClickHouse/issues/115123). [#115227](https://github.com/ClickHouse/ClickHouse/pull/115227) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115602](https://github.com/ClickHouse/ClickHouse/issues/115602): Fixed `uniq`, `uniqExact`, `uniqHLL12` and `uniqTheta` returning a wrong result for an argument wrapped in an injective function that hides nullability, such as `uniqExact(tuple(x))` over a `Nullable` column. The `optimize_injective_functions_inside_uniq` optimization removed the wrapping function, after which NULL rows were skipped instead of counted. [#115466](https://github.com/ClickHouse/ClickHouse/pull/115466) ([Vladimir Cherkasov](https://github.com/vdimir)).
