# 2026 Changelog

### ClickHouse release v26.10.11.12-stable (270407b6b9c) FIXME as compared to v26.10.10.3-stable (875446283b0)

#### Performance Improvement
* Backported in [#133432](https://github.com/ClickHouse/ClickHouse/issues/133432): `GROUP BY ... LIMIT` queries over parallel replicas now prune the aggregation on every replica with the top-K heap (`enable_group_by_top_k_optimization`), with or without `ORDER BY` by the keys, and automatic parallel replicas decides after the plan is optimized, so it compares the plan that would actually run. [#125888](https://github.com/ClickHouse/ClickHouse/pull/125888) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#133589](https://github.com/ClickHouse/ClickHouse/issues/133589): Faster `PREWHERE` with several conditions: the block is filtered once instead of after every condition when the later conditions cannot throw. ClickBench Q38 is up to 10% faster. [#128582](https://github.com/ClickHouse/ClickHouse/pull/128582) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133158](https://github.com/ClickHouse/ClickHouse/issues/133158): Fixed `s3`, `s3Cluster`, `azureBlobStorage`, `gcs`, `hdfs` and the other object storage table functions returning the data of the first entry for every entry of an archive that contains several entries with the same name (for example a tar archive to which `tar -r` appended a file again). The row count and schema caches of these functions and of `file` now also tell such entries apart. Detecting the format of a non-Parquet archive entry by its content in these functions no longer fails with `CANNOT_DETECT_FORMAT`. [#126129](https://github.com/ClickHouse/ClickHouse/pull/126129) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133550](https://github.com/ClickHouse/ClickHouse/issues/133550): Fixed `INSERT`, `MATERIALIZE PROJECTION` and merges failing with `LOGICAL_ERROR` `Projection ... calculated the columns ... while its metadata describes the columns ...` for a table with a projection that has a subquery (`x IN (SELECT ...)`, `EXISTS (SELECT ...)`) in its `SELECT` list or `GROUP BY` and a `WHERE` clause or aggregation. [#130143](https://github.com/ClickHouse/ClickHouse/pull/130143) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133555](https://github.com/ClickHouse/ClickHouse/issues/133555): Fixed connecting over the native protocol (`clickhouse-client`, `remote`, `Distributed` without an interserver `secret`) to an older server whose settings profile has a negative or overflowing value of a `Seconds` setting, for example `max_execution_time = -1`: the connection failed with `A setting's value in seconds cannot be negative`. Such a value sent by the server is now skipped with a warning. [#131636](https://github.com/ClickHouse/ClickHouse/pull/131636) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133176](https://github.com/ClickHouse/ClickHouse/issues/133176): Fix type confusion when deserializing a query plan whose aggregate functions do not match the types of their input columns. Now such a plan is rejected with `INCORRECT_DATA`. [#131789](https://github.com/ClickHouse/ClickHouse/pull/131789) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133592](https://github.com/ClickHouse/ClickHouse/issues/133592): Fixed wrong results of `GROUP BY`, `LIMIT BY` and `ORDER BY` after `GROUP BY` with an injective function and a NULL argument: with `concatAssumeInjective` or `partitionId` and a typed NULL constant or a `Nullable` column, rows where that argument is NULL were split into several groups instead of one; with `bitmaskToArray` or `bitPositionsToArray` of a `Nullable` column, NULL and `0` both map to `[]` but were treated as different keys. [#133115](https://github.com/ClickHouse/ClickHouse/pull/133115) ([Lazizbek Ergashev](https://github.com/lazerg)).
* Backported in [#133612](https://github.com/ClickHouse/ClickHouse/issues/133612): Fixed `EXISTS` returning `1` (and `NOT EXISTS` returning `0`) when its subquery returns no rows because an `arrayJoin` in it expands an empty array. [#133172](https://github.com/ClickHouse/ClickHouse/pull/133172) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133588](https://github.com/ClickHouse/ClickHouse/issues/133588): Removed the background task that cleaned up unused directories in `store/`. With `async_load_databases` enabled, it could revoke all access rights from the data directory of an attached table (queries to the table failed with `Permission denied`) and delete the directory 30 days later. It could also delete the data of a table that was recoverable with `ATTACH TABLE ... UUID` after a power loss. Unused directories in `store/` are now left untouched. The server settings `database_catalog_unused_dir_hide_timeout_sec`, `database_catalog_unused_dir_rm_timeout_sec`, and `database_catalog_unused_dir_cleanup_period_sec` are obsolete and have no effect. [#133464](https://github.com/ClickHouse/ClickHouse/pull/133464) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133542](https://github.com/ClickHouse/ClickHouse/issues/133542): Fixed JSON schema inference that, depending on memory reuse, could reject valid input with `TYPE_MISMATCH` (for example `{"x":0}`, `{"x":-1}`, `{"y":1}`, `{"y":18446744073709551615}` in `JSONEachRow`) or infer a wrong type such as `Array(Dynamic)` instead of `Array(Nullable(UInt64))`. It also infers `String` instead of failing for JSON strings that mix `Int64` and larger integers with non-numeric text (with `input_format_json_try_infer_numbers_from_strings = 1` and `input_format_json_read_numbers_as_strings = 0`). [#133506](https://github.com/ClickHouse/ClickHouse/pull/133506) ([Groene AI](https://github.com/groeneai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#133023](https://github.com/ClickHouse/ClickHouse/issues/133023): Fix Iceberg manifest-list pruning skipping NULL partitions for `ifNull`/`coalesce` filters. [#130158](https://github.com/ClickHouse/ClickHouse/pull/130158) ([Groene AI](https://github.com/groeneai)).
