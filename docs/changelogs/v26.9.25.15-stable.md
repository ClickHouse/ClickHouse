# 2026 Changelog

### ClickHouse release v26.9.25.15-stable (235315b9148) FIXME as compared to v26.9.24.8-stable (eb9d89e2a30)

#### Improvement
* Backported in [#127348](https://github.com/ClickHouse/ClickHouse/issues/127348): Add the `tcp_with_proxy_allow_interserver_mode` server setting, which allows disabling the native protocol's interserver mode on `tcp_with_proxy_port`. [#123188](https://github.com/ClickHouse/ClickHouse/pull/123188) ([Pradeep Chhetri](https://github.com/chhetripradeep)).
* Backported in [#127237](https://github.com/ClickHouse/ClickHouse/issues/127237): Fix a possible crash or out-of-bounds memory access when reading from HDFS if a DataNode or NameNode sends malformed responses. [#126546](https://github.com/ClickHouse/ClickHouse/pull/126546) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#127203](https://github.com/ClickHouse/ClickHouse/issues/127203): Improve glue catalog cache. Let's cache only mapping column name -> timestamp, not the whole metadata. [#127043](https://github.com/ClickHouse/ClickHouse/pull/127043) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#127164](https://github.com/ClickHouse/ClickHouse/issues/127164): Fix a second-factor bypass in the MySQL protocol: a user configured with `plaintext_password` or `double_sha1_password` plus a time-based one-time password could authenticate with the password alone, because the `mysql_native_password` auth response was verified without checking the TOTP. Such users are now switched to the `sha256_password` plugin and must append the one-time password to the password, like `password+123456`. [#117407](https://github.com/ClickHouse/ClickHouse/pull/117407) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#127341](https://github.com/ClickHouse/ClickHouse/issues/127341): Fix query parameters in the filter of `CREATE ROW POLICY` and `ALTER ROW POLICY` being stored unsubstituted: a `{db:Identifier}` table qualifier was resolved in the current database of the query reading the table, and a value parameter made every read of the table fail. The parameters are now substituted when the policy is created, and an `Identifier` query parameter that reaches a filter unsubstituted (for example in `additional_table_filters`) fails with `UNKNOWN_QUERY_PARAMETER`. [#122688](https://github.com/ClickHouse/ClickHouse/pull/122688) ([Groene AI](https://github.com/groeneai)).
* Backported in [#127316](https://github.com/ClickHouse/ClickHouse/issues/127316): Fixed a row-policy bypass where an authenticated user could forge the result of a scalar subquery used in a row policy (e.g. `USING has((SELECT ...), col)`) by sending a `Scalar` packet (as with `clickhouse-client --external ... --scalar`) named with the subquery's query-tree hash, and read rows the policy should hide. Client-supplied scalars are no longer accepted by the analyzer's scalar-subquery cache. <!-- CURSOR_AGENT_PR_BODY_END -->. [#125495](https://github.com/ClickHouse/ClickHouse/pull/125495) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Backported in [#125889](https://github.com/ClickHouse/ClickHouse/issues/125889): Creating a FileLog tables now require READ and WRITE privileges, analogous to File tables. [#125701](https://github.com/ClickHouse/ClickHouse/pull/125701) ([Robert Schulze](https://github.com/rschu1ze)).
* Backported in [#127219](https://github.com/ClickHouse/ClickHouse/issues/127219): For users with a time-based one-time password, the error `REQUIRED_SECOND_FACTOR` is now returned whenever the code is missing, regardless of whether the password is correct. Previously a wrong password without a code returned `AUTHENTICATION_FAILED`, which allowed guessing the password without the second factor. The password is verified only together with the code. The error maps to HTTP status 403 instead of 500. `clickhouse-client` prompts for the password before the code when neither is given, so users with `no_password` and TOTP now press Enter at the password prompt. [#125823](https://github.com/ClickHouse/ClickHouse/pull/125823) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#127358](https://github.com/ClickHouse/ClickHouse/issues/127358): Keeper no longer pre-allocates memory for the array size declared in a request (for example the ACL list in `Create`) before it reads the array elements. Before this fix, a small malformed request could cause a large memory allocation. [#126914](https://github.com/ClickHouse/ClickHouse/pull/126914) ([Antonio Andelic](https://github.com/antonio2368)).
* Backported in [#127306](https://github.com/ClickHouse/ClickHouse/issues/127306): Fixed wrong strings, sometimes followed by an `UNKNOWN_PACKET_FROM_SERVER` error, when a sparse `Nullable(String)` column is sent over the native protocol to `clickhouse-client` or between servers by `remote`, `cluster` and `Distributed`, for example `toString(nullIf(x, 0))` over a sparse column, or `toString` of a `Nullable` column stored with `nullable_serialization_version = 'allow_sparse'`. Closes [#126854](https://github.com/ClickHouse/ClickHouse/issues/126854). [#126937](https://github.com/ClickHouse/ClickHouse/pull/126937) ([Groene AI](https://github.com/groeneai)).
* Backported in [#127104](https://github.com/ClickHouse/ClickHouse/issues/127104): Fix `polygonConvexHullCartesian` returning garbage for a polygon with an empty exterior ring and a non-empty interior ring. [#127015](https://github.com/ClickHouse/ClickHouse/pull/127015) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#127179](https://github.com/ClickHouse/ClickHouse/issues/127179): Fixes a crash in estimateCompressionRatio with codecs DoubleDelta and Gorilla. [#127139](https://github.com/ClickHouse/ClickHouse/pull/127139) ([Robert Schulze](https://github.com/rschu1ze)).
