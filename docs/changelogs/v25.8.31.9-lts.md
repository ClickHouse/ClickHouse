# 2026 Changelog

### ClickHouse release v25.8.31.9-lts (95bde92a2c1) FIXME as compared to v25.8.30.16-lts (041f2f1bd67)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#114621](https://github.com/ClickHouse/ClickHouse/issues/114621): Fix invalid result on joining multiple table expressions, when leftmost table expression is a `-Cluster` table function. Resolves [#89996](https://github.com/ClickHouse/ClickHouse/issues/89996). [#94748](https://github.com/ClickHouse/ClickHouse/pull/94748) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#114761](https://github.com/ClickHouse/ClickHouse/issues/114761): Fix a rare `LOGICAL_ERROR` "Attempt to release query context that does not exist" and the accompanying server crash when reading `MergeTree` tables through a filesystem cache disk created with `enable_filesystem_query_cache_limit = 1`. [#107028](https://github.com/ClickHouse/ClickHouse/pull/107028) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115088](https://github.com/ClickHouse/ClickHouse/issues/115088): `RESTORE` now fsyncs the restored part files when the destination table has `fsync_after_insert` enabled, so a restored part is as durable against power loss as an inserted one. Previously restored files were only written and closed (never fsynced), so a power loss right after `RESTORE` returned `RESTORED` could leave the parts torn and the table empty. [#111378](https://github.com/ClickHouse/ClickHouse/pull/111378) ([Groene AI](https://github.com/groeneai)).
* Backported in [#114307](https://github.com/ClickHouse/ClickHouse/issues/114307): Fixed a row policy containing a scalar subquery being evaluated only once and then reused forever after the table had been read through a `Merge` table. The parsed policy condition is cached and shared by all queries, and reading it through `Merge` rewrote the cached expression in place, which also caused a data race between concurrent queries using the same policy. [#113563](https://github.com/ClickHouse/ClickHouse/pull/113563) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#114804](https://github.com/ClickHouse/ClickHouse/issues/114804): Fix `CANNOT_CONVERT_TYPE` and an exception in `GroupingAggregatedTransform` when reading a `Merge` table with one child being a `Distributed` table under custom-key parallel replicas (`parallel_replicas_mode = 'custom_key_sampling'` or `'custom_key_range'`). Closes [#113741](https://github.com/ClickHouse/ClickHouse/issues/113741). [#113742](https://github.com/ClickHouse/ClickHouse/pull/113742) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#114927](https://github.com/ClickHouse/ClickHouse/issues/114927): Fixed heap memory corruption when reading Parquet through an input format that owns its read buffer, for example a dictionary with `SOURCE(FILE(... format 'Parquet'))`. Background prefetch and decode tasks could still read and write through the buffer after the pipeline released it, which could abort the server. [#114668](https://github.com/ClickHouse/ClickHouse/pull/114668) ([Groene AI](https://github.com/groeneai)).

#### Build/Testing/Packaging Improvement
* Backported in [#114699](https://github.com/ClickHouse/ClickHouse/issues/114699): Update `libssh` to 0.12.0. [#108329](https://github.com/ClickHouse/ClickHouse/pull/108329) ([Konstantin Bogdanov](https://github.com/thevar1able)).

#### NOT FOR CHANGELOG / INSIGNIFICANT
