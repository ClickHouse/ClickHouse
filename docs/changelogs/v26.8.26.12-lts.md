# 2026 Changelog

### ClickHouse release v26.8.26.12-lts (a9f78f125b2) FIXME as compared to v26.8.25.14-lts (fe4c23110e1)

#### Backward Incompatible Change
* Outbound TLS connections no longer verify that the server certificate names the host by default (reverts https://github.com/ClickHouse/ClickHouse/pull/116724), because it broke `clickhouse-client --tls-sni-override`. Set `openSSL.client.extendedVerification` to `true` to enable the check. [#125570](https://github.com/ClickHouse/ClickHouse/pull/125570) ([Nikita Fomichev](https://github.com/fm4v)).

#### Performance Improvement
* Backported in [#124065](https://github.com/ClickHouse/ClickHouse/issues/124065): `optimize_and_compare_chain` again derives transitive conditions through a `DateTime` or lower-scale `DateTime64` constant compared with a `DateTime64` expression, as it did before 26.8. For example, `t1.ts < toDateTime('2026-09-16 00:00:00') AND t1.ts >= t2.ts` adds `t2.ts < toDateTime('2026-09-16 00:00:00')`, so the other side of a join can be pruned by its partition and primary key instead of being read in full. Closes [#123706](https://github.com/ClickHouse/ClickHouse/issues/123706). [#123796](https://github.com/ClickHouse/ClickHouse/pull/123796) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#125541](https://github.com/ClickHouse/ClickHouse/issues/125541): Added a server setting `access_control_improvements.readonly_restricts_set_role`, `false` by default. When enabled, `SET ROLE` is refused with error code `READONLY` in a session or query whose `readonly` setting is not zero. Previously `SET ROLE` was the only identity-changing statement that `readonly` did not refuse. [#118021](https://github.com/ClickHouse/ClickHouse/pull/118021) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125460](https://github.com/ClickHouse/ClickHouse/issues/125460): Added the setting use_aggregation_memory_tracker to choose how GROUP BY measures its memory when deciding on two-level aggregation. compatibility below 26.9 restores the measurement from before 26.7. [#124439](https://github.com/ClickHouse/ClickHouse/pull/124439) ([Hechem Selmi](https://github.com/m-selmi)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125545](https://github.com/ClickHouse/ClickHouse/issues/125545): Fix wrong results for `uniq*`, `GROUP BY`, `LIMIT n BY`, `ORDER BY` after `GROUP BY`, and window `PARTITION BY` over `toString` of a `DateTime`/`DateTime64` in a time zone with a daylight-saving transition, and over `toFixedString` of a `String`. Both functions claimed to be injective while mapping distinct arguments onto the same result, and the default-on optimizations that take that claim as a proof then eliminated the wrapper. [#117238](https://github.com/ClickHouse/ClickHouse/pull/117238) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125473](https://github.com/ClickHouse/ClickHouse/issues/125473): Fixed `use_skip_indexes = 0` also disabling part pruning by the partition-key min-max index (since 26.5), which made such queries read every part of the table. [#123403](https://github.com/ClickHouse/ClickHouse/pull/123403) ([Ashish Kumar Choubey](https://github.com/aschoube)).
* Backported in [#125551](https://github.com/ClickHouse/ClickHouse/issues/125551): Fixed queries that go through another server (`remote`, `Distributed`, parallel replicas, `GLOBAL IN`) failing with `SYNTAX_ERROR`, `UNKNOWN_CODEC` or `CORRUPTED_DATA` when `output_format_native_encode_types_in_binary_format` or `input_format_native_decode_types_in_binary_format` is enabled. The blocks of these queries now carry type names on the wire, and a shard with this change also works with an initiator without it. `clickhouse-client --query_kind secondary_query` follows the same rule. [#123649](https://github.com/ClickHouse/ClickHouse/pull/123649) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124658](https://github.com/ClickHouse/ClickHouse/issues/124658): Reject malformed serialized `groupBitmap` states with `INCORRECT_DATA` instead of failing later during bitmap operations. [#124049](https://github.com/ClickHouse/ClickHouse/pull/124049) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#125387](https://github.com/ClickHouse/ClickHouse/issues/125387): Fixed a `WHERE` condition or a row policy on a Hive partition column (`use_hive_partitioning = 1`) returning too few rows when the Parquet data file also has a column with that name and other values: Parquet row-group, page and dictionary pruning used the file's values instead of the path's. The same applied to a virtual column such as `_file` when the data file has a physical column with that name. Affects `file`, `url`, `s3` and other object storages. [#124991](https://github.com/ClickHouse/ClickHouse/pull/124991) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125481](https://github.com/ClickHouse/ClickHouse/issues/125481): Fixed a heap use-after-free in the `s3`, `azureBlobStorage`, `hdfs` and other object storage table functions and engines when an exception (for example `MEMORY_LIMIT_EXCEEDED`) was thrown while creating the reader of a file in a row input format such as `CSV`. [#125090](https://github.com/ClickHouse/ClickHouse/pull/125090) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125485](https://github.com/ClickHouse/ClickHouse/issues/125485): Fixed a server crash, wrong results or a rejected query in `ORDER BY ... WITH FILL ... INTERPOLATE` when one `INTERPOLATE` expression has to be converted to its target's type and another item reads the same column or literal, for example `INTERPOLATE (a AS b, b AS a)` with targets of different types. [#125129](https://github.com/ClickHouse/ClickHouse/pull/125129) ([Groene AI](https://github.com/groeneai)).
