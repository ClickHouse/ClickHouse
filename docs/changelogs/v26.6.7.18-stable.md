# 2026 Changelog

### ClickHouse release v26.6.7.18-stable (bc7f520bc36) FIXME as compared to v26.6.6.15-stable (36f312a89ae)

#### Improvement
* Backported in [#119965](https://github.com/ClickHouse/ClickHouse/issues/119965): Bump the internal libssh from 0.12.0 to 0.12.2. [#119262](https://github.com/ClickHouse/ClickHouse/pull/119262) ([Robert Schulze](https://github.com/rschu1ze)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#119939](https://github.com/ClickHouse/ClickHouse/issues/119939): Fix a logical error `Invalid cast from Nothing to native type` (an abort in debug/sanitizer builds) when `compile_expressions = 1` compiled an expression with a `Nullable(Nothing)` operand, e.g. `and(Nullable(Nothing), <native comparison>)`. [#111508](https://github.com/ClickHouse/ClickHouse/pull/111508) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119914](https://github.com/ClickHouse/ClickHouse/issues/119914): Fixed Iceberg `INSERT` writing manifest-wide aggregate column statistics into every `data_file` entry when a partition produced more than one data file. Each entry's `null_value_counts`, `column_sizes`, `lower_bounds` and `upper_bounds` now describe only the data file it points at. Previously an entry could report more nulls than the file had rows, so a spec-conforming external reader pruned files that contained matching rows. [#112414](https://github.com/ClickHouse/ClickHouse/pull/112414) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119972](https://github.com/ClickHouse/ClickHouse/issues/119972): Apply `remote_url_allow_hosts` before SQL-supplied S3 and Azure endpoints send schema, metadata, or container requests. [#114357](https://github.com/ClickHouse/ClickHouse/pull/114357) ([Rory Shanks](https://github.com/rorylshanks)).
* Backported in [#119951](https://github.com/ClickHouse/ClickHouse/issues/119951): Fix a segmentation fault when reading in order from a `Merge` table over `MergeTree` tables whose sorting key is shorter than the key prefix chosen for the query: the prefix was forwarded to the underlying reader unchecked, which grew its cloned sorting-key expression list to that length and appended null AST nodes that were then dereferenced. [#116364](https://github.com/ClickHouse/ClickHouse/pull/116364) ([Groene AI](https://github.com/groeneai)).
* Backported in [#120003](https://github.com/ClickHouse/ClickHouse/issues/120003): `format_display_secrets_in_show_and_select` works as expected in EXPLAIN. [#118129](https://github.com/ClickHouse/ClickHouse/pull/118129) ([Kirill Kopnev](https://github.com/Fgrtue)).
* Backported in [#119930](https://github.com/ClickHouse/ClickHouse/issues/119930): Fix rows silently dropped by an `ngrambf_v1` index for a `LIKE` pattern with a run of escaped backslashes before a wildcard. [#118673](https://github.com/ClickHouse/ClickHouse/pull/118673) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#119855](https://github.com/ClickHouse/ClickHouse/issues/119855): Fixed a crash and a `LOGICAL_ERROR` for statements that write `trim(BOTH '' FROM x)` (or the `LEADING`/`TRAILING` spelling) where a function is expected: a column's `STATISTICS(...)` or `CODEC(...)` list, `INDEX ... TYPE`, `ALTER TABLE ... ADD STATISTICS`, `auto_statistics_types`, a table function, a named collection and `SETTINGS`. The parser folded it into its operand instead of building a `trimBoth` call, and those places cast or dereference the result as a function. The fold also bypassed the function's own checks, so `trim(BOTH '' FROM <non-string>)` now raises `ILLEGAL_TYPE_OF_ARGUMENT` and a `FixedString` argument now yields `String`, as every other `trim` spelling does. [#119317](https://github.com/ClickHouse/ClickHouse/pull/119317) ([Groene AI](https://github.com/groeneai)).
* Backported in [#120053](https://github.com/ClickHouse/ClickHouse/issues/120053): Fixed an `ALTER` on a view or materialized view with `SQL SECURITY DEFINER` deleting the auto-created `<user>:definer` account when the `ALTER` did not change the definer. Every later `SELECT` from the view, and every `INSERT` into a materialized view's source table, then failed permanently with `There is no user '<user>:definer' in 'user directories'` (`UNKNOWN_USER`). [#119357](https://github.com/ClickHouse/ClickHouse/pull/119357) ([Groene AI](https://github.com/groeneai)).
* Backported in [#120018](https://github.com/ClickHouse/ClickHouse/issues/120018): Fixed cleartext credentials in `system.asynchronous_insert_log.query`. Secrets of table functions such as `s3`, `url` or `mysql` are now masked as `[HIDDEN]`, the same way `system.query_log` masks them. [#119487](https://github.com/ClickHouse/ClickHouse/pull/119487) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#120086](https://github.com/ClickHouse/ClickHouse/issues/120086): Fixed the server not validating the schema of the second and subsequent data blocks that a client sends for an external table over the native protocol. Such a block could make the data be interpreted as a type other than the one it was sent as. [#119849](https://github.com/ClickHouse/ClickHouse/pull/119849) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120013](https://github.com/ClickHouse/ClickHouse/issues/120013): Fixed a crash of the server caused by a table with `ENGINE = NATS` whose credentials the broker started to reject, for example after a password rotation or on an expired token. Such a table now recreates its connection and resumes consuming once the credentials are accepted again, instead of staying silently idle. [#119853](https://github.com/ClickHouse/ClickHouse/pull/119853) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Backported in [#120005](https://github.com/ClickHouse/ClickHouse/issues/120005): Fix flaky `test_filesystem_split_cache::test_split_cache_system_files_no_eviction`. The baseline System-segment count was sampled straight after `wait_for_cache_initialized`, which only reports that the cache became usable while background loading keeps adding segments, so the baseline was a partially populated snapshot (416 or 467 against a steady state of 701). The assertion was also two-sided (`abs`), so it failed when the count *grew* — the opposite of what a no-eviction test should check, and the cause of every observed failure. Both comparison points now sample once the count has settled, and the assertion only fails on a drop. Fixes failures like this one https://s3.amazonaws.com/clickhouse-test-reports/json.html?PR=111406&sha=6282394660bff978c2f06b63ecfd9f27d28b1e97&name_0=PR&name_1=Integration+tests+%28amd_tsan%2C+3%2F6%29. [#112099](https://github.com/ClickHouse/ClickHouse/pull/112099) ([Pedro Ferreira](https://github.com/PedroTadim)).
