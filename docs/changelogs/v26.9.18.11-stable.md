# 2026 Changelog

### ClickHouse release v26.9.18.11-stable (46140d6a7c6) FIXME as compared to v26.9.17.8-stable (d3f97a8b309)

#### Performance Improvement
* Backported in [#124066](https://github.com/ClickHouse/ClickHouse/issues/124066): `optimize_and_compare_chain` again derives transitive conditions through a `DateTime` or lower-scale `DateTime64` constant compared with a `DateTime64` expression, as it did before 26.8. For example, `t1.ts < toDateTime('2026-09-16 00:00:00') AND t1.ts >= t2.ts` adds `t2.ts < toDateTime('2026-09-16 00:00:00')`, so the other side of a join can be pruned by its partition and primary key instead of being read in full. Closes [#123706](https://github.com/ClickHouse/ClickHouse/issues/123706). [#123796](https://github.com/ClickHouse/ClickHouse/pull/123796) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#125537](https://github.com/ClickHouse/ClickHouse/issues/125537): Added a server setting `access_control_improvements.readonly_restricts_set_role`, `false` by default. When enabled, `SET ROLE` is refused with error code `READONLY` in a session or query whose `readonly` setting is not zero. Previously `SET ROLE` was the only identity-changing statement that `readonly` did not refuse. [#118021](https://github.com/ClickHouse/ClickHouse/pull/118021) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125464](https://github.com/ClickHouse/ClickHouse/issues/125464): Added the setting use_aggregation_memory_tracker to choose how GROUP BY measures its memory when deciding on two-level aggregation. compatibility below 26.9 restores the measurement from before 26.7. [#124439](https://github.com/ClickHouse/ClickHouse/pull/124439) ([Hechem Selmi](https://github.com/m-selmi)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125546](https://github.com/ClickHouse/ClickHouse/issues/125546): Fix wrong results for `uniq*`, `GROUP BY`, `LIMIT n BY`, `ORDER BY` after `GROUP BY`, and window `PARTITION BY` over `toString` of a `DateTime`/`DateTime64` in a time zone with a daylight-saving transition, and over `toFixedString` of a `String`. Both functions claimed to be injective while mapping distinct arguments onto the same result, and the default-on optimizations that take that claim as a proof then eliminated the wrapper. [#117238](https://github.com/ClickHouse/ClickHouse/pull/117238) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125504](https://github.com/ClickHouse/ClickHouse/issues/125504): Fixed the `LOGICAL_ERROR` `Reading from materialized CTE '...' before its materialization completed - DelayedPortsProcessor gate is missing in the query plan` raised when an `IN` or other set subquery defines a `MATERIALIZED` CTE that two other `MATERIALIZED` CTEs of that subquery read (for example a `UNION ALL` whose branches each chain two `MATERIALIZED` CTEs), in a lightweight `UPDATE`/`DELETE` or a `SELECT`, on a table read with more than one stream. [#121010](https://github.com/ClickHouse/ClickHouse/pull/121010) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125474](https://github.com/ClickHouse/ClickHouse/issues/125474): Fixed `use_skip_indexes = 0` also disabling part pruning by the partition-key min-max index (since 26.5), which made such queries read every part of the table. [#123403](https://github.com/ClickHouse/ClickHouse/pull/123403) ([Ashish Kumar Choubey](https://github.com/aschoube)).
* Backported in [#124659](https://github.com/ClickHouse/ClickHouse/issues/124659): Reject malformed serialized `groupBitmap` states with `INCORRECT_DATA` instead of failing later during bitmap operations. [#124049](https://github.com/ClickHouse/ClickHouse/pull/124049) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#125393](https://github.com/ClickHouse/ClickHouse/issues/125393): Fixed a `WHERE` condition or a row policy on a Hive partition column (`use_hive_partitioning = 1`) returning too few rows when the Parquet data file also has a column with that name and other values: Parquet row-group, page and dictionary pruning used the file's values instead of the path's. The same applied to a virtual column such as `_file` when the data file has a physical column with that name. Affects `file`, `url`, `s3` and other object storages. [#124991](https://github.com/ClickHouse/ClickHouse/pull/124991) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125482](https://github.com/ClickHouse/ClickHouse/issues/125482): Fixed a heap use-after-free in the `s3`, `azureBlobStorage`, `hdfs` and other object storage table functions and engines when an exception (for example `MEMORY_LIMIT_EXCEEDED`) was thrown while creating the reader of a file in a row input format such as `CSV`. [#125090](https://github.com/ClickHouse/ClickHouse/pull/125090) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125486](https://github.com/ClickHouse/ClickHouse/issues/125486): Fixed a server crash, wrong results or a rejected query in `ORDER BY ... WITH FILL ... INTERPOLATE` when one `INTERPOLATE` expression has to be converted to its target's type and another item reads the same column or literal, for example `INTERPOLATE (a AS b, b AS a)` with targets of different types. [#125129](https://github.com/ClickHouse/ClickHouse/pull/125129) ([Groene AI](https://github.com/groeneai)).
