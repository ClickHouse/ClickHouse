# 2026 Changelog

### ClickHouse release v26.3.65.10-lts (7c5a986fec0) FIXME as compared to v26.3.64.3-lts (3386d2ee171)

#### Backward Incompatible Change
* Backported in [#131779](https://github.com/ClickHouse/ClickHouse/issues/131779): Settings of type `Seconds` (for example `max_execution_time` or `lock_acquire_timeout`) now reject a negative value with `BAD_ARGUMENTS`. A negative `max_execution_time` meant no limit and passed a `MAX` constraint; a value whose microseconds round to `2^63` (for example `9223372036854.775`) was stored as a large negative number; it is rejected too. Before upgrading, remove negative values of these settings from configuration files, settings profiles, users and table definitions, and let `Distributed` async insert queues drain; otherwise the server can fail to start, a user or table fails to load, or a queued insert is never sent. [#131269](https://github.com/ClickHouse/ClickHouse/pull/131269) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#131747](https://github.com/ClickHouse/ClickHouse/issues/131747): Fixed `optimize_rewrite_aggregate_function_with_if` (enabled by default) turning a short-circuit-guarded aggregate such as `sum(if(number = 0, 0, intDiv(42, number)))` into a query failure: the rewritten `sumIf(intDiv(42, number), number != 0)` evaluates its argument for every row, so the guarded expression ran on the rows the condition excluded and threw. The rewrite is now refused when the lifted branch relies on short-circuit evaluation. Closes [#85784](https://github.com/ClickHouse/ClickHouse/issues/85784). [#118697](https://github.com/ClickHouse/ClickHouse/pull/118697) ([Groene AI](https://github.com/groeneai)).
* Backported in [#131746](https://github.com/ClickHouse/ClickHouse/issues/131746): With `prefer_column_name_to_alias = 1`, an unqualified column name that is ambiguous between joined tables now resolves to the alias with the same name, as the old analyzer did, instead of throwing `AMBIGUOUS_IDENTIFIER`. [#119192](https://github.com/ClickHouse/ClickHouse/pull/119192) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#131524](https://github.com/ClickHouse/ClickHouse/issues/131524): `CREATE NAMED COLLECTION`, `ALTER NAMED COLLECTION` and `DROP NAMED COLLECTION` are now rejected in readonly mode and with `allow_ddl = 0`, like other DDL queries. [#130952](https://github.com/ClickHouse/ClickHouse/pull/130952) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131869](https://github.com/ClickHouse/ClickHouse/issues/131869): Fix a possible crash of the server after a memory allocation failed while a background task was rescheduling itself. [#130997](https://github.com/ClickHouse/ClickHouse/pull/130997) ([Sergei Trifonov](https://github.com/serxa)).
* Backported in [#131553](https://github.com/ClickHouse/ClickHouse/issues/131553): Fixed a use-after-free on reading a Delta Lake table with column mapping in which a column is stored under the name of another column (for example, after column mapping is enabled on an existing table and columns are renamed), when the columns are requested in a particular order, such as `SELECT k_old, k`. [#131029](https://github.com/ClickHouse/ClickHouse/pull/131029) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131802](https://github.com/ClickHouse/ClickHouse/issues/131802): Fix a possible crash of the `Template` input format when the format string for the result set does not contain `${data}`. Now it is an error. [#131730](https://github.com/ClickHouse/ClickHouse/pull/131730) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131841](https://github.com/ClickHouse/ClickHouse/issues/131841): Fix a one-byte heap overflow when reading a `String` state of `any`/`min`/`max` (and similar) aggregate functions in an old format that ends without the zero terminator. Original fix by @motsc. [#131795](https://github.com/ClickHouse/ClickHouse/pull/131795) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Keep the `NULL` partition in Delta Lake partition pruning when the filter's set holds `NULL`. [#131851](https://github.com/ClickHouse/ClickHouse/pull/131851) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
