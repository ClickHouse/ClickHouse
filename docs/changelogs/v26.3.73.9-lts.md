# 2026 Changelog

### ClickHouse release v26.3.73.9-lts (f78b33d4632) FIXME as compared to v26.3.72.6-lts (a587d4a24dd)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134545](https://github.com/ClickHouse/ClickHouse/issues/134545): The `Kafka` table engine no longer accepts `librdkafka` properties that refer to files on the server (for example, `kafka.ssl_ca_location`, `kafka.ssl_key_location`, `kafka.sasl_kerberos_keytab`) from a named collection created with `CREATE NAMED COLLECTION`. Such a table fails with `BAD_ARGUMENTS`, and an existing table stops consuming and producing until the collection is changed. Define the collection in the server configuration file, or pass the contents of the file with the `.pem` properties (for example, `kafka.ssl_ca_pem`). [#132488](https://github.com/ClickHouse/ClickHouse/pull/132488) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#134502](https://github.com/ClickHouse/ClickHouse/issues/134502): `ATTACH MATERIALIZED VIEW` with a full definition now validates the `SELECT` query the same way as `CREATE MATERIALIZED VIEW`. [#133025](https://github.com/ClickHouse/ClickHouse/pull/133025) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Backported in [#134801](https://github.com/ClickHouse/ClickHouse/issues/134801): With `access_control_improvements.readonly_restricts_set_role` enabled, `SET DEFAULT ROLE` is now refused in `readonly` mode as well as `SET ROLE`. Previously a readonly session could change its own default roles and so start the next session with another role. [#133762](https://github.com/ClickHouse/ClickHouse/pull/133762) ([Vadim Skipin](https://github.com/vadimskipin)).
* Backported in [#133880](https://github.com/ClickHouse/ClickHouse/issues/133880): The secret first key argument of "keyed" SipHash SQL functions is now masked in `system.query_log`. [#133828](https://github.com/ClickHouse/ClickHouse/pull/133828) ([Robert Schulze](https://github.com/rschu1ze)).

#### Build/Testing/Packaging Improvement
* Backported in [#134745](https://github.com/ClickHouse/ClickHouse/issues/134745): Update `krb5` from 1.22.2-final to 1.22.3-final. [#133845](https://github.com/ClickHouse/ClickHouse/pull/133845) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#134795](https://github.com/ClickHouse/ClickHouse/issues/134795): Update `zstd` to v1.6.0. [#134248](https://github.com/ClickHouse/ClickHouse/pull/134248) ([Actuele AI](https://github.com/actueleai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#134427](https://github.com/ClickHouse/ClickHouse/issues/134427): When a MergeTree table was created with table_disk=1, it stores all data (parts/tmp files/detached directory) in the root of this disk, and when this table is dropped, dropAllData calls remove-recursive on the root folder. When this table was located on the encrypted disk, this call would, in fact, remove the root folder of that disk. The problem is that if other normal tables (without table_disk) were created there, this call would remove their data as well. [#134192](https://github.com/ClickHouse/ClickHouse/pull/134192) ([Mikhail Artemenko](https://github.com/Michicosun)).
* 26.3: Do not reuse `MacroExpansionInfo` for consecutive `expand` calls in queue storages. [#134710](https://github.com/ClickHouse/ClickHouse/pull/134710) ([Pedro Ferreira](https://github.com/PedroTadim)).
