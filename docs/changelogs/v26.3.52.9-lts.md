# 2026 Changelog

### ClickHouse release v26.3.52.9-lts (fe8ff5d492a) FIXME as compared to v26.3.51.7-lts (c36b897f01f)

#### Backward Incompatible Change
* Backported in [#125778](https://github.com/ClickHouse/ClickHouse/issues/125778): Connections to MySQL (the `mysql` table function, the `MySQL` table and database engines, and `MySQL` dictionaries) that set `ssl_ca` or `ssl_ca_pem` now also verify the server host name, after updating `mariadb-connector-c` to v3.4.10. The certificate chain was already verified against the configured CA, but a connection to a server whose certificate does not list the host name or IP address used to connect succeeded and now fails with `Hostname verification failed`. Before upgrading, make sure the MySQL server certificate lists the host name or IP address ClickHouse connects to. [#119510](https://github.com/ClickHouse/ClickHouse/pull/119510) ([Actuele AI](https://github.com/actueleai)).

#### Improvement
* Backported in [#125787](https://github.com/ClickHouse/ClickHouse/issues/125787): Add S3 bucket to `remote_url_allow_hosts`. [#124453](https://github.com/ClickHouse/ClickHouse/pull/124453) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125832](https://github.com/ClickHouse/ClickHouse/issues/125832): Fixed a stack overflow crash on a deeply nested CapnProto schema that the nesting depth check missed: a comment or a byte order mark between `import` and its path, an escape sequence in the import path, or a backtick text line. A backtick text line with many brackets is no longer rejected as nested too deeply. [#125487](https://github.com/ClickHouse/ClickHouse/pull/125487) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125730](https://github.com/ClickHouse/ClickHouse/issues/125730): The web terminal and the SSH interface no longer reset the settings of the user (from settings profiles, roles, and `CREATE USER ... SETTINGS`) to default values. Previously, restrictions such as `readonly`, resource limits, and `additional_table_filters` were not applied in these interfaces. [#125515](https://github.com/ClickHouse/ClickHouse/pull/125515) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125873](https://github.com/ClickHouse/ClickHouse/issues/125873): Fix a wrong result, or an exception in debug builds, when `optimize_aggregators_of_group_by_keys` eliminated `any`, `min` or `max` of a `GROUPING SETS` key with `group_by_use_nulls`. [#125575](https://github.com/ClickHouse/ClickHouse/pull/125575) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125862](https://github.com/ClickHouse/ClickHouse/issues/125862): Fixed a server crash when a `RabbitMQ` table with the `headers` exchange type had a routing key without `=`, or when `rabbitmq_routing_key_list` was empty. Routing keys without `=` for the `headers` exchange type are now rejected with an exception. The problem was found and reported by @dstesk (https://github.com/dstesk). [#125661](https://github.com/ClickHouse/ClickHouse/pull/125661) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Build/Testing/Packaging Improvement
* Backported in [#125905](https://github.com/ClickHouse/ClickHouse/issues/125905): Update `vectorscan` to 5.4.13. [#125774](https://github.com/ClickHouse/ClickHouse/pull/125774) ([Actuele AI](https://github.com/actueleai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#124946](https://github.com/ClickHouse/ClickHouse/issues/124946): Use `castStorage` for the `Join` row policy check in the legacy analyzer. [#124441](https://github.com/ClickHouse/ClickHouse/pull/124441) ([Vladimir Cherkasov](https://github.com/vdimir)).
