# 2026 Changelog

### ClickHouse release v26.6.2.158-stable (dc7e750e89b) FIXME as compared to v26.6.1.1193-stable (6615864161f)

#### New Feature
* Backported in [#108687](https://github.com/ClickHouse/ClickHouse/issues/108687): Introduce a memory reservation feature for workloads. More details https://clickhouse.com/docs/operations/workload-scheduling. [#82414](https://github.com/ClickHouse/ClickHouse/pull/82414) ([Sergei Trifonov](https://github.com/serxa)).
* Backported in [#109481](https://github.com/ClickHouse/ClickHouse/issues/109481): Added a postprocessor to the text index which transforms the tokens after tokenization. [#108606](https://github.com/ClickHouse/ClickHouse/pull/108606) ([Jimmy Aguilar Mena](https://github.com/Ergus)).

#### Experimental Feature
* Backported in [#112820](https://github.com/ClickHouse/ClickHouse/issues/112820): AI functions no longer take the named collection as the first positional argument. Credentials come from the `ai_function_text_default_credentials` / `ai_function_embedding_default_credentials` settings or from a `credentials` key in an optional trailing `Map(String, String)` argument, which also carries tunables (`model`, `max_tokens`, `temperature`, `system_prompt`, `instructions`, `dimensions`). [#109232](https://github.com/ClickHouse/ClickHouse/pull/109232) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#112937](https://github.com/ClickHouse/ClickHouse/issues/112937): Tag OpenAI-format HTTP requests with the SQL name of the calling AI function for upstream endpoint identification. [#110449](https://github.com/ClickHouse/ClickHouse/pull/110449) ([George Larionov](https://github.com/george-larionov)).

#### Performance Improvement
* Backported in [#110684](https://github.com/ClickHouse/ClickHouse/issues/110684): Improve execution of `arrayElement` on `Array(LowCardinality(String))` and map LIKE functions on maps with `LowCardinality(String)` keys or values by avoiding unnecessary string materialization. [#107450](https://github.com/ClickHouse/ClickHouse/pull/107450) ([Michael Jarrett](https://github.com/EmeraldShift)).
* Backported in [#109124](https://github.com/ClickHouse/ClickHouse/issues/109124): Fixed a performance regression (introduced in [#71781](https://github.com/ClickHouse/ClickHouse/issues/71781)) where reading many small files from object storage via the `s3()` and other table functions stopped prefetching and fell back to synchronous reads, significantly slowing single-threaded / low-concurrency reads of lots of tiny files. [#108872](https://github.com/ClickHouse/ClickHouse/pull/108872) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#109559](https://github.com/ClickHouse/ClickHouse/issues/109559): Issue the initial small-object prefetch also when object storage reads go through the filesystem cache (`filesystem_cache_name`). Previously ([#108872](https://github.com/ClickHouse/ClickHouse/issues/108872)) the prefetch was restored only for non-cached reads, so reads of many small files (e.g. `S3Queue` ingestion) with the filesystem cache enabled remained synchronous and latency-bound. [#109478](https://github.com/ClickHouse/ClickHouse/pull/109478) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#111238](https://github.com/ClickHouse/ClickHouse/issues/111238): Optimized analysis of the text index. [#109886](https://github.com/ClickHouse/ClickHouse/pull/109886) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#110800](https://github.com/ClickHouse/ClickHouse/issues/110800): Account for Map subcolumn on-disk size in prewhere optimization. This fixes the regression in PREWHERE introduced in https://github.com/ClickHouse/ClickHouse/pull/99200. Part of [#110462](https://github.com/ClickHouse/ClickHouse/issues/110462). [#110623](https://github.com/ClickHouse/ClickHouse/pull/110623) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#111637](https://github.com/ClickHouse/ClickHouse/issues/111637): Lazy materialization is now applied to queries with `FINAL`, a filter, and a small `LIMIT`, even without `ORDER BY` (for `ReplacingMergeTree`). [#110722](https://github.com/ClickHouse/ClickHouse/pull/110722) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#111463](https://github.com/ClickHouse/ClickHouse/issues/111463): Fixed O(P×N) deduplication hash recomputation in async insert flushes that split across P partitions. `DeduplicationInfo::prewarmDataHashes` is now called once before the partition loop in `MergeTreeSink` and `ReplicatedMergeTreeSink`, so all per-partition clones inherit pre-computed `data_hash_batch` values instead of recomputing them P times. This reduces `DuplicationElapsedMicroseconds` proportionally to the number of partitions. [#111150](https://github.com/ClickHouse/ClickHouse/pull/111150) ([Valery Petrov](https://github.com/valerypetrov)).

#### Improvement
* Backported in [#110859](https://github.com/ClickHouse/ClickHouse/issues/110859): Support compatibility with the old analyzer under the `analyzer_compatibility_allow_non_aggregate_in_having` setting. If enabled, non-aggregate conjunctions will be moved from HAVING to WHERE. [#104232](https://github.com/ClickHouse/ClickHouse/pull/104232) ([Dmitry Novik](https://github.com/novikd)).
* Backported in [#112776](https://github.com/ClickHouse/ClickHouse/issues/112776): Support the `REDUCED_REDUNDANCY`, `STANDARD_IA`, `ONEZONE_IA`, `GLACIER_IR`, and `EXPRESS_ONEZONE` values (in addition to `STANDARD` and `INTELLIGENT_TIERING`) for the `s3_storage_class_name` setting. [#107251](https://github.com/ClickHouse/ClickHouse/pull/107251) ([Aditya Kumar](https://github.com/adityaksolves)).
* Backported in [#112710](https://github.com/ClickHouse/ClickHouse/issues/112710): AI functions (`aiGenerate`, `aiEmbed`, `aiClassify`, `aiExtract`, `aiTranslate`) now retry transient network failures (connection resets, TLS connect failures, timeouts, unreachable addresses) when `ai_function_max_retries` is set, matching the retry behavior of the `url` table function. Previously only provider-side HTTP error responses were retried. [#107927](https://github.com/ClickHouse/ClickHouse/pull/107927) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#109566](https://github.com/ClickHouse/ClickHouse/issues/109566): Reduce filesystem cache per-segment and per-key memory metadata. [#108477](https://github.com/ClickHouse/ClickHouse/pull/108477) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Backported in [#110379](https://github.com/ClickHouse/ClickHouse/issues/110379): MergeTree can now read a compressed stream whose blocks use different codecs. This is the read-side prerequisite for adaptive codec selection (https://github.com/ClickHouse/ClickHouse/issues/105404). [#108592](https://github.com/ClickHouse/ClickHouse/pull/108592) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Backported in [#109271](https://github.com/ClickHouse/ClickHouse/issues/109271): Restore `show_data_lake_catalogs_in_system_tables` as the setting that controls only `DataLakeCatalog` visibility in `system.tables`, `system.columns`, and `system.completions`. Added `show_remote_databases_in_system_tables`, enabled by default, to let users hide `MySQL` and `PostgreSQL` databases from those system tables separately. [#109082](https://github.com/ClickHouse/ClickHouse/pull/109082) ([Pablo Marcos](https://github.com/pamarcos)).
* Backported in [#112850](https://github.com/ClickHouse/ClickHouse/issues/112850): Reduced memory usage when opening a backup (for `RESTORE`, or as the base of an incremental `BACKUP`). The `.backup` metadata is now parsed as a stream instead of being loaded into an in-memory XML document tree, which for large (especially incremental) backups avoids allocating a multi-gigabyte DOM tree. [#109107](https://github.com/ClickHouse/ClickHouse/pull/109107) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#109318](https://github.com/ClickHouse/ClickHouse/issues/109318): Reduce memory consumption in aggregator. [#109224](https://github.com/ClickHouse/ClickHouse/pull/109224) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#110417](https://github.com/ClickHouse/ClickHouse/issues/110417): I always find it difficult to add multiple metrics to the dashboard during debugging sessions. This patch adds a simpler way to add them directly from the source code or documentation. [#109449](https://github.com/ClickHouse/ClickHouse/pull/109449) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Backported in [#111745](https://github.com/ClickHouse/ClickHouse/issues/111745): Added the `jemalloc_merge_tree_arenas` server setting controlling the dedicated jemalloc arena(s) used for `MergeTree` part and table metadata: `0` disables it, `1` uses a single arena (default), and `N` creates a per-CPU pool. On many-core servers a pool reduces memory-allocator lock contention between concurrent merges. The dedicated arena was also narrowed to hold only long-lived metadata. [#109490](https://github.com/ClickHouse/ClickHouse/pull/109490) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#112809](https://github.com/ClickHouse/ClickHouse/issues/112809): Reduced peak memory usage when finalizing a `BACKUP`. Writing the backup metadata no longer copies the file infos of all files into a temporary vector (which, for backups of millions of files, transiently cost several gigabytes); the infos are now iterated in place. [#109861](https://github.com/ClickHouse/ClickHouse/pull/109861) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#111486](https://github.com/ClickHouse/ClickHouse/issues/111486): `IS NOT DISTINCT FROM` and `IS TRUE` now use primary-key and minmax indexes to prune granules, the same as `=`. Previously `k IS NOT DISTINCT FROM 42` and `(k = 42) IS TRUE` scanned all granules. [#110006](https://github.com/ClickHouse/ClickHouse/pull/110006) ([Groene AI](https://github.com/groeneai)).
* Backported in [#111987](https://github.com/ClickHouse/ClickHouse/issues/111987): Added setting `analyzer_compatibility_apply_final_to_all_joined_tables` that restores the old behavior, where the `FINAL` modifier on the left-most table of a JOIN was also applied to the other joined tables. The setting is registered in the settings changes history, so `compatibility` with versions before 26.6 restores the old semantics automatically. [#111589](https://github.com/ClickHouse/ClickHouse/pull/111589) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#112368](https://github.com/ClickHouse/ClickHouse/issues/112368): The effective named collections storage type is now available as `named_collections_storage.type` in `system.server_settings` and through `getServerSetting('named_collections_storage_type')`. [#111806](https://github.com/ClickHouse/ClickHouse/pull/111806) ([Pablo Marcos](https://github.com/pamarcos)).
* Backported in [#112475](https://github.com/ClickHouse/ClickHouse/issues/112475): Reduce CPU usage when making snapshot for huge amout of files. [#112297](https://github.com/ClickHouse/ClickHouse/pull/112297) ([Han Fei](https://github.com/hanfei1991)).

Models must now be located inside `user_files`. [#108463](https://github.com/ClickHouse/ClickHouse/pull/108463) ([Groene AI](https://github.com/groeneai)).
* Backported in [#108706](https://github.com/ClickHouse/ClickHouse/issues/108706): Fixed `ssl_certificate` user identification so a single `*` wildcard matches exactly one name component (RFC 6125 6.4.3). Previously a wildcard in a `CN` or `DNS:` SAN subject (for example `*.corp.example.com`) also matched multi-label names such as `evil.deep.corp.example.com`, letting a holder of a certificate for a deeper subdomain authenticate as the wildcard user. `URI:` SAN matching is unchanged. [#108472](https://github.com/ClickHouse/ClickHouse/pull/108472) ([Groene AI](https://github.com/groeneai)).

* Backported in [#108832](https://github.com/ClickHouse/ClickHouse/issues/108832): Fixed a server crash (stack overflow) caused by deeply nested expressions such as `[[[ ... ]]]` or `array(array( ... ))` when `max_parser_depth` is set to a large value. [#108508](https://github.com/ClickHouse/ClickHouse/pull/108508) ([Groene AI](https://github.com/groeneai)).
* Backported in [#109572](https://github.com/ClickHouse/ClickHouse/issues/109572): Match `http_forbid_headers` case-insensitively. HTTP header names are case-insensitive, so forbidding `Authorization` now also blocks `authorization`, `AUTHORIZATION` and other case variants. Configured `header_regexp` patterns are now matched case-insensitively without needing an explicit `(?i)` flag. [#108509](https://github.com/ClickHouse/ClickHouse/pull/108509) ([Groene AI](https://github.com/groeneai)).
* Backported in [#108719](https://github.com/ClickHouse/ClickHouse/issues/108719): Fix `NOT_FOUND_COLUMN_IN_BLOCK` when a compound predicate is aliased in `GROUP BY` and referenced again, with `enable_identifier_resolve_cache` enabled (the default). The `optimize_and_compare_chain` optimization was not idempotent and a shared resolved node accumulated a duplicate transitive conjunct. [#108553](https://github.com/ClickHouse/ClickHouse/pull/108553) ([Groene AI](https://github.com/groeneai)).
* Backported in [#110091](https://github.com/ClickHouse/ClickHouse/issues/110091): Fix a `SELECT *` projection returning a column's type default (e.g. `0`) instead of its `DEFAULT` value (e.g. `-1`) when reading a column added with `ALTER TABLE ... * Backported in [#108669](https://github.com/ClickHouse/ClickHouse/issues/108669): Fixed direct read from multiple partially materialized text indexes. [#108607](https://github.com/ClickHouse/ClickHouse/pull/108607) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#108699](https://github.com/ClickHouse/ClickHouse/issues/108699): Fix a metadata-disclosure where `DESCRIBE loop('db', 'table')` and `DESCRIBE loop(<inner table function>)` bypassed the `SHOW COLUMNS` / source access check, letting an unprivileged user read a table's column schema. [#108624](https://github.com/ClickHouse/ClickHouse/pull/108624) ([Groene AI](https://github.com/groeneai)).

* Backported in [#113256](https://github.com/ClickHouse/ClickHouse/issues/113256): Fixed an out-of-bounds write when reading a `Parquet` `DECIMAL` column whose physical type is wider than the type its declared precision maps to, for example `DECIMAL(9, 2)` stored as physical `INT64`. Such files are valid `Parquet` and other writers produce them, but the reader sized the destination column from the declared precision while the decoder wrote the physical width, corrupting memory. Reading such a file now also raises `DECIMAL_OVERFLOW` when a value does not fit the declared precision, instead of returning corrupted data, and reads losslessly with a type hint at least as wide as the physical type. [#113046](https://github.com/ClickHouse/ClickHouse/pull/113046) ([Groene AI](https://github.com/groeneai)).
