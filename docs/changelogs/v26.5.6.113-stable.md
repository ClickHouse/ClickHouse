# 2026 Changelog

### ClickHouse release v26.5.6.113-stable (ab581010f0c) FIXME as compared to v26.5.5.8-stable (1d04e5e9f07)

#### Experimental Feature
* Backported in [#108984](https://github.com/ClickHouse/ClickHouse/issues/108984): Add `aiEmbed` function for using LLM APIs to generate embeddings from within ClickHouse. [#102922](https://github.com/ClickHouse/ClickHouse/pull/102922) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#112525](https://github.com/ClickHouse/ClickHouse/issues/112525): Removing requirement for api key in AI credential named collections. [#105701](https://github.com/ClickHouse/ClickHouse/pull/105701) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#112819](https://github.com/ClickHouse/ClickHouse/issues/112819): AI functions no longer take the named collection as the first positional argument. Credentials come from the `ai_function_text_default_credentials` / `ai_function_embedding_default_credentials` settings or from a `credentials` key in an optional trailing `Map(String, String)` argument, which also carries tunables (`model`, `max_tokens`, `temperature`, `system_prompt`, `instructions`, `dimensions`). [#109232](https://github.com/ClickHouse/ClickHouse/pull/109232) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#112939](https://github.com/ClickHouse/ClickHouse/issues/112939): Tag OpenAI-format HTTP requests with the SQL name of the calling AI function for upstream endpoint identification. [#110449](https://github.com/ClickHouse/ClickHouse/pull/110449) ([George Larionov](https://github.com/george-larionov)).

#### Performance Improvement
* Backported in [#109133](https://github.com/ClickHouse/ClickHouse/issues/109133): Fixed a performance regression (introduced in [#71781](https://github.com/ClickHouse/ClickHouse/issues/71781)) where reading many small files from object storage via the `s3()` and other table functions stopped prefetching and fell back to synchronous reads, significantly slowing single-threaded / low-concurrency reads of lots of tiny files. [#108872](https://github.com/ClickHouse/ClickHouse/pull/108872) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#109558](https://github.com/ClickHouse/ClickHouse/issues/109558): Issue the initial small-object prefetch also when object storage reads go through the filesystem cache (`filesystem_cache_name`). Previously ([#108872](https://github.com/ClickHouse/ClickHouse/issues/108872)) the prefetch was restored only for non-cached reads, so reads of many small files (e.g. `S3Queue` ingestion) with the filesystem cache enabled remained synchronous and latency-bound. [#109478](https://github.com/ClickHouse/ClickHouse/pull/109478) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#110799](https://github.com/ClickHouse/ClickHouse/issues/110799): Account for Map subcolumn on-disk size in prewhere optimization. This fixes the regression in PREWHERE introduced in https://github.com/ClickHouse/ClickHouse/pull/99200. Part of [#110462](https://github.com/ClickHouse/ClickHouse/issues/110462). [#110623](https://github.com/ClickHouse/ClickHouse/pull/110623) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#111636](https://github.com/ClickHouse/ClickHouse/issues/111636): Lazy materialization is now applied to queries with `FINAL`, a filter, and a small `LIMIT`, even without `ORDER BY` (for `ReplacingMergeTree`). [#110722](https://github.com/ClickHouse/ClickHouse/pull/110722) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#111462](https://github.com/ClickHouse/ClickHouse/issues/111462): Fixed O(P×N) deduplication hash recomputation in async insert flushes that split across P partitions. `DeduplicationInfo::prewarmDataHashes` is now called once before the partition loop in `MergeTreeSink` and `ReplicatedMergeTreeSink`, so all per-partition clones inherit pre-computed `data_hash_batch` values instead of recomputing them P times. This reduces `DuplicationElapsedMicroseconds` proportionally to the number of partitions. [#111150](https://github.com/ClickHouse/ClickHouse/pull/111150) ([Valery Petrov](https://github.com/valerypetrov)).

#### Improvement
* Backported in [#110858](https://github.com/ClickHouse/ClickHouse/issues/110858): Support compatibility with the old analyzer under the `analyzer_compatibility_allow_non_aggregate_in_having` setting. If enabled, non-aggregate conjunctions will be moved from HAVING to WHERE. [#104232](https://github.com/ClickHouse/ClickHouse/pull/104232) ([Dmitry Novik](https://github.com/novikd)).
* Backported in [#108852](https://github.com/ClickHouse/ClickHouse/issues/108852): Fix `DataLakeCatalog` databases with `catalog_type = 'onelake'` reading table data by using the OneLake Blob endpoint (`.blob.fabric.microsoft.com`) by default. Set `onelake_use_blob_endpoint = false` to keep the previous DFS endpoint (`.dfs.fabric.microsoft.com`) behavior. [#106843](https://github.com/ClickHouse/ClickHouse/pull/106843) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#112901](https://github.com/ClickHouse/ClickHouse/issues/112901): Support the `REDUCED_REDUNDANCY`, `STANDARD_IA`, `ONEZONE_IA`, `GLACIER_IR`, and `EXPRESS_ONEZONE` values (in addition to `STANDARD` and `INTELLIGENT_TIERING`) for the `s3_storage_class_name` setting. [#107251](https://github.com/ClickHouse/ClickHouse/pull/107251) ([Aditya Kumar](https://github.com/adityaksolves)).
* Backported in [#110489](https://github.com/ClickHouse/ClickHouse/issues/110489): Fixed reading of the `auth_response` length in the MySQL handshake, where a length byte `>= 128` was interpreted as a multi-gigabyte value because it was read as a signed `char`. [#107384](https://github.com/ClickHouse/ClickHouse/pull/107384) ([uwezkhan](https://github.com/uwezkhan)).
* Backported in [#112663](https://github.com/ClickHouse/ClickHouse/issues/112663): AI functions (`aiGenerate`, `aiEmbed`, `aiClassify`, `aiExtract`, `aiTranslate`) now retry transient network failures (connection resets, TLS connect failures, timeouts, unreachable addresses) when `ai_function_max_retries` is set, matching the retry behavior of the `url` table function. Previously only provider-side HTTP error responses were retried. [#107927](https://github.com/ClickHouse/ClickHouse/pull/107927) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#109565](https://github.com/ClickHouse/ClickHouse/issues/109565): Reduce filesystem cache per-segment and per-key memory metadata. [#108477](https://github.com/ClickHouse/ClickHouse/pull/108477) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Backported in [#110387](https://github.com/ClickHouse/ClickHouse/issues/110387): MergeTree can now read a compressed stream whose blocks use different codecs. This is the read-side prerequisite for adaptive codec selection (https://github.com/ClickHouse/ClickHouse/issues/105404). [#108592](https://github.com/ClickHouse/ClickHouse/pull/108592) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Backported in [#109270](https://github.com/ClickHouse/ClickHouse/issues/109270): Restore `show_data_lake_catalogs_in_system_tables` as the setting that controls only `DataLakeCatalog` visibility in `system.tables`, `system.columns`, and `system.completions`. Added `show_remote_databases_in_system_tables`, enabled by default, to let users hide `MySQL` and `PostgreSQL` databases from those system tables separately. [#109082](https://github.com/ClickHouse/ClickHouse/pull/109082) ([Pablo Marcos](https://github.com/pamarcos)).
* Backported in [#110416](https://github.com/ClickHouse/ClickHouse/issues/110416): I always find it difficult to add multiple metrics to the dashboard during debugging sessions. This patch adds a simpler way to add them directly from the source code or documentation. [#109449](https://github.com/ClickHouse/ClickHouse/pull/109449) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Backported in [#111752](https://github.com/ClickHouse/ClickHouse/issues/111752): Added the `jemalloc_merge_tree_arenas` server setting controlling the dedicated jemalloc arena(s) used for `MergeTree` part and table metadata: `0` disables it, `1` uses a single arena (default), and `N` creates a per-CPU pool. On many-core servers a pool reduces memory-allocator lock contention between concurrent merges. The dedicated arena was also narrowed to hold only long-lived metadata. [#109490](https://github.com/ClickHouse/ClickHouse/pull/109490) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#112367](https://github.com/ClickHouse/ClickHouse/issues/112367): The effective named collections storage type is now available as `named_collections_storage.type` in `system.server_settings` and through `getServerSetting('named_collections_storage_type')`. [#111806](https://github.com/ClickHouse/ClickHouse/pull/111806) ([Pablo Marcos](https://github.com/pamarcos)).
* Backported in [#112474](https://github.com/ClickHouse/ClickHouse/issues/112474): Reduce CPU usage when making snapshot for huge amout of files. [#112297](https://github.com/ClickHouse/ClickHouse/pull/112297) ([Han Fei](https://github.com/hanfei1991)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#112750](https://github.com/ClickHouse/ClickHouse/issues/112750): Fix logical error exception when reading Iceberg tables whose format version was upgraded by an external tool (e.g. Spark). [#100407](https://github.com/ClickHouse/ClickHouse/pull/100407) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#109338](https://github.com/ClickHouse/ClickHouse/issues/109338): Fixed a race between `ALTER TABLE ... RENAME COLUMN` and a concurrent `OPTIMIZE TABLE ... FINAL` (or any background merge) in `MergeTree` that could silently replace the renamed column's data with default values. The race window between publishing the new in-memory metadata and registering the rename mutation in `current_mutations_by_version` is now closed by holding `currently_processing_in_background_mutex` across both operations. [#104822](https://github.com/ClickHouse/ClickHouse/pull/104822) ([Groene AI](https://github.com/groeneai)).
* Backported in [#111002](https://github.com/ClickHouse/ClickHouse/issues/111002): Add a new compatibility setting `analyzer_compatibility_prefer_alias_over_subcolumn` (disabled by default). When enabled, the new analyzer prefers the alias-prefix interpretation over Tuple-subcolumn / dotted-column matches for multi-part identifiers, restoring the previous interpreter's behavior. This avoids `AMBIGUOUS_IDENTIFIER` (and related) errors when a query joins a table whose name matches an inner table of a CTE/subquery that uses `SELECT *` over a join, where asterisk-renamed columns (e.g. `b.id`) would otherwise leak the inner table identifiers into the outer scope. [#105491](https://github.com/ClickHouse/ClickHouse/pull/105491) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#109921](https://github.com/ClickHouse/ClickHouse/issues/109921): Added data validation on insertions https://github.com/ClickHouse/ClickHouse/pull/98284#issuecomment-4592701308. * Backported in [#109528](https://github.com/ClickHouse/ClickHouse/issues/109528): Fix `optimize_skip_unused_shards` did not apply (and force_optimize_skip_unused_shards falsely failing) when a `Distributed` table is queried through a `Merge` table or the `merge` table function, with the predicate applied above it. [#106250](https://github.com/ClickHouse/ClickHouse/pull/106250) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#110753](https://github.com/ClickHouse/ClickHouse/issues/110753): Fix `RestCatalog::empty` returning the wrong result when an Iceberg REST catalog contains tables. [#106301](https://github.com/ClickHouse/ClickHouse/pull/106301) ([Lefteris](https://github.com/LefterisXefteris)).

* Backported in [#110658](https://github.com/ClickHouse/ClickHouse/issues/110658): Fixed wrong query results caused by the query condition cache when on-fly mutations (`apply_mutations_on_fly`) or patch parts filtered rows before `PREWHERE`. A query reading with `apply_mutations_on_fly = 1` could poison the cache so that a later query with `apply_mutations_on_fly = 0` and the same predicate skipped marks it should have read and returned too few rows. The same fix also covers row-level security policies, which are prepended as a filter ahead of `PREWHERE`: a query run under a restrictive row policy could poison the cache for a later query that uses the same predicate without that policy. [#107145](https://github.com/ClickHouse/ClickHouse/pull/107145) ([Groene AI](https://github.com/groeneai)).
* Backported in [#108920](https://github.com/ClickHouse/ClickHouse/issues/108920): Incremental backups no longer store `S3` credentials in the `<base_backup>` locator of the `.backup` metadata file. Backups created with `use_same_s3_credentials_for_base_backup = 1`, or with explicit base backup credentials matching this backup locator, store a non-secret marker and are restored without extra restore-time settings; for backups created with different explicit base backup credentials or extra base authentication arguments, pass them to `RESTORE` with the `base_backup` setting. Backups created by older versions with embedded credentials remain restorable. [#107357](https://github.com/ClickHouse/ClickHouse/pull/107357) ([Pablo Marcos](https://github.com/pamarcos)).

The adopted part's merge level is now reset to 0 when the source and destination engines differ, so the destination deduplicates it on the next merge.
