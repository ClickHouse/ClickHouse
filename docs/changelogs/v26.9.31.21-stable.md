# 2026 Changelog

### ClickHouse release v26.9.31.21-stable (0ca4ad747b9) FIXME as compared to v26.9.30.7-stable (a43649d33fb)

#### Improvement
* Backported in [#132045](https://github.com/ClickHouse/ClickHouse/issues/132045): `ReplicatedMergeTree` now removes old deduplication blocks from Keeper in batches of `TryRemove` requests instead of one `Remove` request per block. This reduces the number of Raft entries in Keeper for tables with many replicas. [#128645](https://github.com/ClickHouse/ClickHouse/pull/128645) ([Antonio Andelic](https://github.com/antonio2368)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132032](https://github.com/ClickHouse/ClickHouse/issues/132032): Fixed `NOT_FOUND_COLUMN_IN_BLOCK` (`Not found column _row_exists in block`) that permanently blocked all further mutations of a `MergeTree` table after a lightweight `DELETE` run with `lightweight_delete_mode = 'lightweight_update'` was followed by a heavyweight `ALTER TABLE ... UPDATE` and then by another mutation rewriting all columns. Closes [#115570](https://github.com/ClickHouse/ClickHouse/issues/115570). [#115665](https://github.com/ClickHouse/ClickHouse/pull/115665) ([Groene AI](https://github.com/groeneai)).
* Backported in [#131988](https://github.com/ClickHouse/ClickHouse/issues/131988): With `analyzer_compatibility_join_using_top_level_identifier = 1`, a `JOIN USING` identifier is resolved from an alias of the query only for the outermost `JOIN`; an inner `JOIN` of a query with several joins resolves it from its left table, as the old analyzer did. This fixes `UNKNOWN_IDENTIFIER` for queries such as `SELECT if(m.symbol = '', b.symbol, m.symbol) AS symbol FROM m FULL JOIN b USING (symbol) FULL JOIN dttm ON 1 = 1`, and a `USING clause expected identifier` error when an inner `USING` join is placed below an aliased outermost `USING` key. [#123103](https://github.com/ClickHouse/ClickHouse/pull/123103) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#132304](https://github.com/ClickHouse/ClickHouse/issues/132304): A `Merge` table and the `merge` table function no longer count the matched tables the user cannot see (no `SHOW TABLES`) when `count()` is answered from metadata or in `system.tables` `total_rows`/`total_bytes`, and their `system.columns` sizes include only the columns the user can see (`SHOW COLUMNS`) on each matched table. Before, these disclosed the row count and size of tables the user has no access to, while reading the same data skipped them. [#129818](https://github.com/ClickHouse/ClickHouse/pull/129818) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132100](https://github.com/ClickHouse/ClickHouse/issues/132100): Fix a wrong order of rows for a query like `SELECT ... WHERE toDate(ts) = '2024-01-01' ORDER BY toDate(ts), b LIMIT 5` over a table with the sorting key `(ts, b)` when `optimize_read_in_order` is enabled. A query that filters a leading sorting key column by equality and lists it in `ORDER BY` (`WHERE a = 1 ORDER BY a, b`) is read in order through an `INNER JOIN` again. [#130893](https://github.com/ClickHouse/ClickHouse/pull/130893) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#132211](https://github.com/ClickHouse/ClickHouse/issues/132211): Fixed a memory leak when the merge of the per-thread hash tables of `GROUP BY` failed with an exception, for example on `max_memory_usage`: the states of aggregate functions such as `uniqExact` or `quantileExact` that waited to be merged were never freed. [#131595](https://github.com/ClickHouse/ClickHouse/pull/131595) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132131](https://github.com/ClickHouse/ClickHouse/issues/132131): Fixed `DROP WORKLOAD` removing a resource with the same name and `DROP RESOURCE` removing a workload with the same name when workload entities are stored in Keeper (`workload_zookeeper_path`). A user with only one of the two privileges could remove the other kind of entity. [#131688](https://github.com/ClickHouse/ClickHouse/pull/131688) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132080](https://github.com/ClickHouse/ClickHouse/issues/132080): Fix a server abort when merging a malformed serialized state of a `-Map` aggregate function with a `FixedString` key. Now such a state is rejected with `INCORRECT_DATA`. [#131732](https://github.com/ClickHouse/ClickHouse/pull/131732) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132208](https://github.com/ClickHouse/ClickHouse/issues/132208): Fix a possible crash when an exception (for example, a memory limit) is thrown during the short-circuit evaluation of a function returning an `AggregateFunction` state. [#131733](https://github.com/ClickHouse/ClickHouse/pull/131733) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132204](https://github.com/ClickHouse/ClickHouse/issues/132204): Fix a possible crash of the `PostgreSQL` table engine, table function and database engine when the remote server reports an absurd number of array dimensions. [#131734](https://github.com/ClickHouse/ClickHouse/pull/131734) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132271](https://github.com/ClickHouse/ClickHouse/issues/132271): Fix a stack overflow in the `ParquetMetadata` format for files with a very deeply nested schema. The depth is now limited by `max_parser_depth`, as in the `Parquet` format, and never exceeds 1000. [#131735](https://github.com/ClickHouse/ClickHouse/pull/131735) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132290](https://github.com/ClickHouse/ClickHouse/issues/132290): Fix out-of-bounds reads when deserializing a query plan with a step lacking some of its inputs or having extra children. Now such a plan is rejected with `INCORRECT_DATA`. [#131736](https://github.com/ClickHouse/ClickHouse/pull/131736) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132231](https://github.com/ClickHouse/ClickHouse/issues/132231): Fix a crash of the `DWARF` input format on an ELF file with a malformed attribute length. [#131787](https://github.com/ClickHouse/ClickHouse/pull/131787) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131847](https://github.com/ClickHouse/ClickHouse/issues/131847): Fix out-of-bounds reads when deserializing a query plan with a `FillingStep` repeating an `INTERPOLATE` column. Now such a plan is rejected with `INCORRECT_DATA`. [#131788](https://github.com/ClickHouse/ClickHouse/pull/131788) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132236](https://github.com/ClickHouse/ClickHouse/issues/132236): Fix out-of-bounds memory access with a state of `mergedJSONPatch` containing a repeated path. Now such a state is rejected with `INCORRECT_DATA`. [#131792](https://github.com/ClickHouse/ClickHouse/pull/131792) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132262](https://github.com/ClickHouse/ClickHouse/issues/132262): Fix a regression from [#110006](https://github.com/ClickHouse/ClickHouse/issues/110006) where `(range) OR x IS NULL`, with `x` a `Nullable` cast of a sort key expression (for example a column of a `UNION ALL` view whose other branch returns `NULL`), could not use the primary key or partition pruning and read all parts. [#131944](https://github.com/ClickHouse/ClickHouse/pull/131944) ([Seva Potapov](https://github.com/seva-potapov)).
