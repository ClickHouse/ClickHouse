# 2026 Changelog

### ClickHouse release v26.7.12.6-stable (952cd5eae0b) FIXME as compared to v26.7.11.16-stable (717876c9cef)

#### Performance Improvement
* Backported in [#120827](https://github.com/ClickHouse/ClickHouse/issues/120827): A small `LIMIT` on a query with `arrayJoin` shrinks the read block size again, so such queries no longer read whole blocks on every thread for a few output rows (a regression from 26.6, Closes [#119193](https://github.com/ClickHouse/ClickHouse/issues/119193)). [#120214](https://github.com/ClickHouse/ClickHouse/pull/120214) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#120813](https://github.com/ClickHouse/ClickHouse/issues/120813): Do not terminate the server when a transient error (such as `MEMORY_LIMIT_EXCEEDED`, a network error, or `SYSTEM RESTART REPLICA` running at the same time) happens while outdated data parts are being loaded in the background. Such errors are not a sign of an inconsistent set of parts on disk, so the loading is now retried later instead of aborting the server. [#117981](https://github.com/ClickHouse/ClickHouse/pull/117981) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120783](https://github.com/ClickHouse/ClickHouse/issues/120783): Fix `UNKNOWN_IDENTIFIER` errors in `INSERT ... SELECT` from a parameterized view when `parallel_distributed_insert_select` is enabled. the view was analyzed with the legacy interpreter even though the analyzer was enabled. [#119495](https://github.com/ClickHouse/ClickHouse/pull/119495) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#120794](https://github.com/ClickHouse/ClickHouse/issues/120794): Fixed a `HDFS` database serving a table from its internal cache without the `READ ON HDFS` grant. The grant and the `remote_url_allow_hosts` filter were checked only while a table name was resolved for the first time, so once any user holding the grant had read a name, every user with `SELECT` on the database was served the contents of the file, and that table kept being served after its host was removed from the allowlist. `EXISTS TABLE`, which requires only `SHOW TABLES`, answered from the same cache and so reported which names other users had resolved. Both checks now run before the cache is consulted, and the existence probe no longer consults it. [#119523](https://github.com/ClickHouse/ClickHouse/pull/119523) ([Groene AI](https://github.com/groeneai)).
