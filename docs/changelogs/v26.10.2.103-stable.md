# 2026 Changelog

### ClickHouse release v26.10.2.103-stable (c6428ebcc39) FIXME as compared to v26.10.1.1-new (6e598803749)

#### Backward Incompatible Change
* Backported in [#126380](https://github.com/ClickHouse/ClickHouse/issues/126380): `CREATE TABLE x AS src` inherits the credentials embedded in the engine of `src`, which are masked in `SHOW CREATE TABLE`. It now requires the `SELECT` privilege on `src` when the inherited definition can carry credentials, instead of only `SHOW COLUMNS`. [#118866](https://github.com/ClickHouse/ClickHouse/pull/118866) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Experimental Feature
* Backported in [#127147](https://github.com/ClickHouse/ClickHouse/issues/127147): Added the experimental `Elasticsearch` table engine and `elasticsearch` table function for reading documents from an Elasticsearch index as a `JSON` column, with the document id and index name available as virtual columns. Enable them with the `enable_elasticsearch` setting. [#124283](https://github.com/ClickHouse/ClickHouse/pull/124283) ([Kirill Kopnev](https://github.com/Fgrtue)).
* The setting `use_query_condition_cache_for_time_conditions` (using the query condition cache for conditions involving the current time) is now experimental and disabled by default. [#127632](https://github.com/ClickHouse/ClickHouse/pull/127632) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Performance Improvement
* Backported in [#127520](https://github.com/ClickHouse/ClickHouse/issues/127520): Conditions with AI functions (`aiGenerate`, `aiClassify`, `aiExtract`, `aiTranslate`, `aiFilter`, `aiRedact`, `aiEmbed`, `aiSimilarity`) are moved to the end of PREWHERE, so the AI function is called only for rows that pass the cheaper conditions. [#117802](https://github.com/ClickHouse/ClickHouse/pull/117802) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#127254](https://github.com/ClickHouse/ClickHouse/issues/127254): Column statistics of `MergeTree` data parts are cached per data part and column in a new statistics cache (server settings `statistics_cache_size`, `statistics_cache_policy`, `statistics_cache_size_ratio`; `SYSTEM DROP STATISTICS CACHE`), loaded on demand and merged on the fly for every query. Queries over a pruned set of parts no longer re-read statistics from disk on every execution, and there is no background task that loads the statistics of all columns of all parts. The settings `refresh_statistics_interval` and `use_statistics_cache` are obsolete. A new merge-tree setting `prewarm_statistics_cache` optionally prewarms the cache for new parts and on startup. [#120758](https://github.com/ClickHouse/ClickHouse/pull/120758) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126921](https://github.com/ClickHouse/ClickHouse/issues/126921): Lazy materialization now works for `LIMIT N` queries over JOINs. Controlled by the new setting `query_plan_lazy_materialization_for_join`, enabled by default. <!-- CI automatic block start :ci_links: -->. [#122682](https://github.com/ClickHouse/ClickHouse/pull/122682) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#127193](https://github.com/ClickHouse/ClickHouse/issues/127193): The `bloom_filter` index is now used for LEFT ARRAY JOIN. [#124426](https://github.com/ClickHouse/ClickHouse/pull/124426) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#126754](https://github.com/ClickHouse/ClickHouse/issues/126754): Sets of `IN` with a subquery spill to disk by default: `max_bytes_ratio_before_external_set` now defaults to `0.5`, so a set spills once query memory exceeds half of the memory that the server or user memory limits leave. Set it to `0` to keep such sets in memory. Sets on disk are built and looked up several times faster: they keep numbers, dates, short `FixedString` values and tuples of them in order, pack close keys, read neighboring blocks together without decompression, skip blocks with Bloom filters, cache the blocks that lookups read, and look up each distinct key of a block of rows once. The new settings `max_bytes_for_external_set_bloom_filter` and `max_bytes_for_external_set_cache`, 128 MiB each by default, limit the memory of the Bloom filters and of the cache. [#124907](https://github.com/ClickHouse/ClickHouse/pull/124907) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Backported in [#126581](https://github.com/ClickHouse/ClickHouse/issues/126581): An equality with a `Bool` value that no statistics can estimate, such as `WHERE j.f = false` on a JSON path, a `Bool` column without statistics, or `IN` with a `Bool` set, is now estimated to match half of the rows per value instead of 1%, so a join on such a filtered table builds its hash table from the smaller side again. [#125467](https://github.com/ClickHouse/ClickHouse/pull/125467) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126716](https://github.com/ClickHouse/ClickHouse/issues/126716): Estimating subcolumn sizes for `PREWHERE` (for example `m['key']` of a `Map(LowCardinality(String), String)` column) no longer reads the `LowCardinality` dictionary or the `Variant` discriminators header of every data part, which made planning slow on object storage, especially for each new map key. Closes [#114598](https://github.com/ClickHouse/ClickHouse/issues/114598). [#126046](https://github.com/ClickHouse/ClickHouse/pull/126046) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126767](https://github.com/ClickHouse/ClickHouse/issues/126767): `BACKUP` uses less memory per file it backs up: an entry of the backup no longer keeps a copy of the description of the disk the file is on. A backup of a table with millions of files saves a few gigabytes. [#126388](https://github.com/ClickHouse/ClickHouse/pull/126388) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#127312](https://github.com/ClickHouse/ClickHouse/issues/127312): `parallel_replicas_min_number_of_rows_per_replica` is ignored while `automatic_parallel_replicas_mode` builds its plan with parallel replicas, including in subqueries and views. Previously the row estimate for it ran a full extra index analysis on every such build, and its threshold could keep that plan from using replicas. [#126815](https://github.com/ClickHouse/ClickHouse/pull/126815) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#127192](https://github.com/ClickHouse/ClickHouse/issues/127192): `LEFT ARRAY JOIN` is about 20% faster on long `Array(String)` columns: each window of the joined arrays is now copied once instead of up to three times. The same applies to `arrayJoin(emptyArrayToSingle(x))`, which is executed as `LEFT ARRAY JOIN`. [#126838](https://github.com/ClickHouse/ClickHouse/pull/126838) ([Groene AI](https://github.com/groeneai)).
* Backported in [#127424](https://github.com/ClickHouse/ClickHouse/issues/127424): With parallel replicas and `use_skip_indexes_on_data_read`, follower replicas now evaluate skip indexes over the mark ranges analyzed on the initiator, received from the coordinator, instead of repeating the primary key analysis. [#126954](https://github.com/ClickHouse/ClickHouse/pull/126954) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#127493](https://github.com/ClickHouse/ClickHouse/issues/127493): `predictXGBoost` now runs in parallel on all query threads instead of using a single CPU core. The `verbosity` parameter of the `XGBOOST` dictionary layout no longer accepts the debug level `3`. [#127328](https://github.com/ClickHouse/ClickHouse/pull/127328) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Improvement
* Backported in [#126124](https://github.com/ClickHouse/ClickHouse/issues/126124): Improved `automatic_parallel_replicas` observability by adding outcome-specific `ProfileEvents`, split optimization/plan-build timing counters, and runtime statistics-collection timing in `query_log`. [#120884](https://github.com/ClickHouse/ClickHouse/pull/120884) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#127144](https://github.com/ClickHouse/ClickHouse/issues/127144): Queries with `FINAL` now use the virtual row optimization of reading in order. Supported for `ReplacingMergeTree`, `CollapsingMergeTree`, `VersionedCollapsingMergeTree`, `SummingMergeTree`, `AggregatingMergeTree` and `CoalescingMergeTree`. [#124468](https://github.com/ClickHouse/ClickHouse/pull/124468) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#126383](https://github.com/ClickHouse/ClickHouse/issues/126383): Reduced the memory usage of incremental `BACKUP`: the base backup keeps only the sizes and checksums of its files instead of the full information about each file. For a base backup of millions of files this saves gigabytes. [#125717](https://github.com/ClickHouse/ClickHouse/pull/125717) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#126325](https://github.com/ClickHouse/ClickHouse/issues/126325): Compare TOTP codes and `plaintext_password` passwords in constant time, so that the response time does not depend on how many leading characters are correct or on which time window matched. [#125785](https://github.com/ClickHouse/ClickHouse/pull/125785) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#126123](https://github.com/ClickHouse/ClickHouse/issues/126123): A replica that takes part in a parallel replicas read now follows the initiator even when its own `automatic_parallel_replicas_mode` is not 0, for example when `allow_feature_tier` drops the value the initiator sends, or when `INSERT ... SETTINGS automatic_parallel_replicas_mode = 2 SELECT` re-applies it on the replica. Previously such a replica read its whole table on its own, so a query could count rows more than once and a distributed `INSERT SELECT` wrote them once per replica. [#125801](https://github.com/ClickHouse/ClickHouse/pull/125801) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126650](https://github.com/ClickHouse/ClickHouse/issues/126650): The "Format" button in the Web UI now supports inputs with multiple queries: each query is formatted separately and replaced in place, keeping the comments and delimiters between them. [#125939](https://github.com/ClickHouse/ClickHouse/pull/125939) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#127319](https://github.com/ClickHouse/ClickHouse/issues/127319): Automatic parallel replicas settings (`automatic_parallel_replicas_mode`, `automatic_parallel_replicas_min_bytes_per_replica`) are now production tier instead of experimental. [#126005](https://github.com/ClickHouse/ClickHouse/pull/126005) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#126257](https://github.com/ClickHouse/ClickHouse/issues/126257): The nodes in the output of `EXPLAIN AST graph = 1` are numbered sequentially instead of being identified by memory addresses, so the output is the same on every run. [#126031](https://github.com/ClickHouse/ClickHouse/pull/126031) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#126255](https://github.com/ClickHouse/ClickHouse/issues/126255): Fatal error reports no longer contain runtime memory addresses: stack frames and the fault address are printed as offsets inside the executable or a library, which can be passed to `addr2line`, and other addresses are hidden. `system.crash_log.fault_address` now contains the offset inside the executable, or `NULL` when the address is elsewhere. [#126039](https://github.com/ClickHouse/ClickHouse/pull/126039) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#126912](https://github.com/ClickHouse/ClickHouse/issues/126912): A `JOIN` whose `ON` condition has a constant-false conjunct now works with the experimental `parallel_replicas_plan_based` setting when the join uses `grace_hash`, spills to disk, or runs with `join_use_nulls = 1`, instead of terminating the server or failing with `NOT_FOUND_COLUMN_IN_BLOCK`. [#126204](https://github.com/ClickHouse/ClickHouse/pull/126204) ([Groene AI](https://github.com/groeneai)).
* Backported in [#127238](https://github.com/ClickHouse/ClickHouse/issues/127238): Fix a possible crash or out-of-bounds memory access when reading from HDFS if a DataNode or NameNode sends malformed responses. [#126546](https://github.com/ClickHouse/ClickHouse/pull/126546) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126931](https://github.com/ClickHouse/ClickHouse/issues/126931): Adds a minimum threshold for spilling in-memory data when external aggregation is enabled. [#126756](https://github.com/ClickHouse/ClickHouse/pull/126756) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Backported in [#127466](https://github.com/ClickHouse/ClickHouse/issues/127466): System tables no longer contain runtime memory addresses: stack frames outside the main binary are stored as 0, `system.trace_log.ptr` is an identifier instead of an address, and the ids in `system.processors_profile_log` are indices within the query. [#126760](https://github.com/ClickHouse/ClickHouse/pull/126760) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#127204](https://github.com/ClickHouse/ClickHouse/issues/127204): Improve glue catalog cache. Let's cache only mapping column name -> timestamp, not the whole metadata. [#127043](https://github.com/ClickHouse/ClickHouse/pull/127043) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#127517](https://github.com/ClickHouse/ClickHouse/issues/127517): The `obfuscate` table function and the `clickhouse obfuscator` tool now support `LowCardinality`, `Enum`, `Date32`, `DateTime64`, `Decimal`, wide integers, `IPv4`, `IPv6`, `BFloat16`, `Tuple` and `Map` columns. The exception for an unsupported type now names the type and the column. [#127295](https://github.com/ClickHouse/ClickHouse/pull/127295) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#127576](https://github.com/ClickHouse/ClickHouse/issues/127576): Hardening: certificate chains containing the compromised eMudhra intermediate CAs or the roots that issued them (`emSign Root TLS CA - G3`, `emSign ECC Root CA - G3`) are rejected even if the trust store of the operating system still trusts them. The CA certificates embedded into the binary (used only when the system has none) are updated from the Chromium root store. There is no security issue in typical use cases. [#127318](https://github.com/ClickHouse/ClickHouse/pull/127318) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#127621](https://github.com/ClickHouse/ClickHouse/issues/127621): This patch supports `writeFileUsingBlobWritingFunction` for disks with multiple configured locations. [#127568](https://github.com/ClickHouse/ClickHouse/pull/127568) ([Mikhail Artemenko](https://github.com/Michicosun)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#127093](https://github.com/ClickHouse/ClickHouse/issues/127093): Fixed `RESTORE` failing with `READONLY` for a backup containing a table on read-only storage that provides the table's data itself, such as a shared example dataset. Such storage can now be marked with the storage policy option `backup_metadata_only`: `BACKUP` stores only the definitions of its tables, and `RESTORE` recreates them with their UUIDs from the backup without restoring data. [#113574](https://github.com/ClickHouse/ClickHouse/pull/113574) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#127165](https://github.com/ClickHouse/ClickHouse/issues/127165): Fix a second-factor bypass in the MySQL protocol: a user configured with `plaintext_password` or `double_sha1_password` plus a time-based one-time password could authenticate with the password alone, because the `mysql_native_password` auth response was verified without checking the TOTP. Such users are now switched to the `sha256_password` plugin and must append the one-time password to the password, like `password+123456`. [#117407](https://github.com/ClickHouse/ClickHouse/pull/117407) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#126165](https://github.com/ClickHouse/ClickHouse/issues/126165): Mask credentials embedded in HTTP URIs. [#120407](https://github.com/ClickHouse/ClickHouse/pull/120407) ([Han Fei](https://github.com/hanfei1991)).
* Backported in [#126828](https://github.com/ClickHouse/ClickHouse/issues/126828): Fixed a read of uninitialized memory when a `Variant`, `Dynamic` or `JSON` column holding only `NULL` values is compressed, for example on insert into a `Memory` table created with `compress = 1`, or when a block is compressed for a `JOIN` or for the query result cache. The reported size of such a column was also unspecified. [#120776](https://github.com/ClickHouse/ClickHouse/pull/120776) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126282](https://github.com/ClickHouse/ClickHouse/issues/126282): Requesting SSH-key authentication over the native protocol no longer reveals whether the named user exists, or how it authenticates, before its signature is checked. [#121704](https://github.com/ClickHouse/ClickHouse/pull/121704) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Backported in [#127513](https://github.com/ClickHouse/ClickHouse/issues/127513): Fix merges failing with `NOT_FOUND_COLUMN_IN_BLOCK` on every retry when a rows TTL reads a column that no part stores yet. [#122164](https://github.com/ClickHouse/ClickHouse/pull/122164) ([Murphy](https://github.com/murphy-4o)).
* Backported in [#127325](https://github.com/ClickHouse/ClickHouse/issues/127325): Fix query parameters in the filter of `CREATE ROW POLICY` and `ALTER ROW POLICY` being stored unsubstituted: a `{db:Identifier}` table qualifier was resolved in the current database of the query reading the table, and a value parameter made every read of the table fail. The parameters are now substituted when the policy is created, and an `Identifier` query parameter that reaches a filter unsubstituted (for example in `additional_table_filters`) fails with `UNKNOWN_QUERY_PARAMETER`. [#122688](https://github.com/ClickHouse/ClickHouse/pull/122688) ([Groene AI](https://github.com/groeneai)).
* Backported in [#127462](https://github.com/ClickHouse/ClickHouse/issues/127462): Fix possible crash due to use-after-free of memory reservation, and a possible hang of CPU and IO requests, after DROP WORKLOAD. Queries still running in a dropped workload now fail. [#123341](https://github.com/ClickHouse/ClickHouse/pull/123341) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#127229](https://github.com/ClickHouse/ClickHouse/issues/127229): Fix rows silently skipped by primary key, partition key and `minmax` skip index analysis when a `DateTime64` column with a fractional scale is compared with an integer or `DateTime` constant by `>` or `<`, for example `WHERE dt > 1577836800` on a `DateTime64(3)` key. The regression appeared in 26.3. [#123999](https://github.com/ClickHouse/ClickHouse/pull/123999) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126363](https://github.com/ClickHouse/ClickHouse/issues/126363): Reject CR and LF characters in values sent as HTTP headers or in the request line of outgoing HTTP requests (BigQuery, YTsaurus, `url`, DataLake catalogs, GCP OAuth, AI functions, S3 storage class), which could be used to inject headers or additional requests. [#124905](https://github.com/ClickHouse/ClickHouse/pull/124905) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#127317](https://github.com/ClickHouse/ClickHouse/issues/127317): Fixed a row-policy bypass where an authenticated user could forge the result of a scalar subquery used in a row policy (e.g. `USING has((SELECT ...), col)`) by sending a `Scalar` packet (as with `clickhouse-client --external ... --scalar`) named with the subquery's query-tree hash, and read rows the policy should hide. Client-supplied scalars are no longer accepted by the analyzer's scalar-subquery cache. <!-- CURSOR_AGENT_PR_BODY_END -->. [#125497](https://github.com/ClickHouse/ClickHouse/pull/125497) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Backported in [#127221](https://github.com/ClickHouse/ClickHouse/issues/127221): For users with a time-based one-time password, the error `REQUIRED_SECOND_FACTOR` is now returned whenever the code is missing, regardless of whether the password is correct. Previously a wrong password without a code returned `AUTHENTICATION_FAILED`, which allowed guessing the password without the second factor. The password is verified only together with the code. The error maps to HTTP status 403 instead of 500. `clickhouse-client` prompts for the password before the code when neither is given, so users with `no_password` and TOTP now press Enter at the password prompt. [#125823](https://github.com/ClickHouse/ClickHouse/pull/125823) ([Vladimir Cherkasov](https://github.com/vdimir)).

[#125893](https://github.com/ClickHouse/ClickHouse/pull/125893) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126352](https://github.com/ClickHouse/ClickHouse/issues/126352): The setting `http_zlib_compression_level` now applies only to the `gzip` and `deflate` HTTP response compression.
