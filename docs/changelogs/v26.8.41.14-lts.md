# 2026 Changelog

### ClickHouse release v26.8.41.14-lts (f380d224f9a) FIXME as compared to v26.8.40.7-lts (f20555c09af)

#### Performance Improvement
* Backported in [#132675](https://github.com/ClickHouse/ClickHouse/issues/132675): Removing data parts from a disk with `metadata_type = plain_rewritable` (cleanup of outdated parts, `TRUNCATE`, `DROP PARTITION`, `DROP TABLE`) no longer copies every file of the part to a temporary object before deleting it, and no longer holds the disk metadata lock for those copies. The part directory is removed with one batched delete request. Closes [#123275](https://github.com/ClickHouse/ClickHouse/issues/123275). [#123303](https://github.com/ClickHouse/ClickHouse/pull/123303) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132480](https://github.com/ClickHouse/ClickHouse/issues/132480): Fixed queries and merges on encrypted disks over remote storage discarding the first prefetch of every column and reading it again synchronously. [#132015](https://github.com/ClickHouse/ClickHouse/pull/132015) ([Christoph Wurm](https://github.com/cwurm)).

#### Improvement
* Backported in [#132691](https://github.com/ClickHouse/ClickHouse/issues/132691): Credentials in the URL of a `url` wildcard expanded from HTTP index pages (`allow_url_wildcard_from_index_pages`), or of a `web_index` disk, are now masked in the errors about an index page redirected to a different origin and about an index page over `max_http_index_page_size`. [#126184](https://github.com/ClickHouse/ClickHouse/pull/126184) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132647](https://github.com/ClickHouse/ClickHouse/issues/132647): `ATTACH TABLE ... AS REPLICATED` and `ATTACH TABLE ... AS NOT REPLICATED` now check the `TABLE ENGINE` grant on the engine the table is converted to before changing anything. Previously a query refused for this grant had already rewritten the stored definition of the detached table, so a later `ATTACH TABLE` loaded it with the new engine. [#128995](https://github.com/ClickHouse/ClickHouse/pull/128995) ([Nikolai Ovchinnikov](https://github.com/kolsha)).
* Backported in [#132645](https://github.com/ClickHouse/ClickHouse/issues/132645): When `http_forbid_headers` forbids `Authorization`, Basic credentials that would be sent in that header are now refused too: the userinfo of `url`, `urlCluster` and `URL` table URLs (including url wildcards and `web` disks), `credentials` of `HTTP` dictionaries created by DDL, the userinfo of `format_avro_schema_registry_url`, and `user`/`password` of the `Elasticsearch` engine. Before, only an explicit `Authorization` header was refused. [#129850](https://github.com/ClickHouse/ClickHouse/pull/129850) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132547](https://github.com/ClickHouse/ClickHouse/issues/132547): Prevent impersonation via forged SECONDARY_QUERY on secret clusters. [#130362](https://github.com/ClickHouse/ClickHouse/pull/130362) ([Vitaly Baranov](https://github.com/vitlibar)).
* Backported in [#132663](https://github.com/ClickHouse/ClickHouse/issues/132663): Fix server termination when outdated data parts cannot be scheduled for loading, e.g. when the global thread pool is exhausted. [#130816](https://github.com/ClickHouse/ClickHouse/pull/130816) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#132617](https://github.com/ClickHouse/ClickHouse/issues/132617): Fixed a type confusion (possible crash or out-of-bounds read) triggered by a client sending a column with a `Sparse` or `Replicated` serialization kind, or a `Tuple` with a `Replicated` element, in data over the native protocol. [#130895](https://github.com/ClickHouse/ClickHouse/pull/130895) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#132770](https://github.com/ClickHouse/ClickHouse/issues/132770): Fixed parsing of decimal text with an exponent close to the `Int32` limits: values such as `1e2147483647` were read as `0` instead of being rejected as too big. [#131373](https://github.com/ClickHouse/ClickHouse/pull/131373) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132734](https://github.com/ClickHouse/ClickHouse/issues/132734): The `URL ... is not allowed in configuration file, see <remote_url_allow_hosts>` error now shows only the host and port of the URL, so secrets in its path or query string are no longer exposed. [#132160](https://github.com/ClickHouse/ClickHouse/pull/132160) ([George Larionov](https://github.com/george-larionov)).

#### Build/Testing/Packaging Improvement
* Backported in [#132679](https://github.com/ClickHouse/ClickHouse/issues/132679): Update `wasmtime` to v50.0.1. [#128834](https://github.com/ClickHouse/ClickHouse/pull/128834) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Update `arrow` and `parquet` Rust crates used by Delta Lake support to 58.4.1 (CVE-2026-111959), and `chdig` to v26.11.1. [#132797](https://github.com/ClickHouse/ClickHouse/pull/132797) ([Konstantin Bogdanov](https://github.com/thevar1able)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#132828](https://github.com/ClickHouse/ClickHouse/issues/132828): Do not correct the global memory tracker below jemalloc `stats.allocated`. [#126176](https://github.com/ClickHouse/ClickHouse/pull/126176) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
