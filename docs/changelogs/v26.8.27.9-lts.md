# 2026 Changelog

### ClickHouse release v26.8.27.9-lts (551899e257e) FIXME as compared to v26.8.26.12-lts (a9f78f125b2)

#### Improvement
* Backported in [#125603](https://github.com/ClickHouse/ClickHouse/issues/125603): Add ability to select jemalloc 4K/16K page size on aarch64 (default 64K). [#115424](https://github.com/ClickHouse/ClickHouse/pull/115424) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#125594](https://github.com/ClickHouse/ClickHouse/issues/125594): `DROP TABLE`, `DETACH TABLE`, server shutdown and `ALTER TABLE ... MODIFY SETTING refresh_statistics_interval` no longer wait until a running background refresh of the statistics cache of a `MergeTree` table has read the statistics of every part. On object storage with thousands of parts this wait could take minutes per table and delay a server restart. Closes [#125136](https://github.com/ClickHouse/ClickHouse/issues/125136). [#125165](https://github.com/ClickHouse/ClickHouse/pull/125165) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125747](https://github.com/ClickHouse/ClickHouse/issues/125747): Fix `ALTER TABLE ... MATERIALIZE STATISTICS` / `DROP STATISTICS` failing forever and wedging the table's mutation queue when a server profile sets `allow_statistics = 0` and the statement enables it per-session, the same opt-in `ADD STATISTICS` honours. Also close a hole where `MATERIALIZE STATISTICS` ignored `allow_statistics = 0` altogether under `validate_mutation_query = 0`. [#117351](https://github.com/ClickHouse/ClickHouse/pull/117351) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125645](https://github.com/ClickHouse/ClickHouse/issues/125645): Fixed the `LOGICAL_ERROR` `Reading from materialized CTE '...' before its materialization completed - DelayedPortsProcessor gate is missing in the query plan` raised when an `IN` or other set subquery defines a `MATERIALIZED` CTE that two other `MATERIALIZED` CTEs of that subquery read (for example a `UNION ALL` whose branches each chain two `MATERIALIZED` CTEs), in a lightweight `UPDATE`/`DELETE` or a `SELECT`, on a table read with more than one stream. [#121010](https://github.com/ClickHouse/ClickHouse/pull/121010) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125598](https://github.com/ClickHouse/ClickHouse/issues/125598): Fix a credential written in cleartext to `system.query_log` and the server log when a `key = value` argument precedes the positional arguments of the `mongodb`, `redis`, `remote`, `arrowFlight` and `ytsaurus` table functions or the `MongoDB`, `Redis`, `Remote`, `ArrowFlight`, `ExternalDistributed` and `YTsaurus` table engines. A positional argument after a named one is now always hidden, and the value of a named-collection override whose key is written as an expression is hidden for every such engine. [#122770](https://github.com/ClickHouse/ClickHouse/pull/122770) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#125643](https://github.com/ClickHouse/ClickHouse/issues/125643): Free prefetched messages when StorageKafka2 partitions move between consumers, preventing per-partition memory growth until restart. [#125076](https://github.com/ClickHouse/ClickHouse/pull/125076) ([Aparajita Pandey](https://github.com/aparajita31pandey)).
* Backported in [#125732](https://github.com/ClickHouse/ClickHouse/issues/125732): The web terminal and the SSH interface no longer reset the settings of the user (from settings profiles, roles, and `CREATE USER ... SETTINGS`) to default values. Previously, restrictions such as `readonly`, resource limits, and `additional_table_filters` were not applied in these interfaces. [#125515](https://github.com/ClickHouse/ClickHouse/pull/125515) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
