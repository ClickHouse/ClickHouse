# 2026 Changelog

### ClickHouse release v26.8.38.9-lts (71391c9b2bb) FIXME as compared to v26.8.37.168-lts (40e366b2afb)

#### Backward Incompatible Change
* Backported in [#131780](https://github.com/ClickHouse/ClickHouse/issues/131780): Settings of type `Seconds` (for example `max_execution_time` or `lock_acquire_timeout`) now reject a negative value with `BAD_ARGUMENTS`. A negative `max_execution_time` meant no limit and passed a `MAX` constraint; a value whose microseconds round to `2^63` (for example `9223372036854.775`) was stored as a large negative number; it is rejected too. Before upgrading, remove negative values of these settings from configuration files, settings profiles, users and table definitions, and let `Distributed` async insert queues drain; otherwise the server can fail to start, a user or table fails to load, or a queued insert is never sent. [#131269](https://github.com/ClickHouse/ClickHouse/pull/131269) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#131354](https://github.com/ClickHouse/ClickHouse/issues/131354): With `prefer_column_name_to_alias = 1`, an unqualified column name that is ambiguous between joined tables now resolves to the alias with the same name, as the old analyzer did, instead of throwing `AMBIGUOUS_IDENTIFIER`. [#119192](https://github.com/ClickHouse/ClickHouse/pull/119192) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#130293](https://github.com/ClickHouse/ClickHouse/issues/130293): Fix a crash and wrong `TYPE_MISMATCH` or `CANNOT_CONVERT_TYPE` errors when `contingencyState`, `cramersVState`, `cramersVBiasCorrectedState` or `theilsUState` is used as a window function and its result goes through a spill to disk, a `CAST`, or a distributed query plan. `contingencyMapMerge` and the other `-MapMerge` functions of this family now work as window functions. [#128685](https://github.com/ClickHouse/ClickHouse/pull/128685) ([Alexander Gololobov](https://github.com/davenger)).
* Backported in [#131649](https://github.com/ClickHouse/ClickHouse/issues/131649): Fix a crash and wrong query results when a table has a column literally named `mapKeys(m)` or `mapValues(m)` with a `bloom_filter` index on it. [#130814](https://github.com/ClickHouse/ClickHouse/pull/130814) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#131645](https://github.com/ClickHouse/ClickHouse/issues/131645): On a cluster without an interserver secret, remote nodes now apply the row policies of the roles set by `SET ROLE` on the initiator, not of the default roles of the user. Original fix by @fm4v. [#131300](https://github.com/ClickHouse/ClickHouse/pull/131300) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131501](https://github.com/ClickHouse/ClickHouse/issues/131501): Fix a server crash on a `Decimal` parameter with a scale above the maximum precision. [#131343](https://github.com/ClickHouse/ClickHouse/pull/131343) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#131803](https://github.com/ClickHouse/ClickHouse/issues/131803): Fix a possible crash of the `Template` input format when the format string for the result set does not contain `${data}`. Now it is an error. [#131730](https://github.com/ClickHouse/ClickHouse/pull/131730) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131842](https://github.com/ClickHouse/ClickHouse/issues/131842): Fix a one-byte heap overflow when reading a `String` state of `any`/`min`/`max` (and similar) aggregate functions in an old format that ends without the zero terminator. Original fix by @motsc. [#131795](https://github.com/ClickHouse/ClickHouse/pull/131795) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
