# 2026 Changelog

### ClickHouse release v26.7.15.52-stable (2213c0b278e) FIXME as compared to v26.7.14.3-stable (4b5385ab5e3)

#### Backward Incompatible Change
* Backported in [#122175](https://github.com/ClickHouse/ClickHouse/issues/122175): A MySQL dictionary source created with a `CREATE DICTIONARY` query can no longer enable `enable_local_infile`, at the source or at one of its `REPLICA` entries; loading such a dictionary fails with `BAD_ARGUMENTS`, which with the default `dictionaries_lazy_load` is on first use rather than at `CREATE`. A `REPLICA` that does not set the key inherits the source's value, as the connection pool does. To keep the option, define the dictionary in a server configuration file; `enable_local_infile 0`, and a `SOURCE(MYSQL(NAME ...))` reference to a named collection where the key was never read, are unaffected. [#120972](https://github.com/ClickHouse/ClickHouse/pull/120972) ([Groene AI](https://github.com/groeneai)).

#### New Feature
* Backported in [#121587](https://github.com/ClickHouse/ClickHouse/issues/121587): You can now disable reading through the `executable` table function and from `Executable`/`ExecutablePool` tables with the new `allow_executable_tables` setting, for a deployment that must not run arbitrary server-side scripts. It defaults to `true`, so existing behavior is unchanged. [#120713](https://github.com/ClickHouse/ClickHouse/pull/120713) ([Hanzi Jiang](https://github.com/HanziJiang)).

#### Improvement
* Backported in [#121229](https://github.com/ClickHouse/ClickHouse/issues/121229): Added a `flat_namespaces` setting for the `DataLakeCatalog` database engine. Set it for Iceberg REST catalogs that have only single-level namespaces and reject the `parent` query parameter of the list-namespaces endpoint, such as Apache Polaris federated to AWS Glue: only top-level namespaces are then listed and sub-namespaces are not requested. [#117329](https://github.com/ClickHouse/ClickHouse/pull/117329) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#122374](https://github.com/ClickHouse/ClickHouse/issues/122374): Iceberg partition pruning now uses the partition value of a `day`, `month`, `year` or `hour` transform for a filter that wraps the partition source column in a monotonic function, such as `WHERE toDate(ts) = '2024-01-20'`, including for partition values from before 1970. [#119302](https://github.com/ClickHouse/ClickHouse/pull/119302) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121917](https://github.com/ClickHouse/ClickHouse/issues/121917): Add column size statistics in Avro files. [#121392](https://github.com/ClickHouse/ClickHouse/pull/121392) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#122095](https://github.com/ClickHouse/ClickHouse/issues/122095): The AI function per-query quotas are now disabled by default: `ai_function_max_input_tokens_per_query` (previously `1000000`), `ai_function_max_output_tokens_per_query` (previously `500000`) and `ai_function_max_api_calls_per_query` (previously `1000`) default to `0`, meaning no limit. To keep the previous caps, set the three settings explicitly or use `compatibility = '26.9'`. [#121424](https://github.com/ClickHouse/ClickHouse/pull/121424) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#121763](https://github.com/ClickHouse/ClickHouse/issues/121763): Do not drop the ClickHouse Keeper session when the client's outgoing request queue stays full for longer than `operation_timeout_ms`. The enqueue wait is now three times `session_timeout_ms`, so a short burst of backpressure no longer terminates the session and invalidates all its ephemeral nodes and watches. [#121559](https://github.com/ClickHouse/ClickHouse/pull/121559) ([Kseniia Sumarokova](https://github.com/kssenii)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#121356](https://github.com/ClickHouse/ClickHouse/issues/121356): Fixed an out-of-bounds read when finalizing a crafted `analysisOfVariance` aggregate state whose internal arrays have mismatched lengths. [#107860](https://github.com/ClickHouse/ClickHouse/pull/107860) ([uwezkhan](https://github.com/uwezkhan)).
* Backported in [#121884](https://github.com/ClickHouse/ClickHouse/issues/121884): Fixed dropping whole parts with TTL (`ttl_only_drop_parts = 1`) still reading all data from large, fully-expired parts. [#108626](https://github.com/ClickHouse/ClickHouse/pull/108626) ([Michael Jarrett](https://github.com/EmeraldShift)).
* Backported in [#121846](https://github.com/ClickHouse/ClickHouse/issues/121846): Fix an accounting leak in memory tracking: when an allocation was rejected by a parent memory tracker (for example, the server-wide memory limit), the thread, query, and user level trackers kept the rejected amount. The error accumulated over time, inflating `MemoryTracking` and per-query/per-user memory usage, and could lead to spurious `MEMORY_LIMIT_EXCEEDED` errors. [#110784](https://github.com/ClickHouse/ClickHouse/pull/110784) ([Seva Potapov](https://github.com/seva-potapov)).
* Backported in [#122242](https://github.com/ClickHouse/ClickHouse/issues/122242): Fixes a server crash (double free) when finalizing an aggregate function with the `-State` combinator nested under a combinator that transfers several sub-states in one call (`-Resample`, `-ForEach`, `-Map`, `-Tuple`), for example `groupArrayStateResample`, if an exception such as a memory limit is thrown part-way through the transfer. [#111287](https://github.com/ClickHouse/ClickHouse/pull/111287) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121551](https://github.com/ClickHouse/ClickHouse/issues/121551): Fix `Bad cast from type DB::ColumnNullable to DB::ColumnString` when a mutation that rewrites the whole part runs on a part whose column type is older than the one in the table metadata, for example after `ALTER TABLE ... MODIFY COLUMN` followed by `ALTER TABLE ... MATERIALIZE PROJECTION`. [#112501](https://github.com/ClickHouse/ClickHouse/pull/112501) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121533](https://github.com/ClickHouse/ClickHouse/issues/121533): Fixed Iceberg `INSERT` writing no `lower_bounds`/`upper_bounds` at all into the manifest entry when the table has a column whose type cannot be serialized into a statistics bound (for example `Array(Int32)`), or a column that is entirely `NULL`. Such a field is now omitted individually and the bounds of every other column are still written, so min/max file pruning keeps working. Closes [#112706](https://github.com/ClickHouse/ClickHouse/issues/112706). [#112934](https://github.com/ClickHouse/ClickHouse/pull/112934) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121290](https://github.com/ClickHouse/ClickHouse/issues/121290): A table or database whose name is substituted into a `ReplicatedMergeTree` ZooKeeper path through the `{database}` or `{table}` macro is now rejected if the name would not be a single safe path component. Previously a name containing `/` was spliced in unescaped, so the table registered its znodes inside another table's keeper subtree and permanently broke `ALTER` and `OPTIMIZE` there. A `.` or `..` component, a control character and macro syntax are rejected too. Existing tables keep loading and attaching. [#114006](https://github.com/ClickHouse/ClickHouse/pull/114006) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121323](https://github.com/ClickHouse/ClickHouse/issues/121323): Fixed `ATTACH TABLE ... AS REPLICATED` and the `convert_to_replicated` flag file accepting a conversion whose ZooKeeper path is not a safe path. On a server whose `default_replica_path` substitutes `{database}` or `{table}`, a name containing `/` used to resolve to a path inside another table's subtree, letting the converted table register a replica under a table it has no privileges on. Such a conversion is now rejected with `BAD_ARGUMENTS`, the same way an equivalent `CREATE` already was. Closes [#115967](https://github.com/ClickHouse/ClickHouse/issues/115967). [#115991](https://github.com/ClickHouse/ClickHouse/pull/115991) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121556](https://github.com/ClickHouse/ClickHouse/issues/121556): Fixes a case where `date_time_overflow_behavior` was ignored on parsing Date and DateTime. Closes [#113151](https://github.com/ClickHouse/ClickHouse/issues/113151). [#116099](https://github.com/ClickHouse/ClickHouse/pull/116099) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#121686](https://github.com/ClickHouse/ClickHouse/issues/121686): Functions `h3PolygonToCells` and `h3PolygonToCellsWithContainment` now check for query timeouts and `KILL QUERY` while covering a polygon, and reject vertices whose longitude is outside -180..180 or latitude outside -90..90 degrees. Previously a polygon with such a vertex could keep a thread busy for tens of minutes, ignoring both. [#116335](https://github.com/ClickHouse/ClickHouse/pull/116335) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#121934](https://github.com/ClickHouse/ClickHouse/issues/121934): Fix out of bound in `timeSeriesGroupArray()`. [#117404](https://github.com/ClickHouse/ClickHouse/pull/117404) ([Vitaly Baranov](https://github.com/vitlibar)).
* Backported in [#122002](https://github.com/ClickHouse/ClickHouse/issues/122002): Fixed SQL injection through identifiers when inserting into a table with the `SQLite` engine. The remote table name and the column names were escaped with backslashes, which SQLite does not honour inside a quoted identifier, so a name containing a double quote could close its own identifier and have the rest of it executed as SQL. It is now also possible to insert into a SQLite table whose name, or column name, legitimately contains a double quote or a backslash. [#117421](https://github.com/ClickHouse/ClickHouse/pull/117421) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121379](https://github.com/ClickHouse/ClickHouse/issues/121379): Fix a crash when a client sends a block over the Native TCP protocol that selects the internal `Detached` serialization kind for a column. [#117699](https://github.com/ClickHouse/ClickHouse/pull/117699) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#122039](https://github.com/ClickHouse/ClickHouse/issues/122039): `KILL TRANSACTION ... ON CLUSTER`, `KILL PART_MOVE_TO_SHARD ... ON CLUSTER`, `SYSTEM STOP THREAD FUZZER ON CLUSTER`, `SYSTEM START THREAD FUZZER ON CLUSTER` and `SYSTEM RESET COVERAGE ON CLUSTER` ran without checking any privilege, so a user holding only `CLUSTER` could roll back other users' transactions, cancel part moves between shards, and flip the thread fuzzer and the coverage counters on every host. Each now requires what its non-`ON CLUSTER` spelling has always required: `KILL TRANSACTION` and `SELECT` on `system.transactions`; `SELECT` on `system.part_moves_between_shards`, `ALTER MOVE PARTITION` and `MOVE PARTITION BETWEEN SHARDS`; `SYSTEM THREAD FUZZER`; and `SYSTEM`. [#118360](https://github.com/ClickHouse/ClickHouse/pull/118360) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121635](https://github.com/ClickHouse/ClickHouse/issues/121635): Fixed a `SELECT` from a table with `paimon_incremental_read = 1` failing with `REPLICA_IS_ALREADY_ACTIVE` ("Failed to activate Paimon replica after Keeper reconnection") on the first read after the server's Keeper session was lost and re-established. Reclaiming the replica's own stale `is_active` marker now treats Keeper having already reaped that ephemeral node as success, instead of reporting a `replica_name` collision that did not happen. [#118457](https://github.com/ClickHouse/ClickHouse/pull/118457) ([Groene AI](https://github.com/groeneai)).
* Backported in [#122200](https://github.com/ClickHouse/ClickHouse/issues/122200): Fix a patch part whose `source_parts.dat` lost its content to a zeroed block loading as an empty index, which silently unapplied an acknowledged lightweight `UPDATE` and then let background cleanup delete the only copy of it. Such a part is now detached as broken. [#119585](https://github.com/ClickHouse/ClickHouse/pull/119585) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#122193](https://github.com/ClickHouse/ClickHouse/issues/122193): Fixed `http_max_multipart_form_data_size` silently truncating oversized multipart data instead of failing the query, and made it span a form's external-table parts instead of resetting per part. [#120036](https://github.com/ClickHouse/ClickHouse/pull/120036) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#121571](https://github.com/ClickHouse/ClickHouse/issues/121571): Fixed two ways a table with the `Redis` engine mishandled an `MGET` reply. Reading the whole table stopped at the first key without a string value and silently dropped every key scanned after it, so one key of another Redis type was enough to truncate the result. A reply carrying a different number of elements than keys requested made the engine read and write past the end of an array sized from the request, which could crash the server; such a reply is now rejected with `INTERNAL_REDIS_ERROR`. [#120230](https://github.com/ClickHouse/ClickHouse/pull/120230) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121328](https://github.com/ClickHouse/ClickHouse/issues/121328): Fix `count()` returning the number of default values instead of the number of NULLs when `optimize_trivial_count_with_sparsity_filter` is used on a column widened to `Nullable` by a metadata-only `ALTER TABLE ... MODIFY COLUMN`. [#120245](https://github.com/ClickHouse/ClickHouse/pull/120245) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#122089](https://github.com/ClickHouse/ClickHouse/issues/122089): Bound the header column count in `RowBinary` formats to avoid excessive memory allocation from a crafted header. [#120282](https://github.com/ClickHouse/ClickHouse/pull/120282) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#121827](https://github.com/ClickHouse/ClickHouse/issues/121827): Fix `INSERT INTO <replicated table> SELECT ... FROM url(...)` (and `s3`, `azureBlobStorage`, ... ) with parallel replicas enabled inserting the data once per replica: the query forwarded to the replicas now names the `*Cluster` table function, so every replica reads only its share of the files. Closes [#120485](https://github.com/ClickHouse/ClickHouse/issues/120485). [#120488](https://github.com/ClickHouse/ClickHouse/pull/120488) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121450](https://github.com/ClickHouse/ClickHouse/issues/121450): Fix a server crash (`std::terminate` with `write failed`) in the embedded SSH client when the client's terminal was closed before the line reader was destroyed. [#120764](https://github.com/ClickHouse/ClickHouse/pull/120764) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121238](https://github.com/ClickHouse/ClickHouse/issues/121238): Fixed repeated reading of text index posting lists in multi-threaded queries when the global text index caches are disabled. [#120844](https://github.com/ClickHouse/ClickHouse/pull/120844) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#121833](https://github.com/ClickHouse/ClickHouse/issues/121833): Fixes a segmentation fault that happens when a refreshable materialized view is started up and shut down at the same time, for example when a failed `ATTACH DATABASE` rolls the database back, or when the server shuts down while tables are still loading asynchronously. [#121037](https://github.com/ClickHouse/ClickHouse/pull/121037) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121607](https://github.com/ClickHouse/ClickHouse/issues/121607): `TRUNCATE ALL TABLES FROM` and `TRUNCATE TABLES FROM ... LIKE ...` now skip `Alias` tables, which hold no data of their own. Previously such a statement could fail with `LOGICAL_ERROR: RWLock is already locked in exclusive mode`, truncate a target in another database, or fail when the alias target was missing. An explicit `TRUNCATE TABLE <alias>` still truncates the target. [#121134](https://github.com/ClickHouse/ClickHouse/pull/121134) ([Groene AI](https://github.com/groeneai)).
* Backported in [#122237](https://github.com/ClickHouse/ClickHouse/issues/122237): The `text`, `tokenbf_v1`, `ngrambf_v1` and `sparse_grams` skip indexes are now used for `IN` when `transform_null_in = 1` and the set contains no NULL. Previously such a query read every granule, and one using `force_data_skipping_indices` failed with `INDEX_NOT_USED`. [#121375](https://github.com/ClickHouse/ClickHouse/pull/121375) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Backported in [#121626](https://github.com/ClickHouse/ClickHouse/issues/121626): Fixed an out-of-bounds heap write in `stem`. The output buffer was sized from the input, but some stemmers lengthen a word (Turkish `uag` → `uagı`, Estonian `keeb` → `keesi`), so a block overran its allocation and returned uninitialized heap as result values. The buffer now grows when the output exceeds the estimate. [#121402](https://github.com/ClickHouse/ClickHouse/pull/121402) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Backported in [#121603](https://github.com/ClickHouse/ClickHouse/issues/121603): `remote(<cluster name>, 'db', 'table', 'user', 'password')`, and the same form of `remoteSecure` and of the `Remote` and `RemoteSecure` table engines, wrote the password into `system.query_log`, `system.text_log` and the server log in cleartext, while the `remote('addresses_expr', ...)` form hid it. The password is now replaced with `[HIDDEN]` for the cluster-name form too. [#121474](https://github.com/ClickHouse/ClickHouse/pull/121474) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121683](https://github.com/ClickHouse/ClickHouse/issues/121683): Fix wrong values and a `LOGICAL_ERROR` when reading a partitioned Delta Lake table with `allow_delta_kernel_rs = 0` and column types that differ from the ones in `_delta_log`. [#121544](https://github.com/ClickHouse/ClickHouse/pull/121544) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#122254](https://github.com/ClickHouse/ClickHouse/issues/122254): Fixed a server crash when the `flameGraph` aggregate function was constructed on a thread without a query context, for example while attaching a stored table whose column type names `AggregateFunction(flameGraph, ...)`. [#121894](https://github.com/ClickHouse/ClickHouse/pull/121894) ([Groene AI](https://github.com/groeneai)).
* Fixes a problem that MySQL/Postgres queries may run in an expired session. [#122075](https://github.com/ClickHouse/ClickHouse/pull/122075) ([Robert Schulze](https://github.com/rschu1ze)).
