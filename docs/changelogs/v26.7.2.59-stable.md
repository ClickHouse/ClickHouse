# 2026 Changelog

### ClickHouse release v26.7.2.59-stable (1399e12824d) FIXME as compared to v26.7.1.1315-stable (a6156303df6)

#### Experimental Feature
* Backported in [#112519](https://github.com/ClickHouse/ClickHouse/issues/112519): Tag OpenAI-format HTTP requests with the SQL name of the calling AI function for upstream endpoint identification. [#110449](https://github.com/ClickHouse/ClickHouse/pull/110449) ([George Larionov](https://github.com/george-larionov)).

#### Performance Improvement
* Backported in [#111638](https://github.com/ClickHouse/ClickHouse/issues/111638): Lazy materialization is now applied to queries with `FINAL`, a filter, and a small `LIMIT`, even without `ORDER BY` (for `ReplacingMergeTree`). [#110722](https://github.com/ClickHouse/ClickHouse/pull/110722) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#111455](https://github.com/ClickHouse/ClickHouse/issues/111455): Fixed O(P×N) deduplication hash recomputation in async insert flushes that split across P partitions. `DeduplicationInfo::prewarmDataHashes` is now called once before the partition loop in `MergeTreeSink` and `ReplicatedMergeTreeSink`, so all per-partition clones inherit pre-computed `data_hash_batch` values instead of recomputing them P times. This reduces `DuplicationElapsedMicroseconds` proportionally to the number of partitions. [#111150](https://github.com/ClickHouse/ClickHouse/pull/111150) ([Valery Petrov](https://github.com/valerypetrov)).

#### Improvement
* Backported in [#112325](https://github.com/ClickHouse/ClickHouse/issues/112325): This patch fixes the remaining problems needed for part-level min-max index for `_block_number` and `_block_offset` columns. [#109281](https://github.com/ClickHouse/ClickHouse/pull/109281) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Backported in [#111669](https://github.com/ClickHouse/ClickHouse/issues/111669): Added the `jemalloc_merge_tree_arenas` server setting controlling the dedicated jemalloc arena(s) used for `MergeTree` part and table metadata: `0` disables it, `1` uses a single arena (default), and `N` creates a per-CPU pool. On many-core servers a pool reduces memory-allocator lock contention between concurrent merges. The dedicated arena was also narrowed to hold only long-lived metadata. [#109490](https://github.com/ClickHouse/ClickHouse/pull/109490) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#112074](https://github.com/ClickHouse/ClickHouse/issues/112074): Web UI: fix the "+" (new tab) button rendering taller than the tabs in Firefox. [#109524](https://github.com/ClickHouse/ClickHouse/pull/109524) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#112914](https://github.com/ClickHouse/ClickHouse/issues/112914): Added the setting `use_query_condition_cache_for_top_k` (default disabled) which gates the query condition cache for `ORDER BY ... LIMIT n` (TopK) queries. This turns the feature off by default as a precaution until the soundness of its cache entries is fully established, while keeping it available behind the setting. [#111492](https://github.com/ClickHouse/ClickHouse/pull/111492) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#111978](https://github.com/ClickHouse/ClickHouse/issues/111978): Added setting `analyzer_compatibility_apply_final_to_all_joined_tables` that restores the old behavior, where the `FINAL` modifier on the left-most table of a JOIN was also applied to the other joined tables. The setting is registered in the settings changes history, so `compatibility` with versions before 26.6 restores the old semantics automatically. [#111589](https://github.com/ClickHouse/ClickHouse/pull/111589) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#112369](https://github.com/ClickHouse/ClickHouse/issues/112369): The effective named collections storage type is now available as `named_collections_storage.type` in `system.server_settings` and through `getServerSetting('named_collections_storage_type')`. [#111806](https://github.com/ClickHouse/ClickHouse/pull/111806) ([Pablo Marcos](https://github.com/pamarcos)).
* Backported in [#112476](https://github.com/ClickHouse/ClickHouse/issues/112476): Reduce CPU usage when making snapshot for huge amout of files. [#112297](https://github.com/ClickHouse/ClickHouse/pull/112297) ([Han Fei](https://github.com/hanfei1991)).
* Backported in [#112635](https://github.com/ClickHouse/ClickHouse/issues/112635): Iceberg v2 spec requires sequence_number in manifest files. However, other engines such as BigQuery could write those files without this field. This PR allow to read those non-spec tables. [#112431](https://github.com/ClickHouse/ClickHouse/pull/112431) ([Konstantin Vedernikov](https://github.com/scanhex12)).

[#108977](https://github.com/ClickHouse/ClickHouse/pull/108977) ([Groene AI](https://github.com/groeneai)).

RENAME COLUMN`, or when the column's only values come from a lightweight `UPDATE`. The column could be dropped from the merged part, so all of its values read back as NULL. [#109356](https://github.com/ClickHouse/ClickHouse/pull/109356) ([Groene AI](https://github.com/groeneai)).
* Backported in [#111566](https://github.com/ClickHouse/ClickHouse/issues/111566): Fixed a false `ICEBERG_SPECIFICATION_VIOLATION` error when reading an Iceberg table whose decimal (or other parameterized primitive) type is serialized with different whitespace across metadata files, e.g. `decimal(20,0)` in the table metadata and `decimal(20, 0)` in the manifest. Such spec-equivalent type strings are now compared ignoring whitespace. [#109676](https://github.com/ClickHouse/ClickHouse/pull/109676) ([Groene AI](https://github.com/groeneai)).
* Backported in [#112293](https://github.com/ClickHouse/ClickHouse/issues/112293): Fix credential leaks in `SHOW CREATE`, `system.query_log`, server logs and `EXPLAIN` output. Every `S3` locator form now masks `session_token` and Google ADC secrets, `extra_credentials`/`headers` values at any argument position, duplicated or expression secret keys, invalid positional forms (fail closed), and credentials embedded in S3 URLs; this covers the explicit-url and named-collection `s3`/`s3Cluster` table functions, the S3-backed table engines (`S3`, `GCS`, the data-lake engines, `S3Queue`), the `S3` database engine, `BACKUP ... TO S3` and the `Backup` database engine. In addition, secret arguments of `encrypt`/`decrypt`/HMAC that are built by an expression (including ones inlined from a SQL UDF) are now hidden in projection names, `EXPLAIN QUERY TREE` and `EXPLAIN actions`. [#109768](https://github.com/ClickHouse/ClickHouse/pull/109768) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#111544](https://github.com/ClickHouse/ClickHouse/issues/111544): Fixed wrong results for functions `has`, `mapContainsKey` and `mapContainsValue` with an empty needle when a text index is present. [#110246](https://github.com/ClickHouse/ClickHouse/pull/110246) ([Robert Schulze](https://github.com/rschu1ze)).
* Backported in [#112062](https://github.com/ClickHouse/ClickHouse/issues/112062): Fix `S3Queue`/`AzureQueue` ordered mode with persistent processing nodes: bucket locks are now refreshed during streaming, so that the TTL cleanup (`persistent_processing_node_ttl_seconds`) does not remove locks of a live processor. If lock ownership is nevertheless lost, it is detected and reported (a logical error and the `ObjectStorageQueueBucketLockLostOwnership` profile event), and streaming recovers with a fresh file iterator. [#110292](https://github.com/ClickHouse/ClickHouse/pull/110292) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Backported in [#111560](https://github.com/ClickHouse/ClickHouse/issues/111560): Fix `411 Length Required` errors from Azure services: the Poco-based Azure HTTP transport now sets `Content-Length` from the request body for SDK clients that do not set the header themselves (e.g. Azure Key Vault). [#110299](https://github.com/ClickHouse/ClickHouse/pull/110299) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#111682](https://github.com/ClickHouse/ClickHouse/issues/111682): Fixed a read-only object-storage replica (a disk configured with `read_only = true`) not discovering new parts via `refresh_parts_interval`, and `table_disk = true` being rejected on such a disk with "table_disk is not supported for non-ObjectStorage disks". [#110460](https://github.com/ClickHouse/ClickHouse/pull/110460) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#112450](https://github.com/ClickHouse/ClickHouse/issues/112450): Fix wrong `IS NULL` / `IS NOT NULL` / `count()` results with `optimize_functions_to_subcolumns` on a column that was made `Nullable` by a metadata-only `ALTER MODIFY COLUMN T` to `Nullable(T)`. For parts written before the conversion, the `.null` subcolumn was filled from the storage-type default (NULL) instead of being derived from the physically-present parent column, so existing not-null rows were wrongly reported as NULL. [#110584](https://github.com/ClickHouse/ClickHouse/pull/110584) ([Groene AI](https://github.com/groeneai)).
* Backported in [#111744](https://github.com/ClickHouse/ClickHouse/issues/111744): Fix incorrect pruning from primary key index analysis on tables with a reverse (descending) sorting key (`ORDER BY (g, r DESC)`). A granule spanning a change of a leading key column followed by a descending key column could be pruned incorrectly, dropping matching rows. [#111059](https://github.com/ClickHouse/ClickHouse/pull/111059) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Backported in [#112585](https://github.com/ClickHouse/ClickHouse/issues/112585): Fix a logical error `block.rows() == getRows()` (an out-of-bounds read and broken insert deduplication in release builds) when an `INSERT` flows through a dependent materialized view whose target is an `Alias` and whose inner query changes the number of rows, with a deduplicating table reachable behind the alias hop. This restores backward compatibility for pre-26.6 DDL that started failing with `BAD_ARGUMENTS` ("Partition strategy hive can not be used with a '_partition_id' wildcard in the path") after [#107437](https://github.com/ClickHouse/ClickHouse/issues/107437). A `Join` engine table has a fixed declared strictness that cannot be changed, so the conversion is now declined for such tables.
