# 2026 Changelog

### ClickHouse release v26.9.39.7-stable (5685c755edf) FIXME as compared to v26.9.38.8-stable (ec4e9eb591f)

#### Performance Improvement
* Backported in [#134084](https://github.com/ClickHouse/ClickHouse/issues/134084): Add the `RabbitMQ` table setting `rabbitmq_max_idle_producer_connections`, which keeps idle connections with their channels open and reuses them across `INSERT` queries. This removes the connection setup from every insert, which is especially costly for materialized views that fire often, including when they write no rows. The default `0` keeps the previous behavior. [#127611](https://github.com/ClickHouse/ClickHouse/pull/127611) ([David Mischke](https://github.com/davimi)).
* Backported in [#134066](https://github.com/ClickHouse/ClickHouse/issues/134066): Read columns of Compact part in the order of the file (to avoid backward seeks). [#131439](https://github.com/ClickHouse/ClickHouse/pull/131439) ([Azat Khuzhin](https://github.com/azat)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134236](https://github.com/ClickHouse/ClickHouse/issues/134236): The `CGroupMaxCPU` asynchronous metric now takes the effective cpuset of the cgroup into account, as the minimum of the CPU quota and the number of CPUs in the cpuset. Previously it was not reported for containers with exclusive CPUs and no CFS quota, such as Kubernetes pods with the `static` CPU manager policy (where `cpu.max` is `max` since Kubernetes 1.35), and `CGroupUserTimeNormalized` and `CGroupSystemTimeNormalized` were missing as well. [#132862](https://github.com/ClickHouse/ClickHouse/pull/132862) ([dilu-ch](https://github.com/dilu-ch)).
* Backported in [#134114](https://github.com/ClickHouse/ClickHouse/issues/134114): Fix high memory usage of `MATERIALIZE INDEX` for text indexes on `packed` or `compact` parts. [#132964](https://github.com/ClickHouse/ClickHouse/pull/132964) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#134167](https://github.com/ClickHouse/ClickHouse/issues/134167): Fixed `CREATE TABLE ... AS filesystem(...)` with an explicit column list not checking `READ ON FILE`, which let a user with `WRITE ON FILE` (or with no `FILE` grant at all, via `ON CLUSTER`) read any file under `user_files` through the new table. Such a table now needs `READ` and `WRITE` on `FILE`, the grants that imply `TABLE ENGINE ON File`. This also applies to `CREATE TABLE copy AS src`, short `ATTACH` and local `RESTORE` of such a table. [#133420](https://github.com/ClickHouse/ClickHouse/pull/133420) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133883](https://github.com/ClickHouse/ClickHouse/issues/133883): The secret first key argument of "keyed" SipHash SQL functions is now masked in `system.query_log`. [#133828](https://github.com/ClickHouse/ClickHouse/pull/133828) ([Robert Schulze](https://github.com/rschu1ze)).
