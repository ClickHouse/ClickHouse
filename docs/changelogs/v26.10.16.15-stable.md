# 2026 Changelog

### ClickHouse release v26.10.16.15-stable (a0df21b2de6) FIXME as compared to v26.10.15.10-stable (a08335fbe1a)

#### Performance Improvement
* Backported in [#134085](https://github.com/ClickHouse/ClickHouse/issues/134085): Add the `RabbitMQ` table setting `rabbitmq_max_idle_producer_connections`, which keeps idle connections with their channels open and reuses them across `INSERT` queries. This removes the connection setup from every insert, which is especially costly for materialized views that fire often, including when they write no rows. The default `0` keeps the previous behavior. [#127611](https://github.com/ClickHouse/ClickHouse/pull/127611) ([David Mischke](https://github.com/davimi)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134963](https://github.com/ClickHouse/ClickHouse/issues/134963): Fix `ALTER DELETE`/`ALTER UPDATE` silently skipping rows when the predicate contains `IN <table>`. The default-enabled `optimize_mutations_with_partition_pruning` evaluated that set at submission time and narrowed the mutation's `block_numbers`, so a partition matching only the execution-time set was left out while the mutation still reported `is_done = 1`. [#117272](https://github.com/ClickHouse/ClickHouse/pull/117272) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#134959](https://github.com/ClickHouse/ClickHouse/issues/134959): A projection `ORDER BY` tuple containing an aliased element is now stored in a form that can be parsed back, so it no longer makes `SHOW CREATE TABLE` or server startup fail. [#124137](https://github.com/ClickHouse/ClickHouse/pull/124137) ([Ankit Nakhawa](https://github.com/AnkitNakhawa)).
* Backported in [#135062](https://github.com/ClickHouse/ClickHouse/issues/135062): Fix excessive I/O during mutation and lightweight DELETE prechecks on tables with bucketed `Map` serialization by allowing `m['key']` predicates to be rewritten to Map key subcolumns. [#130291](https://github.com/ClickHouse/ClickHouse/pull/130291) ([Rushikesh Sudhir Kulkarni](https://github.com/Rushikesh1911)).
* Backported in [#135039](https://github.com/ClickHouse/ClickHouse/issues/135039): Fix abrupt server termination when MongoDB returns malformed query results. [#132506](https://github.com/ClickHouse/ClickHouse/pull/132506) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#134957](https://github.com/ClickHouse/ClickHouse/issues/134957): Fixed wrong results of a join stacked above a `RIGHT` or `FULL` hash join with `query_plan_join_shard_by_pk_ranges`: the rows that only the right table has were not matched by the join above. Joins above a `RIGHT` or `FULL` hash join are no longer sharded by primary-key ranges. Closes [#125323](https://github.com/ClickHouse/ClickHouse/issues/125323). [#133614](https://github.com/ClickHouse/ClickHouse/pull/133614) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135069](https://github.com/ClickHouse/ClickHouse/issues/135069): Fixed background merges and `OPTIMIZE` of a table that has a column TTL on an `ALIAS` or `EPHEMERAL` column: once the TTL was due, they failed with `There is no physical column ... in table. (NO_SUCH_COLUMN_IN_TABLE)` and the merge was retried forever. Closes [#134006](https://github.com/ClickHouse/ClickHouse/issues/134006). [#134279](https://github.com/ClickHouse/ClickHouse/pull/134279) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135087](https://github.com/ClickHouse/ClickHouse/issues/135087): Fix dictionaries with a remote ClickHouse source over `Distributed` with a cluster secret. [#134753](https://github.com/ClickHouse/ClickHouse/pull/134753) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#135033](https://github.com/ClickHouse/ClickHouse/issues/135033): A deeply nested PromQL query terminated the server with a segmentation fault. Now such queries fail with `TOO_DEEP_RECURSION` error. `bool`, `group_left`, `group_right`, `on`, `ignoring`, `atan2` are not allowed as unquoted metric names anymore. `(` after `group_left`/`group_right` always starts the label list, so `group_left (b + c)` is now a syntax error. The workaround is to explicitly specify the empty list, e.g. `group_left() (b + c)`. [#134787](https://github.com/ClickHouse/ClickHouse/pull/134787) ([Kirill Shokhin](https://github.com/kirillshokhin)).
* Backported in [#134988](https://github.com/ClickHouse/ClickHouse/issues/134988): A table of a `Filesystem` database is now required to be a file inside the directory of the database. [#134818](https://github.com/ClickHouse/ClickHouse/pull/134818) ([Alexander Tokmakov](https://github.com/tavplubix)).

#### Build/Testing/Packaging Improvement
* Backported in [#135082](https://github.com/ClickHouse/ClickHouse/issues/135082): Alpine-based `clickhouse-server` and `clickhouse-keeper` images now run `apk upgrade` at build time, so they pick up security fixes for packages that are already in the alpine base image, such as OpenSSL. [#124094](https://github.com/ClickHouse/ClickHouse/pull/124094) ([Joel Bandi](https://github.com/joelbandi)).
* Backported in [#135115](https://github.com/ClickHouse/ClickHouse/issues/135115): Update `mongo-c-driver` from 2.5.8 to 2.5.10. [#133662](https://github.com/ClickHouse/ClickHouse/pull/133662) ([Actuele AI](https://github.com/actueleai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#135118](https://github.com/ClickHouse/ClickHouse/issues/135118): Let backport PR builds from this repository write to the shared sccache. [#131392](https://github.com/ClickHouse/ClickHouse/pull/131392) ([Groene AI](https://github.com/groeneai)).
* Backported in [#135095](https://github.com/ClickHouse/ClickHouse/issues/135095): Apply the memory limit of `05828_remerge_sort_memory_bounded` only to the queries under test. [#134360](https://github.com/ClickHouse/ClickHouse/pull/134360) ([Groene AI](https://github.com/groeneai)).
