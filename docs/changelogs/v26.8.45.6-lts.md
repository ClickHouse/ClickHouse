# 2026 Changelog

### ClickHouse release v26.8.45.6-lts (be540b388f4) FIXME as compared to v26.8.44.3-lts (46094a8d754)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133651](https://github.com/ClickHouse/ClickHouse/issues/133651): Fixed `NOT_FOUND_COLUMN_IN_BLOCK` when merging a table that has a rows `TTL` together with a move (`TO DISK`, `TO VOLUME`) or recompression (`RECOMPRESS`) `TTL` over a different column. [#121536](https://github.com/ClickHouse/ClickHouse/pull/121536) ([Murphy](https://github.com/murphy-4o)).
* Backported in [#133678](https://github.com/ClickHouse/ClickHouse/issues/133678): Fixed `toUTCTimestamp` (`to_utc_timestamp`) returning a time one hour off for local times in the hours around a daylight saving time change, for both `DateTime` and `DateTime64`. It now converts a local time as `toDateTime(s, time_zone)` does, also a local time that happens twice or does not exist. Closes [#128266](https://github.com/ClickHouse/ClickHouse/issues/128266). [#128744](https://github.com/ClickHouse/ClickHouse/pull/128744) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133561](https://github.com/ClickHouse/ClickHouse/issues/133561): Fixed connecting over the native protocol (`clickhouse-client`, `remote`, `Distributed` without an interserver `secret`) to an older server whose settings profile has a negative or overflowing value of a `Seconds` setting, for example `max_execution_time = -1`: the connection failed with `A setting's value in seconds cannot be negative`. Such a value sent by the server is now skipped with a warning. [#131636](https://github.com/ClickHouse/ClickHouse/pull/131636) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133586](https://github.com/ClickHouse/ClickHouse/issues/133586): Removed the background task that cleaned up unused directories in `store/`. With `async_load_databases` enabled, it could revoke all access rights from the data directory of an attached table (queries to the table failed with `Permission denied`) and delete the directory 30 days later. It could also delete the data of a table that was recoverable with `ATTACH TABLE ... UUID` after a power loss. Unused directories in `store/` are now left untouched. The server settings `database_catalog_unused_dir_hide_timeout_sec`, `database_catalog_unused_dir_rm_timeout_sec`, and `database_catalog_unused_dir_cleanup_period_sec` are obsolete and have no effect. [#133464](https://github.com/ClickHouse/ClickHouse/pull/133464) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133540](https://github.com/ClickHouse/ClickHouse/issues/133540): Fixed JSON schema inference that, depending on memory reuse, could reject valid input with `TYPE_MISMATCH` (for example `{"x":0}`, `{"x":-1}`, `{"y":1}`, `{"y":18446744073709551615}` in `JSONEachRow`) or infer a wrong type such as `Array(Dynamic)` instead of `Array(Nullable(UInt64))`. It also infers `String` instead of failing for JSON strings that mix `Int64` and larger integers with non-numeric text (with `input_format_json_try_infer_numbers_from_strings = 1` and `input_format_json_read_numbers_as_strings = 0`). [#133506](https://github.com/ClickHouse/ClickHouse/pull/133506) ([Groene AI](https://github.com/groeneai)).
