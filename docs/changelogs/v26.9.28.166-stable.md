# 2026 Changelog

### ClickHouse release v26.9.28.166-stable (81a8d8988c2) FIXME as compared to v26.9.27.3-stable (4bea8b37b25)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#131323](https://github.com/ClickHouse/ClickHouse/issues/131323): Fixed `optimize_rewrite_aggregate_function_with_if` (enabled by default) turning a short-circuit-guarded aggregate such as `sum(if(number = 0, 0, intDiv(42, number)))` into a query failure: the rewritten `sumIf(intDiv(42, number), number != 0)` evaluates its argument for every row, so the guarded expression ran on the rows the condition excluded and threw. The rewrite is now refused when the lifted branch relies on short-circuit evaluation. Closes [#85784](https://github.com/ClickHouse/ClickHouse/issues/85784). [#118697](https://github.com/ClickHouse/ClickHouse/pull/118697) ([Groene AI](https://github.com/groeneai)).
* Backported in [#131059](https://github.com/ClickHouse/ClickHouse/issues/131059): Bloom filters of skip indexes respect the memory limits, so creating large filters fails with `MEMORY_LIMIT_EXCEEDED` instead of the server being killed by the OOM killer. Text bloom filter indexes (`tokenbf_v1`, `ngrambf_v1`, `sparse_grams`) with the total size of filters in a granule (filter size multiplied by the number of columns) over 1 GiB are rejected on creation. [#126549](https://github.com/ClickHouse/ClickHouse/pull/126549) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#131445](https://github.com/ClickHouse/ClickHouse/issues/131445): Fixed `Unsupported storage type: abfs://` when reading a table from a `DataLakeCatalog` database (for example OneLake) whose catalog reports table locations with the plain `abfs://` scheme. Previously only `abfss://` was accepted, although both name the same ADLS Gen2 storage. [#131389](https://github.com/ClickHouse/ClickHouse/pull/131389) ([Nikita Fomichev](https://github.com/fm4v)).
