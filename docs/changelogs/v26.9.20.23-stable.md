# 2026 Changelog

### ClickHouse release v26.9.20.23-stable (579d61a37c0) FIXME as compared to v26.9.19.9-stable (4388bba7592)

#### Backward Incompatible Change
* Backported in [#125983](https://github.com/ClickHouse/ClickHouse/issues/125983): Overriding a key that is stored in a named collection now requires `SHOW NAMED COLLECTIONS SECRETS` on that collection. This also applies to overrides through an alias (including flat `kafka_*` settings over nested `kafka.*` keys), through a `SETTINGS` clause of a table engine or table function, and through keys in a dictionary source (checked when the dictionary is created). Resolving a relative `url` stored in a named collection against `s3_base` or `url_base` also counts as an override of `url`. Adding a key that the collection does not store remains allowed, and keys marked `NOT OVERRIDABLE` cannot be overridden. The `allow_named_collection_override_by_default` setting is obsolete. Existing tables whose `SETTINGS` or alias arguments override a `NOT OVERRIDABLE` key cannot be loaded after the upgrade, and the server does not start: before upgrading, recreate such tables without the override, or make the key overridable. [#123133](https://github.com/ClickHouse/ClickHouse/pull/123133) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Backported in [#125781](https://github.com/ClickHouse/ClickHouse/issues/125781): Connections to MySQL (the `mysql` table function, the `MySQL` table and database engines, and `MySQL` dictionaries) that set `ssl_ca` or `ssl_ca_pem` now verify the server certificate chain and host name, after updating `mariadb-connector-c` to v3.4.10. Previously the CA was not enforced, so a connection to a server whose certificate is signed by another CA, or whose certificate does not list the host name or IP address used to connect, succeeded and now fails with `self-signed certificate in certificate chain` or `Hostname verification failed`. Before upgrading, make sure the configured CA signs the MySQL server certificate and that the certificate lists the host name or IP address ClickHouse connects to. [#119510](https://github.com/ClickHouse/ClickHouse/pull/119510) ([Actuele AI](https://github.com/actueleai)).

#### Performance Improvement
* Backported in [#125811](https://github.com/ClickHouse/ClickHouse/issues/125811): A filter on the `PARTITION BY` columns of a window function is no longer pushed below the window (this reverts [#110114](https://github.com/ClickHouse/ClickHouse/issues/110114)). The push-down made queries up to 8 times slower when the window reads a `JOIN` and the filter removes every row, for example `IN` over an empty subquery, because the join built its right side before the filter could stop the query. Closes [#123875](https://github.com/ClickHouse/ClickHouse/issues/123875). [#125463](https://github.com/ClickHouse/ClickHouse/pull/125463) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#125884](https://github.com/ClickHouse/ClickHouse/issues/125884): A packet that cannot appear at the current point of the native protocol is now rejected without deserializing its payload. Previously the server deserialized the body of an unexpected `Data` packet — including arbitrary data types and aggregate function states — only to throw `UNEXPECTED_PACKET_FROM_CLIENT` and close the connection. [#119368](https://github.com/ClickHouse/ClickHouse/pull/119368) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125790](https://github.com/ClickHouse/ClickHouse/issues/125790): Add S3 bucket to `remote_url_allow_hosts`. [#124453](https://github.com/ClickHouse/ClickHouse/pull/124453) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#125896](https://github.com/ClickHouse/ClickHouse/issues/125896): Reduced the peak memory usage of `RESTORE` and of incremental `BACKUP`: the metadata file of a backup is now parsed while it is read, instead of being read into memory whole first. For backups of millions of files this saves gigabytes. [#125712](https://github.com/ClickHouse/ClickHouse/pull/125712) ([Julia Kartseva](https://github.com/jkartseva)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126052](https://github.com/ClickHouse/ClickHouse/issues/126052): Fixed a crash caused by a stack overflow when a deeply nested JSON document was parsed into a `JSON` column or passed to the `JSONExtract` family of functions. Such documents are now rejected with the `TOO_DEEP_RECURSION` error. [#120887](https://github.com/ClickHouse/ClickHouse/pull/120887) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#126094](https://github.com/ClickHouse/ClickHouse/issues/126094): Fix a server crash when a `RIGHT JOIN`/`FULL JOIN` is planned for parallel replicas (`parallel_replicas_plan_based=1`) and the join output header declares a column by type only — e.g. the residual column of a constant `NULL` conjunct in the `ON` clause. Type-only header columns are now materialized as an empty column of the declared type instead of being dereferenced as null. [#122128](https://github.com/ClickHouse/ClickHouse/pull/122128) ([Ilias](https://github.com/iliasabk)).
* Backported in [#126001](https://github.com/ClickHouse/ClickHouse/issues/126001): Fixed `CANNOT_READ_ALL_DATA` (`while reading prefix of column ...`) during query planning when a `MergeTree` table has an active empty Wide part, left by a TTL drop or by a mutation that deleted all rows of a part, and the query filters on a subcolumn, such as a key of a `Map(LowCardinality(String), String)` column. [#122756](https://github.com/ClickHouse/ClickHouse/pull/122756) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125800](https://github.com/ClickHouse/ClickHouse/issues/125800): Update the vendored `expat` to 2.9.0, fixing a denial of service through a crafted backup manifest during RESTORE (CVE-2026-66046) and the other 2.8.3–2.9.0 security fixes. [#124255](https://github.com/ClickHouse/ClickHouse/pull/124255) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#125822](https://github.com/ClickHouse/ClickHouse/issues/125822): Fixed loading, short `ATTACH`, and `UNDROP TABLE` for existing SQL-defined S3 disks whose endpoints are absent from `remote_url_allow_hosts`; new full-definition `CREATE` and `ATTACH` still reject disallowed endpoints. [#124930](https://github.com/ClickHouse/ClickHouse/pull/124930) ([Alexey Bakharew](https://github.com/alexbakharew)).
* Backported in [#126234](https://github.com/ClickHouse/ClickHouse/issues/126234): Fixed `ORDER BY ... LIMIT` over a column of an `Interval` type (or `Nullable`, `LowCardinality`, `Tuple` or `Array` of one) failing with `TYPE_MISMATCH` when `use_top_k_dynamic_filtering` is enabled, which is the default. Closes [#125197](https://github.com/ClickHouse/ClickHouse/issues/125197). [#125221](https://github.com/ClickHouse/ClickHouse/pull/125221) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125835](https://github.com/ClickHouse/ClickHouse/issues/125835): Fixed a stack overflow crash on a deeply nested CapnProto schema that the nesting depth check missed: a comment or a byte order mark between `import` and its path, an escape sequence in the import path, or a backtick text line. A backtick text line with many brackets is no longer rejected as nested too deeply. [#125487](https://github.com/ClickHouse/ClickHouse/pull/125487) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125935](https://github.com/ClickHouse/ClickHouse/issues/125935): Fixed a possible segmentation fault when reading an Avro `map` into a `Map` column (for example `Map(DateTime, String)`) with the `AvroConfluent` format, including Kafka tables. Closes [#125457](https://github.com/ClickHouse/ClickHouse/issues/125457). [#125505](https://github.com/ClickHouse/ClickHouse/pull/125505) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125870](https://github.com/ClickHouse/ClickHouse/issues/125870): Fixed an issue where pressing Ctrl-R and then Ctrl-Z in the web terminal or the SSH interface suspended the whole server process. [#125512](https://github.com/ClickHouse/ClickHouse/pull/125512) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125876](https://github.com/ClickHouse/ClickHouse/issues/125876): Fix a wrong result, or an exception in debug builds, when `optimize_aggregators_of_group_by_keys` eliminated `any`, `min` or `max` of a `GROUPING SETS` key with `group_by_use_nulls`. [#125575](https://github.com/ClickHouse/ClickHouse/pull/125575) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125866](https://github.com/ClickHouse/ClickHouse/issues/125866): Fixed a server crash when a `RabbitMQ` table with the `headers` exchange type had a routing key without `=`, or when `rabbitmq_routing_key_list` was empty. Routing keys without `=` for the `headers` exchange type are now rejected with an exception. The problem was found and reported by @dstesk (https://github.com/dstesk). [#125661](https://github.com/ClickHouse/ClickHouse/pull/125661) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125999](https://github.com/ClickHouse/ClickHouse/issues/125999): Allow to do vertical merge if result part storage type is not Full. [#125760](https://github.com/ClickHouse/ClickHouse/pull/125760) ([alesapin](https://github.com/alesapin)).
* Backported in [#126070](https://github.com/ClickHouse/ClickHouse/issues/126070): Fixed a crash (stack overflow) on a CapnProto schema with a long chain of type expression suffixes (`Int32.a.a...`, `Int32()()...`) or of declarations that refer to each other (constants, aliases, struct fields, annotations, imports). Such a schema is now rejected with `The CapnProto schema is nested too deeply`. Closes [#125782](https://github.com/ClickHouse/ClickHouse/issues/125782). [#125900](https://github.com/ClickHouse/ClickHouse/pull/125900) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126116](https://github.com/ClickHouse/ClickHouse/issues/126116): Fixed `Reading in parallel from replicas is enabled but cluster to execute query is not provided` (`CLUSTER_DOESNT_EXIST`) when selecting from a `Distributed` table whose cluster is not declared in `remote_servers` - the cluster of a `Replicated` database, or one found by cluster discovery - with parallel replicas enabled. [#126032](https://github.com/ClickHouse/ClickHouse/pull/126032) ([Igor Nikonov](https://github.com/devcrafter)).
