# 2026 Changelog

### ClickHouse release v26.3.21.7-lts (eab23fa14e8) FIXME as compared to v26.3.20.7-lts (22647405581)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#115430](https://github.com/ClickHouse/ClickHouse/issues/115430): Fix exception when Iceberg metadata file path setting contains a null byte. [#100283](https://github.com/ClickHouse/ClickHouse/pull/100283) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#106555](https://github.com/ClickHouse/ClickHouse/issues/106555): Fix a server crash (SIGSEGV) reachable by any user with `CREATE TABLE` rights when sending `CREATE TABLE ... TO INNER UUID '...'` without an `ENGINE` clause over HTTP or the native protocol. The same bug also crashed the client. The parser now reports a proper `BAD_ARGUMENTS` error instead of dereferencing a null pointer. [#105579](https://github.com/ClickHouse/ClickHouse/pull/105579) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115449](https://github.com/ClickHouse/ClickHouse/issues/115449): Fixed `CREATE OR REPLACE MATERIALIZED VIEW ... POPULATE` leaving the new view unsubscribed from its source table, which silently dropped every row inserted after the replace. [#108728](https://github.com/ClickHouse/ClickHouse/pull/108728) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#114892](https://github.com/ClickHouse/ClickHouse/issues/114892): Fixes a bug where an access entity carrying a `Map`-valued setting, such as a settings profile with `http_response_headers` or `additional_table_filters`, is stored in a form that ClickHouse cannot read back, leaving the entity permanently unloadable after a restart. [#114620](https://github.com/ClickHouse/ClickHouse/pull/114620) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115469](https://github.com/ClickHouse/ClickHouse/issues/115469): Fixed wrong results for `SELECT count(arrayJoin(arr))` with the default `optimize_trivial_count_query = 1`. The stored row count was returned instead of the number of array elements, and on `file()` and `url()` the query returned `0`. Closes [#115123](https://github.com/ClickHouse/ClickHouse/issues/115123). [#115227](https://github.com/ClickHouse/ClickHouse/pull/115227) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115599](https://github.com/ClickHouse/ClickHouse/issues/115599): Fixed `uniq`, `uniqExact`, `uniqHLL12` and `uniqTheta` returning a wrong result for an argument wrapped in an injective function that hides nullability, such as `uniqExact(tuple(x))` over a `Nullable` column. The `optimize_injective_functions_inside_uniq` optimization removed the wrapping function, after which NULL rows were skipped instead of counted. [#115466](https://github.com/ClickHouse/ClickHouse/pull/115466) ([Vladimir Cherkasov](https://github.com/vdimir)).
