# 2026 Changelog

### ClickHouse release v26.3.54.6-lts (9f3fea88bbe) FIXME as compared to v26.3.53.4-lts (d8af9de0b15)

#### Improvement
* Backported in [#126083](https://github.com/ClickHouse/ClickHouse/issues/126083): A packet that cannot appear at the current point of the native protocol is now rejected without deserializing its payload. Previously the server deserialized the body of an unexpected `Data` packet — including arbitrary data types and aggregate function states — only to throw `UNEXPECTED_PACKET_FROM_CLIENT` and close the connection. [#119368](https://github.com/ClickHouse/ClickHouse/pull/119368) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125797](https://github.com/ClickHouse/ClickHouse/issues/125797): Update the vendored `expat` to 2.9.0, fixing a denial of service through a crafted backup manifest during RESTORE (CVE-2026-66046) and the other 2.8.3–2.9.0 security fixes. [#124255](https://github.com/ClickHouse/ClickHouse/pull/124255) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#126065](https://github.com/ClickHouse/ClickHouse/issues/126065): Fixed an issue where pressing Ctrl-R and then Ctrl-Z in the web terminal or the SSH interface suspended the whole server process. [#125512](https://github.com/ClickHouse/ClickHouse/pull/125512) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126398](https://github.com/ClickHouse/ClickHouse/issues/126398): The setting `http_zlib_compression_level` now applies only to the `gzip` and `deflate` HTTP response compression. The level of other methods (`zstd`, `lz4`, `br`, `xz`, `bz2`) is controlled by `output_format_compression_level`. Previously, a level suitable for zlib was passed to every method, which could make `lz4` unexpectedly slow or make `xz` fail. [#125899](https://github.com/ClickHouse/ClickHouse/pull/125899) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126067](https://github.com/ClickHouse/ClickHouse/issues/126067): Fixed a crash (stack overflow) on a CapnProto schema with a long chain of type expression suffixes (`Int32.a.a...`, `Int32()()...`) or of declarations that refer to each other (constants, aliases, struct fields, annotations, imports). Such a schema is now rejected with `The CapnProto schema is nested too deeply`. Closes [#125782](https://github.com/ClickHouse/ClickHouse/issues/125782). [#125900](https://github.com/ClickHouse/ClickHouse/pull/125900) ([Groene AI](https://github.com/groeneai)).
