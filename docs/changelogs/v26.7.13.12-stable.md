# 2026 Changelog

### ClickHouse release v26.7.13.12-stable (cd7ea6748fe) FIXME as compared to v26.7.12.6-stable (952cd5eae0b)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#121004](https://github.com/ClickHouse/ClickHouse/issues/121004): Fixed wrong results (the `WHERE` clause was ignored) and a logical error `Cannot serialize FutureSetFromSubquery with no query plan` for queries over `Merge` tables and the `merge` table function when plan-based parallel replicas were enabled. [#112849](https://github.com/ClickHouse/ClickHouse/pull/112849) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120890](https://github.com/ClickHouse/ClickHouse/issues/120890): Fix `Logical error: Duplicate announcement received for replica number N` when automatic parallel replicas (`automatic_parallel_replicas_mode`) adopts a plan whose single-node variant was sharded by `query_plan_join_shard_by_pk_ranges`. [#113730](https://github.com/ClickHouse/ClickHouse/pull/113730) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121108](https://github.com/ClickHouse/ClickHouse/issues/121108): Fix `O(n^2)` decompression of gzip/zlib/deflate streams whose single DEFLATE block spans the whole stream, the shape zlib-ng produces at compression level 1 (the default of the official .NET SDK): a 24 MiB gzip HTTP body that took 11 s to ingest in 26.7 now takes 0.12 s, identical to a multi-block body, with memory bounded by the buffer size instead of the block size. [#114059](https://github.com/ClickHouse/ClickHouse/pull/114059) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121016](https://github.com/ClickHouse/ClickHouse/issues/121016): Messages of the PostgreSQL wire protocol are now parsed within their declared size, so a malformed message can no longer make the server allocate memory for a payload that never arrives. [#116998](https://github.com/ClickHouse/ClickHouse/pull/116998) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120846](https://github.com/ClickHouse/ClickHouse/issues/120846): Fixed filesystem containment checks accepting a path with an embedded NUL byte. A `DeltaLakeLocal` or `IcebergLocal` table could be pointed outside of `user_files` this way. [#119846](https://github.com/ClickHouse/ClickHouse/pull/119846) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120998](https://github.com/ClickHouse/ClickHouse/issues/120998): Fix a server abort when an Azure Blob Storage endpoint reports an asynchronous blob copy as completed without the optional `x-ms-copy-source` or `x-ms-copy-status-description` header. [#120935](https://github.com/ClickHouse/ClickHouse/pull/120935) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Build/Testing/Packaging Improvement
* Backported in [#120895](https://github.com/ClickHouse/ClickHouse/issues/120895): Use `cctz` tzdata 2026c. [#116539](https://github.com/ClickHouse/ClickHouse/pull/116539) ([Konstantin Bogdanov](https://github.com/thevar1able)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#120995](https://github.com/ClickHouse/ClickHouse/issues/120995): The comments of `04367_lambda_arg_backquoted_dot_no_logical_error` (added in https://github.com/ClickHouse/ClickHouse/pull/108735) contain the literal wording of the assertion-failure log message the test guards against. The test's expected `TYPE_MISMATCH` errors echo the full query text — comments included — into the server log, and the CI log checker (`ci/jobs/scripts/log_parser.py`) matches that wording with its `Logical error.*` pattern, reporting a red check (STID 2735-47bf) even though the test passes and nothing aborts. On 2026-07-22 alone, 12 runs across 10 unrelated PRs (including the docs-only https://github.com/ClickHouse/ClickHouse/pull/111251) went red on this false positive. [#111435](https://github.com/ClickHouse/ClickHouse/pull/111435) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#121002](https://github.com/ClickHouse/ClickHouse/issues/121002): Fixed `01076_parallel_alter_replicated_zookeeper` silently testing nothing when its ALTER thread and its DETACH thread picked the same replica. [#118712](https://github.com/ClickHouse/ClickHouse/pull/118712) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121072](https://github.com/ClickHouse/ClickHouse/issues/121072): Pin `05182_limit_shrinks_block_size_with_array_join`'s two per-node oracles to a single local reader, and pin the remote prefetched-pool eligibility its plan-shape oracle needs on object-storage runs. [#120992](https://github.com/ClickHouse/ClickHouse/pull/120992) ([Groene AI](https://github.com/groeneai)).
* Backported in [#121066](https://github.com/ClickHouse/ClickHouse/issues/121066): Shrink the `t_aj_limit` fixture in `05182_limit_shrinks_block_size_with_array_join` from 200000 to 20000 rows. [#121031](https://github.com/ClickHouse/ClickHouse/pull/121031) ([Groene AI](https://github.com/groeneai)).
