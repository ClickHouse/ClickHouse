# 2026 Changelog

### ClickHouse release v26.8.17.4-lts (20fcd0f7eb7) FIXME as compared to v26.8.16.41-lts (4ede48259fe)

#### Improvement
* Backported in [#123727](https://github.com/ClickHouse/ClickHouse/issues/123727): Skip indexes (`bloom_filter`, `tokenbf_v1`, `ngrambf_v1`, `minmax`) and the primary key are now used when the indexed column is wrapped into a conversion that does not change its value, such as `toLowCardinality`, `toNullable` or a `CAST` to `Nullable` or `LowCardinality`. [#123239](https://github.com/ClickHouse/ClickHouse/pull/123239) ([Anton Popov](https://github.com/CurtizJ)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#123732](https://github.com/ClickHouse/ClickHouse/issues/123732): Fix an out-of-bounds read when deserializing a `uniqTheta` state shorter than 24 bytes, for instance from `CAST(<string> AS AggregateFunction(uniqTheta, ...))`. [#119598](https://github.com/ClickHouse/ClickHouse/pull/119598) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#123822](https://github.com/ClickHouse/ClickHouse/issues/123822): Fix a buffer over-read on the sequential read path from Azure Blob Storage: an endpoint that answers a ranged request with more data than was requested could deliver bytes from outside the requested range to the caller. The end of a read is now decided by the locally set right bound, not by the `Content-Length` of the response, and a read is pinned to the listed generation of the blob with `If-Match`, so an object replaced during a read fails with `AZURE_OBJECT_CHANGED_DURING_READ` instead of being truncated (new setting `azure_validate_etag_on_read`, enabled by default). [#120910](https://github.com/ClickHouse/ClickHouse/pull/120910) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
