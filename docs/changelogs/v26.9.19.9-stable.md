# 2026 Changelog

### ClickHouse release v26.9.19.9-stable (4388bba7592) FIXME as compared to v26.9.18.11-stable (46140d6a7c6)

#### Improvement
* Backported in [#125595](https://github.com/ClickHouse/ClickHouse/issues/125595): `DROP TABLE`, `DETACH TABLE`, server shutdown and `ALTER TABLE ... MODIFY SETTING refresh_statistics_interval` no longer wait until a running background refresh of the statistics cache of a `MergeTree` table has read the statistics of every part. On object storage with thousands of parts this wait could take minutes per table and delay a server restart. Closes [#125136](https://github.com/ClickHouse/ClickHouse/issues/125136). [#125165](https://github.com/ClickHouse/ClickHouse/pull/125165) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125748](https://github.com/ClickHouse/ClickHouse/issues/125748): Fix `ALTER TABLE ... MATERIALIZE STATISTICS` / `DROP STATISTICS` failing forever and wedging the table's mutation queue when a server profile sets `allow_statistics = 0` and the statement enables it per-session, the same opt-in `ADD STATISTICS` honours. Also close a hole where `MATERIALIZE STATISTICS` ignored `allow_statistics = 0` altogether under `validate_mutation_query = 0`. [#117351](https://github.com/ClickHouse/ClickHouse/pull/117351) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125599](https://github.com/ClickHouse/ClickHouse/issues/125599): Fix a credential written in cleartext to `system.query_log` and the server log when a `key = value` argument precedes the positional arguments of the `mongodb`, `redis`, `remote`, `arrowFlight` and `ytsaurus` table functions or the `MongoDB`, `Redis`, `Remote`, `ArrowFlight`, `ExternalDistributed` and `YTsaurus` table engines. A positional argument after a named one is now always hidden, and the value of a named-collection override whose key is written as an expression is hidden for every such engine. [#122770](https://github.com/ClickHouse/ClickHouse/pull/122770) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#125552](https://github.com/ClickHouse/ClickHouse/issues/125552): Fixed queries that go through another server (`remote`, `Distributed`, parallel replicas, `GLOBAL IN`) failing with `SYNTAX_ERROR`, `UNKNOWN_CODEC` or `CORRUPTED_DATA` when `output_format_native_encode_types_in_binary_format` or `input_format_native_decode_types_in_binary_format` is enabled. The blocks of these queries now carry type names on the wire, and a shard with this change also works with an initiator without it. `clickhouse-client --query_kind secondary_query` follows the same rule. [#123649](https://github.com/ClickHouse/ClickHouse/pull/123649) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125644](https://github.com/ClickHouse/ClickHouse/issues/125644): Free prefetched messages when StorageKafka2 partitions move between consumers, preventing per-partition memory growth until restart. [#125076](https://github.com/ClickHouse/ClickHouse/pull/125076) ([Aparajita Pandey](https://github.com/aparajita31pandey)).
* Backported in [#125733](https://github.com/ClickHouse/ClickHouse/issues/125733): The web terminal and the SSH interface no longer reset the settings of the user (from settings profiles, roles, and `CREATE USER ... SETTINGS`) to default values. Previously, restrictions such as `readonly`, resource limits, and `additional_table_filters` were not applied in these interfaces. [#125515](https://github.com/ClickHouse/ClickHouse/pull/125515) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125627](https://github.com/ClickHouse/ClickHouse/issues/125627): Don't fuse a filter into ARRAY JOIN before its row-only part is lifted below it, so the element filter doesn't copy the whole array to every element. [#125577](https://github.com/ClickHouse/ClickHouse/pull/125577) ([Konstantin Vedernikov](https://github.com/scanhex12)).
