# 2026 Changelog

### ClickHouse release v26.10.13.11-stable (f3cdd2bf78e) FIXME as compared to v26.10.12.13-stable (7c5cdd4d8bd)

#### Performance Improvement
* Backported in [#134151](https://github.com/ClickHouse/ClickHouse/issues/134151): Automatic parallel replicas no longer builds a plan with parallel replicas for a query whose correlated subquery rules them out. [#129544](https://github.com/ClickHouse/ClickHouse/pull/129544) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#134273](https://github.com/ClickHouse/ClickHouse/issues/134273): `ORDER BY ... LIMIT` over several `ARRAY JOIN` clauses now sorts and limits the rows before all of them, not only before the last one, when the sort key does not use the joined columns. [#131004](https://github.com/ClickHouse/ClickHouse/pull/131004) ([Yaroslav Briukhovetskyi](https://github.com/yariks5s)).

#### Improvement
* Backported in [#134127](https://github.com/ClickHouse/ClickHouse/issues/134127): Added the `hostname` column to `system.dead_letter_queue`. [#133849](https://github.com/ClickHouse/ClickHouse/pull/133849) ([Nikolay Degterinsky](https://github.com/evillique)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134280](https://github.com/ClickHouse/ClickHouse/issues/134280): Fixed a `LOGICAL_ERROR` exception when pruning columns of an `ARRAY JOIN` that uses `Nullable` values or a `USING` reference. [#127044](https://github.com/ClickHouse/ClickHouse/pull/127044) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133602](https://github.com/ClickHouse/ClickHouse/issues/133602): Fix duplicated rows from a merge join of a distributed query plan (`make_distributed_plan`) when `query_plan_join_shard_by_pk_ranges` is enabled. [#130887](https://github.com/ClickHouse/ClickHouse/pull/130887) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#134365](https://github.com/ClickHouse/ClickHouse/issues/134365): Fixed `LOGICAL_ERROR` `Directory '...' is virtual` on the first `INSERT` into a `Set` or `Join` table whose `disk` setting names a `plain_rewritable` disk, on `ALTER TABLE ... DELETE` of such a `Join` table, and on `clickhouse-disks move` or `link` into a directory that `mkdir --parents` created only as a parent. [#132449](https://github.com/ClickHouse/ClickHouse/pull/132449) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134237](https://github.com/ClickHouse/ClickHouse/issues/134237): The `CGroupMaxCPU` asynchronous metric now takes the effective cpuset of the cgroup into account, as the minimum of the CPU quota and the number of CPUs in the cpuset. Previously it was not reported for containers with exclusive CPUs and no CFS quota, such as Kubernetes pods with the `static` CPU manager policy (where `cpu.max` is `max` since Kubernetes 1.35), and `CGroupUserTimeNormalized` and `CGroupSystemTimeNormalized` were missing as well. [#132862](https://github.com/ClickHouse/ClickHouse/pull/132862) ([dilu-ch](https://github.com/dilu-ch)).
* Backported in [#134115](https://github.com/ClickHouse/ClickHouse/issues/134115): Fix high memory usage of `MATERIALIZE INDEX` for text indexes on `packed` or `compact` parts. [#132964](https://github.com/ClickHouse/ClickHouse/pull/132964) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#134168](https://github.com/ClickHouse/ClickHouse/issues/134168): Fixed `CREATE TABLE ... AS filesystem(...)` with an explicit column list not checking `READ ON FILE`, which let a user with `WRITE ON FILE` (or with no `FILE` grant at all, via `ON CLUSTER`) read any file under `user_files` through the new table. Such a table now needs `READ` and `WRITE` on `FILE`, the grants that imply `TABLE ENGINE ON File`. This also applies to `CREATE TABLE copy AS src`, short `ATTACH` and local `RESTORE` of such a table. [#133420](https://github.com/ClickHouse/ClickHouse/pull/133420) ([Groene AI](https://github.com/groeneai)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#134324](https://github.com/ClickHouse/ClickHouse/issues/134324): Fix wrong result of a join reordered by DPsub with `query_plan_join_order_use_interesting_orders` when a join key class mixed column types such as `Date` and `DateTime` in different time zones. [#132507](https://github.com/ClickHouse/ClickHouse/pull/132507) ([Fisnik Kastrati](https://github.com/fkastrati)).
