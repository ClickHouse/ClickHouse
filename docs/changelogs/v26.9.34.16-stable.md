# 2026 Changelog

### ClickHouse release v26.9.34.16-stable (8b3d3127bbb) FIXME as compared to v26.9.33.10-stable (f5ed966e633)

#### Performance Improvement
* Backported in [#132355](https://github.com/ClickHouse/ClickHouse/issues/132355): Fix cubic complexity of enumerating subcolumns of deeply nested `Array` types. [#126554](https://github.com/ClickHouse/ClickHouse/pull/126554) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133075](https://github.com/ClickHouse/ClickHouse/issues/133075): Parsing row-based input formats and `Native` into tables with nested `Tuple` columns is faster for small blocks (streaming engines, async inserts): the per-block columns are now created once per nested element instead of once per nesting level. Closes [#127427](https://github.com/ClickHouse/ClickHouse/issues/127427). [#127859](https://github.com/ClickHouse/ClickHouse/pull/127859) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#133071](https://github.com/ClickHouse/ClickHouse/issues/133071): Add AI function request time, retry backoff time, and prompt-cache token counts to `ProfileEvents`. Include cached Anthropic input tokens in total input usage and query quotas. [#122559](https://github.com/ClickHouse/ClickHouse/pull/122559) ([Ravi Kumar L](https://github.com/upman)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132955](https://github.com/ClickHouse/ClickHouse/issues/132955): Fixed projections returning rows removed by a lightweight `DELETE` after `ALTER UPDATE`, `MATERIALIZE PROJECTION` or `CLEAR COLUMN` rebuilt them on a Wide part. A query with `apply_deleted_mask = 0` no longer uses projections when the table has lightweight-deleted rows, since projections do not store them. On release branches this also fixes a normal projection without a `WHERE` keeping the rows removed by a `rebuild`-mode lightweight `DELETE`, which [#118375](https://github.com/ClickHouse/ClickHouse/issues/118375) fixed on master. [#111809](https://github.com/ClickHouse/ClickHouse/pull/111809) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132940](https://github.com/ClickHouse/ClickHouse/issues/132940): Fixed `NOT_FOUND_COLUMN_IN_BLOCK` for a constant-condition `if`/`multiIf` `GROUP BY` key reused through an alias with `enable_identifier_resolve_cache` (default since 26.6) or read back under `group_by_use_nulls`, lost grouping sets when such a key collapses to another key, a `Bad cast` logical error for a correlated subquery reading the column a key collapses to, and `NOT_FOUND_COLUMN_IN_BLOCK` or wrong values for an `if` chain key under `group_by_use_nulls` and `optimize_if_chain_to_multiif`. Closes [#122404](https://github.com/ClickHouse/ClickHouse/issues/122404). [#122512](https://github.com/ClickHouse/ClickHouse/pull/122512) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132979](https://github.com/ClickHouse/ClickHouse/issues/132979): Check access rights before loading a dictionary or reading its definition in the `dictionary` table function, `dictGet`-family functions, `naiveBayesClassifier`, `Dictionary` tables and `CREATE TABLE ... ENGINE = Dictionary`. Queries without the required grants no longer trigger the dictionary load, and queries or DDL that reference a dictionary now require access to it even when they do not read it, e.g. `DESCRIBE`, `CREATE VIEW` or a `DEFAULT dictGet(...)` column. [#122678](https://github.com/ClickHouse/ClickHouse/pull/122678) ([Matheus Nerone](https://github.com/Manerone)).
* Backported in [#132925](https://github.com/ClickHouse/ClickHouse/issues/132925): Fixed a filtered source grant (e.g. `GRANT WRITE ON S3('https://bucket/allowed/.*')`) authorizing a location outside the filter. `BACKUP`/`RESTORE` and table functions like `s3`, `url` and `azureBlobStorage` with `.`/`..` or empty path segments, a fragment, escapes that change the name, a query in an S3 URI (where `?` is a wildcard) or `url` alternatives outside the path now need the grant on the whole source. A glob character (`*?{}|`, and `,` in `url`) must match the filter both as written and percent-encoded. [#129899](https://github.com/ClickHouse/ClickHouse/pull/129899) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132987](https://github.com/ClickHouse/ClickHouse/issues/132987): Fixed `CREATE WORKLOAD`, `DROP WORKLOAD`, `CREATE RESOURCE` and `DROP RESOURCE` with `workload_zookeeper_path` overwriting definitions written by other replicas when the query was the first to use a renewed Keeper session. [#131719](https://github.com/ClickHouse/ClickHouse/pull/131719) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133059](https://github.com/ClickHouse/ClickHouse/issues/133059): Fix out-of-bounds memory access with an aggregate state containing a `JSON` value with a repeated path. Now such a state is rejected with `INCORRECT_DATA`. [#131791](https://github.com/ClickHouse/ClickHouse/pull/131791) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133010](https://github.com/ClickHouse/ClickHouse/issues/133010): The `/binary` web UI now displays the symbol name and source line in the popup as text instead of interpreting the server response as HTML. [#131895](https://github.com/ClickHouse/ClickHouse/pull/131895) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133079](https://github.com/ClickHouse/ClickHouse/issues/133079): Fix a crash in the `Arrow` and `ArrowStream` input formats when a requested type changed how a nested field was decoded while another requested column read that field with a type that does not describe it: a struct column together with a dotted subcolumn of it, such as `t String, "t.s" IPv6` (including dictionary-encoded `UUID` children), or an Arrow union with a struct child named like another requested column. [#132416](https://github.com/ClickHouse/ClickHouse/pull/132416) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#132776](https://github.com/ClickHouse/ClickHouse/issues/132776): Fixed a memory leak in queries answered by `_minmax_count_projection` that compute `min` or `max` of a `Tuple`, `Array` or `FixedString` primary key or partition column: every part read leaked one aggregate state. [#132557](https://github.com/ClickHouse/ClickHouse/pull/132557) ([Groene AI](https://github.com/groeneai)).
* The `url` of an `HTTP` dictionary source is hidden in `SHOW CREATE`, `system.tables` and the query log, and its userinfo in `system.dictionaries`. [#133043](https://github.com/ClickHouse/ClickHouse/pull/133043) ([George Larionov](https://github.com/george-larionov)).

#### Build/Testing/Packaging Improvement
* Backported in [#133086](https://github.com/ClickHouse/ClickHouse/issues/133086): Update `postgres` to 18.6. [#124281](https://github.com/ClickHouse/ClickHouse/pull/124281) ([Actuele AI](https://github.com/actueleai)).
* Update `arrow` and `parquet` Rust crates used by Delta Lake support to 58.4.1 (CVE-2026-111959), and `chdig` to v26.11.1. [#132798](https://github.com/ClickHouse/ClickHouse/pull/132798) ([Konstantin Bogdanov](https://github.com/thevar1able)).
