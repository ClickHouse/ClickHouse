# 2026 Changelog

### ClickHouse release v26.7.35.11-stable (9ae877699e9) FIXME as compared to v26.7.34.3-stable (26600ba25f1)

#### Backward Incompatible Change
* Backported in [#126501](https://github.com/ClickHouse/ClickHouse/issues/126501): `CREATE TABLE x AS src` inherits the credentials embedded in the engine of `src`, which are masked in `SHOW CREATE TABLE`. It now requires the `SELECT` privilege on `src` when the inherited definition can carry credentials, instead of only `SHOW COLUMNS`. [#118866](https://github.com/ClickHouse/ClickHouse/pull/118866) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Performance Improvement
* Backported in [#126758](https://github.com/ClickHouse/ClickHouse/issues/126758): Estimating subcolumn sizes for `PREWHERE` (for example `m['key']` of a `Map(LowCardinality(String), String)` column) no longer reads the `LowCardinality` dictionary or the `Variant` discriminators header of every data part, which made planning slow on object storage, especially for each new map key. Closes [#114598](https://github.com/ClickHouse/ClickHouse/issues/114598). [#126046](https://github.com/ClickHouse/ClickHouse/pull/126046) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126762](https://github.com/ClickHouse/ClickHouse/issues/126762): `BACKUP` uses less memory per file it backs up: an entry of the backup no longer keeps a copy of the description of the disk the file is on. A backup of a table with millions of files saves a few gigabytes. [#126388](https://github.com/ClickHouse/ClickHouse/pull/126388) ([Julia Kartseva](https://github.com/jkartseva)).

#### Improvement
* Backported in [#126086](https://github.com/ClickHouse/ClickHouse/issues/126086): A packet that cannot appear at the current point of the native protocol is now rejected without deserializing its payload. Previously the server deserialized the body of an unexpected `Data` packet — including arbitrary data types and aggregate function states — only to throw `UNEXPECTED_PACKET_FROM_CLIENT` and close the connection. [#119368](https://github.com/ClickHouse/ClickHouse/pull/119368) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126718](https://github.com/ClickHouse/ClickHouse/issues/126718): Compare TOTP codes and `plaintext_password` passwords in constant time, so that the response time does not depend on how many leading characters are correct or on which time window matched. [#125785](https://github.com/ClickHouse/ClickHouse/pull/125785) ([Vladimir Cherkasov](https://github.com/vdimir)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126727](https://github.com/ClickHouse/ClickHouse/issues/126727): Fixed a server crash and an out-of-bounds write when inserting into a column with a long chain of compression codecs, for example `CODEC(FPC, FPC, ..., FPC)`. `CompressionCodecMultiple` compounded each stage's reserved size in a `UInt32` without checking for overflow, so a long enough chain wrapped the reserved size below its own input and the destination buffer was then sized from the wrapped value while the real payload kept growing. Such a chain is now rejected with `CANNOT_COMPRESS`. A chain of more than 255 codecs, which used to write a part that could not be read back, is now rejected with `BAD_ARGUMENTS` when the codec is created, unless `allow_suspicious_codecs` is set. `ALTER TABLE ... MODIFY COLUMN x CODEC(...)` with the type omitted used to validate the codec against no type at all, skipping every check that needs the column width, and now validates against the column's existing type, which flips some verdicts in both directions under the default `allow_suspicious_codecs = 0`. Tables created earlier are unaffected. [#113877](https://github.com/ClickHouse/ClickHouse/pull/113877) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126824](https://github.com/ClickHouse/ClickHouse/issues/126824): Fixed a read of uninitialized memory when a `Variant`, `Dynamic` or `JSON` column holding only `NULL` values is compressed, for example on insert into a `Memory` table created with `compress = 1`, or when a block is compressed for a `JOIN` or for the query result cache. The reported size of such a column was also unspecified. [#120776](https://github.com/ClickHouse/ClickHouse/pull/120776) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126720](https://github.com/ClickHouse/ClickHouse/issues/126720): Fixed crashes of the interactive line editor of `clickhouse-client` and `clickhouse-local`, which also crashed the server when used through the web terminal or an SSH session: after a history search that found nothing on an edited recalled query, when the prompt or the line given to an Alt-R history search contained a tab, when leaving a history search with a double-width character in the prompt (for example in the server's `display_name`), and on Ctrl-W or Alt-. after some non-ASCII characters. Closes [#126008](https://github.com/ClickHouse/ClickHouse/issues/126008). [#126120](https://github.com/ClickHouse/ClickHouse/pull/126120) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126808](https://github.com/ClickHouse/ClickHouse/issues/126808): Fix segfault when reading a `MySQLDump` file whose `CREATE TABLE` query has an `ENUM` column without a list of values or with non-string values. [#126159](https://github.com/ClickHouse/ClickHouse/pull/126159) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126803](https://github.com/ClickHouse/ClickHouse/issues/126803): Fix a stack overflow when a Redis server replies with deeply nested arrays. [#126547](https://github.com/ClickHouse/ClickHouse/pull/126547) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
