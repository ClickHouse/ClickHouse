# 2026 Changelog

### ClickHouse release v26.10.9.12-stable (bdfa0e7723a) FIXME as compared to v26.10.8.34-stable (6e92eea6c05)

#### Backward Incompatible Change
* Backported in [#133255](https://github.com/ClickHouse/ClickHouse/issues/133255): `CREATE HANDLER`, `ALTER HANDLER`, `DROP HANDLER` and `SHOW HANDLERS` now form the new `HANDLER ADMIN` privilege group and are no longer part of the `CREATE`, `ALTER` and `DROP` groups. Previously `GRANT CREATE ON *.*` or `GRANT ALTER ON *.*` was enough to define or rewrite an HTTP handler, whose query runs with the privileges of the user who calls it. Users who manage handlers must now be granted `HANDLER ADMIN` or the individual handler privileges, including users whose stored grants name only the old groups: for example, `GRANT CREATE, CREATE HANDLER` is stored as `GRANT CREATE`, and `GRANT ALL` followed by `REVOKE SYSTEM` is stored as a list of groups. Revoking `CREATE`, `ALTER` or `DROP` no longer revokes them, so a configured grant list that revokes one of these from `ALL` should also revoke `HANDLER ADMIN`. [#129033](https://github.com/ClickHouse/ClickHouse/pull/129033) ([Groene AI](https://github.com/groeneai)).

#### Performance Improvement
* Backported in [#133228](https://github.com/ClickHouse/ClickHouse/issues/133228): Automatic parallel replicas no longer repeats the index analysis of a join's tables when it builds the plan with parallel replicas to decide whether to use them. [#130516](https://github.com/ClickHouse/ClickHouse/pull/130516) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#133188](https://github.com/ClickHouse/ClickHouse/issues/133188): A query that combines `x IN (subquery)` with other conditions by `AND` now stops reading as soon as the subquery returns an empty set also when `compile_expressions` has compiled the `AND` (by default once the same expression has been seen `min_count_to_compile_expression` times). Before, such a query, for example with `FINAL`, read the whole key range and only then filtered every row out. [#131211](https://github.com/ClickHouse/ClickHouse/pull/131211) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133205](https://github.com/ClickHouse/ClickHouse/issues/133205): Fix `NOT_FOUND_COLUMN_IN_BLOCK` and wrong results when a `GROUP BY` key is used inside an `if` chain with `optimize_if_chain_to_multiif = 1`, or is a tuple used in `ORDER BY` (for example `if(1, tuple(a), tuple(0)) AS k ... GROUP BY k ORDER BY k`). With `group_by_use_nulls = 1`, such an `if` key returned its value instead of `NULL` in `ROLLUP`, `CUBE` and `GROUPING SETS` subtotal rows. Closes [#125803](https://github.com/ClickHouse/ClickHouse/issues/125803). Closes [#125804](https://github.com/ClickHouse/ClickHouse/issues/125804). [#125828](https://github.com/ClickHouse/ClickHouse/pull/125828) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133147](https://github.com/ClickHouse/ClickHouse/issues/133147): Fixed filtered `WRITE` grants (such as `GRANT WRITE ON S3('<regex>')`) being bypassed by `INSERT INTO FUNCTION` into `url`, `s3`, `azureBlobStorage` and `hdfs`. Previously only the URI as typed was checked, so a `PARTITION BY` value like `../other/x`, or a file renamed by `s3_create_new_file_on_insert`, could be written outside the granted path. Now every destination is checked. If a renamed file falls outside a filtered grant, widen the grant or use `s3_truncate_on_insert`. `CREATE TABLE ... AS s3(...)` and other source table functions now need `TABLE ENGINE ON <engine>` grant, like `ENGINE = <engine>`; with only a filtered source grant, grant the engine explicitly. This also applies to `CREATE TABLE copy AS src` when `src` is such a table, and to local `RESTORE` of such a table. [#129605](https://github.com/ClickHouse/ClickHouse/pull/129605) ([Foad Lotfifar](https://github.com/foadl)).
* Backported in [#133210](https://github.com/ClickHouse/ClickHouse/issues/133210): Fix a possible crash of the `RabbitMQ` table engine when the broker confirms a message with an unknown delivery tag. [#131731](https://github.com/ClickHouse/ClickHouse/pull/131731) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133191](https://github.com/ClickHouse/ClickHouse/issues/133191): Fixed a `Merge` table or the `merge` table function over a `Distributed` table returning one column when the query selects the same column more than once, for example `SELECT k, k`. [#131928](https://github.com/ClickHouse/ClickHouse/pull/131928) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133199](https://github.com/ClickHouse/ClickHouse/issues/133199): Fix a crash (double free) when an allocation failed, e.g. because of the memory limit, while an aggregate function used as a window function moved to a new partition or frame, or while an aggregate function with the `-ArgMin` / `-ArgMax` combinator reset its state for a new extreme value. [#132755](https://github.com/ClickHouse/ClickHouse/pull/132755) ([Raúl Marín](https://github.com/Algunenano)).
* Fix a heap-buffer-overflow when parsing text formats read from Azure Blob Storage. [#133226](https://github.com/ClickHouse/ClickHouse/pull/133226) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Fixed `compatibility = '26.8'` setting `iceberg_manifest_decode_concurrency` to `2` instead of the `4` that 26.8 ships. [#133230](https://github.com/ClickHouse/ClickHouse/pull/133230) ([Nikita Fomichev](https://github.com/fm4v)).
