# 2026 Changelog

### ClickHouse release v26.9.12.8-stable (142137457b0) FIXME as compared to v26.9.11.2-stable (a83cd7baa96)

#### Improvement
* Backported in [#124173](https://github.com/ClickHouse/ClickHouse/issues/124173): Filesystem cache: make reserve granularity dynamic. [#123255](https://github.com/ClickHouse/ClickHouse/pull/123255) ([Kseniia Sumarokova](https://github.com/kssenii)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124135](https://github.com/ClickHouse/ClickHouse/issues/124135): Fixed a `text` index dropping matching rows when a `FixedString` is involved in the comparison: a term-preserving tokenizer over a `String` column lost the rows whose value carries literal trailing zero bytes when the search constant is a `FixedString`, and an index over a `FixedString` column lost all matching rows for a `String` constant or a `FixedString` constant of another width. [#118972](https://github.com/ClickHouse/ClickHouse/pull/118972) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#124178](https://github.com/ClickHouse/ClickHouse/issues/124178): Rewriting the body of a view with `ALTER TABLE ... MODIFY QUERY` now needs the same grants as creating it with its SQL security: `SET DEFINER` on the definer of a `SQL SECURITY DEFINER` view, or `ALLOW SQL SECURITY NONE` for a `SQL SECURITY NONE` view. An `ON CLUSTER MODIFY QUERY` fails with `UNKNOWN_TABLE` unless it runs on a host that has the view. [#121629](https://github.com/ClickHouse/ClickHouse/pull/121629) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#124090](https://github.com/ClickHouse/ClickHouse/issues/124090): Fix `basic` statistics of parts written by 26.6 or 26.7: after `ALTER TABLE ... UPDATE` or a lightweight `DELETE`, non-`Nullable` columns reported a default-value count of 0, which made selectivity estimates wrong. Query results were not affected. To repair parts that are already affected, run `ALTER TABLE ... MATERIALIZE STATISTICS ALL`. [#123536](https://github.com/ClickHouse/ClickHouse/pull/123536) ([Samuel Krempaský](https://github.com/NIKTONIKTO717)).
* Backported in [#124062](https://github.com/ClickHouse/ClickHouse/issues/124062): Fix a possible hang of a query under workload CPU scheduling with `cpu_slot_preemption` enabled: when all its threads were preempted, the query could keep CPU slots it had already used and wait forever for one of them. [#123640](https://github.com/ClickHouse/ClickHouse/pull/123640) ([Sergei Trifonov](https://github.com/serxa)).
* Backported in [#124010](https://github.com/ClickHouse/ClickHouse/issues/124010): Fixed a `LEFT`/`RIGHT`/`FULL JOIN` without an equality key that failed with `INVALID_JOIN_ON_EXPRESSION` (`Cannot determine join keys`) when its `WHERE` clause also contained an `IN (subquery)`. The `WHERE` filter now converts such a join to `INNER` again, as it did in 26.6, which also restores that optimization for joins with equality keys. [#123792](https://github.com/ClickHouse/ClickHouse/pull/123792) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124163](https://github.com/ClickHouse/ClickHouse/issues/124163): Respect `iceberg_metadata_staleness_ms` in metadata parsing. [#124113](https://github.com/ClickHouse/ClickHouse/pull/124113) ([Konstantin Vedernikov](https://github.com/scanhex12)).
