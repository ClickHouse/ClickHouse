# 2026 Changelog

### ClickHouse release v26.9.35.9-stable (6ec5d8633b0) FIXME as compared to v26.9.34.16-stable (8b3d3127bbb)

#### Backward Incompatible Change
* Backported in [#133254](https://github.com/ClickHouse/ClickHouse/issues/133254): `CREATE HANDLER`, `ALTER HANDLER`, `DROP HANDLER` and `SHOW HANDLERS` now form the new `HANDLER ADMIN` privilege group and are no longer part of the `CREATE`, `ALTER` and `DROP` groups. Previously `GRANT CREATE ON *.*` or `GRANT ALTER ON *.*` was enough to define or rewrite an HTTP handler, whose query runs with the privileges of the user who calls it. Users who manage handlers must now be granted `HANDLER ADMIN` or the individual handler privileges, including users whose stored grants name only the old groups: for example, `GRANT CREATE, CREATE HANDLER` is stored as `GRANT CREATE`, and `GRANT ALL` followed by `REVOKE SYSTEM` is stored as a list of groups. Revoking `CREATE`, `ALTER` or `DROP` no longer revokes them, so a configured grant list that revokes one of these from `ALL` should also revoke `HANDLER ADMIN`. [#129033](https://github.com/ClickHouse/ClickHouse/pull/129033) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133204](https://github.com/ClickHouse/ClickHouse/issues/133204): Fix `NOT_FOUND_COLUMN_IN_BLOCK` and wrong results when a `GROUP BY` key is used inside an `if` chain with `optimize_if_chain_to_multiif = 1`, or is a tuple used in `ORDER BY` (for example `if(1, tuple(a), tuple(0)) AS k ... GROUP BY k ORDER BY k`). With `group_by_use_nulls = 1`, such an `if` key returned its value instead of `NULL` in `ROLLUP`, `CUBE` and `GROUPING SETS` subtotal rows. Closes [#125803](https://github.com/ClickHouse/ClickHouse/issues/125803). Closes [#125804](https://github.com/ClickHouse/ClickHouse/issues/125804). [#125828](https://github.com/ClickHouse/ClickHouse/pull/125828) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133296](https://github.com/ClickHouse/ClickHouse/issues/133296): Pad the buffer an Azure read owns with PADDING_FOR_SIMD. [#127593](https://github.com/ClickHouse/ClickHouse/pull/127593) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#133148](https://github.com/ClickHouse/ClickHouse/issues/133148): Fixed filtered `WRITE` grants (such as `GRANT WRITE ON S3('<regex>')`) being bypassed by `INSERT INTO FUNCTION` into `url`, `s3`, `azureBlobStorage` and `hdfs`. Previously only the URI as typed was checked, so a `PARTITION BY` value like `../other/x`, or a file renamed by `s3_create_new_file_on_insert`, could be written outside the granted path. Now every destination is checked. If a renamed file falls outside a filtered grant, widen the grant or use `s3_truncate_on_insert`. `CREATE TABLE ... AS s3(...)` and other source table functions now need `TABLE ENGINE ON <engine>` grant, like `ENGINE = <engine>`; with only a filtered source grant, grant the engine explicitly. This also applies to `CREATE TABLE copy AS src` when `src` is such a table, and to local `RESTORE` of such a table. [#129605](https://github.com/ClickHouse/ClickHouse/pull/129605) ([Foad Lotfifar](https://github.com/foadl)).
* Backported in [#133209](https://github.com/ClickHouse/ClickHouse/issues/133209): Fix a possible crash of the `RabbitMQ` table engine when the broker confirms a message with an unknown delivery tag. [#131731](https://github.com/ClickHouse/ClickHouse/pull/131731) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#133198](https://github.com/ClickHouse/ClickHouse/issues/133198): Fix a crash (double free) when an allocation failed, e.g. because of the memory limit, while an aggregate function used as a window function moved to a new partition or frame, or while an aggregate function with the `-ArgMin` / `-ArgMax` combinator reset its state for a new extreme value. [#132755](https://github.com/ClickHouse/ClickHouse/pull/132755) ([Raúl Marín](https://github.com/Algunenano)).
