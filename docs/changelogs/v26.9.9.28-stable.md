# 2026 Changelog

### ClickHouse release v26.9.9.28-stable (2363840e077) FIXME as compared to v26.9.8.3-stable (b7bbb4e80c8)

#### Performance Improvement
* Backported in [#123477](https://github.com/ClickHouse/ClickHouse/issues/123477): Faster planning of queries to Iceberg tables with many manifest files: when a manifest file header has the `schema-id` key and that schema is already known from metadata.json, the schema copy stored in the manifest header is no longer parsed and compared with it. ClickHouse now also writes the `schema-id` key into the headers of manifest files it creates. [#122574](https://github.com/ClickHouse/ClickHouse/pull/122574) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Improvement
* Backported in [#123259](https://github.com/ClickHouse/ClickHouse/issues/123259): Hide the HTTP headers in the definition of `HTTP` dictionary sources in `SHOW CREATE DICTIONARY`, `system.tables` and query logs, the same way as passwords. They can be shown with the existing `display_secrets_in_show_and_select` mechanism. [#122673](https://github.com/ClickHouse/ClickHouse/pull/122673) ([Matheus Nerone](https://github.com/Manerone)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#123575](https://github.com/ClickHouse/ClickHouse/issues/123575): Fixed `SYSTEM SYNC TRANSACTION LOG` (local, non-`ON CLUSTER` form) not checking the `SYSTEM_SYNC_TRANSACTION_LOG` privilege. The `ON CLUSTER` form already required it via `getRequiredAccessForDDLOnCluster`, but the local execution path skipped `checkAccess`, so a user without the grant could run the command when experimental transactions were enabled. [#112441](https://github.com/ClickHouse/ClickHouse/pull/112441) ([Azhar Izzannada E](https://github.com/azharizz)).
* Backported in [#123223](https://github.com/ClickHouse/ClickHouse/issues/123223): Fixed asynchronous TLS connections occasionally failing with an unrelated OpenSSL error left by another connection on the same OS thread. This could terminate distributed queries with a misleading network exception. [#116692](https://github.com/ClickHouse/ClickHouse/pull/116692) ([Dmitriy Borisenko](https://github.com/otselnik)).
* Backported in [#123375](https://github.com/ClickHouse/ClickHouse/issues/123375): Fixed an `ssl_certificate` authentication bypass where an embedded NUL byte in a certificate's Common Name (for example `john\0.evil.com`) was truncated server-side to `john`, letting a holder of such a certificate authenticate as a different user. [#117403](https://github.com/ClickHouse/ClickHouse/pull/117403) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#123502](https://github.com/ClickHouse/ClickHouse/issues/123502): Prevent asynchronous inserts that only need to buffer data from being blocked by another insert waiting for a flush worker while holding their shared queue lock. Ensure a global forced flush waits for batches removed from the queue that are still waiting for a worker. [#118352](https://github.com/ClickHouse/ClickHouse/pull/118352) ([RJ](https://github.com/VrtxOmega)).
* Backported in [#123350](https://github.com/ClickHouse/ClickHouse/issues/123350): Skip indexes (`text`, `tokenbf_v1`, `ngrambf_v1`) are now used when the indexed column or the searched constant is wrapped into `LowCardinality`, `Nullable` or an equivalent `CAST`. For example, `m['key'] = 'value'` on a `Map(String, LowCardinality(String))` column and `hasToken(s, toLowCardinality('x'))` previously scanned all granules. [#120220](https://github.com/ClickHouse/ClickHouse/pull/120220) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#123456](https://github.com/ClickHouse/ClickHouse/issues/123456): `EXPLAIN AST` printed secret function arguments, such as the key of `encrypt`, in clear text, and with `optimize = 1` it did so for the body of a view the user may only `SELECT` from. The dump now prints `'[HIDDEN]'` in their place, under the same gate as `SHOW CREATE`. [#120313](https://github.com/ClickHouse/ClickHouse/pull/120313) ([Harikrishnan Prabakaran](https://github.com/harikrishnan94)).
* Backported in [#123222](https://github.com/ClickHouse/ClickHouse/issues/123222): Column-level `SELECT` privileges are now enforced for columns used only inside `indexHint` and for `ALIAS` columns referenced in `PREWHERE`. As in `WHERE`, referencing an `ALIAS` column in `PREWHERE` requires the grant on the alias name; a grant on its source columns is no longer sufficient. A metadata-only `ALTER` that changes a subcolumn read by a `MATERIALIZED` column through an `ALIAS` is now refused like a direct reference. [#120516](https://github.com/ClickHouse/ClickHouse/pull/120516) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Backported in [#123570](https://github.com/ClickHouse/ClickHouse/issues/123570): Fix a server crash (SIGSEGV) when a `CREATE TABLE ... PROJECTION` / `ALTER TABLE ... ADD PROJECTION` statement is restored from a `clickhouse_json` AST whose projection `query` subtree contains a function node without an `arguments` list. The malformed payload is now rejected with `BAD_ARGUMENTS` during AST JSON deserialization. [#121113](https://github.com/ClickHouse/ClickHouse/pull/121113) ([Ilias](https://github.com/iliasabk)).
* Backported in [#123210](https://github.com/ClickHouse/ClickHouse/issues/123210): Fixed a row policy bypass: a direct `JOIN` with an `EmbeddedRocksDB`, `KeeperMap` or `Redis` table in the legacy analyzer (`enable_analyzer = 0`) ignored the row policy of the right table and returned hidden rows, and `joinGet` on a `Join` table ignored its row policy in both analyzers. Such a table is now joined through its query plan, which keeps the filter, and `JOIN` or `joinGet` against a `Join` table under a row policy throws `ACCESS_DENIED`. [#121398](https://github.com/ClickHouse/ClickHouse/pull/121398) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#123203](https://github.com/ClickHouse/ClickHouse/issues/123203): Fix `NO_COMMON_TYPE` in case of `use_variant_as_common_type=0` for jemalloc fragmentation dashboard. [#121621](https://github.com/ClickHouse/ClickHouse/pull/121621) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#122723](https://github.com/ClickHouse/ClickHouse/issues/122723): Now statistics parts pruning will not work if table has row level policy. [#122035](https://github.com/ClickHouse/ClickHouse/pull/122035) ([alesapin](https://github.com/alesapin)).
* Backported in [#123264](https://github.com/ClickHouse/ClickHouse/issues/123264): Fix filesystem cache accounting when the directory for a new cache key cannot be created, for example because the cache disk is out of space or inodes. The failed reservation stayed counted in the cache until the query released the file segment. [#122211](https://github.com/ClickHouse/ClickHouse/pull/122211) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#123358](https://github.com/ClickHouse/ClickHouse/issues/123358): `CREATE OR REPLACE` in a `Replicated` database or with `ON CLUSTER` now requires the drop privilege for the kind of the table it replaces, so a user without `DROP DICTIONARY` can no longer replace a dictionary. [#122272](https://github.com/ClickHouse/ClickHouse/pull/122272) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#123253](https://github.com/ClickHouse/ClickHouse/issues/123253): Fix `LOGICAL_ERROR` `Cannot capture column N because it has incompatible type` when a materialized view with a lambda over an `Array(Tuple(...))` column receives a block while the source table's column type is being changed by `ALTER TABLE ... MODIFY COLUMN`. [#122345](https://github.com/ClickHouse/ClickHouse/pull/122345) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Backported in [#123473](https://github.com/ClickHouse/ClickHouse/issues/123473): Fix a server crash caused by unbounded recursion when decoding a deeply nested value inside a binary encoded type, for example an `AggregateFunction` parameter in a `Dynamic` value read from `RowBinary` or `Native`. [#122667](https://github.com/ClickHouse/ClickHouse/pull/122667) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#123413](https://github.com/ClickHouse/ClickHouse/issues/123413): Fixes a server crash on `CREATE TABLE` or `ALTER TABLE ... MODIFY TTL` with a TTL expression that uses the result of `arrayMap` with a constant lambda, such as `toString(arrayMap(x -> CAST(1, 'Dynamic'), arr))`. [#122868](https://github.com/ClickHouse/ClickHouse/pull/122868) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123120](https://github.com/ClickHouse/ClickHouse/issues/123120): Fixed secret settings of `S3Queue` and `AzureQueue` tables written with the legacy `s3queue_` prefix, such as `s3queue_after_processing_move_secret_access_key`, being shown in cleartext in `SHOW CREATE TABLE`, `system.tables`, `system.query_log` and the server log. They are now hidden as they are without the prefix. [#123060](https://github.com/ClickHouse/ClickHouse/pull/123060) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123385](https://github.com/ClickHouse/ClickHouse/issues/123385): Add more path validations. [#123099](https://github.com/ClickHouse/ClickHouse/pull/123099) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#123150](https://github.com/ClickHouse/ClickHouse/issues/123150): S3 client check initial url in backup client. [#123114](https://github.com/ClickHouse/ClickHouse/pull/123114) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#123394](https://github.com/ClickHouse/ClickHouse/issues/123394): Fix missing rows in `hasAllTokens` and `hasAnyTokens` searches over a text index when an earlier query with the same predicate read a narrower key range of the same part and `use_text_index_postings_cache` was enabled. [#123228](https://github.com/ClickHouse/ClickHouse/pull/123228) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#123444](https://github.com/ClickHouse/ClickHouse/issues/123444): Fix a crash when reading an ORC file whose root type is not a struct (for example, a file written with a `bigint` or `array<bigint>` root type). Such files are now rejected with an `INCORRECT_DATA` error. Closes [#123305](https://github.com/ClickHouse/ClickHouse/issues/123305). [#123337](https://github.com/ClickHouse/ClickHouse/pull/123337) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123617](https://github.com/ClickHouse/ClickHouse/issues/123617): Fixed a crash and wrong results with `convert_query_to_cnf = 1` when `WHERE` or `HAVING` references the same `SELECT` alias more than once. [#123414](https://github.com/ClickHouse/ClickHouse/pull/123414) ([Groene AI](https://github.com/groeneai)).
