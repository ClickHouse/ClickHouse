# 2026 Changelog

### ClickHouse release v26.7.9.12-stable (dcfd8a8ee1f) FIXME as compared to v26.7.8.15-stable (5cf8a36253e)

#### Improvement
* Backported in [#119963](https://github.com/ClickHouse/ClickHouse/issues/119963): Bump the internal libssh from 0.12.0 to 0.12.2. [#119262](https://github.com/ClickHouse/ClickHouse/pull/119262) ([Robert Schulze](https://github.com/rschu1ze)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#119941](https://github.com/ClickHouse/ClickHouse/issues/119941): Fix a logical error `Invalid cast from Nothing to native type` (an abort in debug/sanitizer builds) when `compile_expressions = 1` compiled an expression with a `Nullable(Nothing)` operand, e.g. `and(Nullable(Nothing), <native comparison>)`. [#111508](https://github.com/ClickHouse/ClickHouse/pull/111508) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119973](https://github.com/ClickHouse/ClickHouse/issues/119973): Fixes a case where `date_time_overflow_behavior = 'saturate'`, an out-of-range value is clamped to the whole second and the sub-second component is discarded. Closes [#113152](https://github.com/ClickHouse/ClickHouse/issues/113152). [#116122](https://github.com/ClickHouse/ClickHouse/pull/116122) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#119952](https://github.com/ClickHouse/ClickHouse/issues/119952): Fix a segmentation fault when reading in order from a `Merge` table over `MergeTree` tables whose sorting key is shorter than the key prefix chosen for the query: the prefix was forwarded to the underlying reader unchecked, which grew its cloned sorting-key expression list to that length and appended null AST nodes that were then dereferenced. [#116364](https://github.com/ClickHouse/ClickHouse/pull/116364) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119931](https://github.com/ClickHouse/ClickHouse/issues/119931): Fix rows silently dropped by an `ngrambf_v1` index for a `LIKE` pattern with a run of escaped backslashes before a wildcard. [#118673](https://github.com/ClickHouse/ClickHouse/pull/118673) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#119912](https://github.com/ClickHouse/ClickHouse/issues/119912): Fixed `optimize_or_like_chain` returning extra rows for `OR` chains of `LIKE`/`ILIKE` patterns that do not end in `%`: a value followed by a trailing newline wrongly matched the filter. [#118766](https://github.com/ClickHouse/ClickHouse/pull/118766) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Backported in [#119995](https://github.com/ClickHouse/ClickHouse/issues/119995): Fixed an `ALTER` on a view or materialized view with `SQL SECURITY DEFINER` deleting the auto-created `<user>:definer` account when the `ALTER` did not change the definer. Every later `SELECT` from the view, and every `INSERT` into a materialized view's source table, then failed permanently with `There is no user '<user>:definer' in 'user directories'` (`UNKNOWN_USER`). [#119357](https://github.com/ClickHouse/ClickHouse/pull/119357) ([Groene AI](https://github.com/groeneai)).
* Backported in [#120019](https://github.com/ClickHouse/ClickHouse/issues/120019): Fixed cleartext credentials in `system.asynchronous_insert_log.query`. Secrets of table functions such as `s3`, `url` or `mysql` are now masked as `[HIDDEN]`, the same way `system.query_log` masks them. [#119487](https://github.com/ClickHouse/ClickHouse/pull/119487) ([Sema Checherinda](https://github.com/CheSema)).
* Backported in [#120094](https://github.com/ClickHouse/ClickHouse/issues/120094): Fixed the server not validating the schema of the second and subsequent data blocks that a client sends for an external table over the native protocol. Such a block could make the data be interpreted as a type other than the one it was sent as. [#119849](https://github.com/ClickHouse/ClickHouse/pull/119849) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#120015](https://github.com/ClickHouse/ClickHouse/issues/120015): Fixed a crash of the server caused by a table with `ENGINE = NATS` whose credentials the broker started to reject, for example after a password rotation or on an expired token. Such a table now recreates its connection and resumes consuming once the credentials are accepted again, instead of staying silently idle. [#119853](https://github.com/ClickHouse/ClickHouse/pull/119853) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#120006](https://github.com/ClickHouse/ClickHouse/issues/120006): Fix flaky `test_filesystem_split_cache::test_split_cache_system_files_no_eviction`. The baseline System-segment count was sampled straight after `wait_for_cache_initialized`, which only reports that the cache became usable while background loading keeps adding segments, so the baseline was a partially populated snapshot (416 or 467 against a steady state of 701). The assertion was also two-sided (`abs`), so it failed when the count *grew* — the opposite of what a no-eviction test should check, and the cause of every observed failure. Both comparison points now sample once the count has settled, and the assertion only fails on a drop. Fixes failures like this one https://s3.amazonaws.com/clickhouse-test-reports/json.html?PR=111406&sha=6282394660bff978c2f06b63ecfd9f27d28b1e97&name_0=PR&name_1=Integration+tests+%28amd_tsan%2C+3%2F6%29. [#112099](https://github.com/ClickHouse/ClickHouse/pull/112099) ([Pedro Ferreira](https://github.com/PedroTadim)).
