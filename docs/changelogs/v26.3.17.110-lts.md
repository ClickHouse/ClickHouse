# 2026 Changelog

### ClickHouse release v26.3.17.110-lts (59141459d99) FIXME as compared to v26.3.16.16-lts (f3c09372ed9)

#### Backward Incompatible Change
* Backported in [#111243](https://github.com/ClickHouse/ClickHouse/issues/111243): Add a setting `dynamic_disk_allow_from_env`, `dynamic_disk_allow_from_zk`, `dynamic_disk_allow_include` to disallow usage of `from_env`, `from_zk`, `include` in dynamic disks. Backward Incompatible Change because prohibits by default the behaviour which used to be allowed by default. [#99138](https://github.com/ClickHouse/ClickHouse/pull/99138) ([Kseniia Sumarokova](https://github.com/kssenii)).

#### Performance Improvement
* Backported in [#109131](https://github.com/ClickHouse/ClickHouse/issues/109131): Fixed a performance regression (introduced in [#71781](https://github.com/ClickHouse/ClickHouse/issues/71781)) where reading many small files from object storage via the `s3()` and other table functions stopped prefetching and fell back to synchronous reads, significantly slowing single-threaded / low-concurrency reads of lots of tiny files. [#108872](https://github.com/ClickHouse/ClickHouse/pull/108872) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#109556](https://github.com/ClickHouse/ClickHouse/issues/109556): Issue the initial small-object prefetch also when object storage reads go through the filesystem cache (`filesystem_cache_name`). Previously ([#108872](https://github.com/ClickHouse/ClickHouse/issues/108872)) the prefetch was restored only for non-cached reads, so reads of many small files (e.g. `S3Queue` ingestion) with the filesystem cache enabled remained synchronous and latency-bound. [#109478](https://github.com/ClickHouse/ClickHouse/pull/109478) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#111460](https://github.com/ClickHouse/ClickHouse/issues/111460): Fixed O(P×N) deduplication hash recomputation in async insert flushes that split across P partitions. `DeduplicationInfo::prewarmDataHashes` is now called once before the partition loop in `MergeTreeSink` and `ReplicatedMergeTreeSink`, so all per-partition clones inherit pre-computed `data_hash_batch` values instead of recomputing them P times. This reduces `DuplicationElapsedMicroseconds` proportionally to the number of partitions. [#111150](https://github.com/ClickHouse/ClickHouse/pull/111150) ([Valery Petrov](https://github.com/valerypetrov)).

#### Improvement
* Backported in [#102959](https://github.com/ClickHouse/ClickHouse/issues/102959): Increases `MAX_BLOCK_NUMBER` from ~1 billion to ~2.1 billion (the maximum `Int32` value). On high-load instances with ~60 inserts per second, block numbers can exceed the old limit within months, which could cause operations like `DROP PARTITION` or mutations to silently skip newer parts. This change provides more headroom while staying within safe Keeper sequence number bounds. [#102243](https://github.com/ClickHouse/ClickHouse/pull/102243) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#108850](https://github.com/ClickHouse/ClickHouse/issues/108850): Fix `DataLakeCatalog` databases with `catalog_type = 'onelake'` reading table data by using the OneLake Blob endpoint (`.blob.fabric.microsoft.com`) by default. Set `onelake_use_blob_endpoint = false` to keep the previous DFS endpoint (`.dfs.fabric.microsoft.com`) behavior. [#106843](https://github.com/ClickHouse/ClickHouse/pull/106843) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#112900](https://github.com/ClickHouse/ClickHouse/issues/112900): Support the `REDUCED_REDUNDANCY`, `STANDARD_IA`, `ONEZONE_IA`, `GLACIER_IR`, and `EXPRESS_ONEZONE` values (in addition to `STANDARD` and `INTELLIGENT_TIERING`) for the `s3_storage_class_name` setting. [#107251](https://github.com/ClickHouse/ClickHouse/pull/107251) ([Aditya Kumar](https://github.com/adityaksolves)).
* Backported in [#110487](https://github.com/ClickHouse/ClickHouse/issues/110487): Fixed reading of the `auth_response` length in the MySQL handshake, where a length byte `>= 128` was interpreted as a multi-gigabyte value because it was read as a signed `char`. [#107384](https://github.com/ClickHouse/ClickHouse/pull/107384) ([uwezkhan](https://github.com/uwezkhan)).
* Backported in [#110385](https://github.com/ClickHouse/ClickHouse/issues/110385): MergeTree can now read a compressed stream whose blocks use different codecs. This is the read-side prerequisite for adaptive codec selection (https://github.com/ClickHouse/ClickHouse/issues/105404). [#108592](https://github.com/ClickHouse/ClickHouse/pull/108592) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Backported in [#109268](https://github.com/ClickHouse/ClickHouse/issues/109268): Restore `show_data_lake_catalogs_in_system_tables` as the setting that controls only `DataLakeCatalog` visibility in `system.tables`, `system.columns`, and `system.completions`. Added `show_remote_databases_in_system_tables`, enabled by default, to let users hide `MySQL` and `PostgreSQL` databases from those system tables separately. [#109082](https://github.com/ClickHouse/ClickHouse/pull/109082) ([Pablo Marcos](https://github.com/pamarcos)).
* Backported in [#110414](https://github.com/ClickHouse/ClickHouse/issues/110414): I always find it difficult to add multiple metrics to the dashboard during debugging sessions. This patch adds a simpler way to add them directly from the source code or documentation. [#109449](https://github.com/ClickHouse/ClickHouse/pull/109449) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Backported in [#112366](https://github.com/ClickHouse/ClickHouse/issues/112366): The effective named collections storage type is now available as `named_collections_storage.type` in `system.server_settings` and through `getServerSetting('named_collections_storage_type')`. [#111806](https://github.com/ClickHouse/ClickHouse/pull/111806) ([Pablo Marcos](https://github.com/pamarcos)).
