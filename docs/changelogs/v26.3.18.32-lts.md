# 2026 Changelog

### ClickHouse release v26.3.18.32-lts (bb40d836b15) FIXME as compared to v26.3.17.110-lts (59141459d99)

#### Improvement
* Backported in [#113887](https://github.com/ClickHouse/ClickHouse/issues/113887): Skip unnecessary mark file loads for JSON advanced shared data. [#107051](https://github.com/ClickHouse/ClickHouse/pull/107051) ([Pavel Kruglov](https://github.com/Avogar)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#114383](https://github.com/ClickHouse/ClickHouse/issues/114383): Fix `LOGICAL_ERROR` exceptions when reading `Iceberg` or `DeltaLake` data lake tables through paths that can reach the read pipeline without a pinned `datalake_table_state`, such as concurrent `Iceberg` metadata updates or `merge` reads over `DeltaLake` tables. [#102033](https://github.com/ClickHouse/ClickHouse/pull/102033) ([Groene AI](https://github.com/groeneai)).
* Backported in [#114299](https://github.com/ClickHouse/ClickHouse/issues/114299): Fix dynamic cache resize race in 26.1+. [#103702](https://github.com/ClickHouse/ClickHouse/pull/103702) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Backported in [#114903](https://github.com/ClickHouse/ClickHouse/issues/114903): Fix a rare `LOGICAL_ERROR` "Attempt to release query context that does not exist" and the accompanying server crash when reading `MergeTree` tables through a filesystem cache disk created with `enable_filesystem_query_cache_limit = 1`. [#107028](https://github.com/ClickHouse/ClickHouse/pull/107028) ([Groene AI](https://github.com/groeneai)).
* Backported in [#114446](https://github.com/ClickHouse/ClickHouse/issues/114446): Fixed reading Iceberg v3 tables whose Parquet data files contain reserved row-lineage columns (such as `_row_id`); the native Parquet reader no longer raises `ICEBERG_SPECIFICATION_VIOLATION` for reserved field ids that are not part of the table schema. [#107377](https://github.com/ClickHouse/ClickHouse/pull/107377) ([Greg Maher](https://github.com/gregakinman)).
* Backported in [#112790](https://github.com/ClickHouse/ClickHouse/issues/112790): Fix `type_json_allow_duplicated_key_with_literal_and_nested_object` not working with typed paths in JSON. [#108218](https://github.com/ClickHouse/ClickHouse/pull/108218) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#109169](https://github.com/ClickHouse/ClickHouse/issues/109169): Fixes a null-pointer dereference segfault in `StreamingStorageRegistry` that occurs when `StreamingStorageRegistry::shutdown` and `StorageObjectStorageQueue::shutdown` are called concurrently. [#108810](https://github.com/ClickHouse/ClickHouse/pull/108810) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#114712](https://github.com/ClickHouse/ClickHouse/issues/114712): Fix possible logical error "Unexpected substream ... for column ..." during bump of compatibility setting. [#109496](https://github.com/ClickHouse/ClickHouse/pull/109496) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#111115](https://github.com/ClickHouse/ClickHouse/issues/111115): Fix a segfault when a query arrives while the server is shutting down after an error during startup that happens in a narrow window between servers' startup and creating an exit scope for stopping and reaping of servers. [#109675](https://github.com/ClickHouse/ClickHouse/pull/109675) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#113873](https://github.com/ClickHouse/ClickHouse/issues/113873): Fix out-of-bounds read in SerializationReplicated on the native protocol on corrupted indexes data. [#112331](https://github.com/ClickHouse/ClickHouse/pull/112331) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#114736](https://github.com/ClickHouse/ClickHouse/issues/114736): Fixed a crash when reading a Parquet file with inconsistent bloom filter metadata. Such files could also silently return fewer rows than they should. [#112498](https://github.com/ClickHouse/ClickHouse/pull/112498) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Backported in [#113374](https://github.com/ClickHouse/ClickHouse/issues/113374): Fixed server startup and `ATTACH` failing with `WITH RECURSIVE is not supported with the old analyzer` for a view with a recursive CTE when `enable_analyzer = 0` is the server default. [#112784](https://github.com/ClickHouse/ClickHouse/pull/112784) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#113790](https://github.com/ClickHouse/ClickHouse/issues/113790): Fixed a case where `CREATE TABLE ... ENGINE = Distributed(...)` without a column list could reveal the structure of a local table the creating user is not allowed to see. For a `CREATE` the local server executes itself, the structure is now inferred under the user's own context, so `SHOW COLUMNS` on the target table is required, as it already is for the `Remote` engine. A `CREATE` replayed from the DDL queue (`ON CLUSTER`, or one inside a `Replicated` database) is not covered. [#113220](https://github.com/ClickHouse/ClickHouse/pull/113220) ([Groene AI](https://github.com/groeneai)).
* Backported in [#113929](https://github.com/ClickHouse/ClickHouse/issues/113929): Fixed reading the internal `_temporary_and_external_tables` database through the `merge` table function and the `Merge` table engine, which allowed one session to read the temporary tables of other sessions and other users, and caused an exception on the old analyzer path. A database regexp now skips that database, and naming it explicitly is denied, the same way as direct access to it is. [#113224](https://github.com/ClickHouse/ClickHouse/pull/113224) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#113495](https://github.com/ClickHouse/ClickHouse/issues/113495): Fix a rare use-after-free bug that is triggered in a rare event of the async insert queue having different entries with identical deadlines. Now it's handled gracefully. [#113363](https://github.com/ClickHouse/ClickHouse/pull/113363) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#113801](https://github.com/ClickHouse/ClickHouse/issues/113801): Fixed a case where `CREATE TABLE ... ENGINE = Buffer(...)` without a column list could reveal the structure of a destination table the creating user is not allowed to see. For a `CREATE` the local server executes itself, the structure is now inferred under the user's own context, so `SHOW COLUMNS` on the destination is required, as it already is for `Merge` and `Remote`. A `CREATE` replayed from the DDL queue (`ON CLUSTER`, or inside a `Replicated` database) is not covered. [#113372](https://github.com/ClickHouse/ClickHouse/pull/113372) ([Groene AI](https://github.com/groeneai)).
* Backported in [#114332](https://github.com/ClickHouse/ClickHouse/issues/114332): Fixed `ATTACH` of a `Kafka` table when `kafka_num_consumers` exceeds the limit derived from the number of CPU cores. [#113390](https://github.com/ClickHouse/ClickHouse/pull/113390) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#114308](https://github.com/ClickHouse/ClickHouse/issues/114308): Fixed a row policy containing a scalar subquery being evaluated only once and then reused forever after the table had been read through a `Merge` table. The parsed policy condition is cached and shared by all queries, and reading it through `Merge` rewrote the cached expression in place, which also caused a data race between concurrent queries using the same policy. [#113563](https://github.com/ClickHouse/ClickHouse/pull/113563) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#114808](https://github.com/ClickHouse/ClickHouse/issues/114808): Fix `CANNOT_CONVERT_TYPE` and an exception in `GroupingAggregatedTransform` when reading a `Merge` table with one child being a `Distributed` table under custom-key parallel replicas (`parallel_replicas_mode = 'custom_key_sampling'` or `'custom_key_range'`). Closes [#113741](https://github.com/ClickHouse/ClickHouse/issues/113741). [#113742](https://github.com/ClickHouse/ClickHouse/pull/113742) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#114717](https://github.com/ClickHouse/ClickHouse/issues/114717): Fixed `ORDER BY ... LIMIT` returning fewer rows than requested, possibly none, when a row policy was the only filter of the query and the sort column had a `minmax` skip index. The top-K optimization narrowed the read before the row policy was applied. [#114073](https://github.com/ClickHouse/ClickHouse/pull/114073) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#114875](https://github.com/ClickHouse/ClickHouse/issues/114875): Fixed heap memory corruption when reading Parquet through an input format that owns its read buffer, for example a dictionary with `SOURCE(FILE(... format 'Parquet'))`. Background prefetch and decode tasks could still read and write through the buffer after the pipeline released it, which could abort the server. [#114668](https://github.com/ClickHouse/ClickHouse/pull/114668) ([Groene AI](https://github.com/groeneai)).
