# 2026 Changelog

### ClickHouse release v26.10.7.24-stable (55d02f6a03f) FIXME as compared to v26.10.6.18-stable (68f652e0c11)

#### Performance Improvement
* Backported in [#132809](https://github.com/ClickHouse/ClickHouse/issues/132809): Query analysis is faster for queries whose `AND` chains of comparisons read columns of large subqueries, such as many inlined CTEs: `optimize_and_compare_chain` now hashes each operand once instead of on every lookup. Analysis of the query from [#131134](https://github.com/ClickHouse/ClickHouse/issues/131134) is 2x faster with the work budget off and 1.5x faster at default settings. [#131361](https://github.com/ClickHouse/ClickHouse/pull/131361) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132640](https://github.com/ClickHouse/ClickHouse/issues/132640): A `MergeTree` query that needs no column of the table, such as `SELECT count()` over a table with lightweight-deleted rows, `count()` over a subquery or `SELECT isNullable(c) FROM t`, again reads the column that is smallest on disk, as it does with `query_plan_remove_unused_columns = 0`. Since 25.12 it read the column with the smallest data type, which could be more than 1000 times larger. Closes [#131235](https://github.com/ClickHouse/ClickHouse/issues/131235). Closes [#106597](https://github.com/ClickHouse/ClickHouse/issues/106597). [#131371](https://github.com/ClickHouse/ClickHouse/pull/131371) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132713](https://github.com/ClickHouse/ClickHouse/issues/132713): Primary key analysis of a filter that matches many whole key ranges, such as `WHERE flag` over a `UInt8` key column, is faster again with many threads: the per-range check for a `NULL` or `NaN` nested in a `Tuple` key no longer copies the key type, which made threads contend on its reference count. [#132532](https://github.com/ClickHouse/ClickHouse/pull/132532) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#132742](https://github.com/ClickHouse/ClickHouse/issues/132742): Index analysis now keeps an exact condition for `IN`, `NOT IN` and `has` on a `Tuple` column under an injective key expression such as `ORDER BY toString(k)`, so `NOT IN` and `NOT has` can skip parts and granules. `toString` of `Time`, `Time64`, `DateTime64` and of a `QBit` of floating-point elements is no longer treated as injective, since distinct values can render to the same string (a `Time` beyond `999:59:59`, a `DateTime64` past `9999-12-31`, `NaN` payloads), so `GROUP BY`, `uniq*` and index analysis no longer rely on that claim for them. [#124831](https://github.com/ClickHouse/ClickHouse/pull/124831) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132693](https://github.com/ClickHouse/ClickHouse/issues/132693): Credentials in the URL of a `url` wildcard expanded from HTTP index pages (`allow_url_wildcard_from_index_pages`), or of a `web_index` disk, are now masked in the errors about an index page redirected to a different origin and about an index page over `max_http_index_page_size`. [#126184](https://github.com/ClickHouse/ClickHouse/pull/126184) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#132824](https://github.com/ClickHouse/ClickHouse/issues/132824): Fixed wrong results when a `GROUP BY` or `LIMIT BY` key, or an `ORDER BY` expression, was a function call whose result type collapses to `Nullable(Nothing)` because an argument is a `NULL` constant, such as `concatAssumeInjective(s, NULL)`. Such a call was still treated as injective and replaced by its argument in the key, so `GROUP BY` and `LIMIT BY` produced one group or row per distinct argument value, and `optimize_truncate_order_by_after_group_by_keys` dropped a still-needed `ORDER BY` tiebreaker. [#117894](https://github.com/ClickHouse/ClickHouse/pull/117894) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132812](https://github.com/ClickHouse/ClickHouse/issues/132812): Fixed `NOT_FOUND_COLUMN_IN_BLOCK` for a query whose `SELECT` alias holds an `AND`/`OR`/`=` chain and is reused by `GROUP BY`, `ORDER BY`, `HAVING`, `WHERE` or another alias, for example `SELECT (((s = '1') = 1) = 1) AND (n > 0) AS r FROM t GROUP BY r ORDER BY r`. [#123925](https://github.com/ClickHouse/ClickHouse/pull/123925) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132725](https://github.com/ClickHouse/ClickHouse/issues/132725): Fixed missing rows with a `set` skip index when an outer `WHERE` compares columns of a subquery that gives a column the name of another one (`SELECT w AS k ...`), for example over `remote()`, and `optimize_and_compare_chain` or `optimize_or_like_chain` derives an `indexHint` from it. [#128079](https://github.com/ClickHouse/ClickHouse/pull/128079) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132821](https://github.com/ClickHouse/ClickHouse/issues/132821): Fixed a `LEFT JOIN` over a `Merge` table with a `WHERE _table = ...` condition and `ORDER BY ... LIMIT` failing with an error (`ILLEGAL_TYPE_OF_ARGUMENT`, `UNKNOWN_TABLE`, `ACCESS_DENIED`) that comes from a table the condition excludes. Closes [#124406](https://github.com/ClickHouse/ClickHouse/issues/124406). [#129163](https://github.com/ClickHouse/ClickHouse/pull/129163) ([Groene AI](https://github.com/groeneai)).
* Backported in [#130847](https://github.com/ClickHouse/ClickHouse/issues/130847): When `http_forbid_headers` forbids `Authorization`, Basic credentials that would be sent in that header are now refused too: the userinfo of `url`, `urlCluster` and `URL` table URLs (including url wildcards and `web` disks), `credentials` of `HTTP` dictionaries created by DDL, the userinfo of `format_avro_schema_registry_url`, and `user`/`password` of the `Elasticsearch` engine. Before, only an explicit `Authorization` header was refused. [#129850](https://github.com/ClickHouse/ClickHouse/pull/129850) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132619](https://github.com/ClickHouse/ClickHouse/issues/132619): Fixed a type confusion (possible crash or out-of-bounds read) triggered by a client sending a column with a `Sparse` or `Replicated` serialization kind, or a `Tuple` with a `Replicated` element, in data over the native protocol. [#130895](https://github.com/ClickHouse/ClickHouse/pull/130895) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#132704](https://github.com/ClickHouse/ClickHouse/issues/132704): Lazy materialization of `MergeTree` columns (also over `JOIN`) no longer disables projections. A normal projection can filter the parts and granules of the read, and can serve the read if it has `_parent_part_offset` or all lazily read columns. [#130913](https://github.com/ClickHouse/ClickHouse/pull/130913) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#132737](https://github.com/ClickHouse/ClickHouse/issues/132737): Fixed `optimize_extract_common_expressions` moving the conditions that every branch of an `OR` starts with behind the rest of the `OR` when the `OR` is part of an `AND`. On tables with Compact parts and no statistics this made a lookup like `m['key'] = 'x'` the first `PREWHERE` step, so the whole `Map` was read for every granule (up to 5x slower), and a guard such as `x != 0` in `(x != 0 AND intDiv(10, x) = 1) OR (x != 0 AND intDiv(10, x) = 2)` could stop protecting `intDiv`, failing the query with `Division by zero`. [#131341](https://github.com/ClickHouse/ClickHouse/pull/131341) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132772](https://github.com/ClickHouse/ClickHouse/issues/132772): Fixed parsing of decimal text with an exponent close to the `Int32` limits: values such as `1e2147483647` were read as `0` instead of being rejected as too big. [#131373](https://github.com/ClickHouse/ClickHouse/pull/131373) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#132736](https://github.com/ClickHouse/ClickHouse/issues/132736): The `URL ... is not allowed in configuration file, see <remote_url_allow_hosts>` error now shows only the host and port of the URL, so secrets in its path or query string are no longer exposed. [#132160](https://github.com/ClickHouse/ClickHouse/pull/132160) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#132777](https://github.com/ClickHouse/ClickHouse/issues/132777): Fixed a memory leak in queries answered by `_minmax_count_projection` that compute `min` or `max` of a `Tuple`, `Array` or `FixedString` primary key or partition column: every part read leaked one aggregate state. [#132557](https://github.com/ClickHouse/ClickHouse/pull/132557) ([Groene AI](https://github.com/groeneai)).
* Backported in [#132818](https://github.com/ClickHouse/ClickHouse/issues/132818): With `compatibility` set to 26.4, 26.5 or 26.6, `MergeTree` tables now build `basic, uniq_v2` automatic statistics (the default since 26.7) instead of `minmax, uniq`. This fixes query planning that was many times slower for such tables after an upgrade. [#132600](https://github.com/ClickHouse/ClickHouse/pull/132600) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#132800](https://github.com/ClickHouse/ClickHouse/issues/132800): Fix a crash when `automatic_parallel_replicas_mode` switched a query to parallel replicas and a `set` skip index over a column filtered by `IN (subquery)` was applied during the read (`use_skip_indexes_on_data_read`). [#132659](https://github.com/ClickHouse/ClickHouse/pull/132659) ([Nikita Taranov](https://github.com/nickitat)).

#### Build/Testing/Packaging Improvement
* Update `arrow` and `parquet` Rust crates used by Delta Lake support to 58.4.1 (CVE-2026-111959), and `chdig` to v26.11.1. [#132799](https://github.com/ClickHouse/ClickHouse/pull/132799) ([Konstantin Bogdanov](https://github.com/thevar1able)).
