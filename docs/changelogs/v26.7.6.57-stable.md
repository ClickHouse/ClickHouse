# 2026 Changelog

### ClickHouse release v26.7.6.57-stable (bf82ad6cfcb) FIXME as compared to v26.7.5.10-stable (c7d5ecce0dd)

#### Performance Improvement
* Backported in [#117028](https://github.com/ClickHouse/ClickHouse/issues/117028): Push a `WHERE` condition on a `USING` column through a `RIGHT JOIN` so the left `MergeTree` input can use it as a primary-key index condition, also when the two join keys have different types. Applies when `enable_analyzer = 1`. [#103478](https://github.com/ClickHouse/ClickHouse/pull/103478) ([Manuel](https://github.com/raimannma)).
* Backported in [#115792](https://github.com/ClickHouse/ClickHouse/issues/115792): Speed up query planning when `uniq_v2` column statistics are used. The estimated number of distinct values is now cached instead of being recomputed on every request, which query planning issues many times per query. (issue [#113038](https://github.com/ClickHouse/ClickHouse/issues/113038)). [#113357](https://github.com/ClickHouse/ClickHouse/pull/113357) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116313](https://github.com/ClickHouse/ClickHouse/issues/116313): Bounded the cost of estimating the selectivity of `col IN (...)` from column statistics, which could add hundreds of milliseconds to the planning of a single query. The estimator no longer runs the subquery behind `col IN (subquery)` to fill a set it only needs one selectivity number from — an unbuilt set is skipped instead. For a set larger than the new `statistics_max_set_size_for_exact_selectivity_estimation` setting (default 10000), the selectivity is now derived from the size of the set and its bounding range. [#114389](https://github.com/ClickHouse/ClickHouse/pull/114389) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#116759](https://github.com/ClickHouse/ClickHouse/issues/116759): Fixed a performance regression where a query combining a text index filter with `ORDER BY ... LIMIT` stopped answering the filter from the index and read the whole text column instead. [#115586](https://github.com/ClickHouse/ClickHouse/pull/115586) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Backported in [#117083](https://github.com/ClickHouse/ClickHouse/issues/117083): Fixed a performance regression since 26.6: a query filtering a `Nullable` column with `IN (subquery)` read the whole table instead of skipping the read when the subquery returned no rows. Closes [#116450](https://github.com/ClickHouse/ClickHouse/issues/116450). [#116538](https://github.com/ClickHouse/ClickHouse/pull/116538) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#117291](https://github.com/ClickHouse/ClickHouse/issues/117291): Sped up SQL function `formatDateTime` with non-const timezone arguments. [#116851](https://github.com/ClickHouse/ClickHouse/pull/116851) ([Robert Schulze](https://github.com/rschu1ze)).

#### Improvement
* Backported in [#116509](https://github.com/ClickHouse/ClickHouse/issues/116509): A `bloom_filter` skip index on an `Array` column is now used for `arrayJoin(column) IN (set)`, `arrayJoin(column) GLOBAL IN (set)` and `arrayJoin(column) = const`, the same way it was already used for `hasAny(column, set)` and `has(column, const)`. Previously these `arrayJoin ...` forms fell back to a full scan. [#109536](https://github.com/ClickHouse/ClickHouse/pull/109536) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116298](https://github.com/ClickHouse/ClickHouse/issues/116298): Use the `bloom_filter` skip index for `IN` predicates on a directly indexed column when `transform_null_in = 1` and the `IN`-set contains no `NULL` value. Previously the index was skipped for such queries, forcing a full scan. [#111329](https://github.com/ClickHouse/ClickHouse/pull/111329) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115794](https://github.com/ClickHouse/ClickHouse/issues/115794): Added a new MergeTree setting `text_index_version` that controls the on-disk format version of text indexes: `v0_initial`, `v1_with_codec`, or `v2_with_positions`. During a rolling upgrade or before a downgrade, set it to an older version so that newer servers keep writing text index parts in a format older servers can still read; the compatibility setting automatically adjusts it. [#111803](https://github.com/ClickHouse/ClickHouse/pull/111803) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#113821](https://github.com/ClickHouse/ClickHouse/issues/113821): Added fs cache download wait timeout configured by `filesystem_cache_wait_for_concurrent_download_timeout_milliseconds`. This timeout defined only the wait for a single chunk (buffer bytes of ~1mb) of data, not the whole file segment. [#113322](https://github.com/ClickHouse/ClickHouse/pull/113322) ([Kseniia Sumarokova](https://github.com/kssenii)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#116680](https://github.com/ClickHouse/ClickHouse/issues/116680): Fixed Kafka tables using `kafka_sasl_mechanism = 'AWS_MSK_IAM'` failing authentication once an hour with `SASL authentication error: Access denied`. The OAUTHBEARER token lifetime advertised to librdkafka is now capped by the remaining validity of the AWS credentials that signed the token, so the next token refresh is always scheduled before those credentials expire. Successful token refreshes are now logged, and unhelpful ClickHouse-side stack traces are omitted from broker-originated SASL errors in `system.kafka_consumers`. [#109125](https://github.com/ClickHouse/ClickHouse/pull/109125) ([kalavt](https://github.com/kalavt)).
* Backported in [#117050](https://github.com/ClickHouse/ClickHouse/issues/117050): Constant folding during query planning no longer executes a function whose argument type differs from the type the function was resolved for during analysis. Such a mismatch used to raise a `LOGICAL_ERROR` while the output header was being computed, which is an assertion failure in debug and sanitizer builds. Folding is now skipped instead, and a genuinely invalid query still reports a recoverable `ILLEGAL_TYPE_OF_ARGUMENT` error from the normal execution path. [#109747](https://github.com/ClickHouse/ClickHouse/pull/109747) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116192](https://github.com/ClickHouse/ClickHouse/issues/116192): Fix a data race (and rare crash) when a parsing/analysis error is reported while reading a file/object storage table. A parse error raised during lazy `KeyCondition` initialization was shared as a single exception object across reader threads, and two threads could concurrently append `(in file/uri ...)` to its message, racing on the exception message string. [#109911](https://github.com/ClickHouse/ClickHouse/pull/109911) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117392](https://github.com/ClickHouse/ClickHouse/issues/117392): Fix `CREATE OR REPLACE` leaving the replaced object behind under an internal name when the caller lacks the drop privilege on it. [#111466](https://github.com/ClickHouse/ClickHouse/pull/111466) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#116390](https://github.com/ClickHouse/ClickHouse/issues/116390): Fixes a `bloom_filter` skip index dropping granules that contain matching rows when a `String` or `FixedString` column is compared for equality against a constant that is wider than the indexed type, so that queries such as `SELECT count() FROM t WHERE s = toFixedString('abc', 5)` no longer silently return too few rows. [#112639](https://github.com/ClickHouse/ClickHouse/pull/112639) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117196](https://github.com/ClickHouse/ClickHouse/issues/117196): Fixes two cases where an AWS Glue `DataLakeCatalog` database reported a table as absent instead of reporting an error. `SHOW TABLES` and `system.tables` no longer fail with `DATALAKE_DATABASE_ERROR` ("Exception calling GetTables ... not found") when a Glue database is absent while its tables are listed, for example because an unrelated database in the same AWS account was dropped concurrently; such a database now contributes no tables instead of aborting the listing. `EXISTS TABLE` no longer answers `0` for a table that exists when the underlying `GetTable` call fails for a reason other than the table being absent, such as an authentication, DNS or 5xx failure. Every other Glue error still propagates in both paths. [#113591](https://github.com/ClickHouse/ClickHouse/pull/113591) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116219](https://github.com/ClickHouse/ClickHouse/issues/116219): Fixed `Logical error: 'Files metadata is empty'` when reading from, altering, or flushing an `S3Queue`/`AzureQueue` table whose metadata handle is gone: concurrently with a `DROP`/`DETACH`, after a failed `startup`, or after a failed `DROP`. Such a table now reports `TABLE_IS_DROPPED` instead. `SYSTEM FLUSH OBJECT STORAGE QUEUE` on such a table no longer crashes the server. [#113695](https://github.com/ClickHouse/ClickHouse/pull/113695) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116766](https://github.com/ClickHouse/ClickHouse/issues/116766): Fix a crash for `ORDER BY ALL` in a `WINDOW VIEW`, and `UNKNOWN_IDENTIFIER` errors for `INTERPOLATE`, `WINDOW` and `LIMIT BY` in a query over a `Merge` or `Distributed` table with a join, with the old analyzer. [#113759](https://github.com/ClickHouse/ClickHouse/pull/113759) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116962](https://github.com/ClickHouse/ClickHouse/issues/116962): Fixes `ORDER BY ... LIMIT` queries on `Tuple()` columns raising a `NOT_IMPLEMENTED` exception when top-K dynamic filtering is enabled. Direct empty tuples now skip the optimization, while supported nested composite types continue to use top-K filtering. [#114182](https://github.com/ClickHouse/ClickHouse/pull/114182) ([Langning Zhang](https://github.com/Boulea7)).
* Backported in [#115561](https://github.com/ClickHouse/ClickHouse/issues/115561): Fix `std::out_of_range: map::at: key not found` when a `MergeTree` key expression contains a `mortonEncode` or `hilbertEncode` call that is not itself a key column, for example `ORDER BY mortonEncode(hilbertEncode(x, y), x, y)` or `PARTITION BY mortonEncode(x, y) % 4`. [#114233](https://github.com/ClickHouse/ClickHouse/pull/114233) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116098](https://github.com/ClickHouse/ClickHouse/issues/116098): Register Iceberg namespace in the catalog before writing table files (needed for SeaweedFS). [#114285](https://github.com/ClickHouse/ClickHouse/pull/114285) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#116466](https://github.com/ClickHouse/ClickHouse/issues/116466): Fixes a server abort (`Logical error: Part patch-... doesn't exist`) when a `DROP TABLE` runs concurrently with a lightweight `UPDATE` on a `ReplicatedMergeTree` table. The update now holds the table's shared lock until its patch part is committed, so the `DROP` waits instead of removing it. [#114826](https://github.com/ClickHouse/ClickHouse/pull/114826) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116194](https://github.com/ClickHouse/ClickHouse/issues/116194): The AI-function quota settings (`ai_function_max_api_calls_per_query`, `ai_function_max_input_tokens_per_query`, `ai_function_max_output_tokens_per_query`) were enforced per block rather than per query, letting a query exceed the configured limit in proportion to the number of blocks and threads processed. They now bound the whole query per server: the API-call limit is an exact cap (atomic reservation), and the token limits are best-effort. A distributed query enforces the limits independently on each participating server / fragment. [#114885](https://github.com/ClickHouse/ClickHouse/pull/114885) ([George Larionov](https://github.com/george-larionov)).
* Backported in [#115859](https://github.com/ClickHouse/ClickHouse/issues/115859): Fixed a hang when dropping a `TimeSeries` table whose name sorts lexicographically below its inner tables' names, for example `` DROP TABLE `-ts` `` or dropping a materialized view declared with `ENGINE = TimeSeries`. The drop self-deadlocked on the DDL guard and could not be cancelled with `KILL QUERY`. [#114953](https://github.com/ClickHouse/ClickHouse/pull/114953) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116536](https://github.com/ClickHouse/ClickHouse/issues/116536): Fixed an out-of-bounds read while deserializing corrupted posting lists of a text index. [#115222](https://github.com/ClickHouse/ClickHouse/pull/115222) ([Anton Popov](https://github.com/CurtizJ)).
* Backported in [#115815](https://github.com/ClickHouse/ClickHouse/issues/115815): Fixed a row policy bypass where the mergeTreeIndex table function exposed primary key and minmax index values of the rows hidden by a SELECT row policy on the source table; reading mergeTreeIndex for a table with a row policy is now denied. [#115304](https://github.com/ClickHouse/ClickHouse/pull/115304) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#116411](https://github.com/ClickHouse/ClickHouse/issues/116411): Fixes asynchronous inserts into `JSON` columns ignoring the `max_dynamic_subcolumns_in_json_type_parsing` setting. Previously, an asynchronous insert (`async_insert = 1`) could store more dynamic paths than the setting allows, giving a different column layout than a synchronous insert with the same settings. The cap is now preserved when asynchronous inserts aggregate parsed data. [#115329](https://github.com/ClickHouse/ClickHouse/pull/115329) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* Backported in [#116266](https://github.com/ClickHouse/ClickHouse/issues/116266): Fixed a bypass of settings constraints: `SET <name> = DEFAULT` reset a setting without checking the constraints from the user's profile, so a `MIN`/`MAX`/`CONST` constraint could be escaped by resetting the setting instead of assigning to it, and a session could leave readonly mode with `SET readonly = DEFAULT`. [#115334](https://github.com/ClickHouse/ClickHouse/pull/115334) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#117156](https://github.com/ClickHouse/ClickHouse/issues/117156): Fixed a settings-constraint bypass: a `SETTINGS` clause inside a subquery, a CTE or a view's inner query was applied without checking the settings constraints, so it could be used to leave readonly mode or to override a `CONST`, `MIN` or `MAX` constraint (for example `additional_table_filters`, breaking row-level isolation). The nested clause is now clamped to the constraints: violating changes are dropped, out-of-bounds values are clamped into their bounds, and the rest of the clause applies. Existing views whose inner query carries such a clause keep working, with the constraints enforced; a clause on the outer query still throws, as before. [#115397](https://github.com/ClickHouse/ClickHouse/pull/115397) ([Itamar Tempelhof](https://github.com/tempel-it)).
* Backported in [#116404](https://github.com/ClickHouse/ClickHouse/issues/116404): Validate Variant discriminator in ColumnVariant arena deserialization. [#115443](https://github.com/ClickHouse/ClickHouse/pull/115443) ([Azat Khuzhin](https://github.com/azat)).
* Backported in [#115754](https://github.com/ClickHouse/ClickHouse/issues/115754): Fix `read_rows`, `read_bytes`, `written_rows` and `written_bytes` in `system.query_thread_log` reporting a thread lifetime running total instead of the values for the logged query. Rows of long-lived pooled threads, in particular the query's initiating `HTTPHandler` thread, were affected. [#115596](https://github.com/ClickHouse/ClickHouse/pull/115596) ([Groene AI](https://github.com/groeneai)).
* Backported in [#115845](https://github.com/ClickHouse/ClickHouse/issues/115845): Allow KeeperMap readers to accept shared metadata when equivalent primary keys differ only by redundant outer parentheses. [#115642](https://github.com/ClickHouse/ClickHouse/pull/115642) ([Sergey Kuznetsov](https://github.com/skuznetsov-clickhouse)).
* Backported in [#115731](https://github.com/ClickHouse/ClickHouse/issues/115731): Fixed a bug in the function `formatRowNoNewline` that could produce incorrect results or a logical error when a row is formatted to an empty result. [#115669](https://github.com/ClickHouse/ClickHouse/pull/115669) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#115955](https://github.com/ClickHouse/ClickHouse/issues/115955): Fix server crashes on deeply nested input in `readWKB`, `JSONMergePatch`, the address parser of the `url`/`remote`/`cluster`/`mysql`/`postgresql` table functions, the `CURSOR` clause parser and the CapnProto schema parser. Fix a crash in the parser of the `EXECUTE` statement when an argument is not a literal. [#115700](https://github.com/ClickHouse/ClickHouse/pull/115700) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116353](https://github.com/ClickHouse/ClickHouse/issues/116353): Validate the states of the `stochasticLinearRegression`, `stochasticLogisticRegression`, `groupUniqArray`, `groupArrayIntersect` and `topK` aggregate functions and of the `Resample` combinator on deserialization: a malformed state could be read out of bounds. [#115701](https://github.com/ClickHouse/ClickHouse/pull/115701) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116653](https://github.com/ClickHouse/ClickHouse/issues/116653): Fix crashes of the Parquet, ORC and Iceberg readers on malformed input: a `DELTA_BYTE_ARRAY` page with an empty length stream, a `DELTA_BYTE_ARRAY` page of a `Decimal` column read under a filter, an out-of-range enum in an Iceberg manifest file and an oversized allocation in the ORC library. [#115703](https://github.com/ClickHouse/ClickHouse/pull/115703) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#115930](https://github.com/ClickHouse/ClickHouse/issues/115930): Do not return uninitialized memory in the result of a binary string literal whose length is not a multiple of eight, and from the LZ4 decompressor when a compressed block has no body. [#115704](https://github.com/ClickHouse/ClickHouse/pull/115704) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#117060](https://github.com/ClickHouse/ClickHouse/issues/117060): Fix a crash of a window function over a `Tuple` with a sparse element, for example `groupConcat(t) OVER ()`. [#115705](https://github.com/ClickHouse/ClickHouse/pull/115705) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

[#115708](https://github.com/ClickHouse/ClickHouse/pull/115708) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

It was previously printed in plaintext, unlike the other AWS credential settings. Closes: [#114999](https://github.com/ClickHouse/ClickHouse/issues/114999). * Backported in [#116015](https://github.com/ClickHouse/ClickHouse/issues/116015): Add Objects' paths to deduplication hashing, preventing incorrect deduplication. [#115866](https://github.com/ClickHouse/ClickHouse/pull/115866) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* Fixed a `TABLE ENGINE` privilege bypass in the `URL` table engine. A user granted only `TABLE ENGINE ON URL` could `ATTACH TABLE ... ENGINE = URL('file://...')` (or `s3://`, `az://`, `hdfs://`) and read through it, because the privilege re-check on the backend the scheme dispatches to ran only for `CREATE`. It now runs for every statement that supplies a fresh definition, `ATTACH` and `RESTORE` included, while a definition replayed from the server's own metadata stays exempt so existing tables keep loading. [#115966](https://github.com/ClickHouse/ClickHouse/pull/115966) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116524](https://github.com/ClickHouse/ClickHouse/issues/116524): Fix a crash of the `showCertificate` function on a server that obtains its TLS certificate with ACME (Let's Encrypt). The function now reports the certificate that is actually served, also after a certificate reload. [#115976](https://github.com/ClickHouse/ClickHouse/pull/115976) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#116747](https://github.com/ClickHouse/ClickHouse/issues/116747): You can now read Iceberg v2 tables whose manifests omit the optional `snapshot_id` column, such as tables managed by BigQuery; reading one previously failed with `Cannot find column snapshot_id`. A manifest that omits `sequence_number` is also no longer read as sequence number 0. Both values are inherited from the manifest list, as the Iceberg spec requires. [#116040](https://github.com/ClickHouse/ClickHouse/pull/116040) ([Takayuki Enomoto](https://github.com/tkykenmt)).
* Backported in [#116143](https://github.com/ClickHouse/ClickHouse/issues/116143): Fix stateless workers crash with object storage. [#116067](https://github.com/ClickHouse/ClickHouse/pull/116067) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#116710](https://github.com/ClickHouse/ClickHouse/issues/116710): Fix wrong window function results for `PARTITION BY` over a floating-point key (also `JSON`, `Dynamic`, and these types nested in `Nullable`/`LowCardinality`/`Array`/`Tuple`/`Map`/`Variant`) with `max_threads > 1`: values that compare as equal, such as `-0.` and `0.`, could hash into different threads, and one logical partition got several window frames. [#116315](https://github.com/ClickHouse/ClickHouse/pull/116315) ([Alexander Gololobov](https://github.com/davenger)).
* Backported in [#116494](https://github.com/ClickHouse/ClickHouse/issues/116494): KeeperMap now writes single-expression primary keys without redundant outer parentheses, so metadata created by newer servers remains readable by ClickHouse 26.4 during supported rolling upgrades and rollbacks. [#116369](https://github.com/ClickHouse/ClickHouse/pull/116369) ([Sergey Kuznetsov](https://github.com/skuznetsov-clickhouse)).
* Backported in [#117056](https://github.com/ClickHouse/ClickHouse/issues/117056): Fixed a `WHERE _table = ...` or `WHERE _database = ...` condition over a `Merge` table silently returning no rows when the matching child table reads its data from other tables, for example a `Distributed`, `Merge`, `Buffer`, or `Alias` child. Such children are now always read, and the condition filters their rows. [#116371](https://github.com/ClickHouse/ClickHouse/pull/116371) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#117367](https://github.com/ClickHouse/ClickHouse/issues/117367): Fix a `bloom_filter` skip index returning fewer rows for `IN` on an `Array` column when the set contains an empty array, for example `WHERE x IN ([])`. [#116449](https://github.com/ClickHouse/ClickHouse/pull/116449) ([Groene AI](https://github.com/groeneai)).
* Backported in [#117374](https://github.com/ClickHouse/ClickHouse/issues/117374): Fixed a 404 (`S3_ERROR`) when reading an Iceberg table through a path that is a parent of the table directory, with the metadata document named by the `iceberg_metadata_file_path` setting: every data and manifest key was resolved against the queried path, so the directories between it and the table were dropped from the key.
