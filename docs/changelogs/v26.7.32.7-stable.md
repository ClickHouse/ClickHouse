# 2026 Changelog

### ClickHouse release v26.7.32.7-stable (cd652d7b774) FIXME as compared to v26.7.31.12-stable (467e69f0016)

#### Backward Incompatible Change
* Backported in [#125981](https://github.com/ClickHouse/ClickHouse/issues/125981): Overriding a key that is stored in a named collection now requires `SHOW NAMED COLLECTIONS SECRETS` on that collection. This also applies to overrides through an alias (including flat `kafka_*` settings over nested `kafka.*` keys), through a `SETTINGS` clause of a table engine or table function, and through keys in a dictionary source (checked when the dictionary is created). Resolving a relative `url` stored in a named collection against `s3_base` or `url_base` also counts as an override of `url`. Adding a key that the collection does not store remains allowed, and keys marked `NOT OVERRIDABLE` cannot be overridden. The `allow_named_collection_override_by_default` setting is obsolete. Existing tables whose `SETTINGS` or alias arguments override a `NOT OVERRIDABLE` key cannot be loaded after the upgrade, and the server does not start: before upgrading, recreate such tables without the override, or make the key overridable. [#123133](https://github.com/ClickHouse/ClickHouse/pull/123133) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125879](https://github.com/ClickHouse/ClickHouse/issues/125879): Do not remove columns when it's referenced in both `PREWHERE` and `WHERE` filter conditions even if it's rewritten into a text index virtual column. [#114460](https://github.com/ClickHouse/ClickHouse/pull/114460) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Backported in [#125833](https://github.com/ClickHouse/ClickHouse/issues/125833): Fixed a stack overflow crash on a deeply nested CapnProto schema that the nesting depth check missed: a comment or a byte order mark between `import` and its path, an escape sequence in the import path, or a backtick text line. A backtick text line with many brackets is no longer rejected as nested too deeply. [#125487](https://github.com/ClickHouse/ClickHouse/pull/125487) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125933](https://github.com/ClickHouse/ClickHouse/issues/125933): Fixed a possible segmentation fault when reading an Avro `map` into a `Map` column (for example `Map(DateTime, String)`) with the `AvroConfluent` format, including Kafka tables. Closes [#125457](https://github.com/ClickHouse/ClickHouse/issues/125457). [#125505](https://github.com/ClickHouse/ClickHouse/pull/125505) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126066](https://github.com/ClickHouse/ClickHouse/issues/126066): Fixed an issue where pressing Ctrl-R and then Ctrl-Z in the web terminal or the SSH interface suspended the whole server process. [#125512](https://github.com/ClickHouse/ClickHouse/pull/125512) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126068](https://github.com/ClickHouse/ClickHouse/issues/126068): Fixed a crash (stack overflow) on a CapnProto schema with a long chain of type expression suffixes (`Int32.a.a...`, `Int32()()...`) or of declarations that refer to each other (constants, aliases, struct fields, annotations, imports). Such a schema is now rejected with `The CapnProto schema is nested too deeply`. Closes [#125782](https://github.com/ClickHouse/ClickHouse/issues/125782). [#125900](https://github.com/ClickHouse/ClickHouse/pull/125900) ([Groene AI](https://github.com/groeneai)).
