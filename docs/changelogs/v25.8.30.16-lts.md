# 2026 Changelog

### ClickHouse release v25.8.30.16-lts (041f2f1bd67) FIXME as compared to v25.8.29.51-lts (54df9137dcf)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#111114](https://github.com/ClickHouse/ClickHouse/issues/111114): Fix a segfault when a query arrives while the server is shutting down after an error during startup that happens in a narrow window between servers' startup and creating an exit scope for stopping and reaping of servers. [#109675](https://github.com/ClickHouse/ClickHouse/pull/109675) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#113373](https://github.com/ClickHouse/ClickHouse/issues/113373): Fixed server startup and `ATTACH` failing with `WITH RECURSIVE is not supported with the old analyzer` for a view with a recursive CTE when `enable_analyzer = 0` is the server default. [#112784](https://github.com/ClickHouse/ClickHouse/pull/112784) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#113789](https://github.com/ClickHouse/ClickHouse/issues/113789): Fixed a case where `CREATE TABLE ... ENGINE = Distributed(...)` without a column list could reveal the structure of a local table the creating user is not allowed to see. For a `CREATE` the local server executes itself, the structure is now inferred under the user's own context, so `SHOW COLUMNS` on the target table is required, as it already is for the `Remote` engine. A `CREATE` replayed from the DDL queue (`ON CLUSTER`, or one inside a `Replicated` database) is not covered. [#113220](https://github.com/ClickHouse/ClickHouse/pull/113220) ([Groene AI](https://github.com/groeneai)).
* Backported in [#113930](https://github.com/ClickHouse/ClickHouse/issues/113930): Fixed reading the internal `_temporary_and_external_tables` database through the `merge` table function and the `Merge` table engine, which allowed one session to read the temporary tables of other sessions and other users, and caused an exception on the old analyzer path. A database regexp now skips that database, and naming it explicitly is denied, the same way as direct access to it is. [#113224](https://github.com/ClickHouse/ClickHouse/pull/113224) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#113494](https://github.com/ClickHouse/ClickHouse/issues/113494): Fix a rare use-after-free bug that is triggered in a rare event of the async insert queue having different entries with identical deadlines. Now it's handled gracefully. [#113363](https://github.com/ClickHouse/ClickHouse/pull/113363) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#113800](https://github.com/ClickHouse/ClickHouse/issues/113800): Fixed a case where `CREATE TABLE ... ENGINE = Buffer(...)` without a column list could reveal the structure of a destination table the creating user is not allowed to see. For a `CREATE` the local server executes itself, the structure is now inferred under the user's own context, so `SHOW COLUMNS` on the destination is required, as it already is for `Merge` and `Remote`. A `CREATE` replayed from the DDL queue (`ON CLUSTER`, or inside a `Replicated` database) is not covered. [#113372](https://github.com/ClickHouse/ClickHouse/pull/113372) ([Groene AI](https://github.com/groeneai)).
* Backported in [#114331](https://github.com/ClickHouse/ClickHouse/issues/114331): Fixed `ATTACH` of a `Kafka` table when `kafka_num_consumers` exceeds the limit derived from the number of CPU cores. [#113390](https://github.com/ClickHouse/ClickHouse/pull/113390) ([Nikolay Degterinsky](https://github.com/evillique)).
* Updated the bundled curl library to 8.21.0, fixing several security issues affecting connection reuse, proxy authentication, cookie handling, and WebSocket support. [#114301](https://github.com/ClickHouse/ClickHouse/pull/114301) ([Chethan Kumar Reddy](https://github.com/chethan-64)).
