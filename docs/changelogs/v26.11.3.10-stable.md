# 2026 Changelog

### ClickHouse release v26.11.3.10-stable (140ed394689) FIXME as compared to v26.11.2.4-stable (66f7a9f1b34)

#### Performance Improvement
* Backported in [#134573](https://github.com/ClickHouse/ClickHouse/issues/134573): With parallel replicas, every replica now applies its own query condition cache to the ranges the coordinator assigns it. Previously only the replica whose index analysis drove the assignment benefited from the cache. [#129375](https://github.com/ClickHouse/ClickHouse/pull/129375) ([Nikita Taranov](https://github.com/nickitat)).
* Backported in [#134672](https://github.com/ClickHouse/ClickHouse/issues/134672): Wake idle ThreadPool thread after releasing the pool mutex. [#134433](https://github.com/ClickHouse/ClickHouse/pull/134433) ([Azat Khuzhin](https://github.com/azat)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134496](https://github.com/ClickHouse/ClickHouse/issues/134496): Do not use non-deterministic table defaults for lazy column materialization. Otherwise, the result could be inconsistent. [#126939](https://github.com/ClickHouse/ClickHouse/pull/126939) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Backported in [#134534](https://github.com/ClickHouse/ClickHouse/issues/134534): Fix slow or failing DNS resolution of one host blocking HTTP and S3 requests to all other hosts and the `SYSTEM CLEAR DNS CACHE` query, because the resolution was done under a global lock. [#132854](https://github.com/ClickHouse/ClickHouse/pull/132854) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Backported in [#134212](https://github.com/ClickHouse/ClickHouse/issues/134212): `ATTACH MATERIALIZED VIEW` with a full definition now validates the `SELECT` query the same way as `CREATE MATERIALIZED VIEW`. [#133025](https://github.com/ClickHouse/ClickHouse/pull/133025) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Backported in [#134520](https://github.com/ClickHouse/ClickHouse/issues/134520): With `access_control_improvements.readonly_restricts_set_role` enabled, `SET DEFAULT ROLE` is now refused in `readonly` mode as well as `SET ROLE`. Previously a readonly session could change its own default roles and so start the next session with another role. [#133762](https://github.com/ClickHouse/ClickHouse/pull/133762) ([Vadim Skipin](https://github.com/vadimskipin)).
* Backported in [#134415](https://github.com/ClickHouse/ClickHouse/issues/134415): Fix substring conditions (`LIKE`, `endsWith`, ...) on a `String` column of the sorting key ignoring a lightweight `DELETE` or `UPDATE` that is not merged into the part yet (deleted rows were returned, updated values were not seen), when `apply_string_filters_during_scan` is enabled (the default). Closes [#133917](https://github.com/ClickHouse/ClickHouse/issues/133917). [#134050](https://github.com/ClickHouse/ClickHouse/pull/134050) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134462](https://github.com/ClickHouse/ClickHouse/issues/134462): Fixed a heap-use-after-free in text index queries over overlapping parts, for example in a `FINAL` query with `use_skip_indexes_if_final_exact_mode = 0`. [#134226](https://github.com/ClickHouse/ClickHouse/pull/134226) ([Groene AI](https://github.com/groeneai)).

#### Build/Testing/Packaging Improvement
* Backported in [#134622](https://github.com/ClickHouse/ClickHouse/issues/134622): Update `zstd` to v1.6.0. [#134248](https://github.com/ClickHouse/ClickHouse/pull/134248) ([Actuele AI](https://github.com/actueleai)).
