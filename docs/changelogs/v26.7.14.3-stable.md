# 2026 Changelog

### ClickHouse release v26.7.14.3-stable (4b5385ab5e3) FIXME as compared to v26.7.13.12-stable (cd7ea6748fe)

#### Backward Incompatible Change
* Backported in [#121186](https://github.com/ClickHouse/ClickHouse/issues/121186): Outbound TLS connections now verify that the server certificate names the host that was connected to. This affects `clickhouse-client --secure`, `remoteSecure()`, `Distributed` over the secure native protocol, secure Keeper connections, and HTTPS clients such as `s3()`, `url()`, HTTP dictionaries and JWT token endpoints. Connecting to an endpoint whose certificate does not name it, for example an IP address with no matching SAN, an S3-compatible gateway fronted by a different name, or an internal CA with missing SANs, now fails with `Unacceptable certificate`. Set `openSSL.client.extendedVerification` to `false` to restore the previous behaviour, or pass `--tls-sni-override` to name the host the certificate was issued for. Loopback addresses stay exempt unless `verificationMode` is `strict`, and the default for `openSSL.server.extendedVerification` is unchanged. [#116724](https://github.com/ClickHouse/ClickHouse/pull/116724) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#121226](https://github.com/ClickHouse/ClickHouse/issues/121226): Fixed an out-of-bounds read when reading a `Variant` column from a truncated `Native` stream using compact discriminators serialization. [#120252](https://github.com/ClickHouse/ClickHouse/pull/120252) ([Raufs Dunamalijevs](https://github.com/rienath)).
