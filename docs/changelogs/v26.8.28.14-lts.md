# 2026 Changelog

### ClickHouse release v26.8.28.14-lts (3694fe07040) FIXME as compared to v26.8.27.9-lts (551899e257e)

#### Backward Incompatible Change
* Backported in [#125780](https://github.com/ClickHouse/ClickHouse/issues/125780): Connections to MySQL (the `mysql` table function, the `MySQL` table and database engines, and `MySQL` dictionaries) that set `ssl_ca` or `ssl_ca_pem` now verify the server certificate chain and host name, after updating `mariadb-connector-c` to v3.4.10. Previously the CA was not enforced, so a connection to a server whose certificate is signed by another CA, or whose certificate does not list the host name or IP address used to connect, succeeded and now fails with `self-signed certificate in certificate chain` or `Hostname verification failed`. Before upgrading, make sure the configured CA signs the MySQL server certificate and that the certificate lists the host name or IP address ClickHouse connects to. [#119510](https://github.com/ClickHouse/ClickHouse/pull/119510) ([Actuele AI](https://github.com/actueleai)).

#### Performance Improvement
* Backported in [#125806](https://github.com/ClickHouse/ClickHouse/issues/125806): A filter on the `PARTITION BY` columns of a window function is no longer pushed below the window (this reverts [#110114](https://github.com/ClickHouse/ClickHouse/issues/110114)). The push-down made queries up to 8 times slower when the window reads a `JOIN` and the filter removes every row, for example `IN` over an empty subquery, because the join built its right side before the filter could stop the query. Closes [#123875](https://github.com/ClickHouse/ClickHouse/issues/123875). [#125463](https://github.com/ClickHouse/ClickHouse/pull/125463) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#125789](https://github.com/ClickHouse/ClickHouse/issues/125789): Add S3 bucket to `remote_url_allow_hosts`. [#124453](https://github.com/ClickHouse/ClickHouse/pull/124453) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#125895](https://github.com/ClickHouse/ClickHouse/issues/125895): Reduced the peak memory usage of `RESTORE` and of incremental `BACKUP`: the metadata file of a backup is now parsed while it is read, instead of being read into memory whole first. For backups of millions of files this saves gigabytes. [#125712](https://github.com/ClickHouse/ClickHouse/pull/125712) ([Julia Kartseva](https://github.com/jkartseva)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125799](https://github.com/ClickHouse/ClickHouse/issues/125799): Update the vendored `expat` to 2.9.0, fixing a denial of service through a crafted backup manifest during RESTORE (CVE-2026-66046) and the other 2.8.3–2.9.0 security fixes. [#124255](https://github.com/ClickHouse/ClickHouse/pull/124255) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#125821](https://github.com/ClickHouse/ClickHouse/issues/125821): Fixed loading, short `ATTACH`, and `UNDROP TABLE` for existing SQL-defined S3 disks whose endpoints are absent from `remote_url_allow_hosts`; new full-definition `CREATE` and `ATTACH` still reject disallowed endpoints. [#124930](https://github.com/ClickHouse/ClickHouse/pull/124930) ([Alexey Bakharew](https://github.com/alexbakharew)).
* Backported in [#125834](https://github.com/ClickHouse/ClickHouse/issues/125834): Fixed a stack overflow crash on a deeply nested CapnProto schema that the nesting depth check missed: a comment or a byte order mark between `import` and its path, an escape sequence in the import path, or a backtick text line. A backtick text line with many brackets is no longer rejected as nested too deeply. [#125487](https://github.com/ClickHouse/ClickHouse/pull/125487) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125934](https://github.com/ClickHouse/ClickHouse/issues/125934): Fixed a possible segmentation fault when reading an Avro `map` into a `Map` column (for example `Map(DateTime, String)`) with the `AvroConfluent` format, including Kafka tables. Closes [#125457](https://github.com/ClickHouse/ClickHouse/issues/125457). [#125505](https://github.com/ClickHouse/ClickHouse/pull/125505) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125869](https://github.com/ClickHouse/ClickHouse/issues/125869): Fixed an issue where pressing Ctrl-R and then Ctrl-Z in the web terminal or the SSH interface suspended the whole server process. [#125512](https://github.com/ClickHouse/ClickHouse/pull/125512) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125875](https://github.com/ClickHouse/ClickHouse/issues/125875): Fix a wrong result, or an exception in debug builds, when `optimize_aggregators_of_group_by_keys` eliminated `any`, `min` or `max` of a `GROUPING SETS` key with `group_by_use_nulls`. [#125575](https://github.com/ClickHouse/ClickHouse/pull/125575) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125864](https://github.com/ClickHouse/ClickHouse/issues/125864): Fixed a server crash when a `RabbitMQ` table with the `headers` exchange type had a routing key without `=`, or when `rabbitmq_routing_key_list` was empty. Routing keys without `=` for the `headers` exchange type are now rejected with an exception. The problem was found and reported by @dstesk (https://github.com/dstesk). [#125661](https://github.com/ClickHouse/ClickHouse/pull/125661) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Build/Testing/Packaging Improvement
* Backported in [#125907](https://github.com/ClickHouse/ClickHouse/issues/125907): Update `vectorscan` to 5.4.13. [#125774](https://github.com/ClickHouse/ClickHouse/pull/125774) ([Actuele AI](https://github.com/actueleai)).
