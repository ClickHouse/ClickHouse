# 2026 Changelog

### ClickHouse release v26.9.23.15-stable (8b433c1d42f) FIXME as compared to v26.9.22.3-stable (3aba10ed64f)

#### Performance Improvement
* Backported in [#124275](https://github.com/ClickHouse/ClickHouse/issues/124275): Reduce repeated `IN` evaluation when many adjacent singleton row-mask updates are applied to one part. [#122718](https://github.com/ClickHouse/ClickHouse/pull/122718) ([Sergey Kuznetsov](https://github.com/skuznetsov-clickhouse)).
* Backported in [#126715](https://github.com/ClickHouse/ClickHouse/issues/126715): Estimating subcolumn sizes for `PREWHERE` (for example `m['key']` of a `Map(LowCardinality(String), String)` column) no longer reads the `LowCardinality` dictionary or the `Variant` discriminators header of every data part, which made planning slow on object storage, especially for each new map key. Closes [#114598](https://github.com/ClickHouse/ClickHouse/issues/114598). [#126046](https://github.com/ClickHouse/ClickHouse/pull/126046) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126766](https://github.com/ClickHouse/ClickHouse/issues/126766): `BACKUP` uses less memory per file it backs up: an entry of the backup no longer keeps a copy of the description of the disk the file is on. A backup of a table with millions of files saves a few gigabytes. [#126388](https://github.com/ClickHouse/ClickHouse/pull/126388) ([Julia Kartseva](https://github.com/jkartseva)).

#### Improvement
* Backported in [#126734](https://github.com/ClickHouse/ClickHouse/issues/126734): Fatal error reports no longer contain runtime memory addresses: stack frames and the fault address are printed as offsets inside the executable or a library, which can be passed to `addr2line`, and other addresses are hidden. `system.crash_log.fault_address` now contains the offset inside the executable, or `NULL` when the address is elsewhere. [#126039](https://github.com/ClickHouse/ClickHouse/pull/126039) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#126911](https://github.com/ClickHouse/ClickHouse/issues/126911): A `JOIN` whose `ON` condition has a constant-false conjunct now works with the experimental `parallel_replicas_plan_based` setting when the join uses `grace_hash`, spills to disk, or runs with `join_use_nulls = 1`, instead of terminating the server or failing with `NOT_FOUND_COLUMN_IN_BLOCK`. [#126204](https://github.com/ClickHouse/ClickHouse/pull/126204) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126827](https://github.com/ClickHouse/ClickHouse/issues/126827): Fixed a read of uninitialized memory when a `Variant`, `Dynamic` or `JSON` column holding only `NULL` values is compressed, for example on insert into a `Memory` table created with `compress = 1`, or when a block is compressed for a `JOIN` or for the query result cache. The reported size of such a column was also unspecified. [#120776](https://github.com/ClickHouse/ClickHouse/pull/120776) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126657](https://github.com/ClickHouse/ClickHouse/issues/126657): `BACKUP` and `RESTORE` to S3 retry requests that fail with `ExpiredToken` after refreshing credentials. The retry time limit is 120 seconds by default and can be changed with `backup_s3_expired_token_retry_timeout_ms`. [#123195](https://github.com/ClickHouse/ClickHouse/pull/123195) ([Nikolai Ovchinnikov](https://github.com/kolsha)).
* Backported in [#126732](https://github.com/ClickHouse/ClickHouse/issues/126732): Fixed a server crash (or missing rows in the view, with a `Null` source table) on `INSERT` into the source table of a materialized view when a row policy or `additional_table_filters` of a table read by the view references the source table, e.g. `USING x IN src`. [#125893](https://github.com/ClickHouse/ClickHouse/pull/125893) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126902](https://github.com/ClickHouse/ClickHouse/issues/126902): Fix a segmentation fault in `GROUP BY` with the adaptive aggregator and external aggregation when a memory limit was hit while draining staged records. [#126126](https://github.com/ClickHouse/ClickHouse/pull/126126) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126810](https://github.com/ClickHouse/ClickHouse/issues/126810): Fix segfault when reading a `MySQLDump` file whose `CREATE TABLE` query has an `ENUM` column without a list of values or with non-string values. [#126159](https://github.com/ClickHouse/ClickHouse/pull/126159) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126849](https://github.com/ClickHouse/ClickHouse/issues/126849): Fixed a heap-use-after-free in the view dependency graph after renaming a materialized view whose query selects from itself. `CREATE MATERIALIZED VIEW` and `ALTER TABLE ... MODIFY QUERY` now reject a query that makes a materialized view select from itself. [#126292](https://github.com/ClickHouse/ClickHouse/pull/126292) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126805](https://github.com/ClickHouse/ClickHouse/issues/126805): Fix a stack overflow when a Redis server replies with deeply nested arrays. [#126547](https://github.com/ClickHouse/ClickHouse/pull/126547) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126797](https://github.com/ClickHouse/ClickHouse/issues/126797): Fix a stack overflow on a Protobuf schema with a very long chain of nested messages. [#126550](https://github.com/ClickHouse/ClickHouse/pull/126550) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
