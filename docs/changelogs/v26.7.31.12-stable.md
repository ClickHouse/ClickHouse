# 2026 Changelog

### ClickHouse release v26.7.31.12-stable (467e69f0016) FIXME as compared to v26.7.30.7-stable (b5e66588b74)

#### Improvement
* Backported in [#125788](https://github.com/ClickHouse/ClickHouse/issues/125788): Add S3 bucket to `remote_url_allow_hosts`. [#124453](https://github.com/ClickHouse/ClickHouse/pull/124453) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#125686](https://github.com/ClickHouse/ClickHouse/issues/125686): Fixed a server startup failure after creating an `Alias` table whose target did not exist yet and later became an `Alias` table itself. Such a table was accepted by `CREATE` but rejected while loading metadata, which aborted startup with `BAD_ARGUMENTS`. The `Alias` target restrictions are now applied only to freshly supplied definitions. [#116153](https://github.com/ClickHouse/ClickHouse/pull/116153) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125746](https://github.com/ClickHouse/ClickHouse/issues/125746): Fix `ALTER TABLE ... MATERIALIZE STATISTICS` / `DROP STATISTICS` failing forever and wedging the table's mutation queue when a server profile sets `allow_statistics = 0` and the statement enables it per-session, the same opt-in `ADD STATISTICS` honours. Also close a hole where `MATERIALIZE STATISTICS` ignored `allow_statistics = 0` altogether under `validate_mutation_query = 0`. [#117351](https://github.com/ClickHouse/ClickHouse/pull/117351) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125798](https://github.com/ClickHouse/ClickHouse/issues/125798): Update the vendored `expat` to 2.9.0, fixing a denial of service through a crafted backup manifest during RESTORE (CVE-2026-66046) and the other 2.8.3–2.9.0 security fixes. [#124255](https://github.com/ClickHouse/ClickHouse/pull/124255) ([Actuele AI](https://github.com/actueleai)).
* Backported in [#125820](https://github.com/ClickHouse/ClickHouse/issues/125820): Fixed loading, short `ATTACH`, and `UNDROP TABLE` for existing SQL-defined S3 disks whose endpoints are absent from `remote_url_allow_hosts`; new full-definition `CREATE` and `ATTACH` still reject disallowed endpoints. [#124930](https://github.com/ClickHouse/ClickHouse/pull/124930) ([Alexey Bakharew](https://github.com/alexbakharew)).
* Backported in [#125642](https://github.com/ClickHouse/ClickHouse/issues/125642): Free prefetched messages when StorageKafka2 partitions move between consumers, preventing per-partition memory growth until restart. [#125076](https://github.com/ClickHouse/ClickHouse/pull/125076) ([Aparajita Pandey](https://github.com/aparajita31pandey)).
* Backported in [#125731](https://github.com/ClickHouse/ClickHouse/issues/125731): The web terminal and the SSH interface no longer reset the settings of the user (from settings profiles, roles, and `CREATE USER ... SETTINGS`) to default values. Previously, restrictions such as `readonly`, resource limits, and `additional_table_filters` were not applied in these interfaces. [#125515](https://github.com/ClickHouse/ClickHouse/pull/125515) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125874](https://github.com/ClickHouse/ClickHouse/issues/125874): Fix a wrong result, or an exception in debug builds, when `optimize_aggregators_of_group_by_keys` eliminated `any`, `min` or `max` of a `GROUPING SETS` key with `group_by_use_nulls`. [#125575](https://github.com/ClickHouse/ClickHouse/pull/125575) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#125863](https://github.com/ClickHouse/ClickHouse/issues/125863): Fixed a server crash when a `RabbitMQ` table with the `headers` exchange type had a routing key without `=`, or when `rabbitmq_routing_key_list` was empty. Routing keys without `=` for the `headers` exchange type are now rejected with an exception. The problem was found and reported by @dstesk (https://github.com/dstesk). [#125661](https://github.com/ClickHouse/ClickHouse/pull/125661) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Build/Testing/Packaging Improvement
* Backported in [#125906](https://github.com/ClickHouse/ClickHouse/issues/125906): Update `vectorscan` to 5.4.13. [#125774](https://github.com/ClickHouse/ClickHouse/pull/125774) ([Actuele AI](https://github.com/actueleai)).
