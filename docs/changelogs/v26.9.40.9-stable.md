# 2026 Changelog

### ClickHouse release v26.9.40.9-stable (c1ab490af71) FIXME as compared to v26.9.39.7-stable (5685c755edf)

#### Performance Improvement
* Backported in [#134670](https://github.com/ClickHouse/ClickHouse/issues/134670): Wake idle ThreadPool thread after releasing the pool mutex. [#134433](https://github.com/ClickHouse/ClickHouse/pull/134433) ([Azat Khuzhin](https://github.com/azat)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134639](https://github.com/ClickHouse/ClickHouse/issues/134639): Fixed index analysis for a condition that wraps the primary key in a widening integer cast such as `toInt64` and then applies another monotonic function such as `negate` or `abs`. Such a condition could silently drop matching rows, or fail with `LOGICAL_ERROR: abs's argument does not match the expected data type`. Present since 26.5. [#116699](https://github.com/ClickHouse/ClickHouse/pull/116699) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134566](https://github.com/ClickHouse/ClickHouse/issues/134566): Fixed the Arrow Flight interface returning garbage values for a `MergeTree` column stored in sparse serialization, which is the default for a column that holds mostly default values. Affected `DoGet` with a SQL ticket, `GetFlightInfo` and `PollFlightInfo`. [#125553](https://github.com/ClickHouse/ClickHouse/pull/125553) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134403](https://github.com/ClickHouse/ClickHouse/issues/134403): Fix data loss in other subcolumns of a `Nested` column when a column TTL expires values of one of its subcolumns. [#129438](https://github.com/ClickHouse/ClickHouse/pull/129438) ([Lazizbek Ergashev](https://github.com/lazerg)).
* Backported in [#134449](https://github.com/ClickHouse/ClickHouse/issues/134449): `CREATE`, `ALTER`, `DROP` and `MOVE ROW POLICY ... ON CLUSTER` with a table name without a database now apply to the table in the current database, the one the privileges are checked against. Previously every host applied them to the table with that name in the server's default database. [#130673](https://github.com/ClickHouse/ClickHouse/pull/130673) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134547](https://github.com/ClickHouse/ClickHouse/issues/134547): The `Kafka` table engine no longer accepts `librdkafka` properties that refer to files on the server (for example, `kafka.ssl_ca_location`, `kafka.ssl_key_location`, `kafka.sasl_kerberos_keytab`) from a named collection created with `CREATE NAMED COLLECTION`. Such a table fails with `BAD_ARGUMENTS`, and an existing table stops consuming and producing until the collection is changed. Define the collection in the server configuration file, or pass the contents of the file with the `.pem` properties (for example, `kafka.ssl_ca_pem`). [#132488](https://github.com/ClickHouse/ClickHouse/pull/132488) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Backported in [#134532](https://github.com/ClickHouse/ClickHouse/issues/134532): `ATTACH MATERIALIZED VIEW` with a full definition now validates the `SELECT` query the same way as `CREATE MATERIALIZED VIEW`. [#133025](https://github.com/ClickHouse/ClickHouse/pull/133025) ([Alexander Tokmakov](https://github.com/tavplubix)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#134429](https://github.com/ClickHouse/ClickHouse/issues/134429): When a MergeTree table was created with table_disk=1, it stores all data (parts/tmp files/detached directory) in the root of this disk, and when this table is dropped, dropAllData calls remove-recursive on the root folder. When this table was located on the encrypted disk, this call would, in fact, remove the root folder of that disk. The problem is that if other normal tables (without table_disk) were created there, this call would remove their data as well. [#134192](https://github.com/ClickHouse/ClickHouse/pull/134192) ([Mikhail Artemenko](https://github.com/Michicosun)).
