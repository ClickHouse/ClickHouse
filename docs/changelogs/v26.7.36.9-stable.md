# 2026 Changelog

### ClickHouse release v26.7.36.9-stable (d6f71b56b61) FIXME as compared to v26.7.35.11-stable (9ae877699e9)

#### Performance Improvement
* Backported in [#126935](https://github.com/ClickHouse/ClickHouse/issues/126935): Combine I/O cost with selectivity in PREWHERE condition ordering. It fixes performance regression in PREWHERE execution in some cases introduced after https://github.com/ClickHouse/ClickHouse/pull/101275. Part of [#110462](https://github.com/ClickHouse/ClickHouse/issues/110462). [#110695](https://github.com/ClickHouse/ClickHouse/pull/110695) ([Pavel Kruglov](https://github.com/Avogar)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126709](https://github.com/ClickHouse/ClickHouse/issues/126709): Mask credentials embedded in HTTP URIs. [#120407](https://github.com/ClickHouse/ClickHouse/pull/120407) ([Han Fei](https://github.com/hanfei1991)).
* Backported in [#126404](https://github.com/ClickHouse/ClickHouse/issues/126404): Reject CR and LF characters in values sent as HTTP headers or in the request line of outgoing HTTP requests (BigQuery, YTsaurus, `url`, DataLake catalogs, GCP OAuth, AI functions, S3 storage class), which could be used to inject headers or additional requests. [#124905](https://github.com/ClickHouse/ClickHouse/pull/124905) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#126908](https://github.com/ClickHouse/ClickHouse/issues/126908): Fixed a heap-use-after-free in the view dependency graph after renaming a materialized view whose query selects from itself. `CREATE MATERIALIZED VIEW` and `ALTER TABLE ... MODIFY QUERY` now reject a query that makes a materialized view select from itself. [#126292](https://github.com/ClickHouse/ClickHouse/pull/126292) ([Groene AI](https://github.com/groeneai)).
* Backported in [#127022](https://github.com/ClickHouse/ClickHouse/issues/127022): Fix use-after-free in complex key `ssd_cache` dictionaries when the cache file wraps around its partitions. Fix `CANNOT_READ_ALL_DATA` when reading long values of `ssd_cache` dictionaries from the cache file. [#126553](https://github.com/ClickHouse/ClickHouse/pull/126553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#127073](https://github.com/ClickHouse/ClickHouse/issues/127073): Fixed `count()` with `WHERE d = toDate32('1900-01-01')` (or `!=`) over a MergeTree `Date32` column returning the number of `1970-01-01` rows when `optimize_trivial_count_with_sparsity_filter` is enabled (the default since 26.8). Closes [#126856](https://github.com/ClickHouse/ClickHouse/issues/126856). [#126942](https://github.com/ClickHouse/ClickHouse/pull/126942) ([Groene AI](https://github.com/groeneai)).
