# 2026 Changelog

### ClickHouse release v26.8.30.8-lts (da45179b6c6) FIXME as compared to v26.8.29.10-lts (7b8b36217c6)

#### Improvement
* Backported in [#126381](https://github.com/ClickHouse/ClickHouse/issues/126381): Reduced the memory usage of incremental `BACKUP`: the base backup keeps only the sizes and checksums of its files instead of the full information about each file. For a base backup of millions of files this saves gigabytes. [#125717](https://github.com/ClickHouse/ClickHouse/pull/125717) ([Julia Kartseva](https://github.com/jkartseva)).
* Backported in [#126323](https://github.com/ClickHouse/ClickHouse/issues/126323): Compare TOTP codes and `plaintext_password` passwords in constant time, so that the response time does not depend on how many leading characters are correct or on which time window matched. [#125785](https://github.com/ClickHouse/ClickHouse/pull/125785) ([Vladimir Cherkasov](https://github.com/vdimir)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126331](https://github.com/ClickHouse/ClickHouse/issues/126331): Fix reading dropped column with existing column in data file. Closes [#113324](https://github.com/ClickHouse/ClickHouse/issues/113324). [#116488](https://github.com/ClickHouse/ClickHouse/pull/116488) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#126280](https://github.com/ClickHouse/ClickHouse/issues/126280): Requesting SSH-key authentication over the native protocol no longer reveals whether the named user exists, or how it authenticates, before its signature is checked. [#121704](https://github.com/ClickHouse/ClickHouse/pull/121704) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Backported in [#126400](https://github.com/ClickHouse/ClickHouse/issues/126400): Reject CR and LF characters in values sent as HTTP headers or in the request line of outgoing HTTP requests (BigQuery, YTsaurus, `url`, DataLake catalogs, GCP OAuth, AI functions, S3 storage class), which could be used to inject headers or additional requests. [#124905](https://github.com/ClickHouse/ClickHouse/pull/124905) ([Raúl Marín](https://github.com/Algunenano)).
* Backported in [#126350](https://github.com/ClickHouse/ClickHouse/issues/126350): The setting `http_zlib_compression_level` now applies only to the `gzip` and `deflate` HTTP response compression. The level of other methods (`zstd`, `lz4`, `br`, `xz`, `bz2`) is controlled by `output_format_compression_level`. Previously, a level suitable for zlib was passed to every method, which could make `lz4` unexpectedly slow or make `xz` fail. [#125899](https://github.com/ClickHouse/ClickHouse/pull/125899) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Fixes distributed queries incorrectly disabling the analyzer on shards when a native application reports its own version. Compatibility decisions use the connecting ClickHouse server's version and preserve explicit analyzer choices, including on the first query of a connection. [#125992](https://github.com/ClickHouse/ClickHouse/pull/125992) ([Ye Yuan](https://github.com/Kryst4lskyxx)).
