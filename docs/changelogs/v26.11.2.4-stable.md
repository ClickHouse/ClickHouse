# 2026 Changelog

### ClickHouse release v26.11.2.4-stable (66f7a9f1b34) FIXME as compared to v26.11.1.2942-stable (5a7822635c6)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#134409](https://github.com/ClickHouse/ClickHouse/issues/134409): Fix data loss in other subcolumns of a `Nested` column when a column TTL expires values of one of its subcolumns. [#129438](https://github.com/ClickHouse/ClickHouse/pull/129438) ([Lazizbek Ergashev](https://github.com/lazerg)).
* Backported in [#134232](https://github.com/ClickHouse/ClickHouse/issues/134232): The `Kafka` table engine no longer accepts `librdkafka` properties that refer to files on the server (for example, `kafka.ssl_ca_location`, `kafka.ssl_key_location`, `kafka.sasl_kerberos_keytab`) from a named collection created with `CREATE NAMED COLLECTION`. Such a table fails with `BAD_ARGUMENTS`, and an existing table stops consuming and producing until the collection is changed. Define the collection in the server configuration file, or pass the contents of the file with the `.pem` properties (for example, `kafka.ssl_ca_pem`). [#132488](https://github.com/ClickHouse/ClickHouse/pull/132488) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#134291](https://github.com/ClickHouse/ClickHouse/issues/134291): When a MergeTree table was created with table_disk=1, it stores all data (parts/tmp files/detached directory) in the root of this disk, and when this table is dropped, dropAllData calls remove-recursive on the root folder. When this table was located on the encrypted disk, this call would, in fact, remove the root folder of that disk. The problem is that if other normal tables (without table_disk) were created there, this call would remove their data as well. [#134192](https://github.com/ClickHouse/ClickHouse/pull/134192) ([Mikhail Artemenko](https://github.com/Michicosun)).
