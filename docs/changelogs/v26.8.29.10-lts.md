# 2026 Changelog

### ClickHouse release v26.8.29.10-lts (7b8b36217c6) FIXME as compared to v26.8.28.14-lts (3694fe07040)

#### Backward Incompatible Change
* Backported in [#125982](https://github.com/ClickHouse/ClickHouse/issues/125982): Overriding a key that is stored in a named collection now requires `SHOW NAMED COLLECTIONS SECRETS` on that collection. This also applies to overrides through an alias (including flat `kafka_*` settings over nested `kafka.*` keys), through a `SETTINGS` clause of a table engine or table function, and through keys in a dictionary source (checked when the dictionary is created). Resolving a relative `url` stored in a named collection against `s3_base` or `url_base` also counts as an override of `url`. Adding a key that the collection does not store remains allowed, and keys marked `NOT OVERRIDABLE` cannot be overridden. The `allow_named_collection_override_by_default` setting is obsolete. Existing tables whose `SETTINGS` or alias arguments override a `NOT OVERRIDABLE` key cannot be loaded after the upgrade, and the server does not start: before upgrading, recreate such tables without the override, or make the key overridable. [#123133](https://github.com/ClickHouse/ClickHouse/pull/123133) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

#### Improvement
* Backported in [#126089](https://github.com/ClickHouse/ClickHouse/issues/126089): A packet that cannot appear at the current point of the native protocol is now rejected without deserializing its payload. Previously the server deserialized the body of an unexpected `Data` packet — including arbitrary data types and aggregate function states — only to throw `UNEXPECTED_PACKET_FROM_CLIENT` and close the connection. [#119368](https://github.com/ClickHouse/ClickHouse/pull/119368) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126051](https://github.com/ClickHouse/ClickHouse/issues/126051): Fixed a crash caused by a stack overflow when a deeply nested JSON document was parsed into a `JSON` column or passed to the `JSONExtract` family of functions. Such documents are now rejected with the `TOO_DEEP_RECURSION` error. [#120887](https://github.com/ClickHouse/ClickHouse/pull/120887) ([Pavel Kruglov](https://github.com/Avogar)).
* Backported in [#126093](https://github.com/ClickHouse/ClickHouse/issues/126093): Fix a server crash when a `RIGHT JOIN`/`FULL JOIN` is planned for parallel replicas (`parallel_replicas_plan_based=1`) and the join output header declares a column by type only — e.g. the residual column of a constant `NULL` conjunct in the `ON` clause. Type-only header columns are now materialized as an empty column of the declared type instead of being dereferenced as null. [#122128](https://github.com/ClickHouse/ClickHouse/pull/122128) ([Ilias](https://github.com/iliasabk)).
* Backported in [#126000](https://github.com/ClickHouse/ClickHouse/issues/126000): Fixed `CANNOT_READ_ALL_DATA` (`while reading prefix of column ...`) during query planning when a `MergeTree` table has an active empty Wide part, left by a TTL drop or by a mutation that deleted all rows of a part, and the query filters on a subcolumn, such as a key of a `Map(LowCardinality(String), String)` column. [#122756](https://github.com/ClickHouse/ClickHouse/pull/122756) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126237](https://github.com/ClickHouse/ClickHouse/issues/126237): Fixed `ORDER BY ... LIMIT` over a column of an `Interval` type (or `Nullable`, `LowCardinality`, `Tuple` or `Array` of one) failing with `TYPE_MISMATCH` when `use_top_k_dynamic_filtering` is enabled, which is the default. Closes [#125197](https://github.com/ClickHouse/ClickHouse/issues/125197). [#125221](https://github.com/ClickHouse/ClickHouse/pull/125221) ([Groene AI](https://github.com/groeneai)).
* Backported in [#125998](https://github.com/ClickHouse/ClickHouse/issues/125998): Allow to do vertical merge if result part storage type is not Full. [#125760](https://github.com/ClickHouse/ClickHouse/pull/125760) ([alesapin](https://github.com/alesapin)).
* Backported in [#126069](https://github.com/ClickHouse/ClickHouse/issues/126069): Fixed a crash (stack overflow) on a CapnProto schema with a long chain of type expression suffixes (`Int32.a.a...`, `Int32()()...`) or of declarations that refer to each other (constants, aliases, struct fields, annotations, imports). Such a schema is now rejected with `The CapnProto schema is nested too deeply`. Closes [#125782](https://github.com/ClickHouse/ClickHouse/issues/125782). [#125900](https://github.com/ClickHouse/ClickHouse/pull/125900) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126114](https://github.com/ClickHouse/ClickHouse/issues/126114): Fixed `Reading in parallel from replicas is enabled but cluster to execute query is not provided` (`CLUSTER_DOESNT_EXIST`) when selecting from a `Distributed` table whose cluster is not declared in `remote_servers` - the cluster of a `Replicated` database, or one found by cluster discovery - with parallel replicas enabled. [#126032](https://github.com/ClickHouse/ClickHouse/pull/126032) ([Igor Nikonov](https://github.com/devcrafter)).
