# 2026 Changelog

### ClickHouse release v26.8.19.9-lts (2ea9c3c9e37) FIXME as compared to v26.8.18.2-lts (9f84259255b)

#### Improvement
* Backported in [#124172](https://github.com/ClickHouse/ClickHouse/issues/124172): Filesystem cache: make reserve granularity dynamic. [#123255](https://github.com/ClickHouse/ClickHouse/pull/123255) ([Kseniia Sumarokova](https://github.com/kssenii)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124130](https://github.com/ClickHouse/ClickHouse/issues/124130): Fixed a `text` index dropping matching rows when a `FixedString` is involved in the comparison: a term-preserving tokenizer over a `String` column lost the rows whose value carries literal trailing zero bytes when the search constant is a `FixedString`, and an index over a `FixedString` column lost all matching rows for a `String` constant or a `FixedString` constant of another width. [#118972](https://github.com/ClickHouse/ClickHouse/pull/118972) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#124089](https://github.com/ClickHouse/ClickHouse/issues/124089): Fix `basic` statistics of parts written by 26.6 or 26.7: after `ALTER TABLE ... UPDATE` or a lightweight `DELETE`, non-`Nullable` columns reported a default-value count of 0, which made selectivity estimates wrong. Query results were not affected. To repair parts that are already affected, run `ALTER TABLE ... MATERIALIZE STATISTICS ALL`. [#123536](https://github.com/ClickHouse/ClickHouse/pull/123536) ([Samuel Krempaský](https://github.com/NIKTONIKTO717)).
* Backported in [#124061](https://github.com/ClickHouse/ClickHouse/issues/124061): Fix a possible hang of a query under workload CPU scheduling with `cpu_slot_preemption` enabled: when all its threads were preempted, the query could keep CPU slots it had already used and wait forever for one of them. [#123640](https://github.com/ClickHouse/ClickHouse/pull/123640) ([Sergei Trifonov](https://github.com/serxa)).
* Backported in [#124009](https://github.com/ClickHouse/ClickHouse/issues/124009): Fixed a `LEFT`/`RIGHT`/`FULL JOIN` without an equality key that failed with `INVALID_JOIN_ON_EXPRESSION` (`Cannot determine join keys`) when its `WHERE` clause also contained an `IN (subquery)`. The `WHERE` filter now converts such a join to `INNER` again, as it did in 26.6, which also restores that optimization for joins with equality keys. [#123792](https://github.com/ClickHouse/ClickHouse/pull/123792) ([Groene AI](https://github.com/groeneai)).
* Backported in [#123988](https://github.com/ClickHouse/ClickHouse/issues/123988): Fixed a segmentation fault or `std::length_error` when reading `TSV` formats with `input_format_tsv_crlf_end_of_line = 1` if an escape sequence ended exactly at the end of a read buffer. [#123861](https://github.com/ClickHouse/ClickHouse/pull/123861) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124162](https://github.com/ClickHouse/ClickHouse/issues/124162): Respect `iceberg_metadata_staleness_ms` in metadata parsing. [#124113](https://github.com/ClickHouse/ClickHouse/pull/124113) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Revert backport of [#116335](https://github.com/ClickHouse/ClickHouse/issues/116335) to 26.8: Check for timeouts and KILL QUERY while covering a polygon with H3 cells. [#124013](https://github.com/ClickHouse/ClickHouse/pull/124013) ([Nikita Fomichev](https://github.com/fm4v)).
