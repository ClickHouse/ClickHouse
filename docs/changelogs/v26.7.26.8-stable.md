# 2026 Changelog

### ClickHouse release v26.7.26.8-stable (ea8639da481) FIXME as compared to v26.7.25.6-stable (062f1949e4f)

#### Improvement
* Backported in [#124615](https://github.com/ClickHouse/ClickHouse/issues/124615): `bloom_filter` and text indexes are now used when a `Nullable` indexed column is cast to the non-`Nullable` type, such as `CAST(x, 'String')` or `json.path::String`. A query that would throw on a NULL value may not throw when the index skips the granules with NULL. [#124220](https://github.com/ClickHouse/ClickHouse/pull/124220) ([Anton Popov](https://github.com/CurtizJ)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124723](https://github.com/ClickHouse/ClickHouse/issues/124723): Fixed `Expected UInt64 column for __grouping_set, got BLOB` and `ColumnBLOB should be converted to a regular column before usage` logical errors on a distributed query executed on a shard with `enable_parallel_blocks_marshalling` (enabled by default), for example with `GROUP BY GROUPING SETS` over a cluster that has a local replica, or when reading a `Merge` table that spans a local and a distributed table. `BlocksMarshallingStep` is no longer added to plans whose blocks are consumed in the same process. [#111997](https://github.com/ClickHouse/ClickHouse/pull/111997) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124889](https://github.com/ClickHouse/ClickHouse/issues/124889): Fixes `DeltaLake` tables returning too few rows when the `WHERE` predicate contains a sub-expression the delta-kernel predicate translator cannot handle, positioned under a `NOT`. Such a sub-expression is now reported to delta-kernel as an explicit unknown predicate instead of as the end of the child iterator, which used to silently truncate the enclosing conjunction. [#112652](https://github.com/ClickHouse/ClickHouse/pull/112652) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124248](https://github.com/ClickHouse/ClickHouse/issues/124248): Fix `EXPLAIN PLAN actions = 1` printing a secret function argument (for example the key of `HMAC` or `encrypt`) in cleartext when its value came from a subquery or from the other side of a JOIN. [#120371](https://github.com/ClickHouse/ClickHouse/pull/120371) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#124247](https://github.com/ClickHouse/ClickHouse/issues/124247): Comparing an `Enum` column with a string literal that is not one of its elements no longer throws `UNKNOWN_ELEMENT_OF_ENUM` when `validate_enum_literals_in_operators` is disabled (the default) and the column is part of the primary key, the partition key, or a `bloom_filter` index. `!=` with such a literal now returns true for every row instead of throwing. Closes [#122235](https://github.com/ClickHouse/ClickHouse/issues/122235), [#111545](https://github.com/ClickHouse/ClickHouse/issues/111545). [#122672](https://github.com/ClickHouse/ClickHouse/pull/122672) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#124687](https://github.com/ClickHouse/ClickHouse/issues/124687): Fix a rare server crash (`SIGSEGV` in `mongoc_log`) when a MongoDB dictionary source or `MongoDB` table was created while another thread created the first MongoDB connection in the process. Messages logged by the MongoDB driver now go to the server log. [#124235](https://github.com/ClickHouse/ClickHouse/pull/124235) ([Vladimir Cherkasov](https://github.com/vdimir)).

#### NOT FOR CHANGELOG / INSIGNIFICANT
