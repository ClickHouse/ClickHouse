# 2026 Changelog

### ClickHouse release v26.3.66.4-lts (20beaefbaee) FIXME as compared to v26.3.65.10-lts (7c5a986fec0)

#### Improvement
* Backported in [#132043](https://github.com/ClickHouse/ClickHouse/issues/132043): `ReplicatedMergeTree` now removes old deduplication blocks from Keeper in batches of `TryRemove` requests instead of one `Remove` request per block. This reduces the number of Raft entries in Keeper for tables with many replicas. [#128645](https://github.com/ClickHouse/ClickHouse/pull/128645) ([Antonio Andelic](https://github.com/antonio2368)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#131986](https://github.com/ClickHouse/ClickHouse/issues/131986): With `analyzer_compatibility_join_using_top_level_identifier = 1`, a `JOIN USING` identifier is resolved from an alias of the query only for the outermost `JOIN`; an inner `JOIN` of a query with several joins resolves it from its left table, as the old analyzer did. This fixes `UNKNOWN_IDENTIFIER` for queries such as `SELECT if(m.symbol = '', b.symbol, m.symbol) AS symbol FROM m FULL JOIN b USING (symbol) FULL JOIN dttm ON 1 = 1`, and a `USING clause expected identifier` error when an inner `USING` join is placed below an aliased outermost `USING` key. [#123103](https://github.com/ClickHouse/ClickHouse/pull/123103) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Backported in [#131352](https://github.com/ClickHouse/ClickHouse/issues/131352): Fixed a Keeper crash when a client sends `CheckWatch` with an unknown watch type. Such requests now get `ZBADARGUMENTS`. [#130755](https://github.com/ClickHouse/ClickHouse/pull/130755) ([Samuel Krempaský](https://github.com/NIKTONIKTO717)).
