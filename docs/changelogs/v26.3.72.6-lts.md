# 2026 Changelog

### ClickHouse release v26.3.72.6-lts (a587d4a24dd) FIXME as compared to v26.3.71.3-lts (7100b1a7cf9)

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#133791](https://github.com/ClickHouse/ClickHouse/issues/133791): Fixed a table with the `keeper_path` of another `S3Queue` or `AzureQueue` making it delete, move or tag its source files. The source must now match, and these actions need the `WRITE` grant. [#129383](https://github.com/ClickHouse/ClickHouse/pull/129383) ([Samuel Krempaský](https://github.com/NIKTONIKTO717)).
* Backported in [#134392](https://github.com/ClickHouse/ClickHouse/issues/134392): Fix data loss in other subcolumns of a `Nested` column when a column TTL expires values of one of its subcolumns. [#129438](https://github.com/ClickHouse/ClickHouse/pull/129438) ([Lazizbek Ergashev](https://github.com/lazerg)).
* Backported in [#133563](https://github.com/ClickHouse/ClickHouse/issues/133563): Fixed connecting over the native protocol (`clickhouse-client`, `remote`, `Distributed` without an interserver `secret`) to an older server whose settings profile has a negative or overflowing value of a `Seconds` setting, for example `max_execution_time = -1`: the connection failed with `A setting's value in seconds cannot be negative`. Such a value sent by the server is now skipped with a warning. [#131636](https://github.com/ClickHouse/ClickHouse/pull/131636) ([Groene AI](https://github.com/groeneai)).
* Backported in [#134364](https://github.com/ClickHouse/ClickHouse/issues/134364): Fixed JSON schema inference that, depending on memory reuse, could reject valid input with `TYPE_MISMATCH` (for example `{"x":0}`, `{"x":-1}`, `{"y":1}`, `{"y":18446744073709551615}` in `JSONEachRow`) or infer a wrong type such as `Array(Dynamic)` instead of `Array(Nullable(UInt64))`. It also infers `String` instead of failing for JSON strings that mix `Int64` and larger integers with non-numeric text (with `input_format_json_try_infer_numbers_from_strings = 1` and `input_format_json_read_numbers_as_strings = 0`). [#133506](https://github.com/ClickHouse/ClickHouse/pull/133506) ([Groene AI](https://github.com/groeneai)).
* Backported in [#133902](https://github.com/ClickHouse/ClickHouse/issues/133902): Fix a crash and incorrect results in the `CapnProto` format when the schema contains groups or named unions declared inline in a struct (`g :group { ... }`, `u :union { ... }`). [#133530](https://github.com/ClickHouse/ClickHouse/pull/133530) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
