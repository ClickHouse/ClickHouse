# 2026 Changelog

### ClickHouse release v26.8.21.10-lts (e9b8ef33ed7) FIXME as compared to v26.8.20.9-lts (68170c6e704)

#### Performance Improvement
* Backported in [#124242](https://github.com/ClickHouse/ClickHouse/issues/124242): A `WHERE` that no row passes is pushed to every `JOIN` input again, including the non-preserved side of an `OUTER JOIN` and a side with no column used above the join, so that input is no longer read and hash-built for nothing. For example, a `UNION ALL` branch whose constant column fails the outer `WHERE` is skipped as in 26.6. Closes [#123702](https://github.com/ClickHouse/ClickHouse/issues/123702), closes [#123878](https://github.com/ClickHouse/ClickHouse/issues/123878). [#123829](https://github.com/ClickHouse/ClickHouse/pull/123829) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124559](https://github.com/ClickHouse/ClickHouse/issues/124559): Hash joins with many matches per key are faster when they output a `LowCardinality` column whose blocks have different dictionaries (several parts, `FINAL`, or a `LowCardinality` value computed per block): short ranges from another dictionary are now inserted key by key instead of through temporary columns. Such joins run 4-9x faster, at the 26.6 level or better. [#123900](https://github.com/ClickHouse/ClickHouse/pull/123900) ([Groene AI](https://github.com/groeneai)).

#### Improvement
* Backported in [#124445](https://github.com/ClickHouse/ClickHouse/issues/124445): Added the setting `query_plan_filter_push_down_below_limit_by` (default `1`), controlling whether filters on `LIMIT BY` key columns are pushed below the `LIMIT BY` step. Setting it to `0` restores the plan shape used before 26.7, for queries where the pushed predicate makes index analysis costlier than the scan it saves. [#121675](https://github.com/ClickHouse/ClickHouse/pull/121675) ([Groene AI](https://github.com/groeneai)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#124415](https://github.com/ClickHouse/ClickHouse/issues/124415): Mask secrets in the queries that a cluster-mode `QueryRunner` table writes to `system.query_log` as well as in queries executed as startup scripts. [#118978](https://github.com/ClickHouse/ClickHouse/pull/118978) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Backported in [#124478](https://github.com/ClickHouse/ClickHouse/issues/124478): Fixed a standalone `UPDATE ... SET` reading the wrong table when a mutation expression names a table that a same-named `WITH` element hides, but which the subquery does not see because its own `SETTINGS` clause disables `enable_global_with_statement`. Such a name is a table name, and it is now resolved in the database of the updated table instead of the database of the session, so the statement no longer silently updates from a different table or fails with `UNKNOWN_TABLE`. [#119630](https://github.com/ClickHouse/ClickHouse/pull/119630) ([Groene AI](https://github.com/groeneai)).
* Backported in [#124515](https://github.com/ClickHouse/ClickHouse/issues/124515): Tables in a database with `lazy_load_tables` were missing from `system.parts`, `system.replicas` and related system tables, and refused by replica commands, after a restart. [#121332](https://github.com/ClickHouse/ClickHouse/pull/121332) ([Nikolay Degterinsky](https://github.com/evillique)).
* Backported in [#124399](https://github.com/ClickHouse/ClickHouse/issues/124399): Fix a server abort when reading an Iceberg table whose sort order names a transform ClickHouse cannot parse (e.g. `bucket[xyz]`); ClickHouse now ignores that sort-order hint and keeps the table readable. [#121687](https://github.com/ClickHouse/ClickHouse/pull/121687) ([Ilias](https://github.com/iliasabk)).
* Fix excessive memory usage of `SELECT DISTINCT` when its result is buffered by the next step, for example on the left side of a `JOIN` or in `INSERT ... SELECT DISTINCT`: each output block kept the memory of its whole input block, so memory grew with the input instead of with the number of distinct rows. [#124588](https://github.com/ClickHouse/ClickHouse/pull/124588) ([Nihal Z. Miaji](https://github.com/nihalzp)).
