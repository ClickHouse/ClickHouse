# 2026 Changelog

### ClickHouse release v26.8.32.14-lts (dc83db6f660) FIXME as compared to v26.8.31.2-lts (bb452427e21)

#### Backward Incompatible Change
* Backported in [#126498](https://github.com/ClickHouse/ClickHouse/issues/126498): `CREATE TABLE x AS src` inherits the credentials embedded in the engine of `src`, which are masked in `SHOW CREATE TABLE`. It now requires the `SELECT` privilege on `src` when the inherited definition can carry credentials, instead of only `SHOW COLUMNS`. [#118866](https://github.com/ClickHouse/ClickHouse/pull/118866) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Performance Improvement
* Backported in [#124274](https://github.com/ClickHouse/ClickHouse/issues/124274): Reduce repeated `IN` evaluation when many adjacent singleton row-mask updates are applied to one part. [#122718](https://github.com/ClickHouse/ClickHouse/pull/122718) ([Sergey Kuznetsov](https://github.com/skuznetsov-clickhouse)).
* Backported in [#126714](https://github.com/ClickHouse/ClickHouse/issues/126714): Estimating subcolumn sizes for `PREWHERE` (for example `m['key']` of a `Map(LowCardinality(String), String)` column) no longer reads the `LowCardinality` dictionary or the `Variant` discriminators header of every data part, which made planning slow on object storage, especially for each new map key. Closes [#114598](https://github.com/ClickHouse/ClickHouse/issues/114598). [#126046](https://github.com/ClickHouse/ClickHouse/pull/126046) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126764](https://github.com/ClickHouse/ClickHouse/issues/126764): `BACKUP` uses less memory per file it backs up: an entry of the backup no longer keeps a copy of the description of the disk the file is on. A backup of a table with millions of files saves a few gigabytes. [#126388](https://github.com/ClickHouse/ClickHouse/pull/126388) ([Julia Kartseva](https://github.com/jkartseva)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126675](https://github.com/ClickHouse/ClickHouse/issues/126675): Fixed a server crash and an out-of-bounds write when inserting into a column with a long chain of compression codecs, for example `CODEC(FPC, FPC, ..., FPC)`. `CompressionCodecMultiple` compounded each stage's reserved size in a `UInt32` without checking for overflow, so a long enough chain wrapped the reserved size below its own input and the destination buffer was then sized from the wrapped value while the real payload kept growing. Such a chain is now rejected with `CANNOT_COMPRESS`. A chain of more than 255 codecs, which used to write a part that could not be read back, is now rejected with `BAD_ARGUMENTS` when the codec is created, unless `allow_suspicious_codecs` is set. `ALTER TABLE ... MODIFY COLUMN x CODEC(...)` with the type omitted used to validate the codec against no type at all, skipping every check that needs the column width, and now validates against the column's existing type, which flips some verdicts in both directions under the default `allow_suspicious_codecs = 0`. Tables created earlier are unaffected. [#113877](https://github.com/ClickHouse/ClickHouse/pull/113877) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126825](https://github.com/ClickHouse/ClickHouse/issues/126825): Fixed a read of uninitialized memory when a `Variant`, `Dynamic` or `JSON` column holding only `NULL` values is compressed, for example on insert into a `Memory` table created with `compress = 1`, or when a block is compressed for a `JOIN` or for the query result cache. The reported size of such a column was also unspecified. [#120776](https://github.com/ClickHouse/ClickHouse/pull/120776) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126656](https://github.com/ClickHouse/ClickHouse/issues/126656): `BACKUP` and `RESTORE` to S3 retry requests that fail with `ExpiredToken` after refreshing credentials. The retry time limit is 120 seconds by default and can be changed with `backup_s3_expired_token_retry_timeout_ms`. [#123195](https://github.com/ClickHouse/ClickHouse/pull/123195) ([Nikolai Ovchinnikov](https://github.com/kolsha)).
* Backported in [#126731](https://github.com/ClickHouse/ClickHouse/issues/126731): Fixed a server crash (or missing rows in the view, with a `Null` source table) on `INSERT` into the source table of a materialized view when a row policy or `additional_table_filters` of a table read by the view references the source table, e.g. `USING x IN src`. [#125893](https://github.com/ClickHouse/ClickHouse/pull/125893) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126900](https://github.com/ClickHouse/ClickHouse/issues/126900): Fix a segmentation fault in `GROUP BY` with the adaptive aggregator and external aggregation when a memory limit was hit while draining staged records. [#126126](https://github.com/ClickHouse/ClickHouse/pull/126126) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126809](https://github.com/ClickHouse/ClickHouse/issues/126809): Fix segfault when reading a `MySQLDump` file whose `CREATE TABLE` query has an `ENUM` column without a list of values or with non-string values. [#126159](https://github.com/ClickHouse/ClickHouse/pull/126159) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126804](https://github.com/ClickHouse/ClickHouse/issues/126804): Fix a stack overflow when a Redis server replies with deeply nested arrays. [#126547](https://github.com/ClickHouse/ClickHouse/pull/126547) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126796](https://github.com/ClickHouse/ClickHouse/issues/126796): Fix a stack overflow on a Protobuf schema with a very long chain of nested messages. [#126550](https://github.com/ClickHouse/ClickHouse/pull/126550) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
