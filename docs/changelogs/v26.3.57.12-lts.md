# 2026 Changelog

### ClickHouse release v26.3.57.12-lts (ec42a9e6311) FIXME as compared to v26.3.56.2-lts (ff8f6efef42)

#### Backward Incompatible Change
* Backported in [#126496](https://github.com/ClickHouse/ClickHouse/issues/126496): `CREATE TABLE x AS src` inherits the credentials embedded in the engine of `src`, which are masked in `SHOW CREATE TABLE`. It now requires the `SELECT` privilege on `src` when the inherited definition can carry credentials, instead of only `SHOW COLUMNS`. [#118866](https://github.com/ClickHouse/ClickHouse/pull/118866) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

#### Improvement
* Backported in [#126717](https://github.com/ClickHouse/ClickHouse/issues/126717): Compare TOTP codes and `plaintext_password` passwords in constant time, so that the response time does not depend on how many leading characters are correct or on which time window matched. [#125785](https://github.com/ClickHouse/ClickHouse/pull/125785) ([Vladimir Cherkasov](https://github.com/vdimir)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#126726](https://github.com/ClickHouse/ClickHouse/issues/126726): Fixed a server crash and an out-of-bounds write when inserting into a column with a long chain of compression codecs, for example `CODEC(FPC, FPC, ..., FPC)`. `CompressionCodecMultiple` compounded each stage's reserved size in a `UInt32` without checking for overflow, so a long enough chain wrapped the reserved size below its own input and the destination buffer was then sized from the wrapped value while the real payload kept growing. Such a chain is now rejected with `CANNOT_COMPRESS`. A chain of more than 255 codecs, which used to write a part that could not be read back, is now rejected with `BAD_ARGUMENTS` when the codec is created, unless `allow_suspicious_codecs` is set. `ALTER TABLE ... MODIFY COLUMN x CODEC(...)` with the type omitted used to validate the codec against no type at all, skipping every check that needs the column width, and now validates against the column's existing type, which flips some verdicts in both directions under the default `allow_suspicious_codecs = 0`. Tables created earlier are unaffected. [#113877](https://github.com/ClickHouse/ClickHouse/pull/113877) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126823](https://github.com/ClickHouse/ClickHouse/issues/126823): Fixed a read of uninitialized memory when a `Variant`, `Dynamic` or `JSON` column holding only `NULL` values is compressed, for example on insert into a `Memory` table created with `compress = 1`, or when a block is compressed for a `JOIN` or for the query result cache. The reported size of such a column was also unspecified. [#120776](https://github.com/ClickHouse/ClickHouse/pull/120776) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126240](https://github.com/ClickHouse/ClickHouse/issues/126240): Fixed `ORDER BY ... LIMIT` over a column of an `Interval` type (or `Nullable`, `LowCardinality`, `Tuple` or `Array` of one) failing with `TYPE_MISMATCH` when `use_top_k_dynamic_filtering` is enabled, which is the default. Closes [#125197](https://github.com/ClickHouse/ClickHouse/issues/125197). [#125221](https://github.com/ClickHouse/ClickHouse/pull/125221) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126729](https://github.com/ClickHouse/ClickHouse/issues/126729): Fixed a server crash (or missing rows in the view, with a `Null` source table) on `INSERT` into the source table of a materialized view when a row policy or `additional_table_filters` of a table read by the view references the source table, e.g. `USING x IN src`. [#125893](https://github.com/ClickHouse/ClickHouse/pull/125893) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126719](https://github.com/ClickHouse/ClickHouse/issues/126719): Fixed crashes of the interactive line editor of `clickhouse-client` and `clickhouse-local`, which also crashed the server when used through the web terminal or an SSH session: after a history search that found nothing on an edited recalled query, when the prompt or the line given to an Alt-R history search contained a tab, when leaving a history search with a double-width character in the prompt (for example in the server's `display_name`), and on Ctrl-W or Alt-. after some non-ASCII characters. Closes [#126008](https://github.com/ClickHouse/ClickHouse/issues/126008). [#126120](https://github.com/ClickHouse/ClickHouse/pull/126120) ([Groene AI](https://github.com/groeneai)).
* Backported in [#126807](https://github.com/ClickHouse/ClickHouse/issues/126807): Fix segfault when reading a `MySQLDump` file whose `CREATE TABLE` query has an `ENUM` column without a list of values or with non-string values. [#126159](https://github.com/ClickHouse/ClickHouse/pull/126159) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126802](https://github.com/ClickHouse/ClickHouse/issues/126802): Fix a stack overflow when a Redis server replies with deeply nested arrays. [#126547](https://github.com/ClickHouse/ClickHouse/pull/126547) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#126794](https://github.com/ClickHouse/ClickHouse/issues/126794): Fix a stack overflow on a Protobuf schema with a very long chain of nested messages. [#126550](https://github.com/ClickHouse/ClickHouse/pull/126550) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
