# 2026 Changelog

### ClickHouse release v26.6.6.15-stable (36f312a89ae) FIXME as compared to v26.6.5.120-stable (ec30b12c0a5)

#### Experimental Feature
* Backported in [#118813](https://github.com/ClickHouse/ClickHouse/issues/118813): Fix duplicated `GROUP BY` keys in the partial aggregation strategy of `make_distributed_plan`, and allow this strategy for aggregations over a distributed read. [#114523](https://github.com/ClickHouse/ClickHouse/pull/114523) ([Alexander Gololobov](https://github.com/davenger)).

#### Improvement
* Backported in [#119339](https://github.com/ClickHouse/ClickHouse/issues/119339): Support parallel replicas for object storage writes. [#119214](https://github.com/ClickHouse/ClickHouse/pull/119214) ([Konstantin Vedernikov](https://github.com/scanhex12)).

#### Bug Fix (user-visible misbehavior in an official stable release)
* Backported in [#119003](https://github.com/ClickHouse/ClickHouse/issues/119003): Fixes silent data loss for TTL expressions that apply large intervals directly to `Date` / `DateTime` source columns by widening the arithmetic away from 16/32-bit overflow. [#101793](https://github.com/ClickHouse/ClickHouse/pull/101793) ([BoloniniD](https://github.com/BoloniniD)).
* Backported in [#114433](https://github.com/ClickHouse/ClickHouse/issues/114433): Restrict local object access only for user files path. Continuation of https://github.com/ClickHouse/ClickHouse/pull/99405. [#111483](https://github.com/ClickHouse/ClickHouse/pull/111483) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#119876](https://github.com/ClickHouse/ClickHouse/issues/119876): Fixed a crash when reading a subcolumn of a `Variant`, `Dynamic` or `JSON` column whose own type is `Nullable` or `LowCardinality(Nullable)` from a `MergeTree` table, for example ``SELECT value.`Tuple(a Nullable(UInt32), b String)`.a`` over a `Dynamic` column. Previously such a read hit a `LOGICAL_ERROR` in debug builds and crashed in release builds. [#112338](https://github.com/ClickHouse/ClickHouse/pull/112338) ([Groene AI](https://github.com/groeneai)).
* Backported in [#116019](https://github.com/ClickHouse/ClickHouse/issues/116019): Fixed `LOGICAL_ERROR: Unexpected return type from tuple. Expected Tuple(..., UInt8). Got Tuple(..., LowCardinality(UInt8))` when a `LowCardinality` column compared with `IN (subquery)` is read through `tuple(...)` across a subquery boundary and `enable_analyzer = 0`. With the old analyzer, `x IN (subquery)` over a `LowCardinality` column now returns `LowCardinality(UInt8)`, the same type as `x IN (literal list)` and the same as with `enable_analyzer = 1`. [#114856](https://github.com/ClickHouse/ClickHouse/pull/114856) ([Nikita Fomichev](https://github.com/fm4v)).
* Backported in [#115203](https://github.com/ClickHouse/ClickHouse/issues/115203): Fixes a server abort that happens when the global thread pool is momentarily saturated while tables are still loading. `AsyncLoader` now keeps running if it cannot spawn an extra loader worker and some worker will still drain the queued jobs, instead of calling `std::terminate`. [#114897](https://github.com/ClickHouse/ClickHouse/pull/114897) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119667](https://github.com/ClickHouse/ClickHouse/issues/119667): Fixes a server abort in debug and sanitizer builds when inserting into a materialized view whose `TO` target is another materialized view. Such an insert already failed on released versions, with an uninformative `Code: 1001 STD_EXCEPTION`; it now reports `NOT_IMPLEMENTED` naming the offending view. [#115985](https://github.com/ClickHouse/ClickHouse/pull/115985) ([Groene AI](https://github.com/groeneai)).
* Backported in [#118838](https://github.com/ClickHouse/ClickHouse/issues/118838): Fix partition pruning and primary key filtering being silently disabled when `parallel_replicas_min_number_of_rows_per_replica` is set inside a subquery or CTE instead of at top query level. [#116529](https://github.com/ClickHouse/ClickHouse/pull/116529) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Backported in [#119689](https://github.com/ClickHouse/ClickHouse/issues/119689): Fixed a server that refused to start after the directory backing a `Filesystem` database had been removed. Such a database is now loaded without tables and can be inspected and dropped, while a `CREATE DATABASE` or `ATTACH DATABASE` issued by a user is still rejected when the path does not exist. [#118684](https://github.com/ClickHouse/ClickHouse/pull/118684) ([Groene AI](https://github.com/groeneai)).
* Backported in [#119417](https://github.com/ClickHouse/ClickHouse/issues/119417): Don't use backoffs on concurrent inserts conflicts (when we use Iceberg + catalog, for example). [#119238](https://github.com/ClickHouse/ClickHouse/pull/119238) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Backported in [#119795](https://github.com/ClickHouse/ClickHouse/issues/119795): Fixed a stack buffer overflow when reading a `BIT` column from MySQL, reachable through the `mysql` table function, the `MySQL` table and database engines, and MySQL dictionaries. The length of the value sent by the server was copied without being validated. [#119680](https://github.com/ClickHouse/ClickHouse/pull/119680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

#### NOT FOR CHANGELOG / INSIGNIFICANT

* Backported in [#119826](https://github.com/ClickHouse/ClickHouse/issues/119826): Make the 04780 index-analysis allocation oracle the minimum of several runs. [#114608](https://github.com/ClickHouse/ClickHouse/pull/114608) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Backported in [#119756](https://github.com/ClickHouse/ClickHouse/issues/119756): Do not leave a `Filesystem` database pointing at a removed directory, which makes the server refuse to start. [#119618](https://github.com/ClickHouse/ClickHouse/pull/119618) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
