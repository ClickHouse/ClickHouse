ClickStack поддерживает визуализацию событий со встроенной возможностью построения диаграмм в интерфейсе ClickStack. Эти диаграммы можно добавлять на панели мониторинга, чтобы открывать к ним общий доступ для других пользователей.

Визуализации можно создавать на основе трассировок, метрик, журналов или любых схем широких событий, определяемых пользователем.

## Создание визуализаций {#creating-visualizations}

Интерфейс **Chart Explorer** в интерфейсе ClickStack позволяет визуализировать метрики, трассировки и журналы с течением времени, упрощая создание быстрых визуализаций для анализа данных. Этот интерфейс также используется при создании панелей мониторинга. В следующем разделе пошагово показано, как создать визуализацию с помощью Chart Explorer.

Создание любой визуализации начинается с выбора **источника данных**, затем **метрики**, а при необходимости — **выражений фильтрации** и полей **группировки**. По сути, визуализации в интерфейсе ClickStack соответствуют SQL-запросу с `GROUP BY`: вы задаёте метрики для агрегации по выбранным измерениям.

<Tip>
  **Генерация диаграмм с помощью ИИ**

  ClickStack также поддерживает создание диаграмм из промптов на естественном языке с помощью возможности [text-to-chart](/ru/clickstack/text-to-chart). Опишите, что вы хотите увидеть, и ClickStack автоматически сгенерирует визуализацию.
</Tip>

Например, можно построить диаграмму количества ошибок (`count()`), сгруппированных по имени сервиса.

В примерах ниже используется удалённый набор данных, доступный на [sql.clickhouse.com](https://sql.clickhouse.com), который описан в руководстве [&quot;Remote Demo Dataset&quot;](/ru/clickstack/example-datasets/remote-demo-data). **Вы также можете повторить эти примеры на [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com).**

<div id="creating-dashboards">
  ## Создание панелей мониторинга {#creating-dashboards}
</div>

Панели мониторинга позволяют группировать связанные визуализации, чтобы сравнивать Метрики и анализировать закономерности рядом друг с другом, выявляя возможные первопричины проблем в ваших системах. Эти панели мониторинга можно использовать для разовых исследований или сохранять для постоянного мониторинга.

Глобальные фильтры можно применять на уровне панели мониторинга, и они автоматически распространяются на все визуализации в её составе. Это обеспечивает единообразную детализацию во всех диаграммах и упрощает сопоставление событий между сервисами и различными типами телеметрии.

Ниже мы создадим панель мониторинга с двумя визуализациями, используя источники данных журналов и трассировок. Эти шаги можно повторить на [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) или локально, подключившись к датасету, размещённому на [sql.clickhouse.com](https://sql.clickhouse.com), как описано в руководстве [&quot;Remote Demo Dataset&quot;](/ru/clickstack/example-datasets/remote-demo-data).

  <Step title="Добавьте плитку тепловой карты для длительности span" id="create-a-tile-heatmap">
    Плитки тепловой карты показывают количество событий, попадающих в каждый бакет `(time, value)`, в виде цветной сетки. Используйте тепловую карту, когда нужно видеть **форму** распределения во времени, а не только среднее значение или один процентиль. Тепловая карта задержки позволяет выявить бимодальные паттерны длительности, кластеры «медленного хвоста» или резкие расширения, которые линейный график просто усреднил бы.

    Чтобы добавить плитку тепловой карты:

    1. Выберите `Add New Tile`.
    2. В верхнем меню выберите тип визуализации `Heatmap`. В раскрывающемся списке источников данных показываются только источники, чей [тип источника — `Traces`](/ru/clickstack/managing/config#traces). Источники журналов, метрик и сеансов скрыты, поскольку для тепловых карт нужен столбец длительности span, который есть только у источников трассировок.
    3. Выберите любой из ваших источников трассировок по имени. Само имя произвольно — значение имеет только тип.

    После выбора источника поля тепловой карты автоматически заполняются:

    * **Value**: `Duration Expression` источника, приведённое к текущей единице отображения (например, `(Duration)/1e6`, чтобы преобразовать длительность span каждого события из наносекунд в миллисекунды)
    * **Count**: `count()`

    4. Задайте имя графика и используйте `Where`, чтобы ограничить тепловую карту конкретным сервисом или набором операций, за производительностью которых вы хотите наблюдать.
    5. Настройте временной диапазон в соответствии с нужным периодом. Более широкие диапазоны позволяют увидеть сдвиги распределения и бимодальные паттерны задержки, которые короткие окна могут скрывать.

    В примере ниже показан один сервис в 24-часовом окне, где быстрый и медленный пути длительности его span чётко разделены на две горизонтальные полосы.

    Чтобы дополнительно настроить тепловую карту, нажмите **Display Settings**, чтобы открыть выдвижную панель для **Scale** (Log или Linear), а также выражений **Value** и **Count**. Полный список параметров приведён в разделе [Customize the heatmap](/ru/clickstack/features/event-deltas#customize) на странице Event Deltas. Здесь используется та же панель.

    Нажмите `Run`, чтобы предварительно просмотреть график, затем — `Save`.

      <Frame>
        ![Редактор плитки тепловой карты с заранее заполненными значениями длительности span, фильтром ServiceName payment и кнопкой Display Settings](/images/clickstack/dashboards/heatmap-tile-editor.webp)
      </Frame>
    </div>

    Сохранённая плитка отображается на панели мониторинга как тепловая карта. Наведите указатель на любую ячейку, чтобы увидеть границы бакета и количество событий.

    <div className="ch-image-lg">
      <Frame>

      </Frame>
    </div>

    <Tip>
      **Два запроса ClickHouse для каждой тепловой карты**

      Тепловая карта строится с помощью двух последовательных запросов: небольшого **запроса границ**, который определяет диапазон значений, и **запроса тепловой карты**, который подсчитывает события в каждом бакете. Оба запроса видны в редакторе в разделе **Generated SQL**, если вы хотите их изучить или скопировать.
    </Tip>

<div id="tile-display-settings">
  ### Настройки отображения плитки {#tile-display-settings}
</div>

У каждой плитки есть выдвижная панель **Display Settings** с параметрами, которые определяют, как отображается её значение. Откройте её в редакторе плитки, нажав **Display Settings**. Доступные параметры зависят от типа визуализации.

<div id="number-tile-color">
  #### Цвет плитки Number {#number-tile-color}
</div>

Для плиток Number можно выбрать статический **цвет** из палитры диаграмм. Выберите плитку Number, откройте **Display Settings** и с помощью элемента управления **цветом** (в целях доступности обозначенного как **цвет плитки Number**) выберите образец цвета или сбросьте выбор, чтобы использовать цвет текста по умолчанию.

Цвета хранятся как токены палитры, а не как необработанные шестнадцатеричные значения, поэтому одна и та же плитка корректно отображается в светлой, тёмной и IDE-темах.

**Категориальные токены** (цветовые тона для нескольких серий):

| Токен              | Метка        |
| ------------------ | ------------ |
| `chart-blue`       | Синий        |
| `chart-orange`     | Оранжевый    |
| `chart-red`        | Красный      |
| `chart-cyan`       | Голубой      |
| `chart-green`      | Зелёный      |
| `chart-pink`       | Розовый      |
| `chart-purple`     | Фиолетовый   |
| `chart-light-blue` | Светло-синий |
| `chart-brown`      | Коричневый   |
| `chart-gray`       | Серый        |

**Семантические токены** (для статусов):

| Токен           | Метка          |
| --------------- | -------------- |
| `chart-success` | Успешно        |
| `chart-warning` | Предупреждение |
| `chart-error`   | Ошибка         |

Используйте семантические токены, если число отражает статус (например, количество ошибок — `chart-error`, а показатель работоспособности — `chart-success`). Категориальные токены используйте, если нужно визуально различать связанные плитки KPI, не обозначая статус.

В старых конфигурациях могут по-прежнему храниться устаревшие числовые токены (`chart-1`–`chart-10`). При загрузке панели мониторинга ClickStack сопоставляет их с указанными выше токенами, названными по цветовым тонам.

Та же палитра используется для необязательных **правил цвета** на той же выдвижной панели: это упорядоченные условия, которые проверяются по отображаемому значению (приоритет имеет последнее совпадение). Если ни одно правило не совпадает, применяется статический цвет, а затем цвет текста по умолчанию.

#### Фоновый график плитки Number {#number-tile-background-chart}

Плитки Number могут показывать **фоновый график**: спарклайн тренда, который отображается за значением, чтобы динамика в выбранном временном диапазоне была видна с первого взгляда. Это полезно для плиток SLO и error budget, где важны не только текущее значение, но и его изменение со временем.

Выбрав плитку Number, откройте **Display Settings** и установите для **Фонового графика** значение **Line** или **Area** (или **None**, чтобы отключить его). Спарклайн строится на основе версии запроса плитки, разбитой по временным бакетам, поэтому дополнительная настройка не требуется. По умолчанию он наследует цвет плитки; задайте **Background color**, чтобы переопределить его и выбрать конкретный цвет из палитры.

  </Frame>
</div>

Фоновые графики доступны для плиток Number, созданных в конструкторе запросов. Плитки Number с Raw SQL возвращают одно значение без временной размерности для разбиения по бакетам, поэтому этот параметр для них отображается, но остаётся недоступным.

Плитки-таблицы могут чередовать фон строк с помощью **Alternate Row Background**, окрашивая каждую вторую строку, чтобы широкие таблицы было проще просматривать. По умолчанию этот параметр выключен.

Выбрав плитку-таблицу, откройте **Display Settings** и включите **Alternate Row Background**. Чередование фона — это исключительно визуальный эффект, поэтому оно работает как для плиток-таблиц из конструктора запросов, так и для плиток-таблиц с raw SQL.

## Пользовательские фильтры и переменные {#custom-filters}

Помимо [текстовых фильтров](#filter-dashboards), доступных на всех панелях мониторинга, сохраненные панели мониторинга поддерживают пользовательские фильтры и переменные. Это удобные, повторно используемые элементы управления, которые позволяют пользователям фильтровать данные без ручного ввода выражений. Их значения могут браться из столбца, запрошенного из источника, из списка, заданного вручную, из SQL-запроса, из значений меток Prometheus или из произвольно заданных условий вида «ключ — значение». Переменные также могут определять, к какому источнику данных или подключению обращается плитка. Полный список см. в разделе [Типы фильтров](#filter-types).

<div className="ch-image-lg">
  <Frame>
    ![Фильтр сервисов в виде раскрывающегося списка, показывающий доступные имена сервисов](/images/clickstack/dashboards/filter-dropdown.webp)
  </Frame>
</div>

Каждый фильтр позволяет пользователю выбрать одно или несколько значений и выполняет с ними одно или оба следующих действия:

* **Broadcast** — применяет выбранные значения как условие фильтра к соответствующим плиткам. Плитки не требуется обновлять для ссылки на фильтр.
* **Переменная** — предоставляет выбранные значения запросам плиток как `$variableName`, поэтому каждая плитка сама определяет, где и как использовать значение.

Какие из этих двух действий поддерживает фильтр, зависит от его [типа](#filter-types). Фильтр типа **SQL expression values** должен выполнять хотя бы одно из них и по умолчанию использует Broadcast.

### Типы фильтров {#filter-types}

Селектор **Type** в диалоговом окне фильтра определяет, откуда берутся значения фильтра и как они попадают в плитки.

| Тип                                                      | Источник значений                                                                                    | Распространение                      | Переменная                                                          |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------- |
| [Значения SQL-выражения](#sql-expression-values-filters) | Уникальные значения выражения, запрашиваемые из источника                                            | Необязательно, по умолчанию включено | Необязательно                                                       |
| [Статические значения](#static-values-filters)           | Список, заданный вручную                                                                             | Нет                                  | Всегда                                                              |
| [Значения SQL-запроса](#sql-query-filters)               | Первый столбец SQL-запроса                                                                           | Нет                                  | Всегда                                                              |
| [Значения метки PromQL](#promql-label-filters)           | Значения метки Prometheus                                                                            | Нет                                  | Всегда                                                              |
| [Произвольные ключи и значения](#adhoc-filters)          | Условия вида `key operator value`, построенные из ключей и значений одного или нескольких источников | Всегда                               | Нет                                                                 |
| [Источник данных](#data-source-variables)                | Источники команды                                                                                    | Нет                                  | Всегда, в виде [ссылки на источник](#source-connection-variables)   |
| [Соединение](#connection-variables)                      | Соединения команды с ClickHouse                                                                      | Нет                                  | Всегда, в виде [ссылки на соединение](#source-connection-variables) |

#### Значения SQL-выражения {#sql-expression-values-filters}

Раскрывающийся список такого фильтра содержит уникальные значения поля **Выражение фильтрации** (Filter expression) в выбранном **источнике данных** (Data source); при необходимости список можно сузить с помощью **фильтра значений раскрывающегося списка** (Dropdown values filter). Для источников метрик также выберите **тип метрики** (Metric type). Фильтр значений SQL-выражения может [распространять](#broadcast-filters) свою выборку, быть [доступным как переменная](#dashboard-variables) или и то и другое одновременно.

#### Статические значения {#static-values-filters}

Раскрывающийся список такого фильтра содержит заданный вручную перечень значений. Введите каждое значение в поле **Options** и нажмите Enter. Фильтр может содержать до 1000 вариантов.

Фильтр со статическими значениями всегда является переменной и никогда не распространяется автоматически, поэтому плитки используют его через ссылку на соответствующую переменную, например `$__filter(SeverityText, $severity)`. Это удобно для значений, которые не хранятся в столбце, или для фиксированного, заранее подобранного списка.

#### Значения SQL-запроса {#sql-query-filters}

Раскрывающийся список этого фильтра содержит значения первого столбца, возвращаемого SQL-запросом на ClickHouse SQL, в том порядке, в котором запрос возвращает строки, — не более 10,000 значений. Настройте следующие параметры:

* **Connection** — соединение ClickHouse, в котором выполняется запрос, или [переменная соединения](#connection-variables).
* **Source** — необязательный параметр. Источник в том же соединении или [переменная источника данных](#data-source-variables). Если источник выбран, в запросе можно использовать `$__sourceTable` и `$__filters`: последний применяет к этому источнику значения, выбранные в распространяемых фильтрах панели мониторинга, — так же, как это делают [плитки Raw SQL](/ru/clickstack/features/dashboards/sql-visualizations#dashboard-filter-macro).
* **SQL query** — сам запрос. В нём можно использовать [макросы времени](/ru/clickstack/features/dashboards/sql-visualizations#time-filter-macros) и ссылаться на другие переменные панели мониторинга. В редакторе отображается предварительный просмотр значений, которые запрос возвращает для текущего временного диапазона панели мониторинга.

Например, следующий запрос выводит список сервисов, для которых были записаны события во временном диапазоне панели мониторинга, с учётом окружений, выбранных в фильтре `environment`:

```sql
SELECT DISTINCT ServiceName
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ResourceAttributes['deployment.environment'], $environment)
ORDER BY ServiceName
```

Фильтр типа «Значения из SQL-запроса» всегда является переменной и никогда не применяет распространение.

#### Значения меток PromQL {#promql-label-filters}

<Note>
  Поддержка PromQL доступна в предварительной версии. В развертываниях с открытым исходным кодом включите её, задав `ENABLE_PROMQL=true` для API и `NEXT_PUBLIC_ENABLE_PROMQL=true` для приложения (см. [необязательные возможности](/ru/clickstack/managing/config#optional-features-and-deployment-modes)), а также включите схему PromQL в коллекторе (см. [метрики, совместимые с Prometheus](/ru/clickstack/managing/config#collector-prometheus-metrics)). О создании источника PromQL см. раздел [Настройки источника PromQL](/ru/clickstack/managing/config#promql-source-settings).
</Note>

Раскрывающийся список этого фильтра содержит значения метки Prometheus. Выберите PromQL-источник в поле **Data source** и укажите в поле **Label** метку, значениями которой будет заполнен раскрывающийся список, например `job`, `instance` или `__name__`. При необходимости укажите **Series matchers** — селектор серий Prometheus, например `up{job="api"}`, который ограничивает набор серий, из которых берутся значения. В Series matchers можно ссылаться на другие переменные панели мониторинга.

Фильтр значений меток PromQL всегда является переменной и никогда не применяется к плиткам автоматически. В плитках PromQL ссылайтесь на него внутри сопоставителя меток, например `rate(http_requests_total{job=~"$job"}[$__rate_interval])`. О том, как подставляются значения, см. раздел [Ссылка на переменную](#referencing-variables).

#### Произвольные ключи и значения {#adhoc-filters}

Вместо единственного раскрывающегося списка произвольный (ad hoc) фильтр позволяет пользователю составить список условий вида `key operator value` на основе ключей его источников: столбцов и ключей map для SQL-источников или меток для источников Prometheus. Ключи и значения подсказываются по мере ввода. Настройте следующие параметры:

* **Source type** — SQL (источники логов, трасс или сеансов) или Prometheus.
* **Data sources** — источники, ключи и значения которых подсказывает фильтр.
* **Keys and values filter** — необязательный параметр, только для SQL-источников. Условие SQL или Lucene, ограничивающее набор строк, из которых берутся подсказки ключей и значений. Может ссылаться на другие переменные панели мониторинга.
* **Applies to sources** — источники, на которые распространяются условия. Оставьте поле пустым, чтобы условия распространялись на все плитки, использующие один из источников данных фильтра.
* **Unique name** — идентифицирует условия фильтра в [URL панели мониторинга](/ru/clickstack/url-parameters#dashboard-filter-values).

Условия для SQL-источников поддерживают следующие операторы: `=`, `!=`, `=~` (регулярное выражение), `!~` (регулярное выражение), `LIKE`, `NOT LIKE`, `IN`. Условия для источников Prometheus поддерживают `=`, `!=`, `=~` (регулярное выражение), `!~` (регулярное выражение) и `IN`; `LIKE` и `NOT LIKE` доступны только для SQL.

Пользователи также могут добавить условие, щёлкнув значение в плитке таблицы, временного ряда или поиска на панели мониторинга.

Произвольные условия всегда распространяются на плитки, и на них нельзя ссылаться как на переменные. Плитки конструктора графиков и плитки PromQL для соответствующих источников подхватывают их автоматически, а плитки Raw SQL применяют их через [макрос `$__filters`](/ru/clickstack/features/dashboards/sql-visualizations#dashboard-filter-macro).

#### Источник данных {#data-source-variables}

Переменная источника данных позволяет пользователю выбрать, к какому источнику обращается плитка. Укажите в поле **Source kinds**, какие типы источников будут доступны в её раскрывающемся списке (например, только источники журналов), и при необходимости ограничьте их одним подключением в поле **Connection**, причём само подключение тоже может быть переменной подключения. О том, как плитки и фильтры используют эту переменную, см. в разделе [Переменные источника данных и подключения](#source-connection-variables).

#### Подключение {#connection-variables}

Переменная подключения позволяет пользователю, просматривающему дашборд, выбрать, какое подключение к ClickHouse используют плитки Raw SQL, фильтры значений на основе SQL-запроса и переменные источника данных. Кроме имени, других настроек у неё нет.

### Переменные источника данных и соединения {#source-connection-variables}

Переменные источника данных и соединения подставляются вместо источника или идентификатора соединения, а не вместо значения в тексте запроса. Везде, где элемент выбора источника или соединения поддерживает такие переменные, переменные панели мониторинга перечислены в группе **Variables**. При выборе одной из них сохраняется ссылка `$name`, которая разрешается в значение, выбранное пользователем в данный момент. Так можно создать одну панель мониторинга, на которой можно переключаться, например, между журналами нескольких окружений или между несколькими кластерами ClickHouse.

| Где используется               | Поддерживает переменную источника данных | Поддерживает переменную соединения |
| ------------------------------ | ---------------------------------------- | ---------------------------------- |
| Плитки конструктора графиков   | Source                                   | —                                  |
| Плитки Raw SQL                 | Source                                   | Connection                         |
| Плитки PromQL                  | Source                                   | —                                  |
| Фильтры значений SQL-выражения | Data source, Applies to sources          | —                                  |
| Фильтры значений меток PromQL  | Data source                              | —                                  |
| Ad hoc-фильтры                 | Data sources, Applies to sources         | —                                  |
| Фильтры значений SQL-запроса   | Source                                   | Connection                         |
| Переменные источника данных    | —                                        | Connection                         |

Переменная источника данных предлагается только там, где подходит хотя бы один из её видов источников. Например, плитка PromQL предлагает только те переменные источника данных, которые допускают источники PromQL.

Переменные источника данных и соединения всегда допускают выбор только одного значения и являются обязательными, поскольку плитка не может выполнить запрос без источника или соединения. Пока значение не выбрано, плитки и фильтры, ссылающиеся на переменную, ожидают его. Чтобы вместо этого приостановить всю панель мониторинга, включите **Block every tile**. [Ссылка на панель мониторинга](/ru/clickstack/url-parameters#dashboard-filter-values) позволяет выбрать источник или соединение как по имени, так и по ID.

<Note>
  Оповещения недоступны для плиток, использующих переменную источника данных или соединения. При сохранении такой плитки её оповещение удаляется.
</Note>

### Параметры выбора {#filter-selection-options}

Фильтры типов SQL expression values, static values, SQL query values и PromQL label values поддерживают следующие дополнительные параметры:

* **Single select** — одновременно можно выбрать только одно значение.
* **Required** — плитки, использующие фильтр (через его переменную или через распространение), не загружаются, пока в фильтре не выбрано значение.
  * **Block every tile** — блокирует все плитки на панели мониторинга, а не только те, что используют фильтр, пока в фильтре не выбрано значение.

### Связанные фильтры {#chained-filters}

Конфигурация фильтра может ссылаться на другие переменные панели мониторинга, и тогда его значения зависят от выбора в другом фильтре. Например, фильтр по сервисам может показывать только сервисы из окружения, выбранного в фильтре `environment`. Ссылаться на переменные можно в следующих местах:

* **Dropdown values filter** фильтра значений на основе SQL-выражения, например `$__filter(ResourceAttributes['deployment.environment'], $environment)`.
* **SQL query** фильтра значений на основе SQL-запроса.
* **Series matchers** фильтра значений меток PromQL, например `up{env="$env"}`.
* **Keys and values filter** ad hoc-фильтра.
* Поля источника и соединения — с помощью [переменных источника данных и переменных подключения](#source-connection-variables).

При изменении выбора в фильтре, на который ссылается зависимый фильтр, значения последнего запрашиваются повторно. Пока в обязательном фильтре, на который есть ссылка, ничего не выбрано, зависящий от него ad hoc-фильтр не позволяет добавлять или изменять условия и показывает имя фильтра, выбора в котором он ожидает.

<div id="broadcast-filters">
  ### Трансляция фильтров {#broadcast-filters}
</div>

Фильтры по значениям SQL-выражения могут транслировать выбранные значения, а ad hoc-фильтры всегда транслируют свои условия. Если для фильтра по значениям SQL-выражения включено **Условие широковещательного фильтра**, выбранные значения применяются в качестве условия фильтра ко всем плиткам на панели мониторинга, даже если ни одна из них явно не ссылается на этот фильтр. По умолчанию условие применяется ко всем плиткам. Используйте **Применяется к источникам**, чтобы ограничить его плитками, использующими указанный набор источников. Это полезно, если выражение фильтра имеет смысл только для части данных на панели мониторинга.

Плитки конструктора диаграмм автоматически учитывают широковещательные фильтры. Плитки Raw SQL должны содержать [макрос `$__filters`](/ru/clickstack/features/dashboards/sql-visualizations#dashboard-filter-macro) и иметь выбранный источник, поскольку ClickStack не может определить, где в написанном вручную запросе следует разместить условие.

<div id="dashboard-variables">
  ### Переменные {#dashboard-variables}
</div>

Фильтры типов «статические значения», «значения SQL-запроса» и «значения меток PromQL» всегда являются переменными. Фильтр типа «значения SQL-выражения» становится переменной, если включена опция **Доступно как переменная**. Переменная делает выбранное в фильтре значение доступным в запросах плиток как `$variableName`. По умолчанию **Имя переменной** совпадает с отображаемым именем фильтра, из которого удалены недопустимые символы, однако его можно переопределить. Имена должны начинаться с буквы и могут содержать только буквы, цифры и символы подчёркивания.

Фильтры ad hoc никогда не являются переменными, а переменные источника данных и соединения представляют собой [ссылки на источник или соединение](#source-connection-variables), а не значения в тексте запроса.

Используйте переменную, если применять условие `WHERE` ко всем плиткам не требуется — например, чтобы использовать значение в выражении `SELECT`, предложении `HAVING` или ключе JOIN либо отфильтровать плитку по столбцу, отличному от выражения самого фильтра.

<div id="referencing-variables">
  #### Использование переменной {#referencing-variables}
</div>

Переменная разворачивается в значения, выбранные в её раскрывающемся списке. Форма ссылки определяет формат вывода:

| Ссылка              | Разворачивается в                                                                                                                                                                                                               | Пустой выбор                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `$name`, `${name}`  | Выбранные значения в формате `sqlstring` или `lucene` в зависимости от контекста. Фигурные скобки отделяют имя, если за ним следуют буквенно-цифровые символы, как в `${name}_total`.                                           | `NULL`                                    |
| `${name:sqlstring}` | Выбранные значения в одинарных кавычках, разделённые запятыми и экранированные как значения SQL, например `'a', 'b'`                                                                                                            | `NULL`                                    |
| `${name:csv}`       | Без кавычек, разделённые запятыми: `a,b`. Не экранируются для SQL.                                                                                                                                                              | пустая строка                             |
| `${name:regex}`     | Альтернация регулярного выражения с экранированием: `(a\|b)`.                                                                                                                                                                   | `.*`                                      |
| `${name:lucene}`    | `OR` терминов в кавычках для ввода Lucene: `("a" OR "b")`.                                                                                                                                                                      | `("")`                                    |
| `${name:promql}`    | Используется по умолчанию в плитках PromQL. Для фильтра с одиночным выбором — выбранное значение для подстановки в `label="$name"`. В остальных случаях — альтернация регулярного выражения для подстановки в `label=~"$name"`. | `.*` (пустая строка при одиночном выборе) |

Поскольку до выбора значения `$name` выводится как `NULL`, используйте следующие макросы везде, где требуется предикат SQL. Пока для переменной макроса ничего не выбрано, оба макроса разворачиваются в `1=1`, поэтому запрос остаётся корректным:

| Макрос                                        | Описание                                                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | Разворачивается в `toString(<filter expression>) IN ($variable)`, если для `variable` выбраны значения, и в `1=1` в противном случае. |
| `$__filter(<expression>, $<variable>)`        | Разворачивается в `<expression> IN ($variable)`, если для `variable` выбраны значения, и в `1=1` в противном случае.                  |
| `$__conditionalAll(<condition>, $<variable>)` | Разворачивается в `<condition>`, если у переменной выбрано значение, и в `1=1` в противном случае.                                    |

<div id="variables-in-builder-tiles">
  #### Использование переменных в плитках конструктора диаграмм {#variables-in-builder-tiles}
</div>

Во всех полях ввода SQL-выражений конструктора диаграмм можно использовать ссылки на переменные: в столбцах `SELECT` и выражениях для каждой серии, а также в `WHERE`, `GROUP BY` и `HAVING`. Редактор автоматически дополняет переменные панели мониторинга и показывает, во что разворачивается каждая ссылка для текущего выбора.

В режиме SQL рекомендуется использовать макросы `$__filter` и `$__conditionalAll`, чтобы запросы оставались корректными при пустом выборе переменных. В полях ввода Lucene макросы недоступны — вместо них используйте переменные напрямую (например, `ServiceName:$service`).

В поле ввода Lucene наличие кавычек вокруг самой ссылки на переменную определяет, как сопоставляется выбор из нескольких значений. Если для `$service` выбраны значения `a,b`:

| Ссылка                   | Разворачивается в                      | Поведение сопоставления                                                                                 |
| ------------------------ | -------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ServiceName:$service`   | `ServiceName:("a" OR "b")`             | Сопоставление по подстроке — переводится в SQL как `ServiceName ILIKE '%a%' OR ServiceName ILIKE '%b%'` |
| `ServiceName:"$service"` | `(ServiceName:"a" OR ServiceName:"b")` | Точное сопоставление с каждым выбранным значением                                                       |

Заключайте ссылку на переменную в кавычки — `Field:"$var"` — если выбранные значения должны точно соответствовать `Field`, а не сопоставляться по подстроке.

<div id="variables-in-sql-tiles">
  #### Использование переменных в SQL-плитках {#variables-in-sql-tiles}
</div>

В плитках Raw SQL переменные можно использовать одинаково в любом месте запроса:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

Полный список макросов, доступных для SQL-плиток, см. в разделе [Визуализация на основе SQL](/ru/clickstack/features/dashboards/sql-visualizations#dashboard-variables).

<Note>
  Оповещения для плитки, использующей переменную панели мониторинга, проверяются при всех переменных в пустом состоянии, а не с выбранными на панели мониторинга значениями.
</Note>
