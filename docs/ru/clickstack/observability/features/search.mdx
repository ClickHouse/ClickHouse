ClickHouse Observability позволяет выполнять полнотекстовый поиск по событиям (журналам и трассировкам). Чтобы начать поиск, достаточно ввести ключевые слова, которые встречаются в ваших событиях. Например, если в журнале есть запись с &quot;Error&quot;, её можно найти, просто введя &quot;Error&quot; в строке поиска.

Тот же синтаксис поиска используется для фильтрации событий на панелях мониторинга и в диаграммах.

## Возможности поиска {#search-features}

### Синтаксис поиска Lucene {#natural-language-syntax}

* Поиск не чувствителен к регистру
* По умолчанию поиск выполняется по целым словам (например, `Error` совпадёт с `Error here`,
  но не с `Errors here`). Чтобы искать по части слова, окружите его подстановочными
  шаблонами (например, `*Error*` совпадёт с `AnyError` и `AnyErrors`)
* Слова поискового запроса ищутся в любом порядке (например, `Hello World` совпадёт с записями журнала,
  содержащими `Hello World` и `World Hello`)
* Чтобы исключить ключевые слова, используйте `NOT` или `-` (например, `Error NOT Exception` или
  `Error -Exception`)
* Для объединения нескольких ключевых слов используйте `AND` и `OR` (например,
  `Error OR Exception`)
* Для поиска точного совпадения заключите фразу в двойные кавычки (например, `"Error tests not found"`)

#### Поиск по столбцам и свойствам {#column-search}

* Для поиска по столбцам и свойствам JSON/Map используйте синтаксис `column:value` (например, `SeverityText:error`,
  `ServiceName:app`)
* Для поиска по диапазону значений используйте операторы сравнения (`>`, `<`,
  `>=`, `<=`) (например, `Duration:>1000`)
* Чтобы проверить наличие свойства, используйте `property:*` (например,
  `Duration:*`)

### Ввод времени {#time-input}

* В поле ввода времени можно указывать значения на естественном языке (например, `1 hour ago`, `yesterday`,
  `last week`).
* Если указать один момент времени, поиск будет выполняться с этого момента
  и до текущего.
* При поиске временной диапазон всегда преобразуется в разобранный временной диапазон, что
  упрощает отладку временных запросов.
* Кроме того, можно выделить столбец гистограммы, чтобы увеличить масштаб для определённого временного диапазона.

### Синтаксис поиска SQL {#sql-syntax}

При необходимости поля поиска можно переключить в режим SQL. В этом режиме для поиска можно использовать любое допустимое
предложение `WHERE`. Это удобно для сложных запросов, которые невозможно
выразить с помощью синтаксиса Lucene.

### Оператор SELECT {#select-statement}

Чтобы указать столбцы, отображаемые в результатах поиска, используйте поле ввода `SELECT`.
Это SQL-выражение `SELECT`, задающее столбцы для выборки на странице поиска.
Псевдонимы пока не поддерживаются (например, нельзя использовать `column as "alias"`).

## Сохранённые поиски {#saved-searches}

Поиски можно сохранять, чтобы быстро возвращаться к ним позже. Сохранённые поиски отображаются на странице `Saved Searches`, поэтому к часто используемым поисковым запросам легко вернуться, не составляя их заново.

### Добавление оповещений к сохранённым поискам {#alerts-on-saved-searches}

Для сохранённых поисков можно настроить оповещения, которые уведомят вас при выполнении заданных условий. Например, оповещение может срабатывать, когда количество событий, соответствующих сохранённому поиску, превышает заданный порог или опускается ниже него.

Подробнее о настройке оповещений см. в [документации по оповещениям](/ru/clickstack/observability/features/alerts).
