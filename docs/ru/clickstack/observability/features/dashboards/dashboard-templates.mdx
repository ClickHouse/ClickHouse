ClickHouse Observability включает библиотеку готовых шаблонов дашбордов для визуализации типовой телеметрии инфраструктуры и приложений. Данные на диаграммах появляются, как только ваш сервис ClickHouse начинает получать телеметрию, необходимую для шаблона.

## Просмотр доступных шаблонов {#browsing-templates}

Чтобы открыть встроенную библиотеку шаблонов, перейдите в раздел **панели мониторинга** и нажмите **Browse шаблоны дашбордов**.

  <Frame>

Откроется галерея, в которой шаблоны сгруппированы по категориям. Нажмите **Import** у нужного шаблона.

## Импорт шаблона {#importing-a-template}

На шаге **Step 2: Map Data** проверьте значения **Dashboard Name** и **Tags**, затем убедитесь, что для каждой плитки и каждого фильтра в столбце **To** указан нужный источник данных. Источники могут быть выбраны заранее. В примере ниже шаблон Node.js Runtime Metrics сопоставляет свои диаграммы и фильтр по сервису с источником **Metrics**. Нажмите **Finish Import**, чтобы создать панель мониторинга.

## Готовые шаблоны {#pre-built-templates}

### Browser RUM {#browser-rum}

Шаблон **Browser RUM** (мониторинг реальных пользователей) отображает метрики Core Web Vitals, процентили времени загрузки страниц, разбивку трафика и отслеживание ошибок. Он работает с браузерными сеансами, инструментированными с помощью браузерного SDK HyperDX или средств инструментирования OpenTelemetry RUM, которые передают `rum.sessionId`.

### Метрики среды выполнения OTel {#otel-runtime-metrics}

Встроенные шаблоны метрик среды выполнения OTel предназначены для приложений, инструментированных с использованием [метрик среды выполнения OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/runtime/).

| Шаблон                      | Описание                                                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **.NET Runtime Metrics**    | Сборка мусора, фрагментация кучи, исключения, использование пула потоков и метрики CPU для приложений .NET                 |
| **Go Runtime Metrics**      | Использование памяти, выделение памяти, целевые значения GC, степень использования CPU и метрики горутин для приложений Go |
| **JVM Runtime Metrics**     | Память кучи, степень использования CPU, потоки и метрики GC для приложений на базе JVM                                     |
| **Node.js Runtime Metrics** | Задержка цикла событий, использование кучи, степень использования CPU и память V8 для приложений Node.js                   |
| **Python Runtime Metrics**  | Степень использования CPU, использование памяти, циклы сборки мусора (GC) и количество потоков для приложений Python       |

Примечания:

* Для каждого шаблона настроен [пользовательский фильтр](/ru/clickstack/observability/features/dashboards/overview#custom-filters), отбирающий сервисы, у которых атрибут ресурса [`telemetry.sdk.language`](https://opentelemetry.io/docs/specs/semconv/registry/attributes/telemetry/#telemetry-sdk-language) совпадает со средой выполнения панели мониторинга.
* Имена метрик могут различаться в разных версиях OpenTelemetry SDK. Если ваш SDK передаёт метрики с другими именами, [отредактируйте визуализации](/ru/clickstack/observability/features/dashboards/overview#dashboards-editing-visualizations) с учётом ваших данных.

## Схемы в самоуправляемых развертываниях {#self-configured-schemas}

Для самоуправляемых развертываний с пользовательскими схемами таблиц метрик измените фильтр по сервису в шаблоне так, чтобы запрос обращался к соответствующим столбцам с именем сервиса и атрибутами ресурса. Для рабочих нагрузок с большим объемом данных рассмотрите возможность [материализации часто запрашиваемых атрибутов](/ru/clickstack/self-configured/managing/performance-tuning#materialize-frequently-queried-attributes), например `ResourceAttributes['telemetry.sdk.language']`, чтобы ускорить загрузку фильтров.
