Табличная плитка часто служит **каталогом**: по одной строке на каждый сервис, хост, конечную точку или группу ошибок и несколько столбцов с оценками для каждого из них. Действия при щелчке по строке превращают такой каталог в рабочий процесс инспекции. Вы просматриваете каталог, находите нужную строку, щёлкаете по ней, и ClickHouse Observability передаёт значения этой строки в виде фильтров. Пункт назначения открывается уже отфильтрованным по выбранному элементу — перестраивать запрос вручную не нужно.

Щелчок может вести в одно из двух мест:

* **на другую панель мониторинга** — для детального просмотра одного элемента, например на панель мониторинга с подробностями по отдельному сервису, или
* **к исходным событиям** в [Поиске](/ru/clickstack/observability/features/search) — к журналам или трассировкам, стоящим за строкой.

Оба сценария использования ниже начинаются с одного и того же каталога (инвентаря сервисов) и ведут из него в каждый из пунктов назначения. Действия при щелчке по строке применимы только к табличным плиткам. Их не следует путать с [переходом к поиску](/ru/clickstack/observability/features/dashboards/overview#drilldown-to-search) из чарта, который открывает контекстное меню при щелчке по точке на линейной или столбчатой диаграмме.

## Анализ сервиса на отдельной панели мониторинга {#inspect-in-dashboard}

Обзорная таблица, где каждому сервису отведена одна строка, отвечает на вопрос «какой сервис работает со сбоями?». Щелчок по строке может открывать панель мониторинга отдельного сервиса, которая отвечает на вопрос «что происходит внутри него?» и показывает данные только по выбранному сервису. В описанной ниже схеме таблица инвентаря сервисов связывается с панелью мониторинга `Service Detail`.

<Steps>
  <Step title="Создайте панель мониторинга с подробностями" id="detail-dashboard">
    Создайте панель мониторинга с именем `Service Detail` и добавьте [пользовательский фильтр](/ru/clickstack/observability/features/dashboards/overview#custom-filters) с выражением `ServiceName` для вашего источника трассировок. Фильтр уровня панели мониторинга ограничивает каждую плитку одним сервисом, поэтому в запросах самих плиток сервис жёстко не задаётся. Добавьте нужные представления для отдельного сервиса: ключевые показатели RED (запросы, ошибки, P95 длительности), чарт процентилей задержки (P50, P95, P99), частоту запросов во времени и разбивку по конечным точкам с группировкой по `SpanName`.

    Сначала сохраните эту панель мониторинга, чтобы на следующем шаге выбрать её в качестве целевой.
  </Step>

  <Step title="Создайте инвентарь сервисов" id="service-inventory">
    На обзорной панели мониторинга добавьте плитку **Table** для вашего источника трассировок с группировкой по `ServiceName`. Добавьте столбцы RED, по которым оценивается каждый сервис, — каждый в виде серии с псевдонимом:

    * `Requests`: количество спанов (rate).
    * `Errors`: количество спанов со статусом ошибки.
    * `P95 Duration`: 95-й процентиль `Duration`. Задайте для столбца числовой формат длительности, чтобы значение отображалось как `288ms`, а не в необработанных наносекундах.

    Отсортируйте по `Requests` по убыванию, чтобы самые нагруженные сервисы оказались вверху. Эта таблица служит каталогом: одна строка на сервис с оценкой по RED.

      </Frame>

    <Tip>
      **Выводите столбец группировки первым**

      По умолчанию таблица отображает столбец группировки (здесь `ServiceName`) справа, после серий. Каталог удобнее читать, когда идентификатор строки стоит первым. Откройте **Display Settings** плитки и включите **Display Group By Columns on Left**, чтобы переместить столбец группировки в начало.
    </Tip>
  </Step>

  <Step title="Настройте щелчок по строке" id="wire-dashboard">
    В таблице инвентаря откройте **Row Click Action**, выберите **Dashboard** и укажите `Service Detail` в списке панелей мониторинга. При прямом выборе панель привязывается по ID: ссылка продолжит работать, даже если панель мониторинга позже переименуют, и сохранится при её экспорте и импорте. (Вариант **Template** используйте, когда для разных строк нужно открывать разные панели мониторинга; см. [Настройка действия при щелчке по строке](#set-up).)

    * **Expression**: `ServiceName` (уже заполнено)
    * **Template**: `{{ServiceName}}`

    Нажмите **Apply** и сохраните изменения. Теперь сервис из выбранной строки передаётся в фильтр `ServiceName` панели мониторинга.
  </Step>

  <Step title="Щёлкните по строке" id="click-dashboard">
    Наведите курсор на строку — у правого края таблицы появится значок ссылки с подсказкой, описывающей действие (`Open dashboard "Service Detail"`).

    Щелчок по строке открывает панель мониторинга `Service Detail`, где в фильтре `Service` уже установлено выбранное значение, поэтому все плитки (ключевые показатели RED, процентили задержки, разбивка по конечным точкам) одним щелчком переключаются на этот сервис.

## Переход от сервиса к его трассировкам {#jump-to-traces}

Иногда вам нужно не очередное агрегированное представление, а необработанные события. Действие **Поиск** направляет щелчок не на панель мониторинга, а на страницу [Поиск](/ru/clickstack/observability/features/search) и открывает журналы или трассировки, стоящие за строкой, с уже применённым фильтром по ней.

Возьмите ту же таблицу инвентаря сервисов и настройте щелчок по строке так, чтобы он вёл непосредственно к трассировкам, а не к детальной панели мониторинга.

<Steps>
  <Step title="Направьте щелчок по строке на Search" id="wire-search">
    В таблице инвентаря откройте **Row Click Action** и выберите **Поиск**. Укажите источник трассировок (в списке отображаются только источники журналов и трассировок). Добавьте один фильтр:

    * **Expression**: `ServiceName`
    * **Template**: `{{ServiceName}}`

    Нажмите **Apply** и сохраните изменения.
  </Step>

  <Step title="Щёлкните по строке" id="click-search">
    Теперь щелчок по строке сервиса открывает страницу Поиск для этого источника трассировок с фильтром `ServiceName = <service>`, и вы видите спаны только этого сервиса за тот же временной диапазон.

    <div className="ch-image-lg">
      <Frame>
        ![Страница Поиск, открытая для источника трассировок после щелчка по строке, с фильтром по выбранному сервису](/images/clickstack/dashboards/row-click-search-drilldown.webp)
      </Frame>
    </div>
  </Step>
</Steps>

Та же схема подходит для любого каталога элементов. Сгруппируйте таблицу не по `ServiceName`, а по операции (`SpanName`) или по атрибуту конечной точки, задайте шаблон фильтра на основе этого столбца — и каждый щелчок по строке будет открывать события конкретной операции или конечной точки. О group-by по атрибуту типа Map см. примечание о псевдонимах в разделе [Проверка и ограничения](#validation).

## Настройка действия при щелчке по строке {#set-up}

Действия при щелчке по строке настраиваются непосредственно в табличной плитке; отдельной страницы для них нет. Добавьте или измените плитку и выберите для неё тип визуализации **Table**. После этого на панели инструментов редактора рядом с **Display Settings** появится кнопка **Row Click Action**. Кнопка отображается только для табличных плиток, а её подпись отражает текущее действие: `Row Click Action: Default`, `Row Click Action: Search` или `Row Click Action: Dashboard`. Нажмите на неё, чтобы открыть выдвижную панель.

<div className="ch-image-lg">
  <Frame>
    ![Выдвижная панель Row Click Action в режиме Dashboard: в качестве целевой выбрана панель мониторинга Service Detail, а фильтр ServiceName формируется по шаблону из строки, по которой выполнен щелчок](/images/clickstack/dashboards/row-click-drawer.webp)
  </Frame>
</div>

В выдвижной панели доступны три действия:

* **Default**: встроенное поведение. Щелчок по строке открывает страницу Поиск с фильтрацией по значениям столбцов группировки этой строки и по выбранному временному диапазону. Это поведение используется, если пользовательское действие не задано.
* **Поиск**: переход по щелчку на страницу Поиск для выбранного вами источника.
* **Dashboard**: переход по щелчку на другую панель мониторинга, принадлежащую вашей команде.

Для **Поиска** и **Dashboard** вы выбираете, куда ведёт щелчок, и задаёте шаблоны для передаваемых фильтров:

* **Destination**: выберите конкретный источник или панель мониторинга либо выберите **Template** и введите шаблон [Handlebars](https://handlebarsjs.com/), который сопоставляется по имени с доступным источником или панелью мониторинга. Выбранная конкретная целевая система закрепляется по ID. Этот вариант предпочтителен для одного фиксированного пункта назначения: привязка сохраняется при переименованиях, а также при экспорте и импорте панелей мониторинга, а для панели мониторинга заранее заполняются объявленные в ней фильтры. Используйте **Template**, если целевая система должна зависеть от строки: в этом случае она выбирается по ссылке на столбец строки (например, `Errors-{{ServiceName}}`).
* **Filters**: нажмите **Add filter** и укажите **Expression** (столбец или выражение в пункте назначения, например `ServiceName`) и **Template** для его значения (например, `{{ServiceName}}`). Шаблоны ссылаются на столбцы строки, по которой выполнен щелчок, с помощью `{{columnName}}` (о доступных столбцах см. примечание ниже). Каждый фильтр преобразуется в условие `expression IN (value)` в пункте назначения, а фильтры с одинаковым выражением объединяются. Если пунктом назначения является панель мониторинга, выдвижная панель заранее добавляет по одному пустому фильтру для каждого фильтра, уже объявленного на этой панели, поэтому вам остаётся только заполнить шаблоны.
* **WHERE** (необязательно): шаблон Handlebars, подставляемый в глобальный фильтр пункта назначения в дополнение к описанным выше условиям отдельных фильтров. Укажите для него язык запросов SQL или Lucene, чтобы пункт назначения мог его разобрать. Например, SQL-шаблон `ServiceName = '{{ServiceName}}'` ограничивает пункт назначения сервисом из строки, по которой выполнен щелчок.

<Info>
  **Шаблоны ссылаются на столбцы таблицы**

  Шаблон `{{...}}` разрешается относительно собственных столбцов табличной плитки: столбцов группировки и серий (по имени или псевдониму) — ровно в том виде, в каком они отображаются в таблице. Столбцы исходного источника, которые таблица не выбирает, шаблону недоступны. Чтобы значение передавалось при щелчке, оно должно быть столбцом таблицы: например, `{{ServiceName}}` работает, поскольку `ServiceName` — столбец группировки таблицы, а на столбец с псевдонимом ссылаются по псевдониму. Если указать имя, которого нет в таблице, щелчок завершится ошибкой `Row has no column '<name>'`.
</Info>

Нажмите **Apply**, чтобы проверить корректность шаблонов (интерфейс сообщит о шаблонах с недопустимым синтаксисом), а затем сохраните панель мониторинга, чтобы действие сохранилось.

## Как определяются пункт назначения и фильтры {#how-it-resolves}

Когда пользователь нажимает на строку, интерфейс выполняет действие с учётом данных этой строки:

* **Пункт назначения.** Если выбран конкретный источник или панель мониторинга, они закрепляются по ID. Цель типа **Template** формируется по шаблону на основе нажатой строки, а затем сопоставляется по имени с источниками или панелями мониторинга вашей команды. Для успешного разрешения имя должно быть уникальным: если у двух источников или двух панелей мониторинга совпадает сформированное по шаблону имя, ссылку невозможно сопоставить ни с одним из них. Ссылка также не разрешается, если сформированное имя пустое или для него не найдено совпадений.
* **Фильтры.** Каждый шаблон фильтра формируется на основе строки и превращается в условие `expression IN (value)` в пункте назначения. Действие `Search` открывает `/search` с привязкой к выбранному источнику, а действие `Dashboard` открывает соответствующую панель мониторинга. В обоих случаях временной диапазон нажатой строки сохраняется.

<Info>
  **Для целевых панелей мониторинга необходимо объявить соответствующий фильтр**

  Фильтр, передаваемый в панель мониторинга, применяется только в том случае, если в целевой панели объявлен [пользовательский фильтр](/ru/clickstack/observability/features/dashboards/overview#custom-filters) верхнего уровня, выражение которого совпадает со значением **Expression** фильтра. Если ни один из объявленных фильтров не совпадает, значение отбрасывается в момент нажатия, и пункт назначения открывается без фильтрации по этому выражению. Именно поэтому в режиме панели мониторинга объявленные фильтры пункта назначения подставляются заранее: укажите совпадающее выражение, и раскрывающийся список в пункте назначения автоматически заполнится значением из нажатой строки.
</Info>

## Проверка и ограничения {#validation}

* **Только табличные плитки.** Кнопка **Row Click Action** доступна для табличных плиток — как для таблицы, созданной в конструкторе графиков, так и для таблицы [на основе SQL](/ru/clickstack/observability/features/dashboards/sql-visualizations). У плиток других типов нет действия при щелчке по строке.
* **Целевыми объектами поиска могут быть только источники журналов или трасс.** Источники метрик и сеансов не предлагаются, поскольку их нельзя просматривать на странице поиска.
* **Имена, используемые в шаблонах, должны быть уникальными.** Целевой объект в шаблоне определяется по имени, поэтому если у двух источников или двух панелей мониторинга одинаковые имена, их нельзя использовать в качестве целевого объекта шаблона.
* **Чтобы переданное значение применилось, на целевой панели мониторинга должен быть объявлен соответствующий фильтр** (см. примечание выше).
* **Столбцам группировки по выражению нужен псевдоним.** При группировке по выражению, например по атрибуту типа Map `SpanAttributes['http.route']`, в результате появляется столбец, имя которого совпадает с необработанным выражением, и ссылаться на него в шаблоне неудобно. Задайте столбцу псевдоним в конструкторе графиков: добавьте `AS <alias>` после выражения в поле **Group By** (например, `SpanAttributes['http.route'] AS Route`), а затем используйте `{{Route}}` в шаблоне. Агрегированные серии точно так же получают псевдоним из поля **Alias**. У столбца группировки по обычному столбцу, например `ServiceName`, имя уже понятное, и псевдоним не нужен.
