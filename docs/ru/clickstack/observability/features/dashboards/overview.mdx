ClickHouse Observability поддерживает визуализацию событий и предоставляет встроенные средства построения диаграмм прямо в интерфейсе. Эти диаграммы можно добавлять на панели мониторинга и открывать к ним общий доступ для других пользователей.

Визуализации можно создавать на основе трассировок, метрик, журналов или любых пользовательских схем широких событий.

## Создание визуализаций {#creating-visualizations}

Интерфейс **Chart Explorer** позволяет визуализировать метрики, трассировку и журналы во времени и быстро строить визуализации для анализа данных. Этот же интерфейс используется при создании панелей мониторинга. В этом разделе описан процесс создания визуализации с помощью Chart Explorer.

Создание любой визуализации начинается с выбора **источника данных** и **метрики**; при необходимости можно задать **выражения фильтрации** и поля **группировки**. По сути, визуализации соответствуют SQL-запросу с `GROUP BY` — вы определяете метрики, которые агрегируются по выбранным измерениям.

<Tip>
  **Генерация диаграмм и панелей мониторинга с помощью ИИ**

  ClickHouse Observability также позволяет создавать диаграммы по запросам на естественном языке с помощью функции [Text-to-Chart](/ru/clickstack/observability/text-to-chart). Опишите, что вы хотите увидеть, и интерфейс автоматически сгенерирует визуализацию. Чтобы сгенерировать полноценную панель мониторинга с несколькими плитками, используйте [Text-to-Dashboard](/ru/clickstack/observability/text-to-dashboard).
</Tip>

Например, можно построить диаграмму количества ошибок (`count()`) с группировкой по имени сервиса.

В примерах ниже используется удалённый набор данных, доступный на [sql.clickhouse.com](https://sql.clickhouse.com). **Эти примеры также можно воспроизвести на [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com).**

## Создание панелей мониторинга {#creating-dashboards}

Панели мониторинга позволяют объединять связанные визуализации, чтобы сравнивать метрики и изучать закономерности бок о бок, выявляя возможные первопричины проблем в ваших системах. Такие панели мониторинга можно использовать для разовых расследований или сохранять для постоянного мониторинга.

Глобальные фильтры можно применять на уровне панели мониторинга — они автоматически распространяются на все её визуализации. Это обеспечивает согласованную детализацию во всех диаграммах и упрощает сопоставление событий между сервисами и типами телеметрии.

Ниже мы создадим панель мониторинга с двумя визуализациями на основе источников данных логов и трасс. Эти шаги можно воспроизвести на [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) или локально, подключившись к набору данных, размещённому на [sql.clickhouse.com](https://sql.clickhouse.com).

  <Step title="Добавьте плитку с тепловой картой длительности спанов" id="create-a-tile-heatmap">
    Плитки тепловой карты отображают количество событий, попадающих в каждый бакет (время, значение), в виде цветной сетки. Используйте тепловую карту, когда нужно увидеть **форму** распределения во времени, а не только среднее значение или отдельный перцентиль. Тепловая карта задержки выявляет бимодальные распределения длительности, кластеры в «медленном хвосте» или внезапное расширение распределения — всё то, что на линейном чарте усреднилось бы.

    Чтобы добавить плитку тепловой карты:

    1. Нажмите `Add`.
    2. Выберите тип визуализации `Heatmap` в верхнем меню. В выпадающем списке источников данных отображаются только источники, у которых [тип источника — `Traces`](/ru/clickstack/observability/managing/config#datasource-settings). Источники логов, метрик и сессий исключаются, поскольку для тепловых карт нужен столбец длительности спана, который есть только у источников трассировок.
    3. Выберите любой из ваших источников трассировок по имени. Само имя может быть любым — важен только тип.

    После выбора источника тепловая карта заполняется автоматически:

    * **Value**: значение `Duration Expression` источника, приведённое к текущей единице отображения (например, `(Duration)/1e6` для перевода длительности спана каждого события из наносекунд в миллисекунды)
    * **Count**: `count()`

    4. Задайте имя чарта и с помощью `Where` ограничьте тепловую карту определённым сервисом или набором операций, производительность которых вы хотите отслеживать.
    5. Задайте временной диапазон, соответствующий интересующему периоду. На более широких диапазонах видны сдвиги распределения и бимодальные распределения задержки, которые в более коротких окнах могут оставаться незаметными.

    В примере ниже показаны длительности спанов для сервиса `payment`: большинство спанов сосредоточено около одной миллисекунды, а выше разбросаны более медленные спаны.

    Для дополнительной настройки тепловой карты нажмите **Display Settings** — откроется выдвижная панель с параметром **Scale** (Log или Linear), а также выражениями **Value** и **Count**. Полный список параметров описан в разделе [Настройка тепловой карты](/ru/clickstack/observability/features/event-deltas#customize) на странице «Различия событий» — там используется та же выдвижная панель.

    Нажмите `Run` для предварительного просмотра чарта, затем `Save`.

### Настройки отображения плитки {#tile-display-settings}

У каждой плитки есть выдвижная панель **Настройки Отображения** с параметрами, которые определяют, как отображается её значение. Чтобы открыть эту панель, нажмите **Настройки Отображения** в редакторе плитки. Набор доступных параметров зависит от типа визуализации.

#### Цвет числовой плитки {#number-tile-color}

Для числовых плиток можно задать статический цвет (**Color**) из подобранной палитры чартов. Выберите числовую плитку, откройте **Настройки Отображения** и с помощью элемента **Color** (для специальных возможностей он помечен как **Number tile color**) выберите образец цвета или сбросьте выбор, чтобы использовать цвет текста по умолчанию.

Цвета хранятся как токены палитры, а не как необработанные шестнадцатеричные значения, поэтому одна и та же плитка корректно отображается в светлой, тёмной и IDE-темах.

**Категориальные токены** (цветовые тона для нескольких серий):

| Токен              | Метка        |
| ------------------ | ------------ |
| `chart-blue`       | Синий        |
| `chart-orange`     | Оранжевый    |
| `chart-red`        | Красный      |
| `chart-cyan`       | Голубой      |
| `chart-green`      | Зелёный      |
| `chart-pink`       | Розовый      |
| `chart-purple`     | Фиолетовый   |
| `chart-light-blue` | Светло-синий |
| `chart-brown`      | Коричневый   |
| `chart-gray`       | Серый        |

**Семантические токены** (для обозначения статуса):

| Токен           | Метка          |
| --------------- | -------------- |
| `chart-success` | Успех          |
| `chart-warning` | Предупреждение |
| `chart-error`   | Ошибка         |

Используйте семантические токены, когда число отражает статус (например, количество ошибок — `chart-error`, показатель работоспособности — `chart-success`). Категориальные токены подходят, когда нужно визуально различать связанные KPI-плитки, не обозначая статус.

В старых конфигурациях могут по-прежнему храниться устаревшие числовые токены (от `chart-1` до `chart-10`). При загрузке панели мониторинга интерфейс сопоставляет их с перечисленными выше токенами, названными по цветовым тонам.

Та же палитра используется в необязательных **правилах цвета** на той же выдвижной панели. Это упорядоченные условия, которые проверяются по отображаемому значению (приоритет у последнего совпадения). Если ни одно правило не сработало, применяется статический цвет, а если он не задан — цвет текста по умолчанию.

#### Фоновая диаграмма числовой плитки {#number-tile-background-chart}

Числовые плитки могут отображать **фоновую диаграмму** — спарклайн тренда, отрисованный позади значения, чтобы его изменение за выбранный временной диапазон было видно с первого взгляда. Это полезно для плиток SLO и бюджета ошибок, где динамика значения важна не меньше, чем его текущая величина.

Выбрав числовую плитку, откройте **Настройки Отображения** и установите для **Background chart** значение **Line** или **Area** (или **None**, чтобы отключить его). Спарклайн строится по версии запроса плитки с разбиением на временные интервалы, поэтому дополнительная настройка не требуется. По умолчанию он наследует цвет плитки; чтобы переопределить его конкретным цветом палитры, задайте **Background color**.

<div className="ch-image-lg">
  <Frame>
    ![Выдвижная панель Настройки Отображения для числовой плитки с параметром Background chart, установленным в Area](/images/clickstack/dashboards/number-tile-background-chart.webp)
  </Frame>
</div>

Фоновые диаграммы доступны для числовых плиток, созданных в конструкторе запросов. Числовые плитки Raw SQL возвращают одно значение без временного измерения, по которому можно было бы выполнить разбиение на интервалы, поэтому для них параметр отображается, но отключён.

В табличных плитках можно включить чередование фона строк с помощью **Alternate Row Background**: каждая вторая строка подсвечивается, что упрощает просмотр широких таблиц. По умолчанию эта функция отключена.

Выбрав табличную плитку, откройте **Настройки Отображения** и включите **Alternate Row Background**. Чередование влияет только на отображение, поэтому работает как в табличных плитках из конструктора запросов, так и в табличных плитках Raw SQL.

Кроме того, при прокрутке табличные плитки сохраняют разделитель между строкой заголовка и данными, благодаря чему заголовки столбцов остаются чётко различимыми.

#### API панелей мониторинга: цвет числовой плитки {#api-number-tile-color}

При создании или обновлении панелей мониторинга через внешний API (`POST` / `PUT` `/api/v2/dashboards`) указывайте в поле `color` конфигурации числовой плитки, созданной в построителе, токен палитры. Необработанные шестнадцатеричные значения не принимаются.

```json
{
  "name": "Error rate KPIs",
  "tiles": [
    {
      "id": "65f5e4a3b9e77c001a222222",
      "name": "Errors",
      "x": 0,
      "y": 0,
      "w": 6,
      "h": 4,
      "config": {
        "displayType": "number",
        "sourceId": "<SOURCE_ID>",
        "select": [
          {
            "aggFn": "count",
            "where": "SeverityText:error",
            "whereLanguage": "lucene",
            "alias": "Errors"
          }
        ],
        "color": "chart-error",
        "backgroundChart": {
          "type": "area"
        }
      }
    }
  ]
}
```

Параметр `color` принимает любой токен из приведённых выше категориальных и семантических списков (например, `chart-blue` или `chart-success`). Необязательный параметр `backgroundChart.color` переопределяет цвет спарклайна и принимает значения из того же перечисления токенов. Сведения об аутентификации и базовых URL см. в [справочнике API](/ru/clickstack/observability/api-reference).

## Панели мониторинга — метки {#tagging}

Это готовые к повторному использованию элементы управления, с которыми можно фильтровать данные несколькими щелчками мыши, не составляя выражения вручную.

### Распространение {#broadcast-filters}

Если включен параметр **Broadcast filter condition**, выбранные значения применяются как условие фильтрации к плиткам панели мониторинга, даже если ни одна плитка явно не ссылается на фильтр. По умолчанию условие действует на все плитки. С помощью параметра **Applies to sources** его можно ограничить плитками, использующими заданный набор источников, — это полезно, когда выражение фильтра имеет смысл лишь для части данных на панели мониторинга.

Плитки, созданные в конструкторе графиков, подхватывают распространяемые фильтры автоматически. Плитки Raw SQL должны содержать [макрос `$__filters`](/ru/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro) и иметь выбранный источник, поскольку интерфейс не может автоматически определить, в какое место написанного вручную запроса подставить условие.

### Переменные {#dashboard-variables}

Если включён параметр **Available as variable**, выбранные в фильтре значения также становятся доступны в запросах плиток как `$variableName`. По умолчанию **Variable name** совпадает с отображаемым именем фильтра, из которого удалены недопустимые символы; это значение можно переопределить. Имена должны начинаться с буквы и могут содержать только буквы, цифры и символы подчёркивания.

Используйте переменную, когда распространение условия `WHERE` вам не подходит — например, чтобы подставить значение в выражение `SELECT`, секцию `HAVING` или ключ JOIN, либо чтобы отфильтровать плитку по столбцу, отличному от собственного выражения фильтра.

#### Ссылка на переменную {#referencing-variables}

Переменная раскрывается в значения, выбранные в данный момент в её раскрывающемся списке. От формы ссылки зависит результат подстановки:

| Ссылка              | Раскрывается в                                                                                                                                                                                     | Пустой выбор  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| `$name`, `${name}`  | Выбранные значения в формате `sqlstring` или `lucene` в зависимости от контекста. Фигурные скобки отделяют имя, если за ним следуют буквы, цифры или символы подчёркивания, как в `${name}_total`. | `NULL`        |
| `${name:sqlstring}` | Выбранные значения в одинарных кавычках, через запятую, экранированные как значения SQL, например `'a', 'b'`                                                                                       | `NULL`        |
| `${name:csv}`       | Без кавычек, через запятую: `a,b`. Экранирование для SQL не выполняется.                                                                                                                           | пустая строка |
| `${name:regex}`     | Альтернация в регулярном выражении с экранированием: `(a\|b)`.                                                                                                                                     | `.*`          |
| `${name:lucene}`    | Термы в кавычках, объединённые через `OR`, для полей ввода Lucene: `("a" OR "b")`.                                                                                                                 | `("")`        |

Поскольку `$name` подставляется как `NULL`, пока ничего не выбрано, везде, где ожидается SQL-предикат, лучше использовать следующие макросы. Оба макроса раскрываются в `1=1`, пока для их переменной ничего не выбрано, поэтому запрос остаётся корректным:

| Макрос                                        | Описание                                                                                                                           |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | Раскрывается в `toString(<filter expression>) IN ($variable)`, если для `variable` выбраны значения, и в `1=1` в противном случае. |
| `$__filter(<expression>, $<variable>)`        | Раскрывается в `<expression> IN ($variable)`, если для `variable` выбраны значения, и в `1=1` в противном случае.                  |
| `$__conditionalAll(<condition>, $<variable>)` | Раскрывается в `<condition>`, если для переменной что-либо выбрано, и в `1=1` в противном случае.                                  |

#### Использование переменных в плитках конструктора графиков {#variables-in-builder-tiles}

Каждое поле ввода SQL-выражения в конструкторе графиков поддерживает ссылки на переменные: столбцы `SELECT` и выражения отдельных серий, `WHERE`, `GROUP BY` и `HAVING`. Редактор предлагает автодополнение для переменных панели мониторинга и показывает, во что раскрывается каждая ссылка при текущей выборке.

В режиме SQL рекомендуется использовать макросы `$__filter` и `$__conditionalAll`, чтобы запросы оставались корректными, даже если в переменных ничего не выбрано. В полях ввода Lucene макросы недоступны — используйте там ссылки на необработанные переменные (например, `ServiceName:$service`).

В поле ввода Lucene способ сопоставления выборки из нескольких значений зависит от того, заключена ли сама ссылка на переменную в кавычки. Например, если для `$service` выбрано `a,b`:

| Ссылка                   | Раскрывается в                         | Способ сопоставления                                                                                 |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `ServiceName:$service`   | `ServiceName:("a" OR "b")`             | Совпадение по подстроке — в SQL преобразуется в `ServiceName ILIKE '%a%' OR ServiceName ILIKE '%b%'` |
| `ServiceName:"$service"` | `(ServiceName:"a" OR ServiceName:"b")` | Точное совпадение с каждым выбранным значением                                                       |

Заключайте ссылку на переменную в кавычки (`Field:"$var"`), если выбранные значения должны точно совпадать с `Field`, а не сопоставляться как подстроки.

#### Использование переменных в SQL-плитках {#variables-in-sql-tiles}

В плитках Raw SQL переменные указываются так же — в любом месте запроса:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

Полный список макросов, доступных в SQL-плитках, см. в разделе [Визуализации на основе SQL](/ru/clickstack/observability/features/dashboards/sql-visualizations#dashboard-variables).

<Note>
  Оповещения для плитки, которая ссылается на переменную панели мониторинга, вычисляются с пустыми значениями всех переменных, а не со значениями, выбранными на панели мониторинга.
</Note>

Эта панель мониторинга позволяет исследовать события Kubernetes, собранные с помощью OpenTelemetry. Она поддерживает расширенную фильтрацию: данные можно фильтровать по поду Kubernetes, развертыванию (Deployment), имени узла, пространству имен и кластеру, а также выполнять полнотекстовый поиск.

Для удобства навигации данные Kubernetes распределены по трем вкладкам: Pods, Nodes и Namespaces.
