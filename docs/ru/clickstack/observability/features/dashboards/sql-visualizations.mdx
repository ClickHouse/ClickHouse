ClickHouse Observability поддерживает визуализации на основе запросов на Raw SQL. Это дает полный контроль над логикой запроса, сохраняя при этом интеграцию с временными диапазонами и фильтрами на уровне панели мониторинга, а также с отрисовкой чартов.

Визуализации на основе SQL пригодятся, когда возможностей встроенного Обозревателя диаграмм недостаточно — например, чтобы выполнить JOIN таблиц или построить сложные агрегации, которые не поддерживаются конструктором графиков.

## Создание визуализации на основе SQL {#creating-a-raw-sql-chart}

Чтобы создать визуализацию на основе SQL, откройте редактор плитки дашборда и выберите **SQL**.

<div className="ch-image-lg">
  <Frame>
    ![Редактор SQL-визуализации с инструкциями по составлению запроса и макросами](/images/clickstack/observability-sql-editor.png)
  </Frame>
</div>

Далее:

1. Выберите **Connection** (соединение), через которое будет выполняться запрос.
2. При необходимости выберите **Source** (источник) — это позволит применять к чарту фильтры уровня дашборда с помощью макроса `$__filters`.
3. Напишите SQL-запрос в редакторе, используя параметры запроса и макросы для связи с временным диапазоном, фильтрами и переменными дашборда.
4. Нажмите **Run**, чтобы просмотреть результаты, а затем **Save**, чтобы сохранить визуализацию.

## Параметры запроса {#query-parameters}

[Параметры запроса](/ru/reference/syntax#defining-and-using-query-parameters) позволяют обращаться в SQL к текущему временному диапазону и гранулярности панели мониторинга. Для них используется синтаксис параметризованных запросов ClickHouse: `{paramName:Type}`.

### Доступные параметры {#available-parameters}

Набор доступных параметров зависит от типа диаграммы:

**Диаграммы временных рядов (включая столбчатые диаграммы с накоплением):**

| Параметр                        | Тип   | Описание                                                                            |
| ------------------------------- | ----- | ----------------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Начало диапазона дат панели мониторинга (в миллисекундах от начала отсчёта времени) |
| `{endDateMilliseconds:Int64}`   | Int64 | Конец диапазона дат панели мониторинга (в миллисекундах от начала отсчёта времени)  |
| `{intervalSeconds:Int64}`       | Int64 | Размер временного интервала в секундах (определяется гранулярностью)                |
| `{intervalMilliseconds:Int64}`  | Int64 | Размер временного интервала в миллисекундах (определяется гранулярностью)           |

**Диаграммы типа «Таблица», «Круговая диаграмма» и «Число»:**

| Параметр                        | Тип   | Описание                                                                            |
| ------------------------------- | ----- | ----------------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Начало диапазона дат панели мониторинга (в миллисекундах от начала отсчёта времени) |
| `{endDateMilliseconds:Int64}`   | Int64 | Конец диапазона дат панели мониторинга (в миллисекундах от начала отсчёта времени)  |

## Макросы {#macros}

Макросы — это сокращения, которые раскрываются в часто используемые выражения ClickHouse SQL. Они начинаются с префикса `$__` и заменяются до отправки запроса в ClickHouse.

### Макросы границ временного диапазона {#time-boundary-macros}

Эти макросы возвращают выражение ClickHouse, задающее время начала или окончания временного диапазона панели мониторинга. Аргументов они не принимают.

| Макрос           | Раскрывается в                                                        | Тип столбца |
| ---------------- | --------------------------------------------------------------------- | ----------- |
| `$__fromTime`    | `toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))` | DateTime    |
| `$__toTime`      | `toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))`   | DateTime    |
| `$__fromTime_ms` | `fromUnixTimestamp64Milli({startDateMilliseconds:Int64})`             | DateTime64  |
| `$__toTime_ms`   | `fromUnixTimestamp64Milli({endDateMilliseconds:Int64})`               | DateTime64  |
| `$__interval_s`  | `{intervalSeconds:Int64}`                                             | Int64       |

### Макросы фильтрации по времени {#time-filter-macros}

Эти макросы генерируют фрагмент предложения `WHERE`, который ограничивает значения столбца временным диапазоном панели мониторинга.

| Макрос                                | Описание                                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------------- |
| `$__timeFilter(column)`               | Фильтрует столбец `DateTime` по диапазону панели мониторинга                                |
| `$__timeFilter_ms(column)`            | Фильтрует столбец `DateTime64` (с точностью до миллисекунд) по диапазону панели мониторинга |
| `$__dateFilter(column)`               | Фильтрует столбец `Date` по диапазону панели мониторинга                                    |
| `$__dateTimeFilter(dateCol, timeCol)` | Фильтрует по отдельным столбцам `Date` и `DateTime`                                         |
| `$__dt(dateCol, timeCol)`             | Псевдоним для `$__dateTimeFilter`                                                           |

**Пример раскрытия** макроса `$__timeFilter(TimestampTime)`:

```sql
TimestampTime >= toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
AND TimestampTime <= toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
```

### Макросы временных интервалов {#time-interval-macros}

Эти макросы разбивают столбец временной метки на интервалы, соответствующие гранулярности панели мониторинга. Обычно они используются в секциях `SELECT` и `GROUP BY` в диаграммах временных рядов. Эти макросы доступны только для визуализаций типа **временной ряд**, включая столбчатые диаграммы с накоплением.

| Макрос                       | Описание                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `$__timeInterval(column)`    | Разбивает столбец типа `DateTime` на интервалы длительностью `intervalSeconds`        |
| `$__timeInterval_ms(column)` | Разбивает столбец типа `DateTime64` на интервалы длительностью `intervalMilliseconds` |

**Пример раскрытия** макроса `$__timeInterval(TimestampTime)`:

```sql
toStartOfInterval(toDateTime(TimestampTime), INTERVAL {intervalSeconds:Int64} second)
```

### Макрос фильтров панели мониторинга {#dashboard-filter-macro}

| Макрос       | Описание                                                                               |
| ------------ | -------------------------------------------------------------------------------------- |
| `$__filters` | Заменяется условиями фильтрации уровня панели мониторинга (требуется выбрать источник) |

Если на чарте выбран **источник** и активны фильтры панели мониторинга, `$__filters` раскрывается в соответствующие условия SQL `WHERE`. Если источник не выбран или фильтры не применены, макрос раскрывается в `(1=1)`, поэтому его всегда можно безопасно использовать в предложении `WHERE`.

`$__filters` применяет только фильтры, для которых включён параметр **Broadcast filter condition**. На фильтры, доступные в виде переменных, нужно ссылаться явно, как описано ниже.

### Макросы переменных панели мониторинга {#dashboard-variables}

Если фильтр панели мониторинга [доступен как переменная](/ru/clickstack/observability/features/dashboards/overview#dashboard-variables), на выбранные в нём значения можно ссылаться в любом месте запроса. Эти макросы доступны только в плитках панели мониторинга, в которой объявлена хотя бы одна переменная.

| Макрос                                        | Описание                                                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | Разворачивается в `toString(<filter expression>) IN ($variable)`, если для `variable` выбраны значения, и в `1=1` в противном случае. |
| `$__filter(<expression>, $<variable>)`        | Разворачивается в `<expression> IN ($variable)`, если для `variable` выбраны значения, и в `1=1` в противном случае.                  |
| `$__conditionalAll(<condition>, $<variable>)` | Разворачивается в `<condition>`, если в переменной что-либо выбрано, и в `1=1` в противном случае.                                    |

Значения переменной также можно подставлять напрямую в виде `$name` или `${name}`, при необходимости указав формат: `${name:sqlstring}` (по умолчанию), `${name:csv}` или `${name:regex}`. В формате по умолчанию прямая ссылка, пока ничего не выбрано, формирует `NULL`, поэтому там, где ожидается предикат, лучше использовать приведённые выше макросы.

## Как результаты запроса отображаются на чартах {#how-results-are-plotted}

Интерфейс автоматически сопоставляет столбцы результата с элементами чарта в зависимости от типов столбцов. Правила сопоставления различаются для разных типов чартов.

### Диаграммы временных рядов {#line-and-stacked-bar-charts}

| Роль                | Тип столбца                          | Описание                                                                                            |
| ------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| **Временная метка** | Первый столбец `Date` или `DateTime` | Используется в качестве оси X.                                                                      |
| **Значение серии**  | Все числовые столбцы                 | Каждый числовой столбец отображается как отдельная серия. Как правило, это агрегированные значения. |
| **Имена групп**     | Столбцы `String`, `Map` или `Array`  | Необязательно. Строки с разными значениями группы отображаются как отдельные серии.                 |

### Круговая диаграмма {#pie-chart}

| Роль                 | Тип столбца                         | Описание                                                                        |
| -------------------- | ----------------------------------- | ------------------------------------------------------------------------------- |
| **Значение сектора** | Первый числовой столбец             | Определяет размер каждого сектора.                                              |
| **Метка сектора**    | Столбцы `String`, `Map` или `Array` | Необязательно. Каждое уникальное значение становится меткой отдельного сектора. |

### Числовой индикатор {#number-chart}

| Роль      | Тип столбца             | Описание                                                          |
| --------- | ----------------------- | ----------------------------------------------------------------- |
| **Число** | Первый числовой столбец | Отображается значение из первой строки первого числового столбца. |

### Табличная диаграмма {#table-chart}

Все столбцы результата выводятся непосредственно как столбцы таблицы.

## Примеры {#examples}

<Info>
  **Имена таблиц в примерах**

  В примерах используются таблицы `otel_logs` и `otel_traces`. Измените имена таблиц и столбцов в соответствии с вашими данными. При выполнении примеров на [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) используйте `otel_v2.otel_logs` или `otel_v2.otel_traces`.
</Info>

### Чарт временного ряда — количество записей журнала во времени по сервисам {#example-line-chart}

Этот запрос подсчитывает события журнала для каждого сервиса, распределяя их по временным интервалам в соответствии с гранулярностью панели мониторинга.

```sql
SELECT
  toStartOfInterval(TimestampTime, INTERVAL {intervalSeconds:Int64} second) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

* `ts` (`DateTime`) используется в качестве временной метки по оси X.
* `count` (числовое значение) отображается как значение серии.
* `ServiceName` (строка) задаёт отдельную линию для каждого сервиса.

### Чарт временного ряда с использованием макросов {#example-line-chart-macros}

Тот же запрос, для краткости записанный с использованием макросов:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

### Чарт временного ряда с переменными дашборда {#example-line-chart-variables}

Пусть на панели мониторинга есть переменная `service` для столбца `ServiceName` и переменная `severity` для столбца `SeverityText`. Тогда этот запрос ограничивает чарт выбранными сервисами и исключает выбранные уровни важности. Пока в переменной ничего не выбрано, соответствующий макрос разворачивается в `1=1`, поэтому чарт отображается без фильтрации, пока пользователь не выберет значение.

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

### Столбчатая диаграмма с накоплением — количество ошибок по уровням серьёзности {#example-stacked-bar}

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  lower(SeverityText),
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND lower(SeverityText) IN ('error', 'warn')
  AND $__filters
GROUP BY SeverityText, ts
ORDER BY ts ASC
```

### Табличная диаграмма — топ-10 самых медленных конечных точек {#example-table}

```sql
SELECT
  SpanName AS endpoint,
  avg(Duration) / 1000 AS avg_duration_ms,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY SpanName
ORDER BY avg_duration_ms DESC
LIMIT 10
```

### Круговая диаграмма — распределение запросов по сервисам {#example-pie}

```sql
SELECT
  ServiceName,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY ServiceName
```

* `request_count` (числовое значение) определяет размер каждого сектора.
* `ServiceName` (строка) задаёт подпись каждого сектора.

### Числовой индикатор — общее количество ошибок {#example-number}

```sql
SELECT
  count() AS total_errors
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND SeverityText = 'error'
  AND $__filters
```

Отображается одно числовое значение `total_errors` из первой строки.

## Примечания {#notes}

* Визуализации на основе SQL выполняются с включенным режимом `readonly` — допускаются только `SELECT`-запросы.
* Каждая визуализация на основе SQL поддерживает только один запрос; несколько запросов не поддерживаются.
* Редактор SQL предлагает автодополнение как для параметров запроса, так и для макросов.
* Чтобы применять фильтры панели мониторинга к визуализациям на основе SQL, необходимо выбрать источник. Для корректной фильтрации источник должен соответствовать запрашиваемой таблице.
* Для переменных дашборда источник не требуется: их значения берутся из раскрывающихся списков фильтров панели мониторинга, а не из собственного источника плитки.
* Оповещения для SQL-плитки, которая ссылается на переменную дашборда, вычисляются со всеми переменными в пустом состоянии, а не со значениями, выбранными на панели мониторинга.
