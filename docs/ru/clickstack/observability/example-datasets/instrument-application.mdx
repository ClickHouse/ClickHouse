    HackerNews Analyzer — это приложение на Node.js, которое выполняет запросы к набору данных HackerNews, размещённому в публичной демонстрационной среде ClickHouse. Действия пользователя на панели мониторинга порождают запросы к бэкенду. Запросы, которые не удаётся обслужить из кэша приложения, дополнительно обращаются к ClickHouse и добавляют в трассу исходящий HTTPS-спан.

    Эта демонстрация объединяет в одном приложении автоматическое инструментирование серверной части, спаны запросов к ClickHouse и воспроизведение сеансов в браузере.

## Предварительные требования {#prerequisites}

    * Версии Node.js и npm, совместимые с [HackerNews Analyzer и его зависимостями](https://github.com/ClickHouse/hn-news-analyzer#readme).
    * Развёрнутый полностью управляемый сервис ClickHouse Observability. См. [руководство «Начало работы» для полностью управляемого варианта](/ru/clickstack/observability/getting-started).
    * Сетевой доступ к управляемой конечной точке телеметрии как с сервера приложения, так и из браузера.

## Клонирование репозитория {#clone-the-repository}

    Клонируйте репозиторий [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), установите зависимости и скопируйте шаблон файла переменных окружения:

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    На следующих шагах вы заполните `.env`, а затем выполните инструментирование из этого каталога.

## Инструментирование приложения {#instrument-the-application}

    <Steps>
      <Step title="Запустите приложение" id="run-the-application">
        Запустите приложение из клонированного каталога `hn-news-analyzer`. По умолчанию источник данных ClickHouse подключается к публичному демонстрационному кластеру с доступом только для чтения, поэтому приложение работает без дополнительной настройки:

        ```bash
        ./run.sh
        ```

        Откройте [http://localhost:5001](http://localhost:5001). Вы увидите селектор года, сводную статистику, чарт активности, таблицы самых активных пользователей и популярных доменов, а также поле поиска. Изучите интерфейс: переключайте годы, открывайте отдельные истории и изучайте подробности.

        На этом этапе приложение уже работает, но ещё не инструментировано. Оно начнёт отправлять телеметрию после того, как вы выполните описанные ниже шаги по инструментированию.
      </Step>

      <Step title="Настройте окружение" id="configure-environment">
        Откройте сервис ClickHouse Observability и перейдите в **Team Settings → Managed Telemetry**. Скопируйте **OTLP HTTP endpoint** и **API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Раздел Managed Telemetry в Team Settings с замаскированными конечной точкой OTLP HTTP и ключом API](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        В файле `.env` приложения задайте следующие значения, подставив вместо плейсхолдеров конечную точку и ключ API:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Оставьте префикс `https://` в `OTEL_EXPORTER_OTLP_ENDPOINT` и не добавляйте в конец `/v1/logs`, `/v1/traces` или `/v1/metrics`: SDK сами добавляют пути для каждого типа сигнала. Задайте для `OTEL_EXPORTER_OTLP_HEADERS` значение `authorization=<your-api-key>` без префикса `Bearer`; приложение также передаёт этот ключ напрямую в браузерный SDK.

        Браузерный SDK использует ту же конечную точку и тот же ключ API. `vite.config.ts` встраивает их в браузерный bundle, где посетители сайта могут их увидеть. Используйте сервис, предназначенный для тестирования этой демонстрации, и не добавляйте `.env` в систему контроля версий.
      </Step>

          <Tab title="Ручное инструментирование" id="instrument-manually">
            Инструментирование состоит из трёх шагов: установка SDK, изменение команды запуска и включение браузерного SDK. Бизнес-логика приложения при этом никак не меняется.

### Установка Node SDK {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### Включение обёртки в run.sh {#enable-run-sh-wrapper}

            В конце `run.sh` есть две строки `exec`. Закомментируйте строку с обычным `node` и раскомментируйте инструментированную:

            ```diff
             # ДО: обычный node, без инструментирования:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # ПОСЛЕ: тот же исходный код, обёрнутый opentelemetry-instrument:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            По-прежнему запускайте приложение через `scripts/entrypoint.js`. Эта прослойка вызывает `require('console')`, чтобы перехват консоли оборачивал `console.log`. Если направить `opentelemetry-instrument` напрямую на `dist/server/index.js`, трассировка будет отправляться, но логи будут молча теряться.

### Включение браузерного SDK {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            В `src/web/telemetry.ts` раскомментируйте импорт, блок `HyperDX.init` и вызов `HyperDX.addAction` в `recordAction`:

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` и `__OTLP_AUTH_TOKEN__` — это константы времени компиляции, которые `vite.config.ts` подставляет из тех же значений `OTEL_EXPORTER_OTLP_*`, что использует серверная часть.
          </Tab>

      <Step title="Сгенерируйте трафик и просмотрите телеметрию" id="generate-traffic-and-view-telemetry">
        Перезапустите приложение, чтобы применить новую команду запуска и заново собранный браузерный бандл:

        ```bash
        # Ctrl-C the previous run, then:
        ./run.sh
        ```

        Убедитесь, что при запуске выводятся три строки `Health check passed` для `/v1/traces`, `/v1/metrics` и `/v1/logs`. Перезагрузите вкладку браузера, чтобы Vite отдал обновлённый bundle, затем переключите годы и откройте несколько историй, чтобы сгенерировать трафик.

        Откройте свой сервис ClickHouse Observability:

        1. Перейдите в раздел **Поиск**, выберите источник **Logs** и установите временной диапазон **Last 15 minutes**. Отфильтруйте `ServiceName` по значению `hn-analyzer-api`, чтобы найти журналы бэкенда.

        3. Откройте **Клиентские сеансы**, выберите сеанс от `hn-analyzer-web` и откройте **Session Replay**, чтобы просмотреть действия пользователя в браузере.

        <Frame>
          <img src="/images/clickstack/getting-started/observability-hackernews-sessions.png" alt="Воспроизведение сеанса в ClickHouse Observability с HackerNews Analyzer, событиями обновления панели мониторинга и поиска" />

        4. Откройте **Обозреватель диаграмм**, выберите **Time Series** и источник **Metrics**, затем выберите метрику, которую отправляет приложение. Задайте фильтр `ResourceAttributes.service.name:"hn-analyzer-api"`, выберите временной диапазон, охватывающий период тестирования, и нажмите **Выполнить**, чтобы убедиться, что данные метрик поступают.

    HackerNews Analyzer — это приложение на Node.js, которое выполняет запросы к набору данных HackerNews, размещённому в публичной демо-среде ClickHouse. Каждый график, таблица и поле поиска — это реальный запрос к ClickHouse, поэтому любое взаимодействие порождает трассировку, основной спан которой — HTTPS-вызов от бэкенда к ClickHouse.

    Этот сценарий отличается от [демонстрации воспроизведения сеансов](/ru/clickstack/observability/example-datasets/session-replay), где инструментируется приложение, работающее только в браузере, а телеметрия отправляется в ClickHouse Observability. Здесь из одного и того же приложения вы получаете автоматическое инструментирование бэкенда, спаны запросов к ClickHouse и воспроизведение сеансов.

## Предварительные требования {#prerequisites-self-configured}

    * Node 18+ и npm
    * Существующий самоуправляемый сервис ClickHouse Observability и запущенный коллектор для ингестии.
    * Конечная точка OTLP HTTP коллектора, доступная как с сервера приложения, так и из вашего браузера. Используйте `http://localhost:4318`, только если коллектор запущен на той же машине.
    * `OTLP_AUTH_TOKEN` коллектора, если он настроен. Задайте заголовки в виде `authorization=<token>` без префикса `Bearer`. Если коллектор не требует аутентификации, оставьте значение `authorization=` пустым. Это учётные данные коллектора для ингестии, а не учётные данные вашей базы данных ClickHouse.
