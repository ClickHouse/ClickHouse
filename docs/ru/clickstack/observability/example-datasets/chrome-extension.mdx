## Обзор {#overview}

    [Расширение HyperDX для Chrome](https://github.com/kyreddie/hyperdx-chrome-extension) внедряет SDK [@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) в посещаемые вами страницы. Оно пригодится, когда нужно отладить воспроизведение сеанса, RUM или распространение трассировки на сайте, не изменяя его кодовую базу, — например, в стороннем приложении, продакшн-сборке или на локальном сервере разработки со строгой политикой безопасности контента (Content Security Policy, CSP).

    SDK входит в состав расширения (~480 KB), поэтому страницам не нужно загружать скрипты из CDN во время выполнения. Сначала расширение пытается внедрить скрипт как внешний через `chrome-extension://`, а если CSP блокирует скрипты из источника расширения, переходит к резервному варианту — встроенному внедрению.

    В отличие от [Демонстрации воспроизведения сеансов](/ru/clickstack/observability/example-datasets/session-replay), где инструментируется подконтрольное вам демо-приложение, при этом подходе инструментируются поддерживаемые страницы, которые вы открываете в Chrome; на некоторых страницах внедрение скриптов ограничено. Данные сеансов формируются, когда вы взаимодействуете с сайтом как обычный пользователь.

    Общие сведения о воспроизведении сеансов и о том, какое место эта возможность занимает в ClickHouse Observability, см. на странице [Воспроизведение сеанса](/ru/clickstack/observability/features/session-replay).

## Предварительные требования {#prerequisites}

    * Google Chrome или браузер на базе Chromium (Edge, Brave и т. д.)
    * Развёрнутый полностью управляемый сервис ClickHouse Observability. См. [руководство «Начало работы» для полностью управляемой версии](/ru/clickstack/observability/getting-started).

## Запуск демонстрации {#running-the-demo}

    <Steps>
      <Step title="Клонируйте репозиторий расширения" id="clone-extension">
        ```shell
        git clone https://github.com/kyreddie/hyperdx-chrome-extension
        cd hyperdx-chrome-extension
        ```
      </Step>

      <Step title="Установите расширение" id="install-extension">
        1. Откройте Chrome и перейдите по адресу `chrome://extensions`.
        2. Включите **Developer mode** (в правом верхнем углу).
        3. Нажмите **Load unpacked**.
        4. Выберите клонированный каталог `hyperdx-chrome-extension`.

        Расширение появится на панели инструментов под названием **HyperDX Browser Extension**.
      </Step>

      <Step title="Получите сведения о подключении" id="get-connection-details">
        Откройте свой сервис ClickHouse Observability и перейдите в **Team Settings → Managed Telemetry**. Скопируйте **OTLP HTTP endpoint** и **API key** — они понадобятся для настройки расширения.

        Используйте предоставленную конечную точку HTTPS целиком, вместе с портом, не добавляя к ней `/v1/logs` или `/v1/traces`.

        <div className="ch-image-lg">
          <Frame>
            ![Раздел Managed Telemetry в Team Settings с замаскированными OTLP HTTP endpoint и ключом API](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>
      </Step>

      <Step title="Настройте расширение" id="configure-extension">
        Нажмите на значок **HyperDX Browser Extension** на панели инструментов Chrome и заполните настройки:

        | Поле                                       | Значение для полностью управляемого варианта         | Примечания                                                                                                         |
        | ------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
        | **Включить мониторинг HyperDX**            | Вкл.                                                 | Главный переключатель внедрения                                                                                    |
        | **Service Name**                           | `my-frontend-app`                                    | Обязательно — идентифицирует сервис в ClickHouse Observability                                                     |
        | **API Key**                                | Ваш ключ API управляемой телеметрии                  | Обязательно; скопируйте из **Team Settings → Managed Telemetry**                                                   |
        | **URL коллектора**                         | Ваша конечная точка OTLP HTTP управляемой телеметрии | Замените URL расширения по умолчанию на конечную точку из **Managed Telemetry**                                    |
        | **Environment**                            | `development`                                        | Необязательно — задаёт атрибут ресурса `deployment.environment`                                                    |
        | **Trace Propagation Targets**              | `/api\.myapp\.domain/i, /localhost/i`                | Необязательно — регулярные выражения JavaScript через запятую, определяющие, куда передаются заголовки трассировки |
        | **Внедрять только на соответствующих URL** | Выкл.                                                | Включите, чтобы ограничить набор инструментируемых сайтов                                                          |
        | **Capture console logs**                   | Выкл.                                                | Включите, чтобы пересылать вывод консоли браузера                                                                  |
        | **Advanced network capture**               | Выкл.                                                | Включите для подробного захвата сетевых запросов                                                                   |

        Нажмите **Save Configuration**, затем перезагрузите вкладки, которые нужно инструментировать.
      </Step>

      <Step title="Откройте сайт и создайте сеанс" id="browse-site">
        Откройте в Chrome любой веб-сайт или локальное приложение — например, [http://localhost:3000](http://localhost:3000), если используете dev-сервер фронтенда.

        Работайте со страницей как обычно: переходите по ссылкам, отправляйте формы, вызывайте ошибки и переключайтесь между представлениями. Если конфигурация корректна, расширение автоматически внедряет Browser SDK при каждой загрузке страницы.
      </Step>

      <Step title="Просмотрите запись сеанса" id="view-session-replay">
        В своём сервисе ClickHouse Observability откройте **Клиентские сеансы** на левой боковой панели. Выберите временной диапазон, который охватывает ваши действия в браузере.

        Ваш сеанс должен появиться в списке с указанием длительности и количества событий. Нажмите кнопку ▶️, чтобы воспроизвести его.

        Переключайтесь между режимами **Highlighted** и **All Events**, чтобы изменить уровень детализации на временной шкале.
      </Step>
    </Steps>

## Фильтрация по URL {#url-filtering}

    По умолчанию, пока мониторинг включён, расширение внедряет SDK на каждую открываемую вами страницу. Чтобы ограничить внедрение определёнными сайтами, включите параметр **Внедрять только на соответствующих URL** и добавьте шаблоны — по одному на строку (или через запятую):

    | Шаблон регулярного выражения | Совпадения                                |
    | ---------------------------- | ----------------------------------------- |
    | `http://homedepot.com/*`     | Только HTTP на `homedepot.com`            |
    | `*://homedepot.com/*`        | HTTP и HTTPS на `homedepot.com`           |
    | `*://*.homedepot.com/*`      | Поддомены, например `www.homedepot.com`   |
    | `https://localhost:3000/*`   | Локальный сервер разработки на порту 3000 |

    Перезагрузите вкладку после сохранения шаблонов URL.

## Проверка внедрения {#verify-injection}

    Откройте DevTools на отслеживаемой странице (вкладка **Console**), перезагрузите страницу и найдите следующие сообщения:

    ```text
    [HyperDX Extension] Configuration valid, injecting HyperDX
    [HyperDX Extension] Injected via extension scripts
    [HyperDX Extension] HyperDX initialized
    ```

    Если CSP блокирует скрипты, загружаемые из расширения, расширение записывает в журнал сообщение о переходе на резервный вариант и повторяет попытку, используя встроенное внедрение.

## Устранение неполадок {#troubleshooting}

    <Accordion title="Сеансы не отображаются в ClickHouse Observability">
      1. Проверьте, нет ли в консоли браузера сообщений лога или ошибок с префиксом `[HyperDX Extension]`
      2. Убедитесь, что переключатель **Включить мониторинг HyperDX** включён, а поле **Service Name** заполнено
      3. Убедитесь, что значения **URL коллектора** и **Ключ API** совпадают со значениями в разделе **Team Settings → Managed Telemetry** вашего сервиса
      4. Измените временной диапазон в представлении «Клиентские сеансы» (например, выберите **Last 15 minutes**)
      5. Выполните принудительное обновление страницы в браузере: `Cmd+Shift+R` (Mac) или `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="Ошибки chrome-extension://invalid/">
      Перезагрузите расширение на странице `chrome://extensions`, затем обновите вкладку с очисткой кэша. Такое происходит, если расширение было обновлено или перезагружено, когда вкладки ещё оставались открытыми.
    </Accordion>

    <Accordion title="Внедрение на сайте отсутствует">
      1. Убедитесь, что мониторинг включен и задано имя сервиса
      2. Если включен параметр **Внедрять только на соответствующих URL**, убедитесь, что URL текущей страницы соответствует одному из ваших шаблонов
      3. Некоторые сайты с помощью CSP блокируют внедрение как скриптов из источника расширения, так и встроенных скриптов — на таких страницах внедрение может оказаться невозможным
    </Accordion>

    <Accordion title="HyperDX: в консоли отсутствует apiKey">
      Введите ключ API из раздела **Team Settings → Managed Telemetry**, сохраните конфигурацию и перезагрузите отслеживаемую страницу. Без этого ключа полностью управляемая ингестия работать не будет.
    </Accordion>

## Конфиденциальность {#privacy}

    Расширение внедряет код обсервабилити в посещаемые вами страницы. Используйте его только на сайтах, которые вам разрешено отлаживать. Не передавайте никому ключи API и не добавляйте их в систему контроля версий.

    ```text
    [HyperDX Extension] HyperDX initialized
    ```

    Если CSP блокирует скрипты, загружаемые из расширения, расширение записывает в журнал сообщение о переходе на резервный вариант и повторяет попытку, используя встроенное внедрение.

## Устранение неполадок {#troubleshooting-self-configured}

    <Accordion title="Сеансы не отображаются в интерфейсе ClickStack">
      1. Проверьте, нет ли в консоли браузера сообщений лога `[HyperDX Extension]` или ошибок
      2. Убедитесь, что переключатель **Включить мониторинг HyperDX** активен, а поле **Service Name** заполнено
      3. Убедитесь, что коллектор запущен, его конечная точка OTLP HTTP доступна из браузера, а ключ API совпадает с токеном аутентификации коллектора
      4. Измените временной диапазон в представлении «Клиентские сеансы» (например, выберите **Last 15 minutes**)
      5. Выполните принудительное обновление страницы в браузере: `Cmd+Shift+R` (Mac) или `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="Ошибки chrome-extension://invalid/">
      Перезагрузите расширение на странице `chrome://extensions`, а затем принудительно обновите вкладку. Такое происходит, если расширение было обновлено или перезагружено, пока вкладки оставались открытыми.
    </Accordion>

    <Accordion title="Нет внедрения на сайте">
      1. Убедитесь, что мониторинг включен и задано имя сервиса
      2. Если включен параметр **Внедрять только на соответствующих URL**, убедитесь, что URL текущей страницы совпадает с одним из ваших шаблонов
      3. Некоторые сайты с помощью CSP блокируют внедрение как скриптов из расширения, так и встроенных скриптов — на таких страницах внедрение может оказаться невозможным
    </Accordion>

    <Accordion title="HyperDX: в консоли отсутствует apiKey">
      Если коллектор требует аутентификации, введите его токен в поле **API Key**, сохраните конфигурацию и перезагрузите отслеживаемую страницу. Не полагайтесь только на сообщение о внедрении: ищите ошибки экспорта в сетевых запросах браузера и журналах коллектора.
    </Accordion>

## Конфиденциальность {#privacy-self-configured}

    Расширение внедряет код обсервабилити в посещаемые вами страницы. Используйте его только на сайтах, которые вам разрешено отлаживать. Не передавайте ключи API третьим лицам и не добавляйте их в систему контроля версий.
