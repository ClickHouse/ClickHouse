<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Бета-версия" />

    [`otelgen`](https://github.com/krzko/otelgen) — это небольшая CLI-утилита на Go, которая генерирует синтетические журналы, трассировки и метрики в формате OTLP. С её помощью можно отправить тестовые данные в полностью управляемый ClickHouse Observability и изучить результаты в разделах Search и Chart Explorer.

    <Steps>
      <Step title="Предварительные требования" id="prerequisites-managed">
        Вам потребуется уже созданный сервис полностью управляемого ClickHouse Observability и сетевой доступ к его управляемой конечной точке телеметрии. См. [руководство «Начало работы» для полностью управляемой версии](/ru/clickstack/observability/getting-started).
      </Step>

      <Step title="Установите otelgen" id="install-otelgen-managed">
        Установка с помощью Homebrew:

        ```shell
        brew install krzko/tap/otelgen
        ```

        Или с помощью Go:

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="Задайте переменные окружения" id="set-env-vars-managed">
        Откройте сервис ClickHouse Observability и перейдите в **Team Settings → Managed Telemetry**. Скопируйте значения **OTLP HTTP endpoint** и **API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Раздел Managed Telemetry в Team Settings с замаскированными OTLP HTTP endpoint и ключом API](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        Укажите конечную точку в виде хоста и порта, удалив префикс `https://`. Например, `https://YOUR_OTEL_ENDPOINT:4318` нужно указать как `YOUR_OTEL_ENDPOINT:4318`. Не добавляйте путь сигнала, например `/v1/logs`.

        ```shell
        export OTEL_ENDPOINT='YOUR_OTEL_ENDPOINT:4318'
        printf "API key: "
        read -r -s OTEL_API_KEY
        printf "\n"
        export OTEL_API_KEY
        ```

        Приведённые ниже команды используют `--protocol http` без `--insecure`, поэтому `otelgen` подключается по HTTPS с проверкой сертификата. Удаление `https://` из аргумента с конечной точкой не отключает TLS. Каждый запрос аутентифицируется ключом API управляемой телеметрии.
      </Step>

      <Step title="Сгенерируйте трассировки" id="generate-traces-managed">
        Отправьте небольшую серию трасс из нескольких спанов:

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate` — количество трасс в секунду, а `--duration` — длительность запуска в секундах. Не указывайте `--insecure`, чтобы соединение шло по HTTPS с проверкой сертификата.
      </Step>

      <Step title="Сгенерируйте журналы" id="generate-logs-managed">
        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          logs multi --duration 10
        ```
      </Step>

      <Step title="Сгенерируйте метрики" id="generate-metrics-managed">
        Выполните следующую команду для генерации метрик, а через несколько секунд остановите её, нажав `Ctrl+C`.

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          metrics sum
        ```

        `otelgen` также поддерживает подкоманды `gauge`, `histogram`, `up-down-counter` и `exponential-histogram` команды `metrics`.
      </Step>

      <Step title="Проверьте данные в ClickHouse Observability" id="verify-managed">
        В сервисе ClickHouse Observability откройте **Search** и, переключаясь между источниками **Logs** и **Traces**, убедитесь, что появились новые события. Установите временной диапазон **Last 15 minutes** и найдите имя сервиса по умолчанию — `otelgen`.

        Откройте **Chart Explorer**, выберите **Metrics** и постройте чарт `otelgen.metrics.sum`, чтобы убедиться, что метрики поступают.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Самоуправляемый">
    [`otelgen`](https://github.com/krzko/otelgen) — это небольшая CLI-утилита на Go, которая генерирует синтетические журналы, трассировки и метрики OTLP. С её помощью можно убедиться, что уже развернутый коллектор ClickStack OpenTelemetry принимает данные, а события отображаются в интерфейсе обсервабилити.

    В этом руководстве предполагается, что коллектор уже запущен и его конечные точки OTLP доступны на портах `4317` (gRPC) и `4318` (HTTP).

    <Steps>
      <Step title="Предварительные требования" id="prerequisites-managed-self-configured">
        В этом руководстве предполагается, что вы выполнили шаги из [руководства «Начало работы» для ClickHouse Observability — Self-managed](/ru/clickstack/self-configured/getting-started/managed) и у вас запущен OpenTelemetry Collector, конечные точки OTLP gRPC (`4317`) и HTTP (`4318`) которого доступны с машины, где вы запускаете `otelgen`. Если вы [защитили коллектор](/ru/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured) с помощью `OTLP_AUTH_TOKEN`, держите это значение под рукой.
      </Step>

      <Step title="Установка otelgen" id="install-otelgen-managed-self-configured">
        Установка с помощью Homebrew:

        ```shell
        brew install krzko/tap/otelgen
        ```

        Или с помощью Go:

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="Настройка переменных окружения" id="set-env-vars-managed-self-configured">
        Экспортируйте конечную точку коллектора и, если коллектор защищён, токен аутентификации:

        ```shell
        export OTEL_ENDPOINT=<host>:4317
        export OTLP_AUTH_TOKEN=<your_otlp_auth_token>
        ```

        Укажите хост и порт вашего коллектора. Если коллектор запущен на той же машине, это `localhost:4317`.

        <Info>
          **Незащищённый коллектор**

          По умолчанию коллектор ClickStack OpenTelemetry не требует аутентификации. Если вы не задавали `OTLP_AUTH_TOKEN` по инструкции из раздела [Защита коллектора](/ru/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured), пропустите здесь `OTLP_AUTH_TOKEN` и уберите флаг `--header` из приведённых ниже команд.
        </Info>
      </Step>

      <Step title="Генерация трассировок" id="generate-traces-managed-self-configured">
        Отправьте короткую серию трасс из нескольких спанов:

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate` задаёт количество трасс в секунду, а `--duration` — длительность запуска в секундах. `--insecure` отключает TLS для gRPC-соединения; это необходимо, когда `otelgen` отправляет данные на незашифрованный порт OTLP коллектора.
      </Step>

      <Step title="Генерация журналов" id="generate-logs-managed-self-configured">
        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          logs multi
        ```
      </Step>

      <Step title="Генерация метрик" id="generate-metrics-managed-self-configured">
        Подкоманды для метрик игнорируют `--duration`. Запустите команду и через несколько секунд остановите её, нажав `Ctrl+C`.

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 \
          metrics sum
        ```

        Кроме того, `otelgen` поддерживает подкоманды `gauge`, `histogram`, `up-down-counter` и `exponential-histogram` в составе `metrics`.
      </Step>

      <Step title="Проверка в интерфейсе обсервабилити" id="verify-managed-self-configured">
        Откройте интерфейс обсервабилити из консоли ClickHouse Cloud. В представлении `Search` переключайте источник между `Logs` и `Traces`, чтобы убедиться, что появились новые события. Установите временной диапазон `Last 15 minutes`. Откройте `Chart Explorer`, выберите `Metrics` и постройте чарт для одной из метрик, созданных `otelgen` (например, `otelgen.metrics.sum`), чтобы проверить приём метрик.
      </Step>
    </Steps>
  </Tab>
</Tabs>
