Страницы ClickHouse Observability можно открывать по глубоким ссылкам с помощью параметров запроса в URL. Так из внешней системы (уведомления об оповещении, runbook, задания CI, сообщения в чате и т. п.) можно сразу перейти к нужному поиску, панели мониторинга или отдельной панели.

В примерах на этой странице используется `<YOUR_CLICKSTACK_URL>`. Замените его на базовый URL вашего интерфейса обсервабилити.

<Note>
  Для удобства чтения параметры запроса в примерах приведены без URL-кодирования. При программном формировании ссылок кодируйте значение каждого параметра запроса.
</Note>

<Info>
  **Параметр идентификатора сервиса Cloud**

  При работе с интерфейсом Cloud ссылки должны содержать параметр `?chcServiceId=`. Он указывает, какой сервис ClickHouse Cloud следует загрузить, если у аутентифицированного пользователя, переходящего по ссылке, есть доступ к нескольким сервисам ClickHouse Cloud.

  Пример: открытие страницы «Поиск» для конкретного сервиса ClickHouse Cloud

  ```text
  https://hyperdx.clickhouse.cloud/search?chcServiceId=abc123
  ```
</Info>

## Поиск — `/search` {#search}

Основное представление поиска по журналам и трассам. Подробнее о синтаксисе поиска см. в разделе [Поиск](/ru/clickstack/observability/features/search).

| Параметр        | Формат                                                                     | Описание                                                                                                                              |
| --------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `source`        | строка                                                                     | Источник для поиска: ID источника или его **имя** (например, `Logs`). На этой странице поддерживаются только источники журналов и трасс. |
| `where`         | строка                                                                     | Текст запроса фильтра в синтаксисе Lucene или SQL (см. `whereLanguage`).                                                              |
| `whereLanguage` | `lucene` | `sql`                                                           | Язык запросов, на котором записан `where`.                                                                                            |
| `select`        | строка                                                                     | Список столбцов или выражений SQL для отображения в таблице результатов.                                                              |
| `filters`       | `{"type":"sql","condition":"<column> IN ('<value1>', '<value2>', ...)"}[]` | Структурированные фасетные фильтры, применяемые в дополнение к `where`.                                                               |
| `orderBy`       | строка                                                                     | SQL-выражение сортировки для таблицы результатов.                                                                                     |
| `mode`          | `results` | `delta` | `pattern`                                            | Активный режим анализа. `delta` доступен только для источников трасс.                                                                 |
| `isLive`        | `true` | `false`                                                           | Включён ли режим live tail (по умолчанию `true`).                                                                                     |
| `traceId`       | строка                                                                     | Сразу открывает каскадное представление трассировки для указанного идентификатора трассы.                                                 |
| `from`, `to`    | миллисекунды с начала эпохи Unix                                           | Абсолютный временной диапазон. Если не задан, по умолчанию используются последние 15 минут.                                           |

Сохранённый поиск также можно открыть напрямую по адресу `/search/<savedSearchId>`.

### Пример: поиск ошибок сервиса `checkout` в источнике `Logs` за заданный временной диапазон {#example-search-errors}

```text
<YOUR_CLICKSTACK_URL>/search?source=Logs&from=1735689600000&to=1735693200000&where=level:error&filters=[{"type":"sql","condition":"ServiceName IN ('checkout')"}]
```

### Пример: переход сразу к каскадному представлению трассы {#example-search-trace}

```text
<YOUR_CLICKSTACK_URL>/search?source=Traces&traceId=ba7217967eb90d040b7eb39f97ecc5c4
```

## Панели мониторинга — `/dashboards/<dashboardId>` {#dashboards}

Сохранённая панель мониторинга. Если не указывать `<dashboardId>` (`/dashboards`), откроется временная несохранённая панель мониторинга. Подробнее о создании панелей мониторинга см. в разделе [Панели мониторинга](/ru/clickstack/observability/features/dashboards/overview).

| Параметр            | Формат                                                                                                                              | Описание                                                                                                                                                                                                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `from`, `to`        | миллисекунды с начала эпохи Unix                                                                                                    | Временной диапазон, применяемый ко всем плиткам. Если не указан, по умолчанию используются последние 15 минут.                                                                                                   |
| `where`             | строка                                                                                                                              | Текст запроса фильтра на уровне панели мониторинга, применяемый ко всем плиткам.                                                                                                                                 |
| `whereLanguage`     | `lucene` | `sql`                                                                                                                    | Язык запросов, на котором записано значение `where`.                                                                                                                                                             |
| `filters`           | JSON-массив записей со значениями фильтров                                                                                          | Выбранные значения [пользовательских фильтров и переменных](/ru/clickstack/observability/features/dashboards/overview#custom-filters) панели мониторинга. См. раздел [Значения фильтров](#dashboard-filter-values). |
| `granularity`       | `auto` | `30 second` | `1 minute` | `5 minute` | `10 minute` | `15 minute` | `30 minute` | `1 hour` | `12 hour` | `1 day` | `7 day` | Размер бакета для плиток с данными time-series. При значении `auto` размер бакета подбирается автоматически в зависимости от выбранного временного диапазона.                                                    |
| `highlightedTileId` | строка                                                                                                                              | Прокручивает страницу к указанной плитке и выделяет её. Удобно при переходе по ссылке из оповещения.                                                                                                             |

### Значения фильтров {#dashboard-filter-values}

Параметр `filters` представляет собой JSON-массив. Каждая запись задаёт выбранные значения одного фильтра в одной из следующих форм:

| Запись                                                                                                            | Назначение                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{"type":"variable","name":"<variableName>","values":["<value1>","<value2>"]}`                                    | Фильтры, являющиеся переменными: фильтры статических значений, значений SQL-запроса и значений меток PromQL, переменные источника данных и соединения, а также фильтры значений SQL-выражения с включённым параметром **Available as variable**. `name` — имя переменной фильтра.                                                      |
| `{"type":"adhoc","name":"<uniqueName>","conditions":[{"key":"<key>","operator":"<operator>","value":"<value>"}]}` | [Ad hoc-фильтры](/ru/clickstack/observability/features/dashboards/overview#adhoc-filters). `name` — уникальное имя фильтра, а `operator` — один из операторов `=`, `!=`, `=~`, `!~`, `LIKE`, `NOT LIKE` или `IN`. `LIKE` и `NOT LIKE` применимы только к SQL-источникам: ad hoc-фильтры Prometheus игнорируют условия с этими операторами. |
| `{"type":"sql","condition":"<expression> IN ('<value1>', '<value2>')"}`                                           | Фильтры значений SQL-выражения, не являющиеся переменными. Выражение в условии должно совпадать с **Filter expression** фильтра.                                                                                                                                                                                                        |

Действуют следующие правила:

* Запись переменной имеет приоритет над записью `sql`, относящейся к тому же фильтру. Ссылки, созданные до появления переменных и использующие записи `sql` для всех фильтров, продолжают работать.
* Для переменных источника данных и соединения в качестве значения можно указать **имя** источника или соединения вместо его ID. Имена сначала сопоставляются точно, а затем без учёта регистра. Благодаря этому ссылки остаются стабильными в разных окружениях, где у одного и того же источника разные ID.
* Фильтр с одиночным выбором использует только первое значение.
* Записи, которые не соответствуют ни одному фильтру на панели мониторинга или имеют некорректный формат, игнорируются.

### Пример: открытие панели мониторинга за заданный временной диапазон с выделенной плиткой {#example-dashboard-highlight}

Удобно, когда ссылка из уведомления об оповещении должна вести сразу к плитке, по которой сработало оповещение.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?from=1735689600000&to=1735693200000&highlightedTileId=chart-1
```

### Пример: выбор значений в фильтрах-переменных {#example-dashboard-variables}

Выбирает `checkout` и `payments` в фильтре с именем переменной `service`, а также `ERROR` в фильтре с именем переменной `severity`.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?filters=[{"type":"variable","name":"service","values":["checkout","payments"]},{"type":"variable","name":"severity","values":["ERROR"]}]
```

### Пример: выбор источника данных и соединения по имени {#example-dashboard-source-variable}

Выбирает источник `Production Logs` в переменной источника данных `logs` и соединение `Production` в переменной соединения `cluster`.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?filters=[{"type":"variable","name":"logs","values":["Production Logs"]},{"type":"variable","name":"cluster","values":["Production"]}]
```

### Пример: добавление условий фильтрации в ad hoc-фильтр {#example-dashboard-adhoc}

Добавляет два условия в ad hoc-фильтр с уникальным именем `adhoc`: `ServiceName` равен `checkout` или `payments`, а `SeverityText` не равен `DEBUG`.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?filters=[{"type":"adhoc","name":"adhoc","conditions":[{"key":"ServiceName","operator":"IN","value":"checkout"},{"key":"ServiceName","operator":"IN","value":"payments"},{"key":"SeverityText","operator":"!=","value":"DEBUG"}]}]
```

## Обозреватель диаграмм — `/chart` {#chart-explorer}

Конструктор графиков для ситуативного анализа, результатами которого можно поделиться.

| Параметр     | Формат                           | Описание                                                                                                                                                            |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config`     | JSON                             | Полная конфигурация чарта (источник, выборка, условие where, тип чарта и т. д.). Как правило, создаётся по ссылкам «Поделиться» в приложении, а не пишется вручную. |
| `from`, `to` | миллисекунды с начала эпохи Unix | Временной диапазон. Если параметры не указаны, по умолчанию используются последние 15 минут.                                                                        |

### Пример: открытие конфигурации чарта задержки p99 за заданный временной диапазон {#example-chart-config}

```text
<YOUR_CLICKSTACK_URL>/chart?granularity=auto&from=1785759381784&to=1785762981785&config={"name":"","select":[{"aggFn":"quantile","aggCondition":"","aggConditionLanguage":"lucene","valueExpression":"Duration","level":0.99,"alias":"p99"}],"where":"","whereLanguage":"lucene","displayType":"line","alignDateRangeToGranularity":true,"source":"68814eb5d40a9d0449afc1f2","connection":"68814b6fd40a9d0449afbe78","groupBy":"ServiceName"}
```

| Параметр        | Формат                           | Описание                                                                                         |
| --------------- | -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `sessionSource` | строка                           | ID или имя источника сеансов.                                                                    |
| `where`         | строка                           | Текст запроса для фильтрации списка сеансов.                                                     |

| Параметр        | Формат                                                                     | Описание                                                                           |
| --------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `tab`           | `http` | `database` | `errors`                                             | Отображаемая вложенная вкладка панели мониторинга сервиса. По умолчанию: `http`    |
| `source`        | строка                                                                     | ID источника трасс.                                                                |
| `service`       | строка                                                                     | Имя выбранного сервиса.                                                            |

| `from`, `to`    | миллисекунды с начала эпохи Unix                                           | Временной диапазон. Если не указан, по умолчанию используются последние 15 минут.  |
