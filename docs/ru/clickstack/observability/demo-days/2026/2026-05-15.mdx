Блокноты теперь умеют создавать оповещения. Тот же сценарий в блокноте, который уже на лету собирает панели мониторинга, теперь сам настроит и оповещение. Так можно перейти от «вот интересный запрос» к «сообщи мне, когда это сработает», не выходя из блокнота.

Есть одна оговорка, о которой стоит знать. В команде настроено множество вебхуков, но пока блокнот не задаёт уточняющих вопросов, поэтому он просто выбирает вебхук, который кажется ему наиболее подходящим, вместо того чтобы дать выбрать вам. Уже готовится PR, который позволит блокнотам задавать уточняющие вопросы, когда им не хватает контекста, так что этот пробел скоро будет устранён.

## Автодополнение на основе materialized view {#autocomplete-from-materialized-views}

*Демо от [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/iQf5EwktBW4" title="Видеоплеер YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Некоторое время назад мы добавили materialized view для автодополнения атрибутов в строке поиска: благодаря этому значения появляются мгновенно, а не вычисляются на лету. Теперь те же MV используются и для боковых фильтров, поэтому на нагруженных инстансах фильтры загружаются значительно быстрее.

Обратите внимание на одно изменение в поведении. Фильтры на основе MV возвращают все возможные значения в пределах текущего временного диапазона, а не только те, что относятся к вашему текущему запросу. С помощью переключателя можно вернуться к фильтрам с учётом поиска, которые выполняют более медленную aggregation по актуальным результатам. Кроме того, увеличено значение `filterValueExpandedKeyLimit` по умолчанию: 20 ключей без MV и 100 ключей с ними; при необходимости его можно повысить сколь угодно (мы проверяли на 1000).

Поддержка MV обходится сравнительно дёшево: она работает на нашем промежуточном инстансе с большим объёмом данных и ведёт себя стабильно. Та же MV используется для автодополнения атрибутов и раскрытия столбцов типа Map, поэтому после её настройки ускорение заметно сразу в нескольких местах. Во время демонстрации обсуждалось, не стоит ли вынести переключатель между фильтрами с учётом поиска и всеми фильтрами из настроек в полноценный переключатель-«пилюлю» в верхней части панели фильтров. Мы планируем рассмотреть это в одной из следующих доработок.

## Порядок столбцов таблицы и форматирование для каждой серии {#table-column-ordering-and-per-series-formatting}

*Демо от [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/iEn8kzvERE8" title="Видеоплеер YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Одновременно вышло несколько связанных улучшений таблиц. Столбцы группировки теперь можно закрепить в левой части таблицы, а не всегда отображать справа. Обычно именно это и нужно для панелей мониторинга в стиле RED, где взгляд скользит вниз по столбцу с именем сервиса. Это поведение задаётся отдельной настройкой отображения для каждой таблицы.

Кроме того, теперь поддерживаются числовые форматы для отдельных серий. Раньше ко всей таблице применялся единый числовой формат, поэтому столбец Requests отображался как `123ms`, если в таблице оказывалась хотя бы одна серия в формате миллисекунд. Теперь формат можно задать для каждого столбца или каждой серии: количество запросов отображается обычными числами, а столбцы задержки — как длительности.

Помимо этого, автоматическое определение формата теперь выполняется для каждой серии отдельно. Если агрегировать по полю Trace Duration, в миллисекундах будет отображаться только эта серия, а остальная таблица не перейдёт на формат миллисекунд лишь потому, что один из столбцов содержит длительность.

## Настраиваемые ссылки между панелями мониторинга {#customizable-dashboard-linking}

*Демо от [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Stlz02xES40" title="Видеоплеер YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Таблицы на панелях мониторинга теперь могут по щелчку по строке вести на другие панели мониторинга (или на страницу поиска), причём и пункт назначения, и передаваемые фильтры можно настраивать с помощью шаблонов. В конфигурации табличной плитки появился новый параметр «Действие при нажатии на строку». Выберите «панель мониторинга», укажите панель мониторинга, на которую нужно перейти, а затем сопоставьте фильтры из текущей строки с фильтрами целевой панели мониторинга. Значения фильтров поддерживают шаблоны в стиле Handlebars, поэтому значение любого столбца из выбранной строки можно подставить в фильтр пункта назначения или в предложение WHERE (на SQL или Lucene). В примере из демонстрации к списку сервисов подключено действие, при котором щелчок по строке открывает панель мониторинга с подробностями о сервисе и уже применённым фильтром по `service.name`.

Вместо выбора конкретной панели мониторинга в качестве пункта назначения можно задать шаблон для самого имени панели мониторинга. Например, если у вас есть отдельные панели мониторинга для каждого сервиса с именами вида `${service.name} dashboard`, ссылка будет вести на ту из них, которая соответствует выбранной строке. Предусмотрена обработка ошибки на случай, если панели мониторинга с таким именем не существует: вместо перехода на нерабочую страницу появляется уведомление.

Поддерживается несколько переменных: в набор фильтров или в шаблон имени панели мониторинга можно передавать любую комбинацию столбцов из выбранной строки. Handlebars поддерживает динамические вспомогательные функции и условные блоки, однако большинство из них пока отключено, чтобы функциональность оставалась компактной и предсказуемой. Обновился и процесс импорта: если панели мониторинга ссылаются на другие панели мониторинга по ID, эти ссылки теперь можно при импорте переназначить на любые панели мониторинга, существующие в аккаунте назначения.
