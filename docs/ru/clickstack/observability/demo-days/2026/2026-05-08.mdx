## Улучшенная обработка секретов в вебхуках {#improved-handling-of-secrets-in-webhooks}

*Демо от [@dhable](https://github.com/dhable)*

</Frame>

URL и заголовки вебхуков нередко содержат учётные данные в открытом виде. В URL вебхука Slack секретный токен находится прямо в пути, а HTTP-вебхуку для аутентификации обычно требуется заголовок авторизации. До этого релиза внутренний API HyperDX для получения списка и редактирования вебхуков возвращал все эти данные в каждом ответе, поэтому любой аутентифицированный участник команды мог прочитать секреты, просто обратившись к API.

Теперь здесь применяется тот же механизм сокрытия конфиденциальных данных, что уже использовался в публичном API. URL вебхуков возвращаются с путём, заменённым на `****`, поэтому токен Slack (или любой другой ключ, встроенный в путь) никогда не покидает сервер. Заголовки по умолчанию тоже маскируются: надёжного способа определить, какие из них содержат секреты, нет, поэтому все значения заменяются на `****` и видны только имена заголовков.

Форма редактирования воспринимает замаскированное значение как «без изменений»: если оставить его как есть, сохранённое значение не изменится; если изменить — будет сохранено новое значение; если очистить — поле будет полностью удалено. Так рабочий процесс остаётся понятным в типичном случае (редактирование одного поля), а реальный секрет никогда не передаётся через браузер туда и обратно.

## Дополнительные метаданные в оповещениях {#extra-metadata-in-alerts}

*Демо от [@dhable](https://github.com/dhable)*

По просьбе участников сообщества в Slack в оповещения добавлена возможность указывать произвольный контекст: историю изменения порогов, ссылки на операционные инструкции или заметки для дежурного инженера. Кроме того, это надёжный источник фактов для AI-сводок: любая LLM, обрабатывающая сработавшее оповещение, теперь может опираться на рассуждения самого оператора, а не угадывать замысел только по запросу.

Поле заметки поддерживает Markdown, поэтому в нём можно использовать сворачиваемые разделы, списки и ссылки. Заметка хранится в конфигурации оповещения и отображается везде, где показывается само оповещение. Интерфейс пока не окончательный: поддержка Markdown — лишь отправная точка, и мы будем рады отзывам о том, как должна выглядеть заметка.

Заодно этот PR улучшает отображение сработавших оповещений в сохранённых поисках. На значке колокольчика на кнопке Оповещения появляется красная точка, когда какое-либо оповещение срабатывает; диалоговое окно выделяет активное оповещение, а не просто ссылается на него, а визуальное оформление теперь совпадает с тем, как то же состояние уже отображается на плитках дашборда.

**Связанные PR:** [#2210](https://github.com/hyperdxio/hyperdx/pull/2210) [HDX-3044] Add optional note field to оповещения

## Возможные темы {#possible-themes}

*Демо от [@elizabetdev](https://github.com/elizabetdev)*

В рамках хакатона мы поэкспериментировали с тремя темами в стиле IDE для интерфейса ClickStack: Nord (арктические синие тона), Catppuccin (пастельные тона) и One Dark (в стиле Atom), каждая — в светлом и тёмном вариантах. Мы попробовали генерировать цветовые токены на основе исходных тем, и это решило бо́льшую часть задачи, хотя остались шероховатости с цветами боковой панели и контрастностью линий, которые ещё нужно было бы доработать.

В итоге PR закрыли без слияния. Команда переходит на ClickUI, который пока поддерживает только одну тему, а сопровождение нескольких параллельных наборов токенов означало бы постоянную дополнительную работу — особенно если как следует проверять контрастность для каждой комбинации. Было решено отложить эту работу, пока сам ClickUI не начнёт поддерживать несколько тем.

Один принцип дизайна из этого эксперимента, на наш взгляд, стоит учесть, когда мы вернёмся к этой задаче. В первой итерации логотип HyperDX перекрашивался под каждую тему, и бренд терял узнаваемость. Более удачный подход: в светлой теме отображается тёмный логотип, в тёмной — светлый, а сам зелёный словесный знак HyperDX остаётся неизменным.
