Elastic Stack предлагает два типа SDK для языков программирования, предназначенных для инструментирования приложений:

1. **[Официальные APM-агенты Elastic](https://www.elastic.co/docs/reference/apm-agents/)** — созданы специально для работы с Elastic Stack. Если вы используете эти агенты, запланируйте переход на [инструментирование OpenTelemetry](https://opentelemetry.io/docs/languages/) для вашего языка, включая все пользовательские спаны и атрибуты, которые использует ваше приложение.

2. **[Elastic Distributions of OpenTelemetry (SDK EDOT)](https://www.elastic.co/docs/reference/opentelemetry/edot-sdks/)** — дистрибутивы стандартных SDK OpenTelemetry от Elastic, доступные для .NET, Java, Node.js, PHP и Python. Если ваше приложение уже использует SDK EDOT, повторно инструментировать код не нужно: достаточно перенастроить SDK на экспорт телеметрических данных в конечную точку OTLP ClickHouse Observability. Подробнее см. в разделе [&quot;Миграция EDOT SDK&quot;](#migrating-edot-sdks-self-configured).

## Миграция EDOT SDK {#migrating-edot-sdks-self-configured}

Elastic Distributions of the OpenTelemetry SDKs (SDK EDOT) — это модифицированные версии официальных SDK OpenTelemetry. Например, [EDOT Python SDK](https://www.elastic.co/docs/reference/opentelemetry/edot-sdks/python/) — это доработанный вендором дистрибутив [OpenTelemetry Python SDK](https://opentelemetry.io/docs/languages/python/), рассчитанный на беспроблемную работу с Elastic Observability.

Поскольку эти SDK основаны на стандартных библиотеках OpenTelemetry, миграция на ClickHouse Observability не вызывает сложностей: повторное инструментирование не требуется. Достаточно изменить Configuration так, чтобы телеметрические данные отправлялись на конечную точку OTLP вашего ClickHouse Observability.

Configuration выполняется стандартными средствами OpenTelemetry. Для Python она, как правило, задаётся через переменные окружения, как описано в [документации OpenTelemetry по инструментированию без изменения кода](https://opentelemetry.io/docs/zero-code/python/configuration/).

Типичная Configuration SDK EDOT может выглядеть так:

```shell
export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
export OTEL_EXPORTER_OTLP_ENDPOINT=https://my-deployment.ingest.us-west1.gcp.cloud.es.io
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=ApiKey P....l"
```

Для миграции обновите настройки подключения OTLP в окружении вашего приложения и перезапустите его. В примерах ниже используется OTLP HTTP с кодированием protobuf.

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Бета-версия" />

    Скопируйте конечную точку OTLP HTTP и ключ API в разделе **Team Settings → Data → Managed Telemetry**:

    ```shell
    export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    Указывайте конечную точку в точности как есть, включая порт, но без суффикса сигнала (например, `/v1/traces`). В значении заголовка `%20` кодирует пробел после `Bearer`. Сведения о подключении см. в разделе [Отправка данных OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry).
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите в SDK доступную конечную точку OTLP HTTP принимающего коллектора:

    ```shell
    export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_COLLECTOR_TOKEN'
    ```

    Если принимающий коллектор защищён с помощью `OTLP_AUTH_TOKEN`, используйте этот токен в качестве значения authorization. Используйте `localhost`, только если приложение и коллектор находятся в одном сетевом пространстве имён. Если в коллекторе включён TLS, укажите его конечную точку HTTPS и настройте SDK так, чтобы он доверял сертификату коллектора. См. раздел [Защита коллектора](/ru/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).

    Если аутентификация коллектора отключена, удалите прежний заголовок Elastic:

    ```shell
    unset OTEL_EXPORTER_OTLP_HEADERS
    ```
  </Tab>
</Tabs>

Если ваше приложение задаёт переменные конечной точки, протокола или заголовков OTLP для отдельных сигналов, обновите и их: они имеют приоритет над приведёнными выше общими настройками. Задавая имя сервиса, сохраните существующие атрибуты ресурса.
