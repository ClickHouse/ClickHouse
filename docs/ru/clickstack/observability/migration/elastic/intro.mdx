## Миграция на ClickHouse Observability с Elastic {#migrating-to-clickstack-from-elastic-self-configured}

В этом руководстве описывается миграция с Elastic Stack, в том числе с развертываний, где Kibana используется для исследования журналов, трасс и метрик, собранных с помощью Elastic Agent и хранящихся в Elasticsearch. Основное внимание уделяется полностью управляемому ClickHouse Observability: здесь рассказывается, как адаптировать поисковые запросы на основе Lucene, перенести сбор телеметрии и спланировать перенос данных. Там, где шаги отличаются, приведены инструкции для самоуправляемого варианта.

ClickHouse Observability — это полностью управляемая платформа для SRE, разработчиков и их агентов. Она сочетает телеметрию с полной детализацией, быстрый поиск, агрегации по high-cardinality данным и SQL для расследования сбоев. Отправляйте телеметрию в управляемую конечную точку OpenTelemetry, а ClickHouse возьмёт на себя ингестию, схемы, инфраструктуру и масштабирование.

Чтобы начать работу, не нужно сопоставлять внутреннее устройство Elasticsearch с ClickHouse. Для самоуправляемых развертываний см. разделы [эквивалентные концепции](/ru/clickstack/self-configured/migration/elastic/concepts) и [сопоставление типов](/ru/clickstack/self-configured/migration/elastic/types).

Переход на ClickHouse Observability стоит рассмотреть, если:

* **Вы хотите использовать собственных SRE-агентов.** Подключайте Claude, Codex или собственную среду агентов через [MCP-сервер ClickStack](/ru/clickstack/observability/mcp) и выбирайте модели и рабочие процессы расследования, которые подходят вашей команде.
* **Вашим агентам недостаточно предопределённых поисковых запросов.** Инструменты MCP поддерживают поиск по журналам, исследование трасс, шаблоны событий и дельты событий. SQL позволяет выполнять JOIN по телеметрии, сравнивать данные с историческими и проводить более глубокий аналитический разбор.
* **Медленные запросы тормозят расследования.** Быстрый поиск и агрегации по high-cardinality телеметрии помогают инженерам и агентам проверять гипотезы и сопоставлять факты.
* **Для анализа первопричин нужна телеметрия с полной детализацией.** Сохраняйте подробные журналы, спаны трасс и атрибуты, которые могут теряться при сэмплировании или предварительной агрегации, — так контекст для расследований остаётся полным.
* **Растущие объёмы телеметрии увеличивают затраты.** Колоночное сжатие и аналитический движок ClickHouse позволяют эффективно хранить и запрашивать большие объёмы телеметрии.
* **Вы хотите тратить меньше времени на эксплуатацию платформы обсервабилити.** Полностью управляемое решение берёт на себя выбор размера базы данных, управление схемами, ингестию и масштабирование.
* **Вы хотите опираться на открытые стандарты.** Используйте OpenTelemetry для сбора данных, SQL для анализа и MCP для доступа агентов — всё это на основе ClickStack с открытым исходным кодом.

ClickHouse Observability может не подойти, если:

* Ваша основная задача — аналитика безопасности, и вам нужен продукт класса SIEM.
* Универсальное профилирование критически важно для вашего рабочего процесса.
* Вам нужна платформа бизнес-аналитики общего назначения, а не рабочие процессы расследования для SRE и разработчиков. В этом случае рассмотрите использование ClickHouse с [Grafana](/ru/integrations/connectors/data-visualization/grafana/index) или [Superset](/ru/integrations/connectors/data-visualization/superset-and-clickhouse).

Если вам нужен прямой доступ к базе данных, чтобы объединять телеметрию с внешними бизнес-данными, или вы хотите самостоятельно оптимизировать базу данных, рассмотрите [самостоятельно управляемый ClickHouse Observability](/ru/clickstack/self-configured/overview). Для большинства команд оптимальным выбором остаётся полностью управляемый вариант.
