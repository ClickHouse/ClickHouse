## Что такое bitdrift? {#what-is-bitdrift}

[bitdrift](https://bitdrift.io/) — это динамическая платформа обсервабилити, созданная специально для мобильных приложений. Она состоит из трёх основных компонентов:

* **[Capture SDK](https://bitdrift.io/feature/performance-centric)** — легковесная кроссплатформенная библиотека на Rust с тонкими обёртками для каждой платформы. Она записывает телеметрию в кольцевой буфер фиксированного размера на устройстве, а не отправляет её сразу.
* **Плоскость управления**, которая поддерживает постоянное двунаправленное соединение с каждым клиентом и в реальном времени доставляет новую конфигурацию, определяя, какие данные собирать и какие загружать.
* **Платформа bitdrift**, где рабочие процессы, временные шкалы сеансов, диаграммы, задачи и оповещения превращают телеметрию мобильных устройств в ответы на вопросы. Платформа доступна через веб-интерфейс, CLI, ИИ-агентов и публичный API.

bitdrift хранит телеметрию мобильных устройств на периферии, пока она не будет запрошена. Благодаря этому команды могут получить полный сеанс без выборки, который привёл к аварийному завершению или проблеме с производительностью, а не довольствоваться фиксированным, заранее отобранным набором сигналов. Платформа bitdrift Capture доступна в виде SaaS, размещённого на стороне bitdrift, или с развертыванием по модели bring-your-own-cloud (или собственного бакета) в вашей учетной записи AWS.

## Почему bitdrift + ClickStack? {#why-bitdrift-clickstack}

ClickStack — это решение для обсервабилити на базе ClickHouse, которое позволяет инженерным командам собирать, хранить и анализировать данные серверных сервисов, веб-фронтендов и инфраструктуры. bitdrift расширяет эту основу до мобильных устройств, где зарождаются многие из самых сложных проблем в продакшне.

* **bitdrift показывает, что произошло на устройстве**: действия пользователя, состояние приложения, сетевые запросы, журналы, ошибки, аварийные завершения, сигналы производительности и контекст сеанса.
* **ClickStack показывает, что произошло после того, как запрос достиг бэкенда**: распределённые трассировки, зависимости между сервисами, журналы, метрики, операции с базой данных и поведение инфраструктуры.
* **Контекст трассировки OpenTelemetry связывает эти данные воедино.**

Расследование может начаться в bitdrift — с неудачного оформления заказа, медленной загрузки экрана, ошибки аутентификации или аварийного завершения приложения. Из сетевого запроса инженер переходит по идентификатору трассировки в интерфейс ClickStack и видит, как запрос проходит через серверные сервисы, — без ручного восстановления картины по разрозненным временным меткам.

<Tip>
  **Основные выводы**

  * **bitdrift** собирает полную (без выборки) телеметрию мобильных приложений, изначально рассчитанную на мобильные платформы, и связывает полученные идентификаторы трассировок с соответствующими backend-трассировками.
  * **ClickStack** хранит итоговую распределённую трассировку в ClickHouse, выполняет по ней запросы и отображает её в интерфейсе ClickStack.
</Tip>

## Предварительные требования {#prerequisites}

* Сервис **ClickHouse Observability**, принимающий backend-трассировку. См. [Начало работы с полностью управляемым ClickHouse Observability](/ru/clickstack/observability/getting-started) или следуйте [руководству «Начало работы» для самоуправляемого развертывания](/ru/clickstack/self-configured/getting-started/managed), если вы используете собственный коллектор для ингестии.
* Серверные сервисы, инструментированные с помощью **OpenTelemetry** и отправляющие трассировку в ClickStack. См. [Загрузка данных с помощью OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry).
* **bitdrift Capture SDK**, интегрированный в ваше мобильное приложение. Инструкции по установке см. в [документации bitdrift SDK](https://docs.bitdrift.io/).
* **Аккаунт bitdrift** и возможность обратиться в [службу поддержки](https://bitdrift.io/contact-us), чтобы включить трассировку для вашего тенанта (трассировка — экспериментальная возможность, которую bitdrift включает отдельно для каждого тенанта).

## Настройка трассировки {#configure-tracing}

Вся настройка выполняется на стороне bitdrift и состоит из трёх шагов:

1. Обратитесь в [службу поддержки bitdrift](https://bitdrift.io/contact-us) с просьбой **включить трассировку для вашего тенанта и настроить глубокие ссылки на трассы в вашем инстансе интерфейса ClickStack**. Именно конфигурация глубоких ссылок направляет ссылки **Просмотреть трассировку** в ваш интерфейс ClickStack: без неё данные трассировки собираются, но ссылка **Просмотреть трассировку** не отображается.
2. **Включите сетевую интеграцию bitdrift** для вашей платформы, чтобы заголовки трассировки передавались в исходящих запросах.
3. **Добавьте действие рабочего процесса Start Tracing**, чтобы включить трассировку для нужных вам сеансов.

Подробнее о каждом шаге для конкретных платформ см. раздел [How bitdrift and ClickStack work together](https://docs.bitdrift.io/product/integration-partners/clickhouse#how-bitdrift-and-clickstack-work-together) в документации bitdrift.

После настройки в строках журнала на временной шкале bitdrift и в представлениях спанов появится ссылка **Просмотреть трассировку**, которая передаёт собранный идентификатор трассы в интерфейс ClickStack.

## Гибкость развертывания {#deployment-flexibility}

Интеграция работает независимо от того, развернут ли ClickStack в самоуправляемом режиме или используется как управляемое решение в ClickHouse Cloud, поскольку она не меняет способ доставки данных в ClickStack. bitdrift не экспортирует телеметрию мобильных устройств в ClickStack: он фиксирует на устройстве контекст трассировки OpenTelemetry для запроса и ссылается на backend-трассировку, которую ваши сервисы, инструментированные с помощью OpenTelemetry, уже отправляют в ClickStack. bitdrift нужен лишь адрес вашего интерфейса ClickStack, чтобы сформировать ссылку **Просмотреть трассировку**, поэтому вносить изменения в развертывание ClickStack или его конвейер ингестии не требуется.

## Дальнейшие шаги {#next-steps}

* **Пройдите путь реального расследования**: от аварийного завершения мобильного приложения или медленного запроса в bitdrift до backend-трассировки в ClickStack
* **Создайте панели мониторинга** в интерфейсе ClickStack для серверных сервисов, от которых зависит ваше мобильное приложение
* **Загляните в [песочницу bitdrift](https://bitdrift.io/sandbox)**, чтобы посмотреть, как выглядит работа с Capture
* **Оформите [бесплатный пробный период](https://bitdrift.io/signup)**, чтобы подключить bitdrift к своему мобильному приложению
