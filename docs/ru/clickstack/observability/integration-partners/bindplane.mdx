## Что такое Bindplane? {#what-is-bindplane}

Bindplane — это нативный для OpenTelemetry конвейер телеметрии с централизованным управлением коллекторами OpenTelemetry. Он упрощает эксплуатацию крупных парков коллекторов за счёт визуального редактирования конфигураций, безопасных поэтапных развёртываний и интеллектуального анализа конвейеров.

## Почему Bindplane + ClickHouse Observability? {#why-bindplane-clickstack}

ClickHouse Observability предоставляет инструменты для хранения телеметрии, поиска и расследования. Bindplane управляет коллекторами OpenTelemetry, которые собирают данные в вашей среде и пересылают их дальше.

Bindplane решает эту задачу, предоставляя:

* Централизованное управление коллекторами OpenTelemetry — от тысяч до более чем миллиона экземпляров
* Визуальное редактирование конфигураций с безопасными поэтапными развёртываниями в один клик
* Автоматическое обнаружение ресурсов и обогащение данных, которые единообразно применяются ещё до того, как данные попадут в ClickHouse Observability
* Маршрутизацию с разветвлением: одни и те же потоки телеметрии можно одновременно отправлять в ClickHouse Observability и другие пункты назначения
* Полную прозрачность конвейера, включая состояние коллекторов, пропускную способность и сквозную производительность

<Tip>
  **Ключевые выводы**

  * **ClickHouse Observability хранит телеметрию и предоставляет инструменты для расследования**
  * **Bindplane управляет конвейером ингестии и берёт на себя операционную сложность эксплуатации парков коллекторов**
</Tip>

## Предварительные требования {#prerequisites}

* [Полностью управляемый сервис ClickHouse Observability](/ru/clickstack/observability/getting-started) или [самоуправляемое развертывание](/ru/clickstack/self-configured/getting-started/managed)
* Аккаунт Bindplane ([создать аккаунт](https://app.bindplane.com))
* Установленный Bindplane OTel Collector (см. [Install your first collector](https://docs.bindplane.com/readme/install-your-first-collector))
* **Полностью управляемый вариант**: конечная точка OTLP по HTTP и ключ API для приёма данных из раздела **Team Settings → Data → Managed Telemetry**
* **Самоуправляемый вариант**: работающий [автономный коллектор](/ru/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured), его конечная точка OTLP и настроенный на нём [`OTLP_AUTH_TOKEN`](/ru/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)
* Сетевая доступность вашей конечной точки OTLP для коллекторов Bindplane

## Интеграция ClickHouse Observability с Bindplane {#integrate-bindplane-clickstack}

<Steps>
  <Step title="Настройте ClickHouse Observability как пункт назначения" id="configure-destination">
    В Bindplane откройте **Library → Add Destination** и выберите **ClickStack**. Так называется пункт назначения Bindplane для отправки телеметрии в ClickHouse Observability по OTLP.

    <Tabs>
      <Tab title="Полностью управляемый">
        <BetaBadge label="Сервис в стадии бета-тестирования" />

        Отправляйте телеметрию на управляемую конечную точку OTLP. ClickHouse берёт на себя ингестию, схемы, хранилище и масштабирование.

        1. В поле **Protocol** выберите **HTTP**.
        2. В поле **Hostname** укажите имя хоста из вашей управляемой конечной точки OTLP без `https://` и порта. Например, для конечной точки `https://<service-id>.otel.<region>.aws.clickhouse.com:4318` введите `<service-id>.otel.<region>.aws.clickhouse.com`.
        3. В поле **Port** укажите `4318`.
        4. В поле **API Ingestion Key** укажите `Bearer <YOUR_INGESTION_API_KEY>`, включая префикс `Bearer`. Значение этого поля передаётся в заголовке `authorization`.
        5. Включите **Enable TLS** и оставьте выключенным параметр **Skip TLS Certificate Verification**.

        Используйте именно управляемую конечную точку OTLP, а не конечную точку базы данных ClickHouse на порту `8443`.
      </Tab>

      <Tab title="Самоуправляемый">
        Отправляйте телеметрию в автономный коллектор, подключённый к вашему сервису ClickHouse Cloud. Этот коллектор уже должен быть запущен и [настроен на аутентификацию запросов](/ru/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).

        1. В поле **Protocol** выберите **HTTP** или **gRPC**.
        2. В поле **Hostname** укажите имя хоста или IP-адрес автономного коллектора без схемы URL и порта.
        3. В поле **Port** укажите `4318` для HTTP или `4317` для gRPC, если вы не настроили другой порт.
        4. В поле **API Ingestion Key** укажите значение `OTLP_AUTH_TOKEN` коллектора без префикса `Bearer`.
        5. Настройте **Enable TLS** в соответствии с конечной точкой коллектора. Для конечных точек с TLS оставьте проверку сертификата включённой.
      </Tab>
    </Tabs>

    Задайте имя пункта назначения, например **Observability production**, и нажмите **Save**. Оставьте сжатие gzip, используемое по умолчанию, если только вы не убедились, что ваша конечная точка поддерживает другой алгоритм.
  </Step>

  <Step title="Создание конфигурации" id="create-configuration">
    После настройки пункта назначения создайте конфигурацию для обработки и маршрутизации телеметрии:

    1. Перейдите в **Configurations** → **Create Configuration**
    2. Задайте имя конфигурации (например, «Observability pipeline»)
    3. Выберите **Collector Type** и **Platform** для вашего развертывания
    4. Добавьте источники:
       * Нажмите **Add Source**, чтобы выбрать один из более чем 80 доступных источников
       * Для тестирования можно добавить источник-генератор телеметрии, имитирующий трафик
       * Для продакшн-среды добавьте источники реальной телеметрии (журналы, метрики, трассировка)
    5. Добавьте пункт назначения:
       * Нажмите **Add Destination**
       * Выберите пункт назначения, созданный на предыдущем шаге
       * Укажите, какие типы телеметрии отправлять (Logs, Metrics, Traces или все)

    <Tip>
      **Главное**

      Вы можете добавить процессоры для фильтрации, сэмплирования, маскирования, обогащения, пакетирования и других операций, чтобы привести телеметрию к нужной форме до того, как она попадет в ClickHouse Observability. Так в ClickHouse будут поступать согласованные структурированные данные.
    </Tip>
  </Step>

  <Step title="Добавьте процессоры (необязательно)" id="add-processors">
    Bindplane обеспечивает интеллектуальный анализ конвейеров и предлагает рекомендации по процессорам. Процессоры можно добавлять для следующих задач:

    * **Фильтрация**: сокращение объёма данных за счёт исключения ненужной телеметрии
    * **Сэмплирование**: применение стратегий сэмплирования к трассировке с большим объёмом данных
    * **Обогащение**: добавление атрибутов ресурсов, меток или метаданных
    * **Преобразование**: изменение структуры или содержимого телеметрии
    * **Пакетирование**: оптимизация размеров пакетов для эффективной передачи

    Эти процессоры единообразно применяются ко всему парку коллекторов ещё до того, как данные попадут в ClickHouse Observability.
  </Step>

  <Step title="Разверните коллекторы и запустите поэтапное развёртывание" id="deploy-collectors">
    1. Добавьте коллектор (BDOT Collector) в конфигурацию:
       * Перейдите в раздел **Collectors** в Bindplane
       * Установите коллектор Bindplane на целевые системы, [следуя инструкциям по установке Bindplane](https://docs.bindplane.com/readme/install-your-first-collector)
       * После подключения коллектор появится в списке коллекторов

    2. Назначьте конфигурацию коллекторам:
       * Выберите нужные коллекторы
       * Назначьте им вашу конфигурацию

    3. Запустите поэтапное развёртывание:
       * Нажмите **Start Rollout**, чтобы развернуть конфигурацию
       * Перед развёртыванием Bindplane проверит конфигурацию
       * Отслеживайте статус поэтапного развёртывания в интерфейсе Bindplane

    <Tip>
      **Ключевые выводы**

      Bindplane обеспечивает безопасное поэтапное развёртывание в один клик с предварительной проверкой. В интерфейсе Bindplane можно в реальном времени отслеживать состояние коллекторов, пропускную способность и возникающие ошибки.
    </Tip>

      <Frame>

      </Frame>
    </div>
  </Step>

  <Step title="Проверьте телеметрию в ClickHouse Observability" id="verify-telemetry">
    После развертывания конфигурации телеметрия из вашего управляемого парка коллекторов начнет поступать в ClickHouse Observability:

    1. Откройте ClickHouse Observability для своего сервиса в консоли ClickHouse Cloud
    2. Найдите свои сервисы в разделе **Поиск**, а для работы с метриками используйте **Обозреватель диаграмм**
    3. Убедитесь, что ожидаемая телеметрия от коллекторов под управлением Bindplane поступает
    4. Если данные не поступают, проверьте журналы коллектора Bindplane на наличие ошибок соединения или аутентификации

    </div>
  </Step>

## Расширенная конфигурация {#advanced-configuration}

### Маршрутизация с разветвлением {#fan-out-routing}

Bindplane поддерживает маршрутизацию с разветвлением, что позволяет одновременно отправлять одни и те же потоки телеметрии в несколько пунктов назначения. Например, можно:

* Отправлять журналы, метрики и трассировку в ClickHouse Observability для долгосрочного хранения и анализа
* Направлять те же данные в другие платформы обсервабилити для оповещений в реальном времени
* Пересылать отдельные виды телеметрии в SIEM-платформы для анализа безопасности

Для этого достаточно добавить несколько пунктов назначения в конфигурацию Bindplane.

### Сжатие и производительность {#compression}

Оставляйте сжатие gzip включенным, чтобы снизить нагрузку на пропускную способность сети. Доступность других алгоритмов сжатия зависит от протокола, и они должны поддерживаться принимающей конечной точкой. Для полностью управляемых развертываний используйте gzip.

## Дальнейшие шаги {#next-steps}

Теперь, когда телеметрия поступает из Bindplane в ClickHouse Observability, вы можете:

* **Создавать панели мониторинга**: создавайте в ClickHouse Observability визуализации для журналов, метрик и трассировок
* **Настраивать оповещения**: настраивайте в ClickHouse Observability оповещения о критических состояниях
* **Масштабировать развертывание**: добавляйте коллекторы и источники по мере роста потребностей в обсервабилити
* **Оптимизировать конвейер**: используйте интеллектуальный анализ конвейеров Bindplane, чтобы находить возможности для оптимизации
