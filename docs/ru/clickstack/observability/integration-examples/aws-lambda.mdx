Собирайте журналы функций и расширений с помощью Rotel Lambda Extension и отправляйте их напрямую в ClickHouse Observability по протоколу OTLP. Расширение работает рядом с вашей Lambda-функцией, поэтому отдельный коллектор не нужен. Кроме того, можно добавить инструментирование OpenTelemetry для сбора трассировки.

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Функция AWS Lambda, развёрнутая из ZIP-архива и использующая среду выполнения, которую поддерживает [Rotel Lambda Extension](https://github.com/streamfold/rotel-lambda-extension)
* AWS CLI v2, настроенный для региона вашей функции (если вы используете примеры с CLI)
* Разрешение на обновление слоёв и переменных окружения функции
* Сетевой доступ из функции Lambda к вашей конечной точке OTLP, включая исходящий доступ для функций, размещённых в VPC

  </Tab>

    ```bash
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=YOUR_INGESTION_KEY"
    ```

## Интеграция с существующими функциями Lambda {#existing-lambda}

<Steps>
  <Step title="Выберите подходящий слой Rotel Lambda Extension" id="choose-layer">
    Выберите слой, соответствующий архитектуре вашей функции (`amd64` или `arm64`), среде выполнения и региону AWS. Скопируйте полный ARN слоя с номером версии со страницы [выпусков Rotel](https://github.com/streamfold/rotel-lambda-extension/releases). Используйте этот ARN в примерах ниже; версии слоёв и их доступность зависят от региона.
  </Step>

  <Step title="Добавьте слой Rotel к функции Lambda" id="add-layer">
    Замените `YOUR_ROTEL_LAYER_ARN` на выбранный ARN, а `my-function` — на имя вашей функции.

##### Вариант 1: консоль AWS {#console}

    1. Откройте консоль AWS Lambda
    2. Перейдите к своей функции Lambda
    3. Прокрутите страницу до раздела **Layers** и нажмите **Add a layer**
    4. Выберите **Specify an ARN**
    5. Введите ARN слоя Rotel:
       ```text
       YOUR_ROTEL_LAYER_ARN
       ```
    6. Нажмите **Add**

##### Вариант 2: AWS CLI {#cli}

    Экспортируйте текущий список слоёв:

    ```bash
    aws lambda get-function-configuration \
      --function-name my-function \
      --query 'Layers[].Arn || `[]`' \
      --output json > layers.json
    ```

    Добавьте ARN слоя Rotel в виде строки в конец массива в `layers.json`, сохранив существующие записи. Затем примените полный список:

    ```bash
    aws lambda update-function-configuration \
      --function-name my-function \
      --layers file://layers.json
    aws lambda wait function-updated --function-name my-function
    ```

##### Вариант 3: AWS SAM {#sam}

    ```yaml
    Resources:
      MyFunction:
        Type: AWS::Serverless::Function
        Properties:
          # ... other configuration ...
          Layers:
            # Keep any existing layer entries here.
            - YOUR_ROTEL_LAYER_ARN
    ```
  </Step>

  <Step title="Настройте расширение для экспорта в ClickHouse Observability" id="configure-extension">
    В консоли Lambda откройте **Configuration → Environment variables** и добавьте приведённые ниже настройки, сохранив все существующие переменные. Это значения конфигурации Lambda, а не команды для запуска в локальном терминале. При вводе значений в консоли не указывайте кавычки, в которые они заключены в примерах.

##### Базовая конфигурация (переменные окружения) {#basic-config}

    Добавьте следующие переменные окружения в свою функцию Lambda:

    ```bash
    # OTLP HTTP endpoint from Connection details
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http

    # Required for managed ingestion
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer YOUR_API_KEY"

    # Optional: Service name (defaults to Lambda function name)
    ROTEL_OTEL_RESOURCE_ATTRIBUTES="service.name=my-lambda-api,service.version=1.0.0"
    ```

##### Расширенная конфигурация (с помощью файла .env) {#advanced-config}

    Для более сложных конфигураций создайте файл `rotel.env` в пакете вашей функции Lambda:

    **rotel.env:**

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer YOUR_API_KEY"
    ROTEL_OTEL_RESOURCE_ATTRIBUTES="service.name=my-lambda-api,deployment.environment=production"
    ```

    Затем задайте переменную окружения, указывающую на этот файл:

    ```bash
    ROTEL_ENV_FILE=/var/task/rotel.env
    ```

##### Использование AWS Secrets Manager или Parameter Store {#secrets}

    Ключ API можно хранить в AWS Secrets Manager или Parameter Store, указав его ARN в `rotel.env`. В примерах ниже используется полностью управляемая аутентификация и предполагается, что секрет содержит только ключ API: префикс `Bearer` Rotel добавляет из конфигурации. Для самоуправляемого коллектора, использующего ключ приёма данных, префикс `Bearer ` указывать не нужно. Замените регион, аккаунт и имена секретов из примера на свои:

    **Пример для AWS Secrets Manager:**

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer ${arn:aws:secretsmanager:us-east-1:123456789012:secret:observability-api-key-abc123}"
    ```

    **Пример для AWS Parameter Store:**

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer ${arn:aws:ssm:us-east-1:123456789012:parameter/observability-api-key}"
    ```

    **Необходимые разрешения IAM:**

    Добавьте следующие разрешения в роль выполнения вашей функции Lambda:

    Для Secrets Manager:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "secretsmanager:GetSecretValue",
            "secretsmanager:BatchGetSecretValue"
          ],
          "Resource": "arn:aws:secretsmanager:us-east-1:123456789012:secret:observability-api-key-*"
        }
      ]
    }
    ```

    Для Parameter Store:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "ssm:GetParameters"
          ],
          "Resource": "arn:aws:ssm:us-east-1:123456789012:parameter/observability-api-key"
        }
      ]
    }
    ```

    <Note>
      Секреты извлекаются на этапе инициализации, что может увеличить задержку холодного старта. Поддерживаемые форматы и необходимые разрешения описаны в разделе [Rotel secret configuration](https://github.com/streamfold/rotel-lambda-extension#secrets). Для ключей шифрования, управляемых клиентом, также может потребоваться разрешение `kms:Decrypt`.
    </Note>
  </Step>

  <Step title="Проверьте интеграцию" id="test-integration">
    Вызовите свою функцию Lambda с событием, которое она принимает, и убедитесь, что обработчик делает запись в журнал. Если ваша функция ожидает другое событие, замените этот пример полезной нагрузки:

    ```bash
    aws lambda invoke \
      --function-name my-function \
      --cli-binary-format raw-in-base64-out \
      --payload '{"test": "data"}' \
      response.json
    ```

    Проверьте журналы Lambda на наличие ошибок:

    ```bash
    aws logs tail /aws/lambda/my-function --follow
    ```
  </Step>

  <Step title="Проверьте журналы" id="verify-logs">
    Откройте **Поиск** в ClickHouse Observability, выберите источник **Logs** и задайте фильтр `ServiceName:my-lambda-api`, если вы использовали имя сервиса из примера. В противном случае укажите имя своей Lambda-функции. Выберите **Last 15 minutes**.

    <div className="ch-image-lg">
      <Frame>
        ![Представление логов Lambda](/images/clickstack/lambda/lambda-log-view.webp)
      </Frame>
    </div>

    <div className="ch-image-lg">
      <Frame>
        ![Подробности записи журнала Lambda](/images/clickstack/lambda/lambda-log.webp)
      </Frame>
    </div>

    Обратите внимание на следующие ключевые атрибуты в журналах:

    * `service.name`: настроенное вами имя сервиса (по умолчанию — имя Lambda-функции)
    * `faas.name`: имя функции AWS Lambda
    * `faas.invocation_id`: уникальный ID вызова
    * `cloud.provider`: &quot;aws&quot;
    * `cloud.platform`: &quot;aws&#95;lambda&quot;
  </Step>
</Steps>

## Отключение CloudWatch Logs (оптимизация затрат) {#disable-cloudwatch}

По умолчанию AWS Lambda отправляет все журналы в CloudWatch Logs, что при больших объёмах может обходиться дорого. Убедившись, что журналы поступают в ClickHouse Observability, вы можете отключить логирование в CloudWatch, чтобы сократить расходы.

<Steps>
  <Step title="Удалите разрешения CloudWatch из роли выполнения" id="remove-permissions">
    1. Откройте консоль AWS и перейдите в **AWS Lambda**
    2. Перейдите к своей Lambda-функции
    3. Выберите **Configuration** → **Permissions**
    4. Нажмите на имя роли выполнения, чтобы открыть консоль IAM
    5. Удалите разрешения на запись в CloudWatch Logs, которые использует эта функция. Если роль используется несколькими функциями, перед внесением изменений назначьте функции отдельную роль:
       * Если используется пользовательская политика, отредактируйте её, удалив `logs:CreateLogGroup`, `logs:CreateLogStream` и `logs:PutLogEvents`
       * Если используется управляемая политика AWS `AWSLambdaBasicExecutionRole`, удалите её из роли
    6. Сохраните роль
  </Step>

  <Step title="Убедитесь, что логирование в CloudWatch отключено" id="verify-disabled">
    Снова вызовите функцию и убедитесь, что:

    1. В группе журналов CloudWatch для этой функции не появляются новые события
    2. Журналы по-прежнему поступают в ClickHouse Observability

    ```bash
    aws logs tail /aws/lambda/my-function --since 5m --follow
    ```
  </Step>
</Steps>

## Добавление автоматического инструментирования OpenTelemetry {#auto-instrumentation}

Rotel может получать телеметрию от установленного рядом с ним слоя инструментирования для конкретного языка. Чтобы выбрать совместимый слой и задать `AWS_LAMBDA_EXEC_WRAPPER`, следуйте [инструкциям Rotel по автоматическому инструментированию](https://github.com/streamfold/rotel-lambda-extension#auto-instrumentation) и документации по языковым слоям, на которую там приведены ссылки.

При добавлении инструментирования сохраните слой Rotel и все уже подключённые слои. После вызова функции выберите источник **Traces** в ClickHouse Observability и отфильтруйте данные по настроенному имени сервиса. Для корреляции журналов и трасс инструментирование приложения должно добавлять в журналы идентификаторы трасс и спанов.
