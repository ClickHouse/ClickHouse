Собирайте журналы сервера MongoDB с помощью приёмника OpenTelemetry `filelog` и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без развёртывания MongoDB, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker и `curl`
* Для работы с собственными журналами — самоуправляемое развертывание MongoDB версии 4.4 или новее с доступом к его файлам журналов в формате JSON

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Конфигурацию можно скопировать кнопкой **Copy connection details**, а скрытый ключ — просмотреть с помощью **Reveal key**.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении управляемой телеметрии](/images/clickstack/getting-started/observability-managed-telemetry.png)

    Для приведённых ниже примеров экспортера OTLP задайте следующие переменные в терминале, в котором будет запускаться коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точными значениями конечной точки (включая порт) и ключа API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/logs`: экспортер сам добавляет в конец путь, соответствующий типу сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP по HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже включают сопоставление хоста.

## Интеграция с существующим MongoDB {#existing-mongodb}

<Steps>
  <Step title="Проверьте конфигурацию журналирования MongoDB" id="verify-mongodb">
    MongoDB 4.4 и более новые версии используют структурированные серверные журналы в формате JSON. Проверьте раздел `systemLog` в файле конфигурации MongoDB. Типичный путь к журналу в Linux — `/var/log/mongodb/mongod.log`.

    Если MongoDB пишет журналы только в stdout, настройте запись журнала в файл в `mongod.conf`:

    ```yaml
    systemLog:
      destination: file
      path: /var/log/mongodb/mongod.log
      logAppend: true
    ```

    Создайте каталог с правами, позволяющими MongoDB записывать в него, а коллектору — читать его. При развертывании в контейнерах откройте коллектору доступ к каталогу журналов и убедитесь, что MongoDB загружает файл конфигурации.

    Перезапустите MongoDB способом, принятым в вашем окружении, например:

    ```bash
    sudo systemctl restart mongod
    # Или для Docker:
    docker restart <mongodb-container>
    ```
  </Step>

  <Step title="Настройте коллектор" id="configure-collector">
    Сохраните следующую конфигурацию в файл `mongodb-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb"

          - type: add
            field: resource["service.name"]
            value: "mongodb-service"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, batch]
          exporters: [otlp_http/observability]
    ```

    Синтаксический анализатор считывает поля временной метки и уровня серьёзности MongoDB, перемещает `msg` в тело записи журнала, а такие поля, как `c`, `ctx`, `id` и `attr`, сохраняет в виде атрибутов журнала. Оставьте `$$date` без изменений: коллектор преобразует экранированный знак доллара в поле MongoDB `$date`. Благодаря `start_at: end` приёмник считывает только новые записи.
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    Задайте [переменные подключения](#connection-details), затем выполните команду из каталога с конфигурацией. При необходимости измените путь к журналу на хосте. Если файлы доступны для чтения группе, добавьте `--group-add LOG_GROUP_ID`, указав числовой идентификатор группы из вывода `ls -ln /var/log/mongodb`.

    ```bash
    docker run --rm --name mongodb-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/mongodb:/var/log/mongodb:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал и выполните на сервере действия, которые приведут к появлению новых записей в журнале. По завершении тестирования остановите коллектор с помощью **Ctrl+C**.
  </Step>

  <Step title="Проверьте журналы" id="verify-logs">
    Откройте **Поиск**, выберите **Журналы**, задайте фильтр `ServiceName:mongodb-service` и выберите **Last 15 minutes**. Должны отобразиться сообщения сервера с разобранными временными метками и уровнями серьёзности.
  </Step>
</Steps>

## Демо-набор данных {#demo-dataset}

Пример содержит 6,956 записей журнала сервера MongoDB за период примерно в 24 часа. Коллектор обновляет их временные метки, сохраняя сообщения и структурированные атрибуты.

<Steps>
  <Step title="Скачайте пример" id="download-sample">
    ```bash
    curl -fL -o mongod.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/mongodb/mongod.log
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo">
    Сохраните следующую конфигурацию в файл `mongodb-demo.yaml`:

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb-demo"

          - type: add
            field: resource["service.name"]
            value: "mongodb-demo"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:52.193Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo">
    Задайте [переменные подключения](#connection-details), затем выполните команду из каталога, в котором находятся оба файла:

    ```bash
    docker run --rm --name mongodb-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/mongod.log:/var/log/mongodb/mongod.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал, пока проверяете приём данных. По завершении остановите коллектор сочетанием клавиш **Ctrl+C**. При повторном запуске демонстрации пример будет загружен заново с обновлёнными временными метками.
  </Step>

  <Step title="Проверьте демонстрационные журналы" id="verify-demo">
    Откройте **Поиск**, выберите **Журналы**, задайте фильтр `ServiceName:mongodb-demo` и выберите **Last 2 days**.

    <div className="ch-image-lg">

      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Журналы не отображаются {#no-logs}

Проверьте вывод коллектора на наличие ошибок разрешений на доступ к файлам, разбора, аутентификации или экспорта. Убедитесь, что сервер записывает журналы в смонтированный каталог, а имена файлов соответствуют шаблонам из списка `include` приёмника. Действующая конфигурация считывает только новые записи.

### Журналы разбираются некорректно {#parsing-errors}

Убедитесь, что файл содержит по одному объекту JSON в каждой строке:

```bash
tail -n 1 /var/log/mongodb/mongod.log | python3 -m json.tool
```

Синтаксический анализатор рассчитан на журналы MongoDB 4.4+ в формате JSON. Для устаревших текстовых журналов нужен другой синтаксический анализатор. Сохраните экранирование `$$date` в конфигурации коллектора.
