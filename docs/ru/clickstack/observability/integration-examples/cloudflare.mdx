## Обзор {#overview-self-configured}

    Cloudflare [Logpush](https://developers.cloudflare.com/logs/about/) экспортирует журналы HTTP-запросов в различные пункты назначения, например в Amazon S3. Пересылка этих журналов в ClickStack позволяет:

    * Анализируйте трафик на периферийных узлах, производительность кэша и события безопасности вместе с остальными данными обсервабилити
    * Выполняйте запросы к журналам на ClickHouse SQL
    * Храните журналы дольше стандартного срока хранения Cloudflare

    В этом руководстве [ClickPipes](/ru/integrations/clickpipes/home) используется для непрерывного приёма файлов журналов Cloudflare из S3 в ClickHouse. S3 служит надёжным буфером между Cloudflare и ClickHouse, обеспечивая семантику «ровно один раз» и возможность повторного применения данных.

    <Info>
      **Альтернатива: прямая ингестия по HTTP**

      Cloudflare Logpush также поддерживает отправку журналов напрямую в [конечные точки HTTP](https://developers.cloudflare.com/logs/get-started/enable-destinations/http/). Поскольку Cloudflare экспортирует журналы в формате JSON с разделением записей переводами строк (NDJSON), а ClickHouse нативно принимает этот формат через `JSONEachRow`, можно направить Logpush напрямую на HTTP-интерфейс вашего сервиса ClickHouse Cloud, указав URL конечной точки в следующем формате:

      ```text
      https://YOUR_CLICKHOUSE_HOST:8443/?query=INSERT+INTO+cloudflare_http_logs+FORMAT+JSONEachRow&header_Authorization=Basic+BASE64_CREDENTIALS
      ```

      Замените `YOUR_CLICKHOUSE_HOST` на имя хоста вашего сервиса ClickHouse Cloud, а `BASE64_CREDENTIALS` — на ваши учётные данные, закодированные в Base64 (`echo -n 'default:YOUR_PASSWORD' | base64`).

      Этот вариант проще в настройке (не нужно настраивать S3, SQS или IAM), однако при сбое доставки Cloudflare Logpush [не может выполнить дозагрузку исторических данных](https://developers.cloudflare.com/logs/logpush/), поэтому если во время отправки ClickHouse окажется недоступен, эти журналы будут безвозвратно потеряны.
    </Info>

## Интеграция с уже настроенным Cloudflare Logpush {#existing-cloudflare-self-configured}

    В этом разделе предполагается, что Cloudflare Logpush уже настроен на экспорт журналов в S3. Если это не так, сначала выполните шаги из [руководства Cloudflare по настройке AWS S3](https://developers.cloudflare.com/logs/get-started/enable-destinations/aws-s3/).

### Предварительные требования {#prerequisites-self-configured}

    * Запущенный **сервис ClickHouse Cloud** (ClickPipes — возможность, доступная только в Cloud и отсутствующая в ClickStack OSS)
    * Настроенный Cloudflare Logpush, который записывает журналы в S3 бакет
    * Имя S3 бакета и регион, в который Cloudflare записывает журналы

    <Steps>
      <Step title="Настройка аутентификации в S3" id="configure-auth-self-configured">
        ClickPipes требуется разрешение на чтение из вашего S3 бакета. Чтобы настроить доступ на основе ролей IAM или доступ по учётным данным, воспользуйтесь руководством [Безопасный доступ к данным S3](/ru/products/cloud/guides/data-sources/accessing-s3-data-securely).

        Подробнее об аутентификации и разрешениях S3 в ClickPipes см. в [справочной документации по S3 ClickPipes](/ru/integrations/clickpipes/object-storage/amazon-s3/overview#access-control).
      </Step>

      <Step title="Создать задачу ClickPipes" id="create-clickpipes-self-configured">
        1. Консоль ClickHouse Cloud → **Источники данных** → **Создать ClickPipe**
        2. **Источник**: Amazon S3

        <div className="ch-image-lg">
          <Frame>
            ![ClickPipe S3](/images/clickstack/cloudflare/clickpipe-s3.webp)
          </Frame>
        </div>

        **Соединение:**

        * **Путь к файлу S3**: путь к бакету с журналами Cloudflare с подстановочным символом для выбора файлов. Если в Logpush включены ежедневные подпапки, используйте `**`, чтобы охватить все подкаталоги:
          * Без подпапок: `https://your-bucket.s3.us-east-1.amazonaws.com/logs/*`
          * С ежедневными подпапками: `https://your-bucket.s3.us-east-1.amazonaws.com/logs/**/*`
        * **Аутентификация**: выберите метод аутентификации и укажите учётные данные или ARN роли IAM

        **Настройки ингестии:**

        Нажмите **Incoming data**, затем настройте следующее:

        * Включите **Непрерывную загрузку данных**
        * **Порядок**: лексикографический порядок

        <div className="ch-image-lg">
          <Frame>
            ![Непрерывная загрузка данных](/images/clickstack/cloudflare/continuous-ingestion.webp)
          </Frame>
        </div>

        Cloudflare Logpush присваивает файлам имена на основе даты (например, `20250127/...`), поэтому они изначально упорядочены лексикографически. ClickPipes каждые 30 секунд проверяет наличие новых файлов и принимает все файлы, имя которых больше имени последнего обработанного файла.

        **Сопоставление схем:**

        Нажмите **Parse information**. ClickPipes анализирует выборку из ваших файлов журналов и автоматически определяет схему. Проверьте сопоставленные столбцы и при необходимости скорректируйте типы. Задайте **ключ сортировки** для целевой таблицы — для журналов Cloudflare хорошо подойдёт `(EdgeStartTimestamp, ClientCountry, EdgeResponseStatus)`.

        <div className="ch-image-lg">
          <Frame>
            ![Информация о разборе](/images/clickstack/cloudflare/parse-information.webp)
          </Frame>
        </div>

        Нажмите **Complete Setup**.

        <Note>
          После создания ClickPipes сначала выполняет первоначальную загрузку **всех существующих файлов** по указанному пути, а затем переходит к непрерывному опросу. Если в вашем бакете накопился большой объём журналов Cloudflare, первоначальная загрузка может занять некоторое время.
        </Note>
      </Step>

      <Step title="Настройка источника данных в интерфейсе ClickStack" id="configure-source-self-configured">
        ClickPipes загружает журналы Cloudflare в плоскую таблицу с нативными именами полей Cloudflare. Чтобы просматривать эти журналы в интерфейсе ClickStack, настройте пользовательский источник данных, который сопоставит столбцы Cloudflare с представлением логов в интерфейсе ClickStack.

        1. Откройте интерфейс ClickStack → **Team Settings** → **Sources**

        <div className="ch-image-lg">
          <Frame>
            ![Добавление источника](/images/clickstack/cloudflare/add-source.webp)
          </Frame>
        </div>

        2. Нажмите **Add source** и задайте следующие настройки. Чтобы открыть все поля, нажмите **Configure Optional Fields**:

        <div className="ch-image-lg">
          <Frame>
            ![Настройка необязательных полей](/images/clickstack/cloudflare/configure-optional-fields.webp)
          </Frame>
        </div>

        | Настройка                          | Значение                                                                                                                                                                                                                                                                                                          |
        | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
        | **Name**                           | `Cloudflare Logs`                                                                                                                                                                                                                                                                                                 |
        | **Source Data Type**               | Log                                                                                                                                                                                                                                                                                                               |
        | **Database**                       | `default`                                                                                                                                                                                                                                                                                                         |
        | **Table**                          | `cloudflare_http_logs`                                                                                                                                                                                                                                                                                            |
        | **Timestamp Column**               | `toDateTime(EdgeStartTimestamp / 1000000000)`                                                                                                                                                                                                                                                                     |
        | **Default Select**                 | `EdgeStartTimestamp, ClientRequestMethod, ClientRequestURI, EdgeResponseStatus, ClientCountry`                                                                                                                                                                                                                    |
        | **Service Name Expression**        | `'cloudflare'`                                                                                                                                                                                                                                                                                                    |
        | **Log Level Expression**           | `multiIf(EdgeResponseStatus >= 500, 'ERROR', EdgeResponseStatus >= 400, 'WARN', 'INFO')`                                                                                                                                                                                                                          |
        | **Body Expression**                | `concat(ClientRequestMethod, ' ', ClientRequestURI, ' ', toString(EdgeResponseStatus))`                                                                                                                                                                                                                           |
        | **Log Attributes Expression**      | `map('http.method', ClientRequestMethod, 'http.status_code', toString(EdgeResponseStatus), 'http.url', ClientRequestURI, 'client.country', ClientCountry, 'client.ip', ClientIP, 'cache.status', CacheCacheStatus, 'bot.score', toString(BotScore), 'cloudflare.ray_id', RayID, 'cloudflare.colo', EdgeColoCode)` |
        | **Resource Attributes Expression** | `map('cloudflare.zone', ClientRequestHost)`                                                                                                                                                                                                                                                                       |
        | **Implicit Column Expression**     | `concat(ClientRequestMethod, ' ', ClientRequestURI)`                                                                                                                                                                                                                                                              |

        3. Нажмите **Save Source**

        <div className="ch-image-lg">
          <Frame>
            ![Сохранение источника](/images/clickstack/cloudflare/save-source.webp)
          </Frame>
        </div>

        Так нативные столбцы Cloudflare сопоставляются с представлением логов в интерфейсе ClickStack напрямую, без преобразования или дублирования данных. В поле **Body** отображается краткая сводка запроса, например `GET /api/v1/users 200`, а все поля Cloudflare доступны для поиска как атрибуты.
      </Step>

      <Step title="Проверьте данные в интерфейсе ClickStack" id="verify-hyperdx-self-configured">
        Перейдите в представление **Search** и выберите источник **Cloudflare Logs**. Задайте временной диапазон, охватывающий ваши данные. Должны отобразиться записи журнала, содержащие:

        * Сводки запросов в столбце Body (например, `GET /api/v1/users 200`)
        * Уровни серьёзности с цветовой маркировкой по HTTP-статусу (INFO для 2xx, WARN для 4xx, ERROR для 5xx)
        * Атрибуты для поиска, такие как `http.status_code`, `client.country`, `cache.status` и `bot.score`

        <div className="ch-image-lg">

        </div>

          </Frame>
        </div>
      </Step>
    </Steps>

## Демонстрационный датасет {#demo-dataset-self-configured}

    Если вы хотите протестировать интеграцию до настройки Cloudflare Logpush в продакшн-среде, воспользуйтесь тестовым набором данных с реалистичными журналами HTTP-запросов.

    <Steps>
      <Step title="Запустите ClickPipes с демо-набором данных" id="start-demo-self-configured">
        1. Консоль ClickHouse Cloud → **Data Sources** → **Create ClickPipe**
        2. **Source**: Amazon S3
        3. **Authentication**: Public
        4. **S3 file path**: `https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/cloudflare/cloudflare-http-logs.json`
        5. Нажмите **Incoming data**
        6. Выберите формат **JSON**
        7. Нажмите **Parse information** и проверьте обнаруженную схему
        8. В поле **Table name** укажите `cloudflare_http_logs`
        9. Нажмите **Complete Setup**

        Набор данных содержит 5,000 записей журнала HTTP-запросов за 24 часа с реалистичными закономерностями: трафиком из разных стран, попаданиями и промахами кэша, запросами к API и статическим ресурсам, ответами с ошибками и событиями безопасности.
      </Step>

      <Step title="Настройте источник данных в интерфейсе ClickStack" id="configure-demo-source-self-configured">
        Выполните [шаги по настройке источника данных](#configure-source-self-configured), чтобы создать в интерфейсе ClickStack источник, указывающий на таблицу `cloudflare_http_logs`. Если вы уже настроили источник в разделе об интеграции для продакшн-среды, этот шаг можно пропустить.
      </Step>

      <Step title="Проверьте демонстрационные данные" id="verify-demo-self-configured">

        Должны отобразиться записи журнала со сводками запросов, атрибутами Cloudflare, по которым можно выполнять поиск, и уровнями серьёзности, определёнными на основе кодов состояния HTTP.

## Устранение неполадок {#troubleshooting-self-configured}

### Данные не появляются в ClickHouse {#no-data-self-configured}

    Убедитесь, что таблица создана и содержит данные:

    ```sql
    SHOW TABLES FROM default LIKE 'cloudflare_http_logs';
    SELECT count() FROM cloudflare_http_logs;
    ```

    Если таблица существует, но пуста, проверьте ClickPipes на наличие ошибок: консоль ClickHouse Cloud → **Источники данных** → ваш ClickPipe → **Журналы**. При проблемах с аутентификацией для частных бакетов см. [документацию по управлению доступом для S3 ClickPipes](/ru/integrations/clickpipes/object-storage/amazon-s3/overview#access-control).

### Журналы не отображаются в интерфейсе ClickStack {#no-hyperdx-self-configured}

    Если данные есть в ClickHouse, но не отображаются в интерфейсе ClickStack, проверьте конфигурацию источника данных:

    * Проверьте, что в интерфейсе ClickStack → **Team Settings** → **Sources** существует источник для `cloudflare_http_logs`
    * Убедитесь, что для параметра **столбец временной метки** задано значение `toDateTime(EdgeStartTimestamp / 1000000000)`: временные метки Cloudflare указаны в наносекундах, поэтому их нужно преобразовать
    * Проверьте, что выбранный в интерфейсе ClickStack временной диапазон охватывает данные. Для демо-набора данных укажите **2026-02-23 00:00:00 - 2026-02-26 00:00:00**

## Переход к промышленной эксплуатации {#going-to-production-self-configured}

    В этом руководстве показана загрузка журналов Cloudflare на примере публичного демо-набора данных. Для продакшн-развертываний настройте Cloudflare Logpush на запись в собственный S3 бакет, а для безопасного доступа настройте ClickPipes с [аутентификацией на основе роли IAM](/ru/products/cloud/guides/data-sources/accessing-s3-data-securely). Выбирайте только нужные [поля Logpush](https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/zone/http_requests/), чтобы сократить затраты на хранение и объём ингестии. Для более удобной организации файлов включите в Logpush ежедневные подпапки, а в шаблоне пути ClickPipes используйте `**/*`, чтобы охватить все подкаталоги.

    Расширенные параметры конфигурации, включая [неупорядоченную ингестию на основе SQS](/ru/integrations/clickpipes/object-storage/amazon-s3/overview#continuous-ingestion-any-order) для дозагрузки исторических данных и обработки файлов, поступающих не по порядку, описаны в [документации по S3 ClickPipes](/ru/integrations/clickpipes/object-storage/amazon-s3/overview).
  </Tab>
