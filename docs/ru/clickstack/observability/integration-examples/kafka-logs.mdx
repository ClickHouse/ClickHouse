Собирайте журналы брокеров Kafka с помощью приёмника OpenTelemetry `filelog` и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без развёрнутого Kafka, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker и `curl`
* Для работы с собственными журналами — доступ к файлам журналов брокера Kafka в формате, приведённом ниже

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Чтобы скопировать конфигурацию, нажмите **Copy connection details**, а чтобы просмотреть замаскированный ключ — **Reveal key**.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров с экспортером OTLP задайте следующие переменные в терминале, в котором будете запускать коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точными значениями конечной точки (включая порт) и ключа API вашего сервиса. Используйте базовую конечную точку HTTP без суффикса `/v1/logs`: экспортер сам добавит путь сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите конечную точку OTLP по HTTP вашего коллектора, доступную по сети (например, `http://YOUR_COLLECTOR_HOST:4318`), и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже содержат сопоставление хоста.

## Интеграция с существующим кластером Kafka {#existing-kafka}

<Steps>
  <Step title="Проверьте конфигурацию логирования Kafka" id="verify-kafka">
    Найдите журналы брокера. В зависимости от способа установки и конфигурации логирования они обычно находятся в `$KAFKA_HOME/logs` или `/var/log/kafka`:

    ```bash
    ls "$KAFKA_HOME/logs/"
    ls /var/log/kafka/
    ```

    Обычно это файлы `server.log` (события брокера), `controller.log` (события контроллера) и `state-change.log` (изменения состояния партиций и реплик). Отдельные файлы создаются только в том случае, если они настроены в appender&#39;ах логирования.

    Синтаксический анализатор в этом руководстве рассчитан на следующий текстовый формат Log4j:

    ```text
    [2026-03-09 14:23:45,123] INFO [KafkaServer id=0] started (kafka.server.KafkaServer)
    ```

    Если брокер пишет журналы только в stdout, настройте файловый appender в конфигурации логирования брокера и откройте коллектору доступ к этому каталогу. Приёмник `filelog` не читает stdout контейнера напрямую. Если ваш шаблон логирования отличается, скорректируйте синтаксический анализатор.
  </Step>

  <Step title="Настройте коллектор" id="configure-collector">
    Сохраните следующую конфигурацию в файл `kafka-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
          - /var/log/kafka/controller.log
          - /var/log/kafka/state-change.log
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka
          - type: add
            field: resource["service.name"]
            value: kafka-service
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, batch]
          exporters: [otlp_http/observability]
    ```

    Укажите в `location` часовой пояс, используемый в журналах брокера; в примере используется UTC. Многострочные записи сохраняют трассировки стека целиком. Коллектор читает только новые записи (`start_at: end`) и приводит текст уровня серьёзности к нижнему регистру.
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    Задайте [переменные подключения](#connection-details), затем выполните команду из каталога конфигурации. При необходимости измените путь к журналам на хосте. Если файлы доступны для чтения только группе, добавьте `--group-add LOG_GROUP_ID`, указав числовой идентификатор группы, который выводит команда `ls -ln /var/log/kafka`.

    ```bash
    docker run --rm --name kafka-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/kafka:/var/log/kafka:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Оставьте терминал открытым и создайте нагрузку на брокер, чтобы в журнал записывались новые записи. По завершении тестирования остановите выполнение, нажав **Ctrl+C**.
  </Step>

  <Step title="Проверьте журналы" id="verify-logs">
    Откройте **Поиск**, выберите **Logs**, задайте фильтр `ServiceName:kafka-service` и выберите **Last 15 minutes**. Должны отобразиться сообщения брокера с разобранными временными метками и уровнем серьёзности.
  </Step>
</Steps>

## Демо-набор данных {#demo-dataset}

Выборка содержит 6,376 записей журнала брокера Kafka примерно за 24 часа. Коллектор обновляет их временные метки, сохраняя сообщения и трассировки стека без изменений.

<Steps>
  <Step title="Скачайте выборку" id="download-sample">
    ```bash
    curl -fL -o server.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/kafka/server.log
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo">
    Сохраните следующую конфигурацию в файл `kafka-logs-demo.yaml`:

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka-demo
          - type: add
            field: resource["service.name"]
            value: kafka-demo
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:58.180Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo">
    Задайте [переменные соединения](#connection-details), затем выполните следующую команду в каталоге, где находятся оба файла:

    ```bash
    docker run --rm --name kafka-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/server.log:/var/log/kafka/server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал, пока проверяете приём данных. По завершении остановите коллектор сочетанием клавиш **Ctrl+C**. При повторном запуске демонстрации выборка будет отправлена заново с обновлёнными временными метками.
  </Step>

  <Step title="Проверьте демонстрационные журналы" id="verify-demo">
    Откройте раздел **Поиск**, выберите **Logs**, задайте фильтр `ServiceName:kafka-demo` и выберите **Last 2 days**.

    <div className="ch-image-lg">
      <Frame>
        ![Демонстрационные журналы Kafka с разобранным уровнем серьёзности в разделе поиска ClickHouse Observability](/images/clickstack/observability-kafka-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Журналы не появляются {#no-logs}

Проверьте вывод коллектора на наличие ошибок прав доступа к файлам, разбора, аутентификации или экспорта. Убедитесь, что брокер записывает журналы в смонтированный каталог, а имена файлов соответствуют шаблонам из списка `include` приёмника. Работающая конфигурация считывает только новые записи.

### Журналы разбираются некорректно {#parsing-errors}

Сравните запись журнала брокера с ожидаемым форматом:

```bash
tail -n 20 /var/log/kafka/server.log
```

Если формат ваших журналов отличается, скорректируйте регулярное выражение и шаблон начала многострочной записи. В параметре `location` синтаксического анализатора временных меток укажите часовой пояс, который используется в журналах вашего брокера.
