Собирайте CSV-журналы PostgreSQL с помощью коллектора OpenTelemetry и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без установки PostgreSQL, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker для запуска примеров коллектора
* Для собственных журналов — PostgreSQL 14 или новее, а также доступ к его конфигурации и файлам журналов
* Для демонстрации — `curl` для загрузки выборки данных

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Бета-версия" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы отобразить скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров с экспортером OTLP задайте следующие переменные в терминале, в котором будете запускать коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точным адресом конечной точки (включая порт) и ключом API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/logs`: экспортер сам добавляет путь сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите конечную точку OTLP HTTP вашего коллектора, доступную по сети (например, `http://YOUR_COLLECTOR_HOST:4318`), и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. В приведённых ниже командах Docker сопоставление хоста уже задано.

## Интеграция с существующим PostgreSQL {#existing-postgres}

<Steps>
  <Step title="Настройка логирования PostgreSQL" id="configure-postgres">
    Чтобы найти файл конфигурации, выполните следующий SQL-запрос от имени администратора базы данных:

    ```sql
    SHOW config_file;
    ```

    Добавьте или измените следующие настройки в файле `postgresql.conf`:

    ```conf
    logging_collector = on
    log_destination = 'csvlog'
    log_directory = '/var/log/postgresql'
    log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
    log_file_mode = 0640
    log_timezone = 'UTC'
    log_connections = on
    log_disconnections = on
    # Optional: log statements taking more than one second
    # log_min_duration_statement = 1000
    ```

    Создайте каталог журналов, назначив ему владельца и разрешения так, чтобы PostgreSQL мог записывать в него, а коллектор — читать. Если PostgreSQL работает в контейнере, смонтируйте этот каталог так, чтобы у коллектора был доступ к тем же файлам. Журналы в формате CSV записываются в файлы с расширением `.csv`, даже если значение `log_filename` оканчивается на `.log`.

    Перезапустите PostgreSQL в соответствии с принятым у вас процессом развертывания, например:

    ```bash
    sudo systemctl restart postgresql
    # Or, for Docker:
    docker restart <postgres-container>
    ```

    Проверьте активный CSV-файл:

    ```sql
    SELECT pg_current_logfile('csvlog');
    ```

    Приведённый ниже синтаксический анализатор рассчитан на [формат CSV PostgreSQL из 26 столбцов](https://www.postgresql.org/docs/14/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-CSVLOG). Для более ранних версий PostgreSQL и других форматов логов нужен другой синтаксический анализатор.
  </Step>

  <Step title="Настройте коллектор" id="configure-collector">
    Сохраните эту конфигурацию в файл `postgres-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql-*.csv
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql"

          - type: add
            field: resource["service.name"]
            value: "postgresql-service"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    Приёмник разбирает многострочные записи CSV, сохраняет их временные метки и тела, а также добавляет атрибут `service.name` со значением `postgresql-service`. Такие поля, как `database_name`, `error_severity`, `message` и `query`, остаются доступными в качестве атрибутов журнала.
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    Выполните следующую команду из каталога с конфигурацией. При необходимости измените путь к каталогу журналов на хосте. Если файлы журналов доступны для чтения группе, добавьте `--group-add LOG_GROUP_ID`, указав числовой ID группы из вывода команды `ls -ln /var/log/postgresql`.

    ```bash
    docker run --rm --name postgres-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/postgresql:/var/log/postgresql:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал. Приёмник использует `start_at: end`, поэтому после запуска коллектора установите новое подключение к базе данных или выполните запрос, вызывающий ошибку:

    ```sql
    SELECT 1 / 0;
    ```
  </Step>

  <Step title="Проверьте журналы" id="verify-logs">
    Откройте **Поиск**, выберите **Logs**, отфильтруйте по `ServiceName:postgresql-service` и выберите **Last 15 minutes**. Разверните запись, чтобы просмотреть её атрибуты PostgreSQL и уровень серьёзности.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Датасет содержит 21,325 записей журнала PostgreSQL в формате CSV, охватывающих активность соединений, запросы и ошибки сервера.

<Steps>
  <Step title="Скачайте тестовый набор данных" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/postgres/postgresql.log
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo">
    Сохраните следующий манифест в файл `postgres-logs-demo.yaml`:

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql-demo"

          - type: add
            field: resource["service.name"]
            value: "postgresql-demo"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-10T23:59:47Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    Процессор временных меток, предназначенный только для демонстрации, сдвигает выборку в интервал последних 24 часов так, чтобы она заканчивалась за две минуты до момента ингестии. Исходные атрибуты временных меток и тела записей журнала не изменяются. Для собственных журналов PostgreSQL этот процессор не нужен.
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo">
    В каталоге с конфигурацией и загруженным файлом журнала выполните:

    ```bash
    docker run --rm --name postgres-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/postgresql.log:/var/log/postgresql/postgresql.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал, пока проверяете ингестию. Завершив проверку, остановите коллектор клавишами **Ctrl+C**. При повторном запуске демо примеры данных загружаются заново с обновлёнными временными метками.
  </Step>

  <Step title="Проверьте демонстрационные журналы" id="verify-demo">
    Откройте **Поиск**, выберите **Logs**, задайте фильтр `ServiceName:postgresql-demo` и выберите **Last 2 days**. Разверните запись, чтобы просмотреть такие поля, как `database_name`, `error_severity`, `message` и `query`.

## Устранение неполадок {#troubleshooting}

### Коллектор не запускается {#collector-fails-to-start}

Проверьте вывод коллектора на наличие ошибок конфигурации. Убедитесь, что конфигурация смонтирована правильно и переменные соединения заданы верно, в терминале, где запущен Docker.

### Журналы не отображаются {#no-logs}

Проверьте, нет ли ошибок аутентификации или экспорта. Определите путь к CSV-файлу с помощью `pg_current_logfile`, убедитесь, что файлы соответствуют шаблону `include` приёмника и что у коллектора есть права на их чтение. При `start_at: end` собираются только новые записи. Для демонстрации добавьте процессор временных меток и выберите **Last 2 days**.

### Отказано в доступе {#permission-denied}

По умолчанию PostgreSQL создаёт файлы журналов, доступные только владельцу. В приведённой выше конфигурации задан параметр `log_file_mode = 0640`, который разрешает чтение для группы; добавьте группу файла в контейнер коллектора с помощью `--group-add`. Для уже существующих файлов сохраняются прежние разрешения. Убедитесь, что для каталога также разрешён доступ группе.

### Ошибки разбора CSV {#csv-parsing-errors}

Синтаксический анализатор рассчитан на 26 столбцов, которые выводит PostgreSQL 14 и новее. Убедитесь, что заданы `log_destination = 'csvlog'` и `log_timezone = 'UTC'`. Для более старых версий или пользовательских форматов скорректируйте заголовок; журналы в форматах stderr и JSON этот синтаксический анализатор CSV обработать не может.
