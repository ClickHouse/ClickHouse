Собирайте метрики PostgreSQL с помощью приёмника PostgreSQL для OpenTelemetry и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без установки PostgreSQL, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker и `curl`
* Для сбора собственных метрик — PostgreSQL 14 или новее, доступный для коллектора, а также пользователь для мониторинга

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы показать скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров с экспортером OTLP задайте следующие переменные в терминале, в котором будете запускать коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точной конечной точкой (включая порт) и ключом API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/metrics`: экспортер сам добавляет путь сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите конечную точку OTLP по HTTP, по которой доступен ваш коллектор (например, `http://YOUR_COLLECTOR_HOST:4318`), и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже включают сопоставление хоста.

## Интеграция с существующим PostgreSQL {#existing-postgres}

<Steps>
  <Step title="Настройте пользователя для мониторинга" id="monitoring-permissions">
    От имени администратора PostgreSQL создайте пользователя для мониторинга, если его ещё нет, и предоставьте ему доступ к статистике:

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    Предоставьте `CONNECT` для каждой базы данных, которую нужно отслеживать. Убедитесь, что сетевые настройки и `pg_hba.conf` позволяют PostgreSQL принимать соединения от коллектора.

    Задайте переменные подключения к базе данных в том же терминале, где заданы переменные подключения OTLP:

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    Если PostgreSQL работает на хосте Docker, используйте `host.docker.internal:5432`. Для контейнеров в общей сети Docker укажите имя хоста контейнера базы данных и добавьте `--network YOUR_NETWORK` в команду запуска коллектора.
  </Step>

  <Step title="Настройте коллектор" id="configure-collector">
    Сохраните следующую конфигурацию в файл `postgres-metrics.yaml`. Замените список `databases` именами ваших баз данных:

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    Эта конфигурация включает TLS и проверяет сертификат сервера. Если используется частный CA, задайте `tls.ca_file` и смонтируйте файл CA в контейнер коллектора. Для локального сервера PostgreSQL без TLS задайте `tls.insecure: true` — это отключит TLS для подключения к базе данных. Подробнее см. в разделе [конфигурации приёмника PostgreSQL](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration).
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал и подождите как минимум два интервала сбора. По завершении тестирования остановите коллектор сочетанием клавиш **Ctrl+C**.
  </Step>

  <Step title="Проверьте метрики" id="verify-metrics">
    Откройте **Обозреватель диаграмм**, выберите источник **Metrics**, задайте фильтр `ServiceName:postgresql-service` и выберите **Last 15 minutes**. Найдите метрики `postgresql.backends`, `postgresql.commits` или `postgresql.db_size`.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Выборка содержит 8,928 точек типов gauge и sum, собранных с интервалом пять минут за 24 часа. В ней сохранены всплески числа соединений, активность кэша, откаты и взаимоблокировки из исходного набора данных. Выборка включает метрики уровня базы данных; при сборе в реальном времени доступны также метрики таблиц и индексов.

Перед началом задайте [переменные подключения](#connection-details).

<Steps>
  <Step title="Скачайте демонстрационные метрики" id="download-sample">
    [Скачайте архив с выборкой](/ru/assets/postgres-metrics-demo.zip) (около 64 КБ) и извлеките `postgres-metrics-demo.json` в рабочий каталог.
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующую конфигурацию в файл `postgres-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      Это преобразование предназначено только для демонстрации: оно обновляет временные метки, сохраняя значения метрик и интервал между начальной и конечной временными метками каждой точки. Для реальных метрик PostgreSQL его не используйте. Ограничение размера пакета не даёт отправляемым данным превысить допустимый для коллектора в пункте назначения объём.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    Из каталога с конфигурацией запустите коллектор и не закрывайте этот терминал:

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Отправьте выборку" id="load-metrics">
    В другом терминале выполните следующую команду из каталога, куда был скачан архив:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    Ответ вида `{}` или `{"partialSuccess":{}}` означает, что локальный коллектор принял запрос. Проверьте, нет ли в терминале коллектора ошибок экспорта, и подождите несколько секунд, пока данные будут переданы. Убедившись, что данные поступили, остановите коллектор сочетанием клавиш **Ctrl+C**. Повторная отправка выборки может привести к дублированию точек.
  </Step>

  <Step title="Проверьте метрики" id="verify-demo-metrics">
    Импортируйте панель мониторинга из [следующего раздела](#dashboards), задайте фильтр `ServiceName:postgresql-demo` и выберите **Last 2 days**. Выборка содержит метрики типов gauge и sum; прямой доступ к базе данных не требуется.
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Коллектор не запускается {#collector-fails-to-start}

Проверьте вывод коллектора на наличие ошибок конфигурации. Убедитесь, что файл конфигурации смонтирован, а переменные подключения заданы в том терминале, где запускается Docker.

### Метрики не отображаются {#no-metrics}

Проверьте вывод коллектора на наличие ошибок подключения к базе данных или ошибок экспорта. Убедитесь, что имя хоста базы данных доступно из контейнера, имена баз данных указаны верно, а PostgreSQL разрешает подключение пользователю, используемому для мониторинга. Проверьте источник **Metrics**, фильтр по имени сервиса и временной диапазон.

### Ошибки аутентификации или TLS {#authentication-errors}

Убедитесь, что у пользователя для мониторинга есть разрешения `pg_monitor` и `CONNECT`. Проверьте учётные данные базы данных с помощью `psql` на хосте, с которого доступен PostgreSQL:

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

Приведите настройки TLS приёмника в соответствие с конфигурацией сервера и смонтируйте необходимый CA‑сертификат. При ошибках экспорта сверьте конечную точку OTLP и параметры авторизации со сведениями о подключении к вашему сервису.
