Собирайте журналы доступа Nginx в формате JSON с помощью коллектора OpenTelemetry и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию, не устанавливая Nginx, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker для выполнения приведённых ниже команд коллектора или уже развёрнутый OpenTelemetry Collector Contrib
* Для сбора собственных журналов — установленный Nginx, разрешение на изменение его конфигурации и доступ коллектора к его файлам журналов

Чтобы опробовать интеграцию без настройки Nginx и сбора собственных журналов, используйте [демо-набор данных](#demo-dataset). В него входит автономная конфигурация коллектора для этих демонстрационных данных.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор запущен на хосте с Docker Desktop, используйте `host.docker.internal` вместо `localhost`. В Linux используйте общую сеть Docker и имя контейнера пункта назначения либо другой доступный адрес хоста.

## Интеграция с существующим Nginx {#existing-nginx}

Запустите коллектор на хосте, с которого доступны для чтения журналы доступа Nginx. Коллектор разбирает журналы и пересылает их на конечную точку OTLP по HTTP вашего сервиса.

<Steps>
  <Step title="Настройка формата логирования Nginx" id="configure-nginx">
    Настройте в `nginx.conf` запись журналов доступа Nginx в формате JSON.

    Файл `nginx.conf` обычно находится по одному из следующих путей:

    * **Linux (apt/yum)**: `/etc/nginx/nginx.conf`
    * **macOS (Homebrew)**: `/usr/local/etc/nginx/nginx.conf` или `/opt/homebrew/etc/nginx/nginx.conf`
    * **Docker**: конфигурация, как правило, монтируется как том

    Добавьте следующие директивы в существующий блок `http`. Остальную конфигурацию оставьте без изменений, а существующую директиву `access_log` для того же файла замените:

    ```nginx
    log_format json_combined escape=json
    '{'
      '"time_local":"$time_local",'
      '"remote_addr":"$remote_addr",'
      '"remote_user":"$remote_user",'
      '"request":"$request",'
      '"status":$status,'
      '"body_bytes_sent":$body_bytes_sent,'
      '"request_time":$request_time,'
      '"upstream_response_time":"$upstream_response_time",'
      '"http_referer":"$http_referer",'
      '"http_user_agent":"$http_user_agent",'
      '"http_x_forwarded_for":"$http_x_forwarded_for",'
      '"http_host":"$http_host"'
    '}';

    access_log /var/log/nginx/access.log json_combined;
    ```

    В этом формате используются те же имена полей, что и в демонстрационном датасете, включая `request`, которое содержит метод, URI и версию HTTP. Поле `upstream_response_time` хранится как строка, поскольку [Nginx может сообщать несколько значений времени ответа вышестоящих серверов](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#var_upstream_response_time). В демонстрационном датасете это поле содержит одно числовое значение.

    Проверьте корректность конфигурации командой `nginx -t`, затем перезагрузите Nginx способом, обычно принятым в вашем развертывании. Если блок `server` или `location` переопределяет `access_log`, обновите и эту директиву, чтобы в ней тоже использовался `json_combined`.
  </Step>

  <Step title="Настройте коллектор" id="custom-otel">
    Получите [сведения о подключении](#demo-connection-details) и задайте переменные окружения для конечной точки и API-ключа в терминале, где будет запускаться коллектор. Сохраните следующую полную конфигурацию в файл `nginx-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx/access.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx
          - type: add
            field: resource["service.name"]
            value: nginx

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx:
          receivers: [filelog/nginx]
          processors: [memory_limiter, batch]
          exporters: [otlp_http/observability]
    ```

    Эта конфигурация считывает новые записи журнала доступа в формате JSON, сохраняет их исходные временные метки и задаёт для `service.name` значение `nginx`. Журналы пересылаются на вашу конечную точку OTLP по HTTP с использованием указанных выше настроек аутентификации. Журналы ошибок Nginx требуют отдельного синтаксического анализатора и в эту конфигурацию не входят.
  </Step>

  <Step title="Запустите коллектор" id="load-custom">
    Приведённая ниже команда предполагает, что логи находятся в каталоге `/var/log/nginx` на хосте Docker. Если ваши файлы расположены в другом месте, измените путь на стороне хоста при монтировании логов. Если Nginx работает в контейнере, вместо этого смонтируйте в коллектор его общий том с логами.

    Из каталога, содержащего `nginx-monitoring.yaml`, выполните:

    ```bash
    docker run --rm --name nginx-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/nginx:/var/log/nginx:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Коллектор работает в интерактивном режиме (не в фоне) и должен иметь разрешение на чтение смонтированных файлов журналов. Не останавливайте его и отправьте несколько запросов к Nginx из другого терминала или браузера, чтобы в журнале доступа появились новые записи.
  </Step>

  <Step title="Проверьте журналы в ClickHouse Observability" id="verifying-logs">
    1. Откройте **Поиск** в интерфейсе и выберите **Logs**.
    2. Задайте фильтр `ServiceName:nginx` и выберите временной диапазон, в который попадают ваши запросы.
    3. Разверните запись и выберите **Column Values**, чтобы просмотреть такие поля, как `request`, `request_time` и `upstream_response_time`, в разделе `LogAttributes`.

    В следующем примере показано то же представление для демо-набора данных с фильтром `ServiceName:nginx-demo`:

    <div className="ch-image-lg">
      <Frame>

      </Frame>
    </div>
  </Step>
</Steps>

## Демо-набор данных {#demo-dataset}

Тестовый набор данных содержит 14,743 записи журнала доступа в формате JSON: успешные запросы, ошибки и время ответа вышестоящих серверов. Вам потребуются Docker и сервис ClickHouse Observability. Перед началом задайте [переменные окружения для соединения](#demo-connection-details); загруженный файл и конфигурация должны находиться в одном каталоге.

<Steps>
  <Step title="Загрузите тестовый набор данных" id="download-sample">
    ```bash
    # Загрузка журналов
    curl -O https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/access.log
    ```
  </Step>

  <Step title="Создайте тестовую конфигурацию коллектора" id="test-config">
    Сохраните приведённую ниже полную конфигурацию в файл `nginx-demo.yaml`. Коллектор считывает загруженные журналы доступа и пересылает их на вашу конечную точку OTLP.

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx-demo/access.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx-demo
          - type: add
            field: resource["service.name"]
            value: nginx-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-21T16:34:27Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx-demo:
          receivers: [filelog/nginx]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Процессор `transform/demo_timestamps`, предназначенный только для демонстрации, сдвигает временные метки выборки примерно в пределы последних 24 часов так, что последняя из них приходится на две минуты до ингестии; характер трафика при этом сохраняется. Исходный атрибут `time_local` и тело записи журнала не изменяются. Для собственных журналов Nginx не используйте этот процессор, чтобы сохранить их исходные временные метки.
    </Note>

    В примерах автономного коллектора используется OpenTelemetry Collector Contrib `0.161.0` — версия, на которой проверялись эти конфигурации.
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo">
    В каталоге, где находятся `access.log` и `nginx-demo.yaml`, запустите образ OpenTelemetry Collector Contrib:

    ```bash
    docker run --rm --name nginx-demo-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/access.log:/var/log/nginx-demo/access.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте этот терминал, пока проверяете ингестию. Оба смонтированных файла должны быть доступны контейнеру для чтения. Когда журналы появятся, нажмите **Ctrl+C**, чтобы остановить демонстрационный коллектор. При повторном запуске набор данных будет загружен заново с новыми сдвинутыми временными метками, поскольку в этой демонстрации смещения в файле не сохраняются.
  </Step>

  <Step title="Проверьте журналы в ClickHouse Observability" id="verify-demo-logs">
    После запуска коллектора:

    1. Откройте UI.
    2. Перейдите в **Search**, выберите **Logs** и примените фильтр `ServiceName:nginx-demo`.
    3. Выберите временной диапазон **Last 2 days**, чтобы охватить весь сдвинутый набор данных.

    Раскройте запись журнала и выберите **Column Values**, чтобы просмотреть разобранные поля в `LogAttributes`.

      <Frame>

      </Frame>

  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Коллектор не запускается {#troubleshooting-not-loading}

Проверьте вывод коллектора в терминале на наличие ошибок конфигурации. Убедитесь, что YAML-файл находится по смонтированному пути. Если вы используете конфигурацию с экспортером OTLP, убедитесь, что переменная конечной точки и необходимые переменные для аутентификации заданы в том терминале, в котором вы запускаете Docker.

### Журналы не отображаются {#no-logs}

* Проверьте вывод коллектора на наличие ошибок аутентификации или ошибок экспорта. Если вы используете экспортер OTLP, сверьте конечную точку и заголовок авторизации со [сведениями о подключении](#demo-connection-details).
* Убедитесь, что Nginx записывает журналы доступа в формате JSON и что коллектор может их читать. При `start_at: end` отправьте новые запросы уже после запуска коллектора.
* Проверьте выбранный источник **Logs** и фильтр по имени сервиса: `ServiceName:nginx-demo` для демо-набора данных или `ServiceName:nginx` для собственных журналов.
* Задайте временной диапазон, в который попадают журналы. Для демо-данных убедитесь, что `transform/demo_timestamps` включён в конвейер, и выберите **Last 2 days**.

Для собственных журналов Nginx проверьте файл на хосте и точки монтирования контейнера коллектора. Убедитесь, что путь назначения совпадает с путём в конфигурации приёмника. Замените `CONTAINER_NAME` на имя контейнера коллектора и при необходимости скорректируйте путь на хосте:

```bash
tail -f /var/log/nginx/access.log
docker inspect --format '{{json .Mounts}}' CONTAINER_NAME
```
