Собирайте распределённые трассировки из Nginx с помощью модуля OpenTelemetry для Nginx и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без установки Nginx, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Для собственных трассировок — установленный Nginx с модулем OpenTelemetry и разрешение на изменение его конфигурации; в приведённом ниже примере для Docker используется `nginx:1.27-otel`
* Для демо-набора данных — `curl` и Docker

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку и ключ API с помощью **Copy connection details** или нажмите **Reveal key**, чтобы увидеть скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Модуль Nginx экспортирует данные по **OTLP/gRPC**, обычно на порт **4317**. Демонстрационный пример с JSON использует **OTLP/HTTP**, обычно на порт **4318**. Укажите конечную точку для соответствующего протокола, включая `https://`, если требуется TLS:

    ```bash
    export OTEL_EXPORTER_OTLP_GRPC_ENDPOINT='https://YOUR_OTEL_HOST:4317'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры сведениями о подключении к вашему сервису. Указывайте базовую конечную точку HTTP без `/v1/traces` — экспортер коллектора добавляет этот путь сам.
  </Tab>

  <Tab title="Самоуправляемый">
    Используйте конечные точки OTLP и настройки аутентификации вашего коллектора. Если коллектор не требует аутентификации, удалите директиву Nginx `header authorization` и блок `headers` в конфигурации демонстрационного коллектора. См. [руководство по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_GRPC_ENDPOINT='http://YOUR_COLLECTOR_HOST:4317'
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка gRPC должна быть доступна из Nginx. В Docker Desktop используйте `host.docker.internal`, чтобы обратиться к коллектору на хосте. Для контейнеров в общей сети Docker укажите имя контейнера коллектора. Для локальной конечной точки без TLS используйте `http://`.

## Интеграция с существующим Nginx {#existing-nginx}

<Steps>
  <Step title="Установите модуль OpenTelemetry для Nginx" id="install-module">
    Образ `nginx:1.27-otel` уже содержит `ngx_otel_module.so`. Для установки вне Docker следуйте инструкциям по установке, ссылки на которые приведены в [документации модуля OpenTelemetry для Nginx](https://nginx.org/en/docs/ngx_otel_module.html).
  </Step>

  <Step title="Настройте трассировку Nginx" id="configure-nginx">
    В следующем примере для Docker используется шаблон, чтобы скрипт запуска контейнера подставлял переменные окружения для подключения. Сохраните его как `nginx.conf.template`. Блок location с `return 200` служит для простой проверки работоспособности; для вашего приложения сохраните существующую конфигурацию сервера и маршрутизации и добавьте показанные здесь директивы трассировки.

    ```nginx
    load_module modules/ngx_otel_module.so;

    events {
        worker_connections 1024;
    }

    http {
        otel_exporter {
            endpoint ${OTEL_EXPORTER_OTLP_GRPC_ENDPOINT};
            header authorization "${OTEL_EXPORTER_OTLP_AUTHORIZATION}";
        }

        otel_service_name "nginx-proxy";
        otel_trace on;

        server {
            listen 80;

            location / {
                otel_trace_context propagate;
                otel_span_name "$request_method $uri";
                otel_span_attr http.status_code $status;
                otel_span_attr http.request.method $request_method;
                otel_span_attr http.route $uri;
                return 200 "Nginx tracing is enabled\n";
            }
        }
    }
    ```

    Сохраните следующий файл как `compose.yaml` в том же каталоге:

    ```yaml
    services:
      nginx:
        image: nginx:1.27-otel
        ports:
          - "8081:80"
        environment:
          OTEL_EXPORTER_OTLP_GRPC_ENDPOINT: ${OTEL_EXPORTER_OTLP_GRPC_ENDPOINT}
          OTEL_EXPORTER_OTLP_AUTHORIZATION: ${OTEL_EXPORTER_OTLP_AUTHORIZATION}
          NGINX_ENVSUBST_OUTPUT_DIR: /etc/nginx
          NGINX_ENVSUBST_FILTER: ^OTEL_EXPORTER_OTLP_
        volumes:
          - ./nginx.conf.template:/etc/nginx/templates/nginx.conf.template:ro
    ```

    Фильтр подстановки оставляет нетронутыми переменные Nginx, такие как `$request_method` и `$uri`. Nginx не подставляет переменные окружения оболочки автоматически в напрямую смонтированный `nginx.conf`. Вне Docker перед проверкой корректности конфигурации замените плейсхолдеры подключения фактическими значениями и ограничьте доступ к файлу, содержащему ключ.
  </Step>

  <Step title="Проверьте конфигурацию и запустите Nginx" id="run-nginx">
    Задайте [переменные подключения](#connection-details) в том же терминале, затем выполните:

    ```bash
    docker compose run --rm nginx nginx -t
    docker compose up -d nginx
    curl http://localhost:8081/
    ```

    Каждый запрос создает спан, в котором фиксируются метод, путь, код состояния и длительность. Для существующего развертывания отправьте запросы на URL вашего приложения. После изменения шаблона или переменных окружения выполните `docker compose up -d --force-recreate nginx`, чтобы применить изменения.
  </Step>

  <Step title="Проверьте трассировки в UI" id="verifying-traces">
    Откройте **Поиск**, выберите **Трассировки** и задайте фильтр `ServiceName:nginx-proxy`. Выберите временной диапазон, охватывающий ваши запросы, и подождите несколько секунд, пока завершится экспорт. Откройте трассу, чтобы изучить её спаны и HTTP-атрибуты.

    <div className="ch-image-lg">
      <Frame>
        ![Трассировки Nginx в представлении поиска](/images/clickstack/observability-nginx-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Этот пример содержит 1,000 спанов Nginx по девяти конечным точкам: успешные запросы, HTTP-ошибки и запросы с разными задержками. Перед отправкой данных задайте [переменные подключения](#connection-details).

<Steps>
  <Step title="Загрузите тестовый набор данных" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nginx-traces-sample.json
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующую конфигурацию в файл `nginx-traces-demo.yaml` в каталоге загрузки:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T19:36:05Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nginx-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Процессор `transform/demo_timestamps`, предназначенный только для демонстрации, сдвигает эту выборку примерно в пределы последних 24 часов так, чтобы она заканчивалась за две минуты до момента приёма. Длительность спанов и характер трафика при этом сохраняются. Для собственных трассировок Nginx не используйте этот процессор, чтобы сохранить их исходные временные метки. Повторная отправка выборки может привести к дублированию спанов.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    <Note>
      Если целевой коллектор запущен на этом же компьютере, задайте для `OTEL_EXPORTER_OTLP_ENDPOINT` значение `http://host.docker.internal:4318`. Приведённая ниже команда уже включает сопоставление хоста Docker.
    </Note>

    Запустите OpenTelemetry Collector Contrib `0.161.0` из каталога с конфигурацией в том терминале, где вы задали переменные подключения. Не закрывайте этот терминал:

    ```bash
    docker run --rm --name nginx-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Локальный приёмник использует порт `14318`, чтобы не конфликтовать с уже работающим коллектором на порту `4318`. Коллектор пересылает трассировки на настроенную вами конечную точку с указанными выше параметрами аутентификации.
  </Step>

  <Step title="Отправьте трассировки" id="send-traces">
    В другом терминале перейдите в каталог загрузки и отправьте исходную выборку в локальный коллектор:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nginx-traces-sample.json
    ```

    Пустой успешный ответ, например `{}` или `{"partialSuccess":{}}`, означает, что локальный коллектор принял запрос. Проверьте вывод коллектора на наличие ошибок экспорта и подождите несколько секунд, пока пакет дойдёт до вашего сервиса. По завершении остановите демонстрационный коллектор сочетанием клавиш **Ctrl+C**.
  </Step>

  <Step title="Проверьте демонстрационные трассировки" id="verify-demo-traces">
    Откройте **Поиск**, выберите **Трассировки**, задайте фильтр `ServiceName:nginx-proxy` и выберите **Last 2 days**, чтобы охватить весь сдвинутый набор данных. Откройте трассировку, чтобы просмотреть её HTTP-атрибуты.

    <div className="ch-image-lg">
      <Frame>
        ![Пример трассировок Nginx в представлении поиска](/images/clickstack/observability-nginx-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Nginx не запускается {#nginx-fails-to-start}

Выполните `docker compose run --rm nginx nginx -t`, чтобы проверить корректность сгенерированной конфигурации. Если появляется ошибка о неизвестной директиве `otel_*` или отсутствующем файле модуля, значит, модуль не установлен или не загружен. Убедитесь, что вы используете образ `-otel` и что шаблон смонтирован по пути, указанному в документации.

### Трассировки не отображаются {#no-traces}

* Проверьте gRPC-конечную точку и параметры аутентификации, которые требует коллектор в пункте назначения. Управляемые сервисы используют префикс `Bearer`. Не используйте HTTP-конечную точку для модуля Nginx.
* Убедитесь, что конечная точка доступна из контейнера Nginx, а её схема соответствует настройке TLS в пункте назначения.
* Сгенерируйте запросы: бездействующий инстанс Nginx не создаёт спаны запросов.
* Проверьте раздел **Трассировки**, фильтр по имени сервиса и выбранный временной диапазон. Для демонстрационного примера убедитесь, что `transform/demo_timestamps` включён в конвейер коллектора, и выберите **Last 2 days**.
* Для демонстрационного примера проверьте вывод коллектора в терминале на наличие ошибок аутентификации или экспорта. Сверьте его HTTP-конечную точку и значение авторизации со сведениями о подключении.
* Просмотрите ошибки Nginx с помощью `docker compose logs nginx`. Если Docker не используется, просмотрите журнал ошибок Nginx.
