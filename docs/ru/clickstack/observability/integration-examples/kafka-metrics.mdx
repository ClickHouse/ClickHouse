Собирайте метрики брокеров Kafka с помощью OpenTelemetry JMX Metric Gatherer и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без развертывания Kafka, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker с Docker Compose и `curl`
* Для сбора собственных метрик — брокер Kafka с включённым удалённым JMX, доступный для сборщика

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → управляемая телеметрия**. Скопируйте конечную точку OTLP по HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы увидеть скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе управляемой телеметрии](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Задайте эти переменные в терминале, в котором будете запускать сборщик JMX или демонстрационный коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точными значениями конечной точки (включая порт) и ключа API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/metrics`: экспортер сам добавляет путь сигнала в конец.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP по HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, не указывайте аргумент `-Dotel.exporter.otlp.headers` сборщика JMX и блок `headers` демонстрационного коллектора. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера сборщика или коллектора. Если коллектор — пункт назначения работает на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже содержат сопоставление хоста.

## Интеграция с существующим развертыванием Kafka {#existing-kafka}

<Steps>
  <Step title="Проверьте конечную точку JMX брокера" id="verify-jmx">
    Используйте удалённую конечную точку JMX, настроенную для вашего брокера. Например, если брокер предоставляет JMX на порту `9999`:

    ```bash
    export KAFKA_JMX_URL='service:jmx:rmi:///jndi/rmi://YOUR_KAFKA_HOST:9999/jmxrmi'
    export KAFKA_BROKER_ID='broker-0'
    ```

    Замените имя хоста и ID брокера своими значениями. Имя хоста RMI, которое объявляет брокер, также должно быть доступно для сборщика. Если брокер использует отдельные порты для registry и RMI, откройте сетевой доступ к обоим. Сборщик считывает данные через JMX, поэтому клиентский порт Kafka `9092` ему не нужен.

    Если контейнеры находятся в общей сети Docker, укажите имя хоста контейнера брокера. Если брокер работает на хосте Docker, используйте `host.docker.internal` и настройте брокер так, чтобы он объявлял имя хоста, доступное из контейнера. Ограничьте доступ к JMX сетью мониторинга и сохраните настройки аутентификации и TLS вашего брокера.
  </Step>

  <Step title="Загрузите JMX Metric Gatherer" id="download-jmx">
    ```bash
    curl -fL -o opentelemetry-jmx-metrics.jar \
      https://github.com/open-telemetry/opentelemetry-java-contrib/releases/download/v1.32.0/opentelemetry-jmx-metrics.jar
    ```
  </Step>

  <Step title="Настройте сборщик" id="configure-gatherer">
    Сохраните следующую конфигурацию в файл `compose.yaml` рядом с загруженным JAR-файлом:

    ```yaml
    services:
      kafka-jmx-gatherer:
        image: eclipse-temurin:11-jre
        extra_hosts:
          - "host.docker.internal:host-gateway"
        environment:
          - KAFKA_JMX_URL
          - KAFKA_BROKER_ID
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        volumes:
          - ./opentelemetry-jmx-metrics.jar:/app/opentelemetry-jmx-metrics.jar:ro
        command:
          - sh
          - -c
          - >-
            exec java
            -Dotel.jmx.service.url="$${KAFKA_JMX_URL}"
            -Dotel.jmx.target.system=kafka
            -Dotel.jmx.interval.milliseconds=10000
            -Dotel.metrics.exporter=otlp
            -Dotel.exporter.otlp.protocol=http/protobuf
            -Dotel.exporter.otlp.endpoint="$${OTEL_EXPORTER_OTLP_ENDPOINT}"
            -Dotel.exporter.otlp.headers="authorization=$${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
            -Dotel.resource.attributes="service.name=kafka-service,kafka.broker.id=$${KAFKA_BROKER_ID}"
            -jar /app/opentelemetry-jmx-metrics.jar
    ```

    Если брокер находится в существующей сети Docker, подключите к ней `kafka-jmx-gatherer` в конфигурации Compose. Для JMX с аутентификацией добавьте свойства `otel.jmx.username` и `otel.jmx.password`; для TLS настройте соответствующее хранилище доверенных сертификатов. Подробнее см. в [описании аутентификации и настройки TLS сборщика](https://github.com/open-telemetry/opentelemetry-java-contrib/tree/v1.32.0/jmx-metrics#configuration).
  </Step>

  <Step title="Запустите сбор" id="run-gatherer">
    Задайте в этом терминале [переменные подключения](#connection-details) и переменные брокера, затем выполните команду в каталоге с файлом `compose.yaml`:

    ```bash
    docker compose up kafka-jmx-gatherer
    ```

    Не закрывайте терминал и следите за ошибками JMX-соединения и ошибками экспорта OTLP. Сборщик собирает данные каждые 10 секунд. Прежде чем проверять сервис, подождите как минимум два интервала сбора. После завершения тестирования остановите сборщик клавишами **Ctrl+C**.

    Если брокеров несколько, запустите отдельный сборщик для каждого из них с собственным JMX URL и `kafka.broker.id`.
  </Step>

  <Step title="Проверьте метрики" id="verify-metrics">
    Откройте **Обозреватель диаграмм**, выберите источник **Metrics**, задайте фильтр `ServiceName:kafka-service` и выберите **Last 15 minutes**. Найдите метрики `kafka.partition.count`, `kafka.partition.under_replicated` или `kafka.message.count`. Метрики, связанные с трафиком, показывают осмысленные значения только при активности брокера.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Выборка содержит 6,282 точки метрик типов Gauge и Sum, снятых с интервалом в пять минут на протяжении примерно 29 часов. В ней сохранены характерные для исходного набора данных всплески трафика, задержки запросов, отставание потребителя и состояние партиций. Развёртывать Kafka или получать прямой доступ к базе данных не требуется.

Перед началом задайте [переменные подключения](#connection-details).

<Steps>
  <Step title="Скачайте пример метрик" id="download-sample">
    [Скачайте архив с примером](/ru/assets/kafka-metrics-demo.zip) (около 53 КБ) и распакуйте `kafka-metrics-demo.json` в рабочий каталог.
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующую конфигурацию в файл `kafka-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: kafka-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-06T22:14:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      Преобразование, нужное только для демонстрации, обновляет временные метки, сохраняя значения метрик и интервал между начальной и конечной временными метками каждой точки. Для реальных метрик Kafka его не используйте. Ограничение размера пакета не позволяет отправляемым данным превысить допустимый для коллектора в пункте назначения объём.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    В каталоге с конфигурацией запустите коллектор и не закрывайте этот терминал:

    ```bash
    docker run --rm --name kafka-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Отправьте выборку" id="load-metrics">
    В другом терминале выполните следующую команду в каталоге, куда был скачан архив:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @kafka-metrics-demo.json
    ```

    Ответ вида `{}` или `{"partialSuccess":{}}` означает, что локальный коллектор принял запрос. Убедитесь, что в терминале коллектора нет ошибок экспорта, и подождите несколько секунд, пока данные будут переданы. Убедившись, что данные поступили, остановите коллектор сочетанием **Ctrl+C**. Повторная отправка выборки может привести к появлению дубликатов точек.
  </Step>

  <Step title="Проверьте метрики" id="verify-demo-metrics">
    Импортируйте панель мониторинга из [следующего раздела](#dashboards), задайте фильтр `ServiceName:kafka-demo` и выберите **последние 2 дня**. Выборка содержит метрики обоих типов — Gauge и Sum; прямой доступ к базе данных не требуется.
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Не удаётся установить JMX-соединение {#jmx-connection-fails}

Проверьте вывод сборщика с помощью `docker compose logs kafka-jmx-gatherer`. Убедитесь, что JMX включён, что registry и объявленная (advertised) конечная точка RMI доступны, а настроенные учётные данные JMX и хранилище доверенных сертификатов соответствуют параметрам брокера. Если используются имена хостов контейнеров, контейнеры должны находиться в одной сети, предусмотренной конфигурацией.

### Метрики не отображаются {#no-metrics}

* Проверьте вывод сборщика или демонстрационного коллектора на наличие ошибок соединения, аутентификации или экспорта.
* Сверьте конечную точку OTLP по HTTP и параметры аутентификации со сведениями о подключении к вашему сервису.
* Проверьте источник **Metrics**, фильтр по имени сервиса и временной диапазон. Для демонстрационного примера выберите **Последние 2 дня**.
* Если вы используете существующий коллектор, убедитесь, что его конвейер метрик включает приёмник OTLP и экспортер метрик.
* Прежде чем использовать демонстрационную панель мониторинга, проверьте фактические имена метрик в **Обозревателе диаграмм**.

### Конфликты портов JMX при выполнении клиентских команд Kafka {#port-conflicts}

Если вы запускаете клиентские команды Kafka внутри контейнера брокера, сбросьте для этой команды унаследованные настройки JMX брокера, чтобы клиент не пытался занять тот же порт:

```bash
env -u JMX_PORT -u KAFKA_JMX_OPTS kafka-topics --list --bootstrap-server YOUR_KAFKA_HOST:9092
```
