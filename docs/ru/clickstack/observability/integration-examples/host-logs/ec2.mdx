Собирайте файлы syslog с EC2 с помощью коллектора OpenTelemetry и отправляйте их в ClickHouse Observability вместе с метаданными инстанса. Чтобы опробовать интеграцию без инстанса EC2, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Для работы с собственными журналами — инстанс Linux EC2 с файлами syslog, доступом к службе метаданных экземпляра и разрешением на установку и запуск коллектора
* Для демонстрации — Docker
* `curl` для загрузки коллектора или демонстрационных данных

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Бета-версия" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы увидеть скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров экспортера OTLP задайте следующие переменные в терминале, в котором будет запускаться коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точным адресом конечной точки (включая порт) и ключом API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/logs`: экспортер сам добавляет путь сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна по сети с вашего инстанса EC2. В демонстрации с Docker коллектор-получатель, запущенный на вашем компьютере, доступен по адресу `http://host.docker.internal:4318`; сопоставление хоста уже задано в демонстрационной команде.

## Интеграция с существующим инстансом EC2 {#existing-ec2}

Выполните следующие шаги на том инстансе EC2, с которого нужно собирать журналы.

<Steps>
  <Step title="Проверьте метаданные инстанса и syslog" id="verify-metadata">
    Убедитесь, что служба метаданных экземпляра доступна через IMDSv2:

    ```bash
    TOKEN=$(curl -fsS --connect-timeout 5 -X PUT \
      -H 'X-aws-ec2-metadata-token-ttl-seconds: 300' \
      http://169.254.169.254/latest/api/token)
    curl -fsS --connect-timeout 5 -H "X-aws-ec2-metadata-token: $TOKEN" \
      http://169.254.169.254/latest/meta-data/instance-id
    ```

    Ответ должен содержать ID экземпляра. С помощью этого сервиса метаданных коллектор добавляет в журналы ID экземпляра, тип, регион, зону доступности и ID аккаунта. Приведённая ниже конфигурация не собирает теги EC2.

    Найдите файл syslog и проверьте его формат:

    ```bash
    # Ubuntu/Debian
    tail -20 /var/log/syslog

    # Amazon Linux/RHEL
    tail -20 /var/log/messages
    ```

    Укажите путь, который фактически существует на вашем инстансе. Если сервис пишет логи только в журнал systemd, для их сбора воспользуйтесь [руководством по Systemd/Journald](/ru/clickstack/observability/integration-examples/systemd).
  </Step>

  <Step title="Установите коллектор" id="install-collector">
    Скачайте OpenTelemetry Collector Contrib `0.161.0` для архитектуры вашего инстанса:

    ```bash
    case "$(uname -m)" in
      x86_64) ARCH=amd64 ;;
      aarch64) ARCH=arm64 ;;
      *) echo "Unsupported architecture"; exit 1 ;;
    esac
    curl -fLO "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz"
    tar -xzf "otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz" otelcol-contrib
    sudo install -m 755 otelcol-contrib /usr/local/bin/otelcol-contrib
    /usr/local/bin/otelcol-contrib --version
    ```
  </Step>

  <Step title="Настройте коллектор" id="configure-collector">
    Сохраните подходящую конфигурацию в файл `ec2-host-logs.yaml`. Выберите вариант в зависимости от формата временных меток в вашем файле и измените `include`, если путь к syslog у вас другой.

    <Tabs>
      <Tab title="Временные метки ISO">
        Для временных меток вида `2026-10-15T12:34:56.123456+00:00`:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="Традиционный syslog">
        Для временных меток вида `Oct 15 12:34:56`:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/messages]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```

        В традиционных временных метках не указываются год и часовой пояс. Синтаксический анализатор определяет год автоматически; если хост ведёт журнал не в UTC, укажите в `location` часовой пояс хоста в формате IANA.
      </Tab>
    </Tabs>

    Приёмник сохраняет исходную строку журнала и извлекает из неё имя хоста, unit, PID (если он указан) и сообщение. Процессор `resourcedetection/ec2` добавляет атрибуты ресурса EC2. Чтобы собирать также теги инстанса, см. [конфигурацию детектора EC2](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/processor/resourcedetectionprocessor#aws-ec2) и требования к разрешениям.
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    Задайте [переменные для соединения](#connection-details) в этом терминале, затем запустите коллектор из каталога с конфигурацией. Коллектору требуется разрешение на чтение файла syslog:

    ```bash
    sudo --preserve-env=OTEL_EXPORTER_OTLP_ENDPOINT,OTEL_EXPORTER_OTLP_AUTHORIZATION \
      /usr/local/bin/otelcol-contrib --config="$(pwd)/ec2-host-logs.yaml"
    ```

    Не закрывайте терминал. Приёмник использует `start_at: end`, поэтому после запуска выполните действия, которые запишут новые события в файл syslog. Для непрерывного сбора данных настройте сервис в рамках вашего процесса развертывания и передайте ему переменные подключения.
  </Step>

  <Step title="Проверьте журналы" id="verify-logs">
    Откройте **Поиск**, выберите источник **Logs**, задайте фильтр `ServiceName:ec2-host-service` и выберите **Last 15 minutes**. Разверните запись и проверьте значения `cloud.provider`, `cloud.region`, `cloud.availability_zone`, `host.id` и `host.type` в её атрибутах ресурса.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Пример содержит 11,658 строк журнала syslog за 24 часа. Коллектор добавляет имитированные метаданные EC2 и обновляет временные метки, поэтому учетная запись AWS не нужна.

<Steps>
  <Step title="Скачать пример" id="download-sample">
    ```bash
    mkdir -p ec2-demo
    cd ec2-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните этот файл как `ec2-host-logs-demo.yaml` в каталоге, куда были загружены данные:

    ```yaml
    receivers:
      filelog/ec2:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: ec2-demo
          - type: add
            field: resource["service.name"]
            value: ec2-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      resource/ec2_demo:
        attributes:
          - key: cloud.provider
            value: "aws"
            action: insert
          - key: cloud.platform
            value: "aws_ec2"
            action: insert
          - key: cloud.region
            value: "us-east-1"
            action: insert
          - key: cloud.availability_zone
            value: "us-east-1a"
            action: insert
          - key: host.id
            value: "i-0abc123def456789"
            action: insert
          - key: host.type
            value: "t3.medium"
            action: insert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/ec2:
          receivers: [filelog/ec2]
          processors: [memory_limiter, resource/ec2_demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Преобразование временных меток, применяемое только для демонстрационных данных, сдвигает выборку примерно в интервал последних 24 часов так, что она заканчивается за две минуты до момента ингестии. Для собственных журналов используйте [конфигурацию инстанса EC2](#existing-ec2): она сохраняет их исходные временные метки.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    Задайте [переменные подключения](#connection-details), затем выполните из каталога загрузки:

    ```bash
    docker run --rm --name ec2-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/ec2-host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал, пока коллектор экспортирует демонстрационные данные, и проверяйте его вывод на наличие ошибок. Если снова запустить новый контейнер, демонстрационные журналы могут продублироваться.
  </Step>

  <Step title="Проверьте демонстрационные журналы" id="verify-demo-logs">
    Откройте **Поиск**, выберите источник **Logs**, задайте фильтр `ServiceName:ec2-demo` и выберите **Last 2 days**. Разверните запись журнала и проверьте имитированные атрибуты ресурса: `cloud.region` имеет значение `us-east-1`, `host.id` — `i-0abc123def456789`, а `host.type` — `t3.medium`. Убедившись, что данные поступают, остановите коллектор сочетанием клавиш **Ctrl+C**.

    <div className="ch-image-lg">
      <Frame>
        ![Демонстрационные журналы EC2 в разделе «Поиск» ClickHouse Observability](/images/clickstack/observability-ec2-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Отсутствуют метаданные EC2 {#no-metadata}

Выполните проверку метаданных на инстансе EC2. Убедитесь, что IMDS включен, а локальный межсетевой экран и настройки прокси разрешают запросы к `169.254.169.254`. Если вы используете прокси, добавьте этот адрес в исключения с помощью `NO_PROXY`. Проверьте вывод коллектора на наличие ошибок определения метаданных. В демонстрации используются имитированные метаданные, поэтому обращения к IMDS не выполняются.

### Журналы не отображаются {#no-logs}

* Убедитесь, что путь, указанный в `include`, существует и коллектор может читать файлы по нему.
* После запуска сгенерируйте новые записи журнала: при `start_at: end` уже существующее содержимое пропускается.
* Проверьте вывод коллектора на наличие ошибок аутентификации или экспорта и убедитесь, что конечная точка доступна с инстанса.
* Проверьте источник **Logs**, фильтр по имени сервиса и временной диапазон. Для демонстрационных данных выберите **Last 2 days**.

### Журналы разбираются некорректно {#logs-not-parsing}

Сверьте формат временных меток в файле с выбранной конфигурацией. Для традиционного syslog укажите правильный часовой пояс хоста. Собирайте только файлы, соответствующие настроенному формату.
