Собирайте журналы AWS CloudWatch с помощью коллектора OpenTelemetry и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без настройки доступа к AWS, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker с Docker Compose для запуска примеров коллектора или уже развернутый OpenTelemetry Collector Contrib
* Для собственных журналов — учётная запись AWS с группами журналов CloudWatch, AWS CLI v2 и учётные данные с перечисленными ниже разрешениями
* Для демонстрации — `curl` для загрузки демонстрационных данных

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Чтобы скопировать конфигурацию, нажмите **Copy connection details**, а чтобы увидеть скрытый ключ — **Reveal key**.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе управляемой телеметрии](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров с экспортером OTLP задайте следующие переменные в терминале, в котором будет запускаться коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точными значениями конечной точки (включая порт) и ключа API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/logs`: экспортер сам добавляет в конец путь сигнала.
  </Tab>

  <Tab title="Самоуправляемый" id="self-managed">
    Укажите конечную точку OTLP по HTTP, доступную на вашем коллекторе (например, `http://YOUR_COLLECTOR_HOST:4318`), и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже включают сопоставление хоста.

## Интеграция с существующими группами журналов CloudWatch {#existing-cloudwatch}

<Steps>
  <Step title="Настройте учётные данные AWS" id="configure-aws">
    Если вы используете AWS SSO, выполните вход и экспортируйте временные учётные данные в терминале, в котором будете запускать коллектор:

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    Замените имя профиля и регион на собственные. Если вы уже используете учётные данные из переменных окружения, задайте `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` и `AWS_SESSION_TOKEN` (для временных учётных данных), а также `AWS_REGION`. Эти учётные данные предоставляют право на чтение журналов AWS и не связаны с учётными данными OTLP вашего пункта назначения.

    IAM-идентичности требуются следующие разрешения. Замените `YOUR_REGION` и `YOUR_ACCOUNT_ID`; при необходимости ограничьте ресурс групп журналов только теми группами, данные из которых вы планируете собирать:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Выведите список доступных групп логов, чтобы выбрать имена для конфигурации:

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="Настройте приёмник CloudWatch" id="configure-receiver">
    Сохраните этот файл как `cloudwatch-logs.yaml`. Замените `/aws/lambda/my-function` на группу журналов из вашего аккаунта; при необходимости добавьте другие группы в раздел `named`.

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    Эта конфигурация сначала собирает журналы за последний час, а затем опрашивает источник каждую минуту. Чтобы изменить начальное окно, настройте параметр `initial_lookback`. Если хранилище контрольных точек не является постоянным, после перезапуска коллектора это окно может быть прочитано повторно, что приведёт к появлению дубликатов.

    Чтобы вместо этого обнаруживать группы по префиксу, замените блок `groups` следующим:

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    Используйте либо `named`, либо `autodiscover`. Дополнительные параметры, включая постоянные контрольные точки, описаны в [документации по приёмнику CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver).
  </Step>

  <Step title="Запустите коллектор" id="start-collector">
    Сохраните этот файл как `docker-compose.yaml` в том же каталоге, что и `cloudwatch-logs.yaml`:

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    В терминале, где вы задали учётные данные AWS и [переменные подключения](#connection-details), запустите коллектор и просмотрите его вывод:

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Проверьте журналы" id="verify-logs">
    Откройте **Поиск** в ClickHouse Observability, выберите источник **Logs** и задайте фильтр `ServiceName:cloudwatch`. Выберите **Last 2 hours** и подождите один-два интервала опроса, пока не появятся журналы.

    Найдите следующие атрибуты ресурса:

    * `aws.region`: регион AWS
    * `cloudwatch.log.group.name`: группа журналов
    * `cloudwatch.log.stream`: поток журнала

    Текст сообщения журнала отображается в поле `Body`. Приёмник сохраняет сообщение, но не определяет автоматически уровень серьёзности по его тексту. Чтобы панели мониторинга с разбивкой по уровню серьёзности работали, ваш конвейер журналов должен заполнять поле `SeverityText`.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Набор содержит 12,785 записей журнала, охватывающих 24 часа активности Lambda, ECS и фоновых задач. В нём есть группы журналов, потоки и значения уровня серьёзности. Для этого варианта не нужны ни учётные данные AWS, ни прямой доступ к базе данных.

<Steps>
  <Step title="Скачайте пример данных" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующую конфигурацию в файл `cloudwatch-demo.yaml` в каталоге загрузки:

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Демонстрационная конфигурация считывает пример данных в формате строк ClickHouse и восстанавливает тело, уровень серьёзности и атрибуты журнала. Преобразование временных меток смещает данные так, чтобы они охватывали примерно последние 24 часа и заканчивались за две минуты до момента приёма. Для собственных журналов используйте приведённую выше конфигурацию приёмника CloudWatch — так их исходные временные метки сохранятся.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    Задайте [переменные подключения](#connection-details), затем выполните следующую команду в каталоге загрузки:

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал, пока коллектор считывает и экспортирует файл. Проверьте его вывод на наличие ошибок. Повторный запуск нового контейнера может привести к дублированию демонстрационных журналов.
  </Step>

  <Step title="Проверьте демонстрационные журналы" id="verify-demo-logs">
    Откройте **Search**, выберите источник **Журналы**, задайте фильтр `ServiceName:cloudwatch-demo` и выберите **Last 2 days**. Разверните запись журнала, чтобы просмотреть её тело, уровень серьёзности, группу журналов и поток. После проверки данных остановите демонстрационный коллектор сочетанием клавиш **Ctrl+C**.

      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Журналы не отображаются {#no-logs}

* Проверьте вывод `docker compose logs otel-collector` на наличие ошибок аутентификации AWS, отказа в доступе или ошибок экспорта OTLP.
* Убедитесь, что `AWS_REGION` и имена групп журналов соответствуют вашему аккаунту, а группы содержат события в пределах `initial_lookback` или новые события, появившиеся после запуска.
* Проверьте разрешения IAM для `logs:DescribeLogGroups` и `logs:FilterLogEvents`.
* Проверьте конечную точку пункта назначения и настройки аутентификации, указанные в разделе [Сведения о подключении](#connection-details).
* Проверьте источник **Журналы**, фильтр по имени сервиса и временной диапазон. Для демонстрационных данных выберите **Last 2 days**.

### Истёк срок действия учётных данных AWS {#expired-credentials}

При использовании SSO снова выполните вход и заново экспортируйте учётные данные, а затем пересоздайте коллектор, чтобы он получил новые значения переменных окружения:

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

Простой перезапуск существующего контейнера не обновляет его учётные данные. Если используются другие временные учётные данные, перед повторным созданием контейнера обновите ключ доступа, секретный ключ и токен сеанса.

### Отсутствуют более старые журналы {#older-logs}

В примере журналы считываются начиная с момента на один час раньше текущего. Увеличьте значение `logs.initial_lookback` или замените его на `logs.start_from` с временной меткой в формате RFC3339, чтобы задать конкретное время начала. Не задавайте оба параметра одновременно. После изменения конфигурации перезапустите коллектор; учтите, что повторное чтение одного и того же временного окна может привести к появлению дубликатов.
