Temporal предоставляет абстракцию для создания простых, но функциональных и отказоустойчивых приложений.

<Info>
  **Кратко**

  Мониторинг метрик Temporal Cloud в ClickHouse Observability с помощью приёмника Prometheus из OTel. Включает преднастроенный дашборд.
</Info>

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Действующий аккаунт Temporal Cloud
* Docker на хосте с доступом по HTTPS к Temporal Cloud и вашей конечной точке OTLP

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы увидеть скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе управляемой телеметрии](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров с экспортером OTLP задайте следующие переменные в терминале, в котором будете запускать коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точной конечной точкой (включая порт) и ключом API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/metrics`: экспортер сам добавляет путь сигнала в конец.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP по HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже включают сопоставление хоста.

## Интеграция с существующим Temporal Cloud {#existing-temporal}

<Steps>
  <Step title="Создайте ключ Temporal Cloud" id="create-temporal-cloud-key">
    Создайте служебную учётную запись Temporal Cloud с ролью **Metrics Read-Only** и сгенерируйте ключ API, следуя [руководству по аутентификации](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication). Создать служебную учётную запись и ключ может только пользователь с ролью Account Owner или Global Admin.

    <Warning>
      **Файл ключа**

      Сохраните ключ API Temporal в файл `temporal.key` в том же каталоге, где будет находиться файл конфигурации, создаваемый ниже. Файл должен содержать только сам ключ — без префикса `Bearer` и без пробелов в начале и конце. Этот ключ не совпадает с ключом API ClickHouse Observability. Убедитесь, что у коллектора есть доступ на чтение смонтированного файла.
    </Warning>
  </Step>

  <Step title="Настройте коллектор OTel" id="custom-otel">
    Запустите отдельный OpenTelemetry Collector с приёмником Prometheus, чтобы собирать метрики Temporal Cloud и пересылать их в ваш сервис.

    Создайте файл `temporal-metrics.yaml` со следующей конфигурацией:

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    Эта конфигурация:

    * подключается к Temporal Cloud по адресу `metrics.temporal.io`;
    * собирает метрики каждые 60 секунд;
    * собирает [ключевые метрики производительности](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference);
    * **задаёт обязательный атрибут ресурса `service.name`** в соответствии с [семантическими соглашениями OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/resource/#service);
    * отправляет метрики на вашу конечную точку OTLP через отдельный конвейер.

    Если у вас несколько аккаунтов Temporal Cloud, задайте для них разные значения `service.name`, чтобы их можно было различать (например, `temporal-prod` и `temporal-dev`).
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    В каталоге с файлами `temporal-metrics.yaml` и `temporal.key` задайте [переменные подключения](#connection-details) и выполните:

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте терминал и следите за ошибками сбора метрик или экспорта. Метрики Temporal Cloud могут появиться лишь через несколько минут. Завершив тестирование, остановите коллектор нажатием **Ctrl+C**.
  </Step>

  <Step title="Проверьте метрики в ClickHouse Observability" id="verifying-metrics">
    После настройки войдите в ClickHouse Observability и убедитесь, что метрики поступают:

    1. Откройте **Обозреватель диаграмм** и выберите источник **Metrics**.
    2. Задайте фильтр `ServiceName:temporal`, выберите **Last 15 minutes** и найдите метрики, имена которых начинаются с `temporal` (например, `temporal_cloud_v1_workflow_success_count`, `temporal_cloud_v1_poll_timeout_count`).
    3. Точки данных метрик должны появляться с заданным интервалом сбора.

    <div className="ch-image-md">
      <Frame>
        ![Метрики Temporal](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Коллектор не запускается {#collector-fails-to-start}

Проверьте вывод в терминале на наличие ошибок конфигурации. Убедитесь, что оба смонтированных файла существуют и коллектор может прочитать `temporal.key`. Также проверьте, что переменные подключения OTLP заданы в том терминале, где запускается Docker.

### Метрики не отображаются {#no-metrics}

Проверьте журналы коллектора:

```bash
docker logs temporal-metrics-collector
```

Проверьте, нет ли ошибок сбора метрик, аутентификации или экспорта. Убедитесь, что у хоста есть доступ к `https://metrics.temporal.io/v1/metrics` и к вашей конечной точке OTLP. В **Обозревателе диаграмм** проверьте источник **Metrics**, фильтр `ServiceName:temporal` и временной диапазон. Метрики Temporal могут появиться лишь через несколько минут, а их наличие зависит от активности в вашем аккаунте.

### Ошибки аутентификации {#auth-errors}

При ошибках сбора метрик Temporal убедитесь, что `temporal.key` содержит действительный ключ API служебной учётной записи с ролью **Metrics Read-Only**. При ошибках экспорта OTLP проверьте конечную точку ClickHouse Observability и значение заголовка авторизации. Это разные учётные данные.

## Дальнейшие шаги {#next-steps}

* Настройте [оповещения](/ru/clickstack/observability/features/alerts) для критически важных метрик (доля сбоев рабочих процессов, рост очереди невыполненных задач, задержка schedule-to-start)
* Создайте дополнительные панели мониторинга для конкретных сценариев использования (мониторинг на уровне пространств имён, производительность в разрезе типов рабочих процессов)
* Для мониторинга нескольких аккаунтов Temporal Cloud продублируйте конфигурацию приёмника, указав другие конечные точки и имена сервисов

## Переход к промышленной эксплуатации {#going-to-production}

В этом руководстве запускается отдельный OpenTelemetry Collector, который пересылает метрики на конечную точку OTLP вашего сервиса. Рекомендации по развертыванию см. в разделе [Отправка данных OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry).
