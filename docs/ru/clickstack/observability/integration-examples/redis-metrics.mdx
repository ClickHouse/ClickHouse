Собирайте метрики Redis с помощью приёмника Redis для OpenTelemetry и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без установки Redis, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Docker для запуска примеров коллектора или уже развернутый OpenTelemetry Collector Contrib
* Для сбора собственных метрик — инстанс Redis, доступный из коллектора, а также учётные данные, если в Redis включена аутентификация
* Для демонстрации — `curl`, чтобы скачать и отправить пример данных

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Чтобы скопировать конфигурацию, нажмите **Copy connection details**, а чтобы просмотреть скрытый ключ — **Reveal key**.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Для приведённых ниже примеров экспортера OTLP задайте следующие переменные в терминале, в котором будет запускаться коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точной конечной точкой (включая порт) и ключом API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/metrics`: экспортер сам добавляет в конец путь, соответствующий типу сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP по HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из контейнера коллектора. Если коллектор, принимающий данные, запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже включают сопоставление хоста.

## Интеграция с существующим Redis {#existing-redis}

<Steps>
  <Step title="Проверьте соединение с Redis" id="verify-redis">
    С хоста, на котором доступен Redis CLI, проверьте ваш инстанс Redis:

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    Первая команда должна вернуть `PONG`, вторая — информацию о сервере. Если Redis требует пароль, перед выполнением этих команд задайте в терминале переменную `REDISCLI_AUTH`. Для пользователей Redis ACL также укажите `--user YOUR_REDIS_USER`.
  </Step>

  <Step title="Настройте коллектор" id="configure-collector">
    Сохраните следующую конфигурацию в файл `redis-metrics.yaml`:

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # Раскомментируйте, если Redis требует аутентификации:
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    Приёмник каждые 10 секунд собирает метрики Redis, в том числе использование памяти, данные о клиентах, количество обработанных команд, попадания и промахи keyspace, а также истёкшие и вытесненные ключи. Процессор resource присваивает `service.name` значение `redis-service`, чтобы данные можно было фильтровать.

    Если Redis требует аутентификации, раскомментируйте соответствующие поля приёмника и задайте `REDIS_USERNAME` и/или `REDIS_PASSWORD`. Эти учётные данные используются для подключения к Redis, а значение авторизации OTLP — для аутентификации в коллекторе назначения. Для Redis с включённым TLS настройте параметры `tls` приёмника, как описано в [документации по приёмнику Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
  </Step>

  <Step title="Запустите коллектор" id="run-collector">
    Задайте [переменные подключения](#connection-details) и адрес Redis, доступный из контейнера коллектора. Если Redis запущен на этом компьютере:

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    Для удалённого Redis укажите его имя хоста и порт. Если Redis работает в другом контейнере, укажите имя этого контейнера и добавьте `--network YOUR_NETWORK` в приведённую ниже команду.

    В каталоге с файлом `redis-metrics.yaml` выполните:

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Не закрывайте этот терминал, пока идёт сбор метрик. Прежде чем проверять интерфейс, подождите не менее двух интервалов сбора.
  </Step>

  <Step title="Проверьте метрики" id="verify-metrics">
    Импортируйте [панель мониторинга](#dashboards), сопоставьте её диаграммы с вашим источником **Metrics** и примените фильтр `ServiceName:redis-service`. Выберите **Last 15 minutes** и запустите панель мониторинга. На исправном инстансе Redis число вытеснений и отклонённых соединений вполне может оставаться нулевым.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Опробуйте интеграцию на 6,912 точках данных типа gauge и sum, собранных с интервалом в пять минут за 24 часа. Выборка сохраняет характерные для исходного набора данных закономерности: прогрев кэша, всплески трафика и давление на память. Вам понадобятся Docker, `curl` и сведения о подключении к коллектору в пункте назначения по OTLP HTTP.

Перед началом задайте [переменные подключения](#connection-details).

<Steps>
  <Step title="Скачайте демонстрационные метрики" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующую конфигурацию в файл `redis-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      Это преобразование нужно только для демонстрации: оно обновляет временные метки, сохраняя значения метрик и интервал между начальной и конечной временными метками каждой точки. Для реальных метрик Redis его не используйте. Ограничение размера пакета делает отправляемые порции достаточно небольшими для коллектора в пункте назначения.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    В каталоге с файлом конфигурации запустите коллектор и не закрывайте этот терминал:

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Отправьте выборку" id="load-metrics">
    В другом терминале выполните эту команду из каталога, куда был скачан файл:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    Ответ вида `{}` или `{"partialSuccess":{}}` означает, что локальный коллектор принял запрос. Проверьте, нет ли в терминале коллектора ошибок экспорта, и подождите несколько секунд, пока данные будут переданы. Убедившись, что данные поступили, остановите коллектор клавишами **Ctrl+C**. Повторная отправка выборки может привести к появлению дублирующихся точек.
  </Step>

  <Step title="Проверьте метрики" id="verify-demo-metrics">
    Импортируйте панель мониторинга из [следующего раздела](#dashboards), задайте фильтр `ServiceName:redis-demo` и выберите **последние 2 дня**. Выборка содержит метрики как типа gauge, так и типа sum; прямой доступ к базе данных не требуется.
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Коллектор не запускается {#collector-fails-to-start}

Проверьте вывод коллектора в терминале на наличие ошибок конфигурации. Убедитесь, что YAML-файл смонтирован по пути, указанному в документации, а в терминале, где вы запускаете Docker, заданы конечная точка и необходимые переменные для аутентификации.

### Метрики не отображаются {#no-metrics}

* Проверьте вывод коллектора на наличие ошибок соединения с Redis или ошибок экспорта OTLP.
* Убедитесь, что Redis доступен из контейнера коллектора. Если используются контейнеры, проверьте, что они подключены к нужной общей сети Docker.
* Проверьте учётные данные Redis и убедитесь, что пользователь может выполнять команды, необходимые [приёмнику Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
* Проверьте источник **Metrics**, фильтр по имени сервиса и временной диапазон. Для демонстрационных данных выберите **последние 2 дня** и убедитесь, что преобразование временных меток включено в конвейер.
* Для управляемых сервисов сверьте конечную точку OTLP по HTTP и ключ API (Bearer) с данными в разделе **Managed Telemetry**. Для самоуправляемых коллекторов используйте их настройки аутентификации.
