Собирайте трассировку из приложения Node.js с помощью автоматического инструментирования OpenTelemetry и отправляйте её в ClickHouse Observability. Чтобы опробовать интеграцию без инструментирования приложения, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Для приложения — Node.js 22 или новее и npm
* Для демонстрации — Docker и `curl`

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → Managed Telemetry**. Скопируйте конечную точку OTLP по HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы увидеть скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении в разделе Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Задайте эти переменные подключения в терминале, в котором будете запускать приложение или демонстрационный коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точными значениями конечной точки (вместе с портом) и ключа API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/traces`: экспортер сам добавляет в конец путь, соответствующий типу сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP по HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, удалите блок `headers` экспортера из приведённых ниже конфигураций. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## Интеграция с существующим приложением Node.js {#existing-nodejs}

<Steps>
  <Step title="Установите OpenTelemetry" id="install-instrumentation">
    В каталоге вашего приложения установите пакеты инструментирования:

    ```bash
    npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node@0.81.0
    ```

    В этих шагах используется [автоматическое инструментирование OpenTelemetry](https://opentelemetry.io/docs/zero-code/js/) для приложений CommonJS. Для нативных ES-модулей требуется [настройка ESM](https://github.com/open-telemetry/opentelemetry-js/blob/main/doc/esm-support.md). Чтобы избежать дублирования спанов, используйте в каждом приложении только один вариант настройки инструментирования.
  </Step>

  <Step title="Настройте трассировку и запустите приложение" id="run-application">
    В терминале, где вы задали переменные подключения, выполните:

    ```bash
    export OTEL_SERVICE_NAME='nodejs-service'
    export OTEL_TRACES_EXPORTER='otlp'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="Authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='none'
    export OTEL_LOGS_EXPORTER='none'

    node --require @opentelemetry/auto-instrumentations-node/register app.js
    ```

    Замените `app.js` на точку входа вашего приложения. Предварительная загрузка инициализирует инструментирование до того, как приложение импортирует свои библиотеки. Для самоуправляемой конечной точки без аутентификации пропустите экспорт заголовков и выполните `unset OTEL_EXPORTER_OTLP_HEADERS`.

    Конечная точка должна быть доступна из приложения. Если приложение работает в контейнере, `localhost` указывает на этот контейнер.
  </Step>

  <Step title="Сгенерируйте трафик" id="generate-traffic">
    Отправьте запросы к конечной точке, которую обслуживает ваше приложение. Например, для приложения, прослушивающего порт `3000`:

    ```bash
    curl http://localhost:3000/
    ```

    Подождите несколько секунд, пока экспортер отправит спаны.
  </Step>

  <Step title="Проверьте трассировку" id="verify-traces">
    Откройте **Поиск**, выберите **Traces**, задайте фильтр `ServiceName:nodejs-service` и выберите **Last 15 minutes**. Откройте трассу, чтобы просмотреть её спаны, длительность и атрибуты.
  </Step>
</Steps>

## Демо-набор данных {#demo-dataset}

Выборка содержит 822 спана из `nodejs-demo-api`. Запущенное приложение Node.js не требуется.

<Steps>
  <Step title="Скачайте пример набора данных" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nodejs/nodejs-traces-sample.json
    ```
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующее содержимое в файл `nodejs-traces-demo.yaml` в каталоге загрузки:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T17:59:15Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nodejs-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Процессор `transform/demo_timestamps`, предназначенный только для демонстрации, сдвигает выборку примерно на последние 24 часа так, чтобы она заканчивалась за две минуты до момента приёма, сохраняя при этом длительность спанов и характер трафика. Для собственных трассировок Node.js этот процессор не используйте, чтобы сохранить их исходные временные метки. Повторная отправка выборки может привести к появлению дублирующихся спанов.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    <Note>
      Если целевой коллектор работает на этом же компьютере, задайте для `OTEL_EXPORTER_OTLP_ENDPOINT` значение `http://host.docker.internal:4318`. Приведённая ниже команда уже включает сопоставление хоста Docker.
    </Note>

    Запустите OpenTelemetry Collector Contrib `0.161.0` из каталога с конфигурацией в том же терминале, где вы задали переменные подключения. Не закрывайте этот терминал:

    ```bash
    docker run --rm --name nodejs-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nodejs-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Локальный приёмник использует порт `14318`, чтобы не конфликтовать с уже работающим коллектором на порту `4318`. Коллектор пересылает трассировки на настроенную конечную точку, используя указанные выше параметры аутентификации.
  </Step>

  <Step title="Отправьте трассы" id="send-traces">
    В другом терминале из каталога загрузки отправьте исходную выборку в локальный коллектор:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nodejs-traces-sample.json
    ```

    Пустой успешный ответ, например `{}` или `{"partialSuccess":{}}`, означает, что локальный коллектор принял запрос. Проверьте вывод коллектора на наличие ошибок экспорта и подождите несколько секунд, пока пакет дойдёт до вашего сервиса. По завершении остановите демонстрационный коллектор сочетанием клавиш **Ctrl+C**.
  </Step>

  <Step title="Проверьте демонстрационные трассы" id="verify-demo-traces">
    Откройте **Поиск**, выберите **Трассировка**, задайте фильтр `ServiceName:nodejs-demo-api` и выберите **последние 2 дня**, чтобы охватить весь сдвинутый набор данных. Откройте трассировку, чтобы изучить HTTP-атрибуты.

    <div className="ch-image-lg">
      <Frame>
        ![Демонстрационные трассировки Node.js в ClickHouse Observability Поиск](/images/clickstack/observability-nodejs-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Трассировка приложения не отображается {#no-application-traces}

Проверьте вывод приложения на наличие ошибок экспорта. Убедитесь, что настройки конечной точки, протокола и аутентификации указаны верно. Загружайте инструментирование до библиотек приложения, сгенерируйте запросы, а затем проверьте фильтр по имени сервиса и временной диапазон. Для нативных ES-модулей выполните настройку ESM по приведённой ссылке.

### Демонстрационные трассировки не отображаются {#no-demo-traces}

Проверьте вывод демонстрационного коллектора на наличие ошибок аутентификации или экспорта. Успешный ответ `curl` подтверждает лишь, что данные приняты локально; подождите несколько секунд, пока они будут переданы в ваш сервис. Убедитесь, что `transform/demo_timestamps` добавлен в конвейер, и выберите **Последние 2 дня**. Повторная отправка демонстрационных данных может привести к появлению дубликатов.
