Собирайте метрики JVM с помощью Java-агента OpenTelemetry и отправляйте их в ClickHouse Observability. Чтобы опробовать интеграцию без инструментирования приложения, воспользуйтесь [демо-набором данных](#demo-dataset).

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability
* Для сбора собственных метрик — Java-приложение (Java 8+) и доступ к его команде запуска или переменным окружения
* Для демонстрации — Docker и `curl`

### Сведения о подключении {#connection-details}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Сервис в стадии бета-тестирования" />

    Откройте ClickHouse Observability и перейдите в **Team Settings → Data → управляемая телеметрия**. Скопируйте конечную точку OTLP по HTTP и ключ API. Нажмите **Copy connection details**, чтобы скопировать конфигурацию, или **Reveal key**, чтобы увидеть скрытый ключ.

    <div className="ch-image-lg">
      <Frame>
        ![Сведения о подключении управляемой телеметрии](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Задайте эти переменные в терминале, в котором будете запускать приложение или демонстрационный коллектор:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Замените плейсхолдеры точной конечной точкой (включая порт) и ключом API вашего сервиса. Указывайте базовую конечную точку HTTP без суффикса `/v1/metrics`: экспортер сам добавляет в конец путь сигнала.
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите доступную конечную точку OTLP по HTTP вашего коллектора (например, `http://YOUR_COLLECTOR_HOST:4318`) и настройки аутентификации. Если коллектор не требует аутентификации, не задавайте `OTEL_EXPORTER_OTLP_HEADERS` для Java-агента и блок `headers` экспортера для демонстрационного коллектора. Инструкции по настройке см. в [руководстве по началу работы с самоуправляемой версией](/ru/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Конечная точка должна быть доступна из вашего приложения, а для демонстрации в Docker — ещё и из контейнера коллектора. Если коллектор-получатель запущен на этом же компьютере, используйте `http://host.docker.internal:4318`. Приведённые ниже команды Docker уже содержат сопоставление хоста.

## Интеграция с существующим JVM-приложением {#existing-jvm}

<Steps>
  <Step title="Скачайте Java-агент" id="download-agent">
    Скачайте Java-агент OpenTelemetry версии `2.22.0`:

    ```bash
    curl -fLO https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/download/v2.22.0/opentelemetry-javaagent.jar
    ```
  </Step>

  <Step title="Настройте и запустите приложение" id="configure-jvm">
    Задайте [переменные подключения](#connection-details), затем настройте агент:

    ```bash
    export OTEL_SERVICE_NAME='jvm-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='otlp'
    export OTEL_LOGS_EXPORTER='none'
    export OTEL_TRACES_EXPORTER='none'

    java -javaagent:./opentelemetry-javaagent.jar -jar my-application.jar
    ```

    Замените `my-application.jar` на JAR-файл вашего приложения и при необходимости укажите другой путь к агенту. Выберите имя сервиса, по которому можно однозначно определить ваше приложение. С этими настройками собираются только метрики. Если ваше приложение уже экспортирует трассировку или журналы, оставьте для этих сигналов существующие настройки экспортера.

    Если приложение запускается как сервис или в контейнере, добавьте агент в существующие аргументы запуска JVM и передайте переменные окружения через конфигурацию развертывания. Подробнее см. в [документации по настройке Java-агента](https://opentelemetry.io/docs/zero-code/java/agent/configuration/).
  </Step>

  <Step title="Проверьте метрики" id="verify-metrics">
    Подождите не менее двух минут, пока агент экспортирует метрики. Откройте **Обозреватель диаграмм**, выберите источник **Metrics** и найдите `jvm.memory.used` или `jvm.thread.count`. Задайте фильтр `ServiceName:jvm-service` и выберите **Last 15 minutes**.
  </Step>
</Steps>

## Демонстрационный датасет {#demo-dataset}

Выборка содержит 6,048 точек типа Gauge, снятых с интервалом в пять минут, а также все 412 событий сборки мусора из исходного набора данных. Она охватывает примерно 24 часа активности памяти, потоков, классов, CPU и GC. Ни Java-приложение, ни прямой доступ к базе данных не требуются.

Перед началом задайте [переменные подключения](#connection-details).

<Steps>
  <Step title="Скачайте пример метрик" id="download-sample">
    [Скачайте демонстрационный архив](/ru/assets/jvm-metrics-demo.zip) и распакуйте его в рабочий каталог. Он содержит `jvm-metrics-demo.json` и `jvm-metrics-dashboard.json`.
  </Step>

  <Step title="Настройте демонстрационный коллектор" id="configure-demo-collector">
    Сохраните следующую конфигурацию в файл `jvm-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: jvm-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-12-08T14:16:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      Это преобразование нужно только для демонстрации: оно обновляет временные метки, сохраняя значения метрик и интервал между начальной и конечной временными метками каждой точки. Для реальных метрик JVM его не используйте. Ограничение размера пакета не даёт отправляемым данным превысить допустимый для коллектора в пункте назначения объём.
    </Note>
  </Step>

  <Step title="Запустите демонстрационный коллектор" id="run-demo-collector">
    Запустите коллектор из каталога с конфигурацией и не закрывайте этот терминал:

    ```bash
    docker run --rm --name jvm-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/jvm-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Отправьте выборку" id="load-metrics">
    В другом терминале выполните следующую команду из каталога, куда был скачан архив:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @jvm-metrics-demo.json
    ```

    Ответ вида `{}` или `{"partialSuccess":{}}` означает, что локальный коллектор принял запрос. Проверьте терминал коллектора на наличие ошибок экспорта и подождите несколько секунд, пока данные будут переданы. Убедившись, что данные получены, остановите коллектор с помощью **Ctrl+C**. Повторная отправка выборки может привести к появлению дублирующихся точек.
  </Step>

  <Step title="Проверьте метрики" id="verify-demo-metrics">
    Импортируйте панель мониторинга из [следующего раздела](#dashboards), задайте фильтр `ServiceName:jvm-demo` и выберите **Последние 2 дня**. Выборка включает метрики как типа Gauge, так и типа Сумма; прямой доступ к базе данных не требуется.
  </Step>
</Steps>

    На панели мониторинга отображаются память кучи, паузы GC, потоки, metaspace, CPU и загруженные классы из демонстрационных данных.

    <div className="ch-image-lg">
      <Frame>
        ![Демонстрационная панель мониторинга метрик JVM в ClickHouse Observability со всеми шестью чартами](/images/clickstack/observability-jvm-metrics-dashboard.png)

    </div>

    <Note>
      В демонстрационных данных используется устаревшая схема метрик JVM. Для Java-агента `2.22.0` выберите тип метрики сумма для метрик памяти, потоков, классов и процессорного времени, а для длительности GC — histogram. Метрики памяти и счётчики являются немонотонными суммами: используйте их текущие значения, а не скорость изменения. Обновите фильтры и группировку чартов, чтобы в них использовались `jvm.memory.type`, `jvm.memory.pool.name`, `jvm.thread.state` и `jvm.gc.name`. Актуальную схему см. в [соглашениях о метриках JVM](https://opentelemetry.io/docs/specs/semconv/runtime/jvm-metrics/).
    </Note>
  </Step>
</Steps>

## Устранение неполадок {#troubleshooting}

### Агент не запускается {#agent-not-starting}

Убедитесь, что JAR-файл агента находится по пути, указанному в `-javaagent`, что у приложения есть права на его чтение и что используется Java версии 8 или выше. Проверьте вывод приложения при запуске на наличие ошибок агента.

### Метрики не отображаются {#no-metrics}

* Проверьте вывод приложения или демонстрационного коллектора на наличие ошибок аутентификации и экспорта.
* Убедитесь, что конечная точка доступна из приложения или контейнера и что используется протокол `http/protobuf`.
* Проверьте источник **Metrics**, фильтр по имени сервиса и временной диапазон. Для демонстрационного примера выберите **Последние 2 дня**.
* Если вы используете существующий коллектор, убедитесь, что его конвейер метрик включает приёмник OTLP и экспортер метрик.
* Если демонстрационный коллектор принимает запросы, но данные не поступают, проверьте вывод в его терминале на наличие ошибок пересылки.
