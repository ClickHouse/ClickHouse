На этой странице описаны полностью управляемый и самоуправляемый режимы ClickHouse Observability, а также даны ответы на часто задаваемые вопросы о сборе данных, оповещениях, панелях мониторинга и обнаружении метрик.

## Развертывание и сбор данных {#data-collection}

<Accordion title="В чём разница между полностью управляемым и самоуправляемым ClickHouse Observability?">
  **Полностью управляемый**

  <BetaBadge label="Сервис в стадии бета-тестирования" />

  С [полностью управляемого ClickHouse Observability](/ru/clickstack/observability/overview) рекомендуется начинать. Отправляйте телеметрию на управляемую конечную точку OpenTelemetry, а ClickHouse возьмёт на себя коллектор для приёма данных, схемы, инфраструктуру и масштабирование.

  **Самоуправляемый**

  [Самостоятельно управляемый ClickHouse Observability](/ru/clickstack/self-configured/overview) даёт вам контроль над приёмом данных, схемами, сроками хранения и конфигурацией базы данных. ClickHouse Cloud размещает ClickHouse и интерфейс ClickStack, а вы обслуживаете коллектор для приёма данных и отвечаете за тонкую настройку и ёмкость базы данных. Самоуправляемый вариант не находится в стадии бета-тестирования.
</Accordion>

<Accordion title="Нужно ли запускать коллектор OpenTelemetry?">
  **Полностью управляемый:** развертывать коллектор для приёма данных не требуется. Приложения и генераторы телеметрии могут отправлять данные напрямую на управляемую конечную точку OpenTelemetry.

  Тем не менее коллектор в вашем собственном окружении может понадобиться, чтобы читать файлы журналов или собирать метрики хоста и Kubernetes, а затем пересылать эти данные в управляемый коллектор. Примеры см. в разделах [Локальные журналы и метрики](/ru/clickstack/observability/example-datasets/local-data) и [Мониторинг Kubernetes](/ru/clickstack/observability/example-datasets/kubernetes).

  **Самоуправляемый:** необходим работающий коллектор для приёма данных, подключённый к вашему сервису ClickHouse Cloud. Приложения и агенты отправляют телеметрию в этот коллектор, а он записывает её в ClickHouse. Мы рекомендуем использовать дистрибутив ClickStack. Инструкции по подключению см. в разделе [Загрузка данных с помощью OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured), а о запуске коллектора — в [руководстве по развертыванию](/ru/clickstack/self-configured/deployment/managed#start-a-collector-existing).
</Accordion>

<Accordion title="Где найти конечную точку телеметрии и ключ API?">
  **Полностью управляемый:** в сервисе ClickHouse Observability откройте **Team Settings → Data → Managed Telemetry** и скопируйте конечную точку OTLP и ключ API для приёма данных. Укажите их при настройке SDK, коллектора-пересыльщика или генератора телеметрии.

  **Самоуправляемый:** используйте конечную точку OTLP коллектора, который вы обслуживаете, и токен аутентификации, если он настроен на приёмнике (receiver) коллектора. Если в коллекторе ClickStack включён `OTLP_AUTH_TOKEN`, передавайте этот токен в заголовке `authorization`. Эти данные отличаются от конечной точки базы данных ClickHouse Cloud и учётных данных, с помощью которых коллектор записывает данные. Примеры см. в разделе [Загрузка данных с помощью OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry#sending-data-to-collector-managed-self-configured).

  Указывайте конечную точку в формате, который требует ваш инструмент. В разделе [примеров данных и демо](/ru/clickstack/observability/example-datasets) приведены примеры конфигурации для каждого инструмента.
</Accordion>

## Оповещения {#alerting}

<Accordion title="Какие типы оповещений поддерживает ClickHouse Observability?">
  ClickHouse Observability поддерживает два типа оповещений:

  * [Оповещения по поиску](/ru/clickstack/observability/features/alerts#search-alerts): отправляют уведомления, когда количество совпадающих записей журналов или трасс во временном окне превышает пороговое значение или опускается ниже него.
  * [Оповещения по графикам на дашборде](/ru/clickstack/observability/features/alerts#dashboard-alerts): отправляют уведомления, когда метрика, отображаемая на плитке дашборда, пересекает заданный порог.

  Оба типа оповещений сравнивают результаты с настроенными пороговыми значениями. Подробнее см. в разделе [Оповещения](/ru/clickstack/observability/features/alerts).
</Accordion>

<Accordion title="Можно ли настроить оповещения по сложным условиям для метрик, например по долям, p95/p99 или формулам с несколькими метриками?">
  Постройте нужное вычисление в виде чарта на панели мониторинга, а затем привяжите к этому чарту пороговое оповещение. [Конструктор графиков](/ru/clickstack/observability/features/dashboards/overview#navigate-chart-explorer) поддерживает такие вычисления, как доли и процентили.

  Для вычислений, требующих SQL, используйте [оповещение по чарту на основе SQL](/ru/clickstack/observability/features/alerts#sql-based-alerts). SQL-оповещения поддерживают чарты типов «Линия», «Столбчатая диаграмма с накоплением» и «Число». Чтобы активировать оповещение, сохраните панель мониторинга.
</Accordion>

## Панели мониторинга и переходы к детальным данным {#dashboards-and-drill-downs}

<Accordion title="Есть ли готовые панели мониторинга?">
  Да. В разделе **Панели мониторинга** доступны предустановленные панели мониторинга **Services**, **Kubernetes** и **LLM**. Они отображают данные, если соответствующая телеметрия поступает в систему, а выбранный временной диапазон охватывает эти данные.

  Вы также можете создавать пользовательские панели мониторинга на основе загруженных журналов, трассировок и метрик. О том, как строить чарты и объединять их в панели мониторинга, см. в разделе [Панели мониторинга](/ru/clickstack/observability/features/dashboards/overview).
</Accordion>

<Accordion title="Поддерживает ли ClickHouse Observability параметризованные панели мониторинга или переменные панели мониторинга?">
  Да, ClickHouse Observability поддерживает панели мониторинга, параметризованные пользовательскими фильтрами и переменными, значения которых берутся из данных, запрашиваемых в ClickHouse. С помощью этих фильтров можно динамически ограничить часть или все плитки панели мониторинга определённым значением (например, именем сервиса, окружением или хостом).

  Подробнее о создании панелей мониторинга и применении фильтров см. в разделе [Панели мониторинга](/ru/clickstack/observability/features/dashboards/overview).
</Accordion>

<Accordion title="Какие возможности переходов к детальным данным доступны?">
  ClickHouse Observability поддерживает следующие сценарии переходов к детальным данным:

  * [Фильтрация на уровне панели мониторинга](/ru/clickstack/observability/features/dashboards/overview#filter-dashboards): фильтры Lucene или SQL на уровне панели мониторинга применяются к плиткам, для которых включён параметр **Apply filters**. Также можно изменить временной диапазон панели мониторинга.
  * Пользовательские фильтры панели мониторинга: в пользовательских панелях мониторинга доступны отдельные элементы управления фильтрами, которые заполняются значениями из ваших данных. Это позволяет ограничивать данные в связанных плитках без ручного написания запросов.
  * Просмотр событий по клику: если щёлкнуть по данным в плитке панели мониторинга и выбрать **View Events**, откроется страница [Поиск](/ru/clickstack/observability/features/search) с соответствующими фильтрами для данных журналов и трассировок.
  * [Переход к детальным данным по клику на строку таблицы](/ru/clickstack/observability/features/dashboards/row-click-drilldowns): табличную плитку можно настроить так, чтобы по щелчку на строке открывалась страница Поиск или другая панель мониторинга, а значения строки передавались в качестве фильтров. Так можно строить многоуровневые сценарии — например, переходить из инвентаря сервисов к панели мониторинга с подробными данными по конкретному сервису.

  <Note>
    Для просмотра отдельных журналов и трассировок используйте [Поиск](/ru/clickstack/observability/features/search). Для изучения метрик используйте Chart Explorer.
  </Note>
</Accordion>

## Обнаружение метрик {#metrics-discovery}

<Accordion title="Есть ли интерфейс для просмотра и поиска метрик?">
  ![Metric Attribute Explorer](/images/clickstack/faq/metrics-explorer-fully-managed.png)

  Имена метрик можно найти в раскрывающемся списке имён метрик в [конструкторе графиков](/ru/clickstack/observability/features/dashboards/overview#navigate-chart-explorer). При выборе метрики на панели Metric Attribute Explorer отображаются её описание, единицы измерения и доступные атрибуты с их значениями. Прямо на этой панели можно просматривать атрибуты и добавлять их в качестве фильтров или полей group-by.

  Отдельной страницы поиска метрик, аналогичной поиску по журналам, пока нет.
</Accordion>
