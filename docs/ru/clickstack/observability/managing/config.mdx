Откройте **Team Settings** в ClickHouse Observability, чтобы управлять доступом к данным, соединениями с API и агентами, интеграциями и настройками запросов. Разделы ниже соответствуют вкладкам в приложении. Ингестией, схемами, инфраструктурой и масштабированием управляет ClickHouse.

## Данные {#data}

Откройте **Team Settings → Data**, чтобы просмотреть ваши источники и сведения о подключении для отправки телеметрии.

### Источники {#datasource-settings}

В разделе **Источники** перечислены источники, предоставляемые вашим управляемым сервисом:

| Источник        | Данные                                  |
| --------------- | --------------------------------------- |
| **Журналы**     | События журналов                        |
| **Трассировки** | Спаны распределённой трассировки        |
| **Метрики**     | Данные метрик                           |
| **Сеансы**      | Данные воспроизведения сеансов браузера |

Для каждого источника отображаются связанное с ним соединение для чтения и, если применимо, имя таблицы. Чтобы включить или отключить источник, используйте переключатель справа от него. Отключённый источник сохраняет свою конфигурацию, но скрывается из селекторов источников и не выбирается автоматически. При этом ингестия телеметрии не останавливается, а сохранённые данные не удаляются. Чтобы источник снова стал доступен в селекторах, включите его.

### Управляемая телеметрия {#managed-telemetry}

Под разделом **Источники** расположен раздел **Управляемая телеметрия**, в котором отображается состояние хранилища и OpenTelemetry Collector, а также сведения о подключении для отправки данных в ваш сервис.

* Выберите **URL**, **Collector config** или **Env vars**, чтобы просмотреть сведения о подключении в нужном формате.
* Нажмите **Copy connection details**, чтобы скопировать конфигурацию. Чтобы просмотреть скрытые учётные данные, нажмите **Reveal key**.
* Нажмите **Send a Test Log**, чтобы отправить в сервис тестовую запись журнала.

Инструкции по настройке приложений и коллекторов см. в разделе [Ингестия данных](/ru/clickstack/observability/ingesting-data/overview).

### IP Access List {#ip-access-list}

В разделе **Управляемая телеметрия** нажмите **IP access list → Изменить**, чтобы указать, с каких IP-адресов или диапазонов CIDR разрешён доступ к конечным точкам вашего коллектора.

### Частные конечные точки {#private-endpoints}

Чтобы настроить частное сетевое подключение к коллектору, используйте **Set up private endpoint**. Для развертываний в AWS используется AWS PrivateLink. Ссылка **частные конечные точки** открывает список частных конечных точек организации в консоли Cloud.

### Опасная зона {#service-settings}

**Delete warehouse** удаляет хранилище Observability и все его сервисы. Сначала удаляются сервисы только для чтения, затем — основной сервис. Используйте эту функцию, только если хранилище и его данные вам больше не нужны.

## Участники и роли {#members-and-roles}

Откройте **Team Settings → Участники и роли**, чтобы просмотреть роли RBAC и роль, назначаемую новым пользователям по умолчанию. Для управления составом команды в ClickHouse Cloud нажмите **Управлять в консоли**. Подробнее см. в разделе [Ролевое управление доступом](/ru/clickstack/observability/managing/rbac).

## API и агенты {#api-and-agents}

Откройте **Team Settings → API &amp; Agents**, чтобы управлять ключами для приёма данных, просматривать идентификаторы сервисов, подключать агентов и настраивать функции ИИ.

### Ключи API для приёма данных {#ingestion-api-keys}

В разделе **Ключи API** отображаются ваши **Team ID**, **Service ID** и ключи для приёма данных. Ключи для приёма данных служат для аутентификации телеметрии, отправляемой в коллектор OpenTelemetry.

Введите имя и нажмите **Create key**, чтобы выпустить ключ для источника или окружения. Для существующих ключей доступны элементы управления **Reveal key**, **Copy key**, **Freeze** и **Revoke**. Изменения вступают в силу примерно в течение минуты.

Отдельная ссылка **Manage API Keys** открывает настройки организации в ClickHouse Cloud, где управляются ключами для API управления.

### Подключение агента {#connect-an-agent}

В разделе **Connect your AI agents** с помощью переключателя **Enable MCP for this service** можно включить или отключить удалённый сервер MCP. Выберите свой клиент и скопируйте сгенерированную для него конфигурацию: она содержит идентификатор сервиса, благодаря чему запросы агента направляются именно к вашему сервису. Кнопка **Manage sessions** открывает консоль Cloud, где можно просмотреть сеансы MCP. Облачная конечная точка MCP использует OAuth: когда клиент предложит выполнить вход, войдите в свой аккаунт ClickHouse Cloud. Инструкции по настройке и список поддерживаемых клиентов см. в разделе [Подключение MCP-клиента](/ru/clickstack/observability/mcp#managed-connecting-a-client).

### Использование API {#use-the-api}

Используйте [ClickHouse Observability API](/ru/clickstack/observability/api-reference) для программного управления панелями мониторинга, оповещениями и другими ресурсами. Запросы к API аутентифицируются по ID и секрету ключа API ClickHouse Cloud с использованием базовой аутентификации HTTP. Необходимые разрешения и порядок настройки ключа описаны в разделе [Аутентификация API](/ru/clickstack/observability/api-reference#authentication).

Учётные данные API — это не то же самое, что ключ API для приёма данных из раздела **Data → Управляемая телеметрия**. MCP-клиенты не используют ни один из этих ключей API: они аутентифицируются через OAuth.

### Экспортировать в Terraform {#export-to-terraform}

Функция **Экспортировать в Terraform** помечена как **экспериментальная**. Выберите нужные типы ресурсов и с помощью **Download import file** добавьте их в проект Terraform. В интерфейсе отображается команда для генерации конфигурации ресурсов через провайдер ClickHouse. Соединения, управляемые платформой, экспортируются как locals, которые служат только для ссылок.

### Настройка генеративного ИИ {#generative-ai}

С помощью **Configure Generative AI** можно включить или отключить возможности генеративного ИИ для сервиса. К ним относятся Chart AI Assistant в Обозревателе диаграмм и [ИИ-блокноты](/ru/clickstack/observability/notebooks).

## Интеграции {#integrations}

Для управления вебхуками откройте **Team Settings → Интеграции**. Чтобы добавить интеграцию для уведомлений об оповещениях, нажмите **Add Webhook**. Подробнее о настройке оповещений см. в разделе [Оповещения](/ru/clickstack/observability/features/alerts).

## Настройки запроса {#query-settings}

Откройте **Team Settings → Настройки запроса**, чтобы настроить, как приложение выполняет запросы к ClickHouse. Чтобы изменить настройку, нажмите **Изменить** рядом с ней. В интерфейсе эта вкладка помечена как **экспериментальная**.

| Настройка                             | Назначение                                                                                                      |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Search Row Limit**                  | Ограничивает количество строк, возвращаемых одним запросом на странице Search и в плитках поисковых панелей мониторинга.  |
| **Query Timeout (seconds)**           | Задаёт максимальное время выполнения запроса.                                                                   |
| **Max Rows to Read (METADATA ONLY)**  | Ограничивает количество строк таблицы, сканируемых запросами к метаданным.                                      |
| **Filter Keys Fetch Limit**           | Определяет, сколько ключей фильтров загружается при нажатии **More filters** на странице Search.                |
| **Field Metadata Queries**            | Определяет, запрашивает ли приложение метаданные полей из ClickHouse.                                           |
| **Parallelize Queries When Possible** | Позволяет выполнять подходящие оконные запросы параллельно. Это может увеличить пиковую нагрузку на ClickHouse. |

На вкладке также можно настроить порог мягкой блокировки гистограммы поиска и длительность окон поиска. Нажмите **Reset to default**, чтобы сбросить настройки запроса к значениям по умолчанию.

## Миграции схемы {#schema-migrations}

Чтобы просмотреть историю миграций, откройте **Team Settings → Миграции схемы**.

Настройки источников и схем для самоуправляемых развертываний описаны в разделе [Настройки источников и схем для самоуправляемых развертываний](/ru/clickstack/self-configured/managing/config).
