ClickHouse Observability поддерживает ролевое управление доступом (RBAC): вы можете определять пользовательские роли с детализированными разрешениями для [панелей мониторинга](/ru/clickstack/observability/features/dashboards/overview), [сохранённых поисков](/ru/clickstack/observability/features/search), источников, [оповещений](/ru/clickstack/observability/features/alerts), вебхуков и блокнотов. Разрешения действуют на двух уровнях: доступ на уровне ресурса («Нет доступа», «Чтение» или «Управление» для каждого типа ресурса) и необязательные детализированные правила, ограничивающие доступ к отдельным ресурсам по имени, метке или ID. Сервис поставляется с тремя встроенными ролями, а при необходимости можно создать пользовательские роли под задачи вашей команды.

## Предварительные требования для доступа пользователей {#user-access-prerequisites}

Сервис выполняет аутентификацию через ClickHouse Cloud. Пользователи должны состоять в вашей организации ClickHouse Cloud и иметь доступ к сервису Observability. Об управлении составом организации см. раздел [Управление пользователями облака](/ru/products/cloud/guides/security/cloud-access-management/manage-cloud-users).

Уровни доступа к Cloud SQL Console соответствуют уровням доступа к Observability следующим образом:

| Доступ к Cloud SQL Console            | Доступ к Observability                                                                                    |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **SQL Console Admin** (Full Access)   | Полный доступ к сервису. Требуется для включения [оповещений](/ru/clickstack/observability/features/alerts). |
| **SQL Console Read Only** (Read Only) | Просмотр данных обсервабилити и создание панелей мониторинга.                                             |
| **Нет доступа**                         | Нет доступа к сервису.                                                                                    |

Откройте **Team Settings → Участники и роли**, чтобы просмотреть участников команды и их текущие роли в Observability. Чтобы управлять составом организации в ClickHouse Cloud, нажмите **Управлять в консоли**.

## Встроенные роли {#built-in-roles}

В сервисе есть три системные роли. Их нельзя изменить или удалить. По умолчанию создателю команды назначается роль администратора.

| Разрешение                                | Администратор | Member | ReadOnly |
| ----------------------------------------- | :---: | :----: | :------: |
| Чтение всех ресурсов                      |   ✓   |    ✓   |     ✓    |
| Управление панелями мониторинга           |   ✓   |    ✓   |          |
| Управление сохранёнными поисками          |   ✓   |    ✓   |          |
| Управление источниками                    |   ✓   |    ✓   |          |
| Управление оповещениями                   |   ✓   |    ✓   |          |
| Управление вебхуками                      |   ✓   |    ✓   |          |
| Управление блокнотами                     |   ✓   |    ✓   |          |
| Изменение настроек команды                |   ✓   |    ✓   |          |
| Создание и удаление команд                |   ✓   |        |          |
| Управление пользователями и приглашениями |   ✓   |        |          |

## Назначение ролей участникам команды {#assigning-roles}

На вкладке **Участники и роли** в разделе **Team Settings** приведён список участников команды и их текущих ролей. Чтобы изменить роль, нажмите **Изменить** рядом с именем пользователя и выберите новую роль. У каждого пользователя ровно одна роль.

### Роль нового пользователя по умолчанию {#default-new-user-role}

В разделе **Team Settings** → **Участники и роли** с помощью параметра **Роль нового пользователя по умолчанию** под списком ролей выберите роль, которая назначается пользователям, автоматически присоединяющимся к команде. Если роль по умолчанию не задана, новые пользователи получают роль **Member**.

## Разрешения ролей {#role-permissions}

### Разрешения на ресурсы {#resource-permissions}

Каждая роль задаёт уровень доступа для каждого типа ресурсов. Всего предусмотрено три уровня:

| Уровень доступа | Что разрешено                                                                         |
| --------------- | ------------------------------------------------------------------------------------- |
| **Нет доступа** | Тип ресурса полностью скрыт от роли.                                                  |
| **Чтение**      | Просмотр ресурса и его конфигурации без возможности создания, изменения или удаления. |
| **Управление**  | Полный контроль — создание, изменение и удаление ресурсов этого типа.                 |

Доступом можно управлять для следующих типов ресурсов:

* **[Панели мониторинга](/ru/clickstack/observability/features/dashboards/overview)** — сохранённые структуры панелей мониторинга и диаграммы.
* **[Сохранённые поиски](/ru/clickstack/observability/features/search)** — сохранённые запросы по журналам, трассам и событиям.
* **Источники** — источники данных, используемые для запросов к данным обсервабилити.
* **[Оповещения](/ru/clickstack/observability/features/alerts)** — правила оповещений и настройки уведомлений для них.
* **Вебхуки** — пункты назначения исходящих уведомлений (например, Slack, PagerDuty и универсальные конечные HTTP-точки), куда доставляются [оповещения](/ru/clickstack/observability/features/alerts). Не путайте с API обсервабилити.
* **Блокноты** — совместные блокноты для расследований.

### Административные разрешения {#administrative-permissions}

Помимо разрешений на ресурсы, каждая роль включает две административные настройки:

* **Users** (Нет доступа · Чтение) — определяет, может ли роль просматривать участников команды и их роли. Управлять составом участников организации можно с помощью действия **Управлять в консоли**.
* **Team** (Чтение · Управление) — определяет, может ли роль просматривать или изменять настройки уровня команды, например политики безопасности и конфигурацию RBAC.

### Детализированные правила доступа {#fine-grained-access-rules}

Для панелей мониторинга, сохранённых поисков, источников и блокнотов доступна точная настройка, позволяющая ограничить доступ к отдельным ресурсам внутри категории. Используйте её, если нужно ограничить роль конкретными ресурсами, а не выдавать полный доступ ко всем ресурсам данного типа.

#### Доступ по умолчанию и точная настройка {#access-control-modes}

Для каждого типа ресурсов задаётся **режим управления доступом**:

* **Доступ по умолчанию** — ко всем ресурсам этого типа применяется единый уровень доступа («Нет доступа», «Чтение» или «Управление»).
* **Точная настройка** — позволяет задавать правила доступа, которые по условию применяются к конкретным ресурсам. Ресурсы, не подпадающие ни под одно правило, по умолчанию недоступны.

Чтобы сменить режим, в редакторе роли разверните нужный тип ресурса, нажав на шеврон, а затем переключите **режим управления доступом**.

#### Настройка правил доступа {#configuring-access-rules}

Каждое правило доступа состоит из **условия** и **уровня доступа**. Условия отбирают ресурсы по их свойствам:

<div className="ch-image-md">
  <Frame>
    ![Всплывающая подсказка условия: отбор ресурсов по имени или метке (видны в заголовке) или по ID (указан в URL)](/images/clickstack/rbac/condition-tip.webp)
  </Frame>
</div>

| Поле условия | Операторы        | Что проверяется                                                                                                                                                 | Пример                                                                                                 |
| ------------ | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Name**     | `is`, `contains` | Отображаемое имя ресурса — например, заголовок панели мониторинга.                                                                                              | Name contains `production` — подходит любая панель мониторинга, в заголовке которой есть «production». |
| **Метка**      | `is`, `contains` | Метки, назначенные ресурсу через панель меток в правом верхнем углу страницы ресурса. Доступно только для панелей мониторинга, сохранённых поисков и блокнотов. | Метка is `critical` — подходят ресурсы с меткой «critical».                                              |
| **ID**       | `is`, `contains` | Идентификатор ресурса, который отображается в адресной строке при открытии ресурса.                                                                             | ID is `abc123` — подходит один конкретный ресурс.                                                      |

На следующем снимке экрана выделены ID панели мониторинга в адресной строке и метка «TESTING» на панели меток (справа вверху).

<div className="ch-image-lg">
  <Frame>
    ![Панель мониторинга с идентификатором ресурса в адресной строке и меткой в правом верхнем углу](/images/clickstack/rbac/dashboard-id-and-tag-example.webp)
  </Frame>
</div>

Для каждого типа ресурсов можно добавить несколько правил. Каждое правило проверяется независимо, по логике OR: ресурс доступен, если он подходит под **любое** из правил. Ресурсы, не подходящие ни под одно правило, недоступны.

<div className="ch-image-md">
  <Frame>
    ![Всплывающая подсказка о правилах доступа с логикой OR](/images/clickstack/rbac/access-rules-tip.webp)
  </Frame>
</div>

**Пример**: чтобы предоставить роли доступ только для чтения к тестовым панелям мониторинга, разверните раздел панелей мониторинга, переключитесь на точную настройку и добавьте два правила:

* **Name** `contains` `testing` с уровнем доступа **Чтение**
* **Метка** `is` `testing` с уровнем доступа **Чтение**

Панель мониторинга, подходящая под любое из этих правил, будет доступна.

<div className="ch-image-md">
  <Frame>
    ![Два детализированных правила доступа, объединённых через OR: Name contains testing с доступом Чтение и Метка is testing с доступом Чтение](/images/clickstack/rbac/dashboard-fine-grained-example.webp)
  </Frame>
</div>

## Политики безопасности {#security-policies}

В разделе **Team Settings → Участники и роли → Политики безопасности** параметр **Отключить экспорт данных** скрывает элементы управления для скачивания и копирования данных журналов, в том числе сведений о строках, у всех участников команды. При этом пользователи по-прежнему могут выделять текст на экране, а API и MCP-сервер продолжают возвращать данные. Эта настройка не ограничивает доступ к исходным данным.

Настройки генеративного ИИ находятся в разделе **Team Settings → API и агенты → Настроить Генеративный ИИ**. Подробнее см. в разделе [Настройка генеративного ИИ](/ru/clickstack/observability/managing/config#generative-ai).
