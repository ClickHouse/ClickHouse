Отправляйте журналы, метрики и трассировки в ClickHouse Observability с помощью Java-агента OpenTelemetry или SDK.

## Настройка OpenTelemetry {#set-up-opentelemetry}

Следуйте официальным [инструкциям по настройке Java-агента OpenTelemetry](https://opentelemetry.io/docs/zero-code/java/agent/getting-started/), чтобы установить инструментирование и настроить приложение. Для ручного инструментирования воспользуйтесь [документацией по Java SDK](https://opentelemetry.io/docs/languages/java/instrumentation/).

Настройте [экспорт OTLP](https://opentelemetry.io/docs/languages/java/configuration/#properties-exporters) для нужных сигналов, используя приведённые ниже настройки соединения. Замените все примеры пунктов назначения из вышестоящих инструкций, в том числе переопределения конечных точек для отдельных сигналов.

## Настройка пункта назначения {#configure-destination}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Бета-версия" />

    Откройте в своём сервисе **Team Settings → Data → Managed Telemetry** и скопируйте значения **конечная точка OTLP HTTP** и **API key**. Указывайте конечную точку HTTPS полностью, включая порт:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите конечную точку OTLP HTTP вашего коллектора и ключ ингестии. Если в коллекторе не настроен TLS, используйте `http://` вместо `https://`. О настройке коллектора см. раздел [Приём данных с помощью OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry#sending-otel-data-self-configured).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## Проверка ингестии {#verify-ingestion}

Запустите инструментированное приложение и создайте на нём нагрузку. В ClickHouse Observability выберите недавний временной диапазон и найдите имя сервиса вашего приложения в разделе журналов или трассировок. Если приложение отправляет метрики, подождите, пока завершится экспорт, и проверьте раздел метрик.

Сведения об устранении неполадок с инструментированием и экспортером см. в [руководстве по устранению неполадок Java-агента OpenTelemetry](https://opentelemetry.io/docs/zero-code/java/agent/getting-started/#troubleshooting).
