ClickStack Browser SDK построен на основе OpenTelemetry и собирает данные о браузерных запросах, ошибках, а также данные для воспроизведения сеансов. С его помощью можно анализировать события фронтенда вместе с телеметрией бэкенда в ClickHouse Observability.

<ClickStackIntegrates signals={['logs', 'traces']} />

## Установка {#install}

Установите пакет в своё фронтенд-приложение:

```shell
npm install @clickhouse/clickstack-browser
```

Пакет использует ES-модули. Peer-зависимости OpenTelemetry npm устанавливает автоматически. Если ваше приложение также напрямую устанавливает `@opentelemetry/api`, используйте версию `~1.9.1` и следите, чтобы в проекте была только одна её копия: версия 1.10 не входит в диапазон, поддерживаемый этим SDK.

## Настройка пункта назначения {#configure-destination}

<Tabs>
  <Tab title="Полностью управляемый">
    <BetaBadge label="Бета-версия" />

    Откройте в своём сервисе **Team Settings → Data → Managed Telemetry** и скопируйте **конечную точку OTLP HTTP** и **API key**. Укажите полную конечную точку HTTPS вместе с портом, но без пути сигнала (например, `/v1/traces`).

    Инициализируйте SDK в модуле точки входа приложения:

    ```javascript
    import { init } from '@clickhouse/clickstack-browser';

    init({
      endpoint: 'https://YOUR_OTEL_ENDPOINT:4318',
      apiKey: 'Bearer YOUR_INGESTION_API_KEY',
      serviceName: 'my-frontend-app',
    });
    ```
  </Tab>

  <Tab title="Самоуправляемый">
    Укажите конечную точку OTLP HTTP вашего коллектора и настроенный для него ключ ингестии. Конечная точка должна быть доступна из браузеров ваших пользователей. Настройка коллектора описана в разделе [Приём данных с помощью OpenTelemetry](/ru/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```javascript
    import { init } from '@clickhouse/clickstack-browser';

    init({
      endpoint: 'https://YOUR_COLLECTOR_HOST:4318',
      apiKey: 'YOUR_INGESTION_API_KEY',
      serviceName: 'my-frontend-app',
    });
    ```

    Используйте ключ, настроенный для приёмника OTLP вашего коллектора. В конфигурации CORS HTTP-приёмника коллектора должна быть разрешена исходная ячейка вашего приложения.
  </Tab>
</Tabs>

Вызывайте `init` один раз при каждой загрузке страницы на верхнем уровне модуля точки входа, например в `src/main.ts` для Vite или в `instrumentation-client.ts` для Next.js. Инициализация выполняется асинхронно, поэтому запросы, отправленные сразу же в том же такте, могут не попасть в телеметрию. Не выполняйте инициализацию в эффекте React: функция очистки, вызывающая `shutdown`, окончательно отключает сбор телеметрии до следующей загрузки страницы.

<Note>
  Конфигурация браузера, включая ключ ингестии, видна любому, кто открывает страницу. Чтобы ключ оставался на сервере, используйте конечную точку с той же исходной ячейкой (например, `/otel`), не указывайте `apiKey` и настройте сервер так, чтобы он пересылал запросы OTLP с нужным заголовком авторизации.
</Note>

## Проверка ингестии {#verify-ingestion}

Загрузите приложение, выполните какие-либо действия на странице, отправьте запрос и вызовите ошибку в консоли. В ClickHouse Observability выберите недавний временной диапазон и выполните поиск `my-frontend-app` в разделе Logs или Traces. Откройте воспроизведение сеанса, чтобы просмотреть записанный сеанс.

Если данные не появились, проверьте консоль браузера и сетевые запросы к `/v1/traces` и `/v1/logs`. Убедитесь, что правильно настроены конечная точка, заголовок авторизации, CORS и Content Security Policy. Для самоуправляемых развертываний убедитесь, что ваша версия ClickStack поддерживает воспроизведение сеанса и стандартный атрибут SDK `session.id`: сам факт получения записей ещё не означает, что сеансы отображаются в интерфейсе.

## Параметры инициализации {#initialization-options}

Передайте эти параметры в `init`. Используйте `endpoint` для общего коллектора или укажите обе конечные точки сигналов, если трассировки и журналы отправляются в разные пункты назначения.

| Параметр             | По умолчанию                                           | Назначение                                                                                                                                                 |
| -------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`           | Обязателен, если не заданы обе конечные точки сигналов | Базовый URL OTLP HTTP или путь прокси на той же исходной ячейке; SDK добавляет к нему пути сигналов                                                                 |
| `tracesEndpoint`     | Не задан                                               | Полный URL для трассировок; используется как есть вместо URL, построенного на основе `endpoint`                                                            |
| `logsEndpoint`       | Не задан                                               | Полный URL для журналов и воспроизведения; используется как есть вместо URL, построенного на основе `endpoint`                                             |
| `serviceName`        | Обязателен                                             | Задаёт `service.name` для всей телеметрии                                                                                                                  |
| `apiKey`             | Не задан                                               | Значение заголовка `authorization`; используйте формат, указанный выше для вашего пункта назначения                                                        |
| `traceOrigins`       | Не задан                                               | Исходные ячейки бэкенда или регулярные выражения, которым передаётся контекст трассировки                                                                           |
| `replay`             | `true`                                                 | Включает запись для воспроизведения сеанса; `false` сохраняет телеметрию браузера, но отключает воспроизведение                                            |
| `resourceAttributes` | Не задан                                               | Дополнительные атрибуты ресурса, в том числе для воспроизведения; `serviceName`, `serviceVersion` и `environment` имеют приоритет над совпадающими ключами |
| `maskAllText`        | `true`                                                 | Маскирует текст в воспроизведении                                                                                                                          |
| `maskAllInputs`      | `true`                                                 | Маскирует значения полей input, textarea и select                                                                                                          |
| `console`            | `'error'`                                              | Собирает сообщения уровня `'error'`, `'warn'`, `'info'` (включая `console.log`) или `'debug'` и более серьёзных уровней; `false` отключает сбор            |
| `serviceVersion`     | Не задан                                               | Идентифицирует релиз вашего приложения                                                                                                                     |
| `environment`        | Не задан                                               | Задаёт `deployment.environment.name`                                                                                                                       |
| `sanitizeUrl`        | Не задан                                               | Переписывает записываемые URL, например чтобы удалить параметры запроса                                                                                    |

Полное описание API см. в [справочнике по браузерному SDK](https://github.com/ClickHouse/clickstack-browser#quick-start).

## Воспроизведение сеансов и конфиденциальность {#session-replay-and-privacy}

Воспроизведение сеансов включено по умолчанию. Текст и вводимые значения по умолчанию маскируются.

Маскирование не скрывает состояние флажков и переключателей (radio), а также атрибуты, например URL ссылок и плейсхолдеры. Чтобы исключить конфиденциальные элементы, используйте класс `rr-block`. Очистка URL не распространяется на URL внутри воспроизводимого содержимого страницы, трассировок стека и сообщений консоли. Собирайте только те сведения о пользователях, которые разрешены вашей политикой конфиденциальности.

Чтобы приостановить воспроизведение сеансов, не останавливая сбор телеметрии браузера:

```javascript
import { pauseReplay } from '@clickhouse/clickstack-browser';

pauseReplay();
```

Когда вы будете готовы возобновить запись:

```javascript
import { resumeReplay } from '@clickhouse/clickstack-browser';

resumeReplay();
```

## Связывание трассировки фронтенда и backend-трассировки {#trace-propagation}

Чтобы связать запросы браузера с backend-трассировкой, добавьте `traceOrigins` в параметры `init`, заменив значение из примера на исходную ячейку вашего бэкенда:

```javascript
traceOrigins: ['https://api.example.com'],
```

Запросы к собственной исходной ячейке (исходной ячейке) страницы и к соответствующим бэкендам содержат заголовки `traceparent`, `tracestate` и `baggage`. Ваш бэкенд должен быть инструментирован, чтобы продолжать этот контекст трассировки.

Бэкенды с другой исходной ячейкой (cross-origin) должны разрешать передачу этих заголовков в настройках CORS. Коллектор телеметрии также должен разрешать исходную ячейку фронтенда. Если в вашем приложении используется Content Security Policy, добавьте конечную точку коллектора в директиву `connect-src`.

## Идентификация пользователей и запись ошибок {#users-and-errors}

При входе пользователя в систему вызовите `setUser`, чтобы привязать информацию о пользователе к последующим спанам и журналам:

```javascript
import { setUser } from '@clickhouse/clickstack-browser';

setUser({ id: 'user-123', email: 'user@example.com' });
```

При выходе пользователя из системы очистите данные о нём и запустите новый сеанс:

```javascript
import { setUser, startNewSession } from '@clickhouse/clickstack-browser';

setUser(null);
startNewSession();
```

Чтобы прикреплять метаданные приложения к последующим спанам и журналам, используйте `setAttributes`. Каждый вызов заменяет предыдущий набор атрибутов; чтобы очистить его, передайте `null`:

```javascript
import { setAttributes } from '@clickhouse/clickstack-browser';

setAttributes({ 'app.team.name': 'checkout' });
```

Неперехваченные ошибки и необработанные отклонения промисов фиксируются автоматически. Ошибки из границ ошибок React, которые сообщают о них через `console.error`, по умолчанию также фиксируются. Используйте `recordException` для перехваченных ошибок, которые ещё не записаны в журнал: если одну и ту же ошибку и зарегистрировать через `recordException`, и записать в журнал, возникнут дублирующиеся события:

```javascript
import { recordException } from '@clickhouse/clickstack-browser';

try {
  await submitCheckout();
} catch (error) {
  recordException(error, { 'app.operation': 'checkout' });
  // Handle the error in your application.
}
```

Замените `submitCheckout` на операцию приложения, которую нужно отслеживать.

## Миграция с браузерного SDK HyperDX {#migration}

Это не просто обновление с заменой имени пакета. `url` становится `endpoint`, `service` — `serviceName`, а `tracePropagationTargets` — `traceOrigins`. Маскирование текста и полей ввода теперь по умолчанию включено (`true`). Замените `setGlobalAttributes` на `setUser` для идентичности пользователя и на `setAttributes` для метаданных приложения. Для границ ошибок React (error boundaries), которые сообщают об ошибках через `console.error`, дополнительный хук не нужен; используйте `recordException`, если ошибка ещё не записана в журнал.

Удалённые параметры и изменения атрибутов описаны в [руководстве по миграции SDK](https://github.com/ClickHouse/clickstack-browser/blob/main/docs/migration.md). Об установке через тег script или об использовании в приложении, где OpenTelemetry уже инициализирован, см. [README SDK](https://github.com/ClickHouse/clickstack-browser#readme).

Если ClickStack Browser SDK вызывает проблемы совместимости в вашем приложении, на время их анализа можно использовать [устаревший браузерный SDK HyperDX](https://github.com/hyperdxio/hyperdx-js/tree/main/packages/browser). Восстановите его конфигурацию и вызовы API по приведённому выше руководству по миграции; эти два SDK не взаимозаменяемы, и использовать их одновременно нельзя.
