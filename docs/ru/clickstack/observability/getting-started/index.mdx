Начните работу с ClickHouse Observability: отправьте тестовое событие и убедитесь, что оно отображается в интерфейсе обсервабилити.

Сервис предоставляет управляемую конечную точку приёма телеметрии. Отправляйте на неё данные из своих приложений, агентов или уже развёрнутого OpenTelemetry Collector.

Если вы самостоятельно управляете конвейером ингестии и схемой данных, воспользуйтесь [руководством по началу работы с самоуправляемым развёртыванием](/ru/clickstack/self-configured/getting-started/managed).

## Перед началом работы {#before-you-begin}

Вам потребуется полностью управляемый сервис ClickHouse Observability, а также доступ к его конечной точке телеметрии и ключу API.

### Создайте сервис {#create-a-service}

Если у вас ещё нет сервиса, начните с раздела [Создание сервиса ClickHouse](/ru/get-started/setup/cloud#1-create-a-clickhouse-service) в руководстве по быстрому старту ClickHouse Cloud. Когда сервис будет запущен, откройте ClickHouse Observability. Если в сервисе ещё нет данных, автоматически откроется страница **Начало работы**. Для отправки телеметрии выберите один из трёх способов, описанных ниже.

## Настройка ClickHouse Observability {#set-up-clickhouse-observability}

Выберите вариант, подходящий для вашего окружения.

<Tabs>
  <Tab title="Использовать существующую настройку OpenTelemetry">
    <div className="ch-image-md">
      <Frame>
        ![Диалог настройки OpenTelemetry с вариантами URL, Collector config и Env vars и скрытыми сведениями о подключении](/images/clickstack/getting-started/observability-connection-details.png)
      </Frame>
    </div>

    Используйте этот вариант, если ваше приложение, агент или коллектор уже генерирует данные OpenTelemetry.

    1. На странице начала работы выберите **View connection details**.

    2. Скопируйте конфигурацию для отправителя телеметрии. В сведениях о подключении доступны варианты **URL**, **Collector config** и **Env vars**.

    3. Настройте отправителя на экспорт телеметрии в управляемую конечную точку, используя предоставленные данные аутентификации.

    4. Поработайте с приложением в обычном режиме, а затем убедитесь, что полученные данные отображаются в разделе [Поиск](/ru/clickstack/observability/features/search).

    Эти сведения о подключении также доступны в разделе **Team Settings → Data → Managed Telemetry**.

    <Tip>
      Для быстрой проверки (необязательно) выберите **send a test log** на странице начала работы. Эта кнопка сразу отправляет тестовую запись журнала из интерфейса, но не проверяет конфигурацию вашего приложения или коллектора.
    </Tip>
  </Tab>

  <Tab title="Инструментировать с помощью ИИ">
    <div className="ch-image-md">
      <Frame>
        ![Диалог настройки с помощью ИИ-агента с промптом для инструментирования и скрытыми переменными окружения для конечной точки и ключа API](/images/clickstack/getting-started/observability-ai-instrumentation.png)
      </Frame>
    </div>

    Используйте этот вариант, если у вас есть прикладной код и вы хотите, чтобы помощник по программированию помог добавить инструментирование OpenTelemetry.

    1. В разделе **Инструментировать с помощью ИИ** выберите **Copy prompt**, чтобы открыть диалог **Set it up with an AI agent**.
    2. Скопируйте промпт из диалога и вставьте его в помощник по программированию, имеющий доступ к коду вашего приложения, например Cursor, Copilot или Claude Code.
    3. Задайте `CLICKSTACK_OTLP_ENDPOINT` и `CLICKSTACK_API_KEY`, используя значения из диалога. Храните их в файле `.env`, исключённом из системы контроля версий, или в хранилище секретов.
    4. Проверьте и примените предложенное инструментирование, затем запустите приложение и сгенерируйте событие.

    Чтобы применить этот подход к собственному приложению, воспользуйтесь руководством [Инструментировать с помощью ИИ](/ru/clickstack/observability/ingesting-data/sdks/instrument-with-ai).

    Полный пример с прикладным кодом и промптом для инструментирования приведён в [демо HackerNews Analyzer](/ru/clickstack/observability/example-datasets/instrument-application). В нём пошагово описана отправка журналов приложения, трассировок, метрик и воспроизведения браузерных сеансов в ваш управляемый сервис.
  </Tab>

  <Tab title="Следовать руководствам по настройке">
    <div className="ch-image-md">
      <Frame>
        ![Диалог отправки данных с поиском по руководствам по настройке для языков, фреймворков, инфраструктуры и коллекторов](/images/clickstack/getting-started/observability-setup-guides.png)
      </Frame>
    </div>

    Используйте этот вариант, если вам нужны инструкции для конкретного приложения или инфраструктурного источника.

    1. Выберите **Browse setup guides**.
    2. Выберите руководство для вашего языка, фреймворка или инфраструктуры.
    3. Выполните описанные в нём шаги по инструментированию и настройке, затем сгенерируйте телеметрию из этого источника.

    Примеры управляемой конфигурации лучше начать с [мониторинга Kubernetes](/ru/clickstack/observability/example-datasets/kubernetes), [локальных журналов и метрик](/ru/clickstack/observability/example-datasets/local-data) или [приложения HackerNews Analyzer](/ru/clickstack/observability/example-datasets/instrument-application). Чтобы опробовать ингестию без инструментирования приложения, используйте [otelgen](/ru/clickstack/observability/example-datasets/otelgen) или [telemetrygen](/ru/clickstack/observability/example-datasets/telemetrygen).
  </Tab>
</Tabs>

## Проверьте ингестию и начните исследование данных {#verify-ingestion}

Выполнив шаги выбранного варианта, нажмите **Start exploring**, чтобы открыть страницу [Поиск](/ru/clickstack/observability/features/search). Прежде чем продолжить, найдите сгенерированное вами событие и убедитесь, что оно появилось.

Для журналов выберите источник **Logs** и временной диапазон, включающий момент отправки события. В примере ниже показана тестовая запись журнала с именем сервиса `example-service`, отправленная с помощью кнопки **send a test log** в интерфейсе. Разверните событие, чтобы просмотреть его атрибуты.
