Карты сервисов наглядно показывают, как взаимодействуют ваши сервисы. ClickHouse Observability строит граф, сопоставляя клиентские спаны (исходящие запросы) с серверными спанами (входящими запросами) в пределах одной трассы и тем самым восстанавливая путь запроса между сервисами.

Чтобы открыть полный граф, нажмите **Карта сервисов** в левой панели навигации. Сервисы появятся, как только вы начнёте [загрузку данных трассировки](/ru/clickstack/observability/ingesting-data/overview) с помощью OpenTelemetry.

## Изучение карты сервисов {#exploring-the-service-map}

Каждый узел соответствует сервису, который определяется атрибутом ресурса `service.name`. Рёбра (пунктирные линии) соединяют сервисы, у которых клиентский спан одного совпадает с серверным спаном другого. Размер узла отражает относительный объём трафика. В режиме **Error rate** красным выделяются сервисы, в которых в выбранном временном диапазоне возникали ошибки. Для переключения между режимами **Latency**, **Error rate** и **Throughput** используйте легенду в правом верхнем углу.

С помощью панели инструментов над картой можно фильтровать и настраивать представление.

**Селектор источников** — выбор источника трасс для построения карты, например **Traces**.

**Ползунок сэмплирования** — настройка частоты сэмплирования для баланса между производительностью и точностью. При более низкой частоте карта на высоконагруженных кластерах загружается быстрее.

**Элемент выбора диапазона дат** — задание временного окна для данных трассировки, по которым строится карта.

Для увеличения и уменьшения масштаба используйте кнопки **+/-** в левом нижнем углу карты или прокрутку.

## Карты сервисов на уровне трассы {#trace-level-service-maps}

При просмотре отдельной трассы откройте вкладку **Карта сервисов**, чтобы увидеть, как именно этот запрос проходил между сервисами. Чтобы вернуться к каскадной диаграмме, переключитесь обратно на вкладку **Трасса**.
