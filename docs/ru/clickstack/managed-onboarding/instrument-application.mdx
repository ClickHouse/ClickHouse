<Note>
  **Вы выбрали самоуправляемый вариант**

  Вы решили настроить ClickHouse Observability самостоятельно, используя [самоуправляемый вариант](/ru/clickstack/self-configured/overview). В этом случае вы сами запускаете коллектор OpenTelemetry, управляете ингестией в ваш сервис ClickHouse Cloud, настраиваете схему и разделяете рабочие нагрузки ингестии и запросов с помощью хранилищ. См. разделы [Коллектор OpenTelemetry](/ru/clickstack/self-configured/ingesting-data/collector), [Настройка производительности](/ru/clickstack/self-configured/managing/performance-tuning) и [Изоляция рабочих нагрузок чтения и записи](/ru/clickstack/self-configured/managing/isolating-read-write).

  Предпочитаете бессерверный вариант, в котором ClickHouse берёт на себя ингестию, схемы и вычислительные ресурсы? Тогда используйте стандартный вариант ClickHouse Observability и следуйте руководству [Инструментируйте своё приложение с помощью OpenTelemetry](/ru/clickstack/managed-onboarding/instrument-application-serverless).
</Note>

В этом руководстве показано, как инструментировать небольшое приложение на Node.js с помощью OpenTelemetry и отправлять его журналы, метрики, трассировки и воспроизведения сеансов в ClickHouse Observability через ваш собственный коллектор. Серверная часть инструментируется без каких-либо изменений в исходном коде приложения.

[HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) — это приложение на Node.js, которое выполняет запросы к набору данных HackerNews, размещённому в публичной демонстрационной среде ClickHouse. За каждым графиком, таблицей и полем поиска стоит реальный запрос к ClickHouse, поэтому каждое действие пользователя порождает трассировку, основной спан которой — HTTPS-вызов от серверной части к ClickHouse.

Предполагается, что вы уже выполнили шаги из руководства [Настройка коллектора OpenTelemetry](/ru/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) и у вас запущен коллектор ClickStack, доступный с машины, на которой будет работать это приложение. **Убедитесь, что вы сохранили его конечную точку OTLP** и значение `OTLP_AUTH_TOKEN`, заданное при развертывании. Перед инструментированием эти значения нужно будет указать в `.env`.

## Предварительные требования {#prerequisites}

* Коллектор ClickStack, доступный с этой машины. Если вы еще не развернули его, сначала следуйте инструкции [Настройка коллектора OpenTelemetry](/ru/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector).
* Конечная точка OTLP/HTTP этого коллектора (обычно порт `4318`) и заданный для него `OTLP_AUTH_TOKEN`. Используйте их в качестве `OTEL_EXPORTER_OTLP_ENDPOINT` и `OTEL_EXPORTER_OTLP_HEADERS=authorization=<token>`.
* Node 18+ и npm.

## Клонируйте репозиторий {#clone-the-repository}

Клонируйте [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), установите зависимости и скопируйте шаблон файла env:

```bash
git clone https://github.com/ClickHouse/hn-news-analyzer.git
cd hn-news-analyzer
npm install
cp .env.example .env
```

На следующих шагах заполните `.env`, затем выполните инструментирование из этого каталога.
