<Info>
  **Кратко**

  Запустите небольшое демо-приложение, инструментируйте его с помощью AI-промпта со страницы «Начало работы» вашего сервиса или внесите вручную две правки и наблюдайте, как журналы, трассировка и метрики поступают в ClickHouse Observability.

  Требуемое время: около 10 минут
</Info>

Сервис ClickHouse Observability создан. Это руководство поможет перейти от пустого сервиса к получению телеметрии от работающего приложения.

ClickHouse Observability предоставляет управляемую конечную точку OpenTelemetry, в которую приложение отправляет телеметрию напрямую. Не нужно запускать коллектор, создавать схему или подбирать размер базы данных: ингестию, схемы, хранилище, оптимизацию и масштабирование мы берём на себя.

## Демо-приложение {#the-demo-application}

Чтобы вам было что инструментировать в условиях, близких к реальным, в этом руководстве используется [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) — демо-приложение, которое мы подготовили специально для этой цели. Это небольшое приложение на Node.js и TypeScript, которое выполняет запросы к набору данных HackerNews, размещённому в публичной демо-среде ClickHouse. За каждым чартом, таблицей и полем поиска стоит реальный запрос к бэкенду. Запросы, не попавшие в кэш приложения, также обращаются к ClickHouse, поэтому в каждой трассе появляется исходящий HTTPS-спан.

Демо-приложение доступно в двух вариантах:

* **Без инструментирования** — в ветке `main`. В этом руководстве вы добавите инструментирование самостоятельно — с помощью ИИ-агента или вручную, — не меняя бизнес-логику приложения. Те же шаги подойдут и для ваших собственных сервисов.
* **С готовым инструментированием** — в ветке `instrumented`. Переключитесь на неё, если хотите быстро получить поток телеметрии и изучить интерфейс.

## Предварительные требования {#prerequisites}

* Сервис ClickHouse Observability. Если у вас его ещё нет, воспользуйтесь [руководством по началу работы](/ru/clickstack/observability/getting-started).
* Node.js версии 18 или новее и npm.
* Сетевой доступ к конечной точке телеметрии вашего сервиса с машины, на которой запускается демо, а также из браузера.

### Подключение демонстрационного приложения к вашему сервису {#configure-environment}

        Откройте файл `.env` и задайте следующие значения, подставив вместо конечной точки и ключа API значения из диалогового окна:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Это стандартные переменные экспортера OpenTelemetry. В исходном коде приложения ничего не захардкожено.

        Сохраните префикс `https://` в `OTEL_EXPORTER_OTLP_ENDPOINT` и не добавляйте в конец `/v1/logs`, `/v1/traces` или `/v1/metrics`: SDK добавляют пути для каждого сигнала самостоятельно. Задайте для `OTEL_EXPORTER_OTLP_HEADERS` значение `authorization=<your-api-key>` без префикса `Bearer`.

        Инструментирование состоит из трёх частей: установка SDK, изменение команды запуска и включение браузерного SDK. Ни одна из них не затрагивает бизнес-логику приложения.

### Установка Node SDK {#install-node-sdk}

        ```bash
        npm install @hyperdx/node-opentelemetry
        ```

### Включите обёртку в run.sh {#enable-run-sh-wrapper}

        В конце файла `run.sh` есть две строки с `exec`. Закомментируйте строку с обычным вызовом `node` и раскомментируйте инструментированную:

        ```diff
         # BEFORE: plain node, no instrumentation:
        -exec node scripts/entrypoint.js
        +# exec node scripts/entrypoint.js

         # AFTER: same source, wrapped by opentelemetry-instrument:
        -# exec npx opentelemetry-instrument scripts/entrypoint.js
        +exec npx opentelemetry-instrument scripts/entrypoint.js
        ```

        По-прежнему запускайте приложение через `scripts/entrypoint.js`. Эта прослойка вызывает `require('console')`, чтобы перехват вывода консоли оборачивал `console.log`. Если направить `opentelemetry-instrument` напрямую на `dist/server/index.js`, трассировка будет отправляться, а журналы — незаметно отбрасываться.

### Включите браузерный SDK {#enable-browser-sdk}

        ```bash
        npm install @hyperdx/browser
        ```

        В файле `src/web/telemetry.ts` раскомментируйте импорт, блок `HyperDX.init` и вызов `HyperDX.addAction` в функции `recordAction`:

        ```diff
        -// import HyperDX from '@hyperdx/browser';
        +import HyperDX from '@hyperdx/browser';

         export function initTelemetry(): void {
        -  // HyperDX.init({
        -  //   url: __OTLP_ENDPOINT__,
        -  //   apiKey: __OTLP_AUTH_TOKEN__,
        -  //   service: 'hn-analyzer-web',
        -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        -  //   consoleCapture: true,
        -  //   advancedNetworkCapture: true,
        -  // });
        +  HyperDX.init({
        +    url: __OTLP_ENDPOINT__,
        +    apiKey: __OTLP_AUTH_TOKEN__,
        +    service: 'hn-analyzer-web',
        +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        +    consoleCapture: true,
        +    advancedNetworkCapture: true,
        +  });
         }
        ```

        `__OTLP_ENDPOINT__` и `__OTLP_AUTH_TOKEN__` — это константы времени компиляции, которые `vite.config.ts` подставляет из тех же значений `OTEL_EXPORTER_OTLP_*`, что использует серверная часть.

        <Warning>
          Браузерный SDK встраивает конечную точку и ключ API в браузерный бандл, где их может прочитать любой, кто откроет вкладку «Сеть». Используйте сервис, предназначенный для тестирования, и не добавляйте `.env` в систему контроля версий.
        </Warning>

        Снова запустите демонстрационное приложение командой `./run.sh`.
      </Tab>

      <Tab title="Используйте ветку с уже инструментированным приложением" id="use-the-instrumented-branch">
        Чтобы пропустить инструментирование и сразу начать с уже инструментированной демонстрационной версии, задайте значения `OTEL_EXPORTER_OTLP_*` в `.env`, как описано на вкладке ручного инструментирования, а затем переключитесь на [ветку `instrumented`](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented):

        ```bash
        git checkout instrumented
        npm install
        ./run.sh
        ```

        Не запускайте `./reset.sh` в этой ветке, если только не хотите удалить SDK.

## Если ничего не отображается {#if-nothing-shows-up}

* Проверьте значения в `.env`. Конечная точка должна начинаться с `https://`, заканчиваться портом `4318` и не содержать суффикса `/v1/...`. Ключ API нужно указать полностью — его можно скопировать, нажав **Reveal key**.
* Если вы выполняли настройку вручную, убедитесь, что `OTEL_EXPORTER_OTLP_HEADERS` имеет значение `authorization=<your-api-key>` без префикса `Bearer`, а в баннере при запуске отображаются все три строки `Health check passed`.
* Убедитесь, что после инструментирования вы перезапустили демо-приложение и перезагрузили вкладку браузера. Воспроизведение сеанса начинается только после того, как сервер начнёт отдавать инструментированный bundle.
* Расширьте временной диапазон на странице **Поиск** и сбросьте все фильтры. Возможно, в качестве источника по умолчанию выбран **Traces**, а не **Журналы**.
* Чтобы исключить проблему на стороне самого сервиса, перейдите в **Team Settings → Managed Telemetry** и воспользуйтесь функцией **Send a Test Журнал**. Если тестовый журнал появится в **Поиск**, значит, сервис получает данные, а проблема — в конфигурации демо-приложения.

## Дальнейшие шаги {#next-steps}

Теперь в вашем сервисе хранится телеметрия реального приложения. Чтобы инструментировать собственные сервисы, повторно используйте промпт **Инструментировать с помощью ИИ** из вашего сервиса или воспользуйтесь [поддерживаемыми SDK для языков программирования](/ru/clickstack/observability/ingesting-data/sdks/index) с той же конечной точкой и тем же ключом API.

Чтобы собирать данные с инфраструктуры, а не из прикладного кода:

* [Мониторинг Kubernetes](/ru/clickstack/observability/example-datasets/kubernetes): сбор журналов и метрик кластера и работа с панелью мониторинга Kubernetes.
* [Локальные журналы и метрики](/ru/clickstack/observability/example-datasets/local-data): сбор локальных файлов и системных метрик в macOS или Linux.

Чтобы глубже освоить интерфейс:

* [Поиск](/ru/clickstack/observability/features/search): запросы к журналам и трассировкам с помощью синтаксиса в стиле Lucene или SQL.
* [Воспроизведение сеанса](/ru/clickstack/observability/features/session-replay): обзор возможности, параметры SDK и настройки конфиденциальности.
* [Демонстрационные наборы данных](/ru/clickstack/observability/example-datasets): более объёмные наборы данных и пошаговые расследования.
