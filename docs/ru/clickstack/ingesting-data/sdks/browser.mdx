Браузерный SDK ClickStack построен на базе OpenTelemetry и собирает данные о браузерных запросах, ошибках и воспроизведении сеансов. С его помощью можно анализировать события фронтенда вместе с телеметрией бэкенда в ClickStack.

## Установка {#install}

Установите пакет в ваше фронтенд-приложение:

```shell
npm install @clickhouse/clickstack-browser
```

Пакет использует ES-модули. npm автоматически устанавливает peer-зависимости OpenTelemetry. Если ваше приложение также напрямую устанавливает `@opentelemetry/api`, используйте версию `~1.9.1` и следите, чтобы в проекте была только одна её копия: версия 1.10 не входит в диапазон версий, поддерживаемых этим SDK.

## Настройка пункта назначения {#configure-destination}

Используйте конечную точку OTLP HTTP вашего коллектора и настроенный для него ключ ингестии. Конечная точка должна быть доступна из браузеров ваших пользователей. О настройке коллектора см. раздел [Загрузка данных с помощью OpenTelemetry](/ru/clickstack/ingesting-data/opentelemetry).

```javascript
import { init } from '@clickhouse/clickstack-browser';

init({
  endpoint: 'https://YOUR_COLLECTOR_HOST:4318',
  apiKey: 'YOUR_INGESTION_API_KEY',
  serviceName: 'my-frontend-app',
});
```

Используйте ключ, настроенный для приёмника OTLP вашего коллектора. В конфигурации CORS HTTP-приёмника коллектора должен быть разрешён источник (origin) вашего приложения.

Вызывайте `init` один раз при каждой загрузке страницы на верхнем уровне входного модуля, например `src/main.ts` в Vite или `instrumentation-client.ts` в Next.js. Инициализация выполняется асинхронно, поэтому запросы, отправленные сразу же в том же тике, могут не попасть в сбор данных. Не выполняйте инициализацию в эффекте React: функция очистки, вызывающая `shutdown`, окончательно прекращает сбор телеметрии до следующей загрузки страницы.

<Note>
  Конфигурация в браузере, включая ключ для ингестии, доступна любому, кто загружает страницу. Чтобы ключ оставался на вашем сервере, используйте конечную точку с тем же origin, например `/otel`, не указывайте `apiKey` и настройте сервер так, чтобы он пересылал запросы OTLP с соответствующим заголовком авторизации.
</Note>

## Проверка ингестии {#verify-ingestion}

Загрузите приложение, выполните какие-либо действия на странице, отправьте запрос и вызовите ошибку в консоли. В ClickStack выберите временной диапазон за последнее время и выполните поиск `my-frontend-app` в разделе журналов или трассировок. Откройте воспроизведение сеанса, чтобы просмотреть записанный сеанс.

Если данные не поступают, проверьте консоль браузера и сетевые запросы к `/v1/traces` и `/v1/logs`. Проверьте конечную точку, заголовок авторизации, настройки CORS и Content Security Policy. Убедитесь, что ваша версия ClickStack поддерживает воспроизведение сеансов и стандартный атрибут SDK `session.id`: само по себе получение записей ещё не гарантирует, что сеансы отобразятся в интерфейсе.

## Параметры инициализации {#initialization-options}

Передайте эти параметры в `init`. Используйте `endpoint` для общего коллектора или укажите обе конечные точки сигналов, если трассировка и журналы отправляются в разные пункты назначения.

| Параметр             | Значение по умолчанию                                    | Назначение                                                                                                                                                        |
| -------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`           | Обязательный, если не заданы обе конечные точки сигналов | Базовый URL OTLP HTTP или путь прокси на том же origin; SDK добавляет к нему пути сигналов                                                                        |
| `tracesEndpoint`     | Не задан                                                 | Полный URL для трассировки; используется как есть вместо URL, производного от `endpoint`                                                                          |
| `logsEndpoint`       | Не задан                                                 | Полный URL для журналов и воспроизведения; используется как есть вместо URL, производного от `endpoint`                                                           |
| `serviceName`        | Обязательный                                             | Задаёт `service.name` для всей телеметрии                                                                                                                         |
| `apiKey`             | Не задан                                                 | Значение заголовка `authorization`; используйте формат, описанный выше для вашего пункта назначения                                                               |
| `traceOrigins`       | Не задан                                                 | Origin backend-сервисов или регулярные выражения, которым передаётся контекст трассировки                                                                         |
| `replay`             | `true`                                                   | Записывать сеансы для воспроизведения; при `false` браузерная телеметрия сохраняется, но воспроизведение отключается                                              |
| `resourceAttributes` | Не задан                                                 | Дополнительные атрибуты ресурса, в том числе для воспроизведения; `serviceName`, `serviceVersion` и `environment` имеют приоритет над совпадающими ключами        |
| `maskAllText`        | `true`                                                   | Маскировать текст при воспроизведении                                                                                                                             |
| `maskAllInputs`      | `true`                                                   | Маскировать значения элементов input, textarea и select                                                                                                           |
| `console`            | `'error'`                                                | Перехватывать сообщения уровня `'error'`, `'warn'`, `'info'` (включая `console.log`) или `'debug'` и всех более высоких уровней; чтобы отключить, укажите `false` |
| `serviceVersion`     | Не задан                                                 | Идентифицирует релиз вашего приложения                                                                                                                            |
| `environment`        | Не задан                                                 | Задаёт `deployment.environment.name`                                                                                                                              |
| `sanitizeUrl`        | Не задан                                                 | Переписывает записываемые URL, например, чтобы удалить параметры запроса                                                                                          |

Полное описание API см. в [справочнике по браузерному SDK](https://github.com/ClickHouse/clickstack-browser#quick-start).

## Воспроизведение сеанса и конфиденциальность {#session-replay-and-privacy}

Воспроизведение сеанса включено по умолчанию. Текст и значения полей ввода по умолчанию маскируются.

Маскирование не скрывает состояния флажков и переключателей, а также такие атрибуты, как URL ссылок и плейсхолдеры. Чтобы исключить конфиденциальные элементы, используйте класс `rr-block`. Санитизация URL не распространяется на URL внутри воспроизводимого содержимого страницы, трассировок стека и сообщений консоли. Собирайте только те данные о пользователях, сбор которых допускает ваша политика конфиденциальности.

Чтобы приостановить воспроизведение сеанса, не прекращая сбор телеметрии браузера:

```javascript
import { pauseReplay } from '@clickhouse/clickstack-browser';

pauseReplay();
```

Когда вы будете готовы возобновить запись:

```javascript
import { resumeReplay } from '@clickhouse/clickstack-browser';

resumeReplay();
```

## Связывание трассировки фронтенда и backend-трассировки {#trace-propagation}

Чтобы связать запросы браузера с backend-трассировкой, добавьте `traceOrigins` в параметры `init`, заменив значение из примера на origin вашего бэкенда:

```javascript
traceOrigins: ['https://api.example.com'],
```

Запросы к собственному origin страницы и к соответствующим бэкендам передают заголовки `traceparent`, `tracestate` и `baggage`. Ваш бэкенд должен быть инструментирован, чтобы продолжать этот контекст трассировки.

Бэкенды на других origin должны разрешать эти заголовки в настройках CORS. Коллектор телеметрии также должен разрешать origin фронтенда. Если в вашем приложении используется Content Security Policy, добавьте конечную точку коллектора в директиву `connect-src`.

## Идентификация пользователей и запись ошибок {#users-and-errors}

При входе пользователя в систему вызовите `setUser`, чтобы прикреплять информацию о пользователе к последующим спанам и журналам:

```javascript
import { setUser } from '@clickhouse/clickstack-browser';

setUser({ id: 'user-123', email: 'user@example.com' });
```

При выходе пользователя из системы очистите информацию о нём и начните новый сеанс:

```javascript
import { setUser, startNewSession } from '@clickhouse/clickstack-browser';

setUser(null);
startNewSession();
```

Чтобы добавить метаданные приложения к последующим спанам и журналам, используйте `setAttributes`. Каждый вызов заменяет ранее заданный набор атрибутов; чтобы очистить его, передайте `null`:

```javascript
import { setAttributes } from '@clickhouse/clickstack-browser';

setAttributes({ 'app.team.name': 'checkout' });
```

Неперехваченные ошибки и необработанные отклонения промисов перехватываются автоматически. Ошибки из границ ошибок React, которые сообщают о них через `console.error`, по умолчанию тоже перехватываются. Используйте `recordException` для перехваченных ошибок, которые ещё не были записаны в журнал: если одну и ту же ошибку и зарегистрировать, и записать в журнал, возникнут дублирующиеся события:

```javascript
import { recordException } from '@clickhouse/clickstack-browser';

try {
  await submitCheckout();
} catch (error) {
  recordException(error, { 'app.operation': 'checkout' });
  // Handle the error in your application.
}
```

Замените `submitCheckout` на операцию приложения, которую нужно отслеживать.

## Миграция с браузерного SDK HyperDX {#migration}

Это не просто обновление с изменением имени пакета. `url` заменяется на `endpoint`, `service` — на `serviceName`, а `tracePropagationTargets` — на `traceOrigins`. Маскирование текста и полей ввода теперь по умолчанию включено (`true`). Вместо `setGlobalAttributes` используйте `setUser` для идентичности пользователя и `setAttributes` для метаданных приложения. Для границ ошибок React (error boundaries), которые сообщают об ошибках через `console.error`, дополнительный хук не нужен; используйте `recordException`, если ошибка ещё не записана в журнал.

Список удалённых параметров и изменений в атрибутах приведён в [руководстве по миграции SDK](https://github.com/ClickHouse/clickstack-browser/blob/main/docs/migration.md). Об установке через тег script и о приложениях, в которых OpenTelemetry уже инициализирован, см. в [README SDK](https://github.com/ClickHouse/clickstack-browser#readme).

Если браузерный SDK ClickStack вызывает проблемы совместимости в вашем приложении, на время их выяснения можно использовать [устаревший браузерный SDK HyperDX](https://github.com/hyperdxio/hyperdx-js/tree/main/packages/browser). Восстановите его конфигурацию и вызовы API по приведённому выше руководству по миграции: эти два SDK не взаимозаменяемы, и использовать их одновременно нельзя.
