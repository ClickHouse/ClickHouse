ClickStack Node.js SDK построен на основе вышестоящего OpenTelemetry SDK и средств автоматического инструментирования. Он дополнительно обеспечивает capture вывода в консоль, capture неперехваченных исключений и сброс телеметрии при остановке. Приложения, в которых OpenTelemetry уже настроен, могут и дальше использовать существующий SDK, достаточно [настроить экспорт по OTLP](/ru/clickstack/ingesting-data/opentelemetry).

## Установка {#install}

Требуется Node.js **версии 22.15 или выше**. Установите SDK в своё приложение:

```shell
npm install @clickhouse/clickstack-node
```

Пакет поддерживает ES-модули и CommonJS. npm автоматически устанавливает его peer-зависимость `@opentelemetry/api`. Если ваше приложение импортирует этот пакет напрямую, установите `@opentelemetry/api@~1.9.1`: версия 1.10 не входит в диапазон версий, поддерживаемых этим SDK.

## Настройка пункта назначения {#configure-destination}

Задайте переменные окружения до запуска приложения. Указывайте базовую конечную точку OTLP HTTP без `/v1/traces`, `/v1/logs` или `/v1/metrics`: экспортеры сами добавляют эти пути в конец.

Используйте конечную точку OTLP HTTP вашего коллектора и ключ ингестии, настроенный для его приёмника OTLP. О настройке коллектора см. раздел [Приём данных с помощью OpenTelemetry](/ru/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
export OTEL_SERVICE_NAME='my-node-app'
```

Эта конечная точка рассчитана на то, что приложение и коллектор работают на одном хосте. Если коллектор запущен в другом месте, замените её адресом, доступным для вашего приложения.

## Запуск приложения {#start-application}

Загрузите SDK заранее — до того, как приложение импортирует инструментируемые им библиотеки:

```shell
node --import @clickhouse/clickstack-node/register server.js
```

Замените `server.js` на файл точки входа вашего приложения. Эта команда загружает SDK до запуска приложения и использует переменные окружения, настроенные выше. Поддерживаются приложения как на CommonJS, так и на ES-модулях.

Теперь можно [проверить ингестию](#verify-ingestion). Приведённые ниже альтернативные варианты нужны, только если вы хотите запускать приложение через npm-скрипт или настраивать SDK в коде.

<Accordion title="Альтернативные способы запуска">
  Также поддерживается `--require`. Если вы используете `NODE_OPTIONS`, задавайте эту переменную только для команды запуска приложения, чтобы инструменты сборки не запускали собственные конвейеры телеметрии:

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  Кроме того, можно создать модуль инструментирования и подключить его предварительно. Экспорт по-прежнему настраивается переменными окружения из предыдущего раздела:

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  Эта проверка не позволяет рабочим потокам, например воркерам транспорта Pino, запускать дополнительные инстансы SDK.

  Используйте либо точку входа регистрации из пакета, либо собственный модуль инструментирования. Не инициализируйте в приложении второй SDK. Статические импорты ES-модулей выполняются до тела модуля, поэтому вызов `init` выше статических импортов в том же файле не гарантирует нужного порядка инициализации.
</Accordion>

## Проверка ингестии {#verify-ingestion}

Запустите приложение, отправьте запросы к инструментированному маршруту и выведите сообщение в консоль. В ClickStack выберите недавний временной диапазон и выполните поиск `my-node-app` в разделе Logs или Traces. Прежде чем проверять метрики, дождитесь окончания интервала экспорта метрик.

Если данные не поступают, проверьте диагностические сообщения SDK в stderr, конечную точку и параметры аутентификации, а также сетевое подключение. Убедитесь, что инструментирование загружается раньше зависимостей приложения. Библиотеки, включённые в бандл, не могут быть автоматически инструментированы, если сборщик встраивает их код, поэтому SDK и инструментированные зависимости следует оставлять внешними. Требования к TypeScript, ES-модулям, фреймворкам и сборщикам приведены в разделе [Совместимость SDK](https://github.com/ClickHouse/clickstack-node#compatibility).

## Настройка инструментирования {#configure-instrumentation}

Стандартные переменные окружения OpenTelemetry сохраняют то же значение, что и в вышестоящем проекте, в том числе переменные для сэмплирования, пакетирования, экспортеров и атрибутов ресурса. Например:

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

Capture вывода в консоль выполняется по умолчанию. Capture тела HTTP-запросов и ответов по умолчанию отключён; включайте его, только если это допустимо для данных, которые обрабатывает ваше приложение:

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

Полученные с помощью capture тела запросов и ответов могут содержать персональные данные и учётные данные. Сокрытие конфиденциальных данных в SDK не гарантирует полной защиты, поэтому при необходимости сохраняйте сокрытие конфиденциальных данных на стороне коллектора. Сведения о capture заголовков, ограничениях размера тела и очистке данных см. в разделе [параметры конфиденциальности SDK](https://github.com/ClickHouse/clickstack-node#privacy).

### Параметры инициализации {#initialization-options}

Передайте эти параметры в `init` в модуле инструментирования:

| Параметр                     | По умолчанию                                      | Назначение                                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`                   | `http://localhost:4318`                           | Базовый URL OTLP HTTP; переопределяется `OTEL_EXPORTER_OTLP_ENDPOINT`                                                                                                           |
| `serviceName`                | `unknown_service:` с именем исполняемого файла    | Имя сервиса; переопределяется `OTEL_SERVICE_NAME` или `service.name` в `OTEL_RESOURCE_ATTRIBUTES`                                                                               |
| `environment`                | Не задано                                         | Задаёт `deployment.environment.name`; тот же ключ в `OTEL_RESOURCE_ATTRIBUTES` имеет приоритет                                                                                  |
| `apiKey`                     | Не задано                                         | Значение заголовка авторизации; игнорируется, если `OTEL_EXPORTER_OTLP_HEADERS` уже не пуста, даже если она содержит только посторонние заголовки                               |
| `httpBodyCapture`            | `false`                                           | Capture тел HTTP-запросов и ответов; переопределяется `CLICKSTACK_CAPTURE_HTTP_BODY`                                                                                             |
| `instrumentations`           | Значения по умолчанию из вышестоящей конфигурации | Map конфигурации для `getNodeAutoInstrumentations`; явно заданные значения `enabled` имеют приоритет над переменными окружения, включающими или отключающими инструментирование |
| `additionalInstrumentations` | `[]`                                              | Дополнительные инстансы инструментирования для библиотек, не входящих в стандартный набор                                                                                       |

Если переменная окружения не задана или пуста, действует значение соответствующего параметра. Чтобы отключить capture вывода консоли, добавьте `console` в `OTEL_NODE_DISABLED_INSTRUMENTATIONS`. Все значения по умолчанию приведены в [справочнике по Node.js SDK](https://github.com/ClickHouse/clickstack-node#quick-start).

О явном завершении процессов и обработчиках AWS Lambda см. в [документации по жизненному циклу SDK](https://github.com/ClickHouse/clickstack-node#lifecycle).

## Использование вышестоящего SDK {#using-upstream-sdk}

Если в вашем приложении OpenTelemetry уже настроен или требуются пользовательские процессоры либо поведение, выходящее за рамки параметров ClickStack SDK, используйте вышестоящий `NodeSDK` и настройте экспорт по OTLP в указанный выше пункт назначения. Воспользуйтесь [примером настройки вышестоящего SDK](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly), в котором описана дополнительная конфигурация загрузчика и жизненного цикла. Не инициализируйте оба SDK в одном процессе.

## Миграция с HyperDX Node.js SDK {#migration}

Замените `@hyperdx/node-opentelemetry` на `@clickhouse/clickstack-node` и используйте новую точку входа для регистрации. Замените `HYPERDX_API_KEY` на `OTEL_EXPORTER_OTLP_HEADERS`, указав формат авторизации для вашего пункта назначения, описанный выше.

Новый SDK поддерживает не все вспомогательные функции и параметры HyperDX. Прежде чем заменять интеграции логгеров, обработчики ошибок, пользовательские атрибуты трасс или настройки сэмплирования, ознакомьтесь с [руководством по миграции SDK](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md).
