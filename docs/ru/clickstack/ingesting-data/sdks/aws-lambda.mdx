Для функций Node.js с асинхронными обработчиками используйте ClickStack Node.js SDK. Для других сред выполнения или обработчиков на основе функций обратного вызова используйте слои Lambda для OpenTelemetry, описанные ниже.

## Асинхронные обработчики Node.js {#nodejs-async-handlers}

Используйте среду выполнения Node.js для Lambda, соответствующую минимальным требованиям SDK (Node.js 22.15). Установите SDK и включите его в пакет развертывания:

```shell
npm install @clickhouse/clickstack-node
```

Задайте следующие переменные окружения Lambda, чтобы инициализировать SDK до загрузки обработчика и задать имя сервиса:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

Оберните асинхронный обработчик в `withFlush`, чтобы буферизованная телеметрия успела экспортироваться до завершения вызова:

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

Укажите `index.handler` в качестве обработчика функции. Если вы собираете функцию в bundle, оставьте SDK и инструментированные зависимости внешними и включите их в пакет развертывания. Не подключайте при такой настройке слой Lambda с автоматическим инструментированием.

Задайте приведённые ниже переменные пункта назначения в конфигурации окружения лямбда-функции. Конечная точка должна быть доступна из вашей функции. SDK завершает сброс данных до истечения предельного срока вызова; `withFlush` не поддерживает обработчики на основе функций обратного вызова.

### Настройка пункта назначения {#configure-destination}

Укажите конечную точку OTLP HTTP и ключ ингестии для коллектора ClickStack. Если для коллектора не настроен TLS, используйте `http://`. Сведения о настройке коллектора см. в разделе [Приём данных с помощью OpenTelemetry](/ru/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## Другие среды выполнения и обработчики {#other-runtimes-and-handlers}

Следуйте официальным [инструкциям по автоматическому инструментированию Lambda](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/), чтобы выбрать слои для вашей среды выполнения, архитектуры и региона AWS и настроить обёртку инструментирования.

Добавьте и настройте [слой Lambda для коллектора OpenTelemetry](https://opentelemetry.io/docs/platforms/faas/lambda-collector/). Как описано в вышестоящей документации, экспортеры SDK приложения должны по-прежнему отправлять данные в локальный коллектор. Исходящее соединение коллектора настраивается ниже.

### Настройка пункта назначения для коллектора Lambda {#configure-lambda-collector-destination}

Задайте `CLICKHOUSE_OTLP_ENDPOINT` и `CLICKHOUSE_INGESTION_API_KEY` в переменных окружения вашей лямбда-функции. Добавьте следующий экспортер в конфигурацию коллектора.

Укажите в `CLICKHOUSE_OTLP_ENDPOINT` конечную точку OTLP HTTP вашего коллектора ClickStack, а в `CLICKHOUSE_INGESTION_API_KEY` — его ключ ингестии. Конечная точка должна быть доступна из вашей лямбда-функции.

```yaml
exporters:
  otlphttp/clickhouse:
    endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
    headers:
      Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
```

Укажите `otlphttp/clickhouse` в списке `exporters` каждого конвейера сигналов, данные которого нужно отправлять. Например, с приёмником `otlp` из вышестоящего проекта:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

Добавьте эти настройки в конфигурацию коллектора, сохранив имеющиеся настройки приёмников и процессоров. Упакуйте конфигурацию вместе с функцией и укажите путь к ней в переменной `OPENTELEMETRY_COLLECTOR_CONFIG_URI`, например `/var/task/collector.yaml`, следуя инструкциям по настройке коллектора из вышестоящей документации.

## Проверка ингестии {#verify-ingestion}

Разверните и вызовите функцию. В ClickStack выберите недавний временной диапазон и найдите имя сервиса вашей функции в разделе Traces. Если ваше инструментирование генерирует журналы и метрики, проверьте также разделы Logs и Metrics: добавление конвейера не включает их сбор автоматически.

Сведения о настройке слоя и устранении неполадок см. в [документации OpenTelemetry Lambda](https://github.com/open-telemetry/opentelemetry-lambda).
