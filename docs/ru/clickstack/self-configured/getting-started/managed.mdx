<Note>
  На этой странице описывается **самостоятельно управляемый ClickHouse Observability**. Рекомендуемый полностью управляемый вариант описан в [документации](/ru/clickstack/observability/getting-started).
</Note>

Разверните самостоятельно управляемый ClickHouse Observability в ClickHouse Cloud, отправьте тестовое событие через конвейер ингестии и убедитесь, что оно отображается в интерфейсе обсервабилити.

ClickHouse Cloud обслуживает серверную часть ClickHouse, а контроль над конвейером ингестии и схемой остаётся за вами. Самостоятельно управляемый ClickHouse Observability обеспечивает:

* Автоматическое масштабирование вычислительных ресурсов независимо от хранилища
* Недорогое и практически неограниченное хранение данных благодаря объектному хранилищу
* Изоляцию рабочих нагрузок чтения и записи друг от друга с помощью [хранилищ](/ru/products/cloud/features/infrastructure/warehouses)
* Встроенную аутентификацию
* Автоматическое резервное копирование
* Возможности для обеспечения безопасности и соответствия требованиям
* Бесшовные обновления

## Перед началом работы {#before-you-begin}

Вы также можете отправлять данные напрямую в ClickHouse с помощью одной из [поддерживаемых интеграций](/ru/integrations/home), используя собственную схему.

### Создайте сервис ClickHouse Cloud {#create-a-managed-clickstack-service}

Выполните шаг [Создание сервиса ClickHouse](/ru/get-started/setup/cloud#1-create-a-clickhouse-service) из руководства по быстрому старту ClickHouse Cloud. Прежде чем продолжить, убедитесь, что сервис запущен.

  ### Подготовьте среду для ингестии {#prepare-your-ingestion-environment}

  * Чтобы запустить новый [OpenTelemetry Collector](/ru/clickstack/self-configured/ingesting-data/collector), установите [Docker](https://docs.docker.com/get-docker/). В Kubernetes разверните коллектор с помощью [Helm](/ru/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured).
  * Чтобы использовать существующий коллектор, запустите его в [роли шлюза](/ru/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) и убедитесь, что его дистрибутив включает [экспортер ClickHouse](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter). Необходимую конфигурацию вы добавите по ходу этого руководства.

      [Vector](https://vector.dev) — это высокопроизводительный, независимый от вендоров конвейер данных для обсервабилити, особенно популярный для ингестии логов благодаря гибкости и низкому потреблению ресурсов.

      При использовании Vector схему вы определяете сами. Она может следовать соглашениям OpenTelemetry или включать поля, характерные для ваших событий.

      <Info>
        **Требуется уже настроенный конвейер Vector**

        Следуйте этому руководству, если у вас уже запущен Vector с входным конвейером. Данные, передаваемые через конвейер, должны содержать **столбец временной метки** или эквивалентное поле времени — его нужно будет выбрать при настройке источника данных в интерфейсе обсервабилити.

        Описанные ниже шаги добавляют приёмник ClickHouse в существующий конвейер.
      </Info>

#### Создание базы данных и таблицы {#create-a-vector-database-and-table}

      Перед настройкой приёмника Vector создайте базу данных и таблицу.

      В ClickHouse Cloud откройте консоль SQL вашего сервиса и создайте базу данных:

      Например, создайте базу данных для журналов:

      ```sql
      CREATE DATABASE IF NOT EXISTS logs
      ```

      Затем создайте таблицу, схема которой соответствует структуре ваших логов. В примере ниже используется классический формат журнала доступа Nginx:

      ```sql
      CREATE TABLE logs.nginx_logs
      (
          `time_local` DateTime,
          `remote_addr` IPv4,
          `remote_user` LowCardinality(String),
          `request` String,
          `status` UInt16,
          `body_bytes_sent` UInt64,
          `http_referer` String,
          `http_user_agent` String,
          `http_x_forwarded_for` LowCardinality(String),
          `request_time` Float32,
          `upstream_response_time` Float32,
          `http_host` String
      )
      ENGINE = MergeTree
      ORDER BY (toStartOfMinute(time_local), status, remote_addr);
      ```

      Таблица должна соответствовать выходной схеме, которую формирует Vector. При необходимости адаптируйте схему под свои данные, следуя [рекомендуемым практикам проектирования схемы](/ru/concepts/best-practices/select-data-type).

      Настоятельно рекомендуем разобраться, как работают [первичные ключи](/ru/concepts/core-concepts/primary-indexes) в ClickHouse, и выбрать ключ сортировки с учётом ваших шаблонов доступа. Рекомендации по выбору первичного ключа см. в руководстве по [оптимизации производительности](/ru/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key).

#### Настройка приёмника ClickHouse {#configure-the-vector-clickhouse-sink}

      После создания таблицы добавьте приёмник ClickHouse в конфигурацию Vector:

      ```yaml
      sinks:
        clickhouse:
          type: clickhouse
          inputs:
            - your_input
          endpoint: "https://<host>:8443"
          database: logs
          table: nginx_logs
          format: json_each_row
          skip_unknown_fields: true
          auth:
            strategy: basic
            user: default
            password: "<your_password_here>"
      ```

      Замените `your_input` на input из вашего существующего конвейера. Замените `<host>` и `<your_password_here>` на значения для вашего сервиса ClickHouse Cloud. При необходимости измените целевую базу данных или таблицу.

      <Accordion title="Используйте отдельные учётные данные для ингестии (рекомендуется)">
        Для продакшн-среды создайте отдельного пользователя и предоставьте ему доступ к целевой таблице Vector. В ClickHouse Cloud откройте консоль SQL своего сервиса и выполните:

        ```sql
        CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
        GRANT SELECT, INSERT ON logs.nginx_logs TO `clickstack-ingest`;
        ```

        Замените `default` на `clickstack-ingest` в приёмнике Vector и укажите в `password` пароль выделенного пользователя.
      </Accordion>

      Сохраните обновлённую конфигурацию, затем перезагрузите или перезапустите Vector в рамках используемого вами процесса развертывания.

      Дополнительные примеры ингестии данных с помощью Vector см. в разделе [Загрузка данных с помощью Vector](/ru/clickstack/observability/ingesting-data/vector), а описание расширенных параметров — в [документации по приёмнику ClickHouse для Vector](https://vector.dev/docs/reference/configuration/sinks/clickhouse/).

#### Создание источника данных {#create-a-vector-data-source}

      Создайте источник данных для таблицы, заполняемой вашим конвейером Vector. При первом входе интерфейс предложит вам создать его.

      В форме уже заполнены выражения для стандартной схемы OpenTelemetry. Для таблицы Nginx, созданной в этом руководстве, настройте источник, указав следующие значения:

      | Настройка                                | Значение                                                                                                        |
      | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
      | **Название**                             | `Nginx logs`                                                                                                    |
      | **Тип данных источника**                 | Log                                                                                                             |
      | **Имя подключения к серверу**            | `Default`                                                                                                       |
      | **База данных**                          | `logs`                                                                                                          |
      | **Таблица**                              | `nginx_logs`                                                                                                    |
      | **Столбец временной метки**              | `time_local`                                                                                                    |
      | **SELECT по умолчанию**                  | `time_local, remote_addr, status, request`                                                                      |
      | **Выражение для имени сервиса**          | `'nginx'`                                                                                                       |
      | **Выражение уровня логирования**         | `multiIf(status >= 500, 'ERROR', status >= 400, 'WARN', 'INFO')`                                                |
      | **Log Attributes Expression**            | `map('http.remote_addr', toString(remote_addr), 'http.status_code', toString(status), 'http.request', request)` |
      | **Выражение атрибутов ресурса**          | `map('service.name', 'nginx')`                                                                                  |
      | **Отображаемый столбец временной метки** | `time_local`                                                                                                    |
      | **Выражение идентификатора трассы**      | `''`                                                                                                            |
      | **Выражение ID спана**                   | `''`                                                                                                            |
      | **Выражение неявного столбца**           | `request`                                                                                                       |

      В таблице Nginx нет столбца `Body`. Задайте для **Body Expression** следующее значение:

      ```sql
      concat(
        remote_addr, ' ',
        remote_user, ' ',
        '[', formatDateTime(time_local, '%d/%b/%Y:%H:%i:%S %z'), '] ',
        '"', request, '" ',
        toString(status), ' ',
        toString(body_bytes_sent), ' ',
        '"', http_referer, '" ',
        '"', http_user_agent, '" ',
        '"', http_x_forwarded_for, '" ',
        toString(request_time), ' ',
        toString(upstream_response_time), ' ',
        '"', http_host, '"'
      )
      ```

      Описание других настроек источника см. в [справочнике по конфигурации](/ru/clickstack/self-configured/managing/config).
    </Step>
