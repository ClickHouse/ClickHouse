<Note>
  Эта страница посвящена **самостоятельно управляемому ClickHouse Observability**. Полностью управляемый ClickHouse Observability — рекомендуемый вариант по умолчанию — сам берёт на себя схемы базы данных и сопоставление типов. Для миграции настраивать эти внутренние компоненты не требуется: чтобы начать, воспользуйтесь [руководством по миграции с Elasticsearch](/ru/clickstack/observability/migration/elastic).
</Note>

Elasticsearch и ClickHouse поддерживают широкий спектр типов данных, однако их нижележащее хранилище и модели выполнения запросов принципиально различаются. В этом разделе часто используемые типы полей Elasticsearch сопоставляются с эквивалентами в ClickHouse (при их наличии), а также приводятся пояснения, которые помогут при миграции. Если эквивалента нет, в комментариях указаны альтернативы или примечания.

### Примечания {#notes}

* **Массивы**: в Elasticsearch все поля нативно поддерживают массивы. В ClickHouse массивы нужно определять явно (например, `Array(String)`), зато можно обращаться к конкретным позициям и выполнять по ним запросы, например `an_array[1]`.
* **Multi-fields**: Elasticsearch позволяет индексировать [одно и то же поле несколькими способами](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields#_multi_fields_with_multiple_analyzers) (например, одновременно как `text` и `keyword`). В ClickHouse такой подход реализуется с помощью отдельных столбцов или представлений.
* **Типы Map и JSON** — в ClickHouse тип [`Map`](/ru/reference/data-types/map) обычно используется для моделирования динамических структур «ключ — значение», таких как `resourceAttributes` и `logAttributes`. Этот тип обеспечивает гибкий приём данных без схемы, позволяя добавлять произвольные ключи во время выполнения, — по сути аналогично объектам JSON в Elasticsearch. Однако у него есть важные ограничения:

  * **Единый тип значений**: столбцы [`Map`](/ru/reference/data-types/map) в ClickHouse должны иметь единый тип значений (например, `Map(String, String)`). Значения разных типов не поддерживаются без приведения типов.
  * **Снижение производительности**: обращение к любому ключу в [`Map`](/ru/reference/data-types/map) требует загрузки всего Map в память, что может негативно сказываться на производительности.
  * **Отсутствие подстолбцов**: в отличие от JSON, ключи в [`Map`](/ru/reference/data-types/map) не представлены как полноценные подстолбцы, что ограничивает возможности ClickHouse по эффективному индексированию, сжатию и выполнению запросов.

  Тип [`JSON`](/ru/reference/data-types/newjson) в ClickHouse — альтернатива [`Map`](/ru/reference/data-types/map) для динамических атрибутов, лишённая ряда этих ограничений:

  * **Полноценное столбцовое хранение**: каждый путь JSON хранится как подстолбец, что обеспечивает эффективное сжатие, фильтрацию и векторизованное выполнение запросов.
  * **Поддержка смешанных типов**: значения разных типов данных (например, целые числа, строки, массивы) могут сосуществовать по одному и тому же пути без приведения или унификации типов.
  * **Масштабируемость на уровне файловой системы**: внутренние ограничения на число динамических ключей (`max_dynamic_paths`) и типов (`max_dynamic_types`) предотвращают взрывной рост числа файлов столбцов на диске даже при наборах ключей с высокой мощностью.
  * **Плотное хранение**: значения null и отсутствующие значения хранятся разреженно, что позволяет избежать лишних накладных расходов.

    Тип [`JSON`](/ru/reference/data-types/newjson) особенно хорошо подходит для задач обсервабилити: он сочетает гибкость приёма данных без схемы с производительностью и масштабируемостью нативных типов ClickHouse, что делает его идеальной заменой [`Map`](/ru/reference/data-types/map) для полей с динамическими атрибутами.

    Подробнее о типе JSON см. [руководство по JSON](/ru/guides/clickhouse/data-formats/json/intro) и статью [«How we built a new powerful JSON data type for ClickHouse»](https://clickhouse.com/blog/a-new-powerful-json-data-type-for-clickhouse).
