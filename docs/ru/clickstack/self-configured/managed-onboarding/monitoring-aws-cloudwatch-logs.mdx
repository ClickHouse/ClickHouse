<Note>
  На этой странице описывается **самостоятельно управляемый ClickHouse Observability**. Рекомендуемый полностью управляемый вариант описан в [этой документации](/ru/clickstack/observability/integration-examples/cloudwatch).
</Note>

В этом руководстве описано, как пересылать логи AWS CloudWatch в самостоятельно управляемый ClickHouse Observability с помощью [приёмника `awscloudwatch`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver) OpenTelemetry, а затем просматривать их в интерфейсе ClickStack.

Мы запустим отдельный коллектор, который опрашивает CloudWatch через AWS API и пересылает события в ваш коллектор ClickStack по OTLP. Размещайте этот коллектор в той же учетной записи AWS и в том же регионе, что и группы логов: так задержки при обращении к API и затраты будут минимальными.

Предполагается, что вы уже выполнили шаги из руководства [Настройка коллектора OpenTelemetry](/ru/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) и у вас запущен коллектор ClickStack.

Коллектор ClickStack можно развернуть либо как **Docker-контейнер** (см. [Настройка коллектора OpenTelemetry](/ru/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)), либо как **Helm-релиз** в Kubernetes с помощью вышестоящего Helm-чарта OpenTelemetry и образа коллектора ClickStack (см. [Развертывание коллектора](/ru/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)). **Обязательно сохраните его конечную точку OTLP** и значение `OTLP_AUTH_TOKEN`, заданное при развертывании.

<Steps>
  <Step title="Предварительные требования" id="gather-prerequisites">
    Вам понадобится:

    * **Учетная запись AWS** с одной или несколькими группами журналов CloudWatch и учётные данные с разрешениями IAM, перечисленными ниже.
    * Хост с установленным **Docker**, доступом к AWS API и исходящим сетевым доступом к вашему коллектору ClickStack. Как правило, это инстанс EC2 в той же учетной записи AWS и том же регионе, что и группы журналов.
    * **Конечная точка OTLP** вашего коллектора ClickStack, доступная с этого хоста. Если коллектор запущен в Docker на той же машине, используйте `http://host.docker.internal:4318` (см. информационный блок в разделе [Настройка приёмника CloudWatch](#configure-receiver)). Для удалённого коллектора укажите его полный URL, например `https://otel.example.com:4318`.
    * Значение `OTLP_AUTH_TOKEN`, заданное для вашего коллектора ClickStack. Если вы не настраивали защиту коллектора, заголовок `authorization` можно удалить из приведённой ниже конфигурации.
  </Step>

  <Step title="Настройте учётные данные AWS" id="configure-aws">
    Приёмник берёт учётные данные AWS из стандартных переменных окружения. Экспортируйте их на хосте, где будет запущен коллектор.

    **Для пользователей AWS SSO:**

    ```shell
    aws sso login --profile YOUR_PROFILE_NAME
    eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
    aws sts get-caller-identity
    ```

    **Для пользователей IAM с долгосрочными учётными данными:**

    ```shell
    export AWS_ACCESS_KEY_ID="your-access-key-id"
    export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
    export AWS_REGION="us-east-1"
    aws sts get-caller-identity
    ```

    Для чтения журналов CloudWatch учётным данным необходима следующая политика IAM:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Замените `YOUR_ACCOUNT_ID` на ID вашей учётной записи AWS.

    <Info>
      **Учётные данные для продакшн-среды**

      В продакшн-среде вместо долгосрочных ключей рекомендуется использовать учётные данные, привязанные к инстансу: роль IAM на EC2, IRSA на EKS или роль задачи на ECS. Приведённая ниже конфигурация коллектора работает без переменных окружения с учётными данными, если приёмник может получить их из службы метаданных экземпляра.
    </Info>
  </Step>

  <Step title="Настройте приёмник CloudWatch" id="configure-receiver">
    Экспортируйте конечную точку коллектора ClickStack и токен аутентификации в переменные окружения, затем создайте файл `otel-collector-config.yaml`.

    <Info>
      **Настройка на одном хосте**

      В примере ниже предполагается, что коллектор ClickStack и этот коллектор CloudWatch работают на одном хосте, поэтому приёмник подключается к нему через `host.docker.internal` (адрес хоста Docker изнутри контейнера). Если ваш коллектор ClickStack размещён в другом месте (сервис внутри кластера, публичный URL, частный IP-адрес), укажите его адрес в `OTEL_COLLECTOR_ENDPOINT` ниже.
    </Info>

    ```shell
    export OTEL_COLLECTOR_ENDPOINT="http://host.docker.internal:4318"
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    ```

    <Accordion title="Поиск групп журналов, доступных в вашем аккаунте">
      Прежде чем редактировать конфигурацию, получите список групп журналов в вашем регионе, чтобы выбрать реальные имена (и заодно убедиться, что регион указан верно):

      ```shell
      aws logs describe-log-groups --region eu-central-1 \
        --query 'logGroups[].logGroupName' --output table
      ```

      Пример вывода:

      ```text
      -------------------------------
      |      DescribeLogGroups      |
      +-----------------------------+
      |  /aws-glue/jobs/error       |
      |  /aws-glue/jobs/logs-v2     |
      |  /aws-glue/jobs/output      |
      |  /aws-glue/sessions/error   |
      |  /aws-glue/sessions/output  |
      +-----------------------------+
      ```

      Подставьте имена из этого списка напрямую в блок `groups.named` из примера 1 ниже. Для приведённого выше аккаунта раздел именованных групп будет выглядеть так:

      ```yaml
      groups:
        named:
          /aws-glue/jobs/error:
          /aws-glue/jobs/logs-v2:
          /aws-glue/jobs/output:
          /aws-glue/sessions/error:
          /aws-glue/sessions/output:
      ```

      Если же у нужных групп общий префикс (в данном случае `/aws-glue/`), вместо перечисления групп по отдельности используйте пример 2 с `prefix: /aws-glue/`.
    </Accordion>

    **Пример 1: именованные группы журналов (рекомендуется)**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws-glue/jobs/error:
              /aws-glue/jobs/output:
              /aws-glue/sessions/error:

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    **Пример 2: Автоматическое обнаружение групп журналов по префиксу**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            autodiscover:
              limit: 100
              prefix: /aws-glue/

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    Основные настройки, которые стоит изменить:

    * `region` — регион, в котором находятся ваши группы журналов.
    * `poll_interval` (по умолчанию `1m`). Меньшие значения позволяют получать журналы почти в реальном времени, но увеличивают число вызовов AWS API.
    * `groups.named` — для явного списка групп; `groups.autodiscover.prefix` — чтобы автоматически подхватывать все группы с заданным префиксом.

    Полный список параметров см. в [документации по приёмнику CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver).

    <Info>
      **Только недавние журналы**

      При первом запуске приёмник устанавливает контрольную точку на текущий момент и загружает только журналы, поступившие после неё. Исторические журналы не дозагружаются.
    </Info>
  </Step>

  <Step title="Запустите коллектор с приёмником" id="start-collector">
    Создайте файл `docker-compose.yaml` рядом с `otel-collector-config.yaml`. Запись `extra_hosts` позволяет контейнеру обращаться через `host.docker.internal` к коллектору ClickStack, запущенному на том же хосте. Bind mount в развёрнутом синтаксисе (long-form) явно завершается ошибкой, если файл конфигурации отсутствует, вместо того чтобы молча создать пустой каталог:

    ```shell
    cat > docker-compose.yaml <<'EOF'
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:latest
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_COLLECTOR_ENDPOINT
          - OTLP_AUTH_TOKEN
        extra_hosts:
          - "host.docker.internal:host-gateway"
        restart: unless-stopped
    EOF
    ```

    Запустите коллектор:

    ```shell
    docker compose up -d
    ```

    Отслеживайте его журналы в реальном времени, чтобы убедиться, что он опрашивает CloudWatch и экспортирует данные в ваш коллектор ClickStack:

    ```shell
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Подтвердите в интерфейсе ClickStack" id="confirm-in-ui">
    Откройте свой сервис в [консоли ClickHouse Cloud](https://console.clickhouse.cloud) и выберите **ClickStack** в левом меню.

    <div className="ch-image-lg">
      <Frame>
        ![Запуск ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    В представлении **Search** переключите источник на `Logs` и задайте временной диапазон **Last 15 minutes**. События CloudWatch должны появиться в течение нескольких интервалов опроса.

    <div className="ch-image-lg">
      <Frame>
        ![Представление поиска ClickStack с журналами CloudWatch](/images/clickstack/cloudwatch/log-search-view-clickstack.webp)
      </Frame>
    </div>

    Каждое событие содержит исходные группу и поток журналов в виде атрибутов ресурса:

    * `ResourceAttributes['aws.region']`: регион AWS (например, `eu-central-1`)
    * `ResourceAttributes['cloudwatch.log.group.name']`: исходная группа журналов
    * `ResourceAttributes['cloudwatch.log.stream']`: исходный поток журнала
    * `Body`: исходная строка журнала

    Чтобы отобразить эти атрибуты, измените поиск на `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body`:

    <div className="ch-image-lg">
      <Frame>
        ![Представление поиска ClickStack с журналами CloudWatch и атрибутами](/images/clickstack/cloudwatch/log-search-attributes-clickstack.webp)
      </Frame>
    </div>

    Выберите запись журнала, чтобы просмотреть её метаданные:

    <div className="ch-image-lg">
      <Frame>
        ![Атрибуты CloudWatch в представлении подробных сведений журнала](/images/clickstack/cloudwatch/error-log-column-values-clickstack.webp)
      </Frame>
    </div>

    Если ничего не отображается:

    * Выполните `aws sts get-caller-identity` на хосте коллектора, чтобы убедиться, что учётные данные действительны.
    * Отслеживайте журнал коллектора с помощью `docker compose logs -f otel-collector` и ищите `AccessDeniedException` (IAM), ошибки `security token` (истёк срок действия учётных данных SSO), `ResourceNotFoundException` (опечатка в имени группы журналов или неверный регион) или `connection refused` (конечная точка коллектора ClickStack недоступна изнутри контейнера; см. примечание о `host.docker.internal` в разделе [Настройка приёмника CloudWatch](#configure-receiver)).
    * Убедитесь, что `OTEL_COLLECTOR_ENDPOINT` доступен изнутри контейнера: `docker compose exec otel-collector wget -qO- ${OTEL_COLLECTOR_ENDPOINT}/v1/logs -S 2>&1 | head -5`.
    * Проверьте, что `OTLP_AUTH_TOKEN` совпадает со значением, заданным в коллекторе ClickStack.
  </Step>
