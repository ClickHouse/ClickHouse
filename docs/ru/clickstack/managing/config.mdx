Для каждого компонента ClickStack доступны следующие параметры конфигурации:

<div id="modifying-settings">
  ## Настройки для дистрибутивов с открытым исходным кодом {#modifying-settings}
</div>

### Docker {#docker}

Если вы используете [All in One](/ru/clickstack/deployment/all-in-one), [только интерфейс ClickStack](/ru/clickstack/deployment/hyperdx-only) или [Local Mode](/ru/clickstack/deployment/local-mode-only), просто задайте нужный параметр через переменную окружения, например:

```shell
docker run -e HYPERDX_APP_PORT=8081 -p 8081:8081 -p 4317:4317 -p 4318:4318 clickhouse/clickstack-all-in-one:latest
```

### Docker Compose {#docker-compose}

Если вы используете руководство по развертыванию [Docker Compose](/ru/clickstack/deployment/docker-compose), для изменения настроек можно использовать файл [`.env`](https://github.com/ClickHouse/clickstack/blob/main/.env).

Либо можно явно переопределить настройки в файле [`docker-compose.yml`](https://github.com/ClickHouse/clickstack/blob/main/docker-compose.yml), например:

Пример:

```yaml
services:
  app:
    environment:
      HYPERDX_API_KEY: ${HYPERDX_API_KEY}
      HYPERDX_LOG_LEVEL: ${HYPERDX_LOG_LEVEL}
      # ... other settings
```

### Helm {#helm}

Воспользуйтесь [руководством по развертыванию с помощью Helm](/ru/clickstack/deployment/helm), чтобы установить операторы и чарт ClickStack. Перед настройкой развертывания получите текущие значения чарта:

```shell
helm show values clickstack/clickstack > values.yaml
```

Задайте окружение приложения и коллектора по отдельности с помощью значений чарта, затем примените конфигурацию:

```shell
helm upgrade --install my-clickstack clickstack/clickstack -f values.yaml
```

Поддерживаемые значения, а также настройки Ingress, ресурсов и Secret описаны в разделе [Конфигурация Helm](/ru/clickstack/deployment/helm-configuration). У более старого Helm-чарта `hyperdx/hdx-oss-v2` другая структура значений.

## Приложение интерфейса ClickStack {#hyperdx}

### Соединения {#connection-settings}

Соединение с базой данных, которое используют ваши источники, настраивается в Team Settings.

| Настройка                  | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Connection Name`          | Имя, под которым это соединение отображается в настройках источника.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `Host`                     | HTTP(S)-конечная точка ClickHouse с указанием порта. Не путайте её с конечной точкой экспорта коллектора.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `Username`                 | Имя пользователя ClickHouse; по умолчанию — `default`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `Password`                 | Пароль ClickHouse; по умолчанию пустой.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `Query Log Setting Prefix` | Необязательный префикс для пользовательской настройки ClickHouse, с помощью которой адрес электронной почты текущего пользователя записывается в журнал запросов. Этот же префикс необходимо добавить в параметр конфигурации ClickHouse `custom_settings_prefixes`, иначе запросы будут отклоняться. Чтобы определить, какая панель мониторинга, оповещение или другая возможность ClickStack отправила запрос, не прибегая к идентификаторам пользователей, см. раздел [Как определить источники нагрузки от запросов](/ru/clickstack/managing/performance-tuning#query-attribution). |

### Настройки источника данных {#datasource-settings}

Интерфейс ClickStack предполагает, что пользователь задаёт источник для каждого из типов/основных сигналов данных обсервабилити:

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

Эту конфигурацию можно выполнить в приложении через `Team Settings -> Sources`, как показано ниже на примере журналов:

<div className="ch-image-md">
  <Frame>
    ![Конфигурация источника в интерфейсе ClickStack](/images/use-cases/observability/hyperdx-25.webp)
  </Frame>
</div>

Для каждого источника нужно задать сопоставления таблиц и столбцов, чтобы интерфейс ClickStack мог выполнять запросы к его данным. Источники метрик могут использовать отдельные таблицы для разных типов метрик. Переключатель `Enabled` появляется при редактировании существующего источника; параметр `Query Settings` на уровне источника принимает до десяти пар «имя/значение».

Если используется [стандартная схема OpenTelemetry (OTel)](/ru/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema), поставляемая с ClickStack, эти столбцы могут быть автоматически определены для каждого источника. Если [схема изменена](#clickhouse) или используется пользовательская схема, пользователи должны указать и обновлять эти сопоставления вручную.

<Note>
  Коллектор создаёт таблицы с помощью миграций схемы или устаревшего механизма создания схемы силами экспортера — в зависимости от его [конфигурации схемы](#collector-schema-and-retention). Сопоставления столбцов соответствуют соглашениям OpenTelemetry, включая [модель данных журналов](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
</Note>

| `Minimum Date`           | Необязательно. Самые ранние дата и время, за которые представление содержит данные. #### Выделенные Атрибуты {#highlighted-attributes}

Выделенные Атрибуты и Highlighted Trace Attributes можно настроить для источников данных Log и Trace.

* Выделенные Атрибуты — это столбцы или выражения, которые отображаются для каждого лога или спана при просмотре сведений о логе или спане.
* Highlighted Trace Attributes — это столбцы или выражения, которые запрашиваются для каждого лога или спана в трассе и отображаются над waterfall-диаграммой трассы.

Эти атрибуты задаются в конфигурации источника и могут быть произвольными SQL-выражениями. Если SQL-выражение возвращает значение в формате URL, атрибут будет отображаться как ссылка. Пустые значения не показываются.

Каждый атрибут настраивается с помощью следующих параметров:

| Настройка           | Описание                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `SQL Expression`    | Столбец или произвольное SQL-выражение для запроса. Обязательно.                                    |
| `Alias`             | Необязательно. Метка, отображаемая для атрибута вместо SQL-выражения.                               |
| `Lucene Expression` | Необязательно. Версия SQL-выражения для Lucene, используемая при поиске по значению этого атрибута. |

### Коррелированные источники {#correlated-sources}

Чтобы включить полную корреляцию между источниками в ClickStack, необходимо настроить коррелированные источники для журналов, трасс, метрик и сеансов. Это позволит интерфейсу ClickStack связывать связанные данные и предоставлять более полный контекст при отображении событий.

* `Logs`: Можно коррелировать с трассами и метриками.
* `Traces`: Можно коррелировать с журналами, сеансами и метриками.
* `Metrics`: Можно коррелировать с журналами.
* `Sessions`: Можно коррелировать с трассами.

Настройка этих корреляций включает несколько возможностей. Например, интерфейс ClickStack может отображать соответствующие журналы рядом с трассой или показывать аномалии метрик, связанные с сеансом.

Настройки среды выполнения, считываемые через `next-runtime-env`, например `NEXT_PUBLIC_INSTANCE_LABEL`, могут быть заданы для контейнера при запуске.

| `HYPERDX_OTEL_EXPORTER_LOGS_TTL`               | `HYPERDX_OTEL_EXPORTER_TABLES_TTL`            | Срок хранения журналов для таблиц, управляемых миграциями.                                                                                                                                                                                                                                          |

TTL для отдельных сигналов и настройка реконсиляции применяются инструментом миграций, который не запускается, если включено устаревшее создание схемы.

### TLS для миграции {#collector-migration-tls}

Эти переменные задают параметры подключения инструмента миграции к ClickHouse. TLS для экспортеров они автоматически не настраивают: при использовании пользовательских сертификатов настройте экспортеры коллектора отдельно.

| Переменная                            | По умолчанию | Описание                                                                                                 |
| ------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------- |
| `CLICKHOUSE_TLS_CA_FILE`              | Не задано    | Путь к файлу CA‑сертификата.                                                                             |
| `CLICKHOUSE_TLS_CERT_FILE`            | Не задано    | Путь к клиентскому сертификату для взаимного TLS.                                                        |
| `CLICKHOUSE_TLS_KEY_FILE`             | Не задано    | Путь к закрытому ключу клиента для взаимного TLS.                                                        |
| `CLICKHOUSE_TLS_SERVER_NAME_OVERRIDE` | Не задано    | Имя сервера для проверки сертификата.                                                                    |
| `CLICKHOUSE_TLS_INSECURE_SKIP_VERIFY` | `false`      | При значении `true` отключает проверку сертификата сервера. Используйте только для устранения неполадок. |

<div id="clickhouse">
  ## ClickHouse {#clickhouse}
</div>

ClickStack с открытым исходным кодом поставляется с конфигурацией ClickHouse по умолчанию, рассчитанной на масштаб в несколько терабайт, но пользователи могут свободно изменять и оптимизировать её под свою рабочую нагрузку.

Чтобы эффективно настраивать ClickHouse, важно понимать ключевые концепции хранения, такие как [части](/ru/concepts/core-concepts/parts), [партиции](/ru/concepts/core-concepts/partitions), [сегменты и реплики](/ru/guides/oss/deployment-and-scaling/shards), а также то, как происходят [слияния](/ru/concepts/core-concepts/merges) в момент вставки. Мы рекомендуем ознакомиться с основами [первичных индексов](/ru/concepts/core-concepts/primary-indexes), [разреженных вторичных индексов](/ru/concepts/features/performance/skip-indexes/skipping-indexes) и индексов пропуска данных, а также с методами [управления жизненным циклом данных](/ru/guides/use-cases/observability/build-your-own/managing-data), например с использованием TTL.

ClickStack поддерживает [настройку схемы](/ru/guides/use-cases/observability/build-your-own/schema-design) — вы можете изменять типы столбцов, извлекать новые поля (например, из журналов), применять кодеки и словари, а также ускорять запросы с помощью проекций.

Кроме того, materialized views можно использовать для [преобразования или фильтрации данных во время ингестии](/ru/guides/use-cases/observability/build-your-own/schema-design#materialized-columns) при условии, что данные записываются в исходную таблицу этого представления, а приложение читает из целевой таблицы. Materialized views также можно использовать для [ускорения запросов встроенными средствами](/ru/clickstack/managing/materialized-views) в ClickStack.

Подробнее см. в документации ClickHouse по проектированию схемы, стратегиям индексирования и рекомендациям по управлению данными — большинство из них напрямую применимы к развертываниям ClickStack.
