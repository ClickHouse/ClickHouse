<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#108869](https://github.com/ClickHouse/ClickHouse/issues/108869): Исправлено аварийное завершение сервера во время `RESTORE` резервных копий, содержащих таблицы с циклическими зависимостями. [#103824](https://github.com/ClickHouse/ClickHouse/pull/103824) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Бэкпортировано в [#108903](https://github.com/ClickHouse/ClickHouse/issues/108903): Исправлена логическая ошибка (`Unexpected return type from equals. Expected Nullable(UInt8). Got UInt8`), возникавшая, когда оптимизация push-down для дизъюнкции (частичного предиката) проталкивала условие через ключ `USING`, тип которого расширялся из-за JOIN. Также исправлен сбой сервера (segmentation fault) в analyzer при разрешении идентификаторов в запросах `JOIN ... USING`, содержащих поддающиеся константной свёртке ветви `if`/`multiIf`, ссылающиеся на неизвестные идентификаторы. [#107407](https://github.com/ClickHouse/ClickHouse/pull/107407) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#108643](https://github.com/ClickHouse/ClickHouse/issues/108643): Исправлен `RESTORE` для таблиц `ReplicatedMergeTree`, чтобы части с дублирующимся содержимым из резервной копии сохранялись, а не молча дедуплицировались. [#107652](https://github.com/ClickHouse/ClickHouse/pull/107652) ([Pablo Marcos](https://github.com/pamarcos)).
* Бэкпортировано в [#108748](https://github.com/ClickHouse/ClickHouse/issues/108748): Запросы векторного поиска, выполняющие SELECT из столбца `_distance`, теперь возвращают корректную ошибку вместо сбоя с `LOGICAL_ERROR`. [#108423](https://github.com/ClickHouse/ClickHouse/pull/108423) ([Robert Schulze](https://github.com/rschu1ze)).
* Бэкпортировано в [#108667](https://github.com/ClickHouse/ClickHouse/issues/108667): Исправлено прямое чтение из нескольких частично материализованных текстовых индексов. [#108607](https://github.com/ClickHouse/ClickHouse/pull/108607) ([Anton Popov](https://github.com/CurtizJ)).
* Бэкпортировано в [#108825](https://github.com/ClickHouse/ClickHouse/issues/108825): Исправлена ситуация, при которой отсечение по партициям и первичному ключу молча отключалось, если ключевой столбец типа `LowCardinality(FixedString)` (или `LowCardinality(Nullable(FixedString))`) был обёрнут в функцию в ключе, например `PARTITION BY sipHash64(k) % N` с `WHERE k = 'literal'`. Такие запросы сканировали все партиции вместо их отсечения. [#108777](https://github.com/ClickHouse/ClickHouse/pull/108777) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#108907](https://github.com/ClickHouse/ClickHouse/issues/108907): Исправлено поведение, при котором `insert_quorum = 'auto'` не отклонял вставки сразу, если в живых оставалось меньше большинства реплик. Теперь такие вставки немедленно завершаются ошибкой `TOO_FEW_LIVE_REPLICAS` вместо записи локальной части и последующего тайм-аута с `UNKNOWN_STATUS_OF_INSERT`. [#108800](https://github.com/ClickHouse/ClickHouse/pull/108800) ([Gagan Dhakrey](https://github.com/gagandhakrey)).
