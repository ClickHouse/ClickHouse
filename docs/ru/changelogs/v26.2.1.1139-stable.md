<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Улучшен формат хранения статистики. Теперь вся статистика хранится в одном файле. [#93414](https://github.com/ClickHouse/ClickHouse/pull/93414) ([Anton Popov](https://github.com/CurtizJ)).
* Ограничен объем метаданных S3(Azure)Queue, хранящихся в памяти. Системные таблицы переименованы из `azure_queue` в `azure_queue_metadata_cache` и из `system.s3queue` в `s3queue_metadata_cache`. [#95809](https://github.com/ClickHouse/ClickHouse/pull/95809) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Исправлена логическая ошибка при несоответствии типов `Variant`. [#95811](https://github.com/ClickHouse/ClickHouse/pull/95811) ([Bharat Nallan](https://github.com/bharatnc)).
* BREAKING CHANGE: с этим изменением дедупликация по умолчанию включена для всех вставок. Ранее она была отключена для async inserts и материализованных представлений, но была включена для синхронных вставок. Цель — сделать значения по умолчанию одинаковыми для обоих способов вставки. Если в вашем кластере дедупликация явно отключена, необходимо явно установить `deduplicate_insert='backward_compatible_choice'`, чтобы сохранить прежнее поведение. То же самое относится к `deduplicate_blocks_in_dependent_materialized_views`. [#95970](https://github.com/ClickHouse/ClickHouse/pull/95970) ([Sema Checherinda](https://github.com/CheSema)).
* Столбцы `DATE` из PostgreSQL теперь определяются как `Date32` в ClickHouse (в предыдущих версиях они определялись как `Date`, что приводило к переполнению значений за пределами узкого диапазона). Разрешена вставка значений `Date32` обратно в PostgreSQL. Закрывает [#73084](https://github.com/ClickHouse/ClickHouse/issues/73084). [#95999](https://github.com/ClickHouse/ClickHouse/pull/95999) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Семантика настройки `do_not_merge_across_partitions_select_final` стала понятнее. Ранее эта возможность могла автоматически включаться, если настройка не была явно задана в конфигурации. Это неоднократно вызывало путаницу и, к сожалению, приводило к проблемам в продакшне. Теперь правила проще: `do_not_merge_across_partitions_select_final=1` безусловно включает эту функциональность. Если `do_not_merge_across_partitions_select_final=0`, то автоматический режим используется только при `enable_automatic_decision_for_merging_across_partitions_for_final=1`, а в противном случае не используется. Чтобы максимально сохранить прежнее поведение, значения по умолчанию установлены как `do_not_merge_across_partitions_select_final=0` и `enable_automatic_decision_for_merging_across_partitions_for_final=1`. [#96110](https://github.com/ClickHouse/ClickHouse/pull/96110) ([Nikita Taranov](https://github.com/nickitat)).
* Добавлена валидация схемы S3. Это закрывает [#96089](https://github.com/ClickHouse/ClickHouse/issues/96089). [#96194](https://github.com/ClickHouse/ClickHouse/pull/96194) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Запрещено использовать подзапросы в ORDER BY и других выражениях ключа таблицы. [#96847](https://github.com/ClickHouse/ClickHouse/pull/96847) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `apply_row_policy_after_final` теперь включен по умолчанию. Изначально, когда `optimize_move_to_prewhere_if_final=0`, и ROW POLICY, и PREWHERE учитывали FINAL и применялись после FINAL. Это было нарушено в [#87303](https://github.com/ClickHouse/ClickHouse/issues/87303), где для фильтра ROW POLICY игнорировался `optimize_move_to_prewhere_if_final`. Чтобы это исправить, этот PR включает настройку `apply_row_policy_after_final`, представленную в [#91065](https://github.com/ClickHouse/ClickHouse/issues/91065). При включенном `apply_row_policy_after_final` ROW POLICY, как и раньше, по умолчанию продолжает учитывать FINAL. Этот PR является несовместимым изменением, потому что меняет поведение для `optimize_move_to_prewhere_if_final=1`. Теперь, чтобы ROW POLICY применялся до FINAL, следует использовать `apply_row_policy_after_final` вместо `optimize_move_to_prewhere_if_final`. [#97279](https://github.com/ClickHouse/ClickHouse/pull/97279) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

* Добавлена поддержка одноразовых паролей на основе времени как метода аутентификации. [#71273](https://github.com/ClickHouse/ClickHouse/pull/71273) ([Vladimir Cherkasov](https://github.com/vdimir)).

* Добавлена настройка default&#95;dictionary&#95;database, которая позволяет ClickHouse разрешать внешние словари, на которые ссылаются без указания базы данных, в указанной базе данных по умолчанию. Это упрощает миграцию с глобальных словарей, определённых в XML, на словари уровня базы данных, определённые в SQL, — позволяя существующим запросам к словарям (например, dictGet(&#39;name&#39;, …)) продолжать работать без изменений. [#91412](https://github.com/ClickHouse/ClickHouse/pull/91412) ([Dmitrii Plotnikov](https://github.com/dimbo4ka)).
* Добавлена поддержка auxiliary ZooKeeper для `DatabaseReplicated`. [#91683](https://github.com/ClickHouse/ClickHouse/pull/91683) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* Реализованы новая табличная функция `primes` и новая системная таблица `system.primes`, содержащая простые числа в порядке возрастания. Закрывает [#90839](https://github.com/ClickHouse/ClickHouse/issues/90839). [#92776](https://github.com/ClickHouse/ClickHouse/pull/92776) ([Nihal Z. Miaji](https://github.com/nihalzp)).

Если обнаруживаются дубликаты, запрос ожидает, пока ранее вставленные данные также не будут реплицированы. [#93356](https://github.com/ClickHouse/ClickHouse/pull/93356) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлены функции `colorOKLABToSRGB` и `colorSRGBToOKLAB` для преобразования значений из sRGB в OKLAB и обратно. [#93361](https://github.com/ClickHouse/ClickHouse/pull/93361) ([Pranav Tiwari](https://github.com/pranavt84)).
* Добавлен новый `deduplicate&#95;insert`, который переопределяет `insert&#95;deduplicate` и `async&#95;insert&#95;deduplicate`. [#94413](https://github.com/ClickHouse/ClickHouse/pull/94413) ([Sema Checherinda](https://github.com/CheSema)).
* В SQL разрешено использовать некоторые функции без скобок. Закрывает [#52102](https://github.com/ClickHouse/ClickHouse/issues/52102). [#94678](https://github.com/ClickHouse/ClickHouse/pull/94678) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* Настройка сервера `insert_deduplication_version` позволяет перейти на унифицированный hash дедупликации. [#95409](https://github.com/ClickHouse/ClickHouse/pull/95409) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлены новые параметры конфигурации: logger.startup&#95;console&#95;level и logger.shutdown&#95;console&#95;level, позволяющие переопределять уровень логирования консоли во время запуска и завершения работы ClickHouse соответственно. [#95919](https://github.com/ClickHouse/ClickHouse/pull/95919) ([Garrett Thomas](https://github.com/garrettthomaskth)).

Это может быть полезно для тестирования: проверки корректности слияний в новой версии, детерминированного воспроизведения ошибок, связанных со слияниями, и надежного бенчмаркинга производительности слияний. [#96122](https://github.com/ClickHouse/ClickHouse/pull/96122) ([Anton Popov](https://github.com/CurtizJ)).

* Добавлена настройка базы данных `lazy_load_tables`. Когда она включена, таблицы не загружаются при запуске базы данных — вместо этого создается легковесный `StorageTableProxy`, а реальный движок таблицы материализуется при первом обращении. <div id="performance-improvement">
  #### Повышение производительности
</div>

* Ускорение некоторых операций hash join за счёт реализации dynamic dispatch для ColumnVector::replicate. [#79573](https://github.com/ClickHouse/ClickHouse/pull/79573) ([Raúl Marín](https://github.com/Algunenano)).
* Повышение производительности ParallelHashJoin при сложных предикатах. Ранее строки, не вошедшие в JOIN, обрабатывались в одном потоке, что неоптимально; суть оптимизации — распараллелить их обработку между несколькими потоками. Управляется настройкой `parallel_non_joined_rows_processing`. Включено по умолчанию. [#92068](https://github.com/ClickHouse/ClickHouse/pull/92068) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Теперь любое детерминированное выражение в первичном ключе может использоваться для пропуска данных (например, `ORDER BY cityHash64(user_id)` / `ORDER BY length(user_id)`). Для детерминированных выражений ClickHouse может применить выражение к константам запроса и использовать результат в индексе первичного ключа для предикатов `=`, `IN` и `has`. Если выражение также является инъективным (например, `ORDER BY hex(p)` или `ORDER BY reverse(tuple(reverse(p), hex(p)))`), индекс можно эффективно использовать и для отрицаний: `!=`, `NOT IN` и `NOT has`. Closes [#10685](https://github.com/ClickHouse/ClickHouse/issues/10685). Closes [#82161](https://github.com/ClickHouse/ClickHouse/issues/82161). [#92952](https://github.com/ClickHouse/ClickHouse/pull/92952) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Незначительная оптимизация парсинга типа JSON. [#93614](https://github.com/ClickHouse/ClickHouse/pull/93614) ([Pavel Kruglov](https://github.com/Avogar)).
* Уменьшение потребления памяти ASTLiteral за счёт удаления полей std::optional<TokenIterator> begin/end из объекта. Оптимизация оправдана, поскольку эти поля не используются при отключённой подсветке синтаксиса и отсутствии парсинга VALUES. [#93974](https://github.com/ClickHouse/ClickHouse/pull/93974) ([Ilya Yatsishin](https://github.com/qoega)).
* Оптимизация потребления памяти AST-объектами именованных кортежей. Имена столбцов теперь хранятся как строки непосредственно в объекте кортежа, а не в обобщённых узлах AST-литералов. [#94704](https://github.com/ClickHouse/ClickHouse/pull/94704) ([Ilya Yatsishin](https://github.com/qoega)).
* Улучшена девиртуализация за счёт дополнительных опций компоновщика. [#94737](https://github.com/ClickHouse/ClickHouse/pull/94737) ([Nikita Taranov](https://github.com/nickitat)).
* Повышение производительности клонирования реплики для таблиц ReplicatedMergeTree с большим количеством частей за счёт пакетной отправки запросов к ZooKeeper. [#94847](https://github.com/ClickHouse/ClickHouse/pull/94847) ([c-end](https://github.com/c-end)).
* Если запрос с `FINAL` использовал условие первичного ключа для фильтрации, а затем индексы пропуска данных для остальных условий, шаг обработки `PrimaryKeyExpand` теперь проверяет пересечение только в рамках предварительно отобранных диапазонов первичного ключа. [#94903](https://github.com/ClickHouse/ClickHouse/pull/94903) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Создание std::vector вынесено за пределы цикла `for` с предварительным выделением памяти. Это позволяет избежать выделения памяти на каждой итерации. [#95178](https://github.com/ClickHouse/ClickHouse/pull/95178) ([Alexey Bakharew](https://github.com/alexbakharew)).
* Если шаг чтения уже содержит фильтры PREWHERE, добавить новый фильтр невозможно. Данное изменение откладывает оптимизацию PREWHERE до завершения оптимизации runtime-фильтров JOIN, что позволяет проталкивать runtime-фильтры в PREWHERE. [#95838](https://github.com/ClickHouse/ClickHouse/pull/95838) ([Alexander Gololobov](https://github.com/davenger)).
* Ускорение сжатия кодеком T64 за счёт использования dynamic dispatch на x86. [#95881](https://github.com/ClickHouse/ClickHouse/pull/95881) ([Raúl Marín](https://github.com/Algunenano)).
* Ускорение `uniq` для числовых типов за счёт пакетной обработки вставок там, где это возможно (не null, не -If, без GROUP BY, без IPv6 или String). [#95904](https://github.com/ClickHouse/ClickHouse/pull/95904) ([Raúl Marín](https://github.com/Algunenano)).
* Было установлено, что `ZooKeeper::observeOperations` потребляет более 20% процессорного времени потока приёма ZooKeeper. Данное изменение устраняет это следующим образом: 1. Для `AggregatedZooKeeperLog::stats` вместо `SipHash` используется `CityHash64`, который работает более чем в 10 раз быстрее. 2. Для `Coordination::ErrorCounter` вместо `std::unordered_map` и `std::mutex` используется `std::array<std::atomic<UInt32>, N>`. [#95962](https://github.com/ClickHouse/ClickHouse/pull/95962) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Отмена 64-байтового выравнивания для ProfileEvents::Counter. [#96097](https://github.com/ClickHouse/ClickHouse/pull/96097) ([Azat Khuzhin](https://github.com/azat)).
* Уменьшение размера структуры CachedOnDiskReadBufferFromFile в 50 раз. [#96098](https://github.com/ClickHouse/ClickHouse/pull/96098) ([Azat Khuzhin](https://github.com/azat)).
* Отказ от копирования старых данных при HashTable::resize, если таблица пуста. [#96180](https://github.com/ClickHouse/ClickHouse/pull/96180) ([Raúl Marín](https://github.com/Algunenano)).
* Поддержка runtime-фильтров JOIN для `RIGHT OUTER` JOIN. [#96183](https://github.com/ClickHouse/ClickHouse/pull/96183) ([Hechem Selmi](https://github.com/m-selmi)).
* Ранее оптимизация прямого чтения с использованием текстового индекса применялась только в том случае, если все части содержали материализованный текстовый индекс. Данное изменение добавляет частичную поддержку: если текстовый индекс материализован лишь в некоторых частях, эти части будут его использовать, тогда как части без материализованного текстового индекса будут выполнять исходное выражение фильтра. [#96411](https://github.com/ClickHouse/ClickHouse/pull/96411) ([Anton Popov](https://github.com/CurtizJ)).
* Устранение регрессии потребления памяти при операциях INSERT, когда дедупликация отключена. [#96503](https://github.com/ClickHouse/ClickHouse/pull/96503) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Отказ от подключения заголовков boost/multiprecision в `wide_integer_impl.h` на платформах с достаточной поддержкой `long double`, что сокращает время сборки. TODO: CHANGE CATEGORY TO BUILD IF PERFORMANCE DOES NOT CHANGE. [#96633](https://github.com/ClickHouse/ClickHouse/pull/96633) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

[#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* В системные таблицы журналов добавлены вторичные индексы `minmax` для столбцов времени и индексы `bloom_filter` для столбцов `query_id`/`initial_query_id` с целью ускорения фильтрации.
