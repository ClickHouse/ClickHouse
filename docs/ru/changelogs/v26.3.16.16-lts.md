<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#108281](https://github.com/ClickHouse/ClickHouse/issues/108281): учетные данные в строках подключения JDBC, ODBC и NATS теперь маскируются в журнале запросов и выводе `SHOW CREATE`, что предотвращает случайное раскрытие конфиденциальной информации. В строках подключения в формате URI (например, {scheme}://{user}:{password}@{host}) маскируется только пароль, а остальная часть остается видимой для удобства отладки. Параметр `nats_token` теперь тоже маскируется. [#99344](https://github.com/ClickHouse/ClickHouse/pull/99344) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#108446](https://github.com/ClickHouse/ClickHouse/issues/108446): Исправлено неверное количество строк из `arrayJoin()`, используемого внутри `JOIN ON`: результат дополнительно умножался на длину массива. [#104785](https://github.com/ClickHouse/ClickHouse/pull/104785) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Бэкпортировано в [#107482](https://github.com/ClickHouse/ClickHouse/issues/107482): Исправлено Исключение, возникавшее, когда запрос векторного поиска использует векторный индекс и другой индекс пропуска данных, например `minmax`, при `use_skip_indexes_on_data_read = 1`. [#106473](https://github.com/ClickHouse/ClickHouse/pull/106473) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Бэкпортировано в [#108259](https://github.com/ClickHouse/ClickHouse/issues/108259): Исправлена ошибка &quot;Too many marks&quot; для text index на пустой слитой части. [#106867](https://github.com/ClickHouse/ClickHouse/pull/106867) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#108170](https://github.com/ClickHouse/ClickHouse/issues/108170): Исправлена logical error `Block structure mismatch in UnionStep stream` (аварийное завершение сервера на debug/sanitizer-сборках, `Code: 49` на релизных сборках), возникавшая, когда одна ветка `UNION`/`INTERSECT`/`EXCEPT` читала столбец, сериализованный как `Sparse`, а соседняя ветка — тот же столбец как полный (например, при отправке в materialized view). [#107041](https://github.com/ClickHouse/ClickHouse/pull/107041) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#108222](https://github.com/ClickHouse/ClickHouse/issues/108222): Исправлено переполнение буфера кучи (сбой сервера) в `windowFunnel` при финализации специально сформированного состояния агрегатной функции с типом события вне допустимого диапазона; проблема была доступна любому пользователю через единственный `SELECT`. [#107412](https://github.com/ClickHouse/ClickHouse/pull/107412) ([uwezkhan](https://github.com/uwezkhan)).
* Бэкпортировано в [#108501](https://github.com/ClickHouse/ClickHouse/issues/108501): Свежий снимок, пересобранный внутри `update()`, уже захватывает текущие учетные данные C++ S3 client через `createBuilder`; теперь он сохраняется, а не отбрасывается при совпадении version, чтобы следующая операция ядра выполнялась на движке со свежими учетными данными и не переживала TTL STS. [#107480](https://github.com/ClickHouse/ClickHouse/pull/107480) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Бэкпортировано в [#108638](https://github.com/ClickHouse/ClickHouse/issues/108638): Исправлен `RESTORE` для таблиц `ReplicatedMergeTree`, чтобы части с дублирующимся содержимым из backup сохранялись, а не молча дедуплицировались. [#107652](https://github.com/ClickHouse/ClickHouse/pull/107652) ([Pablo Marcos](https://github.com/pamarcos)).
* Бэкпортировано в [#108203](https://github.com/ClickHouse/ClickHouse/issues/108203): Исправлено поведение, при котором set-индекс пропуска данных не отбрасывал гранулы по столбцам `LowCardinality`. [#107868](https://github.com/ClickHouse/ClickHouse/pull/107868) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Бэкпортировано в [#108304](https://github.com/ClickHouse/ClickHouse/issues/108304): Исправлен сбой (SIGSEGV в релизных сборках, assertion о несоответствии типов в debug-сборках) в `has` для `Map` с ключом `Dynamic`, когда argument для lookup имеет тип `LowCardinality`, например `has(map('a'::Dynamic, ...), toLowCardinality('b'))`. [#107956](https://github.com/ClickHouse/ClickHouse/pull/107956) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#108196](https://github.com/ClickHouse/ClickHouse/issues/108196): Теперь handlers, вызываемые по завершении батча кэша доступа, запускаются всегда, даже для пустого батча. [#108124](https://github.com/ClickHouse/ClickHouse/pull/108124) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#108320](https://github.com/ClickHouse/ClickHouse/issues/108320): исправлено зависание refreshable materialized view, если в неподходящий момент теряется соединение с ZooKeeper. [#108234](https://github.com/ClickHouse/ClickHouse/pull/108234) ([Michael Kolupaev](https://github.com/al13n321)).
* Бэкпортировано в [#108481](https://github.com/ClickHouse/ClickHouse/issues/108481): скрыты секретные аргументы функций, таких как `encrypt`, `decrypt` и `HMAC`, в выводе `EXPLAIN actions`, `EXPLAIN header` и `EXPLAIN PIPELINE`, когда `format_display_secrets_in_show_and_select` отключён (по умолчанию). [#108386](https://github.com/ClickHouse/ClickHouse/pull/108386) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#108693](https://github.com/ClickHouse/ClickHouse/issues/108693): исправлено раскрытие метаданных, из-за которого `DESCRIBE loop('db', 'table')` и `DESCRIBE loop(<inner table function>)` обходили проверку доступа `SHOW COLUMNS` / к источнику, позволяя непривилегированному пользователю читать схему столбцов таблицы. [#108624](https://github.com/ClickHouse/ClickHouse/pull/108624) ([Groene AI](https://github.com/groeneai)).
