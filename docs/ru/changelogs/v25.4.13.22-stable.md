<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#84033](https://github.com/ClickHouse/ClickHouse/issues/84033): использовать информацию из cgroup (если применимо, то есть если доступен параметр `memory_worker_use_cgroup` и сами cgroups) для корректировки трекера памяти (`memory_worker_correct_memory_tracker`). [#83981](https://github.com/ClickHouse/ClickHouse/pull/83981) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#83140](https://github.com/ClickHouse/ClickHouse/issues/83140): Не использовать несвязанные части общего словаря в функции `lowCardinalityKeys`. [#83118](https://github.com/ClickHouse/ClickHouse/pull/83118) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#84105](https://github.com/ClickHouse/ClickHouse/issues/84105): Скрывать данные authentication в Avro schema registry, чтобы они не были видны пользователю и не попадали в журналы. [#83713](https://github.com/ClickHouse/ClickHouse/pull/83713) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#83913](https://github.com/ClickHouse/ClickHouse/issues/83913): Исправлена проблема, из-за которой, если таблица семейства MergeTree создана с `add_minmax_index_for_numeric_columns=1` или `add_minmax_index_for_string_columns=1`, а индекс позже materialize во время операции ALTER, база данных Replicated не может корректно инициализироваться на новой реплике. [#83751](https://github.com/ClickHouse/ClickHouse/pull/83751) ([Nikolay Degterinsky](https://github.com/evillique)).
* Бэкпортировано в [#83872](https://github.com/ClickHouse/ClickHouse/issues/83872): Добавлена настройка backward compatibility, позволяющая новому analyzer ссылаться на внешний alias в конструкции WITH при конфликте имён. Исправляет [#82700](https://github.com/ClickHouse/ClickHouse/issues/82700). [#83797](https://github.com/ClickHouse/ClickHouse/pull/83797) ([Dmitry Novik](https://github.com/novikd)).
* Бэкпортировано в [#84090](https://github.com/ClickHouse/ClickHouse/issues/84090): При восстановлении из резервной копии пользователь, указанный как definer, может не попасть в резервную копию, из-за чего она целиком становится непригодной. Чтобы это исправить, проверка разрешений при создании целевой таблицы во время restore откладывается и выполняется только во время runtime. [#83818](https://github.com/ClickHouse/ClickHouse/pull/83818) ([pufit](https://github.com/pufit)).
* Бэкпортировано в [#84268](https://github.com/ClickHouse/ClickHouse/issues/84268): Исправлены неверные результаты при использовании кэша условий запроса вместе с рекурсивными CTE (проблема [#81506](https://github.com/ClickHouse/ClickHouse/issues/81506)). [#84026](https://github.com/ClickHouse/ClickHouse/pull/84026) ([zhongyuankai](https://github.com/zhongyuankai)).

<div id="not-for-changelog-insignificant">
  #### НЕ ДЛЯ CHANGELOG / НЕЗНАЧИТЕЛЬНО

* Бэкпортировано в [#83862](https://github.com/ClickHouse/ClickHouse/issues/83862): разрешено параллельное создание таблиц, если значение настройки `max_database_replicated_create_table_thread_pool_size` равно 0 (автоматический размер пула). [#83834](https://github.com/ClickHouse/ClickHouse/pull/83834) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Перенесён [#79124](https://github.com/ClickHouse/ClickHouse/issues/79124) в 25.4: чтобы избежать дублирования в реализациях MergeTreeIndexCondition::alwaysUnknownOrTrue. [#84152](https://github.com/ClickHouse/ClickHouse/pull/84152) ([Elmi Ahmadov](https://github.com/ahmadov)).
