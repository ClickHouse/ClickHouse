<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Незначительное: для настроек сервера backup&#95;threads и restore&#95;threads теперь принудительно задаются ненулевые значения. [#80224](https://github.com/ClickHouse/ClickHouse/pull/80224) ([Raúl Marín](https://github.com/Algunenano)).
* Исправлена функция bitNot() для String: теперь она возвращает строку с завершающим нулём. [#80791](https://github.com/ClickHouse/ClickHouse/pull/80791) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#82079](https://github.com/ClickHouse/ClickHouse/issues/82079): ранее функция `countMatches` прекращала подсчёт на первом пустом совпадении, даже если шаблон регулярного выражения его допускает. Чтобы устранить эту проблему, `countMatches` теперь продолжает выполнение, сдвигаясь на один символ вперёд при пустом совпадении. Пользователи, которые хотят сохранить прежнее поведение, могут включить настройку `count_matches_stop_at_empty_match`. [#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Существующая реализация `Pipe::resize` создает единственный узел `Resize` или `StrictResize`, вставляя его в топологию конвейера, после чего он выступает центральным узлом, соединяющим все входные потоки (upstream nodes) с единым набором выходных потоков (downstream nodes). Такая архитектура приводит к конкуренции за ` ExecutingGraph::Node::status_mutex` во время выполнения графа конвейера, особенно в средах с большим количеством ядер. Когда конвейеры масштабируются до десятков или сотен потоков, эта конкуренция приводит к следующему:. [#77562](https://github.com/ClickHouse/ClickHouse/pull/77562) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Бэкпортировано в [#81959](https://github.com/ClickHouse/ClickHouse/issues/81959): добавлена возможность переносить (де)сжатие и (де)сериализацию блоков в потоки конвейера вместо одного потока, связанного с сетевым соединением. Управляется настройкой `enable_parallel_blocks_marshalling`. Это должно ускорить распределённые запросы, которые передают значительные объемы данных между инициатором и удалёнными узлами. [#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* Запросы DELETE FROM ... WHERE 1 заменены на TRUNCATE. (Отменено). [#78739](https://github.com/ClickHouse/ClickHouse/pull/78739) ([scanhex12](https://github.com/scanhex12)).
* Повышение производительности всех типов bloom filter. [#79800](https://github.com/ClickHouse/ClickHouse/pull/79800) ([Delyan Kratunov](https://github.com/dkratunov)).
* В `UniqExactSet::merge` добавлен оптимальный сценарий для случая, когда одно из множеств пусто. Кроме того, если множество LHS двухуровневое, а RHS — одноуровневое, преобразование RHS в двухуровневое больше не выполняется. [#79971](https://github.com/ClickHouse/ClickHouse/pull/79971) ([Nikita Taranov](https://github.com/nickitat)).
* По умолчанию логирование сделано асинхронным. Это можно отключить, установив `<async>false</async>` в разделе `<logger>`. [#80125](https://github.com/ClickHouse/ClickHouse/pull/80125) ([Raúl Marín](https://github.com/Algunenano)).
* Повышена эффективность повторного использования памяти и уменьшено количество page fault при использовании двухуровневых хеш-таблиц. [#80245](https://github.com/ClickHouse/ClickHouse/pull/80245) ([Jiebin Sun](https://github.com/jiebinn)).
* Устранены лишние обновления и снижена конкуренция за блокировки в QueryConditionCache. [#80247](https://github.com/ClickHouse/ClickHouse/pull/80247) ([Jiebin Sun](https://github.com/jiebinn)).
* Небольшая оптимизация в `concatenateBlocks`. Возможно, это полезно для параллельного hash JOIN. [#80328](https://github.com/ClickHouse/ClickHouse/pull/80328) ([李扬](https://github.com/taiyang-li)).
* При выборе mark ranges из диапазона primary key двоичный поиск нельзя использовать, если primary key обёрнут функциями. Этот PR смягчает это ограничение: двоичный поиск всё ещё можно применять, когда primary key обёрнут в цепочку всегда монотонных функций или когда RPN содержит элемент, который всегда истинен. Этот PR закрывает [#45536](https://github.com/ClickHouse/ClickHouse/issues/45536). [#80597](https://github.com/ClickHouse/ClickHouse/pull/80597) ([zoomxi](https://github.com/zoomxi)).
* Ускорено завершение работы Kafka engine (убрана лишняя задержка в 3 секунды в случае нескольких таблиц Kafka). [#80796](https://github.com/ClickHouse/ClickHouse/pull/80796) ([Azat Khuzhin](https://github.com/azat)).
* Async insert: уменьшено использование памяти и повышена производительность запросов вставки. [#80972](https://github.com/ClickHouse/ClickHouse/pull/80972) ([Raúl Marín](https://github.com/Algunenano)).
* Не профилировать processors, если таблица Log отключена. [#81256](https://github.com/ClickHouse/ClickHouse/pull/81256) ([Raúl Marín](https://github.com/Algunenano)).
* Ускорен `toFixedString`, когда источник в точности соответствует запрошенному. [#81257](https://github.com/ClickHouse/ClickHouse/pull/81257) ([Raúl Marín](https://github.com/Algunenano)).
* Значения квот не обрабатываются, если для пользователя не заданы ограничения. [#81549](https://github.com/ClickHouse/ClickHouse/pull/81549) ([Raúl Marín](https://github.com/Algunenano)).
* ProcfsMetricsProvider сделан `thread_local`, чтобы файлы оставались открытыми между задачами. [#81576](https://github.com/ClickHouse/ClickHouse/pull/81576) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### Улучшения
</div>

* `EXPLAIN SYNTAX` теперь использует новый анализатор. Он возвращает AST, построенное на основе Query Tree. Добавлена опция `query_tree_passes` для управления количеством проходов, выполняемых перед преобразованием Query Tree в AST. [#74536](https://github.com/ClickHouse/ClickHouse/pull/74536) ([Vladimir Cherkasov](https://github.com/vdimir)).

* После ошибки `AuthenticationRequired` учетные данные S3 обновляются. [#77353](https://github.com/ClickHouse/ClickHouse/pull/77353) ([Vitaly Baranov](https://github.com/vitlibar)).
* В `system.asynchronous_metrics` добавлены метрики словарей: `DictionaryMaxUpdateDelay` — максимальная задержка обновления словаря (в секундах). `DictionaryTotalFailedUpdates` — количество ошибок с момента последней успешной загрузки во всех словарях. [#78175](https://github.com/ClickHouse/ClickHouse/pull/78175) ([Vlad](https://github.com/codeworse)).
* Улучшена оптимизация ключа сегментирования в распределенных запросах. [#78452](https://github.com/ClickHouse/ClickHouse/pull/78452) ([fhw12345](https://github.com/fhw12345)).
* Для StorageKafka2 реализована логика, аналогичная перебалансировке Kafka, с использованием ClickHouse Keeper. Для каждой реплики поддерживаются два типа блокировок партиций: постоянные и временные. Реплика старается удерживать постоянные блокировки как можно дольше; в любой момент времени на реплике имеется не более `all_topic_partitions / active_replicas_count` постоянных блокировок (где `all_topic_partitions` — количество всех партиций, а `active_replicas_count` — количество активных реплик). Если их больше, реплика освобождает часть партиций. Часть партиций реплика удерживает временно. Максимальное количество временных блокировок на реплике динамически изменяется, чтобы дать другим репликам возможность перевести часть партиций в постоянные блокировки. При обновлении временных блокировок реплика освобождает их все и снова пытается захватить некоторые из них. [#78726](https://github.com/ClickHouse/ClickHouse/pull/78726) ([Daria Fomina](https://github.com/sinfillo)).
* Добавлено предупреждение о базах данных, которые могли быть созданы для сохранения поврежденных таблиц. [#78841](https://github.com/ClickHouse/ClickHouse/pull/78841) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).

* Настройки, управляющие разрывом соединения при перегрузке CPU, теперь можно применять без перезапуска. [#79052](https://github.com/ClickHouse/ClickHouse/pull/79052) ([Alexey Katsman](https://github.com/alexkats)).
* К путям к данным, отображаемым в system.tables для обычных дисков в Azure Blob Storage, добавлен префикс контейнера, что делает отображение согласованным с S3 и GCP. [#79241](https://github.com/ClickHouse/ClickHouse/pull/79241) ([Julia Kartseva](https://github.com/jkartseva)).
* Теперь ClickHouse также принимает параметры запроса в виде `param-<name>` (дефис) наряду с `param_<name>` (подчеркивание). Это закрывает [#63093](https://github.com/ClickHouse/ClickHouse/issues/63093). [#79429](https://github.com/ClickHouse/ClickHouse/pull/79429) ([Engel Danila](https://github.com/aaaengel)).
