<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Бэкпортировано в [#106045](https://github.com/ClickHouse/ClickHouse/issues/106045): настройка `show_data_lake_catalogs_in_system_tables` была переименована в `show_remote_databases_in_system_tables`, а её область действия расширена: когда её значение равно 0 (по умолчанию), базы данных `MySQL` и `PostgreSQL` также скрываются из `system.tables`, `system.columns` и `system.completions` наряду с каталогами озёр данных. Старое имя настройки сохранено как псевдоним. [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="new-feature">
  #### Новая возможность
</div>

* Бэкпортировано в [#104562](https://github.com/ClickHouse/ClickHouse/issues/104562): добавлены запросы `SYSTEM PAUSE VIEW [db.]name` и `SYSTEM PAUSE VIEWS` для refreshable materialized view. В отличие от `SYSTEM STOP VIEW`, `SYSTEM PAUSE VIEW` не прерывает текущее обновление — уже запущенному обновлению даётся завершиться, а блокируются только последующие обновления. Действие отменяется с помощью `SYSTEM START VIEW` или `SYSTEM START VIEWS`, которые теперь единообразно сбрасывают состояния stopped и paused. [#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#105589](https://github.com/ClickHouse/ClickHouse/issues/105589): Replicated refreshable materialized view в режиме APPEND больше не будет обновляться дважды, если во время обновления соединение с ZooKeeper ненадолго прерывалось. [#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)).

* Бэкпортировано в [#105074](https://github.com/ClickHouse/ClickHouse/issues/105074): Исправлено поведение, при котором `materialize_skip_indexes_on_merge=false` не подавлял текстовые (полнотекстовые) индексы во время слияния. Ранее подавлялись только нетекстовые индексы пропуска данных (minmax, set, bloom&#95;filter); текстовые индексы продолжали строиться, впустую расходуя CPU и I/O. * Бэкпортировано в [#105510](https://github.com/ClickHouse/ClickHouse/issues/105510): Теперь генерируется `INCORRECT_DATA` вместо `LOGICAL_ERROR`, если предоставленные клиентом данные в формате Native обрезаны или повреждены. * Бэкпортировано в [#105673](https://github.com/ClickHouse/ClickHouse/issues/105673): Исправлено игнорирование `cast_string_to_date_time_mode` для `CAST` в `Nullable(DateTime)`. Закрывает [#101840](https://github.com/ClickHouse/ClickHouse/issues/101840). [#103035](https://github.com/ClickHouse/ClickHouse/pull/103035) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#105802](https://github.com/ClickHouse/ClickHouse/issues/105802): Исправлена порча данных при записи Parquet (и других форматов с завершающим блоком, таких как ORC и Arrow) в HDFS через `INSERT INTO FUNCTION hdfs(...)`. Начиная с 26.1, `WriteBufferFromHDFS` не сбрасывал рабочий буфер при `finalize()`, поэтому последние `DBMS_DEFAULT_BUFFER_SIZE` байт или меньше в каждом файле молча терялись, включая футер Parquet `PAR1`. При чтении таких файлов возвращалась ошибка `Not a Parquet file (wrong magic bytes at the end of file)`. [#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105668](https://github.com/ClickHouse/ClickHouse/issues/105668): Длительно выполняющиеся `INSERT ... SELECT` и другие чтения из базы данных `DataLakeCatalog` с `catalog_type = 'glue'` завершаются ошибкой `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)`, как только истекает срок действия учетных данных сеанса STS, зафиксированных в момент загрузки метаданных таблицы. [#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Бэкпортировано в [#105977](https://github.com/ClickHouse/ClickHouse/issues/105977): Исправлено Исключение `BAD_ARGUMENTS` &quot;It&#39;s a bug! Only integer types are supported by `__bitWrapperFunc`&quot;, которое возникало, когда в `SELECT` с индексом пропуска данных `TYPE set(N)` атом в предложении WHERE имел тип результата `Float`, `BFloat16` или любой другой нецелочисленный тип (например, `WHERE c0 + 0.1` или `WHERE log(c0)`). В таких случаях индекс пропуска данных теперь переключается на обычный путь фильтрации. [#105384](https://github.com/ClickHouse/ClickHouse/pull/105384) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105880](https://github.com/ClickHouse/ClickHouse/issues/105880): Исправлено поведение `dictGetOrDefault`, из-за которого возникало `CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN`, когда аргумент по умолчанию является выражением `Nullable`, включен `short_circuit_function_evaluation`, и используется смесь найденных и ненайденных ключей словаря. [#105461](https://github.com/ClickHouse/ClickHouse/pull/105461) ([Raúl Marín](https://github.com/Algunenano)).

WITH ROLLUP`, `WITH CUBE` или `WITH TOTALS` и аргументом `Nullable`. [#105470](https://github.com/ClickHouse/ClickHouse/pull/105470) ([Groene AI](https://github.com/groeneai)).

Закрывает [#103630](https://github.com/ClickHouse/ClickHouse/issues/103630). [#105535](https://github.com/ClickHouse/ClickHouse/pull/105535) ([Pavel Kruglov](https://github.com/Avogar)).
