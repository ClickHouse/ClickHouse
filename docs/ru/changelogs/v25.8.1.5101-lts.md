<div id="clickhouse-release-v25815101-lts-4f2b50b8c92-fixme-as-compared-to-v25811-new-d4d4c9f77fa">
  ### Релиз ClickHouse v25.8.1.5101-lts (4f2b50b8c92) FIXME по сравнению с v25.8.1.1-new (d4d4c9f77fa)
</div>

<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* По умолчанию отключено заключение 64-битных целых чисел в кавычки в JSON-форматах. [#74079](https://github.com/ClickHouse/ClickHouse/pull/74079) ([Pavel Kruglov](https://github.com/Avogar)).
* Для массивов значений разных типов в JSON теперь выводится `Array(Dynamic)` вместо unnamed `Tuple`. Чтобы использовать прежнее поведение, отключите настройку `input_format_json_infer_array_of_dynamic_from_array_of_different_types`. [#80859](https://github.com/ClickHouse/ClickHouse/pull/80859) ([Pavel Kruglov](https://github.com/Avogar)).
* Метрики задержки S3 перенесены в гистограммы для единообразия и простоты. [#82305](https://github.com/ClickHouse/ClickHouse/pull/82305) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Для идентификаторов с точками в выражениях `default` теперь требуются обратные кавычки, чтобы они не разбирались как составные идентификаторы. [#83162](https://github.com/ClickHouse/ClickHouse/pull/83162) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Lazy materialization включена только вместе с analyzer, чтобы избежать необходимости поддерживать режим без analyzer, который, по нашему опыту, имеет некоторые проблемы (например, при использовании `indexHint()` в условиях). [#83791](https://github.com/ClickHouse/ClickHouse/pull/83791) ([Igor Nikonov](https://github.com/devcrafter)).
* Значения типа `Enum` по умолчанию записываются как `BYTE_ARRAY` с logical type `ENUM` в выходном формате Parquet. [#84169](https://github.com/ClickHouse/ClickHouse/pull/84169) ([Pavel Kruglov](https://github.com/Avogar)).
* По умолчанию включена настройка MergeTree `write_marks_for_substreams_in_compact_parts`. Это значительно повышает производительность чтения подстолбцов из вновь созданных Compact parts. Серверы с версией ниже 25.5 не смогут читать новые Compact parts. [#84171](https://github.com/ClickHouse/ClickHouse/pull/84171) ([Pavel Kruglov](https://github.com/Avogar)).
* Ранее значением по умолчанию для `concurrent_threads_scheduler` было `round_robin`, но этот вариант оказался несправедливым при большом количестве однопоточных запросов (например, INSERT). Это изменение делает более безопасный вариант — scheduler `fair_round_robin` — значением по умолчанию. [#84747](https://github.com/ClickHouse/ClickHouse/pull/84747) ([Sergei Trifonov](https://github.com/serxa)).
* ClickHouse поддерживает синтаксис Heredoc в стиле PostgreSQL: `$tag$ string contents... $tag$`, также известный как строковые литералы с dollar-quoting. В предыдущих версиях для тегов было меньше ограничений: они могли содержать произвольные символы, включая знаки пунктуации и пробелы. Это создает неоднозначность при парсинге идентификаторов, которые тоже могут начинаться со знака доллара. При этом PostgreSQL допускает в тегах только символы слова. Чтобы решить эту проблему, теперь мы ограничиваем теги Heredoc только символами слова. Закрывает [#84731](https://github.com/ClickHouse/ClickHouse/issues/84731). [#84846](https://github.com/ClickHouse/ClickHouse/pull/84846) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Функции `azureBlobStorage`, `deltaLakeAzure` и `icebergAzure` были обновлены для корректной проверки разрешений `AZURE`. Все варианты функций для cluster (функции `-Cluster`) теперь проверяют разрешения относительно соответствующих некластерных функций. Кроме того, функции `icebergLocal` и `deltaLakeLocal` теперь также проверяют разрешение `FILE`. [#84938](https://github.com/ClickHouse/ClickHouse/pull/84938) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* По умолчанию включена настройка `allow_dynamic_metadata_for_data_lakes` (настройка уровня движка таблицы). [#85044](https://github.com/ClickHouse/ClickHouse/pull/85044) ([Daniil Ivanik](https://github.com/divanik)).

<div id="new-feature">
  #### Новая возможность
</div>

* Не только таблицы Merge, но и все таблицы поддерживают виртуальный столбец &#95;table. [#63665](https://github.com/ClickHouse/ClickHouse/pull/63665) ([Xiaozhe Yu](https://github.com/wudidapaopao)).
* Добавлена системная таблица для хранения ошибочных входящих сообщений от движков, таких как kafka. [#68873](https://github.com/ClickHouse/ClickHouse/pull/68873) ([Ilya Golshtein](https://github.com/ilejn)).
* Этот PR добавляет функциональность restore database replica для реплицируемых баз данных, аналогичную существующей функциональности restore в ReplicatedMergeTree. [#73100](https://github.com/ClickHouse/ClickHouse/pull/73100) ([Konstantin Morozov](https://github.com/k-morozov)).
* Реализована поддержка протокола [ArrowFlight RPC](https://arrow.apache.org/docs/format/Flight.html) за счет добавления: - новой table function `arrowflight()`: `SELECT * FROM arrowflight('host:port', 'dataset_name')`. [#74184](https://github.com/ClickHouse/ClickHouse/pull/74184) ([zakr600](https://github.com/zakr600)).
* Добавлена поддержка команды `COPY` протокола PostgreSQL. [#74344](https://github.com/ClickHouse/ClickHouse/pull/74344) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Добавлена базовая поддержка диалекта PromQL. Чтобы использовать её, задайте `dialect='promql'` в клиенте ClickHouse, укажите таблицу TimeSeries с помощью настройки `promql_table_name='X'` и выполняйте запросы вида `rate(ClickHouseProfileEvents_ReadCompressedBytes[1m])[5m:1m]`. Кроме того, можно обернуть запрос PromQL в SQL: `SELECT * FROM prometheusQuery('up', ...);`. Пока поддерживаются только функции `rate`, `delta` и `increase`. Унарные и бинарные операторы не поддерживаются. HTTP API отсутствует. [#75036](https://github.com/ClickHouse/ClickHouse/pull/75036) ([Vitaly Baranov](https://github.com/vitlibar)).
* Добавлена поддержка записи в стиле hive partition и переработана реализация чтения (столбцы партиции hive больше не являются виртуальными). [#76802](https://github.com/ClickHouse/ClickHouse/pull/76802) ([Arthur Passos](https://github.com/arthurpassos)).
* Добавлена системная таблица `zookeeper_connection_log` для хранения исторической информации о соединениях с ZooKeeper. [#79494](https://github.com/ClickHouse/ClickHouse/pull/79494) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Настройка сервера `cpu_slot_preemption` включает вытесняющее планирование CPU для рабочих нагрузок и обеспечивает справедливое max-min распределение CPU time между рабочими нагрузками. Добавлены новые настройки рабочей нагрузки для ограничения CPU: `max_cpus`, `max_cpu_share` и `max_burst_cpu_seconds`. Подробнее: [https://clickhouse.com/docs/operations/workload-scheduling#cpu&#95;scheduling](https://clickhouse.com/docs/operations/workload-scheduling#cpu_scheduling). [#80879](https://github.com/ClickHouse/ClickHouse/pull/80879) ([Sergei Trifonov](https://github.com/serxa)).
* Разрывать TCP-соединение после достижения заданного количества запросов или порогового времени. Исправляет [#68000](https://github.com/ClickHouse/ClickHouse/issues/68000). [#81472](https://github.com/ClickHouse/ClickHouse/pull/81472) ([Kenny Sun](https://github.com/hwabis)).
* Реализовано чтение из проекций для параллельных реплик. Для управления включением поддержки проекций добавлена новая настройка `parallel_replicas_support_projection`. Для упрощения реализации поддержка проекций включается только при активной настройке `parallel_replicas_local_plan`. [#82807](https://github.com/ClickHouse/ClickHouse/pull/82807) ([zoomxi](https://github.com/zoomxi)).
* Добавлена поддержка DESCRIBE SELECT в дополнение к DESCRIBE (SELECT ...). [#82947](https://github.com/ClickHouse/ClickHouse/pull/82947) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Принудительно использовать защищенное соединение для mysql&#95;port и postgresql&#95;port. [#82962](https://github.com/ClickHouse/ClickHouse/pull/82962) ([tiandiwonder](https://github.com/tiandiwonder)).
* Добавлена поддержка позиционных удалений для Iceberg TableEngine. [#83094](https://github.com/ClickHouse/ClickHouse/pull/83094) ([Daniil Ivanik](https://github.com/divanik)).
* Теперь пользователи могут выполнять регистронезависимый поиск по JSON-ключам с помощью `JSONExtractCaseInsensitive` (и других вариантов `JSONExtract`). [#83770](https://github.com/ClickHouse/ClickHouse/pull/83770) ([Alistair Evans](https://github.com/alistairjevans)).
* Генерация SQL с помощью ИИ теперь может автоматически использовать переменные окружения ANTHROPIC&#95;API&#95;KEY и OPENAI&#95;API&#95;KEY, если они доступны, что позволяет использовать эту возможность без дополнительной настройки. [#83787](https://github.com/ClickHouse/ClickHouse/pull/83787) ([Kaushik Iska](https://github.com/iskakaushik)).
* Представлена таблица `system.completions`. Закрывает [#81889](https://github.com/ClickHouse/ClickHouse/issues/81889). [#83833](https://github.com/ClickHouse/ClickHouse/pull/83833) ([|2ustam](https://github.com/RuS2m)).
* Добавлена запись в Iceberg при CREATE. Закрывает [#83927](https://github.com/ClickHouse/ClickHouse/issues/83927). [#83983](https://github.com/ClickHouse/ClickHouse/pull/83983) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Добавлена поддержка каталогов Glue для записи. [#84136](https://github.com/ClickHouse/ClickHouse/pull/84136) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Добавлена новая функция `nowInBlock64`. Пример использования: `SELECT nowInBlock64(6)` возвращает `2025-07-29 17:09:37.775725`. [#84178](https://github.com/ClickHouse/ClickHouse/pull/84178) ([Halersson Paris](https://github.com/halersson)).
* В AzureBlobStorage добавлены extra&#95;credentials для аутентификации с помощью client&#95;id и tenant&#95;id. [#84235](https://github.com/ClickHouse/ClickHouse/pull/84235) ([Pablo Marcos](https://github.com/pamarcos)).

Пример использования: `SELECT dateTimeToUUIDv7(toDateTime('2025-08-15 18:57:56'))` возвращает `0198af18-8320-7a7d-abd3-358db23b9d5c`. <div id="performance-improvement">
  #### Повышение производительности
</div>

* Движок таблицы `azureBlobStorage`: по возможности кэшировать и повторно использовать токены аутентификации управляемой идентичности, чтобы избежать throttling. [#79860](https://github.com/ClickHouse/ClickHouse/pull/79860) ([Nick Blakely](https://github.com/niblak)).
* Добавлена новая логика (управляется настройкой `enable_producing_buckets_out_of_order_in_aggregation`, включена по умолчанию), которая позволяет отправлять некоторые бакеты не по порядку во время агрегации с эффективным использованием памяти. Когда слияние одних бакетов агрегации занимает значительно больше времени, чем других, это повышает производительность, поскольку initiator может тем временем сливать бакеты с более высокими идентификаторами. Недостаток — потенциально более высокое использование памяти (не должно быть существенным). [#80179](https://github.com/ClickHouse/ClickHouse/pull/80179) ([Nikita Taranov](https://github.com/nickitat)).
* Новая реализация ридера Parquet. В целом она быстрее и поддерживает pushdown фильтра на уровне страниц и PREWHERE. В настоящее время экспериментальная. Для включения используйте настройку `input_format_parquet_use_native_reader_v3`. [#82789](https://github.com/ClickHouse/ClickHouse/pull/82789) ([Michael Kolupaev](https://github.com/al13n321)).
* Обработка `max_joined_block_rows` вынесена за пределы основного цикла hash JOIN. Это немного повышает производительность для ALL JOIN. [#83216](https://github.com/ClickHouse/ClickHouse/pull/83216) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* curl http client заменен на poco http client для Azure Blob Storage. Добавлено несколько настроек для этих clients, повторяющих настройки из S3. Для Azure и S3 введены агрессивные тайм-ауты соединения. Улучшена introspection событий профиля и метрик Azure. Новый client включен по умолчанию и обеспечивает значительно меньшие latencies для холодных queries поверх Azure Blob Storage. Старый client `Curl` можно вернуть, установив `azure_sdk_use_native_client=false`. [#83294](https://github.com/ClickHouse/ClickHouse/pull/83294) ([alesapin](https://github.com/alesapin)).
* Значительно улучшена производительность чтения подстолбцов `JSON` из общих данных в MergeTree за счет реализации новых форматов serialization для общих данных `JSON` в MergeTree. [#83777](https://github.com/ClickHouse/ClickHouse/pull/83777) ([Pavel Kruglov](https://github.com/Avogar)).
* Сначала обрабатываются min-max индексы с более высокой granularity. Закрывает [#75381](https://github.com/ClickHouse/ClickHouse/issues/75381). [#83798](https://github.com/ClickHouse/ClickHouse/pull/83798) ([Maruth Goyal](https://github.com/maruthgoyal)).
* Запросы векторного поиска, использующие индекс векторного сходства, выполняются с меньшей latency благодаря сокращению чтений из хранилища и снижению CPU usage. [#83803](https://github.com/ClickHouse/ClickHouse/pull/83803) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Реализован addManyDefaults для combinators If. [#83870](https://github.com/ClickHouse/ClickHouse/pull/83870) ([Raúl Marín](https://github.com/Algunenano)).
* Сериализованный столбец ключа теперь вычисляется в столбцовом формате при Group By по нескольким строковым или числовым столбцам. [#83884](https://github.com/ClickHouse/ClickHouse/pull/83884) ([李扬](https://github.com/taiyang-li)).
* Попытка использовать `-falign-functions=64` для более стабильных тестов производительности. [#83920](https://github.com/ClickHouse/ClickHouse/pull/83920) ([Azat Khuzhin](https://github.com/azat)).
* Индекс bloom filter теперь используется для условий вида `has([c1, c2, ...], column)`, где `column` не имеет тип `Array`. Это улучшает производительность таких queries, делая их столь же эффективными, как оператор `IN`. [#83945](https://github.com/ClickHouse/ClickHouse/pull/83945) ([Doron David](https://github.com/dorki)).
* Сокращено количество лишних вызовов memcpy в CompressedReadBufferBase::readCompressedData. [#83986](https://github.com/ClickHouse/ClickHouse/pull/83986) ([Raúl Marín](https://github.com/Algunenano)).
* `All` `LEFT/INNER` JOIN будут автоматически преобразовываться в `RightAny`, если правая сторона функционально определяется столбцами ключа JOIN (все строки имеют уникальные значения ключа JOIN). [#84010](https://github.com/ClickHouse/ClickHouse/pull/84010) ([Nikita Taranov](https://github.com/nickitat)).
* Индексы обрабатываются в порядке возрастания размера файла. Итоговый порядок индексов отдает приоритет minmax- и векторным индексам (соответственно из-за простоты и селективности), а затем — небольшим индексам. Внутри minmax- и векторных индексов также предпочтение отдается индексам меньшего размера. [#84094](https://github.com/ClickHouse/ClickHouse/pull/84094) ([Maruth Goyal](https://github.com/maruthgoyal)).
* Оптимизирован `largestTriangleThreeBuckets` за счет удаления временных данных. [#84479](https://github.com/ClickHouse/ClickHouse/pull/84479) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Оптимизирована десериализация строк за счет упрощения кода. Закрывает [#38564](https://github.com/ClickHouse/ClickHouse/issues/38564). [#84561](https://github.com/ClickHouse/ClickHouse/pull/84561) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Удален нулевой байт. Закрывает [#85062](https://github.com/ClickHouse/ClickHouse/issues/85062). Исправлено несколько мелких ошибок. Функции `structureToProtobufSchema` и `structureToCapnProtoSchema` некорректно добавляли завершающий нулевой байт и использовали вместо него символ новой строки. Это приводило к отсутствию символа новой строки в выводе и могло вызывать переполнение буфера при использовании других функций, зависящих от нулевого байта (таких как `logTrace`, `demangle`, `extractURLParameter`, `toStringCutToZero` и `encrypt`/`decrypt`). Функция `stem` содержала ошибку в обеспечении безопасности исключений, которая в очень редком сценарии могла приводить к утечке памяти. Функция `initcap` работала неправильно для аргументов `FixedString`: она не распознавала начало слова в начале строки, если предыдущая строка в block заканчивалась символом слова. Исправлена уязвимость безопасности формата Apache `ORC`, которая могла приводить к раскрытию неинициализированной памяти. Изменено поведение функции `replaceRegexpAll` и соответствующего псевдонима `REGEXP_REPLACE`: теперь она может выполнять пустое совпадение в конце строки, даже если предыдущее совпадение обработало всю строку, например в случае `^a*|a*$` или `^|.*` — это соответствует семантике JavaScript, Perl, Python, PHP и Ruby, но отличается от семантики PostgreSQL. Реализация многих функций была упрощена и оптимизирована. Документация для нескольких функций была некорректной и теперь исправлена. Имейте в виду, что вывод `byteSize` для String-столбцов и сложных типов, состоящих из String-столбцов, изменился (с 9 байт на пустую строку до 8 байт на пустую строку), и это нормально. [#85063](https://github.com/ClickHouse/ClickHouse/pull/85063) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
