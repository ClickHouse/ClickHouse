<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#104736](https://github.com/ClickHouse/ClickHouse/issues/104736): Когда включены apply&#95;row&#95;policy&#95;after&#95;final или apply&#95;prewhere&#95;after&#95;final, составные условия с AND в политиках строк и `PREWHERE` теперь разбиваются, чтобы извлечь атомарные условия по ключу сортировки для анализа индекса первичного ключа. Раньше, если отложенный фильтр содержал смесь предикатов по ключу сортировки и не по ключу сортировки (например, x &gt; 1 AND y != &#39;foo&#39;), всё выражение исключалось из анализа индекса. Теперь атомарные условия по ключу сортировки (например, x &gt; 1) извлекаются и используются для отсечения гранул, в том числе из вложенных выражений с AND. [#98513](https://github.com/ClickHouse/ClickHouse/pull/98513) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Бэкпортировано в [#104933](https://github.com/ClickHouse/ClickHouse/issues/104933): Больше не откладывается применение политики строк после `FINAL`, если она зависит только от столбцов ключа сортировки и является детерминированной; также в этом случае больше не откладывается связанный `PREWHERE`, к чему раньше приводила политика строк. [#102884](https://github.com/ClickHouse/ClickHouse/pull/102884) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Бэкпортировано в [#104323](https://github.com/ClickHouse/ClickHouse/issues/104323): Replicated refreshable materialized view в режиме APPEND больше не будет обновляться дважды, если во время обновления соединение с ZooKeeper было ненадолго потеряно. [#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)).
* Бэкпортировано в [#104700](https://github.com/ClickHouse/ClickHouse/issues/104700): Исправлено исключение в &#96;lowerUTF8&#96; / &#96;upperUTF8&#96; при обработке больших наборов данных с не-ASCII-символами (например, при сборке текстовых индексов), когда накопленный буфер вывода превышал 2 GiB; чрезмерно длинные отдельные строки теперь отклоняются с понятной ошибкой. [#104229](https://github.com/ClickHouse/ClickHouse/pull/104229) ([Shaohua Wang](https://github.com/tiandiwonder)).

[#98242](https://github.com/ClickHouse/ClickHouse/pull/98242) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

[#103708](https://github.com/ClickHouse/ClickHouse/pull/103708) ([Anton Popov](https://github.com/CurtizJ)).

Медленный путь (без JIT) этой проблеме не был подвержен. Обходной путь для затронутых версий: `SET compile_expressions = 0`.
