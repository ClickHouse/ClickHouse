<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Исправлено непоследовательное форматирование, вызванное некорректной подстановкой псевдонимов в форматтере. Закрывает [#82833](https://github.com/ClickHouse/ClickHouse/issues/82833). Закрывает [#82832](https://github.com/ClickHouse/ClickHouse/issues/82832). Закрывает [#68296](https://github.com/ClickHouse/ClickHouse/issues/68296). Данное изменение потенциально является обратно несовместимым: при отключённом анализаторе некоторые запросы CREATE VIEW с IN, ссылающимся на псевдоним, не могут быть обработаны. Чтобы избежать несовместимости, включите анализатор (по умолчанию он включён начиная с версии 24.3). [#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Кодеки `DEFLATE_QPL` и `ZSTD_QAT` удалены. Перед обновлением рекомендуется конвертировать существующие данные, сжатые с помощью `DEFLATE_QPL` или `ZSTD_QAT`, в другой кодек. Обратите внимание, что для использования этих кодеков необходимо было включить настройки `enable_deflate_qpl_codec` и `enable_zstd_qat_codec`. [#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze)).
* Исправлена отладка UDF: теперь вывод stderr перехватывается и записывается в `system.query_log.exception`. Ранее stderr UDF записывался только в файлы и не отображался в журналах запросов, что делало отладку невозможной. Теперь stderr по умолчанию инициирует исключения и полностью накапливается (до 1 МБ) перед их генерацией, поэтому полные трассировки Python и сообщения об ошибках отображаются в `system.query_log.exception`, что упрощает диагностику проблем. [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
* Пустой список столбцов в конструкции `JOIN USING ()` теперь считается синтаксической ошибкой. Ранее при выполнении запроса ожидалась ошибка `INVALID_JOIN_ON_EXPRESSION`. В некоторых случаях, например при JOIN с хранилищем `Join`, это приводило к `LOGICAL_ERROR`. Закрывает [#82502](https://github.com/ClickHouse/ClickHouse/issues/82502). [#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Расширенные общие данные для JSON включены по умолчанию. После этого изменения откат к версиям ниже 25.8 будет невозможен, поскольку они не смогут читать новые части данных с JSON-столбцом. Для безопасного обновления рекомендуется установить настройку `compatibility` на предыдущую версию либо задать настройки MergeTree `dynamic_serialization_version='v2', object_serialization_version='v2'`. [#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar)).
* По умолчанию для SKIP REGEXP в типе JSON теперь используется частичное совпадение. Закрывает [#79250](https://github.com/ClickHouse/ClickHouse/issues/79250). [#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar)).
* Откат изменения «Allow INSERT into simple ALIAS columns» (откат ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154)). Оно не работает с пользовательскими форматами и не защищено настройкой. [#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat)).
* Добавлена настройка для генерации ошибки, если каталог datalake не имеет доступа к объектному хранилищу. [#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Движок базы данных `Lazy` удалён и более недоступен. Закрывает [#91231](https://github.com/ClickHouse/ClickHouse/issues/91231). [#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Удалён режим `transposed_with_wide_view` для `metric_log` — он неработоспособен из-за ошибки. Определение `system.metric_log` с этим режимом более невозможно. Частично откатывает [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412). [#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Планирование CPU для рабочих нагрузок теперь является вытесняющим по умолчанию. См. настройку сервера `cpu_slot_preemption`. [#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa)).
* Имена файлов индексов теперь экранируются для предотвращения повреждения частей. После этого изменения ClickHouse не сможет загружать индексы с не-ASCII-символами в именах, созданные предыдущими версиями. Для решения этой проблемы можно использовать настройку MergeTree `escape_index_filenames`. [#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano)).
* Настройки формата `exact_rows_before_limit`, `rows_before_aggregation`, `cross_to_inner_join_rewrite`, `regexp_dict_allow_hyperscan`, `regexp_dict_flag_case_insensitive`, `regexp_dict_flag_dotall` и `dictionary_use_async_executor` переведены в разряд обычных (не форматных) настроек. Это сугубо внутреннее изменение без видимых для пользователя последствий, за исключением маловероятного случая, когда любая из этих настроек была указана в определениях движков таблиц Iceberg, DeltaLake, Kafka, S3, S3Queue, Azure, Hive, RabbitMQ, Set, FileLog или NATS. В таких случаях эти настройки ранее игнорировались; теперь подобные определения будут приводить к ошибке. [#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze)).
* Функции `joinGet/joinGetOrNull` теперь проверяют привилегии `SELECT` на базовую таблицу Join. После этого изменения выполнение `joinGet('db.table', 'column', key)` требует наличия у пользователя привилегии `SELECT` как на столбцы ключа, определённые в таблице Join, так и на запрашиваемый столбец атрибута. Запросы без необходимых привилегий завершатся ошибкой `ACCESS_DENIED`. Для миграции предоставьте необходимые разрешения с помощью `GRANT SELECT ON db.join_table TO user` для полного доступа к таблице или `GRANT SELECT(key_col, attr_col) ON db.join_table TO user` для доступа на уровне столбца. Изменение затрагивает всех пользователей и приложения, использующие `joinGet`/`joinGetOrNull`, для которых ранее не были явно настроены права `SELECT`. [#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Для запросов `CREATE TABLE ... AS ...` теперь проверяется привилегия `SHOW COLUMNS`. Ранее проверялась привилегия `SHOW TABLES`, что являлось некорректным правом для данного типа проверки разрешений. [#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit)).





<div id="new-feature">
  #### Новая возможность
</div>

* HTTP API и встроенный веб-интерфейс для CH Keeper. [#78181](https://github.com/ClickHouse/ClickHouse/pull/78181) ([pufit](https://github.com/pufit)).
* Распределённый анализ индексов на нескольких репликах. Полезно для общего хранилища и больших объёмов данных в кластере. [#86786](https://github.com/ClickHouse/ClickHouse/pull/86786) ([Azat Khuzhin](https://github.com/azat)).
* С `<interactive_history_legacy_keymap>true</interactive_history_legacy_keymap>` CLI-клиент теперь может, как и раньше, использовать Ctrl R для обычного поиска, а Ctrl T — для нечёткого поиска. [#87785](https://github.com/ClickHouse/ClickHouse/pull/87785) ([Larry Snizek](https://github.com/larry-cdn77)).
* Дедупликация async insert теперь работает с зависимыми materialized view. При коллизии по block&#95;id исходный блок фильтруется для удаления строк, связанных с этим block&#95;id, а оставшиеся строки преобразуются всеми соответствующими запросами SELECT materialized view, что позволяет пересобрать исходный блок без конфликтующих строк. [#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлена возможность для клиента ClickHouse переопределять TLS SNI при подключении к серверу. [#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).
* Добавлена поддержка text index для столбцов типа Array. [#89895](https://github.com/ClickHouse/ClickHouse/pull/89895) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Добавлена новая системная таблица zookeeper&#95;info. Исправлено [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014). [#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Реализован FunctionVariantAdaptor для поддержки типа Variant в функциях. [#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* Добавлена метрика `ClickHouse_Info` в конечную точку Prometheus `/metrics`, содержащая в основном информацию о версии, чтобы можно было строить графики и отслеживать подробную информацию о версии с течением времени. [#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* Представлена новая четырёхбуквенная команда `rcfg` для Keeper, позволяющая изменять конфигурацию кластера. Эта команда предоставляет более широкие возможности изменения конфигурации, чем стандартный запрос `reconfigure`. Команда принимает строку `json` в качестве аргумента. Весь набор байтов, отправляемых в TCP-интерфейс, должен выглядеть так: `rcfg{json_string_length_big_endian}{json_string}`. Пример команды может выглядеть так: `{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`. [#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* Добавлена функция `reverseBySeparator`, которая меняет порядок подстрок в строке, разделённых указанным разделителем. Закрывает [#91463](https://github.com/ClickHouse/ClickHouse/issues/91463). [#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* Представлены новый синтаксис и новая инфраструктура для упрощения и расширения функциональности индексов проекций. Это развитие https://github.com/ClickHouse/ClickHouse/pull/81021. [#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* Добавлена поддержка REST-каталога Paimon в продолжение https://github.com/ClickHouse/ClickHouse/pull/84423. [#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* Добавлена новая настройка `max_insert_block_size_bytes`, которая позволяет точнее управлять формированием вставляемых блоков. [#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* Можно выполнять DDL-запросы с предложением `ON CLUSTER` для базы данных Replicated, если включена настройка `ignore_on_cluster_for_replicated_database`. В этом случае имя кластера игнорируется. [#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* Реализована функция `mergeTreeAnalyzeIndex()`. [#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* Добавлена новая настройка `use_primary_key`. Установите её в `false`, чтобы отключить отсечение гранул по первичному ключу. [#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Табличная функция `icebergLocalCluster`. [#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Datalakes prewhere и многоэтапный prewhere в ридере Parquet v3 устраняют проблему [#89101](https://github.com/ClickHouse/ClickHouse/issues/89101). [#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Добавлена функция `cosineDistanceTransposed`, которая аппроксимирует [косинусное расстояние](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance) между двумя точками. [#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Прежний оператор очистки кэшей `SYSTEM DROP [...] CACHE` создавал ложное впечатление, что он отключает кэш. Теперь ClickHouse поддерживает оператор `SYSTEM CLEAR [...] CACHE`, который понятнее. Старый синтаксис остаётся доступным. [#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* В таблицу system.parts добавлен столбец files, который показывает количество файлов в каждой части данных. [#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* Добавлен планировщик max-min fair для управления параллелизмом. Он обеспечивает более справедливое распределение ресурсов при высокой переподписке, когда множество запросов конкурируют за ограниченные слоты CPU. Короткие запросы не страдают из-за долгих запросов, которые со временем накопили больше слотов. Включается значением `max_min_fair` настройки сервера `concurrent_threads_scheduler`. [#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* В JOIN теперь проталкивается больше фильтров. [#85556](https://github.com/ClickHouse/ClickHouse/pull/85556) ([Nikita Taranov](https://github.com/nickitat)).
* Отключена оптимизация порядка сортировки для оконных функций, когда partition by совпадает с ключом сортировки или является его префиксом, что повышает производительность параллельного выполнения. [#87299](https://github.com/ClickHouse/ClickHouse/pull/87299) ([Nikita Taranov](https://github.com/nickitat)).
* Внешний фильтр теперь проталкивается в представление, что позволяет применять PREWHERE на локальных и удалённых узлах. Исправлено [#88189](https://github.com/ClickHouse/ClickHouse/issues/88189). [#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).
* Реализована JIT-компиляция для большего числа функций. Закрывает [#73509](https://github.com/ClickHouse/ClickHouse/issues/73509). [#88770](https://github.com/ClickHouse/ClickHouse/pull/88770) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Оптимизированы производительность и использование памяти для дробных `LIMIT` и `OFFSET`. [#91167](https://github.com/ClickHouse/ClickHouse/pull/91167) ([Ahmed Gouda](https://github.com/0xgouda)).
* Исправлено использование более быстрой логики произвольного чтения в Parquet Reader V3 Prefetcher. Закрывает [#90890](https://github.com/ClickHouse/ClickHouse/issues/90890). [#91435](https://github.com/ClickHouse/ClickHouse/pull/91435) ([Arsen Muk](https://github.com/arsenmuk)).
* Повышена производительность `icebergCluster`. Закрывает [#91462](https://github.com/ClickHouse/ClickHouse/issues/91462). [#91537](https://github.com/ClickHouse/ClickHouse/pull/91537) ([Yang Jiang](https://github.com/Ted-Jiang)).
* Отключена фильтрация по виртуальным столбцам для константных фильтров. [#91588](https://github.com/ClickHouse/ClickHouse/pull/91588) ([c-end](https://github.com/c-end)).
* Повышена производительность `DISTINCT` для столбцов `LowCardinality`. Закрывает [#5917](https://github.com/ClickHouse/ClickHouse/issues/5917). [#91639](https://github.com/ClickHouse/ClickHouse/pull/91639) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Оптимизирована агрегатная функция distinctJSONPaths: теперь она читает только JSON-пути из частей данных, а не весь JSON-столбец. [#92196](https://github.com/ClickHouse/ClickHouse/pull/92196) ([Pavel Kruglov](https://github.com/Avogar)).
* Снижено использование памяти при INSERT и слияниях для очень широких таблиц, использующих части Wide, за счёт включения адаптивных буферов записи. Добавлена поддержка адаптивных буферов записи для зашифрованных дисков. [#92250](https://github.com/ClickHouse/ClickHouse/pull/92250) ([Azat Khuzhin](https://github.com/azat)).
* Расширена поддержка проталкивания из условия JOIN ON, когда фильтр использует входные данные только с одной стороны. Поддерживаются `ANY`, `SEMI`, `ANTI` JOIN. [#92584](https://github.com/ClickHouse/ClickHouse/pull/92584) ([Dmitry Novik](https://github.com/novikd)).
* Разрешено использовать эквивалентные sets для проталкивания фильтров в `SEMI JOIN`. Закрывает [#85239](https://github.com/ClickHouse/ClickHouse/issues/85239). [#92837](https://github.com/ClickHouse/ClickHouse/pull/92837) ([Dmitry Novik](https://github.com/novikd)).
* Повышена производительность полнотекстового поиска с текстовым индексом и токенизатором `sparseGrams` за счёт сокращения числа токенов, по которым выполняется поиск в индексе. [#93078](https://github.com/ClickHouse/ClickHouse/pull/93078) ([Anton Popov](https://github.com/CurtizJ)).
* Используется метод &quot;fastrange&quot; (Daniel Lemire) для разбиения данных внутри конвейера выполнения запроса. Это может улучшить параллельную сортировку и JOIN. [#93080](https://github.com/ClickHouse/ClickHouse/pull/93080) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Оптимизирован `uniqExact` для случаев, когда одинаковые элементы часто идут подряд. [#93268](https://github.com/ClickHouse/ClickHouse/pull/93268) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Функция `isValidASCII` оптимизирована для случаев успешной проверки, то есть когда входные значения состоят только из ASCII. [#93347](https://github.com/ClickHouse/ClickHouse/pull/93347) ([Robert Schulze](https://github.com/rschu1ze)).
* Функция `isValidASCII` оптимизирована для случаев успешной проверки, то есть когда входные значения состоят только из ASCII. [#93611](https://github.com/ClickHouse/ClickHouse/pull/93611) ([Robert Schulze](https://github.com/rschu1ze)).
* Чтение левой части hash join теперь пропускается, если правая часть пуста. Ранее левая часть читалась до первого непустого блока, что могло приводить к большому объему работы при интенсивной фильтрации или агрегации. [#94062](https://github.com/ClickHouse/ClickHouse/pull/94062) ([Alexander Gololobov](https://github.com/davenger)).

Это полезно для мультитенантных запросов, таких как &#96;WHERE tenant=&#39;42&#39; ORDER BY tenant, event&#95;time DESC&#96;, которые теперь могут использовать InReverseOrder вместо полной сортировки.&quot;.
