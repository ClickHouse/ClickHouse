* Бэкпортировано в [#97291](https://github.com/ClickHouse/ClickHouse/issues/97291): вывод схемы теперь учитывает `allow_experimental_nullable_tuple_type`. Если этот параметр включен, выведенные типы кортежей могут иметь вид `Nullable(Tuple(...))`, поэтому отсутствующие вложенные объекты могут становиться `NULL`, а не кортежем из элементов `NULL`. [#95525](https://github.com/ClickHouse/ClickHouse/pull/95525) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Бэкпортировано в [#95836](https://github.com/ClickHouse/ClickHouse/issues/95836): внутренняя библиотека libxml2 обновлена до версии 2.15.1. [#95574](https://github.com/ClickHouse/ClickHouse/pull/95574) ([Robert Schulze](https://github.com/rschu1ze)).

[#95899](https://github.com/ClickHouse/ClickHouse/pull/95899) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпорт в [#96316](https://github.com/ClickHouse/ClickHouse/issues/96316): Убрана лишняя проверка пропуска разрешений в запросах `ATTACH` для представления с безопасностью SQL. Это предотвращает потенциальную эскалацию привилегий, когда пользователь подключает представление с `definer` без проверки необходимых прав доступа. [#94865](https://github.com/ClickHouse/ClickHouse/pull/94865) ([pufit](https://github.com/pufit)).
* Бэкпорт в [#95806](https://github.com/ClickHouse/ClickHouse/issues/95806): Исправлен вывод типов для квалифицированных столбцов из исходных таблиц при использовании нескольких JOIN с предложением `USING`. Ранее последующие JOIN некорректно обновляли типы базовых исходных столбцов до общего супертипа, даже если столбец не участвовал в этом JOIN (например, в `SELECT t2.a FROM t1 LEFT JOIN t2 USING (a) LEFT JOIN t3 USING (a)`, столбец `t2.a` используется только в первом JOIN, поэтому его тип должен быть супертипом `t1.a` и `t2.a`, без учёта `t3.a`). Это могло приводить к логическим ошибкам или сбоям, когда функции ожидали одни типы столбцов, а в Execution Plan фактически появлялись другие. [#95157](https://github.com/ClickHouse/ClickHouse/pull/95157) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Бэкпорт в [#96396](https://github.com/ClickHouse/ClickHouse/issues/96396): Исправлена логическая ошибка в некоторых случаях использования отрицательного `LIMIT/OFFSET` в распределённых запросах. [#95357](https://github.com/ClickHouse/ClickHouse/pull/95357) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Бэкпорт в [#96222](https://github.com/ClickHouse/ClickHouse/issues/96222): Исправлен сбой при применении `tupleElement` к массивам JSON. Закрывает [#95581](https://github.com/ClickHouse/ClickHouse/issues/95581). [#95647](https://github.com/ClickHouse/ClickHouse/pull/95647) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпорт в [#95825](https://github.com/ClickHouse/ClickHouse/issues/95825): Исправлено объединение блоков для партиционированных данных Delta Lake. [#95773](https://github.com/ClickHouse/ClickHouse/pull/95773) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Бэкпорт в [#95852](https://github.com/ClickHouse/ClickHouse/issues/95852): Исправлено состояние гонки для Nullable-столбца, используемого в JOIN, в Runtime Filters. [#95775](https://github.com/ClickHouse/ClickHouse/pull/95775) ([Hechem Selmi](https://github.com/m-selmi)).
* Бэкпорт в [#97187](https://github.com/ClickHouse/ClickHouse/issues/97187): Исправлено выполнение `tupleElement` для JSON с вложенными путями; ранее это могло приводить к неверному результату запроса. [#95907](https://github.com/ClickHouse/ClickHouse/pull/95907) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпорт в [#96086](https://github.com/ClickHouse/ClickHouse/issues/96086): Исправлена ошибка `NOT_SUPPORTED`, которая могла возникать при использовании алгоритма JOIN `direct` с пустой таблицей семейства MergeTree. [#95935](https://github.com/ClickHouse/ClickHouse/pull/95935) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Бэкпорт в [#95993](https://github.com/ClickHouse/ClickHouse/issues/95993): Исправлен `event_date` в `system.asynchronous_metric_log`. [#95947](https://github.com/ClickHouse/ClickHouse/pull/95947) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпорт в [#96215](https://github.com/ClickHouse/ClickHouse/issues/96215): Исправлена обработка skipping paths в типе данных JSON. Ранее при `JSON(SKIP path)` пропускались все ключи JSON с префиксом `path`, включая такие ключи, как `"pathpath"`, поэтому это могло приводить к потере данных по этим путям при вставке. Теперь это исправлено, и пропускается только ключ `"path"`. [#95948](https://github.com/ClickHouse/ClickHouse/pull/95948) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#96082](https://github.com/ClickHouse/ClickHouse/issues/96082): Исправлен период для глобальных профилировщиков (управляется параметрами `global_profiler_real_time_period_ns` и `global_profiler_cpu_time_period_ns`). Вместо заданного значения использовалось усечённое, из-за чего профилировщик пробуждался чаще, чем предполагалось. [#96048](https://github.com/ClickHouse/ClickHouse/pull/96048) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#96189](https://github.com/ClickHouse/ClickHouse/issues/96189): Ранее, если ссылочный файл данных внутри манифест-файла Iceberg для position delete присутствовал в записи, но имел значение null, не удавалось получить корректные границы для соответствующих файлов данных.
