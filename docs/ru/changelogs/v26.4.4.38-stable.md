<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Бэкпортировано в [#106046](https://github.com/ClickHouse/ClickHouse/issues/106046): настройка `show_data_lake_catalogs_in_system_tables` была переименована в `show_remote_databases_in_system_tables`, а её действие расширено: если её значение равно 0 (по умолчанию), то базы данных `MySQL` и `PostgreSQL` также скрываются из `system.tables`, `system.columns` и `system.completions`, помимо каталогов озёр данных. Старое имя настройки сохранено как псевдоним. [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#106583](https://github.com/ClickHouse/ClickHouse/issues/106583): Исправлено поведение, при котором `PREWHERE` с подзапросом `IN` по столбцам первичного ключа не использовал индекс первичного ключа для отсечения гранул, из-за чего выполнялось полное сканирование таблицы вместо чтения только нужных гранул. [#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Бэкпортировано в [#105242](https://github.com/ClickHouse/ClickHouse/issues/105242): Асинхронные метрики `HTTPConnectionPool*TCP{Rcv,Snd}BufBytes_{p50,p75,p90,p95}` заменены на гистограмму `http_pool_tcp_buf_bytes` на основе бакетов (метки `group`, `direction`) в `system.histogram_metrics`. Суммарные асинхронные метрики по группам сохранены. [#103704](https://github.com/ClickHouse/ClickHouse/pull/103704) ([Sema Checherinda](https://github.com/CheSema)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#105366](https://github.com/ClickHouse/ClickHouse/issues/105366): исправлены некорректные результаты для RIGHT ANY JOIN, когда правая таблица содержит несколько строк на один ключ, а выходной блок разбивается из-за ограничений по размеру. Закрывает [#99431](https://github.com/ClickHouse/ClickHouse/issues/99431). [#102064](https://github.com/ClickHouse/ClickHouse/pull/102064) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Бэкпортировано в [#105358](https://github.com/ClickHouse/ClickHouse/issues/105358): добавлена проверка на переполнение стека в модуле чтения Avro при десериализации вложенных типов. [#102417](https://github.com/ClickHouse/ClickHouse/pull/102417) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#105512](https://github.com/ClickHouse/ClickHouse/issues/105512): теперь при усечении или повреждении данных, предоставленных клиентом в формате Native, генерируется `INCORRECT_DATA` вместо `LOGICAL_ERROR`. [#102975](https://github.com/ClickHouse/ClickHouse/pull/102975) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#105409](https://github.com/ClickHouse/ClickHouse/issues/105409): исправлена проблема, из-за которой `StorageObjectStorageQueue` (`S3Queue`, `AzureQueue`) блокировал завершение работы, пока частично обработанные файлы не будут полностью прочитаны из Объектного хранилища. Теперь источник немедленно прерывает чтение при завершении работы; дедупликация гарантирует, что строки, уже переданные в целевую таблицу до завершения работы, не будут дублироваться при повторной обработке файла после следующего запуска. [#103126](https://github.com/ClickHouse/ClickHouse/pull/103126) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Бэкпортировано в [#105804](https://github.com/ClickHouse/ClickHouse/issues/105804): исправлено повреждение данных при записи Parquet (и других форматов с трейлером, таких как ORC и Arrow) в HDFS через `INSERT INTO FUNCTION hdfs(...)`. Начиная с 26.1, `WriteBufferFromHDFS` не выполнял flush своего рабочего буфера при `finalize()`, из-за чего последние `DBMS_DEFAULT_BUFFER_SIZE` байт или меньше в каждом файле молча терялись, включая нижний колонтитул `PAR1` в Parquet. Чтение таких файлов возвращало `Not a Parquet file (wrong magic bytes at the end of file)`. [#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#106284](https://github.com/ClickHouse/ClickHouse/issues/106284): исправлена обработка URL-кодированного пути в deltaLakeAzure resolve. [#103525](https://github.com/ClickHouse/ClickHouse/pull/103525) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Бэкпортировано в [#105426](https://github.com/ClickHouse/ClickHouse/issues/105426): отключён **`additional_table_filters`** при использовании **параллельных реплик** и analyzer без сериализации плана запроса. **Ранее это могло приводить к некорректным результатам**. [#104296](https://github.com/ClickHouse/ClickHouse/pull/104296) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#106242](https://github.com/ClickHouse/ClickHouse/issues/106242): исправлена повреждённая patch part после `ALTER TABLE ... DROP PARTITION ID 'patch-...'` с последующим `DETACH`/`ATTACH TABLE`. Ранее пустая covering part записывалась без `partition.dat` и `source_parts.dat`, что приводило к появлению записи `broken-on-start_patch-...` в `system.detached_parts` после следующего `ATTACH TABLE` или перезапуска сервера. Закрывает [#93132](https://github.com/ClickHouse/ClickHouse/issues/93132). Закрывает [#102103](https://github.com/ClickHouse/ClickHouse/issues/102103). [#104353](https://github.com/ClickHouse/ClickHouse/pull/104353) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105753](https://github.com/ClickHouse/ClickHouse/issues/105753): `LEFT ANTI JOIN` теперь корректно возвращает столбец ключа JOIN с правой стороны со значениями по умолчанию для несовпавших строк вместо дублирования значения левого ключа. Ранее `SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` мог возвращать `r = a.x` для несовпавших строк, хотя должен был возвращать значение по умолчанию (`0` для `Int32`, `''` для `String`, `NULL` для `Nullable`). Затронут был только столбец ключа JOIN; неключевые правые столбцы уже корректно заполнялись значениями по умолчанию. Та же ошибка проявлялась и в `RIGHT ANTI JOIN`, когда оптимизатор менял стороны местами. Закрывает [#99959](https://github.com/ClickHouse/ClickHouse/issues/99959). [#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105665](https://github.com/ClickHouse/ClickHouse/issues/105665): Длительно выполняющиеся `INSERT ... SELECT` и другие операции чтения из database `DataLakeCatalog` с `catalog_type = 'glue'` завершаются ошибкой `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)`, как только учетные данные сеанса STS, полученные при загрузке metadata таблицы, истекают. [#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Бэкпортировано в [#105979](https://github.com/ClickHouse/ClickHouse/issues/105979): Исправлено Исключение `BAD_ARGUMENTS` &quot;It&#39;s a bug! Only integer types are supported by `__bitWrapperFunc`&quot;, которое возникало, когда `SELECT` с индексом пропуска данных `TYPE set(N)` содержал атом в предложении WHERE, тип результата которого был `Float`, `BFloat16` или любым другим нецелочисленным типом (например, `WHERE c0 + 0.1` или `WHERE log(c0)`). Теперь в таком случае индекс пропуска данных переключается на обычный путь фильтрации. [#105384](https://github.com/ClickHouse/ClickHouse/pull/105384) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105621](https://github.com/ClickHouse/ClickHouse/issues/105621): Исправлены переполнение буфера кучи при чтении файлов Arrow или ArrowStream с поврежденными промежуточными offsets в бинарном или строковом столбце, а также разыменование нулевого указателя при чтении Arrow-столбцов с геотегами. [#105449](https://github.com/ClickHouse/ClickHouse/pull/105449) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#105882](https://github.com/ClickHouse/ClickHouse/issues/105882): Исправлена ошибка, из-за которой `dictGetOrDefault` генерировал `CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN`, когда аргументом по умолчанию было выражение `Nullable`, а `short_circuit_function_evaluation` был включен при сочетании найденных и ненайденных ключей словаря. [#105461](https://github.com/ClickHouse/ClickHouse/pull/105461) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#105874](https://github.com/ClickHouse/ClickHouse/issues/105874): Исправлен segfault server в `uniqStateOrNull` / `uniqStateOrDefault` / `uniqOrNullState` (и аналогичных цепочках combinator над `uniq`) при использовании с `GROUP BY ... WITH ROLLUP`, `WITH CUBE` или `WITH TOTALS` и аргументом `Nullable`. [#105470](https://github.com/ClickHouse/ClickHouse/pull/105470) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105971](https://github.com/ClickHouse/ClickHouse/issues/105971): Исправлен SEGFAULT при десериализации `singleValueOrNull` для JSON type. Закрывает [#103630](https://github.com/ClickHouse/ClickHouse/issues/103630). [#105535](https://github.com/ClickHouse/ClickHouse/pull/105535) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#105746](https://github.com/ClickHouse/ClickHouse/issues/105746): Исправлен сбой в replxx из-за достижения ограничения FD&#95;SETSIZE в select() (заменено на poll()). Обратите внимание: при включенном SSH/веб-терминале это могло приводить к сбою сервера. [#105559](https://github.com/ClickHouse/ClickHouse/pull/105559) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#106557](https://github.com/ClickHouse/ClickHouse/issues/106557): Исправлен сбой клиента при `CREATE TABLE ... TO INNER UUID '...' ...`, когда оператор не содержит предложения `ENGINE`. Теперь парсер сообщает корректную ошибку `BAD_ARGUMENTS` вместо разыменования нулевого указателя. [#105579](https://github.com/ClickHouse/ClickHouse/pull/105579) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105729](https://github.com/ClickHouse/ClickHouse/issues/105729): Извлечение значений Hive-партиций теперь учитывает настройку `cast_string_to_date_time_mode` и по умолчанию принимает временные метки ISO 8601 с суффиксами часового пояса (например, `+0000`, `+00:00`, `Z`) в ключах партиционирования. [#105584](https://github.com/ClickHouse/ClickHouse/pull/105584) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#105812](https://github.com/ClickHouse/ClickHouse/issues/105812): Исправлен незаметный недосчёт в запросах `SELECT`, когда `use_query_condition_cache = 1` (по умолчанию). Запрос вида `PREWHERE pk_prefix = X WHERE non_pk IN (...)` к столбцу с bloom-filter индексом пропуска данных загрязнял `QueryConditionCache` для предиката `pk_prefix = X`, из-за чего последующий безобидный `SELECT count() ... WHERE pk_prefix = X` возвращал некорректный заниженный результат. Затронуты все релизы 26.x. [#104781](https://github.com/ClickHouse/ClickHouse/issues/104781). [#105686](https://github.com/ClickHouse/ClickHouse/pull/105686) ([Groene AI](https://github.com/groeneai)).
