<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Исправлены метаданные обычных проекций, чтобы проекции с многоколоночными ключами сортировки корректно распознавались. Основано на [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429). [#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* Версии сериализации типов данных теперь распространяются на вложенные типы данных. Например, версия сериализации String `with_size_stream` ранее применялась только к столбцам String верхнего уровня и элементам Tuple. Теперь она применяется к любому типу String внутри любых вложенных типов, таких как Array/Map/Variant/JSON/etc. Это поведение управляется настройкой MergeTree `propagate_types_serialization_versions_to_nested_types`, которая теперь включена по умолчанию. После этого изменения вновь созданные части данных не смогут читаться более старыми версиями, но старые части без проблем читаются в новой версии. Это означает, что обновление безопасно, а понизить версию — нет. [#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* Удален тип индекса пропуска данных `hypothesis`. Это была малоизвестная экспериментальная возможность с ограниченной практической пользой. Создание таблиц с `INDEX ... TYPE hypothesis` теперь будет приводить к ошибке. [#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлена проблема, из-за которой файлы индекса пропуска данных не учитывали настройку replace&#95;long&#95;file&#95;name&#95;to&#95;hash, что вызывало ошибки &quot;File name too long&quot; и нарушало чтение индексов с длинными именами. Теперь имена файлов индекса пропуска данных хешируются, если превышают max&#95;file&#95;name&#95;length, аналогично файлам столбцов. Это обратно совместимо (новые серверы читают старые части), но при понижении версии или при работе старых серверов во время поэтапного обновления индексы с длинными именами могут игнорироваться. [#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* По умолчанию включен async insert. Теперь ClickHouse по умолчанию будет выполнять пакетную обработку всех небольших вставок. Эта настройка задается через compatibility. Если установить `compatibility=<version less than 26.2>`, значением по умолчанию останется прежнее — `false`. Включать и отключать async inserts можно на нескольких уровнях: в конфигурации, в профилях пользователей, для сессии, для запроса или для таблицы семейства MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* Исправлен приоритет оператора `NOT` в соответствии со стандартом SQL: теперь `NOT` связывается слабее, чем `IS NULL`, `BETWEEN`, `LIKE` и арифметические операторы. Например, `NOT (x) IS NULL` теперь разбирается как `NOT (x IS NULL)`, а не как `(NOT x) IS NULL`. Это может изменить результат запросов, которые полагались на прежнее (нестандартное) поведение. [#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Значение по умолчанию для `mysql_datatypes_support_level` изменено с пустого на `decimal,datetime64,date2Date32`, что по умолчанию включает корректное сопоставление MySQL `DATE` с `Date32`, `DECIMAL`/`NUMERIC` с `Decimal`, а `DATETIME`/`TIMESTAMP` с precision — с `DateTime64`. Ранее столбцы MySQL `DATE` сопоставлялись с `Date`, который не может представлять даты до 1970-01-01, что приводило к повреждению данных. [#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Для `mergeTreeAnalyzeIndexes{,UUID}` теперь принимается Array имен частей вместо regexp, поскольку regexps работают медленно (*экспериментальная возможность*). [#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* Удалена экспериментальная функция `detectProgrammingLanguage`. [#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### Новая возможность
</div>

* Теперь можно использовать функцию natural sort key как `naturalSortKey(s)`. [#90322](https://github.com/ClickHouse/ClickHouse/pull/90322) ([Nazarii Piontko](https://github.com/nazarii-piontko)).
* Если параметр имеет тип Nullable и не указан, считается, что его значение — NULL:. [#93869](https://github.com/ClickHouse/ClickHouse/pull/93869) ([Vikash Kumar](https://github.com/vikashkumar2020)).
* Бэкпортировано в [#100331](https://github.com/ClickHouse/ClickHouse/issues/100331): поддержка materialized CTE. Позволяет вычислять CTE только один раз при выполнении запроса и сохранять результаты во временных таблицах. Закрывает [#53449](https://github.com/ClickHouse/ClickHouse/issues/53449). [#94849](https://github.com/ClickHouse/ClickHouse/pull/94849) ([Dmitry Novik](https://github.com/novikd)).
* Добавлена поддержка auxiliary ZooKeeper для `DatabaseReplicated`. [#95590](https://github.com/ClickHouse/ClickHouse/pull/95590) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* Разрешено использовать некоторые функции без скобок в SQL. Закрывает [#52102](https://github.com/ClickHouse/ClickHouse/issues/52102). [#95949](https://github.com/ClickHouse/ClickHouse/pull/95949) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* Добавлена опция LDAP-конфигурации `<follow_referrals>` для каждого сервера (по умолчанию `false`), управляющая тем, следует ли LDAP-клиент перенаправлениям. Отключение перехода по перенаправлениям позволяет избежать тайм-аутов и зависаний при поиске от base DN корня домена Active Directory. Кроме того, в логах стало меньше шума (уровень изменён с `warn` на `trace`). ... [#96765](https://github.com/ClickHouse/ClickHouse/pull/96765) ([paf91](https://github.com/paf91)).
* Добавлена поддержка функции `has()` для JSON type, чтобы проверять существование пути, аналогично Map. [#96927](https://github.com/ClickHouse/ClickHouse/pull/96927) ([DQ](https://github.com/il9ue)).
* Добавлена table function `mergeTreeTextIndex(database, table, index)`, которая позволяет читать данные напрямую из text index. Эту функцию можно использовать для интроспекции или для выполнения aggregations поверх данных text index. [#97003](https://github.com/ClickHouse/ClickHouse/pull/97003) ([Anton Popov](https://github.com/CurtizJ)).
* Добавлена настройка MergeTree `table_readonly`, позволяющая помечать таблицы как только для чтения и запрещать вставку и изменения. [#97652](https://github.com/ClickHouse/ClickHouse/pull/97652) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена новая настройка `use_partition_pruning` и псевдоним `use_partition_key`. Установите значение `false`, чтобы отключить partition pruning на основе ключа партиционирования. [#97888](https://github.com/ClickHouse/ClickHouse/pull/97888) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Реализован `ALTER TABLE ... EXECUTE expire_snapshots('<timestamp>')` для Iceberg table. [#97904](https://github.com/ClickHouse/ClickHouse/pull/97904) ([murphy-4o](https://github.com/murphy-4o)).
* Добавлен новый SLRU-кэш для metadata Parquet, который повышает производительность чтения, устраняя необходимость повторно загружать файлы только ради чтения metadata. [#98140](https://github.com/ClickHouse/ClickHouse/pull/98140) ([Grant Holly](https://github.com/grantholly-clickhouse)).
* Для каждой записи `type=http` в `<protocols>` теперь можно указать пользовательский ключ `<handlers>`, ссылающийся на отдельный раздел config `<http_handlers_*>`, что позволяет задавать разные правила HTTP-маршрутизации для каждого порта. [#98414](https://github.com/ClickHouse/ClickHouse/pull/98414) ([Amos Bird](https://github.com/amosbird)).
* Два улучшения команды `EXPLAIN [PLAN]`:. [#98500](https://github.com/ClickHouse/ClickHouse/pull/98500) ([Kirill Kopnev](https://github.com/Fgrtue)).
* Добавлена настройка сервера `restore_access_entities_with_current_grants`. Если она включена, восстановленные пользователи и роли получают только те привилегии, которые пользователь, выполняющий восстановление, имеет право выдавать (та же семантика, что и у `GRANT CURRENT GRANTS`), вместо завершения с ошибкой `ACCESS_DENIED`. [#98795](https://github.com/ClickHouse/ClickHouse/pull/98795) ([pufit](https://github.com/pufit)).
* Добавлены функции `caseFoldUTF8` и `removeDiacriticsUTF8` для свертки регистра Unicode и удаления диакритических знаков. [#98973](https://github.com/ClickHouse/ClickHouse/pull/98973) ([George Larionov](https://github.com/george-larionov)).
* `SymbolIndex`, `addressToSymbol`, `system.symbols` и `buildId` теперь работают на macOS благодаря разбору таблиц символов Mach-O. [#99014](https://github.com/ClickHouse/ClickHouse/pull/99014) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена строковая функция `normalizeUTF8NFKCCasefold` для нормализации Unicode NFKC&#95;Casefold, которая объединяет нормализацию NFKC со сверткой регистра. [#99276](https://github.com/ClickHouse/ClickHouse/pull/99276) ([George Larionov](https://github.com/george-larionov)).
* Добавлен токенизатор `unicode_word` для полнотекстовых индексов и функции `tokens`. Он разбивает текст по правилам границ слов Unicode: ASCII-слова формируются с символами-соединителями (подчеркивание, двоеточие, точка, одиночная кавычка), а не-ASCII-символы Unicode становятся односимвольными токенами. По умолчанию для настраиваемых стоп-слов используется распространенная пунктуация CJK. [#99357](https://github.com/ClickHouse/ClickHouse/pull/99357) ([Amos Bird](https://github.com/amosbird)).
* Добавлены настройки `max_skip_unavailable_shards_num` и `max_skip_unavailable_shards_ratio`, чтобы ограничить, сколько сегментов можно незаметно пропустить, когда включен `skip_unavailable_shards`. Если количество или доля недоступных сегментов превышает заданный порог, генерируется исключение вместо молчаливого возврата неполных результатов. [#99369](https://github.com/ClickHouse/ClickHouse/pull/99369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Пользователи теперь могут использовать ключевое слово `SOME` в выражениях с подзапросами. Оно работает так же, как `ANY`. [#99842](https://github.com/ClickHouse/ClickHouse/pull/99842) ([Artem Kytkin](https://github.com/Vinceent)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Оптимизировано пропускание гранул для `pointInPolygon` при работе с крупными полигонами, а также исправлена ошибка, из-за которой анализ индексов `pointInPolygon` генерировал исключение при отсечении по первичному ключу. [#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Улучшена производительность функции `levenshteinDistance`. [#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)).
* Оптимизированы преобразования типа Decimal в батчах за счёт отказа от вызовов функций для каждого элемента. [#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 1. В Iceberg появилась возможность асинхронно заранее загружать метаданные в кэш. Ее можно включить, задав `iceberg_metadata_async_prefetch_period_ms` при создании таблицы. Например: `CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. Теперь запросы SELECT к таблицам Iceberg можно выполнять с указанием параметра `iceberg_metadata_staleness_ms`, что позволит ClickHouse использовать кэшированную версию метаданных, если она свежее указанного порога устаревания. В противном случае для получения актуальных метаданных будет выполняться запрос к удаленному каталогу Iceberg, чтобы обработать запрос (как это работало раньше). Благодаря этому изменению мы можем сократить количество обращений к каталогу Iceberg до 0 во время обработки запросов, что, как ожидается, даст заметный прирост производительности. Пример: `SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`. [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)).
* В упорядоченном режиме S3Queue используется S3 ListObjectsV2 StartAfter, чтобы не перечислять повторно всю историю префикса и сократить количество вызовов ListObjects. [#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* В общем случае для дедупликации нужен исходный блок, но для синхронной вставки его можно не использовать и тем самым существенно сэкономить память. [#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлена поддержка параллельного чтения из движка таблицы YTsaurus. [#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Вместо жестко заданного значения 64 теперь используется размер строки кэша, зависящий от архитектуры. [#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
* Добавлена поддержка перестановки сторон соединений ANTI, SEMI и FULL на основе статистики оптимизатора. [#97498](https://github.com/ClickHouse/ClickHouse/pull/97498) ([Hechem Selmi](https://github.com/m-selmi)).
* Слегка оптимизировано чтение из словаря текстового индекса, что улучшает общую производительность анализа текстового индекса. [#97519](https://github.com/ClickHouse/ClickHouse/pull/97519) ([Anton Popov](https://github.com/CurtizJ)).
* Ускорена распаковка LZ4 для блоков размером 16 байт на ARM. [#97774](https://github.com/ClickHouse/ClickHouse/pull/97774) ([Raúl Marín](https://github.com/Algunenano)).
* Токенизация переведена на новый высокопроизводительный интерфейс обратного вызова forEachToken, заменяющий старый API в стиле итератора, чтобы поддерживать SIMD и токенизаторы с сохранением состояния. Часть [#90268](https://github.com/ClickHouse/ClickHouse/issues/90268). [#97871](https://github.com/ClickHouse/ClickHouse/pull/97871) ([Amos Bird](https://github.com/amosbird)).
* Улучшена производительность анализа текстового индекса для запросов с составными условиями, включающими как индексированные, так и неиндексированные столбцы. Ранее в таких случаях оптимизация раннего выхода при анализе индекса ошибочно отключалась. [#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).
* Повышена производительность запросов с константными выражениями, создающими очень длинные массивы или карты. [#98287](https://github.com/ClickHouse/ClickHouse/pull/98287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлен анализ условий по ключу для первичных ключей `DateTime64`, сравниваемых с целочисленными константами; ранее это приводило к отсутствию отсечения гранул. [#98410](https://github.com/ClickHouse/ClickHouse/pull/98410) ([Amos Bird](https://github.com/amosbird)).
* Параметр `optimize_syntax_fuse_functions` теперь включен по умолчанию. [#98424](https://github.com/ClickHouse/ClickHouse/pull/98424) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Теперь возможно отсечение партиций, если условие содержит любой оператор сравнения (`=`, `<`, `>`, `!=`), а ключ партиционирования обернут в цепочку детерминированных функций (например, при `PARTITION BY x` и условиях вроде `cityHash64(x) % 5 > 2`, `toYYYYMM(x) < 2026`, `toYYYYMM(x) = 2026` или `toYYYYMM(x) != 2026` во всех случаях будет использоваться ключ партиционирования для отсечения). Закрывает [#28800](https://github.com/ClickHouse/ClickHouse/issues/28800). [#98432](https://github.com/ClickHouse/ClickHouse/pull/98432) ([Nihal Z. Miaji](https://github.com/nihalzp)).
