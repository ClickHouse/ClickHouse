<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Бэкпортировано в [#98752](https://github.com/ClickHouse/ClickHouse/issues/98752): `async insert` теперь включён по умолчанию. Теперь ClickHouse будет по умолчанию объединять все небольшие вставки в батчи. Эта настройка задаётся через `compatibility`. Если установить `compatibility=<version less than 26.2>`, то значением по умолчанию останется прежнее — `false`. Вы можете включать или отключать `async inserts` на нескольких уровнях: в конфигурации, в профилях пользователей, для сеанса, для запроса или для таблицы семейства MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).

<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#98785](https://github.com/ClickHouse/ClickHouse/issues/98785): новая настройка `allow_nullable_tuple_in_extracted_subcolumns` управляет тем, возвращаются ли извлечённые подстолбцы `Tuple(...)` из `Tuple`, `Variant`, `Dynamic` и `JSON` как `Nullable(Tuple(...))` (`NULL` для отсутствующих строк) или как `Tuple(...)` (значения `Tuple` по умолчанию для отсутствующих строк). По умолчанию отключена; изменить эту настройку можно только перезапуском сервера. [#97299](https://github.com/ClickHouse/ClickHouse/pull/97299) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Бэкпортировано в [#98481](https://github.com/ClickHouse/ClickHouse/issues/98481): добавлена настройка сервера `jemalloc_profiler_sampling_rate` для управления `lg_prof_sample` в jemalloc; она также доступна как асинхронная метрика `jemalloc.prof.lg_sample`. [#97945](https://github.com/ClickHouse/ClickHouse/pull/97945) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#98488](https://github.com/ClickHouse/ClickHouse/issues/98488): добавлено новое событие профиля `KeeperRequestTotalWithSubrequests`, которое учитывает каждый подзапрос в составе мультизапроса отдельно, обеспечивая лучшую видимость фактической рабочей нагрузки Keeper. Существующее событие `KeeperRequestTotal` по-прежнему учитывает каждый мультизапрос как один запрос. [#98348](https://github.com/ClickHouse/ClickHouse/pull/98348) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#98749](https://github.com/ClickHouse/ClickHouse/issues/98749): в распределённом анализе индексов участвуют только «живые» реплики (то есть доступные для подключения). [#98521](https://github.com/ClickHouse/ClickHouse/pull/98521) ([Azat Khuzhin](https://github.com/azat)).

[#98555](https://github.com/ClickHouse/ClickHouse/pull/98555) ([Anton Popov](https://github.com/CurtizJ)).
* Бэкпортировано в [#98673](https://github.com/ClickHouse/ClickHouse/issues/98673): Исправлен распределённый анализ индексов для выражений (а не только столбцов) в PK (это приводило к отсутствию фильтрации лишних гранул на удалённых репликах). [#98561](https://github.com/ClickHouse/ClickHouse/pull/98561) ([Azat Khuzhin](https://github.com/azat)).
