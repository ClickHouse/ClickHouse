<div id="clickhouse-release-v24412088-stable-6d4b31322d1-fixme-as-compared-to-v24312672-lts-2c5c589a882">
  ### Релиз ClickHouse v24.4.1.2088-stable (6d4b31322d1) FIXME по сравнению с v24.3.1.2672-lts (2c5c589a882)

<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Запрещено устанавливать `max_parallel_replicas` в 0, так как это не имеет смысла. Установка значения 0 могла приводить к неожиданным логическим ошибкам. Закрывает [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140). [#61201](https://github.com/ClickHouse/ClickHouse/pull/61201) ([Kruglov Pavel](https://github.com/Avogar)).
* `clickhouse-odbc-bridge` и `clickhouse-library-bridge` — отдельные пакеты. Это закрывает [#61677](https://github.com/ClickHouse/ClickHouse/issues/61677). [#62114](https://github.com/ClickHouse/ClickHouse/pull/62114) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Удалена поддержка запроса INSERT WATCH (часть экспериментальной возможности LIVE VIEW). [#62382](https://github.com/ClickHouse/ClickHouse/pull/62382) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Удалена настройка optimize&#95;monotonous&#95;functions&#95;in&#95;order&#95;by. [#63004](https://github.com/ClickHouse/ClickHouse/pull/63004) ([Raúl Marín](https://github.com/Algunenano)).

<div id="new-feature">
  #### Новая возможность
</div>

* Теперь можно удалять несколько таблиц одновременно, например `drop table a,b,c`;. [#58705](https://github.com/ClickHouse/ClickHouse/pull/58705) ([zhongyuankai](https://github.com/zhongyuankai)).
* Теперь можно выдавать grant на движок таблицы, и это не повлияет на поведение существующих пользователей. [#60117](https://github.com/ClickHouse/ClickHouse/pull/60117) ([jsc0218](https://github.com/jsc0218)).
* Добавлен S3-диск с поддержкой перезаписи, который поддерживает операции INSERT и не требует локально хранимых метаданных. [#61116](https://github.com/ClickHouse/ClickHouse/pull/61116) ([Julia Kartseva](https://github.com/jkartseva)).
* Для удобства `SELECT * FROM numbers() `будет работать так же, как `SELECT * FROM system.numbers`, — без лимита. [#61969](https://github.com/ClickHouse/ClickHouse/pull/61969) ([YenchangChan](https://github.com/YenchangChan)).
* Теперь поддерживается изменение настроек таблицы memory через `ALTER MODIFY SETTING`. `ALTER TABLE memory MODIFY SETTING min_rows_to_keep = 100, max_rows_to_keep = 1000;`. [#62039](https://github.com/ClickHouse/ClickHouse/pull/62039) ([zhongyuankai](https://github.com/zhongyuankai)).
* Анализатор поддерживает рекурсивные CTE. [#62074](https://github.com/ClickHouse/ClickHouse/pull/62074) ([Maksim Kita](https://github.com/kitaisreal)).
* Анализатор поддерживает предложение QUALIFY. Закрывает [#47819](https://github.com/ClickHouse/ClickHouse/issues/47819). [#62619](https://github.com/ClickHouse/ClickHouse/pull/62619) ([Maksim Kita](https://github.com/kitaisreal)).
* В HTTP-интерфейс добавлен параметр запроса `role`. Он работает аналогично `SET ROLE x`, применяя роль перед выполнением оператора. Это позволяет обойти ограничение HTTP-интерфейса: он не допускает несколько операторов, поэтому невозможно одновременно отправить и `SET ROLE x`, и сам оператор. Таким способом можно задать несколько ролей, например `?role=x&role=y`, что эквивалентно `SET ROLE x, y`. [#62669](https://github.com/ClickHouse/ClickHouse/pull/62669) ([Serge Klochkov](https://github.com/slvrtrn)).
* Добавлен `SYSTEM UNLOAD PRIMARY KEY`. [#62738](https://github.com/ClickHouse/ClickHouse/pull/62738) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Снижены накладные расходы на мутации для SELECT-запросов (v2). [#60856](https://github.com/ClickHouse/ClickHouse/pull/60856) ([Azat Khuzhin](https://github.com/azat)).
* Более часто вызываемые функции в PODArray теперь принудительно встраиваются. [#61144](https://github.com/ClickHouse/ClickHouse/pull/61144) ([李扬](https://github.com/taiyang-li)).
* Улучшено проталкивание фильтров JOIN с использованием эквивалентных множеств. [#61216](https://github.com/ClickHouse/ClickHouse/pull/61216) ([Maksim Kita](https://github.com/kitaisreal)).
* По умолчанию включен быстрый кодировщик Parquet (`output_format_parquet_use_custom_encoder`). [#62088](https://github.com/ClickHouse/ClickHouse/pull/62088) ([Michael Kolupaev](https://github.com/al13n321)).
* ... Когда все необходимые поля прочитаны, все оставшиеся поля теперь пропускаются сразу, что позволяет значительно сократить число сравнений. [#62210](https://github.com/ClickHouse/ClickHouse/pull/62210) ([lgbo](https://github.com/lgbo-ustc)).
* Функции `splitByChar` и `splitByRegexp` были значительно ускорены. [#62392](https://github.com/ClickHouse/ClickHouse/pull/62392) ([李扬](https://github.com/taiyang-li)).
* Улучшена производительность простого INSERT SELECT из файлов в табличных функциях file/s3/hdfs/url/.... Добавлена отдельная настройка `max_parsing_threads` для управления числом потоков, используемых при параллельном разборе. [#62404](https://github.com/ClickHouse/ClickHouse/pull/62404) ([Kruglov Pavel](https://github.com/Avogar)).
* Добавлена поддержка параллельного буфера записи для AzureBlobStorage, управляемого настройкой `azure_allow_parallel_part_upload`. [#62534](https://github.com/ClickHouse/ClickHouse/pull/62534) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Функции `to_utc_timestamp` и `from_utc_timestamp` теперь работают примерно в 2 раза быстрее. [#62583](https://github.com/ClickHouse/ClickHouse/pull/62583) ([KevinyhZou](https://github.com/KevinyhZou)).
* Функции `parseDateTimeOrNull`, `parseDateTimeOrZero`, `parseDateTimeInJodaSyntaxOrNull` и `parseDateTimeInJodaSyntaxOrZero` теперь работают значительно быстрее (в 10–1000 раз), когда входные данные содержат в основном значения, которые не удаётся разобрать. [#62634](https://github.com/ClickHouse/ClickHouse/pull/62634) ([LiuNeng](https://github.com/liuneng1994)).
* SELECT-запросы к `system.query_cache` теперь выполняются заметно быстрее, когда query cache содержит много записей (например, более 100 000). [#62671](https://github.com/ClickHouse/ClickHouse/pull/62671) ([Robert Schulze](https://github.com/rschu1ze)).
* В QueryPlan добавлена оптимизация преобразования OUTER JOIN в INNER JOIN, если фильтр после JOIN всегда отбрасывает значения по умолчанию. Оптимизацией можно управлять с помощью настройки `query_plan_convert_outer_join_to_inner_join`; по умолчанию она включена. [#62907](https://github.com/ClickHouse/ClickHouse/pull/62907) ([Maksim Kita](https://github.com/kitaisreal)).
* По умолчанию включена оптимизация `optimize_rewrite_sum_if_to_count_if`. [#62929](https://github.com/ClickHouse/ClickHouse/pull/62929) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### Улучшения
</div>

* В конфигурации Kafka введены отдельные теги consumer/producer. Это позволяет избежать предупреждений librdkafka о том, что свойства consumer были указаны для экземпляров producer, и наоборот (например, `Configuration property session.timeout.ms is a consumer property and will be ignored by this producer instance`). Closes: [#58983](https://github.com/ClickHouse/ClickHouse/issues/58983). [#58956](https://github.com/ClickHouse/ClickHouse/pull/58956) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* В `system.text_log` добавлены столбцы `value1`, `value2`, ..., `value10`. Эти столбцы содержат значения, использованные для форматирования сообщения. [#59619](https://github.com/ClickHouse/ClickHouse/pull/59619) ([Alexey Katsman](https://github.com/alexkats)).
* Добавлена настройка `first_day_of_week`, которая влияет на то, какой день считается первым днем недели в функциях `toStartOfInterval(..., INTERVAL ... WEEK)`. Это обеспечивает согласованность с функцией `toStartOfWeek`, которая по умолчанию считает первым днем недели воскресенье. [#60598](https://github.com/ClickHouse/ClickHouse/pull/60598) ([Jordi Villar](https://github.com/jrdi)).
* Добавлен persistent virtual column `_block_offset`, который хранит исходный номер строки в block, присвоенный при вставке. Постоянное хранение столбца `_block_offset` можно включить с помощью настройки `enable_block_offset_column`. Добавлен virtual column `_part_data_version`, который содержит либо минимальный номер block, либо версию mutation части. Persistent virtual column `_block_number` больше не считается экспериментальным. [#60676](https://github.com/ClickHouse/ClickHouse/pull/60676) ([Anton Popov](https://github.com/CurtizJ)).
* Меньше конфликтов в файловом кэше (часть 3): удаление из файловой системы теперь выполняется без блокировки при попытке резервирования места. [#61163](https://github.com/ClickHouse/ClickHouse/pull/61163) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Функции `date_diff` и `age` теперь вычисляют результат с точностью до наносекунд, а не микросекунд. Кроме того, теперь они поддерживают `nanosecond` (или `nanoseconds`, или `ns`) в качестве возможного значения параметра `unit`. [#61409](https://github.com/ClickHouse/ClickHouse/pull/61409) ([Austin Kothig](https://github.com/kothiga)).
* Теперь marks не загружаются для часть Wide во время слияний. [#61551](https://github.com/ClickHouse/ClickHouse/pull/61551) ([Anton Popov](https://github.com/CurtizJ)).
* Цепочка сертификатов теперь перезагружается при перезагрузке сертификата. [#61671](https://github.com/ClickHouse/ClickHouse/pull/61671) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Ускорено динамическое изменение размера файлового кэша. [#61723](https://github.com/ClickHouse/ClickHouse/pull/61723) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлен `TRUNCATE ALL TABLES`. [#61862](https://github.com/ClickHouse/ClickHouse/pull/61862) ([豪肥肥](https://github.com/HowePa)).
* Предпринята попытка предотвратить [#60432](https://github.com/ClickHouse/ClickHouse/issues/60432): теперь нельзя присоединить таблицу, если для пути этой реплики уже есть активная реплика. [#61876](https://github.com/ClickHouse/ClickHouse/pull/61876) ([Arthur Passos](https://github.com/arthurpassos)).
* Добавлена настройка `input_format_json_throw_on_bad_escape_sequence`; ее отключение позволяет сохранять некорректные escape-последовательности в форматах ввода JSON. [#61889](https://github.com/ClickHouse/ClickHouse/pull/61889) ([Kruglov Pavel](https://github.com/Avogar)).
* Кэш страниц в пространстве пользователя теперь работает со статическим web-хранилищем (`disk(type = web)`). Для включения используйте client setting `use_page_cache_for_disks_without_file_cache=1`. [#61911](https://github.com/ClickHouse/ClickHouse/pull/61911) ([Michael Kolupaev](https://github.com/al13n321)).
* Реализован `input()` для clickhouse-local. [#61923](https://github.com/ClickHouse/ClickHouse/pull/61923) ([Azat Khuzhin](https://github.com/azat)).
* Исправлена логическая ошибка при откате транзакции кворумной вставки. [#61953](https://github.com/ClickHouse/ClickHouse/pull/61953) ([Han Fei](https://github.com/hanfei1991)).
* StorageJoin со strictness `ANY` теперь ведет себя согласованно после перезагрузки. Если вставлено несколько строк с одинаковым ключом, приоритет будет у первой из них (раньше при загрузке таблицы она выбиралась случайным образом). Закрывает [#51027](https://github.com/ClickHouse/ClickHouse/issues/51027). [#61972](https://github.com/ClickHouse/ClickHouse/pull/61972) ([vdimir](https://github.com/vdimir)).
* Автоматически определять Nullable типы столбцов по схеме Apache Arrow. [#61984](https://github.com/ClickHouse/ClickHouse/pull/61984) ([Maksim Kita](https://github.com/kitaisreal)).
* Разрешена отмена параллельного слияния состояний агрегатной функции во время агрегации. Пример: `uniqExact`. [#61992](https://github.com/ClickHouse/ClickHouse/pull/61992) ([Maksim Kita](https://github.com/kitaisreal)).
* Не считать варианты Bool и числовые варианты подозрительными в типе Variant. [#61999](https://github.com/ClickHouse/ClickHouse/pull/61999) ([Kruglov Pavel](https://github.com/Avogar)).
* Использовать `system.keywords` для заполнения подсказок, а также использовать их во всех внутренних местах. [#62000](https://github.com/ClickHouse/ClickHouse/pull/62000) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Реализовано более качественное преобразование из String в Variant с использованием синтаксического разбора. [#62005](https://github.com/ClickHouse/ClickHouse/pull/62005) ([Kruglov Pavel](https://github.com/Avogar)).
* Добавлена поддержка Variant в функциях JSONExtract. [#62014](https://github.com/ClickHouse/ClickHouse/pull/62014) ([Kruglov Pavel](https://github.com/Avogar)).
* Источник словаря с `INVALIDATE_QUERY` больше не перезагружается дважды при запуске. [#62050](https://github.com/ClickHouse/ClickHouse/pull/62050) ([vdimir](https://github.com/vdimir)).
* `OPTIMIZE FINAL` для `ReplicatedMergeTree` теперь будет ждать завершения текущих активных слияний, а затем повторно попытается запланировать финальное слияние. Это приближает его поведение к обычному поведению `MergeTree`. [#62067](https://github.com/ClickHouse/ClickHouse/pull/62067) ([Nikita Taranov](https://github.com/nickitat)).
* При чтении данных из Hive Text File первая строка файла использовалась для определения количества входных полей, и иногда число полей в первой строке не совпадало с определением Hive table; например, Hive table может быть определена с 3 столбцами, как `test_tbl(a Int32, b Int32, c Int32)`, а первая строка текстового файла содержит только 2 поля. В такой ситуации количество входных полей уменьшалось до 2, и если следующая строка текстового файла содержала 3 поля, то третье поле не считывалось, а вместо него устанавливалось значение по умолчанию 0, что неверно. [#62086](https://github.com/ClickHouse/ClickHouse/pull/62086) ([KevinyhZou](https://github.com/KevinyhZou)).
* CREATE AS копирует комментарий. [#62117](https://github.com/ClickHouse/ClickHouse/pull/62117) ([Pablo Marcos](https://github.com/pamarcos)).
* Подсветка синтаксиса при наборе текста в client будет работать на уровне синтаксиса (раньше она работала на уровне лексера). [#62123](https://github.com/ClickHouse/ClickHouse/pull/62123) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлена проблема, из-за которой при добавлении лишнего `= 1` или `= 0` после булевого выражения с primary key не использовался primary index. Например, и `SELECT * FROM <table> WHERE <primary-key> IN (<value>) = 1`, и `SELECT * FROM <table> WHERE <primary-key> NOT IN (<value>) = 0` выполняли полное сканирование таблицы, хотя можно было использовать primary index. [#62142](https://github.com/ClickHouse/ClickHouse/pull/62142) ([josh-hildred](https://github.com/josh-hildred)).
* Добавлен прогресс запроса в таблицу zookeeper. [#62152](https://github.com/ClickHouse/ClickHouse/pull/62152) ([JackyWoo](https://github.com/JackyWoo)).
* Добавлена возможность включать collector трассировок (Real и CPU) на уровне всего сервера. [#62189](https://github.com/ClickHouse/ClickHouse/pull/62189) ([alesapin](https://github.com/alesapin)).
* Добавлена настройка `lightweight_deletes_sync` (значение по умолчанию: 2 — синхронное ожидание всех реплик). Она похожа на настройку `mutations_sync`, но влияет только на поведение легковесных удалений. [#62195](https://github.com/ClickHouse/ClickHouse/pull/62195) ([Anton Popov](https://github.com/CurtizJ)).
* Добавлено различение булевых значений и целых чисел при разборе значений пользовательских настроек: `SET custom_a = true; SET custom_b = 1;`. [#62206](https://github.com/ClickHouse/ClickHouse/pull/62206) ([Vitaly Baranov](https://github.com/vitlibar)).
* Добавлена поддержка доступа к S3 через конечные точки интерфейса AWS Private Link. Закрывает [#60021](https://github.com/ClickHouse/ClickHouse/issues/60021), [#31074](https://github.com/ClickHouse/ClickHouse/issues/31074) и [#53761](https://github.com/ClickHouse/ClickHouse/issues/53761). [#62208](https://github.com/ClickHouse/ClickHouse/pull/62208) ([Arthur Passos](https://github.com/arthurpassos)).
* Клиент должен отправлять серверу заголовок &#39;Keep-Alive: timeout=X&#39;. Если клиент получает от сервера ответ с этим заголовком, он должен использовать значение, полученное от сервера. Кроме того, клиенту лучше не использовать connection, у которого скоро истечёт срок действия, чтобы избежать гонки при закрытии connection. [#62249](https://github.com/ClickHouse/ClickHouse/pull/62249) ([Sema Checherinda](https://github.com/CheSema)).
* Для date&#95;trunc добавлены единицы нано-, микро- и миллисекунд. [#62335](https://github.com/ClickHouse/ClickHouse/pull/62335) ([Misz606](https://github.com/Misz606)).
* clickhouse-client больше не создаёт каталог для UDF, если он не существует. Это закрывает [#59597](https://github.com/ClickHouse/ClickHouse/issues/59597). [#62366](https://github.com/ClickHouse/ClickHouse/pull/62366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Кэш запросов больше не кэширует результаты запросов к системным таблицам (`system.*`, `information_schema.*`, `INFORMATION_SCHEMA.*`). [#62376](https://github.com/ClickHouse/ClickHouse/pull/62376) ([Robert Schulze](https://github.com/rschu1ze)).
* Запрос `MOVE PARTITION TO TABLE` может быть отложен или может сгенерировать исключение `TOO_MANY_PARTS`, чтобы избежать превышения ограничений на число частей. Применяются те же настройки и ограничения, что и для запроса `INSERT` (см. настройки `max_parts_in_total`, `parts_to_delay_insert`, `parts_to_throw_insert`, `inactive_parts_to_throw_insert`, `inactive_parts_to_delay_insert`, `max_avg_part_size_for_too_many_parts`, `min_delay_to_insert_ms` и `max_delay_to_insert`). [#62420](https://github.com/ClickHouse/ClickHouse/pull/62420) ([Sergei Trifonov](https://github.com/serxa)).
* В системную таблицу `blob_storage_log` добавлен отсутствовавший столбец `hostname`. [#62456](https://github.com/ClickHouse/ClickHouse/pull/62456) ([Jayme Bird](https://github.com/jaymebrd)).
* Изменён каталог установки по умолчанию в macOS: с `/usr/bin` на `/usr/local/bin`. Это необходимо, потому что System Integrity Protection от Apple, представленная в macOS El Capitan (2015), запрещает запись в `/usr/bin` даже с `sudo`. [#62489](https://github.com/ClickHouse/ClickHouse/pull/62489) ([haohang](https://github.com/yokofly)).
* Теперь transform всегда возвращает первое совпадение. [#62518](https://github.com/ClickHouse/ClickHouse/pull/62518) ([Raúl Marín](https://github.com/Algunenano)).
* Для единообразия с другими системными таблицами в `system.backup_log` теперь есть столбец `event_time`. [#62541](https://github.com/ClickHouse/ClickHouse/pull/62541) ([Jayme Bird](https://github.com/jaymebrd)).
* Не вычислять DEFAULT-выражения таблицы при выполнении `RESTORE`. [#62601](https://github.com/ClickHouse/ClickHouse/pull/62601) ([Vitaly Baranov](https://github.com/vitlibar)).
* Возвращать поток фрагментов из `system.remote_data_paths` вместо накопления всего результата в одном большом фрагменте. Это позволяет использовать меньше памяти, отображать промежуточный прогресс и отменять запрос.
