<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Запрещено устанавливать max&#95;parallel&#95;replicas в 0, так как это не имеет смысла. Установка значения 0 могла приводить к неожиданным логическим ошибкам. Закрывает [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140). [#60430](https://github.com/ClickHouse/ClickHouse/pull/60430) ([Kruglov Pavel](https://github.com/Avogar)).
* Имя столбца `duration_ms` в таблице `system.zookeeper` изменено на `duration_microseconds`, чтобы отразить тот факт, что длительность измеряется с разрешением в микросекунды. [#60774](https://github.com/ClickHouse/ClickHouse/pull/60774) ([Duc Canh Le](https://github.com/canhld94)).
* Отклонять входящие INSERT-запросы, если настройки уровня запроса `async_insert` и `deduplicate_blocks_in_dependent_materialized_views` включены одновременно. Это поведение управляется настройкой `throw_if_deduplication_in_dependent_materialized_views_enabled_with_async_insert` и включено по умолчанию. Это продолжение [https://github.com/ClickHouse/ClickHouse/pull/59699](https://github.com/ClickHouse/ClickHouse/pull/59699), необходимое для разблокировки [https://github.com/ClickHouse/ClickHouse/pull/59915](https://github.com/ClickHouse/ClickHouse/pull/59915). [#60888](https://github.com/ClickHouse/ClickHouse/pull/60888) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Утилита `clickhouse-copier` перенесена в отдельный репозиторий на GitHub: [https://github.com/ClickHouse/copier](https://github.com/ClickHouse/copier). Она больше не входит в дистрибутив, но по-прежнему доступна для отдельной загрузки. * Для повышения совместимости с MySQL функция `locate` теперь по умолчанию принимает аргументы `(needle, haystack[, start_pos])`. Предыдущее поведение `(haystack, needle, [, start_pos])` можно восстановить, установив `function_locate_has_mysql_compatible_argument_order = 0`. [#61092](https://github.com/ClickHouse/ClickHouse/pull/61092) ([Robert Schulze](https://github.com/rschu1ze)).
* Устаревшие части данных в памяти были помечены как deprecated начиная с версии 23.5 и перестали поддерживаться с версии 23.10. Теперь оставшийся код удалён. Продолжение [#55186](https://github.com/ClickHouse/ClickHouse/issues/55186) и [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409). Маловероятно, что вы использовали части данных в памяти, поскольку они были доступны только до версии 23.5 и только при их ручном включении через соответствующие SETTINGS для таблицы семейства MergeTree. Чтобы проверить, есть ли у вас части данных в памяти, выполните следующий запрос: `SELECT part_type, count() FROM system.parts GROUP BY part_type ORDER BY part_type`. Чтобы отключить использование частей данных в памяти, выполните `ALTER TABLE ... MODIFY SETTING min_bytes_for_compact_part = DEFAULT, min_rows_for_compact_part = DEFAULT`. Перед обновлением со старых релизов ClickHouse сначала убедитесь, что у вас нет частей данных в памяти. Если такие части данных есть, сначала отключите их, затем дождитесь, пока частей данных в памяти не останется, и продолжайте обновление. [#61127](https://github.com/ClickHouse/ClickHouse/pull/61127) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* По умолчанию запретить `SimpleAggregateFunction` в `ORDER BY` таблиц `MergeTree` (как и `AggregateFunction`, поскольку эти типы нельзя сравнивать) (чтобы разрешить их, используйте `allow_suspicious_primary_key`). [#61399](https://github.com/ClickHouse/ClickHouse/pull/61399) ([Azat Khuzhin](https://github.com/azat)).
* ClickHouse допускает произвольные бинарные данные в типе данных String, который обычно содержит UTF-8. Типы String в Parquet/ORC/Arrow поддерживают только UTF-8. Поэтому для типа данных String в ClickHouse можно выбрать, какой тип данных Arrow использовать — String или Binary. Это управляется настройками `output_format_parquet_string_as_string`, `output_format_orc_string_as_string`, `output_format_arrow_string_as_string`. Хотя Binary был бы более корректным и совместимым вариантом, использование String по умолчанию в большинстве случаев лучше соответствует ожиданиям пользователей. Parquet/ORC/Arrow поддерживает множество методов сжатия, включая lz4 и zstd. ClickHouse поддерживает все эти методы сжатия. В некоторых менее совершенных инструментах отсутствует поддержка более быстрого метода сжатия `lz4`, поэтому по умолчанию мы используем `zstd`. Это управляется настройками `output_format_parquet_compression_method`, `output_format_orc_compression_method` и `output_format_arrow_compression_method`. Мы изменили значение по умолчанию на `zstd` для Parquet и ORC, но не для Arrow (он ориентирован на низкоуровневые сценарии использования). [#61817](https://github.com/ClickHouse/ClickHouse/pull/61817) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* В новой версии ClickHouse функции `geoDistance`, `greatCircleDistance` и `greatCircleAngle` будут использовать для внутренних вычислений и возвращаемого типа 64-битный тип данных с плавающей точкой двойной точности, если все аргументы имеют тип Float64. Это закрывает [#58476](https://github.com/ClickHouse/ClickHouse/issues/58476). В предыдущих версиях функция всегда использовала Float32. Вы можете вернуться к прежнему поведению, установив `geo_distance_returns_float64_on_float64_arguments` в `false` или `compatibility` в `24.2` либо более раннюю версию. [#61848](https://github.com/ClickHouse/ClickHouse/pull/61848) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Улучшена производительность сериализованного метода агрегации при использовании нескольких столбцов [nullable]. Это обобщённая версия [#51399](https://github.com/ClickHouse/ClickHouse/issues/51399), которая не нарушает целостность абстракции. [#55809](https://github.com/ClickHouse/ClickHouse/pull/55809) ([Amos Bird](https://github.com/amosbird)).
* Отложенное построение результата JOIN для повышения производительности ALL JOIN. [#58278](https://github.com/ClickHouse/ClickHouse/pull/58278) ([LiuNeng](https://github.com/liuneng1994)).
* Улучшения агрегатных функций ArgMin / ArgMax / any / anyLast / anyHeavy, а также запросов `ORDER BY {u8/u16/u32/u64/i8/i16/u32/i64) LIMIT 1`. [#58640](https://github.com/ClickHouse/ClickHouse/pull/58640) ([Raúl Marín](https://github.com/Algunenano)).
* Небольшая оптимизация фильтрации по столбцам. Исключена фильтрация с `result_size_hint = -1` для столбцов фильтра, базовый тип данных которых не является числовым. В некоторых случаях пиковое потребление памяти может быть снижено до 44% от исходного. [#59698](https://github.com/ClickHouse/ClickHouse/pull/59698) ([李扬](https://github.com/taiyang-li)).
* Если первичный ключ таблицы содержит в основном бесполезные столбцы, их не нужно хранить в памяти. Это управляется новой настройкой `primary_key_ratio_of_unique_prefix_values_to_skip_suffix_columns` со значением `0.9` по умолчанию, что означает: для составного первичного ключа, если столбец меняет своё значение как минимум в 0.9 всех случаев, следующие за ним столбцы загружаться не будут. [#60255](https://github.com/ClickHouse/ClickHouse/pull/60255) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Выполнять функцию multiIf в столбцовом представлении, когда базовый тип `result_type` является числовым. [#60384](https://github.com/ClickHouse/ClickHouse/pull/60384) ([李扬](https://github.com/taiyang-li)).
* Мьютексы стали почти в 2 раза быстрее (раньше были медленнее из-за ThreadFuzzer). [#60823](https://github.com/ClickHouse/ClickHouse/pull/60823) ([Azat Khuzhin](https://github.com/azat)).
* Перенесено освобождение соединений из prepare в work, а также добавлено освобождение нескольких соединений параллельно. [#60845](https://github.com/ClickHouse/ClickHouse/pull/60845) ([lizhuoyu5](https://github.com/lzydmxy)).
* Оптимизирована insertManyFrom для nullable number и nullable string. [#60846](https://github.com/ClickHouse/ClickHouse/pull/60846) ([李扬](https://github.com/taiyang-li)).
* Оптимизирована функция `dotProduct`, чтобы исключить ненужные и дорогостоящие копирования памяти. [#60928](https://github.com/ClickHouse/ClickHouse/pull/60928) ([Robert Schulze](https://github.com/rschu1ze)).
* Операции с файловым кэшем будут меньше страдать от конкуренции за блокировку. [#61066](https://github.com/ClickHouse/ClickHouse/pull/61066) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Оптимизированы ColumnString::replicate и предотвращено превращение memcpySmallAllowReadWriteOverflow15Impl во встроенный memcpy при оптимизации. Закрывает [#61074](https://github.com/ClickHouse/ClickHouse/issues/61074). ColumnString::replicate ускорена в 2.46 раза на x86-64. [#61075](https://github.com/ClickHouse/ClickHouse/pull/61075) ([李扬](https://github.com/taiyang-li)).
* Печать 256-битных целых чисел ускорена в 30 раз. [#61100](https://github.com/ClickHouse/ClickHouse/pull/61100) ([Raúl Marín](https://github.com/Algunenano)).
* Если запрос с синтаксической ошибкой содержал сопоставитель COLUMNS с регулярным выражением, это регулярное выражение компилировалось заново при каждом откате парсера, вместо однократной компиляции. Это была фундаментальная ошибка. Скомпилированный regexp помещался в AST. Но буква A в AST означает &quot;abstract&quot;, то есть он не должен содержать тяжеловесные объекты. Части AST могут создаваться и отбрасываться в процессе парсинга, в том числе при большом количестве откатов. Это замедляет парсинг и, как следствие, позволяет пользователю с правами только для чтения вызвать DoS. Но главная проблема в том, что это мешает прогрессу фаззеров. [#61543](https://github.com/ClickHouse/ClickHouse/pull/61543) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлен новый проход analyzer для оптимизации IN с одним значением. [#61564](https://github.com/ClickHouse/ClickHouse/pull/61564) ([LiuNeng](https://github.com/liuneng1994)).

<div id="improvement">
  #### Улучшения
</div>

* При выполнении запроса MODIFY COLUMN для materialized view проверяйте структуру внутренней таблицы, чтобы убедиться, что в ней присутствуют все столбцы. [#47427](https://github.com/ClickHouse/ClickHouse/pull/47427) ([sunny](https://github.com/sunny19930321)).
* Добавлена таблица `system.keywords`, содержащая все ключевые слова из парсера. В первую очередь она нужна и будет использоваться для более качественного фаззинга и подсветки синтаксиса. [#51808](https://github.com/ClickHouse/ClickHouse/pull/51808) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

[#56942](https://github.com/ClickHouse/ClickHouse/pull/56942) ([shabroo](https://github.com/shabroo)).
* Все блокировки zero copy, связанные с таблицей, должны удаляться при удалении таблицы. Каталог, содержащий эти блокировки, также должен быть удалён. [#57575](https://github.com/ClickHouse/ClickHouse/pull/57575) ([Sema Checherinda](https://github.com/CheSema)).
* Разрешено объявлять enum в структуре external table. [#57857](https://github.com/ClickHouse/ClickHouse/pull/57857) ([Duc Canh Le](https://github.com/canhld94)).
* Учитывать строки, помеченные легковесным удалением, при выборе частей для слияния. [#58223](https://github.com/ClickHouse/ClickHouse/pull/58223) ([Zhuo Qiu](https://github.com/jewelzqiu)).
* Этот PR позволяет повторно использовать HTTP/HTTPS-соединения во всех сценариях. Даже если ответ имеет статус 3xx или 4xx. [#58845](https://github.com/ClickHouse/ClickHouse/pull/58845) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлены комментарии к столбцам ещё в большем числе системных таблиц. Продолжение [https://github.com/ClickHouse/ClickHouse/pull/58356](https://github.com/ClickHouse/ClickHouse/pull/58356). [#59016](https://github.com/ClickHouse/ClickHouse/pull/59016) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Теперь виртуальные столбцы можно использовать в PREWHERE. Это особенно полезно для неконстантных виртуальных столбцов, таких как `_part_offset`. [#59033](https://github.com/ClickHouse/ClickHouse/pull/59033) ([Amos Bird](https://github.com/amosbird)).
* Добавлена возможность пропускать реплики в режиме только для чтения при INSERT в движок Distributed (управляется настройкой `distributed_insert_skip_read_only_replicas`, по умолчанию OFF — для обратной совместимости). [#59176](https://github.com/ClickHouse/ClickHouse/pull/59176) ([Azat Khuzhin](https://github.com/azat)).
* Вместо использования фиксированного ключа объектное хранилище теперь генерирует ключ для определения возможности удаления объектов. [#59495](https://github.com/ClickHouse/ClickHouse/pull/59495) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлен позиционный pread в libhdfs3. Если вы хотите вызвать позиционное чтение в libhdfs3, используйте функцию hdfsPread из hdfs.h следующим образом: `tSize hdfsPread(hdfsFS fs, hdfsFile file, void * buffer, tSize length, tOffset position);`. [#59624](https://github.com/ClickHouse/ClickHouse/pull/59624) ([M1eyu](https://github.com/M1eyu2018)).
* Добавлен асинхронный WriteBuffer для AzureBlobStorage, аналогичный S3. [#59929](https://github.com/ClickHouse/ClickHouse/pull/59929) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Разрешено использовать &quot;local&quot; в качестве типа объектного хранилища вместо &quot;local&#95;blob&#95;storage&quot;. [#60165](https://github.com/ClickHouse/ClickHouse/pull/60165) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Улучшено общее удобство работы с виртуальными столбцами. Теперь виртуальные столбцы можно использовать в `PREWHERE` (это особенно полезно для неконстантных виртуальных столбцов, таких как `_part_offset`). Кроме того, теперь доступна встроенная документация по виртуальным столбцам в виде комментария к столбцу в запросе `DESCRIBE` при включенной настройке `describe_include_virtual_columns`. [#60205](https://github.com/ClickHouse/ClickHouse/pull/60205) ([Anton Popov](https://github.com/CurtizJ)).
