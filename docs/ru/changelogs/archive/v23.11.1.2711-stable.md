  ### Релиз ClickHouse v23.11.1.2711-стабильный (05bc8ef1e02) FIXME в сравнении с v23.10.1.1976-стабильный (13adae0e42f)

<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Форматтеры `%l`/`%k`/`%c` в функции `parseDateTime()` теперь могут разбирать часы/месяцы без ведущих нулей; например, теперь работает `select parseDateTime('2023-11-26 8:14', '%F %k:%i')`. Установите `parsedatetime_parse_without_leading_zeros = 0`, чтобы восстановить прежнее поведение, при котором требовалось двузначное значение. Функция `formatDateTime` теперь также может выводить часы/месяцы без ведущих нулей. Это управляется настройкой `formatdatetime_format_without_leading_zeros`, но по умолчанию она отключена, чтобы не нарушать существующие сценарии использования. [#55872](https://github.com/ClickHouse/ClickHouse/pull/55872) ([Azat Khuzhin](https://github.com/azat)).
* Больше нельзя использовать агрегатную функцию `avgWeighted` с аргументами типа `Decimal`. Обходной путь: преобразовать аргументы в `Float64`. Это закрывает [#43928](https://github.com/ClickHouse/ClickHouse/issues/43928). Это закрывает [#31768](https://github.com/ClickHouse/ClickHouse/issues/31768). Это закрывает [#56435](https://github.com/ClickHouse/ClickHouse/issues/56435). Если вы использовали эту функцию внутри materialized view или проекций с аргументами `Decimal`, обратитесь в службу поддержки: support@clickhouse.com. Исправлена ошибка в агрегатной функции `sumMap`, из-за чего она стала работать примерно в 1.5..2 раза медленнее. Это не имеет значения, потому что функция всё равно мусорная. Это закрывает [#54955](https://github.com/ClickHouse/ClickHouse/issues/54955). Это закрывает [#53134](https://github.com/ClickHouse/ClickHouse/issues/53134). Это закрывает [#55148](https://github.com/ClickHouse/ClickHouse/issues/55148). Исправлена ошибка в функции `groupArraySample` — она использовала одно и то же начальное значение генератора случайных чисел, если в запросе создавалось более одного агрегатного состояния. [#56350](https://github.com/ClickHouse/ClickHouse/pull/56350) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* В стандартном файле конфигурации сервера ClickHouse для пользователя `default` теперь по умолчанию включены `access_management` (управление пользователями с помощью SQL-запросов) и `named_collection_control` (управление именованной коллекцией с помощью SQL-запросов). Это закрывает [#56482](https://github.com/ClickHouse/ClickHouse/issues/56482). [#56619](https://github.com/ClickHouse/ClickHouse/pull/56619) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Несколько улучшений для RESPECT/IGNORE NULLS. [#57189](https://github.com/ClickHouse/ClickHouse/pull/57189) ([Raúl Marín](https://github.com/Algunenano)).
* Удалена оптимизация optimize&#95;move&#95;functions&#95;out&#95;of&#95;any. [#57190](https://github.com/ClickHouse/ClickHouse/pull/57190) ([Raúl Marín](https://github.com/Algunenano)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Поддерживается параллельное вычисление оконных функций. Исправлено [#34688](https://github.com/ClickHouse/ClickHouse/issues/34688). [#39631](https://github.com/ClickHouse/ClickHouse/pull/39631) ([Dmitry Novik](https://github.com/novikd)).
* Значение `max_concurrent_queries` по умолчанию увеличено со 100 до 1000. Это оправданно при большом числе подключающихся клиентов, которые медленно отправляют или получают данные, так что server не ограничен CPU, а также когда число ядер CPU превышает 100. Кроме того, теперь по умолчанию включен контроль параллелизма, а желаемое общее число потоков для обработки запросов установлено равным удвоенному числу ядер CPU. Это повышает производительность в сценариях с очень большим количеством параллельных запросов. [#46927](https://github.com/ClickHouse/ClickHouse/pull/46927) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлена фильтрация по условию `IN(...)` для движка таблицы `Merge`. [#54905](https://github.com/ClickHouse/ClickHouse/pull/54905) ([Nikita Taranov](https://github.com/nickitat)).
* Улучшение для случаев, когда кэш заполнен и выполняются большие чтения. [#55158](https://github.com/ClickHouse/ClickHouse/pull/55158) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлена возможность отключать checksums для S3, чтобы избежать избыточного чтения входного файла (это новое поведение можно включить с помощью `s3_disable_checksum=true`). [#55559](https://github.com/ClickHouse/ClickHouse/pull/55559) ([Azat Khuzhin](https://github.com/azat)).
* Теперь данные из удаленных таблиц читаются синхронно, если они находятся в page cache (как и для локальных таблиц). Это быстрее, не требует синхронизации внутри пула потоков, не боится выполнять `seek` в локальной fs и снижает ожидание CPU. [#55841](https://github.com/ClickHouse/ClickHouse/pull/55841) ([Nikita Taranov](https://github.com/nickitat)).
* ... Этот PR продолжает [#55929](https://github.com/ClickHouse/ClickHouse/issues/55929) и даст ускорение примерно на 30%. - уменьшен объем зарезервированной памяти - сокращено число вызовов `resize`. [#55957](https://github.com/ClickHouse/ClickHouse/pull/55957) ([lgbo](https://github.com/lgbo-ustc)).
* Эксперименты по производительности **OnTime** на устройстве ICX (Intel Xeon Platinum 8380 CPU, 80 cores, 160 threads) показывают, что это изменение может дать прирост **7.4%, 5.9%, 4.7%, 3.0% и 4.6%** для QPS запросов Q2, Q3, Q4, Q5 и Q6 соответственно, не влияя на остальные. [#56079](https://github.com/ClickHouse/ClickHouse/pull/56079) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Ограничено число потоков, занятых внутри query profiler. Если их больше, они будут пропускать сбор данных профилирования. [#56105](https://github.com/ClickHouse/ClickHouse/pull/56105) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WindowTransform уменьшает количество вызовов virtual function. [#56120](https://github.com/ClickHouse/ClickHouse/pull/56120) ([Maksim Kita](https://github.com/kitaisreal)).
* Разрешено рекурсивное pruning полей Tuple в ORC для ускорения сканирования. [#56122](https://github.com/ClickHouse/ClickHouse/pull/56122) ([李扬](https://github.com/taiyang-li)).

Теперь с настройкой `optimize_count_from_files=1` запросы вида `select count() from file(data.npy)` будут работать значительно быстрее благодаря кэшированию результатов. * Улучшена производительность выполнения запросов в сценариях с большим числом пользователей. [#57106](https://github.com/ClickHouse/ClickHouse/pull/57106) ([Andrej Hoos](https://github.com/adikus)).
