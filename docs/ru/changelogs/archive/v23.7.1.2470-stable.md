<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Добавлен тип доступа ` NAMED COLLECTION` (псевдонимы `USE NAMED COLLECTION`, `NAMED COLLECTION USAGE`). Этот PR обратно несовместим, поскольку данный тип доступа по умолчанию отключён (поскольку родительский тип доступа `NAMED COLLECTION ADMIN` также по умолчанию отключён). Предложено в [#50277](https://github.com/ClickHouse/ClickHouse/issues/50277). Чтобы выдать доступ, используйте `GRANT NAMED COLLECTION ON collection_name TO user` или `GRANT NAMED COLLECTION ON * TO user`; для возможности выдавать эти привилегии в config требуется `named_collection_admin` (ранее он назывался `named_collection_control`, поэтому останется как псевдоним). [#50625](https://github.com/ClickHouse/ClickHouse/pull/50625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Исправлена опечатка в имени столбца `system.parts` — `last_removal_attemp_time`. Теперь он называется `last_removal_attempt_time`. [#52104](https://github.com/ClickHouse/ClickHouse/pull/52104) ([filimonov](https://github.com/filimonov)).
* Версия distributed&#95;ddl&#95;entry&#95;format&#95;version по умолчанию повышена до 5 (это включает сквозную передачу OpenTelemetry и initial&#95;query&#95;idd). После **понижения версии** это не позволит обрабатывать существующие записи distributed DDL (но обратите внимание, что обычно таких необработанных записей быть не должно). [#52128](https://github.com/ClickHouse/ClickHouse/pull/52128) ([Azat Khuzhin](https://github.com/azat)).
* Метаданные проекций теперь проверяются так же, как и обычные метаданные. Это изменение может помешать запуску сервера, если в таблице есть некорректная проекция. Например, проекция, создающая позиционные столбцы в PK (например, `projection p (select * order by 1, 4)`, что недопустимо для PK таблицы и может вызвать сбой во время вставки/слияния). Удалите такие проекции перед обновлением. Исправляет [#52353](https://github.com/ClickHouse/ClickHouse/issues/52353). [#52361](https://github.com/ClickHouse/ClickHouse/pull/52361) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Экспериментальная возможность `hashid` удалена из-за ошибки. Качество реализации с самого начала вызывало сомнения, и она так и не вышла из экспериментального статуса. Это закрывает [#52406](https://github.com/ClickHouse/ClickHouse/issues/52406). [#52449](https://github.com/ClickHouse/ClickHouse/pull/52449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Функция `toDecimalString` удалена из-за недостаточного качества реализации. Это закрывает [#52407](https://github.com/ClickHouse/ClickHouse/issues/52407). [#52450](https://github.com/ClickHouse/ClickHouse/pull/52450) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* По умолчанию включены настройки `move_all_conditions_to_prewhere` и `enable_multiple_prewhere_read_steps`. [#46365](https://github.com/ClickHouse/ClickHouse/pull/46365) ([Alexander Gololobov](https://github.com/davenger)).
* Повышена производительность некоторых запросов за счёт настройки allocator. [#46416](https://github.com/ClickHouse/ClickHouse/pull/46416) ([Azat Khuzhin](https://github.com/azat)).
* Запись файлов Parquet теперь выполняется в 10 раз быстрее: она стала многопоточной. Скорость теперь почти такая же, как при чтении. [#49367](https://github.com/ClickHouse/ClickHouse/pull/49367) ([Michael Kolupaev](https://github.com/al13n321)).
* По умолчанию включён автоматический выбор формата разреженной сериализации. Это повышает производительность. Формат поддерживается начиная с версии 22.1. После этого изменения откат на версии старее 22.1 может оказаться невозможным. Вы можете отключить использование формата разреженной сериализации, указав настройку `ratio_of_defaults_for_sparse_serialization = 1` для ваших таблиц семейства MergeTree. [#49631](https://github.com/ClickHouse/ClickHouse/pull/49631) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Теперь в `MergeTreePrefetchedReadPool`, как и в `MergeTreeReadPool`, используются задачи фиксированного размера. Кроме того, теперь для запросов к S3 используется пул соединений. [#49732](https://github.com/ClickHouse/ClickHouse/pull/49732) ([Nikita Taranov](https://github.com/nickitat)).
* Расширен pushdown на правую сторону JOIN. [#50532](https://github.com/ClickHouse/ClickHouse/pull/50532) ([Nikita Taranov](https://github.com/nickitat)).
* Улучшен grace&#95;hash JOIN за счёт предварительного резервирования размера хеш-таблицы (повторное внесение). [#50875](https://github.com/ClickHouse/ClickHouse/pull/50875) ([lgbo](https://github.com/lgbo-ustc)).
* Ожидание блокировки в `OpenedFileCache` иногда могло быть заметным. Чтобы избежать конкуренции за блокировки, мы разбили его на несколько подмап, каждая со своей собственной блокировкой. [#51341](https://github.com/ClickHouse/ClickHouse/pull/51341) ([Nikita Taranov](https://github.com/nickitat)).
* Удалено дублирующееся условие в functionunixtimestamp64.h. [#51857](https://github.com/ClickHouse/ClickHouse/pull/51857) ([lcjh](https://github.com/ljhcage)).
* Идея в том, что условия со столбцами PK, скорее всего, будут использоваться при анализе PK и дадут лишь небольшой дополнительный эффект для фильтрации PREWHERE. [#51958](https://github.com/ClickHouse/ClickHouse/pull/51958) ([Alexander Gololobov](https://github.com/davenger)).
* 1. Добавлен механизм переписывания запросов для старого и нового анализатора. 2. Добавлена настройка `optimize_uniq_to_count`, значение по умолчанию — 0. [#52004](https://github.com/ClickHouse/ClickHouse/pull/52004) ([JackyWoo](https://github.com/JackyWoo)).
* Эксперименты по производительности **OnTime** на устройстве ICX (Intel Xeon Platinum 8380 CPU, 80 ядер, 160 потоков) показывают, что это изменение может повысить QPS запроса **Q8** на **11,6%** без влияния на остальные запросы. [#52036](https://github.com/ClickHouse/ClickHouse/pull/52036) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* `allow_vertical_merges_from_compact_to_wide_parts` теперь включена по умолчанию. Это позволит снизить использование памяти при слияниях. [#52295](https://github.com/ClickHouse/ClickHouse/pull/52295) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлен некорректный анализ проекций, из-за которого первичные ключи становились недействительными. Эта проблема возникает только при `query_plan_optimize_primary_key = 1, query_plan_optimize_projection = 1` . Это исправляет [#48823](https://github.com/ClickHouse/ClickHouse/issues/48823) . Это исправляет [#51173](https://github.com/ClickHouse/ClickHouse/issues/51173) . [#52308](https://github.com/ClickHouse/ClickHouse/pull/52308) ([Amos Bird](https://github.com/amosbird)).
* Уменьшено количество системных вызовов в FileCache::loadMetadata. [#52435](https://github.com/ClickHouse/ClickHouse/pull/52435) ([Raúl Marín](https://github.com/Algunenano)).

Настройка `async_insert_threads` теперь тоже является серверной. [#49160](https://github.com/ClickHouse/ClickHouse/pull/49160) ([Anton Popov](https://github.com/CurtizJ)).

[#49342](https://github.com/ClickHouse/ClickHouse/pull/49342) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Разрешена фильтрация HTTP-заголовков с помощью секции `http_forbid_headers` в конфигурации. Доступны как точное совпадение, так и фильтры на основе регулярных выражений. [#51038](https://github.com/ClickHouse/ClickHouse/pull/51038) ([Nikolay Degterinsky](https://github.com/evillique)).
* В #50727 добавлен новый alias для функции current&#95;database и новая функция current&#95;schemas. [#51076](https://github.com/ClickHouse/ClickHouse/pull/51076) ([Pedro Riera](https://github.com/priera)).
