<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Кэш сделан компонуемым: появилась возможность не вытеснять определённые файлы (например, относящиеся к idx, mrk, ..), старая версия кэша удалена. Теперь кэш можно настраивать для диска Azure Blob Storage, локального диска, диска StaticWeb и т. д. Этот PR помечен как обратно несовместимый, поскольку конфигурация кэша изменилась, и для его работы нужно обновить файл конфигурации. Старый кэш по-прежнему будет использоваться с новой конфигурацией. Сервер успешно запустится и со старой конфигурацией кэша. Закрывает [#36140](https://github.com/ClickHouse/ClickHouse/issues/36140). Закрывает [#37889](https://github.com/ClickHouse/ClickHouse/issues/37889). [#36171](https://github.com/ClickHouse/ClickHouse/pull/36171) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Теперь все соответствующие источники словарей учитывают настройку `remote_url_allow_hosts`. Ранее это уже было сделано для HTTP, Cassandra и Redis. Добавлена поддержка для ClickHouse, MongoDB, MySQL и PostgreSQL. Хост проверяется только для словарей, созданных через DDL. [#39184](https://github.com/ClickHouse/ClickHouse/pull/39184) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Расширен диапазон Date32 и DateTime64 для поддержки дат с 1900 по 2299 год. В предыдущих версиях поддерживаемый интервал был только с 1925 по 2283 год. В реализации используется пролептический григорианский календарь (что соответствует [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601):2004 (clause 3.2.1 The Gregorian calendar)) вместо учёта исторических переходов с юлианского календаря на григорианский. Это изменение затрагивает зависящее от реализации поведение для аргументов вне диапазона. Например, если в предыдущих версиях значение `1899-01-01` приводилось к `1925-01-01`, то в новой версии оно будет приводиться к `1900-01-01`. Это также меняет поведение округления в `toStartOfInterval`, если передать `INTERVAL 3 QUARTER`, вплоть до одного квартала, поскольку интервалы отсчитываются от зависящей от реализации точки во времени. Закрывает [#28216](https://github.com/ClickHouse/ClickHouse/issues/28216), улучшает [#38393](https://github.com/ClickHouse/ClickHouse/issues/38393). [#39425](https://github.com/ClickHouse/ClickHouse/pull/39425) ([Roman Vasin](https://github.com/rvasin)).



<div id="new-feature">
  #### Новая возможность
</div>

* Добавлена настройка `exact_rows_before_limit` (0/1). Когда она включена, ClickHouse будет предоставлять точное значение статистики `rows_before_limit_at_least`, но ценой этого станет необходимость полностью прочитать данные до достижения limit. Это закрывает [#6613](https://github.com/ClickHouse/ClickHouse/issues/6613). [#25333](https://github.com/ClickHouse/ClickHouse/pull/25333) ([kevin wan](https://github.com/MaxWk)).
* Добавлена политика кэша SLRU для кэша несжатых данных и кэша marks. [#34651](https://github.com/ClickHouse/ClickHouse/pull/34651) ([alexX512](https://github.com/alexX512)).
* Intel® In-Memory Analytics Accelerator (Intel® IAA) — это аппаратный ускоритель, доступный в следующем поколении процессоров Intel® Xeon® Scalable (&quot;Sapphire Rapids&quot;). Его цель — ускорить типичные аналитические операции, такие как (де)сжатие данных и фильтрация. В ClickHouse появился новый кодек сжатия &quot;DeflateQpl&quot;, использующий технологию offloading Intel® IAA для высокопроизводительной реализации DEFLATE. Кодек использует [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl), которая абстрагирует доступ к аппаратному ускорителю или, если аппаратный ускоритель недоступен, к программному fallback. В целом DEFLATE обеспечивает более высокую степень сжатия, чем используемый в ClickHouse по умолчанию кодек LZ4, и в результате снижает дисковый IO и потребление оперативной памяти. [#36654](https://github.com/ClickHouse/ClickHouse/pull/36654) ([jasperzhu](https://github.com/jinjunzh)).
* Добавлен параметр concurrent&#95;threads&#95;soft&#95;limit для повышения производительности при высоком RPS за счёт ограничения общего числа потоков для всех запросов. [#37285](https://github.com/ClickHouse/ClickHouse/pull/37285) ([Roman Vasin](https://github.com/rvasin)).
* Добавлена логика управления параллелизмом для ограничения общего числа параллельных потоков, создаваемых запросами. [#37558](https://github.com/ClickHouse/ClickHouse/pull/37558) ([Sergei Trifonov](https://github.com/serxa)).
* Добавлена поддержка параллельного distributed insert select в таблицы с движками Distributed и Replicated [#34670](https://github.com/ClickHouse/ClickHouse/issues/34670). [#39107](https://github.com/ClickHouse/ClickHouse/pull/39107) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Добавлены новые настройки для управления выводом схемы из текстовых форматов: - `input_format_try_infer_dates` - пытаться выводить даты из строк. - `input_format_try_infer_datetimes` - пытаться выводить значения даты и времени из строк. - `input_format_try_infer_integers` - пытаться выводить `Int64` вместо `Float64`. - `input_format_json_try_infer_numbers_from_strings` - пытаться выводить числа из JSON-строк в JSON formats. [#39186](https://github.com/ClickHouse/ClickHouse/pull/39186) ([Kruglov Pavel](https://github.com/Avogar)).
* Эта возможность будет предоставлять вывод логов в формате JSON в консоли. Её цель — упростить приём и выполнение запросов в инструментах анализа логов. [#39277](https://github.com/ClickHouse/ClickHouse/pull/39277) ([Mallik Hassan](https://github.com/SadiHassan)).
* Intel® In-Memory Analytics Accelerator (Intel® IAA) — это аппаратный ускоритель, доступный в следующем поколении процессоров Intel® Xeon® Scalable (&quot;Sapphire Rapids&quot;). Его цель — ускорить типичные аналитические операции, такие как (де)сжатие данных и фильтрация. В ClickHouse появился новый кодек сжатия &quot;DeflateQpl&quot;, использующий технологию offloading Intel® IAA для высокопроизводительной реализации DEFLATE. Кодек использует [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl), которая абстрагирует доступ к аппаратному ускорителю или, если аппаратный ускоритель недоступен, к программному fallback. В целом DEFLATE обеспечивает более высокую степень сжатия, чем используемый в ClickHouse по умолчанию кодек LZ4, и в результате снижает дисковый IO и потребление оперативной памяти. [#39494](https://github.com/ClickHouse/ClickHouse/pull/39494) ([Robert Schulze](https://github.com/rschu1ze)).
* Добавлена функция `nowInBlock`, которая позволяет получать текущее время в ходе длительных и непрерывных запросов. Закрывает [#39522](https://github.com/ClickHouse/ClickHouse/issues/39522). Примечание: функций `now64InBlock` и `todayInBlock` не существует. [#39533](https://github.com/ClickHouse/ClickHouse/pull/39533) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* * В отчёты о прогрессе (`X-ClickHouse-Summary`) добавлены result&#95;rows и result&#95;bytes. [#39567](https://github.com/ClickHouse/ClickHouse/pull/39567) ([Raúl Marín](https://github.com/Algunenano)).
* Добавлена возможность задавать настройки для табличной функции `executable()`. [#39681](https://github.com/ClickHouse/ClickHouse/pull/39681) ([Constantine Peresypkin](https://github.com/pkit)).
* Реализовано автоматическое преобразование движка базы данных из `Ordinary` в `Atomic`. Создайте пустой файл `convert_ordinary_to_atomic` в каталоге `flags`, и все базы данных `Ordinary` будут автоматически преобразованы при следующем запуске сервера. Решает [#39546](https://github.com/ClickHouse/ClickHouse/issues/39546). [#39933](https://github.com/ClickHouse/ClickHouse/pull/39933) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Добавлена новая настройка `schema_inference_hints`, которая позволяет задавать подсказки о структуре для конкретных столбцов при определении схемы. Закрывает [#39569](https://github.com/ClickHouse/ClickHouse/issues/39569). [#40068](https://github.com/ClickHouse/ClickHouse/pull/40068) ([Kruglov Pavel](https://github.com/Avogar)).



<div id="performance-improvement">
  #### Повышение производительности
</div>

* * Исправлено зависание на этапе analyze для сложных запросов. [#38185](https://github.com/ClickHouse/ClickHouse/pull/38185) ([Vladimir C](https://github.com/vdimir)).
* Способ сортировки теперь определяется на основе описания сортировки входного потока. Если входной поток уже отсортирован, сортировка пропускается. [#38719](https://github.com/ClickHouse/ClickHouse/pull/38719) ([Igor Nikonov](https://github.com/devcrafter)).
* `DISTINCT` в сочетании с `ORDER BY` значительно улучшает использование памяти и время выполнения запроса, если столбцы `DISTINCT` совпадают со столбцами `ORDER BY` или образуют их префикс. [#39432](https://github.com/ClickHouse/ClickHouse/pull/39432) ([Igor Nikonov](https://github.com/devcrafter)).
* При выполнении `cluster` и аналогичных табличных функций для получения структуры удалённой таблицы локальный node теперь используется с наивысшим приоритетом. [#39440](https://github.com/ClickHouse/ClickHouse/pull/39440) ([Mingliang Pan](https://github.com/liangliangpan)).
* `DistinctSortedTransform` теперь используется только тогда, когда описание сортировки применимо к столбцам `DISTINCT`, в противном случае используется обычная реализация `DISTINCT`. Это позволяет сократить число проверок во время выполнения `DistinctSortedTransform`. [#39528](https://github.com/ClickHouse/ClickHouse/pull/39528) ([Igor Nikonov](https://github.com/devcrafter)).
* `DistinctSortedTransform` не использовал преимущества сортировки, то есть работал как обычная реализация `DISTINCT`. Исправление значительно снижает использование памяти. [#39538](https://github.com/ClickHouse/ClickHouse/pull/39538) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector: оптимизирован filter с использованием AVX512VBMI2 compress store. [#39633](https://github.com/ClickHouse/ClickHouse/pull/39633) ([Guo Wangyang](https://github.com/guowangy)).
* KeyCondition: оптимизирован applyFunction в многопоточном сценарии. [#39812](https://github.com/ClickHouse/ClickHouse/pull/39812) ([Guo Wangyang](https://github.com/guowangy)).
* Для систем с AVX512 VBMI2 этот PR повышает производительность примерно на 6% для запросов бенчмарка SSB 3.1, 3.2 и 3.3 (SF=100). Тестирование проводилось на Intel Icelake Xeon 8380, 2 socket. [#40033](https://github.com/ClickHouse/ClickHouse/pull/40033) ([Robert Schulze](https://github.com/rschu1ze)).
* * Не обходить AST для UDF, если не зарегистрировано ни одной пользовательской функции (UDF). [#40069](https://github.com/ClickHouse/ClickHouse/pull/40069) ([Raúl Marín](https://github.com/Algunenano)).
* * Оптимизированы alloc и free в CurrentMemoryTracker. [#40078](https://github.com/ClickHouse/ClickHouse/pull/40078) ([Raúl Marín](https://github.com/Algunenano)).



<div id="improvement">
  #### Улучшения
</div>

* Изменён способ анализа PK в MergeTree. [#25563](https://github.com/ClickHouse/ClickHouse/pull/25563) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* * Улучшена структура результирующей таблицы DDL-запроса для базы данных `Replicated` (отдельные столбцы с именем сегмента и реплики, более понятный status) — запросы `CREATE TABLE ... ON CLUSTER` теперь могут сначала нормализоваться на инициаторе, если `distributed_ddl_entry_format_version` установлен в 3 (значение по умолчанию). Это означает, что запросы `ON CLUSTER` могут не работать, если инициатор не принадлежит кластеру, указанному в запросе. Исправлены [#37318](https://github.com/ClickHouse/ClickHouse/issues/37318), [#39500](https://github.com/ClickHouse/ClickHouse/issues/39500) — предложение `ON CLUSTER` игнорируется, если база данных — `Replicated`, а имя кластера совпадает с именем базы данных. Связано с [#35570](https://github.com/ClickHouse/ClickHouse/issues/35570) — прочие небольшие исправления для движка базы данных `Replicated` — при запуске базы данных `Replicated` проверяется согласованность метаданных, а при несоответствии локальных метаданных и метаданных в Keeper запускается восстановление реплики. Решает [#24880](https://github.com/ClickHouse/ClickHouse/issues/24880). [#37198](https://github.com/ClickHouse/ClickHouse/pull/37198) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Добавлена поддержка стандартного SQL-синтаксиса DELETE FROM для таблиц MergeTree и легковесного удаления для семейства MergeTree. [#37893](https://github.com/ClickHouse/ClickHouse/pull/37893) ([Jianmei Zhang](https://github.com/zhangjmruc)).
* `timeSlots` теперь работает с DateTime64; при работе с DateTime64 доступны длительность с точностью до долей секунды и размер слота. [#37951](https://github.com/ClickHouse/ClickHouse/pull/37951) ([Andrey Zvonov](https://github.com/zvonand)).
* Добавлен кэш для автоматического определения схемы для табличных функций file/s3/hdfs/url. Теперь автоматическое определение схемы будет выполняться только при первом запросе к файлу; все последующие запросы к тому же файлу будут использовать схему из кэша, если данные не изменились. Добавлена системная таблица `system.schema_inference_cache` со всеми текущими схемами в кэше, а также системные запросы `SYSTEM DROP SCHEMA CACHE [FOR FILE/S3/HDFS/URL]` для удаления схем из кэша. [#38286](https://github.com/ClickHouse/ClickHouse/pull/38286) ([Kruglov Pavel](https://github.com/Avogar)).
* * Упрощён интерфейс макроса регистрации функций (`FUNCTION_REGISTER*`), чтобы исключить необходимость добавлять и вызывать внешнюю функцию в registerFunctions.cpp; это также ускоряет инкрементальные сборки при добавлении новой функции. [#38615](https://github.com/ClickHouse/ClickHouse/pull/38615) ([Li Yin](https://github.com/liyinsg)).
