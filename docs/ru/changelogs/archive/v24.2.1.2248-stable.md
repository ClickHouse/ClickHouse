<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Проверять подозрительные/экспериментальные типы во вложенных типах. Ранее такие типы (кроме JSON) во вложенных типах, таких как Array/Tuple/Map, не проверялись. [#59385](https://github.com/ClickHouse/ClickHouse/pull/59385) ([Kruglov Pavel](https://github.com/Avogar)).
* Условие сортировки `ORDER BY ALL` (добавленное в v23.12) заменено на `ORDER BY *`. Предыдущий синтаксис был слишком подвержен ошибкам для таблиц со столбцом `all`. [#59450](https://github.com/ClickHouse/ClickHouse/pull/59450) ([Robert Schulze](https://github.com/rschu1ze)).
* Переименовать настройку `extract_kvp_max_pairs_per_row` в `extract_key_value_pairs_max_pairs_per_row`. Ошибка (лишнее сокращение в имени настройки) появилась в https://github.com/ClickHouse/ClickHouse/pull/43606. Исправить документацию для этой настройки. [#59683](https://github.com/ClickHouse/ClickHouse/pull/59683) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Переименовать настройку extract&#95;kvp&#95;max&#95;pairs&#95;per&#95;row в extract&#95;key&#95;value&#95;pairs&#95;max&#95;pairs&#95;per&#95;row. Ошибка (лишнее сокращение в имени настройки) появилась в https://github.com/ClickHouse/ClickHouse/pull/43606. Исправить документацию для этой настройки. [#59960](https://github.com/ClickHouse/ClickHouse/pull/59960) ([jsc0218](https://github.com/jsc0218)).
* Добавить проверку корректности количества потоков и размеров block. [#60138](https://github.com/ClickHouse/ClickHouse/pull/60138) ([Raúl Marín](https://github.com/Algunenano)).



<div id="new-feature">
  #### Новая возможность
</div>

* В квоту добавлено максимальное число последовательных неудачных попыток входа. [#54737](https://github.com/ClickHouse/ClickHouse/pull/54737) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* Добавлен новый синтаксис, позволяющий указывать пользователя-определителя в View/Materialized View. Это позволяет выполнять SELECT/INSERT из представлений без явных привилегий на базовые таблицы. [#54901](https://github.com/ClickHouse/ClickHouse/pull/54901) ([pufit](https://github.com/pufit)).
* Поддержка Backup &amp; Restore для AzureBlobStorage решает проблему [#50747](https://github.com/ClickHouse/ClickHouse/issues/50747). [#56988](https://github.com/ClickHouse/ClickHouse/pull/56988) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Реализовано автоматическое преобразование таблиц семейства MergeTree различных типов в Replicated engine. Создайте пустой файл `convert_to_replicated` в каталоге данных таблицы (`/clickhouse/store/xxx/xxxyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy/`), и таблица будет автоматически преобразована при следующем запуске сервера. [#57798](https://github.com/ClickHouse/ClickHouse/pull/57798) ([Kirill](https://github.com/kirillgarbar)).
* Добавлена табличная функция `mergeTreeIndex`. Она показывает содержимое файлов index и marks таблиц `MergeTree`. Ее можно использовать для интроспекции. Синтаксис: `mergeTreeIndex(database, table, [with_marks = true])`, где `database.table` — существующая таблица с движком `MergeTree`. [#58140](https://github.com/ClickHouse/ClickHouse/pull/58140) ([Anton Popov](https://github.com/CurtizJ)).
* Добавлена функция `seriesOutliersTukey` для обнаружения выбросов в данных временных рядов с использованием метода границ Тьюки. [#58632](https://github.com/ClickHouse/ClickHouse/pull/58632) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* Теперь пользователь может указывать template string непосредственно в запросе, используя `format_schema_rows_template` как альтернативу `format_template_row`. Закрывает [#31363](https://github.com/ClickHouse/ClickHouse/issues/31363). [#59088](https://github.com/ClickHouse/ClickHouse/pull/59088) ([Shaun Struwig](https://github.com/Blargian)).
* Добавлена попытка автоматически определять format файла при выводе схемы, если он неизвестен для движков `file/s3/hdfs/url/azureBlobStorage`. Закрывает [#50576](https://github.com/ClickHouse/ClickHouse/issues/50576). [#59092](https://github.com/ClickHouse/ClickHouse/pull/59092) ([Kruglov Pavel](https://github.com/Avogar)).
* Добавлена функция `variantType`, которая возвращает Enum с именем типа варианта для каждой строки. [#59398](https://github.com/ClickHouse/ClickHouse/pull/59398) ([Kruglov Pavel](https://github.com/Avogar)).
* Добавлен запрос `ALTER TABLE table FORGET PARTITION partition`, который удаляет узлы ZooKeeper, относящиеся к пустой партиции. [#59507](https://github.com/ClickHouse/ClickHouse/pull/59507) ([Sergei Trifonov](https://github.com/serxa)).
* Добавлена поддержка файла учетных данных JWT для движка таблицы NATS. [#59543](https://github.com/ClickHouse/ClickHouse/pull/59543) ([Nickolaj Jepsen](https://github.com/nickolaj-jepsen)).
* Добавлена новая агрегатная функция `groupArrayIntersect`. Продолжение: [#49862](https://github.com/ClickHouse/ClickHouse/issues/49862). [#59598](https://github.com/ClickHouse/ClickHouse/pull/59598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

* Кодек `LZ4HC` теперь поддерживает новый уровень 2, который быстрее прежнего минимального уровня 3, но обеспечивает меньшее сжатие. В предыдущих версиях `LZ4HC(2)` и ниже было эквивалентно `LZ4HC(3)`. Автор: [Cyan4973](https://github.com/Cyan4973). * Добавлена поддержка варианта табличной функции merge с одним аргументом: `merge(['db_name', ] 'tables_regexp')`. [#60372](https://github.com/ClickHouse/ClickHouse/pull/60372) ([豪肥肥](https://github.com/HowePa)).
* Добавлен новый синтаксис, позволяющий указать пользователя definer в View/Materialized View. Это позволяет выполнять SELECT/INSERT из представлений без явных привилегий на базовые таблицы. [#60439](https://github.com/ClickHouse/ClickHouse/pull/60439) ([pufit](https://github.com/pufit)).

* Реализована автоматическая настройка тайм-аутов асинхронной вставки. Добавлены следующие настройки: async&#95;insert&#95;poll&#95;timeout&#95;ms, async&#95;insert&#95;use&#95;adaptive&#95;busy&#95;timeout, async&#95;insert&#95;busy&#95;timeout&#95;min&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;max&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;increase&#95;rate, async&#95;insert&#95;busy&#95;timeout&#95;decrease&#95;rate. Новая настройка `parallel_replicas_prefer_local_join` выбирает локальное выполнение `JOIN` (по умолчанию) вместо `GLOBAL JOIN`. Все таблицы должны существовать на каждой реплике из `cluster_for_parallel_replicas`. Новые настройки `min_external_table_block_size_rows` и `min_external_table_block_size_bytes` используются для объединения небольших блоков, отправляемых для временных таблиц (только с анализатором). [#58916](https://github.com/ClickHouse/ClickHouse/pull/58916) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Разрешены завершающие запятые в типах с несколькими элементами. [#59119](https://github.com/ClickHouse/ClickHouse/pull/59119) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Добавлена поддержка параллельной и распределённой обработки для движка таблицы `S3Queue`. Для распределённой обработки используйте настройку `s3queue_total_shards_num` (по умолчанию `1`). Ранее настройку `s3queue_processing_threads_num` нельзя было использовать в режиме Ordered, теперь это разрешено. Предупреждение: настройки `s3queue_processing_threads_num` (потоки обработки для каждого сегмента) и `s3queue_total_shards_num` в режиме Ordered меняют способ хранения метаданных (число узлов `max_processed_file` становится равным `s3queue_processing_threads_num * s3queue_total_shards_num`), поэтому они должны быть одинаковыми для всех сегментов и не могут быть изменены после создания хотя бы одного сегмента. [#59167](https://github.com/ClickHouse/ClickHouse/pull/59167) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Разрешено конкурентное создание таблиц в `DatabaseReplicated` во время `recoverLostReplica`. [#59277](https://github.com/ClickHouse/ClickHouse/pull/59277) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Настройки для движка таблицы Distributed теперь можно задавать в файле конфигурации сервера (аналогично настройкам MergeTree), например: `<distributed> <flush_on_detach>false</flush_on_detach> </distributed>`. [#59291](https://github.com/ClickHouse/ClickHouse/pull/59291) ([Azat Khuzhin](https://github.com/azat)).
* В качестве движка таблицы по умолчанию теперь используется MergeTree. Это заметно повышает удобство использования и приближает поведение к ClickHouse Cloud. [#59316](https://github.com/ClickHouse/ClickHouse/pull/59316) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* При чтении `system.zookeeper` теперь выполняются повторные попытки при разрыве соединения и истечении сеанса. Это полезно при чтении большого количества строк из таблицы `system.zookeeper`, особенно при искусственно вызванных разрывах соединения. [#59388](https://github.com/ClickHouse/ClickHouse/pull/59388) ([Alexander Gololobov](https://github.com/davenger)).
* Числа с ведущими нулями больше не интерпретируются как восьмеричные, если `input_format_values_interpret_expressions=0`. [#59403](https://github.com/ClickHouse/ClickHouse/pull/59403) ([Joanna Hulboj](https://github.com/jh0x)).
* При запуске и при каждом изменении файлов конфигурации ClickHouse обновляет жёсткие лимиты памяти своего общего трекера памяти. Эти лимиты вычисляются на основе различных настроек сервера и ограничений cgroups (в Linux). Ранее путь `/sys/fs/cgroup/memory.max` (для cgroups v2) был жёстко задан. В результате ограничения памяти cgroup v2, настроенные для вложенных групп (иерархий), например `/sys/fs/cgroup/my/nested/group/memory.max`, игнорировались. Теперь это исправлено. Поведение ограничений памяти v1 остаётся без изменений. [#59435](https://github.com/ClickHouse/ClickHouse/pull/59435) ([Robert Schulze](https://github.com/rschu1ze)).
* Добавлены новые profile events для отслеживания времени, затраченного на вычисление PK/проекций/вторичных индексов во время `INSERT`. [#59436](https://github.com/ClickHouse/ClickHouse/pull/59436) ([Nikita Taranov](https://github.com/nickitat)).
* Разрешено задавать начальную точку для S3Queue в режиме Ordered при создании с помощью настройки `s3queue_last_processed_path`. [#59446](https://github.com/ClickHouse/ClickHouse/pull/59446) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Улучшение Keeper: в памяти кэшируется только определённый объём журналов, который регулируется параметрами `latest_logs_cache_size_threshold` и `commit_logs_cache_size_threshold`. [#59460](https://github.com/ClickHouse/ClickHouse/pull/59460) ([Antonio Andelic](https://github.com/antonio2368)).
* Комментарии для системных таблиц теперь также доступны в `system.tables` в `clickhouse-local`. [#59493](https://github.com/ClickHouse/ClickHouse/pull/59493) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Числа с плавающей точкой в экспоненциальной записи больше не определяются по умолчанию. Добавлена настройка `input_format_try_infer_exponent_floats`, которая возвращает прежнее поведение (по умолчанию отключена). Закрывает [#59476](https://github.com/ClickHouse/ClickHouse/issues/59476). [#59500](https://github.com/ClickHouse/ClickHouse/pull/59500) ([Kruglov Pavel](https://github.com/Avogar)).
* Разрешено заключать alter-операции в круглые скобки. Выводом круглых скобок можно управлять с помощью config `format_alter_operations_with_parentheses`. По умолчанию в форматированных запросах круглые скобки выводятся, так как в некоторых местах мы храним форматированные alter-операции как metadata (например, mutations). Новый синтаксис делает более понятными некоторые запросы, в которых alter-операции заканчиваются списком. Например, запрос `ALTER TABLE x MODIFY TTL date GROUP BY a, b, DROP COLUMN c` невозможно корректно разобрать в старом синтаксисе. В новом синтаксисе запрос `ALTER TABLE x (MODIFY TTL date GROUP BY a, b), (DROP COLUMN c)` интерпретируется однозначно. Старые версии не умеют читать новый синтаксис, поэтому его использование может вызывать проблемы, если в одном cluster используются и новые, и старые версии ClickHouse.
