  ### Релиз ClickHouse v23.10.1.1976-stable (13adae0e42f) FIXME по сравнению с v23.9.1.1854-stable (8f9a227de1f)

<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Хранилище S3Queue было полностью переписано: изменён способ хранения информации в ZooKeeper, что позволяет сократить число запросов к ZooKeeper; добавлено кэширование состояния ZooKeeper в случаях, когда известно, что оно не изменится; улучшен процесс polling из S3, чтобы сделать его менее агрессивным; изменён способ поддержки TTL и max set для отслеживаемых файлов — теперь это фоновый процесс. Добавлены таблицы `system.s3queue` и `system.s3queue_log`. Закрывает [#54998](https://github.com/ClickHouse/ClickHouse/issues/54998). [#54422](https://github.com/ClickHouse/ClickHouse/pull/54422) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Возможность автоматически удалять повреждённые части данных больше недоступна. Это закрывает [#55174](https://github.com/ClickHouse/ClickHouse/issues/55174). [#55184](https://github.com/ClickHouse/ClickHouse/pull/55184) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Устаревшие части данных в памяти больше нельзя читать из журнала предзаписи. Если ранее у вас были настроены части в памяти, их необходимо удалить перед обновлением. [#55186](https://github.com/ClickHouse/ClickHouse/pull/55186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Удалена интеграция с Meilisearch. Причина: она была совместима только со старой версией 0.18. В новых версиях Meilisearch изменился протокол, и она больше не работает. Примечание: будем признательны, если вы поможете вернуть её. [#55189](https://github.com/ClickHouse/ClickHouse/pull/55189) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Концепция monitor каталога переименована в фоновый INSERT. Все настройки `*directory_monitor*` были переименованы в `distributed_background_insert*`. **Обратная совместимость должна быть сохранена** (так как старые настройки были добавлены как alias). [#55978](https://github.com/ClickHouse/ClickHouse/pull/55978) ([Azat Khuzhin](https://github.com/azat)).
* Больше не путаются send&#95;timeout и receive&#95;timeout. [#56035](https://github.com/ClickHouse/ClickHouse/pull/56035) ([Azat Khuzhin](https://github.com/azat)).
* Сравнение интервалов времени с разными единицами теперь будет вызывать исключение. Это закрывает [#55942](https://github.com/ClickHouse/ClickHouse/issues/55942). Возможно, в отдельных случаях вы полагались на прежнее поведение, при котором сравнивались базовые числовые значения вне зависимости от единиц измерения. [#56090](https://github.com/ClickHouse/ClickHouse/pull/56090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Новая возможность
</div>

* Добавлена функция &quot;arrayFold(x1, ..., xn, accum -&gt; expression, array1, ..., arrayn, init&#95;accum)&quot;, которая применяет лямбда-функцию к нескольким массивам одинаковой длины и накапливает результат в аккумуляторе. [#49794](https://github.com/ClickHouse/ClickHouse/pull/49794) ([Lirikl](https://github.com/Lirikl)).
* Добавлена агрегатная функция lttb, использующая алгоритм [Largest-Triangle-Three-Buckets](https://skemman.is/bitstream/1946/15343/3/SS_MSthesis.pdf) для прореживания данных при визуализации. [#53145](https://github.com/ClickHouse/ClickHouse/pull/53145) ([Sinan](https://github.com/sinsinan)).
* Запрос `CHECK TABLE` стал производительнее и удобнее в использовании (отправляет обновления о ходе выполнения, его можно отменить). Поддерживается проверка конкретной части с помощью `CHECK TABLE ... PART 'part_name'`. [#53404](https://github.com/ClickHouse/ClickHouse/pull/53404) ([vdimir](https://github.com/vdimir)).
* Добавлена функция `jsonMergePatch`. При работе с данными JSON в виде строк она позволяет объединять эти строки (с объектами JSON) в одну строку, содержащую один объект JSON. [#54364](https://github.com/ClickHouse/ClickHouse/pull/54364) ([Memo](https://github.com/Joeywzr)).
* Добавлена новая SQL-функция &quot;arrayRandomSample(arr, k)&quot;, которая возвращает выборку из k элементов входного массива. Ранее аналогичной функциональности можно было добиться только с помощью менее удобного синтаксиса, например &quot;SELECT arrayReduce(&#39;groupArraySample(3)&#39;, range(10))&quot;. [#54391](https://github.com/ClickHouse/ClickHouse/pull/54391) ([itayisraelov](https://github.com/itayisraelov)).
* Добавлена новая функция `getHttpHeader` для получения значения заголовка HTTP-запроса, используемого в запросе к ClickHouse server. Возвращает пустую строку, если запрос выполняется не по HTTP-протоколу или такого заголовка нет. [#54813](https://github.com/ClickHouse/ClickHouse/pull/54813) ([凌涛](https://github.com/lingtaolf)).
* Добавлены агрегатные комбинаторы -ArgMin/-ArgMax, которые позволяют выполнять агрегацию только по минимальным/максимальным значениям. Один из вариантов использования приведён в [#54818](https://github.com/ClickHouse/ClickHouse/issues/54818). В этом PR также комбинаторы были вынесены в отдельную папку. [#54947](https://github.com/ClickHouse/ClickHouse/pull/54947) ([Amos Bird](https://github.com/amosbird)).
* Добавлена возможность сбрасывать cache для Protobuf format с помощью `SYSTEM DROP SCHEMA FORMAT CACHE [FOR Protobuf]`. [#55064](https://github.com/ClickHouse/ClickHouse/pull/55064) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Добавлен внешний HTTP Basic authenticator. [#55199](https://github.com/ClickHouse/ClickHouse/pull/55199) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Добавлена функция `byteSwap`, которая меняет порядок байтов в беззнаковых целых числах на обратный. Это особенно полезно для обращения значений типов, которые внутри представлены как беззнаковые целые числа, например IPv4. [#55211](https://github.com/ClickHouse/ClickHouse/pull/55211) ([Priyansh Agrawal](https://github.com/Priyansh121096)).
* Добавлена функция `formatQuery()`, которая возвращает отформатированную строку SQL-запроса (возможно, многострочную). Также добавлена функция `formatQuerySingleLine()`, которая делает то же самое, но возвращаемая строка не содержит переводов строк. [#55239](https://github.com/ClickHouse/ClickHouse/pull/55239) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Добавлен input format DWARF, который читает отладочные символы из ELF executable/library/object file. [#55450](https://github.com/ClickHouse/ClickHouse/pull/55450) ([Michael Kolupaev](https://github.com/al13n321)).
* Добавлена возможность сохранять неразобранные записи и ошибки в движках RabbitMQ, NATS и FileLog. Добавлены виртуальные столбцы `_error` и `_raw_message` (для NATS и RabbitMQ), `_raw_record` (для FileLog), которые заполняются, когда ClickHouse не удаётся разобрать новую запись. Поведение управляется настройками хранилища `nats_handle_error_mode` для NATS, `rabbitmq_handle_error_mode` для RabbitMQ и `handle_error_mode` для FileLog, аналогично `kafka_handle_error_mode`. Если установлено значение `default`, при ошибке разбора записи ClickHouse сгенерирует исключение; если установлено значение `stream`, ошибка и исходная запись будут сохранены в виртуальных столбцах. Закрывает [#36035](https://github.com/ClickHouse/ClickHouse/issues/36035). [#55477](https://github.com/ClickHouse/ClickHouse/pull/55477) ([Kruglov Pavel](https://github.com/Avogar)).
* Улучшение клиента Keeper: добавлена команда get&#95;all&#95;children&#95;number, которая возвращает количество всех дочерних узлов по указанному пути. [#55485](https://github.com/ClickHouse/ClickHouse/pull/55485) ([guoxiaolong](https://github.com/guoxiaolongzte)).
* Если в ключе таблицы используется кривая, заполняющая пространство, например `ORDER BY mortonEncode(x, y)`, то условия для её аргументов, например `x >= 10 AND x <= 20 AND y >= 20 AND y <= 30`, можно использовать для индексирования. Для включения или отключения этого анализа добавлена настройка `analyze_index_with_space_filling_curves`. Это закрывает [#41195](https://github.com/ClickHouse/ClickHouse/issues/41195). Продолжение [#4538](https://github.com/ClickHouse/ClickHouse/issues/4538). Продолжение [#6286](https://github.com/ClickHouse/ClickHouse/issues/6286). Продолжение [#28130](https://github.com/ClickHouse/ClickHouse/issues/28130). Продолжение [#41753](https://github.com/ClickHouse/ClickHouse/issues/41753). [#55642](https://github.com/ClickHouse/ClickHouse/pull/55642) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена настройка `optimize_trivial_approximate_count_query` для использования приближённого `count()` в хранилище EmbeddedRocksDB. Для StorageJoin включён тривиальный подсчёт. [#55806](https://github.com/ClickHouse/ClickHouse/pull/55806) ([Duc Canh Le](https://github.com/canhld94)).
* Улучшение клиента Keeper: добавлена команда get&#95;direct&#95;children&#95;number, которая возвращает количество прямых дочерних узлов по указанному пути. [#55898](https://github.com/ClickHouse/ClickHouse/pull/55898) ([xuzifu666](https://github.com/xuzifu666)).
* Добавлен оператор `SHOW SETTING setting_name`, который является более простой версией существующего оператора `SHOW SETTINGS`. [#55979](https://github.com/ClickHouse/ClickHouse/pull/55979) ([Maksim Kita](https://github.com/kitaisreal)).
* Этот PR добавляет возможность передавать данные в формате Npy в ClickHouse. &#96;&#96;&#96; SELECT * FROM file(&#39;example&#95;array.npy&#39;, Npy). [#55982](https://github.com/ClickHouse/ClickHouse/pull/55982) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Этот PR реализует новую настройку `force_optimize_projection_name`, которая принимает имя проекции в качестве аргумента. Если её значение задано непустой строкой, ClickHouse проверяет, что эта проекция используется в запросе хотя бы один раз. Закрывает [#55331](https://github.com/ClickHouse/ClickHouse/issues/55331). [#56134](https://github.com/ClickHouse/ClickHouse/pull/56134) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Добавлена опция `query_plan_preserve_num_streams_after_window_functions`, которая сохраняет количество streams после вычисления window functions, чтобы обеспечить параллельную stream processing. [#50771](https://github.com/ClickHouse/ClickHouse/pull/50771) ([frinkr](https://github.com/frinkr)).
* Если данных мало, теперь освобождается больше num&#95;streams. [#53867](https://github.com/ClickHouse/ClickHouse/pull/53867) ([Jiebin Sun](https://github.com/jiebinn)).
* RoaringBitmaps теперь оптимизируются перед сериализацией. [#55044](https://github.com/ClickHouse/ClickHouse/pull/55044) ([UnamedRus](https://github.com/UnamedRus)).
* Списки вхождений в инвертированных индексах теперь оптимизируются так, чтобы использовать минимально возможное представление для внутренних битмапов. В зависимости от повторяемости данных это может значительно сократить занимаемое инвертированными индексами место. [#55069](https://github.com/ClickHouse/ClickHouse/pull/55069) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Устранена конкуренция за блокировку Context, что значительно повышает производительность при большом количестве коротких параллельных запросов. [#55121](https://github.com/ClickHouse/ClickHouse/pull/55121) ([Maksim Kita](https://github.com/kitaisreal)).
* Производительность создания инвертированного индекса повышена на 30%. Это было достигнуто заменой `std::unordered_map` на `absl::flat_hash_map`. [#55210](https://github.com/ClickHouse/ClickHouse/pull/55210) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Добавлена поддержка проталкивания фильтра в orc (на уровне rowgroup). [#55330](https://github.com/ClickHouse/ClickHouse/pull/55330) ([李扬](https://github.com/taiyang-li)).
* Повышена производительность внешней агрегации при большом количестве временных файлов. [#55489](https://github.com/ClickHouse/ClickHouse/pull/55489) ([Maksim Kita](https://github.com/kitaisreal)).
* По умолчанию задан разумный размер кэша marks для secondary indices, чтобы не загружать marks снова и снова. [#55654](https://github.com/ClickHouse/ClickHouse/pull/55654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Устранена лишняя реконструкция index granules при чтении индексов пропуска данных. Это исправляет [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653)#issuecomment-1763766009 . [#55683](https://github.com/ClickHouse/ClickHouse/pull/55683) ([Amos Bird](https://github.com/amosbird)).
* Функция cast в set теперь кэшируется во время выполнения, что повышает производительность функции `IN`, когда тип элемента set не полностью совпадает с типом столбца. [#55712](https://github.com/ClickHouse/ClickHouse/pull/55712) ([Duc Canh Le](https://github.com/canhld94)).
* Повышена производительность `ColumnVector::insertMany` и `ColumnVector::insertManyFrom`. [#55714](https://github.com/ClickHouse/ClickHouse/pull/55714) ([frinkr](https://github.com/frinkr)).
* ... Получение значений из map используется очень широко. На практике структуры key обычно одинаковы в пределах одного и того же столбца map, поэтому можно попытаться предсказать позицию key в следующей строке и сократить количество сравнений. [#55929](https://github.com/ClickHouse/ClickHouse/pull/55929) ([lgbo](https://github.com/lgbo-ustc)).
* ... Исправлена проблема, из-за которой в некоторых случаях не работал prune полей struct. Например &#96;&#96;&#96;sql INSERT INTO FUNCTION file(&#39;test&#95;parquet&#95;struct&#39;, Parquet, &#39;x Tuple(a UInt32, b UInt32, c String)&#39;) SELECT tuple(number, rand(), concat(&#39;testxxxxxxx&#39; toString(number))) FROM numbers(10);. [#56117](https://github.com/ClickHouse/ClickHouse/pull/56117) ([lgbo](https://github.com/lgbo-ustc)).

  #### Улучшения

* Создание словаря direct-типа с заданным полем lifetime теперь будет отклоняться на этапе создания. Исправляет: [#27861](https://github.com/ClickHouse/ClickHouse/issues/27861). [#49043](https://github.com/ClickHouse/ClickHouse/pull/49043) ([Rory Crispin](https://github.com/RoryCrispin)).
* Разрешены параметры в запросах с партициями, таких как `ALTER TABLE t DROP PARTITION`. Закрывает [#49449](https://github.com/ClickHouse/ClickHouse/issues/49449). [#49516](https://github.com/ClickHouse/ClickHouse/pull/49516) ([Nikolay Degterinsky](https://github.com/evillique)).
* 1. Рефакторинг кода, связанного с zookeeper&#95;connection 2. Добавлен новый столбец xid для zookeeper&#95;connection. [#50702](https://github.com/ClickHouse/ClickHouse/pull/50702) ([helifu](https://github.com/helifu)).
* Добавлена возможность настраивать количество параллельных реплик, используемых при выполнении запроса, на основе оценки числа строк для чтения. [#51692](https://github.com/ClickHouse/ClickHouse/pull/51692) ([Raúl Marín](https://github.com/Algunenano)).
* Распределённые запросы, выполняемые в режиме `async_socket_for_remote` (по умолчанию), теперь учитывают ограничение `max_threads`. Ранее некоторые запросы могли создавать слишком много потоков (до `max_distributed_connections`), что вызывало проблемы с производительностью сервера. [#53504](https://github.com/ClickHouse/ClickHouse/pull/53504) ([filimonov](https://github.com/filimonov)).
* После перезагрузки отображаются корректные настройки сервера. [#53774](https://github.com/ClickHouse/ClickHouse/pull/53774) ([helifu](https://github.com/helifu)).
* Добавлена поддержка математического символа минус `−` в запросах, аналогично `-`. [#54100](https://github.com/ClickHouse/ClickHouse/pull/54100) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* В движок базы данных Replicated добавлены группы реплик. Закрывает [#53620](https://github.com/ClickHouse/ClickHouse/issues/53620). [#54421](https://github.com/ClickHouse/ClickHouse/pull/54421) ([Nikolay Degterinsky](https://github.com/evillique)).
* Этот PR исправляет ошибку теста UBsan [здесь](https://github.com/ClickHouse/ClickHouse/pull/54566). [#54568](https://github.com/ClickHouse/ClickHouse/pull/54568) ([JackyWoo](https://github.com/JackyWoo)).
* Добавлена поддержка асинхронных вставок с внешними данными через собственный протокол. Ранее это работало только если данные были встроены прямо в запрос. [#54730](https://github.com/ClickHouse/ClickHouse/pull/54730) ([Anton Popov](https://github.com/CurtizJ)).
* Для ошибок S3, допускающих повторную попытку, лучше выполнять retry, чем полностью завершать запрос с ошибкой. Значение `s3&#95;retry&#95;attempts` по умолчанию увеличено. [#54770](https://github.com/ClickHouse/ClickHouse/pull/54770) ([Sema Checherinda](https://github.com/CheSema)).
* Оптимизировано потребление памяти при внешней агрегации в случае, когда создаётся много временных файлов. [#54798](https://github.com/ClickHouse/ClickHouse/pull/54798) ([Nikita Taranov](https://github.com/nickitat)).
* Добавлен алгоритм балансировки нагрузки `test&#95;hostname&#95;levenshtein&#95;distance`. [#54826](https://github.com/ClickHouse/ClickHouse/pull/54826) ([JackyWoo](https://github.com/JackyWoo)).
* Добавлено кэширование записей, которые можно пропустить, при выполнении DDL из распределённой очереди DDL в ZooKeeper. [#54828](https://github.com/ClickHouse/ClickHouse/pull/54828) ([Duc Canh Le](https://github.com/canhld94)).
* Улучшено скрытие секретов в журналах. [#55089](https://github.com/ClickHouse/ClickHouse/pull/55089) ([Vitaly Baranov](https://github.com/vitlibar)).
* В таблицу `system.parts_columns` добавлены поля `substreams` и `filenames`. [#55108](https://github.com/ClickHouse/ClickHouse/pull/55108) ([Anton Popov](https://github.com/CurtizJ)).
* Пока анализ проекций будет выполняться только на уровне плана запроса. Настройка `query_plan_optimize_projection` стала устаревшей (по умолчанию она включена уже давно). [#55112](https://github.com/ClickHouse/ClickHouse/pull/55112) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Если функция &quot;untuple()&quot; теперь вызывается для кортежа с именованными элементами и сама имеет псевдоним (например, &quot;select untuple(tuple(1)::Tuple(element&#95;alias Int)) AS untuple&#95;alias&quot;), то имя результирующего столбца теперь генерируется из псевдонима untuple и псевдонима элемента кортежа (в примере: &quot;untuple&#95;alias.element&#95;alias&quot;). [#55123](https://github.com/ClickHouse/ClickHouse/pull/55123) ([garcher22](https://github.com/garcher22)).
