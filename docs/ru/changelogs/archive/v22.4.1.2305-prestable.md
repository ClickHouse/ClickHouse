<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Функция `yandexConsistentHash` (алгоритм consistent hash Константина &quot;kostik&quot; Облакова) переименована в `kostikConsistentHash`. Старое имя оставлено в качестве псевдонима для совместимости. Хотя это изменение обратно совместимо, в последующих релизах мы можем удалить этот псевдоним, поэтому рекомендуется обновить использование этой функции в ваших приложениях. [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Запрещено указывать SETTINGS после FORMAT в запросах INSERT (есть настройка совместимости `allow_settings_after_format_in_insert`, позволяющая принимать такие запросы, но по умолчанию она отключена). [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* Изменён хешированный путь для файлов кэша. [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Ускорен процесс загрузки частей MergeTree, чтобы сократить время запуска clickhouse-server. Благодаря этому улучшению clickhouse-server смог уменьшить время запуска с 75 минут до 20 секунд при 700 тыс. частях MergeTree. [#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* Размеры хеш-таблиц, используемых при агрегации, теперь собираются и используются в последующих запросах, чтобы избежать их переразмеривания. [#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* Внесено несколько изменений для повышения производительности ASOF JOIN (ускорение в 1,2–1,6 раза). Также добавлена поддержка больших целочисленных типов. [#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* Движок URL теперь загружает несколько фрагментов параллельно, если конечная точка поддерживает HTTP Range. Были добавлены две дополнительные настройки, `max_download_threads` и `max_download_buffer_size`, которые управляют максимальным количеством потоков, которое один запрос может использовать для загрузки файла, и максимальным количеством байт, которое может обработать каждый поток. [#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* Распараллеливание multipart-загрузки в хранилище S3. [#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* Повышена производительность ASOF JOIN, если ключ имеет нативный целочисленный тип. [#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* Новая оптимизация плана выполнения запроса. По возможности функции теперь вычисляются после `ORDER BY`. Например, для запроса `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5` функция `sipHash64` будет вычислена после `ORDER BY` и `LIMIT`, что дает ускорение примерно в 20 раз. [#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* Сужена область действия mutex в связи с проблемой, связанной с setenv LIBHDFS3&#95;CONF [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292). [#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* Повышена производительность функции `hasAll` за счет специализаций для SSE и AVX2. Автор: @youennL-cs. [#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * Оператор EXPLAIN для GLOBAL JOIN двух distributed таблиц теперь может выполняться до 100 раз быстрее: explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2 оптимизации: - Оптимизация тривиального count-запроса к Hive - Ускорение запросов к Hive за счет кэширования метаданных файлов Hive. [#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
