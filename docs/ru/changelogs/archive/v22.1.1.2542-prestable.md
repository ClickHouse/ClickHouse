<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Изменён путь ZooKeeper для zero-copy меток для общих данных. Исправлено удаление меток в ZooKeeper для переименованных частей. [#32061](https://github.com/ClickHouse/ClickHouse/pull/32061) ([ianton-ru](https://github.com/ianton-ru)).
* * Добавлен учёт скалярных подзапросов. С этим изменением строки, прочитанные в скалярных подзапросах, теперь отражаются в `query_log`. Если скалярный подзапрос кэшируется (повторяется или вызывается для нескольких строк), прочитанные строки учитываются только один раз. Это изменение позволяет завершать запросы командой KILL и сообщать о прогрессе во время выполнения скалярных подзапросов. [#32271](https://github.com/ClickHouse/ClickHouse/pull/32271) ([Raúl Marín](https://github.com/Algunenano)).
* Добавлены функции `left`, `right`, `leftUTF8`, `rightUTF8`. Исправлена ошибка в реализации функции `substringUTF8` с отрицательным смещением (смещение от конца строки). Функции `left` и `right` ранее были реализованы в парсере. Примечания по обновлению: распределённые запросы с функциями `left` или `right` без псевдонимов могут сгенерировать исключение, если кластер содержит разные версии clickhouse-server. Если вы обновляете свой кластер и столкнулись с этой ошибкой, вам следует завершить обновление кластера, чтобы все узлы имели одинаковую версию. Также вы можете добавить псевдонимы (`AS something`) к столбцам в ваших запросах, чтобы избежать этой проблемы. [#33407](https://github.com/ClickHouse/ClickHouse/pull/33407) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Новая возможность
</div>

* Реализована разреженная сериализация. Она позволяет сократить использование дискового пространства и повысить производительность некоторых запросов для столбцов, содержащих много значений по умолчанию (нулевых). Ее можно включить, задав `ratio_of_defaults_for_sparse_serialization`. Разреженная сериализация будет выбираться динамически для столбца, если отношение числа значений по умолчанию к общему числу значений превышает этот порог. Сериализация (по умолчанию или разреженная) будет фиксироваться для каждого столбца в части, но может различаться между частями. [#22535](https://github.com/ClickHouse/ClickHouse/pull/22535) ([Anton Popov](https://github.com/CurtizJ)).
* Добавлена функция grouping sets, аналогичная GROUP BY grouping sets (a, b, (a, b)). [#26869](https://github.com/ClickHouse/ClickHouse/pull/26869) ([taylor12805](https://github.com/taylor12805)).
* Добавлена возможность чтения из всех реплик в пределах сегмента во время распределенного запроса. Чтобы включить это, установите `allow_experimental_parallel_reading_from_replicas=true` и `max_parallel_replicas` в любое значение. Это закрывает [#26748](https://github.com/ClickHouse/ClickHouse/issues/26748). [#29279](https://github.com/ClickHouse/ClickHouse/pull/29279) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Запуск и остановка серверов при изменении конфигурации хостов и портов. [#30549](https://github.com/ClickHouse/ClickHouse/pull/30549) ([Kevin Michel](https://github.com/kmichel-aiven)).
* Создание представления любого типа с комментарием. ... [#31062](https://github.com/ClickHouse/ClickHouse/pull/31062) ([Vasily Nemkov](https://github.com/Enmk)).
* Реализован движок таблицы Hive для доступа к Apache Hive из ClickHouse. Связанный RFC: [#29245](https://github.com/ClickHouse/ClickHouse/issues/29245). [#31104](https://github.com/ClickHouse/ClickHouse/pull/31104) ([李扬](https://github.com/taiyang-li)).
* * Автоматическое обнаружение узлов кластера через Zoo/Keeper. [#31442](https://github.com/ClickHouse/ClickHouse/pull/31442) ([Vladimir C](https://github.com/vdimir)).
* Добавлена поддержка дисков, использующих Azure Blob Storage, аналогично тому, как это было реализовано для дисков, использующих AWS S3. Текущая реализация поддерживает все основные операции с диском. [#31505](https://github.com/ClickHouse/ClickHouse/pull/31505) ([Jakub Kuklis](https://github.com/jkuklis)).
* * Добавлена возможность &quot;TABLE OVERRIDE&quot; для настройки схем таблиц MaterializedMySQL. [#32325](https://github.com/ClickHouse/ClickHouse/pull/32325) ([Stig Bakken](https://github.com/stigsb)).
* Реализовано автоматическое определение схемы данных для входных форматов. Теперь можно опускать structure (или просто указывать `auto`) в табличных функциях `file`, `url`, `s3`, `hdfs` и в параметрах `clickhouse-local`. Также можно опускать structure в запросе CREATE для движков таблиц `File`, `HDFS`, `S3`, `URL`, `Merge`, `Buffer`, `Distributed` и `ReplicatedMergeTree` (если добавляются новые реплики). <div id="performance-improvement">
  #### Повышение производительности
</div>

* Несущественное изменение. В крайне редких случаях, когда часть данных потеряна на каждой реплике, после слияния некоторых частей данных последующие запросы могут отсекать меньше партиций при отсечении партиций. Практически ни на что не влияет. [#32220](https://github.com/ClickHouse/ClickHouse/pull/32220) ([Azat Khuzhin](https://github.com/azat)).
* Небольшое повышение производительности функции `reinterpret`. [#32587](https://github.com/ClickHouse/ClickHouse/pull/32587) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Снижено выделение памяти для словарей со строковыми атрибутами. [#33466](https://github.com/ClickHouse/ClickHouse/pull/33466) ([Maksim Kita](https://github.com/kitaisreal)).
* Устранён экспоненциальный бэктрекинг в парсере. Закрывает [#20158](https://github.com/ClickHouse/ClickHouse/issues/20158). [#33481](https://github.com/ClickHouse/ClickHouse/pull/33481) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
