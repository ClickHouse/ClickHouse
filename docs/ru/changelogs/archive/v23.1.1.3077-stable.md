<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Удалён запрос `SYSTEM RESTART DISK`. [#44647](https://github.com/ClickHouse/ClickHouse/pull/44647) ([alesapin](https://github.com/alesapin)).
* Запрещено использовать сжатие Gorilla для столбцов типов, отличных от Float32 и Float64. [#45252](https://github.com/ClickHouse/ClickHouse/pull/45252) ([Robert Schulze](https://github.com/rschu1ze)).
* Удалён PREALLOCATE для словарей HASHED/SPARSE&#95;HASHED. [#45388](https://github.com/ClickHouse/ClickHouse/pull/45388) ([Azat Khuzhin](https://github.com/azat)).
* Параллельные quorum inserts могут работать некорректно с таблицами семейства `*MergeTree`, созданными с использованием устаревшего синтаксиса. Поэтому поддержка параллельных quorum inserts для таких таблиц полностью отключена. Это не затрагивает таблицы, созданные с использованием нового синтаксиса. [#45430](https://github.com/ClickHouse/ClickHouse/pull/45430) ([Alexander Tokmakov](https://github.com/tavplubix)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Добавлена поддержка сегментирования в HashedDictionary, что позволяет выполнять параллельную загрузку (почти линейное масштабирование с ростом числа сегментов). [#40003](https://github.com/ClickHouse/ClickHouse/pull/40003) ([Azat Khuzhin](https://github.com/azat)).
* При запуске таблиц `MergeTree` не загружаются неактивные части. [#42181](https://github.com/ClickHouse/ClickHouse/pull/42181) ([Anton Popov](https://github.com/CurtizJ)).
* * Ускорен парсинг запросов. [#42284](https://github.com/ClickHouse/ClickHouse/pull/42284) ([Raúl Marín](https://github.com/Algunenano)).
* Всегда заменяйте цепочку OR `expr = x1 OR ... OR expr = xN` на `expr IN (x1, ..., xN)`, если `expr` — столбец типа `LowCardinality`. В этом случае настройка `optimize_min_equality_disjunction_chain_length` игнорируется. [#42889](https://github.com/ClickHouse/ClickHouse/pull/42889) ([Guo Wangyang](https://github.com/guowangy)).
* > Оригинальный changelog В исходной реализации память ThreadGroupStatus:: finished&#95;threads&#95;counters&#95;memory освобождается путём перемещения во временный std::vector, который вскоре выходит из области видимости и уничтожается. Этот метод работает, однако он недостаточно очевиден. Чтобы повысить читаемость кода, этот коммит освобождает память вектора, сначала уменьшая его размер до 0, а затем соответствующим образом сокращая ёмкость. [#43586](https://github.com/ClickHouse/ClickHouse/pull/43586) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* В развитие [#42214](https://github.com/ClickHouse/ClickHouse/issues/42214) этот PR пытается оптимизировать вычисление тернарной логики по столбцам благодаря автовекторизации. В тесте производительности этого [микробенчмарка](https://github.com/ZhiguoZh/ClickHouse/blob/20221123-ternary-logic-opt-example/src/Functions/examples/associative_applier_perf.cpp) мы наблюдали максимальный **прирост производительности** в **21 раз** на процессоре ICX (Intel Xeon Platinum 8380 CPU). [#43669](https://github.com/ClickHouse/ClickHouse/pull/43669) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Уменьшена задержка при чтении из хранилища `S3` и табличной функции `s3` при большом количестве небольших файлов. Теперь настройки `remote_filesystem_read_method` и `remote_filesystem_read_prefetch` применяются при чтении из хранилища `S3`. [#43726](https://github.com/ClickHouse/ClickHouse/pull/43726) ([Anton Popov](https://github.com/CurtizJ)).
* * По возможности избегайте установки блокировок на чтение в system.tables. [#43840](https://github.com/ClickHouse/ClickHouse/pull/43840) ([Raúl Marín](https://github.com/Algunenano)).
* Эксперименты по производительности SSB (Star Schema Benchmark) на системе ICX (Intel Xeon Platinum 8380 CPU, 80 ядер, 160 потоков) показывают, что это изменение позволяет снизить конкуренцию за ThreadPoolImpl::mutex на **75%**, повысить загрузку CPU и улучшить общую производительность на **2.4%**. [#44308](https://github.com/ClickHouse/ClickHouse/pull/44308) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Теперь оптимизация применяется, только если размер кэшированного HT достаточно велик (пороговые значения были определены эмпирически и захардкожены). [#44455](https://github.com/ClickHouse/ClickHouse/pull/44455) ([Nikita Taranov](https://github.com/nickitat)).
* ... Сейчас загружается всё поле struct, хотя нам нужно прочитать только одно поле этой struct. [#44484](https://github.com/ClickHouse/ClickHouse/pull/44484) ([lgbo](https://github.com/lgbo-ustc)).
* Небольшое повышение производительности асинхронного чтения из remote fs. [#44868](https://github.com/ClickHouse/ClickHouse/pull/44868) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Переход на более быструю реализацию разделяемого (RW) mutex. Производительность может улучшиться в запросах с большим количеством синхронизации потоков или для структур данных с высокой конкуренцией. [#45007](https://github.com/ClickHouse/ClickHouse/pull/45007) ([Sergei Trifonov](https://github.com/serxa)).
* Добавлен быстрый путь для: - col like &#39;%%&#39; - col like &#39;%&#39; - col not like &#39;%&#39; - col not like &#39;%&#39; - match(col, &#39;.*&#39;). [#45244](https://github.com/ClickHouse/ClickHouse/pull/45244) ([李扬](https://github.com/taiyang-li)).

* Выполнен рефакторинг и улучшены потоковые движки Kafka/RabbitMQ/NATS, а также добавлена поддержка всех форматов; кроме того, немного переработаны сами форматы: - Исправлена отправка сообщений в построчных форматах с суффиксами/префиксами. Теперь каждое сообщение форматируется полностью, со всеми разделителями, и может быть обратно разобрано с помощью входного формата. - Добавлена поддержка блочных форматов, таких как Native, Parquet, ORC и т. д. Каждый блок форматируется как отдельное сообщение. Количество строк в одном сообщении зависит от размера блока, поэтому его можно регулировать настройкой `max_block_size`. - Добавлены новые настройки движка `kafka_max_rows_per_message/rabbitmq_max_rows_per_message/nats_max_rows_per_message`. Они управляют количеством строк, форматируемых в одном сообщении в построчных форматах. Значение по умолчанию: 1. - Исправлено высокое потребление памяти в движке таблицы NATS. - Добавлена поддержка произвольных бинарных данных в NATS producer (ранее это работало только со строками, содержащими \0 в конце) - В документацию добавлены недостающие настройки движков Kafka/RabbitMQ/NATS. - Выполнен рефакторинг отправки и чтения в Kafka/RabbitMQ/NATS, отделив их от семантики WriteBuffers/ReadBuffers. - Выполнен рефакторинг выходных форматов: удалены обратные вызовы для каждой строки, использовавшиеся в Kafka/RabbitMQ/NATS (теперь они там не используются), разрешено использовать IRowOutputFormat напрямую, уточнены разделители конца строки и между строками, добавлена возможность сбрасывать output format, чтобы заново начинать форматирование - Добавлена корректная реализация функции formatRow (бонус после рефакторинга форматов).
