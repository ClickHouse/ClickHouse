<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Функция &quot;toDayOfWeek()&quot; (alias: &quot;DAYOFWEEK&quot;) расширена аргументом mode, который задаёт, начинается ли неделя с понедельника или воскресенья, а также начинается ли отсчёт с 0 или 1. Для единообразия с другими функциями даты и времени аргумент mode был добавлен между аргументами времени и часового пояса. Это нарушает существующее использование (ранее недокументированного) двухаргументного синтаксиса &quot;toDayOfWeek(time, time&#95;zone)&quot;. Исправить это можно, переписав вызов как &quot;toDayOfWeek(time, 0, time&#95;zone)&quot;. [#45233](https://github.com/ClickHouse/ClickHouse/pull/45233) ([Robert Schulze](https://github.com/rschu1ze)).
* Переименовать настройку `max_query_cache_size` в `filesystem_cache_max_download_size`. [#45614](https://github.com/ClickHouse/ClickHouse/pull/45614) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Исправить применение настроек для FORMAT на стороне клиента. [#46003](https://github.com/ClickHouse/ClickHouse/pull/46003) ([Azat Khuzhin](https://github.com/azat)).
* Пользователь `default` по умолчанию больше не будет иметь разрешений для типа доступа `SHOW NAMED COLLECTION` (например, по умолчанию пользователь `default` больше не сможет выполнять `grant ALL` другим пользователям, как это было раньше, поэтому это PR содержит обратно несовместимое изменение). [#46010](https://github.com/ClickHouse/ClickHouse/pull/46010) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Удалить поддержку настройки `materialized_postgresql_allow_automatic_update` (которая по умолчанию была отключена). Исправить интеграционные тесты. [#46106](https://github.com/ClickHouse/ClickHouse/pull/46106) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Немного улучшить производительность `countDigits` на реалистичных датасетах. Это закрывает [#44518](https://github.com/ClickHouse/ClickHouse/issues/44518). В предыдущих версиях `countDigits(0)` возвращала `0`; теперь она возвращает `1`, что более корректно и соответствует существующей документации. [#46187](https://github.com/ClickHouse/ClickHouse/pull/46187) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Это изменение позволяет заметно снизить накладные расходы на получение filter из ColumnNullable(UInt8) и повысить общую производительность запросов. Чтобы оценить эффект, мы использовали бенчмарк TPC-H, изменив типы столбцов с non-nullable на nullable, и измеряли QPS его запросов как показатель производительности. [#45962](https://github.com/ClickHouse/ClickHouse/pull/45962) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).

* Повышена производительность преобразования Decimal, когда scale не меняется. [#46095](https://github.com/ClickHouse/ClickHouse/pull/46095) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Введённая логика работает, если условие PREWHERE представляет собой конъюнкцию нескольких условий (cond1 AND cond2 AND ... ). Она группирует по шагам те условия, для которых требуется чтение одних и тех же столбцов. После каждого шага вычисляется соответствующая часть полного условия, и результирующие строки могут быть отфильтрованы. Это позволяет читать меньше строк на следующих шагах, тем самым экономя пропускную способность IO и сокращая объём вычислений. Пока эта логика по умолчанию отключена. Она будет включена по умолчанию в одном из будущих выпусков, когда станет ясно, что она не вызывает регрессий, поэтому её настоятельно рекомендуется использовать для тестирования. Ею можно управлять с помощью 2 настроек: &quot;enable&#95;multiple&#95;prewhere&#95;read&#95;steps&quot; и &quot;move&#95;all&#95;conditions&#95;to&#95;prewhere&quot;. [#46140](https://github.com/ClickHouse/ClickHouse/pull/46140) ([Alexander Gololobov](https://github.com/davenger)).
* Разрешено увеличить prefetching при чтении данных. [#46168](https://github.com/ClickHouse/ClickHouse/pull/46168) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Выполнен Rewrite arrayExists(x -&gt; x = 1, arr) -&gt; has(arr, 1), что повышает производительность в 1.34 раза. [#46188](https://github.com/ClickHouse/ClickHouse/pull/46188) ([李扬](https://github.com/taiyang-li)).
* Исправлено чрезмерное использование памяти при вертикальных слияниях на нелокальном диске. Для удалённого диска теперь учитывается `max_insert_delayed_streams_for_parallel_write`. [#46275](https://github.com/ClickHouse/ClickHouse/pull/46275) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Обновлён zstd до v1.5.4. В этой версии есть небольшие улучшения производительности и коэффициента сжатия. Если вы используете реплики с разными версиями ClickHouse, вы можете увидеть понятные сообщения об ошибке `Data after merge/mutation is not byte-identical to data on another replicas.` с пояснением. Это нормальные сообщения, беспокоиться не стоит. [#46280](https://github.com/ClickHouse/ClickHouse/pull/46280) ([Raúl Marín](https://github.com/Algunenano)).
* Разрешено использовать алгоритм Вертикального слияния с частями в формате Compact. Это позволит ClickHouse server использовать значительно меньше памяти для фоновых операций. Это закрывает [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084). [#46282](https://github.com/ClickHouse/ClickHouse/pull/46282) ([Anton Popov](https://github.com/CurtizJ)).
* Исправлена деградация производительности, вызванная [#39737](https://github.com/ClickHouse/ClickHouse/issues/39737). [#46309](https://github.com/ClickHouse/ClickHouse/pull/46309) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Поступило несколько сообщений о segfault, связанных с `c-ares`. Во всех недавно наблюдавшихся трассировках стека сбой происходил при вставке в `std::unodered_set<>`. Полагаю, удалось найти первопричину: похоже, дело в необработанных запросах. До этого PR CH вызывал `poll`, чтобы ожидать событий на файловых дескрипторах в канале `c-ares`. Согласно [документации по poll](https://man7.org/linux/man-pages/man2/poll.2.html), отрицательное возвращаемое значение означает, что произошла ошибка. Поэтому выполнение прерывалось и возвращалась ошибка. Проблема в том, что `poll` также возвращает отрицательное значение при системном прерывании. Системное прерывание не означает, что обработка завершилась с ошибкой или была завершена, но мы всё равно её прерывали, поскольку проверяли любое отрицательное значение. После прерывания выполнения уничтожается весь стек, включая `std::unordered_set<std::string>`, переданный через параметр `void *` в callback-функцию c-ares. Когда c-ares завершал запрос, callback-функция вызывалась и обращалась к недопустимому адресу памяти, что приводило к segfault. [#45629](https://github.com/ClickHouse/ClickHouse/pull/45629) ([Arthur Passos](https://github.com/arthurpassos)).
