<div id="backward-incompatible-change">
  #### обратно несовместимое изменение
</div>

* Разрешено указывать `SETTINGS` перед `FORMAT` в цепочке запросов с `UNION`, когда подзапросы заключены в скобки. Это закрывает [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712). Изменено поведение в случаях, когда в запросе предложение `SETTINGS` указано дважды подряд. Теперь для соответствующего подзапроса приоритет имеет ближайшее предложение `SETTINGS`. В предыдущих версиях внешнее предложение `SETTINGS` могло иметь приоритет над внутренним. [#68614](https://github.com/ClickHouse/ClickHouse/pull/68614) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Переупорядочивание условий фильтрации из предложения `[PRE]WHERE` теперь по умолчанию разрешено. Его можно отключить, установив `allow_reorder_prewhere_conditions` в `false`. [#70657](https://github.com/ClickHouse/ClickHouse/pull/70657) ([Nikita Taranov](https://github.com/nickitat)).
* Исправлена оптимизация `optimize_functions_to_subcolumns` (ранее она могла приводить к ошибке `Invalid column type for ColumnUnique::insertRangeFrom. Expected String, got LowCardinality(String)`), за счет сохранения типа `LowCardinality` в `mapKeys`/`mapValues`. [#70716](https://github.com/ClickHouse/ClickHouse/pull/70716) ([Azat Khuzhin](https://github.com/azat)).
* Удалена библиотека `idxd-config` с несовместимой лицензией. Также удален экспериментальный кодек Intel DeflateQPL. [#70987](https://github.com/ClickHouse/ClickHouse/pull/70987) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Новая возможность
</div>

* Интеграция MongoDB переработана: выполнена миграция на новый драйвер mongocxx с устаревшего Poco::MongoDB, удалена поддержка устаревшего старого протокола, добавлена поддержка подключения по URI, всех типов MongoDB, операторов WHERE и ORDER BY на стороне MongoDB, а также введены ограничения для выражений, не поддерживаемых MongoDB. [#63279](https://github.com/ClickHouse/ClickHouse/pull/63279) ([Kirill Nikiforov](https://github.com/allmazz)).
* Новая опция `--progress-table` в clickhouse-client выводит таблицу с метриками, изменяющимися во время выполнения запроса; новая опция `--enable-progress-table-toggle` связана с опцией `--progress-table` и включает или отключает отображение таблицы прогресса по нажатию клавиши управления (Space). [#63689](https://github.com/ClickHouse/ClickHouse/pull/63689) ([Maria Khristenko](https://github.com/mariaKhr)).
* Это позволяет выдавать права на префиксы с подстановочным знаком. `GRANT SELECT ON db.table_pefix_* TO user`. [#65311](https://github.com/ClickHouse/ClickHouse/pull/65311) ([pufit](https://github.com/pufit)).
* Добавлен system.query&#95;metric&#95;log, который содержит историю значений памяти и метрик из таблицы system.events для отдельных запросов; данные периодически сбрасываются на диск. [#66532](https://github.com/ClickHouse/ClickHouse/pull/66532) ([Pablo Marcos](https://github.com/pamarcos)).
* Простой SELECT-запрос можно записывать с неявным SELECT, чтобы включить выражения в стиле калькулятора, например `ch "1 + 2"`. Это управляется новой настройкой `implicit_select`. [#68502](https://github.com/ClickHouse/ClickHouse/pull/68502) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена поддержка режима --copy для clickhouse local как сокращённого способа преобразования форматов [#68503](https://github.com/ClickHouse/ClickHouse/issues/68503). [#68583](https://github.com/ClickHouse/ClickHouse/pull/68583) ([Denis Hananein](https://github.com/denis-hananein)).
* Добавлена поддержка функции `arrayUnion`. [#68989](https://github.com/ClickHouse/ClickHouse/pull/68989) ([Peter Nguyen](https://github.com/petern48)).
* Добавлена поддержка агрегатной функции `quantileExactWeightedInterpolated`, которая представляет собой интерполированную версию `quantileExactWeighted`. У некоторых может возникнуть вопрос, зачем нужна новая `quantileExactWeightedInterpolated`, если у нас уже есть `quantileExactInterpolatedWeighted`. Причина в том, что новая функция точнее старой. Кроме того, это нужно для совместимости со Spark в Apache Gluten. [#69619](https://github.com/ClickHouse/ClickHouse/pull/69619) ([李扬](https://github.com/taiyang-li)).
* Добавлена поддержка функции arrayElementOrNull. Она возвращает null, если индекс массива выходит за пределы диапазона или ключ map не найден. [#69646](https://github.com/ClickHouse/ClickHouse/pull/69646) ([李扬](https://github.com/taiyang-li)).
* Пользователи могут задавать регулярные выражения через новые поля `message_regexp` и `message_regexp_negative` в файле `config.xml`, чтобы отфильтровывать logging. Logging применяется к отформатированному неокрашенному тексту для наиболее интуитивного восприятия разработчиками. [#69657](https://github.com/ClickHouse/ClickHouse/pull/69657) ([Peter Nguyen](https://github.com/petern48)).
* Добавлена поддержка типа Dynamic в большинстве функций за счёт их выполнения над внутренними типами внутри Dynamic. [#69691](https://github.com/ClickHouse/ClickHouse/pull/69691) ([Pavel Kruglov](https://github.com/Avogar)).
* Повторно добавлена функция `RIPEMD160`, которая вычисляет криптографический хеш RIPEMD-160 от строки. Пример: `SELECT HEX(RIPEMD160('The quick brown fox jumps over the lazy dog'))` возвращает `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`. [#70087](https://github.com/ClickHouse/ClickHouse/pull/70087) ([Dergousov Maxim](https://github.com/m7kss1)).
* Разрешено кэшировать читаемые файлы для движков таблиц Объектного хранилища и озёр данных, используя хеш от ETag и пути к файлу в качестве ключа кэша. [#70135](https://github.com/ClickHouse/ClickHouse/pull/70135) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлена поддержка чтения таблиц Iceberg в HDFS. [#70268](https://github.com/ClickHouse/ClickHouse/pull/70268) ([flynn](https://github.com/ucasfl)).
* Добавлена возможность читать/записывать тип JSON как двоичную строку в формате RowBinary с настройками `input_format_binary_read_json_as_string/output_format_binary_write_json_as_string`. [#70288](https://github.com/ClickHouse/ClickHouse/pull/70288) ([Pavel Kruglov](https://github.com/Avogar)).
* Добавлена возможность сериализовать/десериализовать JSON-столбец как один столбец String в формате Native. Для вывода используйте настройку `output_format_native_write_json_as_string`. Для ввода используйте версию сериализации `1` перед данными столбца. [#70312](https://github.com/ClickHouse/ClickHouse/pull/70312) ([Pavel Kruglov](https://github.com/Avogar)).
* Добавлена поддержка стандартного CTE: `with insert`, тогда как ранее поддерживался только `insert ... with ...`. [#70593](https://github.com/ClickHouse/ClickHouse/pull/70593) ([Shichao Jin](https://github.com/jsc0218)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Добавлена поддержка minmax index для `pointInPolygon`. [#62085](https://github.com/ClickHouse/ClickHouse/pull/62085) ([JackyWoo](https://github.com/JackyWoo)).
* Добавлена поддержка bloom-фильтров Parquet. [#62966](https://github.com/ClickHouse/ClickHouse/pull/62966) ([Arthur Passos](https://github.com/arthurpassos)).
* Переименование частей без блокировок, чтобы избежать влияния INSERT на SELECT (из-за блокировки частей) (в обычных условиях с `fsync_part_directory` QPS для SELECT при параллельном выполнении с INSERT увеличился в 2 раза; при высокой нагрузке эффект ещё заметнее). Обратите внимание: пока это касается только `ReplicatedMergeTree`. [#64955](https://github.com/ClickHouse/ClickHouse/pull/64955) ([Azat Khuzhin](https://github.com/azat)).
* Для `materialize ttl` теперь учитывается `ttl_only_drop_parts`; для пересчёта TTL читаются только необходимые столбцы, а части удаляются путём замены на пустые. [#65488](https://github.com/ClickHouse/ClickHouse/pull/65488) ([Andrey Zvonov](https://github.com/zvonand)).
* Выполнен рефакторинг `IDisk` и `IObjectStorage` для повышения производительности. Таблицы из объектных хранилищ `plain` и `plain_rewritable` будут инициализироваться быстрее. [#68146](https://github.com/ClickHouse/ClickHouse/pull/68146) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Оптимизировано создание потоков в ThreadPool для минимизации конкуренции за блокировки. Создание потоков теперь выполняется вне критической секции, чтобы избежать задержек при планировании задач и управлении потоками в условиях высокой нагрузки. Это делает ClickHouse значительно более отзывчивым при высокой конкурентной нагрузке. [#68694](https://github.com/ClickHouse/ClickHouse/pull/68694) ([filimonov](https://github.com/filimonov)).
* Включена поддержка чтения строковых столбцов LowCardinality из ORC. [#69481](https://github.com/ClickHouse/ClickHouse/pull/69481) ([李扬](https://github.com/taiyang-li)).
* Добавлена возможность разбирать данные напрямую в разреженные столбцы. [#69828](https://github.com/ClickHouse/ClickHouse/pull/69828) ([Anton Popov](https://github.com/CurtizJ)).
* Поддерживается параллельное чтение row groups Parquet и предварительная выборка row groups в однопоточном режиме. [#69862](https://github.com/ClickHouse/ClickHouse/pull/69862) ([LiuNeng](https://github.com/liuneng1994)).
* Повышена производительность разбора форматов с большим количеством пропущенных значений (например, `JSONEachRow`). [#69875](https://github.com/ClickHouse/ClickHouse/pull/69875) ([Anton Popov](https://github.com/CurtizJ)).
* Для `ProfileEvents` теперь используется `LowCardinality` в системных журналах, таких как `part_log`, `query_views_log`, `filesystem_cache_log`. [#70152](https://github.com/ClickHouse/ClickHouse/pull/70152) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Повышена производительность функций FromUnixTimestamp/ToUnixTimestamp. [#71042](https://github.com/ClickHouse/ClickHouse/pull/71042) ([kevinyhzou](https://github.com/KevinyhZou)).

<div id="improvement">
  #### Улучшения
</div>

* Разрешены параметризованные псевдонимы SQL. [#50665](https://github.com/ClickHouse/ClickHouse/pull/50665) ([Anton Kozlov](https://github.com/tonickkozlov)).
* Исправлено [#57616](https://github.com/ClickHouse/ClickHouse/issues/57616): эта проблема возникает из-за того, что все аргументы с положительными числами автоматически определяются как тип `uint64`, из-за чего данные типа `int` не удается сопоставить в `summapfiltered`. Это несоответствие действительно сбивает с толку, поскольку пользователь не задает параметры `uint64` явно. Кроме того, если аргументы равны `[1,2,3,toint8(-3)]`, то из-за `getleastsupertype()` эти параметры будут единообразно трактоваться как тип `int`, из-за чего `'1,2,3'` также не сможет сопоставиться с данными типа `uint` в `summapfiltered`. [#58408](https://github.com/ClickHouse/ClickHouse/pull/58408) ([Chen768959](https://github.com/Chen768959)).
* `ALTER TABLE .. REPLACE PARTITION` больше не ждет мутаций/слияний, происходящих в других партициях. [#59138](https://github.com/ClickHouse/ClickHouse/pull/59138) ([Vasily Nemkov](https://github.com/Enmk)).
* refreshable materialized views теперь поддерживаются в базах данных Replicated. [#60669](https://github.com/ClickHouse/ClickHouse/pull/60669) ([Michael Kolupaev](https://github.com/al13n321)).
* Символические ссылки для таблиц в каталоге `data/database_name/` теперь создаются для фактических путей к данным таблицы в зависимости от политики хранения, а не для каталога `store/...` на диске по умолчанию. [#61777](https://github.com/ClickHouse/ClickHouse/pull/61777) ([Kirill](https://github.com/kirillgarbar)).
* Обновления конфигурации теперь применяются в глобальном объекте Context. Это исправляет проблемы вроде [#62308](https://github.com/ClickHouse/ClickHouse/issues/62308). [#62944](https://github.com/ClickHouse/ClickHouse/pull/62944) ([Amos Bird](https://github.com/amosbird)).
* Переработаны настройки, управляющие поведением алгоритмов параллельных реплик. Кратко: в ClickHouse есть четыре различных алгоритма параллельного чтения с участием нескольких реплик, что отражено в настройке `parallel_replicas_mode`; ее значение по умолчанию — `read_tasks`. Кроме того, была добавлена настройка-переключатель `enable_parallel_replicas`. [#63151](https://github.com/ClickHouse/ClickHouse/pull/63151) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлена проблема, из-за которой `ReadSettings` не использовал заданные пользователем значения, а применял только значения по умолчанию. [#65625](https://github.com/ClickHouse/ClickHouse/pull/65625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* При разборе поля Enum из JSON строка, содержащая целое число, будет интерпретироваться как соответствующий элемент Enum. Это закрывает [#65119](https://github.com/ClickHouse/ClickHouse/issues/65119). [#66801](https://github.com/ClickHouse/ClickHouse/pull/66801) ([scanhex12](https://github.com/scanhex12)).
* Разрешено выполнять `TRIM` для пустой строки с `LEADING` или `TRAILING` как no-op. Закрывает [#67792](https://github.com/ClickHouse/ClickHouse/issues/67792). [#68455](https://github.com/ClickHouse/ClickHouse/pull/68455) ([Peter Nguyen](https://github.com/petern48)).
* Добавлена поддержка создания таблицы с запросом: `CREATE TABLE ... CLONE AS ...`. Это клонирует схему исходной таблицы, а затем присоединяет все партиции к вновь созданной таблице. Эта возможность поддерживается только для таблиц семейства `MergeTree`. Закрывает [#65015](https://github.com/ClickHouse/ClickHouse/issues/65015). [#69091](https://github.com/ClickHouse/ClickHouse/pull/69091) ([tuanpach](https://github.com/tuanpach)).
* В Gluten ClickHouse тип `timestamp` из Spark сопоставляется с типом `datetime64(6)` в ClickHouse. При приведении `timestamp '2012-01-01 00:11:22'` к строке Spark возвращает `'2012-01-01 00:11:22'`, тогда как Gluten ClickHouse возвращает `'2012-01-01 00:11:22.000000'`. [#69179](https://github.com/ClickHouse/ClickHouse/pull/69179) ([Wenzheng Liu](https://github.com/lwz9103)).
* Новый анализатор теперь всегда используется для вычисления константных выражений, когда `enable_analyzer` установлен в `true`. Поддерживается вычисление аргументов табличной функции `executable()` как константных выражений без использования запроса `SELECT`. [#69292](https://github.com/ClickHouse/ClickHouse/pull/69292) ([Dmitry Novik](https://github.com/novikd)).
* Добавлен параметр `enable_secure_identifiers`, запрещающий небезопасные идентификаторы. [#69411](https://github.com/ClickHouse/ClickHouse/pull/69411) ([tuanpach](https://github.com/tuanpach)).
* Добавлен параметр `show_create_query_identifier_quoting_rule`, который задаёт правила заключения идентификаторов в кавычки в результате запроса show create. Возможные значения: - `user_display`: когда идентификаторы являются ключевыми словами. - `when_necessary`: когда идентификаторы входят в `{"distinct", "all", "table"}` или могут вызывать неоднозначность: имена столбцов, имена атрибутов словаря. - `always`: всегда заключать идентификаторы в кавычки. [#69448](https://github.com/ClickHouse/ClickHouse/pull/69448) ([tuanpach](https://github.com/tuanpach)).
* Дополнение к [https://github.com/ClickHouse/ClickHouse/pull/69346](https://github.com/ClickHouse/ClickHouse/pull/69346): пункт 4, описанный там, теперь тоже работает. [#69563](https://github.com/ClickHouse/ClickHouse/pull/69563) ([Vitaly Baranov](https://github.com/vitlibar)).
* Реализован универсальный SerDe между Avro Union и типом ClickHouse Variant. Исправляет [#69713](https://github.com/ClickHouse/ClickHouse/issues/69713). [#69712](https://github.com/ClickHouse/ClickHouse/pull/69712) ([Jiří Kozlovský](https://github.com/jirislav)).
* 1. CREATE TABLE AS теперь копирует PRIMARY KEY, ORDER BY и аналогичные секции. Пока это поддерживается только для семейства движков таблиц MergeTree. 2. Например, следующие SQL-команды раньше вызывали исключение, но этот PR исправляет это: если в определении целевой таблицы не задано выражение `ORDER BY` или `PRIMARY KEY`, мы скопируем его из исходной таблицы. [#69739](https://github.com/ClickHouse/ClickHouse/pull/69739) ([sakulali](https://github.com/sakulali)).
* Добавлены настройки на уровне пользователя `min_free_disk_bytes_to_perform_insert` и `min_free_disk_ratio_to_perform_insert`, чтобы предотвратить вставки на почти заполненные диски. [#69755](https://github.com/ClickHouse/ClickHouse/pull/69755) ([Marco Vilas Boas](https://github.com/marco-vb)).
* Если вы запускаете `clickhouse-client` или другое CLI-приложение, и оно запускается медленно из-за перегруженного сервера, а вы в это время начинаете вводить запрос, например `SELECT`, то в предыдущих версиях перед приветственным сообщением отображались оставшиеся символы эха терминала — например, `SELECTClickHouse local version 24.10.1.1.` вместо `ClickHouse local version 24.10.1.1.`. Теперь это исправлено. Это закрывает [#31696](https://github.com/ClickHouse/ClickHouse/issues/31696). [#69856](https://github.com/ClickHouse/ClickHouse/pull/69856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлен новый столбец readonly&#95;duration в таблицу system.replicas. Это нужно, чтобы отличать реальные реплики только для чтения от sentinel-реплик в alerts. [#69871](https://github.com/ClickHouse/ClickHouse/pull/69871) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
