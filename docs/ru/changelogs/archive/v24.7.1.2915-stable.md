  ### Релиз ClickHouse v24.7.1.2915-stable (a37d2d43da7) FIXME в сравнении с v24.7.1.1-new (aa023477a92)

<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Изменена двоичная сериализация типа данных Variant: добавлен режим `compact`, чтобы избежать многократной записи одного и того же дискриминатора для гранул с единственным вариантом или только со значениями NULL. Добавлена настройка MergeTree `use_compact_variant_discriminators_serialization`, включенная по умолчанию. Обратите внимание, что тип Variant всё ещё экспериментальный, поэтому обратно несовместимое изменение в сериализации допустимо. [#62774](https://github.com/ClickHouse/ClickHouse/pull/62774) ([Kruglov Pavel](https://github.com/Avogar)).
* Запрещено использовать `CREATE MATERIALIZED VIEW ... ENGINE Replicated*MergeTree POPULATE AS SELECT ...` с базами данных Replicated. [#63963](https://github.com/ClickHouse/ClickHouse/pull/63963) ([vdimir](https://github.com/vdimir)).
* `clickhouse-keeper-client` будет принимать только пути, заданные строковыми литералами, например `ls '/hello/world'`, а не без кавычек, как в `ls /hello/world`. [#65494](https://github.com/ClickHouse/ClickHouse/pull/65494) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Метрика `KeeperOutstandingRequets` была переименована в `KeeperOutstandingRequests`. Это исправляет опечатку, о которой сообщили в [#66179](https://github.com/ClickHouse/ClickHouse/issues/66179). [#66206](https://github.com/ClickHouse/ClickHouse/pull/66206) ([Robert Schulze](https://github.com/rschu1ze)).
* Поле `is_deterministic` удалено из таблицы `system.functions`. [#66630](https://github.com/ClickHouse/ClickHouse/pull/66630) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Новая возможность
</div>

* Функция `tuple` расширена для создания именованных кортежей в запросах. Добавлена функция `tupleNames` для извлечения имен из кортежей. [#54881](https://github.com/ClickHouse/ClickHouse/pull/54881) ([Amos Bird](https://github.com/amosbird)).
* Добавлена поддержка `ASOF JOIN` для алгоритма `full_sorting_join`. Закрывает [#54493](https://github.com/ClickHouse/ClickHouse/issues/54493). [#55051](https://github.com/ClickHouse/ClickHouse/pull/55051) ([vdimir](https://github.com/vdimir)).
* Добавлена новая table function `fuzzQuery`. Эта функция позволяет вносить случайные изменения в заданную строку запроса. Например: `SELECT query FROM fuzzQuery('SELECT 1');`. [#62103](https://github.com/ClickHouse/ClickHouse/pull/62103) ([pufit](https://github.com/pufit)).
* Добавлена новая window function `percent_rank`. [#62747](https://github.com/ClickHouse/ClickHouse/pull/62747) ([lgbo](https://github.com/lgbo-ustc)).
* Добавлена поддержка JWT authentication в `clickhouse-client`. [#62829](https://github.com/ClickHouse/ClickHouse/pull/62829) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Добавлены SQL-функции `changeYear`, `changeMonth`, `changeDay`, `changeHour`, `changeMinute`, `changeSecond`. Например, `SELECT changeMonth(toDate('2024-06-14'), 7)` возвращает дату `2024-07-14`. [#63186](https://github.com/ClickHouse/ClickHouse/pull/63186) ([cucumber95](https://github.com/cucumber95)).
* Добавлены startup scripts, которые позволяют выполнять предварительно настроенные запросы на этапе запуска. [#64889](https://github.com/ClickHouse/ClickHouse/pull/64889) ([pufit](https://github.com/pufit)).
* Добавлена поддержка `accept_invalid_certificate` в config клиента, чтобы он мог подключаться по защищенному TCP к server, работающему с самоподписанным certificate. Это можно использовать как сокращение для соответствующих client settings `openSSL`: `verificationMode=none` + `invalidCertificateHandler.name=AcceptCertificateHandler`. [#65238](https://github.com/ClickHouse/ClickHouse/pull/65238) ([peacewalker122](https://github.com/peacewalker122)).
* Добавлен `system.error_log`, который содержит историю значений error из таблицы `system.errors` и периодически сбрасывается на диск. [#65381](https://github.com/ClickHouse/ClickHouse/pull/65381) ([Pablo Marcos](https://github.com/pamarcos)).
* Добавлена aggregate function `groupConcat`. Она почти эквивалентна `arrayStringConcat( groupArray(column), ',')`. Может принимать 2 parameter: строковый delimiter и количество обрабатываемых элементов. [#65451](https://github.com/ClickHouse/ClickHouse/pull/65451) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлено хранилище AzureQueue. [#65458](https://github.com/ClickHouse/ClickHouse/pull/65458) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлена новая настройка для отключения/включения записи индекса страниц в файл Parquet. [#65475](https://github.com/ClickHouse/ClickHouse/pull/65475) ([lgbo](https://github.com/lgbo-ustc)).
* Системным администраторам разрешено настраивать `logger.console_log_level`. [#65559](https://github.com/ClickHouse/ClickHouse/pull/65559) ([Azat Khuzhin](https://github.com/azat)).
* Автоматически добавляется подстановочный символ `*` в конец пути к каталогу при использовании table function `file`. [#66019](https://github.com/ClickHouse/ClickHouse/pull/66019) ([Zhidong (David) Guo](https://github.com/Gun9niR)).
* В client в неинтерактивном режиме добавлена опция `--memory-usage`. [#66393](https://github.com/ClickHouse/ClickHouse/pull/66393) ([vdimir](https://github.com/vdimir)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* `optimize_functions_to_subcolumns` включен по умолчанию. [#58661](https://github.com/ClickHouse/ClickHouse/pull/58661) ([Anton Popov](https://github.com/CurtizJ)).
* Алгоритм преобразования int в string заменен на более быстрый: вместо модифицированного amdn/itoa теперь используется модифицированный jeaiii/itoa. [#61661](https://github.com/ClickHouse/ClickHouse/pull/61661) ([Raúl Marín](https://github.com/Algunenano)).
* Размеры хеш-таблиц, создаваемых при JOIN (алгоритм `parallel_hash`), теперь собираются и кэшируются. Эта информация будет использоваться для предварительного выделения места в хеш-таблицах при последующих выполнениях запросов, что позволит сэкономить время на изменении их размера. [#64553](https://github.com/ClickHouse/ClickHouse/pull/64553) ([Nikita Taranov](https://github.com/nickitat)).
* Оптимизированы запросы с `ORDER BY` по первичному ключу и `WHERE`, содержащим условие с высокой избирательностью, за счет использования буферизации. Это поведение управляется настройкой `read_in_order_use_buffering` (включена по умолчанию) и может увеличить использование памяти запросом. [#64607](https://github.com/ClickHouse/ClickHouse/pull/64607) ([Anton Popov](https://github.com/CurtizJ)).
* Улучшена производительность загрузки метаданных `plain_rewritable`. [#65634](https://github.com/ClickHouse/ClickHouse/pull/65634) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Подключение таблиц на дисках только для чтения будет использовать меньше ресурсов, поскольку устаревшие части не загружаются. [#65635](https://github.com/ClickHouse/ClickHouse/pull/65635) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена поддержка minmax hyperrectangle для индексов Set. [#65676](https://github.com/ClickHouse/ClickHouse/pull/65676) ([AntiTopQuark](https://github.com/AntiTopQuark)).
* Первичный индекс устаревших частей теперь выгружается, чтобы сократить общее использование памяти. [#65852](https://github.com/ClickHouse/ClickHouse/pull/65852) ([Anton Popov](https://github.com/CurtizJ)).
* Функции `replaceRegexpAll` и `replaceRegexpOne` теперь работают значительно быстрее, если шаблон регулярного выражения тривиален, то есть не содержит метасимволов, классов шаблонов, флагов, символов группировки и т. д. (Спасибо Taiyang Li). [#66185](https://github.com/ClickHouse/ClickHouse/pull/66185) ([Robert Schulze](https://github.com/rschu1ze)).

<div id="improvement">
  #### Улучшения
</div>

* Добавлена поддержка rocksdb в качестве backend-хранилища Keeper. [#56626](https://github.com/ClickHouse/ClickHouse/pull/56626) ([Han Fei](https://github.com/hanfei1991)).
* Настройка `optimize_trivial_insert_select` по умолчанию отключена. В большинстве случаев это должно быть полезно. Однако если у вас `INSERT SELECT` стал работать медленнее или выросло использование памяти, вы можете снова включить эту настройку или выполнить `SET compatibility = '24.6'`. [#58970](https://github.com/ClickHouse/ClickHouse/pull/58970) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Выводить трассировку стека и диагностическую информацию, если `clickhouse-client` или `clickhouse-local` аварийно завершается. [#61109](https://github.com/ClickHouse/ClickHouse/pull/61109) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Результат `SHOW INDEX | INDEXES | INDICES | KEYS` ранее сортировался по именам столбцов первичного ключа. Поскольку это было неинтуитивно, теперь результат сортируется по положению столбцов в первичном ключе. [#61131](https://github.com/ClickHouse/ClickHouse/pull/61131) ([Robert Schulze](https://github.com/rschu1ze)).
* Этот PR меняет работу дедупликации для MV. Исправлено множество случаев, например: - в целевой таблице: данные разбиваются на 2 или более блоков, и эти блоки считаются дубликатами, когда такой блок вставляется параллельно. - в целевой таблице MV: одинаковые блоки дедуплицируются; это происходит, когда MV из-за агрегации часто создаёт одинаковые результирующие данные для разных входных данных. - в целевой таблице MV: дедуплицируются одинаковые блоки, поступающие из разных MV. [#61601](https://github.com/ClickHouse/ClickHouse/pull/61601) ([Sema Checherinda](https://github.com/CheSema)).
* Разрешено сопоставление имён столбцов без учёта регистра при чтении JSON‑файлов (`input_format_json_case_insensitive_column_matching`). [#61750](https://github.com/ClickHouse/ClickHouse/pull/61750) ([kevinyhzou](https://github.com/KevinyhZou)).
* Добавлена поддержка чтения партиционированных данных DeltaLake. Схема DeltaLake теперь определяется по metadata, а не по данным. [#63201](https://github.com/ClickHouse/ClickHouse/pull/63201) ([Kseniia Sumarokova](https://github.com/kssenii)).
* В Composable protocols уровень TLS принимал только параметры `certificateFile` и `privateKeyFile`. [https://clickhouse.com/docs/en/operations/settings/composable-protocols](https://clickhouse.com/docs/en/operations/settings/composable-protocols). [#63985](https://github.com/ClickHouse/ClickHouse/pull/63985) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Создан интерактивный клиент для clickhouse-disks, добавлена возможность добавлять локальный диск из локального каталога. Исправляет [#56791](https://github.com/ClickHouse/ClickHouse/issues/56791). [#64446](https://github.com/ClickHouse/ClickHouse/pull/64446) ([Daniil Ivanik](https://github.com/divanik)).
* Добавлено событие профиля `SelectQueriesWithPrimaryKeyUsage`, которое показывает, сколько SELECT-запросов используют первичный ключ для вычисления предложения WHERE. [#64492](https://github.com/ClickHouse/ClickHouse/pull/64492) ([0x01f](https://github.com/0xfei)).
* Исправления и улучшения, связанные с `StorageS3Queue`. Значение `s3queue_processing_threads_num` по умолчанию теперь определяется на основе количества физических CPU cores на сервере (вместо прежнего значения 1). Значение `s3queue_loading_retries` по умолчанию установлено равным 10. Исправлено возможное неинформативное &quot;Uncaught exception&quot; в столбце исключений `system.s3queue`. Счётчик повторных попыток больше не увеличивается при исключении `MEMORY_LIMIT_EXCEEDED`. Коммит файлов перенесён на этап после полного завершения вставки в таблицу, чтобы избежать коммита файлов, данные из которых не были вставлены. Добавлены настройки `s3queue_max_processed_files_before_commit`, `s3queue_max_processed_rows_before_commit`, `s3queue_max_processed_bytes_before_commit`, `s3queue_max_processing_time_sec_before_commit` для более точного управления временем коммита и сброса. [#65046](https://github.com/ClickHouse/ClickHouse/pull/65046) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Исправлена некорректная агрегация по нескольким столбцам на s390x. [#65062](https://github.com/ClickHouse/ClickHouse/pull/65062) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Добавлена поддержка псевдонимов в функции параметризованного представления (только в новом анализаторе). [#65190](https://github.com/ClickHouse/ClickHouse/pull/65190) ([Kseniia Sumarokova](https://github.com/kssenii)).
* S3. Уменьшено время повторных попыток для запросов и увеличено их количество для резервных копий. Для запросов — 8,5 минут и 100 повторных попыток, для восстановления из резервной копии — 1,2 часа и 1000 повторных попыток. [#65232](https://github.com/ClickHouse/ClickHouse/pull/65232) ([Sema Checherinda](https://github.com/CheSema)).
* Обновлено маскирование ключа аккаунта в логах azureBlobStorage. [#65273](https://github.com/ClickHouse/ClickHouse/pull/65273) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Отсечение партиций для предикатов `IN`, когда выражение фильтра является частью выражения `PARTITION BY`. [#65335](https://github.com/ClickHouse/ClickHouse/pull/65335) ([Eduard Karacharov](https://github.com/korowa)).
* Добавлены системные таблицы с основной информацией обо всех отсоединенных таблицах. [#65400](https://github.com/ClickHouse/ClickHouse/pull/65400) ([Konstantin Morozov](https://github.com/k-morozov)).
* Добавлена поддержка `cluster_for_parallel_replicas` при использовании параллельных реплик с пользовательским ключом. Это позволяет использовать параллельные реплики с пользовательским ключом с таблицами семейства MergeTree. [#65453](https://github.com/ClickHouse/ClickHouse/pull/65453) ([Antonio Andelic](https://github.com/antonio2368)).
* Добавлена поддержка LIMIT-оптимизации в плане запроса. Добавлен LIMIT pushdown для хранилища PostgreSQL и табличной функции. [#65454](https://github.com/ClickHouse/ClickHouse/pull/65454) ([Maksim Kita](https://github.com/kitaisreal)).
* Arraymin/max теперь можно применять ко всем сопоставимым типам данных. [#65455](https://github.com/ClickHouse/ClickHouse/pull/65455) ([pn](https://github.com/chloro-pn)).
* Улучшен учет памяти для cgroups v2, чтобы исключить объем, занимаемый кэшем страниц. [#65470](https://github.com/ClickHouse/ClickHouse/pull/65470) ([Nikita Taranov](https://github.com/nickitat)).
* Не создавать настройки формата для каждой строки при сериализации чанков для вставки в таблицу EmbeddedRocksDB. [#65474](https://github.com/ClickHouse/ClickHouse/pull/65474) ([Duc Canh Le](https://github.com/canhld94)).
* Исправлено Исключение out-of-range при парсинге Dwarf5 на s390x. [#65501](https://github.com/ClickHouse/ClickHouse/pull/65501) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Промпт `clickhouse-local` сокращен до `:)`. `getFQDNOrHostName()` работает слишком долго на macOS, и хост в промпте для `clickhouse-local` нам все равно не нужен. [#65510](https://github.com/ClickHouse/ClickHouse/pull/65510) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Предотвращен вывод сообщения jemalloc о per-CPU arenas на маломощных виртуальных машинах. [#65532](https://github.com/ClickHouse/ClickHouse/pull/65532) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Фоновая загрузка файлового кэша по умолчанию отключена. Она будет снова включена, когда мы исправим проблему с возможным &quot;Memory limit exceeded&quot;, поскольку при использовании потоков фоновой загрузки освобождение памяти происходит вне контекста запроса (тогда как буфер выделяется внутри контекста запроса). Кроме того, нужно добавить отдельную настройку, чтобы задавать максимальный размер загрузки для фоновых worker-потоков (сейчас он ограничен max&#95;file&#95;segment&#95;size, что может быть слишком большим). [#65534](https://github.com/ClickHouse/ClickHouse/pull/65534) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлена новая опция в config `<config_reload_interval_ms>`, которая позволяет указать, как часто ClickHouse будет перезагружать config. [#65545](https://github.com/ClickHouse/ClickHouse/pull/65545) ([alesapin](https://github.com/alesapin)).
* Реализовано двоичное кодирование для типов данных ClickHouse и добавлена его спецификация в документацию. Оно используется в двоичной сериализации Dynamic; также его можно использовать в форматах RowBinaryWithNamesAndTypes и Native через настройки. [#65546](https://github.com/ClickHouse/ClickHouse/pull/65546) ([Kruglov Pavel](https://github.com/Avogar)).
* Улучшена балансировка нагрузки в ZooKeeper. Текущий сеанс не истекает, пока оптимальные узлы не станут доступны, несмотря на `fallback_session_lifetime`. Добавлена поддержка балансировки с учетом зон доступности (AZ). [#65570](https://github.com/ClickHouse/ClickHouse/pull/65570) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Настройки сервера `compiled_expression_cache_size` и `compiled_expression_cache_elements_size` теперь отображаются в `system.server_settings`. [#65584](https://github.com/ClickHouse/ClickHouse/pull/65584) ([Robert Schulze](https://github.com/rschu1ze)).
* Если легковесное удаление выполняется для таблицы с проекцией(ями), пользователь может либо сгенерировать исключение (по умолчанию), либо удалить проекцию, к которой было бы применено легковесное удаление. [#65594](https://github.com/ClickHouse/ClickHouse/pull/65594) ([jsc0218](https://github.com/jsc0218)).
* Добавлена поддержка идентификации пользователя на основе расширения SubjectAltName сертификата X.509. [#65626](https://github.com/ClickHouse/ClickHouse/pull/65626) ([Anton Kozlov](https://github.com/tonickkozlov)).
* `clickhouse-local` теперь учитывает `max_server_memory_usage` и `max_server_memory_usage_to_ram_ratio` из файла конфигурации. Также по умолчанию он будет устанавливать максимальное использование памяти на уровне 90% от системной памяти, как это делает `clickhouse-server`. Это закрывает [#65695](https://github.com/ClickHouse/ClickHouse/issues/65695). [#65697](https://github.com/ClickHouse/ClickHouse/pull/65697) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлен скрипт для резервного копирования файлов в ClickHouse. Звучит странно, но это работает. [#65699](https://github.com/ClickHouse/ClickHouse/pull/65699) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена поддержка Cancel для источника PostgreSQL. [#65722](https://github.com/ClickHouse/ClickHouse/pull/65722) ([Maksim Kita](https://github.com/kitaisreal)).
* Теперь `allow_experimental_analyzer` управляется узлом-инициатором для распределенных запросов. Это обеспечивает совместимость и корректность операций в кластерах со смешанными версиями. [#65777](https://github.com/ClickHouse/ClickHouse/pull/65777) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* В Keeper теперь учитывается ограничение CPU в cgroup. [#65819](https://github.com/ClickHouse/ClickHouse/pull/65819) ([Antonio Andelic](https://github.com/antonio2368)).
* Разрешено использовать функцию `concat` без аргументов &#96;&#96;&#96; sql :) select concat();. [#65887](https://github.com/ClickHouse/ClickHouse/pull/65887) ([李扬](https://github.com/taiyang-li)).
