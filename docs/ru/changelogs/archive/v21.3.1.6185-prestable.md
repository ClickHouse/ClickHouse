<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Теперь все регистронезависимые имена функций при анализе запроса будут приводиться к нижнему регистру. Это необходимо для маршрутизации запросов к проекциям. [#20174](https://github.com/ClickHouse/ClickHouse/pull/20174) ([Amos Bird](https://github.com/amosbird)).
* Теперь запрещено создавать таблицы семейства MergeTree в старом синтаксисе с table TTL, поскольку он просто игнорируется. Attach старых таблиц по-прежнему возможен. [#20282](https://github.com/ClickHouse/ClickHouse/pull/20282) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Новая возможность
</div>

* Добавлен экспериментальный движок базы данных `Replicated`. Он реплицирует DDL-запросы на несколько хостов. [#16193](https://github.com/ClickHouse/ClickHouse/pull/16193) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Дедупликация распределённых запросов является продолжением [#16033](https://github.com/ClickHouse/ClickHouse/issues/16033) и частично решает задачу, предложенную в [#13574](https://github.com/ClickHouse/ClickHouse/issues/13574). [#17348](https://github.com/ClickHouse/ClickHouse/pull/17348) ([xjewer](https://github.com/xjewer)).

* * Включено в pull request. [#18508](https://github.com/ClickHouse/ClickHouse/pull/18508) ([PHO](https://github.com/depressed-pho)).
* Добавлена функция file() для чтения файла как String. Это закрывает [#issue:18851](https://github.com/ClickHouse/ClickHouse/issues/18851). [#19204](https://github.com/ClickHouse/ClickHouse/pull/19204) ([keenwolf](https://github.com/keen-wolf)).

Настройка `min_marks_to_honor_max_concurrent_queries` указывает применять предыдущую настройку, только если запрос читает не менее указанного числа marks. [#19544](https://github.com/ClickHouse/ClickHouse/pull/19544) ([Amos Bird](https://github.com/amosbird)).

[по ссылке](https://docs.aws.amazon.com/AmazonS3/latest/dev/ServerSideEncryptionCustomerKeys.html). Закрывает [#19428](https://github.com/ClickHouse/ClickHouse/issues/19428). <div id="performance-improvement">
  #### Повышение производительности
</div>

* Добавлен параллельный `select final` для одной части с `level>0`, если значение настройки `do_not_merge_across_partitions_select_final` равно 1. [#19375](https://github.com/ClickHouse/ClickHouse/pull/19375) ([Kruglov Pavel](https://github.com/Avogar)).
* Улучшена производительность столбцов битмапа при JOIN. [#19407](https://github.com/ClickHouse/ClickHouse/pull/19407) ([templarzq](https://github.com/templarzq)).
* HTTP-сервер частично переработан, чтобы сократить количество копий входящих и исходящих данных. Это дает до 1,5-кратного прироста производительности при вставке длинных записей через HTTP. [#19516](https://github.com/ClickHouse/ClickHouse/pull/19516) ([Ivan](https://github.com/abyss7)).
* Улучшена производительность агрегатных функций за счет более строгого aliasing. [#19946](https://github.com/ClickHouse/ClickHouse/pull/19946) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлен случай, когда парсер DataType мог иметь экспоненциальную сложность (обнаружено фаззером). Это закрывает [#20096](https://github.com/ClickHouse/ClickHouse/issues/20096). [#20132](https://github.com/ClickHouse/ClickHouse/pull/20132) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена настройка `compress` для таблиц `Memory`. Если она включена, таблица будет использовать меньше оперативной памяти. На некоторых машинах и датасетах SELECT также может выполняться быстрее, но это не всегда так. Это закрывает [#20093](https://github.com/ClickHouse/ClickHouse/issues/20093). Note: есть причины, по которым таблицы Memory могут работать медленнее, чем MergeTree: (1) отсутствие сжатия (2) статический размер блоков (3) отсутствие индексов и prewhere... [#20168](https://github.com/ClickHouse/ClickHouse/pull/20168) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Блоки больше не объединяются чрезмерно при INSERT SELECT, если вставка идет в таблицу Memory. В предыдущих версиях после INSERT SELECT в таблице Memory создавалось неэффективное представление данных. Это закрывает [#13052](https://github.com/ClickHouse/ClickHouse/issues/13052). [#20169](https://github.com/ClickHouse/ClickHouse/pull/20169) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Улучшена производительность агрегации по нескольким полям фиксированного размера (не подтверждено). [#20454](https://github.com/ClickHouse/ClickHouse/pull/20454) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ускорено чтение из таблиц `Memory` в экстремальных случаях (когда скорость чтения составляет порядка 50 GB/sec) за счет упрощения конвейера и, как следствие, снижения конкуренции за lock при планировании конвейера. [#20468](https://github.com/ClickHouse/ClickHouse/pull/20468) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Улучшена производительность GROUP BY по нескольким ключам фиксированного размера. [#20472](https://github.com/ClickHouse/ClickHouse/pull/20472) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Настройка `distributed_aggregation_memory_efficient` теперь включена по умолчанию. Это снизит использование памяти и улучшит производительность распределенных запросов. [#20599](https://github.com/ClickHouse/ClickHouse/pull/20599) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Код агрегации немного улучшен. [#20978](https://github.com/ClickHouse/ClickHouse/pull/20978) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Возвращены специализации intDiv/module vectorConstant для повышения производительности. Это исправляет [#21293](https://github.com/ClickHouse/ClickHouse/issues/21293) . Регрессия была внесена в [https://github.com/ClickHouse/ClickHouse/pull/18145](https://github.com/ClickHouse/ClickHouse/pull/18145) . [#21307](https://github.com/ClickHouse/ClickHouse/pull/21307) ([Amos Bird](https://github.com/amosbird)).

<div id="improvement">
  #### Улучшения
</div>

* Исправлено создание `TTL` в случаях, когда его выражение является функцией и совпадает с ключом `ORDER BY`. Теперь в `TTL` с `GROUP BY` можно задавать пользовательскую агрегацию для столбцов первичного ключа. Обратная несовместимость: для столбцов первичного ключа, которые не входят в `GROUP BY` и не заданы явно, при истечении TTL теперь применяется функция `any` вместо `max`. Также при использовании TTL с `WHERE` или `GROUP BY` во время rolling update могут возникать исключения при слияниях. [#15450](https://github.com/ClickHouse/ClickHouse/pull/15450) ([Anton Popov](https://github.com/CurtizJ)).
* Hedged Requests для удалённых запросов. Если включена настройка `use_hedged_requests` (по умолчанию), для одного запроса можно устанавливать несколько соединений с разными репликами. Новое соединение устанавливается, если существующее соединение с репликой не было установлено в течение `hedged_connection_timeout` или если в течение `receive_data_timeout` не были получены данные. Запрос использует первое соединение, которое отправит непустой пакет прогресса (или пакет данных, если `allow_changing_replica_until_first_data_packet`); остальные соединения отменяются. Поддерживаются запросы с `max_parallel_replicas > 1`. [#19291](https://github.com/ClickHouse/ClickHouse/pull/19291) ([Kruglov Pavel](https://github.com/Avogar)).
* Выводить inline frames для фатальных трассировок стека. [#19317](https://github.com/ClickHouse/ClickHouse/pull/19317) ([Ivan](https://github.com/abyss7)).
* Больше не игнорировать ошибки записи молча. [#19451](https://github.com/ClickHouse/ClickHouse/pull/19451) ([Azat Khuzhin](https://github.com/azat)).
* Добавлена поддержка `PREWHERE`, когда для таблиц заданы выражения безопасности на уровне строки. [#19576](https://github.com/ClickHouse/ClickHouse/pull/19576) ([Denis Glazachev](https://github.com/traceon)).
* Добавлен интерфейс IStoragePolicy. [#19608](https://github.com/ClickHouse/ClickHouse/pull/19608) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* Добавлена возможность ограничивать INSERT в Distributed по объёму ожидающих байтов для асинхронной отправки (добавлены настройки `bytes_to_delay_insert`/`max_delay_to_insert` и `bytes_to_throw_insert` для движка `Distributed`). [#19673](https://github.com/ClickHouse/ClickHouse/pull/19673) ([Azat Khuzhin](https://github.com/azat)).
* Перемещать условия, не относящиеся к JOIN, в предложение WHERE. [#18720](https://github.com/ClickHouse/ClickHouse/issues/18720). [#19685](https://github.com/ClickHouse/ClickHouse/pull/19685) ([hexiaoting](https://github.com/hexiaoting)).
* Добавлена отдельная директива config для профиля Buffer. [#19721](https://github.com/ClickHouse/ClickHouse/pull/19721) ([Azat Khuzhin](https://github.com/azat)).
* Показывать таблицы MaterializeMySQL в `system.parts`. [#19770](https://github.com/ClickHouse/ClickHouse/pull/19770) ([Stig Bakken](https://github.com/stigsb)).
* Инициализировать MaxDDLEntryID последним значением после перезапуска. До этого PR MaxDDLEntryID оставался нулевым, пока не будет обработан новый DDLTask. [#19924](https://github.com/ClickHouse/ClickHouse/pull/19924) ([Amos Bird](https://github.com/amosbird)).
* Добавлено преобразование структуры блока для INSERT в Distributed tables, если она не совпадает. [#19947](https://github.com/ClickHouse/ClickHouse/pull/19947) ([Azat Khuzhin](https://github.com/azat)).
* Если пользователь вызывает функцию `JSONExtract` с запрошенным типом `Float32`, разрешено неточное преобразование в результирующий тип. Например, число `0.1` в JSON имеет двойную точность и не представимо в Float32, но пользователь всё равно хочет его получить. Предыдущие версии возвращали 0 для типа, не являющегося Nullable, и NULL для типа Nullable, чтобы показать, что преобразование неточно. Логика была на 100% корректной, но это удивляло пользователей и вызывало вопросы. Это закрывает [#13962](https://github.com/ClickHouse/ClickHouse/issues/13962). [#19960](https://github.com/ClickHouse/ClickHouse/pull/19960) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Значение опции MYSQL&#95;OPT&#95;RECONNECT теперь можно задавать параметром &quot;opt&#95;reconnect&quot; в разделе config реплики MySQL. [#19998](https://github.com/ClickHouse/ClickHouse/pull/19998) ([Alexander Kazakov](https://github.com/Akazz)).
