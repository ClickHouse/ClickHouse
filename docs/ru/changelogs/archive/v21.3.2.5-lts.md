<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Теперь имена всех регистронезависимых функций на этапе анализа запроса будут приводиться к нижнему регистру. Это необходимо для маршрутизации запросов к проекциям. [#20174](https://github.com/ClickHouse/ClickHouse/pull/20174) ([Amos Bird](https://github.com/amosbird)).
* Теперь нельзя создавать таблицы MergeTree в старом синтаксисе с TTL на уровне таблицы, поскольку он просто игнорируется. При этом Attach старых таблиц по-прежнему возможен. [#20282](https://github.com/ClickHouse/ClickHouse/pull/20282) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Новая возможность
</div>

* Добавлен экспериментальный движок базы данных `Replicated`. Он реплицирует DDL-запросы на несколько хостов. [#16193](https://github.com/ClickHouse/ClickHouse/pull/16193) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Дедупликация распределённых запросов развивает [#16033](https://github.com/ClickHouse/ClickHouse/issues/16033) и частично закрывает предложение [#13574](https://github.com/ClickHouse/ClickHouse/issues/13574). [#17348](https://github.com/ClickHouse/ClickHouse/pull/17348) ([xjewer](https://github.com/xjewer)).
* Добавлена возможность резервного копирования и восстановления файлов метаданных для DiskS3. [#18377](https://github.com/ClickHouse/ClickHouse/pull/18377) ([Pavel Kovalenko](https://github.com/Jokser)).
* * Вошло в pull request. [#18508](https://github.com/ClickHouse/ClickHouse/pull/18508) ([PHO](https://github.com/depressed-pho)).
* Добавлена функция file() для чтения файла как String. Это закрывает [#issue:18851](https://github.com/ClickHouse/ClickHouse/issues/18851). [#19204](https://github.com/ClickHouse/ClickHouse/pull/19204) ([keenwolf](https://github.com/keen-wolf)).
* У таблиц с движком `MergeTree*` теперь есть две новые настройки уровня таблицы для управления параллелизмом запросов. Настройка `max_concurrent_queries` ограничивает количество одновременно выполняемых запросов, связанных с этой таблицей. Настройка `min_marks_to_honor_max_concurrent_queries` предписывает применять предыдущую настройку, только если запрос читает как минимум такое количество меток. [#19544](https://github.com/ClickHouse/ClickHouse/pull/19544) ([Amos Bird](https://github.com/amosbird)).
* * Упомянуто в [#18454](https://github.com/ClickHouse/ClickHouse/issues/18454) — добавлена функция `htmlOrxmlCoarseParse`; — добавлена поддержка разбора `<script></script>`; — добавлена поддержка разбора `<style></style>`; — добавлена поддержка разбора `<![CDATA[]]>`; — добавлена поддержка схлопывания пробельных символов; — добавлена поддержка разбора любого формата `<content>`; — в HyperScan добавлена поддержка SIMD; — всё выполняется за один проход. [#19600](https://github.com/ClickHouse/ClickHouse/pull/19600) ([zlx19950903](https://github.com/zlx19950903)).

* В ExecutableDictionarySource добавлена опция implicit&#95;key. Исправляет [#14527](https://github.com/ClickHouse/ClickHouse/issues/14527). [#19677](https://github.com/ClickHouse/ClickHouse/pull/19677) ([Maksim Kita](https://github.com/kitaisreal)).
* В клиент S3 добавлена поддержка Server Side Encryption Customer Keys (заголовок `x-amz-server-side-encryption-customer-(key/md5)`). См. [эту ссылку](https://docs.aws.amazon.com/AmazonS3/latest/dev/ServerSideEncryptionCustomerKeys.html). Закрывает [#19428](https://github.com/ClickHouse/ClickHouse/issues/19428). [#19748](https://github.com/ClickHouse/ClickHouse/pull/19748) ([Vladimir Chebotarev](https://github.com/excitoon)).
* Функция `reinterpretAs` обновлена и теперь поддерживает большие целые числа. Исправляет [#19691](https://github.com/ClickHouse/ClickHouse/issues/19691). [#19858](https://github.com/ClickHouse/ClickHouse/pull/19858) ([Maksim Kita](https://github.com/kitaisreal)).
* Добавлена настройка `insert_shard_id`, позволяющая выполнять вставку данных в конкретный сегмент из distributed таблицы. [#19961](https://github.com/ClickHouse/ClickHouse/pull/19961) ([flynn](https://github.com/ucasfl)).
* Добавлена функция timezoneOffset(datetime), которая возвращает смещение относительно UTC в секундах. Закрывает [#issue:19850](https://github.com/ClickHouse/ClickHouse/issues/19850). [#19962](https://github.com/ClickHouse/ClickHouse/pull/19962) ([keenwolf](https://github.com/keen-wolf)).
* В таблицу `system.part_log` добавлен новый столбец `event_time_microseconds`. [#20027](https://github.com/ClickHouse/ClickHouse/pull/20027) ([Bharat Nallan](https://github.com/bharatnc)).
* ... Добавлена aggregate function `deltaSum` для суммирования разностей между последовательными строками. [#20057](https://github.com/ClickHouse/ClickHouse/pull/20057) ([Russ Frank](https://github.com/rf)).
* Добавлены две настройки, позволяющие задерживать вставку или сгенерировать исключение, если неактивных частей слишком много. Это полезно, когда server не успевает достаточно быстро очищать части. [#20178](https://github.com/ClickHouse/ClickHouse/pull/20178) ([Amos Bird](https://github.com/amosbird)).
* Добавлены настройки движка File: `engine_file_empty_if_not_exists` и `engine_file_truncate_on_insert`. [#20620](https://github.com/ClickHouse/ClickHouse/pull/20620) ([M0r64n](https://github.com/M0r64n)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Добавлено параллельное выполнение SELECT FINAL для одной части с level&gt;0, когда настройка `do_not_merge_across_partitions_select_final` равна 1. [#19375](https://github.com/ClickHouse/ClickHouse/pull/19375) ([Kruglov Pavel](https://github.com/Avogar)).
* Повышена производительность столбцов битмапа при JOIN. [#19407](https://github.com/ClickHouse/ClickHouse/pull/19407) ([templarzq](https://github.com/templarzq)).
* HTTP-сервер частично переработан, чтобы делать меньше копий входящих и исходящих данных. Это дает до 1,5-кратного прироста производительности при вставке длинных записей по HTTP. [#19516](https://github.com/ClickHouse/ClickHouse/pull/19516) ([Ivan](https://github.com/abyss7)).
* Повышена производительность агрегатных функций за счет более строгого aliasing. [#19946](https://github.com/ClickHouse/ClickHouse/pull/19946) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлен случай, когда парсер DataType мог иметь экспоненциальную сложность (обнаружено фаззером). Это закрывает [#20096](https://github.com/ClickHouse/ClickHouse/issues/20096). [#20132](https://github.com/ClickHouse/ClickHouse/pull/20132) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена настройка `compress` для таблиц `Memory`. Если она включена, таблица будет использовать меньше оперативной памяти. На некоторых машинах и датасетах она также может работать быстрее на SELECT, но это не всегда так. Это закрывает [#20093](https://github.com/ClickHouse/ClickHouse/issues/20093). Note: есть причины, по которым таблицы Memory могут работать медленнее, чем MergeTree: (1) отсутствие сжатия (2) статический размер блоков (3) отсутствие индексов и prewhere... [#20168](https://github.com/ClickHouse/ClickHouse/pull/20168) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* При INSERT SELECT блоки больше не объединяются чрезмерно, если вставка выполняется в таблицу Memory. В предыдущих версиях после INSERT SELECT в таблице Memory создавалось неэффективное представление данных. Это закрывает [#13052](https://github.com/ClickHouse/ClickHouse/issues/13052). [#20169](https://github.com/ClickHouse/ClickHouse/pull/20169) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Повышена производительность агрегации по нескольким полям фиксированного размера (не подтверждено). [#20454](https://github.com/ClickHouse/ClickHouse/pull/20454) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ускорено чтение из таблиц `Memory` в экстремальных случаях (когда скорость чтения составляет порядка 50 GB/sec) за счет упрощения конвейера и, как следствие, снижения конкуренции за блокировки при планировании конвейера. [#20468](https://github.com/ClickHouse/ClickHouse/pull/20468) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Повышена производительность GROUP BY по нескольким ключам фиксированного размера. [#20472](https://github.com/ClickHouse/ClickHouse/pull/20472) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Настройка `distributed_aggregation_memory_efficient` теперь включена по умолчанию. Она снизит использование памяти и повысит производительность распределенных запросов. [#20599](https://github.com/ClickHouse/ClickHouse/pull/20599) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Немного улучшен код, связанный с агрегацией. [#20978](https://github.com/ClickHouse/ClickHouse/pull/20978) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Возвращены специализации intDiv/module vectorConstant для повышения производительности. Это исправляет [#21293](https://github.com/ClickHouse/ClickHouse/issues/21293) . Регрессия была внесена в [https://github.com/ClickHouse/ClickHouse/pull/18145](https://github.com/ClickHouse/ClickHouse/pull/18145) . [#21307](https://github.com/ClickHouse/ClickHouse/pull/21307) ([Amos Bird](https://github.com/amosbird)).

<div id="improvement">
  #### Улучшения
</div>

* Исправлено создание `TTL` в случаях, когда его выражение является функцией и совпадает с ключом `ORDER BY`. Теперь в `TTL` с `GROUP BY` можно задавать пользовательскую агрегацию для столбцов первичного ключа. Обратная несовместимость: для столбцов первичного ключа, которые не входят в `GROUP BY` и не заданы явно, при истечении TTL теперь применяется функция `any` вместо `max`. Также при использовании TTL с `WHERE` или `GROUP BY` во время слияний могут возникать исключения при выполнении rolling update. [#15450](https://github.com/ClickHouse/ClickHouse/pull/15450) ([Anton Popov](https://github.com/CurtizJ)).
* Hedged Requests для удалённых запросов. Если включена настройка `use_hedged_requests` (по умолчанию), для одного запроса можно устанавливать несколько соединений с разными репликами. Новое соединение устанавливается, если существующее соединение с репликой не было установлено в течение `hedged_connection_timeout` или если данные не были получены в течение `receive_data_timeout`. Запрос использует первое соединение, которое отправит непустой пакет прогресса (или пакет данных, если `allow_changing_replica_until_first_data_packet`); остальные соединения отменяются. Поддерживаются запросы с `max_parallel_replicas > 1`. [#19291](https://github.com/ClickHouse/ClickHouse/pull/19291) ([Kruglov Pavel](https://github.com/Avogar)).
* Печать встроенных кадров для фатальных трассировок стека. [#19317](https://github.com/ClickHouse/ClickHouse/pull/19317) ([Ivan](https://github.com/abyss7)).
* Ошибки записи больше не игнорируются без уведомления. [#19451](https://github.com/ClickHouse/ClickHouse/pull/19451) ([Azat Khuzhin](https://github.com/azat)).
* Добавлена поддержка `PREWHERE` для таблиц, у которых заданы выражения безопасности на уровне строки. [#19576](https://github.com/ClickHouse/ClickHouse/pull/19576) ([Denis Glazachev](https://github.com/traceon)).
* Добавлен интерфейс IStoragePolicy. [#19608](https://github.com/ClickHouse/ClickHouse/pull/19608) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* Добавлена возможность ограничивать INSERT в Distributed в зависимости от объёма байтов, ожидающих асинхронной отправки (добавлены настройки `bytes_to_delay_insert`/`max_delay_to_insert` и `bytes_to_throw_insert` для движка `Distributed`). [#19673](https://github.com/ClickHouse/ClickHouse/pull/19673) ([Azat Khuzhin](https://github.com/azat)).
* Перемещать условия, не относящиеся к JOIN, в предложение WHERE. [#18720](https://github.com/ClickHouse/ClickHouse/issues/18720). [#19685](https://github.com/ClickHouse/ClickHouse/pull/19685) ([hexiaoting](https://github.com/hexiaoting)).
* Добавлена отдельная директива config для профиля Buffer. [#19721](https://github.com/ClickHouse/ClickHouse/pull/19721) ([Azat Khuzhin](https://github.com/azat)).
* Показывать таблицы MaterializeMySQL в `system.parts`. [#19770](https://github.com/ClickHouse/ClickHouse/pull/19770) ([Stig Bakken](https://github.com/stigsb)).
* После перезапуска MaxDDLEntryID инициализируется последним значением. До этого PR MaxDDLEntryID оставался равным нулю, пока не будет обработан новый DDLTask. [#19924](https://github.com/ClickHouse/ClickHouse/pull/19924) ([Amos Bird](https://github.com/amosbird)).
* Добавлено преобразование структуры блока для INSERT в Distributed tables, если она не совпадает. [#19947](https://github.com/ClickHouse/ClickHouse/pull/19947) ([Azat Khuzhin](https://github.com/azat)).
* Если пользователь вызывает функцию `JSONExtract` с запрошенным типом `Float32`, теперь допускается неточное преобразование к результирующему типу. Например, число `0.1` в JSON имеет двойную точность и не может быть представлено в Float32, но пользователь всё равно хочет его получить. Предыдущие версии возвращали 0 для типа non-Nullable и NULL для типа Nullable, чтобы показать, что преобразование неточно. Логика была на 100% правильной, но это удивляло пользователей и вызывало вопросы. Это закрывает [#13962](https://github.com/ClickHouse/ClickHouse/issues/13962). [#19960](https://github.com/ClickHouse/ClickHouse/pull/19960) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Значением опции MYSQL&#95;OPT&#95;RECONNECT теперь можно управлять с помощью параметра &quot;opt&#95;reconnect&quot; в разделе config mysql-реплики. [#19998](https://github.com/ClickHouse/ClickHouse/pull/19998) ([Alexander Kazakov](https://github.com/Akazz)).
