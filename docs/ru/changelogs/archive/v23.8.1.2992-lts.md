<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Возможность кэша метаданных объявлена устаревшей. Она экспериментальная, и мы её никогда не использовали. Эта возможность опасна: [#51182](https://github.com/ClickHouse/ClickHouse/issues/51182). Удалена системная таблица `system.merge_tree_metadata_cache`. Кэш метаданных всё ещё доступен в этой версии, но скоро будет удалён. Это закрывает [#39197](https://github.com/ClickHouse/ClickHouse/issues/39197). [#51303](https://github.com/ClickHouse/ClickHouse/pull/51303) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Если динамический disk содержит имя, его нужно указывать как `disk = disk(name = 'disk_name'`, ...) в аргументах функции disk. В предыдущей версии его можно было указывать как `disk = disk_<disk_name>(...)`, но теперь это больше не поддерживается. [#52820](https://github.com/ClickHouse/ClickHouse/pull/52820) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `clickhouse-benchmark` будет устанавливать connections параллельно при запуске с `--concurrency` больше 1. Ранее утилита была практически непригодна для использования, если запускать её с 1000 параллельными connections из Европы в США. Исправлен расчёт QPS для connections с высокой latency. Обратно несовместимое изменение: удалена опция JSON-вывода для `clickhouse-benchmark`. Если вы использовали эту опцию, в качестве обходного решения можно извлекать данные из `system.query_log` в формате JSON. [#53293](https://github.com/ClickHouse/ClickHouse/pull/53293) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Столбец `microseconds` удалён из `system.text_log`, а столбец `milliseconds` удалён из `system.metric_log`, поскольку они избыточны при наличии столбца `event_time_microseconds`. [#53601](https://github.com/ClickHouse/ClickHouse/pull/53601) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Изменены пути ZooKeeper для metadata хранилища `S3Queue`. [#54137](https://github.com/ClickHouse/ClickHouse/pull/54137) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Включена JIT-компиляция для AArch64, PowerPC, SystemZ и RISCV. [#38217](https://github.com/ClickHouse/ClickHouse/pull/38217) ([Maksim Kita](https://github.com/kitaisreal)).
* Этот патч добавляет способ обрабатывать все hashset&#39;ы параллельно перед merge. [#50748](https://github.com/ClickHouse/ClickHouse/pull/50748) ([Jiebin Sun](https://github.com/jiebinn)).
* Оптимизирована производительность агрегации для nullable-строкового ключа при использовании aggregationmethodserialized. [#51399](https://github.com/ClickHouse/ClickHouse/pull/51399) ([LiuNeng](https://github.com/liuneng1994)).
* Эксперименты по производительности **SSB** на устройстве ICX (Intel Xeon Platinum 8380 CPU, 80 ядер, 160 потоков) показывают, что это изменение может дать прирост **geomean QPS** на **8.5%**, когда включен экспериментальный analyzer. Подробности показаны ниже: ![image](https://github.com/ClickHouse/ClickHouse/assets/26588299/4e58bf8b-d276-408d-ad45-38c82d3cb918). [#52091](https://github.com/ClickHouse/ClickHouse/pull/52091) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Pushdown фильтров для Parquet. То есть при чтении файлов Parquet row group (фрагменты файла) пропускаются на основе условия WHERE и значений min/max в каждом столбце. В частности, если файл приблизительно отсортирован по какому-либо столбцу, запросы с фильтрацией по небольшому диапазону значений этого столбца будут выполняться значительно быстрее. [#52951](https://github.com/ClickHouse/ClickHouse/pull/52951) ([Michael Kolupaev](https://github.com/al13n321)).
* Оптимизирован merge, если в UniqExactSet все hashSet имеют тип singleLevel. [#52973](https://github.com/ClickHouse/ClickHouse/pull/52973) ([Jiebin Sun](https://github.com/jiebinn)).
* StorageJoin: не создавать clone hash join со всеми столбцами. [#53046](https://github.com/ClickHouse/ClickHouse/pull/53046) ([Duc Canh Le](https://github.com/canhld94)).
* Оптимизировано чтение небольших row group в Parquet за счет их объединения в батчи. Закрывает [#53069](https://github.com/ClickHouse/ClickHouse/issues/53069). [#53281](https://github.com/ClickHouse/ClickHouse/pull/53281) ([Kruglov Pavel](https://github.com/Avogar)).
* Реализован native input format ORC без arrow для повышения производительности. [#53324](https://github.com/ClickHouse/ClickHouse/pull/53324) ([李扬](https://github.com/taiyang-li)).
* Панель мониторинга будет указывать серверу сжимать данные, что полезно для больших временных диапазонов при медленном интернет-соединении. Например, один график с 86400 точками может занимать 1.5 MB в несжатом виде и 60 KB в сжатом с `br`. [#53569](https://github.com/ClickHouse/ClickHouse/pull/53569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Оптимизирован count по файлам в большинстве input format. Закрывает [#44334](https://github.com/ClickHouse/ClickHouse/issues/44334). [#53637](https://github.com/ClickHouse/ClickHouse/pull/53637) ([Kruglov Pavel](https://github.com/Avogar)).
* Более эффективное использование пула потоков для BACKUP и RESTORE. [#53649](https://github.com/ClickHouse/ClickHouse/pull/53649) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Удалено ненужное замедление в проверке производительности клиента. [#53695](https://github.com/ClickHouse/ClickHouse/pull/53695) ([Raúl Marín](https://github.com/Algunenano)).
