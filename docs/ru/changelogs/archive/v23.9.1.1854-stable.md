<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение

* Из обработчика Prometheus по умолчанию удалены параметр конфигурации `status_info` и статус словарей. [#54090](https://github.com/ClickHouse/ClickHouse/pull/54090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Новая возможность
</div>

* Добавлен новый тип аутентификации на основе SSH-ключей. Он работает только для собственного TCP-протокола. [#41109](https://github.com/ClickHouse/ClickHouse/pull/41109) ([George Gamezardashvili](https://github.com/InfJoker)).
* Добавлена поддержка планирования ввода-вывода для удаленных дисков. Конфигурация хранилища для типов дисков `s3`, `s3_plain`, `hdfs` и `azure_blob_storage` теперь может содержать элементы `read_resource` и `write_resource` с именами ресурсов. Политики планирования для этих ресурсов можно настроить в отдельном разделе конфигурации сервера `resources`. Запросы можно помечать с помощью настройки `workload` и классифицировать с помощью раздела конфигурации сервера `workload_classifiers`, чтобы решать различные задачи планирования ресурсов. Подробнее см. в docs/en/operations/workload-scheduling.md. [#47009](https://github.com/ClickHouse/ClickHouse/pull/47009) ([Sergei Trifonov](https://github.com/serxa)).
* Добавлен новый столбец &#95;block&#95;number, закрывает [#44532](https://github.com/ClickHouse/ClickHouse/issues/44532). [#47532](https://github.com/ClickHouse/ClickHouse/pull/47532) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Добавлены параметры `partial_result_update_duration_ms` и `max_rows_in_partial_result`, чтобы показывать обновления частичного результата выходной таблицы в реальном времени во время выполнения запроса. [#48607](https://github.com/ClickHouse/ClickHouse/pull/48607) ([Alexey Perevyshin](https://github.com/alexX512)).
* Добавлена поддержка регистронезависимого режима и режима dot-all для сопоставления в словарях RegExpTree. [#50906](https://github.com/ClickHouse/ClickHouse/pull/50906) ([Johann Gan](https://github.com/johanngan)).
* Добавлена поддержка `ALTER TABLE MODIFY COMMENT`. Примечание: нечто похожее уже давно было добавлено внешним участником, но эта возможность вообще не работала и только сбивала пользователей с толку. Это закрывает [#36377](https://github.com/ClickHouse/ClickHouse/issues/36377). [#51304](https://github.com/ClickHouse/ClickHouse/pull/51304) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлен &quot;GCD&quot;, он же &quot;наибольший общий делитель&quot;, как новый кодек сжатия данных. Кодек вычисляет GCD для всех значений столбца, а затем делит каждое значение на GCD. Кодек GCD — это кодек подготовки данных (аналогично Delta и DoubleDelta), и его нельзя использовать самостоятельно. Он работает с целочисленными, десятичными и типами данных даты/времени. Подходящий сценарий использования кодека GCD — значения столбца, которые изменяются (увеличиваются/уменьшаются) с шагом, кратным GCD, например 24 - 28 - 16 - 24 - 8 - 24 (если GCD = 4). [#53149](https://github.com/ClickHouse/ClickHouse/pull/53149) ([Alexander Nam](https://github.com/seshWCS)).
* Добавлены два новых псевдонима типов: &quot;DECIMAL(P)&quot; (как сокращение для &quot;DECIMAL(P, 0&quot;) и &quot;DECIMAL&quot; (как сокращение для &quot;DECIMAL(10, 0)&quot;). Это делает ClickHouse более совместимым с SQL-диалектом MySQL. [#53328](https://github.com/ClickHouse/ClickHouse/pull/53328) ([Val Doroshchuk](https://github.com/valbok)).
* Добавлена новая системная Log-таблица `backup_log` для отслеживания всех операций `BACKUP` и `RESTORE`. [#53638](https://github.com/ClickHouse/ClickHouse/pull/53638) ([Victor Krasnov](https://github.com/sirvickr)).
* Добавлена настройка формата &quot;output&#95;format&#95;markdown&#95;escape&#95;special&#95;characters&quot; (по умолчанию: false). Эта настройка определяет, экранируются ли специальные символы, такие как &quot;!&quot;, &quot;#&quot;, &quot;$&quot; и т. д. (то есть с префиксом в виде символа обратной косой черты), в выходном формате &quot;Markdown&quot;. [#53860](https://github.com/ClickHouse/ClickHouse/pull/53860) ([irenjj](https://github.com/irenjj)).
* Добавлена функция `decodeHTMLComponent`. [#54097](https://github.com/ClickHouse/ClickHouse/pull/54097) ([Bharat Nallan](https://github.com/bharatnc)).
* В таблицу query&#95;log добавлено поле peak&#95;threads&#95;usage. [#54335](https://github.com/ClickHouse/ClickHouse/pull/54335) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* В клиент ClickHouse добавлена поддержка SHOW FUNCTIONS. [#54337](https://github.com/ClickHouse/ClickHouse/pull/54337) ([Julia Kartseva](https://github.com/wat-ze-hex)).
* Этот PR улучшает вывод схемы для JSON formats: 1) Теперь можно выводить именованные Tuple из объектов JSON без экспериментального типа JSON с помощью настройки `input_format_json_try_infer_named_tuples_from_objects`. Ранее без экспериментального типа JSON объекты JSON можно было выводить только как String или Map, теперь — и как именованный Tuple. Получившийся тип Tuple будет содержать все ключи объектов, прочитанных из выборки данных при выводе схемы. Это полезно для чтения структурированных данных JSON без разреженных объектов. Настройка включена по умолчанию. 2) Разрешён разбор JSON-массива в столбец типа String с помощью настройки `input_format_json_read_arrays_as_strings`. Это может быть полезно при чтении массивов со значениями разных типов. 3) Разрешено использовать тип String для ключей JSON с неизвестными типами (`null`/`[]`/`{}`) в выборке данных с помощью настройки `input_format_json_infer_incomplete_types_as_strings`. Теперь в JSON formats можно читать любое значение в столбец String и избежать ошибки `Cannot determine type for column 'column_name' by first 25000 rows of data, most likely this column contains only Nulls or empty Arrays/Maps` при выводе схемы, используя тип String для неизвестных типов, — в этом случае данные будут успешно прочитаны. [#54427](https://github.com/ClickHouse/ClickHouse/pull/54427) ([Kruglov Pavel](https://github.com/Avogar)).
* Добавлена функция &quot;toDaysSinceYearZero&quot; с псевдонимом &quot;TO&#95;DAYS()&quot; (для совместимости с MySQL), которая возвращает число дней, прошедших с 0001-01-01. [#54479](https://github.com/ClickHouse/ClickHouse/pull/54479) ([Robert Schulze](https://github.com/rschu1ze)).
* Добавлены функции YYYYMMDDtoDate(), YYYYMMDDtoDate32(), YYYYMMDDhhmmssToDateTime() и YYYYMMDDhhmmssToDateTime64(). Они преобразуют дату или дату и время, закодированные как целое число (например, 20230911), во внутренний тип даты или даты и времени. Таким образом, они обеспечивают функциональность, обратную существующим функциям YYYYMMDDToDate(), YYYYMMDDToDateTime(), YYYYMMDDhhmmddToDateTime(), YYYYMMDDhhmmddToDateTime64(). [#54509](https://github.com/ClickHouse/ClickHouse/pull/54509) ([Robert Schulze](https://github.com/rschu1ze)).
* Добавлен тип узла планирования ввода-вывода &quot;bandwidth&#95;limit&quot;. Он позволяет задавать ограничения `max_speed` и `max_burst` для трафика, проходящего через этот узел. Подробнее см. в docs/en/operations/workload-scheduling.md. [#54618](https://github.com/ClickHouse/ClickHouse/pull/54618) ([Sergei Trifonov](https://github.com/serxa)).
* Функция `toDaysSinceYearZero()` теперь поддерживает аргументы типов `DateTime` и `DateTime64`. [#54856](https://github.com/ClickHouse/ClickHouse/pull/54856) ([Serge Klochkov](https://github.com/slvrtrn)).
* Для табличных функций `s3`, `gcs`, `oss` разрешены URL в стиле S3. URL автоматически преобразуется в HTTP. Пример: `'s3://clickhouse-public-datasets/hits.csv'` преобразуется в `'https://clickhouse-public-datasets.s3.amazonaws.com/hits.csv'`. [#54931](https://github.com/ClickHouse/ClickHouse/pull/54931) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлено несколько функций расстояния для строк, включая `byteHammingDistance`, `byteJaccardIndex`, `byteEditDistance`. ### Запись в документации для изменений, видимых пользователю. [#54935](https://github.com/ClickHouse/ClickHouse/pull/54935) ([flynn](https://github.com/ucasfl)).
* Добавлена новая настройка `print_pretty_type_names` для вывода в удобочитаемом виде глубоко вложенных типов, таких как Tuple/Maps/Arrays. [#55095](https://github.com/ClickHouse/ClickHouse/pull/55095) ([Kruglov Pavel](https://github.com/Avogar)).

* Заменена библиотека для обработки (кодирования/декодирования) значений base64: вместо Turbo-Base64 теперь используется aklomp-base64. Обе библиотеки используют SIMD-ускорение на x86 и ARM, но 1. лицензия последней (BSD-2) более удобна для ClickHouse, поскольку Turbo64 тем временем перешла на GPL-3, 2. судя по большему числу звёзд на GitHub, aklomp-base64 выглядит более перспективной в долгосрочной перспективе, 3. у aklomp-base64 немного более удобный API (хотя это, возможно, субъективно), и 4. aklomp-base64 не требует обходных решений для ошибок (например, инициализации, небезопасной для потоков). Примечание: aklomp-base64 отклоняет значения base64 без дополнения, тогда как Turbo-Base64 декодирует их по мере возможности. RFC-4648 оставляет открытым вопрос о том, обязательно ли дополнение, но в зависимости от контекста это может быть изменением поведения, о котором стоит знать. [#54119](https://github.com/ClickHouse/ClickHouse/pull/54119) ([Mikhail Koviazin](https://github.com/mkmkme)).
* В HTTP-заголовки X-ClickHouse-Progress и X-ClickHouse-Summary добавлен elapsed&#95;ns. [#54179](https://github.com/ClickHouse/ClickHouse/pull/54179) ([joelynch](https://github.com/joelynch)).
