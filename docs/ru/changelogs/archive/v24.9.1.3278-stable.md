<div id="backward-incompatible-change">
  #### обратно несовместимое изменение
</div>

* Разрешено указывать `SETTINGS` перед `FORMAT` в цепочке запросов с `UNION`, когда подзапросы заключены в скобки. Это закрывает [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712). Также изменено поведение, если в запросе предложение `SETTINGS` указано дважды подряд. Для соответствующего подзапроса приоритет будет у ближайшего предложения `SETTINGS`. В предыдущих версиях внешнее предложение `SETTINGS` могло иметь приоритет над внутренним. [#60197](https://github.com/ClickHouse/ClickHouse/pull/60197) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Запрещено явно указывать UUID при создании таблицы в базе данных Replicated. Также запрещено явно указывать путь ZooKeeper и имя реплики для таблиц семейства *MergeTree в базах данных Replicated. [#66104](https://github.com/ClickHouse/ClickHouse/pull/66104) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Переработан тип Dynamic. Теперь, когда достигнут лимит динамических типов данных, новые типы не приводятся к String, а сохраняются в специальной структуре данных в бинарном формате с бинарно закодированным типом данных. Теперь любой тип, когда-либо вставленный в столбец типа Dynamic, можно читать из него как подстолбец. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Pavel Kruglov](https://github.com/Avogar)).
* Для именованных Tuple поддерживаются выражения вида `a[b].c`, а также именованные обращения по индексу из произвольных выражений, например `expr().name`. Это полезно при обработке JSON. Это закрывает [#54965](https://github.com/ClickHouse/ClickHouse/issues/54965). В предыдущих версиях выражение вида `expr().name` разбиралось как `tupleElement(expr(), name)`, и анализатор запросов искал столбец `name`, а не соответствующий элемент Tuple; в новой версии это изменено на `tupleElement(expr(), 'name')`. В большинстве случаев прежняя версия не работала, но можно представить очень необычный сценарий, в котором это изменение могло бы привести к несовместимости: если вы хранили имена элементов Tuple в столбце или алиасе, имя которого отличалось от имени элемента Tuple: `SELECT 'b' AS a, CAST([tuple(123)] AS 'Array(Tuple(b UInt8))') AS t, t[1].a`. Крайне маловероятно, что вы использовали такие запросы, но мы всё же должны пометить это изменение как потенциально обратно несовместимое. [#68435](https://github.com/ClickHouse/ClickHouse/pull/68435) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Когда включена настройка `print_pretty_type_names`, она будет выводить тип данных `Tuple` в удобочитаемом виде в операторах `SHOW CREATE TABLE`, функции `formatQuery`, а также в интерактивном режиме в клиенте ClickHouse и `clickhouse-local`. В предыдущих версиях эта настройка применялась только к запросам `DESCRIBE` и `toTypeName`. Это закрывает [#65753](https://github.com/ClickHouse/ClickHouse/issues/65753). [#68492](https://github.com/ClickHouse/ClickHouse/pull/68492) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Новая возможность
</div>

* Функция `toStartOfInterval()` теперь имеет новую перегрузку, которая эмулирует функцию `time_bucket()` из TimescaleDB и функцию `date_bin()` из PostgreSQL. ([#55619](https://github.com/ClickHouse/ClickHouse/issues/55619)). Она позволяет выравнивать значения даты или временной метки по кратным заданного интервала, начиная с *произвольной* точки отсчета (вместо 0000-01-01 00:00:00.000 в качестве *фиксированной* точки отсчета). Например, `SELECT toStartOfInterval(toDateTime('2023-01-01 14:45:00'), INTERVAL 1 MINUTE, toDateTime('2023-01-01 14:35:30'));` возвращает `2023-01-01 14:44:30`, то есть значение, кратное интервалу в 1 минуту, начиная с точки отсчета `2023-01-01 14:35:30`. [#56738](https://github.com/ClickHouse/ClickHouse/pull/56738) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлена поддержка `ATTACH PARTITION ALL FROM`. [#61987](https://github.com/ClickHouse/ClickHouse/pull/61987) ([Kirill Nikiforov](https://github.com/allmazz)).
* Добавлена настройка `input_format_try_infer_variants`, которая позволяет выводить тип Variant при выводе схемы для текстовых форматов, когда для элементов столбца/массива возможно более одного типа. [#63798](https://github.com/ClickHouse/ClickHouse/pull/63798) ([Shaun Struwig](https://github.com/Blargian)).
* Представлен формат JSONCompactWithProgress, в котором ClickHouse выводит каждую строку как объект JSON в формате newline-delimited JSON, включая метаданные, данные, прогресс, итоги и статистику. [#66205](https://github.com/ClickHouse/ClickHouse/pull/66205) ([Alexey Korepanov](https://github.com/alexkorep)).
* Реализован новый тип данных JSON. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Pavel Kruglov](https://github.com/Avogar)).
* Добавлена настройка `input_format_json_empty_as_default`, которая во включенном состоянии обрабатывает пустые поля во входных данных JSON как значения по умолчанию. Закрывает [#59339](https://github.com/ClickHouse/ClickHouse/issues/59339). [#66782](https://github.com/ClickHouse/ClickHouse/pull/66782) ([Alexis Arnaud](https://github.com/a-a-f)).
* Добавлены функции `overlay` и `overlayUTF8`, которые заменяют части строки другой строкой. Пример: `SELECT overlay('Hello New York', 'Jersey', 11)` возвращает `Hello New Jersey`. [#66933](https://github.com/ClickHouse/ClickHouse/pull/66933) ([李扬](https://github.com/taiyang-li)).
* Добавлена новая команда легковесного удаления в партиции `DELETE FROM [db.]table [ON CLUSTER cluster] [IN PARTITION partition_expr] WHERE expr;` &#96;&#96;&#96; VM-114-29-tos :) select * from ads&#95;app&#95;poster&#95;ip&#95;source&#95;channel&#95;di&#95;replicated&#95;local;. [#67805](https://github.com/ClickHouse/ClickHouse/pull/67805) ([sunny](https://github.com/sunny19930321)).
* Реализовано сравнение значений типа данных `Interval`, поэтому теперь они преобразуются к наименьшему супертиру. [#68057](https://github.com/ClickHouse/ClickHouse/pull/68057) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлена настройка create&#95;if&#95;not&#95;exists, которая по умолчанию включает поведение IF NOT EXISTS для операторов CREATE. [#68164](https://github.com/ClickHouse/ClickHouse/pull/68164) ([Peter Nguyen](https://github.com/petern48)).
* Появилась возможность читать таблицы Iceberg в Azure и локально. [#68210](https://github.com/ClickHouse/ClickHouse/pull/68210) ([Daniil Ivanik](https://github.com/divanik)).
* Добавлены агрегатные функции distinctDynamicTypes/distinctJSONPaths/distinctJSONPathsAndTypes для более удобной интроспекции содержимого типа столбца JSON. [#68463](https://github.com/ClickHouse/ClickHouse/pull/68463) ([Pavel Kruglov](https://github.com/Avogar)).
* Записи кэша запросов теперь можно удалять по тегу. Например, запись кэша запросов, созданную с помощью `SELECT 1 SETTINGS use_query_cache = true, query_cache_tag = 'abc'`, теперь можно удалить командой `SYSTEM DROP QUERY CACHE TAG 'abc'` (или, конечно, просто `SYSTEM DROP QUERY CACHE`, чтобы очистить весь кэш запросов). [#68477](https://github.com/ClickHouse/ClickHouse/pull/68477) ([Michał Tabaszewski](https://github.com/pinsvin00)).
* Добавлено шифрование хранилища для именованных коллекций. [#68615](https://github.com/ClickHouse/ClickHouse/pull/68615) ([Pablo Marcos](https://github.com/pamarcos)).
* Добавлена функция `ripeMD160`, которая вычисляет криптографический хеш RIPEMD-160 для строки. Пример: `SELECT hex(ripeMD160('The quick brown fox jumps over the lazy dog'))` возвращает `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`. [#68639](https://github.com/ClickHouse/ClickHouse/pull/68639) ([Dergousov Maxim](https://github.com/m7kss1)).
* Добавлен виртуальный столбец &#95;headers для движка таблицы URL. Закрывает [#65026](https://github.com/ClickHouse/ClickHouse/issues/65026). [#68867](https://github.com/ClickHouse/ClickHouse/pull/68867) ([flynn](https://github.com/ucasfl)).
* Добавлена таблица `system.projections` для отслеживания доступных проекций. [#68901](https://github.com/ClickHouse/ClickHouse/pull/68901) ([Jordi Villar](https://github.com/jrdi)).
* Добавлена новая функция `arrayZipUnaligned` для совместимости со Spark(arrays&#95;zip), которая позволяет работать с невыровненными массивами на основе исходной `arrayZip`. &#96;&#96;&#96; sql SELECT arrayZipUnaligned([1], [1, 2, 3]). [#69030](https://github.com/ClickHouse/ClickHouse/pull/69030) ([李扬](https://github.com/taiyang-li)).
* Добавлена метрика `RealTimeMicroseconds` в HTTP-заголовок `X-ClickHouse-Summary`. Так можно узнать время CPU для запроса без необходимости проверять его в `system.query_log`. [#69032](https://github.com/ClickHouse/ClickHouse/pull/69032) ([Alejandro](https://github.com/alexon1234)).
* Добавлены команды cp/mv для клиента Keeper, которые атомарно копируют/перемещают node. [#69034](https://github.com/ClickHouse/ClickHouse/pull/69034) ([Mikhail Artemenko](https://github.com/Michicosun)).
* В функцию `arrayAUC` добавлен аргумент `scale` (по умолчанию: `true`), который позволяет пропустить шаг нормализации (issue [#69609](https://github.com/ClickHouse/ClickHouse/issues/69609)). [#69717](https://github.com/ClickHouse/ClickHouse/pull/69717) ([gabrielmcg44](https://github.com/gabrielmcg44)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Улучшена производительность JOIN за счёт перераспределения правой таблицы по ключам, когда ключи таблицы плотно распределены в left или inner hash join. [#60341](https://github.com/ClickHouse/ClickHouse/pull/60341) ([kevinyhzou](https://github.com/KevinyhZou)).
* Улучшена общая производительность всех JOIN за счёт добавления `RowRefList` или `RowRef` в AddedColumns для ленивого вывода; в `buildOutput` для вывода используются `RowRefList`/`RowRef`, а условие `is_join_get` удалено из цикла в `buildOutput`. [#63677](https://github.com/ClickHouse/ClickHouse/pull/63677) ([kevinyhzou](https://github.com/KevinyhZou)).
* Метаданные файлового кэша теперь загружаются асинхронно в процессе запуска, чтобы ускорить перезапуски. [#65736](https://github.com/ClickHouse/ClickHouse/pull/65736) ([Daniel Pozo Escalona](https://github.com/danipozo)).
* Функции `array` и `map` были оптимизированы для значительно более быстрой обработки некоторых распространённых случаев. [#67707](https://github.com/ClickHouse/ClickHouse/pull/67707) ([李扬](https://github.com/taiyang-li)).
* Выполнена небольшая оптимизация чтения строк ORC, особенно когда столбец не содержит NULL. [#67794](https://github.com/ClickHouse/ClickHouse/pull/67794) ([李扬](https://github.com/taiyang-li)).
* Улучшена общая производительность слияний за счёт снижения накладных расходов на планирование этапов слияния. [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* Ускорены запросы к S3, если profile не задан, credentials не заданы и IMDS недоступен (например, когда вы выполняете запрос к публичному бакету с машины вне облака). Это закрывает [#52771](https://github.com/ClickHouse/ClickHouse/issues/52771). [#68082](https://github.com/ClickHouse/ClickHouse/pull/68082) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Новый алгоритм для определения единицы распределения marks между репликами с помощью consistent hash. Для разных шаблонов чтения выбирается разное количество marks для повышения производительности. [#68424](https://github.com/ClickHouse/ClickHouse/pull/68424) ([Nikita Taranov](https://github.com/nickitat)).
* Предпринята попытка девиртуализировать reader формата в RowInputFormatWithNamesAndTypes и проверить, даст ли это прирост производительности. [#68437](https://github.com/ClickHouse/ClickHouse/pull/68437) ([李扬](https://github.com/taiyang-li)).
* Добавлена реализация параллельного слияния с ключом для максимального использования CPU. [#68441](https://github.com/ClickHouse/ClickHouse/pull/68441) ([Jiebin Sun](https://github.com/jiebinn)).
* Добавлены настройки `output_format_orc_dictionary_key_size_threshold`, позволяющие пользователю включить словарное кодирование для строкового столбца в ORC output format. Это помогает значительно уменьшить размер выходного ORC-файла и заметно повысить производительность чтения. [#68591](https://github.com/ClickHouse/ClickHouse/pull/68591) ([李扬](https://github.com/taiyang-li)).
* Реализовано чтение только необходимых файлов при hive partitioning. [#68963](https://github.com/ClickHouse/ClickHouse/pull/68963) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Представлен новый запрос Keeper RemoveRecursive, который удаляет узел вместе со всем его поддеревом. [#69332](https://github.com/ClickHouse/ClickHouse/pull/69332) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Ускорена производительность вставки с индексом векторного сходства за счёт параллельного добавления данных в векторный индекс. [#69493](https://github.com/ClickHouse/ClickHouse/pull/69493) ([flynn](https://github.com/ucasfl)).
* Ранее алгоритмическая сложность логики дедупликации частей при обработке announcement параллельной реплики составляла O(n^2), что могло занимать заметное время для таблиц с большим количеством частей (или партиций). Это изменение снижает сложность до O(n*log(n)). [#69596](https://github.com/ClickHouse/ClickHouse/pull/69596) ([Alexander Gololobov](https://github.com/davenger)).

<div id="improvement">
  #### Улучшения
</div>

* Повышена надёжность частей кодовой базы, связанных с парсингом небольших сущностей. Были обнаружены и исправлены следующие (незначительные) ошибки: - если таблица `DeltaLake` партиционирована по Bool, значение партиции всегда интерпретировалось как false; - таблица `ExternalDistributed` использовала только один шард из указанных адресов; значение настройки `max_threads` и аналогичных выводилось как `'auto(N)'` вместо `auto(N)`. [#52503](https://github.com/ClickHouse/ClickHouse/pull/52503) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Улучшения refreshable materialized view: режим append (`... REFRESH EVERY 1 MINUTE APPEND ...`) для добавления строк в существующую таблицу вместо перезаписи всей таблицы, повторные попытки (по умолчанию отключены, настраиваются в разделе SETTINGS запроса), запрос `SYSTEM WAIT VIEW <name>`, ожидающий завершения текущего обновления, а также некоторые исправления. [#58934](https://github.com/ClickHouse/ClickHouse/pull/58934) ([Michael Kolupaev](https://github.com/al13n321)).
* Для учёта использования CPU теперь используются метрики, специфичные для cgroup, вместо общесистемных метрик. [#62003](https://github.com/ClickHouse/ClickHouse/pull/62003) ([Nikita Taranov](https://github.com/nickitat)).
* Планирование ввода-вывода для удалённых S3-дисков теперь выполняется на уровне потоков HTTP-сокетов (а не целых S3-запросов), чтобы устранить проблемы с throttling для `bandwidth_limit`. [#65182](https://github.com/ClickHouse/ClickHouse/pull/65182) ([Sergei Trifonov](https://github.com/serxa)).
* Разрешено использовать для одного пользователя несколько методов аутентификации вместо одного. Также теперь можно сбросить методы аутентификации к последнему добавленному методу. Если вы планируете некоторое время запускать инстансы на 24.8 и один на 24.9, на этот период лучше установить `max_authentication_methods_per_user = 1`, чтобы избежать возможных ошибок. [#65277](https://github.com/ClickHouse/ClickHouse/pull/65277) ([Arthur Passos](https://github.com/arthurpassos)).
* Функции `upperUTF8` и `lowerUTF8` ранее могли преобразовывать в верхний / нижний регистр только кириллические символы. Это ограничение снято, и теперь в верхний/нижний регистр преобразуются символы любых языков. Пример: `SELECT upperUTF8('Süden')` теперь возвращает `SÜDEN`. [#65761](https://github.com/ClickHouse/ClickHouse/pull/65761) ([李扬](https://github.com/taiyang-li)).
* При легковесном удалении в таблице с проекциями раньше у пользователей было два варианта: либо сгенерировать исключение (по умолчанию), либо удалить проекцию, чтобы легковесное удаление могло выполниться; теперь появился и третий вариант — выполнить легковесное удаление, а затем пересобрать проекции. [#66169](https://github.com/ClickHouse/ClickHouse/pull/66169) ([Shichao](https://github.com/jsc0218)).
* Добавлены две опции (`dns_allow_resolve_names_to_ipv4` и `dns_allow_resolve_names_to_ipv6`), позволяющие блокировать соединения по семейству IP. [#66895](https://github.com/ClickHouse/ClickHouse/pull/66895) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Добавлен `min_max` как новый тип экспериментальной статистики. Он поддерживает оценку диапазонных предикатов по числовым столбцам, например `x < 100`. [#67013](https://github.com/ClickHouse/ClickHouse/pull/67013) ([JackyWoo](https://github.com/JackyWoo)).
* Сделано настраиваемым игнорирование Ctrl+Z (`ignore&#95;shell&#95;suspend`) в клиенте ClickHouse. [#67134](https://github.com/ClickHouse/ClickHouse/pull/67134) ([Azat Khuzhin](https://github.com/azat)).
* Улучшен `castOrDefault` для столбцов Variant/Dynamic, чтобы он работал, даже когда внутренние типы вообще не поддаются преобразованию. [#67150](https://github.com/ClickHouse/ClickHouse/pull/67150) ([Pavel Kruglov](https://github.com/Avogar)).
* Улучшено кодирование Unicode в JSON output formats. Это гарантирует генерацию корректного JSON в случае определённых байтовых последовательностей в результирующих данных. [#67938](https://github.com/ClickHouse/ClickHouse/pull/67938) ([mwoenker](https://github.com/mwoenker)).
* Добавлены события профиля для слияний и мутаций для более глубокой интроспекции. [#68015](https://github.com/ClickHouse/ClickHouse/pull/68015) ([Anton Popov](https://github.com/CurtizJ)).
* Odbc: параметр http&#95;max&#95;tries теперь берется из конфигурации сервера. [#68128](https://github.com/ClickHouse/ClickHouse/pull/68128) ([Rodolphe Dugé de Bernonville](https://github.com/RodolpheDuge)).
* Добавлена поддержка подстановочных знаков для идентификации пользователей в расширении x509 SubjectAltName. [#68236](https://github.com/ClickHouse/ClickHouse/pull/68236) ([Marco Vilas Boas](https://github.com/marco-vb)).
* Улучшено определение схемы для значений даты и времени. Теперь DateTime64 используется только тогда, когда значение даты и времени содержит дробную часть, в противном случае используется обычный DateTime. Определение Date/DateTime теперь стало строже, особенно когда `date_time_input_format='best_effort'`, чтобы избежать вывода значений даты и времени из строк в пограничных случаях. * Разрешено указывать min и max для случайных настроек в тесте после тегов в виде `setting=(min, max)`.
