<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Добавлены настройки MergeTree (`max_replicated_merges_with_ttl_in_queue` и `max_number_of_merges_with_ttl_in_pool`) для управления количеством TTL-слияний в фоновом пуле и очереди репликации. Это изменение нарушает совместимость со старыми версиями только если вы используете delete TTL. В противном случае репликация останется совместимой. Избежать проблем с несовместимостью можно, если обновить все реплики сегмента одновременно или выполнить `SYSTEM STOP TTL MERGES` до завершения обновления всех реплик. Если в очереди репликации появится несовместимая запись, прежде всего выполните `SYSTEM STOP TTL MERGES`, а затем `ALTER TABLE ... DETACH PARTITION ...` для партиции, которой было назначено несовместимое TTL-слияние. После этого снова выполните ATTACH этой партиции на одной реплике. [#14490](https://github.com/ClickHouse/ClickHouse/pull/14490) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Новая возможность
</div>

* Добавлена табличная функция `view`, которая преобразует подзапрос в табличный объект. Это упрощает передачу запросов. Например, её можно использовать в табличных функциях remote/cluster. [#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* Теперь можно написать `select * apply(length) apply(max) from wide_string_table`, чтобы определить максимальную длину всех строковых столбцов. Также доступны следующие два варианта: [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* В таблицы `system.query_log` и `system.query_thread_log` добавлено поле `query_start_time_microseconds`. [#14252](https://github.com/ClickHouse/ClickHouse/pull/14252) ([Bharat Nallan](https://github.com/bharatnc)).
* Добавлена агрегатная функция RankCorrelationSpearman, которая вычисляет коэффициент ранговой корреляции. Продолжение [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769). [#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Добавлена утилита для генерации базы данных по запросу. Продолжение [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973). [#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Оптимизированы запросы с LIMIT/LIMIT BY/ORDER BY для Distributed при GROUP BY по sharding&#95;key (с параметрами `optimize_skip_unused_shards` и `optimize_distributed_group_by_sharding_key`). [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Улучшения
</div>

* Улучшения в StorageRabbitMQ: добавлена обработка сбоев connection и channels, корректная обработка commits, обработка ошибок вставки, улучшена работа exchanges, добавлена долговечность очереди и возможность возобновления очереди, а также новые настройки очереди. Исправлены тесты. [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлена авторизация Redis через requirepass. [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* Добавлен argument precision для типа DateTime. [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* Повышена производительность Kafka engine за счёт выделения независимого thread для каждого consumer. Добавлен отдельный пул потоков для потоковых движков (таких как Kafka). [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* Добавлен compression codec по умолчанию для частей в `system.part_log` с именем `default_compression_codec`. [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* Wide integers из boost multiprecision заменены на реализацию из [https://github.com/cerevra/int](https://github.com/cerevra/int). [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* В MaterializeMySQL primary key неявно преобразуется в NOT NULL (как в MySQL). Исправляет [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114). [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* Добавлена новая настройка system&#95;events&#95;show&#95;zero&#95;values, как предложено в [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384). [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Теперь obfuscator поддерживает тип UUID, как предложено в [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163). [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Создание Set для нескольких `JOIN` и `IN` теперь выполняется параллельно. Это может немного повысить производительность запросов с несколькими различными выражениями `IN subquery`. [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Теперь TTL будут применяться во время слияния, если ранее они не были materialized. [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* Обработчик MySQL возвращает `OK` для запросов вида `SET @@var = value`. Такой оператор игнорируется. Это необходимо, потому что некоторые драйверы MySQL отправляют запрос `SET @@` для настройки после рукопожатия [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422 . [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* Ускорено завершение работы server при наличии активных S3 requests. [#14496](https://github.com/ClickHouse/ClickHouse/pull/14496) ([Pavel Kovalenko](https://github.com/Jokser)).
* Запрещён пустой argument time&#95;zone в функциях типа `toStartOf*`. [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* Используется std::filesystem::path в ConfigProcessor для объединения file path. [#14558](https://github.com/ClickHouse/ClickHouse/pull/14558) ([Bharat Nallan](https://github.com/bharatnc)).
