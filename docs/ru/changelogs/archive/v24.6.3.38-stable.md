* Бэкпортировано в [#66770](https://github.com/ClickHouse/ClickHouse/issues/66770): управление allow&#95;experimental&#95;analyzer для распределённых запросов передано инициатору. [#65777](https://github.com/ClickHouse/ClickHouse/pull/65777) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#66885](https://github.com/ClickHouse/ClickHouse/issues/66885): Исправлен неожиданный размер столбца с низкой кардинальностью при вызовах функций. [#65298](https://github.com/ClickHouse/ClickHouse/pull/65298) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#66303](https://github.com/ClickHouse/ClickHouse/issues/66303): Улучшена обработка условий JOIN с проверками `IS NULL` (например, `ON (a = b AND (a IS NOT NULL) AND (b IS NOT NULL) ) OR ( (a IS NULL) AND (b IS NULL) )` переписывается в `ON a <=> b`), исправлена некорректная оптимизация при наличии условий, отличных от `IS NULL`. [#65835](https://github.com/ClickHouse/ClickHouse/pull/65835) ([vdimir](https://github.com/vdimir)).
* Бэкпортировано в [#66330](https://github.com/ClickHouse/ClickHouse/issues/66330): В кэш определения схемы добавлены отсутствующие настройки `input_format_csv_skip_first_lines/input_format_tsv_skip_first_lines/input_format_csv_try_infer_numbers_from_strings/input_format_csv_try_infer_strings_from_quoted_tuples`, поскольку они могут изменять итоговую схему. Это предотвращает некорректные результаты определения схемы при изменении этих настроек. [#65980](https://github.com/ClickHouse/ClickHouse/pull/65980) ([Kruglov Pavel](https://github.com/Avogar)).
* Бэкпортировано в [#66157](https://github.com/ClickHouse/ClickHouse/issues/66157): Исправлена ошибка переполнения буфера в реализации `unbin`/`unhex`. [#66106](https://github.com/ClickHouse/ClickHouse/pull/66106) ([Nikita Taranov](https://github.com/nickitat)).
* Бэкпортировано в [#66210](https://github.com/ClickHouse/ClickHouse/issues/66210): Отключена оптимизация `merge-filters`, добавленная в [#64760](https://github.com/ClickHouse/ClickHouse/issues/64760). Она может вызывать исключение, если объединяет два выражения фильтрации без применения укороченного вычисления. [#66126](https://github.com/ClickHouse/ClickHouse/pull/66126) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Бэкпортировано в [#66456](https://github.com/ClickHouse/ClickHouse/issues/66456): Исправлена ошибка в клиенте ZooKeeper: после получения аппаратной ошибки от ZooKeeper сеанс мог зависнуть в непригодном для использования состоянии. Например, это могло происходить из-за &quot;soft memory limit&quot; в ClickHouse Keeper. [#66140](https://github.com/ClickHouse/ClickHouse/pull/66140) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Бэкпортировано в [#66228](https://github.com/ClickHouse/ClickHouse/issues/66228): Исправлена проблема в SumIfToCountIfVisitor при работе со знаковыми целыми числами. [#66146](https://github.com/ClickHouse/ClickHouse/pull/66146) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#66183](https://github.com/ClickHouse/ClickHouse/issues/66183): Исправлен редкий случай отсутствия данных в результате распределённого запроса, закрывает [#61432](https://github.com/ClickHouse/ClickHouse/issues/61432). [#66174](https://github.com/ClickHouse/ClickHouse/pull/66174) ([vdimir](https://github.com/vdimir)).
* Бэкпортировано в [#66271](https://github.com/ClickHouse/ClickHouse/issues/66271): Не генерировать `TIMEOUT_EXCEEDED` для режима `none_only_active` настройки `distributed_ddl_output_mode`. [#66218](https://github.com/ClickHouse/ClickHouse/pull/66218) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Бэкпортировано в [#66682](https://github.com/ClickHouse/ClickHouse/issues/66682): Исправлена обработка LIMIT для `system.numbers_mt`, когда индекс использовать нельзя. [#66231](https://github.com/ClickHouse/ClickHouse/pull/66231) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#66587](https://github.com/ClickHouse/ClickHouse/issues/66587): Исправлено определение ClickHouse server максимального числа доступных ядер CPU в соответствии с cgroups v2, если сервер работает в контейнере, например Docker. Подробности: контейнеры часто запускают свой процесс в корневой cgroup с пустым именем. В этом случае ClickHouse игнорировал ограничения CPU, заданные через cgroups v2.
