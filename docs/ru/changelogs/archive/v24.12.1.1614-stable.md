<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Функции `greatest` и `least` теперь игнорируют входные значения NULL, тогда как раньше возвращали NULL, если один из аргументов был NULL. Например, `SELECT greatest(1, 2, NULL)` теперь возвращает 2. Это делает их поведение совместимым с PostgreSQL. [#65519](https://github.com/ClickHouse/ClickHouse/pull/65519) ([kevinyhzou](https://github.com/KevinyhZou)).
* Устаревшая интеграция MongoDB на базе драйвера Poco удалена. Настройка сервера `use_legacy_mongodb_integration` устарела и больше не оказывает никакого эффекта. [#71997](https://github.com/ClickHouse/ClickHouse/pull/71997) ([Kirill Nikiforov](https://github.com/allmazz)).



<div id="new-feature">
  #### Новая возможность
</div>

* Добавлен запрос, позволяющий подключать таблицы семейства MergeTree как ReplicatedMergeTree и наоборот. [#65401](https://github.com/ClickHouse/ClickHouse/pull/65401) ([Kirill](https://github.com/kirillgarbar)).
* Реализована команда SYSTEM LOAD PRIMARY KEY для загрузки первичных индексов всех частей указанной таблицы или всех таблиц, если таблица не указана. Это полезно для бенчмарков и предотвращения дополнительных задержек при выполнении запросов. [#66252](https://github.com/ClickHouse/ClickHouse/pull/66252) ([ZAWA_ll](https://github.com/Zawa-ll)).
* Добавлен оператор `SYSTEM LOAD PRIMARY KEY` для загрузки первичных индексов всех частей указанной таблицы или всех таблиц, если таблица не указана. Может быть полезно для бенчмаркинга и предотвращения дополнительных задержек при выполнении запросов. [#67733](https://github.com/ClickHouse/ClickHouse/pull/67733) ([ZAWA_ll](https://github.com/Zawa-ll)).
* [Формат хранения данных Iceberg](https://iceberg.apache.org/spec/#file-system-operations) предоставляет широкие возможности для изменения схемы таблицы. В данном pull request реализовано чтение таблиц в формате Iceberg с изменённым порядком столбцов, именами столбцов и простыми расширениями типов. [#69445](https://github.com/ClickHouse/ClickHouse/pull/69445) ([Daniil Ivanik](https://github.com/divanik)).
* Добавлена функция `toUnixTimestamp64Second`, преобразующая `DateTime64` в значение `Int64` с фиксированной точностью до секунды; поддерживается возврат отрицательных значений для дат, предшествующих 00:00:00 UTC в четверг, 1 января 1970 года. [#70597](https://github.com/ClickHouse/ClickHouse/pull/70597) ([zhanglistar](https://github.com/zhanglistar)).
* Добавлена новая настройка `enforce_index_structure_match_on_partition_manipulation`, позволяющая выполнять операцию attach, когда проекции и вторичные индексы исходной таблицы являются подмножеством соответствующих объектов целевой таблицы. Закрывает [#70602](https://github.com/ClickHouse/ClickHouse/issues/70602). [#70603](https://github.com/ClickHouse/ClickHouse/pull/70603) ([zwy991114](https://github.com/zwy991114)).
* Вывод функции `cast` отличается от Apache Spark, что приводит к расхождениям в проекте gluten, см. https://github.com/apache/incubator-gluten/issues/7602. В данном PR добавлена поддержка текстового формата вывода Spark как возможность, отключённая по умолчанию. [#70957](https://github.com/ClickHouse/ClickHouse/pull/70957) ([zhanglistar](https://github.com/zhanglistar)).
* В данном PR введена новая настройка `allow_experimental_reverse_key`, включающая поддержку убывающего порядка сортировки в ключах сортировки MergeTree. Это полезно для анализа временных рядов, особенно для запросов TopN. Пример использования: ```sql CREATE TABLE example ( time DateTime, key Int32, value String ) ENGINE = MergeTree ORDER BY (time DESC, key); -- Убывающий порядок для поля 'time' SETTINGS allow_experimental_reverse_key = 1;. [#71095](https://github.com/ClickHouse/ClickHouse/pull/71095) ([Amos Bird](https://github.com/amosbird)).
* Реализована интеграция с Iceberg REST-каталогом. [#71542](https://github.com/ClickHouse/ClickHouse/pull/71542) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Добавлена возможность выбора стороны JOIN, которая будет выступать внутренней (build) таблицей в плане запроса. Управляется параметром `query_plan_join_swap_table`, который можно установить в значение `auto`. В этом режиме ClickHouse попытается выбрать таблицу с наименьшим количеством строк. [#71577](https://github.com/ClickHouse/ClickHouse/pull/71577) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Добавлен синтаксис ALTER USER {ADD|MODIFY|DROP SETTING}, ALTER USER {ADD|DROP PROFILE}, а также аналогичный синтаксис для ALTER ROLE и ALTER PROFILE. [#72050](https://github.com/ClickHouse/ClickHouse/pull/72050) ([pufit](https://github.com/pufit)).
* Добавлена функция `arrayPrAUC`, вычисляющая AUC (площадь под кривой) для кривой Precision-Recall. [#72073](https://github.com/ClickHouse/ClickHouse/pull/72073) ([Emmanuel](https://github.com/emmanuelsdias)).
* Добавлен кэш первичного индекса для таблиц `MergeTree` (включается настройкой таблицы `use_primary_key_cache`). Если для первичного индекса включены отложенная загрузка и кэширование, он будет загружаться в кэш по требованию (аналогично кэшу меток), а не храниться в памяти постоянно. Добавлен предварительный прогрев первичного индекса при вставках, слияниях и получении частей данных, а также при перезапуске таблицы (включается настройкой `prewarm_primary_key_cache`). [#72102](https://github.com/ClickHouse/ClickHouse/pull/72102) ([Anton Popov](https://github.com/CurtizJ)).
* Бэкпортировано в [#73593](https://github.com/ClickHouse/ClickHouse/issues/73593): операторы `SELECT` и `VIEW` теперь поддерживают псевдонимы, например `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);`. Это позволяет выполнять запрос TPC-H 15 без изменений. [#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлена функция `indexOfAssumeSorted` для массивов. Оптимизирует поиск в массиве, отсортированном в неубывающем порядке. [#72517](https://github.com/ClickHouse/ClickHouse/pull/72517) ([Eric Kurbanov](https://github.com/erickurbanov)).
* Добавлена возможность использовать разделитель в качестве необязательного второго аргумента агрегатной функции `groupConcat`. [#72540](https://github.com/ClickHouse/ClickHouse/pull/72540) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлена новая настройка `http_response_headers`, позволяющая настраивать заголовки HTTP-ответа. Например, можно указать браузеру отображать изображение, хранящееся в базе данных. Закрывает [#59620](https://github.com/ClickHouse/ClickHouse/issues/59620). [#72656](https://github.com/ClickHouse/ClickHouse/pull/72656) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена функция `fromUnixTimestamp64Second`, преобразующая значение Unix-временной метки типа Int64 в DateTime64. [#73146](https://github.com/ClickHouse/ClickHouse/pull/73146) ([Robert Schulze](https://github.com/rschu1ze)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Снижено использование памяти при выполнении `clickhouse disks remove --recursive` для дисков объектного хранилища. [#67323](https://github.com/ClickHouse/ClickHouse/pull/67323) ([Kirill](https://github.com/kirillgarbar)).
* Включена JIT-компиляция для дополнительных выражений: abs/bitCount/sign/modulo/pmod/isNull/isNotNull/assumeNotNull/to(U)Int*/toFloat*, функции сравнения (=, <, >, >=, <=), логические функции (and, or). [#70598](https://github.com/ClickHouse/ClickHouse/pull/70598) ([李扬](https://github.com/taiyang-li)).
* Теперь алгоритм `parallel_hash` будет использоваться (при наличии возможности), когда настройка `join_algorithm` установлена в значение `default`. Два прежних варианта (`direct` и `hash`) по-прежнему рассматриваются, если `parallel_hash` не может быть применён. [#70788](https://github.com/ClickHouse/ClickHouse/pull/70788) ([Nikita Taranov](https://github.com/nickitat)).
* Добавлена возможность извлечения общих выражений из условий `WHERE` и `ON` с целью сокращения числа хеш-таблиц, используемых при JOIN. Включается параметром `optimize_extract_common_expressions = 1`. [#71537](https://github.com/ClickHouse/ClickHouse/pull/71537) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Добавлена возможность использования индексов в запросах `SELECT` с типом `LowCardinality(String)`. [#71598](https://github.com/ClickHouse/ClickHouse/pull/71598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* При выполнении запроса с параллельными репликами и включённым локальным планом анализ индексов на воркерах пропускается. Координатор самостоятельно определяет диапазоны чтения для воркеров на основе анализа индексов на своей стороне (на инициаторе запроса). [#72109](https://github.com/ClickHouse/ClickHouse/pull/72109) ([Igor Nikonov](https://github.com/devcrafter)).
* Возвращена оптимизация чтения подстолбцов одного столбца в компактных частях из https://github.com/ClickHouse/ClickHouse/pull/57631. Ранее она была удалена случайно. [#72285](https://github.com/ClickHouse/ClickHouse/pull/72285) ([Pavel Kruglov](https://github.com/Avogar)).
* Ускорена сортировка столбцов `LowCardinality(String)` за счёт девиртуализации вызовов в компараторе. [#72337](https://github.com/ClickHouse/ClickHouse/pull/72337) ([Alexander Gololobov](https://github.com/davenger)).
* Оптимизированы функции argMin/Max для ряда простых типов данных. [#72350](https://github.com/ClickHouse/ClickHouse/pull/72350) ([alesapin](https://github.com/alesapin)).
* Оптимизирована работа с разделяемыми блокировками в трекере памяти для снижения конкуренции за блокировки. [#72375](https://github.com/ClickHouse/ClickHouse/pull/72375) ([Jiebin Sun](https://github.com/jiebinn)).
* Добавлена новая настройка `use_async_executor_for_materialized_views`. Обеспечивает асинхронное и потенциально многопоточное выполнение запросов materialized view, что может ускорить обработку представлений при INSERT, однако увеличивает использование памяти. [#72497](https://github.com/ClickHouse/ClickHouse/pull/72497) ([alesapin](https://github.com/alesapin)).
* Значения по умолчанию для настроек `max_size_to_preallocate_for_aggregation` и `max_size_to_preallocate_for_joins` дополнительно увеличены до `10^12`, что позволяет применять оптимизацию в большем числе случаев. [#72555](https://github.com/ClickHouse/ClickHouse/pull/72555) ([Nikita Taranov](https://github.com/nickitat)).
* Улучшена производительность десериализации состояний агрегатных функций (в типе данных `AggregateFunction` и в распределённых запросах). Незначительно улучшена производительность разбора формата `RowBinary`. [#72818](https://github.com/ClickHouse/ClickHouse/pull/72818) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### Улучшения
</div>

* Добавлена новая логика отмены: `CancellationChecker` проверяет тайм-ауты для каждого запущенного запроса и останавливает его, как только достигается тайм-аут. [#69880](https://github.com/ClickHouse/ClickHouse/pull/69880) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Удалена настройка `allow_experimental_join_condition`, поэтому неэкви-условия в JOIN теперь разрешены по умолчанию. [#69910](https://github.com/ClickHouse/ClickHouse/pull/69910) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Настройки из конфигурации сервера (users.xml) теперь применяются и на клиенте. Это полезно для настроек формата, например `date_time_output_format`. [#71178](https://github.com/ClickHouse/ClickHouse/pull/71178) ([Michael Kolupaev](https://github.com/al13n321)).
* Исправление [#71227](https://github.com/ClickHouse/ClickHouse/issues/71227). [#71286](https://github.com/ClickHouse/ClickHouse/pull/71286) ([Arthur Passos](https://github.com/arthurpassos)).
* Автоматический сброс `GROUP BY`/`ORDER BY` на диск в зависимости от использования памяти сервером/пользователем. Управляется настройками запроса `max_bytes_ratio_before_external_group_by`/`max_bytes_ratio_before_external_sort`. [#71406](https://github.com/ClickHouse/ClickHouse/pull/71406) ([Azat Khuzhin](https://github.com/azat)).
* Функция `translate` теперь поддерживает удаление символов, если аргумент `from` содержит больше символов, чем аргумент `to`. Пример: `SELECT translate('clickhouse', 'clickhouse', 'CLICK')` теперь возвращает `CLICK`. [#71441](https://github.com/ClickHouse/ClickHouse/pull/71441) ([shuai.xu](https://github.com/shuai-xu)).
* Добавлена поддержка ALTER из Object в JSON. [#71784](https://github.com/ClickHouse/ClickHouse/pull/71784) ([Pavel Kruglov](https://github.com/Avogar)).
* Разбиты ranges в `MergeTreeReadPoolParallelReplicasInOrder`, чтобы снизить потребление памяти при чтении. [#72173](https://github.com/ClickHouse/ClickHouse/pull/72173) ([JIaQi](https://github.com/JiaQiTang98)).
* Учитывается `prefer_locahost_replica` при построении плана для распределённого `INSERT ... SELECT`. [#72190](https://github.com/ClickHouse/ClickHouse/pull/72190) ([filimonov](https://github.com/filimonov)).
* Проблема [описана здесь](https://github.com/ClickHouse/ClickHouse/issues/72091). Azure Iceberg Writer создаёт файлы метаданных Iceberg (а также manifest files), которые нарушают спецификацию. В этом PR я добавил попытку читать метаданные формата Iceberg v1 с помощью reader v2 (поскольку они записывают их именно так), а также добавил ошибку на случай, если не были созданы соответствующие поля в manifest file. [#72277](https://github.com/ClickHouse/ClickHouse/pull/72277) ([Daniil Ivanik](https://github.com/divanik)).
* Типы JSON/Dynamic/Variant переведены из экспериментальных возможностей в бета-статус. [#72294](https://github.com/ClickHouse/ClickHouse/pull/72294) ([Pavel Kruglov](https://github.com/Avogar)).
* Теперь разрешено использовать `CREATE MATERIALIZED VIEW` с `UNION [ALL]` в запросе. Поведение такое же, как и для materialized view с `JOIN`: **только первая table в выражении `SELECT` будет работать как trigger для вставки**, все остальные table будут проигнорированы. [#72347](https://github.com/ClickHouse/ClickHouse/pull/72347) ([alesapin](https://github.com/alesapin)).
* Ускорены вставки в MergeTree в случае единственного значения ключа партиционирования внутри вставляемого батча. [#72348](https://github.com/ClickHouse/ClickHouse/pull/72348) ([alesapin](https://github.com/alesapin)).
* Все небольшие утилиты, которые ранее хранились в папке `/utils` и требовали ручной компиляции из исходников, теперь входят в основной bundle ClickHouse. Это закрывает: [#72404](https://github.com/ClickHouse/ClickHouse/issues/72404). [#72426](https://github.com/ClickHouse/ClickHouse/pull/72426) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Реализовано параллельное создание таблиц при восстановлении из резервной копии. До этого PR команда `RESTORE` всегда создавала таблицы в одном потоке, что могло замедлять восстановление резервных копий с большим количеством таблиц. [#72427](https://github.com/ClickHouse/ClickHouse/pull/72427) ([Vitaly Baranov](https://github.com/vitlibar)).
* Добавлена новая метрика MergeTreeIndexGranularityInternalArraysTotalSize в system.metrics. Эта метрика нужна, чтобы находить instance с огромными датасетами, подверженные проблеме высокого использования памяти. [#72490](https://github.com/ClickHouse/ClickHouse/pull/72490) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Добавлена проверка исходного запроса, когда ClickHouse используется как source для словаря. [#72548](https://github.com/ClickHouse/ClickHouse/pull/72548) ([Alexey Katsman](https://github.com/alexkats)).
* Обеспечено, что ClickHouse видит изменения ZooKeeper при перезагрузке config. [#72593](https://github.com/ClickHouse/ClickHouse/pull/72593) ([Azat Khuzhin](https://github.com/azat)).
* Улучшена оценка использования памяти кэшированными marks, чтобы сократить общее использование памяти кэшем. [#72630](https://github.com/ClickHouse/ClickHouse/pull/72630) ([Antonio Andelic](https://github.com/antonio2368)).
* Добавлена новая метрика `StartupScriptsExecutionState`. Метрика может принимать три значения: 0 = стартовые скрипты еще не завершили выполнение, 1 = стартовые скрипты выполнены успешно, 2 = выполнение стартовых скриптов завершилось ошибкой. Эта метрика нужна, чтобы понимать, успешно ли выполняются стартовые скрипты в Cloud, особенно после изменений в базовых конфигурациях. [#72637](https://github.com/ClickHouse/ClickHouse/pull/72637) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Бэкпортировано в [#73472](https://github.com/ClickHouse/ClickHouse/issues/73472): поддержка подстолбцов в ключе сортировки MergeTree и индексах пропуска данных. [#72644](https://github.com/ClickHouse/ClickHouse/pull/72644) ([Pavel Kruglov](https://github.com/Avogar)).

Ранее другие формы (например, `NULL`) не приводили к выбросу исключений, но при этом формат `Null` в таких случаях фактически не использовался.
