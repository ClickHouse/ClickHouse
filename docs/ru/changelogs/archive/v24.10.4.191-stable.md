<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Бэкпортировано в [#72865](https://github.com/ClickHouse/ClickHouse/issues/72865): для движков таблиц Kafka, NATS и RabbitMQ теперь используются собственные привилегии в иерархии `SOURCES`. Добавьте привилегии всем пользователям базы данных, кроме `default`, которые создают таблицы с этими типами движков. [#71250](https://github.com/ClickHouse/ClickHouse/pull/71250) ([Christoph Wurm](https://github.com/cwurm)).

<div id="new-feature">
  #### Новая возможность
</div>

* Бэкпортировано в [#74317](https://github.com/ClickHouse/ClickHouse/issues/74317): когда `min_age_to_force_merge_seconds` и `min_age_to_force_merge_on_partition_only` оба включены, слияние частей игнорирует ограничение на максимальный размер в байтах. [#73656](https://github.com/ClickHouse/ClickHouse/pull/73656) ([Kai Zhu](https://github.com/nauu)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Бэкпортировано в [#72595](https://github.com/ClickHouse/ClickHouse/issues/72595): во время выполнения запроса с параллельными репликами и включенным локальным планом анализ индекса пропуска данных на воркерах теперь пропускается. Координатор выбирает диапазоны чтения для воркеров на основе анализа индекса на своей стороне (на инициаторе запроса). [#72109](https://github.com/ClickHouse/ClickHouse/pull/72109) ([Igor Nikonov](https://github.com/devcrafter)).
* Бэкпортировано в [#73033](https://github.com/ClickHouse/ClickHouse/issues/73033): возвращена оптимизация чтения подстолбцов одного столбца в компактных частях из [https://github.com/ClickHouse/ClickHouse/pull/57631](https://github.com/ClickHouse/ClickHouse/pull/57631). Она была случайно удалена. [#72285](https://github.com/ClickHouse/ClickHouse/pull/72285) ([Pavel Kruglov](https://github.com/Avogar)).

<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#73565](https://github.com/ClickHouse/ClickHouse/issues/73565): Исправлена проблема, из-за которой ClickHouse в Docker-контейнерах выводил в stderr сообщение &quot;get&#95;mempolicy: Operation not permitted&quot; из-за ограничений на syscalls. [#70900](https://github.com/ClickHouse/ClickHouse/pull/70900) ([filimonov](https://github.com/filimonov)).
* Бэкпортировано в [#73242](https://github.com/ClickHouse/ClickHouse/issues/73242): Методы `removeObject` и `removeObjects` не являются идемпотентными. При повторных попытках из-за сетевых ошибок результатом могло быть `object not found`, потому что объект уже был удалён во время предыдущих попыток. [#71529](https://github.com/ClickHouse/ClickHouse/pull/71529) ([Sema Checherinda](https://github.com/CheSema)).
* Бэкпортировано в [#72758](https://github.com/ClickHouse/ClickHouse/issues/72758): Проблема [описана здесь](https://github.com/ClickHouse/ClickHouse/issues/72091). Azure Iceberg Writer создаёт файлы метаданных Iceberg (а также manifest files), которые нарушают спецификацию. В этот PR добавлена попытка читать метаданные Iceberg формата v1 с помощью reader v2 (поскольку они записываются именно так), а также добавлена ошибка на случай, если в manifest file не создаются соответствующие поля. [#72277](https://github.com/ClickHouse/ClickHouse/pull/72277) ([Daniil Ivanik](https://github.com/divanik)).
* Бэкпортировано в [#72675](https://github.com/ClickHouse/ClickHouse/issues/72675): Улучшена оценка использования памяти для кэшированных marks, чтобы снизить общее использование памяти кэшем. [#72630](https://github.com/ClickHouse/ClickHouse/pull/72630) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#73063](https://github.com/ClickHouse/ClickHouse/issues/73063): Добавлена поддержка разбора ошибки GCS S3 `AuthenticationRequired`. [#72753](https://github.com/ClickHouse/ClickHouse/pull/72753) ([Vitaly Baranov](https://github.com/vitlibar)).
* Бэкпортировано в [#73055](https://github.com/ClickHouse/ClickHouse/issues/73055): Добавлены настройки S3-запросов `http_max_fields`, `http_max_field_name_size`, `http_max_field_value_size`, которые используются при разборе ответов API S3 во время создания резервной копии или восстановления. [#72778](https://github.com/ClickHouse/ClickHouse/pull/72778) ([Vitaly Baranov](https://github.com/vitlibar)).
* Бэкпортировано в [#73453](https://github.com/ClickHouse/ClickHouse/issues/73453): Используются multi requests Keeper в потоке очистки ObjectStorageQueueMetadata. [#73357](https://github.com/ClickHouse/ClickHouse/pull/73357) ([Antonio Andelic](https://github.com/antonio2368)).
