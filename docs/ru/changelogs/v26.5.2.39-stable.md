<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* Бэкпортировано в [#106038](https://github.com/ClickHouse/ClickHouse/issues/106038): настройка `show_data_lake_catalogs_in_system_tables` была переименована в `show_remote_databases_in_system_tables`, а её действие было расширено: если её значение равно 0 (по умолчанию), то в `system.tables`, `system.columns` и `system.completions` также не отображаются базы данных `MySQL` и `PostgreSQL`, помимо каталогов озёр данных. Старое имя настройки сохранено как псевдоним. [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#105770](https://github.com/ClickHouse/ClickHouse/issues/105770): Различные изменения в Keeper, которые в целом ускоряют его примерно в 2 раза (улучшенное батчирование, конвейерная отправка сообщений лидеру, конвейерное добавление записей в журнал). [#101757](https://github.com/ClickHouse/ClickHouse/pull/101757) ([Michael Kolupaev](https://github.com/al13n321)).
* Бэкпортировано в [#106585](https://github.com/ClickHouse/ClickHouse/issues/106585): Исправлен случай, когда `PREWHERE` с подзапросом `IN` по столбцам первичного ключа не использовал индекс первичного ключа для отсеивания гранул, что приводило к полному сканированию таблицы вместо чтения только нужных гранул. [#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Бэкпортировано в [#106233](https://github.com/ClickHouse/ClickHouse/issues/106233): Снижено пиковое потребление памяти при применении полученных снимков в ClickHouse Keeper с `KeeperMemoryStorage`. [#105851](https://github.com/ClickHouse/ClickHouse/pull/105851) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#106123](https://github.com/ClickHouse/ClickHouse/issues/106123): Добавлены `coordination_settings` Keeper для ограничения допуска неподтверждённых записей журнала в `NuRaft` и ограничения скорости обратных проверок append-entries. [#106108](https://github.com/ClickHouse/ClickHouse/pull/106108) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#105806](https://github.com/ClickHouse/ClickHouse/issues/105806): Исправлено повреждение данных при записи Parquet (и других форматов с трейлером, таких как ORC и Arrow) в HDFS через `INSERT INTO FUNCTION hdfs(...)`. Начиная с 26.1, `WriteBufferFromHDFS` не сбрасывал рабочий буфер в `finalize()`, из-за чего последние вплоть до `DBMS_DEFAULT_BUFFER_SIZE` байтов каждого файла незаметно терялись, включая нижний колонтитул Parquet `PAR1`. Чтение таких файлов приводило к ошибке `Not a Parquet file (wrong magic bytes at the end of file)`. [#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105755](https://github.com/ClickHouse/ClickHouse/issues/105755): `LEFT ANTI JOIN` теперь корректно возвращает столбец ключа JOIN с правой стороны со значениями по умолчанию для несовпавших строк, а не дублирует значение левого ключа. Ранее `SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` мог возвращать `r = a.x` для несовпавших строк, хотя должен был возвращать значение по умолчанию (`0` для `Int32`, `''` для `String`, `NULL` для `Nullable`). Затронут был только столбец ключа JOIN; неключевые правые столбцы уже корректно получали значения по умолчанию. Та же ошибка возникала и в `RIGHT ANTI JOIN`, когда оптимизатор менял стороны местами. Закрывает [#99959](https://github.com/ClickHouse/ClickHouse/issues/99959). [#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105670](https://github.com/ClickHouse/ClickHouse/issues/105670): Длительные `INSERT ... SELECT` и другие операции чтения из базы данных `DataLakeCatalog` с `catalog_type = 'glue'` завершаются ошибкой `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)`, когда истекает срок действия учетных данных сеанса STS, полученных при загрузке метаданных таблицы. [#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Бэкпортировано в [#105768](https://github.com/ClickHouse/ClickHouse/issues/105768): Исправлена логическая ошибка в отрицательном `LIMIT BY` в некоторых случаях при использовании с `ARRAY JOIN`. [#105403](https://github.com/ClickHouse/ClickHouse/pull/105403) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Бэкпортировано в [#105622](https://github.com/ClickHouse/ClickHouse/issues/105622): Исправлены heap-buffer-overflow при чтении файлов Arrow или ArrowStream с поврежденными промежуточными offsets в столбце бинарных данных или строковом столбце, а также разыменование нулевого указателя при чтении георазмеченных столбцов Arrow. [#105449](https://github.com/ClickHouse/ClickHouse/pull/105449) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#105884](https://github.com/ClickHouse/ClickHouse/issues/105884): Исправлено, что `dictGetOrDefault` генерировал `CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN`, когда аргумент по умолчанию является выражением `Nullable` и включен `short_circuit_function_evaluation` при сочетании найденных и ненайденных ключей словаря. [#105461](https://github.com/ClickHouse/ClickHouse/pull/105461) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#106489](https://github.com/ClickHouse/ClickHouse/issues/106489): Исправлен SIGSEGV при чтении подстолбцов Dynamic из сжатой таблицы Memory после ALTER. Закрывает [#104901](https://github.com/ClickHouse/ClickHouse/issues/104901). [#105464](https://github.com/ClickHouse/ClickHouse/pull/105464) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#105876](https://github.com/ClickHouse/ClickHouse/issues/105876): Исправлен segfault сервера в `uniqStateOrNull` / `uniqStateOrDefault` / `uniqOrNullState` (и аналогичных цепочках комбинаторов над `uniq`) при использовании с `GROUP BY ... WITH ROLLUP`, `WITH CUBE` или `WITH TOTALS` и аргументом Nullable. [#105470](https://github.com/ClickHouse/ClickHouse/pull/105470) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105973](https://github.com/ClickHouse/ClickHouse/issues/105973): Исправлен SEGFAULT при десериализации `singleValueOrNull` для типа JSON. Закрывает [#103630](https://github.com/ClickHouse/ClickHouse/issues/103630). [#105535](https://github.com/ClickHouse/ClickHouse/pull/105535) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#105724](https://github.com/ClickHouse/ClickHouse/issues/105724): Исправлен crash в replxx из-за достижения ограничения FD&#95;SETSIZE в select() (заменено на poll()). Обратите внимание: при включённом SSH/веб-терминале это может приводить к crash сервера. [#105559](https://github.com/ClickHouse/ClickHouse/pull/105559) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#106559](https://github.com/ClickHouse/ClickHouse/issues/106559): Исправлен crash клиента при `CREATE TABLE ... TO INNER UUID '...' ...`, когда в операторе отсутствует предложение `ENGINE`. Теперь парсер сообщает корректную ошибку `BAD_ARGUMENTS` вместо разыменования нулевого указателя. [#105579](https://github.com/ClickHouse/ClickHouse/pull/105579) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105731](https://github.com/ClickHouse/ClickHouse/issues/105731): Извлечение значений Hive-партиций теперь учитывает настройку `cast_string_to_date_time_mode` и по умолчанию принимает временные метки ISO 8601 с суффиксами часового пояса (например, `+0000`, `+00:00`, `Z`) в ключах партиционирования. [#105584](https://github.com/ClickHouse/ClickHouse/pull/105584) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#105814](https://github.com/ClickHouse/ClickHouse/issues/105814): Исправлен незаметный недосчёт в запросах `SELECT`, когда `use_query_condition_cache = 1` (по умолчанию). Запрос вида `PREWHERE pk_prefix = X WHERE non_pk IN (...)` к столбцу с bloom-filter индексом пропуска данных загрязнял `QueryConditionCache` для предиката `pk_prefix = X`, из-за чего последующий безобидный `SELECT count() ... WHERE pk_prefix = X` возвращал некорректный заниженный результат. Затронуты все релизы 26.x. [#104781](https://github.com/ClickHouse/ClickHouse/issues/104781). [#105686](https://github.com/ClickHouse/ClickHouse/pull/105686) ([Groene AI](https://github.com/groeneai)).
* Бэкпортировано в [#105838](https://github.com/ClickHouse/ClickHouse/issues/105838): Исправлен crash в табличной функции `mongodb`, хранилище MongoDB и источнике словаря MongoDB, возникавший, когда имя коллекции пустое или содержит байты NUL. [#105776](https://github.com/ClickHouse/ClickHouse/pull/105776) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#105794](https://github.com/ClickHouse/ClickHouse/issues/105794): Исправлена очистка снимков `Keeper` после неудачных записей, чтобы частичные снимки безопасно удалялись, а неудачные записи можно было повторить без продвижения `latest_snapshot_meta`. [#105779](https://github.com/ClickHouse/ClickHouse/pull/105779) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#106065](https://github.com/ClickHouse/ClickHouse/issues/106065): Исправлена ошибка `Cannot find column` для распределённых запросов с фильтром `IN Array(...)` в новом анализаторе. [#105894](https://github.com/ClickHouse/ClickHouse/pull/105894) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Бэкпортировано в [#106551](https://github.com/ClickHouse/ClickHouse/issues/106551): Исправлен сбой сервера, который мог возникать при отмене запроса, читающего данные из PostgreSQL — через table function `postgresql`, движок таблицы PostgreSQL или словарь с источником PostgreSQL — если не удавалось отменить удаленный запрос PostgreSQL (например, с помощью `KILL QUERY`). [#105949](https://github.com/ClickHouse/ClickHouse/pull/105949) ([Rory Shanks](https://github.com/rorylshanks)).
* Бэкпортировано в [#106500](https://github.com/ClickHouse/ClickHouse/issues/106500): Исправлен возможный сбой из-за слишком большого строкового литерала, переданного в запросе. [#105996](https://github.com/ClickHouse/ClickHouse/pull/105996) ([Nikita Taranov](https://github.com/nickitat)).
* Бэкпортировано в [#106075](https://github.com/ClickHouse/ClickHouse/issues/106075): Исправлены сбои `Keeper` во время дозагрузки follower, когда новая очередь ответов диспетчера запросов могла заполниться до запуска потока обработки ответов.
