<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* ALTER MODIFY COLUMN теперь требует явного DEFAULT при преобразовании столбцов с типом Nullable в типы без Nullable. Ранее такие ALTER могли зависать с ошибкой cannot convert null to not null; теперь значения NULL заменяются выражением DEFAULT для столбца. Исправляет [#5985](https://github.com/ClickHouse/ClickHouse/issues/5985). [#84770](https://github.com/ClickHouse/ClickHouse/pull/84770) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Токенизатор Ngram больше не будет возвращать n-граммы короче заданной длины N. Text Search не будет возвращать строки, если поисковые токены пусты. [#89757](https://github.com/ClickHouse/ClickHouse/pull/89757) ([George Larionov](https://github.com/george-larionov)).
* При изменении типа столбца с `String` на `Nullable(String)` мутация данных выполняться не будет. Однако для aggregate function `uniq` используется другая структура данных: для столбца с типом Nullable применяется `AggregateFunctionNull` с вложенным агрегатором uniq. `AggregateFunctionNull` сериализует дополнительный булев флаг. Из-за этого файл статистики становится несовместимым. Исправление добавляет флаг, который при сериализации фиксирует, является ли столбец Nullable. Формат статистики изменился, и сервер завершится с ошибкой, если присутствует статистика в старом формате. Этот PR [https://github.com/ClickHouse/ClickHouse/pull/90904](https://github.com/ClickHouse/ClickHouse/pull/90904) исправляет сбой и выбрасывает исключение, если существующая статистика использует устаревший формат. Чтобы избежать исключения, следует выполнить ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL, чтобы заново сгенерировать статистику и тем самым устранить проблему. [#90311](https://github.com/ClickHouse/ClickHouse/pull/90311) ([Han Fei](https://github.com/hanfei1991)).
* Удалены настройки `allow_not_comparable_types_in_order_by`/`allow_not_comparable_types_in_comparison_functions`. Разрешение несравнимых типов в ORDER BY или функциях сравнения может приводить к логическим ошибкам и неожиданным результатам. Исправляет [#90028](https://github.com/ClickHouse/ClickHouse/issues/90028). [#90527](https://github.com/ClickHouse/ClickHouse/pull/90527) ([Pavel Kruglov](https://github.com/Avogar)).
* Значение по умолчанию для настройки `check_query_single_value_result` изменено с `true` на `false`. Из-за этого `CHECK TABLE` теперь возвращает подробные результаты по каждой части вместо агрегированного результата (1 = всё в порядке, 0 = найдены ошибки). По сравнению с предыдущим поведением это, вероятно, лучше соответствует ожиданиям пользователя. [#91009](https://github.com/ClickHouse/ClickHouse/pull/91009) ([Robert Schulze](https://github.com/rschu1ze)).
* Несколько исправлений, связанных с неявными индексами. Отображаемая или сохраняемая схема (метаданные keeper) не будет включать неявные индексы, например созданные настройками `add_minmax_index_for_numeric_columns` или `add_minmax_index_for_string_columns`. Это может вызывать ошибки метаданных, когда таблица семейства ReplicatedMergeTree создаётся или обновляется в более новой версии, а в кластере при этом есть реплика на более старом релизе. В таких случаях отправляйте DDL на старую реплику, пока кластер не будет полностью обновлён. [#91429](https://github.com/ClickHouse/ClickHouse/pull/91429) ([Raúl Marín](https://github.com/Algunenano)).
* Обновлён клиент ClickHouse: теперь он возвращает ненулевой код выхода (159 - TIMEOUT&#95;EXCEEDED), когда запрос завершается по тайм-ауту из-за `receive_timeout`. Ранее тайм-ауты возвращали код выхода 0 (успех), из-за чего скриптам и средствам автоматизации было сложно обнаруживать такие сбои. [#91432](https://github.com/ClickHouse/ClickHouse/pull/91432) ([Sav](https://github.com/sberss)).
* Улучшена организация хранения inverted text index, чтобы повысить эффективность чтения из Объектного хранилища. Повышена производительность слияний в таблицах с inverted text index. Если вы использовали экспериментальный text index до версии 25.12, перед upgrade необходимо удалить индекс и заново построить его в новой версии. [#91518](https://github.com/ClickHouse/ClickHouse/pull/91518) ([Anton Popov](https://github.com/CurtizJ)).
* Теперь запрещено создавать специальные таблицы `MergeTree` (такие как `ReplacingMergeTree`, `CollapsingMergeTree` и т. д.) с пустым ключом `ORDER BY`, поскольку поведение слияний в таких таблицах не определено. Если вам всё же нужно создать такую таблицу, включите настройку `allow_suspicious_primary_key`. [#91569](https://github.com/ClickHouse/ClickHouse/pull/91569) ([Anton Popov](https://github.com/CurtizJ)).
* Исправлены функции bitShiftLeft и bitShiftRight: теперь при сдвиге ровно на размер типа они возвращают 0 или пустое значение. [#91943](https://github.com/ClickHouse/ClickHouse/pull/91943) ([Pablo Marcos](https://github.com/pamarcos)).
* Дополнение к [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380). Этот PR относит отключение позиционных аргументов в проекциях к обратно несовместимым изменениям. Кроме того, он добавляет настройку `enable_positional_arguments_for_projections`, чтобы обеспечить безопасное обновление кластера ClickHouse при наличии позиционных аргументов в проекциях. [#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="new-feature">
  #### Новая возможность
</div>

* Теперь пользователи могут настраивать таблицы S3/Azure Queue так, чтобы они перемещали или помечали обработанные файлы, в дополнение к уже существующим вариантам — сохранять или удалять файлы. Исправлено в [#72944](https://github.com/ClickHouse/ClickHouse/issues/72944). [#86907](https://github.com/ClickHouse/ClickHouse/pull/86907) ([Murat Khairulin](https://github.com/mxwell)).
* В агрегатную функцию `windowFunnel` добавлена опция `allow_reentry`. При включении вместе со strict&#95;order она игнорирует события, нарушающие порядок, вместо того чтобы останавливать анализ воронки. Это позволяет корректно обрабатывать пользовательские сценарии с обновлением страницы (A-&gt;A-&gt;B) или возвратом назад (A-&gt;B-&gt;A-&gt;C) без занижения коэффициентов конверсии. [#86916](https://github.com/ClickHouse/ClickHouse/pull/86916) ([Lee ChaeRok](https://github.com/LeeChaeRok)).
* Клиент CLI теперь может скрывать сообщение &#39;ClickHouse server version is older than ClickHouse client. It may indicate that the server is out of date and can be upgraded.&#39; при указании `--no-server-client-version-message` или `false`. [#87784](https://github.com/ClickHouse/ClickHouse/pull/87784) ([Larry Snizek](https://github.com/larry-cdn77)).
* Совместимость Keeper с ZooKeeper: create with statistics. [#88797](https://github.com/ClickHouse/ClickHouse/pull/88797) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Поддержка постоянных наблюдений ZooKeeper в ClickHouse Keeper. Продолжение, часть 2: [https://github.com/ClickHouse/ClickHouse/pull/78207](https://github.com/ClickHouse/ClickHouse/pull/78207). [#88813](https://github.com/ClickHouse/ClickHouse/pull/88813) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Функции для вычисления площади и периметра для типа Geometry. [#89047](https://github.com/ClickHouse/ClickHouse/pull/89047) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Добавлена возможность runtime-инструментирования с использованием XRay для отладки проблем в продакшн и детерминированного профилирования. Исправлено в [#74249](https://github.com/ClickHouse/ClickHouse/issues/74249). [#89173](https://github.com/ClickHouse/ClickHouse/pull/89173) ([Pablo Marcos](https://github.com/pamarcos)).
* Реализована функция `dictGetKeys`, которая возвращает ключ(и) словаря, атрибут которых равен указанному значению. Она использует обратный кэш поиска на уровне запроса, настраиваемый параметром `max_reverse_dictionary_lookup_cache_size_bytes`, чтобы ускорить повторные обращения. [#89197](https://github.com/ClickHouse/ClickHouse/pull/89197) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Доступ к экземплярам ClickHouse Cloud с использованием учетных данных Cloud через `--login`. [#89261](https://github.com/ClickHouse/ClickHouse/pull/89261) ([Krishna Mannem](https://github.com/kcmannem)).
* Добавлена настройка `type_json_skip_invalid_typed_paths`, отключающая исключения для вставок/приведения типов к JSON type, когда входной JSON не может быть приведен к явно типизированным paths в JSON type. В этом случае используется значение null/zero для типизированного path. [#89886](https://github.com/ClickHouse/ClickHouse/pull/89886) ([Max Justus Spransy](https://github.com/maxjustus)).
* Поддержка `direct` (nested loop) JOIN для таблиц семейства MergeTree. Чтобы использовать его, укажите его как единственную опцию в настройке: `join_algorithm = 'direct'`. [#89920](https://github.com/ClickHouse/ClickHouse/pull/89920) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Поддержка `ORDER BY` в операции `CREATE` для Iceberg + сортировка в `INSERT`. Исправлено в [#89916](https://github.com/ClickHouse/ClickHouse/issues/89916). [#90141](https://github.com/ClickHouse/ClickHouse/pull/90141) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* В этом PR добавлены настройки на уровне проекций, доступные через новое предложение WITH SETTINGS в ALTER TABLE ... ADD PROJECTION. Эти настройки позволяют проекциям переопределять некоторые параметры хранения MergeTree (например, index&#95;granularity, index&#95;granularity&#95;bytes) индивидуально для каждой проекции. [#90158](https://github.com/ClickHouse/ClickHouse/pull/90158) ([Amos Bird](https://github.com/amosbird)).
* Добавлен парсер политик маскирования данных. [#90552](https://github.com/ClickHouse/ClickHouse/pull/90552) ([pufit](https://github.com/pufit)).
* Добавлена SQL-функция `HMAC(algorithm, message, key)` в рамках [#73900](https://github.com/ClickHouse/ClickHouse/issues/73900) и [#38775](https://github.com/ClickHouse/ClickHouse/issues/38775). [#90837](https://github.com/ClickHouse/ClickHouse/pull/90837) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* Добавлена поддержка использования первичного ключа и индексов пропуска данных в функции `has()`, если первый аргумент — константный массив. Закрывает [#90980](https://github.com/ClickHouse/ClickHouse/issues/90980). [#91023](https://github.com/ClickHouse/ClickHouse/pull/91023) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Реализован новый формат ввода-вывода `Buffers`. Этот формат похож на `Native`, однако, в отличие от `Native`, он не хранит имена столбцов, типы столбцов и какие-либо дополнительные метаданные. Закрывает [#84017](https://github.com/ClickHouse/ClickHouse/issues/84017). [#91156](https://github.com/ClickHouse/ClickHouse/pull/91156) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Добавлена настройка `max_streams_for_files_processing_in_cluster_functions` для управления количеством потоков при параллельном чтении файлов в табличных функциях cluster. Закрывает [#90223](https://github.com/ClickHouse/ClickHouse/issues/90223). [#91323](https://github.com/ClickHouse/ClickHouse/pull/91323) ([Pavel Kruglov](https://github.com/Avogar)).

<div id="experimental-feature">
  #### Экспериментальные возможности
</div>

* Добавлена новая логика для автоматического выполнения запросов с использованием параллельных реплик, управляемая настройкой `automatic_parallel_replicas_mode`. Во время обычного выполнения на одном узле ClickHouse собирает статистику, которая затем учитывается на этапе планирования. Если статистика показывает, что параллельные реплики, вероятно, будут полезны, ClickHouse автоматически выполнит этот запрос с использованием параллельных реплик. На данный момент набор поддерживаемых запросов довольно ограничен. [#87541](https://github.com/ClickHouse/ClickHouse/pull/87541) ([Nikita Taranov](https://github.com/nickitat)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Немедленно завершать выполнение запросов при достижении лимита строк. Исправляет [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872). [#62804](https://github.com/ClickHouse/ClickHouse/pull/62804) ([Sean Haynes](https://github.com/seandhaynes)).
* Добавлена оптимизация, удаляющая неиспользуемые столбцы из планов запросов. Исправляет [#75152](https://github.com/ClickHouse/ClickHouse/issues/75152). [#76487](https://github.com/ClickHouse/ClickHouse/pull/76487) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Https://github.com/clickhouse/clickhouse/pull/84477 добавил ограничения на SELECT-запросы, которые можно использовать в запросах `insert select from s3cluster()` для параллельного распределённого выполнения. Это изменение позволяет использовать where, как и раньше. [#84611](https://github.com/ClickHouse/ClickHouse/pull/84611) ([Igor Nikonov](https://github.com/devcrafter)).
* Добавлен prefetch ключей при итерации по хеш-таблице для минимизации промахов кэша. [#84708](https://github.com/ClickHouse/ClickHouse/pull/84708) ([lgbo](https://github.com/lgbo-ustc)).
* Оптимизирован AggregateFunctionHistogram: теперь сортируется только хвост массива точек, а для монотонных входных данных сортировка пропускается, что даёт ускорение примерно на 10%. [#85760](https://github.com/ClickHouse/ClickHouse/pull/85760) ([MakarDev](https://github.com/MakarDev)).
* ClickHouse теперь использует индекс пропуска данных для анализа индексов в предложениях WHERE со смешанными условиями фильтрации, соединёнными `AND` и `OR`. Ранее, чтобы использовать индекс пропуска данных, предложение WHERE должно было представлять собой конъюнкцию (AND) условий фильтрации. Эта возможность управляется новой настройкой `use_skip_indexes_for_disjunctions` (по умолчанию: включено). (issue [#75228](https://github.com/ClickHouse/ClickHouse/issues/75228)). [#87781](https://github.com/ClickHouse/ClickHouse/pull/87781) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Улучшена производительность фильтрации для предикатов с функциями, такими как `like`, `equals`, `has` и другими, за счёт использования дополнительного предварительного фильтра, построенного на основе текстового индекса. Эта оптимизация включается настройкой `query_plan_text_index_add_hint`. Также улучшено использование текстового индекса для столбцов типа данных `Map`. [#88550](https://github.com/ClickHouse/ClickHouse/pull/88550) ([Anton Popov](https://github.com/CurtizJ)).
* Оптимизированы повторные обратные обращения к словарю за счёт более быстрого поиска в заранее вычисленном наборе возможных значений ключа. Закрывает [#7968](https://github.com/ClickHouse/ClickHouse/issues/7968). [#88971](https://github.com/ClickHouse/ClickHouse/pull/88971) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Добавлена поддержка разрежённой сериализации для столбцов типа Nullable. Это продолжение [#44539](https://github.com/ClickHouse/ClickHouse/issues/44539). [#88999](https://github.com/ClickHouse/ClickHouse/pull/88999) ([Amos Bird](https://github.com/amosbird)).
* Добавлена поддержка JOIN Runtime Filters для `ANTI` JOIN. Также переработана реализация Runtime Filters для снижения конкуренции за блокировки. [#89710](https://github.com/ClickHouse/ClickHouse/pull/89710) ([Dmitry Novik](https://github.com/novikd)).
* Добавлена поддержка сохранения упорядоченного чтения из левой таблицы в операциях LEFT/INNER JOIN, которое может использоваться на последующих шагах. Это можно отключить с помощью настройки `query_plan_read_in_order_through_join`. Также добавлена поддержка оптимизации виртуальной строки при чтении (см. настройку `read_in_order_use_virtual_row`) для LEFT/INNER JOIN. [#89815](https://github.com/ClickHouse/ClickHouse/pull/89815) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Оптимизированы запросы `ORDER BY...LIMIT N` за счёт использования индекса пропуска данных и динамического порогового фильтра, что позволяет значительно сократить количество обработанных строк. [#89835](https://github.com/ClickHouse/ClickHouse/pull/89835) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Улучшены производительность и поведение topK. [#90091](https://github.com/ClickHouse/ClickHouse/pull/90091) ([Raúl Marín](https://github.com/Algunenano)).
* Повышена производительность операций сравнения Decimal. Исправляет [#28192](https://github.com/ClickHouse/ClickHouse/issues/28192). [#90153](https://github.com/ClickHouse/ClickHouse/pull/90153) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Добавлена поддержка отсечения партиций для функций Paimon в продолжение [https://github.com/ClickHouse/ClickHouse/pull/84423](https://github.com/ClickHouse/ClickHouse/pull/84423). [#90253](https://github.com/ClickHouse/ClickHouse/pull/90253) ([JIaQi](https://github.com/JiaQiTang98)).
* Улучшена производительность лениво материализованных столбцов при более высоком лимите. [#90309](https://github.com/ClickHouse/ClickHouse/pull/90309) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Пользователи должны заметить снижение задержки при анализе индексов при наличии больших индексов `minmax` (миллионы гранул). [#90428](https://github.com/ClickHouse/ClickHouse/pull/90428) ([Shankar Iyer](https://github.com/shankar-iyer)).

* Улучшена производительность JIT-функций за счёт отказа от ненужной инициализации результирующего столбца нулём. [#90449](https://github.com/ClickHouse/ClickHouse/pull/90449) ([Raúl Marín](https://github.com/Algunenano)).
* Ускорена декомпрессия T64 через динамическую диспетчеризацию. [#90610](https://github.com/ClickHouse/ClickHouse/pull/90610) ([Raúl Marín](https://github.com/Algunenano)).
* Оптимизирована inplace-фильтрация в ридере MergeTree. Исправляет [#87119](https://github.com/ClickHouse/ClickHouse/issues/87119). [#90630](https://github.com/ClickHouse/ClickHouse/pull/90630) ([Xiaozhe Yu](https://github.com/wudidapaopao)).
* Запросы теперь завершаются сразу при достижении лимита по строкам. Исправляет [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872). [#90767](https://github.com/ClickHouse/ClickHouse/pull/90767) ([Sean Haynes](https://github.com/seandhaynes)).
* Реализован простой алгоритм переупорядочивания JOIN DPsize для INNER JOIN. Новая экспериментальная настройка определяет, какие алгоритмы и в каком порядке используются; например, `query_plan_optimize_join_order_algorithm='dpsize,greedy'` означает, что сначала пробуется DPsize, а затем выполняется fallback на greedy.
