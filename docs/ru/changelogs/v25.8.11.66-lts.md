<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#88492](https://github.com/ClickHouse/ClickHouse/issues/88492): Для серверного (native) копирования в пункт назначения резервной копии теперь используется клиент хранилища S3 с настройками, специфичными для резервного копирования (например, backup&#95;slow&#95;all&#95;threads&#95;after&#95;retryable&#95;s3&#95;error). Параметр s3&#95;slow&#95;all&#95;threads&#95;after&#95;retryable&#95;error объявлен устаревшим. [#87660](https://github.com/ClickHouse/ClickHouse/pull/87660) ([Julia Kartseva](https://github.com/jkartseva)).
* Бэкпортировано в [#88537](https://github.com/ClickHouse/ClickHouse/issues/88537): Добавлена дополнительная информация для отслеживания производительности в SELECT-запросах Iceberg. [#87903](https://github.com/ClickHouse/ClickHouse/pull/87903) ([Daniil Ivanik](https://github.com/divanik)).
* Бэкпортировано в [#88300](https://github.com/ClickHouse/ClickHouse/issues/88300): Обновлен Azure SDK: в него включено исправление для `Content-Length`, связанное с функциональностью copy и create container. [#88278](https://github.com/ClickHouse/ClickHouse/pull/88278) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Бэкпортировано в [#88742](https://github.com/ClickHouse/ClickHouse/issues/88742): Добавлен параметр config `keeper_server.coordination_settings.check_node_acl_on_remove`. Если он включен, перед каждым удалением node будут проверяться ACL как самой node, так и parent node. В противном случае будет проверяться только ACL parent node. [#88513](https://github.com/ClickHouse/ClickHouse/pull/88513) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#88781](https://github.com/ClickHouse/ClickHouse/issues/88781): Исправлена утечка памяти из-за `GLOBAL IN` ([https://github.com/ClickHouse/ClickHouse/issues/88615](https://github.com/ClickHouse/ClickHouse/issues/88615)). [#88617](https://github.com/ClickHouse/ClickHouse/pull/88617) ([pranavmehta94](https://github.com/pranavmehta94)).
* Бэкпортировано в [#88764](https://github.com/ClickHouse/ClickHouse/issues/88764): В postinstall script для `clickhouse-keeper` добавлен шаг, включающий запуск при загрузке системы. [#88746](https://github.com/ClickHouse/ClickHouse/pull/88746) ([YenchangChan](https://github.com/YenchangChan)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#88848](https://github.com/ClickHouse/ClickHouse/issues/88848): исправлено определение типов Date/DateTime/DateTime64 для дат вне поддерживаемого диапазона. [#86184](https://github.com/ClickHouse/ClickHouse/pull/86184) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#88594](https://github.com/ClickHouse/ClickHouse/issues/88594): исправлено определение схемы таблицы при использовании табличной функции `url()`, когда настройка `parallel_replicas_for_cluster_functions` установлена в 1. [#87029](https://github.com/ClickHouse/ClickHouse/pull/87029) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Бэкпортировано в [#88843](https://github.com/ClickHouse/ClickHouse/issues/88843): исправлена ошибка неизвестной таблицы в запросе insert select с CTE, [#85368](https://github.com/ClickHouse/ClickHouse/issues/85368). [#87789](https://github.com/ClickHouse/ClickHouse/pull/87789) ([Guang Zhao](https://github.com/zheguang)).
* Бэкпортировано в [#88509](https://github.com/ClickHouse/ClickHouse/issues/88509): исправлено чтение подстолбца null map из Variants, которые не могут находиться внутри Nullable. [#87798](https://github.com/ClickHouse/ClickHouse/pull/87798) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#88390](https://github.com/ClickHouse/ClickHouse/issues/88390): в AzureBlobStorage обновлено поведение: сначала выполняется попытка нативного копирования, а при ошибке &#39;Unauthroized&#39; выполняется переход к чтению и записи (в AzureBlobStorage, если storage account для источника и пункта назначения различаются, возникает ошибка &#39;Unauthorized&#39;). Также исправлено применение &quot;use&#95;native&#95;copy&quot;, когда конечная точка задана в конфигурации. [#87826](https://github.com/ClickHouse/ClickHouse/pull/87826) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Бэкпортировано в [#88436](https://github.com/ClickHouse/ClickHouse/issues/88436): исправлено некорректное отсечение гранул/партиций для ключей на основе datetime при использовании настройки `session_timezone` в запросах. [#87987](https://github.com/ClickHouse/ClickHouse/pull/87987) ([Eduard Karacharov](https://github.com/korowa)).
* Бэкпортировано в [#88420](https://github.com/ClickHouse/ClickHouse/issues/88420): нормализация URI теперь применяется перед проверкой привилегий, введённой в [https://github.com/ClickHouse/ClickHouse/pull/84503](https://github.com/ClickHouse/ClickHouse/pull/84503). [#88089](https://github.com/ClickHouse/ClickHouse/pull/88089) ([pufit](https://github.com/pufit)).
* Бэкпортировано в [#88656](https://github.com/ClickHouse/ClickHouse/issues/88656): теперь DDL воркер очищает набор реплик от устаревших хостов. Это уменьшит объём хранимых метаданных в ZooKeeper. [#88154](https://github.com/ClickHouse/ClickHouse/pull/88154) ([alesapin](https://github.com/alesapin)).
* Бэкпортировано в [#88284](https://github.com/ClickHouse/ClickHouse/issues/88284): исправлено распространение флага `is_shared` в `ColumnLowCardinality`. Это может приводить к неверному результату group-by, если новое значение вставляется в столбец после того, как хеш-значения уже предварительно вычислены и кэшированы в `ReverseIndex`. [#88213](https://github.com/ClickHouse/ClickHouse/pull/88213) ([Nikita Taranov](https://github.com/nickitat)).
* Бэкпортировано в [#88459](https://github.com/ClickHouse/ClickHouse/issues/88459): исправлена настройка рабочей нагрузки `max_cpu_share`. Теперь её можно использовать без заданной настройки рабочей нагрузки `max_cpus`. [#88217](https://github.com/ClickHouse/ClickHouse/pull/88217) ([Neerav](https://github.com/neeravsalaria)).
* Бэкпортировано в [#88336](https://github.com/ClickHouse/ClickHouse/issues/88336): теперь коррелированные подзапросы будут работать с объектными хранилищами. [#88290](https://github.com/ClickHouse/ClickHouse/pull/88290) ([alesapin](https://github.com/alesapin)).
* Бэкпортировано в [#88356](https://github.com/ClickHouse/ClickHouse/issues/88356): Исключены попытки инициализации баз данных DataLake при обращении к `system.projections` и `system.data_skipping_indices`. [#88330](https://github.com/ClickHouse/ClickHouse/pull/88330) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#88430](https://github.com/ClickHouse/ClickHouse/issues/88430): Исправлена квадратичная сложность в функции `countMatches`. Закрывает [#88400](https://github.com/ClickHouse/ClickHouse/issues/88400). [#88401](https://github.com/ClickHouse/ClickHouse/pull/88401) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#88649](https://github.com/ClickHouse/ClickHouse/issues/88649): В больших кластерах с номерами узлов &gt; 10 высока вероятность сбоя восстановления с ошибкой `[941] 67c45db4-4df4-4879-87c5-25b8d1e0d414 <Trace>: RestoreCoordinationOnCluster The version of node /clickhouse/backups/restore-7c551a77-bd76-404c-bad0-3213618ac58e/stage/num_hosts changed (attempt #9), will try again`. Узел `num_hosts` одновременно перезаписывается множеством хостов. Исправление делает параметр, управляющий числом попыток, динамическим. Закрывает [#87721](https://github.com/ClickHouse/ClickHouse/issues/87721). [#88484](https://github.com/ClickHouse/ClickHouse/pull/88484) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* Бэкпортировано в [#88716](https://github.com/ClickHouse/ClickHouse/issues/88716): Исправлен потенциальный сбой, вызванный одновременной мутацией базовых const-столбцов PREWHERE. [#88605](https://github.com/ClickHouse/ClickHouse/pull/88605) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#88906](https://github.com/ClickHouse/ClickHouse/issues/88906): После восстановления реплика базы данных Replicated могла надолго зависнуть, выводя сообщения вроде `Failed to marked query-0004647339 as finished (finished=No node, synced=No node)`, это исправлено. [#88671](https://github.com/ClickHouse/ClickHouse/pull/88671) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Бэкпортировано в [#88890](https://github.com/ClickHouse/ClickHouse/issues/88890): Исправлена проверка прав доступа при выполнении select для табличной функции `loop`. [#88802](https://github.com/ClickHouse/ClickHouse/pull/88802) ([pufit](https://github.com/pufit)).
* Бэкпортировано в [#88835](https://github.com/ClickHouse/ClickHouse/issues/88835): Исключения при сбоях асинхронного логирования теперь перехватываются, чтобы предотвратить аварийное завершение программы. [#88814](https://github.com/ClickHouse/ClickHouse/pull/88814) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#88940](https://github.com/ClickHouse/ClickHouse/issues/88940): Исправлена ошибка в функции `reverseUTF8`. В предыдущих версиях она по ошибке переставляла байты в 4-байтных кодовых точках UTF-8. Это закрывает [#88913](https://github.com/ClickHouse/ClickHouse/issues/88913). [#88914](https://github.com/ClickHouse/ClickHouse/pull/88914) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#88976](https://github.com/ClickHouse/ClickHouse/issues/88976): Убрана проверка доступа `SET DEFINER <current_user>:definer` при создании представления с SQL SECURITY DEFINER. [#88968](https://github.com/ClickHouse/ClickHouse/pull/88968) ([pufit](https://github.com/pufit)).
