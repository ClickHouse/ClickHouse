* бэкпорт в [#98110](https://github.com/ClickHouse/ClickHouse/issues/98110): в вывод запроса EXPLAIN добавлена информация об отложенных фильтрах в виде отдельного пункта (при использовании Row Policies/PREWHERE с FINAL). Связано: [https://github.com/ClickHouse/ClickHouse/pull/91065](https://github.com/ClickHouse/ClickHouse/pull/91065). [#97374](https://github.com/ClickHouse/ClickHouse/pull/97374) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#97491](https://github.com/ClickHouse/ClickHouse/issues/97491): если для таблицы не определена статистика, ClickHouse не должен пытаться к ней обращаться. Это устраняет некоторые накладные расходы (100+ мс) на проверку существования файлов статистики. (issue [#96068](https://github.com/ClickHouse/ClickHouse/issues/96068)). [#96233](https://github.com/ClickHouse/ClickHouse/pull/96233) ([Han Fei](https://github.com/hanfei1991)).
* Бэкпортировано в [#97765](https://github.com/ClickHouse/ClickHouse/issues/97765): исправлена проблема, из-за которой ColumnConst не материализовался перед squashing. [#97019](https://github.com/ClickHouse/ClickHouse/pull/97019) ([Hasyimi Bahrudin](https://github.com/hasyimibhar)).
* Бэкпортировано в [#97409](https://github.com/ClickHouse/ClickHouse/issues/97409): исправлены случаи, когда индексы влияли на результат запросов с row policy/PREWHERE и FINAL. [#97076](https://github.com/ClickHouse/ClickHouse/pull/97076) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Бэкпортировано в [#97450](https://github.com/ClickHouse/ClickHouse/issues/97450): исправлено исключение `LOGICAL_ERROR` при чтении подстолбца `.size` разреженного `Nullable(String)` в Tuple с PREWHERE. [#97264](https://github.com/ClickHouse/ClickHouse/pull/97264) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97469](https://github.com/ClickHouse/ClickHouse/issues/97469): исправлен SEGFAULT в supportsTrivialCountOptimization из-за разыменования null. [#97281](https://github.com/ClickHouse/ClickHouse/pull/97281) ([Pablo Marcos](https://github.com/pamarcos)).
* Бэкпортировано в [#97440](https://github.com/ClickHouse/ClickHouse/issues/97440): удалена проверка TABLE&#95;UUID&#95;MISMATCH для режима без analyzer. [#97323](https://github.com/ClickHouse/ClickHouse/pull/97323) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#97994](https://github.com/ClickHouse/ClickHouse/issues/97994): продолжение [https://github.com/ClickHouse/ClickHouse/pull/61135](https://github.com/ClickHouse/ClickHouse/pull/61135), но с сегментированным кэшем. [#97411](https://github.com/ClickHouse/ClickHouse/pull/97411) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Бэкпортировано в [#97697](https://github.com/ClickHouse/ClickHouse/issues/97697): исправлено исключение `LOGICAL_ERROR` при преобразовании Array в `QBit`, когда `nullable_source` из внешней обёртки Tuple заменяет преобразованный столбец типа Array на несовпадающий тип столбца. Закрывает [#97389](https://github.com/ClickHouse/ClickHouse/issues/97389). [#97413](https://github.com/ClickHouse/ClickHouse/pull/97413) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97809](https://github.com/ClickHouse/ClickHouse/issues/97809): исправлено применение параметра `type_json_allow_duplicated_key_with_literal_and_nested_object` к типизированным paths в JSON. Закрывает [#97278](https://github.com/ClickHouse/ClickHouse/issues/97278). [#97422](https://github.com/ClickHouse/ClickHouse/pull/97422) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#97580](https://github.com/ClickHouse/ClickHouse/issues/97580): исправлен `ACCESS_DENIED` для пользователей без разрешения `CREATE TEMPORARY TABLE`, когда оптимизация `optimize_inverse_dictionary_lookup` переписывает предикаты `dictGet(...)`. Теперь ClickHouse пропускает это переписывание и выполняет исходное выражение. Закрывает [#97269](https://github.com/ClickHouse/ClickHouse/issues/97269). [#97484](https://github.com/ClickHouse/ClickHouse/pull/97484) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Бэкпортировано в [#97631](https://github.com/ClickHouse/ClickHouse/issues/97631): Исправлен сбой проверки assert (исключение в debug/sanitizer-сборках) в `Set` и `MergeTreeIndexSet` при обработке столбцов с внутренними разреженными подстолбцами (например, столбцов `Tuple` из частей MergeTree с разными профилями разреженной сериализации). [#97493](https://github.com/ClickHouse/ClickHouse/pull/97493) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97799](https://github.com/ClickHouse/ClickHouse/issues/97799): Исправлено исключение LOGICAL&#95;ERROR при одновременном чтении разреженного столбца и его подстолбца. [#97515](https://github.com/ClickHouse/ClickHouse/pull/97515) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#97958](https://github.com/ClickHouse/ClickHouse/issues/97958): Исправлена логическая ошибка из-за отсутствующего stream при INSERT SELECT с JSON и бакетами в общих данных. Закрывает [#97331](https://github.com/ClickHouse/ClickHouse/issues/97331). [#97523](https://github.com/ClickHouse/ClickHouse/pull/97523) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#97879](https://github.com/ClickHouse/ClickHouse/issues/97879): Оптимизация read-in-order теперь может использовать политики строк. Например, таблица с `ORDER BY (key1, key2)` и политикой строк `USING key1 = 5` теперь может выполнять запросы `ORDER BY key2` без явной сортировки. [#97538](https://github.com/ClickHouse/ClickHouse/pull/97538) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#97739](https://github.com/ClickHouse/ClickHouse/issues/97739): Исправлено исключение `LOGICAL_ERROR` при использовании `isNull`/`isNotNull` для подстолбцов типов `Nullable(Tuple(... Nullable(T) ...))`. Закрывает [#97224](https://github.com/ClickHouse/ClickHouse/issues/97224). [#97582](https://github.com/ClickHouse/ClickHouse/pull/97582) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97603](https://github.com/ClickHouse/ClickHouse/issues/97603): Исправлено разыменование нулевого указателя при применении патч-частей во время легковесных обновлений. [#97583](https://github.com/ClickHouse/ClickHouse/pull/97583) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97720](https://github.com/ClickHouse/ClickHouse/issues/97720): `BaseSettings::readBinary` передаёт индекс из `accessor.find` в `field_infos[]` без проверки сигнального значения «не найдено» (то есть `-1`), что может привести к выходу `std::vector` за пределы массива. Проблему обнаружили благодаря усиленной защите libcxx. Вероятно, это происходило при десериализации плана запроса, когда более новый сервер отправлял настройку, неизвестную более старому серверу. Метод чтения на основе строк уже обрабатывает это корректно; в `readBinary` такой проверки не хватало. [#97585](https://github.com/ClickHouse/ClickHouse/pull/97585) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Бэкпортировано в [#97757](https://github.com/ClickHouse/ClickHouse/issues/97757): Исправлен `filterPartsByVirtualColumns` для предикатов, всегда равных false. [#97620](https://github.com/ClickHouse/ClickHouse/pull/97620) ([Bharat Nallan](https://github.com/bharatnc)).
* Бэкпортировано в [#97689](https://github.com/ClickHouse/ClickHouse/issues/97689): Исправлено исключение logical error при `GROUP BY ... WITH ROLLUP/CUBE`, когда ключи включают `LowCardinality(Nullable(...))` внутри `Nullable(Tuple(...))`. [#97647](https://github.com/ClickHouse/ClickHouse/pull/97647) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97791](https://github.com/ClickHouse/ClickHouse/issues/97791): Исправлено исключение LOGICAL&#95;ERROR в `concat`, когда аргумент содержит тип `Variant` с `LowCardinality` внутри. [#97654](https://github.com/ClickHouse/ClickHouse/pull/97654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97755](https://github.com/ClickHouse/ClickHouse/issues/97755): Исправлено возможное аварийное завершение/assert процесса ClickHouse, если в `WHERE` было более 32 выражений с AND/OR. [#97698](https://github.com/ClickHouse/ClickHouse/pull/97698) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Бэкпортировано в [#98223](https://github.com/ClickHouse/ClickHouse/issues/98223): Исправлены возможные сбои при чтении пустых гранул в расширенных общих данных JSON. Закрывает [#97563](https://github.com/ClickHouse/ClickHouse/issues/97563). [#97778](https://github.com/ClickHouse/ClickHouse/pull/97778) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#97983](https://github.com/ClickHouse/ClickHouse/issues/97983): Исправлены исключения LOGICAL&#95;ERROR, вызванные `LowCardinality` внутри составных типов (`Variant`, `Dynamic`, `Tuple`) в `concatWithSeparator`, `format`, подзапросах `IN`, `GLOBAL IN` и JOIN с фильтрами времени выполнения. [#97831](https://github.com/ClickHouse/ClickHouse/pull/97831) ([Raúl Marín](https://github.com/Algunenano)).
* Бэкпортировано в [#97917](https://github.com/ClickHouse/ClickHouse/issues/97917): Исправлен некорректный результат при использовании алгоритма `grace_hash` с non-equi JOIN, когда левый блок не может быть полностью обработан из-за ограничений на размер результата JOIN. [#97866](https://github.com/ClickHouse/ClickHouse/pull/97866) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#98061](https://github.com/ClickHouse/ClickHouse/issues/98061): Исправлена гонка данных в клиенте ZooKeeper между sendThread и receiveThread. [#97887](https://github.com/ClickHouse/ClickHouse/pull/97887) ([Pablo Marcos](https://github.com/pamarcos)).
* Бэкпортировано в [#98174](https://github.com/ClickHouse/ClickHouse/issues/98174): Исправлена потеря данных Keeper после перезапуска при использовании Azure Blob Storage с метаданными `s3_plain` для хранения лога. [#97987](https://github.com/ClickHouse/ClickHouse/pull/97987) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#98308](https://github.com/ClickHouse/ClickHouse/issues/98308): Исправлен некорректный результат запросов FINAL при смешивании индексов пропуска данных по первичному ключу и не по первичному ключу. [#98097](https://github.com/ClickHouse/ClickHouse/pull/98097) ([Raúl Marín](https://github.com/Algunenano)).
