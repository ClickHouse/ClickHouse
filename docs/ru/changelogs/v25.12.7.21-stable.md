<div id="backward-incompatible-change">
  #### обратно несовместимое изменение
</div>

* Бэкпортировано в [#97402](https://github.com/ClickHouse/ClickHouse/issues/97402): `apply_row_policy_after_final` включен по умолчанию. Изначально, когда `optimize_move_to_prewhere_if_final=0`, и ROW POLICY, и PREWHERE учитывали FINAL и применялись после FINAL. Это поведение было нарушено в [#87303](https://github.com/ClickHouse/ClickHouse/issues/87303), где для фильтра ROW POLICY игнорировался параметр `optimize_move_to_prewhere_if_final`. Чтобы исправить это, в данном PR включается настройка `apply_row_policy_after_final`, добавленная в [#91065](https://github.com/ClickHouse/ClickHouse/issues/91065). При включенном `apply_row_policy_after_final` ROW POLICY по умолчанию, как и прежде, продолжает учитывать FINAL. Этот PR является несовместимым изменением, поскольку меняет поведение при `optimize_move_to_prewhere_if_final=1`. Теперь, чтобы ROW POLICY применялся до FINAL, нужно использовать `apply_row_policy_after_final` вместо `optimize_move_to_prewhere_if_final`. [#97279](https://github.com/ClickHouse/ClickHouse/pull/97279) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#95490](https://github.com/ClickHouse/ClickHouse/issues/95490): В табличной функции `mergeTreeProjection` отсутствовала проверка прав доступа, из-за чего пользователи без разрешения SELECT на таблицу (но с разрешениями на табличные функции) могли читать данные из её проекций. Это исправление добавляет ту же проверку прав доступа, которая уже есть в `mergeTreeIndex` и `mergeTreeAnalyzeIndexes`. [#95480](https://github.com/ClickHouse/ClickHouse/pull/95480) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97185](https://github.com/ClickHouse/ClickHouse/issues/97185): Исправлено выполнение tupleElement для JSON с вложенными путями; ранее это могло приводить к неверному результату запроса. [#95907](https://github.com/ClickHouse/ClickHouse/pull/95907) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#96785](https://github.com/ClickHouse/ClickHouse/issues/96785): Исправлен сбой при ORDER BY в Iceberg. Продолжение [https://github.com/ClickHouse/ClickHouse/pull/93296](https://github.com/ClickHouse/ClickHouse/pull/93296). Закрывает [#93280](https://github.com/ClickHouse/ClickHouse/issues/93280). [#96484](https://github.com/ClickHouse/ClickHouse/pull/96484) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Бэкпортировано в [#97763](https://github.com/ClickHouse/ClickHouse/issues/97763): Исправлено отсутствие materialize для ColumnConst перед squashing. [#97019](https://github.com/ClickHouse/ClickHouse/pull/97019) ([Hasyimi Bahrudin](https://github.com/hasyimibhar)).
* Бэкпортировано в [#97964](https://github.com/ClickHouse/ClickHouse/issues/97964): Исправлены случаи, когда индексы влияли на результат запросов с ROW POLICY/PREWHERE и FINAL. [#97076](https://github.com/ClickHouse/ClickHouse/pull/97076) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Бэкпортировано в [#97467](https://github.com/ClickHouse/ClickHouse/issues/97467): Исправлен segfault в supportsTrivialCountOptimization из-за разыменования null-указателя. [#97281](https://github.com/ClickHouse/ClickHouse/pull/97281) ([Pablo Marcos](https://github.com/pamarcos)).
* Бэкпортировано в [#97438](https://github.com/ClickHouse/ClickHouse/issues/97438): Удалена проверка TABLE&#95;UUID&#95;MISMATCH для non-analyzer. [#97323](https://github.com/ClickHouse/ClickHouse/pull/97323) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#97993](https://github.com/ClickHouse/ClickHouse/issues/97993): Продолжение [https://github.com/ClickHouse/ClickHouse/pull/61135](https://github.com/ClickHouse/ClickHouse/pull/61135), но с сегментированным cache. [#97411](https://github.com/ClickHouse/ClickHouse/pull/97411) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Бэкпортировано в [#97578](https://github.com/ClickHouse/ClickHouse/issues/97578): Исправлен `ACCESS_DENIED` для пользователей без разрешения `CREATE TEMPORARY TABLE`, когда оптимизация `optimize_inverse_dictionary_lookup` переписывает предикаты `dictGet(...)`. Теперь ClickHouse пропускает это переписывание и выполняет исходное выражение. Закрывает [#97269](https://github.com/ClickHouse/ClickHouse/issues/97269). [#97484](https://github.com/ClickHouse/ClickHouse/pull/97484) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Бэкпортировано в [#97629](https://github.com/ClickHouse/ClickHouse/issues/97629): Исправлено срабатывание assert (исключение в debug/sanitizer builds) в `Set` и `MergeTreeIndexSet` при обработке столбцов с внутренними разреженными подстолбцами (например, столбцов `Tuple` из частей MergeTree с разными профилями разреженной сериализации). [#97493](https://github.com/ClickHouse/ClickHouse/pull/97493) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97797](https://github.com/ClickHouse/ClickHouse/issues/97797): Исправлено исключение LOGICAL&#95;ERROR при одновременном чтении разреженного столбца и его подстолбца. [#97515](https://github.com/ClickHouse/ClickHouse/pull/97515) ([Pavel Kruglov](https://github.com/Avogar)).
* Бэкпортировано в [#97611](https://github.com/ClickHouse/ClickHouse/issues/97611): Исправлено возможное обращение к уже освобождённой памяти в StorageKafka2. [#97520](https://github.com/ClickHouse/ClickHouse/pull/97520) ([Bharat Nallan](https://github.com/bharatnc)).
* Бэкпортировано в [#97877](https://github.com/ClickHouse/ClickHouse/issues/97877): Оптимизации read-in-order теперь разрешено использовать политики строк. Например, таблица с `ORDER BY (key1, key2)` и политикой строк `USING key1 = 5` теперь может выполнять запросы `ORDER BY key2` без явной сортировки. [#97538](https://github.com/ClickHouse/ClickHouse/pull/97538) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#97601](https://github.com/ClickHouse/ClickHouse/issues/97601): Исправлено разыменование нулевого указателя при применении патч-частей во время легковесных обновлений. [#97583](https://github.com/ClickHouse/ClickHouse/pull/97583) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#97718](https://github.com/ClickHouse/ClickHouse/issues/97718): `BaseSettings::readBinary` передаёт индекс из `accessor.find` в `field_infos[]`, не проверяя специальное значение «не найдено» (то есть `-1`), что может привести к выходу за границы `std::vector`. Проблему удалось выявить благодаря механизмам защиты libcxx. Вероятно, это происходило при десериализации плана запроса, когда более новый сервер отправлял настройку, неизвестную более старому серверу. Метод чтения на основе строк уже обрабатывает это корректно; в `readBinary` такой проверки не хватало. [#97585](https://github.com/ClickHouse/ClickHouse/pull/97585) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Бэкпортировано в [#97753](https://github.com/ClickHouse/ClickHouse/issues/97753): Исправлено возможное аварийное завершение/assert процесса ClickHouse, если предложение `WHERE` содержало более 32 выражений с AND/OR. [#97698](https://github.com/ClickHouse/ClickHouse/pull/97698) ([Shankar Iyer](https://github.com/shankar-iyer)).
