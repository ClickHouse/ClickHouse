<div id="backward-incompatible-change">
  #### Обратно несовместимое изменение
</div>

* `clickhouse-client` и `clickhouse-local` теперь по умолчанию работают в режиме multi-query (вместо single-query). Например, теперь работает `clickhouse-client -q "SELECT 1; SELECT 2"`, тогда как раньше пользователям нужно было добавлять `--multiquery` (или `-n`). Переключатель `--multiquery/-n` устарел. INSERT-запросы в multi-query командах обрабатываются особым образом в зависимости от их предложения FORMAT: если FORMAT — `VALUES` (самый распространённый случай), конец оператора INSERT обозначается завершающей точкой с запятой `;` в конце запроса. Для всех остальных FORMATов (например, `CSV` или `JSONEachRow`) конец оператора INSERT обозначается двумя символами новой строки `\n\n` в конце запроса. [#63898](https://github.com/ClickHouse/ClickHouse/pull/63898) ([FFish](https://github.com/wxybear)).
* В предыдущих версиях можно было использовать альтернативный синтаксис для типов данных `LowCardinality`, добавляя `WithDictionary` к имени типа данных. Это была ранняя рабочая реализация, которая никогда не документировалась и не предназначалась для публичного использования. Теперь она устарела. Если вы использовали этот синтаксис, вам нужно выполнить ALTER для ваших таблиц и переименовать типы данных в `LowCardinality`. [#66842](https://github.com/ClickHouse/ClickHouse/pull/66842) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлены логические ошибки при использовании хранилища `Buffer` с распределённой целевой таблицей. Это обратно несовместимое изменение: запросы, использующие `Buffer` с распределённой целевой таблицей, могут перестать работать, если таблица встречается в запросе более одного раза (например, при самосоединении). [#67015](https://github.com/ClickHouse/ClickHouse/pull/67015) ([vdimir](https://github.com/vdimir)).
* В предыдущих версиях вызов функций для случайных распределений на основе гамма-функции (таких как Chi-Squared, Student, Fisher) с отрицательными аргументами, близкими к нулю, приводил к длительным вычислениям или бесконечному циклу. В новой версии вызов этих функций с нулевыми или отрицательными аргументами будет приводить к исключению. Это закрывает [#67297](https://github.com/ClickHouse/ClickHouse/issues/67297). [#67326](https://github.com/ClickHouse/ClickHouse/pull/67326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Системная таблица `text_log` теперь включена по умолчанию. Это полностью совместимо с предыдущими версиями, но вы можете заметить небольшое увеличение использования локального диска (эта системная таблица занимает совсем немного дискового пространства). [#67428](https://github.com/ClickHouse/ClickHouse/pull/67428) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* В предыдущих версиях `arrayWithConstant` могла работать медленно, если от неё требовалось генерировать очень большие массивы. В новой версии размер одного массива ограничен 1 ГБ. Это закрывает [#32754](https://github.com/ClickHouse/ClickHouse/issues/32754). [#67741](https://github.com/ClickHouse/ClickHouse/pull/67741) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Исправлено форматирование модификатора REPLACE (запрещён пропуск скобок). [#67774](https://github.com/ClickHouse/ClickHouse/pull/67774) ([Azat Khuzhin](https://github.com/azat)).
* Бэкпортировано в [#68349](https://github.com/ClickHouse/ClickHouse/issues/68349): тип Dynamic реализован заново. Теперь, когда достигается лимит динамических типов данных, новые типы не приводятся к `String`, а сохраняются в специальной структуре данных в двоичном формате с двоично-кодированным типом данных. Теперь любой тип, когда-либо вставленный в столбец типа Dynamic, можно читать из него как подстолбец. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="new-feature">
  #### Новая возможность
</div>

* Добавлен новый экспериментальный движок хранения Kafka для сохранения смещений в Keeper вместо фиксации их в Kafka. [#57625](https://github.com/ClickHouse/ClickHouse/pull/57625) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Добавлен новый движок таблицы TimeSeries: - по умолчанию: `CREATE TABLE tbl ENGINE=TimeSeries` - или с указанием движков его внутренних таблиц. [#64183](https://github.com/ClickHouse/ClickHouse/pull/64183) ([Vitaly Baranov](https://github.com/vitlibar)).
* Поддерживается больше вариантов strictness для JOIN (`LEFT/RIGHT SEMI/ANTI/ANY JOIN`) с условиями неравенства, в которых используются столбцы как из левой, так и из правой таблицы. Например, t1.y &lt; t2.y (см. настройку `allow_experimental_join_condition`). [#64281](https://github.com/ClickHouse/ClickHouse/pull/64281) ([lgbo](https://github.com/lgbo-ustc)).
* Добавлен виртуальный столбец `_etag` для движка таблицы S3. Исправляет [#65312](https://github.com/ClickHouse/ClickHouse/issues/65312). [#65386](https://github.com/ClickHouse/ClickHouse/pull/65386) ([skyoct](https://github.com/skyoct)).
* Этот pull request добавляет секционирование в стиле Hive для различных движков (`File`, `URL`, `S3`, `AzureBlobStorage`, `HDFS`). Секционирование в стиле Hive организует данные по секционированным подкаталогам, что упрощает выполнение запросов и управление большими датасетами. Пока оно только создает виртуальные столбцы с соответствующими именами и данными. Следующий PR добавит соответствующую фильтрацию данных (ускорение производительности). [#65997](https://github.com/ClickHouse/ClickHouse/pull/65997) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Добавлена функция printf для совместимости со Spark. [#66257](https://github.com/ClickHouse/ClickHouse/pull/66257) ([李扬](https://github.com/taiyang-li)).
* Бэкпортировано в [#68450](https://github.com/ClickHouse/ClickHouse/issues/68450): реализован новый тип данных JSON. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Kruglov Pavel](https://github.com/Avogar)).
* Добавлена новая настройка сервера: disable&#95;insertion&#95;and&#95;mutation. Установите ее в true. Этот узел будет запрещать все вставки и мутации (Alter table delete/update/drop partition), включая асинхронную вставку. [#66519](https://github.com/ClickHouse/ClickHouse/pull/66519) ([Xu Jia](https://github.com/XuJia0210)).
* Добавлены опции `restore_replace_external_engines_to_null` и `restore_replace_external_table_functions_to_null`, которые заменяют внешние движки и функции таблиц на движок Null, что может быть полезно для тестирования. Это должно работать для RESTORE и явного создания таблиц. [#66536](https://github.com/ClickHouse/ClickHouse/pull/66536) ([Ilya Yatsishin](https://github.com/qoega)).
* Добавлена поддержка чтения геометрии MULTILINESTRING в формате WKT с помощью функции readWKTLineString. [#67647](https://github.com/ClickHouse/ClickHouse/pull/67647) ([Jacob Reckhard](https://github.com/jacobrec)).
* Добавлена новая табличная функция `fuzzQuery`. Эта функция позволяет вносить случайные изменения в заданную строку запроса. Пример: `SELECT query FROM fuzzQuery('SELECT 1') LIMIT 5;`. [#67655](https://github.com/ClickHouse/ClickHouse/pull/67655) ([pufit](https://github.com/pufit)).
* Поддерживается запрос `DROP DETACHED PARTITION ALL` для удаления всех отсоединенных партиций. [#67885](https://github.com/ClickHouse/ClickHouse/pull/67885) ([Duc Canh Le](https://github.com/canhld94)).
* Добавлен механизм тегирования (пространства имен) для кэша запросов. Одинаковые запросы с разными тегами теперь считаются разными для кэша запросов. Пример: `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'abc'` и `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'def'` теперь создают разные записи кэша запросов. [#68235](https://github.com/ClickHouse/ClickHouse/pull/68235) ([sakulali](https://github.com/sakulali)).

<div id="performance-improvement">
  #### Повышение производительности
</div>

* Для параллельных реплик используется адаптивный метод расчета размера задач чтения (то есть размер зависит от размеров читаемых столбцов). [#60377](https://github.com/ClickHouse/ClickHouse/pull/60377) ([Nikita Taranov](https://github.com/nickitat)).
* Метаданные каталога диска `plain_rewritable` теперь хранятся в структуре `__meta`, отдельно от данных MergeTree в объектном хранилище. Диск `plain_rewritable` переведен на плоскую структуру каталогов. [#65751](https://github.com/ClickHouse/ClickHouse/pull/65751) ([Julia Kartseva](https://github.com/jkartseva)).
* `compile_expressions` (JIT-компилятор для фрагментов обычных выражений) теперь включен по умолчанию. Это закрывает [#51264](https://github.com/ClickHouse/ClickHouse/issues/51264) и [#56386](https://github.com/ClickHouse/ClickHouse/issues/56386). [#66486](https://github.com/ClickHouse/ClickHouse/pull/66486) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Улучшено укрупнение столбцов для типов String/Array/Map/Variant/Dynamic за счет предварительного резервирования необходимой памяти для всех подстолбцов. [#67043](https://github.com/ClickHouse/ClickHouse/pull/67043) ([Kruglov Pavel](https://github.com/Avogar)).
* Ускорено выполнение SYSTEM FLUSH LOGS; журналы теперь сбрасываются при завершении работы. [#67472](https://github.com/ClickHouse/ClickHouse/pull/67472) ([Sema Checherinda](https://github.com/CheSema)).
* Бэкпортировано в [#68496](https://github.com/ClickHouse/ClickHouse/issues/68496): улучшена общая производительность слияний за счет снижения накладных расходов на планирование их шагов. [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* Настройка `optimize_functions_to_subcolumns` включена по умолчанию. [#68053](https://github.com/ClickHouse/ClickHouse/pull/68053) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### Улучшения
</div>

* Сервер ClickHouse теперь поддерживает новую настройку `max_keep_alive_requests`. Для keep-alive HTTP-соединений с сервером она работает в связке с `keep_alive_timeout`: если тайм-аут простоя еще не истек, но через данное соединение уже выполнено больше `max_keep_alive_requests` запросов, сервер закроет его. [#61793](https://github.com/ClickHouse/ClickHouse/pull/61793) ([Nikita Taranov](https://github.com/nickitat)).
* Поскольку в новой версии SOURCES проверяются на основе логики движка таблицы, даже если grant на движок таблицы по умолчанию отключен, при отсутствии grant для source вместо этого появляется сообщение о движке таблицы, что вводит в заблуждение. [#65419](https://github.com/ClickHouse/ClickHouse/pull/65419) ([jsc0218](https://github.com/jsc0218)).
* Добавлен тип статистики `count_min` (count-min sketches), который предоставляет оценки selectivity для предикатов равенства, таких как `col = 'val'`. Поддерживаемые типы данных: string, date, datatime и числовые типы. [#65521](https://github.com/ClickHouse/ClickHouse/pull/65521) ([JackyWoo](https://github.com/JackyWoo)).
* Не передавать журналы для Keeper явно в образе, чтобы их можно было переопределить. [#65564](https://github.com/ClickHouse/ClickHouse/pull/65564) ([Azat Khuzhin](https://github.com/azat)).
* По умолчанию использовать базу данных `Atomic` в `clickhouse-local`. Устраняет пункты 1 и 5 из [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647). Закрывает [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817). [#65860](https://github.com/ClickHouse/ClickHouse/pull/65860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Добавлена статистика `rows_before_aggregation_at_least` в ответ на запрос, когда включен `rows_before_aggregation`. Эта статистика показывает количество строк, прочитанных до aggregation. В контексте distributed query при использовании `group by` или агрегатной функции `max` без `limit` `rows_before_aggregation_at_least` может отражать количество строк, затронутых запросом. [#66084](https://github.com/ClickHouse/ClickHouse/pull/66084) ([morning-color](https://github.com/morning-color)).
* Добавлены настройки `use_same_password_for_base_backup` для запросов `BACKUP` и `RESTORE`, позволяющие создавать и восстанавливать инкрементные резервные копии в/из архивов, защищенных паролем. [#66214](https://github.com/ClickHouse/ClickHouse/pull/66214) ([Samuele](https://github.com/sguerrini97)).
* Игнорировать async&#95;load&#95;databases для запроса ATTACH (ранее ATTACH мог завершиться до того, как таблицы были подключены). [#66240](https://github.com/ClickHouse/ClickHouse/pull/66240) ([Azat Khuzhin](https://github.com/azat)).
* [Replicated]MergeTreeSink должен корректно отменять свой delayed&#95;chunk в методе `onCancel()`. [#66279](https://github.com/ClickHouse/ClickHouse/pull/66279) ([Sema Checherinda](https://github.com/CheSema)).
* Добавлены журналы и метрики для отклоненных соединений (когда недостаточно ресурсов). [#66410](https://github.com/ClickHouse/ClickHouse/pull/66410) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Настройка `allow_experimental_analyzer` переименована в `enable_analyzer`. Старое имя сохранено в виде алиаса. [#66438](https://github.com/ClickHouse/ClickHouse/pull/66438) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Добавлена поддержка настоящего типа UUID для движка MongoDB. [#66671](https://github.com/ClickHouse/ClickHouse/pull/66671) ([Azat Khuzhin](https://github.com/azat)).
* Добавлена новая настройка `MergeTree` `deduplicate_merge_projection_mode` для управления проекциями при слияниях (для определённых движков) и в запросе `OPTIMIZE DEDUPLICATE`. Поддерживаемые варианты: `throw` (сгенерировать исключение, если проекция поддерживается для таблиц семейства *MergeTree не полностью), `drop` (удалить проекцию при слиянии, если её саму нельзя согласованно слить) и `rebuild` (перестроить проекцию с нуля, что является ресурсоёмкой операцией). [#66672](https://github.com/ClickHouse/ClickHouse/pull/66672) ([jsc0218](https://github.com/jsc0218)).
* Добавлены метрики задержки репликации и времени восстановления. [#66703](https://github.com/ClickHouse/ClickHouse/pull/66703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Добавлена метрика S3DiskNoKeyErrors. [#66704](https://github.com/ClickHouse/ClickHouse/pull/66704) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Обеспечена работа клаузы COMMENT для всех движков таблиц. [#66832](https://github.com/ClickHouse/ClickHouse/pull/66832) ([Joe Lynch](https://github.com/joelynch)).
* Уточнено использование кодов ошибок `BAD_ARGUMENTS` и `ILLEGAL_TYPE_OF_ARGUMENT`: там, где это уместно, теперь используются более точные коды ошибок. [#66851](https://github.com/ClickHouse/ClickHouse/pull/66851) ([Yohann Jardin](https://github.com/yohannj)).
* Функция `mapFromArrays` теперь принимает `Map(K, V)` в качестве первого аргумента, например: `SELECT mapFromArrays(map('a', 4, 'b', 4), ['aa', 'bb'])` теперь работает и возвращает `{('a',4):'aa',('b',4):'bb'}`. Также, если 1-й аргумент — это Array, теперь он тоже может быть типа `Array(Nullable(T))` или `Array(LowCardinality(Nullable(T)))`, если фактические значения массива не равны `NULL`. [#67103](https://github.com/ClickHouse/ClickHouse/pull/67103) ([李扬](https://github.com/taiyang-li)).
* Чтение configuration для clickhouse-local из ~/.clickhouse-local. [#67135](https://github.com/ClickHouse/ClickHouse/pull/67135) ([Azat Khuzhin](https://github.com/azat)).
* Настройка `input_format_orc_read_use_writer_time_zone` переименована в `input_format_orc_reader_timezone`, и теперь пользователь может задавать timezone для reader. [#67175](https://github.com/ClickHouse/ClickHouse/pull/67175) ([kevinyhzou](https://github.com/KevinyhZou)).
* Снижен уровень ошибки &#39;Socket is not connected&#39; в случае, когда HTTP-соединение сразу сбрасывается удалённой стороной после подключения; закрывает [#34218](https://github.com/ClickHouse/ClickHouse/issues/34218). [#67177](https://github.com/ClickHouse/ClickHouse/pull/67177) ([vdimir](https://github.com/vdimir)).
* Ускорено удаление таблиц для запроса `DROP DATABASE`; значение по умолчанию для `database_catalog_drop_table_concurrency` увеличено до 16. [#67228](https://github.com/ClickHouse/ClickHouse/pull/67228) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Добавлена возможность загружать dashboards для system.dashboards из config (после настройки они переопределяют набор dashboards по умолчанию). [#67232](https://github.com/ClickHouse/ClickHouse/pull/67232) ([Azat Khuzhin](https://github.com/azat)).
* Оконные функции в SQL традиционно используют snake case. В ClickHouse используется camelCase, поэтому были созданы новые псевдонимы `denseRank()` и `percentRank()`. Эти новые функции можно вызывать точно так же, как исходные функции `dense_rank()` и `percent_rank()`. Оба варианта синтаксиса — snake case и camelCase — остаются доступными. Также для каждой из этих функций был добавлен новый тест. Это закрывает [#67042](https://github.com/ClickHouse/ClickHouse/issues/67042). [#67334](https://github.com/ClickHouse/ClickHouse/pull/67334) ([Peter Nguyen](https://github.com/petern48)).
* Автоматически определять формат файла конфигурации, если это не .xml, .yml или .yaml. Если файл начинается с &lt;, это может быть XML, в противном случае — YAML. Нерегулярные файлы, такие как PIPE: /dev/fd/X, просто разбирать как XML. [#67391](https://github.com/ClickHouse/ClickHouse/pull/67391) ([sakulali](https://github.com/sakulali)).
* Функции `formatDateTime` и `formatDateTimeInJodaSyntax` теперь считают параметр `format` необязательным. Если он не указан, предполагаются строки формата `%Y-%m-%d %H:%i:%s` и `yyyy-MM-dd HH:mm:ss`. Пример: `SELECT parseDateTime('2021-01-04 23:12:34')` теперь возвращает значение DateTime `2021-01-04 23:12:34` (раньше это приводило к исключению). [#67399](https://github.com/ClickHouse/ClickHouse/pull/67399) ([Robert Schulze](https://github.com/rschu1ze)).
* Автоматически повторять запросы Keeper в KeeperMap, если они завершаются из-за тайм-аута или потери соединения. [#67448](https://github.com/ClickHouse/ClickHouse/pull/67448) ([Antonio Andelic](https://github.com/antonio2368)).
* Переработано использование пользовательских дисков таблицы. [#67684](https://github.com/ClickHouse/ClickHouse/pull/67684) ([Sema Checherinda](https://github.com/CheSema)).

  #### Улучшения сборки/тестирования/упаковки

* Улучшены тесты `test_storage_s3`: увеличен `s3_max_single_read_retries` для чтения из «нестабильного» источника S3, а также разрешено запускать все тесты несколько раз подряд. [#66896](https://github.com/ClickHouse/ClickHouse/pull/66896) ([Ilya Yatsishin](https://github.com/qoega)).
* Flaky-check интеграционных тестов теперь будет запускать каждый тестовый случай несколько раз, чтобы выявлять больше проблем в тестах и повышать их надёжность. Для этого используется библиотека `pytest-repeat`, которая запускает тестовый случай несколько раз в одном и том же окружении. Чтобы тест успешно проходил, важно очищать таблицы и другие сущности в конце каждого тестового случая. Repeat работает значительно быстрее, чем несколько запусков pytest, так как необходимые контейнеры запускаются только один раз.
