<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#82862](https://github.com/ClickHouse/ClickHouse/issues/82862): После [https://github.com/ClickHouse/ClickHouse/pull/73834](https://github.com/ClickHouse/ClickHouse/pull/73834) форматы заголовков `X-ClickHouse-Progress` и `X-ClickHouse-Summary` были изменены так, чтобы исключать нулевые значения. Этот PR возвращает прежнее поведение, но только для `X-ClickHouse-Summary`, поскольку это оправданно. [#82727](https://github.com/ClickHouse/ClickHouse/pull/82727) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Бэкпортировано в [#84037](https://github.com/ClickHouse/ClickHouse/issues/84037): Используется информация из cgroup (если применимо, то есть если доступны `memory_worker_use_cgroup` и cgroups) для корректировки трекера памяти (`memory_worker_correct_memory_tracker`). [#83981](https://github.com/ClickHouse/ClickHouse/pull/83981) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#83144](https://github.com/ClickHouse/ClickHouse/issues/83144): не использовать несвязанные части общего словаря в функции `lowCardinalityKeys`. [#83118](https://github.com/ClickHouse/ClickHouse/pull/83118) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#83766](https://github.com/ClickHouse/ClickHouse/issues/83766): исправление в Keeper: общее число наблюдений теперь корректно обновляется при удалении эфемерных узлов при закрытии сеанса. [#83583](https://github.com/ClickHouse/ClickHouse/pull/83583) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#84109](https://github.com/ClickHouse/ClickHouse/issues/84109): скрывать данные аутентификации Avro schema registry, чтобы они не были видны пользователю и не попадали в логи. [#83713](https://github.com/ClickHouse/ClickHouse/pull/83713) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Бэкпортировано в [#83917](https://github.com/ClickHouse/ClickHouse/issues/83917): исправлена проблема, из-за которой, если таблица семейства MergeTree создается с `add_minmax_index_for_numeric_columns=1` или `add_minmax_index_for_string_columns=1`, а индекс затем материализуется во время операции ALTER, это мешает базе данных Replicated корректно инициализироваться на новой реплике. [#83751](https://github.com/ClickHouse/ClickHouse/pull/83751) ([Nikolay Degterinsky](https://github.com/evillique)).
* Бэкпортировано в [#83874](https://github.com/ClickHouse/ClickHouse/issues/83874): добавлена настройка обратной совместимости, позволяющая новому анализатору ссылаться на внешний псевдоним в конструкции WITH при конфликтах имен. Исправляет [#82700](https://github.com/ClickHouse/ClickHouse/issues/82700). [#83797](https://github.com/ClickHouse/ClickHouse/pull/83797) ([Dmitry Novik](https://github.com/novikd)).
* Бэкпортировано в [#84092](https://github.com/ClickHouse/ClickHouse/issues/84092): при восстановлении из резервной копии пользователь-определитель может не попасть в резервную копию, из-за чего она целиком становится непригодной. Чтобы это исправить, проверка разрешений при создании целевой таблицы во время восстановления откладывается и выполняется только во время выполнения. [#83818](https://github.com/ClickHouse/ClickHouse/pull/83818) ([pufit](https://github.com/pufit)).
* Бэкпортировано в [#84224](https://github.com/ClickHouse/ClickHouse/issues/84224): разрешено ссылаться на любую таблицу в аргументе `view(...)` табличной функции `remote` при включенном анализаторе. Исправляет [#78717](https://github.com/ClickHouse/ClickHouse/issues/78717). Исправляет [#79377](https://github.com/ClickHouse/ClickHouse/issues/79377). [#83844](https://github.com/ClickHouse/ClickHouse/pull/83844) ([Dmitry Novik](https://github.com/novikd)).
* Бэкпортировано в [#84129](https://github.com/ClickHouse/ClickHouse/issues/84129): исправлена редкая ошибка, при которой запрос `MATERIALIZE COLUMN` мог приводить к появлению неожиданных файлов в `checksums.txt` и в конечном итоге к отсоединенным частям данных. [#84007](https://github.com/ClickHouse/ClickHouse/pull/84007) ([alesapin](https://github.com/alesapin)).
* Бэкпортировано в [#84272](https://github.com/ClickHouse/ClickHouse/issues/84272): исправлены неверные результаты при использовании кэша условий запроса вместе с рекурсивными CTE (issue [#81506](https://github.com/ClickHouse/ClickHouse/issues/81506)). [#84026](https://github.com/ClickHouse/ClickHouse/pull/84026) ([zhongyuankai](https://github.com/zhongyuankai)).
* Бэкпортировано в [#84288](https://github.com/ClickHouse/ClickHouse/issues/84288): исправлено редкое аварийное завершение ClickHouse, когда у таблицы есть projection, `lightweight_mutation_projection_mode = 'rebuild'`, и пользователь выполняет lightweight delete, удаляющий ВСЕ строки из любого блока таблицы. [#84158](https://github.com/ClickHouse/ClickHouse/pull/84158) ([alesapin](https://github.com/alesapin)).
