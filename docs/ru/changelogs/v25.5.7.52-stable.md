<div id="improvement">
  #### Улучшения
</div>

* Бэкпортировано в [#83014](https://github.com/ClickHouse/ClickHouse/issues/83014): улучшение Keeper: перемещение файлов changelog между дисками в фоновом потоке. Ранее перенос changelog на другой диск полностью блокировал работу Keeper до завершения операции. Это приводило к снижению производительности, если перенос занимал много времени (например, на S3-диск). [#82485](https://github.com/ClickHouse/ClickHouse/pull/82485) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпортировано в [#83268](https://github.com/ClickHouse/ClickHouse/issues/83268): исправлено неверное значение по умолчанию для опции `--reconnect` в `clickhouse-benchmark`. Оно было изменено по ошибке в [#79465](https://github.com/ClickHouse/ClickHouse/issues/79465). [#82677](https://github.com/ClickHouse/ClickHouse/pull/82677) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#83152](https://github.com/ClickHouse/ClickHouse/issues/83152): в `system.s3queue_log` добавлены столбцы `commit_time`, `commit_id`. [#83016](https://github.com/ClickHouse/ClickHouse/pull/83016) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Бэкпортировано в [#83634](https://github.com/ClickHouse/ClickHouse/issues/83634): если `distributed_ddl_output_mode='*_only_active'`, не ждать новые или восстановленные реплики, у которых задержка репликации превышает `max_replication_lag_to_enqueue`. Это должно помочь избежать `DDL task is not finished on some hosts`, когда новая реплика становится активной после завершения инициализации или восстановления, но за время инициализации успевает накопить огромный журнал репликации. Также реализован запрос `SYSTEM SYNC DATABASE REPLICA STRICT`, который ждёт, пока журнал репликации не станет меньше `max_replication_lag_to_enqueue`. [#83302](https://github.com/ClickHouse/ClickHouse/pull/83302) ([Alexander Tokmakov](https://github.com/tavplubix)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Исправление ошибки (некорректное поведение, заметное пользователю, в официальном стабильном релизе)
</div>

* Бэкпортировано в [#83256](https://github.com/ClickHouse/ClickHouse/issues/83256): Исправлено отключение выравнивания по границам для кэшированного буфера в движках внешних таблиц. Эта функциональность была сломана в [https://github.com/ClickHouse/ClickHouse/pull/81868](https://github.com/ClickHouse/ClickHouse/pull/81868). [#82493](https://github.com/ClickHouse/ClickHouse/pull/82493) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Бэкпортировано в [#82913](https://github.com/ClickHouse/ClickHouse/issues/82913): В AzureBlobStorage при нативном копировании сравниваются методы аутентификации; если при этом возникает исключение, код теперь переключается на чтение и копирование (то есть на ненативное копирование). [#82693](https://github.com/ClickHouse/ClickHouse/pull/82693) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Бэкпортировано в [#83112](https://github.com/ClickHouse/ClickHouse/issues/83112): Исправлена устойчивость к исключениям в rewrite `union/intersect/except&#95;default&#95;mode`. Закрывает [#82664](https://github.com/ClickHouse/ClickHouse/issues/82664). [#82820](https://github.com/ClickHouse/ClickHouse/pull/82820) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#83289](https://github.com/ClickHouse/ClickHouse/issues/83289): Установлена соль для данных аутентификации при разборе из AST с типом SCRAM&#95;SHA256&#95;PASSWORD. [#82888](https://github.com/ClickHouse/ClickHouse/pull/82888) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Бэкпортировано в [#83027](https://github.com/ClickHouse/ClickHouse/issues/83027): Исправлено изменение фильтра для запросов с выражением JOIN с таблицей на хранилище `Merge`. Исправляет [#82092](https://github.com/ClickHouse/ClickHouse/issues/82092). [#82950](https://github.com/ClickHouse/ClickHouse/pull/82950) ([Dmitry Novik](https://github.com/novikd)).
* Бэкпортировано в [#83311](https://github.com/ClickHouse/ClickHouse/issues/83311): Исправлен LOGICAL&#95;ERROR в QueryMetricLog: Mutex не может быть NULL. [#82979](https://github.com/ClickHouse/ClickHouse/pull/82979) ([Pablo Marcos](https://github.com/pamarcos)).
* Бэкпортировано в [#83240](https://github.com/ClickHouse/ClickHouse/issues/83240): Исправлена деградация производительности при включённом analyzer, когда вторичные запросы всегда читают все столбцы из VIEW. Исправляет [#81718](https://github.com/ClickHouse/ClickHouse/issues/81718). [#83036](https://github.com/ClickHouse/ClickHouse/pull/83036) ([Dmitry Novik](https://github.com/novikd)).
* Бэкпортировано в [#83173](https://github.com/ClickHouse/ClickHouse/issues/83173): Исправлено вводящее в заблуждение сообщение об ошибке при восстановлении резервной копии на диске только для чтения. [#83051](https://github.com/ClickHouse/ClickHouse/pull/83051) ([Julia Kartseva](https://github.com/jkartseva)).
* Бэкпортировано в [#83142](https://github.com/ClickHouse/ClickHouse/issues/83142): Не использовать несвязанные части разделяемого словаря в функции `lowCardinalityKeys`. [#83118](https://github.com/ClickHouse/ClickHouse/pull/83118) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Бэкпортировано в [#83404](https://github.com/ClickHouse/ClickHouse/issues/83404): Исправлен `no_sign_request` для клиента S3. Его можно использовать, чтобы явно отключить подпись запросов S3. Его также можно задавать для конкретных конечных точек с помощью настроек для конечных точек. [#83379](https://github.com/ClickHouse/ClickHouse/pull/83379) ([Antonio Andelic](https://github.com/antonio2368)).
* Бэкпорт в [#83722](https://github.com/ClickHouse/ClickHouse/issues/83722): Исправлен сбой, который может возникать при выполнении запроса с настройкой &#39;max&#95;threads=1&#39; под нагрузкой при включенном планировании CPU. [#83387](https://github.com/ClickHouse/ClickHouse/pull/83387) ([Fan Ziqi](https://github.com/f2quantum)).
* Бэкпорт в [#83452](https://github.com/ClickHouse/ClickHouse/issues/83452): Исправлено исключение `TOO_DEEP_SUBQUERIES`, возникающее, когда определение CTE ссылается на другое табличное выражение с тем же именем. * Бэкпорт в [#83662](https://github.com/ClickHouse/ClickHouse/issues/83662): `INSERT SELECT` с `UNION ALL` в редком случае мог приводить к разыменованию нулевого указателя.
