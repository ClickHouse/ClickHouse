Подключается к серверу ClickHouse и многократно выполняет указанные запросы.

**Синтаксис**

```bash
$ clickhouse-benchmark --query ["single query"] [keys]
```

или

```bash
$ echo "single query" | clickhouse-benchmark [keys]
```

или

```bash
$ clickhouse-benchmark [keys] <<< "single query"
```

Если вы хотите отправить набор запросов, создайте текстовый файл и поместите каждый запрос в отдельную строку этого файла. Например:

```sql
SELECT * FROM system.numbers LIMIT 10000000;
SELECT 1;
```

Затем передайте этот файл на стандартный ввод `clickhouse-benchmark`:

```bash
clickhouse-benchmark [keys] < queries_file;
```

## Параметры командной строки {#clickhouse-benchmark-command-line-options}

* `--query=QUERY` — Запрос для выполнения. Если этот параметр не указан, `clickhouse-benchmark` будет читать запросы из стандартного ввода.
* `--query_id=ID` — Query id.
* `--query_id_prefix=ID_PREFIX` — Префикс Query id.
* `--queries-format=FORMAT` — Формат запросов, считываемых из стандартного ввода. Возможные значения: `tsv` (по умолчанию, по одному запросу с экранированной табуляцией в строке) и `script` (разбирать ввод как сценарий из нескольких запросов, разделённых точкой с запятой). Ограничение `script`: запросы `INSERT ... FORMAT` должны находиться на одной строке.
* `-c N`, `--concurrency=N` — Количество запросов, которые `clickhouse-benchmark` отправляет одновременно. Значение по умолчанию: 1.
* `-C N`, `--max_concurrency=N` — Постепенно увеличивает количество параллельных запросов до указанного значения, формируя отдельный отчёт для каждого уровня параллелизма.
* `--precise` — Включает точную отчётность по интервалам со взвешенными метриками.
* `-d N`, `--delay=N` — Интервал в секундах между промежуточными отчётами (чтобы отключить отчёты, установите 0). Значение по умолчанию: 1.
* `-h HOST`, `--host=HOST` — Хост сервера. Значение по умолчанию: `localhost`. Для [режима сравнения](#clickhouse-benchmark-comparison-mode) можно использовать несколько ключей `-h`.
* `-i N`, `--iterations=N` — Общее количество запросов. Значение по умолчанию: 0 (повторять бесконечно).
* `-r`, `--randomize` — Выполнять запросы в случайном порядке, если входных запросов больше одного.
* `--arrival-rate=R` — Включает [режим открытого цикла](#clickhouse-benchmark-open-loop-mode): запросы поступают в случайные моменты времени со средней интенсивностью `R` запросов в секунду. Список интенсивностей через запятую, например `--arrival-rate=5,10,20`, запускает бенчмарк поочерёдно для каждой интенсивности и формирует по отдельному отчёту для каждой из них; для этого требуется `--iterations` или `--timelimit`.
* `--max-in-flight=N` — Максимальное количество одновременно выполняемых запросов в режиме открытого цикла. Значение по умолчанию: 256.
* `--seed=N` — Начальное значение генератора случайных чисел для моментов поступления запросов, порядка запросов при `--randomize` и выбора сервера в режиме открытого цикла. При одинаковых начальном значении и параметрах воспроизводится тот же запуск. Моменты поступления зависят только от начального значения и интенсивности, но не от запросов или серверов, поэтому разные наборы запросов или серверы можно сравнивать при одном и том же расписании поступления. По умолчанию: случайное начальное значение, которое выводится при запуске в режиме открытого цикла.
* `--per-query` — Выводит в конце статистику по каждому запросу: количество запросов и ошибок, QPS, перцентили задержки, максимальную задержку и среднее процессорное время запроса на сервере.
* `-s`, `--secure` — Использовать соединение `TLS`.
* `-t N`, `--timelimit=N` — Ограничение по времени в секундах. `clickhouse-benchmark` прекращает отправку запросов по достижении указанного лимита. Значение по умолчанию: 0 (ограничение отключено).
* `--port=N` — Порт сервера. Значение по умолчанию: 9000. Для [режима сравнения](#clickhouse-benchmark-comparison-mode) можно использовать несколько ключей `--port`.
* `--confidence=N` — Уровень доверия для T-теста. Возможные значения: 0 (80%), 1 (90%), 2 (95%), 3 (98%), 4 (99%), 5 (99.5%). Значение по умолчанию: 5. В [режиме сравнения](#clickhouse-benchmark-comparison-mode) `clickhouse-benchmark` выполняет [Independent two-sample Student&#39;s t-test](https://en.wikipedia.org/wiki/Student%27s_t-test#Independent_two-sample_t-test), чтобы определить, различаются ли два распределения при выбранном уровне доверия.
* `--cumulative` — Выводить накопленные данные вместо данных по интервалам.
* `--database=DATABASE_NAME` — Имя базы данных ClickHouse. Значение по умолчанию: `default`.
* `--user=USERNAME` — Имя пользователя ClickHouse. Значение по умолчанию: `default`.
* `--password=PSWD` — Пароль пользователя ClickHouse. Значение по умолчанию: пустая строка.
* `--stacktrace` — Вывод трассировок стека. Если ключ указан, `clickhouse-benchmark` выводит трассировки стека исключений.
* `--stage=WORD` — Этап обработки запроса на сервере. ClickHouse останавливает обработку запроса на указанном этапе и возвращает ответ в `clickhouse-benchmark`. Возможные значения: `complete`, `fetch_columns`, `with_mergeable_state`. Значение по умолчанию: `complete`.
* `--roundrobin` — Вместо сравнения запросов для разных `--host`/`--port` выбирает случайный `--host`/`--port` для каждого запроса и отправляет запрос туда.
* `--reconnect=N` — Управляет поведением при переподключении. Возможные значения: 0 (никогда не переподключаться), 1 (переподключаться для каждого запроса) или N (переподключаться после каждых N запросов). Значение по умолчанию: 0.
* `--max-consecutive-errors=N` — Количество допустимых последовательных ошибок. Значение по умолчанию: 0.
* `--ignore-error`,`--continue_on_errors` — Продолжать тестирование, даже если запросы завершились ошибкой.
* `--client-side-time` — Показывать время с учётом сетевого взаимодействия вместо времени на стороне сервера; обратите внимание, что для версий сервера до 22.8 мы всегда показываем время на стороне клиента.
* `--proto-caps` — Включить/отключить разбиение на фрагменты при передаче данных. Варианты (можно перечислять через запятую): `chunked_optional`, `notchunked`, `notchunked_optional`, `send_chunked`, `send_chunked_optional`, `send_notchunked`, `send_notchunked_optional`, `recv_chunked`, `recv_chunked_optional`, `recv_notchunked`, `recv_notchunked_optional`. Значение по умолчанию: `notchunked`.
* `--help` — Показывает справочное сообщение.
* `--verbose` — Увеличивает подробность справочного сообщения.

Если вы хотите применить к запросам некоторые [настройки](/ru/concepts/features/configuration/settings/overview), передайте их в виде ключа `--<session setting name>= SETTING_VALUE`. Например, `--max_memory_usage=1048576`.

## Параметры переменных окружения {#clickhouse-benchmark-environment-variable-options}

Имя пользователя, пароль и хост можно задать через переменные окружения `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD` и `CLICKHOUSE_HOST`.
Аргументы командной строки `--user`, `--password` и `--host` имеют приоритет над переменными окружения.

## Режим открытого цикла {#clickhouse-benchmark-open-loop-mode}

По умолчанию `clickhouse-benchmark` работает в замкнутом цикле: каждый из `--concurrency` клиентов отправляет следующий запрос, как только получен ответ на предыдущий. Если сервер замедляется, он получает меньше запросов, и нагрузка подстраивается под сервер.

С параметром `--arrival-rate` нагрузка не зависит от сервера. Запросы поступают в случайные моменты времени с фиксированной средней интенсивностью, как запросы от множества независимых пользователей: интервал между двумя поступлениями — случайная величина с экспоненциальным распределением и средним арифметическим `1 / R` (пуассоновский процесс). Каждый запрос отправляется в момент поступления, даже если предыдущие запросы ещё выполняются.

Одновременно выполняется не более `--max-in-flight` запросов. Если в момент поступления все они заняты, запрос ожидает в очереди на стороне клиента, пока один из них не завершится. Задержка запроса измеряется так же, как в замкнутом цикле (см. `--client-side-time`), поэтому время ожидания в очереди в неё не входит. Количество запросов, попавших в очередь, выводится отдельно.

Параметр `--iterations` задаёт количество поступлений; `clickhouse-benchmark` дожидается завершения их всех. Параметр `--timelimit` прекращает поступление запросов по истечении лимита времени; запросы в обработке выполняются до конца, а запросы, оставшиеся в очереди, отмечаются в отчёте как неотправленные.

Отчёт содержит ещё две строки, например:

```text
Arrivals: 1061, target rate: 100.000/s, achieved rate: 106.100/s, queued: 0 (max queue size 0).
In flight: mean 0.223, max 4 of 256.
```

* `Arrivals`: количество поступлений.
* `target rate`: интенсивность, заданная параметром `--arrival-rate`.
* `achieved rate`: количество поступлений, делённое на длительность процесса поступлений. Отличается от целевой интенсивности на случайную погрешность, которая уменьшается при более длительных запусках.
* `queued`: количество поступлений, при которых все слоты `--max-in-flight` были заняты и запросу пришлось ждать в очереди на стороне клиента (client-side), а также максимальная длина этой очереди.
* `not sent`: количество поступлений, которые ещё оставались в очереди на момент остановки запуска. Отображается, только если значение не равно нулю.
* `In flight`: взвешенное по времени среднее арифметическое и максимум числа одновременно выполняющихся запросов.

При поступлениях в режиме открытого цикла QPS повторяет интенсивность поступлений, поэтому мало что говорит о том, во что обходится нагрузка. В режиме открытого цикла строка состояния каждого сервера также содержит:

* `CPU`: процессорное время запросов на сервере за секунду, в ядрах.
* `CPU per query`: среднее процессорное время одного запроса на сервере, в секундах.

Оба значения учитывают запросы, завершившиеся ошибкой во время выполнения (при `--ignore-error`), поскольку они тоже нагружают сервер.

Процессорное время вычисляется как сумма событий профилирования `UserTimeMicroseconds` и `SystemTimeMicroseconds`, которые сервер отправляет для каждого запроса. Поэтому оно учитывает потоки, выполняющие запрос, и даёт приближённую оценку его общей стоимости по CPU. Для распределённого запроса значение суммируется по всем серверам, на которых выполняется запрос, поскольку initiator пересылает события профилирования удалённых серверов. Если сервер не отправляет события профилирования (например, при `--send_profile_events=0`), в строке состояния выводится `CPU: not reported by the server`.

Чтобы создать смешанную рабочую нагрузку, запустите одновременно несколько процессов `clickhouse-benchmark` — по одному на каждый класс запросов. Каждый процесс выводит статистику своего класса. Задайте каждому процессу собственный `--seed` или не задавайте его вовсе: процессы с одинаковым seed генерируют одну и ту же случайную последовательность, поэтому их поступления совпадают (или, при разной интенсивности, являются масштабированными копиями друг друга). При независимых значениях seed комбинированные поступления всех процессов также образуют пуассоновский процесс.

Примеры:

```bash
# 100 queries per second for 10 seconds; the lines above are from this run.
$ clickhouse-benchmark --arrival-rate=100 --seed=42 --timelimit=10 --query "SELECT sum(number) FROM numbers(1000000)"

# A sweep over four rates, 60 seconds each, with per-query statistics.
$ clickhouse-benchmark --arrival-rate=5,10,20,40 --timelimit=60 --randomize --per-query < queries.tsv
```

## Режим сравнения {#clickhouse-benchmark-comparison-mode}

`clickhouse-benchmark` может сравнивать производительность двух работающих серверов ClickHouse.

Чтобы использовать режим сравнения, укажите конечные точки обоих серверов, задав две пары ключей `--host`, `--port`. Ключи сопоставляются по позиции в списке аргументов: первый `--host` — с первым `--port` и так далее. `clickhouse-benchmark` устанавливает соединения с обоими серверами, а затем отправляет запросы. Каждый запрос направляется на случайно выбранный сервер. Результаты отображаются в таблице.
