## Введение {#grpc-interface-introduction}

ClickHouse поддерживает интерфейс [gRPC](https://grpc.io/). Это система удалённого вызова процедур с открытым исходным кодом, использующая HTTP/2 и [Protocol Buffers](https://en.wikipedia.org/wiki/Protocol_Buffers). Реализация gRPC в ClickHouse поддерживает:

* SSL;
* аутентификацию;
* сеансы;
* сжатие;
* параллельные запросы через один канал;
* отмену запросов;
* получение информации о ходе выполнения и журналов;
* внешние таблицы.

Спецификация интерфейса описана в файле [clickhouse&#95;grpc.proto](https://github.com/ClickHouse/ClickHouse/blob/master/src/Server/grpc_protos/clickhouse_grpc.proto).

## Конфигурация gRPC {#grpc-interface-configuration}

Чтобы использовать gRPC-интерфейс, задайте параметр `grpc_port` в основной [конфигурации сервера](/ru/concepts/features/configuration/server-config/configuration-files). Остальные параметры конфигурации приведены в следующем примере:

```xml
<grpc_port>9100</grpc_port>
    <grpc>
        <enable_ssl>false</enable_ssl>

        <!-- The following two files are used only if SSL is enabled -->
        <ssl_cert_file>/path/to/ssl_cert_file</ssl_cert_file>
        <ssl_key_file>/path/to/ssl_key_file</ssl_key_file>

        <!-- Whether server requests client for a certificate -->
        <ssl_require_client_auth>false</ssl_require_client_auth>

        <!-- The following file is used only if ssl_require_client_auth=true -->
        <ssl_ca_cert_file>/path/to/ssl_ca_cert_file</ssl_ca_cert_file>

        <!-- Default compression algorithm (applied if client doesn't specify another algorithm, see result_compression in QueryInfo).
             Supported algorithms: none, deflate, gzip, stream_gzip -->
        <compression>deflate</compression>

        <!-- Default compression level (applied if client doesn't specify another level, see result_compression in QueryInfo).
             Supported levels: none, low, medium, high -->
        <compression_level>medium</compression_level>

        <!-- Send/receive message size limits in bytes. -1 means unlimited -->
        <max_send_message_size>-1</max_send_message_size>
        <max_receive_message_size>-1</max_receive_message_size>
    </grpc>
```

## Аутентификация {#grpc-authentication}

Запрос аутентифицируется по полям `user_name` и `password` структуры `QueryInfo` (поле `quota` задаёт ключ квоты). Поле `user_name` необязательно: если оно пустое, запрос аутентифицируется от имени пользователя, указанного в [настройке сервера](/ru/reference/settings/server-settings/settings) `default_session_user` (если не настроено иное, это `default`), с переданным паролем, который может быть пустым, — точно так же, как HTTP-запрос без параметра `user`. Пустое имя пользователя — лишь псевдоним этого пользователя: его пароль, `networks` и другие проверки доступа применяются как обычно, поэтому будет ли принят запрос без учётных данных, определяется конфигурацией этого пользователя. Если для `default_session_user` задана пустая строка, запросы без `user_name` отклоняются, а если в конфигурации сервера включён раздел `session_log`, отказ записывается в [`system.session_log`](/ru/reference/system-tables/session_log) как событие `LoginFailure` с пустым `user`.

## Встроенный клиент {#grpc-client}

Вы можете написать клиент на любом языке программирования, поддерживаемом gRPC, используя предоставленную [спецификацию](https://github.com/ClickHouse/ClickHouse/blob/master/src/Server/grpc_protos/clickhouse_grpc.proto).
Также можно воспользоваться встроенным клиентом Python. Он находится в репозитории по пути [utils/grpc-client/clickhouse-grpc-client.py](https://github.com/ClickHouse/ClickHouse/blob/master/utils/grpc-client/clickhouse-grpc-client.py). Для работы встроенного клиента требуются модули Python [grpcio и grpcio-tools](https://grpc.io/docs/languages/python/quickstart).

Клиент поддерживает следующие аргументы:

* `--help` — выводит справку и завершает работу.
* `--host HOST, -h HOST` — имя сервера. Значение по умолчанию: `localhost`. Также можно указать IPv4- или IPv6-адрес.
* `--port PORT` — порт для подключения. Этот порт должен быть включен в конфигурации сервера ClickHouse (см. `grpc_port`). Значение по умолчанию: `9100`.
* `--user USER_NAME, -u USER_NAME` — имя пользователя. Значение по умолчанию: `default`.
* `--password PASSWORD` — пароль. Значение по умолчанию: пустая строка.
* `--query QUERY, -q QUERY` — запрос, выполняемый в неинтерактивном режиме.
* `--database DATABASE, -d DATABASE` — база данных по умолчанию. Если не указана, используется текущая база данных, заданная в настройках сервера (по умолчанию `default`).
* `--format OUTPUT_FORMAT, -f OUTPUT_FORMAT` — [формат](/ru/reference/formats/index) вывода результата. Значение по умолчанию для интерактивного режима: `PrettyCompact`.
* `--debug` — включает вывод отладочной информации.

Чтобы запустить клиент в интерактивном режиме, вызовите его без аргумента `--query`.

В пакетном режиме данные запроса можно передать через `stdin`.

**Пример использования клиента**

В следующем примере создается таблица, в которую загружаются данные из CSV-файла, после чего выполняется запрос к ее содержимому.

```bash title="Query"
./clickhouse-grpc-client.py -q "CREATE TABLE grpc_example_table (id UInt32, text String) ENGINE = MergeTree() ORDER BY id;"
echo -e "0,Input data for\n1,gRPC protocol example" > a.csv
cat a.csv | ./clickhouse-grpc-client.py -q "INSERT INTO grpc_example_table FORMAT CSV"

./clickhouse-grpc-client.py --format PrettyCompact -q "SELECT * FROM grpc_example_table;"
```

```text title="Response"
┌─id─┬─text──────────────────┐
│  0 │ Input data for        │
│  1 │ gRPC protocol example │
└────┴───────────────────────┘
```
