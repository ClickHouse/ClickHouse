Встроенный веб-интерфейс SQL (`play.html`, доступный по пути [`/play`](/ru/concepts/features/connect-to-clickhouse/protocols/http) на любом HTTP-порту ClickHouse) может раскрашивать ячейки результата, чтобы закономерности в столбце было легко заметить с первого взгляда. Для каждого столбца задаётся собственный режим цветового кодирования, который переключается независимо от остальных.

## Переключение режима {#switching-the-mode}

Справа в заголовке каждого столбца отображается значок 🌈. Нажимайте на него, чтобы последовательно переключать режимы отображения столбца. На устройствах с поддержкой наведения указателя (например, с мышью) значок виден только при наведении на заголовок, а в остальное время скрыт, чтобы не мешать. На сенсорных и других устройствах с низкой точностью указателя, где наведение недоступно, значок виден всегда, и на него можно сразу нажать.

Набор доступных режимов столбца зависит от его типа:

* Для числовых столбцов и столбцов типов `Date`/`DateTime`/`Date32`/`DateTime64` режимы переключаются в следующем порядке: `bar` → `heatmap` → `categorical` → `none`.
* Для всех остальных столбцов доступны два режима: `none` и `categorical`.

По умолчанию для числовых столбцов используется режим `bar`, а для всех остальных, включая столбцы даты и времени, — `none`.

## Режимы {#modes}

* **`bar`** — рисует в ячейке горизонтальную полосу, длина которой пропорциональна значению. Для числовых столбцов полоса откладывается от нулевого базового значения, а для столбцов `Date`/`DateTime` она охватывает диапазон `min`..`max` столбца, поскольку нулевое базовое значение для временных меток не имеет смысла.
* **`heatmap`** — заливает весь фон ячейки цветом, кодирующим значение, масштабированное между минимумом и максимумом столбца.
* **`categorical`** — заливает фон ячейки цветом, полученным из хеша значения ячейки, поэтому одинаковые значения окрашиваются одинаково, а разные — в разные цвета. Подходит для столбцов любого типа.
* **`none`** — без цветового кодирования.

Столбцы `Date`, `DateTime`, `Date32` и `DateTime64` окрашиваются по значению времени, разобранному в UTC, поэтому шкала не зависит от часового пояса браузера пользователя.

Для цветов фона в режимах `heatmap` и `categorical` используется цветовое пространство `oklch`: меняется только цветовой тон, а светлота и цветность для каждой темы фиксированы, поэтому текст в ячейке остаётся читаемым как в светлой, так и в тёмной теме. Фон заполняет всю ячейку, даже если строка занимает несколько линий.

## Выделение совпадающих значений в категориальном режиме {#categorical-emphasis}

В режиме `categorical` при выборе ячейки остальные ячейки с тем же значением выделяются более жирным шрифтом и максимально контрастным цветом текста (чисто белым в тёмной теме, чисто чёрным в светлой). Сама выбранная ячейка остаётся без выделения. Это позволяет легко увидеть, где ещё в столбце встречается это значение.

## Сохранение данных {#persistence}

Выбранные режимы для каждого столбца сохраняются в URL страницы и истории браузера, поэтому не сбрасываются при перезагрузке страницы, передаче ссылки и переходах назад и вперёд. Сохраняются только настройки, отличающиеся от значений по умолчанию, чтобы URL и состояние истории оставались компактными.

Как и [закреплённые столбцы](/ru/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/pinned-columns), режимы привязаны к результату, для которого задают окраску: к вкладке запроса, а внутри вкладки с [блокнотом](/ru/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/notebook) — к отдельной ячейке. Таблицы, полученные при одном запуске `Run all` (выполнении нескольких запросов), используют общие режимы, а остальные ячейки и вкладки — собственные.

## Ограничения {#limitations}

* В вертикальной (транспонированной) структуре для одной строки цветовое кодирование не отображается.
* Различия между значениями `DateTime64(9)` меньше микросекунды не учитываются в цветовой шкале, поскольку для градиента они не имеют визуального смысла.
