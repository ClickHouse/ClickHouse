Страница поиска по документации — это небольшой автономный веб-интерфейс для мгновенного поиска по встроенной справочной документации. Она доступна на любом HTTP-порту ClickHouse по пути `/docs`.

Чтобы открыть её, перейдите по адресу с путём `/docs` на любом HTTP-порту ClickHouse (например, `http://localhost:8123/docs`).

## Как это работает {#what-it-does}

По мере ввода текста страница запрашивает таблицу [`system.documentation`](/ru/reference/system-tables/documentation) по HTTP и отображает документацию выбранной сущности в формате Markdown. Поскольку данные берутся из `system.documentation`, страница охватывает все сущности, представленные в этой таблице: функции, агрегатные функции, табличные функции, движки таблиц, движки баз данных, типы данных, настройки, форматы, кодеки сжатия, события профилирования, метрики, сами системные таблицы и многое другое. При этом содержимое всегда соответствует документации, встроенной в работающий сервер.

Введите текст в поле поиска — совпадения появятся в списке с цветовой маркировкой по типу сущности; при выборе совпадения отобразится соответствующая документация. При отображении поддерживаются:

* ссылка со значком карандаша рядом с заголовком сущности, открывающая её исходный файл на GitHub; адрес берётся из столбца `source` таблицы `system.documentation`;
* подсветка синтаксиса ClickHouse SQL в блоках кода с использованием того же встроенного лексического анализатора (`Lexer.wasm`), что и в интерфейсе [`/play`](/ru/concepts/features/connect-to-clickhouse/protocols/http);
* математические формулы TeX с помощью [KaTeX](https://katex.org/) (например, формула на странице `corr`);
* блоки примечаний и советов `:::note`/`:::tip`/…, якоря заголовков со ссылками, которыми можно поделиться, и кнопка «Копировать», появляющаяся при наведении на блок кода;
* относительные ссылки, которые разрешаются в ссылки на другие сущности с документацией внутри приложения, если такие сущности существуют, а в противном случае — на `https://clickhouse.com/docs`; ссылки «См. также» и «Псевдоним для» ведут на страницы внутри приложения.

Текущий поисковый запрос, открытая сущность и раздел отражаются во фрагменте URL. Это позволяет ссылаться напрямую на конкретную страницу или раздел и восстанавливать это состояние при переходах назад и вперёд в браузере. Переключатель светлой и тёмной темы (с автоматическим определением) работает так же, как в `/play`.

## Подключение {#connecting}

В верхней части страницы расположены поля `URL`, `user` и `password`, как и в `/play`. Если страницу отдаёт ClickHouse, в качестве `URL` по умолчанию используется текущий источник (origin). Если страница открыта как локальный файл, по умолчанию используется `http://localhost:8123/`. Таким образом, страницу можно открыть локально и работать с удалённым сервером. Кэш имён перекрёстных ссылок автоматически перестраивается при изменении соединения.

## Статические ресурсы {#assets}

Все статические ресурсы — включая средство отображения Markdown ([Marked](https://marked.js.org/)), средство отображения математических формул (KaTeX вместе со шрифтами) и лексический анализатор SQL — отдаются непосредственно из бинарного файла ClickHouse при загрузке страницы по HTTP. В контексте HTTP-источника ClickHouse не загружаются ресурсы из сторонних CDN, поэтому страница автономна, работает без подключения к сети и не выполняет сторонний код из сети в том же контексте, в котором обрабатывает учётные данные.

## Вопросы безопасности {#security}

Страница отправляет запросы к HTTP-конечной точке ClickHouse с учётными данными, указанными в заголовке, поэтому здесь действуют те же оговорки, что и для HTTP-протокола:

* В недоверенных средах всегда отдавайте `/docs` по HTTPS, чтобы защитить учётные данные.
* Ограничивайте доступ на сетевом уровне (межсетевой экран, обратный прокси или конфигурация `listen_host`) так же, как вы ограничиваете доступ к HTTP-протоколу.

`system.documentation` содержит только статическую справочную документацию, встроенную в сервер, поэтому страница не раскрывает никаких данных из ваших таблиц.
