ClickHouse предоставляет нативный клиент командной строки для выполнения SQL-запросов непосредственно на сервере ClickHouse.
Он поддерживает как интерактивный режим (для выполнения запросов в реальном времени), так и пакетный режим (для скриптов и автоматизации).
Результаты запроса можно выводить в терминал или экспортировать в файл в любом из выходных [форматов](/ru/reference/formats/index) ClickHouse, например Pretty, CSV, JSON и других.

Во время выполнения запроса клиент в реальном времени показывает индикатор прогресса, количество прочитанных строк, объём обработанных байтов и время выполнения запроса.
Клиент поддерживает как [параметры командной строки](#command-line-options), так и [файлы конфигурации](#configuration_files).

## Установка {#install}

Чтобы скачать ClickHouse, выполните:

```bash
curl https://clickhouse.com/ | sh
```

Чтобы установить и его, выполните:

```bash
sudo ./clickhouse install
```

Другие варианты установки см. в разделе [Установка ClickHouse](/ru/get-started/setup/install).

Клиент и сервер разных версий совместимы друг с другом, однако в более старых клиентах некоторые возможности могут быть недоступны. Рекомендуется использовать одну и ту же версию клиента и сервера.

## Запуск {#run}

<Note>
  Если вы только скачали ClickHouse, но не установили его, используйте `./clickhouse client` вместо `clickhouse-client`.
</Note>

Чтобы подключиться к серверу ClickHouse, выполните:

```bash
$ clickhouse-client --host server

ClickHouse client version 24.12.2.29 (official build).
Connecting to server:9000 as user default.
Connected to ClickHouse server version 24.12.2.

:)
```

При необходимости укажите дополнительные сведения о подключении:

| Параметр                         | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--port <port>`                  | Порт, на котором сервер ClickHouse принимает соединения. Порты по умолчанию: 9440 (TLS) и 9000 (без TLS). Если не указаны ни `--port`, ни `--secure`, клиент параллельно пробует подключиться к обоим портам по умолчанию и использует тот, который ответит первым. Благодаря этому подключение к серверу, который прослушивает только один из них, выполняется без ожидания тайм-аута подключения к другому. Обратите внимание, что клиент ClickHouse использует собственный протокол, а не HTTP(S). |
| `-s [ --secure ]`                | Использовать ли TLS (обычно определяется автоматически).                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `-u [ --user ] <username>`       | Пользователь базы данных, от имени которого выполняется подключение. По умолчанию используется пользователь `default`.                                                                                                                                                                                                                                                                                                                                                                                |
| `--password <password>`          | Пароль пользователя базы данных. Пароль для соединения также можно указать в файле конфигурации. Если пароль не указан, клиент запросит его.                                                                                                                                                                                                                                                                                                                                                          |
| `-c [ --config ] <path-to-file>` | Расположение файла конфигурации клиента ClickHouse, если он находится не в одном из расположений по умолчанию. См. [Конфигурационные файлы](#configuration_files).                                                                                                                                                                                                                                                                                                                                    |
| `--connection <name>`            | Имя набора предварительно настроенных сведений о подключении из [файла конфигурации](#connection-credentials).                                                                                                                                                                                                                                                                                                                                                                                        |

Полный список параметров командной строки см. в разделе [Параметры командной строки](#command-line-options).

### Хранение параметров подключения в файле конфигурации {#connection-credentials}

Сведения о подключении к одному или нескольким серверам ClickHouse можно хранить в [файле конфигурации](#configuration_files).

Формат выглядит так:

```xml
<config>
    <connections_credentials>
        <connection>
            <name>default</name>
            <hostname>hostname</hostname>
            <port>9440</port>
            <secure>1</secure>
            <user>default</user>
            <password>password</password>
            <!-- <history_file></history_file> -->
            <!-- <history_max_entries></history_max_entries> -->
            <!-- <accept-invalid-certificate>false</accept-invalid-certificate> -->
            <!-- <prompt></prompt> -->
        </connection>
    </connections_credentials>
</config>
```

Подробнее см. в [разделе о файлах конфигурации](#configuration_files).

<Note>
  Чтобы сосредоточиться на синтаксисе запросов, в остальных примерах сведения о подключении (`--host`, `--port` и т. д.) опущены. Не забудьте указать их при выполнении команд.
</Note>

## Интерактивный режим {#interactive-mode}

### Использование интерактивного режима {#using-interactive-mode}

Чтобы запустить ClickHouse в интерактивном режиме, достаточно выполнить:

```bash
clickhouse-client
```

Откроется цикл «чтение — вычисление — вывод» (REPL, Read-Eval-Print Loop), в котором можно вводить SQL-запросы в интерактивном режиме.
После подключения появится приглашение для ввода запросов:

```bash
ClickHouse client version 25.x.x.x
Connecting to localhost:9000 as user default.
Connected to ClickHouse server version 25.x.x.x

hostname :)
```

В интерактивном режиме формат вывода по умолчанию — `PrettyCompact`.
Изменить формат можно в предложении `FORMAT` запроса или с помощью параметра командной строки `--format`.
Чтобы использовать формат Vertical, укажите `--vertical` или добавьте `\G` в конце запроса.
В этом формате каждое значение выводится на отдельной строке, что удобно для широких таблиц.

В интерактивном режиме по умолчанию всё введённое выполняется при нажатии `Enter`.
Точка с запятой в конце запроса не обязательна.

Клиент можно запустить с параметром `-m, --multiline`.
Чтобы ввести многострочный запрос, поставьте обратную косую черту `\` перед переводом строки.
После нажатия `Enter` будет предложено ввести следующую строку запроса.
Чтобы выполнить запрос, завершите его точкой с запятой и нажмите `Enter`.

Клиент ClickHouse основан на `replxx` (аналог `readline`), поэтому поддерживает привычные сочетания клавиш и сохраняет историю.
По умолчанию история записывается в `~/.clickhouse-client-history`.

Чтобы выйти из клиента, нажмите `Ctrl+D` или введите вместо запроса одну из следующих команд:

* `exit` или `exit;`
* `quit` или `quit;`
* `q`, `Q` или `:q`
* `logout` или `logout;`

### Получение справки {#getting-help}

Документацию по любой функции, движку таблицы, типу данных, формату, настройке и другим компонентам системы можно просмотреть, не выходя из клиента. Введите `help` и затем имя (также поддерживаются эквивалентные формы `/help`, `man` и `/man`):

```text
help domainWithoutWWW
```

Поиск регистронезависимый и выполняется по таблице [`system.documentation`](/ru/reference/system-tables/documentation). Найденная документация преобразуется из Markdown и отображается в терминале с полужирным и курсивным текстом, таблицами и блоками кода с подсветкой синтаксиса. Если одно имя используется несколькими компонентами (например, `file` — это одновременно функция и движок таблицы), выводятся все они.

Если точного совпадения нет, клиент выводит список похожих имён (с учётом возможных опечаток) и компонентов, в документации которых упоминается это слово:

```text
help maxx_threads
```

Если ввести `help` без аргументов, будет выведена краткая справка по использованию.

### Команды {#slash-commands}

Некоторые команды с префиксом `/` клиент выполняет сам, не отправляя их на сервер:

| Команда                                               | Описание                                                                                                                  |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `/help <name>`, `/man <name>`                         | Показать документацию по `<name>` — аналогично `help` выше                                                                |
| `/clear`                                              | Очистить терминал                                                                                                         |
| `/dialect <name>`, `/lang <name>`, `/language <name>` | Переключить диалект SQL или, если команда введена без аргумента, вывести текущий (см. [ниже](#switching-the-sql-dialect)) |

Если ввести `/` в начале строки, список команд появится в виде [подсказок](#command-line-options-formatting), а по мере ввода имени он будет сужаться; `Tab` дополняет набираемую команду — так же команды дополняются и при отключённых подсказках. Отправленный отдельно символ `/` не является командой: как и в Oracle SQL*Plus, он повторяет последний ввод. Если имя команды набрано с ошибкой, клиент не выполняет ввод как запрос, а сообщает об ошибке и предлагает команды, которые, возможно, имелись в виду:

```text
:) /hepl

Exception on client:
Code: 36. DB::Exception: Unknown command `/hepl`. Maybe you meant: ['/help']. Type `/` at the beginning of the line to see all the commands. (BAD_ARGUMENTS)
```

### Переключение диалекта SQL {#switching-the-sql-dialect}

Клиент может разбирать запросы на нескольких диалектах (см. настройку [`dialect`](/ru/reference/settings/session-settings/other#dialect)). Чтобы переключить диалект, введите `/dialect` и имя диалекта (также поддерживаются эквивалентные формы `/language` и `/lang`):

```text
/dialect polyglot
```

Эта команда эквивалентна `SET dialect = 'polyglot'`, но, в отличие от запроса `SET`, её не нужно разбирать в текущем диалекте, поэтому она работает и тогда, когда текущий диалект не позволяет выразить такой запрос (например, в PromQL нет оператора `SET`). Если активен диалект, отличный от диалекта по умолчанию, он отображается в приглашении после отображаемого имени сервера:

```text
clickhouse-cloud (polyglot) :)
```

Пользовательское приглашение (см. параметр `--prompt`) не обязательно должно содержать плейсхолдер `{display_name}` — в таком случае диалект добавляется в конец приглашения.

Если ввести `/dialect` без аргументов, будет выведен текущий диалект.

Команда распознаётся только в интерактивном режиме: неинтерактивный скрипт целиком разбирается как SQL, а диалект для него задаётся параметром `--dialect` или оператором `SET dialect = ...`. Если весь текст запроса `clickhouse-local` состоит только из этой команды (например, `clickhouse-local -q '/dialect kusto'`), он отклоняется с сообщением о том, что команда доступна только в интерактивном режиме. Внутри более длинного скрипта команда вообще не распознаётся и разбирается как часть скрипта, как и любой другой текст.

### Информация об обработке запросов {#processing-info}

При обработке запроса клиент отображает:

1. Ход выполнения, который по умолчанию обновляется не чаще 10 раз в секунду.
   Для быстрых запросов ход выполнения может не успеть отобразиться.
2. Отформатированный запрос после разбора — для отладки.
3. Результат в указанном формате.
4. Количество строк в результате, затраченное время и среднюю скорость обработки запроса.
   Все объёмы указаны для несжатых данных.

Длительный запрос можно отменить, нажав `Ctrl+C`.
Однако придётся немного подождать, пока сервер прервёт выполнение запроса.
На некоторых стадиях отменить запрос невозможно.
Если не дожидаться и нажать `Ctrl+C` повторно, клиент завершит работу.

Клиент ClickHouse позволяет передавать внешние данные (внешние временные таблицы) для выполнения запросов.
Подробнее см. раздел [Внешние данные для обработки запросов](/ru/reference/engines/table-engines/special/external-data).

### Псевдонимы {#cli_aliases}

В REPL можно использовать следующие псевдонимы:

* `\l` — `SHOW DATABASES`
* `\d` — `SHOW TABLES`
* `\d <TABLE>` — `DESCRIBE TABLE <TABLE>`
* `\c <DATABASE>` — `USE <DATABASE>`
* `.` — повторить последний запрос

Если аргумент `\d` не задаёт имя таблицы, а продолжает запрос `SHOW TABLES` (например, `\d FROM system` или `\d LIKE 'hits%'`), команда по-прежнему выполняет получение списка таблиц. Если имя таблицы совпадает с названием одной из этих секций, его необходимо заключить в кавычки: `` \d `format` ``.

### Сочетания клавиш {#keyboard_shortcuts}

* `Alt (Option) + Shift + e` — открыть редактор с текущим запросом. Редактор можно задать с помощью переменной окружения `EDITOR`. По умолчанию используется `vim`.
* `Alt (Option) + #` — закомментировать строку.
* `Ctrl + r` — нечёткий поиск по истории.

Полный список доступных сочетаний клавиш приведён в [replxx](https://github.com/AmokHuginnsson/replxx/blob/1f149bf/src/replxx_impl.cxx#L262).

  Чтобы настроить корректную работу клавиши meta (Option) в macOS:

  iTerm2: перейдите в Preferences -&gt; Profile -&gt; Keys -&gt; Left Option key и выберите Esc+
</Tip>

### Режим Vim {#vim-mode}

Запустите клиент с параметром `--vim`, чтобы редактировать запросы с помощью клавиш в стиле `vim`.
Ввод начинается в режиме вставки; `Esc` переключает в обычный режим, в котором доступны перемещения (`h`, `j`, `k`, `l`, `w`, `b`, `e`, `0`, `$`, `f`, `t`, `%`, `gg`, `G`, ...), операторы (`d`, `c`) со счётчиками повторений, текстовые объекты (`iw`, `aw`, `i(`, `a(`, ...), а также такие команды, как `x`, `r`, `s`, `o`, `A`, `I`, `D`, `C`.
В режиме vim клавиша `Enter` в режиме вставки добавляет новую строку, а в обычном режиме переходит на следующую строку; чтобы отправить запрос, нажмите `Ctrl + j`.
В обычном режиме клавиша `v` открывает текущий запрос в редакторе (недоступно во встроенном клиенте).
Сочетания клавиш для поиска по истории (`Ctrl + r`, `Ctrl + s`, `Ctrl + t`, `Alt + r`) и `Alt + #` работают и в обычном режиме.

## Пакетный режим {#batch-mode}

### Использование пакетного режима {#using-batch-mode}

Вместо интерактивной работы с Клиентом ClickHouse можно запустить его в пакетном режиме.
В пакетном режиме ClickHouse выполняет один запрос и сразу завершает работу — без приглашения к вводу и цикла обработки команд.

Один запрос можно указать следующим образом:

```bash
$ clickhouse-client "SELECT sum(number) FROM numbers(10)"
45
```

Также можно использовать параметр командной строки `--query`:

```bash
$ clickhouse-client --query "SELECT uniq(number) FROM numbers(10)"
10
```

Запрос можно передать через `stdin`:

```bash
$ echo "SELECT avg(number) FROM numbers(10)" | clickhouse-client
4.5
```

Если таблица `messages` уже существует, вы также можете вставлять в неё данные из командной строки:

```bash
$ echo "Hello\nGoodbye" | clickhouse-client --query "INSERT INTO messages FORMAT CSV"
```

Если указан параметр `--query`, все входные данные добавляются в конец запроса после символа перевода строки.

### Вставка данных из CSV-файла в удалённый сервис ClickHouse {#cloud-example}

В этом примере данные из CSV-файла `cell_towers.csv` с тестовым набором данных вставляются в существующую таблицу `cell_towers` в базе данных `default`:

```bash
clickhouse-client --host HOSTNAME.clickhouse.cloud \
  --port 9440 \
  --user default \
  --password PASSWORD \
  --query "INSERT INTO cell_towers FORMAT CSVWithNames" \
  < cell_towers.csv
```

### Примеры вставки данных из командной строки {#more-examples}

Вставить данные из командной строки можно несколькими способами.
В примере ниже две строки данных в формате CSV вставляются в таблицу ClickHouse в пакетном режиме:

```bash
echo -ne "1, 'some text', '2016-08-14 00:00:00'\n2, 'some more text', '2016-08-14 00:00:01'" | \
  clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
```

В примере ниже `cat <<_EOF` открывает heredoc, который считывает всё содержимое, пока снова не встретит `_EOF`, а затем выводит его:

```bash
cat <<_EOF | clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
3, 'some text', '2016-08-14 00:00:00'
4, 'some more text', '2016-08-14 00:00:01'
_EOF
```

В примере ниже содержимое file.csv выводится в stdout с помощью `cat` и через конвейер передаётся на вход `clickhouse-client`:

```bash
cat file.csv | clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
```

В пакетном режиме по умолчанию используется [формат](/ru/reference/formats/index) данных `TabSeparated`.
Формат можно задать в предложении `FORMAT` запроса, как показано в примере выше.

## Запросы с параметрами {#cli-queries-with-parameters}

Вы можете задать параметры в запросе и передать их значения через параметры командной строки.
Это избавляет от необходимости форматировать запрос с конкретными динамическими значениями на стороне клиента.
Например:

```bash
$ clickhouse-client --param_parName="[1, 2]" --query "SELECT {parName: Array(UInt16)}"
[1,2]
```

Параметры также можно задать прямо в [интерактивном сеансе](#interactive-mode):

```text highlight={4,14}
$ clickhouse-client
ClickHouse client version 25.X.X.XXX (official build).

:) SET param_parName='[1, 2]';

SET param_parName = '[1, 2]'

Query id: 7ac1f84e-e89a-4eeb-a4bb-d24b8f9fd977

Ok.

0 rows in set. Elapsed: 0.000 sec.

:) SELECT {parName:Array(UInt16)}

SELECT {parName:Array(UInt16)}

Query id: 0358a729-7bbe-4191-bb48-29b063c548a7

   ┌─_CAST([1, 2]⋯y(UInt16)')─┐
1. │ [1,2]                    │
   └──────────────────────────┘

1 row in set. Elapsed: 0.006 sec.
```

### Синтаксис запроса {#cli-queries-with-parameters-syntax}

В запросе укажите значения, которые нужно подставить с помощью параметров командной строки, в фигурных скобках в следующем формате:

```sql
{<name>:<data type>}
```

| Параметр    | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`      | Идентификатор плейсхолдера. Соответствующий параметр командной строки — `--param_<name> = value`.                                                                                                                                                                                                                                                                                                                                                       |
| `data type` | [Тип данных](/ru/reference/data-types/index) параметра. <br /><br />Например, структура данных вида `(integer, ('string', integer))` может иметь тип данных `Tuple(UInt8, Tuple(String, UInt8))` (можно также использовать другие [целочисленные](/ru/reference/data-types/int-uint) типы). <br /><br />Имя таблицы, имя базы данных и имена столбцов также можно передавать как параметры — в этом случае в качестве типа данных нужно указать `Identifier`. |

### Примеры {#cli-queries-with-parameters-examples}

```bash
$ clickhouse-client --param_tuple_in_tuple="(10, ('dt', 10))" \
    --query "SELECT * FROM table WHERE val = {tuple_in_tuple:Tuple(UInt8, Tuple(String, UInt8))}"

$ clickhouse-client --param_tbl="numbers" --param_db="system" --param_col="number" --param_alias="top_ten" \
    --query "SELECT {col:Identifier} as {alias:Identifier} FROM {db:Identifier}.{tbl:Identifier} LIMIT 10"
```

## Генерация SQL с помощью ИИ {#ai-sql-generation}

Клиент ClickHouse позволяет генерировать SQL-запросы по описаниям на естественном языке благодаря встроенной поддержке ИИ. Эта возможность помогает пользователям писать сложные запросы без глубоких знаний SQL.

Помощь ИИ доступна без дополнительной настройки, если задана переменная окружения `OPENAI_API_KEY` или `ANTHROPIC_API_KEY`. Расширенные настройки описаны в разделе [Configuration](#ai-sql-generation-configuration).

### Использование {#ai-sql-generation-usage}

Чтобы воспользоваться генерацией SQL с помощью ИИ, добавьте `??` в начало запроса на естественном языке:

```bash
:) ?? show all users who made purchases in the last 30 days
```

ИИ выполнит следующие действия:

1. Автоматически изучит схему вашей базы данных
2. Сгенерирует подходящий SQL-запрос на основе обнаруженных таблиц и столбцов
3. Сразу выполнит сгенерированный запрос

### Пример {#ai-sql-generation-example}

```bash
:) ?? count orders by product category

Starting AI SQL generation with schema discovery...
──────────────────────────────────────────────────

🔍 list_databases
   ➜ system, default, sales_db

🔍 list_tables_in_database
   database: sales_db
   ➜ orders, products, categories

🔍 get_schema_for_table
   database: sales_db
   table: orders
   ➜ CREATE TABLE orders (order_id UInt64, product_id UInt64, quantity UInt32, ...)

✨ SQL query generated successfully!
──────────────────────────────────────────────────

SELECT
    c.name AS category,
    COUNT(DISTINCT o.order_id) AS order_count
FROM sales_db.orders o
JOIN sales_db.products p ON o.product_id = p.product_id
JOIN sales_db.categories c ON p.category_id = c.category_id
GROUP BY c.name
ORDER BY order_count DESC
```

### Configuration {#ai-sql-generation-configuration}

Для генерации SQL с помощью ИИ необходимо настроить провайдера ИИ в файле конфигурации клиента ClickHouse. Можно использовать OpenAI, Anthropic или любой сервис с API, совместимым с OpenAI.

#### Переход на резервный вариант: переменные окружения {#ai-sql-generation-fallback}

Если в файле конфигурации не задана конфигурация AI, клиент ClickHouse автоматически попытается использовать переменные окружения:

1. Сначала проверяется переменная окружения `OPENAI_API_KEY`
2. Если она не найдена, проверяется переменная окружения `ANTHROPIC_API_KEY`
3. Если не найдена ни одна из них, возможности AI будут отключены

Это позволяет быстро выполнить настройку без файлов конфигурации:

```bash
# Using OpenAI
export OPENAI_API_KEY=your-openai-key
clickhouse-client

# Using Anthropic
export ANTHROPIC_API_KEY=your-anthropic-key
clickhouse-client
```

* `~/.clickhouse-client/config.yaml` (формат YAML, устаревшее расположение)
* Либо укажите собственный путь с помощью `--config-file`

### Параметры {#ai-sql-generation-parameters}

<Accordion title="Обязательные параметры">
  * `api_key` — ваш ключ API для сервиса ИИ. Можно не указывать, если он задан через переменную окружения:
    * OpenAI: `OPENAI_API_KEY`
    * Anthropic: `ANTHROPIC_API_KEY`
    * Примечание: ключ API в файле конфигурации имеет приоритет над переменной окружения
  * `provider` — провайдер ИИ: `openai` или `anthropic`
    * Если не указан, провайдер выбирается автоматически (с переходом на резервный вариант) на основе доступных переменных окружения
</Accordion>

<Accordion title="Конфигурация модели">
  * `model` — используемая модель (по умолчанию зависит от провайдера)
    * OpenAI: `gpt-4o`, `gpt-4`, `gpt-3.5-turbo` и т. д.
    * Anthropic: `claude-3-5-sonnet-20241022`, `claude-3-opus-20240229` и т. д.
    * OpenRouter: используйте принятые в нём имена моделей, например `anthropic/claude-3.5-sonnet`
</Accordion>

<Accordion title="Настройки соединения">
  * `base_url` — пользовательская конечная точка API для сервисов, совместимых с OpenAI (необязательно)
  * `timeout_seconds` — тайм-аут запроса в секундах (по умолчанию: `30`)
</Accordion>

<Accordion title="Исследование схемы">
  * `enable_schema_access` — разрешить ИИ исследовать схемы базы данных (по умолчанию: `true`)
  * `max_steps` — максимальное количество шагов с вызовом инструментов при исследовании схемы (по умолчанию: `10`)
</Accordion>

<Accordion title="Параметры генерации">
  * `temperature` — управляет степенью случайности: 0.0 — детерминированный результат, 1.0 — максимально творческий. По умолчанию не задаётся и передаётся модели только при явном указании, поскольку некоторые модели не принимают этот параметр.
  * `max_tokens` — максимальная длина ответа в токенах (по умолчанию: `1000`)
  * `system_prompt` — пользовательские инструкции для ИИ (необязательно)
</Accordion>

### Как это работает {#ai-sql-generation-how-it-works}

Генератор SQL на основе ИИ работает в несколько этапов:

1. **Обнаружение схемы**

ИИ изучает вашу базу данных с помощью встроенных инструментов:

* Получает список доступных баз данных
* Находит таблицы в соответствующих базах данных
* Изучает структуру таблиц с помощью операторов `CREATE TABLE`

2. **Генерация запроса**

На основе обнаруженной схемы ИИ генерирует SQL, который:

* Соответствует вашему запросу на естественном языке
* Использует правильные имена таблиц и столбцов
* Применяет подходящие соединения и агрегации

3. **Выполнение**

Сгенерированный SQL выполняется автоматически, после чего отображаются результаты

### Ограничения {#ai-sql-generation-limitations}

* Требуется активное соединение с интернетом
* При использовании API действуют ограничения на частоту запросов и тарифы провайдера ИИ
* Сложные запросы могут потребовать нескольких доработок
* ИИ имеет доступ к сведениям о схеме в режиме только для чтения, но не к самим данным

### Безопасность {#ai-sql-generation-security}

* Ключи API никогда не отправляются на серверы ClickHouse
* ИИ видит только сведения о схеме (имена таблиц и столбцов, а также типы данных), но не сами данные
* Все сгенерированные запросы выполняются с соблюдением ваших текущих прав доступа к базе данных

## Строка подключения {#connection_string}

### Использование {#connection-string-usage}

Клиент ClickHouse также поддерживает подключение к серверу ClickHouse с помощью строки подключения, аналогичной тем, что используются в [MongoDB](https://www.mongodb.com/docs/manual/reference/connection-string/), [PostgreSQL](https://www.postgresql.org/docs/current/libpq-connect.html#LIBPQ-CONNSTRING) и [MySQL](https://dev.mysql.com/doc/refman/8.0/en/connecting-using-uri-or-key-value-pairs.html#connecting-using-uri). Синтаксис строки подключения:

```text
clickhouse:[//[user[:password]@][hosts_and_ports]][/database][?query_parameters]
```

| Компонент (все необязательны) | Описание                                                                                                                                                                  | По умолчанию     |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `user`                        | Имя пользователя базы данных.                                                                                                                                             | `default`        |
| `password`                    | Пароль пользователя базы данных. Если указан символ `:`, а пароль не задан, клиент запросит пароль пользователя.                                                          | -                |
| `hosts_and_ports`             | Список хостов с необязательным указанием портов `host[:port] [, host:[port]], ...`.                                                                                       | `localhost:9000` |
| `database`                    | Имя базы данных.                                                                                                                                                          | `default`        |
| `query_parameters`            | Список пар «ключ — значение» `param1=value1[,&param2=value2], ...`. Для некоторых параметров значение не требуется. Имена и значения параметров чувствительны к регистру. | -                |

### Примечания {#connection-string-notes}

Если имя пользователя, пароль или база данных указаны в строке подключения, их нельзя одновременно задать с помощью `--user`, `--password` или `--database` соответственно (и наоборот).

В качестве хоста можно указать имя хоста, IPv4-адрес или IPv6-адрес.
IPv6-адреса следует заключать в `[]`:

```text
clickhouse://[2001:db8::1234]
```

Строки подключения могут содержать несколько хостов.
Клиент ClickHouse пытается подключиться к ним по порядку (слева направо).
После установления соединения попытки подключения к оставшимся хостам не выполняются.

Строку подключения необходимо указать первым аргументом `clickhouse-client`.
Её можно использовать вместе с любым количеством других [параметров командной строки](#command-line-options), кроме `--host` и `--port`.

Для `query_parameters` допускаются следующие ключи:

| Ключ               | Описание                                                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `secure` (или `s`) | Если указан, клиент подключится к серверу по защищённому соединению (TLS). См. `--secure` в разделе [«Параметры командной строки»](#command-line-options). |

**Процентное кодирование**

Символы, не входящие в US-ASCII, пробелы и специальные символы в следующих параметрах должны быть [закодированы с помощью процентного кодирования (percent-encoded)](https://en.wikipedia.org/wiki/URL_encoding):

* `user`
* `password`
* `hosts`
* `database`
* `query parameters`

### Примеры {#connection_string_examples}

Подключитесь к `localhost` через порт 9000 и выполните запрос `SELECT 1`.

```bash
clickhouse-client clickhouse://localhost:9000 --query "SELECT 1"
```

Подключитесь к `localhost` от имени пользователя `john` с паролем `secret`, указав хост `127.0.0.1` и порт `9000`

```bash
clickhouse-client clickhouse://john:secret@127.0.0.1:9000
```

Подключитесь к `localhost` от имени пользователя `default`, указав IPv6-адрес хоста `[::1]` и порт `9000`.

```bash
clickhouse-client clickhouse://[::1]:9000
```

Подключитесь к `localhost` через порт 9000 в многострочном режиме.

```bash
clickhouse-client clickhouse://localhost:9000 '-m'
```

Подключитесь к `localhost` через порт 9000 от имени пользователя `default`.

```bash
clickhouse-client clickhouse://default@localhost:9000

# equivalent to:
clickhouse-client clickhouse://localhost:9000 --user default
```

Подключитесь к `localhost` на порту 9000 и используйте базу данных `my_database` по умолчанию.

```bash
clickhouse-client clickhouse://localhost:9000/my_database

# equivalent to:
clickhouse-client clickhouse://localhost:9000 --database my_database
```

Подключитесь к `localhost` на порту 9000, используя указанную в строке подключения базу данных `my_database` по умолчанию и включив защищённое соединение с помощью сокращённого параметра `s`.

```bash
clickhouse-client clickhouse://localhost/my_database?s

# equivalent to:
clickhouse-client clickhouse://localhost/my_database -s
```

Подключитесь к хосту по умолчанию через порт по умолчанию, используя пользователя default и базу данных по умолчанию.

```bash
clickhouse-client clickhouse:
```

Подключитесь к хосту по умолчанию, используя порт по умолчанию и имя пользователя `my_user`, без пароля.

```bash
clickhouse-client clickhouse://my_user@

# Using a blank password between : and @ means to asking the user to enter the password before starting the connection.
clickhouse-client clickhouse://my_user:@
```

Подключитесь к `localhost`, указав адрес электронной почты в качестве имени пользователя. При процентном кодировании символ `@` заменяется на `%40`.

```bash
clickhouse-client clickhouse://some_user%40some_mail.com@localhost:9000
```

Подключитесь к одному из двух хостов: `192.168.1.15`, `192.168.1.25`.

```bash
clickhouse-client clickhouse://192.168.1.15,192.168.1.25
```

## Формат идентификатора запроса {#query-id-format}

В интерактивном режиме клиент ClickHouse отображает идентификатор каждого запроса. По умолчанию идентификатор имеет следующий формат:

```sql
Query id: 927f137d-00f1-4175-8914-0dd066365e96
```

Пользовательский формат можно задать в файле конфигурации внутри тега `query_id_formats`. Плейсхолдер `{query_id}` в строке формата заменяется идентификатором запроса. Внутри тега можно указать несколько строк формата.
Эта возможность позволяет создавать URL для удобного анализа данных профилирования запросов.

**Пример**

```xml
<config>
  <query_id_formats>
    <speedscope>http://speedscope-host/#profileURL=qp%3Fid%3D{query_id}</speedscope>
  </query_id_formats>
</config>
```

При указанной выше конфигурации ID запроса отображается в следующем формате:

```response
speedscope:http://speedscope-host/#profileURL=qp%3Fid%3Dc8ecc783-e753-4b38-97f1-42cddfb98b7d
```

## Параметры командной строки {#command-line-options}

### Параметры запросов {#command-line-options-query}

| Параметр                        | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--param_<name>=<value>`        | Значение для подстановки в параметр [запроса с параметрами](#cli-queries-with-parameters).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `-q [ --query ] <query>`        | Запрос для выполнения в пакетном режиме. Параметр можно указать несколько раз (`--query "SELECT 1" --query "SELECT 2"`) или один раз, передав несколько запросов, разделённых точкой с запятой (`--query "SELECT 1; SELECT 2;"`). В последнем случае запросы `INSERT` с форматами, отличными от `VALUES`, необходимо разделять пустыми строками. <br /><br />Один запрос также можно указать без параметра: `clickhouse-client "SELECT 1"` <br /><br />Нельзя использовать вместе с `--queries-file`.                                                                                                                                                                                                                                            |
| `--queries-file <path-to-file>` | Путь к файлу с запросами. `--queries-file` можно указать несколько раз, например: `--queries-file queries1.sql --queries-file queries2.sql`. <br /><br />Нельзя использовать вместе с `--query`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `-m [ --multiline ]`            | Разрешает многострочные запросы (запрос не отправляется при нажатии Enter). Запросы отправляются только после завершающей точки с запятой.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `--ignore-error`                | Позволяет продолжать выполнение при ошибке запроса: ошибка выводится в `stderr`, после чего выполняется следующий запрос. Поскольку ошибки игнорируются, процесс завершается с кодом успешного выполнения, даже если некоторые запросы завершились с ошибкой. Применяется только в пакетном режиме.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `--inline-insert-data`          | Отправляет `INSERT ... VALUES` (и другие форматы со встроенными данными) без изменений в тексте запроса, не преобразуя данные в блоки формата Native. Сервер самостоятельно разбирает встроенные данные, что позволяет избежать дополнительного обмена с клиентом для передачи ему структуры таблицы и значений столбцов по умолчанию. Это может повысить производительность при большом количестве небольших вставок по собственному протоколу. Автоматически устанавливает настройку [`send_table_structure_on_insert_with_inline_data`](/ru/reference/settings/session-settings/send#send_table_structure_on_insert_with_inline_data) в `0`. Нельзя использовать при одновременной передаче встроенных и внешних данных (из stdin или `INFILE`). |

### Настройки запроса {#command-line-options-query-settings}

Настройки запроса можно задать в клиенте с помощью параметров командной строки, например:

```bash
$ clickhouse-client --max_threads 1
```

Список настроек см. в разделе [Настройки](/ru/reference/settings/session-settings).
