[Именованные коллекции](/ru/concepts/features/configuration/server-config/named-collections), созданные через SQL,
можно экспортировать в резервную копию и восстанавливать из неё через таблицу `system.named_collections`.
Экспортированная коллекция содержит свои значения, включая секретные, поэтому резервное копирование
и восстановление коллекций регулируются отдельными привилегиями и настройками, которые описаны на этой странице.

Коллекции, определённые в файлах конфигурации сервера, формируются из конфигурации и
никогда не попадают в резервную копию; восстановление коллекции из резервной копии не перезаписывает
одноимённую коллекцию, определённую в конфигурации.

## Выбор коллекций {#selecting-the-collections}

Запрос `BACKUP` экспортирует именованные коллекции, если в него попадает таблица `system.named_collections`:

* Явно: `BACKUP TABLE system.named_collections`. В этом случае наличие необходимых привилегий (см. ниже)
  обязательно.
* Неявно — через элемент `DATABASE system` или `ALL`. По умолчанию такая резервная копия включает
  коллекции, только если пользователь имеет право читать их значения; в противном случае они пропускаются с предупреждением. Благодаря этому
  `BACKUP ALL` продолжает работать для пользователя, которому разрешено создавать резервные копии всех объектов, но не разрешено читать
  значения.

Выборка, исключающая данные таблицы, — `BACKUP TABLE system.named_collections EXCEPT DATA FROM
TABLE system.named_collections` или элемент с подстановочным шаблоном и `EXCEPT DATA FROM TABLES
system.named_collections`, — сохраняет в резервной копии только определение таблицы. Такая выборка не экспортирует ни одной
коллекции и не требует ни одной из перечисленных ниже привилегий.

## Необходимые привилегии {#required-privileges}

При экспорте коллекций их значения записываются в резервную копию, поэтому для него требуются те же привилегии,
что и для чтения значений из `system.named_collections`:
[`SHOW NAMED COLLECTIONS`](/ru/reference/statements/grant#named-collection-admin),
`SHOW NAMED COLLECTIONS SECRETS` и
[`displaySecretsInShowAndSelect`](/ru/reference/statements/grant#displaysecretsinshowandselect).
Это относится и к зашифрованному хранилищу именованных коллекций: записи копируются в виде шифротекста,
но любой сервер с тем же ключом восстановит их в коллекции, значения которых затем можно прочитать.

Для восстановления коллекций требуется привилегия
[`CREATE NAMED COLLECTION`](/ru/reference/statements/grant#named-collection-admin). Перечисленные выше привилегии
для этого не нужны: оператор может восстановить резервную копию, не имея возможности
её прочитать, а в ошибках и журналах такого восстановления имена коллекций никогда не упоминаются.

Для `BACKUP ON CLUSTER` и `RESTORE ON CLUSTER` привилегии проверяются для пользователя-инициатора
на хосте-инициаторе до того, как запрос будет направлен на обработку другим хостам. Во время поэтапного
обновления хост, работающий на версии с этой возможностью, никогда не экспортирует и не восстанавливает коллекции для
запроса, направленного на обработку initiator на версии без неё, поскольку такой initiator не может
проверить привилегии: экспорт пропускается (а при явной выборке — отклоняется), а
восстановление записей коллекций отклоняется.

## `backup_named_collections` {#backup-named-collections}

Тип: `Bool`. Необязательный; по умолчанию не задан.

Определяет, включает ли запрос `BACKUP` именованные коллекции в резервную копию:

* Не задан (по умолчанию): явно указанный элемент `TABLE system.named_collections` экспортирует их и
  требует соответствующих привилегий; элемент `DATABASE system` или `ALL` экспортирует их, только если у пользователя
  есть эти привилегии, а в противном случае пропускает их с предупреждением.
* `true`: коллекции экспортируются в резервную копию всякий раз, когда запрос затрагивает эту таблицу, а отсутствие
  привилегий приводит к ошибке даже при неявном выборе таблицы.
* `false`: коллекции никогда не экспортируются в резервную копию, даже если таблица `system.named_collections`
  указана явно, и никаких привилегий не требуется.

```sql
-- Fails instead of skipping the collections when the privileges are missing:
BACKUP ALL TO Disk('backups', 'everything') SETTINGS backup_named_collections = 1

-- Never exports the collections:
BACKUP ALL TO Disk('backups', 'no_collections') SETTINGS backup_named_collections = 0
```

## `restore_named_collections` {#restore-named-collections}

Тип: `Bool`. Значение по умолчанию: `true`.

Определяет, восстанавливает ли запрос `RESTORE` именованные коллекции, хранящиеся в резервной копии. В отличие от
[`restore_table_data`](/ru/concepts/features/backup-restore/restore-settings) и аналогичных настроек, при `structure_only` значение по умолчанию остаётся
`true`: коллекции относятся к определениям, а таблицу, движок которой
ссылается на коллекцию (например, `ENGINE = URL(collection)`), без неё создать невозможно.

```sql
-- Restores everything except the named collections:
RESTORE ALL FROM Disk('backups', 'everything') SETTINGS restore_named_collections = 0
```

## `create_named_collection` {#create-named-collection}

Тип: `String`. Значение по умолчанию: `'if-not-exists'`.

Определяет, как `RESTORE` обрабатывает уже существующую именованную коллекцию:

* `'if-not-exists'` (по умолчанию): существующая коллекция сохраняется, а коллекция из резервной копии
  пропускается.
* `'create'`: если коллекция уже существует, восстановление завершается ошибкой.
* `'replace'`: существующая коллекция заменяется коллекцией из резервной копии. Коллекцию, определённую в
  конфигурации сервера, заменить нельзя: в этом случае восстановление завершается ошибкой.

```sql
RESTORE TABLE system.named_collections FROM Disk('backups', 'everything')
SETTINGS create_named_collection = 'replace'
```

## Зашифрованное хранилище именованных коллекций {#encrypted-storage}

При использовании [зашифрованного хранилища для именованных коллекций](/ru/concepts/features/configuration/server-config/named-collections)
(`local_encrypted` или `zookeeper_encrypted`) записи копируются в резервную копию в том же виде
шифротекста, в котором они находятся в хранилище, вместе с кодом аутентификации: ни одно значение в открытом виде
не попадает в резервную копию, а изменённая запись приводит к ошибке восстановления ещё до начала расшифровки.

Для восстановления такой резервной копии требуется сервер, хранилище именованных коллекций которого также зашифровано и
содержит ключ, которым были зашифрованы коллекции. Восстановленные записи повторно шифруются ключом
сервера, на котором выполняется восстановление. Резервную копию с зашифрованными записями нельзя восстановить в незашифрованное
хранилище: либо настройте зашифрованное хранилище с этим ключом, либо пропустите коллекции с помощью
`restore_named_collections = 0`.
