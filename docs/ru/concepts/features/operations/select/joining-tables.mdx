## Типы и строгость JOIN {#join-types-and-strictness}

У каждого JOIN есть тип и строгость. Тип определяет, какие строки без совпадения попадают в результат. Строгость определяет, сколько совпадений возвращается для каждой строки. От обоих параметров зависит, какими алгоритмами можно выполнить JOIN. Полный синтаксис, а также описание дополнительных видов JOIN — `SEMI`, `ANTI`, `CROSS` и `PASTE` — см. в [справочнике по предложению `JOIN`](/ru/reference/statements/select/join#supported-types-of-join).

### `INNER JOIN` {#inner-join}

<div className="ch-image-sm">
  <Frame>
    ![Диаграмма Венна для INNER JOIN: возвращается только пересечение строк левой и правой таблиц с совпадающими ключами JOIN — в виде декартова произведения совпадающих строк](/images/guides/join-algorithms/inner-join.png)
  </Frame>
</div>

Для каждой пары строк с совпадающими ключами JOIN `INNER JOIN` возвращает столбцы строки из левой таблицы вместе со столбцами строки из правой таблицы. Если для строки найдено несколько совпадений, возвращаются все они, поэтому результат содержит декартово произведение строк с одинаковым ключом. Ключевое слово `INNER` можно опустить.

### `LEFT`, `RIGHT` и `FULL OUTER JOIN` {#outer-join}

<div className="ch-image-lg">
  <Frame>
    ![Диаграммы Венна для LEFT, RIGHT и FULL OUTER JOIN: каждый из них возвращает декартово произведение совпадающих строк, а также несовпадающие строки левой таблицы, правой таблицы или обеих таблиц](/images/guides/join-algorithms/outer-join.png)
  </Frame>
</div>

Внешний JOIN возвращает те же строки, что и `INNER JOIN`, а также строки, для которых совпадение не найдено:

* `LEFT OUTER JOIN` дополнительно возвращает каждую строку левой таблицы, не имеющую совпадения, и подставляет значения по умолчанию в столбцы правой таблицы.
* `RIGHT OUTER JOIN` дополнительно возвращает каждую строку правой таблицы, не имеющую совпадения, и подставляет значения по умолчанию в столбцы левой таблицы.
* `FULL OUTER JOIN` возвращает строки без совпадений из обеих таблиц.

Если включена настройка [`join_use_nulls`](/ru/reference/settings/session-settings/join#join_use_nulls), ClickHouse возвращает `NULL` вместо значений по умолчанию. Ключевое слово `OUTER` можно опустить.

### Строгость `ALL` и `ANY` {#all-and-any-strictness}

<div className="ch-image-lg">
  <Frame>
    ![Диаграммы Венна для LEFT, RIGHT и INNER ANY JOIN: каждый из них возвращает совпадающие строки без декартова произведения, а LEFT и RIGHT — ещё и несовпадающие строки левой или правой таблицы соответственно](/images/guides/join-algorithms/any-join.png)
  </Frame>
</div>

При строгости `ALL` JOIN возвращает все совпадения, как описано выше для типов JOIN. При строгости `ANY` JOIN возвращает не более одного совпадения для каждой строки и не образует декартова произведения:

* `LEFT ANY JOIN` возвращает каждую строку левой таблицы ровно один раз, соединяя её с одной совпадающей строкой правой таблицы или со значениями по умолчанию.
* `RIGHT ANY JOIN` возвращает каждую строку правой таблицы ровно один раз, соединяя её с одной совпадающей строкой левой таблицы или со значениями по умолчанию.
* `INNER ANY JOIN` возвращает только строки, для которых найдено совпадение, и использует каждую строку любой из таблиц не более одного раза.

Какую именно из нескольких совпадающих строк вернёт `ANY`, не определено. Выбор строки можно изменить с помощью настройки [`join_any_take_last_row`](/ru/reference/settings/session-settings/join#join_any_take_last_row). JOIN типа `ANY FULL` не поддерживаются. Если строгость в запросе не указана, применяется настройка [`join_default_strictness`](/ru/reference/settings/session-settings/join#join_default_strictness).

Следующий запрос демонстрирует `LEFT ANY JOIN`. Правая таблица содержит по две строки для каждого из ключей `2` и `3`:

```sql
WITH
    left_table AS (SELECT * FROM VALUES('c UInt32', 1, 2, 3)),
    right_table AS (SELECT * FROM VALUES('c UInt32', 2, 2, 3, 3, 4))
SELECT
    l.c AS l_c,
    r.c AS r_c
FROM left_table AS l
LEFT ANY JOIN right_table AS r ON l.c = r.c;
```

```response
┌─l_c─┬─r_c─┐
│   1 │   0 │
│   2 │   2 │
│   3 │   3 │
└─────┴─────┘
```

При строгости `ALL` тот же запрос возвращает пять строк, поскольку каждому из ключей `2` и `3` соответствуют по две строки правой таблицы. При `INNER ANY JOIN` запрос возвращает только строки для ключей `2` и `3`.

### `ASOF JOIN` {#asof-join}

<div className="ch-image-sm">
  <Frame>
    ![Диаграмма Венна для ASOF JOIN: соединяются строки с неточно совпадающими ключами JOIN, и для каждой строки возвращается ближайшее совпадение без декартова произведения](/images/guides/join-algorithms/asof-join.png)
  </Frame>
</div>

`ASOF JOIN` соединяет строки, для которых нет точного совпадения. В ClickHouse `ASOF` — это строгость, которая используется в сочетании с `INNER` или `LEFT` JOIN. Предложение `ON` содержит условия равенства и ровно одно условие ближайшего совпадения с оператором `>`, `>=`, `<` или `<=`. Для каждой строки левой таблицы ClickHouse выбирает среди строк правой таблицы, удовлетворяющих условиям равенства, ту, которая оказывается ближайшей согласно условию ближайшего совпадения. Каждая строка левой таблицы соединяется не более чем с одной строкой правой таблицы.

`ASOF JOIN` обычно применяется для временных рядов. Следующий запрос сопоставляет каждой сделке самую последнюю котировку по тому же тикеру, полученную в момент сделки или раньше:

```sql
WITH
    trades AS (SELECT * FROM VALUES('symbol String, volume UInt32, time DateTime',
        ('ABC', 200, '2023-02-22 14:09:05'),
        ('ABC', 300, '2023-02-22 14:09:28'))),
    quotes AS (SELECT * FROM VALUES('symbol String, time DateTime, price Decimal(10, 2)',
        ('ABC', '2023-02-22 14:09:00', 32.11),
        ('ABC', '2023-02-22 14:09:10', 32.12),
        ('ABC', '2023-02-22 14:09:20', 32.15),
        ('ABC', '2023-02-22 14:09:30', 32.20)))
SELECT
    t.symbol,
    t.volume,
    t.time AS trade_time,
    q.time AS closest_quote_time,
    q.price AS quote_price,
    t.volume * q.price AS final_price
FROM trades AS t
ASOF LEFT JOIN quotes AS q ON t.symbol = q.symbol AND t.time >= q.time
ORDER BY trade_time;
```

```response
┌─symbol─┬─volume─┬──────────trade_time─┬──closest_quote_time─┬─quote_price─┬─final_price─┐
│ ABC    │    200 │ 2023-02-22 14:09:05 │ 2023-02-22 14:09:00 │       32.11 │        6422 │
│ ABC    │    300 │ 2023-02-22 14:09:28 │ 2023-02-22 14:09:20 │       32.15 │        9645 │
└────────┴────────┴─────────────────────┴─────────────────────┴─────────────┴─────────────┘
```

Сделка в `14:09:05` соединяется с котировкой в `14:09:00`, а сделка в `14:09:28` — с котировкой в `14:09:20`. Котировки в `14:09:10` и `14:09:30` не являются ближайшей предшествующей котировкой ни для одной сделки.

Типы столбцов, поддерживаемые для столбца ближайшего совпадения, и синтаксис `USING` описаны в разделе [Использование ASOF JOIN](/ru/reference/statements/select/join#asof-join-usage).
