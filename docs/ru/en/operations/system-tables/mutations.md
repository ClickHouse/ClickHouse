<div id="description">
  ## Описание
</div>

Таблица содержит информацию о [мутациях](/ru/sql-reference/statements/alter/index.md#mutations) таблиц [MergeTree](/ru/engines/table-engines/mergetree-family/mergetree.md) и прогрессе их выполнения. Каждая команда мутации представлена одной строкой.

<div id="columns">
  ## Столбцы:
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/ru/sql-reference/data-types/string)) — Имя базы данных, к которой была применена мутация.
* `table` ([String](/ru/sql-reference/data-types/string)) — Имя таблицы, к которой была применена мутация.
* `mutation_id` ([String](/ru/sql-reference/data-types/string)) — Идентификатор мутации. Для реплицируемых таблиц эти идентификаторы соответствуют именам znode в каталоге `<table_path_in_clickhouse_keeper>/mutations/` в ClickHouse Keeper. Для нереплицируемых таблиц идентификаторы соответствуют именам файлов в каталоге данных таблицы.
* `command` ([String](/ru/sql-reference/data-types/string)) — Строка команды мутации (часть запроса после ALTER TABLE [db.]table).
* `create_time` ([DateTime](/ru/sql-reference/data-types/datetime)) — Дата и время отправки команды мутации на выполнение.
* `block_numbers.partition_id` ([Array(String)](/ru/sql-reference/data-types/array)) — Для мутаций реплицируемых таблиц массив содержит идентификаторы партиций (по одной записи для каждой партиции). Для мутаций нереплицируемых таблиц массив пуст.
* `block_numbers.number` ([Array(Int64)](/ru/sql-reference/data-types/array)) — Для мутаций реплицируемых таблиц массив содержит по одной записи для каждой партиции с номером блока, полученным мутацией. В партиции будут мутированы только те части, которые содержат блоки с номерами меньше этого номера. В нереплицируемых таблицах номера блоков во всех партициях образуют единую последовательность. Это означает, что для мутаций нереплицируемых таблиц столбец будет содержать одну запись с одним номером блока, полученным мутацией.
* `parts_in_progress_names` ([Array(String)](/ru/sql-reference/data-types/array)) — Массив имен частей данных, которые в данный момент мутируются.
* `parts_to_do_names` ([Array(String)](/ru/sql-reference/data-types/array)) — Массив имен частей данных, которые необходимо мутировать для завершения мутации.
* `parts_to_do` ([Int64](/ru/sql-reference/data-types/int-uint)) — Количество частей данных, которые необходимо мутировать для завершения мутации. Примечание: даже если `parts_to_do` = 0, мутация реплицируемой таблицы может быть еще не завершена из-за длительно выполняющегося INSERT, который создает новую часть данных, которую потребуется мутировать.
* `parts_postpone_reasons` ([Map(String, String)](/ru/sql-reference/data-types/map)) — Map имен частей и причин, по которым их обработка отложена.
* `is_done` ([UInt8](/ru/sql-reference/data-types/int-uint)) — Флаг, показывающий, завершена мутация или нет. Возможные значения: 1 — мутация завершена, 0 — мутация все еще выполняется.
* `is_killed` ([UInt8](/ru/sql-reference/data-types/int-uint)) — Указывает, была ли мутация принудительно завершена. Доступно только в ClickHouse Cloud. Примечание: is&#95;killed=1 не обязательно означает, что мутация полностью завершена. Мутация может в течение длительного времени оставаться в состоянии, где is&#95;killed=1 и is&#95;done=0. Это может происходить, если принудительно завершенную мутацию блокирует другая длительно выполняющаяся мутация. Это нормальная ситуация.
* `latest_failed_part` ([String](/ru/sql-reference/data-types/string)) — Имя последней части, которую не удалось мутировать.
* `latest_fail_time` ([DateTime](/ru/sql-reference/data-types/datetime)) — Дата и время последнего сбоя мутации части.
* `latest_fail_reason` ([String](/ru/sql-reference/data-types/string)) — Сообщение исключения, вызвавшего последний сбой мутации части.
* `latest_fail_error_code_name` ([String](/ru/sql-reference/data-types/string)) — Код ошибки исключения, вызвавшего последний сбой мутации части.

{/*AUTOGENERATED_END*/ }

:::note

* Если имя части отсутствует в `parts_postpone_reasons` и часть ещё не была мутирована, это означает, что она ещё не запланирована для мутации.

* Имя части `all_parts` обозначает все части, которые ещё не были мутированы.
  :::

* `is_killed` ([UInt8](/ru/sql-reference/data-types/int-uint.md)) — Указывает, была ли мутация принудительно завершена. **Доступно только в ClickHouse Cloud.**

:::note
`is_killed=1` не обязательно означает, что мутация полностью завершена. Возможна ситуация, когда мутация остаётся в состоянии `is_killed=1` и `is_done=0` в течение длительного времени. Это может происходить, если другую длительно выполняющуюся мутацию блокирует принудительно завершённая мутация. Это нормальная ситуация.
:::

* `is_done` ([UInt8](/ru/sql-reference/data-types/int-uint.md)) — Флаг, указывающий, завершена мутация или нет. Возможные значения:
  * `1`, если мутация завершена,
  * `0`, если мутация все еще выполняется.

:::note
Даже если `parts_to_do = 0`, мутация реплицированной таблицы может быть еще не завершена из-за долго выполняющегося `INSERT`-запроса, который создаст новую часть данных, для которой также потребуется мутация.
:::

Если при мутации некоторых частей данных возникли проблемы, следующие столбцы содержат дополнительную информацию:

* `latest_failed_part` ([String](/ru/sql-reference/data-types/string.md)) — Имя последней части, которую не удалось мутировать.
* `latest_fail_time` ([DateTime](/ru/sql-reference/data-types/datetime.md)) — Дата и время последнего сбоя при мутировании части.
* `latest_fail_reason` ([String](/ru/sql-reference/data-types/string.md)) — Сообщение об исключении, вызвавшем последний сбой при мутировании части.

<div id="monitoring-mutations">
  ## Мониторинг мутаций
</div>

Чтобы отслеживать прогресс в таблице `system.mutations`, используйте следующий запрос:

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

Примечание: для этого нужны разрешения на чтение таблиц `system.*`.

:::tip Использование Cloud
В ClickHouse Cloud таблица `system.mutations` на каждом узле содержит все мутации кластера, поэтому `clusterAllReplicas` не нужен.
:::
