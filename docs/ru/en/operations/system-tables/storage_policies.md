<div id="description">
  ## Описание
</div>

Содержит сведения о политиках хранения и томах, заданных в [конфигурации сервера](../../engines/table-engines/mergetree-family/mergetree.md#table_engine-mergetree-multiple-volumes_configure).

<div id="columns">
  ## Столбцы
</div>

{/*AUTOGENERATED_START*/ }

* `policy_name` ([String](/ru/sql-reference/data-types/string)) — Имя политики хранения.
* `volume_name` ([String](/ru/sql-reference/data-types/string)) — Имя тома.
* `volume_priority` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Приоритет тома.
* `disks` ([Array(String)](/ru/sql-reference/data-types/array)) — Список имен всех дисков, входящих в эту политику хранения.
* `volume_type` ([Enum8(&#39;JBOD&#39; = 0, &#39;SINGLE&#95;DISK&#39; = 1, &#39;UNKNOWN&#39; = 2)](/ru/sql-reference/data-types/enum)) — Тип тома — JBOD или один диск.
* `max_data_part_size` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Максимальный размер части данных, которая может храниться на любом из дисков тома.
* `move_factor` ([Float32](/ru/sql-reference/data-types/float)) — Когда объем доступного пространства становится меньше этого коэффициента, данные автоматически начинают перемещаться на следующий том, если он есть (по умолчанию 0.1).
* `prefer_not_to_merge` ([UInt8](/ru/sql-reference/data-types/int-uint)) — Не следует использовать эту настройку. Отключает слияние частей данных на этом томе (это вредно и приводит к снижению производительности).
* `perform_ttl_move_on_insert` ([UInt8](/ru/sql-reference/data-types/int-uint)) — Отключает TTL move для части данных при INSERT. По умолчанию (если включено), если вставляется часть данных, которая уже подпадает под правило TTL move, она сразу перемещается на том/диск, указанный в правиле перемещения.
* `load_balancing` ([Enum8(&#39;ROUND&#95;ROBIN&#39; = 0, &#39;LEAST&#95;USED&#39; = 1)](/ru/sql-reference/data-types/enum)) — Политика балансировки дисков: `round_robin` или `least_used`.

{/*AUTOGENERATED_END*/ }

<div id="volume-selection-on-insert">
  ## Выбор тома при `INSERT`
</div>

Когда `INSERT` создает новую часть данных, ClickHouse выбирает целевой диск,
последовательно применяя приведенные ниже правила. Срабатывает первое правило, которое подходит **и может
зарезервировать место для части**; в противном случае (правило не применяется, нет свободного
места или превышен `max_data_part_size`) проверка продолжается со следующим
правилом.

1. **Правило TTL move** — если условие `TTL <expr> TO VOLUME 'X'` (или `TO DISK 'X'`)
   уже наступило для вставляемых строк, **и**
   `perform_ttl_move_on_insert = 1` (по умолчанию) задано для **TTL-тома
   назначения** (для `TO DISK 'X'` — для тома, содержащего диск `X`), то часть
   записывается сразу в этот пункт назначения. Если зарезервировать там место не удается,
   вставка переходит к шагам 2–4; предупреждение записывается в лог, но `INSERT`
   не завершается ошибкой только по этой причине.
2. **`max_data_part_size`** — том отклоняет части, размер которых превышает
   `max_data_part_size`. Это проверяется для каждого тома отдельно; это не влияет на
   резервирование на шаге 1 для `TTL ... TO DISK 'X'`, так как оно выполняется
   непосредственно на диск.
3. **`volume_priority`** — среди оставшихся томов выбирается тот,
   у которого значение `volume_priority` наименьшее. Тома без явно заданного
   `<volume_priority>` упорядочиваются по их позиции в конфигурации.
4. **`load_balancing`** — после выбора тома диск внутри этого
   тома выбирается в соответствии с его политикой `load_balancing`
   (`round_robin` или `least_used`).

:::note Переопределение
Если `min_free_disk_bytes_to_perform_insert` или
`min_free_disk_ratio_to_perform_insert` не равен нулю, указанный выше порядок
обходится. `INSERT` пытается использовать только том с наименьшим
`volume_priority` и генерирует `NOT_ENOUGH_SPACE`, если ни один диск в этом томе
не соответствует пороговому значению. Вставки в базу данных `system` являются исключением.
:::

:::note
`perform_ttl_move_on_insert` читается из **TTL-тома назначения**,
а не из исходного тома. Для правила `TO DISK 'X'` этот флаг читается
из тома, который содержит диск `X`. Установка его на любом другом томе
этой policy не влияет на путь вставки.
:::

Чтобы принудительно заставить вставки учитывать `volume_priority`, даже когда применяется
правило TTL move с уже «истекшим» сроком, установите `perform_ttl_move_on_insert = 0` на
TTL-томе назначения (для `TO DISK 'X'` — на томе, который содержит
диск `X`). Тогда часть сначала записывается в том с приоритетом N, а затем
перемещается в TTL-пункт назначения фоновой задачей перемещения (это можно наблюдать через
`system.moves`). См.
[параметр `perform_ttl_move_on_insert` для движка MergeTree](/ru/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-multiple-volumes_configure).
