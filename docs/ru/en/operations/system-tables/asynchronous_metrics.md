<div id="systemasynchronous_metrics">
  # system.asynchronous_metrics
</div>

<SystemTableCloud />

<div id="description">
  ## Описание
</div>

Содержит метрики, которые периодически вычисляются в фоновом режиме. Например, объём используемой оперативной памяти.

<div id="columns">
  ## Столбцы
</div>

{/*AUTOGENERATED_START*/ }

* `metric` ([String](../../sql-reference/data-types/string.md)) — Имя метрики.
* `value` ([Float64](../../sql-reference/data-types/float.md)) — Значение метрики.
* `description` ([String](../../sql-reference/data-types/string.md) - Описание метрики)

{/*AUTOGENERATED_END*/ }

<div id="metric-descriptions">
  ## Описания метрик
</div>

Приведённые ниже описания сгенерированы из исходного кода C++ с помощью `utils/generate-async-metrics-docs`. Единственным источником истины служит строковый literal рядом с регистрацией каждой метрики в `src/Common/AsynchronousMetrics.cpp`, `src/Interpreters/ServerAsynchronousMetrics.cpp` и `src/Coordination/KeeperAsynchronousMetrics.cpp`. Имена метрик, содержащие переменный суффикс (per-disk, per-CPU, per-interface, ...), показаны с плейсхолдером `*name*`; запущенный server сообщает их с подставленным конкретным суффиксом.

<div id="blockactivetime_name">
  ### BlockActiveTime_*name*
</div>

Время в секундах, в течение которого запросы ввода-вывода к блочному устройству находились в очереди. Это общесистемная метрика: она включает все процессы на хосте, а не только clickhouse-server. Источник: `/sys/block`. См. https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="cgroupmemorytotal">

</div>

Общий объём памяти в cgroup, в байтах. Если указано 0, ограничение совпадает с OSMemoryTotal.

<div id="cgroupmemoryused">
  ### CGroupMemoryUsed
</div>

Объём памяти, используемой в cgroup, в байтах. В cgroup v2 это anon + sock + невытесняемая память ядра; в cgroup v1 — RSS. В обоих случаях кэш страниц ОС (файловый кэш) не учитывается.

<div id="cgroupmemoryusedwithoutpagecache">

</div>

Объём памяти, используемой в cgroup, в байтах, без учёта кэша страниц ClickHouse в пространстве пользователя. Это значение CGroupMemoryUsed за вычетом размера кэша страниц в пространстве пользователя. Если кэш страниц в пространстве пользователя отключён, это значение равно CGroupMemoryUsed.

<div id="cgroupsystemtime">
  ### CGroupSystemTime
</div>

Доля времени, в течение которого ядро CPU выполняло код ядра ОС (system).

<div id="cgroupsystemtimenormalized">
  ### CGroupSystemTimeNormalized
</div>

Значение аналогично `CGroupSystemTime`, но делится на число доступных ядер CPU, поэтому измеряется в интервале [0..1] независимо от их количества. Это позволяет усреднять значения этой метрики по нескольким серверам в кластере, даже если число ядер различается, и при этом получать среднюю метрику использования ресурсов. При необходимости вместо фактического числа ядер CPU можно использовать квоту CPU в Cgroup, делённую на её период; в этом случае значение метрики в отдельные моменты может превышать 1.

<div id="cgroupusertime">
  ### CGroupUserTime
</div>

Доля времени, в течение которого ядро CPU выполняло код пользовательского пространства. Сюда также входит время, когда CPU был недозагружен по внутренним для него причинам (обращения к памяти, простои конвейера, ошибки предсказания ветвлений, выполнение на другом SMT-ядре).

<div id="cgroupusertimenormalized">
  ### CGroupUserTimeNormalized
</div>

Это значение похоже на `CGroupUserTime`, но делится на количество доступных ядер CPU, чтобы оставаться в интервале [0..1] независимо от числа ядер. Это позволяет усреднять значения этой Метрики по нескольким серверам в кластере, даже если количество ядер различается, и при этом получать среднюю Метрику использования ресурсов. Если указана квота CPU в Cgroup, делённая на её период, её можно использовать вместо фактического количества ядер CPU; в этом случае значение этой Метрики в отдельные моменты может превышать 1.

<div id="diskused_name">

Количество использованных байт на диске (виртуальная файловая система). Удалённые файловые системы не всегда предоставляют эту информацию.

<div id="edaci_correctable">
  ### EDAC*i*_Correctable
</div>

Количество исправимых ошибок ECC в памяти. Высокое значение этого показателя указывает на неисправную оперативную память, которую необходимо немедленно заменить, поскольку большое число исправленных ошибок также может сопровождаться скрытыми ошибками, приводящими к повреждению данных. Источник: `/sys/devices/system/edac/mc/`

<div id="edaci_uncorrectable">

</div>

Количество неисправимых ошибок памяти ECC. Ненулевое значение этого показателя указывает на неисправную оперативную память, которую необходимо немедленно заменить, поскольку это может привести к повреждению данных. Источник: `/sys/devices/system/edac/mc/`

<div id="executableuserdefinedfunctionmemoryresidentbytes">
  ### ExecutableUserDefinedFunctionMemoryResidentBytes
</div>

Суммарный размер резидентного набора (VmRSS) всех активных процессов пользовательских функций executable и executable&#95;pool, а также их дочерних процессов, в байтах. Бездействующие воркеры executable&#95;pool также включаются. Общие страницы учитываются один раз для каждого процесса, поэтому эта сумма представляет собой верхнюю границу и может превышать уникальный объём фактически используемой физической памяти процессами UDF.

Количество активных процессов, созданных для пользовательских функций `executable` и `executable_pool`, включая их дочерние процессы.

</div>

Объём физической памяти, используемой серверным процессом, в байтах.

<div id="memoryresidentmax">
  ### MemoryResidentMax
</div>

Максимальный объём физической памяти, используемой серверным процессом, в байтах.

<div id="memoryresidentwithoutpagecache">
  ### MemoryResidentWithoutPageCache
</div>

Объем физической памяти, используемой процессом сервера, без учета кэша страниц в пространстве пользователя, в байтах. Этот показатель дает более точное представление о фактическом использовании памяти, когда задействован кэш страниц в пространстве пользователя. Если кэш страниц в пространстве пользователя отключен, это значение равно MemoryResident.

<div id="memoryshared">
  ### MemoryShared
</div>

Объём памяти, используемой процессом сервера и одновременно разделяемой с другими процессами, в байтах. ClickHouse не использует разделяемую память, но операционная система по своим причинам может помечать часть памяти как разделяемую. Обычно следить за этой метрикой нет особого смысла; она существует лишь для полноты.

<div id="memoryvirtual">
  ### MemoryVirtual
</div>

Размер виртуального адресного пространства, выделенного серверным процессом, в байтах. Размер виртуального адресного пространства обычно значительно превышает объём фактически используемой физической памяти, и его не следует использовать для оценки потребления памяти. Большие значения этой метрики совершенно нормальны и имеют смысл только с технической точки зрения.

<div id="mysqlrejectedconnections">
  ### MySQLRejectedConnections
</div>

Количество отклонённых соединений при использовании протокола совместимости MySQL.

<div id="mysqlthreads">
  ### MySQLThreads
</div>

Количество потоков на сервере протокола совместимости MySQL.

<div id="numberofdetachedbyuserparts">
  ### NumberOfDetachedByUserParts
</div>

Общее количество частей, отсоединённых пользователями в таблицах семейства MergeTree с помощью запроса `ALTER TABLE DETACH` (в отличие от неожиданных, повреждённых или проигнорированных частей). Сервер не обращает внимания на отсоединённые части, поэтому их можно удалить.

<div id="numberofdetachedparts">

</div>

Общее количество частей, отсоединённых от таблиц семейства MergeTree. Часть может быть отсоединена пользователем с помощью запроса `ALTER TABLE DETACH` или самим сервером, если она повреждена, обнаружена неожиданно или больше не нужна. Сервер не использует отсоединённые части, поэтому их можно удалить.

<div id="oscontextswitches">
  ### Переключения контекста ОС
</div>

Количество переключений контекста в системе на хост-машине. Это общесистемная метрика: она учитывает все процессы на хост-машине, а не только clickhouse-server.

<div id="oscpuoverload">
  ### OSCPUOverload
</div>

Относительный дефицит CPU, рассчитываемый следующим образом: сколько потоков ожидают CPU по отношению к числу потоков, использующих CPU. Если значение больше нуля, серверу будет полезно больше ресурсов CPU. Если оно значительно больше нуля, сервер может перестать отвечать. Метрика накапливается между обновлениями асинхронных метрик.

<div id="osguestnicetimecpu_suffix">
  ### OSGuestNiceTime*cpu_suffix*
</div>

Доля времени, затраченного на выполнение виртуального CPU для гостевых операционных систем под управлением ядра Linux, когда для гостевой системы был установлен повышенный приоритет (см. `man procfs`). Это общесистемная Метрика: она учитывает все процессы на хост-машине, а не только clickhouse-server. Для ClickHouse эта Метрика несущественна, но присутствует для полноты. Значение для одного ядра CPU находится в диапазоне [0..1]. Значение для всех ядер CPU вычисляется как сумма по всем ядрам [0..num cores].

<div id="osguestnicetimenormalized">
  ### OSGuestNiceTimeNormalized
</div>

Значение похоже на `OSGuestNiceTime`, но делится на количество ядер CPU, чтобы находиться в интервале [0..1] независимо от их числа. Это позволяет усреднять значения этой метрики по нескольким серверам в кластере, даже если число ядер различается, и при этом получать среднюю метрику использования ресурсов. Если указано, вместо фактического количества ядер CPU можно использовать квоту CPU в Cgroup, деленную на ее период; в этом случае значение этой метрики в отдельные моменты может превышать 1.

<div id="osguesttimecpu_suffix">
  ### OSGuestTime*cpu_suffix*
</div>

Отношение времени, затраченного на выполнение виртуального CPU гостевыми операционными системами под управлением ядра Linux (см. `man procfs`). Это общесистемная метрика: она включает все процессы на хост-машине, а не только clickhouse-server. Для ClickHouse эта метрика несущественна, но всё же присутствует для полноты. Значение для одного ядра CPU находится в интервале [0..1]. Значение для всех ядер CPU вычисляется как сумма по всем ядрам [0..num cores].

<div id="osguesttimenormalized">
  ### OSGuestTimeNormalized
</div>

Значение похоже на `OSGuestTime`, но делится на количество ядер CPU, чтобы находиться в интервале [0..1] независимо от числа ядер. Это позволяет усреднять значения этой метрики по нескольким серверам в кластере, даже если количество ядер различается, и при этом по-прежнему получать среднюю метрику использования ресурсов. Если указано, вместо фактического количества ядер CPU можно использовать квоту CPU в Cgroup, делённую на её период; в этом случае значение этой метрики в отдельные моменты может превышать 1.

<div id="osidletimecpu_suffix">
  ### OSIdleTime*cpu_suffix*
</div>

Доля времени, в течение которого ядро CPU бездействовало (то есть даже не было готово выполнять процесс, ожидающий IO), с точки зрения ядра ОС. Это общесистемная метрика: она включает все процессы на хост-машине, а не только clickhouse-server. Сюда не входит время, когда CPU был недоиспользован по внутренним для него причинам (загрузки из памяти, простои конвейера, ошибочные предсказания ветвлений, работа другого SMT-ядра). Значение для одного ядра CPU находится в интервале [0..1]. Значение для всех ядер CPU вычисляется как сумма по всем ядрам [0..num cores].

<div id="osidletimenormalized">
  ### OSIdleTimeNormalized

Значение похоже на `OSIdleTime`, но делится на количество ядер CPU, чтобы находиться в интервале [0..1] независимо от числа ядер. Это позволяет усреднять значения этой метрики по нескольким серверам в кластере, даже если число ядер неодинаково, и при этом получать среднюю метрику использования ресурсов. Это общесистемная метрика: она включает все процессы на хосте, а не только clickhouse-server. Значение для одного ядра CPU находится в интервале [0..1]. Это позволяет усреднять значения этой метрики по нескольким серверам в кластере, даже если число ядер различается, и при этом получать среднюю метрику использования ресурсов. <div id="osirqtimecpu_suffix">
  ### OSIrqTime*cpu_suffix*
</div>

Отношение времени, затраченного на обработку аппаратных прерываний на CPU. Это общесистемная метрика: она включает все процессы на хост-машине, а не только clickhouse-server. Высокое значение этой метрики может указывать на неправильную конфигурацию оборудования или очень высокую сетевую нагрузку. Значение для одного ядра CPU находится в интервале [0..1]. Значение для всех ядер CPU вычисляется как сумма по всем ядрам [0..num cores].

<div id="osirqtimenormalized">
  ### OSIrqTimeNormalized
</div>

Значение аналогично `OSIrqTime`, но делится на число ядер CPU, чтобы измеряться в интервале [0..1] независимо от их количества. Это позволяет усреднять значения этой метрики по нескольким серверам в кластере, даже если число ядер различается, и при этом получать среднюю метрику использования ресурсов. <div id="osmemoryavailable">
  ### OSMemoryAvailable
</div>

Объём памяти, доступной для использования программами, в байтах. Эта метрика очень похожа на `OSMemoryFreePlusCached`. Это общесистемная метрика: она учитывает все процессы на хост-машине, а не только `clickhouse-server`.

<div id="osmemorybuffers">
  ### OSMemoryBuffers
</div>

Объём памяти, используемой буферами ядра ОС, в байтах. Обычно это значение должно быть небольшим, а большие значения могут указывать на некорректную настройку ОС. Это общесистемная метрика: она охватывает все процессы на хост-машине, а не только `clickhouse-server`.

<div id="osmemorycached">
  ### OSMemoryCached
</div>

Объём памяти, используемой кэшем страниц ОС, в байтах. Как правило, кэш страниц ОС использует почти всю доступную память — высокие значения этой метрики нормальны и ожидаемы. Это общесистемная метрика: она включает все процессы на хосте, а не только clickhouse-server.

<div id="osmemoryfreepluscached">
  ### OSMemoryFreePlusCached
</div>

Объём свободной памяти и памяти, занятой кэшем страниц ОС, на хост-системе, в байтах. Эта память доступна для использования программами. Значение должно быть очень близким к `OSMemoryAvailable`. Это общесистемная метрика: она включает все процессы на хост-машине, а не только clickhouse-server.

<div id="osmemoryfreewithoutcached">
  ### OSMemoryFreeWithoutCached
</div>

Объём свободной памяти в хостовой системе, в байтах. Сюда не входит память, используемая кэшем страниц ОС. Память кэша страниц также доступна программам, поэтому значение этой метрики может вводить в заблуждение. Вместо неё используйте метрику `OSMemoryAvailable`. Для удобства мы также предоставляем метрику `OSMemoryFreePlusCached`, которая должна быть в некоторой степени похожа на OSMemoryAvailable. См. также: https://www.linuxatemyram.com/. Это общесистемная метрика: она включает все процессы на хостовой машине, а не только clickhouse-server.
