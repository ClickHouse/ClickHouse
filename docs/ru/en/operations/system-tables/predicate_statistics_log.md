<div id="description">
  ## Описание
</div>

Содержит статистику селективности по выборке, собранную при чтении из таблиц `MergeTree`. Таблица заполняется только тогда, когда [`predicate_statistics_sample_rate`](/ru/operations/settings/settings#predicate_statistics_sample_rate) больше `0`.

Используйте эту таблицу, чтобы оценить, насколько селективны пользовательские предикаты в реальных рабочих нагрузках и сколько гранул остается после фильтрации по первичному ключу или skip-индексу. Эти данные предназначены для выработки рекомендаций по индексам и проекциям на основе рабочих нагрузок.

<div id="row-shapes">
  ## Структуры строк
</div>

Один запрос может порождать два типа строк в `system.predicate_statistics_log`:

* **Строки фильтра**, записываемые для каждого шага prewhere/filter в `MergeTreeSelectProcessor`. В них заполняются `predicate_expression`, `input_rows`, `passed_rows`, `filter_selectivity`, а также столбцы, относящиеся ко всему предикату: `total_input_rows`, `total_passed_rows`, `total_selectivity`. Столбцы, связанные с индексами, остаются пустыми.
* **Строки индексов**, записываемые для каждого шага чтения в `ReadFromMergeTree`. В них заполняются массивы `index_names`, `index_types`, `total_granules`, `granules_after` и `index_selectivities` — по одному элементу на каждый этап индекса (первичный ключ, партиция, индексы пропуска данных). Столбцы, связанные с предикатами, остаются пустыми.

Строки фильтра и строки индексов для одного и того же запроса имеют одинаковые `query_id` и `table`, поэтому при необходимости их можно объединить.

<div id="sampling-and-overhead">
  ## Сэмплирование и накладные расходы
</div>

Сэмплирование задаётся параметром [`predicate_statistics_sample_rate`](/ru/operations/settings/settings#predicate_statistics_sample_rate):

* `0` отключает сбор.
* `1` сэмплирует каждый запрос.
* `N > 1` сэмплирует примерно `1 / N` запросов на основе хеша `query_id`.

Меньшие значения дают больше данных, но увеличивают нагрузку на CPU при чтении и число записей в системный журнал. После включения этой настройки используйте [`SYSTEM FLUSH LOGS`](/ru/sql-reference/statements/system#flush-logs), если нужно, чтобы строки появились сразу.

* `query_id` ([String](/ru/sql-reference/data-types/string)) — Идентификатор запроса для связи с query&#95;log.
* `predicate_expression` ([String](/ru/sql-reference/data-types/string)) — Полное выражение фильтра, обрабатываемое на этом шаге prewhere/filter (дамп ActionsDAG).
* `input_rows` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Строки, поступающие на этот шаг prewhere/filter.
* `passed_rows` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Строки, прошедшие этот шаг prewhere/filter.
* `filter_selectivity` ([Float64](/ru/sql-reference/data-types/float)) — Селективность этого шага: passed&#95;rows / input&#95;rows.
* `total_input_rows` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Строки, поступающие на первый шаг prewhere (общее количество строк, прочитанных из гранул).
* `total_passed_rows` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Строки, прошедшие все шаги prewhere (строки, переданные запросу).
* `total_selectivity` ([Float64](/ru/sql-reference/data-types/float)) — Селективность всего предиката: total&#95;passed&#95;rows / total&#95;input&#95;rows.
* `index_names` ([Array(LowCardinality(String))](/ru/sql-reference/data-types/array)) — Имена применённых индексов, например [&#39;PrimaryKey&#39;, &#39;idx&#95;bf&#95;status&#39;] (только для строк с индексами).
* `index_types` ([Array(LowCardinality(String))](/ru/sql-reference/data-types/array)) — Типы применённых индексов: PrimaryKey, Skip, MinMax, Partition (только для строк с индексами).
* `total_granules` ([Array(UInt64)](/ru/sql-reference/data-types/array)) — Гранулы, поступающие на каждый этап применения индекса (только для строк с индексами).
* `granules_after` ([Array(UInt64)](/ru/sql-reference/data-types/array)) — Гранулы, оставшиеся после каждого этапа применения индекса (только для строк с индексами).
* `index_selectivities` ([Array(Float64)](/ru/sql-reference/data-types/array)) — Селективность каждого индекса: granules&#95;after / total&#95;granules (только для строк с индексами).

<div id="example">
  ## Пример
</div>

```sql
SET predicate_statistics_sample_rate = 1;

SELECT *
FROM hits
WHERE URL LIKE '%/product/%' AND EventDate >= today() - 7
FORMAT Null;

SYSTEM FLUSH LOGS predicate_statistics_log;

SELECT
    query_id,
    predicate_expression,
    round(filter_selectivity, 3) AS step_selectivity,
    round(total_selectivity, 3) AS query_selectivity,
    index_names,
    index_selectivities
FROM system.predicate_statistics_log
WHERE table = 'hits'
ORDER BY event_time DESC
LIMIT 10;
```
