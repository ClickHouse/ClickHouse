<div id="description">
  ## Описание
</div>

Содержит трассировки стека, собранные [выборочным профилировщиком запросов](../../operations/optimizing-performance/sampling-query-profiler.md).

ClickHouse создает эту таблицу, когда настроен раздел конфигурации сервера [trace&#95;log](../../operations/server-configuration-parameters/settings.md#trace_log). См. также настройки: [query&#95;profiler&#95;real&#95;time&#95;period&#95;ns](../../operations/settings/settings.md#query_profiler_real_time_period_ns), [query&#95;profiler&#95;cpu&#95;time&#95;period&#95;ns](../../operations/settings/settings.md#query_profiler_cpu_time_period_ns), [memory&#95;profiler&#95;step](../../operations/settings/settings.md#memory_profiler_step),
[memory&#95;profiler&#95;sample&#95;probability](../../operations/settings/settings.md#memory_profiler_sample_probability), [trace&#95;profile&#95;events](../../operations/settings/settings.md#trace_profile_events).

Для анализа журналов используйте функции интроспекции `addressToLine`, `addressToLineWithInlines`, `addressToSymbol` и `demangle`.

<div id="columns">
  ## Столбцы
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/ru/sql-reference/data-types/lowcardinality)) — Имя хоста сервера, выполняющего запрос.
* `event_date` ([Date](/ru/sql-reference/data-types/date)) — Дата момента сэмплирования.
* `event_time` ([DateTime](/ru/sql-reference/data-types/datetime)) — Временная метка момента сэмплирования.
* `event_time_microseconds` ([DateTime64(6)](/ru/sql-reference/data-types/datetime64)) — Временная метка момента сэмплирования с точностью до микросекунд.
* `timestamp_ns` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Временная метка момента сэмплирования в наносекундах.
* `revision` ([UInt32](/ru/sql-reference/data-types/int-uint)) — Ревизия сборки сервера ClickHouse. При подключении к серверу через `clickhouse-client` вы увидите строку вида `Connected to ClickHouse server version 19.18.1.`. Это поле содержит `revision`, а не `version` сервера.
* `trace_type` ([Enum8(&#39;Real&#39; = 0, &#39;CPU&#39; = 1, &#39;Memory&#39; = 2, &#39;MemorySample&#39; = 3, &#39;MemoryPeak&#39; = 4, &#39;ProfileEvent&#39; = 5, &#39;JemallocSample&#39; = 6, &#39;MemoryAllocatedWithoutCheck&#39; = 7, &#39;Instrumentation&#39; = 8)](/ru/sql-reference/data-types/enum)) — Тип трассировки: `Real` обозначает сбор трассировок стека по wall-clock time. `CPU` обозначает сбор трассировок стека по CPU time. `Memory` обозначает сбор событий выделения и освобождения памяти, когда выделение памяти превышает следующую водяную метку. `MemorySample` обозначает сбор случайных событий выделения и освобождения памяти. `MemoryPeak` обозначает сбор обновлений пикового потребления памяти. `ProfileEvent` обозначает сбор приращений profile events. `JemallocSample` обозначает сбор образцов jemalloc. `MemoryAllocatedWithoutCheck` обозначает сбор значительных выделений (&gt;16MiB), который выполняется без учета каких-либо ограничений памяти (только для разработчиков ClickHouse). `Instrumentation` обозначает traces, собранные с помощью instrumentation через XRay.
* `cpu_id` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Идентификатор CPU.
* `thread_id` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Идентификатор потока.
* `thread_name` ([LowCardinality(String)](/ru/sql-reference/data-types/lowcardinality)) — Имя потока.
* `query_id` ([String](/ru/sql-reference/data-types/string)) — Идентификатор запроса, который можно использовать для получения сведений о запросе, выполнявшемся из системной таблицы query&#95;log.
* `trace` ([Array(UInt64)](/ru/sql-reference/data-types/array)) — Трассировка стека в момент сэмплирования. Каждый элемент — виртуальный адрес памяти внутри процесса сервера ClickHouse.
* `size` ([Int64](/ru/sql-reference/data-types/int-uint)) — Для типов трассировки Memory, MemorySample, MemoryAllocatedWithoutCheck или MemoryPeak это объем выделенной памяти; для остальных типов трассировки — 0.
* `ptr` ([UInt64](/ru/sql-reference/data-types/int-uint)) — Адрес выделенного фрагмента.
* `memory_context` ([Enum8(&#39;Unknown&#39; = -1, &#39;Global&#39; = 0, &#39;User&#39; = 1, &#39;Process&#39; = 2, &#39;Thread&#39; = 3, &#39;Max&#39; = 4)](/ru/sql-reference/data-types/enum)) — Контекст трекера памяти (только для Memory/MemoryPeak): контекст `Unknown` не определен для этого типа трассировки. `Global` обозначает контекст сервера. `User` обозначает контекст пользователя/merge. `Process` обозначает контекст процесса (то есть запроса). `Thread` обозначает контекст потока (потока конкретного процесса). `Max` — это специальное значение, означающее, что трекер памяти не заблокирован (для столбца blocked&#95;context).
* `memory_blocked_context` ([Enum8(&#39;Unknown&#39; = -1, &#39;Global&#39; = 0, &#39;User&#39; = 1, &#39;Process&#39; = 2, &#39;Thread&#39; = 3, &#39;Max&#39; = 4)](/ru/sql-reference/data-types/enum)) — Контекст, для которого заблокирован трекер памяти (только для разработчиков ClickHouse): контекст `Unknown` не определен для этого `trace_type`. `Global` обозначает контекст сервера. `User` обозначает пользовательский контекст/контекст merge. `Process` обозначает контекст процесса (то есть запроса). `Thread` обозначает контекст потока (потока конкретного процесса). `Max` — это специальное значение, означающее, что трекер памяти не заблокирован (для столбца `blocked_context`).
* `event` ([LowCardinality(String)](/ru/sql-reference/data-types/lowcardinality)) — Для типа trace `ProfileEvent` это имя обновленного события профиля, для остальных типов trace — пустая строка.
* `increment` ([Int64](/ru/sql-reference/data-types/int-uint)) — Для типа trace `ProfileEvent` это величина приращения события профиля, для остальных типов trace — 0.
* `symbols` ([Array(LowCardinality(String))](/ru/sql-reference/data-types/array)) — Если символизация включена, содержит деманглированные имена символов, соответствующие `trace`. Символизацию можно включить или отключить с помощью настройки `symbolize` в `trace_log` в файле конфигурации сервера.
* `lines` ([Array(LowCardinality(String))](/ru/sql-reference/data-types/array)) — Если символизация включена, содержит строки с именами файлов и номерами строк, соответствующие `trace`.
* `function_id` ([Nullable(Int32)](/ru/sql-reference/data-types/nullable)) — Для типа trace `Instrumentation` это ID, назначенный функции в разделе `xray_instr_map` ELF-бинарного файла.
* `function_name` ([Nullable(String)](/ru/sql-reference/data-types/nullable)) — Для типа trace `Instrumentation` это имя инструментированной функции.
* `handler` ([Nullable(String)](/ru/sql-reference/data-types/nullable)) — Для типа trace `Instrumentation` это обработчик инструментированной функции.
* `entry_type` ([Nullable(Enum8(&#39;Entry&#39; = 0, &#39;Exit&#39; = 1))](/ru/sql-reference/data-types/nullable)) — Для типа trace `Instrumentation` это тип входа инструментированной функции.
* `duration_nanoseconds` ([Nullable(UInt64)](/ru/sql-reference/data-types/nullable)) — Для типа trace `Instrumentation` это время выполнения функции в наносекундах.

**Псевдонимы:**

* `build_id` — псевдоним для `'E2EEB60ED9503BFFA825B628D480CCDC40B2D416'`.

{/*AUTOGENERATED_END*/ }

Символизацию можно включить или отключить в параметре `symbolize` раздела `trace_log` в конфигурационном файле сервера.

<div id="chrome-event-trace-format">
  ## Преобразование в формат трассировки событий Chrome
</div>

Данные профилирования можно преобразовать в формат трассировки событий Chrome с помощью следующего запроса. Сохраните запрос в файл `chrome_trace.sql`:

```sql
WITH traces AS (
    SELECT * FROM system.trace_log
    WHERE event_date >= today() AND trace_type = 'Instrumentation' AND handler = 'profile'
    ORDER BY event_time, entry_type
)
SELECT
    format(
        '{{"traceEvents": [{}\n]}}',
        arrayStringConcat(
            groupArray(
                format(
                    '\n{{"name": "{}", "cat": "clickhouse", "ph": "{}", "ts": {}, "pid": 1, "tid": {}, "args": {{"query_id": "{}", "cpu_id": {}, "stack": [{}]}}}},',
                    function_name,
                    if(entry_type = 0, 'B', 'E'),
                    timestamp_ns/1000,
                    toString(thread_id),
                    query_id,
                    cpu_id,
                    arrayStringConcat(arrayMap((x, y) -> concat('"', x, ': ', y, '", '), lines, symbols))
                )
            )
        )
    )
FROM traces;
```

И выполнить его в клиенте ClickHouse, чтобы экспортировать результат в файл `trace.json`, который затем можно импортировать либо в [Perfetto](https://ui.perfetto.dev/), либо в [speedscope](https://www.speedscope.app/).

```bash
echo $(clickhouse client --query "$(cat chrome_trace.sql)") > trace.json
```

Мы можем опустить часть со стеком, если нужен более компактный, но менее информативный трейс.
