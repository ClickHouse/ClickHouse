Страница поиска по документации — это небольшой автономный веб-интерфейс для мгновенного поиска по встроенной справочной документации. Он доступен по пути `/docs` на любом HTTP-порту ClickHouse.

Чтобы открыть её, перейдите по пути `/docs` на любом HTTP-порту ClickHouse (например, `http://localhost:8123/docs`).

<div id="what-it-does">
  ## Что здесь можно делать
</div>

По мере ввода страница отправляет HTTP-запросы к таблице [`system.documentation`](/ru/operations/system-tables/documentation) и отображает Markdown выбранной сущности. Поскольку она читает `system.documentation`, охватываются все сущности, доступные через эту таблицу, — функции, агрегатные функции, табличные функции, движки таблиц, движки баз данных, типы данных, настройки, форматы, кодеки сжатия, события профилирования, метрики, сами системные таблицы и многое другое — и содержимое всегда соответствует документации, встроенной в работающий сервер.

Введите текст в поле поиска, и совпадения появятся в списке с цветовой маркировкой по типам; при выборе совпадения отображается его документация. Отображение включает:

* ссылку с иконкой карандаша рядом с заголовком сущности, которая открывает её исходный файл на GitHub; путь берётся из столбца `source` таблицы `system.documentation`;
* подсветку синтаксиса ClickHouse SQL в блоках кода с использованием того же встроенного лексера (`Lexer.wasm`), что и в интерфейсе [`/play`](/ru/interfaces/http);
* формулы TeX через [KaTeX](https://katex.org/) (например, формулу на странице `corr`);
* врезки `:::note`/`:::tip`/…, якоря заголовков с ссылками, которыми можно делиться, и кнопку «Копировать», появляющуюся при наведении на блоки кода;
* относительные ссылки, которые внутри приложения ведут к другой документированной сущности, если она существует, а в противном случае — на `https://clickhouse.com/docs`; ссылки &quot;Related&quot; и &quot;Alias of&quot; становятся внутренними ссылками приложения.

Текущий поисковый запрос, открытая сущность и раздел дублируются во фрагменте URL, поэтому на конкретную страницу или раздел можно дать прямую ссылку, а состояние восстанавливается при переходах назад/вперёд в браузере. Переключатель светлой/тёмной темы (с автоопределением) соответствует `/play`.

<div id="connecting">
  ## Подключение
</div>

В шапке страницы есть поля `URL`, `user` и `password` — так же, как в `/play`. Когда страница отдается ClickHouse, в качестве `URL` по умолчанию используется текущий адрес; когда страница открывается как локальный файл, по умолчанию используется `http://localhost:8123/`, поэтому страницу можно открывать локально и для работы с удаленным сервером. Кэш имен перекрестных ссылок автоматически пересобирается при изменении подключения.

<div id="assets">
  ## Ресурсы
</div>

Все ресурсы — включая средство рендеринга Markdown ([Marked](https://marked.js.org/)), средство рендеринга математических формул (KaTeX вместе со своими шрифтами) и SQL-лексер — отдаются непосредственно из бинарного файла ClickHouse, когда страница обслуживается по HTTP. В HTTP-источнике ClickHouse не загружаются сторонние CDN, поэтому страница полностью самодостаточна, работает офлайн и не выполняет сторонний сетевой код наряду с учетными данными, с которыми она работает.

<div id="security">
  ## Соображения безопасности
</div>

Страница отправляет запросы к HTTP-конечной точке ClickHouse с учетными данными, указанными в шапке, поэтому здесь действуют те же ограничения, что и для HTTP-протокола:

* Всегда открывайте `/docs` по HTTPS в недоверенных средах, чтобы защитить учетные данные.
* Ограничивайте доступ на уровне сети (`firewall`, обратный прокси или конфигурация `listen_host`) так же, как и доступ к HTTP-протоколу.

`system.documentation` содержит только встроенную в сервер статическую справочную документацию, поэтому страница не раскрывает данные из ваших таблиц.
