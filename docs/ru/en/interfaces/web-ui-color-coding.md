Встроенный веб-интерфейс SQL (`play.html`, доступный по пути [`/play`](/ru/interfaces/http) на любом HTTP-порту ClickHouse) может раскрашивать ячейки результатов, чтобы закономерности в столбце было легче заметить с первого взгляда. Для каждого столбца предусмотрен собственный режим цветового кодирования, который можно переключать независимо.

<div id="switching-the-mode">
  ## Переключение режима
</div>

Справа от каждого заголовка столбца отображается значок 🌈. Нажмите его, чтобы по кругу переключать столбец между доступными режимами. На устройствах с указателем, поддерживающим наведение (например, мышью), значок показывается только при наведении на заголовок, чтобы не отвлекать в остальное время; на сенсорных и других устройствах с грубым указателем, где наведения нет, значок показывается всегда, чтобы его можно было нажать напрямую.

Набор режимов, доступных для столбца, зависит от его типа:

* Числовые столбцы и столбцы `Date`/`DateTime`/`Date32`/`DateTime64` циклически переключаются между `bar` → `heatmap` → `categorical` → `none`.
* Все остальные столбцы переключаются между `none` и `categorical`.

Режим по умолчанию — `bar` для числовых столбцов и `none` для всех остальных, включая столбцы даты и времени.

<div id="modes">
  ## Режимы
</div>

* **`bar`** — рисует в ячейке горизонтальную полосу, пропорциональную значению. Для числовых столбцов полоса растёт от нулевой отметки; для столбцов `Date`/`DateTime` вместо этого она охватывает диапазон `min`..`max` столбца, поскольку нулевая отметка не имеет смысла для временных меток.
* **`heatmap`** — заполняет весь фон ячейки цветом, который кодирует значение, масштабированное между минимальным и максимальным значениями столбца.
* **`categorical`** — заполняет фон ячейки цветом, полученным хешированием её значения, так что одинаковые значения получают один и тот же цвет, а разные — разные цвета. Это работает для любого типа столбца.
* **`none`** — без цветового кодирования.

Столбцы `Date`, `DateTime`, `Date32` и `DateTime64` окрашиваются по их временному значению, интерпретируемому в UTC, чтобы шкала не зависела от часового пояса браузера пользователя.

Для цветов фона `heatmap` и `categorical` используется цветовое пространство `oklch`: меняется только цветовой тон, а светлота и цветность остаются фиксированными для каждой темы, чтобы текст в ячейке оставался читаемым и в светлой, и в тёмной теме. Фон заполняет всю ячейку, даже если строка занимает больше одной строки.

<div id="categorical-emphasis">
  ## Категориальное выделение при выборе
</div>

В режиме `categorical` при выборе ячейки выделяются другие ячейки с тем же значением: они отображаются более жирным шрифтом и текстом с максимальным контрастом (чисто белым в тёмной теме и чисто чёрным в светлой). Сама выбранная ячейка при этом не выделяется. Это позволяет легко увидеть, где ещё в столбце встречается конкретное значение.

<div id="persistence">
  ## Сохранение состояния
</div>

Выбранные режимы запоминаются для каждого столбца в URL страницы и в истории браузера, поэтому они сохраняются при перезагрузке страницы, если поделиться ссылкой, а также при переходах назад и вперёд. Чтобы URL и состояние истории оставались компактными, сохраняются только значения, отличающиеся от используемых по умолчанию.

<div id="limitations">
  ## Ограничения
</div>

* В вертикальном (транспонированном) представлении с одной строкой цветовое кодирование не отображается.
* Различия в `DateTime64(9)` меньше микросекунды не различаются на цветовой шкале, поскольку для градиента это визуально не имеет смысла.
