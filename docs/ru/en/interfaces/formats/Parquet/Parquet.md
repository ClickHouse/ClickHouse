<div id="description">
  ## Описание
</div>

[Apache Parquet](https://parquet.apache.org/) — столбцовый формат хранения данных, широко распространённый в экосистеме Hadoop. ClickHouse поддерживает чтение и запись в этом формате.

При записи в файл Parquet типы данных, для которых нет соответствующего типа Parquet, преобразуются в ближайший доступный тип:

| Тип данных ClickHouse                                                  | Тип Parquet                                         |
| ---------------------------------------------------------------------- | --------------------------------------------------- |
| [IPv4](/ru/sql-reference/data-types/ipv4.md)                              | `UINT_32`                                           |
| [IPv6](/ru/sql-reference/data-types/ipv6.md)                              | `FIXED_LEN_BYTE_ARRAY` (16 байт)                    |
| [Date](/ru/sql-reference/data-types/date.md) (16 бит)                     | `DATE` (32 бита)                                    |
| [DateTime](/ru/sql-reference/data-types/datetime.md) (32 бита, секунды)   | `TIMESTAMP` (64 бита, миллисекунды)                 |
| [Int128/UInt128/Int256/UInt256](/ru/sql-reference/data-types/int-uint.md) | `FIXED_LEN_BYTE_ARRAY` (16/32 байта, little-endian) |
| [Point](/ru/sql-reference/data-types/geo.md#point)                        | `BYTE_ARRAY` (WKB) + метаданные GeoParquet          |
| [LineString](/ru/sql-reference/data-types/geo.md#linestring)              | `BYTE_ARRAY` (WKB) + метаданные GeoParquet          |
| [Polygon](/ru/sql-reference/data-types/geo.md#polygon)                    | `BYTE_ARRAY` (WKB) + метаданные GeoParquet          |
| [MultiLineString](/ru/sql-reference/data-types/geo.md#multilinestring)    | `BYTE_ARRAY` (WKB) + метаданные GeoParquet          |
| [MultiPolygon](/ru/sql-reference/data-types/geo.md#multipolygon)          | `BYTE_ARRAY` (WKB) + метаданные GeoParquet          |

Массивы могут быть вложенными и могут принимать в качестве аргумента значение типа `Nullable`. Типы `Tuple` и `Map` также могут быть вложенными.

Типы данных столбцов таблицы ClickHouse могут отличаться от соответствующих полей вставляемых данных Parquet. При вставке данных ClickHouse интерпретирует типы данных в соответствии с таблицей выше, а затем [приводит](/ru/sql-reference/functions/type-conversion-functions#CAST) данные к типу, заданному для столбца таблицы ClickHouse. Например, столбец Parquet типа `UINT_32` можно прочитать в столбец ClickHouse типа [IPv4](/ru/sql-reference/data-types/ipv4.md).

Для некоторых типов Parquet нет близкого соответствия в ClickHouse. Мы читаем их следующим образом:

* `TIME` (время суток) читается как временная метка. Например, `10:23:13.000` становится `1970-01-01 10:23:13.000`.
* `TIMESTAMP`/`TIME` с `isAdjustedToUTC=false` — это локальное время по часам (поля года, месяца, дня, часа, минуты, секунды и долей секунды в локальном часовом поясе, независимо от того, какой именно часовой пояс считается локальным), аналогично SQL `TIMESTAMP WITHOUT TIME ZONE`. Вместо этого ClickHouse читает его так, как если бы это была временная метка UTC. Например, `2025-09-29 18:42:13.000` (представляющая показание локальных часов) становится `2025-09-29 18:42:13.000` (`DateTime64(3, 'UTC')`, представляющий момент времени). Если преобразовать в String, будут показаны правильные год, месяц, день, час, минута, секунда и доля секунды, которые затем можно интерпретировать как относящиеся к некоторому локальному часовому поясу, а не к UTC. Парадоксально, но смена типа с `DateTime64(3, 'UTC')` на `DateTime64(3)` не помогла бы, поскольку оба типа представляют момент времени, а не показание часов, при этом `DateTime64(3)` форматировался бы неверно с использованием локального часового пояса.
* `INTERVAL` в настоящее время читается как `FixedString(12)` с сырым двоичным представлением временного интервала, закодированным в файле Parquet.

<div id="geo-types">
  ## Гео-типы (GeoParquet)
</div>

ClickHouse поддерживает чтение и запись геометрических столбцов в соответствии со спецификацией [GeoParquet](https://geoparquet.org/). Геометрические столбцы хранятся как полезная нагрузка `BYTE_ARRAY`, закодированная в [WKB](https://libgeos.org/specifications/wkb/) (или как WKT при чтении), а JSON-ключ `geo` в метаданных Parquet на уровне файла описывает кодировку, геометрический тип и CRS каждого такого столбца.

<div id="read">
  ### Поведение при чтении
</div>

При чтении геометрические столбцы сопоставляются с соответствующими ClickHouse [гео-типами данных](/ru/sql-reference/data-types/geo.md):

* Столбец, объявленный как `Point`, `LineString`, `Polygon`, `MultiLineString` или `MultiPolygon`, считывается в соответствующий гео-тип ClickHouse.
* Столбец с несколькими или неизвестными типами геометрии считывается в тип [`Geometry`](/ru/sql-reference/data-types/geo.md#geometry), который представляет собой `Variant` из всех поддерживаемых гео-типов.
* Если запрошенный тип столбца — `String`, метаданные GeoParquet игнорируются, и возвращается необработанная закодированная полезная нагрузка геометрии в исходном виде — байты WKB или WKT, в зависимости от кодировки, объявленной для столбца GeoParquet. Это также верно, если для настройки [`input_format_parquet_allow_geoparquet_parser`](/ru/operations/settings/settings-formats.md#input_format_parquet_allow_geoparquet_parser) установлено значение `0`.

<div id="write">
  ### Поведение при записи
</div>

При записи столбцы верхнего уровня типа `Point`, `LineString`, `Polygon`, `MultiLineString` или `MultiPolygon` кодируются как `BYTE_ARRAY` (WKB), а соответствующие JSON-метаданные `geo` добавляются в нижний колонтитул файла Parquet. `Variant` верхнего уровня [`Geometry`](/ru/sql-reference/data-types/geo.md#geometry) также кодируется как полезная нагрузка `BYTE_ARRAY` WKB (его подзначения преобразуются в WKB и сохраняются в столбце `Nullable(String)`), но `geo`-метаданные для него не записываются, поэтому при чтении результат не распознаётся как столбец геометрии GeoParquet. Другие типы, связанные с геоданными, такие как [`Ring`](/ru/sql-reference/data-types/geo.md#ring), записываются в своём исходном внутреннем представлении без метаданных GeoParquet. Это поведение можно полностью отключить, установив [`output_format_parquet_geometadata`](/ru/operations/settings/settings-formats.md#output_format_parquet_geometadata) в `0`; в этом случае даже поддерживаемые гео-типы записываются в своём исходном внутреннем представлении (`Point` как `Tuple(Float64, Float64)`, `LineString` как `Array(Point)`, `Polygon` как `Array(Array(Point))` и т. д.), и метаданные GeoParquet не записываются.

Столбцы Geometry должны находиться в корне схемы или быть вложены в `Tuple` (`struct`); вложение в `Array` или `Map` не поддерживается. `Nullable` также не поддерживается для гео-столбцов.

<div id="reading-data">
  ### Чтение данных
</div>

Считайте данные в формате `Parquet`:

```sql
SELECT *
FROM football
INTO OUTFILE 'football.parquet'
FORMAT Parquet
```

:::tip
Parquet — это двоичный формат, который не выводится в терминале в человекочитаемом виде. Используйте предложение `INTO OUTFILE` для вывода файлов Parquet.
:::

Для обмена данными с Hadoop можно использовать [`движок таблицы HDFS`](/ru/engines/table-engines/integrations/hdfs.md).
