Веб-терминал — это интерфейс в браузере, который предоставляет интерактивный сеанс `clickhouse-client` через WebSocket. Он доступен на любом HTTP-порту ClickHouse по пути `/webterminal`.

Перейдите по адресу `/webterminal` на любом HTTP-порту ClickHouse (например, `http://localhost:8123/webterminal`), чтобы открыть терминал.

<div id="enabling-the-feature">
  ## Включение и отключение возможности
</div>

Конечная точка `/webterminal` включена по умолчанию и управляется настройкой сервера `enable_webterminal`. Чтобы отключить её, задайте для этой настройки значение `false`; после этого запросы к `/webterminal` будут возвращать HTTP-статус `403 Forbidden`.

```xml
<clickhouse>
    <enable_webterminal>false</enable_webterminal>
</clickhouse>
```

:::note
`enable_webterminal` заменяет прежний параметр `allow_experimental_webterminal`. Старое имя по-прежнему поддерживается для обеспечения обратной совместимости, если `enable_webterminal` не задан.
:::

<div id="authentication">
  ## Аутентификация
</div>

Веб-терминал использует для аутентификации пользователя те же проверки `Session` и контроля доступа, что и HTTP-протокол, но учетные данные передаются по уже установленному соединению WebSocket, а не через HTTP-запрос Upgrade. После завершения рукопожатия WebSocket браузер отправляет первое сообщение в формате JSON:

```json
{"type": "auth", "user": "<user>", "password": "<password>"}
```

Это позволяет не передавать учетные данные в URL-параметрах запроса или в заголовках `Authorization`, добавляемых к запросу upgrade, где они могут попасть в историю браузера, журналы доступа сервера и журналы обратного прокси. URL-параметры, HTTP Basic и заголовки `X-ClickHouse-User`/`X-ClickHouse-Key` в запросе upgrade намеренно **не** учитываются `/webterminal`.

Недействительные учетные данные приводят к тому, что сервер закрывает WebSocket с кодом `1008`; интерфейс браузера снова запрашивает учетные данные.

<div id="session">
  ## Как выглядит сеанс
</div>

После аутентификации сервер запускает `clickhouse-client` в псевдотерминале и передает его ввод и вывод через WebSocket. Сеанс поддерживает все возможности `clickhouse-client`, включая:

* Подсветку синтаксиса.
* Автодополнение.
* Многострочные запросы.
* Историю команд (она хранится на стороне сервера в течение сеанса).

Для отрисовки используется [xterm.js](https://xtermjs.org/). Все ресурсы отдаются непосредственно из бинарного файла ClickHouse — никакие сторонние CDN не загружаются.

<div id="play-integration">
  ## Интеграция с `/play`
</div>

SQL-веб-интерфейс [`/play`](/ru/interfaces/http) встраивает веб-терминал в виде закрепляемой панели. Открывайте и скрывайте его с помощью значка терминала на боковой панели или нажмите клавишу `~`, когда редактор запросов пуст. При загрузке страница `/play` проверяет доступность `/webterminal` и скрывает элементы управления терминалом, если конечная точка недоступна (например, когда `enable_webterminal` имеет значение `false`).

<div id="security">
  ## Рекомендации по безопасности
</div>

Веб-терминал предоставляет интерактивный сеанс, похожий на командную оболочку, любому, кто может пройти аутентификацию через HTTP-конечную точку ClickHouse, поэтому здесь действуют те же предостережения, что и для HTTP-протокола:

* Всегда предоставляйте доступ к `/webterminal` по HTTPS в ненадежных средах, чтобы защитить учетные данные и трафик сеанса.
* Ограничивайте доступ на уровне сети (firewall, обратный прокси или конфигурация `listen_host`) так же, как и доступ к HTTP-протоколу.
* Конечная точка сверяет заголовок `Origin` с `Host`, чтобы снизить риск межсайтового перехвата WebSocket; если вы терминируете TLS вне ClickHouse, соответствующим образом настройте обратные прокси.
* За обратным прокси, терминирующим TLS, соединение с ClickHouse на стороне upstream использует обычный `http`, хотя браузер работает по `https`, поэтому строгая проверка same-origin будет отклонять легитимные соединения. Для таких развертываний задайте `webterminal_allowed_origins` в виде разделенного запятыми списка полных origins, которым разрешено открывать WebSocket-сеансы; если этот параметр не пуст, он заменяет проверку same-origin по умолчанию. Пример: `<webterminal_allowed_origins>https://example.com,https://app.example.com:8443</webterminal_allowed_origins>`.

Обработчик также проверяет соответствие WebSocket-протоколу согласно RFC 6455: немаскированные клиентские кадры, зарезервированные opcodes, слишком большие или фрагментированные управляющие кадры, а также зарезервированные биты RSV отклоняются с кодами закрытия protocol-error.

<div id="platform">
  ## Доступность на платформах
</div>

Обработчик компилируется на всех платформах, поддерживаемых ClickHouse. Слой псевдотерминала, используемый встроенным модулем запуска `clickhouse-client`, реализован на основе переносимых примитивов POSIX (`posix_openpt`/`grantpt`/`unlockpt`), с отдельной веткой для Linux, использующей потокобезопасный `ptsname_r`. Ссылки на `/webterminal` на начальной странице ClickHouse и в `/play` автоматически скрываются, если конечная точка недоступна (например, когда `enable_webterminal` имеет значение `false`).
