Оператор `LIMIT` задаёт, сколько строк будет возвращено в результате запроса.

<div id="basic-syntax">
  ## Основной синтаксис
</div>

**Выбор первых строк:**

```sql
LIMIT m
```

Возвращает первые `m` строк из результата или все записи, если их меньше `m`.

**Альтернативный синтаксис TOP (совместимый с MS SQL Server):**

```sql
-- SELECT TOP number|percent column_name(s) FROM table_name
SELECT TOP 10 * FROM numbers(100);
SELECT TOP 0.1 * FROM numbers(100);
```

Это эквивалентно `LIMIT m` и может использоваться для совместимости с запросами к Microsoft SQL Server.

**Выборка со смещением:**

```sql
LIMIT m OFFSET n
-- or equivalently:
LIMIT n, m
```

Пропускает первые `n` строк, а затем возвращает следующие `m` строк.

В обеих формах `n` и `m` должны быть неотрицательными целыми числами.

<div id="negative-limits">
  ## Отрицательные ограничения
</div>

Выбирайте строки с *конца* результирующего набора с помощью отрицательных значений:

| Синтаксис            | Результат                                              |
| -------------------- | ------------------------------------------------------ |
| `LIMIT -m`           | Последние `m` строк                                    |
| `LIMIT -m OFFSET -n` | Последние `m` строк после пропуска последних `n` строк |
| `LIMIT m OFFSET -n`  | Первые `m` строк после пропуска последних `n` строк    |
| `LIMIT -m OFFSET n`  | Последние `m` строк после пропуска первых `n` строк    |

Синтаксис `LIMIT -n, -m` эквивалентен `LIMIT -m OFFSET -n`.

<div id="fractional-limits">
  ## Дробные ограничения
</div>

Используйте десятичные значения от 0 до 1, чтобы выбрать процент строк:

| Синтаксис               | Результат                                             |
| ----------------------- | ----------------------------------------------------- |
| `LIMIT 0.1`             | Первые 10% строк                                      |
| `LIMIT 1 OFFSET 0.5`    | Медианная строка                                      |
| `LIMIT 0.25 OFFSET 0.5` | Третий квартиль (25% строк после пропуска первых 50%) |

:::note

* Дробные значения должны иметь тип [Float64](../../data-types/float.md) и быть больше 0, но меньше 1.
* Дробное число строк округляется вверх до ближайшего целого.
  :::

<div id="combining-limit-types">
  ## Комбинирование типов ограничений
</div>

Можно сочетать стандартные целые числа с дробными или отрицательными смещениями:

```sql
LIMIT 10 OFFSET 0.5    -- 10 rows starting from the halfway point
LIMIT 10 OFFSET -20    -- 10 rows after skipping the last 20
```

<div id="limit--with-ties-modifier">
  ## LIMIT ... WITH TIES
</div>

Модификатор `WITH TIES` включает дополнительные строки, у которых значения `ORDER BY` совпадают со значениями последней строки, попавшей в ограничение.

```sql
SELECT * FROM (
    SELECT number % 50 AS n FROM numbers(100)
) ORDER BY n LIMIT 0, 5
```

```response
┌─n─┐
│ 0 │
│ 0 │
│ 1 │
│ 1 │
│ 2 │
└───┘
```

При использовании `WITH TIES` включаются все строки, соответствующие последнему значению:

```sql
SELECT * FROM (
    SELECT number % 50 AS n FROM numbers(100)
) ORDER BY n LIMIT 0, 5 WITH TIES
```

```response
┌─n─┐
│ 0 │
│ 0 │
│ 1 │
│ 1 │
│ 2 │
│ 2 │
└───┘
```

Строка 6 включена, потому что у неё то же значение (`2`), что и у строки 5.

То же самое происходит, когда смещение задаётся с помощью ключевого слова `OFFSET`:

```sql
SELECT * FROM (
    SELECT number % 50 AS n FROM numbers(100)
) ORDER BY n LIMIT 3 OFFSET 2 WITH TIES
```

```response
┌─n─┐
│ 1 │
│ 1 │
│ 2 │
│ 2 │
└───┘
```

Если пропустить первые 2 строки и выбрать 3, обычно результат будет `1, 1, 2`, но в него также попадёт вторая `2`, потому что она совпадает с последней строкой.

`WITH TIES` также работает с отрицательными LIMIT и OFFSET. В результат включаются дополнительные строки, у которых значения `ORDER BY` совпадают со значениями первой выбранной строки:

```sql
SELECT number % 3 AS n FROM numbers(15)
ORDER BY n LIMIT -4 OFFSET -3 WITH TIES
```

```response
┌─n─┐
│ 1 │
│ 1 │
│ 1 │
│ 1 │
│ 1 │
│ 2 │
│ 2 │
└───┘
```

Без `WITH TIES` результат был бы `1, 1, 2, 2`. С `WITH TIES` добавляются три дополнительные строки со значением `1`, поскольку они имеют то же значение, что и первая выбранная строка.

Этот модификатор можно комбинировать с модификатором [`ORDER BY ... WITH FILL`](/ru/sql-reference/statements/select/order-by#order-by-expr-with-fill-modifier).

<div id="considerations">
  ## Что следует учитывать
</div>

**Недетерминированные результаты:** Без [`ORDER BY`](../../../sql-reference/statements/select/order-by.md) возвращаемые строки могут быть произвольными и меняться от запроса к запросу.

**Ограничение на стороне сервера:** На количество возвращаемых строк также может влиять настройка [limit](../../../operations/settings/settings.md#limit).
