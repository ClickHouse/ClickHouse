ClickHouse периодически обновляет словари в соответствии с тегом `LIFETIME` (задаётся в секундах).
`LIFETIME` — это интервал обновления для полностью загруженных словарей и интервал инвалидации для словарей с кэшем.

Во время обновления старая версия словаря по-прежнему доступна для запросов.
Обновления словаря не блокируют запросы, за исключением первой загрузки при первом использовании.
Если во время обновления происходит ошибка, она записывается в журнал сервера, и запросы могут продолжать использовать старую версию словаря.
Если словарь успешно обновляется, старая версия словаря [атомарно](/ru/concepts/glossary#atomicity) заменяется.

Пример настроек:

<CloudDetails />

```xml
<dictionary>
    ...
    <lifetime>300</lifetime>
    ...
</dictionary>
```

или

```sql
CREATE DICTIONARY (...)
...
LIFETIME(300)
...
```

Значение `<lifetime>0</lifetime>` (`LIFETIME(0)`) не позволяет словарям обновляться.

Вы можете задать интервал обновления, и ClickHouse выберет случайный момент времени с равномерным распределением в пределах этого диапазона. Это необходимо, чтобы распределить нагрузку на источник словаря при обновлении на большом количестве серверов.

Пример настроек:

```xml
<dictionary>
    ...
    <lifetime>
        <min>300</min>
        <max>360</max>
    </lifetime>
    ...
</dictionary>
```

или

```sql
LIFETIME(MIN 300 MAX 360)
```

Если `<min>0</min>` и `<max>0</max>`, ClickHouse не перезагружает словарь по тайм-ауту.
В этом случае ClickHouse может перезагрузить словарь раньше, если был изменён файл конфигурации словаря или была выполнена команда `SYSTEM RELOAD DICTIONARY`.

При обновлении словарей сервер ClickHouse применяет различную логику в зависимости от типа [источника](./sources/):

* Для текстового файла проверяется время изменения. Если оно отличается от ранее зафиксированного времени, словарь обновляется.
* Словари из других источников по умолчанию обновляются каждый раз.

Для других источников (ODBC, PostgreSQL, ClickHouse и т. д.) можно настроить запрос, который будет обновлять словари, только если они действительно изменились, а не каждый раз. Для этого выполните следующие шаги:

* В таблице словаря должно быть поле, которое всегда изменяется при обновлении исходных данных.
* В настройках источника должен быть указан запрос, который получает изменяющееся поле. Сервер ClickHouse интерпретирует результат запроса как строку, и если эта строка изменилась по сравнению с предыдущим состоянием, словарь обновляется. Укажите запрос в поле `<invalidate_query>` в настройках [источника](./sources/).

Пример настроек:

```xml
<dictionary>
    ...
    <odbc>
      ...
      <invalidate_query>SELECT update_time FROM dictionary_source where id = 1</invalidate_query>
    </odbc>
    ...
</dictionary>
```

или

```sql
...
SOURCE(ODBC(... invalidate_query 'SELECT update_time FROM dictionary_source where id = 1'))
...
```

Для словарей `Cache`, `ComplexKeyCache`, `SSDCache` и `SSDComplexKeyCache` поддерживаются как синхронные, так и асинхронные обновления.

Для словарей `Flat`, `Hashed`, `HashedArray`, `ComplexKeyHashed` также можно запрашивать только те данные, которые изменились после предыдущего обновления. Если `update_field` указан в конфигурации источника словаря, в запрос данных будет добавлено значение времени предыдущего обновления в секундах. В зависимости от типа источника (Executable, HTTP, MySQL, PostgreSQL, ClickHouse или ODBC) перед запросом данных из внешнего источника к `update_field` будет применяться разная логика.

* Если источник — HTTP, то `update_field` будет добавлен как параметр запроса, а значением параметра станет время последнего обновления.
* Если источник — Executable, то `update_field` будет добавлен как аргумент исполняемого скрипта, а значением аргумента станет время последнего обновления.
* Если источник — ClickHouse, MySQL, PostgreSQL или ODBC, будет добавлено дополнительное предложение `WHERE`, в котором `update_field` сравнивается со временем последнего обновления по условию «больше или равно».
  * По умолчанию это условие `WHERE` проверяется на верхнем уровне SQL-запроса. При необходимости условие можно проверять и в любом другом предложении `WHERE` внутри запроса, используя ключевое слово `{condition}`. Пример:
    ```sql
    ...
    SOURCE(CLICKHOUSE(...
        update_field 'added_time'
        QUERY '
            SELECT my_arr.1 AS x, my_arr.2 AS y, creation_time
            FROM (
                SELECT arrayZip(x_arr, y_arr) AS my_arr, creation_time
                FROM dictionary_source
                WHERE {condition}
            )'
    ))
    ...
    ```

Если задан параметр `update_field`, можно также задать дополнительный параметр `update_lag`. Значение параметра `update_lag` вычитается из времени предыдущего обновления перед запросом обновлённых данных.

Пример настроек:

```xml
<dictionary>
    ...
        <clickhouse>
            ...
            <update_field>added_time</update_field>
            <update_lag>15</update_lag>
        </clickhouse>
    ...
</dictionary>
```

или

```sql
...
SOURCE(CLICKHOUSE(... update_field 'added_time' update_lag 15))
...
```
