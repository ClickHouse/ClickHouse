Существует по меньшей мере* два типа функций — обычные функции (их называют просто «функциями») и агрегатные функции. Это совершенно разные понятия. Обычные функции работают так, как если бы применялись к каждой строке отдельно (для каждой строки результат функции не зависит от других строк). Агрегатные функции накапливают набор значений из разных строк (то есть зависят от всего набора строк).

В этом разделе рассматриваются обычные функции. Об агрегатных функциях см. раздел «Агрегатные функции».

:::note
Существует и третий тип функций, к которому относится функция [&#39;arrayJoin&#39;](../functions/array-join.md). Кроме того, отдельно можно упомянуть и [табличные функции](../table-functions/index.md).
:::

<div id="strong-typing">
  ## Строгая типизация
</div>

В отличие от стандартного SQL, ClickHouse использует строгую типизацию. Иными словами, он не выполняет неявных преобразований между типами. Каждая функция работает с определённым набором типов. Это означает, что иногда приходится использовать функции преобразования типов.

<div id="common-subexpression-elimination">
  ## Устранение общих подвыражений
</div>

Все выражения в запросе с одинаковым AST (одним и тем же деревом разбора или одним и тем же результатом синтаксического анализа) считаются имеющими одинаковые значения. Такие выражения объединяются и вычисляются один раз. Одинаковые подзапросы также устраняются таким же образом.

<div id="types-of-results">
  ## Типы результатов
</div>

Все функции возвращают одно значение (не несколько и не ноль). Тип результата обычно определяется только типами аргументов, а не их значениями. Исключения составляют функция `tupleElement` (оператор `a.N`) и функция `toFixedString`.

<div id="constants">
  ## Константы
</div>

Для некоторых аргументов некоторые функции могут работать только с константами. Например, правый аргумент оператора LIKE должен быть константой.
Почти все функции возвращают константу для константных аргументов. Исключение составляют функции, генерирующие случайные числа.
Функция &#39;now&#39; возвращает разные значения для запросов, выполненных в разное время, но результат считается константой, поскольку константность важна только в пределах одного запроса.
Константное выражение также считается константой (например, правая часть оператора LIKE может быть составлена из нескольких констант).

Функции могут быть реализованы по-разному для константных и неконстантных аргументов (то есть выполняется разный код). Но результаты для константы и обычного столбца, содержащего только одно и то же значение, должны совпадать.

<div id="null-processing">
  ## Обработка NULL
</div>

Функции ведут себя следующим образом:

* Если хотя бы один из аргументов функции равен `NULL`, результат функции также равен `NULL`.
* Особое поведение, которое отдельно указывается в описании каждой функции. В исходном коде ClickHouse для этих функций установлено `UseDefaultImplementationForNulls=false`.

<div id="constancy">
  ## Константность
</div>

Функции не могут изменять значения своих аргументов — любые изменения возвращаются в результате. Таким образом, результат вычисления отдельных функций не зависит от порядка, в котором эти функции записаны в запросе.

<div id="higher-order-functions">
  ## Функции высшего порядка
</div>

<div id="arrow-operator-and-lambda">
  ### Оператор `->` и функции lambda(params, expr)
</div>

Функции высшего порядка могут принимать в качестве функционального аргумента только лямбда-функции. Чтобы передать лямбда-функцию в функцию высшего порядка, используйте оператор `->`. Слева от стрелки указывается формальный параметр — любой идентификатор — либо несколько формальных параметров, то есть набор идентификаторов в кортеже. Справа от стрелки находится выражение, которое может использовать эти формальные параметры, а также любые столбцы таблицы.

Примеры:

```python
x -> 2 * x
str -> str != Referer
```

Лямбда-функцию, принимающую несколько аргументов, также можно передать в функцию высшего порядка. В этом случае в функцию высшего порядка передаётся несколько массивов одинаковой длины, с которыми будут соотноситься эти аргументы.

Для некоторых функций первый аргумент (лямбда-функцию) можно опустить. В этом случае предполагается тождественное преобразование.

<div id="bare-function-names-as-lambdas">
  ### Имена функций как лямбда-выражения
</div>

Вместо полного лямбда-выражения можно напрямую передать имя функции в функцию высшего порядка. Имя функции автоматически преобразуется в эквивалентное лямбда-выражение.

Например, следующие пары эквивалентны:

```sql
SELECT arrayMap(negate, [1, 2, 3]);            -- [-1, -2, -3]
SELECT arrayMap(x -> negate(x), [1, 2, 3]);    -- [-1, -2, -3]

SELECT arrayMap(plus, [1, 2, 3], [10, 20, 30]);            -- [11, 22, 33]
SELECT arrayMap((x, y) -> plus(x, y), [1, 2, 3], [10, 20, 30]); -- [11, 22, 33]

SELECT arrayFilter(isNotNull, [1, NULL, 3, NULL, 5]);            -- [1, 3, 5]
SELECT arrayFilter(x -> isNotNull(x), [1, NULL, 3, NULL, 5]);    -- [1, 3, 5]

SELECT arrayFold(plus, [1, 2, 3, 4, 5], toUInt64(0));                      -- 15
SELECT arrayFold((acc, x) -> plus(acc, x), [1, 2, 3, 4, 5], toUInt64(0));  -- 15
```

Это работает со встроенными функциями, SQL UDF, executable UDF и WebAssembly UDF. При неоднозначности приоритет имеют имена столбцов и псевдонимов, а не имена функций.

Арность лямбда-выражения определяется по внутренней функции. Например, `arrayMap(plus, ...)` использует арность 2, потому что `plus` принимает два аргумента, поэтому это также работает с входными данными в виде кортежей, как в `arrayMap(plus, [(1, 10), (2, 20)])`, где элементы кортежа распаковываются в аргументы лямбда-выражения.

Для вариативных внутренних функций (например, `concat`, которая принимает любое число аргументов) арность лямбда-выражения определяется по числу аргументов-массивов. Это корректно для функций высшего порядка, таких как `arrayMap`, `arrayFilter` и `arrayFold`. Однако для функций высшего порядка, которые помимо массивов принимают фиксированные параметры не-массивного типа — например, `arrayPartialSort(f, limit, arr)` — простое имя вариативной функции может давать неверную арность, и в таком случае требуется явное лямбда-выражение.

Вариативные внутренние функции также не выполняют автоматическую распаковку входных кортежей. Например, `arrayMap(concat, [('a', 'b'), ('c', 'd')])` переписывается в унарное лямбда-выражение и не эквивалентно `arrayMap((x, y) -> concat(x, y), [('a', 'b'), ('c', 'd')])`. Используйте явное лямбда-выражение, если нужно деструктурировать элементы кортежа в вариативный вызов.
