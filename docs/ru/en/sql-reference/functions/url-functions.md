<div id="overview">
  ## Обзор
</div>

:::note
Функции, упомянутые в этом разделе, оптимизированы для максимальной производительности и по большей части не соответствуют стандарту RFC-3986.
У функций, реализующих RFC-3986, к имени добавляется `RFC`, и обычно они работают медленнее.
:::

Как правило, можно использовать варианты функций без `RFC`, если вы работаете с публично зарегистрированными доменами, которые не содержат ни пользовательских данных, ни символов `@`.
В таблице ниже показано, какие символы в URL соответствующие варианты `RFC` и non-`RFC` могут (`✔`) или не могут (`✗`) разобрать:

| Символ      | non-`RFC` | `RFC` |   |
| ----------- | --------- | ----- | - |
| &#39; &#39; | ✗         | ✗     |   |
| \t          | ✗         | ✗     |   |
| &lt;        | ✗         | ✗     |   |
| &gt;        | ✗         | ✗     |   |
| %           | ✗         | ✔*    |   |
| &#123;      | ✗         | ✗     |   |
| &#125;      | ✗         | ✗     |   |
|             |           | ✗     | ✗ |
| &#92;&#92;  | ✗         | ✗     |   |
| ^           | ✗         | ✗     |   |
| ~           | ✗         | ✔*    |   |
| [           | ✗         | ✗     |   |
| ]           | ✗         | ✔     |   |
| ;           | ✗         | ✔*    |   |
| =           | ✗         | ✔*    |   |
| &amp;       | ✗         | ✔*    |   |

Символы, отмеченные `*`, являются подразделителями в RFC 3986 и допускаются в пользовательской информации после символа `@`.

Существует два типа URL-функций:

* Функции, которые извлекают части URL. Если соответствующая часть в URL отсутствует, возвращается пустая строка.
* Функции, которые удаляют часть URL. Если в URL нет ничего подобного, он остается без изменений.
