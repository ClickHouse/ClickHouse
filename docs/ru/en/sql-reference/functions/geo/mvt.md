<div id="overview">
  ## Обзор
</div>

[векторные тайлы Mapbox](https://github.com/mapbox/vector-tile-spec) (MVT) — это тайлы, закодированные в protobuf, которые веб-картографические
клиенты, такие как MapLibre и Mapbox GL, отображают напрямую. ClickHouse может строить такие тайлы целиком средствами SQL с помощью пары
взаимодействующих функций:

* `MVTEncodeGeom` — скалярная функция, которая проецирует геометрию в локальное пиксельное пространство тайла slippy-map и
  обрезает её по границам тайла.
* `MVTEncode` — агрегатная функция, которая собирает спроецированные геометрии группы в бинарное представление
  однослойного тайла.

Две вспомогательные функции, `MVTBoundingBox` и `MVTBoundingBoxMercator`, возвращают ограничивающий прямоугольник тайла, чтобы строки можно было
ограничить им в предложении `WHERE` с использованием индекса.

Поддерживаются точечные, линейные и полигональные геометрии, включая тип `Geometry` и конкретные гео-типы (`Point`,
`LineString`, `MultiLineString`, `Ring`, `Polygon`, `MultiPolygon`).

Получившиеся байты представляют собой готовый тайл, который можно напрямую вернуть через HTTP-интерфейс с `FORMAT RawBLOB`.

Эти функции повторяют подход PostGIS и также доступны под их именами PostGIS в качестве псевдонимов: `ST_AsMVTGeom`
для `MVTEncodeGeom` и `ST_AsMVT` для `MVTEncode`.

<div id="mvtencodegeom">
  ## MVTEncodeGeom
</div>

Проецирует геометрию, заданную в географических координатах (долгота/широта), в локальное пиксельное пространство тайла
slippy-map, задаваемого `zoom`, `tile_x` и `tile_y`, привязывает её к целочисленной пиксельной сетке, обрезает по границам тайла
и возвращает геометрию в координатах тайла.

Используется проекция Web Mercator по всему диапазону координат `UInt32`. Возвращаемые координаты имеют начало в
левом верхнем углу тайла, а ось y направлена вниз, что соответствует системе координат формата векторного тайла Mapbox, поэтому результат можно напрямую передавать в `MVTEncode`. Координаты округляются до целых пикселей, поэтому группировка по
`MVTEncodeGeom` объединяет геометрию, попадающую в одну и ту же ячейку сетки, в единый кластер.

Когда `clip` включён (по умолчанию), геометрия обрезается по тайлу, расширенному на `buffer` пикселей (диапазон
`[-buffer, extent + buffer]` по каждой оси); геометрия, которая целиком оказывается за его пределами, становится `NULL`. Это аналог
PostGIS `ST_AsMVTGeom`.

Координаты полигонов перед валидацией ограничиваются диапазоном `2^30` — это в точности пиксельный охват всего мира при
`zoom` 18 и `extent` 4096 — поэтому для реалистичных тайлов геометрия проходит валидацию, но никогда не обрезается, а это ограничение влияет только на
геометрию, заданную при экстремальных значениях `zoom` или `extent`.

Тип выходной геометрии зависит от входной: `Point` возвращает `Point`; `LineString` или `MultiLineString` возвращает
`MultiLineString`; `Ring`, `Polygon` или `MultiPolygon` возвращает `MultiPolygon` (при обрезке геометрия может разбиваться на
несколько частей).

**Синтаксис**

```sql
MVTEncodeGeom(geometry, zoom, tile_x, tile_y[, extent[, buffer[, clip]]])
```

**Аргументы**

* `geometry` — Геометрия в градусах долготы/широты. Долгота ограничивается диапазоном `[-180, 180]`, а широта — диапазоном Web Mercator `[-85.05112878, 85.05112878]`. [`Point`](../../data-types/geo.md) / [`LineString`](../../data-types/geo.md) / [`MultiLineString`](../../data-types/geo.md) / [`Ring`](../../data-types/geo.md) / [`Polygon`](../../data-types/geo.md) / [`MultiPolygon`](../../data-types/geo.md) / [`Geometry`](../../data-types/geo.md).
* `zoom` — Уровень масштабирования slippy-map в диапазоне `[0, 32]`. [`UInt8`](../../data-types/int-uint.md).
* `tile_x` — Индекс столбца тайла в диапазоне `[0, 2^zoom - 1]`. [`UInt32`](../../data-types/int-uint.md).
* `tile_y` — Индекс строки тайла в диапазоне `[0, 2^zoom - 1]`. [`UInt32`](../../data-types/int-uint.md).
* `extent` — Необязательный размер тайла в пикселях по стороне, в диапазоне `[1, 2147483647]`. По умолчанию `4096`, стандартное значение для векторного тайла Mapbox. [`UInt32`](../../data-types/int-uint.md).
* `buffer` — Необязательный буфер отсечения в пикселях, в диапазоне `[0, 2147483647]`. По умолчанию `1`. [`UInt32`](../../data-types/int-uint.md).
* `clip` — Необязательный флаг; если не равен нулю (значение по умолчанию), геометрия обрезается по границам тайла с учетом буфера. [`UInt8`](../../data-types/int-uint.md).

**Возвращаемое значение**

Возвращает геометрию в системе координат тайла или `NULL`, если она полностью отсечена. [`Geometry`](../../data-types/geo.md).

**Пример**

```sql
SELECT MVTEncodeGeom((13.37, 52.52)::Point, 10, 550, 335) AS pixel
```

```text
┌─pixel──────┐
│ (124,3384) │
└────────────┘
```

<div id="mvtencode">
  ## MVTEncode
</div>

Кодирует группу объектов в бинарный слой векторного тайла Mapbox. Это агрегатный аналог скалярной
функции `MVTEncodeGeom`. Каждая входная строка превращается в один объект; поддерживаются геометрии типов point, line и polygon.

Аргумент `geometry` — это `Geometry` с координатами в tile-space, обычно создаваемый `MVTEncodeGeom`. Строки, у которых
геометрия имеет значение `NULL` (например, была отсечена функцией `MVTEncodeGeom`), пропускаются. Необязательный аргумент `properties` — это
именованный кортеж, имена элементов которого становятся ключами атрибутов объекта, а типы элементов определяют типы значений
в vector tile.

Результат представляет собой необработанные байты тайла с одним слоем. Пустая группа создает пустой тайл. Это аналог
PostGIS `ST_AsMVT`.

**Синтаксис**

```sql
MVTEncode(layer_name[, extent[, feature_id_name[, stringify_unsupported]]])(geometry[, properties])
```

**Параметры**

* `layer_name` — Имя слоя векторного тайла. [`String`](../../data-types/string.md).
* `extent` — Размер тайла в пикселях по каждой стороне, в диапазоне `[1, 2147483647]`. По умолчанию — `4096`. [`UInt32`](../../data-types/int-uint.md).
* `feature_id_name` — Необязательное имя элемента типа беззнакового целого числа в кортеже `properties`, который будет записан как `id` объекта MVT Feature (типа `UInt64`), а не как тег. Знаковые целые числа не поддерживаются. Если `id` имеет значение `NULL`, он для этого объекта опускается. Параметры позиционные, поэтому для использования этого параметра необходимо указать `extent`. [`String`](../../data-types/string.md).
* `stringify_unsupported` — Необязательный флаг (`0`/`1`, по умолчанию `0`); если задано `1`, типы свойств, которые не поддерживаются напрямую (например, большие целые числа, `UUID`, `Decimal`), кодируются как их текстовое `string_value` вместо возврата ошибки. [`UInt8`](../../data-types/int-uint.md).

**Аргументы**

* `geometry` — Геометрия в координатах тайла, например из `MVTEncodeGeom`. [`Geometry`](../../data-types/geo.md).
* `properties` — Необязательный именованный кортеж атрибутов объекта. Имена элементов становятся ключами атрибутов. [`Tuple`](../../data-types/tuple.md).

**Возвращаемое значение**

Возвращает двоичное содержимое однослойного векторного тайла Mapbox. [`String`](../../data-types/string.md).

<div id="property-types">
  ### Типы свойств
</div>

Каждый элемент свойства кодируется как вариант `Value` формата векторного тайла Mapbox, соответствующий его типу ClickHouse:

| Тип ClickHouse                                                 | Тип значения векторного тайла |
| -------------------------------------------------------------- | ----------------------------- |
| `String` / `FixedString`                                       | `string_value`                |
| `Float32` / `BFloat16`                                         | `float_value`                 |
| `Float64`                                                      | `double_value`                |
| `Bool`                                                         | `bool_value`                  |
| `Int8` / `Int16` / `Int32` / `Int64` / `Date32`                | `sint_value`                  |
| `UInt8` / `UInt16` / `UInt32` / `UInt64` / `Date` / `DateTime` | `uint_value`                  |

Типы могут быть обёрнуты в `Nullable` и/или `LowCardinality`. Если значение равно `NULL`, этот атрибут для объекта опускается, так как
формат векторных тайлов не поддерживает null-значения. Любой другой тип свойства вызывает исключение, если не задан `stringify_unsupported`, в
этом случае значение кодируется как текстовый `string_value`.

Одинаковые значения свойств интернируются в общий пул значений слоя, поэтому значение, встречающееся во многих объектах,
сохраняется только один раз.

<div id="naming-the-properties-tuple">
  ### Именование кортежа properties
</div>

Кортеж properties должен иметь явно заданные имена элементов. Псевдонимы столбцов внутри `tuple(...)` **не** переносятся в имена
элементов кортежа, поэтому задайте имена элементов с помощью приведения типа:

```sql
tuple(count(), any(id))::Tuple(cluster_count UInt64, id String)
```

<div id="clustering">
  ### Кластеризация
</div>

Кластеризация задаётся в SQL, а не функцией. Поскольку `MVTEncodeGeom` округляет до целых пикселей, группировка по
пиксельной геометрии объединяет совпадающие геометрические объекты; сначала выполните агрегацию по группам в подзапросе, а затем передайте в
`MVTEncode` по одной строке на каждый кластер:

```sql
SELECT MVTEncode('points')(geom, tuple(cluster_count)::Tuple(cluster_count UInt64)) AS tile
FROM
(
    SELECT MVTEncodeGeom((lon, lat)::Point, 10, 550, 335) AS geom, count() AS cluster_count
    FROM points
    GROUP BY geom
)
SETTINGS allow_suspicious_types_in_group_by = 1;
```

Группировка по значению `Geometry` требует `allow_suspicious_types_in_group_by = 1`, поскольку группировка по типу
`Geometry` на базе `Variant` по умолчанию ограничена. Чтобы выводить по одному геообъекту для каждой входной строки
вместо кластеризованных геообъектов, опустите внутренний `GROUP BY` (и `count()`).

<div id="mvtboundingbox">
  ## MVTBoundingBox
</div>

Возвращает географический ограничивающий прямоугольник тайла в схеме slippy-map, заданного `zoom`, `tile_x` и `tile_y`, в виде кортежа
`(min_lon, min_lat, max_lon, max_lat)` в градусах.

Используйте её, чтобы ограничить строки одним тайлом, фильтруя напрямую по столбцам `longitude`/`latitude`, — тогда можно использовать первичный ключ или
индекс по этим столбцам — вместо того чтобы заново вычислять проекцию Web Mercator для каждой строки. Необязательный параметр `margin`
расширяет прямоугольник с каждой стороны на указанную долю размера тайла; задайте значение `buffer / extent`, чтобы учесть буфер обрезки
`MVTEncodeGeom`.

**Синтаксис**

```sql
MVTBoundingBox(zoom, tile_x, tile_y[, margin])
```

**Аргументы**

* `zoom` — Уровень масштабирования slippy-map, в диапазоне `[0, 32]`. [`UInt8`](../../data-types/int-uint.md).
* `tile_x` — Индекс столбца тайла, в диапазоне `[0, 2^zoom - 1]`. [`UInt32`](../../data-types/int-uint.md).
* `tile_y` — Индекс строки тайла, в диапазоне `[0, 2^zoom - 1]`. [`UInt32`](../../data-types/int-uint.md).
* `margin` — Необязательная доля размера тайла, на которую прямоугольник расширяется с каждой стороны. По умолчанию `0`. [`Float64`](../../data-types/float.md).

**Возвращаемое значение**

Возвращает ограничивающий прямоугольник тайла в виде кортежа `(min_lon, min_lat, max_lon, max_lat)` в градусах. [`Tuple(Float64, Float64, Float64, Float64)`](../../data-types/tuple.md).

**Пример**

```sql
SELECT MVTBoundingBox(0, 0, 0) AS bbox
```

```text
┌─bbox────────────────────────────────────────────┐
│ (-180,-85.05112877980659,180,85.05112877980659)  │
└──────────────────────────────────────────────────┘
```

<div id="mvtboundingboxmercator">
  ## MVTBoundingBoxMercator
</div>

Аналог `MVTBoundingBox` для Web Mercator. Возвращает
ограничивающий прямоугольник тайла в полном пространстве координат Web Mercator с диапазоном `UInt32`, которое `MVTEncodeGeom` использует внутри, в виде кортежа
`(min_x, min_y, max_x, max_y)`. Ось y направлена вниз (север сверху). Предназначена для таблиц, в которых материализуются
столбцы с координатами Меркатора и индексируются они, а не `longitude`/`latitude`.

**Синтаксис**

```sql
MVTBoundingBoxMercator(zoom, tile_x, tile_y[, margin])
```

**Аргументы**

То же, что и у [`MVTBoundingBox`](#mvtboundingbox).

**Возвращаемое значение**

Возвращает ограничивающий прямоугольник тайла в виде кортежа `(min_x, min_y, max_x, max_y)` в координатах Web Mercator. [`Tuple(Float64, Float64, Float64, Float64)`](../../data-types/tuple.md).

**Пример**

```sql
SELECT MVTBoundingBoxMercator(1, 0, 0) AS bbox
```

```text
┌─bbox────────────────────────┐
│ (0,0,2147483648,2147483648)  │
└──────────────────────────────┘
```

<div id="restricting-rows-to-a-tile">
  ## Ограничение строк по тайлу
</div>

Тайл должен содержать только ту геометрию, которая к нему относится. Лучше всего описать это как два взаимодополняющих шага: недорогой
предикат ограничивающего прямоугольника, использующий индекс, в предложении `WHERE` (производительность), и обрезку в `MVTEncodeGeom` (корректность).
Обрезка отсекает геометрию за пределами тайла, поэтому даже неточный предикат ограничивающего прямоугольника не даст геометрии
вне тайла попасть в результат.

```sql
WITH
    1 AS buffer,
    4096 AS extent,
    MVTBoundingBox({z:UInt8}, {x:UInt32}, {y:UInt32}, buffer / extent) AS bounding_box   -- margin matches the clip buffer
SELECT MVTEncode('points')(geom, tuple(cluster_count)::Tuple(cluster_count UInt64))
FROM
(
    SELECT MVTEncodeGeom((lon, lat)::Point, {z:UInt8}, {x:UInt32}, {y:UInt32}) AS geom, count() AS cluster_count
    FROM points
    WHERE lon BETWEEN bounding_box.1 AND bounding_box.3 AND lat BETWEEN bounding_box.2 AND bounding_box.4   -- index-using prefilter
    GROUP BY geom
)
SETTINGS allow_suspicious_types_in_group_by = 1
```

Предикат ограничивающего прямоугольника — это лишь грубый предварительный фильтр; точная граница тайла обеспечивается обрезкой в
`MVTEncodeGeom`. Передайте `clip => false` (седьмой аргумент) в `MVTEncodeGeom`, чтобы отключить обрезку и полагаться
только на предикат `WHERE`.

<div id="serving-tiles-over-http">
  ## Отдача тайлов по HTTP
</div>

По умолчанию ClickHouse не предоставляет конечную точку для тайлов: HTTP-интерфейс принимает запросы только по адресу `/`. Аккуратный
URL `/tile/{z}/{x}/{y}` добавляется оператором с помощью [обработчика предопределённого запроса](/ru/interfaces/http) в
конфигурации сервера. В `url` обработчика используется форма `regex:` для захвата сегментов пути, привязки их к
параметрам запроса и возврата байтов в формате `FORMAT RawBLOB`.

В простейшем случае в таблице есть столбец `Geometry`, а обработчик отдает по одному объекту на строку — `MVTEncodeGeom`
проецирует каждую геометрию в запрошенный тайл и обрезает её, поэтому строки за пределами тайла автоматически отбрасываются:

```xml
<http_handlers>
    <rule>
        <methods>GET</methods>
        <url><![CDATA[regex:/tile/(?P<z>\d+)/(?P<x>\d+)/(?P<y>\d+)]]></url>
        <handler>
            <type>predefined_query_handler</type>
            <query>
                SELECT MVTEncode('shapes')(
                    MVTEncodeGeom(geom, {z:UInt8}, {x:UInt32}, {y:UInt32}),
                    tuple(id, name)::Tuple(id UInt32, name String))
                FROM shapes
                FORMAT RawBLOB
            </query>
            <content_type>application/vnd.mapbox-vector-tile</content_type>
        </handler>
    </rule>
    <defaults/>
</http_handlers>
```

Здесь `shapes` — это таблица со столбцом `geom Geometry` (любое сочетание точек, линий и полигонов). `GET /tile/10/550/335`
возвращает закодированный тайл.

Для точечных данных это также хорошо работает с обычными столбцами `longitude`/`latitude`, если формировать точку прямо в выражении с помощью
`MVTEncodeGeom((lon, lat)::Point, …)`. Чтобы кластеризовать совпадающие объекты или добавить предварительную фильтрацию по ограничивающему прямоугольнику с использованием индекса
для больших таблиц, расширьте внутренний запрос, как показано в разделах [Кластеризация](#clustering) и
[Ограничение строк границами тайла](#restricting-rows-to-a-tile).

<div id="limitations">
  ## Ограничения
</div>

* Проекция Web Mercator ограничивает широту значениями `±85.05112878°` и не поддерживает входные данные, пересекающие антимеридиан.
