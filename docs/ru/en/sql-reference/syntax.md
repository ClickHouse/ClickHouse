В этом разделе мы рассмотрим синтаксис SQL в ClickHouse.
ClickHouse использует синтаксис на основе SQL, но также предлагает ряд расширений и оптимизаций.

<div id="query-parsing">
  ## Разбор запросов
</div>

В ClickHouse есть два типа парсеров:

* *Полный SQL-парсер* (парсер рекурсивного спуска).
* *Парсер формата данных* (высокоскоростной потоковый парсер).

Полный SQL-парсер используется во всех случаях, кроме запроса `INSERT`, в котором задействуются оба парсера.

Рассмотрим запрос ниже:

```sql
INSERT INTO t VALUES (1, 'Hello, world'), (2, 'abc'), (3, 'def')
```

Как уже упоминалось, запрос `INSERT` использует оба парсера.
Фрагмент `INSERT INTO t VALUES` разбирается полным парсером,
а данные `(1, 'Hello, world'), (2, 'abc'), (3, 'def')` — парсером формата данных, или быстрым потоковым парсером.

<details>
  <summary>Включение полного парсера</summary>

  Для данных также можно включить полный парсер
  с помощью настройки [`input_format_values_interpret_expressions`](../operations/settings/settings-formats.md#input_format_values_interpret_expressions).

  Когда указанная выше настройка установлена в `1`,
  ClickHouse сначала пытается разобрать значения с помощью быстрого потокового парсера.
  Если это не удается, ClickHouse пытается использовать для данных полный парсер, рассматривая их как SQL-[выражение](#expressions).
</details>

Данные могут иметь любой формат.
При получении запроса сервер держит в оперативной памяти не более [max&#95;query&#95;size](../operations/settings/settings.md#max_query_size) байт запроса
(по умолчанию 1 МБ), а остальное разбирается в потоковом режиме.
Это позволяет избежать проблем с большими запросами `INSERT`, которые являются рекомендуемым способом вставки данных в ClickHouse.

При использовании формата [`Values`](/ru/interfaces/formats/Values) в запросе `INSERT`
может показаться, что данные разбираются так же, как выражения в запросе `SELECT`, однако это не так.
Формат `Values` гораздо более ограничен.

Остальная часть этого раздела посвящена полному парсеру.

:::note
Дополнительную информацию о парсерах форматов см. в разделе [Форматы](../interfaces/formats.md).
:::

<div id="spaces">
  ## Пробелы
</div>

* Между синтаксическими конструкциями может быть любое количество пробельных символов (в том числе в начале и в конце запроса).
* К пробельным символам относятся пробел, символ табуляции, перевод строки, CR и перевод страницы.

<div id="comments">
  ## Комментарии
</div>

ClickHouse поддерживает комментарии как в стиле SQL, так и в стиле C:

* Комментарии в стиле SQL начинаются с `--`, `#!` или `# ` и продолжаются до конца строки. Пробел после `--` и `#!` можно не ставить.
* Комментарии в стиле C:
  * `//` (или более двух символов `/`), после которых идёт текст до конца строки. Пробелы после `/` не обязательны.
  * Также могут начинаться с `/*` и заканчиваться `*/` — это многострочные комментарии. Пробелы здесь тоже не обязательны.
  * Комментарии в стиле C могут быть вложенными.

Например:

```sql
/*
 * Compute the number of days between two dates.
 * /* Returns NULL if either argument is NULL */
 */
SELECT
    dateDiff('day', toDate('2024-01-01'), toDate('2024-12-31')) AS days_in_year, -- 365
    dateDiff('day', toDate('2020-01-01'), today()) AS days_since  #! since 2020
    ///////////////////////////////////////////////////////////////////
    # TODO: add hour/minute variants
```

<div id="keywords">
  ## Ключевые слова
</div>

Ключевые слова в ClickHouse, в зависимости от контекста, могут быть как *чувствительными к регистру*, так и *регистронезависимыми*.

Ключевые слова **регистронезависимы**, если они относятся к:

* стандарту SQL. Например, `SELECT`, `select` и `SeLeCt` — все эти варианты корректны.
* реализации в некоторых популярных СУБД (MySQL или Postgres). Например, `DateTime` — то же самое, что и `datetime`.

:::note
Проверить, чувствительно ли имя типа данных к регистру, можно в таблице [system.data&#95;type&#95;families](/ru/operations/system-tables/data_type_families).
:::

В отличие от стандартного SQL, все остальные ключевые слова (включая имена функций) **чувствительны к регистру**.

Кроме того, ключевые слова не являются зарезервированными.
Они рассматриваются как ключевые только в соответствующем контексте.
Если вы используете [идентификаторы](#identifiers) с теми же именами, что и ключевые слова, заключайте их в двойные кавычки или обратные кавычки.

Например, следующий запрос корректен, если в таблице `table_name` есть столбец с именем `"FROM"`:

```sql
SELECT "FROM" FROM table_name
```

<div id="identifiers">
  ## Идентификаторы
</div>

Идентификаторами могут быть:

* имена кластеров, баз данных, таблиц, партиций и столбцов;
* [Функции](#functions);
* [Типы данных](../sql-reference/data-types/index.md);
* [Псевдонимы выражений](#expression-aliases).

Идентификаторы могут быть заключены в кавычки или использоваться без кавычек, хотя предпочтителен второй вариант.

Идентификаторы без кавычек должны соответствовать регулярному выражению `^[a-zA-Z_][0-9a-zA-Z_]*$` и не могут совпадать с [ключевыми словами](#keywords).
Примеры допустимых и недопустимых идентификаторов приведены в таблице ниже:

| Допустимые идентификаторы                      | Недопустимые идентификаторы            |
| ---------------------------------------------- | -------------------------------------- |
| `xyz`, `_internal`, `Id_with_underscores_123_` | `1x`, `tom@gmail.com`, `äußerst_schön` |

Если вы хотите использовать идентификаторы, совпадающие с ключевыми словами, или включать в идентификаторы другие символы, заключайте их в двойные кавычки или обратные кавычки, например `"id"`, `` `id` ``.

:::note
Те же правила экранирования, которые применяются к идентификаторам в кавычках, применяются и к строковым литералам. Подробнее см. в разделе [String](#string).
:::

:::tip[Избегайте использования точек в именах столбцов]
Имена столбцов, содержащие точки, столбцы с общим префиксом до точки и столбцы типа `Array` могут интерпретироваться как часть уплощённой структуры `Nested`, когда `flatten_nested = 1` (значение по умолчанию). Это может привести к неожиданной проверке длины массивов при вставке и ограничениям на переименование.

По возможности не используйте точки в именах столбцов.
Используйте символ подчёркивания (`_`) или другой разделитель вместо точек в именах столбцов, если только вам намеренно не нужна семантика `Nested`.
:::

<div id="literals">
  ## Литералы
</div>

В ClickHouse литерал — это значение, которое напрямую задано в запросе.
Иными словами, это фиксированное значение, которое не изменяется при выполнении запроса.

Литералы могут быть:

* [String](#string)
* [Числовыми](#numeric)
* [Составными](#compound)
* [`NULL`](#null)
* [Heredoc](#heredoc) (пользовательские строковые литералы)

Ниже мы подробнее рассмотрим каждый из этих типов.

<div id="string">
  ### String
</div>

Литералы типа String должны быть заключены в одинарные кавычки. Двойные кавычки не поддерживаются.

Экранирование работает одним из двух способов:

* с помощью предшествующей одинарной кавычки: символ одинарной кавычки `'` (и только его) можно экранировать как `''`, или
* с помощью предшествующей обратной косой черты и одной из поддерживаемых escape-последовательностей, перечисленных в таблице ниже.

:::note
Обратная косая черта теряет своё специальное значение, то есть интерпретируется буквально, если стоит перед символами, отличными от перечисленных ниже.
:::

| Поддерживаемая escape-последовательность | Описание                                                                                        |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `\xHH`                                   | Спецификация 8-битного символа, за которой следует любое количество шестнадцатеричных цифр (H). |
| `\N`                                     | зарезервировано, ничего не делает (например, `SELECT 'a\Nb'` возвращает `ab`)                   |
| `\a`                                     | сигнал                                                                                          |
| `\b`                                     | возврат на один символ                                                                          |
| `\e`                                     | escape-символ                                                                                   |
| `\f`                                     | перевод страницы                                                                                |
| `\n`                                     | перевод строки                                                                                  |
| `\r`                                     | возврат каретки                                                                                 |
| `\t`                                     | горизонтальная табуляция                                                                        |
| `\v`                                     | вертикальная табуляция                                                                          |
| `\0`                                     | нулевой символ                                                                                  |
| `\\`                                     | обратная косая черта                                                                            |
| `\'` (или `''`)                          | одинарная кавычка                                                                               |
| `\"`                                     | двойная кавычка                                                                                 |
| `` ` ``                                  | обратная кавычка                                                                                |
| `\/`                                     | прямая косая черта                                                                              |
| `\=`                                     | знак равенства                                                                                  |
| Управляющие символы ASCII (c &lt;= 31).  |                                                                                                 |

:::note
В строковых литералах необходимо экранировать как минимум символы `'` и `\`, используя escape-коды `\'` (или `''`) и `\\`.
:::

<div id="numeric">
  ### Числовые литералы
</div>

Числовые литералы разбираются следующим образом:

* Если литерал начинается со знака минуса `-`, этот токен пропускается, а после разбора результат делается отрицательным.
* Сначала числовой литерал разбирается как 64-битное беззнаковое целое число с помощью функции [strtoull](https://en.cppreference.com/w/cpp/string/byte/strtoul).
  * Если значение имеет префикс `0b` или `0x`/`0X`, число разбирается как двоичное или шестнадцатеричное соответственно.
  * Если значение отрицательное, а его абсолютная величина больше 2<sup>63</sup>, возвращается ошибка.
* Если это не удаётся, значение затем разбирается как число с плавающей точкой с помощью функции [strtod](https://en.cppreference.com/w/cpp/string/byte/strtof).
* В противном случае возвращается ошибка.

Значения литералов приводятся к наименьшему типу, в который помещается значение.
Например:

* `1` разбирается как `UInt8`
* `256` разбирается как `UInt16`.

:::note Важно
Целочисленные значения шире 64 бит (`UInt128`, `Int128`, `UInt256`, `Int256`) необходимо привести к более широкому типу, чтобы они разбирались корректно:

```sql
-170141183460469231731687303715884105728::Int128
340282366920938463463374607431768211455::UInt128
-57896044618658097711785492504343953926634992332820282019728792003956564819968::Int256
115792089237316195423570985008687907853269984665640564039457584007913129639935::UInt256
```

Это позволяет обойти описанный выше алгоритм и разобрать целое число с помощью процедуры, поддерживающей произвольную точность.

В противном случае литерал будет разобран как число с плавающей точкой, что может привести к потере точности из-за усечения.
:::

Дополнительную информацию см. в разделе [Типы данных](../sql-reference/data-types/index.md).

Символы подчёркивания `_` внутри числовых литералов игнорируются и могут использоваться для удобства чтения.

Поддерживаются следующие числовые литералы:

| Числовой литерал                                            | Примеры                                         |
| ----------------------------------------------------------- | ----------------------------------------------- |
| **Целые числа**                                             | `1`, `10_000_000`, `18446744073709551615`, `01` |
| **Десятичные числа**                                        | `0.1`                                           |
| **Экспоненциальная запись**                                 | `1e100`, `-1e-100`                              |
| **Числа с плавающей точкой**                                | `123.456`, `inf`, `nan`                         |
| **Шестнадцатеричные**                                       | `0xc0fe`                                        |
| **Шестнадцатеричная строка, совместимая со стандартом SQL** | `x'c0fe'`                                       |
| **Двоичные**                                                | `0b1101`                                        |
| **Двоичная строка, совместимая со стандартом SQL**          | `b'1101'`                                       |

:::note
Восьмеричные литералы не поддерживаются во избежание ошибок интерпретации.
:::

<div id="compound">
  ### Составные
</div>

Массивы создаются с помощью `[]`: `[1, 2, 3]`. Кортежи создаются с помощью `()`: `(1, 'Hello, world!', 2)`.
Технически это не литералы, а выражения с оператором создания массива и оператором создания кортежа соответственно.
Массив должен содержать как минимум один элемент, а кортеж — как минимум два элемента.

:::note
Есть отдельный случай, когда кортежи встречаются в условии `IN` запроса `SELECT`.
Результаты запроса могут включать кортежи, но сохранять кортежи в базу данных нельзя (кроме таблиц, использующих движок [Memory](../engines/table-engines/special/memory.md)).
:::

<div id="null">
  ### NULL
</div>

`NULL` используется для указания на отсутствие значения.
Чтобы хранить `NULL` в поле таблицы, оно должно иметь тип [Nullable](../sql-reference/data-types/nullable.md).

:::note
Следует учитывать следующее о `NULL`:

* В зависимости от формата данных (входного или выходного) `NULL` может иметь разное представление. Подробнее см. в разделе [форматы данных](/ru/interfaces/formats).
* Обработка `NULL` имеет свои нюансы. Например, если хотя бы один из аргументов операции сравнения равен `NULL`, результат этой операции тоже будет `NULL`. То же верно для умножения, сложения и других операций. Рекомендуем ознакомиться с документацией по каждой операции.
* В запросах вы можете проверять `NULL` с помощью операторов [`IS NULL`](/ru/sql-reference/functions/functions-for-nulls#isNull) и [`IS NOT NULL`](/ru/sql-reference/functions/functions-for-nulls#isNotNull), а также связанных с ними функций `isNull` и `isNotNull`.
  :::

<div id="heredoc">
  ### Heredoc
</div>

[Heredoc](https://en.wikipedia.org/wiki/Here_document) — это способ задать строку (часто многострочную), сохранив её исходное форматирование.
Heredoc определяется как пользовательский строковый литерал, заключённый между двумя символами `$`.

Например:

```sql
SELECT $heredoc$SHOW CREATE VIEW my_view$heredoc$;

┌─'SHOW CREATE VIEW my_view'─┐
│ SHOW CREATE VIEW my_view   │
└────────────────────────────┘
```

:::note

* Значение между двумя heredoc обрабатывается &quot;как есть&quot;.
  :::

:::tip

* С помощью heredoc можно вставлять фрагменты кода SQL, HTML, XML и т. д.
  :::

<div id="defining-and-using-query-parameters">
  ## Определение и использование параметров запроса
</div>

Параметры запроса позволяют писать универсальные запросы с абстрактными плейсхолдерами вместо конкретных идентификаторов.
Когда выполняется запрос с параметрами,
все плейсхолдеры разрешаются и заменяются фактическими значениями параметров.

Параметры запроса можно задавать несколькими способами:

* `SET param_<name>=<value>` — с помощью команды `SET` в запросе.
* `--param_<name>='<value>'` — как аргумент `clickhouse-client` в командной строке.
* `param_<name>=<value>` — как параметр строки запроса URL для HTTP-интерфейса.

На параметр запроса можно ссылаться в запросе с помощью `{<name>: <datatype>}`, где `<name>` — имя параметра запроса, а `<datatype>` — тип данных, в который он преобразуется.

<details>
  <summary>Пример с командой SET</summary>

  Например, следующий SQL задаёт параметры с именами `a`, `b`, `c` и `d` — каждый со своим типом данных:

  ```sql
  SET param_a = 13;
  SET param_b = 'str';
  SET param_c = '2022-08-04 18:30:53';
  SET param_d = {'10': [11, 12], '13': [14, 15]};

  SELECT
     {a: UInt32},
     {b: String},
     {c: DateTime},
     {d: Map(String, Array(UInt8))};

  13    str    2022-08-04 18:30:53    {'10':[11,12],'13':[14,15]}
  ```
</details>

<details>
  <summary>Пример с clickhouse-client</summary>

  Если вы используете `clickhouse-client`, параметры указываются в виде `--param_name=value`. Например, следующий параметр имеет имя `message` и считывается как `String`:

  ```bash
  clickhouse-client --param_message='hello' --query="SELECT {message: String}"

  hello
  ```

  Если параметр запроса представляет имя базы данных, таблицы, функции или другой идентификатор, используйте `Identifier` в качестве его типа. Например, следующий запрос возвращает строки из таблицы `uk_price_paid`:

  ```sql
  SET param_mytablename = "uk_price_paid";
  SELECT * FROM {mytablename:Identifier};
  ```
</details>

<details>
  <summary>Пример с HTTP-интерфейсом</summary>

  Параметры запроса можно передавать как параметры строки запроса URL с префиксом `param_`. Например:

  ```bash
  curl -s "http://localhost:8123/?param_message=hello" --data-binary "SELECT {message: String}"

  hello
  ```
</details>

<details>
  <summary>Пример с web UI</summary>

  Встроенный web UI (`play.html`) автоматически распознаёт плейсхолдеры параметров `{name:Type}` в запросе и отображает подписанные поля ввода для каждого параметра. Значения параметров включаются в HTTP-запрос, а также сохраняются в URL страницы для закладок и общего доступа.
</details>

:::note
Параметры запроса — это не универсальные текстовые подстановки, которые можно использовать в произвольных местах произвольных SQL-запросов.
Они в первую очередь предназначены для работы в командах `SELECT` вместо идентификаторов или литералов.
:::

<div id="functions">
  ## Функции
</div>

Вызовы функций записываются в виде идентификатора со списком аргументов (возможно, пустым) в `()`.
В отличие от стандартного SQL, скобки обязательны даже при пустом списке аргументов.
Например:

```sql
now()
```

Также существуют:

* [Обычные функции](/ru/sql-reference/functions/overview).
* [Агрегатные функции](/ru/sql-reference/aggregate-functions).

Некоторые агрегатные функции могут содержать два списка аргументов в скобках. Например:

```sql
quantile (0.9)(x) 
```

Эти агрегатные функции называются &quot;параметрическими&quot;,
а аргументы в первом списке — &quot;параметрами&quot;.

:::note
Синтаксис агрегатных функций без параметров такой же, как и у обычных функций.
:::

<div id="operators">
  ## Операторы
</div>

Операторы при разборе запроса преобразуются в соответствующие функции с учетом их приоритета и ассоциативности.

Например, выражение

```text
1 + 2 * 3 + 4
```

преобразуется в

```text
plus(plus(1, multiply(2, 3)), 4)`
```

<div id="expressions">
  ## Выражения
</div>

Выражением может быть любое из следующего:

* функция
* идентификатор
* литерал
* применение оператора
* выражение в скобках
* подзапрос
* звёздочка

Оно также может содержать [псевдоним](#expression-aliases).

Список выражений — это одно или несколько выражений, разделённых запятыми.
Функции и операторы, в свою очередь, могут принимать выражения в качестве аргументов.

Константное выражение — это выражение, результат которого известен на этапе анализа запроса, то есть до его выполнения.
Например, выражения, составленные из литералов, являются константными.

<div id="expression-aliases">
  ## Псевдонимы выражений
</div>

Псевдоним — это заданное пользователем имя для [выражения](#expressions) в запросе.

```sql
expr AS alias
```

Части синтаксиса, приведённого выше, объясняются ниже.

| Часть синтаксиса | Описание                                                                                                                                                        | Пример                                                                  | Примечания                                                                                                                                 |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `AS`             | Ключевое слово для задания псевдонимов. Псевдоним для имени таблицы или имени столбца можно задать в предложении `SELECT` без использования ключевого слова `AS`. | `SELECT table_name_alias.column_name FROM table_name table_name_alias`. | В функции [CAST](/ru/sql-reference/functions/type-conversion-functions#CAST) ключевое слово `AS` имеет другое значение. См. описание функции. |
| `expr`           | Любое выражение, поддерживаемое ClickHouse.                                                                                                                     | `SELECT column_name * 2 AS double FROM some_table`                      |                                                                                                                                            |
| `alias`          | Имя для `expr`. Псевдонимы должны соответствовать синтаксису [идентификаторов](#identifiers).                                                                   | `SELECT "table t".column_name FROM table_name AS "table t"`.            |                                                                                                                                            |

<div id="notes-on-usage">
  ### Примечания по использованию
</div>

* Псевдонимы действуют глобально в пределах запроса или подзапроса, и определить псевдоним для любого выражения можно в любой части запроса. Например:

```sql
SELECT (1 AS n) + 2, n`.
```

* Псевдонимы недоступны в подзапросах и между ними. Например, при выполнении следующего запроса ClickHouse выдаёт исключение `Unknown identifier: num`:

```sql
`SELECT (SELECT sum(b.a) + num FROM b) - a.a AS num FROM a`
```

* Если для результирующих столбцов в предложении `SELECT` подзапроса задан псевдоним, эти столбцы видны во внешнем запросе. Например:

```sql
SELECT n + m FROM (SELECT 1 AS n, 2 AS m)`.
```

* Будьте осторожны с псевдонимами, совпадающими с именами столбцов или таблиц. Рассмотрим следующий пример:

```sql
CREATE TABLE t
(
    a Int,
    b Int
)
ENGINE = TinyLog();

SELECT
    argMax(a, b),
    sum(b) AS b
FROM t;

Received exception from server (version 18.14.17):
Code: 184. DB::Exception: Received from localhost:9000, 127.0.0.1. DB::Exception: Aggregate function sum(b) is found inside another aggregate function in query.
```

В предыдущем примере мы объявили таблицу `t` со столбцом `b`.
Затем при выборке данных мы задали псевдоним `sum(b) AS b`.
Поскольку псевдонимы являются глобальными,
ClickHouse подставил в выражение `argMax(a, b)` выражение `sum(b)` вместо литерала `b`.
Из-за этой подстановки возникло исключение.

:::note
Это поведение по умолчанию можно изменить, установив [prefer&#95;column&#95;name&#95;to&#95;alias](/ru/operations/settings/settings#prefer_column_name_to_alias) в `1`.
:::
