Вложенная структура данных похожа на таблицу внутри ячейки. Параметры вложенной структуры данных — имена и типы столбцов — задаются так же, как в запросе [CREATE TABLE](../../../sql-reference/statements/create/table.md). Каждой строке таблицы может соответствовать любое количество строк во вложенной структуре данных.

:::tip[Избегайте точек в именах столбцов]
Имена столбцов, содержащие точки, столбцы с общим префиксом до точки и столбцы типа `Array` могут интерпретироваться как часть развёрнутой структуры Nested, когда `flatten_nested = 1` (по умолчанию). Это может привести к неожиданной проверке длины массивов при вставке и ограничениям на переименование.

По возможности не используйте точки в именах столбцов.
Используйте символ подчёркивания (`_`) или другой разделитель вместо точек, если только вам намеренно не нужна семантика `Nested`.
:::

Пример:

```sql

  CounterID UInt32,
  StartDate Date,
  Sign Int8,
  IsNew UInt8,
  VisitID UInt64,
  UserID UInt64,
--highlight-start
  Goals Nested(
    ID UInt32,
    Serial UInt32,
    EventTime DateTime,
    Price Int64,
    OrderID String,
    CurrencyID UInt32
  )
--highlight-end
)
ENGINE = CollapsingMergeTree(Sign)
ORDER BY (StartDate, intHash32(UserID), (CounterID, StartDate, intHash32(UserID), VisitID));
```

Приведённый выше DDL-оператор `CREATE TABLE` объявляет вложенную структуру данных `Goals`, которая содержит данные о конверсиях, то есть о достигнутых целях.
Каждая строка в таблице &#39;visits&#39; соответствует нулю, одной или нескольким конверсиям.

Если для настройки [`flatten_nested`](/ru/operations/settings/settings#flatten_nested) задано значение `0` (`flatten_nested=1` по умолчанию), поддерживаются произвольные уровни вложенности.

В большинстве случаев при работе с вложенной структурой данных её столбцы указываются через имена столбцов, разделённые точкой.
Каждый из этих столбцов представляет собой массив соответствующего типа.
Все массивы столбцов одной вложенной структуры данных имеют одинаковую длину.

Например:

```sql
SELECT
    Goals.ID,
    Goals.EventTime
FROM test.visits
WHERE CounterID = 101500 AND length(Goals.ID) < 5
ORDER BY VisitID
LIMIT 10
```

<div id="filtering-nested-columns-in-where">
  ### Фильтрация столбцов Nested в WHERE
</div>

Поскольку каждый столбец структуры `Nested` хранится как `Array`, при обращении к такому столбцу в предложении `WHERE` вы получаете весь массив для каждой строки, а не отдельный элемент. Напрямую сравнивать вложенный столбец со скалярным значением нельзя, поэтому вместо этого нужно использовать [функции для работы с массивами](/ru/sql-reference/functions/array-functions).

Например, этот запрос **не** просто тихо возвращает пустой результат — он вызывает исключение, потому что `Goals.ID` имеет тип `Array(UInt32)`, а `equals(Array(UInt32), UInt32)` не является допустимым сравнением:

```sql
-- WRONG: compares the entire Array to a scalar
SELECT * FROM test.visits
WHERE Goals.ID = 591325;
```

```text
Code: 43. DB::Exception: Illegal types of arguments (`Array(UInt32)`, `UInt32`)
of function `equals`. (ILLEGAL_TYPE_OF_ARGUMENT)
```

Используйте [`has`](/ru/sql-reference/functions/array-functions#has), чтобы проверить, содержит ли массив определённое значение:

```sql
-- Find visits that have at least one goal with ID 591325
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE has(Goals.ID, 591325);
```

Используйте [`arrayExists`](/ru/sql-reference/functions/array-functions#arrayExists), если условие сложнее:

```sql
-- Find visits that have at least one goal with ID greater than 1000000
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE arrayExists(id -> id > 1000000, Goals.ID);
```

Вы можете фильтровать массивы по длине с помощью `length` или исключать пустые массивы с помощью `notEmpty`:

```sql
-- Visits with at least 3 goals
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE length(Goals.ID) >= 3;

-- Visits with at least one goal (non-empty array)
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE notEmpty(Goals.ID);
```

Чтобы фильтровать не целые строки, а отдельные элементы вложенной структуры, сначала используйте `ARRAY JOIN`, чтобы развернуть массивы.
После `ARRAY JOIN` каждый элемент становится отдельной строкой, поэтому предложение `WHERE` применяется к скалярным значениям.
Дополнительные сведения см. в разделе [предложение `ARRAY JOIN`](/ru/sql-reference/statements/select/array-join). Пример:

```sql
SELECT
    Goal.ID,
    Goal.EventTime
FROM test.visits
ARRAY JOIN Goals AS Goal
WHERE CounterID = 101500 AND length(Goals.ID) < 5
ORDER BY VisitID, Goal.Serial
LIMIT 10
```

<div id="inserting-data">
  ### Вставка данных
</div>

Для запроса `INSERT` все массивы столбцов-компонентов вложенной структуры данных следует передавать отдельно (как если бы это были массивы отдельных столбцов). При вставке система проверяет, что их длина одинакова.

Каждый вложенный подстолбец указывается в списке столбцов с использованием точечной нотации (`Goals.ID`, `Goals.Serial`, ...), а соответствующие значения представляют собой массивы:

```sql
INSERT INTO test.visits
    (CounterID, StartDate, Sign, IsNew, VisitID, UserID,
     Goals.ID, Goals.Serial, Goals.EventTime, Goals.Price, Goals.OrderID, Goals.CurrencyID)
VALUES
    -- A visit with two goals: each nested sub-column gets an array of length 2
    (101500, '2014-03-18', 1, 1, 2001, 200001,
     [1073752, 591325], [1, 2],
     ['2014-03-18 10:00:00', '2014-03-18 10:05:00'],
     [100, 200], ['order_a', 'order_b'], [1, 2]),
    -- A visit with no goals: all nested sub-columns get empty arrays
    (101500, '2014-03-18', 1, 0, 2002, 200002,
     [], [], [], [], [], []);
```

Все вложенные массивы подстолбцов в одной строке должны иметь одинаковую длину. Несовпадение длин вызывает ошибку:

```sql
-- ERROR: Goals.ID has 2 elements, but Goals.Serial has 1
INSERT INTO test.visits
    (CounterID, StartDate, Sign, IsNew, VisitID, UserID,
     Goals.ID, Goals.Serial, Goals.EventTime, Goals.Price, Goals.OrderID, Goals.CurrencyID)
VALUES
    (101500, '2014-03-18', 1, 1, 2003, 200003,
     [1073752, 591325], [1],
     ['2014-03-18 12:00:00'], [0], [''], [0]);
```

Для запроса `DESCRIBE` столбцы вложенной структуры данных также перечисляются по отдельности.

<div id="alter-limitations">
  ### Ограничения `ALTER`
</div>

У запросов `ALTER` для вложенных структур данных есть следующие ограничения:

**Добавление подстолбцов** работает как обычно. Вы можете добавить новый подстолбец в существующую структуру `Nested`:

```sql
ALTER TABLE test.visits ADD COLUMN Goals.Revenue Float64;
```

**Удаление подстолбцов** применимо и к отдельным подстолбцам:

```sql
ALTER TABLE test.visits DROP COLUMN Goals.Revenue;
```

**Изменение типа** подстолбца поддерживается и запускает мутацию (перезапись данных):

```sql
ALTER TABLE test.visits MODIFY COLUMN Goals.Price Int32;
```

**Для переименования** есть ограничения. Вы можете переименовать подстолбец в пределах одной и той же вложенной структуры:

```sql
-- OK: stays within the Goals structure
ALTER TABLE test.visits RENAME COLUMN Goals.Price TO Goals.Amount;
```

Однако **нельзя**:

* Переименовать всю саму структуру Nested (например, `Goals` в `Conversions`).
* Переместить подстолбец в другую структуру Nested (например, `Goals.ID` в `OtherNested.ID`).
* Переместить подстолбец из структуры Nested или в неё (например, `Goals.ID` в `GoalID` или наоборот).
