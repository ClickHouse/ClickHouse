## use_columns_cache {#use_columns_cache}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "Новая экспериментальная настройка, включающая кэш столбцов для таблиц семейства MergeTree; по умолчанию отключена."}]}]} />

Определяет, использовать ли кэш столбцов. Принимает значения 0 или 1. По умолчанию — 0 (отключено).
Кэш столбцов хранит десериализованные столбцы из таблиц семейства `MergeTree`, что избавляет от повторной декомпрессии и десериализации «горячих» данных. Это может значительно снизить задержку повторяющихся запросов к одним и тем же данным. Ключ кэша состоит из UUID таблицы, имени части данных, имени столбца и полосы (stripe) — последовательности гранул объёмом около 65536 строк.

Поскольку в ключ записи входит UUID таблицы, кэш работает только для таблиц в базах данных, назначающих UUID, таких как `Atomic`, `Replicated` и `Shared` (движок баз данных по умолчанию в ClickHouse Cloud); таблицы семейства `MergeTree` в устаревших базах данных `Ordinary` имеют нулевой UUID и молча игнорируют эту настройку.

В настоящее время кэш применяется только к частям Wide: данные компактных частей не читаются из кэша столбцов и не записываются в него, поэтому ускорится ли чтение, зависит от формата части.

Запись содержит непрерывный диапазон гранул одной полосы. Гранула попадает в кэш только после того, как она прочитана целиком — от первой до последней строки; чтение из кэша выполняется погранульно, а диапазоны, записанные разными операциями чтения, сливаются. Благодаря этому операции чтения, разбивающие часть на разные диапазоны меток, используют одни и те же записи.

## use_constant_folding_in_index_analysis {#use_constant_folding_in_index_analysis}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.7"},{"label": "0"},{"label": "Новая настройка: подстановка констант уровня партиции в предикат фильтра для каждой части при анализе индексов MergeTree, что улучшает отсечение данных для фильтров, ветви которых зависят от значений партиции."}]}]} />

Подставляет константы уровня партиции в предикат фильтра при анализе первичного ключа и индекса пропуска данных для каждой части.

Если ключ партиционирования используется в фильтре вместе со столбцами первичного ключа или индекса пропуска данных, анализ индексов может отдельно сворачивать значение партиции в пределах каждой части. Это особенно полезно для дизъюнктивных фильтров, ветви которых относятся к разным партициям. Например, при `PARTITION BY a` и `ORDER BY b`:

```sql
SELECT * FROM t WHERE (a = 1 AND b >= 1) OR (a = 2 AND b > 10) OR (a = 3 AND b > 10)
```

Для части в партиции `a = 1` условие упрощается до `b >= 1`, а для партиций `a = 2` и `a = 3` — до `b > 10`, поэтому каждая часть анализируется с предикатом, который действительно к ней применим.

Возможные значения:

* 0 — Отключено.
* 1 — Включено.

## use_hedged_requests {#use_hedged_requests}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "21.9"},{"label": "1"},{"label": "По умолчанию включает возможность Hedged Requests"}]}]} />

Включает логику hedged requests для удалённых запросов. Позволяет устанавливать для одного запроса несколько соединений с разными репликами.
Новое соединение создаётся, если существующее соединение с репликой не было установлено в течение `hedged_connection_timeout`
или если в течение `receive_data_timeout` не были получены данные. Запрос использует первое соединение, которое отправит непустой пакет Прогресс (или пакет данные, если `allow_changing_replica_until_first_data_packet`);
остальные соединения отменяются. Поддерживаются запросы с `max_parallel_replicas > 1`.

Включено по умолчанию.

Значение по умолчанию в Cloud: `0`.

## use_indexes_refiner_in_read_pools {#use_indexes_refiner_in_read_pools}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для отбрасывания диапазонов меток, полностью отфильтрованных индексами пропуска данных или индексом проекции, до создания задач чтения в пулах чтения MergeTree."}]}]} />

Применяет индексы, вычисляемые при чтении данных, непосредственно внутри пулов чтения MergeTree: диапазоны меток, полностью отфильтрованные индексами пропуска данных (см. `use_skip_indexes_on_data_read`) или индексом проекции (см. `optimize_use_projection_filtering`), отбрасываются до создания задач чтения, а не пропускаются гранула за гранулой в процессе чтения.

В пуле чтения с предварительным чтением отброшенные диапазоны никогда не подвергаются предварительному чтению, однако границы задач и допуск предварительного чтения через `filesystem_prefetch_max_memory_usage` / `filesystem_prefetches_limit` по-прежнему определяются до фильтрации. Поэтому при высокоселективных фильтрах оставшиеся задачи могут оказаться меньше заданного размера, а допуск — излишне консервативным.

## use_uncompressed_cache {#use_uncompressed_cache}

<SettingsInfoBlock type="Bool" default_value="0" />

Определяет, использовать ли кэш несжатых данных. Допустимые значения: 0 или 1. По умолчанию — 0 (отключено).
Использование кэша несжатых данных (только для таблиц семейства MergeTree) может значительно снизить задержку и повысить пропускную способность при работе с большим количеством коротких запросов. Включайте этот параметр для пользователей, которые часто отправляют короткие запросы. Также обратите внимание на параметр конфигурации [uncompressed&#95;cache&#95;size](/ru/reference/settings/server-settings/settings/uncompressed-cache#uncompressed_cache_size) (задается только в файле конфигурации) — размер блоков кэша несжатых данных. По умолчанию он составляет 8 GiB. Кэш несжатых данных заполняется по мере необходимости, а наименее используемые данные удаляются автоматически.

Для запросов, которые считывают хотя бы относительно большой объем данных (один миллион строк или более), кэш несжатых данных отключается автоматически, чтобы освободить место для действительно небольших запросов. Это означает, что параметр &#39;use&#95;uncompressed&#95;cache&#39; можно всегда оставлять равным 1.
