## database_replicated_allow_only_replicated_engine {#database_replicated_allow_only_replicated_engine}

<SettingsInfoBlock type="Bool" default_value="0" />

Разрешает создавать таблицу в базе данных с движком `Replicated`, только если таблица либо реплицирует собственные
данные, хранящиеся на диске, либо вообще не хранит собственных данных на диске.

Это ограничение распространяется только на собственные данные таблицы на диске, включая данные на удалённых дисках. Оно не гарантирует
сохранность данных в памяти или данных, управляемых внешними системами.

Например, разрешены `ReplicatedMergeTree`, движки, хранящие данные в памяти, такие как `Memory` и `Buffer`, metadata-only движки,
такие как `Merge` и `Alias`, а также движки внешних хранилищ и озер данных, такие как `S3` и `AzureBlobStorage`.
Non-replicated движки, хранящие данные таблицы на диске, такие как `MergeTree`, `Log`, `File` и `Set`,
отклоняются — в том числе если их политика хранения, доступная для записи, использует удалённые диски. Таблицы `Set` и `Join`, созданные с
`SETTINGS persistent = 0`, хранят данные только в памяти, поэтому разрешены.

Таблицы `Distributed`, `Remote` и `RemoteSecure` разрешены. Их необязательная локальная фоновая очередь `INSERT` —
это временный буфер отправки, а не данные самой таблицы. Она не реплицируется; чтобы обойтись без этой очереди, задайте
`distributed_foreground_insert = 1`.

Значение по умолчанию в облаке: `1`.

## database_replicated_always_detach_permanently {#database_replicated_always_detach_permanently}

<SettingsInfoBlock type="Bool" default_value="0" />

Выполнять DETACH TABLE как DETACH TABLE PERMANENTLY, если используется движок базы данных Replicated

## database_replicated_enforce_synchronous_settings {#database_replicated_enforce_synchronous_settings}

<SettingsInfoBlock type="Bool" default_value="0" />

Включает синхронное ожидание для некоторых запросов (см. также database&#95;atomic&#95;wait&#95;for&#95;drop&#95;and&#95;detach&#95;synchronously, mutations&#95;sync, alter&#95;sync). Не рекомендуется включать эти настройки.

## database_replicated_initial_query_timeout_sec {#database_replicated_initial_query_timeout_sec}

<SettingsInfoBlock type="UInt64" default_value="300" />

Задаёт, сколько времени начальный DDL-запрос должен ждать, пока база данных Replicated обработает предыдущие записи в очереди DDL, в секундах.

Возможные значения:

* Положительное целое число.
* 0 — Без ограничений.
