## async_insert_deduplicate {#async_insert_deduplicate}

<SettingsInfoBlock type="Bool" default_value="0" />

Для асинхронных запросов INSERT в реплицируемой таблице задаёт, следует ли выполнять дедупликацию вставляемых блоков.

Этот параметр действует только при значении `backward_compatible_choice` для [`deduplicate_insert`](/ru/reference/settings/session-settings/deduplicate-insert#deduplicate_insert).

## async_insert_select_as_async_insert {#async_insert_select_as_async_insert}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Асинхронные вставки для запросов `INSERT ... SELECT` теперь включены по умолчанию."}]}]} />

Определяет, может ли запрос `INSERT ... SELECT`, запущенный пользователем, использовать очередь асинхронных вставок, если включена настройка `async_insert` и запрос удовлетворяет условиям (один небольшой блок, вставляемый в таблицу семейства `MergeTree` без зависимых представлений). Если настройка отключена, `INSERT ... SELECT` всегда выполняется синхронно независимо от значения `async_insert`. Внутренние вставки (refreshable materialized view, `POPULATE`, `CREATE TABLE ... AS SELECT`) всегда выполняются синхронно и эту настройку игнорируют.
