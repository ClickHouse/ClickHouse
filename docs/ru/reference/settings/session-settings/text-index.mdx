## text_index_like_min_pattern_length {#text_index_like_min_pattern_length}

<SettingsInfoBlock type="UInt64" default_value="4" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "4"},{"label": "новая настройка"}]}]} />

Минимальная длина буквенно-цифровой подстроки в шаблоне LIKE/ILIKE или подстроки в `startsWith`/`endsWith`,
необходимая для использования оценки LIKE текстового индекса при сканировании словаря.
Шаблоны короче этого порога соответствуют слишком большому количеству токенов словаря и пропускаются во избежание ресурсоемкого сканирования.

При использовании токенизатора `array`, при котором подходит любой шаблон, порог сравнивается с количеством символов без подстановочных знаков во всем шаблоне.

Требует, чтобы `use_text_index_like_evaluation_by_dictionary_scan` был включен.

## text_index_posting_list_apply_mode {#text_index_posting_list_apply_mode}

<SettingsInfoBlock type="TextIndexPostingListApplyMode" default_value="lazy" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "lazy"},{"label": "Запросы с текстовым индексом теперь декодируют списки вхождений по требованию с помощью курсора вместо материализации в Roaring Bitmaps, что снижает использование памяти и время CPU для выборочных запросов."}]}, {"id": "row-2","items": [{"label": "26.6"},{"label": "materialize"},{"label": "Новая настройка для режима отложенного применения списков вхождений"}]}]} />

Управляет способом применения списков вхождений в запросах, использующих текстовый индекс.
&#39;materialize&#39; сразу декодирует списки вхождений в Roaring Bitmaps.
&#39;lazy&#39; (по умолчанию) использует декодирование по требованию на основе курсора (требуется формат индекса с сериализованным кодеком).
&#39;lazy&#39; применяется только там, где поддерживается: запросы с шаблонами (например, `LIKE`) и части с индексом, записанным более старой версией, переключаются на &#39;materialize&#39;.

## text_index_postings_intersection_algorithm {#text_index_postings_intersection_algorithm}

<SettingsInfoBlock type="TextIndexPostingsIntersectionAlgorithm" default_value="auto" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "auto"},{"label": "Новая настройка, заменяющая `text_index_lazy_intersection_density_threshold`: выбирает алгоритм пересечения списков вхождений в режиме их отложенного применения. Значение `auto` сохраняет прежнее поведение по умолчанию, поэтому настройка `compatibility` не должна его менять."}]}]} />

Выбирает алгоритм пересечения списков вхождений в режиме их отложенного применения (`text_index_posting_list_apply_mode = 'lazy'`).

* `auto` (по умолчанию): алгоритм leapfrog используется, только если самый разреженный список вхождений позволяет пропускать целые упакованные блоки самого плотного; в остальных случаях битмапы пересекаются полным перебором.
* `bruteforce`: всегда пересекать битмапы полным перебором.
* `leapfrog`: всегда использовать пересечение методом leapfrog.

При пересечении 256 и более токенов всегда используется leapfrog.
