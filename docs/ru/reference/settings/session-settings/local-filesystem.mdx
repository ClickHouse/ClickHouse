<div id="local_filesystem_read_method">
  ## local_filesystem_read_method
</div>

<SettingsInfoBlock type="String" default_value="pread_threadpool" />

Метод чтения данных из локальной файловой системы; одно из следующих значений: read, pread, mmap, io&#95;uring, pread&#95;threadpool.

Метод &#39;pread&#95;threadpool&#39; передаёт операцию чтения в пул потоков, если данные ещё не находятся в кэше страниц; это проверяется с помощью системного вызова `preadv2` и флага `RWF_NOWAIT`. Для такой проверки требуется Linux 5.11 или новее, а системный вызов не должен отклоняться профилем `seccomp` среды выполнения контейнеров. При запуске проверяется, доступен ли системный вызов, и если нет, значение этой настройки по умолчанию меняется на &#39;pread&#39;, поскольку передача каждой операции чтения в пул потоков, включая чтения из кэша страниц, требует значительных затрат; причина записывается в журнал сервера. Профиль `seccomp` обнаруживается только в том случае, если он отклоняет системный вызов с кодом ошибки, как это делают среды выполнения контейнеров; профиль, который вместо этого завершает процесс, обнаружить невозможно. Значение, явно заданное в конфигурации или с помощью `SET`, не изменяется.

Метод &#39;io&#95;uring&#39; экспериментальный и не работает для Log, TinyLog, StripeLog, File, Set и JOIN, а также других таблиц с файлами, допускающими дописывание, при одновременных чтении и записи.
Если вы читали в интернете разные статьи об &#39;io&#95;uring&#39;, не стоит ими обольщаться. Это не более эффективный метод чтения файлов, кроме случаев с большим количеством мелких запросов IO, что для ClickHouse нехарактерно. Нет причин включать &#39;io&#95;uring&#39;.

  ## local_filesystem_read_prefetch
</div>

<SettingsInfoBlock type="Bool" default_value="0" />
