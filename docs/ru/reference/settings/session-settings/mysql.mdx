Определяет, как типы MySQL преобразуются в соответствующие типы ClickHouse. Это разделенный запятыми список, содержащий любую комбинацию из `decimal`, `datetime64`, `date2Date32`, `date2String` или `geometry`. Все современные сопоставления (`decimal`, `datetime64`, `date2Date32`, `geometry`) включены по умолчанию.

* `decimal`: преобразует типы `NUMERIC` и `DECIMAL` в `Decimal`, если это допускает precision.
* `datetime64`: преобразует типы `DATETIME` и `TIMESTAMP` в `DateTime64` вместо `DateTime`, если precision не равна `0`.
* `date2Date32`: преобразует `DATE` в `Date32` вместо `Date`. Имеет приоритет над `date2String`.
* `date2String`: преобразует `DATE` в `String` вместо `Date`. Переопределяется `datetime64`.
* `geometry`: преобразует пространственные типы MySQL (`LINESTRING`, `POLYGON`, `MULTILINESTRING`, `MULTIPOLYGON`, `MULTIPOINT`) в соответствующие геометрические типы ClickHouse, а обобщенный тип `GEOMETRY` — в универсальный тип `Geometry`. `POINT` всегда преобразуется в `Point` независимо от этой опции. Поскольку обобщенный столбец `GEOMETRY` может содержать любой подтип, при чтении значения, подтип которого не имеет аналога в ClickHouse (`GEOMETRYCOLLECTION`), генерируется исключение; столбцы, объявленные как `GEOMETRYCOLLECTION`, сопоставляются с `String`. Допускающий NULL пространственный столбец, отличный от `POINT`, также сопоставляется с `Nullable(String)`, поскольку `Point` — единственный геометрический тип, который может быть вложен в `Nullable`. Каждая такая строка представляет собой 4-байтовый префикс SRID, за которым следует полезная нагрузка WKB, возвращаемая MySQL. Всё вышесказанное применяется, когда схема выводится из типов столбцов таблицы MySQL; если источником является запрос (аргумент `query(...)` табличной функции `mysql` или движка таблицы `MySQL`), MySQL сообщает о каждом пространственном столбце результата как об обобщенном `GEOMETRY` без конкретного подтипа, поэтому такие столбцы, включая `POINT`, сопоставляются с `String` (`Nullable(String)`, если допускают NULL).
