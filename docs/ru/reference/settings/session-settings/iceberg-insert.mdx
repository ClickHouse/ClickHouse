Максимальный размер в байтах файла данных Parquet Iceberg при выполнении операции вставки.

Значение по умолчанию повторяет документированное значение по умолчанию свойства таблицы Iceberg `write.target-file-size-bytes` (512 МиБ),
см. https://iceberg.apache.org/docs/1.5.2/configuration/. Это ограничение сравнивается с размером файла,
записанного к текущему моменту, то есть с размером сжатых данных, поэтому файл может превысить его на объём данных, которые ещё удерживаются в буфере записи, например
незавершённых групп строк Parquet и групп, находящихся в процессе кодирования. `iceberg_insert_max_rows_in_data_file` ограничивает файл
независимо от его размера.

## iceberg_insert_single_manifest_for_all_partitions {#iceberg_insert_single_manifest_for_all_partitions}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Новая настройка."}]}]} />

`INSERT` в партиционированную таблицу Iceberg записывает один файл манифеста для всех затронутых партиций, как это делают Spark
и PyIceberg, а не отдельный файл манифеста для каждой партиции. Это правило действует в пределах каждого потока вставки: каждый поток коммитит собственный
снимок с собственным манифестом, поэтому `INSERT` записывает ровно один манифест только при `max_insert_threads = 1`.
Кроме того, `OPTIMIZE TABLE ... MANIFEST` в этом случае объединяет манифесты разных партиций в один.
`ALTER TABLE ... DROP PARTITION` не может удалить партицию, манифест которой общий с другими партициями.
