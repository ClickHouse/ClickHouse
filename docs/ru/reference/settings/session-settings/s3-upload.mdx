## s3_upload_checksum_algorithm {#s3_upload_checksum_algorithm}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": ""},{"label": "Новая настройка для выбора алгоритма контрольной суммы при загрузке в S3."}]}]} />

Алгоритм контрольной суммы, используемый ClickHouse при загрузке данных в `S3`. `CRC32` и `SHA256` отправляются в виде гибких заголовков `x-amz-checksum-*`, а `MD5` — в виде заголовка `Content-MD5`.

По умолчанию значение пустое, и ClickHouse позволяет AWS SDK вычислять `Content-MD5`. В режиме FIPS `MD5` недоступен, поэтому SDK молча не добавляет его, и загрузка выполняется вообще без контрольной суммы. Вместо этого задайте `CRC32` или `SHA256`, чтобы добавить гибкую контрольную сумму. В случаях, когда применяется эта настройка, явно заданный `MD5` отклоняется.

Для бакетов, отличных от `S3Express`, параметр `s3_disable_checksum` отменяет действие этой настройки. Она применяется при создании клиента `S3`, поэтому действует для операций в рамках запроса, таких как табличная функция `s3` и `BACKUP ... TO S3`; последующий `SET` для отдельного запроса не перенастраивает уже созданный долгоживущий клиент, например диск `S3`.

Бакеты `S3Express` требуют гибкой контрольной суммы и не принимают `Content-MD5`: явно заданные `CRC32` или `SHA256` используются, при пустом значении применяется `CRC32`, а явно заданный `MD5` отклоняется.

Конечные точки `GCS` (`storage.googleapis.com`) полностью игнорируют эту настройку и сохраняют поведение SDK в отношении `Content-MD5`, поскольку `GCS` отклоняет запросы, подписанные `SigV4` и содержащие заголовки AWS `x-amz-checksum-*`.

Копирование на стороне сервера игнорирует эту настройку.

## s3_upload_part_size_multiply_factor {#s3_upload_part_size_multiply_factor}

<SettingsInfoBlock type="UInt64" default_value="2" />

Увеличивайте `s3_min_upload_part_size` в это число раз каждый раз, когда за одну запись в S3 было загружено `s3_multiply_parts_count_threshold` частей.

## s3_upload_part_size_multiply_parts_count_threshold {#s3_upload_part_size_multiply_parts_count_threshold}

<SettingsInfoBlock type="UInt64" default_value="500" />

Каждый раз после загрузки такого количества частей в S3 значение s3&#95;min&#95;upload&#95;part&#95;size умножается на s3&#95;upload&#95;part&#95;size&#95;multiply&#95;factor.
