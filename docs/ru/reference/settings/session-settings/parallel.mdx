## parallel_distributed_insert_select {#parallel_distributed_insert_select}

<SettingsInfoBlock type="UInt64" default_value="2" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.7"},{"label": "2"},{"label": "По умолчанию включает параллельный distributed insert select"}]}]} />

Включает параллельное выполнение запроса `INSERT ... SELECT` для Distributed.

Если выполняются запросы `INSERT INTO distributed_table_a SELECT ... FROM distributed_table_b`, обе таблицы используют один и тот же кластер, и обе таблицы либо [реплицируемые](/ru/reference/engines/table-engines/mergetree-family/replication), либо нереплицируемые, то этот запрос обрабатывается локально на каждом сегменте.

Возможные значения:

* `0` — Отключено.
* `1` — `SELECT` будет выполняться на каждом сегменте из базовой таблицы движка Distributed.
* `2` — `SELECT` и `INSERT` будут выполняться на каждом сегменте из/в базовую таблицу движка Distributed.

Начиная с v25.4, `INSERT ... SELECT` из источника `ReplicatedMergeTree` или `SharedMergeTree` также можно распараллелить между репликами. Чтобы включить это:

* `parallel_distributed_insert_select = 2`
* `enable_parallel_replicas = 1`

<Note>
  Переписанный запрос, включая каждое выражение в `SELECT` (подзапросы, пользовательские функции (UDF) и т. д.), выполняется на сегментах с учётными данными из конфигурации кластера — по той же модели доверия, что и другая обработка на стороне сегментов, например подзапросы в `IN` без `GLOBAL`. Если операции чтения на стороне сегментов должны авторизоваться от имени вызывающего пользователя, настройте межсерверный секрет (элемент `secret` в конфигурации кластера).
</Note>

## parallel_hash_join_threshold {#parallel_hash_join_threshold}

<SettingsInfoBlock type="UInt64" default_value="100000" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "100000"},{"label": "новая настройка"}]}, {"id": "row-2","items": [{"label": "25.4"},{"label": "0"},{"label": "новая настройка"}]}, {"id": "row-3","items": [{"label": "25.3"},{"label": "0"},{"label": "новая настройка"}]}]} />

Для hash JOIN типа `INNER`, `LEFT`, `RIGHT` или `FULL` этот порог определяет способ построения хеш-таблицы.
Если оценочное число строк в правой таблице меньше порога, JOIN строит хеш-таблицу целиком, одной частью в одном потоке.
Если оценка равна порогу или превышает его, а также если оценки нет, JOIN разбивает хеш-таблицу на части, которые одновременно заполняются не более чем `max_threads` потоками (одним потоком при `max_threads = 1`).
При значении `0` хеш-таблица разбивается всегда.
Если `hash_join_layout` имеет значение `serial` или `parallel`, этот порог не используется: JOIN строит одну часть или разбивает хеш-таблицу независимо от оценки.
Оценка берётся из плана запроса или из статистики предыдущих выполнений того же JOIN (см. `collect_hash_table_stats_during_joins`).
Для правой таблицы, которая заведомо пуста (например, таблицы `MergeTree` без частей данных), план запроса даёт оценку в 0 строк.
Для соединений `ASOF` оценка никогда не вычисляется, а при `query_plan_optimize_join_order_limit = 0` её не получает ни один JOIN.

## parallel_non_joined_rows_processing {#parallel_non_joined_rows_processing}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "1"},{"label": "Новая настройка для включения параллельной обработки строк без совпадений в RIGHT/FULL JOIN с алгоритмом parallel_hash."}]}]} />

Позволяет нескольким потокам параллельно обрабатывать строки без совпадений из правой таблицы при RIGHT и FULL JOIN.
Это может ускорить этап обработки строк без совпадений в хеш-соединениях с большими правыми таблицами, если хеш-таблица строится в нескольких потоках (см. `parallel_hash_join_threshold`).
Если настройка отключена или хеш-таблица строится в одном потоке, строки без совпадений обрабатываются одним потоком.
В любом случае строки без совпадений возвращаются в произвольном порядке. Используйте `ORDER BY`, если запросу нужен детерминированный порядок.

## parallel_replica_offset {#parallel_replica_offset}

<BetaBadge />

<SettingsInfoBlock type="UInt64" default_value="0" />

Это внутренний параметр, который не следует использовать напрямую; он относится к деталям реализации режима «параллельных реплик». Этот параметр автоматически задается сервером-инициатором для распределенных запросов и содержит индекс реплики, участвующей в обработке запроса в режиме параллельных реплик.
