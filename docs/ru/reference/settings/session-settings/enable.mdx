<div id="enable_adaptive_aggregator">
  ## enable_adaptive_aggregator
</div>

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Новая настройка для включения адаптивной агрегации `GROUP BY`: локальная хеш-таблица каждого потока замораживается по достижении `adaptive_aggregator_freeze_threshold` ключей, благодаря чему частые ключи продолжают агрегироваться в небольших локальных таблицах, а редкие ключи по хешу направляются в очереди отдельных бакетов и агрегируются ровно один раз при параллельном слиянии по бакетам; редкие ключи хранятся и обрабатываются один раз, а не по одному разу для каждого потока."}]}]} />

Включает адаптивный алгоритм `GROUP BY`: каждый поток агрегирует данные в локальную хеш-таблицу, пока число ключей не достигнет `adaptive_aggregator_freeze_threshold` (или объём памяти не достигнет `adaptive_aggregator_freeze_threshold_bytes`), после чего таблица замораживается. Строки уже встречавшихся (частых) ключей продолжают обновляться в этой таблице, а новые (редкие) ключи по хешу направляются в очереди отдельных бакетов и агрегируются ровно один раз при параллельном слиянии по бакетам. Частые ключи остаются в небольших таблицах, помещающихся в кэше, а редкие ключи хранятся и обрабатываются один раз, а не по одному разу для каждого потока.

Настройки внешней агрегации (`max_bytes_before_external_group_by`, `max_bytes_ratio_before_external_group_by`) учитываются: после превышения порога очереди заранее переносятся в общую таблицу, а если этого недостаточно для возврата ниже порога, общая таблица выгружается на диск с помощью обычной внешней агрегации.

Включает `DISTINCT` в подзапросах `IN`. Это компромиссная настройка: при включении она может значительно уменьшить размер временных таблиц, передаваемых для распределённых подзапросов `IN`, и существенно ускорить передачу данных между сегментами, поскольку отправляются только уникальные значения.

<div id="enable_group_by_top_k_optimization">
  ## enable_group_by_top_k_optimization
</div>

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Новая настройка для управления оптимизацией фильтрации TopK при агрегации в запросах `GROUP BY key ORDER BY key LIMIT N`."}]}]} />

Включает оптимизацию фильтрации TopK при агрегации в запросах `GROUP BY keys ORDER BY <prefix of keys> LIMIT K`, а также в запросах `GROUP BY keys LIMIT K` без `ORDER BY` (в этом случае допустим любой набор из `K` групп, поэтому синтезируется сортировка по всем ключам).

Когда параметр включен, агрегатор поддерживает ограниченную кучу из `K` лучших ключей, найденных к текущему моменту, и не вставляет новые строки в хеш-таблицу, если их ключ группировки не может попасть в итоговый результат. Это позволяет избежать агрегации строк, которые будут отброшены последующим `ORDER BY ... LIMIT`. Если куча ранжирует полный ключ `GROUP BY`, она также удаляет вытесненные группы из промежуточной хеш-таблицы, ограничивая ее размер значением `LIMIT`, а не числом различных ключей. Если `ORDER BY` охватывает только собственный префикс ключей `GROUP BY`, ранжирование не позволяет определить полную группу, поэтому применяется только пропуск строк: хеш-таблица хранит все допущенные группы и все еще может расти с увеличением мощности оставшихся столбцов ключа.

Оптимизация отключается, если запрошенный `LIMIT` превышает [query&#95;plan&#95;max&#95;limit&#95;for&#95;top&#95;k&#95;optimization](/ru/reference/settings/session-settings/query-plan#query_plan_max_limit_for_top_k_optimization) или жесткий предел `100000`, поскольку потребление памяти и CPU кучей растет с увеличением запрошенного `LIMIT`.

Оптимизация не применяется к формам запросов, в которых удаление групп может изменить результат, включая `WITH TOTALS`, `HAVING`, `QUALIFY`, оконные функции, `ROLLUP`/`CUBE`/`GROUPING SETS`, `LIMIT WITH TIES`, `COLLATE` для любого из сопоставленных ключей `GROUP BY` (`COLLATE` для более позднего столбца `ORDER BY` после полного префикса ключа не влияет на то, какие группы попадут в результат, поэтому не отключает оптимизацию), `ORDER BY` по агрегату или по чему-либо, что не является начальным префиксом ключей `GROUP BY`, а также запросы, в которых задан `max_rows_to_group_by` или `exact_rows_before_limit`.

Возможные значения:

* 0 — Отключено.
* 1 — Включено.
