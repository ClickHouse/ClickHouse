## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "Автоматические параллельные реплики теперь отклоняют запрос, если более половины его чтения пришлось бы повторять на каждой реплике. Ранее ограничения не было; именно такое поведение по-прежнему задаёт значение 1."}]}]} />

Доля объёма чтения запроса (от общего объёма), которая может считываться каждой репликой целиком, а не распределяться между ними, прежде чем автоматические параллельные реплики отклонят запрос.

Распределяется только то чтение, которое координируют параллельные реплики; все остальные чтения того же поддерева полностью выполняются на каждой
реплике. Эти чтения в любом случае занимают одинаковое местное время, поэтому при сравнении по модели стоимости они не учитываются,
однако кластер выполняет для них в `max_parallel_replicas` раз больше работы. Эта настройка ограничивает такие потери: при значении по умолчанию 0.5 запрос, у которого координируемое чтение составляет менее половины всего объёма чтения,
продолжает выполняться на одном узле независимо от результата сравнения времени.

Установите значение 1, чтобы допускать любой объём дублированного чтения: в этом случае восстанавливается прежнее поведение, при котором сравнивается только время.

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

Пороговый объём байт для чтения на реплику, при котором автоматически включаются параллельные реплики (применяется только при `automatic_parallel_replicas_mode`=1). 0 означает отсутствие порога.
Общий объём байт для чтения оценивается на основе собранной статистики.

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "Новая настройка"}]}]} />

Включает автоматическое переключение на выполнение запроса с параллельными репликами на основе собранной статистики. Требует `enable_parallel_replicas = 1`, `parallel_replicas_local_plan = 1` и указания `cluster_for_parallel_replicas`. При `enable_parallel_replicas = 2` параллельные реплики используются принудительно, а автоматический режим не применяется.
0 — выключено, 1 — включено, 2 — включен только сбор статистики (переключение на выполнение с параллельными репликами отключено).

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Новая настройка. Автоматическая параллельная реплика теперь запоминает для каждого плана запроса границу доли работы, приходящейся на реплики; ранее для её определения каждый запрос строил план с параллельными репликами."}]}]} />

Позволяет автоматической параллельной реплике запоминать для каждого плана запроса, где заканчивается доля работы, приходящаяся на реплики. Благодаря этому
для повторного запроса, для которого статистика не рекомендует использовать параллельные реплики, решение принимается без построения плана с параллельными
репликами.

Отключите настройку, если нужно, чтобы каждый запрос полностью оплачивал стоимость принятия этого решения, например при бенчмаркинге этой стоимости.
