## automatic_parallel_replicas_ignore_thresholds {#automatic_parallel_replicas_ignore_thresholds}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Новая настройка: для тестирования игнорирует ограничение на число потоков чтения в стоимостной модели автоматических параллельных реплик, чтобы решение для небольших операций чтения принималось по результату сравнения, а не досрочно определялось этим ограничением."}]}]} />

Предназначена для тестирования стоимостной модели автоматических параллельных реплик: игнорирует ограничение на число потоков, которые операция чтения может эффективно задействовать (вычисляется на основе `merge_tree_min_bytes_per_task_for_remote_reading`). Без этой настройки ограничение приводит обе стороны сравнения к одному и тому же значению, если операция чтения слишком мала, чтобы задействовать `max_threads`. В результате сравнение сводится к `0 > output_bytes / replicas`, и решение по запросу принимается ещё до обращения к стоимостной модели.

Настройка намеренно НЕ влияет на `automatic_parallel_replicas_min_bytes_per_replica`: чтобы отключить это условие, установите для него значение 0 — именно для этого оно и предназначено. Она также не меняет сайзинг задач чтения и не отключает повторный сбор статистики, в которой возникло расхождение: решение, принятое на основе устаревшей статистики, не является решением стоимостной модели.

## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "Автоматические параллельные реплики теперь отклоняют запрос, если более половины его чтения пришлось бы повторять на каждой реплике. Ранее ограничения не было; именно такое поведение по-прежнему задаёт значение 1."}]}]} />

Доля объёма чтения запроса (от общего объёма), которая может считываться каждой репликой целиком, а не распределяться между ними, прежде чем автоматические параллельные реплики отклонят запрос.

Распределяется только то чтение, которое координируют параллельные реплики; все остальные чтения того же поддерева полностью выполняются на каждой
реплике. Эти чтения в любом случае занимают одинаковое местное время, поэтому при сравнении по модели стоимости они не учитываются,
однако кластер выполняет для них в `max_parallel_replicas` раз больше работы. Эта настройка ограничивает такие потери: при значении по умолчанию 0.5 запрос, у которого координируемое чтение составляет менее половины всего объёма чтения,
продолжает выполняться на одном узле независимо от результата сравнения времени.

Установите значение 1, чтобы допускать любой объём дублированного чтения: в этом случае восстанавливается прежнее поведение, при котором сравнивается только время.

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

Пороговый объём байт для чтения на реплику, при котором автоматически включаются параллельные реплики (применяется только при `automatic_parallel_replicas_mode`=1). 0 означает отсутствие порога.
Общий объём байт для чтения оценивается на основе собранной статистики.

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "Новая настройка"}]}]} />

Включает автоматическое переключение на выполнение запроса с параллельными репликами на основе собранной статистики. Требует `enable_parallel_replicas = 1`, `parallel_replicas_local_plan = 1` и указания `cluster_for_parallel_replicas`. При `enable_parallel_replicas = 2` параллельные реплики используются принудительно, а автоматический режим не применяется.
0 — выключено, 1 — включено, 2 — включен только сбор статистики (переключение на выполнение с параллельными репликами отключено).

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Новая настройка. Автоматическая параллельная реплика теперь запоминает для каждого плана запроса границу доли работы, приходящейся на реплики; ранее для её определения каждый запрос строил план с параллельными репликами."}]}]} />

Позволяет автоматической параллельной реплике запоминать для каждого плана запроса, где заканчивается доля работы, приходящаяся на реплики. Благодаря этому
для повторного запроса, для которого статистика не рекомендует использовать параллельные реплики, решение принимается без построения плана с параллельными
репликами.

Отключает запоминание границ. Чтобы измерить в бенчмарке стоимость построения плана с параллельными репликами, также установите
`automatic_parallel_replicas_undecided_retry_after_executions = 0`: планы, последнее построение которых завершилось без
принятия решения, пропускаются независимо от этой настройки.

## automatic_parallel_replicas_statistics_drift_ratio {#automatic_parallel_replicas_statistics_drift_ratio}

<SettingsInfoBlock type="Float" default_value="1.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1.5"},{"label": "Новая настройка. Ранее доля была фиксированной и равнялась 2; теперь при изменении данных статистика собирается заново раньше."}]}]} />

Допустимое расхождение между количеством строк, выбираемых при чтении, и количеством строк, выбранных в момент, когда механизм автоматических параллельных реплик собирал
статистику. Задаётся как отношение большего значения к меньшему. При превышении этого значения статистика считается устаревшей и собирается заново,
а не используется для принятия решения.

Учитываются строки, выбранные в ходе анализа индексов на initiator, поэтому отсечение, которое выполняют только реплики во время чтения (например,
с помощью собственных кэшей условий запроса), не учитывается. Чем меньше доля, тем раньше статистика собирается заново при изменении
таблицы. Значение должно быть больше 1.

## automatic_parallel_replicas_undecided_retry_after_executions {#automatic_parallel_replicas_undecided_retry_after_executions}

<SettingsInfoBlock type="UInt64" default_value="10" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "10"},{"label": "Новая настройка. Механизм автоматических параллельных реплик теперь пропускает построение плана с параллельными репликами в течение нескольких выполнений плана запроса, если его последнее построение завершилось без принятия решения; ранее план строился при каждом выполнении."}]}]} />

Количество выполнений плана запроса, в которых пропускается построение плана с параллельными репликами после того, как его последнее построение в режиме автоматических параллельных реплик завершилось без принятия решения: два плана не удалось сравнить, планировщик не использовал параллельные реплики
в плане, построенном с ними, какой-либо шаг плана не может собирать статистику или при сборе ничего не было измерено. Параллельные выполнения действуют по очереди: одно из каждых `automatic_parallel_replicas_undecided_retry_after_executions + 1` строит план заново.
После первого такого исхода для плана запроса следующее выполнение сразу строит план заново — на случай, если первое выполнение заполнило другие кэши статистики и решения планировщика изменятся.

Значение 0 отключает откладывание после исходов без принятия решения. Настройка не зависит от `automatic_parallel_replicas_remember_boundary`, которая позволяет не выполнять построение для планов, решение по которым принято на основе статистики.
