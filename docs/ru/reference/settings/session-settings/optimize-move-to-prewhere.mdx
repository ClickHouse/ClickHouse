## optimize_move_to_prewhere {#optimize_move_to_prewhere}

<SettingsInfoBlock type="Bool" default_value="1" />

Включает или отключает автоматическую оптимизацию [PREWHERE](/ru/reference/statements/select/prewhere) в запросах [SELECT](/ru/reference/statements/select/index).

Работает только для [таблиц семейства *MergeTree](/ru/reference/engines/table-engines/mergetree-family/index).

Возможные значения:

* 0 — Автоматическая оптимизация `PREWHERE` отключена.
* 1 — Автоматическая оптимизация `PREWHERE` включена.

## optimize_move_to_prewhere_if_final {#optimize_move_to_prewhere_if_final}

Включает или отключает автоматическую оптимизацию [PREWHERE](/ru/reference/statements/select/prewhere) в запросах [SELECT](/ru/reference/statements/select/index) с модификатором [FINAL](/ru/reference/statements/select/from#final-modifier).

Переносятся только условия, которые зависят исключительно от ключа сортировки и являются детерминированными в пределах запроса,
поэтому результат применения `FINAL` не меняется. Для [GraphiteMergeTree](/ru/reference/engines/table-engines/mergetree-family/graphitemergetree)
`FINAL` объединяет соседние строки одного пути в одну строку. Следовательно, оптимизация переносит только условия по столбцу пути
и только если путь является первым столбцом ключа сортировки.

Работает только для таблиц семейства [*MergeTree](/ru/reference/engines/table-engines/mergetree-family/index).

Возможные значения:

* 0 — Автоматическая оптимизация `PREWHERE` в запросах `SELECT` с модификатором `FINAL` отключена.
* 1 — Автоматическая оптимизация `PREWHERE` в запросах `SELECT` с модификатором `FINAL` включена.

## optimize_move_to_prewhere_respect_short_circuit {#optimize_move_to_prewhere_respect_short_circuit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "1"},{"label": "Новая настройка: автоматический PREWHERE оставляет условие, которое может сгенерировать исключение, после условий, которые укороченное вычисление применяет перед ним. Значение `compatibility` ниже 26.12 возвращает прежний порядок."}]}]} />

При перемещении условий из WHERE в PREWHERE условие, которое может сгенерировать исключение, остаётся после условий, записанных перед ним,
если при укороченном вычислении оно вычислялось бы только на тех строках, которые эти условия оставляют.
Например, `a = 'one' AND toDateTime64(s, 3) > '2020-01-01'` не разбирает `s` в строках, где `a != 'one'`.
Такое условие не упорядочивается по стоимости. Если настройка отключена, условия упорядочиваются так, как если бы
[short&#95;circuit&#95;function&#95;evaluation](/ru/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation) имела значение `disable`, и запрос может сгенерировать исключение
на строках, которые отсекает предшествующее условие.
