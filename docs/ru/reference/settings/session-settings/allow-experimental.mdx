## allow_experimental_analyzer {#allow_experimental_analyzer}

**Псевдонимы**: `enable_analyzer`

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "1"},{"label": "Настройка устарела: анализатор теперь обязателен, а прежний анализ запросов больше не поддерживается. Попытка отключить его отклоняется, а не игнорируется; `compatibility` с версией ниже 24.3 больше не возвращает прежнее поведение."}]}, {"id": "row-2","items": [{"label": "24.3"},{"label": "1"},{"label": "По умолчанию включать анализатор и планировщик."}]}]} />

Устарело с v26.9: анализатор больше нельзя отключить.

Анализатор — это инфраструктура для анализа и планирования запросов, используемая по умолчанию с версии v24.3. В v26.9 эта настройка зафиксирована на единственном поддерживаемом значении `1`: попытка установить её в `0` отклоняется, а настройка `compatibility` больше не возвращает прежнее поведение. В v26.10 анализ запросов, на который она переключала, был удалён. Удалите `enable_analyzer = 0` из запросов, настроек сеанса, профилей настроек и конфигураций клиентов. Чтобы сравнить поведение или производительность запроса с прежним анализом запросов, используйте версию ClickHouse старше v26.9.

## allow_experimental_parallel_reading_from_replicas {#allow_experimental_parallel_reading_from_replicas}

**Псевдонимы**: `enable_parallel_replicas`

<SettingsInfoBlock type="UInt64" default_value="0" />

Использовать до `max_parallel_replicas` реплик из каждого сегмента при выполнении запроса SELECT. Чтение распараллеливается и координируется динамически. 0 — отключено, 1 — включено, при сбое отключается без уведомления, 2 — включено, при сбое сгенерировать исключение
