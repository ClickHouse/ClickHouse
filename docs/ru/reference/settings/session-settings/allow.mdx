<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.5"},{"label": "1"},{"label": "Новая настройка для переписывания предикатов вида `coalesce(a_1, ..., a_N) <op> const` (и аналогично для `ifNull`, а также с константой слева) в дизъюнкцию перед анализом индексов, чтобы можно было использовать первичный ключ по каждому столбцу и индексы пропуска данных для каждого `a_i`. Переписывает предикаты вида `coalesce(a_1, ..., a_N) <op> const` (и аналогично для `ifNull`, а также с константой слева) в дизъюнкцию `(a_1 <op> const) OR (a_1 IS NULL AND a_2 <op> const) OR ... OR (a_1 IS NULL AND ... AND a_{N-1} IS NULL AND a_N <op> const)` перед анализом индексов, чтобы можно было использовать первичный ключ по каждому столбцу и индексы пропуска данных для каждого `a_i`. Обрабатываются формы с частично константными аргументами, такие как `coalesce(a, 42, b)` и `coalesce(a, b, 42)`: список аргументов нормализуется так же, как в самом `coalesce` (литералы `NULL` отбрасываются, аргументы после первого не-`Nullable` отбрасываются), а завершающая константа, отличная от `NULL`, если она есть, добавляется как последняя ветвь. Переписывание исключительно расширяет возможности отсечения данных по индексам; при выполнении запроса по-прежнему используется исходный предикат.
Кроме того, предикаты точного равенства вида `nullIf(key, sentinel) = const` (где `sentinel != const` и типы полностью совпадают) переписываются в `key = const`, чтобы первичный ключ, партиция и индексы пропуска данных по `key` могли напрямую отсекать гранулы. Отсечение гранул для диапазонных и дизъюнктивных условий с `nullIf` не поддерживается.
