<div id="http_allow_database_as_path">
  ## http_allow_database_as_path
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для распознавания имени базы данных в пути URL HTTP-запросов."}]}]} />

Если включено, HTTP-интерфейс распознаёт компонент `/database/` в пути URL и использует его в качестве текущей базы данных.

Это настройка для отдельного пользователя, определяющая, будет ли интерпретироваться маршрутизируемый запрос с путём в URL. Сама маршрутизация глобально регулируется настройкой конфигурации уровня сервера `http_allow_path_requests` (по умолчанию отключена). Её необходимо включить, чтобы HTTP-интерфейс вообще направлял запрос с путём в URL (например, `/my_db/my_table.csv`) обработчику запросов: решение о маршрутизации принимается до аутентификации запроса, поэтому оно не может зависеть от настройки для отдельного пользователя. Если `http_allow_path_requests` отключена, неизвестные пути возвращают обычный ответ `404`. После маршрутизации эта настройка повторно проверяется с учётом действующих настроек аутентифицированного пользователя, поэтому её можно выборочно включать для отдельных пользователей, ролей или профилей.

<div id="http_allow_filters_as_path">
  ## http_allow_filters_as_path
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для распознавания в пути URL HTTP-запросов фильтров `name=value` в стиле партиционирования Hive."}]}]} />

Если включено, HTTP-интерфейс распознаёт компоненты `/name=value/` в пути (в стиле партиционирования Hive) и преобразует их в фильтры, объединённые с помощью AND. Также распознаются операторы `>`, `<`, `>=`, `<=`, `!=`, `<>`.

Как и [`http_allow_database_as_path`](/ru/reference/settings/session-settings/http#http_allow_database_as_path), это настройка для отдельного пользователя; маршрутизация запросов с путём в URL глобально регулируется настройкой конфигурации уровня сервера `http_allow_path_requests` (маршрутизация выполняется до аутентификации).

<div id="http_allow_filters_as_unrecognized_url_parameters">
  ## http_allow_filters_as_unrecognized_url_parameters
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для обработки нераспознанных URL-параметров как выражений фильтра в HTTP-запросах."}]}]} />

Если включено, любой URL-параметр, не распознанный как известный параметр, настройка или параметр с префиксом `param_*`, обрабатывается как фильтр и объединяется с другими с помощью AND. Поддерживаются две формы:

* Обычный `name=value` преобразуется в проверку на равенство `` `name` = 'value' `` (идентификатор заключается в обратные кавычки, а значение — в одинарные кавычки как строковый литерал).
* Оператор сравнения (`!=`, `>`, `<`, `>=`, `<=`, `<>`) превращает его в сравнение: он может быть разделён между именем и значением параметра (`?a!=2`, `?a>=2`) или записан непосредственно, если в URL нет `=` для разделения (`?a<>2`, `?f(x)>3`); в этом случае восстановленное `name[=value]` разбирается как полное SQL-выражение.

<div id="http_allow_table_as_file">
  ## http_allow_table_as_file
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для распознавания имени таблицы в пути URL HTTP-запросов с необязательными расширениями формата\/сжатия."}]}]} />

Если включено, HTTP-интерфейс распознаёт последний компонент пути URL как имя таблицы в форме `table`, `table.format` или `table.format.compression`. Путь интерпретируется как `SELECT * FROM table`.

Как и [`http_allow_database_as_path`](/ru/reference/settings/session-settings/http#http_allow_database_as_path), это настройка для отдельного пользователя; маршрутизация запросов с путём в URL глобально контролируется настройкой конфигурации уровня сервера `http_allow_path_requests` (маршрутизация выполняется до аутентификации).

<div id="http_make_head_request">
  ## http_make_head_request
</div>

<SettingsInfoBlock type="Bool" default_value="1" />

Настройка `http_make_head_request` позволяет выполнять запрос `HEAD` при чтении данных по HTTP, чтобы получить сведения о файле, например его размер. Поскольку она включена по умолчанию, если сервер не поддерживает запросы `HEAD`, эту настройку может быть целесообразно отключить.

<div id="http_native_compression_disable_checksumming_on_decompress">
  ## http_native_compression_disable_checksumming_on_decompress
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

Включает или отключает проверку контрольной суммы при распаковке данных HTTP POST, полученных от клиента. Используется только для собственного формата сжатия ClickHouse (не используется с `gzip` или `deflate`).

Для получения дополнительной информации см. [описание HTTP-интерфейса](/ru/concepts/features/interfaces/http).

Возможные значения:

* 0 — Отключено.
* 1 — Включено.
