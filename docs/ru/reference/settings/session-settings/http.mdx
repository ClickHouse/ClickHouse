## http_allow_database_as_path {#http_allow_database_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для распознавания имени базы данных в пути URL HTTP-запросов."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Включена по умолчанию: HTTP-интерфейс интерпретирует компонент `\/database\/` в пути URL как текущую базу данных."}]}]} />

Если включено, HTTP-интерфейс распознаёт компонент `/database/` в пути URL и использует его в качестве текущей базы данных.

Это настройка для отдельного пользователя, определяющая, будет ли интерпретироваться маршрутизируемый запрос с путём в URL. Сама маршрутизация глобально регулируется настройкой конфигурации уровня сервера `http_allow_path_requests` (по умолчанию включена). Её необходимо включить, чтобы HTTP-интерфейс вообще направлял запрос с путём в URL (например, `/my_db/my_table.csv`) обработчику запросов: решение о маршрутизации принимается до аутентификации запроса, поэтому оно не может зависеть от настройки для отдельного пользователя. Если `http_allow_path_requests` отключена, неизвестные пути возвращают обычный ответ `404`. После маршрутизации эта настройка повторно проверяется с учётом действующих настроек аутентифицированного пользователя, поэтому её можно выборочно отключать для отдельных пользователей, ролей или профилей.

## http_allow_filters_as_path {#http_allow_filters_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для распознавания в пути URL HTTP-запросов фильтров `name=value` в стиле партиционирования Hive."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Включена по умолчанию: HTTP-интерфейс интерпретирует компоненты пути `\/name=value\/` как фильтры, объединённые через `AND`."}]}]} />

Если включено, HTTP-интерфейс распознаёт компоненты `/name=value/` в пути (в стиле партиционирования Hive) и преобразует их в фильтры, объединённые с помощью AND. Также распознаются операторы `>`, `<`, `>=`, `<=`, `!=`, `<>`.

Как и [`http_allow_database_as_path`](/ru/reference/settings/session-settings/http#http_allow_database_as_path), это настройка для отдельного пользователя; маршрутизация запросов с путём в URL глобально регулируется настройкой конфигурации уровня сервера `http_allow_path_requests` (маршрутизация выполняется до аутентификации).

## http_allow_filters_as_unrecognized_url_parameters {#http_allow_filters_as_unrecognized_url_parameters}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для обработки нераспознанных URL-параметров как выражений фильтра в HTTP-запросах."}]}]} />

Если включено, любой URL-параметр, не распознанный как известный параметр, настройка или параметр с префиксом `param_*`, обрабатывается как фильтр и объединяется с другими с помощью AND. Поддерживаются две формы:

* Обычный `name=value` преобразуется в проверку на равенство `` `name` = 'value' `` (идентификатор заключается в обратные кавычки, а значение — в одинарные кавычки как строковый литерал).
* Оператор сравнения (`!=`, `>`, `<`, `>=`, `<=`, `<>`) превращает его в сравнение: он может быть разделён между именем и значением параметра (`?a!=2`, `?a>=2`) или записан непосредственно, если в URL нет `=` для разделения (`?a<>2`, `?f(x)>3`); в этом случае восстановленное `name[=value]` разбирается как полное SQL-выражение.

В отличие от других настроек `http_allow_*`, эта настройка по умолчанию отключена. Она действует для каждого запроса HTTP-интерфейса, включая конечную точку `/?query=...`, поэтому после её включения любой нераспознанный URL-параметр, который добавляет клиент (идентификатор запроса, подпись, параметр для обхода кэша), становится фильтром запроса. Опечатка в имени настройки в этом случае приводит уже не к ошибке `UNKNOWN_SETTING`, а к ошибке `UNKNOWN_IDENTIFIER` (а если имя совпадёт с именем столбца, результат будет незаметно отфильтрован). Кроме того, значение параметра попадает в текст запроса и не маскируется там, в отличие от `Request URI` в журнале.

## http_make_head_request {#http_make_head_request}

<SettingsInfoBlock type="Bool" default_value="1" />

Настройка `http_make_head_request` позволяет выполнять запрос `HEAD` при чтении данных по HTTP, чтобы получить сведения о файле, например его размер. Поскольку она включена по умолчанию, если сервер не поддерживает запросы `HEAD`, эту настройку может быть целесообразно отключить.

## http_native_compression_disable_checksumming_on_decompress {#http_native_compression_disable_checksumming_on_decompress}

<SettingsInfoBlock type="Bool" default_value="0" />

Включает или отключает проверку контрольной суммы при распаковке данных HTTP POST, полученных от клиента. Используется только для собственного формата сжатия ClickHouse (не используется с `gzip` или `deflate`).

Для получения дополнительной информации см. [описание HTTP-интерфейса](/ru/concepts/features/interfaces/http).

Возможные значения:

* 0 — Отключено.
* 1 — Включено.

## http_x_clickhouse_format_overrides_output_format {#http_x_clickhouse_format_overrides_output_format}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Определяет, является ли HTTP-заголовок `X-ClickHouse-Format` псевдонимом для `output_format` (и переопределяет предложение `FORMAT` запроса), как начиная с 26.8, или для `default_format`, как до 26.8. Эта запись задним числом документирует изменение из 26.8, чтобы при `compatibility` с версиями до 26.8 восстанавливалось прежнее поведение заголовка."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Настройка добавлена в 26.10 для управления изменением поведения HTTP-заголовка `X-ClickHouse-Format`, появившимся в 26.8. Значимое семантическое изменение зарегистрировано в блоке 26.8, поэтому `compatibility = '26.7'` откатывает его, а `compatibility = '26.8'` и `'26.9'` сохраняют поведение этих релизов; эта запись нужна для того, чтобы проверка обновления принимала новое имя."}]}]} />

Определяет, какой настройке соответствует HTTP-заголовок `X-ClickHouse-Format`.

Если настройка включена (по умолчанию), заголовок является псевдонимом настройки `output_format`: он явно переопределяет формат ответа и имеет приоритет как над предложением `FORMAT` в запросе, так и над расширением файла в пути URL.

Если настройка отключена, заголовок является псевдонимом настройки `default_format`, как было до версии 26.8: он лишь задаёт формат, который используется, если в запросе нет предложения `FORMAT` и не применяется никакое другое переопределение формата.

В обоих случаях заголовок переопределяет одноимённый параметр URL (`output_format` или `default_format` соответственно) и никак не влияет на разбор тела запроса `INSERT`.

Это настройка совместимости для HTTP-интерфейса: заголовок обрабатывается до разбора запроса, поэтому настройку необходимо передавать через параметр URL или профиль пользователя, а не через предложение `SETTINGS` внутри запроса. Как и сами `output_format` и `default_format`, её можно изменить даже в режиме только для чтения (`readonly = 1`), поэтому пользователь с правом только на чтение может передать её как параметр URL.

## http_zlib_compression_level {#http_zlib_compression_level}

<SettingsInfoBlock type="Int64" default_value="3" />

Задает уровень сжатия данных в ответе на HTTP-запрос, если [enable&#95;http&#95;compression = 1](/ru/reference/settings/session-settings/enable#enable_http_compression).
