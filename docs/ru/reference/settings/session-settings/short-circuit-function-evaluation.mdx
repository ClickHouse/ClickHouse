## short_circuit_function_evaluation {#short_circuit_function_evaluation}

<SettingsInfoBlock type="ShortCircuitFunctionEvaluation" default_value="enable" />

Позволяет вычислять функции [if](/ru/reference/functions/regular-functions/conditional-functions#if), [multiIf](/ru/reference/functions/regular-functions/conditional-functions#multiIf), [and](/ru/reference/functions/regular-functions/logical-functions#and) и [or](/ru/reference/functions/regular-functions/logical-functions#or) по принципу [короткого замыкания](https://en.wikipedia.org/wiki/Short-circuit_evaluation). Это помогает оптимизировать вычисление сложных выражений в этих функциях и предотвращать возможные исключения (например, деление на ноль там, где оно не должно выполняться).

Возможные значения:

* `enable` — Включает вычисление функций с коротким замыканием для функций, где это применимо (то есть для тех, которые могут сгенерировать исключение или требуют больших вычислительных затрат).
* `force_enable` — Включает вычисление функций с коротким замыканием для всех функций.
* `disable` — Отключает вычисление функций с коротким замыканием.

## short_circuit_function_evaluation_for_nulls {#short_circuit_function_evaluation_for_nulls}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.1"},{"label": "1"},{"label": "Разрешает выполнять функции с аргументами Nullable только для строк, в которых все аргументы имеют значения, отличные от NULL"}]}]} />

Оптимизирует вычисление функций, которые возвращают NULL, если хотя бы один аргумент равен NULL. Когда доля NULL-значений в аргументах функции превышает short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls&#95;threshold, система пропускает построчное вычисление функции. Вместо этого она сразу возвращает NULL для всех строк, избегая лишних вычислений.

Эта настройка управляет только оптимизацией. Функции, которые не могут быть выполнены со значениями по умолчанию своих аргументов — такие как `parseDateTime`, `IPv4StringToNum` или `intDiv` — всегда пропускают строки, содержащие NULL, независимо от этой настройки: за NULL хранится значение по умолчанию для типа аргумента, и выполнение над ним сгенерировало бы исключение на в остальном корректных данных.

## short_circuit_function_evaluation_for_nulls_threshold {#short_circuit_function_evaluation_for_nulls_threshold}

Пороговое отношение NULL-значений, при котором функции с аргументами Nullable выполняются только для строк, где во всех аргументах значения отличны от NULL. Применяется, когда включена настройка short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls.
Когда отношение строк, содержащих NULL-значения, к общему числу строк превышает этот порог, строки с NULL-значениями не вычисляются.

## short_circuit_function_evaluation_reorder_arguments {#short_circuit_function_evaluation_reorder_arguments}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Новая настройка"}]}]} />

Позволяет изменять порядок вычисления аргументов функций [and](/ru/reference/functions/regular-functions/logical-functions#and) и [or](/ru/reference/functions/regular-functions/logical-functions#or) при [укороченном вычислении](/ru/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation), если это не влияет на результат и не приводит к исключениям.

* Если первый аргумент требует больших вычислительных затрат, а другой вычисляется дёшево, то сначала вычисляется дешёвый аргумент, а тяжёлый — только для тех строк, для которых результат ещё не определён. Например, в `WHERE JSONExtractString(json, 'a') = 'x' AND id < 100` JSON разбирается только для строк с `id < 100`.
* Аргументы, которые вычисляются лениво и не могут сгенерировать исключение, вычисляются в порядке возрастания времени, затрачиваемого на каждую строку, для которой они определяют результат; это время измеряется на предыдущих блоках. Аргументы, которые могут сгенерировать исключение, всегда остаются после всех предшествующих им аргументов, поэтому, например, в выражении `x != 0 AND intDiv(1, x) > 0` деления на ноль никогда не происходит.
