## iceberg_manifest_decode_concurrency {#iceberg_manifest_decode_concurrency}

**Псевдонимы**: `iceberg_delete_manifest_decode_concurrency`

<SettingsInfoBlock type="NonZeroUInt64" default_value="4" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "4"},{"label": "Новая настройка, ограничивающая количество одновременно декодируемых Iceberg файлов манифеста — как delete-, так и манифестов данных. Она заменяет `iceberg_delete_manifest_decode_concurrency` (сохранён как псевдоним). Значение `2` примерно воспроизводит путь к данным до версии 26.9, где манифесты декодировались по одному, а fetch следующего уже был in-flight; поэтому при `compatibility` 26.8 или ниже декодирование delete-манифестов также выполняется с параллелизмом 2, а не со штатным значением по умолчанию 4 — это сохраняет прежний envelope потребления памяти на пути к данным ценой меньшего перекрытия при декодировании delete-манифестов."}]}]} />

Максимальное количество Iceberg файлов манифеста, декодируемых одновременно при чтении таблицы.

Все delete-манифесты декодируются до того, как будет прочитан хотя бы один файл данных; манифесты данных декодируются по ходу формирования списка файлов данных для запроса, причём новые декодируются только по мере того, как запрос обрабатывает уже декодированные entries. Одновременное декодирование нескольких манифестов позволяет совмещать round-trip к объектному хранилищу с работой по pruning для каждой entry.

Более высокие значения увеличивают пиковое потребление памяти, если кеш Iceberg metadata files отключён или заполнен, поскольку каждый находящийся in-flight манифест хранит собственное декодированное содержимое.

Значение должно быть больше нуля; при `1` манифесты декодируются по одному.
