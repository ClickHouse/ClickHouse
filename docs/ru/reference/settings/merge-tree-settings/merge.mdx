## merge_checkpoints_min_bytes {#merge_checkpoints_min_bytes}

<ExperimentalBadge />

<SettingsInfoBlock type="UInt64" default_value="10737418240" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "10737418240"},{"label": "Новая настройка для надёжных контрольных точек слияний"}]}]} />

Минимальный суммарный размер исходных частей слияния в байтах, начиная с которого для него создаётся контрольная точка при включённой настройке `enable_merge_checkpoints`.
Для слияний меньшего размера контрольные точки не создаются, поскольку их повторное выполнение обходится недорого.

## merge_checkpoints_min_interval_seconds {#merge_checkpoints_min_interval_seconds}

<ExperimentalBadge />

<SettingsInfoBlock type="Seconds" default_value="60" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "60"},{"label": "Новая настройка для надёжных контрольных точек слияния"}]}]} />

Минимальное время между двумя контрольными точками слияния при включённой настройке `enable_merge_checkpoints`.
Вертикальное слияние всегда создаёт контрольную точку после слияния столбцов ключа. Далее контрольная точка после завершения обработки очередного столбца
создаётся, только если с момента предыдущей контрольной точки прошло не меньше указанного времени.

## merge_use_batch_sorting_queue {#merge_use_batch_sorting_queue}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Новая настройка для использования пакетной очереди сортировки при обычных слияниях `MergeTree`."}]}]} />

Используйте пакетную очередь сортировки, чтобы снизить накладные расходы на обработку каждой строки в очереди при слиянии отсортированных потоков.

Применяется только к слияниям в режиме слияния `Ordinary`: к слияниям частей обычного `MergeTree`, включая
слияния, при которых строки удаляются или переписываются (легковесные удаления, удаления по TTL, патч-части легковесных
обновлений и `OPTIMIZE ... DEDUPLICATE`), а также к слияниям частей обычных проекций. Алгоритмы слияния
движков с семантикой, применяемой во время слияния, таких как `ReplacingMergeTree`, `CollapsingMergeTree`,
`SummingMergeTree`, `AggregatingMergeTree`, `CoalescingMergeTree`, `GraphiteMergeTree` и
`VersionedCollapsingMergeTree`, а также алгоритмы слияния частей агрегирующих проекций сами выбирают очередь сортировки, поэтому
эта настройка на них не влияет.

## merge_workload {#merge_workload}

Используется для управления тем, как ресурсы используются и распределяются между слияниями и
другими рабочими нагрузками. Указанное значение используется в качестве значения настройки `workload` для
фоновых слияний этой таблицы. Если оно не указано (пустая строка),
вместо него используется настройка сервера `merge_workload`.
