## materialize_skip_indexes_on_merge {#materialize_skip_indexes_on_merge}

<SettingsInfoBlock type="Bool" default_value="1" />

Если параметр включен, при слиянии для новых частей создаются и сохраняются индексы пропуска данных.
В противном случае их можно создать/сохранить явной командой [MATERIALIZE INDEX](/ru/reference/statements/alter/skipping-index#materialize-index)
или [при INSERT](/ru/reference/settings/session-settings/materialize#materialize_skip_indexes_on_insert).

См. также [exclude&#95;materialize&#95;skip&#95;indexes&#95;on&#95;merge](/ru/reference/settings/merge-tree-settings/exclude#exclude_materialize_skip_indexes_on_merge) для более тонкой настройки.

## materialize_statistics_on_merge {#materialize_statistics_on_merge}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.1"},{"label": "1"},{"label": "новая настройка"}]}]} />

Если параметр включен, при слиянии для новых частей будет создаваться и сохраняться статистика.
В противном случае ее можно создать/сохранить явной командой [MATERIALIZE STATISTICS](/ru/reference/statements/alter/statistics)
или [во время INSERT](/ru/reference/settings/session-settings/materialize-statistics-on-insert#materialize_statistics_on_insert)

## materialize_ttl_recalculate_only {#materialize_ttl_recalculate_only}

<SettingsInfoBlock type="Bool" default_value="0" />

Если настройка включена, `MATERIALIZE TTL` пересчитывает сохранённые метаданные `TTL` для каждой части данных, не удаляя в ходе этой операции данные с истёкшим сроком жизни. Если настройка отключена, обычная материализация TTL, как правило, применяет настроенные действия TTL для строк, столбцов или `GROUP BY`. Для таблиц, в которых задан только TTL для строк и включена настройка `ttl_only_drop_parts`, вместо этого пересчитываются метаданные `TTL` и удаляются только те части, срок жизни всех данных в которых полностью истёк.
