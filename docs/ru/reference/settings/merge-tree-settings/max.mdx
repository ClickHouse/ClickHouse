Эти настройки доступны в [system.merge&#95;tree&#95;settings](/ru/reference/system-tables/merge_tree_settings) и автоматически генерируются из исходного кода ClickHouse.

## max_avg_part_size_for_too_many_parts {#max_avg_part_size_for_too_many_parts}

<SettingsInfoBlock type="UInt64" default_value="1073741824" />

Проверка на «слишком большое количество частей» в соответствии с &#39;parts&#95;to&#95;delay&#95;insert&#39; и
&#39;parts&#95;to&#95;throw&#95;insert&#39; будет выполняться только в том случае, если средний размер части (в
соответствующей партиции) не превышает указанный порог. Если он
превышает указанный порог, операции INSERT не будут ни задерживаться, ни
отклоняться. Это позволяет хранить сотни терабайт в одной таблице на
одном сервере, если части успешно сливаются в более крупные части. Это
не влияет на пороги для неактивных частей или общего количества частей.

## max_compress_block_size {#max_compress_block_size}

<SettingsInfoBlock type="UInt64" default_value="0" />

Максимальный размер блоков несжатых данных перед сжатием при записи
в таблицу. Этот параметр также можно указать в глобальных настройках
(см. параметр [max&#95;compress&#95;block&#95;size](/ru/reference/settings/merge-tree-settings/max#max_compress_block_size)).
Значение, указанное при создании таблицы, переопределяет глобальное
значение этого параметра.

## max_concurrent_queries {#max_concurrent_queries}

<SettingsInfoBlock type="UInt64" default_value="0" />

Максимальное количество одновременно выполняемых запросов, связанных с таблицей семейства MergeTree.
Запросы по-прежнему будут ограничиваться другими настройками `max_concurrent_queries`.

Возможные значения:

* Положительное целое число.
* `0` — без ограничений.

Значение по умолчанию: `0` (без ограничений).

**Пример**

```xml
<max_concurrent_queries>50</max_concurrent_queries>
```

## max_file_name_length {#max_file_name_length}

<SettingsInfoBlock type="UInt64" default_value="127" />

Максимальная длина имени файла, при которой оно сохраняется без хеширования.
Действует, только если включена настройка `replace_long_file_name_to_hash`.
Значение этой настройки не включает длину расширения файла. Поэтому
рекомендуется задавать его меньше максимальной длины имени файла (обычно 255
байт), оставляя некоторый запас, чтобы избежать ошибок файловой системы.

## max_partitions_to_read {#max_partitions_to_read}

также можно задать на уровне запроса / сеанса / профиля.

## max_table_size_bytes_compressed {#max_table_size_bytes_compressed}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "Новая настройка, ограничивающая суммарный объём сжатых байт по всем активным и неактивным частям данных таблицы."}]}]} />

Если суммарный объём сжатых байт (размер на диске) по всем активным и неактивным
частям данных таблицы превышает это значение, `INSERT` прерывается
исключением `Table size limit exceeded`. Неактивные части также учитываются,
поскольку цель этой настройки — ограничить использование диска. Обратите
внимание, что неактивные части удаляются в фоновом режиме (см. настройку
`old_parts_lifetime`), поэтому наблюдаемый размер со временем может
уменьшаться. Ограничение проверяется в начале `INSERT` и при коммите новых
частей данных в рабочий набор, включая результаты фоновых слияний и мутаций.
Вставки, выполняемые materialized views, также проверяются. При
репликационных загрузках ограничение не проверяется, из-за чего возможно состояние гонки,
когда параллельные вставки в несколько реплик в сумме превышают ограничение. Коммит
пустых частей данных разрешён всегда, поэтому данные можно удалить из
таблицы, превысившей ограничение, например с помощью `TRUNCATE` или
`ALTER TABLE ... DROP PARTITION`.

Возможные значения:

* Любое положительное целое число.
* 0 — без ограничений.

Настройка полезна для мультитенантных, временных и демонстрационных сервисов.

## max_table_size_rows {#max_table_size_rows}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "Новая настройка для ограничения общего числа строк в активных частях данных таблицы."}]}]} />

Если общее число строк в активных частях данных таблицы превышает это
значение, `INSERT` прерывается с исключением `Table size limit exceeded`.
Ограничение проверяется в начале `INSERT` и при коммите новых частей данных
в рабочий набор, включая результаты фоновых слияний и мутаций (поэтому
мутация, увеличивающая размер таблицы сверх лимита, будет повторяться, так
и не завершившись). Вставки, выполняемые materialized views, также
проверяются. При репликационных загрузках ограничение не проверяется, что
допускает состояние гонки, когда параллельные вставки в несколько реплик
совместно превышают лимит. Коммит пустых частей данных разрешён всегда,
поэтому данные можно удалить из таблицы, превысившей лимит, например с
помощью `TRUNCATE` или `ALTER TABLE ... DROP PARTITION`.

Возможные значения:

* Любое положительное целое число.
* 0 — без ограничений.

Полезно для мультитенантных, временных и демонстрационных сервисов.
