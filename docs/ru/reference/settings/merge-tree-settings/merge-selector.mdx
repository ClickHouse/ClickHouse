## merge_selector_small_parts_max_age {#merge_selector_small_parts_max_age}

<SettingsInfoBlock type="UInt64" default_value="600" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "600"},{"label": "Предельный возраст для ограничения на слияние небольших частей"}]}]} />

Предельный возраст (в секундах) для ограничения на небольшие части: как только возраст хотя бы одной части в диапазоне
превышает это значение, ограничение `merge_selector_small_parts_min_count` снимается.
Благодаря этому накопившиеся устаревшие небольшие части всё равно могут быть слиты, даже если диапазон короче
`merge_selector_small_parts_min_count`. Применяется к селекторам слияний Simple и StochasticSimple
и только при выборе фоновых слияний: агрессивный выбор (`OPTIMIZE` без `FINAL`)
игнорирует настройки `small_parts_*`.

## merge_selector_small_parts_min_count {#merge_selector_small_parts_min_count}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "Минимальное количество частей данных, при котором допускается слияние небольших свежих частей (0 = отключено)"}]}]} />

Если все части в диапазоне слияния небольшие (меньше `merge_selector_small_parts_threshold`)
и свежие (моложе `merge_selector_small_parts_max_age`), для слияния требуется не менее
указанного количества частей. Сокращает число операций слияния при частой вставке небольших частей.
0 означает, что настройка отключена. Работает с селекторами слияний Simple и StochasticSimple.

Это условие действует только при выборе фоновых слияний. Агрессивный выбор — `OPTIMIZE`
без `FINAL` — это явный запрос пользователя, не учитывающий новизну частей, поэтому он игнорирует эту
настройку и сливает небольшие свежие части независимо от их количества.

Селектор никогда не рассматривает кандидатов на слияние шире `max_parts_to_merge_at_once`, а также
кандидатов, отстоящих дальше чем на `merge_selector_window_size` частей назад, поэтому значение
любого из этих параметров ниже указанного минимума приводит к противоречивой конфигурации: небольшие свежие части в этом случае
сливаются только по истечении `merge_selector_small_parts_max_age` (или раньше, если срабатывает принудительное слияние по
`min_age_to_force_merge_seconds` или `min_partition_age_to_force_merge_seconds`). Задавайте оба параметра
не ниже этого минимума.
(Если встроенная эвристика заполненности временно опускает своё эффективное ограничение ниже этого минимума,
селектор всё равно рассматривает первого кандидата такой ширины, состоящего только из небольших свежих частей. Для устаревших или
крупных кандидатов, а также для кандидатов, уже подпадающих под принудительное слияние по
`min_age_to_force_merge_seconds` или `min_partition_age_to_force_merge_seconds`, сохраняется
сниженное ограничение.)

## merge_selector_small_parts_threshold {#merge_selector_small_parts_threshold}

<SettingsInfoBlock type="UInt64" default_value="10485760" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "10485760"},{"label": "Порог размера для эвристики пакетирования небольших частей в селекторе слияний"}]}]} />

Порог размера в байтах: диапазон слияния считается состоящим «только из небольших частей», если размер каждой части
меньше этого значения. Используется совместно с `merge_selector_small_parts_min_count`.
Применяется к селекторам слияний Simple и StochasticSimple и только при выборе частей для фонового слияния:
при агрессивном выборе (`OPTIMIZE` без `FINAL`) настройки `small_parts_*` игнорируются.
