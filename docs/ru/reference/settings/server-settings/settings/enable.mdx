Эти настройки задают конфигурацию сервера ClickHouse и автоматически сгенерированы из исходного кода ClickHouse.

<div id="enable_azure_sdk_logging">
  ## enable_azure_sdk_logging
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Нет" />Включает логирование Azure SDK

<div id="enable_read_through_distributed_cache">
  ## enable_read_through_distributed_cache
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Yes" />Действует только в ClickHouse Cloud. Разрешает чтение из распределённого кэша. Это переключатель уровня сервера, применяемый без перезапуска; ему также подчиняются фоновые операции без собственного профиля запроса (слияния, мутации, сбросы таблиц `Buffer`). Отдельные запросы могут переопределять его с помощью настройки `force_read_through_distributed_cache`.

<div id="enable_silk_runtime">
  ## enable_silk_runtime
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />Включает экспериментальную поддержку среды выполнения волокон Silk: при запуске сервера инициализируется планировщик волокон Silk, что позволяет поддерживающим его подсистемам выполнять задачи на волокнах.

<div id="enable_webterminal">
  ## enable_webterminal
</div>

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />Включает интерфейс веб-терминала на HTTP-конечной точке `/webterminal`. Предоставляет интерактивный сеанс клиента ClickHouse в браузере через WebSocket. Если установлено значение `false`, запросы к `/webterminal` возвращают HTTP-статус `403 Forbidden`.

<div id="enable_write_through_distributed_cache">
  ## enable_write_through_distributed_cache
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Yes" />Действует только в ClickHouse Cloud. Разрешает запись в распределённый кэш (запись в S3 также будет выполняться через распределённый кэш). Это переключатель уровня сервера, применяемый без перезапуска, поэтому его также используют фоновые операции без собственного профиля запроса (слияния, мутации, сброс таблицы `Buffer`). Отдельные запросы могут переопределять это поведение с помощью настройки `force_write_through_distributed_cache`.
