Эти настройки относятся к серверу ClickHouse и автоматически генерируются из исходного кода ClickHouse.

  ## default_database

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="Нет" />Имя базы данных по умолчанию.

<div id="default_password_type">
  ## default_password_type
</div>

Задаёт тип пароля, который будет автоматически устанавливаться в запросах вида `CREATE USER u IDENTIFIED BY 'p'`.

Допустимые значения:

* `plaintext_password`

* `sha256_password`

* `double_sha1_password`

* `bcrypt_password`

* **По умолчанию:** `sha256_password`

```xml
<default_password_type>sha256_password</default_password_type>
```

<div id="default_profile">
  ## default_profile
</div>

Профиль настроек, используемый по умолчанию. Профили настроек находятся в файле, указанном в параметре `user_config`.

* **По умолчанию:** `default`

**Пример**

```xml
<default_profile>default</default_profile>
```

<div id="default_session_timeout">
  ## default_session_timeout
</div>

Тайм-аут сеанса по умолчанию в секундах.

* **По умолчанию:** `60`

```xml
<default_session_timeout>60</default_session_timeout>
```

<div id="default_session_user">
  ## default_session_user
</div>

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="No" />

Имя пользователя, используемое для аутентификации, если клиент подключается без указания имени пользователя: HTTP-запрос без параметра `user` и заголовка `X-ClickHouse-User`, пакет `Hello` собственного протокола с пустым именем пользователя, рукопожатие MySQL или PostgreSQL с пустым именем пользователя, gRPC-запрос без `user_name`, вызов Arrow Flight без заголовка `authorization` (или с учётными данными Basic и пустым именем пользователя), либо сообщение WebSocket `auth` [веб-терминала](/ru/concepts/features/interfaces/web-terminal) с отсутствующим или пустым полем `user`.

Перед аутентификацией пустое имя пользователя заменяется этим значением, поэтому к подключению по-прежнему применяются механизмы аутентификации подставленного пользователя: пароль, проверка сети и другие проверки доступа выполняются как обычно. Пустое имя пользователя — лишь псевдоним настроенного имени пользователя, и его принятие не предоставляет доступ сверх того, который уже даёт явное указание того же имени пользователя. До появления этой настройки подстановка `default` для пустого имени пользователя существовала только при передаче параметров HTTP-запроса, для gRPC-запросов, вызовов Arrow Flight и веб-терминала, тогда как собственный протокол, MySQL и PostgreSQL отклоняли пустое имя пользователя; теперь его принимают все они. До появления этой настройки HTTP Basic-аутентификация с пустым именем пользователя и запросы с `X-ClickHouse-Key`, но без `X-ClickHouse-User`, также отклоняли пустое имя пользователя.

Если задана пустая строка, подключения без имени пользователя отклоняются. HTTP-обработчики с фиксированным пользователем (ключ `user` внутри `handler` правила `http_handlers` или ключ `user` внутри `handler` правила `prometheus.handlers`) аутентифицируются как настроенный пользователь и не затрагиваются.

Когда раздел `session_log` включён в конфигурации сервера, каждое такое отклонение записывается в [`system.session_log`](/ru/reference/system-tables/session_log) как событие `LoginFailure` с пустым `user`, что позволяет проверять запрещённые подключения без имени пользователя через любой интерфейс.

Пользователь сеанса по умолчанию никогда не применяется к межсерверным подключениям: они идентифицируют себя специальным маркером вместо имени пользователя и аутентифицируются с помощью секрета кластера и исходного пользователя.

Значение можно переопределить для конкретной конечной точки составного протокола с помощью ключа `default_session_user` в разделе `protocols`; см. [Составные протоколы](/ru/concepts/features/configuration/server-config/composable-protocols).
