Эти настройки управляют конфигурацией сервера ClickHouse и автоматически генерируются из исходного кода ClickHouse.

## amber_connections_hard_limit {#amber_connections_hard_limit}

<SettingsInfoBlock type="UInt64" default_value="200000" changeable_without_restart="No" />При достижении этого лимита попытка создать соединение завершается исключением. Чтобы отключить жёсткий лимит, установите значение 0. Лимит распространяется на соединения Amber.

## amber_connections_rcvbuf {#amber_connections_rcvbuf}

<SettingsInfoBlock type="UInt64" default_value="204800" changeable_without_restart="Yes" />Размер параметра SO&#95;RCVBUF для соединений Amber. Значение по умолчанию — 204800 (200 КБ): обращение к объектному хранилищу выполняется в пределах одного региона, где произведение пропускной способности на задержку значительно меньше 100 КБ, поэтому даже небольшого ограничения достаточно для полной пропускной способности. При этом не выделяются буферы размером в несколько МиБ на каждый сокет, которые иначе выделила бы автоматическая настройка ядра. Установите значение 0, чтобы использовать для буфера приёма автотюнинг TCP ядра. Примечание: если вернуть этой настройке значение 0, автоматическая настройка восстановится только для вновь создаваемых соединений; существующие соединения из пула сохраняют фиксированные размеры буферов до их повторного создания.

## amber_connections_sndbuf {#amber_connections_sndbuf}

<SettingsInfoBlock type="UInt64" default_value="0" changeable_without_restart="Yes" />Размер параметра SO&#95;SNDBUF для соединений Amber. Значение больше 0 переопределяет автотюнинг TCP ядра для буфера отправки. 0 — значение ядра по умолчанию (автоматическая настройка). Примечание: при возврате этой настройки к значению 0 автоматическая настройка восстанавливается только для вновь создаваемых соединений; существующие соединения из пула сохраняют фиксированный размер буфера до их повторного создания.

## amber_connections_soft_limit {#amber_connections_soft_limit}

<SettingsInfoBlock type="UInt64" default_value="5000" changeable_without_restart="No" />У соединений сверх этого лимита время жизни значительно короче. Лимит распространяется на соединения Amber.

## amber_connections_store_limit {#amber_connections_store_limit}

<SettingsInfoBlock type="UInt64" default_value="10000" changeable_without_restart="No" />Максимальное количество бездействующих соединений, хранящихся в пуле для повторного использования. Когда в пуле уже сохранено указанное количество соединений, последующие соединения после использования сбрасываются, а не сохраняются. Ограничение не распространяется на используемые в данный момент соединения. Чтобы отключить кэш подключений, установите значение 0. Ограничение применяется к соединениям Amber.

## amber_connections_warn_limit {#amber_connections_warn_limit}

<SettingsInfoBlock type="UInt64" default_value="8000" changeable_without_restart="No" />Если число используемых соединений превышает этот лимит, в журнал записываются предупреждения. Лимит распространяется на соединения Amber.
