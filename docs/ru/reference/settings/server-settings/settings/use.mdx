Эти настройки настраивают сервер ClickHouse и автоматически сгенерированы на основе исходного кода ClickHouse.

## use_minimalistic_part_header_in_zookeeper {#use_minimalistic_part_header_in_zookeeper}

Устаревшая настройка, ни на что не влияет. [Реплицируемые](/ru/reference/engines/table-engines/mergetree-family/replication) таблицы всегда хранят заголовок части данных в компактном виде в одном `znode`. Заголовки частей, записанные более старыми версиями в виде отдельных дочерних `znodes` `columns` и `checksums`, по-прежнему считываются.

## use_separate_cache_arena {#use_separate_cache_arena}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />

Включает отдельную arena jemalloc для выделения памяти под кэш (mark cache, кэш несжатых данных, page cache).
Изолирует данные кэша от выделений памяти при обработке запросов, уменьшая фрагментацию памяти.

## use_shared_merge_tree_log_pipeline {#use_shared_merge_tree_log_pipeline}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />

Доступно только в ClickHouse Cloud. Если настройка включена, системные журналы записываются через конвейер `SharedMergeTree`,
а база данных `system` становится общей базой данных, поэтому все реплики видят одни и те же таблицы логов.

При каждом сбросе журнала на диск с помощью табличной функции `s3` (или `azureBlobStorage`) записывается файл в формате `Native` в папку
генерации журнала, которая определяется хешем его столбцов и ключей. Для каждой генерации конвейер поддерживает очередь `system._<log>_s3queue_<hash>`,
читающую эту папку, materialized view `system._<log>_mv_<hash>` и таблицу `SharedMergeTree` `system.<log>_<hash>`.
`system.<log>` — это таблица `Merge` поверх всех генераций. Новая схема порождает новую генерацию; настройки, TTL и индексы
берутся из ключей `smt_settings`, `smt_ttl` и `smt_indices` конфигурации журнала и изменяются на месте.
Объекты создаются при первом сбросе журнала на диск или при запуске сервера, если задана настройка `prepare_system_log_tables_on_startup`.
Ключ сортировки таблицы — это ключ журнала, перед которым добавлен `hostname`, поэтому строки отдельной реплики читаются по ключу.
Ключи `smt_order_by` и `smt_partition_by` конфигурации журнала заменяют соответствующие ключи таблицы.

Пока настройка включена, локальная база данных `system` переименовывается в `system_local`. В конфигурации сервера должны быть заданы `shared_database_catalog`
и `<shared_log_pipeline><endpoint>`.
См. также: `shared_log_pipeline.enable_sync_flush`, `shared_log_pipeline.flush_timeout_seconds`.
