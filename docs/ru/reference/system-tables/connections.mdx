## Описание {#description}

Показывает открытые клиентские соединения интерфейсов запросов нативного TCP и HTTP.
Соединение находится в состоянии `active`, пока выполняется запрос, и в состоянии `idle`, пока ожидает следующего запроса.

В таблице не отображаются следующие соединения:

* Соединения по другим протоколам, например MySQL, PostgreSQL и gRPC.
* Межсерверные соединения.
* HTTP-соединения, в рамках которых не выполнялись запросы, например `/ping` и соединения Prometheus.

Сервер собирает сведения о соединениях, только если настройка сервера `collect_connection_metrics` имеет значение `true`. Если настройка имеет значение `false`, таблица пуста.
Настройку можно изменить без перезапуска (`SYSTEM RELOAD CONFIG`):

* Если изменить значение настройки на `false`, таблица очищается, и сервер прекращает регистрировать новые соединения.
* Если изменить значение настройки на `true`, уже открытое соединение появится в таблице при выполнении следующего запроса.

Сервер добавляет TCP-соединение в таблицу после аутентификации и удаляет его при закрытии соединения.
Сервер добавляет HTTP-соединение в таблицу при первом запросе и удаляет его при закрытии сокета.
Поэтому в промежутках между запросами HTTP-соединение keep-alive отображается в таблице в состоянии `idle`.

Пользователь без привилегии `SHOW CONNECTIONS` видит только собственные соединения.
При проверке используется ID пользователя, а не имя. Поэтому переименованный пользователь сохраняет свои соединения, а новый пользователь со старым именем их не получает.

`connection_id` — это случайный UUID. Поэтому он уникален в пределах всех серверов, и таблицы нескольких реплик можно объединять, например с помощью `clusterAllReplicas`.

`connected_time` имеет одинаковый смысл для TCP и HTTP: это время, когда сервер начал обрабатывать сокет.
Этот момент предшествует TCP-рукопожатию, аутентификации и первому запросу. Поэтому он может оказаться раньше момента появления соединения в таблице.

## Столбцы {#columns}

* `connection_id` ([UUID](/ru/reference/data-types/uuid)) — Уникальный идентификатор соединения: случайный UUID. Он уникален в пределах всех серверов, например при использовании `clusterAllReplicas`. TCP-соединение получает идентификатор после аутентификации, HTTP-соединение — при первом запросе.
* `protocol` ([LowCardinality(String)](/ru/reference/data-types/lowcardinality)) — Протокол соединения: TCP (собственный протокол) или HTTP.
* `client_address` ([IPv6](/ru/reference/data-types/ipv6)) — IP-адрес клиента. Если соединение проходит через прокси, это адрес клиента при условии, что сервер доверяет протоколу PROXY или заголовку `X-Forwarded-For`. Для HTTP это адрес последнего запроса.
* `client_port` ([UInt16](/ru/reference/data-types/int-uint)) — TCP-порт клиента. Если соединение проходит через прокси, это порт из протокола PROXY или заголовка `X-Forwarded-For` при условии, что сервер им доверяет. Для HTTP это порт последнего запроса.
* `server_port` ([UInt16](/ru/reference/data-types/int-uint)) — Порт сервера, принявший соединение.
* `user` ([String](/ru/reference/data-types/string)) — Имя аутентифицированного пользователя. Для HTTP-соединения это пользователь последнего запроса. Каждый запрос в keep-alive-соединении проходит отдельную аутентификацию. Если пользователь переименован, в этом столбце отображается старое имя до следующей аутентификации. При проверке доступа используется ID пользователя, а не имя.
* `status` ([LowCardinality(String)](/ru/reference/data-types/lowcardinality)) — Состояние соединения. `active`: в данный момент выполняется запрос. `idle`: соединение открыто и ожидает следующего запроса или следующего HTTP-запроса.
* `query_id` ([String](/ru/reference/data-types/string)) — Идентификатор выполняемого в данный момент запроса. Пустая строка, если соединение бездействует.
* `client_name` ([String](/ru/reference/data-types/string)) — Имя клиентского приложения. TCP-клиент передаёт это имя при рукопожатии. Для HTTP это заголовок `User-Agent` последнего запроса.
* `client_version_major` ([UInt64](/ru/reference/data-types/int-uint)) — Мажорная версия клиента, полученная при TCP-рукопожатии. Для HTTP-соединений — 0.
* `client_version_minor` ([UInt64](/ru/reference/data-types/int-uint)) — Минорная версия клиента, полученная при TCP-рукопожатии. Для HTTP-соединений — 0.
* `client_version_patch` ([UInt64](/ru/reference/data-types/int-uint)) — Патч-версия клиента, полученная при TCP-рукопожатии. Для HTTP-соединений — 0.
* `connected_time` ([DateTime](/ru/reference/data-types/datetime)) — Время, когда сервер начал обрабатывать сокет. Для TCP и HTTP оно определяется одинаково: до рукопожатия, аутентификации и первого запроса.
* `last_query_time` ([Nullable(DateTime)](/ru/reference/data-types/nullable)) — Время начала последнего запроса в этом соединении. NULL, если в соединении не выполнялось ни одного запроса.

## Примеры {#examples}

```sql
SELECT connection_id, protocol, user, status, query_id, client_name, connected_time, last_query_time
FROM system.connections
FORMAT Vertical;
```

```sql
SELECT hostName(), protocol, status, count()
FROM clusterAllReplicas(default, system.connections)
GROUP BY ALL;
```
