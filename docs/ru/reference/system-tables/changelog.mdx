## Описание {#description}

Содержит записи курируемого журнала изменений ClickHouse (файл `CHANGELOG.md` в репозитории): по одной строке на каждую запись каждого релиза с новыми возможностями, что позволяет обращаться к примечаниям к выпуску с помощью SQL-запросов.

## Столбцы {#columns}

* `version` ([Tuple(major UInt16, minor UInt8, patch UInt16)](/ru/reference/data-types/tuple)) — версия релиза, к которому относится запись, в виде кортежа, допускающего сравнение. Курируемый журнал изменений описывает релизы с новыми возможностями, поэтому `patch` равен 0.
* `release_date` ([Date](/ru/reference/data-types/date)) — дата релиза.
* `is_lts` ([UInt8](/ru/reference/data-types/int-uint)) — 1, если это релиз с долгосрочной поддержкой (LTS).
* `category` ([LowCardinality(String)](/ru/reference/data-types/lowcardinality)) — раздел журнала изменений, к которому относится запись, например &#39;New Feature&#39;, &#39;Performance Improvement&#39;, &#39;Bug Fix&#39;.
* `description` ([String](/ru/reference/data-types/string)) — текст записи в журнале изменений.
* `pull_requests` ([Array(UInt32)](/ru/reference/data-types/array)) — номера pull request, на которые ссылается запись.
* `authors` ([Array(String)](/ru/reference/data-types/array)) — авторы этих pull request.

## Пример {#example}

Найдём недавние изменения, связанные с JSON, начиная с самого нового релиза:

```sql
SELECT version, category, description
FROM system.changelog
WHERE description ILIKE '%JSON%' AND version >= (26, 1, 0)
ORDER BY version DESC
LIMIT 3
```
