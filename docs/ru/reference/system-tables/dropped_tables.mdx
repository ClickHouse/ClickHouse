<div id="description">
  ## Описание
</div>

Содержит информацию о таблицах, для которых была выполнена команда DROP TABLE, но очистка данных для них ещё не завершена.

<div id="columns">
  ## Столбцы
</div>

{/*AUTOGENERATED_START*/}

* `index` ([UInt32](/ru/reference/data-types/int-uint)) — Индекс в очереди marked&#95;dropped&#95;tables.
* `database` ([String](/ru/reference/data-types/string)) — Имя базы данных.
* `table` ([String](/ru/reference/data-types/string)) — Имя таблицы.
* `uuid` ([UUID](/ru/reference/data-types/uuid)) — UUID таблицы.
* `engine` ([String](/ru/reference/data-types/string)) — Имя движка таблицы.
* `metadata_dropped_path` ([String](/ru/reference/data-types/string)) — Путь к файлу метаданных таблицы в каталоге metadata&#95;dropped.
* `table_dropped_time` ([DateTime](/ru/reference/data-types/datetime)) — Время, на которое запланирована следующая попытка удалить данные таблицы. Обычно это время удаления таблицы плюс `database_atomic_delay_before_drop_table_sec`.

{/*AUTOGENERATED_END*/}

В этой таблице перечислены только таблицы, удалённые из баз данных `Atomic`. Для таких таблиц значение `table_dropped_time` обычно определяется параметром [`database_atomic_delay_before_drop_table_sec`](/ru/reference/settings/server-settings/settings/other#database_atomic_delay_before_drop_table_sec). Однако для базы данных `Shared` в ClickHouse Cloud период восстановления задаётся параметром [`database_shared_drop_table_delay_seconds`](/ru/reference/settings/session-settings/database#database_shared_drop_table_delay_seconds), значение которого по умолчанию составляет 8 часов; удалённые таблицы из баз данных `Shared` не отображаются в `system.dropped_tables`.

<div id="example">
  ## Пример
</div>

В следующем примере показано, как получить сведения о `dropped_tables`.

```sql
SELECT *
FROM system.dropped_tables\G
```

