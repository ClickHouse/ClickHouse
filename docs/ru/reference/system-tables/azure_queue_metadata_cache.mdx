## Описание {#description}

Содержит хранящееся в памяти состояние метаданных AzureQueue и строки, обрабатываемые в данный момент, для каждого файла.

## Столбцы {#columns}

* `zookeeper_path` ([String](/ru/reference/data-types/string)) — путь к метаданным в ZooKeeper
* `file_path` ([String](/ru/reference/data-types/string)) — путь к обрабатываемому файлу
* `file_name` ([String](/ru/reference/data-types/string)) — имя обрабатываемого файла
* `rows_processed` ([UInt64](/ru/reference/data-types/int-uint)) — текущее количество обработанных строк
* `status` ([String](/ru/reference/data-types/string)) — статус обработки: Processed, Processing, Failed или None для файла, который известен кэшу, но не имеет состояния, например для файла, обработка которого была сброшена. Непустое значение `processing_observed_in_keeper_time` означает, что статус `Processing` был не установлен процессором, удерживающим файл, а прочитан из Keeper
* `processing_start_time` ([Nullable(DateTime)](/ru/reference/data-types/nullable)) — время начала обработки файла
* `processing_end_time` ([Nullable(DateTime)](/ru/reference/data-types/nullable)) — время окончания обработки файла
* `exception` ([String](/ru/reference/data-types/string)) — исключение, возникшее во время обработки. Всегда относится к последней попытке данного сервера и никогда — к тому исключению, которое Keeper хранит для файла
* `processing_observed_in_keeper_time` ([Nullable(DateTime)](/ru/reference/data-types/nullable)) — время, когда процессор данного сервера не смог взять файл и вместо того, чтобы установить статус `Processing` самостоятельно, прочитал его из Keeper. Обычно файл удерживается другим сервером, но он также может удерживаться процессором данного сервера, который только что его взял. В обоих случаях `rows_processed`, `processing_start_time`, `processing_end_time` и `exception` описывают последнюю попытку данного сервера обработать файл, а не ту обработку, которая удерживает его сейчас
