<div id="description">
  ## Описание
</div>

Содержит сведения о каждой отсоединённой таблице.

<div id="columns">
  ## Столбцы
</div>

{/*AUTOGENERATED_START*/}

* `database` ([String](/ru/reference/data-types/string)) — Имя базы данных, в которой находится таблица.
* `table` ([String](/ru/reference/data-types/string)) — Имя таблицы.
* `uuid` ([UUID](/ru/reference/data-types/uuid)) — UUID таблицы (база данных Atomic).
* `metadata_path` ([String](/ru/reference/data-types/string)) — Путь к метаданным таблицы в файловой системе.
* `is_permanently` ([UInt8](/ru/reference/data-types/int-uint)) — Таблица отсоединена навсегда.

{/*AUTOGENERATED_END*/}

<div id="notes">
  ## Примечания
</div>

В `DatabaseMySQL` и `DatabasePostgreSQL` данные хранятся не в самой базе данных, а на удалённом сервере MySQL/PostgreSQL. Поэтому операция `DROP TABLE` для таблицы из одной из этих баз данных внутренне реализуется как `detachTablePermanently`: она лишь удаляет локальную информацию ClickHouse об отслеживании таблицы, а сама таблица отображается в `system.detached_tables` с `is_permanently = 1`, как и при явном `DETACH TABLE PERMANENTLY`. Удалённые данные при этом не затрагиваются. Для постоянных баз данных MySQL/PostgreSQL состояние отсоединённой таблицы сохраняется после перезапусков сервера и повторных подключений: `DatabaseMySQL` сохраняет маркер `.remove_flag` в каталоге метаданных, а `DatabasePostgreSQL` — маркер `.removed`. При запуске оба маркера повторно загружаются функцией `loadStoredObjects`. Таблица вновь появляется только при создании нового сопоставления с внешней базой данных без старого каталога метаданных — например, если метаданные удалены или база данных создана под другим именем.
