Движок `Elasticsearch` позволяет читать документы из индекса в [Elasticsearch](https://www.elastic.co/elasticsearch). Каждый документ возвращается в виде одной строки: его `_source` представлен одним столбцом типа [JSON](/ru/reference/data-types/newjson), а ID документа и имя индекса доступны как виртуальные столбцы.

Движок работает только в режиме чтения. Документы извлекаются постранично через API `_search` с использованием [момента времени](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results#search-after) (point in time), поэтому запрос видит согласованный снимок индекса, даже если индекс в это время изменяется.

Требуется Elasticsearch версии 7.12 или новее: движок использует API point in time и поле сортировки `_shard_doc`. OpenSearch не поддерживается, так как в нём нет поля `_shard_doc`. Сервер более старой версии отклонит первый же запрос с ошибкой.

## Создание таблицы {#creating-a-table}

```sql
CREATE TABLE [IF NOT EXISTS] [db.]table_name
[(
    name1 JSON
)]
ENGINE = Elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...])
[SETTINGS keep_alive = 60, page_size = 10000]
```

<Note>
  Интеграция с Elasticsearch является экспериментальной. Включите её с помощью настройки [`enable_elasticsearch`](/ru/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

Список столбцов необязателен. Если он не указан, таблица содержит единственный столбец `document` типа `JSON`. Если он указан, в нём должен быть ровно один столбец типа `JSON` — при необходимости с подсказками типов и пропускаемыми путями. Столбцы `MATERIALIZED`, `ALIAS` и `EPHEMERAL` не поддерживаются, а имена `_id` и `_index` зарезервированы для виртуальных столбцов.

**Параметры движка**

* `url` — базовый URL кластера Elasticsearch, например `https://localhost:9200`. Это должен быть URL со схемой `http` или `https` без учётных данных, строки запроса и фрагмента.
* `index` — индекс для чтения. Также можно указать псевдоним, поток данных (data stream), список через запятую, шаблон с подстановочными символами или выражение с арифметикой дат (арифметика дат), например `<logs-{now/d}>`, — в любом виде, который принимает API point in time Elasticsearch. Значение передаётся как есть и не должно быть URL-кодированным. Если шаблону не соответствует ни один индекс, возникает ошибка.
* `user`, `password` — необязательные учётные данные для базовой аутентификации HTTP.
* `query('...')` — необязательный объект [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) Elasticsearch в формате JSON, определяющий, какие документы читать. Указывается после позиционных аргументов. По умолчанию: `{"match_all": {}}`.

Параметры также можно передать в виде [именованной коллекции](/ru/concepts/features/configuration/server-config/named-collections) с переопределениями вида `key = value`. Полный список ключей и описание [методов аутентификации](/ru/reference/functions/table-functions/elasticsearch#authentication) см. в описании [табличной функции `elasticsearch`](/ru/reference/functions/table-functions/elasticsearch#arguments).

**Настройки движка**

| Настройка    | По умолчанию | Описание                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------ | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keep_alive` | `60`         | Время в секундах, в течение которого Elasticsearch держит момент времени (point in time) открытым между двумя последовательными запросами страниц.                                                                                                                                                                                                                                                                           |
| `page_size`  | `10000`      | Количество документов, запрашиваемых у Elasticsearch за один запрос. Каждая страница становится одним блоком, поэтому эта настройка также определяет размер блока при чтении; [`max_block_size`](/ru/reference/settings/session-settings/max#max_block_size) при этом не действует. Значения, превышающие заданное в настройке индекса Elasticsearch `index.max_result_window` (по умолчанию `10000`), Elasticsearch отклоняет. |

Эти настройки нельзя изменить с помощью `ALTER TABLE ... MODIFY SETTING`. Чтобы изменить их, пересоздайте таблицу.

## Виртуальные столбцы {#virtual-columns}

* `_id` — идентификатор документа. Тип: `String`.
* `_index` — имя индекса, из которого был прочитан документ. Тип: `LowCardinality(String)`.

Если запрос читает только виртуальные столбцы, поле документа `_source` не запрашивается у Elasticsearch. Индекс, в котором `_source` не хранится (поле `_source` отключено в его маппинге), можно прочитать только через виртуальные столбцы: запрос, читающий `JSON`-столбец из такого индекса, завершится ошибкой, а не вернёт пустые документы.

## Пример использования {#usage-example}

```sql
CREATE TABLE logs
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*', 'elastic', 'changeme')
SETTINGS page_size = 5000;

SELECT _index, _id, document.message
FROM logs
WHERE document.level = 'error'
LIMIT 10;
```

Отфильтруйте данные на стороне Elasticsearch с помощью объекта Query DSL:

```sql
CREATE TABLE errors_since_october
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*',
                       query('{"bool": {"filter": [{"term": {"level": "error"}}, {"range": {"@timestamp": {"gte": "2026-10-01T00:00:00Z"}}}]}}'),
                       api_key = '...');
```

Используйте абсолютные даты в `query`: арифметика дат, например `now-1h`, вычисляется заново для каждой страницы, из-за чего часть документов может быть пропущена. См. [ограничения табличной функции `elasticsearch`](/ru/reference/functions/table-functions/elasticsearch#limitations).
