Движок позволяет импортировать данные из SQLite и экспортировать их в SQLite, а также выполнять запросы к таблицам SQLite напрямую из ClickHouse.

## Создание таблицы {#creating-a-table}

```sql
    CREATE TABLE [IF NOT EXISTS] [db.]table_name
    (
        name1 [type1],
        name2 [type2], ...
    ) ENGINE = SQLite('db_path', 'table')
```

**Параметры движка**

* `db_path` — Путь к файлу SQLite с базой данных.
* `table` — Имя таблицы в базе данных SQLite или запрос, передаваемый в SQLite как есть (см. [Передача запроса вместо имени таблицы](#passing-a-query)).

## Передача запроса вместо имени таблицы {#passing-a-query}

Вместо имени таблицы в качестве аргумента `table` можно указать `SELECT`-запрос, который передаётся в SQLite как есть. Структура таблицы определяется по результату запроса. Запрос можно записать либо как подзапрос, либо обернуть в функцию `query`:

```sql
CREATE TABLE sqlite_table ENGINE = SQLite('sqlite.db', (SELECT col1, col2 FROM table1 WHERE col2 > 1));
CREATE TABLE sqlite_table ENGINE = SQLite('sqlite.db', query('SELECT col1, col2 FROM table1 WHERE col2 > 1'));
```

Такая таблица доступна только для чтения: операция `INSERT` в неё запрещена. Тот же синтаксис поддерживается табличной функцией [`sqlite`](/ru/reference/functions/table-functions/sqlite).

<Note>
  Форма подзапроса `(SELECT ...)` разбирается ClickHouse и повторно сериализуется перед отправкой в SQLite. Поэтому она должна быть корректным ClickHouse SQL. Чтобы передать специфичный для SQLite синтаксис, который ClickHouse не разбирает, используйте форму `query('...')`, текст которой отправляется в SQLite дословно.

  Любые внешние `WHERE`, `LIMIT`, агрегирование и т. д. из окружающего запроса к ClickHouse **не** проталкиваются в передаваемый запрос — они применяются в ClickHouse после получения полного результата запроса. Чтобы ограничить объём данных, считываемых из SQLite, поместите фильтр внутрь передаваемого запроса. При [`external_table_strict_query = 1`](/ru/reference/settings/session-settings/external-table#external_table_strict_query) внешний фильтр по столбцам таблицы отклоняется с исключением вместо локального применения, поскольку его нельзя протолкнуть в передаваемый запрос. Проверка охватывает предикат верхнего уровня `WHERE` и каждый конъюнкт верхнего уровня `AND`. `PREWHERE` по столбцам этой таблицы не относится к данному параметру: этот движок таблицы не поддерживает `PREWHERE`, и такой запрос отклоняется с `ILLEGAL_PREWHERE` независимо от параметра. При использовании анализатора (по умолчанию) проверка выполняется только там, где фильтр вообще может быть протолкнут: когда эта таблица является единственной таблицей запроса, находится по обе стороны `INNER JOIN` или на сохраняющей стороне внешнего JOIN (левой стороне `LEFT JOIN`, правой стороне `RIGHT JOIN`). На несохраняющей стороне `LEFT`/`RIGHT JOIN` и по обе стороны `FULL JOIN` ничего не проталкивается и не проверяется, поэтому фильтр по столбцам этой таблицы применяется локально после JOIN даже в строгом режиме. Там, где выполняется проверка, предикат, ссылающийся на другие таблицы, присоединённые в окружающем запросе, не проталкивается и исключается из проверки — независимо от того, ссылается ли он только на присоединённую сторону или смешивает её с этой таблицей в одном выражении, не содержащем `AND` (например, в `OR`); такой предикат сохраняет обычную точку вычисления в ClickHouse (`WHERE` после JOIN, `PREWHERE` до него) и не отклоняется. При использовании старого анализатора (`enable_analyzer = 0`) это ограничение области действия не применяется: весь внешний фильтр проверяется, когда эта таблица является первой таблицей дерева JOIN, включая предикат по присоединённой стороне, а присоединённая правая таблица не проверяется.
</Note>

## Поддержка типов данных {#data-types-support}

Если в определении таблицы явно указать типы столбцов ClickHouse, из столбцов SQLite TEXT можно разобрать следующие типы ClickHouse:

* [Date](/ru/reference/data-types/date), [Date32](/ru/reference/data-types/date32)
* [DateTime](/ru/reference/data-types/datetime), [DateTime64](/ru/reference/data-types/datetime64)
* [UUID](/ru/reference/data-types/uuid)
* [Enum8, Enum16](/ru/reference/data-types/enum)
* [Decimal32, Decimal64, Decimal128, Decimal256](/ru/reference/data-types/decimal)
* [FixedString](/ru/reference/data-types/fixedstring)
* Все целочисленные типы ([UInt8, UInt16, UInt32, UInt64, Int8, Int16, Int32, Int64](/ru/reference/data-types/int-uint))
* [Float32, Float64](/ru/reference/data-types/float)

Сопоставление типов по умолчанию см. в разделе [движок базы данных SQLite](/ru/reference/engines/database-engines/sqlite#data_types-support).

## Пример использования {#usage-example}

Показан запрос на создание таблицы SQLite:

```sql
SHOW CREATE TABLE sqlite_db.table2;
```

```text
CREATE TABLE SQLite.table2
(
    `col1` Nullable(Int32),
    `col2` Nullable(String)
)
ENGINE = SQLite('sqlite.db','table2');
```

Возвращает данные из таблицы:

```sql
SELECT * FROM sqlite_db.table2 ORDER BY col1;
```

```text
┌─col1─┬─col2──┐
│    1 │ text1 │
│    2 │ text2 │
│    3 │ text3 │
└──────┴───────┘
```
