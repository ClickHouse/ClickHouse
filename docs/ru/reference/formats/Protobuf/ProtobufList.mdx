<div id="description">
  ## Описание {#description}
</div>

Формат `ProtobufList` объединяет строки в одно сообщение [Protocol Buffers](/ru/reference/formats/Protobuf/Protobuf) с префиксом длины, которое называется `Envelope`. Каждая строка кодируется как подсообщение с номером поля 1.

## Пример использования {#example-usage}

Сохраните следующую схему в файле `schemafile.proto`. Объявите поле `row` как `repeated`, чтобы декодер Protobuf, использующий эту схему, мог прочитать все строки в оболочке.

```capnp title="schemafile.proto"
syntax = "proto3";
message Envelope {
  message MessageType {
    string name = 1;
  }
  repeated MessageType row = 1;
}
```

В том же каталоге выполните следующие команды, чтобы записать две строки в файл и затем прочитать их.

```bash
clickhouse local --query "SELECT name FROM values('name String', 'Ada', 'Grace') ORDER BY name
    SETTINGS format_schema = 'schemafile:MessageType' FORMAT ProtobufList" > people.bin

clickhouse local --structure 'name String' --input-format ProtobufList \
    --format_schema 'schemafile:MessageType' --query 'SELECT name FROM table' < people.bin
```

```text
Ada
Grace
```

Тип сообщения, указанный в `format_schema`, определяется следующим образом: сначала система ищет его как вложенный тип в сообщении верхнего уровня `Envelope`. Если совпадение не найдено — либо потому, что в схеме нет сообщения `Envelope`, либо потому, что `Envelope` не содержит сообщения с запрошенным именем, — напрямую используется сообщение верхнего уровня с этим именем.
