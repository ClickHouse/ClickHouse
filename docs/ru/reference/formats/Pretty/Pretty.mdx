## Описание {#description}

Формат `Pretty` выводит данные в виде таблиц, нарисованных символами Unicode,
используя ANSI-последовательности экранирования для отображения цветов в терминале.
Отрисовывается полная сетка таблицы, и каждая строка занимает в терминале две строки.
Каждый блок результата выводится как отдельная таблица.
Это необходимо, чтобы блоки можно было выводить без буферизации результатов (буферизация потребовалась бы для предварительного вычисления видимой ширины всех значений).

[NULL](/ru/reference/syntax) выводится как `ᴺᵁᴸᴸ`.

## Пример использования {#example-usage}

Пример (для формата [`PrettyCompact`](/ru/reference/formats/Pretty/PrettyCompact)):

```sql title="Query"
SELECT * FROM t_null
```

```response title="Response"
┌─x─┬────y─┐
│ 1 │ ᴺᵁᴸᴸ │
└───┴──────┘
```

Строки не экранируются ни в одном из форматов `Pretty`. Вместо этого непечатаемые управляющие символы (управляющие символы C0 `0x00`-`0x1F` и `DEL` `0x7F`) в значениях и именах столбцов по умолчанию отображаются соответствующими символами Unicode &quot;Control Pictures&quot; (`U+2400`-`U+2421`): так они остаются видимыми и не искажают таблицу. Например, символ NUL отображается как `␀`:

```sql title="Query"
SELECT 'String with a NUL \0 character' AS Escaping_test FORMAT PrettyCompact
```

```response title="Response"
┌─Escaping_test─────────────────┐
│ String with a NUL ␀ character │
└───────────────────────────────┘
```

`TAB`, перевод строки и `ESC` являются исключениями: они всегда выводятся как есть, поскольку терминал не поглощает их, а интерпретирует: символ табуляции перемещает курсор к следующей позиции табуляции, а ANSI-последовательность экранирования позволяет встраивать в данные визуализацию. Перевод строки по-прежнему разрывает строку: внутри ячейки таблицы, если включена настройка [`output_format_pretty_multiline_fields`](/ru/reference/settings/formats#output_format_pretty_multiline_fields), и как есть в остальных случаях. Исключением из этого исключения является имя столбца: заголовок и нижний колонтитул выводятся в одну строку, поэтому перевод строки в имени заменяется так же, как любой другой управляющий символ.

Чтобы выводить управляющие символы без изменений, отключите настройку [`output_format_pretty_display_control_characters`](/ru/reference/settings/formats#output_format_pretty_display_control_characters):

```sql title="Query"
SELECT 'String with a NUL \0 character' AS Escaping_test FORMAT PrettyCompact
SETTINGS output_format_pretty_display_control_characters = 0
```

В этом случае ответ содержит необработанный байт `NUL`. Терминал его поглощает, поэтому символ
не отображается, а строка оказывается на одну позицию шире рамки, рассчитанной для неё, — именно такого
искажения таблицы позволяет избежать отображение символа из блока Control Pictures.

Чтобы не выводить в терминал слишком много данных, печатаются только первые `10,000` строк.
Если количество строк больше или равно `10,000`, выводится сообщение &quot;Showed first 10 000&quot;.

<Note>
  Этот формат подходит только для вывода результатов запроса, но не для парсинга данных.
</Note>

Формат Pretty поддерживает вывод итоговых значений (при использовании `WITH TOTALS`) и экстремальных значений (когда `extremes` установлено в 1).
В этих случаях итоговые и экстремальные значения выводятся после основных данных в отдельных таблицах.
Это показано в следующем примере, где используется формат [`PrettyCompact`](/ru/reference/formats/Pretty/PrettyCompact):

```sql title="Query"
SELECT EventDate, count() AS c 
FROM test.hits 
GROUP BY EventDate 
WITH TOTALS 
ORDER BY EventDate 
FORMAT PrettyCompact
```

```response title="Response"
┌──EventDate─┬───────c─┐
│ 2014-03-17 │ 1406958 │
│ 2014-03-18 │ 1383658 │
│ 2014-03-19 │ 1405797 │
│ 2014-03-20 │ 1353623 │
│ 2014-03-21 │ 1245779 │
│ 2014-03-22 │ 1031592 │
│ 2014-03-23 │ 1046491 │
└────────────┴─────────┘

Totals:
┌──EventDate─┬───────c─┐
│ 1970-01-01 │ 8873898 │
└────────────┴─────────┘

Extremes:
┌──EventDate─┬───────c─┐
│ 2014-03-17 │ 1031592 │
│ 2014-03-23 │ 1406958 │
└────────────┴─────────┘
```
