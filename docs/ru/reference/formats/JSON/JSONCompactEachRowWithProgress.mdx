## Описание {#description}

Сочетает компактный построчный вывод формата [`JSONCompactEachRow`](/ru/reference/formats/JSON/JSONCompactEachRow) с потоковой передачей информации о ходе выполнения запроса. ClickHouse передаёт каждое событие в виде отдельного объекта JSON; значения столбцов сохраняют свои исходные типы JSON.

Родственный формат `JSONCompactStringsEachRowWithProgress` использует те же виды объектов верхнего уровня, но значения полей в нём сериализуются как строки.

Использует тот же контракт потока, что и [`JSONEachRowWithProgress`](/ru/reference/formats/JSON/JSONEachRowWithProgress) (`writesProgressConcurrently` / `finalizeImpl`), с той лишь разницей, что полезная нагрузка `row` / `totals` / `min` / `max` представляет собой не именованные объекты, а **массивы** значений, упорядоченные по столбцам.

## Объекты потока {#stream-objects}

Каждая строка ответа — это один объект JSON. Клиенты должны определять тип объекта по ключу верхнего уровня:

| Ключ верхнего уровня         | Когда появляется                                                                     | Структура                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `meta`                       | Один раз, перед первым `row` (перед ним может быть выдан объект `progress`)          | `{"meta":[{"name":...,"type":...}, ...]}` — имена и типы столбцов                                                                                     |
| `row`                        | Один раз для каждой строки результата                                                | `{"row":[...]}` — значения столбцов в порядке заголовка                                                                                               |
| `progress`                   | Периодически во время выполнения запроса                                             | `{"progress":{...}}` — счётчики, например `read_rows`, `read_bytes`, `total_rows_to_read`                                                             |
| `totals`                     | При наличии итоговых значений                                                        | `{"totals":[...]}` — значения итоговой строки в порядке заголовка                                                                                     |
| `min` / `max`                | При наличии экстремальных значений                                                   | `{"min":[...]}` / `{"max":[...]}` — значения строк с экстремумами в порядке заголовка                                                                 |
| `rows_before_limit_at_least` | Если запрос содержит `LIMIT`                                                         | `{"rows_before_limit_at_least":N}` — нижняя оценка числа строк, которое получилось бы без `LIMIT` (не означает, что какие-либо строки были отброшены) |
| `rows_before_aggregation`    | Если запрос выполняет агрегацию и счётчик `rows_before_aggregation` включён          | `{"rows_before_aggregation":N}`                                                                                                                       |
| `exception`                  | При ошибке выполнения запроса через HTTP с `http_write_exception_in_output_format=1` | `{"exception":"..."}` — текст ошибки в виде **строки верхнего уровня**, а не вложенного в `row` значения                                              |

Объект `rows_before_limit_at_least` выдаётся, если запрос содержит `LIMIT`, даже когда ограничение не отбросило ни одной строки. Это нижняя оценка числа строк, которое получилось бы без `LIMIT` (то же значение, что и в `JSON`); клиенты не должны считать его доказательством того, что строки были отброшены.

`meta` выдаётся один раз перед первым `row`, однако объект `progress` может прийти раньше `meta`. Объект верхнего уровня `exception` выдаётся при работе через HTTP только при `http_write_exception_in_output_format=1`; в противном случае ошибка передаётся на транспортном уровне. Если этот объект выдаётся, он является отдельным объектом верхнего уровня и не вкладывается в `row`.

## Пример использования {#example-usage}

```sql title="Query"
SELECT *
FROM generateRandom('a Array(Int8), d Decimal32(4), c Tuple(DateTime64(3), UUID)', 1, 10, 2)
LIMIT 5
FORMAT JSONCompactEachRowWithProgress
```
