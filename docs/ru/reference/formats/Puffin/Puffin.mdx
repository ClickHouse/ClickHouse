## Описание {#description}

Формат для чтения и записи файлов [Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/).

Формат предоставляет позиции удалённых строк из blob-объектов `deletion-vector-v1`. Blob-объекты других типов, например `apache-datasketches-theta-v1`, пропускаются, как того требует спецификация Puffin; чтобы увидеть их, используйте `PuffinMetadata`.
Если файл Puffin содержит несколько blob-объектов `deletion-vector-v1`, формат выводит по одной строке на каждый такой blob-объект.

Фиксированные выходные столбцы:

* `referenced_data_file` (`String`) — местоположение файла данных, к которому применяется вектор удаления (свойство blob-объекта `referenced-data-file`)
* `deleted_rows` (`Array(UInt64)`) — 64-битные позиции строк, удалённых согласно roaring bitmap вектора удаления

При использовании в качестве выходного формата входные данные должны содержать те же два столбца, которые формат возвращает при чтении: файл данных, на который ссылается вектор (`String` или `LowCardinality(String)`), и позиции удалённых строк (целое число — одна позиция на строку — или массив целых чисел). Файл содержит по одному blob-объекту `deletion-vector-v1` на каждый уникальный файл данных, упорядоченных по местоположению файла данных, поэтому файл Puffin с несколькими векторами удаления можно скопировать как есть. Позиции всех строк с одинаковым файлом данных сливаются в один вектор удаления, дедуплицируются и сортируются; отрицательные позиции, позиции, превышающие предел вектора удаления Iceberg, и пустые местоположения файлов данных отклоняются. Метаданные blob-объекта записываются так же, как Apache Iceberg записывает векторы удаления: `fields` имеет значение `[2147483645]` (id столбца метаданных `_pos`), `snapshot-id` и `sequence-number` равны `-1`, а также задаются свойства `referenced-data-file` и `cardinality`. Нижний колонтитул не сжимается, поэтому полученный файл можно зарегистрировать в таблице Iceberg v3 как файл удаления с вектором удаления и читать другими движками, например Apache Spark. Чтобы получить `offset` и `length` каждого blob-объекта для полей манифеста `content_offset` и `content_size_in_bytes`, примените `PuffinMetadata` к записанному файлу.

Если настройка `output_format_puffin_blob_type` имеет значение `apache-datasketches-theta-v1`, формат вместо этого записывает статистику столбцов так же, как Apache Iceberg: каждый входной столбец становится одним blob-объектом `apache-datasketches-theta-v1` с компактным скетчем Apache DataSketches Theta (seed и размер по умолчанию), построенным по значениям столбца, отличным от null, а в свойство `ndv` записывается оценка числа уникальных значений. Значения передаются в скетч в бинарной сериализации одиночного значения Iceberg для типа столбца, поэтому скетчи можно объединять со скетчами, записанными Apache Spark: `Bool` как `boolean`, `Int8`, `UInt8`, `Int16`, `UInt16` и `Int32` как `int`, `UInt32`, `Int64` и `UInt64` как `long` (значения `UInt64` за пределами диапазона `Int64` сохраняют свои биты), `Float32` как `float`, `Float64` как `double`, `Date` и `Date32` как `date`, `DateTime` и `DateTime64` с точностью до 6 знаков как `timestamp` (в микросекундах), `String` как `string`, `FixedString` как `fixed`, `UUID` как `uuid` и `Decimal` как `decimal`; также поддерживаются `Nullable` и `LowCardinality` этих типов. Пустые строки игнорируются, как и в Iceberg. Значение `fields` blob-объектов берётся из настройки `output_format_puffin_field_ids`, а `snapshot-id` и `sequence-number` — из настроек `output_format_puffin_snapshot_id` и `output_format_puffin_sequence_number`; все три настройки обязательны, поскольку считыватели привязывают статистику к указанным в них столбцам и снимку. Результат можно зарегистрировать как файл статистики Iceberg.

Векторы удаления, у которых заявленное значение `cardinality` превышает абсолютный предел материализации, отклоняются при запросе `deleted_rows`. Свойства `deletion-vector-v1` в нижнем колонтитуле (в том числе то, что `cardinality` разбирается как беззнаковое целое число) проверяются всегда. При выборке только `referenced_data_file` операции I/O с полезной нагрузкой на диске не выполняются, а значит, пропускаются и проверка оболочки, CRC, десериализация roaring и проверка предела материализации. Это сделано намеренно, чтобы проекция только по пути не читала данные вплоть до предельного размера blob-объекта.

Длина blob-объекта `deletion-vector-v1` на диске ограничена абсолютным пределом (согласованным с проверкой размера содержимого в Iceberg, равной 2 GiB). При запросе `deleted_rows` считыватель предварительно читает заголовок оболочки (общую длину и magic), прежде чем выделить память под всю полезную нагрузку; CRC проверяется после ограниченного чтения.

Поддерживаются сжатые LZ4 и несжатые нижние колонтитулы Puffin. Размер полезной нагрузки нижнего колонтитула (и заявленный размер содержимого LZ4) ограничен коэффициентом сжатия, где это применимо, и абсолютным пределом; нижние колонтитулы слишком большого размера отклоняются до выделения памяти.

Можно запросить только подмножество выходных столбцов. Структура, предоставленная пользователем и содержащая неожиданные имена или типы столбцов, отклоняется при создании формата.

## Пример использования {#example-usage}

Прочитайте позиции удалённых строк из указанного файла данных:

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

Разверните удалённые позиции в отдельные строки:

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

Используйте `PuffinMetadata` для проверки дескрипторов blob-объектов в нижнем колонтитуле перед чтением векторов удаления.

Запишите векторы удаления для двух файлов данных в один файл Puffin:

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

Запишите Theta-скетчи двух столбцов в файл статистики Iceberg:

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
