Секция `SHUFFLE` возвращает строки результата запроса в равномерно случайном порядке. Она используется вместо секции [ORDER BY](/ru/reference/statements/select/order-by) и не может применяться совместно с ней.

Результат совпадает с результатом `ORDER BY rand()`, но вычисляется за время O(n), а не O(n * log(n)).

`SHUFFLE` можно использовать без `LIMIT`, чтобы перемешать все строки, или с `LIMIT n`, чтобы получить равномерно случайную выборку из `n` строк (также в случайном порядке). При использовании `LIMIT n` каждый поток хранит только `n` строк, поэтому использование памяти составляет O(n) независимо от количества строк в результате запроса. `OFFSET` и `LIMIT BY` можно использовать так же, как с `ORDER BY`.

<Note>
  Это экспериментальная возможность. Чтобы включить её, используйте настройку [`allow_experimental_shuffle_query`](/ru/reference/settings/session-settings#allow_experimental_shuffle_query).
</Note>

## Подробности реализации {#implementation-details}

Случайный выбор выполняется непосредственно во время обработки: случайные значения для строк заранее не генерируются и не сохраняются. Без `LIMIT` каждая строка отправляется в случайно выбранный поток из `max_threads`, каждый поток параллельно перемешивается алгоритмом Фишера — Йейтса (частями, помещающимися в кэш CPU), после чего потоки объединяются. С `LIMIT n` каждый поток хранит равномерную случайную выборку из `n` строк с помощью резервуарного сэмплирования, при котором строки, заведомо не попадающие в выборку, пропускаются без просмотра, а затем выполняется слияние выборок: количество строк, берущихся из каждого потока, определяется сэмплированием без возвращения по количествам строк в потоках. В распределённом запросе удалённые серверы перемешивают свои данные и добавляют к строкам отсортированные случайные ключи, а initiator выполняет слияние перемешанных потоков по этим ключам, что требует O(1) памяти.

Без `LIMIT` `SHUFFLE` хранит все строки в памяти. В отличие от `ORDER BY`, он не выполняет сброс данных на диск.

`ORDER BY rand()` и `ORDER BY rand64()` могут выполняться так же, как `SHUFFLE` (настройка `query_plan_use_shuffle_for_order_by_rand`), если случайное значение больше нигде в запросе не используется и внешняя сортировка отключена. Если внешняя сортировка настроена, эта оптимизация отключается даже при конечном `LIMIT`, поскольку выборка всё равно может не поместиться в память, а `SHUFFLE` не умеет сбрасывать данные на диск. Для `ORDER BY rand64()` с конечным лимитом сортировка сохраняется, чтобы не терять ни одного бита случайных значений.

## Примеры {#examples}

```sql
SET allow_experimental_shuffle_query = 1;

SELECT number FROM numbers(5) SHUFFLE;
```

```text
┌─number─┐
│      3 │
│      0 │
│      4 │
│      1 │
│      2 │
└────────┘
```

Случайная выборка из трёх строк:

```sql
SELECT number FROM numbers(1000000) SHUFFLE LIMIT 3;
```

```text
┌─number─┐
│ 493721 │
│  20857 │
│ 871324 │
└────────┘
```

`SHUFFLE` — ключевое слово, если оно стоит после предложения `FROM`. Чтобы использовать `shuffle` как псевдоним таблицы, укажите `AS shuffle`.
