Позволяет выполнять несколько команд параллельно.

## Синтаксис {#syntax}

```sql
statement1 PARALLEL WITH statement2 [PARALLEL WITH statement3 ...]
```

Выполняет операторы `statement1`, `statement2`, `statement3`, ... параллельно. Объединять можно только операторы, которые не возвращают результирующий набор и не ожидают входных данных, см. [Ограничения](#restrictions).

Во многих случаях параллельное выполнение операторов может быть быстрее, чем их обычное последовательное выполнение. Например, `statement1 PARALLEL WITH statement2 PARALLEL WITH statement3`, скорее всего, выполнится быстрее, чем `statement1; statement2; statement3`.

## Примеры {#examples}

Создаются две таблицы параллельно:

```sql
CREATE TABLE table1(x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2(y String) ENGINE = MergeTree ORDER BY tuple();
```

Удаляет две таблицы параллельно:

```sql
DROP TABLE table1
PARALLEL WITH
DROP TABLE table2;
```

## Ограничения {#restrictions}

Оператор, который возвращает результирующий набор (например, `SELECT`) или ожидает входные данные, отклоняется с ошибкой `INCORRECT_QUERY`.

DDL, выполняемый с [`ON CLUSTER`](/ru/reference/statements/distributed-ddl) или через журнал DDL базы данных [`Replicated`](/ru/reference/engines/database-engines/replicated), возвращает таблицу статусов, поэтому такой запрос тоже отклоняется, но лишь после того, как он уже отправлен на хосты, и они его всё равно выполняют. Его можно комбинировать, если параметр [`distributed_ddl_output_mode`](/ru/reference/settings/session-settings/distributed-ddl#distributed_ddl_output_mode) имеет значение `none` или `none_only_active`:

```sql
SET distributed_ddl_output_mode = 'none';

CREATE TABLE table1 ON CLUSTER default (x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2 ON CLUSTER default (y String) ENGINE = MergeTree ORDER BY tuple();
```

## Настройки {#settings}

Параметр [max&#95;threads](/ru/reference/settings/session-settings/max-threads#max_threads) определяет, сколько потоков будет создано.

## Сравнение с UNION {#comparison-with-union}

Конструкция `PARALLEL WITH` в некоторой степени похожа на [UNION](/ru/reference/statements/select/union), который тоже выполняет свои операнды параллельно. Однако есть несколько отличий:

* `PARALLEL WITH` не возвращает никаких результатов выполнения своих операндов и может лишь повторно сгенерировать возникшее в них исключение, если оно есть;
* `PARALLEL WITH` объединяет операторы, которые не возвращают результирующий набор и не ожидают входных данных, тогда как `UNION` объединяет запросы `SELECT`.
