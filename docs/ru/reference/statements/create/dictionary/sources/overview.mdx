## Синтаксис {#dictionary-sources}

<CloudDetails />

Словарь можно подключить к ClickHouse из самых разных источников.
Источник задаётся в разделе `source` файла конфигурации и с помощью предложения `SOURCE` в DDL-операторе.

<Tabs>
  <Tab title="DDL">
    ```sql
    CREATE DICTIONARY dict_name (...)
    ...
    SOURCE(SOURCE_TYPE(param1 val1 ... paramN valN)) -- Конфигурация источника
    ...
    ```
  </Tab>

  <Tab title="файл конфигурации">
    ```xml
    <clickhouse>
      <dictionary>
        ...
        <source>
          <source_type>
            <!-- Конфигурация источника -->
          </source_type>
        </source>
        ...
      </dictionary>
      ...
    </clickhouse>
    ```
  </Tab>
</Tabs>

<br />

* [Исполняемый файл](/ru/reference/statements/create/dictionary/sources/executable-file)
* [Executable Pool](/ru/reference/statements/create/dictionary/sources/executable-pool)
* [HTTP(S)](/ru/reference/statements/create/dictionary/sources/http)
* СУБД
  * [ODBC](/ru/reference/statements/create/dictionary/sources/odbc)
  * [MySQL](/ru/reference/statements/create/dictionary/sources/mysql)
  * [ClickHouse](/ru/reference/statements/create/dictionary/sources/clickhouse)
  * [MongoDB](/ru/reference/statements/create/dictionary/sources/mongodb)
  * [Redis](/ru/reference/statements/create/dictionary/sources/redis)
  * [Cassandra](/ru/reference/statements/create/dictionary/sources/cassandra)
  * [PostgreSQL](/ru/reference/statements/create/dictionary/sources/postgresql)
  * [YTsaurus](/ru/reference/statements/create/dictionary/sources/ytsaurus)
* [YAMLRegExpTree](/ru/reference/statements/create/dictionary/sources/yamlregexptree)
* [Null](/ru/reference/statements/create/dictionary/sources/null)

Для типов источников [Локальный файл](/ru/reference/statements/create/dictionary/sources/local-file), [Исполняемый файл](/ru/reference/statements/create/dictionary/sources/executable-file), [HTTP(s)](/ru/reference/statements/create/dictionary/sources/http), [ClickHouse](/ru/reference/statements/create/dictionary/sources/clickhouse)
можно использовать дополнительные настройки:

<Tabs>
  <Tab title="DDL">
    ```sql highlight={2}
    SOURCE(FILE(path './user_files/os.tsv' format 'TabSeparated'))
    SETTINGS(format_csv_allow_single_quotes = 0)
    ```
  </Tab>

  <Tab title="Файл конфигурации">
    ```xml highlight={7}
    <source>
      <file>
        <path>/opt/dictionaries/os.tsv</path>
        <format>TabSeparated</format>
      </file>
      <settings>
          <format_csv_allow_single_quotes>0</format_csv_allow_single_quotes>
      </settings>
    </source>
    ```
  </Tab>
</Tabs>

## Порядок столбцов в пользовательском запросе {#custom-query-column-order}

Источники [ClickHouse](/ru/reference/statements/create/dictionary/sources/clickhouse),
[MySQL](/ru/reference/statements/create/dictionary/sources/mysql),
[PostgreSQL](/ru/reference/statements/create/dictionary/sources/postgresql) и
[ODBC](/ru/reference/statements/create/dictionary/sources/odbc) поддерживают поле `query`, которое
заменяет запрос, формируемый ClickHouse по умолчанию на основе `table` и `where`.

Словарь ожидает столбцы результата в фиксированном порядке, который отличается от порядка
атрибутов в операторе `CREATE DICTIONARY`:

1. ключевой столбец (или столбцы) в порядке `PRIMARY KEY`;
2. для словаря [`range_hashed`](/ru/reference/statements/create/dictionary/layouts/range-hashed) или
   `complex_key_range_hashed` — столбец `range_min`, затем столбец `range_max`;
3. остальные атрибуты в порядке их объявления.

Источник ClickHouse сопоставляет результат с этим порядком по именам столбцов, поэтому для него порядок
столбцов в `query` не важен, если имя каждого столбца совпадает с именем заполняемого им атрибута. Источники
MySQL, PostgreSQL и ODBC берут столбцы по позиции, поэтому если в `query` для них столбцы расположены
в другом порядке, значения загрузятся не в те атрибуты. В зависимости от задействованных типов
словарь либо не загрузится из-за ошибки преобразования, либо сохранит неверные значения. Поэтому
указывайте столбцы в `query` в приведённом выше порядке:

```sql
CREATE DICTIONARY contracts (
    meter_no String,
    id Int64,
    contract_time Date,
    end_date Date
)
PRIMARY KEY meter_no
-- The key comes first, then the range columns, then the remaining attributes.
SOURCE(POSTGRESQL(... query 'SELECT meter_no, contract_time, end_date, id FROM contracts'))
LAYOUT(RANGE_HASHED())
RANGE(MIN contract_time MAX end_date)
LIFETIME(300)
```
