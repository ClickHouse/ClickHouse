Добавлено в: v24.11.0

Создаёт ресурс для [планирования рабочей нагрузки](/ru/concepts/features/configuration/server-config/workload-scheduling): вид доступа (например, чтение с диска или процессорное время), который распределяется между рабочими нагрузками, созданными с помощью [`CREATE WORKLOAD`](/ru/reference/statements/create/workload).

## Синтаксис {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`, `IF NOT EXISTS` и `ON CLUSTER` работают так же, как в [`CREATE WORKLOAD`](/ru/reference/statements/create/workload#syntax).

## Режимы доступа {#access-modes}

| Режим доступа                                 | Планируемый доступ                                                                                                                                 | Добавлено в |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | Чтение с диска `disk_name` или запись на него, см. [Ресурсы](/ru/concepts/features/configuration/server-config/workload-scheduling#resources)         | v24.11.0    |
| `READ ANY DISK`, `WRITE ANY DISK`             | Чтение с любого диска или запись на любой диск                                                                                                     | v24.11.0    |
| `MASTER THREAD`, `WORKER THREAD`              | CPU, см. [Планирование ресурсов CPU](/ru/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)                            | v25.4.0     |
| `QUERY`                                       | Слоты запросов, см. [Планирование слотов выполнения запросов](/ru/concepts/features/configuration/server-config/workload-scheduling#query_scheduling) | v25.6.0     |
| `MEMORY RESERVATION`                          | Память, см. [Резервирование памяти](/ru/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)                        | v26.6.2     |

Все режимы доступа одного ресурса должны относиться к одному виду: диск, потоки CPU, `QUERY` или `MEMORY RESERVATION`. Каждый из режимов `MASTER THREAD`, `WORKER THREAD`, `QUERY` и `MEMORY RESERVATION` может относиться не более чем к одному ресурсу. `CREATE OR REPLACE RESOURCE` не позволяет изменить вид ресурса: удалите ресурс и создайте его заново.

<Note>
  `MEMORY RESERVATION` — экспериментальная возможность: её SQL-интерфейс и поведение могут измениться в будущих версиях.
</Note>

## Хранилище {#storage}

Ресурсы хранятся так же, как рабочие нагрузки, см. раздел [Хранилище](/ru/reference/statements/create/workload#storage). Список ресурсов содержится в таблице [`system.resources`](/ru/reference/system-tables/resources).

## Привилегии {#privileges}

Для выполнения `CREATE RESOURCE` требуется привилегия `CREATE RESOURCE`. Для `CREATE OR REPLACE RESOURCE` также требуется привилегия `DROP RESOURCE`.

## Пример {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
