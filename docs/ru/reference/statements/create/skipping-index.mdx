Добавлено в: v22.7.0

Добавляет [индекс пропуска данных](/ru/reference/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-data_skipping-indexes) в таблицу семейства `MergeTree`. Это автономная форма команды [`ALTER TABLE ... ADD INDEX`](/ru/reference/statements/alter/skipping-index#add-index), требующая той же привилегии `ALTER ADD INDEX`.

## Синтаксис {#syntax}

```sql
CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [db.]table [ON CLUSTER cluster] expression TYPE type [GRANULARITY value]
```

* `expression` — индексируемое выражение, которое можно заключить в скобки. Список в скобках `(expr1, expr2, ...)` создаёт один индекс по всем выражениям — так же, как `INDEX name (expr1, expr2, ...)` в `CREATE TABLE`.
* `TYPE type [GRANULARITY value]` — как в секции `INDEX` оператора `CREATE TABLE`, см. [типы индексов пропуска данных](/ru/reference/engines/table-engines/mergetree-family/mergetree#skip-index-types).
* `IF NOT EXISTS` — если в таблице уже есть индекс с именем `name`, запрос ничего не делает.

Как и `ADD INDEX`, этот оператор изменяет только метаданные таблицы. Чтобы построить индекс для данных, которые уже есть в таблице, выполните [`ALTER TABLE ... MATERIALIZE INDEX`](/ru/reference/statements/alter/skipping-index#materialize-index).

## Совместимость с SQL {#sql-compatibility}

Для совместимости с другими системами баз данных:

* `ASC` и `DESC` после выражений в списке, заключённом в скобки, игнорируются.
* `CREATE UNIQUE INDEX` отклоняется, если только настройка [`create_index_ignore_unique`](/ru/reference/settings/session-settings/create#create_index_ignore_unique) не равна `1`. В этом случае `UNIQUE` игнорируется и создаётся обычный индекс.
* `CREATE INDEX` без `TYPE` отклоняется, если только настройка [`allow_create_index_without_type`](/ru/reference/settings/session-settings/allow#allow_create_index_without_type) не равна `1`. В этом случае запрос ничего не делает.

## Пример {#example}

```sql title="Query"
CREATE TABLE t (id UInt64, s String) ENGINE = MergeTree ORDER BY id;
INSERT INTO t SELECT number, toString(number) FROM numbers(1000);
CREATE INDEX idx_s ON t (s) TYPE bloom_filter GRANULARITY 1;
ALTER TABLE t MATERIALIZE INDEX idx_s SETTINGS mutations_sync = 1;
SELECT name, type, expr, granularity FROM system.data_skipping_indices WHERE database = currentDatabase() AND table = 't';
```

```text title="Response"
┌─name──┬─type─────────┬─expr─┬─granularity─┐
│ idx_s │ bloom_filter │ s    │           1 │
└───────┴──────────────┴──────┴─────────────┘
```
