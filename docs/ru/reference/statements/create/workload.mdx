Добавлено в: v24.11.0

Создаёт рабочую нагрузку — узел иерархии, с помощью которой [планирование рабочих нагрузок](/ru/concepts/features/configuration/server-config/workload-scheduling) распределяет ресурсы между рабочими нагрузками. Ресурсы для планирования создаются с помощью [`CREATE RESOURCE`](/ru/reference/statements/create/resource).

## Синтаксис {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` — заменяет определение существующей рабочей нагрузки. Не может использоваться вместе с `IF NOT EXISTS`.
* `IF NOT EXISTS` — если рабочая нагрузка с именем `name` уже существует, запрос ничего не делает.
* `IN parent_name` — создаёт рабочую нагрузку как дочернюю по отношению к рабочей нагрузке `parent_name`. Рабочая нагрузка без `IN` является корневой. Циклические зависимости между рабочими нагрузками не допускаются.
* `SETTINGS` — настройки планирования рабочей нагрузки, например `weight`, `priority`, `max_concurrent_threads` или `max_bytes_per_second`, описанные в разделе [Иерархия рабочих нагрузок](/ru/concepts/features/configuration/server-config/workload-scheduling#workloads). Настройка с `FOR resource_name` применяется только к указанному ресурсу, без него — ко всем ресурсам. Неизвестная настройка приводит к ошибке.

Рабочие нагрузки и ресурсы находятся в отдельных пространствах имён, поэтому рабочая нагрузка и ресурс могут иметь одинаковое имя. Запрос выполняется в рабочей нагрузке, заданной его настройкой [`workload`](/ru/reference/settings/session-settings/other#workload), см. [Разметка рабочих нагрузок](/ru/concepts/features/configuration/server-config/workload-scheduling#workload-markup).

<Note>
  Планирование резервирования памяти является экспериментальной возможностью. Это относится к ресурсу `MEMORY RESERVATION` и к настройкам рабочей нагрузки `max_memory`, `max_memory_ratio`, `max_memory_before_spill` и `max_memory_to_spill_ratio`. См. [Резервирование памяти](/ru/concepts/features/configuration/server-config/workload-scheduling#memory-reservations).
</Note>

## Хранилище {#storage}

Рабочие нагрузки хранятся на диске в каталоге [`workload_path`](/ru/reference/settings/server-settings/settings/workload#workload_path) или в ZooKeeper по пути [`workload_zookeeper_path`](/ru/reference/settings/server-settings/settings/workload#workload_zookeeper_path), если этот параметр задан. При использовании хранилища ZooKeeper предложение `ON CLUSTER` не допускается, поскольку определения реплицируются автоматически. Рабочие нагрузки, [определённые в конфигурации сервера](/ru/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads), нельзя заменить или удалить средствами SQL. Список рабочих нагрузок содержится в таблице [`system.workloads`](/ru/reference/system-tables/workloads).

## Привилегии {#privileges}

Для выполнения `CREATE WORKLOAD` требуется привилегия `CREATE WORKLOAD`. Для `CREATE OR REPLACE WORKLOAD` дополнительно требуется привилегия `DROP WORKLOAD`.

## Пример {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
