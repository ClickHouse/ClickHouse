Операторы управления транзакциями `BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK` и `SET TRANSACTION SNAPSHOT` объединяют несколько запросов к таблицам `MergeTree` в одну транзакцию.
Запросы транзакции читают единый согласованный снимок изменений, закоммиченных другими транзакциями.
Операции записи вне транзакций не изолированы: результат `INSERT`, `TRUNCATE TABLE` или `ALTER TABLE ... DELETE`, выполненных вне транзакции, виден следующему запросу активной транзакции. Поэтому для получения стабильного представления данных записывающие клиенты также должны использовать транзакции, например с помощью [`implicit_transaction`](/ru/reference/settings/session-settings/implicit#implicit_transaction).
Другие транзакции видят изменения транзакции только после `COMMIT`, а `ROLLBACK` отменяет их.
Запросы, выполняемые вне транзакции, могут видеть изменения активной транзакции ещё до её коммита.

<Note>
  Эти операторы входят в набор экспериментальных функций.
  Чтобы включить экспериментальную поддержку транзакций, добавьте следующую настройку в [конфигурацию](/ru/concepts/features/configuration/server-config/configuration-files):


## Синтаксис {#syntax}

```sql
BEGIN TRANSACTION
START TRANSACTION
COMMIT
ROLLBACK
SET TRANSACTION SNAPSHOT snapshot
```

Транзакция принадлежит сеансу, и в одном сеансе может быть не более одной транзакции.
При работе по HTTP отправляйте все запросы транзакции с одним и тем же `session_id`: запрос без `session_id` выполняется в отдельном сеансе, который завершается вместе с этим запросом.
Если на момент завершения сеанса транзакция всё ещё выполняется, она откатывается.

## BEGIN TRANSACTION {#begin-transaction}

Начинает транзакцию в текущем сеансе. `START TRANSACTION` — псевдоним этой команды, добавленный в v24.3.0.

Вложенные транзакции не поддерживаются: `BEGIN TRANSACTION` внутри транзакции выбрасывает исключение `INVALID_TRANSACTION`.

## COMMIT {#commit}

Коммитит текущую транзакцию и делает её изменения видимыми для других транзакций.
Если текущей транзакции нет, `COMMIT` выбрасывает исключение `INVALID_TRANSACTION`.

Если запрос внутри транзакции завершается с ошибкой, транзакция откатывается. Запрос, который не удаётся разобрать (например, из-за синтаксической ошибки) или у которого параметры запроса отсутствуют или недопустимы, не выполняется и оставляет транзакцию активной, поэтому последующий `COMMIT` всё равно её закоммитит.
Пока откатанная транзакция не будет завершена с помощью `ROLLBACK`, `COMMIT` и другие последующие запросы выбрасывают исключение `INVALID_TRANSACTION`. Выполняются только `ROLLBACK`, `SET TRANSACTION SNAPSHOT` и запросы `EXPLAIN`, кроме `EXPLAIN ANALYZE`.

Настройка [`wait_changes_become_visible_after_commit_mode`](/ru/reference/settings/session-settings/other#wait_changes_become_visible_after_commit_mode) определяет, чего ожидает `COMMIT`.

## ROLLBACK {#rollback}

Откатывает текущую транзакцию и отменяет внесённые в ней изменения.
Если текущей транзакции нет, `ROLLBACK` выбрасывает исключение `INVALID_TRANSACTION`.

## SET TRANSACTION SNAPSHOT {#set-transaction-snapshot}

Изменяет снимок, из которого читает текущая транзакция, на порядковый номер коммита (CSN) `snapshot` — например, на значение, которое [`transactionLatestSnapshot`](/ru/reference/functions/regular-functions/other-functions#transactionLatestSnapshot) вернула в одной из предыдущих транзакций.
После этого транзакция видит собственные изменения, данные, записанные вне транзакций, и изменения транзакций, закоммиченных до этого CSN.
Она читает только те части, которые сервер ещё хранит, и не защищает их от удаления: как только не остаётся выполняющихся транзакций, начатых до того, как слияние, мутация или другой запрос удалили часть, сервер может удалить эту часть, и более ранний снимок перестанет видеть её строки.
Не используйте `SET TRANSACTION SNAPSHOT` в расчёте на повторяемое чтение исторических данных.
`SET TRANSACTION SNAPSHOT` без текущей транзакции выбрасывает исключение `INVALID_TRANSACTION`.

Значения от `0` до `32` зарезервированы и приводят к исключению `INVALID_TRANSACTION`, кроме двух:
`1` делает видимыми только данные, записанные вне транзакций, и собственные изменения транзакции, а `3` делает видимыми все части таблицы, включая части ещё не закоммиченных транзакций и части, которые транзакции удалили или откатили.

## Запросы внутри транзакции {#queries-inside-a-transaction}

Внутри транзакции можно выполнять запросы `SELECT`, `INSERT`, `DELETE`, `OPTIMIZE`, `TRUNCATE TABLE`, `SET` и `EXPLAIN`, а также мутации `ALTER TABLE` и операции с партициями.
Другие запросы, например `CREATE TABLE`, `UPDATE` или `ALTER TABLE ... ADD COLUMN`, выбрасывают исключение `NOT_IMPLEMENTED`. То же относится к запросам к таблицам, которые не поддерживают транзакции, например к таблицам `ReplicatedMergeTree` или `Memory`, а также к `system.transactions`.

Асинхронные вставки внутри транзакции не поддерживаются, а настройка [`async_insert`](/ru/reference/settings/session-settings/async-insert#async_insert) по умолчанию включена, поэтому `INSERT ... VALUES` или `INSERT ... SELECT` внутри транзакции выбрасывает исключение `NOT_IMPLEMENTED`, если не отключить `async_insert`, например с помощью `SET async_insert = 0`.

Если настройка [`throw_on_unsupported_query_inside_transaction`](/ru/reference/settings/session-settings/throw-on#throw_on_unsupported_query_inside_transaction) имеет значение `0`, некоторые из этих запросов не генерируют исключение, а выполняются вне транзакции, поэтому `ROLLBACK` их не отменяет. Например, это касается `CREATE TABLE` или `INSERT` в таблицу `Memory`.

Если включена настройка [`implicit_transaction`](/ru/reference/settings/session-settings/implicit#implicit_transaction), каждый запрос, выполняемый вне транзакции, выполняется в отдельной транзакции, которая коммитится при успешном выполнении запроса и откатывается в случае ошибки.

## Примеры {#examples}

Откат вставки:

```sql title="Query"
CREATE TABLE t (n UInt64) ENGINE = MergeTree ORDER BY n;
SET async_insert = 0;

BEGIN TRANSACTION;
INSERT INTO t VALUES (1);
SELECT count() FROM t;
ROLLBACK;
SELECT count() FROM t;
```

```text title="Response"
┌─count()─┐
│       1 │
└─────────┘
┌─count()─┐
│       0 │
└─────────┘
```

Коммит вставки:

```sql title="Query"
BEGIN TRANSACTION;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```text title="Response"
┌─n─┐
│ 2 │
└───┘
```
