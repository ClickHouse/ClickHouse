```sql
ALTER TABLE [db.]table [ON CLUSTER cluster] DELETE WHERE filter_expr
```

Удаляет данные, соответствующие указанному фильтрующему выражению. Реализовано в виде [мутации](/ru/reference/statements/alter/index#mutations).

<Warning>
  Префикс `ALTER TABLE` указывает на то, что это тяжеловесная операция, в отличие от похожих запросов в OLTP-базах данных. `ALTER TABLE ... DELETE` переписывает каждую часть данных, содержащую строки, соответствующие выражению фильтрации, создавая значительный объем операций ввода-вывода. Используйте её редко, так как она может повлиять на производительность `SELECT`.

  Для таблиц `MergeTree` рассмотрите возможность использования [запроса `DELETE FROM`](/ru/reference/statements/delete), который выполняет легковесное удаление и может быть значительно быстрее. Для рабочих нагрузок, требующих частых удалений или исправлений, рассмотрите возможность использования [`ReplacingMergeTree`](/ru/concepts/features/operations/update/replacing-merge-tree) или [`CollapsingMergeTree`](/ru/reference/engines/table-engines/mergetree-family/collapsingmergetree).
</Warning>

`filter_expr` должен иметь тип `UInt8`. Запрос удаляет строки таблицы, для которых это выражение принимает ненулевое значение.

Один запрос может содержать несколько команд, разделенных запятыми.

Синхронность выполнения запроса определяется настройкой [mutations&#95;sync](/ru/reference/settings/session-settings/mutations#mutations_sync). По умолчанию запрос выполняется асинхронно.
