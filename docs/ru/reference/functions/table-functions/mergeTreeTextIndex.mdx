Представляет словарь текстового индекса в таблицах MergeTree.
Возвращает токены с метаданными списка вхождений.
Может использоваться для интроспекции.

## Синтаксис {#syntax}

```sql
mergeTreeTextIndex(database, table, index_name)
```

## Аргументы {#arguments}

| Аргумент     | Описание                                                  |
| ------------ | --------------------------------------------------------- |
| `database`   | Имя базы данных, из которой считывается текстовый индекс. |
| `table`      | Имя таблицы, из которой считывается текстовый индекс.     |
| `index_name` | Имя текстового индекса, который считывается.              |

## Возвращаемое значение {#returned-value}

Объект таблица с токенами и метаданными их списков вхождений.

Если индекс использует токенизатор `keyValuePairs`, каждый токен представляет собой пару `(key, value)` из столбца типа `Map`, а результат содержит два дополнительных столбца — `token_key` и `token_value` — с декодированными частями токена.

Списки вхождений токенов возвращаются в следующих виртуальных столбцах. Запрос `SELECT *` их не возвращает, поэтому их нужно указывать явно.

| Столбец     | Тип             | Описание                                                                                                 |
| ----------- | --------------- | -------------------------------------------------------------------------------------------------------- |
| `row_id`    | `UInt32`        | Номер строки в части данных (см. `_part_offset`) из списка вхождений токена.                             |
| `positions` | `Array(UInt32)` | Позиции токена в строке. Присутствует, только если у индекса задан аргумент `support_phrase_search = 1`. |

Если выбран хотя бы один из этих столбцов, результат содержит отдельную строку для каждой строки из списка вхождений каждого токена — аналогично `ARRAY JOIN` по списку вхождений; при этом остальные столбцы токена повторяются в каждой такой строке.

Списки вхождений возвращаются в том виде, в котором они хранятся в индексе части данных, поэтому до слияния части в них присутствуют строки, удалённые с помощью легковесного `DELETE` (см. `_row_exists`).

## Пример использования {#usage-example}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha)
)
ENGINE = MergeTree
ORDER BY id;

INSERT INTO tab SELECT number, concatWithSeparator(' ', 'apple', 'banana') FROM numbers(500);
INSERT INTO tab SELECT 500 + number, concatWithSeparator(' ', 'cherry', 'date') FROM numbers(500);

SELECT * FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s);
```

## Пример использования: списки вхождений {#usage-example-posting-lists}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha, support_phrase_search = 1)
)
ENGINE = MergeTree
ORDER BY id
SETTINGS allow_experimental_text_index_phrase_search = 1;

INSERT INTO tab VALUES (0, 'apple banana apple'), (1, 'banana cherry'), (2, 'cherry apple');

SELECT token, row_id, positions FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s) ORDER BY token, row_id;
```

```text title="Response"
   ┌─token──┬─row_id─┬─positions─┐
1. │ apple  │      0 │ [0,2]     │
2. │ apple  │      2 │ [1]       │
3. │ banana │      0 │ [1]       │
4. │ banana │      1 │ [0]       │
5. │ cherry │      1 │ [1]       │
6. │ cherry │      2 │ [0]       │
   └────────┴────────┴───────────┘
```
