Позволяет выполнять `SELECT`-запросы к документам индекса в [Elasticsearch](https://www.elastic.co/elasticsearch). Каждый документ возвращается в виде одной строки: его поле `_source` представлено одним столбцом типа [JSON](/ru/reference/data-types/newjson), а идентификатор документа и имя индекса доступны в виде виртуальных столбцов. Функция работает только в режиме чтения.

## Синтаксис {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  Интеграция с Elasticsearch является экспериментальной. Чтобы её включить, используйте настройку [`enable_elasticsearch`](/ru/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## Аргументы {#arguments}

| Аргумент       | Описание                                                                                                                                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | Базовый URL кластера Elasticsearch, например `https://localhost:9200`. Это должен быть URL со схемой `http` или `https` без учётных данных, строки запроса и фрагмента.                                                                                           |
| `index`        | Индекс для чтения. Также можно указать псевдоним, список через запятую или подстановочный шаблон — в том виде, в каком их принимает API point in time Elasticsearch. Если шаблону не соответствует ни один индекс, возникает ошибка.                              |
| `user`         | Имя пользователя для базовой HTTP-аутентификации (необязательный).                                                                                                                                                                                                |
| `password`     | Пароль для базовой HTTP-аутентификации (необязательный, требует указания `user`).                                                                                                                                                                                 |
| `query('...')` | Объект [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) Elasticsearch в формате JSON, определяющий, какие документы читать (необязательный). Указывается после позиционных аргументов. По умолчанию: `{"match_all": {}}`. |

Аргументы `url`, `index`, `user` и `password` также можно задавать в форме `key = value`. Позиционные аргументы заполняют эти позиции в указанном порядке; если аргумент указан одновременно позиционно и как ключ (или один и тот же ключ указан дважды), возникает ошибка.

Следующие аргументы можно указывать в форме `key = value` (или как ключи именованной коллекции):

| Ключ           | Описание                                                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | Имя пользователя для базовой HTTP-аутентификации.                                                                                                                                       |
| `password`     | Пароль для базовой HTTP-аутентификации.                                                                                                                                                 |
| `bearer_token` | Токен, передаваемый в заголовке `Authorization: Bearer <token>`, например токен служебной учётной записи Elasticsearch.                                                                 |
| `api_key`      | Ключ API Elasticsearch, передаваемый в заголовке `Authorization: ApiKey <api_key>`. Значение — закодированная в base64 строка `id:api_key`, которую возвращает API создания ключей API. |

Именованная коллекция может содержать ключ `query`. Чтобы переопределить его, передайте `query('...')` или `query = '...'` после имени коллекции.

Кроме того, табличная функция принимает:

| Ключ        | Описание                                                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `structure` | Структура таблицы в форме `'name JSON'`. Структура должна содержать ровно один столбец типа `JSON`; имена `_id` и `_index` зарезервированы. По умолчанию: `'document JSON'`. |

Настройки чтения `keep_alive` и `page_size` можно передать в концевом предложении `SETTINGS`; их описание см. в разделе [движок таблицы `Elasticsearch`](/ru/reference/engines/table-engines/integrations/elasticsearch#creating-a-table).

## Аутентификация {#authentication}

Можно указать не более одного метода аутентификации:

1. **Базовая аутентификация**. Передайте `user` и `password`.
2. **Bearer-токен**. Передайте `bearer_token`.
3. **Ключ API**. Передайте `api_key`.

Если ни один из них не указан, запрос отправляется анонимно — это работает, только если в Elasticsearch отключены механизмы безопасности.

Храните учётные данные в [именованной коллекции](/ru/concepts/features/configuration/server-config/named-collections), чтобы не указывать их в каждом запросе. Постоянная таблица, созданная на основе именованной коллекции (с движком таблицы `Elasticsearch` или с помощью `CREATE TABLE ... AS elasticsearch(...)`), регистрируется как зависимость коллекции, поэтому `DROP NAMED COLLECTION` блокируется, пока эта таблица существует.

## Виртуальные столбцы {#virtual-columns}

* `_id` — идентификатор документа. Тип: `String`.
* `_index` — имя индекса, из которого был прочитан документ. Тип: `LowCardinality(String)`.

Если запрос читает только виртуальные столбцы, поле `_source` документа не запрашивается из Elasticsearch. Индекс, в котором не хранится `_source` (поле `_source` отключено в его сопоставлении), можно читать только через виртуальные столбцы: запрос, читающий `JSON`-столбец из такого индекса, завершится ошибкой, а не вернёт пустые документы.

## Примеры {#examples}

Подсчёт количества документов в индексе:

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

Прочитаем поля документов как подстолбцы `JSON`-столбца:

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

Отфильтруйте данные на стороне Elasticsearch с помощью объекта Query DSL и настройте размер страницы:

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

Использование именованной коллекции:

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## Ограничения {#limitations}

* Функция работает только в режиме чтения; `INSERT` не поддерживается.
* Предикаты не проталкиваются. Условие в предложении `WHERE` применяется в ClickHouse уже после загрузки документов; чтобы фильтровать данные на стороне Elasticsearch, используйте аргумент `query`.
* `query` отправляется с `size`, равным размеру страницы. Запрос, результат которого зависит от `size` (например, запрос `knn` без `k`), возвращает набор документов, зависящий от `page_size`. Указывайте такие параметры явно.
* Каждая страница запрашивается отдельным поисковым запросом, и Elasticsearch заново вычисляет выражения с датами, такие как `now-1h`, в `query` для каждого запроса. Момент времени (point in time) фиксирует набор документов, но не время, поэтому `query`, зависящий от времени, может незаметно пропускать документы вблизи смещающейся границы. Используйте в `query` абсолютные даты.
* При каждом чтении открывается момент времени (point in time), результаты постранично перебираются с помощью `search_after` с сортировкой по `_shard_doc`, а в конце момент времени закрывается. Если запрос страницы завершается сбоем на каком-либо сегменте или превышает тайм-аут в Elasticsearch, возникает ошибка — частичные результаты не возвращаются.
* Требуется Elasticsearch 7.12 или новее: функция использует API point in time и поле сортировки `_shard_doc`, поэтому более старые версии и OpenSearch отклоняют первый же запрос.
* `page_size` не может превышать значение настройки индекса `index.max_result_window` в Elasticsearch (по умолчанию `10000`).
