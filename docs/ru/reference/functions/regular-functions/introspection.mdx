Вы можете использовать функции, описанные в этой главе, для интроспекции [ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format) и [DWARF](https://en.wikipedia.org/wiki/DWARF) при профилировании запросов.

<Note>
  Эти функции работают медленно и могут создавать риски для безопасности.
</Note>

Для корректной работы функций интроспекции:

* Установите пакет `clickhouse-common-static-dbg`.

* Установите значение настройки [allow&#95;introspection&#95;functions](/ru/reference/settings/session-settings/allow#allow_introspection_functions) равным 1.

  По соображениям безопасности функции интроспекции по умолчанию отключены.

ClickHouse сохраняет отчёты профилировщика в системную таблицу [trace&#95;log](/ru/reference/system-tables/trace_log). Убедитесь, что таблица и профилировщик настроены правильно.

## addressToLine {#addressToLine}

Добавлено в: v20.1.0

Преобразует адрес инструкции в основном исполняемом файле ClickHouse в имя файла и номер строки в исходном коде ClickHouse.

Адрес должен быть смещением внутри основного исполняемого файла ClickHouse — именно в таком виде адреса хранятся в столбцах `trace` таблиц `system.trace_log`, `system.stack_trace` и `system.crash_log`, а также в столбце `last_error_trace` таблицы `system.error_log`.
Адреса среды выполнения (адреса виртуальной памяти) не принимаются, чтобы с помощью функции нельзя было узнать структуру памяти процесса сервера.
Кадры стека за пределами основного исполняемого файла хранятся как `0`, и для них функция возвращает пустой результат.

<Note>
  Эта функция работает медленно и может представлять риск для безопасности.
</Note>

Чтобы включить эту функцию интроспекции:

* Установите пакет `clickhouse-common-static-dbg`.
* Задайте для настройки [`allow_introspection_functions`](/ru/reference/settings/session-settings/allow#allow_introspection_functions) значение `1`.

<Note>
  Эта функция недетерминирована: для одних и тех же аргументов она может возвращать разные результаты.
</Note>

**Синтаксис**

```sql
addressToLine(address_of_binary_instruction)
```

**Аргументы**

* `address_of_binary_instruction` — смещение инструкции в основном исполняемом файле ClickHouse, хранящееся в столбце `trace` таблицы `system.trace_log` и аналогичных таблиц. [`UInt64`](/ru/reference/data-types/int-uint)

**Возвращаемое значение**

Возвращает имя файла исходного кода и номер строки, разделённые двоеточием, например `/build/obj-x86_64-linux-gnu/../src/Common/ThreadPool.cpp:199`. Если для адреса не удалось найти отладочную информацию, возвращает имя бинарного файла, а для `0` — пустую строку. [`String`](/ru/reference/data-types/string)

**Примеры**

**Выборка первой строки из системной таблицы `trace_log`**

```sql title=Query
SELECT * FROM system.trace_log LIMIT 1 FORMAT Vertical;
```

## addressToLineWithInlines {#addressToLineWithInlines}

Добавленный в: v22.2.0

Похожа на `addressToLine`, но возвращает Array со всеми встраиваемыми функциями.
Поэтому она работает медленнее, чем `addressToLine`.

Адрес должен быть смещением внутри основного исполняемого файла ClickHouse — именно в таком виде адреса хранятся в столбцах `trace` таблиц `system.trace_log`, `system.stack_trace` и `system.crash_log`, а также в столбце `last_error_trace` таблицы `system.error_log`.
Адреса среды выполнения (адреса виртуальной памяти) не принимаются, чтобы с помощью функции нельзя было узнать структуру памяти процесса сервера.
Кадры стека за пределами основного исполняемого файла хранятся как `0`, и для них функция возвращает пустой результат.

Чтобы включить эту функцию интроспекции:

* Установите пакет `clickhouse-common-static-dbg`.
* Установите значение `1` для настройки [`allow_introspection_functions`](/ru/reference/settings/session-settings/allow#allow_introspection_functions).

<Note>
  Эта функция недетерминированная: она может возвращать разные результаты для одних и тех же аргументов.
</Note>

**Синтаксис**

```sql
addressToLineWithInlines(address_of_binary_instruction)
```

**Аргументы**

* `address_of_binary_instruction` — Смещение инструкции внутри основного исполняемого файла ClickHouse, как оно хранится в столбце `trace` таблицы `system.trace_log` и аналогичных таблиц. [`UInt64`](/ru/reference/data-types/int-uint)

**Возвращаемое значение**

Возвращает массив, первый элемент которого содержит имя файла исходного кода и номер строки, разделённые двоеточием. Второй, третий и последующие элементы содержат имена файлов исходного кода, номера строк и имена встраиваемых функций. Если отладочную информацию найти не удалось, возвращается массив с единственным элементом — именем бинарного файла; для `0` возвращается пустой массив. [`Array(String)`](/ru/reference/data-types/array)

## addressToSymbol {#addressToSymbol}

Добавлено в: v20.1.0

Преобразует адрес инструкции внутри основного исполняемого файла ClickHouse в символ из объектных файлов ClickHouse.

Адрес должен быть смещением внутри основного исполняемого файла ClickHouse — именно в таком виде адреса хранятся в столбцах `trace` таблиц `system.trace_log`, `system.stack_trace` и `system.crash_log`, а также в столбце `last_error_trace` таблицы `system.error_log`.
Адреса среды выполнения (адреса виртуальной памяти) не принимаются, чтобы с помощью функции нельзя было выяснить структуру памяти процесса сервера.
Кадры стека вне основного исполняемого файла хранятся как `0`, и для них функция возвращает пустой результат.

<Note>
  Эта функция недетерминирована: она может возвращать разные результаты для одних и тех же аргументов.
</Note>

**Синтаксис**

```sql
addressToSymbol(address_of_binary_instruction)
```

**Аргументы**

* `address_of_binary_instruction` — смещение инструкции в основном исполняемом файле ClickHouse, хранящееся в столбце `trace` таблицы `system.trace_log` и подобных таблиц. [`UInt64`](/ru/reference/data-types/int-uint)

## demangle {#demangle}

Добавленный в: v20.1.0

Преобразует символ в имя функции на C++.
Обычно этот символ возвращает функция `addressToSymbol`.

**Синтаксис**

```sql

```

* `symbol` — символ из объектного файла. [`String`](/ru/reference/data-types/string)

## getQueryProfileEvent {#getQueryProfileEvent}

Добавлено в: v26.11.0

Возвращает текущее значение [события профилирования](/ru/reference/system-tables/events) для текущего запроса.

Значение суммируется по всем потокам, выполняющим запрос, так же как в столбце `ProfileEvents` таблицы `system.query_log`.
Функция недетерминирована: она вычисляется один раз для каждого [блока](/ru/resources/develop-contribute/introduction/architecture#block) данных во время выполнения запроса,
поэтому все строки одного блока получают одно и то же значение, а само значение растёт по мере выполнения запроса.
Это позволяет дополнять вывод или вставляемые данные сведениями о ходе выполнения запроса, например о количестве строк или байтов, прочитанных к текущему моменту.

При распределённом запросе каждый сервер возвращает значение для своей части запроса.
Некоторые события, например `RealTimeMicroseconds` или `OSReadBytes`, обновляются лишь периодически, поэтому их значение может отставать от фактического.

<Note>
  Эта функция недетерминирована: она может возвращать разные результаты для одних и тех же аргументов.
</Note>

**Синтаксис**

```sql
getQueryProfileEvent(event_name)
```

**Аргументы**

* `event_name` — имя события профилирования, как в `system.events`. [`const String`](/ru/reference/data-types/string)

**Возвращаемое значение**

Текущее значение события профилирования для текущего запроса. [`UInt64`](/ru/reference/data-types/int-uint)

**Примеры**

**Ход выполнения чтения**

```sql title=Query
SELECT number, getQueryProfileEvent('SelectedRows') AS selected_rows
FROM numbers_mt(10)
SETTINGS max_block_size = 3, max_threads = 1
```

```response title=Response

│      1 │             3 │
│      2 │             3 │
│      3 │             6 │
│      4 │             6 │
```
