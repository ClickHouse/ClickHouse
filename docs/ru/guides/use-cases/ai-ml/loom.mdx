В этом руководстве описывается установка [ClickHouse Loom](https://loom.clickhouse.com/) — MCP-сервера и HTTP API с открытым исходным кодом (Apache-2.0), который предоставляет ИИ-агентам общую долговременную память, поиск по документам со ссылками на источники и индекс кода ваших репозиториев. В итоге Loom будет работать поверх ClickHouse, хранить первую запись в памяти и обслуживать подключённого агента для программирования.

## Перед началом работы {#before-you-begin}

* Docker с Compose 2.20 или новее на Linux `amd64` или `arm64` (Docker Desktop на Apple Silicon тоже подойдёт) и свободный порт 7777.
* ClickHouse для Loom. Стек Loom может запускать собственный контейнер ClickHouse. Если вместо этого вы хотите использовать сервис ClickHouse Cloud или самоуправляемый сервер, потребуются:

  * версия 26.4 или новее (в Cloud учитывается самая старая реплика сервиса);
  * Keeper: в Cloud он уже есть, а на самоуправляемом сервере нужно добавить файл Loom `keeper.xml` в каталог `config.d/` либо раздел `<zookeeper>`, указывающий на ваш Keeper;
  * пользователь с полными правами на `loom.*` и `loom_telemetry.*` (`GRANT ALL` или, в Cloud, `GRANT CURRENT GRANTS`), правом `SELECT` на системные таблицы, из которых читает Loom, и правом `READ ON REMOTE`.

  См. [требования к ClickHouse](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/operations/deployment.md#clickhouse-requirements).

## Как это работает {#how-it-works}

1. Установщик загружает Compose bundle нужного релиза, проверяет его контрольную сумму и запускает сервер Loom и его экстрактор документов из опубликованных образов.
2. Встроенный контейнер ClickHouse запускается с базой данных `loom`. Если используется собственный ClickHouse, установщик создаёт её сам или выводит SQL-запрос, который должен выполнить администратор. Loom создаёт свои таблицы при первом запуске. Воспоминания, документы и индекс кода хранятся в них как обычные таблицы.
3. Агенты читают и записывают данные через MCP или HTTP API. Python SDK, TypeScript SDK, а также плагины Claude Code и Codex используют тот же API.

## Установка Loom {#install-loom}

<Steps>
  <Step title="Запустите установщик" id="run-the-installer">
    Запускайте его из домашнего каталога или другого каталога, доступного для записи только вам: перед запуском установщик сохраняет туда `loom-install.sh`.

    <Tabs>
      <Tab title="Встроенный ClickHouse" id="bundled-clickhouse">
        Стек запускает собственный контейнер ClickHouse:

        ```bash
        curl -fsSL https://github.com/ClickHouse/loom/releases/latest/download/install.sh -o loom-install.sh \
          && sh loom-install.sh && rm loom-install.sh
        ```
      </Tab>

      <Tab title="ClickHouse Cloud" id="clickhouse-cloud">
        Создайте для Loom отдельного пользователя в своем сервисе (не `default`) и добавьте IP-адрес хоста Loom в IP Access List сервиса. Передайте установщику URL сервиса. Если пароль не указан ни в URL, ни в `LOOM_CH_PASSWORD`, установщик запросит его. Затем он создаст базу данных `loom` и пользователя с доступом только на чтение. Если у пользователя недостаточно прав, установщик выведет SQL-запросы, которые вместо этого должен выполнить администратор:

        ```bash
        curl -fsSL https://github.com/ClickHouse/loom/releases/latest/download/install.sh -o loom-install.sh \
          && sh loom-install.sh --clickhouse https://loom@<service-host>:8443 \
          && rm loom-install.sh
        ```

        Для развертывания в Kubernetes с ClickHouse Cloud и ClickHouse Managed Postgres воспользуйтесь руководством [ClickHouse Cloud и Managed Postgres](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/operations/clickhouse-cloud.md).
      </Tab>

      <Tab title="Самостоятельно управляемый ClickHouse" id="self-managed-clickhouse">
        Передайте URL своего сервера; установщик работает так же, как на вкладке Cloud. Для `http://` по умолчанию используется порт 8123. Сервер, запущенный на самом Docker-хосте, доступен по адресу `host.docker.internal`, поскольку `localhost` внутри контейнера Loom указывает на сам контейнер:

        ```bash
        curl -fsSL https://github.com/ClickHouse/loom/releases/latest/download/install.sh -o loom-install.sh \
          && sh loom-install.sh --clickhouse http://loom@host.docker.internal:8123 && rm loom-install.sh
        ```
      </Tab>
    </Tabs>

    Установщик ждет, пока `http://localhost:7777/v1/health` не вернет `status` `ok`. Такая установка рассчитана на одного пользователя: вход в систему не требуется, доступ возможен только с localhost, а по умолчанию используется пространство имен `dev/local`, поэтому вызовам MCP и SDK token не нужен. В командном развертывании включается вход в систему, а каждому агенту выдается token с привилегиями на пространства имен; см. [Режимы идентичности](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/operations/deployment.md#identity-modes).
  </Step>

  <Step title="Сохраните и извлеките запись памяти" id="save-and-recall">
    ```bash
    curl -sX POST http://localhost:7777/v1/memory.set -H 'Content-Type: application/json' \
      -d '{"org":"dev","namespace":"local","agent":"quickstart",
           "memory_key":"deploy_window","value":"Tue and Thu only; never Friday."}'
    curl -sX POST http://localhost:7777/v1/memory.get -H 'Content-Type: application/json' \
      -d '{"org":"dev","namespace":"local","agent":"quickstart","memory_key":"deploy_window"}'
    ```

    Ответ `memory.get` содержит `found: true` и `value` в том виде, в каком оно было записано.
  </Step>

  <Step title="Подключите агента для программирования" id="connect-a-coding-agent">
    <Tabs>
      <Tab title="Claude Code" id="claude-code">
        ```bash
        claude plugin marketplace add ClickHouse/loom
        claude plugin install loom@loom
        ```

        Когда Claude Code запросит настройки плагина, оставьте URL сервера по умолчанию, а поле token — пустым.
      </Tab>

      <Tab title="Codex" id="codex">
        ```bash
        codex plugin marketplace add ClickHouse/loom
        codex plugin add loom@loom
        ```

        Затем один раз запустите `codex` в интерактивном режиме и одобрите хуки плагина: до этого инструменты работают, но данные не сохраняются.
      </Tab>

      <Tab title="Cursor" id="cursor">
        Добавьте эту запись в `~/.cursor/mcp.json` и перезапустите Cursor:

        ```json
        { "mcpServers": { "loom": { "url": "http://localhost:7777/mcp?toolset=coding" } } }
        ```
      </Tab>
    </Tabs>
  </Step>
</Steps>

## Рекомендуемые практики {#best-practices}

### Выделите каждой команде собственное пространство имён {#namespace-per-team}

Воспоминания, документы и привилегии существуют в рамках пространства имён. Агенты, которые должны обмениваться полученными знаниями, записывают данные в одно и то же пространство имён; token ограничивают каждого агента теми пространствами имён, в которых ему разрешены чтение и запись. См. [token и привилегии](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/guides/tokens-and-grants.md).

### Настройка провайдера LLM для извлечения данных и формирования ответов {#configure-an-llm}

В релизной сборке стек создаёт эмбеддинги с помощью локальной модели на CPU и использует LLM-заглушку, поэтому извлечение данных, сводки и `memory.ask` не дают осмысленных результатов, пока провайдер моделей не задан на панели мониторинга в разделе **Settings → Models &amp; keys**. Одного ключа OpenAI достаточно и для модели, и для векторных представлений; для Anthropic требуется отдельный провайдер эмбеддингов. См. [Модели и ключи](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/getting-started/models-and-keys.md).

## Устранение неполадок {#troubleshooting}

<Accordion title="Установщик останавливается на проверке ClickHouse">
  Для Loom требуются ClickHouse версии 26.4 или новее, Keeper, а также привилегии, перечисленные в разделе [Перед началом работы](#before-you-begin). Если на самоуправляемом сервере нет Keeper, добавьте его или запустите установщик с флагом `--bundled`, чтобы использовать собственный ClickHouse из стека. Команда `docker compose --project-directory "$HOME/.loom" run --rm loom loom ch-setup --print-sql` выводит SQL-запросы для администратора, не подключаясь к серверу.
</Accordion>

<Accordion title="Loom не переходит в работоспособное состояние">
  Просмотрите журналы с помощью команды `docker compose --project-directory "$HOME/.loom" logs --tail 100 loom clickhouse`. В разделе [Устранение неполадок](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/operations/troubleshooting.md) для каждой проблемы описаны симптомы, проверка, позволяющая её подтвердить, и способ устранения.
</Accordion>

## Часто задаваемые вопросы {#faq}

<Accordion title="Запускает ли Loom агентов?">
  Нет. Loom хранит, ранжирует и извлекает контекст для агентов, но не является фреймворком для агентов.
</Accordion>

<Accordion title="Можно ли хранить актуальную память в Postgres?">
  Да. При первом запуске новое развертывание может выбрать Postgres в качестве источника истины для актуальной памяти и текущих версий (heads) документов базы знаний, при этом векторы, поиск и история остаются в ClickHouse. См. [Postgres](https://github.com/ClickHouse/loom/blob/v1.2.0/docs/operations/postgres.md).
</Accordion>
