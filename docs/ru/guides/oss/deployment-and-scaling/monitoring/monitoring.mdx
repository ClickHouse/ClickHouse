<Note>
  Данные мониторинга, описанные в этом руководстве, доступны в ClickHouse Cloud. Помимо встроенной панели мониторинга, описанной ниже, базовые и расширенные метрики производительности также можно просматривать напрямую в основной консоли сервиса.
</Note>

Вы можете отслеживать:

* Степень использования аппаратных ресурсов.
* Метрики сервера ClickHouse.

## Встроенная расширенная панель обсервабилити {#built-in-advanced-observability-dashboard}

<div className="ch-image-md">
  <Frame>
    ![Встроенная расширенная панель обсервабилити](/images/cloud/manage/monitoring/native_advanced_dashboard.webp)
  </Frame>
</div>

В ClickHouse есть встроенная расширенная панель обсервабилити, доступная по адресу `$HOST:$PORT/dashboard` (требуются имя пользователя и пароль), где отображаются следующие метрики:

* Запросов в секунду
* Использование CPU (ядра)
* Выполняющиеся запросы
* Активные слияния
* Выбранные байты в секунду
* Ожидание ввода-вывода
* Ожидание CPU
* Использование CPU ОС (пользовательское пространство)
* Использование CPU ОС (ядро)
* Чтение с диска
* Чтение из файловой системы
* Память (отслеживаемая)
* Вставленные строки в секунду
* Общее количество частей MergeTree
* Максимум частей в партиции

ClickHouse также самостоятельно отслеживает состояние аппаратных ресурсов, например:

* Нагрузку и температуру процессоров.
* Использование системы хранения, оперативной памяти и сети.

Эти данные собираются в таблице `system.asynchronous_metric_log`.

## Метрики сервера ClickHouse {#clickhouse-server-metrics}

Сервер ClickHouse имеет встроенные средства для мониторинга собственного состояния.

Для отслеживания событий сервера используйте серверный журнал. См. раздел [logger](/ru/reference/settings/server-settings/settings/other#logger) файла конфигурации.

ClickHouse собирает:

* Различные метрики использования сервером вычислительных ресурсов.
* Общую статистику обработки запросов.

Метрики доступны в таблицах [system.metrics](/ru/reference/system-tables/metrics), [system.events](/ru/reference/system-tables/events) и [system.asynchronous&#95;metrics](/ru/reference/system-tables/asynchronous_metrics).

ClickHouse можно настроить на экспорт метрик в [Graphite](https://github.com/graphite-project). См. [раздел Graphite](/ru/reference/settings/server-settings/settings/graphite#graphite) в файле конфигурации сервера ClickHouse. Перед настройкой экспорта метрик необходимо установить Graphite в соответствии с официальным [руководством](https://graphite.readthedocs.io/en/latest/install.html).

ClickHouse можно настроить на экспорт метрик в [Prometheus](https://prometheus.io). См. [раздел Prometheus](/ru/reference/settings/server-settings/settings/other#prometheus) в файле конфигурации сервера ClickHouse. Перед настройкой экспорта метрик необходимо установить Prometheus в соответствии с официальным [руководством](https://prometheus.io/docs/prometheus/latest/installation/).

Кроме того, доступность сервера можно отслеживать через HTTP API. Отправьте запрос `HTTP GET` на `/ping`. Если сервер доступен, он возвращает `200 OK`.

Для мониторинга серверов в конфигурации кластера необходимо задать параметр [max&#95;replica&#95;delay&#95;for&#95;distributed&#95;queries](/ru/reference/settings/session-settings/max#max_replica_delay_for_distributed_queries) и использовать HTTP-ресурс `/replicas_status`. Запрос к `/replicas_status` возвращает `200 OK`, если реплика доступна и не отстаёт от других реплик. Если реплика отстаёт, возвращается `503 HTTP_SERVICE_UNAVAILABLE` с информацией о величине отставания.
