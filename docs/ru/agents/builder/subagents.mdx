Субагент — это дочерний агент, которого родительский агент вызывает для выполнения автономной подзадачи. Дочерний агент работает в собственном контекстном окне и с собственным набором подключённых инструментов, а затем возвращает родительскому агенту компактный результат. Родительский агент не видит промежуточных шагов дочернего агента — только итоговый ответ.

Используйте субагентов, чтобы родительский агент не отвлекался от своей задачи. Длительные исследовательские проходы, исследование с активным использованием инструментов и специализированные шаги проверки работают эффективнее, если их промежуточное состояние, занимающее много токенов, не попадает в контекст родительского агента.

## Включение субагентов {#enable-subagents}

В Конструкторе агентов откройте **Расширенные настройки** и включите переключатель **Субагенты**. Появятся ещё два элемента управления:

* **Allow self-spawn** — если параметр включён, агент может порождать собственные копии для параллельной работы. Полезно для сценариев fan-out (один родительский агент и несколько идентичных воркеров).
* **Additional subagents** — выберите других агентов, которым этот родительский агент может делегировать работу. Во время выполнения родительский агент сам решает, исходя из задачи, какого субагента вызвать и нужно ли вызывать его вообще.

Нажмите «Сохранить». Теперь при запуске агенту будет доступен новый инструмент для вызова субагентов.

## Когда полезен субагент {#when-a-subagent-helps}

* **Исследовательские подзадачи** — родительский агент разбивает сложный вопрос на части, передаёт каждую из них субагенту, специализирующемуся на этой части, и обобщает полученные ответы.
* **Этапы с активным использованием инструментов** — сеансы интерпретатора кода, многошаговые циклы веб-поиска и любые другие операции, которые засорили бы контекст родительского агента промежуточным выводом инструментов.
* **Специализированная проверка** — один агент генерирует результат, другой его проверяет, при этом весь ход рассуждений проверяющего остаётся в его собственном контекстном окне.

Не используйте субагентов для тривиальных вызовов: передача задачи увеличивает задержку и расход токенов.

## Субагенты и цепочка агентов {#subagents-vs-agent-chain}

Субагенты — это механизм делегирования во время выполнения: родительский агент принимает решения на лету. Цепочка агентов — это заранее заданный граф агентов, которые выполняются в фиксированном порядке. Если маршрутизация динамическая, используйте субагентов, а если фиксированная — цепочку.

## Ограничения {#limits}

* Не более **10** субагентов в списке одного родительского агента.
* Максимальная глубина вложенности — **5** переходов от корневого агента.
* Не более **50** уникальных целевых субагентов, загружаемых за один запуск.
* Не более **100** развёрнутых конфигураций субагентов на один запрос.

Субагенты, на которые вы ссылаетесь, должны быть доступны пользователю, запускающему родительского агента. Ссылки на недоступного или удалённого агента пропускаются без предупреждения, поэтому проектируйте родительских агентов так, чтобы они корректно обрабатывали отсутствие дочернего агента.
