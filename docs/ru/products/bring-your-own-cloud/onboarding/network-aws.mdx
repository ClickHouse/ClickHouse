ClickHouse BYOC на AWS поддерживает два варианта приватного подключения: пиринг VPC и AWS PrivateLink.

<div id="common-prerequisites">
  ## Предварительные требования {#common-prerequisites}
</div>

Общие шаги, необходимые как для пиринга VPC, так и для PrivateLink.

### Включите приватный балансировщик нагрузки для ClickHouse BYOC {#step-enable-private-load-balancer-for-clickhouse-byoc}

В консоли ClickHouse Cloud включите **приватный балансировщик нагрузки** для инфраструктуры BYOC.

## Настройка пиринга VPC {#aws-vpc-peering}

Чтобы создать или удалить пиринг VPC для ClickHouse BYOC, выполните следующие действия:

<Steps>
  <Step title="Создайте пиринговое соединение" id="step-1-create-a-peering-connection">
    1. Перейдите в панель мониторинга VPC в аккаунте ClickHouse BYOC.
    2. Выберите Пиринговые соединения.
    3. Нажмите Создать пиринговое соединение.
    4. Укажите идентификатор VPC ClickHouse в поле VPC Requester.
    5. Укажите идентификатор целевой VPC в поле VPC Accepter. (При необходимости выберите другой аккаунт)
    6. Нажмите Создать пиринговое соединение.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Создание пирингового соединения](/images/cloud/reference/byoc-vpcpeering-1.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Примите запрос на пиринговое соединение" id="step-2-accept-the-peering-connection-request">
    Перейдите в аккаунт, с которым настраивается пиринг; на странице (VPC -&gt; Пиринговые соединения -&gt; Actions -&gt; Accept request) можно одобрить этот запрос на пиринг VPC.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Принятие пирингового соединения](/images/cloud/reference/byoc-vpcpeering-2.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Добавьте пункт назначения в таблицы маршрутизации ClickHouse VPC" id="step-3-add-destination-to-clickhouse-vpc-route-tables">
    В аккаунте ClickHouse BYOC,

    1. Выберите Таблицы маршрутизации в панели мониторинга VPC.
    2. Найдите идентификатор VPC ClickHouse. Измените каждую таблицу маршрутизации, связанную с частными подсетями.
    3. Нажмите кнопку Edit на вкладке Routes.
    4. Нажмите Add another route.
    5. Введите CIDR-диапазон целевой VPC в поле Destination.
    6. Выберите “Пиринговое соединение” и ID пирингового соединения в поле Target.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Добавление таблицы маршрутизации](/images/cloud/reference/byoc-vpcpeering-3.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Добавьте пункт назначения в таблицы маршрутизации целевой VPC" id="step-4-add-destination-to-the-target-vpc-route-tables">
    В AWS-аккаунте, с которым настраивается пиринг,

    1. Выберите Таблицы маршрутизации в панели мониторинга VPC.
    2. Найдите идентификатор целевой VPC.
    3. Нажмите кнопку Edit на вкладке Routes.
    4. Нажмите Add another route.
    5. Введите CIDR-диапазон ClickHouse VPC в поле Destination.
    6. Выберите “Пиринговое соединение” и ID пирингового соединения в поле Target.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Добавление таблицы маршрутизации](/images/cloud/reference/byoc-vpcpeering-4.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Измените группу безопасности, чтобы разрешить доступ из пиринговой VPC" id="step-5-edit-security-group-to-allow-peered-vpc-access">
    В аккаунте ClickHouse BYOC нужно обновить настройки группы безопасности, чтобы разрешить трафик из вашей пиринговой VPC. Обратитесь в службу поддержки ClickHouse, чтобы запросить добавление правил входящего трафика, включающих CIDR-диапазоны вашей пиринговой VPC.

    ***

    Теперь сервис ClickHouse должен быть доступен из пиринговой VPC.
  </Step>
</Steps>

Для частного доступа к ClickHouse подготавливаются приватный балансировщик нагрузки и конечная точка для безопасного подключения из пиринговой VPC пользователя. Частная конечная точка использует формат публичной конечной точки с суффиксом `-private`. Например:

* **Публичная конечная точка**: `h5ju65kv87.mhp0y4dmph.us-west-2.aws.clickhouse-byoc.com`
* **Частная конечная точка**: `h5ju65kv87-private.mhp0y4dmph.us-west-2.aws.clickhouse-byoc.com`

При необходимости, после того как вы убедитесь, что пиринг работает, можно запросить удаление публичного балансировщика нагрузки для ClickHouse BYOC.

<div id="setup-privatelink">
  ## Настройка PrivateLink {#setup-privatelink}
</div>

AWS PrivateLink обеспечивает безопасное приватное подключение к вашим сервисам ClickHouse BYOC без пиринга VPC или интернет-шлюзов. Весь трафик проходит внутри сети AWS и никогда не выходит в публичный интернет.

<Note>
  **Межрегиональные подключения.** Переключатель **Enable private link** в консоли ClickHouse создаёт сервис конечной точки и действует только для потребителей **в том же регионе**. AWS по умолчанию отключает межрегиональный доступ к сервисам конечных точек, а консоль ClickHouse не управляет этой настройкой. Если ваши клиенты находятся в другом регионе, включите его самостоятельно: сервис конечной точки находится в вашем аккаунте BYOC, поэтому добавьте регионы потребителей в список **Supported regions** в своей консоли AWS (см. шаг 3 ниже). ClickHouse не будет изменять или сбрасывать эти значения. Применяются тарифы AWS на межрегиональную передачу данных.
</Note>

<Steps>
  <Step title="Включите Private Link в Консоли ClickHouse" id="step-1-enable-private-link">
    <Note>
      Предварительно убедитесь, что **частный балансировщик нагрузки** включён.
    </Note>

    <div className="ch-image-md">
      <Frame>
        ![Включение BYOC PrivateLink](/images/cloud/reference/byoc-privatelink.webp)
      </Frame>
    </div>
  </Step>

  <Step title={<>Получите <code>Service name</code> конечной точки</>} id="step-2-obtain-endpoint-service-name">
    1. В консоли ClickHouse Cloud откройте страницу Settings сервиса, к которому нужно подключиться через PrivateLink.
    2. Нажмите «Set up private endpoint».
    3. В открывшейся выдвижной панели скопируйте значение `Service name`: оно понадобится на следующем шаге. (После включения PrivateLink это значение может сгенерироваться не сразу.)

       <div className="ch-image-md">
         <Frame>
           ![Частные конечные точки](/images/cloud/security/aws-privatelink-pe-create.webp)
         </Frame>
       </div>
  </Step>

  <Step title="Создайте конечную точку в своей сети" id="step-3-create-endpoint">
    1. Откройте **собственную консоль AWS** (т. е. учетную запись AWS, в которой находится ваше клиентское приложение) → VPC → Endpoints → Create endpoints.

    2. Выберите &quot;Endpoint services that use NLBs and GWLBs&quot; и укажите `Service name`, полученное на предыдущем шаге.

    3. Нажмите &quot;Verify service&quot;.

       <div className="ch-image-md">
         <Frame>
           ![Настройки конечной точки AWS PrivateLink](/images/cloud/security/aws-privatelink-endpoint-settings.webp)
         </Frame>
       </div>

    4. (Необязательно) Чтобы установить межрегиональное соединение через PrivateLink, установите флажок &quot;Cross region endpoint&quot; и укажите регион сервиса — регион, в котором создана ваша BYOC infrastructure. Затем:
       1. Откройте **консоль AWS для BYOC** (т. е. учетную запись AWS, в которой создана ваша BYOC infrastructure) → VPC → Endpoint services → `clickhouse-cloud-infra-xxx` → Supported regions.
       2. Добавьте регион, в котором работает ваше клиентское приложение, в список поддерживаемых регионов. По умолчанию поддерживается только регион, в котором развернута данная BYOC infrastructure. Если вы хотите подключаться из разных регионов, можно добавить несколько регионов — ClickHouse не будет изменять или сбрасывать эти значения.

          <div className="ch-image-md">
            <Frame>
              ![Настройки межрегиональной конечной точки AWS PrivateLink](/images/cloud/reference/byoc-privatelink-aws-cross-region.webp)
            </Frame>
          </div>

    5. Выберите VPC и подсети (рекомендуется по одной подсети на каждую зону доступности).

       <div className="ch-image-md">
         <Frame>
           ![Выбор VPC и подсетей](/images/cloud/security/aws-privatelink-select-vpc-and-subnets.webp)
         </Frame>
       </div>

    6. **Важно**: включите &quot;Private DNS names&quot; для конечной точки — без этого частный DNS не будет работать корректно.
       Частный DNS для конечных точек BYOC (в формате `*.vpce.{subdomain}`) использует встроенную функцию AWS PrivateLink &quot;Private DNS names&quot;. Записи Route53 не нужны — разрешение DNS-имён выполняется автоматически, если:
       * включён параметр &quot;Private DNS names&quot; и
       * включён параметр &quot;DNS Hostnames&quot;

         в разделе VPC Settings → DNS resolution and DNS hostnames.

         Благодаря этому соединения через поддомен `vpce` автоматически направляются через конечную точку PrivateLink без дополнительной настройки DNS.

    7. (Необязательно) Назначьте группы безопасности и теги.
       <Note>
         Убедитесь, что в группе безопасности разрешены порты `443`, `8443` и `9440`.
       </Note>

    8. Нажмите &quot;Create endpoint&quot; и дождитесь создания конечной точки.

    9. После создания конечной точки скопируйте значение `Endpoint ID` — оно понадобится на следующем шаге.

       <div className="ch-image-md">
         <Frame>
           ![VPC Endpoint ID](/images/cloud/security/aws-privatelink-vpc-endpoint-id.webp)
         </Frame>
       </div>
  </Step>

  <Step title="Одобрите соединение с конечной точкой" id="step-4-approve-endpoint-connection">
    1. Снова откройте **консоль BYOC VPC** → Endpoint services → `clickhouse-cloud-infra-xxx` → Endpoint connections.
    2. Найдите запрос на соединение, созданный из вашего VPC, и нажмите &quot;Accept endpoint connection request&quot;, чтобы одобрить его.

       <div className="ch-image-md">
         <Frame>
           ![Одобрение запроса BYOC PrivateLink](/images/cloud/reference/byoc-privatelink-2.webp)
         </Frame>
       </div>
  </Step>

  <Step title={<>Добавьте <code>Endpoint ID</code> в список разрешённых для сервиса ClickHouse</>} id="step-5-add-endpoint-id-to-services-allow-list">
    1. В консоли ClickHouse Cloud перейдите на страницу Settings того сервиса, к которому вы хотите подключаться через PrivateLink.
    2. Нажмите &quot;Set up private endpoint&quot;.
    3. В открывшейся выдвижной панели введите `Endpoint ID`, полученный на предыдущем шаге, и при необходимости добавьте описание.
    4. Нажмите &quot;Create endpoint&quot;.

    <Note>
      Чтобы разрешить доступ через уже существующее соединение PrivateLink, выберите его в раскрывающемся списке существующих конечных точек.
      В этом списке отображаются существующие соединения PrivateLink с сервисами в той же инфраструктуре.
    </Note>

    <div className="ch-image-md">
      <Frame>
        ![Фильтр частных конечных точек](/images/cloud/security/aws-privatelink-pe-filters.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Доступ к инстансу через PrivateLink" id="step-6-connect-via-privatelink">
    1. В консоли ClickHouse Cloud перейдите на страницу Settings нужного сервиса.
    2. Нажмите &quot;Set up private endpoint&quot;.
    3. В открывшейся выдвижной панели скопируйте значение `DNS name`.

       <div className="ch-image-md">
         <Frame>
           ![DNS-имя частной конечной точки](/images/cloud/security/aws-privatelink-pe-dns-name.webp)
         </Frame>
       </div>

       Доступ к сервисам ClickHouse через PrivateLink контролируется на двух уровнях:

       1. **Istio Authorization Policy**: политики авторизации на уровне сервиса, которыми ClickHouse управляет в вашей BYOC infrastructure
       2. **Группа безопасности конечной точки VPC**: группа безопасности, подключённая к вашей конечной точке VPC, определяет, какие ресурсы в вашем VPC могут использовать эту конечную точку

       <Note>
         У частного балансировщика нагрузки отключена возможность &quot;Enforce inbound rules on PrivateLink traffic&quot;, поэтому доступ контролируется только политиками авторизации Istio и группой безопасности вашей конечной точки VPC.
       </Note>
  </Step>
</Steps>
