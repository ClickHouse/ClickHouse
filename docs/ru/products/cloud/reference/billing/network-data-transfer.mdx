ClickHouse Cloud учитывает объем входящего и исходящего трафика данных.
Сюда входят любые данные, поступающие в ClickHouse Cloud и выходящие из него, а также любая передача данных внутри региона
и между регионами. Это использование отслеживается на уровне сервиса. На основании
этих показателей клиентам начисляется плата за передачу данных, которая затем добавляется к их
ежемесячному счету.

ClickHouse Cloud взимает плату за:

* Исходящий трафик из ClickHouse Cloud в публичный интернет, в том числе в другие
  регионы других облачных провайдеров.
* Исходящий трафик в другой регион у того же облачного провайдера.

Плата за передачу данных внутри региона, а также за использование Private Link/Private
Service Connect и передачу данных через них не взимается. Однако мы оставляем за собой право вводить
дополнительные параметры тарификации передачи данных, если увидим сценарии использования, которые влияют
на нашу возможность корректно тарифицировать пользователей.

Примечание: за использование Private Link/Private Service Connect взимается плата со стороны Cloud Service Provider (CSP). Актуальную информацию см. на странице цен CSP.

Плата за передачу данных различается в зависимости от Cloud Service Provider (CSP) и региона.
Стоимость исходящего трафика в публичный интернет зависит только от исходного региона.
Стоимость передачи между регионами (или межрегиональной передачи) зависит как от исходного региона, так и от региона пункта назначения.

## Managed Postgres {#managed-postgres}

Исходящий трафик ClickHouse Managed Postgres в публичный интернет и межрегиональный исходящий трафик тарифицируется по ставкам, указанным на этой странице. Передача данных классифицируется по IP-адресу пункта назначения с учётом диапазонов IP-адресов, опубликованных облачным провайдером. Трафик в пункт назначения, IP-адрес которого не входит в опубликованные диапазоны вашего региона, учитывается как исходящий трафик в публичный интернет, даже если этот пункт назначения размещён у того же облачного провайдера — например, peer, использующий собственный блок IP-адресов (BYOIP). Если вы подключаетесь к такому peer, обратитесь в [службу поддержки](https://clickhouse.com/support/program), чтобы мы могли проверить классификацию.

Вычислительные ресурсы [ClickPipes](/ru/products/managed-postgres/clickpipes) предоставляются бесплатно при репликации данных из Managed Postgres в ClickHouse Cloud. Исходящий трафик из Managed Postgres в ClickPipes учитывается так же, как любая другая передача данных: если оба находятся в одном регионе, плата не взимается; межрегиональная репликация тарифицируется по соответствующему межрегиональному уровню, а репликация в сервис ClickHouse Cloud у другого облачного провайдера — по ставке для публичного интернета.

Чтобы снизить затраты на передачу данных, по возможности размещайте приложение и Managed Postgres в одном регионе одного облачного провайдера.

**Рекомендации по минимизации затрат на передачу данных**

Ниже приведены некоторые сценарии, которые стоит учитывать при передаче данных в
ClickHouse Cloud и из него, чтобы минимизировать затраты на передачу данных.

1. При передаче данных в ClickHouse Cloud и из него по возможности используйте сжатие,
   чтобы уменьшить объем передаваемых данных и связанные с этим затраты.

2. Обратите внимание, что при выполнении `INSERT` через собственный протокол с не встроенными в запрос
   значениями (например, `INSERT INTO [TABLE] FROM INFILE [FILE] FORMAT NATIVE`) клиенты ClickHouse
   получают метаданные с серверов, чтобы упаковать данные. Если объем метаданных больше, чем
   полезная нагрузка `INSERT`, с точки зрения сервера вы можете неожиданно увидеть больший исходящий трафик,
   чем входящий. Если это неприемлемо, рассмотрите возможность
   встраивания данных с помощью синтаксиса `VALUES` или использования HTTP-протокола.

В таблицах ниже показано, как различается плата за передачу данных для исходящего трафика через публичный
интернет или межрегионального исходящего трафика в зависимости от облачного провайдера и региона.

  в ClickHouse Cloud вы увидите, что использование передачи данных разбито по уровням.
</Note>
