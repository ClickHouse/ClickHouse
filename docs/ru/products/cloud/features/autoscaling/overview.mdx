Масштабирование — это возможность изменять доступные ресурсы в соответствии с потребностями клиентов. Сервисы уровней Scale и Enterprise можно масштабировать горизонтально, программно вызывая API или меняя настройки в интерфейсе. Сервисы уровня Scale и сервисы уровня Enterprise со стандартными профилями `1:4` также можно **автоматически масштабировать** по вертикали в соответствии с потребностями приложения.

<ScalePlanFeatureBadge feature="Автоматическое вертикальное масштабирование" />

<Note>
  Уровни Scale и Enterprise поддерживают сервисы как с одной, так и с несколькими репликами. Сервисы Scale с одной репликой и сервисы Enterprise со стандартными профилями `1:4` поддерживают вертикальное автомасштабирование в режиме самообслуживания. Для вертикального изменения размера сервисов Enterprise с пользовательскими профилями требуется помощь службы поддержки. Сервисы Scale и Enterprise можно масштабировать горизонтально до нескольких реплик. Сервисы уровня Basic имеют одну реплику, фиксированный размер и не поддерживают ни вертикальное, ни горизонтальное масштабирование. Дополнительные сведения см. в разделе [Крупные сервисы с одной репликой](/ru/products/cloud/features/large-single-replica-services).
</Note>

## Выбор варианта вычислительных ресурсов {#choosing-a-compute-option}

Выберите вариант в зависимости от того, хотите ли вы изменить мощность существующего сервиса, изолировать рабочую нагрузку на выделенных вычислительных ресурсах или временно добавить вычислительные ресурсы для подходящего запроса.

| Вариант                                                                        | Что делает                                                                                                                                                               | Когда использовать                                                                                          |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| Масштабирование существующего сервиса                                          | Вертикальное масштабирование изменяет CPU и объём памяти. Горизонтальное масштабирование изменяет количество реплик — вручную или автоматически, где это поддерживается. | Вы хотите, чтобы существующий сервис увеличивал или уменьшал мощность по мере изменения рабочей нагрузки.   |
| [Хранилища](/ru/products/cloud/features/infrastructure/warehouses)                | Создаёт отдельные сервисы с выделенными вычислительными ресурсами и конечными точками, работающие с одними и теми же данными.                                            | Вам нужна долговременная изоляция вычислительных ресурсов для разных рабочих нагрузок.                      |
| [On-Demand Compute](/ru/products/cloud/features/infrastructure/on-demand-compute) | Временно выделяет воркеров из управляемого пула через существующий сервис и конечную точку.                                                                              | Подходящему `SELECT`-запросу требуются дополнительные вычислительные ресурсы без изменения размера сервиса. |

<Note>
  Поддержка масштабирования зависит от уровня сервиса и профиля. [Горизонтальное автомасштабирование](/ru/products/cloud/features/autoscaling/horizontal-autoscaling) доступно в режиме закрытой предварительной версии. On-Demand Compute также доступен в режиме закрытой предварительной версии и поддерживает только подходящие `SELECT`-запросы.
</Note>

## Как работает масштабирование в ClickHouse Cloud {#how-scaling-works-in-clickhouse-cloud}

ClickHouse Cloud поддерживает ручное горизонтальное масштабирование для сервисов уровней Scale и Enterprise. Сервисы уровня Scale также поддерживают вертикальное автомасштабирование; поддержка вертикального автомасштабирования для сервисов уровня Enterprise зависит от профиля, как описано ниже. [Горизонтальное автомасштабирование](/ru/products/cloud/features/autoscaling/horizontal-autoscaling) доступно в закрытой предварительной версии для сервисов уровней Scale и Enterprise.

Для сервисов уровня Enterprise масштабирование работает следующим образом:

* **Горизонтальное масштабирование**: Ручное горизонтальное масштабирование доступно для всех стандартных и пользовательских профилей на уровне Enterprise.
* **Вертикальное масштабирование**:
  * Стандартные профили `1:4` поддерживают вертикальное автомасштабирование.
  * Пользовательские профили (`highMemory` и `highCPU`) не поддерживают вертикальное автомасштабирование и ручное вертикальное масштабирование. Однако для таких сервисов вертикальное масштабирование возможно через обращение в поддержку.

<Note>
  В ClickHouse Cloud масштабирование выполняется по модели [&quot;Make Before Break&quot; (MBB)](/ru/products/cloud/features/autoscaling/make-before-break).
  Сначала добавляется одна или несколько реплик нового размера, и только потом удаляются старые, что позволяет избежать потери производительности во время масштабирования.
  Благодаря отсутствию разрыва между удалением существующих реплик и добавлением новых MBB делает процесс масштабирования более плавным и менее disruptive.
  Это особенно полезно при масштабировании вверх, когда высокая загрузка ресурсов требует дополнительной мощности, поскольку преждевременное удаление реплик только усугубило бы нехватку ресурсов.
  В рамках этого подхода мы ждем до одного часа, чтобы все текущие запросы на старых репликах успели завершиться, прежде чем удалять их.
  Это позволяет, с одной стороны, дождаться завершения текущих запросов, а с другой — не допустить, чтобы старые реплики оставались слишком долго.
</Note>
