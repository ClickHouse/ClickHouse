ClickHouse Cloud анализирует ваш трафик запросов и схемы таблиц и формирует рекомендации по повышению производительности. Проверки детерминированы, не используют LLM и не выполняются на ваших сервисах.

Рекомендации бывают двух видов:

* Рекомендации по схеме отображаются в разделе **Мониторинг** &gt; **Tables** и касаются изменений, которые можно внести в схемы ваших таблиц.
* Рекомендации по запросам отображаются в разделе **Мониторинг** &gt; **Query performance** при открытии запроса и касаются изменений, которые можно внести в ваши запросы.
  Некоторые рекомендации по схеме и по запросам могут пересекаться, предлагая разные способы решения проблемы — через шаблон запроса или через схему таблицы.

<Warning>
  Рекомендации доступны в предварительной версии. Они могут изменяться, и на них не распространяется стандартное SLA ClickHouse Cloud.
</Warning>

## Рекомендации по схеме {#schema-recommendations}

Они отображаются для таблицы в разделе [Мониторинг](/ru/products/cloud/features/monitoring/cloud-console).

| Рекомендация             | Когда появляется                                                                          | Что делать                                                                                                                                                                                                                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Изменить ключ сортировки | Многие запросы фильтруют по одним и тем же столбцам, которые не входят в ключ сортировки. | Рассмотрите возможность изменить ключ сортировки так, чтобы типичные фильтры соответствовали ключу. Это приведёт к перестроению таблицы. [Schema Advisor](/ru/products/cloud/features/ai-ml/schema-advisor) может спланировать и развернуть это изменение.                                         |
| Добавить проекцию        | Многие запросы фильтруют по небольшому набору столбцов, не входящих в ключ сортировки.    | Добавьте [проекцию](/ru/data-modeling/projections) по этим столбцам. Это ускорит такие запросы без изменения ключа сортировки. [Schema Advisor](/ru/products/cloud/features/ai-ml/schema-advisor) применяет это изменение на месте с помощью `ALTER TABLE`, без перестроения и без `EXCHANGE TABLES`. |
| Использовать словарь     | Большинство запросов к таблице — это поиск одной строки.                                  | Для таблицы измерений, которая часто читается и редко обновляется, рассмотрите использование [словаря](/ru/sql-reference/statements/create/dictionary).                                                                                                                                            |
| Пакетные вставки         | В таблицу поступает много небольших вставок, которые создают много небольших частей.      | Объединяйте вставки в пакеты, чтобы каждая часть была крупнее. Чем меньше частей, тем меньше работы по слиянию. См. [асинхронные вставки](/ru/optimize/asynchronous-inserts).                                                                                                                      |

## Рекомендации по запросам {#query-recommendations}

Они отображаются, когда вы открываете нормализованный запрос в разделе **Мониторинг** &gt; **Query performance**. Эта страница — новая версия [Аналитики запросов](/ru/products/cloud/features/sql-console-features/query-insights): на ней можно фильтровать запросы по таблице и открывать отдельный запрос, чтобы просмотреть его метрики. Чтобы применить рекомендацию по запросу, нужно изменить сам запрос. Schema Advisor не применяет такие рекомендации автоматически.

| Рекомендация                                    | Когда появляется                                                                                                                                                                                                                                                                                                                                           | Что делать                                                                                                                                                                         |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Используйте `uniq`                              | Запрос использует `COUNT(DISTINCT ...)` или [`uniqExact`](/ru/sql-reference/aggregate-functions/reference/uniqexact), хотя приблизительного подсчета было бы достаточно.                                                                                                                                                                                      | Используйте [`uniq`](/ru/sql-reference/aggregate-functions/reference/uniq) для подсчета большого числа уникальных значений. Эта функция потребляет меньше памяти.                     |
| Храните JSON в нативном виде                    | Запрос разбирает JSON из строкового столбца во время выполнения.                                                                                                                                                                                                                                                                                           | Храните значение в столбце типа [JSON](/ru/sql-reference/data-types/newjson) или в обычных столбцах, вместо того чтобы разбирать строку при каждом запросе.                           |
| Перечисляйте нужные столбцы                     | Запрос использует `SELECT *` или `alias.*` для широкой таблицы.                                                                                                                                                                                                                                                                                            | Укажите нужные столбцы, чтобы ClickHouse не читал остальные.                                                                                                                       |
| Избегайте регулярного `OPTIMIZE ... FINAL`      | Запрос выполняет [`OPTIMIZE`](/ru/sql-reference/statements/optimize) с `FINAL`, что приводит к перезаписи таблицы.                                                                                                                                                                                                                                            | Не выполняйте `OPTIMIZE ... FINAL` на регулярной основе. Эта операция создает высокую нагрузку на I/O и CPU и может блокировать вставки.                                           |
| Используйте JOIN методом сортировки и слияния   | Обе стороны `JOIN` уже отсортированы по ключам соединения.                                                                                                                                                                                                                                                                                                 | Установите для [`join_algorithm`](/ru/reference/settings/session-settings/join#join_algorithm) значение `full_sorting_merge`, чтобы ClickHouse не сортировал входные данные повторно. |
| Фильтруйте по ведущим столбцам ключа сортировки | Фильтры запроса не затрагивают ведущие столбцы ключа сортировки. ClickHouse по-прежнему может отсекать гранулы по последующим столбцам ключа, но такое отсечение может быть менее эффективным. См. раздел [фильтрация по вторичным столбцам ключа](/ru/guides/clickhouse/data-modelling/sparse-primary-indexes#efficient-filtering-on-secondary-key-columns). | Проверьте план с помощью `EXPLAIN indexes = 1`. Добавляйте фильтр по ведущему столбцу ключа, только если результат запроса при этом не меняется.                                   |
| Разрешите асинхронные вставки                   | `INSERT` отключает асинхронные вставки и создает множество небольших частей.                                                                                                                                                                                                                                                                               | Оставьте [асинхронные вставки](/ru/optimize/asynchronous-inserts) включенными или объединяйте вставки в пакеты на стороне клиента, чтобы небольшие операции записи группировались.    |
