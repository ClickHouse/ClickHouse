ClickHouse CLI (`clickhousectl`, псевдоним `chctl`) позволяет управлять ClickHouse Cloud из терминала, скрипта или агента для программирования. На этой странице описаны возможности CLI, относящиеся к Cloud. Сведения обо всех группах команд и локальной разработке, а также полное описание работы CLI см. в [справочнике по clickhousectl](/ru/concepts/features/interfaces/cli).

## Чем можно управлять {#what-you-can-manage}

Команды `clickhousectl cloud` позволяют работать со следующим:

* **Сервисы:** создание, масштабирование, запуск и остановка сервисов ClickHouse Cloud, а также выполнение SQL-запросов к ним через API запросов.
* **[Managed Postgres](/ru/products/managed-postgres/overview) (бета):** создание сервисов Postgres, реплик для чтения и восстановление на определённый момент времени, а также изменение их конфигурации.
* **[ClickPipes](/ru/integrations/clickpipes/home):** приём данных из объектного хранилища, Kafka, Kinesis, Pub/Sub, Postgres, MySQL, MongoDB и BigQuery.
* **[ClickStack](/ru/clickstack/overview):** управление источниками, панелями мониторинга, оповещениями, вебхуками, сохранёнными поисками и ролями в сервисе [Управляемый ClickStack](/ru/clickstack/deployment/managed).
* **Пользовательские функции:** локальное тестирование исполняемых UDF и их последующее развертывание в сервисе ClickHouse Cloud.
* **Резервные копии:** просмотр списка резервных копий, изменение расписания резервного копирования и восстановление резервной копии в новый сервис.
* **Доступ к организации:** организации, участники, приглашения, ключи API и журнал действий.

Чтобы узнать флаги любой команды и необходимые для неё разрешения ключа API, выполните `clickhousectl cloud <command> --help`.

## Установка {#installation}

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

Скрипт устанавливает `~/.local/bin/clickhousectl` и псевдоним `chctl`. Убедитесь, что каталог `~/.local/bin` добавлен в `PATH`. Об установке через npm, pip, uv и другими способами см. раздел [Установка](/ru/concepts/features/interfaces/cli#installation).

## Аутентификация {#authentication}

Вход через OAuth в браузере даёт доступ только для чтения. Чтобы создавать или изменять ресурсы, нужен [ключ API](/ru/products/cloud/features/admin-features/api/openapi) с ролью, которая разрешает соответствующие изменения.

```bash
# Read-only: OAuth device flow in your browser
clickhousectl cloud auth login

# Read and write: prompts for the API key and secret, keeping the secret out of shell history
clickhousectl cloud auth login --interactive

# Alternative for scripts
clickhousectl cloud auth login --api-key <key> --api-secret <secret>
```

При входе проверяются учётные данные и выводится текущая идентичность. Проверить её можно в любой момент командой `clickhousectl cloud auth whoami`. Если вы состоите в нескольких организациях, добавляйте к командам Cloud параметр `--org-id <org-id>` (или `--org-name <name>`). В CI вместо входа задайте переменные `CLICKHOUSE_CLOUD_API_KEY` и `CLICKHOUSE_CLOUD_API_SECRET`. Порядок приоритета учётных данных и выход из системы описаны в разделе [Аутентификация](/ru/concepts/features/interfaces/cli#authentication).

## Примеры {#examples}

### Создание сервиса и выполнение запросов к нему {#create-and-query-a-service}

```bash
# Create a service. Save the initial password; it is printed only once.
# Omitting --ip-allow allows all addresses (0.0.0.0/0).
clickhousectl cloud service create --name analytics \
  --provider aws --region us-east-1 \
  --ip-allow '203.0.113.10/32=Office'

# Look up the service ID, then run SQL over the Query API
CH_ID=$(clickhousectl cloud service get --name analytics --json | jq -r .id)
clickhousectl cloud service query "$CH_ID" --query "SELECT version()"
```

Команда создания завершается до того, как сервис будет запущен. Периодически выполняйте `clickhousectl cloud service get "$CH_ID"`, пока `state` не примет значение `running`.

При первом запросе с ключом API clickhousectl добавляет ваш ключ API к конечной точке API запросов сервиса и при необходимости создаёт эту конечную точку; новый ключ при этом не создаётся. Чтобы вместо этого команда завершалась с ошибкой, передайте `--no-auto-enable`. При использовании OAuth команда `service query` выполняет операторы `SELECT` только в режиме только для чтения. Тайм-аут API запросов составляет около 30 секунд, поэтому для длительных запросов и массовых загрузок используйте `clickhouse client`.

### Создание управляемого сервиса Postgres {#create-a-managed-postgres-service}

```bash
clickhousectl cloud postgres create --name app-db \
  --provider aws --region us-east-1 --size c6gd.xlarge --pg-version 18 \
  --ip-allow '203.0.113.10/32:5432=Office'
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output ca.pem
```

Пароль и строку подключения возвращает только команда `create`, поэтому обязательно сохраните их. Если не указать `--ip-allow`, порты 5432 и 6432 будут открыты для всех адресов. Дождитесь, пока поле `state` примет значение `running`, а затем подключитесь через `psql`, используя CA‑сертификат.

### Просмотр ClickPipes, ClickStack и резервных копий {#inspect-clickpipes-clickstack-and-backups}

```bash
clickhousectl cloud clickpipe list "$CH_ID"
clickhousectl cloud clickstack source list <clickstack-service-id>
clickhousectl cloud backup list "$CH_ID"
```

Эти команды чтения поддерживают аутентификацию через OAuth. Для создания ClickPipe или изменения ресурса ClickStack нужен ключ API — см. руководства в репозитории ниже.

### Развертывание пользовательской функции {#deploy-a-user-defined-function}

```bash
# Uploads clickhouse/udfs/my_udf/, waits for the build, then attaches that version to the service
clickhousectl cloud udf deploy my_udf --service "$CH_ID"
```

Сначала протестируйте функцию на локальном сервере с помощью команды `clickhousectl local udf deploy my_udf`.

## Вывод в формате JSON и агенты для программирования {#json-output}

Команды Cloud поддерживают параметр `--json`, а CLI автоматически переключается на JSON, если обнаруживает агента для программирования. В этом случае `cloud service query` по умолчанию использует формат `JSONEachRow`, поэтому скрипты, которые разбирают его вывод, должны явно указывать `--format`, например `--format TabSeparated`. См. разделы [Вывод в формате JSON](/ru/concepts/features/interfaces/cli#json-output) и [Коды выхода](/ru/concepts/features/interfaces/cli#exit-codes). Чтобы установить ClickHouse agent skills, выполните `clickhousectl skills`.
