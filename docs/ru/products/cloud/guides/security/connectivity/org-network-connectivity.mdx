Защищённое сетевое подключение внутри организации позволяет одному сервису ClickHouse Cloud выполнять запросы к другому сервису в той же организации и регионе с помощью [`remoteSecure()`](/ru/reference/functions/table-functions/remote). Трафик передаётся по частной сети ClickHouse Cloud, а не через общедоступный интернет, поэтому подключение работает даже в том случае, если доступ к сервису, из которого читаются данные, ограничен с помощью [PrivateLink](/ru/products/cloud/guides/security/connectivity/private-networking/aws-privatelink) или [IP Access List](/ru/products/cloud/guides/security/connectivity/setting-ip-filters).

Эта возможность пригодится, если:

* Ваши сервисы доступны только через PrivateLink или защищены строгим IP Access List, поэтому вызвать `remoteSecure()` через публичную конечную точку не получится.
* Ваши требования к безопасности не допускают передачу трафика между сервисами через общедоступный интернет.
* Ваши сервисы не используют общие данные через [хранилища](/ru/products/cloud/features/infrastructure/warehouses) (разделение вычислительных ресурсов), но вам нужно выполнять запросы между ними.

<Note>
  Эта возможность находится в статусе закрытой предварительной версии, и каждое соединение для вас настраивает наша команда. Чтобы получить доступ, свяжитесь с командой сопровождения аккаунта ClickHouse или со [службой поддержки ClickHouse](https://clickhouse.com/support/program).
</Note>

## Как это работает {#how-it-works}

В этом руководстве используются два термина:

* **Producer**: сервис, содержащий таблицу, которую нужно прочитать.
* **Consumer**: сервис, который выполняет `remoteSecure()` для чтения данных из Producer.

ClickHouse Cloud создаёт одностороннее соединение от Consumer к Producer. Consumer аутентифицируется с помощью сертификата, которым управляет ClickHouse Cloud, а Producer с помощью стандартного `GRANT` определяет, какие таблицы может читать Consumer. Создавать или ротировать пароли не требуется.

Запрос должен пройти три проверки:

1. **Сеть**: обращаться к Producer через частную сеть может только Consumer с установленным соединением.
2. **Идентичность**: Consumer аутентифицируется с помощью сертификата, привязанного к его имени хоста.
3. **Разрешения на таблицы**: Producer с помощью `GRANT` определяет, какие таблицы может читать Consumer. При обращении к объектам, на которые права не выданы, возвращается ошибка «доступ запрещён».

## Предварительные требования {#prerequisites}

* Оба сервиса находятся в одной организации ClickHouse Cloud, у одного облачного провайдера и в одном регионе. Например, сервис в AWS `us-east-2` не может подключиться к сервису в AWS `us-west-2`. Перед созданием соединения наша команда проверит, подходят ли ваши сервисы.
* Ни один из сервисов не является регулируемым (HIPAA или PCI).
* У вас есть идентификаторы сервисов и имена хостов обоих сервисов. Их можно найти на странице **Настройки** каждого сервиса в консоли.
* У вас есть права администратора для выполнения SQL-запросов на обоих сервисах.

<Tip>
  Начните с тестовых сервисов, чтобы не затронуть продакшн. При создании первого соединения сервис-потребитель (Consumer) проходит один поочередный перезапуск.
</Tip>

## Настройка соединения {#setup}

### Отправьте нам сведения о ваших сервисах {#send-service-details}

На этапе закрытой предварительной версии в консоли нет интерфейса для управления соединениями. Отправьте своему контактному лицу в ClickHouse:

* Идентификаторы сервисов Producer и Consumer. Укажите, какой из них какой, а также нужно ли выполнять запросы в обоих направлениях.
* Время, когда допустим поочередный перезапуск сервиса Consumer. Для последующих соединений перезапуск не требуется.

### ClickHouse создаёт соединение {#clickhouse-creates-connection}

Мы проверяем, что оба сервиса соответствуют требованиям, и создаём соединение. Затем на сервисе Producer мы создаём пользователя `rt_<Consumer service ID>` с аутентификацией по сертификату и сообщаем вам его точное имя.

### Предоставление Consumer доступа к таблицам {#grant-access}

Выполните приведённые ниже тестовые запросы или предоставьте на стороне Producer право на выборку из собственных таблиц.

```sql
CREATE TABLE default.rs_demo_events (id UInt32, val String) ENGINE = MergeTree ORDER BY id;

INSERT INTO default.rs_demo_events VALUES (1, 'hello'), (2, 'from the Producer');

GRANT SELECT ON default.rs_demo_events TO `rt_<Consumer service ID>`;

CREATE TABLE default.rs_demo_no_grant (id UInt32) ENGINE = MergeTree ORDER BY id;
```

### Выполнение запросов со стороны Consumer {#query-from-consumer}

Выполните следующее на Consumer. Мы включим для вас возможность именованных коллекций, которая находится на этапе закрытой предварительной версии. Приведённый ниже SQL создаёт [именованную коллекцию](/ru/concepts/features/configuration/server-config/named-collections), указывающую на Producer, а затем выполняет через неё запросы. Укажите имя хоста Producer из консоли — то же, которое вы использовали бы для прямого подключения к нему.

```sql
CREATE NAMED COLLECTION IF NOT EXISTS my_producer AS
    host = '<Producer hostname>',
    port = 9440,
    user = 'rt_<Consumer service ID>',
    database = 'default';

SELECT * FROM remoteSecure(my_producer, table = 'rs_demo_events');

SELECT * FROM remoteSecure(my_producer, table = 'rs_demo_no_grant');
```

Если вы выполнили тестовые запросы, то наверняка заметили, что первый запрос возвращает результаты, а второй завершился ошибкой «доступ запрещён» из-за недостаточных разрешений.

## Ограничения {#limitations}

### Область применения {#scope}

* Запросы выполняются только в режиме чтения. Consumer может выполнять `SELECT` через `remoteSecure()`, но не может выполнять `INSERT` в Producer.
* Оба сервиса должны находиться в одной организации, у одного облачного провайдера и в одном регионе. Поддержка межрегиональных соединений и соединений между организациями запланирована.
* Одно соединение охватывает один сервис. Если вы используете [хранилища](/ru/products/cloud/features/infrastructure/warehouses), соединение с одним сервисом не распространяется на другие сервисы, использующие те же данные. Для каждого из них требуется отдельное соединение.
* Соединения однонаправленные. Чтобы выполнять запросы в обоих направлениях, нужны два соединения.
* Чтение выполняет Producer — так же, как сейчас при использовании табличной функции [`remoteSecure()`](/ru/reference/functions/table-functions/remote).

### Переход в состояние простоя {#idling}

* Бездействующий или остановленный Producer не выходит из состояния простоя при получении запроса `remoteSecure()`: запрос завершается ошибкой «в соединении отказано». Если сервисам Consumer требуется стабильно выполнять запросы к Producer, отключите для Producer [переход в состояние простоя](/ru/products/cloud/features/autoscaling/idling). В этом случае он будет работать непрерывно, а вычислительные ресурсы будут оплачиваться постоянно.
* Long-running запросы `remoteSecure()` могут завершиться ошибкой, если Consumer перейдёт в состояние простоя во время их выполнения.

### Сообщения об ошибках {#error-messages}

Большинство сбоев проявляется в виде общей сетевой ошибки — например, «в соединении отказано», отклонённое рукопожатие или тайм-аут, — а не в виде сообщения с указанием причины. Воспользуйтесь приведённой ниже таблицей [устранения неполадок](#troubleshooting) и поделитесь с нами текстом ошибки, чтобы мы могли сделать эти сообщения понятнее.

### Удаление сервиса {#deleting-a-service}

Наличие соединения не мешает удалить любой из двух сервисов. На этапе закрытой предварительной версии сообщите нам, если удалите один из них, чтобы мы могли удалить соединение.

## Устранение неполадок {#troubleshooting}

| Что вы видите                                                 | Вероятная причина                                                                            | Что делать                                                                                                                      |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Доступ запрещён                                               | Пользователю Consumer не выдан grant на эту таблицу                                          | Выполните `GRANT SELECT` на стороне Producer, как описано в разделе [Предоставление Consumer доступа к таблицам](#grant-access) |
| Ошибка аутентификации                                         | Пользователь в вашей именованной коллекции не совпадает с пользователем, которого мы создали | Проверьте имя пользователя, которое мы вам отправили                                                                            |
| В соединении отказано                                         | Producer бездействует или остановлен либо соединение в этом направлении не настроено         | Запустите Producer. Если он работает, уточните у нас направление соединения                                                     |
| Запрос зависает или завершается по тайм-ауту без явной ошибки | Возможно, соединение ещё не до конца настроено                                               | Свяжитесь с нами и укажите идентификаторы обоих сервисов                                                                        |

## ЧАСТО ЗАДАВАЕМЫЕ ВОПРОСЫ {#faq}

<AccordionGroup>
  <Accordion title="Взимается ли за это дополнительная плата?" id="cost">
    Вы платите только за фактически используемые вычислительные ресурсы, включая время, когда Producer не находится в состоянии простоя.
  </Accordion>

  <Accordion title="Нужно ли управлять паролями или сертификатами?" id="credentials">
    Нет. Consumer аутентифицируется с помощью сертификата, которым ClickHouse Cloud управляет за вас.
  </Accordion>

  <Accordion title="Проходит ли трафик через общедоступный интернет?" id="public-internet">
    Нет. Трафик не покидает частную сеть ClickHouse Cloud, поэтому всё работает, даже если Producer принимает только трафик PrivateLink или его IP Access List не разрешает ни одного адреса.
  </Accordion>

  <Accordion title="Может ли Producer читать данные из Consumer?" id="reverse-reads">
    Нет, если только вы не запросите второе соединение в обратном направлении.
  </Accordion>

  <Accordion title="Приведёт ли включение этой функции к перезапуску моих сервисов?" id="restarts">
    Первое соединение на Consumer вызывает однократный поочередный перезапуск. Producer не перезапускается, а последующие соединения или отзыв доступа не вызывают никаких перезапусков.
  </Accordion>

  <Accordion title="Как отозвать доступ?" id="remove-access">
    Чтобы отозвать доступ к таблице, выполните `REVOKE` на Producer. Чтобы удалить само соединение в период закрытой предварительной версии, обратитесь к своему контактному лицу в ClickHouse.
  </Accordion>
</AccordionGroup>
