Защита сервиса от удаления — это настройка отдельного сервиса, которая блокирует его удаление, пока вы её не отключите. Включайте её для сервисов ClickHouse Cloud, которые нужно уберечь от случайного удаления в консоли Cloud, через [ClickHouse Cloud API](/ru/cloud/manage/api/api-overview) или с помощью Terraform.

<Note>
  Защита распространяется на сервисы ClickHouse Cloud, но не на сервисы [ClickHouse Managed Postgres](/ru/cloud/managed-postgres).
</Note>

По умолчанию защита отключена. Отключение защиты не приводит к удалению сервиса. Защищённый сервис продолжает работать, а запросы, масштабирование и другие настройки не меняются.

Пока защита включена, запросы на удаление отклоняются: `DELETE /v1/organizations/{organizationId}/services/{serviceId}` возвращает HTTP `409`, пока вы не отключите защиту. Кроме того, перед удалением сервис необходимо остановить. Само удаление выполняется асинхронно.

## Кто может изменить эту настройку {#who-can-change-it}

Для включения и отключения защиты требуется разрешение [`control-plane:service:delete`](/ru/cloud/security/console-roles). Этим разрешением обладают администраторы организации. См. [Роли и разрешения в консоли](/ru/cloud/security/console-roles).

Кроме того, для включения защиты необходимо, чтобы защита от удаления была доступна в организации. В организациях ClickHouse Cloud она доступна. Если в организации она недоступна, запрос на создание или обновление, устанавливающий для `deletionProtection` значение `true`, возвращает HTTP `400`. При отключении защиты эта проверка не выполняется: запрос, устанавливающий для `deletionProtection` значение `false`, принимается, в том числе для сервиса, который уже защищён.

| Действие                                                | Разрешение                                                                                                                    |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Включить или отключить переключатель в консоли          | `control-plane:service:delete` для сервиса                                                                                    |
| Задать `deletionProtection` для существующего сервиса   | `control-plane:service:manage` и `control-plane:service:delete` для сервиса                                                   |
| Отправить значение, которое уже установлено для сервиса | Только `control-plane:service:manage`. Для повторной отправки текущего значения `control-plane:service:delete` не требуется   |
| Создать сервис с `deletionProtection: true`             | `control-plane:organization:create-service`, а также `control-plane:service:delete`, выданное для всех сервисов в организации |
| Удалить сервис                                          | `control-plane:service:delete` для сервиса. Сервис должен быть остановлен, а защита — отключена                               |

Сервисы ClickStack нельзя обновить через Облачный API. Защиту от удаления для них можно включить или отключить в консоли.

## Включение и отключение защиты в консоли {#console}

Откройте сервис и перейдите в раздел **Настройки**. В блоке **Защита от удаления** воспользуйтесь переключателем. Изменение сохраняется сразу.

Переключатель доступен всем, у кого есть разрешение `control-plane:service:delete` для этого сервиса. При включённой защите консоль не позволит удалить сервис, пока вы не выключите переключатель.

## Настройка через Облачный API {#cloud-api}

У объекта сервиса есть поле логического типа `deletionProtection`. Задайте его при создании сервиса (`POST /v1/organizations/{organizationId}/services`) или при его обновлении (`PATCH /v1/organizations/{organizationId}/services/{serviceId}`). Это поле возвращается в ответах на запросы получения сервиса и списка сервисов. Если поле отсутствует, сервис не защищён.

Чтобы включить защиту:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": true}'
```

Чтобы удалить защищённый сервис, отключите защиту, остановите сервис, дождитесь его остановки, а затем удалите его. Запрос `PATCH .../state` с `"command": "stop"` требует разрешения `control-plane:service:manage` и возвращает ответ до фактической остановки сервиса. Запрос на удаление, отправленный, пока сервис ещё находится в состоянии `stopping`, отклоняется. Запрос на удаление защищённого сервиса возвращает `409`, а сам сервис при этом не удаляется.

Отключите защиту:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": false}'
```

Отправьте запрос на остановку:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID/state" \
  -d '{"command": "stop"}'
```

Дождитесь, пока `result.state` примет значение `stopped`, затем удалите:

```bash
while [ "$(curl --silent --user "$KEY_ID:$KEY_SECRET" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  | jq -r '.result.state')" != "stopped" ]; do
  sleep 5
done

curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X DELETE \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID"
```

## Terraform {#terraform}

<Note>
  `deletion_protection` отсутствует в последней выпущенной версии провайдера [v3.43.0](https://github.com/ClickHouse/terraform-provider-clickhouse/releases/tag/v3.43.0). Атрибут был добавлен в [terraform-provider-clickhouse#799](https://github.com/ClickHouse/terraform-provider-clickhouse/pull/799): этот PR уже слит, но пока не вошёл в релиз. На v3.43.0 приведённый ниже пример завершается ошибкой о неподдерживаемом аргументе. Используйте релиз провайдера новее v3.43.0, в который входит этот атрибут.
</Note>

Ресурс `clickhouse_service` принимает параметр `deletion_protection`. Пока он имеет значение `true`, команда `terraform destroy` и любое изменение, требующее замены сервиса, завершаются ошибкой. Установите значение `false` и примените это изменение отдельно, после чего удалите сервис.

Если удалить `deletion_protection` из конфигурации, текущее значение настройки не изменится.

```hcl
resource "clickhouse_service" "example" {
  # ...

  deletion_protection = true
}
```

Чтобы задать `deletion_protection = true` при создании сервиса, нужен ключ API с разрешением на удаление всех сервисов в организации. Чтобы изменить этот параметр позднее, требуется разрешение на удаление данного сервиса.
