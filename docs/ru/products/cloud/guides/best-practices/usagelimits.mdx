ClickHouse создан для скорости и надёжности. Чтобы производительность оставалась оптимальной, мы рекомендуем придерживаться определённых рабочих параметров. Например, слишком большое количество таблиц, баз данных или частей может негативно сказаться на производительности. Чтобы этого избежать, ClickHouse Cloud вводит ограничения по нескольким эксплуатационным параметрам.

Мягкие ограничения действуют на трёх разных уровнях. Разделы ниже начинаются с ограничений уровня сервиса — именно с ними чаще всего сталкиваются рабочие нагрузки.

| Уровень                                 | Что охватывает                                                                                                           | Ограничения на этом уровне                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| **[Сервис](#service-limits)**           | Отдельный сервис и его вычислительные ресурсы                                                                            | Вычислительные ресурсы на сервис (параллелизм запросов, батчевый приём); ограничения на объекты данных при автономной работе (см. ниже) |
| **[Хранилище](#warehouse-limits)**      | Одно [хранилище](/ru/products/cloud/features/infrastructure/warehouses) — группа сервисов, использующих одни и те же данные | Суммарное количество реплик в хранилище; объекты данных в общем каталоге (таблицы, базы данных и т. д.)                                 |
| **[Организация](#organization-limits)** | Вся ваша организация ClickHouse Cloud (все хранилища и сервисы вместе)                                                   | Количество сервисов; количество хранилищ                                                                                                |

Уровень действия **ограничений на объекты данных** (базы данных, таблицы, столбцы, партиции и части) зависит от того, как вы запускаете свои сервисы.
Если вы используете **автономные сервисы**, эти ограничения применяются к каждому сервису отдельно.
Как только сервисы начинают совместно использовать данные в **хранилище**, те же ограничения применяются один раз — к общему каталогу хранилища.
Сами значения не меняются — меняется только уровень, на котором они измеряются.

<Tip>
  Если вы столкнулись с одним из этих ограничений, возможно, ваш сценарий использования реализован неоптимально. Обратитесь в [поддержку](https://clickhouse.com/support/program) — мы с радостью поможем доработать ваш сценарий, чтобы не выходить за рамки ограничений, либо вместе рассмотрим, как их можно контролируемо увеличить.
</Tip>

<div id="service-limits">
  ## Ограничения сервиса
</div>

Приведённые ниже ограничения применяются к **автономному сервису** (а в части количества объектов данных — к хранилищу этого сервиса).

Если сервис входит в состав **хранилища**, ограничения на объекты данных (базы данных, таблицы, столбцы, партиции и части) применяются вместо этого к общему каталогу хранилища, как описано ниже в разделе [Ограничения хранилища](#warehouse-limits) — значения остаются прежними, но измеряются по хранилищу в целом, а не по отдельному сервису. Остальные ограничения, такие как **параллелизм запросов** и **батчевый приём**, в обоих случаях действуют на уровне сервиса (или реплики).

| Параметр                                                    | Ограничение                                                                                                     |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Базы данных**                                             | 1000                                                                                                            |
| **Таблицы**                                                 | 5000                                                                                                            |
| **Представления**                                           | 15000                                                                                                           |
| **Словари**                                                 | 5000                                                                                                            |
| **Именованные коллекции** (закрытая предварительная версия) | 1000                                                                                                            |
| **Столбцы**                                                 | ~1000 (широкий формат предпочтительнее компактного)                                                             |
| **Партиции**                                                | 50k                                                                                                             |
| **Части**                                                   | 10k (см. настройку [`max_parts_in_total`](/ru/products/cloud/guides/cloud-compatibility#max_parts_in_total-10000)) |
| **Размер части**                                            | 150 GB                                                                                                          |
| **Низкая кардинальность**                                   | 10k или меньше                                                                                                  |
| **Первичных ключей в таблице**                              | 4–5, обеспечивающих достаточную фильтрацию данных                                                               |
| **Параллелизм запросов**                                    | 1000 (на реплику)                                                                                               |
| **Батчевый приём**                                          | Всё &gt; 1M строк разделяется на блоки по 1M строк                                                              |

Приведенные выше значения являются ограничениями по умолчанию. Ограничение для конкретного сервиса может быть выше указанного здесь значения, поскольку для более крупных сервисов предусмотрен больший запас ресурсов. Фактическое ограничение для вашего сервиса указано в предупреждении, которое вы получите при приближении к нему. Для сервисов, уже превышающих эти ограничения, ограничения на таблицы и базы данных устанавливаются на уровне текущего количества у сервиса плюс 25%.

<Note>
  Для сервисов с одной репликой максимальное количество баз данных ограничено
  100, а максимальное количество таблиц — 500. Кроме того, объем хранилища
  для сервисов Basic Tier ограничен 1 TB. Указанные выше ограничения на представления, словари и именованные
  коллекции являются едиными для всех сервисов,
  включая сервисы с одной репликой.
</Note>

Конкретные пороги предупреждения и ошибки для вашего сервиса можно проверить, выполнив запрос к `system.server_settings`. Например:

```sql
SELECT *
FROM system.server_settings
WHERE name IN ('max_table_num_to_warn', 'max_table_num_to_throw', 'max_database_num_to_warn', 'max_database_num_to_throw', 'max_view_num_to_warn', 'max_view_num_to_throw', 'max_dictionary_num_to_warn', 'max_dictionary_num_to_throw', 'max_named_collection_num_to_warn', 'max_named_collection_num_to_throw')
```

<div id="warehouse-limits">
  ## Ограничения хранилища
</div>

[Хранилище](/ru/products/cloud/features/infrastructure/warehouses) — это набор сервисов, использующих одни и те же данные.
Ограничения хранилища применяются к этой общей группе в целом, а не к каждому сервису по отдельности и не ко всей организации.

| Параметр                | Ограничение |
| ----------------------- | ----------- |
| **Реплик на хранилище** | 50 (мягкое) |

Ограничение на реплики — это **суммарное** количество реплик по всем сервисам хранилища.
Поскольку все сервисы в хранилище используют один ClickHouse Keeper, это ограничение введено для защиты стабильности Keeper. Значение по умолчанию 50 является мягким и зависит от ваших данных и рабочей нагрузки; в ClickHouse 26.6+ верхний предел выше, и в будущем мы планируем повысить его ещё больше.
Чтобы увеличить его, обратитесь в [поддержку](https://clickhouse.com/support/program); подробнее о масштабировании хранилищ см. в разделе [хранилища](/ru/products/cloud/features/infrastructure/warehouses#scaling).

**Отдельного ограничения на количество сервисов** в хранилище нет — оно определяется только суммарным лимитом реплик, указанным выше.

Поскольку сервисы в хранилище используют один каталог (одни и те же таблицы, базы данных, представления и т. д.), приведённые выше [ограничения на объекты данных уровня сервиса](#service-limits) учитываются **один раз на хранилище**, а не умножаются на количество сервисов. Разные хранилища изолированы друг от друга, поэтому каждое хранилище учитывает в рамках этих ограничений собственные таблицы и базы данных.

<div id="organization-limits">
  ## Ограничения на уровне организации
</div>

Эти ограничения действуют для всей организации ClickHouse Cloud — то есть для всех её хранилищ и сервисов вместе взятых.

| Параметр                    | Ограничение     |
| --------------------------- | --------------- |
| **Хранилищ на организацию** | Без ограничений |
| **Сервисов на организацию** | 20 (мягкое)     |

Ограничение на **число сервисов в организации** учитывает все сервисы во *всех* хранилищах организации. Это скорее исторически сложившееся ограничение, чем жёсткий предел; обратитесь в [поддержку](https://clickhouse.com/support/program) — как правило, его повышают после короткой проверки.
