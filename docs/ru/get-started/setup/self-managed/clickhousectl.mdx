<Info>
  **Пользователи Windows**

  ClickHouse работает нативно в Linux и macOS. В Windows выполняйте эти шаги в
  [Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/about).
</Info>

ClickHouse CLI (`clickhousectl`, псевдоним `chctl`) устанавливает локальные версии
ClickHouse и управляет ими, запускает локальные серверы ClickHouse и Postgres, выполняет запросы,
а также управляет ClickHouse Cloud. На этой странице описано, как установить CLI,
запустить локальный сервер ClickHouse и подключиться к нему.

Если вы использовали скрипт [быстрой установки](/ru/get-started/setup/self-managed/quick-install),
`clickhousectl` уже установлен. Перейдите к разделу
[Установка ClickHouse](#cli-install-clickhouse).

<Steps>
  <Step title="Установите ClickHouse CLI" id="install-the-cli">
    Скрипт установки поддерживает macOS и Linux на архитектурах x86&#95;64 и ARM64:

    ```bash
    curl -fsSL https://clickhouse.com/cli | sh
    ```

    Скрипт устанавливает `clickhousectl` в `~/.local/bin` и создаёт рядом с ним псевдоним `chctl`.
    Если скрипт сообщает, что каталога `~/.local/bin` нет в переменной `PATH`, добавьте его туда,
    а чтобы это работало и в последующих сеансах, добавьте ту же строку в профиль командной оболочки
    (`~/.bashrc`, `~/.zshrc`):

    ```bash
    export PATH="$HOME/.local/bin:$PATH"
    ```

    <Accordion title="Другие способы установки">
      | Инструмент                            | Команда                         |
      | ------------------------------------- | ------------------------------- |
      | npm                                   | `npm install -g clickhousectl`  |
      | uv                                    | `uv tool install clickhousectl` |
      | pipx                                  | `pipx install clickhousectl`    |
      | pip                                   | `pip install clickhousectl`     |
      | cargo-binstall                        | `cargo binstall clickhousectl`  |
      | Cargo, из исходного кода (Rust 1.94+) | `cargo install clickhousectl`   |

      Псевдоним `chctl` создают только скрипт установки и npm.
    </Accordion>

    Чтобы проверить наличие нового релиза CLI и установить его:

    ```bash
    clickhousectl update --check
    clickhousectl update
    ```
  </Step>

  <Step title="Установите ClickHouse" id="cli-install-clickhouse">
    Установите последнюю версию ClickHouse и сделайте её версией по умолчанию:

    ```bash
    clickhousectl local use latest
    ```

    `local use` устанавливает версию, если она ещё не установлена, делает её версией
    по умолчанию и создаёт символическую ссылку `clickhouse` в `~/.local/bin`, чтобы
    исполняемый файл `clickhouse` можно было запускать напрямую. Благодаря этому все последующие шаги в этой документации, где выполняется
    команда `clickhouse`, будут работать без изменений — при условии, что каталог `~/.local/bin` указан в переменной `PATH`.

    Также можно выбрать последний релиз с долгосрочной поддержкой (LTS) или конкретную
    версию:

    ```bash
    clickhousectl local use lts             # Latest LTS release
    clickhousectl local use 26.8            # Latest 26.8.x.x release
    clickhousectl local use 26.8.1.1760     # Exact version
    ```

    Чтобы узнать, какие минорные версии доступны для загрузки и какие версии у вас
    уже установлены:

    ```bash
    clickhousectl local list --remote
    clickhousectl local list
    ```

    <Info>
      **use и install**

      `clickhousectl local use <version>` устанавливает версию *и* делает её
      версией по умолчанию, обновляя символическую ссылку `clickhouse`. `clickhousectl local install <version>`
      только загружает версию: она становится версией по умолчанию, лишь если такая версия
      ещё не задана, а символическая ссылка при этом не обновляется. Чтобы задать версию по умолчанию, не создавая и не
      обновляя символическую ссылку, используйте `clickhousectl local use <version> --no-global`.
    </Info>
  </Step>

  <Step title="Запустите clickhouse-server" id="cli-start-clickhouse-server">
    `clickhousectl` привязывает локальные серверы к каталогу, из которого он запущен. Создайте
    каталог проекта и запустите в нём сервер:

    ```bash
    mkdir my-project && cd my-project
    clickhousectl local server start
    ```

    ```response
    Server 'default' started in background (PID: 14705)
      HTTP port: 8123
      TCP port:  9000
      Version:   26.9.1.1312
    ```

    Сервер работает в фоновом режиме и называется `default`. Его данные хранятся в
    `./.clickhouse/`, поэтому последующие команды `clickhousectl local` запускайте из того же
    каталога: `clickhousectl` не ищет данные в родительских каталогах. Сервер прослушивает
    HTTP-порт `8123` и TCP-порт `9000`, а если они заняты — свободные порты.
    Чтобы задать порты, используйте параметры `--http-port` и `--tcp-port`. Чтобы запустить несколько
    серверов, присвойте каждому имя, например: `clickhousectl local server start dev`.

    Чтобы убедиться, что сервер работает, выполните:

    ```bash
    clickhousectl local server list
    ```

    ```response
    | Name    | Status  | PID   | Version     | HTTP Port | TCP Port |
    |---------|---------|-------|-------------|-----------|----------|
    | default | running | 14705 | 26.9.1.1312 | 8123      | 9000     |

    1 server, 1 running
    ```
  </Step>

  <Step title="Запустите клиент ClickHouse" id="cli-start-clickhouse-client">
    Подключитесь к серверу с помощью `clickhouse-client` из того же каталога:

    ```bash
    clickhousectl local client
    ```

    Команда `local client` подключается к серверу с именем `default` и использует ту же
    версию ClickHouse, что и сервер. Чтобы подключиться к другому серверу, укажите его имя,
    например `clickhousectl local client dev`. Вывод будет примерно таким:

    ```response
    ClickHouse client version 26.9.1.1312 (official build).
    Connecting to localhost:9000 as user default.
    Connected to ClickHouse server version 26.9.1.

    local-host :)
    ```

    Теперь можно отправлять SQL-команды в ClickHouse! Чтобы выйти из клиента, введите `exit`.

    Чтобы выполнить один запрос, не открывая интерактивный сеанс, используйте параметр `-q`:

    ```bash
    clickhousectl local client -q "SELECT version()"
    ```

    <Tip>
      В руководстве [Создание таблиц в ClickHouse](/ru/get-started/quickstarts/creating-tables) пошагово описано, как создавать таблицы и вставлять в них данные.
    </Tip>
  </Step>

  <Step title="Остановите сервер" id="cli-stop-clickhouse-server">
    Сервер работает в фоновом режиме, пока вы его не остановите. Чтобы остановить его, выполните команду из того же
    каталога:

    ```bash
    clickhousectl local server stop
    ```

    При остановке данные сервера сохраняются до следующего запуска `clickhousectl local server start`.

    <Warning>
      Команда `clickhousectl local server remove` безвозвратно удаляет данные остановленного сервера.
    </Warning>
  </Step>
</Steps>

## Дальнейшие шаги {#next-steps}

* **Запустите Postgres локально.** Убедитесь, что Docker запущен, затем запустите локальный сервер Postgres
  и подключитесь к нему с помощью `psql`:

  ```bash
  clickhousectl local postgres start
  clickhousectl local postgres client
  ```

* **Подключитесь к ClickHouse Cloud.** Создайте аккаунт или войдите в существующий.
  Вход через браузер дает доступ только для чтения; для создания или изменения ресурсов Cloud
  нужен ключ API — его запросит команда `clickhousectl cloud auth login --interactive`.

  ```bash
  clickhousectl cloud auth signup
  clickhousectl cloud auth login
  ```

* **Изучите остальные возможности CLI.** См. [справочник по clickhousectl](/ru/concepts/features/interfaces/cli)
  или выполните `clickhousectl --help`.
