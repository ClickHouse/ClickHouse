В этом руководстве описано, как зарегистрироваться и начать репликацию данных из исходной базы данных в ваш экземпляр ClickHouse. Полный пример см. в разделе [Пример конвейера для SQL Server](/ru/integrations/connectors/data-ingestion/etl-tools/striim/sample-pipeline).

## Предварительные требования {#prerequisites}

| **Что потребуется** | **Подробности**                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ClickHouse          | Работающий сервис ClickHouse Cloud или самоуправляемое развертывание, а также права администратора для создания базы данных и пользователя. Для `CoalescingMergeTree` требуется сервер ClickHouse версии 25.6 или новее.                                                                                                                                                                                            |
| Источник            | Права администратора в исходной системе данных для настройки CDC (фиксации изменений данных) и необходимых разрешений для считывателя.                                                                                                                                                                                                                                                                              |
| Сетевой маршрут     | Одобренный сетевой маршрут от Striim на AWS к вашему источнику и к ClickHouse. При необходимости Striim for ClickHouse поддерживает частное сетевое подключение с помощью списка разрешённых IP-адресов, AWS PrivateLink или туннелирования SSH. Подробнее см. в разделе [Security and Networking](https://www.striim.com/docs/striimforclickhouse/en/security-and-networking-for-striim.html) документации Striim. |

## Создайте аккаунт Striim {#create-your-striim-account}

Зарегистрируйтесь напрямую в Striim или через AWS Marketplace. 14-дневный бесплатный пробный период начинается с момента активации аккаунта. Кредитная карта для пробного периода не требуется.

1. Откройте [форму регистрации Striim for ClickHouse](https://go2.striim.com/trial-clickhouse), заполните обязательные поля и нажмите **Sign up**.
2. Откройте письмо с активацией аккаунта, активируйте аккаунт и войдите в облачную консоль Striim.

Если ваша организация приобретает продукты через AWS Marketplace, следуйте инструкциям из раздела [Subscribe and sign up](https://www.striim.com/docs/striimforclickhouse/en/subscribe-and-sign-up.html#id211623): после оформления подписки на Striim for ClickHouse в AWS Marketplace завершите настройку аккаунта Striim.

## Создание сервиса {#create-your-service}

Сервис — это управляемая среда Striim в AWS, в которой вы создаёте, запускаете и отслеживаете конвейеры, записывающие данные в ClickHouse. В аккаунте одновременно может быть только один активный сервис Striim for ClickHouse.

1. При первом входе в Striim for ClickHouse нажмите **Get Started**. Либо выберите **Marketplace** на боковой панели и в разделе **Striim for ClickHouse** нажмите **Create**.
2. Задайте следующие параметры:
   * **Service Name:** имя, обозначающее рабочую нагрузку или среду.
   * **AWS Region:** регион, в котором работает сервис. По возможности выберите тот же регион, что и у вашего ClickHouse, чтобы снизить задержку и расходы на межрегиональную передачу данных. В противном случае выберите ближайший доступный регион.
3. Имя и регион нельзя изменить после создания. Чтобы изменить любой из этих параметров, придётся удалить сервис и создать новый.
4. Нажмите **Create a service**. Подготовка ресурсов может занять несколько минут. По умолчанию новые сервисы используют план **Premium**. Сменить план можно на странице **Billing**.
5. Когда сервис будет готов, выберите способ запуска:
   * **Start building with Striim Clara AI:** запуск с Clara AI под управлением Striim. Ключ API не требуется.
   * **Review your service settings before launch:** перед запуском можно подключить собственного провайдера ИИ, настроить пользователей, а также SSH или AWS PrivateLink.

При последующих входах открывайте сервис из списка **Services**, чтобы создавать конвейеры или управлять его настройками.

## Подготовка целевой системы ClickHouse {#prepare-your-clickhouse-target}

<Steps>
  <Step title="Получите сведения о подключении" id="get-connection-details">
    В ClickHouse Cloud выберите свой сервис, нажмите **Connect**, затем выберите **HTTPS**, чтобы увидеть хост и порт (8443). Для самоуправляемого ClickHouse узнайте хост и порт у администратора.
  </Step>

  <Step title="Выберите или создайте целевую базу данных" id="create-target-database">
    Striim не создаёт целевую базу данных: если её нет, приложение останавливается при запуске. Используйте существующую базу данных или создайте новую:

    ```sql
    CREATE DATABASE IF NOT EXISTS <your_database>;
    ```
  </Step>

  <Step title="Создайте отдельного пользователя для Striim" id="create-target-user">
    Не используйте административного пользователя по умолчанию — создайте отдельного пользователя:

    ```sql
    CREATE USER <user> IDENTIFIED BY '<password>';
    ```

    Для самоуправляемого ClickHouse также можно настроить аутентификацию по SSL-сертификату X.509.
  </Step>

  <Step title="Предоставьте необходимые привилегии" id="grant-target-privileges">
    Предоставьте пользователю следующие привилегии, перечисленные в [документации Striim](https://www.striim.com/docs/striimforclickhouse/en/initial-setup-to-write-to-clickhouse.html):

    ```sql
    GRANT CREATE TABLE ON <your_database>.* TO <user>;
    GRANT ALTER TABLE ON <your_database>.* TO <user>;
    GRANT DROP TABLE ON <your_database>.* TO <user>;
    GRANT TRUNCATE ON <your_database>.* TO <user>;
    GRANT CREATE DATABASE ON *.* TO <user>;
    GRANT SHOW TABLES ON *.* TO <user>;
    GRANT SHOW DATABASES ON *.* TO <user>;
    GRANT SELECT ON information_schema.* TO <user>;
    GRANT SELECT ON system.tables TO <user>;
    GRANT SELECT ON system.columns TO <user>;
    GRANT SELECT ON system.parts TO <user>;
    GRANT SELECT, INSERT, UPDATE, DELETE ON <your_database>.* TO <user>;
    ```
  </Step>
</Steps>

### Рекомендуемая конфигурация ClickHouse {#recommended-clickhouse-configuration}

| Настройка                   | **ClickHouse Cloud**                                                   | **Самоуправляемый**                                                                                |
| --------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Порт                        | 8443 (открыт по умолчанию; управляется ClickHouse Cloud)               | Откройте нужные: 8123 (HTTP), 9000 (нативный), 8443 (HTTPS), 9440 (TLS)                            |
| Шифрование                  | Всегда TLS                                                             | TLS настраивается самостоятельно; включите его в профиле подключения с помощью свойства `EnableSSL` |
| Движок баз данных           | `Shared`                                                               | `Atomic` (по умолчанию)                                                                            |
| Аутентификация              | Имя пользователя и пароль                                              | Имя пользователя и пароль либо SSL X.509 (взаимный TLS)                                            |
| Частное сетевое подключение | AWS PrivateLink (только в тарифах Scale и Enterprise ClickHouse Cloud) | SSH-туннель или список разрешённых IP-адресов                                                      |

## Создание профиля подключения {#create-a-connection-profile}

Создайте профиль подключения к ClickHouse, на который конвейеры смогут ссылаться по имени. В мастере создания профиля подключения задайте следующие параметры:

| **Свойство**                                           | **Значение**                                                                                                                    |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| Connection URL                                         | `jdbc:clickhouse://<host>:<port>`, где используются хост и порт из предыдущего раздела (для ClickHouse Cloud — порт 8443)       |
| Authentication Type                                    | Password (по умолчанию) или SSL X.509                                                                                           |
| Username / Password                                    | Данные выделенного пользователя ClickHouse для Striim, созданного на предыдущем шаге при подготовке целевой системы ClickHouse. |
| Client SSL Certificate, Client SSL Key, CA Certificate | Требуются только для SSL X.509. Закрытый ключ должен быть в формате PKCS#8 PEM.                                                 |

Чтобы обновить учётные данные или сертификаты, откройте **Connection Profiles**, измените профиль и сохраните изменения.

Для AWS PrivateLink оставьте Connection URL, предоставленный ClickHouse Cloud. Настройте частную размещённую зону (private hosted zone) Route 53, чтобы из вашего сервиса Striim имя хоста разрешалось в частную конечную точку. См. [Initial setup to write to ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/initial-setup-to-write-to-clickhouse.html).

## Подготовка источника {#prepare-your-source}

Для каждого типа источника предусмотрена своя процедура настройки. Найдите свой источник в разделе [Sources](https://www.striim.com/docs/striimforclickhouse/en/sources.html) документации Striim for ClickHouse и выполните инструкции из соответствующего раздела о конфигурации. Для источников с поддержкой CDC (фиксация изменений данных) может потребоваться включить фиксацию изменений на стороне источника и создать для Striim отдельного пользователя с привилегиями, указанными для этого источника. Прежде чем продолжить, подготовьте следующее:

* Хост, порт и учётные данные пользователя Striim.
* Схемы и таблицы, которые нужно реплицировать. По возможности выбирайте отдельные таблицы, а не схемы целиком.
* Подтверждение того, что Striim может подключиться к источнику из AWS (межсетевой экран, VPC, PrivateLink, SSH или список разрешённых IP-адресов).
* Ваш тарифный план: для CDC из Oracle, SQL Server, Snowflake и Salesforce требуется план Premium.

## Создание и запуск конвейера {#build-and-start-a-pipeline}

Создать конвейер можно одним из следующих способов:

* **Striim Clara AI:** нажмите **Ask Clara** и опишите конвейер. Например: «Build a pipeline from &lt;source&gt; to ClickHouse for &lt;schema.table&gt;.» Clara запросит стратегию чтения и сведения о подключении, а затем сгенерирует план TQL. Проверьте план, нажмите **Accept TQL**, а затем — **Deploy and Start this App**. См. [Build your first application](https://www.striim.com/docs/striimforclickhouse/en/build-your-first-application.html).
* **Мастер автоматизированного конвейера:** создайте два связанных приложения: одно для первоначальной загрузки, другое для CDC (фиксации изменений данных). После завершения первоначальной загрузки Striim автоматически запускает приложение CDC. [См. процедуру ниже](#using-the-automated-pipeline-wizard).
* **Flow Designer:** создавайте и редактируйте приложения в визуальном редакторе и добавляйте преобразования до того, как данные попадут в ClickHouse. Кроме того, можно экспортировать TQL приложения, отредактировать его и импортировать обновлённую конфигурацию.

### Использование мастера автоматизированного конвейера {#using-the-automated-pipeline-wizard}

1. Выберите **Apps &gt; Create an App**, затем найдите и выберите свой источник.
2. Нажмите **Get Started** и выберите автоматизированный конвейер (первоначальная загрузка и CDC (фиксация изменений данных)), если он доступен для вашего источника.
3. Введите имя конвейера, выберите пространство имён и нажмите **Next**.
4. Укажите свойства соединения с источником. Рядом с каждой настройкой отображается встроенная справка. Striim проверяет соединение; прежде чем продолжить, необходимо устранить все ошибки.
5. Выберите схемы для репликации (кроме системных), затем нажмите **Next**.
6. Выберите таблицы в каждой схеме, затем нажмите **Next**.
7. Выберите профиль подключения к ClickHouse и **движок таблицы**. Описание поведения движков см. в разделе [Как данные попадают в ClickHouse](#how-data-lands-in-clickhouse).
8. Проверьте сопоставления таблиц. При необходимости измените их, затем нажмите **Save &amp; Start**.

Сначала Striim выполняет первоначальную загрузку. После её завершения Striim переводит приложение первоначальной загрузки в состояние покоя (quiesce) и автоматически запускает связанное приложение CDC.

Не выполняйте DDL-операторы над исходными таблицами во время первоначальной загрузки. Сохраняйте журналы изменений или потоки источника с момента начала первоначальной загрузки до тех пор, пока приложение CDC не догонит источник. Если конвейер остановится, перед возобновлением работы изучите ошибку и предложенные способы её устранения.

## Проверка данных в ClickHouse {#verify-data-in-clickhouse}

1. На панели мониторинга Striim убедитесь, что события считываются и записываются. Текущую задержку также можно узнать у Clara.

2. В ClickHouse проверьте таблицу, созданную Striim:

   ```sql
   SHOW CREATE TABLE <your_database>.<your_table>;
   ```

3. Сравните количество строк с источником. Для таблиц `ReplacingMergeTree` используйте запрос из следующего раздела.

4. Внесите небольшое изменение в источнике (вставку, обновление и удаление тестовой строки) и убедитесь, что оно появилось в ClickHouse.

## Как данные попадают в ClickHouse {#how-data-lands-in-clickhouse}

При настройке целевой системы ClickHouse выберите **движок таблицы**. По умолчанию ClickHouse Writer использует **`MergeTree`**. От движка зависит, как применяются изменения и может ли Striim сам создать целевую таблицу.

| **Движок таблицы**                                  | **Поведение**                                                                                                                                                     | **Когда использовать**                                                                                                                                                |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReplacingMergeTree`                                | Обновления и удаления записываются как новые строки с версией и флагом мягкого удаления; дедупликация выполняется фоновыми слияниями или с помощью `FINAL`.       | Источники CDC, которые при обновлении передают полный образ строки. Самая простая схема CDC с наивысшей пропускной способностью; безопасна для повторного применения. |
| `MergeTree`                                         | По умолчанию данные только добавляются в конец. При Mode = `MERGE` обновления и удаления применяются к таблице (легковесное удаление или удаление через мутацию). | Первоначальная загрузка, журналы и события, а также CDC, когда строки нужно удалять физически и без дополнительных столбцов.                                             |
| `CollapsingMergeTree`                               | Записывает столбец sign: +1 для текущего состояния, -1 для отмены.                                                                                                | Источники CDC, которые передают образы строки до и после изменения. Небезопасен для повторного применения после восстановления.                                       |
| `CoalescingMergeTree`                               | Частичные обновления строк; `NULL` означает «оставить без изменений». Требуются сервер версии 25.6 или новее и неключевые столбцы типа `Nullable`.                | Источники CDC, которые передают неполные строки.                                                                                                                      |
| `SummingMergeTree`                                  | Только вставка. При `UPDATE` или `DELETE` приложение останавливается.                                                                                             | Числовые агрегаты, которые только пополняются, например счётчики.                                                                                                     |
| `AggregatingMergeTree`, `Replicated`, `Distributed` | Только запись данных. Целевые таблицы нужно создать самостоятельно до развертывания.                                                                              | Базовые таблицы для материализованных представлений; кластерные и шардированные самоуправляемые развертывания.                                                        |

Для автоматического создания и изменения схемы используйте `MergeTree`, `ReplacingMergeTree`, `CollapsingMergeTree`, `CoalescingMergeTree` или `SummingMergeTree`. Для `ReplacingMergeTree` Striim добавляет столбцы `__STRIIM_VERSION` и `__STRIIM_ISDELETED`, для `CollapsingMergeTree` — `__STRIIM_SIGN`. Запрашивайте данные из таблиц `ReplacingMergeTree` с модификатором `FINAL` и исключайте мягко удалённые строки:

```sql
SELECT * FROM <your_database>.<your_table> FINAL WHERE __STRIIM_ISDELETED = 0;
```

Типы данных источника автоматически сопоставляются с типами ClickHouse. Подробнее см. в разделе [Поддерживаемые типы данных](https://www.striim.com/docs/striimforclickhouse/en/clickhouse-writer-programmer-s-reference.html#supported-data-types-787538).

## Мониторинг конвейера {#monitor-your-pipeline}

Striim отображает метрики ClickHouse Writer в веб-интерфейсе: количество принятых событий и событий, подтверждённых ClickHouse, актуальность данных в целевой системе, время последней записи, число пакетов и время слияния по каждой таблице. Системные оповещения включаются автоматически; дополнительно можно настроить пользовательские оповещения по электронной почте, в Slack или Microsoft Teams. Кроме того, можно задать вопрос ассистенту Clara, например: «Какова текущая задержка в моём приложении?»

## Устранение неполадок {#troubleshooting}

<Accordion title="Приложение останавливается при запуске с сообщением об отсутствующей базе данных">
  Striim не создаёт целевую базу данных. Создайте её в ClickHouse и перезапустите приложение.
</Accordion>

<Accordion title="Таблица или столбец не найдены, хотя та же схема работает в другом месте">
  Имена столбцов всегда чувствительны к регистру; чувствительность имён баз данных и таблиц к регистру зависит от файловой системы сервера (в типичных системах Linux они чувствительны к регистру). Указывайте имена точно в том же регистре, в каком они определены в ClickHouse.
</Accordion>

<Accordion title="CollapsingMergeTree показывает дубликаты или отрицательные суммы после перезапуска">
  Доставка выполняется по принципу «как минимум один раз» (at-least-once), а этот движок не выполняет дедупликацию. Если вы используете восстановление, лучше выбрать `ReplacingMergeTree` или `MergeTree` с Mode = `MERGE`.
</Accordion>

<Accordion title="PrivateLink: Connection timed out">
  Убедитесь, что группа безопасности конечной точки VPC разрешает входящий трафик на порты 443, 8443, 9440 и 3306, а правила для исходящего трафика разрешают соединение.
</Accordion>

<Accordion title="PrivateLink: Connection reset by peer">
  Добавьте Endpoint ID конечной точки AWS в список разрешённых для сервиса в ClickHouse Cloud.
</Accordion>

<Accordion title="Приложение завершается с незнакомым исключением">
  Попросите Clara объяснить ошибку и предложить способы её исправления. Прежде чем вносить изменения в продакшн, проверьте её рекомендации.
</Accordion>
