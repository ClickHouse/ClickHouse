Подключите ClickHouse Cloud к каталогам данных, чтобы получить доступ к таблицам в открытом табличном формате. Подключения можно настроить в интерфейсе **источник данных**. Для настройки через SQL используйте движок базы данных [`DataLakeCatalog`](/ru/reference/engines/database-engines/datalake) в предпочитаемом редакторе SQL.

<Image img="/images/cloud/features/data-catalogs-ui.png" size="md" alt="Интерфейс ClickHouse Cloud с интеграциями с каталогами данных" />

После подключения таблицы каталога отображаются в консоли SQL в базе данных с выбранным вами именем. К ним можно выполнять стандартные запросы ClickHouse SQL, объединять их с таблицами [MergeTree](/ru/reference/engines/table-engines/mergetree-family/mergetree) с помощью JOIN и использовать в качестве источников для [materialized views](/ru/concepts/features/materialized-views).

<div id="prerequisites">
  ## Предварительные требования
</div>

Перед подключением каталога убедитесь в следующем:

* **Разрешения сервиса.** Для доступа к странице **Источники данных** и добавления каталогов требуется разрешение `control-plane:service:manage`.
* **Запущенный сервис.** Если сервис бездействует, активируйте его на странице **Источники данных** или в настройках сервиса, прежде чем подключать или просматривать связанные каталоги.
* **Учетные данные каталога.** Перед открытием выдвижной панели подготовьте сведения о подключении для вашего типа каталога. Для каждого каталога используются разные поля и способы аутентификации — см. ниже раздел [Добавление подключения к каталогу](#add-your-catalog-connection).

<div id="connect-your-catalog">
  ## Подключение каталога
</div>

<Steps>
  <Step title="Откройте выдвижную панель каталога данных" id="open-data-catalog-flyout">
    1. В левой навигации выберите **Источники данных**.
    2. Если вы ещё не настроили ни одного источника данных, нажмите **+ Add catalog**. В противном случае нажмите **Add data source** &gt; **Add data lake catalog**.
    3. На выдвижной панели **Connect your data catalog** выберите каталог из раскрывающегося списка **Select catalog**. Если каталог поддерживает несколько открытых табличных форматов, выберите нужный формат в поле **Open table format**.

    <Image img="/images/integrations/data-catalogs/catalog-flyout-select.png" alt="Выдвижная панель Connect your data catalog с раскрывающимся списком Select catalog, содержащим AWS Glue, BigLake Metastore, Microsoft OneLake, Polaris, REST Catalog и Unity Catalog" size="lg" />
  </Step>

  <Step title="Добавьте подключение к каталогу" id="add-your-catalog-connection">
    Выберите ниже свой каталог, чтобы ознакомиться с инструкциями и предварительными требованиями. Затем укажите параметры подключения, а также **Database name** — базу данных ClickHouse, через которую таблицы вашего каталога будут доступны в SQL-консоли.

    <Tabs>
      <Tab title="AWS Glue" id="aws-glue">
        [Каталог AWS Glue](/ru/guides/use-cases/data-warehousing/glue-catalog) предоставляет доступ к таблицам [Iceberg](/ru/reference/engines/table-engines/integrations/iceberg), зарегистрированным в Glue Data Catalog.

        Перед подключением убедитесь, что:

        * используется ClickHouse версии 25.12+;
        * таблицы Iceberg зарегистрированы в AWS Glue Data Catalog в целевом регионе;
        * для аутентификации по ключу доступа у вас есть ключ доступа пользователя IAM с разрешениями на чтение метаданных Glue и соответствующих объектов S3;
        * для аутентификации с использованием роли IAM (26.2+) у вас есть роль IAM, доверяющая сервисной роли ClickHouse. Добавьте ARN сервисной роли из **Settings → Network security information** в политику доверия роли. Примеры политик IAM см. в разделе [Безопасный доступ к данным Iceberg](/ru/products/cloud/guides/data-sources/accessing-iceberg-data-securely).

        На выдвижной панели укажите AWS **Region** (например, `us-west-2`), затем выберите метод аутентификации:

        **Аутентификация по ключу доступа**

        1. Выберите **AWS Access Key** в качестве **метода аутентификации**.
        2. Введите **Access Key ID** и **Secret Access Key**.
        3. Укажите **Database name** для базы данных ClickHouse, предоставляющей доступ к таблицам Glue.

        **Аутентификация с использованием роли IAM (26.2+)**

        1. Выберите **AWS IAM Role** в качестве **метода аутентификации**.
        2. Скопируйте **Service role ID (IAM)** с выдвижной панели и добавьте его в политику доверия роли IAM.
        3. Укажите **AWS Role ARN** и необязательное **AWS Role Session Name**.
        4. Укажите **Database name** для базы данных ClickHouse, предоставляющей доступ к таблицам Glue.

        <Note>
          Glue поддерживает несколько форматов таблиц, но ClickHouse читает из Glue только таблицы **Iceberg**.
        </Note>
      </Tab>

      <Tab title="Unity Catalog (Iceberg)" id="unity-iceberg">
        Выполняйте запросы к таблицам [Iceberg](/ru/reference/engines/table-engines/integrations/iceberg) в Unity Catalog, использующим внешние хранилища, с помощью OAuth-учётных данных сервисного субъекта Databricks. Полную информацию о настройке см. в [руководстве по Unity Catalog](/ru/guides/use-cases/data-warehousing/unity-catalog#read-iceberg).

        Перед подключением убедитесь в следующем:

        * Используется ClickHouse версии 25.12 или выше.
        * [Unity Catalog настроен для доступа к внешним данным](https://docs.databricks.com/aws/en/external-access/admin).
        * У сервисного субъекта Databricks есть OAuth client ID и secret, как описано [здесь](https://docs.databricks.com/aws/en/dev-tools/auth/oauth-m2m). Сервисный субъект имеет привилегии `USE CATALOG`, `USE SCHEMA`, `USE EXTERNAL SCHEMA` и `SELECT` для таблиц, к которым вы хотите выполнять запросы.

        В выдвижной панели:

        1. Введите **URL рабочего пространства** Databricks (например, `dbc-1234567a-cbde.cloud.databricks.com`).
        2. Введите **имя каталога Databricks**, к которому нужно подключиться (например, `icebench`).
        3. Введите OAuth **Client ID** и **Client secret** для сервисного субъекта.
        4. Введите **имя базы данных** ClickHouse, предоставляющей доступ к таблицам Unity Catalog.
      </Tab>

      <Tab title="Unity Catalog (Delta)" id="unity-delta">
        Выполняйте запросы к таблицам Unity Catalog [Delta Lake](/ru/reference/engines/table-engines/integrations/deltalake), использующим внешние расположения хранилищ, с помощью персонального токена доступа (PAT) Databricks. Полные инструкции по настройке см. в [руководстве по Unity Catalog](/ru/guides/use-cases/data-warehousing/unity-catalog#read-delta).

        Перед подключением убедитесь, что:

        * используется ClickHouse версии 25.12 или выше;
        * [Unity Catalog настроен для доступа к внешним данным](https://docs.databricks.com/aws/en/external-access/admin);
        * у вас есть [персональный токен доступа](https://docs.databricks.com/aws/en/dev-tools/auth/pat) Databricks с правами `EXTERNAL USE SCHEMA`, `USE CATALOG`, `USE SCHEMA` и `SELECT` как минимум для целевых таблиц.

        На выдвижной панели:

        1. Укажите **URL рабочего пространства** Databricks (например, `dbc-1234567a-cbde.azuredatabricks.net`).
        2. Укажите **имя каталога Databricks**, к которому требуется подключиться.
        3. Укажите свой **персональный токен доступа**.
        4. Укажите **имя базы данных** ClickHouse, которая предоставляет доступ к вашим таблицам Delta.

        <Note>
          Iceberg и Delta используют в интерфейсе разные способы аутентификации. Для доступа к обоим типам таблиц потребуются две отдельные базы данных ClickHouse.
        </Note>
      </Tab>

      <Tab title="REST-каталог" id="rest">
        Подключитесь к любому каталогу, поддерживающему спецификацию [Iceberg REST Catalog](https://github.com/apache/iceberg/blob/main/open-api/rest-catalog-open-api.yaml). Полную информацию о настройке см. в [руководстве по REST-каталогу](/ru/guides/use-cases/data-warehousing/rest-catalog).

        Перед подключением убедитесь, что:

        * Используется ClickHouse версии 25.12 или выше.
        * Конечная точка REST-каталога доступна из ClickHouse Cloud.
        * У вас есть учетные данные OAuth-клиента или Bearer-токен — в зависимости от конфигурации каталога.
        * У вас есть URI S3 или совместимой **конечной точки хранилища** для данных таблиц (например, `s3://my-bucket/path`).

        В выдвижной панели:

        1. Введите **URL каталога** (например, `https://catalog.example.com/v1`).
        2. Введите **хранилище** или пространство имен каталога (например, `demo`).
        3. Введите префикс URI **конечной точки хранилища** для хранения данных таблиц.
        4. Выберите **метод аутентификации**: **учетные данные OAuth-клиента** или **Bearer-токен**, затем введите соответствующие учетные данные.
        5. Введите **имя базы данных** для базы данных ClickHouse, предоставляющей доступ к таблицам REST-каталога.
      </Tab>

      <Tab title="Microsoft OneLake" id="onelake">
        Выполняйте запросы к таблицам [Iceberg](/ru/reference/engines/table-engines/integrations/iceberg) в Microsoft Fabric OneLake с помощью учетных данных приложения Azure AD. Полную инструкцию по настройке см. в [руководстве по Fabric OneLake](/ru/guides/use-cases/data-warehousing/onelake-catalog).

        Перед подключением убедитесь, что:

        * Используется ClickHouse версии 25.12 или выше.
        * Таблицы Iceberg существуют в рабочем пространстве Fabric.
        * У вас есть приложение Entra ID (Azure AD) с идентификатором клиента и секретом.
        * У вас есть идентификаторы тенанта, рабочего пространства и элемента данных. Используйте **Lakehouse ID** из URL страницы Lakehouse. Подробнее о том, где найти эти значения, см. в [предварительных требованиях Microsoft OneLake](https://learn.microsoft.com/en-us/fabric/onelake/table-apis/table-apis-overview#prerequisites).

        В выдвижной панели:

        1. Введите **Workspace ID** Fabric.
        2. В поле **Data Item ID** укажите Lakehouse ID. Идентификаторы хранилищ не поддерживаются.
        3. Введите **Tenant ID**, **Application (client) ID** и **Client secret** Entra ID.
        4. Введите **Database name** для базы данных ClickHouse, предоставляющей доступ к таблицам OneLake.
      </Tab>

      <Tab title="Polaris" id="polaris">
        Подключитесь к развертыванию Snowflake Open Catalog (Polaris) для таблиц [Iceberg](/ru/reference/engines/table-engines/integrations/iceberg). Полную информацию о настройке см. в [руководстве по каталогу Polaris](/ru/guides/use-cases/data-warehousing/polaris-catalog).

        Перед подключением убедитесь, что:

        * Используется ClickHouse версии 26.2 или выше.
        * У вас есть каталог Polaris с учетными данными OAuth-клиента.
        * У вас есть URI конечной точки хранилища данных таблиц Iceberg (например, `s3://company-iceberg-prod/warehouse/`).

        В выдвижной панели:

        1. Введите **идентификатор аккаунта каталога** (например, `ab12345.snowflakecomputing.com`).
        2. Введите **имя каталога** (например, `snowflake_open_catalog`).
        3. Введите OAuth **идентификатор клиента** и **секрет клиента**.
        4. Введите префикс URI **конечной точки хранилища** для хранения таблиц.
        5. Введите **имя базы данных** для базы данных ClickHouse, предоставляющей доступ к вашим таблицам Polaris.
      </Tab>

      <Tab title="BigLake Metastore" id="biglake">
        Подключитесь к Google Cloud BigLake Metastore (также известному как каталог среды выполнения Lakehouse) для работы с таблицами [Iceberg](/ru/reference/engines/table-engines/integrations/iceberg) в GCS. Полные инструкции по настройке см. в [руководстве по BigLake Metastore](/ru/guides/use-cases/data-warehousing/biglake-catalog).

        Перед подключением убедитесь, что:

        * используется ClickHouse версии 26.2 или выше;
        * у вас есть экземпляр BigLake Metastore с таблицами Iceberg в GCS;
        * у вас есть учетные данные Google Application Default Credentials (ADC): идентификатор клиента, секрет клиента, токен обновления и идентификатор проекта квоты.

        В выдвижной панели:

        1. Введите **Google ADC Client ID**, **Client Secret**, **Refresh Token** и **Quota Project ID**.
        2. Введите URI **бакета Cloud Storage** для данных таблиц (например, `gs://biglake-public-nyc-taxi-iceberg`).
        3. Введите **имя базы данных** ClickHouse, предоставляющей доступ к вашим таблицам BigLake.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Сохраните подключение" id="save-connection">
    После заполнения полей:

    1. Нажмите **Add catalog**. При сохранении ClickHouse проверит подключение и учетные данные.
    2. При успешном сохранении появится уведомление со ссылкой **View in SQL console**. Каталог будет указан в таблице **Linked catalogs** с его статусом подключения и количеством таблиц.

    В меню **Actions** в строке подключенного каталога можно удалить подключение к нему. При удалении из ClickHouse удаляется база данных каталога, но данные во внешнем каталоге не затрагиваются.
  </Step>
</Steps>

<div id="query-data">
  ## Выполните запрос к данным
</div>

<Steps>
  <Step title="Просмотрите таблицы каталога" id="view-tables">
    На странице **Источники данных** найдите свой каталог в таблице **Связанные каталоги** и нажмите **Просмотреть таблицы**.

    <Image img="/images/integrations/data-catalogs/linked-catalogs-table.png" alt="Таблица связанных каталогов с действием «Просмотреть таблицы»" size="lg" />

    ClickHouse откроет консоль SQL с выбранной базой данных каталога и отобразит список доступных таблиц.

    <Note>
      Таблицы могут появиться не сразу после подключения каталога. В зависимости от каталога отображение всех таблиц может занять до 3 минут.
    </Note>

    <Image img="/images/integrations/data-catalogs/catalog-tables-browser.png" alt="Браузер таблиц консоли SQL с таблицами каталога" size="lg" />
  </Step>

  <Step title="Выполните запрос" id="run-a-query">
    Введите запрос в редакторе SQL и нажмите **Запустить**. Заключите полное имя таблицы в обратные кавычки:

    ```sql
    SELECT * FROM `identity_profiles.identity_profiles_iceberg`
    ```

    <Image img="/images/integrations/data-catalogs/catalog-sql-query.png" alt="SQL-запрос с результатами: для имени таблицы с точкой используются обратные кавычки" size="lg" />
  </Step>
</Steps>

<div id="troubleshooting">
  ## Устранение неполадок
</div>

* Если в консоли SQL не отображаются ваши таблицы, проверьте учетные данные, сетевой доступ и типы таблиц в каталоге. Убедитесь, что ожидаемые таблицы используют поддерживаемые файловые и табличные форматы.
