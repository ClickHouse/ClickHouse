Все типы ClickPipes можно создавать и настраивать с помощью ресурса `clickhouse_clickpipe` в [Terraform-провайдере ClickHouse](https://registry.terraform.io/providers/ClickHouse/clickhouse/latest/docs/resources/clickpipe). На этой странице описаны настройка провайдера и примеры конфигурации для каждого поддерживаемого типа ClickPipe.

## Настройка провайдера {#provider-setup}

<Note>
  Поддержка ClickPipes доступна для общего использования начиная с версии провайдера **v3.14.0**.
  Если вы используете более раннюю версию, вам потребуется альфа-версия — подробности см. в
  [changelog провайдера](https://github.com/ClickHouse/terraform-provider-clickhouse/releases).
</Note>

Добавьте провайдер ClickHouse в конфигурацию Terraform:

```hcl
terraform {
  required_providers {
    clickhouse = {
      source  = "ClickHouse/clickhouse"
      version = ">= 3.14.0"
    }
  }
}

provider "clickhouse" {
  organization_id = var.organization_id
  token_key       = var.token_key
  token_secret    = var.token_secret
}
```

Инструкции по созданию ключа API для работы с провайдером см. в разделе [Управление ключами API](/ru/products/cloud/features/admin-features/api/openapi).

## Обзор ресурса {#resource-overview}

Ресурс `clickhouse_clickpipe` поддерживает следующие аргументы верхнего уровня:

| Аргумент         | Обязательно | Описание                                                                                      |
| ---------------- | ----------- | --------------------------------------------------------------------------------------------- |
| `name`           | Да          | Имя ClickPipe.                                                                                |
| `service_id`     | Да          | Идентификатор сервиса ClickHouse Cloud.                                                       |
| `source`         | Да          | Конфигурация источника (один блок source для каждого ClickPipe).                              |
| `destination`    | Да          | Конфигурация пункта назначения.                                                               |
| `scaling`        | Нет         | Количество реплик и их размер. По умолчанию — 1 реплика.                                      |
| `field_mappings` | Нет         | Пользовательские сопоставления полей между столбцами источника и пункта назначения.           |
| `settings`       | Нет         | Расширенные настройки ClickPipe.                                                              |
| `stopped`        | Нет         | Установите `true`, чтобы создать ClickPipe в остановленном состоянии. По умолчанию — `false`. |

Атрибуты `id` и `state` доступны только для чтения и заполняются ClickHouse Cloud после создания.

## GCP Workload Identity (бета) {#gcp-workload-identity}

Прежде чем использовать приведённые ниже примеры с Workload Identity, выполните шаги из [руководства по GCP Workload Identity](/ru/integrations/clickpipes/security/gcp-workload-identity#terraform): получите служебную учётную запись, управляемую ClickPipes, и предоставьте ей доступ к источнику.

## Пункт назначения {#destination}

Блок `destination` является общим для всех типов источников:

```hcl
destination {
  database      = "default"           # Целевая база данных. По умолчанию "default".
  table         = "my_table"          # Имя целевой таблицы. Обязательно для всех источников, кроме CDC.
  managed_table = true                # Разрешить ClickPipes создавать таблицу и управлять ею. По умолчанию true.

  table_definition {
    engine {
      type      = "MergeTree"         # MergeTree, ReplacingMergeTree, SummingMergeTree или Null.
    }
    sorting_key   = ["id", "ts"]      # Необязательно.
    partition_by  = "toYYYYMM(ts)"    # Необязательно.
  }

  columns {
    name = "id"
    type = "UInt64"
  }

  columns {
    name = "message"
    type = "String"
  }
}
```

Для CDC-источников (Postgres, MySQL, MongoDB, BigQuery) целевые таблицы создаются автоматически на основе схемы источника — обычно требуется только `database`.

## Примеры по типам ClickPipe {#examples}

### Kafka {#kafka}

Поддерживаемые значения для `type`: `kafka`, `confluent`, `msk`, `azureeventhub`, `redpanda`, `warpstream`, а также `gcmk` (закрытая предварительная версия).

```hcl
resource "clickhouse_clickpipe" "kafka_clickpipe" {
  name       = "My Kafka ClickPipe"
  service_id = var.service_id

  scaling {
    replicas               = 2
    replica_cpu_millicores = 250
    replica_memory_gb      = 1.0
  }

  source {
    kafka {
      type           = "confluent"
      format         = "JSONEachRow"
      brokers        = "broker.example.com:9092"
      topics         = "my_topic"
      consumer_group = "clickpipes-consumer-group"
      authentication = "PLAIN"

      credentials {
        username = "my_user"
        password = var.kafka_password
      }

      offset {
        strategy = "from_latest"
      }
    }
  }

  destination {
    table         = "my_table"
    managed_table = true

    table_definition {
      engine {
        type = "MergeTree"
      }
    }

    columns {
      name = "id"
      type = "UInt64"
    }

    columns {
      name = "message"
      type = "String"
    }

    columns {
      name = "timestamp"
      type = "DateTime"
    }
  }
}
```

#### Google Managed Kafka с использованием GCP Workload Identity {#gcmk-workload-identity}

Перед созданием ClickPipe назначьте служебной учётной записи ClickPipes роль `roles/managedkafka.client`. Для Google Managed Kafka требуется TLS. ACL Kafka должны предоставлять служебной учётной записи (`User:<service-account-email>`) права `READ` и `DESCRIBE` на выбранные топики и группы потребителей.

```hcl
resource "google_project_iam_member" "gcmk_client" {
  project = var.gcp_project_id
  role    = "roles/managedkafka.client"
  member  = "serviceAccount:${data.clickhouse_clickpipes_service_context.service.gcp_workload_identity.principal}"
}

resource "clickhouse_clickpipe" "gcmk_clickpipe" {
  name       = "My Google Managed Kafka ClickPipe"
  service_id = var.service_id

  source = {
    kafka = {
      type           = "gcmk"
      format         = "JSONEachRow"
      brokers        = "bootstrap.kafka.us-central1.managedkafka.example-project.cloud.goog:9092"
      topics         = "events"
      authentication = "SERVICE_ACCOUNT_WORKLOAD_IDENTITY"
    }
  }

  destination = {
    table         = "events"
    managed_table = true
    table_definition = {
      engine = {
        type = "MergeTree"
      }
    }
    columns = [
      {
        name = "id"
        type = "String"
      }
    ]
  }

  field_mappings = [
    {
      source_field      = "id"
      destination_field = "id"
    }
  ]

  depends_on = [google_project_iam_member.gcmk_client]
}
```

#### Kinesis с загруженной схемой Protobuf {#kinesis-protobuf-schema}

Задайте для `format` значение `Protobuf` и передайте в `protobuf_schema` закодированный в base64 файл `.proto` или сериализованный `FileDescriptorSet`. При загрузке схемы не настраивайте `schema_registry`.

```hcl
resource "clickhouse_clickpipe" "kinesis_protobuf_clickpipe" {
  name       = "My Kinesis Protobuf ClickPipe"
  service_id = var.service_id

  source {
    kinesis {
      format          = "Protobuf"
      stream_name     = "my-stream"
      region          = "us-east-1"
      iterator_type   = "TRIM_HORIZON"
      authentication  = "IAM_USER"
      protobuf_schema = filebase64("${path.module}/event.proto")

      access_key {
        access_key_id = var.aws_access_key_id
        secret_key    = var.aws_secret_key
      }
    }
  }

  destination {
    table         = "my_table"
    managed_table = true

    table_definition {
      engine {
        type = "MergeTree"
      }
    }

    columns {
      name = "id"
      type = "UInt64"
    }
  }
}
```

#### GCS с GCP Workload Identity {#gcs-workload-identity}

Выдав служебной учётной записи ClickPipes [необходимые разрешения GCS](/ru/integrations/clickpipes/object-storage/gcs/overview#permissions), замените приведённый выше блок `source` следующим:

```hcl
source = {
  object_storage = {
    type           = "gcs"
    url            = "gs://my-bucket/data/*.json"
    format         = "JSONEachRow"
    authentication = "SERVICE_ACCOUNT_WORKLOAD_IDENTITY"
  }
}
```

Для неупорядоченной ингестии также задайте `is_continuous = true` и укажите полное значение `queue_url` в формате `projects/<project-id>/subscriptions/<subscription-id>`.

### Postgres CDC {#postgres}

```hcl
resource "clickhouse_clickpipe" "postgres_cdc_clickpipe" {
  name       = "My Postgres CDC ClickPipe"
  service_id = var.service_id

  source {
    postgres {
      host     = "postgres.example.com"
      port     = 5432
      database = "mydb"

      credentials {
        username = "postgres_user"
        password = var.postgres_password
      }

      settings {
        replication_mode = "cdc"

        # Необязательные настройки
        sync_interval_seconds              = 60
        pull_batch_size                    = 100000
        allow_nullable_columns             = true
        initial_load_parallelism           = 4
        snapshot_num_rows_per_partition    = 100000
        snapshot_number_of_parallel_tables = 1
      }

      table_mappings {
        source_schema_name = "public"
        source_table       = "users"
        target_table       = "public_users"
      }

      table_mappings {
        source_schema_name = "public"
        source_table       = "orders"
        target_table       = "public_orders"

        # Необязательно
        excluded_columns       = ["internal_notes"]
        use_custom_sorting_key = true
        sorting_keys           = ["id", "created_at"]
        table_engine           = "ReplacingMergeTree"
      }
    }
  }

  destination {
    database = "default"
  }
}
```

### BigQuery {#bigquery}

`service_account_file` должен содержать содержимое JSON-файла ключа сервисного аккаунта GCP, закодированное в base64.

```hcl

  name       = "My BigQuery ClickPipe"
  service_id = var.service_id

  source {
    bigquery {
      snapshot_staging_path = "gs://my-staging-bucket/staging/"

      credentials {
        service_account_file = var.gcp_service_account_key
      }

      settings {
        replication_mode = "snapshot"

        # Необязательные настройки
        initial_load_parallelism           = 4
        snapshot_num_rows_per_partition    = 100000
        snapshot_number_of_parallel_tables = 2
        allow_nullable_columns             = true
      }

      table_mappings {
        source_dataset_name = "my_dataset"
        source_table        = "my_table"
        target_table        = "my_bigquery_table"
      }

      table_mappings {
        source_dataset_name    = "my_dataset"
        source_table           = "another_table"
        target_table           = "another_bigquery_table"
        table_engine           = "ReplacingMergeTree"
        use_custom_sorting_key = true
        sorting_keys           = ["id"]
        excluded_columns       = ["internal_col"]
      }
    }
  }

  destination {
    database = "default"
  }
}
```

#### BigQuery с GCP Workload Identity {#bigquery-workload-identity}

Выдав служебной учётной записи ClickPipes [необходимые разрешения BigQuery и GCS](/ru/integrations/clickpipes/bigquery/overview#permissions), замените приведённый выше блок `source` следующим:

```hcl
source = {
  bigquery = {
    authentication        = "SERVICE_ACCOUNT_WORKLOAD_IDENTITY"
    project_id            = var.gcp_project_id
    snapshot_staging_path = "gs://my-staging-bucket/staging/"

    settings = {
      replication_mode = "snapshot"
    }

    table_mappings = [{
      source_dataset_name = "my_dataset"
      source_table        = "my_table"
      target_table        = "my_bigquery_table"
    }]
  }
}
```

## Масштабирование {#scaling}

Все типы ClickPipe поддерживают блок `scaling` для настройки количества реплик и выделяемых им ресурсов:

```hcl
scaling {
  replicas               = 2     # По умолчанию: 1. Максимум: 10.
  replica_cpu_millicores = 500   # От 125 до 2000.
  replica_memory_gb      = 2.0   # От 0.5 до 8.0.
}
```
