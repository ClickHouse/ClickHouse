### Первоначальная загрузка {#initial-load}

При первоначальной загрузке выбранные таблицы из [набора данных](https://docs.cloud.google.com/bigquery/docs/datasets-intro) BigQuery копируются в ClickHouse. Её можно выполнить отдельно или затем перейти к непрерывной репликации. Для промежуточного хранения данных используется указанный вами бакет Google Cloud Storage (GCS). ClickPipe, настроенный только на первоначальную загрузку, останавливается после её завершения.

<Note>
  ClickPipes использует запросы BigQuery [`EXPORT DATA`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/export-statements), чтобы скопировать данные в бакет промежуточного хранилища. BigQuery взимает плату за выполнение этих запросов; хранение данных в GCS также оплачивается.
</Note>

### Непрерывная репликация {#cdc}

После первоначальной загрузки ClickPipe для BigQuery может периодически проверять наличие новых данных и переносить их в ClickHouse. Непрерывную репликацию можно запустить и без первоначальной загрузки. Выбирайте метод репликации в зависимости от того, как изменяется исходная таблица. В примерах показана структура запросов; ClickPipes выбирает настроенные столбцы и метаданные событий.

| Метод                                                                                                         | Когда использовать                                                                                                        | Что реплицирует ClickPipes                                                                                                      | Пример запроса                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| На основе запросов                                                                                            | У каждой вставленной или обновлённой строки есть столбец `TIMESTAMP`, значение которого обновляется при изменении строки. | Строки, у которых значение водяной метки новее последнего реплицированного значения. Удаления не обнаруживаются.                | `SELECT * FROM dataset.orders WHERE TIMESTAMP(updated_at) > @start AND TIMESTAMP(updated_at) <= @end`                                                           |
| [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) | Нужно реплицировать только новые строки таблицы.                                                                          | Строки, добавленные в таблицу, в том числе с помощью `MERGE`. Обновления и удаления не реплицируются.                           | [`SELECT * FROM APPENDS(TABLE dataset.orders, @start, @end)`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) |
| [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) | В ClickHouse должны отражаться вставки, обновления и удаления.                                                            | Изменения, зафиксированные в истории изменений BigQuery, в том числе изменения, внесённые с помощью `MERGE`, и очистка таблицы. | [`SELECT * FROM CHANGES(TABLE dataset.orders, @start, @end)`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) |

Для репликации на основе запросов выберите в каждой таблице столбец, который будет служить водяной меткой. Он должен иметь тип `TIMESTAMP` и входить в число реплицируемых столбцов. Устанавливайте его значение при вставке или обновлении строки. Если строка изменится, но значение водяной метки не обновится, ClickPipes не обнаружит это изменение. Если необходимо реплицировать удаления, используйте [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes).

Оба метода на основе событий работают только с обычными таблицами BigQuery. Для [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) включать историю изменений не нужно. Чтобы использовать [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes), включите историю изменений для каждой исходной таблицы перед созданием ClickPipe:

```sql
ALTER TABLE `project.dataset.table` SET OPTIONS (enable_change_history = TRUE);
```

[`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) также требует, чтобы для целевой таблицы был задан первичный ключ BigQuery или пользовательский ключ сортировки. Выберите столбцы, по которым можно однозначно определить строку, чтобы ClickPipes применял обновления и удаления к нужной строке. BigQuery не проверяет соблюдение ограничений первичного ключа, поэтому значения этих столбцов в исходных данных должны быть уникальными.

<Note>
  [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) и [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) могут считывать изменения только в пределах [окна путешествия во времени BigQuery](https://docs.cloud.google.com/bigquery/docs/time-travel) для исходной таблицы. По умолчанию оно составляет семь дней, но может быть сокращено до двух. Если репликация отстанет настолько, что изменения выйдут за пределы этого окна, заново выполните первоначальную загрузку, чтобы восстановить полную копию. BigQuery взимает плату за запросы, выполняемые всеми тремя методами. Включение истории изменений для [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) также увеличивает затраты на хранение в BigQuery.
</Note>

#### Учетные данные сервисного аккаунта {#service-account-credentials}

ClickPipes аутентифицируется в вашем проекте Google Cloud с помощью [ключа сервисного аккаунта](https://docs.cloud.google.com/iam/docs/keys-create-delete). Мы рекомендуем создать отдельный сервисный аккаунт с минимально необходимым набором [разрешений](#permissions), чтобы ClickPipes мог экспортировать данные из BigQuery, загружать их в промежуточный GCS-бакет и считывать в ClickHouse.

<div id="permissions">
  ### Разрешения {#permissions}
</div>

#### BigQuery {#bigquery}

Сервисному аккаунту нужны следующие роли BigQuery:

* [`roles/bigquery.dataViewer`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.dataViewer)
* [`roles/bigquery.jobUser`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.jobUser)

Для непрерывной репликации также предоставьте сервисному аккаунту роль [`roles/bigquery.readSessionUser`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.readSessionUser) на уровне проекта Google Cloud. ClickPipes использует [BigQuery Storage Read API](https://docs.cloud.google.com/bigquery/docs/reference/storage#permissions) для создания сеансов чтения и получения результатов запросов CDC. Эту роль нельзя предоставить на уровне набора данных. Сохраните для сервисного аккаунта роль `roles/bigquery.dataViewer` на уровне исходных наборов данных или таблиц, чтобы он мог читать их данные.

Чтобы дополнительно сузить область доступа, рекомендуем использовать [условия IAM](https://docs.cloud.google.com/bigquery/docs/conditions), чтобы ограничить ресурсы, к которым у роли есть доступ. Например, роль `dataViewer` можно ограничить конкретным набором данных, содержащим таблицы, которые вы хотите синхронизировать:

```bash
resource.name.startsWith("projects/<PROJECT_ID>/datasets/<DATASET_NAME>")
```

<div id="cloud-storage">
  #### Cloud Storage {#cloud-storage}
</div>

Сервисный аккаунт должен иметь следующие роли Cloud Storage:

* [`roles/storage.objectAdmin`](https://docs.cloud.google.com/storage/docs/access-control/iam-roles#storage.objectAdmin)
* [`roles/storage.bucketViewer`](https://docs.cloud.google.com/storage/docs/access-control/iam-roles#storage.bucketViewer)

Чтобы дополнительно сузить область доступа, мы рекомендуем использовать [условия IAM](https://docs.cloud.google.com/bigquery/docs/conditions), чтобы ограничить ресурсы, к которым у роли есть доступ. Например, можно ограничить роли `objectAdmin` и `bucketViewer`, предоставив им доступ только к выделенному бакету, созданному для синхронизации ClickPipes.

```bash
resource.name.startsWith("projects/_/buckets/<BUCKET_NAME>")
```
