С помощью ClickPipes вы можете выполнять ингестию данных из базы данных MongoDB в ClickHouse Cloud. Исходная база данных MongoDB может размещаться в собственной инфраструктуре или в облаке с использованием таких сервисов, как MongoDB Atlas.

MongoDB ClickPipes можно развертывать и настраивать вручную через интерфейс ClickPipes, а также программно с помощью [OpenAPI](/ru/integrations/clickpipes/programmatic-access/openapi) и [Terraform](/ru/integrations/clickpipes/programmatic-access/terraform).

## Предварительные требования {#prerequisites}

Перед началом убедитесь, что ваша база данных MongoDB правильно настроена для репликации. Шаги настройки зависят от того, как вы разворачиваете MongoDB, поэтому воспользуйтесь соответствующим руководством ниже:

1. [MongoDB Atlas](/ru/integrations/clickpipes/mongodb/source/atlas)

2. [Универсальный MongoDB](/ru/integrations/clickpipes/mongodb/source/generic)

3. [Amazon DocumentDB](/ru/integrations/clickpipes/mongodb/source/documentdb)

После настройки исходной базы данных MongoDB можно перейти к созданию ClickPipe.

#### Настройте дополнительные параметры {#advanced-settings}

При необходимости можно настроить дополнительные параметры. Ниже приведено краткое описание каждого из них:

* **Интервал синхронизации**: интервал, с которым ClickPipes будет опрашивать исходную базу данных на наличие изменений. Это влияет на целевой сервис ClickHouse, поэтому пользователям, чувствительным к стоимости, рекомендуется устанавливать более высокое значение (свыше `3600`).
* **Размер батча Pull**: количество строк, получаемых за один батч. Это параметр best effort, поэтому он может соблюдаться не во всех случаях.
* **Количество таблиц, обрабатываемых параллельно при создании снимка**: количество таблиц, которые будут извлекаться параллельно во время создания первоначального снимка. Это полезно, если у вас много таблиц и вы хотите контролировать, сколько из них обрабатывается параллельно.

### Настройка таблиц {#configure-the-tables}

6. Выберите таблицы, которые нужно реплицировать из исходной базы данных MongoDB. При выборе таблиц их также можно переименовать в целевой базе данных ClickHouse.

Коллекции можно реплицировать в двух режимах:

* **Ингестия по умолчанию**: документы загружаются в ClickHouse как есть, с типом JSON. В этом случае целевая таблица будет содержать отдельный столбец для `id` и столбец `doc` с полным документом.
* **Структурированная ингестия**: документы загружаются как строки таблицы в соответствии с общей схемой коллекции. Схема автоматически определяется по выборке данных при создании пайпа. Этот режим включается переключателем **Map document to columns** для коллекции.

Если структурированная ингестия включена, в разделе **Column settings** отображаются поля, найденные в выборке, и выведенные для них типы ClickHouse. Можно выбрать, какие поля реплицировать в виде столбцов; ключ документа `_id` включается всегда, с типом `String`.

<div className="ch-image-md">
  <Frame>
    ![Настройки структурированной ингестии для коллекции](/images/integrations/data-ingestion/clickpipes/mongodb/mongodb-structured-ingestion.webp)
  </Frame>
</div>

Поскольку коллекции MongoDB полиморфны (то есть документы в одной коллекции могут иметь разную схему), структурированная ингестия должна обрабатывать записи-выбросы:

* **Отсутствующие поля:** все структурированные столбцы загружаются как `Nullable`, поэтому если в документе нет какого-либо поля, соответствующий столбец получит значение `NULL`.

* **Лишние поля:** поля, не входящие в выведенную схему, сохраняются в формате JSON в столбце `_peerdb_malformed_data`, по одному ключу на поле. Каждый ключ содержит `"unexpected_field": true` и исходное значение в `value`:

  ```json
  {
    "rating": {
      "unexpected_field": true,
      "value": 4.5
    }
  }
  ```

  Эти данные легко запрашивать и анализировать. Например, так можно получить список неожиданных полей, найденных в таблице:

  ```sql
  SELECT DISTINCT arrayJoin(JSONAllPaths(_peerdb_malformed_data)) AS malformed
  FROM movies
  WHERE malformed LIKE '%.unexpected_field';
  ```

  📝 Примечание: если вы не хотите, чтобы значения лишних полей попадали в столбец `_peerdb_malformed_data`, включите для коллекции параметр **Hide unexpected values**.

* **Несоответствие типа поля:** значения, тип которых не соответствует типу столбца, также сохраняются в столбце `_peerdb_malformed_data`, по одному ключу на поле. Каждый ключ содержит `"type_mismatch": true` и исходное значение в `value`. Соответствующему столбцу присваивается `NULL`:

  ```json
  {
    "year": {
      "type_mismatch": true,
      "value": "two thousand nineteen"
    }
  }
  ```

  Чтобы прочитать поле независимо от того, соответствует ли его значение ожидаемому типу, объедините столбец с его резервным значением:

  ```sql
  SELECT name, coalesce(year, _peerdb_malformed_data.year.value)
  FROM movies;
  ```

📝 Примечание: поля, попавшие в `_peerdb_malformed_data`, можно рассматривать как выбросы, для которых используется резервная ингестия в JSON-столбец.

Поскольку при структурированной ингестии схема определяется до создания таблицы, в этом режиме можно задавать собственные выражения партиционирования и ключи сортировки на основе структурированных столбцов.
Все структурированные столбцы загружаются как `Nullable`. Учитывайте это при написании выражения ключа партиционирования или использовании таких столбцов в ключе сортировки. В этих случаях целевая таблица создаётся с настройкой `allow_nullable_key`.

📝 В обоих режимах ингестии можно включить параметр **Persist deleted documents**, чтобы события удаления сохраняли удалённые значения в целевом ClickHouse. Обратите внимание: для этого в исходной коллекции должен быть включён `changeStreamPreAndPostImage`.

## Важные замечания {#caveats}

Вот несколько важных моментов, которые следует учитывать при использовании этого коннектора:

* Требуется MongoDB версии 5.1.0 и выше.
* Для CDC мы используем нативный API Change Streams в MongoDB, который опирается на MongoDB oplog для фиксации изменений в реальном времени.
* По умолчанию документы из MongoDB реплицируются в ClickHouse в типе JSON. Это обеспечивает гибкое управление схемой и позволяет использовать в ClickHouse богатый набор JSON-операторов для запросов и аналитики. Подробнее о запросах к данным JSON можно узнать [здесь](/ru/reference/data-types/newjson).
