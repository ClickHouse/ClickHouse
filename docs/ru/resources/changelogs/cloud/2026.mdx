<Update label="17 августа 2026 г.">
  Обновления этой недели расширяют возможности платформы и улучшают наблюдаемость при эксплуатации. Managed Postgres теперь доступен в GCP для отдельных партнёров по проектированию, ресурсами ClickStack можно управлять через официальный Terraform-провайдер, а новые уведомления о биллинге заранее предупреждают клиентов об истечении кредитов или приостановке сервиса. Мы также улучшили трассировку для ClickHouse Agents и упростили вход через SAML.

  ### Managed Postgres теперь доступен в GCP

  [ClickHouse Cloud Managed Postgres](/ru/products/managed-postgres/overview) теперь доступен в GCP для отдельных партнёров по проектированию во всех публичных регионах GCP; `us-west1` стал первым частным регионом. Это расширяет доступность Managed Postgres для клиентов, работающих на GCP; закрытая предварительная версия запланирована на 2026-08.

  ### Управляйте ресурсами ClickStack с помощью Terraform

  Поддержка ClickStack теперь доступна в бета-версии 3.25.0 официального [Terraform-провайдера `ClickHouse/clickhouse`](https://registry.terraform.io/providers/ClickHouse/clickhouse/latest/docs#clickstack-alpha). Команды могут создавать, обновлять, импортировать и удалять панели мониторинга, оповещения, источники, сохранённые поиски, подключения и вебхуки с помощью стандартного процесса `terraform plan` и `terraform apply`. Интеграция поддерживает как Управляемый ClickStack, так и самоуправляемые развертывания.

  ### Новые уведомления о биллинге для кредитов и платежей

  Уведомления о биллинге теперь управляются через Центр уведомлений ClickHouse Cloud и доставляются через консоль, электронную почту и Slack. Клиенты заранее получают уведомления о скором истечении или исчерпании предоплаченных либо пробных кредитов, а также при добавлении кредитов, изменении способа оплаты или переходе аккаунта в льготный период при неуплате. Это даёт больше времени на продление, добавление кредитов или решение проблем с оплатой до приостановки сервиса.

  ### Открывайте трассировки сеансов Langfuse из ClickHouse Agents

  Администраторы организации теперь могут открыть соответствующий сеанс Langfuse непосредственно из чата [ClickHouse Agents](/ru/products/cloud/features/ai-ml/agents/index) и просмотреть трассировки всего диалога. Это упрощает анализ поведения агента и отладку многошаговых запусков. Улучшение доступно в публичной бете для новых чатов.

  ### Перенаправления SAML помогают предотвратить создание дублирующихся аккаунтов

  Когда пользователь пытается войти через Google или Microsoft, а для его организации настроен SAML, ClickHouse Cloud теперь перенаправляет его в правильный сценарий входа через SAML. Это помогает предотвратить случайное создание отдельной организации, когда пользователь намеревался получить доступ к существующему аккаунту.
</Update>

<Update label="13 июля 2026">
  В обновления этой недели входят sticky-маршрутизация реплик через обычный HTTPS, пользовательские даты начала расчетного периода биллинга и новые элементы управления первоначальной загрузкой для ClickPipes для объектного хранилища.

  ### Sticky-маршрутизация реплик через HTTPS (закрытая предварительная версия)

  Теперь вы можете закреплять запросы за конкретной репликой через стандартный HTTPS, добавив параметр `?session_id=` к обычному URL вашего сервиса, без специальных имен хостов или изменений DNS. Это сохраняет доступность объектов с областью видимости сеанса, таких как временные таблицы, между запросами, а также помогает повторным запросам попадать в прогретые локальные кэши реплики. Возможность постепенно становится доступной в рамках закрытой предварительной версии всем клиентам Enterprise, а для клиентов Scale — по запросу. Существующая маршрутизация на основе поддоменов продолжает работать, но со временем будет переведена на этот подход. См. документацию по [маршрутизации с учетом реплик](/ru/products/cloud/features/infrastructure/replica-aware-routing).

  ### Пользовательские даты начала расчетного периода биллинга

  Теперь вы можете запросить изменение даты биллинга вашей организации — дня месяца, в который начинается каждый расчетный период биллинга, — например, чтобы синхронизировать счета с календарным месяцем. Откройте тикет в поддержку и укажите желаемую дату. Даты биллинга применяются в UTC, и каждый счет охватывает использование с даты биллинга до той же даты следующего месяца (не включая ее).

  ### Пропуск первоначальной загрузки для ClickPipes для объектного хранилища

  [ClickPipes](/ru/integrations/clickpipes/home) для объектного хранилища (S3, GCS и Azure Blob Storage) теперь предлагают два способа управления первоначальной загрузкой при создании пайпа: **Start after**, который пропускает файлы вплоть до указанного ключа объекта включительно, и **Пропуск первоначальной загрузки**, который полностью пропускает уже существующие файлы и обрабатывает только уведомления о новых объектах. Ранее новый пайп всегда выполнял дозагрузку всех файлов по указанному пути. Эти два варианта взаимоисключающие и являются постоянными для конкретного пайпа: пропущенную дозагрузку нельзя запустить позже. Доступно в интерфейсе, Cloud API и Terraform v3.18.0 и более поздних версиях.
</Update>

  ### ClickHouse Managed Postgres (публичная бета)

Нативный CDC-конвейер передаёт данные напрямую в ClickHouse без промежуточной инфраструктуры, а расширение `pg_clickhouse` с открытым исходным кодом позволяет выполнять запросы к таблицам ClickHouse из стандартных сеансов Postgres.

  ### Горизонтальное автомасштабирование (закрытая предварительная версия)

  Горизонтальное автомасштабирование автоматически регулирует количество реплик в кластере ClickHouse Cloud: агрессивно масштабируется при всплесках спроса и постепенно сокращается по мере снижения нагрузки — так что командам с переменными высококонкурентными рабочими нагрузками больше не нужно вручную подбирать размер кластеров. В закрытой предварительной версии масштабирование основано на количестве параллельных запросов; поддержка сигналов CPU и памяти запланирована для публичной беты. Доступно клиентам уровней Enterprise и Scale на ClickHouse 26.2+.

  Примечание: На момент первоначального GA-запуска горизонтальное и вертикальное автомасштабирование являются взаимоисключающими. Горизонтальное автомасштабирование активируется только при отключённом вертикальном автомасштабировании (то есть когда для сервиса задан фиксированный размер). То же самое справедливо и для вертикального автомасштабирования: оно может быть включено только при фиксированном количестве реплик. В будущих релизах это поведение станет более гибким.

  ### ClickStack MCP Server (с открытым исходным кодом)

  Новый MCP-сервер ClickStack с открытым исходным кодом предоставляет внешним AI-агентам структурированные инструменты для расследований в области observability на базе ClickStack и ClickHouse. Он открывает семантические примитивы для логов, метрик и трейсов — с поддержкой анализа шаблонов в логах, расследования аномалий в трейсах, корреляционного анализа и отладки по нескольким сигналам — а также позволяет сохранять дашборды, поисковые запросы и алерты, сохраняя при этом нативный доступ к SQL для более глубокого изучения данных. Подключайте агентов, таких как Claude Code, Cursor, Codex или собственные фреймворки.

  Для получения подробной информации см. [документацию ClickStack MCP server](/ru/clickstack/mcp) и [публикацию в блоге Observability MCP server + AI Notebooks](https://clickhouse.com/blog/observability-mcp-server-ai-notebooks#clickstack-mcp-server).

  ### Исполняемые пользовательские функции

  {/* vale on */}

  Теперь вы можете написать функцию на Python, упаковать её в zip-архив, загрузить в кластер и вызывать из SQL как любую встроенную функцию. ClickHouse запускает пул долгоживущих изолированных процессов и пропускает через них строки на скорости выполнения запроса, поэтому функцию можно вызывать в любом месте, где работает SQL: в разовых запросах, в JOINах и даже в materialized view, срабатывающих при каждой вставке. Ваш код модели хранится прямо рядом с данными, а развертывание — это всего одна страница загрузки в консоли Cloud.

  Чтобы продемонстрировать возможности этого подхода, мы создали [демо](https://github.com/ClickHouse/stock-anomaly-udf). На основе данных о биржевых сделках в реальном времени из StockHouse мы обучили небольшой автоэнкодер PyTorch для оценки тиков торгов акциями на предмет аномалий в процессе их приёма. Всё решение состоит из одной пользовательской функции (UDF) и одного DDL-оператора, а всё остальное — обычный SQL. Мы также добавили предварительный просмотр UDF с сетевым доступом (закрытая бета), которые позволяют UDF выполнять исходящие HTTPS-вызовы. С их помощью мы подтягиваем новости и документы SEC, а затем с помощью Claude классифицируем причины аномального поведения той или иной сделки.

  Подробнее см. в [блоге с анонсом](https://clickhouse.com/blog/executable-udfs-clickhouse-cloud-beta) или в [документации](/ru/products/cloud/features/sql-console-features/user-defined-functions)
</Update>

  ### Оповещения о расходах организации теперь в статусе GA

  Оповещения организации о [расходах](/ru/products/cloud/reference/billing/spend-alerts) теперь общедоступны. В качестве каналов уведомлений можно выбрать Email, консоль Cloud (интерфейс) и/или Slack. Оповещения основаны на общем объеме потребления организации, срабатывают каждый час и автоматически сбрасываются в начале каждого расчетного периода. Требуется роль Org Admin или Billing Admin.

Для сервисов ClickHouse Cloud, созданных в этом регионе начиная с 19 мая 2026 года, ClickPipes будут размещаться в том же регионе. Для сервисов, созданных до этой даты, ClickPipes по умолчанию будут использовать регион `us-east-2`; если это ваш случай, [свяжитесь с нашей командой](https://clickhouse.com/company/contact?loc=clickpipes), чтобы перевести сервис на новый регион.

  Все основные сервисы теперь поддерживают переход в режим простоя.

  ### Клиент Python v1.0.0

  Мажорный релиз [clickhouse-connect](/ru/integrations/language-clients/python/index), клиента Python для ClickHouse. Основные изменения:

  * Полноценный диалект SQLAlchemy с более глубокой поддержкой ClickHouse SQL
  * Нативный асинхронный клиент на базе aiohttp с полным паритетом возможностей, включая стриминг
  * Значительное повышение производительности для DateTime, DateTime64, вставки числовых типов фиксированной ширины, Maps, Decimals и BigDecimals
  * Переработанная обработка часовых поясов с новыми параметрами `tz_mode` и `tz_source`
  * Нативная запись в столбцы Variant
  * Ленивые импорты для необязательных зависимостей (numpy, pandas, pyarrow, polars), ускоряющие базовый import в 4 раза
  * Экспериментальная поддержка free-threading в Python 3.14

  **Несовместимые изменения:** прекращена поддержка Python &lt; 3.9 и Pandas 1.x. Ознакомьтесь с [примечаниями к релизу](https://github.com/ClickHouse/clickhouse-connect/releases), чтобы узнать о других несовместимых изменениях, связанных с часовыми поясами.

  ### Построение графиков и оповещений на основе SQL в ClickStack

  [ClickStack](/ru/clickstack/overview) теперь поддерживает создание графиков и оповещений с использованием произвольных запросов ClickHouse SQL. Пользователи могут писать raw SQL прямо в редакторе панелей мониторинга и конструкторе оповещений с полной поддержкой оконных функций, CTE, многоэтапных запросов и нативных аналитических функций ClickHouse. Оповещения на основе SQL позволяют закодировать всю логику срабатывания прямо в самом запросе, открывая возможности для обнаружения аномалий, средних с лагом и статистического выявления всплесков. Возможность доступна во всех развертываниях ClickStack (Cloud, Private, BYOC, OSS). Подробнее см. [визуализации на основе SQL](/ru/clickstack/features/dashboards/sql-visualizations) и [интерпретацию результатов SQL-оповещений](/ru/clickstack/features/alerts#sql-result-interpretation).

  ### Query insights для Postgres (закрытая предварительная версия)

  Новая вкладка **Query insights** теперь доступна в [ClickHouse Managed Postgres](/ru/products/managed-postgres/overview) (закрытая предварительная версия). Она ранжирует каждый шаблон запроса по влиянию и показывает, почему он работает медленно, в трех разделах:

  * **Overview** — общее состояние базы данных на одном экране
  * **Patterns** — таблица с сортировкой по времени выполнения, CPU, ошибкам и P95
  * **Выдвижная панель по каждому шаблону** — процентильные значения задержки, CPU vs I/O, cache vs disk, сбросы временных данных на диск, нехватка parallel workers и объем WAL

  Основано на [pg&#95;stat&#95;ch](https://github.com/ClickHouse/pg_stat_ch) — расширении Postgres с открытым исходным кодом.

<Update label="10 апреля 2026 г.">
  ### Централизованный биллинг через маркетплейс

  Теперь клиенты могут консолидировать биллинг между организациями с помощью одной подписки через облачный маркетплейс (AWS, Azure и GCP). Основные изменения включают:

  * **Совместное использование подписки через маркетплейс:** Переведите организацию с оплаты кредитной картой на существующую подписку через маркетплейс из другой организации, чтобы не создавать дополнительную подписку через маркетплейс. Консолидируется только использование PAYG (предоплаченные кредиты не включаются).
  * **Обновление подписок через маркетплейс:** Замените подписку организации через маркетплейс на подписку, используемую другой организацией.
  * **Резервный способ оплаты:** Организации, использующие биллинг через маркетплейс, теперь могут добавить кредитную карту в качестве резервного способа оплаты, если основная подписка через маркетплейс будет отменена или истечет.

  Подробнее см. в [документации по биллингу](/ru/products/cloud/reference/billing/managing-payment-methods).

<Update label="3 апреля 2026 г.">
  * **Более интеллектуальное автомасштабирование с двухоконным рекомендателем:** ClickHouse Cloud теперь использует для вертикального автомасштабирования подход с двумя окнами анализа прошлой нагрузки: вместо прежнего единственного 30-часового окна применяются 3-часовое «малое окно» и 30-часовое «большое окно». Это сокращает задержку scale-down с 30 часов до всего 3 часов, снижая затраты на инфраструктуру для переменных рабочих нагрузок без ущерба для скорости scale-up. Подробнее читайте в [публикации блога](https://clickhouse.com/blog/smarter-auto-scaling).
  * **Monitoring в консоли Cloud:** Новые обзорные и инфраструктурные панели дают лучшее представление о поведении серверов ClickHouse. Пользователи с ролью Admin теперь получают уведомления по электронной почте о распространенных проблемах при использовании ClickHouse Cloud. Подробнее читайте в [публикации блога](https://clickhouse.com/blog/clickhouse-cloud-new-monitoring-capabilities) для более подробной информации.
  * **Compute-compute separation (хранилища):** Поддержка auto-idling для основных сервисов (также называемых родительскими сервисами) постепенно становится доступной в рамках публичного предварительного просмотра. Если эта возможность еще не включена для вашей организации, [обратитесь в службу поддержки](https://clickhouse.com/support/program), чтобы получить доступ. После выхода этой возможности в общую доступность поведение по умолчанию будет таким: для существующих основных сервисов можно будет включить auto-idling, а для новых основных сервисов он будет включен по умолчанию.
  * **Интеграция с каталогом данных:** ClickHouse Cloud теперь поддерживает Iceberg REST Catalog и Microsoft OneLake как интеграции с каталогами озер данных в интерфейсе источников данных. После подключения каталог отображается как база данных, что позволяет читать таблицы Iceberg напрямую, без дублирования данных.
  * **Собственное облако (BYOC) на GCP теперь общедоступно:** ClickHouse BYOC теперь общедоступен в Google Cloud, что позволяет развертывать сервисы ClickHouse в вашем собственном проекте GCP и соблюдать строгие требования к резидентности данных. Подробнее читайте в [документации](/ru/products/cloud/guides/infrastructure/deployment-options/byoc/overview) и [публикации блога](https://clickhouse.com/blog/byoc-gcp-ga). Вы можете [связаться с нами](https://clickhouse.com/cloud/bring-your-own-cloud), чтобы запросить доступ.
  * **Уведомления о биллинге для предоплаченных кредитов и изменениях способа оплаты:** ClickHouse Cloud теперь отправляет уведомления, когда в вашу организацию добавляются предоплаченные кредиты в рамках контракта с обязательствами или когда обновляется способ оплаты (кредитная карта или подписка через маркетплейс). По умолчанию уведомления включены в интерфейсе и по электронной почте, а при необходимости их также можно настроить для отправки в Slack.
