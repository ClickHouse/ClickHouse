ClickHouse Cloud предлагает разные каналы релизов, чтобы учитывать различные потребности пользователей в плане стабильности, доступа к новым возможностям и предсказуемости обновлений. У каждого канала свой график обновлений, и каждый из них предназначен для разных сценариев использования — как для пользователей, которым нужен немедленный доступ к новым релизам, так и для тех, кто хочет отложить обновление, чтобы получить максимально стабильную версию релиза.

Запланированные окна обновления доступны во всех каналах релизов для сервисов уровня Enterprise. Эта возможность позволяет настроить временное окно в заданный день недели для обновлений.

## График выпусков {#release-schedule}

<Warning>
  **Как понимать даты релизов**

  Указанные ниже даты начала показывают, когда ClickHouse **начинает поэтапное развёртывание** новой версии базы данных в каждом канале релизов, а не когда будет обновлён именно ваш сервис.

  * Поэтапное развёртывание выполняется автоматически и происходит постепенно в течение нескольких недель
  * Сервисы с настроенными запланированными окнами обновления обновляются в своё окно на неделе после завершения поэтапного развёртывания в канале (начиная с понедельника, 10:00 UTC)
  * Завершение поэтапного развёртывания может быть отложено из-за приостановки поэтапного развёртывания (например, на время праздников) или по результатам мониторинга состояния
  * [Дата EOL](https://clickhouse.com/legal/support-services-policy) наступает не ранее чем через 60 дней после завершения поэтапного развёртывания в канале Slow. Для релизов, у которых дата завершения в канале Slow ещё не запланирована, дата EOL указывается как `TBD`.

  Чтобы заранее протестировать обновления перед их применением в production, используйте канал Fast или Regular для непродуктивных сервисов, а канал Slow — для production-сервисов.
</Warning>

<Note>
  **Предстоящие периоды заморозки релизов**

  Во время заморозки релизов ClickHouse приостанавливает поэтапное развёртывание и не обновляет сервисы, даже если для сервиса настроено запланированное окно обновления. Исключение составляют критические патчи безопасности и исправления проблем, которые могут привести к повреждению или потере данных.

  Запланированные периоды заморозки (даты указаны в UTC, включительно):

  * **Чёрная пятница и Киберпонедельник:** с 2026-11-24 по 2026-12-01
  * **Рождество и Новый год:** с 2026-12-23 по 2027-01-03

  Если вы готовитесь к повышенной нагрузке в эти периоды, см. раздел [Подготовка к пиковым нагрузкам](/ru/products/cloud/features/scaling/preparing-for-traffic-spikes).
</Note>
