## Устранение ошибки проверки разработчика в macOS {#fix-the-developer-verification-error-in-macos}

По умолчанию macOS не запускает приложения и инструменты, загруженные из интернета, если они не подписаны идентифицированным разработчиком и не прошли нотаризацию в Apple.

Начиная с релиза 26.7.4 (а также во всех релизах 26.8 и новее) сборки ClickHouse для macOS подписываются сертификатом Developer ID компании ClickHouse Inc. и проходят нотаризацию в Apple. Они публикуются на [странице релизов GitHub](https://github.com/ClickHouse/ClickHouse/releases) в виде архивов `clickhouse-macos.zip` (Intel) и `clickhouse-macos-aarch64.zip` (Apple silicon); именно их устанавливает Homebrew cask. Если вы используете одну из этих сборок, macOS запускает `clickhouse` без каких-либо предупреждений, и эта статья вам не понадобится.

Ошибка всё же может возникнуть, если вы запускаете неподписанный бинарный файл, который macOS поместила в карантин, например:

* более старый релиз ClickHouse, установленный через Homebrew, — выполните `brew upgrade --cask clickhouse`, чтобы получить подписанную версию;
* самораспаковывающийся бинарный файл `clickhouse-macos` или `clickhouse-macos-aarch64` со страницы релизов GitHub, загруженный через браузер, — вместо него загрузите файл `.zip` того же релиза;
* релиз старше 26.7.4, загруженный через браузер.

Бинарный файл, установленный с помощью `curl https://clickhouse.com/ | sh`, не подписан, однако `curl` не помещает загружаемые файлы в карантин, поэтому macOS запускает его без этой ошибки.

При попытке запустить бинарный файл `clickhouse`, находящийся в карантине, может появиться следующая ошибка:

<Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/dev-verification-error.webp" size="md" alt="Диалоговое окно ошибки проверки разработчика в macOS" border />

Если перейти на подписанную сборку невозможно, снимите с бинарного файла карантин — в Системных настройках или в терминале.

## Процесс через системные настройки {#system-settings-process}

1. Попробуйте один раз запустить бинарный файл `clickhouse`, чтобы macOS показала описанную выше ошибку и зарегистрировала заблокированный бинарный файл.

2. Откройте **Системные настройки**.

3. Перейдите в раздел **Конфиденциальность и безопасность**:

   <Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/privacy-and-security-default-view.webp" size="md" alt="Стандартный вид настроек macOS «Конфиденциальность и безопасность»" border />

4. Прокрутите вниз до раздела **Безопасность** и найдите сообщение: *«Использование „clickhouse-macos-aarch64“ было заблокировано, так как программа не получена от идентифицированного разработчика»*.

5. Нажмите **Всё равно разрешить** (в последних версиях macOS — **Всё равно открыть**).

   <Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/privacy-and-security-screen-allow-anyway.webp" size="md" alt="Настройки macOS «Конфиденциальность и безопасность» с кнопкой «Все равно разрешить»" border />

6. Введите пароль пользователя macOS.

После этого вы сможете выполнять команды `clickhouse` в терминале. При следующем запуске macOS может ещё раз запросить подтверждение.

## Процесс в терминале {#terminal-process}

Если кнопка в Системных настройках не решает проблему или вы предпочитаете командную строку, снимите с бинарного файла атрибут карантина с помощью `xattr`.

Если `clickhouse` находится в вашем `PATH`, выясните, где именно он расположен:

```shell
which clickhouse
```

В результате вы увидите примерно следующее:

```shell
/opt/homebrew/bin/clickhouse
```

Удалите `clickhouse` из карантина, выполнив `xattr -d com.apple.quarantine`, а затем добавив путь из предыдущей команды:

```shell
xattr -d com.apple.quarantine /opt/homebrew/bin/clickhouse
```

Теперь вы сможете запустить исполняемый файл `clickhouse`:

```shell
clickhouse
```

В результате вы увидите примерно следующее:

```shell
Use one of the following commands:
clickhouse local [args]
clickhouse client [args]
clickhouse benchmark [args]
...
```
