<div id="description">
  ## Descripción
</div>

Contiene estadísticas de selectividad obtenidas mediante muestreo, recopiladas durante la lectura de tablas `MergeTree`. La tabla se puebla solo cuando [`predicate_statistics_sample_rate`](/es/operations/settings/settings#predicate_statistics_sample_rate) es mayor que `0`.

Use esta tabla para inspeccionar cuán selectivos son los predicados de usuario en cargas de trabajo reales y cuántos gránulos permanecen después del filtrado por clave primaria o índice de omisión. Los datos están pensados como entrada para recomendaciones de índices y proyecciones basadas en la carga de trabajo.

<div id="row-shapes">
  ## Estructura de las filas
</div>

Una sola consulta puede producir dos tipos de filas en `system.predicate_statistics_log`:

* **Filas de filtro**, emitidas en cada paso de prewhere/filtro en `MergeTreeSelectProcessor`. Rellenan `predicate_expression`, `input_rows`, `passed_rows`, `filter_selectivity` y las columnas del predicado completo `total_input_rows`, `total_passed_rows`, `total_selectivity`. Las columnas relacionadas con los índices quedan vacías.
* **Filas de índice**, emitidas en cada paso de lectura en `ReadFromMergeTree`. Rellenan los arrays `index_names`, `index_types`, `total_granules`, `granules_after` e `index_selectivities`, con una entrada por cada etapa del índice (clave primaria, partición, índices de omisión). Las columnas relacionadas con el predicado quedan vacías.

Las filas de filtro y las filas de índice de la misma consulta comparten el mismo `query_id` y `table`, por lo que se pueden combinar cuando se necesiten ambas.

<div id="sampling-and-overhead">
  ## Muestreo y sobrecarga
</div>

El muestreo se controla mediante [`predicate_statistics_sample_rate`](/es/operations/settings/settings#predicate_statistics_sample_rate):

* `0` desactiva la recopilación.
* `1` toma muestras de cada consulta.
* `N > 1` toma muestras de aproximadamente `1 / N` de las consultas, aplicando hash sobre `query_id`.

Los valores más bajos generan más datos, pero añaden carga de CPU en la ruta de lectura y más escrituras en el log del sistema. Después de habilitar esta configuración, use [`SYSTEM FLUSH LOGS`](/es/sql-reference/statements/system#flush-logs) si necesita que las filas aparezcan de inmediato.

  ## Columnas
</div>

* `hostname` ([LowCardinality(String)](/es/sql-reference/data-types/lowcardinality)) — Nombre del host del servidor que ejecuta la consulta.
* `event_date` ([Date](/es/sql-reference/data-types/date)) — Fecha del evento.
* `event_time` ([DateTime](/es/sql-reference/data-types/datetime)) — Marca temporal en la que se escribió esta entrada de log.
* `database` ([LowCardinality(String)](/es/sql-reference/data-types/lowcardinality)) — Nombre de la base de datos de la tabla de destino.
* `table` ([LowCardinality(String)](/es/sql-reference/data-types/lowcardinality)) — Nombre de la tabla de destino.
* `query_id` ([String](/es/sql-reference/data-types/string)) — ID de la consulta para vincularla con query&#95;log.
* `predicate_expression` ([String](/es/sql-reference/data-types/string)) — Expresión de filtro completa procesada por este paso de prewhere/filter (volcado de ActionsDAG).
* `input_rows` ([UInt64](/es/sql-reference/data-types/int-uint)) — Filas que entran en este paso de prewhere/filter.
* `passed_rows` ([UInt64](/es/sql-reference/data-types/int-uint)) — Filas que superan este paso de prewhere/filter.
* `filter_selectivity` ([Float64](/es/sql-reference/data-types/float)) — Selectividad de este paso: passed&#95;rows / input&#95;rows.
* `total_input_rows` ([UInt64](/es/sql-reference/data-types/int-uint)) — Filas que entran en el primer paso de prewhere (total de filas leídas de los gránulos).
* `total_passed_rows` ([UInt64](/es/sql-reference/data-types/int-uint)) — Filas que superan todos los pasos de prewhere (filas entregadas a la consulta).
* `total_selectivity` ([Float64](/es/sql-reference/data-types/float)) — Selectividad de todo el predicado: total&#95;passed&#95;rows / total&#95;input&#95;rows.
* `index_names` ([Array(LowCardinality(String))](/es/sql-reference/data-types/array)) — Nombres de los índices aplicados, p. ej. [&#39;PrimaryKey&#39;, &#39;idx&#95;bf&#95;status&#39;] (solo en filas de índice).
* `index_types` ([Array(LowCardinality(String))](/es/sql-reference/data-types/array)) — Tipos de índices aplicados: PrimaryKey, Skip, MinMax, Partition (solo en filas de índice).
* `total_granules` ([Array(UInt64)](/es/sql-reference/data-types/array)) — Gránulos que entran en cada etapa de índice (solo en filas de índice).
* `granules_after` ([Array(UInt64)](/es/sql-reference/data-types/array)) — Gránulos restantes después de cada etapa de índice (solo en filas de índice).
* `index_selectivities` ([Array(Float64)](/es/sql-reference/data-types/array)) — Selectividad por índice: granules&#95;after / total&#95;granules (solo en filas de índice).

<div id="example">
  ## Ejemplo
</div>

```sql
SET predicate_statistics_sample_rate = 1;

SELECT *
FROM hits
WHERE URL LIKE '%/product/%' AND EventDate >= today() - 7
FORMAT Null;

SYSTEM FLUSH LOGS predicate_statistics_log;

SELECT
    query_id,
    predicate_expression,
    round(filter_selectivity, 3) AS step_selectivity,
    round(total_selectivity, 3) AS query_selectivity,
    index_names,
    index_selectivities
FROM system.predicate_statistics_log
WHERE table = 'hits'
ORDER BY event_time DESC
LIMIT 10;
```
