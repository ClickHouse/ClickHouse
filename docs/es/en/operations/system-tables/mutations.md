<div id="description">
  ## Descripción
</div>

La tabla contiene información sobre las [mutaciones](/es/sql-reference/statements/alter/index.md#mutations) de las tablas [MergeTree](/es/engines/table-engines/mergetree-family/mergetree.md) y su progreso. Cada comando de mutación se representa con una sola fila.

<div id="columns">
  ## Columnas:
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/es/sql-reference/data-types/string)) — El nombre de la base de datos a la que se aplicó la mutación.
* `table` ([String](/es/sql-reference/data-types/string)) — El nombre de la tabla a la que se aplicó la mutación.
* `mutation_id` ([String](/es/sql-reference/data-types/string)) — El ID de la mutación. En las tablas replicadas, estos ID corresponden a nombres de znode en el directorio `<table_path_in_clickhouse_keeper>/mutations/` de ClickHouse Keeper. En las tablas no replicadas, los ID corresponden a nombres de archivo en el directorio de datos de la tabla.
* `command` ([String](/es/sql-reference/data-types/string)) — La cadena del comando de mutación (la parte de la consulta después de ALTER TABLE [db.]table).
* `create_time` ([DateTime](/es/sql-reference/data-types/datetime)) — Fecha y hora en que se envió el comando de mutación para su ejecución.
* `block_numbers.partition_id` ([Array(String)](/es/sql-reference/data-types/array)) — Para las mutaciones de tablas replicadas, el array contiene los ID de las particiones (un registro por cada partición). Para las mutaciones de tablas no replicadas, el array está vacío.
* `block_numbers.number` ([Array(Int64)](/es/sql-reference/data-types/array)) — Para las mutaciones de tablas replicadas, el array contiene un registro por cada partición con el número de bloque adquirido por la mutación. En la partición, solo se mutarán las partes que contengan bloques con números menores que este. En las tablas no replicadas, los números de bloque de todas las particiones forman una única secuencia. Esto significa que, para las mutaciones de tablas no replicadas, la columna contendrá un registro con un único número de bloque adquirido por la mutación.
* `parts_in_progress_names` ([Array(String)](/es/sql-reference/data-types/array)) — Un array con los nombres de las partes de datos que se están mutando actualmente.
* `parts_to_do_names` ([Array(String)](/es/sql-reference/data-types/array)) — Un array con los nombres de las partes de datos que deben mutarse para que la mutación se complete.
* `parts_to_do` ([Int64](/es/sql-reference/data-types/int-uint)) — El número de partes de datos que deben mutarse para que la mutación se complete. Nota: incluso si `parts_to_do` = 0, es posible que una mutación de una tabla replicada todavía no se haya completado debido a una operación INSERT de larga duración que está creando una nueva parte de datos que deberá mutarse.
* `parts_postpone_reasons` ([Map(String, String)](/es/sql-reference/data-types/map)) — Un mapa de nombres de partes a los motivos por los que se posponen.
* `is_done` ([UInt8](/es/sql-reference/data-types/int-uint)) — El indicador de si la mutación se ha completado o no. Valores posibles: 1 si la mutación se ha completado, 0 si la mutación sigue en proceso.
* `is_killed` ([UInt8](/es/sql-reference/data-types/int-uint)) — Indica si una mutación ha sido cancelada. Solo disponible en ClickHouse Cloud. Nota: is&#95;killed=1 no significa necesariamente que la mutación se haya finalizado por completo. Es posible que una mutación permanezca en un estado en el que is&#95;killed=1 e is&#95;done=0 durante un período prolongado. Esto puede ocurrir si otra mutación de larga duración está bloqueando la mutación cancelada. Esta es una situación normal.
* `latest_failed_part` ([String](/es/sql-reference/data-types/string)) — El nombre de la parte más reciente que no pudo mutarse.
* `latest_fail_time` ([DateTime](/es/sql-reference/data-types/datetime)) — La fecha y hora del fallo más reciente al mutar una parte.
* `latest_fail_reason` ([String](/es/sql-reference/data-types/string)) — El mensaje de excepción que causó el fallo más reciente al mutar una parte.
* `latest_fail_error_code_name` ([String](/es/sql-reference/data-types/string)) — El código de error de la excepción que causó el fallo más reciente al mutar una parte.

{/*AUTOGENERATED_END*/ }

:::note

* Si el nombre de una parte no está en `parts_postpone_reasons` y aún no ha sido mutada, significa que esa parte todavía no se ha programado para una mutación.

* El nombre de parte `all_parts` representa todas las partes que aún no han sido mutadas.
  :::

* `is_killed` ([UInt8](/es/sql-reference/data-types/int-uint.md)) — Indica si una mutación ha sido cancelada. **Solo disponible en ClickHouse Cloud.**

:::note
`is_killed=1` no significa necesariamente que la mutación se haya finalizado por completo. Es posible que una mutación permanezca en un estado en el que `is_killed=1` e `is_done=0` durante un período prolongado. Esto puede ocurrir si otra mutación de larga duración está bloqueando la mutación cancelada. Esta es una situación normal.
:::

* `is_done` ([UInt8](/es/sql-reference/data-types/int-uint.md)) — El indicador de si la mutación se ha completado o no. Valores posibles:
  * `1` si la mutación se ha completado,
  * `0` si la mutación sigue en proceso.

:::note
Aunque `parts_to_do = 0`, es posible que una mutación de una tabla replicada aún no se haya completado debido a una consulta `INSERT` de larga duración, que creará una nueva parte de datos a la que deberá aplicarse la mutación.
:::

Si hubo problemas al mutar algunas partes de datos, las siguientes columnas contienen información adicional:

* `latest_failed_part` ([String](/es/sql-reference/data-types/string.md)) — El nombre de la parte más reciente a la que no se pudo aplicar la mutación.
* `latest_fail_time` ([DateTime](/es/sql-reference/data-types/datetime.md)) — La fecha y hora del fallo más reciente al aplicar una mutación a una parte.
* `latest_fail_reason` ([String](/es/sql-reference/data-types/string.md)) — El mensaje de excepción que provocó el fallo más reciente al aplicar una mutación a una parte.

<div id="monitoring-mutations">
  ## Seguimiento de mutaciones
</div>

Para seguir el progreso en la tabla `system.mutations`, use la siguiente consulta:

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

Nota: esto requiere permisos de lectura en las tablas `system.*`.

:::tip Uso de Cloud
En ClickHouse Cloud, la tabla `system.mutations` de cada nodo contiene todas las mutaciones del clúster, por lo que no es necesario usar `clusterAllReplicas`.
:::
