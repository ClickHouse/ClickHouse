<div id="description">
  ## Descripción
</div>

Contiene una lista de todas las operaciones `BACKUP` o `RESTORE`, con sus estados actuales y otras propiedades. Tenga en cuenta que esta tabla no es persistente y solo muestra las operaciones ejecutadas después del último reinicio del servidor.

<div id="columns">
  ## Columnas
</div>

{/*AUTOGENERATED_START*/ }

* `id` ([String](/es/sql-reference/data-types/string)) — ID de la operación; puede pasarse mediante SETTINGS id=... o ser un UUID generado aleatoriamente.
* `name` ([String](/es/sql-reference/data-types/string)) — Nombre de la operación, una cadena como `Disk('backups', 'my_backup')`
* `base_backup_name` ([String](/es/sql-reference/data-types/string)) — Nombre de la operación de la copia de seguridad base, una cadena como `Disk('backups', 'my_base_backup')`
* `query_id` ([String](/es/sql-reference/data-types/string)) — Query ID de la consulta que inició la copia de seguridad.
* `status` ([Enum8(&#39;CREATING&#95;BACKUP&#39; = 0, &#39;BACKUP&#95;CREATED&#39; = 1, &#39;BACKUP&#95;FAILED&#39; = 2, &#39;RESTORING&#39; = 3, &#39;RESTORED&#39; = 4, &#39;RESTORE&#95;FAILED&#39; = 5, &#39;BACKUP&#95;CANCELLED&#39; = 6, &#39;RESTORE&#95;CANCELLED&#39; = 7)](/es/sql-reference/data-types/enum)) — Estado de la operación de copia de seguridad o restauración.
* `error` ([String](/es/sql-reference/data-types/string)) — El mensaje de error, si existe.
* `start_time` ([DateTime64(6)](/es/sql-reference/data-types/datetime64)) — Hora de inicio de la operación.
* `end_time` ([DateTime64(6)](/es/sql-reference/data-types/datetime64)) — Hora de finalización de la operación.
* `num_files` ([UInt64](/es/sql-reference/data-types/int-uint)) — Número de archivos almacenados en la copia de seguridad.
* `total_size` ([UInt64](/es/sql-reference/data-types/int-uint)) — Tamaño total de los archivos almacenados en la copia de seguridad.
* `num_entries` ([UInt64](/es/sql-reference/data-types/int-uint)) — Número de entradas de la copia de seguridad; es decir, el número de archivos dentro de la carpeta si la copia de seguridad se almacena como una carpeta.
* `uncompressed_size` ([UInt64](/es/sql-reference/data-types/int-uint)) — Tamaño sin comprimir de la copia de seguridad.
* `compressed_size` ([UInt64](/es/sql-reference/data-types/int-uint)) — Tamaño comprimido de la copia de seguridad.
* `files_read` ([UInt64](/es/sql-reference/data-types/int-uint)) — Devuelve el número de archivos leídos durante RESTORE desde esta copia de seguridad.
* `bytes_read` ([UInt64](/es/sql-reference/data-types/int-uint)) — Devuelve el tamaño total de los archivos leídos durante RESTORE desde esta copia de seguridad.
* `ProfileEvents` ([Map(LowCardinality(String), UInt64)](/es/sql-reference/data-types/map)) — Todos los profile events capturados durante esta operación.
* `settings` ([Map(LowCardinality(String), String)](/es/sql-reference/data-types/map)) — Ajustes específicos de copia de seguridad/restauración usados efectivamente en esta operación (de la cláusula `SETTINGS`, incluidos los valores predeterminados). Los ajustes sensibles no se exponen.
* `engine_settings` ([Map(LowCardinality(String), String)](/es/sql-reference/data-types/map)) — Ajustes usados efectivamente por el reader/writer del motor de copia de seguridad (por ejemplo, S3 `allow_native_copy`). Vacío cuando la operación implica más de un motor y un mapa plano no puede representarlo: copias de seguridad incrementales y restauraciones, restauraciones lightweight de snapshot y operaciones `ON CLUSTER` no internas.

<div id="restore-atomicity">
  ## Atomicidad de la restauración
</div>

`RESTORE` no es transaccional y no revierte los cambios si se produce un fallo. Para cada tabla, todas las partes seleccionadas se copian antes de adjuntar ninguna, pero la fase de adjuntar en sí no es transaccional: las partes pasan a ser visibles una a una. Las tablas se procesan de forma independiente.

**Las tablas son independientes.** Una tabla cuya restauración se completa permanece en su lugar aunque otra tabla del mismo comando falle más adelante:

```sql
RESTORE TABLE db.t0, TABLE db.t1
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

Si este comando falla después de que `db.t0` se haya restaurado por completo, pero antes de que `db.t1` termine, `db.t0` permanece restaurada.

**La cláusula `PARTITIONS` no es un límite de commit.** Solo determina qué partes de una tabla se restauran:

```sql
RESTORE TABLE db.t0 PARTITIONS '2026-06-01', '2026-06-02', '2026-06-03'
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

Todas las partes seleccionadas de la tabla se copian primero y se adjuntan solo cuando todas están listas. Por lo tanto, si este comando falla durante la fase de copia —por ejemplo, después de que la partición `2026-06-01` se haya copiado por completo, pero `2026-06-02` y `2026-06-03` aún no hayan terminado— entonces `2026-06-01` **no** se confirma con commit y la tabla queda sin datos restaurados por este comando. Una vez completada la fase de copia y al comenzar el paso de adjuntar, las partes hacen commit una por una, por lo que un fallo durante la adjunción puede dejar la tabla restaurada parcialmente, sin rollback.

Para hacer commit de las particiones de forma independiente (de modo que una partición completada sobreviva a un fallo posterior y pueda reintentarse de forma aislada), ejecute un `RESTORE` por separado para cada partición, usando `SETTINGS allow_non_empty_tables = true` después de la primera.
