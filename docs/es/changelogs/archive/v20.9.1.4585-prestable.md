  ### Versión de ClickHouse v20.9.1.4585-prestable FIXME en comparación con la v20.8.1.4513-prestable
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se añadieron opciones de configuración de MergeTree (`max_replicated_merges_with_ttl_in_queue` y `max_number_of_merges_with_ttl_in_pool`) para controlar el número de merges con TTL en el grupo de segundo plano y en la cola de replicación. Este cambio solo rompe la compatibilidad con versiones anteriores si utiliza TTL de eliminación. En caso contrario, la replicación seguirá siendo compatible. Puede evitar problemas de incompatibilidad si actualiza todas las réplicas del segmento a la vez o ejecuta `SYSTEM STOP TTL MERGES` hasta completar la actualización de todas las réplicas. Si aparece una entrada incompatible en la cola de replicación, antes que nada ejecute `SYSTEM STOP TTL MERGES` y después `ALTER TABLE ... DETACH PARTITION ...` en la partición a la que se asignó el merge de TTL incompatible. Vuelva a adjuntarla en una sola réplica. [#14490](https://github.com/ClickHouse/ClickHouse/pull/14490) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade la función de tabla `view`, que convierte una subconsulta en un objeto de tabla. Esto facilita reutilizar consultas. Por ejemplo, puede usarse en las funciones de tabla remote/cluster. [#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* Ahora podemos escribir `select * apply(length) apply(max) from wide_string_table` para averiguar la longitud máxima de todas las columnas String. También se ofrecen las dos variantes siguientes: [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* Se añade el campo `query_start_time_microseconds` a las tablas `system.query_log` y `system.query_thread_log`. [#14252](https://github.com/ClickHouse/ClickHouse/pull/14252) ([Bharat Nallan](https://github.com/bharatnc)).
* Se añadió una función de agregación RankCorrelationSpearman que calcula un coeficiente de correlación de rangos. Continuación de [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769). [#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se añadió la generación de bases de datos mediante la utilidad de consulta. Continuación de [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973). [#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se optimizan las consultas con LIMIT/LIMIT BY/ORDER BY para Distributed con GROUP BY sharding&#95;key (con optimize&#95;skip&#95;unused&#95;shards y optimize&#95;distributed&#95;group&#95;by&#95;sharding&#95;key). [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Mejora
</div>

* Mejoras en StorageRabbitMQ: se añadieron el manejo de fallos de conexión y canales, commits correctos, manejo de fallos de insert, mejores exchanges, durabilidad de la queue y posibilidad de reanudarla, así como nuevos ajustes de queue. Se corrigieron las pruebas. [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se añadió la autorización `requirepass` de Redis. [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* Se añadió el argument de precision para el tipo DateTime. [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* Se mejora el rendimiento del motor Kafka al proporcionar un thread independiente para cada consumer. Grupo de threads separado para motores de streaming (como Kafka). [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* Se añadió el códec de compresión predeterminado para las partes en `system.part_log` con el nombre `default_compression_codec`. [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* Se reemplazaron los enteros wide de boost multiprecision por la implementación de [https://github.com/cerevra/int](https://github.com/cerevra/int). [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* La primary key se convierte implícitamente en Not null en MaterializeMySQL (igual que en MySQL). Corrige [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114). [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* Se añadió el nuevo ajuste system&#95;events&#95;show&#95;zero&#95;values, como se propuso en [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384). [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Ahora el ofuscador admite el tipo UUID, como se propuso en [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163). [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Creación de sets para múltiples `JOIN` e `IN` en paralelo. Esto puede mejorar ligeramente el rendimiento de las consultas con varias expresiones `IN subquery` diferentes. [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Ahora los TTL se aplicarán durante el merge si no se habían materializado previamente. [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* El handler de MySQL devuelve `OK` para consultas como `SET @@var = value`. Esa instrucción se ignora. Esto es necesario porque algunos drivers de MySQL envían una consulta `SET @@` como configuración tras el handshake [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422 . [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* Se acelera el proceso de apagado del server si hay requests de S3 en curso. [#14496](https://github.com/ClickHouse/ClickHouse/pull/14496) ([Pavel Kovalenko](https://github.com/Jokser)).
* No se permite un argument `time_zone` vacío en las funciones de tipo `toStartOf*`. [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* Se usa std::filesystem::path en ConfigProcessor para concatenar file paths. [#14558](https://github.com/ClickHouse/ClickHouse/pull/14558) ([Bharat Nallan](https://github.com/bharatnc)).
