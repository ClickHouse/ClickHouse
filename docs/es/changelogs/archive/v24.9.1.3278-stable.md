<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se permite escribir `SETTINGS` antes de `FORMAT` en una cadena de consultas con `UNION` cuando las subconsultas están entre paréntesis. Esto cierra [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712). Se cambia el comportamiento cuando una consulta tiene la cláusula SETTINGS especificada dos veces en una secuencia. La cláusula SETTINGS más cercana tendrá preferencia para la subconsulta correspondiente. En versiones anteriores, la cláusula SETTINGS más externa podía tener preferencia sobre la interna. [#60197](https://github.com/ClickHouse/ClickHouse/pull/60197) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* No se permite especificar explícitamente el UUID al crear una tabla en una base de datos Replicated. Tampoco se permite especificar explícitamente la ruta de ZooKeeper ni el nombre de la réplica para tablas *MergeTree en bases de datos Replicated. [#66104](https://github.com/ClickHouse/ClickHouse/pull/66104) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Se reimplementa el tipo Dynamic. Ahora, cuando se alcanza el límite de tipos de datos dinámicos, los tipos nuevos no se convierten con CAST a String, sino que se almacenan en una estructura de datos especial en formato binario, con el tipo de dato codificado en binario. Ahora, cualquier tipo que se haya insertado alguna vez en una columna Dynamic puede leerse desde ella como subcolumna. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Pavel Kruglov](https://github.com/Avogar)).
* Se admiten expresiones como `a[b].c` para tuplas con nombre, así como subíndices con nombre desde expresiones arbitrarias, por ejemplo, `expr().name`. Esto es útil para procesar JSON. Esto cierra [#54965](https://github.com/ClickHouse/ClickHouse/issues/54965). En versiones anteriores, una expresión con la forma `expr().name` se interpretaba como `tupleElement(expr(), name)`, y el analizador de consultas buscaba una columna `name` en lugar del elemento de tupla correspondiente; en la nueva versión, en cambio, pasa a ser `tupleElement(expr(), 'name')`. En la mayoría de los casos, la versión anterior no funcionaba, pero es posible imaginar un caso muy inusual en el que este cambio podría provocar incompatibilidades: si almacenabas nombres de elementos de tupla en una columna o un alias con un nombre distinto del nombre del elemento de la tupla: `SELECT 'b' AS a, CAST([tuple(123)] AS 'Array(Tuple(b UInt8))') AS t, t[1].a`. Es muy poco probable que hayas usado consultas de este tipo, pero aun así tenemos que marcar este cambio como potencialmente incompatible con versiones anteriores. [#68435](https://github.com/ClickHouse/ClickHouse/pull/68435) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Cuando la configuración `print_pretty_type_names` está habilitada, imprimirá el tipo de dato `Tuple` en formato Pretty en las sentencias `SHOW CREATE TABLE`, la función `formatQuery` y en el modo interactivo de `clickhouse-client` y `clickhouse-local`. En versiones anteriores, esta configuración solo se aplicaba a las consultas `DESCRIBE` y a `toTypeName`. Esto cierra [#65753](https://github.com/ClickHouse/ClickHouse/issues/65753). [#68492](https://github.com/ClickHouse/ClickHouse/pull/68492) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* La función `toStartOfInterval()` ahora tiene una nueva sobrecarga que emula la función `time_bucket()` de TimescaleDB y la función `date_bin()` de PostgreSQL, respectivamente. ([#55619](https://github.com/ClickHouse/ClickHouse/issues/55619)). Permite alinear valores de fecha o timestamp a múltiplos de un intervalo dado a partir de un origen *arbitrario* (en lugar de 0000-01-01 00:00:00.000 como origen *fijo*). Por ejemplo, `SELECT toStartOfInterval(toDateTime('2023-01-01 14:45:00'), INTERVAL 1 MINUTE, toDateTime('2023-01-01 14:35:30'));` devuelve `2023-01-01 14:44:30`, que es un múltiplo de intervalos de 1 minuto a partir del origen `2023-01-01 14:35:30`. [#56738](https://github.com/ClickHouse/ClickHouse/pull/56738) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se añade soporte para `ATTACH PARTITION ALL FROM`. [#61987](https://github.com/ClickHouse/ClickHouse/pull/61987) ([Kirill Nikiforov](https://github.com/allmazz)).
* Se añade la configuración `input_format_try_infer_variants`, que permite inferir el tipo Variant durante la inferencia de esquema para formatos de texto cuando hay más de un tipo posible para los elementos de una columna o array. [#63798](https://github.com/ClickHouse/ClickHouse/pull/63798) ([Shaun Struwig](https://github.com/Blargian)).
* Se introdujo el formato JSONCompactWithProgress, en el que ClickHouse genera cada fila como un objeto JSON delimitado por saltos de línea, incluidos metadatos, datos, progreso, totales y estadísticas. [#66205](https://github.com/ClickHouse/ClickHouse/pull/66205) ([Alexey Korepanov](https://github.com/alexkorep)).
* Implementa el nuevo tipo de datos JSON. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Pavel Kruglov](https://github.com/Avogar)).
* Se añade la configuración `input_format_json_empty_as_default`, que, cuando está habilitada, trata los campos vacíos en entradas JSON como valores predeterminados. Cierra [#59339](https://github.com/ClickHouse/ClickHouse/issues/59339). [#66782](https://github.com/ClickHouse/ClickHouse/pull/66782) ([Alexis Arnaud](https://github.com/a-a-f)).
* Se añadieron las funciones `overlay` y `overlayUTF8`, que reemplazan partes de una cadena con otra cadena. Ejemplo: `SELECT overlay('Hello New York', 'Jersey', 11)` devuelve `Hello New Jersey`. [#66933](https://github.com/ClickHouse/ClickHouse/pull/66933) ([李扬](https://github.com/taiyang-li)).
* Se añade un nuevo comando, eliminación ligera en partición `DELETE FROM [db.]table [ON CLUSTER cluster] [IN PARTITION partition_expr] WHERE expr;` &#96;&#96;&#96; VM-114-29-tos :) select * from ads&#95;app&#95;poster&#95;ip&#95;source&#95;channel&#95;di&#95;replicated&#95;local;. [#67805](https://github.com/ClickHouse/ClickHouse/pull/67805) ([sunny](https://github.com/sunny19930321)).
* Se implementó la comparación de valores del tipo de datos `Interval`, por lo que ahora se convierten al menor supertipo común. [#68057](https://github.com/ClickHouse/ClickHouse/pull/68057) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se añade la configuración create&#95;if&#95;not&#95;exists para usar por defecto el comportamiento IF NOT EXISTS durante las sentencias CREATE. [#68164](https://github.com/ClickHouse/ClickHouse/pull/68164) ([Peter Nguyen](https://github.com/petern48)).
* Permite leer tablas Iceberg en Azure y en entornos locales. [#68210](https://github.com/ClickHouse/ClickHouse/pull/68210) ([Daniil Ivanik](https://github.com/divanik)).
* Se añaden las funciones de agregación distinctDynamicTypes/distinctJSONPaths/distinctJSONPathsAndTypes para una mejor introspección del contenido del tipo de columna JSON. [#68463](https://github.com/ClickHouse/ClickHouse/pull/68463) ([Pavel Kruglov](https://github.com/Avogar)).
* Las entradas de la query cache ahora pueden eliminarse por etiqueta. Por ejemplo, la entrada de la query cache creada por `SELECT 1 SETTINGS use_query_cache = true, query_cache_tag = 'abc'` ahora puede eliminarse con `SYSTEM DROP QUERY CACHE TAG 'abc'` (o, por supuesto, simplemente con: `SYSTEM DROP QUERY CACHE`, que limpiará toda la query cache). [#68477](https://github.com/ClickHouse/ClickHouse/pull/68477) ([Michał Tabaszewski](https://github.com/pinsvin00)).
* Añade cifrado del almacenamiento para las named collections. [#68615](https://github.com/ClickHouse/ClickHouse/pull/68615) ([Pablo Marcos](https://github.com/pamarcos)).
* Se añadió la función `ripeMD160`, que calcula el hash criptográfico RIPEMD-160 de una cadena. Ejemplo: `SELECT hex(ripeMD160('The quick brown fox jumps over the lazy dog'))` devuelve `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`. [#68639](https://github.com/ClickHouse/ClickHouse/pull/68639) ([Dergousov Maxim](https://github.com/m7kss1)).
* Añade la columna virtual &#95;headers para el table engine URL. Cierra [#65026](https://github.com/ClickHouse/ClickHouse/issues/65026). [#68867](https://github.com/ClickHouse/ClickHouse/pull/68867) ([flynn](https://github.com/ucasfl)).
* Añade la tabla `system.projections` para realizar un seguimiento de las projections disponibles. [#68901](https://github.com/ClickHouse/ClickHouse/pull/68901) ([Jordi Villar](https://github.com/jrdi)).
* Añade la nueva función `arrayZipUnaligned` para compatibilidad con Spark (arrays&#95;zip), que permite arrays no alineados basándose en la función original `arrayZip`. &#96;&#96;&#96; sql SELECT arrayZipUnaligned([1], [1, 2, 3]). [#69030](https://github.com/ClickHouse/ClickHouse/pull/69030) ([李扬](https://github.com/taiyang-li)).
* Añade la métrica `RealTimeMicroseconds` en el encabezado HTTP `X-ClickHouse-Summary`. De esta forma, podemos conocer el tiempo de CPU de una solicitud sin tener que comprobarlo en `system.query_log`. [#69032](https://github.com/ClickHouse/ClickHouse/pull/69032) ([Alejandro](https://github.com/alexon1234)).
* Se añadieron los comandos cp/mv para el client de Keeper, que copian/mueven el nodo de forma atómica. [#69034](https://github.com/ClickHouse/ClickHouse/pull/69034) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Añade el argumento `scale` (predeterminado: `true`) a la función `arrayAUC`, que permite omitir el paso de normalización (issue [#69609](https://github.com/ClickHouse/ClickHouse/issues/69609)). [#69717](https://github.com/ClickHouse/ClickHouse/pull/69717) ([gabrielmcg44](https://github.com/gabrielmcg44)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se mejoró el rendimiento de `join` reordenando la tabla derecha por claves cuando las claves de la tabla son densas en `left` o `inner hash join`. [#60341](https://github.com/ClickHouse/ClickHouse/pull/60341) ([kevinyhzou](https://github.com/KevinyhZou)).
* Se mejoró el rendimiento de todos los `join` al agregar `RowRefList` o `RowRef` a AddedColumns para salida diferida; durante `buildOutput`, se usan `RowRefList`/`RowRef` para la salida y se elimina la condición `is_join_get` del bucle `for` de `buildOutput`. [#63677](https://github.com/ClickHouse/ClickHouse/pull/63677) ([kevinyhzou](https://github.com/KevinyhZou)).
* Se cargan los metadatos de la filesystem cache de forma asíncrona durante el proceso de arranque, para que los reinicios sean más rápidos. [#65736](https://github.com/ClickHouse/ClickHouse/pull/65736) ([Daniel Pozo Escalona](https://github.com/danipozo)).
* Las Functions `array` y `map` se optimizaron para procesar mucho más rápido ciertos casos habituales. [#67707](https://github.com/ClickHouse/ClickHouse/pull/67707) ([李扬](https://github.com/taiyang-li)).
* Optimización menor de la lectura de cadenas ORC, especialmente cuando la columna no contiene valores NULL. [#67794](https://github.com/ClickHouse/ClickHouse/pull/67794) ([李扬](https://github.com/taiyang-li)).
* Se mejoró el rendimiento general de las merges al reducir la sobrecarga de planificación de sus pasos. [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* Se aceleran las solicitudes a S3 cuando no se ha configurado un profile, no se han configurado credenciales y IMDS no está disponible (por ejemplo, al consultar un bucket público desde una máquina fuera de la Cloud). Esto cierra [#52771](https://github.com/ClickHouse/ClickHouse/issues/52771). [#68082](https://github.com/ClickHouse/ClickHouse/pull/68082) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nuevo algoritmo para determinar la unidad de distribución de marks entre réplicas mediante consistent hash. Se eligen distintas cantidades de marks para diferentes patrones de lectura a fin de mejorar el rendimiento. [#68424](https://github.com/ClickHouse/ClickHouse/pull/68424) ([Nikita Taranov](https://github.com/nickitat)).
* Se intenta desvirtualizar el reader de format en RowInputFormatWithNamesAndTypes para comprobar si aporta alguna mejora del rendimiento. [#68437](https://github.com/ClickHouse/ClickHouse/pull/68437) ([李扬](https://github.com/taiyang-li)).
* Se agrega la implementación de merge en paralelo con clave para maximizar el uso de la CPU. [#68441](https://github.com/ClickHouse/ClickHouse/pull/68441) ([Jiebin Sun](https://github.com/jiebinn)).
* Se agrega el settings `output_format_orc_dictionary_key_size_threshold` para permitir al usuario habilitar la codificación por diccionario para columnas String en el ORC output format. Esto ayuda a reducir significativamente el tamaño del archivo ORC de salida y a mejorar el rendimiento de lectura. [#68591](https://github.com/ClickHouse/ClickHouse/pull/68591) ([李扬](https://github.com/taiyang-li)).
* Se implementó la lectura únicamente de los archivos necesarios durante el partitioning de Hive. [#68963](https://github.com/ClickHouse/ClickHouse/pull/68963) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se introduce una nueva request de Keeper, RemoveRecursive, que elimina un nodo junto con todo su subárbol. [#69332](https://github.com/ClickHouse/ClickHouse/pull/69332) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Se acelera el rendimiento de insert con vector similarity index al agregar datos al vector index en paralelo. [#69493](https://github.com/ClickHouse/ClickHouse/pull/69493) ([flynn](https://github.com/ucasfl)).
* Antes, la complejidad algorítmica de la lógica de deduplicación de partes en el manejo de announcement de parallel replica era O(n^2), lo que podía llevar un tiempo apreciable en tablas con muchas partes (o particiones). Este cambio hace que la complejidad pase a ser O(n*log(n)). [#69596](https://github.com/ClickHouse/ClickHouse/pull/69596) ([Alexander Gololobov](https://github.com/davenger)).

<div id="buildtestingpackaging-improvement">
  #### Mejora de compilación/pruebas/empaquetado
</div>

* Permite especificar el mínimo y el máximo de los parámetros aleatorios en la prueba después de las tags con la forma `setting=(min, max)`. En algunas pruebas, un valor muy bajo de un parámetro puede provocar un timeout (por ejemplo, `index_granularity=1`), pero aun así queremos aleatorizar este parámetro en esas pruebas. Para evitar timeouts, podemos especificar un valor mínimo personalizado para este parámetro. [#67875](https://github.com/ClickHouse/ClickHouse/pull/67875) ([Pavel Kruglov](https://github.com/Avogar)).
* La comprobación flaky de las pruebas de integración ahora ejecuta cada módulo (archivo) como un grupo independiente. Esto permite aplicar un timeout por módulo. Antes, las pruebas lentas podían consumir todo el tiempo y las demás no se ejecutaban en la comprobación flaky, aunque el resultado fuera satisfactorio. [#68380](https://github.com/ClickHouse/ClickHouse/pull/68380) ([Ilya Yatsishin](https://github.com/qoega)).
