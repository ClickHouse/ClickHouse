<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se amplía la función &quot;toDayOfWeek()&quot; (alias: &quot;DAYOFWEEK&quot;) con un argumento de modo que indica si la semana empieza en lunes o en domingo y si el recuento comienza en 0 o en 1. Para mantener la coherencia con otras funciones de fecha y hora, el argumento de modo se insertó entre los argumentos de hora y zona horaria. Esto rompe el uso existente de la sintaxis de 2 argumentos (antes no documentada) &quot;toDayOfWeek(time, time&#95;zone)&quot;. La solución es reescribir la función como &quot;toDayOfWeek(time, 0, time&#95;zone)&quot;. [#45233](https://github.com/ClickHouse/ClickHouse/pull/45233) ([Robert Schulze](https://github.com/rschu1ze)).
* Se cambia el nombre del ajuste `max_query_cache_size` a `filesystem_cache_max_download_size`. [#45614](https://github.com/ClickHouse/ClickHouse/pull/45614) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se corrige la aplicación de ajustes para FORMAT en el client. [#46003](https://github.com/ClickHouse/ClickHouse/pull/46003) ([Azat Khuzhin](https://github.com/azat)).
* El usuario `default` no tendrá permisos para el tipo de acceso `SHOW NAMED COLLECTION` de forma predeterminada (por ejemplo, el usuario `default` ya no podrá hacer grant ALL a otros usuarios como antes; por lo tanto, este PR es incompatible con versiones anteriores). [#46010](https://github.com/ClickHouse/ClickHouse/pull/46010) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se elimina la compatibilidad con el ajuste `materialized_postgresql_allow_automatic_update` (que estaba desactivado de forma predeterminada). Se corrigen las pruebas de integración. [#46106](https://github.com/ClickHouse/ClickHouse/pull/46106) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se mejora ligeramente el rendimiento de `countDigits` en conjuntos de datos realistas. Esto cerró [#44518](https://github.com/ClickHouse/ClickHouse/issues/44518). En versiones anteriores, `countDigits(0)` devolvía `0`; ahora devuelve `1`, lo cual es más correcto y sigue la documentación existente. [#46187](https://github.com/ClickHouse/ClickHouse/pull/46187) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Se corrigió el rendimiento de consultas `SELECT` cortas que leen de tablas con un gran número de columnas `Array`/`Map`/`Nested`. [#45630](https://github.com/ClickHouse/ClickHouse/pull/45630) ([Anton Popov](https://github.com/CurtizJ)).
* Se permite usar el algoritmo de mezcla Vertical con partes en formato Compact. Esto permitirá que el servidor ClickHouse use mucha menos memoria para las operaciones en segundo plano. Esto cierra [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084). [#45681](https://github.com/ClickHouse/ClickHouse/pull/45681) ([Anton Popov](https://github.com/CurtizJ)).

Para evaluar el impacto de este cambio, adoptamos el benchmark TPC-H, pero cambiamos los tipos de columna de no Nullable a Nullable, y medimos el QPS de sus consultas como indicador de rendimiento. [#45962](https://github.com/ClickHouse/ClickHouse/pull/45962) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).

* Se mejora el rendimiento de la conversión de Decimal cuando la scale no cambia. [#46095](https://github.com/ClickHouse/ClickHouse/pull/46095) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La lógica introducida funciona si la condición PREWHERE es una conjunción de múltiples condiciones (cond1 AND cond2 AND ... ). Agrupa en pasos las condiciones que requieren leer las mismas columnas. Después de cada paso, se calcula la parte correspondiente de la condición completa y las filas resultantes pueden filtrarse. Esto permite leer menos filas en los pasos siguientes, ahorrando así ancho de banda de IO y reduciendo el cómputo. Por ahora, esta lógica está deshabilitada de forma predeterminada. Se habilitará de forma predeterminada en uno de los futuros lanzamientos una vez que se confirme que no provoca regresiones, por lo que se recomienda encarecidamente usarla para pruebas. Se puede controlar con 2 ajustes: &quot;enable&#95;multiple&#95;prewhere&#95;read&#95;steps&quot; y &quot;move&#95;all&#95;conditions&#95;to&#95;prewhere&quot;. [#46140](https://github.com/ClickHouse/ClickHouse/pull/46140) ([Alexander Gololobov](https://github.com/davenger)).
* Permitir aumentar el prefetching en la lectura de datos. [#46168](https://github.com/ClickHouse/ClickHouse/pull/46168) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Reescribir arrayExists(x -&gt; x = 1, arr) -&gt; has(arr, 1), lo que mejora el rendimiento en 1,34x. [#46188](https://github.com/ClickHouse/ClickHouse/pull/46188) ([李扬](https://github.com/taiyang-li)).
* Corregir el uso excesivo de memoria en las fusiones verticales sobre disco no remoto. Respetar `max_insert_delayed_streams_for_parallel_write` para el disco remoto. [#46275](https://github.com/ClickHouse/ClickHouse/pull/46275) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Actualizar zstd a v1.5.4. Incluye algunas mejoras menores de rendimiento y ratio de compresión. Si ejecuta réplicas con distintas versiones de ClickHouse, puede ver mensajes de error razonables como `Data after merge/mutation is not byte-identical to data on another replicas.`, con su explicación correspondiente. Estos mensajes son normales y no debe preocuparse. [#46280](https://github.com/ClickHouse/ClickHouse/pull/46280) ([Raúl Marín](https://github.com/Algunenano)).
* Permitir usar el algoritmo Vertical merge con partes en formato Compact. Esto permitirá que ClickHouse server use mucha menos memoria para operaciones en segundo plano. Esto cierra [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084). [#46282](https://github.com/ClickHouse/ClickHouse/pull/46282) ([Anton Popov](https://github.com/CurtizJ)).
