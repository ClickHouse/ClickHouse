<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* La configuración `print_pretty_type_names` está activada de forma predeterminada. Puede desactivarla para mantener el comportamiento anterior o usar `SET compatibility = '23.12'`. [#57726](https://github.com/ClickHouse/ClickHouse/pull/57726) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La configuración de MergeTree `clean_deleted_rows` está obsoleta y ya no tiene efecto. La palabra clave `CLEANUP` para `OPTIMIZE` no está permitida de forma predeterminada (a menos que `allow_experimental_replacing_merge_with_cleanup` esté habilitada). [#58316](https://github.com/ClickHouse/ClickHouse/pull/58316) ([Alexander Tokmakov](https://github.com/tavplubix)).
* La función `reverseDNSQuery` ya no está disponible. Esto cierra la issue [#58368](https://github.com/ClickHouse/ClickHouse/issues/58368). [#58369](https://github.com/ClickHouse/ClickHouse/pull/58369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se habilitan varios cambios para mejorar el control de acceso en el archivo de configuración. Estos cambios afectan al comportamiento, y debe revisar `config.xml` en la sección `access_control_improvements`. Si no está seguro, mantenga los valores del archivo de configuración como estaban en la versión anterior. [#58584](https://github.com/ClickHouse/ClickHouse/pull/58584) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se permiten consultas sin alias para subconsultas en `PASTE JOIN`. [#58654](https://github.com/ClickHouse/ClickHouse/pull/58654) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se corrige sumMapFiltered con valores NaN. Los valores NaN ahora se colocan al final (en lugar de aleatoriamente) y se consideran distintos de cualquier otro valor. Ahora `-0` también se trata como igual a `0`; dado que los valores 0 se descartan, los valores `-0` también se descartan. [#58959](https://github.com/ClickHouse/ClickHouse/pull/58959) ([Raúl Marín](https://github.com/Algunenano)).
* La función `visibleWidth` se comportará de acuerdo con la documentación. En versiones anteriores, simplemente contaba puntos de código después de la serialización de cadenas, como la función `lengthUTF8`, pero no tenía en cuenta los caracteres de ancho cero y los combinatorios, los caracteres de ancho completo, las tabulaciones ni los caracteres de borrado. Ahora el comportamiento ha cambiado en consecuencia. Si desea mantener el comportamiento anterior, establezca `function_visible_width_behavior` en `0`, o `compatibility` en `23.12` o una versión inferior. [#59022](https://github.com/ClickHouse/ClickHouse/pull/59022) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* El dialecto Kusto está deshabilitado hasta que se corrijan estos dos errores: [#59037](https://github.com/ClickHouse/ClickHouse/issues/59037) y [#59036](https://github.com/ClickHouse/ClickHouse/issues/59036). [#59305](https://github.com/ClickHouse/ClickHouse/pull/59305) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se permite adjuntar particiones de tablas con distintas expresiones de partición cuando la expresión de partición de la tabla de destino no reparticiona ni divide la parte. [#39507](https://github.com/ClickHouse/ClickHouse/pull/39507) ([Arthur Passos](https://github.com/arthurpassos)).
* Se añadió la sentencia `SYSTEM RELOAD ASYNCHRONOUS METRICS`, que actualiza las métricas asíncronas. Resulta principalmente útil para pruebas y desarrollo. [#53710](https://github.com/ClickHouse/ClickHouse/pull/53710) ([Robert Schulze](https://github.com/rschu1ze)).
* Ciertos ajustes (actualmente `min_compress_block_size` y `max_compress_block_size`) ahora pueden especificarse a nivel de columna, donde tienen precedencia sobre el ajuste correspondiente a nivel de tabla. Ejemplo: `CREATE TABLE tab (col String SETTINGS (min_compress_block_size = 81920, max_compress_block_size = 163840)) ENGINE = MergeTree ORDER BY tuple();`. [#55201](https://github.com/ClickHouse/ClickHouse/pull/55201) ([Duc Canh Le](https://github.com/canhld94)).
* Se añadió la función de agregación `quantileDDSketch`, así como las correspondientes `quantilesDDSketch` y `medianDDSketch`. Se basa en DDSketch https://www.vldb.org/pvldb/vol12/p2195-masson.pdf. ### Entrada de documentación para cambios visibles al usuario. [#56342](https://github.com/ClickHouse/ClickHouse/pull/56342) ([Srikanth Chekuri](https://github.com/srikanthccv)).
* Se añadió la función `seriesDecomposeSTL()`, que descompone una serie temporal en un componente estacional, una tendencia y un componente residual. [#57078](https://github.com/ClickHouse/ClickHouse/pull/57078) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* Se introdujo el cliente de binlog de MySQL para MaterializedMySQL: una sola conexión de binlog para múltiples bases de datos. [#57323](https://github.com/ClickHouse/ClickHouse/pull/57323) ([Val Doroshchuk](https://github.com/valbok)).
* Intel QuickAssist Technology (QAT) ofrece compresión y criptografía aceleradas por hardware. ClickHouse incorpora un nuevo códec de compresión `ZSTD_QAT` que aprovecha QAT para la compresión zstd. El códec utiliza [Intel's QATlib](https://github.com/intel/qatlib) y el [plugin QAT ZSTD de Intel](https://github.com/intel/QAT-ZSTD-Plugin). Por ahora, solo la compresión puede acelerarse por hardware (se activa un mecanismo de respaldo por software si QAT no puede inicializarse); la descompresión siempre se ejecuta por software. [#57509](https://github.com/ClickHouse/ClickHouse/pull/57509) ([jasperzhu](https://github.com/jinjunzh)).
* Se implementó una nueva forma de generar las claves de almacenamiento de objetos para discos S3. Ahora el formato puede definirse mediante la sintaxis de expresiones regulares `re2` con la opción `key_template` en la descripción del disco. [#57663](https://github.com/ClickHouse/ClickHouse/pull/57663) ([Sema Checherinda](https://github.com/CheSema)).
* La tabla `system.dropped_tables_parts` contiene las partes de las tablas en `system.dropped_tables` (tablas eliminadas pero aún no borradas definitivamente). [#58038](https://github.com/ClickHouse/ClickHouse/pull/58038) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Se implementó el tipo de dato Variant, que representa una unión de otros tipos de datos. El tipo `Variant(T1, T2, ..., TN)` indica que cada fila de este tipo tiene un valor de tipo `T1`, `T2`, ..., `TN` o ninguno de ellos (valor `NULL`). El tipo Variant está disponible mediante el ajuste `allow_experimental_variant_type`. Referencia: [#54864](https://github.com/ClickHouse/ClickHouse/issues/54864). [#58047](https://github.com/ClickHouse/ClickHouse/pull/58047) ([Kruglov Pavel](https://github.com/Avogar)).
* Se añadió el ajuste `max_materialized_views_size_for_table` para limitar el número de vistas materializadas asociadas a una tabla. [#58068](https://github.com/ClickHouse/ClickHouse/pull/58068) ([zhongyuankai](https://github.com/zhongyuankai)).
* Mejoras en `clickhouse-format`: * soporte para consultas INSERT con `VALUES` * soporte para comentarios (use `--comments` para mostrarlos) * soporte para la opción `--max_line_length` para formatear en multilínea solo las consultas largas. [#58246](https://github.com/ClickHouse/ClickHouse/pull/58246) ([vdimir](https://github.com/vdimir)).
* Se añadieron los modos `null_status_on_timeout_only_active` y `throw_only_active` para `distributed_ddl_output_mode`, que permiten evitar esperar a réplicas inactivas. [#58350](https://github.com/ClickHouse/ClickHouse/pull/58350) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Se añadió la tabla `system.database_engines`. [#58390](https://github.com/ClickHouse/ClickHouse/pull/58390) ([Bharat Nallan](https://github.com/bharatnc)).
* Se añadió el modificador FROM <Replicas> para la consulta SYSTEM SYNC REPLICA LIGHTWEIGHT. El modificador FROM garantiza que se espere únicamente las recuperaciones y los rangos de eliminación de las réplicas de origen especificadas, así como de cualquier réplica que no esté en ZooKeeper o que tenga `source_replica` vacío. [#58393](https://github.com/ClickHouse/ClickHouse/pull/58393) ([Jayme Bird](https://github.com/jaymebrd)).
* Se añadió la función `arrayShingles()` para calcular submatrices; por ejemplo, `arrayShingles([1, 2, 3, 4, 5], 3)` devuelve `[[1,2,3],[2,3,4],[3,4,5]]`. [#58396](https://github.com/ClickHouse/ClickHouse/pull/58396) ([Zheng Miao](https://github.com/zenmiao7)).
* Se añadieron las funciones `punycodeEncode()`, `punycodeDecode()`, `idnaEncode()` e `idnaDecode()`, útiles para traducir nombres de dominio internacionales a su representación ASCII conforme al estándar IDNA. [#58454](https://github.com/ClickHouse/ClickHouse/pull/58454) ([Robert Schulze](https://github.com/rschu1ze)).
* Se añadieron las funciones de similitud de cadenas `dramerauLevenshteinDistance()`, `jaroSimilarity()` y `jaroWinklerSimilarity()`. [#58531](https://github.com/ClickHouse/ClickHouse/pull/58531) ([Robert Schulze](https://github.com/rschu1ze)).
* Se añadieron dos ajustes: `output_format_compression_level` para modificar el nivel de compresión de salida, y `output_format_compression_zstd_window_log` para establecer explícitamente el tamaño de la ventana de compresión y habilitar el modo de rango extendido para la compresión zstd cuando el método de compresión de salida es `zstd`. Se aplica a `INTO OUTFILE` y al escribir en las funciones de tabla `file`, `url`, `hdfs`, `s3` y `azureBlobStorage`. [#58539](https://github.com/ClickHouse/ClickHouse/pull/58539) ([Duc Canh Le](https://github.com/canhld94)).
* Se deshabilitan automáticamente las secuencias de escape ANSI en los formatos Pretty cuando la salida no es una terminal. Se añadió el nuevo modo `auto` al ajuste `output_format_pretty_color`. [#58614](https://github.com/ClickHouse/ClickHouse/pull/58614) ([Shaun Struwig](https://github.com/Blargian)).
* Se añadió el ajuste `update_insert_deduplication_token_in_dependent_materialized_views`. Este ajuste permite actualizar el token de deduplicación de inserción con el identificador de tabla al insertar en vistas materializadas dependientes. Cierra [#59165](https://github.com/ClickHouse/ClickHouse/issues/59165). [#59238](https://github.com/ClickHouse/ClickHouse/pull/59238) ([Maksim Kita](https://github.com/kitaisreal)).





<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Implementación final más eficiente en términos de caché. Nota sobre el cambio de comportamiento: anteriormente, las queries con el modificador `FINAL` que se leían con un único flujo (p. ej., `max_threads=1`) producían una salida ordenada sin una cláusula `ORDER BY` especificada explícitamente. Este comportamiento ya no existe cuando `enable_vertical_final = true` (y ese es el valor predeterminado). [#54366](https://github.com/ClickHouse/ClickHouse/pull/54366) ([Duc Canh Le](https://github.com/canhld94)).
* Optimiza la función de elementos de array cuando la entrada es array(map)/array(array(num)/array(array(string))/array(bigint)/array(decimal). La implementación actual provoca demasiadas reasignaciones. La optimización la acelera ~6x, especialmente cuando el tipo de entrada es array(map). [#56403](https://github.com/ClickHouse/ClickHouse/pull/56403) ([李扬](https://github.com/taiyang-li)).
* Omite la abstracción `Poco::BasicBufferedStreamBuf` al leer desde S3 (concretamente, `ReadBufferFromIStream`) para evitar copias adicionales de datos. [#56961](https://github.com/ClickHouse/ClickHouse/pull/56961) ([Nikita Taranov](https://github.com/nickitat)).
* Lee la columna una sola vez cuando se lee más de una subcolumna de ella en partes compactas. [#57631](https://github.com/ClickHouse/ClickHouse/pull/57631) ([Kruglov Pavel](https://github.com/Avogar)).
* Reescribe el AST de la función sum(column + literal). [#57853](https://github.com/ClickHouse/ClickHouse/pull/57853) ([Jiebin Sun](https://github.com/jiebinn)).
* La evaluación de la función `match()` ahora utiliza índices de omisión `ngrambf_v1` y `tokenbf_v1`. [#57882](https://github.com/ClickHouse/ClickHouse/pull/57882) ([凌涛](https://github.com/lingtaolf)).
* El coordinador predeterminado para las réplicas paralelas se ha reescrito para mejorar la localidad de caché (casi siempre se asignan los mismos mark ranges a las mismas réplicas). También se usa hash consistente durante el work stealing, por lo que se espera una mejor tail latency. Se ha probado con escalabilidad lineal en un centenar de réplicas. [#57968](https://github.com/ClickHouse/ClickHouse/pull/57968) ([Nikita Taranov](https://github.com/nickitat)).
* Evita que MergeTree FINAL compare filas de una misma parte no L0. [#58142](https://github.com/ClickHouse/ClickHouse/pull/58142) ([Duc Canh Le](https://github.com/canhld94)).
* Acelera las llamadas a iota (rellenado de array con números consecutivos). [#58271](https://github.com/ClickHouse/ClickHouse/pull/58271) ([Raúl Marín](https://github.com/Algunenano)).
* La evaluación de la función `match()` ahora utiliza índices invertidos. [#58284](https://github.com/ClickHouse/ClickHouse/pull/58284) ([凌涛](https://github.com/lingtaolf)).
* Acelera MIN/MAX para tipos no numéricos. [#58334](https://github.com/ClickHouse/ClickHouse/pull/58334) ([Raúl Marín](https://github.com/Algunenano)).
* Habilita la compilación JIT para la agregación sin clave. Cierra [#41461](https://github.com/ClickHouse/ClickHouse/issues/41461). Originalmente [#53757](https://github.com/ClickHouse/ClickHouse/issues/53757). [#58440](https://github.com/ClickHouse/ClickHouse/pull/58440) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Los experimentos de rendimiento de **OnTime** en el servidor Intel con soporte de hasta AVX2 (y BMI2) muestran que este cambio podría mejorar de forma efectiva el QPS de **Q2** y **Q3** en **5.0%** y **3.7%** al reducir la proporción de ciclos del punto caliente, ***DB::MergeTreeRangeReader::ReadResult::optimize***, **de 11.48% a 1.09%** y **de 8.09% a 0.67%** respectivamente, sin afectar a los demás. [#58800](https://github.com/ClickHouse/ClickHouse/pull/58800) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Usa un hilo menos en `clickhouse-local`. [#58968](https://github.com/ClickHouse/ClickHouse/pull/58968) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Los estados de agregación grandes de `uniqExact` se fusionarán en paralelo en consultas distribuidas. [#59009](https://github.com/ClickHouse/ClickHouse/pull/59009) ([Nikita Taranov](https://github.com/nickitat)).
* Se reduce el uso de memoria después de leer desde tablas `MergeTree`. [#59290](https://github.com/ClickHouse/ClickHouse/pull/59290) ([Anton Popov](https://github.com/CurtizJ)).
* Se reduce el uso de memoria en las fusiones verticales. [#59340](https://github.com/ClickHouse/ClickHouse/pull/59340) ([Anton Popov](https://github.com/CurtizJ)).
