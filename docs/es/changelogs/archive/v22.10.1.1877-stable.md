  # Registro de cambios de 2022

<div id="clickhouse-release-v221011877-stable-98ab5a3c189-fixme-as-compared-to-v22912603-stable-3030d4c7ff0">
  ### Lanzamiento de ClickHouse v22.10.1.1877-stable (98ab5a3c189) FIXME en comparación con v22.9.1.2603-stable (3030d4c7ff0)
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Renombrar los comandos de caché: `show caches` -&gt; `show filesystem caches`, `describe cache` -&gt; `describe filesystem cache`. [#41508](https://github.com/ClickHouse/ClickHouse/pull/41508) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Eliminar la compatibilidad con la cláusula `WITH TIMEOUT` en `LIVE VIEW`. Esto cierra el issue [#40557](https://github.com/ClickHouse/ClickHouse/issues/40557). [#42173](https://github.com/ClickHouse/ClickHouse/pull/42173) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade compatibilidad con código Rust en ClickHouse, usando la biblioteca de funciones hash BLAKE3 como ejemplo. [#33435](https://github.com/ClickHouse/ClickHouse/pull/33435) ([BoloniniD](https://github.com/BoloniniD)).
* Esta es la implementación inicial de Kusto Query Language (MVP). [#37961](https://github.com/ClickHouse/ClickHouse/pull/37961) ([Yong Wang](https://github.com/kashwy)).
* * Se permite limitar los datos temporales almacenados en disco mediante la configuración `max_temporary_data_on_disk_size_for_user`/`max_temporary_data_on_disk_size_for_query` . [#40893](https://github.com/ClickHouse/ClickHouse/pull/40893) ([Vladimir C](https://github.com/vdimir)).
* Se admite el hash de enteros de Java en `javaHash`. [#41131](https://github.com/ClickHouse/ClickHouse/pull/41131) ([JackyWoo](https://github.com/JackyWoo)).
* Este PR añade compatibilidad con la compilación interna de OpenSSL, al igual que con el submódulo de BoringSSL. El indicador de compilación ENABLE&#95;CH&#95;BUNDLE&#95;BORINGSSL se utiliza para elegir entre BoringSSL y OpenSSL. De forma predeterminada, se usará la compilación interna de BoringSSL. [#41142](https://github.com/ClickHouse/ClickHouse/pull/41142) ([MeenaRenganathan22](https://github.com/MeenaRenganathan22)).
* Se añade una configuración de protocolo componible. [#41198](https://github.com/ClickHouse/ClickHouse/pull/41198) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Se añade compatibilidad con OpenTelemetry para DDL ON CLUSTER (requiere que `distributed_ddl_entry_format_version` esté establecido en 4). [#41484](https://github.com/ClickHouse/ClickHouse/pull/41484) ([Frank Chen](https://github.com/FrankChen021)).
* Se añade la configuración `format_json_object_each_row_column_for_object_name` para escribir/analizar el nombre del objeto como valor de columna en el formato JSONObjectEachRow. [#41703](https://github.com/ClickHouse/ClickHouse/pull/41703) ([Kruglov Pavel](https://github.com/Avogar)).
* Se añaden funciones de codificación y decodificación de Morton Coding (ZCurve). [#41753](https://github.com/ClickHouse/ClickHouse/pull/41753) ([Constantine Peresypkin](https://github.com/pkit)).
* Se implementa compatibilidad con distintos formatos binarios de UUID, incluidos los dos más habituales: el big-endian predeterminado y el mixed-endian de Microsoft, tal como se especifica en [RFC 4122](https://datatracker.ietf.org/doc/html/rfc4122#section-4.1.1). [#42108](https://github.com/ClickHouse/ClickHouse/pull/42108) ([ltrk2](https://github.com/ltrk2)).
* Se añadió una función de agregación `analysisOfVariance` (`anova`) para realizar una prueba estadística sobre varios grupos de observaciones con distribución normal y determinar si todos los grupos tienen la misma media o no. PR original [#37872](https://github.com/ClickHouse/ClickHouse/issues/37872). [#42131](https://github.com/ClickHouse/ClickHouse/pull/42131) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se añade compatibilidad con `SET setting_name = DEFAULT`. [#42187](https://github.com/ClickHouse/ClickHouse/pull/42187) ([Filatenkov Artur](https://github.com/FArthur-cmd)).
* * Se añaden funciones de `URL` conformes con la RFC. Las funciones incluyen: `cutToFirstSignificantSubdomainCustomRFC`, `cutToFirstSignificantSubdomainCustomWithWWWRFC`, `cutToFirstSignificantSubdomainRFC`, `cutToFirstSignificantSubdomainWithWWWRFC`, `domainRFC`, `domainWithoutWWWRFC`, `firstSignificantSubdomainCustomRFC`, `firstSignificantSubdomainRFC`, `portRFC`, `topLevelDomainRFC`. [#42274](https://github.com/ClickHouse/ClickHouse/pull/42274) ([Quanfa Fu](https://github.com/dentiscalprum)).
* Se añadieron funciones (`randUniform`, `randNormal`, `randLogNormal`, `randExponential`, `randChiSquared`, `randStudentT`, `randFisherF`, `randBernoulli`, `randBinomial`, `randNegativeBinomial`, `randPoisson` ) para generar valores aleatorios según las distribuciones especificadas. Con esto se cierra el issue [#21834](https://github.com/ClickHouse/ClickHouse/issues/21834). [#42411](https://github.com/ClickHouse/ClickHouse/pull/42411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Implementa un parser de elementos con precedencia de operadores para resolver problemas de desbordamiento de pila y reducir el tamaño de pila necesario. [#34892](https://github.com/ClickHouse/ClickHouse/pull/34892) ([Nikolay Degterinsky](https://github.com/evillique)).
* La optimización de DISTINCT en orden aprovecha las propiedades de ordenación de los flujos de datos. Esta mejora permitirá la lectura en orden para DISTINCT cuando corresponda (antes era necesario especificar ORDER BY para las columnas de DISTINCT). [#41014](https://github.com/ClickHouse/ClickHouse/pull/41014) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector: optimiza el índice UInt8 con AVX512VBMI. [#41247](https://github.com/ClickHouse/ClickHouse/pull/41247) ([Guo Wangyang](https://github.com/guowangy)).
* Los experimentos de rendimiento de **SSB** (Star Schema Benchmark) en el dispositivo ICX (CPU Intel Xeon Platinum 8380, 80 núcleos, 160 threads) muestran que este cambio podría aportar una mejora de **2.95x** en la media geométrica del QPS de todos los subcasos. [#41675](https://github.com/ClickHouse/ClickHouse/pull/41675) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Se corrigió la lentitud de JSONExtract con tuplas LowCardinality(String). [#41726](https://github.com/ClickHouse/ClickHouse/pull/41726) ([AlfVII](https://github.com/AlfVII)).
* Añade capacidades ldapr a las builds de AArch64. Esto es compatible a partir de Graviton 2+, e instancias de Azure y GCP. Solo apareció en clang-15 [hace no mucho](https://github.com/llvm/llvm-project/commit/9609b5daffe9fd28d83d83da895abc5113f76c24). [#41778](https://github.com/ClickHouse/ClickHouse/pull/41778) ([Daniel Kutenin](https://github.com/danlark1)).
* Mejora el rendimiento al comparar Strings cuando uno de los argumentos es una String constante vacía. [#41870](https://github.com/ClickHouse/ClickHouse/pull/41870) ([Jiebin Sun](https://github.com/jiebinn)).
* Optimiza insertFrom de ColumnAggregateFunction para compartir el estado de agregación en algunos casos. [#41960](https://github.com/ClickHouse/ClickHouse/pull/41960) ([flynn](https://github.com/ucasfl)).
* Relaja el umbral de &quot;Too many parts&quot;. Esto cierra [#6551](https://github.com/ClickHouse/ClickHouse/issues/6551). Ahora ClickHouse permitirá más partes en una partición si el tamaño medio de las partes es lo bastante grande (al menos 10 GiB). Esto permite tener hasta petabytes de datos en una sola partición de una sola tabla en un solo server, lo que es posible usando cabinas de discos o object storage. [#42002](https://github.com/ClickHouse/ClickHouse/pull/42002) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Hace más eficiente la escritura en AzureBlobStorage (respeta `max_single_part_upload_size` en lugar de escribir un bloque por cada tamaño de búfer). La ineficiencia se mencionó en [#41754](https://github.com/ClickHouse/ClickHouse/issues/41754). [#42041](https://github.com/ClickHouse/ClickHouse/pull/42041) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Hace que los ID de thread de la lista de procesos y query&#95;log sean únicos para evitar desperdicio. [#42180](https://github.com/ClickHouse/ClickHouse/pull/42180) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="improvement">
  #### Mejora
</div>

* Se añadió una nueva infraestructura para el análisis y la planificación de consultas en la opción de configuración `allow_experimental_analyzer`. [#31796](https://github.com/ClickHouse/ClickHouse/pull/31796) ([Maksim Kita](https://github.com/kitaisreal)).
* * Se admite la expresión `(EXPLAIN SELECT ...)` en una subconsulta. Consultas como `SELECT * FROM (EXPLAIN PIPELINE SELECT col FROM TABLE ORDER BY col)` pasaron a ser válidas. [#40630](https://github.com/ClickHouse/ClickHouse/pull/40630) ([Vladimir C](https://github.com/vdimir)).
* Actualmente, cambiar `async_insert_max_data_size` o `async_insert_busy_timeout_ms` en el ámbito de una consulta no tiene sentido y esto genera una mala experiencia de usuario. Por ejemplo, un usuario quiere insertar datos con poca frecuencia y no tiene acceso a la configuración del servidor para ajustar la configuración predeterminada. [#40668](https://github.com/ClickHouse/ClickHouse/pull/40668) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* El Keeper integrado siempre se iniciará en segundo plano, lo que permitirá que ClickHouse se inicie sin alcanzar el cuórum. [#40991](https://github.com/ClickHouse/ClickHouse/pull/40991) ([Antonio Andelic](https://github.com/antonio2368)).
* Mejoras en la lectura desde filesystems remotos; ahora el tamaño del threadpool para lecturas/escrituras es configurable. Cierra [#41070](https://github.com/ClickHouse/ClickHouse/issues/41070). [#41011](https://github.com/ClickHouse/ClickHouse/pull/41011) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se hizo más reactiva la restauración de una nueva conexión en caso de que expirara la anterior. Antes había una tarea que se ejecutaba cada minuto de forma predeterminada y, por lo tanto, una tabla podía permanecer en estado readonly durante aproximadamente ese tiempo. [#41092](https://github.com/ClickHouse/ClickHouse/pull/41092) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Compatibilidad con todas las combinaciones de combinators en el versionado de WindowTransform/arratReduce*/initializeAggregation/aggregate functions. Antes, combinators como `ForEach/Resample/Map` no funcionaban en estos casos; usarlos provocaba excepciones como `State function ... inserts results into non-state column`. [#41107](https://github.com/ClickHouse/ClickHouse/pull/41107) ([Kruglov Pavel](https://github.com/Avogar)).
* Ahora las projections pueden usarse con replicación zero copy. [#41147](https://github.com/ClickHouse/ClickHouse/pull/41147) ([alesapin](https://github.com/alesapin)).
* * Agrega la función tryDecrypt, que devuelve NULL cuando el descifrado falla (p. ej., al descifrar con una clave incorrecta) en lugar de lanzar una excepción. [#41206](https://github.com/ClickHouse/ClickHouse/pull/41206) ([Duc Canh Le](https://github.com/canhld94)).
* Añade la columna `unreserved_space` a la tabla `system.disks` para comprobar cuánto espacio no está ocupado por reservas en cada disco. [#41254](https://github.com/ClickHouse/ClickHouse/pull/41254) ([filimonov](https://github.com/filimonov)).
* Añade compatibilidad con encabezados de autorización de S3 desde argumentos AST. [#41261](https://github.com/ClickHouse/ClickHouse/pull/41261) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Añade la configuración &#39;allow&#95;implicit&#95;no&#95;password&#39;, que prohíbe crear un usuario sin contraseña a menos que se especifique explícitamente &#39;IDENTIFIED WITH no&#95;password&#39;. [#41341](https://github.com/ClickHouse/ClickHouse/pull/41341) ([Nikolay Degterinsky](https://github.com/evillique)).
* keeper-improvement: añade compatibilidad para subir snapshots a S3. La información de S3 puede definirse dentro de `keeper_server.s3_snapshot`. [#41342](https://github.com/ClickHouse/ClickHouse/pull/41342) ([Antonio Andelic](https://github.com/antonio2368)).
* Añade compatibilidad con MultiRead en Keeper y en el client interno de ZooKeeper. [#41410](https://github.com/ClickHouse/ClickHouse/pull/41410) ([Antonio Andelic](https://github.com/antonio2368)).
* Añade compatibilidad para comparar el tipo Decimal con un literal de coma flotante en el operador IN. [#41544](https://github.com/ClickHouse/ClickHouse/pull/41544) ([liang.huang](https://github.com/lhuang09287750)).
* Permite valores de tamaño legible en la configuración de caché. [#41688](https://github.com/ClickHouse/ClickHouse/pull/41688) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Comprueba la ruta del archivo frente a ataques de recorrido de rutas en el logger de errores para formatos de entrada. [#41694](https://github.com/ClickHouse/ClickHouse/pull/41694) ([Kruglov Pavel](https://github.com/Avogar)).

Durante ese período, ClickHouse podía, no obstante, intentar establecer una conexión y generar errores. Este comportamiento se ha corregido. <div id="buildtestingpackaging-improvement">
  #### Mejora de compilación/pruebas/empaquetado
</div>

* Se añadió compatibilidad con la generación de la cláusula WHERE a AST Fuzzer, así como la posibilidad de añadir o eliminar ORDER BY y la cláusula WHERE. [#38519](https://github.com/ClickHouse/ClickHouse/pull/38519) ([Ilya Yatsishin](https://github.com/qoega)).
* Los binarios Aarch64 ahora requieren como mínimo ARMv8.2, publicado en 2016. En particular, esto permite usar ARM LSE, es decir, operaciones atómicas nativas. Además, se ha añadido la build option de CMake &quot;NO&#95;ARMV81&#95;OR&#95;HIGHER&quot; para permitir compilar binarios para hardware ARMv8.0 más antiguo, por ejemplo, Raspberry Pi 4.
