<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se elimina el ajuste `experimental_use_processors`. Está habilitado de forma predeterminada. [#10924](https://github.com/ClickHouse/ClickHouse/pull/10924) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* El ajuste `input_format_with_names_use_header` está habilitado de forma predeterminada. Esto afectará al análisis de los formatos de entrada `-WithNames` y `-WithNamesAndTypes`. [#10937](https://github.com/ClickHouse/ClickHouse/pull/10937) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió una comprobación para el caso en que un ajuste de nivel de usuario se especifica en un lugar incorrecto. Los ajustes de nivel de usuario deben especificarse en `users.xml`, dentro de la sección `<profile>` del perfil de usuario correspondiente (o en `<default>` para los ajustes predeterminados). El servidor no se iniciará y mostrará un mensaje de excepción en el log. Esto corrige [#9051](https://github.com/ClickHouse/ClickHouse/issues/9051). Si quiere omitir la comprobación, puede mover los ajustes al lugar adecuado o añadir `<skip_check_for_incorrect_settings>1</skip_check_for_incorrect_settings>` a config.xml. [#11449](https://github.com/ClickHouse/ClickHouse/pull/11449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Devuelve un resultado no Nullable en COUNT(DISTINCT) y en la familia de funciones de agregación `uniq`. Si todos los valores pasados son NULL, devuelve cero en su lugar. Esto mejora la compatibilidad con SQL. [#11661](https://github.com/ClickHouse/ClickHouse/pull/11661) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Nueva optimización que extrae las operaciones aritméticas de las funciones de agregación. [#10047](https://github.com/ClickHouse/ClickHouse/pull/10047) ([Ruslan](https://github.com/kamalov-ruslan)).

* Se añade detección de CPU en tiempo de ejecución para seleccionar y usar la mejor implementación de función. Se añade compatibilidad con generación de código para múltiples objetivos. Esto cierra [#1017](https://github.com/ClickHouse/ClickHouse/issues/1017). [#10058](https://github.com/ClickHouse/ClickHouse/pull/10058) ([DimasKovas](https://github.com/DimasKovas)).
* Se eliminan ORDER BY y DISTINCT duplicados de las subconsultas. [#10067](https://github.com/ClickHouse/ClickHouse/pull/10067) ([Mikhail Malafeev](https://github.com/demo-99)).
* Se ordenan partes más grandes de la tabla izquierda en MergeJoin. Se almacenan en búfer en memoria los bloques de la tabla izquierda. Se añade la configuración `partial_merge_join_left_table_buffer_bytes` para gestionar el tamaño de los búferes de los bloques de la tabla izquierda. [#10601](https://github.com/ClickHouse/ClickHouse/pull/10601) ([Artem Zuikov](https://github.com/4ertus2)).
* Se obtiene el diccionario y se comprueban los derechos de acceso solo una vez por cada llamada a cualquier función que lea diccionarios externos. [#10928](https://github.com/ClickHouse/ClickHouse/pull/10928) ([Vitaly Baranov](https://github.com/vitlibar)).
* Mejora de radix sort mediante la eliminación de algunos movimientos de datos redundantes. [#10981](https://github.com/ClickHouse/ClickHouse/pull/10981) ([Arslan Gumerov](https://github.com/g-arslan)).
* Hace que las queries con la función de agregación `sum` y sin claves de GROUP BY se ejecuten varias veces más rápido. [#10992](https://github.com/ClickHouse/ClickHouse/pull/10992) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se habilita mlock para el binario de ClickHouse de forma predeterminada. Esto evitará que el ejecutable de ClickHouse se pagine al disco bajo alta carga de IO. [#11139](https://github.com/ClickHouse/ClickHouse/pull/11139) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rendimiento mejorado para queries con `ORDER BY` y `LIMIT` pequeño (menor que `max_block_size`). [#11171](https://github.com/ClickHouse/ClickHouse/pull/11171) ([Provet](https://github.com/Provet)).
* Mejora el rendimiento de las queries INSERT mediante INSERT SELECT o INSERT con clickhouse-client cuando se generan bloques pequeños (caso típico con parsing en paralelo). Esto corrige [#11275](https://github.com/ClickHouse/ClickHouse/issues/11275). Se corrige el problema de que las CONSTRAINT no funcionaban para campos DEFAULT. Esto corrige [#11273](https://github.com/ClickHouse/ClickHouse/issues/11273). Se corrige el problema de que las CONSTRAINT se ignoraban para tablas TEMPORARY. Esto corrige [#11274](https://github.com/ClickHouse/ClickHouse/issues/11274). [#11276](https://github.com/ClickHouse/ClickHouse/pull/11276) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el rendimiento de `clickhouse-client` en modo interactivo cuando se usan formatos Pretty. En versiones anteriores, se podía dedicar una cantidad significativa de tiempo a calcular el ancho visible de una cadena UTF-8. Esto cierra [#11323](https://github.com/ClickHouse/ClickHouse/issues/11323). [#11323](https://github.com/ClickHouse/ClickHouse/pull/11323) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nueva optimización que extrae todas las operaciones de la función &quot;any&quot;. [#11529](https://github.com/ClickHouse/ClickHouse/pull/11529) ([Ruslan](https://github.com/kamalov-ruslan)).
* Acelera el merging en AggregatingMergeTree. Esto corrige una regresión de rendimiento introducida hace más de un año en [#4348](https://github.com/ClickHouse/ClickHouse/issues/4348) (en la versión 19.3). [#11534](https://github.com/ClickHouse/ClickHouse/pull/11534) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Permite que varias réplicas asignen merges, mutaciones y operaciones de eliminación, movimiento y reemplazo de particiones de forma concurrente. Esto cierra [#10367](https://github.com/ClickHouse/ClickHouse/issues/10367). [#11639](https://github.com/ClickHouse/ClickHouse/pull/11639) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
