<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se permite escribir `SETTINGS` antes de `FORMAT` en una cadena de consultas con `UNION` cuando las subconsultas están entre paréntesis. Esto cierra [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712). Se cambia el comportamiento cuando una consulta tiene la cláusula SETTINGS especificada dos veces en secuencia. La cláusula SETTINGS más cercana tendrá prioridad para la subconsulta correspondiente. En versiones anteriores, la cláusula SETTINGS más externa podía tener prioridad sobre la interna. [#68614](https://github.com/ClickHouse/ClickHouse/pull/68614) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ahora se permite, de forma predeterminada, reordenar las condiciones de filtro de la cláusula `[PRE]WHERE`. Esto puede deshabilitarse estableciendo `allow_reorder_prewhere_conditions` en `false`. [#70657](https://github.com/ClickHouse/ClickHouse/pull/70657) ([Nikita Taranov](https://github.com/nickitat)).
* Se corrige la optimización `optimize_functions_to_subcolumns` (antes podía provocar el error `Invalid column type for ColumnUnique::insertRangeFrom. Expected String, got LowCardinality(String)`), conservando el tipo `LowCardinality` en `mapKeys`/`mapValues`. [#70716](https://github.com/ClickHouse/ClickHouse/pull/70716) ([Azat Khuzhin](https://github.com/azat)).
* Se elimina la biblioteca `idxd-config`, que tiene una licencia incompatible. Esto también elimina el codec experimental Intel DeflateQPL. [#70987](https://github.com/ClickHouse/ClickHouse/pull/70987) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Integración de MongoDB refactorizada: migración al nuevo driver mongocxx desde el obsoleto Poco::MongoDB, eliminación del soporte para el antiguo protocolo obsoleto, soporte para conexión por URI, soporte para todos los tipos de MongoDB, soporte para sentencias WHERE y ORDER BY del lado de MongoDB, y restricción de expresiones no compatibles con MongoDB. [#63279](https://github.com/ClickHouse/ClickHouse/pull/63279) ([Kirill Nikiforov](https://github.com/allmazz)).
* Una nueva opción `--progress-table` en clickhouse-client imprime una tabla con métricas que cambian durante la ejecución de la consulta; una nueva opción `--enable-progress-table-toggle` está asociada a `--progress-table` y alterna la visualización de la tabla de progreso al pulsar la tecla de control (Espacio). [#63689](https://github.com/ClickHouse/ClickHouse/pull/63689) ([Maria Khristenko](https://github.com/mariaKhr)).
* Esto permite conceder acceso a prefijos con comodín. `GRANT SELECT ON db.table_pefix_* TO user`. [#65311](https://github.com/ClickHouse/ClickHouse/pull/65311) ([pufit](https://github.com/pufit)).
* Se añade system.query&#95;metric&#95;log, que contiene el historial de memoria y valores de métricas de la tabla system.events para consultas individuales, volcados periódicamente a disco. [#66532](https://github.com/ClickHouse/ClickHouse/pull/66532) ([Pablo Marcos](https://github.com/pamarcos)).
* Una consulta SELECT sencilla puede escribirse con SELECT implícito para habilitar expresiones de estilo calculadora; por ejemplo, `ch "1 + 2"`. Esto se controla mediante una nueva configuración, `implicit_select`. [#68502](https://github.com/ClickHouse/ClickHouse/pull/68502) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se admite el modo --copy en clickhouse local como atajo para la conversión de formato [#68503](https://github.com/ClickHouse/ClickHouse/issues/68503). [#68583](https://github.com/ClickHouse/ClickHouse/pull/68583) ([Denis Hananein](https://github.com/denis-hananein)).
* Se añade soporte para la función `arrayUnion`. [#68989](https://github.com/ClickHouse/ClickHouse/pull/68989) ([Peter Nguyen](https://github.com/petern48)).
* Se admite la función agregada `quantileExactWeightedInterpolated`, que es una versión interpolada basada en quantileExactWeighted. Algunos pueden preguntarse por qué necesitamos una nueva `quantileExactWeightedInterpolated` si ya tenemos `quantileExactInterpolatedWeighted`. La razón es que la nueva es más precisa que la anterior. Además, es para compatibilidad con Spark en Apache Gluten. [#69619](https://github.com/ClickHouse/ClickHouse/pull/69619) ([李扬](https://github.com/taiyang-li)).
* Se admite la función arrayElementOrNull. Devuelve NULL si el índice del array está fuera de rango o no se encuentra la clave del mapa. [#69646](https://github.com/ClickHouse/ClickHouse/pull/69646) ([李扬](https://github.com/taiyang-li)).
* Permite a los usuarios especificar expresiones regulares mediante los nuevos campos `message_regexp` y `message_regexp_negative` en el archivo `config.xml` para filtrar el logging. El logging se aplica al texto formateado sin color para ofrecer la experiencia más intuitiva para los desarrolladores. [#69657](https://github.com/ClickHouse/ClickHouse/pull/69657) ([Peter Nguyen](https://github.com/petern48)).
* Se admite el tipo Dynamic en la mayoría de las funciones ejecutándolas sobre los tipos internos dentro de Dynamic. [#69691](https://github.com/ClickHouse/ClickHouse/pull/69691) ([Pavel Kruglov](https://github.com/Avogar)).
* Se volvió a añadir la función `RIPEMD160`, que calcula el hash criptográfico RIPEMD-160 de una cadena. Ejemplo: `SELECT HEX(RIPEMD160('The quick brown fox jumps over the lazy dog'))` devuelve `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`. [#70087](https://github.com/ClickHouse/ClickHouse/pull/70087) ([Dergousov Maxim](https://github.com/m7kss1)).
* Permite almacenar en caché archivos leídos para motores de tabla de almacenamiento de objetos y lagos de datos usando el hash de ETag + la ruta del archivo como clave de caché. [#70135](https://github.com/ClickHouse/ClickHouse/pull/70135) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se admite la lectura de tablas Iceberg en HDFS. [#70268](https://github.com/ClickHouse/ClickHouse/pull/70268) ([flynn](https://github.com/ucasfl)).
* Se permite leer y escribir el tipo JSON como cadena binaria en formato RowBinary con la configuración `input_format_binary_read_json_as_string/output_format_binary_write_json_as_string`. [#70288](https://github.com/ClickHouse/ClickHouse/pull/70288) ([Pavel Kruglov](https://github.com/Avogar)).
* Se permite serializar y deserializar una columna JSON como una única columna String en formato Native. Para la salida, use la configuración `output_format_native_write_json_as_string`. Para la entrada, use la versión de serialización `1` antes de los datos de la columna. [#70312](https://github.com/ClickHouse/ClickHouse/pull/70312) ([Pavel Kruglov](https://github.com/Avogar)).
* Admite CTE estándar, `with insert`, mientras que antes solo admitía `insert ... with ...`. [#70593](https://github.com/ClickHouse/ClickHouse/pull/70593) ([Shichao Jin](https://github.com/jsc0218)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Compatibilidad con el índice minmax para `pointInPolygon`. [#62085](https://github.com/ClickHouse/ClickHouse/pull/62085) ([JackyWoo](https://github.com/JackyWoo)).
* Se añade compatibilidad con filtros bloom de Parquet. [#62966](https://github.com/ClickHouse/ClickHouse/pull/62966) ([Arthur Passos](https://github.com/arthurpassos)).
* Cambio de nombre de partes sin bloqueos para evitar que `INSERT` afecte a `SELECT` (debido al bloqueo de partes) (en condiciones normales con `fsync_part_directory`, el QPS de `SELECT` con `INSERT` en paralelo aumentó 2 veces; bajo alta carga, el efecto es aún mayor). Tenga en cuenta que, por ahora, esto solo incluye `ReplicatedMergeTree`. [#64955](https://github.com/ClickHouse/ClickHouse/pull/64955) ([Azat Khuzhin](https://github.com/azat)).
* Se respeta `ttl_only_drop_parts` en `materialize ttl`; solo se leen las columnas necesarias para recalcular el TTL y eliminar partes reemplazándolas por una vacía. [#65488](https://github.com/ClickHouse/ClickHouse/pull/65488) ([Andrey Zvonov](https://github.com/zvonand)).
* Se refactorizan `IDisk` e `IObjectStorage` para mejorar el rendimiento. Las tablas de los almacenamientos de objetos `plain` y `plain_rewritable` se inicializarán más rápido. [#68146](https://github.com/ClickHouse/ClickHouse/pull/68146) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se optimizó la creación de hilos en ThreadPool para minimizar la contención de bloqueos. La creación de hilos ahora se realiza fuera de la sección crítica para evitar retrasos en la planificación de trabajos y la gestión de hilos en condiciones de alta carga. Esto hace que ClickHouse responda mucho mejor bajo alta carga concurrente. [#68694](https://github.com/ClickHouse/ClickHouse/pull/68694) ([filimonov](https://github.com/filimonov)).
* Se habilita la lectura de columnas String LowCardinality desde ORC. [#69481](https://github.com/ClickHouse/ClickHouse/pull/69481) ([李扬](https://github.com/taiyang-li)).
* Se añadió la capacidad de analizar datos directamente en columnas dispersas. [#69828](https://github.com/ClickHouse/ClickHouse/pull/69828) ([Anton Popov](https://github.com/CurtizJ)).
* Admite la lectura en paralelo de grupos de filas de Parquet y la precarga de grupos de filas en modo de un solo hilo. [#69862](https://github.com/ClickHouse/ClickHouse/pull/69862) ([LiuNeng](https://github.com/liuneng1994)).
* Se mejoró el rendimiento del análisis de formatos con un gran número de valores ausentes (por ejemplo, `JSONEachRow`). [#69875](https://github.com/ClickHouse/ClickHouse/pull/69875) ([Anton Popov](https://github.com/CurtizJ)).
* Se usa `LowCardinality` para `ProfileEvents` en registros del sistema como `part_log`, `query_views_log` y `filesystem_cache_log`. [#70152](https://github.com/ClickHouse/ClickHouse/pull/70152) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se mejoró el rendimiento de las funciones FromUnixTimestamp/ToUnixTimestamp. [#71042](https://github.com/ClickHouse/ClickHouse/pull/71042) ([kevinyhzou](https://github.com/KevinyhZou)).

<div id="improvement">
  #### Mejora
</div>

* Permitir alias SQL con parámetros. [#50665](https://github.com/ClickHouse/ClickHouse/pull/50665) ([Anton Kozlov](https://github.com/tonickkozlov)).
* Se corrigió [#57616](https://github.com/ClickHouse/ClickHouse/issues/57616): este problema se produce porque todos los argumentos numéricos positivos se identifican automáticamente como de tipo `uint64`, lo que impide hacer coincidir datos de tipo `int` en `summapfiltered`. Esta falta de coincidencia resulta especialmente confusa, ya que el usuario no especifica los parámetros `uint64`. Además, si los argumentos son `[1,2,3,toint8(-3)]`, debido a `getleastsupertype()`, estos parámetros se tratarán uniformemente como de tipo `int`, lo que también hará que `'1,2,3'` no coincida con los datos de tipo `uint` en `summapfiltered`. [#58408](https://github.com/ClickHouse/ClickHouse/pull/58408) ([Chen768959](https://github.com/Chen768959)).
* `ALTER TABLE .. REPLACE PARTITION` ya no espera a que finalicen las mutations/merges que se producen en otras particiones. [#59138](https://github.com/ClickHouse/ClickHouse/pull/59138) ([Vasily Nemkov](https://github.com/Enmk)).
* Las vistas materializadas actualizables ahora son compatibles con las bases de datos Replicated. [#60669](https://github.com/ClickHouse/ClickHouse/pull/60669) ([Michael Kolupaev](https://github.com/al13n321)).
* Los enlaces simbólicos de las tablas en el directorio `data/database_name/` se crean para las rutas reales de los datos de la tabla, según la storage policy, en lugar de apuntar al directorio `store/...` del disco predeterminado. [#61777](https://github.com/ClickHouse/ClickHouse/pull/61777) ([Kirill](https://github.com/kirillgarbar)).
* Aplicar actualizaciones de configuración en el objeto de contexto global. Esto corrige problemas como [#62308](https://github.com/ClickHouse/ClickHouse/issues/62308). [#62944](https://github.com/ClickHouse/ClickHouse/pull/62944) ([Amos Bird](https://github.com/amosbird)).
* Se rediseñaron los ajustes que controlan el comportamiento de los algoritmos de parallel replicas. Breve resumen: ClickHouse tiene cuatro algoritmos distintos para la lectura en paralelo con varias réplicas, lo que se refleja en el ajuste `parallel_replicas_mode`; su valor predeterminado es `read_tasks`. Además, se añadió el ajuste de activación `enable_parallel_replicas`. [#63151](https://github.com/ClickHouse/ClickHouse/pull/63151) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se corrigió un problema por el que `ReadSettings` no usaba los valores establecidos por el usuario, sino únicamente los valores predeterminados. [#65625](https://github.com/ClickHouse/ClickHouse/pull/65625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Al analizar un campo Enum desde JSON, una cadena que contiene un entero se interpretará como el elemento Enum correspondiente. Esto cierra [#65119](https://github.com/ClickHouse/ClickHouse/issues/65119). [#66801](https://github.com/ClickHouse/ClickHouse/pull/66801) ([scanhex12](https://github.com/scanhex12)).
* Permitir que `TRIM` aplicado a una cadena vacía con `LEADING` o `TRAILING` actúe como un no-op. Cierra [#67792](https://github.com/ClickHouse/ClickHouse/issues/67792). [#68455](https://github.com/ClickHouse/ClickHouse/pull/68455) ([Peter Nguyen](https://github.com/petern48)).
* Se admite crear una tabla a partir de una consulta: `CREATE TABLE ... CLONE AS ...`. Clona el schema de la tabla de origen y luego adjunta todas las particiones a la tabla recién creada. Esta funcionalidad solo es compatible con tablas de la familia `MergeTree`. Cierra [#65015](https://github.com/ClickHouse/ClickHouse/issues/65015). [#69091](https://github.com/ClickHouse/ClickHouse/pull/69091) ([tuanpach](https://github.com/tuanpach)).
* En Gluten ClickHouse, el tipo `timestamp` de Spark se asigna al tipo `datetime64(6)` de ClickHouse. Al convertir el timestamp &#39;2012-01-01 00:11:22&#39; a cadena, Spark devuelve &#39;2012-01-01 00:11:22&#39;, mientras que Gluten ClickHouse devuelve &#39;2012-01-01 00:11:22.000000&#39;. [#69179](https://github.com/ClickHouse/ClickHouse/pull/69179) ([Wenzheng Liu](https://github.com/lwz9103)).
* Usar siempre el nuevo analizador para calcular expresiones constantes cuando `enable_analyzer` esté configurado como `true`. Admitir el cálculo de argumentos de la función de tabla `executable()` sin usar una consulta `SELECT` para la expresión constante. [#69292](https://github.com/ClickHouse/ClickHouse/pull/69292) ([Dmitry Novik](https://github.com/novikd)).

Posibles valores: - `user_display`: cuando los identificadores sean una palabra clave. - `when_necessary`: cuando los identificadores sean uno de `{"distinct", "all", "table"}` o puedan causar ambigüedad: nombres de columna, nombres de atributos de diccionario. - `always`: entrecomillar siempre los identificadores.
