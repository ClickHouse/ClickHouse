<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* La función `yandexConsistentHash` (algoritmo de hash consistente de Konstantin &quot;kostik&quot; Oblakov) pasa a llamarse `kostikConsistentHash`. El nombre anterior se mantiene como alias por compatibilidad. Aunque este cambio es compatible con versiones anteriores, es posible que eliminemos el alias en versiones posteriores, por lo que se recomienda actualizar el uso de esta función en las aplicaciones. [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* No se permite SETTINGS después de FORMAT en consultas INSERT (existe la configuración de compatibilidad `allow_settings_after_format_in_insert` para aceptar esas consultas, pero está desactivada de forma predeterminada). [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* Se cambió la ruta hash de los archivos de caché. [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se aceleró el proceso de carga de partes de MergeTree para reducir el tiempo de arranque de clickhouse-server. Con esta mejora, clickhouse-server pudo reducir el tiempo de arranque de 75 minutos a 20 segundos con 700k partes de MergeTree. [#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* Los tamaños de las tablas hash utilizadas durante la agregación ahora se recopilan y se usan en consultas posteriores para evitar el redimensionamiento de las tablas hash. [#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* Múltiples cambios para mejorar el rendimiento de ASOF JOIN (entre 1,2 y 1,6 veces más rápido). También añade compatibilidad con enteros grandes. [#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* El motor de almacenamiento URL ahora descarga múltiples fragmentos en paralelo si el endpoint admite HTTP Range. Se añadieron dos settings adicionales, `max_download_threads` y `max_download_buffer_size`, que controlan el número máximo de threads que una sola consulta puede usar para descargar el archivo y el número máximo de bytes que cada thread puede procesar. [#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* Paralelización de multipart upload en el almacenamiento S3. [#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* Mejora del rendimiento de ASOF JOIN si la key es un entero nativo. [#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* Nueva optimización del plan de consulta: evaluar las funciones después de `ORDER BY` cuando sea posible. Por ejemplo, en una consulta `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5`, la función `sipHash64` se evaluaría después de `ORDER BY` y `LIMIT`, lo que proporciona una aceleración de ~20x. [#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* Se redujo el alcance del mutex para un issue relacionado con setenv LIBHDFS3&#95;CONF [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292). [#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* Mejora del rendimiento de la función `hasAll` mediante especializaciones para SSE y AVX2. Autor: @youennL-cs. [#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * La instrucción explain de GLOBAL JOIN entre dos tablas distribuidas puede acelerarse hasta 100x: explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2 optimizaciones: - Optimizar una consulta count trivial de Hive - Acelerar consultas de Hive mediante el almacenamiento en caché de los metadatos de archivos de Hive. [#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
