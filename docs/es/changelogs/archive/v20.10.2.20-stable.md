<div id="clickhouse-release-v2010220-stable-fixme-as-compared-to-v20914585-prestable">
  ### Lanzamiento de ClickHouse v20.10.2.20-stable FIXME en comparación con v20.9.1.4585-prestable
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se añade compatibilidad con comentarios multilínea anidados `/* comment /* comment */ */` en SQL. Esto cumple con el estándar SQL. [#14655](https://github.com/ClickHouse/ClickHouse/pull/14655) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se cambia el valor predeterminado de la configuración `format_regexp_escaping_rule` (está relacionada con el formato `Regexp`) a `Raw` (es decir, leer el subpatrón completo como un valor) para que el comportamiento se asemeje más a lo que esperan los usuarios. [#15426](https://github.com/ClickHouse/ClickHouse/pull/15426) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `multiple_joins_rewriter_version` pasa a estar obsoleto. Se elimina la primera versión del reescritor de JOIN. [#15472](https://github.com/ClickHouse/ClickHouse/pull/15472) ([Artem Zuikov](https://github.com/4ertus2)).



<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Añade una nueva funcionalidad: el formato `LineAsString`, que acepta una secuencia de líneas separadas por saltos de línea, espacios y/o comas. [#14703](https://github.com/ClickHouse/ClickHouse/pull/14703) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se añadió la función `formatReadableQuantity`. Es útil para que las personas puedan leer números grandes más fácilmente. [#14725](https://github.com/ClickHouse/ClickHouse/pull/14725) ([Artem Hnilov](https://github.com/BooBSD)).
* Añade la capacidad de eliminar propiedades de columnas y TTL de tablas. Se introdujeron las consultas `ALTER TABLE MODIFY COLUMN col_name REMOVE what_to_remove` y `ALTER TABLE REMOVE TTL`. Ambas operaciones son ligeras y se ejecutan a nivel de metadatos. [#14742](https://github.com/ClickHouse/ClickHouse/pull/14742) ([alesapin](https://github.com/alesapin)).
* Introduce el campo event&#95;time&#95;microseconds en las tablas `system.text_log`, `system.trace_log`, `system.query_log` y `system.query_thread_log`. [#14760](https://github.com/ClickHouse/ClickHouse/pull/14760) ([Bharat Nallan](https://github.com/bharatnc)).
* Ahora admitimos `WITH <identifier> AS (subquery) ... ` para introducir subconsultas con nombre en el contexto de la consulta. Esto cierra [#2416](https://github.com/ClickHouse/ClickHouse/issues/2416). Esto cierra [#4967](https://github.com/ClickHouse/ClickHouse/issues/4967). [#14771](https://github.com/ClickHouse/ClickHouse/pull/14771) ([Amos Bird](https://github.com/amosbird)).
* Permite omitir argumentos para el motor de tabla Replicated si se especifican valores predeterminados en la configuración. [#14791](https://github.com/ClickHouse/ClickHouse/pull/14791) ([vxider](https://github.com/Vxider)).
* Añade la función de tabla `null('structure')`. [#14797](https://github.com/ClickHouse/ClickHouse/pull/14797) ([vxider](https://github.com/Vxider)).
* Se añadió una herramienta de ofuscación de consultas. Permite compartir más consultas para mejorar las pruebas. Esto cierra [#15268](https://github.com/ClickHouse/ClickHouse/issues/15268). [#15321](https://github.com/ClickHouse/ClickHouse/pull/15321) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió el formato `RawBLOB`. Está pensado para la entrada o salida de un único valor sin caracteres de escape ni delimitadores. Esto cierra [#15349](https://github.com/ClickHouse/ClickHouse/issues/15349). [#15364](https://github.com/ClickHouse/ClickHouse/pull/15364) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige [15350](https://github.com/ClickHouse/ClickHouse/issues/15350). [#15443](https://github.com/ClickHouse/ClickHouse/pull/15443) ([flynn](https://github.com/ucasfl)).
* Introduce la configuración `enable_global_with_statement`, que propaga las cláusulas `WITH` del primer `SELECT` a otras consultas `SELECT` del mismo nivel y hace que los alias de las sentencias `WITH` sean visibles para las subconsultas. [#15451](https://github.com/ClickHouse/ClickHouse/pull/15451) ([Amos Bird](https://github.com/amosbird)).
* Añade la función `reinterpretAsUUID`, que permite convertir una cadena de bytes big-endian en UUID. [#15480](https://github.com/ClickHouse/ClickHouse/pull/15480) ([Alexander Kuzmenkov](https://github.com/akuzm)).
* Añade inserciones con cuórum en paralelo. Esto cierra [#15601](https://github.com/ClickHouse/ClickHouse/issues/15601). [#15601](https://github.com/ClickHouse/ClickHouse/pull/15601) ([Latysheva Alexandra](https://github.com/alexelex)).



<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Mejora el rendimiento de los valores de 256 bits usando (u)int64&#95;t como tipo base para enteros anchos. Los enteros anchos originales usan tipos de 8 bits como base. [#14859](https://github.com/ClickHouse/ClickHouse/pull/14859) ([Artem Zuikov](https://github.com/4ertus2)).
* Bloquea con `mlock` solo el segmento de código al iniciar clickhouse-server. En versiones anteriores, todas las regiones mapeadas se bloqueaban en memoria, incluida la información de depuración. La información de depuración normalmente se separa en un archivo independiente, pero si no es así, esto provocaba un uso de memoria adicional de +2..3 GiB. [#14929](https://github.com/ClickHouse/ClickHouse/pull/14929) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Antes se elegía el método de fixed key para agrupar por un FixedString. Esto es innecesario, ya que tenemos StringHashTable, que realiza una optimización packedFix similar para columnas FixedString. Y deberíamos usar low&#95;cardinality&#95;key&#95;fixed&#95;string si es posible. [#15034](https://github.com/ClickHouse/ClickHouse/pull/15034) ([Amos Bird](https://github.com/amosbird)).
* Corrige la selección errónea de la implementación genérica lenta para `DateTime <op> DateTime`. Esto corrige [#15153](https://github.com/ClickHouse/ClickHouse/issues/15153). [#15178](https://github.com/ClickHouse/ClickHouse/pull/15178) ([Amos Bird](https://github.com/amosbird)).
* Usa una sola request DeleteObjects de S3 en lugar de múltiples DeleteObject en un ciclo. No hay cambios de funcionalidad, por lo que queda cubierto por las pruebas existentes, como integration/test&#95;log&#95;family&#95;s3. [#15238](https://github.com/ClickHouse/ClickHouse/pull/15238) ([ianton-ru](https://github.com/ianton-ru)).
* Multiplicación de 256 bits más rápida. [#15418](https://github.com/ClickHouse/ClickHouse/pull/15418) ([Artem Zuikov](https://github.com/4ertus2)).
* Mejora el rendimiento de `quantileTDigest`. Esto corrige [#2668](https://github.com/ClickHouse/ClickHouse/issues/2668). [#15542](https://github.com/ClickHouse/ClickHouse/pull/15542) ([Kruglov Pavel](https://github.com/Avogar)).
* Usa explícitamente un disco temporal para almacenar los datos temporales de la vertical merge. [#15639](https://github.com/ClickHouse/ClickHouse/pull/15639) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
