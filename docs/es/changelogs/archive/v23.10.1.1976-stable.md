<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se reescribió por completo el almacenamiento S3Queue: se cambió la forma en que mantenemos la información en ZooKeeper, lo que permite hacer menos solicitudes a ZooKeeper; se añadió almacenamiento en caché del estado de ZooKeeper en los casos en que sabemos que el estado no cambiará; se mejoró el proceso de sondeo desde S3 para hacerlo menos agresivo; se cambió la forma en que se mantienen el TTL y el valor máximo de los archivos rastreados, y ahora es un proceso en segundo plano. Se añadieron las tablas `system.s3queue` y `system.s3queue_log`. Cierra [#54998](https://github.com/ClickHouse/ClickHouse/issues/54998). [#54422](https://github.com/ClickHouse/ClickHouse/pull/54422) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Ya no existe una opción para eliminar automáticamente las partes de datos dañadas. Esto cierra [#55174](https://github.com/ClickHouse/ClickHouse/issues/55174). [#55184](https://github.com/ClickHouse/ClickHouse/pull/55184) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Las partes de datos obsoletas en memoria ya no pueden leerse desde el write-ahead log. Si configuró partes en memoria anteriormente, deben eliminarse antes de la actualización. [#55186](https://github.com/ClickHouse/ClickHouse/pull/55186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se eliminó la integración con Meilisearch. Motivo: solo era compatible con la antigua versión 0.18. La versión reciente de Meilisearch cambió el protocolo y ya no funciona. Nota: agradeceríamos su ayuda para restaurarla. [#55189](https://github.com/ClickHouse/ClickHouse/pull/55189) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se cambió el nombre del concepto de monitor de directorio a background INSERT. Todas las configuraciones `*directory_monitor*` se renombraron a `distributed_background_insert*`. **La compatibilidad con versiones anteriores debe preservarse** (ya que la configuración antigua se añadió como alias). [#55978](https://github.com/ClickHouse/ClickHouse/pull/55978) ([Azat Khuzhin](https://github.com/azat)).
* Ya no se confunden `send_timeout` y `receive_timeout`. [#56035](https://github.com/ClickHouse/ClickHouse/pull/56035) ([Azat Khuzhin](https://github.com/azat)).
* La comparación de intervalos de tiempo con distintas unidades lanzará una excepción. Esto cierra [#55942](https://github.com/ClickHouse/ClickHouse/issues/55942). Es posible que en ocasiones dependiera del comportamiento anterior, en el que se comparaban los valores numéricos subyacentes sin tener en cuenta las unidades. [#56090](https://github.com/ClickHouse/ClickHouse/pull/56090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añadió la función &quot;arrayFold(x1, ..., xn, accum -&gt; expression, array1, ..., arrayn, init&#95;accum)&quot;, que aplica una función lambda a varios arrays con la misma cardinalidad y acumula el resultado en un acumulador. [#49794](https://github.com/ClickHouse/ClickHouse/pull/49794) ([Lirikl](https://github.com/Lirikl)).
* Se añadió la función de agregación lttb, que utiliza el algoritmo [Largest-Triangle-Three-Buckets](https://skemman.is/bitstream/1946/15343/3/SS_MSthesis.pdf) para reducir el muestreo de los datos para su visualización. [#53145](https://github.com/ClickHouse/ClickHouse/pull/53145) ([Sinan](https://github.com/sinsinan)).
* La consulta `CHECK TABLE` tiene mejor rendimiento y usabilidad (envía actualizaciones de progreso y se puede cancelar). Se admite comprobar una parte concreta con `CHECK TABLE ... PART 'part_name'`. [#53404](https://github.com/ClickHouse/ClickHouse/pull/53404) ([vdimir](https://github.com/vdimir)).
* Se añadió la función `jsonMergePatch`. Al trabajar con datos JSON como cadenas, ofrece una forma de fusionarlas (de objetos JSON) para formar una sola cadena que contiene un único objeto JSON. [#54364](https://github.com/ClickHouse/ClickHouse/pull/54364) ([Memo](https://github.com/Joeywzr)).
* Se añadió una nueva función SQL, &quot;arrayRandomSample(arr, k)&quot;, que devuelve una muestra de k elementos del array de entrada. Antes, una funcionalidad similar solo podía lograrse con una sintaxis menos práctica, por ejemplo, &quot;SELECT arrayReduce(&#39;groupArraySample(3)&#39;, range(10))&quot;. [#54391](https://github.com/ClickHouse/ClickHouse/pull/54391) ([itayisraelov](https://github.com/itayisraelov)).
* Se añadió una nueva función `getHttpHeader` para obtener el valor del encabezado de una solicitud HTTP usada en una solicitud al servidor de ClickHouse. Devuelve una cadena vacía si la solicitud no se realiza a través del protocolo HTTP o si ese encabezado no existe. [#54813](https://github.com/ClickHouse/ClickHouse/pull/54813) ([凌涛](https://github.com/lingtaolf)).
* Se introducen los combinators de agregación -ArgMin/-ArgMax, que permiten realizar la agregación solo por valores mínimos o máximos. Puede encontrarse un caso de uso en [#54818](https://github.com/ClickHouse/ClickHouse/issues/54818). Este PR también reorganiza los combinators en una carpeta específica. [#54947](https://github.com/ClickHouse/ClickHouse/pull/54947) ([Amos Bird](https://github.com/amosbird)).
* Se permite eliminar la caché del formato Protobuf con `SYSTEM DROP SCHEMA FORMAT CACHE [FOR Protobuf]`. [#55064](https://github.com/ClickHouse/ClickHouse/pull/55064) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Se añadió un authenticator HTTP Basic externo. [#55199](https://github.com/ClickHouse/ClickHouse/pull/55199) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Se añadió la función `byteSwap`, que invierte los bytes de enteros sin signo. Esto resulta especialmente útil para invertir valores de tipos que se representan internamente como enteros sin signo, como IPv4. [#55211](https://github.com/ClickHouse/ClickHouse/pull/55211) ([Priyansh Agrawal](https://github.com/Priyansh121096)).
* Se añadió la función `formatQuery()`, que devuelve una versión con formato (posiblemente en varias líneas) de una cadena de consulta SQL. También se añadió la función `formatQuerySingleLine()`, que hace lo mismo, pero la cadena devuelta no contendrá saltos de línea. [#55239](https://github.com/ClickHouse/ClickHouse/pull/55239) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Se añadió el formato de entrada DWARF, que lee símbolos de depuración de un ejecutable, biblioteca o archivo objeto ELF. [#55450](https://github.com/ClickHouse/ClickHouse/pull/55450) ([Michael Kolupaev](https://github.com/al13n321)).
* Permitir guardar registros no procesados y errores en los motores RabbitMQ, NATS y FileLog. Añadir las columnas virtuales `_error` y `_raw_message` (para NATS y RabbitMQ), y `_raw_record` (para FileLog), que se rellenan cuando ClickHouse no puede analizar un registro nuevo. El comportamiento se controla mediante la configuración de almacenamiento `nats_handle_error_mode` para NATS, `rabbitmq_handle_error_mode` para RabbitMQ y `handle_error_mode` para FileLog, de forma similar a `kafka_handle_error_mode`. Si se establece en `default`, se lanzará una excepción cuando ClickHouse no pueda analizar un registro; si se establece en `stream`, el error y el registro sin procesar se guardarán en columnas virtuales. Cierra [#36035](https://github.com/ClickHouse/ClickHouse/issues/36035). [#55477](https://github.com/ClickHouse/ClickHouse/pull/55477) ([Kruglov Pavel](https://github.com/Avogar)).
* Mejora del client de Keeper: añadir el comando get&#95;all&#95;children&#95;number, que devuelve el número total de nodos hijo bajo una ruta específica. [#55485](https://github.com/ClickHouse/ClickHouse/pull/55485) ([guoxiaolong](https://github.com/guoxiaolongzte)).
* Si una tabla tiene una curva de llenado de espacio en su clave, por ejemplo, `ORDER BY mortonEncode(x, y)`, las condiciones sobre sus argumentos, por ejemplo, `x >= 10 AND x <= 20 AND y >= 20 AND y <= 30`, pueden usarse para la indexación. Se añade la configuración `analyze_index_with_space_filling_curves` para habilitar o deshabilitar este análisis. Esto cierra [#41195](https://github.com/ClickHouse/ClickHouse/issues/41195). Continuación de [#4538](https://github.com/ClickHouse/ClickHouse/issues/4538). Continuación de [#6286](https://github.com/ClickHouse/ClickHouse/issues/6286). Continuación de [#28130](https://github.com/ClickHouse/ClickHouse/issues/28130). Continuación de [#41753](https://github.com/ClickHouse/ClickHouse/issues/41753). [#55642](https://github.com/ClickHouse/ClickHouse/pull/55642) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añadir la configuración `optimize_trivial_approximate_count_query` para usar la aproximación de `count()` en el almacenamiento EmbeddedRocksDB. Habilitar el conteo trivial para StorageJoin. [#55806](https://github.com/ClickHouse/ClickHouse/pull/55806) ([Duc Canh Le](https://github.com/canhld94)).
* Mejora del client de Keeper: añadir el comando get&#95;direct&#95;children&#95;number, que devuelve el número de nodos hijo directos bajo una ruta. [#55898](https://github.com/ClickHouse/ClickHouse/pull/55898) ([xuzifu666](https://github.com/xuzifu666)).
* Añadir la sentencia `SHOW SETTING setting_name`, que es una versión más sencilla de la sentencia existente `SHOW SETTINGS`. [#55979](https://github.com/ClickHouse/ClickHouse/pull/55979) ([Maksim Kita](https://github.com/kitaisreal)).
* Este PR permite pasar datos en formato Npy a ClickHouse. &#96;&#96;&#96; SELECT * FROM file(&#39;example&#95;array.npy&#39;, Npy). [#55982](https://github.com/ClickHouse/ClickHouse/pull/55982) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Este PR implementa una nueva configuración llamada `force_optimize_projection_name`; toma como argumento un nombre de proyección. Si su valor se establece en una cadena no vacía, ClickHouse comprueba que esta proyección se use en la consulta al menos una vez. Cierra [#55331](https://github.com/ClickHouse/ClickHouse/issues/55331). [#56134](https://github.com/ClickHouse/ClickHouse/pull/56134) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se añadió la opción `query_plan_preserve_num_streams_after_window_functions` para preservar el número de flujos tras evaluar las funciones de ventana y permitir el procesamiento de flujo en paralelo. [#50771](https://github.com/ClickHouse/ClickHouse/pull/50771) ([frinkr](https://github.com/frinkr)).
* Se liberan más `num_streams` si los datos son pequeños. [#53867](https://github.com/ClickHouse/ClickHouse/pull/53867) ([Jiebin Sun](https://github.com/jiebinn)).
* Se optimizan los RoaringBitmaps antes de la serialización. [#55044](https://github.com/ClickHouse/ClickHouse/pull/55044) ([UnamedRus](https://github.com/UnamedRus)).
* Las posting lists de los índices invertidos ahora están optimizadas para usar la representación más pequeña posible para los bitmaps internos. Dependiendo de la repetitividad de los datos, esto puede reducir significativamente el consumo de espacio de los índices invertidos. [#55069](https://github.com/ClickHouse/ClickHouse/pull/55069) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Se corrigió la contención en el bloqueo de Context; esto mejora significativamente el rendimiento de muchas consultas concurrentes de corta duración. [#55121](https://github.com/ClickHouse/ClickHouse/pull/55121) ([Maksim Kita](https://github.com/kitaisreal)).
* Se mejoró en un 30 % el rendimiento de la creación de índices invertidos. Esto se logró sustituyendo `std::unordered_map` por `absl::flat_hash_map`. [#55210](https://github.com/ClickHouse/ClickHouse/pull/55210) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Compatibilidad con filter push down de ORC (a nivel de row group). [#55330](https://github.com/ClickHouse/ClickHouse/pull/55330) ([李扬](https://github.com/taiyang-li)).
* Se mejoró el rendimiento de la agregación externa con muchos archivos temporales. [#55489](https://github.com/ClickHouse/ClickHouse/pull/55489) ([Maksim Kita](https://github.com/kitaisreal)).
* Se establece de forma predeterminada un tamaño razonable para la caché de marks de los índices secundarios, para evitar cargar las marks una y otra vez. [#55654](https://github.com/ClickHouse/ClickHouse/pull/55654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se evita la reconstrucción innecesaria de los gránulos de índice al leer skip indexes. Esto corrige [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653)#issuecomment-1763766009 . [#55683](https://github.com/ClickHouse/ClickHouse/pull/55683) ([Amos Bird](https://github.com/amosbird)).
* Se almacena en caché la función cast en Set durante la ejecución para mejorar el rendimiento de la función `IN` cuando el tipo de elemento del Set no coincide exactamente con el tipo de columna. [#55712](https://github.com/ClickHouse/ClickHouse/pull/55712) ([Duc Canh Le](https://github.com/canhld94)).
* Mejora del rendimiento de `ColumnVector::insertMany` y `ColumnVector::insertManyFrom`. [#55714](https://github.com/ClickHouse/ClickHouse/pull/55714) ([frinkr](https://github.com/frinkr)).
* ... La obtención de valores de un Map se usa ampliamente. En la práctica, las estructuras de clave suelen ser las mismas dentro de una misma columna Map, por lo que se puede intentar predecir la posición de la clave de la siguiente fila y reducir las comparaciones. [#55929](https://github.com/ClickHouse/ClickHouse/pull/55929) ([lgbo](https://github.com/lgbo-ustc)).
* ... Se corrigió un issue por el que la poda de campos de struct no funciona en algunos casos. Por ejemplo &#96;&#96;&#96;sql INSERT INTO FUNCTION file(&#39;test&#95;parquet&#95;struct&#39;, Parquet, &#39;x Tuple(a UInt32, b UInt32, c String)&#39;) SELECT tuple(number, rand(), concat(&#39;testxxxxxxx&#39; toString(number))) FROM numbers(10);. [#56117](https://github.com/ClickHouse/ClickHouse/pull/56117) ([lgbo](https://github.com/lgbo-ustc)).
