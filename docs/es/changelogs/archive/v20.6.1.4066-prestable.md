<div id="clickhouse-release-v20614066-prestable-fixme-as-compared-to-v20513833-prestable">
  ### Lanzamiento de ClickHouse v20.6.1.4066-prestable FIXME en comparación con la v20.5.1.3833-prestable
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* `clickhouse-local` ahora usa de forma predeterminada un directorio temporal de datos único, y ya no el directorio actual como antes. Si es necesario, el directorio de datos puede especificarse explícitamente con la opción `-- --path`. [#11931](https://github.com/ClickHouse/ClickHouse/pull/11931) ([Alexander Kuzmenkov](https://github.com/akuzm)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añadió soporte para `Alter table drop replica replica_name`. Esto corrige [#7080](https://github.com/ClickHouse/ClickHouse/issues/7080). [#10679](https://github.com/ClickHouse/ClickHouse/pull/10679) ([sundyli](https://github.com/sundy-li)).
* Se añadió un nuevo formato in-memory para partes en tablas de la familia `MergeTree`, que almacena los datos en memoria. Las partes se escriben en disco en la primera merge. Se creará una parte en formato in-memory si su tamaño en filas o bytes está por debajo de los umbrales `min_rows_for_compact_part` y `min_bytes_for_compact_part`. También hay soporte opcional para Write-Ahead-Log, que está habilitado de forma predeterminada y se controla mediante la configuración `in_memory_parts_enable_wal`. [#10697](https://github.com/ClickHouse/ClickHouse/pull/10697) ([Anton Popov](https://github.com/CurtizJ)).
* Se añadió el combinador -Distinct para funciones de agregación. [#10930](https://github.com/ClickHouse/ClickHouse/pull/10930) ([Sofia Antipushina](https://github.com/Sonichka1311)).
* Soporte para el table engine mongo(host:port, database, collection, user, password). [#10931](https://github.com/ClickHouse/ClickHouse/pull/10931) ([ageraab](https://github.com/ageraab)).
* Se añadió el storage RabbitMQ. [#11069](https://github.com/ClickHouse/ClickHouse/pull/11069) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Configuraciones opcionales para enviar informes de fallos al equipo principal de ClickHouse mediante [Sentry](https://sentry.io). [#11300](https://github.com/ClickHouse/ClickHouse/pull/11300) ([Ivan Blinkov](https://github.com/blinkov)).
* Se añadió ORCBlockOutputFormat. [#11662](https://github.com/ClickHouse/ClickHouse/pull/11662) ([Kruglov Pavel](https://github.com/Avogar)).
* Configuración `max_thread_pool_size` para cambiar el número máximo de hilos en el Global Thread Pool. [#11668](https://github.com/ClickHouse/ClickHouse/pull/11668) ([Bharat Nallan](https://github.com/bharatnc)).
* Implementación inicial de la consulta `EXPLAIN`. Sintaxis: `EXPLAIN SELECT ...`. Esto corrige [#1118](https://github.com/ClickHouse/ClickHouse/issues/1118). [#11873](https://github.com/ClickHouse/ClickHouse/pull/11873) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Se cambiaron a relativas las rutas en los metadatos de S3, lo que permite gestionar los blobs de S3 más fácilmente. [#11892](https://github.com/ClickHouse/ClickHouse/pull/11892) ([Vladimir Chebotarev](https://github.com/excitoon)).
* Soporte de entrada/salida para UUID de Avro. [#11954](https://github.com/ClickHouse/ClickHouse/pull/11954) ([Andrew Onyshchuk](https://github.com/oandrew)).
* Se añadió el table engine de MongoDB de solo lectura. Permite leer campos planos (tipos primitivos, no anidados). [#11983](https://github.com/ClickHouse/ClickHouse/pull/11983) ([alesapin](https://github.com/alesapin)).
* Se añadió una configuración para los campos no encontrados en el schema de Avro. [#12007](https://github.com/ClickHouse/ClickHouse/pull/12007) ([Andrew Onyshchuk](https://github.com/oandrew)).
* Se añadió la función `parseDateTimeBestEffortUS`. [#12028](https://github.com/ClickHouse/ClickHouse/pull/12028) ([flynn](https://github.com/ucasfl)).
* #4006 Soporte para ALTER TABLE ... [ADD|MODIFY] COLUMN ... FIRST. [#12073](https://github.com/ClickHouse/ClickHouse/pull/12073) ([Winter Zhang](https://github.com/zhang2014)).
* Se añadió la función initializedAggregation para inicializar una agregación a partir de un único valor. [#12109](https://github.com/ClickHouse/ClickHouse/pull/12109) ([Guillaume Tassery](https://github.com/YiuRULE)).
* Soporte para RIGHT y FULL JOIN con `set join_algorithm=partial_merge`. Solo se admite la strictness ALL (ANY, SEMI, ANTI y ASOF no son compatibles). [#12118](https://github.com/ClickHouse/ClickHouse/pull/12118) ([Artem Zuikov](https://github.com/4ertus2)).
* Implementación del operador ILIKE al estilo de PostgreSQL para [#11710](https://github.com/ClickHouse/ClickHouse/issues/11710). [#12125](https://github.com/ClickHouse/ClickHouse/pull/12125) ([Mike Kot](https://github.com/myrrc)).
* Permitir tipos Nullable como claves en tablas MergeTree. [#5319](https://github.com/ClickHouse/ClickHouse/issues/5319). [#12433](https://github.com/ClickHouse/ClickHouse/pull/12433) ([Amos Bird](https://github.com/amosbird)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se permite usar direct&#95;io y mmap&#95;io para índices secundarios si están configurados los ajustes `min_bytes_to_use_direct_io` o `min_bytes_to_use_mmap_io`. [#11955](https://github.com/ClickHouse/ClickHouse/pull/11955) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se corrige la estimación del número de marcas al leer desde MergeTree. Esto es necesario para manejar correctamente los ajustes `merge_tree_max_rows_to_use_cache`, `merge_tree_max_bytes_to_use_cache`, `merge_tree_min_rows_for_concurrent_read`, `merge_tree_min_bytes_for_concurrent_read`, `merge_tree_min_rows_for_seek`, `merge_tree_min_bytes_for_seek`. Ahora el ajuste `min_bytes_to_use_mmap_io` también se aplica a la lectura del índice y de las partes compactas en la familia de motores de tabla MergeTree. [#11970](https://github.com/ClickHouse/ClickHouse/pull/11970) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se corrige &quot;[#10574](https://github.com/ClickHouse/ClickHouse/issues/10574) Índice no utilizado para el operador IN con literales&quot;, una regresión de rendimiento introducida en torno a la versión v19.3. [#12062](https://github.com/ClickHouse/ClickHouse/pull/12062) ([nvartolomei](https://github.com/nvartolomei)).
* Se eliminan las funciones inyectivas dentro de `uniq*()` si `set optimize_injective_functions_inside_uniq=1`. [#12337](https://github.com/ClickHouse/ClickHouse/pull/12337) ([Artem Zuikov](https://github.com/4ertus2)).
* Se añade una optimización de ORDER BY que reescribe `ORDER BY x, f(x)` como `ORDER BY x` si `set optimize_redundant_functions_in_order_by = 1`. [#12404](https://github.com/ClickHouse/ClickHouse/pull/12404) ([Artem Zuikov](https://github.com/4ertus2)).
* Se reduce el uso de memoria en algunas operaciones hasta 2 veces. [#12424](https://github.com/ClickHouse/ClickHouse/pull/12424) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
