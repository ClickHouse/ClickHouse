<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se amplían los símbolos permitidos en la parte authority de la URL en *domain*RFC()/netloc(). [#46841](https://github.com/ClickHouse/ClickHouse/pull/46841) ([Azat Khuzhin](https://github.com/azat)).
* Se prohíbe crear tablas basadas en KafkaEngine con sentencias DEFAULT/EPHEMERAL/ALIAS/MATERIALIZED para columnas. [#47138](https://github.com/ClickHouse/ClickHouse/pull/47138) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Se elimina la funcionalidad de &quot;drenaje asíncrono de conexiones&quot;. También se eliminan las configuraciones y métricas relacionadas. Era una funcionalidad interna, por lo que su eliminación no debería afectar a los usuarios que nunca habían oído hablar de ella. [#47486](https://github.com/ClickHouse/ClickHouse/pull/47486) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Se añade soporte para el tipo de dato Decimal de 256 bits (más de 38 dígitos) en `arraySum`/`Min`/`Max`/`Avg`/`Product`, `arrayCumSum`/`CumSumNonNegative`, `arrayDifference`, construcción de arrays, operador IN, parámetros de consulta, `groupArrayMovingSum`, funciones estadísticas, `min`/`max`/`any`/`argMin`/`argMax`, protocolo de red de PostgreSQL, motor de tabla y función MySQL, `sumMap`, `mapAdd`, `mapSubtract`, `arrayIntersect`. También se añade soporte para enteros grandes en `arrayIntersect`. Las funciones de agregación estadísticas que implican momentos (como `corr` o varios `TTest`) usarán `Float64` como representación interna (antes de este cambio usaban `Decimal128`, pero no tenía sentido), y estas funciones pueden devolver `nan` en lugar de `inf` en caso de varianza infinita. Algunas funciones estaban permitidas para tipos de dato `Decimal256`, pero devolvían `Decimal128` en versiones anteriores; ahora esto se ha corregido. Esto cierra [#47569](https://github.com/ClickHouse/ClickHouse/issues/47569). Esto cierra [#44864](https://github.com/ClickHouse/ClickHouse/issues/44864). Esto cierra [#28335](https://github.com/ClickHouse/ClickHouse/issues/28335). [#47594](https://github.com/ClickHouse/ClickHouse/pull/47594) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se convierten backup&#95;threads/restore&#95;threads en configuraciones del servidor. [#47881](https://github.com/ClickHouse/ClickHouse/pull/47881) ([Azat Khuzhin](https://github.com/azat)).
* Se corrige la función isIPv6String, que podía producir un falso positivo en caso de dirección IPv6 incorrecta. Por ejemplo, `1234::1234:` se consideraba una dirección IPv6 válida. [#47895](https://github.com/ClickHouse/ClickHouse/pull/47895) ([Nikolay Degterinsky](https://github.com/evillique)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade un nuevo modo para dividir el trabajo entre réplicas mediante los ajustes `parallel_replicas_custom_key` y `parallel_replicas_custom_key_filter_type`. Si el clúster consta de un único segmento con varias réplicas, se seleccionarán aleatoriamente hasta `max_parallel_replicas` y se convertirán en segmentos. Para cada segmento, se añade a la consulta un filtro correspondiente en el initiator antes de enviarla al segmento. Si el clúster consta de varios segmentos, se comportará igual que `sample_key`, pero con la posibilidad de definir una clave arbitraria. [#45108](https://github.com/ClickHouse/ClickHouse/pull/45108) ([Antonio Andelic](https://github.com/antonio2368)).
* Se añadió el ajuste de consulta `partial_result_on_first_cancel`, que permite que una consulta cancelada (por ejemplo, con Ctrl-C) devuelva un resultado parcial. [#45689](https://github.com/ClickHouse/ClickHouse/pull/45689) ([Alexey Perevyshin](https://github.com/alexX512)).
* Se añadió soporte para motores de tabla arbitrarios en tablas temporales, excepto los motores Replicated y KeeperMap. Cierra parcialmente [#31497](https://github.com/ClickHouse/ClickHouse/issues/31497). [#46071](https://github.com/ClickHouse/ClickHouse/pull/46071) ([Roman Vasin](https://github.com/rvasin)).
* Se añade replicación de funciones SQL definidas por el usuario mediante ZooKeeper. [#46085](https://github.com/ClickHouse/ClickHouse/pull/46085) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Se implementa `system.server_settings` (similar a `system.settings`), que contendrá configuraciones del servidor. [#46550](https://github.com/ClickHouse/ClickHouse/pull/46550) ([pufit](https://github.com/pufit)).
* Se introduce la función `WIDTH_BUCKET`. [#42974](https://github.com/ClickHouse/ClickHouse/issues/42974). [#46790](https://github.com/ClickHouse/ClickHouse/pull/46790) ([avoiderboi](https://github.com/avoiderboi)).
* Se añaden las nuevas funciones parseDateTime/parseDateTimeInJodaSyntax según la cadena de formato especificada. parseDateTime interpreta cadenas como datetime con sintaxis MySQL, y parseDateTimeInJodaSyntax las interpreta con sintaxis Joda. [#46815](https://github.com/ClickHouse/ClickHouse/pull/46815) ([李扬](https://github.com/taiyang-li)).
* Se usa `dummy UInt8` como estructura predeterminada de la table function `null`. Cierra [#46930](https://github.com/ClickHouse/ClickHouse/issues/46930). [#47006](https://github.com/ClickHouse/ClickHouse/pull/47006) ([flynn](https://github.com/ucasfl)).
* Soporte para `Dec 15, 2021` en la función parseDateTimeBestEffort. Cierra [#46816](https://github.com/ClickHouse/ClickHouse/issues/46816). [#47071](https://github.com/ClickHouse/ClickHouse/pull/47071) ([chen](https://github.com/xiedeyantu)).
* Se añade la función ULIDStringToDateTime(). Cierra [#46945](https://github.com/ClickHouse/ClickHouse/issues/46945). [#47087](https://github.com/ClickHouse/ClickHouse/pull/47087) ([Nikolay Degterinsky](https://github.com/evillique)).
* Se añaden los ajustes `http_wait_end_of_query` y `http_response_buffer_size`, que corresponden a los parámetros de URL `wait_end_of_query` y `buffer_size` de la interfaz HTTP. [#47108](https://github.com/ClickHouse/ClickHouse/pull/47108) ([Vladimir C](https://github.com/vdimir)).
* Soporte para la consulta `UNDROP TABLE`. Cierra [#46811](https://github.com/ClickHouse/ClickHouse/issues/46811). [#47241](https://github.com/ClickHouse/ClickHouse/pull/47241) ([chen](https://github.com/xiedeyantu)).
* Se añade la tabla `system.marked_dropped_tables`, que muestra las tablas eliminadas de bases de datos `Atomic` pero que todavía no se han eliminado por completo. [#47364](https://github.com/ClickHouse/ClickHouse/pull/47364) ([chen](https://github.com/xiedeyantu)).
* Agrega `INSTR` como alias de `positionCaseInsensitive` para mejorar la compatibilidad con MySQL. Cierra [#47529](https://github.com/ClickHouse/ClickHouse/issues/47529). [#47535](https://github.com/ClickHouse/ClickHouse/pull/47535) ([flynn](https://github.com/ucasfl)).
* Se agregó la función `toDecimalString`, que permite convertir números en cadenas con precisión fija. [#47838](https://github.com/ClickHouse/ClickHouse/pull/47838) ([Andrey Zvonov](https://github.com/zvonand)).
* Se agregó el operador &quot;REGEXP&quot; (similar a operadores como &quot;LIKE&quot;, &quot;IN&quot; y &quot;MOD&quot;, entre otros) para mejorar la compatibilidad con MySQL. [#47869](https://github.com/ClickHouse/ClickHouse/pull/47869) ([Robert Schulze](https://github.com/rschu1ze)).
* Permite ejecutar el pipeline de lectura para el Diccionario DIRECT con fuente CLICKHOUSE en varios hilos. Para habilitarlo, establezca `dictionary_use_async_executor=1` en la sección `SETTINGS` de la fuente en la sentencia `CREATE DICTIONARY`. [#47986](https://github.com/ClickHouse/ClickHouse/pull/47986) ([Vladimir C](https://github.com/vdimir)).
* Agrega la configuración de MergeTree `max_number_of_mutatuins_for_replica`. Limita la cantidad de part mutations por réplica al valor especificado. Cero significa que no hay límite en la cantidad de mutations por réplica (la ejecución aún puede estar limitada por otras configuraciones). [#48047](https://github.com/ClickHouse/ClickHouse/pull/48047) ([Vladimir C](https://github.com/vdimir)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se optimizó el rendimiento de una agregación con una clave Nullable. [#45772](https://github.com/ClickHouse/ClickHouse/pull/45772) ([LiuNeng](https://github.com/liuneng1994)).
* Se implementó el uso del índice tokenbf&#95;v1 en minúsculas para hasTokenOrNull, hasTokenCaseInsensitive y hasTokenCaseInsensitiveOrNull. [#46252](https://github.com/ClickHouse/ClickHouse/pull/46252) ([ltrk2](https://github.com/ltrk2)).
* Se optimizó el StringSearcher SIMD genérico buscando primero los dos primeros caracteres. [#46289](https://github.com/ClickHouse/ClickHouse/pull/46289) ([Jiebin Sun](https://github.com/jiebinn)).
* System.detached&#95;parts podía ser muy grande. - se añadieron varias fuentes teniendo en cuenta la limitación del tamaño de bloque - en cada bloque se usa el grupo de hilos de E/S para calcular el tamaño de la parte, es decir, para realizar syscalls en paralelo. [#46624](https://github.com/ClickHouse/ClickHouse/pull/46624) ([Sema Checherinda](https://github.com/CheSema)).
* Se aumentó el valor predeterminado de `max_replicated_merges_in_queue` para las tablas ReplicatedMergeTree de 16 a 1000. Esto permite operaciones de merge en segundo plano más rápidas en clusters con un número muy elevado de réplicas, como los clusters con almacenamiento compartido en ClickHouse Cloud. [#47050](https://github.com/ClickHouse/ClickHouse/pull/47050) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Las copias de seguridad con grandes cantidades de archivos eran increíblemente lentas en versiones anteriores. [#47251](https://github.com/ClickHouse/ClickHouse/pull/47251) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se admite filter push down hacia la tabla izquierda para JOIN con StorageJoin, StorageDictionary y StorageEmbeddedRocksDB. [#47280](https://github.com/ClickHouse/ClickHouse/pull/47280) ([Maksim Kita](https://github.com/kitaisreal)).
* Las marks en memoria ahora están comprimidas y usan entre 3 y 6 veces menos memoria. [#47290](https://github.com/ClickHouse/ClickHouse/pull/47290) ([Michael Kolupaev](https://github.com/al13n321)).
* Se actualizó copier para usar group by en lugar de distinct para obtener la lista de particiones. En tablas grandes, esto redujo el tiempo de selección de más de 500 s a menos de 1 s. [#47386](https://github.com/ClickHouse/ClickHouse/pull/47386) ([Clayton McClure](https://github.com/cmcclure-twilio)).
* Aborda [https://github.com/clickhouse/clickhouse/issues/46453](https://github.com/clickhouse/clickhouse/issues/46453). Bisect marcó [https://github.com/clickhouse/clickhouse/pull/35525](https://github.com/clickhouse/clickhouse/pull/35525) como el cambio problemático. Esta PR parece revertir los cambios de esa PR. [#47544](https://github.com/ClickHouse/ClickHouse/pull/47544) ([Ongkong](https://github.com/ongkong)).
* Se corrigió la lectura excesiva en queries con `FINAL`. [#47801](https://github.com/ClickHouse/ClickHouse/pull/47801) ([Nikita Taranov](https://github.com/nickitat)).
* `max_final_threads` se establecerá en el número de núcleos al iniciar el server (con el mismo algoritmo que usamos para `max_threads`). Esto mejora la concurrencia de la ejecución de `final` en servers con una gran cantidad de CPU. [#47915](https://github.com/ClickHouse/ClickHouse/pull/47915) ([Nikita Taranov](https://github.com/nickitat)).
* Evita dividir batches en las read requests para mejorar el rendimiento. [#47978](https://github.com/ClickHouse/ClickHouse/pull/47978) ([Antonio Andelic](https://github.com/antonio2368)).
