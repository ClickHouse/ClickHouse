  ### Versión de ClickHouse v20.8.6.6-lts FIXME en comparación con v20.8.5.45-lts
</div>

<div id="bug-fix">
  #### Corrección de errores
</div>

* Retroportado en [#16494](https://github.com/ClickHouse/ClickHouse/issues/16494): Se corrige un bug en la base de datos MySQL. Cuando el servidor MySQL usado como motor de base de datos no está disponible, algunas consultas generan una Exception porque intentan obtener tablas de un servidor deshabilitado, aunque no es necesario. Por ejemplo, la consulta `SELECT ... FROM system.parts` debería funcionar solo con tablas MergeTree y no acceder en absoluto a la base de datos MySQL. [#16032](https://github.com/ClickHouse/ClickHouse/pull/16032) ([Kruglov Pavel](https://github.com/Avogar)).
* Retroportado en [#16816](https://github.com/ClickHouse/ClickHouse/issues/16816): Se corrigió el comportamiento inconsistente por el que parte de los datos devueltos podía descartarse porque no se había creado el conjunto para su filtrado. [#16308](https://github.com/ClickHouse/ClickHouse/pull/16308) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Retroportado en [#16506](https://github.com/ClickHouse/ClickHouse/issues/16506): Se corrige el procesamiento de entradas muy grandes en la cola de replicación. Pueden aparecer entradas muy grandes en consultas ALTER si la estructura de la tabla es extremadamente grande (cerca de 1 MB). Esto corrige [#16307](https://github.com/ClickHouse/ClickHouse/issues/16307). [#16332](https://github.com/ClickHouse/ClickHouse/pull/16332) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Retroportado en [#16472](https://github.com/ClickHouse/ClickHouse/issues/16472): Se corrige DROP TABLE para Distributed (condición de carrera con INSERT). [#16409](https://github.com/ClickHouse/ClickHouse/pull/16409) ([Azat Khuzhin](https://github.com/azat)).
* Retroportado en [#16573](https://github.com/ClickHouse/ClickHouse/issues/16573): Se corrige el rápido crecimiento de los metadatos al usar MySQL Master -&gt; MySQL Slave -&gt; el engine MaterializeMySQL de ClickHouse, con `slave_parallel_worker` habilitado en MySQL Slave, mediante la reducción correcta de los conjuntos GTID. Esto corrige [#15951](https://github.com/ClickHouse/ClickHouse/issues/15951). [#16504](https://github.com/ClickHouse/ClickHouse/pull/16504) ([TCeason](https://github.com/TCeason)).
* Retroportado en [#16552](https://github.com/ClickHouse/ClickHouse/issues/16552): Ahora, al analizar AVRO desde la entrada, se elimina LowCardinality del tipo. Corrige [#16188](https://github.com/ClickHouse/ClickHouse/issues/16188). [#16521](https://github.com/ClickHouse/ClickHouse/pull/16521) ([Mike Kot](https://github.com/myrrc)).
* Retroportado en [#16823](https://github.com/ClickHouse/ClickHouse/issues/16823): Se corrigió [#16081](https://github.com/ClickHouse/ClickHouse/issues/16081). [#16613](https://github.com/ClickHouse/ClickHouse/pull/16613) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Retroportado en [#16892](https://github.com/ClickHouse/ClickHouse/issues/16892): Se corrigen cierres inesperados silenciosos poco frecuentes cuando el query profiler está activado y ClickHouse está instalado en un sistema operativo con una versión de glibc que tiene (supuestamente) asynchronous unwind tables defectuosas para algunas funciones. Esto corrige [#15301](https://github.com/ClickHouse/ClickHouse/issues/15301). Esto corrige [#13098](https://github.com/ClickHouse/ClickHouse/issues/13098). [#16846](https://github.com/ClickHouse/ClickHouse/pull/16846) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
