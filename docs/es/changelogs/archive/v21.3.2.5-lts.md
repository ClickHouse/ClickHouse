<div id="clickhouse-release-v21325-lts-fixme-as-compared-to-v21215869-prestable">
  ### Versión de ClickHouse v21.3.2.5-lts FIXME en comparación con v21.2.1.5869-prestable
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Ahora, todos los nombres de funciones case-insensitive se convertirán a minúsculas durante el análisis de la consulta. Esto es necesario para el enrutamiento de consultas con proyecciones. [#20174](https://github.com/ClickHouse/ClickHouse/pull/20174) ([Amos Bird](https://github.com/amosbird)).
* Ahora ya no está permitido crear tablas MergeTree con la sintaxis antigua y table TTL, porque simplemente se ignora. El Attach de tablas antiguas sigue siendo posible. [#20282](https://github.com/ClickHouse/ClickHouse/pull/20282) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade el motor de base de datos experimental `Replicated`. Replica las consultas DDL en múltiples hosts. [#16193](https://github.com/ClickHouse/ClickHouse/pull/16193) ([Alexander Tokmakov](https://github.com/tavplubix)).
* La deduplicación de consultas distribuidas da continuidad a [#16033](https://github.com/ClickHouse/ClickHouse/issues/16033) y resuelve parcialmente la propuesta [#13574](https://github.com/ClickHouse/ClickHouse/issues/13574). [#17348](https://github.com/ClickHouse/ClickHouse/pull/17348) ([xjewer](https://github.com/xjewer)).
* Se añade la posibilidad de hacer copias de seguridad y restaurar archivos de metadatos de DiskS3. [#18377](https://github.com/ClickHouse/ClickHouse/pull/18377) ([Pavel Kovalenko](https://github.com/Jokser)).
* * Incluido en el pull request. [#18508](https://github.com/ClickHouse/ClickHouse/pull/18508) ([PHO](https://github.com/depressed-pho)).

* Las tablas con motor `MergeTree*` ahora tienen dos nuevas configuraciones a nivel de tabla para controlar la concurrencia de consultas. La configuración `max_concurrent_queries` limita el número de consultas ejecutadas de forma concurrente asociadas a esta tabla. La configuración `min_marks_to_honor_max_concurrent_queries` indica que la configuración anterior solo se aplique si la consulta lee al menos esta cantidad de marks. [#19544](https://github.com/ClickHouse/ClickHouse/pull/19544) ([Amos Bird](https://github.com/amosbird)).
* * Mencionado en [#18454](https://github.com/ClickHouse/ClickHouse/issues/18454): se añade la función `htmlOrxmlCoarseParse`; compatibilidad con el análisis de `<script></script>`; compatibilidad con el análisis de `<style></style>`; compatibilidad con el análisis de `<![CDATA[]]>`; compatibilidad con la contracción de espacios en blanco; compatibilidad con el análisis de cualquier formato `<content>`; HyperScan admite SIMD; todo se realiza en una sola pasada. [#19600](https://github.com/ClickHouse/ClickHouse/pull/19600) ([zlx19950903](https://github.com/zlx19950903)).
* Agrega el tipo de QUOTA QUERY&#95;SELECTS y QUERY&#95;INSERTS. [#19603](https://github.com/ClickHouse/ClickHouse/pull/19603) ([JackyWoo](https://github.com/JackyWoo)).
* Se añadió la opción implicit&#95;key a ExecutableDictionarySource. Corrige [#14527](https://github.com/ClickHouse/ClickHouse/issues/14527). [#19677](https://github.com/ClickHouse/ClickHouse/pull/19677) ([Maksim Kita](https://github.com/kitaisreal)).
* Se añadió compatibilidad con Server Side Encryption Customer Keys (la cabecera `x-amz-server-side-encryption-customer-(key/md5)`) en el client de S3. [#19748](https://github.com/ClickHouse/ClickHouse/pull/19748) ([Vladimir Chebotarev](https://github.com/excitoon)).

* Agrega la configuración `insert_shard_id` para admitir la inserción de datos en un segmento específico desde una tabla distribuida. [#19961](https://github.com/ClickHouse/ClickHouse/pull/19961) ([flynn](https://github.com/ucasfl)).
* Se añadió la función timezoneOffset(datetime), que devuelve el desfase con respecto a UTC en segundos. Esto cierra [#issue:19850](https://github.com/ClickHouse/ClickHouse/issues/19850). [#19962](https://github.com/ClickHouse/ClickHouse/pull/19962) ([keenwolf](https://github.com/keen-wolf)).

* ... Agrega la función de agregación `deltaSum` para sumar las diferencias entre filas consecutivas. [#20057](https://github.com/ClickHouse/ClickHouse/pull/20057) ([Russ Frank](https://github.com/rf)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se añade SELECT FINAL en paralelo para una parte con level&gt;0 cuando la configuración `do_not_merge_across_partitions_select_final` es 1. [#19375](https://github.com/ClickHouse/ClickHouse/pull/19375) ([Kruglov Pavel](https://github.com/Avogar)).
* Mejora el rendimiento de las columnas bitmap durante los joins. [#19407](https://github.com/ClickHouse/ClickHouse/pull/19407) ([templarzq](https://github.com/templarzq)).
* Reimplementa parcialmente el servidor HTTP para que haga menos copias de los datos entrantes y salientes. Esto ofrece hasta 1,5 veces más rendimiento al insertar registros largos a través de HTTP. [#19516](https://github.com/ClickHouse/ClickHouse/pull/19516) ([Ivan](https://github.com/abyss7)).
* Mejora el rendimiento de las funciones de agregación mediante un aliasing más estricto. [#19946](https://github.com/ClickHouse/ClickHouse/pull/19946) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige el caso en que el parser de DataType puede tener complejidad exponencial (detectado por el fuzzer). Esto cierra [#20096](https://github.com/ClickHouse/ClickHouse/issues/20096). [#20132](https://github.com/ClickHouse/ClickHouse/pull/20132) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añade la configuración `compress` para las tablas `Memory`. Si está habilitada, la tabla usará menos RAM. En algunas máquinas y conjuntos de datos también puede funcionar más rápido en SELECT, pero no siempre es así. Esto cierra [#20093](https://github.com/ClickHouse/ClickHouse/issues/20093). Nota: hay razones por las que las tablas Memory pueden funcionar más lento que MergeTree: (1) falta de compresión (2) tamaño estático de los bloques (3) falta de índices y prewhere... [#20168](https://github.com/ClickHouse/ClickHouse/pull/20168) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* No compacta en exceso los bloques en INSERT SELECT si se está insertando en una tabla Memory. En versiones anteriores, se creaba una representación de datos ineficiente en la tabla Memory después de INSERT SELECT. Esto cierra [#13052](https://github.com/ClickHouse/ClickHouse/issues/13052). [#20169](https://github.com/ClickHouse/ClickHouse/pull/20169) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el rendimiento de la agregación al usar varios campos de tamaño fijo (sin confirmar). [#20454](https://github.com/ClickHouse/ClickHouse/pull/20454) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelera la lectura desde tablas `Memory` en casos extremos (cuando la velocidad de lectura es del orden de 50 GB/s) mediante la simplificación del pipeline y, en consecuencia, una menor contención de bloqueos en la planificación del pipeline. [#20468](https://github.com/ClickHouse/ClickHouse/pull/20468) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el rendimiento de GROUP BY con múltiples claves de tamaño fijo. [#20472](https://github.com/ClickHouse/ClickHouse/pull/20472) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La configuración `distributed_aggregation_memory_efficient` está habilitada de forma predeterminada. Reducirá el uso de memoria y mejorará el rendimiento de las consultas distribuidas. [#20599](https://github.com/ClickHouse/ClickHouse/pull/20599) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ligera mejora del código de agregación. [#20978](https://github.com/ClickHouse/ClickHouse/pull/20978) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Vuelve a añadir especializaciones de vectorConstant para intDiv/module a fin de mejorar el rendimiento. Esto corrige [#21293](https://github.com/ClickHouse/ClickHouse/issues/21293) . La regresión se introdujo en [https://github.com/ClickHouse/ClickHouse/pull/18145](https://github.com/ClickHouse/ClickHouse/pull/18145) . [#21307](https://github.com/ClickHouse/ClickHouse/pull/21307) ([Amos Bird](https://github.com/amosbird)).

<div id="improvement">
  #### Mejora
</div>

* Se corrigió la creación de `TTL` en los casos en que su expresión es una función y coincide con la clave `ORDER BY`. Ahora se permite establecer una agregación personalizada para las columnas de la clave primaria en `TTL` con `GROUP BY`. Cambio incompatible con versiones anteriores: para las columnas de la clave primaria que no están en `GROUP BY` y no se establecen explícitamente, ahora se aplica la función `any` en lugar de `max` cuando expira el TTL. Además, si usa TTL con `WHERE` o `GROUP BY`, puede ver excepciones durante las merges al realizar una rolling update. [#15450](https://github.com/ClickHouse/ClickHouse/pull/15450) ([Anton Popov](https://github.com/CurtizJ)).
* Solicitudes hedged para consultas remotas. Cuando la opción `use_hedged_requests` está habilitada (de forma predeterminada), se permite establecer varias conexiones con distintas réplicas para una consulta. Se habilita una nueva conexión si la(s) conexión(es) existente(s) con la(s) réplica(s) no se ha(n) establecido dentro de `hedged_connection_timeout` o si no se han recibido datos dentro de `receive_data_timeout`. La consulta usa la primera conexión que envía un packet de progreso no vacío (o un packet de datos, si `allow_changing_replica_until_first_data_packet`); las demás conexiones se cancelan. Se admiten las consultas con `max_parallel_replicas > 1`. [#19291](https://github.com/ClickHouse/ClickHouse/pull/19291) ([Kruglov Pavel](https://github.com/Avogar)).
* Imprimir frames en línea para stacktraces fatales. [#19317](https://github.com/ClickHouse/ClickHouse/pull/19317) ([Ivan](https://github.com/abyss7)).
* No ignorar silenciosamente los errores de escritura. [#19451](https://github.com/ClickHouse/ClickHouse/pull/19451) ([Azat Khuzhin](https://github.com/azat)).
* Se añadió compatibilidad con `PREWHERE` cuando las tablas tienen expresiones de seguridad a nivel de fila especificadas. [#19576](https://github.com/ClickHouse/ClickHouse/pull/19576) ([Denis Glazachev](https://github.com/traceon)).
* Se añadió la interfaz IStoragePolicy. [#19608](https://github.com/ClickHouse/ClickHouse/pull/19608) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* Se añadió la posibilidad de limitar INSERT en `Distributed` en función de la cantidad de bytes pendientes para el envío asíncrono (se han añadido las configuraciones `bytes_to_delay_insert`/`max_delay_to_insert` y `bytes_to_throw_insert` para el engine `Distributed`). [#19673](https://github.com/ClickHouse/ClickHouse/pull/19673) ([Azat Khuzhin](https://github.com/azat)).
* Mover las conditions que no están relacionadas con JOIN a la cláusula WHERE. [#18720](https://github.com/ClickHouse/ClickHouse/issues/18720). [#19685](https://github.com/ClickHouse/ClickHouse/pull/19685) ([hexiaoting](https://github.com/hexiaoting)).
* Se añadió una directiva de configuración independiente para el profile de Buffer. [#19721](https://github.com/ClickHouse/ClickHouse/pull/19721) ([Azat Khuzhin](https://github.com/azat)).
* Mostrar las tablas de MaterializeMySQL en `system.parts`. [#19770](https://github.com/ClickHouse/ClickHouse/pull/19770) ([Stig Bakken](https://github.com/stigsb)).
* Inicializar MaxDDLEntryID con el último valor tras reiniciar. Antes de este PR, MaxDDLEntryID permanecía en cero hasta que se procesaba una nueva DDLTask. [#19924](https://github.com/ClickHouse/ClickHouse/pull/19924) ([Amos Bird](https://github.com/amosbird)).
* Añadir la conversión de la estructura del bloque para INSERT en tablas distribuidas si no coincide. [#19947](https://github.com/ClickHouse/ClickHouse/pull/19947) ([Azat Khuzhin](https://github.com/azat)).
* Si el usuario llama a la función `JSONExtract` con el tipo `Float32`, se permite la conversión inexacta al tipo de resultado. Por ejemplo, el número `0.1` en JSON es de doble precisión y no puede representarse en Float32, pero el usuario aun así quiere obtenerlo. Las versiones anteriores devolvían 0 para el tipo no `Nullable` y NULL para el tipo `Nullable` para indicar que la conversión era imprecisa. La lógica era 100% correcta, pero sorprendía a los usuarios y generaba preguntas. Esto cierra [#13962](https://github.com/ClickHouse/ClickHouse/issues/13962). [#19960](https://github.com/ClickHouse/ClickHouse/pull/19960) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
