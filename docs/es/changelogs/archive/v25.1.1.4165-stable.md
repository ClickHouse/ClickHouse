<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* El output format Parquet convierte las columnas Date y DateTime en tipos de fecha/hora compatibles con Parquet, en lugar de escribirlas como números sin procesar. DateTime pasa a ser DateTime64(3) (antes: UInt32); la configuración `output_format_parquet_datetime_as_uint32` recupera el comportamiento anterior. Date pasa a ser Date32 (antes: UInt16). [#70950](https://github.com/ClickHouse/ClickHouse/pull/70950) ([Michael Kolupaev](https://github.com/al13n321)).
* Ya no se permiten de forma predeterminada tipos no comparables (como JSON/Object/AggregateFunction) en ORDER BY ni en funciones de comparación como `less/greater/equal/etc`. [#73276](https://github.com/ClickHouse/ClickHouse/pull/73276) ([Pavel Kruglov](https://github.com/Avogar)).
* `JSONEachRowWithProgress` escribirá el progreso cada vez que se produzca. En versiones anteriores, el progreso solo se mostraba después de cada block del resultado, lo que lo hacía inútil. También cambia la forma de mostrar el progreso: no se mostrarán valores cero. Ten en cuenta que el progreso se envía incluso si se produce con frecuencia. Esto puede generar un volumen considerable de tráfico. Ten en cuenta también que el progreso no se vuelca cuando la salida está comprimida. Esto cierra [#70800](https://github.com/ClickHouse/ClickHouse/issues/70800). [#73834](https://github.com/ClickHouse/ClickHouse/pull/73834) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* El database engine `MaterializedMySQL`, ya obsoleto, se ha eliminado y ya no está disponible. [#73879](https://github.com/ClickHouse/ClickHouse/pull/73879) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* El Diccionario source `mysql` ya no ejecuta la consulta `SHOW TABLE STATUS`, porque no aporta ningún valor para las tablas InnoDB ni para ninguna versión reciente de MySQL. Esto cierra [#72636](https://github.com/ClickHouse/ClickHouse/issues/72636). Este cambio es compatible con versiones anteriores, pero se incluye en esta categoría para que tengas ocasión de advertirlo. [#73914](https://github.com/ClickHouse/ClickHouse/pull/73914) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Las tablas `Merge` unificarán la estructura de las underlying tables mediante una union de sus columnas y la deducción de types comunes. Esto cierra [#64864](https://github.com/ClickHouse/ClickHouse/issues/64864). En algunos casos, este cambio podría no ser compatible con versiones anteriores. Un ejemplo es cuando no existe un type común entre tablas, pero la conversión al type de la primera tabla sigue siendo posible, como en el caso de UInt64 e Int64 o de cualquier type numérico y String. Si quieres volver al comportamiento anterior, establece `merge_table_max_tables_to_look_for_schema_inference` en `1` o configura `compatibility` en `24.12` o una versión anterior. [#73956](https://github.com/ClickHouse/ClickHouse/pull/73956) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Las consultas `CHECK TABLE` ahora requieren un grant `CHECK` independiente. En versiones anteriores, bastaba con tener el grant `SHOW TABLES` para ejecutar estas consultas. Pero una consulta `CHECK TABLE` puede ser costosa, y los límites habituales de query complexity para las consultas `SELECT` no se le aplican. Esto podía dar lugar a un posible DoS. [#74471](https://github.com/ClickHouse/ClickHouse/pull/74471) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La función `h3ToGeo()` ahora devuelve los resultados en el orden `(lat, lon)` (que es el orden estándar de las funciones geométricas). Los usuarios que deseen conservar el orden de resultado legacy `(lon, lat)` pueden establecer la configuración `h3togeo_lon_lat_result_order = true`. [#74719](https://github.com/ClickHouse/ClickHouse/pull/74719) ([Manish Gill](https://github.com/mgill25)).



<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se ha añadido la interfaz SSH. Ahora es posible conectarse al ClickHouse server usando cualquier client SSH y ejecutar queries de forma interactiva mediante PTY con `clickhouse-client` integrado. [#48902](https://github.com/ClickHouse/ClickHouse/pull/48902) ([George Gamezardashvili](https://github.com/InfJoker)).
* Se añadió una caché en memoria para los gránulos deserializados de índices de omisión. Esto debería acelerar las queries repetidas que usan índices de omisión. El tamaño de la nueva caché se controla mediante las server settings `skipping_index_cache_size` y `skipping_index_cache_max_entries`. La motivación original de esta caché fueron los vector similarity indexes, que ahora son mucho más rápidos. [#70102](https://github.com/ClickHouse/ClickHouse/pull/70102) ([Robert Schulze](https://github.com/rschu1ze)).
* Se implementó la poda de particiones para tablas Iceberg en operaciones de particionado con transformaciones relacionadas con el tiempo en Iceberg. [#72044](https://github.com/ClickHouse/ClickHouse/pull/72044) ([Daniil Ivanik](https://github.com/divanik)).
* Se añadió la capacidad de crear índices min-max (de omisión) de forma predeterminada para las columnas gestionadas por MergeTree usando los settings `enable_minmax_index_for_all_numeric_columns` (para columnas numéricas) y `enable_minmax_index_for_all_string_columns` (para columnas String). Por ahora, ambos settings están deshabilitados, por lo que todavía no hay cambios de comportamiento. [#72090](https://github.com/ClickHouse/ClickHouse/pull/72090) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Se añadió la función de aggregation `sequenceMatchEvents`, que devuelve timestamps de los eventos coincidentes para la cadena de eventos más larga del patrón. [#72349](https://github.com/ClickHouse/ClickHouse/pull/72349) ([UnamedRus](https://github.com/UnamedRus)).
* Las sentencias `SELECT` y `VIEW` ahora admiten aliases, por ejemplo, `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);`. Esto permite ejecutar la query 15 de TPC-H sin modificaciones. [#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se añadió la función `arrayNormalizedGini`. [#72823](https://github.com/ClickHouse/ClickHouse/pull/72823) ([flynn](https://github.com/ucasfl)).
* Cuando `min_age_to_force_merge_seconds` y `min_age_to_force_merge_on_partition_only` están ambos habilitados, la fusión de partes ignorará el límite máximo de bytes. [#73656](https://github.com/ClickHouse/ClickHouse/pull/73656) ([Kai Zhu](https://github.com/nauu)).
* Se admite la lectura de valores HALF&#95;FLOAT desde Apache Arrow/Parquet/ORC (se leen como Float32). Esto cierra la issue [#72960](https://github.com/ClickHouse/ClickHouse/issues/72960). Tenga en cuenta que IEEE-754 half float no es lo mismo que BFloat16. Cierra la issue [#73835](https://github.com/ClickHouse/ClickHouse/issues/73835). [#73836](https://github.com/ClickHouse/ClickHouse/pull/73836) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La tabla `system.trace_log` contendrá dos nuevas columnas, `symbols` y `lines`, que contienen una stack trace simbolizada. Esto permite recopilar y exportar fácilmente información de perfil. Esto se controla mediante el valor de server configuration `symbolize` dentro de `trace_log` y está habilitado de forma predeterminada. [#73896](https://github.com/ClickHouse/ClickHouse/pull/73896) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió una nueva función, `generateSerialID`, que puede usarse para generar números autoincrementales en tablas. Continuación de [#64310](https://github.com/ClickHouse/ClickHouse/issues/64310) por [kazalika](https://github.com/kazalika). Esto cierra la issue [#62485](https://github.com/ClickHouse/ClickHouse/issues/62485). [#73950](https://github.com/ClickHouse/ClickHouse/pull/73950) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añadir la sintaxis `query1 PARALLEL WITH query2 PARALLEL WITH query3 ... PARALLEL WITH queryN`. Esto significa que las subconsultas `{query1, query2, ... queryN}` pueden ejecutarse en paralelo entre sí (y es lo preferible). [#73983](https://github.com/ClickHouse/ClickHouse/pull/73983) ([Vitaly Baranov](https://github.com/vitlibar)).
* Ahora, la interfaz Play tiene una barra de progreso durante la ejecución de la consulta. Permite cancelar consultas. Muestra el número total de registros e información ampliada sobre la velocidad. La tabla puede renderizarse de forma incremental en cuanto llegan los datos. Habilita la compresión HTTP. El renderizado de la tabla ahora es más rápido. La cabecera de la tabla ahora es sticky. Permite seleccionar celdas y navegar entre ellas con las teclas de dirección. Corrige el issue por el que el contorno de la celda seleccionada la hacía más pequeña. Las celdas ya no se expanden al pasar el ratón por encima, sino solo al seleccionarlas. El momento de detener el renderizado de los datos entrantes se decide en el client en lugar de en el servidor. Resalta grupos de dígitos en los números. El diseño general se renovó y ahora es más marcado. Comprueba si el servidor es accesible y si las credenciales son correctas, y muestra la versión del servidor y su uptime. El icono de Cloud tiene contorno en todas las fuentes, incluso en Safari. Los enteros grandes dentro de tipos de datos anidados se renderizarán mejor. Mostrará correctamente inf/nan. Mostrará los tipos de datos al pasar el ratón sobre la cabecera de una columna. [#74204](https://github.com/ClickHouse/ClickHouse/pull/74204) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añadir la capacidad de crear índices min-max (skipping) de forma predeterminada para las columnas gestionadas por MergeTree mediante las opciones de configuración `add_minmax_index_for_numeric_columns` (para columnas numéricas) y `add_minmax_index_for_string_columns` (para columnas String). Por ahora, ambas opciones de configuración están deshabilitadas, así que todavía no hay cambios de comportamiento. [#74266](https://github.com/ClickHouse/ClickHouse/pull/74266) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Añadir los field `script_query_number` y `script_line_number` a `system.query_log`, a ClientInfo en el protocolo nativo y a los logs del servidor. Esto cierra [#67542](https://github.com/ClickHouse/ClickHouse/issues/67542). Créditos a [pinsvin00](https://github.com/pinsvin00) por haber impulsado antes esta feature en [#68133](https://github.com/ClickHouse/ClickHouse/issues/68133). [#74477](https://github.com/ClickHouse/ClickHouse/pull/74477) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añadir compatibilidad con el operador menos para DateTime64, para permitir la resta entre valores DateTime64, así como con DateTime. [#74482](https://github.com/ClickHouse/ClickHouse/pull/74482) ([Li Yin](https://github.com/liyinsg)).
* Retroportado en [#75020](https://github.com/ClickHouse/ClickHouse/issues/75020): Se añadió la capacidad de aplicar mutaciones no finalizadas (no materializadas por un proceso en segundo plano) durante la ejecución de consultas `SELECT` inmediatamente después de enviarlas. Puede habilitarse con la opción de configuración `apply_mutations_on_fly`. [#74877](https://github.com/ClickHouse/ClickHouse/pull/74877) ([Anton Popov](https://github.com/CurtizJ)).





<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Empezar a comparar las filas por las columnas con más probabilidades de ser distintas. [#63780](https://github.com/ClickHouse/ClickHouse/pull/63780) ([UnamedRus](https://github.com/UnamedRus)).
* Optimizar el formato de entrada RowBinary. Cierra [#63805](https://github.com/ClickHouse/ClickHouse/issues/63805). [#65059](https://github.com/ClickHouse/ClickHouse/pull/65059) ([Pavel Kruglov](https://github.com/Avogar)).
* Acelerar la deserialización de cadenas mediante una optimización de bajo nivel. [#65948](https://github.com/ClickHouse/ClickHouse/pull/65948) ([Nikita Taranov](https://github.com/nickitat)).
* Mejorar el rendimiento de grace hash join reordenando por claves la tabla derecha del join. [#72237](https://github.com/ClickHouse/ClickHouse/pull/72237) ([kevinyhzou](https://github.com/KevinyhZou)).
* Permitir que `arrayROCAUC` y `arrayAUCPR` calculen un área parcial de la curva completa, de modo que su cálculo pueda paralelizarse en conjuntos de datos enormes. [#72904](https://github.com/ClickHouse/ClickHouse/pull/72904) ([Emmanuel](https://github.com/emmanuelsdias)).
* Evitar crear demasiados hilos inactivos. [#72920](https://github.com/ClickHouse/ClickHouse/pull/72920) ([Guo Wangyang](https://github.com/guowangy)).
* Se eliminó la división por hash de los bloques de la tabla izquierda de la fase de sondeo del algoritmo JOIN `parallel_hash`. [#73089](https://github.com/ClickHouse/ClickHouse/pull/73089) ([Nikita Taranov](https://github.com/nickitat)).
* No listar claves de almacenamiento de blobs si en la función de tabla solo hay expansión con llaves. Cierra [#73333](https://github.com/ClickHouse/ClickHouse/issues/73333). [#73518](https://github.com/ClickHouse/ClickHouse/pull/73518) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Revertir &quot;Revert &quot;Optimización de cortocircuito para funciones ejecutadas sobre argumentos Nullable&quot;&quot;. Añadir una ruta rápida para funciones cuyos tipos de argumentos sean todos numéricos. Corregir problemas de rendimiento en https://github.com/ClickHouse/ClickHouse/pull/72258. [#73820](https://github.com/ClickHouse/ClickHouse/pull/73820) ([李扬](https://github.com/taiyang-li)).
* No aplicar `maskedExecute` a columnas que no son funciones; mejorar el rendimiento de la ejecución de cortocircuito. [#73965](https://github.com/ClickHouse/ClickHouse/pull/73965) ([lgbo](https://github.com/lgbo-ustc)).
* Deshabilitar la detección de encabezados para Kafka/NATS/RabbitMQ/FileLog para mejorar el rendimiento. [#74006](https://github.com/ClickHouse/ClickHouse/pull/74006) ([Azat Khuzhin](https://github.com/azat)).
* Usar los envoltorios de log por valor y no asignarlos en el heap. [#74034](https://github.com/ClickHouse/ClickHouse/pull/74034) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Ejecutar el pipeline con un mayor grado de paralelismo tras la agregación con grouping sets. [#74082](https://github.com/ClickHouse/ClickHouse/pull/74082) ([Nikita Taranov](https://github.com/nickitat)).
* Reducir la sección crítica en `MergeTreeReadPool`. [#74202](https://github.com/ClickHouse/ClickHouse/pull/74202) ([Guo Wangyang](https://github.com/guowangy)).
* Se optimizó la función `indexHint`. Ahora, las columnas que solo se usan como argumentos de la función `indexHint` no se leen de la tabla. [#74314](https://github.com/ClickHouse/ClickHouse/pull/74314) ([Anton Popov](https://github.com/CurtizJ)).
* Mejora del rendimiento de las réplicas paralelas. La deserialización de paquetes en el iniciador de la consulta, para los paquetes no relacionados con el protocolo de réplicas paralelas, ahora siempre se realiza en el hilo del pipeline. Antes, podía producirse en un hilo responsable de la planificación del pipeline, lo que podía hacer que el iniciador fuera menos reactivo y retrasar la ejecución del pipeline. [#74398](https://github.com/ClickHouse/ClickHouse/pull/74398) ([Igor Nikonov](https://github.com/devcrafter)).
* Retroportado en [#75069](https://github.com/ClickHouse/ClickHouse/issues/75069): se corrigió el cálculo del tamaño en memoria de las columnas `LowCardinality`. [#74688](https://github.com/ClickHouse/ClickHouse/pull/74688) ([Nikita Taranov](https://github.com/nickitat)).
