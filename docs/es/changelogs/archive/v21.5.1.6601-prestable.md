<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se modifica la comparación entre enteros y números de coma flotante cuando el entero no puede representarse exactamente en el tipo de dato de coma flotante. En la nueva versión, la comparación devolverá false, ya que se producirá un error de redondeo. Ejemplo: `9223372036854775808.0 != 9223372036854775808`, porque el número `9223372036854775808` no puede representarse exactamente como número de coma flotante (y `9223372036854775808.0` se redondea a `9223372036854776000.0`). Sin embargo, en la versión anterior la comparación devolvía que los números eran iguales, porque si el número de coma flotante `9223372036854776000.0` se convertía de nuevo a UInt64, el resultado era `9223372036854775808`. Como referencia, el lenguaje de programación Python también trata estos números como iguales. Pero este comportamiento dependía del modelo de CPU (con resultados distintos en AMD64 y AArch64 para algunos números fuera de rango), por lo que hacemos la comparación más precisa. Solo tratará los números int y float como iguales si el int está representado exactamente en el tipo de coma flotante. [#22595](https://github.com/ClickHouse/ClickHouse/pull/22595) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
