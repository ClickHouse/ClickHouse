  ### Versión de ClickHouse v24.4.1.2088-stable (6d4b31322d1) FIXME en comparación con v24.3.1.2672-lts (2c5c589a882)
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Ya no se permite establecer max&#95;parallel&#95;replicas en 0, ya que no tiene sentido. Establecerlo en 0 podía provocar errores lógicos inesperados. Cierra [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140). [#61201](https://github.com/ClickHouse/ClickHouse/pull/61201) ([Kruglov Pavel](https://github.com/Avogar)).
* `clickhouse-odbc-bridge` y `clickhouse-library-bridge` son paquetes independientes. Con esto se cierra [#61677](https://github.com/ClickHouse/ClickHouse/issues/61677). [#62114](https://github.com/ClickHouse/ClickHouse/pull/62114) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se elimina la compatibilidad con la consulta INSERT WATCH (parte de la funcionalidad experimental LIVE VIEW). [#62382](https://github.com/ClickHouse/ClickHouse/pull/62382) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se elimina la configuración optimize&#95;monotonous&#95;functions&#95;in&#95;order&#95;by. [#63004](https://github.com/ClickHouse/ClickHouse/pull/63004) ([Raúl Marín](https://github.com/Algunenano)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Permite eliminar varias tablas al mismo tiempo, como `drop table a,b,c`;. [#58705](https://github.com/ClickHouse/ClickHouse/pull/58705) ([zhongyuankai](https://github.com/zhongyuankai)).
* Ahora se pueden conceder permisos sobre el motor de tabla, sin afectar el comportamiento de los usuarios existentes. [#60117](https://github.com/ClickHouse/ClickHouse/pull/60117) ([jsc0218](https://github.com/jsc0218)).
* Se añadió un disco S3 reescribible que admite operaciones `INSERT` y no requiere metadatos almacenados localmente. [#61116](https://github.com/ClickHouse/ClickHouse/pull/61116) ([Julia Kartseva](https://github.com/jkartseva)).
* Por comodidad, `SELECT * FROM numbers() `funcionará de la misma manera que `SELECT * FROM system.numbers`: sin límite. [#61969](https://github.com/ClickHouse/ClickHouse/pull/61969) ([YenchangChan](https://github.com/YenchangChan)).
* Ahora se admite modificar la configuración de la tabla memory mediante `ALTER MODIFY SETTING`. `ALTER TABLE memory MODIFY SETTING min_rows_to_keep = 100, max_rows_to_keep = 1000;`. [#62039](https://github.com/ClickHouse/ClickHouse/pull/62039) ([zhongyuankai](https://github.com/zhongyuankai)).
* El analizador admite CTE recursivas. [#62074](https://github.com/ClickHouse/ClickHouse/pull/62074) ([Maksim Kita](https://github.com/kitaisreal)).
* El analizador admite la cláusula QUALIFY. Cierra [#47819](https://github.com/ClickHouse/ClickHouse/issues/47819). [#62619](https://github.com/ClickHouse/ClickHouse/pull/62619) ([Maksim Kita](https://github.com/kitaisreal)).
* Se añadió el parámetro de consulta `role` a la interfaz HTTP. Funciona de forma similar a `SET ROLE x`, aplicando el rol antes de que se ejecute la sentencia. Esto permite superar la limitación de la interfaz HTTP, ya que no se permiten múltiples sentencias y no es posible enviar `SET ROLE x` y la propia sentencia al mismo tiempo. Es posible establecer varios roles de esta forma; por ejemplo, `?role=x&role=y`, que será equivalente a `SET ROLE x, y`. [#62669](https://github.com/ClickHouse/ClickHouse/pull/62669) ([Serge Klochkov](https://github.com/slvrtrn)).
* Se añadió `SYSTEM UNLOAD PRIMARY KEY`. [#62738](https://github.com/ClickHouse/ClickHouse/pull/62738) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Reduce la sobrecarga de las mutations para los SELECT (v2). [#60856](https://github.com/ClickHouse/ClickHouse/pull/60856) ([Azat Khuzhin](https://github.com/azat)).
* Las funciones invocadas con más frecuencia en PODArray ahora se inlinean de forma forzada. [#61144](https://github.com/ClickHouse/ClickHouse/pull/61144) ([李扬](https://github.com/taiyang-li)).
* Mejoras en el push down de filtros de JOIN mediante conjuntos equivalentes. [#61216](https://github.com/ClickHouse/ClickHouse/pull/61216) ([Maksim Kita](https://github.com/kitaisreal)).
* Se habilitó de forma predeterminada el codificador rápido de Parquet (output&#95;format&#95;parquet&#95;use&#95;custom&#95;encoder). [#62088](https://github.com/ClickHouse/ClickHouse/pull/62088) ([Michael Kolupaev](https://github.com/al13n321)).
* ... Cuando ya se han leído todos los campos necesarios, se omiten directamente todos los campos restantes, lo que puede ahorrar muchas comparaciones. [#62210](https://github.com/ClickHouse/ClickHouse/pull/62210) ([lgbo](https://github.com/lgbo-ustc)).
* Las funciones `splitByChar` y `splitByRegexp` se aceleraron significativamente. [#62392](https://github.com/ClickHouse/ClickHouse/pull/62392) ([李扬](https://github.com/taiyang-li)).
* Mejora el caso trivial de insert-select desde archivos en las table functions file/s3/hdfs/url/.... Añade una configuración independiente, `max_parsing_threads`, para controlar la cantidad de threads usados en paralelo para el parsing. [#62404](https://github.com/ClickHouse/ClickHouse/pull/62404) ([Kruglov Pavel](https://github.com/Avogar)).
* Añade compatibilidad con un búfer de escritura en paralelo para AzureBlobStorage, gestionado mediante la configuración `azure_allow_parallel_part_upload`. [#62534](https://github.com/ClickHouse/ClickHouse/pull/62534) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Las funciones `to_utc_timestamp` y `from_utc_timestamp` ahora son aproximadamente el doble de rápidas. [#62583](https://github.com/ClickHouse/ClickHouse/pull/62583) ([KevinyhZou](https://github.com/KevinyhZou)).
* Las funciones `parseDateTimeOrNull`, `parseDateTimeOrZero`, `parseDateTimeInJodaSyntaxOrNull` y `parseDateTimeInJodaSyntaxOrZero` ahora se ejecutan mucho más rápido (10x - 1000x) cuando la entrada contiene mayoritariamente valores que no se pueden parsear. [#62634](https://github.com/ClickHouse/ClickHouse/pull/62634) ([LiuNeng](https://github.com/liuneng1994)).
* Los SELECT sobre `system.query_cache` ahora son notablemente más rápidos cuando la query cache contiene muchas entries (p. ej., más de 100.000). [#62671](https://github.com/ClickHouse/ClickHouse/pull/62671) ([Robert Schulze](https://github.com/rschu1ze)).
* Optimización de QueryPlan para convertir OUTER JOIN en INNER JOIN si el filtro posterior al JOIN siempre filtra valores predeterminados. La optimización puede controlarse con la configuración `query_plan_convert_outer_join_to_inner_join`, habilitada de forma predeterminada. [#62907](https://github.com/ClickHouse/ClickHouse/pull/62907) ([Maksim Kita](https://github.com/kitaisreal)).
* Se habilita `optimize_rewrite_sum_if_to_count_if` de forma predeterminada. [#62929](https://github.com/ClickHouse/ClickHouse/pull/62929) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### Mejora
</div>

* Se introducen etiquetas separadas de consumer/producer para la configuración de Kafka. Esto evita advertencias de librdkafka indicando que se especificaron propiedades de consumer para instancias de producer y viceversa (p. ej., `Configuration property session.timeout.ms is a consumer property and will be ignored by this producer instance`). Cierra: [#58983](https://github.com/ClickHouse/ClickHouse/issues/58983). [#58956](https://github.com/ClickHouse/ClickHouse/pull/58956) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Se agregaron las columnas `value1`, `value2`, ..., `value10` a `system.text_log`. Estas columnas contienen los valores usados para dar formato al mensaje. [#59619](https://github.com/ClickHouse/ClickHouse/pull/59619) ([Alexey Katsman](https://github.com/alexkats)).
* Se agrega la configuración `first_day_of_week`, que afecta al primer día de la semana considerado por las funciones `toStartOfInterval(..., INTERVAL ... WEEK)`. Esto permite mantener la coherencia con la función `toStartOfWeek`, cuyo valor predeterminado es el domingo como primer día de la semana. [#60598](https://github.com/ClickHouse/ClickHouse/pull/60598) ([Jordi Villar](https://github.com/jrdi)).
* Se agregó la columna virtual persistente `_block_offset`, que almacena el número original de la fila dentro del block asignado al insertar. La persistencia de la columna `_block_offset` puede habilitarse con la configuración `enable_block_offset_column`. Se agregó la columna virtual `_part_data_version`, que contiene el número mínimo de block o la versión de mutation de la parte. La columna virtual persistente `_block_number` ya no se considera experimental. [#60676](https://github.com/ClickHouse/ClickHouse/pull/60676) ([Anton Popov](https://github.com/CurtizJ)).
* Menor contención en filesystem cache (parte 3): ejecutar la eliminación del filesystem sin lock al intentar reservar espacio. [#61163](https://github.com/ClickHouse/ClickHouse/pull/61163) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Las funciones `date_diff` y `age` ahora calculan su resultado con precisión de nanosegundos en lugar de microsegundos. Además, ahora admiten `nanosecond` (o `nanoseconds` o `ns`) como posible valor para el parámetro `unit`. [#61409](https://github.com/ClickHouse/ClickHouse/pull/61409) ([Austin Kothig](https://github.com/kothiga)).
* Ahora no se cargan los marks de las wide parts durante los merges. [#61551](https://github.com/ClickHouse/ClickHouse/pull/61551) ([Anton Popov](https://github.com/CurtizJ)).
* Recarga la cadena de certificados durante la recarga del certificado. [#61671](https://github.com/ClickHouse/ClickHouse/pull/61671) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Se acelera el cambio dinámico de tamaño de filesystem cache. [#61723](https://github.com/ClickHouse/ClickHouse/pull/61723) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se agrega `TRUNCATE ALL TABLES`. [#61862](https://github.com/ClickHouse/ClickHouse/pull/61862) ([豪肥肥](https://github.com/HowePa)).
* Se intenta evitar [#60432](https://github.com/ClickHouse/ClickHouse/issues/60432) impidiendo adjuntar una tabla si ya existe una réplica activa para esa ruta de réplica. [#61876](https://github.com/ClickHouse/ClickHouse/pull/61876) ([Arthur Passos](https://github.com/arthurpassos)).
* Se agrega la configuración `input_format_json_throw_on_bad_escape_sequence`; deshabilitarla permite guardar secuencias de escape no válidas en los formatos de entrada JSON. [#61889](https://github.com/ClickHouse/ClickHouse/pull/61889) ([Kruglov Pavel](https://github.com/Avogar)).
* Userspace page cache ahora funciona con almacenamiento web estático (`disk(type = web)`). Use la configuración de cliente `use_page_cache_for_disks_without_file_cache=1` para habilitarla. [#61911](https://github.com/ClickHouse/ClickHouse/pull/61911) ([Michael Kolupaev](https://github.com/al13n321)).
* Se implementa input() para clickhouse-local. [#61923](https://github.com/ClickHouse/ClickHouse/pull/61923) ([Azat Khuzhin](https://github.com/azat)).
* Se corrigió un error lógico al deshacer una transacción de inserción con quorum. [#61953](https://github.com/ClickHouse/ClickHouse/pull/61953) ([Han Fei](https://github.com/hanfei1991)).
* StorageJoin con strictness `ANY` mantiene la consistencia después de recargarse. Cuando se insertan varias filas con la misma clave, la primera tendrá mayor prioridad (antes, se elegía aleatoriamente durante la carga de la tabla). cierra [#51027](https://github.com/ClickHouse/ClickHouse/issues/51027). [#61972](https://github.com/ClickHouse/ClickHouse/pull/61972) ([vdimir](https://github.com/vdimir)).
* Inferir automáticamente tipos de columna Nullable a partir del esquema de Apache Arrow. [#61984](https://github.com/ClickHouse/ClickHouse/pull/61984) ([Maksim Kita](https://github.com/kitaisreal)).
* Permitir cancelar la fusión paralela de estados de agregación durante la agregación. Ejemplo: `uniqExact`. [#61992](https://github.com/ClickHouse/ClickHouse/pull/61992) ([Maksim Kita](https://github.com/kitaisreal)).
* No tratar las variantes Bool y numéricas como sospechosas en el tipo Variant. [#61999](https://github.com/ClickHouse/ClickHouse/pull/61999) ([Kruglov Pavel](https://github.com/Avogar)).
* Usar `system.keywords` para rellenar las sugerencias y usarlas también internamente en todas partes. [#62000](https://github.com/ClickHouse/ClickHouse/pull/62000) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Implementar una mejor conversión de String a Variant mediante análisis sintáctico. [#62005](https://github.com/ClickHouse/ClickHouse/pull/62005) ([Kruglov Pavel](https://github.com/Avogar)).
* Añadir compatibilidad con Variant en las funciones JSONExtract. [#62014](https://github.com/ClickHouse/ClickHouse/pull/62014) ([Kruglov Pavel](https://github.com/Avogar)).
* El dictionary source con `INVALIDATE_QUERY` no se recarga dos veces al iniciar. [#62050](https://github.com/ClickHouse/ClickHouse/pull/62050) ([vdimir](https://github.com/vdimir)).
* `OPTIMIZE FINAL` para `ReplicatedMergeTree` ahora esperará a que finalicen las fusiones activas en ese momento y luego volverá a intentar programar una fusión final. Esto lo alinea más con el comportamiento habitual de `MergeTree`. [#62067](https://github.com/ClickHouse/ClickHouse/pull/62067) ([Nikita Taranov](https://github.com/nickitat)).
* Al leer datos de un archivo de texto de Hive, se usaba la primera línea del archivo para reajustar el número de campos de entrada, y a veces el número de campos de la primera línea no coincide con el definido en la tabla de Hive; por ejemplo, la tabla de Hive está definida con 3 columnas, como `test_tbl(a Int32, b Int32, c Int32)`, pero la primera línea del archivo de texto solo tiene 2 campos, y en esa situación los campos de entrada se reajustan a 2; si la siguiente línea del archivo de texto tiene 3 campos, el tercero no puede leerse y en su lugar se establece el valor predeterminado 0, lo cual no es correcto. [#62086](https://github.com/ClickHouse/ClickHouse/pull/62086) ([KevinyhZou](https://github.com/KevinyhZou)).
* CREATE AS copia el comment. [#62117](https://github.com/ClickHouse/ClickHouse/pull/62117) ([Pablo Marcos](https://github.com/pamarcos)).
* El resaltado de sintaxis mientras se escribe en el client funcionará a nivel de sintaxis (anteriormente funcionaba a nivel de lexer). [#62123](https://github.com/ClickHouse/ClickHouse/pull/62123) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se corrigió un issue por el que, cuando se añade un `= 1` o `= 0` redundante después de una expresión booleana que involucra la clave primaria, no se usa el índice primario. Por ejemplo, tanto `SELECT * FROM <table> WHERE <primary-key> IN (<value>) = 1` como `SELECT * FROM <table> WHERE <primary-key> NOT IN (<value>) = 0` realizarán un escaneo completo de la tabla, aunque se puede usar el índice primario. [#62142](https://github.com/ClickHouse/ClickHouse/pull/62142) ([josh-hildred](https://github.com/josh-hildred)).
* Añadir el progreso de la consulta a la tabla zookeeper. [#62152](https://github.com/ClickHouse/ClickHouse/pull/62152) ([JackyWoo](https://github.com/JackyWoo)).
* Añadir la posibilidad de activar el collector de trazas (real y CPU) en todo el server. [#62189](https://github.com/ClickHouse/ClickHouse/pull/62189) ([alesapin](https://github.com/alesapin)).
* Se añadió el ajuste `lightweight_deletes_sync` (valor predeterminado: 2; espera todas las réplicas de forma síncrona). Es similar al ajuste `mutations_sync`, pero solo afecta al comportamiento de las eliminaciones ligeras. [#62195](https://github.com/ClickHouse/ClickHouse/pull/62195) ([Anton Popov](https://github.com/CurtizJ)).
* Distinguir entre valores booleanos y enteros al analizar values para ajustes personalizados: `SET custom_a = true; SET custom_b = 1;`. [#62206](https://github.com/ClickHouse/ClickHouse/pull/62206) ([Vitaly Baranov](https://github.com/vitlibar)).
* Compatibilidad con acceso a S3 a través de endpoints de interfaz de AWS Private Link. Cierra [#60021](https://github.com/ClickHouse/ClickHouse/issues/60021), [#31074](https://github.com/ClickHouse/ClickHouse/issues/31074) y [#53761](https://github.com/ClickHouse/ClickHouse/issues/53761). [#62208](https://github.com/ClickHouse/ClickHouse/pull/62208) ([Arthur Passos](https://github.com/arthurpassos)).
* El client debe enviar el header &#39;Keep-Alive: timeout=X&#39; al server. Si un client recibe una respuesta del server con ese header, debe usar el valor proporcionado por el server. Además, es mejor que un client no use una connection que esté a punto de expirar para evitar una condición de carrera al connection close. [#62249](https://github.com/ClickHouse/ClickHouse/pull/62249) ([Sema Checherinda](https://github.com/CheSema)).
* Se añadieron las unidades de nano-, micro- y milisegundos para date&#95;trunc. [#62335](https://github.com/ClickHouse/ClickHouse/pull/62335) ([Misz606](https://github.com/Misz606)).
* No crear un directory para UDF en clickhouse-client si no existe. Esto cierra [#59597](https://github.com/ClickHouse/ClickHouse/issues/59597). [#62366](https://github.com/ClickHouse/ClickHouse/pull/62366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La query cache ya no almacena en caché los resultados de consultas sobre tablas del sistema (`system.*`, `information_schema.*`, `INFORMATION_SCHEMA.*`). [#62376](https://github.com/ClickHouse/ClickHouse/pull/62376) ([Robert Schulze](https://github.com/rschu1ze)).
* La consulta `MOVE PARTITION TO TABLE` puede retrasarse o lanzar la excepción `TOO_MANY_PARTS` para evitar superar los límites del recuento de partes. Se aplican los mismos ajustes y límites que para la consulta `INSERT` (consulte los ajustes `max_parts_in_total`, `parts_to_delay_insert`, `parts_to_throw_insert`, `inactive_parts_to_throw_insert`, `inactive_parts_to_delay_insert`, `max_avg_part_size_for_too_many_parts`, `min_delay_to_insert_ms` y `max_delay_to_insert`). [#62420](https://github.com/ClickHouse/ClickHouse/pull/62420) ([Sergei Trifonov](https://github.com/serxa)).
* Se añadió la columna `hostname` que faltaba a la tabla del sistema `blob_storage_log`. [#62456](https://github.com/ClickHouse/ClickHouse/pull/62456) ([Jayme Bird](https://github.com/jaymebrd)).
* Se cambió el directory de instalación predeterminado en macOS de `/usr/bin` a `/usr/local/bin`. Esto es necesario porque System Integrity Protection de Apple, introducido con macOS El Capitan (2015), impide escribir en `/usr/bin`, incluso con `sudo`. [#62489](https://github.com/ClickHouse/ClickHouse/pull/62489) ([haohang](https://github.com/yokofly)).
* Hacer que transform devuelva siempre la primera coincidencia. [#62518](https://github.com/ClickHouse/ClickHouse/pull/62518) ([Raúl Marín](https://github.com/Algunenano)).
* Para mantener la coherencia con otras tablas del sistema, `system.backup_log` ahora tiene una columna `event_time`. [#62541](https://github.com/ClickHouse/ClickHouse/pull/62541) ([Jayme Bird](https://github.com/jaymebrd)).
* Evita evaluar las expresiones DEFAULT de la tabla al ejecutar `RESTORE`. [#62601](https://github.com/ClickHouse/ClickHouse/pull/62601) ([Vitaly Baranov](https://github.com/vitlibar)).
* Devuelve un flujo de fragmentos desde `system.remote_data_paths` en lugar de acumular todo el resultado en un único fragmento grande. Esto permite usar menos memoria, mostrar el progreso intermedio y cancelar la consulta. [#62613](https://github.com/ClickHouse/ClickHouse/pull/62613) ([Alexander Gololobov](https://github.com/davenger)).
* El almacenamiento S3 y las copias de seguridad también necesitan la misma configuración predeterminada de keep alive que el disco S3. [#62648](https://github.com/ClickHouse/ClickHouse/pull/62648) ([Sema Checherinda](https://github.com/CheSema)).
* La tabla `system.backup_log` ahora tiene la clave de ordenación &quot;default&quot;, que es `event_date, event_time`, la misma que otros motores de tabla `_log`. [#62667](https://github.com/ClickHouse/ClickHouse/pull/62667) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Marca el tipo Variant como comparable para que pueda usarse como clave primaria. [#62693](https://github.com/ClickHouse/ClickHouse/pull/62693) ([Kruglov Pavel](https://github.com/Avogar)).
* Añade el identificador del client de librdkafka a los mensajes de registro para poder diferenciar los mensajes de registro de distintos consumers de una misma tabla. [#62813](https://github.com/ClickHouse/ClickHouse/pull/62813) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Permitir macros especiales {uuid} y {database} en la ruta de ZooKeeper de una base de datos Replicated. [#62818](https://github.com/ClickHouse/ClickHouse/pull/62818) ([Vitaly Baranov](https://github.com/vitlibar)).
* Permitir el uso de quota key con un esquema de autenticación distinto en las solicitudes HTTP. [#62842](https://github.com/ClickHouse/ClickHouse/pull/62842) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Eliminar la etiqueta Experimental del motor de base de datos Replicated. Ahora se encuentra en fase Beta. [#62937](https://github.com/ClickHouse/ClickHouse/pull/62937) ([Justin de Guzman](https://github.com/justindeguzman)).
* Reducir el nivel de detalle del argumento de línea de comandos `--help` en `clickhouse client` y `clickhouse local`. La salida anterior ahora se genera con `--help --verbose`. [#62973](https://github.com/ClickHouse/ClickHouse/pull/62973) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Cerrar la sesión si se alcanza [el `valid_until` del usuario](https://clickhouse.com/docs/en/sql-reference/statements/create/user#valid-until-clause). [#63046](https://github.com/ClickHouse/ClickHouse/pull/63046) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* `log_bin_use_v1_row_events` se eliminó en MySQL 8.3; se corrige la issue [#60479](https://github.com/ClickHouse/ClickHouse/issues/60479). [#63101](https://github.com/ClickHouse/ClickHouse/pull/63101) ([Eugene Klimov](https://github.com/Slach)).
