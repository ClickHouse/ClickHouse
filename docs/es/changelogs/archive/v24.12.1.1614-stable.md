<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Las funciones `greatest` y `least` ahora ignoran los valores de entrada NULL, mientras que antes devolvían NULL si alguno de los argumentos era NULL. Por ejemplo, `SELECT greatest(1, 2, NULL)` ahora devuelve 2. Esto hace que el comportamiento sea compatible con PostgreSQL. [#65519](https://github.com/ClickHouse/ClickHouse/pull/65519) ([kevinyhzou](https://github.com/KevinyhZou)).
* Se ha eliminado la integración legacy de MongoDB basada en el driver Poco. La configuración del servidor `use_legacy_mongodb_integration` está obsoleta y ya no tiene ningún efecto. [#71997](https://github.com/ClickHouse/ClickHouse/pull/71997) ([Kirill Nikiforov](https://github.com/allmazz)).



<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añadió una consulta que permite vincular tablas MergeTree como ReplicatedMergeTree y viceversa. [#65401](https://github.com/ClickHouse/ClickHouse/pull/65401) ([Kirill](https://github.com/kirillgarbar)).
* Se implementó el comando SYSTEM LOAD PRIMARY KEY para cargar los índices primarios de todas las partes de una tabla especificada, o de todas las tablas si no se especifica ninguna. Resulta útil para benchmarks y para evitar latencia adicional durante la ejecución de consultas. [#66252](https://github.com/ClickHouse/ClickHouse/pull/66252) ([ZAWA_ll](https://github.com/Zawa-ll)).
* Se añadió la sentencia `SYSTEM LOAD PRIMARY KEY` para cargar los índices primarios de todas las partes de una tabla especificada, o de todas las tablas si no se especifica ninguna. Puede resultar útil para benchmarking y para evitar latencia adicional durante la ejecución de consultas. [#67733](https://github.com/ClickHouse/ClickHouse/pull/67733) ([ZAWA_ll](https://github.com/Zawa-ll)).
* El formato de almacenamiento de datos [Iceberg](https://iceberg.apache.org/spec/#file-system-operations) ofrece al usuario amplias opciones para modificar el esquema de su tabla. En este pull request se implementó la lectura de tablas en formato Iceberg donde se han modificado el orden de las columnas, los nombres de columna y las extensiones de tipos simples. [#69445](https://github.com/ClickHouse/ClickHouse/pull/69445) ([Daniil Ivanik](https://github.com/divanik)).
* Se añadió la función `toUnixTimestamp64Second`, que convierte un valor `DateTime64` a un valor `Int64` con precisión fija en segundos, lo que permite retornar valores negativos para fechas anteriores a las 00:00:00 UTC del jueves 1 de enero de 1970. [#70597](https://github.com/ClickHouse/ClickHouse/pull/70597) ([zhanglistar](https://github.com/zhanglistar)).
* Se añadió la nueva configuración `enforce_index_structure_match_on_partition_manipulation` para permitir la operación de attach cuando las proyecciones e índices secundarios de la tabla de origen son un subconjunto de los de la tabla de destino. Cierra [#70602](https://github.com/ClickHouse/ClickHouse/issues/70602). [#70603](https://github.com/ClickHouse/ClickHouse/pull/70603) ([zwy991114](https://github.com/zwy991114)).
* La salida de la función `cast` difiere de la de Apache Spark, lo que genera discrepancias en el proyecto gluten; véase https://github.com/apache/incubator-gluten/issues/7602. Este PR añade soporte para el formato de salida de texto de Spark, desactivado por defecto. [#70957](https://github.com/ClickHouse/ClickHouse/pull/70957) ([zhanglistar](https://github.com/zhanglistar)).
* Este PR introduce la nueva configuración `allow_experimental_reverse_key`, que habilita el soporte para orden descendente en las claves de ordenación de MergeTree. Resulta útil para el análisis de series temporales, especialmente en consultas TopN. Ejemplo de uso: ```sql CREATE TABLE example ( time DateTime, key Int32, value String ) ENGINE = MergeTree ORDER BY (time DESC, key); -- Descending order for 'time' field SETTINGS allow_experimental_reverse_key = 1;. [#71095](https://github.com/ClickHouse/ClickHouse/pull/71095) ([Amos Bird](https://github.com/amosbird)).
* Se añadió integración con Iceberg REST Catalog. [#71542](https://github.com/ClickHouse/ClickHouse/pull/71542) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se añadió una opción para seleccionar qué lado del join actuará como tabla interna (build) en el plan de consulta. Esto se controla mediante `query_plan_join_swap_table`, que puede establecerse en `auto`. En este modo, ClickHouse intentará elegir la tabla con el menor número de filas. [#71577](https://github.com/ClickHouse/ClickHouse/pull/71577) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Se añadió la sintaxis ALTER USER {ADD|MODIFY|DROP SETTING}, ALTER USER {ADD|DROP PROFILE}, y sus equivalentes para ALTER ROLE y ALTER PROFILE. [#72050](https://github.com/ClickHouse/ClickHouse/pull/72050) ([pufit](https://github.com/pufit)).
* Se añadió la función `arrayPrAUC`, que calcula el AUC (área bajo la curva) para la curva de Precisión-Recall. [#72073](https://github.com/ClickHouse/ClickHouse/pull/72073) ([Emmanuel](https://github.com/emmanuelsdias)).
* Se añadió caché para el índice primario de las tablas `MergeTree` (puede habilitarse mediante la configuración de tabla `use_primary_key_cache`). Si la carga diferida y la caché están habilitadas para el índice primario, este se cargará en caché bajo demanda (de forma similar a la caché de marcas) en lugar de mantenerse en memoria de forma indefinida. Se añadió el precalentamiento del índice primario en inserciones, fusiones y recuperaciones de partes de datos, así como al reiniciar la tabla (puede habilitarse mediante la configuración `prewarm_primary_key_cache`). [#72102](https://github.com/ClickHouse/ClickHouse/pull/72102) ([Anton Popov](https://github.com/CurtizJ)).
* Retroportado en [#73593](https://github.com/ClickHouse/ClickHouse/issues/73593): las sentencias `SELECT` y `VIEW` ahora admiten aliases; por ejemplo, `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);`. Esto permite ejecutar la consulta 15 de TPC-H sin modificaciones. [#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se añadió la función `indexOfAssumeSorted` para tipos Array. Optimiza la búsqueda en arrays ordenados en orden no decreciente. [#72517](https://github.com/ClickHouse/ClickHouse/pull/72517) ([Eric Kurbanov](https://github.com/erickurbanov)).
* Se permite usar un delimitador como segundo argumento opcional de la función de agregación `groupConcat`. [#72540](https://github.com/ClickHouse/ClickHouse/pull/72540) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se añadió la nueva configuración `http_response_headers`, que permite personalizar las cabeceras de respuesta HTTP. Por ejemplo, es posible indicarle al navegador que muestre una imagen almacenada en la base de datos. Esto cierra [#59620](https://github.com/ClickHouse/ClickHouse/issues/59620). [#72656](https://github.com/ClickHouse/ClickHouse/pull/72656) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió la función `fromUnixTimestamp64Second`, que convierte un valor de Unix timestamp de tipo `Int64` a un `DateTime64`. [#73146](https://github.com/ClickHouse/ClickHouse/pull/73146) ([Robert Schulze](https://github.com/rschu1ze)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se reduce el uso de memoria de `clickhouse disks remove --recursive` para los discos de almacenamiento de objetos. [#67323](https://github.com/ClickHouse/ClickHouse/pull/67323) ([Kirill](https://github.com/kirillgarbar)).
* Se habilita la compilación JIT para más expresiones: abs/bitCount/sign/modulo/pmod/isNull/isNotNull/assumeNotNull/to(U)Int*/toFloat*, funciones de comparación (=, <, >, >=, <=), funciones lógicas (and, or). [#70598](https://github.com/ClickHouse/ClickHouse/pull/70598) ([李扬](https://github.com/taiyang-li)).
* A partir de ahora, el algoritmo `parallel_hash` se utilizará (cuando sea aplicable) si la configuración `join_algorithm` está establecida en `default`. Las dos alternativas anteriores (`direct` y `hash`) siguen considerándose cuando `parallel_hash` no puede utilizarse. [#70788](https://github.com/ClickHouse/ClickHouse/pull/70788) ([Nikita Taranov](https://github.com/nickitat)).
* Se añade la opción de extraer expresiones comunes de las cláusulas `WHERE` y `ON` para reducir el número de tablas hash utilizadas durante los joins. Puede habilitarse con `optimize_extract_common_expressions = 1`. [#71537](https://github.com/ClickHouse/ClickHouse/pull/71537) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Permite utilizar índices en `SELECT` con `LowCardinality(String)`. [#71598](https://github.com/ClickHouse/ClickHouse/pull/71598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Durante la ejecución de consultas con réplicas paralelas y plan local habilitado, se omite el análisis de índices en los workers. El coordinador seleccionará los rangos de lectura para los workers a partir del análisis de índices realizado en su propio lado (en el iniciador de la consulta). [#72109](https://github.com/ClickHouse/ClickHouse/pull/72109) ([Igor Nikonov](https://github.com/devcrafter)).
* Se recupera la optimización para la lectura de subcolumnas de una sola columna en partes compactas de https://github.com/ClickHouse/ClickHouse/pull/57631, que había sido eliminada accidentalmente. [#72285](https://github.com/ClickHouse/ClickHouse/pull/72285) ([Pavel Kruglov](https://github.com/Avogar)).
* Se acelera la ordenación de columnas `LowCardinality(String)` mediante la desvirtualización de llamadas en el comparador. [#72337](https://github.com/ClickHouse/ClickHouse/pull/72337) ([Alexander Gololobov](https://github.com/davenger)).
* Se optimiza la función argMin/Max para algunos tipos de datos simples. [#72350](https://github.com/ClickHouse/ClickHouse/pull/72350) ([alesapin](https://github.com/alesapin)).
* Se optimiza el bloqueo con locks compartidos en el memory tracker para reducir la contención de locks. [#72375](https://github.com/ClickHouse/ClickHouse/pull/72375) ([Jiebin Sun](https://github.com/jiebinn)).
* Se añade una nueva configuración, `use_async_executor_for_materialized_views`. Permite la ejecución asíncrona y potencialmente multihilo de la consulta de vista materializada; puede acelerar el procesamiento de vistas durante INSERT, aunque también consume más memoria. [#72497](https://github.com/ClickHouse/ClickHouse/pull/72497) ([alesapin](https://github.com/alesapin)).
* Los valores predeterminados de las configuraciones `max_size_to_preallocate_for_aggregation` y `max_size_to_preallocate_for_joins` se incrementaron aún más hasta `10^12`, de modo que la optimización se aplicará en más casos. [#72555](https://github.com/ClickHouse/ClickHouse/pull/72555) ([Nikita Taranov](https://github.com/nickitat)).
* Se mejora el rendimiento de la deserialización de estados de funciones de agregación (en el tipo de dato `AggregateFunction` y en consultas distribuidas). Se mejora ligeramente el rendimiento del análisis sintáctico del formato `RowBinary`. [#72818](https://github.com/ClickHouse/ClickHouse/pull/72818) ([Anton Popov](https://github.com/CurtizJ)).
