<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se eliminan la opción de configuración `status_info` y el estado de Dictionaries del handler predeterminado de Prometheus. [#54090](https://github.com/ClickHouse/ClickHouse/pull/54090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La caché de metadatos experimental de partes se elimina de la base de código. [#54215](https://github.com/ClickHouse/ClickHouse/pull/54215) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se deshabilita por defecto la configuración `input_format_json_try_infer_numbers_from_strings`, por lo que ya no se intenta inferir números a partir de cadenas en los formatos JSON de forma predeterminada, para evitar posibles errores de análisis cuando los datos de muestra contienen cadenas que parecen números. [#55099](https://github.com/ClickHouse/ClickHouse/pull/55099) ([Kruglov Pavel](https://github.com/Avogar)).
* Los índices bloom filter de IPv6 creados antes de marzo de 2023 no son compatibles con la versión actual y deben reconstruirse. [#54200](https://github.com/ClickHouse/ClickHouse/pull/54200) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).



<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añadió un nuevo tipo de autenticación basado en claves SSH. Funciona solo con el protocolo TCP nativo. [#41109](https://github.com/ClickHouse/ClickHouse/pull/41109) ([George Gamezardashvili](https://github.com/InfJoker)).
* Se añadió compatibilidad con la planificación de IO para discos remotos. La configuración de almacenamiento para los tipos de disco `s3`, `s3_plain`, `hdfs` y `azure_blob_storage` ahora puede contener elementos `read_resource` y `write_resource` con nombres de recurso. Las políticas de planificación para estos recursos se pueden configurar en una sección independiente de la configuración del servidor, `resources`. Las consultas se pueden marcar mediante el setting `workload` y clasificar mediante la sección de configuración del servidor `workload_classifiers` para lograr distintos objetivos de planificación de recursos. Más detalles en docs/en/operations/workload-scheduling.md. [#47009](https://github.com/ClickHouse/ClickHouse/pull/47009) ([Sergei Trifonov](https://github.com/serxa)).
* Se añadió una nueva columna &#95;block&#95;number que resuelve [#44532](https://github.com/ClickHouse/ClickHouse/issues/44532). [#47532](https://github.com/ClickHouse/ClickHouse/pull/47532) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Se añadieron las opciones `partial_result_update_duration_ms` y `max_rows_in_partial_result` para mostrar actualizaciones en tiempo real de un resultado parcial de la tabla de salida durante la ejecución de la consulta. [#48607](https://github.com/ClickHouse/ClickHouse/pull/48607) ([Alexey Perevyshin](https://github.com/alexX512)).
* Se añadió compatibilidad con los modos de coincidencia sin distinción entre mayúsculas y minúsculas y dot-all en los diccionarios RegExpTree. [#50906](https://github.com/ClickHouse/ClickHouse/pull/50906) ([Johann Gan](https://github.com/johanngan)).
* Se añadió compatibilidad con `ALTER TABLE MODIFY COMMENT`. Nota: hace mucho tiempo un colaborador externo añadió algo similar, pero la función no funcionaba en absoluto y solo confundía a los usuarios. Esto cierra [#36377](https://github.com/ClickHouse/ClickHouse/issues/36377). [#51304](https://github.com/ClickHouse/ClickHouse/pull/51304) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió &quot;GCD&quot;, también conocido como &quot;greatest common denominator&quot;, como un nuevo códec de compresión de datos. El códec calcula el GCD de todos los valores de la columna y luego divide cada valor por el GCD. El códec GCD es un códec de preparación de datos (similar a Delta y DoubleDelta) y no puede usarse por sí solo. Funciona con tipos de datos enteros, decimales y de fecha/hora. Un caso de uso viable del códec GCD son los valores de columna que cambian (aumentan/disminuyen) en múltiplos del GCD, p. ej., 24 - 28 - 16 - 24 - 8 - 24 (suponiendo GCD = 4). [#53149](https://github.com/ClickHouse/ClickHouse/pull/53149) ([Alexander Nam](https://github.com/seshWCS)).
* Se añadieron dos nuevos aliases de tipo: &quot;DECIMAL(P)&quot; (como atajo de &quot;DECIMAL(P, 0&quot;) y &quot;DECIMAL&quot; (como atajo de &quot;DECIMAL(10, 0)&quot;). Esto hace que ClickHouse sea más compatible con el SQL dialect de MySQL. [#53328](https://github.com/ClickHouse/ClickHouse/pull/53328) ([Val Doroshchuk](https://github.com/valbok)).
* Se añadió una nueva tabla Log del sistema, `backup_log`, para rastrear todas las operaciones `BACKUP` y `RESTORE`. [#53638](https://github.com/ClickHouse/ClickHouse/pull/53638) ([Victor Krasnov](https://github.com/sirvickr)).
* Se añadió un setting de formato, &quot;output&#95;format&#95;markdown&#95;escape&#95;special&#95;characters&quot; (valor predeterminado: false). El setting controla si los caracteres especiales como &quot;!&quot;, &quot;#&quot;, &quot;$&quot;, etc. se escapan (es decir, si se les antepone una barra invertida) en el formato de salida &quot;Markdown&quot;. [#53860](https://github.com/ClickHouse/ClickHouse/pull/53860) ([irenjj](https://github.com/irenjj)).
* Se añadió la función `decodeHTMLComponent`. [#54097](https://github.com/ClickHouse/ClickHouse/pull/54097) ([Bharat Nallan](https://github.com/bharatnc)).
* Se añadió peak&#95;threads&#95;usage a la tabla query&#95;log. [#54335](https://github.com/ClickHouse/ClickHouse/pull/54335) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* Se añadió compatibilidad con SHOW FUNCTIONS a clickhouse-client. [#54337](https://github.com/ClickHouse/ClickHouse/pull/54337) ([Julia Kartseva](https://github.com/wat-ze-hex)).
* Este PR mejora la inferencia de esquema en formatos JSON: 1) Ahora es posible inferir Tuples con nombre a partir de objetos JSON sin el JSON type experimental, mediante la configuración `input_format_json_try_infer_named_tuples_from_objects` en formatos JSON. Anteriormente, sin el JSON type experimental, solo podíamos inferir objetos JSON como Strings o Maps; ahora podemos inferir named Tuple. El tipo Tuple resultante contendrá todas las claves de los objetos que se hayan leído en la muestra de datos durante la inferencia de esquema. Esto puede ser útil para leer datos JSON estructurados sin objetos dispersos. La configuración está habilitada de forma predeterminada. 2) Permite el parsing de JSON array en una columna de tipo String mediante la configuración `input_format_json_read_arrays_as_strings`. Esto puede ayudar a leer arrays con valores de distintos tipos. 3) Permite usar el tipo String para claves JSON con tipos desconocidos (`null`/`[]`/`{}`) en los datos de muestra mediante la configuración `input_format_json_infer_incomplete_types_as_strings`. Ahora, en formatos JSON, podemos leer cualquier valor en una columna String y evitar el error `Cannot determine type for column 'column_name' by first 25000 rows of data, most likely this column contains only Nulls or empty Arrays/Maps` durante la inferencia de esquema usando el tipo String para los tipos desconocidos, por lo que los datos se leerán correctamente. [#54427](https://github.com/ClickHouse/ClickHouse/pull/54427) ([Kruglov Pavel](https://github.com/Avogar)).
* Se añadió la función &quot;toDaysSinceYearZero&quot; con el alias &quot;TO&#95;DAYS()&quot; (por compatibilidad con MySQL), que devuelve el número de días transcurridos desde 0001-01-01. [#54479](https://github.com/ClickHouse/ClickHouse/pull/54479) ([Robert Schulze](https://github.com/rschu1ze)).
* Se añadieron las funciones YYYYMMDDtoDate(), YYYYMMDDtoDate32(), YYYYMMDDhhmmssToDateTime() y YYYYMMDDhhmmssToDateTime64(). Convierten una fecha o una fecha con hora codificada como entero (p. ej., 20230911) en una fecha nativa o una fecha con hora nativa. Como tales, proporcionan la funcionalidad opuesta a las funciones existentes YYYYMMDDToDate(), YYYYMMDDToDateTime(), YYYYMMDDhhmmddToDateTime(), YYYYMMDDhhmmddToDateTime64(). [#54509](https://github.com/ClickHouse/ClickHouse/pull/54509) ([Robert Schulze](https://github.com/rschu1ze)).
* Se añadió el tipo de nodo de planificación de IO &quot;bandwidth&#95;limit&quot;. Permite especificar restricciones `max_speed` y `max_burst` sobre el tráfico que pasa por este nodo. Más detalles en docs/en/operations/workload-scheduling.md. [#54618](https://github.com/ClickHouse/ClickHouse/pull/54618) ([Sergei Trifonov](https://github.com/serxa)).
* La función `toDaysSinceYearZero()` ahora admite argumentos de tipo `DateTime` y `DateTime64`. [#54856](https://github.com/ClickHouse/ClickHouse/pull/54856) ([Serge Klochkov](https://github.com/slvrtrn)).
* Se permiten URL de estilo S3 para las table functions `s3`, `gcs`, `oss`. La URL se convierte automáticamente a HTTP. Ejemplo: `'s3://clickhouse-public-datasets/hits.csv'` se convierte en `'https://clickhouse-public-datasets.s3.amazonaws.com/hits.csv'`. [#54931](https://github.com/ClickHouse/ClickHouse/pull/54931) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se añadieron varias funciones de distancia para cadenas, incluidas `byteHammingDistance`, `byteJaccardIndex` y `byteEditDistance`. ### Entrada de documentación para cambios orientados al usuario. [#54935](https://github.com/ClickHouse/ClickHouse/pull/54935) ([flynn](https://github.com/ucasfl)).
* Se añade la nueva configuración `print_pretty_type_names` para mostrar tipos anidados complejos de forma legible, como Tuple/Maps/Arrays. [#55095](https://github.com/ClickHouse/ClickHouse/pull/55095) ([Kruglov Pavel](https://github.com/Avogar)).

* Se reemplazó la biblioteca usada para manejar (codificar/decodificar) valores base64 de Turbo-Base64 por aklomp-base64. Nota: aklomp-base64 rechaza los valores base64 sin padding, mientras que Turbo-Base64 los decodifica en la medida de lo posible. RFC-4648 deja abierto si el padding es obligatorio o no, pero según el contexto esto puede suponer un cambio de comportamiento que conviene tener en cuenta. [#54119](https://github.com/ClickHouse/ClickHouse/pull/54119) ([Mikhail Koviazin](https://github.com/mkmkme)).
