<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se elimina la funcionalidad `do_not_evict_index_and_mark_files` de la caché de fs. Esta funcionalidad solo empeoraba las cosas. [#51253](https://github.com/ClickHouse/ClickHouse/pull/51253) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se elimina el soporte de ALTER para LIVE VIEW experimental. [#51287](https://github.com/ClickHouse/ClickHouse/pull/51287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade la configuración `session_timezone`; se usa como zona horaria predeterminada de la sesión cuando no se especifica explícitamente. [#44149](https://github.com/ClickHouse/ClickHouse/pull/44149) ([Andrey Zvonov](https://github.com/zvonand)).
* Se añadieron el motor de base de datos overlay y la representación de un directorio como base de datos. Este commit añade 4 bases de datos: 1. DatabaseOverlay: implementa la interfaz IDatabase. Permite combinar varias bases de datos, como FileSystem y Memory. Internamente, almacena un vector con punteros a otras bases de datos y redirige las solicitudes a cada una por turno hasta que una se ejecuta correctamente. 2. DatabaseFilesystem: permite interactuar en modo de solo lectura con archivos almacenados en el sistema de archivos. Internamente, usa TableFunctionFile para cargar implícitamente el archivo cuando un usuario solicita la tabla. El resultado de la llamada a TableFunctionFile se almacena en caché internamente para proporcionar acceso rápido. 3. DatabaseS3: permite interactuar en modo de solo lectura con el almacenamiento S3. Usa TableFunctionS3 para cargar implícitamente la tabla desde S3. 4. DatabaseHDFS: permite interactuar con el almacenamiento HDFS. Usa TableFunctionHDFS para cargar implícitamente la tabla desde HDFS. [#48821](https://github.com/ClickHouse/ClickHouse/pull/48821) ([alekseygolub](https://github.com/alekseygolub)).
* Se añade una nueva configuración llamada `use_mysql_types_in_show_columns` para modificar la instrucción SQL `SHOW COLUMNS` y mostrar tipos equivalentes de MySQL cuando un client está conectado mediante el puerto de compatibilidad con MySQL. [#49577](https://github.com/ClickHouse/ClickHouse/pull/49577) ([Thomas Panetti](https://github.com/tpanetti)).
* Se añadió la opción `--rename_files_after_processing <pattern>`. Esto cierra [#34207](https://github.com/ClickHouse/ClickHouse/issues/34207). [#49626](https://github.com/ClickHouse/ClickHouse/pull/49626) ([alekseygolub](https://github.com/alekseygolub)).
* 1. Se añade `TableFunctionRedis` 3. Se añade el motor de tabla Redis 4. Se añade `RedisCommon`, que contiene herramientas y tipos relacionados con Redis 5. Se admite el push down de los filtros `equals` e `in` en Redis. [#50150](https://github.com/ClickHouse/ClickHouse/pull/50150) ([JackyWoo](https://github.com/JackyWoo)).
* Permite omitir archivos vacíos en las table functions file/s3/url/hdfs mediante las configuraciones `s3_skip_empty_files`, `hdfs_skip_empty_files`, `engine_file_skip_empty_files`, `engine_url_skip_empty_files`. [#50364](https://github.com/ClickHouse/ClickHouse/pull/50364) ([Kruglov Pavel](https://github.com/Avogar)).
* Ahora se puede invocar `clickhouse-client` con una connection en lugar de `--host`, `--port`, `--user`, etc. [#50689](https://github.com/ClickHouse/ClickHouse/pull/50689) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* El códec DEFLATE&#95;QPL ahora se controla mediante la configuración del servidor `enable_deflate_qpl_codec` (predeterminado: false) en lugar de la configuración `allow_experimental_codecs`. Esto hace que QPL&#95;DEFLATE deje de ser experimental. [#50775](https://github.com/ClickHouse/ClickHouse/pull/50775) ([Robert Schulze](https://github.com/rschu1ze)).



<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Mejora el rendimiento con QueryProfiler habilitado usando `timer_id` local al hilo en lugar de un objeto global. [#48778](https://github.com/ClickHouse/ClickHouse/pull/48778) ([Jiebin Sun](https://github.com/jiebinn)).
* Reescribe el formato de entrada/salida de CapnProto para mejorar su rendimiento. Hace que los nombres de columna de Map y los campos de CapnProto no distingan entre mayúsculas y minúsculas, y corrige la lectura/escritura de los campos de estructuras anidadas. [#49752](https://github.com/ClickHouse/ClickHouse/pull/49752) ([Kruglov Pavel](https://github.com/Avogar)).
* Optimiza el rendimiento de escritura de Parquet para hilos en paralelo. [#50102](https://github.com/ClickHouse/ClickHouse/pull/50102) ([Hongbin Ma](https://github.com/binmahone)).
* ### Entrada de documentación para cambios orientados al usuario Deshabilita `parallelize_output_from_storages` al procesar MATERIALIZED VIEWs y almacenamientos con un solo bloque. [#50214](https://github.com/ClickHouse/ClickHouse/pull/50214) ([Azat Khuzhin](https://github.com/azat)).
* Fusiona el PR https://github.com/ClickHouse/ClickHouse/pull/46558 (Evitar procesar datos ya ordenados). Evita la permutación de bloques durante la ordenación si el bloque ya está ordenado. [#50697](https://github.com/ClickHouse/ClickHouse/pull/50697) ([Maksim Kita](https://github.com/kitaisreal)).
* En los PR anteriores ([#50062](https://github.com/ClickHouse/ClickHouse/issues/50062), [#50307](https://github.com/ClickHouse/ClickHouse/issues/50307)), propusimos un patrón de optimización que transforma los predicados con toYear/toYYYYMM en una forma equivalente, pero sin conversión. Esta transformación podía tener un impacto significativo en el rendimiento de algunas cargas de trabajo, como SSB. Sin embargo, como indicó el issue [#50628](https://github.com/ClickHouse/ClickHouse/issues/50628), estos dos PR introducían problemas que podían dar lugar a resultados de consulta incompletos y, por ello, se revirtieron en [#50629](https://github.com/ClickHouse/ClickHouse/issues/50629). [#50951](https://github.com/ClickHouse/ClickHouse/pull/50951) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Realiza varias solicitudes de listado a ZooKeeper en paralelo para acelerar la lectura desde la tabla system.zookeeper. [#51042](https://github.com/ClickHouse/ClickHouse/pull/51042) ([Alexander Gololobov](https://github.com/davenger)).
* Acelera la inicialización de las tablas de lookup de DateTime para zonas horarias. Esto debería reducir el tiempo de arranque/conexión de clickhouse client, especialmente en una build de depuración, ya que es bastante costoso. [#51347](https://github.com/ClickHouse/ClickHouse/pull/51347) ([Alexander Gololobov](https://github.com/davenger)).
