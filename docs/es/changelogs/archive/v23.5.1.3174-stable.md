<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Hacer que el almacenamiento de objetos local funcione de forma coherente con el almacenamiento de objetos S3, corregir el problema con append (cierra [#48465](https://github.com/ClickHouse/ClickHouse/issues/48465)) y hacerlo configurable como almacenamiento independiente. El cambio es incompatible con versiones anteriores porque la caché sobre el almacenamiento de objetos local no es compatible con las versiones previas. [#48791](https://github.com/ClickHouse/ClickHouse/pull/48791) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Hacer que la función Date&#95;trunc siempre devuelva el tipo datetime. [#48851](https://github.com/ClickHouse/ClickHouse/pull/48851) ([Shane Andrade](https://github.com/mauidude)).
* Eliminar la funcionalidad experimental &quot;in-memory data parts&quot;. El formato de datos sigue siendo compatible, pero los ajustes no tienen efecto, y en su lugar se usarán partes compact o wide. Esto cierra [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409). [#49429](https://github.com/ClickHouse/ClickHouse/pull/49429) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se cambiaron los valores predeterminados de los ajustes parallelize&#95;output&#95;from&#95;storages e input&#95;format&#95;parquet&#95;preserve&#95;order. Esto permite que ClickHouse reordene las filas al leer desde archivos (p. ej., CSV o Parquet), lo que mejora enormemente el rendimiento en muchos casos. Para restaurar el comportamiento anterior de preservar el orden, use `parallelize_output_from_storages = 0`, `input_format_parquet_preserve_order = 1`. [#49479](https://github.com/ClickHouse/ClickHouse/pull/49479) ([Michael Kolupaev](https://github.com/al13n321)).
* Hacer que las proyecciones estén listas para producción. Agregar el ajuste `optimize_use_projections` para controlar si se seleccionarán las proyecciones para las consultas SELECT. El ajuste `allow_experimental_projection_optimization` es obsoleto y no hace nada. [#49719](https://github.com/ClickHouse/ClickHouse/pull/49719) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Marcar joinGet() como no determinista (igual que dictGet). [#49843](https://github.com/ClickHouse/ClickHouse/pull/49843) ([Azat Khuzhin](https://github.com/azat)).
* Revertir &quot;`groupArray` no puede devolver Nullable&quot; (debido a una ruptura de compatibilidad binaria para `groupArray`/`groupArrayLast`/`groupArraySample` sobre tipos `Nullable`, lo que probablemente provocará `TOO_LARGE_ARRAY_SIZE` o `CANNOT_READ_ALL_DATA`). [#49971](https://github.com/ClickHouse/ClickHouse/pull/49971) ([Azat Khuzhin](https://github.com/azat)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Comprime las marcas y la clave primaria de forma predeterminada. Esto reduce significativamente el tiempo de las consultas en frío. Notas de actualización: el soporte para marcas y clave primaria comprimidas se añadió en la versión 22.9. Si activó las marcas o la clave primaria comprimidas, o instaló la versión 23.5 o posterior, en la que las marcas y la clave primaria vienen comprimidas de forma predeterminada, no podrá volver a la versión 22.8 o anterior. También puede desactivar explícitamente la compresión de las marcas o de las claves primarias especificando las configuraciones `compress_marks` y `compress_primary_key` en la sección `<merge_tree>` del archivo de configuración del servidor. **Notas de actualización:** Si actualiza desde versiones anteriores a la 22.9, debe actualizar todas las réplicas a la vez, desactivar la compresión antes de actualizar o pasar por una versión intermedia en la que las marcas comprimidas sean compatibles pero no estén activadas de forma predeterminada, como la 23.3. [#42587](https://github.com/ClickHouse/ClickHouse/pull/42587) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Al leer desde varios archivos, se reduce el número de threads de parsing en paralelo para cada archivo, lo que resuelve [#42192](https://github.com/ClickHouse/ClickHouse/issues/42192). [#46661](https://github.com/ClickHouse/ClickHouse/pull/46661) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* No almacena blocks en `ANY` hash join si no se inserta nada. [#48633](https://github.com/ClickHouse/ClickHouse/pull/48633) ([vdimir](https://github.com/vdimir)).
* Corrige el aggregate combinator `-If` cuando se compila con JIT. Cierra [#48120](https://github.com/ClickHouse/ClickHouse/issues/48120). [#49083](https://github.com/ClickHouse/ClickHouse/pull/49083) ([Igor Nikonov](https://github.com/devcrafter)).
* Para leer desde tablas remotas, usamos tasks más pequeñas (en lugar de leer la parte completa) para que funcione el stealing de tasks * el task size se determina por el tamaño de las columns que se van a leer * se usan siempre búferes de 1 MB para leer desde s3 * los límites de los segments de la caché se alinean a 1 MB para que tengan un tamaño razonable incluso con tasks pequeñas. Esto también debería evitar la fragmentación. [#49287](https://github.com/ClickHouse/ClickHouse/pull/49287) ([Nikita Taranov](https://github.com/nickitat)).
* El tamaño predeterminado de un read buffer para leer desde el local filesystem se cambió por un valor ligeramente mejor. También se introducen dos nuevas configuraciones: `max_read_buffer_size_local_fs` y `max_read_buffer_size_remote_fs`. [#49321](https://github.com/ClickHouse/ClickHouse/pull/49321) ([Nikita Taranov](https://github.com/nickitat)).
* Mejora el uso de memoria y la velocidad de los Dictionaries `SPARSE_HASHED`/`HASHED` (por ejemplo, `SPARSE_HASHED` ahora consume 2.6x menos memoria y es ~2x más rápido). [#49380](https://github.com/ClickHouse/ClickHouse/pull/49380) ([Azat Khuzhin](https://github.com/azat)).
* Usa la aggregate projection solo si lee menos granules que la lectura normal. Esto debería ayudar cuando la consulta alcanza la PK de la tabla, pero no la proyección. Corrige [#49150](https://github.com/ClickHouse/ClickHouse/issues/49150). [#49417](https://github.com/ClickHouse/ClickHouse/pull/49417) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Optimiza las llamadas a PODArray::resize&#95;fill(). [#49459](https://github.com/ClickHouse/ClickHouse/pull/49459) ([Azat Khuzhin](https://github.com/azat)).
* Optimiza las tablas system.query&#95;log y system.query&#95;thread&#95;log aplicando LowCardinality cuando corresponde. Las consultas sobre estas tablas serán más rápidas. [#49530](https://github.com/ClickHouse/ClickHouse/pull/49530) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejor rendimiento al leer archivos Parquet locales (mediante lectura paralela). [#49539](https://github.com/ClickHouse/ClickHouse/pull/49539) ([Michael Kolupaev](https://github.com/al13n321)).
* Mejora el rendimiento de `RIGHT/FULL JOIN` hasta 2 veces en determinados escenarios, especialmente al unir una tabla izquierda pequeña con una tabla derecha grande. [#49585](https://github.com/ClickHouse/ClickHouse/pull/49585) ([lgbo](https://github.com/lgbo-ustc)).
* Mejora el rendimiento de BLAKE3 en un 11 % al habilitar LTO para Rust. [#49600](https://github.com/ClickHouse/ClickHouse/pull/49600) ([Azat Khuzhin](https://github.com/azat)).
* Optimiza la estructura de `system.opentelemetry_span_log`. Usa `LowCardinality` cuando corresponda. Aunque esta tabla en general está bastante mal diseñada (usa el tipo de dato Map incluso para atributos comunes), será ligeramente mejor. [#49647](https://github.com/ClickHouse/ClickHouse/pull/49647) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Intenta reservar el tamaño de la hash table en el join `grace_hash`. [#49816](https://github.com/ClickHouse/ClickHouse/pull/49816) ([lgbo](https://github.com/lgbo-ustc)).
* Como se indica en el issue [#49748](https://github.com/ClickHouse/ClickHouse/issues/49748), los predicados con convertidores de fecha, como **toYear, toYYYYMM**, podrían reescribirse como comparaciones equivalentes de fechas (YYYY-MM-DD) a nivel de AST. [#50062](https://github.com/ClickHouse/ClickHouse/pull/50062) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Fusión paralela de estados `uniqExactIf`. Cierra [#49885](https://github.com/ClickHouse/ClickHouse/issues/49885). [#50285](https://github.com/ClickHouse/ClickHouse/pull/50285) ([flynn](https://github.com/ucasfl)).
