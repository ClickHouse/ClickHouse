<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se añade el tipo de acceso ` NAMED COLLECTION` (alias `USE NAMED COLLECTION`, `NAMED COLLECTION USAGE`). Este PR es incompatible con versiones anteriores porque este tipo de acceso está deshabilitado de forma predeterminada (ya que el tipo de acceso padre `NAMED COLLECTION ADMIN` también lo está de forma predeterminada). Propuesto en [#50277](https://github.com/ClickHouse/ClickHouse/issues/50277). Para concederlo, use `GRANT NAMED COLLECTION ON collection_name TO user` o `GRANT NAMED COLLECTION ON * TO user`; para poder otorgar estos grants, se requiere `named_collection_admin` en la configuración (anteriormente se llamaba `named_collection_control`, por lo que seguirá siendo un alias). [#50625](https://github.com/ClickHouse/ClickHouse/pull/50625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se corrige una errata en el nombre de la columna de `system.parts` `last_removal_attemp_time`. Ahora se llama `last_removal_attempt_time`. [#52104](https://github.com/ClickHouse/ClickHouse/pull/52104) ([filimonov](https://github.com/filimonov)).
* Se incrementa de forma predeterminada a 5 la versión de `distributed_ddl_entry_format_version` (habilita el paso de `opentelemetry` e `initial_query_idd`). Esto impedirá procesar las entradas existentes de DDL distribuido después de un **downgrade** (aunque, normalmente, no debería haber este tipo de entradas sin procesar). [#52128](https://github.com/ClickHouse/ClickHouse/pull/52128) ([Azat Khuzhin](https://github.com/azat)).
* Se comprueban los metadatos de las proyecciones de la misma forma que se comprueban los metadatos normales. Este cambio puede impedir que el servidor se inicie si existía una tabla con una proyección no válida. Un ejemplo es una proyección que crea columnas posicionales en la PK (p. ej., `projection p (select * order by 1, 4)`), lo cual no está permitido en la PK de una tabla y puede provocar un crash durante insert/merge. Elimine esas proyecciones antes de la actualización. Corrige [#52353](https://github.com/ClickHouse/ClickHouse/issues/52353). [#52361](https://github.com/ClickHouse/ClickHouse/pull/52361) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* La característica experimental `hashid` se elimina debido a un bug. La calidad de la implementación era cuestionable desde el principio y no llegó a superar el estado experimental. Esto cierra [#52406](https://github.com/ClickHouse/ClickHouse/issues/52406). [#52449](https://github.com/ClickHouse/ClickHouse/pull/52449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La función `toDecimalString` se elimina debido a la baja calidad de su implementación. Esto cierra [#52407](https://github.com/ClickHouse/ClickHouse/issues/52407). [#52450](https://github.com/ClickHouse/ClickHouse/pull/52450) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Habilita de forma predeterminada las opciones `move_all_conditions_to_prewhere` y `enable_multiple_prewhere_read_steps`. [#46365](https://github.com/ClickHouse/ClickHouse/pull/46365) ([Alexander Gololobov](https://github.com/davenger)).

* La escritura de archivos Parquet es 10 veces más rápida; ahora usa varios hilos. Casi alcanza la misma velocidad que la lectura. [#49367](https://github.com/ClickHouse/ClickHouse/pull/49367) ([Michael Kolupaev](https://github.com/al13n321)).
* Habilita de forma predeterminada la selección automática del formato de serialización disperso. Mejora el rendimiento. El formato es compatible desde la versión 22.1. Después de este cambio, es posible que no se pueda volver a versiones anteriores a la 22.1. Puede desactivar el uso del formato de serialización disperso estableciendo la configuración `ratio_of_defaults_for_sparse_serialization = 1` para sus tablas MergeTree. [#49631](https://github.com/ClickHouse/ClickHouse/pull/49631) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ahora usamos tareas de tamaño fijo en `MergeTreePrefetchedReadPool`, como en `MergeTreeReadPool`. Además, a partir de ahora usamos un grupo de conexiones para las solicitudes a S3. [#49732](https://github.com/ClickHouse/ClickHouse/pull/49732) ([Nikita Taranov](https://github.com/nickitat)).
* Más pushdown en el lado derecho del join. [#50532](https://github.com/ClickHouse/ClickHouse/pull/50532) ([Nikita Taranov](https://github.com/nickitat)).
* Mejora `grace_hash` join reservando el tamaño de la tabla hash (reenvío). [#50875](https://github.com/ClickHouse/ClickHouse/pull/50875) ([lgbo](https://github.com/lgbo-ustc)).
* A veces, la espera por el bloqueo en `OpenedFileCache` podía ser perceptible. Lo dividimos en varios submapas (cada uno con su propio bloqueo) para evitar la contención. [#51341](https://github.com/ClickHouse/ClickHouse/pull/51341) ([Nikita Taranov](https://github.com/nickitat)).
* Elimina una condición duplicada en functionunixtimestamp64.h. [#51857](https://github.com/ClickHouse/ClickHouse/pull/51857) ([lcjh](https://github.com/ljhcage)).
* La idea es que las condiciones sobre columnas de PK probablemente se usarán en el análisis de PK y no aportarán mucho más al filtrado PREWHERE. [#51958](https://github.com/ClickHouse/ClickHouse/pull/51958) ([Alexander Gololobov](https://github.com/davenger)).
* 1. Se añade un reescritor tanto para el analizador antiguo como para el nuevo. 2. Se añade la configuración `optimize_uniq_to_count`, cuyo valor predeterminado es 0. [#52004](https://github.com/ClickHouse/ClickHouse/pull/52004) ([JackyWoo](https://github.com/JackyWoo)).

[#52036](https://github.com/ClickHouse/ClickHouse/pull/52036) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Se habilita `allow_vertical_merges_from_compact_to_wide_parts` de forma predeterminada. Reducirá el uso de memoria durante las fusiones. [#52295](https://github.com/ClickHouse/ClickHouse/pull/52295) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

Corrige [#48823](https://github.com/ClickHouse/ClickHouse/issues/48823) . Corrige [#51173](https://github.com/ClickHouse/ClickHouse/issues/51173) .
