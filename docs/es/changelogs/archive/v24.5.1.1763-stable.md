<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se cambió el nombre de &quot;inverted indexes&quot; a &quot;full-text indexes&quot;, un nombre menos técnico y más fácil de usar. Esto también modifica los metadatos internos de las tablas y rompe las tablas con &quot;inverted indexes&quot; (experimentales) existentes. Asegúrese de eliminar esos índices antes de la actualización y volver a crearlos después. [#62884](https://github.com/ClickHouse/ClickHouse/pull/62884) ([Robert Schulze](https://github.com/rschu1ze)).
* El uso de las funciones `neighbor`, `runningAccumulate`, `runningDifferenceStartingWithFirstValue` y `runningDifference` ha quedado obsoleto (porque es propenso a errores). En su lugar, deben usarse las funciones de ventana adecuadas. Para volver a habilitarlas, establezca `allow_deprecated_functions=1`. [#63132](https://github.com/ClickHouse/ClickHouse/pull/63132) ([Nikita Taranov](https://github.com/nickitat)).
* Las consultas a `system.columns` funcionarán más rápido si hay una gran cantidad de columnas, pero no se ha concedido `SHOW TABLES` sobre muchas bases de datos o tablas. Tenga en cuenta que, en versiones anteriores, si concede `SHOW COLUMNS` sobre columnas individuales sin conceder `SHOW TABLES` sobre las tablas correspondientes, la tabla `system.columns` mostrará esas columnas; en la nueva versión, en cambio, omitirá la tabla por completo. Se eliminaron los mensajes del trace log &quot;Access granted&quot; y &quot;Access denied&quot;, que ralentizaban las consultas. [#63439](https://github.com/ClickHouse/ClickHouse/pull/63439) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade compatibilidad para la función AzureBlobStorage en ClickHouse server, de modo que pueda usar Azure Workload identity para autenticarse en Azure blob storage. Si se establece el parámetro `use_workload_identity` en la configuración, se usa [workload identity](https://github.com/Azure/azure-sdk-for-cpp/tree/main/sdk/identity/azure-identity#authenticate-azure-hosted-applications) para la autenticación. [#57881](https://github.com/ClickHouse/ClickHouse/pull/57881) ([Vinay Suryadevara](https://github.com/vinay92-ch)).
* Se introduce la carga masiva en StorageEmbeddedRocksDB mediante la creación e ingesta de un archivo SST en lugar de depender de la memtable integrada de rocksdb. Esto ayuda a aumentar la velocidad de importación, especialmente en insert query de larga duración sobre tablas StorageEmbeddedRocksDB. Además, se introducen los table settings de `StorageEmbeddedRocksDB`. [#59163](https://github.com/ClickHouse/ClickHouse/pull/59163) ([Duc Canh Le](https://github.com/canhld94)).
* Ahora el usuario puede parsear CRLF con el format TSV usando la setting `input_format_tsv_crlf_end_of_line`. Cierra [#56257](https://github.com/ClickHouse/ClickHouse/issues/56257). [#59747](https://github.com/ClickHouse/ClickHouse/pull/59747) ([Shaun Struwig](https://github.com/Blargian)).
* Añade Form Format para leer y escribir un único registro en el formato application/x-www-form-urlencoded. [#60199](https://github.com/ClickHouse/ClickHouse/pull/60199) ([Shaun Struwig](https://github.com/Blargian)).
* Se añadió la posibilidad de comprimir en CROSS JOIN. [#60459](https://github.com/ClickHouse/ClickHouse/pull/60459) ([p1rattttt](https://github.com/p1rattttt)).
* Nueva setting `input_format_force_null_for_omitted_fields` que fuerza valores NULL en los campos omitidos. [#60887](https://github.com/ClickHouse/ClickHouse/pull/60887) ([Constantine Peresypkin](https://github.com/pkit)).
* Se añade compatibilidad con join con condiciones de desigualdad que involucran columns tanto de la tabla izquierda como de la right table. Por ejemplo, `t1.y < t2.y`. Para habilitarlo, `SET allow_experimental_join_condition = 1`. [#60920](https://github.com/ClickHouse/ClickHouse/pull/60920) ([lgbo](https://github.com/lgbo-ustc)).
* Anteriormente, nuestro S3 storage y la S3 table function no admitían seleccionar desde archivos comprimidos. He creado una solución que permite iterar sobre los archivos dentro de archivos comprimidos en S3. [#62259](https://github.com/ClickHouse/ClickHouse/pull/62259) ([Daniil Ivanik](https://github.com/divanik)).
* Se añade compatibilidad con la función condicional `clamp`. [#62377](https://github.com/ClickHouse/ClickHouse/pull/62377) ([skyoct](https://github.com/skyoct)).
* Añade el output format npy. [#62430](https://github.com/ClickHouse/ClickHouse/pull/62430) ([豪肥肥](https://github.com/HowePa)).
* Se añadieron las funciones SQL `generateUUIDv7`, `generateUUIDv7ThreadMonotonic`, `generateUUIDv7NonMonotonic` (con distintas compensaciones entre monotonía y rendimiento) para generar UUIDs de version 7, también conocidos como UUIDs basados en timestamp, con un componente aleatorio. También se añadió una nueva función `UUIDToNum` para extraer bytes de un UUID y una nueva función `UUIDv7ToDateTime` para extraer el timestamp component de un UUID versión 7. [#62852](https://github.com/ClickHouse/ClickHouse/pull/62852) ([Alexey Petrunyaka](https://github.com/pet74alex)).
* Retroportado en [#64307](https://github.com/ClickHouse/ClickHouse/issues/64307): se implementa el tipo de dato Dynamic, que permite almacenar values de cualquier tipo sin conocerlos todos de antemano. El tipo Dynamic está disponible bajo la setting `allow_experimental_dynamic_type`. Reference: [#54864](https://github.com/ClickHouse/ClickHouse/issues/54864). [#63058](https://github.com/ClickHouse/ClickHouse/pull/63058) ([Kruglov Pavel](https://github.com/Avogar)).
* Se introdujo la carga masiva en StorageEmbeddedRocksDB mediante la creación e ingestión de un archivo SST, en lugar de depender de la memtable integrada de RocksDB. Esto ayuda a aumentar la velocidad de importación, especialmente en consultas de inserción de larga duración sobre tablas StorageEmbeddedRocksDB. Además, se introdujeron opciones de configuración de tabla para StorageEmbeddedRocksDB. [#63324](https://github.com/ClickHouse/ClickHouse/pull/63324) ([Duc Canh Le](https://github.com/canhld94)).
* Raw como sinónimo de TSVRaw. [#63394](https://github.com/ClickHouse/ClickHouse/pull/63394) ([Unalian](https://github.com/Unalian)).
* Se agregó la posibilidad de realizar un cross join en un archivo temporal si el tamaño supera los límites. [#63432](https://github.com/ClickHouse/ClickHouse/pull/63432) ([p1rattttt](https://github.com/p1rattttt)).
* En Linux y MacOS, si el programa tiene STDOUT redirigido a un archivo con una extensión de compresión, usa el método de compresión correspondiente en lugar de no usar ninguno (haciendo que se comporte de forma similar a `INTO OUTFILE`). [#63662](https://github.com/ClickHouse/ClickHouse/pull/63662) ([v01dXYZ](https://github.com/v01dXYZ)).
* Se cambió la advertencia sobre un número elevado de tablas adjuntas para diferenciar entre tablas, vistas y diccionarios. [#64180](https://github.com/ClickHouse/ClickHouse/pull/64180) ([Francisco J. Jurado Moreno](https://github.com/Beetelbrox)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Omitir la fusión de bloques de proyección recién creados durante los `INSERT`. [#59405](https://github.com/ClickHouse/ClickHouse/pull/59405) ([Nikita Taranov](https://github.com/nickitat)).
* Procesar las funciones de cadena XXXUTF8 de forma &quot;ASCII&quot; si las cadenas de entrada contienen solo caracteres ASCII. Inspirado en [https://github.com/apache/doris/pull/29799](https://github.com/apache/doris/pull/29799). Aceleración general de 1.07x~1.62x. Tenga en cuenta que el pico de uso de memoria se redujo en algunos casos. [#61632](https://github.com/ClickHouse/ClickHouse/pull/61632) ([李扬](https://github.com/taiyang-li)).
* Se mejoró el rendimiento de los globs de selección (`{}`) en StorageS3. [#62120](https://github.com/ClickHouse/ClickHouse/pull/62120) ([Andrey Zvonov](https://github.com/zvonand)).
* HostResolver contiene cada dirección IP varias veces. Si el host remoto tiene varias IP y, por alguna razón (por ejemplo, reglas de firewall), el acceso a algunas IP está permitido y a otras está prohibido, entonces solo el primer registro de las IP prohibidas se marca como fallido, y en cada intento esas IP pueden volver a elegirse (y fallar de nuevo). Incluso si esto se corrige, cada 120 segundos se vacía la caché DNS y las IP pueden volver a elegirse. [#62652](https://github.com/ClickHouse/ClickHouse/pull/62652) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Añadir una nueva configuración `prefer_merge_sort_block_bytes` para controlar el uso de memoria y acelerar 2 veces la ordenación durante la fusión cuando hay muchas columnas. [#62904](https://github.com/ClickHouse/ClickHouse/pull/62904) ([LiuNeng](https://github.com/liuneng1994)).
* `clickhouse-local` se iniciará más rápido. En versiones anteriores, por error no eliminaba los directorios temporales. Ahora sí lo hará. Esto cierra [#62941](https://github.com/ClickHouse/ClickHouse/issues/62941). [#63074](https://github.com/ClickHouse/ClickHouse/pull/63074) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Microoptimizaciones para el nuevo analizador. [#63429](https://github.com/ClickHouse/ClickHouse/pull/63429) ([Raúl Marín](https://github.com/Algunenano)).
* El análisis de índices funcionará si `DateTime` se compara con `DateTime64`. Esto cierra [#63441](https://github.com/ClickHouse/ClickHouse/issues/63441). [#63443](https://github.com/ClickHouse/ClickHouse/pull/63443) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
