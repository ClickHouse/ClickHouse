<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Validar tipos sospechosos o experimentales en tipos anidados. Antes no validábamos esos tipos (excepto JSON) en tipos anidados como Array/Tuple/Map. [#59385](https://github.com/ClickHouse/ClickHouse/pull/59385) ([Kruglov Pavel](https://github.com/Avogar)).
* La cláusula de ordenación `ORDER BY ALL` (introducida en la v23.12) se sustituye por `ORDER BY *`. La sintaxis anterior era demasiado propensa a errores en tablas con una columna `all`. [#59450](https://github.com/ClickHouse/ClickHouse/pull/59450) ([Robert Schulze](https://github.com/rschu1ze)).
* Renombrar la SETTING `extract_kvp_max_pairs_per_row` a `extract_key_value_pairs_max_pairs_per_row`. El error (una abreviatura innecesaria en el nombre de la SETTING) se introdujo en https://github.com/ClickHouse/ClickHouse/pull/43606. Corregir la documentación de esta SETTING. [#59683](https://github.com/ClickHouse/ClickHouse/pull/59683) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Renombrar la SETTING extract&#95;kvp&#95;max&#95;pairs&#95;per&#95;row a extract&#95;key&#95;value&#95;pairs&#95;max&#95;pairs&#95;per&#95;row. El error (una abreviatura innecesaria en el nombre de la SETTING) se introdujo en https://github.com/ClickHouse/ClickHouse/pull/43606. Corregir la documentación de esta SETTING. [#59960](https://github.com/ClickHouse/ClickHouse/pull/59960) ([jsc0218](https://github.com/jsc0218)).
* Añadir una comprobación básica del número de hilos y de los tamaños de bloque. [#60138](https://github.com/ClickHouse/ClickHouse/pull/60138) ([Raúl Marín](https://github.com/Algunenano)).



<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añadió a la QUOTA un número máximo de fallos consecutivos de inicio de sesión. [#54737](https://github.com/ClickHouse/ClickHouse/pull/54737) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* Se añadió una nueva sintaxis que permite especificar el usuario definidor en View/Materialized View. Esto permite ejecutar selects/inserts desde vistas sin grants explícitos sobre las tablas subyacentes. [#54901](https://github.com/ClickHouse/ClickHouse/pull/54901) ([pufit](https://github.com/pufit)).
* Se añadió compatibilidad de Backup &amp; Restore para AzureBlobStorage, lo que resuelve [#50747](https://github.com/ClickHouse/ClickHouse/issues/50747). [#56988](https://github.com/ClickHouse/ClickHouse/pull/56988) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Se implementó la conversión automática de tablas MergeTree de distintos tipos al motor Replicated. Cree un archivo vacío `convert_to_replicated` en el directorio de datos de la tabla (`/clickhouse/store/xxx/xxxyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy/`) y la tabla se convertirá automáticamente en el siguiente inicio del servidor. [#57798](https://github.com/ClickHouse/ClickHouse/pull/57798) ([Kirill](https://github.com/kirillgarbar)).
* Se añadió la table function `mergeTreeIndex`. Representa el contenido de los archivos de índice y marcas de las tablas `MergeTree`. Puede usarse para introspección. Sintaxis: `mergeTreeIndex(database, table, [with_marks = true])`, donde `database.table` es una tabla existente con motor `MergeTree`. [#58140](https://github.com/ClickHouse/ClickHouse/pull/58140) ([Anton Popov](https://github.com/CurtizJ)).
* Se añadió la función `seriesOutliersTukey` para detectar outliers en series de datos mediante el algoritmo de cercas de Tukey. [#58632](https://github.com/ClickHouse/ClickHouse/pull/58632) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* Ahora el usuario puede especificar la template string directamente en la consulta usando `format_schema_rows_template` como alternativa a `format_template_row`. Cierra [#31363](https://github.com/ClickHouse/ClickHouse/issues/31363). [#59088](https://github.com/ClickHouse/ClickHouse/pull/59088) ([Shaun Struwig](https://github.com/Blargian)).
* Se intenta detectar automáticamente el formato de archivo durante la inferencia de esquema si es desconocido en los motores `file/s3/hdfs/url/azureBlobStorage`. Cierra [#50576](https://github.com/ClickHouse/ClickHouse/issues/50576). [#59092](https://github.com/ClickHouse/ClickHouse/pull/59092) ([Kruglov Pavel](https://github.com/Avogar)).
* Se añade la función `variantType`, que devuelve un Enum con el nombre del tipo Variant de cada fila. [#59398](https://github.com/ClickHouse/ClickHouse/pull/59398) ([Kruglov Pavel](https://github.com/Avogar)).
* Se añadió la consulta `ALTER TABLE table FORGET PARTITION partition`, que elimina nodos de ZooKeeper relacionados con una partición vacía. [#59507](https://github.com/ClickHouse/ClickHouse/pull/59507) ([Sergei Trifonov](https://github.com/serxa)).
* Se añadió compatibilidad con archivos de credentials JWT para el motor de tabla NATS. [#59543](https://github.com/ClickHouse/ClickHouse/pull/59543) ([Nickolaj Jepsen](https://github.com/nickolaj-jepsen)).
* Se incorpora la nueva función de agregación `groupArrayIntersect`. Continuación de: [#49862](https://github.com/ClickHouse/ClickHouse/issues/49862). [#59598](https://github.com/ClickHouse/ClickHouse/pull/59598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se implementó la tabla system.dns&#95;cache, que puede ser útil para depurar problemas de DNS. [#59856](https://github.com/ClickHouse/ClickHouse/pull/59856) ([Kirill Nikiforov](https://github.com/allmazz)).
* El códec `LZ4HC` aceptará un nuevo nivel 2, que es más rápido que el anterior nivel mínimo 3, a costa de una menor compresión. En versiones anteriores, `LZ4HC(2)` y valores inferiores eran equivalentes a `LZ4HC(3)`. Autor: [Cyan4973](https://github.com/Cyan4973). [#60090](https://github.com/ClickHouse/ClickHouse/pull/60090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se implementó la tabla system.dns&#95;cache, que puede ser útil para depurar problemas de DNS. Nueva configuración del servidor dns&#95;cache&#95;max&#95;size. [#60257](https://github.com/ClickHouse/ClickHouse/pull/60257) ([Kirill Nikiforov](https://github.com/allmazz)).
* Se añadió compatibilidad con la versión de un solo argumento de la función de tabla merge, como `merge(['db_name', ] 'tables_regexp')`. [#60372](https://github.com/ClickHouse/ClickHouse/pull/60372) ([豪肥肥](https://github.com/HowePa)).
* Se añadió una nueva sintaxis que permite especificar el usuario definidor en View/vista materializada. Esto permite ejecutar selects/inserts desde vistas sin grants explícitos sobre las tablas subyacentes. [#60439](https://github.com/ClickHouse/ClickHouse/pull/60439) ([pufit](https://github.com/pufit)).



<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Elimina los agregadores min/max/any/anyLast de las claves de GROUP BY en la sección SELECT. [#52230](https://github.com/ClickHouse/ClickHouse/pull/52230) ([JackyWoo](https://github.com/JackyWoo)).
* Funciones de distancia vectorizadas usadas en la búsqueda vectorial. [#58866](https://github.com/ClickHouse/ClickHouse/pull/58866) ([Robert Schulze](https://github.com/rschu1ze)).
* Continúa optimizando los fallos de predicción de rama de la función if cuando el tipo de resultado es float*/decimal*/int*, como continuación de https://github.com/ClickHouse/ClickHouse/pull/57885. [#59148](https://github.com/ClickHouse/ClickHouse/pull/59148) ([李扬](https://github.com/taiyang-li)).
* Optimiza la función if cuando el tipo de entrada es Map, con una aceleración de ~10x. [#59413](https://github.com/ClickHouse/ClickHouse/pull/59413) ([李扬](https://github.com/taiyang-li)).
* Mejora el rendimiento del tipo Int8 mediante la implementación de aliasing estricto. [#59485](https://github.com/ClickHouse/ClickHouse/pull/59485) ([Raúl Marín](https://github.com/Algunenano)).
* Optimiza condicionalmente el rendimiento de sum/avg para tipos bigint y decimal grandes reduciendo los fallos de predicción de rama. [#59504](https://github.com/ClickHouse/ClickHouse/pull/59504) ([李扬](https://github.com/taiyang-li)).
* Mejora el rendimiento de las consultas SELECT con mutaciones activas. [#59531](https://github.com/ClickHouse/ClickHouse/pull/59531) ([Azat Khuzhin](https://github.com/azat)).
* Optimiza la función `isNotNull` con AVX2. [#59621](https://github.com/ClickHouse/ClickHouse/pull/59621) ([李扬](https://github.com/taiyang-li)).
* Reutiliza el resultado de `FunctionFactory::instance().get("isNotNull", context)` y `FunctionFactory::instance().get("assumeNotNull", context)`. Garantiza que se llame una sola vez durante el ciclo de vida de `FunctionCoalesce`. [#59627](https://github.com/ClickHouse/ClickHouse/pull/59627) ([李扬](https://github.com/taiyang-li)).
* Mejora el rendimiento de ASOF JOIN para datos ordenados o casi ordenados. [#59731](https://github.com/ClickHouse/ClickHouse/pull/59731) ([Maksim Kita](https://github.com/kitaisreal)).
* La clave primaria usará menos memoria. [#60049](https://github.com/ClickHouse/ClickHouse/pull/60049) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el uso de memoria de la clave primaria y de algunas otras operaciones. [#60050](https://github.com/ClickHouse/ClickHouse/pull/60050) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Las claves primarias de las tablas se cargarán en memoria de forma diferida en el primer acceso. Esto se controla mediante el nuevo SETTING de MergeTree `primary_key_lazy_load`, que está activado de forma predeterminada. Esto ofrece varias ventajas: - no se cargará para las tablas que no se usen; - si no hay suficiente memoria, se lanzará una excepción en el primer uso en lugar de al iniciar el server. Esto también presenta varias desventajas: - la latencia de cargar la clave primaria se pagará en la primera consulta en lugar de antes de aceptar conexiones; esto, en teoría, puede introducir un problema de thundering herd. Esto cierra [#11188](https://github.com/ClickHouse/ClickHouse/issues/11188). [#60093](https://github.com/ClickHouse/ClickHouse/pull/60093) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Función vectorizada `dotProduct`, útil para la búsqueda vectorial. [#60202](https://github.com/ClickHouse/ClickHouse/pull/60202) ([Robert Schulze](https://github.com/rschu1ze)).

* Se añadió compatibilidad con las vistas parametrizadas en el analyzer para evitar analizar `create parameterized view`. También se refactorizó la lógica existente de vistas parametrizadas para evitar analizar `create parameterized view`. [#54211](https://github.com/ClickHouse/ClickHouse/pull/54211) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* No se considera una data part como dañada si una proyección está dañada. Cierra [#56593](https://github.com/ClickHouse/ClickHouse/issues/56593). [#56864](https://github.com/ClickHouse/ClickHouse/pull/56864) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se añadió compatibilidad con la evaluación de cortocircuito para la función `dictGetOrDefault`. Cierra [#52098](https://github.com/ClickHouse/ClickHouse/issues/52098). [#57767](https://github.com/ClickHouse/ClickHouse/pull/57767) ([jsc0218](https://github.com/jsc0218)).
* Al ejecutar `ALTER COLUMN MATERIALIZE` en una columna con una expresión `DEFAULT` o `MATERIALIZED`, ahora se escriben los valores correctos: el valor predeterminado para las partes existentes con valor predeterminado, o el valor no predeterminado para las partes existentes con valor no predeterminado. Anteriormente, se escribía el valor predeterminado en todas las partes existentes. [#58023](https://github.com/ClickHouse/ClickHouse/pull/58023) ([Duc Canh Le](https://github.com/canhld94)).
* Se habilitó una lógica de backoff (por ejemplo, exponencial). Esto permitirá reducir el uso de CPU, el uso de memoria y el tamaño de los archivos de registro. [#58036](https://github.com/ClickHouse/ClickHouse/pull/58036) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Se añadió una mejora para contabilizar InitialQuery. [#58195](https://github.com/ClickHouse/ClickHouse/pull/58195) ([Unalian](https://github.com/Unalian)).
* Se añadió compatibilidad con argumentos posicionales negativos. Cierra [#57736](https://github.com/ClickHouse/ClickHouse/issues/57736). [#58292](https://github.com/ClickHouse/ClickHouse/pull/58292) ([flynn](https://github.com/ucasfl)).
* Se implementó el ajuste automático de los timeouts de insert asíncrono. Se introducen las siguientes configuraciones: async&#95;insert&#95;poll&#95;timeout&#95;ms, async&#95;insert&#95;use&#95;adaptive&#95;busy&#95;timeout, async&#95;insert&#95;busy&#95;timeout&#95;min&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;max&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;increase&#95;rate, async&#95;insert&#95;busy&#95;timeout&#95;decrease&#95;rate. [#58486](https://github.com/ClickHouse/ClickHouse/pull/58486) ([Julia Kartseva](https://github.com/jkartseva)).
* Ahora se permite definir `volume_priority` en `storage_configuration`. [#58533](https://github.com/ClickHouse/ClickHouse/pull/58533) ([Andrey Zvonov](https://github.com/zvonand)).
* Se añadió compatibilidad con el tipo Date32 en el códec T64. [#58738](https://github.com/ClickHouse/ClickHouse/pull/58738) ([Hongbin Ma (Mahone)](https://github.com/binmahone)).
* Se añadió compatibilidad con `LEFT JOIN`, `ALL INNER JOIN` y subconsultas simples para las réplicas paralelas (solo con el analyzer). La nueva configuración `parallel_replicas_prefer_local_join` elige la ejecución local de `JOIN` (de forma predeterminada) frente a `GLOBAL JOIN`. Todas las tablas deben existir en cada réplica de `cluster_for_parallel_replicas`. Las nuevas configuraciones `min_external_table_block_size_rows` y `min_external_table_block_size_bytes` se usan para compactar bloques pequeños que se envían a las tablas temporales (solo con el analyzer). [#58916](https://github.com/ClickHouse/ClickHouse/pull/58916) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Ahora se permiten comas finales en tipos con varios elementos. [#59119](https://github.com/ClickHouse/ClickHouse/pull/59119) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Se permite el procesamiento paralelo y distribuido para el table engine `S3Queue`. Para el procesamiento distribuido, use la setting `s3queue_total_shards_num` (por defecto, `1`). Anteriormente, la setting `s3queue_processing_threads_num` no se permitía en el Ordered mode; ahora sí. Advertencia: las settings `s3queue_processing_threads_num` (threads de procesamiento por cada shard) y `s3queue_total_shards_num` para Ordered mode cambian la forma en que se almacenan los metadatos (hacen que el número de nodos `max_processed_file` sea igual a `s3queue_processing_threads_num * s3queue_total_shards_num`), por lo que deben ser iguales en todos los shards y no pueden cambiarse una vez creado al menos un shard. [#59167](https://github.com/ClickHouse/ClickHouse/pull/59167) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se permite la creación concurrente de tablas en `DatabaseReplicated` durante `recoverLostReplica`. [#59277](https://github.com/ClickHouse/ClickHouse/pull/59277) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Las settings del table engine Distributed ahora pueden especificarse en el archivo de configuración del servidor (de forma similar a las settings de MergeTree), por ejemplo, `<distributed> <flush_on_detach>false</flush_on_detach> </distributed>`. [#59291](https://github.com/ClickHouse/ClickHouse/pull/59291) ([Azat Khuzhin](https://github.com/azat)).
* Se usa MergeTree como table engine predeterminado. Esto mejora considerablemente la usabilidad y lo acerca más a ClickHouse Cloud. [#59316](https://github.com/ClickHouse/ClickHouse/pull/59316) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se reintentan las desconexiones y las sessions expiradas al leer `system.zookeeper`. Esto resulta útil al leer muchas filas de la tabla `system.zookeeper`, especialmente cuando hay desconexiones inducidas por fallos. [#59388](https://github.com/ClickHouse/ClickHouse/pull/59388) ([Alexander Gololobov](https://github.com/davenger)).
* No se interpretan como octales los números con ceros a la izquierda cuando `input_format_values_interpret_expressions=0`. [#59403](https://github.com/ClickHouse/ClickHouse/pull/59403) ([Joanna Hulboj](https://github.com/jh0x)).
* Al iniciarse y cada vez que cambian los archivos de configuración, ClickHouse actualiza los hard memory limits de su memory tracker total. Estos límites se calculan en función de varias server settings y de los límites de cgroups (en Linux). Anteriormente, `/sys/fs/cgroup/memory.max` (para cgroups v2) estaba codificado de forma fija. Como resultado, se ignoraban los límites de memoria de cgroup v2 configurados para grupos anidados (jerarquías), por ejemplo, `/sys/fs/cgroup/my/nested/group/memory.max`. Esto ya se corrigió. El comportamiento de los límites de memoria de v1 no cambia. [#59435](https://github.com/ClickHouse/ClickHouse/pull/59435) ([Robert Schulze](https://github.com/rschu1ze)).
* Se agregaron nuevos profile events para observar el tiempo invertido en calcular PK/projections/secondary indices durante los `INSERT`. [#59436](https://github.com/ClickHouse/ClickHouse/pull/59436) ([Nikita Taranov](https://github.com/nickitat)).
* Se permite definir, al momento de la creación, un punto de inicio para S3Queue con Ordered mode mediante la setting `s3queue_last_processed_path`. [#59446](https://github.com/ClickHouse/ClickHouse/pull/59446) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Mejora en Keeper: almacenar en caché en memoria solo una cantidad determinada de logs, controlada por `latest_logs_cache_size_threshold` y `commit_logs_cache_size_threshold`. [#59460](https://github.com/ClickHouse/ClickHouse/pull/59460) ([Antonio Andelic](https://github.com/antonio2368)).
* Los comments de las system tables ahora también están disponibles en `system.tables` en `clickhouse-local`. [#59493](https://github.com/ClickHouse/ClickHouse/pull/59493) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* No se infieren floats en notación exponencial de forma predeterminada. Se agrega la setting `input_format_try_infer_exponent_floats`, que restaura el comportamiento anterior (deshabilitada por defecto). Cierra [#59476](https://github.com/ClickHouse/ClickHouse/issues/59476). [#59500](https://github.com/ClickHouse/ClickHouse/pull/59500) ([Kruglov Pavel](https://github.com/Avogar)).
* Permitir que las operaciones ALTER estén entre paréntesis. La inclusión de paréntesis puede controlarse con la configuración `format_alter_operations_with_parentheses`. De forma predeterminada, en las consultas formateadas se incluyen los paréntesis, ya que almacenamos las operaciones ALTER formateadas en algunos lugares como metadatos (por ejemplo, mutations). La nueva sintaxis aclara algunas consultas en las que las operaciones ALTER terminan en una lista. Por ejemplo, `ALTER TABLE x MODIFY TTL date GROUP BY a, b, DROP COLUMN c` no puede analizarse correctamente con la sintaxis anterior. Con la nueva sintaxis, la consulta `ALTER TABLE x (MODIFY TTL date GROUP BY a, b), (DROP COLUMN c)` resulta inequívoca. Las versiones anteriores no pueden leer la nueva sintaxis; por lo tanto, usarla podría causar problemas si se mezclan versiones nuevas y antiguas de ClickHouse en un mismo clúster. [#59532](https://github.com/ClickHouse/ClickHouse/pull/59532) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* El valor predeterminado anterior de `async_insert_max_data_size`, de 1 MB, resultó ser demasiado pequeño. El nuevo valor será de 10 MiB. [#59536](https://github.com/ClickHouse/ClickHouse/pull/59536) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Anteriormente, todo el resultado se acumulaba en memoria y se devolvía como un único fragmento grande. Este cambio debería ayudar a reducir el consumo de memoria al leer muchas filas de `system.zookeeper`, permitir mostrar el progreso intermedio (cuántas filas se han leído hasta el momento) y evitar alcanzar el tiempo de espera de la conexión cuando el conjunto de resultados es grande. [#59545](https://github.com/ClickHouse/ClickHouse/pull/59545) ([Alexander Gololobov](https://github.com/davenger)).

Continuación de [#59124](https://github.com/ClickHouse/ClickHouse/issues/59124). [#59548](https://github.com/ClickHouse/ClickHouse/pull/59548) ([Amos Bird](https://github.com/amosbird)).
