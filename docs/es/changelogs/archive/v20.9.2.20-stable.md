<div id="clickhouse-release-v209220-stable-fixme-as-compared-to-v20814513-prestable">
  ### Lanzamiento de ClickHouse v20.9.2.20-stable FIXME en comparación con v20.8.1.4513-prestable
</div>

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se añade la función de tabla `view`, que convierte una subconsulta en un objeto de tabla. Esto facilita reutilizar consultas. Por ejemplo, puede usarse en funciones de tabla remotas/de clúster. [#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* Ahora se puede escribir `select * apply(length) apply(max) from wide_string_table` para averiguar la longitud máxima de todas las columnas String. También se proporcionan las dos variantes siguientes:. [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* Se añadió una función de agregación RankCorrelationSpearman que simplemente calcula un coeficiente de correlación de rangos. Continuación de [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769). [#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se añadió la generación de bases de datos mediante una utilidad de consulta. Continuación de [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973). [#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Optimización de las consultas con LIMIT/LIMIT BY/ORDER BY para Distributed con GROUP BY sharding&#95;key (con optimize&#95;skip&#95;unused&#95;shards y optimize&#95;distributed&#95;group&#95;by&#95;sharding&#95;key). [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Mejora
</div>

* Mejoras en StorageRabbitMQ: se añadió el manejo de fallos de conexión y de canales, commits correctos, manejo de fallos de inserción, mejores exchanges, durabilidad de la cola y posibilidad de reanudarla, además de nuevos ajustes de cola. Se corrigieron las pruebas. [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se añadió la autorización `requirepass` de Redis. [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* Se añadió el argumento precision para el tipo DateTime. [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* Se mejora el rendimiento del motor Kafka proporcionando un hilo independiente para cada consumer. Pool de hilos independiente para los motores de streaming (como Kafka). [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* Se añadió el códec de compresión predeterminado para las partes en `system.part_log` con el nombre `default_compression_codec`. [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* Se reemplazan los enteros de gran tamaño de boost multiprecision por la implementación de [https://github.com/cerevra/int](https://github.com/cerevra/int). [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* Se convierte implícitamente la clave primaria en no nula en MaterializeMySQL (igual que en MySQL). Corrige [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114). [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* Se añadió el nuevo ajuste system&#95;events&#95;show&#95;zero&#95;values, como se propuso en [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384). [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Ahora el ofuscador admite el tipo UUID, como se propuso en [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163). [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Creación de conjuntos para múltiples `JOIN` e `IN` en paralelo. Esto puede mejorar ligeramente el rendimiento de las consultas con varias expresiones `subquery IN` diferentes. [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Ahora los TTL se aplicarán durante la fusión si no se habían materializado previamente. [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* El handler de MySQL devuelve `OK` para consultas como `SET @@var = value`. Esa instrucción se ignora. Esto es necesario porque algunos drivers de MySQL envían una consulta `SET @@` para la configuración después del handshake [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422. [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* Ya no se permite un argumento time&#95;zone vacío en funciones del tipo `toStartOf*`. [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* Backport en [#14873](https://github.com/ClickHouse/ClickHouse/issues/14873): permitir el uso de multi-volume storage configuration en el almacenamiento Distributed. [#14839](https://github.com/ClickHouse/ClickHouse/pull/14839) ([Pavel Kovalenko](https://github.com/Jokser)).
