<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* No permitir establecer max&#95;parallel&#95;replicas en 0, ya que no tiene sentido. Establecerlo en 0 podría provocar errores lógicos inesperados. Cierra [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140). [#60430](https://github.com/ClickHouse/ClickHouse/pull/60430) ([Kruglov Pavel](https://github.com/Avogar)).
* Cambiar el nombre de la columna de `duration_ms` a `duration_microseconds` en la tabla `system.zookeeper` para reflejar que la duración tiene resolución de microsegundos. [#60774](https://github.com/ClickHouse/ClickHouse/pull/60774) ([Duc Canh Le](https://github.com/canhld94)).
* Rechazar las consultas INSERT entrantes cuando los ajustes a nivel de consulta `async_insert` y `deduplicate_blocks_in_dependent_materialized_views` estén habilitados al mismo tiempo. Este comportamiento está controlado por la configuración `throw_if_deduplication_in_dependent_materialized_views_enabled_with_async_insert` y está habilitado de forma predeterminada. Esto es una continuación de [https://github.com/ClickHouse/ClickHouse/pull/59699](https://github.com/ClickHouse/ClickHouse/pull/59699) necesaria para desbloquear [https://github.com/ClickHouse/ClickHouse/pull/59915](https://github.com/ClickHouse/ClickHouse/pull/59915). [#60888](https://github.com/ClickHouse/ClickHouse/pull/60888) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* La utilidad `clickhouse-copier` se ha movido a un repositorio independiente en GitHub: [https://github.com/ClickHouse/copier](https://github.com/ClickHouse/copier). Ya no está incluida en el paquete, pero sigue disponible como descarga independiente. Esto cierra: [#60734](https://github.com/ClickHouse/ClickHouse/issues/60734) Esto cierra: [#60540](https://github.com/ClickHouse/ClickHouse/issues/60540) Esto cierra: [#60250](https://github.com/ClickHouse/ClickHouse/issues/60250) Esto cierra: [#52917](https://github.com/ClickHouse/ClickHouse/issues/52917) Esto cierra: [#51140](https://github.com/ClickHouse/ClickHouse/issues/51140) Esto cierra: [#47517](https://github.com/ClickHouse/ClickHouse/issues/47517) Esto cierra: [#47189](https://github.com/ClickHouse/ClickHouse/issues/47189) Esto cierra: [#46598](https://github.com/ClickHouse/ClickHouse/issues/46598) Esto cierra: [#40257](https://github.com/ClickHouse/ClickHouse/issues/40257) Esto cierra: [#36504](https://github.com/ClickHouse/ClickHouse/issues/36504) Esto cierra: [#35485](https://github.com/ClickHouse/ClickHouse/issues/35485) Esto cierra: [#33702](https://github.com/ClickHouse/ClickHouse/issues/33702) Esto cierra: [#26702](https://github.com/ClickHouse/ClickHouse/issues/26702) ### Entrada de documentación para cambios de cara al usuario. [#61058](https://github.com/ClickHouse/ClickHouse/pull/61058) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Para aumentar la compatibilidad con MySQL, la función `locate` ahora acepta de forma predeterminada los argumentos `(needle, haystack[, start_pos])`. El comportamiento anterior `(haystack, needle, [, start_pos])` puede restaurarse estableciendo `function_locate_has_mysql_compatible_argument_order = 0`. [#61092](https://github.com/ClickHouse/ClickHouse/pull/61092) ([Robert Schulze](https://github.com/rschu1ze)).
* Las partes de datos en memoria obsoletas están deprecadas desde la versión 23.5 y dejaron de ser compatibles a partir de la versión 23.10. Ahora se elimina el código restante. Continuación de [#55186](https://github.com/ClickHouse/ClickHouse/issues/55186) y [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409). Es poco probable que haya utilizado partes de datos en memoria, porque solo estaban disponibles antes de la versión 23.5 y únicamente si las habilitaba manualmente especificando los SETTINGS correspondientes para una tabla MergeTree. Para comprobar si tiene partes de datos en memoria, ejecute la siguiente consulta: `SELECT part_type, count() FROM system.parts GROUP BY part_type ORDER BY part_type`. Para deshabilitar el uso de partes de datos en memoria, ejecute `ALTER TABLE ... MODIFY SETTING min_bytes_for_compact_part = DEFAULT, min_rows_for_compact_part = DEFAULT`. Antes de actualizar desde versiones anteriores de ClickHouse, compruebe primero que no tiene partes de datos en memoria. Si las hay, deshabilítelas primero, espere a que ya no quede ninguna y continúe con la actualización. [#61127](https://github.com/ClickHouse/ClickHouse/pull/61127) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se prohíbe `SimpleAggregateFunction` en `ORDER BY` de las tablas `MergeTree` de forma predeterminada (igual que `AggregateFunction`; ambas están prohibidas porque no son comparables). Use `allow_suspicious_primary_key` para permitirlas. [#61399](https://github.com/ClickHouse/ClickHouse/pull/61399) ([Azat Khuzhin](https://github.com/azat)).
* ClickHouse permite datos binarios arbitrarios en el tipo de datos String, que normalmente es UTF-8. Los tipos String de Parquet/ORC/Arrow solo admiten UTF-8. Por eso puede elegir qué tipo de datos de Arrow usar para el tipo de datos String de ClickHouse: String o Binary. Esto se controla con los ajustes `output_format_parquet_string_as_string`, `output_format_orc_string_as_string`, `output_format_arrow_string_as_string`. Aunque Binary sería más correcto y compatible, usar String de forma predeterminada se ajusta a las expectativas de los usuarios en la mayoría de los casos. Parquet/ORC/Arrow admite muchos métodos de compresión, incluidos lz4 y zstd. ClickHouse admite todos los métodos de compresión. Algunas herramientas de menor calidad no admiten el método de compresión `lz4`, que es más rápido, por eso establecemos `zstd` como valor predeterminado. Esto se controla con los ajustes `output_format_parquet_compression_method`, `output_format_orc_compression_method` y `output_format_arrow_compression_method`. Hemos cambiado el valor predeterminado a `zstd` para Parquet y ORC, pero no para Arrow (que se prioriza para usos de bajo nivel). [#61817](https://github.com/ClickHouse/ClickHouse/pull/61817) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* En la nueva versión de ClickHouse, las funciones `geoDistance`, `greatCircleDistance` y `greatCircleAngle` usarán el tipo de datos de coma flotante de doble precisión de 64 bits para los cálculos internos y como tipo de retorno si todos los argumentos son Float64. Esto cierra [#58476](https://github.com/ClickHouse/ClickHouse/issues/58476). En versiones anteriores, la función siempre usaba Float32. Puede volver al comportamiento anterior configurando `geo_distance_returns_float64_on_float64_arguments` en `false` o `compatibility` en `24.2` o una versión anterior. [#61848](https://github.com/ClickHouse/ClickHouse/pull/61848) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Mejora el rendimiento del método de agregación serializada cuando intervienen múltiples columnas [Nullable]. Esta es una versión general de [#51399](https://github.com/ClickHouse/ClickHouse/issues/51399) que no compromete la integridad de la abstracción. [#55809](https://github.com/ClickHouse/ClickHouse/pull/55809) ([Amos Bird](https://github.com/amosbird)).
* Generación diferida del resultado del join para mejorar el rendimiento de ALL join. [#58278](https://github.com/ClickHouse/ClickHouse/pull/58278) ([LiuNeng](https://github.com/liuneng1994)).
* Mejoras en las funciones de agregación ArgMin / ArgMax / any / anyLast / anyHeavy, así como en las consultas `ORDER BY {u8/u16/u32/u64/i8/i16/u32/i64) LIMIT 1`. [#58640](https://github.com/ClickHouse/ClickHouse/pull/58640) ([Raúl Marín](https://github.com/Algunenano)).
* Optimización trivial del filtro de columnas. Evita filtrar con `result_size_hint = -1` aquellas columnas de filtro cuyo tipo de dato subyacente no es numérico. El uso máximo de memoria puede reducirse al 44% del original en algunos casos. [#59698](https://github.com/ClickHouse/ClickHouse/pull/59698) ([李扬](https://github.com/taiyang-li)).
* Si la clave primaria de la tabla contiene mayormente columnas inútiles, no las mantenga en memoria. Esto se controla mediante una nueva configuración, `primary_key_ratio_of_unique_prefix_values_to_skip_suffix_columns`, con el valor predeterminado `0.9`, lo que significa que, para una clave primaria compuesta, si una columna cambia de valor al menos 0.9 de las veces, las columnas siguientes no se cargarán. [#60255](https://github.com/ClickHouse/ClickHouse/pull/60255) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ejecuta la función multiIf de forma columnar cuando el tipo subyacente de result&#95;type es numérico. [#60384](https://github.com/ClickHouse/ClickHouse/pull/60384) ([李扬](https://github.com/taiyang-li)).
* Mutexes más rápidos (casi 2x) (eran más lentos debido a ThreadFuzzer). [#60823](https://github.com/ClickHouse/ClickHouse/pull/60823) ([Azat Khuzhin](https://github.com/azat)).
* Mueve el drenaje de conexiones de prepare a work, y drena varias conexiones en paralelo. [#60845](https://github.com/ClickHouse/ClickHouse/pull/60845) ([lizhuoyu5](https://github.com/lzydmxy)).
* Optimiza insertManyFrom para Nullable number o Nullable string. [#60846](https://github.com/ClickHouse/ClickHouse/pull/60846) ([李扬](https://github.com/taiyang-li)).
* Se optimizó la función `dotProduct` para omitir copias de memoria innecesarias y costosas. [#60928](https://github.com/ClickHouse/ClickHouse/pull/60928) ([Robert Schulze](https://github.com/rschu1ze)).
* Las operaciones con la caché del sistema de archivos sufrirán menos por la contención de bloqueos. [#61066](https://github.com/ClickHouse/ClickHouse/pull/61066) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimiza ColumnString::replicate y evita que memcpySmallAllowReadWriteOverflow15Impl se optimice como la función integrada memcpy. Cierra [#61074](https://github.com/ClickHouse/ClickHouse/issues/61074). ColumnString::replicate acelera 2.46x en x86-64. [#61075](https://github.com/ClickHouse/ClickHouse/pull/61075) ([李扬](https://github.com/taiyang-li)).
* Impresión 30x más rápida para enteros de 256 bits. [#61100](https://github.com/ClickHouse/ClickHouse/pull/61100) ([Raúl Marín](https://github.com/Algunenano)).
* Si una consulta con un error de sintaxis contenía un matcher COLUMNS con una expresión regular, la expresión regular se compilaba cada vez durante el retroceso del analizador sintáctico, en lugar de compilarse una sola vez. Este era un error fundamental. La regexp compilada se almacenaba en el AST. Pero la letra A de AST significa &quot;abstract&quot;, lo que implica que no debe contener objetos pesados. Las partes del AST pueden crearse y descartarse durante el parsing, incluidos numerosos retrocesos. Esto provoca lentitud durante el parsing y, en consecuencia, permite ataques DoS por parte de un usuario readonly. Pero el problema principal es que impide avanzar con los fuzzers. [#61543](https://github.com/ClickHouse/ClickHouse/pull/61543) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añadir una nueva pasada del analyzer para optimizar IN con un único valor. [#61564](https://github.com/ClickHouse/ClickHouse/pull/61564) ([LiuNeng](https://github.com/liuneng1994)).
