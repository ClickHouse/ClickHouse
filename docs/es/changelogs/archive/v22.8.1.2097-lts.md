<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se hizo la caché componible, permitiendo que ciertos archivos (relacionados con idx, mrk, etc.) no se expulsen, y se eliminó la versión antigua de la caché. Ahora es posible configurar la caché sobre un disco de Azure blob storage, sobre un disco local, sobre un disco StaticWeb, etc. Esta PR está marcada como incompatible con versiones anteriores porque cambia la configuración de la caché y, para que funcione, es necesario actualizar el archivo de configuración. La caché antigua seguirá utilizándose con la nueva configuración. El servidor arrancará correctamente con la configuración antigua de la caché. Cierra [#36140](https://github.com/ClickHouse/ClickHouse/issues/36140). Cierra [#37889](https://github.com/ClickHouse/ClickHouse/issues/37889). [#36171](https://github.com/ClickHouse/ClickHouse/pull/36171) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Ahora, todos los dictionary sources relevantes respetan la configuración `remote_url_allow_hosts`. Esto ya se había hecho para HTTP, Cassandra y Redis. Se añadieron ClickHouse, MongoDB, MySQL y PostgreSQL. El host se comprueba solo para los diccionarios creados mediante DDL. [#39184](https://github.com/ClickHouse/ClickHouse/pull/39184) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Se amplió el rango de Date32 y DateTime64 para admitir fechas desde el año 1900 hasta 2299. En versiones anteriores, el intervalo admitido abarcaba solo desde 1925 hasta 2283. La implementación usa el calendario gregoriano proléptico (conforme con [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601):2004 (cláusula 3.2.1, el calendario gregoriano)) en lugar de tener en cuenta las transiciones históricas del calendario juliano al gregoriano. Este cambio afecta al comportamiento específico de la implementación para argumentos fuera de rango. Por ejemplo, si en versiones anteriores el valor `1899-01-01` se ajustaba a `1925-01-01`, en la nueva versión se ajustará a `1900-01-01`. También cambia el comportamiento del redondeo con `toStartOfInterval` si se pasa `INTERVAL 3 QUARTER` a un trimestre, porque los intervalos se cuentan desde un punto temporal específico de la implementación. Cierra [#28216](https://github.com/ClickHouse/ClickHouse/issues/28216), mejora [#38393](https://github.com/ClickHouse/ClickHouse/issues/38393). [#39425](https://github.com/ClickHouse/ClickHouse/pull/39425) ([Roman Vasin](https://github.com/rvasin)).

* Se añadió un ajuste `exact_rows_before_limit` (0/1). Cuando está habilitado, ClickHouse proporcionará el valor exacto de la estadística `rows_before_limit_at_least`, pero a costa de tener que leer por completo los datos previos al límite. Esto cierra [#6613](https://github.com/ClickHouse/ClickHouse/issues/6613). [#25333](https://github.com/ClickHouse/ClickHouse/pull/25333) ([kevin wan](https://github.com/MaxWk)).

* Intel® In-Memory Analytics Accelerator (Intel® IAA) es un acelerador de hardware disponible en la próxima generación de procesadores Intel® Xeon® Scalable (&quot;Sapphire Rapids&quot;). Su objetivo es acelerar operaciones habituales de analítica, como la (des)compresión de datos y el filtrado. ClickHouse incorporó el nuevo códec de compresión &quot;DeflateQpl&quot;, que utiliza la tecnología de descarga de Intel® IAA para ofrecer una implementación DEFLATE de alto rendimiento. El códec utiliza la [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl), que abstrae el acceso al acelerador de hardware o, en su defecto, a una alternativa por software cuando el acelerador no está disponible. En general, DEFLATE ofrece mayores tasas de compresión que el códec LZ4 predeterminado de ClickHouse y, como resultado, reduce la E/S de disco y el consumo de memoria principal. [#36654](https://github.com/ClickHouse/ClickHouse/pull/36654) ([jasperzhu](https://github.com/jinjunzh)).
* Se añadió el parámetro concurrent&#95;threads&#95;soft&#95;limit para aumentar el rendimiento en caso de RPS alto, limitando el número total de hilos para todas las consultas. [#37285](https://github.com/ClickHouse/ClickHouse/pull/37285) ([Roman Vasin](https://github.com/rvasin)).
* Se añadió lógica de control de concurrencia para limitar el número total de hilos concurrentes creados por las consultas. [#37558](https://github.com/ClickHouse/ClickHouse/pull/37558) ([Sergei Trifonov](https://github.com/serxa)).
* Se añadió compatibilidad con `insert select` distribuido en paralelo en tablas con motores Distributed y Replicated [#34670](https://github.com/ClickHouse/ClickHouse/issues/34670). [#39107](https://github.com/ClickHouse/ClickHouse/pull/39107) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se añadieron nuevos ajustes para controlar la inferencia de esquema a partir de formatos de texto: - `input_format_try_infer_dates` - intenta inferir fechas a partir de cadenas. - `input_format_try_infer_datetimes` - intenta inferir DateTimes a partir de cadenas. - `input_format_try_infer_integers` - intenta inferir `Int64` en lugar de `Float64`. - `input_format_json_try_infer_numbers_from_strings` - intenta inferir números a partir de cadenas JSON en formatos JSON. [#39186](https://github.com/ClickHouse/ClickHouse/pull/39186) ([Kruglov Pavel](https://github.com/Avogar)).
* Esta funcionalidad proporcionará salida de logs con formato JSON en la consola. Su propósito es facilitar la ingestión y la consulta en herramientas de análisis de logs. [#39277](https://github.com/ClickHouse/ClickHouse/pull/39277) ([Mallik Hassan](https://github.com/SadiHassan)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* * La interrupción durante el análisis se atascaba en consultas complejas. [#38185](https://github.com/ClickHouse/ClickHouse/pull/38185) ([Vladimir C](https://github.com/vdimir)).
* Deducir cómo ordenar a partir de la descripción de ordenación del flujo de entrada. Omitir la ordenación si el flujo de entrada ya está ordenado. [#38719](https://github.com/ClickHouse/ClickHouse/pull/38719) ([Igor Nikonov](https://github.com/devcrafter)).
* `DISTINCT` junto con `ORDER BY` mejora (significativamente) el uso de memoria y el tiempo de ejecución de la consulta si las columnas de `DISTINCT` coinciden con las columnas de `ORDER BY` (o forman un prefijo de ellas). [#39432](https://github.com/ClickHouse/ClickHouse/pull/39432) ([Igor Nikonov](https://github.com/devcrafter)).
* Usar el nodo local como primera prioridad para obtener la estructura de la tabla remota al ejecutar `cluster` y funciones de tabla similares. [#39440](https://github.com/ClickHouse/ClickHouse/pull/39440) ([Mingliang Pan](https://github.com/liangliangpan)).
* Usar `DistinctSortedTransform` solo cuando la descripción de ordenación sea aplicable a las columnas de `DISTINCT`; en caso contrario, recurrir a la implementación habitual de `DISTINCT`. Esto permite realizar menos comprobaciones durante la ejecución de `DistinctSortedTransform`. [#39528](https://github.com/ClickHouse/ClickHouse/pull/39528) ([Igor Nikonov](https://github.com/devcrafter)).
* `DistinctSortedTransform` no aprovechaba la ordenación; es decir, funcionaba como una implementación habitual de `DISTINCT`. La corrección reduce significativamente el uso de memoria. [#39538](https://github.com/ClickHouse/ClickHouse/pull/39538) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector: optimizar el filtro con compress store de AVX512VBMI2. [#39633](https://github.com/ClickHouse/ClickHouse/pull/39633) ([Guo Wangyang](https://github.com/guowangy)).
* KeyCondition: optimizar applyFunction en escenarios multihilo. [#39812](https://github.com/ClickHouse/ClickHouse/pull/39812) ([Guo Wangyang](https://github.com/guowangy)).
* Para sistemas con AVX512 VBMI2, este PR mejora el rendimiento en aprox. un 6 % para las consultas 3.1, 3.2 y 3.3 del benchmark SSB (SF=100). Probado en un Intel Icelake Xeon 8380 de 2 sockets. [#40033](https://github.com/ClickHouse/ClickHouse/pull/40033) ([Robert Schulze](https://github.com/rschu1ze)).
* * No recorrer el AST para UDFs si no hay ninguna registrada. [#40069](https://github.com/ClickHouse/ClickHouse/pull/40069) ([Raúl Marín](https://github.com/Algunenano)).
* * Optimizar alloc y free de CurrentMemoryTracker. [#40078](https://github.com/ClickHouse/ClickHouse/pull/40078) ([Raúl Marín](https://github.com/Algunenano)).
