<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se introduce el tipo `Geometry`. Se admite la lectura de los formatos `WKB` y `WKT` para este tipo. En versiones anteriores, el tipo `Geometry` era un alias de `String`, pero ahora es un tipo con todas las funcionalidades. [#83344](https://github.com/ClickHouse/ClickHouse/pull/83344) ([scanhex12](https://github.com/scanhex12)).
* Se elimina el tipo Object obsoleto. [#85718](https://github.com/ClickHouse/ClickHouse/pull/85718) ([Pavel Kruglov](https://github.com/Avogar)).
* Se escapan los nombres de archivo creados para las subcolumnas del tipo Variant en Wide data part de las tablas MergeTree. Este cambio rompe la compatibilidad con tablas antiguas con tipos de datos Variant/Dynamic/JSON. Corrige el almacenamiento de tipos con símbolos especiales dentro de Variant (como DateTime con una timezone específica que contiene `\`). El escaping puede deshabilitarse cambiando la configuración de MergeTree `escape_variant_subcolumn_filenames` (para mantener la compatibilidad, deshabilite esta configuración en la configuración de MergeTree o establezca la configuración `compatibility` en la versión anterior antes de la actualización). Resuelve [#69590](https://github.com/ClickHouse/ClickHouse/issues/69590). [#87300](https://github.com/ClickHouse/ClickHouse/pull/87300) ([Pavel Kruglov](https://github.com/Avogar)).
* Se elimina la funcionalidad obsoleta `LIVE VIEW`. Si usa `LIVE VIEW`, no será posible actualizar a la nueva versión. [#88706](https://github.com/ClickHouse/ClickHouse/pull/88706) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se admite el etiquetado de excepciones en la respuesta de resultados HTTP para que los client puedan analizar las excepciones de forma más fiable. Resuelve [#75175](https://github.com/ClickHouse/ClickHouse/issues/75175). La configuración `http_write_exception_in_output_format` está deshabilitada de forma predeterminada para mantener la coherencia entre formatos. [#88818](https://github.com/ClickHouse/ClickHouse/pull/88818) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* Se prohíbe la creación de varios discos `plain-rewritable` sobre la ruta compartida de object storage, ya que esto puede provocar un comportamiento undefined durante colisiones entre distintas transactions de metadata storage. [#89038](https://github.com/ClickHouse/ClickHouse/pull/89038) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Se habilita de forma predeterminada el formato de serialization with&#95;size&#95;stream para el tipo de datos String. Este cambio es compatible con versiones anteriores, pero el nuevo formato de serialization solo es compatible a partir de la versión 25.10, lo que significa que no será posible volver a versiones anteriores a la 25.10. Si quiere mantener la posibilidad de volver a la versión 25.9 y anteriores, configure serialization&#95;info&#95;version como basic y string&#95;serialization&#95;version como single&#95;stream en la sección merge&#95;tree de la server configuration. [#89329](https://github.com/ClickHouse/ClickHouse/pull/89329) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se corrige la precedencia de la configuración SASL de Kafka storage. La configuración SASL a nivel de tabla especificada en las consultas CREATE TABLE ahora sobrescribe correctamente la configuración específica de consumer/producer de los configuration files. [#89401](https://github.com/ClickHouse/ClickHouse/pull/89401) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Se corrige `Fatal` al comprimir datos con un tamaño no alineado con el tamaño del elemento (en el códec T64). Resuelve [#89282](https://github.com/ClickHouse/ClickHouse/issues/89282). [#89432](https://github.com/ClickHouse/ClickHouse/pull/89432) ([yanglongwei](https://github.com/ylw510)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Los RIGHT y FULL JOINs ahora usan ConcurrentHashJoin; eso significa que estos tipos de JOIN ahora se ejecutan con un mayor grado de paralelismo. Mejora varios casos de RIGHT y FULL JOINs hasta 2 veces. Resuelve [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027). [#78462](https://github.com/ClickHouse/ClickHouse/pull/78462) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Optimización para valores grandes en ConstantNode. Cierra [#72880](https://github.com/ClickHouse/ClickHouse/issues/72880). [#81104](https://github.com/ClickHouse/ClickHouse/pull/81104) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Consultas `SELECT` hasta 8 veces más rápidas con un pruning de particiones intensivo en tablas con más de 10K partes. [#85535](https://github.com/ClickHouse/ClickHouse/pull/85535) ([James Morrison](https://github.com/jawm)).
* Se corrigió vsdo para aarch64 y posiblemente para otras combinaciones de arquitectura/kernel. [#86096](https://github.com/ClickHouse/ClickHouse/pull/86096) ([Tomas Hulata](https://github.com/tombokombo)).
* Cuando una consulta usa un mapa hash fijo para el aggregation state (GROUP BY sobre un entero pequeño), ClickHouse fusiona el aggregation state en paralelo para acelerar la consulta. Resuelve [#63666](https://github.com/ClickHouse/ClickHouse/issues/63666). [#87366](https://github.com/ClickHouse/ClickHouse/pull/87366) ([Jianfei Hu](https://github.com/incfly)).
* Ejecución Distributed: mejor división de tareas por IDs de row groups, no por archivos. [#87508](https://github.com/ClickHouse/ClickHouse/pull/87508) ([scanhex12](https://github.com/scanhex12)).
* Mejora la velocidad de descompresión de LZ4 simplificando el código y ajustando el [algoritmo de selección](https://clickhouse.com/blog/lz4-compression-in-clickhouse#how-to-choose-the-best-algorithm). [#88360](https://github.com/ClickHouse/ClickHouse/pull/88360) ([Raúl Marín](https://github.com/Algunenano)).
* S3 particiona internamente los objetos según los prefijos del nombre de la clave y escala automáticamente a tasas altas de solicitudes por partición. Este cambio introduce dos nuevas configuraciones de BACKUP: data&#95;file&#95;name&#95;generator y data&#95;file&#95;name&#95;prefix&#95;length. Cuando data&#95;file&#95;name&#95;generator=checksum, los data files del backup se nombran usando un hash de su contenido. Example: para una suma de comprobación = `abcd1234ef567890abcd1234ef567890` y `data_file_name_prefix_length = 3`, la ruta resultante será: `abc/d1234ef567890abcd1234ef567890`. La distribución resultante de claves mejora el balanceo de carga entre las particiones de S3 y reduce el riesgo de throttling. [#88418](https://github.com/ClickHouse/ClickHouse/pull/88418) ([Julia Kartseva](https://github.com/jkartseva)).
* Implementa replicación diferida de columnas en JOIN y ARRAY JOIN. Evita convertir representaciones especiales de columnas, como Sparse y Replicated, en columnas completas en algunos output formats. Esto evita copias de datos innecesarias en memoria. [#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar)).
* Se mejoró el rendimiento del text index almacenando en caché bloques de diccionario y usando tablas hash para lookups de tokens en lugar de binary search. [#88786](https://github.com/ClickHouse/ClickHouse/pull/88786) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Parquet reader v3 está habilitado de forma predeterminada. [#88827](https://github.com/ClickHouse/ClickHouse/pull/88827) ([Michael Kolupaev](https://github.com/al13n321)).
* Las consultas ahora pueden beneficiarse simultáneamente de optimize&#95;read&#95;in&#95;order y query&#95;plan&#95;optimize&#95;lazy&#95;materialization. Resuelve [#88767](https://github.com/ClickHouse/ClickHouse/issues/88767). [#88866](https://github.com/ClickHouse/ClickHouse/pull/88866) ([Manuel](https://github.com/raimannma)).
* Usar proyección de agregación para consultas con `DISTINCT`. Cierra [#86925](https://github.com/ClickHouse/ClickHouse/issues/86925). [#88894](https://github.com/ClickHouse/ClickHouse/pull/88894) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Dado que las posting lists son las que más ocupan en términos de tamaño de datos, almacenarlas en caché mejoraría el rendimiento en ejecuciones consecutivas. [#88912](https://github.com/ClickHouse/ClickHouse/pull/88912) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Ejecutar la transformación LIMIT BY en streaming cuando el orden de ordenación de la entrada coincida con las claves de LIMIT BY. [#88969](https://github.com/ClickHouse/ClickHouse/pull/88969) ([Eduard Karacharov](https://github.com/korowa)).
* Deshabilitar ThreadFuzzer de forma predeterminada en los binarios que no son del servidor. [#89115](https://github.com/ClickHouse/ClickHouse/pull/89115) ([Raúl Marín](https://github.com/Algunenano)).
* Permitir reescribir ANY LEFT JOIN o ANY RIGHT JOIN como ALL INNER JOIN en algunos casos. [#89403](https://github.com/ClickHouse/ClickHouse/pull/89403) ([Dmitry Novik](https://github.com/novikd)).
* Menos operaciones atómicas por entrada durante el logging asíncrono. [#89651](https://github.com/ClickHouse/ClickHouse/pull/89651) ([Sergei Trifonov](https://github.com/serxa)).
* Cuando los Runtime Filters están habilitados en una consulta con varios joins y se añaden varios Runtime Filters, es necesario aplicar pushdown a los pasos de filtro recién añadidos por encima de otros BuildRuntimeFilterStep. [#89725](https://github.com/ClickHouse/ClickHouse/pull/89725) ([Alexander Gololobov](https://github.com/davenger)).
* Acelerar ligeramente algunas operaciones de countDistinct al reducir la sobrecarga de HashSetTable::merge. [#89727](https://github.com/ClickHouse/ClickHouse/pull/89727) ([Raúl Marín](https://github.com/Algunenano)).
* Los RIGHT y FULL JOIN ahora usan ConcurrentHashJoin; eso significa que estos tipos de join ahora se ejecutan con un mayor grado de paralelismo. Mejora varios casos de RIGHT y FULL JOIN hasta 2 veces. Resuelve [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027). [#89737](https://github.com/ClickHouse/ClickHouse/pull/89737) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

Esto hará que el archivo de estadísticas sea incompatible. La corrección consiste en añadir un indicador para registrar si se trata de una columna Nullable durante la serialización.
