<div id="clickhouse-release-v2651882-stable-5b96a8d8a5e-fixme-as-compared-to-v26511-new-a7b13e00eb1">
  ### Lanzamiento de ClickHouse v26.5.1.882-stable (5b96a8d8a5e) FIXME en comparación con v26.5.1.1-new (a7b13e00eb1)
</div>

<div id="backward-incompatible-change">
  #### Cambio Incompatible con Versiones Anteriores
</div>

* Se cambiaron los valores predeterminados de `date_time_input_format` y `cast_string_to_date_time_mode` de `basic` a `best_effort`. Las consultas que antes no podían interpretar cadenas de fecha y hora no básicas (p. ej., `2024 April 4`, `Apr 15, 2020 10:30:00`) ahora pueden ejecutarse correctamente de forma predeterminada. Para mantener el comportamiento anterior de análisis estricto, establezca estos ajustes en `basic` (o use `compatibility`). [#89334](https://github.com/ClickHouse/ClickHouse/pull/89334) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Este cambio se revirtió. [#90043](https://github.com/ClickHouse/ClickHouse/pull/90043) ([Raúl Marín](https://github.com/Algunenano)).
* El nombre del elemento de Tuple `null` ahora está prohibido porque entra en conflicto con el nombre de subcolumna usado para los mapas de nulos de Nullable, lo que provoca una resolución ambigua de subcolumnas. [#98377](https://github.com/ClickHouse/ClickHouse/pull/98377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se agregó un ajuste `dynamic_disk_allow_from_env`, `dynamic_disk_allow_from_zk`, `dynamic_disk_allow_include` para impedir el uso de `from_env`, `from_zk` e `include` en discos dinámicos. Cambio incompatible con versiones anteriores porque prohíbe de forma predeterminada un comportamiento que antes estaba permitido de forma predeterminada. [#99138](https://github.com/ClickHouse/ClickHouse/pull/99138) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Ya no se puede usar el lector y escritor de Parquet obsoletos basados en Arrow. En su lugar, se usará la implementación nativa. [#100949](https://github.com/ClickHouse/ClickHouse/pull/100949) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `SHOW CREATE TABLE t` ahora da preferencia a la tabla temporal cuando existen tanto una tabla permanente como una temporal llamadas `t` y no se especifica ninguna base de datos, en consonancia con el comportamiento existente de `DESCRIBE TABLE`. Además, ahora se admite la sintaxis `DESCRIBE TEMPORARY TABLE`. [#100966](https://github.com/ClickHouse/ClickHouse/pull/100966) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se redujo el valor predeterminado de `http_max_fields` de 1,000,000 a 1,000 y el de `http_max_field_name_size` de 128 KB a 4 KB para limitar el uso de memoria previo a la autenticación de las conexiones HTTP. Se agregaron los ajustes `http_max_request_header_size` y `http_headers_read_timeout`. Los usuarios que dependan de los límites superiores anteriores pueden restaurarlos mediante ajustes. [#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).
* Se agregó una columna anidada `histograms` a `system.metric_log` que toma instantáneas de cada métrica de histograma registrada por fila, con un nuevo ajuste `system_metric_log_show_zero_values_in_histograms` para controlar la emisión de valores cero. Esto deja obsoleta la tabla `system.histogram_metric_log`. [#103770](https://github.com/ClickHouse/ClickHouse/pull/103770) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Las window functions `RANK` y `DENSE_RANK` ahora rechazan argumentos y generan `NUMBER_OF_ARGUMENTS_DOESNT_MATCH`, en línea con el estándar SQL. Anteriormente, consultas como `RANK(x) OVER (ORDER BY id)` se aceptaban silenciosamente con el argumento ignorado, lo que era una fuente frecuente de confusión para los usuarios. Para restaurar el comportamiento permisivo anterior, establezca `allow_rank_dense_rank_arguments = 1`. Cierra [#49526](https://github.com/ClickHouse/ClickHouse/issues/49526). [#104324](https://github.com/ClickHouse/ClickHouse/pull/104324) ([Groene AI](https://github.com/groeneai)).
* `CAST` a `DateTime` o `DateTime64` sin una zona horaria explícita ahora conserva la zona horaria de su argumento de origen (cuando el origen es un `DateTime`/`DateTime64` con una zona horaria explícita), en consonancia con el comportamiento de las funciones `toDateTime`/`toDateTime64`. Cierra [#55072](https://github.com/ClickHouse/ClickHouse/issues/55072). [#104433](https://github.com/ClickHouse/ClickHouse/pull/104433) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se revirtió el objetivo de compilación x86 predeterminado a x86-64-v2 (SSE4.2). Se deshizo el cambio anterior a x86-64-v3 (AVX2). [#104971](https://github.com/ClickHouse/ClickHouse/pull/104971) ([Raúl Marín](https://github.com/Algunenano)).
* Se eliminó la función de tabla `kql`. Use `SET dialect = 'kusto'` para ejecutar consultas en el dialecto KQL. [#105101](https://github.com/ClickHouse/ClickHouse/pull/105101) ([Alexey Milovidov](https://github.com/alexey-milovidov)).





<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Añade la función de tabla `filesystem`. Permite representar la estructura de directorios como una tabla y consultar con SQL los metadatos y el contenido de los archivos. Originalmente en https://github.com/ClickHouse/ClickHouse/pull/42039 por @perst20. Véase [#42039](https://github.com/ClickHouse/ClickHouse/issues/42039). Véase [#50208](https://github.com/ClickHouse/ClickHouse/issues/50208). [#53610](https://github.com/ClickHouse/ClickHouse/pull/53610) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se introduce el parámetro kafka&#95;autodetect&#95;client&#95;rack. Si se configura, detecta la zona de disponibilidad a través de la infraestructura cloud y la propaga como parámetro client.rack de librdkafka para evitar comunicaciones entre zonas. [#81323](https://github.com/ClickHouse/ClickHouse/pull/81323) ([Ilya Golshtein](https://github.com/ilejn)).
* Añade el tipo de evento `Read` a `system.blob_storage_log` para hacer seguimiento de las operaciones de lectura del almacenamiento de objetos, controlado por la nueva opción `enable_blob_storage_log_for_read_operations`. [#96867](https://github.com/ClickHouse/ClickHouse/pull/96867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añade un parámetro opcional de variante de codificación a `bech32Encode` (`'bech32'` / `'bech32m'`) y un modo de decodificación sin procesar a `bech32Decode` para la codificación de direcciones que no son SegWit (p. ej., Cosmos SDK, Injective, Osmosis). [#98986](https://github.com/ClickHouse/ClickHouse/pull/98986) ([Yash ](https://github.com/Onyx2406)).
* Ahora los usuarios pueden ver los watches de ZooKeeper emitidos por clickhouse-server mediante la nueva tabla `system.zookeeper_watches`. [#99277](https://github.com/ClickHouse/ClickHouse/pull/99277) ([Den Kalantaevskii](https://github.com/Diskein)).
* Añade el evento de perfil `Shards`, que cuenta el número de segmentos implicados en las consultas distribuidas, sumado entre todas las tablas. [#99470](https://github.com/ClickHouse/ClickHouse/pull/99470) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añade compatibilidad con los predicados de valor de verdad de SQL `IS TRUE`, `IS FALSE`, `IS UNKNOWN`, `IS NOT TRUE`, `IS NOT FALSE` e `IS NOT UNKNOWN` para expresiones booleanas Nullable. [#99997](https://github.com/ClickHouse/ClickHouse/pull/99997) ([ibrahim karimeddin](https://github.com/ibrahimkarimeddin)).
* WASM UDF puede declararse DETERMINISTIC y someterse a plegado de constantes. [#100005](https://github.com/ClickHouse/ClickHouse/pull/100005) ([Vasily Chekalkin](https://github.com/bacek)).
* Añade la opción `parallel_replicas_prefer_local_replica`: cuando está deshabilitada, las réplicas paralelas se seleccionan únicamente mediante el algoritmo de balanceo de carga, lo que permite que incluso las consultas con `max_parallel_replicas = 1` se dirijan a otro host. [#100139](https://github.com/ClickHouse/ClickHouse/pull/100139) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añade las opciones de servidor `{disk,storage,http}_connections_rcvbuf` y `{disk,storage,http}_connections_sndbuf` para controlar el tamaño de los búferes de socket TCP en las conexiones HTTP salientes, lo que permite a los operadores sobrescribir el autotuning del kernel y limitar el uso de memoria por conexión. [#100478](https://github.com/ClickHouse/ClickHouse/pull/100478) ([Sema Checherinda](https://github.com/CheSema)).
* Compatibilidad con `CREATE OR REPLACE MATERIALIZED VIEW` con la misma semántica de intercambio atómico que `CREATE OR REPLACE TABLE`. Funciona con tablas internas, tablas `TO`, `POPULATE`, `REFRESH` y `ON CLUSTER`. [#100539](https://github.com/ClickHouse/ClickHouse/pull/100539) ([DQ](https://github.com/il9ue)).
* Permite pasar nombres de función simples a funciones de orden superior como `arrayMap`, `arrayFilter`, etc. Por ejemplo, `arrayMap(negate, [1, 2, 3])` ahora es equivalente a `arrayMap(x -> negate(x), [1, 2, 3])`. [#101033](https://github.com/ClickHouse/ClickHouse/pull/101033) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añade la configuración `send_table_structure_on_insert_with_inline_data` y la opción `--inline-insert-data` del client para permitir que el servidor analice por sí mismo los datos inline de INSERT a través del protocolo nativo, evitando el viaje de ida y vuelta necesario para recibir la estructura de la tabla y mejorando el rendimiento en muchas inserciones pequeñas. [#101034](https://github.com/ClickHouse/ClickHouse/pull/101034) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añaden las funciones `tokenizeQuery` y `highlightQuery` para la tokenización de consultas SQL y el resaltado de sintaxis. `tokenizeQuery` devuelve tokens del analizador léxico con desplazamientos de bytes y tipos de token; `highlightQuery` devuelve rangos de resaltado de sintaxis basados en el analizador sintáctico, con categorías de resaltado (palabra clave, identificador, función, número, cadena, etc.). [#101054](https://github.com/ClickHouse/ClickHouse/pull/101054) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añade la configuración `url_base` para resolver URL relativas en la función de tabla `url` y el motor de tabla `URL`, siguiendo la semántica de la RFC 3986. [#101113](https://github.com/ClickHouse/ClickHouse/pull/101113) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añaden las métricas de histograma `s3_read_request_duration_microseconds` y `s3_read_request_bytes` para observar la duración de la conexión de las solicitudes GET a S3 y los bytes consumidos; son visibles en `system.histogram_metrics` y en el endpoint de Prometheus. [#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)).
* Caché de condiciones de consulta para tablas Iceberg. [#102115](https://github.com/ClickHouse/ClickHouse/pull/102115) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Se añaden los motores de tabla `Paimon`, `PaimonS3`, `PaimonAzure`, `PaimonHDFS` y `PaimonLocal` con soporte para lectura incremental respaldado por el seguimiento del progreso de snapshots de Keeper. El modo incremental devuelve solo las filas nuevas desde el último snapshot confirmado. Las lecturas delta de snapshots específicos están disponibles mediante `paimon_target_snapshot_id`, y los límites de snapshots por consulta, mediante `max_consume_snapshots`. La actualización de metadatos en segundo plano se puede configurar con `paimon_metadata_refresh_interval_sec`. Está controlado por `allow_experimental_paimon_storage_engine`. [#102343](https://github.com/ClickHouse/ClickHouse/pull/102343) ([XiaoBinMu](https://github.com/Binnn-MX)).
* Se añadió el tipo de estadísticas NullCount para un recuento preciso de valores NULL en columnas Nullable. Esto permite mejorar la optimización de `PREWHERE` y la poda de partes. [#102356](https://github.com/ClickHouse/ClickHouse/pull/102356) ([zoomxi](https://github.com/zoomxi)).
* Ahora puedes dar formato a una cadena como JSON legible para humanos con la función `prettyPrintJSON`. Resulta útil para paneles o informes en los que antes dar formato al JSON requería un paso adicional del lado del cliente. Cierra [#62523](https://github.com/ClickHouse/ClickHouse/issues/62523). [#102594](https://github.com/ClickHouse/ClickHouse/pull/102594) ([Dmitry Prokofyev](https://github.com/prokofyevDmitry)).
* Soporte para valores negativos en la cláusula `LIMIT BY` para seleccionar filas desde el *final* de cada grupo en lugar del principio. Por ejemplo, `LIMIT -2 BY id` devuelve las dos últimas filas por `id`. También se admiten offsets negativos (`LIMIT -1 OFFSET -1 BY id`) y signos mixtos (`LIMIT -2 OFFSET 1 BY id`). [#103222](https://github.com/ClickHouse/ClickHouse/pull/103222) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Se añadió una nueva configuración para tablas Kafka, `kafka_map_virtual_columns_on_write`. Cuando está habilitada, las columnas `_key`, `_timestamp`, `_headers.name` y `_headers.value` del esquema de la tabla Kafka se generan en `INSERT` como la clave, el timestamp y los headers correspondientes del mensaje de Kafka, y se excluyen de la carga útil del mensaje. [#103243](https://github.com/ClickHouse/ClickHouse/pull/103243) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadieron las consultas `SYSTEM PAUSE VIEW [db.]name` y `SYSTEM PAUSE VIEWS` para vistas materializadas actualizables. A diferencia de `SYSTEM STOP VIEW`, `SYSTEM PAUSE VIEW` no interrumpe la actualización que se está ejecutando en ese momento: deja que la actualización en curso finalice y solo evita las actualizaciones posteriores. Esto se deshace con `SYSTEM START VIEW` o `SYSTEM START VIEWS`, que ahora eliminan de forma uniforme tanto el estado detenido como el pausado. [#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se añadió un nuevo ajuste &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;join&#96;, en línea con &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;group&#95;by&#96; y &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;sort&#96;. Expresa el umbral de volcado a disco para hash joins como una fracción de la memoria disponible; al combinarse con el valor absoluto &#96;max&#95;bytes&#95;before&#95;external&#95;join&#96;, se aplica el menor de los dos umbrales resultantes. [#103862](https://github.com/ClickHouse/ClickHouse/pull/103862) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió la función `regexpPosition` (con alias compatibles con PostgreSQL `regexpInstr` y `regexp_instr`) que devuelve la posición en bytes de la enésima coincidencia de regex en una cadena. Admite desplazamiento inicial, modo de retorno después de la coincidencia, indicadores de regex y selección de grupo de captura. [#104172](https://github.com/ClickHouse/ClickHouse/pull/104172) ([Abhinav Agarwal](https://github.com/aagarwal-gtr)).
* Las estadísticas de columna NullCount ahora pueden usarse para part pruning. Las consultas con predicados IS NULL o IS NOT NULL en columnas Nullable que tienen estadísticas NullCount pueden omitir partes de datos completas cuando las estadísticas demuestran que no existen filas coincidentes. [#104214](https://github.com/ClickHouse/ClickHouse/pull/104214) ([zoomxi](https://github.com/zoomxi)).
* Nuevas funciones `isPrime` e `isProbablePrime` para comprobaciones de primalidad. `isPrime` devuelve un resultado exacto para enteros sin signo de hasta `UInt64`. `isProbablePrime` también admite `UInt128` y `UInt256`; para esos tipos más amplios, `0` significa definitivamente compuesto y `1` significa probablemente primo. El segundo argumento opcional de `isProbablePrime`, `rounds`, controla el nivel de confianza; con el valor predeterminado de `25` rondas, la tasa de falsos positivos para un número compuesto aleatorio queda por debajo de `10^-15`. [#104234](https://github.com/ClickHouse/ClickHouse/pull/104234) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Clear y /clear ahora limpian la terminal en las herramientas de línea de comandos de ClickHouse en lugar de ejecutarse como una consulta por error. [#104318](https://github.com/ClickHouse/ClickHouse/pull/104318) ([Tyler Hannan](https://github.com/tylerhannan)).
* Se permitió que la función de tabla `file` acepte un `Array(String)` de rutas en consultas `SELECT`. [#104442](https://github.com/ClickHouse/ClickHouse/pull/104442) ([Yue](https://github.com/niyue)).
* Se añadieron las columnas `deterministic` y `higher_order` a la tabla `system.functions`. [#104479](https://github.com/ClickHouse/ClickHouse/pull/104479) ([Pedro Ferreira](https://github.com/PedroTadim)).



<div id="experimental-feature">
  #### Funcionalidad experimental
</div>

* Se añadió una interfaz experimental de terminal web en `/webterminal` que proporciona una sesión interactiva de `clickhouse-client` en el navegador a través de WebSocket. Está deshabilitada de forma predeterminada; actívela con la configuración del servidor `allow_experimental_webterminal`. [#100277](https://github.com/ClickHouse/ClickHouse/pull/100277) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WASM UDF ahora puede realizar coerción entre más tipos numéricos. Los enteros más pequeños pueden convertirse en enteros más grandes; por ejemplo, Int8 a UInt64. Cualquier entero puede convertirse en float; por ejemplo, Int32 a F32. [#100435](https://github.com/ClickHouse/ClickHouse/pull/100435) ([Vasily Chekalkin](https://github.com/bacek)).
* Compatibilidad con tipos Geo para Iceberg. [#103113](https://github.com/ClickHouse/ClickHouse/pull/103113) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* La terminal web experimental (`allow_experimental_webterminal`) ahora puede incrustarse en modo cross-origin desde `clickhouse.com`, `clickhouse.cloud` y sus subdominios. Antes, los `postMessage` de cualquier contenedor padre con un origen distinto se rechazaban en la entrada y se descartaban silenciosamente en la salida, lo que hacía que la terminal fuera, en la práctica, imposible de incrustar fuera de `play.clickhouse.com`. La lista de orígenes aceptados es una allowlist explícita (solo https y anclada al hostname), por lo que los orígenes no confiables siguen rechazándose. [#105191](https://github.com/ClickHouse/ClickHouse/pull/105191) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Optimiza `cramersV`, `cramersVBiasCorrected`, `theilsU` y `contingency` cuando se usan con funciones de ventana. Cierra [#83521](https://github.com/ClickHouse/ClickHouse/issues/83521). [#93384](https://github.com/ClickHouse/ClickHouse/pull/93384) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Habilita de forma predeterminada las configuraciones `use_top_k_dynamic_filtering` y `use_skip_indexes_for_top_k` para mejorar el rendimiento de las consultas `ORDER BY ... LIMIT N`. [#99537](https://github.com/ClickHouse/ClickHouse/pull/99537) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Limita la cantidad de streams activos simultáneamente en UNION ALL para reducir el uso máximo de memoria. [#100176](https://github.com/ClickHouse/ClickHouse/pull/100176) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se añadió una optimización de consultas que reescribe `tupleElement(dictGet('dict', ('a', 'b', 'c'), key), N)` como `dictGet('dict', 'a', key)`, evitando recuperar atributos de Diccionario innecesarios. Está controlada por la configuración `optimize_dictget_tuple_element` (habilitada de forma predeterminada). [#100186](https://github.com/ClickHouse/ClickHouse/pull/100186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimiza ligeramente la caché de páginas en espacio de usuario. [#100300](https://github.com/ClickHouse/ClickHouse/pull/100300) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelera el análisis de índices que implica conversiones de tipos y aplicación de funciones. Cierra [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653). [#100366](https://github.com/ClickHouse/ClickHouse/pull/100366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelera las consultas muy grandes sobre tablas `Merge` con una gran cantidad de tablas subyacentes. Cierra [#32465](https://github.com/ClickHouse/ClickHouse/issues/32465). [#100369](https://github.com/ClickHouse/ClickHouse/pull/100369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añade las configuraciones `max_threads_min_free_memory_per_thread` y `max_insert_threads_min_free_memory_per_thread` para reducir automáticamente el paralelismo de las consultas cuando el server tiene poca memoria libre. [#100383](https://github.com/ClickHouse/ClickHouse/pull/100383) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el uso de memoria en sistemas con poca memoria (&lt; 4 GiB). [#100389](https://github.com/ClickHouse/ClickHouse/pull/100389) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Habilita el almacenamiento en búfer para los pasos de ordenación en el initiator en consultas distribuidas con ordenación. [#100661](https://github.com/ClickHouse/ClickHouse/pull/100661) ([Nikita Taranov](https://github.com/nickitat)).
* Mejora el rendimiento de partial&#95;merge&#95;join. [#100945](https://github.com/ClickHouse/ClickHouse/pull/100945) ([Artem Zuikov](https://github.com/4ertus2)).
* Reduce ligeramente la sobreasignación de memoria en JOIN `partial_merge`. [#100963](https://github.com/ClickHouse/ClickHouse/pull/100963) ([Artem Zuikov](https://github.com/4ertus2)).
* Optimiza las asignaciones/liberaciones almacenando en caché la configuración de sampling en lugar de recorrer toda la jerarquía del memory tracker. [#101267](https://github.com/ClickHouse/ClickHouse/pull/101267) ([Azat Khuzhin](https://github.com/azat)).
* Reduce la sobrecarga de asignación de memoria durante uploads multiparte a S3 mediante la preasignación de contenedores internos de seguimiento. [#101799](https://github.com/ClickHouse/ClickHouse/pull/101799) ([Gagan Dhakrey](https://github.com/gagandhakrey)).
* Elimina la vtable de los tipos de campo de configuración, lo que reduce el tamaño de copia de `Settings` en ~28x y mejora la localidad de caché mediante una disposición de arrays tipados para todos los tipos de configuración. [#102269](https://github.com/ClickHouse/ClickHouse/pull/102269) ([Raúl Marín](https://github.com/Algunenano)).
* Añade software prefetch en la fase de sondeo de hash join para reducir la latencia de acceso a memoria en hash tables grandes, controlado por la opción `enable_software_prefetch_in_join`. [#102444](https://github.com/ClickHouse/ClickHouse/pull/102444) ([Xiaozhe Yu](https://github.com/wudidapaopao)).
* Optimiza la estructura de MemoryTracker (mejora su rendimiento en ~25%). [#103464](https://github.com/ClickHouse/ClickHouse/pull/103464) ([Azat Khuzhin](https://github.com/azat)).
* Reescribe los predicados `coalesce(a, b, ...) <op> const` y `ifNull(a, b) <op> const` antes del análisis de índices para que la primary key por columna y los skip indexes de cada argumento puedan descartar granules. Controlado por la nueva opción `allow_key_condition_coalesce_rewrite` (activada de forma predeterminada). [#103468](https://github.com/ClickHouse/ClickHouse/pull/103468) ([Manuel](https://github.com/raimannma)).

[#105281](https://github.com/ClickHouse/ClickHouse/pull/105281) ([Groene AI](https://github.com/groeneai)).
* Se corrige una regresión en `clickhouse extract-from-config --try`: cuando la configuración usaba attributes `from_env` y no tenía ningún elemento `include_from` (o tenía uno que apuntaba a un archivo inexistente), todas las substitutions `from_env` se descartaban silenciosamente y devolvían cadenas vacías. Esto rompía la detección del puerto en el entrypoint de Docker en la versión 26.2.5. Cierra [#101704](https://github.com/ClickHouse/ClickHouse/issues/101704). [#105283](https://github.com/ClickHouse/ClickHouse/pull/105283) ([Groene AI](https://github.com/groeneai)).
* Se corrige el fallo de `INSERT INTO sqlite_table` con un error de sintaxis de SQLite cuando el valor insertado es un `Enum`, `JSON` o `AggregateFunction` cuya representación textual contiene una comilla simple. La configuración `output_format_values_escape_quote_with_quote` ahora se respeta en las serializaciones correspondientes (antes solo la respetaban `String` y `FixedString`). [#105285](https://github.com/ClickHouse/ClickHouse/pull/105285) ([Groene AI](https://github.com/groeneai)).
* Se corrige `Code: 44. ILLEGAL_COLUMN: Cannot add column ...: column with this name already exists`, que se producía en consultas distribuidas con `allow_push_predicate_ast_for_distributed_subqueries = 1` (el valor predeterminado) cuando una tupla `GLOBAL IN` se compara con una subconsulta cuya proyección contiene nombres de columna duplicados, por ejemplo, `(x, y) GLOBAL IN (SELECT number, number FROM numbers(5))`. [#105290](https://github.com/ClickHouse/ClickHouse/pull/105290) ([Groene AI](https://github.com/groeneai)).
* Se corrige que `reinterpret` a `Array(LowCardinality(...))` devolviera un error `NOT_IMPLEMENTED` confuso en tiempo de ejecución; ahora devuelve `ILLEGAL_TYPE_OF_ARGUMENT` durante la verificación de tipos. [#105301](https://github.com/ClickHouse/ClickHouse/pull/105301) ([Raúl Marín](https://github.com/Algunenano)).
* `minMap`/`maxMap` (array form) y `minMappedArrays`/`maxMappedArrays` ahora tratan `NaN` de forma coherente con `ORDER BY`: `NaN` se considera el último valor (solo se devuelve cuando todos los valores son `NaN`). Antes, los resultados dependían de la posición de `NaN` en los datos debido a la semántica de comparación no ordenada de IEEE 754, y no coincidían con la forma con argumento `Map` de `minMap`/`maxMap` que se corrigió en [#100448](https://github.com/ClickHouse/ClickHouse/issues/100448). [#105331](https://github.com/ClickHouse/ClickHouse/pull/105331) ([Raúl Marín](https://github.com/Algunenano)).
* Se corrige una fuga de memoria en la caché `ColumnsDescription` por tabla para tablas de la familia `MergeTree` con columnas `Nested`. Las entradas nunca se desalojaban durante los ciclos `ALTER ADD COLUMN`/`DROP COLUMN` cuando `share_nested_offsets=1` (el valor predeterminado). [#105376](https://github.com/ClickHouse/ClickHouse/pull/105376) ([Groene AI](https://github.com/groeneai)).
* Se corrige la excepción `BAD_ARGUMENTS` &quot;It&#39;s a bug!
