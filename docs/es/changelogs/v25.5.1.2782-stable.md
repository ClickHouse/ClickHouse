<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* La función `geoToH3()` ahora acepta la entrada en el orden (lat, lon,res) (que es el orden estándar de las funciones geométricas). Los usuarios que deseen conservar el orden de resultado anterior (lon, lat,res) pueden establecer la configuración `geotoh3_lon_lat_input_order = true`. [#78852](https://github.com/ClickHouse/ClickHouse/pull/78852) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Los índices de tipo `full_text` pasaron a llamarse `gin`. Esto sigue la terminología más habitual de PostgreSQL y otras bases de datos. Los índices existentes de tipo `full_text` siguen pudiendo cargarse, pero generarán una excepción (sugiriendo usar índices `gin` en su lugar) cuando se intente utilizarlos en búsquedas. [#79024](https://github.com/ClickHouse/ClickHouse/pull/79024) ([Robert Schulze](https://github.com/rschu1ze)).
* Se añade una configuración de la caché del sistema de archivos, `allow_dynamic_cache_resize`, con valor predeterminado `false`, para permitir el redimensionamiento dinámico de la caché del sistema de archivos. Motivo: en determinados entornos (ClickHouse Cloud), todos los eventos de escalado se producen mediante el reinicio del proceso, y queremos que esta funcionalidad esté deshabilitada explícitamente para tener un mayor control sobre el comportamiento, además de servir como medida de seguridad. Este PR está marcado como incompatible con versiones anteriores porque, en versiones antiguas, el redimensionamiento dinámico de la caché funcionaba de forma predeterminada sin necesidad de una configuración especial. [#79148](https://github.com/ClickHouse/ClickHouse/pull/79148) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se eliminó el soporte para los tipos de índice heredados `annoy` y `usearch`. Ambos han sido implementaciones vacías durante mucho tiempo; es decir, cualquier intento de usar estos índices heredados devolvía un error de todos modos. Si todavía tiene índices `annoy` y `usearch`, elimínelos. [#79802](https://github.com/ClickHouse/ClickHouse/pull/79802) ([Robert Schulze](https://github.com/rschu1ze)).
* Se elimina la configuración del servidor `format_alter_commands_with_parentheses`. Esta configuración se introdujo y estaba deshabilitada de forma predeterminada en la versión 24.2. Se habilitó de forma predeterminada en la versión 25.2. Como no hay versiones LTS que no admitan el nuevo formato, podemos eliminar esta configuración. [#79970](https://github.com/ClickHouse/ClickHouse/pull/79970) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Acelera los índices secundarios evaluando sus expresiones en varios gránulos a la vez. [#64109](https://github.com/ClickHouse/ClickHouse/pull/64109) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se introdujo un umbral (controlado por el ajuste `parallel_hash_join_threshold`) para volver al algoritmo `hash` cuando el tamaño de la tabla derecha está por debajo de ese umbral. [#76185](https://github.com/ClickHouse/ClickHouse/pull/76185) ([Nikita Taranov](https://github.com/nickitat)).
* Mejora el rendimiento de S3Queue/AzureQueue al permitir `INSERT` de datos en paralelo (se puede habilitar con el ajuste de cola `parallel_inserts=true`). Anteriormente, S3Queue/AzureQueue solo podía ejecutar en paralelo la primera parte del pipeline (descarga y parsing); `INSERT` era de un solo hilo. Y los `INSERT` casi siempre son el cuello de botella. Ahora escalará de forma casi lineal con `processing_threads_num`. [#77671](https://github.com/ClickHouse/ClickHouse/pull/77671) ([Azat Khuzhin](https://github.com/azat)).
* Cambia el formato de parte Compact para guardar marcas para cada substream y poder leer subcolumnas individuales. El formato Compact anterior sigue siendo compatible para lecturas y puede habilitarse para escrituras mediante el ajuste de MergeTree `write_marks_for_substreams_in_compact_parts`. Está deshabilitado de forma predeterminada para que las actualizaciones sean más seguras, ya que cambia el almacenamiento de las partes compactas. Se habilitará de forma predeterminada en una de las próximas versiones. [#77940](https://github.com/ClickHouse/ClickHouse/pull/77940) ([Pavel Kruglov](https://github.com/Avogar)).
* Se introdujo un nuevo ajuste: `use_skip_indexes_in_final_exact_mode`. Si una consulta sobre una tabla `ReplacingMergeTree` tiene la cláusula FINAL, leer solo rangos de tabla basados en skip indexes puede producir resultados incorrectos. Este ajuste puede garantizar que se devuelvan resultados correctos escaneando partes más nuevas que se solapen con los rangos de clave primaria devueltos por el skip index. Establezca 0 para deshabilitarlo y 1 para habilitarlo. [#78350](https://github.com/ClickHouse/ClickHouse/pull/78350) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Ahora usamos el número de réplicas para determinar el tamaño de tarea al leer con parallel replicas habilitadas. Esto proporciona una mejor distribución del trabajo entre réplicas cuando la cantidad de datos que se va a leer no es muy grande. [#78695](https://github.com/ClickHouse/ClickHouse/pull/78695) ([Nikita Taranov](https://github.com/nickitat)).
* Permite la fusión en paralelo de estados `uniqExact` durante la etapa final de la agregación distribuida. [#78703](https://github.com/ClickHouse/ClickHouse/pull/78703) ([Nikita Taranov](https://github.com/nickitat)).
* Corrige una posible degradación del rendimiento de la fusión en paralelo de estados `uniqExact` para agregaciones con clave. [#78724](https://github.com/ClickHouse/ClickHouse/pull/78724) ([Nikita Taranov](https://github.com/nickitat)).
* Reduce el número de llamadas a la API List Blobs de Azure Storage. [#78860](https://github.com/ClickHouse/ClickHouse/pull/78860) ([Julia Kartseva](https://github.com/jkartseva)).
* Fusiona las condiciones de igualdad del paso de filtro del plan de consulta en la condición JOIN, cuando sea posible, para permitir usarlas como claves de la hash table. [#78877](https://github.com/ClickHouse/ClickHouse/pull/78877) ([Dmitry Novik](https://github.com/novikd)).
* Mejora el rendimiento del parsing de rutas hive usando `extractKeyValuePairs` en lugar de expresiones regulares. [#79067](https://github.com/ClickHouse/ClickHouse/pull/79067) ([Arthur Passos](https://github.com/arthurpassos)).
* Corrige el rendimiento de `INSERT SELECT` distribuido con parallel replicas. [#79441](https://github.com/ClickHouse/ClickHouse/pull/79441) ([Azat Khuzhin](https://github.com/azat)).
* Permite mover condiciones con subcolumnas a prewhere. [#79489](https://github.com/ClickHouse/ClickHouse/pull/79489) ([Pavel Kruglov](https://github.com/Avogar)).
* Evita que `LogSeriesLimiter` realice una limpieza en cada construcción, evitando la contención de bloqueos y las regresiones de rendimiento en escenarios de alta concurrencia. [#79864](https://github.com/ClickHouse/ClickHouse/pull/79864) ([filimonov](https://github.com/filimonov)).
* Habilita `compile_expressions` (compilador JIT para fragmentos de expresiones ordinarias) de forma predeterminada. Esto resuelve [#51264](https://github.com/ClickHouse/ClickHouse/issues/51264), [#56386](https://github.com/ClickHouse/ClickHouse/issues/56386) y [#66486](https://github.com/ClickHouse/ClickHouse/issues/66486). [#79907](https://github.com/ClickHouse/ClickHouse/pull/79907) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelera las consultas con una optimización trivial de `count`. [#79945](https://github.com/ClickHouse/ClickHouse/pull/79945) ([Raúl Marín](https://github.com/Algunenano)).
* Añade `__attribute__((always_inline))` a `convertDecimalsImpl`. [#79999](https://github.com/ClickHouse/ClickHouse/pull/79999) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Establece `input_format_parquet_bloom_filter_push_down` en true de forma predeterminada. Además, corrige un error en el historial de cambios de Settings. [#80058](https://github.com/ClickHouse/ClickHouse/pull/80058) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
