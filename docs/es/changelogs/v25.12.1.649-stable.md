<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* ALTER MODIFY COLUMN ahora requiere un DEFAULT explícito al convertir columnas Nullable a tipos no anulables. Antes, esos ALTER podían quedarse bloqueados con errores de cannot convert null to not null; ahora los NULL se sustituyen por la expresión por defecto de la columna. Resuelve [#5985](https://github.com/ClickHouse/ClickHouse/issues/5985). [#84770](https://github.com/ClickHouse/ClickHouse/pull/84770) ([Vladimir Cherkasov](https://github.com/vdimir)).
* El tokenizer Ngram ya no devolverá ngrams más cortos que la longitud N con la que se configuró. Text Search no devolverá filas cuando los tokens de búsqueda estén vacíos. [#89757](https://github.com/ClickHouse/ClickHouse/pull/89757) ([George Larionov](https://github.com/george-larionov)).
* Al hacer ALTER de una columna de `String` a `Nullable(String)`, no se aplicará ninguna mutation a los datos. Pero, para la aggregate function `uniq`, se usa una estructura de datos distinta: para una columna Nullable, se utilizará `AggregateFunctionNull` con un agregador `uniq` anidado. `AggregateFunctionNull` serializará un indicador booleano adicional. Esto hará que el archivo de estadísticas sea incompatible. La corrección consiste en añadir un indicador para registrar si se trata de una columna Nullable durante la serialización. El formato de las estadísticas ha cambiado; el servidor fallará si hay estadísticas con el formato anterior. Este PR [https://github.com/ClickHouse/ClickHouse/pull/90904](https://github.com/ClickHouse/ClickHouse/pull/90904) corregirá el fallo y lanzará una excepción cuando las estadísticas existentes usen el formato heredado. Para evitar la excepción, debe ejecutar ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL para regenerar las estadísticas y corregirlo. [#90311](https://github.com/ClickHouse/ClickHouse/pull/90311) ([Han Fei](https://github.com/hanfei1991)).
* Se eliminaron los settings `allow_not_comparable_types_in_order_by`/`allow_not_comparable_types_in_comparison_functions`. Permitir tipos no comparables en ORDER BY o en funciones de comparación puede provocar errores lógicos y resultados inesperados. Resuelve [#90028](https://github.com/ClickHouse/ClickHouse/issues/90028). [#90527](https://github.com/ClickHouse/ClickHouse/pull/90527) ([Pavel Kruglov](https://github.com/Avogar)).
* Se cambió el valor por defecto del setting `check_query_single_value_result` de `true` a `false`. Esto hace que `CHECK TABLE` devuelva resultados detallados por parte en lugar de un resultado agregado (1 = correcto, 0 = errores encontrados). En comparación con el comportamiento anterior, esto probablemente se ajusta mejor a lo que quiere el usuario. [#91009](https://github.com/ClickHouse/ClickHouse/pull/91009) ([Robert Schulze](https://github.com/rschu1ze)).
* Varias correcciones relacionadas con índices implícitos. El esquema mostrado o almacenado (metadata de keeper) no incluirá índices implícitos, como los creados por los settings `add_minmax_index_for_numeric_columns` o `add_minmax_index_for_string_columns`. Esto podría causar errores de metadata cuando una tabla ReplicatedMergeTree se crea o actualiza en una versión más reciente, mientras hay una réplica en una versión anterior. En esos casos, envíe los DDL a la réplica antigua hasta que el cluster se haya actualizado por completo. [#91429](https://github.com/ClickHouse/ClickHouse/pull/91429) ([Raúl Marín](https://github.com/Algunenano)).
* Se actualizó clickhouse-client para que devuelva un código de salida distinto de cero (159 - TIMEOUT&#95;EXCEEDED) cuando una consulta exceda el timeout debido a `receive_timeout`. Antes, los timeouts devolvían el código de salida 0 (éxito), lo que dificultaba que los scripts y la automatización detectaran fallos por timeout. [#91432](https://github.com/ClickHouse/ClickHouse/pull/91432) ([Sav](https://github.com/sberss)).
* Se mejoró la disposición de almacenamiento del inverted text index para que sea más eficiente al leer desde object storage. Se mejoró el rendimiento de las merges en tablas con inverted text indexes. Si usó el text index experimental antes de la versión 25.12, debe eliminar el índice antes de la actualización y volver a crearlo en la nueva versión. [#91518](https://github.com/ClickHouse/ClickHouse/pull/91518) ([Anton Popov](https://github.com/CurtizJ)).
* Ahora está prohibido crear tablas `MergeTree` especiales (como `ReplacingMergeTree`, `CollapsingMergeTree`, etc.) con una clave `ORDER BY` vacía, ya que el comportamiento de combinación en estas tablas no está definido. Si aún necesita crear una tabla de este tipo, habilite la configuración `allow_suspicious_primary_key`. [#91569](https://github.com/ClickHouse/ClickHouse/pull/91569) ([Anton Popov](https://github.com/CurtizJ)).
* Se corrigen las funciones bitShiftLeft y bitShiftRight para que devuelvan 0 o un valor vacío cuando el shift es exactamente igual al tamaño del tipo. [#91943](https://github.com/ClickHouse/ClickHouse/pull/91943) ([Pablo Marcos](https://github.com/pamarcos)).
* Seguimiento de [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380). Este PR marca la deshabilitación de los argumentos posicionales en las proyecciones como un cambio incompatible con versiones anteriores. Además, introduce la configuración `enable_positional_arguments_for_projections` para permitir una actualización segura de un clúster de ClickHouse cuando hay argumentos posicionales en las proyecciones. [#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="experimental-feature">
  #### Funcionalidad experimental
</div>

* Se introduce una nueva lógica para ejecutar automáticamente consultas con réplicas en paralelo, controlada por la configuración `automatic_parallel_replicas_mode`. Durante la ejecución normal en un solo nodo, ClickHouse recopila estadísticas que posteriormente se tienen en cuenta en la etapa de planificación. Si esas estadísticas sugieren que las réplicas en paralelo probablemente aporten beneficios, ClickHouse ejecutará automáticamente la consulta en cuestión con réplicas en paralelo. Actualmente, el conjunto de consultas compatibles es bastante limitado. [#87541](https://github.com/ClickHouse/ClickHouse/pull/87541) ([Nikita Taranov](https://github.com/nickitat)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Fallo rápido cuando las consultas alcanzan los límites de filas. Resuelve [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872). [#62804](https://github.com/ClickHouse/ClickHouse/pull/62804) ([Sean Haynes](https://github.com/seandhaynes)).
* Añade una optimización para eliminar columnas no utilizadas en los planes de consulta. Resuelve [#75152](https://github.com/ClickHouse/ClickHouse/issues/75152). [#76487](https://github.com/ClickHouse/ClickHouse/pull/76487) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Https://github.com/clickhouse/clickhouse/pull/84477 añadió restricciones sobre las consultas select que pueden usarse en consultas `insert select from s3cluster()` para la ejecución distribuida en paralelo. Este cambio permite usar where, algo que ya era posible antes. [#84611](https://github.com/ClickHouse/ClickHouse/pull/84611) ([Igor Nikonov](https://github.com/devcrafter)).
* Precarga claves durante la iteración de la hash table para minimizar los fallos de caché. [#84708](https://github.com/ClickHouse/ClickHouse/pull/84708) ([lgbo](https://github.com/lgbo-ustc)).
* Optimiza AggregateFunctionHistogram ordenando solo la parte final del array de puntos y omitiendo la ordenación para entradas monótonas, logrando una mejora de velocidad de ~10%. [#85760](https://github.com/ClickHouse/ClickHouse/pull/85760) ([MakarDev](https://github.com/MakarDev)).
* ClickHouse ahora usa skip indexes para realizar análisis de índices en cláusulas WHERE con condiciones de filtro conectadas mediante `AND` y `OR`. Antes, la cláusula WHERE debía ser una conjunción (AND) de condiciones de filtro para aprovechar los skip indexes. Un nuevo ajuste `use_skip_indexes_for_disjunctions` (predeterminado: activado) controla esta funcionalidad. (issue [#75228](https://github.com/ClickHouse/ClickHouse/issues/75228)). [#87781](https://github.com/ClickHouse/ClickHouse/pull/87781) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Se mejoró el rendimiento del filtrado para predicados con funciones como `like`, `equals`, `has` y otras, aprovechando un filtro preliminar adicional construido a partir del text index. Esta optimización se habilita mediante el ajuste `query_plan_text_index_add_hint`. También se mejoró el uso del text index para columnas del tipo de dato `Map`. [#88550](https://github.com/ClickHouse/ClickHouse/pull/88550) ([Anton Popov](https://github.com/CurtizJ)).
* Optimiza las búsquedas inversas repetidas en diccionarios realizando búsquedas más rápidas en un conjunto precalculado de posibles valores de clave. Cierra [#7968](https://github.com/ClickHouse/ClickHouse/issues/7968). [#88971](https://github.com/ClickHouse/ClickHouse/pull/88971) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Se añadió soporte para serialización dispersa en columnas de tipo Nullable. Esto da continuidad a [#44539](https://github.com/ClickHouse/ClickHouse/issues/44539). [#88999](https://github.com/ClickHouse/ClickHouse/pull/88999) ([Amos Bird](https://github.com/amosbird)).
* Añade soporte para Runtime Filters de JOIN en JOINs `ANTI`. Además, se refactorizó la implementación de Runtime Filters para reducir la contención de bloqueos. [#89710](https://github.com/ClickHouse/ClickHouse/pull/89710) ([Dmitry Novik](https://github.com/novikd)).
* Añade soporte para mantener la lectura en orden desde la tabla izquierda en operaciones LEFT/INNER JOIN, lo que puede aprovecharse en pasos posteriores. Puede deshabilitarse mediante el ajuste `query_plan_read_in_order_through_join`. También añade soporte para la optimización de fila virtual durante la lectura (véase el ajuste `read_in_order_use_virtual_row`) en LEFT/INNER JOINs. [#89815](https://github.com/ClickHouse/ClickHouse/pull/89815) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Optimiza las consultas `ORDER BY...LIMIT N` mediante skip index y un filtro de umbral dinámico para reducir significativamente las filas procesadas. [#89835](https://github.com/ClickHouse/ClickHouse/pull/89835) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Mejora el rendimiento y el comportamiento de topK. [#90091](https://github.com/ClickHouse/ClickHouse/pull/90091) ([Raúl Marín](https://github.com/Algunenano)).
* Se mejoró el rendimiento de las operaciones de comparación de Decimal. Resuelve [#28192](https://github.com/ClickHouse/ClickHouse/issues/28192). [#90153](https://github.com/ClickHouse/ClickHouse/pull/90153) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Se añade compatibilidad con el partition pruning para las funciones de Paimon, como continuación de [https://github.com/ClickHouse/ClickHouse/pull/84423](https://github.com/ClickHouse/ClickHouse/pull/84423). [#90253](https://github.com/ClickHouse/ClickHouse/pull/90253) ([JIaQi](https://github.com/JiaQiTang98)).
* Se mejora el rendimiento de las columnas materializadas de forma diferida con un límite mayor. [#90309](https://github.com/ClickHouse/ClickHouse/pull/90309) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Los usuarios deberían notar una menor latencia en el análisis de índices cuando hay índices `minmax` grandes (millones de gránulos). [#90428](https://github.com/ClickHouse/ClickHouse/pull/90428) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Se usan operaciones SIMD avanzadas para funciones lógicas mediante dynamic dispatch. [#90432](https://github.com/ClickHouse/ClickHouse/pull/90432) ([Raúl Marín](https://github.com/Algunenano)).
* Se mejora el rendimiento de las funciones JIT al evitar inicializar innecesariamente a cero la columna de resultado. [#90449](https://github.com/ClickHouse/ClickHouse/pull/90449) ([Raúl Marín](https://github.com/Algunenano)).
* Se acelera la descompresión de T64 mediante dynamic dispatch. [#90610](https://github.com/ClickHouse/ClickHouse/pull/90610) ([Raúl Marín](https://github.com/Algunenano)).
* Se optimiza el filtrado in-place del reader de MergeTree. Resuelve [#87119](https://github.com/ClickHouse/ClickHouse/issues/87119). [#90630](https://github.com/ClickHouse/ClickHouse/pull/90630) ([Xiaozhe Yu](https://github.com/wudidapaopao)).
* Se aborta rápidamente cuando las consultas alcanzan los límites de filas. Resuelve [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872). [#90767](https://github.com/ClickHouse/ClickHouse/pull/90767) ([Sean Haynes](https://github.com/seandhaynes)).
* Se implementa un algoritmo simple de reordenación de joins DPsize para INNER JOINs. Un nuevo ajuste experimental controla qué algoritmos se usan y en qué orden; por ejemplo, `query_plan_optimize_join_order_algorithm='dpsize,greedy'` significa que primero se prueba DPsize y, si falla, se recurre a greedy. [#91002](https://github.com/ClickHouse/ClickHouse/pull/91002) ([Alexander Gololobov](https://github.com/davenger)).
* Se introduce una heurística adicional para reducir la amplitud de las opciones de merge seleccionadas. Realizar merges más estrechos aumentará la amplificación de escritura, pero al mismo tiempo puede ayudar a evitar errores `TOO_MANY_PARTS`. [#91163](https://github.com/ClickHouse/ClickHouse/pull/91163) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Se mejora el rendimiento de las consultas en tablas S3 creadas con un glob pattern al trasladar los valores de filtro de `_path`, lo que evita operaciones de listado en S3. Se controla con el ajuste `s3_path_filter_limit`. [#91165](https://github.com/ClickHouse/ClickHouse/pull/91165) ([Eduard Karacharov](https://github.com/korowa)).
* Se acelera la conversión de columnas a bool (en cláusulas WHERE) mediante dynamic dispatch. [#91203](https://github.com/ClickHouse/ClickHouse/pull/91203) ([Raúl Marín](https://github.com/Algunenano)).
* Se acelera la ordenación de un único block numérico mediante dynamic dispatch. [#91213](https://github.com/ClickHouse/ClickHouse/pull/91213) ([Raúl Marín](https://github.com/Algunenano)).
