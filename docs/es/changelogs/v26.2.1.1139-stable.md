<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se mejoró el formato de almacenamiento de las estadísticas. Ahora, todas las estadísticas se almacenan en un único archivo. [#93414](https://github.com/ClickHouse/ClickHouse/pull/93414) ([Anton Popov](https://github.com/CurtizJ)).
* Se limitan los metadatos en memoria de S3(Azure)Queue. Las tablas del sistema se renombraron de `azure_queue` a `azure_queue_metadata_cache` y de `system.s3queue` a `s3queue_metadata_cache`. [#95809](https://github.com/ClickHouse/ClickHouse/pull/95809) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Se corrige un error lógico por incompatibilidad de tipos en `Variant`. [#95811](https://github.com/ClickHouse/ClickHouse/pull/95811) ([Bharat Nallan](https://github.com/bharatnc)).
* CAMBIO IMPORTANTE: Con este cambio, la deduplicación queda activada de forma predeterminada para todas las inserciones. Antes estaba desactivada para las async inserts y para las MV, pero activada para las inserciones síncronas. El objetivo es tener los mismos valores predeterminados para ambos tipos de inserciones. Si tienes la deduplicación desactivada explícitamente en tu clúster, debes establecer explícitamente `deduplicate_insert='backward_compatible_choice'` para mantener el comportamiento anterior. Lo mismo aplica a `deduplicate_blocks_in_dependent_materialized_views`. [#95970](https://github.com/ClickHouse/ClickHouse/pull/95970) ([Sema Checherinda](https://github.com/CheSema)).
* Las columnas `DATE` de PostgreSQL ahora se infieren como `Date32` en ClickHouse (en versiones anteriores se inferían como `Date`, lo que provocaba overflow en los valores fuera de un rango estrecho). Se permite insertar valores `Date32` de vuelta en PostgreSQL. Cierra [#73084](https://github.com/ClickHouse/ClickHouse/issues/73084). [#95999](https://github.com/ClickHouse/ClickHouse/pull/95999) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La semántica de la configuración `do_not_merge_across_partitions_select_final` se hizo más clara. Anteriormente, la funcionalidad podía habilitarse automáticamente cuando la configuración no se establecía explícitamente en la configuración. Esto provocó confusión repetidamente y, por desgracia, dio lugar a algunos problemas en producción. Ahora, las reglas son más simples: `do_not_merge_across_partitions_select_final=1` habilita la funcionalidad de forma incondicional. Si `do_not_merge_across_partitions_select_final=0`, el modo automático se usa solo si la nueva configuración `enable_automatic_decision_for_merging_across_partitions_for_final=1`; en caso contrario, no se usa. Para preservar en la medida de lo posible el comportamiento anterior, los valores predeterminados se establecieron en `do_not_merge_across_partitions_select_final=0` y `enable_automatic_decision_for_merging_across_partitions_for_final=1`. [#96110](https://github.com/ClickHouse/ClickHouse/pull/96110) ([Nikita Taranov](https://github.com/nickitat)).
* Se añade validación de schema para S3. Esto cierra [#96089](https://github.com/ClickHouse/ClickHouse/issues/96089). [#96194](https://github.com/ClickHouse/ClickHouse/pull/96194) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Se prohíbe usar subconsultas en ORDER BY y otras expresiones de clave de tabla. [#96847](https://github.com/ClickHouse/ClickHouse/pull/96847) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se habilita `apply_row_policy_after_final` de forma predeterminada. Inicialmente, cuando `optimize_move_to_prewhere_if_final=0`, tanto ROW POLICY como PREWHERE respetaban FINAL y se aplicaban después de FINAL. Esto se rompió en [#87303](https://github.com/ClickHouse/ClickHouse/issues/87303), donde se ignoraba `optimize_move_to_prewhere_if_final` para el filtro de ROW POLICY. Para corregirlo, este PR habilita la configuración `apply_row_policy_after_final`, introducida en [#91065](https://github.com/ClickHouse/ClickHouse/issues/91065). Con `apply_row_policy_after_final` habilitado, ROW POLICY seguiría respetando FINAL de forma predeterminada, como antes. Este PR es un cambio incompatible porque modifica el comportamiento para `optimize_move_to_prewhere_if_final=1`. Ahora, para que ROW POLICY se aplique antes de FINAL, debe usarse `apply_row_policy_after_final` en lugar de `optimize_move_to_prewhere_if_final`. [#97279](https://github.com/ClickHouse/ClickHouse/pull/97279) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

Esto simplifica la migración de diccionarios globales definidos en XML a diccionarios por base de datos definidos en SQL, permitiendo que las consultas de diccionario existentes (por ejemplo, dictGet(&#39;name&#39;, …)) sigan funcionando sin modificaciones. Cierra [#90839](https://github.com/ClickHouse/ClickHouse/issues/90839). [#92776](https://github.com/ClickHouse/ClickHouse/pull/92776) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Los inserts asíncronos admiten quorum en paralelo. Los datos insertados se replican en el quorum. Si se encuentran duplicados, la consulta espera hasta que los datos insertados previamente también se hayan replicado. [#93356](https://github.com/ClickHouse/ClickHouse/pull/93356) ([Sema Checherinda](https://github.com/CheSema)).

* La configuración del servidor `insert_deduplication_version` permite migrar a un hash de deduplicación unificado. [#95409](https://github.com/ClickHouse/ClickHouse/pull/95409) ([Sema Checherinda](https://github.com/CheSema)).
* Nuevas opciones de configuración: logger.startup&#95;console&#95;level y logger.shutdown&#95;console&#95;level para permitir la sobrescritura del nivel de log de la consola durante el inicio y el apagado de ClickHouse, respectivamente. [#95919](https://github.com/ClickHouse/ClickHouse/pull/95919) ([Garrett Thomas](https://github.com/garrettthomaskth)).

* Se agregó la consulta `OPTIMIZE <table> DRY RUN PARTS <part names>` para simular fusiones sin hacer `commit` de la parte de resultado. Puede ser útil para pruebas: verificar la corrección de la fusión en la nueva versión, reproducir de forma determinista errores relacionados con fusiones y realizar benchmark del rendimiento de las fusiones de forma fiable. [#96122](https://github.com/ClickHouse/ClickHouse/pull/96122) ([Anton Popov](https://github.com/CurtizJ)).

Cuando está habilitada, las tablas no se cargan durante el inicio de la base de datos; en su lugar, se crea un `StorageTableProxy` ligero y el motor de tabla real se materializa en el primer acceso. [#96283](https://github.com/ClickHouse/ClickHouse/pull/96283) ([xiaohuanlin](https://github.com/xiaohuanlin)).

* Se agregó `system.fail_points` para inspeccionar los failpoints existentes en el servidor y si están habilitados o no. Esto ayudará a automatizar las pruebas. [#96762](https://github.com/ClickHouse/ClickHouse/pull/96762) ([Pedro Ferreira](https://github.com/PedroTadim)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se aceleran algunas operaciones de hash join mediante la implementación de dynamic dispatch para ColumnVector::replicate. [#79573](https://github.com/ClickHouse/ClickHouse/pull/79573) ([Raúl Marín](https://github.com/Algunenano)).
* Mejora del rendimiento para ParallelHashJoin en casos de predicados complejos. Anteriormente, las filas no unidas se procesaban en un único thread, lo cual es subóptimo; la idea de la optimización es paralelizar el procesamiento de dichas filas entre múltiples threads. Se puede activar o desactivar mediante el parámetro `parallel_non_joined_rows_processing`. Habilitado por defecto. [#92068](https://github.com/ClickHouse/ClickHouse/pull/92068) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Se permite el uso de cualquier expresión determinista en la clave primaria para el salto de datos (p. ej., `ORDER BY cityHash64(user_id)` / `ORDER BY length(user_id)`). Para expresiones deterministas, ClickHouse puede aplicar la expresión a las constantes de la consulta y usar el resultado en el índice de clave primaria para predicados como `=`, `IN` y `has`. Si la expresión también es inyectiva (p. ej., `ORDER BY hex(p)` u `ORDER BY reverse(tuple(reverse(p), hex(p)))`), el índice puede utilizarse eficazmente para las formas negadas: `!=`, `NOT IN` y `NOT has`. Cierra [#10685](https://github.com/ClickHouse/ClickHouse/issues/10685). Cierra [#82161](https://github.com/ClickHouse/ClickHouse/issues/82161). [#92952](https://github.com/ClickHouse/ClickHouse/pull/92952) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Se optimiza ligeramente el parsing del tipo JSON. [#93614](https://github.com/ClickHouse/ClickHouse/pull/93614) ([Pavel Kruglov](https://github.com/Avogar)).
* Se reduce el uso de memoria de ASTLiteral eliminando std::optional<TokenIterator> begin/end del objeto. La optimización tiene sentido dado que estos campos no se utilizan cuando no se emplea resaltado de sintaxis ni hay parsing de VALUES. [#93974](https://github.com/ClickHouse/ClickHouse/pull/93974) ([Ilya Yatsishin](https://github.com/qoega)).
* Se optimiza el consumo de memoria de los objetos AST de Tuple con nombre. Los nombres de columna se almacenan como cadenas en el objeto Tuple en lugar de ubicarlos en nodos AST literales genéricos. [#94704](https://github.com/ClickHouse/ClickHouse/pull/94704) ([Ilya Yatsishin](https://github.com/qoega)).
* Se mejora la devirtualización con opciones adicionales del enlazador. [#94737](https://github.com/ClickHouse/ClickHouse/pull/94737) ([Nikita Taranov](https://github.com/nickitat)).
* Se mejora el rendimiento de clonación de réplicas para tablas ReplicatedMergeTree con muchas partes agrupando en lotes las solicitudes a ZooKeeper. [#94847](https://github.com/ClickHouse/ClickHouse/pull/94847) ([c-end](https://github.com/c-end)).
* Si una consulta `FINAL` utilizaba una condición de clave primaria para el filtrado seguida de índices de salto para otras condiciones, el paso de procesamiento `PrimaryKeyExpand` ahora solo verificará los rangos de clave primaria preseleccionados inicialmente para determinar intersecciones. [#94903](https://github.com/ClickHouse/ClickHouse/pull/94903) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Se crea std::vector fuera del bucle `for` y se reserva memoria antes de este, evitando así asignaciones en cada iteración. [#95178](https://github.com/ClickHouse/ClickHouse/pull/95178) ([Alexey Bakharew](https://github.com/alexbakharew)).
* Cuando el paso de lectura ya tiene filtros PREWHERE, no es posible añadir un nuevo filtro. Este cambio pospone la optimización de PREWHERE hasta después de la optimización de los Runtime Filters de JOIN, de modo que dichos filtros también puedan trasladarse a PREWHERE. [#95838](https://github.com/ClickHouse/ClickHouse/pull/95838) ([Alexander Gololobov](https://github.com/davenger)).
* Se acelera la compresión del códec T64 mediante dynamic dispatch en x86. [#95881](https://github.com/ClickHouse/ClickHouse/pull/95881) ([Raúl Marín](https://github.com/Algunenano)).
* Se acelera `uniq` sobre tipos numéricos agrupando las inserciones en lotes cuando es posible (sin nulos, sin -If, sin GROUP BY, sin IPv6 ni String). [#95904](https://github.com/ClickHouse/ClickHouse/pull/95904) ([Raúl Marín](https://github.com/Algunenano)).
* Se ha detectado que `ZooKeeper::observeOperations` representa más del 20 % del consumo de CPU del thread de recepción de ZooKeeper. Este cambio lo aborda de la siguiente manera: 1. Para `AggregatedZooKeeperLog::stats`, se utiliza `CityHash64` en lugar de `SipHash`, que es más de 10 veces más rápido. 2. Para `Coordination::ErrorCounter`, se utiliza `std::array<std::atomic<UInt32>, N>` en lugar de `std::unordered_map` y `std::mutex`. [#95962](https://github.com/ClickHouse/ClickHouse/pull/95962) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Se revierte el alineamiento de 64 bytes para ProfileEvents::Counter. [#96097](https://github.com/ClickHouse/ClickHouse/pull/96097) ([Azat Khuzhin](https://github.com/azat)).
* Se reduce el tamaño de la estructura CachedOnDiskReadBufferFromFile en 50 veces. [#96098](https://github.com/ClickHouse/ClickHouse/pull/96098) ([Azat Khuzhin](https://github.com/azat)).
* Se evita copiar datos antiguos en HashTable::resize cuando está vacío. [#96180](https://github.com/ClickHouse/ClickHouse/pull/96180) ([Raúl Marín](https://github.com/Algunenano)).
* Se añade soporte de Runtime Filters de JOIN para `RIGHT OUTER` JOINs. [#96183](https://github.com/ClickHouse/ClickHouse/pull/96183) ([Hechem Selmi](https://github.com/m-selmi)).
* Anteriormente, la optimización de lectura directa del text index solo se aplicaba cuando todas las partes tenían un text index materializado. Este cambio añade soporte parcial: si algunas partes tienen un text index materializado, dichas partes lo utilizarán, mientras que las partes sin text index materializado recurrirán a ejecutar la expresión de filtro original. [#96411](https://github.com/ClickHouse/ClickHouse/pull/96411) ([Anton Popov](https://github.com/CurtizJ)).
* Se evita la regresión en el uso de memoria durante las inserciones cuando la deduplicación no está habilitada. [#96503](https://github.com/ClickHouse/ClickHouse/pull/96503) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se evita incluir las cabeceras boost/multiprecision en `wide_integer_impl.h` en plataformas con `long double` adecuado, mejorando el tiempo de compilación. TODO: CAMBIAR CATEGORÍA A BUILD SI EL RENDIMIENTO NO VARÍA. [#96633](https://github.com/ClickHouse/ClickHouse/pull/96633) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Retroportado en [#97942](https://github.com/ClickHouse/ClickHouse/issues/97942): En general, el bloque original es necesario para la deduplicación, pero en el caso de inserciones síncronas puede omitirse y liberar memoria de forma definitiva. [#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* Se añaden índices secundarios `minmax` en columnas de tiempo e índices `bloom_filter` en las columnas `query_id`/`initial_query_id` de las tablas de registro del sistema para acelerar el filtrado. [#96712](https://github.com/ClickHouse/ClickHouse/pull/96712) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* LZ4: Se acelera la descompresión de bloques de 32 bytes en x86. [#96778](https://github.com/ClickHouse/ClickHouse/pull/96778) ([Raúl Marín](https://github.com/Algunenano)).
* La optimización de materialización diferida ahora se aplica a todas las ramas de una consulta `UNION ALL`, no solo a la primera. Las consultas que combinan múltiples lecturas ordenadas y limitadas de distintas tablas `MergeTree` mediante `UNION ALL` se beneficiarán ahora de la lectura diferida de columnas en cada rama, lo que reduce la E/S. [#96832](https://github.com/ClickHouse/ClickHouse/pull/96832) ([Federico Ginosa](https://github.com/menxit)).
* Se optimiza el cálculo del índice de salto minmax durante las inserciones eliminando una copia de datos innecesaria y habilitando el cálculo vectorizado de mínimo/máximo para columnas numéricas. [#97392](https://github.com/ClickHouse/ClickHouse/pull/97392) ([Raúl Marín](https://github.com/Algunenano)).
* Retroportado en [#98184](https://github.com/ClickHouse/ClickHouse/issues/98184): Se mejoró el rendimiento del análisis de índice de texto para consultas con condiciones combinadas que involucran columnas indexadas y no indexadas. Anteriormente, la optimización de salida anticipada durante el análisis de índice se deshabilitaba incorrectamente en estos casos. [#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).

<div id="performance-optimization">
  #### Optimización del rendimiento
</div>

* El valor predeterminado de `concurrent_threads_scheduler` ahora es `max_min_fair` en lugar de `fair_round_robin`. Esto mejora la equidad con cargas elevadas al priorizar las consultas con menos slots asignados, de modo que las consultas de corta duración no se vean penalizadas por las de larga duración. [#95300](https://github.com/ClickHouse/ClickHouse/pull/95300) ([Sergei Trifonov](https://github.com/serxa)).
