<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Retroportado en [#98752](https://github.com/ClickHouse/ClickHouse/issues/98752): Activar async insert de forma predeterminada. Ahora ClickHouse agrupará por lotes todas las inserciones pequeñas de forma predeterminada. Esta configuración se establece en compatibility. Si establece `compatibility=<version less than 26.2>`, el valor predeterminado será el anterior, `false`. Puede desactivar o activar async inserts en varios niveles: en la configuración, en los perfiles de usuario, para la sesión, para la consulta o para la tabla MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).

<div id="improvement">
  #### Mejora
</div>

* Retroportado en [#98785](https://github.com/ClickHouse/ClickHouse/issues/98785): La nueva configuración `allow_nullable_tuple_in_extracted_subcolumns` controla si las subcolumnas `Tuple(...)` extraídas de `Tuple`, `Variant`, `Dynamic` y `JSON` se devuelven como `Nullable(Tuple(...))` (`NULL` para las filas ausentes) o como `Tuple(...)` (valores de tupla predeterminados para las filas ausentes). Está deshabilitada de forma predeterminada y solo puede cambiarse reiniciando el servidor. [#97299](https://github.com/ClickHouse/ClickHouse/pull/97299) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Retroportado en [#98481](https://github.com/ClickHouse/ClickHouse/issues/98481): Se añade la configuración del servidor `jemalloc_profiler_sampling_rate` para controlar `lg_prof_sample` de jemalloc y exponerla como la métrica asíncrona `jemalloc.prof.lg_sample`. [#97945](https://github.com/ClickHouse/ClickHouse/pull/97945) ([Antonio Andelic](https://github.com/antonio2368)).
* Retroportado en [#98488](https://github.com/ClickHouse/ClickHouse/issues/98488): Se añadió un nuevo evento de perfil, `KeeperRequestTotalWithSubrequests`, que cuenta individualmente cada subsolicitud dentro de una solicitud múltiple, lo que proporciona una mejor visibilidad de la carga de trabajo real de Keeper. El evento existente `KeeperRequestTotal` sigue contando cada solicitud múltiple como una sola solicitud. [#98348](https://github.com/ClickHouse/ClickHouse/pull/98348) ([Antonio Andelic](https://github.com/antonio2368)).
* Retroportado en [#98749](https://github.com/ClickHouse/ClickHouse/issues/98749): Solo las réplicas &quot;activas&quot; (es decir, aquellas a las que se puede conectar) participan en el análisis distribuido de índices. [#98521](https://github.com/ClickHouse/ClickHouse/pull/98521) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Corrección de errores (mal funcionamiento visible para el usuario en una versión estable oficial)
</div>

* Retroportado en [#98439](https://github.com/ClickHouse/ClickHouse/issues/98439): Corrige resultados incorrectos o excepciones durante la lectura de subcolumnas de columnas ALIAS. [#95408](https://github.com/ClickHouse/ClickHouse/pull/95408) ([Pavel Kruglov](https://github.com/Avogar)).
* Retroportado en [#98820](https://github.com/ClickHouse/ClickHouse/issues/98820): Corrige que la función de agregación `sumCount` no pudiera leer estados serializados antiguos tras la introducción de `Nullable(Tuple)`. Cierra [#97370](https://github.com/ClickHouse/ClickHouse/issues/97370). [#97502](https://github.com/ClickHouse/ClickHouse/pull/97502) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Retroportado en [#98659](https://github.com/ClickHouse/ClickHouse/issues/98659): Aplica comprobaciones READ ON FILE para file() escalar y DESCRIBE TABLE file(). [#98115](https://github.com/ClickHouse/ClickHouse/pull/98115) ([Nikolay Degterinsky](https://github.com/evillique)).
* Retroportado en [#98563](https://github.com/ClickHouse/ClickHouse/issues/98563): Corrige resultados incorrectos con el análisis distribuido de índices (característica experimental) y la caché de condiciones de consulta. [#98269](https://github.com/ClickHouse/ClickHouse/pull/98269) ([Azat Khuzhin](https://github.com/azat)).
* Retroportado en [#98774](https://github.com/ClickHouse/ClickHouse/issues/98774): Corrige `LOGICAL_ERROR: Not-ready Set is passed as the second argument for function 'in'` al usar `PREWHERE` con una subconsulta `IN` en tablas MergeTree. [#98522](https://github.com/ClickHouse/ClickHouse/pull/98522) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Retroportado en [#98651](https://github.com/ClickHouse/ClickHouse/issues/98651): Corrige la reversión de columnas en el motor Buffer al gestionar una excepción durante la adición de un bloque nuevo. La lógica anterior podía provocar un estado en memoria corrupto de las columnas. [#98551](https://github.com/ClickHouse/ClickHouse/pull/98551) ([Pavel Kruglov](https://github.com/Avogar)).
* Retroportado en [#98623](https://github.com/ClickHouse/ClickHouse/issues/98623): Se corrigió el uso del índice de texto con otros índices de omisión. Anteriormente, podían producirse errores lógicos como &quot;Trying to get non-existing mark&quot; cuando un filtro de consulta utilizaba simultáneamente un índice de texto y otros índices de omisión normales. [#98555](https://github.com/ClickHouse/ClickHouse/pull/98555) ([Anton Popov](https://github.com/CurtizJ)).
* Retroportado en [#98673](https://github.com/ClickHouse/ClickHouse/issues/98673): Corrige el análisis distribuido de índices con expresiones (no solo columnas) en la PK (provoca un filtrado nulo de gránulos redundantes en réplicas remotas). [#98561](https://github.com/ClickHouse/ClickHouse/pull/98561) ([Azat Khuzhin](https://github.com/azat)).
