<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se cambió la configuración predeterminada `schema_inference_make_columns_nullable` para que respete la información de `Nullable` de la columna presente en los metadatos de Parquet/ORC/Arrow, en lugar de hacer que todo sea Nullable. No hay cambios para los formatos de texto. [#71499](https://github.com/ClickHouse/ClickHouse/pull/71499) ([Michael Kolupaev](https://github.com/al13n321)).
* Este PR hace que la caché de resultados de consultas ignore la configuración `log_comment`, de modo que cambiar solo `log_comment` en una consulta ya no provoque un cache miss. Existe una pequeña posibilidad de que algunos usuarios segmentaran intencionalmente su caché variando `log_comment`. Este cambio modifica ese comportamiento y, por lo tanto, no es retrocompatible. Use la configuración `query_cache_tag` para este fin. [#79878](https://github.com/ClickHouse/ClickHouse/pull/79878) ([filimonov](https://github.com/filimonov)).
* En versiones anteriores, las consultas con funciones de tabla llamadas igual que las funciones de implementación de operadores se formateaban de forma inconsistente. Cierra [#81601](https://github.com/ClickHouse/ClickHouse/issues/81601). Cierra [#81977](https://github.com/ClickHouse/ClickHouse/issues/81977). Cierra [#82834](https://github.com/ClickHouse/ClickHouse/issues/82834). Cierra [#82835](https://github.com/ClickHouse/ClickHouse/issues/82835). Las consultas EXPLAIN SYNTAX no formatearán operadores; este nuevo comportamiento refleja mejor el propósito de explicar la sintaxis. `clickhouse-format`, `formatQuery` y herramientas similares no formatearán funciones como operadores si la consulta las contenía en forma funcional. [#82825](https://github.com/ClickHouse/ClickHouse/pull/82825) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se prohíbe usar el tipo Dynamic en las claves de JOIN. Esto podría producir resultados inesperados cuando un tipo Dynamic se compara con un tipo no Dynamic. Es mejor convertir la columna Dynamic al tipo requerido. [#86358](https://github.com/ClickHouse/ClickHouse/pull/86358) ([Pavel Kruglov](https://github.com/Avogar)).
* La opción del servidor Storage&#95;metadata&#95;write&#95;full&#95;object&#95;key está activada de forma predeterminada y ya no se puede desactivar. Este es un cambio retrocompatible. Usé la etiqueta para llamar la atención. Este cambio solo es compatible hacia adelante con las versiones 25.x. Eso significa que, si necesita revertir la nueva versión, solo podrá hacer downgrade a alguna versión 25.x. [#87335](https://github.com/ClickHouse/ClickHouse/pull/87335) ([Sema Checherinda](https://github.com/CheSema)).
* Se reduce replicated&#95;deduplication&#95;window&#95;seconds de 1 semana a una hora para almacenar menos znodes en ZooKeeper cuando la tasa de inserción es baja. [#87414](https://github.com/ClickHouse/ClickHouse/pull/87414) ([Sema Checherinda](https://github.com/CheSema)).
* Se cambió el nombre de la configuración `query_plan_use_new_logical_join_step` a `query_plan_use_logical_join_step`. [#87679](https://github.com/ClickHouse/ClickHouse/pull/87679) ([Vladimir Cherkasov](https://github.com/vdimir)).
* La nueva sintaxis permite que el parámetro tokenizer sea más expresivo. [#87997](https://github.com/ClickHouse/ClickHouse/pull/87997) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Se cambiaron los nombres de las funciones `searchAny` y `searchAll` a `hasAnyTokens` y `hasAllTokens` para mantener una mayor coherencia con la función existente `hasToken`. [#88109](https://github.com/ClickHouse/ClickHouse/pull/88109) ([Robert Schulze](https://github.com/rschu1ze)).
* Se elimina `cache_hits_threshold` de la caché del sistema de archivos. Esta funcionalidad fue añadida por un colaborador externo antes de que tuviéramos la cache policy SLRU y, ahora que la tenemos, no tiene sentido mantener ambas. [#88344](https://github.com/ClickHouse/ClickHouse/pull/88344) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Dos pequeños cambios en el funcionamiento de los ajustes `min_free_disk_ratio_to_perform_insert` y `min_free_disk_bytes_to_perform_insert`: - usar bytes no reservados en lugar de bytes disponibles para determinar si se debe rechazar un insert. Probablemente esto no sea crucial si las reservas para background merges y mutations son pequeñas en comparación con los umbrales configurados, pero parece más correcto. - No aplicar estos ajustes a las tablas del sistema. El motivo es que queremos seguir permitiendo que tablas como `query_log` se actualicen. Esto ayuda mucho con la depuración. Los datos escritos en las tablas del sistema suelen ser pequeños en comparación con los datos reales, por lo que deberían poder seguir escribiéndose durante mucho más tiempo con un umbral razonable de `min_free_disk_ratio_to_perform_insert`. [#88468](https://github.com/ClickHouse/ClickHouse/pull/88468) ([c-end](https://github.com/c-end)).
* Habilitar el modo asíncrono para la replicación interna de Keeper. Keeper conservará el mismo comportamiento que antes, con posibles mejoras del rendimiento. Si está actualizando desde una versión anterior a la 23.9, primero debe actualizar a la 23.9+ y después a la 25.10+. También puede establecer `keeper_server.coordination_settings.async_replication` en 0 antes de la actualización y habilitarlo una vez finalizada. [#88515](https://github.com/ClickHouse/ClickHouse/pull/88515) ([Antonio Andelic](https://github.com/antonio2368)).

* Se añadió compatibilidad con la sintaxis `LIMIT BY ALL`. Al igual que `GROUP BY ALL` y `ORDER BY ALL`, `LIMIT BY ALL` se expande automáticamente para usar todas las expresiones no agregadas de la cláusula SELECT como claves de LIMIT BY. Por ejemplo, `SELECT id, name, count(*) FROM table GROUP BY id LIMIT 1 BY ALL` es equivalente a `SELECT id, name, count(*) FROM table GROUP BY id LIMIT 1 BY id, name`. Esta funcionalidad simplifica las consultas cuando quieres limitar por todas las columnas no agregadas seleccionadas sin tener que enumerarlas explícitamente. Se comporta de forma similar a la función `histogram_quantile()` de PromQL en histogramas clásicos. [#86294](https://github.com/ClickHouse/ClickHouse/pull/86294) ([Stephen Chi](https://github.com/stephchi0)).
* Se añadió la capacidad de crear automáticamente estadísticas en todas las columnas adecuadas de las tablas `MergeTree`. Se añadió la configuración de nivel de tabla `auto_statistics_types`, que almacena los tipos de estadísticas que se deben crear separados por comas (p. ej., `auto_statistics_types = 'minmax, uniq, countmin'`). [#87241](https://github.com/ClickHouse/ClickHouse/pull/87241) ([Anton Popov](https://github.com/CurtizJ)).

[#87374](https://github.com/ClickHouse/ClickHouse/pull/87374) ([Guang Zhao](https://github.com/zheguang)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Se mejoró el rendimiento de las consultas refactorizando el orden y la integración de Query Condition Cache (QCC) con el análisis de índices. El filtrado de QCC ahora se aplica antes del análisis de la primary key y de los skip indexes, lo que reduce el cómputo innecesario de índices. El análisis de índices se ha ampliado para admitir varios filtros de rango, y sus resultados ahora se vuelven a almacenar en la QCC. Esto acelera significativamente las consultas en las que el análisis de índices domina el tiempo de ejecución, especialmente las que dependen de skip indexes (p. ej., índices vectoriales o invertidos). [#82380](https://github.com/ClickHouse/ClickHouse/pull/82380) ([Amos Bird](https://github.com/amosbird)).
* Se agrega la serialización opcional de la subcolumna `.size` para las columna String de nivel superior en tablas MergeTree, con el fin de mejorar la compresión y permitir un acceso eficiente a las subcolumnas. Se introducen nuevas configuraciones de MergeTree para controlar la versión de serialización y optimizar expresiones para cadenas vacías. [#82850](https://github.com/ClickHouse/ClickHouse/pull/82850) ([Amos Bird](https://github.com/amosbird)).
* Un conjunto de microoptimizaciones para acelerar las consultas pequeñas. [#83096](https://github.com/ClickHouse/ClickHouse/pull/83096) ([Raúl Marín](https://github.com/Algunenano)).
* Comprime logs y profile events en el native protocol. En clusters con más de 100 réplicas, los profile events sin comprimir ocupan entre 1 y 10 MB/s, y la barra de progreso se vuelve lenta en conexiones a Internet lentas. Esto cierra [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533). [#83586](https://github.com/ClickHouse/ClickHouse/pull/83586) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el rendimiento de la búsqueda en cadenas case sensitive (operaciones como el filtrado, por ejemplo `WHERE URL LIKE '%google%'`) mediante la biblioteca [StringZilla](https://github.com/ashvardanian/StringZilla), aprovechando instrucciones SIMD de la CPU cuando están disponibles. [#84161](https://github.com/ClickHouse/ClickHouse/pull/84161) ([Raúl Marín](https://github.com/Algunenano)).
* Reduce la asignación y copia de memoria al hacer select desde una tabla aggregating merge tree con FINAL cuando la tabla tiene columnas del tipo `SimpleAggregateFunction(anyLast)`. [#84428](https://github.com/ClickHouse/ClickHouse/pull/84428) ([Duc Canh Le](https://github.com/canhld94)).
* Proporciona una lógica para el pushdown de predicados disyuntivos en JOIN. Example: en TPC-H Q7, para una condición sobre 2 tablas n1 y n2 como `(n1.n_name = 'FRANCE' AND n2.n_name = 'GERMANY') OR (n1.n_name = 'GERMANY' AND n2.n_name = 'FRANCE')`, se extraen filtros parciales independientes para cada tabla: `n1.n_name = 'FRANCE' OR n1.n_name = 'GERMANY'` para n1 y `n2.n_name = 'GERMANY' OR n2.n_name = 'FRANCE'` para n2. [#84735](https://github.com/ClickHouse/ClickHouse/pull/84735) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Mejora el rendimiento de `LIKE` con prefijo o sufijo mediante la nueva configuración predeterminada `optimize_rewrite_like_perfect_affix`. [#85920](https://github.com/ClickHouse/ClickHouse/pull/85920) ([Guang Zhao](https://github.com/zheguang)).
* Corrige la degradación del rendimiento causada por una key serializada grande al agrupar por varias columnas de cadena o numéricas. Cierra https://github.com/ClickHouse/ClickHouse/pull/83884#issuecomment-3187972297 cc @mkmkme . Es una continuación de https://github.com/ClickHouse/ClickHouse/pull/83884. [#85924](https://github.com/ClickHouse/ClickHouse/pull/85924) ([李扬](https://github.com/taiyang-li)).
* Mejoras en DB::SharedMutex. [#87491](https://github.com/ClickHouse/ClickHouse/pull/87491) ([Raúl Marín](https://github.com/Algunenano)).
* Se mejoró el rendimiento de la creación del text index para documentos que contienen principalmente tokens poco frecuentes. [#87546](https://github.com/ClickHouse/ClickHouse/pull/87546) ([Anton Popov](https://github.com/CurtizJ)).
* Acelera el caso más habitual del destructor de Field. [#87631](https://github.com/ClickHouse/ClickHouse/pull/87631) ([Raúl Marín](https://github.com/Algunenano)).
* Se omite el recálculo de las estadísticas de la tabla hash en runtime durante la optimización de join. Se añadieron nuevos eventos de perfil `JoinOptimizeMicroseconds` y `QueryPlanOptimizeMicroseconds`. [#87683](https://github.com/ClickHouse/ClickHouse/pull/87683) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Se habilitó el guardado de marcas en caché y se evita la E/S directa para el lector MergeTreeLazy. [#87989](https://github.com/ClickHouse/ClickHouse/pull/87989) ([Nikita Taranov](https://github.com/nickitat)).
* La consulta SELECT con la cláusula `FINAL` en una tabla `ReplacingMergeTree` con la columna `is_deleted` ahora se ejecuta más rápido gracias a una mejor paralelización de 2 optimizaciones existentes: 1) la optimización `do_not_merge_across_partitions_select_final` para las particiones de la tabla que solo tienen una `part` 2) la división de otros rangos seleccionados de la tabla en `intersecting / non-intersecting`, de modo que solo los rangos `intersecting` tienen que pasar por la transformación de merge FINAL. [#88090](https://github.com/ClickHouse/ClickHouse/pull/88090) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Se reduce el impacto de no usar fail points. [#88196](https://github.com/ClickHouse/ClickHouse/pull/88196) ([Raúl Marín](https://github.com/Algunenano)).
* Se evita el full scan de `system.tables` al filtrar por `uuid` (puede ser útil si solo tiene el UUID a partir de los logs o de la ruta de ZooKeeper). [#88379](https://github.com/ClickHouse/ClickHouse/pull/88379) ([Azat Khuzhin](https://github.com/azat)).
* Se mejoró el rendimiento de las funciones `tokens`, `hasAllTokens`, `hasAnyTokens`. [#88416](https://github.com/ClickHouse/ClickHouse/pull/88416) ([Anton Popov](https://github.com/CurtizJ)).
* Lectura en orden para Iceberg. [#88454](https://github.com/ClickHouse/ClickHouse/pull/88454) ([scanhex12](https://github.com/scanhex12)).
* Se declaró `AddedColumns::appendFromBlock` como inline para mejorar ligeramente el rendimiento de join en algunos casos. [#88455](https://github.com/ClickHouse/ClickHouse/pull/88455) ([Nikita Taranov](https://github.com/nickitat)).
* Retroportado en [#89182](https://github.com/ClickHouse/ClickHouse/issues/89182): se implementó la replicación diferida de columnas en JOIN y ARRAY JOIN. Se evita convertir representaciones especiales de columnas, como Sparse y Replicated, en columnas completas en algunos formatos de salida. Esto evita copias de datos innecesarias en memoria. [#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar)).





<div id="improvement">
  #### Mejora

* Permite configurar la limitación de velocidad a nivel de servidor cuando la configuración se sobreescribe en Keeper. Cierra [#73964](https://github.com/ClickHouse/ClickHouse/issues/73964). [#74066](https://github.com/ClickHouse/ClickHouse/pull/74066) ([JIaQi](https://github.com/JiaQiTang98)).
* `mannWhitneyUTest` ya no lanza una excepción cuando ambas muestras contienen únicamente valores idénticos. Ahora devuelve un resultado válido, coherente con SciPy. Cierra: [#79814](https://github.com/ClickHouse/ClickHouse/issues/79814). [#80009](https://github.com/ClickHouse/ClickHouse/pull/80009) ([DeanNeaht](https://github.com/DeanNeaht)).
* La reescritura de transacciones de almacenamiento de objetos en disco elimina los blobs remotos anteriores si la transacción de metadatos se ha confirmado. [#81787](https://github.com/ClickHouse/ClickHouse/pull/81787) ([Sema Checherinda](https://github.com/CheSema)).
* Se corrigió el paso de optimización para expresiones de igualdad redundantes cuando la cardinalidad baja (LowCardinality) del tipo resultante difiere antes y después de la optimización. [#82651](https://github.com/ClickHouse/ClickHouse/pull/82651) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Cuando los clientes HTTP establecen la cabecera `X-ClickHouse-100-Continue: defer` además de `Expect: 100-continue`, ClickHouse no envía una respuesta `100 Continue` al cliente hasta que la validación de cuota se completa satisfactoriamente, evitando así el desperdicio de ancho de banda al transmitir cuerpos de solicitud que de todas formas serían descartados. Esto es relevante para las consultas INSERT en las que la consulta puede enviarse en la cadena de consulta de la URL y los datos se envían en el cuerpo de la solicitud. Abortar una solicitud sin enviar el cuerpo completo impide la reutilización de la conexión con HTTP/1.1, pero la latencia adicional introducida al abrir nuevas conexiones suele ser insignificante en comparación con la duración total del INSERT con grandes volúmenes de datos. [#84304](https://github.com/ClickHouse/ClickHouse/pull/84304) ([c-end](https://github.com/c-end)).
* El autocompletado del cliente es más rápido y consistente al utilizar `system.completions` en lugar de emitir múltiples consultas a tablas del sistema. [#84694](https://github.com/ClickHouse/ClickHouse/pull/84694) ([|2ustam](https://github.com/RuS2m)).
* Se aceleran algunas consultas JOIN construyendo un filtro de Bloom a partir del subárbol derecho en tiempo de ejecución y pasando dicho filtro al escaneo del subárbol izquierdo. Esto puede ser beneficioso para consultas como `SELECT avg(o_totalprice) FROM orders, customer, nation WHERE c_custkey = o_custkey AND c_nationkey=n_nationkey AND n_name = 'FRANCE'`. [#84772](https://github.com/ClickHouse/ClickHouse/pull/84772) ([Alexander Gololobov](https://github.com/davenger)).
* Se enmascaran las credenciales de S3 en los registros cuando se utiliza DATABASE ENGINE = Backup con almacenamiento S3. [#85336](https://github.com/ClickHouse/ClickHouse/pull/85336) ([Kenny Sun](https://github.com/hwabis)).
* Retroportado en [#88990](https://github.com/ClickHouse/ClickHouse/issues/88990): Hace visibles las optimizaciones del plan de consulta para el subplan de entrada de la subconsulta correlacionada, posponiendo su materialización. Parte de [#79890](https://github.com/ClickHouse/ClickHouse/issues/79890). [#85455](https://github.com/ClickHouse/ClickHouse/pull/85455) ([Dmitry Novik](https://github.com/novikd)).
* Se renombra `InterpreterSystemQuery::dropReplicaImpl` a `InterpreterSystemQuery::dropStorageReplica`. En `InterpreterSystemQuery::dropDatabaseReplica`: al eliminar con base de datos o eliminar la réplica completa, también se elimina la réplica de cada tabla de la base de datos. Si se proporciona `WITH TABLES`, se elimina la réplica de cada almacenamiento; de lo contrario, la lógica no cambia y solo se llama a `DatabaseReplicated::dropReplica` en las bases de datos. Al eliminar una réplica de base de datos con la ruta de Keeper: si se proporciona `WITH TABLES`, se restaura la base de datos como Atomic, se restauran las tablas RMT a partir de la sentencia en Keeper y se elimina la base de datos (las tablas restauradas también se eliminan); de lo contrario, solo se llama a `DatabaseReplicated::dropReplica` en la ruta de Keeper proporcionada. [#85637](https://github.com/ClickHouse/ClickHouse/pull/85637) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Se corrige el formato inconsistente del TTL cuando contiene una función `materialize`. Cierra [#82828](https://github.com/ClickHouse/ClickHouse/issues/82828). [#85749](https://github.com/ClickHouse/ClickHouse/pull/85749) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* El estado de la tabla Iceberg ya no se almacena en un objeto de almacenamiento. Esto debería permitir usar Iceberg en ClickHouse con consultas concurrentes. [#86062](https://github.com/ClickHouse/ClickHouse/pull/86062) ([Daniil Ivanik](https://github.com/divanik)).
