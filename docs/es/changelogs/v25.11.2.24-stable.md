  ### Lanzamiento de ClickHouse v25.11.2.24-stable (d4877847359) FIXME en comparación con v25.11.1.558-stable (16f22f3d744)

<div id="improvement">
  #### Mejora
</div>

* Retroportado en [#90983](https://github.com/ClickHouse/ClickHouse/issues/90983): Debido a [https://github.com/ClickHouse/ClickHouse/pull/90311](https://github.com/ClickHouse/ClickHouse/pull/90311), el formato de las estadísticas ha cambiado, y el servidor fallará si hay estadísticas en el formato antiguo. Este PR corrige el fallo y generará una excepción cuando las estadísticas existentes usen el formato heredado. Para evitar la excepción, debemos ejecutar `ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL` para regenerar las estadísticas&#96; y así corregirlo. [#90904](https://github.com/ClickHouse/ClickHouse/pull/90904) ([Han Fei](https://github.com/hanfei1991)).
* Retroportado en [#91193](https://github.com/ClickHouse/ClickHouse/issues/91193): Ahora se generará la excepción `HTTP_CONNECTION_LIMIT_REACHED` cuando se alcance `hard_limit` para la conexión de los client HTTP. Está configurado en `20000` para las conexiones de disco. [#91016](https://github.com/ClickHouse/ClickHouse/pull/91016) ([Sema Checherinda](https://github.com/CheSema)).
* Retroportado en [#91254](https://github.com/ClickHouse/ClickHouse/issues/91254): Se corrigió una posible inanición del grupo de subprocesos al leer muestras de columnas para columnas JSON con muchas subcolumnas, respetando la configuración `merge_tree_use_prefixes_deserialization_thread_pool` en lugar de usar incondicionalmente el grupo de subprocesos. [#91208](https://github.com/ClickHouse/ClickHouse/pull/91208) ([Raufs Dunamalijevs](https://github.com/rienath)).
