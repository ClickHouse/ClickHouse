<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se deshabilitan las operaciones binarias sin sentido con IPv4/IPv6: se deshabilitan la suma y la resta de una dirección IPv4/IPv6 con un tipo no entero. Antes se permitían operaciones con tipos de punto flotante y se producían errores lógicos con algunos otros tipos (como DateTime). [#86336](https://github.com/ClickHouse/ClickHouse/pull/86336) ([Raúl Marín](https://github.com/Algunenano)).
* Se depreca la configuración `allow_dynamic_metadata_for_data_lakes`. Ahora todas las tablas Iceberg intentan obtener del almacenamiento el esquema de tabla más actualizado antes de ejecutar cada consulta. [#86366](https://github.com/ClickHouse/ClickHouse/pull/86366) ([Daniil Ivanik](https://github.com/divanik)).
* El índice de texto invertido se rehízo desde cero para que escale con conjuntos de datos que no caben en RAM. [#86485](https://github.com/ClickHouse/ClickHouse/pull/86485) ([Anton Popov](https://github.com/CurtizJ)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Se admite el motor de tabla Alias. [#76569](https://github.com/ClickHouse/ClickHouse/pull/76569) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* Se añadió la función `arrayExcept`, que resta un Array tratado como conjunto de otro. [#82368](https://github.com/ClickHouse/ClickHouse/pull/82368) ([Joanna Hulboj](https://github.com/jh0x)).
* Se añade una nueva tabla del sistema, `database_replicas`, con información sobre las réplicas de bases de datos. [#83408](https://github.com/ClickHouse/ClickHouse/pull/83408) ([Konstantin Morozov](https://github.com/k-morozov)).
* Ahora los usuarios pueden usar NATS JetStream para consumir mensajes especificando los nuevos ajustes `nats_stream` y `nats_consumer` para el motor NATS. [#84799](https://github.com/ClickHouse/ClickHouse/pull/84799) ([Dmitry Novikov](https://github.com/dmitry-sles-novikov)).
* Se añade una nueva tabla, `system.aggregated_zookeeper_log`. La tabla contiene estadísticas (p. ej., número de operaciones, latencia media, errores) de las operaciones de ZooKeeper agrupadas por ID de sesión, ruta padre y tipo de operación, y se vuelca periódicamente en disco. [#85102](https://github.com/ClickHouse/ClickHouse/pull/85102) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Se añadió la función `isValidASCII` para comprobar si una cadena contiene solo caracteres ASCII. Cierra [#85377](https://github.com/ClickHouse/ClickHouse/issues/85377). [#85786](https://github.com/ClickHouse/ClickHouse/pull/85786) ([rajat mohan](https://github.com/rajatmohan22)).
* Tratar un nombre de ajuste sin valor en un ajuste de consulta como equivalente a `1` (p. ej., `SELECT ... SETTINGS use_query_cache` es equivalente a `use_query_cache = 1`). [#85800](https://github.com/ClickHouse/ClickHouse/pull/85800) ([thraeka](https://github.com/thraeka)).
* Nuevas opciones de configuración: `logger.startupLevel` y `logger.shutdownLevel` permiten sobrescribir el nivel de log durante el arranque y el apagado de ClickHouse, respectivamente. [#85967](https://github.com/ClickHouse/ClickHouse/pull/85967) ([Lennard Eijsackers](https://github.com/Blokje5)).
* Funciones de agregación `timeSeriesChangesToGrid` y `timeSeriesResetsToGrid`. Se comportan de forma similar a `timeSeriesRateToGrid`: aceptan parámetros para la marca de tiempo de inicio, la marca de tiempo de fin, el step y la ventana retrospectiva, además de dos argumentos para las marcas de tiempo y los valores, pero requieren al menos 1 sample por ventana en lugar de 2. Calculan `changes`/`resets` de PromQL, contando cuántas veces cambia o disminuye el valor del sample en la ventana especificada para cada marca de tiempo de la cuadrícula temporal definida por los parámetros. El tipo de retorno es Array(Nullable(Float64)). [#86010](https://github.com/ClickHouse/ClickHouse/pull/86010) ([Stephen Chi](https://github.com/stephchi0)).
* `ALTER UPDATE` para el motor de tabla Iceberg. [#86059](https://github.com/ClickHouse/ClickHouse/pull/86059) ([scanhex12](https://github.com/scanhex12)).
* Se añade la tabla del sistema `iceberg_metadata_log` para recuperar archivos de metadata de Iceberg durante las sentencias SELECT. [#86152](https://github.com/ClickHouse/ClickHouse/pull/86152) ([scanhex12](https://github.com/scanhex12)).
* Permite a los usuarios crear vistas temporales con la misma sintaxis que las tablas temporales. [#86432](https://github.com/ClickHouse/ClickHouse/pull/86432) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* Tablas Iceberg y delta lake con configuración de disco. Esto permite especificar tablas de usuario con un disco existente. Se añade el ajuste `allowed_disks_for_table_engines`, que permite usar discos específicos para Iceberg. Ejemplo: `CREATE TABLE test ENGINE = Iceberg('path/inside/disk') SETTING datalake_disk_name = '<some_user_disk>';` ### Entrada de documentación para cambios orientados al usuario. [#86778](https://github.com/ClickHouse/ClickHouse/pull/86778) ([scanhex12](https://github.com/scanhex12)).
* Añadir advertencias de CPU y memoria a la tabla `system.warnings`. [#86838](https://github.com/ClickHouse/ClickHouse/pull/86838) ([Bharat Nallan](https://github.com/bharatnc)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Mejora de la optimización de PREWHERE para condiciones como `func(primary_column) = 'xx'` y `column in (xxx)`. [#85529](https://github.com/ClickHouse/ClickHouse/pull/85529) ([李扬](https://github.com/taiyang-li)).
* Se implementó la reescritura de JOIN: 1. Convierte `LEFT ANY JOIN` y `RIGHT ANY JOIN` en JOIN `SEMI`/`ANTI` si la condición de filtro siempre es false para las filas coincidentes o no coincidentes. Esta optimización está controlada por el nuevo ajuste `query_plan_convert_any_join_to_semi_or_anti_join`. 2. Convierte `FULL ALL JOIN` en JOIN `LEFT ALL` o `RIGHT ALL` si la condición de filtro siempre es false para las filas no coincidentes de uno de los lados. [#86028](https://github.com/ClickHouse/ClickHouse/pull/86028) ([Dmitry Novik](https://github.com/novikd)).
* Se mejoró el rendimiento de las fusiones verticales tras ejecutar una eliminación ligera. [#86169](https://github.com/ClickHouse/ClickHouse/pull/86169) ([Anton Popov](https://github.com/CurtizJ)).
* Se optimizó ligeramente el rendimiento de `HashJoin` cuando el join `LEFT/RIGHT` tiene muchas filas sin coincidencia. [#86312](https://github.com/ClickHouse/ClickHouse/pull/86312) ([Nikita Taranov](https://github.com/nickitat)).
* RadixSort: ayuda al compilador a usar SIMD y a que la CPU realice una mejor precarga. Usa despacho dinámico para utilizar precarga por software solo en CPU Intel. Continúa el trabajo de @taiyang-li en [https://github.com/ClickHouse/ClickHouse/pull/77029](https://github.com/ClickHouse/ClickHouse/pull/77029). [#86378](https://github.com/ClickHouse/ClickHouse/pull/86378) ([Raúl Marín](https://github.com/Algunenano)).
* La reordenación de JOIN ahora usa estadísticas. La característica puede habilitarse estableciendo `allow_statistics_optimize = 1` y `query_plan_optimize_join_order_limit = 10`. [#86822](https://github.com/ClickHouse/ClickHouse/pull/86822) ([Han Fei](https://github.com/hanfei1991)).
* Mejora el rendimiento de las consultas rápidas con muchas partes en la tabla (optimizando `MarkRanges` mediante el uso de `devector` en lugar de `deque`). [#86933](https://github.com/ClickHouse/ClickHouse/pull/86933) ([Azat Khuzhin](https://github.com/azat)).
* Se mejoró el rendimiento de la aplicación de partes de parche en modo join. [#87094](https://github.com/ClickHouse/ClickHouse/pull/87094) ([Anton Popov](https://github.com/CurtizJ)).

* Soporte para Unity Catalog sobre Azure blob storage. [#80013](https://github.com/ClickHouse/ClickHouse/pull/80013) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Se añadió una optimización experimental del orden de los JOIN que puede reordenarlos automáticamente para mejorar el rendimiento (controlada por la configuración `query_plan_optimize_join_order_limit`). Tenga en cuenta que esta optimización actualmente tiene soporte limitado de estadísticas y se basa principalmente en estimaciones del recuento de filas de los motores de almacenamiento; en versiones futuras se añadirán una recopilación de estadísticas y una estimación de cardinalidad más sofisticadas. **Si encuentra issues con consultas JOIN después de actualizar**, puede deshabilitar temporalmente la nueva implementación estableciendo `SET query_plan_use_new_logical_join_step = 0` y reportar el issue para su investigación. **Nota sobre la resolución de identificadores de la cláusula USING**: se cambió la resolución de la columna fusionada de la cláusula `OUTER JOIN ... USING` para que sea más coherente: anteriormente, al seleccionar tanto la columna de USING como las columnas calificadas (`a, t1.a, t2.a`) en un OUTER JOIN, la columna de USING se resolvía incorrectamente como `t1.a`, mostrando 0/NULL para las filas de la tabla derecha sin coincidencia a la izquierda. Ahora, los identificadores de la cláusula USING siempre se resuelven a la columna fusionada, mientras que los identificadores calificados se resuelven a las columnas no fusionadas, independientemente de qué otros identificadores estén presentes en la consulta. Por ejemplo: &#96;&#96;&#96;sql SELECT a, t1.a, t2.a FROM (SELECT 1 as a WHERE 0) t1 FULL JOIN (SELECT 2 as a) t2 USING (a) -- Antes: a=0, t1.a=0, t2.a=2 (incorrecto: &#39;a&#39; se resolvía como t1.a) -- Después: a=2, t1.a=0, t2.a=2 (correcto: &#39;a&#39; es la columna fusionada). [#80848](https://github.com/ClickHouse/ClickHouse/pull/80848) ([Vladimir Cherkasov](https://github.com/vdimir)).
