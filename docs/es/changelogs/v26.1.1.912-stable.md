<div id="backward-incompatible-change">
  #### Cambio con Incompatibilidad hacia Atrás
</div>

* Se corrige el formato inconsistente causado por una sustitución incorrecta de alias en el formateador. Cierra [#82833](https://github.com/ClickHouse/ClickHouse/issues/82833). Cierra [#82832](https://github.com/ClickHouse/ClickHouse/issues/82832). Cierra [#68296](https://github.com/ClickHouse/ClickHouse/issues/68296). Este cambio es potencialmente incompatible hacia atrás: cuando el analizador está deshabilitado, ciertas consultas CREATE VIEW con IN que hacen referencia a un alias no pueden procesarse. Para evitar la incompatibilidad, habilite el analizador (habilitado por defecto desde la versión 24.3). [#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Los códecs `DEFLATE_QPL` y `ZSTD_QAT` han sido eliminados. Se recomienda convertir los datos existentes comprimidos con `DEFLATE_QPL` o `ZSTD_QAT` a otro códec antes de actualizar. Tenga en cuenta que para usar estos códecs era necesario habilitar los ajustes `enable_deflate_qpl_codec` y `enable_zstd_qat_codec`. [#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze)).
* Se corrige la depuración de UDF habilitando la captura de stderr en `system.query_log.exception`. Anteriormente, el stderr de los UDF solo se registraba en archivos y no se exponía en los registros de consultas, lo que hacía imposible depurarlos. Ahora, stderr genera excepciones por defecto y se acumula por completo (hasta 1 MB) antes de lanzarlas, de modo que los trazados completos de Python y los mensajes de error aparecen en `system.query_log.exception` para facilitar la resolución de problemas. [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
* Una lista de columnas vacía en la cláusula `JOIN USING ()` ahora se considera un error de sintaxis. Anteriormente, se esperaba que produjera `INVALID_JOIN_ON_EXPRESSION` durante la ejecución de la consulta. En algunos casos, como al hacer join con el almacenamiento `Join`, generaba un `LOGICAL_ERROR`. Cierra [#82502](https://github.com/ClickHouse/ClickHouse/issues/82502). [#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Se habilitan los datos compartidos avanzados para JSON por defecto. Tras este cambio, no será posible hacer downgrade a versiones anteriores a la 25.8, ya que dichas versiones no podrán leer las nuevas partes de datos con columna JSON. Para actualizaciones seguras, se recomienda establecer el ajuste `compatibility` a la versión anterior, o bien configurar los ajustes de MergeTree `dynamic_serialization_version='v2', object_serialization_version='v2'`. [#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar)).
* Se usa coincidencia parcial para SKIP REGEXP en el tipo JSON por defecto. Cierra [#79250](https://github.com/ClickHouse/ClickHouse/issues/79250). [#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar)).
* Se revierte &quot;Allow INSERT into simple ALIAS columns&quot; (revierte ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154)). No funciona con formatos personalizados y no está protegido por ningún ajuste. [#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat)).
* Se añade un ajuste para lanzar un error si el catálogo de datalake no tiene acceso al almacenamiento de objetos. [#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* El motor de base de datos `Lazy` ha sido eliminado y ya no está disponible. Cierra [#91231](https://github.com/ClickHouse/ClickHouse/issues/91231). [#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se elimina el modo `transposed_with_wide_view` de `metric_log`, ya que no es utilizable debido a un error. Ya no es posible definir `system.metric_log` con este modo. Esto revierte parcialmente [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412). [#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La planificación de CPU para cargas de trabajo ahora es apropiativa por defecto. Consulte el ajuste de servidor `cpu_slot_preemption`. [#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa)).
* Se escapan los nombres de archivo de índice para evitar partes corruptas. Con este cambio, ClickHouse no podrá cargar índices cuyos nombres contengan caracteres no ASCII creados por versiones anteriores. Para gestionar esta situación, puede usar el ajuste de MergeTree `escape_index_filenames`. [#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano)).
* Los ajustes de formato `exact_rows_before_limit`, `rows_before_aggregation`, `cross_to_inner_join_rewrite`, `regexp_dict_allow_hyperscan`, `regexp_dict_flag_case_insensitive`, `regexp_dict_flag_dotall` y `dictionary_use_async_executor` han pasado a ser ajustes regulares (no de formato). Se trata de un cambio puramente interno sin efectos visibles para el usuario, salvo en el caso (improbable) de que alguno de estos ajustes se haya especificado en definiciones de motores de tabla Iceberg, DeltaLake, Kafka, S3, S3Queue, Azure, Hive, RabbitMQ, Set, FileLog o NATS. En esos casos, dichos ajustes se ignoraban anteriormente; ahora tales definiciones generan un error. [#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze)).
* Las funciones `joinGet/joinGetOrNull` ahora exigen privilegios `SELECT` sobre la tabla Join subyacente. Tras este cambio, ejecutar `joinGet('db.table', 'column', key)` requiere que el usuario tenga el privilegio `SELECT` tanto sobre las columnas clave definidas en la tabla Join como sobre la columna de atributo que se recupera. Las consultas que carezcan de estos privilegios fallarán con `ACCESS_DENIED`. Para migrar, otorgue los permisos necesarios mediante `GRANT SELECT ON db.join_table TO user` para acceso completo a la tabla, o `GRANT SELECT(key_col, attr_col) ON db.join_table TO user` para acceso a nivel de columna. Este cambio afecta a todos los usuarios y aplicaciones que dependan de `joinGet`/`joinGetOrNull` y en los que no se hubieran configurado previamente privilegios `SELECT` explícitos. [#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Se verifica `SHOW COLUMNS` para las consultas `CREATE TABLE ... AS ...`. Anteriormente se comprobaba `SHOW TABLES`, lo cual es un privilegio incorrecto para este tipo de verificación de permisos. [#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit)).

* API HTTP e interfaz web integrada para CH Keeper. [#78181](https://github.com/ClickHouse/ClickHouse/pull/78181) ([pufit](https://github.com/pufit)).

* La deduplicación de inserciones asíncronas ahora funciona con vistas materializadas dependientes. Cuando se produce una colisión por block&#95;id, el bloque original se filtra para eliminar las filas asociadas con el block&#95;id, y las filas restantes se transforman con todas las consultas SELECT de las vistas materializadas pertinentes; esto reconstruye el bloque original sin las filas en conflicto. [#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* Se añadió la capacidad de que clickhouse client sobrescriba el TLS SNI al conectarse al servidor. [#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).

* Nueva tabla del sistema zookeeper&#95;info. Corrige [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014). [#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Se implementó FunctionVariantAdaptor para admitir el tipo Variant en funciones. [#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* Añade una métrica `ClickHouse_Info` al endpoint `/metrics` de Prometheus que contiene principalmente información de versión, por lo que es posible crear gráficos para seguir información detallada de las versiones a lo largo del tiempo. [#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* Se introduce un nuevo comando de cuatro letras `rcfg` para Keeper que permite cambiar la configuración del clúster. Este comando ofrece más posibilidades de cambio de configuración que la solicitud estándar `reconfigure`. El comando toma una cadena `json` como argumento. El conjunto completo de bytes enviados a la interfaz TCP debe verse así: `rcfg{json_string_length_big_endian}{json_string}`. Algunos ejemplos del comando pueden verse así: `{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`. [#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* Se añade la función `reverseBySeparator`, que invierte el orden de las subcadenas de una cadena separadas por un separador especificado. Cierra [#91463](https://github.com/ClickHouse/ClickHouse/issues/91463). [#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* Se introdujo una nueva sintaxis y un nuevo framework para simplificar y ampliar la funcionalidad de índices de proyección. Esto da continuidad a https://github.com/ClickHouse/ClickHouse/pull/81021. [#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* Compatibilidad con REST catalog de Paimon, continuando desde https://github.com/ClickHouse/ClickHouse/pull/84423. [#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* Añade la nueva configuración `max_insert_block_size_bytes`, que permite controlar con mayor detalle la formación de los bloques insertados. [#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* Es posible ejecutar consultas DDL con la cláusula `ON CLUSTER` para una base de datos Replicated si está habilitada la configuración `ignore_on_cluster_for_replicated_database`. En este caso, se ignorará el nombre del clúster. [#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* Implementa la función `mergeTreeAnalyzeIndex()`. [#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* Añade la nueva configuración `use_primary_key`. Establécela en `false` para deshabilitar la poda de gránulos basada en la clave primaria. [#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Función de tabla `icebergLocalCluster`. [#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* El prewhere para datalakes y el prewhere multietapa en el lector de Parquet v3 resuelven [#89101](https://github.com/ClickHouse/ClickHouse/issues/89101). [#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Añade la función `cosineDistanceTransposed`, que aproxima la [distancia de coseno](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance) entre dos puntos. [#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* La instrucción anterior para vaciar cachés, `SYSTEM DROP [...] CACHE`, daba la falsa impresión de que deshabilitaba la caché. ClickHouse ahora admite la instrucción `SYSTEM CLEAR [...] CACHE`, que resulta más clara. La sintaxis anterior sigue estando disponible. [#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* Añade la columna files a la tabla system.parts, que muestra el número de archivos en cada data part. [#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* Añade un planificador max-min justo para el control de concurrencia. Proporciona una mejor equidad en situaciones de alta sobresuscripción, cuando muchas consultas compiten por slots de CPU limitados. Las consultas de corta duración no se ven penalizadas por las de larga duración, que con el tiempo han acumulado más slots. Se habilita con el valor `max_min_fair` de la configuración del servidor `concurrent_threads_scheduler`. [#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

[#87299](https://github.com/ClickHouse/ClickHouse/pull/87299) ([Nikita Taranov](https://github.com/nickitat)).
* El filtro externo se empuja a la vista, lo que permite aplicar PREWHERE en nodos locales y remotos. Resuelve [#88189](https://github.com/ClickHouse/ClickHouse/issues/88189). [#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).
* Se implementaron compilaciones JIT para más funciones. Cierra [#73509](https://github.com/ClickHouse/ClickHouse/issues/73509). [#88770](https://github.com/ClickHouse/ClickHouse/pull/88770) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se optimizó el rendimiento y el uso de memoria para `LIMIT` y `OFFSET` fraccionarios. [#91167](https://github.com/ClickHouse/ClickHouse/pull/91167) ([Ahmed Gouda](https://github.com/0xgouda)).
* Se corrigió el uso de una lógica de lectura aleatoria más rápida en Parquet Reader V3 Prefetcher. Cierra [#90890](https://github.com/ClickHouse/ClickHouse/issues/90890). [#91435](https://github.com/ClickHouse/ClickHouse/pull/91435) ([Arsen Muk](https://github.com/arsenmuk)).

* Se redujo el uso de memoria de INSERT/merges con wide parts para tablas muy anchas al habilitar búferes de escritura adaptativos. Se añadió compatibilidad con búferes de escritura adaptativos para discos cifrados. [#92250](https://github.com/ClickHouse/ClickHouse/pull/92250) ([Azat Khuzhin](https://github.com/azat)).

* Se mejoró el rendimiento de la búsqueda de texto completo con índice de texto y el tokenizer `sparseGrams` al reducir el número de tokens buscados en el índice. [#93078](https://github.com/ClickHouse/ClickHouse/pull/93078) ([Anton Popov](https://github.com/CurtizJ)).
* Se usa el método &quot;fastrange&quot; (Daniel Lemire) para particionar datos dentro del pipeline de consulta. Esto podría mejorar la ordenación en paralelo y los JOINs. [#93080](https://github.com/ClickHouse/ClickHouse/pull/93080) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimiza `uniqExact` en los casos en que suelen aparecer consecutivamente elementos idénticos. [#93268](https://github.com/ClickHouse/ClickHouse/pull/93268) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La función `isValidASCII` se optimizó para resultados positivos, es decir, valores de entrada compuestos íntegramente por ASCII. [#93347](https://github.com/ClickHouse/ClickHouse/pull/93347) ([Robert Schulze](https://github.com/rschu1ze)).
* La función `isValidASCII` se optimizó para resultados positivos, es decir, valores de entrada compuestos íntegramente por ASCII. [#93611](https://github.com/ClickHouse/ClickHouse/pull/93611) ([Robert Schulze](https://github.com/rschu1ze)).
* Omite la lectura del lado izquierdo del hash join cuando el lado derecho está vacío. Antes, se leía el lado izquierdo hasta el primer bloque no vacío, lo que podía implicar mucho trabajo en casos con filtrado intenso o agregación. [#94062](https://github.com/ClickHouse/ClickHouse/pull/94062) ([Alexander Gololobov](https://github.com/davenger)).
* La optimización de lectura en orden ahora reconoce cuándo las columnas de ORDER BY son constantes debido a las condiciones de WHERE, lo que permite lecturas eficientes en orden inverso. Esto beneficia a consultas multitenant como &#96;WHERE tenant=&#39;42&#39; ORDER BY tenant, event&#95;time DESC&#96;, que ahora pueden usar InReverseOrder en lugar de requerir una ordenación completa.&quot;. [#94103](https://github.com/ClickHouse/ClickHouse/pull/94103) ([matanper](https://github.com/matanper)).
* Introduce una class especializada de Enum AST para almacenar parámetros de valor como pares cadena-entero en lugar de hijos de ASTLiteral, con el fin de optimizar el consumo de memoria. [#94178](https://github.com/ClickHouse/ClickHouse/pull/94178) ([Ilya Yatsishin](https://github.com/qoega)).

</div>

* Soporte para múltiples columnas como clave primaria en StorageEmbeddedRocksDB. Cierra [#32819](https://github.com/ClickHouse/ClickHouse/issues/32819). [#33917](https://github.com/ClickHouse/ClickHouse/pull/33917) ([usurai](https://github.com/usurai)).

[#64577](https://github.com/ClickHouse/ClickHouse/pull/64577) ([Francisco J. Jurado Moreno](https://github.com/Beetelbrox)).
* Se añade la sintaxis `ALTER TABLE <table> ATTACH PART <part_name> FROM <directory_name>` para la consulta `ALTER`. Permite adjuntar partes desde cualquier subdirectorio del directorio `detached/`. Resulta útil para adjuntar partes con prefijos personalizados (como `broken-on-start`, `unexpected`, etc.) que fueron desvinculadas por error y solo necesitan volver a adjuntarse sin intervención manual. Anteriormente, era necesario renombrar manualmente los directorios en el sistema de archivos. * Soporte para estrategia de rotación compuesta (tamaño + tiempo) en el registro del servidor. [#87620](https://github.com/ClickHouse/ClickHouse/pull/87620) ([Jianmei Zhang](https://github.com/zhangjmruc)).
* El cliente CLI ahora puede especificar `<warnings>false</warnings>` en lugar del argumento de línea de comandos `--no-warnings`. [#87783](https://github.com/ClickHouse/ClickHouse/pull/87783) ([Larry Snizek](https://github.com/larry-cdn77)).

* Soporte para más motores de tablas y tipos de fuentes de datos en subconsultas correlacionadas. Cierra [#80775](https://github.com/ClickHouse/ClickHouse/issues/80775). [#90175](https://github.com/ClickHouse/ClickHouse/pull/90175) ([Dmitry Novik](https://github.com/novikd)).
* Si el esquema de una vista parametrizada se especifica explícitamente, ahora se muestra.
