<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Corrige los metadatos de las proyecciones normales para que las proyecciones con claves de ordenación de varias columnas se reconozcan correctamente. Se basa en [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429). [#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* Propaga las versiones de serialización de los tipos de datos a los tipos de datos anidados. Por ejemplo, la versión de serialización `with_size_stream` de String antes solo se aplicaba a las columnas String de nivel superior y a los elementos de Tuple. Ahora se aplica a cualquier tipo String dentro de cualquier tipo anidado, como Array/Map/Variant/JSON/etc. Este comportamiento está controlado por la configuración de MergeTree `propagate_types_serialization_versions_to_nested_types`, que ahora está habilitada de forma predeterminada. Después de este cambio, las nuevas partes de datos creadas no pueden ser leídas por versiones anteriores, pero las partes antiguas pueden leerse en la nueva versión sin problemas. Esto significa que la actualización es segura, pero la reversión no lo es. [#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* Elimina el tipo de skip index `hypothesis`. Era una funcionalidad poco conocida y experimental, con una utilidad práctica limitada. Crear tablas con `INDEX ... TYPE hypothesis` ahora producirá un error. [#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige un problema por el que los archivos de skip index no respetaban la configuración replace&#95;long&#95;file&#95;name&#95;to&#95;hash, lo que provocaba errores de &quot;File name too long&quot; y fallos de lectura de índices con nombres largos. Los nombres de archivo de skip index ahora se convierten en hash cuando superan max&#95;file&#95;name&#95;length, de forma similar a los archivos de columnas. Esto es compatible con versiones anteriores (los servidores nuevos leen las partes antiguas), pero una reversión (o los servidores antiguos durante una actualización progresiva) puede hacer que se ignoren los índices con nombres largos. [#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* Activa async insert de forma predeterminada. ClickHouse ahora hará batching de todos los inserts pequeños de forma predeterminada. Esta configuración se establece en compatibility. Si se establece `compatibility=<version less than 26.2>`, el valor predeterminado será el anterior, `false`. Se pueden desactivar o activar los async inserts en varios niveles: en la configuración de los perfiles de usuario, para la sesión, para la consulta o para la tabla MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* Corrige la precedencia del operador `NOT` para que coincida con el estándar SQL: `NOT` ahora tiene menor precedencia que `IS NULL`, `BETWEEN`, `LIKE` y los operadores aritméticos. Por ejemplo, `NOT (x) IS NULL` ahora se analiza como `NOT (x IS NULL)` en lugar de `(NOT x) IS NULL`. Esto puede cambiar el resultado de las consultas que dependían del comportamiento anterior (no estándar). [#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Cambia el valor predeterminado de `mysql_datatypes_support_level` de vacío a `decimal,datetime64,date2Date32`, lo que habilita la asignación correcta de `DATE` de MySQL a `Date32`, `DECIMAL`/`NUMERIC` a `Decimal` y `DATETIME`/`TIMESTAMP` con precisión a `DateTime64` de forma predeterminada. Anteriormente, las columnas `DATE` de MySQL se asignaban a `Date`, que no puede representar fechas anteriores a 1970-01-01, lo que provocaba corrupción de datos. [#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acepta un Array de nombres de partes en lugar de una expresión regular para `mergeTreeAnalyzeIndexes{,UUID}`, ya que las expresiones regulares son lentas (*funcionalidad experimental*). [#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* Elimina la función experimental `detectProgrammingLanguage`. [#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

[#98140](https://github.com/ClickHouse/ClickHouse/pull/98140) ([Grant Holly](https://github.com/grantholly-clickhouse)).

Cuando está habilitada, los usuarios/roles restaurados tienen sus grants limitados a lo que el usuario que realiza la restauración puede conceder (con la misma semántica que `GRANT CURRENT GRANTS`), en lugar de fallar con `ACCESS_DENIED`. [#98795](https://github.com/ClickHouse/ClickHouse/pull/98795) ([pufit](https://github.com/pufit)).
* Se añaden las funciones `caseFoldUTF8` y `removeDiacriticsUTF8` para case folding de Unicode y la eliminación de marcas diacríticas. [#98973](https://github.com/ClickHouse/ClickHouse/pull/98973) ([George Larionov](https://github.com/george-larionov)).

* Se añade la función de cadena `normalizeUTF8NFKCCasefold` para la normalización Unicode NFKC&#95;Casefold, que combina la normalización NFKC con case folding. [#99276](https://github.com/ClickHouse/ClickHouse/pull/99276) ([George Larionov](https://github.com/george-larionov)).

Si el número o la proporción de segmentos no disponibles supera el umbral configurado, se genera una excepción en lugar de devolver silenciosamente resultados incompletos. [#99369](https://github.com/ClickHouse/ClickHouse/pull/99369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Los usuarios ahora pueden usar la palabra clave `SOME` para expresiones de subconsulta. Se comporta de forma idéntica a `ANY`. [#99842](https://github.com/ClickHouse/ClickHouse/pull/99842) ([Artem Kytkin](https://github.com/Vinceent)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Optimiza la omisión de gránulos para `pointInPolygon` en polígonos grandes y corrige las excepciones del análisis de índices de `pointInPolygon` durante la poda de la clave primaria. [#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Mejora el rendimiento de la función `levenshteinDistance`. [#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)).
* Optimiza las conversiones por lotes del tipo Decimal evitando llamadas a funciones por elemento. [#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 1. Iceberg incorpora la capacidad de precargar metadatos en caché de forma asíncrona. Esto se puede habilitar configurando `iceberg_metadata_async_prefetch_period_ms` al crear la tabla. P. ej.: `CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. Las consultas SELECT sobre tablas Iceberg ahora pueden ejecutarse especificando el parámetro `iceberg_metadata_staleness_ms`, lo que permite a ClickHouse basarse en la versión en caché de los metadatos si es más reciente que el nivel de obsolescencia especificado. De lo contrario, se consultará el catálogo Iceberg remoto para obtener los metadatos más recientes y procesar la solicitud (como funcionaba antes). Con este cambio, podemos reducir a 0 las llamadas al catálogo Iceberg durante el procesamiento de solicitudes, lo que debería aportar una mejora visible del rendimiento. Ejemplo: `SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`. [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)).
* El modo ordenado de S3Queue usa S3 ListObjectsV2 StartAfter para evitar volver a listar todo el historial del prefijo, lo que reduce las llamadas a ListObjects. [#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* En general, el bloque original es necesario para la deduplicación, pero en la inserción síncrona puede omitirse y ahorrar esa memoria definitivamente. [#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* Habilita lecturas paralelas desde el motor de tabla YTsaurus. [#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Usa un valor específico de la arquitectura para el tamaño de la línea de caché en lugar de un valor fijo de 64. [#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
* Añade compatibilidad para intercambiar los lados de los joins ANTI, SEMI y FULL en función de las estadísticas del optimizador. [#97498](https://github.com/ClickHouse/ClickHouse/pull/97498) ([Hechem Selmi](https://github.com/m-selmi)).
* Se optimizó ligeramente la lectura desde el diccionario del índice de texto, mejorando el rendimiento general del análisis del índice de texto. [#97519](https://github.com/ClickHouse/ClickHouse/pull/97519) ([Anton Popov](https://github.com/CurtizJ)).
* Acelera la descompresión LZ4 de bloques de 16 bytes en ARM. [#97774](https://github.com/ClickHouse/ClickHouse/pull/97774) ([Raúl Marín](https://github.com/Algunenano)).
* Refactoriza la tokenización con una nueva interfaz de callback `forEachToken` de alto rendimiento, que reemplaza la antigua API de estilo iterador para admitir SIMD y tokenizadores con estado. Parte de [#90268](https://github.com/ClickHouse/ClickHouse/issues/90268). [#97871](https://github.com/ClickHouse/ClickHouse/pull/97871) ([Amos Bird](https://github.com/amosbird)).
* Se mejoró el rendimiento del análisis del índice de texto para consultas con condiciones combinadas que involucran tanto columnas indexadas como no indexadas. Anteriormente, la optimización de salida anticipada durante el análisis del índice se deshabilitaba incorrectamente en esos casos. [#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).
* Mejora el rendimiento de las consultas con expresiones constantes que generan arrays o mapas muy largos. [#98287](https://github.com/ClickHouse/ClickHouse/pull/98287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige el análisis de la condición de clave para claves primarias `DateTime64` comparadas con constantes enteras, lo que antes impedía la poda de gránulos. [#98410](https://github.com/ClickHouse/ClickHouse/pull/98410) ([Amos Bird](https://github.com/amosbird)).

[#98482](https://github.com/ClickHouse/ClickHouse/pull/98482) ([Nihal Z. Miaji](https://github.com/nihalzp)).

Cierra [#85167](https://github.com/ClickHouse/ClickHouse/issues/85167). [#98516](https://github.com/ClickHouse/ClickHouse/pull/98516) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Optimiza la función de agregación `avgWeighted` usando acumuladores locales en lugar de almacenamiento y reenvío por fila a través del estado de agregación, mejorando el rendimiento hasta en un 27 % para entradas Nullable. [#98793](https://github.com/ClickHouse/ClickHouse/pull/98793) ([Antonio Andelic](https://github.com/antonio2368)).
* Mejora el rendimiento y reduce el uso de memoria de las funciones de ventana paralelas en ciertos escenarios, así como de las cargas de trabajo de arrayFold con arrays grandes. Esto también puede reducir la presión por fallos de página y mejorar la estabilidad con límites de memoria ajustados para las consultas afectadas. [#98892](https://github.com/ClickHouse/ClickHouse/pull/98892) ([filimonov](https://github.com/filimonov)).
* Añade icolumn::comparetrackat() para merges ordenados. [#99013](https://github.com/ClickHouse/ClickHouse/pull/99013) ([Artem Zuikov](https://github.com/4ertus2)).
* Optimiza `INTERSECT ALL` y `EXCEPT ALL`. [#99097](https://github.com/ClickHouse/ClickHouse/pull/99097) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Añade compatibilidad con la optimización `read_in_order_use_virtual_row` para lecturas en orden inverso. [#99198](https://github.com/ClickHouse/ClickHouse/pull/99198) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Reduce la contención de caché en los JOIN RIGHT y FULL comprobando si JoinUsedFlags está establecido antes de escribir. [#99274](https://github.com/ClickHouse/ClickHouse/pull/99274) ([Hechem Selmi](https://github.com/m-selmi)).
* Optimiza `PrefetchingHelper::calcPrefetchLookAhead` sustituyendo los cálculos en coma flotante por aritmética entera, mejorando la disposición de la caché de instrucciones y reduciendo la sobrecarga de ciclos durante los bucles de agregación. [#99327](https://github.com/ClickHouse/ClickHouse/pull/99327) ([Riyane El Qoqui](https://github.com/riyaneel)).
* Mejora el rendimiento de los lagos de datos. En versiones anteriores, la lectura desde almacenamiento de objetos no redimensionaba el pipeline al número de hilos de procesamiento. [#99548](https://github.com/ClickHouse/ClickHouse/pull/99548) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

El nuevo contenedor almacena de 0 a 1 hijos en línea, sin asignación en heap, lo que cubre la mayoría de los nodos de Keeper. Esto reduce el tamaño de `KeeperMemNode` de 144 a 128 bytes. [#99860](https://github.com/ClickHouse/ClickHouse/pull/99860) ([Antonio Andelic](https://github.com/antonio2368)).
