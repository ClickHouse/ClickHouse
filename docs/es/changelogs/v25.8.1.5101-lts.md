<div id="clickhouse-release-v25815101-lts-4f2b50b8c92-fixme-as-compared-to-v25811-new-d4d4c9f77fa">
  ### Lanzamiento de ClickHouse v25.8.1.5101-lts (4f2b50b8c92) FIXME en comparación con v25.8.1.1-new (d4d4c9f77fa)
</div>

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Se deshabilita de forma predeterminada el entrecomillado de enteros de 64 bits en formatos JSON. [#74079](https://github.com/ClickHouse/ClickHouse/pull/74079) ([Pavel Kruglov](https://github.com/Avogar)).
* Se infiere `Array(Dynamic)` en lugar de `Tuple` sin nombre para arrays de valores de distintos tipos en JSON. Para usar el comportamiento anterior, deshabilita la configuración `input_format_json_infer_array_of_dynamic_from_array_of_different_types`. [#80859](https://github.com/ClickHouse/ClickHouse/pull/80859) ([Pavel Kruglov](https://github.com/Avogar)).
* Las métricas de latencia de S3 se pasan a histogramas para mejorar la homogeneidad y la simplicidad. [#82305](https://github.com/ClickHouse/ClickHouse/pull/82305) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Se requieren backticks alrededor de los identificadores con puntos en expresiones predeterminadas para evitar que se interpreten como identificadores compuestos. [#83162](https://github.com/ClickHouse/ClickHouse/pull/83162) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* La materialización diferida solo está habilitada con el analizador para evitar el mantenimiento sin analizador, que, según nuestra experiencia, presenta algunos problemas (por ejemplo, al usar `indexHint()` en condiciones). [#83791](https://github.com/ClickHouse/ClickHouse/pull/83791) ([Igor Nikonov](https://github.com/devcrafter)).
* Los valores del tipo `Enum` se escriben de forma predeterminada como `BYTE_ARRAY` con el tipo lógico `ENUM` en el formato de salida Parquet. [#84169](https://github.com/ClickHouse/ClickHouse/pull/84169) ([Pavel Kruglov](https://github.com/Avogar)).
* Se habilita de forma predeterminada la configuración de MergeTree `write_marks_for_substreams_in_compact_parts`. Esto mejora significativamente el rendimiento de lectura de subcolumns desde partes Compact recién creadas. Los servidores con versiones anteriores a la 25.5 no podrán leer las nuevas partes Compact. [#84171](https://github.com/ClickHouse/ClickHouse/pull/84171) ([Pavel Kruglov](https://github.com/Avogar)).
* El valor predeterminado anterior de `concurrent_threads_scheduler` era `round_robin`, que demostró ser injusto cuando había un gran número de queries de un solo hilo (por ejemplo, INSERTs). Este cambio establece como valor predeterminado una alternativa más segura: el scheduler `fair_round_robin`. [#84747](https://github.com/ClickHouse/ClickHouse/pull/84747) ([Sergei Trifonov](https://github.com/serxa)).
* ClickHouse admite la sintaxis Heredoc de estilo PostgreSQL: `$tag$ string contents... $tag$`, también conocida como literales de cadena delimitados por dólares. En versiones anteriores, había menos restricciones para las etiquetas: podían contener caracteres arbitrarios, incluidos signos de puntuación y espacios en blanco. Esto introduce ambigüedad de parsing con identificadores que también pueden comenzar con un signo de dólar. Al mismo tiempo, PostgreSQL solo permite caracteres de palabra en las etiquetas. Para resolver el problema, ahora restringimos las etiquetas Heredoc para que solo contengan caracteres de palabra. Cierra [#84731](https://github.com/ClickHouse/ClickHouse/issues/84731). [#84846](https://github.com/ClickHouse/ClickHouse/pull/84846) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Las funciones `azureBlobStorage`, `deltaLakeAzure` e `icebergAzure` se han actualizado para validar correctamente los permisos `AZURE`. Todas las funciones variantes de cluster (funciones `-Cluster`) ahora verifican los permisos con respecto a sus equivalentes no clusterizados. Además, las funciones `icebergLocal` y `deltaLakeLocal` ahora exigen comprobaciones del permiso `FILE`. [#84938](https://github.com/ClickHouse/ClickHouse/pull/84938) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se habilita de forma predeterminada la configuración `allow_dynamic_metadata_for_data_lakes` (configuración a nivel de motor de tabla). [#85044](https://github.com/ClickHouse/ClickHouse/pull/85044) ([Daniil Ivanik](https://github.com/divanik)).

<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Motor de tabla `azureBlobStorage`: almacenar en caché y reutilizar tokens de autenticación de identidad administrada cuando sea posible para evitar el throttling. [#79860](https://github.com/ClickHouse/ClickHouse/pull/79860) ([Nick Blakely](https://github.com/niblak)).
* Se añadió una nueva lógica (controlada por la opción `enable_producing_buckets_out_of_order_in_aggregation`, habilitada de forma predeterminada) que permite enviar algunos buckets fuera de orden durante la aggregation eficiente en memoria. Cuando algunos buckets de aggregation tardan bastante más en fusionarse que otros, esto mejora el rendimiento al permitir que el nodo iniciador fusione mientras tanto buckets con identificadores más altos. La desventaja es un uso de memoria potencialmente mayor (no debería ser significativo). [#80179](https://github.com/ClickHouse/ClickHouse/pull/80179) ([Nikita Taranov](https://github.com/nickitat)).
* Nueva implementación del lector de Parquet. En general es más rápida y admite pushdown de filtros a nivel de página y PREWHERE. Actualmente es experimental. Use la opción `input_format_parquet_use_native_reader_v3` para habilitarla. [#82789](https://github.com/ClickHouse/ClickHouse/pull/82789) ([Michael Kolupaev](https://github.com/al13n321)).
* Procesar `max_joined_block_rows` fuera del bucle principal de hash JOIN. Rendimiento ligeramente mejor para ALL JOIN. [#83216](https://github.com/ClickHouse/ClickHouse/pull/83216) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Sustituir el client HTTP de curl por el client HTTP de poco para Azure Blob Storage. Se introdujeron varias opciones para estos clients que replican opciones de S3. Se introdujeron timeouts de conexión agresivos tanto para Azure como para S3. Se mejoró la introspección de los profile events y las métricas de Azure. El nuevo client está habilitado de forma predeterminada y ofrece latencias mucho mejores para consultas en frío sobre Azure Blob Storage. Se puede volver al client `Curl` anterior configurando `azure_sdk_use_native_client=false`. [#83294](https://github.com/ClickHouse/ClickHouse/pull/83294) ([alesapin](https://github.com/alesapin)).
* Mejorar significativamente el rendimiento de lectura de las subcolumnas de `JSON` desde datos compartidos en MergeTree mediante la implementación de nuevas serializaciones para los datos compartidos de `JSON` en MergeTree. [#83777](https://github.com/ClickHouse/ClickHouse/pull/83777) ([Pavel Kruglov](https://github.com/Avogar)).
* Procesar primero los índices min-max de mayor granularidad. Cierra [#75381](https://github.com/ClickHouse/ClickHouse/issues/75381). [#83798](https://github.com/ClickHouse/ClickHouse/pull/83798) ([Maruth Goyal](https://github.com/maruthgoyal)).
* Las consultas de búsqueda vectorial que usan un índice de similitud vectorial se completan con menor latencia gracias a la reducción de lecturas de almacenamiento y del uso de CPU. [#83803](https://github.com/ClickHouse/ClickHouse/pull/83803) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Implementar addManyDefaults para los combinadores If. [#83870](https://github.com/ClickHouse/ClickHouse/pull/83870) ([Raúl Marín](https://github.com/Algunenano)).
* Calcular la columna clave serializada de forma columnar al agrupar por varias columnas de cadena o numéricas. [#83884](https://github.com/ClickHouse/ClickHouse/pull/83884) ([李扬](https://github.com/taiyang-li)).
* Probar `-falign-functions=64` para intentar obtener pruebas de rendimiento más estables. [#83920](https://github.com/ClickHouse/ClickHouse/pull/83920) ([Azat Khuzhin](https://github.com/azat)).
* El índice bloom filter ahora se usa para condiciones como `has([c1, c2, ...], column)`, donde `column` no es de tipo `Array`. Esto mejora el rendimiento de esas consultas y las hace tan eficientes como el operador `IN`. [#83945](https://github.com/ClickHouse/ClickHouse/pull/83945) ([Doron David](https://github.com/dorki)).
* Reducir las llamadas innecesarias a memcpy en CompressedReadBufferBase::readCompressedData. [#83986](https://github.com/ClickHouse/ClickHouse/pull/83986) ([Raúl Marín](https://github.com/Algunenano)).
* Los JOIN `All` `LEFT/INNER` se convertirán automáticamente en `RightAny` si el lado derecho está determinado funcionalmente por las columnas clave de join (todas las filas tienen valores únicos de clave de join). [#84010](https://github.com/ClickHouse/ClickHouse/pull/84010) ([Nikita Taranov](https://github.com/nickitat)).
* Procesa los índices en orden creciente de tamaño de archivo. En conjunto, el orden de los índices prioriza los índices minmax y vectoriales (por simplicidad y selectividad, respectivamente), y después los índices pequeños. Dentro de los índices minmax/vectoriales también se priorizan los más pequeños. [#84094](https://github.com/ClickHouse/ClickHouse/pull/84094) ([Maruth Goyal](https://github.com/maruthgoyal)).
* Optimiza `largestTriangleThreeBuckets` eliminando datos temporales. [#84479](https://github.com/ClickHouse/ClickHouse/pull/84479) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimiza la deserialización de cadenas simplificando el código. Cierra [#38564](https://github.com/ClickHouse/ClickHouse/issues/38564). [#84561](https://github.com/ClickHouse/ClickHouse/pull/84561) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Anteriormente, los datos del índice de texto se dividían en varios segmentos (el tamaño predeterminado de cada segmento era de 256 MiB). Esto podía reducir el consumo de memoria al construir el índice de texto; sin embargo, aumenta el espacio necesario en disco y el tiempo de respuesta de la consulta. [#84590](https://github.com/ClickHouse/ClickHouse/pull/84590) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Se corrigió el cálculo del tamaño mínimo de tarea para las réplicas paralelas. [#84752](https://github.com/ClickHouse/ClickHouse/pull/84752) ([Nikita Taranov](https://github.com/nickitat)).
* Se mejoró el rendimiento al aplicar partes patch en modo `Join`. [#85040](https://github.com/ClickHouse/ClickHouse/pull/85040) ([Anton Popov](https://github.com/CurtizJ)).
* Se elimina el byte nulo. Cierra [#85062](https://github.com/ClickHouse/ClickHouse/issues/85062). Se corrigieron algunos errores menores. Las funciones `structureToProtobufSchema`, `structureToCapnProtoSchema` no colocaban correctamente un byte nulo de terminación y usaban un salto de línea en su lugar. Esto provocaba la ausencia de un salto de línea en la salida y podía causar desbordamientos de búfer al usar otras funciones que dependen del byte nulo (como `logTrace`, `demangle`, `extractURLParameter`, `toStringCutToZero` y `encrypt`/`decrypt`). El layout de diccionario `regexp_tree` no admitía el procesamiento de cadenas con bytes nulos. La función `formatRowNoNewline`, llamada con el formato `Values` o con cualquier otro formato sin salto de línea al final de las filas, recortaba erróneamente el último carácter de la salida. La función `stem` contenía un error de seguridad ante excepciones que podía provocar una fuga de memoria en un caso muy poco frecuente. La función `initcap` funcionaba incorrectamente para argumentos `FixedString`: no reconocía el inicio de una palabra al comienzo de la cadena si la cadena anterior de un block terminaba con un carácter de palabra. Se corrigió una vulnerabilidad de seguridad del formato Apache `ORC`, que podía provocar la exposición de memoria no inicializada. Se cambió el comportamiento de la función `replaceRegexpAll` y del alias correspondiente, `REGEXP_REPLACE`: ahora puede hacer una coincidencia vacía al final de la cadena incluso si la coincidencia anterior procesó toda la cadena, como en el caso de `^a*|a*$` o `^|.*`; esto corresponde a la semántica de JavaScript, Perl, Python, PHP y Ruby, pero difiere de la semántica de PostgreSQL. La implementación de muchas funciones se ha simplificado y optimizado. La documentación de varias funciones era incorrecta y ya se ha corregido. Ten en cuenta que la salida de `byteSize` para columnas String y tipos complejos compuestos por columnas String ha cambiado (de 9 bytes por cadena vacía a 8 bytes por cadena vacía), y esto es normal. [#85063](https://github.com/ClickHouse/ClickHouse/pull/85063) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimiza la materialización de constantes cuando esta materialización se hace únicamente para devolver una sola fila. [#85071](https://github.com/ClickHouse/ClickHouse/pull/85071) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Mejora el procesamiento paralelo de archivos con el backend delta-kernel-rs. [#85642](https://github.com/ClickHouse/ClickHouse/pull/85642) ([Azat Khuzhin](https://github.com/azat)).

  #### Mejora

* Mostrar el número de rangos que se leerán en la salida de `EXPLAIN indexes = 1`. [#79938](https://github.com/ClickHouse/ClickHouse/pull/79938) ([Christoph Wurm](https://github.com/cwurm)).
* Introducir ajustes para configurar el tamaño del bloque de Compression de ORC y actualizar su valor predeterminado de 64 KB a 256 KB para mantener la coherencia con Spark y Hive. [#80602](https://github.com/ClickHouse/ClickHouse/pull/80602) ([李扬](https://github.com/taiyang-li)).
