  ### Lanzamiento de ClickHouse v24.8.1.2684-lts (161c62fd295) FIXME en comparación con v24.8.1.1-new (3f8b27d7acc)

<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* `clickhouse-client` y `clickhouse-local` ahora usan de forma predeterminada el modo multiconsulta (en lugar del modo de consulta única). Por ejemplo, `clickhouse-client -q "SELECT 1; SELECT 2"` ahora funciona, mientras que antes los usuarios tenían que añadir `--multiquery` (o `-n`). La opción `--multiquery/-n` quedó obsoleta. Las consultas INSERT en sentencias multiconsulta se tratan de forma especial según su cláusula FORMAT: si FORMAT es `VALUES` (el caso más habitual), el final de la sentencia INSERT se representa con un punto y coma `;` al final de la consulta. Para cualquier otro FORMAT (p. ej., `CSV` o `JSONEachRow`), el final de la sentencia INSERT se representa con dos saltos de línea `\n\n` al final de la consulta. [#63898](https://github.com/ClickHouse/ClickHouse/pull/63898) ([FFish](https://github.com/wxybear)).
* En versiones anteriores, era posible usar una sintaxis alternativa para los tipos de datos `LowCardinality` añadiendo `WithDictionary` al nombre del tipo de dato. Era una implementación inicial funcional y nunca se documentó ni se expuso públicamente. Ahora está obsoleta. Si ha usado esta sintaxis, debe ejecutar ALTER en sus tablas y cambiar el nombre de los tipos de datos a `LowCardinality`. [#66842](https://github.com/ClickHouse/ClickHouse/pull/66842) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige errores lógicos del almacenamiento `Buffer` cuando se usa con una tabla de destino distribuida. Es un cambio incompatible con versiones anteriores: las consultas que usan `Buffer` con una tabla de destino distribuida pueden dejar de funcionar si la tabla aparece más de una vez en la consulta (p. ej., en una autounión). [#67015](https://github.com/ClickHouse/ClickHouse/pull/67015) ([vdimir](https://github.com/vdimir)).
* En versiones anteriores, llamar a funciones para distribuciones aleatorias basadas en la función gamma (como Chi-Squared, Student o Fisher) con argumentos negativos cercanos a cero provocaba un cálculo prolongado o un bucle infinito. En la nueva versión, llamar a estas funciones con argumentos cero o negativos producirá una excepción. Esto cierra [#67297](https://github.com/ClickHouse/ClickHouse/issues/67297). [#67326](https://github.com/ClickHouse/ClickHouse/pull/67326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La tabla del sistema `text_log` está habilitada de forma predeterminada. Esto es totalmente compatible con versiones anteriores, pero puede que note un ligero aumento en el uso de disco local (esta tabla del sistema ocupa una cantidad mínima de espacio en disco). [#67428](https://github.com/ClickHouse/ClickHouse/pull/67428) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* En versiones anteriores, `arrayWithConstant` podía ser lento si se le pedía generar arrays muy grandes. En la nueva versión, está limitado a 1 GB por array. Esto cierra [#32754](https://github.com/ClickHouse/ClickHouse/issues/32754). [#67741](https://github.com/ClickHouse/ClickHouse/pull/67741) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige el formato del modificador REPLACE (se prohíbe omitir los paréntesis). [#67774](https://github.com/ClickHouse/ClickHouse/pull/67774) ([Azat Khuzhin](https://github.com/azat)).
* Retroportado en [#68349](https://github.com/ClickHouse/ClickHouse/issues/68349): Se reimplementa el tipo Dynamic. Ahora, cuando se alcanza el límite de tipos de datos dinámicos, los tipos nuevos no se convierten a String, sino que se almacenan en una estructura de datos especial en formato binario con el tipo de dato codificado en binario. Ahora, cualquier tipo que se haya insertado alguna vez en una columna Dynamic puede leerse de ella como subcolumna. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="new-feature">
  #### Nueva funcionalidad
</div>

* Añade un nuevo motor de almacenamiento Kafka experimental para almacenar offsets en Keeper en lugar de depender de confirmarlos en Kafka. [#57625](https://github.com/ClickHouse/ClickHouse/pull/57625) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Añade un nuevo motor de tabla TimeSeries: - de forma predeterminada: `CREATE TABLE tbl ENGINE=TimeSeries` - o especificando los motores de sus tablas internas. [#64183](https://github.com/ClickHouse/ClickHouse/pull/64183) ([Vitaly Baranov](https://github.com/vitlibar)).
* Admite más variantes de strictness de JOIN (`LEFT/RIGHT SEMI/ANTI/ANY JOIN`) con condiciones de desigualdad que involucran columnas de las tablas izquierda y derecha; por ejemplo, t1.y &lt; t2.y (consulta la configuración `allow_experimental_join_condition`). [#64281](https://github.com/ClickHouse/ClickHouse/pull/64281) ([lgbo](https://github.com/lgbo-ustc)).
* Añade la columna virtual `_etag` para el motor de tabla S3. Corrige [#65312](https://github.com/ClickHouse/ClickHouse/issues/65312). [#65386](https://github.com/ClickHouse/ClickHouse/pull/65386) ([skyoct](https://github.com/skyoct)).
* Este pull request introduce el particionamiento de estilo Hive para distintos motores (`File`, `URL`, `S3`, `AzureBlobStorage`, `HDFS`). El particionamiento de estilo Hive organiza los datos en subdirectorios particionados, lo que hace más eficiente consultar y gestionar grandes conjuntos de datos. Actualmente, solo crea columnas virtuales con el nombre y los datos adecuados. El PR de seguimiento introducirá el filtrado de datos correspondiente (mejora del rendimiento). [#65997](https://github.com/ClickHouse/ClickHouse/pull/65997) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Añade la función printf para compatibilidad con Spark. [#66257](https://github.com/ClickHouse/ClickHouse/pull/66257) ([李扬](https://github.com/taiyang-li)).
* Retroportado en [#68450](https://github.com/ClickHouse/ClickHouse/issues/68450): Implementa el nuevo tipo de datos JSON. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Kruglov Pavel](https://github.com/Avogar)).
* Añade una nueva configuración del servidor: disable&#95;insertion&#95;and&#95;mutation. Establécela en true. Este nodo denegará todas las inserciones y mutaciones (Alter table delete/update/drop partition). Incluye la inserción asíncrona. [#66519](https://github.com/ClickHouse/ClickHouse/pull/66519) ([Xu Jia](https://github.com/XuJia0210)).
* Añade las opciones `restore_replace_external_engines_to_null` y `restore_replace_external_table_functions_to_null` para reemplazar motores externos y funciones de tabla externas por el motor Null, lo que puede ser útil para pruebas. Debe funcionar para RESTORE y para la creación explícita de tablas. [#66536](https://github.com/ClickHouse/ClickHouse/pull/66536) ([Ilya Yatsishin](https://github.com/qoega)).
* Se añadió compatibilidad para leer geometrías MULTILINESTRING en formato WKT mediante la función readWKTLineString. [#67647](https://github.com/ClickHouse/ClickHouse/pull/67647) ([Jacob Reckhard](https://github.com/jacobrec)).
* Añade una nueva función de tabla `fuzzQuery`. Esta función permite modificar una cadena de consulta dada con variaciones aleatorias. Ejemplo: `SELECT query FROM fuzzQuery('SELECT 1') LIMIT 5;`. [#67655](https://github.com/ClickHouse/ClickHouse/pull/67655) ([pufit](https://github.com/pufit)).
* Admite la consulta `DROP DETACHED PARTITION ALL` para eliminar todas las particiones detached. [#67885](https://github.com/ClickHouse/ClickHouse/pull/67885) ([Duc Canh Le](https://github.com/canhld94)).
* Se añadió un mecanismo de etiquetado (espacio de nombres) para la caché de consultas. La caché de consultas considera distintas las mismas consultas con diferentes tags. Ejemplo: `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'abc'` y `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'def'` ahora crean entradas diferentes en la caché de consultas. [#68235](https://github.com/sakulali)).

<div id="performance-improvement">

* Se utiliza un método de cálculo adaptativo del tamaño de las tareas de lectura (adaptativo significa que depende del tamaño de las columnas leídas) para las réplicas paralelas. [#60377](https://github.com/ClickHouse/ClickHouse/pull/60377) ([Nikita Taranov](https://github.com/nickitat)).
* Se almacenan los metadatos del directorio del disco `plain_rewritable` en el layout `__meta`, por separado de los datos de MergeTree en el almacenamiento de objetos. El disco `plain_rewritable` pasa a una estructura de directorios plana. [#65751](https://github.com/ClickHouse/ClickHouse/pull/65751) ([Julia Kartseva](https://github.com/jkartseva)).
* Se habilita `compile_expressions` (compilador JIT para fragmentos de expresiones ordinarias) de forma predeterminada. Esto cierra [#51264](https://github.com/ClickHouse/ClickHouse/issues/51264) y [#56386](https://github.com/ClickHouse/ClickHouse/issues/56386). [#66486](https://github.com/ClickHouse/ClickHouse/pull/66486) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se mejora la compactación de columnas para los tipos String/Array/Map/Variant/Dynamic reservando por adelantado la memoria necesaria para todas las subcolumnas. [#67043](https://github.com/ClickHouse/ClickHouse/pull/67043) ([Kruglov Pavel](https://github.com/Avogar)).
* Se acelera el vaciado de los logs del sistema y se vacían los logs al apagar. [#67472](https://github.com/ClickHouse/ClickHouse/pull/67472) ([Sema Checherinda](https://github.com/CheSema)).
* Retroportado en [#68496](https://github.com/ClickHouse/ClickHouse/issues/68496): se mejoró el rendimiento general de las fusiones al reducir la sobrecarga de la planificación de las etapas de fusión. [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* La configuración `optimize_functions_to_subcolumns` está habilitada de forma predeterminada. [#68053](https://github.com/ClickHouse/ClickHouse/pull/68053) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### Mejora
</div>

* El servidor ClickHouse ahora admite la nueva configuración `max_keep_alive_requests`. Para las conexiones HTTP keep-alive al servidor, funciona junto con `keep_alive_timeout`: si el tiempo de inactividad aún no ha expirado, pero ya se han realizado más de `max_keep_alive_requests` solicitudes a través de una conexión determinada, el servidor la cerrará. [#61793](https://github.com/ClickHouse/ClickHouse/pull/61793) ([Nikita Taranov](https://github.com/nickitat)).
* Dado que en la nueva versión SOURCES se comprueba según la lógica de Table Engine, aunque el permiso grant para el motor de tablas está deshabilitado de forma predeterminada, si no se ha concedido permiso sobre una fuente aparecerá en su lugar un aviso del motor de tablas, lo que resulta engañoso. [#65419](https://github.com/ClickHouse/ClickHouse/pull/65419) ([jsc0218](https://github.com/jsc0218)).
* Se añadió el tipo de estadísticas `count_min` (count-min sketches), que proporciona estimaciones de selectividad para predicados de igualdad como `col = 'val'`. Los tipos de datos compatibles son string, date, datetime y tipos numéricos. [#65521](https://github.com/ClickHouse/ClickHouse/pull/65521) ([JackyWoo](https://github.com/JackyWoo)).
* No pasar explícitamente logs para Keeper en la imagen para permitir su sobrescritura. [#65564](https://github.com/ClickHouse/ClickHouse/pull/65564) ([Azat Khuzhin](https://github.com/azat)).
* Se usa la base de datos `Atomic` de forma predeterminada en `clickhouse-local`. Aborda los puntos 1 y 5 de [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647). Cierra [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817). [#65860](https://github.com/ClickHouse/ClickHouse/pull/65860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Añade la estadística `rows_before_aggregation_at_least` a la respuesta de la consulta cuando `rows_before_aggregation` está habilitado. Esta estadística representa el número de filas leídas antes de la agregación. En el contexto de una consulta distribuida, al usar la función de agregación `group by` o `max` sin `limit`, `rows_before_aggregation_at_least` puede reflejar el número de filas alcanzadas por la consulta. [#66084](https://github.com/ClickHouse/ClickHouse/pull/66084) ([morning-color](https://github.com/morning-color)).
* Se introdujeron las configuraciones `use_same_password_for_base_backup` para las consultas `BACKUP` y `RESTORE`, lo que permite crear y restaurar copias de seguridad incrementales hacia/desde archivos protegidos con contraseña. [#66214](https://github.com/ClickHouse/ClickHouse/pull/66214) ([Samuele](https://github.com/sguerrini97)).
* Ignorar async&#95;load&#95;databases para la consulta ATTACH (anteriormente era posible que ATTACH devolviera el control antes de que las tablas se hubieran adjuntado). [#66240](https://github.com/ClickHouse/ClickHouse/pull/66240) ([Azat Khuzhin](https://github.com/azat)).
* [Replicated]MergeTreeSink tiene que cancelar correctamente su delayed&#95;chunk en el método `onCancel()`. [#66279](https://github.com/ClickHouse/ClickHouse/pull/66279) ([Sema Checherinda](https://github.com/CheSema)).
* Se añadieron logs y métricas para las conexiones rechazadas (cuando no hay suficientes recursos). [#66410](https://github.com/ClickHouse/ClickHouse/pull/66410) ([Alexander Tokmakov](https://github.com/tavplubix)).
* La configuración `allow_experimental_analyzer` pasa a llamarse `enable_analyzer`. El nombre anterior se conserva como alias. [#66438](https://github.com/ClickHouse/ClickHouse/pull/66438) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Se admite el tipo UUID real para el motor MongoDB. [#66671](https://github.com/ClickHouse/ClickHouse/pull/66671) ([Azat Khuzhin](https://github.com/azat)).
* Se añadió una nueva configuración de `MergeTree`, `deduplicate_merge_projection_mode`, para controlar las proyecciones durante las fusiones (para motores específicos) y la consulta `OPTIMIZE DEDUPLICATE`. Opciones compatibles: `throw` (lanza una excepción en caso de que la proyección no sea totalmente compatible con el motor *MergeTree), `drop` (elimina la proyección durante la fusión si no puede fusionarse por sí sola de forma coherente) y `rebuild` (reconstruye la proyección desde cero, lo que supone una operación costosa). [#66672](https://github.com/ClickHouse/ClickHouse/pull/66672) ([jsc0218](https://github.com/jsc0218)).
* Añade métricas de retraso de replicación y tiempo de recuperación. [#66703](https://github.com/ClickHouse/ClickHouse/pull/66703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Añade la métrica S3DiskNoKeyErrors. [#66704](https://github.com/ClickHouse/ClickHouse/pull/66704) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Garantiza que la cláusula COMMENT funcione para todos los motores de tabla. [#66832](https://github.com/ClickHouse/ClickHouse/pull/66832) ([Joe Lynch](https://github.com/joelynch)).
* Actualiza el uso de los códigos de error `BAD_ARGUMENTS` e `ILLEGAL_TYPE_OF_ARGUMENT` por códigos de error más precisos cuando corresponde. [#66851](https://github.com/ClickHouse/ClickHouse/pull/66851) ([Yohann Jardin](https://github.com/yohannj)).
* La función `mapFromArrays` ahora acepta `Map(K, V)` como primer argumento; por ejemplo, `SELECT mapFromArrays(map('a', 4, 'b', 4), ['aa', 'bb'])` ahora funciona y devuelve `{('a',4):'aa',('b',4):'bb'}`. Además, si el primer argumento es un Array, ahora también puede ser de tipo `Array(Nullable(T))` o `Array(LowCardinality(Nullable(T)))`, siempre que los valores reales del array no sean `NULL`. [#67103](https://github.com/ClickHouse/ClickHouse/pull/67103) ([李扬](https://github.com/taiyang-li)).
* Lee la configuración de clickhouse-local desde ~/.clickhouse-local. [#67135](https://github.com/ClickHouse/ClickHouse/pull/67135) ([Azat Khuzhin](https://github.com/azat)).
* Renombra la configuración `input_format_orc_read_use_writer_time_zone` a `input_format_orc_reader_timezone` y permite al usuario establecer la zona horaria del lector. [#67175](https://github.com/ClickHouse/ClickHouse/pull/67175) ([kevinyhzou](https://github.com/KevinyhZou)).
* Reduce el nivel del error &#39;Socket is not connected&#39; cuando la otra parte restablece inmediatamente la conexión HTTP tras conectarse; cierra [#34218](https://github.com/ClickHouse/ClickHouse/issues/34218). [#67177](https://github.com/ClickHouse/ClickHouse/pull/67177) ([vdimir](https://github.com/vdimir)).

* Añade la capacidad de cargar dashboards para system.dashboards desde la configuración (una vez definidos, sobrescriben el conjunto predeterminado de dashboards). [#67232](https://github.com/ClickHouse/ClickHouse/pull/67232) ([Azat Khuzhin](https://github.com/azat)).
* Las funciones de ventana en SQL tradicionalmente están en snake case. ClickHouse usa camelCase, por lo que se han creado nuevos alias `denseRank()` y `percentRank()`. Estas nuevas funciones pueden invocarse exactamente igual que las funciones originales `dense_rank()` y `percent_rank()`. Tanto la sintaxis snake case como la camelCase siguen siendo utilizables. Si no se especifica, se asumen las cadenas de formato `%Y-%m-%d %H:%i:%s` y `yyyy-MM-dd HH:mm:ss`. Ejemplo: `SELECT parseDateTime('2021-01-04 23:12:34')` ahora devuelve el valor DateTime `2021-01-04 23:12:34` (antes, esto generaba una excepción). [#67399](https://github.com/ClickHouse/ClickHouse/pull/67399) ([Robert Schulze](https://github.com/rschu1ze)).
* Reintentar automáticamente las solicitudes de Keeper en KeeperMap si se producen por un timeout o por pérdida de conexión. [#67448](https://github.com/ClickHouse/ClickHouse/pull/67448) ([Antonio Andelic](https://github.com/antonio2368)).
