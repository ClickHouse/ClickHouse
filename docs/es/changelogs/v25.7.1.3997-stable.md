<div id="backward-incompatible-change">
  #### Cambio incompatible con versiones anteriores
</div>

* Cambios en este PR: 1. Se introduce un nuevo argumento `unexpected_quoting_character_strategy` en la función que controla qué ocurre cuando se encuentra inesperadamente un `quoting_character` al leer una clave o un valor sin comillas. El valor puede ser uno de los siguientes: `invalid`, `accept` o `promote`. Invalid descartará la clave y volverá al estado de espera de clave. Accept lo tratará como parte de la clave. Promote descartará el carácter anterior y empezará a analizarlo como una clave entrecomillada. Creo que el comportamiento predeterminado (y quizá el único comportamiento) debería ser `INVALID`, pero en 2023, en https://github.com/ClickHouse/ClickHouse/pull/56423, se implementó la lógica `PROMOTE`. Así que, para hacerlo en cierta medida retrocompatible, creé este ajuste. 2. Después de analizar un valor entrecomillado, solo se analizará la siguiente clave si se encuentra un delimitador de par. [#80657](https://github.com/ClickHouse/ClickHouse/pull/80657) ([Arthur Passos](https://github.com/arthurpassos)).
* Anteriormente, la función `countMatches` dejaba de contar en la primera coincidencia vacía, incluso si el patrón la aceptaba. Para solucionar este problema, `countMatches` ahora continúa la ejecución avanzando un solo carácter cuando se produce una coincidencia vacía. Los usuarios que prefieran conservar el comportamiento anterior pueden habilitar el ajuste `count_matches_stop_at_empty_match`. [#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Anteriormente, las consultas BACKUP, las merges y las mutations no usaban limitadores de ancho de banda de todo el servidor para el tráfico local (`max_local_read_bandwidth_for_server` y `max_local_write_bandwidth_for_server`) y remoto (`max_remote_read_network_bandwidth_for_server` y `max_remote_write_network_bandwidth_for_server`); en su lugar, solo se limitaban mediante ajustes dedicados del servidor (`max_backup_bandwidth_for_server`, `max_mutations_bandwidth_for_server` y `max_merges_bandwidth_for_server`). Ahora usan ambos tipos de limitadores simultáneamente. [#81753](https://github.com/ClickHouse/ClickHouse/pull/81753) ([Sergei Trifonov](https://github.com/serxa)).
* Prohibir la creación de una tabla sin columnas en las que se puedan hacer inserts. [#81835](https://github.com/ClickHouse/ClickHouse/pull/81835) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Las funciones de cluster con archivos comprimidos solían enviar los archivos completos a las réplicas, lo que hacía que la lectura dentro del archivo no pudiera paralelizarse en el cluster (por ejemplo, con un solo archivo, simplemente se enviaba completo a una de las réplicas para procesarlo y todas las demás réplicas quedaban inactivas, lo que es ineficiente). Se añadió un nuevo ajuste `cluster_function_process_archive_on_multiple_nodes`, con valor predeterminado `true`. Si se establece en `true`, aumenta el rendimiento del procesamiento de archivos en las funciones de cluster. Debe establecerse en `false` por compatibilidad y para evitar errores durante la actualización a 25.7+ si se usan funciones de cluster con archivos en versiones anteriores. [#82355](https://github.com/ClickHouse/ClickHouse/pull/82355) ([Kseniia Sumarokova](https://github.com/kssenii)).
* La consulta `SYSTEM RESTART REPLICAS` provocaba la activación de tablas en la base de datos Lazy, incluso sin acceso a esa base de datos, y eso ocurría mientras esas tablas se eliminaban de forma concurrente. Nota: Ahora `SYSTEM RESTART REPLICAS` solo reiniciará réplicas en las bases de datos en las que tenga permiso para `SHOW TABLES`, lo cual es lo natural. [#83321](https://github.com/ClickHouse/ClickHouse/pull/83321) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="experimental-feature">
  #### Funcionalidad experimental
</div>

* Se añadieron las funciones `searchAny` y `searchAll`, que son herramientas de propósito general para buscar en índices de texto. [#80641](https://github.com/ClickHouse/ClickHouse/pull/80641) ([Elmi Ahmadov](https://github.com/ahmadov)).
* El índice de texto ahora admite el tokenizador `string`. [#81752](https://github.com/ClickHouse/ClickHouse/pull/81752) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Se cambió a 64 el valor predeterminado de la granularidad del índice para los índices `text`. Esto mejora el rendimiento esperado de la consulta de prueba media en benchmarks internos. [#82162](https://github.com/ClickHouse/ClickHouse/pull/82162) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* El bitmap de 256 bits almacena las etiquetas salientes de un estado de forma ordenada, pero los estados salientes se guardan en disco en el orden en que aparecen en la tabla hash. Por lo tanto, una etiqueta apuntaría al siguiente estado incorrecto al leer desde disco. [#82783](https://github.com/ClickHouse/ClickHouse/pull/82783) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Actualmente, el árbol FST se guarda en disco sin comprimir. Esto podría provocar un rendimiento lento o un mayor ancho de banda de E/S tanto al escribir en disco como al leer de él. [#83093](https://github.com/ClickHouse/ClickHouse/pull/83093) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Se eliminaron `searchAny` y `searchAll` debido a un error. Consulte [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385). [#83117](https://github.com/ClickHouse/ClickHouse/pull/83117) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Recientemente, el fuzzer encontró un issue en las funciones `searchAny` y `searchAll` (consulte [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385)). Esta excepción se produce siempre que las funciones `searchAny` o `searchAll` reciben parámetros de índice de texto distintos para la misma columna. Este escenario solo es posible cuando hay dos índices de texto distintos para la misma columna. Este PR restringe la definición del índice de texto para que una columna solo pueda definirse una vez, aunque sigue permitiéndose un envoltorio alrededor de la columna (por ejemplo, `lower(column)`). [#83303](https://github.com/ClickHouse/ClickHouse/pull/83303) ([Elmi Ahmadov](https://github.com/ahmadov)).



<div id="performance-improvement">
  #### Mejora del rendimiento
</div>

* Optimización trivial del combinador -If. [#78454](https://github.com/ClickHouse/ClickHouse/pull/78454) ([李扬](https://github.com/taiyang-li)).
* Se introdujo una opción para descargar la (des)compresión y la (des)serialización de bloques en los hilos del pipeline, en lugar de en un único hilo asociado a una conexión de red. Se controla mediante la configuración `enable_parallel_blocks_marshalling`. Debería acelerar las consultas distribuidas que transfieren cantidades significativas de datos entre el iniciador y los nodos remotos. [#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* Las consultas de búsqueda vectorial que usan un índice de similitud vectorial se completan con menor latencia gracias a la reducción de las lecturas de almacenamiento y del uso de CPU. [#79103](https://github.com/ClickHouse/ClickHouse/pull/79103) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Se respeta `merge_tree_min_{rows,bytes}_for_seek` en `filterPartsByQueryConditionCache` para alinearlo con otros métodos que filtran por índices. [#80312](https://github.com/ClickHouse/ClickHouse/pull/80312) ([李扬](https://github.com/taiyang-li)).
* Se hace multihilo el pipeline después del paso TOTALS. [#80331](https://github.com/ClickHouse/ClickHouse/pull/80331) ([UnamedRus](https://github.com/UnamedRus)).
* INSERT SELECT distribuido en paralelo está habilitado de forma predeterminada en el modo en que INSERT SELECT se ejecuta de forma independiente en cada shard; consulte la configuración `parallel_distributed_insert_select`. [#80425](https://github.com/ClickHouse/ClickHouse/pull/80425) ([Igor Nikonov](https://github.com/devcrafter)).
* Se ajustaron algunas configuraciones de jemalloc para mejorar el rendimiento. [#81807](https://github.com/ClickHouse/ClickHouse/pull/81807) ([Antonio Andelic](https://github.com/antonio2368)).
* Se corrige el filtro por clave para los almacenamientos Redis y KeeperMap. [#81833](https://github.com/ClickHouse/ClickHouse/pull/81833) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Se añade la nueva configuración `min_joined_block_size_rows` (análoga a `min_joined_block_size_bytes`; valor predeterminado: 65409) para controlar el tamaño mínimo del bloque (en filas) de los bloques de entrada y salida de JOIN (si el algoritmo de join lo admite). Los bloques pequeños se compactarán. [#81886](https://github.com/ClickHouse/ClickHouse/pull/81886) ([Nikita Taranov](https://github.com/nickitat)).
* Cuando la consulta de agregación contiene solo una función `COUNT()` sobre una columna NOT NULL, la lógica de agregación se inserta completamente en línea durante el sondeo de la tabla hash. Esto evita asignar y mantener cualquier estado de agregación, lo que reduce significativamente el uso de memoria y la sobrecarga de CPU. Esto aborda parcialmente [#81982](https://github.com/ClickHouse/ClickHouse/issues/81982). [#82104](https://github.com/ClickHouse/ClickHouse/pull/82104) ([Amos Bird](https://github.com/amosbird)).
* Se optimiza el rendimiento de `HashJoin` al eliminar el bucle adicional sobre tablas hash en el caso típico de una sola columna clave; además, se eliminan las comprobaciones de `null_map` y `join_mask` cuando siempre son `true`/`false`. [#82308](https://github.com/ClickHouse/ClickHouse/pull/82308) ([Nikita Taranov](https://github.com/nickitat)).
* `ATTACH PARTITION` ya no provoca la eliminación de todas las cachés. [#82377](https://github.com/ClickHouse/ClickHouse/pull/82377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se optimiza el plan generado para las subconsultas correlacionadas eliminando operaciones JOIN redundantes mediante clases de equivalencia. Si hay expresiones equivalentes para todas las columnas correlacionadas, no se genera `CROSS JOIN` si la configuración `query_plan_correlated_subqueries_use_substitution` está habilitada. [#82435](https://github.com/ClickHouse/ClickHouse/pull/82435) ([Dmitry Novik](https://github.com/novikd)).
* Se leen solo las columnas necesarias en la subconsulta correlacionada cuando parece ser un argumento de la función `EXISTS`. [#82443](https://github.com/ClickHouse/ClickHouse/pull/82443) ([Dmitry Novik](https://github.com/novikd)).
* Se introduce el `logging` asíncrono. [#82516](https://github.com/ClickHouse/ClickHouse/pull/82516) ([Raúl Marín](https://github.com/Algunenano)).
* Se comprimen los `logs` y los eventos de perfil en el protocolo nativo. En clusters con más de 100 réplicas, los eventos de perfil sin comprimir consumen entre 1 y 10 MB/s, y la barra de progreso responde con lentitud en conexiones lentas a Internet. Esto cierra [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533). [#82535](https://github.com/ClickHouse/ClickHouse/pull/82535) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Se intenta acelerar un poco QueryTreeHash. [#82617](https://github.com/ClickHouse/ClickHouse/pull/82617) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Se añade alineación en el Counter de ProfileEvents para reducir el false sharing. [#82697](https://github.com/ClickHouse/ClickHouse/pull/82697) ([Jiebin Sun](https://github.com/jiebinn)).
* El INSERT SELECT distribuido en paralelo está habilitado de forma predeterminada en el modo en que INSERT SELECT se ejecuta en cada segmento de forma independiente; consulte la configuración `parallel_distributed_insert_select`. [#83040](https://github.com/ClickHouse/ClickHouse/pull/83040) ([Igor Nikonov](https://github.com/devcrafter)).

Además, se optimizó la estructura de datos `KnownRowsHolder`. [#83041](https://github.com/ClickHouse/ClickHouse/pull/83041) ([Nikita Taranov](https://github.com/nickitat)).
* Se usa `std::vector<std::atomic_bool>` simple para los indicadores de join, a fin de evitar calcular un hash en cada acceso a ellos. [#83043](https://github.com/ClickHouse/ClickHouse/pull/83043) ([Nikita Taranov](https://github.com/nickitat)).

Además, conocemos la cantidad exacta de coincidencias una vez finalizada la unión, por lo que podemos preasignar con mayor precisión. [#83304](https://github.com/ClickHouse/ClickHouse/pull/83304) ([Nikita Taranov](https://github.com/nickitat)).
* Se minimiza la copia de memoria en las cabeceras de los puertos durante la construcción del pipeline. [PR](https://github.com/ClickHouse/ClickHouse/pull/70105) original de [heymind](https://github.com/heymind). [#83381](https://github.com/ClickHouse/ClickHouse/pull/83381) ([Raúl Marín](https://github.com/Algunenano)).

* Se evita mantener el bloqueo mientras se crean los datos de la instantánea del almacenamiento para reducir la contención del bloqueo bajo alta carga concurrente. [#83510](https://github.com/ClickHouse/ClickHouse/pull/83510) ([Duc Canh Le](https://github.com/canhld94)).

<div id="improvement">
  #### Mejora
</div>

* Se introducen dos nuevos tipos de acceso, `READ` y `WRITE`, para fuentes, y se dejan obsoletos todos los tipos de acceso anteriores relacionados con ellas. Antes: `GRANT S3 ON *.* TO user`; ahora: `GRANT READ, WRITE ON S3 TO user`. Esto también permite separar los permisos `READ` y `WRITE` para fuentes, p. ej.: `GRANT READ ON * TO user`, `GRANT WRITE ON S3 TO user`. La funcionalidad se controla mediante la configuración `access_control_improvements.enable_read_write_grants` y está deshabilitada de forma predeterminada. [#73659](https://github.com/ClickHouse/ClickHouse/pull/73659) ([pufit](https://github.com/pufit)).
* Verifica que la part tenga un archivo `checksum.txt` con una suma de comprobación coherente justo antes de confirmarla. [#76625](https://github.com/ClickHouse/ClickHouse/pull/76625) ([Sema Checherinda](https://github.com/CheSema)).
* Se implementan los métodos `moveFile` y `replaceFile` en s3&#95;plain&#95;rewritable para admitirlo como disco de base de datos. [#79424](https://github.com/ClickHouse/ClickHouse/pull/79424) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Se permiten backups para bases de datos PostgreSQL, MySQL y DataLake. Un backup de una base de datos de este tipo solo guardaría la definición y no los datos que contiene. [#79982](https://github.com/ClickHouse/ClickHouse/pull/79982) ([Nikolay Degterinsky](https://github.com/evillique)).
* Se admiten eliminaciones por posición para el motor de tabla Iceberg. [#80237](https://github.com/ClickHouse/ClickHouse/pull/80237) ([YanghongZhong](https://github.com/yahoNanJing)).
* La configuración `allow_experimental_join_condition` se marcó como obsoleta. [#80566](https://github.com/ClickHouse/ClickHouse/pull/80566) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Se añaden métricas de presión a las métricas asíncronas de ClickHouse. [#80779](https://github.com/ClickHouse/ClickHouse/pull/80779) ([Xander Garbett](https://github.com/Garbett1)).
* Se añadieron las métricas `MarkCacheEvictedBytes`, `MarkCacheEvictedMarks`, `MarkCacheEvictedFiles` para rastrear expulsiones de la caché de marcas. (issue [#60989](https://github.com/ClickHouse/ClickHouse/issues/60989)). [#80799](https://github.com/ClickHouse/ClickHouse/pull/80799) ([Shivji Kumar Jha](https://github.com/shiv4289)).
* Se acelera el listado de tablas en los catálogos de datos mediante solicitudes asíncronas. [#81084](https://github.com/ClickHouse/ClickHouse/pull/81084) ([alesapin](https://github.com/alesapin)).
* Se admite la escritura de `enum` de Parquet como un arreglo de bytes, tal como dicta la [especificación](https://github.com/apache/parquet-format/blob/master/LogicalTypes.md#enum). Escribiré más información más adelante. [#81090](https://github.com/ClickHouse/ClickHouse/pull/81090) ([Arthur Passos](https://github.com/arthurpassos)).
* Una mejora para el motor de tabla `DeltaLake`: delta-kernel-rs tiene la API `ExpressionVisitor`, que se implementa en este PR y se aplica a la transformación de expresiones de columnas de partición (reemplazará una forma antigua y obsoleta de delta-kernel-rs que se usaba antes en nuestro código).
