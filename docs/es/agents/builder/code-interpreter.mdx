El Intérprete de código permite que un agente ejecute código en un sandbox gestionado. Úselo para cálculos, transformación de datos, conversión de formatos, generación de gráficos y cualquier otra tarea que se resuelva mejor con código que con lenguaje natural.

## Habilitar el intérprete de código {#enable-it}

En el Constructor de Agentes, active **Run Code** en la sección **Capabilities** y, a continuación, guarde los cambios. El agente decide cuándo ejecutar código en función de la solicitud del usuario y de las instrucciones que se le hayan dado.

## Lenguajes compatibles {#supported-languages}

El sandbox es un entorno Unix con dos entornos de ejecución de propósito general y algunas utilidades de shell:

* **Python 3**: la opción predeterminada para tareas con datos.
* **Node.js (JavaScript)**: cuando un agente prefiere JS para el trabajo.
* **Bash** y **sh**: scripting de shell para encadenar comandos y realizar operaciones rápidas de E/S.
* **AWK** y **sed**: procesamiento de texto orientado a líneas.
* **bc**: cálculos matemáticos de precisión arbitraria.

Los agentes recurren primero a Python para cualquier tarea que implique analizar, transformar o procesar datos.

<Tip>
  Reserve las herramientas de shell para tareas que realmente se resuelvan mejor con un comando de una sola línea.
</Tip>

## Archivos {#files}

Los usuarios pueden subir archivos a una conversación; el intérprete de código puede acceder a ellos en el directorio de trabajo del sandbox. El código también puede generar archivos de salida (CSV, gráficos, archivos comprimidos), que aparecen en la conversación como adjuntos descargables.

## Aislamiento del sandbox {#sandbox-isolation}

Cada ejecución se realiza en un sandbox efímero, sin acceso a la red ni almacenamiento persistente. Las sesiones no comparten estado: las variables y los archivos de una ejecución no pasan a la siguiente, a menos que el agente los vuelva a cargar explícitamente.

Se aplican límites de recursos específicos de cada plan (memoria, archivos por ejecución, cuotas mensuales de solicitudes). Los errores y la salida de stderr se muestran en la conversación junto con stdout.

## Cuándo usarlo {#when-to-use-it}

Recurra al intérprete de código cuando la respuesta requiera un cálculo determinista que un modelo de lenguaje no pueda obtener de forma fiable solo mediante el razonamiento.
Algunos casos habituales son:

* Analizar un archivo CSV o JSON cargado por el usuario.
* Calcular estadísticas descriptivas o ejecutar una simulación rápida.
* Convertir entre formatos (Parquet, JSON, CSV).
* Generar un gráfico a partir de los resultados de una consulta.

<Tip>
  Evite usarlo para tareas que el modelo ya puede resolver a partir del contexto.
  La ejecución de código añade latencia y consume cuota.
</Tip>
