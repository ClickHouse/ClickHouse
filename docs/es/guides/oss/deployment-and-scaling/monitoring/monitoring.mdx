<Note>
  Los datos de monitorización descritos en esta guía están disponibles en ClickHouse Cloud. Además de mostrarse en el panel de control integrado que se describe a continuación, tanto las métricas básicas como las avanzadas de rendimiento también pueden consultarse directamente en la consola principal del servicio.
</Note>

Puede supervisar:

* La utilización de los recursos de hardware.
* Las métricas del servidor ClickHouse.

## Panel de control integrado de observabilidad avanzada {#built-in-advanced-observability-dashboard}

<div className="ch-image-md">
  <Frame>
    ![Panel de control nativo de observabilidad avanzada](/images/cloud/manage/monitoring/native_advanced_dashboard.webp)
  </Frame>
</div>

ClickHouse incluye un panel de control integrado avanzado de observabilidad al que se puede acceder mediante `$HOST:$PORT/dashboard` (requiere usuario y contraseña) y que muestra las siguientes métricas:

* Consultas/segundo
* Uso de CPU (núcleos)
* Consultas en ejecución
* Merges en ejecución
* Bytes seleccionados/segundo
* Espera de E/S
* Espera de CPU
* Uso de CPU del SO (espacio de usuario)
* Uso de CPU del SO (kernel)
* Lectura desde disco
* Lectura desde el sistema de archivos
* Memoria (monitorizada)
* Filas insertadas/segundo
* Total de partes de MergeTree
* Máximo de partes por partición

ClickHouse también supervisa por sí mismo el estado de los recursos de hardware, como:

* La carga y la temperatura de los procesadores.
* La utilización del sistema de almacenamiento, la RAM y la red.

Estos datos se recopilan en la tabla `system.asynchronous_metric_log`.

## Métricas del servidor ClickHouse {#clickhouse-server-metrics}

El servidor de ClickHouse incorpora instrumentación integrada para monitorizar su propio estado.

Para hacer seguimiento de los eventos del servidor, utilice los logs del servidor. Consulte la sección [logger](/es/reference/settings/server-settings/settings/other#logger) del archivo de configuración.

ClickHouse recopila:

* Diversas métricas sobre el uso que hace el servidor de los recursos de cómputo.
* Estadísticas generales sobre el procesamiento de consultas.

Puede consultar las métricas en las tablas [system.metrics](/es/reference/system-tables/metrics), [system.events](/es/reference/system-tables/events) y [system.asynchronous&#95;metrics](/es/reference/system-tables/asynchronous_metrics).

Puede configurar ClickHouse para exportar métricas a [Graphite](https://github.com/graphite-project). Consulte la [sección Graphite](/es/reference/settings/server-settings/settings/graphite#graphite) del archivo de configuración del servidor de ClickHouse. Antes de configurar la exportación de métricas, debe instalar Graphite siguiendo su [guía](https://graphite.readthedocs.io/en/latest/install.html) oficial.

Puede configurar ClickHouse para exportar métricas a [Prometheus](https://prometheus.io). Consulte la [sección Prometheus](/es/reference/settings/server-settings/settings/other#prometheus) del archivo de configuración del servidor de ClickHouse. Antes de configurar la exportación de métricas, debe instalar Prometheus siguiendo su [guía](https://prometheus.io/docs/prometheus/latest/installation/) oficial.

Además, puede monitorizar la disponibilidad del servidor mediante la API HTTP. Envíe una solicitud `HTTP GET` a `/ping`. Si el servidor está disponible, responde con `200 OK`.

Para monitorizar servidores en una configuración de cluster, establezca el parámetro [max&#95;replica&#95;delay&#95;for&#95;distributed&#95;queries](/es/reference/settings/session-settings/max#max_replica_delay_for_distributed_queries) y utilice el recurso HTTP `/replicas_status`. Una solicitud a `/replicas_status` devuelve `200 OK` si la réplica está disponible y no presenta retraso con respecto a las demás réplicas. Si una réplica presenta retraso, devuelve `503 HTTP_SERVICE_UNAVAILABLE` junto con información sobre el desfase.
