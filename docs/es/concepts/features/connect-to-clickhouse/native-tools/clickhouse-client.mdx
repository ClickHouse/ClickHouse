ClickHouse proporciona un Client de línea de comandos nativo para ejecutar consultas SQL directamente en un servidor de ClickHouse.
Admite tanto el modo interactivo (para ejecutar consultas en directo) como el modo por lotes (para scripts y automatización).
Los resultados de las consultas se pueden mostrar en la terminal o exportar a un archivo en cualquiera de los [formatos](/es/reference/formats/index) de salida de ClickHouse, como Pretty, CSV o JSON, entre otros.

El Client ofrece información en real-time sobre la ejecución de consultas mediante una barra de progreso e indica el número de filas leídas, los bytes procesados y el tiempo de ejecución de la consulta.
Admite tanto [opciones de la línea de comandos](#command-line-options) como [archivos de configuración](#configuration_files).

## Instalación {#install}

Para descargar ClickHouse, ejecute:

```bash
curl https://clickhouse.com/ | sh
```

Para instalarlo también, ejecute:

```bash
sudo ./clickhouse install
```

Consulte [Instalar ClickHouse](/es/get-started/setup/install) para ver más opciones de instalación.

Las distintas versiones del Client y del servidor son compatibles entre sí, pero es posible que algunas funcionalidades no estén disponibles en versiones anteriores del Client. Recomendamos utilizar la misma versión para el Client y el servidor.

## Ejecución {#run}

<Note>
  Si solo descargó ClickHouse y no lo instaló, use `./clickhouse client` en lugar de `clickhouse-client`.
</Note>

Para conectarse a un servidor de ClickHouse, ejecute:

```bash
$ clickhouse-client --host server

ClickHouse client version 24.12.2.29 (official build).
Connecting to server:9000 as user default.
Connected to ClickHouse server version 24.12.2.

:)
```

Especifique datos de conexión adicionales según sea necesario:

| Opción                           | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--port <port>`                  | El puerto en el que el servidor de ClickHouse acepta conexiones. Los puertos predeterminados son 9440 (TLS) y 9000 (sin TLS). Si no se especifica ni `--port` ni `--secure`, se prueban ambos puertos predeterminados de forma concurrente y se utiliza el que responda primero; así, la conexión a un servidor que solo escucha en uno de ellos se establece sin esperar a que se agote el tiempo de espera de conexión del otro. Tenga en cuenta que ClickHouse Client utiliza el protocolo nativo y no HTTP(S). |
| `-s [ --secure ]`                | Indica si se debe usar TLS (normalmente se detecta automáticamente).                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `-u [ --user ] <username>`       | El usuario de base de datos con el que conectarse. De forma predeterminada, se conecta como el usuario `default`.                                                                                                                                                                                                                                                                                                                                                                                                  |
| `--password <password>`          | La contraseña del usuario de base de datos. También puede especificar la contraseña de una conexión en el archivo de configuración. Si no especifica la contraseña, el Client se la solicitará.                                                                                                                                                                                                                                                                                                                   |
| `-c [ --config ] <path-to-file>` | La ubicación del archivo de configuración de ClickHouse Client, si no se encuentra en ninguna de las ubicaciones predeterminadas. Consulte [Archivos de configuración](#configuration_files).                                                                                                                                                                                                                                                                                                                      |
| `--connection <name>`            | El nombre de un conjunto de datos de conexión preconfigurados en el [archivo de configuración](#connection-credentials).                                                                                                                                                                                                                                                                                                                                                                                           |

Para obtener la lista completa de opciones de la línea de comandos, consulte [Opciones de la línea de comandos](#command-line-options).

### Almacenamiento de conexiones en un archivo de configuración {#connection-credentials}

Puede almacenar los datos de conexión de uno o varios servidores de ClickHouse en un [archivo de configuración](#configuration_files).

El formato es el siguiente:

```xml
<config>
    <connections_credentials>
        <connection>
            <name>default</name>
            <hostname>hostname</hostname>
            <port>9440</port>
            <secure>1</secure>
            <user>default</user>
            <password>password</password>
            <!-- <history_file></history_file> -->
            <!-- <history_max_entries></history_max_entries> -->
            <!-- <accept-invalid-certificate>false</accept-invalid-certificate> -->
            <!-- <prompt></prompt> -->
        </connection>
    </connections_credentials>
</config>
```

Consulte la [sección sobre archivos de configuración](#configuration_files) para obtener más información.

<Note>
  Para centrarnos en la sintaxis de consulta, en el resto de los ejemplos se omiten los datos de conexión (`--host`, `--port`, etc.). Recuerde añadirlos cuando ejecute los comandos.
</Note>

## Modo interactivo {#interactive-mode}

### Uso del modo interactivo {#using-interactive-mode}

Para ejecutar ClickHouse en modo interactivo, basta con lanzar:

```bash
clickhouse-client
```

Se abrirá el bucle de lectura-evaluación-impresión (REPL), donde puede empezar a escribir consultas SQL de forma interactiva.
Una vez conectado, verá un prompt en el que podrá escribir consultas:

```bash
ClickHouse client version 25.x.x.x
Connecting to localhost:9000 as user default.
Connected to ClickHouse server version 25.x.x.x

hostname :)
```

En modo interactivo, el formato de salida predeterminado es `PrettyCompact`.
Puede cambiar el formato mediante la cláusula `FORMAT` de la consulta o la opción de línea de comandos `--format`.
Para utilizar el formato Vertical, puede usar `--vertical` o especificar `\G` al final de la consulta.
En este formato, cada valor se imprime en una línea independiente, lo que resulta práctico para tablas anchas.

En modo interactivo, de forma predeterminada, todo lo introducido se ejecuta al pulsar `Enter`.
No es necesario incluir un punto y coma al final de la consulta.

Puede iniciar el Client con el parámetro `-m, --multiline`.
Para escribir una consulta multilínea, introduzca una barra invertida `\` antes del salto de línea.
Tras pulsar `Enter`, se le pedirá que introduzca la siguiente línea de la consulta.
Para ejecutar la consulta, termínela con un punto y coma y pulse `Enter`.

ClickHouse Client se basa en `replxx` (similar a `readline`), por lo que utiliza atajos de teclado conocidos y mantiene un historial.
El historial se guarda en `~/.clickhouse-client-history` de forma predeterminada.

Para salir del Client, pulse `Ctrl+D` o introduzca una de las siguientes opciones en lugar de una consulta:

* `exit` o `exit;`
* `quit` o `quit;`
* `q`, `Q` o `:q`
* `logout` o `logout;`

### Obtener ayuda {#getting-help}

Puede consultar la documentación de cualquier función, motor de table, tipo de datos, formato, parámetro de configuración u otro componente del sistema sin salir del Client. Escriba `help` seguido de un nombre (también funcionan las formas equivalentes `/help`, `man` y `/man`):

```text
help domainWithoutWWW
```

La búsqueda no distingue entre mayúsculas y minúsculas y consulta la table [`system.documentation`](/es/reference/system-tables/documentation). La documentación correspondiente se renderiza desde Markdown en la terminal, con texto en negrita/cursiva, tables y bloques de código con resaltado de sintaxis. Cuando varios componentes comparten un mismo nombre (por ejemplo, `file`, que es tanto una función como un motor de table), se muestran todos.

Si no hay ninguna coincidencia exacta, el Client muestra una lista de nombres similares (teniendo en cuenta posibles errores tipográficos) y de los componentes cuya documentación menciona la palabra:

```text
help maxx_threads
```

Si escribe `help` sin argumentos, se muestra un breve resumen de uso.

### Comandos {#slash-commands}

El Client ejecuta por sí mismo algunos comandos con el prefijo `/` en lugar de enviarlos al servidor:

| Comando                                               | Descripción                                                                                                                |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `/help <name>`, `/man <name>`                         | Muestra la documentación de `<name>`, igual que `help` más arriba                                                          |
| `/clear`                                              | Limpia la terminal                                                                                                         |
| `/dialect <name>`, `/lang <name>`, `/language <name>` | Cambia el dialecto SQL o, si se introduce sin argumento, muestra el actual (véase [más abajo](#switching-the-sql-dialect)) |

Al escribir `/` al principio de la entrada, se muestran los comandos como [indicaciones](#command-line-options-formatting), y la lista se va acotando a medida que se escribe más del nombre; `Tab` completa el comando que se está escribiendo, y es también la forma de completar los comandos cuando las indicaciones están deshabilitadas. Una `/` enviada sola no es un comando: al igual que en Oracle SQL*Plus, repite la última entrada. Si un nombre de comando está mal escrito, se notifica como tal, junto con los comandos que probablemente se querían usar, en lugar de ejecutarse como consulta:

```text
:) /hepl

Exception on client:
Code: 36. DB::Exception: Unknown command `/hepl`. Maybe you meant: ['/help']. Type `/` at the beginning of the line to see all the commands. (BAD_ARGUMENTS)
```

### Cambiar el dialecto SQL {#switching-the-sql-dialect}

El Client puede analizar consultas en varios dialectos (consulte el parámetro de configuración [`dialect`](/es/reference/settings/session-settings/other#dialect)). Para cambiar de dialecto, escriba `/dialect` seguido de su nombre (también funcionan las formas equivalentes `/language` y `/lang`):

```text
/dialect polyglot
```

El comando es equivalente a `SET dialect = 'polyglot'`, pero, a diferencia de una consulta `SET`, no necesita analizarse en el dialecto actual, por lo que también funciona cuando el dialecto actual no permite expresar dicha consulta (por ejemplo, PromQL no tiene sentencia `SET`). Mientras haya activo un dialecto distinto del predeterminado, este se muestra en el prompt después del nombre visible del servidor:

```text
clickhouse-cloud (polyglot) :)
```

Un prompt personalizado (consulte la opción `--prompt`) no tiene por qué contener el marcador de posición `{display_name}`; en ese caso, el dialecto se añade al final del prompt.

Si se introduce `/dialect` sin argumentos, se muestra el dialecto actual.

El comando solo se reconoce en modo interactivo: un script no interactivo se analiza íntegramente como SQL, y su dialecto se selecciona con la opción `--dialect` o con una sentencia `SET dialect = ...`. Cuando todo el texto de la consulta de `clickhouse-local` consiste únicamente en el comando (por ejemplo, `clickhouse-local -q '/dialect kusto'`), se rechaza con un mensaje que indica que el comando solo está disponible en modo interactivo. Dentro de un script más largo, el comando no se reconoce en absoluto y se analiza como una parte más del script, igual que cualquier otro texto.

### Información sobre el procesamiento de consultas {#processing-info}

Al procesar una consulta, el Client muestra:

1. El progreso, que de forma predeterminada se actualiza como máximo 10 veces por segundo.
   En consultas rápidas, es posible que el progreso no llegue a mostrarse.
2. La consulta formateada tras el análisis, con fines de depuración.
3. El resultado en el formato especificado.
4. El número de líneas del resultado, el tiempo transcurrido y la velocidad media de procesamiento de la consulta.
   Todas las cantidades de datos se refieren a datos sin comprimir.

Puede cancelar una consulta larga pulsando `Ctrl+C`.
Sin embargo, tendrá que esperar un poco a que el servidor aborte la solicitud.
En determinadas etapas no es posible cancelar una consulta.
Si no espera y pulsa `Ctrl+C` por segunda vez, el Client se cerrará.

ClickHouse Client permite pasar datos externos (tablas temporales externas) para usarlos en las consultas.
Para obtener más información, consulte la sección [Datos externos para el procesamiento de consultas](/es/reference/engines/table-engines/special/external-data).

### Alias {#cli_aliases}

Puede usar los siguientes alias desde el REPL:

* `\l` - `SHOW DATABASES`
* `\d` - `SHOW TABLES`
* `\d <TABLE>` - `DESCRIBE TABLE <TABLE>`
* `\c <DATABASE>` - `USE <DATABASE>`
* `.` - repetir la última consulta

Si el argumento de `\d` continúa la consulta `SHOW TABLES` en lugar de nombrar una table (como en `\d FROM system` o `\d LIKE 'hits%'`), se mantiene la enumeración. Una table cuyo nombre coincida con una de estas cláusulas debe escribirse entre comillas: `` \d `format` ``.

### Atajos de teclado {#keyboard_shortcuts}

* `Alt (Option) + Shift + e`: abre el editor con la consulta actual. Puede especificar qué editor utilizar mediante la variable de entorno `EDITOR`. De forma predeterminada, se utiliza `vim`.
* `Alt (Option) + #`: comenta la línea.
* `Ctrl + r`: búsqueda difusa en el historial.

La lista completa de atajos de teclado disponibles se encuentra en [replxx](https://github.com/AmokHuginnsson/replxx/blob/1f149bf/src/replxx_impl.cxx#L262).

<Tip>
  Para que la tecla meta (Option) funcione correctamente en MacOS:

  iTerm2: vaya a Preferences -&gt; Profile -&gt; Keys -&gt; Left Option key y haga clic en Esc+
</Tip>

### Modo Vim {#vim-mode}

Inicie el Client con el parámetro `--vim` para editar consultas con atajos de teclado al estilo de `vim`.
La entrada comienza en modo de inserción; `Esc` cambia al modo normal, donde están disponibles los movimientos (`h`, `j`, `k`, `l`, `w`, `b`, `e`, `0`, `$`, `f`, `t`, `%`, `gg`, `G`, ...), los operadores (`d`, `c`) con recuentos y objetos de texto (`iw`, `aw`, `i(`, `a(`, ...), así como comandos como `x`, `r`, `s`, `o`, `A`, `I`, `D` y `C`.
En el modo Vim, `Enter` inserta una nueva línea en el modo de inserción y salta a la línea siguiente en el modo normal; pulse `Ctrl + j` para enviar la consulta.
En el modo normal, `v` abre la consulta actual en el editor (no disponible en el Client integrado).
Los atajos de búsqueda en el historial (`Ctrl + r`, `Ctrl + s`, `Ctrl + t`, `Alt + r`) y `Alt + #` también funcionan en el modo normal.

## Modo por lotes {#batch-mode}

### Uso del modo por lotes {#using-batch-mode}

En lugar de usar ClickHouse Client de forma interactiva, puede ejecutarlo en modo por lotes.
En el modo por lotes, ClickHouse ejecuta una única consulta y finaliza de inmediato: no hay prompt interactivo ni bucle.

Puede especificar una única consulta de la siguiente manera:

```bash
$ clickhouse-client "SELECT sum(number) FROM numbers(10)"
45
```

También puede usar la opción de línea de comandos `--query`:

```bash
$ clickhouse-client --query "SELECT uniq(number) FROM numbers(10)"
10
```

Puede pasar una consulta a través de `stdin`:

```bash
$ echo "SELECT avg(number) FROM numbers(10)" | clickhouse-client
4.5
```

Si existe una table `messages`, también puede insertar datos desde la línea de comandos:

```bash
$ echo "Hello\nGoodbye" | clickhouse-client --query "INSERT INTO messages FORMAT CSV"
```

Cuando se especifica `--query`, cualquier entrada se añade al final de la solicitud tras un salto de línea.

### Inserción de un archivo CSV en un servicio de ClickHouse remoto {#cloud-example}

En este ejemplo se inserta un archivo CSV del conjunto de datos de ejemplo, `cell_towers.csv`, en la table existente `cell_towers` de la base de datos `default`:

```bash
clickhouse-client --host HOSTNAME.clickhouse.cloud \
  --port 9440 \
  --user default \
  --password PASSWORD \
  --query "INSERT INTO cell_towers FORMAT CSVWithNames" \
  < cell_towers.csv
```

### Ejemplos de inserción de datos desde la línea de comandos {#more-examples}

Hay varias formas de insertar datos desde la línea de comandos.
En el siguiente ejemplo se insertan dos filas de datos CSV en una tabla de ClickHouse mediante el modo por lotes:

```bash
echo -ne "1, 'some text', '2016-08-14 00:00:00'\n2, 'some more text', '2016-08-14 00:00:01'" | \
  clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
```

En el siguiente ejemplo, `cat <<_EOF` inicia un heredoc que lee todo hasta volver a encontrar `_EOF` y, a continuación, lo muestra como salida:

```bash
cat <<_EOF | clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
3, 'some text', '2016-08-14 00:00:00'
4, 'some more text', '2016-08-14 00:00:01'
_EOF
```

En el siguiente ejemplo, el contenido de file.csv se envía a stdout con `cat` y se canaliza como entrada a `clickhouse-client`:

```bash
cat file.csv | clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
```

En modo por lotes, el [formato](/es/reference/formats/index) de datos predeterminado es `TabSeparated`.
Puede especificar el formato en la cláusula `FORMAT` de la consulta, como se muestra en el ejemplo anterior.

## Consultas con parámetros {#cli-queries-with-parameters}

Puede especificar parámetros en una consulta y pasarle valores mediante opciones de la línea de comandos.
Así se evita tener que formatear la consulta con valores dinámicos concretos en el lado del cliente.
Por ejemplo:

```bash
$ clickhouse-client --param_parName="[1, 2]" --query "SELECT {parName: Array(UInt16)}"
[1,2]
```

También es posible definir parámetros desde una [sesión interactiva](#interactive-mode):

```text highlight={4,14}
$ clickhouse-client
ClickHouse client version 25.X.X.XXX (official build).

:) SET param_parName='[1, 2]';

SET param_parName = '[1, 2]'

Query id: 7ac1f84e-e89a-4eeb-a4bb-d24b8f9fd977

Ok.

0 rows in set. Elapsed: 0.000 sec.

:) SELECT {parName:Array(UInt16)}

SELECT {parName:Array(UInt16)}

Query id: 0358a729-7bbe-4191-bb48-29b063c548a7

   ┌─_CAST([1, 2]⋯y(UInt16)')─┐
1. │ [1,2]                    │
   └──────────────────────────┘

1 row in set. Elapsed: 0.006 sec.
```

### Sintaxis de consulta {#cli-queries-with-parameters-syntax}

En la consulta, coloque entre llaves los valores que desea completar mediante parámetros de línea de comandos, con el siguiente formato:

```sql
{<name>:<data type>}
```

| Parámetro   | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`      | Identificador del marcador de posición. La opción de línea de comandos correspondiente es `--param_<name> = value`.                                                                                                                                                                                                                                                                                                                                                                        |
| `data type` | [Tipo de datos](/es/reference/data-types/index) del parámetro. <br /><br />Por ejemplo, una estructura de datos como `(integer, ('string', integer))` puede tener el tipo de datos `Tuple(UInt8, Tuple(String, UInt8))` (también puede usar otros tipos [integer](/es/reference/data-types/int-uint)). <br /><br />También es posible pasar como parámetros el nombre de tabla, el nombre de la base de datos y los nombres de columnas; en ese caso, debe usar `Identifier` como tipo de datos. |

### Ejemplos {#cli-queries-with-parameters-examples}

```bash
$ clickhouse-client --param_tuple_in_tuple="(10, ('dt', 10))" \
    --query "SELECT * FROM table WHERE val = {tuple_in_tuple:Tuple(UInt8, Tuple(String, UInt8))}"

$ clickhouse-client --param_tbl="numbers" --param_db="system" --param_col="number" --param_alias="top_ten" \
    --query "SELECT {col:Identifier} as {alias:Identifier} FROM {db:Identifier}.{tbl:Identifier} LIMIT 10"
```

## Generación de SQL con IA {#ai-sql-generation}

ClickHouse Client incluye asistencia de IA integrada para generar consultas SQL a partir de descripciones en lenguaje natural. Esta funcionalidad permite a los usuarios escribir consultas complejas sin necesidad de tener conocimientos avanzados de SQL.

La asistencia de IA funciona sin configuración adicional si tiene definida la variable de entorno `OPENAI_API_KEY` o `ANTHROPIC_API_KEY`. Para una configuración más avanzada, consulte la sección [Configuración](#ai-sql-generation-configuration).

### Uso {#ai-sql-generation-usage}

Para usar la generación de SQL con IA, anteponga `??` a su consulta en lenguaje natural:

```bash
:) ?? show all users who made purchases in the last 30 days
```

La IA realizará las siguientes acciones:

1. Explorará automáticamente el esquema de su base de datos
2. Generará el SQL adecuado a partir de las tablas y columnas detectadas
3. Ejecutará de inmediato la consulta generada

### Ejemplo {#ai-sql-generation-example}

```bash
:) ?? count orders by product category

Starting AI SQL generation with schema discovery...
──────────────────────────────────────────────────

🔍 list_databases
   ➜ system, default, sales_db

🔍 list_tables_in_database
   database: sales_db
   ➜ orders, products, categories

🔍 get_schema_for_table
   database: sales_db
   table: orders
   ➜ CREATE TABLE orders (order_id UInt64, product_id UInt64, quantity UInt32, ...)

✨ SQL query generated successfully!
──────────────────────────────────────────────────

SELECT
    c.name AS category,
    COUNT(DISTINCT o.order_id) AS order_count
FROM sales_db.orders o
JOIN sales_db.products p ON o.product_id = p.product_id
JOIN sales_db.categories c ON p.category_id = c.category_id
GROUP BY c.name
ORDER BY order_count DESC
```

### Configuración {#ai-sql-generation-configuration}

Para usar la generación de SQL con IA, debe configurar un proveedor de IA en el archivo de configuración de ClickHouse Client. Puede usar OpenAI, Anthropic o cualquier servicio de API compatible con OpenAI.

#### Alternativa de respaldo basada en variables de entorno {#ai-sql-generation-fallback}

Si no se especifica ninguna configuración de IA en el archivo de configuración, ClickHouse Client intentará usar automáticamente las variables de entorno:

1. Primero comprueba la variable de entorno `OPENAI_API_KEY`
2. Si no la encuentra, comprueba la variable de entorno `ANTHROPIC_API_KEY`
3. Si no encuentra ninguna de las dos, las funcionalidades de IA quedarán deshabilitadas

Esto permite una configuración rápida sin necesidad de archivos de configuración:

```bash
# Using OpenAI
export OPENAI_API_KEY=your-openai-key
clickhouse-client

# Using Anthropic
export ANTHROPIC_API_KEY=your-anthropic-key
clickhouse-client
```

#### Archivo de configuración {#ai-sql-generation-configuration-file}

Para tener un mayor control sobre los ajustes de IA, configúrelos en el archivo de configuración de ClickHouse Client, ubicado en:

* `$XDG_CONFIG_HOME/clickhouse/config.xml` (o `~/.config/clickhouse/config.xml` si `XDG_CONFIG_HOME` no está definida) (formato XML)
* `$XDG_CONFIG_HOME/clickhouse/config.yaml` (o `~/.config/clickhouse/config.yaml` si `XDG_CONFIG_HOME` no está definida) (formato YAML)
* `~/.clickhouse-client/config.xml` (formato XML, ubicación heredada)
* `~/.clickhouse-client/config.yaml` (formato YAML, ubicación heredada)
* O especifique una ubicación personalizada con `--config-file`

<Tabs>
  <Tab title="XML">
    ```xml
    <config>
        <ai>
            {/* Obligatorio: su clave de API (o configúrela mediante una variable de entorno) */}
            <api_key>your-api-key-here</api_key>

            {/* Obligatorio: tipo de provider (openai, anthropic) */}
            <provider>openai</provider>

            {/* Modelo que se utilizará (los valores predeterminados varían según el provider) */}
            <model>gpt-4o</model>

            {/* Opcional: punto de conexión de API personalizado para servicios compatibles con OpenAI */}
            {/* <base_url>https://openrouter.ai/api</base_url> */}

            {/* Ajustes de exploración del esquema */}
            <enable_schema_access>true</enable_schema_access>

            {/* Parámetros de generación */}
            {/* Opcional: la temperatura solo se envía al modelo cuando se define aquí.
                 Se omite de forma predeterminada porque algunos modelos rechazan este parámetro. */}
    ```

### Parámetros {#ai-sql-generation-parameters}

<Accordion title="Parámetros obligatorios">
  * `api_key` - Su clave de API para el servicio de IA. Puede omitirse si se define mediante una variable de entorno:
    * OpenAI: `OPENAI_API_KEY`
    * Anthropic: `ANTHROPIC_API_KEY`
    * Nota: la clave de API del archivo de configuración tiene precedencia sobre la variable de entorno
  * `provider` - El provider de IA: `openai` o `anthropic`
    * Si se omite, se utiliza una alternativa de respaldo automática en función de las variables de entorno disponibles
</Accordion>

<Accordion title="Configuración del modelo">
  * `model` - El modelo que se utilizará (predeterminado: depende del provider)
    * OpenAI: `gpt-4o`, `gpt-4`, `gpt-3.5-turbo`, etc.
    * Anthropic: `claude-3-5-sonnet-20241022`, `claude-3-opus-20240229`, etc.
    * OpenRouter: utilice su nomenclatura de modelos, como `anthropic/claude-3.5-sonnet`
</Accordion>

<Accordion title="Configuración de conexión">
  * `base_url` - Punto de conexión de API personalizado para servicios compatibles con OpenAI (opcional)
  * `timeout_seconds` - Tiempo de espera de la solicitud en segundos (predeterminado: `30`)
</Accordion>

<Accordion title="Exploración del esquema">
  * `enable_schema_access` - Permite que la IA explore los esquemas de la base de datos (predeterminado: `true`)
  * `max_steps` - Número máximo de pasos de llamadas a herramientas para explorar el esquema (predeterminado: `10`)
</Accordion>

<Accordion title="Parámetros de generación">
  * `temperature` - Controla la aleatoriedad: 0.0 = determinista, 1.0 = creativo. Se omite de forma predeterminada y solo se envía al modelo cuando se define explícitamente, ya que algunos modelos rechazan este parámetro.
  * `max_tokens` - Longitud máxima de la respuesta en tokens (predeterminado: `1000`)
  * `system_prompt` - Instrucciones personalizadas para la IA (opcional)
</Accordion>

### Cómo funciona {#ai-sql-generation-how-it-works}

El generador de SQL con IA sigue un proceso de varios pasos:

1. **Descubrimiento del esquema**

La IA utiliza herramientas integradas para explorar su base de datos

* Enumera las bases de datos disponibles
* Descubre las tablas de las bases de datos relevantes
* Examina las estructuras de las tablas mediante sentencias `CREATE TABLE`

2. **Generación de consultas**

A partir del esquema descubierto, la IA genera SQL que:

* Se ajusta a la intención que usted expresa en lenguaje natural
* Utiliza los nombres correctos de tablas y columnas
* Aplica los joins y las agregaciones adecuados

3. **Ejecución**

El SQL generado se ejecuta automáticamente y se muestran los resultados

### Limitaciones {#ai-sql-generation-limitations}

* Requiere una conexión activa a Internet
* El uso de la API está sujeto a los límites de solicitudes y los costes del proveedor de IA
* Las consultas complejas pueden requerir varios ajustes
* La IA tiene acceso de solo lectura a la información del esquema, no a los datos en sí

### Seguridad {#ai-sql-generation-security}

* Las claves de API nunca se envían a los servidores ClickHouse
* La IA solo ve información del esquema (nombres y tipos de las tables y columnas), no los datos reales
* Todas las consultas generadas respetan los permisos de base de datos que ya tiene

## Cadena de conexión {#connection_string}

### Uso {#connection-string-usage}

ClickHouse Client también permite conectarse a un servidor de ClickHouse mediante una cadena de conexión similar a las de [MongoDB](https://www.mongodb.com/docs/manual/reference/connection-string/), [PostgreSQL](https://www.postgresql.org/docs/current/libpq-connect.html#LIBPQ-CONNSTRING) y [MySQL](https://dev.mysql.com/doc/refman/8.0/en/connecting-using-uri-or-key-value-pairs.html#connecting-using-uri). Su sintaxis es la siguiente:

```text
clickhouse:[//[user[:password]@][hosts_and_ports]][/database][?query_parameters]
```

| Componente (todos opcionales) | Descripción                                                                                                                                                                                      | Valor predeterminado |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------- |
| `user`                        | Nombre de usuario de la base de datos.                                                                                                                                                           | `default`            |
| `password`                    | Contraseña del usuario de la base de datos. Si se especifica `:` y la contraseña está vacía, el Client solicitará la contraseña del usuario.                                                    | -                    |
| `hosts_and_ports`             | Lista de anfitriones con puertos opcionales `host[:port] [, host:[port]], ...`.                                                                                                                  | `localhost:9000`     |
| `database`                    | Nombre de la base de datos.                                                                                                                                                                      | `default`            |
| `query_parameters`            | Lista de pares clave-valor `param1=value1[,&param2=value2], ...`. Algunos parámetros no requieren ningún valor. Los nombres y valores de los parámetros son sensibles a mayúsculas y minúsculas. | -                    |

### Notas {#connection-string-notes}

Si el nombre de usuario, la contraseña o la base de datos se han especificado en la cadena de conexión, no se pueden especificar mediante `--user`, `--password` o `--database` (y viceversa).

El componente host puede ser un nombre del host o una dirección IPv4 o IPv6.
Las direcciones IPv6 deben ir entre corchetes (`[]`):

```text
clickhouse://[2001:db8::1234]
```

Las cadenas de conexión pueden contener varios anfitriones.
ClickHouse Client intentará conectarse a estos anfitriones en orden (de izquierda a derecha).
Una vez establecida la conexión, no se intentará conectar con los anfitriones restantes.

La cadena de conexión debe especificarse como primer argumento de `clickhouse-client`.
La cadena de conexión se puede combinar con cualquier número de [opciones de la línea de comandos](#command-line-options), excepto `--host` y `--port`.

Se permiten las siguientes claves para `query_parameters`:

| Clave            | Descripción                                                                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `secure` (o `s`) | Si se especifica, el Client se conectará al servidor mediante una conexión segura (TLS). Consulte `--secure` en las [opciones de la línea de comandos](#command-line-options). |

**Codificación porcentual**

Los caracteres que no pertenecen al conjunto US-ASCII, los espacios y los caracteres especiales de los siguientes parámetros deben representarse mediante [codificación porcentual](https://en.wikipedia.org/wiki/URL_encoding):

* `user`
* `password`
* `hosts`
* `database`
* `query parameters`

### Ejemplos {#connection_string_examples}

Conéctese a `localhost` por el puerto 9000 y ejecute la consulta `SELECT 1`.

```bash
clickhouse-client clickhouse://localhost:9000 --query "SELECT 1"
```

Conéctese a `localhost` con el usuario `john`, la contraseña `secret`, el host `127.0.0.1` y el puerto `9000`

```bash
clickhouse-client clickhouse://john:secret@127.0.0.1:9000
```

Conéctese a `localhost` como usuario `default`, usando la dirección IPv6 `[::1]` y el puerto `9000`.

```bash
clickhouse-client clickhouse://[::1]:9000
```

Conéctese a `localhost` por el puerto 9000 en modo multilínea.

```bash
clickhouse-client clickhouse://localhost:9000 '-m'
```

Conéctese a `localhost` por el puerto 9000 con el usuario `default`.

```bash
clickhouse-client clickhouse://default@localhost:9000

# equivalent to:
clickhouse-client clickhouse://localhost:9000 --user default
```

Conéctese a `localhost` en el puerto 9000 y use `my_database` como base de datos predeterminada.

```bash
clickhouse-client clickhouse://localhost:9000/my_database

# equivalent to:
clickhouse-client clickhouse://localhost:9000 --database my_database
```

Conéctese a `localhost` en el puerto 9000, utilice como base de datos predeterminada `my_database`, especificada en la cadena de conexión, y establezca una conexión segura mediante el parámetro abreviado `s`.

```bash
clickhouse-client clickhouse://localhost/my_database?s

# equivalent to:
clickhouse-client clickhouse://localhost/my_database -s
```

Conéctese al host predeterminado con el puerto predeterminado, el usuario `default` y la base de datos predeterminada.

```bash
clickhouse-client clickhouse:
```

Conéctese al host predeterminado a través del puerto predeterminado, con el usuario `my_user` y sin contraseña.

```bash
clickhouse-client clickhouse://my_user@

# Using a blank password between : and @ means to asking the user to enter the password before starting the connection.
clickhouse-client clickhouse://my_user:@
```

Conéctese a `localhost` usando la dirección de correo electrónico como nombre de usuario. El símbolo `@` se representa como `%40` en la codificación porcentual.

```bash
clickhouse-client clickhouse://some_user%40some_mail.com@localhost:9000
```

Conéctese a uno de los dos anfitriones: `192.168.1.15`, `192.168.1.25`.

```bash
clickhouse-client clickhouse://192.168.1.15,192.168.1.25
```

## Formato del ID de consulta {#query-id-format}

En modo interactivo, ClickHouse Client muestra el ID de cada consulta. De forma predeterminada, el ID tiene el siguiente formato:

```sql
Query id: 927f137d-00f1-4175-8914-0dd066365e96
```

Se puede especificar un formato personalizado en un archivo de configuración dentro de una etiqueta `query_id_formats`. El marcador de posición `{query_id}` de la cadena de formato se reemplaza por el ID de consulta. La etiqueta admite varias cadenas de formato.
Esta funcionalidad permite generar URL que faciliten el perfilado de consultas.

**Ejemplo**

```xml
<config>
  <query_id_formats>
    <speedscope>http://speedscope-host/#profileURL=qp%3Fid%3D{query_id}</speedscope>
  </query_id_formats>
</config>
```

Con la configuración anterior, el ID de una consulta se muestra en el siguiente formato:

```response
speedscope:http://speedscope-host/#profileURL=qp%3Fid%3Dc8ecc783-e753-4b38-97f1-42cddfb98b7d
```

### Opciones de consulta {#command-line-options-query}

| Opción                          | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--param_<name>=<value>`        | Valor de sustitución para un parámetro de una [consulta con parámetros](#cli-queries-with-parameters).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `-q [ --query ] <query>`        | La consulta que se ejecutará en modo por lotes. Puede especificarse varias veces (`--query "SELECT 1" --query "SELECT 2"`) o una sola vez con varias consultas separadas por punto y coma (`--query "SELECT 1; SELECT 2;"`). En este último caso, las consultas `INSERT` con formatos distintos de `VALUES` deben separarse mediante líneas en blanco. <br /><br />También puede especificarse una única consulta sin indicar un parámetro: `clickhouse-client "SELECT 1"` <br /><br />No puede utilizarse junto con `--queries-file`.                                                                                                                                                                                                                        |
| `--queries-file <path-to-file>` | Ruta a un archivo que contiene consultas. `--queries-file` puede especificarse varias veces, por ejemplo, `--queries-file queries1.sql --queries-file queries2.sql`. <br /><br />No puede utilizarse junto con `--query`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `-m [ --multiline ]`            | Si se especifica, permite consultas multilínea (no envía la consulta al pulsar Intro). Las consultas solo se enviarán cuando terminen con un punto y coma.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `--ignore-error`                | No se detiene si falla una consulta: informa del error en `stderr` y continúa con la siguiente consulta. Como los errores se ignoran, el proceso finaliza con un código de éxito incluso si algunas consultas han fallado. Solo se aplica en modo por lotes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `--inline-insert-data`          | Envía `INSERT ... VALUES` (y otros formatos en línea) tal cual en el texto de la consulta, en lugar de convertir los datos en bloques en el formato Native. El propio servidor analiza los datos en línea, lo que evita el intercambio de ida y vuelta necesario para devolver al Client la estructura de la tabla y los valores predeterminados de las columnas. Esto puede mejorar el rendimiento cuando se realizan muchas inserciones pequeñas a través del protocolo nativo. Establece automáticamente [`send_table_structure_on_insert_with_inline_data`](/es/reference/settings/session-settings/send#send_table_structure_on_insert_with_inline_data) en `0`. No puede combinarse con datos en línea y datos externos (procedentes de stdin o `INFILE`). |

### Ajustes de consulta {#command-line-options-query-settings}

Los ajustes de consulta se pueden especificar como opciones de la línea de comandos en el Client, por ejemplo:

```bash
$ clickhouse-client --max_threads 1
```

Consulte [Configuración](/es/reference/settings/session-settings) para ver la lista de ajustes.
