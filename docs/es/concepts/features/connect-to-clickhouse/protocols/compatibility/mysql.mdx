ClickHouse admite el protocolo de comunicación de MySQL. Esto permite que ciertos Clients que no disponen de conectores nativos de ClickHouse utilicen en su lugar el protocolo MySQL. Esta compatibilidad se ha validado con las siguientes herramientas de BI:

* [Looker Studio](/es/integrations/connectors/data-visualization/looker-studio-and-clickhouse)
* [Tableau Online](/es/integrations/connectors/data-visualization/tableau/tableau-online-and-clickhouse)
* [QuickSight](/es/integrations/connectors/data-visualization/quicksight-and-clickhouse)

Si está probando otros Clients o integraciones no verificados, tenga en cuenta que podrían existir las siguientes limitaciones:

* Es posible que la implementación de SSL no sea totalmente compatible; podrían surgir problemas con [TLS SNI](https://www.cloudflare.com/learning/ssl/what-is-sni/).
* Una herramienta concreta podría requerir funcionalidades del dialecto (p. ej., funciones o ajustes específicos de MySQL) que aún no están implementadas.

Si hay un controlador nativo disponible (p. ej., [DBeaver](/es/integrations/connectors/sql-clients/dbeaver)), siempre es preferible utilizarlo en lugar de la interfaz de MySQL. Además, aunque la mayoría de los Clients para lenguajes de programación de MySQL deberían funcionar correctamente, no se garantiza que la interfaz de MySQL pueda sustituir sin cambios a una base de código con consultas de MySQL existentes.

Si su caso de uso implica una herramienta concreta que no dispone de un controlador nativo de ClickHouse, desea utilizarla a través de la interfaz de MySQL y ha encontrado alguna incompatibilidad, [cree un issue](https://github.com/ClickHouse/ClickHouse/issues) en el repositorio de ClickHouse.

<Note>
  Para ofrecer una mejor compatibilidad con el dialecto SQL de las herramientas de BI mencionadas, la interfaz de MySQL de ClickHouse ejecuta implícitamente las consultas SELECT con el parámetro de configuración [prefer&#95;column&#95;name&#95;to&#95;alias = 1](/es/reference/settings/session-settings/prefer#prefer_column_name_to_alias).
  Esto no se puede desactivar y, en casos límite poco frecuentes, puede provocar diferencias de comportamiento entre las consultas enviadas a la interfaz normal de ClickHouse y las enviadas a la interfaz de MySQL.
</Note>

## Creación de varios usuarios MySQL en ClickHouse Cloud {#creating-multiple-mysql-users-in-clickhouse-cloud}

De forma predeterminada, existe un usuario integrado `mysql4<subdomain>`, que utiliza la misma contraseña que el usuario `default`. La parte `<subdomain>` es el primer segmento del nombre del host de ClickHouse Cloud. Este formato es necesario para trabajar con herramientas que implementan una conexión segura, pero que no proporcionan [información SNI en su handshake TLS](https://www.cloudflare.com/learning/ssl/what-is-sni), lo que impide realizar el enrutamiento interno sin una pista adicional en el nombre de usuario (el Client de consola de MySQL es una de estas herramientas).

Por este motivo, *recomendamos encarecidamente* seguir el formato `mysql4<subdomain>_<username>` al crear un nuevo usuario destinado a la interfaz de MySQL, donde `<subdomain>` es una pista para identificar su Servicio de Cloud y `<username>` es un sufijo arbitrario de su elección.

<Tip>
  Para un nombre del host de ClickHouse Cloud como `foobar.us-east1.aws.clickhouse.cloud`, la parte `<subdomain>` equivale a `foobar`, y un nombre de usuario MySQL personalizado podría ser `mysql4foobar_team1`.
</Tip>

Puede crear usuarios adicionales para la interfaz de MySQL si, por ejemplo, necesita aplicar ajustes adicionales.

1. Opcional: cree un [perfil de configuración](/es/reference/statements/create/settings-profile) para aplicarlo a su usuario personalizado. Por ejemplo, `my_custom_profile` con un parámetro de configuración adicional que se aplicará de forma predeterminada al conectarse con el usuario que creará más adelante:

   ```sql
   CREATE SETTINGS PROFILE my_custom_profile SETTINGS prefer_column_name_to_alias=1;
   ```

   `prefer_column_name_to_alias` se utiliza solo como ejemplo; puede usar otros ajustes en su lugar.

2. [Cree un usuario](/es/reference/statements/create/user) con el siguiente formato: `mysql4<subdomain>_<username>` ([véase más arriba](#creating-multiple-mysql-users-in-clickhouse-cloud)). La contraseña debe estar en formato doble SHA1. Por ejemplo:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$';
   ```

   o, si desea usar un perfil personalizado para este usuario:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$' SETTINGS PROFILE 'my_custom_profile';
   ```

   donde `my_custom_profile` es el nombre del perfil que creó anteriormente.

3. [Otorgue](/es/reference/statements/grant) al nuevo usuario los permisos necesarios para interactuar con las tablas o bases de datos que necesite. Por ejemplo, si desea otorgar acceso únicamente a `system.query_log`:

   ```sql
   GRANT SELECT ON system.query_log TO mysql4foobar_team1;
   ```

4. Utilice el usuario creado para conectarse a su servicio de ClickHouse Cloud mediante la interfaz de MySQL.

### Resolución de problemas con varios usuarios MySQL en ClickHouse Cloud {#troubleshooting-multiple-mysql-users-in-clickhouse-cloud}

Si creó un nuevo usuario MySQL y obtiene el siguiente error al conectarse con el Client CLI de MySQL:

```sql
ERROR 2013 (HY000): Lost connection to MySQL server at 'reading authorization packet', system error: 54
```

En este caso, asegúrese de que el nombre de usuario siga el formato `mysql4<subdomain>_<username>`, tal como se describe ([más arriba](#creating-multiple-mysql-users-in-clickhouse-cloud)).

## Habilitar la interfaz de MySQL en ClickHouse autogestionado {#enabling-the-mysql-interface-on-self-managed-clickhouse}

Agregue el parámetro de configuración [mysql&#95;port](/es/reference/settings/server-settings/settings/mysql#mysql_port) al archivo de configuración de su servidor. Por ejemplo, puede definir el puerto en un nuevo archivo XML dentro de su [carpeta](/es/concepts/features/configuration/server-config/configuration-files) `config.d/`:

```xml
<clickhouse>
    <mysql_port>9004</mysql_port>
</clickhouse>
```

Inicie su servidor de ClickHouse y busque un mensaje de log similar al siguiente, que contiene Listening for MySQL compatibility protocol:

```bash
{} <Information> Application: Listening for MySQL compatibility protocol: 127.0.0.1:9004
```

## Conectar MySQL a ClickHouse {#connect-mysql-to-clickhouse}

El siguiente comando muestra cómo conectar el Client `mysql` de MySQL a ClickHouse:

```bash
mysql --protocol tcp -h [hostname] -u [username] -P [port_number] [database_name]
```

Por ejemplo:

```bash
$ mysql --protocol tcp -h 127.0.0.1 -u default -P 9004 default
```

Salida si la conexión se establece correctamente:

```text
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 4
Server version: 20.2.1.1-ClickHouse

Copyright (c) 2000, 2019, Oracle and/or its affiliates. All rights reserved.

Oracle is a registered trademark of Oracle Corporation and/or its
affiliates. Other names may be trademarks of their respective
owners.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>
```

Para garantizar la compatibilidad con todos los Clients de MySQL, se recomienda especificar la contraseña del usuario con [doble SHA1](/es/concepts/features/configuration/settings/settings-users#user-namepassword) en el archivo de configuración.
Si la contraseña del usuario se especifica con [SHA256](/es/reference/functions/regular-functions/hash-functions#SHA256), algunos Clients no podrán autenticarse (mysqljs y versiones antiguas de la herramienta de línea de comandos de MySQL y MariaDB).

Restricciones:

* las consultas preparadas no son compatibles

* algunos tipos de datos se envían como cadenas

Para cancelar una consulta de larga duración, utilice la sentencia `KILL QUERY connection_id` (durante su procesamiento, se reemplaza por `KILL QUERY WHERE query_id = connection_id`). Por ejemplo:

```bash
$ mysql --protocol tcp -h mysql_server -P 9004 default -u default --password=123 -e "KILL QUERY 123456;"
```
