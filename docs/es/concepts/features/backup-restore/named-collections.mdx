Las [colecciones con nombre](/es/concepts/features/configuration/server-config/named-collections) creadas mediante SQL
pueden exportarse a una copia de seguridad y restaurarse desde ella a través de la tabla `system.named_collections`.
Una colección exportada contiene sus valores, incluidos los secretos, por lo que la copia de seguridad
y la restauración de colecciones se rigen por sus propios privilegios y ajustes, que se documentan en esta página.

Las colecciones definidas en los archivos de configuración del servidor se generan a partir de la configuración y
nunca forman parte de una copia de seguridad; restaurar una colección desde una copia de seguridad no sobrescribe una colección
definida en la configuración que tenga el mismo nombre.

## Selección de las colecciones {#selecting-the-collections}

Una consulta `BACKUP` exporta las colecciones con nombre cuando selecciona la tabla
`system.named_collections`:

* De forma explícita: `BACKUP TABLE system.named_collections`. En este caso, los privilegios necesarios (véase más abajo) son
  obligatorios.
* De forma implícita, mediante un elemento `DATABASE system` o `ALL`. De forma predeterminada, este tipo de copia de seguridad exporta las
  colecciones solo si el usuario puede leer sus valores; de lo contrario, las omite y emite una advertencia, de modo
  que `BACKUP ALL` siga funcionando para un usuario que puede hacer copias de seguridad de todo, pero no puede leer los
  valores.

Una selección que excluye los datos de la tabla (`BACKUP TABLE system.named_collections EXCEPT DATA FROM
TABLE system.named_collections`, o un elemento con comodín con `EXCEPT DATA FROM TABLES
system.named_collections`) conserva únicamente la definición de la tabla en la copia de seguridad. No exporta ninguna
colección ni requiere ninguno de los privilegios que se indican a continuación.

## Privilegios requeridos {#required-privileges}

Al exportar las colecciones, sus valores se escriben en la copia de seguridad, por lo que se requieren los mismos privilegios
que para leer los valores de `system.named_collections`:
[`SHOW NAMED COLLECTIONS`](/es/reference/statements/grant#named-collection-admin),
`SHOW NAMED COLLECTIONS SECRETS` y
[`displaySecretsInShowAndSelect`](/es/reference/statements/grant#displaysecretsinshowandselect).
Esto también se aplica a un almacenamiento cifrado de colecciones con nombre: las entradas se copian como texto cifrado,
pero cualquier servidor que disponga de la misma clave las restaura en colecciones cuyos valores pueden leerse después.

Para restaurar las colecciones se requiere el privilegio
[`CREATE NAMED COLLECTION`](/es/reference/statements/grant#named-collection-admin). No
se requieren los privilegios indicados anteriormente: un operador puede restaurar una copia de seguridad sin poder
leerla, y los errores y logs de dicha restauración nunca mencionan el nombre de ninguna colección.

En el caso de `BACKUP ON CLUSTER` y `RESTORE ON CLUSTER`, los privilegios se comprueban para el usuario iniciador
en el host iniciador antes de que la consulta se envíe a los demás hosts. Durante una actualización
progresiva, un host que ejecuta una versión con esta funcionalidad nunca exporta ni restaura las colecciones en
una consulta enviada por un initiator que ejecuta una versión sin ella, ya que dicho initiator no puede
comprobar los privilegios: la exportación se omite (o, si se trata de una selección explícita, se rechaza), y la
restauración de las entradas de colecciones se rechaza.

## `backup_named_collections` {#backup-named-collections}

Tipo: `Bool`. Opcional; sin establecer de forma predeterminada.

Controla si una consulta `BACKUP` exporta las colecciones con nombre:

* Sin establecer (valor predeterminado): un elemento `TABLE system.named_collections` explícito las exporta y
  requiere los privilegios; un elemento `DATABASE system` o `ALL` solo las exporta si el usuario
  tiene los privilegios y, en caso contrario, las omite y emite una advertencia.
* `true`: la copia de seguridad exporta las colecciones siempre que la consulta seleccione la tabla, y la falta de
  privilegios provoca un error incluso cuando la selección es implícita.
* `false`: la copia de seguridad nunca exporta las colecciones, ni siquiera cuando se indica explícitamente la tabla
  `system.named_collections`, y no requiere ninguno de los privilegios.

```sql
-- Fails instead of skipping the collections when the privileges are missing:
BACKUP ALL TO Disk('backups', 'everything') SETTINGS backup_named_collections = 1

-- Never exports the collections:
BACKUP ALL TO Disk('backups', 'no_collections') SETTINGS backup_named_collections = 0
```

## `restore_named_collections` {#restore-named-collections}

Tipo: `Bool`. Valor predeterminado: `true`.

Indica si una consulta `RESTORE` restaura las colecciones con nombre incluidas en la copia de seguridad. A diferencia de
[`restore_table_data`](/es/concepts/features/backup-restore/restore-settings) y los ajustes análogos, el valor predeterminado sigue siendo
`true` con `structure_only`: las colecciones son definiciones, y una tabla cuyo motor
hace referencia a una colección (p. ej., `ENGINE = URL(collection)`) no puede crearse sin ella.

```sql
-- Restores everything except the named collections:
RESTORE ALL FROM Disk('backups', 'everything') SETTINGS restore_named_collections = 0
```

## `create_named_collection` {#create-named-collection}

Tipo: `String`. Valor predeterminado: `'if-not-exists'`.

Cómo gestiona `RESTORE` una colección con nombre que ya existe:

* `'if-not-exists'` (valor predeterminado): se conserva la colección existente y se omite la
  de la copia de seguridad.
* `'create'`: si la colección ya existe, la restauración falla.
* `'replace'`: la colección existente se reemplaza por la de la copia de seguridad. Una colección definida en
  la configuración del servidor no se puede reemplazar y provoca que la restauración falle.

```sql
RESTORE TABLE system.named_collections FROM Disk('backups', 'everything')
SETTINGS create_named_collection = 'replace'
```

## Almacenamiento cifrado de colecciones con nombre {#encrypted-storage}

Con un [almacenamiento cifrado para colecciones con nombre](/es/concepts/features/configuration/server-config/named-collections)
(`local_encrypted` o `zookeeper_encrypted`), las entradas se copian en la copia de seguridad tal como
están en texto cifrado en el almacenamiento, seguidas de un código de autenticación: ningún valor en texto sin cifrar aparece
en ninguna parte de la copia de seguridad, y si una entrada se ha modificado, la restauración falla antes de descifrar nada.

Para restaurar una copia de seguridad de este tipo se necesita un servidor cuyo almacenamiento de colecciones con nombre también esté cifrado y
contenga la clave con la que se cifraron las colecciones. Las entradas restauradas se vuelven a cifrar con la
clave del servidor que realiza la restauración. Una copia de seguridad con entradas cifradas no se puede restaurar en un almacenamiento
sin cifrar; configure un almacenamiento cifrado que contenga la clave u omita las colecciones con
`restore_named_collections = 0`.
