<Info>
  **Usuarios de Windows**

  ClickHouse se ejecuta de forma nativa en Linux y macOS. En Windows, ejecuta estos pasos dentro de
  [Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/about).
</Info>

La ClickHouse CLI (`clickhousectl`, alias `chctl`) instala y administra versiones locales
de ClickHouse, ejecuta servidores locales de ClickHouse y Postgres, ejecuta consultas
y administra ClickHouse Cloud. Esta página te guía por la instalación de la CLI,
el inicio de un servidor de ClickHouse local y la conexión a él.

Si usaste el script de [instalación rápida](/es/get-started/setup/self-managed/quick-install),
`clickhousectl` ya está instalado. Pasa directamente a
[Instala ClickHouse](#cli-install-clickhouse).

<Steps>
  <Step title="Instale la CLI de ClickHouse" id="install-the-cli">
    El script de instalación es compatible con macOS y Linux en x86&#95;64 y ARM64:

    ```bash
    curl -fsSL https://clickhouse.com/cli | sh
    ```

    El script instala `clickhousectl` en `~/.local/bin` y crea un alias `chctl`
    en el mismo directorio. Si el script indica que `~/.local/bin` no está en su `PATH`, agréguelo
    y añada esa misma línea al perfil de su shell (`~/.bashrc`, `~/.zshrc`) para las sesiones
    futuras:

    ```bash
    export PATH="$HOME/.local/bin:$PATH"
    ```

    <Accordion title="Otros métodos de instalación">
      | Herramienta                                    | Comando                         |
      | ---------------------------------------------- | ------------------------------- |
      | npm                                            | `npm install -g clickhousectl`  |
      | uv                                             | `uv tool install clickhousectl` |
      | pipx                                           | `pipx install clickhousectl`    |
      | pip                                            | `pip install clickhousectl`     |
      | cargo-binstall                                 | `cargo binstall clickhousectl`  |
      | Cargo, a partir del código fuente (Rust 1.94+) | `cargo install clickhousectl`   |

      Solo el script de instalación y npm crean el alias `chctl`.
    </Accordion>

    Para comprobar si hay una versión más reciente de la CLI e instalarla:

    ```bash
    clickhousectl update --check
    clickhousectl update
    ```
  </Step>

  <Step title="Instale ClickHouse" id="cli-install-clickhouse">
    Instale la versión más reciente de ClickHouse y establézcala como predeterminada:

    ```bash
    clickhousectl local use latest
    ```

    `local use` instala la versión si aún no está presente, la establece como
    predeterminada y crea un enlace simbólico `clickhouse` en `~/.local/bin`, de modo que puede ejecutar el
    binario `clickhouse` directamente. Así, cualquier paso posterior de esta documentación que ejecute un
    comando `clickhouse` funcionará sin cambios, siempre que `~/.local/bin` esté en su `PATH`.

    También puede seleccionar la versión de soporte a largo plazo (LTS) más reciente o una
    versión específica:

    ```bash
    clickhousectl local use lts             # Latest LTS release
    clickhousectl local use 26.8            # Latest 26.8.x.x release
    clickhousectl local use 26.8.1.1760     # Exact version
    ```

    Para ver qué versiones menores están disponibles para descargar y qué versiones
    tiene instaladas:

    ```bash
    clickhousectl local list --remote
    clickhousectl local list
    ```

    <Info>
      **use frente a install**

      `clickhousectl local use <version>` instala una versión *y* la establece como
      predeterminada, además de actualizar el enlace simbólico `clickhouse`. `clickhousectl local install <version>`
      solo descarga una versión; esta solo pasa a ser la predeterminada si aún no
      tiene ninguna, y no actualiza el enlace simbólico. Para establecer la versión predeterminada sin crear ni
      actualizar el enlace simbólico, use `clickhousectl local use <version> --no-global`.
    </Info>
  </Step>

  <Step title="Inicie clickhouse-server" id="cli-start-clickhouse-server">
    `clickhousectl` limita el ámbito de los servidores locales al directorio desde el que lo ejecutas. Crea un
    directorio de proyecto e inicia un servidor en él:

    ```bash
    mkdir my-project && cd my-project
    clickhousectl local server start
    ```

    ```response
    Server 'default' started in background (PID: 14705)
      HTTP port: 8123
      TCP port:  9000
      Version:   26.9.1.1312
    ```

    El servidor se ejecuta en segundo plano y se llama `default`. Sus datos se almacenan en
    `./.clickhouse/`, por lo que debe ejecutar los comandos `clickhousectl local` posteriores desde el mismo
    directorio; `clickhousectl` no busca en los directorios superiores. El servidor escucha
    en el puerto HTTP `8123` y en el puerto TCP `9000`, o en puertos libres si estos ya están en uso.
    Para elegir los puertos, use `--http-port` y `--tcp-port`. Para ejecutar más de un
    servidor, asigne un nombre a cada uno, por ejemplo, `clickhousectl local server start dev`.

    Para comprobar que se está ejecutando:

    ```bash
    clickhousectl local server list
    ```

    ```response
    | Name    | Status  | PID   | Version     | HTTP Port | TCP Port |
    |---------|---------|-------|-------------|-----------|----------|
    | default | running | 14705 | 26.9.1.1312 | 8123      | 9000     |

    1 server, 1 running
    ```
  </Step>

  <Step title="Inicie clickhouse-client" id="cli-start-clickhouse-client">
    Conéctese al servidor con `clickhouse-client` desde el mismo directorio:

    ```bash
    clickhousectl local client
    ```

    `local client` se conecta al servidor llamado `default` y usa la misma
    versión de ClickHouse que el servidor. Para conectarse a otro servidor, indique su nombre,
    por ejemplo, `clickhousectl local client dev`. Verá algo similar a lo siguiente:

    ```response
    ClickHouse client version 26.9.1.1312 (official build).
    Connecting to localhost:9000 as user default.
    Connected to ClickHouse server version 26.9.1.

    local-host :)
    ```

    ¡Ya puede empezar a enviar comandos SQL a ClickHouse! Escriba `exit` para
    salir del cliente.

    Para ejecutar una sola consulta sin abrir una sesión interactiva, use `-q`:

    ```bash
    clickhousectl local client -q "SELECT version()"
    ```

    <Tip>
      La guía [Creación de tablas en ClickHouse](/es/get-started/quickstarts/creating-tables) le explica paso a paso cómo crear tablas e insertar datos.
    </Tip>
  </Step>

  <Step title="Detenga el servidor" id="cli-stop-clickhouse-server">
    El servidor sigue ejecutándose en segundo plano hasta que lo detengas. Para detenerlo, hazlo desde el
    mismo directorio:

    ```bash
    clickhousectl local server stop
    ```

    Al detener el servidor, sus datos se conservan para la próxima ejecución de `clickhousectl local server start`.

    <Warning>
      `clickhousectl local server remove` elimina permanentemente los datos de un servidor detenido.
    </Warning>
  </Step>
</Steps>

## Próximos pasos {#next-steps}

* **Ejecute Postgres localmente.** Con Docker en ejecución, inicie un servidor Postgres local
  y conéctese a él con `psql`:

  ```bash
  clickhousectl local postgres start
  clickhousectl local postgres client
  ```

* **Conéctese a ClickHouse Cloud.** Cree una cuenta o inicie sesión con una
  existente. El inicio de sesión desde el navegador es de solo lectura; para crear o modificar recursos de Cloud se necesita una
  clave de API, que `clickhousectl cloud auth login --interactive` le solicitará.

  ```bash
  clickhousectl cloud auth signup
  clickhousectl cloud auth login
  ```

* **Descubra el resto de la CLI.** Consulte la [referencia de clickhousectl](/es/concepts/features/interfaces/cli)
  o ejecute `clickhousectl --help`.
