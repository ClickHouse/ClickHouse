### Añadir datos con la Consola SQL {#add-data-using-the-sql-console}

        Al igual que la mayoría de los sistemas de gestión de bases de datos, ClickHouse agrupa lógicamente las tablas en **bases de datos**. Utilice el comando [`CREATE DATABASE`](/es/reference/statements/create/database) para crear una nueva base de datos en ClickHouse:

        ```sql
        CREATE DATABASE IF NOT EXISTS helloworld
        ```

        Ejecute el siguiente comando para crear una tabla llamada `my_first_table` en la base de datos `helloworld`:

        ```sql
        CREATE TABLE helloworld.my_first_table
        (
            user_id UInt32,
            message String,
            timestamp DateTime,
            metric Float32
        )
        ENGINE = MergeTree()
        PRIMARY KEY (user_id, timestamp)
        ```

        En el ejemplo anterior, `my_first_table` es una tabla [`MergeTree`](/es/reference/engines/table-engines/mergetree-family/mergetree) con cuatro columnas:

        * `user_id`:  un entero sin signo de 32 bits ([UInt32](/es/reference/data-types/int-uint))
        * `message`: un tipo de datos [String](/es/reference/data-types/string), que sustituye a tipos como `VARCHAR`, `BLOB`, `CLOB` y otros propios de otros sistemas de bases de datos
        * `timestamp`: un valor [DateTime](/es/reference/data-types/datetime), que representa un instante en el tiempo
        * `metric`: un número de coma flotante de 32 bits ([Float32](/es/reference/data-types/float))

        <Info>
          **Motores de tablas**

          Los motores de tablas determinan:

          * Cómo y dónde se almacenan los datos
          * Qué consultas se admiten
          * Si los datos se replican o no

          <br />

          Hay muchos motores de tablas entre los que elegir, pero para una tabla sencilla en un servidor de ClickHouse de un solo nodo, lo más probable es que elija [`MergeTree`](/es/reference/engines/table-engines/mergetree-family/mergetree).
        </Info>

#### Breve introducción a las claves primarias {#a-brief-intro-to-primary-keys}

        Antes de continuar, es importante entender cómo funcionan las claves primarias en ClickHouse (¡la implementación
        de las claves primarias puede resultar inesperada!):

        * las claves primarias en ClickHouse ***no son únicas*** para cada fila de una tabla

        La clave primaria de una tabla de ClickHouse determina cómo se ordenan los datos al escribirse en disco. Por cada 8,192 filas o 10MB de
        datos (lo que se denomina **granularidad del índice**) se crea una entrada en el archivo de índice de clave primaria. Este concepto de granularidad
        da lugar a un **índice disperso** que cabe fácilmente en memoria, y los gránulos representan una franja con la cantidad mínima de
        datos de columna que se procesa durante las consultas `SELECT`.

        La clave primaria se puede definir mediante el parámetro `PRIMARY KEY`. Si define una tabla sin especificar una `PRIMARY KEY`,
        la clave pasa a ser la tupla especificada en la cláusula `ORDER BY`. Si especifica tanto una `PRIMARY KEY` como un `ORDER BY`, la clave primaria debe ser un subconjunto del criterio de ordenación.

        La clave primaria es también la clave de ordenación, que es la tupla `(user_id, timestamp)`.  Por lo tanto, los datos almacenados en cada
        archivo de columna estarán ordenados por `user_id` y, a continuación, por `timestamp`.

        Para un análisis en profundidad de los conceptos fundamentales de ClickHouse, consulte [&quot;Conceptos fundamentales&quot;](/es/concepts/core-concepts/index).

#### Insertar datos en su tabla {#insert-data-into-your-table}

        Puede usar el conocido comando [`INSERT INTO TABLE`](/es/reference/statements/insert-into) con ClickHouse, pero es importante tener en cuenta que cada inserción en una tabla [`MergeTree`](/es/reference/engines/table-engines/mergetree-family/mergetree) crea una **parte** en el almacenamiento.

        <Tip>
          **Práctica recomendada de ClickHouse**

          Inserte una gran cantidad de filas por lote: decenas de miles o incluso millones de
          filas a la vez. No se preocupe: ClickHouse puede gestionar sin problemas ese volumen de datos y, además, le permitirá [ahorrar dinero](/es/concepts/best-practices/selecting-an-insert-strategy#batch-inserts-if-synchronous), ya que se envían menos solicitudes de escritura a su servicio.
        </Tip>

        <br />

        Aunque se trate de un ejemplo sencillo, insertemos más de una fila a la vez:

        ```sql
        INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
            (101, 'Hello, ClickHouse!',                                 now(),       -1.0    ),
            (102, 'Insert a lot of rows per batch',                     yesterday(), 1.41421 ),
            (102, 'Sort your data based on your commonly-used queries', today(),     2.718   ),
            (101, 'Granules are the smallest chunks of data read',      now() + 5,   3.14159 )
        ```

        <Note>
          Observe que la columna `timestamp` se rellena mediante varias funciones de [**Date**](/es/reference/data-types/date) y [**DateTime**](/es/reference/data-types/datetime). ClickHouse ofrece cientos de funciones útiles que puede [consultar en la sección **Funciones**](/es/reference/functions/index).
        </Note>

        Comprobemos que ha funcionado:

        ```sql
        SELECT * FROM helloworld.my_first_table
        ```

### Añadir datos con ClickHouse Client {#add-data-using-the-clickhouse-client}

        También puede conectarse a su servicio de ClickHouse Cloud mediante una herramienta de línea de comandos llamada [**clickhouse client**](/es/concepts/features/interfaces/client). Haga clic en `Connect` en el menú izquierdo para acceder a estos detalles. En el cuadro de diálogo, seleccione `Native` en la lista desplegable:

        <div className="ch-image-lg">
          <Frame>
            ![datos de conexión del cliente de ClickHouse](/images/_snippets/client_details.webp)
          </Frame>
        </div>

        <br />

        1. Instale [ClickHouse](/es/get-started/setup/self-managed/quick-install).

        2. Ejecute el comando, sustituyendo los valores por su nombre de host, nombre de usuario y contraseña:

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password>
        ```

        Si aparece el indicador con la carita sonriente, ¡ya puede ejecutar consultas!

        ```response
        :)
        ```

        3. Pruébelo ejecutando la siguiente consulta:

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        ```

        Observe que la respuesta se devuelve en un práctico formato de tabla:

        ```response
        ┌─user_id─┬─message────────────────────────────────────────────┬───────────timestamp─┬──metric─┐
        │     102 │ Insert a lot of rows per batch                     │ 2022-03-21 00:00:00 │ 1.41421 │
        │     102 │ Sort your data based on your commonly-used queries │ 2022-03-22 00:00:00 │   2.718 │
        │     101 │ Hello, ClickHouse!                                 │ 2022-03-22 14:04:09 │      -1 │
        │     101 │ Granules are the smallest chunks of data read      │ 2022-03-22 14:04:14 │ 3.14159 │
        └─────────┴────────────────────────────────────────────────────┴─────────────────────┴─────────┘

        4 rows in set. Elapsed: 0.008 sec.
        ```

        4. Agregue una cláusula [`FORMAT`](/es/reference/statements/select/format) para especificar uno de los [numerosos formatos de salida compatibles con ClickHouse](/es/reference/formats/index):

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        FORMAT TabSeparated
        ```

        En la consulta anterior, la salida se devuelve en formato tab-separated:

        ```response
        Query id: 3604df1c-acfd-4117-9c56-f86c69721121

        102 Insert a lot of rows per batch      2022-03-21 00:00:00     1.41421
        102 Sort your data based on your commonly-used queries  2022-03-22 00:00:00     2.718
        101 Hello, ClickHouse!  2022-03-22 14:04:09     -1
        101 Granules are the smallest chunks of data read       2022-03-22 14:04:14     3.14159

        4 rows in set. Elapsed: 0.005 sec.
        ```

        5. Para salir de `clickhouse client`, introduzca el comando **exit**:

        <br />

        ```bash
        exit
        ```

### Subir un archivo {#upload-a-file}

        Una tarea habitual al empezar a trabajar con una base de datos es insertar datos que ya tiene en archivos. Disponemos de algunos
        datos de muestra disponibles en línea que puede insertar y que representan datos de clickstream: incluyen un ID de usuario, la URL visitada y
        la marca de tiempo del evento.

        Supongamos que tenemos el siguiente texto en un archivo CSV llamado `data.csv`:

        ```bash title="data.csv"
        102,This is data in a file,2022-02-22 10:43:28,123.45
        101,It is comma-separated,2022-02-23 00:00:00,456.78
        103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
        ```

        1. El siguiente comando inserta los datos en `my_first_table`:

        <br />

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password> \
        --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
        ```

        2. Si consulta desde la consola SQL, verá que ahora aparecen las nuevas filas en la tabla:

        <br />

        <div className="ch-image-lg">
          <Frame>
            ![Nuevas filas del archivo CSV](/images/_snippets/new_rows_from_csv.webp)
          </Frame>
        </div>
