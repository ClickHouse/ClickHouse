## Solucionar el error de verificación del desarrollador en macOS {#fix-the-developer-verification-error-in-macos}

De forma predeterminada, macOS no ejecuta aplicaciones ni herramientas descargadas de Internet a menos que estén firmadas por un desarrollador identificado y notarizadas por Apple.

A partir de la versión 26.7.4 (y en todas las versiones 26.8 y posteriores), las compilaciones de ClickHouse para macOS están firmadas con el Developer ID de ClickHouse Inc. y notarizadas por Apple. Se publican en la [página de versiones de GitHub](https://github.com/ClickHouse/ClickHouse/releases) como `clickhouse-macos.zip` (Intel) y `clickhouse-macos-aarch64.zip` (Apple silicon), y son las que instala el cask de Homebrew. Si utiliza alguna de ellas, macOS ejecuta `clickhouse` sin mostrar ninguna advertencia y no necesita seguir los pasos de este artículo.

Aun así, es posible que vea el error si ejecuta un binary sin firmar que macOS ha puesto en cuarentena, por ejemplo:

* una versión anterior de ClickHouse instalada con Homebrew: ejecute `brew upgrade --cask clickhouse` para obtener la versión firmada;
* el binary autoextraíble `clickhouse-macos` o `clickhouse-macos-aarch64` de la página de versiones de GitHub descargado con un navegador web: en su lugar, descargue el archivo `.zip` de la misma versión;
* una versión anterior a la 26.7.4 descargada con un navegador web.

El binary instalado con `curl https://clickhouse.com/ | sh` no está firmado, pero `curl` no pone en cuarentena los archivos que descarga, por lo que macOS lo ejecuta sin mostrar este error.

Al intentar ejecutar un binary `clickhouse` en cuarentena, es posible que aparezca este error:

<Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/dev-verification-error.webp" size="md" alt="Cuadro de diálogo del error de verificación del desarrollador de MacOS" border />

Si no puede cambiar a una compilación firmada, saque el binary de la cuarentena, ya sea desde Ajustes del Sistema o desde la terminal.

## Proceso en Ajustes del Sistema {#system-settings-process}

1. Intenta ejecutar el binary `clickhouse` una vez para que macOS muestre el error anterior y registre el binary bloqueado.

2. Abre **Ajustes del Sistema**.

3. Ve a **Privacy &amp; Security**:

   <Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/privacy-and-security-default-view.webp" size="md" alt="vista predeterminada de Privacy & Security en MacOS" border />

4. Desplázate hasta la sección **Security** para encontrar un mensaje que indica que *&quot;clickhouse-macos-aarch64&quot; fue bloqueado porque no proviene de un desarrollador identificado*.

5. Haz clic en **Allow Anyway** (**Open Anyway** en las versiones recientes de macOS).

   <Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/privacy-and-security-screen-allow-anyway.webp" size="md" alt="configuración de Privacy & Security en MacOS que muestra el botón Allow Anyway" border />

6. Introduce la contraseña de tu usuario de macOS.

Ahora deberías poder ejecutar comandos de `clickhouse` en tu terminal. Es posible que macOS te pida confirmarlo una vez más la próxima vez que lo ejecutes.

## Proceso en la terminal {#terminal-process}

Si el botón de Ajustes del Sistema no soluciona el problema, o si prefieres usar la línea de comandos, elimina el atributo de cuarentena del binary con `xattr`.

Si `clickhouse` está en tu `PATH`, averigua dónde se encuentra:

```shell
which clickhouse
```

Esto debería mostrar algo similar a:

```shell
/opt/homebrew/bin/clickhouse
```

Elimine `clickhouse` de la cuarentena ejecutando `xattr -d com.apple.quarantine`, seguido de la ruta del comando anterior:

```shell
xattr -d com.apple.quarantine /opt/homebrew/bin/clickhouse
```

Ahora ya deberías poder ejecutar `clickhouse`:

```shell
clickhouse
```

Esto debería mostrar algo similar a:

```shell
Use one of the following commands:
clickhouse local [args]
clickhouse client [args]
clickhouse benchmark [args]
...
```
