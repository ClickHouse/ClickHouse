<Note>
  Esta página trata sobre **Self-managed ClickHouse Observability**. Si prefiere la experiencia totalmente gestionada, que es la opción recomendada, consulte la documentación [aquí](/es/clickstack/observability/managing/config).
</Note>

Esta guía describe los ajustes del origen de datos, el recolector que ejecuta y la configuración del esquema de base de datos en Self-managed ClickHouse Observability.

## Interfaz de usuario {#hyperdx}

### Configuración del origen de datos {#datasource-settings}

La interfaz de usuario requiere que el usuario defina una fuente para cada uno de los tipos de datos o pilares de observabilidad:

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

Abra **Team Settings → Data → Sources** para configurar una fuente. Seleccione **Configure Optional Fields** para acceder a ajustes adicionales, como se muestra resaltado a continuación para los logs:

<div className="ch-image-md">
  <Frame>
    ![Configuración de la fuente de registros con Configure Optional Fields resaltado](/images/clickstack/source-settings-optional-fields.png)
  </Frame>
</div>

Cada fuente necesita una tabla y unas correspondencias de columnas que permitan a la interfaz de usuario consultar sus datos. Las fuentes de métricas de OTel usan una tabla independiente para cada tipo de métrica; seleccione las tablas que contienen las métricas que recopila.

Si utiliza el [esquema predeterminado de OpenTelemetry (OTel)](/es/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema) distribuido con ClickStack, estas columnas pueden inferirse automáticamente para cada una de las fuentes. Si [modifica el esquema](#clickhouse) o utiliza un esquema personalizado, deberá especificar y actualizar estas correspondencias.

<Note>
  El recopilador de ClickStack crea sus tablas predeterminadas mediante migraciones de esquemas incluidas. Estos esquemas se basan en el [exportador de ClickHouse para el OTel collector](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter) y en el [modelo de datos de OpenTelemetry](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
</Note>

Las siguientes tablas recogen los ajustes de las fuentes. Los valores inferidos dependen de las columnas y tablas presentes en su base de datos. Las correspondencias opcionales habilitan las funcionalidades asociadas, como la correlación de trazas; no son necesarias para guardar una fuente.

#### Vistas materializadas {#materialized-views-settings}

Las vistas materializadas pueden registrarse en orígenes de datos de logs y de trazas para que las consultas de agregación aptas se resuelvan a partir de la vista preagregada en lugar de la tabla de origen. Para obtener información sobre cómo crear y registrar vistas, consulte [&quot;Vistas materializadas&quot;](/es/clickstack/self-configured/managing/materialized-views).

Cada vista registrada se configura con los siguientes ajustes:

| Ajuste                   | Descripción                                                                                                                                                                                                                                                                       |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Database`               | Base de datos en ClickHouse que contiene la tabla de destino de la vista materializada.                                                                                                                                                                                           |
| `Table`                  | Tabla de destino de la vista materializada, no la vista en sí.                                                                                                                                                                                                                    |
| `Timestamp Column`       | Columna de marca de tiempo de la tabla de destino.                                                                                                                                                                                                                                |
| `Granularity`            | Intervalo de tiempo de la columna de marca de tiempo de la tabla de destino, por ejemplo, `1 minute`. Una consulta solo puede usar la vista si su propio intervalo de tiempo es igual o de mayor granularidad que este.                                                           |
| `Minimum Date`           | Opcional. Fecha y hora más antiguas para las que la vista contiene datos. Si no se indica, ClickStack asume que la vista contiene datos para todas las fechas presentes en la tabla de origen.                                                                                    |
| `Dimension Columns`      | Lista separada por comas de las columnas que la vista no preagrega y que, por lo tanto, pueden usarse para filtrar y agrupar.                                                                                                                                                     |
| `Pre-aggregated Columns` | Columnas que la vista preagrega. Cada entrada asigna una función de agregación (`avg`, `count`, `max`, `min`, `quantile`, `sum` o `histogram`) y una columna de la tabla de origen a la columna correspondiente de la vista. La columna de origen no es obligatoria para `count`. |

Al seleccionar la tabla de destino, la interfaz de usuario intenta inferir estos ajustes a partir del esquema de la vista. Revise los valores inferidos y complete los campos que falten.

#### Vistas materializadas de metadata {#metadata-materialized-views-settings}

Las vistas materializadas de metadata son vistas materializadas que agilizan el descubrimiento de campos para los filtros y el autocompletado. Pueden configurarse en los orígenes de datos de logs y de trazas.

| Ajuste             | Descripción                                                                             |
| ------------------ | --------------------------------------------------------------------------------------- |
| `Key Rollup Table` | Opcional y obsoleto. Tabla de agregación de las claves presentes en la tabla de origen. |
| `KV Rollup Table`  | Tabla de agregación de los pares clave/valor presentes en la tabla de origen.           |
| `Granularity`      | Intervalo de tiempo que utilizan las tablas de agregación; por ejemplo, `15 minute`.    |

#### Atributos Destacados {#highlighted-attributes}

Los Atributos Destacados y los Atributos de Traza Destacados se pueden configurar en los orígenes de datos de logs y de trazas.

* Los Atributos Destacados son columnas o expresiones que se muestran para cada log o span al ver sus detalles.
* Los Atributos de Traza Destacados son columnas o expresiones que se consultan en cada log o span de una traza y se muestran encima del waterfall de la traza.

Estos atributos se definen en la configuración de la fuente y pueden ser expresiones SQL arbitrarias. Si la expresión SQL devuelve un valor con formato de URL, el atributo se mostrará como un enlace. Los valores vacíos no se muestran.

Cada atributo se configura con los siguientes ajustes:

| Ajuste              | Descripción                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| `SQL Expression`    | La columna o expresión SQL arbitraria que se consultará. Obligatorio.                                |
| `Alias`             | Opcional. La etiqueta que se muestra para el atributo en lugar de la expresión SQL.                  |
| `Lucene Expression` | Opcional. Una versión en Lucene de la expresión SQL, que se usa al buscar el valor de este atributo. |

### Fuentes correlacionadas {#correlated-sources}

Para habilitar la correlación completa entre fuentes, debe configurar fuentes correlacionadas para logs, trazas, métricas y sesiones. Esto permite que la interfaz de usuario asocie los datos relacionados y ofrezca un contexto más completo al mostrar los eventos.

* `Logs`: se pueden correlacionar con trazas y métricas.
* `Traces`: se pueden correlacionar con logs, sesiones y métricas.
* `Metrics`: se pueden correlacionar con logs.
* `Sessions`: se pueden correlacionar con trazas.

Definir estas correlaciones habilita varias funcionalidades. Por ejemplo, la interfaz de usuario puede mostrar los logs relevantes junto a una traza y permitir la navegación entre fuentes relacionadas. La correlación también depende de que existan las correspondencias adecuadas de ID y atributos; seleccionar una fuente por sí solo no crea esas relaciones.

## Recolector de OpenTelemetry {#otel-collector}

Consulte [&quot;Recopilador de OpenTelemetry de ClickStack&quot;](/es/clickstack/self-configured/ingesting-data/collector) para obtener más información.

* `CLICKHOUSE_ENDPOINT`
  * **Valor predeterminado:** *None (obligatorio)* para la imagen del recolector independiente.
  * **Descripción:** URL de conexión de ClickHouse que utiliza el exportador.
  * **Recomendaciones:**
    * Utilice un endpoint seguro de ClickHouse Cloud, como `https://<host>:8443` o `tcp://<host>:9440?secure=true`
    * Es obligatorio para que el recolector pueda enviar datos a ClickHouse

* `CLICKHOUSE_USER`
  * **Valor predeterminado:** `default` en la herramienta de migración; para el recolector independiente, configúrelo explícitamente.
  * **Descripción:** Nombre de usuario con el que se autentica en la instancia de ClickHouse.
  * **Recomendaciones:**
    * El usuario necesita permiso para insertar telemetría y, si la creación de esquemas o las migraciones están habilitadas, para crear o modificar los objetos de base de datos necesarios
    * Se recomienda crear un usuario dedicado para la ingestión

* `CLICKHOUSE_PASSWORD`
  * **Valor predeterminado:** *None (obligatorio si la autenticación está habilitada)*
  * **Descripción:** Contraseña del usuario de ClickHouse especificado.
  * **Recomendaciones:**
    * Es obligatoria si la cuenta de usuario tiene una contraseña definida
    * En implementaciones de producción, almacénela de forma segura mediante secretos

* `HYPERDX_LOG_LEVEL`
  * **Valor predeterminado:** Depende de la implementación; configúrelo explícitamente, por ejemplo, `info`.
  * **Descripción:** Nivel de detalle de los logs del recolector.
  * **Recomendaciones:**
    * Admite valores como `debug`, `info`, `warn` y `error`
    * Utilice `debug` durante la resolución de problemas

* `OTLP_AUTH_TOKEN`
  * **Valor predeterminado:** *None*. Solo se utiliza con la imagen independiente.
  * **Descripción:** Define el token necesario para la ingestión OTLP independiente. El recolector actual acepta su valor en el encabezado `Authorization`, ya sea directamente o con el prefijo `Bearer`. Es posible que las versiones anteriores del recolector requieran el token sin prefijo. Se ignora si hay autenticación OIDC configurada.
  * **Recomendaciones:**
    * Configure la autenticación antes de exponer el recolector. Sin un token ni una configuración OIDC, el receiver OTLP independiente acepta solicitudes no autenticadas.

* `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE`
  * **Valor predeterminado:** `default` en la herramienta de migración; para el recolector independiente, configúrelo explícitamente.
  * **Descripción:** Base de datos en ClickHouse en la que el recolector escribe los datos de telemetría.
  * **Recomendaciones:**
    * Configúrelo si utiliza un nombre de base de datos personalizado
    * Asegúrese de que el usuario especificado tenga acceso a esta base de datos

## ClickHouse {#clickhouse}

Para ajustar ClickHouse de forma eficaz, debe comprender conceptos clave de almacenamiento como las [partes](/es/concepts/core-concepts/parts), las [particiones](/es/concepts/core-concepts/partitions), los [segmentos y réplicas](/es/guides/oss/deployment-and-scaling/shards) y cómo se producen las [fusiones](/es/concepts/core-concepts/merges) en el momento de inserción. Recomendamos repasar los fundamentos de los [índices primarios](/es/concepts/core-concepts/primary-indexes), los [índices secundarios dispersos](/es/concepts/features/performance/skip-indexes/skipping-indexes) y los índices de omisión de datos, así como las técnicas para [gestionar el ciclo de vida de los datos](/es/guides/use-cases/observability/build-your-own/managing-data), por ejemplo, mediante un ciclo de vida basado en TTL.

Puede [personalizar el esquema](/es/guides/use-cases/observability/build-your-own/schema-design): modificar los tipos de columnas, extraer nuevos campos (p. ej., de los logs), aplicar códecs y diccionarios, y acelerar las consultas mediante proyecciones.

Además, las vistas materializadas pueden utilizarse para [transformar o filtrar datos durante la ingestión](/es/guides/use-cases/observability/build-your-own/schema-design#materialized-views), siempre que los datos se escriban en la tabla de origen de la vista y la aplicación lea de la tabla de destino. Las vistas materializadas también permiten [acelerar las consultas de forma nativa](/es/clickstack/self-configured/managing/materialized-views) en el servicio.

Para más información, consulte la documentación de ClickHouse sobre diseño de esquemas, estrategias de indexación y buenas prácticas de gestión de datos, la mayoría de las cuales se aplican directamente a las implementaciones autogestionadas.
