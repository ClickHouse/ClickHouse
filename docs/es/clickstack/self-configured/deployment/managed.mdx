Esta **guía está dirigida a usuarios actuales de ClickHouse Cloud**. Si es nuevo en ClickHouse Cloud, le recomendamos nuestra guía de [Primeros pasos](/es/clickstack/self-configured/getting-started/managed) para Self-managed ClickHouse Observability.

En este patrón de despliegue, tanto ClickHouse como la UI de ClickStack se alojan en ClickHouse Cloud, lo que reduce al mínimo el número de componentes que el usuario debe autoalojar.

Además de simplificar la administración de la infraestructura, este patrón de despliegue garantiza que la autenticación esté integrada con el SSO/SAML de ClickHouse Cloud. A diferencia de las implementaciones autoalojadas, tampoco es necesario aprovisionar una instancia de MongoDB para almacenar el estado de la aplicación, como dashboards, búsquedas guardadas, configuración del usuario y alertas. Los usuarios también se benefician de:

* Escalado automático de la capacidad de cómputo de forma independiente del almacenamiento
* Retención de bajo costo y prácticamente ilimitada basada en almacenamiento de objetos
* La posibilidad de [aislar de forma independiente los workloads de lectura y escritura](/es/clickstack/self-configured/managing/isolating-read-write) mediante almacenes.
* Autenticación integrada
* Copias de seguridad automatizadas
* Funciones de seguridad y cumplimiento normativo
* Actualizaciones sin interrupciones

En este modo, la ingesta de datos queda completamente a cargo del usuario. Puede ingestar datos en Self-managed ClickHouse Observability mediante su propio recolector de OpenTelemetry alojado, ingestión directa desde bibliotecas cliente, motores de tablas nativos de ClickHouse (como Kafka o S3), canalizaciones ETL o ClickPipes, el servicio de ingestión gestionado de ClickHouse Cloud. Este enfoque es la forma más sencilla y eficiente de operar ClickStack.

### Casos de uso adecuados {#suitable-for}

Este patrón de despliegue es ideal en los siguientes escenarios:

1. Ya tiene datos de observabilidad en ClickHouse Cloud y desea visualizarlos con ClickStack.
2. Opera un despliegue de observabilidad a gran escala y necesita el rendimiento dedicado y la escalabilidad que ofrece ClickStack ejecutándose en ClickHouse Cloud.
3. Ya utiliza ClickHouse Cloud para analítica y desea instrumentar su aplicación con las bibliotecas de instrumentación de ClickStack, enviando los datos al mismo cluster. En este caso, recomendamos usar [almacenes](/es/products/cloud/features/infrastructure/warehouses) para aislar la capacidad de cómputo destinada a los workloads de observabilidad.

### Crear una base de datos y una tabla {#create-database-and-tables}

            Vector requiere que la tabla y el esquema estén definidos antes de la ingesta de datos.

            Primero, cree una base de datos. Puede hacerlo desde la [consola de ClickHouse Cloud](/es/products/cloud/features/sql-console-features/sql-console).

            Por ejemplo, cree una base de datos para logs:

            ```sql
            CREATE DATABASE IF NOT EXISTS logs
            ```

            A continuación, cree una table cuyo esquema coincida con la estructura de sus datos de log. El siguiente ejemplo presupone el formato de registro de acceso clásico de Nginx:

            ```sql
            CREATE TABLE logs.nginx_logs
            (
                `time_local` DateTime,
                `remote_addr` IPv4,
                `remote_user` LowCardinality(String),
                `request` String,
                `status` UInt16,
                `body_bytes_sent` UInt64,
                `http_referer` String,
                `http_user_agent` String,
                `http_x_forwarded_for` LowCardinality(String),
                `request_time` Float32,
                `upstream_response_time` Float32,
                `http_host` String
            )
            ENGINE = MergeTree
            ORDER BY (toStartOfMinute(time_local), status, remote_addr);
            ```

            Su tabla debe ajustarse al esquema de salida generado por Vector. Adapte el esquema a sus datos según sea necesario, siguiendo las [buenas prácticas de esquema](/es/concepts/best-practices/select-data-type) recomendadas.

            Recomendamos encarecidamente comprender cómo funcionan las [claves primarias](/es/concepts/core-concepts/primary-indexes) en ClickHouse y elegir una clave de ordenación en función de sus patrones de acceso. Consulte la guía [específica de ClickStack](/es/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key) sobre cómo elegir una clave primaria.

            Una vez creada la tabla, copie el fragmento de configuración que se muestra. Ajuste la entrada para que consuma sus canalizaciones existentes y, si es necesario, también la tabla de destino y la base de datos. Las credenciales deberían aparecer ya completadas.

## Tareas adicionales {#additional-tasks}

### Concesión de acceso a Self-managed ClickHouse Observability {#configure-access}

1. Acceda a su servicio en la consola de ClickHouse Cloud
2. Vaya a **Settings** → **SQL Console Access**
3. Asigne el nivel de permiso adecuado a cada usuario:
   * **Service Admin → Full Access** - Obligatorio para habilitar las alertas
   * **Service Read Only → Read Only** - Permite ver los datos de observabilidad y crear dashboards
   * **No access** - No permite acceder a la UI de ClickStack

### Uso de ClickStack con recursos de cómputo de solo lectura {#clickstack-read-only-compute}

La UI de ClickStack puede ejecutarse por completo en un servicio de ClickHouse Cloud de solo lectura. Es la configuración recomendada cuando se quieren aislar los workloads de ingestión y de consultas.

#### Cómo selecciona ClickStack la capacidad de cómputo {#how-clickstack-selects-compute}

La UI de ClickStack siempre se conecta al servicio de ClickHouse desde el que se abre en la consola de ClickHouse Cloud.

Esto significa que:

* Si abre ClickStack desde un servicio de solo lectura, todas las consultas que realice la UI de ClickStack se ejecutarán en esa capacidad de cómputo de solo lectura.
* Si abre ClickStack desde un servicio de lectura y escritura, ClickStack utilizará, en cambio, la capacidad de cómputo de ese servicio.

No es necesaria ninguna configuración adicional en ClickStack para garantizar el comportamiento de solo lectura.

#### Configuración recomendada {#recommended-setup}

Para ejecutar ClickStack en recursos de cómputo de solo lectura:

1. Cree o identifique un servicio de ClickHouse Cloud en el almacén configurado como de solo lectura.
2. En la consola de ClickHouse Cloud, seleccione el servicio de solo lectura.
3. Inicie ClickStack desde el menú de la barra de navegación izquierda.

Una vez iniciada, la UI de ClickStack se vinculará automáticamente a este servicio de solo lectura.

Tenga en cuenta que los dashboards, las búsquedas guardadas, las alertas y las fuentes se limitan al servicio desde el que se inició ClickStack, por lo que nada de lo guardado en otro servicio del almacén estará disponible aquí y tendrá que volver a crearse. Las fuentes que usan el esquema estándar de OpenTelemetry se detectan automáticamente, por lo que la búsqueda sobre esos datos funciona de inmediato; en cambio, las fuentes personalizadas o configuradas manualmente no se detectan y deben configurarse de nuevo.

Para conocer la topología completa (incluido hacia dónde dirigir la ingestión, en qué servicio ejecutar las sentencias DDL y cómo se comportan las alertas), consulte [&quot;Aislamiento de workloads de lectura y escritura&quot;](/es/clickstack/self-configured/managing/isolating-read-write).

## Elección de esquema: Map frente a JSON {#schema-choice-map-vs-json}

De forma predeterminada, ClickStack almacena los atributos en columnas `Map(LowCardinality(String), String)`. Este es el esquema recomendado para workloads de observabilidad. Junto con la [serialización de mapas por cubetas](/es/reference/data-types/map#bucketed-map-serialization) y los índices de texto sobre las claves y valores del mapa, permite búsquedas selectivas sin la sobrecarga de ingesta por clave que generan las subcolumnas JSON dinámicas.

Hay disponible un esquema basado en el tipo `JSON` en Beta para su evaluación en workloads con un conjunto de claves de atributo reducido y estable. **No se recomienda** como opción predeterminada. Consulte [Map frente al tipo JSON](/es/clickstack/self-configured/ingesting-data/schema/map-vs-json) para ver la comparación completa y las variables de entorno necesarias para activar la compatibilidad con JSON.
