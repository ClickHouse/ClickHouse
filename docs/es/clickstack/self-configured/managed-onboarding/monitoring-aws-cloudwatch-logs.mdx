<Note>
  Esta página trata sobre **Self-managed ClickHouse Observability**. Si prefiere la experiencia totalmente gestionada recomendada, consulte la documentación [aquí](/es/clickstack/observability/integration-examples/cloudwatch).
</Note>

Esta guía explica cómo reenviar log de AWS CloudWatch a Self-managed ClickHouse Observability mediante el [receptor `awscloudwatch`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver) de OpenTelemetry y, después, visualizarlos en la UI de ClickStack.

Ejecutaremos un recolector independiente que sondea CloudWatch a través de la API de AWS y reenvía los eventos a su recopilador de ClickStack mediante OTLP. Mantenga este recolector en la misma cuenta de AWS y en la misma región que los grupos de registros para minimizar la latencia y el coste de la API.

En esta guía se da por hecho que ya ha completado [Configuración de su recopilador de OpenTelemetry](/es/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) y que tiene un recopilador de ClickStack en ejecución.

El recopilador de ClickStack puede desplegarse como un **contenedor de Docker** (consulte [Configuración de su recopilador de OpenTelemetry](/es/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)) o como una **versión de Helm** en Kubernetes mediante el gráfico de Helm upstream de OpenTelemetry con la imagen del recopilador de ClickStack (consulte [Implementación del recolector](/es/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)). **Asegúrese de haber anotado su endpoint OTLP** y el `OTLP_AUTH_TOKEN` que definió al desplegarlo.

<Steps>
  <Step title="Prepare los requisitos previos" id="gather-prerequisites">
    Necesitará:

    * Una **cuenta de AWS** con uno o más grupos de registros de CloudWatch y credenciales con los permisos de IAM que se indican a continuación.
    * Un host con **Docker** instalado, acceso a la API de AWS y acceso de red saliente a su recopilador de ClickStack. Normalmente se trata de una instancia EC2 en la misma cuenta y región de AWS que los grupos de registros.
    * El **endpoint OTLP** de su recopilador de ClickStack, accesible desde este host. Si se ejecuta en Docker en la misma máquina, use `http://host.docker.internal:4318` (consulte el recuadro destacado en [Configurar el receptor de CloudWatch](#configure-receiver)). Si el recolector es remoto, use su URL completa, por ejemplo, `https://otel.example.com:4318`.
    * El valor de `OTLP_AUTH_TOKEN` que configuró en su recopilador de ClickStack. Si no lo protegió, puede eliminar el encabezado `authorization` de la configuración que se muestra a continuación.
  </Step>

  <Step title="Configure las credenciales de AWS" id="configure-aws">
    El receptor obtiene las credenciales de AWS de las variables de entorno estándar. Expórtelas en el host en el que se ejecutará el recolector.

    **Para usuarios de AWS SSO:**

    ```shell
    aws sso login --profile YOUR_PROFILE_NAME
    eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
    aws sts get-caller-identity
    ```

    **Para usuarios de IAM con credenciales de larga duración:**

    ```shell
    export AWS_ACCESS_KEY_ID="your-access-key-id"
    export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
    export AWS_REGION="us-east-1"
    aws sts get-caller-identity
    ```

    Las credenciales requieren la siguiente política de IAM para leer los logs de CloudWatch:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Reemplace `YOUR_ACCOUNT_ID` por el ID de su cuenta de AWS.

    <Info>
      **Credenciales de producción**

      En producción, es preferible usar credenciales asociadas a la instancia en lugar de claves de larga duración: un rol de IAM en EC2, IRSA en EKS o un rol de tarea en ECS. La misma configuración del recolector que se muestra a continuación funciona sin variables de entorno de credenciales cuando el receptor puede obtener las credenciales del servicio de metadatos de instancia.
    </Info>
  </Step>

  <Step title="Configure el receptor de CloudWatch" id="configure-receiver">
    Exporte el endpoint y el token de autenticación de su recopilador de ClickStack y, a continuación, cree un archivo `otel-collector-config.yaml`.

    <Info>
      **Configuración en el mismo host**

      En el siguiente ejemplo se da por hecho que el recopilador de ClickStack y este recolector de CloudWatch se ejecutan en el mismo host, por lo que el receptor se conecta a él mediante `host.docker.internal` (la dirección del host de Docker desde dentro de un contenedor). Si su recopilador de ClickStack se encuentra en otro lugar (un servicio in-cluster, una URL pública, una IP privada), sustituya su dirección en `OTEL_COLLECTOR_ENDPOINT` más abajo.
    </Info>

    ```shell
    export OTEL_COLLECTOR_ENDPOINT="http://host.docker.internal:4318"
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    ```

    <Accordion title="Descubra los grupos de registros disponibles en su cuenta">
      Antes de editar la configuración, enumere los grupos de registros que existen en su región para poder elegir nombres reales (y confirmar que la región es la correcta):

      ```shell
      aws logs describe-log-groups --region eu-central-1 \
        --query 'logGroups[].logGroupName' --output table
      ```

      Ejemplo de salida:

      ```text
      -------------------------------
      |      DescribeLogGroups      |
      +-----------------------------+
      |  /aws-glue/jobs/error       |
      |  /aws-glue/jobs/logs-v2     |
      |  /aws-glue/jobs/output      |
      |  /aws-glue/sessions/error   |
      |  /aws-glue/sessions/output  |
      +-----------------------------+
      ```

      Use los nombres de esta lista directamente en el bloque `groups.named` del Ejemplo 1 que aparece más abajo. Para la cuenta anterior, la sección de grupos con nombre quedaría así:

      ```yaml
      groups:
        named:
          /aws-glue/jobs/error:
          /aws-glue/jobs/logs-v2:
          /aws-glue/jobs/output:
          /aws-glue/sessions/error:
          /aws-glue/sessions/output:
      ```

      Como alternativa, si los grupos que le interesan comparten un prefijo común (en este caso, `/aws-glue/`), use el Ejemplo 2 con `prefix: /aws-glue/` en lugar de enumerarlos uno por uno.
    </Accordion>

    **Ejemplo 1: grupos de registros con nombre (recomendado)**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws-glue/jobs/error:
              /aws-glue/jobs/output:
              /aws-glue/sessions/error:

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    **Ejemplo 2: Detección automática de grupos de registros por prefijo**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            autodiscover:
              limit: 100
              prefix: /aws-glue/

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    Ajustes clave que conviene modificar:

    * `region`, para que coincida con la región donde se encuentran sus grupos de registros.
    * `poll_interval` (`1m` de forma predeterminada). Los valores más bajos permiten obtener logs casi en real-time, a costa de más llamadas a la API de AWS.
    * `groups.named`, para indicar una lista explícita, o `groups.autodiscover.prefix`, para incluir todos los grupos que coincidan con un prefijo.

    Para ver el conjunto completo de opciones, consulte la [documentación del receptor de CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver).

    <Info>
      **Solo logs recientes**

      En la primera ejecución, el receptor establece un punto de control en la hora actual y solo recupera los logs generados a partir de ese momento. No se realiza la carga de datos históricos de los logs anteriores.
    </Info>
  </Step>

  <Step title="Inicie el recolector receptor" id="start-collector">
    Cree un archivo `docker-compose.yaml` junto a `otel-collector-config.yaml`. La entrada `extra_hosts` permite que el contenedor acceda, mediante `host.docker.internal`, a un recopilador de ClickStack que se ejecuta en el mismo host; el montaje de tipo bind en su sintaxis larga genera un error explícito si falta el archivo de configuración, en lugar de crear silenciosamente un directorio vacío:

    ```shell
    cat > docker-compose.yaml <<'EOF'
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:latest
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_COLLECTOR_ENDPOINT
          - OTLP_AUTH_TOKEN
        extra_hosts:
          - "host.docker.internal:host-gateway"
        restart: unless-stopped
    EOF
    ```

    Inicie el recolector:

    ```shell
    docker compose up -d
    ```

    Siga sus logs en tiempo real para confirmar que está sondeando CloudWatch y exportando datos a su recopilador de ClickStack:

    ```shell
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Confirme en la UI de ClickStack" id="confirm-in-ui">
    Abra su servicio en la [consola de ClickHouse Cloud](https://console.clickhouse.cloud) y seleccione **ClickStack** en el menú izquierdo.

    <div className="ch-image-lg">
      <Frame>
        ![Iniciar ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    En la vista **Search**, cambie la fuente a `Logs` y establezca el intervalo de tiempo en **Last 15 minutes**. Los eventos de CloudWatch deberían aparecer en un par de intervalos de sondeo.

    <div className="ch-image-lg">
      <Frame>
        ![Vista de búsqueda de ClickStack con logs de CloudWatch](/images/clickstack/cloudwatch/log-search-view-clickstack.webp)
      </Frame>
    </div>

    Cada evento incluye el grupo y el stream de origen como atributos del recurso:

    * `ResourceAttributes['aws.region']`: la región de AWS (por ejemplo, `eu-central-1`)
    * `ResourceAttributes['cloudwatch.log.group.name']`: el grupo de registros de origen
    * `ResourceAttributes['cloudwatch.log.stream']`: el stream de log de origen
    * `Body`: la línea de registro original

    Modifique la búsqueda a `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body` para incluir estos atributos:

    <div className="ch-image-lg">
      <Frame>
        ![Vista de búsqueda de ClickStack con logs de CloudWatch y atributos](/images/clickstack/cloudwatch/log-search-attributes-clickstack.webp)
      </Frame>
    </div>

    Seleccione una entrada de registro para inspeccionar sus metadata:

    <div className="ch-image-lg">
      <Frame>
        ![Atributos de CloudWatch en la vista de detalles del log](/images/clickstack/cloudwatch/error-log-column-values-clickstack.webp)
      </Frame>
    </div>

    Si no aparece nada:

    * Ejecute `aws sts get-caller-identity` en el host del recolector para confirmar que las credenciales son válidas.
    * Siga los logs del recolector con `docker compose logs -f otel-collector` y busque `AccessDeniedException` (IAM), errores de `security token` (credenciales de SSO expiradas), `ResourceNotFoundException` (error tipográfico en el nombre del grupo de registros o región incorrecta) o `connection refused` (el endpoint de su recopilador de ClickStack no es accesible desde dentro del contenedor; consulte la nota sobre `host.docker.internal` en [Configurar el receptor de CloudWatch](#configure-receiver)).
    * Verifique que `OTEL_COLLECTOR_ENDPOINT` sea accesible desde dentro del contenedor: `docker compose exec otel-collector wget -qO- ${OTEL_COLLECTOR_ENDPOINT}/v1/logs -S 2>&1 | head -5`.
    * Confirme que `OTLP_AUTH_TOKEN` coincide con el valor configurado en su recopilador de ClickStack.
  </Step>

  <Step title="Importe el panel de control de CloudWatch (opcional)" id="import-dashboard">
    Puede descargar un panel preconfigurado con el volumen de registros, el desglose por gravedad y la distribución de errores.

    <TrackedLink href={'https://clickhouse-docs-assets.s3.us-east-1.amazonaws.com/examples/cloudwatch-logs-dashboard.json'} download="cloudwatch-logs-dashboard.json" eventName="docs.cloudwatch_logs_monitoring.dashboard_download">Descargue `cloudwatch-logs-dashboard.json`</TrackedLink> y, a continuación, en la UI de ClickStack, vaya a **Dashboards** y haga clic en **Import**.

    <div className="ch-image-lg">
      <Frame>
        ![Botón para importar el panel](/images/clickstack/clickstack-import-dashboard.webp)
      </Frame>
    </div>

    Cargue el archivo JSON y haga clic en **Finish Import**.

    <div className="ch-image-lg">
      <Frame>
        ![Cuadro de diálogo para finalizar la importación](/images/clickstack/cloudwatch/finish-clickstack-import.webp)
      </Frame>
    </div>
  </Step>
