<Note>
  Esta página trata sobre **Self-managed ClickHouse Observability**. La versión totalmente gestionada de ClickHouse Observability, la experiencia predeterminada recomendada, gestiona por usted los esquemas de base de datos y la correspondencia de tipos. No necesita configurar estos componentes internos para realizar la migración; para comenzar, siga la [guía de migración desde Elasticsearch](/es/clickstack/observability/migration/elastic).
</Note>

Elasticsearch y ClickHouse admiten una amplia variedad de tipos de datos, pero su almacenamiento subyacente y sus modelos de consulta son fundamentalmente distintos. En esta sección se establece la correspondencia entre los tipos de campo de Elasticsearch más habituales y sus equivalentes en ClickHouse, cuando los hay, y se ofrece contexto para orientar las migraciones. Cuando no existe un equivalente, se indican alternativas o notas en los comentarios.

### Notas {#notes}

* **Matrices**: En Elasticsearch, todos los campos admiten matrices de forma nativa. En ClickHouse, las matrices deben definirse explícitamente (p. ej., `Array(String)`), con la ventaja de que se puede acceder a posiciones concretas y consultarlas, p. ej., `an_array[1]`.
* **Campos múltiples**: Elasticsearch permite indexar el [mismo campo de varias formas](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields#_multi_fields_with_multiple_analyzers) (p. ej., como `text` y como `keyword`). En ClickHouse, este patrón debe modelarse mediante columnas o vistas independientes.
* **Tipos Map y JSON** - En ClickHouse, el tipo [`Map`](/es/reference/data-types/map) se usa habitualmente para modelar estructuras dinámicas de clave-valor, como `resourceAttributes` y `logAttributes`. Este tipo permite una ingestión flexible sin esquema, ya que admite añadir claves arbitrarias en tiempo de ejecución, de forma similar en esencia a los objetos JSON de Elasticsearch. Sin embargo, conviene tener en cuenta algunas limitaciones importantes:

  * **Tipos de valor uniformes**: las columnas [`Map`](/es/reference/data-types/map) de ClickHouse deben tener un tipo de valor coherente (p. ej., `Map(String, String)`). No se admiten valores de tipos mixtos sin conversión.
  * **Coste de rendimiento**: acceder a cualquier clave de un [`Map`](/es/reference/data-types/map) requiere cargar el mapa completo en memoria, lo que puede penalizar el rendimiento.
  * **Sin subcolumnas**: a diferencia de JSON, las claves de un [`Map`](/es/reference/data-types/map) no se representan como subcolumnas reales, lo que limita la capacidad de ClickHouse para indexar, comprimir y consultar de forma eficiente.

  El tipo [`JSON`](/es/reference/data-types/newjson) de ClickHouse ofrece una alternativa a [`Map`](/es/reference/data-types/map) para atributos dinámicos y resuelve varias de estas limitaciones:

  * **Almacenamiento columnar real**: cada ruta JSON se almacena como una subcolumna, lo que permite una compresión, un filtrado y una ejecución vectorizada de consultas eficientes.
  * **Compatibilidad con tipos mixtos**: distintos tipos de datos (p. ej., enteros, cadenas, matrices) pueden coexistir en la misma ruta sin conversión ni unificación de tipos.
  * **Escalabilidad del sistema de archivos**: los límites internos sobre claves dinámicas (`max_dynamic_paths`) y tipos (`max_dynamic_types`) evitan una proliferación descontrolada de archivos de columna en disco, incluso con conjuntos de claves de alta cardinalidad.
  * **Almacenamiento denso**: los valores nulos y ausentes se almacenan de forma dispersa para evitar una sobrecarga innecesaria.

    El tipo [`JSON`](/es/reference/data-types/newjson) es especialmente adecuado para cargas de trabajo de observabilidad, ya que combina la flexibilidad de la ingestión sin esquema con el rendimiento y la escalabilidad de los tipos nativos de ClickHouse, lo que lo convierte en el sustituto ideal de [`Map`](/es/reference/data-types/map) en campos de atributos dinámicos.

    Para obtener más información sobre el tipo JSON, recomendamos consultar la [guía de JSON](/es/guides/clickhouse/data-formats/json/intro) y [&quot;How we built a new powerful JSON data type for ClickHouse&quot;](https://clickhouse.com/blog/a-new-powerful-json-data-type-for-clickhouse).
