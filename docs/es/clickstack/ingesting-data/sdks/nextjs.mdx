Elige la instrumentación del lado del servidor para tu despliegue de Next.js:

* **Autoalojado, tiempo de ejecución de Node.js:** usa el SDK de Node.js de ClickStack.
* **Vercel o el tiempo de ejecución Edge:** usa `@vercel/otel`.

Para la telemetría del navegador y la reproducción de sesiones, consulta la [guía del SDK para navegador](/es/clickstack/ingesting-data/sdks/browser).

## Next.js autoalojado {#self-hosted-nextjs}

Use Node.js 22.15 o una versión posterior e instale el SDK:

```shell
npm install @clickhouse/clickstack-node
```

Cree `instrumentation.ts` en la raíz de su proyecto, o en `src` si su aplicación utiliza ese directorio. Inicialice el SDK únicamente en el tiempo de ejecución de Node.js:

```typescript
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { init } = await import('@clickhouse/clickstack-node');
    init();
  }
}
```

Agregue el SDK a `serverExternalPackages` en su configuración actual de Next.js para que se cargue fuera del bundle del servidor:

```javascript
// next.config.mjs
export default {
  serverExternalPackages: ['@clickhouse/clickstack-node'],
};
```

Configure el destino a continuación y defina `OTEL_SERVICE_NAME` para identificar su aplicación. No precargue además el SDK ni inicialice otro SDK de OpenTelemetry. Para ver más opciones, consulte la [guía de Node.js](/es/clickstack/ingesting-data/sdks/nodejs).

Para consideraciones sobre la terminación del proceso y el despliegue, consulte las [recomendaciones del SDK para Next.js](https://github.com/ClickHouse/clickstack-node#nextjs).

## Vercel y tiempo de ejecución de Edge {#vercel-or-edge}

Use `@vercel/otel` siguiendo las [instrucciones de configuración de OpenTelemetry para Next.js](https://nextjs.org/docs/app/guides/open-telemetry). Utilice esta configuración en lugar de la inicialización del SDK de Node.js de ClickStack descrita anteriormente.

Configure la [exportación OTLP](https://github.com/vercel/otel/tree/main/packages/otel#registerotelconfig-configuration) con los ajustes de conexión que se indican a continuación. Reemplace los destinos de ejemplo y las sobrescrituras de endpoint específicas de cada señal, y defina las variables en la configuración de su despliegue.

Si su despliegue de Vercel ya utiliza una integración de tracing, configure un [exportador personalizado](https://nextjs.org/docs/app/guides/open-telemetry#custom-exporters) para este destino; las variables de entorno del endpoint no bastan por sí solas para sobrescribir esa integración.

## Configure su destino {#configure-destination}

Establezca un nombre de servicio para cualquiera de las dos opciones de instrumentación:

```shell
export OTEL_SERVICE_NAME='my-nextjs-app'
```

Configure el endpoint HTTP de OTLP y la clave de ingestión de su recopilador de ClickStack. Use `http://` si su recolector no tiene TLS configurado. Para configurar el recolector, consulte [Ingesta con OpenTelemetry](/es/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## Verificar la ingestión {#verify-ingestion}

Inicie su aplicación y envíe solicitudes a una página renderizada en el servidor o a una ruta de API. En ClickStack, seleccione un intervalo de tiempo reciente y busque el nombre del servicio de su aplicación en Traces.
