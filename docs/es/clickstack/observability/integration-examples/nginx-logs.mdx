Recopile los log de acceso en formato JSON de Nginx con un recolector de OpenTelemetry y envíelos a ClickHouse Observability. Utilice el [conjunto de datos de demostración](#demo-dataset) para probar la integración sin necesidad de tener Nginx instalado.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Docker para ejecutar los comandos del recolector que se indican a continuación, o una implementación existente de OpenTelemetry Collector Contrib
* Para usar sus propios logs: una instalación existente de Nginx, permiso para editar su configuración y acceso a sus archivos de registro desde el recolector

Para probar la integración sin configurar Nginx ni recopilar sus propios logs, utilice el [conjunto de datos de demostración](#demo-dataset). Incluye una configuración independiente del recolector para los datos de muestra.

<Tabs>

    <div className="ch-image-lg">

    Para los ejemplos del exportador OTLP que se muestran a continuación, defina estas variables en el terminal donde vaya a ejecutar el recolector:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Reemplace los marcadores de posición por el endpoint exacto de su servicio (incluido el puerto) y por su clave de API. Use el endpoint HTTP base, sin el sufijo `/v1/logs`; el exportador añade la ruta de cada señal.
  </Tab>

  <Tab title="Autogestionado">
    Use un endpoint HTTP de OTLP de su recolector que sea accesible (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`) y sus ajustes de autenticación. Si su recolector no requiere autenticación, omita el bloque `headers` del exportador en las configuraciones siguientes. Consulte la [guía de introducción para la versión autogestionada](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el contenedor del recolector. Si el recolector se ejecuta en su host de Docker Desktop, use `host.docker.internal` en lugar de `localhost`. En Linux, use una red de Docker compartida y el nombre del contenedor de destino, u otra dirección de host accesible.

## Integración con una instalación existente de Nginx {#existing-nginx}

Ejecute un recolector en un host que tenga acceso de lectura a los logs de acceso de Nginx. El recolector analiza los logs y los reenvía al endpoint OTLP HTTP de su servicio.

<Steps>
  <Step title="Configurar el formato de registro de Nginx" id="configure-nginx">
    Configure Nginx para que escriba los logs de acceso en formato JSON en `nginx.conf`.

    El archivo `nginx.conf` suele encontrarse en:

    * **Linux (apt/yum)**: `/etc/nginx/nginx.conf`
    * **macOS (Homebrew)**: `/usr/local/etc/nginx/nginx.conf` o `/opt/homebrew/etc/nginx/nginx.conf`
    * **Docker**: la configuración normalmente se monta como un volumen

    Agregue las siguientes directivas dentro de su bloque `http` existente. Conserve el resto de la configuración y reemplace cualquier directiva `access_log` existente que apunte al mismo archivo:

    ```nginx
    log_format json_combined escape=json
    '{'
      '"time_local":"$time_local",'
      '"remote_addr":"$remote_addr",'
      '"remote_user":"$remote_user",'
      '"request":"$request",'
      '"status":$status,'
      '"body_bytes_sent":$body_bytes_sent,'
      '"request_time":$request_time,'
      '"upstream_response_time":"$upstream_response_time",'
      '"http_referer":"$http_referer",'
      '"http_user_agent":"$http_user_agent",'
      '"http_x_forwarded_for":"$http_x_forwarded_for",'
      '"http_host":"$http_host"'
    '}';

    access_log /var/log/nginx/access.log json_combined;
    ```

    Este formato utiliza los mismos nombres de campo que el conjunto de datos de demostración, incluido `request`, que contiene el método, la URI y la versión de HTTP. `upstream_response_time` se mantiene como cadena porque [Nginx puede registrar varios tiempos de upstream](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#var_upstream_response_time). En el conjunto de datos de demostración, este campo contiene un único valor numérico.

    Valide la configuración con `nginx -t` y, a continuación, recargue Nginx siguiendo el procedimiento habitual de su despliegue. Si un bloque `server` o `location` sobrescribe `access_log`, actualice también esa directiva para que use `json_combined`.
  </Step>

  <Step title="Configure el recolector" id="custom-otel">
    Obtenga sus [datos de conexión](#demo-connection-details) y defina las variables de entorno del endpoint y de la clave de API en el terminal donde vaya a ejecutar el recolector. Guarde la siguiente configuración completa como `nginx-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx/access.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx
          - type: add
            field: resource["service.name"]
            value: nginx

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx:
          receivers: [filelog/nginx]
          processors: [memory_limiter, batch]
          exporters: [otlp_http/observability]
    ```

    Esta configuración lee las nuevas entradas JSON del log de acceso, conserva sus marcas de tiempo originales y asigna `nginx` a `service.name`. Reenvía los logs a su endpoint OTLP HTTP con los ajustes de autenticación indicados anteriormente. Los logs de errores de Nginx requieren un analizador aparte y no se incluyen.
  </Step>

  <Step title="Ejecute el recolector" id="load-custom">
    El siguiente comando supone que el directorio de logs es `/var/log/nginx` en el host de Docker. Ajuste la ruta del lado del host en el montaje de logs si sus archivos se encuentran en otra ubicación. Si ejecuta Nginx en contenedores, monte en su lugar el volumen compartido de logs de Nginx en el recolector.

    Desde el directorio que contiene `nginx-monitoring.yaml`, ejecute:

    ```bash
    docker run --rm --name nginx-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/nginx:/var/log/nginx:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    El recolector se ejecuta en primer plano y debe tener permiso para leer los archivos de registro montados. Déjelo en ejecución y genere algunas solicitudes a Nginx desde otra terminal o desde un navegador para que escriba nuevas entradas en el log de acceso.
  </Step>

  <Step title="Compruebe los logs en ClickHouse Observability" id="verifying-logs">
    1. Abra **Search** en su interfaz de usuario y seleccione **Logs**.
    2. Filtre por `ServiceName:nginx` y seleccione un intervalo de tiempo que abarque sus solicitudes.
    3. Expanda una entrada y seleccione **Column Values** para revisar campos como `request`, `request_time` y `upstream_response_time` dentro de `LogAttributes`.

    El siguiente ejemplo muestra la misma vista con el conjunto de datos de demostración, filtrando por `ServiceName:nginx-demo`:

    <div className="ch-image-lg">
      <Frame>
        ![Logs de demostración de Nginx filtrados por nombre del servicio, con una entrada expandida que muestra los atributos de log analizados](/images/clickstack/observability-nginx-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Conjunto de datos de demostración {#demo-dataset}

El conjunto de datos de ejemplo contiene 14,743 entradas de logs de acceso en formato JSON con solicitudes correctas, errores y tiempos de respuesta del upstream. Necesita Docker y un servicio de ClickHouse Observability. Configure las [variables de entorno de conexión](#demo-connection-details) antes de empezar y guarde el archivo descargado y la configuración en el mismo directorio.

<Steps>
  <Step title="Descargar el conjunto de datos de ejemplo" id="download-sample">
    ```bash
    # Descargar los logs
    curl -O https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/access.log
    ```
  </Step>

  <Step title="Crear la configuración del recolector de prueba" id="test-config">
    Guarde la siguiente configuración completa como `nginx-demo.yaml`. El recolector lee los logs de acceso descargados y los reenvía a su endpoint OTLP.

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx-demo/access.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx-demo
          - type: add
            field: resource["service.name"]
            value: nginx-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-21T16:34:27Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx-demo:
          receivers: [filelog/nginx]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      El procesador `transform/demo_timestamps`, exclusivo de esta demostración, desplaza las marcas de tiempo de la muestra para que abarquen aproximadamente las últimas 24 horas y terminen dos minutos antes de la ingestión, conservando su patrón de tráfico. El atributo original `time_local` y el cuerpo del log no se modifican. Omita este procesador con sus propios logs de Nginx para conservar sus marcas de tiempo originales.
    </Note>

    Los ejemplos de recolector independiente usan OpenTelemetry Collector Contrib `0.161.0`, la versión con la que se validaron estas configuraciones.
  </Step>

  <Step title="Ejecutar el recolector de demostración" id="run-demo">
    Desde el directorio que contiene `access.log` y `nginx-demo.yaml`, ejecute la imagen de OpenTelemetry Collector Contrib:

    ```bash
    docker run --rm --name nginx-demo-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/access.log:/var/log/nginx-demo/access.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenga esta terminal abierta mientras verifica la ingestión. El contenedor debe tener permisos de lectura sobre ambos archivos montados. Cuando aparezcan los logs, pulse **Ctrl+C** para detener el recolector de demostración. Si lo vuelve a ejecutar, el conjunto de datos se ingestará de nuevo con las marcas de tiempo desplazadas otra vez, ya que esta demostración no conserva los offsets del archivo.
  </Step>

  <Step title="Verificar los logs en ClickHouse Observability" id="verify-demo-logs">
    Una vez que el recolector esté en ejecución:

    1. Abra la interfaz de usuario.
    2. Vaya a **Search**, seleccione **Logs** y filtre por `ServiceName:nginx-demo`.
    3. Establezca el intervalo de tiempo en **Last 2 days** para incluir todo el conjunto de datos desplazado.

    Expanda una entrada de log y seleccione **Column Values** para inspeccionar los campos analizados en `LogAttributes`.

    <div className="ch-image-lg">
      <Frame>
        ![Logs de demostración de Nginx filtrados por nombre de servicio, con una entrada expandida que muestra los atributos de log analizados](/images/clickstack/observability-nginx-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Resolución de problemas {#troubleshooting}

### El recolector no se inicia {#troubleshooting-not-loading}

Revise la salida del recolector en la terminal para detectar errores de configuración. Confirme que el archivo YAML existe en la ruta montada. Si utiliza la configuración del exportador OTLP, compruebe que la variable del endpoint y las variables de autenticación necesarias estén definidas en la terminal donde ejecuta Docker.

### No aparecen logs {#no-logs}

* Revise la salida del recolector en busca de errores de autenticación o de exportación. Si utiliza el exportador OTLP, compare el endpoint y la cabecera de autorización con sus [datos de conexión](#demo-connection-details).
* Confirme que Nginx está escribiendo logs de acceso en formato JSON y que el recolector puede leerlos. Con `start_at: end`, genere nuevas solicitudes una vez iniciado el recolector.
* Compruebe la fuente **Logs** seleccionada y el filtro por nombre de servicio: `ServiceName:nginx-demo` para el conjunto de datos de demostración, o `ServiceName:nginx` para sus propios logs.
* Ajuste el intervalo de tiempo para que abarque los logs. Para la demostración, confirme que `transform/demo_timestamps` está incluido en la canalización y seleccione **Last 2 days**.

Para sus propios logs de Nginx, compruebe el archivo en el host e inspeccione los montajes del contenedor del recolector. Confirme que la ruta de destino coincide con la configuración del receptor. Reemplace `CONTAINER_NAME` por el nombre del contenedor de su recolector y ajuste la ruta del host si es necesario:

```bash
tail -f /var/log/nginx/access.log
docker inspect --format '{{json .Mounts}}' CONTAINER_NAME
```
