Recopile métricas de PostgreSQL con el receptor de PostgreSQL de OpenTelemetry y envíelas a ClickHouse Observability. Use el [conjunto de datos de demostración](#demo-dataset) para probar la integración sin necesidad de instalar PostgreSQL.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Docker y `curl`
* Para recopilar sus propias métricas: PostgreSQL 14 o una versión posterior accesible desde el recolector, y un usuario de monitorización

### Datos de conexión {#connection-details}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra ClickHouse Observability y vaya a **Team Settings → Data → Managed Telemetry**. Copie su endpoint OTLP HTTP y su clave de API. Puede usar **Copy connection details** para copiar la configuración o **Reveal key** para ver la clave enmascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Datos de conexión de Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para los ejemplos del exportador OTLP que se muestran a continuación, defina estas variables en el terminal donde vaya a ejecutar el recolector:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Reemplace los marcadores de posición por el endpoint exacto de su servicio, incluido el puerto, y por su clave de API. Use el endpoint HTTP base sin el sufijo `/v1/metrics`, ya que el exportador añade al final la ruta de la señal.
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP de su recolector, que debe ser accesible (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`), y los ajustes de autenticación correspondientes. Si su recolector no requiere autenticación, omita el bloque `headers` del exportador en las configuraciones siguientes. Consulte la [guía de introducción para la versión autogestionada](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el contenedor del recolector. Si el recolector de destino se ejecuta en este mismo equipo, use `http://host.docker.internal:4318`. Los comandos de Docker que se muestran a continuación ya incluyen la correspondencia del host.

## Integración con una instancia de PostgreSQL existente {#existing-postgres}

<Steps>
  <Step title="Configurar el usuario de monitorización" id="monitoring-permissions">
    Como administrador de PostgreSQL, cree un usuario de monitorización si aún no tiene uno y concédale acceso a las estadísticas:

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    Conceda `CONNECT` en cada base de datos que desee monitorizar. Asegúrese de que PostgreSQL acepte conexiones del recolector mediante su configuración de red y de `pg_hba.conf`.

    Defina las variables de conexión de la base de datos en el mismo terminal que sus variables de conexión OTLP:

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    Si PostgreSQL se ejecuta en el host de Docker, use `host.docker.internal:5432`. Si se trata de contenedores en una red de Docker compartida, use el nombre del host del contenedor de la base de datos y añada `--network YOUR_NETWORK` al comando del recolector.
  </Step>

  <Step title="Configurar el recolector" id="configure-collector">
    Guarde lo siguiente como `postgres-metrics.yaml`. Sustituya la lista `databases` por los nombres de sus bases de datos:

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    Esta configuración habilita TLS y verifica el certificado del servidor. Si usa una CA privada, establezca `tls.ca_file` y monte el archivo de la CA en el recolector. Para un servidor PostgreSQL local sin TLS, establezca `tls.insecure: true`; esto deshabilita TLS en la conexión a la base de datos. Consulte la [configuración del receptor de PostgreSQL](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration).
  </Step>

  <Step title="Ejecutar el recolector" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Deje el terminal abierto y espere al menos dos intervalos de recolección. Cuando termine las pruebas, detenga el recolector con **Ctrl+C**.
  </Step>

  <Step title="Verificar las métricas" id="verify-metrics">
    Abra **Chart Explorer**, seleccione su fuente **Metrics**, filtre por `ServiceName:postgresql-service` y seleccione **Last 15 minutes**. Busque `postgresql.backends`, `postgresql.commits` o `postgresql.db_size`.
  </Step>
</Steps>

## Conjunto de datos de demostración {#demo-dataset}

La muestra contiene 8,928 puntos de tipo gauge y suma, muestreados cada cinco minutos a lo largo de 24 horas. Conserva los picos de conexiones, la actividad de caché, las reversiones y los deadlocks del conjunto de datos original. La muestra incluye métricas a nivel de base de datos; la recolección en vivo también proporciona métricas de tablas e índices.

Defina las [variables de conexión](#connection-details) antes de comenzar.

<Steps>
  <Step title="Descargar las métricas de muestra" id="download-sample">
    [Descargue el paquete de muestra](/es/assets/postgres-metrics-demo.zip) (unos 64 KB) y extraiga `postgres-metrics-demo.json` en su directorio de trabajo.
  </Step>

  <Step title="Configurar el recolector de demostración" id="configure-demo-collector">
    Guarde lo siguiente como `postgres-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      La transformación, exclusiva de la demostración, actualiza las marcas de tiempo y conserva los valores de las métricas y el intervalo entre las marcas de tiempo de inicio y fin de cada punto. Omítala para métricas de PostgreSQL en vivo. El límite de batch mantiene las cargas con un tamaño adecuado para el recolector de destino.
    </Note>
  </Step>

  <Step title="Ejecutar el recolector de demostración" id="run-demo-collector">
    Desde el directorio que contiene la configuración, ejecute el recolector y deje esta terminal abierta:

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Enviar la muestra" id="load-metrics">
    En otra terminal, ejecute este comando desde el directorio de descarga:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    Una respuesta como `{}` o `{"partialSuccess":{}}` indica que el recolector local aceptó la solicitud. Revise la terminal del recolector por si hay errores de exportación y espere unos segundos a que se reenvíen los datos. Una vez verificados los datos, detenga el recolector con **Ctrl+C**. Si vuelve a enviar la muestra, pueden generarse puntos duplicados.
  </Step>

  <Step title="Verificar las métricas" id="verify-demo-metrics">
    Importe el panel de control de la [siguiente sección](#dashboards), filtre por `ServiceName:postgresql-demo` y seleccione **Últimos 2 días**. La muestra incluye métricas de tipo gauge y de tipo suma; no se necesita acceso directo a la base de datos.
  </Step>
</Steps>

## Resolución de problemas {#troubleshooting}

### El recolector no se inicia {#collector-fails-to-start}

Revise la salida del recolector en busca de errores de configuración. Compruebe que el archivo de configuración esté montado y que las variables de conexión estén definidas en la terminal donde se ejecuta Docker.

### No aparecen métricas {#no-metrics}

Revise la salida del recolector en busca de errores de conexión a la base de datos o de exportación. Confirme que el nombre del host de la base de datos sea accesible desde el contenedor, que los nombres de las bases de datos sean correctos y que PostgreSQL permita la conexión del usuario de monitorización. Revise también su fuente **Metrics**, el filtro por nombre de servicio y el intervalo de tiempo.

### Errores de autenticación o TLS {#authentication-errors}

Confirme que el usuario de monitorización tiene los permisos `pg_monitor` y `CONNECT`. Pruebe las credenciales de la base de datos con `psql` desde un host que tenga acceso a PostgreSQL:

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

Ajuste la configuración de TLS del receptor para que coincida con la de su servidor y monte el certificado de CA que sea necesario. Si se producen errores de exportación, compruebe que el endpoint OTLP y la autorización coincidan con los datos de conexión de su servicio.
