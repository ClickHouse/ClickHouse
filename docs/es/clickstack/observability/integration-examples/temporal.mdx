Temporal ofrece una abstracción para crear aplicaciones sencillas, sofisticadas y resilientes.

<Info>
  **TL;DR**

  Supervise las métricas de Temporal Cloud en ClickHouse Observability con el receptor de Prometheus de OTel. Incluye un panel preconfigurado.
</Info>

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Una cuenta de Temporal Cloud ya existente
* Docker en un host con acceso HTTPS a Temporal Cloud y a su endpoint OTLP

### Datos de conexión {#connection-details}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra ClickHouse Observability y vaya a **Team Settings → Data → Managed Telemetry**. Copie su endpoint OTLP HTTP y su clave de API. Puede usar **Copy connection details** para copiar la configuración o **Reveal key** para ver la clave enmascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Datos de conexión de Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para los ejemplos de exportador OTLP que se muestran a continuación, defina estas variables en el terminal donde vaya a ejecutar el recolector:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Sustituya los marcadores de posición por el endpoint exacto de su servicio, incluido el puerto, y por su clave de API. Use el endpoint HTTP base sin el sufijo `/v1/metrics`; el exportador añade al final la ruta de la señal.
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP de su recolector, que debe ser accesible (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`), y sus ajustes de autenticación. Si su recolector no requiere autenticación, omita el bloque `headers` del exportador en las configuraciones siguientes. Consulte la [guía de introducción para la versión autogestionada](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el contenedor del recolector. Si el recolector de destino se ejecuta en este mismo equipo, use `http://host.docker.internal:4318`. Los comandos de Docker que se muestran a continuación ya incluyen la correspondencia del host.

## Integración con una instancia existente de Temporal Cloud {#existing-temporal}

<Steps>
  <Step title="Crear la clave de Temporal Cloud" id="create-temporal-cloud-key">
    Cree una cuenta de servicio de Temporal Cloud con el rol **Metrics Read-Only** y genere una clave de API siguiendo la [guía de autenticación](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication). La cuenta de servicio y la clave deben crearlas un Account Owner o un Global Admin.

    <Warning>
      **Archivo de clave**

      Guarde la clave de API de Temporal en un archivo `temporal.key` en el mismo directorio que el archivo de configuración que se crea más adelante. Guarde solo la clave, sin el prefijo `Bearer` ni espacios al principio o al final. Esta clave es distinta de su clave de API de ClickHouse Observability. Asegúrese de que el recolector pueda leer el archivo montado.
    </Warning>
  </Step>

  <Step title="Configurar el recolector de OTel" id="custom-otel">
    Ejecute un Colector de OpenTelemetry independiente con el Receptor de Prometheus para recopilar las métricas de Temporal Cloud y reenviarlas a su servicio.

    Cree un archivo llamado `temporal-metrics.yaml` con la siguiente configuración:

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    Esta configuración:

    * Se conecta a Temporal Cloud en `metrics.temporal.io`
    * Recopila métricas cada 60 segundos
    * Recopila las [métricas clave de rendimiento](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)
    * **Establece el atributo de recurso obligatorio `service.name`** conforme a las [convenciones semánticas de OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/resource/#service)
    * Envía las métricas a su endpoint OTLP mediante una canalización dedicada

    Si tiene varias cuentas de Temporal Cloud, personalice `service.name` para diferenciarlas (por ejemplo, `temporal-prod` y `temporal-dev`).
  </Step>

  <Step title="Ejecutar el recolector" id="run-collector">
    Desde el directorio que contiene `temporal-metrics.yaml` y `temporal.key`, defina las [variables de conexión](#connection-details) y ejecute:

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenga la terminal abierta y compruebe si se producen errores de recopilación o de exportación. Las métricas de Temporal Cloud pueden tardar unos minutos en aparecer. Cuando termine las pruebas, detenga el recolector con **Ctrl+C**.
  </Step>

  <Step title="Verificar las métricas en ClickHouse Observability" id="verifying-metrics">
    Una vez configurado todo, inicie sesión en ClickHouse Observability y compruebe que las métricas están llegando:

    1. Abra **Explorador de Gráficos** y seleccione su fuente **Metrics**
    2. Filtre por `ServiceName:temporal`, seleccione **Last 15 minutes** y busque métricas que empiecen por `temporal` (p. ej., `temporal_cloud_v1_workflow_success_count`, `temporal_cloud_v1_poll_timeout_count`)
    3. Deberían aparecer puntos de datos de métricas con la frecuencia del intervalo de recopilación configurado

    <div className="ch-image-md">
      <Frame>
        ![Métricas de Temporal](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## Resolución de problemas {#troubleshooting}

### El recolector no se inicia {#collector-fails-to-start}

Revise la salida del terminal para detectar errores de configuración. Confirme que ambos archivos montados existen y que el recolector puede leer `temporal.key`. Asegúrese de que las variables de conexión de OTLP estén definidas en el terminal donde se ejecuta Docker.

### No aparecen métricas {#no-metrics}

Revise los logs del recolector:

```bash
docker logs temporal-metrics-collector
```

Busque errores de recopilación de métricas, de autenticación o de exportación. Confirme que el host puede acceder a `https://metrics.temporal.io/v1/metrics` y a su endpoint OTLP. En el **Explorador de Gráficos**, revise la fuente **Metrics**, el filtro `ServiceName:temporal` y el intervalo de tiempo. Las métricas de Temporal pueden tardar unos minutos en estar disponibles y dependen de la actividad de su cuenta.

### Errores de autenticación {#auth-errors}

Si se producen errores en la recopilación de métricas de Temporal, confirme que `temporal.key` contiene una clave de API válida de una cuenta de servicio con el rol **Metrics Read-Only**. Si se producen errores de exportación OTLP, compruebe el endpoint de ClickHouse Observability y el valor de autorización. Se trata de credenciales distintas.

* Monitorice varias cuentas de Temporal Cloud duplicando la configuración del receptor con distintos puntos de conexión y nombres de servicio

## Paso a producción {#going-to-production}

Esta guía ejecuta un Colector de OpenTelemetry independiente que reenvía las métricas al endpoint OTLP de su servicio. Consulte [Envío de datos de OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry) para obtener orientación sobre el despliegue.
