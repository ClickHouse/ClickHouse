Recopile los archivos syslog del host con un recolector de OpenTelemetry y envíelos a ClickHouse Observability. Use el [conjunto de datos de demostración](#demo-dataset) para probar la integración sin necesidad de recopilar logs de su propio host.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Docker para ejecutar los ejemplos del recolector, o una implementación existente de OpenTelemetry Collector Contrib
* Para sus propios logs, archivos de syslog y permiso de lectura sobre ellos para el recolector
* Para la demo, `curl` para descargar la muestra

### Datos de conexión {#connection-details}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra ClickHouse Observability y vaya a **Configuración del equipo → Data → Managed Telemetry**. Copie su endpoint OTLP HTTP y su clave de API. Puede usar **Copy connection details** para copiar la configuración o **Reveal key** para ver la clave enmascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Datos de conexión de Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para los ejemplos del exportador OTLP que se muestran a continuación, defina estas variables en el terminal donde vaya a ejecutar el recolector:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Reemplace los marcadores de posición por el endpoint exacto de su servicio, incluido el puerto, y por su clave de API. Use el endpoint HTTP base, sin el sufijo `/v1/logs`; el exportador añade al final la ruta de la señal.
  </Tab>

  <Tab title="Autogestionado" id="self-managed">
    Use un endpoint OTLP HTTP de su recolector que sea accesible (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`) y sus ajustes de autenticación. Si su recolector no requiere autenticación, omita el bloque `headers` del exportador en las configuraciones siguientes. Consulte la [guía de introducción para despliegues autogestionados](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el contenedor del recolector. Si el recolector de destino se ejecuta en este mismo equipo, use `http://host.docker.internal:4318`. Los comandos de Docker que aparecen a continuación ya incluyen la correspondencia del host.

## Integración con anfitriones existentes {#existing-hosts}

<Steps>
  <Step title="Localice su archivo de syslog" id="locate-syslog">
    Las ubicaciones habituales son `/var/log/syslog` en Ubuntu/Debian, `/var/log/messages` en sistemas basados en RHEL y `/var/log/system.log` para los logs de texto de macOS. Inspeccione el archivo que exista en su host:

    ```bash
    tail -20 /var/log/syslog
    ```

    Ajuste la ruta según sea necesario. Si su host Linux solo escribe en el registro de systemd (journal), utilice la [guía de Systemd/Journald](/es/clickstack/observability/integration-examples/systemd). Esta guía lee archivos de texto; no recopila el almacén de registros unificado de macOS.
  </Step>

  <Step title="Configure el recolector" id="configure-collector">
    Guarde la configuración que corresponda como `host-logs.yaml`. Elíjala según el formato de las marcas de tiempo de su archivo. Si es necesario, cambie `include` a `/var/log/host/messages` o `/var/log/host/system.log`. Agregue otros archivos solo si usan el mismo formato.

    <Tabs>
      <Tab title="Marcas de tiempo ISO">
        Para líneas que comienzan con una marca de tiempo como `2026-10-15T12:34:56.123456+00:00`:

        ```yaml
        receivers:
          filelog/host:
            include: [/var/log/host/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: host-logs
              - type: add
                field: resource["service.name"]
                value: host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/host:
              receivers: [filelog/host]
              processors: [memory_limiter, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="Syslog tradicional">
        Para líneas que comienzan con una marca de tiempo como `Oct 15 12:34:56`:

        ```yaml
        receivers:
          filelog/host:
            include: [/var/log/host/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: host-logs
              - type: add
                field: resource["service.name"]
                value: host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/host:
              receivers: [filelog/host]
              processors: [memory_limiter, batch]
              exporters: [otlp_http/observability]
        ```

        Las marcas de tiempo tradicionales no incluyen el año ni la zona horaria. El analizador infiere el año; si su host no registra en UTC, establezca `location` en su zona horaria IANA, como `America/Chicago`.
      </Tab>
    </Tabs>

    El receptor extrae `hostname`, `unit`, `pid` (si existe) y `message`, y conserva la línea original en `Body`. Además, establece `service.name` en `host-service` y copia el nombre del host en `host.name`. Estos formatos de texto no incluyen un campo de gravedad, por lo que esta configuración no infiere la gravedad a partir del texto del mensaje.
  </Step>

  <Step title="Ejecute el recolector" id="run-collector">
    Configure las [variables de conexión](#connection-details). Desde el directorio que contiene `host-logs.yaml`, ejecute:

    ```bash
    docker run --rm --name host-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/host-logs.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log:/var/log/host:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    En macOS, use `-v /private/var/log:/var/log/host:ro` y conceda a Docker Desktop acceso a ese directorio. Asegúrese de que el recolector pueda leer el archivo de registro seleccionado.

    Mantenga abierta esta terminal. Con `start_at: end`, el receptor recopila las líneas nuevas escritas después del inicio. Genere actividad normal que escriba en el archivo de registro seleccionado.
  </Step>

  <Step title="Verifique los logs" id="verify-logs">
    Abra **Búsqueda**, seleccione su fuente **Logs**, filtre por `ServiceName:host-service` y seleccione **Last 15 minutes**. Despliegue un log para inspeccionar el nombre del host, la unidad, el PID y el mensaje analizados.
  </Step>
</Steps>

## Conjunto de datos de demostración {#demo-dataset}

La muestra contiene 11,658 líneas de syslog que abarcan 24 horas, entre ellas mensajes de arranque, actividad SSH, bloqueos del cortafuegos, tareas programadas y reinicios de servicios.

<Steps>
  <Step title="Descargar la muestra" id="download-sample">
    ```bash
    mkdir -p host-demo
    cd host-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="Configurar el recolector de demostración" id="configure-demo-collector">
    Guarde lo siguiente como `host-logs-demo.yaml` en el directorio de descarga:

    ```yaml
    receivers:
      filelog/host:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: host-demo
          - type: add
            field: resource["service.name"]
            value: host-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/host:
          receivers: [filelog/host]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      La transformación de marcas de tiempo, exclusiva de la demostración, desplaza la muestra aproximadamente a las últimas 24 horas, de modo que termine dos minutos antes de la ingestión. Para sus propios logs, use la [configuración para anfitriones existentes](#existing-hosts), que conserva las marcas de tiempo originales.
    </Note>
  </Step>

  <Step title="Ejecutar el recolector de demostración" id="run-demo-collector">
    Defina las [variables de conexión](#connection-details) y, a continuación, ejecute desde el directorio de descarga:

    ```bash
    docker run --rm --name host-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenga la terminal abierta mientras el recolector exporta la muestra y revise la salida por si aparecen errores. Si vuelve a iniciar un contenedor nuevo, los logs de muestra podrían duplicarse.
  </Step>

  <Step title="Verificar los logs de demostración" id="verify-demo-logs">
    Abra **Search**, seleccione su fuente **Logs**, filtre por `ServiceName:host-demo` y seleccione **últimos 2 días**. Expanda un log para inspeccionar sus atributos analizados. Una vez verificados los datos, detenga el recolector con **Ctrl+C**.

    <div className="ch-image-lg">
      <Frame>
        ![Logs de demostración del host en Search de ClickHouse Observability](/images/clickstack/observability-host-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Resolución de problemas {#troubleshooting}

### El recolector no se inicia {#collector-fails-to-start}

Revise la terminal del recolector para detectar errores de configuración. Compruebe que el archivo YAML se encuentra en la ruta montada y que las variables de conexión están definidas en la terminal desde la que ejecuta Docker.

### No aparecen logs {#no-logs}

* Confirme que el archivo existe en el host y que su ruta montada coincide con `include`.
* Compruebe los permisos del archivo y, en macOS, el uso compartido de archivos de Docker Desktop.
* Para logs en tiempo real, genere nuevas entradas después de que se inicie el recolector; `start_at: end` omite el contenido existente.
* Revise la salida del recolector en busca de errores de autenticación o de exportación.
* Compruebe la fuente **Logs**, el filtro por nombre de servicio y el intervalo de tiempo. Para la demo, seleccione **Últimos 2 días**.

### Los logs no se analizan correctamente {#logs-not-parsing}

Compare una línea de su archivo con el formato de marca de tiempo seleccionado. Utilice la configuración correspondiente y, si es necesario, ajuste la zona horaria del syslog tradicional. Evite recopilar formatos de log de aplicaciones no relacionadas con un patrón glob de archivos demasiado amplio.
