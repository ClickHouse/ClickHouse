Recopile métricas de los brókers de Kafka con el JMX Metric Gatherer de OpenTelemetry y envíelas a ClickHouse Observability. Use el [conjunto de datos de demostración](#demo-dataset) para probar la integración sin necesidad de desplegar Kafka.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Docker con Docker Compose y `curl`
* Para recopilar sus propias métricas, un bróker de Kafka con JMX remoto habilitado y accesible desde el recopilador

### Datos de conexión {#connection-details}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra ClickHouse Observability y vaya a **Team Settings → Data → Managed Telemetry**. Copie su endpoint OTLP HTTP y su clave de API. Puede usar **Copy connection details** para copiar la configuración o **Reveal key** para ver la clave enmascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Datos de conexión de Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Defina estas variables en el terminal donde vaya a ejecutar el recopilador JMX o el recolector de demostración:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Reemplace los marcadores de posición por el endpoint exacto de su servicio, incluido el puerto, y por su clave de API. Use el endpoint HTTP base sin el sufijo `/v1/metrics`; el exportador añade al final la ruta de la señal.
  </Tab>

  <Tab title="Autogestionado">
    Use un endpoint OTLP HTTP de su recolector que sea accesible (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`) y los ajustes de autenticación correspondientes. Si su recolector no requiere autenticación, omita el argumento `-Dotel.exporter.otlp.headers` del recopilador JMX y el bloque `headers` del recolector de demostración. Consulte la [guía de introducción para despliegues autogestionados](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el contenedor del recopilador o del recolector. Si el recolector de destino se ejecuta en este mismo equipo, use `http://host.docker.internal:4318`. Los comandos de Docker que se muestran a continuación incluyen la correspondencia del host.

## Integración con una implementación existente de Kafka {#existing-kafka}

<Steps>
  <Step title="Compruebe el endpoint JMX del bróker" id="verify-jmx">
    Use el endpoint JMX remoto configurado para su bróker. Para un bróker que expone JMX en el puerto `9999`:

    ```bash
    export KAFKA_JMX_URL='service:jmx:rmi:///jndi/rmi://YOUR_KAFKA_HOST:9999/jmxrmi'
    export KAFKA_BROKER_ID='broker-0'
    ```

    Sustituya el nombre del host y el ID del bróker por sus propios valores. El nombre del host RMI que anuncia el bróker también debe ser accesible desde el recopilador. Si el bróker utiliza puertos distintos para el registro y para RMI, permita el tráfico por ambos en la red. El recopilador lee JMX; no necesita el puerto de cliente de Kafka `9092`.

    Para contenedores en una red de Docker compartida, use el nombre del host del contenedor del bróker. Para un bróker que se ejecuta en el host de Docker, use `host.docker.internal` y configure el bróker para que anuncie un nombre del host accesible desde el contenedor. Restrinja el acceso JMX a su red de monitorización y mantenga la configuración de autenticación y TLS de su bróker.
  </Step>

  <Step title="Descargue el JMX Metric Gatherer" id="download-jmx">
    ```bash
    curl -fL -o opentelemetry-jmx-metrics.jar \
      https://github.com/open-telemetry/opentelemetry-java-contrib/releases/download/v1.32.0/opentelemetry-jmx-metrics.jar
    ```
  </Step>

  <Step title="Configure el recopilador" id="configure-gatherer">
    Guarde lo siguiente como `compose.yaml` junto al JAR descargado:

    ```yaml
    services:
      kafka-jmx-gatherer:
        image: eclipse-temurin:11-jre
        extra_hosts:
          - "host.docker.internal:host-gateway"
        environment:
          - KAFKA_JMX_URL
          - KAFKA_BROKER_ID
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        volumes:
          - ./opentelemetry-jmx-metrics.jar:/app/opentelemetry-jmx-metrics.jar:ro
        command:
          - sh
          - -c
          - >-
            exec java
            -Dotel.jmx.service.url="$${KAFKA_JMX_URL}"
            -Dotel.jmx.target.system=kafka
            -Dotel.jmx.interval.milliseconds=10000
            -Dotel.metrics.exporter=otlp
            -Dotel.exporter.otlp.protocol=http/protobuf
            -Dotel.exporter.otlp.endpoint="$${OTEL_EXPORTER_OTLP_ENDPOINT}"
            -Dotel.exporter.otlp.headers="authorization=$${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
            -Dotel.resource.attributes="service.name=kafka-service,kafka.broker.id=$${KAFKA_BROKER_ID}"
            -jar /app/opentelemetry-jmx-metrics.jar
    ```

    Si el bróker está en una red de Docker existente, conecte `kafka-jmx-gatherer` a esa red en su configuración de Compose. Para JMX autenticado, añada las propiedades `otel.jmx.username` y `otel.jmx.password`; para TLS, configure el almacén de confianza correspondiente. Consulte la [configuración de autenticación y TLS del recopilador](https://github.com/open-telemetry/opentelemetry-java-contrib/tree/v1.32.0/jmx-metrics#configuration).
  </Step>

  <Step title="Inicie la recopilación" id="run-gatherer">
    Defina las [variables de conexión](#connection-details) y las variables del bróker en este terminal y, a continuación, ejecute el siguiente comando desde el directorio que contiene `compose.yaml`:

    ```bash
    docker compose up kafka-jmx-gatherer
    ```

    Mantenga el terminal abierto y compruebe si se producen errores de conexión JMX o errores de exportación OTLP. El recopilador recoge datos cada 10 segundos. Espere al menos dos intervalos de recopilación antes de comprobar su servicio. Cuando termine las pruebas, deténgalo con **Ctrl+C**.

    Si tiene varios brókers, ejecute un recopilador por bróker, cada uno con su propia URL de JMX y su propio `kafka.broker.id`.
  </Step>

  <Step title="Verifique las métricas" id="verify-metrics">
    Abra **Explorador de Gráficos**, seleccione su fuente **Metrics**, filtre por `ServiceName:kafka-service` y seleccione **Last 15 minutes**. Busque `kafka.partition.count`, `kafka.partition.under_replicated` o `kafka.message.count`. Las métricas relacionadas con el tráfico requieren actividad en el bróker para generar valores significativos.
  </Step>
</Steps>

## Conjunto de datos de demostración {#demo-dataset}

La muestra contiene 6,282 puntos de tipo gauge y suma, muestreados cada cinco minutos durante unas 29 horas. Conserva los patrones del conjunto de datos original en cuanto a picos de tráfico, latencia de solicitudes, retraso del consumidor y estado de las particiones. No se necesita ningún despliegue de Kafka ni acceso directo a la base de datos.

Configure las [variables de conexión](#connection-details) antes de comenzar.

<Steps>
  <Step title="Descargar las métricas de muestra" id="download-sample">
    [Descargue el paquete de muestra](/es/assets/kafka-metrics-demo.zip) (unos 53 KB) y extraiga `kafka-metrics-demo.json` en su directorio de trabajo.
  </Step>

  <Step title="Configurar el recolector de demostración" id="configure-demo-collector">
    Guarde lo siguiente como `kafka-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: kafka-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-06T22:14:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      La transformación, exclusiva de la demostración, actualiza las marcas de tiempo y conserva los valores de las métricas, así como el intervalo entre las marcas de tiempo de inicio y fin de cada punto. Omítala cuando trabaje con métricas reales de Kafka. El límite de batch mantiene los envíos lo bastante pequeños para el recolector de destino.
    </Note>
  </Step>

  <Step title="Ejecutar el recolector de demostración" id="run-demo-collector">
    Desde el directorio que contiene la configuración, ejecute el recolector y deje esta terminal abierta:

    ```bash
    docker run --rm --name kafka-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Enviar la muestra" id="load-metrics">
    En otra terminal, ejecute este comando desde el directorio de descarga:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @kafka-metrics-demo.json
    ```

    Una respuesta como `{}` o `{"partialSuccess":{}}` indica que el recolector local aceptó la solicitud. Revise la terminal del recolector en busca de errores de exportación y espere unos segundos a que se reenvíen los datos. Una vez verificados los datos, detenga el recolector con **Ctrl+C**. Si vuelve a enviar la muestra, pueden generarse puntos duplicados.
  </Step>

  <Step title="Verificar las métricas" id="verify-demo-metrics">
    Importe el panel de control de la [siguiente sección](#dashboards), filtre por `ServiceName:kafka-demo` y seleccione **Últimos 2 días**. La muestra incluye métricas de tipo gauge y suma; no se necesita acceso directo a la base de datos.
  </Step>
</Steps>

## Resolución de problemas {#troubleshooting}

### Falla la conexión JMX {#jmx-connection-fails}

Revise la salida del recopilador con `docker compose logs kafka-jmx-gatherer`. Compruebe que JMX esté habilitado, que tanto el registro como el endpoint RMI anunciado sean accesibles y que las credenciales JMX y el almacén de confianza configurados coincidan con los del bróker. Si se usan nombres de host de contenedores, los contenedores deben estar en la misma red prevista.

### No aparecen métricas {#no-metrics}

* Revise la salida del recopilador o del recolector de la demo en busca de errores de conexión, de autenticación o de exportación.
* Verifique que el endpoint OTLP HTTP y la autenticación coincidan con los datos de conexión de su servicio.
* Compruebe la fuente **Metrics**, el filtro por nombre de servicio y el intervalo de tiempo. Para la demo, use **Últimos 2 días**.
* Si usa un recolector existente, confirme que su canalización de métricas incluye el receiver OTLP y un exportador de métricas.
* Compruebe los nombres de las métricas activas en el **Explorador de Gráficos** antes de usar el panel de control de la demo.

### Conflictos de puerto JMX en los comandos de cliente de Kafka {#port-conflicts}

Si ejecuta comandos de cliente de Kafka dentro del contenedor del bróker, anule para ese comando los ajustes JMX heredados del bróker para que el cliente no intente enlazarse al mismo puerto:

```bash
env -u JMX_PORT -u KAFKA_JMX_OPTS kafka-topics --list --bootstrap-server YOUR_KAFKA_HOST:9092
```
