Recopile los logs CSV de PostgreSQL con un recolector de OpenTelemetry y envíelos a ClickHouse Observability. Utilice el [conjunto de datos de demostración](#demo-dataset) para probar la integración sin necesidad de instalar PostgreSQL.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Docker para ejecutar los ejemplos del recolector
* Para sus propios logs, PostgreSQL 14 o posterior y acceso a sus archivos de configuración y de registro
* Para la demo, `curl` para descargar la muestra

### Datos de conexión {#connection-details}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra ClickHouse Observability y vaya a **Team Settings → Data → Managed Telemetry**. Copie su endpoint OTLP HTTP y su clave de API. Puede usar **Copiar datos de conexión** para copiar la configuración o **Reveal key** para mostrar la clave enmascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Datos de conexión de Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para los ejemplos de exportador OTLP que se muestran a continuación, defina estas variables en el terminal donde vaya a ejecutar el recolector:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Reemplace los marcadores de posición por el endpoint exacto de su servicio, incluido el puerto, y por su clave de API. Use el endpoint HTTP base sin el sufijo `/v1/logs`; el exportador añade al final la ruta de la señal.
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP accesible de su recolector (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`) y sus ajustes de autenticación. Si su recolector no requiere autenticación, omita el bloque `headers` del exportador en las configuraciones siguientes. Consulte la [guía de primeros pasos para la versión autogestionada](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el contenedor del recolector. Si el recolector de destino se ejecuta en este mismo equipo, use `http://host.docker.internal:4318`. Los comandos de Docker que se muestran a continuación ya incluyen la correspondencia del host.

## Integración con una instancia de PostgreSQL existente {#existing-postgres}

<Steps>
  <Step title="Configurar el registro de PostgreSQL" id="configure-postgres">
    Localice su archivo de configuración ejecutando la siguiente consulta SQL como administrador de la base de datos:

    ```sql
    SHOW config_file;
    ```

    Añada o actualice estos ajustes en `postgresql.conf`:

    ```conf
    logging_collector = on
    log_destination = 'csvlog'
    log_directory = '/var/log/postgresql'
    log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
    log_file_mode = 0640
    log_timezone = 'UTC'
    log_connections = on
    log_disconnections = on
    # Optional: log statements taking more than one second
    # log_min_duration_statement = 1000
    ```

    Cree el directorio de logs con el propietario y los permisos necesarios para que PostgreSQL pueda escribir en él y el recolector pueda leerlo. Si PostgreSQL se ejecuta en contenedores, monte ese directorio para que el recolector pueda acceder a los mismos archivos. La salida CSV usa la extensión `.csv` aunque `log_filename` termine en `.log`.

    Reinicie PostgreSQL según su proceso de despliegue habitual, por ejemplo:

    ```bash
    sudo systemctl restart postgresql
    # Or, for Docker:
    docker restart <postgres-container>
    ```

    Compruebe el archivo CSV activo:

    ```sql
    SELECT pg_current_logfile('csvlog');
    ```

    El analizador que se muestra a continuación está diseñado para el [formato CSV de PostgreSQL de 26 columnas](https://www.postgresql.org/docs/14/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-CSVLOG). Las versiones anteriores de PostgreSQL y otros formatos de registro requieren un analizador diferente.
  </Step>

  <Step title="Configure el recolector" id="configure-collector">
    Guarde este contenido como `postgres-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql-*.csv
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql"

          - type: add
            field: resource["service.name"]
            value: "postgresql-service"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    El receptor analiza las entradas CSV multilínea, conserva sus marcas de tiempo y cuerpos, y añade `service.name` con el valor `postgresql-service`. Campos como `database_name`, `error_severity`, `message` y `query` siguen estando disponibles como atributos del log.
  </Step>

  <Step title="Ejecute el recolector" id="run-collector">
    Desde el directorio que contiene la configuración, ejecute el siguiente comando. Ajuste el directorio de registros del host si es necesario. Si los archivos de registro tienen permisos de lectura para el grupo, añada `--group-add LOG_GROUP_ID` con el ID numérico del grupo que muestra `ls -ln /var/log/postgresql`.

    ```bash
    docker run --rm --name postgres-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/postgresql:/var/log/postgresql:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Deje la terminal abierta. Como el receptor usa `start_at: end`, después de iniciar el recolector debe crear una nueva conexión a la base de datos o ejecutar una consulta que genere un error:

    ```sql
    SELECT 1 / 0;
    ```
  </Step>

  <Step title="Verificar los logs" id="verify-logs">
    Abra **Búsqueda**, seleccione **Logs**, filtre por `ServiceName:postgresql-service` y seleccione **Últimos 15 minutos**. Expanda un registro para examinar sus atributos de PostgreSQL y su gravedad.
  </Step>
</Steps>

        start_at: beginning
        force_flush_period: 1s
        multiline:

        operators:

            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'

              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-10T23:59:47Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]

    El procesador de marcas de tiempo, exclusivo de la demo, desplaza la muestra a las últimas 24 horas, de modo que finalice dos minutos antes de la ingestión. Los atributos de marca de tiempo originales y los cuerpos de los log no se modifican. Omita este procesador para sus propios log de PostgreSQL.

  </Step>

## Resolución de problemas {#troubleshooting}

### El recolector no se inicia {#collector-fails-to-start}

Revise la salida del recolector en busca de errores de configuración. Compruebe el montaje de la configuración y las variables de conexión en la terminal donde se ejecuta Docker.

### No aparecen logs {#no-logs}

Compruebe si hay errores de autenticación o de exportación. Confirme la ruta del archivo CSV con `pg_current_logfile`, asegúrese de que los archivos coincidan con el patrón `include` del receptor y verifique que el recolector tenga permisos para leerlos. Con `start_at: end`, solo se recopilan las entradas nuevas. Para la demo, incluya el procesador de marca de tiempo y seleccione **Últimos 2 días**.

### Permiso denegado {#permission-denied}

PostgreSQL normalmente crea archivos de registro a los que solo puede acceder el propietario. La configuración anterior usa `log_file_mode = 0640` para permitir lecturas al grupo; añada el grupo del archivo al contenedor del recolector con `--group-add`. Los archivos existentes conservan sus permisos anteriores. Asegúrese de que el directorio también permita el acceso al grupo.

### Errores de análisis sintáctico de CSV {#csv-parsing-errors}

El analizador espera las 26 columnas que genera PostgreSQL 14 o posterior. Compruebe que estén configurados `log_destination = 'csvlog'` y `log_timezone = 'UTC'`. Ajuste el encabezado para versiones anteriores o formatos personalizados; los logs de stderr y JSON no son compatibles con este analizador de CSV.
