Recopile los logs del registro de systemd con el receptor de journald de OpenTelemetry y envíelos a ClickHouse Observability. Utilice el [conjunto de datos de demostración](#demo-dataset) para probar la integración sin un host Linux.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability
* Para sus propios logs, un host Linux que ejecute systemd, con `journalctl` y permiso para leer su registro
* `curl` y Docker para la demo

### Datos de conexión {#connection-details}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra ClickHouse Observability y vaya a **Configuración del equipo → Datos → Managed Telemetry**. Copie su endpoint OTLP HTTP y su clave de API. Puede usar **Copiar datos de conexión** para copiar la configuración o **Mostrar clave** para ver la clave enmascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Datos de conexión de Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para los ejemplos del exportador OTLP que aparecen a continuación, defina estas variables en el terminal donde vaya a ejecutar el recolector:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Reemplace los marcadores de posición por el endpoint exacto de su servicio, incluido el puerto, y por su clave de API. Use el endpoint HTTP base sin el sufijo `/v1/logs`; el exportador añade al final la ruta de cada señal.
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP de su recolector, que debe ser accesible (por ejemplo, `http://YOUR_COLLECTOR_HOST:4318`), y sus ajustes de autenticación. Si su recolector no requiere autenticación, omita el bloque `headers` del exportador en las configuraciones siguientes. Consulte la [guía de introducción para despliegues autogestionados](/es/clickstack/self-configured/getting-started/managed) para obtener instrucciones de configuración.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

El endpoint debe ser accesible desde el host monitorizado o desde el recolector de demostración. Si el recolector de destino se ejecuta en el host de Docker, use `http://host.docker.internal:4318`.

## Integración con sistemas existentes {#existing-systems}

<Steps>
  <Step title="Verifique el registro" id="verify-systemd">
    En el host Linux que desea monitorizar:

    ```bash
    systemctl --version
    sudo journalctl -n 20
    sudo journalctl --disk-usage
    ```

    El receptor utiliza el `journalctl` del host para leer los registros disponibles. Se admiten tanto el almacenamiento persistente como el volátil del registro, por lo que no es necesario cambiar los ajustes de almacenamiento.
  </Step>

  <Step title="Descargue el recolector" id="download-collector">
    Ejecute estos comandos en el host Linux monitorizado:

    ```bash
    case "$(uname -m)" in
      x86_64) arch=amd64 ;;
      aarch64|arm64) arch=arm64 ;;
      *) echo "Unsupported architecture"; exit 1 ;;
    esac
    curl -fL -o otelcol-contrib.tar.gz \
      "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_${arch}.tar.gz"
    tar -xzf otelcol-contrib.tar.gz otelcol-contrib
    ```

    El recolector se ejecuta directamente en el host para poder usar el `journalctl` instalado. La imagen de Docker estándar de Contrib no incluye ese binario.
  </Step>

  <Step title="Configure el recolector" id="configure-collector">
    Guarde este contenido como `systemd-monitoring.yaml`:

    ```yaml
    receivers:
      journald:
        start_at: end
        priority: info
        convert_message_bytes: true
    processors:
      transform/journald:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - merge_maps(log.attributes, log.body, "upsert")
              - set(resource.attributes["host.name"], log.attributes["_HOSTNAME"])
              - set(resource.attributes["service.name"], "systemd-logs")
              - set(log.attributes["unit"], log.attributes["SYSLOG_IDENTIFIER"])
              - set(log.attributes["unit"], log.attributes["_SYSTEMD_UNIT"]) where log.attributes["_SYSTEMD_UNIT"] != nil
              - set(log.attributes["priority"], log.attributes["PRIORITY"])
              - set(log.body, log.attributes["MESSAGE"])
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "warn") where Int(log.attributes["PRIORITY"]) == 4
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where Int(log.attributes["PRIORITY"]) == 3
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where Int(log.attributes["PRIORITY"]) < 3
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs:
          receivers: [journald]
          processors: [transform/journald, batch]
          exporters: [otlp_http/observability]
    ```

    Los campos del registro (journal) se conservan como atributos del log, el mensaje pasa a ser el cuerpo del registro y el nombre del host se convierte en un atributo de recurso. El receptor recopila todas las unidades con prioridad `info` o superior. Para limitar la recopilación, añada una lista `units` en `journald` con los nombres reales de las unidades de su host, como `ssh.service` o `nginx.service`.
  </Step>

  <Step title="Ejecute el recolector" id="run-collector">
    Configure las [variables de conexión](#connection-details) y, a continuación, ejecute el comando desde el directorio de descarga. Este comando utiliza permisos de administrador para leer el registro del sistema y conserva únicamente las dos variables de conexión:

    ```bash
    sudo --preserve-env=OTEL_EXPORTER_OTLP_ENDPOINT,OTEL_EXPORTER_OTLP_AUTHORIZATION \
      ./otelcol-contrib --config=systemd-monitoring.yaml
    ```

    Mantenga la terminal abierta. En otra terminal, genere una entrada en el registro:

    ```bash
    echo 'ClickHouse Observability journal ingestion test' | systemd-cat -t observability-test -p info
    ```

    Detenga el recolector con **Ctrl+C** cuando termine las pruebas. Para una recolección continua, ejecútelo como servicio de systemd con acceso al registro y configure el [almacenamiento del cursor](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/journaldreceiver#cursor-tracking) para que se reanude tras cada reinicio.
  </Step>

  <Step title="Verifique los logs" id="verify-logs">
    Abra **Búsqueda**, seleccione **Logs**, filtre por `ServiceName:systemd-logs` y seleccione **Last 15 minutes**. Busque el mensaje de prueba y atributos como `unit` y `priority`.
  </Step>
</Steps>

## Conjunto de datos de demostración {#demo-dataset}

La muestra contiene 1,334 entradas de log de texto que abarcan aproximadamente 48 horas, entre ellas actividad SSH, tareas programadas y eventos de servicios. Utiliza el receptor `filelog`, por lo que no es necesario instalar systemd ni `journalctl`. El recolector actualiza las marcas de tiempo y conserva los cuerpos originales y el espaciado entre eventos.

<Steps>
  <Step title="Descargar la muestra" id="download-sample">
    ```bash
    curl -fL -o systemd-demo.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/systemd/systemd-demo.log
    ```
  </Step>

  <Step title="Configurar el recolector de demostración" id="configure-demo">
    Guarde lo siguiente como `systemd-demo.yaml`:

    ```yaml
    receivers:
      filelog/systemd:
        include:
          - /var/log/demo/systemd-demo.log
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout: '%Y-%m-%dT%H:%M:%S%z'
          - type: add
            field: attributes.source
            value: systemd-demo
          - type: add
            field: resource["service.name"]
            value: systemd-demo
    processors:
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(resource.attributes["host.name"], log.attributes["hostname"])
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-16T23:45:00Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs:
          receivers: [filelog/systemd]
          processors: [transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    La muestra de texto no incluye el campo de prioridad del registro de systemd, por lo que la demostración no asigna la severidad a partir del texto del mensaje.
  </Step>

  <Step title="Ejecutar el recolector de demostración" id="run-demo">
    Defina las [variables de conexión](#connection-details) y, a continuación, ejecute el siguiente comando desde el directorio que contiene ambos archivos:

    ```bash
    docker run --rm --name systemd-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/systemd-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/systemd-demo.log:/var/log/demo/systemd-demo.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenga la terminal abierta mientras verifica la ingesta. Cuando termine, detenga el recolector con **Ctrl+C**. Si vuelve a ejecutar la demostración, la muestra se ingestará de nuevo con marcas de tiempo actualizadas.
  </Step>

  <Step title="Verificar los logs de demostración" id="verify-demo">
    Abra **Búsqueda**, seleccione **Logs**, filtre por `ServiceName:systemd-demo` y seleccione **últimos 2 días**. Debería ver las entradas de muestra con los atributos `unit`, `hostname` y `message`.

    <div className="ch-image-lg">
      <Frame>
        ![Logs de demostración de systemd en Búsqueda de ClickHouse Observability](/images/clickstack/observability-systemd-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Resolución de problemas {#troubleshooting}

### No se encuentra journalctl {#journalctl-not-found}

Ejecute el recolector real en el host Linux supervisado, con `journalctl` instalado y disponible en su ruta de ejecución. La demo usa `filelog` y no lo necesita.

### No aparecen logs {#no-logs}

Revise la salida del recolector para detectar errores de acceso al registro, de autenticación o de exportación. Compruebe que `sudo journalctl -n 20` devuelve entradas en el host supervisado. Si configuró un filtro de unidades, compruebe que coincide con los nombres de sus servicios. Genere una nueva entrada después de iniciar la recolección.

En ClickHouse Observability, revise la fuente **Logs**, el filtro por nombre de servicio y el intervalo de tiempo. Para la demo, seleccione **Últimos 2 días** y compruebe que el archivo de muestra está montado en la ruta configurada.
