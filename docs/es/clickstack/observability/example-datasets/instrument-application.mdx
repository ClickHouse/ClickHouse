    <Note>
      **TL;DR**

      Clona el repositorio [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), rellena `.env` con tu endpoint OTLP HTTP gestionado y tu clave de API y, a continuación, pega el prompt del agente. El backend no necesita importaciones de OpenTelemetry: el agente conecta `@hyperdx/node-opentelemetry` al iniciarse el proceso.

      Tiempo estimado: unos 10 minutos
    </Note>

    HackerNews Analyzer es una aplicación Node.js que consulta el conjunto de datos de HackerNews alojado en la demo pública de ClickHouse. Las interacciones con el panel de control generan solicitudes al backend. Las solicitudes que no se resuelven desde la caché de la aplicación también consultan ClickHouse, lo que añade a la traza un span HTTPS saliente.

    Esta demo combina la autoinstrumentación del backend, los spans de consultas de ClickHouse y la reproducción de sesiones del navegador en una sola aplicación.

## Requisitos previos {#prerequisites}

    * Versiones de Node.js y npm compatibles con [HackerNews Analyzer y sus dependencias](https://github.com/ClickHouse/hn-news-analyzer#readme).
    * Un servicio de ClickHouse Observability totalmente gestionado ya existente. Consulte la [guía de introducción de la versión totalmente gestionada](/es/clickstack/observability/getting-started).
    * Acceso de red al endpoint de telemetría gestionado, tanto desde el servidor de la aplicación como desde su navegador.

## Clonar el repositorio {#clone-the-repository}

    Clone [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), instale las dependencias y copie la plantilla del archivo env:

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    En los próximos pasos completará el archivo `.env` y, después, instrumentará la aplicación desde este directorio.

## Instrumentación de la aplicación {#instrument-the-application}

    <Steps>
      <Step title="Ejecute la aplicación" id="run-the-application">
        Desde el directorio `hn-news-analyzer` clonado, inicie la aplicación. La fuente de datos de ClickHouse apunta de forma predeterminada al cluster público de demo de solo lectura, por lo que funciona sin ninguna configuración adicional:

        ```bash
        ./run.sh
        ```

        Abra [http://localhost:5001](http://localhost:5001). Verá un selector de año, estadísticas de resumen, un gráfico de actividad, tablas con los principales usuarios y dominios, y un cuadro de búsqueda. Explore la aplicación: cambie de año y consulte el detalle de las historias.

        <Frame>
          <img src="/images/clickstack/getting-started/hackernews_main.webp" alt="La aplicación HackerNews Analyzer ejecutándose localmente" />
        </Frame>

        En este punto, la aplicación ya está en ejecución, pero aún no está instrumentada. Empezará a enviar telemetría una vez que complete los pasos de instrumentación que se describen a continuación.
      </Step>

      <Step title="Configurar el entorno" id="configure-environment">
        Abra su servicio de ClickHouse Observability y vaya a **Configuración del equipo → Managed Telemetry**. Copie el **endpoint OTLP HTTP** y la **clave de API**.

        <div className="ch-image-lg">
          <Frame>
            ![Sección Managed Telemetry en Configuración del equipo, con el endpoint OTLP HTTP y la clave de API enmascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        En el archivo `.env` de la aplicación, defina los siguientes valores y sustituya los marcadores de posición del endpoint y de la clave de API:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Mantenga el prefijo `https://` en `OTEL_EXPORTER_OTLP_ENDPOINT` y no añada `/v1/logs`, `/v1/traces` ni `/v1/metrics`. Los SDK añaden por sí mismos las rutas de cada señal. Establezca `OTEL_EXPORTER_OTLP_HEADERS` en `authorization=<your-api-key>` sin el prefijo `Bearer`; la aplicación también pasa esta clave directamente al SDK para navegador.

        El SDK para navegador utiliza el mismo endpoint y la misma clave de API. `vite.config.ts` los incrusta en el paquete del navegador, donde cualquier visitante puede inspeccionarlos. Utilice un servicio destinado exclusivamente a probar esta demo y mantenga `.env` fuera del control de versiones.
      </Step>

          <Tab title="Instrumentación manual" id="instrument-manually">
            La instrumentación consta de tres partes: instalar los SDKS, cambiar el comando de inicio y habilitar el SDK para navegador. Nada de esto modifica la lógica de negocio de la aplicación.

### Instalar el SDK de Node {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### Habilitar el envoltorio en run.sh {#enable-run-sh-wrapper}

            Al final de `run.sh` hay dos líneas `exec`. Comente la línea que usa `node` directamente y descomente la instrumentada:

            ```diff
             # BEFORE: plain node, no instrumentation:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # AFTER: same source, wrapped by opentelemetry-instrument:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            Siga iniciando la aplicación a través de `scripts/entrypoint.js`. Ese shim llama a `require('console')` para que la captura de consola envuelva `console.log`. Si apunta `opentelemetry-instrument` directamente a `dist/server/index.js`, las trazas se envían, pero los logs se descartan sin ningún aviso.

### Habilitar el SDK para navegador {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            En `src/web/telemetry.ts`, descomente el import, el bloque `HyperDX.init` y `HyperDX.addAction` en `recordAction`:

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` y `__OTLP_AUTH_TOKEN__` son constantes de tiempo de compilación que `vite.config.ts` inyecta a partir de los mismos valores `OTEL_EXPORTER_OTLP_*` que usa el backend.
          </Tab>

          <Tab title="Usar una rama preinstrumentada" id="use-the-instrumented-branch">
            Para omitir la instrumentación y partir de una aplicación ya instrumentada, haga checkout de la [rama `instrumented`](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented).

            ```bash
            git checkout instrumented
            npm install
            ```

            No ejecute `./reset.sh` en esta rama, salvo que quiera eliminar los SDKS.
          </Tab>

    HackerNews Analyzer es una aplicación Node.js que consulta el conjunto de datos de HackerNews alojado en la demo pública de ClickHouse. Cada gráfico, tabla y cuadro de búsqueda corresponde a una consulta de ClickHouse real, por lo que cada interacción genera una traza cuyo span principal es la llamada HTTPS que el backend realiza a ClickHouse.

    Este caso es distinto de la [demo de reproducción de sesiones](/es/clickstack/observability/example-datasets/session-replay), que instrumenta una aplicación que se ejecuta solo en el navegador y envía telemetría a ClickHouse Observability. Aquí obtendrá autoinstrumentación del backend, spans de consultas de ClickHouse y reproducción de sesiones desde una misma aplicación.

## Requisitos previos {#prerequisites-self-configured}

    * Node 18+ y npm
    * Un servicio de Self-managed ClickHouse Observability ya existente y un recolector de ingestión en ejecución.
    * El endpoint OTLP HTTP del recolector, accesible tanto desde el servidor de la aplicación como desde su navegador. Utilice `http://localhost:4318` solo si el recolector se ejecuta en la misma máquina.
    * El `OTLP_AUTH_TOKEN` del recolector, si está configurado. Defina los encabezados como `authorization=<token>`, sin el prefijo `Bearer`. Si el recolector no requiere autenticación, deje `authorization=` vacío. Se trata de credenciales de ingestión del recolector, no de las credenciales de su base de datos en ClickHouse.
