<Info>
  **TL;DR**

  Esta guía explica cómo instrumentar una aplicación web para la reproducción de sesiones con el SDK para navegador y ClickHouse Observability, ya sea en su versión totalmente gestionada o autogestionada. A diferencia de otros conjuntos de datos de ejemplo que cargan datos pregenerados, esta demo ofrece una aplicación interactiva en la que usted mismo genera los datos de sesión a través de sus propias interacciones.

  Tiempo necesario: 10-15 minutos
</Info>

## Descripción general {#overview}

La [aplicación de demostración de reproducción de sesiones](https://github.com/ClickHouse/clickstack-session-replay-demo) es un explorador de documentación creado con JavaScript puro. Demuestra lo sencilla que puede ser la instrumentación de reproducción de sesiones: basta con una etiqueta script y una llamada de inicialización para capturar automáticamente las interacciones del usuario.

El repositorio incluye dos ramas:

* **`main`**: totalmente instrumentada y lista para usar de inmediato
* **`pre-instrumented`**: una versión limpia sin instrumentación, con comentarios en el código que indican dónde añadirla

Esta guía utiliza primero la rama `main` para ver la reproducción de sesiones en acción y, a continuación, repasa el código de instrumentación para que pueda aplicar el mismo patrón a su propia aplicación.

Para obtener información general sobre qué es la reproducción de sesiones y cómo se integra en ClickStack, consulte la página de la funcionalidad [Reproducción de sesiones](/es/clickstack/observability/features/session-replay).

## Requisitos previos {#prerequisites}

* Docker instalado y en ejecución, con Docker Compose disponible
* El puerto 3000 libre para la aplicación de demostración
* Un servicio de ClickHouse Observability existente, ya sea totalmente gestionado o autogestionado
* Acceso a la red desde su navegador al endpoint de telemetría que se configura más abajo

        Necesita un [servicio totalmente gestionado](/es/clickstack/observability/getting-started) existente. ClickHouse proporciona el recolector de ingestión.

        En su servicio de ClickHouse Observability, abra **Team Settings → Data → Managed Telemetry** y copie el **OTLP HTTP endpoint** y la **API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Managed Telemetry con el endpoint OTLP HTTP y la clave de API enmascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)

        ```shell

        export CLICKSTACK_API_KEY='Bearer YOUR_API_KEY'
        export CLICKSTACK_UI_URL='YOUR_OBSERVABILITY_UI_URL'
        ```

        Conserve el prefijo `https://` y omita las rutas de señal, como `/v1/traces`. Incluya el prefijo `Bearer ` para la ingestión totalmente gestionada, tal como se muestra arriba.

        `CLICKSTACK_UI_URL` controla los enlaces **Open Observability** de la demo; es independiente del endpoint de ingestión de telemetría.

        El servidor pasa el endpoint de telemetría y la clave de API al SDK para navegador. La clave de ingestión queda visible en el navegador, por lo que conviene usar un servicio de prueba para esta demo.
      </Tab>

      <Tab title="Autogestionado">
        Necesita un [servicio autogestionado](/es/clickstack/self-configured/getting-started/managed) existente y un Recopilador de OpenTelemetry de ClickStack en ejecución conectado a él. Consulte [Ingesta con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured) para ver las instrucciones de conexión o la [guía de despliegue](/es/clickstack/self-configured/deployment/managed#start-a-collector-existing) para iniciar un recolector.

        El endpoint OTLP HTTP del recolector debe ser accesible desde su navegador y la configuración de CORS debe permitir `http://localhost:3000`. La interfaz de usuario debe admitir el atributo `session.id` del nuevo SDK en Client Sessions; consulte los [requisitos de compatibilidad del SDK](https://github.com/ClickHouse/clickstack-browser#clickstack-versions).

        Asigne a `CLICKSTACK_OTEL_ENDPOINT` el endpoint OTLP HTTP de su recolector, sin ninguna ruta de señal como `/v1/traces`. Asigne a `CLICKSTACK_UI_URL` la URL de **Client Sessions** copiada de la interfaz de usuario de su servicio autogestionado.

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
        export CLICKSTACK_API_KEY='YOUR_COLLECTOR_TOKEN'
        export CLICKSTACK_UI_URL='YOUR_CLIENT_SESSIONS_URL'
        ```

        Use el token de autenticación configurado en el receptor de su recolector. Para un recopilador de ClickStack protegido con `OTLP_AUTH_TOKEN`, use ese valor sin el prefijo `Bearer`. Si su receptor no requiere autenticación, asigne a `CLICKSTACK_API_KEY` una cadena vacía. No utilice aquí la contraseña de su base de datos en ClickHouse.

        El token de ingestión se pasa al SDK para navegador y queda visible en el navegador. Las credenciales de la base de datos en ClickHouse del recolector permanecen en el propio recolector.

## La instrumentación {#instrumentation}

La aplicación de demostración muestra lo poco código que se necesita para habilitar la reproducción de sesiones. Basta con añadir dos elementos a la aplicación. Los siguientes ejemplos utilizan el nuevo SDK de navegador de ClickStack:

**1. Incluya el SDK (`app/public/index.html`):**

```html
<script src="https://cdn.jsdelivr.net/npm/@clickhouse/clickstack-browser@1.0.0/dist/clickstack.iife.js" integrity="sha384-NW4JhbuY4Thx4fMuqFwKvifcPn7ad9dJ7DU/MTxhkoHeadG27i4F38Yo1Gz6y0WA" crossorigin="anonymous"></script>
```

**2. Inicialice el SDK para navegador (`app/public/js/app.js`):**

```javascript
window.ClickStack.init({
  endpoint: window.CLICKSTACK_CONFIG.endpoint,
  apiKey: window.CLICKSTACK_CONFIG.apiKey,
  serviceName: 'clickhouse-session-replay-demo',
  console: 'debug',
});
```

`app/server.js` proporciona `window.CLICKSTACK_CONFIG` a partir de las variables de entorno `CLICKSTACK_OTEL_ENDPOINT`, `CLICKSTACK_API_KEY` y `CLICKSTACK_UI_URL`. El SDK usa el endpoint y la clave de API, mientras que los enlaces de la demo usan la URL de la interfaz de usuario. El SDK captura la reproducción de sesiones, los registros de la consola, las solicitudes de red y los errores sin modificar la lógica de negocio de la aplicación.

Los textos y los valores de entrada se enmascaran de forma predeterminada. Consulte los [controles de privacidad del SDK para navegador](/es/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy) antes de modificar los ajustes de enmascaramiento.

### Pruébelo usted mismo {#try-it-yourself}

Para instrumentar la aplicación desde cero, detenga la demo en ejecución con `Ctrl+C` y, a continuación, cambie a la rama `pre-instrumented`:

```shell
git checkout pre-instrumented
```

Esta rama contiene la misma aplicación, pero sin el SDK para navegador habilitado. Los comentarios del código en `app/public/index.html` y `app/public/js/app.js` indican dónde añadir los dos fragmentos anteriores. Mantenga las variables de conexión configuradas previamente y, a continuación, vuelva a compilar e inicie la aplicación:

```shell
docker compose --profile demo up --build --no-deps demo-app
```

Recargue la demo en su navegador e interactúe con ella para generar una nueva sesión.

## Resolución de problemas {#troubleshooting}

### Las sesiones no aparecen {#sessions-not-appearing}

1. Revise la consola del navegador en busca de errores
2. Verifique que la aplicación de demostración esté en ejecución: `docker compose ps demo-app`
3. Confirme que `CLICKSTACK_OTEL_ENDPOINT` y `CLICKSTACK_API_KEY` estén definidas en la terminal desde la que inició la aplicación. Si las modifica, vuelva a ejecutar el comando de inicio y recargue la pestaña del navegador.
4. En implementaciones autogestionadas, revise los errores de exportación del recolector, la configuración de CORS y los requisitos de compatibilidad del SDK indicados anteriormente
5. Ajuste el intervalo de tiempo en la vista Client Sessions (pruebe con **Last 15 minutes**)
6. Fuerce la recarga del navegador: `Cmd+Shift+R` (Mac) o `Ctrl+Shift+R` (Windows/Linux)

### Errores 401 Unauthorized {#401-errors}

La clave de API no está configurada correctamente. Asegúrese de lo siguiente:

1. Exportó `CLICKSTACK_API_KEY` en su terminal con el valor correspondiente a su modo de despliegue
2. Inició la aplicación de demostración en la **misma terminal** en la que la exportó
3. En la opción totalmente gestionada, utilizó la API key de ingesta de **configuración del equipo → Datos → Managed Telemetry** con el prefijo `Bearer `. En la opción autogestionada, utilizó el token del receptor de su recolector sin dicho prefijo.

## Limpieza {#cleanup}

Cierre las pestañas del navegador de la demo para detener la telemetría del navegador y pulse `Ctrl+C` en la terminal en la que se ejecuta la aplicación. Para detenerla desde otra terminal, ejecute este comando desde el directorio del repositorio:

```bash
docker compose stop demo-app
```

Esto detiene la aplicación local; la telemetría ya ingerida en su servicio se conserva.
