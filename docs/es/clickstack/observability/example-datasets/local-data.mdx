Recopile logs locales y métricas del sistema y envíelos a **ClickHouse Observability** para su visualización y análisis.

Este ejemplo utiliza Docker en Linux o Docker Desktop en macOS. Antes de comenzar, instale e inicie Docker y cree un servicio de ClickHouse Observability siguiendo la [guía de primeros pasos para la versión totalmente gestionada](/es/clickstack/observability/getting-started) o la [guía de primeros pasos para la versión autogestionada](/es/clickstack/self-configured/getting-started/managed).

## Recopilar datos locales {#collect-local-data}

Seleccione su tipo de implementación a continuación para configurar e iniciar el recolector. Una vez completada la configuración, ambas implementaciones siguen los mismos pasos de exploración.

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase Beta" />

    En su servicio de ClickHouse Observability, abra **Configuración del equipo → Datos** y copie el endpoint HTTP de OTLP y la clave de API.

    <Steps>
      <Step title="Cree una configuración personalizada de OpenTelemetry" id="create-otel-configuration">
        Cree un archivo `custom-local-config.yaml` con el siguiente contenido:

        ```yaml
        receivers:
          file_log:
            include:
              - /host/var/log/**/*.log
              - /host/var/log/syslog
              - /host/var/log/messages
            start_at: end
            resource:
              service.name: system-logs

          host_metrics:
            root_path: ${env:HOST_METRICS_ROOT_PATH}
            collection_interval: 30s
            scrapers:
              cpu:
                metrics:
                  system.cpu.utilization:
                    enabled: true
              memory:
                metrics:
                  system.memory.utilization:
                    enabled: true
              filesystem:
              paging:
              disk:
              load:
              network:

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resource:
            attributes:
              - key: host.name
                value: ${env:HOST_NAME}
                action: upsert
          batch:
            timeout: 5s
            send_batch_size: 1024

        exporters:
          otlp_http:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: "Bearer ${env:OTEL_EXPORTER_OTLP_API_KEY}"

        service:
          pipelines:
            logs:
              receivers: [file_log]
              processors: [memory_limiter, resource, batch]
              exporters: [otlp_http]
            metrics:
              receivers: [host_metrics]
              processors: [memory_limiter, resource, batch]
              exporters: [otlp_http]
        ```

        El receptor `file_log` lee de forma continua (tail) los archivos de registro locales, y el receptor `host_metrics` recopila métricas del sistema. Ambas canalizaciones envían los datos a su endpoint de telemetría gestionada mediante HTTPS.

        <Info>
          Este ejemplo solo lee las entradas de log nuevas (`start_at: end`). No analiza las marcas de tiempo del cuerpo del registro. Añada un analizador de marcas de tiempo al receptor de archivos si necesita conservar el tiempo del evento original. Use `start_at: beginning` para ingestar también las entradas ya existentes en los archivos recién descubiertos.
        </Info>

        Para obtener más información sobre la estructura de configuración de OpenTelemetry (OTel), recomendamos consultar [la guía oficial](https://opentelemetry.io/docs/collector/configuration/).
      </Step>

      <Step title="Inicie el colector de OpenTelemetry" id="start-the-otel-collector">
        Configure el endpoint y la clave de API copiados desde **Configuración del equipo → Datos**:

        ```shell
        export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
        printf "API key: "
        read -r -s OTEL_EXPORTER_OTLP_API_KEY
        printf "\n"
        export OTEL_EXPORTER_OTLP_API_KEY
        ```

        El endpoint es la URL base de OTLP HTTP, sin `/v1/logs` ni `/v1/metrics`. El recolector añade la ruta correspondiente.

        <Tabs>
          <Tab title="Linux">
            Monte el sistema de archivos del host en modo de solo lectura para que el recolector pueda leer las métricas del host y los archivos de registro:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e OTEL_EXPORTER_OTLP_ENDPOINT \
              -e OTEL_EXPORTER_OTLP_API_KEY \
              -e HOST_NAME="$(hostname)" \
              -e HOST_METRICS_ROOT_PATH=/hostfs \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/config.yaml:ro" \
              -v /:/hostfs:ro \
              -v /var/log:/host/var/log:ro \
              otel/opentelemetry-collector-contrib:0.161.0
            ```
          </Tab>

          <Tab title="macOS (Docker Desktop)">
            Monte el directorio de logs de macOS en modo de solo lectura. Las métricas corresponden a la VM Linux de Docker Desktop y usan la etiqueta de host correspondiente:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e OTEL_EXPORTER_OTLP_ENDPOINT \
              -e OTEL_EXPORTER_OTLP_API_KEY \
              -e HOST_NAME="$(hostname)-docker-desktop" \
              -e HOST_METRICS_ROOT_PATH=/ \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/config.yaml:ro" \
              -v /private/var/log:/host/var/log:ro \
              otel/opentelemetry-collector-contrib:0.161.0
            ```

            Docker Desktop debe tener permiso para compartir `/private/var/log`.
          </Tab>
        </Tabs>

        Compruebe que el recolector se inicia sin errores de configuración ni de exportación:

        ```shell
        docker logs local-otel-collector
        ```

        Las métricas se recopilan cada 30 segundos. Los logs aparecen cuando se añaden nuevas entradas al final de un archivo que coincide con el patrón. Mantenga el recolector en ejecución mientras explora los datos en los pasos siguientes.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Autogestionado" id="self-managed">
    Utilice las credenciales de conexión de su servicio de ClickHouse Cloud, tal como se describe en la [guía de primeros pasos para la versión autogestionada](/es/clickstack/self-configured/getting-started/managed#next-steps).

    <Steps>
      <Step title="Crear una configuración personalizada de OpenTelemetry" id="create-otel-configuration-self-configured">
        Cree un archivo `custom-local-config.yaml` con el siguiente contenido:

        ```yaml
        receivers:
          file_log:
            include:
              - /host/var/log/**/*.log        # Linux logs from host
              - /host/var/log/syslog
              - /host/var/log/messages
            start_at: beginning
            resource:
              service.name: "system-logs"

          host_metrics:
            root_path: ${env:HOST_METRICS_ROOT_PATH}
            collection_interval: 1s
            scrapers:
              cpu:
                metrics:
                  system.cpu.time:
                    enabled: true
                  system.cpu.utilization:
                    enabled: true
              memory:
                metrics:
                  system.memory.usage:
                    enabled: true
                  system.memory.utilization:
                    enabled: true
              filesystem:
                metrics:
                  system.filesystem.usage:
                    enabled: true
                  system.filesystem.utilization:
                    enabled: true
              paging:
                metrics:
                  system.paging.usage:
                    enabled: true
                  system.paging.utilization:
                    enabled: true
                  system.paging.faults:
                    enabled: true
              disk:
              load:
              network:
              processes:

        service:
          pipelines:
            logs/local:
              receivers: [file_log]
              processors:
                - memory_limiter
                - batch
              exporters:
                - clickhouse
            metrics/hostmetrics:
              receivers: [host_metrics]
              processors:
                - memory_limiter
                - batch
              exporters:
                - clickhouse
        ```

        Esta configuración recopila registros del sistema y métricas de sistemas macOS y Linux, y envía los resultados a su servicio. La configuración amplía el recopilador de ClickStack añadiendo nuevos receivers y canalizaciones: se hace referencia al exportador `clickhouse` y a los procesadores (`memory_limiter`, `batch`) que ya están configurados en el recopilador de ClickStack base.

        <Info>
          **Marcas de tiempo en la ingestión**

          Esta configuración ajusta las marcas de tiempo durante la ingestión y asigna un valor de tiempo actualizado a cada evento. Lo ideal es [preprocesar o analizar las marcas de tiempo](/es/clickstack/self-configured/ingesting-data/collector#processing-filtering-transforming-enriching-self-configured) mediante procesadores u operadores de OTel en los archivos de registro para garantizar que se conserve con precisión el tiempo del evento.

          Con esta configuración de ejemplo, si el receptor o el procesador de archivos está configurado para comenzar desde el principio del archivo, a todas las entradas de log existentes se les asignará la misma marca de tiempo ajustada: el momento del procesamiento, en lugar del tiempo del evento original. Los nuevos eventos añadidos al final del archivo recibirán marcas de tiempo próximas a su momento real de generación.

          Para evitar este comportamiento, puede establecer la posición de inicio en `end` en la configuración del receptor. Así, solo se ingestarán las entradas nuevas, con una marca de tiempo cercana a su momento real de llegada.
        </Info>

        Para obtener más información sobre la estructura de configuración de OpenTelemetry (OTel), recomendamos consultar [la guía oficial](https://opentelemetry.io/docs/collector/configuration/).
      </Step>

      <Step title="Inicie el colector de OpenTelemetry" id="start-the-otel-collector-self-configured">
        Ejecute un recolector independiente con los valores que exportó de `CLICKHOUSE_ENDPOINT`, `CLICKHOUSE_USER` y `CLICKHOUSE_PASSWORD`:

        <Tabs>
          <Tab title="Linux">
            Monte el sistema de archivos del host en modo de solo lectura para que el recolector pueda leer las métricas del host y los archivos de registro:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e CUSTOM_OTELCOL_CONFIG_FILE=/etc/otelcol-contrib/custom.config.yaml \
              -e CLICKHOUSE_ENDPOINT \
              -e CLICKHOUSE_USER \
              -e CLICKHOUSE_PASSWORD \
              -e HOST_METRICS_ROOT_PATH=/hostfs \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/custom.config.yaml:ro" \
              -v /:/hostfs:ro \
              -v /var/log:/host/var/log:ro \
              clickhouse/clickstack-otel-collector:latest
            ```
          </Tab>

          <Tab title="macOS (Docker Desktop)">
            Monte el directorio de registros de macOS en modo de solo lectura. Las métricas corresponden a la VM Linux de Docker Desktop, no al host macOS:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e CUSTOM_OTELCOL_CONFIG_FILE=/etc/otelcol-contrib/custom.config.yaml \
              -e CLICKHOUSE_ENDPOINT \
              -e CLICKHOUSE_USER \
              -e CLICKHOUSE_PASSWORD \
              -e HOST_METRICS_ROOT_PATH=/ \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/custom.config.yaml:ro" \
              -v /private/var/log:/host/var/log:ro \
              clickhouse/clickstack-otel-collector:latest
            ```

            Docker Desktop debe tener permiso para compartir `/private/var/log`.
          </Tab>
        </Tabs>

        Compruebe que el recolector se inicia sin errores de configuración ni de exportación:

        ```shell
        docker logs local-otel-collector
        ```

        El recolector comenzará de inmediato a recopilar los registros del sistema y las métricas locales.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Explore sus datos {#explore-your-data}

Mantenga el recolector en ejecución mientras explora los datos. Las capturas de pantalla muestran la misma interfaz de Búsqueda y Explorador de Gráficos que se utiliza en ambos modos de despliegue.

<Steps>
  <Step title="Explorar los registros del sistema" id="explore-system-logs">
    En la consola de ClickHouse Cloud, seleccione su servicio y abra ClickHouse Observability.

    Abra [Búsqueda](/es/clickstack/observability/features/search) y seleccione la fuente **Logs**. Elija un intervalo de tiempo que abarque el periodo en el que el recolector estuvo en ejecución y, a continuación, filtre **ServiceName** por `system-logs`.

    Expanda un evento para inspeccionar sus atributos. La captura de pantalla muestra datos de ejemplo; sus mensajes de registro y los atributos del host serán diferentes.

    <div className="ch-image-lg">
      <Frame>
        ![Log local de ejemplo en ClickHouse Observability, con el nombre del archivo de registro y los atributos del host](/images/clickstack/observability-local-logs.png)
      </Frame>
    </div>
  </Step>

  <Step title="Explorar las métricas del sistema" id="explore-system-metrics">
    Abra **Explorador de Gráficos** y seleccione **Time Series** y la fuente **Métricas**. Elija **Maximum** como agregación y, a continuación, seleccione `system.memory.utilization`. Deje **Delta** sin marcar.

    En el campo **Where**, utilice `Attributes.state:"used"` para mostrar la memoria utilizada. Si recopila métricas de varios hosts, filtre también por el atributo de host presente en sus datos.

    Seleccione un intervalo de tiempo que abarque el periodo en el que el recolector estuvo en ejecución y, a continuación, haga clic en **Run**. La captura de pantalla muestra datos de ejemplo filtrados para un único host. La métrica es una proporción entre 0 y 1: un valor de `0.62` representa una utilización del 62%.

    <div className="ch-image-lg">
      <Frame>
        ![Utilización de memoria filtrada por memoria utilizada en un host de ejemplo en ClickHouse Observability](/images/clickstack/observability-local-memory-utilization.png)
      </Frame>
    </div>

    Para mostrar la utilización como porcentaje, abra **Configuración De Visualización** y elija **Percentage** en **formato de salida**.

    <div className="ch-image-lg">
      <Frame>
        ![Configuración De Visualización del Explorador de Gráficos con Percentage seleccionado como formato de salida](/images/clickstack/observability-local-memory-display-settings.png)
      </Frame>
    </div>

    Haga clic en **Apply** para actualizar el gráfico.

    <div className="ch-image-lg">
      <Frame>
        ![Utilización de memoria mostrada como porcentaje para un host de ejemplo](/images/clickstack/observability-local-memory-percentage.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Detener la recopilación {#stop-collection}

Cuando termine, detenga la recopilación y elimine el contenedor:

```shell
docker stop local-otel-collector
docker rm local-otel-collector
```
