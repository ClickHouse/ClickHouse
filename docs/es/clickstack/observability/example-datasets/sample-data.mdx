Explore ClickHouse Observability con logs, sesiones, trazas y métricas de muestra de una tienda de comercio electrónico. Ambos modos de despliegue utilizan el mismo conjunto de datos y el mismo flujo de trabajo de investigación.

Antes de comenzar, complete la [guía de primeros pasos de la versión totalmente gestionada](/es/clickstack/observability/getting-started) o la [guía de primeros pasos de la versión autogestionada](/es/clickstack/self-configured/getting-started/managed).

<Steps>
  <Step title="Configure su conexión" id="configure-your-connection">
    Elija su implementación y defina las siguientes variables en la terminal donde cargará los datos de muestra.

    <Tabs>
      <Tab title="Totalmente gestionado">
        <BetaBadge label="Oferta Beta" />

        Abra **Team Settings → Data** y busque **Managed Telemetry**. En **OpenTelemetry Collector**, use la opción **URL** para copiar el endpoint OTLP HTTP y la clave de API. Seleccione **Reveal key** para ver los valores completos.

        Defina el endpoint base sin una ruta de señal como `/v1/logs`. Incluya el prefijo `Bearer` en el valor de autorización:

        ```shell
        export CLICKSTACK_OTLP_ENDPOINT='<your-managed-otlp-http-endpoint>'
        export CLICKSTACK_AUTHORIZATION='Bearer <your-api-key>'
        ```

        Para este ejemplo no es necesario desplegar un recolector.
      </Tab>

      <Tab title="Autogestionado" id="self-managed">
        Necesita un Recopilador de OpenTelemetry de ClickStack en ejecución y conectado a su servicio de ClickHouse Cloud. Siga la [guía de ingesta con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#self-managed) para configurar la conexión, o la [guía de implementación](/es/clickstack/self-configured/deployment/managed) para iniciar un recolector.

        Defina el endpoint OTLP HTTP del recolector, que debe ser accesible desde la máquina donde se ejecuta el comando de carga. Use la URL base sin una ruta de señal como `/v1/logs`:

        ```shell
        export CLICKSTACK_OTLP_ENDPOINT='http://<collector-host>:4318'
        export CLICKSTACK_AUTHORIZATION=''
        ```

        Si el recolector requiere autenticación, asigne a `CLICKSTACK_AUTHORIZATION` el token de su receptor. Para un recopilador de ClickStack protegido con `OTLP_AUTH_TOKEN`, use ese valor sin el prefijo `Bearer`. Deje el valor vacío si el receptor no requiere autenticación. No use aquí la contraseña de su base de datos en ClickHouse.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Descargar datos de muestra" id="download-sample-data">
    Para poblar la interfaz de usuario con datos de muestra, descargue el siguiente archivo:

    [Datos de muestra](https://storage.googleapis.com/hyperdx/sample.tar.gz)

    ```shell
    # curl
    curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
    # or
    # wget https://storage.googleapis.com/hyperdx/sample.tar.gz
    ```

    Este archivo contiene logs, métricas y trazas de ejemplo de nuestra [OpenTelemetry demo](https://github.com/ClickHouse/opentelemetry-demo) pública, una sencilla tienda de comercio electrónico basada en microservicios. Copie este archivo en el directorio que prefiera.
  </Step>

  <Step title="Cargar datos de muestra" id="load-sample-data">
    Ejecute los siguientes comandos en **Bash** desde el directorio que contiene `sample.tar.gz`. Estos comandos envían los datos de muestra al endpoint configurado anteriormente y solo añaden una cabecera de autorización cuando es necesaria.

    ```bash
    set -eo pipefail

    auth_headers=()
    if [ -n "${CLICKSTACK_AUTHORIZATION:-}" ]; then
      auth_headers=(-H "Authorization: ${CLICKSTACK_AUTHORIZATION}")
    fi

    for filename in $(tar -tf sample.tar.gz); do
      endpoint="${CLICKSTACK_OTLP_ENDPOINT%/}/v1/${filename%.json}"
      echo "loading ${filename%.json}"
      tar -xOf sample.tar.gz "$filename" | while read -r line; do
        printf '%s\n' "$line" | curl --fail-with-body -sS -X POST "$endpoint" \
          -H "Content-Type: application/json" \
          "${auth_headers[@]}" \
          --data-binary @-
      done
    done
    ```

    Esto simula fuentes OTLP de logs, trazas y métricas que envían datos. En producción, estas fuentes pueden ser SDK de aplicaciones, agentes o Colectores de OpenTelemetry.

    En la consola de ClickHouse Cloud, seleccione su servicio y abra ClickHouse Observability.

    Vuelva a [Búsqueda](/es/clickstack/observability/features/search) para ver los datos cargados. Seleccione la fuente **Logs** y un intervalo de tiempo que incluya las marcas de tiempo de los eventos de muestra. En la siguiente captura de pantalla se muestran logs de muestra llegando en **Live Tail**:

      </Frame>
    </div>

    La carga de datos tardará unos minutos. Espere a que finalice antes de continuar con los siguientes pasos.
  </Step>

  <Step title="Explorar sesiones" id="explore-sessions">
    Supongamos que recibimos informes de que nuestros usuarios tienen problemas al pagar sus compras. Podemos ver su experiencia mediante la reproducción de sesiones.

    Seleccione **Client Sessions** en el menú izquierdo y establezca un intervalo de tiempo que incluya las sesiones de muestra cargadas.

    <div className="ch-image-lg">
      <Frame>

      </Frame>

    Esta vista muestra las sesiones de la tienda de demostración, tanto sesiones anónimas como sesiones identificadas mediante una dirección de correo electrónico.

    Algunas sesiones tienen un recuento de errores distinto de cero. En este ejemplo, la sesión resaltada tiene un error.

    Seleccione la sesión resaltada para abrir su reproducción. Use el botón de reproducción situado en la parte inferior del reproductor para ver la sesión.

    <div className="ch-image-lg">
      <Frame>
        ![Reproducción de sesión con la tienda de la OpenTelemetry demo y los eventos de navegación](/images/clickstack/getting-started/observability-sample-data-replay.png)

    La reproducción muestra al usuario navegando por el sitio y añadiendo artículos a su carrito. Si lo desea, puede avanzar hasta el momento de la sesión en que intenta completar un pago.

  <Step title="Explorar logs" id="explore-logs">
    Para investigar otros fallos de pago, vuelva a [Búsqueda](/es/clickstack/observability/features/search).

    Seleccione **Logs** como fuente y elija `payment` en el filtro **ServiceName**. Utilice un intervalo de tiempo que incluya la sesión investigada.

    <div className="ch-image-lg">
      <Frame>
        ![Búsqueda filtrada por el servicio payment que muestra errores de tarjeta expirada y de caché de Visa llena junto a transacciones completadas correctamente](/images/clickstack/getting-started/observability-sample-data-payment-logs.png)
      </Frame>
    </div>

    Los resultados incluyen el error de tarjeta expirada de la sesión que investigamos, además de errores repetidos `Visa cache full: cannot add new item.`. Para ver cuándo se producen errores en el servicio de pagos, represente estos logs de errores en un gráfico a lo largo del tiempo.
  </Step>

  <Step title="Crear un gráfico de los errores de pago" id="chart-payment-errors">
    Abre el **Explorador de Gráficos**, selecciona **Serie temporal** y elige **Logs** como origen de datos. Selecciona **Count of Events** como agregación.

    En **Where**, selecciona **Lucene** e introduce el siguiente filtro:

    ```text
    SeverityText:"error" ServiceName:"payment"
    ```

    Establezca un intervalo de tiempo que abarque los datos de muestra y seleccione **Ejecutar**.

    <div className="ch-image-lg">
      <Frame>
        ![Explorador de Gráficos con el recuento de logs de error del servicio de pagos a lo largo del tiempo mediante un filtro de Lucene](/images/clickstack/getting-started/observability-sample-data-payment-errors-chart.png)
      </Frame>
    </div>

    El gráfico muestra el número de logs de error coincidentes en cada intervalo de tiempo. Incluye todos los errores del servicio `payment`, incluidos los de tarjeta expirada y los de caché llena. Se trata de recuentos de eventos de log, no de un recuento de pagos fallidos únicos.
  </Step>
</Steps>
