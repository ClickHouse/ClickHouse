  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta Beta" />

    [`otelgen`](https://github.com/krzko/otelgen) es una pequeña CLI escrita en Go que genera logs, trazas y métricas OTLP sintéticos. Úsela para enviar datos de prueba a ClickHouse Observability totalmente gestionado y explorar los resultados en Búsqueda y en el Explorador de Gráficos.

    <Steps>
      <Step title="Requisitos previos" id="prerequisites-managed">
        Necesita un servicio de ClickHouse Observability totalmente gestionado ya creado y acceso de red a su endpoint de telemetría gestionada. Consulte la [guía de primeros pasos de la versión totalmente gestionada](/es/clickstack/observability/getting-started).
      </Step>

      <Step title="Instalar otelgen" id="install-otelgen-managed">
        Instálelo con Homebrew:

        ```shell
        brew install krzko/tap/otelgen
        ```

        O instálelo con Go:

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="Configurar las variables de entorno" id="set-env-vars-managed">
        Abra su servicio de ClickHouse Observability y vaya a **Team Settings → Managed Telemetry**. Copie el **OTLP HTTP endpoint** y la **API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Managed Telemetry en Team Settings con el endpoint OTLP HTTP y la clave de API enmascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        Defina el endpoint con solo su host y puerto, sin el prefijo `https://`. Por ejemplo, `https://YOUR_OTEL_ENDPOINT:4318` pasa a ser `YOUR_OTEL_ENDPOINT:4318`. No añada ninguna ruta de señal, como `/v1/logs`.

        ```shell
        export OTEL_ENDPOINT='YOUR_OTEL_ENDPOINT:4318'
        printf "API key: "
        read -r -s OTEL_API_KEY
        printf "\n"
        export OTEL_API_KEY
        ```

        Los comandos siguientes usan `--protocol http` sin `--insecure`, por lo que `otelgen` se conecta mediante HTTPS con verificación de certificados. Quitar `https://` del argumento del endpoint no desactiva TLS. Cada solicitud se autentica con su clave de API de telemetría gestionada.
      </Step>

      <Step title="Generar trazas" id="generate-traces-managed">
        Envíe una breve ráfaga de trazas con varios spans:

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate` indica el número de trazas por segundo y `--duration`, la duración de la ejecución en segundos. Omita `--insecure` para que la conexión use HTTPS con verificación de certificados.
      </Step>

      <Step title="Generar logs" id="generate-logs-managed">
        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          logs multi --duration 10
        ```
      </Step>

      <Step title="Generar métricas" id="generate-metrics-managed">
        Ejecute el siguiente comando para generar métricas y, al cabo de unos segundos, pulse `Ctrl+C` para detenerlo.

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          metrics sum
        ```

        `otelgen` también admite los subcomandos `gauge`, `histogram`, `up-down-counter` y `exponential-histogram` dentro de `metrics`.
      </Step>

      <Step title="Verificar en ClickHouse Observability" id="verify-managed">
        En su servicio de ClickHouse Observability, abra **Search** y alterne entre las fuentes **Logs** y **Traces** para comprobar que aparecen nuevos eventos. Establezca el intervalo de tiempo en **Last 15 minutes** y busque el nombre de servicio predeterminado `otelgen`.

        Abra **Chart Explorer**, seleccione **Metrics** y cree un gráfico de `otelgen.metrics.sum` para verificar la ingesta de métricas.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Autogestionado">
    [`otelgen`](https://github.com/krzko/otelgen) es una pequeña CLI escrita en Go que genera logs, trazas y métricas OTLP sintéticos. Úsela para confirmar que un recolector de OpenTelemetry de ClickStack existente está aceptando datos y que los eventos aparecen en la interfaz de usuario de observabilidad.

    Esta guía presupone que el recolector ya está en ejecución con endpoints OTLP en `4317` (gRPC) y `4318` (HTTP).

    <Steps>
      <Step title="Requisitos previos" id="prerequisites-managed-self-configured">
        Esta guía presupone que ha completado la [guía de primeros pasos de ClickHouse Observability — Self-managed](/es/clickstack/self-configured/getting-started/managed) y que tiene un recolector de OpenTelemetry en ejecución con los endpoints OTLP gRPC (`4317`) y HTTP (`4318`) accesibles desde la máquina en la que ejecuta `otelgen`. Si [protegió el recolector](/es/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured) con un `OTLP_AUTH_TOKEN`, tenga ese valor a mano.
      </Step>

      <Step title="Instalar otelgen" id="install-otelgen-managed-self-configured">
        Instálelo con Homebrew:

        ```shell
        brew install krzko/tap/otelgen
        ```

        O bien con Go:

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="Definir variables de entorno" id="set-env-vars-managed-self-configured">
        Exporte el endpoint del recolector y, si el recolector está protegido, el token de autenticación:

        ```shell
        export OTEL_ENDPOINT=<host>:4317
        export OTLP_AUTH_TOKEN=<your_otlp_auth_token>
        ```

        Utilice el host y el puerto de su recolector. Si el recolector se ejecuta en la misma máquina, el valor es `localhost:4317`.

        <Info>
          **Recolector sin protección**

          De forma predeterminada, el recolector de OpenTelemetry de ClickStack no requiere autenticación. Si no ha seguido los pasos de [Protección del recolector](/es/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured) para definir un `OTLP_AUTH_TOKEN`, omita aquí `OTLP_AUTH_TOKEN` y elimine el flag `--header` de los comandos siguientes.
        </Info>
      </Step>

      <Step title="Generar trazas" id="generate-traces-managed-self-configured">
        Envíe una breve ráfaga de trazas con múltiples spans:

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate` indica las trazas por segundo y `--duration`, la duración de la ejecución en segundos. `--insecure` desactiva TLS en la conexión gRPC, algo necesario cuando se apunta `otelgen` al puerto OTLP sin cifrar del recolector.
      </Step>

      <Step title="Generar logs" id="generate-logs-managed-self-configured">
        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          logs multi
        ```
      </Step>

      <Step title="Generar métricas" id="generate-metrics-managed-self-configured">
        Los subcomandos de métricas no tienen en cuenta `--duration`. Ejecute el comando y pulse `Ctrl+C` al cabo de unos segundos para detenerlo.

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 \
          metrics sum
        ```

        `otelgen` también admite los subcomandos `gauge`, `histogram`, `up-down-counter` y `exponential-histogram` dentro de `metrics`.
      </Step>

      <Step title="Verificar en la interfaz de usuario de observabilidad" id="verify-managed-self-configured">
        Abra la interfaz de usuario de observabilidad desde la consola de ClickHouse Cloud. En la vista `Search`, alterne el origen entre `Logs` y `Traces` para confirmar que aparecen nuevos eventos. Establezca el rango de tiempo en `Last 15 minutes`. Abra el `Chart Explorer`, seleccione `Metrics` y represente en un gráfico una de las métricas generadas por `otelgen` (por ejemplo, `otelgen.metrics.sum`) para verificar la ingesta de métricas.
      </Step>
    </Steps>
  </Tab>
