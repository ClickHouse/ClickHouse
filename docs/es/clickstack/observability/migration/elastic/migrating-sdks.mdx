Elastic Stack ofrece dos tipos de SDK de lenguaje para instrumentar aplicaciones:

1. **[Agentes APM oficiales de Elastic](https://www.elastic.co/docs/reference/apm-agents/)**: están diseñados específicamente para usarse con Elastic Stack. Si utiliza estos agentes, planifique la transición a la [instrumentación de OpenTelemetry](https://opentelemetry.io/docs/languages/) correspondiente a su lenguaje, incluidos los spans y atributos personalizados que utilice su aplicación.

2. **[Elastic Distributions of OpenTelemetry (SDKs de EDOT)](https://www.elastic.co/docs/reference/opentelemetry/edot-sdks/)**: son las distribuciones de Elastic de los SDK estándar de OpenTelemetry, disponibles para .NET, Java, Node.js, PHP y Python. Si su aplicación ya utiliza un SDK de EDOT, no es necesario volver a instrumentar el código. Basta con reconfigurar el SDK para que exporte los datos de telemetría a su endpoint OTLP de ClickHouse Observability. Consulte [&quot;Migración de los SDK de EDOT&quot;](#migrating-edot-sdks-self-configured) para obtener más información.

## Migración de los SDK de EDOT {#migrating-edot-sdks-self-configured}

Las Elastic Distributions of the OpenTelemetry SDKs (SDKs de EDOT) son versiones personalizadas de los SDK oficiales de OpenTelemetry. Por ejemplo, el [EDOT Python SDK](https://www.elastic.co/docs/reference/opentelemetry/edot-sdks/python/) es una distribución personalizada por el proveedor del [SDK de OpenTelemetry para Python](https://opentelemetry.io/docs/languages/python/), diseñada para integrarse sin fricciones con Elastic Observability.

Dado que estos SDK se basan en las bibliotecas estándar de OpenTelemetry, la migración a ClickHouse Observability es sencilla: no es necesario volver a instrumentar las aplicaciones. Basta con ajustar la configuración para enviar los datos de telemetría a su endpoint OTLP de ClickHouse Observability.

La configuración sigue los mecanismos estándar de OpenTelemetry. En Python, normalmente se realiza mediante variables de entorno, tal como se describe en la [documentación de instrumentación sin código de OpenTelemetry](https://opentelemetry.io/docs/zero-code/python/configuration/).

Una configuración típica de un SDK de EDOT podría tener este aspecto:

```shell
export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
export OTEL_EXPORTER_OTLP_ENDPOINT=https://my-deployment.ingest.us-west1.gcp.cloud.es.io
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=ApiKey P....l"
```

Para migrar, actualice la configuración de conexión OTLP en el entorno de su aplicación y reiníciela. Los siguientes ejemplos usan OTLP HTTP con codificación protobuf.

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Copie el endpoint OTLP HTTP y la clave de API desde **Team Settings → Data → Managed Telemetry**:

    ```shell
    export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    Use el endpoint exacto, incluido el puerto, sin ningún sufijo de señal como `/v1/traces`. El valor de la cabecera usa `%20` para codificar el espacio que sigue a `Bearer`. Consulte [Envío de datos de OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry) para obtener los datos de conexión.
  </Tab>

  <Tab title="Autogestionado">
    Configure el SDK para que apunte al endpoint OTLP HTTP accesible de su recolector receptor:

    ```shell
    export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_COLLECTOR_TOKEN'
    ```

    Si protegió el recolector receptor con `OTLP_AUTH_TOKEN`, use ese token como valor de autorización. Use `localhost` solo si la aplicación y el recolector comparten el mismo espacio de nombres de red. Si el recolector tiene TLS habilitado, use su punto de conexión HTTPS y configure el SDK para que confíe en su certificado. Consulte [Protección del recolector](/es/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).

    Si la autenticación del recolector está deshabilitada, elimine el encabezado anterior de Elastic:

    ```shell
    unset OTEL_EXPORTER_OTLP_HEADERS
    ```
  </Tab>
</Tabs>

Si su aplicación define variables de endpoint, protocolo o encabezado OTLP específicas de cada señal, actualícelas también, ya que tienen precedencia sobre la configuración genérica anterior. Conserve los atributos del recurso existentes al establecer el nombre del servicio.
