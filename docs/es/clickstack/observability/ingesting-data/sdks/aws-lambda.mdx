Para funciones de Node.js con handlers async, utilice el SDK de Node.js de ClickStack. Para otros entornos de tiempo de ejecución o handlers basados en callbacks, utilice las capas de Lambda de OpenTelemetry que se describen a continuación.

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## Handlers async de Node.js {#nodejs-async-handlers}

Use un tiempo de ejecución de Node.js en Lambda que cumpla con la versión mínima de Node.js 22.15 que requiere el SDK. Instale el SDK e inclúyalo en su paquete de despliegue:

```shell
npm install @clickhouse/clickstack-node
```

Configure estas variables de entorno de Lambda para inicializar el SDK antes de que se cargue su handler y asignar un nombre a su servicio:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

Envuelva su handler async con `withFlush` para que la telemetría almacenada temporalmente en el búfer se exporte antes de que finalice la invocación:

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

Establezca el handler de la función en `index.handler`. Si empaqueta la función, mantenga el SDK y las dependencias instrumentadas como externos e inclúyalos en el paquete de despliegue. No habilite también una capa de Lambda de autoinstrumentación en esta configuración.

Defina las variables de destino que se indican a continuación en la configuración de entorno de la función Lambda. El endpoint debe ser accesible desde su función. El SDK completa su vaciado antes del plazo límite de la invocación; `withFlush` no es compatible con handlers basados en callbacks.

### Configure su destino {#configure-destination}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta Beta" />

    Abra **Team Settings → Data → Managed Telemetry** en su servicio y copie el **endpoint OTLP HTTP** y la **clave de API**. Use el endpoint HTTPS completo, incluido el puerto:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP y la clave de ingestión de su recolector. Si su recolector no tiene TLS configurado, use `http://` en lugar de `https://`. Para configurar el recolector, consulte [Ingesta con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## Otros tiempos de ejecución y handlers {#other-runtimes-and-handlers}

Siga las [instrucciones oficiales de autoinstrumentación de Lambda](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/) para seleccionar las capas correspondientes a su tiempo de ejecución, arquitectura y región de AWS, y para configurar el envoltorio de instrumentación.

Agregue y configure la [capa de Lambda del Colector de OpenTelemetry](https://opentelemetry.io/docs/platforms/faas/lambda-collector/). Mantenga los exportadores del SDK de la aplicación apuntando al recolector local, tal como se indica en la documentación upstream. A continuación, configure la conexión saliente del recolector.

### Configurar el destino del recolector de Lambda {#configure-lambda-collector-destination}

Defina `CLICKHOUSE_OTLP_ENDPOINT` y `CLICKHOUSE_INGESTION_API_KEY` en las variables de entorno de su función Lambda. Agregue el siguiente exportador a la configuración de su recolector.

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta Beta" />

    Abra **Team Settings → Data → Managed Telemetry** en su servicio y copie el **endpoint OTLP HTTP** y la **clave de API**. Asigne a `CLICKHOUSE_OTLP_ENDPOINT` el endpoint HTTPS completo, incluido el puerto, y a `CLICKHOUSE_INGESTION_API_KEY`, la clave.

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "Bearer ${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>

  <Tab title="Autogestionado">
    Asigne a `CLICKHOUSE_OTLP_ENDPOINT` el endpoint OTLP HTTP de su recolector y a `CLICKHOUSE_INGESTION_API_KEY`, su clave de ingestión. El endpoint debe ser accesible desde su función Lambda. Para configurar el recolector de destino, consulte [Ingesta con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>
</Tabs>

Incluya `otlphttp/clickhouse` en la lista `exporters` de cada canalización de señales que quiera enviar. Por ejemplo, con el receptor `otlp` de upstream:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

Incorpore estos ajustes a la configuración de su recolector y conserve los ajustes de su receptor y de su procesador. Empaquete la configuración con su función y establezca `OPENTELEMETRY_COLLECTOR_CONFIG_URI` con su ubicación, por ejemplo `/var/task/collector.yaml`, siguiendo las instrucciones de configuración del recolector de la documentación upstream.

## Verificar la ingestión {#verify-ingestion}

Despliegue e invoque su función. En ClickHouse Observability, seleccione un intervalo de tiempo reciente y busque el nombre del servicio de su función en Trazas. Consulte también Logs y Métricas si su instrumentación emite esas señales; añadir una canalización no activa su recopilación de forma automática.

Para la configuración de la capa y la resolución de problemas, consulte la [documentación de OpenTelemetry Lambda](https://github.com/open-telemetry/opentelemetry-lambda).
