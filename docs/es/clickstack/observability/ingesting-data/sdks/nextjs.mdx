Elija la instrumentación del lado del servidor para su despliegue de Next.js:

* **Autoalojado, con el tiempo de ejecución de Node.js:** utilice el SDK de Node.js de ClickStack.
* **Vercel o el tiempo de ejecución Edge:** utilice `@vercel/otel`.

Para la telemetría del navegador y la reproducción de sesiones, consulte la [guía del SDK para navegador](/es/clickstack/observability/ingesting-data/sdks/browser).

## Next.js autoalojado {#self-hosted-nextjs}

Use Node.js 22.15 o una versión posterior e instale el SDK:

```shell
npm install @clickhouse/clickstack-node
```

Cree `instrumentation.ts` en la raíz de su proyecto, o en `src` si su aplicación utiliza ese directorio. Inicialice el SDK únicamente en el tiempo de ejecución de Node.js:

```typescript
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { init } = await import('@clickhouse/clickstack-node');
    init();
  }
}
```

Agregue el SDK a `serverExternalPackages` en su configuración actual de Next.js para que se cargue fuera del paquete del servidor:

```javascript
// next.config.mjs
export default {
  serverExternalPackages: ['@clickhouse/clickstack-node'],
};
```

Configure el destino que se indica a continuación y establezca `OTEL_SERVICE_NAME` para identificar su aplicación. No precargue también el SDK ni inicialice otro SDK de OpenTelemetry. Para ver más opciones, consulte la [guía de Node.js](/es/clickstack/observability/ingesting-data/sdks/nodejs).

Para obtener información sobre la finalización y el despliegue, consulte las [indicaciones del SDK para Next.js](https://github.com/ClickHouse/clickstack-node#nextjs).

## Vercel y el tiempo de ejecución Edge {#vercel-or-edge}

Use `@vercel/otel` siguiendo las [instrucciones de configuración de OpenTelemetry para Next.js](https://nextjs.org/docs/app/guides/open-telemetry). Utilice esta configuración en lugar de la inicialización del SDK de Node.js de ClickStack descrita anteriormente.

Configure la [exportación OTLP](https://github.com/vercel/otel/tree/main/packages/otel#registerotelconfig-configuration) con los ajustes de conexión que se indican a continuación. Reemplace los destinos de ejemplo y las sobrescrituras de endpoint específicas de cada señal, y defina las variables en la configuración de su despliegue.

Si su despliegue de Vercel ya utiliza una integración de tracing, configure un [exportador personalizado](https://nextjs.org/docs/app/guides/open-telemetry#custom-exporters) para este destino, ya que las variables de entorno del endpoint por sí solas no sobrescriben dicha integración.

## Configure su destino {#configure-destination}

Establezca un nombre de servicio para cualquiera de las dos opciones de instrumentación:

```shell
export OTEL_SERVICE_NAME='my-nextjs-app'
```

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta en fase beta" />

    Abra **Team Settings → Data → Managed Telemetry** en su servicio y copie el **endpoint OTLP HTTP** y la **clave de API**. Use el endpoint HTTPS completo, incluido el puerto:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP de su recolector y la API key de ingesta. Use `http://` en lugar de `https://` si su recolector no tiene TLS configurado. Para configurar el recolector, consulte [Ingesta con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## Verificar la ingestión {#verify-ingestion}

Inicie su aplicación y envíe solicitudes a una página renderizada en el servidor o a una ruta de API. En ClickHouse Observability, seleccione un intervalo de tiempo reciente y busque el nombre del servicio de su aplicación en Traces.
