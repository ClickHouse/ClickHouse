Utilice un asistente de programación para añadir instrumentación a su aplicación siguiendo la guía correspondiente a su lenguaje o framework. El asistente puede identificar los puntos de entrada, instalar el SDK adecuado y configurar la exportación de telemetría.

La instrumentación automática cubre las bibliotecas y frameworks compatibles. Según el lenguaje y la aplicación, es posible que aún deba modificar el código o crear spans personalizados para capturar las operaciones de negocio. Revise los cambios generados antes de desplegarlos.

## Antes de comenzar {#before-you-begin}

Necesita el código fuente de su aplicación, un asistente de programación con acceso al repositorio y un destino de ClickHouse Observability. Elija la [guía del SDK](/es/clickstack/observability/ingesting-data/sdks) correspondiente al lenguaje de su aplicación; en ella encontrará los paquetes del SDK, las señales compatibles y los ajustes del exportador que debe utilizar.

## Proporcione a su asistente la guía del lenguaje {#give-your-assistant-the-language-guide}

Abra el repositorio de su aplicación en su asistente de programación, como Claude Code, Cursor o Codex. Copie el siguiente prompt y sustituya los marcadores de posición por la URL de la guía de su lenguaje, el tipo de despliegue y el nombre del servicio. Indique los nombres de sus variables de entorno en lugar de pegar credenciales directamente en el prompt.

```text wrap
Instrument this application to send telemetry to ClickHouse Observability.

Language or framework guide: <LANGUAGE_SDK_GUIDE_URL>
Destination: <fully managed or self-managed>
Service name: <SERVICE_NAME>
Endpoint environment variable: <ENDPOINT_VARIABLE_NAME>
Ingestion key environment variable: <API_KEY_VARIABLE_NAME>

Read the linked guide and use the instructions for my destination.
Inspect the application's language, framework, dependencies, and startup
commands before making changes. If you cannot read the guide, ask me for
its contents rather than guessing SDK names or configuration.

Reuse existing OpenTelemetry instrumentation where present. Otherwise,
install the SDK and supported automatic instrumentation described in the
guide. Initialize instrumentation at the point required by that SDK.
Use the guide's protocol, endpoint, and authentication format, reading
connection values from the environment. Do not hardcode or print secrets.

Preserve the application's existing behavior. Check for duplicate SDK
initialization, exporters, and logging handlers, including those installed
by automatic instrumentation. If logs are supported, check both the
application's logging level and the SDK's export level so the test log
is captured once. Use the language guide's settings for these checks.

Explain which signals are supported and any operations that need manual
instrumentation. Do not assume every SDK exports logs, metrics, traces,
or session replay.

Update the startup command and document the required environment variables.
Run the application's existing checks and a local startup check. Exercise
an instrumented operation with a unique test marker. If logs are supported,
emit one test log during that operation at an enabled severity. Allow time
for batched export or flush telemetry before shutting down.

When you have destination access, find the test events there and verify
the service name, marker, and absence of duplicates. If log-to-trace
correlation is supported, check that the test log references the operation's
trace and span. Distinguish local export, endpoint acceptance, and events
stored in ClickHouse Observability; startup or an HTTP success response
alone does not prove storage.

Summarize the changes, tests performed, and results. Clearly state which
checks you could not run and give me the remaining verification steps.
```

Los nombres de variables de este prompt indican dónde se almacenan los valores de su conexión. No sustituyen a las variables obligatorias del SDK: el asistente debe asignarlas a los ajustes documentados en la guía de su lenguaje. Para aplicaciones de navegador, utilice la [guía del SDK para navegador](/es/clickstack/observability/ingesting-data/sdks/browser), incluida su configuración de endpoint y clave específica para navegador.

## Revisar y ejecutar la aplicación {#review-and-run-the-application}

Revise los cambios en las dependencias, la inicialización y el inicio. Compruebe que el asistente haya seleccionado el destino y el formato de autenticación correctos, haya conservado la instrumentación existente y no haya incluido secretos en los archivos confirmados.

Ejecute las pruebas existentes de su aplicación y, a continuación, iníciela con el comando y el entorno actualizados. Realice una solicitud o una acción que ejercite una biblioteca instrumentada. Si necesita telemetría para una operación que la instrumentación automática no captura, pida al asistente que añada un span personalizado mediante la API de su SDK.

## Verificar la telemetría {#verify-telemetry}

1. Abra [Búsqueda](/es/clickstack/observability/features/search) en ClickHouse Observability.
2. Seleccione la fuente de logs o trazas correspondiente y un intervalo de tiempo que abarque su actividad de prueba.
3. Filtre por el nombre de su servicio e inspeccione los eventos generados. Compruebe que aparece la solicitud u operación esperada.
4. Si el SDK exporta métricas, use el [Explorador de Gráficos](/es/clickstack/observability/features/dashboards/overview#navigate-chart-explorer) para inspeccionarlas.

Que la aplicación se inicie correctamente no garantiza que la telemetría se esté entregando. Si faltan eventos, revise los errores del exportador de la aplicación, así como la configuración del endpoint, del protocolo y de la autenticación. En implementaciones autogestionadas, inspeccione también los logs del recolector.

Para ver un ejemplo completo de aplicación, siga la [demo de HackerNews Analyzer](/es/clickstack/observability/example-datasets/instrument-application).
