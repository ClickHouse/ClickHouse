Utilice el SDK de Python de ClickStack para enviar logs y trazas a ClickHouse Observability. El SDK es una distribución de OpenTelemetry publicada como `hyperdx-opentelemetry` que instrumenta automáticamente las bibliotecas y los frameworks de Python compatibles.

<ClickStackIntegrates signals={['logs', 'traces']} />

## Instalar el SDK {#install-the-sdk}

Instale el [SDK de Python de ClickStack](https://github.com/hyperdxio/hyperdx-py) en el entorno de Python de su aplicación:

```shell
pip install hyperdx-opentelemetry
opentelemetry-bootstrap -a install
```

El comando bootstrap instala la instrumentación correspondiente a las dependencias que tiene instaladas su aplicación. Ejecútelo después de instalar dichas dependencias.

## Configure el destino {#configure-destination}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta Beta" />

    Abra **Team Settings → Data → Managed Telemetry** en su servicio y copie el **endpoint HTTP de OTLP** y la **clave de API**. Utilice el endpoint HTTPS completo, incluido el puerto:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export HYPERDX_API_KEY='Bearer YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-python-app'
    ```
  </Tab>

  <Tab title="Autogestionado">
    Utilice el endpoint HTTP de OTLP de su recolector y la clave de ingestión. Use `http://` en lugar de `https://` si su recolector no tiene TLS configurado. Para configurar el recolector, consulte [Ingesta de datos con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#sending-otel-data-self-configured).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export HYPERDX_API_KEY='YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-python-app'
    ```
  </Tab>
</Tabs>

## Inicie su aplicación {#start-your-application}

Ejecute su aplicación con instrumentación automática:

```shell
export OTEL_LOG_LEVEL='warning'
export OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION='false'
opentelemetry-instrument python app.py
```

Reemplace `app.py` por el archivo de entrada de su aplicación.

`OTEL_LOG_LEVEL` define el nivel de registro del SDK. Asígnele el valor `warning` para capturar el mensaje de prueba que aparece a continuación, o `info` para incluir registros de aplicaciones de menor severidad. Si no se configura ningún nivel, el SDK usa `ERROR` de forma predeterminada.

El SDK de ClickStack ya instala un exportador de logs. Al establecer `OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION=false`, se evita que la instrumentación de registro de OpenTelemetry añada otro exportador y duplique los registros de log; el SDK sigue exportando los logs.

## Verificar la ingestión {#verify-ingestion}

Envíe solicitudes a su aplicación y emita un mensaje de log de Python con nivel `WARNING` o superior. En ClickHouse Observability, seleccione un intervalo de tiempo reciente y busque `my-python-app` (o el nombre del servicio que haya configurado) en los logs o las trazas.

## Configuración opcional {#optional-configuration}

Para capturar los encabezados y los cuerpos de las solicitudes HTTP, active la captura avanzada de red antes de iniciar su aplicación:

```shell
export HYPERDX_ENABLE_ADVANCED_NETWORK_CAPTURE=1
```

Los encabezados y los cuerpos de las solicitudes pueden contener datos confidenciales. Active la captura solo para los datos que realmente quiera recopilar.

## Resolución de problemas {#troubleshooting}

Si faltan logs, revise `OTEL_LOG_LEVEL` y los niveles del logger y del handler de su aplicación. Configúrelos para que capturen los mensajes con el nivel de severidad que espera.

Para resolver problemas de instrumentación y del exportador, consulte la [guía de resolución de problemas de OpenTelemetry para Python](https://opentelemetry.io/docs/zero-code/python/troubleshooting/).
