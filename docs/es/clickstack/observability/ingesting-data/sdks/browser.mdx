El SDK de navegador de ClickStack se basa en OpenTelemetry para recopilar las solicitudes y los errores del navegador, así como la reproducción de sesiones. Utilícelo para analizar los eventos del frontend junto con la telemetría de su backend en ClickHouse Observability.

<ClickStackIntegrates signals={['logs', 'traces']} />

## Instalación {#install}

Instale el paquete en su aplicación frontend:

```shell
npm install @clickhouse/clickstack-browser
```

El paquete utiliza módulos ES. npm instala automáticamente sus dependencias peer de OpenTelemetry. Si su aplicación también instala `@opentelemetry/api` directamente, use la versión `~1.9.1` y mantenga una sola copia; la versión 1.10 queda fuera del rango de versiones compatibles con este SDK.

## Configure su destino {#configure-destination}

<Tabs>
  <Tab title="Totalmente gestionado">
    <BetaBadge label="Oferta Beta" />

    Abra **Team Settings → Data → Managed Telemetry** en su servicio y copie el **OTLP HTTP endpoint** y la **API key**. Use el endpoint HTTPS completo, incluido el puerto, sin rutas de señal como `/v1/traces`.

    Inicialice el SDK en el módulo de entrada de su aplicación:

    ```javascript
    import { init } from '@clickhouse/clickstack-browser';

    init({
      endpoint: 'https://YOUR_OTEL_ENDPOINT:4318',
      apiKey: 'Bearer YOUR_INGESTION_API_KEY',
      serviceName: 'my-frontend-app',
    });
    ```
  </Tab>

  <Tab title="Autogestionado">
    Use el endpoint OTLP HTTP de su recolector y la clave de ingestión que tenga configurada. El endpoint debe ser accesible desde los navegadores de sus usuarios. Para configurar el recolector, consulte [Ingesta con OpenTelemetry](/es/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```javascript
    import { init } from '@clickhouse/clickstack-browser';

    init({
      endpoint: 'https://YOUR_COLLECTOR_HOST:4318',
      apiKey: 'YOUR_INGESTION_API_KEY',
      serviceName: 'my-frontend-app',
    });
    ```

    Use la clave configurada para el receiver OTLP de su recolector. El recolector debe permitir el origen de su aplicación en la configuración CORS de su receptor HTTP.
  </Tab>
</Tabs>

Llame a `init` una sola vez por carga de página, en el nivel superior de su módulo de entrada, como `src/main.ts` en Vite o `instrumentation-client.ts` en Next.js. La inicialización es asíncrona, por lo que es posible que no se capturen las solicitudes realizadas inmediatamente en el mismo tick. No inicialice el SDK dentro de un efecto de React: una función de limpieza que llame a `shutdown` detiene de forma permanente la telemetría durante esa carga de página.

<Note>
  La configuración del navegador, incluida la clave de ingestión, es visible para cualquiera que cargue la página. Para mantener la clave en su servidor, use un endpoint del mismo origen, como `/otel`, omita `apiKey` y configure su servidor para que reenvíe las solicitudes OTLP con la cabecera de autorización adecuada.
</Note>

## Verificar la ingestión {#verify-ingestion}

Cargue su aplicación, interactúe con la página, realice una solicitud y genere un error en la consola. En ClickHouse Observability, seleccione un intervalo de tiempo reciente y busque `my-frontend-app` en Logs o trazas. Abra reproducción de sesiones para examinar la sesión grabada.

Si faltan datos, revise la consola del navegador y las solicitudes de red a `/v1/traces` y `/v1/logs`. Compruebe el endpoint, la cabecera de autorización, CORS y la Content Security Policy (CSP). En implementaciones autogestionadas, confirme que su versión de ClickStack admite la reproducción de sesiones y el atributo estándar `session.id` del SDK. Recibir registros no garantiza por sí solo que las sesiones aparezcan en la interfaz de usuario.

## Opciones de inicialización {#initialization-options}

Pase estas opciones a `init`. Use `endpoint` para un recolector compartido, o indique ambos endpoints de señal cuando las trazas y los logs tengan destinos distintos.

| Opción               | Valor predeterminado                                         | Propósito                                                                                                                                                                |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `endpoint`           | Obligatorio salvo que se configuren ambos endpoints de señal | URL base de OTLP HTTP o ruta de proxy del mismo origen; el SDK añade las rutas de cada señal                                                                             |
| `tracesEndpoint`     | Sin definir                                                  | URL completa de trazas, que se usa tal cual en lugar de la URL derivada de `endpoint`                                                                                    |
| `logsEndpoint`       | Sin definir                                                  | URL completa de logs y de reproducción, que se usa tal cual en lugar de la URL derivada de `endpoint`                                                                    |
| `serviceName`        | Obligatorio                                                  | Establece `service.name` en toda la telemetría                                                                                                                           |
| `apiKey`             | Sin definir                                                  | Valor del encabezado `authorization`; use el formato correspondiente a su destino, indicado más arriba                                                                   |
| `traceOrigins`       | Sin definir                                                  | Orígenes del backend o expresiones regulares que reciben el contexto de traza                                                                                            |
| `replay`             | `true`                                                       | Graba la reproducción de sesiones; con `false` se conserva la telemetría del navegador, pero se desactiva la reproducción                                                |
| `resourceAttributes` | Sin definir                                                  | Atributos del recurso adicionales, también aplicados a la reproducción; `serviceName`, `serviceVersion` y `environment` tienen precedencia sobre las claves coincidentes |
| `maskAllText`        | `true`                                                       | Enmascara el texto en la reproducción                                                                                                                                    |
| `maskAllInputs`      | `true`                                                       | Enmascara los valores de input, textarea y select                                                                                                                        |
| `console`            | `'error'`                                                    | Captura `'error'`, `'warn'`, `'info'` (incluido `console.log`) o `'debug'`, junto con los niveles más graves; use `false` para desactivarlo                              |
| `serviceVersion`     | Sin definir                                                  | Identifica la versión de su aplicación                                                                                                                                   |
| `environment`        | Sin definir                                                  | Establece `deployment.environment.name`                                                                                                                                  |
| `sanitizeUrl`        | Sin definir                                                  | Reescribe las URL registradas, por ejemplo, para eliminar parámetros de consulta                                                                                         |

Para consultar la API completa, vea la [referencia del SDK para navegadores](https://github.com/ClickHouse/clickstack-browser#quick-start).

## Reproducción de sesiones y privacidad {#session-replay-and-privacy}

La reproducción de sesiones está habilitada de forma predeterminada. El texto y los valores de entrada se enmascaran también de forma predeterminada.

El enmascaramiento no oculta el estado de las casillas de verificación ni de los botones de opción, ni atributos como las URL de los enlaces o los marcadores de posición. Use la clase `rr-block` para excluir elementos sensibles. La sanitización de URL no se aplica a las URL que aparecen en el contenido reproducido de la página, en las trazas de pila ni en los mensajes de la consola. Capture únicamente la información de usuario que permita su política de privacidad.

Para pausar la reproducción sin detener la telemetría del navegador:

```javascript
import { pauseReplay } from '@clickhouse/clickstack-browser';

pauseReplay();
```

Cuando quiera reanudar la grabación:

```javascript
import { resumeReplay } from '@clickhouse/clickstack-browser';

resumeReplay();
```

## Vincular las trazas del frontend y del backend {#trace-propagation}

Para vincular las solicitudes del navegador con las trazas del backend, añada `traceOrigins` a las opciones de `init` y sustituya el valor de ejemplo por el origen de su backend:

```javascript
traceOrigins: ['https://api.example.com'],
```

Las solicitudes al propio origen de la página y a los backends coincidentes incluyen `traceparent`, `tracestate` y `baggage`. Su backend debe estar instrumentado para dar continuidad a ese contexto.

Los backends de origen cruzado deben permitir el paso de estos encabezados mediante CORS. El recolector de telemetría también debe aceptar el origen del frontend. Si su aplicación utiliza Content Security Policy (CSP), permita el endpoint del recolector en `connect-src`.

## Identificar usuarios y registrar errores {#users-and-errors}

Al iniciar sesión, use `setUser` para asociar la información del usuario a los spans y logs posteriores:

```javascript
import { setUser } from '@clickhouse/clickstack-browser';

setUser({ id: 'user-123', email: 'user@example.com' });
```

Al cerrar sesión, borre la información del usuario e inicie una nueva sesión:

```javascript
import { setUser, startNewSession } from '@clickhouse/clickstack-browser';

setUser(null);
startNewSession();
```

Para asociar metadata de la aplicación a los spans y logs posteriores, utilice `setAttributes`. Cada llamada reemplaza el conjunto anterior; pase `null` para borrarlo:

```javascript
import { setAttributes } from '@clickhouse/clickstack-browser';

setAttributes({ 'app.team.name': 'checkout' });
```

Los errores no capturados y los rechazos no gestionados (unhandled rejections) se capturan automáticamente. Los límites de error (error boundaries) de React que notifican mediante `console.error` también se capturan de forma predeterminada. Use `recordException` para los errores capturados que aún no se hayan registrado; si un mismo error se registra con `recordException` y también mediante logging, se generan eventos duplicados:

```javascript
import { recordException } from '@clickhouse/clickstack-browser';

try {
  await submitCheckout();
} catch (error) {
  recordException(error, { 'app.operation': 'checkout' });
  // Handle the error in your application.
}
```

Reemplace `submitCheckout` por la operación de la aplicación que desee supervisar.

## Migración desde el SDK para navegador de HyperDX {#migration}

No basta con cambiar el nombre del paquete. `url` pasa a ser `endpoint`, `service` pasa a ser `serviceName` y `tracePropagationTargets` pasa a ser `traceOrigins`. El enmascaramiento de texto y de campos de entrada ahora tiene `true` como valor predeterminado. Reemplace `setGlobalAttributes` por `setUser` para la identity del usuario y por `setAttributes` para los metadata de la aplicación. Los límites de error de React que notifican errores mediante `console.error` no necesitan ningún hook adicional; use `recordException` cuando un error no se haya registrado previamente.

Consulte la [guía de migración del SDK](https://github.com/ClickHouse/clickstack-browser/blob/main/docs/migration.md) para conocer las opciones eliminadas y los cambios en los atributos. Si realiza la instalación mediante una etiqueta script o su aplicación ya inicializa OpenTelemetry, consulte el [README del SDK](https://github.com/ClickHouse/clickstack-browser#readme).

Si el SDK de navegador de ClickStack provoca un problema de compatibilidad en su aplicación, puede usar el [SDK para navegador heredado de HyperDX](https://github.com/hyperdxio/hyperdx-js/tree/main/packages/browser) mientras lo investiga. Restaure su configuración y sus llamadas a la API siguiendo la guía de migración anterior. Ambos SDK no son intercambiables y no deben ejecutarse a la vez.
