    Envíe logs, métricas y trazas a ClickHouse Observability mediante los SDK de OpenTelemetry o un recolector en su entorno. El servicio incluye un recolector de ingestión gestionado que recibe la telemetría a través de OTLP y la escribe en ClickHouse Cloud.

## Obtener los datos de conexión {#sending-otel-data}

    Abra su servicio y vaya a **Configuración del equipo → Datos → Managed Telemetry**. Copie el **endpoint OTLP HTTP** y la **clave de API**. Las pestañas **Variables de entorno** y **Configuración del recolector** ofrecen la configuración correspondiente a su servicio.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry con el endpoint OTLP HTTP y la clave de API enmascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Utilice el endpoint HTTPS completo, incluido el puerto que se muestra en Managed Telemetry. Si usa un endpoint OTLP HTTP base, omita las rutas específicas de cada señal, como `/v1/logs`, `/v1/traces` y `/v1/metrics`; los exportadores añaden estas rutas automáticamente.

## Envío directo desde una aplicación {#sending-data-to-collector-managed}

    Instale e inicialice la instrumentación de OpenTelemetry y un exportador OTLP HTTP para el lenguaje de su aplicación. En los SDK que admiten configuración mediante variables de entorno, defina estos valores en el entorno de la aplicación antes de iniciarla:

    ```shell
    export OTEL_SERVICE_NAME='my-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    Reemplace el endpoint por el valor exacto que aparece en Managed Telemetry y `YOUR_API_KEY` por la clave de API de su servicio. El `%20` codifica el espacio entre `Bearer` y la clave en la variable de entorno del encabezado.

    La compatibilidad con variables de entorno varía según el SDK. Si su SDK requiere que la configuración se realice en el código, indique el mismo punto de conexión HTTPS, el protocolo OTLP HTTP y un encabezado `authorization` con el valor `Bearer YOUR_API_KEY`. Consulte la [referencia de configuración del exportador de OpenTelemetry](https://opentelemetry.io/docs/languages/sdk-configuration/otlp-exporter/) para conocer la compatibilidad de cada lenguaje y las sobrescrituras específicas de cada señal.

    Estos ajustes solo configuran la exportación: su aplicación sigue necesitando instrumentación para generar telemetría. Para las grabaciones de sesiones del navegador, consulte la [guía de reproducción de sesiones](/es/clickstack/observability/features/session-replay).

## Reenviar datos desde un recolector {#forward-from-a-collector}

    Si ya recopila telemetría con un recolector de OpenTelemetry, configure un exportador OTLP HTTP para reenviarla al endpoint gestionado. Mantenga sus receptores y procesadores actuales para recopilar y procesar los datos.

    Defina las siguientes variables de entorno en el entorno de ejecución del recolector:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_API_KEY='YOUR_API_KEY'
    ```

    Reemplace ambos marcadores de posición por los valores de Managed Telemetry. Añada este exportador a la configuración del recopilador:

    ```yaml
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "Bearer ${env:OTEL_EXPORTER_OTLP_API_KEY}"
    ```

    Añada `otlp_http/observability` a la lista `exporters` de cada canalización de logs, métricas o trazas que desee reenviar en `service.pipelines`. Incorpórelo a su configuración existente y, a continuación, reinicie o vuelva a desplegar el recolector para aplicar los cambios.

    El ejemplo utiliza el nombre actual del exportador, `otlp_http`. Las versiones anteriores del recolector pueden usar `otlphttp`; utilice el nombre compatible con su distribución. Consulte la [documentación del exportador OTLP HTTP](https://github.com/open-telemetry/opentelemetry-collector/tree/main/exporter/otlphttpexporter) para conocer las opciones de configuración.

    Para ver un ejemplo completo que recopila registros del host y métricas, consulte [Registros y métricas del sistema local](/es/clickstack/observability/example-datasets/local-data).

## Verificar la ingestión {#verify-ingestion}

    Genere telemetría en su aplicación y, a continuación, abra [Búsqueda](/es/clickstack/observability/features/search) en ClickHouse Observability. Seleccione **Logs** o **Traces**, elija un intervalo de tiempo que incluya los nuevos eventos y busque el nombre de su servicio.

    Si los datos no aparecen, revise los logs de su SDK o del recolector en busca de errores de exportación. Verifique el endpoint, el encabezado de autenticación y el protocolo, y confirme que la aplicación o el recolector pueden acceder al endpoint gestionado. Compruebe también si hay ajustes del exportador específicos de cada señal que sobrescriban el endpoint base o los encabezados.

    Puede usar **Send a Test Log** en Managed Telemetry para enviar un log de muestra al servicio. Verifique por separado la telemetría de su aplicación para confirmar que su instrumentación y su configuración de exportación son correctas.

Para administrar los recolectores de forma centralizada, [Bindplane](/es/clickstack/observability/integration-partners/bindplane) ofrece un destino de ClickHouse Observability y herramientas para recopilar, procesar y enrutar telemetría.

## Envío de datos de OpenTelemetry {#sending-otel-data-self-configured}

### Conexión del recolector a ClickHouse Cloud {#installing-otel-collector-managed-self-configured}

    Configure su recolector con el [rol de puerta de enlace](/es/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) para que reciba OTLP a través de HTTP o gRPC y lo reenvíe a ClickHouse Cloud.

    <Info>
      **Recomendamos usar el recopilador de OpenTelemetry de ClickStack**

      La distribución de ClickStack ofrece procesamiento y esquemas compatibles con ClickHouse Observability. El esquema predeterminado habilita la detección automática de fuentes y correspondencias de columnas preconfiguradas.
    </Info>

    En ClickHouse Cloud, abra su servicio y [obtenga sus datos de conexión](/es/products/cloud/guides/sql-console/connection-details). Configure estas variables de entorno en el entorno de ejecución de la distribución ClickStack del recolector:

    ```shell
    CLICKHOUSE_ENDPOINT="https://<host>:8443"
    CLICKHOUSE_USER="<ingestion-user>"
    CLICKHOUSE_PASSWORD="<ingestion-password>"
    ```

    Use el endpoint HTTPS de la base de datos de su servicio como valor de `CLICKHOUSE_ENDPOINT`, junto con las credenciales de un [usuario de ingestión dedicado](/es/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured). Reinicie o vuelva a desplegar el recolector para aplicar la configuración. El recolector recibe la telemetría a través de OTLP y la escribe en su servicio de ClickHouse Cloud.

    Si utiliza otra distribución del recolector, configure su exportador de ClickHouse con el mismo endpoint y las mismas credenciales. Consulte [Modificar la configuración](/es/clickstack/self-configured/ingesting-data/collector#modifying-otel-collector-configuration-managed-self-configured) para ver un ejemplo.

    Para obtener instrucciones de instalación, consulte [Implementación del recolector](/es/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured). Antes de enviar tráfico de producción, [proteja el recolector](/es/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured). Si activa `OTLP_AUTH_TOKEN`, configure sus SDK y los recolectores de reenvío para que envíen ese token en el encabezado `authorization`.

### Envío de datos al recolector {#sending-data-to-collector-managed-self-configured}

    Si el recolector se ejecuta localmente con los puertos OTLP predeterminados, dirija la instrumentación de OpenTelemetry a los puntos de conexión que se indican a continuación. Si sus aplicaciones o agentes se ejecutan en otro host o en otro contenedor, reemplace `localhost` por el nombre del host del recolector que sea accesible desde ese entorno:

    * **HTTP (OTLP):** `http://localhost:4318`
    * **gRPC (OTLP):** `localhost:4317`

    Para los [SDK de lenguaje](/es/clickstack/observability/ingesting-data/sdks) que admiten configuración mediante variables de entorno, establezca el endpoint y el protocolo antes de iniciar su aplicación instrumentada:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    ```

    Si el recolector requiere autenticación, defina también `OTEL_EXPORTER_OTLP_HEADERS="authorization=<collector-token>"` y sustituya `<collector-token>` por el valor de su `OTLP_AUTH_TOKEN`. No añada el prefijo `Bearer` que usan los puntos de conexión totalmente gestionados. Estos ajustes solo configuran la exportación; la aplicación sigue necesitando instrumentación para generar telemetría.

    Un agente que utilice la [distribución contrib del OTel collector](https://github.com/open-telemetry/opentelemetry-collector-contrib) puede reenviar logs mediante OTLP. El siguiente ejemplo lee este [archivo de registro estructurado](https://datasets-documentation.s3.eu-west-3.amazonaws.com/http_logs/access-structured.log.gz). Descárguelo y descomprímalo en la ruta indicada en `include` antes de iniciar el agente. Si su puerta de enlace requiere autenticación, añada al exportador del agente un encabezado `authorization` con el token de dicha puerta de enlace.

    ```yaml
    # clickhouse-agent-config.yaml
    receivers:
      filelog:
        include:
          - /opt/data/logs/access-structured.log
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.time_local
              layout: '%Y-%m-%d %H:%M:%S'
    exporters:
      # HTTP setup
      otlphttp/hdx:
        endpoint: 'http://localhost:4318'
        compression: gzip

      # gRPC setup (alternative)
      otlp/hdx:
        endpoint: 'localhost:4317'
        compression: gzip
    processors:
      batch:
        timeout: 5s
        send_batch_size: 10000
    service:
      telemetry:
        metrics:
          address: 0.0.0.0:9888 # Modified as 2 collectors running on same host
      pipelines:
        logs:
          receivers: [filelog]
          processors: [batch]
          exporters: [otlphttp/hdx]
    ```
