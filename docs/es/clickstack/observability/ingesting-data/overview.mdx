    ClickHouse Observability incluye un **recolector de OpenTelemetry (OTel) gestionado** que recibe logs, métricas, trazas y datos de reproducción de sesiones, y los escribe en ClickHouse Cloud. ClickHouse Cloud se encarga de operar el recolector de ingestión, la base de datos y la UI de ClickStack. Usted instrumenta sus aplicaciones y las configura, o configura sus agentes de recopilación de datos, para que envíen telemetría al servicio gestionado.

## Obtener los datos de conexión {#connection-details}

    En su servicio, abra **Team Settings → Data** y busque **Managed Telemetry**. Esta sección proporciona el endpoint OTLP y la clave de API necesarios para enviar telemetría a su servicio.

    Seleccione **URL**, **Collector config** o **Env vars** para ver los datos de conexión en el formato que necesite y, a continuación, use **Copy connection details**. Configure su SDK o recolector con el endpoint y los parámetros de autenticación proporcionados.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry con el endpoint OTLP HTTP y la clave de API enmascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)

    Consulte [Managed Telemetry](/es/clickstack/observability/managing/config#managed-telemetry) para obtener más información. Puede usar **Send a Test Log** para enviar un log de ejemplo al servicio.

## Elegir cómo enviar la telemetría {#sending-telemetry}

### Instrumentación de aplicaciones {#application-instrumentation}

    Los SDK de cada lenguaje recopilan telemetría desde dentro de sus aplicaciones, como trazas de solicitudes y registros de aplicaciones. Configure su SDK para exportar la telemetría mediante OTLP al endpoint gestionado o a un recolector de su entorno que la reenvíe al servicio.

    Puede usar la instrumentación de OpenTelemetry que ya tenga. Los SDK de ClickStack también ofrecen funcionalidades como la reproducción de sesiones en el navegador; consulte [Reproducción de sesiones](/es/clickstack/observability/features/session-replay) para ver un ejemplo de configuración gestionada.

### Infraestructura y agentes de recopilación {#collection-agents}

    Ejecute agentes de recopilación en su entorno para recopilar telemetría como métricas de host, logs de contenedores y eventos de Kubernetes. Un recolector de OpenTelemetry puede ejecutarse junto a una aplicación, en un host o como un DaemonSet de Kubernetes, según lo que necesite recopilar.

    Configure estos agentes para que reenvíen la telemetría al endpoint OTLP gestionado con los datos de conexión de su servicio. También puede enrutar la telemetría de las aplicaciones a través de estos recolectores para procesarla antes de que llegue a ClickHouse Observability.

## Verificar la ingestión {#verify-ingestion}

    Después de configurar su aplicación o recolector, genere algo de telemetría y abra [Búsqueda](/es/clickstack/observability/features/search). Seleccione la fuente **Logs** o **Traces**, elija un intervalo de tiempo que incluya los nuevos eventos y busque el nombre de su servicio para confirmar que los datos han llegado.

  <Tab title="Autogestionado">
    Todos los datos se ingestan en Self-managed ClickHouse Observability mediante un **OpenTelemetry (OTel) collector**, que actúa como punto de entrada principal para logs, métricas, trazas y datos de sesión.

    Usted ejecuta un Colector de OpenTelemetry para recibir datos de telemetría de sus aplicaciones. Con Self-managed ClickHouse Observability, ClickHouse y la interfaz de usuario se alojan y gestionan en ClickHouse Cloud, y el servicio se encarga de la autenticación integrada y de la gestión operativa.

    <div className="ch-image-lg">
      <Frame>
        ![Telemetría OTLP que fluye a través de un recolector autogestionado hacia ClickHouse, con la UI de ClickStack alojada en ClickHouse Cloud](/images/use-cases/observability/clickstack-self-managed-architecture.svg)
      </Frame>
    </div>

    El recolector expone dos endpoints OTLP:

    * **HTTP**: puerto `4318`
    * **gRPC**: puerto `4317`

    Puede enviar datos a estos puntos de conexión directamente desde los [SDK de lenguaje](/es/clickstack/observability/ingesting-data/sdks) o desde agentes de recopilación de datos compatibles con OTel, como otros OTel collectors que recopilen métricas y logs de infraestructura.

    En concreto:

    * Los [**SDK de lenguaje**](/es/clickstack/observability/ingesting-data/sdks) se encargan de recopilar telemetría desde dentro de su aplicación (sobre todo **trazas** y **logs**) y de exportar estos datos, a través del endpoint OTLP, al recolector de OpenTelemetry, que gestiona la ingestión en ClickHouse. Para obtener más información sobre los SDK de lenguaje disponibles, consulte [SDKs](/es/clickstack/observability/ingesting-data/sdks).

    * Los **agentes de recopilación de datos** son agentes desplegados en el edge: en servidores, en nodos de Kubernetes o junto a las aplicaciones. Recopilan telemetría de infraestructura (por ejemplo, logs y métricas) o reciben eventos directamente de aplicaciones instrumentadas con SDK. En este caso, el agente se ejecuta en el mismo host que la aplicación, a menudo como sidecar o DaemonSet. Estos agentes reenvían los datos al colector OTel de ClickStack central, que actúa como [puerta de enlace](/es/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) y que normalmente se despliega una vez por clúster, centro de datos o región. La [puerta de enlace](/es/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) recibe eventos OTLP de agentes o aplicaciones y gestiona la ingestión en ClickHouse. Consulte [OTel collector](/es/clickstack/self-configured/ingesting-data/collector) para obtener más información. Estos agentes pueden ser otras instancias del OTel collector o tecnologías alternativas como [Fluentd](https://www.fluentd.org/) o [Vector](https://vector.dev/).

    <Info>
      **Compatibilidad con OpenTelemetry**

      Aunque ClickStack ofrece sus propios SDK de lenguaje y un recolector de OpenTelemetry personalizado, con telemetría y funcionalidades mejoradas, también puede utilizar sin problemas sus SDK de OpenTelemetry y agentes existentes.
    </Info>
