ClickHouse Observability le permite realizar búsquedas de texto completo en sus eventos (logs y trazas). Para empezar a buscar, basta con escribir palabras clave que coincidan con sus eventos. Por ejemplo, si su log contiene &quot;Error&quot;, puede encontrarlo simplemente escribiendo &quot;Error&quot; en la barra de búsqueda.

Esta misma sintaxis de búsqueda se utiliza para filtrar eventos en dashboards y gráficos.

## Funcionalidades de búsqueda {#search-features}

### Sintaxis de búsqueda de Lucene {#natural-language-syntax}

* Las búsquedas no distinguen entre mayúsculas y minúsculas
* De forma predeterminada, las búsquedas coinciden con palabras completas (p. ej., `Error` coincidirá con `Error here`
  pero no con `Errors here`). Puede rodear una palabra con comodines para que coincida con palabras
  parciales (p. ej., `*Error*` coincidirá con `AnyError` y `AnyErrors`)
* Los términos de búsqueda se buscan en cualquier orden (p. ej., `Hello World` coincidirá con los logs que
  contengan `Hello World` y `World Hello`)
* Puede excluir palabras clave con `NOT` o `-` (p. ej., `Error NOT Exception` o
  `Error -Exception`)
* Puede usar `AND` y `OR` para combinar varias palabras clave (p. ej.,
  `Error OR Exception`)
* Para buscar coincidencias exactas, use comillas dobles (p. ej., `"Error tests not found"`)

#### Búsqueda por columna/propiedad {#column-search}

* Puede buscar en columnas y propiedades de JSON/mapa mediante `column:value` (p. ej., `SeverityText:error`,
  `ServiceName:app`)
* Puede buscar un rango de valores mediante operadores de comparación (`>`, `<`,
  `>=`, `<=`) (p. ej., `Duration:>1000`)
* Puede comprobar si existe una propiedad mediante `property:*` (p. ej.,
  `Duration:*`)

### Entrada de tiempo {#time-input}

* La entrada de tiempo acepta expresiones en lenguaje natural (p. ej., `1 hour ago`, `yesterday`,
  `last week`).
* Si se especifica un único momento dado, la búsqueda abarcará desde ese momento
  hasta ahora.
* Al realizar la búsqueda, el intervalo de tiempo siempre se convierte en el intervalo de tiempo analizado para
  facilitar la depuración de las consultas temporales.
* También puede seleccionar una barra del histograma para ampliar un intervalo de tiempo específico.

### Sintaxis de búsqueda SQL {#sql-syntax}

Opcionalmente, puede cambiar los campos de búsqueda al modo SQL. En este modo se acepta cualquier
cláusula `WHERE` válida para realizar búsquedas. Resulta útil para consultas complejas que no se pueden
expresar con la sintaxis de Lucene.

### Sentencia SELECT {#select-statement}

Para especificar las columnas que se muestran en los resultados de búsqueda, puede usar la entrada `SELECT`.
Se trata de una expresión SQL `SELECT` que indica las columnas que se seleccionarán en la página de búsqueda.
Por el momento no se admiten alias (p. ej., no puede usar `column as "alias"`).

## Búsquedas guardadas {#saved-searches}

Puede guardar sus búsquedas para acceder a ellas rápidamente más adelante. Una vez guardadas, aparecerán en la página `Saved Searches`, lo que facilita volver a las consultas de búsqueda que utiliza con frecuencia sin tener que reconstruirlas.

### Añadir alertas a búsquedas guardadas {#alerts-on-saved-searches}

Las búsquedas guardadas pueden supervisarse mediante alertas que le notifiquen cuando se cumplan determinadas condiciones. Puede configurar alertas que se disparen cuando el número de eventos que coinciden con su búsqueda guardada supere un umbral determinado o quede por debajo de él.

Para obtener más información sobre cómo crear y configurar alertas, consulte la [documentación de alertas](/es/clickstack/observability/features/alerts).
