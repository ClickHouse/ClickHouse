ClickHouse Observability admite visualizaciones basadas en consultas de SQL directo. Esto le ofrece un control total sobre la lógica de la consulta, sin renunciar a la integración con los rangos de tiempo, los filtros y la generación de gráficos a nivel de panel de control.

Las visualizaciones basadas en SQL resultan útiles cuando necesita ir más allá del Explorador de Gráficos integrado; por ejemplo, para unir tablas o crear agregaciones complejas que el creador de gráficos no admite.

## Creación de una visualización basada en SQL {#creating-a-raw-sql-chart}

Para crear una visualización basada en SQL, abra el editor de un bloque del panel de control y seleccione **SQL**.

<div className="ch-image-lg">
  <Frame>
    ![Editor de visualizaciones SQL con instrucciones de consulta y macros](/images/clickstack/observability-sql-editor.png)
  </Frame>
</div>

A continuación:

1. Seleccione la **Conexión** en la que se ejecutará la consulta.
2. Opcionalmente, seleccione una **Fuente**, lo que permite aplicar a su gráfico los filtros a nivel de panel de control mediante la macro `$__filters` y que la consulta utilice `$__sourceTable`.
3. Escriba su consulta SQL en el editor y utilice parámetros de consulta y macros para integrarla con el intervalo de tiempo, los filtros y las variables del panel de control.
4. Haga clic en **Ejecutar** para previsualizar los resultados y, después, en **Guardar** para guardar la visualización.

La conexión y la fuente también pueden ser una [variable de conexión o variable de origen de datos](/es/clickstack/observability/features/dashboards/overview#source-connection-variables), de modo que sea el usuario que visualiza el panel de control quien elija la conexión o la fuente que consulta el bloque.

## Parámetros de consulta {#query-parameters}

Los [parámetros de consulta](/es/reference/syntax#defining-and-using-query-parameters) permiten que sus consultas SQL hagan referencia al intervalo de tiempo y a la granularidad actuales del panel de control. Emplean la sintaxis de consultas parametrizadas de ClickHouse: `{paramName:Type}`.

### Parámetros disponibles {#available-parameters}

Los parámetros disponibles dependen del tipo de gráfico:

**Gráficos de serie temporal (incluidas las barras apiladas):**

| Parámetro                       | Tipo  | Descripción                                                                |
| ------------------------------- | ----- | -------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Inicio del rango de fechas del panel de control (milisegundos desde epoch) |
| `{endDateMilliseconds:Int64}`   | Int64 | Fin del rango de fechas del panel de control (milisegundos desde epoch)    |
| `{intervalSeconds:Int64}`       | Int64 | Tamaño del intervalo de tiempo en segundos (según la granularidad)         |
| `{intervalMilliseconds:Int64}`  | Int64 | Tamaño del intervalo de tiempo en milisegundos (según la granularidad)     |

**Gráficos de tabla, circulares y numéricos:**

| Parámetro                       | Tipo  | Descripción                                                                |
| ------------------------------- | ----- | -------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Inicio del rango de fechas del panel de control (milisegundos desde epoch) |
| `{endDateMilliseconds:Int64}`   | Int64 | Fin del rango de fechas del panel de control (milisegundos desde epoch)    |

## Macros {#macros}

Las macros son atajos que se expanden en expresiones habituales de SQL de ClickHouse. Llevan el prefijo `$__` y se reemplazan antes de que la consulta se envíe a ClickHouse.

### Macros de límites temporales {#time-boundary-macros}

Estas macros devuelven una expresión de ClickHouse que representa la hora de inicio o de finalización del panel de control. No reciben argumentos.

| Macro            | Se expande a                                                          | Tipo de columna |
| ---------------- | --------------------------------------------------------------------- | --------------- |
| `$__fromTime`    | `toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))` | DateTime        |
| `$__toTime`      | `toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))`   | DateTime        |
| `$__fromTime_ms` | `fromUnixTimestamp64Milli({startDateMilliseconds:Int64})`             | DateTime64      |
| `$__toTime_ms`   | `fromUnixTimestamp64Milli({endDateMilliseconds:Int64})`               | DateTime64      |
| `$__interval_s`  | `{intervalSeconds:Int64}`                                             | Int64           |

### Macros de filtro de tiempo {#time-filter-macros}

Estas macros generan un fragmento de cláusula `WHERE` que filtra una columna según el intervalo de tiempo del panel de control.

| Macro                                 | Descripción                                                                                             |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `$__timeFilter(column)`               | Filtra una columna `DateTime` según el intervalo del panel de control                                   |
| `$__timeFilter_ms(column)`            | Filtra una columna `DateTime64` (con precisión de milisegundos) según el intervalo del panel de control |
| `$__dateFilter(column)`               | Filtra una columna `Date` según el intervalo del panel de control                                       |
| `$__dateTimeFilter(dateCol, timeCol)` | Filtra mediante columnas `Date` y `DateTime` independientes                                             |
| `$__dt(dateCol, timeCol)`             | Alias de `$__dateTimeFilter`                                                                            |

**Ejemplo de expansión** de `$__timeFilter(TimestampTime)`:

```sql
TimestampTime >= toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
AND TimestampTime <= toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
```

### Macros de intervalo de tiempo {#time-interval-macros}

Estas macros agrupan una columna de marca de tiempo en intervalos que se ajustan a la granularidad del panel de control. Normalmente se usan en las cláusulas `SELECT` y `GROUP BY` de los gráficos de series temporales. Estas macros solo están disponibles para visualizaciones de tipo **serie temporal**, incluidas las barras apiladas.

| Macro                        | Descripción                                                             |
| ---------------------------- | ----------------------------------------------------------------------- |
| `$__timeInterval(column)`    | Agrupa una columna `DateTime` en intervalos de `intervalSeconds`        |
| `$__timeInterval_ms(column)` | Agrupa una columna `DateTime64` en intervalos de `intervalMilliseconds` |

**Ejemplo de expansión** de `$__timeInterval(TimestampTime)`:

```sql
toStartOfInterval(toDateTime(TimestampTime), INTERVAL {intervalSeconds:Int64} second)
```

### Macro de filtro del panel de control {#dashboard-filter-macro}

| Macro            | Descripción                                                                                                                                                                                                                                                                                         |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filters`     | Se reemplaza por las condiciones de filtrado del panel de control (requiere seleccionar una fuente)                                                                                                                                                                                                 |
| `$__sourceTable` | Se reemplaza por la tabla de la fuente seleccionada, con su nombre completo, como `default.otel_logs`. Para fuentes de métricas, use `$__sourceTable(<metric type>)`, donde el tipo de métrica es `gauge`, `histogram`, `sum`, `summary` o `exponential histogram`. Requiere seleccionar una fuente |

Cuando se selecciona una **fuente** en el gráfico y hay filtros del panel de control activos, `$__filters` se expande a las condiciones `WHERE` de SQL correspondientes. Si no hay ninguna fuente seleccionada o no se aplica ningún filtro, se expande a `(1=1)`, por lo que siempre puede incluirse de forma segura en una cláusula `WHERE`.

`$__filters` aplica las selecciones de los filtros de valores de expresiones SQL que tienen habilitada la opción **Broadcast filter condition**, así como las condiciones de los [filtros ad hoc](/es/clickstack/observability/features/dashboards/overview#adhoc-filters) que se aplican a la fuente del bloque. Los filtros expuestos como variables se referencian de forma explícita, como se describe a continuación.

### Macros de variables de panel de control {#dashboard-variables}

Cuando un filtro de panel de control está [disponible como variable](/es/clickstack/observability/features/dashboards/overview#dashboard-variables) (un filtro de valores de expresión SQL con **Available as variable** habilitado, o cualquier filtro de valores estáticos, de valores de consulta SQL o de valores de etiquetas de PromQL), sus valores seleccionados pueden referenciarse en cualquier parte de la consulta. Estas macros solo están disponibles en los bloques de un panel de control que declare al menos una variable.

| Macro                                         | Descripción                                                                                                                               |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | Se expande a `toString(<filter expression>) IN ($variable)` cuando hay valores seleccionados para `variable` y a `1=1` en caso contrario. |
| `$__filter(<expression>, $<variable>)`        | Se expande a `<expression> IN ($variable)` cuando hay valores seleccionados para `variable` y a `1=1` en caso contrario.                  |
| `$__conditionalAll(<condition>, $<variable>)` | Se expande a `<condition>` cuando la variable tiene una selección y a `1=1` en caso contrario.                                            |

Los valores de una variable también pueden interpolarse directamente como `$name` o `${name}`, con un formato opcional: `${name:sqlstring}` (el predeterminado), `${name:csv}` o `${name:regex}`. Con el formato predeterminado, una referencia directa se renderiza como `NULL` mientras no haya nada seleccionado, por lo que conviene usar las macros anteriores siempre que se espere un predicado.

## Cómo se representan gráficamente los resultados de la consulta {#how-results-are-plotted}

La interfaz de usuario asigna automáticamente las columnas del resultado a los elementos del gráfico en función de los tipos de columnas. Las reglas de correspondencia varían según el tipo de gráfico.

### Gráficos de series temporales {#line-and-stacked-bar-charts}

| Rol                   | Tipo de columna                     | Descripción                                                                                          |
| --------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Marca de tiempo**   | Primera columna `Date` o `DateTime` | Se usa como eje x.                                                                                   |
| **Valor de la serie** | Todas las columnas numéricas        | Cada columna numérica se representa como una serie independiente. Normalmente son valores agregados. |
| **Nombres de grupo**  | Columnas `String`, `Map` o `Array`  | Opcional. Las filas con distintos valores de grupo se representan como series independientes.        |

### Gráfico circular {#pie-chart}

| Rol                     | Tipo de columna                    | Descripción                                                          |
| ----------------------- | ---------------------------------- | -------------------------------------------------------------------- |
| **Valor del sector**    | Primera columna numérica           | Determina el tamaño de cada sector.                                  |
| **Etiqueta del sector** | Columnas `String`, `Map` o `Array` | Opcional. Cada valor único se convierte en la etiqueta de un sector. |

### Gráfico numérico {#number-chart}

| Rol        | Tipo de columna          | Descripción                                                            |
| ---------- | ------------------------ | ---------------------------------------------------------------------- |
| **Número** | Primera columna numérica | Se muestra el valor de la primera fila de la primera columna numérica. |

### Gráfico de tabla {#table-chart}

Todas las columnas del resultado se muestran directamente como columnas de la tabla.

## Ejemplos {#examples}

<Info>
  **Nombres de tablas de ejemplo**

  Los ejemplos usan `otel_logs` y `otel_traces`. Adapte los nombres de tablas y de columnas a sus datos. Si ejecuta los ejemplos en [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com), utilice `otel_v2.otel_logs` u `otel_v2.otel_traces`.
</Info>

### Gráfico de serie temporal — recuento de logs a lo largo del tiempo por servicio {#example-line-chart}

Esta consulta cuenta los eventos de log por servicio, agrupados en intervalos de tiempo que se ajustan a la granularidad del panel de control.

```sql
SELECT
  toStartOfInterval(TimestampTime, INTERVAL {intervalSeconds:Int64} second) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

* `ts` (`DateTime`) se utiliza como marca de tiempo del eje x.
* `count` (numérico) se representa como el valor de la serie.
* `ServiceName` (cadena) genera una línea independiente para cada servicio.

### Gráfico de series temporales: uso de macros {#example-line-chart-macros}

La misma consulta, escrita con macros para abreviar:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

### Gráfico de serie temporal — uso de variables del panel {#example-line-chart-variables}

Dado un panel de control con una variable `service` sobre `ServiceName` y una variable `severity` sobre `SeverityText`, esta consulta restringe el gráfico a los servicios seleccionados actualmente y excluye las severidades seleccionadas. Ambas macros se expanden a `1=1` mientras su variable no tenga ningún valor seleccionado, por lo que el gráfico se renderiza sin filtrar hasta que el usuario elige un valor.

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

### Gráfico de barras apiladas — recuento de errores por severidad {#example-stacked-bar}

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  lower(SeverityText),
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND lower(SeverityText) IN ('error', 'warn')
  AND $__filters
GROUP BY SeverityText, ts
ORDER BY ts ASC
```

### Gráfico de tabla: los 10 puntos de conexión más lentos {#example-table}

```sql
SELECT
  SpanName AS endpoint,
  avg(Duration) / 1000 AS avg_duration_ms,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY SpanName
ORDER BY avg_duration_ms DESC
LIMIT 10
```

### Gráfico circular: distribución de solicitudes por servicio {#example-pie}

```sql
SELECT
  ServiceName,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY ServiceName
```

* `request_count` (numérico) determina el tamaño de cada sector.
* `ServiceName` (cadena) define la etiqueta de cada sector.

### Gráfico numérico — recuento total de errores {#example-number}

```sql
SELECT
  count() AS total_errors
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND SeverityText = 'error'
  AND $__filters
```

Se muestra el valor numérico único `total_errors` de la primera fila.

## Notas {#notes}

* Las visualizaciones basadas en SQL se ejecutan con el modo `readonly` habilitado: solo se permiten consultas `SELECT`.
* Cada visualización basada en SQL admite una única consulta; no se admiten consultas múltiples.
* El Editor SQL ofrece sugerencias de autocompletado tanto para parámetros de consulta como para macros.
* Para aplicar los filtros del panel de control a las visualizaciones basadas en SQL, es necesario seleccionar una fuente. La fuente debe corresponder a la tabla consultada para garantizar un filtrado preciso.
* Las variables del panel no requieren una fuente: los valores provienen de las listas desplegables de filtros del panel de control, no de la fuente propia del bloque.
* Las alertas de un bloque SQL que hace referencia a una variable del panel se evalúan con todas las variables en estado vacío, no con los valores seleccionados en el panel de control.
