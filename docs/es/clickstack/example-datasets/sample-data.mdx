Esta guía presenta ClickStack Open Source con un conjunto de datos de ejemplo.

En el siguiente ejemplo se da por hecho que ya ha iniciado ClickStack Open Source con la [imagen todo en uno](/es/clickstack/getting-started/oss) y que ha copiado la [API key de ingesta](/es/clickstack/getting-started/oss#copy-ingestion-api-key).

<Steps>
  <Step title="Acceda a la UI de ClickStack" id="navigate-to-the-hyperdx-ui">
    Visite [http://localhost:8080](http://localhost:8080) para acceder a la UI de ClickStack.

    <div className="ch-image-lg">
      <Frame>
        ![UI de ClickStack](/images/use-cases/observability/hyperdx.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Copiar API key de ingesta" id="copy-ingestion-api-key">
    Vaya a [`Team Settings`](http://localhost:8080/team) y copie la `Ingestion API Key` de la sección `API Keys`. Esta clave de API garantiza que la ingesta de datos a través del recolector de OpenTelemetry sea segura.

    <div className="ch-image-lg">
      <Frame>
        ![Copiar clave de API](/images/use-cases/observability/copy_api_key.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Descargar datos de muestra" id="download-sample-data">
    Para poblar la interfaz de usuario con datos de muestra, descargue el siguiente archivo:

    [Datos de muestra](https://storage.googleapis.com/hyperdx/sample.tar.gz)

    ```shell
    # curl
    curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
    # or
    # wget https://storage.googleapis.com/hyperdx/sample.tar.gz
    ```

    Este archivo contiene logs, métricas y trazas de ejemplo de nuestra [OpenTelemetry demo](https://github.com/ClickHouse/opentelemetry-demo) pública: una sencilla tienda de comercio electrónico basada en microservicios. Copie este archivo en el directorio que prefiera.
  </Step>

  <Step title="Cargar datos de muestra" id="load-sample-data">
    Para cargar estos datos, basta con enviarlos al endpoint HTTP del recolector de OpenTelemetry (OTel) desplegado.

    En primer lugar, exporte la clave de API que copió anteriormente.

    ```shell
    # export API key
    export CLICKSTACK_API_KEY=<YOUR_INGESTION_API_KEY>
    ```

    Ejecute el siguiente comando para enviar los datos al OTel collector:

    ```shell
    for filename in $(tar -tf sample.tar.gz); do
      endpoint="http://localhost:4318/v1/${filename%.json}"
      echo "loading ${filename%.json}"
      tar -xOf sample.tar.gz "$filename" | while read -r line; do
        printf '%s\n' "$line" | curl -s -o /dev/null -X POST "$endpoint" \
        -H "Content-Type: application/json" \
        -H "authorization: ${CLICKSTACK_API_KEY}" \
        --data-binary @-
      done
    done
    ```

    Esto simula fuentes OTLP de logs, trazas y métricas que envían datos al OTel collector. En producción, estas fuentes pueden ser clientes para lenguajes de programación o incluso otros OTel collectors.

    Si vuelve a la vista `Search`, debería ver que los datos han empezado a cargarse (ajuste el intervalo de tiempo a `Last 1 hour` si no se muestran los datos):

    <div className="ch-image-lg">
      <Frame>
        ![Búsqueda en la UI de ClickStack](/images/use-cases/observability/hyperdx-10.webp)
      </Frame>
    </div>

    La carga de datos tardará unos minutos. Espere a que finalice antes de continuar con los siguientes pasos.
  </Step>

  <Step title="Explorar sesiones" id="explore-sessions">
    Supongamos que recibimos informes de que nuestros usuarios tienen problemas para pagar sus compras. Podemos ver su experiencia mediante las capacidades de reproducción de sesiones de la UI de ClickStack.

    Seleccione [`Client Sessions`](http://localhost:8080/sessions?from=1747312320000\&to=1747312920000\&sessionSource=l1324572572) en el menú izquierdo.

    <div className="ch-image-lg">
      <Frame>
        ![Sesiones](/images/use-cases/observability/hyperdx-11.webp)
      </Frame>
    </div>

    Esta vista nos permite ver las sesiones de front-end de nuestra tienda de comercio electrónico. Las sesiones permanecen anónimas hasta que los usuarios inician el proceso de pago e intentan completar una compra.

    Observe que algunas sesiones con correo electrónico tienen un error asociado, lo que podría confirmar los informes de transacciones fallidas.

    Seleccione una traza con un fallo y un correo electrónico asociado. La vista que aparece a continuación nos permite reproducir la sesión del usuario y analizar su problema. Pulse el botón de reproducción para ver la sesión.

    <div className="ch-image-lg">
      <Frame>
        ![Reproducción de sesiones](/images/use-cases/observability/hyperdx-12.webp)
      </Frame>
    </div>

    La reproducción muestra al usuario navegando por el sitio y añadiendo artículos a su carrito. Puede avanzar hasta un momento posterior de la sesión, cuando intenta completar un pago.

    <Tip>
      Todos los errores se marcan en rojo en la línea de tiempo.
    </Tip>

    El usuario no pudo realizar el pedido, sin que se mostrara ningún error evidente. Desplácese hasta la parte inferior del panel izquierdo, que contiene los eventos de red y de consola del navegador del usuario. Verá que se lanzó un error 500 al realizar una llamada a `/api/checkout`.

    <div className="ch-image-lg">
      <Frame>
        ![Error en la sesión](/images/use-cases/observability/hyperdx-13.webp)
      </Frame>
    </div>

    Seleccione este error `500`. Ni `Overview` ni `Column Values` indican el origen del problema, más allá de que el error es inesperado y provoca un `Internal Error`.
  </Step>

  <Step title="Explorar trazas" id="explore-traces">
    Vaya a la pestaña `Trace` para ver la traza distribuida completa.

    <div className="ch-image-lg">
      <Frame>
        ![Traza de la sesión](/images/use-cases/observability/hyperdx-14.webp)
      </Frame>
    </div>

    Desplácese hacia abajo por la traza para ver el origen del error: el span del servicio `checkout`. Seleccione el span del servicio `Payment`.

    <div className="ch-image-lg">
      <Frame>
        ![Span](/images/use-cases/observability/hyperdx-15.webp)
      </Frame>
    </div>

    Seleccione la pestaña `Column Values` y desplácese hacia abajo. Podemos ver que el problema se debe a que una caché está llena.

    <div className="ch-image-lg">
      <Frame>
        ![Valores de columna](/images/use-cases/observability/hyperdx-16.webp)
      </Frame>
    </div>

    Si nos desplazamos hacia arriba y volvemos a la traza, podemos ver que los logs están correlacionados con el span gracias a la configuración que realizamos anteriormente. Estos logs aportan contexto adicional.

    <div className="ch-image-lg">
      <Frame>
        ![Log correlacionado](/images/use-cases/observability/hyperdx-17.webp)
      </Frame>
    </div>

    Hemos determinado que una caché se está llenando en el servicio de pagos, lo que impide que los pagos se completen.
  </Step>

  <Step title="Explorar logs" id="explore-logs">
    Para obtener más detalles, podemos volver a la [vista `Search`](http://localhost:8080/search):

    Seleccione `Logs` entre las fuentes y aplique un filtro sobre el servicio `payment`.

    <div className="ch-image-lg">
      <Frame>
        ![Logs](/images/use-cases/observability/hyperdx-18.webp)
      </Frame>
    </div>

    Podemos ver que, aunque el problema es reciente, el número de pagos afectados es elevado. Además, una caché relacionada con los pagos con Visa parece estar provocando problemas.
  </Step>

  <Step title="Métricas del gráfico" id="chart-metrics">
    Aunque es evidente que se ha introducido un error en el código, podemos usar métricas para confirmar el tamaño de la caché. Vaya a la vista `Chart Explorer`.

    Seleccione `Metrics` como origen de datos. Complete el creador de gráficos para representar el `Maximum` de `visa_validation_cache.size (Gauge)` y pulse el botón de reproducción. Se observa claramente que la caché fue aumentando hasta alcanzar un tamaño máximo, momento a partir del cual empezaron a generarse errores.

    <div className="ch-image-lg">
      <Frame>
        ![Métricas](/images/use-cases/observability/hyperdx-19.webp)
      </Frame>
    </div>
  </Step>
