<Info>
  **Resumen**

  Ejecuta una pequeña aplicación de demostración, instruméntala con el prompt de IA de la página Primeros pasos de tu servicio o con dos modificaciones manuales, y observa cómo llegan los logs, las trazas y las métricas a ClickHouse Observability.

  Tiempo necesario: unos 10 minutos
</Info>

Ya has creado tu servicio de ClickHouse Observability. Esta guía te lleva de ese servicio vacío a recibir telemetría de una aplicación en ejecución.

ClickHouse Observability ofrece un endpoint de OpenTelemetry gestionado al que tu aplicación envía la telemetría directamente. No tienes que ejecutar ningún recolector, crear ningún esquema ni dimensionar ninguna base de datos: la ingestión, los esquemas, el almacenamiento, la optimización y el escalado se gestionan automáticamente.

## La aplicación de demostración {#the-demo-application}

Para que tenga algo realista que instrumentar, esta guía utiliza [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), una aplicación de demostración que ofrecemos precisamente con este fin. Se trata de una pequeña aplicación en Node.js y TypeScript que consulta el conjunto de datos de HackerNews alojado en la demo pública de ClickHouse. Cada gráfico, tabla y cuadro de búsqueda se apoya en una solicitud real al backend. Las solicitudes que no se resuelven desde la caché de la aplicación también consultan ClickHouse, lo que añade un span HTTPS saliente a cada traza.

La demo está disponible en dos variantes:

* **Sin instrumentar**, en la rama `main`. En esta guía, usted mismo añadirá la instrumentación, ya sea con un agente de IA o manualmente, sin modificar la lógica de negocio de la aplicación. Los mismos pasos son aplicables a sus propios servicios.
* **Preinstrumentada**, en la rama `instrumented`. Utilice esta rama si solo quiere empezar a recibir telemetría rápidamente y explorar la interfaz de usuario.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability. Si aún no tiene uno, siga la [guía de introducción](/es/clickstack/observability/getting-started).
* Node.js 18 o posterior y npm.
* Acceso de red al endpoint de telemetría de su servicio, tanto desde la máquina donde se ejecuta la demo como desde su navegador.

### Configure la demo para que apunte a su servicio {#configure-environment}

        Abra `.env` y establezca los siguientes valores, sustituyendo el endpoint y la clave de API por los que aparecen en el cuadro de diálogo:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Estas son variables estándar del exportador de OpenTelemetry. No hay ningún valor codificado de forma fija en el código fuente de la aplicación.

        Mantenga el prefijo `https://` en `OTEL_EXPORTER_OTLP_ENDPOINT` y no añada `/v1/logs`, `/v1/traces` ni `/v1/metrics`, ya que los SDK añaden las rutas de cada señal. Establezca `OTEL_EXPORTER_OTLP_HEADERS` en `authorization=<your-api-key>`, sin el prefijo `Bearer`.

        A continuación, la instrumentación consta de tres pasos: instalar el SDK, cambiar el comando de inicio y habilitar el SDK para navegador. Nada de esto modifica la lógica de negocio de la aplicación.

### Instalar el SDK de Node {#install-node-sdk}

        ```bash
        npm install @hyperdx/node-opentelemetry
        ```

### Habilitar el envoltorio en run.sh {#enable-run-sh-wrapper}

        Al final de `run.sh` hay dos líneas `exec`. Comente la línea que ejecuta `node` directamente y descomente la instrumentada:

        ```diff
         # BEFORE: plain node, no instrumentation:
        -exec node scripts/entrypoint.js
        +# exec node scripts/entrypoint.js

         # AFTER: same source, wrapped by opentelemetry-instrument:
        -# exec npx opentelemetry-instrument scripts/entrypoint.js
        +exec npx opentelemetry-instrument scripts/entrypoint.js
        ```

        Siga iniciando la aplicación mediante `scripts/entrypoint.js`. Ese shim llama a `require('console')` para que la captura de consola envuelva `console.log`. Si apunta `opentelemetry-instrument` directamente a `dist/server/index.js`, las trazas se envían, pero los logs se descartan sin ningún aviso.

### Activar el SDK para navegador {#enable-browser-sdk}

        ```bash
        npm install @hyperdx/browser
        ```

        En `src/web/telemetry.ts`, descomenta la importación, el bloque `HyperDX.init` y `HyperDX.addAction` en `recordAction`:

        ```diff
        -// import HyperDX from '@hyperdx/browser';
        +import HyperDX from '@hyperdx/browser';

         export function initTelemetry(): void {
        -  // HyperDX.init({
        -  //   url: __OTLP_ENDPOINT__,
        -  //   apiKey: __OTLP_AUTH_TOKEN__,
        -  //   service: 'hn-analyzer-web',
        -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        -  //   consoleCapture: true,
        -  //   advancedNetworkCapture: true,
        -  // });
        +  HyperDX.init({
        +    url: __OTLP_ENDPOINT__,
        +    apiKey: __OTLP_AUTH_TOKEN__,
        +    service: 'hn-analyzer-web',
        +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        +    consoleCapture: true,
        +    advancedNetworkCapture: true,
        +  });
         }
        ```

        `__OTLP_ENDPOINT__` y `__OTLP_AUTH_TOKEN__` son constantes de tiempo de compilación que `vite.config.ts` inyecta a partir de los mismos valores `OTEL_EXPORTER_OTLP_*` que utiliza el backend.

        <Warning>
          El SDK para navegador incrusta el endpoint y la clave de API en el bundle del navegador, donde cualquiera que inspeccione la pestaña Red puede leerlos. Utilice un servicio destinado a pruebas y mantenga `.env` fuera del control de versiones.
        </Warning>

        Vuelva a iniciar la demo con `./run.sh`.
      </Tab>

## Si no aparece nada {#if-nothing-shows-up}

* Compruebe los valores de `.env`. El endpoint debe comenzar por `https://`, terminar con el puerto `4318` y no incluir ningún sufijo `/v1/...`. La clave de API debe ser el valor completo, que puede copiar tras seleccionar **Reveal key**.
* Si siguió el procedimiento manual, confirme que `OTEL_EXPORTER_OTLP_HEADERS` es `authorization=<your-api-key>` sin el prefijo `Bearer` y que el banner de inicio muestra las tres líneas `Health check passed`.
* Confirme que reinició la demo después de instrumentarla y que recargó la pestaña del navegador. La reproducción de sesiones solo se inicia cuando se sirve el paquete instrumentado.
* Amplíe el intervalo de tiempo en **Búsqueda** y quite todos los filtros. Es posible que la fuente predeterminada esté configurada como **Traces** en lugar de **Logs**.
* Para descartar un problema del propio servicio, vaya a **Team Settings → Managed Telemetry** y use **Send a Test Log**. Si ese log aparece en **Búsqueda**, el servicio está recibiendo datos y el problema está en la configuración de la demo.

## Próximos pasos {#next-steps}

Su servicio ya contiene telemetría de una aplicación real. Para instrumentar sus propios servicios, reutilice el prompt **Instrument with AI** de su servicio o utilice los [SDK de lenguaje compatibles](/es/clickstack/observability/ingesting-data/sdks/index) con el mismo endpoint y la misma clave de API.

Para recopilar datos de la infraestructura en lugar del código de aplicación:

* [Monitorización de Kubernetes](/es/clickstack/observability/example-datasets/kubernetes): recopile logs y métricas del cluster y explore el Panel de Kubernetes.
* [Logs y métricas locales](/es/clickstack/observability/example-datasets/local-data): recopile archivos locales y métricas del sistema en macOS o Linux.

Para sacar más partido a la interfaz de usuario:

* [Búsqueda](/es/clickstack/observability/features/search): consulte logs y trazas con sintaxis de tipo Lucene o con SQL.
* [Reproducción de sesiones](/es/clickstack/observability/features/session-replay): descripción general de la funcionalidad, opciones del SDK y controles de privacidad.
* [Conjuntos de datos de ejemplo](/es/clickstack/observability/example-datasets): conjuntos de datos más completos e investigaciones guiadas.
