<Info>
  **TL;DR**

  Elija los grupos de registros de CloudWatch que desee, pegue el bloque del exportador de la pestaña **Collector config** de su servicio en una configuración breve del Colector de OpenTelemetry e inícielo con Docker Compose. El recolector sondea los grupos de registros y envía cada evento directamente a ClickHouse Observability, etiquetado con su grupo de registros y su stream.

  Tiempo necesario: unos 15 minutos
</Info>

Ya ha creado su servicio de ClickHouse Observability. Esta guía está pensada para los casos en que los log que le interesan ya se encuentran en CloudWatch: funciones Lambda, tareas de ECS, RDS, VPC flow logs o cualquier otro recurso que escriba en un grupo de registros.

El patrón es el estándar de OpenTelemetry. Un único recolector con el [receptor `aws_cloudwatch`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver) sondea sus grupos de registros mediante la API de CloudWatch Logs y envía los eventos directamente al endpoint OTLP de su servicio. Puede ejecutarse en cualquier entorno que disponga de Docker y acceso a la API de AWS. Si utiliza una instancia de EC2 en la misma región que los grupos de registros, reducirá la latencia de la API y los costes de transferencia de datos.

## Requisitos previos {#prerequisites}

* Un servicio de ClickHouse Observability. Si todavía no tiene uno, siga la [guía de introducción](/es/clickstack/observability/getting-started).
* Una cuenta de AWS con uno o más grupos de registros de CloudWatch, y permiso para crear o usar credenciales con acceso de lectura a ellos.
* Un host con Docker, la [AWS CLI](https://aws.amazon.com/cli/) y acceso HTTPS saliente por el puerto `4318` al endpoint de telemetría de su servicio.

Ejecute los comandos de AWS y Docker desde una misma shell en ese host. El recolector obtiene sus credenciales de AWS del entorno de esa shell.

## Configurar el recolector {#set-up-the-collector}

<Steps>
  <Step title="Configure las credenciales de AWS" id="set-up-aws-credentials">
    El receptor utiliza la cadena de credenciales estándar del AWS SDK, por lo que cualquier método que funcione con la AWS CLI también funcionará con el recolector. Las credenciales deben tener permisos para listar grupos de registros y leer sus eventos:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Reemplace `YOUR_ACCOUNT_ID` por el ID de su cuenta de AWS. Exporte las credenciales y, a continuación, compruebe que funcionan:

    <Tabs>
      <Tab title="AWS SSO" id="aws-sso">
        ```shell
        aws sso login --profile YOUR_PROFILE_NAME
        eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
        aws sts get-caller-identity
        ```

        Las credenciales de SSO caducan, normalmente al cabo de 8 a 12 horas. Vuelva a ejecutar estos comandos para actualizar y exportar las credenciales y, a continuación, ejecute `docker compose up -d --force-recreate otel-collector` desde el directorio de Compose. Al recrear el contenedor se aplican las nuevas variables de entorno; si solo se reinicia, conserva las credenciales expiradas. Con claves de acceso o un rol de instancia se evita esta interrupción.
      </Tab>

      <Tab title="Claves de acceso de IAM" id="iam-access-keys">
        ```shell
        export AWS_ACCESS_KEY_ID="your-access-key-id"
        export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
        export AWS_REGION="us-east-1"
        aws sts get-caller-identity
        ```
      </Tab>
    </Tabs>

    <Info>
      **Credenciales en producción**

      En producción, adjunte la política al host en lugar de exportar claves: un rol de IAM en EC2, IRSA en EKS o un rol de tarea en ECS. De este modo, el recolector obtiene las credenciales del servicio de metadatos de instancia y el archivo de Compose que se muestra a continuación no necesita ninguna variable de AWS.
    </Info>
  </Step>

  <Step title="Seleccione sus grupos de registros" id="pick-your-log-groups">
    Liste los grupos de registros de su región para poder usar los nombres exactos y comprobar que la región es la correcta:

    ```shell
    aws logs describe-log-groups --region us-east-1 \
      --query 'logGroups[].logGroupName' --output table
    ```

    Anote los nombres que necesite. Los grupos que comparten un prefijo, como `/aws/lambda/`, pueden seleccionarse en conjunto al escribir la configuración.
  </Step>

  <Step title="Copie sus datos de conexión" id="copy-connection-details">
    Abra su servicio de ClickHouse Observability. Mientras no lleguen datos, se mostrará la página **Start sending telemetry**.

    <div className="ch-image-lg">
      <Frame>
        ![Página Start sending telemetry que muestra el servicio actual todavía sin datos y tres opciones: Use an existing OpenTelemetry setup, Instrument with AI y Follow setup guides](/images/clickstack/getting-started/observability-start-sending-telemetry.png)
      </Frame>
    </div>

    En **Use an existing OpenTelemetry setup**, seleccione **View connection details** y, a continuación, abra la pestaña **Collector config**. En ella verá un bloque de exportador ya preparado para su servicio: el endpoint y un encabezado `authorization` que ya incluye su clave de API con el prefijo `Bearer`. Seleccione **Reveal key** para mostrar la clave completa y, después, use el botón de copiar.

    <div className="ch-image-md">
      <Frame>
        ![Cuadro de diálogo Set up OpenTelemetry con la pestaña Collector config seleccionada, que muestra un exportador otlphttp con el endpoint enmascarado y un encabezado de autorización Bearer](/images/clickstack/getting-started/observability-collector-config.png)
      </Frame>
    </div>

    El bloque tiene esta forma. En el siguiente paso, lo pegará en la configuración del recolector exactamente tal como lo copió:

    ```yaml
    exporters:
      otlphttp:
        endpoint: https://YOUR_OTEL_ENDPOINT:4318
        headers:
          authorization: Bearer <your-api-key>
    ```

    Puede consultar estos mismos valores en cualquier momento en **Configuración del equipo → Managed Telemetry**.
  </Step>

  <Step title="Escriba la configuración del recopilador" id="write-the-configuration">
    Cree `otel-collector-config.yaml` a partir de la variante que se ajuste a la forma en que desea seleccionar los grupos de registros y, a continuación, reemplace su bloque `exporters` por el que copió. Ambas variantes leen los eventos de la última hora durante el inicio.

    <Tabs>
      <Tab title="Grupos de registros con nombre" id="named-log-groups">
        ```yaml
        receivers:
          aws_cloudwatch:
            region: us-east-1
            logs:
              poll_interval: 1m
              initial_lookback: 1h
              groups:
                named:
                  /aws/lambda/payment-processor:
                  /aws/lambda/order-service:
                  /ecs/api-gateway:

        processors:
          batch:
            timeout: 10s

        exporters:
          otlphttp:
            endpoint: https://YOUR_OTEL_ENDPOINT:4318
            headers:
              authorization: Bearer <your-api-key>

        service:
          pipelines:
            logs:
              receivers: [aws_cloudwatch]
              processors: [batch]
              exporters: [otlphttp]
        ```

        Cada clave bajo `named` corresponde a un grupo de registros. Deje el valor vacío para leer todos los streams del grupo, o añada `names:` o `prefixes:` debajo para leer solo algunos de ellos.
      </Tab>

      <Tab title="Descubrimiento automático por prefijo" id="autodiscover-by-prefix">
        ```yaml
        receivers:
          aws_cloudwatch:
            region: us-east-1
            logs:
              poll_interval: 1m
              initial_lookback: 1h
              groups:
                autodiscover:
                  limit: 100
                  prefix: /aws/lambda/

        processors:
          batch:
            timeout: 10s

        exporters:
          otlphttp:
            endpoint: https://YOUR_OTEL_ENDPOINT:4318
            headers:
              authorization: Bearer <your-api-key>

        service:
          pipelines:
            logs:
              receivers: [aws_cloudwatch]
              processors: [batch]
              exporters: [otlphttp]
        ```

        Esta configuración lee todos los grupos de registros cuyo nombre empieza por el prefijo, hasta el valor de `limit`, incluidos los grupos que se creen más adelante. Use `pattern` en lugar de `prefix` para buscar una subcadena en cualquier parte del nombre.
      </Tab>
    </Tabs>

    El nombre del exportador `otlphttp` coincide con el que indica la pestaña. Las versiones recientes del recolector lo llaman `otlp_http` y conservan `otlphttp` como alias, por lo que ambos funcionan, y el recolector registra `"otlphttp" alias is deprecated` una vez durante el inicio. Esta advertencia es inofensiva. Si renombra el exportador, renómbrelo también en la canalización. Use el endpoint como URL base: no añada `/v1/logs`, ya que el propio exportador agrega la ruta de la señal.

    El archivo ahora contiene su clave de API, así que no lo incluya en el control de versiones. El contenedor del recolector se ejecuta como UID/GID `10001:10001`. En Linux, conceda a ese grupo acceso de lectura sin que el archivo deje de ser editable por su propietario en el host:

    ```shell
    sudo chgrp 10001 otel-collector-config.yaml
    chmod 640 otel-collector-config.yaml
    ```

    Esto permite que el contenedor lea la configuración montada mediante bind mount sin que la clave de API quede legible para todos los usuarios.

    Ajustes que debe modificar:

    * `region`: la región en la que se encuentran los grupos de registros.
    * `initial_lookback`: cuánto tiempo hacia atrás se leen los datos al iniciarse el recolector. Sin esta opción, el receptor lee todo el historial retenido de cada grupo, lo que puede suponer una carga de datos históricos puntual de gran volumen, con el consiguiente número de llamadas a la API. Para realizar la carga de datos históricos a partir de un momento concreto, sustitúyala por `start_from` y una marca de tiempo en formato RFC 3339.
    * `poll_interval`: `1m` de forma predeterminada. Con intervalos más cortos, los log están más actualizados, a cambio de un mayor número de llamadas a la API.
    * Cada reinicio vuelve a leer la ventana retrospectiva, por lo que la última hora aparece duplicada tras reiniciar. Para una implementación de ejecución prolongada, añada la extensión `file_storage` y configure la opción `storage` del receptor para que reanude la lectura donde la dejó.

    El [README](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver) del receptor describe las opciones restantes, incluidos los filtros de stream y la lectura desde cuentas vinculadas.

    <Accordion title="Opcional: utilice el grupo de registros como nombre del servicio">
      Los eventos de CloudWatch no incluyen el nombre del servicio, por lo que `ServiceName` aparece vacío en Búsqueda y los filtros de servicios no tienen ningún efecto. Para rellenarlo a partir del grupo de registros, añada un procesador `transform` y colóquelo antes de `batch` en la canalización:

      ```yaml
      processors:
        transform:
          log_statements:
            - context: resource
              statements:
                - set(attributes["service.name"], attributes["cloudwatch.log.group.name"])
        batch:
          timeout: 10s

      service:
        pipelines:
          logs:
            receivers: [aws_cloudwatch]
            processors: [transform, batch]
            exporters: [otlphttp]
      ```
    </Accordion>
  </Step>

  <Step title="Inícielo con Docker Compose" id="start-with-docker-compose">
    Cree `docker-compose.yaml` junto al archivo de configuración. Este archivo monta la configuración y pasa sus credenciales de AWS desde el shell al contenedor:

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.162.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
        restart: unless-stopped
    ```

    Inícielo y supervise los logs:

    ```shell
    docker compose up -d
    docker compose logs -f otel-collector
    ```

    Un inicio correcto termina con `Everything is ready. Begin running and processing data.` El primer sondeo se produce un `poll_interval` después del inicio, así que espere uno o dos minutos. Errores que conviene saber identificar:

    * `panic: runtime error: invalid memory address or nil pointer dereference` en `ensureSession`, tras lo cual el contenedor se reinicia: el recolector no pudo autenticarse en AWS. Las credenciales faltan, no son válidas o han expirado, o el endpoint de STS no es accesible. La versión 0.162.0 del recolector notifica esta situación como una terminación inesperada en lugar de como un mensaje de error, algo que se está siguiendo en upstream en el [issue 50961](https://github.com/open-telemetry/opentelemetry-collector-contrib/issues/50961). Ejecute `aws sts get-caller-identity` en el host, actualice y exporte credenciales válidas y, a continuación, ejecute `docker compose up -d --force-recreate otel-collector` desde el directorio de Compose.
    * `AccessDeniedException`: las credenciales necesitan `logs:DescribeLogGroups` con `"Resource": "*"` y `logs:FilterLogEvents` en los grupos de registros correspondientes.
    * `ResourceNotFoundException`: el nombre de un grupo de registros está mal escrito o se encuentra en otra región.
    * `401` o `403` del exportador: el valor de `authorization` en la configuración es incorrecto. Debe contener `Bearer` seguido de la clave completa, tal como aparece en la pestaña Collector config. Corrija el archivo y ejecute `docker compose restart otel-collector`.
    * `404` del exportador: se añadió al final del endpoint una ruta de señal como `/v1/logs`.
  </Step>
</Steps>

## Confirmar que los datos están llegando {#confirm-data-is-arriving}

Vuelva a la página **Start sending telemetry** de su servicio y seleccione **Check for data**. Cuando llegue la telemetría, el estado del servicio cambiará a **Data received** y **Start exploring** estará disponible.

</div>

Seleccione **Start exploring** para abrir **Búsqueda**, seleccione la fuente **Logs** y establezca el intervalo de tiempo en **Last 15 minutes**. Los eventos aparecerán en un par de intervalos de sondeo. Cada uno incluye su origen como atributos del recurso:

* `aws.region`: la región que configuró.
* `cloudwatch.log.group.name`: el grupo de registros de origen.
* `cloudwatch.log.stream`: el log stream de origen.
* `cloud.account.id`: la cuenta de AWS de la que provienen los eventos.

Para mostrarlos como columnas, reemplace el `SELECT` por `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body`:

## Si no aparece nada {#if-nothing-shows-up}

* Revise primero los logs del recolector con `docker compose logs -f otel-collector`. Tanto los problemas de AWS como los del exportador se notifican allí con los mensajes indicados anteriormente.
* Ejecute `aws sts get-caller-identity` en el host para confirmar que las credenciales siguen siendo válidas. Las sesiones de SSO caducan y, cuando esto ocurre, el recolector termina de forma inesperada en lugar de registrar un error.
* Confirme que el grupo ha recibido eventos recientemente, ya que el receptor solo lee los eventos escritos dentro de la ventana retrospectiva o con posterioridad. Por ejemplo: `aws logs filter-log-events --log-group-name /aws/lambda/order-service --region us-east-1 --limit 5`.
* Amplíe el intervalo de tiempo en **Búsqueda** y elimine todos los filtros. Es posible que la fuente predeterminada esté configurada como **Traces** en lugar de **Logs**.
* Para descartar un problema en el propio servicio, vaya a **Configuración del equipo → Managed Telemetry** y utilice **Send a Test Log**. Si ese log aparece en **Búsqueda**, el servicio está recibiendo datos y el problema se encuentra entre el recolector y CloudWatch o el endpoint.
