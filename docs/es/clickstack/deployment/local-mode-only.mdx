Al igual que la [imagen todo en uno](/es/clickstack/deployment/all-in-one), esta imagen de Docker completa agrupa todos los componentes de ClickStack:

* **ClickHouse**
* **UI de ClickStack**
* **colector de OpenTelemetry (OTel)** (expone OTLP en los puertos `4317` y `4318`)
* **MongoDB** (para el estado persistente de la aplicación)

**Sin embargo, la autenticación de usuarios está deshabilitada para esta distribución de la UI de ClickStack**

<div id="suitable-for">
  ### Adecuado para {#suitable-for}
</div>

* Demos
* Depuración
* Desarrollo con la UI de ClickStack

## Pasos de despliegue {#deployment-steps}

<br />

<Steps>
  <Step title="Desplegar con Docker" id="deploy-with-docker">
    El modo local despliega la UI de ClickStack en el puerto 8080.

    ```shell
    docker run -p 8080:8080 clickhouse/clickstack-local:latest
    ```
  </Step>

  <Step title="Acceder a la UI de ClickStack" id="navigate-to-hyperdx-ui">
    Visite [http://localhost:8080](http://localhost:8080) para acceder a la UI de ClickStack.

    **No se le pedirá que cree un usuario, ya que la autenticación no está habilitada en este modo de despliegue.**

    Conéctese a su propio cluster externo de ClickHouse, por ejemplo, ClickHouse Cloud.

    <div className="ch-image-md">
      <Frame>
        ![Crear inicio de sesión](/images/use-cases/observability/hyperdx-2.webp)
      </Frame>
    </div>

    Cree una fuente, mantenga todos los valores predeterminados y rellene el campo `Table` con el valor `otel_logs`. El resto de los ajustes deberían detectarse automáticamente, por lo que podrá hacer clic en `Save New Source`.

    <div className="ch-image-md">
      <Frame>
        ![Crear fuente de registros](/images/use-cases/observability/hyperdx-logs.webp)
      </Frame>
    </div>
  </Step>
</Steps>
