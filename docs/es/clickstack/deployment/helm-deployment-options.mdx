## Descripción general {#overview}

El gráfico de Helm de ClickStack admite varias configuraciones de implementación:

* **Pila completa** (predeterminada) — Incluye todos los componentes, gestionados por operadores
* **ClickHouse externo** — Usa un clúster de ClickHouse existente
* **OTel collector externo** — Usa infraestructura de OTel existente
* **Implementación mínima** — Solo la UI de ClickStack y dependencias externas

## ClickHouse externo {#external-clickhouse}

Si ya dispone de un clúster de ClickHouse (incluido ClickHouse Cloud), puede desactivar el ClickHouse integrado y conectarse a su instancia externa.

El OTel collector incluido sigue habilitado. Configure su endpoint de protocolo nativo y sus credenciales de forma independiente de la conexión HTTP de consultas de HyperDX. El usuario del recolector necesita permiso para crear el esquema de telemetría e insertar datos.

### Opción 1: Configuración inline (desarrollo/pruebas) {#external-clickhouse-inline}

Use este enfoque para pruebas rápidas o entornos no productivos. Proporcione los detalles de conexión mediante `hyperdx.config` y `hyperdx.secrets`:

```yaml
# values-external-clickhouse.yaml
clickhouse:
  enabled: false  # Disable the operator-managed ClickHouse

hyperdx:
  config:
    CLICKHOUSE_ENDPOINT: "tcp://your-clickhouse-server:9000?dial_timeout=10s"
    CLICKHOUSE_USER: "your-username"
  secrets:
    CLICKHOUSE_PASSWORD: "your-password"
    CLICKHOUSE_APP_PASSWORD: "your-password"

  deployment:
    defaultConnections: |
      [
        {
          "name": "Local ClickHouse",
          "host": "http://your-clickhouse-server:8123",
          "username": "your-username",
          "password": "your-password"
        }
      ]
```

Mantenga el nombre de conexión `Local ClickHouse`, ya que las fuentes predeterminadas del gráfico hacen referencia a él, incluso cuando el servidor es externo.

Instale con esta configuración:

```shell
helm install my-clickstack clickstack/clickstack -f values-external-clickhouse.yaml
```

### Opción 2: Secreto externo (recomendado para producción) {#external-clickhouse-secret}

Para despliegues de producción en los que quieras mantener las credenciales separadas de la configuración de Helm:

#### Cree los archivos de configuración {#create-configuration}

Incluya el puerto HTTP(S) en la URL `host` de cada conexión. En este ejemplo se utiliza el puerto HTTPS `8443`; use el puerto configurado en su servidor.

```bash
# Create connections.json
cat <<EOF > connections.json
[
  {
    "name": "Production ClickHouse",
    "host": "https://your-production-clickhouse.com:8443",
    "username": "hyperdx_user",
    "password": "your-secure-password"
  }
]
EOF

# Create sources.json
cat <<EOF > sources.json
[
  {
    "from": {
      "databaseName": "default",
      "tableName": "otel_logs"
    },
    "kind": "log",
    "name": "Logs",
    "connection": "Production ClickHouse",
    "timestampValueExpression": "TimestampTime",
    "displayedTimestampValueExpression": "Timestamp",
    "implicitColumnExpression": "Body",
    "serviceNameExpression": "ServiceName",
    "bodyExpression": "Body",
    "eventAttributesExpression": "LogAttributes",
    "resourceAttributesExpression": "ResourceAttributes",
    "defaultTableSelectExpression": "Timestamp,ServiceName,SeverityText,Body",
    "severityTextExpression": "SeverityText",
    "traceIdExpression": "TraceId",
    "spanIdExpression": "SpanId"
  },
  {
    "from": {
      "databaseName": "default",
      "tableName": "otel_traces"
    },
    "kind": "trace",
    "name": "Traces",
    "connection": "Production ClickHouse",
    "timestampValueExpression": "Timestamp",
    "displayedTimestampValueExpression": "Timestamp",
    "implicitColumnExpression": "SpanName",
    "serviceNameExpression": "ServiceName",
    "traceIdExpression": "TraceId",
    "spanIdExpression": "SpanId",
    "durationExpression": "Duration",
    "durationPrecision": 9,
    "defaultTableSelectExpression": "Timestamp,ServiceName,StatusCode,round(Duration/1e6),SpanName",
    "parentSpanIdExpression": "ParentSpanId",
    "spanNameExpression": "SpanName",
    "spanKindExpression": "SpanKind"
  }
]
EOF
```

#### Cree el secreto de Kubernetes {#create-kubernetes-secret}

```bash
kubectl create secret generic hyperdx-external-config \
  --from-file=connections.json=connections.json \
  --from-file=sources.json=sources.json

# Eliminar archivos locales
rm connections.json sources.json
```

#### Configura Helm para usar el secreto {#configure-helm-secret}

El secreto de configuración proporciona la conexión de consultas y las fuentes de HyperDX. Configura por separado el endpoint y las credenciales del recolector a continuación, usando el puerto TLS nativo de tu servidor (en el ejemplo, `9440`).

```yaml
# values-external-clickhouse-secret.yaml
clickhouse:
  enabled: false

hyperdx:
  config:
    CLICKHOUSE_ENDPOINT: "tcp://your-production-clickhouse.com:9440?secure=true"
    CLICKHOUSE_USER: "hyperdx_user"
  secrets:
    CLICKHOUSE_PASSWORD: "your-secure-password"
  deployment:
    useExistingConfigSecret: true
    existingConfigSecret: "hyperdx-external-config"
    existingConfigConnectionsKey: "connections.json"
    existingConfigSourcesKey: "sources.json"
```

```shell
helm install my-clickstack clickstack/clickstack -f values-external-clickhouse-secret.yaml
```

### Uso de ClickHouse Cloud {#using-clickhouse-cloud}

En el caso de ClickHouse Cloud:

```yaml
# values-clickhouse-cloud.yaml
clickhouse:
  enabled: false

hyperdx:
  config:
    CLICKHOUSE_ENDPOINT: "tcp://your-cloud-instance.clickhouse.cloud:9440?secure=true"
    CLICKHOUSE_USER: "default"
  secrets:
    CLICKHOUSE_PASSWORD: "your-cloud-password"
    CLICKHOUSE_APP_PASSWORD: "your-cloud-password"

  deployment:
    useExistingConfigSecret: true
    existingConfigSecret: "clickhouse-cloud-config"
    existingConfigConnectionsKey: "connections.json"
    existingConfigSourcesKey: "sources.json"
```

## OTel collector externo {#external-otel-collector}

Si ya cuenta con una infraestructura de OTel collector, desactive el subgráfico:

```yaml
# values-external-otel.yaml
otel-collector:
  enabled: false  # Disable the subchart OTEL collector

hyperdx:
  config:
    OTEL_EXPORTER_OTLP_ENDPOINT: "http://your-otel-collector:4318"
```

```shell
helm install my-clickstack clickstack/clickstack -f values-external-otel.yaml
```

Para obtener instrucciones sobre cómo exponer los endpoints del OTel collector mediante Ingreso, consulta [Configuración de Ingreso](/es/clickstack/deployment/helm-configuration#otel-collector-ingress).

## Implementación mínima {#minimal-deployment}

Para las organizaciones que ya cuentan con infraestructura, implemente solo la UI de ClickStack:

```yaml
# values-minimal.yaml
clickhouse:
  enabled: false

otel-collector:
  enabled: false

hyperdx:
  config:
    OTEL_EXPORTER_OTLP_ENDPOINT: "http://your-otel-collector:4318"

  deployment:
    # Option 1: Inline (for testing)
    defaultConnections: |
      [
        {
          "name": "Local ClickHouse",
          "host": "http://your-clickhouse-server:8123",
          "username": "your-username",
          "password": "your-password"
        }
      ]

    # Option 2: External secret (production)
    # useExistingConfigSecret: true
    # existingConfigSecret: "my-external-config"
    # existingConfigConnectionsKey: "connections.json"
    # existingConfigSourcesKey: "sources.json"
```

```shell
helm install my-clickstack clickstack/clickstack -f values-minimal.yaml
```
