Las siguientes opciones de configuración están disponibles para cada componente de ClickStack:

<div id="modifying-settings">
  ## Configuración para distribuciones de código abierto {#modifying-settings}
</div>

### Docker {#docker}

Si usas [Todo en uno](/es/clickstack/deployment/all-in-one), [Solo UI de ClickStack](/es/clickstack/deployment/hyperdx-only) o [Modo local](/es/clickstack/deployment/local-mode-only), solo tienes que pasar la configuración deseada mediante una variable de entorno; por ejemplo:

```shell
docker run -e HYPERDX_APP_PORT=8081 -p 8081:8081 -p 4317:4317 -p 4318:4318 clickhouse/clickstack-all-in-one:latest
```

### Docker Compose {#docker-compose}

Si utiliza la guía de implementación de [Docker Compose](/es/clickstack/deployment/docker-compose), puede usar el archivo [`.env`](https://github.com/ClickHouse/clickstack/blob/main/.env) para modificar la configuración.

Como alternativa, sobrescriba explícitamente la configuración en el archivo [`docker-compose.yml`](https://github.com/ClickHouse/clickstack/blob/main/docker-compose.yml); por ejemplo:

Ejemplo:

```yaml
services:
  app:
    environment:
      HYPERDX_API_KEY: ${HYPERDX_API_KEY}
      HYPERDX_LOG_LEVEL: ${HYPERDX_LOG_LEVEL}
      # ... other settings
```

### Helm {#helm}

Utilice la [guía de despliegue con Helm](/es/clickstack/deployment/helm) para instalar los operadores y el chart de ClickStack. Antes de personalizar un despliegue, obtenga los valores del chart actual:

```shell
helm show values clickstack/clickstack > values.yaml
```

Configure por separado el entorno de la aplicación y el del recolector mediante los valores del chart y, a continuación, aplique la configuración:

```shell
helm upgrade --install my-clickstack clickstack/clickstack -f values.yaml
```

Consulte [Configuración de Helm](/es/clickstack/deployment/helm-configuration) para conocer los valores compatibles y la configuración de Ingreso, recursos y secrets. El chart antiguo `hyperdx/hdx-oss-v2` usa una estructura de valores distinta.

## Aplicación UI de ClickStack {#hyperdx}

### Conexiones {#connection-settings}

Configure la conexión a la base de datos que utilizan sus fuentes en la configuración del equipo.

| Ajuste                     | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Connection Name`          | Nombre que identifica esta conexión en la configuración de la fuente.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `Host`                     | Endpoint HTTP(S) de ClickHouse, incluido su puerto. Es distinto del endpoint de exportación del recolector.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `Username`                 | Nombre de usuario de ClickHouse; el valor predeterminado es `default`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `Password`                 | Contraseña de ClickHouse; de forma predeterminada está vacía.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `Query Log Setting Prefix` | Prefijo opcional para un parámetro de configuración personalizado de ClickHouse que registra el correo electrónico del usuario actual en los registros de consultas. Incluya el mismo prefijo en la configuración `custom_settings_prefixes` de ClickHouse; de lo contrario, las consultas se rechazarán. Para ver qué panel de control, alerta u otra funcionalidad de ClickStack lanzó una consulta, sin identificadores de usuario, consulte [Identificar qué genera la carga de consultas](/es/clickstack/managing/performance-tuning#query-attribution). |
| `Prometheus compatible`    | Si está disponible, trata Host como un punto de conexión de API compatible con Prometheus para consultas PromQL a través de un proxy. Esta conexión no se puede usar para fuentes de log, trazas o métricas de OTel respaldadas por ClickHouse.                                                                                                                                                                                                                                                                                                            |

### Configuración de las fuentes de datos {#datasource-settings}

La UI de ClickStack requiere que el usuario defina una fuente para cada uno de los tipos o pilares de datos de observabilidad:

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

Esta configuración puede realizarse dentro de la aplicación desde `Team Settings -> Sources`, como se muestra a continuación para los logs:

<div className="ch-image-md">
  <Frame>
    ![Configuración de fuente en la UI de ClickStack](/images/use-cases/observability/hyperdx-25.webp)
  </Frame>
</div>

Cada fuente necesita correspondencias de tablas y columnas para que la UI de ClickStack pueda consultar sus datos. Las fuentes de métricas pueden usar tablas independientes para distintos tipos de métricas. El interruptor `Enabled` aparece al editar una fuente existente; los `Query Settings` a nivel de fuente admiten hasta diez pares nombre/valor.

Si se utiliza el [esquema predeterminado de OpenTelemetry (OTel)](/es/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema) incluido con ClickStack, estas columnas pueden inferirse automáticamente para cada una de las fuentes. Si se [modifica el esquema](#clickhouse) o se usa un esquema personalizado, los usuarios deben especificar y actualizar estas correspondencias.

<Note>
  El recolector crea las tablas mediante migraciones de esquemas o mediante la creación de esquemas heredada gestionada por el exportador, según su [configuración de esquema](#collector-schema-and-retention). Las correspondencias de columnas siguen las convenciones de OpenTelemetry, incluido el [modelo de datos de logs](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
</Note>

### Fuentes correlacionadas {#correlated-sources}

Para habilitar la correlación completa entre fuentes en ClickStack, debe configurar fuentes correlacionadas para logs, trazas, métricas y sesiones. Esto permite que la UI de ClickStack asocie datos relacionados y proporcione un contexto enriquecido al mostrar eventos.

Configurar estas correlaciones habilita varias funcionalidades. Por ejemplo, la UI de ClickStack puede mostrar logs relevantes junto a una traza o resaltar anomalías de métricas vinculadas a una sesión.

| `NEXT_PUBLIC_INSTANCE_LABEL`       | Vacío          | Etiqueta que se añade al título del navegador y se muestra en la barra lateral; resulta útil para distinguir instancias.                                                                                                                                                                 |
| `ENABLE_DATADOG_RECEIVER`          | `false`        | Habilita el receptor de trazas de Datadog en la configuración del recopilador generada por OpAMP. El receptor del puerto `8126` valida `DD-API-KEY` cuando existen claves de ingesta del equipo y se exige la autenticación del recolector; en caso contrario, no requiere autenticación. |
| `BETA_CH_OTEL_JSON_SCHEMA_ENABLED` | `false`        | Selecciona correspondencias de origen predeterminadas compatibles con JSON en el punto de entrada all-in-one. Úsela junto con `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_JSON_ENABLE` en el recolector.                                                                                                     |

`NEXT_PUBLIC_IS_LOCAL_MODE` es el indicador de build del frontend para la [distribución Modo local](/es/clickstack/deployment/local-mode-only). No es un interruptor de desarrollo de propósito general. Utilice la distribución adecuada en lugar de deshabilitar la autenticación en una implementación existente. `IS_LOCAL_MODE` e `IS_OSS` son nombres de constantes de la aplicación, no las variables de entorno que deben establecerse. `NEXT_PUBLIC_IS_OSS` es un parámetro de configuración de build; no es un interruptor de la edición Enterprise. `MINER_API_URL` ya no se utiliza en la aplicación actual.

Si utiliza la configuración de proxy inverso proporcionada para una subruta, establezca `HYPERDX_BASE_PATH` y `NEXT_PUBLIC_HYPERDX_BASE_PATH` con el mismo prefijo (por ejemplo, `/clickstack`) e incluya dicho prefijo en `FRONTEND_URL`.

Algunos ajustes del frontend se leen en tiempo de build. En concreto, para cambiar `NEXT_PUBLIC_HYPERDX_BASE_PATH` (el prefijo de ruta de despliegue), `NEXT_PUBLIC_NOINDEX` (indexación en motores de búsqueda) o los indicadores de modo de la distribución, es necesario compilar el frontend con esos valores. Los ajustes de tiempo de ejecución que se leen mediante `next-runtime-env`, como `NEXT_PUBLIC_INSTANCE_LABEL`, se pueden especificar al contenedor durante el arranque.

<div id="clickhouse">
  ## ClickHouse {#clickhouse}
</div>

ClickStack Open Source incluye una configuración predeterminada de ClickHouse diseñada para escalar a varios terabytes, pero los usuarios pueden modificarla y optimizarla según su carga de trabajo.

Para optimizar ClickHouse de forma eficaz, debe comprender conceptos clave de almacenamiento como las [partes](/es/concepts/core-concepts/parts), las [particiones](/es/concepts/core-concepts/partitions), los [segmentos y réplicas](/es/guides/oss/deployment-and-scaling/shards) y cómo se producen las [fusiones](/es/concepts/core-concepts/merges) durante la inserción. Recomendamos revisar los fundamentos de los [índices primarios](/es/concepts/core-concepts/primary-indexes), los [índices secundarios dispersos](/es/concepts/features/performance/skip-indexes/skipping-indexes) y los índices de omisión de datos, junto con técnicas para [gestionar el ciclo de vida de los datos](/es/guides/use-cases/observability/build-your-own/managing-data), por ejemplo, mediante TTL.

ClickStack admite la [personalización del esquema](/es/guides/use-cases/observability/build-your-own/schema-design): puede modificar los tipos de las columnas, extraer nuevos campos (p. ej., de logs), aplicar codecs y diccionarios, y acelerar las consultas mediante proyecciones.

Además, las vistas materializadas pueden utilizarse para [transformar o filtrar datos durante la ingestión](/es/guides/use-cases/observability/build-your-own/schema-design#materialized-columns), siempre que los datos se escriban en la tabla origen de la vista y la aplicación lea de la tabla de destino. Las vistas materializadas también pueden utilizarse para [acelerar consultas de forma nativa](/es/clickstack/managing/materialized-views) en ClickStack.

Para obtener más información, consulte la documentación de ClickHouse sobre diseño de esquemas, estrategias de indexación y buenas prácticas para la gestión de datos; la mayoría se aplican directamente a las implementaciones de ClickStack.
