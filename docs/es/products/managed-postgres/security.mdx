ClickHouse Managed Postgres está diseñado con funciones de seguridad de nivel empresarial para proteger sus datos y cumplir los requisitos de cumplimiento normativo. Esta página cubre la seguridad de red, el cifrado y las políticas de retención de copias de seguridad.

## Inclusión de IP en listas de permitidos {#ip-whitelisting}

Los filtros IP determinan qué direcciones IP de origen pueden conectarse a su instancia de ClickHouse Managed Postgres, y proporcionan control de acceso a nivel de red para proteger la base de datos frente a conexiones no autorizadas.

<div className="ch-image-md">
  <Frame>
    ![Configuración de la Lista de acceso IP](/images/managed-postgres/ip-filters.webp)
  </Frame>
</div>

<div id="configuring-ip-filters">
  ### Configuración de filtros IP {#configuring-ip-filters}
</div>

Para configurar los filtros IP:

1. Ve a la pestaña **Settings**
2. En **IP Filters**, haz clic en **Edit**
3. Agrega las direcciones IP o los rangos CIDR a los que se permitirá la conexión
4. Haz clic en **Save** para aplicar los cambios

Puedes especificar:

* Direcciones IP individuales (p. ej., `203.0.113.5`)
* Rangos CIDR de red (p. ej., `192.168.1.0/24`)
* **Anywhere** para permitir todas las direcciones IP (no se recomienda en producción)
* **Nowhere** para bloquear todas las conexiones

<Warning>
  **Buenas prácticas para producción**

  Si no se configura ningún filtro IP, se permiten conexiones desde cualquier dirección IP. Para cargas de trabajo de producción, restringe el acceso a direcciones IP conocidas o rangos CIDR. Considera limitar el acceso a:

  * Tus servidores de aplicaciones
  * Direcciones IP del gateway de VPN
  * Hosts bastión para acceso administrativo
  * Direcciones IP de pipelines de CI/CD para implementaciones automatizadas
</Warning>

## Cifrado {#encryption}

ClickHouse Managed Postgres cifra sus datos en reposo y en tránsito.

### Cifrado en reposo {#encryption-at-rest}

El cifrado en reposo está habilitado en todas las instancias y no se puede desactivar. Es transparente para sus aplicaciones y no requiere ninguna configuración. Abarca:

* **Almacenamiento NVMe:** archivos de base de datos, logs de transacciones y archivos temporales, cifrados con algoritmos de cifrado estándar del sector.
* **Almacenamiento de objetos:** copias de seguridad completas diarias, archivos WAL incrementales y datos de recuperación a un punto en el tiempo.

### Cifrado en tránsito {#encryption-in-transit}

Todas las conexiones de red a ClickHouse Managed Postgres están protegidas con TLS (Transport Layer Security) para proteger los datos mientras se transfieren entre sus aplicaciones y la base de datos.

<div id="tls-ssl">
  #### Configuración de TLS/SSL {#tls-ssl}
</div>

De forma predeterminada, las conexiones usan cifrado TLS sin verificación de certificados. Para las cargas de trabajo de producción, recomendamos conectarse mediante TLS con verificación de certificados para garantizar que se está comunicando con el servidor correcto.

Para obtener más detalles sobre la configuración de TLS y las opciones de conexión, consulte la página [Conexión](/es/products/managed-postgres/connection#tls).

## AWS PrivateLink {#private-link}

AWS PrivateLink permite la conectividad privada entre tu instancia de ClickHouse Managed Postgres y tu nube privada virtual (VPC) de AWS, sin exponer el tráfico a la Internet pública. Esto proporciona una capa adicional de aislamiento y seguridad de red.

<Info>
  **Se requiere configuración manual**

  AWS PrivateLink está disponible, pero requiere configuración manual por parte del soporte de ClickHouse. Esta funcionalidad es ideal para clientes empresariales con requisitos estrictos de aislamiento de red.
</Info>

### Solicitud de configuración de AWS PrivateLink {#requesting-private-link}

Para habilitar AWS PrivateLink para tu instancia de ClickHouse Managed Postgres:

1. **Ponte en contacto con el soporte de ClickHouse** creando un ticket de soporte

2. **Proporciona la siguiente información**:
   * Tu ID de organización de ClickHouse
   * El ID/hostname del servicio de Postgres
   * Los ID/ARN de las cuentas de AWS con las que quieres conectar el private link
     * (Opcional) Cualquier región distinta de la región de la instancia de Postgres desde la que quieras conectarte

3. **El soporte de ClickHouse**:
   * Aprovisionará el endpoint de Private Link en el lado de ClickHouse Managed Postgres
   * Te proporcionará los detalles de conexión del endpoint, que podrás usar para crear una interfaz de endpoint.

4. **Configura tu AWS PrivateLink**:
   * Crea el AWS PrivateLink yendo a la interfaz de endpoint en la configuración de AWS y usando la configuración proporcionada por el soporte de ClickHouse.
   * Una vez que tu AWS PrivateLink esté en estado &quot;Available&quot;, podrás conectarte usando el nombre DNS privado proporcionado en la UI de AWS.

## GCP Private Service Connect {#gcp-private-service-connect}

GCP Private Service Connect (PSC) permite establecer conectividad privada entre su instancia de ClickHouse Managed Postgres y su nube privada virtual (VPC) de Google Cloud sin exponer el tráfico a internet pública. Esto aporta una capa adicional de aislamiento y seguridad de red.

<Info>
  **Requiere configuración manual**

  GCP Private Service Connect está disponible, pero debe configurarlo manualmente el soporte de ClickHouse. Esta funcionalidad resulta ideal para clientes empresariales con requisitos estrictos de aislamiento de red.
</Info>

### Solicitud de configuración de GCP Private Service Connect {#requesting-gcp-private-service-connect}

El acceso se concede por endpoint de Private Service Connect, no por proyecto de GCP. Solo se aceptará el endpoint que cree y comunique al soporte de ClickHouse. Por eso, la configuración requiere dos intercambios con el equipo de soporte.

Para habilitar GCP Private Service Connect para su instancia de ClickHouse Managed Postgres:

1. **Póngase en contacto con el soporte de ClickHouse** mediante un ticket de soporte

2. **Proporcione la siguiente información**:
   * El ID de su organización de ClickHouse
   * El ID o nombre del host del servicio de Postgres

3. **El soporte de ClickHouse**:
   * Aprovisionará la asociación de servicio de Private Service Connect para ClickHouse Managed Postgres
   * Le proporcionará el ID de la asociación de servicio para que pueda crear un endpoint.

4. **Cree su endpoint de Private Service Connect**:
   * Cree el endpoint de Private Service Connect en su VPC, en la misma región que el servicio de Postgres, con el ID de la asociación de servicio proporcionado por el soporte de ClickHouse. Los endpoints de Private Service Connect son regionales, por lo que no se admiten conexiones entre regiones.

   * La conexión aparecerá como «Pending» en la consola de GCP. Permanecerá en ese estado hasta que el soporte de ClickHouse la acepte.

   * Localice el **ID de conexión de PSC** del endpoint. Puede consultarlo en los detalles del endpoint en la consola de GCP o ejecutar:

     ```bash
     gcloud compute forwarding-rules describe <endpoint-name> --region <region> --format='value(pscConnectionId)'
     ```

   * Envíe el ID de conexión de PSC al soporte de ClickHouse en el mismo ticket de soporte.

5. **El soporte de ClickHouse**:
   * Añadirá su endpoint a la lista de permitidos de la asociación de servicio. La conexión pasará de «Pending» a «Accepted».

6. **Conéctese a su instancia de ClickHouse Managed Postgres**:
   * Una vez que el endpoint esté en estado «Accepted», podrá conectarse a la instancia mediante la IP del endpoint por el puerto `5432` (conexión directa) o `6432` (agrupador de conexiones).
   * La IP del endpoint no tiene un nombre DNS que coincida con el nombre del host de Postgres. Use `sslmode=require` o, si desea usar `sslmode=verify-full`, añada un registro privado en Cloud DNS que asocie el nombre del host de Postgres con la IP del endpoint.

Para conectar otro endpoint a la misma instancia, por ejemplo, desde otra VPC o tras volver a crear un endpoint, repita los pasos 4 y 5: cree el endpoint con el mismo ID de la asociación de servicio y envíe su ID de conexión de PSC al soporte de ClickHouse. Para revocar el acceso de un endpoint, solicite al soporte de ClickHouse que lo retire de la lista de permitidos.

## Retención de copias de seguridad {#backup-retention}

ClickHouse Managed Postgres realiza copias de seguridad de sus datos automáticamente para protegerlos frente a la eliminación accidental, la corrupción y otros escenarios de pérdida de datos.

<div id="retention-policy">
  ### Política de retención {#retention-policy}
</div>

* **Período de retención predeterminado**: 7 días
* **Frecuencia de las copias de seguridad**: copias de seguridad completas diarias + archivado continuo del WAL (cada 60 segundos o 16 MB, lo que ocurra primero)
* **Granularidad de la recuperación**: recuperación a punto en el tiempo dentro del período de retención

### Seguridad de las copias de seguridad {#backup-security}

Las copias de seguridad están [cifradas en reposo](#encryption-at-rest) y se almacenan en buckets de almacenamiento aislados por instancia, con credenciales de alcance limitado para que solo la instancia de Postgres vinculada a la copia de seguridad pueda acceder a ellas.

Para obtener más información sobre las estrategias de copia de seguridad y la recuperación a un punto en el tiempo, consulte la página [Backup and restore](/es/products/managed-postgres/backup-and-restore).
