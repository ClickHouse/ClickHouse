Aunque ClickHouse es conocido por su velocidad y fiabilidad, el rendimiento óptimo se
alcanza dentro de determinados parámetros operativos. Por ejemplo, tener demasiadas tablas,
bases de datos o partes puede afectar negativamente al rendimiento. Para evitarlo, ClickHouse
Cloud aplica límites en varias dimensiones operativas.
A continuación se enumeran los valores predeterminados de estas medidas de protección. Salvo que se indique lo contrario,
estas medidas de protección se aplican a nivel de servicio.

<Tip>
  Si ha alcanzado una de estas medidas de protección, es posible que esté
  implementando su caso de uso de forma no optimizada. Póngase en contacto con [soporte](https://clickhouse.com/support/program) y
  estaremos encantados de ayudarle a perfeccionar su caso de uso para evitar superar estas medidas de protección
  o analizar juntos cómo aumentarlas de forma controlada.
</Tip>

| Dimensión                                         | Límite                                                                                                                         |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Bases de datos**                                | 1000                                                                                                                           |
| **Tablas**                                        | 5000                                                                                                                           |
| **Vistas**                                        | 15000                                                                                                                          |
| **Diccionarios**                                  | 5000                                                                                                                           |
| **Colecciones con nombre** (vista previa privada) | 1000                                                                                                                           |
| **Columnas**                                      | ~1000 (se prefiere el formato ancho al compacto)                                                                               |
| **Particiones**                                   | 50k                                                                                                                            |
| **Partes**                                        | 10k (consulte la configuración de [`max_parts_in_total`](/es/products/cloud/guides/cloud-compatibility#max_parts_in_total-10000)) |
| **Tamaño de parte**                               | 150 GB                                                                                                                         |
| **Servicios por organización**                    | 20 (flexible)                                                                                                                  |
| **Réplicas por servicio**                         | 20 (flexible)                                                                                                                  |
| **Réplicas por warehouse**                        | 50 (flexible)                                                                                                                  |
| **Baja cardinalidad**                             | 10k o menos                                                                                                                    |
| **Claves principales en una tabla**               | 4–5 que filtren suficientemente los datos                                                                                      |
| **Concurrencia de consultas**                     | 1000 (por réplica)                                                                                                             |
| **Ingesta por lotes**                             | Cualquier valor &gt; 1M de filas se divide en bloques de 1M de filas                                                           |

Para conocer los límites de réplicas y escalado de warehouse, consulte [warehouses](/es/products/cloud/features/infrastructure/warehouses#scaling).

Los valores anteriores son medidas de protección predeterminadas. El límite aplicado a un servicio específico puede ser superior al valor mostrado aquí, ya que los servicios más grandes se configuran con mayor holgura. El límite real aplicable a su servicio se incluye en la advertencia que recibe al aproximarse a él. Para los servicios que ya superan los límites de uso anteriores, los límites de tablas y bases de datos se establecen en el recuento actual de tablas y bases de datos del servicio más un 25 %.

<Note>
  Para los servicios de réplica única, el número máximo de bases de datos está limitado a
  100 y el número máximo de tablas está limitado a 500. Además, el almacenamiento
  para los servicios de nivel Basic está limitado a 1 TB. Los límites anteriores de vistas, diccionarios y colecciones con
  nombre son un único valor que se aplica a todos los servicios,
  incluidos los servicios de réplica única.
</Note>

Los límites específicos de advertencia y rechazo de su servicio pueden verificarse consultando system.server&#95;settings. Por ejemplo,

```
SELECT * 
FROM system.server_settings 
WHERE name IN ('max_table_num_to_warn', 'max_table_num_to_throw', 'max_database_num_to_warn', 'max_database_num_to_throw', 'max_view_num_to_warn', 'max_view_num_to_throw', 'max_dictionary_num_to_warn', 'max_dictionary_num_to_throw', 'max_named_collection_num_to_warn', 'max_named_collection_num_to_throw')
```
