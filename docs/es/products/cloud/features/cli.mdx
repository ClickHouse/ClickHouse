La CLI de ClickHouse (`clickhousectl`, alias `chctl`) permite administrar ClickHouse Cloud desde una terminal, un script o un agente de programación. Esta página trata la parte de la CLI dedicada a Cloud. Para obtener información sobre todos los grupos de comandos, el desarrollo local y el comportamiento completo, consulte la [referencia de clickhousectl](/es/concepts/features/interfaces/cli).

## Qué puede gestionar {#what-you-can-manage}

Los comandos `clickhousectl cloud` permiten:

* **Servicios:** crear, escalar, iniciar y detener servicios de ClickHouse Cloud, así como ejecutar SQL sobre ellos mediante la API de consultas.
* **[Managed Postgres](/es/products/managed-postgres/overview) (Beta):** crear servicios de Postgres, réplicas de lectura y restauraciones a un momento dado, y modificar su configuración.
* **[ClickPipes](/es/integrations/clickpipes/home):** ingerir datos desde almacenamiento de objetos, Kafka, Kinesis, Pub/Sub, Postgres, MySQL, MongoDB y BigQuery.
* **[ClickStack](/es/clickstack/overview):** gestionar fuentes, dashboards, alertas, webhooks, búsquedas guardadas y roles en un servicio de [Managed ClickStack](/es/clickstack/deployment/managed).
* **Funciones definidas por el usuario:** probar UDF ejecutables en local y, después, desplegarlas en un servicio de Cloud.
* **Copias de seguridad:** listar copias de seguridad, modificar su programación y restaurar una copia de seguridad en un nuevo servicio.
* **Acceso a la organización:** organizaciones, miembros, invitaciones, claves de API y el registro de actividad.

Ejecute `clickhousectl cloud <command> --help` para consultar las opciones de cualquier comando y los permisos de clave de API que necesita.

## Instalación {#installation}

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

El script instala `~/.local/bin/clickhousectl` y un alias `chctl`. Asegúrese de que `~/.local/bin` esté incluido en su `PATH`. Para npm, pip, uv y los demás métodos de instalación, consulte [Instalación](/es/concepts/features/interfaces/cli#installation).

## Autenticación {#authentication}

El inicio de sesión con OAuth desde el navegador es de solo lectura. Para crear o modificar recursos, se necesita una [clave de API](/es/products/cloud/features/admin-features/api/openapi) con un rol que permita realizar el cambio.

```bash
# Read-only: OAuth device flow in your browser
clickhousectl cloud auth login

# Read and write: prompts for the API key and secret, keeping the secret out of shell history
clickhousectl cloud auth login --interactive

# Alternative for scripts
clickhousectl cloud auth login --api-key <key> --api-secret <secret>
```

Al iniciar sesión, se verifican las credenciales y se muestra la identidad. Puede comprobarla en cualquier momento con `clickhousectl cloud auth whoami`. Si pertenece a varias organizaciones, agregue `--org-id <org-id>` (o `--org-name <name>`) a los comandos de Cloud. En CI, configure `CLICKHOUSE_CLOUD_API_KEY` y `CLICKHOUSE_CLOUD_API_SECRET` en lugar de iniciar sesión. Consulte [Autenticación](/es/concepts/features/interfaces/cli#authentication) para conocer la precedencia de las credenciales y cómo cerrar sesión.

## Ejemplos {#examples}

### Crear y consultar un servicio {#create-and-query-a-service}

```bash
# Create a service. Save the initial password; it is printed only once.
# Omitting --ip-allow allows all addresses (0.0.0.0/0).
clickhousectl cloud service create --name analytics \
  --provider aws --region us-east-1 \
  --ip-allow '203.0.113.10/32=Office'

# Look up the service ID, then run SQL over the Query API
CH_ID=$(clickhousectl cloud service get --name analytics --json | jq -r .id)
clickhousectl cloud service query "$CH_ID" --query "SELECT version()"
```

La operación de creación devuelve el control antes de que el servicio esté en ejecución. Consulte periódicamente `clickhousectl cloud service get "$CH_ID"` hasta que `state` sea `running`.

En la primera consulta autenticada con clave de API, clickhousectl añade su clave de API al Endpoint de la API de Consultas del servicio y, si es necesario, crea el endpoint; no se crea ninguna clave nueva. Use `--no-auto-enable` para que, en su lugar, la operación falle. Con OAuth, `service query` ejecuta sentencias `SELECT` de solo lectura. La API de consultas agota el tiempo de espera tras unos 30 segundos, así que utilice `clickhouse client` para consultas largas y cargas masivas.

### Crear un servicio administrado de Postgres {#create-a-managed-postgres-service}

```bash
clickhousectl cloud postgres create --name app-db \
  --provider aws --region us-east-1 --size c6gd.xlarge --pg-version 18 \
  --ip-allow '203.0.113.10/32:5432=Office'
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output ca.pem
```

Solo `create` devuelve la contraseña y la cadena de conexión, así que guárdelas. Si se omite `--ip-allow`, los puertos 5432 y 6432 quedan abiertos a cualquier dirección. Espere a que `state` sea `running` y, a continuación, conéctese con `psql` utilizando el certificado de CA.

### Inspeccionar ClickPipes, ClickStack y copias de seguridad {#inspect-clickpipes-clickstack-and-backups}

```bash
clickhousectl cloud clickpipe list "$CH_ID"
clickhousectl cloud clickstack source list <clickstack-service-id>
clickhousectl cloud backup list "$CH_ID"
```

Estos comandos de lectura funcionan con OAuth. Para crear un ClickPipe o modificar un recurso de ClickStack se necesita una clave de API; consulte las guías del repositorio que se indican a continuación.

### Desplegar una función definida por el usuario {#deploy-a-user-defined-function}

```bash
# Uploads clickhouse/udfs/my_udf/, waits for the build, then attaches that version to the service
clickhousectl cloud udf deploy my_udf --service "$CH_ID"
```

Pruebe primero la función en un servidor local con `clickhousectl local udf deploy my_udf`.

## Salida JSON y agentes de programación {#json-output}

Los comandos de Cloud aceptan `--json`, y la CLI selecciona JSON automáticamente cuando detecta un agente de programación. En ese caso, `cloud service query` usa `JSONEachRow` de forma predeterminada, por lo que los scripts que analicen su salida deben especificar `--format`, por ejemplo, `--format TabSeparated`. Consulte [Salida JSON](/es/concepts/features/interfaces/cli#json-output) y [Códigos de salida](/es/concepts/features/interfaces/cli#exit-codes). Instale las ClickHouse agent skills con `clickhousectl skills`.
