## short_circuit_function_evaluation {#short_circuit_function_evaluation}

<SettingsInfoBlock type="ShortCircuitFunctionEvaluation" default_value="enable" />

Permite calcular las funciones [if](/es/reference/functions/regular-functions/conditional-functions#if), [multiIf](/es/reference/functions/regular-functions/conditional-functions#multiIf), [and](/es/reference/functions/regular-functions/logical-functions#and) y [or](/es/reference/functions/regular-functions/logical-functions#or) mediante [evaluación de cortocircuito](https://en.wikipedia.org/wiki/Short-circuit_evaluation). Esto ayuda a optimizar la ejecución de expressions complejas en estas funciones y a evitar posibles excepciones (como una división por cero cuando no se espera).

Valores posibles:

* `enable` — Habilita la evaluación de funciones con cortocircuito para las funciones a las que resulta aplicable (pueden lanzar una excepción o ser computacionalmente costosas).
* `force_enable` — Habilita la evaluación de funciones con cortocircuito para todas las funciones.
* `disable` — Deshabilita la evaluación de funciones con cortocircuito.

## short_circuit_function_evaluation_for_nulls {#short_circuit_function_evaluation_for_nulls}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.1"},{"label": "1"},{"label": "Permite ejecutar funciones con argumentos Nullable solo en las filas en las que todos los argumentos tienen valores no NULL"}]}]} />

Optimiza la evaluación de funciones que devuelven NULL cuando algún argumento es NULL. Cuando el porcentaje de valores NULL en los argumentos de la función supera short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls&#95;threshold, el sistema omite evaluar la función fila por fila. En su lugar, devuelve NULL de inmediato para todas las filas, evitando cálculos innecesarios.

Esta configuración controla únicamente una optimización. Las funciones que no pueden ejecutarse sobre el valor predeterminado de sus argumentos —como `parseDateTime`, `IPv4StringToNum` o `intDiv`— siempre omiten las filas que contienen un NULL, independientemente de esta configuración, porque el valor almacenado detrás de un NULL es el valor predeterminado del tipo del argumento y ejecutarlas sobre él lanzaría una excepción con datos que por lo demás son válidos.

## short_circuit_function_evaluation_for_nulls_threshold {#short_circuit_function_evaluation_for_nulls_threshold}

<SettingsInfoBlock type="Double" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.1"},{"label": "1"},{"label": "Umbral de proporción de valores NULL a partir del cual las funciones con argumentos Nullable se ejecutan solo en las filas con valores no NULL en todos los argumentos. Umbral de proporción de valores NULL a partir del cual las funciones con argumentos Nullable se ejecutan solo en las filas con valores no NULL en todos los argumentos. Se aplica cuando la configuración short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls está habilitada.
Cuando la proporción de filas que contienen valores NULL respecto al número total de filas supera este umbral, esas filas con valores NULL no se evaluarán.

## short_circuit_function_evaluation_reorder_arguments {#short_circuit_function_evaluation_reorder_arguments}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nuevo ajuste."}]}]} />

Permite cambiar el orden en que se evalúan los argumentos de las funciones [and](/es/reference/functions/regular-functions/logical-functions#and) y [or](/es/reference/functions/regular-functions/logical-functions#or) con [evaluación en cortocircuito](/es/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation), siempre que ello no altere el resultado ni introduzca excepciones.

* Si el primer argumento es computacionalmente costoso y otro argumento es ligero, el argumento ligero se evalúa primero y el costoso solo se evalúa en las filas cuyo resultado aún no está determinado. Por ejemplo, en `WHERE JSONExtractString(json, 'a') = 'x' AND id < 100`, el JSON solo se analiza en las filas con `id < 100`.
* Los argumentos que se evalúan de forma diferida y no pueden lanzar una excepción se evalúan en orden creciente de tiempo por cada fila que determinan, según lo medido en los bloques anteriores. Los argumentos que pueden lanzar una excepción conservan delante todos los argumentos que los preceden, de modo que, por ejemplo, `x != 0 AND intDiv(1, x) > 0` nunca divide por cero.
