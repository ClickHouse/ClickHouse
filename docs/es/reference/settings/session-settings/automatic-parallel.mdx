## automatic_parallel_replicas_ignore_thresholds {#automatic_parallel_replicas_ignore_thresholds}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Nueva configuración: para pruebas, ignora el límite de threads de lectura del modelo de costes de réplicas paralelas automáticas, de modo que las lecturas pequeñas se decidan mediante la comparación en lugar de resolverse por cortocircuito a causa del límite."}]}]} />

Para pruebas del modelo de costes de réplicas paralelas automáticas: ignora el límite de threads que una lectura puede ocupar de forma útil (derivado de `merge_tree_min_bytes_per_task_for_remote_reading`). Si no se ignora, este límite fija ambos lados de la comparación en el mismo valor cuando una lectura es demasiado pequeña para ocupar `max_threads`, por lo que la comparación se reduce a `0 > output_bytes / replicas` y la consulta se resuelve antes de recurrir al modelo de costes.

Deliberadamente NO afecta a `automatic_parallel_replicas_min_bytes_per_replica`: establézcalo en 0 para desactivar esa condición, que es precisamente su finalidad. Tampoco modifica el dimensionamiento de las tareas de lectura ni impide que se vuelvan a recopilar las estadísticas que hayan sufrido deriva: una decisión tomada con estadísticas desactualizadas no es una decisión tomada por el modelo de costes.

## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "Las réplicas paralelas automáticas ahora rechazan cualquier consulta que repetiría más de la mitad de su lectura en cada réplica. Antes no había ningún límite, que es lo que se sigue obteniendo con el valor 1."}]}]} />

Proporción del volumen de lectura de una consulta que puede leerse en todas las réplicas, en lugar de repartirse entre ellas, expresada como
fracción del total, antes de que las réplicas paralelas automáticas rechacen la consulta.

Solo se reparte la lectura que coordinan las réplicas paralelas; cualquier otra lectura del mismo subárbol se ejecuta íntegramente en cada
réplica. Esas lecturas tardan el mismo tiempo de reloj en ambos casos, por lo que la comparación del modelo de costes no las tiene en cuenta,
pero el cluster realiza `max_parallel_replicas` veces más trabajo para ellas. Este parámetro de configuración limita
ese desperdicio: con el valor predeterminado de 0.5, una consulta cuya lectura coordinada sea inferior a la mitad de todo lo que lee
sigue ejecutándose en un solo nodo, sea cual sea el resultado de la comparación de tiempos.

Establézcalo en 1 para aceptar cualquier cantidad de lectura duplicada, lo que restaura el comportamiento anterior, en el que solo se comparaban los tiempos.

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

Umbral de bytes que deben leerse por réplica para habilitar automáticamente las réplicas paralelas (se aplica solo cuando `automatic_parallel_replicas_mode`=1). 0 significa que no hay umbral.
El número total de bytes que deben leerse se calcula a partir de las estadísticas recopiladas.

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "Nueva configuración"}]}]} />

Habilita el cambio automático a la ejecución con réplicas paralelas en función de las estadísticas recopiladas. Requiere `enable_parallel_replicas = 1`, `parallel_replicas_local_plan = 1` y que se proporcione `cluster_for_parallel_replicas`. Con `enable_parallel_replicas = 2`, se fuerza el uso de réplicas paralelas y no se aplica el modo automático.
0 - deshabilitado, 1 - habilitado, 2 - solo está habilitada la recopilación de estadísticas (el cambio a la ejecución con réplicas paralelas está deshabilitado).

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nuevo ajuste. Las réplicas paralelas automáticas ahora recuerdan, para cada plan de consulta, el límite de la parte del trabajo que corresponde a las réplicas; anteriormente, cada consulta construía el plan con réplicas paralelas para determinarlo."}]}]} />

Permite que las réplicas paralelas automáticas recuerden, para cada plan de consulta, dónde termina la parte del trabajo que corresponde a las réplicas, de modo que,
cuando se repite una consulta cuyas estadísticas descartan las réplicas paralelas, la decisión se tome sin construir el plan con réplicas
paralelas.

Deshabilita los límites recordados. Para medir mediante un benchmark el coste de construir el plan con réplicas paralelas, establezca también
`automatic_parallel_replicas_undecided_retry_after_executions = 0`: los planes cuya última construcción terminó sin una
decisión se omiten con independencia de este parámetro de configuración.

## automatic_parallel_replicas_statistics_drift_ratio {#automatic_parallel_replicas_statistics_drift_ratio}

<SettingsInfoBlock type="Float" default_value="1.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1.5"},{"label": "Nuevo ajuste. La proporción era 2 y no se podía cambiar; ahora las estadísticas se vuelven a recopilar antes a medida que cambian los datos."}]}]} />

Cuánto pueden diferir las filas que selecciona una lectura de las que seleccionaba cuando las réplicas paralelas automáticas recopilaron sus
estadísticas, expresado como la proporción entre el valor mayor y el menor, antes de que las estadísticas se consideren desactualizadas y se vuelvan a recopilar
en lugar de usarse para tomar la decisión.

Las filas son las que selecciona el análisis de índices del initiator, por lo que no se tiene en cuenta la poda que solo realizan las réplicas durante la lectura (por
ejemplo, mediante sus propias cachés de condiciones de consulta). Con una proporción más baja, las estadísticas se vuelven a recopilar antes a medida que la tabla
cambia. Debe ser mayor que 1.

## automatic_parallel_replicas_undecided_retry_after_executions {#automatic_parallel_replicas_undecided_retry_after_executions}

<SettingsInfoBlock type="UInt64" default_value="10" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "10"},{"label": "Nuevo ajuste. Las réplicas paralelas automáticas ahora omiten la construcción del plan con réplicas paralelas durante un número determinado de ejecuciones de un plan de consulta cuya última construcción terminó sin decisión; antes, se construía en cada ejecución."}]}]} />

Número de ejecuciones de un plan de consulta que omiten la construcción del plan con réplicas paralelas después de que su última construcción terminara sin decisión en las réplicas paralelas automáticas: no fue posible comparar los dos planes, el planificador no usó réplicas paralelas
en el plan construido con ellas, un paso del plan no puede recopilar las estadísticas o la recopilación no midió nada. Las ejecuciones concurrentes se turnan: una de cada `automatic_parallel_replicas_undecided_retry_after_executions + 1` vuelve a construir el plan.
Tras el primer resultado de este tipo para un plan de consulta, la siguiente ejecución vuelve a construir el plan de inmediato, por si la primera ejecución pobló otras cachés de estadísticas y las decisiones de planificación cambian.

0 deshabilita el aplazamiento tras resultados sin decisión. Es independiente de `automatic_parallel_replicas_remember_boundary`, que evita la construcción en los planes cuya decisión se tomó a partir de estadísticas.
