## insert_allow_materialized_columns {#insert_allow_materialized_columns}

<SettingsInfoBlock type="Bool" default_value="0" />

Si esta configuración está habilitada, permite usar columnas materializadas en INSERT.

## insert_deduplicate {#insert_deduplicate}

<SettingsInfoBlock type="Bool" default_value="1" />

Activa o desactiva la deduplicación de bloques de `INSERT` (para tablas Replicated*).

Esta configuración solo surte efecto cuando [`deduplicate_insert`](/es/reference/settings/session-settings/deduplicate-insert#deduplicate_insert) se establece en `backward_compatible_choice`.

Valores posibles:

* 0 — Desactivado.
* 1 — Activado.

De forma predeterminada, los bloques insertados en tablas replicadas mediante la instrucción `INSERT` se deduplican (consulte [Replicación de datos](/es/reference/engines/table-engines/mergetree-family/replication)).
En las tablas replicadas, de forma predeterminada solo se deduplican los 100 bloques más recientes de cada partición (consulte [replicated&#95;deduplication&#95;window](/es/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window), [replicated&#95;deduplication&#95;window&#95;seconds](/es/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window_seconds)).
Para las tablas no replicadas, consulte [non&#95;replicated&#95;deduplication&#95;window](/es/reference/settings/merge-tree-settings/other#non_replicated_deduplication_window).

## insert_deduplication_token {#insert_deduplication_token}

Esta configuración permite al usuario definir su propia semántica de deduplicación en MergeTree/ReplicatedMergeTree.
Por ejemplo, al proporcionar un valor único para esta configuración en cada instrucción INSERT,
el usuario puede evitar que se deduplicen los mismos datos insertados.

Valores posibles:

* Cualquier cadena

`insert_deduplication_token` se usa para la deduplicación *solo* cuando no está vacío.

En las tablas replicadas, de forma predeterminada, solo se deduplican las 100 inserciones más recientes de cada partición (consulte [replicated&#95;deduplication&#95;window](/es/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window), [replicated&#95;deduplication&#95;window&#95;seconds](/es/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window_seconds)).
Para las tablas no replicadas, consulte [non&#95;replicated&#95;deduplication&#95;window](/es/reference/settings/merge-tree-settings/other#non_replicated_deduplication_window).

<Note>
  `insert_deduplication_token` se registra por partición, por lo que varias particiones escritas mediante una sola inserción pueden llevar el mismo token. Sin un token, la suma de comprobación de contenido predeterminada se calcula sobre todo el bloque insertado, por lo que una inserción se deduplica solo cuando todos sus datos coinciden con los de una inserción anterior (un reintento), no cuando las filas de una sola partición coinciden por casualidad con las de una inserción distinta.
</Note>

Ejemplo:

```sql
CREATE TABLE test_table
( A Int64 )
ENGINE = MergeTree
ORDER BY A
SETTINGS non_replicated_deduplication_window = 100;

INSERT INTO test_table SETTINGS insert_deduplication_token = 'test' VALUES (1);

-- the next insert won't be deduplicated because insert_deduplication_token is different
INSERT INTO test_table SETTINGS insert_deduplication_token = 'test1' VALUES (1);

-- the next insert will be deduplicated because insert_deduplication_token
-- is the same as one of the previous
INSERT INTO test_table SETTINGS insert_deduplication_token = 'test' VALUES (2);

SELECT * FROM test_table

┌─A─┐
│ 1 │
└───┘
┌─A─┐
│ 1 │
└───┘
```

## insert_null_as_default {#insert_null_as_default}

<SettingsInfoBlock type="Bool" default_value="1" />

Habilita o deshabilita la inserción de [valores predeterminados](/es/reference/statements/create/table#default_values) en lugar de [NULL](/es/reference/syntax#null) en columnas con un tipo de dato no [Nullable](/es/reference/data-types/nullable).
Si el tipo de la columna no es Nullable y esta configuración está deshabilitada, insertar `NULL` provoca una excepción. Si el tipo de la columna es Nullable, los valores `NULL` se insertan sin cambios, independientemente de esta configuración.

Esta configuración se aplica a las consultas [INSERT ... SELECT](/es/reference/statements/insert-into#inserting-the-results-of-select). Ten en cuenta que las subconsultas `SELECT` pueden concatenarse con la cláusula `UNION ALL`.

Valores posibles:

* 0 — Insertar `NULL` en una columna no Nullable provoca una excepción.
* 1 — Se inserta el valor predeterminado de la columna en lugar de `NULL`.

## insert_shard_id {#insert_shard_id}

<SettingsInfoBlock type="UInt64" default_value="0" />

Si no es `0`, especifica el segmento de la tabla [Distributed](/es/reference/engines/table-engines/special/distributed) en el que se insertarán los datos de forma síncrona.

Si el valor de `insert_shard_id` es incorrecto, el servidor generará una excepción.

Para obtener el número de segmentos en `requested_cluster`, puedes consultar la configuración del servidor o usar esta consulta:

```sql
SELECT uniq(shard_num) FROM system.clusters WHERE cluster = 'requested_cluster';
```

Valores posibles:

* 0 — Desactivado.
* Cualquier número entre `1` y `shards_num` de la tabla [Distributed](/es/reference/engines/table-engines/special/distributed) correspondiente.

**Ejemplo**

Consulta:

```sql
CREATE TABLE x AS system.numbers ENGINE = MergeTree ORDER BY number;
CREATE TABLE x_dist AS x ENGINE = Distributed('test_cluster_two_shards_localhost', currentDatabase(), x);
INSERT INTO x_dist SELECT * FROM numbers(5) SETTINGS insert_shard_id = 1;
SELECT * FROM x_dist ORDER BY number ASC;
```

Resultado:

```text
┌─number─┐
│      0 │
│      0 │
│      1 │
│      1 │
│      2 │
│      2 │
│      3 │
│      3 │
│      4 │
│      4 │
└────────┘
```

## insert_squashing_max_memory_ratio {#insert_squashing_max_memory_ratio}

<SettingsInfoBlock type="Double" default_value="0.1125" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0.1125"},{"label": "Nuevo ajuste. El límite de `min_insert_block_size_bytes` en función del memory limit estaba fijado en el código como 0.9 \/ 8 del límite; ahora es configurable."}]}]} />

Limita `min_insert_block_size_bytes` a esta fracción del memory limit del servidor (`max_server_memory_usage`)
en las etapas de agrupación de un `INSERT`: la agrupación para la tabla de destino, la agrupación de los resultados de
las vistas materializadas dependientes y el tamaño de bloque de la fuente de un `INSERT ... SELECT` trivial.

Una etapa de agrupación no retiene un solo bloque de `min_insert_block_size_bytes`, sino varios: acumula el
siguiente bloque mientras se concatena el anterior, el bloque concatenado sigue activo en el destino y los bloques
se miden por su tamaño lógico, mientras que los arrays subyacentes redondean su capacidad al alza. En un servidor con
poca memoria, esto puede provocar que un `INSERT` falle con `MEMORY_LIMIT_EXCEEDED`. Con el valor predeterminado de
`min_insert_block_size_bytes`, el valor predeterminado de este ajuste solo surte efecto con un memory limit inferior a unos 2.2 GiB; un valor
más bajo, como `0.0625`, permite que un `INSERT` en una tabla wide quepa en la memoria de un servidor pequeño.

El límite depende únicamente del memory limit y de este parámetro de configuración, no del número de vistas materializadas ni
de flujos de inserción. Tenga en cuenta que el memory limit puede cambiar en tiempo de ejecución (consulte `memory_worker_dynamic_hard_limit`)
y que, cuando el límite surte efecto, un `INSERT` reintentado puede dividirse en bloques de forma distinta a la del primer intento.

Valores posibles: de `0` a `1`. Establézcalo en `0` para desactivar el límite.
