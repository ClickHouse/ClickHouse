Reescribe predicados de la forma `coalesce(a_1, ..., a_N) <op> const` (o, de forma equivalente, `ifNull`, o con la constante a la izquierda) como la disyunción `(a_1 <op> const) OR (a_1 IS NULL AND a_2 <op> const) OR ... OR (a_1 IS NULL AND ... AND a_{N-1} IS NULL AND a_N <op> const)` antes del análisis de índices, de modo que puedan usarse la clave primaria por columna y los índices de omisión de cada `a_i`. Se manejan formas con constantes parciales como `coalesce(a, 42, b)` y `coalesce(a, b, 42)`: la lista de argumentos se normaliza como el propio `coalesce` (se eliminan los literales `NULL` y los argumentos posteriores al primero que no es `Nullable`) y, si existe, una constante no `NULL` final se emite como la rama final. La reescritura es estrictamente aditiva para la poda de índices; el filtrado en tiempo de ejecución sigue usando el predicado original.
Además, los predicados de igualdad exacta de la forma `nullIf(key, sentinel) = const` (donde `sentinel != const` y los tipos coinciden exactamente) se reescriben como `key = const` para que la clave primaria, la partición y los índices de omisión de `key` puedan descartar gránulos directamente. No se admite la poda por rango ni disyuntiva de `nullIf`.

Permite que `ALTER TABLE ... REPLACE PARTITION ... FROM ...` elimine silenciosamente la partición de destino cuando la tabla de origen no tiene partes en esa partición.

De forma predeterminada, esto no está permitido: `REPLACE PARTITION` desde una tabla de origen que no tiene datos en la partición solicitada genera una excepción, porque en ese caso la operación pasa, en la práctica, a ser un `DROP PARTITION` silencioso en el destino (se eliminan los datos del destino y nada los sustituye), una causa habitual de pérdida accidental de datos (consulta [#23727](https://github.com/ClickHouse/ClickHouse/issues/23727)).

Habilita esta configuración para restaurar el comportamiento anterior, por ejemplo, cuando uses intencionadamente una partición de origen vacía para borrar datos del destino. Si quieres eliminarla sin condiciones, es preferible usar `ALTER TABLE ... DROP PARTITION ...`.

Controla si se permite o no `SETTINGS` después de `FORMAT` en las consultas `INSERT`. No se recomienda usarlo, ya que puede interpretar parte de `SETTINGS` como valores.

Ejemplo:

```sql
INSERT INTO FUNCTION null('foo String') SETTINGS max_threads=1 VALUES ('bar');
```

Pero la siguiente consulta solo funcionará con `allow_settings_after_format_in_insert`:

```sql
SET allow_settings_after_format_in_insert=1;
INSERT INTO FUNCTION null('foo String') VALUES ('bar') SETTINGS max_threads=1;
```

Valores posibles:

* 0 — No permitir.
* 1 — Permitir.

<Note>
  Use esta configuración solo para mantener la compatibilidad con versiones anteriores si sus casos de uso dependen de la sintaxis anterior.
</Note>
