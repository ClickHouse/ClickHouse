## external_storage_push_down_limit {#external_storage_push_down_limit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nueva configuración para trasladar el `LIMIT` de la consulta a la consulta enviada a una base de datos externa cuando sea seguro hacerlo. previous_value=false, de modo que `compatibility` con versiones anteriores a 26.10 restaura el comportamiento previo (sin pushdown)."}]}]} />

Permite trasladar (pushdown) la cláusula `LIMIT` de la consulta a la consulta enviada a una base de datos externa (como MySQL, PostgreSQL o SQLite).

El pushdown no se realiza en los puentes genéricos ODBC/JDBC, ya que no exponen la sintaxis remota de `LIMIT` y algunas de las bases de datos compatibles directamente no admiten la cláusula `LIMIT`.

El `LIMIT` solo se traslada cuando se garantiza que es seguro hacerlo, es decir, cuando todas las cláusulas que lógicamente se aplican antes que él se copian sin cambios en la consulta externa. En concreto, la consulta debe ser un `SELECT` simple sobre una sola tabla:

* no contiene `JOIN`, `ARRAY JOIN`, `SAMPLE` ni `FINAL` (de lo contrario, las filas podrían eliminarse o transformarse localmente, por lo que no conviene limitarlas de antemano);
* la cláusula `WHERE`, si existe, es totalmente compatible y se copia sin cambios en la consulta reescrita (de lo contrario, filtrar después del `LIMIT` remoto eliminaría algunas filas);
* no contiene ninguna otra cláusula ni modificador (como `DISTINCT`, `GROUP BY`, `ORDER BY`, `LIMIT BY`, `WITH TIES`, etc.) que pueda invalidar la limitación previa en el lado remoto debido a la reordenación, la agregación o el filtrado de los datos;
* se admite `OFFSET`: se aplica localmente, por lo que las filas que omite también deben leerse, y el límite enviado a la base de datos externa es `offset + length`;
* la lista del `SELECT` produce exactamente una fila de resultado por cada fila de origen, es decir, no contiene funciones de agregación, funciones de ventana ni `arrayJoin` (también escrito `unnest`), ya que estas se evalúan localmente sobre todas las filas leídas de la tabla externa;
* no se aplica localmente ningún filtro sobre las filas leídas de la tabla externa, como una política de filas o `additional_table_filters` (ese filtro se ejecuta antes del `LIMIT`, por lo que limitar previamente en el lado remoto podría descartar filas que el filtro habría conservado).

Esto reduce la cantidad de datos que se leen de la base de datos externa y que esta envía. Desactive este parámetro de configuración para restaurar el comportamiento anterior en caso de problemas de compatibilidad.
