## azure_validate_etag_on_read {#azure_validate_etag_on_read}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nueva configuración para detectar sobrescrituras concurrentes de blobs de Azure en la misma ubicación durante una lectura, vinculando cada `GET` al `ETag` obtenido al enumerarlos mediante `If-Match` y validando el `ETag` de la respuesta, como hace `s3_validate_etag_on_read` para S3. `compatibility` con versiones anteriores a 26.10 restablece el comportamiento anterior (sin validación)."}]}]} />

Al leer un blob de Azure Blob Storage mediante las funciones de tabla `azureBlobStorage` / `azureBlobStorageCluster` o el motor de tabla `AzureBlobStorage`, vincule cada solicitud `GET` a la generación del blob observada al enumerarlo, enviando su `ETag` en `If-Match`, y compruebe el `ETag` de la respuesta. La lectura de un único archivo genera múltiples solicitudes `GET` de rangos; si el blob se sobrescribe en la misma ubicación entre estas solicitudes (por ejemplo, si un proceso de escritura externo reescribe una clave fija), las lecturas podrían combinar datos de dos generaciones distintas del blob y dar lugar a una suma de comprobación incorrecta o a un error de análisis. El tamaño registrado durante la enumeración también se utiliza como límite superior de la lectura, por lo que solo es válido para la generación para la que se registró. Cuando se detecta una discrepancia, la lectura falla con `AZURE_OBJECT_CHANGED_DURING_READ` en lugar de devolver datos inconsistentes. Desactive esta opción únicamente para workload que lean intencionadamente blobs que se estén sobrescribiendo y puedan tolerar lecturas inconsistentes.
