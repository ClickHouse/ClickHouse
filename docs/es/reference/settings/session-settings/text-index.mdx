## text_index_like_min_pattern_length {#text_index_like_min_pattern_length}

<SettingsInfoBlock type="UInt64" default_value="4" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "4"},{"label": "Nueva configuración"}]}]} />

Longitud mínima de la subcadena alfanumérica buscada en un patrón LIKE/ILIKE, o de una subcadena buscada de `startsWith`/`endsWith`, necesaria para usar la evaluación de LIKE en el índice de texto mediante escaneo del diccionario.
Los patrones más cortos que este umbral coinciden con demasiados tokens del diccionario y se omiten para evitar escaneos costosos.

Con el tokenizador `array`, donde cualquier patrón es apto, el umbral se compara con el número de caracteres que no son comodines en todo el patrón.

Requiere que `use_text_index_like_evaluation_by_dictionary_scan` esté habilitado.

## text_index_posting_list_apply_mode {#text_index_posting_list_apply_mode}

<SettingsInfoBlock type="TextIndexPostingListApplyMode" default_value="lazy" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "lazy"},{"label": "Las consultas sobre índice de texto ahora decodifican las listas de postings bajo demanda con un cursor en lugar de materializarlas en Roaring Bitmaps, lo que reduce el uso de memoria y el tiempo de CPU en consultas selectivas."}]}, {"id": "row-2","items": [{"label": "26.6"},{"label": "materialize"},{"label": "Nueva configuración para el modo diferido de aplicación de listas de postings"}]}]} />

Controla cómo se aplican las listas de postings durante las consultas sobre índice de texto.
&#39;materialize&#39; decodifica inmediatamente las listas de postings en Roaring Bitmaps.
&#39;lazy&#39; (predeterminado) usa decodificación bajo demanda basada en cursores (requiere un formato de índice con un codec serializado).
&#39;lazy&#39; se aplica solo donde es compatible: las consultas con patrones (como `LIKE`) y las partes con un índice escrito por una versión anterior recurren a &#39;materialize&#39;.

## text_index_postings_intersection_algorithm {#text_index_postings_intersection_algorithm}

<SettingsInfoBlock type="TextIndexPostingsIntersectionAlgorithm" default_value="auto" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "auto"},{"label": "Nueva configuración que reemplaza a `text_index_lazy_intersection_density_threshold`: selecciona el algoritmo de intersección de listas de postings en el modo de aplicación diferida de listas de postings. `auto` conserva el comportamiento predeterminado anterior, por lo que `compatibility` no debe modificarlo."}]}]} />

Selecciona el algoritmo con el que se intersecan las listas de postings en el modo de aplicación diferida de listas de postings (`text_index_posting_list_apply_mode = 'lazy'`).

* `auto` (predeterminado): se usa leapfrog solo cuando la lista de postings más dispersa puede omitir bloques empaquetados completos de la más densa; en caso contrario, se usa la intersección de bitmaps por fuerza bruta.
* `bruteforce`: siempre se usa la intersección de bitmaps por fuerza bruta.
* `leapfrog`: siempre se usa la intersección leapfrog.

Las intersecciones de 256 tokens o más siempre usan leapfrog.
