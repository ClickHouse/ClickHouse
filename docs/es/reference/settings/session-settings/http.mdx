## http_allow_database_as_path {#http_allow_database_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nueva configuración para reconocer un nombre de base de datos en la ruta URL de las solicitudes HTTP."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Habilitada de forma predeterminada: la interfaz HTTP interpreta un componente `\/database\/` de la ruta URL como base de datos actual."}]}]} />

Si está habilitada, la interfaz HTTP reconoce un componente `/database/` en la ruta URL y lo utiliza como base de datos actual.

Esta configuración por usuario determina si se interpreta una solicitud enrutada de estilo de ruta. El enrutamiento propiamente dicho se controla globalmente mediante la configuración del servidor `http_allow_path_requests` (activada de forma predeterminada), que debe habilitarse para que la interfaz HTTP enrute una solicitud de estilo de ruta (como `/my_db/my_table.csv`) al manejador de consultas; esta decisión de enrutamiento se toma antes de autenticar la solicitud, por lo que no puede depender de una configuración por usuario. Cuando `http_allow_path_requests` está desactivada, las rutas desconocidas devuelven un simple `404`. Tras el enrutamiento, esta configuración se vuelve a comprobar con la configuración efectiva del usuario autenticado, por lo que puede deshabilitarse selectivamente para cada usuario, rol o perfil.

## http_allow_filters_as_path {#http_allow_filters_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nueva configuración para reconocer filtros `name=value` de estilo Hive en la ruta URL de las solicitudes HTTP."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Habilitada de forma predeterminada: la interfaz HTTP interpreta los componentes de ruta `\/name=value\/` como filtros combinados con `AND`."}]}]} />

Si está habilitada, la interfaz HTTP reconoce componentes `/name=value/` en la ruta (estilo de particionamiento Hive) y los traduce en filtros combinados con AND. También reconoce los operadores `>`, `<`, `>=`, `<=`, `!=`, `<>`.

Al igual que [`http_allow_database_as_path`](/es/reference/settings/session-settings/http#http_allow_database_as_path), esta es una configuración por usuario; el enrutamiento de las solicitudes de estilo de ruta se controla globalmente mediante la configuración de servidor `http_allow_path_requests` (el enrutamiento se realiza antes de la autenticación).

## http_allow_filters_as_unrecognized_url_parameters {#http_allow_filters_as_unrecognized_url_parameters}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nueva configuración para tratar los parámetros URL no reconocidos como expresiones de filtro en solicitudes HTTP."}]}]} />

Si está habilitada, cualquier parámetro URL que no se reconozca como parámetro, configuración o prefijo `param_*` conocido se trata como un filtro y se combina mediante AND. Se admiten dos formas:

* Un `name=value` simple se convierte en la igualdad `` `name` = 'value' `` (el identificador se delimita con comillas invertidas y el valor se entrecomilla como un literal de cadena).
* Un operador de comparación (`!=`, `>`, `<`, `>=`, `<=`, `<>`) lo convierte en una comparación: ya sea separado dentro del parámetro (`?a!=2`, `?a>=2`) o escrito en línea cuando la URL no contiene un `=` por el que separar (`?a<>2`, `?f(x)>3`), en cuyo caso el `name[=value]` reconstruido se analiza como una expresión SQL completa.

Está deshabilitada de forma predeterminada, a diferencia de las demás configuraciones `http_allow_*`: se aplica a todas las solicitudes de la interfaz HTTP, incluido el endpoint `/?query=...`, por lo que, al habilitarla, cualquier parámetro URL no reconocido que añada un Client (un identificador de solicitud, una firma, un parámetro para evitar la caché) se convierte en un filtro de la consulta. En ese caso, un nombre de configuración mal escrito ya no se notifica como `UNKNOWN_SETTING`, sino que falla con `UNKNOWN_IDENTIFIER` (o, si el nombre coincide con el de una columna, filtra el resultado sin avisar), y el valor del parámetro pasa a formar parte del texto de la consulta, donde no se enmascara como ocurre con el `Request URI` en el log.

## http_allow_table_as_file {#http_allow_table_as_file}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nueva configuración para reconocer un nombre de tabla en la ruta URL de las solicitudes HTTP, con extensiones opcionales de formato\/compresión."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Habilitada de forma predeterminada: la interfaz HTTP interpreta el último componente de la ruta URL como `table[.format[.compression]]` y responde con `SELECT * FROM table`."}]}]} />

Si está habilitada, la interfaz HTTP reconoce el último componente de la ruta URL como un nombre de tabla con el formato `table`, `table.format` o `table.format.compression`. La ruta se interpreta como `SELECT * FROM table`.

Al igual que [`http_allow_database_as_path`](/es/reference/settings/session-settings/http#http_allow_database_as_path), esta configuración es por usuario; el enrutamiento de las solicitudes de estilo de ruta se controla globalmente mediante la configuración de servidor `http_allow_path_requests` (el enrutamiento se realiza antes de la autenticación).

## http_make_head_request {#http_make_head_request}

<SettingsInfoBlock type="Bool" default_value="1" />

La configuración `http_make_head_request` permite ejecutar una solicitud `HEAD` al leer datos desde HTTP para obtener información sobre el archivo que se va a leer, como su tamaño. Dado que está habilitada de forma predeterminada, puede ser conveniente desactivar esta configuración cuando el servidor no admita solicitudes `HEAD`.

## http_native_compression_disable_checksumming_on_decompress {#http_native_compression_disable_checksumming_on_decompress}

<SettingsInfoBlock type="Bool" default_value="0" />

Habilita o deshabilita la verificación de la suma de comprobación al descomprimir los datos de una solicitud HTTP POST del client. Se usa solo con el formato de compresión nativo de ClickHouse (no se usa con `gzip` ni `deflate`).

Para obtener más información, lea la [descripción de la interfaz HTTP](/es/concepts/features/interfaces/http).

Valores posibles:

* 0 — Deshabilitado.
* 1 — Habilitado.

## http_x_clickhouse_format_overrides_output_format {#http_x_clickhouse_format_overrides_output_format}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Controla si el encabezado HTTP `X-ClickHouse-Format` es un alias de `output_format` (y sobrescribe la cláusula `FORMAT` de la consulta), como ocurre desde la versión 26.8, o de `default_format`, como ocurría antes de la 26.8. Esta entrada documenta retroactivamente el cambio de la 26.8 para que `compatibility` con versiones anteriores a la 26.8 restaure el comportamiento anterior del encabezado."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Configuración añadida en la 26.10 para controlar el cambio del encabezado HTTP `X-ClickHouse-Format` introducido en la 26.8. El cambio semántico relevante se registra en el bloque de la 26.8, de modo que `compatibility = '26.7'` lo revierte, mientras que `compatibility = '26.8'` y `'26.9'` mantienen el comportamiento de esas versiones; esta entrada existe para que la comprobación de actualización acepte el nombre recién introducido."}]}]} />

Controla a qué configuración corresponde el encabezado HTTP `X-ClickHouse-Format`.

Si está habilitada (valor predeterminado), el encabezado es un alias de la configuración `output_format`: actúa como una sobrescritura explícita del formato de respuesta que prevalece sobre la cláusula `FORMAT` de la consulta y sobre la extensión de archivo en la ruta de la URL.

Si está deshabilitada, el encabezado es un alias de la configuración `default_format`, como ocurría antes de la versión 26.8: solo determina el formato que se usa cuando la consulta no tiene cláusula `FORMAT` y no se aplica ninguna otra sobrescritura de formato.

En ambos casos, el encabezado prevalece sobre el parámetro de URL del mismo nombre (`output_format` o `default_format`, respectivamente) y nunca altera la forma en que se analiza el cuerpo de la solicitud de un `INSERT`.

Esta es una configuración de compatibilidad para la interfaz HTTP: el encabezado se procesa antes de analizar la consulta, por lo que debe proporcionarse mediante un parámetro de URL o un perfil de usuario, y no mediante una cláusula `SETTINGS` dentro de la consulta. Al igual que `output_format` y `default_format`, siempre puede modificarse en modo de solo lectura (`readonly = 1`), por lo que un usuario de solo lectura puede pasarla como parámetro de URL.

## http_zlib_compression_level {#http_zlib_compression_level}

<SettingsInfoBlock type="Int64" default_value="3" />

Establece el nivel de compresión de datos en la respuesta a una solicitud HTTP si [enable&#95;http&#95;compression = 1](/es/reference/settings/session-settings/enable#enable_http_compression).

Posibles valores: números del 1 al 12. Los niveles superiores a `9` requieren la compilación predeterminada con `libdeflate`; una compilación sin `libdeflate` admite niveles del 1 al 9.
