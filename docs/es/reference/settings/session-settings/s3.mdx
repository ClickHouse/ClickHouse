## s3_base {#s3_base}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": ""},{"label": "Nueva configuración para especificar la URL base para resolver URL relativas en la función de tabla s3 y el motor de tabla S3."}]}]} />

La URL base que se utiliza para resolver URL relativas en la función de tabla [s3](/es/reference/functions/table-functions/s3) y el motor de tabla [S3](/es/reference/engines/table-engines/integrations/s3), así como en las funciones de tabla que comparten su configuración (`s3Cluster`, `gcs`, `oss`).

Cuando se configura, una URL sin esquema se resuelve con respecto a `s3_base` conforme a RFC 3986, siguiendo las mismas reglas que [url&#95;base](/es/reference/settings/session-settings/url#url_base). Las URL que ya contienen un esquema se utilizan tal cual.

Por ejemplo, si `s3_base` es `s3://clickhouse-public-datasets/`, `s3('hits_compatible/hits.csv')` lee `s3://clickhouse-public-datasets/hits_compatible/hits.csv`.

La URL base puede usar cualquier formato aceptado por la función de tabla `s3`, por ejemplo, `s3://bucket/`, `https://bucket.s3.amazonaws.com/` o `https://endpoint/bucket/`.

## s3_create_new_file_on_insert {#s3_create_new_file_on_insert}

<SettingsInfoBlock type="Bool" default_value="0" />

Habilita o deshabilita la creación de un archivo nuevo con cada inserción en las tablas con motor S3. Si se habilita, en cada inserción se creará un nuevo objeto en S3 con la clave, siguiendo un patrón como este:

inicial: `data.Parquet.gz` -&gt; `data.1.Parquet.gz` -&gt; `data.2.Parquet.gz`, etc.

Valores posibles:

* 0 — la consulta `INSERT` crea un archivo nuevo o falla si el archivo ya existe y no se ha configurado s3&#95;truncate&#95;on&#95;insert.
* 1 — la consulta `INSERT` crea un archivo nuevo con cada inserción usando un sufijo (a partir del segundo) si no se ha configurado s3&#95;truncate&#95;on&#95;insert.

Consulta más detalles [aquí](/es/integrations/connectors/data-ingestion/AWS/integrating-s3-with-clickhouse#inserting-data).

## s3_slow_all_threads_after_network_error {#s3_slow_all_threads_after_network_error}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "1"},{"label": "Nueva configuración"}]}]} />

Cuando se establece en `true`, todos los hilos que ejecutan solicitudes a S3 hacia el mismo endpoint de copia de seguridad se ralentizan
después de que una sola solicitud a S3 encuentre un error de red reintentable, como un timeout de socket.
Cuando se establece en `false`, cada hilo gestiona el backoff de las solicitudes a S3 de forma independiente de los demás.

## s3_truncate_on_insert {#s3_truncate_on_insert}

<SettingsInfoBlock type="Bool" default_value="0" />

Habilita o deshabilita el truncado antes de las inserciones en las tablas con motor S3. Si está deshabilitado, se lanzará una excepción al intentar insertar si ya existe un objeto en S3.

Valores posibles:

* 0 — la consulta `INSERT` crea un archivo nuevo o falla si el archivo ya existe y `s3_create_new_file_on_insert` no está configurado.
* 1 — la consulta `INSERT` reemplaza el contenido existente del archivo con los nuevos datos.

Consulta más detalles [aquí](/es/integrations/connectors/data-ingestion/AWS/integrating-s3-with-clickhouse#inserting-data).

## s3_use_adaptive_timeouts {#s3_use_adaptive_timeouts}

<SettingsInfoBlock type="Bool" default_value="1" />

Cuando se establece en `true`, en todas las solicitudes a S3 los dos primeros intentos se realizan con tiempos de espera de envío y recepción reducidos.
