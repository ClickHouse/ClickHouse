## enable_adaptive_codec_selection {#enable_adaptive_codec_selection}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nueva configuración."}]}]} />

Cuando está habilitada, las operaciones de fusión y las mutaciones eligen un códec por bloque para las columnas que usan el códec predeterminado (sin cláusula `CODEC` o con `CODEC(Default)`).
Los candidatos son el códec predeterminado de la tabla (consulte la configuración `default_compression_codec`), `NONE` y códecs especializados adecuados para el tipo de columna.
Se elige la salida más pequeña. Por lo tanto, la compresión nunca es peor que la predeterminada y los bloques no comprimibles se almacenan sin procesar.
Una columna cuyo códec predeterminado incluye cifrado (por ejemplo, `AES_128_GCM_SIV`) nunca se selecciona de forma adaptativa, por lo que el cifrado siempre se aplica.
Los códecs por bloque se indican mediante la función de tabla [`mergeTreeCodecBlockCounts`](/es/reference/functions/table-functions/index).

## enable_mixed_granularity_parts {#enable_mixed_granularity_parts}

<SettingsInfoBlock type="Bool" default_value="1" />

Habilita o deshabilita el control del tamaño del gránulo mediante la
configuración `index_granularity_bytes`. Antes de la versión 19.11, solo existía la
configuración `index_granularity` para restringir el tamaño del gránulo. La
configuración `index_granularity_bytes` mejora el rendimiento de ClickHouse al
seleccionar datos de tablas con filas grandes (decenas o cientos de megabytes).
Si tiene tablas con filas grandes, puede habilitar esta configuración en dichas tablas
para mejorar la eficiencia de las consultas `SELECT`.
