<div id="always_fetch_merged_part">
  ## always_fetch_merged_part
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

Si es true, esta réplica nunca combina partes y siempre descarga partes fusionadas
de otras réplicas.

Valores posibles:

* true, false

<div id="always_fetch_mutated_part">
  ## always_fetch_mutated_part
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nueva configuración para que una réplica obtenga partes mutadas en lugar de ejecutar mutaciones localmente"}]}]} />

Si es true, esta réplica nunca ejecuta entradas `MUTATE_PART` del registro de replicación
(mutaciones normales como `ALTER TABLE ... UPDATE/DELETE`) y siempre
descarga las partes mutadas resultantes de otras réplicas.

Al menos una réplica debe tener esta configuración desactivada; de lo contrario, las mutaciones
no podrán finalizar.

Esta configuración no afecta a las partes de parche creadas por actualizaciones ligeras:
se siguen aplicando localmente al fusionarse las partes. Active también
`always_fetch_merged_part` para descargar las fusiones (incluida la
aplicación de partes de parche) en otras réplicas.

Dado que esta réplica no ejecuta mutaciones y el estado de error de una mutación
es local para cada réplica, una espera síncrona en esta réplica
no puede detectar errores de mutación que se produzcan en las réplicas que ejecutan
la mutación. Por lo tanto, las mutaciones síncronas (`mutations_sync` = 1
o 2) y las consultas `ALTER` síncronas que modifican datos
(`alter_sync` = 1 o 2) se rechazan en dicha réplica con un
error `SUPPORT_IS_DISABLED`, en lugar de realizar una espera que quedaría bloqueada si la
mutación falla. Use `mutations_sync` = 0 (`alter_sync` = 0) o ejecute
estas consultas en una réplica que ejecute mutaciones.

Valores posibles:

* true, false
