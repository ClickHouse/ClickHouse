Estos ajustes corresponden a la configuración del servidor de ClickHouse y se generan automáticamente a partir del código fuente de ClickHouse.

## allow_feature_tier {#allow_feature_tier}

<SettingsInfoBlock type="UInt32" default_value="0" changeable_without_restart="Yes" />

Controla si el usuario puede cambiar configuraciones relacionadas con los distintos niveles de funcionalidades.

* `0` - Se permiten cambios en cualquier configuración (experimental, vista previa privada, beta, producción).
* `1` - Solo se permiten cambios en configuraciones de funcionalidades en vista previa privada, beta y de producción. Se rechazan los cambios en configuraciones experimentales.
* `2` - Solo se permiten cambios en configuraciones de funcionalidades beta y de producción. Se rechazan los cambios en configuraciones experimentales o en vista previa privada.
* `3` - Solo se permiten cambios en configuraciones de producción. Se rechazan los cambios en configuraciones experimentales, en vista previa privada o beta.

Esto equivale a aplicar una restricción readonly a todas las funcionalidades `EXPERIMENTAL` / `PRIVATE PREVIEW` / `BETA`.

Se rechaza una sentencia que afecta a un usuario, un rol o un perfil de configuración cuando asigna a una configuración de este tipo un valor distinto
del vigente en la sesión que la ejecuta. También se rechaza cuando modifica una configuración de este tipo para algún usuario, incluso
sin mencionar ninguna configuración: al conceder o revocar un rol que incluya una, asignar un perfil de configuración,
eliminar un rol o un perfil, o eliminar una sobrescritura por omisión. Un usuario definido mediante SQL no puede iniciar sesión si su propia configuración o
la de sus roles contiene un valor de este tipo. Nunca se rechazan las configuraciones que el propio servidor aplica mediante
el archivo de configuración ni los usuarios definidos en él. La configuración `compatibility` mantiene una
configuración de un nivel deshabilitado en su valor predeterminado, en lugar de aplicar el valor predeterminado de la versión anterior.

<Note>
  Un valor de `0` significa que se pueden cambiar todas las configuraciones.
</Note>

<Note>
  `2` anteriormente significaba &quot;solo configuraciones de producción&quot;. Ahora también permite configuraciones beta, por lo que una configuración
  que fijaba `2` para permitir solo configuraciones de producción debe usar `3`.
</Note>

## allow_impersonate_user {#allow_impersonate_user}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />Habilita o deshabilita la funcionalidad IMPERSONATE (EXECUTE AS target&#95;user). Esta configuración está obsoleta.

## allow_implicit_no_password {#allow_implicit_no_password}

Prohíbe crear un usuario sin contraseña, a menos que se especifique explícitamente &#39;IDENTIFIED WITH no&#95;password&#39;.

* **Predeterminado:** `true`

```xml
<allow_implicit_no_password>1</allow_implicit_no_password>
```

## allow_no_password {#allow_no_password}

Indica si se permite o no el tipo de contraseña no segura `no_password`.

* **Predeterminado:** `true`

```xml
<allow_no_password>1</allow_no_password>
```

## allow_plaintext_password {#allow_plaintext_password}

Indica si se permiten o no los tipos de contraseña en texto plano (inseguros).

* **Predeterminado:** `true`

```xml
<allow_plaintext_password>1</allow_plaintext_password>
```

## allow_use_jemalloc_memory {#allow_use_jemalloc_memory}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />Permite usar la memoria de jemalloc.
