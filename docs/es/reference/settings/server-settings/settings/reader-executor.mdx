Estos ajustes configuran el servidor de ClickHouse y se generan automáticamente a partir del código fuente de ClickHouse.

## reader_executor_memory_pressure_critical_level_pct {#reader_executor_memory_pressure_critical_level_pct}

<SettingsInfoBlock type="UInt64" default_value="95" changeable_without_restart="Yes" />Umbral de presión de memoria a partir del cual el `ReaderExecutor` experimental pasa al nivel de presión de memoria `Critical`, que aplica la reducción más agresiva de la ventana de lectura. Consulte `reader_executor_memory_pressure_elevated_level_pct` para conocer los ámbitos, el rango y las reglas de ordenación.

## reader_executor_memory_pressure_elevated_level_pct {#reader_executor_memory_pressure_elevated_level_pct}

<SettingsInfoBlock type="UInt64" default_value="75" changeable_without_restart="Yes" />Umbral de presión de memoria, expresado como porcentaje del hard limit de un memory tracker, a partir del cual el `ReaderExecutor` experimental entra en el nivel de presión de memoria `Elevated` y empieza a reducir su ventana de lectura. Los umbrales se aplican de forma independiente a tres ámbitos —el total del server (`max_server_memory_usage`), el usuario (`max_memory_usage_for_user`) y la consulta (`max_memory_usage`)— y un reader toma el más alto de los tres, de modo que una consulta próxima a su propio límite reduce su window aunque el server esté idle. Un ámbito sin hard limit no aporta nada. Debe estar en `[1, 100]` y cumplir `elevated <= high <= critical`; una terna fuera de rango o desordenada se rechaza al arrancar y al ejecutar `SYSTEM RELOAD CONFIG`. El valor cero se rechaza porque un `elevated` de 0 dejaría todos los ámbitos en `Elevated`, incluidos los que no tienen hard limit.

Consulte `reader_executor_memory_pressure_elevated_level_pct` para conocer los ámbitos, el rango y las reglas de ordenación.
