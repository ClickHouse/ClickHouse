Estos ajustes configuran el servidor de ClickHouse y se generan automáticamente a partir del código fuente de ClickHouse.

<div id="default_database">
  ## default_database
</div>

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="No" />El nombre de la base de datos predeterminada.

<div id="default_password_type">
  ## default_password_type
</div>

Establece el tipo de contraseña que se asignará automáticamente en consultas como `CREATE USER u IDENTIFIED BY 'p'`.

Los valores aceptados son:

* `plaintext_password`

* `sha256_password`

* `double_sha1_password`

* `bcrypt_password`

* **Predeterminado:** `sha256_password`

```xml
<default_password_type>sha256_password</default_password_type>
```

<div id="default_profile">
  ## default_profile
</div>

Perfil de configuración predeterminado. Los perfiles de configuración están en el archivo especificado en la configuración `user_config`.

* **Predeterminado:** `default`

**Ejemplo**

```xml
<default_profile>default</default_profile>
```

<div id="default_session_timeout">
  ## default_session_timeout
</div>

Tiempo de espera predeterminado de la sesión, en segundos.

* **Predeterminado:** `60`

```xml
<default_session_timeout>60</default_session_timeout>
```

<div id="default_session_user">
  ## default_session_user
</div>

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="No" />

El nombre de usuario que se usa para la autenticación cuando un cliente se conecta sin especificar uno: una solicitud HTTP sin el parámetro `user` ni la cabecera `X-ClickHouse-User`, un paquete `Hello` del protocolo nativo con un nombre de usuario vacío, un handshake de MySQL o PostgreSQL con un nombre de usuario vacío, una consulta gRPC sin `user_name`, una llamada de Arrow Flight sin la cabecera `authorization` (o con credenciales Basic que tengan un nombre de usuario vacío), o un mensaje `auth` de WebSocket del [terminal web](/es/concepts/features/interfaces/web-terminal) con el campo `user` omitido o vacío.

El nombre de usuario vacío se resuelve a este valor antes de la autenticación, por lo que la conexión sigue sujeta a la autenticación del usuario sustituido: se aplican la contraseña, la red y otras comprobaciones de acceso habituales. Un nombre de usuario vacío es simplemente un alias del nombre de usuario configurado, y aceptarlo no concede ningún acceso adicional al que ya se obtiene al especificar explícitamente el mismo nombre de usuario. En las versiones anteriores a la introducción de esta configuración, el uso de `default` como alternativa para un nombre de usuario vacío solo existía en la ruta HTTP simple mediante parámetros de consulta, las consultas gRPC, las llamadas de Arrow Flight y el terminal web, mientras que los protocolos nativo, MySQL y PostgreSQL rechazaban un nombre de usuario vacío; ahora todos lo aceptan. La autenticación HTTP Basic con un nombre de usuario vacío y las solicitudes con `X-ClickHouse-Key` pero sin `X-ClickHouse-User` también rechazaban un nombre de usuario vacío antes de que se introdujera esta configuración.

Si se establece en una cadena vacía, se rechazan las conexiones sin nombre de usuario. Los handler HTTP con un usuario fijo (la clave `user` dentro de `handler` de una regla `http_handlers`, o la clave `user` dentro de `handler` de una regla `prometheus.handlers`) se autentican como el usuario configurado y no se ven afectados.

Cuando la sección `session_log` está habilitada en la configuración del servidor, cada uno de estos rechazos se registra en [`system.session_log`](/es/reference/system-tables/session_log) como un evento `LoginFailure` con `user` vacío, lo que permite auditar en cada interfaz las conexiones prohibidas sin nombre de usuario.

El usuario de sesión predeterminado nunca se aplica a las conexiones entre servidores: estas se identifican con un marcador especial en lugar de un nombre de usuario y se autentican mediante el secreto del clúster y el usuario inicial.

El valor se puede sobrescribir para un endpoint específico de un protocolo componible mediante la clave `default_session_user` en la sección `protocols`; consulte [Protocolos componibles](/es/concepts/features/configuration/server-config/composable-protocols).
