## Descripción {#description}

Contiene entradas de registro con información sobre diversas operaciones de almacenamiento de blobs, como cargas y eliminaciones.

Es seguro truncar o eliminar esta tabla en cualquier momento.

## Columnas {#columns}

* `hostname` ([LowCardinality(String)](/es/reference/data-types/lowcardinality)) — Nombre de host del servidor que ejecuta la consulta.
* `clickhouse_version` ([LowCardinality(String)](/es/reference/data-types/lowcardinality)) — Versión del servidor ClickHouse que produjo la fila.
* `system_processor` ([LowCardinality(String)](/es/reference/data-types/lowcardinality)) — Arquitectura de CPU del servidor ClickHouse que produjo la fila.
* `event_date` ([Date](/es/reference/data-types/date)) — Fecha del evento.
* `event_time` ([DateTime](/es/reference/data-types/datetime)) — Hora del evento.
* `event_time_microseconds` ([DateTime64(6)](/es/reference/data-types/datetime64)) — Hora del evento con precisión de microsegundos.
* `event_type` ([Enum8(&#39;Upload&#39; = 1, &#39;Delete&#39; = 2, &#39;MultiPartUploadCreate&#39; = 3, &#39;MultiPartUploadWrite&#39; = 4, &#39;MultiPartUploadComplete&#39; = 5, &#39;MultiPartUploadAbort&#39; = 6, &#39;Read&#39; = 7, &#39;Copy&#39; = 8)](/es/reference/data-types/enum)) — Tipo de evento. Valores posibles: &#39;Upload&#39;, &#39;Delete&#39;, &#39;MultiPartUploadCreate&#39;, &#39;MultiPartUploadWrite&#39;, &#39;MultiPartUploadComplete&#39;, &#39;MultiPartUploadAbort&#39;, &#39;Read&#39;, &#39;Copy&#39;
* `query_id` ([String](/es/reference/data-types/string)) — Identificador de la consulta asociada al evento, si existe.
* `thread_id` ([UInt64](/es/reference/data-types/int-uint)) — Identificador del hilo que realiza la operación.
* `thread_name` ([String](/es/reference/data-types/string)) — Nombre del hilo que realiza la operación.
* `disk_name` ([LowCardinality(String)](/es/reference/data-types/lowcardinality)) — Nombre del disco asociado.
* `bucket` ([String](/es/reference/data-types/string)) — Nombre del bucket.
* `remote_path` ([String](/es/reference/data-types/string)) — Ruta al recurso remoto.
* `local_path` ([String](/es/reference/data-types/string)) — Ruta al archivo de metadatos en el sistema local, que hace referencia al recurso remoto.
* `source_bucket` ([String](/es/reference/data-types/string)) — Nombre del bucket desde el que se copió el objeto, en el caso del evento &#39;Copy&#39;. Vacío para los demás eventos.
* `source_remote_path` ([String](/es/reference/data-types/string)) — Ruta al objeto desde el que se copiaron los datos, en el caso del evento &#39;Copy&#39;. Vacío para los demás eventos.
* `data_size` ([UInt64](/es/reference/data-types/int-uint)) — Tamaño de los datos implicados en la operación.
* `elapsed_microseconds` ([UInt64](/es/reference/data-types/int-uint)) — Tiempo transcurrido de la operación, en microsegundos.
* `connection_id` ([UInt64](/es/reference/data-types/int-uint)) — Identificador de la conexión HTTP por la que se realizó la operación, único dentro del proceso del servidor. Agrupe por este valor para seguir una conexión concreta: el SO reutiliza los puertos y los inodos de socket en cuanto se cierra un socket, por lo que estos no permiten distinguir conexiones consecutivas. 0 si no se puede atribuir una única solicitud HTTP a esta fila: la operación no usó ninguna conexión HTTP; usó más de una (una escritura reintentada se registra como una sola fila cuyo tiempo transcurrido abarca todos sus intentos, y ninguna conexión individual la describe); o compartió una solicitud con otras filas (una eliminación por lotes escribe una fila `Delete` por objeto y atribuye la conexión solo a la primera de ellas). Todas las columnas `connection_*` solo tienen sentido cuando `connection_id` es distinto de 0; en caso contrario, todas valen 0.
* `connection_local_port` ([UInt16](/es/reference/data-types/int-uint)) — Puerto TCP local de esa conexión. Solo es único entre los sockets abiertos en un mismo momento; úselo para cruzarlo con una captura de paquetes o con una fila de /proc/net/tcp obtenida en ese momento.
* `connection_socket_inode` ([UInt64](/es/reference/data-types/int-uint)) — Inodo del socket de esa conexión, según lo devuelve fstat. Se aplica la misma salvedad que al puerto: solo es único mientras el socket permanece abierto. 0 si el SO no expone ningún inodo para los sockets, como ocurre en macOS.
* `connection_requests` ([UInt32](/es/reference/data-types/int-uint)) — Número de solicitudes que la conexión ya había enviado antes de esta. 0 indica que se trata de su primera solicitud, siempre que `connection_id` sea distinto de 0.
* `connection_age_microseconds` ([UInt64](/es/reference/data-types/int-uint)) — Tiempo transcurrido desde que se estableció el socket TCP de la conexión. Se restablece con cada reconexión, por lo que mide la vida útil del socket y no la del objeto de sesión.
* `connection_idle_microseconds` ([UInt64](/es/reference/data-types/int-uint)) — Tiempo que la conexión permaneció inactiva en el grupo antes de asignarse a esta operación. 0 en la primera solicitud de una conexión y también cuando `connection_id` es 0.
* `error_code` ([Int32](/es/reference/data-types/int-uint)) — Código de error de la operación. 0 si no hubo ningún error.
* `error` ([String](/es/reference/data-types/string)) — Mensaje de error asociado al evento, si existe.

## Ejemplo {#example}

Supongamos que una operación de almacenamiento de blobs sube un archivo y se registra un evento:

```sql
SELECT * FROM system.blob_storage_log WHERE query_id = '7afe0450-504d-4e4b-9a80-cd9826047972' ORDER BY event_date, event_time_microseconds \G
```

```text
Row 1:
──────
hostname:                clickhouse.eu-central1.internal
event_date:              2023-10-31
event_time:              2023-10-31 16:03:40
event_time_microseconds: 2023-10-31 16:03:40.481437
event_type:              Upload
query_id:                7afe0450-504d-4e4b-9a80-cd9826047972
thread_id:               2381740
disk_name:               disk_s3
bucket:                  bucket1
remote_path:             rrr/kxo/tbnqtrghgtnxkzgtcrlutwuslgawe
local_path:              store/654/6549e8b3-d753-4447-8047-d462df6e6dbe/tmp_insert_all_1_1_0/checksums.txt
data_size:               259
error:
```

En este ejemplo, la operación de carga se asoció con la consulta `INSERT` con ID `7afe0450-504d-4e4b-9a80-cd9826047972`. El archivo local de metadatos `store/654/6549e8b3-d753-4447-8047-d462df6e6dbe/tmp_insert_all_1_1_0/checksums.txt` hace referencia a la ruta remota `rrr/kxo/tbnqtrghgtnxkzgtcrlutwuslgawe` en el bucket `bucket1` del disco `disk_s3`, con un tamaño de 259 bytes.
