<div id="description">
  ## Descripción
</div>

Contiene una lista de todas las operaciones `BACKUP` o `RESTORE`, con sus estados actuales y otras propiedades. Tenga en cuenta que esta tabla no es persistente y solo muestra las operaciones ejecutadas después del último reinicio del servidor.

<div id="columns">
  ## Columnas
</div>

{/*AUTOGENERATED_START*/}

* `id` ([String](/es/reference/data-types/string)) — ID de la operación; puede proporcionarse mediante SETTINGS id=... o generarse como un UUID aleatorio.
* `name` ([String](/es/reference/data-types/string)) — Nombre de la operación, una cadena como `Disk('backups', 'my_backup')`
* `base_backup_name` ([String](/es/reference/data-types/string)) — Nombre de la operación de copia de seguridad base, una cadena como `Disk('backups', 'my_base_backup')`
* `query_id` ([String](/es/reference/data-types/string)) — ID de la consulta que inició la copia de seguridad.
* `status` ([Enum8(&#39;CREATING&#95;BACKUP&#39; = 0, &#39;BACKUP&#95;CREATED&#39; = 1, &#39;BACKUP&#95;FAILED&#39; = 2, &#39;RESTORING&#39; = 3, &#39;RESTORED&#39; = 4, &#39;RESTORE&#95;FAILED&#39; = 5, &#39;BACKUP&#95;CANCELLED&#39; = 6, &#39;RESTORE&#95;CANCELLED&#39; = 7)](/es/reference/data-types/enum)) — Estado de la operación de copia de seguridad o restauración.
* `error` ([String](/es/reference/data-types/string)) — El mensaje de error, si lo hay.
* `start_time` ([DateTime64(6)](/es/reference/data-types/datetime64)) — La hora de inicio de la operación.
* `end_time` ([DateTime64(6)](/es/reference/data-types/datetime64)) — La hora de finalización de la operación.
* `num_files` ([UInt64](/es/reference/data-types/int-uint)) — Número de archivos almacenados en la copia de seguridad.
* `total_size` ([UInt64](/es/reference/data-types/int-uint)) — Tamaño total de los archivos almacenados en la copia de seguridad.
* `num_entries` ([UInt64](/es/reference/data-types/int-uint)) — Número de entradas de la copia de seguridad; es decir, el número de archivos de la carpeta si la copia de seguridad se almacena como carpeta.
* `uncompressed_size` ([UInt64](/es/reference/data-types/int-uint)) — Tamaño sin comprimir de la copia de seguridad.
* `compressed_size` ([UInt64](/es/reference/data-types/int-uint)) — Tamaño comprimido de la copia de seguridad.
* `files_read` ([UInt64](/es/reference/data-types/int-uint)) — Devuelve el número de archivos leídos durante RESTORE desde esta copia de seguridad.
* `bytes_read` ([UInt64](/es/reference/data-types/int-uint)) — Devuelve el tamaño total de los archivos leídos durante RESTORE desde esta copia de seguridad.
* `ProfileEvents` ([Map(LowCardinality(String), UInt64)](/es/reference/data-types/map)) — Todos los eventos de perfil registrados durante esta operación.
* `settings` ([Map(LowCardinality(String), String)](/es/reference/data-types/map)) — Configuración específica de la copia de seguridad o restauración utilizada para esta operación (procedente de la cláusula `SETTINGS`, incluidos los valores predeterminados). No se exponen los ajustes confidenciales.
* `engine_settings` ([Map(LowCardinality(String), String)](/es/reference/data-types/map)) — Configuración utilizada por el lector/escritor del motor de copia de seguridad (por ejemplo, `allow_native_copy` de S3). Está vacío cuando la operación implica más de un motor y no puede representarse mediante un mapa plano: copias de seguridad incrementales y restauraciones, restauraciones de instantáneas ligeras y operaciones `ON CLUSTER` no internas.

<div id="restore-atomicity">
  ## Atomicidad de la restauración
</div>

`RESTORE` no es transaccional y no revierte los cambios en caso de error. En cada tabla, todas las partes seleccionadas se copian antes de adjuntar cualquiera de ellas, pero la fase de adjuntar en sí no es transaccional: las partes pasan a ser visibles una a una. Las tablas se procesan de forma independiente.

**Las tablas son independientes.** Una tabla cuya restauración se completa permanece en su lugar aunque más adelante falle otra tabla del mismo comando:

```sql
RESTORE TABLE db.t0, TABLE db.t1
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

Si este comando falla después de que `db.t0` se haya restaurado por completo, pero `db.t1` aún no haya terminado, `db.t0` sigue restaurada.

**La cláusula `PARTITIONS` no marca un límite de commit.** Solo selecciona qué partes de una tabla se restauran:

```sql
RESTORE TABLE db.t0 PARTITIONS '2026-06-01', '2026-06-02', '2026-06-03'
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

Primero se copian todas las partes seleccionadas de la tabla y solo se adjuntan cuando todas están listas. Por lo tanto, si este comando falla durante la fase de copia —por ejemplo, después de que la partición `2026-06-01` se haya copiado por completo pero `2026-06-02` y `2026-06-03` no hayan terminado— entonces **no** se hace commit de `2026-06-01` y la tabla queda sin datos restaurados por este comando. Una vez que finaliza la fase de copia y comienza el paso de adjuntar, se hace commit de las partes de una en una, por lo que un fallo durante el adjuntar puede dejar la tabla parcialmente restaurada, sin rollback.

Para hacer commit de las particiones de forma independiente (de modo que una partición completada sobreviva a un fallo posterior y pueda reintentarse de forma aislada), ejecute un `RESTORE` independiente por partición, usando `SETTINGS allow_non_empty_tables = true` después de la primera.
