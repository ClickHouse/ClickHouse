## Descripción {#description}

Muestra las conexiones de cliente abiertas de las interfaces de consulta TCP nativo y HTTP.
Una conexión está `active` mientras se ejecuta una consulta. Una conexión está `idle` mientras espera la siguiente consulta.

La tabla no muestra las siguientes conexiones:

* Conexiones de otros protocolos, por ejemplo, MySQL, PostgreSQL y gRPC.
* Conexiones entre servidores.
* Conexiones HTTP que no ejecutaron ninguna consulta, por ejemplo, `/ping` y las conexiones de Prometheus.

El servidor recopila las conexiones solo si el ajuste del servidor `collect_connection_metrics` es `true`. Si el parámetro de configuración es `false`, la tabla permanece vacía.
Puede cambiar el parámetro de configuración sin reiniciar (`SYSTEM RELOAD CONFIG`):

* Si cambia el parámetro de configuración a `false`, la tabla se vacía y el servidor deja de registrar nuevas conexiones.
* Si cambia el parámetro de configuración a `true`, cada conexión abierta aparece en la tabla con su siguiente consulta.

El servidor añade una conexión TCP a la tabla tras la autenticación y la elimina cuando esta se cierra.
El servidor añade una conexión HTTP a la tabla con su primera consulta y la elimina cuando se cierra el socket.
Por eso, la tabla muestra una conexión HTTP keep-alive como `idle` entre una solicitud y otra.

Un usuario sin el privilegio `SHOW CONNECTIONS` solo ve sus propias conexiones.
La comprobación se basa en el ID del usuario, no en su nombre. Por eso, un usuario renombrado conserva sus conexiones, y un usuario nuevo con el nombre anterior no las obtiene.

`connection_id` es un UUID aleatorio. Por lo tanto, es único entre servidores y permite combinar las tablas de varias réplicas, por ejemplo, con `clusterAllReplicas`.

`connected_time` tiene el mismo significado para TCP y HTTP: el momento en que el servidor empezó a gestionar el socket.
Este momento es anterior al handshake TCP, a la autenticación y a la primera consulta. Por lo tanto, puede ser anterior al momento en que la conexión aparece en la tabla.

## Columnas {#columns}

* `connection_id` ([UUID](/es/reference/data-types/uuid)) — Identificador único de la conexión: un UUID aleatorio. Es único entre servidores, por ejemplo, en `clusterAllReplicas`. Una conexión TCP obtiene el identificador tras la autenticación. Una conexión HTTP lo obtiene con su primera consulta.
* `protocol` ([LowCardinality(String)](/es/reference/data-types/lowcardinality)) — Protocolo de la conexión: TCP (protocolo nativo) o HTTP.
* `client_address` ([IPv6](/es/reference/data-types/ipv6)) — Dirección IP del cliente. Detrás de un proxy, es la dirección del cliente si el servidor confía en el protocolo PROXY o en el encabezado `X-Forwarded-For`. En HTTP, es la dirección de la última solicitud.
* `client_port` ([UInt16](/es/reference/data-types/int-uint)) — Puerto TCP del cliente. Detrás de un proxy, es el puerto indicado por el protocolo PROXY o por el encabezado `X-Forwarded-For`, si el servidor confía en ellos. En HTTP, es el puerto de la última solicitud.
* `server_port` ([UInt16](/es/reference/data-types/int-uint)) — Puerto del servidor que aceptó la conexión.
* `user` ([String](/es/reference/data-types/string)) — Nombre del usuario autenticado. En una conexión HTTP, es el usuario de la última solicitud. Cada solicitud en una conexión keep-alive se autentica por separado. Si se renombra el usuario, esta columna muestra el nombre anterior hasta la siguiente autenticación. La comprobación de acceso utiliza el ID del usuario, no su nombre.
* `status` ([LowCardinality(String)](/es/reference/data-types/lowcardinality)) — Estado de la conexión. `active`: hay una consulta en ejecución. `idle`: la conexión está abierta a la espera de la siguiente consulta o de la siguiente solicitud HTTP.
* `query_id` ([String](/es/reference/data-types/string)) — Identificador de la consulta en ejecución. Vacío si la conexión está inactiva.
* `client_name` ([String](/es/reference/data-types/string)) — Nombre de la aplicación cliente. Un cliente TCP envía este nombre durante el handshake. En HTTP, es el encabezado `User-Agent` de la última solicitud.
* `client_version_major` ([UInt64](/es/reference/data-types/int-uint)) — Versión principal del cliente, obtenida del handshake TCP. 0 en las conexiones HTTP.
* `client_version_minor` ([UInt64](/es/reference/data-types/int-uint)) — Versión menor del cliente, obtenida del handshake TCP. 0 en las conexiones HTTP.
* `client_version_patch` ([UInt64](/es/reference/data-types/int-uint)) — Versión de parche del cliente, obtenida del handshake TCP. 0 en las conexiones HTTP.
* `connected_time` ([DateTime](/es/reference/data-types/datetime)) — Momento en que el servidor empezó a gestionar el socket. Este momento es el mismo para TCP y HTTP: anterior al handshake, a la autenticación y a la primera consulta.
* `last_query_time` ([Nullable(DateTime)](/es/reference/data-types/nullable)) — Hora de inicio de la última consulta en esta conexión. NULL si la conexión no ha ejecutado ninguna consulta.

## Ejemplos {#examples}

```sql
SELECT connection_id, protocol, user, status, query_id, client_name, connected_time, last_query_time
FROM system.connections
FORMAT Vertical;
```

```sql
SELECT hostName(), protocol, status, count()
FROM clusterAllReplicas(default, system.connections)
GROUP BY ALL;
```
