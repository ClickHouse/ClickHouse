El motor `Elasticsearch` permite leer documentos de un índice de [Elasticsearch](https://www.elastic.co/elasticsearch). Cada documento se devuelve como una fila: su `_source` se expone como una única columna de tipo [JSON](/es/reference/data-types/newjson), mientras que el id del documento y el nombre del índice están disponibles como columnas virtuales.

El motor es de solo lectura. Los documentos se recuperan por páginas mediante la API `_search`, utilizando un [point in time](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results#search-after) para que una consulta vea una instantánea coherente del índice aunque este se esté modificando.

Se requiere Elasticsearch 7.12 o posterior, ya que el motor depende de la API de point in time y del campo de ordenación `_shard_doc`. OpenSearch no es compatible, porque no dispone del campo `_shard_doc`. Un servidor de una versión anterior rechazará la primera solicitud con un error.

## Creación de una table {#creating-a-table}

```sql
CREATE TABLE [IF NOT EXISTS] [db.]table_name
[(
    name1 JSON
)]
ENGINE = Elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...])
[SETTINGS keep_alive = 60, page_size = 10000]
```

<Note>
  La integración con Elasticsearch es experimental. Actívela con el parámetro de configuración [`enable_elasticsearch`](/es/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

La lista de columnas es opcional. Si se omite, la table tiene una única columna `document` de tipo `JSON`. Si se especifica, debe contener exactamente una columna de tipo `JSON`, opcionalmente con indicaciones de tipo y rutas omitidas. No se admiten columnas `MATERIALIZED`, `ALIAS` ni `EPHEMERAL`, y los nombres `_id` e `_index` están reservados para las columnas virtuales.

**Parámetros del motor**

* `url` — La URL base del clúster de Elasticsearch, por ejemplo `https://localhost:9200`. Debe ser una URL `http` o `https` sin credenciales, cadena de consulta ni fragmento.
* `index` — El índice que se va a leer. También puede ser un alias, un data stream, una lista separada por comas, un patrón con comodines o una expresión de cálculo de fechas como `<logs-{now/d}>`, tal como los acepta la API de point in time de Elasticsearch. El valor es el nombre literal y no debe estar URL-encoded. Si un patrón no coincide con ningún índice, se produce un error.
* `user`, `password` — Credenciales opcionales para la autenticación básica HTTP.
* `query('...')` — Un objeto opcional de [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) de Elasticsearch en JSON que selecciona los documentos que se van a leer. Debe ir después de los argumentos posicionales. Valor predeterminado: `{"match_all": {}}`.

Los parámetros también pueden pasarse como una [colección con nombre](/es/concepts/features/configuration/server-config/named-collections) con sobrescrituras `key = value`. Consulte la [función de tabla `elasticsearch`](/es/reference/functions/table-functions/elasticsearch#arguments) para ver la lista completa de claves y la descripción de los [métodos de autenticación](/es/reference/functions/table-functions/elasticsearch#authentication).

**Configuración del motor**

| Ajuste       | Predeterminado | Descripción                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `keep_alive` | `60`           | Tiempo, en segundos, durante el cual Elasticsearch mantiene abierto el point in time entre dos solicitudes de página consecutivas.                                                                                                                                                                                                                                                                           |
| `page_size`  | `10000`        | Número de documentos que se solicitan a Elasticsearch en cada solicitud. Cada página se convierte en un bloque, por lo que este ajuste también determina el tamaño de bloque de la lectura; [`max_block_size`](/es/reference/settings/session-settings/max#max_block_size) no tiene efecto. Elasticsearch rechaza los valores superiores a su ajuste de índice `index.max_result_window` (`10000` por defecto). |

Estos ajustes no pueden modificarse con `ALTER TABLE ... MODIFY SETTING`. Para cambiarlos, vuelva a crear la table.

## Columnas virtuales {#virtual-columns}

* `_id` — El ID del documento. Tipo: `String`.
* `_index` — El nombre del índice del que se leyó el documento. Tipo: `LowCardinality(String)`.

Cuando una consulta lee únicamente columnas virtuales, no se solicita a Elasticsearch el `_source` del documento. Un índice que no almacena `_source` (es decir, que tiene el campo `_source` deshabilitado en su mapping) solo puede leerse a través de las columnas virtuales: una consulta que lea la columna `JSON` de un índice así fallará con un error en lugar de devolver documentos vacíos.

## Ejemplo de uso {#usage-example}

```sql
CREATE TABLE logs
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*', 'elastic', 'changeme')
SETTINGS page_size = 5000;

SELECT _index, _id, document.message
FROM logs
WHERE document.level = 'error'
LIMIT 10;
```

Aplique el filtro en Elasticsearch mediante un objeto de Query DSL:

```sql
CREATE TABLE errors_since_october
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*',
                       query('{"bool": {"filter": [{"term": {"level": "error"}}, {"range": {"@timestamp": {"gte": "2026-10-01T00:00:00Z"}}}]}}'),
                       api_key = '...');
```

Use fechas absolutas en `query`: las expresiones de cálculo de fechas como `now-1h` se vuelven a evaluar en cada página, por lo que podrían omitirse documentos. Consulte las [limitaciones de la función de tabla `elasticsearch`](/es/reference/functions/table-functions/elasticsearch#limitations).
