## Descripción {#description}

[Apache ORC](https://orc.apache.org/) es un formato de almacenamiento columnar ampliamente utilizado en el ecosistema de [Hadoop](https://hadoop.apache.org/).

## Correspondencia de tipos de datos {#data-types-matching-orc}

La siguiente tabla compara los tipos de datos ORC compatibles y sus correspondientes [tipos de datos](/es/reference/data-types/index) de ClickHouse en las consultas `INSERT` y `SELECT`.

| Tipo de dato ORC (`INSERT`)   | Tipo de dato de ClickHouse                                                          | Tipo de dato ORC (`SELECT`) |
| ----------------------------- | ----------------------------------------------------------------------------------- | --------------------------- |
| `Boolean`                     | [Bool](/es/reference/data-types/boolean)                                               | `Boolean`                   |
| `Tinyint`                     | [Int8/UInt8](/es/reference/data-types/int-uint)/[Enum8](/es/reference/data-types/enum)    | `Tinyint`                   |
| `Smallint`                    | [Int16/UInt16](/es/reference/data-types/int-uint)/[Enum16](/es/reference/data-types/enum) | `Smallint`                  |
| `Int`                         | [Int32/UInt32](/es/reference/data-types/int-uint)                                      | `Int`                       |
| `Bigint`                      | [Int64/UInt64](/es/reference/data-types/int-uint)                                      | `Bigint`                    |
| `Float`                       | [Float32](/es/reference/data-types/float)                                              | `Float`                     |
| `Double`                      | [Float64](/es/reference/data-types/float)                                              | `Double`                    |
| `Decimal`                     | [Decimal](/es/reference/data-types/decimal)                                            | `Decimal`                   |
| `Date`                        | [Date32](/es/reference/data-types/date32)                                              | `Date`                      |
| `Timestamp`                   | [DateTime64](/es/reference/data-types/datetime64)                                      | `Timestamp`                 |
| `String`, `Varchar`, `Binary` | [String](/es/reference/data-types/string)                                              | `String`                    |
| `Char`                        | [FixedString](/es/reference/data-types/fixedstring)                                    | `String`                    |
| `List`                        | [Array](/es/reference/data-types/array)                                                | `List`                      |
| `Struct`                      | [Tuple](/es/reference/data-types/tuple)                                                | `Struct`                    |
| `Map`                         | [Map](/es/reference/data-types/map)                                                    | `Map`                       |
| `Int`                         | [IPv4](/es/reference/data-types/int-uint)                                              | `Int`                       |
| `Binary`                      | [IPv6](/es/reference/data-types/ipv6)                                                  | `Binary`                    |
| `Binary`                      | [Int128/UInt128/Int256/UInt256](/es/reference/data-types/int-uint)                     | `Binary`                    |
| `Binary`                      | [Decimal256](/es/reference/data-types/decimal)                                         | `Binary`                    |
| `Union`                       | [Variant](/es/reference/data-types/variant)                                            | `Union`                     |

* Los demás tipos no son compatibles.
* Una columna ORC `Union` se lee como un [Variant](/es/reference/data-types/variant) con los tipos de rama de la unión, y una columna `Variant` se escribe como una `Union` de ORC con sus tipos de rama. Tenga en cuenta que `Variant` ordena sus tipos de rama, por lo que el orden de las ramas puede diferir del archivo ORC. Las uniones con tipos de rama duplicados (p. ej., `uniontype<int,int>`) no son compatibles.
* Los arrays pueden anidarse y pueden tener un valor de tipo `Nullable` como argumento. Los tipos `Tuple` y `Map` también pueden anidarse.
* Los tipos de datos de las columnas de una tabla de ClickHouse no tienen por qué coincidir con los campos de datos ORC correspondientes. Al insertar datos, ClickHouse interpreta los tipos de datos según la tabla anterior y luego [convierte](/es/reference/functions/regular-functions/type-conversion-functions#CAST) los datos al tipo de dato definido para la columna de la tabla de ClickHouse.
* Los valores `DateTime64` entre `1969-12-31 23:59:59.001` y `1969-12-31 23:59:59.999999999` (UTC) se escriben como `1970-01-01 00:00:00`. Esto se debe a una laguna en la [especificación de ORC](https://orc.apache.org/specification/ORCv1/#timestamp-columns), que almacena los segundos y los nanosegundos de una marca de tiempo, sin permitir nanosegundos negativos. Las implementaciones de referencia suman un segundo a una marca de tiempo negativa con más de 999999 nanosegundos, y los lectores lo restan, pero entonces una marca de tiempo entre -1 y 0 segundos se almacenaría como 0 segundos y, al leerla, quedaría después del epoch. Cada implementación escribe estas marcas de tiempo de forma distinta: los escritores de Java y C++ de Apache ORC las escriben de modo que se leen un segundo más tarde, y el adaptador ORC de Arrow (PyArrow) escribe nanosegundos negativos, algo que la especificación no permite y que el lector de Java rechaza. ClickHouse, en cambio, escribe el epoch, que todos los lectores leen de la misma manera.
* Cuando las zonas horarias del escritor y del lector de una marca de tiempo difieren, el lector de Java de Apache ORC y ClickHouse restan ese segundo antes de convertir entre zonas horarias, ya que los escritores lo suman, mientras que el lector de C++ de Apache ORC (que también utiliza PyArrow) lo resta después de la conversión. En consecuencia, el lector de C++ puede leer con un segundo de desfase las marcas de tiempo anteriores a 1970 que se encuentran dentro del desplazamiento de la zona horaria respecto al epoch, sea cual sea el escritor del archivo.

## Ejemplo de uso {#example-usage}

### Inserción de datos {#inserting-data}

Usa un archivo ORC con los siguientes datos, llamado `football.orc`:

```text
    ┌───────date─┬─season─┬─home_team─────────────┬─away_team───────────┬─home_team_goals─┬─away_team_goals─┐
 1. │ 2022-04-30 │   2021 │ Sutton United         │ Bradford City       │               1 │               4 │
 2. │ 2022-04-30 │   2021 │ Swindon Town          │ Barrow              │               2 │               1 │
 3. │ 2022-04-30 │   2021 │ Tranmere Rovers       │ Oldham Athletic     │               2 │               0 │
 4. │ 2022-05-02 │   2021 │ Port Vale             │ Newport County      │               1 │               2 │
 5. │ 2022-05-02 │   2021 │ Salford City          │ Mansfield Town      │               2 │               2 │
 6. │ 2022-05-07 │   2021 │ Barrow                │ Northampton Town    │               1 │               3 │
 7. │ 2022-05-07 │   2021 │ Bradford City         │ Carlisle United     │               2 │               0 │
 8. │ 2022-05-07 │   2021 │ Bristol Rovers        │ Scunthorpe United   │               7 │               0 │
 9. │ 2022-05-07 │   2021 │ Exeter City           │ Port Vale           │               0 │               1 │
10. │ 2022-05-07 │   2021 │ Harrogate Town A.F.C. │ Sutton United       │               0 │               2 │
11. │ 2022-05-07 │   2021 │ Hartlepool United     │ Colchester United   │               0 │               2 │
12. │ 2022-05-07 │   2021 │ Leyton Orient         │ Tranmere Rovers     │               0 │               1 │
13. │ 2022-05-07 │   2021 │ Mansfield Town        │ Forest Green Rovers │               2 │               2 │
14. │ 2022-05-07 │   2021 │ Newport County        │ Rochdale            │               0 │               2 │
15. │ 2022-05-07 │   2021 │ Oldham Athletic       │ Crawley Town        │               3 │               3 │
16. │ 2022-05-07 │   2021 │ Stevenage Borough     │ Salford City        │               4 │               2 │
17. │ 2022-05-07 │   2021 │ Walsall               │ Swindon Town        │               0 │               3 │
    └────────────┴────────┴───────────────────────┴─────────────────────┴─────────────────┴─────────────────┘
```

Inserte los datos:

```sql
INSERT INTO football FROM INFILE 'football.orc' FORMAT ORC;
```

### Lectura de datos {#reading-data}

Lea los datos en formato `ORC`:

```sql
SELECT *
FROM football
INTO OUTFILE 'football.orc'
FORMAT ORC
```

<Tip>
  ORC es un formato binario que no puede mostrarse en la terminal de forma legible para humanos. Use `INTO OUTFILE` para generar archivos ORC.
</Tip>
