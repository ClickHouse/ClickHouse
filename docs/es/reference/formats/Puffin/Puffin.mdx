<div id="description">
  ## Descripción
</div>

Formato de entrada para leer archivos [Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/).

El formato expone las posiciones de las filas eliminadas a partir de blobs `deletion-vector-v1`. Es el único tipo de blob compatible: se rechaza cualquier archivo que contenga otro tipo de blob (por ejemplo, `apache-datasketches-theta-v1`).
Si un archivo puffin contiene varios blobs `deletion-vector-v1`, el formato genera una fila por cada uno de ellos.

Columnas de salida fijas:

* `referenced_data_file` (`String`) - ubicación del archivo de datos al que se aplica el vector de eliminación (propiedad del blob `referenced-data-file`)
* `deleted_rows` (`Array(UInt64)`) - posiciones de filas de 64 bits eliminadas según el bitmap roaring del vector de eliminación

Los vectores de eliminación cuya `cardinality` declarada supera un límite absoluto de materialización se rechazan cuando se solicita `deleted_rows`. Las propiedades `deletion-vector-v1` del pie de página (incluida la validación de que `cardinality` se analice como un entero sin signo) siempre se validan. Seleccionar solo `referenced_data_file` omite la E/S de la carga útil en disco y, por tanto, también omite el sobre, el CRC, la deserialización roaring y el límite de materialización, de forma intencionada, para que una proyección que solo incluya la ruta no lea hasta el límite de tamaño del blob.

La longitud del blob `deletion-vector-v1` en disco está limitada por un límite absoluto (en consonancia con la comprobación de Iceberg de un tamaño de contenido de 2 GiB). Cuando se solicita `deleted_rows`, el lector inspecciona la cabecera del sobre (longitud combinada y magic) antes de asignar la carga útil completa; el CRC se verifica después de la lectura acotada.

Se admiten pies de página puffin comprimidos con LZ4 y sin comprimir. El tamaño de la carga útil del pie de página (y el tamaño de contenido LZ4 declarado) está limitado, cuando corresponde, por una relación de compresión y por un límite absoluto; los pies de página demasiado grandes se rechazan antes de la asignación.

Solo se puede solicitar un subconjunto de las columnas de salida. Se rechaza una estructura proporcionada por el usuario con nombres o tipos de columna inesperados al crear el formato.

<div id="example-usage">
  ## Ejemplo de uso
</div>

Lea las posiciones de las filas eliminadas del archivo de datos referenciado:

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

Expanda las posiciones eliminadas en filas individuales:

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

Usa `PuffinMetadata` para inspeccionar los descriptores de blobs del pie de página antes de leer los vectores de eliminación.
