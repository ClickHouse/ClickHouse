## Descripción {#description}

Formato para leer y escribir archivos [Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/).

El formato expone las posiciones de las filas eliminadas a partir de blobs `deletion-vector-v1`. Los blobs de otros tipos, como `apache-datasketches-theta-v1`, se omiten, tal como exige la especificación de Puffin; use `PuffinMetadata` para verlos.
Si un archivo Puffin contiene varios blobs `deletion-vector-v1`, el formato genera una fila por cada uno de ellos.

Columnas de salida fijas:

* `referenced_data_file` (`String`) - ubicación del archivo de datos al que se aplica el vector de eliminación (propiedad `referenced-data-file` del blob)
* `deleted_rows` (`Array(UInt64)`) - posiciones de fila de 64 bits eliminadas según el roaring bitmap del vector de eliminación

Cuando se usa como formato de salida, la entrada debe tener las mismas dos columnas que el formato produce al leer: el archivo de datos referenciado (`String` o `LowCardinality(String)`) y las posiciones de las filas eliminadas (un integer, una posición por fila, o un array de integers). El archivo contiene un blob `deletion-vector-v1` por cada archivo de datos referenciado distinto, ordenados por la ubicación del archivo de datos, de modo que un archivo Puffin con varios vectores de eliminación puede copiarse tal cual. Las posiciones de todas las filas con el mismo archivo de datos referenciado se fusionan en un único vector de eliminación, sin duplicados y ordenadas; se rechazan las posiciones negativas, las que superan el límite del vector de eliminación de Iceberg y las ubicaciones de archivo de datos vacías. La metadata del blob se escribe del mismo modo en que Apache Iceberg escribe los vectores de eliminación: `fields` es `[2147483645]` (el id de la columna de metadata `_pos`), `snapshot-id` y `sequence-number` son `-1`, y se establecen las propiedades `referenced-data-file` y `cardinality`. El pie no está comprimido, por lo que el archivo resultante puede registrarse en una tabla Iceberg v3 como archivo de eliminación de tipo vector de eliminación y leerse desde otros motores como Apache Spark. Use `PuffinMetadata` sobre el archivo escrito para obtener `offset` y `length` de cada blob, que corresponden a los campos `content_offset` y `content_size_in_bytes` del manifiesto.

Si el parámetro de configuración `output_format_puffin_blob_type` se establece en `apache-datasketches-theta-v1`, el formato escribe en su lugar estadísticas de columnas del mismo modo que Apache Iceberg: cada columna de entrada se convierte en un blob `apache-datasketches-theta-v1` con un sketch Theta compacto de Apache DataSketches (semilla y tamaño predeterminados) sobre los valores no nulos de la columna, y la propiedad `ndv` se establece en el número estimado de valores distintos. Los valores se introducen en el sketch con la serialización binaria de valor único de Iceberg correspondiente al tipo de la columna, de modo que los sketches pueden fusionarse con los escritos por Apache Spark: `Bool` como `boolean`, `Int8`, `UInt8`, `Int16`, `UInt16` e `Int32` como `int`, `UInt32`, `Int64` y `UInt64` como `long` (los valores de `UInt64` por encima del rango de `Int64` conservan sus bits), `Float32` como `float`, `Float64` como `double`, `Date` y `Date32` como `date`, `DateTime` y `DateTime64` con hasta 6 dígitos de precisión como `timestamp` (en microsegundos), `String` como `string`, `FixedString` como `fixed`, `UUID` como `uuid` y `Decimal` como `decimal`; también se admiten `Nullable` y `LowCardinality` de estos tipos. Las cadenas vacías se ignoran, igual que en Iceberg. Los `fields` de los blobs se toman del parámetro de configuración `output_format_puffin_field_ids`, y `snapshot-id` y `sequence-number`, de los ajustes `output_format_puffin_snapshot_id` y `output_format_puffin_sequence_number`; los tres ajustes son obligatorios, porque los lectores asocian las estadísticas a las columnas y a la instantánea que indican. El resultado puede registrarse como archivo de estadísticas de Iceberg.

Los vectores de eliminación cuya `cardinality` declarada supera un límite absoluto de materialización se rechazan cuando se solicita `deleted_rows`. Las propiedades `deletion-vector-v1` del pie (incluido que `cardinality` pueda interpretarse como entero sin signo) se validan siempre. Si solo se selecciona `referenced_data_file`, se omite la E/S de la carga útil en disco y, por tanto, también el envoltorio, el CRC, la deserialización de roaring y el límite de materialización. Esto es intencionado: así, una proyección que solo incluye rutas no lee hasta el tope de tamaño del blob.

La longitud en disco de un blob `deletion-vector-v1` está acotada por un límite absoluto (alineado con la comprobación de tamaño de contenido de 2 GiB de Iceberg). Cuando se solicita `deleted_rows`, el lector examina la cabecera del envoltorio (longitud combinada y número mágico) antes de asignar la carga útil completa; el CRC se verifica tras la lectura acotada.

Se admiten pies puffin comprimidos con LZ4 y sin comprimir. El tamaño de la carga útil del pie (y el tamaño de contenido LZ4 declarado) está limitado, cuando corresponde, por una relación de compresión y por un límite absoluto; los pies demasiado grandes se rechazan antes de la asignación.

Solo se puede solicitar un subconjunto de las columnas de salida. Se rechaza una estructura proporcionada por el usuario con nombres o tipos de columna inesperados al crear el formato.

## Ejemplo de uso {#example-usage}

Lea las posiciones de las filas eliminadas del archivo de datos referenciado:

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

Expanda las posiciones eliminadas en filas individuales:

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

Usa `PuffinMetadata` para inspeccionar los descriptores de blobs del pie antes de leer los vectores de eliminación.

Escriba vectores de eliminación para dos archivos de datos en un único archivo Puffin:

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

Escriba los sketches Theta de dos columnas en un archivo de estadísticas de Iceberg:

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
