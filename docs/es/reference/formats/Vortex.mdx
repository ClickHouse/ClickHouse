## Descripción {#description}

[Vortex](https://vortex.dev/) es un formato de archivo columnar y extensible para datos comprimidos compatibles con Apache Arrow,
diseñado para escaneos rápidos y acceso aleatorio. ClickHouse admite la lectura y la escritura de archivos Vortex.

## Correspondencia de tipos de datos {#data-types-matching-vortex}

La siguiente tabla muestra los tipos de datos de Vortex y los [tipos de datos](/es/reference/data-types/index) de ClickHouse correspondientes
en las consultas `INSERT` y `SELECT`.

| Tipo de datos de Vortex (`INSERT`) | Tipo de datos de ClickHouse                                                               | Tipo de datos de Vortex (`SELECT`)                                |
| ---------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `Bool`                             | [Bool](/es/reference/data-types/boolean)                                                     | `Bool`                                                            |
| `I8`, `U8`                         | [Int8/UInt8](/es/reference/data-types/int-uint)                                              | `I8`, `U8`                                                        |
| `I16`, `U16`                       | [Int16/UInt16](/es/reference/data-types/int-uint)                                            | `I16`, `U16`                                                      |
| `I32`, `U32`                       | [Int32/UInt32](/es/reference/data-types/int-uint)                                            | `I32`, `U32`                                                      |
| `I64`, `U64`                       | [Int64/UInt64](/es/reference/data-types/int-uint)                                            | `I64`, `U64`                                                      |
| `F32`                              | [Float32](/es/reference/data-types/float)                                                    | `F32`                                                             |
| `F64`                              | [Float64](/es/reference/data-types/float)                                                    | `F64`                                                             |
| `Utf8`, `Binary`                   | [String](/es/reference/data-types/string)                                                    | `Utf8` (`Binary` con `output_format_vortex_string_as_string = 0`) |
| `Binary`                           | [FixedString](/es/reference/data-types/fixedstring)                                          | `Binary`                                                          |
| `Decimal`                          | [Decimal](/es/reference/data-types/decimal)                                                  | `Decimal`                                                         |
| `vortex.date`                      | [Date32](/es/reference/data-types/date32)                                                    | `vortex.date`                                                     |
| `vortex.timestamp`                 | [DateTime](/es/reference/data-types/datetime)/[DateTime64](/es/reference/data-types/datetime64) | `vortex.timestamp`                                                |
| `vortex.time`                      | [Time64](/es/reference/data-types/time64)                                                    | `vortex.time`                                                     |
| `List`                             | [Array](/es/reference/data-types/array)                                                      | `List`                                                            |
| `Struct`                           | [Tuple](/es/reference/data-types/tuple)                                                      | `Struct`                                                          |
| `Null`                             | [Nullable(Nothing)](/es/reference/data-types/special-data-types/nothing)                     | `Null`                                                            |

Los demás tipos no son compatibles. En particular, las columnas [Map](/es/reference/data-types/map),
[Int128/UInt128/Int256/UInt256](/es/reference/data-types/int-uint), [IPv6](/es/reference/data-types/ipv6)
e [Interval](/es/reference/data-types/special-data-types/interval) no pueden escribirse en archivos Vortex.
Las columnas [String](/es/reference/data-types/string) se escriben como `Utf8`, que Vortex comprime mejor
que `Binary`. Vortex exige que los valores `Utf8` sean UTF-8 válido, mientras que las cadenas de ClickHouse son secuencias
arbitrarias de bytes, por lo que escribir un valor que no sea UTF-8 válido lanza una excepción; con
`output_format_vortex_string_as_string = 0`, las cadenas se escriben como `Binary`. Vortex no tiene
un tipo binario de tamaño fijo, por lo que [FixedString](/es/reference/data-types/fixedstring) siempre se escribe como `Binary`;
la inferencia del esquema lo lee de vuelta como [String](/es/reference/data-types/string).
Las columnas [LowCardinality](/es/reference/data-types/lowcardinality) se escriben con su tipo subyacente
(Vortex elige por sí mismo, de forma adaptativa, la codificación de diccionario y otras codificaciones).
Las columnas [DateTime](/es/reference/data-types/datetime) se escriben como `vortex.timestamp` con precisión de segundos,
por lo que se leen de vuelta como [DateTime64](/es/reference/data-types/datetime64) con escala 0.
Un `vortex.timestamp` incluye una unidad y no una escala, por lo que solo las escalas que una unidad representa exactamente
(0, 3, 6 y 9) se conservan tras la inferencia del esquema; cualquier otra escala se escribe en la siguiente unidad más amplia y
se infiere como la escala de esa unidad, de modo que [DateTime64](/es/reference/data-types/datetime64)`(1)` y `(2)` se leen
como `DateTime64(3)`, `(4)` y `(5)` como `DateTime64(6)`, y `(7)` y `(8)` como `DateTime64(9)`. Los valores
se reescalan y conservan su significado; solo se amplía la escala declarada, y si se indica el tipo explícitamente, se lee de vuelta
sin cambios. Lo mismo se aplica a [Time64](/es/reference/data-types/time64).
`vortex.time` representa una hora del día, mientras que [Time/Time64](/es/reference/data-types/time64) en ClickHouse también admite
valores negativos y valores de 24 horas o más; al escribir un valor así se lanza una excepción en lugar de escribir uno incorrecto.
Las columnas [IPv4](/es/reference/data-types/ipv4) se escriben como `U32` porque Vortex no tiene un tipo para direcciones IP,
por lo que la inferencia del esquema las lee de vuelta como [UInt32](/es/reference/data-types/int-uint). Especifique el tipo explícitamente
para leer dicha columna como `IPv4`: `SELECT * FROM file('data.vortex', Vortex, 'ip IPv4')`.

Los tipos de datos de las columnas de la tabla de ClickHouse no tienen por qué coincidir con los campos de datos de Vortex correspondientes.
Al insertar datos, ClickHouse interpreta los tipos de datos según la tabla anterior y luego
[convierte](/es/reference/functions/regular-functions/type-conversion-functions#CAST) los datos al tipo de datos establecido para la
columna de la tabla de ClickHouse.

## Ejemplo de uso {#example-usage}

Puede seleccionar datos de un archivo Vortex:

```sql
SELECT * FROM file('data.vortex');
```

Y escribir datos en un archivo Vortex:

```sql
SELECT * FROM numbers(3) INTO OUTFILE 'numbers.vortex' FORMAT Vortex;
```

## Configuración de formato {#format-settings}

| Ajuste                                  | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Valor predeterminado |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------- |
| `input_format_vortex_filter_push_down`  | Traslada al escaneo las partes traducibles de la condición `WHERE`, de modo que una consulta selectiva lea y decodifique menos datos. Dentro del escaneo solo se aplica la parte traducida de la condición: una condición que solo es parcialmente traducible se amplía a otra que conserve al menos todas las filas coincidentes, por lo que todavía pueden leerse y decodificarse filas que no coinciden; después, ClickHouse vuelve a aplicar el filtro completo. Actualmente, el pushdown admite columnas top-level de tipo integer, de coma flotante, cadena/binary, `Bool`, `Date`, `Date32` y `DateTime64`. | `1`                  |
| `input_format_vortex_preserve_order`    | Devuelve las filas en el orden en que aparecen en el archivo. De forma predeterminada, las divisiones de filas de un archivo se decodifican en paralelo y se devuelven en cuanto están listas, por lo que no se garantiza el orden de las filas; con este ajuste activado, una división lenta retiene las que vienen detrás.                                                                                                                                                                                                                                                                                       | `0`                  |
| `output_format_vortex_string_as_string` | Escribe las columnas [String](/es/reference/data-types/string) como `Utf8` en lugar de `Binary`. Un valor que no sea UTF-8 válido lanza una excepción; desactive el ajuste para escribir esos datos como `Binary`.                                                                                                                                                                                                                                                                                                                                                                                                    | `1`                  |
| `max_parsing_threads`                   | Número de threads que decodifican los archivos Vortex (compartidos por los archivos que una misma consulta lee en paralelo). `1` deshabilita el pool de hilos: en ese caso, el archivo se lee dentro de `read`, en el thread del pipeline de ejecución de consultas.                                                                                                                                                                                                                                                                                                                                               | número de núcleos    |
| `max_download_threads`                  | Número de threads que leen el archivo. Con `0`, las lecturas comparten los threads de decodificación.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `4`                  |

Como en otros formatos columnares, solo se leen del archivo las columnas que utiliza la consulta, y
las columnas ausentes en el archivo se rellenan con valores predeterminados.

## Rendimiento {#performance}

Los archivos se leen en paralelo. El escaneo los divide en rangos de filas (alineados con los límites de los fragmentos de
las columnas solicitadas, con un máximo de 100 000 filas cada uno) que se leen, filtran y decodifican de forma concurrente:
la decodificación se ejecuta en hasta `max_parsing_threads` threads del mismo grupo que utiliza el lector de `Parquet`,
las lecturas, en hasta `max_download_threads` threads, y la conversión de un fragmento decodificado a
columnas de ClickHouse se realiza en el mismo thread que lo decodificó. Los bloques se devuelven en cuanto están
listos, por lo que el orden de las filas no está garantizado a menos que se establezca `input_format_vortex_preserve_order`. Las
lecturas de segmentos cercanos dentro del archivo se fusionan en una única solicitud (hasta 4 MiB para archivos
locales y 16 MiB para almacenamiento remoto). El pushdown de filtros reduce la cantidad de datos que se leen y decodifican
en las consultas selectivas.
