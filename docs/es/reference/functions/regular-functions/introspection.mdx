Puede usar las funciones descritas en este capítulo para realizar la introspección de [ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format) y [DWARF](https://en.wikipedia.org/wiki/DWARF) para el perfilado de consultas.

<Note>
  Estas funciones son lentas y pueden plantear implicaciones de seguridad.
</Note>

Para que las funciones de introspección funcionen correctamente:

* Instale el paquete `clickhouse-common-static-dbg`.

* Establezca el ajuste [allow&#95;introspection&#95;functions](/es/reference/settings/session-settings/allow#allow_introspection_functions) en 1.

  Por motivos de seguridad, las funciones de introspección están deshabilitadas de forma predeterminada.

ClickHouse guarda los informes del perfilador en la tabla del sistema [trace&#95;log](/es/reference/system-tables/trace_log). Asegúrese de que la tabla y el perfilador estén configurados correctamente.

## addressToLine {#addressToLine}

Introducido en: v20.1.0

Convierte la dirección de una instrucción dentro del ejecutable principal de ClickHouse en un nombre de archivo y un número de línea del código fuente de ClickHouse.

La dirección debe ser un offset dentro del ejecutable principal de ClickHouse, que es la forma en que se almacenan las direcciones en las columnas `trace` de `system.trace_log`, `system.stack_trace` y `system.crash_log`, y en la columna `last_error_trace` de `system.error_log`.
No se aceptan direcciones de tiempo de ejecución (memoria virtual), para que la función no pueda utilizarse para conocer la disposición de memoria del proceso del servidor.
Los marcos de pila fuera del ejecutable principal se almacenan como `0`, y para ellos la función devuelve un resultado vacío.

<Note>
  Esta función es lenta y puede implicar consideraciones de seguridad.
</Note>

Para habilitar esta función de introspección:

* Instale el paquete `clickhouse-common-static-dbg`.
* Establezca el parámetro de configuración [`allow_introspection_functions`](/es/reference/settings/session-settings/allow#allow_introspection_functions) en `1`.

<Note>
  Esta función es no determinista: puede devolver resultados diferentes para los mismos argumentos.
</Note>

**Sintaxis**

```sql
addressToLine(address_of_binary_instruction)
```

**Argumentos**

* `address_of_binary_instruction` — Offset de una instrucción dentro del ejecutable principal de ClickHouse, tal como se almacena en la columna `trace` de `system.trace_log` y en tablas similares. [`UInt64`](/es/reference/data-types/int-uint)

**Valor devuelto**

Devuelve un nombre de archivo de código fuente y un número de línea separados por dos puntos; por ejemplo, `/build/obj-x86_64-linux-gnu/../src/Common/ThreadPool.cpp:199`. Devuelve el nombre del binary si no se encuentra información de depuración para la dirección, o una cadena vacía para `0`. [`String`](/es/reference/data-types/string)

**Ejemplos**

## addressToLineWithInlines {#addressToLineWithInlines}

Introducido en: v22.2.0

Similar a `addressToLine`, pero devuelve un Array con todas las funciones en línea.
Por ello, es más lenta que `addressToLine`.

La dirección debe ser un offset dentro del ejecutable principal de ClickHouse, que es la forma en que se almacenan las direcciones en las columnas `trace` de `system.trace_log`, `system.stack_trace` y `system.crash_log`, y en la columna `last_error_trace` de `system.error_log`.
No se aceptan direcciones en tiempo de ejecución (de memoria virtual), para que la función no pueda utilizarse para averiguar la disposición de memoria del proceso del servidor.
Los marcos de pila situados fuera del ejecutable principal se almacenan como `0`, y para ellos la función devuelve un resultado vacío.

Para habilitar esta función de introspección:

* Instale el paquete `clickhouse-common-static-dbg`.
* Establezca el parámetro de configuración [`allow_introspection_functions`](/es/reference/settings/session-settings/allow#allow_introspection_functions) en `1`.

<Note>
  Esta función no es determinista: puede devolver resultados diferentes con los mismos argumentos.
</Note>

**Sintaxis**

```sql
addressToLineWithInlines(address_of_binary_instruction)
```

**Argumentos**

* `address_of_binary_instruction` — Offset de una instrucción dentro del ejecutable principal de ClickHouse, tal como se almacena en la columna `trace` de `system.trace_log` y tablas similares. [`UInt64`](/es/reference/data-types/int-uint)

**Valor devuelto**

Devuelve un array cuyo primer elemento es el nombre del archivo de código fuente y el número de línea, separados por dos puntos. El segundo, tercer, etc. elemento enumera los nombres de archivo del código fuente, los números de línea y los nombres de las funciones en línea. Si no se encuentra información de depuración, se devuelve un array con un único elemento igual al nombre del binary; en cambio, para `0` se devuelve un array vacío. [`Array(String)`](/es/reference/data-types/array)

Introducido en: v20.1.0

## getQueryProfileEvent {#getQueryProfileEvent}

Introducido en: v26.11.0

Devuelve el valor actual de un [evento de perfilado](/es/reference/system-tables/events) para la consulta actual.

El valor se acumula entre todos los threads que ejecutan la consulta, del mismo modo que en la columna `ProfileEvents` de `system.query_log`.
La función es no determinista: se evalúa una vez por [bloque](/es/resources/develop-contribute/introduction/architecture#block) de datos durante la ejecución de la consulta,
por lo que todas las filas de un mismo bloque reciben el mismo valor, y este aumenta a medida que avanza la consulta.
Esto permite anotar la salida o los datos insertados con el progreso de la consulta, como el número de filas o bytes leídos hasta ese momento.

En una consulta distribuida, cada servidor devuelve el valor correspondiente a su propia parte de la consulta.
Algunos eventos, como `RealTimeMicroseconds` u `OSReadBytes`, solo se actualizan periódicamente, por lo que su valor puede ir con retraso.

<Note>
  Esta función es no determinista: puede devolver resultados diferentes para los mismos argumentos.
</Note>

**Sintaxis**

```sql
getQueryProfileEvent(event_name)
```

**Argumentos**

* `event_name` — El nombre del evento de perfilado, tal como aparece en `system.events`. [`const String`](/es/reference/data-types/string)

**Valor devuelto**

El valor actual del evento de perfilado para la consulta en curso. [`UInt64`](/es/reference/data-types/int-uint)

**Ejemplos**

**Progreso de la lectura**


## logTrace {#logTrace}

Introducido en: v20.12.0

Emite un mensaje de traza en el registro del servidor.

La función solo acepta un argumento constante, por lo que la llamada se evalúa durante el análisis de la consulta y se sustituye
por su resultado. Por lo tanto, el mensaje se emite una vez mientras se analiza la consulta, y no una vez por cada
[bloque](/es/resources/develop-contribute/introduction/architecture#block) procesado: el número de filas y la configuración `max_block_size` no afectan
a la cantidad de mensajes que aparecen en el log.

**Sintaxis**

```sql
logTrace(message)
```

**Argumentos**

* `message` — Mensaje que se emite al registro del servidor. [`const String`](/es/reference/data-types/string)

**Valor devuelto**

Devuelve siempre `0`. [`UInt8`](/es/reference/data-types/int-uint)

**Ejemplos**

**Ejemplo básico**

```sql title=Query
SELECT logTrace('logTrace message');
```

