## evalMLMethod {#evalmlmethod}

La predicción con modelos de regresión ajustados se realiza con la función `evalMLMethod`. Consulte el enlace en `linearRegression`.

## stochasticLinearRegression {#stochasticlinearregression}

La [stochasticLinearRegression](/es/reference/functions/aggregate-functions/stochasticLinearRegression) función de agregado implementa el método de descenso de gradiente estocástico con un modelo lineal y la función de pérdida MSE. Usa `evalMLMethod` para hacer predicciones sobre datos nuevos.

## stochasticLogisticRegression {#stochasticlogisticregression}

La función de agregado [stochasticLogisticRegression](/es/reference/functions/aggregate-functions/stochasticLogisticRegression) implementa el método de descenso de gradiente estocástico para un problema de clasificación binaria. Usa `evalMLMethod` para hacer predicciones sobre datos nuevos.

## assignCentroid {#assignCentroid}

Introducido en: v26.8.0

Devuelve el id del centroide más cercano (L2) a un vector. Los centroides se especifican como un array constante de arrays, donde el id es la posición (empezando en 0) dentro de dicho array, o como el nombre de un `Dictionary` que contiene los atributos `cid` y `vec`, donde el id es `cid`.

<Note>
  Esta función es no determinista: puede devolver resultados distintos para los mismos argumentos.
</Note>

**Sintaxis**

```sql
assignCentroid(vec, centroids | dict_name)
```

**Argumentos**

* `vec` — Vector que se va a asignar. Su dimensión debe coincidir con la dimensión de los centroides. Los tipos de elemento distintos de `Float32` se convierten a `Float32`, que es lo que utiliza el kernel de puntuación. [`Array(Float32)`](/es/reference/data-types/array) o [`Array(Float64)`](/es/reference/data-types/array) o [`Array(BFloat16)`](/es/reference/data-types/array) o [`Array(Int8)`](/es/reference/data-types/array) o [`Array(UInt8)`](/es/reference/data-types/array)
* `centroids` — Los centroides con los que se compara, que deben ser constantes. Se indican como un array de arrays no vacíos y de igual tamaño con cualquiera de los tipos de elemento aceptados para `vec` (no necesariamente el mismo), siendo el id la posición en ese array (empezando en 0); o como el nombre de un `Dictionary` con un atributo `cid` de un integer type sin signo que quepa en `UInt32` y un atributo `vec` de tipo `Array(Float32)`, en cuyo caso el id es `cid`. El diccionario se lee una sola vez y se mantiene cached hasta que se vuelve a cargar. [`Array(Array(Float32))`](/es/reference/data-types/array) o [`Array(Array(Float64))`](/es/reference/data-types/array) o [`Array(Array(BFloat16))`](/es/reference/data-types/array) o [`Array(Array(Int8))`](/es/reference/data-types/array) o [`Array(Array(UInt8))`](/es/reference/data-types/array) o [`String`](/es/reference/data-types/string)

**Valor devuelto**

El id del centroide más cercano. [`UInt32`](/es/reference/data-types/int-uint)

**Ejemplos**

**Centroides Inline**

```sql title=Query
SELECT assignCentroid([1.0, 2.0]::Array(Float32), [[0.0, 0.0], [1.0, 2.0]]::Array(Array(Float32)))
```

```response title=Response
1
```

## evalMLMethod {#evalMLMethod}

Introducido en: v20.1.0

Aplica un modelo de aprendizaje automático entrenado a las variables de entrada para generar predicciones.

**Sintaxis**

```sql
evalMLMethod(model, x1[, x2, ...])
```

**Argumentos**

* `model` — El modelo de aprendizaje automático entrenado. [`AggregateFunctionState`](/es/reference/data-types/aggregatefunction)
* `x1, x2, ...` — Valores de las características para la predicción. [`Float*`](/es/reference/data-types/float) o [`(U)Int*`](/es/reference/data-types/int-uint)

**Valor devuelto**

Devuelve el valor predicho en función del modelo entrenado. [`Float64`](/es/reference/data-types/float)

**Ejemplos**

**Ejemplo de uso**

```sql title=Query
CREATE TABLE trips (pickup_datetime DateTime('UTC'), trip_distance Float64, total_amount Float64) ENGINE = Memory;

-- A fare of 3, plus 2.5 for every unit of distance.
INSERT INTO trips
SELECT toDateTime('2020-01-01 00:00:00', 'UTC') + number * 60, number % 10 + 1, 2.5 * (number % 10 + 1) + 3
FROM numbers(1000);

-- One model per year of the data.
CREATE TABLE models ENGINE = Memory AS
SELECT
    toYear(pickup_datetime) AS year,
    stochasticLinearRegressionState(0.01, 0.0, 10, 'SGD')(total_amount, trip_distance) AS model
FROM trips
GROUP BY year;

SELECT
    trip_distance,
    round(evalMLMethod(model, trip_distance), 2) AS predicted,
    total_amount
FROM trips
LEFT JOIN models ON year = toYear(pickup_datetime)
ORDER BY pickup_datetime
LIMIT 5
```

```response title=Response
┌─trip_distance─┬─predicted─┬─total_amount─┐
│             1 │      4.05 │          5.5 │
│             2 │      6.79 │            8 │
│             3 │      9.53 │         10.5 │
│             4 │     12.28 │           13 │
│             5 │     15.02 │         15.5 │
└───────────────┴───────────┴──────────────┘
```

## naiveBayesClassifier {#naiveBayesClassifier}

Introducido en: v25.11.0

Clasifica el texto de entrada mediante un diccionario [`NAIVE_BAYES`](/es/reference/statements/create/dictionary/layouts/naive-bayes). Devuelve el mismo valor de clase predicho que `dictGet(dictionary_name, class_attribute, input_text)`, donde class&#95;attribute es el nombre del atributo de etiqueta de clase configurado en el [layout](/es/reference/statements/create/dictionary/layouts/naive-bayes#layout-parameters) del diccionario. A diferencia de `dictGet`, el tipo del resultado siempre es `UInt32` en lugar del tipo declarado del atributo de clase, y `input_text` debe ser un `String` (no se aplica ninguna conversión del tipo de clave).

<Note>
  Esta función es no determinista: puede devolver resultados diferentes para los mismos argumentos.
</Note>

**Sintaxis**

```sql
naiveBayesClassifier(dictionary_name, input_text)
```

**Argumentos**

* `dictionary_name` — Nombre de un diccionario con el layout NAIVE&#95;BAYES. [`String`](/es/reference/data-types/string)
* `input_text` — Texto que se va a clasificar. [`String`](/es/reference/data-types/string)

**Valor devuelto**

ID de la clase predicha. [`UInt32`](/es/reference/data-types/int-uint)

**Ejemplos**

**Clasificar texto**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT naiveBayesClassifier('sentiment', 'a good and great film') AS class_id;
```

```response title=Response
┌─class_id─┐
│        0 │
└──────────┘
```

## naiveBayesClassifierWithAllProbs {#naiveBayesClassifierWithAllProbs}

Introducido en: v26.7.0

Clasifica el texto de entrada mediante un diccionario [`NAIVE_BAYES`](/es/reference/statements/create/dictionary/layouts/naive-bayes) y devuelve todas las clases con sus probabilidades, ordenadas de mayor a menor probabilidad.

<Note>
  Esta función es no determinista: puede devolver resultados distintos para los mismos argumentos.
</Note>

**Sintaxis**

```sql
naiveBayesClassifierWithAllProbs(dictionary_name, input_text)
```

**Argumentos**

* `dictionary_name` — Nombre de un diccionario con el layout NAIVE&#95;BAYES. [`String`](/es/reference/data-types/string)
* `input_text` — Texto que se va a clasificar. [`String`](/es/reference/data-types/string)

**Valor devuelto**

Array de tuplas (class&#95;id, probability), ordenadas de la más probable a la menos probable. [`Array(Tuple(UInt32, Float64))`](/es/reference/data-types/array)

**Ejemplos**

**Todas las probabilidades de clase**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT arrayMap(p -> (p.1, round(p.2, 4)), naiveBayesClassifierWithAllProbs('sentiment', 'a good and great film')) AS predictions;
```

```response title=Response
┌─predictions─────────────┐
│ [(0,0.9677),(1,0.0323)] │
└─────────────────────────┘
```

<Note>

**Sintaxis**


**Valor devuelto**

Tuple de (class&#95;id, probability). [`Tuple(UInt32, Float64)`](/es/reference/data-types/tuple)

**Ejemplos**

**Clasificación con probabilidad**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
```

## predictXGBoost {#predictXGBoost}

Introducido en: v26.10.0

Predice un valor objetivo numérico para un vector de características mediante un diccionario [`XGBOOST`](/es/reference/statements/create/dictionary/layouts/xgboost). Las características se pasan de forma posicional, en el mismo orden en que se declararon las columnas de clave del diccionario. Esta es la única forma de consultar un diccionario `XGBOOST`: contiene un modelo entrenado en lugar de filas, por lo que la interfaz genérica de diccionarios (`dictGet`, `dictHas`, `SELECT * FROM dict`) no es compatible. La integración con XGBoost es experimental, por lo que el parámetro de configuración `enable_xgboost` debe estar habilitado.

**Sintaxis**

```sql
predictXGBoost(dictionary_name, feature1[, feature2, ...][, params])
```

**Argumentos**

* `dictionary_name` — Nombre de un diccionario con la disposición XGBOOST. Consulte la [estructura del diccionario XGBOOST](/es/reference/statements/create/dictionary/layouts/xgboost) para saber cómo crearlo y qué parámetros de entrenamiento acepta. [`String`](/es/reference/data-types/string)
* `featureN` — Valores numéricos de las características, en el orden posicional de las claves del diccionario. Una característica NULL se pasa al modelo como valor ausente, que XGBoost trata según cómo fue entrenado, por lo que la predicción nunca es NULL. [`(U)Int*`](/es/reference/data-types/int-uint) o [`Float*`](/es/reference/data-types/float) o [`Nullable((U)Int*)`](/es/reference/data-types/nullable) o [`Nullable(Float*)`](/es/reference/data-types/nullable)
* `params` — Map constante opcional de parámetros de predicción de XGBoost, que asocia cada nombre de parámetro a un valor entero, p. ej., `map('type', 0, 'iteration_end', 0)`. Todos los parámetros aceptados son enteros o booleanos, por lo que se rechazan los valores fraccionarios. Consulte los [parámetros de predicción](/es/reference/statements/create/dictionary/layouts/xgboost#prediction-parameters) para conocer las claves aceptadas. [`Map(String, (U)Int8/16/32/64)`](/es/reference/data-types/map)

**Valor devuelto**

La predicción del modelo como Float64, una por fila. [`Float64`](/es/reference/data-types/float)

**Ejemplos**

**Predicción**

```sql title=Query
-- A model trained on the linear target y = 2 * x1 + 3 * x2. The XGBoost integration is experimental.
SET enable_xgboost = 1;

CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO training_data SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y FROM numbers(100);

CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(objective 'reg:squarederror' num_iterations 100 max_depth 6))
LIFETIME(0);

-- The ground truth is 2 * 1 + 3 * 2 = 8.
SELECT round(predictXGBoost('model', 1.0, 2.0), 1) AS prediction;
```

```response title=Response
┌─prediction─┐
│          8 │
└────────────┘
```

**Predicción con parámetros**

```sql title=Query
-- The raw margin of the model above, before the objective's transformation. For `reg:squarederror` it is the
-- prediction itself, while for `binary:logistic` it is the log-odds rather than the probability.
SELECT round(predictXGBoost('model', 1.0, 2.0, map('type', 1)), 1) AS margin;
```

```response title=Response
┌─margin─┐
│      8 │
└────────┘
```
