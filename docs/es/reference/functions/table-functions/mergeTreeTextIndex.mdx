Representa el diccionario de un índice de texto en tablas MergeTree.
Devuelve los tokens con los metadatos de su posting list.
Puede usarse para introspección.

## Sintaxis {#syntax}

```sql
mergeTreeTextIndex(database, table, index_name)
```

## Argumentos {#arguments}

| Argumento    | Descripción                                                          |
| ------------ | -------------------------------------------------------------------- |
| `database`   | El nombre de la base de datos de la que se leerá el índice de texto. |
| `table`      | El nombre de la tabla de la que se leerá el índice de texto.         |
| `index_name` | El nombre del índice de texto que se leerá.                          |

## Valor devuelto {#returned-value}

Un objeto de tabla con tokens y los metadatos de la lista de postings.

Si el índice utiliza el tokenizador `keyValuePairs`, cada token es un par `(clave, valor)` de una columna de tipo `Map`, y el resultado incluye dos columnas adicionales, `token_key` y `token_value`, que contienen los componentes decodificados del token.

Las listas de postings de los tokens se devuelven en las siguientes columnas virtuales. Estas columnas no se incluyen en `SELECT *` y deben seleccionarse explícitamente.

| Columna     | Tipo            | Descripción                                                                                                   |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------- |
| `row_id`    | `UInt32`        | El número de fila dentro de la parte de datos (consulte `_part_offset`) en la lista de postings del token.    |
| `positions` | `Array(UInt32)` | Las posiciones del token en la fila. Solo existe si el índice tiene el argumento `support_phrase_search = 1`. |

Si se selecciona cualquiera de estas columnas, el resultado contiene una fila por cada fila de la lista de postings de cada token, de forma similar a un `ARRAY JOIN` de la lista de postings: las demás columnas del token se repiten en cada una de ellas.

Las listas de postings se devuelven tal como están almacenadas en el índice de la parte de datos, por lo que incluyen las filas eliminadas mediante eliminación ligera (consulte `_row_exists`) hasta que la parte se fusione.

## Ejemplo de uso {#usage-example}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha)
)
ENGINE = MergeTree
ORDER BY id;

INSERT INTO tab SELECT number, concatWithSeparator(' ', 'apple', 'banana') FROM numbers(500);
INSERT INTO tab SELECT 500 + number, concatWithSeparator(' ', 'cherry', 'date') FROM numbers(500);

SELECT * FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s);
```

## Ejemplo de uso: listas de postings {#usage-example-posting-lists}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha, support_phrase_search = 1)
)
ENGINE = MergeTree
ORDER BY id
SETTINGS allow_experimental_text_index_phrase_search = 1;

INSERT INTO tab VALUES (0, 'apple banana apple'), (1, 'banana cherry'), (2, 'cherry apple');

SELECT token, row_id, positions FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s) ORDER BY token, row_id;
```

```text title="Response"
   ┌─token──┬─row_id─┬─positions─┐
1. │ apple  │      0 │ [0,2]     │
2. │ apple  │      2 │ [1]       │
3. │ banana │      0 │ [1]       │
4. │ banana │      1 │ [0]       │
5. │ cherry │      1 │ [1]       │
6. │ cherry │      2 │ [0]       │
   └────────┴────────┴───────────┘
```
