Permite ejecutar consultas `SELECT` sobre los documentos de un índice de [Elasticsearch](https://www.elastic.co/elasticsearch). Cada documento se devuelve como una fila: su `_source` se expone como una única columna de tipo [JSON](/es/reference/data-types/newjson), mientras que el ID del documento y el nombre del índice están disponibles como columnas virtuales. La función es de solo lectura.

## Sintaxis {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  La integración con Elasticsearch es experimental. Actívela con el parámetro de configuración [`enable_elasticsearch`](/es/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## Argumentos {#arguments}

| Argumento      | Descripción                                                                                                                                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `url`          | La URL base del cluster de Elasticsearch, por ejemplo `https://localhost:9200`. Debe ser una URL `http` o `https` sin credenciales, cadena de consulta ni fragmento.                                                                                                                       |
| `index`        | El índice que se va a leer. También puede ser un alias, una lista separada por comas o un patrón con comodines, siempre que lo admita la API point in time de Elasticsearch. Si un patrón no coincide con ningún índice, se produce un error.                                              |
| `user`         | El nombre de usuario para la autenticación básica HTTP (opcional).                                                                                                                                                                                                                         |
| `password`     | La contraseña para la autenticación básica HTTP (opcional; requiere `user`).                                                                                                                                                                                                               |
| `query('...')` | Un objeto [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) de Elasticsearch en formato JSON que selecciona los documentos que se van a leer (opcional). Debe ir después de los argumentos posicionales. Valor predeterminado: `{"match_all": {}}`. |

Los argumentos `url`, `index`, `user` y `password` también pueden indicarse con la forma `key = value`. Los argumentos posicionales ocupan estas posiciones en ese orden, y especificar un argumento a la vez de forma posicional y como clave (o repetir la misma clave) produce un error.

Los siguientes argumentos pueden especificarse con la forma `key = value` (o como claves de una colección con nombre):

| Clave          | Descripción                                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | El nombre de usuario para la autenticación básica HTTP.                                                                                                                                           |
| `password`     | La contraseña para la autenticación básica HTTP.                                                                                                                                                  |
| `bearer_token` | Un token que se envía como `Authorization: Bearer <token>`, por ejemplo, un token de cuenta de servicio de Elasticsearch.                                                                         |
| `api_key`      | Una clave de API de Elasticsearch, que se envía como `Authorization: ApiKey <api_key>`. El valor es la cadena `id:api_key` codificada en Base64 que devuelve la API de creación de claves de API. |

Una colección con nombre puede contener la clave `query`. Para sobrescribirla, pase `query('...')` o `query = '...'` después del nombre de la colección.

Además, la función de tabla admite:

| Clave       | Descripción                                                                                                                                                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `structure` | La estructura de la tabla con la forma `'name JSON'`. La estructura debe contener exactamente una columna de tipo `JSON`; los nombres `_id` y `_index` están reservados. Valor predeterminado: `'document JSON'`. |

Los parámetros de configuración de lectura `keep_alive` y `page_size` pueden pasarse en una cláusula `SETTINGS` al final; consulte el [motor de tabla `Elasticsearch`](/es/reference/engines/table-engines/integrations/elasticsearch#creating-a-table) para ver su descripción.

## Autenticación {#authentication}

Se puede especificar como máximo un método de autenticación:

1. **Autenticación básica**. Indique `user` y `password`.
2. **Token Bearer**. Indique `bearer_token`.
3. **Clave de API**. Indique `api_key`.

Si no se especifica ninguno, la solicitud se envía de forma anónima, lo que solo funciona cuando la seguridad está deshabilitada en Elasticsearch.

Almacene las credenciales en una [colección con nombre](/es/concepts/features/configuration/server-config/named-collections) para no tener que especificarlas en cada consulta. Una tabla permanente creada a partir de una colección con nombre (con el motor de tabla `Elasticsearch` o mediante `CREATE TABLE ... AS elasticsearch(...)`) se registra como dependencia de la colección, por lo que `DROP NAMED COLLECTION` queda bloqueado mientras exista la tabla.

## Columnas virtuales {#virtual-columns}

* `_id` — El ID del documento. Tipo: `String`.
* `_index` — El nombre del índice del que se leyó el documento. Tipo: `LowCardinality(String)`.

Cuando una consulta lee únicamente columnas virtuales, no se solicita a Elasticsearch el `_source` del documento. Un índice que no almacena `_source` (es decir, cuyo campo `_source` está deshabilitado en su mapping) solo puede leerse a través de las columnas virtuales: una consulta que lea la columna `JSON` de un índice de este tipo produce un error en lugar de devolver documentos vacíos.

## Ejemplos {#examples}

Contar los documentos de un índice:

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

Lea los campos de los documentos como subcolumnas de la columna `JSON`:

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

Filtre del lado de Elasticsearch con un objeto de Query DSL y ajuste el tamaño de página:

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

Uso de una colección con nombre:

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## Limitaciones {#limitations}

* La función es de solo lectura; `INSERT` no es compatible.
* No se hace pushdown de los predicados. Las condiciones `WHERE` se aplican en ClickHouse una vez descargados los documentos; use el argumento `query` para filtrar en el lado de Elasticsearch.
* La `query` se envía con el `size` de una página. Una consulta cuyo resultado depende de `size`, como una consulta `knn` sin `k`, devuelve un conjunto de documentos que depende de `page_size`. Especifique estos parámetros de forma explícita.
* Cada página es una solicitud de búsqueda independiente, y Elasticsearch vuelve a evaluar en cada solicitud las expresiones de fecha de la `query`, como `now-1h`. El point in time congela los documentos, pero no el reloj, por lo que una `query` dependiente del tiempo puede omitir sin aviso documentos cercanos al límite móvil. Use fechas absolutas en la `query`.
* Cada lectura abre un point in time, recorre los resultados página a página con `search_after`, ordenados por `_shard_doc`, y cierra el point in time al terminar. Si una solicitud de página falla en algún segmento o agota el tiempo de espera en Elasticsearch, se lanza un error en lugar de devolver resultados parciales.
* Se requiere Elasticsearch 7.12 o posterior: la función depende de la API de point in time y del campo de ordenación `_shard_doc`, por lo que las versiones anteriores y OpenSearch rechazan la primera solicitud.
* `page_size` no puede superar el parámetro de configuración de índice `index.max_result_window` de Elasticsearch (`10000` de forma predeterminada).
