La cláusula `SHUFFLE` devuelve las filas del resultado de la consulta en un orden aleatorio uniforme. Se utiliza en lugar de la cláusula [ORDER BY](/es/reference/statements/select/order-by) y no puede combinarse con ella.

Devuelve el mismo resultado que `ORDER BY rand()`, pero se ejecuta en tiempo O(n) en lugar de O(n * log(n)).

`SHUFFLE` puede utilizarse sin `LIMIT`, para aleatorizar el orden de todas las filas, o con `LIMIT n`, para obtener una muestra aleatoria uniforme de `n` filas (que también se devuelven en orden aleatorio). Con `LIMIT n`, cada stream conserva solo `n` filas, por lo que el uso de memoria es O(n) independientemente del número de filas del resultado de la consulta. `OFFSET` y `LIMIT BY` pueden utilizarse del mismo modo que con `ORDER BY`.

<Note>
  Se trata de una funcionalidad experimental. Actívela con el parámetro de configuración [`allow_experimental_shuffle_query`](/es/reference/settings/session-settings#allow_experimental_shuffle_query).
</Note>

## Detalles de implementación {#implementation-details}

Las elecciones aleatorias se realizan sobre la marcha: no se generan ni se almacenan valores aleatorios para las filas por adelantado. Sin `LIMIT`, cada fila se envía a uno de los `max_threads` streams elegido al azar, cada stream se baraja en paralelo con el algoritmo de Fisher-Yates (en partes que caben en la caché de la CPU) y los streams se concatenan. Con `LIMIT n`, cada stream conserva una muestra aleatoria uniforme de `n` filas mediante muestreo de reservorio, que descarta sin examinarlas las filas que no pueden entrar en la muestra, y las muestras se fusionan: el número de filas tomadas de cada stream se determina mediante muestreo sin reemplazo a partir del número de filas de los streams. En una consulta distribuida, los servidores remotos barajan sus datos y adjuntan claves aleatorias ordenadas a las filas, y el initiator fusiona los streams barajados según dichas claves, lo que requiere memoria O(1).

Sin `LIMIT`, `SHUFFLE` mantiene todas las filas en memoria. A diferencia de `ORDER BY`, no vuelca datos a disco.

`ORDER BY rand()` y `ORDER BY rand64()` pueden ejecutarse del mismo modo que `SHUFFLE` (parámetro de configuración `query_plan_use_shuffle_for_order_by_rand`) cuando el valor aleatorio no se utiliza en ninguna otra parte de la consulta y la ordenación externa está deshabilitada. Cuando la ordenación externa está configurada, esta optimización se deshabilita incluso con un `LIMIT` finito, ya que la muestra podría seguir sin caber en memoria y `SHUFFLE` no puede volcar datos a disco. `ORDER BY rand64()` con un límite finito mantiene la ordenación para conservar todos los bits de los valores aleatorios.

## Ejemplos {#examples}

```sql
SET allow_experimental_shuffle_query = 1;

SELECT number FROM numbers(5) SHUFFLE;
```

```text
┌─number─┐
│      3 │
│      0 │
│      4 │
│      1 │
│      2 │
└────────┘
```

Una muestra aleatoria de tres filas:

```sql
SELECT number FROM numbers(1000000) SHUFFLE LIMIT 3;
```

```text
┌─number─┐
│ 493721 │
│  20857 │
│ 871324 │
└────────┘
```

`SHUFFLE` es una palabra clave cuando aparece después de la cláusula `FROM`. Para usar `shuffle` como alias de una table, escriba `AS shuffle`.
