Introducido en: v22.7.0

Agrega un [índice de omisión de datos](/es/reference/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-data_skipping-indexes) a una tabla de la familia `MergeTree`. Es una forma independiente de [`ALTER TABLE ... ADD INDEX`](/es/reference/statements/alter/skipping-index#add-index) y requiere el mismo privilegio `ALTER ADD INDEX`.

## Sintaxis {#syntax}

```sql
CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [db.]table [ON CLUSTER cluster] expression TYPE type [GRANULARITY value]
```

* `expression` - la expresión indexada, opcionalmente entre paréntesis. Una lista entre paréntesis `(expr1, expr2, ...)` crea un único índice sobre todas las expresiones, tal como lo hace `INDEX name (expr1, expr2, ...)` en `CREATE TABLE`.
* `TYPE type [GRANULARITY value]` - igual que en la cláusula `INDEX` de `CREATE TABLE`; consulte [tipos de índices de omisión de datos](/es/reference/engines/table-engines/mergetree-family/mergetree#skip-index-types).
* `IF NOT EXISTS` - si la tabla ya tiene un índice llamado `name`, la consulta no hace nada.

Al igual que `ADD INDEX`, la sentencia solo modifica la metadata de la tabla. Para generar el índice de los datos que ya existen en la tabla, ejecute [`ALTER TABLE ... MATERIALIZE INDEX`](/es/reference/statements/alter/skipping-index#materialize-index).

## Compatibilidad con SQL {#sql-compatibility}

Para mantener la compatibilidad con otros sistemas de bases de datos:

* Se ignoran `ASC` y `DESC` cuando aparecen después de las expresiones de una lista entre paréntesis.
* `CREATE UNIQUE INDEX` se rechaza, salvo que [`create_index_ignore_unique`](/es/reference/settings/session-settings/create#create_index_ignore_unique) sea `1`. En ese caso, se ignora `UNIQUE` y se crea un índice ordinario.
* `CREATE INDEX` sin `TYPE` se rechaza, salvo que [`allow_create_index_without_type`](/es/reference/settings/session-settings/allow#allow_create_index_without_type) sea `1`. En ese caso, la consulta no tiene ningún efecto.

## Ejemplo {#example}

```sql title="Query"
CREATE TABLE t (id UInt64, s String) ENGINE = MergeTree ORDER BY id;
INSERT INTO t SELECT number, toString(number) FROM numbers(1000);
CREATE INDEX idx_s ON t (s) TYPE bloom_filter GRANULARITY 1;
ALTER TABLE t MATERIALIZE INDEX idx_s SETTINGS mutations_sync = 1;
SELECT name, type, expr, granularity FROM system.data_skipping_indices WHERE database = currentDatabase() AND table = 't';
```

```text title="Response"
┌─name──┬─type─────────┬─expr─┬─granularity─┐
│ idx_s │ bloom_filter │ s    │           1 │
└───────┴──────────────┴──────┴─────────────┘
```
