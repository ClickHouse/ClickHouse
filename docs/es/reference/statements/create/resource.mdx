Introducido en: v24.11.0

Crea un recurso para la [planificación de cargas de trabajo](/es/concepts/features/configuration/server-config/workload-scheduling): un tipo de acceso, como las lecturas de disco o el tiempo de CPU, que se planifica entre los workloads creados con [`CREATE WORKLOAD`](/es/reference/statements/create/workload).

## Sintaxis {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`, `IF NOT EXISTS` y `ON CLUSTER` funcionan igual que en [`CREATE WORKLOAD`](/es/reference/statements/create/workload#syntax).

## Modos de acceso {#access-modes}

| Modo de acceso                                | Acceso planificado                                                                                                                                                                | Introducido en |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | Lecturas o escrituras en el disco `disk_name`; consulte [Recursos](/es/concepts/features/configuration/server-config/workload-scheduling#resources)                                  | v24.11.0       |
| `READ ANY DISK`, `WRITE ANY DISK`             | Lecturas o escrituras en cualquier disco                                                                                                                                          | v24.11.0       |
| `MASTER THREAD`, `WORKER THREAD`              | CPU; consulte [Planificación de CPU](/es/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)                                                           | v25.4.0        |
| `QUERY`                                       | Cupos de ejecución de consultas; consulte [Planificación de cupos de ejecución de consultas](/es/concepts/features/configuration/server-config/workload-scheduling#query_scheduling) | v25.6.0        |
| `MEMORY RESERVATION`                          | Memoria; consulte [Reservas de memoria](/es/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)                                                   | v26.6.2        |

Todos los modos de acceso de un recurso deben ser del mismo tipo: disco, threads de CPU, `QUERY` o `MEMORY RESERVATION`. Cada uno de los modos `MASTER THREAD`, `WORKER THREAD`, `QUERY` y `MEMORY RESERVATION` puede pertenecer, como máximo, a un único recurso. `CREATE OR REPLACE RESOURCE` no permite cambiar el tipo de un recurso: elimínelo y vuelva a crearlo.

<Note>
  `MEMORY RESERVATION` es experimental: su sintaxis SQL y su comportamiento pueden cambiar en versiones futuras.
</Note>

## Almacenamiento {#storage}

Los recursos se almacenan del mismo modo que los workloads; consulte [Almacenamiento](/es/reference/statements/create/workload#storage). La tabla [`system.resources`](/es/reference/system-tables/resources) enumera los recursos.

## Privilegios {#privileges}

`CREATE RESOURCE` requiere el privilegio `CREATE RESOURCE`. `CREATE OR REPLACE RESOURCE` requiere además el privilegio `DROP RESOURCE`.

## Ejemplo {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
