Introducido en: v24.11.0

Crea un workload: un nodo de la jerarquía que la [planificación de cargas de trabajo](/es/concepts/features/configuration/server-config/workload-scheduling) utiliza para repartir recursos entre workloads. Los recursos que se van a planificar se crean con [`CREATE RESOURCE`](/es/reference/statements/create/resource).

## Sintaxis {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - reemplaza la definición de un workload existente. No se puede combinar con `IF NOT EXISTS`.
* `IF NOT EXISTS` - si ya existe un workload llamado `name`, la consulta no hace nada.
* `IN parent_name` - crea el workload como hijo del workload `parent_name`. Un workload sin `IN` es un workload raíz. Se rechazan los ciclos de workloads.
* `SETTINGS` - ajustes de planificación del workload, por ejemplo `weight`, `priority`, `max_concurrent_threads` o `max_bytes_per_second`, descritos en [Jerarquía de Cargas de Trabajo](/es/concepts/features/configuration/server-config/workload-scheduling#workloads). Un parámetro de configuración con `FOR resource_name` se aplica solo a ese recurso; de lo contrario, se aplica a todos los recursos. Un parámetro de configuración desconocido produce un error.

Los workloads y los recursos tienen espacios de nombres independientes, por lo que un workload y un recurso pueden tener el mismo nombre. Una consulta se ejecuta en el workload indicado por su parámetro de configuración [`workload`](/es/reference/settings/session-settings/other#workload); consulte [Marcado de carga de trabajo](/es/concepts/features/configuration/server-config/workload-scheduling#workload-markup).

<Note>
  La planificación de reservas de memoria es experimental, lo que incluye el recurso `MEMORY RESERVATION` y los parámetros de configuración de la carga de trabajo `max_memory`, `max_memory_ratio`, `max_memory_before_spill` y `max_memory_to_spill_ratio`. Consulte [Reservas de memoria](/es/concepts/features/configuration/server-config/workload-scheduling#memory-reservations).
</Note>

## Almacenamiento {#storage}

Los workload se almacenan en disco en [`workload_path`](/es/reference/settings/server-settings/settings/workload#workload_path) o, si está configurado, en ZooKeeper en [`workload_zookeeper_path`](/es/reference/settings/server-settings/settings/workload#workload_zookeeper_path). Con el almacenamiento en ZooKeeper, se rechaza `ON CLUSTER`, ya que las definiciones se replican automáticamente. Los workload [definidos en la configuración del servidor](/es/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads) no se pueden reemplazar ni eliminar mediante SQL. La tabla [`system.workloads`](/es/reference/system-tables/workloads) muestra los workload.

## Privilegios {#privileges}

`CREATE WORKLOAD` requiere el privilegio `CREATE WORKLOAD`. `CREATE OR REPLACE WORKLOAD` requiere además el privilegio `DROP WORKLOAD`.

## Ejemplo {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
