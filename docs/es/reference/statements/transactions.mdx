Las sentencias de control de transacciones `BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK` y `SET TRANSACTION SNAPSHOT` agrupan varias consultas sobre tablas `MergeTree` en una única transacción.
Las consultas de una transacción leen una instantánea coherente de los cambios de los que otras transacciones han hecho commit.
Las escrituras realizadas fuera de una transacción no están aisladas: un `INSERT`, `TRUNCATE TABLE` o `ALTER TABLE ... DELETE` que se ejecuta fuera de una transacción es visible para la siguiente consulta de una transacción en curso, por lo que, para obtener una vista estable, los escritores también deben usar transacciones, por ejemplo mediante [`implicit_transaction`](/es/reference/settings/session-settings/implicit#implicit_transaction).
Las demás transacciones solo ven sus cambios después de `COMMIT`, y `ROLLBACK` los descarta.
Las consultas que se ejecutan fuera de una transacción pueden ver los cambios de una transacción en curso antes de que se haga commit de esta.

## Sintaxis {#syntax}

```sql
BEGIN TRANSACTION
START TRANSACTION
COMMIT
ROLLBACK
SET TRANSACTION SNAPSHOT snapshot
```

Una transacción pertenece a una sesión, y una sesión tiene como máximo una transacción.
A través de HTTP, envíe todas las consultas de una transacción con el mismo `session_id`: una solicitud sin `session_id` se ejecuta en su propia sesión, que finaliza con la solicitud.
Si una transacción sigue en curso cuando finaliza su sesión, se revierte.

## BEGIN TRANSACTION {#begin-transaction}

Inicia una transacción en la sesión actual. `START TRANSACTION` es un alias, introducido en v24.3.0.

Las transacciones anidadas no son compatibles: ejecutar `BEGIN TRANSACTION` dentro de una transacción lanza una excepción `INVALID_TRANSACTION`.

## COMMIT {#commit}

Hace commit de la transacción actual y hace que sus cambios sean visibles para otras transacciones.
Ejecutar `COMMIT` sin una transacción en curso lanza una excepción `INVALID_TRANSACTION`.

Si una consulta dentro de la transacción falla, la transacción se revierte. Una consulta que no se puede analizar (por ejemplo, debido a un error de sintaxis), o cuyos parámetros de consulta están ausentes o no son válidos, no se ejecuta y la transacción sigue en curso, por lo que un `COMMIT` posterior hace commit de ella igualmente.
Hasta que `ROLLBACK` finalice una transacción revertida, `COMMIT` y las demás consultas posteriores lanzan una excepción `INVALID_TRANSACTION`. Solo se siguen ejecutando `ROLLBACK`, `SET TRANSACTION SNAPSHOT` y las consultas `EXPLAIN` distintas de `EXPLAIN ANALYZE`.

El parámetro de configuración [`wait_changes_become_visible_after_commit_mode`](/es/reference/settings/session-settings/other#wait_changes_become_visible_after_commit_mode) controla qué espera `COMMIT`.

## ROLLBACK {#rollback}

Revierte la transacción actual y descarta sus cambios.
Ejecutar `ROLLBACK` sin una transacción en curso lanza una excepción `INVALID_TRANSACTION`.

## SET TRANSACTION SNAPSHOT {#set-transaction-snapshot}

Cambia la instantánea que lee la transacción actual al número de secuencia de commit (CSN) `snapshot`; por ejemplo, un valor que [`transactionLatestSnapshot`](/es/reference/functions/regular-functions/other-functions#transactionLatestSnapshot) devolvió en una transacción anterior.
A partir de ese momento, la transacción ve sus propios cambios, los datos escritos fuera de transacciones y los cambios de las transacciones de las que se ha hecho commit hasta ese CSN.
Solo lee las partes que el servidor todavía conserva y no las protege de su eliminación: en cuanto no queda ninguna transacción en ejecución iniciada antes de que una fusión, una mutación u otra consulta eliminara una parte, el servidor puede borrar esa parte y, a partir de entonces, una instantánea anterior deja de ver sus filas.
No dependa de `SET TRANSACTION SNAPSHOT` para realizar lecturas repetibles de datos históricos.
Ejecutar `SET TRANSACTION SNAPSHOT` sin una transacción actual lanza una excepción `INVALID_TRANSACTION`.

Los valores de `0` a `32` están reservados y lanzan una excepción `INVALID_TRANSACTION`, salvo dos:
`1` hace visibles únicamente los datos escritos fuera de transacciones y los cambios propios de la transacción, y `3` hace visibles todas las partes de una tabla, incluidas las partes de transacciones que aún no han hecho commit y las partes que las transacciones eliminaron o revirtieron.

## Consultas dentro de una transacción {#queries-inside-a-transaction}

Una transacción puede ejecutar consultas `SELECT`, `INSERT`, `DELETE`, `OPTIMIZE`, `TRUNCATE TABLE`, `SET` y `EXPLAIN`, así como mutaciones `ALTER TABLE` y operaciones sobre particiones.
Otras consultas, como `CREATE TABLE`, `UPDATE` o `ALTER TABLE ... ADD COLUMN`, lanzan una excepción `NOT_IMPLEMENTED`, al igual que las consultas sobre tablas que no admiten transacciones, como las tablas `ReplicatedMergeTree` o `Memory`, o `system.transactions`.

Las inserciones asíncronas no son compatibles dentro de una transacción y [`async_insert`](/es/reference/settings/session-settings/async-insert#async_insert) está habilitado de forma predeterminada, por lo que un `INSERT ... VALUES` o un `INSERT ... SELECT` dentro de una transacción lanza una excepción `NOT_IMPLEMENTED`, a menos que se deshabilite `async_insert`, por ejemplo con `SET async_insert = 0`.

Si [`throw_on_unsupported_query_inside_transaction`](/es/reference/settings/session-settings/throw-on#throw_on_unsupported_query_inside_transaction) se establece en `0`, algunas de estas consultas se ejecutan fuera de la transacción en lugar de lanzar una excepción, por lo que `ROLLBACK` no las deshace; por ejemplo, un `CREATE TABLE` o un `INSERT` en una tabla `Memory`.

Si [`implicit_transaction`](/es/reference/settings/session-settings/implicit#implicit_transaction) está habilitado, cada consulta que se ejecuta fuera de una transacción lo hace en su propia transacción, de la que se hace commit si la consulta se completa correctamente y se revierte si falla.

## Ejemplos {#examples}

Revertir una inserción:

```sql title="Query"
CREATE TABLE t (n UInt64) ENGINE = MergeTree ORDER BY n;
SET async_insert = 0;

BEGIN TRANSACTION;
INSERT INTO t VALUES (1);
SELECT count() FROM t;
ROLLBACK;
SELECT count() FROM t;
```

```text title="Response"
┌─count()─┐
│       1 │
└─────────┘
┌─count()─┐
│       0 │
└─────────┘
```

Hacer commit de una inserción:

```sql title="Query"
BEGIN TRANSACTION;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```text title="Response"
┌─n─┐
│ 2 │
└───┘
```
