```sql
ALTER TABLE [db.]table [ON CLUSTER cluster] DELETE WHERE filter_expr
```

Elimina los datos que coinciden con la expresión de filtrado especificada. Se implementa como una [mutación](/es/reference/statements/alter/index#mutations).

<Warning>
  El prefijo `ALTER TABLE` indica que se trata de una operación pesada, a diferencia de consultas similares en bases de datos OLTP. `ALTER TABLE ... DELETE` reescribe cada parte de datos que contiene filas que coinciden con la expresión de filtrado, lo que genera una cantidad considerable de E/S de escritura. Úselo con moderación, ya que puede afectar al rendimiento de `SELECT`.

  Para las tablas `MergeTree`, considere usar la [consulta `DELETE FROM`](/es/reference/statements/delete), que realiza una eliminación ligera y puede ser considerablemente más rápida. Para cargas de trabajo que requieren eliminaciones o correcciones frecuentes, considere usar [`ReplacingMergeTree`](/es/concepts/features/operations/update/replacing-merge-tree) o [`CollapsingMergeTree`](/es/reference/engines/table-engines/mergetree-family/collapsingmergetree).
</Warning>

`filter_expr` debe ser de tipo `UInt8`. La consulta elimina las filas de la tabla para las que esta expresión toma un valor distinto de cero.

Una consulta puede contener varios comandos separados por comas.

La sincronía del procesamiento de la consulta se define mediante la configuración [mutations&#95;sync](/es/reference/settings/session-settings/mutations#mutations_sync). De forma predeterminada, es asíncrona.
