Modifica una política de filas.

Sintaxis:

```sql
-- Rename: exactly one fully qualified policy (one name on one target).
-- RENAME TO may be combined with the same optional alteration clauses as below.
ALTER [ROW] POLICY [IF EXISTS] name
    ON { [database.]table | database.* }
    RENAME TO new_name
    [ON CLUSTER cluster_name]
    [AS {PERMISSIVE | RESTRICTIVE}]
    [FOR SELECT]
    [USING {condition | NONE}][,...]
    [TO {role [,...] | ALL | ALL EXCEPT role [,...]}]

-- Multiple names on one table target (no RENAME)
ALTER [ROW] POLICY [IF EXISTS] name [, ...]
    [ON CLUSTER cluster_name]
    ON { [database.]table | database.* }
    [AS {PERMISSIVE | RESTRICTIVE}]
    [FOR SELECT]
    [USING {condition | NONE}][,...]
    [TO {role [,...] | ALL | ALL EXCEPT role [,...]}]

-- One name on multiple table targets (no RENAME)
ALTER [ROW] POLICY [IF EXISTS] name
    [ON CLUSTER cluster_name]
    ON { [database.]table | database.* } [, ...]
    [AS {PERMISSIVE | RESTRICTIVE}]
    [FOR SELECT]
    [USING {condition | NONE}][,...]
    [TO {role [,...] | ALL | ALL EXCEPT role [,...]}]

-- Mixed packing: each name paired with its own table target (no RENAME)
ALTER [ROW] POLICY [IF EXISTS]
    name ON { [database.]table | database.* } [, name ON { [database.]table | database.* } ...]
    [ON CLUSTER cluster_name]
    [AS {PERMISSIVE | RESTRICTIVE}]
    [FOR SELECT]
    [USING {condition | NONE}][,...]
    [TO {role [,...] | ALL | ALL EXCEPT role [,...]}]
```

`RENAME TO` solo se acepta cuando la sentencia especifica **exactamente una** política en **una** tabla de destino. Las listas agrupadas de varios nombres o varias tablas no pueden incluir `RENAME TO`; cambie el nombre de esas políticas en sentencias independientes. En esta forma de política única, `RENAME TO` puede combinarse con otras modificaciones, como `AS`, `USING` y `TO`, en la misma sentencia.

Sin `RENAME TO`, la agrupación se ajusta a `ParserRowPolicyNames`: varios nombres en **un** destino, un nombre en **varios** destinos o pares mixtos de `name ON target`. No se acepta la combinación de varios nombres × varias tablas (`p1, p2 ON t1, t2`). El `ON CLUSTER` opcional se aplica una sola vez a toda la sentencia; ejecute sentencias `ALTER ROW POLICY` independientes cuando se requieran clústeres distintos.

Ejemplos:

```sql
-- Single-policy rename
ALTER ROW POLICY p1 ON db.table RENAME TO p1_new;

-- Rename plus other alterations on the same single policy
ALTER POLICY old_name ON db.table RENAME TO new_name USING id > 10;

-- Multiple names, one table
ALTER POLICY p1, p2 ON db.table TO ALL;

-- One name, multiple tables
ALTER POLICY p1 ON db.table, db.table2 USING NONE;

-- Mixed targets without rename
ALTER POLICY p1 ON db.table, p2 ON db2.table2 TO ALL;
```

**Parte de:** `ALTER`

**Relacionado:** `CREATE ROW POLICY`, `ALTER`, `SHOW`
