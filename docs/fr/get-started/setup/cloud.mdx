### Ajouter des données via la Console SQL {#add-data-using-the-sql-console}

        Comme la plupart des systèmes de gestion de bases de données, ClickHouse regroupe logiquement les tables dans des **bases de données**. Utilisez la commande [`CREATE DATABASE`](/fr/reference/statements/create/database) pour créer une nouvelle base de données dans ClickHouse :

        ```sql
        CREATE DATABASE IF NOT EXISTS helloworld
        ```

        Exécutez la commande suivante pour créer une table nommée `my_first_table` dans la base de données `helloworld` :

        ```sql
        CREATE TABLE helloworld.my_first_table
        (
            user_id UInt32,
            message String,
            timestamp DateTime,
            metric Float32
        )
        ENGINE = MergeTree()
        PRIMARY KEY (user_id, timestamp)
        ```

        Dans l&#39;exemple ci-dessus, `my_first_table` est une table [`MergeTree`](/fr/reference/engines/table-engines/mergetree-family/mergetree) comportant quatre colonnes :

        * `user_id` : un entier non signé de 32 bits ([UInt32](/fr/reference/data-types/int-uint))
        * `message` : un type de données [String](/fr/reference/data-types/string), qui remplace des types tels que `VARCHAR`, `BLOB`, `CLOB` et d&#39;autres issus d&#39;autres systèmes de bases de données
        * `timestamp` : une valeur [DateTime](/fr/reference/data-types/datetime), qui représente un instant précis
        * `metric` : un nombre à virgule flottante sur 32 bits ([Float32](/fr/reference/data-types/float))

        <Info>
          **Moteurs de table**

          Les moteurs de table déterminent :

          * comment et où les données sont stockées ;
          * quelles requêtes sont prises en charge ;
          * si les données sont répliquées ou non.

          <br />

          Il existe de nombreux moteurs de table, mais pour une table simple sur un serveur ClickHouse à nœud unique, [`MergeTree`](/fr/reference/engines/table-engines/mergetree-family/mergetree) sera probablement le choix le plus indiqué.
        </Info>

#### Brève introduction aux clés primaires {#a-brief-intro-to-primary-keys}

        Avant d&#39;aller plus loin, il est important de comprendre le fonctionnement des clés primaires dans ClickHouse (leur implémentation
        peut sembler surprenante !) :

        * dans ClickHouse, les clés primaires ne sont ***pas uniques*** pour chaque ligne d&#39;une table

        La clé primaire d’une table ClickHouse détermine l’ordre dans lequel les données sont triées lors de leur écriture sur disque. Toutes les 8,192 lignes ou tous les 10MB de
        données (ce que l’on appelle la **granularité de l’index**), une entrée est créée dans le fichier d’index de clé primaire. Ce principe de granularité
        produit un **index clairsemé** qui tient facilement en mémoire, et les granules correspondent à une bande représentant la plus petite quantité de
        données de colonne traitée lors des requêtes `SELECT`.

        La clé primaire peut être définie à l&#39;aide du paramètre `PRIMARY KEY`. Si vous définissez une table sans spécifier de `PRIMARY KEY`,
        la clé correspond alors au tuple spécifié dans la clause `ORDER BY`. Si vous spécifiez à la fois une `PRIMARY KEY` et un `ORDER BY`, la clé primaire doit être un sous-ensemble de l&#39;ordre de tri.

        La clé primaire est également la clé de tri, qui est un tuple `(user_id, timestamp)`.  Par conséquent, les données stockées dans chaque
        fichier de colonne seront triées par `user_id`, puis par `timestamp`.

        Pour une analyse approfondie des concepts fondamentaux de ClickHouse, consultez [« Concepts fondamentaux »](/fr/concepts/core-concepts/index).

#### Insérer des données dans votre table {#insert-data-into-your-table}

        Vous pouvez utiliser la commande habituelle [`INSERT INTO TABLE`](/fr/reference/statements/insert-into) avec ClickHouse, mais il est important de comprendre que chaque insertion dans une table [`MergeTree`](/fr/reference/engines/table-engines/mergetree-family/mergetree) entraîne la création d&#39;une **partie de données** dans le stockage.

        <Tip>
          **Bonne pratique ClickHouse**

          Insérez un grand nombre de lignes par batch, soit des dizaines de milliers, voire des millions de
          lignes à la fois. Rassurez-vous : ClickHouse absorbe sans difficulté de tels volumes, et vous [réaliserez des économies](/fr/concepts/best-practices/selecting-an-insert-strategy#batch-inserts-if-synchronous) en envoyant moins de requêtes d’écriture à votre service.
        </Tip>

        <br />

        Même pour un exemple simple, insérons plusieurs lignes à la fois :

        ```sql
        INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
            (101, 'Hello, ClickHouse!',                                 now(),       -1.0    ),
            (102, 'Insert a lot of rows per batch',                     yesterday(), 1.41421 ),
            (102, 'Sort your data based on your commonly-used queries', today(),     2.718   ),
            (101, 'Granules are the smallest chunks of data read',      now() + 5,   3.14159 )
        ```

        <Note>
          Notez que la colonne `timestamp` est remplie à l&#39;aide de diverses fonctions [**Date**](/fr/reference/data-types/date) et [**DateTime**](/fr/reference/data-types/datetime). ClickHouse propose des centaines de fonctions utiles, que vous pouvez [consulter dans la section **Fonctions**](/fr/reference/functions/index).
        </Note>

        Vérifions que tout fonctionne :

        ```sql
        SELECT * FROM helloworld.my_first_table
        ```

### Ajouter des données avec le Client ClickHouse {#add-data-using-the-clickhouse-client}

        Vous pouvez également vous connecter à votre service ClickHouse Cloud à l&#39;aide d&#39;un outil en ligne de commande nommé [**client ClickHouse**](/fr/concepts/features/interfaces/client). Cliquez sur `Connect` dans le menu de gauche pour accéder à ces informations. Dans la boîte de dialogue, sélectionnez `Native` dans la liste déroulante :

        <div className="ch-image-lg">
          <Frame>
            ![informations de connexion du client ClickHouse](/images/_snippets/client_details.webp)
          </Frame>
        </div>

        <br />

        1. Installez [ClickHouse](/fr/get-started/setup/self-managed/quick-install).

        2. Exécutez la commande suivante en remplaçant le nom d’hôte, le nom d’utilisateur et le mot de passe par les vôtres :

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password>
        ```

        Si l&#39;invite avec le smiley s&#39;affiche, vous êtes prêt à exécuter des requêtes !

        ```response
        :)
        ```

        3. Faites un essai en exécutant la requête suivante :

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        ```

        Notez que la réponse s&#39;affiche sous la forme d&#39;un tableau clair et lisible :

        ```response
        ┌─user_id─┬─message────────────────────────────────────────────┬───────────timestamp─┬──metric─┐
        │     102 │ Insert a lot of rows per batch                     │ 2022-03-21 00:00:00 │ 1.41421 │
        │     102 │ Sort your data based on your commonly-used queries │ 2022-03-22 00:00:00 │   2.718 │
        │     101 │ Hello, ClickHouse!                                 │ 2022-03-22 14:04:09 │      -1 │
        │     101 │ Granules are the smallest chunks of data read      │ 2022-03-22 14:04:14 │ 3.14159 │
        └─────────┴────────────────────────────────────────────────────┴─────────────────────┴─────────┘

        4 rows in set. Elapsed: 0.008 sec.
        ```

        4. Ajoutez une clause [`FORMAT`](/fr/reference/statements/select/format) pour indiquer l&#39;un des [nombreux formats de sortie pris en charge par ClickHouse](/fr/reference/formats/index) :

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        FORMAT TabSeparated
        ```

        Dans la requête ci-dessus, la sortie est renvoyée au format tab-separated :

        ```response
        Query id: 3604df1c-acfd-4117-9c56-f86c69721121

        102 Insert a lot of rows per batch      2022-03-21 00:00:00     1.41421
        102 Sort your data based on your commonly-used queries  2022-03-22 00:00:00     2.718
        101 Hello, ClickHouse!  2022-03-22 14:04:09     -1
        101 Granules are the smallest chunks of data read       2022-03-22 14:04:14     3.14159

        4 rows in set. Elapsed: 0.005 sec.
        ```

        5. Pour quitter `clickhouse client`, saisissez la commande **exit** :

        <br />

        ```bash
        exit
        ```

### Importer un fichier {#upload-a-file}

        Lorsque l’on débute avec une base de données, une tâche courante consiste à insérer des données dont on dispose déjà sous forme de fichiers. Nous proposons en ligne des
        données d’exemple à insérer, qui représentent des données de clickstream : elles comprennent un ID utilisateur, l’URL visitée et
        le timestamp de l’événement.

        Supposons que nous ayons le texte suivant dans un fichier CSV nommé `data.csv` :

        ```bash title="data.csv"
        102,This is data in a file,2022-02-22 10:43:28,123.45
        101,It is comma-separated,2022-02-23 00:00:00,456.78
        103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
        ```

        1. La commande suivante insère les données dans `my_first_table` :

        <br />

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password> \
        --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
        ```

        2. Si vous interrogez la table depuis la console SQL, vous constaterez que les nouvelles lignes y apparaissent désormais :

        <br />
