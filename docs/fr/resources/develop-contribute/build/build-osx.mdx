<Info>
  **Ce guide de compilation s’adresse aux contributeurs qui modifient ClickHouse lui-même.**

  Si vous ne modifiez pas le code source de ClickHouse, vous pouvez installer une version précompilée de ClickHouse comme indiqué dans le [Quick Start](/fr/get-started/setup/install).
</Info>

ClickHouse peut être compilé sur macOS x86&#95;64 (Intel) et arm64 (Apple Silicon), à partir de macOS 10.15 (Catalina).

Comme compilateur, seul Clang fourni par Homebrew est pris en charge.

## Installer les prérequis {#install-prerequisites}

Commencez par consulter la [documentation générale sur les prérequis](/fr/resources/develop-contribute/introduction/developer-instruction).

Ensuite, installez [Homebrew](https://brew.sh/) et exécutez

Puis exécutez :

```bash
brew update
brew install ccache cmake ninja libtool gettext llvm lld binutils grep findutils nasm bash rust rustup
```

<Note>
  Comme `llvm`, le paquet `rustup` de Homebrew est keg-only : son répertoire `bin` n’est donc pas ajouté automatiquement au `PATH`. Exportez-le de la même manière que le `PATH` de `llvm` dans [Construire ClickHouse](#build-clickhouse) :

  ```bash
  export PATH=$(brew --prefix rustup)/bin:$PATH
  ```

  ClickHouse fixe également la version de la chaîne d’outils Rust utilisée par le module contrib `corrosion`. Installez-la et sélectionnez-la en suivant la section [Installer le compilateur Rust](/fr/development/build#install-the-rust-compiler-optional) du guide de construction sous Linux. Sans cela, `cmake` échoue sur le module contrib `corrosion` avec l’erreur `Cannot find nightly-<date> Rust toolchain`.
</Note>

<Note>
  Par défaut, Apple utilise un système de fichiers insensible à la casse. Bien que cela n’ait généralement pas d’impact sur la compilation (en particulier, les compilations depuis zéro fonctionneront), cela peut perturber des opérations sur les fichiers comme `git mv`.
  Pour un développement sérieux sur macOS, assurez-vous que le code source est stocké sur un volume de disque sensible à la casse ; consultez par exemple [ces instructions](https://brianboyko.medium.com/a-case-sensitive-src-folder-for-mac-programmers-176cc82a3830).
</Note>

## Construction de ClickHouse {#build-clickhouse}

Pour la construction, vous devez utiliser le compilateur Clang de Homebrew :

```bash
cd ClickHouse
mkdir build
export PATH=$(brew --prefix llvm)/bin:$PATH
cmake -S . -B build
cmake --build build
# The resulting binary will be created at: build/programs/clickhouse
```

<Note>
  Une simple commande `brew install llvm` installe toujours la dernière version de LLVM proposée par Homebrew, qui peut être plus récente que la version de Clang figée pour l’intégration continue et les constructions Linux (voir [Installer le compilateur Clang](/fr/development/build#install-the-clang-compiler)). Une version plus récente de Clang peut activer des diagnostics `-Weverything` qui ne sont pas encore neutralisés dans la construction et faire échouer celle-ci avec `-Werror`. Dans ce cas, plutôt que de désactiver les avertissements, installez la version majeure figée, par exemple via une formule versionnée (`brew install llvm@<version>`) si Homebrew la propose encore.
</Note>

<Note>
  Si vous rencontrez des erreurs `ld: archive member '/' not a mach-o file in ...` lors de l’édition des liens, il peut être nécessaire
  d’utiliser llvm-ar en définissant l’option `-DCMAKE_AR=/opt/homebrew/opt/llvm/bin/llvm-ar`.
</Note>

## Points à retenir {#caveats}

Si vous prévoyez d’exécuter `clickhouse-server`, veillez à augmenter la variable système `maxfiles`.

<Note>
  Vous devrez utiliser sudo.
</Note>

Pour cela, créez le fichier `/Library/LaunchDaemons/limit.maxfiles.plist` avec le contenu suivant :

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
        "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
  <dict>
    <key>Label</key>
    <string>limit.maxfiles</string>
    <key>ProgramArguments</key>
    <array>
      <string>launchctl</string>
      <string>limit</string>
      <string>maxfiles</string>
      <string>524288</string>
      <string>524288</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>ServiceIPC</key>
    <false/>
  </dict>
</plist>
```

Attribuez au fichier les permissions appropriées :

```bash
sudo chown root:wheel /Library/LaunchDaemons/limit.maxfiles.plist
```

Vérifiez que le fichier est correct :

```bash
plutil /Library/LaunchDaemons/limit.maxfiles.plist
```

Rechargez le fichier (ou redémarrez) :

```bash
sudo launchctl load -w /Library/LaunchDaemons/limit.maxfiles.plist
```

Pour vérifier que cela fonctionne, utilisez les commandes `ulimit -n` ou `launchctl limit maxfiles`.
