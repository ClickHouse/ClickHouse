Si la façon dont `clickhouse client` et clickhouse-local affichent le Prompt dans votre terminal ne vous convient pas, vous pouvez le modifier en y ajoutant un préfixe.
Cet article explique comment modifier le Prompt comme vous le souhaitez.

Le Prompt par défaut est le nom de votre ordinateur local suivi de `:) ` :

<div className="ch-image-md">
  <Frame>
    ![Prompt par défaut du client ClickHouse](/images/knowledgebase/change-the-prompt-in-clickhouse-client/0_prompt.webp)
  </Frame>
</div>

Voici les variables que vous pouvez utiliser dans un Prompt : `{user}`, `{host}`

Il existe plusieurs façons de mettre à jour le Prompt, et nous allons les passer en revue une par une.

## Option `--prompt` {#--prompt-flag}

La première façon de modifier cette option consiste à utiliser `--prompt` :

```bash
clickhouse --prompt 👉
```

Cela ajoutera l’emoji en forme de doigt avant le smiley :

<div className="ch-image-md">
  <Frame>
    ![Prompt du client ClickHouse avec un emoji en forme de doigt](/images/knowledgebase/change-the-prompt-in-clickhouse-client/1_prompt.webp)
  </Frame>
</div>

## Fichier de configuration - niveau supérieur {#config-file---top-level}

Vous pouvez également définir un préfixe de Prompt dans un fichier `config.xml` :

```xml
<config>
    <prompt>👉 </prompt>
</config>
```

```
clickhouse
```

<div className="ch-image-md">
  <Frame>
    ![Prompt du client ClickHouse avec un fichier de configuration](/images/knowledgebase/change-the-prompt-in-clickhouse-client/2_prompt.webp)
  </Frame>
</div>

Nous pouvons utiliser un fichier de configuration portant le nom de notre choix et le passer à l&#39;aide de l&#39;option `-C` :

```xml
<config>
    <prompt>🎄 </prompt>
</config>
```

```
clickhouse -C christmas.xml
```

</div>

Vous préférez rédiger vos fichiers de configuration en YAML ?
C&#39;est également possible :

```yaml

```

```bash

```

## Fichier de configuration - connections_credentials {#config-file---connections_credentials}

Vous pouvez également définir un Prompt pour chaque jeu d’identifiants de connexion.
Cela n’a de sens que si vous utilisez clickhouse-client.

```xml
<config>
    <connections_credentials>
        <connection>
            <n>prod</n>
            <hostname>127.0.0.1</hostname>
            <port>9000</port>
            <secure>0</secure>
            <user>default</user>
            <prompt>\e[31m[PRODUCTION]\e[0m {user}@prod</prompt>
        </connection>
        <connection>
            <n>dev</n>
            <hostname>127.0.0.1</hostname>
            <port>9000</port>
            <secure>0</secure>
            <user>default</user>
            <prompt>\e[32m[DEVELOPMENT]\e[0m {user}@dev</prompt>
        </connection>
    </connections_credentials>
</config>
```

Nous pouvons ensuite essayer de nous connecter à l’aide de la connexion `dev` :

```bash
clickhouse client -C connections.xml --connection dev
```

  <Frame>

  </Frame>
</div>

Ou celle de `prod` :

```bash
clickhouse client -C connections.xml --connection prod
```

<div className="ch-image-md">
  <Frame>
    ![Prompt du client ClickHouse avec connexion de production](/images/knowledgebase/change-the-prompt-in-clickhouse-client/6_prompt.webp)

Et voici une version YAML :

```yaml
connections_credentials:
  connection:
    - name: prod
      hostname: 127.0.0.1
      port: 9000
      secure: 0
      user: default
      prompt: "\e[35m[PRODUCTION]\e[0m {user}@{host}"
    - name: dev
      hostname: 127.0.0.1
      port: 9000
      secure: 0
      user: default
      prompt: "\e[34m[DEVELOPMENT]\e[0m {user}@{host}"
```

Avec la connexion `dev` :

```bash
clickhouse client -C connections.yaml --connection dev
```
