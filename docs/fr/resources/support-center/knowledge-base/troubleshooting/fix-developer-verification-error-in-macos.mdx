## Corriger l&#39;erreur de vérification du développeur sous macOS {#fix-the-developer-verification-error-in-macos}

Par défaut, macOS refuse d&#39;exécuter une application ou un outil téléchargé depuis Internet s&#39;il n&#39;est pas signé par un développeur identifié et notarié par Apple.

Depuis la version 26.7.4 (et dans toutes les versions 26.8 et ultérieures), les versions compilées de ClickHouse pour macOS sont signées avec le Developer ID de ClickHouse Inc. et notariées par Apple. Elles sont publiées sur la [page des versions GitHub](https://github.com/ClickHouse/ClickHouse/releases) sous les noms `clickhouse-macos.zip` (Intel) et `clickhouse-macos-aarch64.zip` (Apple silicon), et c&#39;est également elles qu&#39;installe le cask Homebrew. Si vous utilisez l&#39;une d&#39;entre elles, macOS exécute `clickhouse` sans le moindre avertissement et vous n&#39;avez rien à faire de ce qui est décrit dans cet article.

Cette erreur peut néanmoins apparaître si vous exécutez un binaire non signé que macOS a placé en quarantaine, par exemple :

* une ancienne version de ClickHouse installée avec Homebrew - exécutez `brew upgrade --cask clickhouse` pour obtenir la version signée ;
* le binaire auto-extractible `clickhouse-macos` ou `clickhouse-macos-aarch64` de la page des versions GitHub, téléchargé avec un navigateur web - téléchargez plutôt le fichier `.zip` de la même version ;
* une version antérieure à la 26.7.4, téléchargée avec un navigateur web.

Le binaire installé avec `curl https://clickhouse.com/ | sh` n&#39;est pas signé, mais `curl` ne place pas en quarantaine les fichiers qu&#39;il télécharge ; macOS l&#39;exécute donc sans afficher cette erreur.

Lorsque vous tentez d&#39;exécuter un binaire `clickhouse` placé en quarantaine, l&#39;erreur suivante peut s&#39;afficher :

<Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/dev-verification-error.webp" size="md" alt="Boîte de dialogue d'erreur de vérification du développeur sous MacOS" border />

Si vous ne pouvez pas passer à une version compilée signée, retirez le binaire de la quarantaine, soit dans les Réglages système, soit depuis le terminal.

## Procédure via les réglages système {#system-settings-process}

1. Essayez d’exécuter une première fois le binaire `clickhouse`, afin que macOS affiche l’erreur ci-dessus et enregistre le binaire bloqué.

2. Ouvrez **Réglages système**.

3. Accédez à **Confidentialité et sécurité** :

   <Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/privacy-and-security-default-view.webp" size="md" alt="Vue par défaut des réglages MacOS Confidentialité et sécurité" border />

4. Faites défiler jusqu’à la section **Sécurité** pour trouver un message indiquant que *« clickhouse-macos-aarch64 » a été bloqué, car il ne provient pas d’un développeur identifié*.

5. Cliquez sur **Autoriser quand même** (**Ouvrir quand même** dans les versions récentes de macOS).

   <Image img="/images/knowledgebase/fix-the-developer-verification-error-in-macos/privacy-and-security-screen-allow-anyway.webp" size="md" alt="Réglages MacOS Confidentialité et sécurité affichant le bouton Autoriser quand même" border />

6. Saisissez le mot de passe de votre compte macOS.

Vous devriez maintenant pouvoir exécuter les commandes `clickhouse` dans votre terminal. macOS peut vous demander une nouvelle confirmation lors de la prochaine exécution.

## Processus dans le terminal {#terminal-process}

Si le bouton dans Réglages système ne résout pas le problème, ou si vous préférez la ligne de commande, supprimez l’attribut de quarantaine du binaire avec `xattr`.

Si `clickhouse` se trouve dans votre `PATH`, repérez son emplacement :

```shell
which clickhouse
```

Cela devrait afficher quelque chose comme :

```shell
/opt/homebrew/bin/clickhouse
```

Supprimez `clickhouse` de la quarantaine en exécutant `xattr -d com.apple.quarantine`, puis en ajoutant le chemin renvoyé par la commande précédente :

```shell
xattr -d com.apple.quarantine /opt/homebrew/bin/clickhouse
```

Vous devriez maintenant pouvoir lancer l’exécutable `clickhouse` :

```shell
clickhouse
```

Cela devrait afficher quelque chose comme :

```shell
Use one of the following commands:
clickhouse local [args]
clickhouse client [args]
clickhouse benchmark [args]
...
```
