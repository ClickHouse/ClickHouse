ClickHouse BYOC sur AWS prend en charge deux options de connexion privée : l’appairage de VPC et AWS PrivateLink.

<div id="common-prerequisites">
  ## Prérequis {#common-prerequisites}
</div>

Étapes communes requises pour VPC peering et PrivateLink.

### Activez le load balancer privé pour ClickHouse BYOC {#step-enable-private-load-balancer-for-clickhouse-byoc}

Dans la console ClickHouse Cloud, activez le **load balancer privé** pour votre infrastructure BYOC.

<div className="ch-image-md">
  <Frame>
    ![BYOC - Activer le load balancer privé](/images/cloud/reference/byoc-private-load-balancer.webp)
  </Frame>
</div>

## Configurer l’appairage de VPC {#aws-vpc-peering}

Pour créer ou supprimer un appairage de VPC pour ClickHouse BYOC, suivez les étapes suivantes :

<Steps>
  <Step title="Créer une connexion de peering" id="step-1-create-a-peering-connection">
    1. Accédez au VPC Dashboard dans le compte ClickHouse BYOC.
    2. Sélectionnez Connexions d’appairage.
    3. Cliquez sur Create Connexion d’appairage
    4. Définissez VPC Requester sur l’ID du ClickHouse VPC.
    5. Définissez VPC Accepter sur l’ID du VPC cible. (Sélectionnez un autre compte si nécessaire)
    6. Cliquez sur Create Connexion d’appairage.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Créer une connexion d’appairage](/images/cloud/reference/byoc-vpcpeering-1.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Accepter la demande de connexion de peering" id="step-2-accept-the-peering-connection-request">
    Dans le compte de peering, sur la page (VPC -&gt; Connexions d’appairage -&gt; Actions -&gt; Accept request), le client peut approuver cette demande d’appairage de VPC.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Accepter une connexion d’appairage](/images/cloud/reference/byoc-vpcpeering-2.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Ajouter la destination aux tables de routage du ClickHouse VPC" id="step-3-add-destination-to-clickhouse-vpc-route-tables">
    Dans le compte ClickHouse BYOC,

    1. Sélectionnez Tables de routage dans le VPC Dashboard.
    2. Recherchez l’ID du ClickHouse VPC. Modifiez chaque table de routage associée aux sous-réseaux privés.
    3. Cliquez sur le bouton Edit sous l’onglet Routes.
    4. Cliquez sur Add another route.
    5. Saisissez la plage CIDR du VPC cible dans Destination.
    6. Sélectionnez « Connexion d’appairage » et l’ID de la connexion d’appairage dans Target.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Ajouter une table de routage](/images/cloud/reference/byoc-vpcpeering-3.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Ajouter la destination aux tables de routage du VPC cible" id="step-4-add-destination-to-the-target-vpc-route-tables">
    Dans l’AWS account de peering,

    1. Sélectionnez Tables de routage dans le VPC Dashboard.
    2. Recherchez l’ID du VPC cible.
    3. Cliquez sur le bouton Edit sous l’onglet Routes.
    4. Cliquez sur Add another route.
    5. Saisissez la plage CIDR du ClickHouse VPC dans Destination.
    6. Sélectionnez « Connexion d’appairage » et l’ID de la connexion d’appairage dans Target.

    <div className="ch-image-lg">
      <Frame>
        ![BYOC Ajouter une table de routage](/images/cloud/reference/byoc-vpcpeering-4.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Modifier le groupe de sécurité pour autoriser l’accès depuis le VPC appairé" id="step-5-edit-security-group-to-allow-peered-vpc-access">
    Dans le compte ClickHouse BYOC, vous devez mettre à jour les paramètres du groupe de sécurité pour autoriser le trafic provenant de votre VPC appairé. Veuillez contacter le support ClickHouse pour demander l’ajout de règles entrantes incluant les plages CIDR de votre VPC appairé.

    ***

    Le service ClickHouse devrait désormais être accessible depuis le VPC appairé.
  </Step>
</Steps>

Pour accéder à ClickHouse de manière privée, un load balancer privé et un point de terminaison sont provisionnés afin d’assurer une connectivité sécurisée depuis le VPC appairé de l’utilisateur. Le point de terminaison privé reprend le format du point de terminaison public avec le suffixe `-private`. Par exemple :

* **Point de terminaison public** : `h5ju65kv87.mhp0y4dmph.us-west-2.aws.clickhouse-byoc.com`
* **Point de terminaison privé** : `h5ju65kv87-private.mhp0y4dmph.us-west-2.aws.clickhouse-byoc.com`

Une fois le bon fonctionnement du peering vérifié, vous pouvez, si vous le souhaitez, demander la suppression du load balancer public pour ClickHouse BYOC.

<div id="setup-privatelink">
  ## Configurer PrivateLink {#setup-privatelink}
</div>

AWS PrivateLink fournit une connexion sécurisée et privée à vos services ClickHouse BYOC, sans nécessiter de peering VPC ni de passerelles Internet. L&#39;ensemble du trafic circule au sein du réseau AWS, ce qui garantit qu&#39;il ne transite jamais par l&#39;Internet public.

<Note>
  **Connexions inter-régions.** Le bouton à bascule **Activer le lien privé** de la console ClickHouse provisionne le service de point de terminaison et ne couvre que les consommateurs de la **même région**. AWS désactive par défaut l&#39;accès inter-régions pour les services de point de terminaison, et la console ClickHouse ne le gère pas. Si vos clients se trouvent dans une autre région, vous devez l&#39;activer vous-même : le service de point de terminaison réside dans votre compte BYOC. Ajoutez donc les régions des consommateurs à sa liste de **Régions prises en charge** dans votre propre console AWS (voir l&#39;étape 3 ci-dessous). ClickHouse ne modifiera ni ne réinitialisera ces valeurs. Les tarifs AWS de transfert de données inter-régions s&#39;appliquent.
</Note>

<Steps>
  <Step title="Activer Private Link dans la console ClickHouse" id="step-1-enable-private-link">
    <Note>
      Au préalable, assurez-vous que l&#39;**équilibreur de charge privé** est activé.
    </Note>

    <div className="ch-image-md">
      <Frame>
        ![Activer BYOC PrivateLink](/images/cloud/reference/byoc-privatelink.webp)
      </Frame>
    </div>
  </Step>

  <Step title={<>Obtenez le <code>Nom du service</code> de l’endpoint</>} id="step-2-obtain-endpoint-service-name">
    1. Dans la Console ClickHouse Cloud, accédez à la page Paramètres du service auquel vous souhaitez vous connecter via PrivateLink.
    2. Cliquez sur « Configurer un point de terminaison privé ».
    3. Dans le panneau déroulant qui s&#39;ouvre, copiez la valeur `Service name` : vous en aurez besoin à l&#39;étape suivante. (La génération de cette valeur peut prendre un certain temps après l&#39;activation de PrivateLink.)

       <div className="ch-image-md">
         <Frame>
           ![Points de terminaison privés](/images/cloud/security/aws-privatelink-pe-create.webp)
         </Frame>
       </div>
  </Step>

  <Step title="Créer un endpoint dans votre réseau" id="step-3-create-endpoint">
    1. Ouvrez votre **propre console AWS** (c.-à-d. le compte AWS où se trouve votre application cliente) → VPC → Endpoints → Create endpoints.

    2. Sélectionnez &quot;Endpoint services that use NLBs and GWLBs&quot; et utilisez le `Service name` obtenu à l’étape précédente.

    3. Cliquez sur &quot;Verify service&quot;.

       <div className="ch-image-md">
         <Frame>
           ![Paramètres du point de terminaison AWS PrivateLink](/images/cloud/security/aws-privatelink-endpoint-settings.webp)
         </Frame>
       </div>

    4. (Facultatif) Pour établir une connexion interrégionale via PrivateLink, cochez la case &quot;Cross region endpoint&quot; et indiquez la région du service, c’est-à-dire celle où votre infrastructure BYOC a été créée. Parallèlement :
       1. Ouvrez votre **console AWS BYOC** (c.-à-d. le compte AWS où votre infrastructure BYOC a été créée) → VPC → Endpoint services → `clickhouse-cloud-infra-xxx` → Supported regions.
       2. Ajoutez la région dans laquelle s’exécute votre application cliente à la liste des régions prises en charge. Par défaut, seule la région de cette infrastructure BYOC est prise en charge. Vous pouvez ajouter plusieurs régions si vous souhaitez vous connecter depuis différentes régions ; ClickHouse ne modifiera ni ne réinitialisera ces valeurs.

          <div className="ch-image-md">
            <Frame>
              ![Paramètres du point de terminaison interrégional AWS PrivateLink](/images/cloud/reference/byoc-privatelink-aws-cross-region.webp)
            </Frame>
          </div>

    5. Sélectionnez votre VPC et vos sous-réseaux (il est recommandé d’en choisir un par zone de disponibilité).

       <div className="ch-image-md">
         <Frame>
           ![Sélection du VPC et des sous-réseaux](/images/cloud/security/aws-privatelink-select-vpc-and-subnets.webp)
         </Frame>
       </div>

    6. **Important** : activez &quot;Private DNS names&quot; pour l’endpoint — c’est indispensable au bon fonctionnement du DNS privé.
       Le DNS privé des endpoints BYOC (au format `*.vpce.{subdomain}`) s’appuie sur la fonctionnalité intégrée &quot;Private DNS names&quot; d’AWS PrivateLink. Aucun enregistrement Route53 n’est nécessaire — la résolution DNS s’effectue automatiquement lorsque :
       * &quot;Private DNS names&quot; est activé et
       * &quot;DNS Hostnames&quot; est activé

         via VPC Settings → DNS resolution and DNS hostnames.

         Ainsi, les connexions utilisant le sous-domaine `vpce` sont automatiquement acheminées via le point de terminaison PrivateLink, sans configuration DNS supplémentaire.

    7. (Facultatif) Attribuez des groupes de sécurité et des tags.
       <Note>
         Assurez-vous que les ports `443`, `8443` et `9440` sont autorisés dans le groupe de sécurité.
       </Note>

    8. Cliquez sur &quot;Create endpoint&quot;, puis patientez quelques instants pendant la création de l’endpoint.

    9. Une fois l’endpoint créé, copiez la valeur `Endpoint ID` — vous en aurez besoin à l’étape suivante.

       <div className="ch-image-md">
         <Frame>
           ![Identifiant du point de terminaison VPC](/images/cloud/security/aws-privatelink-vpc-endpoint-id.webp)
         </Frame>
       </div>
  </Step>

  <Step title="Approuver la connexion à l’endpoint" id="step-4-approve-endpoint-connection">
    1. Ouvrez à nouveau la **console de votre VPC BYOC** → Endpoint services → `clickhouse-cloud-infra-xxx` → Endpoint connections.
    2. Repérez la demande de connexion créée depuis votre propre VPC, puis cliquez sur « Accept endpoint connection request » pour l&#39;approuver.

       <div className="ch-image-md">
         <Frame>
           ![Approbation PrivateLink BYOC](/images/cloud/reference/byoc-privatelink-2.webp)
         </Frame>
       </div>
  </Step>

  <Step title={<>Ajouter l’<code>Identifiant du point de terminaison</code> à la liste d’autorisation du service ClickHouse</>} id="step-5-add-endpoint-id-to-services-allow-list">
    1. Dans la Console ClickHouse Cloud, accédez à la page Paramètres du service auquel vous souhaitez vous connecter via PrivateLink.
    2. Cliquez sur « Configurer un point de terminaison privé ».
    3. Dans le panneau déroulant qui s&#39;ouvre, saisissez l&#39;`Endpoint ID` obtenu à l&#39;étape précédente, ainsi qu&#39;une description facultative.
    4. Cliquez sur « Créer un point de terminaison ».

    <Note>
      Pour autoriser l&#39;accès depuis une connexion PrivateLink existante, utilisez le menu déroulant des endpoints existants.
      Ce menu affiche les connexions PrivateLink existantes vers les services de la même infrastructure.
    </Note>

    <div className="ch-image-md">
      <Frame>
        ![Filtre des points de terminaison privés](/images/cloud/security/aws-privatelink-pe-filters.webp)
      </Frame>
    </div>
  </Step>

  <Step title="Accéder à une instance via PrivateLink" id="step-6-connect-via-privatelink">
    1. Dans la Console ClickHouse Cloud, accédez à la page Paramètres du service.
    2. Cliquez sur « Configurer un point de terminaison privé ».
    3. Dans le panneau déroulant qui s&#39;ouvre, copiez la valeur `DNS name`.

       <div className="ch-image-md">
         <Frame>
           ![Nom DNS du point de terminaison privé](/images/cloud/security/aws-privatelink-pe-dns-name.webp)
         </Frame>
       </div>

       L&#39;accès aux services ClickHouse via PrivateLink est contrôlé à deux niveaux :

       1. **Politique d&#39;autorisation Istio** : politiques d&#39;autorisation au niveau du service, gérées par ClickHouse au sein de votre infrastructure BYOC
       2. **Groupe de sécurité du point de terminaison VPC** : le groupe de sécurité associé à votre point de terminaison VPC détermine quelles ressources de votre VPC peuvent utiliser ce point de terminaison

       <Note>
         La fonctionnalité « Enforce inbound rules on PrivateLink traffic » de l&#39;équilibreur de charge privé est désactivée : l&#39;accès est donc contrôlé uniquement par les politiques d&#39;autorisation Istio et par le groupe de sécurité de votre point de terminaison VPC.
       </Note>
  </Step>
</Steps>
