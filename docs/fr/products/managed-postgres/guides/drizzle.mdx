[Drizzle ORM](https://orm.drizzle.team/) est un ORM TypeScript doté d&#39;un query builder à la syntaxe proche du SQL, et `drizzle-kit` est la CLI qui l&#39;accompagne pour générer et exécuter des migrations. Dans ce guide, vous définissez une table `todos` en TypeScript, vous la créez au moyen d&#39;une migration `drizzle-kit`, puis vous servez des requêtes de création, de lecture, de mise à jour et de suppression depuis un petit serveur HTTP Node.js. Toutes les connexions utilisent TLS avec une vérification complète des certificats.

## Prérequis {#prerequisites}

* [Node.js](https://nodejs.org/) 20 ou version ultérieure
* Un compte ClickHouse Cloud
* [`psql`](https://www.postgresql.org/download/), pour créer la base de données. Vous pouvez également exécuter le statement `CREATE DATABASE` dans la [console SQL](/fr/integrations/connectors/sql-clients/sql-console).

## Créer un service ClickHouse Managed Postgres {#create-service}

Dans la console ClickHouse Cloud, cliquez sur **New service** et sélectionnez **Postgres**. L&#39;instance est prête en quelques minutes. Pour une présentation pas à pas, consultez le [guide de démarrage rapide](/fr/products/managed-postgres/quickstart).

## Obtenir vos informations de connexion {#connection-details}

Cliquez sur **Connect** dans la barre latérale gauche de votre service. La fenêtre modale affiche votre nom d&#39;utilisateur, votre mot de passe, le serveur et le port, ainsi qu&#39;un bouton bascule **Directly** / **via PgBouncer**.

Ce guide utilise deux chaînes de connexion :

* **Directe (port `5432`)** pour `drizzle-kit`. Les migrations exécutent du DDL, peuvent durer longtemps et dépendre de l&#39;état de session, par exemple `SET lock_timeout` ; elles doivent donc communiquer directement avec Postgres.
* **PgBouncer (port `6432`)** pour l&#39;application. Le [PgBouncer](/fr/products/managed-postgres/connection#pgbouncer) intégré fonctionne en mode de pool de connexions par transaction et permet à de nombreuses instances de l&#39;application, y compris des fonctions serverless, de se partager un petit nombre de connexions Postgres.

<Tip>
  Si vous exécutez un seul serveur Node.js de longue durée, `node-postgres` gère déjà son propre pool de connexions ; vous pouvez donc aussi faire pointer l&#39;application vers la connexion directe. Utilisez la connexion PgBouncer lorsque vous répartissez la charge sur de nombreux processus ou que vous déployez sur des plateformes serverless.
</Tip>

Une fois **Directly** sélectionné, activez **Use SSL**. L&#39;URL de connexion de l&#39;onglet **url** se termine alors par `sslmode=verify-full&sslrootcert=<service-name>-ca-certificate.pem`, et le port est `5432`. Sélectionnez **via PgBouncer** pour afficher les informations de connexion via le pool : le port passe à `6432`, et l&#39;URL inclut toujours `sslmode=verify-full`.

Dans la fenêtre modale, cliquez sur **Download CA certificate**. Vous pouvez également le télécharger depuis **Settings → CA Certificate**. Ce certificat est propre à votre instance, ce qui permet au driver de vérifier qu&#39;il communique bien avec votre serveur.

## Configurer le projet {#project-setup}

Créez un projet et installez Drizzle ORM, le driver [`node-postgres`](https://node-postgres.com/) (`pg`) ainsi que `drizzle-kit` :

```bash
mkdir drizzle-managed-postgres && cd drizzle-managed-postgres
npm init -y
npm pkg set type=module
npm install drizzle-orm pg dotenv
npm install -D drizzle-kit tsx @types/pg
```

<Tip>
  **Vous ajoutez Drizzle à une application existante ?**

  Ignorez les commandes `mkdir`, `npm init` et `npm pkg set type=module`. Dans votre projet, exécutez `npm install drizzle-orm pg dotenv` et `npm install -D drizzle-kit tsx @types/pg`, puis passez directement à la section [Configurer la connexion](#configure-connection).
</Tip>

## Configurer la connexion {#configure-connection}

Déplacez le certificat CA que vous avez téléchargé dans le répertoire du projet et renommez-le en `ca-certificate.pem`.

Créez une base de données pour l&#39;application. Remplacez `<PASSWORD>` et l&#39;hôte par les valeurs indiquées dans la fenêtre modale **Connect** :

```bash
psql "postgresql://postgres:<PASSWORD>@your-instance.pg.clickhouse.cloud:5432/postgres?sslmode=verify-full&sslrootcert=ca-certificate.pem" -c "CREATE DATABASE guide_drizzle;"
```

```text
CREATE DATABASE
```

Ajoutez les deux chaînes de connexion à un fichier `.env` à la racine du projet, ou à votre fichier `.env` existant. Elles ne diffèrent que par le port et pointent toutes deux vers la base de données `guide_drizzle` :

```bash title=".env"
# Runtime queries go through PgBouncer (port 6432)
DATABASE_URL="postgresql://postgres:<PASSWORD>@your-instance.pg.clickhouse.cloud:6432/guide_drizzle?sslmode=verify-full&sslrootcert=ca-certificate.pem"
# drizzle-kit migrations connect directly to Postgres (port 5432)
DIRECT_DATABASE_URL="postgresql://postgres:<PASSWORD>@your-instance.pg.clickhouse.cloud:5432/guide_drizzle?sslmode=verify-full&sslrootcert=ca-certificate.pem"
```

`node-postgres` lit `sslmode=verify-full` et `sslrootcert` depuis l’URL. Il charge le fichier de l&#39;autorité de certification (CA) et vérifie à la fois la chaîne de certificats et le nom d’hôte : vous n&#39;avez donc besoin d&#39;aucun code TLS supplémentaire. Le path `sslrootcert` est résolu par rapport au répertoire depuis lequel vous exécutez les commandes. Ne versionnez pas le fichier `.env` : excluez-le du contrôle de version.

<Note>
  Si le fichier de la CA est manquant ou incorrect, la connexion échoue avec l&#39;erreur `unable to verify the first certificate`. Si le nom d’hôte ne correspond pas au certificat, elle échoue avec l&#39;erreur `ERR_TLS_CERT_ALTNAME_INVALID`. Si votre mot de passe contient des caractères spéciaux tels que `@`, `/` ou `#`, encodez-les au format URL.
</Note>

## Définir le schéma {#schema}

Créez le fichier `src/db/schema.ts` :

```ts title="src/db/schema.ts"
import { boolean, integer, pgTable, text, timestamp } from "drizzle-orm/pg-core";

export const todos = pgTable("todos", {
  id: integer().primaryKey().generatedAlwaysAsIdentity(),
  title: text().notNull(),
  done: boolean().notNull().default(false),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});
```

Créez `drizzle.config.ts` à la racine du projet. Ce fichier indique à `drizzle-kit` où trouver le schéma et quelle connexion directe utiliser :

```ts title="drizzle.config.ts"
import "dotenv/config";
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dbCredentials: {
    // Migrations use the direct connection (port 5432)
    url: process.env.DIRECT_DATABASE_URL!,
  },
});
```

## Exécuter les migrations {#migrations}

Générez une migration SQL à partir du schéma :

```bash
npx drizzle-kit generate --name init
```

```text
1 tables
todos 4 columns 0 indexes 0 fks

[✓] Your SQL migration file ➜ drizzle/0000_init.sql 🚀
```

Le fichier `drizzle/0000_init.sql` généré contient le statement `CREATE TABLE`. Relisez-le, puis commitez le dossier `drizzle` avec votre code. Appliquez-le ensuite :

```bash
npx drizzle-kit migrate
```

```text
Using 'pg' driver for database querying
[✓] migrations applied successfully!
```

`drizzle-kit migrate` enregistre les migrations appliquées dans la table `drizzle.__drizzle_migrations` et n&#39;exécute que les nouvelles lors des appels suivants. Chaque fois que vous modifiez `schema.ts`, exécutez `generate`, puis à nouveau `migrate`.

<Tip>
  `drizzle-kit migrate` se termine avec le statut `1`, sans aucun message d&#39;erreur, lorsqu&#39;il ne parvient pas à se connecter, par exemple si le path `sslrootcert` ou le mot de passe est incorrect. Dans ce cas, testez d&#39;abord `DIRECT_DATABASE_URL` avec `psql`.
</Tip>

`drizzle-kit push` applique les modifications de schéma sans passer par des fichiers de migration. C&#39;est pratique pour le prototypage, mais en production, `generate` et `migrate` vous offrent des fichiers SQL que vous pouvez relire, ainsi qu&#39;un historique.

## Interroger la base de données {#query}

Créez `src/db/index.ts`. Ce fichier instancie le client Drizzle sur un pool `node-postgres` qui passe par la connexion PgBouncer :

```ts title="src/db/index.ts"
import "dotenv/config";
import { drizzle } from "drizzle-orm/node-postgres";

// The app uses the PgBouncer connection (port 6432)
export const db = drizzle(process.env.DATABASE_URL!);
```

Créez `src/server.ts`, un petit serveur HTTP qui exécute une requête Drizzle par route. Dans une application existante, vous pouvez à la place appeler ces mêmes requêtes `db` depuis vos propres handlers de route :

```ts title="src/server.ts"
import { createServer } from "node:http";
import { desc, eq, not } from "drizzle-orm";
import { db } from "./db";
import { todos } from "./db/schema";

const server = createServer(async (req, res) => {
  const url = new URL(req.url ?? "/", "http://localhost");
  const id = Number(url.pathname.split("/")[2]);
  let body: unknown;

  try {
    if (req.method === "GET" && url.pathname === "/todos") {
      // Read
      body = await db.select().from(todos).orderBy(desc(todos.id));
    } else if (req.method === "POST" && url.pathname === "/todos") {
      // Create
      const title = url.searchParams.get("title") ?? "Untitled";
      [body] = await db.insert(todos).values({ title }).returning();
    } else if (req.method === "PATCH" && id) {
      // Update: toggle the done flag
      [body] = await db
        .update(todos)
        .set({ done: not(todos.done) })
        .where(eq(todos.id, id))
        .returning();
    } else if (req.method === "DELETE" && id) {
      // Delete
      [body] = await db.delete(todos).where(eq(todos.id, id)).returning();
    } else {
      res.writeHead(404).end();
      return;
    }
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify(body, null, 2) + "\n");
  } catch (err) {
    console.error(err);
    res.writeHead(500).end("Database error\n");
  }
});

server.listen(3101, () => console.log("Listening on http://localhost:3101/todos"));
```

<Note>
  Aucun paramètre de driver n&#39;est nécessaire pour PgBouncer. Par défaut, les requêtes de Drizzle utilisent des statements non nommés, et le PgBouncer intégré prend également en charge les prepared statements nommés, comme ceux créés avec la méthode `.prepare` de Drizzle, en mode pool de connexions par transaction. Les fonctionnalités propres à la session, comme `LISTEN` et les verrous consultatifs de session, ne fonctionnent pas via PgBouncer. Consultez la [FAQ](/fr/products/managed-postgres/faq#prepared-statement-errors).
</Note>

## Exécuter et vérifier {#verify}

Démarrez le serveur :

```bash
npx tsx src/server.ts
```

```text
Listening on http://localhost:3101/todos
```

Dans un second terminal, créez deux tâches, marquez la première comme terminée et supprimez la seconde :

```bash
curl -X POST "http://localhost:3101/todos?title=Try%20Drizzle%20ORM"
curl -X POST "http://localhost:3101/todos?title=Write%20a%20migration"
curl -X PATCH http://localhost:3101/todos/1
curl -X DELETE http://localhost:3101/todos/2
```

La requête `PATCH` renvoie la ligne mise à jour :

```json
{
  "id": 1,
  "title": "Try Drizzle ORM",
  "done": true,
  "createdAt": "2026-09-30T16:45:14.610Z"
}
```

Ouvrez `http://localhost:3101/todos` dans votre navigateur pour afficher la liste des tâches restantes. La réponse se présente comme suit :

```json
[
  {
    "id": 1,
    "title": "Try Drizzle ORM",
    "done": true,
    "createdAt": "2026-09-30T16:45:14.610Z"
  }
]
```

Pour afficher les données dans la console, ouvrez **console SQL** dans la barre latérale gauche de votre service, développez `guide_drizzle` puis `public`, et cliquez sur la table `todos`. Le schéma `drizzle` héberge la table d&#39;historique des migrations. La table `todos` contient la ligne restante :

| id | title           | done | created&#95;at                |
| -- | --------------- | ---- | ----------------------------- |
| 1  | Try Drizzle ORM | true | 2026-09-30 16:45:14.610099+00 |
