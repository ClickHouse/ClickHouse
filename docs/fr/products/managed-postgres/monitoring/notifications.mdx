ClickHouse Cloud envoie des notifications lorsqu&#39;un service Managed Postgres
requiert une attention particulière. Elles sont envoyées via le
[système de notifications de la Console Cloud](/fr/products/cloud/features/monitoring/notifications) :
la boîte de réception de la console, l&#39;e-mail et Slack. Vous pouvez personnaliser chaque
notification depuis la section **Postgres** de la page des paramètres de
notification. Cette section s&#39;affiche pour les organisations disposant de services Managed Postgres.

## Notifications prises en charge {#supported-notifications}

| Notifier lorsque                                                | Condition d’alerte spécifique                                                                                                                                                                       | Canaux de notification par défaut | Étapes de résolution                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le stockage Postgres dépasse le seuil de 85 %                   | Lorsque l’utilisation du stockage d’un service Managed Postgres atteint 85 % de sa capacité. La notification n’est déclenchée qu’une fois par jour calendaire.                                      | UI, e-mail                        | Le stockage est automatiquement mis à l’échelle lorsque l’utilisation atteint 90 % (brève interruption de service lors du basculement). Aucune action n’est requise, sauf si l’Auto-scaling a déjà atteint sa limite.                                                                                                                                                                                                  |
| Le retard de réplication Postgres dépasse le seuil de 5 minutes | Lorsque le retard de réplication sur une instance de secours à haute disponibilité ou sur une réplique de lecture reste supérieur à 5 minutes. La notification n’est déclenchée qu’une fois par jour calendaire. | UI, e-mail                        | Pour une instance de secours, la capacité de basculement est réduite tant qu’elle n’a pas rattrapé son retard ; pour une réplique de lecture, les lectures peuvent renvoyer des données obsolètes. Le retard se résorbe généralement de lui-même une fois la charge d’écriture retombée. S’il continue d’augmenter, vérifiez le CPU, la mémoire et le disque de la réplique dans le Tableau de bord Monitoring, ou contactez le support. |
| Permutation planifiée terminée                                    | Lorsqu’une instance de secours est promue instance principale lors d’une opération de maintenance ou d’une modification de configuration sur un service Managed Postgres.                           | UI                                | Les connexions ont été brièvement interrompues. Votre chaîne de connexion reste inchangée et aucune action n’est requise. Consultez [Gestion des défaillances](/fr/products/managed-postgres/high-availability#handling-failures).                                                                                                                                                                                        |
| Basculement non planifié terminé                                | Lorsque l’instance principale devient indisponible et qu’une instance de secours est promue instance principale sur un service Managed Postgres.                                                    | UI, e-mail                        | Les connexions ont été interrompues pendant la promotion d’une instance de secours, généralement pendant quelques minutes. Votre chaîne de connexion reste inchangée et aucune action n’est requise. Consultez [Gestion des défaillances](/fr/products/managed-postgres/high-availability#handling-failures).                                                                                                             |
