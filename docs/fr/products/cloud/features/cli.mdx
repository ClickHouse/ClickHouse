L’interface en ligne de commande de ClickHouse (`clickhousectl`, alias `chctl`) permet de gérer ClickHouse Cloud depuis un terminal, un script ou un agent de code. Cette page traite du volet Cloud de la CLI. Pour découvrir l’ensemble des groupes de commandes, le développement local et le fonctionnement détaillé de l’outil, consultez la [référence de clickhousectl](/fr/concepts/features/interfaces/cli).

## Ce que vous pouvez gérer {#what-you-can-manage}

Les commandes `clickhousectl cloud` permettent de gérer :

* **Services :** créer, mettre à l’échelle, démarrer et arrêter des services ClickHouse Cloud, et y exécuter des requêtes SQL via l’API de requête.
* **[Managed Postgres](/fr/products/managed-postgres/overview) (Bêta) :** créer des services Postgres, des réplicas de lecture et des restaurations point-in-time, et modifier leur configuration.
* **[ClickPipes](/fr/integrations/clickpipes/home) :** ingérer des données depuis le stockage d’objet, Kafka, Kinesis, Pub/Sub, Postgres, MySQL, MongoDB et BigQuery.
* **[ClickStack](/fr/clickstack/overview) :** gérer les sources, tableaux de bord, alertes, webhooks, recherches enregistrées et rôles d’un service [Managed ClickStack](/fr/clickstack/deployment/managed).
* **Fonctions définies par l’utilisateur :** tester des UDF exécutables en local, puis les déployer sur un Service Cloud.
* **Sauvegardes :** lister les sauvegardes, modifier la planification des sauvegardes et restaurer une sauvegarde dans un nouveau service.
* **Accès à l’organisation :** organisations, membres, invitations, Clés API et journal d’activité.

Exécutez `clickhousectl cloud <command> --help` pour afficher les options d’une commande ainsi que les autorisations d’API key qu’elle requiert.

## Installation {#installation}

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

Le script installe `~/.local/bin/clickhousectl` ainsi qu&#39;un alias `chctl`. Assurez-vous que `~/.local/bin` figure dans votre `PATH`. Pour npm, pip, uv et les autres méthodes d&#39;installation, consultez la section [Installation](/fr/concepts/features/interfaces/cli#installation).

## Authentification {#authentication}

La connexion OAuth via le navigateur ne donne qu&#39;un accès en lecture seule. Pour créer ou modifier des ressources, vous avez besoin d&#39;une [API key](/fr/products/cloud/features/admin-features/api/openapi) associée à un rôle qui autorise cette modification.

```bash
# Read-only: OAuth device flow in your browser
clickhousectl cloud auth login

# Read and write: prompts for the API key and secret, keeping the secret out of shell history
clickhousectl cloud auth login --interactive

# Alternative for scripts
clickhousectl cloud auth login --api-key <key> --api-secret <secret>
```

La connexion vérifie les identifiants et affiche l&#39;identité associée. Vous pouvez la consulter à tout moment avec `clickhousectl cloud auth whoami`. Si vous appartenez à plusieurs organisations, ajoutez `--org-id <org-id>` (ou `--org-name <name>`) aux commandes Cloud. En intégration continue, définissez `CLICKHOUSE_CLOUD_API_KEY` et `CLICKHOUSE_CLOUD_API_SECRET` plutôt que de vous connecter. Consultez la section [Authentification](/fr/concepts/features/interfaces/cli#authentication) pour connaître l&#39;ordre de préséance des informations d&#39;authentification et la procédure de déconnexion.

## Exemples {#examples}

### Créer et interroger un service {#create-and-query-a-service}

```bash
# Create a service. Save the initial password; it is printed only once.
# Omitting --ip-allow allows all addresses (0.0.0.0/0).
clickhousectl cloud service create --name analytics \
  --provider aws --region us-east-1 \
  --ip-allow '203.0.113.10/32=Office'

# Look up the service ID, then run SQL over the Query API
CH_ID=$(clickhousectl cloud service get --name analytics --json | jq -r .id)
clickhousectl cloud service query "$CH_ID" --query "SELECT version()"
```

La commande de création rend la main avant que le service ne soit en cours d’exécution. Interrogez `clickhousectl cloud service get "$CH_ID"` jusqu’à ce que `state` ait la valeur `running`.

Lors de la première requête effectuée avec une API key, clickhousectl ajoute votre API key au Point de terminaison de l’API de requêtes du service, en créant l’endpoint si nécessaire ; aucune nouvelle clé n’est créée. Passez `--no-auto-enable` pour que la commande échoue plutôt. Avec OAuth, `service query` exécute des statements `SELECT` en lecture seule. L’API de requête expire au bout d’environ 30 secondes : utilisez donc `clickhouse client` pour les requêtes longues et les chargements en masse.

### Créer un service Postgres géré {#create-a-managed-postgres-service}

```bash
clickhousectl cloud postgres create --name app-db \
  --provider aws --region us-east-1 --size c6gd.xlarge --pg-version 18 \
  --ip-allow '203.0.113.10/32:5432=Office'
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output ca.pem
```

Seule la commande `create` renvoie le mot de passe et la chaîne de connexion : pensez donc à les enregistrer. Si vous omettez `--ip-allow`, les ports 5432 et 6432 sont ouverts à toutes les adresses. Attendez que `state` passe à `running`, puis connectez-vous avec `psql` à l’aide du certificat de CA.

### Inspecter ClickPipes, ClickStack et les sauvegardes {#inspect-clickpipes-clickstack-and-backups}

```bash
clickhousectl cloud clickpipe list "$CH_ID"
clickhousectl cloud clickstack source list <clickstack-service-id>
clickhousectl cloud backup list "$CH_ID"
```

Ces commandes de lecture fonctionnent avec OAuth. En revanche, la création d’un ClickPipe ou la modification d’une ressource ClickStack nécessite une API key ; consultez les guides du dépôt ci-dessous.

### Déployer une fonction définie par l&#39;utilisateur {#deploy-a-user-defined-function}

```bash
# Uploads clickhouse/udfs/my_udf/, waits for the build, then attaches that version to the service
clickhousectl cloud udf deploy my_udf --service "$CH_ID"
```

Testez d&#39;abord la fonction sur un serveur local avec `clickhousectl local udf deploy my_udf`.

## Sortie JSON et agents de code {#json-output}

Les commandes Cloud acceptent l&#39;option `--json`, et la CLI bascule automatiquement sur le format JSON lorsqu&#39;elle détecte un agent de code. `cloud service query` utilise alors `JSONEachRow` par défaut ; les scripts qui analysent sa sortie doivent donc spécifier `--format`, par exemple `--format TabSeparated`. Consultez [Sortie JSON](/fr/concepts/features/interfaces/cli#json-output) et [Codes de sortie](/fr/concepts/features/interfaces/cli#exit-codes). Installez les ClickHouse agent skills avec `clickhousectl skills`.
