Ces paramètres configurent le serveur ClickHouse et sont générés automatiquement à partir du code source de ClickHouse.

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="No" />Nom de la base de données par défaut.

<div id="default_password_type">
  ## default_password_type
</div>

Définit le type de mot de passe utilisé automatiquement dans les requêtes telles que `CREATE USER u IDENTIFIED BY 'p'`.

Les valeurs acceptées sont :

* `plaintext_password`

* `sha256_password`

* `double_sha1_password`

* `bcrypt_password`

* **Par défaut :** `sha256_password`

```xml
<default_password_type>sha256_password</default_password_type>
```

<div id="default_profile">
  ## default_profile
</div>

Profil de paramètres par défaut. Les profils de paramètres se trouvent dans le fichier indiqué par le paramètre `user_config`.

* **Par défaut :** `default`

**Exemple**

```xml
<default_profile>default</default_profile>
```

<div id="default_session_timeout">
  ## default_session_timeout
</div>

Expiration de session par défaut, en secondes.

* **Par défaut :** `60`

```xml
<default_session_timeout>60</default_session_timeout>
```

<div id="default_session_user">
  ## default_session_user
</div>

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="No" />

Nom d’utilisateur utilisé pour l’authentification lorsqu’un client se connecte sans en spécifier un : requête HTTP sans paramètre `user` ni en-tête `X-ClickHouse-User`, paquet `Hello` du protocole natif avec un nom d’utilisateur vide, négociation MySQL ou PostgreSQL avec un nom d’utilisateur vide, requête gRPC sans `user_name`, appel Arrow Flight sans en-tête `authorization` (ou avec des identifiants Basic dont le nom d’utilisateur est vide), ou message WebSocket `auth` du [terminal web](/fr/concepts/features/interfaces/web-terminal) dont le champ `user` est absent ou vide.

Le nom d’utilisateur vide est résolu en cette valeur avant l’authentification ; la connexion reste donc soumise à l’authentification de l’utilisateur ainsi substitué : le mot de passe, le réseau et les autres contrôles d’accès s’appliquent normalement. Un nom d’utilisateur vide n’est qu’un alias du nom d’utilisateur configuré, et son acceptation n’accorde aucun accès supplémentaire par rapport à la spécification explicite du même nom d’utilisateur. Dans les versions antérieures à l’introduction de ce paramètre, le repli d’un nom d’utilisateur vide vers `default` n’existait que pour les requêtes HTTP simples utilisant des paramètres de requête, les requêtes gRPC, les appels Arrow Flight et le terminal web, tandis que les protocoles natif, MySQL et PostgreSQL rejetaient un nom d’utilisateur vide ; ils l’acceptent désormais tous. Avant l’introduction de ce paramètre, l’authentification HTTP Basic avec un nom d’utilisateur vide ainsi que les requêtes contenant `X-ClickHouse-Key` mais pas `X-ClickHouse-User` rejetaient également un nom d’utilisateur vide.

S’il est défini sur une chaîne vide, les connexions sans nom d’utilisateur sont rejetées. Les gestionnaires HTTP avec un utilisateur fixe (la clé `user` dans `handler` d’une règle `http_handlers`, ou la clé `user` dans `handler` d’une règle `prometheus.handlers`) s’authentifient avec l’utilisateur configuré et ne sont pas affectés.

Lorsque la section `session_log` est activée dans la configuration du serveur, chaque rejet de ce type est enregistré dans [`system.session_log`](/fr/reference/system-tables/session_log) en tant qu’événement `LoginFailure` avec un `user` vide, afin que les connexions interdites sans nom d’utilisateur puissent être auditées sur chaque interface.

L’utilisateur de session par défaut ne s’applique jamais aux connexions interserveur : elles s’identifient à l’aide d’un marqueur spécial plutôt que d’un nom d’utilisateur et sont authentifiées par le secret de cluster et l’utilisateur initial.

La valeur peut être surchargée pour un endpoint spécifique d’un protocole composable à l’aide de la clé `default_session_user` dans la section `protocols` ; voir [Protocoles composables](/fr/concepts/features/configuration/server-config/composable-protocols).
