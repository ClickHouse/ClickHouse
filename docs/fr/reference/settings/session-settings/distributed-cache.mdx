<div id="distributed_cache_client_id">
  ## distributed_cache_client_id
</div>

<CloudOnlyBadge />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": ""},{"label": "Nouveau paramètre (tests d’intégration continue uniquement) permettant de surcharger l’ID client du cache distribué pour chaque requête."}]}, {"id": "row-2","items": [{"label": "26.8"},{"label": ""},{"label": "Nouveau paramètre (tests d’intégration continue uniquement) permettant de surcharger l’ID client du cache distribué pour chaque requête."}]}]} />

N’a d’effet que dans ClickHouse Cloud. Ce paramètre, utilisé uniquement pour les tests d’intégration continue, surcharge, lorsqu’il n’est pas vide, l’ID client du cache distribué configuré dans le registry pour les requêtes de cette requête. Il permet aux tests de répartir les données entre un ensemble limité d’ID client tout en conservant les mêmes données sur le même ID client. Il nécessite l’activation de `ci_mode` dans la config du client de cache distribué : dans le cas contraire (ce qui est le comportement par défaut, notamment en production), une requête qui effectue une lecture ou une écriture via le cache distribué échoue avec `SUPPORT_IS_DISABLED`, au lieu de revenir silencieusement à l’ID client configuré. Les requêtes qui n’atteignent jamais le cache distribué ne sont pas affectées ; la valeur y est donc ignorée.
