## external_storage_push_down_limit {#external_storage_push_down_limit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nouveau paramètre permettant d'appliquer en amont la clause `LIMIT` de la requête dans la requête envoyée à une base de données externe, lorsque cela ne présente aucun risque. previous_value=false, de sorte que `compatibility` avec les versions antérieures à 26.10 rétablit le comportement précédent (pas d'application en amont)."}]}]} />

Permet d&#39;appliquer en amont la clause `LIMIT` de la requête dans la requête envoyée à une base de données externe (comme MySQL, PostgreSQL ou SQLite).

L&#39;application en amont n&#39;est pas effectuée pour les passerelles génériques ODBC/JDBC, car elles n&#39;exposent pas la syntaxe `LIMIT` distante, et certaines des bases de données prises en charge n&#39;acceptent aucune clause `LIMIT`.

La clause `LIMIT` n&#39;est appliquée en amont que lorsque cela est garanti sans risque, c&#39;est-à-dire lorsque chaque clause qui s&#39;applique logiquement avant elle est reprise telle quelle dans la requête externe. Plus précisément, la requête doit être un simple `SELECT` portant sur une seule table :

* elle ne comporte ni `JOIN`, ni `ARRAY JOIN`, ni `SAMPLE`, ni `FINAL` (sinon des lignes pourraient être supprimées ou transformées localement, ce qui rend toute limitation préalable indésirable) ;
* la clause `WHERE`, le cas échéant, est entièrement compatible et reprise telle quelle dans la requête réécrite (sinon un filtrage appliqué après la clause `LIMIT` distante éliminerait certaines lignes) ;
* elle ne comporte aucune autre clause ni aucun modificateur (comme `DISTINCT`, `GROUP BY`, `ORDER BY`, `LIMIT BY`, `WITH TIES`, etc.) susceptible de fausser la limitation préalable distante en raison d&#39;un réordonnancement, d&#39;une agrégation ou d&#39;un filtrage des données ;
* un `OFFSET` est autorisé : il est appliqué localement, si bien que les lignes qu&#39;il ignore doivent également être lues, et la limite envoyée à la base de données externe vaut `offset + length` ;
* la liste du `SELECT` fait correspondre chaque ligne source à une seule ligne de résultat, c&#39;est-à-dire qu&#39;elle ne contient ni fonctions d&#39;agrégation, ni fonctions de fenêtrage, ni `arrayJoin` (également écrit `unnest`), celles-ci étant évaluées localement sur l&#39;ensemble des lignes lues depuis la table externe ;
* aucun filtre n&#39;est appliqué localement aux lignes lues depuis la table externe, comme une politique de ligne ou `additional_table_filters` (un tel filtre s&#39;exécute avant la clause `LIMIT` ; une limitation préalable côté distant risquerait donc d&#39;écarter des lignes qu&#39;il aurait conservées).

Cela réduit la quantité de données lues et transmises par la base de données externe. Désactivez ce paramètre pour rétablir le comportement précédent en cas de problèmes de compatibilité.
