## use_page_cache_for_local_disks {#use_page_cache_for_local_disks}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "0"},{"label": "Nouveau paramètre pour utiliser le cache de pages en espace utilisateur pour les disques locaux"}]}]} />

Utilise le cache de pages en espace utilisateur lors de la lecture depuis des disques locaux. Utilisé pour les tests, il est peu probable qu&#39;il améliore les performances en pratique. Nécessite `local_filesystem_read_method = 'pread'` ou `'read'`. Cela ne désactive pas l&#39;OS page cache ; `min_bytes_to_use_direct_io` peut être utilisé à cette fin. N&#39;affecte que les tables ordinaires, pas la fonction de table `file()` ni le moteur de table `File()`.

## use_page_cache_for_object_storage {#use_page_cache_for_object_storage}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "0"},{"label": "Nouveau paramètre permettant d’utiliser le cache de pages en espace utilisateur pour les fonctions de table de stockage d’objet"}]}, {"id": "row-2","items": [{"label": "26.12"},{"label": "1"},{"label": "Utilisation par défaut du cache de pages en espace utilisateur pour les moteurs de table et les fonctions de table de stockage d’objet, si le cache de pages est configuré sur le serveur."}]}]} />

Utilise le cache de pages en espace utilisateur lors de la lecture depuis les fonctions de table de stockage d’objet (s3, azure, hdfs, Iceberg, Delta Lake, etc.) et les moteurs de table (S3, Azure, HDFS, Iceberg, Delta Lake, etc.). Ce paramètre n’a d’effet que si le cache de pages en espace utilisateur est configuré sur le serveur (`page_cache_max_size`), et uniquement pour les objets disposant d’un ETag fort ou d’une identity immuable issue des enregistrements de la table (fichiers de données d’Iceberg et de Delta Lake). Il n’est pas utilisé en combinaison avec le cache du système de fichiers. En combinaison avec le Distributed Cache, il n’est utilisé que si `use_page_cache_with_distributed_cache` est également activé.

## use_page_cache_lookahead_for_text_index {#use_page_cache_lookahead_for_text_index}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Nouveau paramètre"}]}]} />

Par défaut, les fichiers d’index de texte qui ne sont pas lus dans l’ordre du fichier (dictionnaire, listes d’occurrences, positions) sont lus via le cache de pages en espace utilisateur avec une lecture anticipée d’un seul bloc, afin de pouvoir réutiliser la connexion distante après chaque lecture. Activez ce paramètre pour que ces fichiers utilisent plutôt `page_cache_lookahead_blocks`, comme les autres fichiers.

## use_page_cache_with_distributed_cache {#use_page_cache_with_distributed_cache}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.3"},{"label": "0"},{"label": "Nouveau paramètre"}]}]} />

Utilisez le cache de pages en espace utilisateur lorsque le distributed cache est utilisé.
