## iceberg_metadata_log_level {#iceberg_metadata_log_level}

<SettingsInfoBlock type="IcebergMetadataLogLevel" default_value="none" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.9"},{"label": "none"},{"label": "Nouveau paramètre."}]}]} />

Contrôle le niveau de journalisation des métadonnées des tables Iceberg dans `system.iceberg_metadata_log`.
En général, ce paramètre peut être modifié à des fins de débogage.

Valeurs possibles :

* none - Aucune journalisation des métadonnées.
* metadata - Fichier racine metadata.json.
* manifest&#95;list&#95;metadata - Tout ce qui précède + les métadonnées de la liste de manifestes Avro correspondant à un snapshot.
* manifest&#95;list&#95;entry - Tout ce qui précède + les entrées de la liste de manifestes Avro.
* manifest&#95;file&#95;metadata - Tout ce qui précède + les métadonnées des fichiers manifestes Avro parcourus.
* manifest&#95;file&#95;entry - Tout ce qui précède + les entrées des fichiers manifestes Avro parcourus.

## iceberg_metadata_previous_versions_max {#iceberg_metadata_previous_versions_max}

<SettingsInfoBlock type="NonZeroUInt64" default_value="100" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "100"},{"label": "Nouveau paramètre. Les écritures dans les tables Iceberg limitent la taille du `metadata-log`, qui augmentait auparavant à chaque validation."}]}]} />

Nombre maximal d’entrées qu’une écriture conserve dans le `metadata-log` d’une table Iceberg, y compris l’entrée correspondant au fichier de métadonnées qu’elle écrit. Lorsqu’une écriture ajoute une entrée qui fait dépasser cette limite, les entrées les plus anciennes sont supprimées. Les fichiers de métadonnées eux-mêmes ne sont pas supprimés.

La propriété de table Iceberg `write.metadata.previous-versions-max` prime sur ce paramètre. Comme dans l’implémentation Java, cette propriété indique le nombre de fichiers de métadonnées précédents et vaut au moins un. Le `metadata-log` conserve donc une entrée de plus que cette valeur.

Ce paramètre n’a aucun effet sur les tables d’un catalogue qui écrit lui-même les fichiers de métadonnées, tel qu’un catalogue REST : le catalogue gère le `metadata-log` selon sa propre configuration et la propriété de la table.

## iceberg_metadata_staleness_ms {#iceberg_metadata_staleness_ms}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.3"},{"label": "0"},{"label": "Nouveau paramètre permettant d'utiliser une version des métadonnées mise en cache lors des opérations READ afin d'éviter une récupération depuis le catalogue distant"}]}]} />

Si cette valeur est non nulle, la récupération de la dernière version des métadonnées Iceberg (depuis le catalogue distant, depuis `metadata/version-hint.text` avec `iceberg_use_version_hint`, ou par énumération des fichiers de métadonnées) est ignorée s&#39;il en existe une version mise en cache plus récente que la fenêtre d&#39;obsolescence indiquée. Une valeur de zéro signifie qu&#39;il faut toujours récupérer la dernière version des métadonnées. Définir ce paramètre sur une valeur non nulle permet de réduire la latence des opérations de lecture au prix d&#39;un certain degré d&#39;obsolescence.
