## http_allow_database_as_path {#http_allow_database_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nouveau paramètre permettant de reconnaître un nom de base de données dans le chemin d’URL des requêtes HTTP."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Activé par défaut : l’interface HTTP interprète un composant `\/database\/` du chemin d’URL comme base de données courante."}]}]} />

Lorsqu’elle est activée, l’interface HTTP reconnaît le composant `/database/` dans le chemin d’URL et l’utilise comme base de données courante.

Ce paramètre, défini par utilisateur, détermine si une requête de type chemin routée est interprétée. Le routage lui-même est contrôlé globalement par le paramètre de configuration `http_allow_path_requests` au niveau du serveur (activé par défaut). Celui-ci doit être activé pour que l’interface HTTP route une requête de type chemin (telle que `/my_db/my_table.csv`) vers le gestionnaire de requêtes. Cette décision de routage étant prise avant l’authentification de la requête, elle ne peut pas dépendre d’un paramètre par utilisateur. Lorsque `http_allow_path_requests` est désactivé, les chemins inconnus renvoient simplement un `404`. Après le routage, ce paramètre est vérifié à nouveau au regard des paramètres effectifs de l’utilisateur authentifié, ce qui permet de le désactiver de manière sélective pour un utilisateur, un rôle ou un profil.

## http_allow_filters_as_path {#http_allow_filters_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nouveau paramètre permettant de reconnaître les filtres `name=value` de style Hive dans le chemin d’URL des requêtes HTTP."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Activé par défaut : l’interface HTTP interprète les composants de chemin `\/name=value\/` comme des filtres combinés par `AND`."}]}]} />

Lorsqu’elle est activée, l’interface HTTP reconnaît les composants `/name=value/` dans le chemin (style de partitionnement Hive) et les traduit en filtres combinés par AND. Les opérateurs `>`, `<`, `>=`, `<=`, `!=`, `<>` sont également reconnus.

Comme [`http_allow_database_as_path`](/fr/reference/settings/session-settings/http#http_allow_database_as_path), il s’agit d’un paramètre par utilisateur ; le routage des requêtes avec chemin est contrôlé globalement par le paramètre de configuration `http_allow_path_requests` au niveau du serveur (le routage a lieu avant l’authentification).

## http_allow_filters_as_unrecognized_url_parameters {#http_allow_filters_as_unrecognized_url_parameters}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nouveau paramètre permettant de traiter les paramètres d’URL non reconnus comme des expressions de filtre dans les requêtes HTTP."}]}]} />

Si cette option est activée, tout paramètre d’URL non reconnu comme paramètre, paramètre de configuration ou préfixe `param_*` connu est traité comme un filtre et combiné avec AND. Deux formes sont acceptées :

* Un simple `name=value` devient une expression d’égalité : `` `name` = 'value' `` (l’identifiant est entouré d’accents graves et la valeur est entre guillemets en tant que littéral de chaîne).
* Un opérateur de comparaison (`!=`, `>`, `<`, `>=`, `<=`, `<>`) en fait une comparaison : soit séparé dans le paramètre (`?a!=2`, `?a>=2`), soit écrit directement lorsque l’URL ne contient aucun `=` permettant de le séparer (`?a<>2`, `?f(x)>3`) ; dans ce cas, le `name[=value]` reconstitué est analysé comme une expression SQL complète.

Désactivé par défaut, contrairement aux autres paramètres `http_allow_*` : il s’applique à toutes les requêtes de l’interface HTTP, y compris l’endpoint `/?query=...`. Son activation transforme donc tout paramètre d’URL non reconnu ajouté par un client (un identifiant de requête, une signature, un paramètre anti-cache) en filtre de la requête. Un nom de paramètre mal orthographié n’est alors plus signalé par `UNKNOWN_SETTING`, mais provoque une erreur `UNKNOWN_IDENTIFIER` (ou, si le nom correspond par hasard à une colonne, filtre silencieusement le résultat), et la valeur du paramètre est intégrée au texte de la requête, où elle n’est pas masquée, contrairement au `Request URI` dans le journal.

## http_allow_table_as_file {#http_allow_table_as_file}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nouveau paramètre permettant de reconnaître un nom de table dans le chemin d’URL des requêtes HTTP, avec des extensions de format/compression facultatives."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Activé par défaut : l’interface HTTP interprète le dernier composant du chemin d’URL comme `table[.format[.compression]]` et y répond par `SELECT * FROM table`."}]}]} />

Lorsqu’elle est activée, l’interface HTTP interprète le dernier composant du chemin d’URL comme un nom de table sous la forme `table`, `table.format` ou `table.format.compression`. Le chemin est interprété comme `SELECT * FROM table`.

Comme [`http_allow_database_as_path`](/fr/reference/settings/session-settings/http#http_allow_database_as_path), il s’agit d’un paramètre par utilisateur ; le routage des requêtes avec un chemin d’URL est contrôlé globalement par le paramètre de configuration `http_allow_path_requests` au niveau du serveur (le routage s’effectue avant l’authentification).

## http_make_head_request {#http_make_head_request}

<SettingsInfoBlock type="Bool" default_value="1" />

Le paramètre `http_make_head_request` permet d&#39;exécuter une requête `HEAD` lors de la lecture de données via HTTP afin de récupérer des informations sur le fichier à lire, telles que sa taille. Comme il est activé par défaut, il peut être utile de désactiver ce paramètre lorsque le server ne prend pas en charge les requêtes `HEAD`.

## http_x_clickhouse_format_overrides_output_format {#http_x_clickhouse_format_overrides_output_format}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Détermine si l’en-tête HTTP `X-ClickHouse-Format` est un alias de `output_format` (et remplace donc la clause `FORMAT` de la requête), comme c’est le cas depuis la version 26.8, ou de `default_format`, comme avant la version 26.8. Détermine à quel paramètre correspond l’en-tête HTTP `X-ClickHouse-Format`.

S’il est activé (valeur par défaut), l’en-tête est un alias du paramètre `output_format` : il constitue une surcharge explicite du format de réponse, qui prime sur la clause `FORMAT` de la requête et sur l’extension de fichier présente dans le chemin d’URL.

S’il est désactivé, l’en-tête est un alias du paramètre `default_format`, comme avant la version 26.8 : il se contente de sélectionner le format utilisé lorsque la requête ne comporte pas de clause `FORMAT` et qu’aucune autre surcharge de format n’est appliquée.

Dans les deux cas, l’en-tête prime sur le paramètre d’URL du même nom (respectivement `output_format` ou `default_format`) et ne modifie jamais la manière dont le corps de requête d’un `INSERT` est analysé.

Il s’agit d’un paramètre de compatibilité pour l’interface HTTP : l’en-tête étant traité avant l’analyse de la requête, ce paramètre doit être fourni via un paramètre d’URL ou un profil utilisateur, et non via une clause `SETTINGS` dans la requête. Comme `output_format` et `default_format`, il peut toujours être modifié en mode lecture seule (`readonly = 1`) : un utilisateur en lecture seule peut donc le transmettre comme paramètre d’URL.

## http_zlib_compression_level {#http_zlib_compression_level}

<SettingsInfoBlock type="Int64" default_value="3" />

Définit le niveau de compression des données dans la réponse à une requête HTTP si [enable&#95;http&#95;compression = 1](/fr/reference/settings/session-settings/enable#enable_http_compression).

Valeurs possibles : nombres de 1 à 12. Les niveaux supérieurs à `9` nécessitent le build par défaut avec `libdeflate` ; un build sans `libdeflate` prend en charge les niveaux de 1 à 9.
