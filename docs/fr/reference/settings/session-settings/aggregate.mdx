## aggregate_function_input_format {#aggregate_function_input_format}

<SettingsInfoBlock type="AggregateFunctionInputFormat" default_value="state" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "state"},{"label": "Nouveau paramètre permettant de contrôler le format d'entrée AggregateFunction lors des opérations INSERT. Valeur du paramètre définie à state par défaut"}]}]} />

Comment les formats d&#39;entrée lisent les colonnes de type `AggregateFunction`.

Valeurs possibles :

* `state` — l&#39;état sérialisé de la fonction d&#39;agrégation, tel que l&#39;écrivent les formats de sortie (valeur par défaut).
* `value` — une valeur de l&#39;argument de la fonction d&#39;agrégation, ou un tuple des arguments s&#39;il y en a plusieurs. La valeur est agrégée pour former l&#39;état.
* `array` — un tableau de valeurs, telles que décrites pour l&#39;option `value` ci-dessus. Tous les éléments du tableau sont agrégés pour former l&#39;état.

Dans les modes `value` et `array`, le format lit la colonne comme si elle était du type des valeurs : `T` pour `AggregateFunction(f, T)`, `Tuple(T1, T2)` pour `AggregateFunction(f, T1, T2)`, ou un `Array` de ce type en mode `array`. Les valeurs sont écrites selon la représentation que le format emploie pour ce type : un nombre ou une chaîne dans un format texte, un tableau JSON dans les JSON formats, l&#39;encodage binaire du type dans `RowBinary` ou `Native`, une colonne de ce type dans `Parquet`, etc. Cela vaut pour tous les formats d&#39;entrée, ainsi que pour les `AggregateFunction` imbriquées dans `Array`, `Tuple` ou `Map`.

**Exemples**

Pour une table ayant la structure suivante :

```sql
CREATE TABLE example (
    user_id UInt64,
    avg_session_length AggregateFunction(avg, UInt32)
);
```

Avec `aggregate_function_input_format = 'value'` :

```sql
INSERT INTO example FORMAT CSV
123,456
```

```sql
INSERT INTO example FORMAT JSONEachRow
{"user_id": 123, "avg_session_length": 456}
```

Avec `aggregate_function_input_format = 'array'` :

```sql
INSERT INTO example FORMAT CSV
123,"[456,789,101]"
```

```sql
INSERT INTO example FORMAT JSONEachRow
{"user_id": 123, "avg_session_length": [456, 789, 101]}
```

Remarque : les formats `value` et `array` sont plus lents que le format `state` par défaut, car ils nécessitent de créer et d&#39;agréger les valeurs lors de l&#39;insertion.

## aggregate_functions_null_for_empty {#aggregate_functions_null_for_empty}

<SettingsInfoBlock type="Bool" default_value="0" />

Active ou désactive la réécriture de toutes les fonctions d’agrégation d’une requête, en leur ajoutant le suffixe [-OrNull](/fr/reference/functions/aggregate-functions/combinators#-ornull). Activez ce paramètre pour assurer la compatibilité avec la norme SQL.
Cette fonctionnalité est implémentée via une réécriture de requête (semblable au paramètre [count&#95;distinct&#95;implementation](/fr/reference/settings/session-settings/count-distinct#count_distinct_implementation)) afin d’obtenir des résultats cohérents pour les requêtes distribuées.

Valeurs possibles :

* 0 — Désactivé.
* 1 — Activé.

**Exemple**

Considérez la requête suivante avec des fonctions d’agrégation :

```sql
SELECT SUM(-1), MAX(0) FROM system.one WHERE 0;
```

Avec `aggregate_functions_null_for_empty = 0`, on obtiendrait :

```text
┌─SUM(-1)─┬─MAX(0)─┐
│       0 │      0 │
└─────────┴────────┘
```

Avec `aggregate_functions_null_for_empty = 1`, le résultat serait :

```text
┌─SUMOrNull(-1)─┬─MAXOrNull(0)─┐
│          NULL │         NULL │
└───────────────┴──────────────┘
```
