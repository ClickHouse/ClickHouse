<div id="local_filesystem_read_method">
  ## local_filesystem_read_method
</div>

<SettingsInfoBlock type="String" default_value="pread_threadpool" />

Méthode de lecture des données depuis le système de fichiers local, parmi les suivantes : read, pread, mmap, io&#95;uring, pread&#95;threadpool.

La méthode &#39;pread&#95;threadpool&#39; confie une lecture à un pool de threads, sauf si les données se trouvent déjà dans le cache de pages, ce qui est vérifié à l&#39;aide de l&#39;appel système `preadv2` et du drapeau `RWF_NOWAIT`. Cette vérification nécessite Linux 5.11 ou une version ultérieure, et l&#39;appel système ne doit pas être rejeté par un profil `seccomp` d&#39;un environnement d&#39;exécution de conteneurs. Au démarrage, il est vérifié si l&#39;appel système peut être utilisé et, si ce n&#39;est pas le cas, la valeur par défaut de ce paramètre est remplacée par &#39;pread&#39;, car confier chaque lecture à un pool de threads, y compris les lectures servies depuis le cache de pages, est coûteux ; la raison est signalée dans le journal du serveur. Un profil `seccomp` n&#39;est détecté que s&#39;il rejette l&#39;appel système avec un code d&#39;erreur, ce que font les environnements d&#39;exécution de conteneurs ; un profil qui met fin au processus ne peut en revanche pas être détecté. Une valeur définie explicitement, dans la configuration ou avec `SET`, n&#39;est pas remplacée.

La méthode &#39;io&#95;uring&#39; est expérimentale et ne fonctionne pas avec Log, TinyLog, StripeLog, File, Set et Join, ni avec les autres tables utilisant des fichiers auxquels on peut ajouter des données en présence de lectures et d&#39;écritures concurrentes.
Si vous lisez divers articles sur &#39;io&#95;uring&#39; sur Internet, ne vous y fiez pas aveuglément. Ce n&#39;est pas une meilleure méthode de lecture de fichiers, sauf dans le cas d&#39;un grand nombre de petites requêtes d&#39;IO, ce qui n&#39;est pas le cas dans ClickHouse. Il n&#39;y a aucune raison d&#39;activer &#39;io&#95;uring&#39;.
