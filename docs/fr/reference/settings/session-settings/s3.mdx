## s3_base {#s3_base}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": ""},{"label": "Nouveau paramètre permettant de spécifier l’URL de base utilisée pour résoudre les URL relatives dans la fonction de table s3 et le moteur de table S3."}]}]} />

URL de base utilisée pour résoudre les URL relatives dans la fonction de table [s3](/fr/reference/functions/table-functions/s3) et le moteur de table [S3](/fr/reference/engines/table-engines/integrations/s3), ainsi que dans les fonctions de table partageant leur configuration (`s3Cluster`, `gcs`, `oss`).

Lorsqu’elle est définie, une URL sans schéma est résolue par rapport à `s3_base` conformément à la RFC 3986, selon les mêmes règles que [url&#95;base](/fr/reference/settings/session-settings/url#url_base). Les URL contenant déjà un schéma sont utilisées telles quelles.

Par exemple, si `s3_base` est défini sur `s3://clickhouse-public-datasets/`, alors `s3('hits_compatible/hits.csv')` lit `s3://clickhouse-public-datasets/hits_compatible/hits.csv`.

L’URL de base peut prendre toute forme acceptée par la fonction de table `s3`, par exemple `s3://bucket/`, `https://bucket.s3.amazonaws.com/` ou `https://endpoint/bucket/`.

Lorsque l’URL relative provient d’une [collection nommée](/fr/concepts/features/configuration/server-config/named-collections), sa résolution est considérée comme une redéfinition de la clé `url` de la collection et nécessite le privilège `SHOW NAMED COLLECTIONS SECRETS` sur cette collection.

## s3_create_new_file_on_insert {#s3_create_new_file_on_insert}

<SettingsInfoBlock type="Bool" default_value="0" />

Active ou désactive la création d’un nouveau fichier à chaque insertion dans les tables du moteur S3. Si cette option est activée, un nouvel objet S3 est créé à chaque insertion avec cette clé, selon un schéma comme celui-ci :

initial : `data.Parquet.gz` -&gt; `data.1.Parquet.gz` -&gt; `data.2.Parquet.gz`, etc.

Valeurs possibles :

* 0 — la requête `INSERT` crée un nouveau fichier, ou échoue si le fichier existe et que s3&#95;truncate&#95;on&#95;insert n’est pas défini.
* 1 — la requête `INSERT` crée un nouveau fichier à chaque insertion en utilisant un suffixe (à partir du deuxième) si s3&#95;truncate&#95;on&#95;insert n’est pas défini.

Voir plus de détails [ici](/fr/integrations/connectors/data-ingestion/AWS/integrating-s3-with-clickhouse#inserting-data).

## s3_list_object_parallelism {#s3_list_object_parallelism}

<SettingsInfoBlock type="UInt64" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "1"},{"label": "Nouveau paramètre permettant de lister les chemins avec motif glob sur un stockage d’objet compatible S3 (les fonctions de table `s3` et `s3Cluster`, le table engine `S3` et leurs alias `gcs`, `cosn`, `oss`) à l’aide de plusieurs requêtes `ListObjects` concurrentes, en parcourant en parallèle l’arborescence des préfixes communs."}]}]} />

Nombre de requêtes `ListObjects` concurrentes utilisées pour lister les fichiers lorsque le chemin contient des motifs glob, lors des lectures depuis un stockage d’objet compatible S3 : la fonction de table `s3`, le table engine `S3`, la fonction de table `s3Cluster`, ainsi que leurs alias `gcs`, `cosn` et `oss`.

Lorsque la valeur est supérieure à `1`, les fichiers correspondants sont listés en parcourant l’arborescence de « répertoires » (les préfixes communs formés par le délimiteur `/`) avec autant de fils d’exécution en parallèle, au lieu de paginer l’intégralité du préfixe dans un seul flux séquentiel. Cela peut accélérer considérablement les requêtes portant sur des buckets contenant des millions d’objets, en particulier avec des dispositions partitionnées hiérarchiquement (par exemple `year=*/month=*/`), où des sous-arbres entiers sans correspondance sont élagués pendant le parcours.

Une valeur de `1` (par défaut) conserve l’ancien comportement d’énumération séquentielle. Les motifs glob récursifs (`**`) utilisent toujours l’énumération séquentielle.

## s3_request_payer {#s3_request_payer}

<SettingsInfoBlock type="S3RequestPayer" default_value="none" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "none"},{"label": "Nouveau paramètre permettant d’accéder aux buckets S3 de type « requester-pays »."}]}]} />

Définissez ce paramètre sur `requester` pour accéder à un bucket `S3` de type « requester-pays » : chaque requête inclut alors l’en-tête `x-amz-request-payer: requester`, de sorte que les frais de requête et de transfert de données sont à la charge du demandeur. Valeurs possibles : `none` (valeur par défaut, l’en-tête n’est pas envoyé), `requester`.

Ce paramètre est pris en compte lors de la création du client `S3` ; il s’applique donc aux usages limités à la portée d’une requête, comme la fonction de table `s3` et `BACKUP ... TO S3`. Un `SET` ultérieur au niveau d’une requête ne reconfigure pas un client à longue durée de vie déjà créé, comme un disque `S3` ou une table `S3` disposant de ses propres identifiants. Dans ces cas, utilisez la clé `request_payer` d’une section d’endpoint de la configuration du serveur `<s3>` ou de la définition du disque, qui a par ailleurs préséance sur ce paramètre.

## s3_skip_hidden_files {#s3_skip_hidden_files}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Nouveau paramètre : ignore les objets dont un segment de chemin commence par `_` ou `.` sous le préfixe sans glob lors de l'énumération des fichiers par glob, à l'instar des autres lecteurs de l'écosystème Hive. Les tables avec `partition_strategy = 'hive'` ignorent toujours ces chemins."}]}]} />

Active ou désactive l&#39;exclusion des chemins cachés lors de l&#39;énumération des fichiers par glob dans les tables utilisant le moteur [S3](/fr/reference/engines/table-engines/integrations/s3), c&#39;est-à-dire les objets dont un segment de chemin commence par `_` ou `.` sous le préfixe sans glob du chemin. Un segment contenant `=` est un répertoire de partition (par exemple `_p=1` pour une colonne de partitionnement `_p`) et n&#39;est pas considéré comme caché. Les rédacteurs de l&#39;écosystème Hive (Hive, Spark, Trino) placent leur sortie en cours dans un stockage intermédiaire et écrivent des objets marqueurs sous ces chemins (`_temporary/`, `.spark-staging-<id>/`, `_SUCCESS`). Leur lecture entre alors en concurrence avec la validation du rédacteur : la requête peut renvoyer des données non validées, ou échouer si le rédacteur renomme ou supprime l&#39;objet mis en tampon pendant la lecture. Les segments situés dans le préfixe sans glob ne sont pas vérifiés. Les tables avec `partition_strategy = 'hive'` ignorent toujours les chemins cachés, quelle que soit la valeur de ce paramètre.

Valeurs possibles :

* 0 — tous les objets correspondant au glob sont lus.
* 1 — les objets comportant un segment de chemin caché sous le préfixe sans glob sont ignorés.

## s3_slow_all_threads_after_network_error {#s3_slow_all_threads_after_network_error}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "1"},{"label": "Nouveau paramètre"}]}]} />

Lorsque cette option est définie sur `true`, tous les threads exécutant des requêtes S3 vers le même endpoint de sauvegarde sont ralentis
dès qu’une seule requête S3 rencontre une erreur réseau pouvant donner lieu à un réessai, comme un timeout de socket.
Lorsque cette option est définie sur `false`, chaque thread gère le backoff des requêtes S3 indépendamment des autres.

## s3_truncate_on_insert {#s3_truncate_on_insert}

<SettingsInfoBlock type="Bool" default_value="0" />

Active ou désactive la troncature avant les insertions dans les tables utilisant le moteur S3. Si cette option est désactivée, une exception sera levée lors d’une tentative d’insertion si un objet S3 existe déjà.

Valeurs possibles :

Voir plus de détails [ici](/fr/integrations/connectors/data-ingestion/AWS/integrating-s3-with-clickhouse#inserting-data).

## s3_use_idempotency_id {#s3_use_idempotency_id}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1"},{"label": "Nouveau paramètre permettant de désactiver l'identifiant d'idempotence dans les métadonnées des objets téléversés vers S3."}]}]} />

Ajoute un identifiant d&#39;idempotence unique dans les métadonnées définies par l&#39;utilisateur (l&#39;en-tête `x-amz-meta-clickhouse-idempotency-id`) de chaque objet téléversé vers S3. Lorsqu&#39;une écriture est réessayée après la perte de sa réponse, cet identifiant permet à ClickHouse de reconnaître que l&#39;objet a déjà été écrit lors d&#39;une tentative précédente de la même écriture, et de considérer celle-ci comme réussie au lieu de la faire échouer.

Désactivez-le pour les composants de stockage compatibles S3 qui rejettent les métadonnées d&#39;objet définies par l&#39;utilisateur. Les écritures concernées ne bénéficient alors plus de la récupération en cas de perte de réponse. Les écritures dans les tables d&#39;une base de données `DataLakeCatalog` avec `catalog_type = 's3tables'` (Amazon S3 Tables) n&#39;ajoutent pas l&#39;identifiant, sauf si ce paramètre est explicitement activé dans la requête, car S3 Tables ne prend pas en charge les métadonnées d&#39;objet définies par l&#39;utilisateur.
