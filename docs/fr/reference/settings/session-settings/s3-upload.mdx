## s3_upload_checksum_algorithm {#s3_upload_checksum_algorithm}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": ""},{"label": "Nouveau paramètre permettant de choisir l'algorithme de somme de contrôle pour les téléversements vers S3."}]}]} />

Algorithme de somme de contrôle utilisé lorsque ClickHouse téléverse des données vers `S3`. `CRC32` et `SHA256` sont envoyés sous forme d&#39;en-têtes flexibles `x-amz-checksum-*`, tandis que `MD5` est envoyé dans l&#39;en-tête `Content-MD5`.

Par défaut, la valeur est vide et ClickHouse laisse le SDK AWS calculer `Content-MD5`. En mode FIPS, `MD5` n&#39;est pas disponible ; le SDK l&#39;omet donc silencieusement et le téléversement ne comporte alors aucune somme de contrôle. Définissez plutôt `CRC32` ou `SHA256` pour ajouter une somme de contrôle flexible. Lorsque ce paramètre s&#39;applique, un `MD5` explicite est alors rejeté.

Pour les buckets autres que `S3Express`, `s3_disable_checksum` désactive ce paramètre. Il prend effet lors de la création du client `S3` et s&#39;applique donc aux utilisations limitées à une requête, telles que la table function `s3` et `BACKUP ... TO S3` ; un `SET` ultérieur par requête ne reconfigure pas un client à longue durée de vie déjà créé, tel qu&#39;un disk `S3`.

Les buckets `S3Express` exigent une somme de contrôle flexible et n&#39;acceptent pas `Content-MD5` : un `CRC32` ou `SHA256` explicite est pris en compte, une valeur vide utilise `CRC32` et un `MD5` explicite est rejeté.

Les endpoints `GCS` (`storage.googleapis.com`) ignorent entièrement ce paramètre et conservent le comportement `Content-MD5` du SDK, car `GCS` rejette les requêtes signées par `SigV4` comportant les en-têtes AWS `x-amz-checksum-*`.

Les copies côté serveur ignorent ce paramètre.

## s3_upload_part_size_multiply_factor {#s3_upload_part_size_multiply_factor}

<SettingsInfoBlock type="UInt64" default_value="2" />
