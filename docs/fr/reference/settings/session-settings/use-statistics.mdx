## use_statistics_for_min_max_aggregation {#use_statistics_for_min_max_aggregation}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "1"},{"label": "Nouveau paramètre permettant de répondre aux agrégations `min`, `max` et `count` sans `GROUP BY` ni filtres à partir des statistiques de colonnes par part, pour les parts qui les ont matérialisées, en ne lisant que les parts restantes. previous_value=false, de sorte que la `compatibility` avec les versions antérieures à 26.9 laisse l'optimisation désactivée et rétablit le plan préexistant."}]}]} />

Répondre aux agrégations `min`, `max` et `count` à partir des statistiques de colonnes par part plutôt qu&#39;en lisant les données.

Lorsque ce paramètre est activé, une requête de la forme `SELECT min(column), max(column), count() FROM table` sans `GROUP BY` ni filtres
est traitée à partir des statistiques de colonnes (par exemple les statistiques MinMax, voir le paramètre MergeTree `auto_statistics_types`)
pour les data parts qui les ont matérialisées, et seules les parts restantes sont lues.

Valeurs possibles :

* 0 — Désactivé.
* 1 — Activé.

## use_statistics_for_part_pruning {#use_statistics_for_part_pruning}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "1"},{"label": "Nouveau paramètre permettant d’utiliser les statistiques pour l’élagage des parts lors de l’exécution des requêtes."}]}]} />

Utilise les statistiques pour filtrer les parts lors de l’exécution des requêtes.

Lorsqu’il est activé, l’élagage dans les requêtes SELECT s’appuie sur les statistiques de colonnes (par ex. les statistiques MinMax) pour éliminer les parts qui ne peuvent pas contenir de données correspondantes avant de lire la moindre donnée.

Valeurs possibles :

* 0 — Désactivé.
* 1 — Activé.
