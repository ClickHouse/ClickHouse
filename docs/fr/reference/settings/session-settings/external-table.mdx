## external_table_functions_use_nulls {#external_table_functions_use_nulls}

<SettingsInfoBlock type="Bool" default_value="1" />

Définit comment les fonctions de table [mysql](/fr/reference/functions/table-functions/mysql), [postgresql](/fr/reference/functions/table-functions/postgresql) et [odbc](/fr/reference/functions/table-functions/odbc) utilisent des colonnes Nullable.

Valeurs possibles :

* 0 — La fonction de table utilise explicitement des colonnes Nullable.
* 1 — La fonction de table utilise implicitement des colonnes Nullable.

**Utilisation**

Si ce paramètre est défini sur `0`, la fonction de table n&#39;utilise pas de colonnes Nullable et insère des valeurs par défaut à la place de NULL. Cela s&#39;applique également aux valeurs NULL à l&#39;intérieur des tableaux.

## external_table_strict_query {#external_table_strict_query}

<SettingsInfoBlock type="Bool" default_value="0" />

S&#39;il est défini à true, un filtre portant sur les columns d&#39;une external table (`MySQL`, `PostgreSQL`, `SQLite`, `ODBC`, `JDBC`) qui ne peut pas être pushed down vers l&#39;external database est rejeté avec une exception au lieu d&#39;être appliqué localement après la récupération des données.

La vérification couvre le predicate `WHERE` de premier niveau ainsi que chaque conjonction d&#39;un `AND` de premier niveau. Un `PREWHERE` sur les columns de l&#39;external table ne relève pas de ce paramètre : ces table engines ne prennent pas en charge `PREWHERE`, et une telle query est rejetée avec `ILLEGAL_PREWHERE`, quelle que soit la valeur du paramètre. Avec l&#39;analyzer (comportement par défaut), la vérification n&#39;a lieu que là où un filtre peut effectivement être pushed down : lorsque l&#39;external table est la seule table de la query, de part et d&#39;autre d&#39;un `INNER JOIN`, ou du côté préservé d&#39;un outer join (le côté gauche d&#39;un `LEFT JOIN`, le côté droit d&#39;un `RIGHT JOIN`). Du côté non préservé d&#39;un `LEFT`/`RIGHT JOIN` et de part et d&#39;autre d&#39;un `FULL JOIN`, rien n&#39;est pushed down et rien n&#39;est vérifié : un filtre sur les columns de l&#39;external table est donc appliqué localement après le join, même en mode strict. Là où la vérification a lieu, un predicate qui référence d&#39;autres tables jointes dans la query environnante n&#39;est pas pushed down et se trouve exclu de la vérification, qu&#39;il référence uniquement le côté joint (par exemple `WHERE r.flag`) ou qu&#39;il le combine avec l&#39;external table au sein d&#39;une même expression non-`AND` (par exemple `WHERE l.id = 1 OR r.flag`) ; un tel predicate conserve son point d&#39;évaluation ClickHouse habituel (`WHERE` après le join, `PREWHERE` avant) et n&#39;est pas rejeté. Avec l&#39;ancien analyzer (`enable_analyzer = 0`), cette délimitation ne s&#39;applique pas : l&#39;intégralité du filtre externe est vérifiée lorsque l&#39;external table est la première table de l&#39;arbre de join, y compris un predicate portant sur le côté joint, tandis qu&#39;une external table jointe à droite n&#39;est pas vérifiée.
