## group_by_overflow_mode {#group_by_overflow_mode}

<SettingsInfoBlock type="OverflowModeGroupBy" default_value="throw" />

Définit le comportement lorsque le nombre de clés uniques pour l’agrégation dépasse la limite :

* `throw` : lever une exception
* `break` : arrêter l’exécution de la requête et renvoyer un résultat partiel
* `any` : poursuivre l’agrégation pour les clés déjà présentes dans l’ensemble, sans y ajouter de nouvelles clés.

L’utilisation de la valeur &#39;any&#39; permet d’exécuter une approximation de GROUP BY. La qualité de
cette approximation dépend de la nature statistique des données.

## group_by_top_k_optimization_observation_rows {#group_by_top_k_optimization_observation_rows}

<ExperimentalBadge />

<SettingsInfoBlock type="UInt64" default_value="65536" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "65536"},{"label": "Nouveau paramètre expérimental : nombre de lignes que chaque flux d’agrégation observe avant de considérer qu’un tas top-K plein, n’ayant jamais rien rejeté, ne représente qu’une surcharge inutile, puis de le figer."}]}]} />

Pour `enable_group_by_top_k_optimization` : nombre de lignes que chaque flux d’agrégation observe avant de figer un tas top-K plein qui a ignoré moins de 10 % des lignes en entrée et évincé moins de clés que sa capacité. Un tas figé signifie que l’agrégation se poursuit comme si l’optimisation était désactivée.

La fenêtre effective est au moins égale à deux fois la taille réservée du tas, afin qu’il ait toujours la possibilité de se remplir avant d’être évalué. `0` désactive ce gel (le tas est néanmoins figé lorsqu’un ensemble d’égalités à la limite devient trop grand).

Cela n’a aucun effet sur les requêtes `GROUP BY keys LIMIT K` sans `ORDER BY`, pour lesquelles le gel est toujours désactivé : le plan associé à cette forme contient un tri synthétisé qui n’est rentable que tant que le tas limite la taille de la table de hachage ; figer le tas produirait donc un plan plus lent que celui sans optimisation.

## group_by_top_k_optimization_shared_boundary {#group_by_top_k_optimization_shared_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nouveau paramètre : partage la borne de saut top-K la plus stricte entre les threads d'agrégation, afin que les threads dont les clés locales sont mal classées puissent ignorer des lignes à l'aide d'une borne publiée par un autre thread. previous_value=false : ainsi, `compatibility` avec les versions antérieures à 26.10 rétablit des bornes propres à chaque thread."}]}]} />

Pour `enable_group_by_top_k_optimization` : partage la borne de saut la plus stricte entre les threads d&#39;agrégation. Chaque thread publie la borne de son propre ensemble top-K une fois par bloc traité, dès lors que celle-ci s&#39;est resserrée, et tous les threads ignorent les lignes en se fondant sur la meilleure borne publiée, et non plus uniquement sur la leur. Si `K` clés sont strictement meilleures qu&#39;une ligne, cette ligne ne peut pas figurer dans le résultat final, quel que soit le thread qui détient ces clés ; ce partage ne modifie donc pas le résultat. Il permet simplement aux threads dont les clés locales sont mal classées (par exemple lorsque les valeurs de clé sont regroupées par endroits dans la table) d&#39;ignorer des lignes qu&#39;ils agrégeraient sinon en pure perte.

Valeurs possibles :

* 0 — Désactivé.
* 1 — Activé.

## group_by_two_level_threshold {#group_by_two_level_threshold}

<SettingsInfoBlock type="UInt64" default_value="100000" />

Nombre de clés à partir duquel une agrégation à deux niveaux démarre. 0 - le seuil n&#39;est pas défini.

## group_by_two_level_threshold_bytes {#group_by_two_level_threshold_bytes}

<SettingsInfoBlock type="UInt64" default_value="50000000" />

Taille en octets de l’état d’agrégation à partir de laquelle une agrégation à deux niveaux commence à être utilisée. 0 : le seuil n’est pas défini. L’agrégation à deux niveaux est utilisée lorsqu’au moins l’un des seuils est atteint.

## group_by_use_nulls {#group_by_use_nulls}

<SettingsInfoBlock type="Bool" default_value="0" />

Modifie la façon dont la [clause GROUP BY](/fr/reference/statements/select/group-by) traite les types des clés d’agrégation.
Lorsque les spécificateurs `ROLLUP`, `CUBE` ou `GROUPING SETS` sont utilisés, certaines clés d’agrégation peuvent ne pas servir à produire certaines lignes de résultat.
Les colonnes correspondant à ces clés sont renseignées soit avec la valeur par défaut, soit avec `NULL` dans les lignes correspondantes, selon ce paramètre.

Valeurs possibles :

* 0 — La valeur par défaut du type de clé d’agrégation est utilisée pour produire les valeurs manquantes.
* 1 — ClickHouse exécute `GROUP BY` conformément à la norme SQL. Les types des clés d’agrégation sont convertis en [Nullable](/fr/reference/data-types/nullable). Les colonnes correspondant à ces clés d’agrégation sont renseignées avec [NULL](/fr/reference/syntax#null) pour les lignes qui ne les utilisent pas.
