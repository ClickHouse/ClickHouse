## short_circuit_function_evaluation {#short_circuit_function_evaluation}

<SettingsInfoBlock type="ShortCircuitFunctionEvaluation" default_value="enable" />

Permet de calculer les fonctions [if](/fr/reference/functions/regular-functions/conditional-functions#if), [multiIf](/fr/reference/functions/regular-functions/conditional-functions#multiIf), [and](/fr/reference/functions/regular-functions/logical-functions#and) et [or](/fr/reference/functions/regular-functions/logical-functions#or) selon le principe de l’[évaluation en court-circuit](https://en.wikipedia.org/wiki/Short-circuit_evaluation). Cela permet d’optimiser l’exécution des expressions complexes dans ces fonctions et d’éviter d’éventuelles exceptions (comme une division par zéro lorsqu’elle n’est pas attendue).

Valeurs possibles :

* `enable` — Active l’évaluation en court-circuit pour les fonctions qui s’y prêtent (celles qui peuvent lever une exception ou sont coûteuses en calcul).
* `force_enable` — Active l’évaluation en court-circuit pour toutes les fonctions.
* `disable` — Désactive l’évaluation en court-circuit.

## short_circuit_function_evaluation_for_nulls {#short_circuit_function_evaluation_for_nulls}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.1"},{"label": "1"},{"label": "Permet d’exécuter les fonctions avec des arguments Nullable uniquement sur les lignes dont tous les arguments ont des valeurs non NULL"}]}]} />

Optimise l’évaluation des fonctions qui renvoient NULL dès qu’un argument est NULL. Lorsque le pourcentage de valeurs NULL dans les arguments de la fonction dépasse le seuil short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls&#95;threshold, le système évite d’évaluer la fonction ligne par ligne. À la place, il renvoie immédiatement NULL pour toutes les lignes, ce qui évite des calculs inutiles.

Ce paramètre ne contrôle qu’une optimisation. Les fonctions qui ne peuvent pas être exécutées sur la valeur par défaut de leurs arguments — telles que `parseDateTime`, `IPv4StringToNum` ou `intDiv` — ignorent toujours les lignes contenant un NULL, quel que soit ce paramètre, car la valeur stockée derrière un NULL est la valeur par défaut du type de l’argument et son exécution lèverait une exception sur des données pourtant valides.

Seuil de proportion de valeurs NULL à partir duquel les fonctions avec des arguments Nullable sont exécutées uniquement sur les lignes dont tous les arguments ont des valeurs non-NULL. S&#39;applique lorsque le paramètre short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls est activé.
Lorsque la proportion de lignes contenant des valeurs NULL par rapport au nombre total de lignes dépasse ce seuil, ces lignes contenant des valeurs NULL ne sont pas évaluées.

## short_circuit_function_evaluation_reorder_arguments {#short_circuit_function_evaluation_reorder_arguments}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nouveau paramètre."}]}]} />

Permet de modifier l&#39;ordre d&#39;évaluation des arguments des fonctions [and](/fr/reference/functions/regular-functions/logical-functions#and) et [or](/fr/reference/functions/regular-functions/logical-functions#or) lors de l&#39;[évaluation en court-circuit](/fr/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation), lorsque cela ne modifie pas le résultat et n&#39;introduit pas d&#39;exceptions.

* Si le premier argument est coûteux à calculer et qu&#39;un autre argument l&#39;est peu, ce dernier est évalué en premier, et l&#39;argument coûteux n&#39;est évalué que sur les lignes pour lesquelles le résultat n&#39;est pas encore déterminé. Par exemple, dans `WHERE JSONExtractString(json, 'a') = 'x' AND id < 100`, le JSON n&#39;est analysé que pour les lignes où `id < 100`.
* Les arguments évalués de manière paresseuse et qui ne peuvent pas lever d&#39;exception sont évalués par ordre croissant du temps nécessaire par ligne déterminée, tel que mesuré sur les blocs précédents. Pour les arguments susceptibles de lever une exception, tous les arguments qui les précèdent restent placés avant eux : ainsi, par exemple, `x != 0 AND intDiv(1, x) > 0` n&#39;effectue jamais de division par zéro.
