## min_bytes_before_external_group_by {#min_bytes_before_external_group_by}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Nouveau paramètre : taille minimale de l’état d’agrégation d’un fil d’exécution avant que le `GROUP BY` externe ne l’écrive sur le disque, afin qu’une requête ayant déjà dépassé le seuil n’écrive pas chaque bloc dans un fichier distinct."}]}]} />

Taille minimale, en octets, de l’état d’agrégation d’un fil d’exécution avant que le `GROUP BY` externe ne l’écrive sur le disque.

Lorsque la mémoire de la requête dépasse `max_bytes_before_external_group_by` ou `max_bytes_ratio_before_external_group_by` à cause d’autres opérateurs (par exemple une jointure de hachage qui conserve une grande table en mémoire), chaque fil d’exécution écrirait sinon sur le disque chaque bloc agrégé sous la forme d’un petit fichier distinct. Or, relire un grand nombre de petits fichiers consomme davantage de mémoire que les écritures n’en font économiser. Avec ce paramètre, un fil d’exécution poursuit l’agrégation jusqu’à ce que son propre état atteigne la taille indiquée, et ce n’est qu’alors qu’il l’écrit dans un seul fichier.

La mémoire utilisée au-delà du seuil est bornée par cette valeur multipliée par le nombre de fils d’exécution.

Valeurs possibles :

* Un entier positif, correspondant à la taille en octets.
* `0` — aucun minimum : l’état est écrit dès que le seuil est atteint.

## min_bytes_to_use_direct_io {#min_bytes_to_use_direct_io}

<SettingsInfoBlock type="UInt64" default_value="0" />

Le volume minimal de données nécessaire pour utiliser les E/S directes sur le disque de stockage.

ClickHouse utilise ce paramètre lors de la lecture des données des tables. Si le volume total de toutes les données à lire dépasse `min_bytes_to_use_direct_io` octets, ClickHouse lit alors les données sur le disque de stockage avec l’option `O_DIRECT`.

Valeurs possibles :

* 0 — Les E/S directes sont désactivées.
* Entier positif.

## min_bytes_to_use_mmap_io {#min_bytes_to_use_mmap_io}

<SettingsInfoBlock type="UInt64" default_value="0" />

Il s’agit d’un paramètre expérimental. Définit la taille minimale à partir de laquelle les gros fichiers sont lus sans copie des données du noyau vers l’espace utilisateur. Le seuil recommandé est d’environ 64 Mo, car [mmap/munmap](https://en.wikipedia.org/wiki/Mmap) est lent. Ce paramètre n’a de sens que pour les gros fichiers et n’est utile que si les données se trouvent dans le cache de pages.

Valeurs possibles :

* Entier positif.
* 0 — Les gros fichiers sont lus uniquement avec copie des données du noyau vers l’espace utilisateur.
