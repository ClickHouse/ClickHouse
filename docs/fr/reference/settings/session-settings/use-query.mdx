<div id="use_query_cache">
  ## use_query_cache
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

S’il est activé, les requêtes `SELECT` peuvent utiliser le [cache de requêtes](/fr/concepts/features/performance/caches/query-cache). Les paramètres [enable&#95;reads&#95;from&#95;query&#95;cache](/fr/reference/settings/session-settings/enable#enable_reads_from_query_cache)
et [enable&#95;writes&#95;to&#95;query&#95;cache](/fr/reference/settings/session-settings/enable#enable_writes_to_query_cache) déterminent plus précisément comment le cache est utilisé.

Valeurs possibles :

* 0 - Désactivé
* 1 - Activé

<div id="use_query_condition_cache">
  ## use_query_condition_cache
</div>

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.4"},{"label": "1"},{"label": "Une nouvelle optimisation"}]}, {"id": "row-2","items": [{"label": "25.3"},{"label": "0"},{"label": "Nouveau paramètre."}]}]} />

Active le [cache des conditions de requête](/fr/concepts/features/performance/caches/query-condition-cache). Le cache stocke les plages de granules, dans les parties de données, qui ne satisfont pas la condition de la clause `WHERE`,
puis réutilise ces informations comme index éphémère pour les requêtes suivantes.

Valeurs possibles :

* 0 - Désactivé
* 1 - Activé

<div id="use_query_condition_cache_for_top_k">
  ## use_query_condition_cache_for_top_k
</div>

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Nouveau paramètre permettant d'activer le cache de conditions de requête pour les lectures `ORDER BY ... LIMIT n` (TopK) ; activé par défaut. Le contrôle est désactivé dans la version 26.7, donc la `compatibility` avec une version antérieure le maintient désactivé."}]}]} />

Activez le [cache de conditions de requête](/fr/concepts/features/performance/caches/query-condition-cache) pour les requêtes utilisant l&#39;optimisation `ORDER BY <column> LIMIT n` (TopK), basée sur le filtrage dynamique ou les index de saut. Lorsqu&#39;il est désactivé, ces lectures ne consultent pas le cache et ne l&#39;alimentent pas non plus.

Ces requêtes peuvent ignorer des granules lors de l&#39;exécution selon le seuil courant. Leurs entrées de cache sont donc partitionnées en fonction des paramètres du plan TopK et de l&#39;ensemble des parties de données lues. Ce paramètre n&#39;a aucun effet si `use_query_condition_cache` n&#39;est pas également activé.

Valeurs possibles :

* 0 - Désactivé
* 1 - Activé
