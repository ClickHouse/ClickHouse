Nombre cible de lignes par record batch pour les formats de sortie `Arrow` et `ArrowStream`. Le regroupement des petits blocs réduit le surcoût lié aux métadonnées et au remplissage des tampons, en particulier pour les requêtes comportant des filters sélectifs.

Si vous définissez une cible en lignes, les batches regroupés contiennent moins du double de ce nombre de lignes, mais un bloc d&#39;entrée isolé peut être plus volumineux.

## output_format_arrow_unsupported_types {#output_format_arrow_unsupported_types}

<SettingsInfoBlock type="ArrowUnsupportedTypes" default_value="binary" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "binary"},{"label": "Nouveau paramètre remplaçant `output_format_arrow_unsupported_types_as_binary`, qui ajoute un mode `text`. Sa valeur par défaut correspond au comportement précédent, `compatibility` ne doit donc pas la modifier."}]}]} />

Ce qu&#39;il faut écrire pour une colonne dont le type n&#39;a pas de correspondance native en Arrow (par exemple `JSON`, `Dynamic`, `QBit` ou `AggregateFunction`) :

* `throw` — rejeter la requête ;
* `text` — une valeur sous forme textuelle par ligne (ce que produirait `CAST(col AS String)`), dans une colonne Arrow `Utf8` ;
* `binary` — la représentation binaire de chaque valeur, dans une colonne Arrow `Binary` (le même encodage par valeur que `RowBinary`).

Une colonne `AggregateFunction` est également de type `Binary` en mode `text`, car sa forme textuelle est l&#39;état d&#39;agrégation brut et non du texte, or une colonne Arrow `Utf8` doit contenir de l&#39;UTF-8 valide. Utilisez `finalizeAggregation` pour obtenir une valeur lisible.

Une valeur écrite dans une colonne `Utf8` est ajustée pour contenir de l&#39;UTF-8 valide, chaque séquence invalide étant remplacée par U+FFFD. Cela ne concerne que du texte qu&#39;un lecteur n&#39;aurait de toute façon pas pu interpréter comme tel — par exemple un `Dynamic` contenant une `String` faite d&#39;octets arbitraires. Utilisez le mode `binary` lorsque les octets doivent être préservés à l&#39;identique.

`output_format_arrow_string_as_string` ne s&#39;applique pas à ces colonnes, mais uniquement aux véritables colonnes `String` et `FixedString`. Le type Arrow d&#39;une colonne opaque reste ainsi une indication de l&#39;encodage qu&#39;elle contient : `Utf8` correspond à la forme textuelle et `Binary` à la forme binaire, quelle que soit la valeur de ce paramètre.

Il en va de même pour un état d&#39;agrégation contenu dans un `Dynamic` : la colonne est typée à partir de `Dynamic`, ce qui ne dit rien de ce que contiennent ses lignes, et le schéma Arrow est fixé avant qu&#39;aucune valeur n&#39;ait été vue ; l&#39;état ne peut donc pas recevoir sa propre colonne `Binary`, contrairement à une colonne `AggregateFunction`. En mode `text`, il y a par conséquent perte d&#39;information. Le mode `binary`, lui, la préserve. Un `Variant` n&#39;est pas concerné : il énumère ses alternatives, de sorte qu&#39;un `AggregateFunction` figurant parmi elles obtient son propre enfant `Binary`.

En mode `text` comme en mode `binary`, le champ est étiqueté dans le schéma Arrow avec le nom d&#39;extension `clickhouse.opaque` et le nom du type ClickHouse d&#39;origine, afin qu&#39;un lecteur puisse le distinguer d&#39;une véritable colonne de chaîne ou binaire.

ClickHouse ne relit une telle colonne dans le type nommé par l&#39;étiquette que si le côté lecture connaît déjà ce type, parce qu&#39;une table le déclare ou qu&#39;un structure argument tel que celui accepté par `file` et `s3` le nomme ; il le fait alors également à l&#39;intérieur de `Array`, `Tuple`, `Map` et `Nullable`. La schéma inference ne consulte pas l&#39;étiquette : une colonne lue sans type nommé pour elle arrive donc toujours en tant que `String` contenant la charge utile brute. Une alternative d&#39;un `Variant` n&#39;est jamais relue, même avec le type nommé, car l&#39;union Arrow que forment ses alternatives est décodée sans consulter les étiquettes. Dans tous les cas, les données écrites restent bien formées pour les autres lecteurs Arrow.

Ce paramètre est prioritaire sur l&#39;ancien `output_format_arrow_unsupported_types_as_binary`, qui n&#39;est consulté que lorsque ce paramètre est laissé à sa valeur par défaut.
