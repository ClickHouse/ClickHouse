## Description {#description}

Le format `ProtobufList` regroupe les lignes dans un seul message [Protocol Buffers](/fr/reference/formats/Protobuf/Protobuf) length-delimited nommé `Envelope`. Chaque ligne est encodée sous forme de sous-message portant le numéro de champ 1.

## Exemple d’utilisation {#example-usage}

Enregistrez le schéma suivant sous le nom `schemafile.proto`. Déclarez le champ `row` comme `repeated` afin qu’un décodeur Protobuf utilisant ce schéma puisse lire toutes les lignes contenues dans l’enveloppe.

```capnp title="schemafile.proto"
syntax = "proto3";
message Envelope {
  message MessageType {
    string name = 1;
  }
  repeated MessageType row = 1;
}
```

Depuis le même répertoire, exécutez ces commandes pour écrire deux lignes dans un fichier, puis les relire.

```bash
clickhouse local --query "SELECT name FROM values('name String', 'Ada', 'Grace') ORDER BY name
    SETTINGS format_schema = 'schemafile:MessageType' FORMAT ProtobufList" > people.bin

clickhouse local --structure 'name String' --input-format ProtobufList \
    --format_schema 'schemafile:MessageType' --query 'SELECT name FROM table' < people.bin
```

```text
Ada
Grace
```

Le type de message spécifié dans `format_schema` est d’abord recherché comme type imbriqué dans un message `Envelope` de niveau supérieur. Si aucune correspondance n’y est trouvée — soit parce que le schéma ne comporte pas de message `Envelope`, soit parce que `Envelope` ne contient aucun message portant le nom demandé — le message de niveau supérieur portant ce nom est utilisé directement.
