## Description {#description}

Format de lecture et d’écriture des fichiers [Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/).

Le format expose les positions des lignes supprimées contenues dans les blobs `deletion-vector-v1`. Les blobs d’autres types, tels que `apache-datasketches-theta-v1`, sont ignorés, comme l’exige la spécification Puffin ; utilisez `PuffinMetadata` pour les consulter.
Si un fichier Puffin contient plusieurs blobs `deletion-vector-v1`, le format produit une ligne par blob de ce type.

Colonnes de sortie fixes :

* `referenced_data_file` (`String`) - emplacement du fichier de données auquel s’applique le vecteur de suppression (propriété de blob `referenced-data-file`)
* `deleted_rows` (`Array(UInt64)`) - positions 64 bits des lignes supprimées d’après le bitmap roaring du vecteur de suppression

Lorsqu’il est utilisé comme format de sortie, l’entrée doit comporter les deux mêmes colonnes que celles produites par le format en lecture : le fichier de données référencé (`String` ou `LowCardinality(String)`) et les positions des lignes supprimées (un integer, à raison d’une position par ligne, ou un tableau d’integers). Le fichier contient un blob `deletion-vector-v1` par fichier de données référencé distinct, trié par emplacement du fichier de données, de sorte qu’un fichier Puffin comportant plusieurs vecteurs de suppression peut être copié tel quel. Les positions de toutes les lignes partageant le même fichier de données référencé sont fusionnées en un seul vecteur de suppression, dédupliquées et triées ; les positions négatives, les positions dépassant la limite du vecteur de suppression Iceberg et les emplacements de fichiers de données vides sont rejetés. Les métadonnées des blobs sont écrites comme le fait Apache Iceberg pour les vecteurs de suppression : `fields` vaut `[2147483645]` (l’identifiant de la colonne de métadonnées `_pos`), `snapshot-id` et `sequence-number` valent `-1`, et les propriétés `referenced-data-file` et `cardinality` sont définies. Le pied de page n’est pas compressé, de sorte que le fichier obtenu peut être enregistré dans une table Iceberg v3 en tant que fichier de suppression de type vecteur de suppression et lu par d’autres moteurs tels qu’Apache Spark. Exécutez `PuffinMetadata` sur le fichier écrit pour obtenir l’`offset` et la `length` de chaque blob, à renseigner dans les champs de manifeste `content_offset` et `content_size_in_bytes`.

Lorsque le paramètre `output_format_puffin_blob_type` est défini sur `apache-datasketches-theta-v1`, le format écrit à la place des statistiques de colonnes, comme le fait Apache Iceberg : chaque colonne d’entrée devient un blob `apache-datasketches-theta-v1` contenant un sketch Theta Apache DataSketches compact (graine et taille par défaut) calculé sur les valeurs non nulles de la colonne, et la propriété `ndv` reçoit le nombre estimé de valeurs distinctes. Les valeurs sont transmises au sketch selon la sérialisation binaire à valeur unique d’Iceberg propre au type de la colonne, de sorte que les sketches peuvent être fusionnés avec ceux écrits par Apache Spark : `Bool` en `boolean`, `Int8`, `UInt8`, `Int16`, `UInt16` et `Int32` en `int`, `UInt32`, `Int64` et `UInt64` en `long` (les valeurs `UInt64` dépassant la plage de `Int64` conservent leurs bits), `Float32` en `float`, `Float64` en `double`, `Date` et `Date32` en `date`, `DateTime` et `DateTime64` avec une précision allant jusqu’à 6 chiffres en `timestamp` (en microsecondes), `String` en `string`, `FixedString` en `fixed`, `UUID` en `uuid` et `Decimal` en `decimal` ; `Nullable` et `LowCardinality` appliqués à ces types sont également pris en charge. Les chaînes vides sont ignorées, comme dans Iceberg. Les `fields` des blobs proviennent du paramètre `output_format_puffin_field_ids`, et `snapshot-id` et `sequence-number` des paramètres `output_format_puffin_snapshot_id` et `output_format_puffin_sequence_number` ; ces trois paramètres sont obligatoires, car les lecteurs rattachent les statistiques aux colonnes et au snapshot qu’ils désignent. Le résultat peut être enregistré en tant que fichier de statistiques Iceberg.

Les vecteurs de suppression dont la `cardinality` déclarée dépasse un plafond absolu de materialization sont rejetés lorsque `deleted_rows` est demandé. Les propriétés `deletion-vector-v1` du pied de page (y compris le fait que `cardinality` puisse être analysé comme un entier non signé) sont toujours validées. La sélection de la seule colonne `referenced_data_file` évite les E/S sur la charge utile sur disque et ignore donc également l’enveloppe, le CRC, la désérialisation roaring et le plafond de materialization — délibérément, afin qu’une projection limitée au chemin ne lise pas jusqu’à la taille maximale du blob.

La longueur sur disque d’un blob `deletion-vector-v1` est limitée par un plafond absolu (aligné sur la vérification de taille de contenu de 2 GiB d’Iceberg). Lorsque `deleted_rows` est demandé, le lecteur inspecte l’en-tête de l’enveloppe (longueur combinée et nombre magique) avant d’allouer la charge utile complète ; le CRC est vérifié après la lecture bornée.

Les pieds de page Puffin compressés avec LZ4 et non compressés sont pris en charge. La taille de la charge utile du pied de page (ainsi que la taille de contenu LZ4 déclarée) est limitée, le cas échéant, par un taux de compression et par un plafond absolu ; les pieds de page surdimensionnés sont rejetés avant l’allocation.

Seul un sous-ensemble des colonnes de sortie peut être demandé. Une structure fournie par l’utilisateur comportant des noms ou des types de colonnes inattendus est rejetée lors de la création du format.

## Exemple d’utilisation {#example-usage}

Lisez les positions des lignes supprimées à partir du fichier de données référencé :

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

Développez les positions supprimées en lignes distinctes :

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

Utilisez `PuffinMetadata` pour examiner les descripteurs de blobs du pied de page avant de lire les vecteurs de suppression.

Écrivez les vecteurs de suppression de deux fichiers de données dans un seul fichier Puffin :

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

Écrivez les sketches Theta de deux colonnes dans un fichier de statistiques Iceberg :

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
