## Description {#description}

[Vortex](https://vortex.dev/) est un format de fichier extensible en colonnes destiné aux données compressées compatibles avec Apache Arrow,
conçu pour des parcours rapides et un accès aléatoire. ClickHouse prend en charge la lecture et l&#39;écriture de fichiers Vortex.

## Correspondance des types de données {#data-types-matching-vortex}

Le tableau ci-dessous présente les types de données Vortex et les [types de données](/fr/reference/data-types/index) ClickHouse correspondants
dans les requêtes `INSERT` et `SELECT`.

| Type de données Vortex (`INSERT`) | Type de données ClickHouse                                                                | Type de données Vortex (`SELECT`)                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `Bool`                            | [Bool](/fr/reference/data-types/boolean)                                                     | `Bool`                                                             |
| `I8`, `U8`                        | [Int8/UInt8](/fr/reference/data-types/int-uint)                                              | `I8`, `U8`                                                         |
| `I16`, `U16`                      | [Int16/UInt16](/fr/reference/data-types/int-uint)                                            | `I16`, `U16`                                                       |
| `I32`, `U32`                      | [Int32/UInt32](/fr/reference/data-types/int-uint)                                            | `I32`, `U32`                                                       |
| `I64`, `U64`                      | [Int64/UInt64](/fr/reference/data-types/int-uint)                                            | `I64`, `U64`                                                       |
| `F32`                             | [Float32](/fr/reference/data-types/float)                                                    | `F32`                                                              |
| `F64`                             | [Float64](/fr/reference/data-types/float)                                                    | `F64`                                                              |
| `Utf8`, `Binary`                  | [String](/fr/reference/data-types/string)                                                    | `Utf8` (`Binary` avec `output_format_vortex_string_as_string = 0`) |
| `Binary`                          | [FixedString](/fr/reference/data-types/fixedstring)                                          | `Binary`                                                           |
| `Decimal`                         | [Decimal](/fr/reference/data-types/decimal)                                                  | `Decimal`                                                          |
| `vortex.date`                     | [Date32](/fr/reference/data-types/date32)                                                    | `vortex.date`                                                      |
| `vortex.timestamp`                | [DateTime](/fr/reference/data-types/datetime)/[DateTime64](/fr/reference/data-types/datetime64) | `vortex.timestamp`                                                 |
| `vortex.time`                     | [Time64](/fr/reference/data-types/time64)                                                    | `vortex.time`                                                      |
| `List`                            | [Array](/fr/reference/data-types/array)                                                      | `List`                                                             |
| `Struct`                          | [Tuple](/fr/reference/data-types/tuple)                                                      | `Struct`                                                           |
| `Null`                            | [Nullable(Nothing)](/fr/reference/data-types/special-data-types/nothing)                     | `Null`                                                             |

Les autres types ne sont pas pris en charge. En particulier, les colonnes [Map](/fr/reference/data-types/map),
[Int128/UInt128/Int256/UInt256](/fr/reference/data-types/int-uint), [IPv6](/fr/reference/data-types/ipv6)
et [Interval](/fr/reference/data-types/special-data-types/interval) ne peuvent pas être écrites dans des fichiers Vortex.
Les colonnes [String](/fr/reference/data-types/string) sont écrites en tant que `Utf8`, que Vortex compresse mieux
que `Binary`. Vortex exige que les valeurs `Utf8` soient en UTF-8 valide, alors que les chaînes de caractères ClickHouse sont des
séquences d&#39;octets arbitraires ; l&#39;écriture d&#39;une valeur qui n&#39;est pas en UTF-8 valide lève donc une exception. Avec
`output_format_vortex_string_as_string = 0`, les chaînes de caractères sont écrites en tant que `Binary`. Vortex ne dispose d&#39;aucun
type binaire de taille fixe : [FixedString](/fr/reference/data-types/fixedstring) est donc toujours écrit en tant que `Binary`,
et l&#39;inférence de schéma le relit en tant que [String](/fr/reference/data-types/string).
Les colonnes [LowCardinality](/fr/reference/data-types/lowcardinality) sont écrites avec leur type sous-jacent
(Vortex choisit lui-même, de manière adaptative, l&#39;encodage par dictionnaire et les autres encodages).
Les colonnes [DateTime](/fr/reference/data-types/datetime) sont écrites en tant que `vortex.timestamp` avec une précision à la seconde ;
elles sont donc relues en tant que [DateTime64](/fr/reference/data-types/datetime64) avec une scale de 0.
Un `vortex.timestamp` porte une unité et non une scale ; seules les scales qu&#39;une unité exprime exactement -
0, 3, 6 et 9 - sont donc préservées par l&#39;inférence de schéma. Toute autre scale est écrite dans l&#39;unité immédiatement plus large et
inférée avec la scale de cette unité : ainsi, [DateTime64](/fr/reference/data-types/datetime64)`(1)` et `(2)` sont relus
en tant que `DateTime64(3)`, `(4)` et `(5)` en tant que `DateTime64(6)`, et `(7)` et `(8)` en tant que `DateTime64(9)`. Les valeurs
sont remises à l&#39;échelle et conservent leur signification ; seule la scale déclarée s&#39;élargit, et indiquer explicitement le type permet de
le relire tel quel. Il en va de même pour [Time64](/fr/reference/data-types/time64).
`vortex.time` représente une heure de la journée, alors que [Time/Time64](/fr/reference/data-types/time64) dans ClickHouse accepte également
des valeurs négatives et des valeurs de 24 heures ou plus ; l&#39;écriture d&#39;une telle valeur lève une exception plutôt que d&#39;écrire une valeur erronée.
Les colonnes [IPv4](/fr/reference/data-types/ipv4) sont écrites en tant que `U32`, car Vortex ne dispose d&#39;aucun type pour les adresses IP ;
l&#39;inférence de schéma les relit donc en tant que [UInt32](/fr/reference/data-types/int-uint). Indiquez explicitement le type
pour relire une telle colonne en tant que `IPv4` : `SELECT * FROM file('data.vortex', Vortex, 'ip IPv4')`.

Les types de données des colonnes de la table ClickHouse ne doivent pas nécessairement correspondre aux champs de données Vortex associés.
Lors de l&#39;insertion de données, ClickHouse interprète les types de données selon le tableau ci-dessus, puis
[convertit](/fr/reference/functions/regular-functions/type-conversion-functions#CAST) les données dans le type de données défini pour la
colonne de la table ClickHouse.

## Exemple d&#39;utilisation {#example-usage}

Vous pouvez sélectionner des données depuis un fichier Vortex :

```sql
SELECT * FROM file('data.vortex');
```

Et pour écrire des données dans un fichier Vortex :

```sql
SELECT * FROM numbers(3) INTO OUTFILE 'numbers.vortex' FORMAT Vortex;
```

## Paramètres de format {#format-settings}

| Paramètre                               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Valeur par défaut |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `input_format_vortex_filter_push_down`  | Pousse les parties traduisibles de la condition `WHERE` jusque dans le parcours, afin qu’une requête sélective lise et décode moins de données. Seule la partie traduite de la condition est appliquée dans le parcours : une condition qui n’est que partiellement traduisible est élargie en une condition qui conserve au moins toutes les lignes correspondantes. Des lignes non correspondantes peuvent donc tout de même être lues et décodées, et ClickHouse réapplique ensuite le filtre complet. Le pushdown prend actuellement en charge les colonnes de premier niveau de type integer, à virgule flottante, string/binaire, `Bool`, `Date`, `Date32` et `DateTime64`. | `1`               |
| `input_format_vortex_preserve_order`    | Renvoie les lignes dans l’ordre du fichier. Par défaut, les divisions de lignes d’un fichier sont décodées en parallèle et renvoyées dès qu’elles sont prêtes : l’ordre des lignes n’est donc pas garanti. Lorsque ce paramètre est activé, une division lente bloque celles qui la suivent.                                                                                                                                                                                                                                                                                                                                                                                      | `0`               |
| `output_format_vortex_string_as_string` | Écrit les colonnes [String](/fr/reference/data-types/string) en `Utf8` au lieu de `Binary`. Une valeur qui n’est pas en UTF-8 valide lève une exception ; désactivez le paramètre pour écrire ces données en `Binary`.                                                                                                                                                                                                                                                                                                                                                                                                                                                               | `1`               |
| `max_parsing_threads`                   | Nombre de fils d’exécution qui décodent les fichiers Vortex (partagés entre les fichiers lus en parallèle par une même requête). `1` désactive le thread pool : le fichier est alors lu dans `read`, sur le fil d’exécution du pipeline de requête.                                                                                                                                                                                                                                                                                                                                                                                                                               | nombre de cœurs   |
| `max_download_threads`                  | Nombre de fils d’exécution qui lisent le fichier. Avec `0`, les lectures utilisent les fils d’exécution de décodage.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `4`               |

Comme pour les autres formats en colonnes, seules les colonnes utilisées par la requête sont lues depuis le fichier, et
les colonnes absentes du fichier sont remplies avec les valeurs par défaut.

## Performance {#performance}

Un fichier est lu en parallèle. Le parcours le découpe en plages de lignes (alignées sur les limites des fragments des
colonnes demandées, 100 000 lignes au maximum chacune), qui sont lues, filtrées et décodées de manière concurrente :
le décodage s&#39;exécute sur au plus `max_parsing_threads` fils d’exécution du même pool que celui utilisé par le lecteur `Parquet`,
les lectures sur au plus `max_download_threads` fils d’exécution, et la conversion d&#39;un fragment décodé en
colonnes ClickHouse s&#39;effectue sur le fil d’exécution qui l&#39;a décodé. Les fragments sont renvoyés dès qu&#39;ils sont
prêts : l&#39;ordre des lignes n&#39;est donc pas garanti, sauf si `input_format_vortex_preserve_order` est activé. Les
lectures de segments proches dans le fichier sont fusionnées en une seule requête (jusqu&#39;à 4 Mio pour les fichiers
locaux et 16 Mio pour le stockage distant). Le pushdown des filtres réduit la quantité de données lues et décodées
par les requêtes sélectives.
