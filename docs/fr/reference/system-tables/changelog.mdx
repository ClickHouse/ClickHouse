## Description {#description}

Contient les entrées du journal des modifications de ClickHouse, tel qu&#39;il est tenu à jour dans le fichier `CHANGELOG.md` du dépôt, à raison d&#39;une ligne par entrée pour chaque version de fonctionnalités, afin de pouvoir interroger les notes de version en SQL.

## Colonnes {#columns}

* `version` ([Tuple(major UInt16, minor UInt8, patch UInt16)](/fr/reference/data-types/tuple)) — Version à laquelle appartient l&#39;entrée, sous forme de tuple comparable. Le journal des modifications éditorialisé ne décrit que les versions de fonctionnalités ; `patch` vaut donc 0.
* `release_date` ([Date](/fr/reference/data-types/date)) — Date de publication de la version.
* `is_lts` ([UInt8](/fr/reference/data-types/int-uint)) — 1 si la version bénéficie d&#39;un support à long terme (LTS).
* `category` ([LowCardinality(String)](/fr/reference/data-types/lowcardinality)) — Section du journal des modifications à laquelle appartient l&#39;entrée, par exemple &#39;New Feature&#39;, &#39;Performance Improvement&#39; ou &#39;Bug Fix&#39;.
* `description` ([String](/fr/reference/data-types/string)) — Texte de l&#39;entrée du journal des modifications.
* `pull_requests` ([Array(UInt32)](/fr/reference/data-types/array)) — Numéros des pull requests référencées par l&#39;entrée.
* `authors` ([Array(String)](/fr/reference/data-types/array)) — Auteurs des pull requests référencées.

## Exemple {#example}

Recherchez les modifications récentes liées à JSON, en commençant par la version la plus récente :

```sql
SELECT version, category, description
FROM system.changelog
WHERE description ILIKE '%JSON%' AND version >= (26, 1, 0)
ORDER BY version DESC
LIMIT 3
```
