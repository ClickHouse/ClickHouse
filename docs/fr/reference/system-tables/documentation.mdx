<div id="description">
  ## Description
</div>

Collecte dans une seule table la documentation embarquée des composants documentés de manière uniforme du système. Chaque ligne correspond à une entité (une fonction, un moteur de table, un type de données, etc.) et contient la documentation de référence de cette entité au format Markdown — le même contenu que celui publié sur le site web et exposé par les tables `system.*` propres à chaque type.

La `description` est construite à partir des parties structurées de la documentation embarquée (`description`, `syntax`, arguments, exemples, etc.), de sorte qu&#39;une seule colonne contient la documentation complète d&#39;une entité. Lorsque la documentation embarquée contient toute la page de référence dans sa `description` (comme c&#39;est le cas pour les composants dont les pages du site web sont générées automatiquement à partir de celle-ci : moteurs de table, moteurs de base de données, types de données, formats, fonctions de table), la page est publiée telle quelle, sans ajouter de sections composées à partir des champs de métadonnées structurées — le corps de la page couvre déjà ces informations. Les alias sont présentés sous la forme d&#39;un bref renvoi vers l&#39;entité canonique, par ex. ``Alias of `trunc`.``

Cette table regroupe, d&#39;une certaine manière, les informations disponibles dans les tables de documentation propres à chaque type ([`system.functions`](/fr/reference/system-tables/functions), [`system.table_engines`](/fr/reference/system-tables/table_engines), [`system.data_type_families`](/fr/reference/system-tables/data_type_families), entre autres). Elle est notamment conçue pour servir de base à une commande `help` interactive dans le client, mais elle est également utile à elle seule.

Les types d&#39;entités suivants sont collectés (la valeur de la colonne `type` est indiquée entre parenthèses) :

* Fonctions (`Function`)
* Fonctions d’agrégation (`Aggregate Function`)
* Fonctions de table (`Table Function`)
* Moteurs de table (`Table Engine`)
* Moteurs de base de données (`Database Engine`)
* Types de données (`Data Type`)
* Structures de dictionnaire (`Dictionary Layout`)
* Sources de dictionnaire (`Dictionary Source`)
* Combinateurs de fonctions d’agrégation (`Aggregate Function Combinator`)
* Types d&#39;index de saut de données (`Data Skipping Index`)
* Types de disque (`Disk Type`)
* Paramètres (`Setting`)
* Paramètres MergeTree (`MergeTree Setting`)
* Paramètres du serveur (`Server Setting`)
* Formats (`Format`)
* Codecs de compression (`Compression Codec`)
* Événements de profil (`Profile Event`)
* Métriques actuelles (`Current Metric`)
* Métriques asynchrones (`Asynchronous Metric`)
* Tables système (`System Table`)
* Instructions SQL (`Statement`)

Pour les paramètres (de tout type), la documentation correspond à la description du paramètre, ainsi qu&#39;à son type et à sa valeur par défaut ; les paramètres obsolètes ne sont pas exposés. Elle contient également l&#39;historique des modifications de la valeur par défaut du paramètre au fil des versions de ClickHouse : la version dans laquelle le paramètre a été introduit et chaque modification ultérieure de sa valeur par défaut, avec la valeur précédente, la nouvelle valeur et la raison de la modification. Il s&#39;agit des mêmes données qui servent de base au paramètre `compatibility` et à [`system.settings_changes`](/fr/reference/system-tables/settings_changes) ; elles couvrent donc les modifications enregistrées depuis l&#39;introduction de ce mécanisme : un ancien paramètre dont la valeur par défaut n&#39;a jamais changé n&#39;a pas d&#39;historique, pas plus que les paramètres du serveur, que `compatibility` ne couvre pas. Une modification enregistrée sous un alias d&#39;un paramètre appartient à l&#39;historique de ce paramètre, de la même manière que `compatibility` l&#39;applique ; ainsi, l&#39;historique d&#39;un paramètre qui a été renommé n&#39;est pas interrompu lors du renommage. L&#39;exception est un enregistrement écrit sous un alias dans le seul but d&#39;enregistrer cet alias, qui appartient uniquement à l&#39;historique de l&#39;alias. Un alias contient l&#39;historique de son propre nom : chaque enregistrement écrit sous celui-ci, ainsi que l&#39;enregistrement qui l&#39;a déclaré comme alias, que le fichier d&#39;historique écrit parfois sous un autre nom du même paramètre.

Pour les tables système, la documentation correspond au commentaire de la table ainsi qu&#39;à la liste de ses colonnes (le nom, le type et la description de chacune).

Pour les instructions SQL, la documentation est générée à partir des champs structurés exposés par `system.statements`, y compris la syntaxe et les instructions associées lorsque ces sections ne font pas déjà partie de la description détenue par la source.

La colonne `source` contient le chemin du fichier source dans lequel la documentation de l&#39;entité est définie, relatif à la racine du dépôt. Pour la plupart des entités, il est capturé automatiquement à l&#39;endroit où l&#39;objet de documentation est construit (le point d&#39;enregistrement du composant) ; pour les types documentés chacun dans un fichier source unique (comme les paramètres, les événements de profil et les métriques actuelles), il s&#39;agit de ce fichier.

<div id="columns">
  ## Colonnes
</div>

{/*AUTOGENERATED_START*/}

* `name` ([String](/fr/reference/data-types/string)) — Le nom de l’entité, par ex. `domainWithoutWWW` ou `MergeTree`.
* `type` ([Enum8(&#39;Function&#39; = 1, &#39;Aggregate Function&#39; = 2, &#39;Table Function&#39; = 3, &#39;Table Engine&#39; = 4, &#39;Database Engine&#39; = 5, &#39;Data Type&#39; = 6, &#39;Dictionary Layout&#39; = 7, &#39;Dictionary Source&#39; = 8, &#39;Aggregate Function Combinator&#39; = 9, &#39;Data Skipping Index&#39; = 10, &#39;Disk Type&#39; = 11, &#39;Setting&#39; = 12, &#39;MergeTree Setting&#39; = 13, &#39;Server Setting&#39; = 14, &#39;Format&#39; = 15, &#39;Compression Codec&#39; = 16, &#39;Profile Event&#39; = 17, &#39;Current Metric&#39; = 18, &#39;Asynchronous Metric&#39; = 19, &#39;System Table&#39; = 20, &#39;Statement&#39; = 21)](/fr/reference/data-types/enum)) — Le type de l’entité, par ex. `Function` ou `Table Engine`.
* `description` ([String](/fr/reference/data-types/string)) — La documentation de référence de l’entité, au format Markdown, est générée à partir de la documentation embarquée (le même contenu que celui publié sur le site web), y compris la syntaxe, les exemples et d’autres parties structurées, le cas échéant.
* `source` ([String](/fr/reference/data-types/string)) — Le chemin d’accès au fichier source où la documentation de l’entité est définie, relatif à la racine du dépôt. Vide si l’emplacement de la source est inconnu.

{/*AUTOGENERATED_END*/}

<div id="example">
  ## Exemple
</div>

Consultez la documentation d’une entité donnée :

```sql title="Query"
SELECT description
FROM system.documentation
WHERE type = 'Table Engine' AND name = 'MergeTree'
FORMAT TSVRaw;
```

Le même nom peut désigner plusieurs types d’entités (par exemple, il existe à la fois une fonction de table `file` et une source de dictionnaire `file`) ; il est donc pratique de rechercher un nom dans tous les types :

```sql title="Query"
SELECT type, name
FROM system.documentation
WHERE name = 'file'
ORDER BY type;
```

Comptez les entités documentées de chaque type :

```sql title="Query"
SELECT type, count()
FROM system.documentation
GROUP BY type
ORDER BY count() DESC;
```

Découvrez dans quelle version un paramètre a été introduit et comment sa valeur par défaut a évolué depuis :

```sql title="Query"
SELECT description
FROM system.documentation
WHERE type = 'Setting' AND name = 'async_insert_max_data_size'
FORMAT TSVRaw;
```
