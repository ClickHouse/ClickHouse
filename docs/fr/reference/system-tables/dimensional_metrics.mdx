## Description {#description}

Cette table contient des métriques dimensionnelles qui peuvent être calculées instantanément et exportées au format Prometheus. Elle est toujours à jour.

## Description des métriques {#metric_descriptions}

### merge_failures {#merge_failures}

Nombre total des fusions ayant échoué depuis le démarrage.

### startup_scripts_failure_reason {#startup_scripts_failure_reason}

Indique les échecs des scripts de démarrage par type d’erreur. Vaut 1 lorsqu’un script de démarrage échoue, étiqueté avec le nom de l’erreur.

### merge_tree_parts {#merge_tree_parts}

Nombre de parties de données MergeTree, étiquetées selon l’état de la partie, son type et le fait qu’il s’agisse ou non d’une partie de projection.

### `filesystem_cache_evictions_total` {#filesystem-cache-evictions-total}

Nombre de segments de fichier évincés du cache du système de fichiers, avec le nom du cache comme étiquette. Désactivé par défaut ; activez cette métrique avec `expose_prometheus_eviction_metrics`.

### `filesystem_cache_evicted_bytes_total` {#filesystem-cache-evicted-bytes-total}

Nombre total d’octets de segments de fichier évincés d’un cache du système de fichiers, avec le nom du cache comme étiquette. Désactivé par défaut ; activez-le avec `expose_prometheus_eviction_metrics`.

### `filesystem_cache_evictions_by_user_total` {#filesystem-cache-evictions-by-user-total}

Nombre de segments de fichier évincés du cache du système de fichiers, étiqueté par nom de cache et identifiant utilisateur. Désactivé par défaut ; activez cette métrique avec `expose_prometheus_eviction_metrics` et `expose_prometheus_eviction_metrics_per_user`.

### `filesystem_cache_evicted_bytes_by_user_total` {#filesystem-cache-evicted-bytes-by-user-total}

Nombre total d’octets de segments de fichier évincés d’un cache du système de fichiers, avec comme étiquettes le nom du cache et l’identifiant de l’utilisateur. Désactivé par défaut ; activez-le avec `expose_prometheus_eviction_metrics` et `expose_prometheus_eviction_metrics_per_user`.

### `object_storage_queue_failures_total` {#object-storage-queue-failures-total}

Nombre d’échecs d’`ObjectStorageQueue` (`S3Queue`/`AzureQueue`), étiqueté par base de données, table, étape de traitement (`read`, `set_processing`, `insert`, `commit`, `after_processing`) et code d’erreur. Pour l’étape `after_processing`, la valeur correspond au nombre d’objets pour lesquels l’action `after_processing` (suppression, étiquetage ou déplacement) n’a pas abouti.

### `object_storage_queue_permanently_failed_files_total` {#object-storage-queue-permanently-failed-files-total}

Nombre de fichiers `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) définitivement abandonnés après épuisement des tentatives (ou lorsque celles-ci sont désactivées), étiqueté par base de données et table. Chacun représente un fichier dont les données ne seront jamais traitées.

### `object_storage_queue_newest_seen_object_timestamp_seconds` {#object-storage-queue-newest-seen-object-timestamp-seconds}

Horodatage Unix correspondant à l’heure de dernière modification de l’objet le plus récent détecté jusqu’à présent par une table `ObjectStorageQueue` (`S3Queue`/`AzureQueue`), étiqueté avec la base de données et la table. La série est supprimée lorsque la table est supprimée ou détachée. Après un renommage, la série associée à l’ancien nom subsiste jusqu’au prochain restart du serveur.

### `object_storage_queue_newest_committed_object_timestamp_seconds` {#object-storage-queue-newest-committed-object-timestamp-seconds}

Horodatage Unix de l’heure de dernière modification de l’objet le plus récent entièrement traité jusqu’à présent par une table `ObjectStorageQueue` (`S3Queue`/`AzureQueue`), étiqueté avec la base de données et la table. La série est retirée lorsque la table est supprimée ou détachée. Après un renommage, la série associée à l’ancien nom subsiste jusqu’au restart du serveur.

### `object_storage_queue_processed_files_total` {#object-storage-queue-processed-files-total}

Nombre de fichiers validés comme traités par cette table `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) sur ce serveur, étiqueté avec la base de données et la table.

### `object_storage_queue_last_poll_timestamp_seconds` {#object-storage-queue-last-poll-timestamp-seconds}

Horodatage Unix du dernier démarrage, par un fil d’exécution de diffusion en continu en arrière-plan d’une table `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) sur ce serveur, d’un cycle de recherche de fichiers à traiter ou d’un lot de ce cycle, étiqueté par base de données et table. Il est mis à jour au démarrage d’un cycle, une fois que la table s’est enregistrée comme active dans Keeper, puis à nouveau avant chaque lot du cycle ; il progresse donc aussi lorsque le cycle ne trouve aucun fichier ou échoue, ainsi que pendant le traitement d’un arriéré important. Il ne progresse pas lorsque l’enregistrement échoue. La valeur 0 signifie que la table n’a pas interrogé la source depuis son démarrage. Il ne progresse pas tant que la table n’a aucune vue matérialisée attachée et prête, tant que la diffusion en continu est arrêtée ou en pause, ni tant que la diffusion en continu est désactivée sur le serveur, car la table ne consomme alors aucune donnée. Tous les fils d’exécution de diffusion en continu d’une table écrivent dans la même série ; celle-ci reflète donc le cycle le plus récent, quel que soit le fil concerné. La série est supprimée lorsque la table est supprimée ou détachée. Après un renommage, la série associée à l’ancien nom subsiste jusqu’au restart du serveur.

### `system_log_flushes_total` {#system-log-flushes-total}

Nombre de tentatives de vidage du tampon en mémoire d&#39;un journal système vers sa table, étiqueté par la base de données et la table du journal système, ainsi que par résultat (`success`, `failure`).

### `system_log_flushed_rows_total` {#system-log-flushed-rows-total}

Nombre de lignes écrites lors des vidages réussis d&#39;un journal système, étiqueté par la base de données et la table du journal système.

### `system_log_dropped_rows_total` {#system-log-dropped-rows-total}

Nombre de lignes perdues d&#39;un journal système, étiqueté par la base de données et la table du journal système, ainsi que par raison : `queue_full` pour les lignes refusées parce que le tampon en mémoire a atteint `max_size_rows` (la valeur est mise à jour lorsque le tampon est récupéré pour le prochain vidage), `flush_failed` pour les lignes d&#39;un vidage en échec.

## Colonnes {#columns}

* `metric` ([String](/fr/reference/data-types/string)) — Nom de la métrique.
* `value` ([Float64](/fr/reference/data-types/float)) — Valeur de la métrique.
* `description` ([String](/fr/reference/data-types/string)) — Description de la métrique.
* `labels` ([Map(String, String)](/fr/reference/data-types/map)) — Labels de métrique.

**Alias :**

* `name` — alias de `metric`.

## Exemple {#example}

Vous pouvez utiliser une requête comme celle-ci pour exporter toutes les métriques dimensionnelles au format Prometheus.

```sql
SELECT
  metric AS name,
  toFloat64(value) AS value,
  description AS help,
  labels,
  'gauge' AS type
FROM system.dimensional_metrics
FORMAT Prometheus
```
