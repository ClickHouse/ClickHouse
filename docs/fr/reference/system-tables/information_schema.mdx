`INFORMATION_SCHEMA` (ou : `information_schema`) est une base de données système qui fournit une [vue indépendante du SGBD](https://en.wikipedia.org/wiki/Information_schema), quoique seulement partiellement normalisée, des métadonnées des objets de base de données. Les vues de `INFORMATION_SCHEMA` sont généralement moins complètes que les tables système classiques, mais les outils peuvent les utiliser pour obtenir des informations de base de manière inter-SGBD. La structure et le contenu des vues de `INFORMATION_SCHEMA` sont conçus pour évoluer de manière rétrocompatible, c’est-à-dire que seules de nouvelles fonctionnalités sont ajoutées, sans modification ni suppression des fonctionnalités existantes. Du point de vue de l’implémentation interne, les vues de `INFORMATION_SCHEMA` correspondent généralement à des tables système classiques telles que [system.columns](/fr/reference/system-tables/columns), [system.databases](/fr/reference/system-tables/databases) et [system.tables](/fr/reference/system-tables/tables).

```sql
SHOW TABLES FROM INFORMATION_SCHEMA;

-- or:
SHOW TABLES FROM information_schema;
```

Des vues équivalentes non sensibles à la casse, par exemple `INFORMATION_SCHEMA.columns`, sont fournies pour des raisons de compatibilité avec d&#39;autres bases de données. Il en va de même pour toutes les colonnes de ces vues : des variantes en minuscules (par exemple `table_name`) et en majuscules (`TABLE_NAME`) sont disponibles.

## TABLES {#tables}

Contient les colonnes lues à partir de la table système [system.tables](/fr/reference/system-tables/tables).

Colonnes :

* `table_catalog` ([String](/fr/reference/data-types/string)) — Le nom de la base de données dans laquelle se trouve la table.
* `table_schema` ([String](/fr/reference/data-types/string)) — Le nom de la base de données dans laquelle se trouve la table.
* `table_name` ([String](/fr/reference/data-types/string)) — Le nom de la table.
* `table_type` ([String](/fr/reference/data-types/string)) — Le type de table. Valeurs possibles :
  * `BASE TABLE`
  * `VIEW`
  * `FOREIGN TABLE`
  * `LOCAL TEMPORARY`
  * `SYSTEM VIEW`
* `table_rows` ([Nullable](/fr/reference/data-types/nullable)([UInt64](/fr/reference/data-types/int-uint))) — Le nombre total de lignes. NULL s&#39;il n&#39;a pas pu être déterminé.
* `data_length` ([Nullable](/fr/reference/data-types/nullable)([UInt64](/fr/reference/data-types/int-uint))) — La taille des données sur disque. NULL si elle n&#39;a pas pu être déterminée.
* `index_length` ([Nullable](/fr/reference/data-types/nullable)([UInt64](/fr/reference/data-types/int-uint))) — La taille totale de la clé primaire, des index secondaires et de toutes les marks.
* `table_collation` ([Nullable](/fr/reference/data-types/nullable)([String](/fr/reference/data-types/string))) — La collation par défaut de la table. Toujours `utf8mb4_0900_ai_ci`.
* `table_comment` ([Nullable](/fr/reference/data-types/nullable)([String](/fr/reference/data-types/string))) — Le commentaire utilisé lors de la création de la table.

**Exemple**

```sql title="Query"
SELECT table_catalog,

       table_type, 
       table_collation, 
       table_comment

WHERE (table_schema = currentDatabase() OR table_schema = '')
  AND table_name NOT LIKE '%inner%'

FORMAT Vertical;
```

## VIEWS {#views}

Contient les colonnes issues de la table système [system.tables](/fr/reference/system-tables/tables), lorsque le moteur de table [View](/fr/reference/engines/table-engines/special/view) est utilisé.

Colonnes :

{/*AUTOGENERATED_START*/}

* `table_catalog` ([String](/fr/reference/data-types/string)) — Nom de la base de données dans laquelle se trouve la table.
* `table_schema` ([String](/fr/reference/data-types/string)) — Nom de la base de données dans laquelle se trouve la table.
* `table_name` ([String](/fr/reference/data-types/string)) — Nom de la table.
* `view_definition` ([String](/fr/reference/data-types/string)) — Requête `SELECT` de la vue.
* `check_option` ([String](/fr/reference/data-types/string)) — `NONE`, aucune vérification.
* `is_updatable` ([Enum8](/fr/reference/data-types/enum)) — `NO`, la vue ne peut pas être mise à jour.
* `is_insertable_into` ([Enum8](/fr/reference/data-types/enum)) — Indique si la vue créée est [matérialisée](/fr/reference/statements/create/view#materialized-view). Valeurs possibles :
  * `NO` — La vue créée n’est pas matérialisée.
  * `YES` — La vue créée est matérialisée.
* `is_trigger_updatable` ([Enum8](/fr/reference/data-types/enum)) — `NO`, le déclencheur ne peut pas être mis à jour.
* `is_trigger_deletable` ([Enum8](/fr/reference/data-types/enum)) — `NO`, le déclencheur ne peut pas être supprimé.
* `is_trigger_insertable_into` ([Enum8](/fr/reference/data-types/enum)) — `NO`, aucune donnée ne peut être insérée dans le déclencheur.

{/*AUTOGENERATED_END*/}

**Exemple**

```sql title="Query"

       is_trigger_updatable,
       is_trigger_deletable,
       is_trigger_insertable_into
```

## COLLATIONS {#collations}

Fournit des informations sur les collations disponibles. Contient les collations de [system.collations](/fr/reference/system-tables/collations), ainsi que deux lignes de compatibilité MySQL : `utf8mb4_0900_ai_ci` — la collation annoncée par le protocole MySQL lors du handshake, dans `SCHEMATA.DEFAULT_COLLATION_NAME` et dans `TABLES.TABLE_COLLATION` — et `binary` — la pseudo-collation que le protocole MySQL attribue aux colonnes numériques et aux autres colonnes non textuelles dans les métadonnées du jeu de résultats — afin qu&#39;un client compatible MySQL qui suit les collations annoncées jusqu&#39;à cette vue puisse les y trouver.

Colonnes :

* `collation_name` ([String](/fr/reference/data-types/string)) — Le nom de la collation.
* `character_set_name` ([Nullable](/fr/reference/data-types/nullable)([String](/fr/reference/data-types/string))) — Le jeu de caractères associé (`utf8mb4` pour `utf8mb4_0900_ai_ci`, `binary` pour `binary`, sinon `NULL`). Fourni pour assurer la compatibilité avec MySQL.
* `id` ([Nullable](/fr/reference/data-types/nullable)([UInt64](/fr/reference/data-types/int-uint))) — L&#39;identifiant de la collation MySQL (`255` pour `utf8mb4_0900_ai_ci`, `63` pour `binary`, sinon `NULL`). Fourni pour assurer la compatibilité avec MySQL.
* `is_default` ([Nullable](/fr/reference/data-types/nullable)([String](/fr/reference/data-types/string))) — Indique si la collation est celle par défaut de son jeu de caractères (`Yes` pour les deux lignes de compatibilité MySQL, sinon `NULL`). Fourni pour assurer la compatibilité avec MySQL.
* `is_compiled` ([Nullable](/fr/reference/data-types/nullable)([String](/fr/reference/data-types/string))) — Indique si la collation est compilée dans le serveur (`Yes` pour les deux lignes de compatibilité MySQL, sinon `NULL`). Fourni pour assurer la compatibilité avec MySQL.
* `sortlen` ([Nullable](/fr/reference/data-types/nullable)([UInt64](/fr/reference/data-types/int-uint))) — La longueur minimale de tri (`0` pour `utf8mb4_0900_ai_ci`, `1` pour `binary`, sinon `NULL`). Fourni pour assurer la compatibilité avec MySQL.
* `pad_attribute` ([Nullable](/fr/reference/data-types/nullable)([String](/fr/reference/data-types/string))) — L&#39;attribut de remplissage, `NO PAD` ou `PAD SPACE` (`NO PAD` pour les deux lignes de compatibilité MySQL, sinon `NULL`). Fourni pour assurer la compatibilité avec MySQL.

## USER_PRIVILEGES {#user_privileges}

Fournit des informations sur les privilèges globaux, issues de la table système [system.grants](/fr/reference/system-tables/grants) (lignes sans base de données).

Les vues `*_PRIVILEGES` n&#39;affichent que les privilèges accordés positifs et sans caractère générique : les révocations partielles, les autorisations avec caractères génériques (par ex. `GRANT SELECT ON db_prefix*.*`) et les privilèges accordés sur des objets nommés spécifiques pour des types de privilèges paramétrés (par ex. `GRANT TABLE ENGINE ON TinyLog`) ne peuvent pas être représentés dans le format compatible MySQL et sont donc omis. Par conséquent, un bénéficiaire restreint par une révocation partielle apparaît avec le privilège non restreint. Les privilèges `ON *` de types paramétrés apparaissent comme de simples privilèges globaux. `system.grants` fait foi. Contrairement à MySQL, les vues affichent les privilèges accordés à l&#39;ensemble des utilisateurs et des rôles, et leur lecture nécessite un accès à `system.grants` ; sans cet accès, la requête échoue avec une exception `ACCESS_DENIED`. Il n&#39;existe pas de colonne `GRANTOR`, car ClickHouse n&#39;enregistre pas l&#39;auteur d&#39;un privilège accordé.

Colonnes :

* `grantee` ([String](/fr/reference/data-types/string)) — L&#39;utilisateur ou le rôle auquel le privilège est accordé, au format MySQL : `'name'@'%'`. Les rôles n&#39;ayant pas d&#39;équivalent dans MySQL, ils sont représentés de la même manière que les utilisateurs.
* `table_catalog` ([String](/fr/reference/data-types/string)) — Toujours `def`.
* `privilege_type` ([String](/fr/reference/data-types/string)) — Le nom du privilège, par ex. `SELECT` ou `ALTER UPDATE`. Consultez [system.privileges](/fr/reference/system-tables/privileges) pour la liste complète.
* `is_grantable` ([String](/fr/reference/data-types/string)) — `YES` si le privilège est accordé `WITH GRANT OPTION`, sinon `NO`.
* `grantee_type` ([String](/fr/reference/data-types/string)) — `USER` ou `ROLE`. Colonne non standard : dans ClickHouse, un utilisateur et un rôle peuvent porter le même nom, et cette colonne permet de les distinguer.

## SCHEMA_PRIVILEGES {#schema_privileges}

Fournit des informations sur les privilèges au niveau de la base de données, lus depuis la table système [system.grants](/fr/reference/system-tables/grants) (lignes comportant une base de données mais aucune table). Consultez [USER&#95;PRIVILEGES](#user_privileges) pour connaître les limitations communes à toutes les vues `*_PRIVILEGES`.

Colonnes :

* `grantee` ([String](/fr/reference/data-types/string)) — Utilisateur ou rôle auquel le privilège est accordé, au format MySQL : `'name'@'%'`.
* `table_catalog` ([String](/fr/reference/data-types/string)) — Toujours `def`.
* `table_schema` ([String](/fr/reference/data-types/string)) — Nom de la base de données.
* `privilege_type` ([String](/fr/reference/data-types/string)) — Nom du privilège.
* `is_grantable` ([String](/fr/reference/data-types/string)) — `YES` si le privilège est accordé avec `WITH GRANT OPTION`, sinon `NO`.
* `grantee_type` ([String](/fr/reference/data-types/string)) — `USER` ou `ROLE`. Colonne non standard : dans ClickHouse, un utilisateur et un rôle peuvent porter le même nom ; cette colonne permet de distinguer ces bénéficiaires.
