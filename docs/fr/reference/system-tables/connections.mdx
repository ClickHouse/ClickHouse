## Description {#description}

Affiche les connexions client ouvertes des interfaces de requête TCP natif et HTTP.
Une connexion est `active` lorsqu&#39;une requête est en cours d&#39;exécution. Une connexion est `idle` lorsqu&#39;elle attend la requête suivante.

La table n&#39;affiche pas les connexions suivantes :

* Les connexions d&#39;autres protocoles, par exemple MySQL, PostgreSQL et gRPC.
* Les connexions interserveur.
* Les connexions HTTP qui n&#39;ont exécuté aucune requête, par exemple les connexions `/ping` et Prometheus.

Le serveur ne collecte les connexions que si le paramètre du serveur `collect_connection_metrics` vaut `true`. Si ce paramètre vaut `false`, la table est vide.
Vous pouvez modifier ce paramètre sans redémarrage (`SYSTEM RELOAD CONFIG`) :

* Si vous passez le paramètre à `false`, la table se vide et le serveur cesse d&#39;enregistrer les nouvelles connexions.
* Si vous passez le paramètre à `true`, une connexion ouverte apparaît dans la table lors de sa requête suivante.

Le serveur ajoute une connexion TCP à la table après l&#39;authentification et la retire lorsqu&#39;elle se ferme.
Le serveur ajoute une connexion HTTP à la table lors de sa première requête et la retire lorsque le socket se ferme.
Une connexion HTTP keep-alive apparaît donc comme `idle` dans la table entre deux requêtes.

Un utilisateur ne disposant pas du privilège `SHOW CONNECTIONS` ne voit que ses propres connexions.
La vérification repose sur l&#39;ID de l&#39;utilisateur, et non sur son nom. Ainsi, un utilisateur renommé conserve ses connexions, et un nouvel utilisateur portant l&#39;ancien nom n&#39;y a pas accès.

`connection_id` est un UUID aléatoire. Il est donc unique d&#39;un serveur à l&#39;autre, et vous pouvez combiner les tables de plusieurs répliques, par exemple avec `clusterAllReplicas`.

`connected_time` a la même signification pour TCP et HTTP : l&#39;heure à laquelle le serveur a commencé à traiter le socket.
Cette heure précède la poignée de main TCP, l&#39;authentification et la première requête. Elle peut donc être antérieure au moment où la connexion apparaît dans la table.

## Colonnes {#columns}

* `connection_id` ([UUID](/fr/reference/data-types/uuid)) — Identifiant unique de la connexion : un UUID aléatoire. Il est unique sur l&#39;ensemble des serveurs, par exemple avec `clusterAllReplicas`. Une connexion TCP reçoit son identifiant après l&#39;authentification. Une connexion HTTP reçoit son identifiant lors de sa première requête.
* `protocol` ([LowCardinality(String)](/fr/reference/data-types/lowcardinality)) — Protocole de la connexion : TCP (protocole natif) ou HTTP.
* `client_address` ([IPv6](/fr/reference/data-types/ipv6)) — Adresse IP du client. Derrière un proxy, il s&#39;agit de l&#39;adresse du client si le serveur fait confiance au protocole PROXY ou à l&#39;en-tête `X-Forwarded-For`. En HTTP, il s&#39;agit de l&#39;adresse de la dernière requête.
* `client_port` ([UInt16](/fr/reference/data-types/int-uint)) — Port TCP du client. Derrière un proxy, il s&#39;agit du port fourni par le protocole PROXY ou l&#39;en-tête `X-Forwarded-For` si le serveur leur fait confiance. En HTTP, il s&#39;agit du port de la dernière requête.
* `server_port` ([UInt16](/fr/reference/data-types/int-uint)) — Port du serveur ayant accepté la connexion.
* `user` ([String](/fr/reference/data-types/string)) — Nom de l&#39;utilisateur authentifié. Pour une connexion HTTP, il s&#39;agit de l&#39;utilisateur de la dernière requête. Chaque requête d&#39;une connexion keep-alive fait l&#39;objet de sa propre authentification. Si l&#39;utilisateur est renommé, cette colonne affiche l&#39;ancien nom jusqu&#39;à la prochaine authentification. La vérification des accès s&#39;appuie sur l&#39;ID de l&#39;utilisateur, et non sur son nom.
* `status` ([LowCardinality(String)](/fr/reference/data-types/lowcardinality)) — Statut de la connexion. `active` : une requête est en cours d&#39;exécution. `idle` : la connexion est ouverte et attend la prochaine requête ou la prochaine requête HTTP.
* `query_id` ([String](/fr/reference/data-types/string)) — Identifiant de la requête en cours d&#39;exécution. Vide si la connexion est inactive.
* `client_name` ([String](/fr/reference/data-types/string)) — Nom de l&#39;application cliente. Un client TCP transmet ce nom lors de la poignée de main. En HTTP, il s&#39;agit de l&#39;en-tête `User-Agent` de la dernière requête.
* `client_version_major` ([UInt64](/fr/reference/data-types/int-uint)) — Version majeure du client, obtenue lors de la poignée de main TCP. 0 pour les connexions HTTP.
* `client_version_minor` ([UInt64](/fr/reference/data-types/int-uint)) — Version mineure du client, obtenue lors de la poignée de main TCP. 0 pour les connexions HTTP.
* `client_version_patch` ([UInt64](/fr/reference/data-types/int-uint)) — Version de correctif du client, obtenue lors de la poignée de main TCP. 0 pour les connexions HTTP.
* `connected_time` ([DateTime](/fr/reference/data-types/datetime)) — Heure à laquelle le serveur a commencé à traiter le socket. Cette heure est définie de la même manière pour TCP et HTTP : avant la poignée de main, l&#39;authentification et la première requête.
* `last_query_time` ([Nullable(DateTime)](/fr/reference/data-types/nullable)) — Horodatage de début de la dernière requête sur cette connexion. NULL si la connexion n&#39;a exécuté aucune requête.

## Exemples {#examples}

```sql
SELECT connection_id, protocol, user, status, query_id, client_name, connected_time, last_query_time
FROM system.connections
FORMAT Vertical;
```

```sql
SELECT hostName(), protocol, status, count()
FROM clusterAllReplicas(default, system.connections)
GROUP BY ALL;
```
