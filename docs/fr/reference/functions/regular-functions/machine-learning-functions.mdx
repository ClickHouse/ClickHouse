## evalMLMethod {#evalmlmethod}

La prédiction à l’aide de modèles de régression ajustés s’effectue avec la fonction `evalMLMethod`. Voir le lien sous `linearRegression`.

## stochasticLinearRegression {#stochasticlinearregression}

La fonction d’agrégation [stochasticLinearRegression](/fr/reference/functions/aggregate-functions/stochasticLinearRegression) implémente la méthode de descente de gradient stochastique à l’aide d’un modèle linéaire et de la fonction de perte MSE. Elle utilise `evalMLMethod` pour effectuer des prédictions sur de nouvelles données.

## stochasticLogisticRegression {#stochasticlogisticregression}

La fonction d’agrégation [stochasticLogisticRegression](/fr/reference/functions/aggregate-functions/stochasticLogisticRegression) implémente une méthode de descente de gradient stochastique pour un problème de classification binaire. Elle utilise `evalMLMethod` pour effectuer des prédictions sur de nouvelles données.

## assignCentroid {#assignCentroid}

Introduite dans : v26.8.0

Renvoie l’identifiant du centroïde (L2) le plus proche d’un vecteur. Les centroïdes sont fournis sous la forme d’un tableau constant de tableaux de nombres à virgule flottante, l’identifiant correspondant à la position d’indice 0 dans ce tableau, ou sous la forme du nom d’un `Dictionary` contenant les attributs `cid` et `vec`, auquel cas l’identifiant est `cid`.

<Note>
  Cette fonction est non déterministe : elle peut renvoyer des résultats différents pour les mêmes arguments.
</Note>

**Syntaxe**

```sql
assignCentroid(vec, centroids | dict_name)
```

**Arguments**

* `vec` — Vecteur à affecter. Sa dimension doit correspondre à celle des centroïdes. Les types autres que `Float32` sont convertis en `Float32`, utilisé par le kernel de calcul des scores. [`Array(Float32)`](/fr/reference/data-types/array) ou [`Array(Float64)`](/fr/reference/data-types/array) ou [`Array(BFloat16)`](/fr/reference/data-types/array)
* `centroids` — Centroïdes par rapport auxquels calculer les scores, qui doivent être constants. Ils peuvent être fournis sous forme d’un tableau de tableaux de flottants non vides et de même taille, l’identifiant étant alors la position à partir de 0 dans ce tableau, ou sous forme du nom d’un `Dictionary` avec un attribut `cid` de type entier non signé compatible avec `UInt32` et un attribut `vec` de type `Array(Float32)`, l’identifiant étant alors `cid`. Le dictionnaire est lu une fois et mis en cache jusqu’à son rechargement. [`Array(Array(Float32))`](/fr/reference/data-types/array) ou [`Array(Array(Float64))`](/fr/reference/data-types/array) ou [`Array(Array(BFloat16))`](/fr/reference/data-types/array) ou [`String`](/fr/reference/data-types/string)

**Valeur renvoyée**

L’identifiant du centroïde le plus proche. [`UInt32`](/fr/reference/data-types/int-uint)

**Exemples**

**Centroïdes intégrés**

```sql title=Query
SELECT assignCentroid([1.0, 2.0]::Array(Float32), [[0.0, 0.0], [1.0, 2.0]]::Array(Array(Float32)))
```

```response title=Response
1
```

## evalMLMethod {#evalMLMethod}

Introduit dans : v20.1.0

Applique un modèle d’apprentissage automatique entraîné aux variables d’entrée afin de générer des prédictions.

**Syntaxe**

```sql
evalMLMethod(model, x1[, x2, ...])
```

**Arguments**

* `model` — Le modèle d’apprentissage automatique entraîné. [`AggregateFunctionState`](/fr/reference/data-types/aggregatefunction)
* `x1, x2, ...` — Valeurs des caractéristiques pour la prédiction. [`Float*`](/fr/reference/data-types/float) ou [`(U)Int*`](/fr/reference/data-types/int-uint)

**Valeur renvoyée**

Renvoie la valeur prédite à partir du modèle entraîné. [`Float64`](/fr/reference/data-types/float)

**Exemples**

**Exemple d&#39;utilisation**

```sql title=Query
CREATE TABLE trips (pickup_datetime DateTime('UTC'), trip_distance Float64, total_amount Float64) ENGINE = Memory;

-- A fare of 3, plus 2.5 for every unit of distance.
INSERT INTO trips
SELECT toDateTime('2020-01-01 00:00:00', 'UTC') + number * 60, number % 10 + 1, 2.5 * (number % 10 + 1) + 3
FROM numbers(1000);

-- One model per year of the data.
CREATE TABLE models ENGINE = Memory AS
SELECT
    toYear(pickup_datetime) AS year,
    stochasticLinearRegressionState(0.01, 0.0, 10, 'SGD')(total_amount, trip_distance) AS model
FROM trips
GROUP BY year;

SELECT
    trip_distance,
    round(evalMLMethod(model, trip_distance), 2) AS predicted,
    total_amount
FROM trips
LEFT JOIN models ON year = toYear(pickup_datetime)
ORDER BY pickup_datetime
LIMIT 5
```

```response title=Response
┌─trip_distance─┬─predicted─┬─total_amount─┐
│             1 │      4.05 │          5.5 │
│             2 │      6.79 │            8 │
│             3 │      9.53 │         10.5 │
│             4 │     12.28 │           13 │
│             5 │     15.02 │         15.5 │
└───────────────┴───────────┴──────────────┘
```

## naiveBayesClassifier {#naiveBayesClassifier}

Introduit dans : v25.11.0

Classe le texte d’entrée à l’aide d’un dictionnaire [`NAIVE_BAYES`](/fr/reference/statements/create/dictionary/layouts/naive-bayes). Renvoie la même valeur de classe prédite que `dictGet(dictionary_name, class_attribute, input_text)`, où class&#95;attribute est le nom de l’attribut de libellé de classe configuré dans le [layout](/fr/reference/statements/create/dictionary/layouts/naive-bayes#layout-parameters) du dictionnaire. Contrairement à `dictGet`, le type de résultat est toujours `UInt32` plutôt que le type déclaré de l’attribut de classe, et `input_text` doit être une `String` (aucune conversion de type de clé n’est appliquée).

<Note>
  Cette fonction est non déterministe : elle peut renvoyer des résultats différents pour les mêmes arguments.
</Note>

**Syntaxe**

```sql
naiveBayesClassifier(dictionary_name, input_text)
```

**Arguments**

* `dictionary_name` — Nom d&#39;un dictionnaire avec le layout NAIVE&#95;BAYES. [`String`](/fr/reference/data-types/string)
* `input_text` — Texte à classer. [`String`](/fr/reference/data-types/string)

**Valeur renvoyée**

ID de la classe prédite. [`UInt32`](/fr/reference/data-types/int-uint)

**Exemples**

**Classer un texte**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT naiveBayesClassifier('sentiment', 'a good and great film') AS class_id;
```

```response title=Response
┌─class_id─┐
│        0 │
└──────────┘
```

## naiveBayesClassifierWithAllProbs {#naiveBayesClassifierWithAllProbs}

Introduit dans : v26.7.0

Classe le texte d’entrée à l’aide d’un dictionnaire [`NAIVE_BAYES`](/fr/reference/statements/create/dictionary/layouts/naive-bayes) et renvoie toutes les classes avec leurs probabilités, classées de la plus probable à la moins probable.

<Note>
  Cette fonction est non-déterministe : elle peut renvoyer des résultats différents pour les mêmes arguments.
</Note>

**Syntaxe**

```sql
naiveBayesClassifierWithAllProbs(dictionary_name, input_text)
```

**Arguments**

* `dictionary_name` — Nom d’un dictionnaire utilisant le layout NAIVE&#95;BAYES. [`String`](/fr/reference/data-types/string)
* `input_text` — Texte à classer. [`String`](/fr/reference/data-types/string)

**Valeur renvoyée**

Tableau de tuples (class&#95;id, probability) triés du plus probable au moins probable. [`Array(Tuple(UInt32, Float64))`](/fr/reference/data-types/array)

**Exemples**

**Toutes les probabilités de classe**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT arrayMap(p -> (p.1, round(p.2, 4)), naiveBayesClassifierWithAllProbs('sentiment', 'a good and great film')) AS predictions;
```

```response title=Response
┌─predictions─────────────┐
│ [(0,0.9677),(1,0.0323)] │
└─────────────────────────┘
```

## naiveBayesClassifierWithProb {#naiveBayesClassifierWithProb}

Introduit dans : v26.7.0

Classe le texte d’entrée à l’aide d’un dictionnaire [`NAIVE_BAYES`](/fr/reference/statements/create/dictionary/layouts/naive-bayes) et renvoie la classe prédite ainsi que sa probabilité.

<Note>
  Cette fonction est non déterministe : elle peut renvoyer des résultats différents pour les mêmes arguments.
</Note>

**Syntaxe**

```sql
naiveBayesClassifierWithProb(dictionary_name, input_text)
```

**Arguments**

* `dictionary_name` — Nom d’un dictionnaire avec la disposition NAIVE&#95;BAYES. [`String`](/fr/reference/data-types/string)
* `input_text` — Texte à classer. [`String`](/fr/reference/data-types/string)

**Valeur renvoyée**

Tuple de (class&#95;id, probabilité). [`Tuple(UInt32, Float64)`](/fr/reference/data-types/tuple)

**Exemples**

**Classer avec probabilité**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

WITH naiveBayesClassifierWithProb('sentiment', 'a good and great film') AS p
SELECT (p.1, round(p.2, 4)) AS prediction;
```

```response title=Response
┌─prediction─┐
│ (0,0.9677) │
└────────────┘
```

## predictXGBoost {#predictXGBoost}

Introduit dans : v26.10.0

Prédit une valeur cible numérique pour un vecteur de caractéristiques à l&#39;aide d&#39;un dictionnaire [`XGBOOST`](/fr/reference/statements/create/dictionary/layouts/xgboost). Les caractéristiques sont transmises par position, dans l&#39;ordre de déclaration des colonnes de clé du dictionnaire. C&#39;est la seule façon d&#39;interroger un dictionnaire `XGBOOST` : celui-ci contient un modèle entraîné et non des lignes, si bien que l&#39;interface générique des dictionnaires (`dictGet`, `dictHas`, `SELECT * FROM dict`) n&#39;est pas prise en charge. L&#39;intégration XGBoost étant expérimentale, le paramètre `enable_xgboost` doit être activé.

**Syntaxe**

```sql
predictXGBoost(dictionary_name, feature1[, feature2, ...][, params])
```

**Arguments**

* `dictionary_name` — Nom d&#39;un dictionnaire utilisant la disposition XGBOOST. Consultez la [disposition du dictionnaire XGBOOST](/fr/reference/statements/create/dictionary/layouts/xgboost) pour savoir comment le créer et quels paramètres d&#39;entraînement il accepte. [`String`](/fr/reference/data-types/string)
* `featureN` — Valeurs numériques des caractéristiques, fournies par position dans l&#39;ordre des clés du dictionnaire. Une caractéristique NULL est transmise au modèle comme valeur manquante, que XGBoost traite selon la manière dont il a été entraîné ; la prédiction n&#39;est donc jamais NULL. [`(U)Int*`](/fr/reference/data-types/int-uint) ou [`Float*`](/fr/reference/data-types/float) ou [`Nullable((U)Int*)`](/fr/reference/data-types/nullable) ou [`Nullable(Float*)`](/fr/reference/data-types/nullable)
* `params` — Map constante facultative de paramètres de prédiction XGBoost, qui associe un nom de paramètre à une valeur entière, par exemple `map('type', 0, 'iteration_end', 0)`. Tous les paramètres acceptés sont des entiers ou des booléens ; les valeurs décimales sont donc rejetées. Consultez les [paramètres de prédiction](/fr/reference/statements/create/dictionary/layouts/xgboost#prediction-parameters) pour connaître les clés acceptées. [`Map(String, (U)Int8/16/32/64)`](/fr/reference/data-types/map)

**Valeur renvoyée**

La prédiction du modèle au format Float64, une par ligne. [`Float64`](/fr/reference/data-types/float)

**Exemples**

**Prédiction**

```sql title=Query
-- A model trained on the linear target y = 2 * x1 + 3 * x2. The XGBoost integration is experimental.
SET enable_xgboost = 1;

CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO training_data SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y FROM numbers(100);

CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(objective 'reg:squarederror' num_iterations 100 max_depth 6))
LIFETIME(0);

-- The ground truth is 2 * 1 + 3 * 2 = 8.
SELECT round(predictXGBoost('model', 1.0, 2.0), 1) AS prediction;
```

```response title=Response
┌─prediction─┐
│          8 │
└────────────┘
```

**Prédiction avec paramètres**

```sql title=Query
-- The raw margin of the model above, before the objective's transformation. For `reg:squarederror` it is the
-- prediction itself, while for `binary:logistic` it is the log-odds rather than the probability.
SELECT round(predictXGBoost('model', 1.0, 2.0, map('type', 1)), 1) AS margin;
```

```response title=Response
┌─margin─┐
│      8 │
└────────┘
```
