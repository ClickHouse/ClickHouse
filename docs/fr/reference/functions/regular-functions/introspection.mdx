Vous pouvez utiliser les fonctions décrites dans ce chapitre pour inspecter [ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format) et [DWARF](https://en.wikipedia.org/wiki/DWARF) dans le cadre du profilage des requêtes.

<Note>
  Ces fonctions sont lentes et peuvent poser des problèmes de sécurité.
</Note>

Pour que les fonctions d’introspection fonctionnent correctement :

* Installez le paquet `clickhouse-common-static-dbg`.

* Définissez le paramètre [allow&#95;introspection&#95;functions](/fr/reference/settings/session-settings/allow#allow_introspection_functions) sur 1.

  Pour des raisons de sécurité, les fonctions d’introspection sont désactivées par défaut.

ClickHouse enregistre les rapports du profileur dans la table système [trace&#95;log](/fr/reference/system-tables/trace_log). Assurez-vous que la table et le profileur sont correctement configurés.

## addressToLine {#addressToLine}

Introduit dans : v20.1.0

Convertit l&#39;adresse d&#39;une instruction située dans l&#39;exécutable ClickHouse principal en un nom de fichier et un numéro de ligne dans le code source de ClickHouse.

L&#39;adresse doit être une position dans l&#39;exécutable ClickHouse principal, c&#39;est-à-dire la forme sous laquelle les adresses sont stockées dans les colonnes `trace` de `system.trace_log`, `system.stack_trace` et `system.crash_log`, ainsi que dans la colonne `last_error_trace` de `system.error_log`.
Les adresses d&#39;exécution (mémoire virtuelle) ne sont pas acceptées, afin d&#39;empêcher que la fonction serve à déterminer la disposition de la mémoire du processus serveur.
Les cadres de pile situés hors de l&#39;exécutable principal sont stockés sous la forme `0`, et la fonction renvoie pour eux un résultat vide.

<Note>
  Cette fonction est lente et peut soulever des considérations de sécurité.
</Note>

Pour activer cette fonction d’introspection :

* Installez le paquet `clickhouse-common-static-dbg`.
* Définissez le paramètre [`allow_introspection_functions`](/fr/reference/settings/session-settings/allow#allow_introspection_functions) sur `1`.

<Note>
  Cette fonction est non déterministe : elle peut renvoyer des résultats différents pour les mêmes arguments.
</Note>

**Syntaxe**

```sql
addressToLine(address_of_binary_instruction)
```

**Arguments**

* `address_of_binary_instruction` — Position d’une instruction au sein de l’exécutable ClickHouse principal, telle que stockée dans la colonne `trace` de `system.trace_log` et de tables similaires. [`UInt64`](/fr/reference/data-types/int-uint)

**Valeur renvoyée**

Renvoie un nom de fichier de code source et un numéro de ligne séparés par deux-points, par exemple `/build/obj-x86_64-linux-gnu/../src/Common/ThreadPool.cpp:199`. Renvoie le nom du binaire si aucune information de débogage n’a été trouvée pour l’adresse, ou une chaîne vide pour `0`. [`String`](/fr/reference/data-types/string)

**Exemples**

## addressToLineWithInlines {#addressToLineWithInlines}

Introduit dans : v22.2.0

Semblable à `addressToLine`, mais renvoie un Array contenant toutes les fonctions inline.
Par conséquent, elle est plus lente que `addressToLine`.

L’adresse doit être une position au sein de l’exécutable ClickHouse principal, c’est-à-dire la forme sous laquelle les adresses sont stockées dans les colonnes `trace` de `system.trace_log`, `system.stack_trace` et `system.crash_log`, ainsi que dans la colonne `last_error_trace` de `system.error_log`.
Les adresses d’exécution (mémoire virtuelle) ne sont pas acceptées, afin que la fonction ne puisse pas servir à déterminer la disposition mémoire du processus serveur.
Les cadres de pile situés en dehors de l’exécutable principal sont stockés sous la forme `0`, et la fonction renvoie alors un résultat vide.

Pour activer cette fonction d’introspection :

* Installez le paquet `clickhouse-common-static-dbg`.
* Définissez le paramètre [`allow_introspection_functions`](/fr/reference/settings/session-settings/allow#allow_introspection_functions) sur `1`.

<Note>
  Cette fonction est non déterministe : elle peut renvoyer des résultats différents avec les mêmes arguments.
</Note>

**Syntaxe**

```sql
addressToLineWithInlines(address_of_binary_instruction)
```

**Arguments**

* `address_of_binary_instruction` — Position d’une instruction dans l’exécutable ClickHouse principal, telle que stockée dans la colonne `trace` de `system.trace_log` et des tables similaires. [`UInt64`](/fr/reference/data-types/int-uint)

**Valeur renvoyée**

Renvoie un tableau dont le premier élément est le nom du fichier source et le numéro de ligne, séparés par un deux-points. Les deuxième, troisième, etc. éléments listent les noms des fichiers source, les numéros de ligne et les noms des fonctions inline. Si aucune information de débogage n’a pu être trouvée, un tableau contenant un seul élément correspondant au nom du binaire est renvoyé ; sinon, un tableau vide est renvoyé pour `0`. [`Array(String)`](/fr/reference/data-types/array)

**Exemples**

## getQueryProfileEvent {#getQueryProfileEvent}

Introduit dans : v26.11.0

Renvoie la valeur actuelle d&#39;un [événement de profilage](/fr/reference/system-tables/events) pour la requête en cours.

La valeur est cumulée sur l&#39;ensemble des fils d’exécution qui exécutent la requête, de la même manière que dans la colonne `ProfileEvents` de `system.query_log`.
La fonction est non déterministe : elle est évaluée une fois par [bloc](/fr/resources/develop-contribute/introduction/architecture#block) de données pendant l&#39;exécution de la requête,
de sorte que toutes les lignes d&#39;un même bloc reçoivent la même valeur, et que cette valeur augmente à mesure que la requête progresse.
Elle permet ainsi d&#39;annoter la sortie ou les données insérées avec la progression de la requête, par exemple le nombre de lignes ou d&#39;octets lus jusque-là.

Dans une requête distribuée, chaque serveur renvoie la valeur correspondant à sa propre partie de la requête.
Certains événements, tels que `RealTimeMicroseconds` ou `OSReadBytes`, ne sont mis à jour que périodiquement ; leur valeur peut donc présenter un certain retard.

<Note>
  Cette fonction est non déterministe : elle peut renvoyer des résultats différents pour les mêmes arguments.
</Note>

**Syntaxe**

```sql
getQueryProfileEvent(event_name)
```
