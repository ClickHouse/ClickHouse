Permet d&#39;exécuter des requêtes `SELECT` sur les documents d&#39;un index [Elasticsearch](https://www.elastic.co/elasticsearch). Chaque document est renvoyé sous la forme d&#39;une ligne : son champ `_source` est exposé dans une colonne unique de type [JSON](/fr/reference/data-types/newjson), tandis que l&#39;identifiant du document et le nom de l&#39;index sont accessibles via des colonnes virtuelles. Cette fonction est en lecture seule.

## Syntaxe {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  L&#39;intégration Elasticsearch est expérimentale. Activez-la à l&#39;aide du paramètre [`enable_elasticsearch`](/fr/reference/settings/session-settings/enable#enable_elasticsearch) :

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## Arguments {#arguments}

| Argument       | Description                                                                                                                                                                                                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | L’URL de base du cluster Elasticsearch, par exemple `https://localhost:9200`. Il doit s’agir d’une URL `http` ou `https` sans identifiants, chaîne de requête ni fragment.                                                                                                   |
| `index`        | L’index à lire. Il peut également s’agir d’un alias, d’une liste séparée par des virgules ou d’un motif avec caractère générique, tels qu’acceptés par l’API point in time d’Elasticsearch. Un motif qui ne correspond à aucun index provoque une erreur.                    |
| `user`         | Le nom d’utilisateur pour l’authentification de base HTTP (facultatif).                                                                                                                                                                                                      |
| `password`     | Le mot de passe pour l’authentification de base HTTP (facultatif, nécessite `user`).                                                                                                                                                                                         |
| `query('...')` | Un objet [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) Elasticsearch au format JSON qui sélectionne les documents à lire (facultatif). Il doit figurer après les arguments positionnels. Valeur par défaut : `{"match_all": {}}`. |

Les arguments `url`, `index`, `user` et `password` peuvent également être fournis sous la forme `key = value`. Les arguments positionnels occupent ces emplacements dans cet ordre ; spécifier un argument à la fois par position et en tant que clé (ou spécifier deux fois la même clé) provoque une erreur.

Les arguments suivants peuvent être spécifiés sous la forme `key = value` (ou en tant que clés d’une collection nommée) :

| Clé            | Description                                                                                                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | Le nom d’utilisateur pour l’authentification de base HTTP.                                                                                                                                    |
| `password`     | Le mot de passe pour l’authentification de base HTTP.                                                                                                                                         |
| `bearer_token` | Un jeton envoyé sous la forme `Authorization: Bearer <token>`, par exemple un jeton de compte de service Elasticsearch.                                                                       |
| `api_key`      | Une API key Elasticsearch, envoyée sous la forme `Authorization: ApiKey <api_key>`. La valeur correspond à la chaîne `id:api_key` encodée en base64 renvoyée par l’API de création d’API key. |

Une collection nommée peut contenir la clé `query`. Pour la surcharger, passez `query('...')` ou `query = '...'` après le nom de la collection.

En outre, la fonction de table accepte :

| Clé         | Description                                                                                                                                                                                               |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `structure` | La structure de la table sous la forme `'name JSON'`. La structure doit contenir exactement une colonne de type `JSON` ; les noms `_id` et `_index` sont réservés. Valeur par défaut : `'document JSON'`. |

Les paramètres de lecture `keep_alive` et `page_size` peuvent être transmis dans une clause `SETTINGS` finale ; leur description figure dans la page du [table engine `Elasticsearch`](/fr/reference/engines/table-engines/integrations/elasticsearch#creating-a-table).

## Authentification {#authentication}

Vous pouvez fournir au plus une méthode d’authentification :

1. **Authentification de base**. Transmettez `user` et `password`.
2. **Jeton Bearer**. Transmettez `bearer_token`.
3. **API key**. Transmettez `api_key`.

Si aucune d’entre elles n’est fournie, la requête est envoyée de manière anonyme, ce qui ne fonctionne que si la sécurité est désactivée dans Elasticsearch.

Stockez les identifiants dans une [collection nommée](/fr/concepts/features/configuration/server-config/named-collections) pour éviter de devoir les spécifier dans chaque requête. Une table permanente créée à partir d’une collection nommée (avec le table engine `Elasticsearch` ou `CREATE TABLE ... AS elasticsearch(...)`) est enregistrée comme dépendance de cette collection : `DROP NAMED COLLECTION` est donc bloqué tant que la table existe.

## Colonnes virtuelles {#virtual-columns}

* `_id` — L&#39;identifiant du document. Type : `String`.
* `_index` — Le nom de l&#39;index depuis lequel le document a été lu. Type : `LowCardinality(String)`.

Lorsqu&#39;une requête ne lit que des colonnes virtuelles, le champ `_source` du document n&#39;est pas demandé à Elasticsearch. Un index qui ne stocke pas `_source` (le champ `_source` est désactivé dans son mapping) n&#39;est lisible qu&#39;au travers des colonnes virtuelles : une requête qui lit la colonne `JSON` d&#39;un tel index échoue avec une erreur au lieu de renvoyer des documents vides.

## Exemples {#examples}

Compter les documents d&#39;un index :

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

Lisez les champs des documents sous forme de sous-colonnes de la colonne `JSON` :

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

Filtrez côté Elasticsearch à l&#39;aide d&#39;un objet Query DSL et ajustez la taille de page :

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

Utilisation d&#39;une collection nommée :

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## Limitations {#limitations}

* La fonction est en lecture seule ; `INSERT` n&#39;est pas pris en charge.
* Les prédicats ne sont pas appliqués en amont. Une condition `WHERE` est appliquée dans ClickHouse après le téléchargement des documents ; utilisez l&#39;argument `query` pour filtrer côté Elasticsearch.
* La `query` est envoyée avec la `size` d&#39;une page. Une requête dont le résultat dépend de `size`, comme une requête `knn` sans `k`, renvoie un ensemble de documents qui dépend de `page_size`. Spécifiez explicitement ces paramètres.
* Chaque page correspond à une requête de recherche distincte, et Elasticsearch réévalue à chaque requête les expressions de calcul de dates telles que `now-1h` présentes dans la `query`. Le point in time fige les documents, mais pas l&#39;horloge : une `query` dépendante du temps peut donc ignorer silencieusement des documents situés près de la frontière mouvante. Utilisez des dates absolues dans la `query`.
* Chaque lecture ouvre un point in time, parcourt les résultats page par page avec `search_after` en les triant par `_shard_doc`, puis ferme le point in time à la fin. Une requête de page qui échoue sur l&#39;un des shards, ou qui expire dans Elasticsearch, lève une erreur au lieu de renvoyer des résultats partiels.
* Elasticsearch 7.12 ou une version ultérieure est requis : la fonction s&#39;appuie sur l&#39;API point in time et sur le champ de tri `_shard_doc` ; les versions antérieures et OpenSearch rejettent donc la première requête.
* `page_size` ne peut pas dépasser la valeur du paramètre d&#39;index `index.max_result_window` d&#39;Elasticsearch (`10000` par défaut).
