Représente le dictionnaire d’un index de texte intégral dans les tables MergeTree.
Renvoyer les tokens avec leurs métadonnées de posting list.
Peut être utilisé pour l’introspection.

## Syntaxe {#syntax}

```sql
mergeTreeTextIndex(database, table, index_name)
```

## Arguments {#arguments}

| Argument     | Description                                                                 |
| ------------ | --------------------------------------------------------------------------- |
| `database`   | Le nom de la base de données où se trouve l’index de texte intégral à lire. |
| `table`      | Le nom de la table où se trouve l’index de texte intégral à lire.           |
| `index_name` | Le nom de l’index de texte intégral à lire.                                 |

## Valeur retournée {#returned-value}

Un objet table contenant les jetons et leurs métadonnées de liste de postings.

Si l’index utilise le tokeniseur `keyValuePairs`, chaque jeton correspond à une paire `(key, value)` d’une colonne `Map`. Le résultat comporte alors deux colonnes supplémentaires, `token_key` et `token_value`, qui contiennent les parties décodées du jeton.

Les listes de postings des jetons sont renvoyées dans les colonnes virtuelles suivantes. Elles ne sont pas renvoyées par `SELECT *` et doivent être sélectionnées explicitement.

| Colonne     | Type            | Description                                                                                                                  |
| ----------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `row_id`    | `UInt32`        | Le numéro d’une ligne de la part (voir `_part_offset`) figurant dans la liste de postings du jeton.                          |
| `positions` | `Array(UInt32)` | Les positions du jeton dans la ligne. Présente uniquement si l’index est défini avec l’argument `support_phrase_search = 1`. |

Si l’une de ces colonnes est sélectionnée, le résultat comporte une ligne pour chaque ligne de la liste de postings de chaque jeton, à la manière d’un `ARRAY JOIN` sur la liste de postings : les autres colonnes du jeton sont répétées sur chacune de ces lignes.

Les listes de postings sont renvoyées telles qu’elles sont stockées dans l’index de la part : elles incluent donc les lignes supprimées par un `DELETE` léger (voir `_row_exists`) tant que la part n’a pas été fusionnée.

## Exemple d’utilisation {#usage-example}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha)
)
ENGINE = MergeTree
ORDER BY id;

INSERT INTO tab SELECT number, concatWithSeparator(' ', 'apple', 'banana') FROM numbers(500);
INSERT INTO tab SELECT 500 + number, concatWithSeparator(' ', 'cherry', 'date') FROM numbers(500);

SELECT * FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s);
```

## Exemple d’utilisation : listes de postings {#usage-example-posting-lists}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha, support_phrase_search = 1)
)
ENGINE = MergeTree
ORDER BY id
SETTINGS allow_experimental_text_index_phrase_search = 1;

INSERT INTO tab VALUES (0, 'apple banana apple'), (1, 'banana cherry'), (2, 'cherry apple');

SELECT token, row_id, positions FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s) ORDER BY token, row_id;
```

```text title="Response"
   ┌─token──┬─row_id─┬─positions─┐
1. │ apple  │      0 │ [0,2]     │
2. │ apple  │      2 │ [1]       │
3. │ banana │      0 │ [1]       │
4. │ banana │      1 │ [0]       │
5. │ cherry │      1 │ [1]       │
6. │ cherry │      2 │ [0]       │
   └────────┴────────┴───────────┘
```
