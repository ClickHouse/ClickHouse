Fournit une interface de type table en lecture seule pour les tables Apache [Paimon](https://paimon.apache.org/) stockées dans Amazon S3, Azure, HDFS ou en local.

## Syntaxe {#syntax}

```sql
paimon(url [,access_key_id, secret_access_key] [,format] [,structure] [,compression] [,extra_credentials])

paimonS3(url [,access_key_id, secret_access_key] [,format] [,structure] [,compression] [,extra_credentials])

paimonAzure(connection_string|storage_account_url, container_name, blobpath, [,account_name], [,account_key] [,format] [,compression_method])

paimonHDFS(path_to_table, [,format] [,compression_method])

paimonLocal(path_to_table, [,format] [,compression_method])
```

## Arguments {#arguments}

La description de ces arguments correspond à celle des arguments des fonctions de table `s3`, `azureBlobStorage`, `HDFS` et `file`, respectivement.
`format` désigne le format des data files de la table Paimon.

Pour `paimonS3`, vous pouvez utiliser le paramètre facultatif `extra_credentials` pour transmettre un `role_arn` afin d&#39;activer un accès basé sur les rôles dans ClickHouse Cloud. Voir [Secure S3](/fr/products/cloud/guides/data-sources/accessing-s3-data-securely) pour les étapes de configuration.

### Valeur renvoyée {#returned-value}

Une table ayant la structure spécifiée, permettant de lire les données de la table Paimon indiquée.

## Limitations {#limitations}

La fusion à la lecture (merge-on-read) n&#39;étant pas implémentée, une table à clé primaire n&#39;est lue que dans les cas où Paimon la lit sans fusion : un bucket est
lu lorsque tous ses fichiers de données se trouvent au-dessus du niveau 0, sont réputés ne contenir aucune ligne de rétractation et se trouvent tous dans un même niveau. Avec
`deletion-vectors.enabled` ou `'merge-engine' = 'first-row'`, les fichiers peuvent se répartir sur plusieurs niveaux et, sauf si
`batch-scan-mode` est défini sur un mode autre que `none`, les fichiers de niveau 0 ne sont pas lus tant qu&#39;ils n&#39;ont pas été compactés, comme dans Paimon.
La lecture de tout autre bucket lève une exception ; un compactage complet dans Paimon (`compact_strategy => 'full'`) le rend lisible.

Les vecteurs de suppression n&#39;étant pas appliqués, **les snapshots comportant des vecteurs de suppression ne peuvent pas être lus** : l&#39;ensemble de résultats contiendrait encore
les lignes supprimées par des instructions `DELETE` et `UPDATE` ultérieures. La lecture d&#39;un snapshot dont le manifest d&#39;index référence
des vecteurs de suppression lève donc une exception, même après la désactivation de `deletion-vectors.enabled`.
Un compactage complet dans Paimon (`compact_strategy => 'full'`) applique les vecteurs de suppression ; les snapshots créés ensuite
peuvent alors de nouveau être lus.

Chaque fichier de données est lu avec le schéma utilisé lors de son écriture, et ses colonnes de premier niveau sont mises en correspondance avec le schéma actuel via
l&#39;identifiant de champ Paimon : les colonnes renommées, ainsi que les colonnes supprimées puis rajoutées sous le même nom, sont donc lues comme dans Spark.

Les champs d&#39;une colonne `ROW` sont mis en correspondance avec les fichiers de données par nom, et non par identifiant de champ Paimon. Par conséquent, **les fichiers de données écrits avant qu&#39;un
champ d&#39;une colonne `ROW` soit renommé, ou avant qu&#39;un tel champ soit supprimé puis remplacé par un autre portant le même nom (comparé
sans tenir compte de la casse), ne peuvent pas être lus** : l&#39;ensemble de résultats contiendrait `NULL` pour le champ renommé et les valeurs du champ
supprimé pour le champ rajouté. La lecture d&#39;un tel fichier de données lève donc une exception. L&#39;ajout et la suppression de champs sont pris en charge.
Réécrire la table avec le schéma actuel dans Paimon, par exemple avec `INSERT OVERWRITE <table> SELECT * FROM <table>`,
rend lisibles les snapshots créés ensuite.

## Définir une collection nommée {#defining-a-named-collection}

Voici un exemple de configuration d&#39;une collection nommée pour stocker l&#39;URL et les informations d&#39;authentification :

```xml
<clickhouse>
    <named_collections>
        <paimon_conf>
            <url>http://test.s3.amazonaws.com/clickhouse-bucket/</url>
            <access_key_id>test</access_key_id>
            <secret_access_key>test</secret_access_key>
            <format>auto</format>
            <structure>auto</structure>
        </paimon_conf>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM paimonS3(paimon_conf, filename = 'test_table')
DESCRIBE paimonS3(paimon_conf, filename = 'test_table')
```

## Alias {#aliases}

La fonction de table `paimon` est désormais un alias de `paimonS3`.

## Colonnes virtuelles {#virtual-columns}

* `_path` — Chemin du fichier. Type : `LowCardinality(String)`.
* `_file` — Nom du fichier. Type : `LowCardinality(String)`.
* `_size` — Taille du fichier en octets. Type : `Nullable(UInt64)`. Si la taille du fichier est inconnue, la valeur est `NULL`.
* `_time` — Date et heure de dernière modification du fichier. Type : `Nullable(DateTime)`. Si la date et l’heure sont inconnues, la valeur est `NULL`.
* `_etag` — ETag du fichier. Type : `LowCardinality(String)`. Si l’ETag est inconnu, la valeur est `NULL`.
