Le moteur `Elasticsearch` permet de lire les documents d&#39;un index [Elasticsearch](https://www.elastic.co/elasticsearch). Chaque document est renvoyé sous la forme d&#39;une ligne : son `_source` est exposé dans une seule colonne de type [JSON](/fr/reference/data-types/newjson), tandis que l&#39;identifiant du document et le nom de l&#39;index sont disponibles sous forme de colonnes virtuelles.

Le moteur fonctionne en lecture seule. Les documents sont récupérés par pages via l&#39;API `_search`, à l&#39;aide d&#39;un [point in time](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results#search-after), afin qu&#39;une requête dispose d&#39;un snapshot cohérent de l&#39;index, même si celui-ci est modifié en cours de lecture.

Elasticsearch 7.12 ou une version ultérieure est requis : le moteur s&#39;appuie sur l&#39;API point in time et sur le champ de tri `_shard_doc`. OpenSearch n&#39;est pas pris en charge, car il ne dispose pas du champ `_shard_doc`. Un serveur plus ancien rejette la première requête avec une erreur.

## Créer une table {#creating-a-table}

```sql
CREATE TABLE [IF NOT EXISTS] [db.]table_name
[(
    name1 JSON
)]
ENGINE = Elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...])
[SETTINGS keep_alive = 60, page_size = 10000]
```

<Note>
  L&#39;intégration Elasticsearch est expérimentale. Activez-la avec le paramètre [`enable_elasticsearch`](/fr/reference/settings/session-settings/enable#enable_elasticsearch) :

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

La liste de colonnes est facultative. Si elle est omise, la table comporte une seule colonne `document` de type `JSON`. Si elle est spécifiée, elle doit contenir exactement une colonne, de type `JSON`, éventuellement assortie d&#39;indications de type et de chemins ignorés. Les colonnes `MATERIALIZED`, `ALIAS` et `EPHEMERAL` ne sont pas prises en charge, et les noms `_id` et `_index` sont réservés aux colonnes virtuelles.

**Paramètres du moteur**

* `url` — L&#39;URL de base du cluster Elasticsearch, par exemple `https://localhost:9200`. Il doit s&#39;agir d&#39;une URL `http` ou `https` sans identifiants, chaîne de requête ni fragment.
* `index` — L&#39;index à lire. Il peut également s&#39;agir d&#39;un alias, d&#39;un flux de données, d&#39;une liste séparée par des virgules, d&#39;un motif générique ou d&#39;une expression de calcul de date telle que `<logs-{now/d}>`, conformément à ce qu&#39;accepte l&#39;API point in time d&#39;Elasticsearch. La valeur correspond au nom littéral et ne doit pas être encodée pour les URL. Un motif qui ne correspond à aucun index provoque une erreur.
* `user`, `password` — Identifiants facultatifs pour l&#39;authentification de base HTTP.
* `query('...')` — Objet [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) Elasticsearch facultatif, au format JSON, qui sélectionne les documents à lire. Il doit suivre les arguments positionnels. Valeur par défaut : `{"match_all": {}}`.

Les paramètres peuvent également être transmis sous forme de [collection nommée](/fr/concepts/features/configuration/server-config/named-collections), avec des surcharges `key = value`. Consultez la [fonction de table `elasticsearch`](/fr/reference/functions/table-functions/elasticsearch#arguments) pour la liste complète des clés et la description des [méthodes d’authentification](/fr/reference/functions/table-functions/elasticsearch#authentication).

**Paramètres du moteur**

| Paramètre    | Valeur par défaut | Description                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------ | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keep_alive` | `60`              | Durée, en secondes, pendant laquelle Elasticsearch maintient le point in time ouvert entre deux requêtes de page consécutives.                                                                                                                                                                                                                                                                                            |
| `page_size`  | `10000`           | Nombre de documents demandés à Elasticsearch par requête. Chaque page correspond à un bloc ; ce paramètre détermine donc également la taille de bloc de la lecture, et [`max_block_size`](/fr/reference/settings/session-settings/max#max_block_size) reste sans effet. Les valeurs supérieures au paramètre d&#39;index `index.max_result_window` d&#39;Elasticsearch (`10000` par défaut) sont rejetées par Elasticsearch. |

Ces paramètres ne peuvent pas être modifiés avec `ALTER TABLE ... MODIFY SETTING`. Pour les modifier, recréez la table.

## Colonnes virtuelles {#virtual-columns}

* `_id` — L&#39;identifiant du document. Type : `String`.
* `_index` — Le nom de l&#39;index dans lequel le document a été lu. Type : `LowCardinality(String)`.

Lorsqu&#39;une requête ne lit que des colonnes virtuelles, le champ `_source` du document n&#39;est pas demandé à Elasticsearch. Un index qui ne stocke pas `_source` (le champ `_source` est désactivé dans son mapping) ne peut être lu qu&#39;au moyen des colonnes virtuelles : une requête qui lit la colonne `JSON` d&#39;un tel index échoue en renvoyant une erreur plutôt que des documents vides.

## Exemple d’utilisation {#usage-example}

```sql
CREATE TABLE logs
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*', 'elastic', 'changeme')
SETTINGS page_size = 5000;

SELECT _index, _id, document.message
FROM logs
WHERE document.level = 'error'
LIMIT 10;
```

Filtrez côté Elasticsearch à l&#39;aide d&#39;un objet Query DSL :

```sql
CREATE TABLE errors_since_october
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*',
                       query('{"bool": {"filter": [{"term": {"level": "error"}}, {"range": {"@timestamp": {"gte": "2026-10-01T00:00:00Z"}}}]}}'),
                       api_key = '...');
```

Utilisez des dates absolues dans le paramètre `query` : les calculs de date tels que `now-1h` sont réévalués à chaque page, ce qui peut entraîner l&#39;omission de certains documents. Consultez les [limitations de la fonction de table `elasticsearch`](/fr/reference/functions/table-functions/elasticsearch#limitations).
