Permet d&#39;exécuter plusieurs instructions en parallèle.

## Syntaxe {#syntax}

```sql
statement1 PARALLEL WITH statement2 [PARALLEL WITH statement3 ...]
```

Exécute les statements `statement1`, `statement2`, `statement3`, ... en parallèle. Seuls les statements qui ne renvoient pas d&#39;ensemble de résultats et n&#39;attendent pas de données en entrée peuvent être combinés ; voir [Restrictions](#restrictions).

Dans de nombreux cas, l&#39;exécution de statements en parallèle peut être plus rapide qu&#39;une simple suite des mêmes statements. Par exemple, `statement1 PARALLEL WITH statement2 PARALLEL WITH statement3` sera probablement plus rapide que `statement1; statement2; statement3`.

## Exemples {#examples}

Crée deux tables en parallèle :

```sql
CREATE TABLE table1(x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2(y String) ENGINE = MergeTree ORDER BY tuple();
```

Supprime deux tables en parallèle :

```sql
DROP TABLE table1
PARALLEL WITH
DROP TABLE table2;
```

## Restrictions {#restrictions}

Un statement qui renvoie un ensemble de résultats, comme `SELECT`, ou qui attend des données en entrée est rejeté avec l&#39;erreur `INCORRECT_QUERY`.

Une instruction DDL exécutée avec [`ON CLUSTER`](/fr/reference/statements/distributed-ddl) ou via le journal DDL d&#39;une base de données [`Replicated`](/fr/reference/engines/database-engines/replicated) renvoie une table de statut : elle est donc rejetée elle aussi, mais seulement après avoir été envoyée aux hôtes, qui l&#39;exécutent malgré tout. Elle peut toutefois être combinée si [`distributed_ddl_output_mode`](/fr/reference/settings/session-settings/distributed-ddl#distributed_ddl_output_mode) vaut `none` ou `none_only_active` :

```sql
SET distributed_ddl_output_mode = 'none';

CREATE TABLE table1 ON CLUSTER default (x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2 ON CLUSTER default (y String) ENGINE = MergeTree ORDER BY tuple();
```

## Paramètres {#settings}

Le paramètre [max&#95;threads](/fr/reference/settings/session-settings/max-threads#max_threads) détermine le nombre de threads créés.

## Comparaison avec UNION {#comparison-with-union}

La clause `PARALLEL WITH` présente quelques similitudes avec [UNION](/fr/reference/statements/select/union), qui exécute lui aussi ses opérandes en parallèle. Il existe toutefois quelques différences :

* `PARALLEL WITH` ne renvoie aucun résultat issu de l’exécution de ses opérandes ; il peut seulement relancer une exception provenant de l’un d’eux, le cas échéant ;
* `PARALLEL WITH` combine des statements qui ne renvoient pas d’ensemble de résultats et n’attendent aucune donnée en entrée, tandis que `UNION` combine des requêtes `SELECT`.
