La clause `SHUFFLE` renvoie les lignes du résultat de la requête dans un ordre aléatoire uniforme. Elle s&#39;utilise à la place de la clause [ORDER BY](/fr/reference/statements/select/order-by) et ne peut pas être combinée avec celle-ci.

Elle renvoie le même résultat que `ORDER BY rand()`, mais s&#39;exécute en temps O(n) au lieu de O(n * log(n)).

`SHUFFLE` peut s&#39;utiliser sans `LIMIT`, pour mélanger aléatoirement toutes les lignes, ou avec `LIMIT n`, pour prélever un échantillon aléatoire uniforme de `n` lignes (elles aussi renvoyées dans un ordre aléatoire). Avec `LIMIT n`, chaque flux ne conserve que `n` lignes : l&#39;utilisation de la mémoire est donc en O(n), quel que soit le nombre de lignes du résultat de la requête. `OFFSET` et `LIMIT BY` s&#39;utilisent de la même manière qu&#39;avec `ORDER BY`.

<Note>
  Il s&#39;agit d&#39;une fonctionnalité expérimentale. Activez-la à l&#39;aide du paramètre [`allow_experimental_shuffle_query`](/fr/reference/settings/session-settings#allow_experimental_shuffle_query).
</Note>

## Détails d’Implémentation {#implementation-details}

Les choix aléatoires sont effectués à la volée : aucune valeur aléatoire n’est générée ni stockée à l’avance pour les lignes. Sans `LIMIT`, chaque ligne est envoyée vers l’un des `max_threads` flux, choisi au hasard, chaque flux est mélangé en parallèle à l’aide de l’algorithme de Fisher-Yates (par blocs qui tiennent dans le cache du CPU), puis les flux sont concaténés. Avec `LIMIT n`, chaque flux conserve un échantillon uniformément aléatoire de `n` lignes par échantillonnage par réservoir, qui ignore sans les examiner les lignes ne pouvant pas entrer dans l’échantillon, puis les échantillons sont fusionnés : le nombre de lignes prélevées dans chaque flux est tiré par échantillonnage sans remise parmi les nombres de lignes des flux. Dans une requête distribuée, les serveurs distants mélangent leurs données et associent aux lignes des clés aléatoires triées, puis l’initiateur fusionne les flux mélangés selon ces clés, ce qui ne requiert qu’une mémoire en O(1).

Sans `LIMIT`, `SHUFFLE` conserve toutes les lignes en mémoire. Contrairement à `ORDER BY`, il ne déverse pas les données sur disque.

`ORDER BY rand()` et `ORDER BY rand64()` peuvent être exécutés de la même manière que `SHUFFLE` (paramètre `query_plan_use_shuffle_for_order_by_rand`) lorsque la valeur aléatoire n’est utilisée nulle part ailleurs dans la requête et que le tri externe est désactivé. Lorsque le tri externe est configuré, cette optimisation est désactivée même avec une `LIMIT` finie, car l’échantillon peut malgré tout dépasser la mémoire disponible et `SHUFFLE` ne peut pas déverser sur disque. `ORDER BY rand64()` avec une limite finie conserve le tri afin de préserver tous les bits des valeurs aléatoires.

## Exemples {#examples}

```sql
SET allow_experimental_shuffle_query = 1;

SELECT number FROM numbers(5) SHUFFLE;
```

```text
┌─number─┐
│      3 │
│      0 │
│      4 │
│      1 │
│      2 │
└────────┘
```

Un échantillon aléatoire de trois lignes :

```sql
SELECT number FROM numbers(1000000) SHUFFLE LIMIT 3;
```

```text
┌─number─┐
│ 493721 │
│  20857 │
│ 871324 │
└────────┘
```

Après la clause `FROM`, `SHUFFLE` est interprété comme un mot-clé. Pour utiliser `shuffle` comme alias de table, écrivez `AS shuffle`.
