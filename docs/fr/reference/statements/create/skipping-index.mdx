Introduit dans : v22.7.0

Ajoute un [index de saut de données](/fr/reference/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-data_skipping-indexes) à une table de la famille `MergeTree`. Il s&#39;agit d&#39;une forme autonome de [`ALTER TABLE ... ADD INDEX`](/fr/reference/statements/alter/skipping-index#add-index), qui requiert le même privilège `ALTER ADD INDEX`.

## Syntaxe {#syntax}

```sql
CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [db.]table [ON CLUSTER cluster] expression TYPE type [GRANULARITY value]
```

* `expression` - l’expression indexée, éventuellement entre parenthèses. Une liste entre parenthèses `(expr1, expr2, ...)` crée un seul index portant sur toutes les expressions, comme le fait `INDEX name (expr1, expr2, ...)` dans `CREATE TABLE`.
* `TYPE type [GRANULARITY value]` - comme dans la clause `INDEX` de `CREATE TABLE` ; voir [types d’index de saut](/fr/reference/engines/table-engines/mergetree-family/mergetree#skip-index-types).
* `IF NOT EXISTS` - si la table possède déjà un index nommé `name`, la requête est sans effet.

Comme `ADD INDEX`, ce statement ne modifie que les métadonnées de la table. Pour construire l’index sur les données déjà présentes dans la table, exécutez [`ALTER TABLE ... MATERIALIZE INDEX`](/fr/reference/statements/alter/skipping-index#materialize-index).

## Compatibilité SQL {#sql-compatibility}

Pour assurer la compatibilité avec d&#39;autres systèmes de base de données :

* `ASC` et `DESC` placés après les expressions d&#39;une liste entre parenthèses sont ignorés.
* `CREATE UNIQUE INDEX` est rejeté, sauf si [`create_index_ignore_unique`](/fr/reference/settings/session-settings/create#create_index_ignore_unique) vaut `1`. Dans ce cas, `UNIQUE` est ignoré et un index ordinaire est créé.
* `CREATE INDEX` sans `TYPE` est rejeté, sauf si [`allow_create_index_without_type`](/fr/reference/settings/session-settings/allow#allow_create_index_without_type) vaut `1`. Dans ce cas, la requête n&#39;a aucun effet.

## Exemple {#example}

```sql title="Query"
CREATE TABLE t (id UInt64, s String) ENGINE = MergeTree ORDER BY id;
INSERT INTO t SELECT number, toString(number) FROM numbers(1000);
CREATE INDEX idx_s ON t (s) TYPE bloom_filter GRANULARITY 1;
ALTER TABLE t MATERIALIZE INDEX idx_s SETTINGS mutations_sync = 1;
SELECT name, type, expr, granularity FROM system.data_skipping_indices WHERE database = currentDatabase() AND table = 't';
```

```text title="Response"
┌─name──┬─type─────────┬─expr─┬─granularity─┐
│ idx_s │ bloom_filter │ s    │           1 │
└───────┴──────────────┴──────┴─────────────┘
```
