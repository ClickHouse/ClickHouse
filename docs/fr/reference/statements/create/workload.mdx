Introduit dans : v24.11.0

Crée une charge de travail : un nœud de la hiérarchie utilisée par la [planification des charges de travail](/fr/concepts/features/configuration/server-config/workload-scheduling) pour répartir les ressources entre les charges de travail. Les ressources à planifier sont créées avec [`CREATE RESOURCE`](/fr/reference/statements/create/resource).

## Syntaxe {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - remplace la définition d’une charge de travail existante. Ne peut pas être combiné avec `IF NOT EXISTS`.
* `IF NOT EXISTS` - si une charge de travail nommée `name` existe déjà, la requête n’a aucun effet.
* `IN parent_name` - crée la charge de travail en tant qu’enfant de la charge de travail `parent_name`. Une charge de travail définie sans `IN` est une charge de travail racine. Tout cycle de charges de travail est rejeté.
* `SETTINGS` - paramètres d’ordonnancement de la charge de travail, par exemple `weight`, `priority`, `max_concurrent_threads` ou `max_bytes_per_second`, décrits dans [Hiérarchie des charges de travail](/fr/concepts/features/configuration/server-config/workload-scheduling#workloads). Un paramètre suivi de `FOR resource_name` s’applique uniquement à cette ressource ; sinon, il s’applique à toutes les ressources. Un paramètre inconnu provoque une erreur.

Les charges de travail et les ressources disposent d’espaces de noms distincts : une charge de travail et une ressource peuvent donc porter le même nom. Une requête s’exécute dans la charge de travail désignée par son paramètre [`workload`](/fr/reference/settings/session-settings/other#workload) ; voir [Marquage des workloads](/fr/concepts/features/configuration/server-config/workload-scheduling#workload-markup).

<Note>
  La planification des réservations de mémoire est expérimentale : cela concerne la ressource `MEMORY RESERVATION` et les paramètres de charge de travail `max_memory`, `max_memory_ratio`, `max_memory_before_spill` et `max_memory_to_spill_ratio`. Voir [Réservations de mémoire](/fr/concepts/features/configuration/server-config/workload-scheduling#memory-reservations).
</Note>

## Stockage {#storage}

Les charges de travail sont stockées sur disque dans [`workload_path`](/fr/reference/settings/server-settings/settings/workload#workload_path), ou dans ZooKeeper à l&#39;emplacement [`workload_zookeeper_path`](/fr/reference/settings/server-settings/settings/workload#workload_zookeeper_path) si ce paramètre est défini. Avec le stockage ZooKeeper, la clause `ON CLUSTER` est rejetée, car les définitions sont répliquées automatiquement. Les charges de travail [définies dans la configuration du serveur](/fr/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads) ne peuvent être ni remplacées ni supprimées en SQL. La table [`system.workloads`](/fr/reference/system-tables/workloads) répertorie les charges de travail.

## Privilèges {#privileges}

`CREATE WORKLOAD` nécessite le privilège `CREATE WORKLOAD`. `CREATE OR REPLACE WORKLOAD` requiert en outre le privilège `DROP WORKLOAD`.

## Exemple {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
