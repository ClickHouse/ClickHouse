Introduit dans : v24.11.0

Crée une ressource pour la [planification des charges de travail](/fr/concepts/features/configuration/server-config/workload-scheduling) : un type d&#39;accès, tel que les lectures sur disque ou le temps CPU, dont l&#39;utilisation est répartie entre les charges de travail créées avec [`CREATE WORKLOAD`](/fr/reference/statements/create/workload).

## Syntaxe {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`, `IF NOT EXISTS` et `ON CLUSTER` fonctionnent comme dans [`CREATE WORKLOAD`](/fr/reference/statements/create/workload#syntax).

## Modes d’accès {#access-modes}

| Mode d’accès                                  | Accès planifié                                                                                                                                                                      | Introduit dans |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | Lectures ou écritures sur le disque `disk_name`, voir [Ressources](/fr/concepts/features/configuration/server-config/workload-scheduling#resources)                                    | v24.11.0       |
| `READ ANY DISK`, `WRITE ANY DISK`             | Lectures ou écritures sur n’importe quel disque                                                                                                                                     | v24.11.0       |
| `MASTER THREAD`, `WORKER THREAD`              | CPU, voir [Ordonnancement du CPU](/fr/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)                                                                | v25.4.0        |
| `QUERY`                                       | Créneaux d’exécution des requêtes, voir [Ordonnancement des créneaux d’exécution des requêtes](/fr/concepts/features/configuration/server-config/workload-scheduling#query_scheduling) | v25.6.0        |
| `MEMORY RESERVATION`                          | Mémoire, voir [Réservations de mémoire](/fr/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)                                                     | v26.6.2        |

Les modes d’accès d’une même ressource doivent tous être du même type : disque, fils d’exécution CPU, `QUERY` ou `MEMORY RESERVATION`. Chacun des modes `MASTER THREAD`, `WORKER THREAD`, `QUERY` et `MEMORY RESERVATION` ne peut appartenir qu’à une seule ressource au maximum. `CREATE OR REPLACE RESOURCE` ne permet pas de modifier le type d’une ressource : supprimez-la, puis recréez-la.

<Note>
  `MEMORY RESERVATION` est expérimental : sa syntaxe SQL et son comportement sont susceptibles d’évoluer dans les versions futures.
</Note>

## Stockage {#storage}

Les ressources sont stockées de la même manière que les charges de travail ; voir [Stockage](/fr/reference/statements/create/workload#storage). La table [`system.resources`](/fr/reference/system-tables/resources) répertorie les ressources.

## Privilèges {#privileges}

`CREATE RESOURCE` nécessite le privilège `CREATE RESOURCE`. `CREATE OR REPLACE RESOURCE` nécessite en outre le privilège `DROP RESOURCE`.

## Exemple {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
