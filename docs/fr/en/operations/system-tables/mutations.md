<div id="description">
  ## Description
</div>

Cette table contient des informations sur les [mutations](/fr/sql-reference/statements/alter/index.md#mutations) des tables [MergeTree](/fr/engines/table-engines/mergetree-family/mergetree.md) ainsi que sur leur progression. Chaque commande de mutation est représentée par une seule ligne.

<div id="columns">
  ## Colonnes :
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/fr/sql-reference/data-types/string)) — Le nom de la base de données à laquelle la mutation a été appliquée.
* `table` ([String](/fr/sql-reference/data-types/string)) — Le nom de la table à laquelle la mutation a été appliquée.
* `mutation_id` ([String](/fr/sql-reference/data-types/string)) — L’ID de la mutation. Pour les tables répliquées, ces ID correspondent aux noms de znode dans le répertoire `<table_path_in_clickhouse_keeper>/mutations/` de ClickHouse Keeper. Pour les tables non répliquées, les ID correspondent aux noms de fichier dans le répertoire de données de la table.
* `command` ([String](/fr/sql-reference/data-types/string)) — La chaîne de commande de la mutation (la partie de la requête après ALTER TABLE [db.]table).
* `create_time` ([DateTime](/fr/sql-reference/data-types/datetime)) — La date et l’heure auxquelles la commande de mutation a été soumise à l’exécution.
* `block_numbers.partition_id` ([Array(String)](/fr/sql-reference/data-types/array)) — Pour les mutations de tables répliquées, le tableau contient les ID des partitions (un enregistrement pour chaque partition). Pour les mutations de tables non répliquées, le tableau est vide.
* `block_numbers.number` ([Array(Int64)](/fr/sql-reference/data-types/array)) — Pour les mutations de tables répliquées, le tableau contient un enregistrement pour chaque partition, avec le numéro de bloc obtenu par la mutation. Seules les parties contenant des blocs dont le numéro est inférieur à cette valeur seront mutées dans la partition. Dans les tables non répliquées, les numéros de bloc de toutes les partitions forment une seule séquence. Cela signifie que, pour les mutations de tables non répliquées, la colonne contiendra un enregistrement avec un seul numéro de bloc obtenu par la mutation.
* `parts_in_progress_names` ([Array(String)](/fr/sql-reference/data-types/array)) — Un tableau contenant les noms des parties de données en cours de mutation.
* `parts_to_do_names` ([Array(String)](/fr/sql-reference/data-types/array)) — Un tableau contenant les noms des parties de données qui doivent être mutées pour que la mutation se termine.
* `parts_to_do` ([Int64](/fr/sql-reference/data-types/int-uint)) — Le nombre de parties de données qui doivent être mutées pour que la mutation se termine. Remarque : même si `parts_to_do` = 0, la mutation d’une table répliquée peut ne pas être encore terminée en raison d’un INSERT de longue durée qui crée une nouvelle partie de données devant être mutée.
* `parts_postpone_reasons` ([Map(String, String)](/fr/sql-reference/data-types/map)) — Une map associant les noms des parties aux raisons pour lesquelles elles sont reportées.
* `is_done` ([UInt8](/fr/sql-reference/data-types/int-uint)) — Indique si la mutation est terminée ou non. Valeurs possibles : 1 si la mutation est terminée, 0 si la mutation est toujours en cours.
* `is_killed` ([UInt8](/fr/sql-reference/data-types/int-uint)) — Indique si une mutation a été arrêtée. Disponible uniquement dans ClickHouse Cloud. Remarque : is&#95;killed=1 ne signifie pas nécessairement que la mutation est entièrement finalisée. Il est possible qu’une mutation reste pendant une longue période dans un état où is&#95;killed=1 et is&#95;done=0. Cela peut se produire si une autre mutation de longue durée bloque la mutation arrêtée. Il s’agit d’une situation ordinaire.
* `latest_failed_part` ([String](/fr/sql-reference/data-types/string)) — Le nom de la partie la plus récente qui n’a pas pu être mutée.
* `latest_fail_time` ([DateTime](/fr/sql-reference/data-types/datetime)) — La date et l’heure du dernier échec de mutation d’une partie.
* `latest_fail_reason` ([String](/fr/sql-reference/data-types/string)) — Le message d’exception à l’origine du dernier échec de mutation d’une partie.
* `latest_fail_error_code_name` ([String](/fr/sql-reference/data-types/string)) — Le code d’erreur de l’exception à l’origine du dernier échec de mutation d’une partie.

{/*AUTOGENERATED_END*/ }

:::note

* Si un nom de partie ne figure pas dans `parts_postpone_reasons` et n&#39;a pas encore été muté, cela signifie que la partie n&#39;est pas encore planifiée pour une mutation.

* Le nom de partie `all_parts` représente toutes les parties qui n&#39;ont pas encore été mutées.
  :::

* `is_killed` ([UInt8](/fr/sql-reference/data-types/int-uint.md)) — Indique si une mutation a été interrompue. **Disponible uniquement dans ClickHouse Cloud.**

:::note
`is_killed=1` ne signifie pas nécessairement que la mutation est entièrement finalisée. Il est possible qu&#39;une mutation reste longtemps dans un état où `is_killed=1` et `is_done=0`. Cela peut se produire si une autre mutation de longue durée bloque la mutation interrompue. Il s&#39;agit d&#39;une situation normale.
:::

* `is_done` ([UInt8](/fr/sql-reference/data-types/int-uint.md)) — Indique si la mutation est terminée ou non. Valeurs possibles :
  * `1` si la mutation est terminée,
  * `0` si la mutation est toujours en cours.

:::note
Même si `parts_to_do = 0`, il est possible qu&#39;une mutation d&#39;une table répliquée ne soit pas encore terminée à cause d&#39;une requête `INSERT` de longue exécution, qui créera une nouvelle partie de données devant être mutée.
:::

S&#39;il y a eu des problèmes lors de la mutation de certaines parties de données, les colonnes suivantes contiennent des informations supplémentaires :

* `latest_failed_part` ([String](/fr/sql-reference/data-types/string.md)) — Le nom de la partie la plus récente qui n&#39;a pas pu être mutée.
* `latest_fail_time` ([DateTime](/fr/sql-reference/data-types/datetime.md)) — La date et l&#39;heure du dernier échec de mutation d&#39;une partie.
* `latest_fail_reason` ([String](/fr/sql-reference/data-types/string.md)) — Le message d&#39;exception à l&#39;origine du dernier échec de mutation d&#39;une partie.

<div id="monitoring-mutations">
  ## Suivi des mutations
</div>

Pour suivre la progression dans la table `system.mutations`, utilisez la requête suivante :

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

Remarque : cela nécessite des droits de lecture sur les tables `system.*`.

:::tip Usage de Cloud
Dans ClickHouse Cloud, la table `system.mutations` de chaque nœud contient toutes les mutations du cluster, et il n’est pas nécessaire d’utiliser `clusterAllReplicas`.
:::
