<div id="systemasynchronous_metrics">
  # system.asynchronous_metrics
</div>

<SystemTableCloud />

<div id="description">
  ## Description
</div>

Contient des métriques calculées périodiquement en arrière-plan. Par exemple, la quantité de RAM utilisée.

<div id="columns">
  ## Colonnes
</div>

{/*AUTOGENERATED_START*/ }

* `metric` ([String](../../sql-reference/data-types/string.md)) — Nom de la métrique.
* `value` ([Float64](../../sql-reference/data-types/float.md)) — Valeur de la métrique.
* `description` ([String](../../sql-reference/data-types/string.md)) — Description de la métrique.

{/*AUTOGENERATED_END*/ }

<div id="metric-descriptions">
  ## Description des métriques
</div>

Les descriptions ci-dessous sont générées à partir du code source C++ par `utils/generate-async-metrics-docs`. La source de vérité unique est la chaîne littérale située à côté de chaque enregistrement de métrique dans `src/Common/AsynchronousMetrics.cpp`, `src/Interpreters/ServerAsynchronousMetrics.cpp` et `src/Coordination/KeeperAsynchronousMetrics.cpp`. Les noms de métriques qui incluent un suffixe variable (par disk, par CPU, par interface, ...) sont affichés avec l’espace réservé `*name*` ; le server en cours d’exécution les signale avec le suffixe concret remplacé.

<div id="cgroupmemoryused">

</div>

La quantité de mémoire utilisée par le cgroup, en octets. Avec cgroup v2, il s’agit de anon + sock + mémoire noyau non récupérable ; avec cgroup v1, il s’agit de RSS. Dans les deux cas, le cache de pages du noyau (cache de fichiers) est exclu.

<div id="cgroupsystemtime">
  ### CGroupSystemTime
</div>

La proportion du temps pendant laquelle le cœur de CPU exécutait du code du noyau du système d’exploitation (system).

<div id="cgroupsystemtimenormalized">
  ### CGroupSystemTimeNormalized
</div>

La valeur est similaire à `CGroupSystemTime`, mais divisée par le nombre de cœurs CPU disponibles afin d’être mesurée dans l’intervalle [0..1], quel que soit le nombre de cœurs. Cela permet de calculer la moyenne des valeurs de cette métrique sur plusieurs serveurs d’un cluster, même si le nombre de cœurs n’est pas uniforme, tout en obtenant une métrique moyenne d’utilisation des ressources. Si elle est définie, le quota CPU du cgroup, divisé par sa période, peut être utilisé à la place du nombre réel de cœurs CPU ; dans ce cas, la valeur de cette métrique peut dépasser 1 à certains moments.

<div id="cgroupusertime">
  ### CGroupUserTime
</div>

La proportion du temps pendant lequel le cœur du CPU exécutait du code en espace utilisateur. Cela inclut également le temps pendant lequel le CPU était sous-utilisé pour des raisons internes au CPU (chargements mémoire, blocages du pipeline, erreurs de prédiction de branchement, exécution d’un autre cœur SMT).

<div id="cgroupusertimenormalized">
  ### CGroupUserTimeNormalized
</div>

Cette valeur est similaire à `CGroupUserTime`, mais divisée par le nombre de cœurs CPU disponibles afin d’être ramenée à l’intervalle [0..1], quel que soit le nombre de cœurs. Cela permet de calculer la moyenne des valeurs de cette métrique sur plusieurs serveurs d’un cluster, même si le nombre de cœurs n’est pas uniforme, tout en obtenant une métrique moyenne d’utilisation des ressources. Si elle est spécifiée, la quota CPU du cgroup divisée par sa période peut être utilisée à la place du nombre réel de cœurs CPU ; dans ce cas, la valeur de cette métrique peut dépasser 1 à certains moments.

</div>

Le nombre d’erreurs mémoire ECC corrigeables.
