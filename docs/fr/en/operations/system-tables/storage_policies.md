<div id="description">
  ## Description
</div>

Contient des informations sur les politiques de stockage et les volumes définis dans la [configuration du serveur](../../engines/table-engines/mergetree-family/mergetree.md#table_engine-mergetree-multiple-volumes_configure).

<div id="columns">
  ## Colonnes
</div>

{/*AUTOGENERATED_START*/ }

* `policy_name` ([String](/fr/sql-reference/data-types/string)) — Le nom de la politique de stockage.
* `volume_name` ([String](/fr/sql-reference/data-types/string)) — Le nom du volume.
* `volume_priority` ([UInt64](/fr/sql-reference/data-types/int-uint)) — La priorité du volume.
* `disks` ([Array(String)](/fr/sql-reference/data-types/array)) — La liste des noms de tous les disques qui font partie de cette politique de stockage.
* `volume_type` ([Enum8(&#39;JBOD&#39; = 0, &#39;SINGLE&#95;DISK&#39; = 1, &#39;UNKNOWN&#39; = 2)](/fr/sql-reference/data-types/enum)) — Le type du volume : JBOD ou disque unique.
* `max_data_part_size` ([UInt64](/fr/sql-reference/data-types/int-uint)) — la taille maximale d’une partie pouvant être stockée sur l’un des disques du volume.
* `move_factor` ([Float32](/fr/sql-reference/data-types/float)) — Lorsque l’espace disponible devient inférieur à ce facteur, les données commencent automatiquement à être déplacées vers le volume suivant, s’il y en a un (par défaut, 0.1).
* `prefer_not_to_merge` ([UInt8](/fr/sql-reference/data-types/int-uint)) — Vous ne devez pas utiliser ce paramètre. Désactive la fusion des parties de données sur ce volume (cela est nuisible et entraîne une dégradation des performances).
* `perform_ttl_move_on_insert` ([UInt8](/fr/sql-reference/data-types/int-uint)) — Désactive le déplacement TTL lors de l’`INSERT` d’une partie de données. Par défaut (si activé), si une partie de données déjà expirée selon la règle de déplacement TTL est insérée, elle est immédiatement placée sur le volume/disque défini dans la règle de déplacement.
* `load_balancing` ([Enum8(&#39;ROUND&#95;ROBIN&#39; = 0, &#39;LEAST&#95;USED&#39; = 1)](/fr/sql-reference/data-types/enum)) — Politique d’équilibrage des disques : `round_robin` ou `least_used`.

{/*AUTOGENERATED_END*/ }

<div id="volume-selection-on-insert">
  ## Sélection du volume lors de `INSERT`
</div>

Lorsqu&#39;un `INSERT` crée une nouvelle partie de données, ClickHouse choisit un disque de destination
en appliquant les règles ci-dessous dans l&#39;ordre. La première règle qui correspond **et peut
réserver de l&#39;espace pour la partie** est retenue ; sinon (si la règle ne s&#39;applique pas, s&#39;il n&#39;y a pas d&#39;espace
libre, ou si `max_data_part_size` est dépassé), l&#39;évaluation se poursuit avec la règle
suivante.

1. **Règle de déplacement TTL** — si une clause `TTL <expr> TO VOLUME 'X'` (ou `TO DISK 'X'`)
   est déjà expirée pour les lignes en cours d&#39;insertion, **et que**
   `perform_ttl_move_on_insert = 1` (par défaut) sur le **volume de destination
   TTL** (pour `TO DISK 'X'`, le volume contenant le disque `X`), la partie
   est écrite directement vers cette destination. Si la réservation échoue à cet emplacement, l&#39;
   insertion passe alors aux étapes 2 à 4 ; un avertissement est consigné, mais l&#39;`INSERT`
   n&#39;échoue pas pour cette seule raison.
2. **`max_data_part_size`** — un volume rejette les parties plus grandes que sa
   valeur `max_data_part_size`. Cette vérification s&#39;effectue par volume ; elle ne bloque pas une
   réservation à l&#39;étape 1 avec `TTL ... TO DISK 'X'`, qui cible le disque
   directement.
3. **`volume_priority`** — parmi les volumes restants, celui dont la
   valeur `volume_priority` est la plus faible est choisi. Les volumes sans
   `<volume_priority>` explicite sont ordonnés selon leur position dans la configuration.
4. **`load_balancing`** — une fois le volume choisi, le disque à l&#39;intérieur de ce
   volume est sélectionné selon sa politique `load_balancing`
   (`round_robin` ou `least_used`).

:::note Dérogation
Si `min_free_disk_bytes_to_perform_insert` ou
`min_free_disk_ratio_to_perform_insert` est non nul, la préséance ci-dessus
est contournée. `INSERT` essaie uniquement le volume dont la
`volume_priority` est la plus faible et renvoie `NOT_ENOUGH_SPACE` si aucun disque de ce volume
ne respecte le seuil. Les insertions dans la base de données `system` sont exemptées.
:::

:::note
`perform_ttl_move_on_insert` est lu sur le volume de **destination TTL**,
et non sur le volume source. Pour une règle `TO DISK 'X'`, l&#39;indicateur est lu
sur le volume qui contient le disque `X`. Le définir sur un autre volume de
la politique est sans effet sur le chemin d&#39;insertion.
:::

Pour forcer les insertions à respecter `volume_priority` même lorsqu&#39;une règle de déplacement TTL « déjà
expirée » s&#39;applique, définissez `perform_ttl_move_on_insert = 0` sur
le volume de destination TTL (pour `TO DISK 'X'`, sur le volume qui contient
le disque `X`). La partie est alors d&#39;abord écrite sur le volume de priorité N, puis
déplacée vers la destination TTL par une tâche de déplacement en arrière-plan (observable via
`system.moves`). Consultez le
[paramètre `perform_ttl_move_on_insert` du moteur MergeTree](/fr/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-multiple-volumes_configure).
