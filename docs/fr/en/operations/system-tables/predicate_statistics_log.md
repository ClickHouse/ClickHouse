<div id="description">
  ## Description
</div>

Contient des statistiques de sélectivité échantillonnées collectées lors de la lecture de tables `MergeTree`. La table n&#39;est alimentée que lorsque [`predicate_statistics_sample_rate`](/fr/operations/settings/settings#predicate_statistics_sample_rate) est supérieur à `0`.

Utilisez cette table pour examiner le niveau de sélectivité des prédicats utilisateur dans des charges de travail réelles, ainsi que le nombre de granules restant après le filtrage par clé primaire ou index de saut. Ces données sont destinées à servir de base à des recommandations d&#39;index et de projections fondées sur les charges de travail.

<div id="row-shapes">
  ## Structure des lignes
</div>

Une même requête peut produire deux types de lignes dans `system.predicate_statistics_log` :

* **Lignes de filtre**, émises à chaque étape prewhere/filter dans `MergeTreeSelectProcessor`. Elles renseignent `predicate_expression`, `input_rows`, `passed_rows`, `filter_selectivity`, ainsi que les colonnes relatives au prédicat complet `total_input_rows`, `total_passed_rows`, `total_selectivity`. Les colonnes liées aux index sont vides.
* **Lignes d’index**, émises à chaque étape de lecture dans `ReadFromMergeTree`. Elles renseignent les tableaux `index_names`, `index_types`, `total_granules`, `granules_after` et `index_selectivities`, avec une entrée par étape d’index (clé primaire, partition, skip indexes). Les colonnes liées aux prédicats sont vides.

Les lignes de filtre et les lignes d’index d’une même requête partagent les mêmes valeurs de `query_id` et de `table` ; elles peuvent donc être jointes lorsque les deux sont nécessaires.

<div id="sampling-and-overhead">
  ## Échantillonnage et surcoût
</div>

L’échantillonnage est contrôlé par [`predicate_statistics_sample_rate`](/fr/operations/settings/settings#predicate_statistics_sample_rate) :

* `0` désactive la collecte.
* `1` échantillonne chaque requête.
* `N > 1` échantillonne environ `1 / N` des requêtes, selon un hachage basé sur `query_id`.

Des valeurs plus faibles produisent davantage de données, mais augmentent la charge CPU côté lecture ainsi que le nombre d’écritures dans le journal système. Après avoir activé ce paramètre, utilisez [`SYSTEM FLUSH LOGS`](/fr/sql-reference/statements/system#flush-logs) si vous avez besoin que les lignes soient visibles immédiatement.

  ## Colonnes
</div>

* `hostname` ([LowCardinality(String)](/fr/sql-reference/data-types/lowcardinality)) — Nom d’hôte du serveur qui exécute la requête.
* `event_date` ([Date](/fr/sql-reference/data-types/date)) — Date de l’événement.
* `event_time` ([DateTime](/fr/sql-reference/data-types/datetime)) — Horodatage auquel cette entrée de journal a été consignée.
* `database` ([LowCardinality(String)](/fr/sql-reference/data-types/lowcardinality)) — Nom de la base de données de la table cible.
* `table` ([LowCardinality(String)](/fr/sql-reference/data-types/lowcardinality)) — Nom de la table cible.
* `query_id` ([String](/fr/sql-reference/data-types/string)) — ID de requête permettant de faire le lien avec query&#95;log.
* `predicate_expression` ([String](/fr/sql-reference/data-types/string)) — Expression de filtre complète traitée par cette étape prewhere/filter (dump ActionsDAG).
* `input_rows` ([UInt64](/fr/sql-reference/data-types/int-uint)) — Lignes entrant dans cette étape prewhere/filter.
* `passed_rows` ([UInt64](/fr/sql-reference/data-types/int-uint)) — Lignes conservées après cette étape prewhere/filter.
* `filter_selectivity` ([Float64](/fr/sql-reference/data-types/float)) — Sélectivité de cette étape : passed&#95;rows / input&#95;rows.
* `total_input_rows` ([UInt64](/fr/sql-reference/data-types/int-uint)) — Lignes entrant dans la première étape prewhere (nombre total de lignes lues à partir des granules).
* `total_passed_rows` ([UInt64](/fr/sql-reference/data-types/int-uint)) — Lignes conservées après toutes les étapes prewhere (lignes transmises à la requête).
* `total_selectivity` ([Float64](/fr/sql-reference/data-types/float)) — Sélectivité de l’ensemble du prédicat : total&#95;passed&#95;rows / total&#95;input&#95;rows.
* `index_names` ([Array(LowCardinality(String))](/fr/sql-reference/data-types/array)) — Noms des index appliqués, par ex. [&#39;PrimaryKey&#39;, &#39;idx&#95;bf&#95;status&#39;] (lignes d’index uniquement).
* `index_types` ([Array(LowCardinality(String))](/fr/sql-reference/data-types/array)) — Types d’index appliqués : PrimaryKey, Skip, MinMax, Partition (lignes d’index uniquement).
* `total_granules` ([Array(UInt64)](/fr/sql-reference/data-types/array)) — Granules entrant dans chaque étape d’index (lignes d’index uniquement).
* `granules_after` ([Array(UInt64)](/fr/sql-reference/data-types/array)) — Granules restant après chaque étape d’index (lignes d’index uniquement).
* `index_selectivities` ([Array(Float64)](/fr/sql-reference/data-types/array)) — Sélectivité par index : granules&#95;after / total&#95;granules (lignes d’index uniquement).

<div id="example">
  ## Exemple
</div>

```sql
SET predicate_statistics_sample_rate = 1;

SELECT *
FROM hits
WHERE URL LIKE '%/product/%' AND EventDate >= today() - 7
FORMAT Null;

SYSTEM FLUSH LOGS predicate_statistics_log;

SELECT
    query_id,
    predicate_expression,
    round(filter_selectivity, 3) AS step_selectivity,
    round(total_selectivity, 3) AS query_selectivity,
    index_names,
    index_selectivities
FROM system.predicate_statistics_log
WHERE table = 'hits'
ORDER BY event_time DESC
LIMIT 10;
```
