<div id="s3-table-function">
  # Fonction de table s3
</div>

Fournit une interface de type table pour sélectionner et insérer des fichiers dans [Amazon S3](https://aws.amazon.com/s3/) et [Google Cloud Storage](https://cloud.google.com/storage/). Cette fonction de table est similaire à la [fonction hdfs](../../sql-reference/table-functions/hdfs.md), mais offre des fonctionnalités spécifiques à S3.

Si votre cluster comporte plusieurs répliques, vous pouvez utiliser la [fonction s3Cluster](../../sql-reference/table-functions/s3Cluster.md) à la place afin de paralléliser les insertions.

Lors de l’utilisation de la `s3 table function` avec [`INSERT INTO...SELECT`](../../sql-reference/statements/insert-into#inserting-the-results-of-select), les données sont lues et insérées en continu. Seuls quelques blocs de données résident en mémoire, tandis que les blocs sont lus en continu depuis S3 et envoyés vers la table de destination.

<div id="syntax">
  ## Syntaxe
</div>

```sql
s3(url [, NOSIGN | access_key_id, secret_access_key, [session_token]] [,format] [,structure] [,compression_method],[,headers], [,extra_credentials], [,partition_strategy], [,partition_columns_in_data_file])
s3(named_collection[, option=value [,..]])
```

:::tip GCS
La fonction de table S3 s’intègre à Google Cloud Storage à l’aide de l’API XML de GCS et de clés HMAC. Consultez la [documentation Google sur l’interopérabilité](https://cloud.google.com/storage/docs/interoperability) pour plus de détails sur l’endpoint et le HMAC.

Pour GCS, remplacez votre clé HMAC et votre secret HMAC là où vous voyez `access_key_id` et `secret_access_key`.
:::

**Paramètres**

La fonction de table `s3` prend en charge les paramètres simples suivants :

| Parameter                               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`                                   | URL du bucket avec le chemin vers le fichier. Prend en charge les caractères génériques suivants en mode readonly : `*`, `**`, `?`, `{abc,def}` et `{N..M}`, où `N` et `M` sont des nombres, et `'abc'` et `'def'` des chaînes. Pour plus d’informations, voir [ici](../../engines/table-engines/integrations/s3.md#wildcards-in-path).                                                                                                                                                                                                                                         |
| `NOSIGN`                                | Si ce keyword est fourni à la place des identifiants, aucune request ne sera signée.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `access_key_id` and `secret_access_key` | Clés qui spécifient les identifiants à utiliser avec l’endpoint donné. Facultatif.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `session_token`                         | Token de session à utiliser avec les clés fournies. Facultatif lorsque des clés sont transmises.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `format`                                | Le [format](/fr/sql-reference/formats) du fichier.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `structure`                             | Structure de la table. Format : `'column1_name column1_type, column2_name column2_type, ...'`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `compression_method`                    | Paramètre facultatif. Valeurs prises en charge : `none`, `gzip` ou `gz`, `brotli` ou `br`, `xz` ou `LZMA`, `zstd` ou `zst`. Par défaut, la méthode de compression est détectée automatiquement à partir de l’extension du fichier.                                                                                                                                                                                                                                                                                                                                              |
| `headers`                               | Paramètre facultatif. Permet de transmettre des headers dans la request S3. Utilisez le format `headers(key=value)`, par exemple `headers('x-amz-request-payer' = 'requester')`.                                                                                                                                                                                                                                                                                                                                                                                                |
| `partition_strategy`                    | Paramètre facultatif. Valeurs prises en charge : `wildcard` ou `hive`. `wildcard` exige un `{_partition_id}` dans le chemin, remplacé par la clé de partition. `hive` n’autorise pas les caractères génériques, suppose que le chemin est la racine de la table et génère des répertoires partitionnés de style Hive avec des Snowflake IDs comme noms de fichiers et le format du fichier comme extension. La valeur par défaut est le setting `file_like_engine_default_partition_strategy` (`wildcard` dans les settings `compatibility` antérieurs à `26.6`, sinon `hive`). |
| `partition_columns_in_data_file`        | Paramètre facultatif. Utilisé uniquement avec la stratégie de partitionnement `hive`. Indique à ClickHouse s’il doit s’attendre à ce que les colonnes de partition soient écrites dans le fichier de données. La valeur par défaut est `false`.                                                                                                                                                                                                                                                                                                                                       |
| `extra_credentials`                     | Paramètre facultatif. Utilisé pour transmettre un `role_arn` pour le contrôle d’accès basé sur le rôle dans ClickHouse Cloud. Voir [Secure S3](/fr/cloud/data-sources/secure-s3) pour les étapes de configuration.                                                                                                                                                                                                                                                                                                                                                                                 |
| `storage_class_name`                    | Paramètre facultatif. Valeurs prises en charge : `STANDARD` ou `INTELLIGENT_TIERING`. Permet de spécifier [AWS S3 Intelligent Tiering](https://aws.amazon.com/s3/storage-classes/intelligent-tiering/). La valeur par défaut est `STANDARD`.                                                                                                                                                                                                                                                                                                                                    |

:::note GCS
L’URL GCS est de ce format, car l’endpoint de l’API XML de Google est différent de celui de l’API JSON :

```text
  https://storage.googleapis.com/<bucket>/<folder>/<filename(s)>
```

et non ~~https://storage.cloud.google.com~~.
:::

Les arguments peuvent également être fournis à l’aide de [collections nommées](/fr/operations/named-collections.md). Dans ce cas, `url`, `access_key_id`, `secret_access_key`, `format`, `structure` et `compression_method` fonctionnent de la même manière, et quelques paramètres supplémentaires sont également pris en charge :

| Argument                      | Description                                                                                                                                                                                                                                                      |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filename`                    | ajouté à l’URL s’il est spécifié.                                                                                                                                                                                                                                |
| `use_environment_credentials` | activé par défaut, permet de transmettre des paramètres supplémentaires à l’aide des variables d’environnement `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`, `AWS_CONTAINER_CREDENTIALS_FULL_URI`, `AWS_CONTAINER_AUTHORIZATION_TOKEN`, `AWS_EC2_METADATA_DISABLED`. |
| `no_sign_request`             | désactivé par défaut.                                                                                                                                                                                                                                            |
| `expiration_window_seconds`   | la valeur par défaut est 120.                                                                                                                                                                                                                                    |

<div id="returned_value">
  ## Valeur renvoyée
</div>

Une table présentant la structure spécifiée pour lire ou écrire des données dans le fichier indiqué.

<div id="examples">
  ## Exemples
</div>

Sélection des 5 premières lignes de la table depuis le fichier S3 `https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv` :

```sql
SELECT *
FROM s3(
   'https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv',
   'CSVWithNames'
)
LIMIT 5;
```

```response
┌───────Date─┬────Open─┬────High─┬─────Low─┬───Close─┬───Volume─┬─OpenInt─┐
│ 1984-09-07 │ 0.42388 │ 0.42902 │ 0.41874 │ 0.42388 │ 23220030 │       0 │
│ 1984-09-10 │ 0.42388 │ 0.42516 │ 0.41366 │ 0.42134 │ 18022532 │       0 │
│ 1984-09-11 │ 0.42516 │ 0.43668 │ 0.42516 │ 0.42902 │ 42498199 │       0 │
│ 1984-09-12 │ 0.42902 │ 0.43157 │ 0.41618 │ 0.41618 │ 37125801 │       0 │
│ 1984-09-13 │ 0.43927 │ 0.44052 │ 0.43927 │ 0.43927 │ 57822062 │       0 │
└────────────┴─────────┴─────────┴─────────┴─────────┴──────────┴─────────┘
```

:::note
ClickHouse utilise les extensions de fichier pour déterminer le format des données. Par exemple, nous aurions pu exécuter la commande précédente sans `CSVWithNames` :

```sql
SELECT *
FROM s3(
   'https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv'
)
LIMIT 5;
```

ClickHouse peut également déterminer la méthode de compression du fichier. Par exemple, si le fichier a été compressé avec l’extension `.csv.gz`, ClickHouse le décompressera automatiquement.
:::

:::note
Les fichiers Parquet portant des noms comme `*.parquet.snappy` ou `*.parquet.zstd` peuvent perturber ClickHouse et provoquer les erreurs `TOO_LARGE_COMPRESSED_BLOCK` ou `ZSTD_DECODER_FAILED`.
Cela s’explique par le fait que ClickHouse tenterait de lire l’intégralité du fichier comme des données encodées en Snappy ou en ZSTD, alors qu’en réalité, Parquet applique la compression au niveau des groupes de lignes et des colonnes.

Les métadonnées Parquet indiquent déjà la compression utilisée pour chaque colonne ; l’extension du fichier est donc superflue.
Dans ce cas, vous pouvez simplement utiliser `compression_method = 'none'` :

```sql
SELECT *
FROM s3(
  'https://<my-bucket>.s3.<my-region>.amazonaws.com/path/to/my-data.parquet.snappy',
  compression_format = 'none'
);
```

:::

<div id="usage">
  ## Utilisation
</div>

Supposons que nous ayons plusieurs fichiers avec les URI suivants sur S3 :

* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/some&#95;prefix/some&#95;file&#95;1.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/some&#95;prefix/some&#95;file&#95;2.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/some&#95;prefix/some&#95;file&#95;3.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/some&#95;prefix/some&#95;file&#95;4.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/another&#95;prefix/some&#95;file&#95;1.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/another&#95;prefix/some&#95;file&#95;2.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/another&#95;prefix/some&#95;file&#95;3.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/another&#95;prefix/some&#95;file&#95;4.csv&#39;

Comptez le nombre de lignes dans les fichiers dont le nom se termine par un chiffre de 1 à 3 :

```sql
SELECT count(*)
FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/my-test-bucket-768/{some,another}_prefix/some_file_{1..3}.csv', 'CSV', 'column1 UInt32, column2 UInt32, column3 UInt32')
```

```text
┌─count()─┐
│      18 │
└─────────┘
```

Comptez le nombre total de lignes dans tous les fichiers de ces deux répertoires :

```sql
SELECT count(*)
FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/my-test-bucket-768/{some,another}_prefix/*', 'CSV', 'column1 UInt32, column2 UInt32, column3 UInt32')
```

```text
┌─count()─┐
│      24 │
└─────────┘
```

:::tip
Si votre liste de fichiers contient des plages de nombres avec des zéros de tête, utilisez la construction avec des accolades pour chaque chiffre séparément ou utilisez `?`.
:::

Comptez le nombre total de lignes dans les fichiers nommés `file-000.csv`, `file-001.csv`, ... , `file-999.csv` :

```sql
SELECT count(*)
FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/my-test-bucket-768/big_prefix/file-{000..999}.csv', 'CSV', 'column1 UInt32, column2 UInt32, column3 UInt32');
```

```text
┌─count()─┐
│      12 │
└─────────┘
```

Insérez des données dans le fichier `test-data.csv.gz` :

```sql
INSERT INTO FUNCTION s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip')
VALUES ('test-data', 1), ('test-data-2', 2);
```

Insérer des données dans le fichier `test-data.csv.gz` à partir d&#39;une table existante :

```sql
INSERT INTO FUNCTION s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip')
SELECT name, value FROM existing_table;
```

Le glob ** peut être utilisé pour parcourir les répertoires de manière récursive. Prenons l&#39;exemple ci-dessous : il récupère tous les fichiers du répertoire `my-test-bucket-768` de façon récursive :

```sql
SELECT * FROM s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/**', 'CSV', 'name String, value UInt32', 'gzip');
```

Ce qui suit récupère les données de tous les fichiers `test-data.csv.gz` dans n&#39;importe quel dossier du répertoire `my-test-bucket`, de façon récursive :

```sql
SELECT * FROM s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/**/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip');
```

Note. Il est possible de spécifier des mappeurs d&#39;URL personnalisés dans le fichier de configuration du serveur. Exemple :

```sql
SELECT * FROM s3('s3://clickhouse-public-datasets/my-test-bucket-768/**/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip');
```

L&#39;URL `'s3://clickhouse-public-datasets/my-test-bucket-768/**/test-data.csv.gz'` sera remplacée par `'http://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/**/test-data.csv.gz'`

Vous pouvez ajouter un mappeur personnalisé à `config.xml` :

```xml
<url_scheme_mappers>
   <s3>
      <to>https://{bucket}.s3.amazonaws.com</to>
   </s3>
   <gs>
      <to>https://{bucket}.storage.googleapis.com</to>
   </gs>
   <oss>
      <to>https://{bucket}.oss.aliyuncs.com</to>
   </oss>
</url_scheme_mappers>
```

Pour une utilisation en production, il est recommandé d&#39;utiliser les [collections nommées](/fr/operations/named-collections.md). Voici un exemple :

```sql

CREATE NAMED COLLECTION creds AS
        access_key_id = '***',
        secret_access_key = '***';
SELECT count(*)
FROM s3(creds, url='https://s3-object-url.csv')
```

  ## Écriture partitionnée
</div>

<div id="partition-strategy">
  ### Stratégie de partitionnement
</div>

Pris en charge uniquement pour les requêtes `INSERT`.

`wildcard` : remplace le caractère générique `{_partition_id}` dans le chemin du fichier par la clé de partition réelle. Il est sélectionné par défaut uniquement lorsque le paramètre `compatibility` est antérieur à `26.6` ; sinon, la valeur par défaut est `hive` (voir le paramètre `file_like_engine_default_partition_strategy`).

`hive` implémente le partitionnement de style Hive pour les lectures et les écritures. Il génère des fichiers au format suivant : `<prefix>/<key1=val1/key2=val2...>/<snowflakeid>.<toLower(file_format)>`.

**Exemple de stratégie de partitionnement `hive`**

```sql
INSERT INTO FUNCTION s3(s3_conn, filename='t_03363_function', format=Parquet, partition_strategy='hive') PARTITION BY (year, country) SELECT 2020 as year, 'Russia' as country, 1 as id;
```

```result
SELECT _path, * FROM s3(s3_conn, filename='t_03363_function/**.parquet');

   ┌─_path──────────────────────────────────────────────────────────────────────┬─id─┬─country─┬─year─┐
1. │ test/t_03363_function/year=2020/country=Russia/7351295896279887872.parquet │  1 │ Russia  │ 2020 │
   └────────────────────────────────────────────────────────────────────────────┴────┴─────────┴──────┘
```

**Exemples de la stratégie de partition `wildcard`**

1. Inclure l’identifiant de partition dans une clé crée des fichiers distincts :

```sql
INSERT INTO TABLE FUNCTION
    s3('http://bucket.amazonaws.com/my_bucket/file_{_partition_id}.csv', 'CSV', 'a String, b UInt32, c UInt32')
    PARTITION BY a VALUES ('x', 2, 3), ('x', 4, 5), ('y', 11, 12), ('y', 13, 14), ('z', 21, 22), ('z', 23, 24);
```

Par conséquent, les données sont enregistrées dans trois fichiers : `file_x.csv`, `file_y.csv` et `file_z.csv`.

2. L’utilisation de l’identifiant de partition dans le nom d’un bucket crée des fichiers dans des buckets différents :

```sql
INSERT INTO TABLE FUNCTION
    s3('http://bucket.amazonaws.com/my_bucket_{_partition_id}/file.csv', 'CSV', 'a UInt32, b UInt32, c UInt32')
    PARTITION BY a VALUES (1, 2, 3), (1, 4, 5), (10, 11, 12), (10, 13, 14), (20, 21, 22), (20, 23, 24);
```

Par conséquent, les données sont écrites dans trois fichiers, chacun situé dans un bucket différent : `my_bucket_1/file.csv`, `my_bucket_10/file.csv` et `my_bucket_20/file.csv`.

<div id="accessing-public-buckets">
  ## Accéder aux public buckets
</div>

ClickHouse essaie de récupérer des identifiants à partir de nombreux types de sources.
Cela peut parfois poser problème lors de l&#39;accès à certains public buckets, le client renvoyant alors un code d&#39;erreur `403`.
Pour éviter ce problème, utilisez le mot-clé `NOSIGN`, qui force le client à ignorer tous les identifiants et à ne pas signer les requêtes.

```sql
SELECT *
FROM s3(
   'https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv',
   NOSIGN,
   'CSVWithNames'
)
LIMIT 5;
```

<div id="using-s3-credentials-clickhouse-cloud">
  ## Utilisation des identifiants S3 (ClickHouse Cloud)
</div>

Pour les buckets non publics, les utilisateurs peuvent transmettre un `aws_access_key_id` et un `aws_secret_access_key` à la fonction. Par exemple :

```sql
SELECT count() FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/mta/*.tsv', '<KEY>', '<SECRET>','TSVWithNames')
```

Cela convient pour des accès ponctuels ou lorsque les identifiants peuvent être facilement renouvelés. Cependant, cette approche n’est pas recommandée comme solution à long terme pour des accès répétés ou lorsque les identifiants sont sensibles. Dans ce cas, nous recommandons aux utilisateurs de s’appuyer sur un contrôle d’accès basé sur les rôles.

Le contrôle d’accès basé sur les rôles pour S3 dans ClickHouse Cloud est documenté [ici](/fr/cloud/data-sources/secure-s3).

Une fois configuré, un `roleARN` peut être transmis à la fonction s3 via le paramètre `extra_credentials`. Par exemple :

```sql
SELECT count() FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/mta/*.tsv','CSVWithNames',extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001'))
```

Un `external_id` facultatif peut également être fourni avec `role_arn`. Il est transmis en tant que paramètre `ExternalId` dans l’appel AWS STS `AssumeRole` et permet à la stratégie d’approbation du rôle d’exiger un secret partagé, ce qui atténue le [problème du « confused deputy »](https://docs.aws.amazon.com/IAM/latest/UserGuide/confused-deputy.html). Par exemple :

```sql
SELECT count() FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/mta/*.tsv','CSVWithNames',extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001', external_id = 'my-external-id'))
```

D&#39;autres exemples sont disponibles [ici](/fr/cloud/data-sources/secure-s3#access-your-s3-bucket-with-the-clickhouseaccess-role)

<div id="working-with-archives">
  ## Utilisation des archives
</div>

Supposons que nous disposions de plusieurs fichiers d’archive avec les URI suivantes sur S3 :

* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-10.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-11.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-12.csv.zip&#39;

Il est possible d’extraire des données de ces archives à l’aide de ::. Des globs peuvent être utilisés aussi bien dans la partie URL que dans la partie après :: (qui correspond au nom d’un fichier à l’intérieur de l’archive).

```sql
SELECT *
FROM s3(
   'https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-1{0..2}.csv.zip :: *.csv'
);
```

:::note
ClickHouse prend en charge trois formats d’archive :
ZIP
TAR
7Z
Si les archives ZIP et TAR sont accessibles depuis n’importe quel emplacement de stockage pris en charge, les archives 7Z ne peuvent être lues que depuis le système de fichiers local sur lequel ClickHouse est installé.
:::

<div id="inserting-data">
  ## Insertion de données
</div>

Notez que des lignes ne peuvent être insérées que dans de nouveaux fichiers. Il n’existe ni cycles de fusion ni opérations de fractionnement de fichiers. Une fois un fichier écrit, les insertions ultérieures échoueront. Voir plus de détails [ici](/fr/integrations/s3#inserting-data).

<div id="virtual-columns">
  ## Colonnes virtuelles
</div>

* `_path` — Chemin du fichier. Type : `LowCardinality(String)`. Dans le cas d&#39;une archive, affiche le chemin au format : `"{path_to_archive}::{path_to_file_inside_archive}"`
* `_file` — Nom du fichier. Type : `LowCardinality(String)`. Dans le cas d&#39;une archive, affiche le nom du fichier à l&#39;intérieur de l&#39;archive.
* `_size` — Taille du fichier en octets. Type : `Nullable(UInt64)`. Si la taille du fichier est inconnue, la valeur est `NULL`. Dans le cas d&#39;une archive, affiche la taille non compressée du fichier à l&#39;intérieur de l&#39;archive.
* `_time` — Date et heure de la dernière modification du fichier. Type : `Nullable(DateTime)`. Si l&#39;heure est inconnue, la valeur est `NULL`.

<div id="hive-style-partitioning">
  ## Paramètre use_hive_partitioning
</div>

Il s’agit d’une indication permettant à ClickHouse d’analyser les fichiers partitionnés de type Hive au moment de la lecture. Cela n’a aucun effet sur l’écriture. Pour assurer une symétrie entre lecture et écriture, utilisez l’argument `partition_strategy`.

Lorsque le paramètre `use_hive_partitioning` est défini sur 1, ClickHouse détecte le partitionnement de type Hive dans le chemin (`/name=value/`) et permet d’utiliser les colonnes de partition comme colonnes virtuelles dans la requête. Ces colonnes virtuelles auront les mêmes noms que dans le chemin partitionné.

**Exemple**

```sql
SELECT * FROM s3('s3://data/path/date=*/country=*/code=*/*.parquet') WHERE date > '2020-01-01' AND country = 'Netherlands' AND code = 42;
```

<div id="accessing-requester-pays-buckets">
  ## Accès aux buckets à la charge du demandeur
</div>

Pour accéder à un bucket à la charge du demandeur, un en-tête `x-amz-request-payer = requester` doit être transmis dans chaque requête. Pour cela, passez le paramètre `headers('x-amz-request-payer' = 'requester')` à la fonction s3. Par exemple :

```sql
SELECT
    count() AS num_rows,
    uniqExact(_file) AS num_files
FROM s3('https://coiled-datasets-rp.s3.us-east-1.amazonaws.com/1trc/measurements-100*.parquet', 'AWS_ACCESS_KEY_ID', 'AWS_SECRET_ACCESS_KEY', headers('x-amz-request-payer' = 'requester'))

┌───num_rows─┬─num_files─┐
│ 1110000000 │       111 │
└────────────┴───────────┘

1 row in set. Elapsed: 3.089 sec. Processed 1.09 billion rows, 0.00 B (353.55 million rows/s., 0.00 B/s.)
Peak memory usage: 192.27 KiB.
```

<div id="storage-settings">
  ## Paramètres de stockage
</div>

* [s3&#95;truncate&#95;on&#95;insert](/fr/operations/settings/settings.md#s3_truncate_on_insert) - permet de tronquer le fichier avant d’y insérer des données. Désactivé par défaut.
* [s3&#95;create&#95;new&#95;file&#95;on&#95;insert](/fr/operations/settings/settings.md#s3_create_new_file_on_insert) - permet de créer un nouveau fichier à chaque insertion si le format comporte un suffixe. Désactivé par défaut.
* [s3&#95;skip&#95;empty&#95;files](/fr/operations/settings/settings.md#s3_skip_empty_files) - permet d’ignorer les fichiers vides lors de la lecture. Activé par défaut.

<div id="nested-avro-schemas">
  ## Schémas Avro imbriqués
</div>

Lors de la lecture de fichiers Avro contenant des **enregistrements imbriqués** dont la structure varie d’un fichier à l’autre (par exemple, certains fichiers comportent un champ supplémentaire dans un objet imbriqué), ClickHouse peut renvoyer une erreur du type :

> The number of leaves in record doesn&#39;t match the number of elements in tuple...

Cela se produit parce que ClickHouse s’attend à ce que toutes les structures d’enregistrements imbriqués correspondent au même schéma.
Pour gérer ce cas, vous pouvez :

* Utiliser `schema_inference_mode='union'` pour fusionner différents schémas d’enregistrements imbriqués, ou
* Aligner manuellement vos structures imbriquées et activer
  `use_structure_from_insertion_table_in_table_functions=1`.

:::note[Note sur les performances]
`schema_inference_mode='union'` peut prendre plus de temps sur de très grands jeux de données S3, car il doit analyser chaque fichier pour en déduire le schéma.
:::

**Exemple**

```sql
INSERT INTO data_stage
SELECT
    id,
    data
FROM s3('https://bucket-name/*.avro', 'Avro')
SETTINGS schema_inference_mode='union';
```
