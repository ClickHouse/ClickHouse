Choisissez l’instrumentation côté serveur adaptée à votre déploiement Next.js :

* **Auto-hébergé, environnement d’exécution Node.js :** utilisez le SDK Node.js de ClickStack.
* **Vercel ou environnement d’exécution Edge :** utilisez `@vercel/otel`.

Pour la télémétrie côté navigateur et la relecture de session, consultez le [guide du SDK pour navigateur](/fr/clickstack/ingesting-data/sdks/browser).

## Next.js auto-hébergé {#self-hosted-nextjs}

Utilisez Node.js 22.15 ou une version ultérieure, puis installez le SDK :

```shell
npm install @clickhouse/clickstack-node
```

Créez `instrumentation.ts` à la racine de votre projet, ou dans `src` si votre application utilise ce répertoire. N’initialisez le SDK que dans l’environnement d’exécution Node.js :

```typescript
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { init } = await import('@clickhouse/clickstack-node');
    init();
  }
}
```

Ajoutez le SDK à `serverExternalPackages` dans votre configuration Next.js existante afin qu&#39;il soit chargé en dehors du bundle serveur :

```javascript
// next.config.mjs
export default {
  serverExternalPackages: ['@clickhouse/clickstack-node'],
};
```

Configurez la destination ci-dessous et définissez `OTEL_SERVICE_NAME` pour identifier votre application. Ne préchargez pas le SDK en plus et n&#39;initialisez pas d&#39;autre SDK OpenTelemetry. Pour découvrir d&#39;autres options, consultez le [guide Node.js](/fr/clickstack/ingesting-data/sdks/nodejs).

Pour les points à prendre en compte concernant l&#39;arrêt et le déploiement, consultez les [recommandations du SDK pour Next.js](https://github.com/ClickHouse/clickstack-node#nextjs).

## Vercel et environnement d’exécution Edge {#vercel-or-edge}

Utilisez `@vercel/otel` en suivant les [instructions de configuration OpenTelemetry de Next.js](https://nextjs.org/docs/app/guides/open-telemetry). Cette configuration remplace l’initialisation du SDK Node.js de ClickStack décrite ci-dessus.

Configurez l’[export OTLP](https://github.com/vercel/otel/tree/main/packages/otel#registerotelconfig-configuration) à l’aide des paramètres de connexion ci-dessous. Remplacez les destinations données en exemple ainsi que toute surcharge d’endpoint propre à un signal, puis définissez les variables dans la configuration de votre déploiement.

Si votre déploiement Vercel utilise déjà une intégration de traçage, configurez un [exportateur personnalisé](https://nextjs.org/docs/app/guides/open-telemetry#custom-exporters) pour cette destination : les variables d’environnement d’endpoint ne suffisent pas à elles seules à surcharger cette intégration.

## Configurer votre destination {#configure-destination}

Définissez un nom de service, quelle que soit l&#39;option d&#39;instrumentation choisie :

```shell
export OTEL_SERVICE_NAME='my-nextjs-app'
```

Définissez l&#39;endpoint HTTP OTLP et la clé d&#39;ingestion de votre collecteur ClickStack. Utilisez `http://` si TLS n&#39;est pas configuré sur votre collecteur. Pour configurer le collecteur, consultez [Ingestion avec OpenTelemetry](/fr/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## Vérifier l&#39;ingestion {#verify-ingestion}

Démarrez votre application et envoyez des requêtes vers une page générée côté serveur ou vers une route d&#39;API. Dans ClickStack, sélectionnez un intervalle de temps récent et recherchez le nom du service de votre application dans la vue Traces.
