Semblable à l’[image tout-en-un](/fr/clickstack/deployment/all-in-one), cette image Docker complète regroupe tous les composants de ClickStack :

* **ClickHouse**
* **Interface utilisateur de ClickStack**
* **collecteur OpenTelemetry (OTel)** (exposant OTLP sur les ports `4317` et `4318`)
* **MongoDB** (pour l’état persistant de l’application)

**Cependant, l’authentification des utilisateurs est désactivée dans cette distribution de l’interface utilisateur de ClickStack**

<div id="suitable-for">
  ### Convient pour {#suitable-for}
</div>

* Démonstrations
* Débogage
* Développement avec l&#39;interface utilisateur de ClickStack

## Étapes de déploiement {#deployment-steps}

<br />

<Steps>
  <Step title="Déployer avec Docker" id="deploy-with-docker">
    Le mode local déploie l’interface utilisateur de ClickStack sur le port 8080.

    ```shell
    docker run -p 8080:8080 clickhouse/clickstack-local:latest
    ```
  </Step>

  <Step title="Accéder à l’interface utilisateur de ClickStack" id="navigate-to-hyperdx-ui">
    Rendez-vous sur [http://localhost:8080](http://localhost:8080) pour accéder à l’interface utilisateur de ClickStack.

    **Aucun utilisateur ne vous sera demandé, car l’authentification n’est pas activée dans ce mode de déploiement.**

    Connectez-vous à votre propre cluster ClickHouse externe, par exemple ClickHouse Cloud.

    <div className="ch-image-md">
      <Frame>
        ![Créer un identifiant de connexion](/images/use-cases/observability/hyperdx-2.webp)
      </Frame>
    </div>

    Créez une source en conservant toutes les valeurs par défaut, puis renseignez le champ `Table` avec la valeur `otel_logs`. Tous les autres paramètres devraient être détectés automatiquement : il vous suffit alors de cliquer sur `Save New Source`.

    <div className="ch-image-md">
      <Frame>
        ![Créer une source de journaux](/images/use-cases/observability/hyperdx-logs.webp)
      </Frame>
    </div>
  </Step>
</Steps>
