Le serveur MCP de ClickStack s’appuie sur le [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) pour permettre aux assistants IA d’interagir avec vos données ClickHouse Observability. Une fois connecté, un assistant IA peut interroger les logs, les traces et les métriques, gérer les tableaux de bord et les alertes, explorer les sources de données et exploiter les recherches enregistrées, le tout en langage naturel.

Vous pouvez ainsi utiliser des outils comme [Claude Code](https://docs.anthropic.com/en/docs/claude-code), [Cursor](https://www.cursor.com/) ou tout client compatible MCP pour analyser des incidents, créer des tableaux de bord et gérer votre configuration d’observability sans quitter votre environnement de développement.

## Se connecter à ClickHouse Observability {#managed-clickstack}

ClickHouse Observability se connecte via l&#39;endpoint MCP dans le cloud, à l&#39;adresse `https://mcp.clickhouse.cloud/clickstack`, et s&#39;authentifie avec OAuth 2.0. L&#39;authentification par API key n&#39;est pas prise en charge sur cet endpoint.

### Prérequis {#managed-prerequisites}

* Un service ClickHouse Cloud en cours d’exécution avec l’[observability activée](/fr/clickstack/observability/getting-started)
* [MCP activé](/fr/products/cloud/features/ai-ml/mcp/remote-mcp#enable-remote-mcp-server) sur le service : ouvrez la Console Cloud, cliquez sur **Connecter**, sélectionnez **Connect with MCP**, puis activez l’interrupteur

### Endpoint {#managed-endpoint}

```text
https://mcp.clickhouse.cloud/clickstack
```

L’authentification repose sur OAuth 2.0. Lors de la première connexion de votre client MCP, une fenêtre de navigateur s’ouvre pour que vous puissiez vous connecter avec vos identifiants ClickHouse Cloud. Aucune API key n’est requise.

### Connexion d’un client MCP {#managed-connecting-a-client}

Ouvrez **Paramètres de l’équipe → API &amp; Agents** dans votre service ClickHouse Observability pour copier une configuration prête à l’emploi pour votre client MCP. La configuration générée inclut l’identifiant du service, de sorte que les requêtes ciblent ce service.

Vous pouvez également utiliser l’un des exemples ci-dessous. Lors de la connexion, votre client vous invite à vous authentifier via OAuth.

<Tabs>
  <Tab title="Claude Code">
    ```shell
    claude mcp add --transport http clickstack https://mcp.clickhouse.cloud/clickstack
    ```

    Lancez Claude Code et exécutez `/mcp`, puis sélectionnez `clickstack` pour finaliser le flux OAuth.
  </Tab>

  <Tab title="Cursor">
    Ajoutez le contenu suivant au fichier `.cursor/mcp.json` :

    ```json
    {
      "mcpServers": {
        "clickstack": {
          "url": "https://mcp.clickhouse.cloud/clickstack"
        }
      }
    }
    ```
  </Tab>

  <Tab title="VS Code">
    Ajoutez le contenu suivant au fichier `.vscode/mcp.json` :

    ```json
    {
      "servers": {
        "clickstack": {
          "type": "http",
          "url": "https://mcp.clickhouse.cloud/clickstack"
        }
      }
    }
    ```
  </Tab>

  <Tab title="OpenCode">
    Ajoutez le contenu suivant au fichier `opencode.json` :

    ```json
    {
      "mcp": {
        "clickstack": {
          "type": "remote",
          "url": "https://mcp.clickhouse.cloud/clickstack"
        }
      }
    }
    ```
  </Tab>

  <Tab title="LibreChat">
    Ajoutez le contenu suivant au fichier `librechat.yaml` :

    ```yaml
    mcpServers:
      clickstack:
        type: streamable-http
        url: https://mcp.clickhouse.cloud/clickstack
    ```
  </Tab>

  <Tab title="Autres">
    Tout client MCP prenant en charge **Streamable HTTP** avec OAuth peut se connecter. Configurez-le avec :

    * **URL :** `https://mcp.clickhouse.cloud/clickstack`
  </Tab>
</Tabs>

### Cibler un service spécifique {#managed-service-override}

Sans l&#39;en-tête `x-service-id`, les requêtes sont envoyées par défaut au premier service d&#39;observability provisionné et utilisé par votre compte. Pour modifier le service par défaut, ouvrez **User Preferences** dans ClickStack et sélectionnez un service par défaut.

Pour cibler un service spécifique depuis un client MCP, ajoutez l&#39;en-tête `x-service-id: <YOUR_SERVICE_ID>` dans sa configuration. Cet en-tête prend le pas sur le service par défaut.

## Que pouvez-vous faire avec MCP ? {#capabilities}

Une fois connecté, votre assistant IA a accès à un ensemble d’outils couvrant les principaux domaines du service, notamment :

* **Exécution de requêtes** — Recherchez et agrégez des logs, des traces et des métriques à l’aide du constructeur de requêtes, de la syntaxe de recherche ou de SQL brut.
* **Sources de données** — Listez les sources de données disponibles, les connexions aux bases de données, les schémas de colonnes et les clés d’attribut.
* **Tableaux de bord** — Créez, modifiez, supprimez et examinez des tableaux de bord ainsi que leurs tuiles.
* **Alertes** — Créez, modifiez et examinez des alertes ainsi que leur historique des évaluations.
* **Recherches enregistrées** — Créez, modifiez et examinez des définitions de recherches enregistrées réutilisables.
* **Webhooks** — Listez les destinations de webhook disponibles pour les notifications d’alerte.
* **Équipes** — Listez les équipes dont l’utilisateur courant fait partie et identifiez l’équipe active.

L’ensemble des outils proposés est susceptible de s’enrichir au fil du temps. Votre client MCP découvrira automatiquement les outils disponibles lors de sa connexion.

## Dépannage {#troubleshooting}

<Accordion title="Le flux OAuth n'aboutit pas">
  * Vérifiez que votre client MCP prend en charge OAuth 2.0. Les clients qui ne prennent en charge que les jetons Bearer ou le transport stdio ne peuvent pas s&#39;authentifier auprès de l&#39;endpoint Cloud.
  * Assurez-vous que votre navigateur ne bloque pas la fenêtre contextuelle ou la redirection OAuth.
  * Vérifiez que votre compte ClickHouse Cloud a accès à l&#39;organisation et au service.
</Accordion>

<Accordion title="MCP est activé, mais le client ne parvient pas à se connecter">
  * Vérifiez que vous utilisez l&#39;endpoint d&#39;observability (`https://mcp.clickhouse.cloud/clickstack`) et non l&#39;endpoint MCP général dans le cloud (`https://mcp.clickhouse.cloud/mcp`).
  * Vérifiez que [MCP est activé](/fr/products/cloud/features/ai-ml/mcp/remote-mcp#enable-remote-mcp-server) pour le service dans la Console Cloud.
</Accordion>

<Accordion title="Les requêtes sont envoyées au mauvais service">
  Sans l&#39;en-tête `x-service-id`, les requêtes sont dirigées par défaut vers le premier service d&#39;observability provisionné et utilisé par votre compte. Modifiez le service par défaut dans **User Preferences** de ClickStack, ou transmettez l&#39;en-tête pour cibler un service spécifique. Consultez [Cibler un service spécifique](#managed-service-override).
</Accordion>
