ClickHouse Observability intègre un contrôle d’accès basé sur les rôles (RBAC) qui vous permet de définir des rôles personnalisés dotés d’autorisations à granularité fine sur les [tableaux de bord](/fr/clickstack/observability/features/dashboards/overview), les [recherches enregistrées](/fr/clickstack/observability/features/search), les sources, les [alertes](/fr/clickstack/observability/features/alerts), les webhooks et les notebooks. Les autorisations s’appliquent à deux niveaux : l’accès au niveau de la ressource (aucun accès, lecture ou gestion, par type de ressource) et, de manière facultative, des règles à granularité fine qui restreignent l’accès à des ressources individuelles par nom, étiquette ou ID. Le service est fourni avec trois rôles prédéfinis, et vous pouvez créer des rôles personnalisés adaptés aux besoins de votre équipe.

## Prérequis d’accès des utilisateurs {#user-access-prerequisites}

L’authentification au service s’effectue via ClickHouse Cloud. Les utilisateurs doivent appartenir à votre organisation ClickHouse Cloud et disposer d’un accès au service Observability. Pour la gestion des membres de l’organisation, consultez [Gérer les utilisateurs du cloud](/fr/products/cloud/guides/security/cloud-access-management/manage-cloud-users).

Les niveaux d’accès à la Console SQL Cloud correspondent aux accès Observability de la manière suivante :

| Accès à la Console SQL Cloud                         | Accès Observability                                                                                          |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Administrateur de la Console SQL** (accès complet) | Accès complet au service. Obligatoire pour activer les [alertes](/fr/clickstack/observability/features/alerts). |
| **Console SQL en lecture seule** (lecture seule)     | Peut consulter les données d’observability et créer des tableaux de bord.                                    |
| **Aucun accès**                                      | Aucun accès au service.                                                                                      |

Ouvrez **Paramètres de l’équipe → Membres et rôles** pour afficher les membres de l’équipe et leurs rôles Observability actuels. Sélectionnez **Gérer dans la console** pour gérer les membres de l’organisation dans ClickHouse Cloud.

## Rôles prédéfinis {#built-in-roles}

Le service comprend trois rôles système, qui ne peuvent être ni modifiés ni supprimés. Le rôle administrateur est assigné par défaut au créateur de l’équipe.

| Permission                                | Administrateur | Membre | Lecture seule |
| ----------------------------------------- | :------------: | :----: | :-----------: |
| Lire toutes les ressources                |        ✓       |    ✓   |       ✓       |
| Gérer les tableaux de bord                |        ✓       |    ✓   |               |
| Gérer les recherches enregistrées         |        ✓       |    ✓   |               |
| Gérer les sources                         |        ✓       |    ✓   |               |
| Gérer les alertes                         |        ✓       |    ✓   |               |
| Gérer les webhooks                        |        ✓       |    ✓   |               |
| Gérer les notebooks                       |        ✓       |    ✓   |               |
| Modifier les paramètres de l’équipe       |        ✓       |    ✓   |               |
| Créer/supprimer des équipes               |        ✓       |        |               |
| Gérer les utilisateurs et les invitations |        ✓       |        |               |

## Attribuer des rôles aux membres de l’équipe {#assigning-roles}

L’onglet **Membres et rôles** des **Paramètres de l’équipe** répertorie les membres de l’équipe ainsi que leur rôle actuel. Pour changer de rôle, cliquez sur **Modifier** à côté du nom de l’utilisateur, puis sélectionnez un nouveau rôle. Chaque utilisateur dispose d’un seul et unique rôle.

### Rôle par défaut des nouveaux utilisateurs {#default-new-user-role}

Dans **Paramètres de l’équipe** → **Membres et rôles**, utilisez le paramètre **Rôle par défaut des nouveaux utilisateurs**, situé sous la liste des rôles, pour choisir le rôle assigné aux utilisateurs qui rejoignent automatiquement l’équipe. Si aucun rôle par défaut n’est défini, les nouveaux utilisateurs se voient attribuer le rôle **Membre**.

## Autorisations des rôles {#role-permissions}

### Autorisations sur les ressources {#resource-permissions}

Chaque rôle accorde un niveau d’accès par type de ressource. Les trois niveaux sont les suivants :

| Niveau d’accès  | Ce qu’il permet                                                                                 |
| --------------- | ----------------------------------------------------------------------------------------------- |
| **Aucun Accès** | Le type de ressource est entièrement masqué pour le rôle.                                       |
| **Lecture**     | Consulter la ressource et sa configuration, sans pouvoir la créer, la modifier ni la supprimer. |
| **Gérer**       | Contrôle total : créer, modifier et supprimer les ressources de ce type.                        |

Les types de ressources que vous pouvez contrôler sont les suivants :

* **[Tableaux de bord](/fr/clickstack/observability/features/dashboards/overview)** — dispositions de tableaux de bord et graphiques enregistrés.
* **[Recherches enregistrées](/fr/clickstack/observability/features/search)** — requêtes persistées portant sur les journaux, les traces et les événements.
* **Sources** — sources de données utilisées pour interroger les données d’observability.
* **[Alertes](/fr/clickstack/observability/features/alerts)** — règles d’alerte et leurs paramètres de notification.
* **Webhooks** — destinations de notification sortantes (comme Slack, PagerDuty ou des endpoints HTTP génériques) auxquelles les [alertes](/fr/clickstack/observability/features/alerts) envoient leurs notifications. Il ne s’agit pas de l’API d’observability.
* **Carnets** — notebooks d’investigation collaboratifs.

### Autorisations administratives {#administrative-permissions}

Outre les autorisations sur les ressources, chaque rôle comprend deux paramètres administratifs :

* **Utilisateurs** (Aucun Accès · Lecture) — détermine si le rôle peut consulter les membres de l&#39;équipe et leurs rôles. Pour gérer les membres de l&#39;organisation, utilisez **Gérer dans la console**.
* **Équipe** (Lecture · Gérer) — détermine si le rôle peut consulter ou modifier les paramètres de l&#39;équipe, tels que les politiques de sécurité et la configuration RBAC.

### Règles d&#39;accès à granularité fine {#fine-grained-access-rules}

Les tableaux de bord, les recherches enregistrées, les Sources et les Carnets prennent en charge des contrôles à granularité fine qui permettent de restreindre l&#39;accès à des ressources individuelles au sein d&#39;une même catégorie. Utilisez-les lorsque vous devez limiter un rôle à certaines ressources précises plutôt que de lui accorder un accès global à l&#39;ensemble du type de ressource.

#### Accès par défaut ou contrôles à granularité fine {#access-control-modes}

Chaque type de ressource dispose d’un **mode de contrôle d’accès** :

* **Accès par défaut** — applique un niveau d’accès unique (Aucun Accès, Lecture ou Gérer) à toutes les ressources de ce type.
* **Contrôles Granulaires** — permet de définir des règles d’accès qui ciblent des ressources spécifiques selon une condition. Les ressources qui ne correspondent à aucune règle ne sont, par défaut, pas accessibles.

Pour changer de mode, cliquez sur le chevron pour déplier un type de ressource dans l’éditeur de rôles, puis basculez l’interrupteur **Mode de contrôle d’accès**.

#### Configurer les règles d&#39;accès {#configuring-access-rules}

Chaque règle d&#39;accès se compose d&#39;une **condition** et d&#39;un **niveau d&#39;accès**. Les conditions sélectionnent les ressources en fonction de leurs propriétés :

<div className="ch-image-md">
  <Frame>
    ![Infobulle de condition : sélectionner les ressources par nom ou par étiquette (visibles dans le titre) ou par ID (présent dans l'URL)](/images/clickstack/rbac/condition-tip.webp)
  </Frame>
</div>

| Champ de condition | Opérateurs       | Éléments correspondants                                                                                                                                                                                                               | Exemple                                                                                               |
| ------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Name**           | `is`, `contains` | Le nom d&#39;affichage de la ressource, par exemple le titre du tableau de bord.                                                                                                                                                      | Name contains `production` : correspond à tout tableau de bord dont le titre contient « production ». |
| **Étiquette**            | `is`, `contains` | Les étiquettes attribuées à la ressource depuis le panneau des étiquettes, dans le coin supérieur droit de la vue de la ressource. Disponible uniquement pour les tableaux de bord, les recherches enregistrées et les carnets (Notebooks). | Étiquette is `critical` : correspond aux ressources portant l’étiquette « critical ».                         |
| **ID**             | `is`, `contains` | L&#39;identifiant de la ressource, visible dans la barre d&#39;adresse lorsque vous ouvrez la ressource.                                                                                                                              | ID is `abc123` : correspond à une seule ressource précise.                                            |

La capture d&#39;écran suivante montre l&#39;ID du tableau de bord, mis en évidence dans la barre d&#39;adresse, ainsi qu&#39;une étiquette « TESTING » dans le panneau des étiquettes (en haut à droite).

<div className="ch-image-lg">
  <Frame>
    ![Tableau de bord affichant l'ID de la ressource dans la barre d'adresse et une étiquette dans le coin supérieur droit](/images/clickstack/rbac/dashboard-id-and-tag-example.webp)
  </Frame>
</div>

Vous pouvez ajouter plusieurs règles par type de ressource. Chaque règle est évaluée indépendamment selon une logique OR : une ressource est accessible si elle correspond à **au moins une** règle. Les ressources qui ne correspondent à aucune règle ne sont pas accessibles.

<div className="ch-image-md">
  <Frame>
    ![Infobulle sur les règles d'accès et la logique OR](/images/clickstack/rbac/access-rules-tip.webp)
  </Frame>
</div>

**Exemple** : pour accorder à un rôle un accès en lecture seule aux tableaux de bord de test, développez Tableaux de bord, passez en mode Contrôles Granulaires et ajoutez deux règles :

* **Name** `contains` `testing` avec le niveau d&#39;accès **Lecture**
* **Étiquette** `is` `testing` avec le niveau d&#39;accès **Lecture**

Tout tableau de bord correspondant à l&#39;une ou l&#39;autre de ces règles est accessible.

<div className="ch-image-md">
  <Frame>
    ![Deux règles d'accès à granularité fine combinées par OR : Name contains testing avec accès en lecture, et Étiquette is testing avec accès en lecture](/images/clickstack/rbac/dashboard-fine-grained-example.webp)
  </Frame>
</div>

## Politiques de sécurité {#security-policies}

Dans **Paramètres de l’équipe → Membres et rôles → Politiques de sécurité**, l’option **Désactiver les exportations de données** masque les boutons de téléchargement et de copie des données de journal, y compris le détail des lignes, pour tous les membres de l’équipe. Les utilisateurs peuvent toujours sélectionner du texte à l’écran, et l’API ainsi que le serveur MCP continuent de renvoyer des données. Ce paramètre n’empêche pas l’accès aux données sous-jacentes.

Les options relatives à l’IA générative se trouvent dans **Paramètres de l’équipe → API et agents → Configurer l’IA générative**. Pour plus de détails, consultez [Configurer l’IA générative](/fr/clickstack/observability/managing/config#generative-ai).
