    <Info>
      **En bref**

      Ce guide explique comment injecter le SDK pour navigateur dans n&#39;importe quel site web à l&#39;aide de l&#39;[extension Chrome HyperDX](https://github.com/kyreddie/hyperdx-chrome-extension). Aucune modification du code source de l&#39;application cible n&#39;est nécessaire : il suffit de configurer l&#39;extension une seule fois, de naviguer sur le site, puis de consulter les relectures de session dans ClickHouse Observability.

      Durée estimée : 10-15 minutes
    </Info>

## Vue d’ensemble {#overview}

    L&#39;[extension Chrome HyperDX](https://github.com/kyreddie/hyperdx-chrome-extension) injecte le SDK [@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) dans les pages que vous visitez. Elle est utile pour déboguer la relecture de session, le RUM ou la propagation du contexte de traçage sur un site sans modifier sa base de code : par exemple, une application tierce, une construction de production ou un serveur de développement local soumis à une Content Security Policy (CSP) stricte.

    Le SDK est intégré à l’extension (~480 KB) ; les pages n’ont donc pas besoin de charger de scripts depuis un CDN à l’exécution. L’extension tente d’abord une injection de script externe via `chrome-extension://` et se rabat sur l’injection inline lorsque la CSP bloque les scripts provenant de l’extension.

    Contrairement à la [Démo de relecture de session](/fr/clickstack/observability/example-datasets/session-replay), qui instrumente une application de démonstration que vous contrôlez, cette approche instrumente les pages prises en charge que vous ouvrez dans Chrome ; certaines pages limitent toutefois l&#39;injection de scripts. Vous générez les données de session en naviguant sur le site comme n&#39;importe quel utilisateur.

    Pour en savoir plus sur la relecture de session et sa place dans ClickHouse Observability, consultez la page de la fonctionnalité [Relecture de session](/fr/clickstack/observability/features/session-replay).

## Prérequis {#prerequisites}

    * Google Chrome ou un navigateur basé sur Chromium (Edge, Brave, etc.)
    * Un service ClickHouse Observability entièrement géré déjà en place. Consultez le [guide de démarrage de la version entièrement gérée](/fr/clickstack/observability/getting-started).

## Exécution de la démonstration {#running-the-demo}

    <Steps>
      <Step title="Cloner le dépôt de l’extension" id="clone-extension">
        ```shell
        git clone https://github.com/kyreddie/hyperdx-chrome-extension
        cd hyperdx-chrome-extension
        ```
      </Step>

      <Step title="Installer l’extension" id="install-extension">
        1. Ouvrez Chrome et accédez à `chrome://extensions`.
        2. Activez le **Mode développeur** (en haut à droite).
        3. Cliquez sur **Charger l’extension non empaquetée**.
        4. Sélectionnez le répertoire `hyperdx-chrome-extension` que vous avez cloné.

        L’extension apparaît dans votre barre d’outils sous le nom **HyperDX Browser Extension**.
      </Step>

      <Step title="Récupérer vos informations de connexion" id="get-connection-details">
        Ouvrez votre service ClickHouse Observability et accédez à **Paramètres de l’équipe → Télémétrie gérée**. Copiez l’**endpoint OTLP HTTP** et l’**API key**, qui serviront à configurer l’extension.

        Utilisez l’endpoint HTTPS complet fourni, port compris, sans y ajouter `/v1/logs` ni `/v1/traces`.

        <div className="ch-image-lg">
          <Frame>
            ![Télémétrie gérée dans les Paramètres de l’équipe, avec l’endpoint OTLP HTTP et l’API key masqués](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>
      </Step>

      <Step title="Configurer l’extension" id="configure-extension">
        Cliquez sur l’icône **HyperDX Browser Extension** dans la barre d’outils de Chrome et renseignez les paramètres :

        | Champ                                               | Valeur (offre entièrement gérée)             | Remarques                                                                                                            |
        | --------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
        | **Activer la surveillance HyperDX**                 | Activé                                       | Interrupteur principal de l’injection                                                                                |
        | **Nom du service**                                  | `my-frontend-app`                            | Obligatoire — identifie le service dans ClickHouse Observability                                                     |
        | **API Key**                                         | Votre API key de télémétrie gérée            | Obligatoire ; à copier depuis **Paramètres de l’équipe → Télémétrie gérée**                                          |
        | **URL du collecteur**                               | Votre endpoint OTLP HTTP de télémétrie gérée | Remplacez l’URL par défaut de l’extension par l’endpoint indiqué dans **Télémétrie gérée**                           |
        | **Environnement**                                   | `development`                                | Facultatif — définit l’attribut de ressource `deployment.environment`                                                |
        | **Cibles de propagation du contexte de traçage**    | `/api\.myapp\.domain/i, /localhost/i`        | Facultatif — expressions régulières JavaScript, séparées par des virgules, pour la propagation des en-têtes de trace |
        | **Injecter uniquement sur les URL correspondantes** | Désactivé                                    | À activer pour limiter les sites instrumentés                                                                        |
        | **Capturer les journaux de la console**             | Désactivé                                    | À activer pour transmettre la sortie de la console du navigateur                                                     |
        | **Capture réseau avancée**                          | Désactivé                                    | À activer pour capturer le détail des requêtes réseau                                                                |

        Cliquez sur **Save Configuration**, puis rechargez les onglets que vous souhaitez instrumenter.
      </Step>

      <Step title="Parcourir un site et générer une session" id="browse-site">
        Ouvrez n’importe quel site web ou application locale dans Chrome — par exemple, [http://localhost:3000](http://localhost:3000) pour un serveur de développement frontend.

        Utilisez la page normalement : cliquez sur des liens, envoyez des formulaires, déclenchez des erreurs et naviguez d’une vue à l’autre. Si la configuration est valide, l’extension injecte automatiquement le Browser SDK à chaque chargement de page.
      </Step>

      <Step title="Afficher la relecture de session" id="view-session-replay">
        Dans votre service ClickHouse Observability, ouvrez **Sessions client** depuis la barre latérale gauche. Sélectionnez une plage de temps couvrant votre activité de navigation.

        Votre session devrait apparaître dans la liste, avec sa durée et son nombre d’événements. Cliquez sur le bouton ▶️ pour la rejouer.

        Basculez entre les modes **Highlighted** et **All Events** pour ajuster le niveau de détail de la chronologie.
      </Step>
    </Steps>

## Filtrage par URL {#url-filtering}

    Par défaut, l&#39;extension injecte le SDK dans chaque page que vous visitez tant que la supervision est activée. Pour limiter l&#39;injection à certains sites, activez **Injecter uniquement sur les URL correspondantes** et ajoutez un motif par ligne (ou plusieurs motifs séparés par des virgules) :

    | Motif                      | Correspondances                                 |
    | -------------------------- | ----------------------------------------------- |
    | `http://homedepot.com/*`   | HTTP uniquement sur `homedepot.com`             |
    | `*://homedepot.com/*`      | HTTP et HTTPS sur `homedepot.com`               |
    | `*://*.homedepot.com/*`    | Sous-domaines, par exemple `www.homedepot.com`  |
    | `https://localhost:3000/*` | Serveur de développement local sur le port 3000 |

    Rechargez l&#39;onglet après avoir enregistré les motifs d&#39;URL.

## Vérifier l’injection {#verify-injection}

    Ouvrez les DevTools sur une page surveillée (onglet **Console**), rechargez la page et repérez :

    ```text
    [HyperDX Extension] Configuration valid, injecting HyperDX
    [HyperDX Extension] Injected via extension scripts
    [HyperDX Extension] HyperDX initialized
    ```

    Si la CSP bloque les scripts provenant de l&#39;extension, celle-ci consigne un message de repli dans le journal et réessaie au moyen d&#39;une injection inline.

## Dépannage {#troubleshooting}

    <Accordion title="Les sessions n’apparaissent pas dans ClickHouse Observability">
      1. Recherchez dans la console du navigateur des messages de journalisation `[HyperDX Extension]` ou des erreurs
      2. Vérifiez que l’option **Activer la surveillance HyperDX** est activée et que le champ **Nom du service** est renseigné
      3. Vérifiez que les valeurs **URL du collecteur** et **API Key** correspondent à celles indiquées dans **Paramètres de l’équipe → Télémétrie gérée** de votre service
      4. Ajustez l’intervalle de temps dans la vue Sessions client (essayez **Last 15 minutes**)
      5. Forcez l’actualisation du navigateur : `Cmd+Shift+R` (Mac) ou `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="erreurs chrome-extension://invalid/">
      Rechargez l&#39;extension depuis `chrome://extensions`, puis forcez l&#39;actualisation de l&#39;onglet. Ce problème survient lorsque l&#39;extension a été mise à jour ou rechargée alors que des onglets étaient encore ouverts.
    </Accordion>

    <Accordion title="Aucune injection sur un site">
      1. Vérifiez que la supervision est activée et qu&#39;un nom de service est configuré
      2. Si **Injecter uniquement sur les URL correspondantes** est activé, vérifiez que l&#39;URL de la page actuelle correspond à l&#39;un de vos motifs
      3. Certains sites bloquent, via leur CSP, à la fois l&#39;injection de scripts depuis l&#39;origine de l&#39;extension et l&#39;injection de scripts intégrés — l&#39;injection peut alors s&#39;avérer impossible sur ces pages
    </Accordion>

    <Accordion title="HyperDX : apiKey manquante dans la console">
      Saisissez l’API key indiquée dans **Paramètres de l’équipe → Télémétrie gérée**, enregistrez la configuration, puis rechargez la page surveillée. Cette clé est indispensable à l’ingestion entièrement gérée.
    </Accordion>

## Confidentialité {#privacy}

    L&#39;extension injecte du code d&#39;observability dans les pages que vous visitez. Utilisez-la uniquement sur les sites que vous êtes autorisé à déboguer. Ne partagez pas vos clés API et ne les commitez pas dans un système de contrôle de version.

        | **Environment**                  | `development`                                       | Facultatif — définit l&#39;attribut de ressource `deployment.environment`                                                                   |
        | **Trace Propagation Targets**    | `/api\.myapp\.domain/i, /localhost/i`               | Facultatif — expressions régulières JavaScript, séparées par des virgules, pour la propagation des en-têtes de trace                        |
        | **Only inject on matching URLs** | Off                                                 | Activez cette option pour limiter les sites instrumentés                                                                                    |
        | **Capture console logs**         | Off                                                 | Activez cette option pour transmettre la sortie de la console du navigateur                                                                 |
        | **Advanced network capture**     | Off                                                 | Activez cette option pour capturer les requêtes réseau en détail                                                                            |

        Cliquez sur **Save Configuration**, puis rechargez les onglets que vous souhaitez instrumenter.
