    Le HackerNews Analyzer est une application Node.js qui interroge le jeu de données HackerNews hébergé dans la démo publique de ClickHouse. Les interactions avec le tableau de bord génèrent des requêtes vers le backend. Les requêtes qui ne trouvent pas de résultat dans le cache de l&#39;application interrogent également ClickHouse, ce qui ajoute un span HTTPS sortant à la trace.

    Cette démonstration réunit dans une seule application l&#39;auto-instrumentation du backend, les spans des requêtes ClickHouse et la relecture de session dans le navigateur.

## Prérequis {#prerequisites}

    * Des versions de Node.js et de npm compatibles avec [HackerNews Analyzer et ses dépendances](https://github.com/ClickHouse/hn-news-analyzer#readme).
    * Un service ClickHouse Observability entièrement géré déjà en place. Consultez le [guide de démarrage de la version entièrement gérée](/fr/clickstack/observability/getting-started).
    * Un accès réseau à l&#39;endpoint de télémétrie gérée, depuis le serveur de l&#39;application comme depuis votre navigateur.

## Cloner le dépôt {#clone-the-repository}

    Clonez le dépôt [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), installez les dépendances, puis copiez le modèle de fichier env :

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    Vous renseignerez le fichier `.env` au cours des étapes suivantes, puis vous lancerez l&#39;instrumentation depuis ce répertoire.

## Instrumenter l&#39;application {#instrument-the-application}

    <Steps>
      <Step title="Lancez l’application" id="run-the-application">
        Depuis le répertoire `hn-news-analyzer` cloné, démarrez l&#39;application. La source de données ClickHouse pointe par défaut vers le cluster de démonstration public en lecture seule : l&#39;application fonctionne donc sans aucune configuration supplémentaire :

        ```bash
        ./run.sh
        ```

        Ouvrez [http://localhost:5001](http://localhost:5001). Vous y trouverez un sélecteur d’année, des statistiques récapitulatives, un graphique d’activité, des tableaux des principaux utilisateurs et domaines, ainsi qu’un champ de recherche. Explorez l’interface : changez d’année, consultez le détail des articles.

        <Frame>
          <img src="/images/clickstack/getting-started/hackernews_main.webp" alt="L’application HackerNews Analyzer exécutée en local" />
        </Frame>

        À ce stade, l’application est en cours d’exécution, mais n’est pas instrumentée. Elle enverra des données de télémétrie une fois que vous aurez effectué les étapes d’instrumentation ci-dessous.
      </Step>

      <Step title="Configurer l’environnement" id="configure-environment">
        Ouvrez votre service ClickHouse Observability et accédez à **Paramètres de l’équipe → Managed Telemetry**. Copiez l’**endpoint OTLP HTTP** et l’**API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Section Managed Telemetry des Paramètres de l’équipe, affichant l’endpoint OTLP HTTP et l’API key masqués](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        Dans le fichier `.env` de l&#39;application, définissez les valeurs suivantes en remplaçant les caractères de substitution de l’endpoint et de l’API key :

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Conservez le préfixe `https://` dans `OTEL_EXPORTER_OTLP_ENDPOINT` et n&#39;ajoutez pas `/v1/logs`, `/v1/traces` ni `/v1/metrics` : les SDK ajoutent eux-mêmes les chemins propres à chaque signal. Définissez `OTEL_EXPORTER_OTLP_HEADERS` sur `authorization=<your-api-key>` sans préfixe `Bearer`. L&#39;application transmet également cette clé directement au SDK pour navigateur.

        Le SDK pour navigateur utilise le même endpoint et la même API key. `vite.config.ts` les intègre dans le bundle destiné au navigateur, où les visiteurs peuvent les inspecter. Utilisez un service réservé aux tests de cette démonstration et excluez `.env` du contrôle de version.
      </Step>

          <Tab title="Instrumentation manuelle" id="instrument-manually">
            L&#39;instrumentation comporte trois étapes : installer les SDK, modifier la commande de lancement et activer le SDK pour navigateur. Aucune de ces étapes ne modifie la logique métier de l&#39;application.

### Installer le SDK Node {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### Activer le wrapper dans run.sh {#enable-run-sh-wrapper}

            La fin de `run.sh` contient deux lignes `exec`. Commentez la ligne `node` simple et décommentez la ligne instrumentée :

            ```diff
             # BEFORE: plain node, no instrumentation:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # AFTER: same source, wrapped by opentelemetry-instrument:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            Continuez à lancer l&#39;application via `scripts/entrypoint.js`. Ce shim appelle `require('console')` afin que la capture de la console encapsule `console.log`. Si vous pointez `opentelemetry-instrument` directement vers `dist/server/index.js`, les traces sont bien envoyées, mais les journaux sont ignorés sans le moindre avertissement.

### Activer le SDK pour navigateur {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            Dans `src/web/telemetry.ts`, décommentez l&#39;import, le bloc `HyperDX.init` et l&#39;appel `HyperDX.addAction` dans `recordAction` :

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` et `__OTLP_AUTH_TOKEN__` sont des constantes de compilation injectées par `vite.config.ts` à partir des mêmes valeurs `OTEL_EXPORTER_OTLP_*` que celles utilisées par le backend.
          </Tab>

          <Tab title="Utiliser une branche pré-instrumentée" id="use-the-instrumented-branch">
            Pour passer l&#39;étape d&#39;instrumentation et partir d&#39;une application déjà instrumentée, faites un checkout de la [branche `instrumented`](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented).

            ```bash
            git checkout instrumented
            npm install
            ```

            N&#39;exécutez pas `./reset.sh` sur cette branche, sauf si vous souhaitez supprimer les SDK.
          </Tab>


        Vérifiez que la bannière de démarrage affiche trois lignes `Health check passed` pour `/v1/traces`, `/v1/metrics` et `/v1/logs`. Rechargez l&#39;onglet du navigateur pour que Vite serve le bundle mis à jour, puis changez d&#39;année et cliquez sur des articles pour générer du trafic.

        Ouvrez votre service ClickHouse Observability :

        1. Accédez à **Recherche**, sélectionnez la source **Logs** et réglez l&#39;intervalle de temps sur **Last 15 minutes**. Filtrez `ServiceName` sur `hn-analyzer-api` pour afficher les logs du backend.

        4. Ouvrez l&#39;**Explorateur de graphiques**, sélectionnez **Time Series** et la source **Metrics**, puis choisissez une métrique émise par l&#39;application.     HackerNews Analyzer est une application Node.js qui interroge le jeu de données HackerNews hébergé dans la démo publique ClickHouse. Chaque graphique, tableau et champ de recherche correspond à une véritable requête ClickHouse : chaque interaction produit donc une trace dont le span principal est l’appel HTTPS émis par le backend vers ClickHouse.

    Cette démo diffère de la [démo de relecture de session](/fr/clickstack/observability/example-datasets/session-replay), qui instrumente une application s’exécutant uniquement dans le navigateur et envoie la télémétrie à ClickHouse Observability. Ici, vous obtenez l’auto-instrumentation du backend, les spans des requêtes ClickHouse et la relecture de session à partir d’une seule et même application.

## Prérequis {#prerequisites-self-configured}

    * Node 18+ et npm
    * Un service Self-managed ClickHouse Observability existant et un collecteur d’ingestion en cours d’exécution.
    * Le point de terminaison OTLP HTTP du collecteur, joignable à la fois depuis le serveur de l’application et depuis votre navigateur. N’utilisez `http://localhost:4318` que si le collecteur s’exécute sur la même machine.
    * Le `OTLP_AUTH_TOKEN` du collecteur, s’il est configuré. Définissez les en-têtes sur `authorization=<token>`, sans préfixe `Bearer`. Si le collecteur n’exige pas d’authentification, laissez `authorization=` vide. Il s’agit des identifiants d’ingestion du collecteur, et non des identifiants de votre base de données ClickHouse.
