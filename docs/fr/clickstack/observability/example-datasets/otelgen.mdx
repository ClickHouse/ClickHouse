  <Tab title="Entièrement géré">
    <BetaBadge label="Offre bêta" />

    [`otelgen`](https://github.com/krzko/otelgen) est un petit outil CLI écrit en Go qui génère des logs, des traces et des métriques OTLP synthétiques. Utilisez-le pour envoyer des données de test vers l’offre entièrement gérée ClickHouse Observability, puis explorez les résultats dans Recherche et dans l’Explorateur de graphiques.

    <Steps>
      <Step title="Prérequis" id="prerequisites-managed">
        Vous devez disposer d’un service ClickHouse Observability entièrement géré et d’un accès réseau à son endpoint de télémétrie gérée. Consultez le [guide de démarrage de l’offre entièrement gérée](/fr/clickstack/observability/getting-started).
      </Step>

      <Step title="Installer otelgen" id="install-otelgen-managed">
        Installez-le avec Homebrew :

        ```shell
        brew install krzko/tap/otelgen
        ```

        Ou avec Go :

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="Définir les variables d’environnement" id="set-env-vars-managed">
        Ouvrez votre service ClickHouse Observability et accédez à **Team Settings → Managed Telemetry**. Copiez l’**OTLP HTTP endpoint** et l’**API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Section Managed Telemetry de Team Settings affichant l’endpoint OTLP HTTP et l’API key masqués](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        Renseignez l’endpoint sous la forme hôte et port, sans le préfixe `https://`. Par exemple, `https://YOUR_OTEL_ENDPOINT:4318` devient `YOUR_OTEL_ENDPOINT:4318`. N’ajoutez pas de chemin de signal tel que `/v1/logs`.

        ```shell
        export OTEL_ENDPOINT='YOUR_OTEL_ENDPOINT:4318'
        printf "API key: "
        read -r -s OTEL_API_KEY
        printf "\n"
        export OTEL_API_KEY
        ```

        Les commandes ci-dessous utilisent `--protocol http` sans `--insecure` : `otelgen` se connecte donc en HTTPS avec vérification du certificat. Retirer `https://` de l’argument d’endpoint ne désactive pas TLS. Chaque requête est authentifiée par votre API key de télémétrie gérée.
      </Step>

      <Step title="Générer des traces" id="generate-traces-managed">
        Envoyez une courte rafale de traces comportant plusieurs spans :

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate` indique le nombre de traces par seconde et `--duration` la durée d’exécution en secondes. N’utilisez pas `--insecure`, afin que la connexion passe par HTTPS avec vérification du certificat.
      </Step>

      <Step title="Générer des logs" id="generate-logs-managed">
        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          logs multi --duration 10
        ```
      </Step>

      <Step title="Générer des métriques" id="generate-metrics-managed">
        Exécutez la commande suivante pour générer des métriques, puis appuyez sur `Ctrl+C` au bout de quelques secondes pour l’arrêter.

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          metrics sum
        ```

        `otelgen` prend également en charge les sous-commandes `gauge`, `histogram`, `up-down-counter` et `exponential-histogram` de `metrics`.
      </Step>

      <Step title="Vérifier dans ClickHouse Observability" id="verify-managed">
        Dans votre service ClickHouse Observability, ouvrez **Search** et passez d’une source à l’autre entre **Logs** et **Traces** pour vérifier l’arrivée de nouveaux événements. Réglez la plage de temps sur **Last 15 minutes** et recherchez le nom de service par défaut `otelgen`.

        Ouvrez **Chart Explorer**, sélectionnez **Metrics**, puis affichez `otelgen.metrics.sum` dans un graphique pour vérifier l’ingestion des métriques.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Autogéré">
    [`otelgen`](https://github.com/krzko/otelgen) est un petit CLI écrit en Go qui génère des logs, des traces et des métriques OTLP synthétiques. Utilisez-le pour vérifier qu’un collecteur OpenTelemetry ClickStack existant accepte bien les données et que les événements apparaissent dans l’UI d’observability.

    Ce guide suppose que le collecteur est déjà en cours d’exécution, avec des endpoints OTLP sur `4317` (gRPC) et `4318` (HTTP).

    <Steps>
      <Step title="Prérequis" id="prerequisites-managed-self-configured">
        Ce guide suppose que vous avez suivi le [Guide de démarrage de ClickHouse Observability — Self-managed](/fr/clickstack/self-configured/getting-started/managed) et que vous disposez d’un collecteur OpenTelemetry en cours d’exécution, dont les endpoints OTLP gRPC (`4317`) et HTTP (`4318`) sont accessibles depuis la machine sur laquelle vous exécutez `otelgen`. Si vous avez [sécurisé le collecteur](/fr/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured) avec un `OTLP_AUTH_TOKEN`, gardez cette valeur à portée de main.
      </Step>

      <Step title="Installer otelgen" id="install-otelgen-managed-self-configured">
        Installez-le avec Homebrew :

        ```shell
        brew install krzko/tap/otelgen
        ```

        Ou avec Go :

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="Définir les variables d’environnement" id="set-env-vars-managed-self-configured">
        Exportez l’endpoint du collecteur et, si celui-ci est sécurisé, le jeton d’authentification :

        ```shell
        export OTEL_ENDPOINT=<host>:4317
        export OTLP_AUTH_TOKEN=<your_otlp_auth_token>
        ```

        Indiquez l’hôte et le port de votre collecteur. Pour un collecteur exécuté sur la même machine, il s’agit de `localhost:4317`.

        <Info>
          **Collecteur non sécurisé**

          Par défaut, le collecteur OpenTelemetry ClickStack n’exige aucune authentification. Si vous n’avez pas suivi la section [Sécuriser le collecteur](/fr/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured) pour définir un `OTLP_AUTH_TOKEN`, ignorez `OTLP_AUTH_TOKEN` ici et supprimez l’option `--header` des commandes ci-dessous.
        </Info>
      </Step>

      <Step title="Générer des traces" id="generate-traces-managed-self-configured">
        Envoyez une courte rafale de traces comportant plusieurs spans :

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate` correspond au nombre de traces par seconde et `--duration` à la durée d’exécution en secondes. `--insecure` désactive TLS sur la connexion gRPC, ce qui est nécessaire lorsque `otelgen` cible le port OTLP en clair du collecteur.
      </Step>

      <Step title="Générer des logs" id="generate-logs-managed-self-configured">
        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          logs multi
        ```
      </Step>

      <Step title="Générer des métriques" id="generate-metrics-managed-self-configured">
        Les sous-commandes de métriques ne tiennent pas compte de `--duration`. Exécutez la commande, puis appuyez sur `Ctrl+C` au bout de quelques secondes pour l’arrêter.

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 \
          metrics sum
        ```

        `otelgen` prend également en charge les sous-commandes `gauge`, `histogram`, `up-down-counter` et `exponential-histogram` sous `metrics`.
      </Step>

      <Step title="Vérifier dans l’UI d’observability" id="verify-managed-self-configured">
        Ouvrez l’UI d’observability depuis la Console ClickHouse Cloud. Dans la vue `Search`, basculez la source entre `Logs` et `Traces` pour confirmer l’arrivée de nouveaux événements. Réglez la plage temporelle sur `Last 15 minutes`. Ouvrez le `Chart Explorer`, sélectionnez `Metrics` et créez un graphique à partir de l’un des noms de métriques produits par `otelgen` (par exemple `otelgen.metrics.sum`) afin de vérifier l’ingestion des métriques.
      </Step>
    </Steps>
  </Tab>
