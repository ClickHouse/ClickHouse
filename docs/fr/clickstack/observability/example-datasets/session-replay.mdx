<Info>
  **En bref**

  Ce guide explique comment instrumenter une application web pour la relecture de session à l’aide du SDK pour navigateur et de ClickHouse Observability, en version entièrement gérée ou autogérée. Contrairement à d’autres jeux de données d’exemple qui chargent des données prégénérées, cette démonstration propose une application interactive dans laquelle vous générez vous-même des données de session au fil de vos interactions.

  Durée : 10-15 minutes
</Info>

## Vue d’ensemble {#overview}

L&#39;[application de démonstration de relecture de session](https://github.com/ClickHouse/clickstack-session-replay-demo) est un explorateur de documentation développé en JavaScript natif (vanilla). Elle montre à quel point l&#39;instrumentation de la relecture de session peut être légère : une seule balise script et un seul appel d&#39;initialisation suffisent pour capturer automatiquement les interactions des utilisateurs.

Le dépôt comprend deux branches :

* **`main`** — entièrement instrumentée et prête à l&#39;emploi
* **`pre-instrumented`** — une version épurée sans instrumentation, avec des commentaires dans le code indiquant où l&#39;ajouter

Ce guide s&#39;appuie d&#39;abord sur la branche `main` pour vous montrer la relecture de session en action, puis passe en revue le code d&#39;instrumentation afin que vous puissiez reproduire la même approche dans votre propre application.

Pour en savoir plus sur la relecture de session et sa place dans ClickStack, consultez la page consacrée à la fonctionnalité [Relecture de session](/fr/clickstack/observability/features/session-replay).

## Prérequis {#prerequisites}

* Docker installé et en cours d’exécution, avec Docker Compose disponible
* Port 3000 libre pour l’application de démonstration
* Un service ClickHouse Observability existant, entièrement géré ou autogéré
* Un accès réseau depuis votre navigateur vers l’endpoint de télémétrie configuré ci-dessous

## Exécution de la démo {#running-the-demo}

<Steps>
  <Step title="Clonez le dépôt" id="clone-repository">
    ```shell
    git clone https://github.com/ClickHouse/clickstack-session-replay-demo
    cd clickstack-session-replay-demo
    ```
  </Step>

  <Step title="Configurer la connexion" id="configure-connection">
    Choisissez votre mode de déploiement :

    <Tabs>
      <Tab title="Entièrement géré">
        <BetaBadge label="Offre bêta" />

        Vous devez disposer d’un [service entièrement géré](/fr/clickstack/observability/getting-started) existant. ClickHouse fournit le collecteur d’ingestion.

        Dans votre service ClickHouse Observability, ouvrez **Team Settings → Data → Managed Telemetry** et copiez l’**OTLP HTTP endpoint** et l’**API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Managed Telemetry affichant l’endpoint OTLP HTTP et l’API key masqués](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        Définissez `CLICKSTACK_UI_URL` sur l’URL de l’UI de votre service managé. Pour ouvrir directement les replays, copiez l’URL affichée dans le navigateur depuis **Client Sessions**. Remplacez les caractères de substitution ci-dessous par vos informations de connexion, puis exécutez ces commandes dans votre terminal :

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
        export CLICKSTACK_API_KEY='Bearer YOUR_API_KEY'
        export CLICKSTACK_UI_URL='YOUR_OBSERVABILITY_UI_URL'
        ```

        Conservez le préfixe `https://` et n’ajoutez pas de chemin de signal tel que `/v1/traces`. Pour l’ingestion entièrement gérée, incluez le préfixe `Bearer `, comme indiqué ci-dessus.

        `CLICKSTACK_UI_URL` définit la cible des liens **Open Observability** de la démonstration ; cette variable est indépendante de l’endpoint d’ingestion de la télémétrie.

        Le serveur transmet l’endpoint de télémétrie et l’API key au SDK pour navigateur. La clé d’ingestion étant visible dans le navigateur, utilisez un service de test pour cette démonstration.
      </Tab>

      <Tab title="Autogéré">
        Vous devez disposer d’un [service autogéré](/fr/clickstack/self-configured/getting-started/managed) existant et d’un collecteur OpenTelemetry ClickStack en cours d’exécution, connecté à ce service. Consultez [Ingestion avec OpenTelemetry](/fr/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured) pour les instructions de connexion, ou le [guide de déploiement](/fr/clickstack/self-configured/deployment/managed#start-a-collector-existing) pour démarrer un collecteur.

        L&#39;endpoint OTLP HTTP du collecteur doit être accessible depuis votre navigateur, et la configuration CORS doit autoriser `http://localhost:3000`. L&#39;UI doit prendre en charge l&#39;attribut `session.id` du nouveau SDK dans Client Sessions ; consultez les [exigences de compatibilité du SDK](https://github.com/ClickHouse/clickstack-browser#clickstack-versions).

        Définissez `CLICKSTACK_OTEL_ENDPOINT` sur l&#39;endpoint OTLP HTTP de votre collecteur, sans chemin de signal tel que `/v1/traces`. Définissez `CLICKSTACK_UI_URL` sur l&#39;URL **Client Sessions** copiée depuis l&#39;UI de votre service autogéré.

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
        export CLICKSTACK_API_KEY='YOUR_COLLECTOR_TOKEN'
        export CLICKSTACK_UI_URL='YOUR_CLIENT_SESSIONS_URL'
        ```

        Utilisez le jeton d&#39;authentification configuré sur le récepteur de votre collecteur. Pour un collecteur ClickStack sécurisé avec `OTLP_AUTH_TOKEN`, utilisez cette valeur sans préfixe `Bearer`. Si votre récepteur n&#39;exige pas d&#39;authentification, définissez `CLICKSTACK_API_KEY` sur une chaîne vide. N&#39;utilisez pas ici le mot de passe de votre base de données ClickHouse.

        Le jeton d&#39;ingestion est transmis au SDK pour navigateur et reste donc visible dans le navigateur. Les identifiants de la base de données ClickHouse utilisés par le collecteur restent sur celui-ci.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Démarrez l’application de démonstration" id="start-demo-app">
    Depuis le répertoire du dépôt, exécutez cette commande dans le terminal où vous avez exporté les variables de connexion :

    ```shell
    docker compose --profile demo up --build --no-deps demo-app
    ```

    `--no-deps` démarre uniquement l&#39;application de démonstration, en utilisant l&#39;endpoint de télémétrie que vous avez configuré. Cette option ne démarre pas le service ClickStack local fourni avec le dépôt.

    Ouvrez [http://localhost:3000](http://localhost:3000) dans votre navigateur et interagissez avec l&#39;application : recherchez des sujets, filtrez par catégorie, consultez des exemples de code et ajoutez des éléments à vos favoris.

      </Frame>
    </div>

    Le SDK pour navigateur capture la session et l&#39;envoie à l&#39;endpoint de télémétrie que vous avez configuré.

## L&#39;instrumentation {#instrumentation}

L&#39;application de démonstration montre qu&#39;il faut très peu de code pour activer la relecture de session : deux ajouts à l&#39;application suffisent. Les exemples ci-dessous utilisent le nouveau SDK navigateur ClickStack :

**1. Inclure le SDK (`app/public/index.html`) :**

```html
<script src="https://cdn.jsdelivr.net/npm/@clickhouse/clickstack-browser@1.0.0/dist/clickstack.iife.js" integrity="sha384-NW4JhbuY4Thx4fMuqFwKvifcPn7ad9dJ7DU/MTxhkoHeadG27i4F38Yo1Gz6y0WA" crossorigin="anonymous"></script>
```

**2. Initialiser le SDK pour navigateur (`app/public/js/app.js`) :**

```javascript
window.ClickStack.init({
  endpoint: window.CLICKSTACK_CONFIG.endpoint,
  apiKey: window.CLICKSTACK_CONFIG.apiKey,
  serviceName: 'clickhouse-session-replay-demo',
  console: 'debug',
});
```

`app/server.js` fournit `window.CLICKSTACK_CONFIG` à partir des variables d’environnement `CLICKSTACK_OTEL_ENDPOINT`, `CLICKSTACK_API_KEY` et `CLICKSTACK_UI_URL`. Le SDK utilise l’endpoint et l’API key, tandis que les liens de démonstration utilisent l’URL de l’UI. Le SDK capture la relecture de session, les journaux de la console, les requêtes réseau et les erreurs sans modifier la logique métier de l&#39;application.

Le texte et les valeurs d’entrée sont masqués par défaut. Consultez les [contrôles de confidentialité du SDK pour navigateur](/fr/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy) avant de modifier les paramètres de masquage.

### Essayez par vous-même {#try-it-yourself}

Pour instrumenter l’application à partir de zéro, arrêtez la démo en cours avec `Ctrl+C`, puis basculez sur la branche `pre-instrumented` :

```shell
git checkout pre-instrumented
```

Cette branche contient la même application, mais sans le SDK pour navigateur activé. Des commentaires dans le code des fichiers `app/public/index.html` et `app/public/js/app.js` indiquent où ajouter les deux extraits ci-dessus. Conservez les variables de connexion configurées précédemment, puis reconstruisez et démarrez l&#39;application :

```shell
docker compose --profile demo up --build --no-deps demo-app
```

Rechargez la démo dans votre navigateur, puis interagissez avec elle pour générer une nouvelle session.

## Dépannage {#troubleshooting}

### Les sessions n’apparaissent pas {#sessions-not-appearing}

1. Recherchez d’éventuelles erreurs dans la console du navigateur
2. Vérifiez que l’application de démonstration est en cours d’exécution : `docker compose ps demo-app`
3. Assurez-vous que les variables `CLICKSTACK_OTEL_ENDPOINT` et `CLICKSTACK_API_KEY` sont définies dans le terminal utilisé pour démarrer l’application. Si vous les modifiez, relancez la commande de démarrage et rechargez l’onglet du navigateur.
4. En mode autogéré, vérifiez les erreurs d’export du collecteur, la configuration CORS et les exigences de compatibilité du SDK mentionnées ci-dessus
5. Ajustez l’intervalle de temps dans la vue Sessions client (essayez **Last 15 minutes**)
6. Forcez l’actualisation du navigateur : `Cmd+Shift+R` (Mac) ou `Ctrl+Shift+R` (Windows/Linux)

### Erreurs 401 Non autorisé {#401-errors}

L’API key n’est pas correctement définie. Vérifiez que vous avez :

1. Exporté `CLICKSTACK_API_KEY` dans votre terminal avec la valeur correspondant à votre mode de déploiement
2. Démarré l’application de démonstration dans le **même terminal** que celui où vous l’avez exportée
3. Pour l’option entièrement gérée, utilisé l’API key d’ingestion indiquée dans **Paramètres de l’équipe → Données → Managed Telemetry**, avec le préfixe `Bearer `. Pour l’option autogérée, utilisé le jeton du récepteur de votre collecteur, sans ce préfixe.

## Nettoyage {#cleanup}

Fermez les onglets de démonstration ouverts dans le navigateur pour arrêter la télémétrie du navigateur, puis appuyez sur `Ctrl+C` dans le terminal où s&#39;exécute l&#39;application. Pour l&#39;arrêter depuis un autre terminal, exécutez cette commande depuis le répertoire du dépôt :

```bash
docker compose stop demo-app
```

Cette opération arrête l&#39;application locale ; les données de télémétrie déjà ingérées dans votre service y sont conservées.
