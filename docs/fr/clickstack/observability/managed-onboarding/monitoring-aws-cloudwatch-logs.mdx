Ce guide explique comment transférer les logs AWS CloudWatch vers Self-managed ClickHouse Observability à l&#39;aide du [récepteur `awscloudwatch`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver) d&#39;OpenTelemetry, puis comment les consulter dans l&#39;interface utilisateur de ClickStack.

Nous allons exécuter un collecteur distinct qui interroge CloudWatch via l&#39;API AWS et transfère les événements vers votre collecteur ClickStack via OTLP. Placez ce collecteur dans le même compte AWS et la même région que les groupes de journaux afin de réduire au minimum la latence et le coût des appels API.

Ce guide suppose que vous avez suivi le guide [Configuration de votre collecteur OpenTelemetry](/fr/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) et qu&#39;un collecteur ClickStack est en cours d&#39;exécution.

Le collecteur ClickStack peut être déployé soit sous forme de **conteneur Docker** (voir [Configuration de votre collecteur OpenTelemetry](/fr/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)), soit sous forme de **release Helm** dans Kubernetes, à l&#39;aide du chart Helm OpenTelemetry amont et de l&#39;image du collecteur ClickStack (voir [Déploiement du collecteur](/fr/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)). **Assurez-vous d&#39;avoir noté son point de terminaison OTLP** ainsi que le `OTLP_AUTH_TOKEN` défini lors de son déploiement.

<Steps>
  <Step title="Préparez les prérequis" id="gather-prerequisites">
    Vous aurez besoin des éléments suivants :

    * Un **compte AWS** comportant un ou plusieurs groupes de journaux CloudWatch, ainsi que des identifiants disposant des autorisations IAM ci-dessous.
    * Un hôte sur lequel **Docker** est installé, disposant d’un accès à l’API AWS et d’un accès réseau sortant vers votre collecteur ClickStack. Il s’agit généralement d’une instance EC2 située dans le même compte AWS et la même région que les groupes de journaux.
    * Le **point de terminaison OTLP** de votre collecteur ClickStack, joignable depuis cet hôte. Si le collecteur s’exécute dans Docker sur la même machine, utilisez `http://host.docker.internal:4318` (voir l’encadré dans [Configurer le récepteur CloudWatch](#configure-receiver)). Pour un collecteur distant, utilisez son URL complète, par exemple `https://otel.example.com:4318`.
    * La valeur `OTLP_AUTH_TOKEN` que vous avez définie sur votre collecteur ClickStack. Si vous ne l’avez pas sécurisé, vous pouvez supprimer l’en-tête `authorization` de la configuration ci-dessous.
  </Step>

  <Step title="Configurer les identifiants AWS" id="configure-aws">
    Le récepteur lit les identifiants AWS depuis les variables d’environnement standard. Exportez-les sur l’hôte qui exécutera le collecteur.

    **Pour les utilisateurs d’AWS SSO :**

    ```shell
    aws sso login --profile YOUR_PROFILE_NAME
    eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
    aws sts get-caller-identity
    ```

    **Pour les utilisateurs IAM disposant d’identifiants à long terme :**

    ```shell
    export AWS_ACCESS_KEY_ID="your-access-key-id"
    export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
    export AWS_REGION="us-east-1"
    aws sts get-caller-identity
    ```

    Les identifiants doivent disposer de la politique IAM suivante pour lire les logs CloudWatch :

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Remplacez `YOUR_ACCOUNT_ID` par l’ID de votre compte AWS.

    <Info>
      **Identifiants en production**

      En production, privilégiez les identifiants associés à l’instance plutôt que des clés à longue durée de vie : un rôle IAM sur EC2, IRSA sur EKS ou un rôle de tâche sur ECS. La configuration du collecteur ci-dessous fonctionne telle quelle, sans aucune variable d’environnement d’identification, dès lors que le récepteur peut obtenir les identifiants auprès du service de métadonnées d’instance.
    </Info>
  </Step>

  <Step title="Configurer le récepteur CloudWatch" id="configure-receiver">
    Exportez l&#39;endpoint de votre collecteur ClickStack ainsi que votre jeton d&#39;authentification, puis créez un fichier `otel-collector-config.yaml`.

    <Info>
      **Configuration sur un même hôte**

      L&#39;exemple ci-dessous part du principe que le collecteur ClickStack et ce collecteur CloudWatch s&#39;exécutent sur le même hôte ; le récepteur s&#39;y connecte donc via `host.docker.internal` (l&#39;adresse de l&#39;hôte Docker vue depuis un conteneur). Si votre collecteur ClickStack se trouve ailleurs (service in-cluster, URL publique, adresse IP privée), indiquez son adresse dans `OTEL_COLLECTOR_ENDPOINT` ci-dessous.
    </Info>

    ```shell
    export OTEL_COLLECTOR_ENDPOINT="http://host.docker.internal:4318"
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    ```

    <Accordion title="Identifier les groupes de journaux disponibles dans votre compte">
      Avant de modifier la configuration, listez les groupes de journaux existants dans votre région afin de choisir des noms réels (et de vérifier que la région est correcte) :

      ```shell
      aws logs describe-log-groups --region eu-central-1 \
        --query 'logGroups[].logGroupName' --output table
      ```

      Exemple de sortie :

      ```text
      -------------------------------
      |      DescribeLogGroups      |
      +-----------------------------+
      |  /aws-glue/jobs/error       |
      |  /aws-glue/jobs/logs-v2     |
      |  /aws-glue/jobs/output      |
      |  /aws-glue/sessions/error   |
      |  /aws-glue/sessions/output  |
      +-----------------------------+
      ```

      Reprenez directement les noms de cette liste dans le bloc `groups.named` de l&#39;exemple 1 ci-dessous. Pour le compte ci-dessus, la section des groupes nommés deviendrait :

      ```yaml
      groups:
        named:
          /aws-glue/jobs/error:
          /aws-glue/jobs/logs-v2:
          /aws-glue/jobs/output:
          /aws-glue/sessions/error:
          /aws-glue/sessions/output:
      ```

      Si les groupes souhaités partagent un préfixe commun (ici `/aws-glue/`), vous pouvez également utiliser l&#39;exemple 2 avec `prefix: /aws-glue/` au lieu de les lister un par un.
    </Accordion>

    **Exemple 1 : groupes de journaux nommés (recommandé)**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws-glue/jobs/error:
              /aws-glue/jobs/output:
              /aws-glue/sessions/error:

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    **Exemple 2 : Découverte automatique des groupes de journaux par préfixe**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            autodiscover:
              limit: 100
              prefix: /aws-glue/

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    Principaux paramètres à ajuster :

    * `region` : la région où se trouvent vos groupes de journaux.
    * `poll_interval` (`1m` par défaut). Des valeurs plus faibles permettent d’obtenir des logs quasiment en temps réel, au prix d’un plus grand nombre d’appels à l’API AWS.
    * `groups.named` pour une liste explicite, ou `groups.autodiscover.prefix` pour récupérer tous les groupes correspondant à un préfixe.

    Pour la liste complète des options, consultez la [documentation du récepteur CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver).

    <Info>
      **Logs récents uniquement**

      Lors de la première exécution, le récepteur enregistre un point de contrôle à l’heure actuelle et ne récupère que les logs postérieurs à ce moment. Les logs antérieurs ne sont pas récupérés rétroactivement.
    </Info>
  </Step>

  <Step title="Démarrez le collecteur de réception" id="start-collector">
    Créez un fichier `docker-compose.yaml` à côté de `otel-collector-config.yaml`. L’entrée `extra_hosts` permet au conteneur de joindre, via `host.docker.internal`, un collecteur ClickStack exécuté sur le même hôte. Le montage de type bind en syntaxe longue renvoie explicitement une erreur si le fichier de configuration est absent, au lieu de créer silencieusement un répertoire vide :

    ```shell
    cat > docker-compose.yaml <<'EOF'
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:latest
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_COLLECTOR_ENDPOINT
          - OTLP_AUTH_TOKEN
        extra_hosts:
          - "host.docker.internal:host-gateway"
        restart: unless-stopped
    EOF
    ```

    Démarrez le collecteur :

    ```shell
    docker compose up -d
    ```

    Suivez ses log en continu pour vérifier qu&#39;il interroge périodiquement CloudWatch et exporte les données vers votre collecteur ClickStack :

    ```shell
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Vérifiez dans l’interface utilisateur de ClickStack" id="confirm-in-ui">
    Ouvrez votre service dans la [Console ClickHouse Cloud](https://console.clickhouse.cloud) et sélectionnez **ClickStack** dans le menu de gauche.

    <div className="ch-image-lg">
      <Frame>
        ![Lancer ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    Dans la vue **Recherche**, définissez la source sur `Logs` et l&#39;intervalle de temps sur **Last 15 minutes**. Les événements CloudWatch devraient apparaître au bout de quelques intervalles d&#39;interrogation.

    <div className="ch-image-lg">
      <Frame>
        ![Vue de recherche ClickStack avec les logs CloudWatch](/images/clickstack/cloudwatch/log-search-view-clickstack.webp)
      </Frame>
    </div>

    Chaque événement inclut le groupe et le flux d&#39;origine sous forme d&#39;attributs de ressource :

    * `ResourceAttributes['aws.region']` : la région AWS (par exemple `eu-central-1`)
    * `ResourceAttributes['cloudwatch.log.group.name']` : le groupe de journaux d&#39;origine
    * `ResourceAttributes['cloudwatch.log.stream']` : le flux de journaux d&#39;origine
    * `Body` : la ligne de journal d&#39;origine

    Remplacez la recherche par `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body` pour afficher ces attributs :

    <div className="ch-image-lg">
      <Frame>
        ![Vue de recherche ClickStack avec les logs CloudWatch et leurs attributs](/images/clickstack/cloudwatch/log-search-attributes-clickstack.webp)
      </Frame>
    </div>

    Sélectionnez une entrée de journal pour en examiner les métadonnées :

    <div className="ch-image-lg">
      <Frame>
        ![Attributs CloudWatch dans la vue détaillée du log](/images/clickstack/cloudwatch/error-log-column-values-clickstack.webp)
      </Frame>
    </div>

    Si rien n&#39;apparaît :

    * Exécutez `aws sts get-caller-identity` sur l&#39;hôte du collecteur pour vérifier que les identifiants sont valides.
    * Suivez les logs du collecteur avec `docker compose logs -f otel-collector` et recherchez `AccessDeniedException` (IAM), des erreurs `security token` (identifiants SSO expirés), `ResourceNotFoundException` (faute de frappe dans le nom du groupe de journaux ou mauvaise région) ou `connection refused` (l&#39;endpoint de votre collecteur ClickStack est injoignable depuis le conteneur ; voir la remarque sur `host.docker.internal` dans [Configurer le récepteur CloudWatch](#configure-receiver)).
    * Vérifiez que `OTEL_COLLECTOR_ENDPOINT` est joignable depuis le conteneur : `docker compose exec otel-collector wget -qO- ${OTEL_COLLECTOR_ENDPOINT}/v1/logs -S 2>&1 | head -5`.
    * Vérifiez que `OTLP_AUTH_TOKEN` correspond à la valeur définie sur votre collecteur ClickStack.
  </Step>

  <Step title="Importer le tableau de bord CloudWatch (facultatif)" id="import-dashboard">
    Un tableau de bord préconfiguré présentant le volume de journaux, la ventilation par sévérité et la distribution des erreurs est disponible au téléchargement.

    <TrackedLink href={'https://clickhouse-docs-assets.s3.us-east-1.amazonaws.com/examples/cloudwatch-logs-dashboard.json'} download="cloudwatch-logs-dashboard.json" eventName="docs.cloudwatch_logs_monitoring.dashboard_download">Téléchargez `cloudwatch-logs-dashboard.json`</TrackedLink>, puis, dans l’interface utilisateur de ClickStack, accédez à **Tableaux de bord** et cliquez sur **Importer**.

    <div className="ch-image-lg">
      <Frame>
        ![Bouton d’import de tableau de bord](/images/clickstack/clickstack-import-dashboard.webp)
      </Frame>
    </div>

    Téléversez le fichier JSON, puis cliquez sur **Terminer l’Import**.

    <div className="ch-image-lg">
      <Frame>
        ![Boîte de dialogue de finalisation de l’import](/images/clickstack/cloudwatch/finish-clickstack-import.webp)
      </Frame>
    </div>
  </Step>
