Collectez les logs AWS CloudWatch avec un collecteur OpenTelemetry et envoyez-les vers ClickHouse Observability. Utilisez le [jeu de données de démonstration](#demo-dataset) pour tester l&#39;intégration sans avoir à configurer l&#39;accès AWS.

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Docker avec Docker Compose pour exécuter les exemples de collecteur, ou un déploiement existant d&#39;OpenTelemetry Collector Contrib
* Pour vos propres logs, un compte AWS disposant de groupes de journaux CloudWatch, l&#39;AWS CLI v2 et des identifiants dotés des autorisations indiquées ci-dessous
* Pour la démonstration, `curl` afin de télécharger l&#39;échantillon

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Data → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copy informations de connexion** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la Télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Pour les exemples d’exportateur OTLP ci-dessous, définissez ces variables dans le terminal depuis lequel vous exécuterez le collecteur :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port compris, ainsi que par son API key. Utilisez l’endpoint HTTP de base, sans le suffixe `/v1/logs` ; l’exportateur ajoute lui-même le chemin du signal.
  </Tab>

  <Tab title="Autogéré" id="self-managed">
    Utilisez le point de terminaison OTLP HTTP joignable de votre collecteur (par exemple, `http://YOUR_COLLECTOR_HOST:4318`) ainsi que ses paramètres d’authentification. Si votre collecteur ne nécessite pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la configuration, consultez le [guide de démarrage autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

L’endpoint doit être joignable depuis le conteneur du collecteur. Si le collecteur de destination s’exécute sur cette machine, utilisez `http://host.docker.internal:4318`. Les commandes Docker ci-dessous incluent la correspondance d’hôte.

## Intégration avec des groupes de journaux CloudWatch existants {#existing-cloudwatch}

<Steps>
  <Step title="Configurer les identifiants AWS" id="configure-aws">
    Pour AWS SSO, connectez-vous et exportez des identifiants temporaires dans le terminal depuis lequel vous lancerez le collecteur :

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    Remplacez le nom du profil et la région par les vôtres. Si vous utilisez déjà des identifiants d’environnement, définissez `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` et `AWS_SESSION_TOKEN` pour des identifiants temporaires, ainsi que `AWS_REGION`. Ces identifiants autorisent la lecture des logs AWS ; ils sont distincts des identifiants OTLP de votre destination.

    L’identité IAM doit disposer des autorisations suivantes. Remplacez `YOUR_REGION` et `YOUR_ACCOUNT_ID` ; le cas échéant, limitez la ressource de groupe de logs aux seuls groupes que vous souhaitez collecter :

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Affichez la liste des groupes de journaux disponibles afin de choisir les noms à indiquer dans la configuration :

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="Configurer le récepteur CloudWatch" id="configure-receiver">
    Enregistrez ce fichier sous le nom `cloudwatch-logs.yaml`. Remplacez `/aws/lambda/my-function` par un groupe de journaux de votre compte ; ajoutez d&#39;autres groupes sous `named` selon vos besoins.

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    Cette configuration commence par récupérer les logs de la dernière heure, puis interroge la source toutes les minutes. Modifiez `initial_lookback` pour ajuster la fenêtre initiale. Sans stockage persistant des points de contrôle, un redémarrage du collecteur peut entraîner une relecture de cette fenêtre et produire des doublons.

    Pour découvrir plutôt les groupes par préfixe, remplacez le bloc `groups` par :

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    Utilisez soit `named`, soit `autodiscover`. Pour d&#39;autres options, notamment les points de contrôle persistants, consultez la [documentation du récepteur CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver).
  </Step>

  <Step title="Démarrez le collecteur" id="start-collector">
    Enregistrez ce fichier sous le nom `docker-compose.yaml` dans le même répertoire que `cloudwatch-logs.yaml` :

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    Dans le terminal où vous avez défini les identifiants AWS et les [variables de connexion](#connection-details), démarrez le collecteur et consultez sa sortie :

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Vérifier les logs" id="verify-logs">
    Ouvrez **Recherche** dans ClickHouse Observability, sélectionnez votre source **Logs**, puis filtrez sur `ServiceName:cloudwatch`. Sélectionnez **Last 2 hours** et patientez un ou deux intervalles d’interrogation, le temps que les logs apparaissent.

    Recherchez les attributs de ressource suivants :

    * `aws.region` : la région AWS
    * `cloudwatch.log.group.name` : le groupe de journaux
    * `cloudwatch.log.stream` : le flux de journaux

    Le message de log apparaît dans `Body`. Le récepteur conserve le message, mais n’infère pas la sévérité à partir de son contenu. Pour que les panneaux de tableau de bord basés sur la sévérité fonctionnent, votre pipeline de logs doit remplir `SeverityText`.
  </Step>
</Steps>

## Jeu de données de démonstration {#demo-dataset}

L’échantillon contient 12,785 logs couvrant 24 heures d’activité Lambda, ECS et de jobs en arrière-plan. Il comprend des groupes de journaux, des flux et des valeurs de sévérité. Cette approche ne nécessite ni identifiants AWS ni accès direct à la base de données.

<Steps>
  <Step title="Télécharger l’échantillon" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="Configurer le collecteur de démonstration" id="configure-demo-collector">
    Enregistrez ce contenu sous le nom `cloudwatch-demo.yaml` dans le répertoire de téléchargement :

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      La configuration de démonstration lit l’échantillon au format de ligne ClickHouse et restaure le corps, la sévérité et les attributs de chaque log. La transformation des timestamps ramène l’échantillon sur environ les dernières 24 heures, jusqu’à deux minutes avant l’ingestion. Pour vos propres logs, utilisez la configuration du récepteur CloudWatch présentée plus haut afin de conserver leurs timestamps d’origine.
    </Note>
  </Step>

  <Step title="Exécuter le collecteur de démonstration" id="run-demo-collector">
    Définissez les [variables de connexion](#connection-details), puis exécutez cette commande depuis le répertoire de téléchargement :

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez le terminal ouvert pendant que le collecteur lit et exporte le fichier. Surveillez sa sortie pour repérer d’éventuelles erreurs. Lancer un nouveau conteneur une seconde fois peut dupliquer les logs de l’échantillon.
  </Step>

  <Step title="Vérifier les logs de démonstration" id="verify-demo-logs">
    Ouvrez **Search**, sélectionnez votre source **Logs**, filtrez sur `ServiceName:cloudwatch-demo`, puis sélectionnez **2 derniers jours**. Développez un log pour examiner son corps, sa sévérité, son groupe de journaux et son flux. Une fois les données vérifiées, arrêtez le collecteur de démonstration avec **Ctrl+C**.

    <div className="ch-image-lg">
      <Frame>
        ![Logs de démonstration CloudWatch dans ClickHouse Observability](/images/clickstack/observability-cloudwatch-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Aucun log n’apparaît {#no-logs}

* Consultez la sortie de `docker compose logs otel-collector` pour repérer d’éventuelles erreurs d’authentification AWS, de refus d’accès ou d’exportation OTLP.
* Vérifiez que `AWS_REGION` et les noms des groupes de journaux correspondent à votre compte, et que ces groupes contiennent des événements compris dans la fenêtre `initial_lookback` ou de nouveaux événements postérieurs au démarrage.
* Contrôlez les autorisations IAM pour `logs:DescribeLogGroups` et `logs:FilterLogEvents`.
* Vérifiez l’endpoint de destination et les paramètres d’authentification indiqués dans [Informations de connexion](#connection-details).
* Vérifiez la source **Logs**, le filtre par nom de service et l’intervalle de temps. Pour la démonstration, sélectionnez **2 derniers jours**.

### Identifiants AWS expirés {#expired-credentials}

Avec le SSO, reconnectez-vous et exportez de nouveaux identifiants, puis recréez le collecteur afin qu’il récupère les nouvelles variables d’environnement :

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

Redémarrer le conteneur existant ne suffit pas à mettre à jour ses identifiants. Pour les autres identifiants temporaires, renouvelez la clé d’accès, la clé secrète et le jeton de session avant de recréer le conteneur.

### Logs plus anciens manquants {#older-logs}

L&#39;exemple remonte par défaut à une heure en arrière. Augmentez `logs.initial_lookback`, ou remplacez ce paramètre par `logs.start_from` avec un timestamp RFC3339 pour définir un horodatage de début précis. Ne définissez pas les deux. Redémarrez le collecteur après avoir modifié sa configuration ; la relecture d&#39;une fenêtre temporelle peut produire des doublons.
