Collectez les journaux du serveur Redis à l&#39;aide d&#39;un collecteur OpenTelemetry et envoyez-les vers ClickHouse Observability. Utilisez le [jeu de données de démonstration](#demo-dataset) pour tester l&#39;intégration sans installer Redis.

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Docker pour exécuter les exemples de collecteur, ou un déploiement existant d&#39;OpenTelemetry Collector Contrib
* Pour vos propres logs, une installation Redis existante et l&#39;accès à ses fichiers de log

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Data → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copy connection details** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Pour les exemples d’exportateur OTLP ci-dessous, définissez ces variables dans le terminal où vous exécuterez le collecteur :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port compris, ainsi que par son API key. Utilisez l’endpoint HTTP de base, sans suffixe `/v1/logs` : l’exportateur ajoute lui-même le chemin propre à chaque signal.
  </Tab>

  <Tab title="Autogéré">
    Utilisez un point de terminaison OTLP HTTP de votre collecteur qui soit joignable (par exemple, `http://YOUR_COLLECTOR_HOST:4318`), ainsi que vos paramètres d’authentification. Si votre collecteur ne requiert pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la mise en place, consultez le [guide de démarrage autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

L’endpoint doit être joignable depuis le conteneur du collecteur. Si le collecteur de destination s’exécute sur cette machine, utilisez `http://host.docker.internal:4318`. Les commandes Docker ci-dessous incluent la correspondance d’hôte nécessaire.

## Intégration avec une instance Redis existante {#existing-redis}

<Steps>
  <Step title="Vérifiez la configuration de la journalisation de Redis" id="verify-redis">
    Vérifiez où Redis écrit ses logs :

    ```bash
    redis-cli CONFIG GET logfile
    ```

    Emplacements courants des journaux Redis :

    * **Linux (apt/yum)** : `/var/log/redis/redis-server.log`
    * **macOS (Homebrew)** : `/usr/local/var/log/redis.log` ou `/opt/homebrew/var/log/redis.log`
    * **Docker** : généralement journalisé sur stdout, mais peut être configuré pour écrire dans `/data/redis.log`

    Si Redis écrit ses journaux sur stdout, configurez-le pour qu&#39;il les écrive dans un fichier en modifiant `redis.conf` :

    ```bash
    # Log to file instead of stdout
    logfile /var/log/redis/redis-server.log

    # Set log level (options: debug, verbose, notice, warning)
    loglevel notice
    ```

    Assurez-vous que le répertoire des journaux existe et que Redis dispose des droits d’écriture sur celui-ci. Après avoir modifié la configuration, redémarrez Redis à l’aide du nom de service propre à votre installation :

    ```bash
    # For systemd
    sudo systemctl restart redis

    # For Docker
    docker restart <redis-container>
    ```
  </Step>

  <Step title="Configurer le collecteur" id="configure-collector">
    Enregistrez ce contenu sous le nom `redis-monitoring.yaml` :

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis/redis-server.log
        start_at: end
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis
          - type: add
            field: resource["service.name"]
            value: redis-service

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, batch]
          exporters: [otlp_http/observability]
    ```

    Cette configuration analyse l&#39;ID du processus, le rôle, le timestamp, le niveau de journalisation et le message. Elle définit `service.name` sur `redis-service` et fait correspondre les niveaux de journalisation Redis à `SeverityText` pour le tableau de bord. Les messages Redis de type notice (`*`) correspondent à `info`, les avertissements (`#`) à `warn`, et les messages de débogage et verbeux (`.` et `-`) à `debug`.

    Les timestamps des journaux Redis n&#39;incluent pas de fuseau horaire. Définissez `location` sur le fuseau horaire de votre serveur Redis, par exemple `America/Chicago` ; l&#39;exemple utilise `UTC`. Les timestamps d&#39;origine et le corps du journal sont conservés. Avec `start_at: end`, seules les nouvelles entrées sont lues lorsque le collecteur ouvre le fichier pour la première fois.
  </Step>

  <Step title="Exécutez le collecteur" id="run-collector">
    Définissez les [variables de connexion](#connection-details), puis exécutez la commande depuis le répertoire contenant `redis-monitoring.yaml`. Adaptez le chemin du répertoire de journaux sur l&#39;hôte ainsi que le nom de fichier indiqué dans le paramètre `include` du récepteur en fonction de votre installation :

    ```bash
    docker run --rm --name redis-monitoring-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/redis:/var/log/redis:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez ce terminal ouvert et générez de l&#39;activité Redis qui produit de nouvelles entrées de log. Le collecteur doit pouvoir lire les fichiers montés.
  </Step>

  <Step title="Vérifier les logs" id="verify-logs">
    Ouvrez **Recherche**, sélectionnez **Logs** et filtrez sur `ServiceName:redis-service`. Sélectionnez un intervalle de temps couvrant vos nouveaux logs. Développez une entrée pour examiner `SeverityText` ainsi que les champs analysés sous `LogAttributes`.

    <div className="ch-image-lg">
      <Frame>
        ![Journaux Redis dans la vue de recherche](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Jeu de données de démonstration {#demo-dataset}

L&#39;échantillon contient 10,000 entrées de log du serveur Redis. Définissez les [variables de connexion](#connection-details) avant de commencer.

<Steps>
  <Step title="Télécharger le jeu de données d’exemple" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-server.log
    ```
  </Step>

  <Step title="Configurer le collecteur de démonstration" id="configure-demo">
    Enregistrez ce fichier sous le nom `redis-demo.yaml` dans le répertoire de téléchargement :

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis-demo/redis-server.log
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis-demo
          - type: add
            field: resource["service.name"]
            value: redis-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-28T14:59:22Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Le processeur `transform/demo_timestamps`, propre à la démonstration, décale l&#39;échantillon pour le placer approximativement sur les dernières 24 heures, jusqu&#39;à deux minutes avant l&#39;ingestion, tout en conservant son profil de trafic. L&#39;attribut de timestamp d&#39;origine et le corps du journal restent inchangés. N&#39;utilisez pas ce processeur pour vos propres journaux Redis.
    </Note>
  </Step>

  <Step title="Exécutez le collecteur de démonstration" id="run-demo">
    Depuis le répertoire contenant `redis-server.log` et `redis-demo.yaml`, exécutez :

    ```bash
    docker run --rm --name redis-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/redis-server.log:/var/log/redis-demo/redis-server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez le terminal ouvert pendant que vous vérifiez l’ingestion. Une fois la vérification terminée, arrêtez le collecteur avec **Ctrl+C**. Si vous relancez la démonstration, l’échantillon est réingéré avec des timestamps actualisés, car cet exemple ne persiste pas les décalages de fichier.
  </Step>

  <Step title="Vérifiez les logs de démonstration" id="verify-demo-logs">
    Ouvrez **Recherche**, sélectionnez **Logs**, filtrez sur `ServiceName:redis-demo`, puis sélectionnez **2 derniers jours**. Développez une entrée de journal pour examiner les attributs analysés et la sévérité.

    <div className="ch-image-lg">
      <Frame>
        ![Exemple de journaux Redis dans la vue de recherche](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Le collecteur ne démarre pas {#collector-fails-to-start}

Consultez le terminal du collecteur pour repérer d&#39;éventuelles erreurs de configuration. Vérifiez que le fichier YAML est bien monté au path indiqué dans la documentation, et que l&#39;endpoint ainsi que toutes les variables d&#39;authentification requises sont définis dans le terminal depuis lequel vous exécutez Docker.

### Aucun log n’apparaît {#no-logs}

* Recherchez d’éventuelles erreurs d’authentification ou d’exportation dans la sortie du collecteur, et vérifiez vos informations de connexion.
* Exécutez `redis-cli CONFIG GET logfile` pour vérifier que Redis écrit bien dans un fichier. Assurez-vous que le collecteur peut le lire et que son path monté correspond au path `include` du récepteur.
* Avec `start_at: end`, générez de nouvelles entrées de log après le démarrage du collecteur.
* Vérifiez la source **Logs**, le filtre par nom de service et l’intervalle de temps. Pour la démonstration, incluez `transform/demo_timestamps` dans le pipeline et sélectionnez **2 derniers jours**.

### Les logs ne sont pas analysés correctement {#logs-not-parsing}

Le récepteur s&#39;attend au format standard de Redis, `pid:role timestamp level message`. Vérifiez votre fichier journal et adaptez l&#39;expression régulière si votre format est différent. Définissez le paramètre `location` du parseur temporel sur le fuseau horaire du serveur Redis.
