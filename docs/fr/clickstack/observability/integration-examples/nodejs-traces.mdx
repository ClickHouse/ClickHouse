Capturez les traces de votre application Node.js grâce à l&#39;instrumentation automatique OpenTelemetry et envoyez-les vers ClickHouse Observability. Utilisez le [jeu de données de démonstration](#demo-dataset) pour tester l&#39;intégration sans avoir à instrumenter d&#39;application.

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Pour votre application : Node.js 22 ou version ultérieure, et npm
* Pour la démonstration : Docker et `curl`

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Données → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copy connection details** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Définissez ces variables de connexion dans le terminal à partir duquel vous exécuterez votre application ou le collecteur de démonstration :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port compris, ainsi que par votre API key. Utilisez l’endpoint HTTP de base, sans le suffixe `/v1/traces` : l’exportateur ajoute lui-même le path du signal.
  </Tab>

  <Tab title="Autogéré">
    Utilisez un point de terminaison OTLP HTTP joignable de votre collecteur (par exemple, `http://YOUR_COLLECTOR_HOST:4318`) ainsi que vos paramètres d’authentification. Si votre collecteur ne requiert pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la mise en place, consultez le [guide de démarrage en mode autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## Intégration avec une application Node.js existante {#existing-nodejs}

<Steps>
  <Step title="Installer OpenTelemetry" id="install-instrumentation">
    Depuis le répertoire de votre application, installez les paquets d’instrumentation :

    ```bash
    npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node@0.81.0
    ```

    Ces étapes utilisent l’[instrumentation automatique OpenTelemetry](https://opentelemetry.io/docs/zero-code/js/) pour les applications CommonJS. Les modules ES natifs nécessitent la [configuration ESM](https://github.com/open-telemetry/opentelemetry-js/blob/main/doc/esm-support.md). Utilisez une seule configuration d’instrumentation par application afin d’éviter les spans en double.
  </Step>

  <Step title="Configurer le traçage et démarrer votre application" id="run-application">
    Dans le terminal où vous avez défini les variables de connexion, exécutez :

    ```bash
    export OTEL_SERVICE_NAME='nodejs-service'
    export OTEL_TRACES_EXPORTER='otlp'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="Authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='none'
    export OTEL_LOGS_EXPORTER='none'

    node --require @opentelemetry/auto-instrumentations-node/register app.js
    ```

    Remplacez `app.js` par le point d’entrée de votre application. Le préchargement initialise l’instrumentation avant que votre application n’importe ses bibliothèques. Pour un endpoint autogéré sans authentification, omettez l’export des en-têtes et exécutez `unset OTEL_EXPORTER_OTLP_HEADERS`.

    L’endpoint doit être joignable depuis l’application. Si celle-ci s’exécute dans un conteneur, `localhost` désigne ce conteneur.
  </Step>

  <Step title="Générer du trafic" id="generate-traffic">
    Envoyez des requêtes à un endpoint exposé par votre application. Par exemple, pour une application à l’écoute sur le port `3000` :

    ```bash
    curl http://localhost:3000/
    ```

    Patientez quelques secondes, le temps que l’exportateur envoie les spans.
  </Step>

  <Step title="Vérifier les traces" id="verify-traces">
    Ouvrez **Recherche**, sélectionnez **Traces**, filtrez sur `ServiceName:nodejs-service`, puis sélectionnez **Last 15 minutes**. Ouvrez une trace pour en examiner les spans, les durées et les attributs.
  </Step>
</Steps>

## Jeu de données de démonstration {#demo-dataset}

L’échantillon contient 822 spans provenant de `nodejs-demo-api`. Aucune application Node.js en cours d’exécution n’est nécessaire.

<Steps>
  <Step title="Télécharger le jeu de données d’exemple" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nodejs/nodejs-traces-sample.json
    ```
  </Step>

  <Step title="Configurer le collecteur de démonstration" id="configure-demo-collector">
    Enregistrez le contenu suivant sous le nom `nodejs-traces-demo.yaml` dans le répertoire de téléchargement :

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T17:59:15Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nodejs-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      Le processeur `transform/demo_timestamps`, réservé à la démonstration, décale cet échantillon sur environ les 24 dernières heures, jusqu’à deux minutes avant l’ingestion, tout en préservant la durée des spans et le profil du trafic. N’utilisez pas ce processeur pour vos propres traces Node.js, afin de conserver leurs timestamp d’origine. Renvoyer l’échantillon peut produire des spans en double.
    </Note>
  </Step>

  <Step title="Exécuter le collecteur de démonstration" id="run-demo-collector">
    <Note>
      Si le collecteur de destination s’exécute sur cet ordinateur, définissez `OTEL_EXPORTER_OTLP_ENDPOINT` sur `http://host.docker.internal:4318`. La commande ci-dessous inclut le mappage de l’hôte Docker.
    </Note>

    Exécutez OpenTelemetry Collector Contrib `0.161.0` depuis le répertoire contenant la configuration, dans le terminal où vous avez défini les variables de connexion. Laissez ce terminal ouvert :

    ```bash
    docker run --rm --name nodejs-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nodejs-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Le récepteur local utilise le port `14318` pour éviter tout conflit avec un collecteur existant sur le port `4318`. Le collecteur transmet les traces à l’endpoint configuré à l’aide des paramètres d’authentification définis plus haut.
  </Step>

  <Step title="Envoyer les traces" id="send-traces">
    Dans un autre terminal, depuis le répertoire de téléchargement, envoyez l’échantillon d’origine au collecteur local :

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nodejs-traces-sample.json
    ```

    Une réponse vide, telle que `{}` ou `{"partialSuccess":{}}`, indique que le collecteur local a accepté la requête. Vérifiez la sortie du collecteur afin de repérer d’éventuelles erreurs d’exportation, et patientez quelques secondes le temps que le batch parvienne à votre service. Une fois terminé, arrêtez le collecteur de démonstration avec **Ctrl+C**.
  </Step>

  <Step title="Vérifier les traces de démonstration" id="verify-demo-traces">
    Ouvrez **Recherche**, sélectionnez **Traces**, filtrez sur `ServiceName:nodejs-demo-api` et sélectionnez **2 derniers jours** pour inclure l’intégralité du jeu de données décalé. Ouvrez une trace pour examiner les attributs HTTP.

    <div className="ch-image-lg">
      <Frame>
        ![Traces de démonstration Node.js dans la page Recherche de ClickHouse Observability](/images/clickstack/observability-nodejs-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Aucune trace d’application n’apparaît {#no-application-traces}

Recherchez d’éventuelles erreurs d’exportation dans la sortie de l’application. Vérifiez les paramètres d’endpoint, de protocole et d’authentification. Chargez l’instrumentation avant les bibliothèques de l’application, générez des requêtes, puis contrôlez le filtre par nom de service et l’intervalle de temps. Pour les modules ES natifs, suivez la procédure de configuration ESM accessible via le lien.

### Les traces de démonstration n’apparaissent pas {#no-demo-traces}

Consultez la sortie du collecteur de démonstration afin de repérer d’éventuelles erreurs d’authentification ou d’exportation. Une réponse `curl` réussie confirme que les données ont été acceptées localement ; comptez quelques secondes pour leur transmission vers votre service. Ajoutez `transform/demo_timestamps` au pipeline et sélectionnez **2 derniers jours**. Renvoyer l’échantillon peut créer des doublons.
