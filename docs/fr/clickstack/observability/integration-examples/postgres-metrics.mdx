Collectez les métriques PostgreSQL avec le récepteur PostgreSQL d&#39;OpenTelemetry et envoyez-les vers ClickHouse Observability. Utilisez le [jeu de données de démonstration](#demo-dataset) pour tester l&#39;intégration sans installer PostgreSQL.

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Docker et `curl`
* Pour vos propres métriques : PostgreSQL 14 ou version ultérieure, joignable depuis le collecteur, ainsi qu&#39;un utilisateur dédié à la supervision

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Data → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copy connection details** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Pour les exemples d’exportateur OTLP ci-dessous, définissez ces variables dans le terminal depuis lequel vous exécuterez le collecteur :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port inclus, ainsi que par son API key. Utilisez l’endpoint HTTP de base, sans le suffixe `/v1/metrics` : l’exportateur ajoute lui-même le chemin du signal.
  </Tab>

  <Tab title="Autogéré">
    Utilisez le point de terminaison OTLP HTTP de votre collecteur, qui doit être joignable (par exemple, `http://YOUR_COLLECTOR_HOST:4318`), ainsi que ses paramètres d’authentification. Si votre collecteur ne requiert pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la mise en place, consultez le [guide de démarrage autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

L’endpoint doit être joignable depuis le conteneur du collecteur. Si le collecteur de destination s’exécute sur cette machine, utilisez `http://host.docker.internal:4318`. Les commandes Docker ci-dessous incluent la correspondance d’hôte.

## Intégration avec un PostgreSQL existant {#existing-postgres}

<Steps>
  <Step title="Configurer l’utilisateur de supervision" id="monitoring-permissions">
    En tant qu’administrateur PostgreSQL, créez un utilisateur de supervision si vous n’en avez pas déjà un, puis accordez-lui l’accès aux statistiques :

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    Accordez le privilège `CONNECT` sur chaque base de données à superviser. Vérifiez que la configuration réseau de PostgreSQL et son fichier `pg_hba.conf` autorisent les connexions provenant du collecteur.

    Définissez les variables de connexion à la base de données dans le même terminal que vos variables de connexion OTLP :

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    Si PostgreSQL s’exécute sur l’hôte Docker, utilisez `host.docker.internal:5432`. Pour des conteneurs sur un réseau Docker partagé, utilisez le nom d’hôte du conteneur de la base de données et ajoutez `--network YOUR_NETWORK` à la commande du collecteur.
  </Step>

  <Step title="Configurer le collecteur" id="configure-collector">
    Enregistrez le contenu suivant sous `postgres-metrics.yaml`. Remplacez la liste `databases` par les noms de vos bases de données :

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    Cette configuration active TLS et vérifie le certificat serveur. Avec une AC privée, définissez `tls.ca_file` et montez le fichier de l’AC dans le collecteur. Pour un serveur PostgreSQL local sans TLS, définissez `tls.insecure: true` ; TLS est alors désactivé pour la connexion à la base de données. Consultez la [configuration du récepteur PostgreSQL](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration).
  </Step>

  <Step title="Lancer le collecteur" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez le terminal ouvert et patientez au moins deux intervalles de collecte. Une fois vos tests terminés, arrêtez le collecteur avec **Ctrl+C**.
  </Step>

  <Step title="Vérifier les métriques" id="verify-metrics">
    Ouvrez l’**Explorateur de graphiques**, sélectionnez votre source **Metrics**, filtrez sur `ServiceName:postgresql-service` et sélectionnez **15 dernières minutes**. Recherchez `postgresql.backends`, `postgresql.commits` ou `postgresql.db_size`.
  </Step>
</Steps>

## Jeu de données de démonstration {#demo-dataset}

L&#39;échantillon contient 8,928 points de type jauge et somme, échantillonnés toutes les cinq minutes sur 24 heures. Il conserve les pics de connexions, l&#39;activité du cache, les transactions annulées et les deadlocks du jeu de données d&#39;origine. L&#39;échantillon inclut des métriques au niveau de la base de données ; la collecte en conditions réelles fournit également des métriques sur les tables et les index.

Définissez les [variables de connexion](#connection-details) avant de commencer.

<Steps>
  <Step title="Télécharger les métriques d'exemple" id="download-sample">
    [Téléchargez l&#39;archive d&#39;exemple](/fr/assets/postgres-metrics-demo.zip) (environ 64 KB) et extrayez `postgres-metrics-demo.json` dans votre répertoire de travail.
  </Step>

  <Step title="Configurer le collecteur de démonstration" id="configure-demo-collector">
    Enregistrez le contenu suivant sous `postgres-metrics-demo.yaml` :

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      La transformation, propre à la démonstration, actualise les timestamps tout en préservant les valeurs des métriques et l&#39;intervalle entre les timestamps de début et de fin de chaque point. Supprimez-la pour collecter des métriques PostgreSQL réelles. La limite de batch permet de conserver des envois suffisamment légers pour le collecteur de destination.
    </Note>
  </Step>

  <Step title="Lancer le collecteur de démonstration" id="run-demo-collector">
    Depuis le répertoire contenant la configuration, lancez le collecteur et laissez ce terminal ouvert :

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Envoyer l'échantillon" id="load-metrics">
    Dans un autre terminal, exécutez cette commande depuis le répertoire de téléchargement :

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    Une réponse telle que `{}` ou `{"partialSuccess":{}}` indique que le collecteur local a accepté la requête. Vérifiez l&#39;absence d&#39;erreurs d&#39;exportation dans le terminal du collecteur et patientez quelques secondes, le temps du transfert. Une fois les données vérifiées, arrêtez le collecteur avec **Ctrl+C**. Renvoyer l&#39;échantillon peut entraîner des points en double.
  </Step>

  <Step title="Vérifier les métriques" id="verify-demo-metrics">
    Importez le tableau de bord présenté dans la [section suivante](#dashboards), filtrez sur `ServiceName:postgresql-demo` et sélectionnez **2 derniers jours**. L&#39;échantillon inclut des métriques de type jauge et somme ; aucun accès direct à la base de données n&#39;est nécessaire.
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Le collecteur ne démarre pas {#collector-fails-to-start}

Examinez la sortie du collecteur pour repérer d&#39;éventuelles erreurs de configuration. Vérifiez que le fichier de configuration est bien monté et que les variables de connexion sont définies dans le terminal où Docker est exécuté.

### Aucune métrique n’apparaît {#no-metrics}

Consultez la sortie du collecteur pour repérer d’éventuelles erreurs de connexion à la base de données ou erreurs d’exportation. Vérifiez que le nom d’hôte de la base de données est joignable depuis le conteneur, que les noms des bases de données sont corrects et que PostgreSQL autorise la connexion de l’utilisateur de supervision. Contrôlez également votre source **Metrics**, le filtre par nom de service et l’intervalle de temps.

### Erreurs d’authentification ou TLS {#authentication-errors}

Vérifiez que l’utilisateur de supervision dispose des autorisations `pg_monitor` et `CONNECT`. Testez les identifiants de la base de données avec `psql` depuis un hôte ayant accès à PostgreSQL :

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

Alignez les paramètres TLS du récepteur sur ceux de votre serveur et montez, le cas échéant, le certificat de CA requis. En cas d’erreurs d’exportation, vérifiez que le point de terminaison OTLP et l’autorisation correspondent aux informations de connexion de votre service.
