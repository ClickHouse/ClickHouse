Collectez les métriques Redis à l&#39;aide du récepteur Redis d&#39;OpenTelemetry, puis envoyez-les vers ClickHouse Observability. Utilisez le [jeu de données de démonstration](#demo-dataset) pour tester l&#39;intégration sans installer Redis.

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Docker pour exécuter les exemples de collecteur, ou un déploiement existant d&#39;OpenTelemetry Collector Contrib
* Pour vos propres métriques, une instance Redis joignable depuis le collecteur, ainsi que des identifiants si Redis exige une authentification
* Pour la démonstration, `curl` pour télécharger et envoyer l&#39;échantillon

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Data → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copier les informations de connexion** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Pour les exemples d’exportateur OTLP ci-dessous, définissez ces variables dans le terminal où vous exécuterez le collecteur :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port compris, ainsi que par son API key. Utilisez l’endpoint HTTP de base, sans le suffixe `/v1/metrics` : l’exportateur ajoute lui-même le chemin propre à chaque signal.
  </Tab>

  <Tab title="Autogéré">
    Utilisez le point de terminaison OTLP HTTP de votre collecteur, qui doit être joignable (par exemple, `http://YOUR_COLLECTOR_HOST:4318`), ainsi que ses paramètres d’authentification. Si votre collecteur ne requiert pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la mise en place, consultez le [guide de démarrage autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

L’endpoint doit être joignable depuis le conteneur du collecteur. Si le collecteur de destination s’exécute sur cette machine, utilisez `http://host.docker.internal:4318`. Les commandes Docker ci-dessous incluent la correspondance d’hôte nécessaire.

## Intégration avec une instance Redis existante {#existing-redis}

<Steps>
  <Step title="Vérifier la connexion Redis" id="verify-redis">
    Depuis un hôte disposant d’un accès à la CLI Redis, vérifiez votre instance Redis :

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    La première commande doit renvoyer `PONG`, et la seconde des informations sur le serveur. Si Redis exige un mot de passe, définissez `REDISCLI_AUTH` dans votre terminal avant d’exécuter ces commandes. Pour les utilisateurs ACL Redis, ajoutez également `--user YOUR_REDIS_USER`.
  </Step>

  <Step title="Configurer le collecteur" id="configure-collector">
    Enregistrez la configuration suivante sous `redis-metrics.yaml` :

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # Décommentez si Redis exige une authentification :
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    Le récepteur collecte les métriques Redis toutes les 10 secondes, notamment l’utilisation de la mémoire, les clients, les commandes traitées, les succès et échecs d’accès au keyspace, ainsi que les clés expirées ou évincées. Le processeur `resource` définit `service.name` sur `redis-service` afin de faciliter le filtrage.

    Si Redis exige une authentification, décommentez les champs correspondants du récepteur et définissez `REDIS_USERNAME` et/ou `REDIS_PASSWORD`. Ces identifiants servent à se connecter à Redis, tandis que la valeur d’autorisation OTLP permet de s’authentifier auprès de votre collecteur de destination. Si TLS est activé sur Redis, configurez les paramètres `tls` du récepteur comme indiqué dans la [documentation du récepteur Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
  </Step>

  <Step title="Exécuter le collecteur" id="run-collector">
    Définissez les [variables de connexion](#connection-details) ainsi que l’adresse Redis accessible depuis le conteneur du collecteur. Si Redis s’exécute sur cette machine :

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    Pour un Redis distant, utilisez son nom d’hôte et son port. Si Redis s’exécute dans un autre conteneur, utilisez le nom de ce conteneur et ajoutez `--network YOUR_NETWORK` à la commande ci-dessous.

    Depuis le répertoire contenant `redis-metrics.yaml`, exécutez :

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez ce terminal ouvert pendant toute la durée de la collecte des métriques. Patientez au moins deux intervalles de collecte avant de vérifier dans l’UI.
  </Step>

  <Step title="Vérifier les métriques" id="verify-metrics">
    Importez le [tableau de bord](#dashboards), associez ses graphiques à votre source **Metrics** et filtrez sur `ServiceName:redis-service`. Sélectionnez **Last 15 minutes** et exécutez le tableau de bord. Sur une instance Redis saine, les évictions et les connexions rejetées peuvent rester à zéro.
  </Step>
</Steps>

## Jeu de données de démonstration {#demo-dataset}

Testez l&#39;intégration avec 6,912 points de données de type jauge et somme, échantillonnés toutes les cinq minutes sur 24 heures. L&#39;échantillon conserve les schémas de préchauffage du cache, de pics de trafic et de pression mémoire du jeu de données d&#39;origine. Vous aurez besoin de Docker, de `curl` et des informations de connexion OTLP HTTP du collecteur de destination.

Définissez les [variables de connexion](#connection-details) avant de commencer.

<Steps>
  <Step title="Télécharger les métriques d'exemple" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="Configurer le collecteur de démonstration" id="configure-demo-collector">
    Enregistrez ce contenu sous `redis-metrics-demo.yaml` :

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      La transformation, propre à la démonstration, actualise les timestamps tout en préservant les valeurs des métriques et l&#39;intervalle entre les timestamps de début et de fin de chaque point. Supprimez-la pour des métriques Redis réelles. La limite de batch garantit des envois suffisamment légers pour le collecteur de destination.
    </Note>
  </Step>

  <Step title="Lancer le collecteur de démonstration" id="run-demo-collector">
    Depuis le répertoire contenant la configuration, lancez le collecteur et laissez ce terminal ouvert :

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Envoyer l'échantillon" id="load-metrics">
    Dans un autre terminal, exécutez cette commande depuis le répertoire de téléchargement :

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    Une réponse telle que `{}` ou `{"partialSuccess":{}}` indique que le collecteur local a accepté la requête. Vérifiez l&#39;absence d&#39;erreurs d&#39;exportation dans le terminal du collecteur et patientez quelques secondes, le temps de la transmission. Une fois les données vérifiées, arrêtez le collecteur avec **Ctrl+C**. Un nouvel envoi de l&#39;échantillon risque de créer des points en double.
  </Step>

  <Step title="Vérifier les métriques" id="verify-demo-metrics">
    Importez le tableau de bord présenté dans la [section suivante](#dashboards), filtrez sur `ServiceName:redis-demo` et sélectionnez **2 derniers jours**. L&#39;échantillon comprend des métriques de type jauge et somme ; aucun accès direct à la base de données n&#39;est nécessaire.
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Le collecteur ne démarre pas {#collector-fails-to-start}

Consultez le terminal du collecteur pour repérer d&#39;éventuelles erreurs de configuration. Assurez-vous que le fichier YAML est monté au path indiqué dans la documentation, et que l&#39;endpoint ainsi que les variables d&#39;authentification requises sont définis dans le terminal où vous exécutez Docker.

### Aucune métrique n’apparaît {#no-metrics}

* Examinez la sortie du collecteur pour repérer d’éventuelles erreurs de connexion Redis ou erreurs d’exportation OTLP.
* Vérifiez que Redis est joignable depuis le conteneur du collecteur. Dans le cas de conteneurs, assurez-vous qu’ils partagent bien le réseau Docker prévu.
* Vérifiez les identifiants Redis et assurez-vous que l’utilisateur peut exécuter les commandes requises par le [récepteur Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
* Vérifiez la source **Metrics**, le filtre par nom de service et l’intervalle de temps. Pour la démonstration, sélectionnez **2 derniers jours** et assurez-vous que la transformation du timestamp figure bien dans le pipeline.
* Pour les services gérés, comparez le point de terminaison OTLP HTTP et l’API key Bearer avec les valeurs indiquées dans **Télémétrie gérée**. Pour les collecteurs autogérés, utilisez leurs paramètres d’authentification.
