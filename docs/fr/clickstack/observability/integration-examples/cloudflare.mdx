      **En bref**

      Ce guide explique comment ingérer des journaux Cloudflare dans ClickStack à l&#39;aide de ClickPipes. Cloudflare Logpush écrit les logs dans S3, puis ClickPipes ingère en continu les nouveaux fichiers dans ClickHouse. Contrairement à la plupart des guides d&#39;intégration ClickStack, qui s&#39;appuient sur le collecteur OpenTelemetry, ce guide utilise [ClickPipes](/fr/integrations/clickpipes/home) pour récupérer les données directement depuis S3.

      Un jeu de données de démonstration est disponible si vous souhaitez explorer les tableaux de bord avant de configurer l&#39;ingestion en production.
    </Info>

## Vue d’ensemble {#overview-self-configured}

    Cloudflare [Logpush](https://developers.cloudflare.com/logs/about/) exporte les logs de requêtes HTTP vers des destinations telles qu’Amazon S3. Transférer ces logs vers ClickStack vous permet de :

    * Analysez le trafic edge, les performances du cache et les événements de sécurité aux côtés de vos autres données d&#39;observability
    * Interrogez les logs en SQL ClickHouse
    * Conservez les logs au-delà de la durée de rétention par défaut de Cloudflare

    Ce guide utilise [ClickPipes](/fr/integrations/clickpipes/home) pour ingérer en continu les fichiers de log Cloudflare stockés dans S3 vers ClickHouse. S3 sert de tampon durable entre Cloudflare et ClickHouse, ce qui garantit une sémantique de traitement exactement une fois et permet de rejouer les données.

    <Info>
      **Alternative : ingestion HTTP directe**

      Cloudflare Logpush permet également d&#39;envoyer directement les logs vers des [endpoints HTTP](https://developers.cloudflare.com/logs/get-started/enable-destinations/http/). Comme Cloudflare exporte les logs au format JSON délimité par des sauts de ligne (NDJSON) et que ClickHouse accepte nativement ce format via `JSONEachRow`, vous pouvez configurer Logpush pour qu&#39;il envoie directement les données vers l&#39;interface HTTP de votre service ClickHouse Cloud, en utilisant le format d&#39;URL du point de terminaison suivant :

      ```text
      https://YOUR_CLICKHOUSE_HOST:8443/?query=INSERT+INTO+cloudflare_http_logs+FORMAT+JSONEachRow&header_Authorization=Basic+BASE64_CREDENTIALS
      ```

      Remplacez `YOUR_CLICKHOUSE_HOST` par le nom d’hôte de votre service ClickHouse Cloud et `BASE64_CREDENTIALS` par vos identifiants encodés en Base64 (`echo -n 'default:YOUR_PASSWORD' | base64`).

      Cette approche est plus simple à mettre en place (aucune configuration S3, SQS ou IAM n’est requise), mais Cloudflare Logpush [ne peut pas effectuer de chargement de données historiques](https://developers.cloudflare.com/logs/logpush/) en cas d’échec de l’envoi : si ClickHouse est indisponible au moment d’un push, les logs concernés sont définitivement perdus.
    </Info>

## Intégration avec une configuration Cloudflare Logpush existante {#existing-cloudflare-self-configured}

    Cette section suppose que Cloudflare Logpush est configuré pour exporter les logs vers S3. Si ce n&#39;est pas le cas, suivez d&#39;abord le [guide de configuration AWS S3 de Cloudflare](https://developers.cloudflare.com/logs/get-started/enable-destinations/aws-s3/).

### Prérequis {#prerequisites-self-configured}

    * **Service ClickHouse Cloud** opérationnel (ClickPipes est une fonctionnalité réservée à Cloud et n’est pas disponible dans ClickStack OSS)
    * Cloudflare Logpush configuré et écrivant activement des logs dans un compartiment S3
    * Nom et région du compartiment S3 dans lequel Cloudflare écrit les logs

    <Steps>
      <Step title="Configurer l’authentification S3" id="configure-auth-self-configured">
        ClickPipes doit disposer de l’autorisation de lire votre compartiment S3. Suivez le guide [Accéder aux données S3 en toute sécurité](/fr/products/cloud/guides/data-sources/accessing-s3-data-securely) pour configurer soit un accès basé sur un rôle IAM, soit un accès par identifiants.

        Pour plus de détails sur l’authentification et les autorisations S3 de ClickPipes, consultez la [documentation de référence des S3 ClickPipes](/fr/integrations/clickpipes/object-storage/amazon-s3/overview#access-control).
      </Step>

      <Step title="Créer un job ClickPipes" id="create-clickpipes-self-configured">
        1. Console ClickHouse Cloud → **Sources de données** → **Créer un ClickPipe**
        2. **Source** : Amazon S3

        <div className="ch-image-lg">
          <Frame>
            ![Clickpipe s3](/images/clickstack/cloudflare/clickpipe-s3.webp)
          </Frame>
        </div>

        **Connexion :**

        * **Chemin du fichier S3** : le chemin de votre bucket de journaux Cloudflare, avec un caractère générique pour cibler les fichiers. Si vous avez activé les sous-dossiers quotidiens dans Logpush, utilisez `**` pour inclure tous les sous-répertoires :
          * Sans sous-dossiers : `https://your-bucket.s3.us-east-1.amazonaws.com/logs/*`
          * Sous-dossiers quotidiens : `https://your-bucket.s3.us-east-1.amazonaws.com/logs/**/*`
        * **Authentification** : sélectionnez votre méthode d’authentification et fournissez les identifiants ou l’ARN du rôle IAM

        **Paramètres d’ingestion :**

        Cliquez sur **Incoming data**, puis configurez les options suivantes :

        * Activez **Continuous ingestion**
        * **Ordering** : Lexicographical order

        <div className="ch-image-lg">
          <Frame>
            ![Ingestion continue](/images/clickstack/cloudflare/continuous-ingestion.webp)
          </Frame>
        </div>

        Cloudflare Logpush nomme les fichiers d’après la date (par exemple, `20250127/...`), ce qui respecte naturellement l’ordre lexicographique. ClickPipes recherche de nouveaux fichiers toutes les 30 secondes et ingère tout fichier dont le nom est supérieur à celui du dernier fichier traité.

        **Mise en correspondance des schémas :**

        Cliquez sur **Parse information**. ClickPipes analyse un échantillon de vos fichiers de log et détecte automatiquement le schéma. Vérifiez les colonnes mappées et ajustez les types si nécessaire. Définissez une **clé de tri** pour la table de destination ; pour les journaux Cloudflare, `(EdgeStartTimestamp, ClientCountry, EdgeResponseStatus)` constitue un bon choix.

        <div className="ch-image-lg">
          <Frame>
            ![Analyser les informations](/images/clickstack/cloudflare/parse-information.webp)
          </Frame>
        </div>

        Cliquez sur **Complete Setup**.

        <Note>
          À sa création, ClickPipes effectue un chargement initial de **tous les fichiers existants** dans le chemin spécifié avant de passer à l’interrogation continue. Si votre bucket contient un historique volumineux de journaux Cloudflare, ce chargement initial peut prendre un certain temps.
        </Note>
      </Step>

      <Step title="Configurer la source de données de l’interface utilisateur de ClickStack" id="configure-source-self-configured">
        ClickPipes ingère les journaux Cloudflare dans une table plate en conservant les noms de champs natifs de Cloudflare. Pour afficher ces journaux dans l’interface utilisateur de ClickStack, configurez une source de données personnalisée qui associe les colonnes Cloudflare à la vue des journaux de l’interface utilisateur de ClickStack.

        1. Ouvrez l’interface utilisateur de ClickStack → **Team Settings** → **Sources**

        <div className="ch-image-lg">
          <Frame>
            ![Ajouter une source](/images/clickstack/cloudflare/add-source.webp)
          </Frame>
        </div>

        2. Cliquez sur **Add source** et configurez les paramètres suivants. Cliquez sur **Configure Optional Fields** pour afficher l’ensemble des champs :

        <div className="ch-image-lg">
          <Frame>
            ![Configurer les champs facultatifs](/images/clickstack/cloudflare/configure-optional-fields.webp)
          </Frame>
        </div>

        | Paramètre                          | Valeur                                                                                                                                                                                                                                                                                                            |
        | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
        | **Name**                           | `Cloudflare Logs`                                                                                                                                                                                                                                                                                                 |
        | **Source Data Type**               | Log                                                                                                                                                                                                                                                                                                               |
        | **Database**                       | `default`                                                                                                                                                                                                                                                                                                         |
        | **Table**                          | `cloudflare_http_logs`                                                                                                                                                                                                                                                                                            |
        | **Timestamp Column**               | `toDateTime(EdgeStartTimestamp / 1000000000)`                                                                                                                                                                                                                                                                     |
        | **Default Select**                 | `EdgeStartTimestamp, ClientRequestMethod, ClientRequestURI, EdgeResponseStatus, ClientCountry`                                                                                                                                                                                                                    |
        | **Service Name Expression**        | `'cloudflare'`                                                                                                                                                                                                                                                                                                    |
        | **Log Level Expression**           | `multiIf(EdgeResponseStatus >= 500, 'ERROR', EdgeResponseStatus >= 400, 'WARN', 'INFO')`                                                                                                                                                                                                                          |
        | **Body Expression**                | `concat(ClientRequestMethod, ' ', ClientRequestURI, ' ', toString(EdgeResponseStatus))`                                                                                                                                                                                                                           |
        | **Log Attributes Expression**      | `map('http.method', ClientRequestMethod, 'http.status_code', toString(EdgeResponseStatus), 'http.url', ClientRequestURI, 'client.country', ClientCountry, 'client.ip', ClientIP, 'cache.status', CacheCacheStatus, 'bot.score', toString(BotScore), 'cloudflare.ray_id', RayID, 'cloudflare.colo', EdgeColoCode)` |
        | **Resource Attributes Expression** | `map('cloudflare.zone', ClientRequestHost)`                                                                                                                                                                                                                                                                       |
        | **Implicit Column Expression**     | `concat(ClientRequestMethod, ' ', ClientRequestURI)`                                                                                                                                                                                                                                                              |

        3. Cliquez sur **Save Source**

        <div className="ch-image-lg">
          <Frame>
            ![Enregistrer la source](/images/clickstack/cloudflare/save-source.webp)
          </Frame>
        </div>

        Cette configuration associe directement les colonnes natives de Cloudflare à la visionneuse de journaux de l’interface utilisateur de ClickStack, sans transformation ni duplication des données. Le champ **Body** affiche un résumé de la requête, par exemple `GET /api/v1/users 200`, et tous les champs Cloudflare sont disponibles sous forme d’attributs consultables par recherche.
      </Step>

      <Step title="Vérifiez les données dans l’interface utilisateur de ClickStack" id="verify-hyperdx-self-configured">
        Accédez à la vue **Search** et sélectionnez la source **Cloudflare Logs**. Définissez l’intervalle de temps de façon à couvrir vos données. Vous devriez voir des entrées de log comportant :

        * des résumés de requête dans la colonne Body (par exemple, `GET /api/v1/users 200`) ;
        * des niveaux de sévérité dont la couleur varie selon le statut HTTP (INFO pour 2xx, WARN pour 4xx, ERROR pour 5xx) ;
        * des attributs consultables par recherche, tels que `http.status_code`, `client.country`, `cache.status` et `bot.score`.

        <div className="ch-image-lg">
          <Frame>
            ![Vue de recherche](/images/clickstack/cloudflare/search-view.webp)
          </Frame>
        </div>

        <div className="ch-image-lg">

          </Frame>
        </div>
      </Step>
    </Steps>

## Jeu de données de démonstration {#demo-dataset-self-configured}

    Si vous souhaitez tester l’intégration avant de configurer Cloudflare Logpush en production, nous mettons à votre disposition un jeu de données d’exemple contenant des logs de requêtes HTTP réalistes.

    <Steps>
      <Step title="Démarrer ClickPipes avec le jeu de données de démonstration" id="start-demo-self-configured">
        1. Console ClickHouse Cloud → **Data Sources** → **Create ClickPipe**
        2. **Source** : Amazon S3
        3. **Authentication** : Public
        4. **S3 file path** : `https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/cloudflare/cloudflare-http-logs.json`
        5. Cliquez sur **Incoming data**
        6. Sélectionnez **JSON** comme format
        7. Cliquez sur **Parse information** et vérifiez le schéma détecté
        8. Définissez **Table name** sur `cloudflare_http_logs`
        9. Cliquez sur **Complete Setup**

        Le jeu de données contient 5,000 entrées de log de requêtes HTTP réparties sur 24 heures, avec des motifs réalistes : trafic provenant de plusieurs pays, succès et échecs du cache, requêtes d&#39;API et de ressources statiques, réponses d&#39;erreur et événements de sécurité.
      </Step>

      <Step title="Configurer la source de données dans l'interface utilisateur de ClickStack" id="configure-demo-source-self-configured">
        Suivez les [étapes de configuration de la source de données](#configure-source-self-configured) pour créer, dans l&#39;interface utilisateur de ClickStack, une source pointant vers la table `cloudflare_http_logs`. Si vous avez déjà configuré la source dans la section consacrée à l&#39;intégration en production, vous pouvez ignorer cette étape.

## Dépannage {#troubleshooting-self-configured}

### Les données n’apparaissent pas dans ClickHouse {#no-data-self-configured}

    Vérifiez que la table a été créée et qu&#39;elle contient des données :

    ```sql
    SHOW TABLES FROM default LIKE 'cloudflare_http_logs';
    SELECT count() FROM cloudflare_http_logs;
    ```

    Si la table existe mais reste vide, vérifiez la présence d’erreurs dans ClickPipes : Console ClickHouse Cloud → **Sources de données** → votre ClickPipe → **Logs**. En cas de problème d’authentification avec des buckets privés, consultez la [documentation sur le contrôle d’accès des S3 ClickPipes](/fr/integrations/clickpipes/object-storage/amazon-s3/overview#access-control).

### Les logs n’apparaissent pas dans l’interface utilisateur de ClickStack {#no-hyperdx-self-configured}

    Si les données sont présentes dans ClickHouse mais n&#39;apparaissent pas dans l&#39;interface utilisateur de ClickStack, vérifiez la configuration de la source de données :

    * Vérifiez qu’une source existe pour `cloudflare_http_logs` dans l’interface utilisateur de ClickStack → **Paramètres de l’équipe** → **Sources**
    * Assurez-vous que la **Colonne d’horodatage** est définie sur `toDateTime(EdgeStartTimestamp / 1000000000)` : les timestamps de Cloudflare sont exprimés en nanosecondes et doivent être convertis
    * Vérifiez que l’intervalle de temps sélectionné dans l’interface utilisateur de ClickStack couvre bien les données. Pour le jeu de données de démonstration, utilisez **2026-02-23 00:00:00 - 2026-02-26 00:00:00**

## Prochaines étapes {#next-steps-self-configured}

    * Configurez des [alertes](/fr/clickstack/observability/features/alerts) pour les événements de sécurité (blocages WAF, pics de trafic de bots, dépassements de seuils de taux d’erreur)

## Passage en production {#going-to-production-self-configured}

    Ce guide montre comment ingérer des journaux Cloudflare à l’aide d’un jeu de données de démonstration public. Pour les déploiements en production, configurez Cloudflare Logpush afin qu’il écrive dans votre propre compartiment S3, puis configurez ClickPipes avec une [authentification basée sur un rôle IAM](/fr/products/cloud/guides/data-sources/accessing-s3-data-securely) pour sécuriser l’accès. Sélectionnez uniquement les [champs Logpush](https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/zone/http_requests/) dont vous avez besoin afin de réduire les coûts de stockage et le volume d’ingestion. Activez les sous-dossiers quotidiens dans Logpush pour mieux organiser les fichiers, et utilisez `**/*` dans le motif de chemin de votre ClickPipe pour inclure tous les sous-répertoires.

    Consultez la [documentation des S3 ClickPipes](/fr/integrations/clickpipes/object-storage/amazon-s3/overview) pour découvrir les options de configuration avancées, notamment l’[ingestion en mode unordered basée sur SQS](/fr/integrations/clickpipes/object-storage/amazon-s3/overview#continuous-ingestion-any-order), qui permet de gérer le chargement de données historiques et les fichiers arrivant dans le désordre.
