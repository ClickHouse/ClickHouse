Temporal fournit une abstraction pour concevoir des applications simples, sophistiquées et résilientes.

<Info>
  **TL;DR**

  Surveillez les métriques de Temporal Cloud dans ClickHouse Observability à l’aide du récepteur Prometheus d’OTel. Un tableau de bord préconfiguré est inclus.
</Info>

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Un compte Temporal Cloud existant
* Docker installé sur un hôte disposant d&#39;un accès HTTPS à Temporal Cloud et à votre point de terminaison OTLP

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Data → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copy connection details** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Pour les exemples d’exportateur OTLP ci-dessous, définissez ces variables dans le terminal où vous exécuterez le collecteur :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port compris, et par son API key. Utilisez l’endpoint HTTP de base, sans le suffixe `/v1/metrics` : l’exportateur ajoute lui-même le chemin propre au signal.
  </Tab>

  <Tab title="Autogéré">
    Utilisez un point de terminaison OTLP HTTP de votre collecteur qui soit joignable (par exemple, `http://YOUR_COLLECTOR_HOST:4318`), ainsi que vos paramètres d’authentification. Si votre collecteur n’exige pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la mise en place, consultez le [guide de démarrage autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

L’endpoint doit être joignable depuis le conteneur du collecteur. Si le collecteur de destination s’exécute sur cet ordinateur, utilisez `http://host.docker.internal:4318`. Les commandes Docker ci-dessous incluent la correspondance d’hôte nécessaire.

## Intégration avec un environnement Temporal Cloud existant {#existing-temporal}

<Steps>
  <Step title="Créer une clé Temporal Cloud" id="create-temporal-cloud-key">
    Créez un compte de service Temporal Cloud doté du rôle **Metrics Read-Only** et générez une API key en suivant le [guide d’authentification](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication). Le compte de service et la clé doivent être créés par un Account Owner ou un Global Admin.

    <Warning>
      **Fichier de clé**

      Enregistrez l’API key Temporal dans un fichier `temporal.key` situé dans le même répertoire que le fichier de configuration créé ci-dessous. N’y placez que la clé, sans préfixe `Bearer` ni espaces avant ou après. Cette clé est distincte de votre API key ClickHouse Observability. Assurez-vous que le collecteur dispose des droits de lecture sur le fichier monté.
    </Warning>
  </Step>

  <Step title="Configurer le collecteur OTel" id="custom-otel">
    Exécutez un collecteur OpenTelemetry autonome avec le récepteur Prometheus afin de collecter les métriques de Temporal Cloud et de les transmettre à votre service.

    Créez un fichier nommé `temporal-metrics.yaml` avec la configuration suivante :

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    Cette configuration :

    * Se connecte à Temporal Cloud via `metrics.temporal.io`
    * Collecte les métriques toutes les 60 secondes
    * Collecte les [principales métriques de performance](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)
    * **Définit l’attribut de ressource `service.name` requis**, conformément aux [conventions sémantiques OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/resource/#service)
    * Envoie les métriques à votre point de terminaison OTLP via un pipeline dédié

    Si vous disposez de plusieurs comptes Temporal Cloud, personnalisez `service.name` pour les distinguer (par exemple, `temporal-prod` et `temporal-dev`).
  </Step>

  <Step title="Exécuter le collecteur" id="run-collector">
    Depuis le répertoire contenant `temporal-metrics.yaml` et `temporal.key`, définissez les [variables de connexion](#connection-details), puis exécutez :

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez le terminal ouvert et surveillez d’éventuelles erreurs de collecte ou d’exportation. Comptez quelques minutes avant l’apparition des métriques Temporal Cloud. Une fois les tests terminés, arrêtez le collecteur avec **Ctrl+C**.
  </Step>

  <Step title="Vérifier les métriques dans ClickHouse Observability" id="verifying-metrics">
    Une fois la configuration terminée, connectez-vous à ClickHouse Observability et vérifiez que les métriques remontent bien :

    1. Ouvrez **Explorateur de graphiques** et sélectionnez votre source **Metrics**
    2. Filtrez sur `ServiceName:temporal`, sélectionnez **Last 15 minutes**, puis recherchez les métriques commençant par `temporal` (par ex. `temporal_cloud_v1_workflow_success_count`, `temporal_cloud_v1_poll_timeout_count`)
    3. Des points de données de métriques devraient apparaître à l’intervalle de collecte configuré

    <div className="ch-image-md">
      <Frame>
        ![Métriques Temporal](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Le collecteur ne démarre pas {#collector-fails-to-start}

Examinez la sortie du terminal pour repérer d&#39;éventuelles erreurs de configuration. Assurez-vous que les deux fichiers montés existent et que le collecteur peut lire `temporal.key`. Vérifiez que les variables de connexion OTLP sont bien définies dans le terminal où Docker s&#39;exécute.

### Aucune métrique n&#39;apparaît {#no-metrics}

Consultez les logs du collecteur :

```bash
docker logs temporal-metrics-collector
```

Recherchez d&#39;éventuelles erreurs de collecte, d&#39;authentification ou d&#39;exportation. Vérifiez que l&#39;hôte peut joindre `https://metrics.temporal.io/v1/metrics` ainsi que votre point de terminaison OTLP. Dans l&#39;**Explorateur de graphiques**, vérifiez la source **Metrics**, le filtre `ServiceName:temporal` et l&#39;intervalle de temps. Les métriques Temporal peuvent mettre quelques minutes à apparaître et dépendent de l&#39;activité de votre compte.

### Erreurs d’authentification {#auth-errors}

Pour les erreurs de collecte Temporal, vérifiez que `temporal.key` contient une API key valide pour un compte de service disposant du rôle **Metrics Read-Only**. Pour les erreurs d’exportation OTLP, vérifiez votre endpoint ClickHouse Observability ainsi que la valeur d’autorisation. Il s’agit d’identifiants distincts.

## Étapes suivantes {#next-steps}

* Configurez des [alertes](/fr/clickstack/observability/features/alerts) sur les métriques critiques (taux d’échec des flux de travail, augmentation du nombre de tâches en attente, latence entre la planification et le démarrage)
* Créez des tableaux de bord supplémentaires pour des cas d’utilisation spécifiques (supervision par namespace, performance par type de flux de travail)
* Supervisez plusieurs comptes Temporal Cloud en dupliquant la configuration du récepteur avec des endpoints et des noms de service différents

## Passage en production {#going-to-production}

Ce guide utilise un collecteur OpenTelemetry distinct qui transfère les métriques vers le point de terminaison OTLP de votre service. Consultez [Envoi de données OpenTelemetry](/fr/clickstack/observability/ingesting-data/opentelemetry) pour obtenir des recommandations sur le déploiement.
