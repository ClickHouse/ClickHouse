Collectez les journaux du serveur MongoDB avec le récepteur OpenTelemetry `filelog` et envoyez-les vers ClickHouse Observability. Utilisez le [jeu de données de démonstration](#demo-dataset) pour tester l&#39;intégration sans disposer d&#39;un déploiement MongoDB.

## Prérequis {#prerequisites}

* Un service ClickHouse Observability
* Docker et `curl`
* Pour vos propres logs, un déploiement MongoDB 4.4 ou version ultérieure autogéré, avec accès à ses fichiers de log JSON

### Informations de connexion {#connection-details}

<Tabs>
  <Tab title="Entièrement géré">
    <BetaBadge label="Offre en version bêta" />

    Ouvrez ClickHouse Observability et accédez à **Paramètres de l’équipe → Data → Télémétrie gérée**. Copiez votre point de terminaison OTLP HTTP et votre API key. Vous pouvez utiliser **Copy connection details** pour copier la configuration, ou **Reveal key** pour afficher la clé masquée.

    <div className="ch-image-lg">
      <Frame>
        ![Informations de connexion de la Télémétrie gérée](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Pour les exemples d’exportateur OTLP ci-dessous, définissez ces variables dans le terminal où vous exécuterez le collecteur :

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Remplacez les caractères de substitution par l’endpoint exact de votre service, port compris, et par son API key. Utilisez l’endpoint HTTP de base, sans le suffixe `/v1/logs` : l’exportateur ajoute lui-même le chemin propre à chaque signal.
  </Tab>

  <Tab title="Autogéré">
    Utilisez le point de terminaison OTLP HTTP de votre collecteur, qui doit être joignable (par exemple, `http://YOUR_COLLECTOR_HOST:4318`), ainsi que vos paramètres d’authentification. Si votre collecteur ne requiert pas d’authentification, supprimez le bloc `headers` de l’exportateur dans les configurations ci-dessous. Pour la mise en place, consultez le [guide de démarrage autogéré](/fr/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

L’endpoint doit être joignable depuis le conteneur du collecteur. Si le collecteur de destination s’exécute sur cette machine, utilisez `http://host.docker.internal:4318`. Les commandes Docker ci-dessous incluent la correspondance d’hôte.

## Intégration avec une instance MongoDB existante {#existing-mongodb}

<Steps>
  <Step title="Vérifier la configuration de journalisation de MongoDB" id="verify-mongodb">
    À partir de la version 4.4, MongoDB produit des journaux du serveur au format JSON structuré. Vérifiez la section `systemLog` de votre fichier de configuration MongoDB. Sous Linux, les logs se trouvent généralement dans `/var/log/mongodb/mongod.log`.

    Si MongoDB écrit ses logs uniquement sur stdout, configurez la journalisation dans un fichier via `mongod.conf` :

    ```yaml
    systemLog:
      destination: file
      path: /var/log/mongodb/mongod.log
      logAppend: true
    ```

    Créez le répertoire avec des permissions permettant à MongoDB d&#39;y écrire et au collecteur de le lire. Pour les déploiements conteneurisés, partagez le répertoire des logs avec le collecteur et assurez-vous que MongoDB charge bien le fichier de configuration.

    Redémarrez MongoDB selon votre processus de déploiement habituel, par exemple :

    ```bash
    sudo systemctl restart mongod
    # Ou, pour Docker :
    docker restart <mongodb-container>
    ```
  </Step>

  <Step title="Configurer le collecteur" id="configure-collector">
    Enregistrez la configuration suivante sous `mongodb-monitoring.yaml` :

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb"

          - type: add
            field: resource["service.name"]
            value: "mongodb-service"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, batch]
          exporters: [otlp_http/observability]
    ```

    Le parseur lit les champs de timestamp et de sévérité de MongoDB, déplace `msg` dans le corps du log et conserve les champs tels que `c`, `ctx`, `id` et `attr` en tant qu&#39;attributs de log. Laissez `$$date` tel quel : le collecteur convertit le signe dollar échappé pour cibler le champ `$date` de MongoDB. Grâce à `start_at: end`, le récepteur ne lit que les nouvelles entrées.
  </Step>

  <Step title="Exécuter le collecteur" id="run-collector">
    Définissez les [variables de connexion](#connection-details), puis lancez la commande depuis le répertoire de configuration. Adaptez au besoin le chemin des logs sur l&#39;hôte. Si les fichiers sont lisibles par un groupe, ajoutez `--group-add LOG_GROUP_ID` en indiquant l&#39;identifiant numérique du groupe affiché par `ls -ln /var/log/mongodb`.

    ```bash
    docker run --rm --name mongodb-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/mongodb:/var/log/mongodb:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez le terminal ouvert et générez de l&#39;activité sur le serveur afin de produire de nouvelles entrées de log. Une fois vos tests terminés, arrêtez le collecteur avec **Ctrl+C**.
  </Step>

  <Step title="Vérifier les logs" id="verify-logs">
    Ouvrez **Recherche**, sélectionnez **Logs**, filtrez sur `ServiceName:mongodb-service` et sélectionnez **Last 15 minutes**. Les messages du serveur doivent s&#39;afficher avec leurs timestamps et leur sévérité correctement analysés.
  </Step>
</Steps>

## Jeu de données de démonstration {#demo-dataset}

L’échantillon contient 6,956 entrées de log du serveur MongoDB couvrant environ 24 heures. Le collecteur actualise leurs timestamps tout en conservant les messages et les attributs structurés.

<Steps>
  <Step title="Télécharger l’échantillon" id="download-sample">
    ```bash
    curl -fL -o mongod.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/mongodb/mongod.log
    ```
  </Step>

  <Step title="Configurer le collecteur de démonstration" id="configure-demo">
    Enregistrez ce qui suit sous le nom `mongodb-demo.yaml` :

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb-demo"

          - type: add
            field: resource["service.name"]
            value: "mongodb-demo"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:52.193Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="Lancer le collecteur de démonstration" id="run-demo">
    Définissez les [variables de connexion](#connection-details), puis exécutez la commande suivante depuis le répertoire contenant les deux fichiers :

    ```bash
    docker run --rm --name mongodb-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/mongod.log:/var/log/mongodb/mongod.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Laissez le terminal ouvert pendant que vous vérifiez l’ingestion, puis arrêtez le collecteur avec **Ctrl+C** une fois terminé. Chaque nouvelle exécution de la démonstration ingère à nouveau l’échantillon avec des timestamps actualisés.
  </Step>

  <Step title="Vérifier les logs de démonstration" id="verify-demo">
    Ouvrez **Recherche**, sélectionnez **Logs**, filtrez sur `ServiceName:mongodb-demo`, puis sélectionnez **Last 2 days**.

    <div className="ch-image-lg">
      <Frame>
        ![Logs de démonstration MongoDB avec messages analysés et niveaux de sévérité dans la page Recherche de ClickHouse Observability](/images/clickstack/observability-mongodb-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Dépannage {#troubleshooting}

### Aucun log n&#39;apparaît {#no-logs}

Consultez la sortie du collecteur pour repérer d&#39;éventuelles erreurs de permission sur les fichiers, d&#39;analyse, d&#39;authentification ou d&#39;exportation. Vérifiez que votre serveur écrit bien dans le répertoire monté et que les noms de fichiers correspondent à la liste `include` du récepteur. La configuration active ne lit que les nouvelles entrées.

### Les logs ne sont pas analysés correctement {#parsing-errors}

Vérifiez que le fichier contient un objet JSON par ligne :

```bash
tail -n 1 /var/log/mongodb/mongod.log | python3 -m json.tool
```

Le parseur attend des logs JSON MongoDB 4.4+. Les anciens logs au format texte nécessitent un autre parseur. Conservez l&#39;échappement `$$date` dans la configuration du collecteur.
