Faites vos premiers pas avec ClickHouse Observability : envoyez un événement de test, puis vérifiez qu&#39;il apparaît bien dans l&#39;UI d&#39;observability.

Le service fournit un endpoint de télémétrie géré. Envoyez vers cet endpoint les données de vos applications, de vos agents ou d&#39;un collecteur OpenTelemetry existant.

Si vous gérez vous-même votre pipeline d&#39;ingestion et votre schéma, suivez le [guide de premiers pas en mode autogéré](/fr/clickstack/self-configured/getting-started/managed).

## Avant de commencer {#before-you-begin}

Vous devez disposer d&#39;un service ClickHouse Observability entièrement géré, ainsi que d&#39;un accès à son endpoint de télémétrie et à son API key.

### Créer un service {#create-a-service}

Si vous n&#39;avez pas encore de service, commencez par la section [Créer un service ClickHouse](/fr/get-started/setup/cloud#1-create-a-clickhouse-service) du guide de démarrage rapide de ClickHouse Cloud. Une fois votre service démarré, ouvrez ClickHouse Observability. Si le service ne contient encore aucune donnée, la page **Premiers pas** s&#39;ouvre automatiquement. Choisissez l&#39;une des trois méthodes ci-dessous pour envoyer vos données de télémétrie.

## Configurer ClickHouse Observability {#set-up-clickhouse-observability}

Choisissez l’approche adaptée à votre environnement.

<Tabs>
  <Tab title="Utiliser une configuration OpenTelemetry existante">
    <div className="ch-image-md">
      <Frame>
        ![Boîte de dialogue Set up OpenTelemetry avec les options URL, Collector config et Env vars, et les informations de connexion masquées](/images/clickstack/getting-started/observability-connection-details.png)
      </Frame>
    </div>

    Choisissez cette approche si votre application, votre agent ou votre collecteur produit déjà des données OpenTelemetry.

    1. Sur la page Premiers pas, sélectionnez **Afficher les informations de connexion**.

    2. Copiez la configuration adaptée à votre émetteur de télémétrie. Les informations de connexion proposent les options **URL**, **Collector config** et **Env vars**.

    3. Configurez votre émetteur pour qu’il exporte la télémétrie vers l’endpoint géré à l’aide des informations d’authentification fournies.

    4. Générez une activité normale dans votre application, puis vérifiez que les données obtenues apparaissent dans [Recherche](/fr/clickstack/observability/features/search).

    Ces informations de connexion sont également disponibles sous **Team Settings → Data → Managed Telemetry**.

    <Tip>
      Pour une vérification rapide facultative, sélectionnez **send a test log** sur la page Premiers pas. Ce bouton envoie immédiatement un log de test depuis l’UI ; il ne vérifie pas la configuration de votre application ni celle de votre collecteur.
    </Tip>
  </Tab>

  <Tab title="Instrumenter avec l’IA">
    <div className="ch-image-md">
      <Frame>
        ![Boîte de dialogue Set it up with an AI agent affichant le prompt d’instrumentation ainsi que les variables d’environnement de l’endpoint et de l’API key masquées](/images/clickstack/getting-started/observability-ai-instrumentation.png)
      </Frame>
    </div>

    Choisissez cette approche si vous disposez de code applicatif et souhaitez que votre assistant de programmation vous aide à ajouter l’instrumentation OpenTelemetry.

    1. Sous **Instrumenter avec l’IA**, sélectionnez **Copy prompt** pour ouvrir la boîte de dialogue **Set it up with an AI agent**.
    2. Copiez le prompt affiché dans la boîte de dialogue et collez-le dans un assistant de programmation ayant accès à votre code applicatif, comme Cursor, Copilot ou Claude Code.
    3. Définissez `CLICKSTACK_OTLP_ENDPOINT` et `CLICKSTACK_API_KEY` avec les valeurs fournies dans la boîte de dialogue. Stockez-les dans un fichier `.env` exclu du contrôle de version ou dans votre gestionnaire de secrets.
    4. Examinez et appliquez l’instrumentation proposée, puis lancez votre application et générez un événement.

    Pour appliquer ce workflow à votre propre application, consultez [Instrumenter avec l’IA](/fr/clickstack/observability/ingesting-data/sdks/instrument-with-ai).

    Pour un exemple complet avec du code applicatif et un prompt d’instrumentation, suivez la [démo HackerNews Analyzer](/fr/clickstack/observability/example-datasets/instrument-application). Elle explique pas à pas comment envoyer les logs applicatifs, les traces, les métriques et la relecture de session navigateur vers votre service managé.
  </Tab>

  <Tab title="Suivre les guides de configuration">
    <div className="ch-image-md">
      <Frame>
        ![Boîte de dialogue Send data avec des guides de configuration consultables par langage, framework, infrastructure et collecteur](/images/clickstack/getting-started/observability-setup-guides.png)
      </Frame>
    </div>

    Choisissez cette approche si vous souhaitez des instructions propres à une application ou à une source d’infrastructure donnée.

    1. Sélectionnez **Parcourir les guides de configuration**.
    2. Choisissez le guide correspondant à votre langage, framework ou infrastructure.
    3. Suivez les étapes d’instrumentation et de configuration indiquées, puis générez de la télémétrie depuis cette source.

    Pour des exemples de configuration gérée, commencez par [la supervision Kubernetes](/fr/clickstack/observability/example-datasets/kubernetes), [les logs et métriques locaux](/fr/clickstack/observability/example-datasets/local-data) ou [l’application HackerNews Analyzer](/fr/clickstack/observability/example-datasets/instrument-application). Pour tester l’ingestion sans instrumenter d’application, utilisez [otelgen](/fr/clickstack/observability/example-datasets/otelgen) ou [telemetrygen](/fr/clickstack/observability/example-datasets/telemetrygen).
  </Tab>
</Tabs>

## Vérifier l&#39;ingestion et commencer l&#39;exploration {#verify-ingestion}

Une fois le parcours choisi terminé, sélectionnez **Start exploring** pour ouvrir [Recherche](/fr/clickstack/observability/features/search). Recherchez un événement que vous avez généré et vérifiez qu&#39;il est bien présent avant de poursuivre.

Pour les logs, sélectionnez la source **Logs** et un intervalle de temps couvrant le moment où vous avez envoyé l&#39;événement. L&#39;exemple ci-dessous montre un log envoyé à l&#39;aide du bouton **send a test log** de l&#39;UI, avec `example-service` comme nom de service. Développez un événement pour examiner ses attributs.
