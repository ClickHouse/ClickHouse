ClickHouse Observability vous permet d&#39;effectuer une recherche en texte intégral sur vos événements (logs et traces). Pour commencer, il vous suffit de saisir des mots-clés correspondant à vos événements. Par exemple, si votre log contient &quot;Error&quot;, vous le trouverez en saisissant simplement &quot;Error&quot; dans la barre de recherche.

La même syntaxe de recherche permet de filtrer les événements dans les tableaux de bord et les graphiques.

## Fonctionnalités de recherche {#search-features}

### Syntaxe de recherche Lucene {#natural-language-syntax}

* Les recherches ne sont pas sensibles à la casse
* Par défaut, les recherches portent sur des mots entiers (ex. `Error` correspondra à `Error here`
  mais pas à `Errors here`). Vous pouvez entourer un mot de caractères génériques pour rechercher des mots
  partiels (ex. `*Error*` correspondra à `AnyError` et `AnyErrors`)
* Les termes de recherche sont recherchés dans n’importe quel ordre (ex. `Hello World` correspondra aux logs
  contenant `Hello World` et `World Hello`)
* Vous pouvez exclure des mots-clés à l’aide de `NOT` ou `-` (ex. `Error NOT Exception` ou
  `Error -Exception`)
* Vous pouvez utiliser `AND` et `OR` pour combiner plusieurs mots-clés (ex.
  `Error OR Exception`)
* Pour obtenir des correspondances exactes, utilisez des guillemets doubles (ex. `"Error tests not found"`)

#### Recherche par colonne/propriété {#column-search}

* Vous pouvez effectuer une recherche dans les colonnes et les propriétés JSON/map avec la syntaxe `column:value` (par ex. `SeverityText:error`,
  `ServiceName:app`)
* Vous pouvez rechercher une plage de valeurs à l&#39;aide des opérateurs de comparaison (`>`, `<`,
  `>=`, `<=`) (par ex. `Duration:>1000`)
* Vous pouvez vérifier l&#39;existence d&#39;une propriété avec `property:*` (par ex.
  `Duration:*`)

### Saisie de l&#39;heure {#time-input}

* La saisie de l&#39;heure accepte des expressions en langage naturel (p. ex. `1 hour ago`, `yesterday`,
  `last week`).
* Si vous indiquez un seul instant donné, la recherche s&#39;effectue de cet instant
  jusqu&#39;à maintenant.
* Lors de la recherche, l&#39;intervalle de temps est toujours converti en intervalle de temps analysé, afin de
  faciliter le débogage des requêtes temporelles.
* Vous pouvez également sélectionner une barre de l&#39;histogramme pour zoomer sur un intervalle de temps précis.

### Syntaxe de recherche SQL {#sql-syntax}

Vous pouvez, si vous le souhaitez, basculer les champs de recherche en mode SQL. Ce mode accepte toute
clause `WHERE` valide pour la recherche. Il est utile pour les requêtes complexes qu&#39;il est impossible
d&#39;exprimer avec la syntaxe Lucene.

### Instruction SELECT {#select-statement}

Pour définir les colonnes à afficher dans les résultats de recherche, vous pouvez utiliser le champ
`SELECT`. Il s&#39;agit d&#39;une expression SQL `SELECT` qui indique les colonnes à sélectionner dans la page de recherche.
Les alias ne sont pas pris en charge pour le moment (par ex., vous ne pouvez pas utiliser `column as "alias"`).

## Recherches enregistrées {#saved-searches}

Vous pouvez enregistrer vos recherches pour y accéder rapidement par la suite. Une fois enregistrées, elles apparaissent sur la page `Saved Searches`, ce qui vous permet de retrouver facilement vos requêtes de recherche les plus utilisées sans avoir à les reconstruire.

### Ajouter des alertes aux recherches enregistrées {#alerts-on-saved-searches}

Les recherches enregistrées peuvent être surveillées à l&#39;aide d&#39;alertes qui vous préviennent lorsque certaines conditions sont remplies. Vous pouvez configurer des alertes qui se déclenchent lorsque le nombre d&#39;événements correspondant à votre recherche enregistrée dépasse un seuil donné ou passe en dessous de celui-ci.

Pour en savoir plus sur la mise en place et la configuration des alertes, consultez la [documentation sur les alertes](/fr/clickstack/observability/features/alerts).
