ClickHouse Observability prend en charge les visualisations basées sur des requêtes SQL brutes. Vous gardez ainsi un contrôle total sur la logique des requêtes, tout en profitant des intervalles de temps et des filtres définis au niveau du tableau de bord, ainsi que du rendu des graphiques.

Les visualisations basées sur SQL sont utiles lorsque vous devez aller au-delà de l’Explorateur de graphiques intégré, par exemple pour effectuer des jointures entre tables ou construire des agrégations complexes que l’éditeur de graphiques ne prend pas en charge.

## Créer une visualisation basée sur SQL {#creating-a-raw-sql-chart}

Pour créer une visualisation basée sur SQL, ouvrez l&#39;éditeur d&#39;une tuile de tableau de bord et sélectionnez **SQL**.

<div className="ch-image-lg">
  <Frame>
    ![Éditeur de visualisation SQL avec instructions de requête et macros](/images/clickstack/observability-sql-editor.png)
  </Frame>
</div>

Ensuite :

1. Sélectionnez la **Connexion** sur laquelle exécuter la requête.
2. Sélectionnez éventuellement une **Source** : cela permet d&#39;appliquer à votre graphique les filtres au niveau du tableau de bord via la macro `$__filters`, et permet à la requête d&#39;utiliser `$__sourceTable`.
3. Rédigez votre requête SQL dans l&#39;éditeur en utilisant des paramètres de requête et des macros pour tenir compte de l&#39;intervalle de temps, des filtres et des variables du tableau de bord.
4. Cliquez sur **Exécuter** pour prévisualiser les résultats, puis sur **Enregistrer** pour enregistrer la visualisation.

La connexion et la source peuvent également être définies par une [variable de connexion ou une variable de source de données](/fr/clickstack/observability/features/dashboards/overview#source-connection-variables) : c&#39;est alors l&#39;utilisateur qui consulte le tableau de bord qui choisit la connexion ou la source interrogée par la tuile.

## Paramètres de requête {#query-parameters}

Les [paramètres de requête](/fr/reference/syntax#defining-and-using-query-parameters) permettent à vos requêtes SQL de faire référence à l&#39;intervalle de temps et à la granularité actuels du tableau de bord. Ils reposent sur la syntaxe des requêtes paramétrées de ClickHouse : `{paramName:Type}`.

### Paramètres disponibles {#available-parameters}

Les paramètres disponibles dépendent du type de graphique :

**Graphiques de séries temporelles (y compris les barres empilées) :**

| Paramètre                       | Type  | Description                                                                               |
| ------------------------------- | ----- | ----------------------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Début de la plage de dates du tableau de bord (en millisecondes depuis l&#39;époque Unix) |
| `{endDateMilliseconds:Int64}`   | Int64 | Fin de la plage de dates du tableau de bord (en millisecondes depuis l&#39;époque Unix)   |
| `{intervalSeconds:Int64}`       | Int64 | Taille de l&#39;intervalle temporel en secondes (selon la granularité)                    |
| `{intervalMilliseconds:Int64}`  | Int64 | Taille de l&#39;intervalle temporel en millisecondes (selon la granularité)               |

**Graphiques de type table, secteurs et nombre :**

| Paramètre                       | Type  | Description                                                                               |
| ------------------------------- | ----- | ----------------------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Début de la plage de dates du tableau de bord (en millisecondes depuis l&#39;époque Unix) |
| `{endDateMilliseconds:Int64}`   | Int64 | Fin de la plage de dates du tableau de bord (en millisecondes depuis l&#39;époque Unix)   |

## Macros {#macros}

Les macros sont des raccourcis qui se développent en expressions SQL ClickHouse courantes. Elles sont préfixées par `$__` et sont remplacées avant l&#39;envoi de la requête à ClickHouse.

### Macros de bornes temporelles {#time-boundary-macros}

Ces macros renvoient une expression ClickHouse représentant l&#39;heure de début ou de fin de la plage temporelle du tableau de bord. Elles ne prennent aucun argument.

| Macro            | Développée en                                                         | Type de colonne |
| ---------------- | --------------------------------------------------------------------- | --------------- |
| `$__fromTime`    | `toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))` | DateTime        |
| `$__toTime`      | `toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))`   | DateTime        |
| `$__fromTime_ms` | `fromUnixTimestamp64Milli({startDateMilliseconds:Int64})`             | DateTime64      |
| `$__toTime_ms`   | `fromUnixTimestamp64Milli({endDateMilliseconds:Int64})`               | DateTime64      |
| `$__interval_s`  | `{intervalSeconds:Int64}`                                             | Int64           |

### Macros de filtre temporel {#time-filter-macros}

Ces macros génèrent un fragment de clause `WHERE` qui restreint une colonne à l&#39;intervalle de temps du tableau de bord.

| Macro                                 | Description                                                                                            |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `$__timeFilter(column)`               | Restreint une colonne `DateTime` à l&#39;intervalle du tableau de bord                                 |
| `$__timeFilter_ms(column)`            | Restreint une colonne `DateTime64` (précision à la milliseconde) à l&#39;intervalle du tableau de bord |
| `$__dateFilter(column)`               | Restreint une colonne `Date` à l&#39;intervalle du tableau de bord                                     |
| `$__dateTimeFilter(dateCol, timeCol)` | Filtre à partir de colonnes `Date` et `DateTime` distinctes                                            |
| `$__dt(dateCol, timeCol)`             | Alias de `$__dateTimeFilter`                                                                           |

**Exemple de développement** de `$__timeFilter(TimestampTime)` :

```sql
TimestampTime >= toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
AND TimestampTime <= toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
```

### Macros d’intervalle de temps {#time-interval-macros}

Ces macros regroupent les valeurs d’une colonne timestamp en intervalles correspondant à la granularité du tableau de bord. Elles sont généralement utilisées dans les clauses `SELECT` et `GROUP BY` des graphiques de séries temporelles. Ces macros ne sont disponibles que pour les visualisations **série temporelle**, y compris les barres empilées.

| Macro                        | Description                                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| `$__timeInterval(column)`    | Regroupe les valeurs d’une colonne `DateTime` en intervalles de `intervalSeconds`        |
| `$__timeInterval_ms(column)` | Regroupe les valeurs d’une colonne `DateTime64` en intervalles de `intervalMilliseconds` |

**Exemple de développement** de `$__timeInterval(TimestampTime)` :

```sql
toStartOfInterval(toDateTime(TimestampTime), INTERVAL {intervalSeconds:Int64} second)
```

### Macro de filtre de tableau de bord {#dashboard-filter-macro}

| Macro            | Description                                                                                                                                                                                                                                                                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filters`     | Remplacée par les conditions de filtrage définies au niveau du tableau de bord (nécessite qu&#39;une source soit sélectionnée)                                                                                                                                                                                                               |
| `$__sourceTable` | Remplacée par la table de la source sélectionnée, sous sa forme entièrement qualifiée, par exemple `default.otel_logs`. Pour les sources de métriques, utilisez `$__sourceTable(<metric type>)`, où le type de métrique est `gauge`, `histogram`, `sum`, `summary` ou `exponential histogram`. Nécessite qu&#39;une source soit sélectionnée |

Lorsqu&#39;une **Source** est sélectionnée pour le graphique et que des filtres de tableau de bord sont actifs, `$__filters` est développée en conditions SQL `WHERE` correspondantes. Lorsqu&#39;aucune source n&#39;est sélectionnée ou qu&#39;aucun filtre n&#39;est appliqué, elle est développée en `(1=1)` : on peut donc toujours l&#39;inclure sans risque dans une clause `WHERE`.

`$__filters` applique les valeurs sélectionnées dans les filtres de valeurs d&#39;expression SQL pour lesquels l&#39;option **Broadcast filter condition** est activée, ainsi que les conditions des [filtres ad hoc](/fr/clickstack/observability/features/dashboards/overview#adhoc-filters) qui s&#39;appliquent à la source de la tuile. Les filtres exposés sous forme de variables doivent être référencés explicitement, comme décrit ci-dessous.

### Macros de variables de tableau de bord {#dashboard-variables}

Lorsqu’un filtre de tableau de bord est [disponible en tant que variable](/fr/clickstack/observability/features/dashboards/overview#dashboard-variables) — un filtre de valeurs d’expression SQL avec l’option **Available as variable** activée, ou tout filtre de valeurs statiques, de valeurs de requête SQL ou de valeurs d’étiquette PromQL —, ses valeurs sélectionnées peuvent être référencées n’importe où dans la requête. Ces macros ne sont disponibles que dans les tuiles d’un tableau de bord qui déclare au moins une variable.

| Macro                                         | Description                                                                                                                                  |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | Est remplacée par `toString(<filter expression>) IN ($variable)` lorsque des valeurs sont sélectionnées pour `variable`, et par `1=1` sinon. |
| `$__filter(<expression>, $<variable>)`        | Est remplacée par `<expression> IN ($variable)` lorsque des valeurs sont sélectionnées pour `variable`, et par `1=1` sinon.                  |
| `$__conditionalAll(<condition>, $<variable>)` | Est remplacée par `<condition>` lorsque la variable comporte une sélection, et par `1=1` sinon.                                              |

Les valeurs d’une variable peuvent également être interpolées directement sous la forme `$name` ou `${name}`, avec un format facultatif : `${name:sqlstring}` (par défaut), `${name:csv}` ou `${name:regex}`. Avec le format par défaut, une référence directe est remplacée par `NULL` tant qu’aucune valeur n’est sélectionnée ; privilégiez donc les macros ci-dessus partout où un prédicat est attendu.

## Représentation graphique des résultats de requête {#how-results-are-plotted}

L&#39;UI associe automatiquement les colonnes de l&#39;ensemble de résultats aux éléments du graphique en fonction des types de colonnes. Les règles de correspondance varient selon le type de graphique.

### Graphiques de séries temporelles {#line-and-stacked-bar-charts}

| Rôle                | Type de colonne                       | Description                                                                                                         |
| ------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Timestamp**       | Première colonne `Date` ou `DateTime` | Sert d’axe des abscisses.                                                                                           |
| **Valeur de série** | Toutes les colonnes numériques        | Chaque colonne numérique est représentée sous forme de série distincte. Il s’agit généralement de valeurs agrégées. |
| **Noms de groupe**  | Colonnes `String`, `Map` ou `Array`   | Facultatif. Les lignes dont les valeurs de groupe diffèrent sont représentées sous forme de séries distinctes.      |

### Diagramme circulaire {#pie-chart}

| Rôle                   | Type de colonne                     | Description                                                     |
| ---------------------- | ----------------------------------- | --------------------------------------------------------------- |
| **Valeur du secteur**  | Première colonne numérique          | Détermine la taille de chaque secteur.                          |
| **Libellé du secteur** | Colonnes `String`, `Map` ou `Array` | Facultatif. Chaque valeur unique devient un libellé de secteur. |

### Graphique numérique {#number-chart}

| Rôle       | Type de colonne            | Description                                                              |
| ---------- | -------------------------- | ------------------------------------------------------------------------ |
| **Nombre** | Première colonne numérique | Affiche la valeur de la première ligne de la première colonne numérique. |

### Tableau {#table-chart}

Toutes les colonnes de l&#39;ensemble de résultats s&#39;affichent directement comme colonnes du tableau.

## Exemples {#examples}

<Info>
  **Noms de tables utilisés dans les exemples**

  Les exemples utilisent `otel_logs` et `otel_traces`. Adaptez les noms de tables et de colonnes à vos données. Pour exécuter les exemples sur [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com), utilisez `otel_v2.otel_logs` ou `otel_v2.otel_traces`.
</Info>

### Graphique de série temporelle — nombre de journaux par service au fil du temps {#example-line-chart}

Cette requête compte les événements de journal par service, regroupés en intervalles de temps correspondant à la granularité du tableau de bord.

```sql
SELECT
  toStartOfInterval(TimestampTime, INTERVAL {intervalSeconds:Int64} second) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

* `ts` (`DateTime`) sert de timestamp pour l&#39;axe des abscisses.
* `count` (numérique) est représenté comme valeur de la série.
* `ServiceName` (string) génère une ligne distincte par service.

### Graphique de séries temporelles — avec des macros {#example-line-chart-macros}

La même requête, réécrite avec des macros pour plus de concision :

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

### Graphique de série temporelle — utilisation des variables de tableau de bord {#example-line-chart-variables}

Pour un tableau de bord comportant une variable `service` sur `ServiceName` et une variable `severity` sur `SeverityText`, cette requête limite le graphique au service actuellement sélectionné et exclut les niveaux de sévérité sélectionnés. Les deux macros sont remplacées par `1=1` tant qu&#39;aucune valeur n&#39;est sélectionnée pour leur variable : le graphique s&#39;affiche donc sans filtre jusqu&#39;à ce que l&#39;utilisateur choisisse une valeur.

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

### Graphique à barres empilées — nombre d&#39;erreurs par niveau de sévérité {#example-stacked-bar}

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  lower(SeverityText),
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND lower(SeverityText) IN ('error', 'warn')
  AND $__filters
GROUP BY SeverityText, ts
ORDER BY ts ASC
```

### Tableau — les 10 endpoints les plus lents {#example-table}

```sql
SELECT
  SpanName AS endpoint,
  avg(Duration) / 1000 AS avg_duration_ms,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY SpanName
ORDER BY avg_duration_ms DESC
LIMIT 10
```

### Diagramme circulaire — répartition des requêtes par service {#example-pie}

```sql
SELECT
  ServiceName,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY ServiceName
```

* `request_count` (numérique) détermine la taille de chaque secteur.
* `ServiceName` (string) sert d&#39;étiquette à chaque secteur.

### Graphique numérique — nombre total d&#39;erreurs {#example-number}

```sql
SELECT
  count() AS total_errors
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND SeverityText = 'error'
  AND $__filters
```

Seule la valeur numérique `total_errors` de la première ligne est affichée.

## Notes {#notes}

* Les visualisations basées sur SQL s&#39;exécutent en mode `readonly` : seules les requêtes `SELECT` sont autorisées.
* Chaque visualisation basée sur SQL ne prend en charge qu&#39;une seule requête ; les requêtes multiples ne sont pas prises en charge.
* L&#39;éditeur SQL propose la complétion automatique pour les paramètres de requête comme pour les macros.
* Pour appliquer les filtres du tableau de bord aux visualisations basées sur SQL, vous devez sélectionner une source. Celle-ci doit correspondre à la table interrogée afin de garantir un filtrage précis.
* Les variables de tableau de bord ne nécessitent aucune source : leurs valeurs proviennent des listes déroulantes de filtres du tableau de bord, et non de la source propre à la tuile.
* Les alertes définies sur une tuile SQL qui fait référence à une variable de tableau de bord sont évaluées avec toutes les variables à l&#39;état vide, et non avec les valeurs sélectionnées dans le tableau de bord.
