    <Note>
      Ce guide s&#39;applique uniquement à **Self-managed ClickHouse Observability**. La destination ClickHouse de Vector écrit directement dans des tables que vous gérez. La version entièrement gérée de ClickHouse Observability requiert une ingestion OTLP ; consultez [Ingestion avec OpenTelemetry](/fr/clickstack/observability/ingesting-data/opentelemetry#fully-managed) pour les paramètres d&#39;endpoint et d&#39;authentification.
    </Note>

    [Vector](https://vector.dev) est un pipeline de données d&#39;observability hautes performances et indépendant de tout fournisseur. Il sert couramment à collecter, transformer et acheminer des logs et des métriques issus d&#39;un large éventail de sources, et il est particulièrement apprécié pour l&#39;ingestion de logs grâce à sa flexibilité et à sa faible consommation de ressources.

    Lorsqu&#39;ils utilisent Vector avec Self-managed ClickHouse Observability, les utilisateurs doivent définir eux-mêmes leurs schémas. Ces schémas peuvent suivre les conventions OpenTelemetry, mais aussi être entièrement personnalisés et refléter des structures d&#39;événements propres à l&#39;utilisateur. En pratique, l&#39;ingestion via Vector sert le plus souvent pour les **logs**, lorsque les utilisateurs veulent garder un contrôle total sur l&#39;analyse et l&#39;enrichissement avant l&#39;écriture des données dans ClickHouse.

    Ce guide explique comment ingérer des données dans Self-managed ClickHouse Observability à l&#39;aide de Vector. Par souci de simplicité, il ne détaille pas les sources Vector ni la configuration du pipeline. Il se concentre plutôt sur la configuration de la **destination** qui écrit les données dans ClickHouse, ainsi que sur la compatibilité du schéma obtenu avec Self-managed ClickHouse Observability.

    La seule exigence stricte du service est que les données comportent une **colonne de timestamp** (ou un champ temporel équivalent), que l’on peut déclarer lors de la configuration de la source de données dans l’UI d’observability.

## Envoi de données avec Vector {#sending-data-with-vector-self-configured}

    <br />

    Ce guide suppose que vous avez déjà créé un service Self-managed ClickHouse Observability et noté les identifiants de votre service. Si ce n&#39;est pas le cas, suivez le guide [Premiers pas](/fr/clickstack/self-configured/getting-started/managed) pour Self-managed ClickHouse Observability jusqu&#39;à ce que vous soyez invité à configurer Vector.

    <Steps>
      <Step title="Créez une base de données et une table" id="create-a-database-table-self-configured">
        Vector exige qu&#39;une table et un schéma soient définis avant toute ingestion de données.

        Commencez par créer une base de données. Vous pouvez le faire depuis la [Console ClickHouse Cloud](/fr/products/cloud/features/sql-console-features/sql-console).

        Dans l&#39;exemple ci-dessous, nous utilisons `logs` :

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        Créez une table pour vos données. Elle doit correspondre au schéma de sortie de vos données. L&#39;exemple ci-dessous repose sur une structure Nginx classique. Adaptez-la à vos données en respectant les [bonnes pratiques relatives aux schémas](/fr/concepts/best-practices/select-data-type). Nous vous **recommandons vivement** de vous familiariser avec le [concept de clés primaires](/fr/concepts/core-concepts/primary-indexes), puis de choisir votre clé primaire en suivant les recommandations décrites [ici](/fr/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key).

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Clé primaire Nginx**

          La clé primaire ci-dessus repose sur des schémas d’accès typiques dans l’UI d’observability pour les logs Nginx, mais il peut être nécessaire de l’ajuster en fonction de votre charge de travail dans les environnements de production.
        </Info>
      </Step>

      <Step title="Ajouter une destination ClickHouse à la configuration de Vector" id="add-clickhouse-sink-to-config-self-configured">
        Modifiez votre configuration Vector pour y ajouter la destination ClickHouse, en mettant à jour le champ `inputs` afin qu&#39;il reçoive les événements de vos pipelines existants.

        Cette configuration suppose que votre pipeline Vector en amont a déjà **préparé les données pour qu&#39;elles correspondent au schéma ClickHouse cible**, c&#39;est-à-dire que les champs sont analysés, correctement nommés et typés de manière appropriée pour l&#39;insertion. Consultez l&#39;[**exemple Nginx ci-dessous**](#example-dataset-with-vector-self-configured) pour une illustration complète de l&#39;analyse et de la normalisation de lignes de log brutes selon un schéma adapté au service.

        ```yaml
        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - your_input
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        Par défaut, nous recommandons d&#39;utiliser le format **`json_each_row`**, qui encode chaque événement sous la forme d&#39;un unique objet JSON par ligne. Il s&#39;agit du format par défaut et recommandé par le service pour l&#39;ingestion de données JSON ; il est à privilégier par rapport à d&#39;autres formats, comme les objets JSON encodés en chaînes de caractères.

        La destination ClickHouse prend également en charge l&#39;**encodage Arrow stream** (actuellement en bêta). Celui-ci peut offrir un débit plus élevé, mais s&#39;accompagne de contraintes importantes : la base de données et la table doivent être statiques, car le schéma n&#39;est récupéré qu&#39;une seule fois au démarrage, et le routage dynamique n&#39;est pas pris en charge. C&#39;est pourquoi l&#39;encodage Arrow convient surtout aux pipelines d&#39;ingestion fixes et bien définis.

        Nous vous recommandons de consulter les options de configuration disponibles pour la destination dans la [documentation de Vector](https://vector.dev/docs/reference/configuration/sinks/clickhouse) :

        <Note>
          L&#39;exemple ci-dessus utilise l&#39;utilisateur default de Self-managed ClickHouse Observability. Pour les déploiements en production, nous recommandons de [créer un utilisateur d&#39;ingestion dédié](/fr/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured) disposant des autorisations et des limites appropriées.
        </Note>
      </Step>

      <Step title="Accédez à l’UI d’observability" id="navigate-to-clickstack-ui-self-configured">
        Accédez à votre service Self-managed ClickHouse Observability et sélectionnez &quot;ClickStack&quot; dans le menu de gauche. Si vous avez déjà terminé la configuration initiale, l’UI d’observability s’ouvrira dans un nouvel onglet et vous serez automatiquement authentifié. Sinon, effectuez la configuration initiale, puis sélectionnez « Launch ClickStack » après avoir choisi Vector comme source d’entrée.

        <div className="ch-image-lg">
          <Frame>
            ![Lancer ClickStack pour Vector](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="Créer une source de données" id="create-a-datasource-managed-self-configured">
        Créez une source de données de logs. Si aucune source de données n’existe, vous serez invité à en créer une lors de votre première connexion. Sinon, accédez à Paramètres de l’équipe et ajoutez une nouvelle source de données.

        <div className="ch-image-lg">
          <Frame>
            ![Créer une source de données - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        La configuration ci-dessus suppose un schéma de type Nginx, avec une colonne `time_local` utilisée comme timestamp. Dans la mesure du possible, il doit s’agir de la colonne de timestamp déclarée dans la clé primaire. Cette colonne est obligatoire.

        Nous recommandons également de modifier le `Default SELECT` afin de définir explicitement les colonnes renvoyées dans la vue des logs. Si d’autres champs sont disponibles, comme le nom du service, le niveau de journalisation ou une colonne de corps, vous pouvez également les configurer. La colonne de timestamp affichée peut aussi être surchargée si elle diffère de la colonne utilisée dans la clé primaire de la table et configurée ci-dessus.

        Dans l’exemple ci-dessus, les données ne contiennent pas de colonne `Body`. Celle-ci est donc définie au moyen d’une expression SQL qui reconstruit une ligne de journal Nginx à partir des champs disponibles.

        Pour connaître les autres options possibles, consultez la [référence de configuration](/fr/clickstack/self-configured/managing/config).
      </Step>

      <Step title="Explorer les données" id="explore-the-data-managed-self-configured">
        Accédez à la vue des logs pour explorer les données et commencer à utiliser le service.

        <div className="ch-image-lg">

          </Frame>
        </div>
      </Step>
    </Steps>

## Jeu de données d’exemple avec Vector {#example-dataset-with-vector-self-configured}

    Pour un exemple plus complet, nous utilisons ci-dessous un **fichier journal Nginx**.

    Ce guide suppose que vous avez déjà créé un service Self-managed ClickHouse Observability et noté les identifiants de votre service. Si ce n&#39;est pas le cas, suivez le guide [Premiers pas](/fr/clickstack/self-configured/getting-started/managed) de Self-managed ClickHouse Observability jusqu&#39;à ce que vous soyez invité à configurer Vector.

    <Steps>
      <Step title="Installation de Vector" id="installing-vector-self-configured">
        <InstallingVector />
      </Step>

      <Step title="Télécharger les données d’exemple" id="download-the-sample-data-self-configured">
        <VectorSampleData />
      </Step>

      <Step title="Créez une base de données et une table" id="create-database-table-nginx-managed-self-configured">
        Vector exige qu&#39;une table et un schéma soient définis avant l&#39;ingestion de données.

        Commencez par créer une base de données, par exemple depuis la [console ClickHouse Cloud](/fr/products/cloud/features/sql-console-features/sql-console).

        Créez une base de données `logs` :

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        Créez une table pour vos données.

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Clé primaire Nginx**

          La clé primaire ci-dessus repose sur les schémas d’accès typiques de l’UI d’observability pour les logs Nginx, mais elle peut nécessiter des ajustements selon votre charge de travail dans les environnements de production.
        </Info>
      </Step>

      <Step title="Copier la configuration de Vector" id="copy-vector-configuration-self-configured">
        Copiez la configuration Vector et créez un fichier `nginx.yaml` en y définissant `CLICKHOUSE_ENDPOINT` et `CLICKHOUSE_PASSWORD`.

        ```yaml
        data_dir: ./.vector-data
        sources:
          nginx_logs:
            type: file
            include:
              - access.log
            read_from: beginning

        transforms:
          decode_json:
            type: remap
            inputs:
              - nginx_logs
            source: |
              . = parse_json!(to_string!(.message))
              ts = parse_timestamp!(.time_local, format: "%d/%b/%Y:%H:%M:%S %z")
              # ClickHouse-friendly DateTime format
              .time_local = format_timestamp!(ts, format: "%F %T")

        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - decode_json
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        <Note>
          L&#39;exemple ci-dessus utilise l&#39;utilisateur default pour Self-managed ClickHouse Observability. Pour les déploiements en production, nous vous recommandons de [créer un utilisateur d&#39;ingestion dédié](/fr/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured) doté des autorisations et des limites appropriées.
        </Note>
      </Step>

      <Step title="Démarrer Vector" id="start-vector-self-configured">
        Démarrez Vector avec la commande suivante, après avoir créé le répertoire de données qui servira à enregistrer les décalages de lecture des fichiers.

        ```bash
        mkdir ./.vector-data
        vector --config nginx.yaml
        ```
      </Step>

      <Step title="Accédez à l’UI d’observability" id="navigate-to-clickstack-ui-nginx-managed-self-configured">
        Accédez à votre service Self-managed ClickHouse Observability et sélectionnez &quot;ClickStack&quot; dans le menu de gauche. Si vous avez déjà terminé la configuration initiale, l’UI d’observability s’ouvrira dans un nouvel onglet et vous serez automatiquement authentifié. Sinon, suivez la configuration initiale, puis sélectionnez « Launch ClickStack » après avoir choisi Vector comme source d’entrée.

        <div className="ch-image-lg">
          <Frame>
            ![Lancer ClickStack pour Vector](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="Créer une source de données" id="create-a-datasource-nginx-managed-self-configured">
        Créez une source de données de logs. S&#39;il n&#39;existe aucune source de données, vous serez invité à en créer une lors de votre première connexion. Sinon, accédez à **Paramètres de l’équipe** et ajoutez une nouvelle source de données.

        <div className="ch-image-lg">
          <Frame>
            ![Créer une source de données - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        Cette configuration repose sur le schéma Nginx, avec une colonne `time_local` utilisée comme timestamp. Il s&#39;agit de la colonne de timestamp déclarée dans la clé primaire. Cette colonne est obligatoire.

        Nous avons également défini la sélection par défaut sur `time_local, remote_addr, status, request`, qui détermine les colonnes renvoyées dans la vue des logs.

        Dans l&#39;exemple ci-dessus, les données ne contiennent pas de colonne `Body`. Celle-ci est définie par l&#39;expression SQL suivante :

        ```sql
        concat(
          remote_addr, ' ',
          remote_user, ' ',
          '[', formatDateTime(time_local, '%d/%b/%Y:%H:%M:%S %z'), '] ',
          '"', request, '" ',
          toString(status), ' ',
          toString(body_bytes_sent), ' ',
          '"', http_referer, '" ',
          '"', http_user_agent, '" ',
          '"', http_x_forwarded_for, '" ',
          toString(request_time), ' ',
          toString(upstream_response_time), ' ',
          '"', http_host, '"'
        )
        ```

        La ligne de journal est ainsi reconstruite à partir des champs structurés.

        Pour connaître les autres options disponibles, consultez la [référence de configuration](/fr/clickstack/self-configured/managing/config).
      </Step>

      <Step title="Explorer les données" id="explore-the-data-nginx-managed-self-configured">

          </Frame>
        </div>
      </Step>
