    ClickHouse Observability inclut un **collecteur OpenTelemetry (OTel) géré** qui reçoit les logs, les métriques, les traces et les données de relecture de session, puis les écrit dans ClickHouse Cloud. ClickHouse Cloud exploite le collecteur d’ingestion, la base de données et l’interface utilisateur de ClickStack. De votre côté, il vous suffit d’instrumenter vos applications et de les configurer, ou de configurer vos agents de collecte de données, pour envoyer la télémétrie au service managé.

## Trouver vos informations de connexion {#connection-details}

    Dans votre service, ouvrez **Team Settings → Data** et repérez la section **Managed Telemetry**. Celle-ci fournit le point de terminaison OTLP et l’API key permettant d’envoyer la télémétrie à votre service.

    Sélectionnez **URL**, **Collector config** ou **Env vars** pour afficher les informations de connexion au format souhaité, puis cliquez sur **Copy connection details**. Configurez votre SDK ou votre collecteur avec l’endpoint et les paramètres d’authentification fournis.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry affichant l’endpoint OTLP HTTP masqué et l’API key](/images/clickstack/getting-started/observability-managed-telemetry.png)

    Pour plus de détails, consultez [Managed Telemetry](/fr/clickstack/observability/managing/config#managed-telemetry). Le bouton **Send a Test Log** vous permet d’envoyer un log de test au service.

## Choisir comment envoyer la télémétrie {#sending-telemetry}

### Instrumentation des applications {#application-instrumentation}

    Les SDK par langage collectent la télémétrie directement au sein de vos applications, par exemple les traces de requêtes et les journaux d’application. Configurez votre SDK pour exporter la télémétrie via OTLP vers l’endpoint géré, ou vers un collecteur de votre environnement qui la transmet au service.

    Vous pouvez réutiliser une instrumentation OpenTelemetry existante. Les SDK ClickStack offrent également des fonctionnalités telles que la relecture de session dans le navigateur ; consultez [Relecture de session](/fr/clickstack/observability/features/session-replay) pour un exemple de configuration gérée.

### Infrastructure et agents de collecte {#collection-agents}

    Exécutez des agents de collecte dans votre environnement pour recueillir de la télémétrie telle que les métriques des hôtes, les logs des conteneurs et les événements Kubernetes. Selon ce que vous devez collecter, un collecteur OpenTelemetry peut s’exécuter aux côtés d’une application, sur un hôte ou en tant que DaemonSet Kubernetes.

    Configurez ces agents pour qu’ils transmettent la télémétrie au point de terminaison OTLP géré à l’aide des informations de connexion de votre service. Vous pouvez également faire transiter la télémétrie applicative par ces collecteurs afin de la traiter avant qu’elle n’atteigne ClickHouse Observability.

## Vérifier l’ingestion {#verify-ingestion}

    Après avoir configuré votre application ou votre collecteur, générez de la télémétrie et ouvrez [Recherche](/fr/clickstack/observability/features/search). Sélectionnez la source **Logs** ou **Traces**, choisissez une plage de temps incluant les nouveaux événements, puis recherchez le nom de votre service pour vérifier que les données sont bien arrivées.

  <Tab title="Autogéré">
    Toutes les données sont ingérées dans Self-managed ClickHouse Observability via un **collecteur OpenTelemetry (OTel)**. Celui-ci constitue le point d’entrée principal des logs, des métriques, des traces et des données de session.

    Vous exécutez un collecteur OpenTelemetry pour recevoir les données de télémétrie de vos applications. Avec Self-managed ClickHouse Observability, ClickHouse et l’UI sont hébergés et gérés dans ClickHouse Cloud, l’authentification intégrée et la gestion opérationnelle étant prises en charge pour vous.

    <div className="ch-image-lg">
      <Frame>
        ![Télémétrie OTLP transitant par un collecteur autogéré vers ClickHouse, avec l’interface utilisateur de ClickStack hébergée dans ClickHouse Cloud](/images/use-cases/observability/clickstack-self-managed-architecture.svg)
      </Frame>
    </div>

    Le collecteur expose deux endpoints OTLP :

    * **HTTP** - port `4318`
    * **gRPC** - port `4317`

    Vous pouvez envoyer des données à ces endpoints soit directement depuis les [SDK par langage](/fr/clickstack/observability/ingesting-data/sdks), soit depuis des agents de collecte de données compatibles OTel, par exemple d’autres OTel collectors qui collectent des métriques et des logs d’infrastructure.

    Plus précisément :

    * Les [**SDK par langage**](/fr/clickstack/observability/ingesting-data/sdks) collectent la télémétrie au sein de votre application — principalement les **traces** et les **logs** — et exportent ces données, via le point de terminaison OTLP, vers le collecteur OpenTelemetry, qui se charge de l’ingestion dans ClickHouse. Pour plus de détails sur les SDK par langage disponibles, consultez [SDKs](/fr/clickstack/observability/ingesting-data/sdks).

    * Les **agents de collecte de données** sont des agents déployés en périphérie — sur des serveurs, des nœuds Kubernetes ou aux côtés des applications. Ils collectent la télémétrie d’infrastructure (par exemple, logs et métriques) ou reçoivent des événements directement des applications instrumentées avec des SDK. Dans ce cas, l’agent s’exécute sur le même hôte que l’application, souvent sous forme de sidecar ou de DaemonSet. Ces agents transmettent les données au collecteur OTel central de ClickStack, qui joue le rôle de [passerelle](/fr/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) et est généralement déployé une fois par cluster, centre de données ou région. La [passerelle](/fr/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) reçoit les événements OTLP des agents ou des applications et se charge de l’ingestion dans ClickHouse. Consultez [OTel collector](/fr/clickstack/self-configured/ingesting-data/collector) pour plus de détails. Ces agents peuvent être d’autres instances de l’OTel collector ou d’autres technologies, telles que [Fluentd](https://www.fluentd.org/) ou [Vector](https://vector.dev/).

    <Info>
      **Compatibilité OpenTelemetry**

      Bien que ClickStack propose ses propres SDK par langage et un collecteur OpenTelemetry personnalisé, offrant une télémétrie et des fonctionnalités enrichies, vous pouvez également utiliser en toute transparence vos SDK OpenTelemetry et agents existants.
