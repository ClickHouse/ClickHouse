    Envoyez des logs, des métriques et des traces vers ClickHouse Observability à l’aide des SDK OpenTelemetry ou d’un collecteur déployé dans votre environnement. Le service inclut un collecteur d’ingestion géré qui reçoit la télémétrie via OTLP et l’écrit dans ClickHouse Cloud.

## Obtenir vos informations de connexion {#sending-otel-data}

    Ouvrez votre service et accédez à **Paramètres de l’équipe → Données → Télémétrie gérée**. Copiez le **point de terminaison OTLP HTTP** et l’**API key**. Les onglets **Variables d’environnement** et **Configuration du collecteur** fournissent la configuration propre à votre service.

    <div className="ch-image-lg">
      <Frame>
        ![Télémétrie gérée affichant le point de terminaison OTLP HTTP et l’API key masqués](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Utilisez le point de terminaison HTTPS complet, y compris le port indiqué dans Télémétrie gérée. Pour un point de terminaison OTLP HTTP de base, omettez les chemins propres à chaque signal, tels que `/v1/logs`, `/v1/traces` et `/v1/metrics` ; les exportateurs ajoutent eux-mêmes ces chemins à la fin.

## Envoyer directement depuis une application {#sending-data-to-collector-managed}

    Installez et initialisez l’instrumentation OpenTelemetry ainsi qu’un exportateur OTLP HTTP pour le langage de votre application. Pour les SDK qui prennent en charge la configuration par variables d’environnement, définissez les valeurs suivantes dans l’environnement de l’application avant de la démarrer :

    ```shell
    export OTEL_SERVICE_NAME='my-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    Remplacez l’endpoint par la valeur exacte indiquée dans Télémétrie gérée, et `YOUR_API_KEY` par l’API key de votre service. Dans la variable d’environnement de l’en-tête, `%20` encode l’espace entre `Bearer` et la clé.

    La prise en charge des variables d’environnement varie selon le SDK. Si votre SDK impose une configuration dans le code, indiquez le même point de terminaison HTTPS, le protocole OTLP HTTP et un en-tête `authorization` avec la valeur `Bearer YOUR_API_KEY`. Consultez la [référence de configuration de l’exportateur OpenTelemetry](https://opentelemetry.io/docs/languages/sdk-configuration/otlp-exporter/) pour connaître la prise en charge selon les langages et les surcharges propres à chaque signal.

    Ces paramètres configurent uniquement l’exportation : votre application doit toujours être instrumentée pour générer de la télémétrie. Pour les enregistrements de sessions dans le navigateur, consultez le [guide de relecture de session](/fr/clickstack/observability/features/session-replay).

## Transférer des données depuis un collecteur {#forward-from-a-collector}

    Si vous collectez déjà de la télémétrie avec un collecteur OpenTelemetry, configurez un exportateur OTLP HTTP pour la transférer vers l’endpoint géré. Conservez vos récepteurs et processeurs existants pour la collecte et le traitement des données.

    Définissez les variables d’environnement suivantes dans l’environnement d’exécution du collecteur :

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_API_KEY='YOUR_API_KEY'
    ```

    Remplacez les deux caractères de substitution par les valeurs indiquées dans la section Télémétrie gérée. Ajoutez cet exportateur à la configuration de votre collecteur :

    ```yaml
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "Bearer ${env:OTEL_EXPORTER_OTLP_API_KEY}"
    ```

    Ajoutez `otlp_http/observability` à la liste `exporters` de chaque pipeline de logs, de métriques ou de traces à transférer, sous `service.pipelines`. Intégrez cet exportateur à votre configuration existante, puis redémarrez ou redéployez le collecteur pour appliquer les modifications.

    L’exemple utilise le nom d’exportateur actuel, `otlp_http`. Les versions plus anciennes du collecteur peuvent utiliser `otlphttp` ; utilisez le nom pris en charge par votre distribution. Consultez la [documentation de l’exportateur OTLP HTTP](https://github.com/open-telemetry/opentelemetry-collector/tree/main/exporter/otlphttpexporter) pour connaître les options de configuration.

    Pour un exemple complet de collecte des journaux de l’hôte et des métriques, consultez [Logs et métriques du système local](/fr/clickstack/observability/example-datasets/local-data).

## Vérifier l’ingestion {#verify-ingestion}

    Générez de la télémétrie dans votre application, puis ouvrez la page [Recherche](/fr/clickstack/observability/features/search) dans ClickHouse Observability. Sélectionnez **Logs** ou **Traces**, choisissez un intervalle de temps couvrant les nouveaux événements, puis recherchez le nom de votre service.

    Si aucune donnée n’apparaît, consultez les logs de votre SDK ou de votre collecteur pour repérer d’éventuelles erreurs d’exportation. Vérifiez l’endpoint, l’en-tête d’authentification et le protocole, et assurez-vous que l’application ou le collecteur peut joindre l’endpoint géré. Vérifiez également qu’aucun paramètre d’exportateur propre à un signal ne surcharge l’endpoint de base ou les en-têtes.

    Vous pouvez utiliser **Send a Test Log** dans Télémétrie gérée pour envoyer un log de test au service. Vérifiez séparément la télémétrie de votre application afin de valider son instrumentation et sa configuration d’exportation.

    Pour Self-managed ClickHouse Observability, un **collecteur OpenTelemetry (OTel)** reçoit les logs, les metrics, les traces et les données de session, puis les écrit dans ClickHouse Cloud. Nous recommandons la [distribution ClickStack](#installing-otel-collector-managed-self-configured) officielle du collecteur.

    Envoyez des données à ce collecteur depuis les [SDK par langage](/fr/clickstack/observability/ingesting-data/sdks) ou depuis des agents qui collectent les logs et métriques d’infrastructure. Il peut s’agir de collecteurs OpenTelemetry dans un [rôle d’agent](/fr/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured), de [Fluentd](https://www.fluentd.org/) ou de [Vector](https://vector.dev/). Pour une gestion centralisée des collecteurs, [Bindplane](/fr/clickstack/observability/integration-partners/bindplane) fournit une destination ClickHouse Observability ainsi que des outils de collecte, de traitement et de routage de la télémétrie.

## Envoi de données OpenTelemetry {#sending-otel-data-self-configured}

### Connecter le collecteur à ClickHouse Cloud {#installing-otel-collector-managed-self-configured}

    Configurez votre collecteur avec le [rôle de passerelle](/fr/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) afin qu’il reçoive les données OTLP via HTTP ou gRPC et les transmette à ClickHouse Cloud.

    <Info>
      **Nous vous recommandons d&#39;utiliser le collecteur OpenTelemetry ClickStack**

      La distribution ClickStack fournit un traitement et des schémas compatibles avec ClickHouse Observability. Le schéma par défaut permet la détection automatique des sources ainsi que des correspondances de colonnes préconfigurées.
    </Info>

    Dans ClickHouse Cloud, ouvrez votre service et [récupérez ses informations de connexion](/fr/products/cloud/guides/sql-console/connection-details). Configurez ces variables d’environnement dans l’environnement d’exécution de la distribution ClickStack du collecteur :

    ```shell
    CLICKHOUSE_ENDPOINT="https://<host>:8443"
    CLICKHOUSE_USER="<ingestion-user>"
    CLICKHOUSE_PASSWORD="<ingestion-password>"
    ```

    Utilisez l&#39;endpoint HTTPS de la base de données de votre service pour `CLICKHOUSE_ENDPOINT`, ainsi que les identifiants d&#39;un [utilisateur d&#39;ingestion dédié](/fr/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured). Redémarrez ou redéployez le collecteur pour appliquer ces paramètres. Celui-ci reçoit les données de télémétrie via OTLP et les écrit dans votre service ClickHouse Cloud.

    Si vous utilisez une autre distribution du collecteur, configurez son exportateur ClickHouse avec le même endpoint et les mêmes identifiants. Pour un exemple, consultez [Modification de la configuration](/fr/clickstack/self-configured/ingesting-data/collector#modifying-otel-collector-configuration-managed-self-configured).

    Pour les instructions d&#39;installation, consultez la section [Déploiement du collecteur](/fr/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured). Avant d&#39;envoyer du trafic de production, [sécurisez le collecteur](/fr/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured). Si vous activez `OTLP_AUTH_TOKEN`, configurez vos SDK et vos collecteurs de relais pour qu&#39;ils envoient ce jeton dans l&#39;en-tête `authorization`.

### Envoi des données au collecteur {#sending-data-to-collector-managed-self-configured}

    Pour un collecteur exécuté localement avec les ports OTLP par défaut, configurez votre instrumentation OpenTelemetry pour qu’elle pointe vers les endpoints ci-dessous. Si vos applications ou agents s’exécutent sur un autre hôte ou dans un autre conteneur, remplacez `localhost` par le nom d’hôte du collecteur joignable depuis cet environnement :

    * **HTTP (OTLP) :** `http://localhost:4318`
    * **gRPC (OTLP) :** `localhost:4317`

    Pour les [SDK par langage](/fr/clickstack/observability/ingesting-data/sdks) qui prennent en charge la configuration par variables d&#39;environnement, définissez l&#39;endpoint et le protocole avant de démarrer votre application instrumentée :

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    ```

    Si le collecteur requiert une authentification, définissez également `OTEL_EXPORTER_OTLP_HEADERS="authorization=<collector-token>"`, en remplaçant `<collector-token>` par la valeur de son `OTLP_AUTH_TOKEN`. N&#39;ajoutez pas le préfixe `Bearer` utilisé par les endpoints entièrement gérés. Ces paramètres configurent uniquement l&#39;exportation : l&#39;application doit toujours être instrumentée pour générer des données de télémétrie.

    Un agent utilisant la [distribution contrib de l&#39;OTel collector](https://github.com/open-telemetry/opentelemetry-collector-contrib) peut transférer des logs via OTLP. L&#39;exemple ci-dessous lit ce [fichier de journal structuré](https://datasets-documentation.s3.eu-west-3.amazonaws.com/http_logs/access-structured.log.gz). Téléchargez-le et décompressez-le à l&#39;emplacement indiqué dans `include` avant de démarrer l&#39;agent. Si votre passerelle exige une authentification, ajoutez à l&#39;exportateur de l&#39;agent un en-tête `authorization` contenant le jeton de la passerelle.

    ```yaml
    # clickhouse-agent-config.yaml
    receivers:
      filelog:
        include:
          - /opt/data/logs/access-structured.log
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.time_local
              layout: '%Y-%m-%d %H:%M:%S'
    exporters:
      # HTTP setup
      otlphttp/hdx:
        endpoint: 'http://localhost:4318'
        compression: gzip

      # gRPC setup (alternative)
      otlp/hdx:
        endpoint: 'localhost:4317'
        compression: gzip
    processors:
      batch:
        timeout: 5s
        send_batch_size: 10000
    service:
      telemetry:
        metrics:
          address: 0.0.0.0:9888 # Modified as 2 collectors running on same host
      pipelines:
        logs:
          receivers: [filelog]
          processors: [batch]
          exporters: [otlphttp/hdx]
    ```
