ClickStack comprend une bibliothèque de modèles de tableau de bord préconfigurés qui vous offrent une visibilité immédiate sur les métriques courantes de l’infrastructure et des applications.

## Parcourir les modèles disponibles {#browsing-templates}

Pour parcourir la bibliothèque de modèles intégrés, accédez à **Tableaux de bord**, puis cliquez sur **Parcourir les modèles de tableaux de bord**.

<div className="ch-image-lg">
  <Frame>
    ![Bouton Parcourir les modèles de tableaux de bord](/images/use-cases/observability/browse-dashboard-template.webp)
  </Frame>
</div>

Cela ouvre la galerie de modèles, dans laquelle ils sont classés par catégorie. Cliquez sur **Importer** pour démarrer le processus d&#39;importation de ce modèle.

<div className="ch-image-lg">
  <Frame>
    ![Galerie de modèles de tableaux de bord](/images/use-cases/observability/dashboard-template-gallery.webp)
  </Frame>
</div>

## Importer un modèle {#importing-a-template}

Pour importer un modèle, vous devez définir une source de données pour chaque visualisation du tableau de bord. Sélectionnez une source de données dans la liste déroulante pour chaque visualisation, puis cliquez sur `Finish Import`.

### Métriques d’exécution OTel {#otel-runtime-metrics}

Les modèles intégrés Métriques d’exécution OTel sont conçus pour les applications instrumentées avec les [métriques de l’environnement d’exécution OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/runtime/).

| Modèle                      | Description                                                                                                                  |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **.NET Runtime Metrics**    | Collectes du GC, taille du tas, utilisation du pool de threads et nombre d’assemblies pour les applications .NET             |
| **Go Runtime Metrics**      | Nombre de goroutines, durées de pause du GC, utilisation du tas et statistiques mémoire pour les applications Go             |
| **JVM Runtime Metrics**     | Mémoire du tas et hors tas, durée du GC, nombre de threads et chargement des classes pour les applications basées sur la JVM |
| **Node.js Runtime Metrics** | Délai de la boucle d’événements, utilisation du tas, taux d’utilisation du CPU et mémoire V8 pour les applications Node.js   |

Remarques :

* Chaque modèle est configuré avec un [filtre personnalisé](/fr/clickstack/features/dashboards/overview#custom-filters) ciblant les services dont l’attribut de ressource [`telemetry.sdk.language`](https://opentelemetry.io/docs/specs/semconv/registry/attributes/telemetry/#telemetry-sdk-language) correspond à l’environnement d’exécution du tableau de bord.
  * Dans les environnements utilisant des schémas de table de métriques ClickHouse personnalisés, il peut être nécessaire d’ajuster ce filtre afin d’interroger les bonnes colonnes Service Name et Resource Attributes.
  * Dans les environnements à fort volume, le temps de chargement des filtres peut être réduit en [matérialisant](/fr/clickstack/managing/performance-tuning#materialize-frequently-queried-attributes) la colonne `ResourceAttributes['telemetry.sdk.language']`.
* Les modèles s’appuient sur les conventions sémantiques OTel en vigueur au moment de leur publication et sont mis à jour périodiquement au fil des évolutions de la spécification OTel. Pour les services instrumentés avec des SDK OTel plus anciens, il faudra peut-être [modifier](/fr/clickstack/features/dashboards/overview#dashboards-editing-visualizations) les visualisations afin qu’elles utilisent les anciens noms de métriques.
