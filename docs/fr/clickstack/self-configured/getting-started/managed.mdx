  Cette page porte sur **Self-managed ClickHouse Observability**. Pour l’expérience entièrement gérée recommandée, consultez la documentation [ici](/fr/clickstack/observability/getting-started).
</Note>

Déployez Self-managed ClickHouse Observability sur ClickHouse Cloud, envoyez un événement de test dans votre pipeline d’ingestion, puis vérifiez que l’événement apparaît bien dans l’UI d’observability.

ClickHouse Cloud exploite le backend ClickHouse, tandis que vous gardez la maîtrise du pipeline d’ingestion et du schéma. Self-managed ClickHouse Observability offre :

* Mise à l’échelle automatique de la capacité de calcul, indépendamment du stockage
* Rétention économique et pratiquement illimitée grâce au stockage d’objet
* Isolation des charges de travail de lecture et d’écriture grâce aux [entrepôts](/fr/products/cloud/features/infrastructure/warehouses)
* Authentification intégrée
* Sauvegardes automatisées
* Fonctionnalités de sécurité et de conformité
* Mises à niveau transparentes

## Avant de commencer {#before-you-begin}

Vous pouvez également envoyer des données directement à ClickHouse à l&#39;aide d&#39;une [intégration prise en charge](/fr/integrations/home) et de votre propre schéma.

Suivez l’étape [Créer un service ClickHouse](/fr/get-started/setup/cloud#1-create-a-clickhouse-service) du guide de démarrage rapide de ClickHouse Cloud. Avant de poursuivre, vérifiez que le service est bien en cours d’exécution.

  ### Préparer l&#39;environnement d&#39;ingestion {#prepare-your-ingestion-environment}

  * Pour démarrer un nouveau [collecteur OpenTelemetry](/fr/clickstack/self-configured/ingesting-data/collector), installez [Docker](https://docs.docker.com/get-docker/). Sur Kubernetes, déployez le collecteur avec [Helm](/fr/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured).
  * Pour utiliser un collecteur existant, exécutez-le dans le [rôle de passerelle](/fr/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) et assurez-vous que sa distribution inclut l&#39;[exportateur ClickHouse](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter). Vous ajouterez la configuration nécessaire au fil de ce guide.

          L’UI génère la commande du collecteur avec les identifiants administrateur `default`. Nous recommandons d’utiliser des identifiants d’ingestion dédiés, afin de séparer l’accès à l’ingestion de l’administration et de ne pas dépendre du mot de passe administrateur.

          <Accordion title="Créer des identifiants d’ingestion dédiés (recommandé)">
            Dans ClickHouse Cloud, ouvrez la console SQL de votre service et exécutez :

            ```sql
            CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
            GRANT SELECT, INSERT, CREATE DATABASE, CREATE TABLE, CREATE VIEW ON default.* TO `clickstack-ingest`;
            ```

            Dans la commande générée, remplacez `CLICKHOUSE_USER="default"` par `CLICKHOUSE_USER="clickstack-ingest"` et renseignez dans `CLICKHOUSE_PASSWORD` le mot de passe de l’utilisateur dédié.
          </Accordion>

          Pour conserver les identifiants administrateur `default`, copiez la commande depuis l’onglet **Start Collector**. L’UI préremplit l’endpoint du service. Remplacez l’espace réservé du mot de passe par le mot de passe de votre service. Si vous ne l’avez plus, [récupérez ou réinitialisez vos informations de connexion](/fr/products/cloud/guides/sql-console/connection-details).

          La commande se présente sous la forme suivante :

          ```shell
          docker run -e CLICKHOUSE_ENDPOINT="https://<host>:8443" \
              -e CLICKHOUSE_USER="default" \
              -e CLICKHOUSE_PASSWORD="<your_password_here>" \
              -p 4317:4317 -p 4318:4318 \
              clickhouse/clickstack-otel-collector:latest
          ```

          Remplacez `<host>` et `<your_password_here>` par les valeurs de votre service ClickHouse Cloud, puis exécutez la commande.

          Le collecteur s’exécute au premier plan. Laissez ce terminal ouvert et utilisez un second terminal pour les autres commandes de ce guide.

          <Note>
            Cette commande expose les ports OTLP sans authentification et n’est destinée qu’à une évaluation locale. Avant d’envoyer du trafic de production, [sécurisez le collecteur](/fr/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).

Pour utiliser des identifiants d’ingestion dédiés, suivez la configuration facultative décrite dans l’onglet **Démarrer un nouveau collecteur**. Dans les deux blocs d’exportateur ClickHouse, remplacez `username: default` par `username: clickstack-ingest` et renseignez dans `password` le mot de passe de l’utilisateur dédié.

      ```shell
      NOW_NANO="$(date +%s)000000000"

      curl -i "http://localhost:4318/v1/logs" \
        -H "Content-Type: application/json" \
        --data-binary @- <<EOF
      {
        "resourceLogs": [{
          "resource": {
            "attributes": [{
              "key": "service.name",
              "value": {"stringValue": "clickstack-docs-test"}
            }]
          },
          "scopeLogs": [{
            "scope": {"name": "clickstack-docs-test"},
            "logRecords": [{
              "timeUnixNano": "${NOW_NANO}",
              "severityText": "INFO",
              "body": {"stringValue": "ClickStack ingestion test"}
            }]
          }]
        }]
      }
      EOF
      ```

  ## Configurer Self-managed ClickHouse Observability {#set-up-managed-clickstack-vector}

  <Steps titleSize="h3">

      Sur la page **Choose an ingestion source**, sélectionnez [Vector](https://vector.dev/).

      [Vector](https://vector.dev) est un pipeline de données d&#39;observability hautes performances et indépendant de tout fournisseur, particulièrement apprécié pour l&#39;ingestion de journaux grâce à sa flexibilité et à sa faible consommation de ressources.

      Avec Vector, c&#39;est vous qui définissez le schéma. Il peut suivre les conventions OpenTelemetry ou utiliser des champs propres à vos événements.

      <Info>
        **Pipeline Vector existant requis**

        Suivez ce guide si vous exécutez déjà Vector avec un pipeline d’entrée. Les données transmises par le pipeline doivent inclure une **colonne d’horodatage** ou un champ temporel équivalent, que vous sélectionnerez lors de la configuration de la source de données dans l’UI d’observability.

        Les étapes ci-dessous permettent d’ajouter une destination ClickHouse à votre pipeline existant.
      </Info>

#### Créer une base de données et une table {#create-a-vector-database-and-table}

      Créez une base de données et une table avant de configurer la destination Vector.

      Dans ClickHouse Cloud, ouvrez la console SQL de votre service et créez une base de données :

      Par exemple, créez une base de données pour les logs :

      ```sql
      CREATE DATABASE IF NOT EXISTS logs
      ```

      Créez ensuite une table dont le schéma correspond à la structure de vos données de journaux. L&#39;exemple ci-dessous part du principe que vos journaux d&#39;accès Nginx utilisent le format classique :

      ```sql
      CREATE TABLE logs.nginx_logs
      (
          `time_local` DateTime,
          `remote_addr` IPv4,
          `remote_user` LowCardinality(String),
          `request` String,
          `status` UInt16,
          `body_bytes_sent` UInt64,
          `http_referer` String,
          `http_user_agent` String,
          `http_x_forwarded_for` LowCardinality(String),
          `request_time` Float32,
          `upstream_response_time` Float32,
          `http_host` String
      )
      ENGINE = MergeTree
      ORDER BY (toStartOfMinute(time_local), status, remote_addr);
      ```

      Votre table doit correspondre au schéma de sortie produit par Vector. Adaptez le schéma à vos données si nécessaire, en suivant les [bonnes pratiques recommandées pour les schémas](/fr/concepts/best-practices/select-data-type).

      Nous vous recommandons vivement de bien comprendre le fonctionnement des [clés primaires](/fr/concepts/core-concepts/primary-indexes) dans ClickHouse et de choisir une clé de tri adaptée à vos schémas d’accès. Consultez les recommandations du guide d’[optimisation des performances](/fr/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key) sur le choix d’une clé primaire.

#### Configurer la destination ClickHouse {#configure-the-vector-clickhouse-sink}

      Une fois la table créée, ajoutez une destination ClickHouse à votre configuration Vector :

      ```yaml
      sinks:
        clickhouse:
          type: clickhouse
          inputs:
            - your_input
          endpoint: "https://<host>:8443"
          database: logs
          table: nginx_logs
          format: json_each_row
          skip_unknown_fields: true
          auth:
            strategy: basic
            user: default
            password: "<your_password_here>"
      ```

      Remplacez `your_input` par l’entrée de votre pipeline existant. Remplacez `<host>` et `<your_password_here>` par les valeurs de votre service ClickHouse Cloud. Si nécessaire, modifiez la base de données cible ou la table.

      <Accordion title="Utilisez des identifiants dédiés à l’ingestion (recommandé)">
        En production, créez un utilisateur dédié et accordez-lui l&#39;accès à la table cible de Vector. Dans ClickHouse Cloud, ouvrez la console SQL de votre service et exécutez :

        ```sql
        CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
        GRANT SELECT, INSERT ON logs.nginx_logs TO `clickstack-ingest`;
        ```

        Remplacez `default` par `clickstack-ingest` dans la destination Vector et définissez `password` sur le mot de passe de l&#39;utilisateur dédié.
      </Accordion>

      Enregistrez la configuration modifiée, puis rechargez ou redémarrez Vector selon votre processus de déploiement habituel.

      Pour d&#39;autres exemples d&#39;ingestion de données avec Vector, consultez [Ingestion avec Vector](/fr/clickstack/observability/ingesting-data/vector) ou, pour les options avancées, la [documentation de la destination ClickHouse de Vector](https://vector.dev/docs/reference/configuration/sinks/clickhouse/).

#### Créer une source de données {#create-a-vector-data-source}

      Créez une source de données pour la table alimentée par votre pipeline Vector. L’UI vous invite à en créer une lors de votre première connexion.

      Le formulaire préremplit les expressions correspondant au schéma OpenTelemetry par défaut. Pour la table Nginx créée dans ce guide, configurez la source avec les valeurs suivantes :

      | Paramètre                                  | Valeur                                                                                                          |
      | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
      | **Nom**                                    | `Nginx logs`                                                                                                    |
      | **Type de données de la source**           | Journal                                                                                                         |
      | **Connexion au Serveur**                   | `Default`                                                                                                       |
      | **Base de données**                        | `logs`                                                                                                          |
      | **Table**                                  | `nginx_logs`                                                                                                    |
      | **Colonne d’horodatage**                   | `time_local`                                                                                                    |
      | **SELECT par défaut**                      | `time_local, remote_addr, status, request`                                                                      |
      | **Expression du nom du service**           | `'nginx'`                                                                                                       |
      | **Expression du niveau de journalisation** | `multiIf(status >= 500, 'ERROR', status >= 400, 'WARN', 'INFO')`                                                |
      | **Expression des Attributs de Journal**    | `map('http.remote_addr', toString(remote_addr), 'http.status_code', toString(status), 'http.request', request)` |
      | **Expression des Attributs de Ressource**  | `map('service.name', 'nginx')`                                                                                  |
      | **Colonne d’horodatage affichée**          | `time_local`                                                                                                    |
      | **Expression de l&#39;ID de trace**        | `''`                                                                                                            |
      | **Expression de l&#39;ID de span**         | `''`                                                                                                            |
      | **Expression de colonne implicite**        | `request`                                                                                                       |

      La table Nginx ne contient pas de colonne `Body`. Définissez **Body Expression** comme suit :

      ```sql
      concat(
        remote_addr, ' ',
        remote_user, ' ',
        '[', formatDateTime(time_local, '%d/%b/%Y:%H:%i:%S %z'), '] ',
        '"', request, '" ',
        toString(status), ' ',
        toString(body_bytes_sent), ' ',
        '"', http_referer, '" ',
        '"', http_user_agent, '" ',
        '"', http_x_forwarded_for, '" ',
        toString(request_time), ' ',
        toString(upstream_response_time), ' ',
        '"', http_host, '"'
      )
      ```

      Pour les autres paramètres de la source, consultez la [référence de configuration](/fr/clickstack/self-configured/managing/config).
    </Step>

    </Step>
