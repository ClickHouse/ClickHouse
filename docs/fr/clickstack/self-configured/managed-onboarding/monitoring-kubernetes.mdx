<Note>
  Cette page concerne **Self-managed ClickHouse Observability**. Pour l’expérience entièrement gérée, que nous recommandons, consultez la documentation [ici](/fr/clickstack/observability/integration-examples/kubernetes).
</Note>

Ce guide explique comment collecter les logs, les métriques d’infrastructure et les événements Kubernetes d’un cluster dans Self-managed ClickHouse Observability, puis les consulter dans le tableau de bord Kubernetes intégré.

Il s’appuie sur le modèle OpenTelemetry standard : deux collecteurs déployés via le [chart Helm OpenTelemetry](https://github.com/open-telemetry/opentelemetry-helm-charts/tree/main/charts/opentelemetry-collector), qui transmettent chacun les données à votre collecteur passerelle ClickStack via OTLP. Un **DaemonSet** s’exécute sur chaque nœud pour collecter les logs des conteneurs et les métriques du kubelet. Un **Déploiement** à réplica unique collecte les événements Kubernetes et les métriques à l’échelle du cluster. Pour en savoir plus sur le rôle de passerelle, consultez [Rôles du collecteur](/fr/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured).

Ce guide suppose que vous avez suivi [Configuration de votre collecteur OpenTelemetry](/fr/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) et qu’un collecteur passerelle ClickStack est en cours d’exécution.

Pour une charge de travail hébergée dans Kubernetes, le collecteur passerelle doit lui-même être déployé **dans le même cluster à l’aide du chart Helm OpenTelemetry upstream et de l’image du collecteur ClickStack**. Pour l’installer, suivez la procédure Helm décrite dans [Déploiement du collecteur](/fr/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured). **Veillez à noter ce point de terminaison OTLP**.

<Steps>
  <Step title="Préparez les prérequis" id="gather-prerequisites">
    Vous aurez besoin de :

    * Un **cluster Kubernetes** (v1.20+ recommandée) avec `kubectl` configuré pour y accéder.
    * **[Helm](https://helm.sh/) v3+**.
    * Le **point de terminaison OTLP** de votre collecteur passerelle ClickStack, joignable depuis l&#39;intérieur du cluster, par exemple `http://clickstack-otel-collector.observability.svc.cluster.local:4318`. Le collecteur doit être déployé à un emplacement joignable par vos DaemonSets et votre Déploiement, généralement dans le même cluster ou derrière un service de type `LoadBalancer`.
    * La valeur `OTLP_AUTH_TOKEN` que vous avez définie lors du déploiement du collecteur passerelle. Si vous n&#39;avez pas sécurisé le collecteur, vous pouvez ignorer l&#39;étape de création du secret ci-dessous et retirer l&#39;en-tête `authorization` des manifestes.

    <Info>
      **Emplacement de la passerelle**

      Pour un déploiement local au cluster, exécutez le collecteur passerelle sous forme de `Deployment` ou de `StatefulSet` Kubernetes dans le même cluster, et joignez-le via le nom DNS de son service in-cluster. Si la passerelle s&#39;exécute en dehors du cluster, utilisez son URL accessible depuis l&#39;extérieur.
    </Info>
  </Step>

  <Step title="Créez le secret d’authentification et la ConfigMap" id="create-secret-and-configmap">
    Choisissez le namespace dans lequel déployer les collecteurs, puis créez un secret contenant le `OTLP_AUTH_TOKEN` et une ConfigMap pointant vers votre passerelle :

    ```shell
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    export OTEL_COLLECTOR_ENDPOINT="http://clickstack-otel-collector.observability.svc.cluster.local:4318"
    export NAMESPACE=observability

    kubectl create namespace ${NAMESPACE} --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic clickstack-otlp-secret \
      --from-literal=OTLP_AUTH_TOKEN=${OTLP_AUTH_TOKEN} \
      -n ${NAMESPACE}

    kubectl create configmap otel-config-vars \
      --from-literal=YOUR_OTEL_COLLECTOR_ENDPOINT=${OTEL_COLLECTOR_ENDPOINT} \
      -n ${NAMESPACE}
    ```

    Les deux collecteurs ci-dessous lisent ces valeurs via `extraEnvs` : ils réutilisent donc le même secret et la même ConfigMap.
  </Step>

  <Step title="Ajoutez le dépôt Helm d’OpenTelemetry" id="add-otel-helm-repo">
    ```shell
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update
    ```
  </Step>

  <Step title="Déployer le collecteur du cluster" id="deploy-cluster-collector">
    Il s’agit d’un Déploiement à réplique unique qui collecte les **événements Kubernetes** et les **métriques à l’échelle du cluster** (nombre de nœuds, phases des groupes de conteneurs, statut des déploiements, etc.). Exécuter plusieurs répliques produirait des doublons.

    Enregistrez le contenu suivant sous le nom `k8s_deployment.yaml` :

    <Accordion title="k8s_deployment.yaml">
      ```yaml
      # k8s_deployment.yaml
      mode: deployment

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # Un seul de ces collecteurs est nécessaire : au-delà, les données seraient dupliquées
      replicaCount: 1

      presets:
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        # Collecte les événements Kubernetes via le k8sobject receiver.
        kubernetesEvents:
          enabled: true
        # Collecte les métriques au niveau du cluster via le k8s_cluster receiver.
        clusterMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"
        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    Installez-le :

    ```shell
    helm install k8s-otel-deployment open-telemetry/opentelemetry-collector \
      -f k8s_deployment.yaml \
      -n ${NAMESPACE}
    ```
  </Step>

  <Step title="Déployer le collecteur de nœud" id="deploy-node-collector">
    Il s&#39;agit d&#39;un DaemonSet qui s&#39;exécute sur chaque nœud afin de collecter les **logs des conteneurs**, les **métriques de l&#39;hôte** et les **métriques de l&#39;agent de nœud Kubernetes (kubelet)** (taux d’utilisation du CPU et de la mémoire par groupe de conteneurs et par conteneur, rapporté aux requests et aux limits).

    Enregistrez le contenu suivant sous le nom `k8s_daemonset.yaml` :

    <Accordion title="k8s_daemonset.yaml">
      ```yaml
      # k8s_daemonset.yaml
      mode: daemonset

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # Requis pour utiliser les métriques de taux d'utilisation CPU/mémoire de kubeletstats
      clusterRole:
        create: true
        rules:
          - apiGroups:
              - ''
            resources:
              - nodes/proxy
            verbs:
              - get

      presets:
        logsCollection:
          enabled: true
        hostMetrics:
          enabled: true
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        kubeletMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        receivers:
          # Métriques kubelet supplémentaires exprimées en taux d'utilisation rapporté aux requests et aux limits.
          kubeletstats:
            collection_interval: 20s
            auth_type: 'serviceAccount'
            endpoint: '${env:K8S_NODE_NAME}:10250'
            insecure_skip_verify: true
            metrics:
              k8s.pod.cpu_limit_utilization:
                enabled: true
              k8s.pod.cpu_request_utilization:
                enabled: true
              k8s.pod.memory_limit_utilization:
                enabled: true
              k8s.pod.memory_request_utilization:
                enabled: true
              k8s.pod.uptime:
                enabled: true
              k8s.node.uptime:
                enabled: true
              k8s.container.cpu_limit_utilization:
                enabled: true
              k8s.container.cpu_request_utilization:
                enabled: true
              k8s.container.memory_limit_utilization:
                enabled: true
              k8s.container.memory_request_utilization:
                enabled: true
              container.uptime:
                enabled: true

        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"

        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    Installez-le :

    ```shell
    helm install k8s-otel-daemonset open-telemetry/opentelemetry-collector \
      -f k8s_daemonset.yaml \
      -n ${NAMESPACE}
    ```

    Vérifiez que les deux releases sont opérationnelles :

    ```shell
    kubectl get pods -n ${NAMESPACE} -l app.kubernetes.io/name=opentelemetry-collector
    ```

    Vous devriez voir un groupe de conteneurs pour le Déploiement et un groupe de conteneurs DaemonSet par nœud, tous à l’état `Running`.
  </Step>

  <Step title="Transmettre les attributs Kubernetes à vos applications (recommandé)" id="forward-k8s-attributes">
    Pour corréler les journaux d’application, les métriques et les traces avec les métadonnées Kubernetes (nom du groupe de conteneurs, namespace, nœud, déploiement), transmettez ces métadonnées à votre application via `OTEL_RESOURCE_ATTRIBUTES`. Le processeur `k8sattributes` du DaemonSet enrichira alors la télémétrie entrante avec les attributs du groupe de conteneurs et du nœud correspondants.

    ```yaml
    # my_app_deployment.yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: app-deployment
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: app
      template:
        metadata:
          labels:
            app: app
            service.name: <MY_APP_NAME>
        spec:
          containers:
            - name: app-container
              image: my-image
              env:
                - name: POD_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.name
                - name: POD_UID
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.uid
                - name: POD_NAMESPACE
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.namespace
                - name: NODE_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: spec.nodeName
                - name: DEPLOYMENT_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.labels['deployment']
                - name: OTEL_RESOURCE_ATTRIBUTES
                  value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME),k8s.deployment.name=$(DEPLOYMENT_NAME)
    ```
  </Step>

  <Step title="Confirmez dans l’interface utilisateur de ClickStack" id="confirm-in-ui">
    Ouvrez votre service dans la [Console ClickHouse Cloud](https://console.clickhouse.cloud) et sélectionnez **ClickStack** dans le menu de gauche.

    <div className="ch-image-lg">
      <Frame>
        ![Lancer ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    Dans la vue **Search**, définissez la source sur `Logs` et l’intervalle de temps sur **Last 15 minutes**. Les logs des conteneurs de l’ensemble du cluster devraient apparaître en quelques secondes, enrichis d’attributs tels que `k8s.namespace.name`, `k8s.pod.name` et `k8s.node.name`.

    <div className="ch-image-lg">
      <Frame>
        ![Vue de recherche ClickStack avec les logs Kubernetes](/images/use-cases/observability/clickstack-search-with-k8-logs.webp)
      </Frame>
    </div>

    Pour visualiser en contexte les métriques et les événements de l’infrastructure, ouvrez le tableau de bord intégré **Kubernetes** via **Dashboards** -&gt; **Kubernetes**. Les onglets `Pods`, `Nodes` et `Namespaces` devraient tous contenir des données.

    <div className="ch-image-lg">
      <Frame>
        ![Tableau de bord Kubernetes de ClickStack](/images/use-cases/observability/clickstack-dashboard-kubernetes.webp)
      </Frame>
    </div>

    Si rien ne s’affiche :

    * Vérifiez que les groupes de conteneurs du DaemonSet et du Déploiement sont à l’état `Running` et suivez leurs logs avec `kubectl logs -n ${NAMESPACE} <pod>`.
    * Assurez-vous que `YOUR_OTEL_COLLECTOR_ENDPOINT` est joignable depuis l’intérieur du cluster (connectez-vous à l’un des groupes de conteneurs du collecteur avec `kubectl exec`, puis testez l’endpoint avec `curl`).
    * Vérifiez que le `OTLP_AUTH_TOKEN` du secret correspond à la valeur définie sur le collecteur passerelle.
  </Step>
