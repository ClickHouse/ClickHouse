<Note>
  Cette page porte sur **Self-managed ClickHouse Observability**. La version entièrement gérée de ClickHouse Observability, expérience par défaut recommandée, gère pour vous les schémas de base de données et la correspondance des types. Vous n&#39;avez pas besoin de configurer ces composants internes pour effectuer la migration : pour commencer, suivez le [guide de migration depuis Elasticsearch](/fr/clickstack/observability/migration/elastic).
</Note>

Elasticsearch et ClickHouse prennent en charge une grande variété de types de données, mais leurs modèles de stockage sous-jacent et d&#39;interrogation diffèrent fondamentalement. Cette section associe les types de champs Elasticsearch les plus courants à leurs équivalents ClickHouse, lorsqu&#39;ils existent, et apporte des éléments de contexte pour guider vos migrations. En l&#39;absence d&#39;équivalent, des alternatives ou des remarques sont indiquées dans les commentaires.

### Notes {#notes}

* **Tableaux** : dans Elasticsearch, tous les champs prennent en charge les tableaux de manière native. Dans ClickHouse, les tableaux doivent être définis explicitement (par exemple, `Array(String)`), ce qui présente l&#39;avantage de pouvoir accéder à des positions précises et de les interroger, par exemple `an_array[1]`.
* **Multi-champs** : Elasticsearch permet d&#39;indexer le [même champ de plusieurs manières](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields#_multi_fields_with_multiple_analyzers) (par exemple, à la fois en `text` et en `keyword`). Dans ClickHouse, ce modèle doit être reproduit à l&#39;aide de colonnes ou de vues distinctes.
* **Types Map et JSON** - Dans ClickHouse, le type [`Map`](/fr/reference/data-types/map) est couramment utilisé pour modéliser des structures clé-valeur dynamiques telles que `resourceAttributes` et `logAttributes`. Ce type permet une ingestion flexible sans schéma, car il autorise l&#39;ajout de clés arbitraires à l&#39;exécution — dans un esprit proche des objets JSON d&#39;Elasticsearch. Il présente toutefois des limitations importantes à prendre en compte :

  * **Types de valeurs uniformes** : les colonnes [`Map`](/fr/reference/data-types/map) de ClickHouse doivent avoir un type de valeur unique (par exemple, `Map(String, String)`). Les valeurs de types mixtes ne sont pas prises en charge sans conversion.
  * **Coût en performance** : l&#39;accès à n&#39;importe quelle clé d&#39;une [`Map`](/fr/reference/data-types/map) nécessite de charger l&#39;intégralité de la map en mémoire, ce qui peut nuire aux performances.
  * **Pas de sous-colonnes** : contrairement à JSON, les clés d&#39;une [`Map`](/fr/reference/data-types/map) ne sont pas représentées comme de véritables sous-colonnes, ce qui limite la capacité de ClickHouse à indexer, compresser et interroger efficacement les données.

  Le type [`JSON`](/fr/reference/data-types/newjson) de ClickHouse constitue une alternative à [`Map`](/fr/reference/data-types/map) pour les attributs dynamiques et lève plusieurs de ces limitations :

  * **Véritable stockage en colonnes** : chaque path JSON est stocké sous forme de sous-colonne, ce qui permet une compression, un filtrage et une exécution vectorisée des requêtes efficaces.
  * **Prise en charge des types mixtes** : différents types de données (par exemple, entiers, chaînes, tableaux) peuvent coexister sous le même path sans conversion ni unification des types.
  * **Capacité de mise à l’échelle du système de fichiers** : des limites internes sur les clés dynamiques (`max_dynamic_paths`) et les types (`max_dynamic_types`) empêchent une explosion du nombre de fichiers de colonnes sur le disque, même avec des ensembles de clés à cardinalité élevée.
  * **Stockage dense** : les valeurs nulles et manquantes sont stockées de manière creuse afin d&#39;éviter toute surcharge inutile.

    Le type [`JSON`](/fr/reference/data-types/newjson) est particulièrement adapté aux charges de travail d&#39;observability : il allie la flexibilité d&#39;une ingestion sans schéma aux performances et à la capacité de mise à l’échelle des types natifs de ClickHouse, ce qui en fait un remplaçant idéal de [`Map`](/fr/reference/data-types/map) pour les champs d&#39;attributs dynamiques.

    Pour en savoir plus sur le type JSON, nous vous recommandons le [guide JSON](/fr/guides/clickhouse/data-formats/json/intro) ainsi que l&#39;article [« How we built a new powerful JSON data type for ClickHouse »](https://clickhouse.com/blog/a-new-powerful-json-data-type-for-clickhouse).
