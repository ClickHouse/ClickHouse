<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Rétroporté dans [#74316](https://github.com/ClickHouse/ClickHouse/issues/74316) : lorsque `min_age_to_force_merge_seconds` et `min_age_to_force_merge_on_partition_only` sont tous deux activés, la fusion des parties de données ignorera la limite maximale en octets. [#73656](https://github.com/ClickHouse/ClickHouse/pull/73656) ([Kai Zhu](https://github.com/nauu)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#74222](https://github.com/ClickHouse/ClickHouse/issues/74222) : évite une pause après `ALTER TABLE REPLACE/MOVE PARTITION FROM/TO TABLE`. Récupère les paramètres corrects pour la planification des tâches en arrière-plan. [#72024](https://github.com/ClickHouse/ClickHouse/pull/72024) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#73889](https://github.com/ClickHouse/ClickHouse/issues/73889) : correction de la préparation au squash pour les colonnes Dynamic et JSON. Auparavant, dans certains cas, de nouveaux types pouvaient être insérés dans le variant partagé/les données partagées même lorsque la limite du nombre de types/chemins n’était pas atteinte. [#73388](https://github.com/ClickHouse/ClickHouse/pull/73388) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#74435](https://github.com/ClickHouse/ClickHouse/issues/74435) : corrige un segfault lorsque la source du dictionnaire contient une fonction avec des données incorrectes. [#73535](https://github.com/ClickHouse/ClickHouse/pull/73535) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#74139](https://github.com/ClickHouse/ClickHouse/issues/74139) : correction d’une incohérence possible des données dans une colonne Dynamic. Corrige également l’erreur logique possible `Nested columns sizes are inconsistent with local_discriminators column size`. [#73644](https://github.com/ClickHouse/ClickHouse/pull/73644) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#74527](https://github.com/ClickHouse/ClickHouse/issues/74527) : correction de `NOT_FOUND_COLUMN_IN_BLOCK` dans les requêtes avec `FINAL` et `SAMPLE`. Correction d’un résultat incorrect dans les requêtes SELECT avec `FINAL` sur `CollapsingMergeTree` et activation des optimisations de `FINAL`. [#73682](https://github.com/ClickHouse/ClickHouse/pull/73682) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#74138](https://github.com/ClickHouse/ClickHouse/issues/74138) : correction de la désérialisation de la structure Dynamic/Object. Cela pouvait entraîner des exceptions `CANNOT_READ_ALL_DATA`. [#73767](https://github.com/ClickHouse/ClickHouse/pull/73767) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#74111](https://github.com/ClickHouse/ClickHouse/issues/74111) : corrige [#72078](https://github.com/ClickHouse/ClickHouse/issues/72078) (la prise en charge de S3 Express était cassée). [#73777](https://github.com/ClickHouse/ClickHouse/pull/73777) ([Sameer Tamsekar](https://github.com/stamsekar)).
* Rétroporté dans [#74104](https://github.com/ClickHouse/ClickHouse/issues/74104) : un disque utilisant les métadonnées plain&#95;rewritable peut être partagé entre plusieurs instances de serveur. Il est normal qu’une instance lise un objet de métadonnées pendant qu’une autre le modifie. Les erreurs « objet introuvable » sont ignorées lors de l’initialisation de plain&#95;rewritable avec le stockage Azure, comme c’est déjà le cas pour S3. [#74059](https://github.com/ClickHouse/ClickHouse/pull/74059) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#74152](https://github.com/ClickHouse/ClickHouse/issues/74152) : corrige le cas où l’utilisateur spécifie des arguments nommés dans le moteur de table Kafka. [#74064](https://github.com/ClickHouse/ClickHouse/pull/74064) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#74173](https://github.com/ClickHouse/ClickHouse/issues/74173) : corrige un crash lors de la lecture d’une sous-colonne depuis une table compressée utilisant le moteur Memory. Corrige [#74009](https://github.com/ClickHouse/ClickHouse/issues/74009). [#74161](https://github.com/ClickHouse/ClickHouse/pull/74161) ([Nikita Taranov](https://github.com/nickitat)).
