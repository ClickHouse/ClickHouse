<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Rétroporté dans [#71359](https://github.com/ClickHouse/ClickHouse/issues/71359) : corrige une erreur possible `No such file or directory` due à des symboles spéciaux non échappés dans les fichiers des sous-colonnes JSON. [#71182](https://github.com/ClickHouse/ClickHouse/pull/71182) ([Pavel Kruglov](https://github.com/Avogar)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#70680](https://github.com/ClickHouse/ClickHouse/issues/70680) : ne pas effectuer de validation lors de la synchronisation de `user_directories` depuis Keeper. [#70644](https://github.com/ClickHouse/ClickHouse/pull/70644) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#71395](https://github.com/ClickHouse/ClickHouse/issues/71395) : ne pas appeler l&#39;API de stockage objet lors du listage des répertoires, car cela peut engendrer des coûts inutiles. À la place, stocker la liste des noms de fichiers en mémoire. Le compromis est un temps de chargement initial plus long et davantage de mémoire nécessaire pour stocker les noms de fichiers. [#70823](https://github.com/ClickHouse/ClickHouse/pull/70823) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#71287](https://github.com/ClickHouse/ClickHouse/issues/71287) : réduire le nombre de requêtes API HEAD vers le stockage objet sur le disque plain&#95;rewritable. [#70915](https://github.com/ClickHouse/ClickHouse/pull/70915) ([Julia Kartseva](https://github.com/jkartseva)).

  #### Correction de bogue (comportement incorrect observable par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#70934](https://github.com/ClickHouse/ClickHouse/issues/70934) : correction d’une optimisation incorrecte de la clause JOIN ON dans le cas d’une vérification `IS NULL` imbriquée dans une autre fonction (comme `NOT`), pouvant entraîner des résultats erronés. Clôt [#67915](https://github.com/ClickHouse/ClickHouse/issues/67915). [#68049](https://github.com/ClickHouse/ClickHouse/pull/68049) ([Vladimir Cherkasov](https://github.com/vdimir)).

Cela corrige [#68618](https://github.com/ClickHouse/ClickHouse/issues/68618). [#68848](https://github.com/ClickHouse/ClickHouse/pull/68848) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#71138](https://github.com/ClickHouse/ClickHouse/issues/71138) : correction de la propagation de l’argument de structure dans s3Cluster. Auparavant, l’expression `DEFAULT` de la colonne pouvait être perdue lors de l’envoi de la query aux répliques dans s3Cluster. [#69147](https://github.com/ClickHouse/ClickHouse/pull/69147) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#70561](https://github.com/ClickHouse/ClickHouse/issues/70561) : correction de `getSubcolumn` avec des colonnes `LowCardinality` en surchargeant `useDefaultImplementationForLowCardinalityColumns` pour renvoyer `true`. [#69831](https://github.com/ClickHouse/ClickHouse/pull/69831) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#70903](https://github.com/ClickHouse/ClickHouse/issues/70903) : évite la réutilisation de colonnes entre différents named tuples lors de l’évaluation des fonctions `tuple`. Cela corrige [#70022](https://github.com/ClickHouse/ClickHouse/issues/70022). [#70103](https://github.com/ClickHouse/ClickHouse/pull/70103) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#70623](https://github.com/ClickHouse/ClickHouse/issues/70623) : correction d’un segfault du server lors de la création d’une vue matérialisée avec deux SELECT et un `INTERSECT`, par ex. `CREATE MATERIALIZED VIEW v0 AS (SELECT 1) INTERSECT (SELECT 1);`. [#70264](https://github.com/ClickHouse/ClickHouse/pull/70264) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#70688](https://github.com/ClickHouse/ClickHouse/issues/70688) : correction d’un possible use-after-free dans `SYSTEM DROP FORMAT SCHEMA CACHE FOR Protobuf`. [#70358](https://github.com/ClickHouse/ClickHouse/pull/70358) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#70494](https://github.com/ClickHouse/ClickHouse/issues/70494) : correction d’un crash lors d’un GROUP BY sur une subcolumn de sous-objet JSON. [#70374](https://github.com/ClickHouse/ClickHouse/pull/70374) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#70482](https://github.com/ClickHouse/ClickHouse/issues/70482) : ne pas prefetch les parts pour les vertical merges si une part ne contient aucune row. [#70452](https://github.com/ClickHouse/ClickHouse/pull/70452) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#70556](https://github.com/ClickHouse/ClickHouse/issues/70556) : correction d’un crash dans WHERE avec des fonctions lambda. [#70464](https://github.com/ClickHouse/ClickHouse/pull/70464) ([Raúl Marín](https://github.com/Algunenano)).

Ferme [#62644](https://github.com/ClickHouse/ClickHouse/issues/62644). [#70530](https://github.com/ClickHouse/ClickHouse/pull/70530) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#71052](https://github.com/ClickHouse/ClickHouse/issues/71052) : ignorer frozen&#95;metadata.txt lors du parcours du répertoire shadow depuis system.remote&#95;data&#95;paths. [#70590](https://github.com/ClickHouse/ClickHouse/pull/70590) ([Aleksei Filatov](https://github.com/aalexfvk)).

* Rétroporté dans [#70757](https://github.com/ClickHouse/ClickHouse/issues/70757) : corrige de rares plantages dans les requêtes `SELECT` et les fusions après l&#39;ajout d&#39;une colonne de type `Array` avec une expression par défaut non vide.
