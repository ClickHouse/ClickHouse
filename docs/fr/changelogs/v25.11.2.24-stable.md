<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#90983](https://github.com/ClickHouse/ClickHouse/issues/90983) : en raison de [https://github.com/ClickHouse/ClickHouse/pull/90311](https://github.com/ClickHouse/ClickHouse/pull/90311), le format des statistiques a changé, et le serveur plantera si des statistiques utilisent encore l’ancien format. Cette PR corrige le plantage et lève une exception lorsque les statistiques existantes utilisent l’ancien format. Pour éviter cette exception, exécutez `ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL` afin de régénérer les statistiques&#96; et de corriger le problème. [#90904](https://github.com/ClickHouse/ClickHouse/pull/90904) ([Han Fei](https://github.com/hanfei1991)).
* Rétroporté dans [#91193](https://github.com/ClickHouse/ClickHouse/issues/91193) : désormais, l’exception `HTTP_CONNECTION_LIMIT_REACHED` est levée lorsque la `hard_limit` des connexions des clients HTTP est atteinte. Elle est définie à `20000` pour les connexions disk. [#91016](https://github.com/ClickHouse/ClickHouse/pull/91016) ([Sema Checherinda](https://github.com/CheSema)).
* Rétroporté dans [#91254](https://github.com/ClickHouse/ClickHouse/issues/91254) : correction d’un risque potentiel de starvation du thread pool lors de la lecture d’échantillons de colonnes pour des colonnes JSON comportant de nombreuses sous-colonnes, en respectant le paramètre `merge_tree_use_prefixes_deserialization_thread_pool` au lieu d’utiliser systématiquement le thread pool. [#91208](https://github.com/ClickHouse/ClickHouse/pull/91208) ([Raufs Dunamalijevs](https://github.com/rienath)).
