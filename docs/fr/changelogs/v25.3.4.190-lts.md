<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Rétroporté dans [#79660](https://github.com/ClickHouse/ClickHouse/issues/79660) : introduction d’un seuil (contrôlé par le paramètre `parallel_hash_join_threshold`) permettant de basculer automatiquement vers l’algorithme `hash` lorsque la taille de la table de droite est inférieure à ce seuil. [#76185](https://github.com/ClickHouse/ClickHouse/pull/76185) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#79922](https://github.com/ClickHouse/ClickHouse/issues/79922) : empêche `LogSeriesLimiter` d’effectuer un nettoyage à chaque initialisation, ce qui évite la contention sur les verrous et les régressions de performances dans les scénarios à forte concurrence. [#79864](https://github.com/ClickHouse/ClickHouse/pull/79864) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#81857](https://github.com/ClickHouse/ClickHouse/issues/81857) : évite une mise à jour inutile et réduit la contention sur les verrous dans QueryConditionCache. [#80247](https://github.com/ClickHouse/ClickHouse/pull/80247) ([Jiebin Sun](https://github.com/jiebinn)).
* Rétroporté dans [#81757](https://github.com/ClickHouse/ClickHouse/issues/81757) : correction d’une régression des performances dans le suivi de la mémoire. [#81694](https://github.com/ClickHouse/ClickHouse/pull/81694) ([Michael Kolupaev](https://github.com/al13n321)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#79902](https://github.com/ClickHouse/ClickHouse/issues/79902) : ajout du paramètre `access_control_improvements.enable_user_name_access_type`. Ce paramètre permet d’activer ou de désactiver des grants précis pour les utilisateurs/rôles, introduits dans [https://github.com/ClickHouse/ClickHouse/pull/72246](https://github.com/ClickHouse/ClickHouse/pull/72246). Il peut être préférable de désactiver ce paramètre si vous avez un cluster avec des répliques antérieures à 25.1. [#79842](https://github.com/ClickHouse/ClickHouse/pull/79842) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#79932](https://github.com/ClickHouse/ClickHouse/issues/79932) : l’implémentation correcte de la méthode `ASTSelectWithUnionQuery::clone()` prend désormais aussi en compte le champ `is_normalized`. [#79909](https://github.com/ClickHouse/ClickHouse/pull/79909) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#81379](https://github.com/ClickHouse/ClickHouse/issues/81379) : mise à jour de `c-ares` vers `v1.34.5`. [#81159](https://github.com/ClickHouse/ClickHouse/pull/81159) ([Konstantin Bogdanov](https://github.com/thevar1able)).

* Rétroporté dans [#81226](https://github.com/ClickHouse/ClickHouse/issues/81226) : mise à niveau de libarchive vers 3.7.9 pour corriger : CVE-2024-20696 CVE-2025-25724 CVE-2024-48958 CVE-2024-57970 CVE-2025-1632 CVE-2024-48957 CVE-2024-48615. * Rétroporté dans [#81313](https://github.com/ClickHouse/ClickHouse/issues/81313) : MemoryResidentWithoutPageCache fournit la quantité de mémoire physique utilisée par le processus serveur, hors cache de pages en espace utilisateur, en octets. Cela offre une vue plus précise de l’utilisation réelle de la mémoire lorsque le cache de pages en espace utilisateur est utilisé. Lorsque le cache de pages en espace utilisateur est désactivé, cette valeur est égale à MemoryResident. [#81233](https://github.com/ClickHouse/ClickHouse/pull/81233) ([Jayme Bird](https://github.com/jaymebrd)).

Avec un disque lent, cela peut prendre du temps. Il est clairement pertinent de le sortir de la portée du verrou de réservation. [#81371](https://github.com/ClickHouse/ClickHouse/pull/81371) ([Kseniia Sumarokova](https://github.com/kssenii)).
