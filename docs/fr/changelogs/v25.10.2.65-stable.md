<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Rétroporté dans [#89358](https://github.com/ClickHouse/ClickHouse/issues/89358) : interdire la création de plusieurs disques `plain-rewritable` sur le chemin partagé du stockage objet, car cela peut entraîner un comportement indéfini en cas de collision entre différentes transactions du stockage des métadonnées. [#89038](https://github.com/ClickHouse/ClickHouse/pull/89038) ([Mikhail Artemenko](https://github.com/Michicosun)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Rétroporté dans [#89506](https://github.com/ClickHouse/ClickHouse/issues/89506) : les requêtes peuvent désormais tirer parti simultanément de `optimize_read_in_order` et de `query_plan_optimize_lazy_materialization`. Résout [#88767](https://github.com/ClickHouse/ClickHouse/issues/88767). [#88866](https://github.com/ClickHouse/ClickHouse/pull/88866) ([Manuel](https://github.com/raimannma)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#89650](https://github.com/ClickHouse/ClickHouse/issues/89650) : ajout d’un cache pour l’authentification bcrypt. [#87115](https://github.com/ClickHouse/ClickHouse/pull/87115) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#89425](https://github.com/ClickHouse/ClickHouse/issues/89425) : les sous-requêtes figurant dans des expressions IN lors de requêtes sur une table Iceberg seront correctement précalculées avant l’analyse du partition pruning. [#89177](https://github.com/ClickHouse/ClickHouse/pull/89177) ([Daniil Ivanik](https://github.com/divanik)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#89578](https://github.com/ClickHouse/ClickHouse/issues/89578) : correction de la lecture d’un Array mixte de Float et de Bool dans JSON. Auparavant, l’insertion de telles données entraînait une exception. [#88008](https://github.com/ClickHouse/ClickHouse/pull/88008) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#89508](https://github.com/ClickHouse/ClickHouse/issues/89508) : correction d’une erreur logique dans le réordonnancement des CROSS JOIN lorsque query&#95;plan&#95;optimize&#95;join&#95;order&#95;limit &gt; 1. Clôture de [#89409](https://github.com/ClickHouse/ClickHouse/issues/89409). [#88286](https://github.com/ClickHouse/ClickHouse/pull/88286) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#89673](https://github.com/ClickHouse/ClickHouse/issues/89673) : correction de [#88426](https://github.com/ClickHouse/ClickHouse/issues/88426) : 1. Interdiction des définitions explicites de colonnes dans Alias, les colonnes étant désormais chargées automatiquement depuis la table cible. Cela garantit que l’alias correspond toujours au schéma de la table cible. 2. Exposition par proxy d’un plus grand nombre de méthodes depuis IStorage. [#88552](https://github.com/ClickHouse/ClickHouse/pull/88552) ([Kai Zhu](https://github.com/nauu)).
* Rétroporté dans [#89446](https://github.com/ClickHouse/ClickHouse/issues/89446) : correction du possible &quot;Context has expired&quot; avec le nouvel analyseur et les sous-requêtes. [#88694](https://github.com/ClickHouse/ClickHouse/pull/88694) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#89466](https://github.com/ClickHouse/ClickHouse/issues/89466) : correction de la propagation des restrictions de taille par les paramètres max&#95;table&#95;size&#95;to&#95;drop et max&#95;partition&#95;size&#95;to&#95;drop lors du DROP des tables internes. [#88812](https://github.com/ClickHouse/ClickHouse/pull/88812) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#89716](https://github.com/ClickHouse/ClickHouse/issues/89716) : correction du protocole icebergS3Cluster. Prise en charge de la schema evolution, des suppressions positionnelles et des suppressions par égalité dans la fonction de cluster iceberg. Résout [#88287](https://github.com/ClickHouse/ClickHouse/issues/88287). [#88919](https://github.com/ClickHouse/ClickHouse/pull/88919) ([Yang Jiang](https://github.com/Ted-Jiang)).
* Rétroporté dans [#89438](https://github.com/ClickHouse/ClickHouse/issues/89438) : correction de LOGICAL&#95;ERROR dans L2DistanceTransposed(vec1, vec2, p), où l’optimisation de lecture partielle de QBit supprimait à tort Nullable du type de retour lorsque p était LowCardinality(Nullable(T)). Résout [#88362](https://github.com/ClickHouse/ClickHouse/issues/88362). [#89397](https://github.com/ClickHouse/ClickHouse/pull/89397) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Rétroporté dans [#89449](https://github.com/ClickHouse/ClickHouse/issues/89449) : correction du chargement des tables avec une sérialisation sparse incorrecte pour le tuple lui-même (écrite par d’anciennes versions de ClickHouse). * Rétroporté dans [#89487](https://github.com/ClickHouse/ClickHouse/issues/89487) : correction de la gestion incorrecte, lors du merge, des parts vidées par TTL avec des projections non vides lors de l’utilisation de `deduplicate_merge_projection_mode='ignore'`. Résout [#89391](https://github.com/ClickHouse/ClickHouse/issues/89391). [#89512](https://github.com/ClickHouse/ClickHouse/pull/89512) ([Vladimir Cherkasov](https://github.com/vdimir)).

* Rétroporté dans [#89688](https://github.com/ClickHouse/ClickHouse/issues/89688) : corrige un crash dans le cas où l&#39;état d&#39;une fonction d&#39;agrégation contient une valeur sérialisée d&#39;une colonne LowCardinality(String).
