  #### Amélioration des performances

* Rétroporté dans [#83343](https://github.com/ClickHouse/ClickHouse/issues/83343) : tentative d’accélération de QueryTreeHash. [#82617](https://github.com/ClickHouse/ClickHouse/pull/82617) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#83207](https://github.com/ClickHouse/ClickHouse/issues/83207) : autoriser ALTER UPDATE sur les colonnes JSON et Dynamic. [#82419](https://github.com/ClickHouse/ClickHouse/pull/82419) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#83015](https://github.com/ClickHouse/ClickHouse/issues/83015) : amélioration de Keeper : déplacer les fichiers de changelog entre disques dans un thread en arrière-plan. Auparavant, déplacer le changelog vers un autre disque bloquait Keeper dans son ensemble jusqu’à la fin du déplacement. Cela entraînait une dégradation des performances lorsque le déplacement était une opération longue (par exemple vers un disque S3). [#82485](https://github.com/ClickHouse/ClickHouse/pull/82485) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#83205](https://github.com/ClickHouse/ClickHouse/issues/83205) : `SYSTEM RESTART REPLICA` peut échouer en raison de problèmes de connexion à ZooKeeper. Pour éviter que cette table ne soit oubliée, nous réessayons désormais jusqu’à ce qu’elle soit créée. [#82616](https://github.com/ClickHouse/ClickHouse/pull/82616) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#83270](https://github.com/ClickHouse/ClickHouse/issues/83270) : corriger la mauvaise valeur par défaut de l’option `--reconnect` dans `clickhouse-benchmark`. Elle avait été modifiée par erreur dans [#79465](https://github.com/ClickHouse/ClickHouse/issues/79465). [#82677](https://github.com/ClickHouse/ClickHouse/pull/82677) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#82928](https://github.com/ClickHouse/ClickHouse/issues/82928) : amélioration de Keeper : prise en charge de permissions spécifiques pour l’ACL world:anyone. [#82755](https://github.com/ClickHouse/ClickHouse/pull/82755) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#83146](https://github.com/ClickHouse/ClickHouse/issues/83146) : ajout des colonnes `commit_time`, `commit_id` à `system.s3queue_log`. [#83016](https://github.com/ClickHouse/ClickHouse/pull/83016) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#83184](https://github.com/ClickHouse/ClickHouse/issues/83184) : regrouper les avertissements relatifs aux paramètres inconnus dans clickhouse client et les consigner sous forme de résumé. [#83042](https://github.com/ClickHouse/ClickHouse/pull/83042) ([Bharat Nallan](https://github.com/bharatnc)).
* Rétroporté dans [#83281](https://github.com/ClickHouse/ClickHouse/issues/83281) : il y avait une vérification incorrecte des dépendances pour INSERT avec des MV comportant des requêtes SELECT mal formées, et l’utilisateur pouvait recevoir une `std::exception` peu explicite au lieu d’une erreur significative accompagnée d’une explication claire. C’est désormais corrigé. Ceci corrige : [#82889](https://github.com/ClickHouse/ClickHouse/issues/82889). [#83190](https://github.com/ClickHouse/ClickHouse/pull/83190) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#82781](https://github.com/ClickHouse/ClickHouse/issues/82781) : correction de l’analyse du filtre lorsque seule une colonne d’alias constante est utilisée dans la requête. Corrige [#79448](https://github.com/ClickHouse/ClickHouse/issues/79448). [#82037](https://github.com/ClickHouse/ClickHouse/pull/82037) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#83148](https://github.com/ClickHouse/ClickHouse/issues/83148) : correction de `DatabaseReplicated::getClusterImpl`. Si le premier élément (ou les premiers éléments) de `hosts` a `id == DROPPED_MARK` et qu’il n’existe aucun autre élément pour le même shard, le premier élément de `shards` sera un vecteur vide, ce qui provoque `std::out_of_range`. [#82093](https://github.com/ClickHouse/ClickHouse/pull/82093) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#83211](https://github.com/ClickHouse/ClickHouse/issues/83211) : correction d’une dégradation des performances dans SummingMergeTree introduite en 25.5 dans [https://github.com/ClickHouse/ClickHouse/pull/79051](https://github.com/ClickHouse/ClickHouse/pull/79051). [#82130](https://github.com/ClickHouse/ClickHouse/pull/82130) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#83217](https://github.com/ClickHouse/ClickHouse/issues/83217) : correction de &quot;Context has expired&quot; pour Iceberg. [#82146](https://github.com/ClickHouse/ClickHouse/pull/82146) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#82946](https://github.com/ClickHouse/ClickHouse/issues/82946) : correction des data races dans le client (en n’utilisant pas de contexte global) et des surcharges de `session_timezone` (auparavant, lorsque `session_timezone` était défini, par exemple dans `users.xml`/les options du client, sur une valeur non vide, et sur une valeur vide dans le contexte de requête, la valeur de `users.xml` était utilisée, alors que c’était incorrect ; désormais, le contexte de requête aura toujours priorité sur le contexte global). [#82444](https://github.com/ClickHouse/ClickHouse/pull/82444) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#82758](https://github.com/ClickHouse/ClickHouse/issues/82758) : correction de cas où l’analyse de `Time` pouvait entraîner des problèmes avec msan. Corrige : [#82477](https://github.com/ClickHouse/ClickHouse/issues/82477). [#82514](https://github.com/ClickHouse/ClickHouse/pull/82514) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#82739](https://github.com/ClickHouse/ClickHouse/issues/82739) : l’implémentation du paramètre `use_skip_indexes_if_final_exact_mode` (introduite en 25.6) pouvait ne pas sélectionner de plage candidate pertinente selon les paramètres du moteur `MergeTree` et la distribution des données. Ce problème est désormais résolu. [#82667](https://github.com/ClickHouse/ClickHouse/pull/82667) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Rétroporté dans [#82737](https://github.com/ClickHouse/ClickHouse/issues/82737) : les fonctions `trim{Left,Right,Both}` prennent désormais en charge les chaînes d’entrée de type &quot;FixedString(N)&quot;. Par exemple, `SELECT trimBoth(toFixedString('abc', 3), 'ac')` fonctionne maintenant. [#82691](https://github.com/ClickHouse/ClickHouse/pull/82691) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#82915](https://github.com/ClickHouse/ClickHouse/issues/82915) : dans AzureBlobStorage, pour la copie native, nous comparons les méthodes d’authentification ; si une exception se produit pendant cette comparaison, le code a été mis à jour pour revenir à la lecture et à la copie (c.-à-d. une copie non native). [#82693](https://github.com/ClickHouse/ClickHouse/pull/82693) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Rétroporté dans [#82802](https://github.com/ClickHouse/ClickHouse/issues/82802) : correction de la désérialisation de `groupArraySample`/`groupArrayLast` en cas d’éléments vides (la désérialisation pouvait ignorer une partie du binaire si l’entrée était vide, ce qui peut entraîner une corruption lors de la lecture des données et l’erreur UNKNOWN&#95;PACKET&#95;FROM&#95;SERVER dans le protocole TCP). Cela n’affecte ni les nombres ni les types date/heure. [#82763](https://github.com/ClickHouse/ClickHouse/pull/82763) ([Pedro Ferreira](https://github.com/PedroTadim)).
* Rétroporté dans [#83572](https://github.com/ClickHouse/ClickHouse/issues/83572) : correction de la sauvegarde d’une table `Memory` vide, qui faisait échouer la restauration de la sauvegarde avec l’erreur `BACKUP_ENTRY_NOT_FOUND`. [#82791](https://github.com/ClickHouse/ClickHouse/pull/82791) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#83114](https://github.com/ClickHouse/ClickHouse/issues/83114) : correction de la sûreté en cas d’exception dans la réécriture union/intersect/except&#95;default&#95;mode.
