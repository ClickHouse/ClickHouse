  ### Release ClickHouse v25.11.7.41-stable (d635abf3eae) FIXME par rapport à v25.11.6.11-stable (90415175004)

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#94476](https://github.com/ClickHouse/ClickHouse/issues/94476) : introduction du paramètre de sauvegarde `backup_data_from_refreshable_materialized_view_targets` pour déterminer si les données des vues matérialisées actualisables doivent être sauvegardées. Les cibles des RMV avec la stratégie d’actualisation APPEND sont toujours sauvegardées. [#93658](https://github.com/ClickHouse/ClickHouse/pull/93658) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#94119](https://github.com/ClickHouse/ClickHouse/issues/94119) : dans certains cas, nous avons constaté que ClickHouse ne respectait pas la limite de mémoire lors de la lecture d’une table. Ce comportement a été corrigé. [#93715](https://github.com/ClickHouse/ClickHouse/pull/93715) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

Résout [#81261](https://github.com/ClickHouse/ClickHouse/issues/81261), [#82058](https://github.com/ClickHouse/ClickHouse/issues/82058), [#88169](https://github.com/ClickHouse/ClickHouse/issues/88169). [#87205](https://github.com/ClickHouse/ClickHouse/pull/87205) ([Pavel Kruglov](https://github.com/Avogar)).

* Rétroporté dans [#94622](https://github.com/ClickHouse/ClickHouse/issues/94622) : corrige une possible erreur logique lors de la réception d’une autre requête de lecture provenant d’une réplique après l’envoi d’une réponse avec l’indicateur `finish=true`. Cela était possible en raison d’une condition de concurrence logique dans `MergeTreeReadPoolParallelReplicas`, même si la probabilité que cela se produise était très faible. [#90921](https://github.com/ClickHouse/ClickHouse/pull/90921) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#93723](https://github.com/ClickHouse/ClickHouse/issues/93723) : corrige la résolution des sous-colonnes dynamiques dans les alias de colonne de l’analyseur. Auparavant, une sous-colonne dynamique dans un alias de colonne était encapsulée dans `getSubcolumn` et, dans certains cas, pouvait ne pas être résolue du tout. Clôt [#91434](https://github.com/ClickHouse/ClickHouse/issues/91434). [#92583](https://github.com/ClickHouse/ClickHouse/pull/92583) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#93594](https://github.com/ClickHouse/ClickHouse/issues/93594) : corrige un blocage possible lors de l’arrêt du pool de planification en arrière-plan (ce qui peut entraîner des blocages du serveur à l’arrêt).
