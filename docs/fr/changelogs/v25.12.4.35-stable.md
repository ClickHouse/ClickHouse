<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#94210](https://github.com/ClickHouse/ClickHouse/issues/94210) : refonte du paramètre `insert_select_deduplicate` afin de permettre de préserver la compatibilité descendante. [#92951](https://github.com/ClickHouse/ClickHouse/pull/92951) ([Sema Checherinda](https://github.com/CheSema)).
* Rétroporté dans [#94383](https://github.com/ClickHouse/ClickHouse/issues/94383) : introduction du paramètre de sauvegarde `backup_data_from_refreshable_materialized_view_targets` pour contrôler si les données des vues matérialisées actualisables doivent être sauvegardées. Les cibles des RMV avec la stratégie d&#39;actualisation APPEND sont toujours sauvegardées. [#93658](https://github.com/ClickHouse/ClickHouse/pull/93658) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#94121](https://github.com/ClickHouse/ClickHouse/issues/94121) : dans certains cas, nous avons constaté que ClickHouse ne respectait pas la limite de mémoire lors de la lecture d’une table. Ce comportement a été corrigé. [#93715](https://github.com/ClickHouse/ClickHouse/pull/93715) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#94031](https://github.com/ClickHouse/ClickHouse/issues/94031) : correction du calcul de la taille en octets de la requête `check` avec statistiques. [#93907](https://github.com/ClickHouse/ClickHouse/pull/93907) ([Mikhail Artemenko](https://github.com/Michicosun)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement perceptible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#94128](https://github.com/ClickHouse/ClickHouse/issues/94128) : corrige `Not found column` pour l’optimisation `use_top_k_dynamic_filtering`. Corrige [#93186](https://github.com/ClickHouse/ClickHouse/issues/93186). [#93316](https://github.com/ClickHouse/ClickHouse/pull/93316) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#94067](https://github.com/ClickHouse/ClickHouse/issues/94067) : évite la connexion OAuth dans ClickHouse Client lorsque le nom d’utilisateur/mot de passe figure dans la chaîne de connexion. [#93459](https://github.com/ClickHouse/ClickHouse/pull/93459) ([Krishna Mannem](https://github.com/kcmannem)).
* Rétroporté dans [#94023](https://github.com/ClickHouse/ClickHouse/issues/94023) : corrige un bogue dans le mécanisme de dispatch de l’instrument système. [#93937](https://github.com/ClickHouse/ClickHouse/pull/93937) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#94084](https://github.com/ClickHouse/ClickHouse/issues/94084) : dans [https://github.com/ClickHouse/ClickHouse/pull/89173](https://github.com/ClickHouse/ClickHouse/pull/89173), nous avons ajouté un champ supplémentaire à la structure que `TraceSender` envoie via un pipe interne. Cependant, la taille du buffer n’a pas été mise à jour ([ici](https://github.com/ClickHouse/ClickHouse/pull/89173/changes#diff-36ecfac5cde34c92c031652d8a77f0d12782cd5d43e68d6ef159e6d46a54224fL44)) ; nous écrivons donc plus de données dans le buffer que `buffer_size`, ce qui provoque plusieurs flushes. Et comme `TraceSender::send` est appelé depuis différents threads, les flushes de ces threads peuvent s’entrelacer, ce qui rompt l’invariant sur lequel s’appuie l’extrémité réceptrice (`TraceCollector`). [#93966](https://github.com/ClickHouse/ClickHouse/pull/93966) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#94594](https://github.com/ClickHouse/ClickHouse/issues/94594) : corrige la conversion de type vers un supertype lors de l’opération de jointure du moteur de stockage `Join` avec la clause `USING`. Corrige [#91672](https://github.com/ClickHouse/ClickHouse/issues/91672). Corrige [#78572](https://github.com/ClickHouse/ClickHouse/issues/78572). [#94000](https://github.com/ClickHouse/ClickHouse/pull/94000) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#94074](https://github.com/ClickHouse/ClickHouse/issues/94074) : une requête `SELECT` contenant un prédicat sur plusieurs colonnes avec des skip indexes de type bloom filter, en présence à la fois de conditions `OR` et `NOT`, pouvait renvoyer des résultats incohérents. C’est désormais corrigé. [#94026](https://github.com/ClickHouse/ClickHouse/pull/94026) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Rétroporté dans [#94456](https://github.com/ClickHouse/ClickHouse/issues/94456) : corrige l’utilisation d’une valeur non initialisée dans `ReadWriteBufferFromHTTP`. [#94058](https://github.com/ClickHouse/ClickHouse/pull/94058) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#94245](https://github.com/ClickHouse/ClickHouse/issues/94245) : corrige une mauvaise vérification des chemins typés dans JSON. Cette vérification a été introduite dans [https://github.com/ClickHouse/ClickHouse/pull/92842](https://github.com/ClickHouse/ClickHouse/pull/92842) et peut entraîner une erreur au démarrage des tables existantes. [#94070](https://github.com/ClickHouse/ClickHouse/pull/94070) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#94206](https://github.com/ClickHouse/ClickHouse/issues/94206) : corrige la précision de `uniqTheta` lors de l’utilisation, en parallèle, de clés d’agrégation UInt8 (`max_threads` &gt; 1 - par défaut). [#94095](https://github.com/ClickHouse/ClickHouse/pull/94095) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#94167](https://github.com/ClickHouse/ClickHouse/issues/94167) : corrige [https://github.com/ClickHouse/clickhouse-core-incidents/issues/1217](https://github.com/ClickHouse/clickhouse-core-incidents/issues/1217). Une exception a été levée lors d’un appel à `socket.setBlocking(true)` dans `SCOPE_EXIT` : [logs](https://grafana.clickhouse-prd.com/a/loghouseapp/sysex?thanos_datasource=LightHouse+Thanos+%28production%29\&environment=production\&sortOrder=Asc\&namespace=ns-olive-ae-66\&region=us-central1\&limit=500\&whereExtra=and+level+%3D+%27Fatal%27\&tableName=text_log\&groupBy=level\&extraCols=level\&timeFrom=2025-12-29T01%3A13%3A46Z\&timeFromCHFormat=2025-12-29+01%3A13%3A46\&timeFromUnix=1766970826\&timeTo=2025-12-29T02%3A13%3A51Z\&timeToCHFormat=2025-12-29+02%3A13%3A51\&timeToUnix=1766974431\&dateTo=2025-12-29\&dateFrom=2025-12-29). Comme `SCOPE_EXIT` crée un objet de garde de portée et exécute le code fourni dans son destructeur, nous ne pouvons pas utiliser `SCOPE_EXIT` avec des fonctions qui lèvent des exceptions et devons utiliser `SCOPE_EXIT_SAFE` à la place. [#94100](https://github.com/ClickHouse/ClickHouse/pull/94100) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
