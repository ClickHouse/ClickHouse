<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement perceptible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#101224](https://github.com/ClickHouse/ClickHouse/issues/101224) : correction des requêtes d&#39;insertions asynchrones qui signalaient `written_rows`, `read_rows` et `result_rows` à zéro dans `query_log` et dans la sortie du client. [#99879](https://github.com/ClickHouse/ClickHouse/pull/99879) ([Sema Checherinda](https://github.com/CheSema)).
* Rétroporté dans [#100891](https://github.com/ClickHouse/ClickHouse/issues/100891) : validation des chemins des entrées de fichier dans les métadonnées de sauvegarde afin de rejeter les traversées de chemin, les chemins absolus et les noms vides pendant `RESTORE`. [#100483](https://github.com/ClickHouse/ClickHouse/pull/100483) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#101394](https://github.com/ClickHouse/ClickHouse/issues/101394) : correction de la prise en compte de `session_timezone`, qui était ignoré lors de l&#39;analyse des valeurs `DateTime` pendant les insertions asynchrones (TCP) et toutes les insertions via HTTP. [#100647](https://github.com/ClickHouse/ClickHouse/pull/100647) ([Sema Checherinda](https://github.com/CheSema)).
* Rétroporté dans [#100922](https://github.com/ClickHouse/ClickHouse/issues/100922) : correction d&#39;un crash du serveur lors de l&#39;utilisation de la fonction `has()` avec PREWHERE/WHERE sur une clé Tuple contenant des éléments LowCardinality. [#100760](https://github.com/ClickHouse/ClickHouse/pull/100760) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#101187](https://github.com/ClickHouse/ClickHouse/issues/101187) : correction d&#39;un `segfault` dû au déréférencement d&#39;un pointeur nul lors du chargement des dictionnaires pendant l&#39;arrêt du serveur. `Context::getUserDefinedSQLObjectsStorage` (qui déréférence `user_defined_sql_objects_storage`) est appelé par les threads des dictionnaires en concurrence avec le thread principal, qui appelle `Context::shutdown` (et définit `user_defined_sql_objects_storage` à null). Il faut s&#39;assurer de désactiver les futures mises à jour dans le chargeur de dictionnaires, d&#39;arrêter les requêtes de dictionnaire en cours d&#39;exécution et d&#39;attendre la fin des threads de chargement des dictionnaires, le tout avant d&#39;exécuter `Context::shutdown`. Comme pour les requêtes ordinaires. [#100839](https://github.com/ClickHouse/ClickHouse/pull/100839) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#101091](https://github.com/ClickHouse/ClickHouse/issues/101091) : correction d&#39;un dépassement de tampon dans `ULIDStringToDateTime` lorsque l&#39;entrée contient des octets non ASCII. [#100843](https://github.com/ClickHouse/ClickHouse/pull/100843) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#101015](https://github.com/ClickHouse/ClickHouse/issues/101015) : correction d&#39;une exception dans `intDiv`/`intDivOrZero` sur des Array de Tuple Nullable, par ex. `SELECT intDiv([divide((1, 2), ... AND NULL)], 2)`. [#100895](https://github.com/ClickHouse/ClickHouse/pull/100895) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#101250](https://github.com/ClickHouse/ClickHouse/issues/101250) : évaluation des arguments de moteur pour `StorageAlias` avant le stockage de la définition, afin que des expressions comme `currentDatabase()` soient résolues en littéraux avant d&#39;être enregistrées dans la base de données. [#100902](https://github.com/ClickHouse/ClickHouse/pull/100902) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#101140](https://github.com/ClickHouse/ClickHouse/issues/101140) : correction d&#39;un crash lors de l&#39;utilisation d&#39;un index de recherche textuelle avec une clause `IN` contenant une sous-requête de tuple, par ex. `WHERE (id, str) IN (SELECT (id, str) FROM ...)`, ou lorsque le nombre de colonnes dans la sous-requête ne correspond pas au tuple situé à gauche de `IN`. [#100959](https://github.com/ClickHouse/ClickHouse/pull/100959) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#101080](https://github.com/ClickHouse/ClickHouse/issues/101080) : correction de la fonction d&#39;agrégation `sumCountOrDefault` qui, avec un ou plusieurs arguments `Nullable`, ne pouvait pas lire les anciens états sérialisés après l&#39;introduction de `Nullable(Tuple)`. Clôt [#100882](https://github.com/ClickHouse/ClickHouse/issues/100882). [#101021](https://github.com/ClickHouse/ClickHouse/pull/101021) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#101169](https://github.com/ClickHouse/ClickHouse/issues/101169) : correction d&#39;une exception dans `optimizeLazyMaterialization` lorsqu&#39;une projection avec PREWHERE est utilisée avec `ORDER BY ... LIMIT`. [#101115](https://github.com/ClickHouse/ClickHouse/pull/101115) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#101349](https://github.com/ClickHouse/ClickHouse/issues/101349) : correction d&#39;un cas pouvant entraîner l&#39;erreur logique `Having zero bytes, ...` du cache lorsqu&#39;un objet distant est écrasé entre `list` et `read`, ce qui produisait auparavant des métadonnées d&#39;objet périmées. [#101219](https://github.com/ClickHouse/ClickHouse/pull/101219) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#101373](https://github.com/ClickHouse/ClickHouse/issues/101373) : ... [#101230](https://github.com/ClickHouse/ClickHouse/pull/101230) ([Kseniia Sumarokova](https://github.com/kssenii)).
