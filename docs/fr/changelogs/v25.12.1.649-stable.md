<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* ALTER MODIFY COLUMN exige désormais un DEFAULT explicite lors de la conversion de colonnes Nullable vers des types non NULL. Auparavant, de tels ALTER pouvaient rester bloqués avec des erreurs cannot convert null to not null ; désormais, les NULL sont remplacés par l&#39;expression par défaut de la colonne. Résout [#5985](https://github.com/ClickHouse/ClickHouse/issues/5985). [#84770](https://github.com/ClickHouse/ClickHouse/pull/84770) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Le tokenizer Ngram ne renverra plus de ngrams dont la longueur est inférieure à la longueur N avec laquelle il a été configuré. Search ne renverra aucune ligne lorsque les tokens de recherche sont vides. [#89757](https://github.com/ClickHouse/ClickHouse/pull/89757) ([George Larionov](https://github.com/george-larionov)).
* Lors d&#39;un ALTER COLUMN de `String` vers `Nullable(String)`, aucune mutation ne sera effectuée sur les données. En revanche, pour la fonction d&#39;agrégation `uniq`, une structure de données différente est utilisée : pour une colonne Nullable, `AggregateFunctionNull` est utilisé avec un agrégateur uniq imbriqué. `AggregateFunctionNull` sérialise un booléen supplémentaire. Cela rend le fichier de statistiques incompatible. Le correctif consiste à ajouter un indicateur pour enregistrer s&#39;il s&#39;agit d&#39;une colonne Nullable lors de la sérialisation. Le format des statistiques a changé ; le serveur plantera si des statistiques utilisent l&#39;ancien format. Cette PR [https://github.com/ClickHouse/ClickHouse/pull/90904](https://github.com/ClickHouse/ClickHouse/pull/90904) corrigera le crash et lèvera une exception lorsque les statistiques existantes utilisent l&#39;ancien format. Pour éviter l&#39;exception, exécutez ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL afin de régénérer les statistiques et corriger le problème. [#90311](https://github.com/ClickHouse/ClickHouse/pull/90311) ([Han Fei](https://github.com/hanfei1991)).
* Suppression des settings `allow_not_comparable_types_in_order_by`/`allow_not_comparable_types_in_comparison_functions`. Autoriser des types non comparables dans ORDER BY ou dans des fonctions de comparaison peut entraîner des erreurs logiques et des résultats inattendus. Résout [#90028](https://github.com/ClickHouse/ClickHouse/issues/90028). [#90527](https://github.com/ClickHouse/ClickHouse/pull/90527) ([Pavel Kruglov](https://github.com/Avogar)).
* La valeur par défaut du setting `check_query_single_value_result` a été modifiée de `true` à `false`. Cela amène `CHECK TABLE` à renvoyer des résultats détaillés par part au lieu d&#39;un résultat agrégé (1 = OK, 0 = erreurs trouvées). Par rapport au comportement précédent, cela correspond probablement mieux à ce que l&#39;utilisateur souhaite. [#91009](https://github.com/ClickHouse/ClickHouse/pull/91009) ([Robert Schulze](https://github.com/rschu1ze)).
* Plusieurs corrections autour des indices implicites. Le schéma affiché ou stocké (métadonnées du keeper) n&#39;inclura pas les indices implicites, comme ceux créés par les settings `add_minmax_index_for_numeric_columns` ou `add_minmax_index_for_string_columns`. Cela peut provoquer des erreurs de métadonnées lorsqu&#39;une table ReplicatedMergeTree est créée ou mise à jour dans une version plus récente, alors qu&#39;une réplique exécute une version plus ancienne. Dans ce cas, envoyez les DDL à l&#39;ancienne réplique jusqu&#39;à ce que le cluster soit entièrement mis à niveau. [#91429](https://github.com/ClickHouse/ClickHouse/pull/91429) ([Raúl Marín](https://github.com/Algunenano)).
* Mise à jour de clickhouse-client pour renvoyer un code de sortie non nul (159 - TIMEOUT&#95;EXCEEDED) lorsqu&#39;une requête expire à cause de `receive_timeout`. Auparavant, les dépassements de délai renvoyaient le code de sortie 0 (succès), ce qui compliquait la détection de ces échecs par les scripts et l&#39;automatisation. [#91432](https://github.com/ClickHouse/ClickHouse/pull/91432) ([Sav](https://github.com/sberss)).
* Amélioration de l&#39;organisation du stockage de l&#39;inverted text index pour rendre la lecture depuis l&#39;object storage plus efficace. Amélioration des performances des fusions dans les tables avec des inverted text indexes. Si vous avez utilisé le text index Experimental avant la version 25.12, vous devez supprimer l&#39;index avant la mise à niveau, puis le reconstruire sur la nouvelle version. [#91518](https://github.com/ClickHouse/ClickHouse/pull/91518) ([Anton Popov](https://github.com/CurtizJ)).
* Il est désormais interdit de créer des tables `MergeTree` spéciales (comme `ReplacingMergeTree`, `CollapsingMergeTree`, etc.) avec une clé `ORDER BY` vide, car le comportement de fusion de ces tables est indéfini. Si vous devez malgré tout créer une telle table, activez le paramètre `allow_suspicious_primary_key`. [#91569](https://github.com/ClickHouse/ClickHouse/pull/91569) ([Anton Popov](https://github.com/CurtizJ)).
* Correction des fonctions bitShiftLeft et bitShiftRight afin qu’elles renvoient 0 ou une valeur vide lorsque le décalage est exactement égal à la taille du type. [#91943](https://github.com/ClickHouse/ClickHouse/pull/91943) ([Pablo Marcos](https://github.com/pamarcos)).
* Suite de [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380). Cette PR classe la désactivation des arguments positionnels dans les projections comme un changement non rétrocompatible. De plus, elle introduit le paramètre `enable_positional_arguments_for_projections` pour permettre une mise à niveau sûre d’un cluster ClickHouse lorsque des arguments positionnels sont présents dans les projections. [#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="experimental-feature">
  #### Fonctionnalité expérimentale
</div>

* Une nouvelle logique a été introduite pour exécuter automatiquement les requêtes à l’aide de répliques parallèles, via le paramètre `automatic_parallel_replicas_mode`. Lors d’une exécution ordinaire sur un seul nœud, ClickHouse collecte des statistiques qui seront ensuite prises en compte à l’étape de planification. Si ces statistiques indiquent que les répliques parallèles seront probablement bénéfiques, ClickHouse exécutera automatiquement la requête concernée avec des répliques parallèles. L’ensemble des requêtes prises en charge est actuellement assez limité. [#87541](https://github.com/ClickHouse/ClickHouse/pull/87541) ([Nikita Taranov](https://github.com/nickitat)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Échouer rapidement lorsque les requêtes atteignent leur limite de lignes. Résout [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872). [#62804](https://github.com/ClickHouse/ClickHouse/pull/62804) ([Sean Haynes](https://github.com/seandhaynes)).
* Ajouter une optimisation pour supprimer les colonnes inutilisées dans les plans de requête. Résout [#75152](https://github.com/ClickHouse/ClickHouse/issues/75152). [#76487](https://github.com/ClickHouse/ClickHouse/pull/76487) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Https://github.com/clickhouse/clickhouse/pull/84477 a ajouté des contraintes sur les requêtes select pouvant être utilisées dans les requêtes `insert select from s3cluster()` pour une exécution distribuée parallèle. Ce changement permet d’utiliser where, ce qui était déjà possible auparavant. [#84611](https://github.com/ClickHouse/ClickHouse/pull/84611) ([Igor Nikonov](https://github.com/devcrafter)).
* Précharger les clés pendant l’itération de la table de hachage afin de minimiser les défauts de cache. [#84708](https://github.com/ClickHouse/ClickHouse/pull/84708) ([lgbo](https://github.com/lgbo-ustc)).
* Optimiser AggregateFunctionHistogram en triant uniquement la fin du tableau de points et en évitant le tri pour les entrées monotones, ce qui permet un gain de performances d’environ 10 %. [#85760](https://github.com/ClickHouse/ClickHouse/pull/85760) ([MakarDev](https://github.com/MakarDev)).
* ClickHouse utilise désormais les skip indexes pour effectuer une analyse des index sur des clauses WHERE avec des conditions de filtrage mixtes reliées par `AND` et `OR`. Auparavant, la clause WHERE devait être une conjonction (AND) de conditions de filtrage pour utiliser les skip indexes. Un nouveau réglage `use_skip_indexes_for_disjunctions` (par défaut : activé) contrôle cette fonctionnalité. (issue [#75228](https://github.com/ClickHouse/ClickHouse/issues/75228)). [#87781](https://github.com/ClickHouse/ClickHouse/pull/87781) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Amélioration des performances de filtrage pour les prédicats utilisant des fonctions telles que `like`, `equals`, `has` et d’autres, en s’appuyant sur un filtre préliminaire supplémentaire construit à partir du text index. Cette optimisation est activée via le réglage `query_plan_text_index_add_hint`. Amélioration également de l’utilisation du text index pour les colonnes de type de données `Map`. [#88550](https://github.com/ClickHouse/ClickHouse/pull/88550) ([Anton Popov](https://github.com/CurtizJ)).
* Optimiser les lookups inverses répétés dans les dictionnaires en effectuant des lookups plus rapides dans un ensemble précalculé de valeurs de clé possibles. Ferme [#7968](https://github.com/ClickHouse/ClickHouse/issues/7968). [#88971](https://github.com/ClickHouse/ClickHouse/pull/88971) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Ajout de la prise en charge de la sérialisation sparse pour les colonnes de type Nullable. Cela fait suite à [#44539](https://github.com/ClickHouse/ClickHouse/issues/44539). [#88999](https://github.com/ClickHouse/ClickHouse/pull/88999) ([Amos Bird](https://github.com/amosbird)).
* Prise en charge des Runtime Filters de JOIN pour les JOIN `ANTI`. En outre, refactorisation de l’implémentation des Runtime Filters afin de réduire la contention sur les verrous. [#89710](https://github.com/ClickHouse/ClickHouse/pull/89710) ([Dmitry Novik](https://github.com/novikd)).
* Prise en charge du maintien de la lecture dans l’ordre depuis la table de gauche dans les opérations LEFT/INNER JOIN, ce qui peut être exploité par les étapes suivantes. Peut être désactivé à l’aide du réglage `query_plan_read_in_order_through_join`. Prise en charge également de l’optimisation de lecture avec ligne virtuelle (voir le réglage `read_in_order_use_virtual_row`) pour les LEFT/INNER JOIN. [#89815](https://github.com/ClickHouse/ClickHouse/pull/89815) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Optimiser les requêtes `ORDER BY...LIMIT N` en utilisant un skip index et un filtre à seuil dynamique afin de réduire considérablement le nombre de lignes traitées. [#89835](https://github.com/ClickHouse/ClickHouse/pull/89835) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Améliorer les performances et le comportement de topK. [#90091](https://github.com/ClickHouse/ClickHouse/pull/90091) ([Raúl Marín](https://github.com/Algunenano)).
* Amélioration des performances des opérations de comparaison sur Decimal. Résout [#28192](https://github.com/ClickHouse/ClickHouse/issues/28192). [#90153](https://github.com/ClickHouse/ClickHouse/pull/90153) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Prise en charge du partition pruning pour les fonctions Paimon, dans la continuité de [https://github.com/ClickHouse/ClickHouse/pull/84423](https://github.com/ClickHouse/ClickHouse/pull/84423). [#90253](https://github.com/ClickHouse/ClickHouse/pull/90253) ([JIaQi](https://github.com/JiaQiTang98)).
* Amélioration des performances des colonnes matérialisées à la volée avec une limite plus élevée. [#90309](https://github.com/ClickHouse/ClickHouse/pull/90309) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Les utilisateurs devraient constater une latence réduite lors de l’analyse des index lorsque de gros index `minmax` (des millions de granules) sont présents. [#90428](https://github.com/ClickHouse/ClickHouse/pull/90428) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Utilisation d’opérations SIMD avancées pour les fonctions logiques via dynamic dispatch. [#90432](https://github.com/ClickHouse/ClickHouse/pull/90432) ([Raúl Marín](https://github.com/Algunenano)).
* Amélioration des performances d’exécution des fonctions JIT en évitant d’initialiser inutilement la colonne de résultat à zéro. [#90449](https://github.com/ClickHouse/ClickHouse/pull/90449) ([Raúl Marín](https://github.com/Algunenano)).
* Accélération de la décompression T64 via dynamic dispatch. [#90610](https://github.com/ClickHouse/ClickHouse/pull/90610) ([Raúl Marín](https://github.com/Algunenano)).
* Optimisation du filtrage sur place du reader MergeTree. Résout [#87119](https://github.com/ClickHouse/ClickHouse/issues/87119). [#90630](https://github.com/ClickHouse/ClickHouse/pull/90630) ([Xiaozhe Yu](https://github.com/wudidapaopao)).
* Échec rapide lorsque les queries atteignent les limites de lignes. Résout [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872). [#90767](https://github.com/ClickHouse/ClickHouse/pull/90767) ([Sean Haynes](https://github.com/seandhaynes)).
* Implémentation d’un algorithme simple de réordonnancement des jointures DPsize pour les INNER JOIN. Un nouveau paramètre Experimental contrôle les algorithmes utilisés ainsi que leur ordre ; par exemple, `query_plan_optimize_join_order_algorithm='dpsize,greedy'` signifie que DPsize est essayé en premier, avec fallback vers greedy. [#91002](https://github.com/ClickHouse/ClickHouse/pull/91002) ([Alexander Gololobov](https://github.com/davenger)).
* Introduction d’une heuristique supplémentaire pour réduire la largeur des choix de merge sélectionnés. Effectuer des merges plus étroits augmentera la write amplification, mais peut en même temps aider à éviter les erreurs `TOO_MANY_PARTS`. [#91163](https://github.com/ClickHouse/ClickHouse/pull/91163) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Amélioration des performances des queries sur des tables S3 créées avec un glob pattern en appliquant les valeurs du filtre `_path` au plus tôt, ce qui évite les opérations de listing S3. Contrôlé par le paramètre `s3_path_filter_limit`. [#91165](https://github.com/ClickHouse/ClickHouse/pull/91165) ([Eduard Karacharov](https://github.com/korowa)).
* Accélération de la conversion des colonnes en Bool (dans les clauses WHERE) via dynamic dispatch. [#91203](https://github.com/ClickHouse/ClickHouse/pull/91203) ([Raúl Marín](https://github.com/Algunenano)).
* Accélération du tri d’un unique block numérique via dynamic dispatch. [#91213](https://github.com/ClickHouse/ClickHouse/pull/91213) ([Raúl Marín](https://github.com/Algunenano)).
