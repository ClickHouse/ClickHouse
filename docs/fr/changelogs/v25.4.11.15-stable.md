<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#83633](https://github.com/ClickHouse/ClickHouse/issues/83633) : lorsque `distributed_ddl_output_mode='*_only_active'`, ne pas attendre les nouvelles répliques ou les répliques restaurées dont le retard de réplication dépasse `max_replication_lag_to_enqueue`. Cela devrait aider à éviter `DDL task is not finished on some hosts` lorsqu&#39;une nouvelle réplique devient active après avoir terminé son initialisation ou sa récupération, mais qu&#39;elle a accumulé un volumineux journal de réplication pendant l&#39;initialisation. Implémente également la query `SYSTEM SYNC DATABASE REPLICA STRICT`, qui attend que le journal de réplication repasse sous `max_replication_lag_to_enqueue`. [#83302](https://github.com/ClickHouse/ClickHouse/pull/83302) ([Alexander Tokmakov](https://github.com/tavplubix)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">

</div>

* Rétroporté dans [#83570](https://github.com/ClickHouse/ClickHouse/issues/83570) : corrige un problème de sauvegarde d’une table `Memory` vide, qui faisait échouer la restauration de la sauvegarde avec l’erreur `BACKUP_ENTRY_NOT_FOUND`. [#82791](https://github.com/ClickHouse/ClickHouse/pull/82791) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#83670](https://github.com/ClickHouse/ClickHouse/issues/83670) : corrige un problème de mémoire lié à max&#95;untracked&#95;memory. [#83607](https://github.com/ClickHouse/ClickHouse/pull/83607) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#83661](https://github.com/ClickHouse/ClickHouse/issues/83661) : INSERT SELECT avec UNION ALL pouvait entraîner un déréférencement de pointeur nul dans un cas limite. Clôt [#83618](https://github.com/ClickHouse/ClickHouse/issues/83618). [#83643](https://github.com/ClickHouse/ClickHouse/pull/83643) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
