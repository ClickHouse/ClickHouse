<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement erroné visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#108866](https://github.com/ClickHouse/ClickHouse/issues/108866) : correction d’une interruption du serveur lors de `RESTORE` de sauvegardes contenant des tables avec des dépendances cycliques. [#103824](https://github.com/ClickHouse/ClickHouse/pull/103824) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#108847](https://github.com/ClickHouse/ClickHouse/issues/108847) : les sauvegardes incrémentielles ne stockent plus les informations d’authentification `S3` dans le localisateur `<base_backup>` du fichier de métadonnées `.backup`. Les sauvegardes créées avec `use_same_s3_credentials_for_base_backup = 1`, ou avec des informations d’authentification explicites pour la sauvegarde de base correspondant à ce localisateur, stockent un marqueur non secret et sont restaurées sans paramètres supplémentaires au moment de la restauration ; pour les sauvegardes créées avec des informations d’authentification explicites différentes pour la sauvegarde de base ou des arguments d’authentification de base supplémentaires, transmettez-les à `RESTORE` avec le paramètre `base_backup`. Les sauvegardes créées par des versions plus anciennes avec des informations d’authentification intégrées restent restaurables. [#107357](https://github.com/ClickHouse/ClickHouse/pull/107357) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#107889](https://github.com/ClickHouse/ClickHouse/issues/107889) : correction d’un problème rendant l’interface MySQL inutilisable avec `MySQL Connector/J` 8.2.0 et les versions ultérieures (y compris 9.x). Le champ `info` du paquet `OK` est désormais encodé avec préfixe de longueur, comme sur le serveur MySQL, afin que le pilote JDBC puisse se connecter. [#107693](https://github.com/ClickHouse/ClickHouse/pull/107693) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#108763](https://github.com/ClickHouse/ClickHouse/issues/108763) : correction de l’identification des utilisateurs via `ssl_certificate`, afin qu’un unique joker `*` corresponde exactement à un seul composant de nom (RFC 6125 6.4.3). Auparavant, un joker dans un sujet `CN` ou un SAN `DNS:` (par exemple `*.corp.example.com`) correspondait aussi à des noms à plusieurs labels tels que `evil.deep.corp.example.com`, permettant au détenteur d’un certificat pour un sous-domaine plus profond de s’authentifier en tant qu’utilisateur correspondant au joker. La correspondance des SAN `URI:` reste inchangée. [#108472](https://github.com/ClickHouse/ClickHouse/pull/108472) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#108896](https://github.com/ClickHouse/ClickHouse/issues/108896) : correction d’un crash du serveur (dépassement de pile) provoqué par des expressions fortement imbriquées telles que `[[[ ... ]]]` ou `array(array( ... ))` lorsque `max_parser_depth` est défini sur une valeur élevée. [#108493](https://github.com/ClickHouse/ClickHouse/pull/108493) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#109141](https://github.com/ClickHouse/ClickHouse/issues/109141) : correction d’une erreur de segmentation lors de la fusion d’états d’agrégation `uniqExact` avec `GROUPING SETS`, `ROLLUP` ou `CUBE` et `max_threads > 1`. [#108928](https://github.com/ClickHouse/ClickHouse/pull/108928) ([Raúl Marín](https://github.com/Algunenano)).
