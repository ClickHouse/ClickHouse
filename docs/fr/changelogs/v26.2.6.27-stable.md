  #### Amélioration

* Rétroporté dans [#100070](https://github.com/ClickHouse/ClickHouse/issues/100070) : ajout des ProfileEvents `ObjectStorageListedObjects`, `ObjectStorageGlobFilteredObjects`, `ObjectStoragePredicateFilteredObjects` et `ObjectStorageReadObjects` pour l’introspection du pipeline de listage et de lecture des fichiers dans le stockage d’objets (S3, Azure, etc.). [#99778](https://github.com/ClickHouse/ClickHouse/pull/99778) ([Sema Checherinda](https://github.com/CheSema)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#100460](https://github.com/ClickHouse/ClickHouse/issues/100460) : les identifiants dans les chaînes de connexion JDBC, ODBC et NATS sont désormais masqués dans les journaux de requêtes et dans la sortie de `SHOW CREATE`, afin d’éviter toute divulgation accidentelle d’informations sensibles. Pour les chaînes de connexion au format URI (par ex. {scheme}://{user}:{password}@{host}), seule la partie correspondant au mot de passe est masquée, tandis que le reste demeure visible pour faciliter le débogage. Le paramètre `nats_token` est désormais lui aussi masqué. [#99344](https://github.com/ClickHouse/ClickHouse/pull/99344) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#100082](https://github.com/ClickHouse/ClickHouse/issues/100082) : correction de l’ignorance de TABLE&#95;UUID&#95;MISMATCH en l’absence d’analyseur. [#99380](https://github.com/ClickHouse/ClickHouse/pull/99380) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#100060](https://github.com/ClickHouse/ClickHouse/issues/100060) : correction de la compatibilité lors de la mise à niveau de tables répliquées avec des indices minmax implicites de la version 25.10 vers des versions plus récentes. [#99392](https://github.com/ClickHouse/ClickHouse/pull/99392) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#100317](https://github.com/ClickHouse/ClickHouse/issues/100317) : suppression de la prise en charge des fonctions niées (`notEquals`, `notLike`, `notIn`) dans l’analyse de l’index de texte. Ces fonctions ne pouvaient jamais exclure de granules ; analyser l’index pour elles n’ajoutait donc qu’un surcoût, sans aucun bénéfice. [#99393](https://github.com/ClickHouse/ClickHouse/pull/99393) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100106](https://github.com/ClickHouse/ClickHouse/issues/100106) : correction d’un rare marquage erroné d’une data part comme corrompue, suivi de son détachement après une requête `DETACH/ATTACH TABLE`. [#99529](https://github.com/ClickHouse/ClickHouse/pull/99529) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100358](https://github.com/ClickHouse/ClickHouse/issues/100358) : correction d’un partition pruning incorrect pour `toWeek()`, qui faisait que les requêtes avec `WHERE toWeek(date, mode) = N` renvoyaient des résultats vides pour les semaines 49 à 52 sur des tables partitionnées par `toYYYYMM(date)`. [#99542](https://github.com/ClickHouse/ClickHouse/pull/99542) ([Takumi Hara](https://github.com/takumihara)).
* Rétroporté dans [#99750](https://github.com/ClickHouse/ClickHouse/issues/99750) : interdiction de lire des identifiants Google depuis un fichier local. Ce paramètre n’est pas sécurisé, car il permet de lire d’autres identifiants si le chemin du fichier est connu. [#99584](https://github.com/ClickHouse/ClickHouse/pull/99584) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Rétroporté dans [#100316](https://github.com/ClickHouse/ClickHouse/issues/100316) : correction de l’analyse des prédicats avec la fonction `IN` par l’index de texte avec le préprocesseur. Correction également des collisions entre les tokens recherchés dans l’index de texte, qui pouvaient entraîner des résultats incorrects. [#99755](https://github.com/ClickHouse/ClickHouse/pull/99755) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100099](https://github.com/ClickHouse/ClickHouse/issues/100099) : correction d’un échec d’assertion (exception dans les builds de débogage, résultats incorrects dans les builds de release) lors de la multiplication des aggregate states `NumericIndexedVector` par une constante entière paire, causé par un auto-XOR sur des bitmaps Roaring aliasés dans `pointwiseAddInplace`. [#99976](https://github.com/ClickHouse/ClickHouse/pull/99976) ([Desel72](https://github.com/Desel72)).
* Rétroporté dans [#100285](https://github.com/ClickHouse/ClickHouse/issues/100285) : correction de l’utilisation incorrecte de l’index de texte avec les fonctions `startsWith` et `endsWith` pour les tokenizers qui ne prennent pas en charge la correspondance par sous-chaîne (`array`, `splitByString`). Auparavant, ces tokenizers produisaient silencieusement des résultats erronés, ce qui pouvait amener l’index à exclure des granules contenant des lignes correspondantes. [#100151](https://github.com/ClickHouse/ClickHouse/pull/100151) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100267](https://github.com/ClickHouse/ClickHouse/issues/100267) : correction d’un rare plantage lors de la levée d’une exception &quot;Memory Limit&quot; pendant la construction de l’index de texte. [#100213](https://github.com/ClickHouse/ClickHouse/pull/100213) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100258](https://github.com/ClickHouse/ClickHouse/issues/100258) : correction des erreurs &quot;Not-ready Set is passed as the second argument&quot; lors de l&#39;analyse d&#39;un index de texte construit sur `mapValues` pour des prédicats contenant la clause `IN`. [#100224](https://github.com/ClickHouse/ClickHouse/pull/100224) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100344](https://github.com/ClickHouse/ClickHouse/issues/100344) : correction d&#39;une exception `LOGICAL_ERROR` dans des requêtes impliquant des colonnes `Dynamic` avec des jointures croisées et des filtres d&#39;exécution, causée par `ColumnVariant::filter`, qui partageait des pointeurs vers des colonnes variantes au lieu de les cloner dans le chemin d&#39;optimisation `hasOnlyNulls`. Clôt [https://github.com/ClickHouse/ClickHouse/pull/100147](https://github.com/ClickHouse/ClickHouse/pull/100147). [#100234](https://github.com/ClickHouse/ClickHouse/pull/100234) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#100553](https://github.com/ClickHouse/ClickHouse/issues/100553) : correction d&#39;un bug de copier-coller où `delta_lake_snapshot_end_version`, défini sans `delta_lake_snapshot_start_version`, était ignoré silencieusement au lieu de produire une erreur `BAD_ARGUMENTS`. [#100454](https://github.com/ClickHouse/ClickHouse/pull/100454) ([Mohammad Lareb Zafar](https://github.com/zlareb1)).
* Rétroporté dans [#100596](https://github.com/ClickHouse/ClickHouse/issues/100596) : correction de l&#39;exception LOGICAL&#95;ERROR &quot;Stream ... not found&quot; lors de l&#39;insertion dans une table avec des colonnes `Array(JSON)` imbriquées dans des wide parts avec `optimize_on_insert=0`. [#100475](https://github.com/ClickHouse/ClickHouse/pull/100475) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#100889](https://github.com/ClickHouse/ClickHouse/issues/100889) : validation des chemins des entrées de fichier dans les métadonnées de sauvegarde afin de rejeter les traversées de chemin, les chemins absolus et les noms vides lors de `RESTORE`. [#100483](https://github.com/ClickHouse/ClickHouse/pull/100483) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#100638](https://github.com/ClickHouse/ClickHouse/issues/100638) : correction d&#39;un segfault où `SerializationInfoTuple::add` effectue un `assert_cast` sur une simple référence `SerializationInfo` lors de la fusion de parts après qu&#39;`ALTER MODIFY COLUMN` a changé une colonne d&#39;un type non-`Tuple` en `Tuple`. [#100509](https://github.com/ClickHouse/ClickHouse/pull/100509) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#100727](https://github.com/ClickHouse/ClickHouse/issues/100727) : correction des cas NOT&#95;FOUND&#95;COLUMN&#95;IN&#95;BLOCK où la partie SELECT de la projection contient des colonnes qui n&#39;existent pas dans la partie SELECT d&#39;origine de la requête. Clôt [#100194](https://github.com/ClickHouse/ClickHouse/issues/100194). [#100623](https://github.com/ClickHouse/ClickHouse/pull/100623) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#100865](https://github.com/ClickHouse/ClickHouse/issues/100865) : correction des combinateurs de fonctions d&#39;agrégation `If`, `Distinct`, `DistinctIf`, `IfState ` avec un type de retour `Tuple` et un ou plusieurs arguments `Nullable`, qui ne pouvaient pas lire d&#39;anciens états sérialisés après l&#39;introduction de `Nullable(Tuple)`. Clôt [#98917](https://github.com/ClickHouse/ClickHouse/issues/98917). [#100826](https://github.com/ClickHouse/ClickHouse/pull/100826) ([Nihal Z. Miaji](https://github.com/nihalzp)).
