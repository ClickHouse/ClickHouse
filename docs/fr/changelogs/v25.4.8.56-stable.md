<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#82417](https://github.com/ClickHouse/ClickHouse/issues/82417) : prise en charge des horodatages Unix avec partie fractionnaire dans le parsing DateTime64 en mode best effort. [#78908](https://github.com/ClickHouse/ClickHouse/pull/78908) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#82413](https://github.com/ClickHouse/ClickHouse/issues/82413) : les fonctions de hachage prennent désormais en charge les NULL dans les arrays, tuples et maps. (issues [#48365](https://github.com/ClickHouse/ClickHouse/issues/48365) et [#48623](https://github.com/ClickHouse/ClickHouse/issues/48623)). [#79008](https://github.com/ClickHouse/ClickHouse/pull/79008) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#81801](https://github.com/ClickHouse/ClickHouse/issues/81801) : ajout de l&#39;événement de profil `PageCacheReadBytes`. [#81742](https://github.com/ClickHouse/ClickHouse/pull/81742) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#82593](https://github.com/ClickHouse/ClickHouse/issues/82593) : amélioration de Keeper : ajout de la nouvelle config `keeper_server.cleanup_old_and_ignore_new_acl`. Si elle est activée, les ACL de tous les nœuds seront effacées, tandis que les ACL des nouvelles requêtes seront ignorées. Si l&#39;objectif est de supprimer complètement les ACL des nœuds, il est important de laisser cette config activée jusqu&#39;à la création d&#39;un nouveau snapshot. [#82496](https://github.com/ClickHouse/ClickHouse/pull/82496) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#82858](https://github.com/ClickHouse/ClickHouse/issues/82858) : après [https://github.com/ClickHouse/ClickHouse/pull/73834](https://github.com/ClickHouse/ClickHouse/pull/73834), les formats des en-têtes `X-ClickHouse-Progress` et `X-ClickHouse-Summary` ont été modifiés pour omettre les valeurs égales à zéro. Cette PR vise à rétablir le comportement précédent uniquement pour `X-ClickHouse-Summary`, car c&#39;est plus pertinent. [#82727](https://github.com/ClickHouse/ClickHouse/pull/82727) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#82924](https://github.com/ClickHouse/ClickHouse/issues/82924) : amélioration de Keeper : prise en charge d&#39;autorisations spécifiques pour l&#39;ACL world:anyone. [#82755](https://github.com/ClickHouse/ClickHouse/pull/82755) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)

* Rétroporté dans [#82185](https://github.com/ClickHouse/ClickHouse/issues/82185) : correction d&#39;une erreur logique lors de la matérialisation d&#39;une projection lorsque le type de colonne a été changé en Nullable. [#80741](https://github.com/ClickHouse/ClickHouse/pull/80741) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#81811](https://github.com/ClickHouse/ClickHouse/issues/81811) : correction de l&#39;erreur `Table does not exist` pour les requêtes distribuées avec prédicat poussé (`allow_push_predicate_ast_for_distributed_subqueries=1`) lorsque la table source n&#39;existe pas sur l&#39;initiateur. Corrige [#77281](https://github.com/ClickHouse/ClickHouse/issues/77281). [#80915](https://github.com/ClickHouse/ClickHouse/pull/80915) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#82014](https://github.com/ClickHouse/ClickHouse/issues/82014) : correction de `Unknown table expression identifier` pour `distributed_product_mode_local=local` avec réplication croisée. [#81162](https://github.com/ClickHouse/ClickHouse/pull/81162) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#82330](https://github.com/ClickHouse/ClickHouse/issues/82330) : correction de l&#39;exécution de `IN` avec `transform_null_in=1`, avec une valeur null dans l&#39;argument de gauche et un résultat de sous-requête non Nullable. [#81584](https://github.com/ClickHouse/ClickHouse/pull/81584) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#82175](https://github.com/ClickHouse/ClickHouse/issues/82175) : ne pas valider les types expérimentaux/suspects lors de l&#39;exécution des expressions default/materialize pendant la lecture d&#39;une table existante. [#81618](https://github.com/ClickHouse/ClickHouse/pull/81618) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#82124](https://github.com/ClickHouse/ClickHouse/issues/82124) : correction de &quot;Context has expired&quot; pendant les fusions lorsqu&#39;un dict est utilisé dans une expression TTL. [#81690](https://github.com/ClickHouse/ClickHouse/pull/81690) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#82323](https://github.com/ClickHouse/ClickHouse/issues/82323) : dans les versions précédentes, le serveur renvoyait un contenu excessif pour les requêtes vers `/js`. Cela clôt [#61890](https://github.com/ClickHouse/ClickHouse/issues/61890). [#81895](https://github.com/ClickHouse/ClickHouse/pull/81895) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#82235](https://github.com/ClickHouse/ClickHouse/issues/82235) : auparavant, les définitions du moteur de table `MongoDB` pouvaient inclure un composant de chemin dans l&#39;argument `host:port`, qui était ignoré silencieusement. L&#39;intégration MongoDB refusait de charger de telles tables. Avec ce correctif, *nous autorisons le chargement de telles tables et ignorons le composant de chemin* si le moteur `MongoDB` a cinq arguments, en utilisant le nom de la base de données fourni dans les arguments. *Remarque :* le correctif ne s&#39;applique pas aux tables nouvellement créées ni aux requêtes utilisant la fonction de table `mongo`, ni aux sources de dictionnaire et aux collections nommées. [#81942](https://github.com/ClickHouse/ClickHouse/pull/81942) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#82777](https://github.com/ClickHouse/ClickHouse/issues/82777) : correction de l&#39;analyse du filtre lorsqu&#39;une seule colonne d&#39;alias constante est utilisée dans la requête. Corrige [#79448](https://github.com/ClickHouse/ClickHouse/issues/79448). [#82037](https://github.com/ClickHouse/ClickHouse/pull/82037) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#82550](https://github.com/ClickHouse/ClickHouse/issues/82550) : correction de LOGICAL&#95;ERROR et du crash qui s&#39;ensuivait lors de l&#39;utilisation de la même colonne dans le TTL pour GROUP BY et SET. [#82054](https://github.com/ClickHouse/ClickHouse/pull/82054) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#82153](https://github.com/ClickHouse/ClickHouse/issues/82153) : correction d&#39;une erreur de copier-coller dans arraySimilarity, avec interdiction d&#39;utiliser des poids UInt32 et Int32. Mise à jour des tests et de la documentation. [#82103](https://github.com/ClickHouse/ClickHouse/pull/82103) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* Rétroporté dans [#82316](https://github.com/ClickHouse/ClickHouse/issues/82316) : correction de l&#39;erreur `Not found column` pour les requêtes avec `arrayJoin` dans une condition `WHERE` et `IndexSet`. [#82113](https://github.com/ClickHouse/ClickHouse/pull/82113) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#82558](https://github.com/ClickHouse/ClickHouse/issues/82558) : correction d&#39;un interblocage possible pour les requêtes distantes lorsque le serveur subit une pression mémoire. [#82160](https://github.com/ClickHouse/ClickHouse/pull/82160) ([Kirill](https://github.com/kirillgarbar)).
* Rétroporté dans [#82521](https://github.com/ClickHouse/ClickHouse/issues/82521) : ajout d&#39;une expiration au jeton AWS ECS afin qu&#39;il puisse être rechargé. [#82422](https://github.com/ClickHouse/ClickHouse/pull/82422) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#82577](https://github.com/ClickHouse/ClickHouse/issues/82577) : correction du masquage des valeurs des collections nommées dans logs/query&#95;log. Ferme [#82405](https://github.com/ClickHouse/ClickHouse/issues/82405). [#82510](https://github.com/ClickHouse/ClickHouse/pull/82510) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#82568](https://github.com/ClickHouse/ClickHouse/issues/82568) : correction d&#39;un plantage possible lors de la journalisation pendant la fermeture d&#39;une session, car user&#95;id peut parfois être vide. [#82513](https://github.com/ClickHouse/ClickHouse/pull/82513) ([Bharat Nallan](https://github.com/bharatnc)).
* Rétroporté dans [#82686](https://github.com/ClickHouse/ClickHouse/issues/82686) : correction de `LOGICAL_ERROR` lors de l&#39;analyse de l&#39;expression de ROW POLICY pour les colonnes corrélées. [#82618](https://github.com/ClickHouse/ClickHouse/pull/82618) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#82733](https://github.com/ClickHouse/ClickHouse/issues/82733) : les fonctions `trim{Left,Right,Both}` prennent désormais en charge les chaînes d&#39;entrée de type &quot;FixedString(N)&quot;. Par exemple, `SELECT trimBoth(toFixedString('abc', 3), 'ac')` fonctionne désormais. [#82691](https://github.com/ClickHouse/ClickHouse/pull/82691) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#82798](https://github.com/ClickHouse/ClickHouse/issues/82798) : correction de la désérialisation de `groupArraySample`/`groupArrayLast` en cas d&#39;éléments vides (la désérialisation pouvait ignorer une partie du binaire si l&#39;entrée était vide, ce qui peut entraîner une corruption lors de la lecture des données ainsi que l&#39;erreur UNKNOWN&#95;PACKET&#95;FROM&#95;SERVER dans le protocole TCP).
