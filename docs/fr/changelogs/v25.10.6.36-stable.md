<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#94931](https://github.com/ClickHouse/ClickHouse/issues/94931) : forcer la purge des arènes jemalloc lorsque le ratio entre la taille des pages sales et `max_server_memory_usage` dépasse `memory_worker_purge_dirty_pages_threshold_ratio`. [#93500](https://github.com/ClickHouse/ClickHouse/pull/93500) ([Eduard Karacharov](https://github.com/korowa)).
* Rétroporté dans [#94728](https://github.com/ClickHouse/ClickHouse/issues/94728) : ajout de la prise en charge des collections nommées définies en SQL dans BACKUP/RESTORE pour S3 et Azure Blob Storage. Clôt [#94604](https://github.com/ClickHouse/ClickHouse/issues/94604). [#94605](https://github.com/ClickHouse/ClickHouse/pull/94605) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#94984](https://github.com/ClickHouse/ClickHouse/issues/94984) : faire en sorte que le scheduler privilégie le thread MemoryWorker en cas de manque de CPU, car il protège le processus ClickHouse d’une menace existentielle. [#94864](https://github.com/ClickHouse/ClickHouse/pull/94864) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#95141](https://github.com/ClickHouse/ClickHouse/issues/95141) : exécuter la purge des pages sales de jemalloc dans un thread distinct du thread principal de MemoryWorker. Si la purge est lente, elle peut retarder les mises à jour de l’utilisation de la mémoire RSS, ce qui peut entraîner l’arrêt du processus par manque de mémoire. Introduction d’une nouvelle config `memory_worker_purge_total_memory_threshold_ratio` pour déclencher la purge des pages sales en fonction du ratio d’utilisation mémoire totale. [#94902](https://github.com/ClickHouse/ClickHouse/pull/94902) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#95434](https://github.com/ClickHouse/ClickHouse/issues/95434) : désormais, `view_duration_ms` affiche la durée pendant laquelle le groupe était actif, et non la somme des durées des threads qu’il contient. [#94966](https://github.com/ClickHouse/ClickHouse/pull/94966) ([Sema Checherinda](https://github.com/CheSema)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#94621](https://github.com/ClickHouse/ClickHouse/issues/94621) : correction d’une possible erreur logique lors de la réception d’une autre requête de lecture provenant d’une réplique après l’envoi d’une réponse avec l’indicateur `finish=true`. Cela pouvait se produire en raison d’une condition de concurrence logique dans `MergeTreeReadPoolParallelReplicas`, bien que ce cas soit très peu probable. [#90921](https://github.com/ClickHouse/ClickHouse/pull/90921) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#95284](https://github.com/ClickHouse/ClickHouse/issues/95284) : correction de la substitution des paramètres de requête dans les méthodes d’authentification de CREATE USER lors de l’utilisation de ON CLUSTER. Les paramètres de requête dans les méthodes d’authentification (par ex. `password`) n’étaient pas remplacés, ce qui provoquait des erreurs UNKNOWN&#95;QUERY&#95;PARAMETER sur les nœuds distants. [#92777](https://github.com/ClickHouse/ClickHouse/pull/92777) ([xiaohuanlin](https://github.com/xiaohuanlin)).
* Rétroporté dans [#94763](https://github.com/ClickHouse/ClickHouse/issues/94763) : correction des résultats de jointure lorsque la clé de jointure du côté droit est une colonne sparse. Cela clôt [#92920](https://github.com/ClickHouse/ClickHouse/issues/92920). Je ne peux reproduire le bug qu’avec `set compatibility='23.3'`. Je ne suis pas certain qu’il faille le rétroporter. [#93038](https://github.com/ClickHouse/ClickHouse/pull/93038) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#95528](https://github.com/ClickHouse/ClickHouse/issues/95528) : les sauvegardes pouvaient faire planter le serveur si vous exécutiez de nombreuses sauvegardes concurrentes en conflit sur les mêmes fichiers. [#93659](https://github.com/ClickHouse/ClickHouse/pull/93659) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#94884](https://github.com/ClickHouse/ClickHouse/issues/94884) : correction de l’attachement des bases de données Replicated lorsque l’hôte interserveur changeait après un redémarrage. [#93779](https://github.com/ClickHouse/ClickHouse/pull/93779) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Rétroporté dans [#94590](https://github.com/ClickHouse/ClickHouse/issues/94590) : correction de la conversion de type vers un supertype lors de l’opération de jointure du moteur de stockage `Join` avec la clause `USING`. Corrige [#91672](https://github.com/ClickHouse/ClickHouse/issues/91672). Corrige [#78572](https://github.com/ClickHouse/ClickHouse/issues/78572). [#94000](https://github.com/ClickHouse/ClickHouse/pull/94000) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#94356](https://github.com/ClickHouse/ClickHouse/issues/94356) : correction d’une mauvaise vérification des chemins typés dans JSON. Cette vérification a été introduite dans [https://github.com/ClickHouse/ClickHouse/pull/92842](https://github.com/ClickHouse/ClickHouse/pull/92842) et peut entraîner une erreur au démarrage des tables existantes. [#94070](https://github.com/ClickHouse/ClickHouse/pull/94070) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#95201](https://github.com/ClickHouse/ClickHouse/issues/95201) : correction du fait que l’optimisation des fonctions vers les sous-colonnes ne s’appliquait pas aux sous-colonnes. [#94323](https://github.com/ClickHouse/ClickHouse/pull/94323) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#94927](https://github.com/ClickHouse/ClickHouse/issues/94927) : correction d’un plantage pendant l’optimisation de ANY LEFT JOIN lorsque `isNotNull` est évalué sur une colonne manquante. [#94600](https://github.com/ClickHouse/ClickHouse/pull/94600) ([Molly](https://github.com/ggmolly)).
* Rétroporté dans [#94820](https://github.com/ClickHouse/ClickHouse/issues/94820) : correction des problèmes d’autorisation dans les opérations BACKUP/RESTORE. [#94617](https://github.com/ClickHouse/ClickHouse/pull/94617) ([Pablo Marcos](https://github.com/pamarcos)).

Probablement à cause d&#39;une confusion, `data_type` (qui peut être `DataTypeNullable*`) est converti par `static_cast` en `DataTypeDateTime64*`. Il faut à la place convertir `check_type` (la variable de type imbriqué). [#94627](https://github.com/ClickHouse/ClickHouse/pull/94627) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
