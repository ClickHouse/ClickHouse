<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Rétroporté dans [#68710](https://github.com/ClickHouse/ClickHouse/issues/68710) : les entrées du cache de requêtes peuvent désormais être supprimées par tag. Par exemple, l’entrée du cache de requêtes créée par `SELECT 1 SETTINGS use_query_cache = true, query_cache_tag = 'abc'` peut désormais être supprimée avec `SYSTEM DROP QUERY CACHE TAG 'abc'` (ou, bien sûr, simplement avec : `SYSTEM DROP QUERY CACHE`, ce qui videra l’intégralité du cache de requêtes). [#68477](https://github.com/ClickHouse/ClickHouse/pull/68477) ([Michał Tabaszewski](https://github.com/pinsvin00)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#68973](https://github.com/ClickHouse/ClickHouse/issues/68973) : correction de la borne supérieure de la fonction `fromModifiedJulianDay`. Elle était censée être `9999-12-31`, mais avait été définie par erreur sur `9999-01-01`. [#67583](https://github.com/ClickHouse/ClickHouse/pull/67583) ([PHO](https://github.com/depressed-pho)).
* Rétroporté dans [#68818](https://github.com/ClickHouse/ClickHouse/issues/68818) : correction d’un crash lors du filtrage Parquet lorsque les types de données du fichier diffèrent sensiblement des types demandés (par ex. `... FROM file('a.parquet', Parquet, 'x String')`, alors que le fichier contient `x Int64`). Sans ce correctif, utilisez `input_format_parquet_filter_push_down = 0` comme solution de contournement. [#68131](https://github.com/ClickHouse/ClickHouse/pull/68131) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#68893](https://github.com/ClickHouse/ClickHouse/issues/68893) : après [https://github.com/ClickHouse/ClickHouse/pull/61984](https://github.com/ClickHouse/ClickHouse/pull/61984), `schema_inference_make_columns_nullable=0` peut toujours rendre des colonnes `Nullable` dans les formats Parquet/Arrow. Ce changement n’était pas rétrocompatible, et les utilisateurs ont constaté cette modification de comportement. Cette PR rétablit le fonctionnement antérieur de `schema_inference_make_columns_nullable=0` (aucune colonne `Nullable` ne sera inférée) et introduit une nouvelle valeur, `auto`, pour ce paramètre, afin de rendre les colonnes `Nullable` uniquement si les données contiennent des informations de nullabilité. [#68298](https://github.com/ClickHouse/ClickHouse/pull/68298) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68721](https://github.com/ClickHouse/ClickHouse/issues/68721) : corrige [#50868](https://github.com/ClickHouse/ClickHouse/issues/50868). De petites valeurs constantes DateTime64 renvoyées par une sous-requête imbriquée dans une requête distribuée étaient transformées à tort en valeurs nulles, provoquant ainsi des erreurs et des résultats de la requête potentiellement incorrects. [#68323](https://github.com/ClickHouse/ClickHouse/pull/68323) ([Shankar](https://github.com/shiyer7474)).
* Rétroporté dans [#69029](https://github.com/ClickHouse/ClickHouse/issues/69029) : réajout des colonnes virtuelles ` _table` et `_database` aux tables distribuées. Elles étaient disponibles jusqu’à la version 24.3. [#68672](https://github.com/ClickHouse/ClickHouse/pull/68672) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68864](https://github.com/ClickHouse/ClickHouse/issues/68864) : correction d’une erreur possible `Size of permutation (0) is less than required (...)` lors de la permutation d’une colonne Variant. [#68681](https://github.com/ClickHouse/ClickHouse/pull/68681) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68854](https://github.com/ClickHouse/ClickHouse/issues/68854) : correction d’une erreur possible `DB::Exception: Block structure mismatch in joined block stream: different columns:` avec la nouvelle colonne JSON. [#68686](https://github.com/ClickHouse/ClickHouse/pull/68686) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68790](https://github.com/ClickHouse/ClickHouse/issues/68790) : correction d’un problème lié aux clés constantes matérialisées lors du hachage de maps dont les clés sont des arrays dans les fonctions `sipHash(64/128)Keyed`. [#68731](https://github.com/ClickHouse/ClickHouse/pull/68731) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Rétroporté dans [#69108](https://github.com/ClickHouse/ClickHouse/issues/69108) : TODO. [#68744](https://github.com/ClickHouse/ClickHouse/pull/68744) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

Résout [#68739](https://github.com/ClickHouse/ClickHouse/issues/68739). [#68836](https://github.com/ClickHouse/ClickHouse/pull/68836) ([Kseniia Sumarokova](https://github.com/kssenii)).
