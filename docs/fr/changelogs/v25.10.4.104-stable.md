<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Rétroporté dans [#92119](https://github.com/ClickHouse/ClickHouse/issues/92119) : suite de [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380). Cette PR considère la désactivation des arguments positionnels dans les projections comme un changement non rétrocompatible. De plus, elle introduit le paramètre `enable_positional_arguments_for_projections` pour permettre une mise à niveau sûre d’un cluster ClickHouse lorsque des arguments positionnels sont présents dans les projections. [#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Rétroporté dans [#91308](https://github.com/ClickHouse/ClickHouse/issues/91308) : ajout d’un nouveau paramètre MergeTree `merge_max_dynamic_subcolumns_in_wide_part` afin de limiter le nombre de sous-colonnes dynamiques dans la Wide part après fusion, indépendamment des paramètres spécifiés dans le type de données. [#87646](https://github.com/ClickHouse/ClickHouse/pull/87646) ([Pavel Kruglov](https://github.com/Avogar)).

  #### Amélioration des performances
</div>

* Rétroporté dans [#92310](https://github.com/ClickHouse/ClickHouse/issues/92310) : Https://github.com/clickhouse/clickhouse/pull/84477 a ajouté des contraintes concernant les requêtes `select` pouvant être utilisées dans les requêtes `insert select from s3cluster()` pour une exécution distribuée parallèle.
