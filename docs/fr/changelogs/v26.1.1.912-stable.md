  ### Version de ClickHouse v26.1.1.912-stable (4c47e680f55) FIXME par rapport à v26.1.1.1-new (1f0c87b97de)

<div id="backward-incompatible-change">
  #### Changement Incompatible avec les Versions Précédentes
</div>

* Correction d&#39;un formatage incohérent causé par une substitution incorrecte d&#39;alias dans le formateur. Résout [#82833](https://github.com/ClickHouse/ClickHouse/issues/82833). Résout [#82832](https://github.com/ClickHouse/ClickHouse/issues/82832). Résout [#68296](https://github.com/ClickHouse/ClickHouse/issues/68296). Ce changement est potentiellement incompatible avec les versions précédentes : lorsque l&#39;analyseur est désactivé, certaines requêtes CREATE VIEW utilisant IN en référence à un alias ne peuvent pas être traitées. Pour éviter cette incompatibilité, activez l&#39;analyseur (activé par défaut depuis la version 24.3). [#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Les codecs `DEFLATE_QPL` et `ZSTD_QAT` ont été supprimés. Il est conseillé aux utilisateurs de convertir les données existantes compressées avec `DEFLATE_QPL` ou `ZSTD_QAT` vers un autre codec avant toute mise à niveau. Notez que pour utiliser ces codecs, les paramètres `enable_deflate_qpl_codec` et `enable_zstd_qat_codec` devaient être activés. [#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze)).
* Correction du débogage des UDF en activant la capture de stderr dans `system.query_log.exception`. Auparavant, le stderr des UDF n&#39;était consigné que dans des fichiers et n&#39;apparaissait pas dans les journaux de requêtes, rendant le débogage impossible. Désormais, stderr déclenche des exceptions par défaut et est entièrement accumulé (jusqu&#39;à 1 Mo) avant d&#39;être levé, de sorte que les traces Python complètes et les messages d&#39;erreur apparaissent dans `system.query_log.exception` pour faciliter le dépannage. [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
* Une liste de colonnes vide dans la clause `JOIN USING ()` est désormais considérée comme une erreur de syntaxe. Auparavant, cela devait générer une `INVALID_JOIN_ON_EXPRESSION` lors de l&#39;exécution de la requête. Dans certains cas, comme lors d&#39;une jointure avec le moteur de stockage `Join`, cela entraînait une `LOGICAL_ERROR` ; résout [#82502](https://github.com/ClickHouse/ClickHouse/issues/82502). [#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Activation par défaut des données partagées avancées pour JSON. Suite à ce changement, le retour à des versions antérieures à 25.8 ne sera plus possible, car ces versions ne pourront pas lire les nouveaux data parts contenant une colonne JSON. Pour des mises à niveau sécurisées, il est recommandé de définir le paramètre `compatibility` sur la version précédente, ou de configurer les paramètres MergeTree `dynamic_serialization_version='v2', object_serialization_version='v2'`. [#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar)).
* Utilisation par défaut de la correspondance partielle pour SKIP REGEXP dans le type JSON. Résout [#79250](https://github.com/ClickHouse/ClickHouse/issues/79250). [#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar)).
* Annulation de « Allow INSERT into simple ALIAS columns » (annule ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154)). Cette fonctionnalité ne fonctionne pas avec les formats personnalisés et n&#39;est pas protégée par un paramètre. [#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat)).
* Ajout d&#39;un paramètre permettant de lever une erreur si le catalogue datalake n&#39;a pas accès au stockage objet. [#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Le moteur de base de données `Lazy` a été supprimé et n&#39;est plus disponible. Résout [#91231](https://github.com/ClickHouse/ClickHouse/issues/91231). [#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Suppression du mode `transposed_with_wide_view` du `metric_log` — inutilisable en raison d&#39;un bogue. Il n&#39;est plus possible de définir `system.metric_log` avec ce mode. Annule partiellement [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412). [#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La planification CPU des charges de travail est désormais préemptive par défaut. Voir le paramètre serveur `cpu_slot_preemption`. [#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa)).
* Échappement des noms de fichiers d&#39;index pour éviter les parts corrompus. Suite à ce changement, ClickHouse ne pourra pas charger les index dont le nom contient des caractères non-ASCII créés par des versions précédentes. Pour y remédier, vous pouvez utiliser le paramètre MergeTree `escape_index_filenames`. [#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano)).
* Les paramètres de format `exact_rows_before_limit`, `rows_before_aggregation`, `cross_to_inner_join_rewrite`, `regexp_dict_allow_hyperscan`, `regexp_dict_flag_case_insensitive`, `regexp_dict_flag_dotall` et `dictionary_use_async_executor` ont été convertis en paramètres ordinaires (non liés au format). Il s&#39;agit d&#39;un changement purement interne sans effet visible pour l&#39;utilisateur, sauf dans le cas (peu probable) où vous auriez spécifié l&#39;un de ces paramètres dans les définitions de moteur de table Iceberg, DeltaLake, Kafka, S3, S3Queue, Azure, Hive, RabbitMQ, Set, FileLog ou NATS. Dans ces cas, ces paramètres étaient auparavant ignorés ; désormais, de telles définitions lèvent une erreur. [#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze)).
* Les fonctions `joinGet/joinGetOrNull` appliquent désormais les privilèges `SELECT` sur la table Join sous-jacente. Suite à ce changement, l&#39;exécution de `joinGet('db.table', 'column', key)` requiert que l&#39;utilisateur dispose du privilège `SELECT` à la fois sur les colonnes clés définies dans la table Join et sur la colonne d&#39;attribut récupérée. Les requêtes ne disposant pas de ces privilèges échoueront avec `ACCESS_DENIED`. Pour migrer, accordez les autorisations nécessaires via `GRANT SELECT ON db.join_table TO user` pour un accès complet à la table, ou `GRANT SELECT(key_col, attr_col) ON db.join_table TO user` pour un accès au niveau des colonnes. Ce changement affecte tous les utilisateurs et applications s&#39;appuyant sur `joinGet`/`joinGetOrNull` pour lesquels des droits `SELECT` explicites n&#39;avaient pas été configurés auparavant. [#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Vérification de `SHOW COLUMNS` pour les requêtes `CREATE TABLE ... AS ...`. Auparavant, la vérification portait sur `SHOW TABLES`, ce qui constituait un droit incorrect pour ce type de contrôle de permission. [#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit)).





<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* API HTTP et interface Web intégrée pour CH Keeper. [#78181](https://github.com/ClickHouse/ClickHouse/pull/78181) ([pufit](https://github.com/pufit)).
* Analyse d’index distribuée sur plusieurs répliques. Bénéfique pour le stockage partagé et les très grands volumes de données dans le cluster. [#86786](https://github.com/ClickHouse/ClickHouse/pull/86786) ([Azat Khuzhin](https://github.com/azat)).
* Avec `<interactive_history_legacy_keymap>true</interactive_history_legacy_keymap>`, le client CLI peut désormais revenir à Ctrl R pour la recherche classique comme auparavant, tandis que Ctrl T effectue une recherche floue. [#87785](https://github.com/ClickHouse/ClickHouse/pull/87785) ([Larry Snizek](https://github.com/larry-cdn77)).
* La déduplication des insertions asynchrones fonctionne désormais avec les vues matérialisées dépendantes. Lorsqu’une collision sur block&#95;id se produit, le bloc d’origine est filtré pour supprimer les lignes associées à ce block&#95;id, puis les lignes restantes sont transformées à l’aide de toutes les requêtes SELECT des vues matérialisées pertinentes, ce qui reconstruit le bloc d’origine sans lignes en conflit. [#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* Ajout de la possibilité, pour clickhouse client, de remplacer le SNI TLS lors de la connexion au serveur. [#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).
* Ajout de la prise en charge des index de texte intégral pour les colonnes Array. [#89895](https://github.com/ClickHouse/ClickHouse/pull/89895) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Nouvelle table système zookeeper&#95;info. Corrige [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014). [#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Implémentation de FunctionVariantAdaptor pour prendre en charge le type Variant dans les fonctions. [#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* Ajoute une métrique `ClickHouse_Info` au point de terminaison Prometheus `/metrics`, contenant principalement des informations de version, afin de permettre la création de graphiques suivant des informations de version détaillées au fil du temps. [#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* Introduction d’une nouvelle commande `rcfg` à quatre lettres pour Keeper, qui permet de modifier la configuration du cluster. Cette commande offre davantage de possibilités de modification de la configuration que la requête standard `reconfigure`. La commande prend une chaîne `json` comme argument. L’ensemble des octets envoyés à l’interface TCP doit ressembler à ceci : `rcfg{json_string_length_big_endian}{json_string}`. Voici à quoi peuvent ressembler certaines commandes : `{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`. [#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* Ajout de la fonction `reverseBySeparator`, qui inverse l’ordre des sous-chaînes d’une chaîne séparées par un séparateur donné. Clôt [#91463](https://github.com/ClickHouse/ClickHouse/issues/91463). [#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* Introduction d’une nouvelle syntaxe et d’un nouveau framework pour simplifier et étendre la fonctionnalité des index de projection. Cela fait suite à https://github.com/ClickHouse/ClickHouse/pull/81021. [#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* Prise en charge du Paimon REST Catalog, dans la continuité de https://github.com/ClickHouse/ClickHouse/pull/84423. [#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* Ajoute le nouveau paramètre `max_insert_block_size_bytes`, qui contrôle plus finement la formation des blocs insérés. [#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* Il est possible d’exécuter des requêtes DDL avec la clause `ON CLUSTER` pour une base de données Replicated si le paramètre `ignore_on_cluster_for_replicated_database` est activé. Dans ce cas, le nom du cluster sera ignoré. [#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* Implémente la fonction `mergeTreeAnalyzeIndex()`. [#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* Ajoute le nouveau paramètre `use_primary_key`. Définissez-le sur `false` pour désactiver l’élagage des granules basé sur la clé primaire. [#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Fonction de table `icebergLocalCluster`. [#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Le prewhere pour les data lakes et le prewhere multi-étapes dans le lecteur Parquet v3 corrigent [#89101](https://github.com/ClickHouse/ClickHouse/issues/89101). [#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Ajoute la fonction `cosineDistanceTransposed`, qui approxime la [distance cosinus](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance) entre deux points. [#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* L’instruction précédente pour vider les caches, `SYSTEM DROP [...] CACHE`, donnait la fausse impression qu’elle désactivait le cache. ClickHouse prend désormais en charge l’instruction `SYSTEM CLEAR [...] CACHE`, plus explicite. L’ancienne syntaxe reste disponible. [#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* Ajoute une colonne files à la table system.parts, qui affiche le nombre de fichiers dans chaque data part. [#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* Ajoute un ordonnanceur d’équité max-min pour le contrôle de la concurrence. Il offre une meilleure équité en cas de forte surallocation, lorsque de nombreuses requêtes se disputent un nombre limité de slots CPU. Les requêtes de courte durée ne sont pas pénalisées par les requêtes de longue durée qui ont accumulé davantage de slots au fil du temps. Il s’active avec la valeur `max_min_fair` du paramètre serveur `concurrent_threads_scheduler`. [#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Davantage de filtres sont poussés dans les JOIN. [#85556](https://github.com/ClickHouse/ClickHouse/pull/85556) ([Nikita Taranov](https://github.com/nickitat)).
* Désactivation de l&#39;optimisation de l&#39;ordre de tri pour les window functions lorsque `PARTITION BY` correspond à la sorting key ou en est un préfixe, ce qui améliore les performances de l&#39;exécution parallèle. [#87299](https://github.com/ClickHouse/ClickHouse/pull/87299) ([Nikita Taranov](https://github.com/nickitat)).
* Le filtre externe est poussé dans la vue, ce qui permet d&#39;appliquer PREWHERE sur les nœuds locaux et distants. Résout [#88189](https://github.com/ClickHouse/ClickHouse/issues/88189). [#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).
* Implémentation de la compilation JIT pour davantage de fonctions. Clôt [#73509](https://github.com/ClickHouse/ClickHouse/issues/73509). [#88770](https://github.com/ClickHouse/ClickHouse/pull/88770) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimisation des performances et de l&#39;utilisation mémoire pour `LIMIT` et `OFFSET` fractionnaires. [#91167](https://github.com/ClickHouse/ClickHouse/pull/91167) ([Ahmed Gouda](https://github.com/0xgouda)).
* Correction de l&#39;utilisation de la logique de lecture aléatoire rapide pour le prefetcher Parquet Reader V3. Clôt [#90890](https://github.com/ClickHouse/ClickHouse/issues/90890). [#91435](https://github.com/ClickHouse/ClickHouse/pull/91435) ([Arsen Muk](https://github.com/arsenmuk)).
* Amélioration des performances de `icebergCluster`. Clôt [#91462](https://github.com/ClickHouse/ClickHouse/issues/91462). [#91537](https://github.com/ClickHouse/ClickHouse/pull/91537) ([Yang Jiang](https://github.com/Ted-Jiang)).
* Ne pas filtrer sur les colonnes virtuelles lorsque les filtres sont constants. [#91588](https://github.com/ClickHouse/ClickHouse/pull/91588) ([c-end](https://github.com/c-end)).
* Amélioration des performances de `DISTINCT` sur les colonnes `LowCardinality`. Clôt [#5917](https://github.com/ClickHouse/ClickHouse/issues/5917). [#91639](https://github.com/ClickHouse/ClickHouse/pull/91639) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Optimisation de la fonction d&#39;agrégation distinctJSONPaths afin qu&#39;elle lise uniquement les JSON paths à partir des data parts, et non l&#39;intégralité de la JSON column. [#92196](https://github.com/ClickHouse/ClickHouse/pull/92196) ([Pavel Kruglov](https://github.com/Avogar)).
* Réduction de l&#39;utilisation mémoire d&#39;INSERT/merges avec les wide parts pour les very wide tables grâce à l&#39;activation de buffers d&#39;écriture adaptatifs. Ajout de la prise en charge des buffers d&#39;écriture adaptatifs pour les disks chiffrés. [#92250](https://github.com/ClickHouse/ClickHouse/pull/92250) ([Azat Khuzhin](https://github.com/azat)).
* Prise en charge de davantage de cas de push down à partir de la condition ON d&#39;un join lorsque le filtre utilise uniquement des entrées d&#39;un seul côté. Prise en charge des joins `ANY`, `SEMI`, `ANTI`. [#92584](https://github.com/ClickHouse/ClickHouse/pull/92584) ([Dmitry Novik](https://github.com/novikd)).
* Autorisation d&#39;utiliser des sets équivalents pour pousser les filtres vers le bas pour `SEMI JOIN`. Clôt [#85239](https://github.com/ClickHouse/ClickHouse/issues/85239). [#92837](https://github.com/ClickHouse/ClickHouse/pull/92837) ([Dmitry Novik](https://github.com/novikd)).
* Amélioration des performances de la recherche en texte intégral avec le text index et le tokenizer `sparseGrams`, en réduisant le nombre de tokens recherchés dans l&#39;index. [#93078](https://github.com/ClickHouse/ClickHouse/pull/93078) ([Anton Popov](https://github.com/CurtizJ)).
* Utilisation de la méthode &quot;fastrange&quot; (Daniel Lemire) pour partitionner les données au sein du query pipeline. Cela peut améliorer le tri parallèle et les JOIN. [#93080](https://github.com/ClickHouse/ClickHouse/pull/93080) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimisation de `uniqExact` dans les cas où des éléments identiques se suivent souvent. [#93268](https://github.com/ClickHouse/ClickHouse/pull/93268) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La fonction `isValidASCII` a été optimisée pour les cas positifs, c.-à-d. lorsque les valeurs d’entrée sont entièrement en ASCII. [#93347](https://github.com/ClickHouse/ClickHouse/pull/93347) ([Robert Schulze](https://github.com/rschu1ze)).
* La fonction `isValidASCII` a été optimisée pour les cas positifs, c.-à-d. lorsque les valeurs d’entrée sont entièrement en ASCII. [#93611](https://github.com/ClickHouse/ClickHouse/pull/93611) ([Robert Schulze](https://github.com/rschu1ze)).
* La lecture du côté gauche du hash join est désormais ignorée lorsque le côté droit est vide. Auparavant, nous lisions le côté gauche jusqu’au premier block non vide, ce qui pouvait entraîner beaucoup de travail en cas de filtrage important ou d’agrégation. [#94062](https://github.com/ClickHouse/ClickHouse/pull/94062) ([Alexander Gololobov](https://github.com/davenger)).
* L’optimisation de lecture ordonnée reconnaît désormais quand les colonnes de ORDER BY sont constantes en raison des conditions WHERE, ce qui permet des lectures efficaces en ordre inverse. Cela profite aux requêtes multi-tenant comme &#96;WHERE tenant=&#39;42&#39; ORDER BY tenant, event&#95;time DESC&#96;, qui peuvent maintenant utiliser InReverseOrder au lieu d’exiger un tri complet.&quot;. [#94103](https://github.com/ClickHouse/ClickHouse/pull/94103) ([matanper](https://github.com/matanper)).
* Ajout d’une classe AST spécialisée pour Enum afin de stocker les paramètres de valeur sous forme de paires chaîne/entier au lieu de nœuds enfants ASTLiteral, afin d’optimiser la consommation mémoire. [#94178](https://github.com/ClickHouse/ClickHouse/pull/94178) ([Ilya Yatsishin](https://github.com/qoega)).





<div id="improvement">
  #### Improvement
</div>

* Prise en charge de plusieurs colonnes comme clé primaire dans StorageEmbeddedRocksDB. Clôture [#32819](https://github.com/ClickHouse/ClickHouse/issues/32819). [#33917](https://github.com/ClickHouse/ClickHouse/pull/33917) ([usurai](https://github.com/usurai)).

Elle permet d'attacher des parties depuis n'importe quel sous-répertoire du répertoire `detached/`. Cela peut être utile pour rattacher des parties avec des préfixes personnalisés (tels que `broken-on-start`, `unexpected`, etc.) qui ont été détachées par erreur et doivent simplement être rattachées sans intervention manuelle. Auparavant, un renommage manuel des répertoires sur le système de fichiers était nécessaire. [#74816](https://github.com/ClickHouse/ClickHouse/pull/74816) ([Anton Popov](https://github.com/CurtizJ)).
* Suivi du partitionnement hive pour le mode ordonné dans S3Queue. Résout [#71161](https://github.com/ClickHouse/ClickHouse/issues/71161). [#81040](https://github.com/ClickHouse/ClickHouse/pull/81040) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Optimisation de la réservation d'espace dans le cache du système de fichiers. `FileCache::collectCandidatesForEviction` sera exécuté sans verrou exclusif. [#82764](https://github.com/ClickHouse/ClickHouse/pull/82764) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Prise en charge d'une stratégie de rotation composite (taille + temps) pour le journal du serveur. [#87620](https://github.com/ClickHouse/ClickHouse/pull/87620) ([Jianmei Zhang](https://github.com/zhangjmruc)).
* Le client CLI peut désormais spécifier `<warnings>false</warnings>` à la place de l'option en ligne de commande `--no-warnings`. [#87783](https://github.com/ClickHouse/ClickHouse/pull/87783) ([Larry Snizek](https://github.com/larry-cdn77)).
* Ajout de la prise en charge de la fonction d'agrégation `avg()` avec des valeurs de type Date, DateTime et Time comme arguments. Clôture [#82267](https://github.com/ClickHouse/ClickHouse/issues/82267). [#87845](https://github.com/ClickHouse/ClickHouse/pull/87845) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
