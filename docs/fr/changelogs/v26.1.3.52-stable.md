* Rétroporté dans [#97291](https://github.com/ClickHouse/ClickHouse/issues/97291) : l’inférence de schéma respecte désormais `allow_experimental_nullable_tuple_type`. Lorsque ce paramètre est activé, il permet aux types Tuple inférés d’être `Nullable(Tuple(...))`, de sorte que les objets imbriqués absents puissent devenir `NULL` plutôt qu’un tuple d’éléments `NULL`. [#95525](https://github.com/ClickHouse/ClickHouse/pull/95525) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#95836](https://github.com/ClickHouse/ClickHouse/issues/95836) : mise à niveau de la bibliothèque interne libxml2 vers 2.15.1. [#95574](https://github.com/ClickHouse/ClickHouse/pull/95574) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#96034](https://github.com/ClickHouse/ClickHouse/issues/96034) : ignorer les lectures dans le stockage objet lors de l’interrogation des tables `DeltaLake` depuis system.tables. [#95899](https://github.com/ClickHouse/ClickHouse/pull/95899) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96908](https://github.com/ClickHouse/ClickHouse/issues/96908) : meilleure introspection de jemalloc. [#96840](https://github.com/ClickHouse/ClickHouse/pull/96840) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction d’anomalie (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#96316](https://github.com/ClickHouse/ClickHouse/issues/96316) : suppression de la vérification inutile du contournement des permissions dans les requêtes `ATTACH` pour une vue avec SQL Security. Cela évite une potentielle escalade de privilèges lorsqu’un utilisateur attache une vue avec un definer sans valider les accès requis. [#94865](https://github.com/ClickHouse/ClickHouse/pull/94865) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#95806](https://github.com/ClickHouse/ClickHouse/issues/95806) : correction de l’inférence de type pour les colonnes qualifiées provenant des tables sources lorsque plusieurs jointures sont utilisées avec la clause `USING`. Auparavant, les jointures suivantes mettaient à jour de manière incorrecte les types des colonnes sources sous-jacentes vers un supertype commun, même lorsque la colonne n’était pas impliquée dans cette jointure (par exemple, dans `SELECT t2.a FROM t1 LEFT JOIN t2 USING (a) LEFT JOIN t3 USING (a)`, la colonne `t2.a` n’est utilisée que par la première jointure ; son type doit donc être le supertype de `t1.a` et `t2.a`, à l’exclusion de `t3.a`). Cela pouvait entraîner des erreurs logiques ou des plantages lorsque des fonctions attendaient des types de colonnes différents de ceux présents dans le plan d’exécution. [#95157](https://github.com/ClickHouse/ClickHouse/pull/95157) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#96396](https://github.com/ClickHouse/ClickHouse/issues/96396) : correction d’une erreur logique dans certains cas lorsque `LIMIT/OFFSET` négatif est utilisé dans des requêtes distribuées. [#95357](https://github.com/ClickHouse/ClickHouse/pull/95357) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#96222](https://github.com/ClickHouse/ClickHouse/issues/96222) : correction d’un plantage lors de l’application de `tupleElement` à des tableaux de JSON. Clôt [#95581](https://github.com/ClickHouse/ClickHouse/issues/95581). [#95647](https://github.com/ClickHouse/ClickHouse/pull/95647) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#95825](https://github.com/ClickHouse/ClickHouse/issues/95825) : correction du compactage des données delta lake partitionnées. [#95773](https://github.com/ClickHouse/ClickHouse/pull/95773) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#95852](https://github.com/ClickHouse/ClickHouse/issues/95852) : correction d’une race condition sur une colonne de jointure Nullable dans les filtres d’exécution. [#95775](https://github.com/ClickHouse/ClickHouse/pull/95775) ([Hechem Selmi](https://github.com/m-selmi)).
* Rétroporté dans [#97187](https://github.com/ClickHouse/ClickHouse/issues/97187) : correction de l’exécution de `tupleElement` sur du JSON avec des chemins imbriqués ; auparavant, cela pouvait produire un résultat de la requête erroné. [#95907](https://github.com/ClickHouse/ClickHouse/pull/95907) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#96086](https://github.com/ClickHouse/ClickHouse/issues/96086) : correction d’une erreur `NOT_SUPPORTED` qui pouvait survenir lors de l’utilisation de l’algorithme de jointure `direct` avec une table MergeTree vide. [#95935](https://github.com/ClickHouse/ClickHouse/pull/95935) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#95993](https://github.com/ClickHouse/ClickHouse/issues/95993) : correction de event&#95;date dans system.asynchronous&#95;metric&#95;log. [#95947](https://github.com/ClickHouse/ClickHouse/pull/95947) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#96215](https://github.com/ClickHouse/ClickHouse/issues/96215) : correction des chemins ignorés dans le type de données JSON. Auparavant, avec `JSON(SKIP path)`, toutes les clés JSON ayant le préfixe `path` étaient ignorées, y compris des clés comme `"pathpath"` ; cela pouvait donc entraîner une perte de données pour ces chemins lors de l’insertion. C’est désormais corrigé : seule la clé `"path"` est ignorée. [#95948](https://github.com/ClickHouse/ClickHouse/pull/95948) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#96082](https://github.com/ClickHouse/ClickHouse/issues/96082) : corrige la période des profileurs globaux (contrôlée par `global_profiler_real_time_period_ns` et `global_profiler_cpu_time_period_ns`). Au lieu de la valeur définie, une valeur tronquée était utilisée, ce qui faisait réveiller le profiler plus souvent que prévu. [#96048](https://github.com/ClickHouse/ClickHouse/pull/96048) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96189](https://github.com/ClickHouse/ClickHouse/issues/96189) : auparavant, si le fichier de données de référence dans le fichier manifest Iceberg pour la suppression par position était présent dans une entrée mais nul, nous n’obtenions pas les bornes correctes pour les fichiers de données correspondants.
