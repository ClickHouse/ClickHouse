<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bugs (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#108869](https://github.com/ClickHouse/ClickHouse/issues/108869) : correction d’un arrêt brutal du serveur pendant `RESTORE` de sauvegardes contenant des tables avec des dépendances cycliques. [#103824](https://github.com/ClickHouse/ClickHouse/pull/103824) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#108903](https://github.com/ClickHouse/ClickHouse/issues/108903) : correction d’une erreur logique (`Unexpected return type from equals. Expected Nullable(UInt8). Got UInt8`) lorsque l’optimisation de push-down de disjonction (prédicat partiel) applique une condition sur une clé `USING` dont le type est élargi par le JOIN. Correction également d’un plantage du serveur (segmentation fault) dans l’analyseur lors de la résolution des identifiants dans des requêtes `JOIN ... USING` contenant des branches `if`/`multiIf` réductibles en constantes qui référencent des identifiants inconnus. [#107407](https://github.com/ClickHouse/ClickHouse/pull/107407) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#108643](https://github.com/ClickHouse/ClickHouse/issues/108643) : correction de `RESTORE` pour les tables `ReplicatedMergeTree`, afin que les parts à contenu dupliqué d’une sauvegarde soient préservées au lieu d’être dédupliquées silencieusement. [#107652](https://github.com/ClickHouse/ClickHouse/pull/107652) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#108748](https://github.com/ClickHouse/ClickHouse/issues/108748) : les requêtes de recherche vectorielle qui font un `SELECT` sur la colonne `_distance` renvoient désormais une erreur appropriée au lieu d’échouer avec `LOGICAL_ERROR`. [#108423](https://github.com/ClickHouse/ClickHouse/pull/108423) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#108667](https://github.com/ClickHouse/ClickHouse/issues/108667) : correction de la lecture directe depuis plusieurs index de texte partiellement matérialisés. [#108607](https://github.com/ClickHouse/ClickHouse/pull/108607) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#108825](https://github.com/ClickHouse/ClickHouse/issues/108825) : correction de la désactivation silencieuse de l’élagage des partitions et de la clé primaire lorsqu’une colonne de clé `LowCardinality(FixedString)` (ou `LowCardinality(Nullable(FixedString))`) est enveloppée dans une fonction au niveau de la clé, par exemple `PARTITION BY sipHash64(k) % N` avec `WHERE k = 'literal'`. De telles requêtes parcouraient toutes les partitions au lieu de les élaguer. [#108777](https://github.com/ClickHouse/ClickHouse/pull/108777) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#108907](https://github.com/ClickHouse/ClickHouse/issues/108907) : correction de `insert_quorum = 'auto'`, qui ne rejetait pas les insertions immédiatement lorsque moins de la majorité des répliques étaient disponibles. De telles insertions échouent désormais immédiatement avec `TOO_FEW_LIVE_REPLICAS` au lieu d’écrire une part locale puis d’expirer plus tard avec `UNKNOWN_STATUS_OF_INSERT`. [#108800](https://github.com/ClickHouse/ClickHouse/pull/108800) ([Gagan Dhakrey](https://github.com/gagandhakrey)).
