<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#97109](https://github.com/ClickHouse/ClickHouse/issues/97109) : correction d’une possible erreur logique lors de l’utilisation de `analyzer_compatibility_join_using_top_level_identifier` avec plusieurs jointures. [#90010](https://github.com/ClickHouse/ClickHouse/pull/90010) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#96400](https://github.com/ClickHouse/ClickHouse/issues/96400) : correction d’un possible résultat de la requête incorrect après des lightweight updates dans des requêtes `SELECT` avec le query condition cache activé. Corrige [#90176](https://github.com/ClickHouse/ClickHouse/issues/90176). Corrige [#90054](https://github.com/ClickHouse/ClickHouse/issues/90054). [#90204](https://github.com/ClickHouse/ClickHouse/pull/90204) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#91754](https://github.com/ClickHouse/ClickHouse/issues/91754) : correction de la validation des accès pour les requêtes `ALTER UPDATE` lorsqu’une table function `remote` est utilisée avec `localhost` comme hôte cible. [#90761](https://github.com/ClickHouse/ClickHouse/pull/90761) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#97815](https://github.com/ClickHouse/ClickHouse/issues/97815) : issue associée : [#6365](https://github.com/ClickHouse/support-escalation/issues/6365). [#92339](https://github.com/ClickHouse/ClickHouse/pull/92339) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Rétroporté dans [#97327](https://github.com/ClickHouse/ClickHouse/issues/97327) : suppression d’une vérification de permissions inutile dans les requêtes `ATTACH` pour une vue avec SQL Security. Cela empêche une possible escalation de privilèges lorsqu’un utilisateur attache une vue avec un definer sans valider les accès requis. [#94865](https://github.com/ClickHouse/ClickHouse/pull/94865) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#95814](https://github.com/ClickHouse/ClickHouse/issues/95814) : correction de l’inférence de type pour les colonnes qualifiées des tables source lorsque plusieurs jointures sont utilisées avec la clause `USING`. Auparavant, les jointures suivantes mettaient incorrectement à jour les types des colonnes source sous-jacentes vers un supertype commun, même lorsque la colonne n’était pas impliquée dans cette jointure (par exemple, dans `SELECT t2.a FROM t1 LEFT JOIN t2 USING (a) LEFT JOIN t3 USING (a)`, la colonne `t2.a` n’est utilisée que par la première jointure ; son type devrait donc être le supertype de `t1.a` et `t2.a`, à l’exclusion de `t3.a`). Cela pouvait entraîner des erreurs logiques ou des crashs lorsque les fonctions attendaient des types de colonnes différents de ceux réellement présents dans le plan d’exécution. [#95157](https://github.com/ClickHouse/ClickHouse/pull/95157) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#95484](https://github.com/ClickHouse/ClickHouse/issues/95484) : la table function `mergeTreeProjection` ne comportait pas de vérification d’accès, ce qui permettait à des utilisateurs ne disposant pas de la permission SELECT sur une table (mais ayant des permissions pour les table functions) de lire des données à partir de ses projections. Ce correctif ajoute la même vérification d’accès que `mergeTreeIndex` et `mergeTreeAnalyzeIndexes`. [#95480](https://github.com/ClickHouse/ClickHouse/pull/95480) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#96052](https://github.com/ClickHouse/ClickHouse/issues/96052) : correction du squashing des données delta lake partitionnées. [#95773](https://github.com/ClickHouse/ClickHouse/pull/95773) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#96209](https://github.com/ClickHouse/ClickHouse/issues/96209) : correction des skipping paths dans le type de données JSON. Auparavant, avec `JSON(SKIP path)`, toutes les clés JSON ayant le préfixe `path` étaient ignorées, y compris des clés comme `"pathpath"`, ce qui pouvait entraîner une perte de données pour ces paths lors de l’insert. Désormais, c’est corrigé et seule la clé `"path"` est ignorée. [#95948](https://github.com/ClickHouse/ClickHouse/pull/95948) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#96076](https://github.com/ClickHouse/ClickHouse/issues/96076) : correction de la période des profileurs globaux (contrôlée par `global_profiler_real_time_period_ns` et `global_profiler_cpu_time_period_ns`). Au lieu de la valeur configurée, une valeur tronquée était utilisée, ce qui amenait le profileur à se réveiller plus souvent que prévu. [#96048](https://github.com/ClickHouse/ClickHouse/pull/96048) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96538](https://github.com/ClickHouse/ClickHouse/issues/96538) : correction de la révocation des rôles par défaut. [#96103](https://github.com/ClickHouse/ClickHouse/pull/96103) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#97149](https://github.com/ClickHouse/ClickHouse/issues/97149) : correction de `AccessRights::contains`, qui renvoyait des résultats incorrects en cas de révocations partielles. [#96170](https://github.com/ClickHouse/ClickHouse/pull/96170) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#96276](https://github.com/ClickHouse/ClickHouse/issues/96276) : correction d’un interblocage possible dans ProcessList. Cela peut se produire en raison d’une inversion de verrous si le mécanisme de suivi de memory overcommit se déclenche pendant l’ajout d’une tâche au vérificateur d’annulation. [#96182](https://github.com/ClickHouse/ClickHouse/pull/96182) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96555](https://github.com/ClickHouse/ClickHouse/issues/96555) : correction d’un crash dans l’ancien analyzer en présence de JOIN et d’alias dupliqués. [#96405](https://github.com/ClickHouse/ClickHouse/pull/96405) ([Ilya Golshtein](https://github.com/ilejn)).
* Rétroporté dans [#96578](https://github.com/ClickHouse/ClickHouse/issues/96578) : correction d’un verrouillage actif dans le thread du vérificateur d’annulation pour les requêtes avec des valeurs élevées de `max_execution_time`. [#96450](https://github.com/ClickHouse/ClickHouse/pull/96450) ([Sergei Trifonov](https://github.com/serxa)).
* Rétroporté dans [#96689](https://github.com/ClickHouse/ClickHouse/issues/96689) : validation de la version witness dans bech32 pour éviter un dépassement de tampon. [#96671](https://github.com/ClickHouse/ClickHouse/pull/96671) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#97202](https://github.com/ClickHouse/ClickHouse/issues/97202) : correction de `min(timestamp)`, qui renvoyait l’époque Unix (`1970-01-01`) via `_minmax_count_projection` après une fusion TTL lorsque toutes les lignes d’un block étaient filtrées.
