<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#95286](https://github.com/ClickHouse/ClickHouse/issues/95286) : correction de la substitution des paramètres de requête dans les méthodes d’authentification de `CREATE USER` lors de l’utilisation de `ON CLUSTER`. Les paramètres de requête dans les méthodes d’authentification (par ex. `password`) n’étaient pas remplacés, ce qui provoquait des erreurs UNKNOWN&#95;QUERY&#95;PARAMETER sur les nœuds distants. [#92777](https://github.com/ClickHouse/ClickHouse/pull/92777) ([xiaohuanlin](https://github.com/xiaohuanlin)).
* Rétroporté dans [#95529](https://github.com/ClickHouse/ClickHouse/issues/95529) : les sauvegardes pouvaient faire planter le serveur si de nombreuses sauvegardes concurrentes entraient en conflit sur les mêmes fichiers. [#93659](https://github.com/ClickHouse/ClickHouse/pull/93659) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#94973](https://github.com/ClickHouse/ClickHouse/issues/94973) : créer un workload dans un autre workload en cours d’utilisation ne provoque plus de crash. [#94599](https://github.com/ClickHouse/ClickHouse/pull/94599) ([Sergei Trifonov](https://github.com/serxa)).
* Rétroporté dans [#95642](https://github.com/ClickHouse/ClickHouse/issues/95642) : correction de l’élagage incorrect de la clé primaire et de l’index de saut pour les prédicats impliquant `toWeek`, `toYearWeek`, `toStartOfWeek`, `toLastDayOfWeek` et `toDayOfWeek`, ainsi que des exceptions dans certaines de ces fonctions pour des requêtes valides avec `LowCardinality(String)`. [#94816](https://github.com/ClickHouse/ClickHouse/pull/94816) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#95629](https://github.com/ClickHouse/ClickHouse/issues/95629) : correction d’un crash au démarrage de `ReplicatedMergeTree` causé par la suppression concurrente de répertoires `delete_tmp_*`. [#94892](https://github.com/ClickHouse/ClickHouse/pull/94892) ([myeongjun](https://github.com/myeongjjun)).
* Rétroporté dans [#95815](https://github.com/ClickHouse/ClickHouse/issues/95815) : correction de l’inférence de type pour les colonnes qualifiées issues des tables sources lorsque plusieurs JOIN sont utilisés avec la clause `USING`. Auparavant, les JOIN suivants mettaient incorrectement à jour les types des colonnes sources sous-jacentes vers un supertype commun, même lorsque la colonne n’était pas impliquée dans ce JOIN (par ex., dans `SELECT t2.a FROM t1 LEFT JOIN t2 USING (a) LEFT JOIN t3 USING (a)`, la colonne `t2.a` n’est utilisée que par le premier JOIN ; son type devrait donc être le supertype de `t1.a` et `t2.a`, à l’exclusion de `t3.a`). Cela pouvait entraîner des erreurs logiques ou des crashs lorsque les fonctions attendaient des types de colonnes différents de ceux présents dans le plan d’exécution. [#95157](https://github.com/ClickHouse/ClickHouse/pull/95157) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#95425](https://github.com/ClickHouse/ClickHouse/issues/95425) : n’effectuer la transformation des colonnes qu’une seule fois lors de la récupération du contenu de la liste et des fichiers `.avro` du manifeste. [#95164](https://github.com/ClickHouse/ClickHouse/pull/95164) ([Daniil Ivanik](https://github.com/divanik)).
* Rétroporté dans [#95382](https://github.com/ClickHouse/ClickHouse/issues/95382) : correction d’une comptabilisation imprécise de la mémoire lors de l’application de grandes patch parts après des lightweight updates. Auparavant, l’application de gros patchs pouvait entraîner une utilisation excessive de la mémoire et faire tuer le processus serveur par l’OOM killer. [#95231](https://github.com/ClickHouse/ClickHouse/pull/95231) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#95572](https://github.com/ClickHouse/ClickHouse/issues/95572) : l’argument `password` de la fonction de table `redis` sera désormais masqué dans les journaux et les tables système (par ex. : `query_log`). [#95325](https://github.com/ClickHouse/ClickHouse/pull/95325) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#96392](https://github.com/ClickHouse/ClickHouse/issues/96392) : correction d’une erreur logique dans certains cas où un `LIMIT/OFFSET` négatif est utilisé dans des requêtes distribuées. [#95357](https://github.com/ClickHouse/ClickHouse/pull/95357) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#95606](https://github.com/ClickHouse/ClickHouse/issues/95606) : évite un crash possible des requêtes distribuées en cas d’annulation. [#95466](https://github.com/ClickHouse/ClickHouse/pull/95466) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Rétroporté dans [#95546](https://github.com/ClickHouse/ClickHouse/issues/95546) : corrige la vérification des disques chiffrés sur plain&#95;rewritable (corrige l’erreur possible `It is not possible to register multiple plain-rewritable disks with the same object storage prefix`). [#95470](https://github.com/ClickHouse/ClickHouse/pull/95470) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#95695](https://github.com/ClickHouse/ClickHouse/issues/95695) : correction de l’erreur logique `There was an error: Cannot obtain error message` lors de l’attente d’un DDL distribué et de la suppression simultanée de la base de données Replicated. Corrige [#95539](https://github.com/ClickHouse/ClickHouse/issues/95539). [#95664](https://github.com/ClickHouse/ClickHouse/pull/95664) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#96053](https://github.com/ClickHouse/ClickHouse/issues/96053) : corrige le squashing des données Delta Lake partitionnées. [#95773](https://github.com/ClickHouse/ClickHouse/pull/95773) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#96211](https://github.com/ClickHouse/ClickHouse/issues/96211) : corrige les chemins ignorés dans le type de données JSON. Auparavant, avec `JSON(SKIP path)`, toutes les clés JSON ayant le préfixe `path` étaient ignorées, y compris des clés comme `"pathpath"` ; cela pouvait donc entraîner une perte de données pour ces chemins lors de l’insert. Désormais, seule la clé `"path"` est ignorée. [#95948](https://github.com/ClickHouse/ClickHouse/pull/95948) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#96078](https://github.com/ClickHouse/ClickHouse/issues/96078) : corrige la période des global profilers (contrôlée par `global_profiler_real_time_period_ns` et `global_profiler_cpu_time_period_ns`). Au lieu de la valeur définie, une valeur tronquée était utilisée, ce qui amenait le profiler à se réveiller plus souvent que prévu. [#96048](https://github.com/ClickHouse/ClickHouse/pull/96048) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96155](https://github.com/ClickHouse/ClickHouse/issues/96155) : corrige l’utilisation d’une valeur non initialisée dans `formatDateTime` avec des formatters à largeur non fixe, comme les styles MySQL et JODA. [#96133](https://github.com/ClickHouse/ClickHouse/pull/96133) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#96278](https://github.com/ClickHouse/ClickHouse/issues/96278) : corrige un interblocage possible dans ProcessList. Cela peut se produire en raison d’une inversion de lock si l’overcommit tracker mémoire se déclenche pendant l’ajout d’une tâche au vérificateur d’annulation. [#96182](https://github.com/ClickHouse/ClickHouse/pull/96182) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96325](https://github.com/ClickHouse/ClickHouse/issues/96325) : corrige `stack-use-after-scope` dans l’index de similarité vectorielle. [#96259](https://github.com/ClickHouse/ClickHouse/pull/96259) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#96530](https://github.com/ClickHouse/ClickHouse/issues/96530) : corrige un livelock dans le thread du vérificateur d’annulation pour les requêtes avec des valeurs élevées de `max_execution_time`. [#96450](https://github.com/ClickHouse/ClickHouse/pull/96450) ([Sergei Trifonov](https://github.com/serxa)).
* Rétroporté dans [#96625](https://github.com/ClickHouse/ClickHouse/issues/96625) : correction de l&#39;exception `LOGICAL_ERROR` dans le lecteur natif Parquet V3 lorsque la colonne de filtre `PREWHERE` contient des valeurs UInt8 non booléennes. [#96594](https://github.com/ClickHouse/ClickHouse/pull/96594) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#96691](https://github.com/ClickHouse/ClickHouse/issues/96691) : validation de la witness version dans bech32 afin d&#39;éviter un dépassement de tampon. [#96671](https://github.com/ClickHouse/ClickHouse/pull/96671) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#96917](https://github.com/ClickHouse/ClickHouse/issues/96917) : correction des requêtes `ALTER TABLE DROP COLUMN` qui échouaient après l&#39;exécution préalable d&#39;une lightweight update sur la même colonne. [#96861](https://github.com/ClickHouse/ClickHouse/pull/96861) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#96936](https://github.com/ClickHouse/ClickHouse/issues/96936) : correction de l&#39;exception `std::terminate` dans `indexOfAssumeSorted` lorsqu&#39;elle est appelée avec des types incompatibles (par ex., un tableau `IPv4` avec une valeur de recherche entière). [#96877](https://github.com/ClickHouse/ClickHouse/pull/96877) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
