<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Rétroporté dans [#106038](https://github.com/ClickHouse/ClickHouse/issues/106038) : le paramètre `show_data_lake_catalogs_in_system_tables` a été renommé en `show_remote_databases_in_system_tables` et sa portée a été étendue : lorsque sa valeur est 0 (par défaut), les bases de données `MySQL` et `PostgreSQL` sont également masquées dans `system.tables`, `system.columns` et `system.completions`, en plus des catalogues de data lake. L’ancien nom du paramètre est conservé comme alias. [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#105770](https://github.com/ClickHouse/ClickHouse/issues/105770) : Divers changements apportés à Keeper le rendent globalement près de 2x plus rapide (meilleur traitement par lots, mise en pipeline des messages vers le leader, mise en pipeline des ajouts au journal). [#101757](https://github.com/ClickHouse/ClickHouse/pull/101757) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#106585](https://github.com/ClickHouse/ClickHouse/issues/106585) : Correction de `PREWHERE` avec une sous-requête `IN` sur des colonnes de clé primaire qui n’utilisait pas l’index de clé primaire pour l’élagage des granules, provoquant des parcours complets de la table au lieu de ne lire que les granules pertinentes. [#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#106233](https://github.com/ClickHouse/ClickHouse/issues/106233) : Réduction du pic d’utilisation mémoire lors de l’application des snapshots reçus dans ClickHouse Keeper avec `KeeperMemoryStorage`. [#105851](https://github.com/ClickHouse/ClickHouse/pull/105851) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#106123](https://github.com/ClickHouse/ClickHouse/issues/106123) : Ajout de `coordination_settings` à Keeper pour limiter l’admission des entrées de journal non validées de `NuRaft` et le throttling des sondes arrière `append-entries`. [#106108](https://github.com/ClickHouse/ClickHouse/pull/106108) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (comportement incorrect perceptible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#105806](https://github.com/ClickHouse/ClickHouse/issues/105806) : correction d’une corruption de données lors de l’écriture de Parquet (et d’autres formats avec footer, comme ORC et Arrow) dans HDFS via `INSERT INTO FUNCTION hdfs(...)`. Depuis la version 26.1, `WriteBufferFromHDFS` ne vidait pas son tampon de travail lors de `finalize()`, si bien que les derniers octets de chaque fichier, jusqu’à `DBMS_DEFAULT_BUFFER_SIZE`, étaient silencieusement perdus, y compris le footer Parquet `PAR1`. La lecture de tels fichiers renvoyait `Not a Parquet file (wrong magic bytes at the end of file)`. [#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105755](https://github.com/ClickHouse/ClickHouse/issues/105755) : `LEFT ANTI JOIN` renvoie désormais correctement la colonne de clé de jointure du côté droit avec des valeurs par défaut pour les lignes sans correspondance, au lieu de dupliquer la valeur de la clé de gauche. Auparavant, `SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` pouvait renvoyer `r = a.x` pour les lignes sans correspondance alors qu’il aurait dû renvoyer la valeur par défaut (`0` pour `Int32`, `''` pour `String`, `NULL` pour `Nullable`). Seule la colonne de clé de jointure était affectée ; les colonnes non clés du côté droit recevaient déjà correctement leurs valeurs par défaut. Le même bug apparaissait dans `RIGHT ANTI JOIN` chaque fois que l’optimiseur inversait les côtés. Clôt [#99959](https://github.com/ClickHouse/ClickHouse/issues/99959). [#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105670](https://github.com/ClickHouse/ClickHouse/issues/105670) : les `INSERT ... SELECT` de longue durée et les autres lectures depuis une base de données `DataLakeCatalog` avec `catalog_type = 'glue'` échouent avec `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)` une fois que les informations d’authentification de session STS capturées au moment du chargement des métadonnées de la table ont expiré. [#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Rétroporté dans [#105768](https://github.com/ClickHouse/ClickHouse/issues/105768) : correction d’une erreur logique avec `LIMIT BY` négatif dans certains cas lorsqu’il est utilisé avec `ARRAY JOIN`. [#105403](https://github.com/ClickHouse/ClickHouse/pull/105403) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#105622](https://github.com/ClickHouse/ClickHouse/issues/105622) : correction d’un heap-buffer-overflow lors de la lecture de fichiers Arrow ou ArrowStream avec des offsets intermédiaires corrompus dans une colonne binaire ou de chaîne, ainsi que d’un déréférencement de pointeur nul lors de la lecture de colonnes Arrow avec balises géographiques. [#105449](https://github.com/ClickHouse/ClickHouse/pull/105449) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#105884](https://github.com/ClickHouse/ClickHouse/issues/105884) : correction de `dictGetOrDefault`, qui levait `CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN` lorsque l’argument par défaut est une expression `Nullable` et que `short_circuit_function_evaluation` est activé avec un mélange de clés de dictionnaire trouvées et non trouvées. [#105461](https://github.com/ClickHouse/ClickHouse/pull/105461) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#106489](https://github.com/ClickHouse/ClickHouse/issues/106489) : correction d’un SIGSEGV lors de la lecture de sous-colonnes Dynamic depuis une table Memory compressée après ALTER. Clôt [#104901](https://github.com/ClickHouse/ClickHouse/issues/104901). [#105464](https://github.com/ClickHouse/ClickHouse/pull/105464) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#105876](https://github.com/ClickHouse/ClickHouse/issues/105876) : correction d’un segfault du serveur dans `uniqStateOrNull` / `uniqStateOrDefault` / `uniqOrNullState` (et des chaînes de combinators similaires sur `uniq`) lors de l’utilisation avec `GROUP BY ... WITH ROLLUP`, `WITH CUBE` ou `WITH TOTALS`, et un argument Nullable. [#105470](https://github.com/ClickHouse/ClickHouse/pull/105470) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105973](https://github.com/ClickHouse/ClickHouse/issues/105973) : correction d’un SEGFAULT dans la désérialisation de `singleValueOrNull` pour le type JSON. Ferme [#103630](https://github.com/ClickHouse/ClickHouse/issues/103630). [#105535](https://github.com/ClickHouse/ClickHouse/pull/105535) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#105724](https://github.com/ClickHouse/ClickHouse/issues/105724) : correction d’un crash dans replxx dû à l’atteinte de la limite FD&#95;SETSIZE de select() (remplacé par poll()). À noter qu’avec SSH/le terminal web activé, cela peut faire planter le serveur. [#105559](https://github.com/ClickHouse/ClickHouse/pull/105559) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#106559](https://github.com/ClickHouse/ClickHouse/issues/106559) : correction d’un crash du client sur `CREATE TABLE ... TO INNER UUID '...' ...` lorsque l’instruction n’a pas de clause `ENGINE`. Le parseur signale désormais correctement une erreur `BAD_ARGUMENTS` au lieu de déréférencer un pointeur nul. [#105579](https://github.com/ClickHouse/ClickHouse/pull/105579) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105731](https://github.com/ClickHouse/ClickHouse/issues/105731) : l’extraction de la valeur de partition Hive respecte désormais le paramètre `cast_string_to_date_time_mode` et accepte par défaut les timestamps ISO 8601 avec suffixes de fuseau horaire (par ex. `+0000`, `+00:00`, `Z`) dans les clés de partition. [#105584](https://github.com/ClickHouse/ClickHouse/pull/105584) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#105814](https://github.com/ClickHouse/ClickHouse/issues/105814) : correction d’un sous-comptage silencieux dans les requêtes `SELECT` lorsque `use_query_condition_cache = 1` (par défaut). Une requête de la forme `PREWHERE pk_prefix = X WHERE non_pk IN (...)` sur une colonne avec un skip index de type bloom filter empoisonnait le `QueryConditionCache` pour le prédicat `pk_prefix = X`, si bien qu’une requête ultérieure bénigne `SELECT count() ... WHERE pk_prefix = X` renvoyait un résultat incorrect, sous-compté. Toutes les releases 26.x étaient affectées. [#104781](https://github.com/ClickHouse/ClickHouse/issues/104781). [#105686](https://github.com/ClickHouse/ClickHouse/pull/105686) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105838](https://github.com/ClickHouse/ClickHouse/issues/105838) : correction d’un crash dans la table function `mongodb`, le moteur de stockage MongoDB et la source de dictionnaire MongoDB lorsque le nom de la collection est vide ou contient des octets NUL. [#105776](https://github.com/ClickHouse/ClickHouse/pull/105776) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#105794](https://github.com/ClickHouse/ClickHouse/issues/105794) : correction du nettoyage des snapshots `Keeper` après des écritures ayant échoué, afin que les snapshots partiels soient supprimés en toute sécurité et que les écritures en échec puissent être retentées sans faire avancer `latest_snapshot_meta`. [#105779](https://github.com/ClickHouse/ClickHouse/pull/105779) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#106065](https://github.com/ClickHouse/ClickHouse/issues/106065) : correction de l’erreur `Cannot find column` pour les requêtes distribuées avec un filtre `IN Array(...)` dans le nouvel analyseur. [#105894](https://github.com/ClickHouse/ClickHouse/pull/105894) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#106551](https://github.com/ClickHouse/ClickHouse/issues/106551) : correction d’un crash du serveur pouvant survenir lorsqu’une requête lisant depuis PostgreSQL — via la fonction de table `postgresql`, le moteur de table PostgreSQL ou un dictionnaire avec une source PostgreSQL — était annulée (par exemple avec KILL QUERY) et que l’annulation de la requête PostgreSQL distante échouait.
