  ### Version de ClickHouse v25.8.16.34-lts (7938087aa80) FIXME par rapport à v25.8.15.35-lts (7a0b36cf893)

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#95144](https://github.com/ClickHouse/ClickHouse/issues/95144) : forcer la purge des arènes jemalloc lorsque le ratio entre la taille des pages sales et `max_server_memory_usage` dépasse `memory_worker_purge_dirty_pages_threshold_ratio`. [#93500](https://github.com/ClickHouse/ClickHouse/pull/93500) ([Eduard Karacharov](https://github.com/korowa)).
* Rétroporté dans [#94727](https://github.com/ClickHouse/ClickHouse/issues/94727) : ajout de la prise en charge des collections nommées définies en SQL dans BACKUP/RESTORE pour S3 et Azure Blob Storage. Clôt [#94604](https://github.com/ClickHouse/ClickHouse/issues/94604). [#94605](https://github.com/ClickHouse/ClickHouse/pull/94605) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#95165](https://github.com/ClickHouse/ClickHouse/issues/95165) : exécute la purge des pages sales jemalloc dans un thread distinct du thread principal de MemoryWorker. Si la purge est lente, elle peut retarder les mises à jour de l’utilisation de la RSS, ce qui peut conduire à l’arrêt du processus par manque de mémoire. Introduction d’une nouvelle configuration, `memory_worker_purge_total_memory_threshold_ratio`, pour déclencher la purge des pages sales en fonction du ratio d’utilisation totale de la mémoire. [#94902](https://github.com/ClickHouse/ClickHouse/pull/94902) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#95432](https://github.com/ClickHouse/ClickHouse/issues/95432) : désormais, `view_duration_ms` affiche le temps pendant lequel le groupe était actif, et non la somme de la durée des threads qu’il contient. [#94966](https://github.com/ClickHouse/ClickHouse/pull/94966) ([Sema Checherinda](https://github.com/CheSema)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (anomalie visible par l’utilisateur dans une version stable officielle)
</div>

* Correction des valeurs min/max dans les écritures Iceberg. [#91589](https://github.com/ClickHouse/ClickHouse/pull/91589) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Rétroporté dans [#95282](https://github.com/ClickHouse/ClickHouse/issues/95282) : correction de la substitution des query parameters dans les authentication methods de CREATE USER lors de l&#39;utilisation de ON CLUSTER. Les query parameters dans les authentication methods (par ex. le password) n&#39;étaient pas remplacés, ce qui entraînait des erreurs UNKNOWN&#95;QUERY&#95;PARAMETER sur les nœuds distants. [#92777](https://github.com/ClickHouse/ClickHouse/pull/92777) ([xiaohuanlin](https://github.com/xiaohuanlin)).
* Rétroporté dans [#94761](https://github.com/ClickHouse/ClickHouse/issues/94761) : correction des résultats de jointure lorsque la join key de droite est une colonne sparse. Cela clôt [#92920](https://github.com/ClickHouse/ClickHouse/issues/92920). Je ne peux reproduire le bug qu&#39;avec `set compatibility='23.3'`. Je ne sais pas s&#39;il faut le rétroporter. [#93038](https://github.com/ClickHouse/ClickHouse/pull/93038) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#95527](https://github.com/ClickHouse/ClickHouse/issues/95527) : les backups pouvaient faire planter le serveur en cas de nombreux backups concurrents entrant en conflit sur les mêmes fichiers. [#93659](https://github.com/ClickHouse/ClickHouse/pull/93659) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#95349](https://github.com/ClickHouse/ClickHouse/issues/95349) : correction de l&#39;attachement des DB Replicated lorsque l&#39;hôte interserver changeait après un redémarrage. [#93779](https://github.com/ClickHouse/ClickHouse/pull/93779) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Rétroporté dans [#95512](https://github.com/ClickHouse/ClickHouse/issues/95512) : correction de la corruption de `_part_offset` lorsque les projections sont reconstruites pendant les merges, et optimisation du traitement des projections en évitant les lectures inutiles de la colonne `_part_offset` et en ignorant les colonnes inutiles dans les calculs de projection. Cela prolonge les optimisations introduites dans [#93233](https://github.com/ClickHouse/ClickHouse/issues/93233). [#93827](https://github.com/ClickHouse/ClickHouse/pull/93827) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#94355](https://github.com/ClickHouse/ClickHouse/issues/94355) : correction d&#39;une vérification incorrecte des paths typés dans JSON. Cette vérification a été introduite dans [https://github.com/ClickHouse/ClickHouse/pull/92842](https://github.com/ClickHouse/ClickHouse/pull/92842) et peut entraîner une erreur au démarrage de tables existantes. [#94070](https://github.com/ClickHouse/ClickHouse/pull/94070) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#95200](https://github.com/ClickHouse/ClickHouse/issues/95200) : correction de l&#39;optimisation des fonctions vers les subcolumns, qui ne s&#39;appliquait pas aux subcolumns. [#94323](https://github.com/ClickHouse/ClickHouse/pull/94323) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#94926](https://github.com/ClickHouse/ClickHouse/issues/94926) : correction d&#39;un crash lors de l&#39;optimisation de ANY LEFT JOIN lorsque `isNotNull` est évalué sur une valeur manquante. [#94600](https://github.com/ClickHouse/ClickHouse/pull/94600) ([Molly](https://github.com/ggmolly)).
* Rétroporté dans [#94819](https://github.com/ClickHouse/ClickHouse/issues/94819) : correction de problèmes de permission dans les restore operations BACKUP/RESTORE. [#94617](https://github.com/ClickHouse/ClickHouse/pull/94617) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#94840](https://github.com/ClickHouse/ClickHouse/issues/94840) : corrige [https://github.com/ClickHouse/clickhouse-core-incidents/issues/1250](https://github.com/ClickHouse/clickhouse-core-incidents/issues/1250). Vraisemblablement en raison d&#39;une confusion, `data_type` (qui peut être `DataTypeNullable*`) est transtypé via `static_cast` en `DataTypeDateTime64*`. Il faudrait à la place transtyper `check_type` (la variable du type imbriqué). [#94627](https://github.com/ClickHouse/ClickHouse/pull/94627) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#94808](https://github.com/ClickHouse/ClickHouse/issues/94808) : corrige un JOIN result RIGHT potentiellement incorrect lors de l&#39;utilisation de conditions ON complexes.
