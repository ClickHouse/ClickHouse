  ### Version de ClickHouse v26.4.4.38-stable (fe0b1d6e9c1) FIXME par rapport à v26.4.3.37-stable (a5dd9c96830)
</div>

<div id="backward-incompatible-change">
  #### Changement rétro-incompatible
</div>

* Rétroporté dans [#106046](https://github.com/ClickHouse/ClickHouse/issues/106046) : le paramètre `show_data_lake_catalogs_in_system_tables` a été renommé en `show_remote_databases_in_system_tables` et élargi : lorsque sa valeur est 0 (valeur par défaut), les bases de données `MySQL` et `PostgreSQL` sont également masquées dans `system.tables`, `system.columns` et `system.completions`, en plus des catalogues de data lake. L’ancien nom du paramètre est conservé comme alias. [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#106583](https://github.com/ClickHouse/ClickHouse/issues/106583) : correction de `PREWHERE` avec une sous-requête `IN` sur des colonnes de la clé primaire, qui n’utilisait pas l’index de clé primaire pour le pruning des granules, provoquant des parcours complets de la table au lieu de lire uniquement les granules pertinentes. [#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#105242](https://github.com/ClickHouse/ClickHouse/issues/105242) : remplacement des métriques asynchrones `HTTPConnectionPool*TCP{Rcv,Snd}BufBytes_{p50,p75,p90,p95}` par un histogramme `http_pool_tcp_buf_bytes` basé sur des buckets (labels `group`, `direction`) dans `system.histogram_metrics`. Les métriques asynchrones totales par groupe sont conservées. [#103704](https://github.com/ClickHouse/ClickHouse/pull/103704) ([Sema Checherinda](https://github.com/CheSema)).

  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)

* Rétroporté dans [#105366](https://github.com/ClickHouse/ClickHouse/issues/105366) : correction de résultats incorrects pour RIGHT ANY JOIN lorsque la table de droite contient plusieurs lignes par clé et que le bloc de sortie est scindé en raison de limites de taille. Clôt [#99431](https://github.com/ClickHouse/ClickHouse/issues/99431). [#102064](https://github.com/ClickHouse/ClickHouse/pull/102064) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#105358](https://github.com/ClickHouse/ClickHouse/issues/105358) : vérification d’un dépassement de pile dans le lecteur Avro lors de la désérialisation des types imbriqués. [#102417](https://github.com/ClickHouse/ClickHouse/pull/102417) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#105512](https://github.com/ClickHouse/ClickHouse/issues/105512) : lever `INCORRECT_DATA` au lieu de `LOGICAL_ERROR` lorsque les données fournies par le client au format Native sont tronquées ou mal formées. [#102975](https://github.com/ClickHouse/ClickHouse/pull/102975) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#105409](https://github.com/ClickHouse/ClickHouse/issues/105409) : correction de `StorageObjectStorageQueue` (`S3Queue`, `AzureQueue`), qui bloquait l’arrêt jusqu’à la lecture complète, depuis le stockage objet, des fichiers partiellement traités. La source interrompt désormais la lecture immédiatement lors de l’arrêt ; la déduplication garantit que les lignes déjà transmises à la table de destination avant l’arrêt ne sont pas dupliquées lorsque le fichier est réessayé au démarrage suivant. [#103126](https://github.com/ClickHouse/ClickHouse/pull/103126) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Rétroporté dans [#105804](https://github.com/ClickHouse/ClickHouse/issues/105804) : correction d’une corruption de données lors de l’écriture de Parquet (et d’autres formats avec bande-annonce, comme ORC et Arrow) vers HDFS via `INSERT INTO FUNCTION hdfs(...)`. Depuis la version 26.1, `WriteBufferFromHDFS` ne vidait pas son tampon de travail lors de `finalize()`, de sorte que jusqu’aux `DBMS_DEFAULT_BUFFER_SIZE` derniers octets de chaque fichier étaient silencieusement perdus, y compris le footer Parquet `PAR1`. La lecture de tels fichiers renvoyait `Not a Parquet file (wrong magic bytes at the end of file)`. [#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#106284](https://github.com/ClickHouse/ClickHouse/issues/106284) : correction du traitement du chemin encodé en URL dans la résolution deltaLakeAzure. [#103525](https://github.com/ClickHouse/ClickHouse/pull/103525) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Rétroporté dans [#105426](https://github.com/ClickHouse/ClickHouse/issues/105426) : désactivation de **`additional_table_filters`** avec **parallel replicas**, `analyzer` et sans sérialisation du plan de requête. **Auparavant, cela pouvait entraîner des résultats incorrects**. [#104296](https://github.com/ClickHouse/ClickHouse/pull/104296) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#106242](https://github.com/ClickHouse/ClickHouse/issues/106242) : correction d’une patch part corrompue après `ALTER TABLE ... DROP PARTITION ID 'patch-...'` suivi de `DETACH`/`ATTACH TABLE`. Auparavant, la part de couverture vide était écrite sans `partition.dat` ni `source_parts.dat`, ce qui entraînait une entrée `broken-on-start_patch-...` dans `system.detached_parts` après le prochain attach ou le redémarrage du serveur. Clôt [#93132](https://github.com/ClickHouse/ClickHouse/issues/93132). Clôt [#102103](https://github.com/ClickHouse/ClickHouse/issues/102103). [#104353](https://github.com/ClickHouse/ClickHouse/pull/104353) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105753](https://github.com/ClickHouse/ClickHouse/issues/105753) : `LEFT ANTI JOIN` renvoie désormais correctement la colonne de clé de jointure du côté droit avec des valeurs par défaut pour les lignes sans correspondance, au lieu de dupliquer la valeur de la clé de gauche. Auparavant, `SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` pouvait renvoyer `r = a.x` pour les lignes sans correspondance alors qu’il devrait renvoyer la valeur par défaut (`0` pour `Int32`, `''` pour `String`, `NULL` pour `Nullable`). Seule la colonne de clé de jointure était affectée ; les colonnes non clés du côté droit recevaient déjà correctement leurs valeurs par défaut. Le même bogue apparaissait dans `RIGHT ANTI JOIN` chaque fois que l’optimiseur permutait les côtés. Clôt [#99959](https://github.com/ClickHouse/ClickHouse/issues/99959). [#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105665](https://github.com/ClickHouse/ClickHouse/issues/105665) : les `INSERT ... SELECT` de longue durée et autres lectures depuis une base de données `DataLakeCatalog` avec `catalog_type = 'glue'` échouent avec `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)` une fois que les credentials de session STS capturés au moment du chargement des métadonnées de la table ont expiré. [#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Rétroporté dans [#105979](https://github.com/ClickHouse/ClickHouse/issues/105979) : corrige l’Exception `BAD_ARGUMENTS` &quot;It&#39;s a bug! Only integer types are supported by `__bitWrapperFunc`&quot; levée lorsqu’un `SELECT` avec un skip index `TYPE set(N)` contient un atome WHERE dont le type de résultat est `Float`, `BFloat16` ou tout autre type non entier (par exemple `WHERE c0 + 0.1` ou `WHERE log(c0)`). Le skip index repasse désormais par le chemin de filtre normal dans ce cas. [#105384](https://github.com/ClickHouse/ClickHouse/pull/105384) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#105621](https://github.com/ClickHouse/ClickHouse/issues/105621) : correction d’un heap-buffer-overflow lors de la lecture de fichiers Arrow ou ArrowStream avec des offsets intermédiaires corrompus dans une colonne binaire ou de type chaîne, ainsi que d’un déréférencement de pointeur nul lors de la lecture de colonnes Arrow géolocalisées.
