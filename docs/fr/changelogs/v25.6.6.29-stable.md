* Rétroporté dans [#84395](https://github.com/ClickHouse/ClickHouse/issues/84395) : correction du retour arrière de la colonne Dynamic en cas d’échec de l’analyse syntaxique. [#82169](https://github.com/ClickHouse/ClickHouse/pull/82169) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#84671](https://github.com/ClickHouse/ClickHouse/issues/84671) : correction de la fusion du filtre dans la condition JOIN lorsque les opérandes d’égalité ont des types différents ou font référence à des constantes. Corrige [#83432](https://github.com/ClickHouse/ClickHouse/issues/83432). [#84145](https://github.com/ClickHouse/ClickHouse/pull/84145) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#84558](https://github.com/ClickHouse/ClickHouse/issues/84558) : correction d’un interblocage provoqué par le thread de vérification d’annulation en arrière-plan. [#84203](https://github.com/ClickHouse/ClickHouse/pull/84203) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#84493](https://github.com/ClickHouse/ClickHouse/issues/84493) : correction de la construction incorrecte de tuples vides dans la fonction `array()`. Cela corrige [#84202](https://github.com/ClickHouse/ClickHouse/issues/84202). [#84297](https://github.com/ClickHouse/ClickHouse/pull/84297) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#84453](https://github.com/ClickHouse/ClickHouse/issues/84453) : fait de `zoutofmemory` une erreur matérielle, sinon une erreur logique sera levée. Voir [https://github.com/clickhouse/clickhouse-core-incidents/issues/877](https://github.com/clickhouse/clickhouse-core-incidents/issues/877). [#84420](https://github.com/ClickHouse/ClickHouse/pull/84420) ([Han Fei](https://github.com/hanfei1991)).
* Rétroporté dans [#84652](https://github.com/ClickHouse/ClickHouse/issues/84652) : correction des écritures dans le désordre dans le changelog de Keeper. Auparavant, des écritures pouvaient être en cours dans le changelog, mais un retour arrière pouvait provoquer une modification concurrente du fichier cible. Cela pouvait entraîner des logs incohérents et une possible perte de données. [#84434](https://github.com/ClickHouse/ClickHouse/pull/84434) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#84627](https://github.com/ClickHouse/ClickHouse/issues/84627) : correction du pruning des fichiers à l’aide d’une colonne virtuelle dans les lacs de données. [#84520](https://github.com/ClickHouse/ClickHouse/pull/84520) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#84632](https://github.com/ClickHouse/ClickHouse/issues/84632) : remplacement, pour compatibilité, de la valeur d’avant la 25.5 de `allow_experimental_delta_kernel_rs` par `false`. [#84587](https://github.com/ClickHouse/ClickHouse/pull/84587) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#84727](https://github.com/ClickHouse/ClickHouse/issues/84727) : verrouillage du &#39;mutex&#39; lors de la récupération de &#39;zookeeper&#39; depuis &#39;view&#39; dans RefreshTask.
