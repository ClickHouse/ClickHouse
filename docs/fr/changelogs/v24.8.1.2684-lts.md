<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* `clickhouse-client` et `clickhouse-local` utilisent désormais par défaut le mode multi-requête (au lieu du mode requête unique). Par exemple, `clickhouse-client -q "SELECT 1; SELECT 2"` fonctionne maintenant, alors qu&#39;auparavant il fallait ajouter `--multiquery` (ou `-n`). L&#39;option `--multiquery/-n` est devenue obsolète. Les requêtes INSERT dans des instructions multi-requêtes sont traitées différemment selon leur clause FORMAT : si le FORMAT est `VALUES` (le cas le plus courant), la fin de l&#39;instruction INSERT est marquée par un point-virgule final `;` à la fin de la requête. Pour tous les autres FORMATs (par ex. `CSV` ou `JSONEachRow`), la fin de l&#39;instruction INSERT est marquée par deux retours à la ligne `\n\n` à la fin de la requête. [#63898](https://github.com/ClickHouse/ClickHouse/pull/63898) ([FFish](https://github.com/wxybear)).
* Dans les versions précédentes, il était possible d&#39;utiliser une syntaxe alternative pour les types de données `LowCardinality` en ajoutant `WithDictionary` au nom du type de données. Il s&#39;agissait d&#39;une implémentation initiale fonctionnelle, qui n&#39;a jamais été documentée ni exposée au public. Désormais, elle est dépréciée. Si vous avez utilisé cette syntaxe, vous devez exécuter ALTER sur vos tables et renommer les types de données en `LowCardinality`. [#66842](https://github.com/ClickHouse/ClickHouse/pull/66842) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Correction d&#39;erreurs logiques avec le stockage `Buffer` utilisé avec une table de destination distribuée. Il s&#39;agit d&#39;un changement incompatible avec les versions précédentes : les requêtes utilisant `Buffer` avec une table de destination distribuée peuvent cesser de fonctionner si la table apparaît plus d&#39;une fois dans la requête (par ex. dans une auto-jointure). [#67015](https://github.com/ClickHouse/ClickHouse/pull/67015) ([vdimir](https://github.com/vdimir)).
* Dans les versions précédentes, l&#39;appel de fonctions de distributions aléatoires basées sur la fonction gamma (telles que Chi-Squared, Student, Fisher) avec des arguments négatifs proches de zéro entraînait un calcul long ou une boucle infinie. Dans la nouvelle version, appeler ces fonctions avec des arguments nuls ou négatifs produira une exception. Cela clôt [#67297](https://github.com/ClickHouse/ClickHouse/issues/67297). [#67326](https://github.com/ClickHouse/ClickHouse/pull/67326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La table système `text_log` est activée par défaut. Cela reste entièrement compatible avec les versions précédentes, mais vous pourriez remarquer une légère augmentation de l&#39;utilisation du disque local (cette table système occupe une très faible quantité d&#39;espace disque). [#67428](https://github.com/ClickHouse/ClickHouse/pull/67428) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Dans les versions précédentes, `arrayWithConstant` pouvait être lent lorsqu&#39;on lui demandait de générer de très grands tableaux. Dans la nouvelle version, il est limité à 1 Go par tableau. Cela clôt [#32754](https://github.com/ClickHouse/ClickHouse/issues/32754). [#67741](https://github.com/ClickHouse/ClickHouse/pull/67741) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Correction du formatage du modificateur REPLACE (il n&#39;est plus permis d&#39;omettre les parenthèses). [#67774](https://github.com/ClickHouse/ClickHouse/pull/67774) ([Azat Khuzhin](https://github.com/azat)).
* rétroporté [#68349](https://github.com/ClickHouse/ClickHouse/issues/68349) : réimplémentation du type Dynamic. Désormais, lorsque la limite des types de données dynamiques est atteinte, les nouveaux types ne sont plus convertis en String, mais stockés dans une structure de données spéciale au format binaire avec un type de données encodé en binaire. Désormais, tout type déjà inséré dans une colonne Dynamic peut être lu depuis celle-ci en tant que sous-colonne. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Ajout d’un nouveau moteur de stockage Kafka expérimental pour stocker les offsets dans Keeper au lieu de dépendre de leur validation dans Kafka. [#57625](https://github.com/ClickHouse/ClickHouse/pull/57625) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Ajout d’un nouveau moteur de table TimeSeries : - par défaut : `CREATE TABLE tbl ENGINE=TimeSeries` - ou en spécifiant les moteurs de ses tables internes. [#64183](https://github.com/ClickHouse/ClickHouse/pull/64183) ([Vitaly Baranov](https://github.com/vitlibar)).
* Prise en charge d’un plus grand nombre de niveaux de strictness de join (`LEFT/RIGHT SEMI/ANTI/ANY JOIN`) avec des conditions d’inégalité impliquant des colonnes de la table de gauche comme de la table de droite. Par exemple : t1.y &lt; t2.y (voir le paramètre `allow_experimental_join_condition`). [#64281](https://github.com/ClickHouse/ClickHouse/pull/64281) ([lgbo](https://github.com/lgbo-ustc)).
* Ajout de la colonne virtuelle `_etag` pour le moteur de table S3. Corrige [#65312](https://github.com/ClickHouse/ClickHouse/issues/65312). [#65386](https://github.com/ClickHouse/ClickHouse/pull/65386) ([skyoct](https://github.com/skyoct)).
* Cette pull request introduit le partitionnement de style Hive pour différents moteurs (`File`, `URL`, `S3`, `AzureBlobStorage`, `HDFS`). Le partitionnement de style Hive organise les données en sous-répertoires partitionnés, ce qui permet d’interroger et de gérer efficacement de grands jeux de données. Actuellement, il crée uniquement des colonnes virtuelles avec le nom et les données appropriés. La PR suivante introduira le filtrage approprié des données (gain de performances). [#65997](https://github.com/ClickHouse/ClickHouse/pull/65997) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout de la fonction printf pour la compatibilité avec Spark. [#66257](https://github.com/ClickHouse/ClickHouse/pull/66257) ([李扬](https://github.com/taiyang-li)).
* rétroporté [#68450](https://github.com/ClickHouse/ClickHouse/issues/68450) : implémentation du nouveau type de données JSON. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Kruglov Pavel](https://github.com/Avogar)).
* Ajout d’un nouveau paramètre serveur : disable&#95;insertion&#95;and&#95;mutation. Définissez-le sur true. Ce nœud refusera toutes les insertions et mutations (Alter table delete/update/drop partition). Cela inclut l’insertion asynchrone. [#66519](https://github.com/ClickHouse/ClickHouse/pull/66519) ([Xu Jia](https://github.com/XuJia0210)).
* Ajout des options `restore_replace_external_engines_to_null` et `restore_replace_external_table_functions_to_null` pour remplacer les moteurs externes et les fonctions de table externes par le moteur Null, ce qui peut être utile pour les tests. Cela doit fonctionner pour RESTORE et la création explicite de tables. [#66536](https://github.com/ClickHouse/ClickHouse/pull/66536) ([Ilya Yatsishin](https://github.com/qoega)).
* Ajout de la prise en charge de la lecture de la géométrie MULTILINESTRING au format WKT à l’aide de la fonction readWKTLineString. [#67647](https://github.com/ClickHouse/ClickHouse/pull/67647) ([Jacob Reckhard](https://github.com/jacobrec)).
* Ajout d’une nouvelle fonction de table `fuzzQuery`. Cette fonction permet de modifier une query string donnée en y appliquant des variations aléatoires. Exemple : `SELECT query FROM fuzzQuery('SELECT 1') LIMIT 5;`. [#67655](https://github.com/ClickHouse/ClickHouse/pull/67655) ([pufit](https://github.com/pufit)).
* Prise en charge de la requête `DROP DETACHED PARTITION ALL` pour supprimer toutes les partitions détachées. [#67885](https://github.com/ClickHouse/ClickHouse/pull/67885) ([Duc Canh Le](https://github.com/canhld94)).
* Ajout d’un mécanisme de balisage (espace de noms) pour le cache de requêtes. Des requêtes identiques avec des tags différents sont considérées comme distinctes par le cache de requêtes. Exemple : `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'abc'` et `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'def'` créent désormais des entrées distinctes dans le cache de requêtes. [#68235](https://github.com/ClickHouse/ClickHouse/pull/68235) ([sakulali](https://github.com/sakulali)).

<div id="improvement">
  #### Amélioration
</div>

* ClickHouse server prend désormais en charge le nouveau paramètre `max_keep_alive_requests`. Pour les connexions HTTP persistantes au serveur, il fonctionne de concert avec `keep_alive_timeout` : si le délai d&#39;inactivité n&#39;a pas expiré mais que plus de `max_keep_alive_requests` requêtes ont déjà été effectuées via une connexion donnée, celle-ci sera fermée par le serveur. [#61793](https://github.com/ClickHouse/ClickHouse/pull/61793) ([Nikita Taranov](https://github.com/nickitat)).
* Dans la nouvelle version, SOURCES est vérifié selon la logique des moteurs de table. Même si le droit sur les moteurs de table est désactivé par défaut, si une source n&#39;est pas autorisée, une invite concernant le moteur de table s&#39;affichait à la place, ce qui était trompeur. [#65419](https://github.com/ClickHouse/ClickHouse/pull/65419) ([jsc0218](https://github.com/jsc0218)).
* Ajout du type de statistiques `count_min` (count-min sketches), qui fournit des estimations de sélectivité pour des prédicats d&#39;égalité comme `col = 'val'`. Les types de données pris en charge sont string, date, datetime et les types numériques. [#65521](https://github.com/ClickHouse/ClickHouse/pull/65521) ([JackyWoo](https://github.com/JackyWoo)).
* Ne pas transmettre explicitement les logs de Keeper dans l&#39;image afin de permettre leur surcharge. [#65564](https://github.com/ClickHouse/ClickHouse/pull/65564) ([Azat Khuzhin](https://github.com/azat)).
* Utilisation de la base de données `Atomic` par défaut dans `clickhouse-local`. Traite les points 1 et 5 de [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647). Clôt [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817). [#65860](https://github.com/ClickHouse/ClickHouse/pull/65860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout de la statistique `rows_before_aggregation_at_least` à la réponse de la requête lorsque `rows_before_aggregation` est activé. Cette statistique représente le nombre de lignes lues avant l&#39;agrégation. Dans le contexte d&#39;une requête distribuée, lors de l&#39;utilisation de la fonction d&#39;agrégation `group by` ou `max` sans `limit`, `rows_before_aggregation_at_least` peut refléter le nombre de lignes touchées par la requête. [#66084](https://github.com/ClickHouse/ClickHouse/pull/66084) ([morning-color](https://github.com/morning-color)).
* Introduction du paramètre `use_same_password_for_base_backup` pour les requêtes `BACKUP` et `RESTORE`, permettant de créer et de restaurer des sauvegardes incrémentielles vers/depuis des archives protégées par mot de passe. [#66214](https://github.com/ClickHouse/ClickHouse/pull/66214) ([Samuele](https://github.com/sguerrini97)).
* Ignorer async&#95;load&#95;databases pour la requête ATTACH (auparavant, ATTACH pouvait renvoyer avant que les tables ne soient attachées). [#66240](https://github.com/ClickHouse/ClickHouse/pull/66240) ([Azat Khuzhin](https://github.com/azat)).
* [Replicated]MergeTreeSink doit annuler correctement son delayed&#95;chunk dans la méthode `onCancel()`. [#66279](https://github.com/ClickHouse/ClickHouse/pull/66279) ([Sema Checherinda](https://github.com/CheSema)).
* Ajout de logs et de métriques pour les connexions rejetées (lorsqu&#39;il n&#39;y a pas assez de ressources). [#66410](https://github.com/ClickHouse/ClickHouse/pull/66410) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Le paramètre `allow_experimental_analyzer` est renommé en `enable_analyzer`. L&#39;ancien nom est conservé sous forme d&#39;alias. [#66438](https://github.com/ClickHouse/ClickHouse/pull/66438) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Prise en charge du véritable type UUID pour le moteur MongoDB. [#66671](https://github.com/ClickHouse/ClickHouse/pull/66671) ([Azat Khuzhin](https://github.com/azat)).
* Ajout d’un nouveau paramètre `MergeTree` `deduplicate_merge_projection_mode` pour contrôler les projections lors des fusions (pour certains engines) et de la requête `OPTIMIZE DEDUPLICATE`. Options prises en charge : `throw` (lever une exception si la projection n’est pas entièrement prise en charge pour le moteur *MergeTree), `drop` (supprimer la projection pendant la fusion si elle ne peut pas être fusionnée elle-même de manière cohérente) et `rebuild` (reconstruire la projection à partir de zéro, ce qui est une opération lourde). [#66672](https://github.com/ClickHouse/ClickHouse/pull/66672) ([jsc0218](https://github.com/jsc0218)).
* Ajout de métriques de replication lag et de temps de recovery. [#66703](https://github.com/ClickHouse/ClickHouse/pull/66703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Ajout de la métrique S3DiskNoKeyErrors. [#66704](https://github.com/ClickHouse/ClickHouse/pull/66704) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* La clause COMMENT fonctionne désormais avec tous les moteurs de table. [#66832](https://github.com/ClickHouse/ClickHouse/pull/66832) ([Joe Lynch](https://github.com/joelynch)).
* Mise à jour de l’utilisation des codes d’erreur `BAD_ARGUMENTS` et `ILLEGAL_TYPE_OF_ARGUMENT` au profit de codes d’erreur plus précis lorsque c’est approprié. [#66851](https://github.com/ClickHouse/ClickHouse/pull/66851) ([Yohann Jardin](https://github.com/yohannj)).
* La fonction `mapFromArrays` accepte désormais `Map(K, V)` comme premier argument. Par exemple, `SELECT mapFromArrays(map('a', 4, 'b', 4), ['aa', 'bb'])` fonctionne maintenant et renvoie `{('a',4):'aa',('b',4):'bb'}`. De plus, si le 1er argument est un Array, il peut désormais aussi être de type `Array(Nullable(T))` ou `Array(LowCardinality(Nullable(T)))`, tant que les valeurs réelles du tableau ne sont pas `NULL`. [#67103](https://github.com/ClickHouse/ClickHouse/pull/67103) ([李扬](https://github.com/taiyang-li)).
* Lecture de la configuration de clickhouse-local depuis ~/.clickhouse-local. [#67135](https://github.com/ClickHouse/ClickHouse/pull/67135) ([Azat Khuzhin](https://github.com/azat)).
* Le paramètre `input_format_orc_read_use_writer_time_zone` a été renommé en `input_format_orc_reader_timezone`, et l’utilisateur peut désormais définir le fuseau horaire du lecteur. [#67175](https://github.com/ClickHouse/ClickHouse/pull/67175) ([kevinyhzou](https://github.com/KevinyhZou)).
* Réduction du niveau de l’erreur &#39;Socket is not connected&#39; lorsqu’une connexion HTTP est immédiatement réinitialisée par le pair après établissement de la connexion, correction de [#34218](https://github.com/ClickHouse/ClickHouse/issues/34218). [#67177](https://github.com/ClickHouse/ClickHouse/pull/67177) ([vdimir](https://github.com/vdimir)).

[#67391](https://github.com/ClickHouse/ClickHouse/pull/67391) ([sakulali](https://github.com/sakulali)).

S’il n’est pas spécifié, les chaînes de format `%Y-%m-%d %H:%i:%s` et `yyyy-MM-dd HH:mm:ss` sont supposées. Exemple : `SELECT parseDateTime('2021-01-04 23:12:34')` renvoie désormais la valeur DateTime `2021-01-04 23:12:34` (auparavant, cela levait une exception). [#67399](https://github.com/ClickHouse/ClickHouse/pull/67399) ([Robert Schulze](https://github.com/rschu1ze)).
