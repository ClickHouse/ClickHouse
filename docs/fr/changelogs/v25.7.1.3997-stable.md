  ### Release ClickHouse v25.7.1.3997-stable (28a03cae61b) FIXME par rapport à v25.7.1.1-new (c5372bebfd3)
</div>

<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Changements dans cette PR : 1. Introduction d’un nouvel argument `unexpected_quoting_character_strategy` dans la fonction, qui contrôle ce qui se passe lorsqu’un `quoting_character` est rencontré de manière inattendue lors de la lecture d’une clé ou d’une valeur non entre guillemets. La valeur peut être l’une des suivantes : `invalid`, `accept` ou `promote`. `Invalid` ignore la clé et revient à l’état d’attente de clé. `Accept` le traite comme faisant partie de la clé. `Promote` ignore le caractère précédent et commence l’analyse comme s’il s’agissait d’une clé entre guillemets. J’estime que le comportement par défaut (et peut-être le seul comportement) devrait être `INVALID`, mais en 2023, dans https://github.com/ClickHouse/ClickHouse/pull/56423, la logique `PROMOTE` a été implémentée. Donc, afin de conserver une certaine rétrocompatibilité, j’ai créé ce paramètre. 2. Après l’analyse d’une valeur entre guillemets, n’analyser la clé suivante que si un délimiteur de paire est trouvé. [#80657](https://github.com/ClickHouse/ClickHouse/pull/80657) ([Arthur Passos](https://github.com/arthurpassos)).
* Auparavant, la fonction `countMatches` cessait de compter à la première correspondance vide, même si le pattern l’acceptait. Pour corriger ce problème, `countMatches` poursuit désormais son exécution en avançant d’un caractère lorsqu’une correspondance vide se produit. Les utilisateurs qui souhaitent conserver l’ancien comportement peuvent activer le paramètre `count_matches_stop_at_empty_match`. [#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Auparavant, les requêtes BACKUP, les merges et les mutations n’utilisaient pas les throttlers globaux du server pour le trafic local (`max_local_read_bandwidth_for_server` et `max_local_write_bandwidth_for_server`) et distant (`max_remote_read_network_bandwidth_for_server` et `max_remote_write_network_bandwidth_for_server`) ; ils étaient uniquement limités par des server settings dédiés (`max_backup_bandwidth_for_server`, `max_mutations_bandwidth_for_server` et `max_merges_bandwidth_for_server`). Désormais, ils utilisent les deux types de throttlers simultanément. [#81753](https://github.com/ClickHouse/ClickHouse/pull/81753) ([Sergei Trifonov](https://github.com/serxa)).
* Interdire la création d’une table sans colonnes dans lesquelles il est possible de faire des insert. [#81835](https://github.com/ClickHouse/ClickHouse/pull/81835) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Auparavant, les fonctions de cluster avec archives envoyaient les archives entières aux répliques, ce qui empêchait la lecture à l’intérieur d’une archive d’être parallélisée au niveau du cluster (par exemple, avec une seule archive, elle était envoyée en bloc à une seule des répliques pour traitement, tandis que toutes les autres restaient inactives, ce qui est inefficace). Ajout d’un nouveau paramètre `cluster_function_process_archive_on_multiple_nodes`, défini sur `true` par défaut. Lorsqu’il est défini sur `true`, il améliore les performances du traitement des archives dans les fonctions de cluster. Il doit être défini sur `false` pour des raisons de compatibilité et afin d’éviter des erreurs lors de la mise à niveau vers 25.7+ si vous utilisez des fonctions de cluster avec archives sur des versions antérieures. [#82355](https://github.com/ClickHouse/ClickHouse/pull/82355) ([Kseniia Sumarokova](https://github.com/kssenii)).
* La query `SYSTEM RESTART REPLICAS` entraînait le réveil de tables dans la database Lazy, même sans accès à cette database, et cela se produisait alors que ces tables étaient supprimées simultanément. Note : désormais, `SYSTEM RESTART REPLICAS` redémarre uniquement les répliques dans les databases pour lesquelles vous avez la permission d’exécuter `SHOW TABLES`, ce qui est logique. [#83321](https://github.com/ClickHouse/ClickHouse/pull/83321) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Ajout de SZ3 comme codec de compression avec perte, mais à erreur bornée, pour les colonnes de type `Float32` et `Float64`. [#67161](https://github.com/ClickHouse/ClickHouse/pull/67161) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Prise en charge des types complexes dans l’évolution de schéma d’Iceberg. [#73714](https://github.com/ClickHouse/ClickHouse/pull/73714) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* **NumericIndexedVector** : nouvelle structure de données vectorielle reposant sur une compression bitmap Roaring bit-sliced, accompagnée de plus de 20 fonctions pour la construction, l’analyse et l’arithmétique point à point. Peut réduire le stockage et accélérer les jointures, les filtres et les agrégations sur des données creuses. Implémente [#70582](https://github.com/ClickHouse/ClickHouse/issues/70582) et l’article [“Large-Scale Metric Computation in Online Controlled Experiment Platform”](https://arxiv.org/abs/2405.08411) de T. Xiong et Y. Wang, présenté à VLDB 2024. [#74193](https://github.com/ClickHouse/ClickHouse/pull/74193) ([FriendLey](https://github.com/FriendLey)).
* Ajout du paramètre &#39;format&#95;schema&#95;source&#39;, qui définit la source de &#39;format&#95;schema&#39;. [#80874](https://github.com/ClickHouse/ClickHouse/pull/80874) ([Tuan Pham Anh](https://github.com/tuanpach)).
* Nouveaux types de données : Time ([H]HH:MM:SS) et Time64 ([H]HH:MM:SS[.fractional]), ainsi que quelques fonctions CAST de base et des fonctions permettant d’interagir avec d’autres types de données. Ajout de paramètres pour assurer la compatibilité avec la fonction legacy `ToTime`. [#81217](https://github.com/ClickHouse/ClickHouse/pull/81217) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Le workload setting `max_waiting_queries` est désormais pris en charge. Il peut être utilisé pour limiter la taille de la file d’attente des requêtes. Si la limite est atteinte, toutes les requêtes suivantes seront interrompues avec l’erreur `SERVER_OVERLOADED`. [#81250](https://github.com/ClickHouse/ClickHouse/pull/81250) ([Oleg Doronin](https://github.com/dorooleg)).
* Il est désormais possible d’utiliser USE DATABASE {name}. [#81307](https://github.com/ClickHouse/ClickHouse/pull/81307) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout de fonctions financières : `financialInternalRateOfReturnExtended` (`XIRR`), `financialInternalRateOfReturn` (`IRR`), `financialNetPresentValueExtended` (`XNPV`), `financialNetPresentValue` (`NPV`). [#81599](https://github.com/ClickHouse/ClickHouse/pull/81599) ([Joanna Hulboj](https://github.com/jh0x)).
* Ajout d&#39;une nouvelle table système `system.codecs` pour inspecter les codecs disponibles. (issue [#81525](https://github.com/ClickHouse/ClickHouse/issues/81525)). [#81600](https://github.com/ClickHouse/ClickHouse/pull/81600) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Ajout des fonctions géospatiales `polygonIntersectsCartesian` et `polygonIntersectsSpherical` pour vérifier si deux polygones se recoupent. [#81882](https://github.com/ClickHouse/ClickHouse/pull/81882) ([Paul Lamb](https://github.com/plamb)).
* Ajout de la prise en charge des lightweight updates pour les tables de la famille `MergeTree`. Les lightweight updates peuvent être utilisées avec une nouvelle syntaxe : `UPDATE <table> SET col1 = val1, col2 = val2, ... WHERE <condition>`. Ajout de l&#39;implémentation des lightweight deletes via les lightweight updates. Cette fonctionnalité peut être activée en définissant `lightweight_delete_mode = 'lightweight_update'`. [#82004](https://github.com/ClickHouse/ClickHouse/pull/82004) ([Anton Popov](https://github.com/CurtizJ)).
* Prise en charge des window functions `lag` et `lead`. Closes [#9887](https://github.com/ClickHouse/ClickHouse/issues/9887). [#82108](https://github.com/ClickHouse/ClickHouse/pull/82108) ([Dmitry Novik](https://github.com/novikd)).
* Prise en charge de la colonne virtuelle `_part_granule_offset` dans les tables de la famille MergeTree. Cette colonne indique l&#39;index, à partir de zéro, du granule/repère auquel appartient chaque ligne au sein de sa data part. Cela répond à [#79572](https://github.com/ClickHouse/ClickHouse/issues/79572). [#82341](https://github.com/ClickHouse/ClickHouse/pull/82341) ([Amos Bird](https://github.com/amosbird)).
* Introduction de l&#39;écriture dans Iceberg pour les requêtes `insert`. [#82692](https://github.com/ClickHouse/ClickHouse/pull/82692) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Ajout de SZ3 comme compression codec avec perte, mais à erreur bornée, pour les colonnes de type `Float32` et `Float64`. [#83088](https://github.com/ClickHouse/ClickHouse/pull/83088) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Ajout de la génération SQL assistée par IA au clickhouse client. Les utilisateurs peuvent désormais générer des requêtes SQL à partir de descriptions en langage naturel en préfixant leur requête par &quot;??&quot;. Prise en charge des providers OpenAI et Anthropic avec schema discovery automatique. [#83314](https://github.com/ClickHouse/ClickHouse/pull/83314) ([Kaushik Iska](https://github.com/iskakaushik)).
* Lecture des data files Iceberg par ID de champ. Cela clôt [#83065](https://github.com/ClickHouse/ClickHouse/issues/83065). [#83653](https://github.com/ClickHouse/ClickHouse/pull/83653) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Ajout des fonctions SQL `colorSRGBToOkLCH` et `colorOkLCHToSRGB` pour convertir les couleurs entre les espaces colorimétriques sRGB et OkLCH. [#83679](https://github.com/ClickHouse/ClickHouse/pull/83679) ([Fgrtue](https://github.com/Fgrtue)).
* Rétroporté dans [#84005](https://github.com/ClickHouse/ClickHouse/issues/84005) : la génération SQL assistée par IA peut désormais déduire la configuration à partir des variables d&#39;environnement ANTHROPIC&#95;API&#95;KEY et OPENAI&#95;API&#95;KEY si elles sont disponibles, afin de proposer une option sans configuration pour utiliser cette fonctionnalité. [#83787](https://github.com/ClickHouse/ClickHouse/pull/83787) ([Kaushik Iska](https://github.com/iskakaushik)).



<div id="experimental-feature">
  #### Fonctionnalité expérimentale
</div>

* Ajout des fonctions `searchAny` et `searchAll`, des outils génériques permettant d&#39;interroger les index de texte. [#80641](https://github.com/ClickHouse/ClickHouse/pull/80641) ([Elmi Ahmadov](https://github.com/ahmadov)).
* L&#39;index de texte prend désormais en charge le tokenizer `string`. [#81752](https://github.com/ClickHouse/ClickHouse/pull/81752) ([Elmi Ahmadov](https://github.com/ahmadov)).
* La valeur par défaut de la granularité d&#39;index pour les index `text` a été portée à 64. Cela améliore les performances attendues de la requête de test moyenne dans les benchmarks internes. [#82162](https://github.com/ClickHouse/ClickHouse/pull/82162) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* Le bitmap 256 bits stocke les labels sortants d&#39;un état dans un ordre déterminé, mais les états sortants sont enregistrés sur le disque dans l&#39;ordre où ils apparaissent dans la table de hachage. Par conséquent, un label pouvait pointer vers un état suivant incorrect lors de la lecture depuis le disque. [#82783](https://github.com/ClickHouse/ClickHouse/pull/82783) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Actuellement, l&#39;arbre FST est enregistré sur le disque sans compression. Cela peut entraîner des performances dégradées ou un débit d&#39;E/S plus élevé, aussi bien à l&#39;écriture qu&#39;à la lecture sur le disque. [#83093](https://github.com/ClickHouse/ClickHouse/pull/83093) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Suppression de `searchAny` et `searchAll` en raison d&#39;un bug. Voir [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385). [#83117](https://github.com/ClickHouse/ClickHouse/pull/83117) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Récemment, le fuzzer a détecté un problème dans les fonctions `searchAny` et `searchAll` (voir [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385)). Cette exception se produit lorsque les fonctions `searchAny` ou `searchAll` reçoivent des paramètres d&#39;index de texte différents pour la même colonne. Ce scénario n&#39;est possible que s&#39;il existe deux index de texte différents pour une même colonne. Cette PR limite désormais la définition d&#39;un index de texte à une seule occurrence par colonne, mais une expression enveloppant la colonne (par exemple `lower(column)`) reste autorisée. [#83303](https://github.com/ClickHouse/ClickHouse/pull/83303) ([Elmi Ahmadov](https://github.com/ahmadov)).



<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Optimisation triviale pour le combinateur -If. [#78454](https://github.com/ClickHouse/ClickHouse/pull/78454) ([李扬](https://github.com/taiyang-li)).
* Ajout d&#39;une option permettant de déporter la (dé)compression et la (dé)sérialisation des blocs vers les threads du pipeline au lieu d&#39;un seul thread associé à une connexion réseau. Elle est contrôlée par le paramètre `enable_parallel_blocks_marshalling`. Cela devrait accélérer les requêtes distribuées qui transfèrent des volumes importants de données entre l&#39;initiateur et les nœuds distants. [#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* Les requêtes de recherche vectorielle utilisant un index de similarité vectorielle s&#39;exécutent avec une latence plus faible grâce à la réduction des lectures sur le stockage et de l&#39;utilisation du CPU. [#79103](https://github.com/ClickHouse/ClickHouse/pull/79103) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Prise en compte de `merge_tree_min_{rows,bytes}_for_seek` dans `filterPartsByQueryConditionCache` afin de l&#39;aligner sur les autres méthodes de filtrage par index. [#80312](https://github.com/ClickHouse/ClickHouse/pull/80312) ([李扬](https://github.com/taiyang-li)).
* Le pipeline après l&#39;étape TOTALS devient multithread. [#80331](https://github.com/ClickHouse/ClickHouse/pull/80331) ([UnamedRus](https://github.com/UnamedRus)).
* INSERT SELECT distribué parallèle est activé par défaut dans le mode où INSERT SELECT s&#39;exécute indépendamment sur chaque shard ; voir le paramètre `parallel_distributed_insert_select`. [#80425](https://github.com/ClickHouse/ClickHouse/pull/80425) ([Igor Nikonov](https://github.com/devcrafter)).
* Ajustement de certaines configurations jemalloc pour améliorer les performances. [#81807](https://github.com/ClickHouse/ClickHouse/pull/81807) ([Antonio Andelic](https://github.com/antonio2368)).
* Correction du filtre par clé pour les stockages Redis et KeeperMap. [#81833](https://github.com/ClickHouse/ClickHouse/pull/81833) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Ajout du nouveau paramètre `min_joined_block_size_rows` (analogue à `min_joined_block_size_bytes` ; valeur par défaut : 65409) pour contrôler la taille minimale des blocs (en nombre de lignes) pour les blocs d&#39;entrée et de sortie de JOIN (si l&#39;algorithme de jointure le prend en charge). Les petits blocs seront regroupés. [#81886](https://github.com/ClickHouse/ClickHouse/pull/81886) ([Nikita Taranov](https://github.com/nickitat)).
* Lorsque la requête d&#39;agrégation contient uniquement une fonction `COUNT()` sur une colonne NOT NULL, la logique d&#39;agrégation est entièrement intégrée au sondage de la table de hachage. Cela évite d&#39;allouer et de maintenir un état d&#39;agrégation, ce qui réduit considérablement l&#39;utilisation mémoire et le surcoût CPU. Cela répond partiellement à [#81982](https://github.com/ClickHouse/ClickHouse/issues/81982). [#82104](https://github.com/ClickHouse/ClickHouse/pull/82104) ([Amos Bird](https://github.com/amosbird)).
* Les performances de `HashJoin` ont été optimisées en supprimant la boucle supplémentaire sur les tables de hachage dans le cas typique d&#39;une seule colonne clé ; les vérifications `null_map` et `join_mask` sont également supprimées lorsqu&#39;elles sont systématiquement `true`/`false`. [#82308](https://github.com/ClickHouse/ClickHouse/pull/82308) ([Nikita Taranov](https://github.com/nickitat)).
* `ATTACH PARTITION` n&#39;entraîne plus la suppression de tous les caches. [#82377](https://github.com/ClickHouse/ClickHouse/pull/82377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimisation du plan généré pour les sous-requêtes corrélées en supprimant les opérations JOIN redondantes à l&#39;aide de classes d&#39;équivalence. S&#39;il existe des expressions équivalentes pour toutes les colonnes corrélées, `CROSS JOIN` n&#39;est pas généré si le paramètre `query_plan_correlated_subqueries_use_substitution` est activé. [#82435](https://github.com/ClickHouse/ClickHouse/pull/82435) ([Dmitry Novik](https://github.com/novikd)).
* Lecture uniquement des colonnes requises dans une sous-requête corrélée lorsqu&#39;elle est utilisée comme argument de la fonction `EXISTS`. [#82443](https://github.com/ClickHouse/ClickHouse/pull/82443) ([Dmitry Novik](https://github.com/novikd)).
* Introduction de la journalisation asynchrone. [#82516](https://github.com/ClickHouse/ClickHouse/pull/82516) ([Raúl Marín](https://github.com/Algunenano)).
* Compression des logs et des profile events dans le native protocol. Sur les clusters de plus de 100 répliques, les profile events non compressés représentent 1 à 10 Mo/s, et la barre de progression est lente sur les connexions Internet lentes. Cela corrige [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533). [#82535](https://github.com/ClickHouse/ClickHouse/pull/82535) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Tentative d&#39;accélération de QueryTreeHash. [#82617](https://github.com/ClickHouse/ClickHouse/pull/82617) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Ajout d&#39;un alignement dans le Counter de ProfileEvents afin de réduire le false sharing. [#82697](https://github.com/ClickHouse/ClickHouse/pull/82697) ([Jiebin Sun](https://github.com/jiebinn)).
* L&#39;INSERT SELECT Distributed en parallèle est activé par défaut dans le mode où l&#39;INSERT SELECT est exécuté indépendamment sur chaque shard ; voir le paramètre `parallel_distributed_insert_select`. [#83040](https://github.com/ClickHouse/ClickHouse/pull/83040) ([Igor Nikonov](https://github.com/devcrafter)).
* Les optimisations pour `null_map` et `JoinMask` de [#82308](https://github.com/ClickHouse/ClickHouse/issues/82308) ont été appliquées au cas des JOIN avec plusieurs disjonctions. De plus, la structure de données `KnownRowsHolder` a été optimisée. [#83041](https://github.com/ClickHouse/ClickHouse/pull/83041) ([Nikita Taranov](https://github.com/nickitat)).
* Un simple `std::vector<std::atomic_bool>` est utilisé pour les indicateurs de join afin d&#39;éviter de calculer un hash à chaque accès. [#83043](https://github.com/ClickHouse/ClickHouse/pull/83043) ([Nikita Taranov](https://github.com/nickitat)).
* Ne préallouez pas la mémoire des colonnes de résultat à l&#39;avance lorsque `HashJoin` utilise le mode de sortie `lazy`. C&#39;est sous-optimal, en particulier lorsque le nombre de correspondances est faible. De plus, une fois la jointure terminée, nous connaissons le nombre exact de correspondances, ce qui permet une préallocation plus précise. [#83304](https://github.com/ClickHouse/ClickHouse/pull/83304) ([Nikita Taranov](https://github.com/nickitat)).
* Réduction des copies mémoire dans les headers de port lors de la construction du pipeline. [PR](https://github.com/ClickHouse/ClickHouse/pull/70105) original par [heymind](https://github.com/heymind). [#83381](https://github.com/ClickHouse/ClickHouse/pull/83381) ([Raúl Marín](https://github.com/Algunenano)).
* Amélioration de Keeper pour le initial loading de rocksdb. [#83390](https://github.com/ClickHouse/ClickHouse/pull/83390) ([Antonio Andelic](https://github.com/antonio2368)).
* Évite de conserver le verrou pendant la création des données de snapshot du stockage afin de réduire la contention sur le verrou en cas de charge concurrente élevée. [#83510](https://github.com/ClickHouse/ClickHouse/pull/83510) ([Duc Canh Le](https://github.com/canhld94)).
* Amélioration des performances du input format ProtobufSingle grâce à la réutilisation du sérialiseur lorsqu&#39;aucune parsing error ne se produit. [#83613](https://github.com/ClickHouse/ClickHouse/pull/83613) ([Eduard Karacharov](https://github.com/korowa)).
* Amélioration des performances de construction du pipeline. [#83631](https://github.com/ClickHouse/ClickHouse/pull/83631) ([Raúl Marín](https://github.com/Algunenano)).
* Optimisation de MergeTreeReadersChain::getSampleBlock. [#83875](https://github.com/ClickHouse/ClickHouse/pull/83875) ([Raúl Marín](https://github.com/Algunenano)).

  #### Amélioration

* Introduction de deux nouveaux types d’accès : `READ` et `WRITE` pour les sources, avec dépréciation de tous les types d’accès précédemment liés aux sources. Avant : `GRANT S3 ON *.* TO user` ; désormais : `GRANT READ, WRITE ON S3 TO user`. Cela permet également de dissocier les permissions `READ` et `WRITE` pour les sources, par ex. : `GRANT READ ON * TO user`, `GRANT WRITE ON S3 TO user`. Cette fonctionnalité est contrôlée par le paramètre `access_control_improvements.enable_read_write_grants` et est désactivée par défaut. [#73659](https://github.com/ClickHouse/ClickHouse/pull/73659) ([pufit](https://github.com/pufit)).
* Vérifie que la part possède un fichier checksum.txt cohérent juste avant sa validation. [#76625](https://github.com/ClickHouse/ClickHouse/pull/76625) ([Sema Checherinda](https://github.com/CheSema)).
* Implémentation des méthodes `moveFile` et `replaceFile` dans s3&#95;plain&#95;rewritable pour permettre son utilisation comme disque de base de données. [#79424](https://github.com/ClickHouse/ClickHouse/pull/79424) ([Tuan Pham Anh](https://github.com/tuanpach)).

[#79982](https://github.com/ClickHouse/ClickHouse/pull/79982) ([Nikolay Degterinsky](https://github.com/evillique)).
* Prise en charge des suppressions par position pour le moteur de table Iceberg. [#80237](https://github.com/ClickHouse/ClickHouse/pull/80237) ([YanghongZhong](https://github.com/yahoNanJing)).
* Le paramètre `allow_experimental_join_condition` est désormais marqué comme obsolète. [#80566](https://github.com/ClickHouse/ClickHouse/pull/80566) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Ajout de métriques de pression aux métriques asynchrones de ClickHouse. [#80779](https://github.com/ClickHouse/ClickHouse/pull/80779) ([Xander Garbett](https://github.com/Garbett1)).
* Ajout des métriques `MarkCacheEvictedBytes`, `MarkCacheEvictedMarks`, `MarkCacheEvictedFiles` pour suivre les évictions du cache de marks. (issue [#60989](https://github.com/ClickHouse/ClickHouse/issues/60989)). [#80799](https://github.com/ClickHouse/ClickHouse/pull/80799) ([Shivji Kumar Jha](https://github.com/shiv4289)).
