<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Rétroporté dans [#98752](https://github.com/ClickHouse/ClickHouse/issues/98752) : activation d’async insert par défaut. ClickHouse regroupera désormais par lots toutes les petites insertions par défaut. Ce paramètre se configure via compatibility. Si vous définissez `compatibility=<version less than 26.2>`, la valeur par défaut redeviendra l’ancienne, `false`. Vous pouvez désactiver/activer async inserts à plusieurs niveaux : dans la config, dans les profils utilisateur, pour la session, pour la requête ou pour la table MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#98785](https://github.com/ClickHouse/ClickHouse/issues/98785) : le nouveau paramètre `allow_nullable_tuple_in_extracted_subcolumns` détermine si les sous-colonnes `Tuple(...)` extraites de `Tuple`, `Variant`, `Dynamic` et `JSON` sont renvoyées sous la forme `Nullable(Tuple(...))` (`NULL` pour les lignes manquantes) ou sous la forme `Tuple(...)` (avec les valeurs de tuple par défaut pour les lignes manquantes). Désactivé par défaut, ce paramètre ne peut être modifié qu’en redémarrant le serveur. [#97299](https://github.com/ClickHouse/ClickHouse/pull/97299) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#98481](https://github.com/ClickHouse/ClickHouse/issues/98481) : ajout du paramètre serveur `jemalloc_profiler_sampling_rate` pour contrôler `lg_prof_sample` de jemalloc et l’exposer en tant que Metric asynchrone `jemalloc.prof.lg_sample`. [#97945](https://github.com/ClickHouse/ClickHouse/pull/97945) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#98488](https://github.com/ClickHouse/ClickHouse/issues/98488) : ajout d’un nouvel événement de profile `KeeperRequestTotalWithSubrequests` qui comptabilise individuellement chaque sous-requête au sein d’une requête multiple, offrant une meilleure visibilité sur la charge réelle de Keeper. L’événement existant `KeeperRequestTotal` continue de comptabiliser chaque requête multiple comme une seule request. [#98348](https://github.com/ClickHouse/ClickHouse/pull/98348) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#98749](https://github.com/ClickHouse/ClickHouse/issues/98749) : seules les réplique « vivantes » (c’est-à-dire joignables) participent à l’analyse d’index distribuée. [#98521](https://github.com/ClickHouse/ClickHouse/pull/98521) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#98439](https://github.com/ClickHouse/ClickHouse/issues/98439) : corrige un résultat erroné ou une exception lors de la lecture des sous-colonnes de colonnes ALIAS. [#95408](https://github.com/ClickHouse/ClickHouse/pull/95408) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#98820](https://github.com/ClickHouse/ClickHouse/issues/98820) : corrige l’impossibilité, pour la fonction d’agrégation `sumCount`, de lire d’anciens états sérialisés après l’introduction de `Nullable(Tuple)`. Ferme [#97370](https://github.com/ClickHouse/ClickHouse/issues/97370). [#97502](https://github.com/ClickHouse/ClickHouse/pull/97502) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#98659](https://github.com/ClickHouse/ClickHouse/issues/98659) : impose les vérifications READ ON FILE pour `file()` scalaire et `DESCRIBE TABLE file()`. [#98115](https://github.com/ClickHouse/ClickHouse/pull/98115) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#98563](https://github.com/ClickHouse/ClickHouse/issues/98563) : corrige des résultats erronés avec l’analyse d’index distribuée (fonctionnalité expérimentale) et le cache des conditions de requête. [#98269](https://github.com/ClickHouse/ClickHouse/pull/98269) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#98774](https://github.com/ClickHouse/ClickHouse/issues/98774) : corrige `LOGICAL_ERROR: Not-ready Set is passed as the second argument for function 'in'` lors de l’utilisation de `PREWHERE` avec une sous-requête `IN` sur des tables MergeTree. [#98522](https://github.com/ClickHouse/ClickHouse/pull/98522) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#98651](https://github.com/ClickHouse/ClickHouse/issues/98651) : corrige l’annulation de colonne dans le moteur Buffer lors du traitement d’une exception pendant l’ajout d’un nouveau bloc. L’ancienne logique pouvait entraîner un état en mémoire corrompu des colonnes. [#98551](https://github.com/ClickHouse/ClickHouse/pull/98551) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#98623](https://github.com/ClickHouse/ClickHouse/issues/98623) : corrige l’utilisation de l’index de texte avec d’autres index de saut. Auparavant, des erreurs logiques comme &quot;Trying to get non-existing mark&quot; pouvaient être levées lorsqu’un filtre de requête utilisait simultanément un index de texte et d’autres index de saut classiques. [#98555](https://github.com/ClickHouse/ClickHouse/pull/98555) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#98673](https://github.com/ClickHouse/ClickHouse/issues/98673) : corrige l’analyse d’index distribuée avec des expressions (et pas seulement des colonnes) dans la PK (ce qui entraînait l’absence de filtrage des granules redondants sur les répliques distantes). [#98561](https://github.com/ClickHouse/ClickHouse/pull/98561) ([Azat Khuzhin](https://github.com/azat)).
