<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (comportement erroné visible par l&#39;utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#100217](https://github.com/ClickHouse/ClickHouse/issues/100217) : corrige un crash pouvant survenir lors du déréférencement d&#39;un pointeur nul dans des tables système créées entre le moment où un instantané des tables est pris dans l&#39;appel `IDatabaseTablesIterator::table()` et celui où les tables sont modifiées par un autre thread lors de l&#39;itération suivante. [#98792](https://github.com/ClickHouse/ClickHouse/pull/98792) ([Grant Holly](https://github.com/grantholly-clickhouse)).
* Rétroporté dans [#100855](https://github.com/ClickHouse/ClickHouse/issues/100855) : corrige un heap-use-after-free lorsqu&#39;une table est supprimée de manière concurrente avec une requête de lecture en cours d&#39;exécution (19 occurrences en intégration continue au cours des 90 derniers jours). [#99483](https://github.com/ClickHouse/ClickHouse/pull/99483) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#101472](https://github.com/ClickHouse/ClickHouse/issues/101472) : corrige un bogue dans Keeper où une requête de lecture pouvait rester bloquée (entraînant l&#39;expiration de la session) si une autre session sans lien sur le même serveur était fermée au mauvais moment. [#99484](https://github.com/ClickHouse/ClickHouse/pull/99484) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#101393](https://github.com/ClickHouse/ClickHouse/issues/101393) : corrige l&#39;ignorance de `session_timezone` lors de l&#39;analyse des valeurs `DateTime` pendant les async inserts (TCP) et tous les inserts via HTTP. [#100647](https://github.com/ClickHouse/ClickHouse/pull/100647) ([Sema Checherinda](https://github.com/CheSema)).
* Rétroporté dans [#101960](https://github.com/ClickHouse/ClickHouse/issues/101960) : corrige des résultats erronés lorsqu&#39;un JOIN avec l&#39;optimisation shard-by-PK utilise le query condition cache et que certaines parts sont filtrées par des conditions mises en cache. [#100926](https://github.com/ClickHouse/ClickHouse/pull/100926) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#101642](https://github.com/ClickHouse/ClickHouse/issues/101642) : corrige un comportement indéfini (dépassement d&#39;entier signé) dans parseDateTimeBestEffort lors de l&#39;analyse de chaînes DateTime avec plus de 18 chiffres de seconde fractionnaire. [#100948](https://github.com/ClickHouse/ClickHouse/pull/100948) ([Vasily Chekalkin](https://github.com/bacek)).
* Rétroporté dans [#101362](https://github.com/ClickHouse/ClickHouse/issues/101362) : corrige les fonctions d&#39;agrégation `MAX`/`MIN` sur des colonnes `Decimal` qui renvoyaient des résultats incorrects lorsque la compilation JIT est activée (une fois le seuil de compilation atteint). [#101203](https://github.com/ClickHouse/ClickHouse/pull/101203) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#101371](https://github.com/ClickHouse/ClickHouse/issues/101371) : ... [#101230](https://github.com/ClickHouse/ClickHouse/pull/101230) ([Kseniia Sumarokova](https://github.com/kssenii)).
