<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#108153](https://github.com/ClickHouse/ClickHouse/issues/108153) : amélioration du cache du système de fichiers : empêcher les entrées prioritaires invalidées d&#39;épingler `KeyMetadata`. Fait suite à [https://github.com/ClickHouse/ClickHouse/pull/106387](https://github.com/ClickHouse/ClickHouse/pull/106387). [#107903](https://github.com/ClickHouse/ClickHouse/pull/107903) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#108450](https://github.com/ClickHouse/ClickHouse/issues/108450) : correction d’un nombre de lignes erroné avec `arrayJoin()` utilisé dans `JOIN ON` : le résultat était multiplié une fois de trop par la longueur du tableau. [#104785](https://github.com/ClickHouse/ClickHouse/pull/104785) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Rétroporté dans [#108263](https://github.com/ClickHouse/ClickHouse/issues/108263) : correction de l’erreur &quot;Too many marks&quot; pour un text index sur une merged part vide. [#106867](https://github.com/ClickHouse/ClickHouse/pull/106867) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#107911](https://github.com/ClickHouse/ClickHouse/issues/107911) : correction d’un crash (`Source column is not Map` / `SIGSEGV`) lors de la fusion de blocks triés contenant une colonne `Variant` avec une variante `Map` dont l’ordre de stockage local diffère de l’ordre global. [#107011](https://github.com/ClickHouse/ClickHouse/pull/107011) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#108168](https://github.com/ClickHouse/ClickHouse/issues/108168) : correction d’un possible dépassement de pile du server (crash) lors de la lecture d’un schéma ou d’une valeur profondément imbriqués dans les formats MsgPack, BSON, ORC, Parquet, JSON, DeltaLake, Iceberg et Paimon. Ces entrées fortement imbriquées sont désormais rejetées avec une exception. [#107341](https://github.com/ClickHouse/ClickHouse/pull/107341) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#108226](https://github.com/ClickHouse/ClickHouse/issues/108226) : correction d’un heap buffer overflow (crash du server) dans `windowFunnel` lors de la finalisation d’un état de fonction d’agrégation forgé avec un type d’événement hors plage, exploitable par n’importe quel utilisateur avec un simple `SELECT`. [#107412](https://github.com/ClickHouse/ClickHouse/pull/107412) ([uwezkhan](https://github.com/uwezkhan)).
* Rétroporté dans [#108503](https://github.com/ClickHouse/ClickHouse/issues/108503) : le snapshot reconstruit dans `update()` capture déjà les identifiants actuels du client S3 C++ via `createBuilder` ; il est désormais conservé au lieu d’être ignoré lorsque la version correspond, afin que la prochaine opération du noyau s’exécute sur un engine avec des identifiants fraîchement renouvelés et n’outrepasse pas le TTL STS. [#107480](https://github.com/ClickHouse/ClickHouse/pull/107480) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Rétroporté dans [#108239](https://github.com/ClickHouse/ClickHouse/issues/108239) : ajout des vérifications de limites manquantes lors du parsing d’Elf et de DWARF. [#107579](https://github.com/ClickHouse/ClickHouse/pull/107579) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#108162](https://github.com/ClickHouse/ClickHouse/issues/108162) : la lecture de données Arrow/ArrowStream avec des colonnes `String`/`Binary` vides produites par Apache Arrow Java &lt; 19.0.0 (y compris Apache Spark) ne throws plus `INCORRECT_DATA`. [#107764](https://github.com/ClickHouse/ClickHouse/pull/107764) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#108208](https://github.com/ClickHouse/ClickHouse/issues/108208) : correction d’un set skip index qui n’élaguait pas les granules sur les colonnes LowCardinality. [#107868](https://github.com/ClickHouse/ClickHouse/pull/107868) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#108308](https://github.com/ClickHouse/ClickHouse/issues/108308) : correction d’un crash (SIGSEGV dans les builds de release, assertion d’incompatibilité de type dans les builds de débogage) dans `has` sur un `Map` avec une clé `Dynamic` lorsque l’argument de lookup est `LowCardinality`, par exemple `has(map('a'::Dynamic, ...), toLowCardinality('b'))`. [#107956](https://github.com/ClickHouse/ClickHouse/pull/107956) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#108398](https://github.com/ClickHouse/ClickHouse/issues/108398) : correction d&#39;une régression des performances des sous-colonnes de Map avec PREWHERE. Clôt [#107912](https://github.com/ClickHouse/ClickHouse/issues/107912). Causé par : [https://github.com/ClickHouse/ClickHouse/pull/99200](https://github.com/ClickHouse/ClickHouse/pull/99200). [#107988](https://github.com/ClickHouse/ClickHouse/pull/107988) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#108136](https://github.com/ClickHouse/ClickHouse/issues/108136) : correction d&#39;une régression des performances lors de la lecture de colonnes `Dynamic` avec plusieurs threads. Causé par [https://github.com/ClickHouse/ClickHouse/pull/100730](https://github.com/ClickHouse/ClickHouse/pull/100730). Clôt [#107942](https://github.com/ClickHouse/ClickHouse/issues/107942). [#107997](https://github.com/ClickHouse/ClickHouse/pull/107997) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#108200](https://github.com/ClickHouse/ClickHouse/issues/108200) : exécute toujours les handlers de fin de batch du cache d&#39;accès, même si le batch est vide. [#108124](https://github.com/ClickHouse/ClickHouse/pull/108124) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#108322](https://github.com/ClickHouse/ClickHouse/issues/108322) : correction d&#39;une vue matérialisée actualisable qui restait bloquée si la connexion à ZooKeeper était perdue au mauvais moment. [#108234](https://github.com/ClickHouse/ClickHouse/pull/108234) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#108485](https://github.com/ClickHouse/ClickHouse/issues/108485) : masque les arguments secrets de fonctions telles que `encrypt`, `decrypt` et `HMAC` dans la sortie de `EXPLAIN actions`, `EXPLAIN header` et `EXPLAIN PIPELINE` lorsque `format_display_secrets_in_show_and_select` est désactivé (par défaut). [#108386](https://github.com/ClickHouse/ClickHouse/pull/108386) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#108780](https://github.com/ClickHouse/ClickHouse/issues/108780) : correction de l&#39;identification des utilisateurs `ssl_certificate` afin qu&#39;un unique joker `*` corresponde à exactement un composant de nom (RFC 6125 6.4.3). Auparavant, un joker dans un sujet SAN `CN` ou `DNS:` (par exemple `*.corp.example.com`) correspondait aussi à des noms à plusieurs labels tels que `evil.deep.corp.example.com`, permettant au détenteur d&#39;un certificat pour un sous-domaine plus profond de s&#39;authentifier comme utilisateur joker. La correspondance SAN `URI:` reste inchangée. [#108472](https://github.com/ClickHouse/ClickHouse/pull/108472) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#108697](https://github.com/ClickHouse/ClickHouse/issues/108697) : correction d&#39;une fuite de métadonnées où `DESCRIBE loop('db', 'table')` et `DESCRIBE loop(<inner table function>)` contournaient la vérification d&#39;accès `SHOW COLUMNS` / source, permettant à un utilisateur non privilégié de lire le schéma des colonnes d&#39;une table. [#108624](https://github.com/ClickHouse/ClickHouse/pull/108624) ([Groene AI](https://github.com/groeneai)).
