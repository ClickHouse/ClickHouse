<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Introduction du type `Geometry`. La lecture des formats `WKB` et `WKT` est désormais prise en charge pour ce type. Dans les versions précédentes, le type `Geometry` était un alias de `String`, mais c&#39;est désormais un type pleinement fonctionnel. [#83344](https://github.com/ClickHouse/ClickHouse/pull/83344) ([scanhex12](https://github.com/scanhex12)).
* Suppression du type `Object` obsolète. [#85718](https://github.com/ClickHouse/ClickHouse/pull/85718) ([Pavel Kruglov](https://github.com/Avogar)).
* Échappement des noms de fichiers créés pour les sous-colonnes du type Variant dans les Wide data parts des tables MergeTree. Ce changement rompt la compatibilité avec les anciennes tables utilisant les types de données Variant/Dynamic/JSON. Il corrige le stockage des types contenant des symboles spéciaux dans Variant (par exemple DateTime avec un timezone spécifique contenant `\`). L&#39;échappement peut être désactivé en modifiant le paramètre MergeTree `escape_variant_subcolumn_filenames` (pour conserver la compatibilité, désactivez ce paramètre dans la configuration de MergeTree ou définissez le paramètre `compatibility` sur la version précédente avant la mise à niveau). Résout [#69590](https://github.com/ClickHouse/ClickHouse/issues/69590). [#87300](https://github.com/ClickHouse/ClickHouse/pull/87300) ([Pavel Kruglov](https://github.com/Avogar)).
* Suppression de la fonctionnalité obsolète `LIVE VIEW`. Si vous utilisez `LIVE VIEW`, la mise à niveau vers la nouvelle version ne sera pas possible. [#88706](https://github.com/ClickHouse/ClickHouse/pull/88706) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Prise en charge du balisage des exceptions dans les réponses de résultats HTTP afin de permettre aux clients d&#39;analyser les exceptions de manière plus fiable. Résout [#75175](https://github.com/ClickHouse/ClickHouse/issues/75175). Le paramètre `http_write_exception_in_output_format` est désactivé par défaut afin de garantir la cohérence entre les formats. [#88818](https://github.com/ClickHouse/ClickHouse/pull/88818) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* Interdiction de créer plusieurs disques `plain-rewritable` sur un chemin partagé d&#39;object storage, car cela peut entraîner un comportement indéfini en cas de collision entre différentes transactions de metadata storage. [#89038](https://github.com/ClickHouse/ClickHouse/pull/89038) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Activation par défaut du format de serialization with&#95;size&#95;stream pour le type de données String. Ce changement est rétrocompatible, mais le nouveau format de serialization n&#39;est pris en charge qu&#39;à partir de la version 25.10, ce qui signifie qu&#39;un retour à une version antérieure à 25.10 ne sera pas possible. Si vous souhaitez conserver la possibilité de revenir à la version 25.9 ou à une version antérieure, configurez serialization&#95;info&#95;version sur basic et string&#95;serialization&#95;version sur single&#95;stream dans la section merge&#95;tree de la server configuration. [#89329](https://github.com/ClickHouse/ClickHouse/pull/89329) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Correction de la préséance des paramètres SASL du stockage Kafka. Les paramètres SASL au niveau de la table spécifiés dans les requêtes CREATE TABLE remplacent désormais correctement les paramètres spécifiques au consommateur/producteur provenant des fichiers de configuration. [#89401](https://github.com/ClickHouse/ClickHouse/pull/89401) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Correction de `Fatal` lors de la compression de données dont la taille n&#39;est pas alignée sur celle de l&#39;élément (dans le codec T64). Résout [#89282](https://github.com/ClickHouse/ClickHouse/issues/89282). [#89432](https://github.com/ClickHouse/ClickHouse/pull/89432) ([yanglongwei](https://github.com/ylw510)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Les RIGHT et FULL JOIN utilisent désormais ConcurrentHashJoin ; ces types de jointure s’exécutent donc avec un niveau de parallélisme plus élevé. Améliore jusqu’à 2 fois les performances dans divers cas impliquant RIGHT et FULL JOIN. Résout [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027). [#78462](https://github.com/ClickHouse/ClickHouse/pull/78462) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Optimisation des grandes valeurs dans ConstantNode. Clôt [#72880](https://github.com/ClickHouse/ClickHouse/issues/72880). [#81104](https://github.com/ClickHouse/ClickHouse/pull/81104) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Requêtes `SELECT` jusqu’à 8x plus rapides avec un partition pruning important sur des tables comportant plus de 10K parties. [#85535](https://github.com/ClickHouse/ClickHouse/pull/85535) ([James Morrison](https://github.com/jawm)).
* Correction de vsdo pour aarch64 et, potentiellement, d’autres combinaisons architecture/noyau. [#86096](https://github.com/ClickHouse/ClickHouse/pull/86096) ([Tomas Hulata](https://github.com/tombokombo)).
* Lorsqu’une requête utilise une table de hachage fixe pour l’état d’agrégation (GROUP BY sur un petit entier), ClickHouse fusionne l’état d’agrégation en parallèle afin d’accélérer la requête. Résout [#63666](https://github.com/ClickHouse/ClickHouse/issues/63666). [#87366](https://github.com/ClickHouse/ClickHouse/pull/87366) ([Jianfei Hu](https://github.com/incfly)).
* Exécution Distributed : meilleure répartition des tâches par ID de groupes de lignes plutôt que par fichiers. [#87508](https://github.com/ClickHouse/ClickHouse/pull/87508) ([scanhex12](https://github.com/scanhex12)).
* Amélioration de la vitesse de décompression LZ4 en simplifiant le code et en ajustant l’[algorithme de sélection](https://clickhouse.com/blog/lz4-compression-in-clickhouse#how-to-choose-the-best-algorithm). [#88360](https://github.com/ClickHouse/ClickHouse/pull/88360) ([Raúl Marín](https://github.com/Algunenano)).
* S3 partitionne en interne les objets selon les préfixes des noms de clé et s’adapte automatiquement à des taux de requêtes élevés par partition. Cette modification introduit deux nouveaux paramètres BACKUP : data&#95;file&#95;name&#95;generator et data&#95;file&#95;name&#95;prefix&#95;length. Lorsque data&#95;file&#95;name&#95;generator=checksum, les fichiers de données de sauvegarde sont nommés à l’aide d’un hash de leur contenu. Example : pour un checksum = `abcd1234ef567890abcd1234ef567890` et `data_file_name_prefix_length = 3`, le chemin obtenu sera : `abc/d1234ef567890abcd1234ef567890`. La distribution des clés ainsi obtenue améliore l’équilibrage de charge entre les partitions S3 et réduit le risque de throttling. [#88418](https://github.com/ClickHouse/ClickHouse/pull/88418) ([Julia Kartseva](https://github.com/jkartseva)).
* Implémentation de la réplication lazy des colonnes dans JOIN et ARRAY JOIN. Évite de convertir des représentations spéciales de colonnes, comme Sparse et Replicated, en colonnes complètes dans certains formats de sortie. Cela évite des copies inutiles de données en mémoire. [#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar)).
* Amélioration des performances du text index grâce à la mise en cache des blocs de dictionnaire et à l’utilisation de tables de hachage pour les lookups de jetons au lieu d’une recherche binaire. [#88786](https://github.com/ClickHouse/ClickHouse/pull/88786) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Parquet reader v3 est activé par défaut. [#88827](https://github.com/ClickHouse/ClickHouse/pull/88827) ([Michael Kolupaev](https://github.com/al13n321)).
* Les requêtes peuvent désormais bénéficier simultanément de optimize&#95;read&#95;in&#95;order et de query&#95;plan&#95;optimize&#95;lazy&#95;materialization. Résout [#88767](https://github.com/ClickHouse/ClickHouse/issues/88767). [#88866](https://github.com/ClickHouse/ClickHouse/pull/88866) ([Manuel](https://github.com/raimannma)).
* Utilisation d&#39;une projection d&#39;agrégation pour les requêtes avec `DISTINCT`. Clôt [#86925](https://github.com/ClickHouse/ClickHouse/issues/86925). [#88894](https://github.com/ClickHouse/ClickHouse/pull/88894) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Comme les posting lists sont les plus volumineuses, leur mise en cache améliore les performances lors d&#39;exécutions consécutives. [#88912](https://github.com/ClickHouse/ClickHouse/pull/88912) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Exécute la transformation LIMIT BY en mode streaming lorsque l&#39;ordre de tri en entrée correspond aux clés LIMIT BY. [#88969](https://github.com/ClickHouse/ClickHouse/pull/88969) ([Eduard Karacharov](https://github.com/korowa)).
* Désactive ThreadFuzzer par défaut dans les binaires autres que le serveur. [#89115](https://github.com/ClickHouse/ClickHouse/pull/89115) ([Raúl Marín](https://github.com/Algunenano)).
* Autorise la réécriture de ANY LEFT JOIN ou ANY RIGHT JOIN en ALL INNER JOIN dans certains cas. [#89403](https://github.com/ClickHouse/ClickHouse/pull/89403) ([Dmitry Novik](https://github.com/novikd)).
* Réduit le nombre d&#39;opérations atomiques par entrée lors de la journalisation asynchrone. [#89651](https://github.com/ClickHouse/ClickHouse/pull/89651) ([Sergei Trifonov](https://github.com/serxa)).
* Lorsque les Runtime Filters sont activés dans une requête comportant plusieurs joins et que plusieurs Runtime Filters y sont ajoutés, il faut appliquer le pushdown des nouvelles étapes de filtre ajoutées au-dessus des autres BuildRuntimeFilterStep. [#89725](https://github.com/ClickHouse/ClickHouse/pull/89725) ([Alexander Gololobov](https://github.com/davenger)).
* Accélère légèrement certaines opérations countDistinct en réduisant le surcoût de HashSetTable::merge. [#89727](https://github.com/ClickHouse/ClickHouse/pull/89727) ([Raúl Marín](https://github.com/Algunenano)).
* Les RIGHT et FULL JOIN utilisent désormais ConcurrentHashJoin, ce qui signifie que ces types de join s&#39;exécutent maintenant avec un degré de parallélisme plus élevé. Améliore divers cas pour les RIGHT et FULL JOIN jusqu&#39;à 2 fois. Résout [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027). [#89737](https://github.com/ClickHouse/ClickHouse/pull/89737) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Porte la limite des lignes pour la lazy materialization de 10 à 100. [#89772](https://github.com/ClickHouse/ClickHouse/pull/89772) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
