  ### Version de ClickHouse v24.8.8.17-lts (81036bd118b) FIXME par rapport à v24.8.7.41-lts (e28553d4f2b)
</div>

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#72060](https://github.com/ClickHouse/ClickHouse/issues/72060) : lors de la récupération de données directement depuis un dictionnaire à l’aide du moteur Dictionary, de la fonction de table de dictionnaire ou d’un `SELECT` direct sur le dictionnaire lui-même, il suffit désormais de disposer de la permission `SELECT` ou de la permission `dictGet` sur le dictionnaire. Cela s’inscrit dans la continuité des tentatives précédentes visant à empêcher les contournements d’ACL : [https://github.com/ClickHouse/ClickHouse/pull/57362](https://github.com/ClickHouse/ClickHouse/pull/57362) et [https://github.com/ClickHouse/ClickHouse/pull/65359](https://github.com/ClickHouse/ClickHouse/pull/65359). Cela rend également cette dernière rétrocompatible. [#72051](https://github.com/ClickHouse/ClickHouse/pull/72051) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#71981](https://github.com/ClickHouse/ClickHouse/issues/71981) : après [ce ticket](https://github.com/ClickHouse/ClickHouse/pull/59946#issuecomment-1943653197), il existe en production un certain nombre de répliques de tables dont la valeur du nœud `metadata_version` est à la fois égale à `0` et différente de la version du nœud `metadata` de la table correspondante. Cela provoque l’échec des requêtes `alter` sur ces répliques. [#69274](https://github.com/ClickHouse/ClickHouse/pull/69274) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#72142](https://github.com/ClickHouse/ClickHouse/issues/72142) : acquisition d’un verrou partagé zero-copy avant le déplacement d’une part vers un disque zero-copy afin d’éviter une éventuelle perte de données si Keeper n’est pas disponible. [#71845](https://github.com/ClickHouse/ClickHouse/pull/71845) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#72038](https://github.com/ClickHouse/ClickHouse/issues/72038) : correction d’une exception pour toDayOfWeek sur une condition WHERE avec une clé primaire de type DateTime64. [#71849](https://github.com/ClickHouse/ClickHouse/pull/71849) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Rétroporté dans [#72032](https://github.com/ClickHouse/ClickHouse/issues/72032) : correction de l’erreur `Illegal type` pour les tables `MergeTree` avec une fonction monotone binaire dans `ORDER BY` lorsque le premier argument est constant. Corrige [#71941](https://github.com/ClickHouse/ClickHouse/issues/71941). [#71966](https://github.com/ClickHouse/ClickHouse/pull/71966) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#72155](https://github.com/ClickHouse/ClickHouse/issues/72155) : autoriser uniquement les requêtes SELECT dans EXPLAIN AST utilisé à l’intérieur d’une sous-requête. Les autres types de requêtes entraînent l’erreur logique : &#39;Bad cast from type DB::ASTCreateQuery to DB::ASTSelectWithUnionQuery&#39; ou `Inconsistent AST formatting`. [#71982](https://github.com/ClickHouse/ClickHouse/pull/71982) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#72114](https://github.com/ClickHouse/ClickHouse/issues/72114) : correction de la mise en forme des commandes alter `MOVE PARTITION ... TO TABLE ...` lorsque `format_alter_commands_with_parentheses` est activé. [#72080](https://github.com/ClickHouse/ClickHouse/pull/72080) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
