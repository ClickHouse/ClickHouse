<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#99158](https://github.com/ClickHouse/ClickHouse/issues/99158) : interdit la suppression d’une colonne lorsque ses sous-colonnes sont utilisées dans les expressions par défaut ou d’alias d’autres colonnes, et utilise l’analyseur pour les expressions par défaut lors de `ALTER DROP COLUMN`. [#98569](https://github.com/ClickHouse/ClickHouse/pull/98569) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#100080](https://github.com/ClickHouse/ClickHouse/issues/100080) : corrige la non-prise en compte de TABLE&#95;UUID&#95;MISMATCH en l’absence d’analyseur. [#99380](https://github.com/ClickHouse/ClickHouse/pull/99380) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#100356](https://github.com/ClickHouse/ClickHouse/issues/100356) : corrige un élagage des partitions incorrect pour `toWeek()`, qui faisait que les requêtes avec `WHERE toWeek(date, mode) = N` renvoyaient des résultats vides pour les semaines 49 à 52 sur des tables partitionnées par `toYYYYMM(date)`. [#99542](https://github.com/ClickHouse/ClickHouse/pull/99542) ([Takumi Hara](https://github.com/takumihara)).
* Rétroporté dans [#100168](https://github.com/ClickHouse/ClickHouse/issues/100168) : ... [#100024](https://github.com/ClickHouse/ClickHouse/pull/100024) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Rétroporté dans [#100265](https://github.com/ClickHouse/ClickHouse/issues/100265) : corrige un plantage rare en cas de déclenchement d’une exception &quot;Memory Limit&quot; lors de la construction de l’index de texte intégral. [#100213](https://github.com/ClickHouse/ClickHouse/pull/100213) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#100342](https://github.com/ClickHouse/ClickHouse/issues/100342) : corrige une exception `LOGICAL_ERROR` dans des requêtes impliquant des colonnes `Dynamic`, des jointures croisées et des filtres d’exécution, due au fait que `ColumnVariant::filter` partageait des pointeurs vers des colonnes Variant au lieu de les cloner dans le chemin d’optimisation `hasOnlyNulls`. Ferme [https://github.com/ClickHouse/ClickHouse/pull/100147](https://github.com/ClickHouse/ClickHouse/pull/100147). [#100234](https://github.com/ClickHouse/ClickHouse/pull/100234) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#100594](https://github.com/ClickHouse/ClickHouse/issues/100594) : corrige l’exception LOGICAL&#95;ERROR &quot;Stream ... not found&quot; lors de l’insertion dans une table avec des colonnes imbriquées `Array(JSON)` dans des wide parts avec `optimize_on_insert=0`. [#100475](https://github.com/ClickHouse/ClickHouse/pull/100475) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#100887](https://github.com/ClickHouse/ClickHouse/issues/100887) : valide les chemins des entrées de fichier dans les métadonnées de sauvegarde afin de rejeter les traversées de répertoires, les chemins absolus et les noms vides lors de `RESTORE`. [#100483](https://github.com/ClickHouse/ClickHouse/pull/100483) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#100725](https://github.com/ClickHouse/ClickHouse/issues/100725) : corrige les cas NOT&#95;FOUND&#95;COLUMN&#95;IN&#95;BLOCK où la partie SELECT de la projection contient des colonnes qui n’existent pas dans la partie SELECT d’origine de la requête. Ferme [#100194](https://github.com/ClickHouse/ClickHouse/issues/100194). [#100623](https://github.com/ClickHouse/ClickHouse/pull/100623) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#100918](https://github.com/ClickHouse/ClickHouse/issues/100918) : corrige un plantage du serveur lors de l’utilisation de la fonction `has()` avec PREWHERE/WHERE sur une clé Tuple contenant des éléments LowCardinality. [#100760](https://github.com/ClickHouse/ClickHouse/pull/100760) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#100868](https://github.com/ClickHouse/ClickHouse/issues/100868) : correction des combinateurs de fonctions d’agrégation `If`, `Distinct`, `DistinctIf`, `IfState ` avec un type de retour `Tuple` et un ou plusieurs arguments `Nullable`, qui ne pouvaient plus lire d’anciens états sérialisés après l’introduction de `Nullable(Tuple)`. Clôt [#98917](https://github.com/ClickHouse/ClickHouse/issues/98917). [#100826](https://github.com/ClickHouse/ClickHouse/pull/100826) ([Nihal Z. Miaji](https://github.com/nihalzp)).
