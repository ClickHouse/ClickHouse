<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#101233](https://github.com/ClickHouse/ClickHouse/issues/101233) : correction des requêtes d&#39;`async insert` qui signalaient zéro `written_rows`, `read_rows` et `result_rows` dans `query_log` et dans la sortie du client. [#99879](https://github.com/ClickHouse/ClickHouse/pull/99879) ([Sema Checherinda](https://github.com/CheSema)).
* Rétroporté dans [#100170](https://github.com/ClickHouse/ClickHouse/issues/100170) : ... [#100024](https://github.com/ClickHouse/ClickHouse/pull/100024) ([Shaohua Wang](https://github.com/tiandiwonder)).
* Rétroporté dans [#100920](https://github.com/ClickHouse/ClickHouse/issues/100920) : correction d&#39;un crash du serveur lors de l&#39;utilisation de la fonction `has()` avec PREWHERE/WHERE sur une clé Tuple contenant des éléments LowCardinality. [#100760](https://github.com/ClickHouse/ClickHouse/pull/100760) ([Groene AI](https://github.com/groeneai)).
* Rétroporté dans [#101185](https://github.com/ClickHouse/ClickHouse/issues/101185) : correction d&#39;un segfault dû à un déréférencement de pointeur nul lors du chargement des dictionnaires pendant l&#39;arrêt du serveur. `Context::getUserDefinedSQLObjectsStorage` (déréférence `user_defined_sql_objects_storage`) est appelé par les threads des dictionnaires en concurrence avec le thread principal qui appelle `Context::shutdown` (définit `user_defined_sql_objects_storage` sur null). Nous devons nous assurer de désactiver les futures mises à jour dans le chargeur de dictionnaires, d&#39;arrêter les requêtes de dictionnaire en cours d&#39;exécution et d&#39;attendre la fin des threads de chargement des dictionnaires, le tout avant d&#39;exécuter `Context::shutdown`. Comme pour les requêtes ordinaires. [#100839](https://github.com/ClickHouse/ClickHouse/pull/100839) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#101089](https://github.com/ClickHouse/ClickHouse/issues/101089) : correction d&#39;un débordement de tampon dans `ULIDStringToDateTime` lorsque l&#39;entrée contient des octets non ASCII. [#100843](https://github.com/ClickHouse/ClickHouse/pull/100843) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#101013](https://github.com/ClickHouse/ClickHouse/issues/101013) : correction d&#39;une exception dans `intDiv`/`intDivOrZero` sur des tableaux de tuples Nullable, par ex. `SELECT intDiv([divide((1, 2), ... AND NULL)], 2)`. [#100895](https://github.com/ClickHouse/ClickHouse/pull/100895) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#101248](https://github.com/ClickHouse/ClickHouse/issues/101248) : évaluer les arguments du moteur pour `StorageAlias` avant d&#39;enregistrer la définition, afin que des expressions comme `currentDatabase()` soient résolues en littéraux avant d&#39;être enregistrées dans la base de données. [#100902](https://github.com/ClickHouse/ClickHouse/pull/100902) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#101124](https://github.com/ClickHouse/ClickHouse/issues/101124) : correction d&#39;un crash lors de l&#39;utilisation d&#39;un index de recherche textuelle avec une clause `IN` contenant une sous-requête de tuple, par ex. `WHERE (id, str) IN (SELECT (id, str) FROM ...)`, ou lorsque le nombre de colonnes dans la sous-requête ne correspond pas au tuple à gauche de `IN`. [#100959](https://github.com/ClickHouse/ClickHouse/pull/100959) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#101078](https://github.com/ClickHouse/ClickHouse/issues/101078) : correction de la fonction d&#39;agrégation `sumCountOrDefault` qui, avec un ou plusieurs arguments `Nullable`, ne pouvait pas lire les anciens états sérialisés après l&#39;introduction de `Nullable(Tuple)`. Closes [#100882](https://github.com/ClickHouse/ClickHouse/issues/100882). [#101021](https://github.com/ClickHouse/ClickHouse/pull/101021) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#101346](https://github.com/ClickHouse/ClickHouse/issues/101346) : correction d’un cas pouvant entraîner l’erreur logique `Having zero bytes, ...` provenant du cache, lorsqu’un objet distant est écrasé entre `list` et `read`, ce qui aboutissait auparavant à des métadonnées d’objet obsolètes. [#101219](https://github.com/ClickHouse/ClickHouse/pull/101219) ([Kseniia Sumarokova](https://github.com/kssenii)).
