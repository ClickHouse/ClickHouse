<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Rétroporté dans [#106045](https://github.com/ClickHouse/ClickHouse/issues/106045) : le paramètre `show_data_lake_catalogs_in_system_tables` a été renommé en `show_remote_databases_in_system_tables` et son périmètre a été élargi : lorsque sa valeur est 0 (par défaut), les bases de données `MySQL` et `PostgreSQL` sont elles aussi masquées dans `system.tables`, `system.columns` et `system.completions`, en plus des catalogues de data lake. L&#39;ancien nom du paramètre est conservé comme alias. [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Rétroporté dans [#104562](https://github.com/ClickHouse/ClickHouse/issues/104562) : ajout des requêtes `SYSTEM PAUSE VIEW [db.]name` et `SYSTEM PAUSE VIEWS` pour les vues matérialisées actualisables. Contrairement à `SYSTEM STOP VIEW`, `SYSTEM PAUSE VIEW` n’interrompt pas l’actualisation en cours : l’actualisation déjà lancée est autorisée à aller à son terme, et seules les actualisations suivantes sont empêchées. L’annulation s’effectue avec `SYSTEM START VIEW` ou `SYSTEM START VIEWS`, qui effacent désormais de manière uniforme les états d’arrêt et de pause. [#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#105589](https://github.com/ClickHouse/ClickHouse/issues/105589) : une vue matérialisée actualisable Replicated en mode APPEND ne sera plus actualisée deux fois si la connexion à ZooKeeper est brièvement interrompue lors de l’actualisation. [#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)).
