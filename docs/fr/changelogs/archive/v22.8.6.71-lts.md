  #### Amélioration

[#41330](https://github.com/ClickHouse/ClickHouse/pull/41330) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="bug-fix">

* Rétroporté dans [#41229](https://github.com/ClickHouse/ClickHouse/issues/41229) : corrige des problèmes de sécurité mémoire dans les fonctions `encrypt` et `contingency` lorsqu’un Array de Nullable est utilisé comme argument. Cela corrige [#41004](https://github.com/ClickHouse/ClickHouse/issues/41004). [#40195](https://github.com/ClickHouse/ClickHouse/pull/40195) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogue (dysfonctionnement perceptible par l’utilisateur dans la version stable officielle)
</div>

* Rétroporté dans [#41284](https://github.com/ClickHouse/ClickHouse/issues/41284) : correction des colonnes inconnues inutilisées introduites par l’instruction WITH. Cela corrige [#37812](https://github.com/ClickHouse/ClickHouse/issues/37812). [#39131](https://github.com/ClickHouse/ClickHouse/pull/39131) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#41837](https://github.com/ClickHouse/ClickHouse/issues/41837) : correction de la fusion verticale de parts contenant des lignes supprimées via lightweight delete. [#40559](https://github.com/ClickHouse/ClickHouse/pull/40559) ([Alexander Gololobov](https://github.com/davenger)).
* Rétroporté dans [#41618](https://github.com/ClickHouse/ClickHouse/issues/41618) : correction de possibles segfaults, de use-after-free sur le tas et de fuites de mémoire dans les combinateurs de fonctions d’agrégation. Ferme [#40848](https://github.com/ClickHouse/ClickHouse/issues/40848). [#41083](https://github.com/ClickHouse/ClickHouse/pull/41083) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#41667](https://github.com/ClickHouse/ClickHouse/issues/41667) : les requêtes avec une clause `OFFSET` dans une sous-requête et une clause `WHERE` dans la requête externe pouvaient renvoyer un résultat incorrect ; c’est désormais corrigé. Corrige [#40416](https://github.com/ClickHouse/ClickHouse/issues/40416). [#41280](https://github.com/ClickHouse/ClickHouse/pull/41280) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#41685](https://github.com/ClickHouse/ClickHouse/issues/41685) : correction d’un possible résultat de la requête incorrect lorsque `query_plan_optimize_primary_key` est activé. Corrige [#40599](https://github.com/ClickHouse/ClickHouse/issues/40599). [#41281](https://github.com/ClickHouse/ClickHouse/pull/41281) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41362](https://github.com/ClickHouse/ClickHouse/issues/41362) : correction de l’erreur logique incorrecte `Expected relative path` dans le stockage objet du disque. Lié à [#41246](https://github.com/ClickHouse/ClickHouse/issues/41246). [#41297](https://github.com/ClickHouse/ClickHouse/pull/41297) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#41359](https://github.com/ClickHouse/ClickHouse/issues/41359) : ajout d’une vérification du type de colonne avant l’insertion d’UUID au format MsgPack. [#41309](https://github.com/ClickHouse/ClickHouse/pull/41309) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#41596](https://github.com/ClickHouse/ClickHouse/issues/41596) : correction d’un possible interblocage avec async&#95;socket&#95;for&#95;remote/use&#95;hedged&#95;requests et KILL en parallèle. [#41343](https://github.com/ClickHouse/ClickHouse/pull/41343) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#41521](https://github.com/ClickHouse/ClickHouse/issues/41521) : depuis la version 22.8, la clause `ON CLUSTER` est ignorée si la base de données est `Replicated` et que le nom du cluster est identique à celui de la base de données. De ce fait, `DROP PARTITION ON CLUSTER` se comportait de manière inattendue avec `Replicated`. C’est corrigé : désormais, la clause `ON CLUSTER` n’est ignorée que pour les requêtes répliquées au niveau de la base de données. Corrige [#41299](https://github.com/ClickHouse/ClickHouse/issues/41299). [#41390](https://github.com/ClickHouse/ClickHouse/pull/41390) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#41480](https://github.com/ClickHouse/ClickHouse/issues/41480) : des données malveillantes au format Native pourraient provoquer un crash. [#41441](https://github.com/ClickHouse/ClickHouse/pull/41441) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41806](https://github.com/ClickHouse/ClickHouse/issues/41806) : la fonction d’agrégation `categorialInformationValue` avait des propriétés incorrectement définies, ce qui pouvait provoquer un déréférencement de pointeur NULL à l’exécution. Cela clôt [#41443](https://github.com/ClickHouse/ClickHouse/issues/41443). [#41449](https://github.com/ClickHouse/ClickHouse/pull/41449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41506](https://github.com/ClickHouse/ClickHouse/issues/41506) : l’écriture de données au format Apache `ORC` pouvait entraîner un dépassement de tampon. [#41458](https://github.com/ClickHouse/ClickHouse/pull/41458) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41581](https://github.com/ClickHouse/ClickHouse/issues/41581) : corrige un blocage/interblocage possible lors de l’annulation d’une requête (`KILL QUERY` ou arrêt du serveur). [#41467](https://github.com/ClickHouse/ClickHouse/pull/41467) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#41645](https://github.com/ClickHouse/ClickHouse/issues/41645) : les requêtes avec `ORDER BY` et `1500 <= LIMIT <= max_block_size` pouvaient renvoyer un résultat incorrect avec des lignes manquantes au début. Corrige [#41182](https://github.com/ClickHouse/ClickHouse/issues/41182). [#41576](https://github.com/ClickHouse/ClickHouse/pull/41576) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41642](https://github.com/ClickHouse/ClickHouse/issues/41642) : corrige une possible exception `pipeline stuck` pour les requêtes avec `OFFSET`. L’erreur a été constatée avec `enable_optimize_predicate_expression = 0` et une condition toujours false dans `WHERE`. Corrige [#41383](https://github.com/ClickHouse/ClickHouse/issues/41383). [#41588](https://github.com/ClickHouse/ClickHouse/pull/41588) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41901](https://github.com/ClickHouse/ClickHouse/issues/41901) : corrige un crash possible dans `SELECT` depuis une table `Merge` avec le paramètre `optimize_monotonous_functions_in_order_by` activé. Corrige [#41269](https://github.com/ClickHouse/ClickHouse/issues/41269). [#41740](https://github.com/ClickHouse/ClickHouse/pull/41740) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41836](https://github.com/ClickHouse/ClickHouse/issues/41836) : n’autorise pas la création ou la modification de tables merge tree avec le nom de colonne virtuelle &#95;row&#95;exists, réservé au lightweight delete. Corrige [#41716](https://github.com/ClickHouse/ClickHouse/issues/41716). [#41763](https://github.com/ClickHouse/ClickHouse/pull/41763) ([Jianmei Zhang](https://github.com/zhangjmruc)).
* Rétroporté dans [#41890](https://github.com/ClickHouse/ClickHouse/issues/41890) : les anciennes versions de la base de données Replicated n’ont pas de marqueur spécial dans [Zoo]Keeper. Il faut vérifier uniquement si le nœud contient des données quelconques plutôt qu’un marqueur spécial. [#41875](https://github.com/ClickHouse/ClickHouse/pull/41875) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
