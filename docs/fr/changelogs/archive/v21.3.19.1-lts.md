  # Journal des changements 2022

<div id="clickhouse-release-v213191-lts-fixme-as-compared-to-v213184-lts">
  ### Version de ClickHouse v21.3.19.1-lts FIXME par rapport à v21.3.18.4-lts
</div>

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Rétroporté dans [#31733](https://github.com/ClickHouse/ClickHouse/issues/31733) : améliore les performances des formats de sortie JSON et XML. [#31673](https://github.com/ClickHouse/ClickHouse/pull/31673) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="bug-fix">
  #### Correction de bogue
</div>

* Rétroporté dans [#31577](https://github.com/ClickHouse/ClickHouse/issues/31577) : la limite du quota n’était pas atteinte, alors même qu’elle était dépassée. Cette PR corrige [#31174](https://github.com/ClickHouse/ClickHouse/issues/31174). [#31337](https://github.com/ClickHouse/ClickHouse/pull/31337) ([sunny](https://github.com/sunny19930321)).
* Rétroporté dans [#32347](https://github.com/ClickHouse/ClickHouse/issues/32347) : corrige un bogue lors de la suppression de colonnes inutiles dans une sous-requête. S’il existe une fonction d’agrégation dans une requête sans clause GROUP BY, ne pas la supprimer même si elle est inutile. [#32289](https://github.com/ClickHouse/ClickHouse/pull/32289) ([dongyifeng](https://github.com/dyf6372)).

#### Correction de bogue (comportement incorrect visible par l’utilisateur dans une version stable officielle

* Rétroporté dans [#30913](https://github.com/ClickHouse/ClickHouse/issues/30913) : correction de `ORDER BY ... WITH FILL` lorsque `TO` et `FROM` sont définis et qu’aucune ligne n’est renvoyée dans le jeu de résultats. [#30888](https://github.com/ClickHouse/ClickHouse/pull/30888) ([Anton Popov](https://github.com/CurtizJ)).

<div id="bug-fix-user-visible-misbehaviour-in-official-stable-release">
  #### correction de bogue (comportement incorrect visible par l&#39;utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#30750](https://github.com/ClickHouse/ClickHouse/issues/30750) : les fonctions de recherche insensible à la casse dans les chaînes UTF8, comme `positionCaseInsensitiveUTF8` et `countSubstringsCaseInsensitiveUTF8`, pouvaient trouver des sous-chaînes qui ne correspondaient pas réellement ; c&#39;est corrigé. [#30663](https://github.com/ClickHouse/ClickHouse/pull/30663) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#31038](https://github.com/ClickHouse/ClickHouse/issues/31038) : l&#39;utilisation de la fonction `formatRow` avec des formats autres que des formats de ligne entraînait un segfault. L&#39;utilisation de cette fonction avec de tels formats n&#39;est plus autorisée (car cela n&#39;a pas de sens). [#31001](https://github.com/ClickHouse/ClickHouse/pull/31001) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#31519](https://github.com/ClickHouse/ClickHouse/issues/31519) : suppression de la fonction not like dans RPNElement. [#31169](https://github.com/ClickHouse/ClickHouse/pull/31169) ([sundyli](https://github.com/sundy-li)).
* Rétroporté dans [#31581](https://github.com/ClickHouse/ClickHouse/issues/31581) : * Désactivation de `partial_merge_join_left_table_buffer_bytes` jusqu&#39;à la correction du bogue dans cette optimisation. Voir [#31009](https://github.com/ClickHouse/ClickHouse/issues/31009)). * Suppression de l&#39;option redondante `partial_merge_join_optimizations`. [#31528](https://github.com/ClickHouse/ClickHouse/pull/31528) ([Vladimir C](https://github.com/vdimir)).
* Rétroporté dans [#31792](https://github.com/ClickHouse/ClickHouse/issues/31792) : les paramètres `input_format_allow_errors_num` et `input_format_allow_errors_ratio` ne fonctionnaient pas pour l&#39;analyse des types de domaine, tels que `IPv4` ; c&#39;est corrigé. Corrige [#31686](https://github.com/ClickHouse/ClickHouse/issues/31686). [#31697](https://github.com/ClickHouse/ClickHouse/pull/31697) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#31816](https://github.com/ClickHouse/ClickHouse/issues/31816) : correction d&#39;une condition de concurrence dans le format de sortie JSONEachRowWithProgress lorsque les données et les lignes de progression sont mélangées dans la sortie. [#31736](https://github.com/ClickHouse/ClickHouse/pull/31736) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#31758](https://github.com/ClickHouse/ClickHouse/issues/31758) : correction de l&#39;utilisation du table engine `Buffer` avec le type `Map`. Corrige [#30546](https://github.com/ClickHouse/ClickHouse/issues/30546). [#31742](https://github.com/ClickHouse/ClickHouse/pull/31742) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#32153](https://github.com/ClickHouse/ClickHouse/issues/32153) : correction d&#39;un crash lorsque la fonction `dictGet` avec type est utilisée pour un dictionary attribute dont le type est `Nullable`. Corrige [#30980](https://github.com/ClickHouse/ClickHouse/issues/30980). [#31800](https://github.com/ClickHouse/ClickHouse/pull/31800) ([Maksim Kita](https://github.com/kitaisreal)).
* Rétroporté dans [#31894](https://github.com/ClickHouse/ClickHouse/issues/31894) : correction d&#39;une assertion possible `../src/IO/ReadBuffer.h:58: bool DB::ReadBuffer::next(): Assertion '!hasPendingData()' failed.` dans le format TSKV. [#31804](https://github.com/ClickHouse/ClickHouse/pull/31804) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#32214](https://github.com/ClickHouse/ClickHouse/issues/32214) : le nombre de répliques actives pouvait être déterminé incorrectement lors d&#39;une insertion avec quorum si le paramètre `replicated_can_become_leader` est désactivé sur certaines répliques. C&#39;est corrigé. [#32157](https://github.com/ClickHouse/ClickHouse/pull/32157) ([Alexander Tokmakov](https://github.com/tavplubix)).
