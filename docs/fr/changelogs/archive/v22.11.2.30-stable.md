<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Rétroporté dans [#43488](https://github.com/ClickHouse/ClickHouse/issues/43488) : correction d’une rupture de compatibilité dans la (dé)sérialisation des états des fonctions d’agrégation `min`, `max`, `any*`, `argMin`, `argMax` avec un argument `String`. L’incompatibilité a été introduite dans [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431) et affecte les branches 22.9, 22.10 et 22.11 (corrigée respectivement à partir des versions 22.9.6, 22.10.4 et 22.11.2). Certaines versions mineures des branches 22.3, 22.7 et 22.8 sont également affectées : 22.3.13...22.3.14 (corrigé à partir de 22.3.15), 22.8.6...22.8.9 (corrigé à partir de 22.8.10), 22.7.6 et versions ultérieures (ne sera pas corrigé en 22.7, nous recommandons de passer de 22.7.* à 22.8.10 ou à une version ultérieure). Cette note de version ne concerne pas les utilisateurs qui n’ont jamais utilisé les versions affectées. Les versions incompatibles ajoutent un `'\0'` supplémentaire aux chaînes lors de la lecture des états des fonctions d’agrégation mentionnées ci-dessus. Par exemple, si une ancienne version a enregistré l’état de `anyState('foobar')` dans `state_column`, une version incompatible affichera alors `'foobar\0'` avec `anyMerge(state_column)`. Les versions incompatibles écrivent également les états des fonctions d’agrégation sans `'\0'` final. Les versions plus récentes (qui incluent le correctif) peuvent lire correctement les données écrites par toutes les versions, y compris les versions incompatibles, sauf dans un cas limite. Si une version incompatible a enregistré un état avec une chaîne qui se termine réellement par un caractère nul, une version plus récente supprimera alors le `'\0'` final lors de la lecture de l’état de la fonction d’agrégation affectée. Par exemple, si une version incompatible a enregistré l’état de `anyState('abrac\0dabra\0')` dans `state_column`, les versions incompatibles afficheront alors `'abrac\0dabra'` avec `anyMerge(state_column)`. Le problème affecte également les requêtes distribuées lorsqu’une version incompatible fonctionne dans un cluster avec des versions plus anciennes ou plus récentes. [#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#43511](https://github.com/ClickHouse/ClickHouse/issues/43511) : restriction de l’accès par défaut aux named collections pour l’utilisateur défini dans la config. Celui-ci doit explicitement avoir `show_named_collections=1` pour pouvoir les voir. [#43325](https://github.com/ClickHouse/ClickHouse/pull/43325) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogue (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#43716](https://github.com/ClickHouse/ClickHouse/issues/43716) : un problème avec l’exception suivante a été signalé lors de la tentative de lecture d’un fichier Parquet depuis S3 vers ClickHouse. [#43297](https://github.com/ClickHouse/ClickHouse/pull/43297) ([Arthur Passos](https://github.com/arthurpassos)).
* Rétroporté dans [#43431](https://github.com/ClickHouse/ClickHouse/issues/43431) : correction des requêtes avec `SAMPLE BY` et l’optimisation PREWHERE sur des tables utilisant le moteur `Merge`. [#43315](https://github.com/ClickHouse/ClickHouse/pull/43315) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#43577](https://github.com/ClickHouse/ClickHouse/issues/43577) : correction d’une possible erreur `Cannot create non-empty column with type Nothing` dans les fonctions if/multiIf. Résout [#43356](https://github.com/ClickHouse/ClickHouse/issues/43356). [#43368](https://github.com/ClickHouse/ClickHouse/pull/43368) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#43507](https://github.com/ClickHouse/ClickHouse/issues/43507) : correction d’un bogue lorsque le filtre au niveau des lignes utilise la valeur par défaut d’une colonne. [#43387](https://github.com/ClickHouse/ClickHouse/pull/43387) ([Alexander Gololobov](https://github.com/davenger)).
* Rétroporté dans [#43724](https://github.com/ClickHouse/ClickHouse/issues/43724) : correction de l’analyse de la clé primaire avec des conditions impliquant `toString(enum)`. [#43596](https://github.com/ClickHouse/ClickHouse/pull/43596) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#43807](https://github.com/ClickHouse/ClickHouse/issues/43807) : optimisation du nombre de requêtes List vers ZooKeeper lors de la sélection d’une part à fusionner. Auparavant, cela pouvait produire des milliers de requêtes dans certains cas. Résout [#43647](https://github.com/ClickHouse/ClickHouse/issues/43647). [#43675](https://github.com/ClickHouse/ClickHouse/pull/43675) ([Alexander Tokmakov](https://github.com/tavplubix)).
