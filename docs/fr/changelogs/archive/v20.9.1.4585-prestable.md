<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Ajout de paramètres MergeTree (`max_replicated_merges_with_ttl_in_queue` et `max_number_of_merges_with_ttl_in_pool`) pour contrôler le nombre de fusions avec TTL dans le background pool et la file d’attente de réplication. Ce changement ne rompt la compatibilité avec les anciennes versions que si vous utilisez un TTL de suppression. Sinon, la réplication restera compatible. Vous pouvez éviter les problèmes d’incompatibilité en mettant à jour toutes les répliques du shard en même temps ou en exécutant `SYSTEM STOP TTL MERGES` jusqu’à ce que la mise à jour de toutes les répliques soit terminée. Si vous obtenez une entrée incompatible dans la file d’attente de réplication, commencez par exécuter `SYSTEM STOP TTL MERGES`, puis `ALTER TABLE ... DETACH PARTITION ...` sur la partition à laquelle la fusion TTL incompatible a été affectée. Rattachez-la ensuite sur une seule réplique. [#14490](https://github.com/ClickHouse/ClickHouse/pull/14490) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Ajout de la fonction de table `view`, qui transforme une sous-requête en objet de type table. Cela facilite la transmission des requêtes. Par exemple, elle peut être utilisée dans les fonctions de table remote/cluster. [#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* Il est désormais possible d&#39;écrire `select * apply(length) apply(max) from wide_string_table` pour déterminer la longueur maximale de toutes les colonnes de type String. Les deux variantes suivantes sont également disponibles : [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* Ajout du champ `query_start_time_microseconds` aux tables `system.query_log` et `system.query_thread_log`. [#14252](https://github.com/ClickHouse/ClickHouse/pull/14252) ([Bharat Nallan](https://github.com/bharatnc)).
* Ajout d&#39;une fonction d&#39;agrégation RankCorrelationSpearman, qui calcule simplement un coefficient de corrélation des rangs. Suite de [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769). [#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Ajout de la génération de base de données via l&#39;utilitaire de requêtes. Suite de [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973). [#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Optimisation des requêtes avec LIMIT/LIMIT BY/ORDER BY pour Distributed avec GROUP BY sharding&#95;key (avec optimize&#95;skip&#95;unused&#95;shards et optimize&#95;distributed&#95;group&#95;by&#95;sharding&#95;key). [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Amélioration
</div>

* Améliorations de StorageRabbitMQ : ajout de la gestion des échecs de connexion et de canaux, de commits corrects, de la gestion des échecs d’insertion, d’une meilleure gestion des exchanges, de la durabilité de la file d’attente et de la possibilité de reprendre la file d’attente, ainsi que de nouveaux paramètres de file d’attente. Tests corrigés. [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Ajout de l’autorisation `requirepass` pour Redis. [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* Ajout de l’argument de précision pour le type DateTime. [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* Amélioration des performances du moteur Kafka grâce à un thread indépendant pour chaque consumer. Pool de threads séparé pour les moteurs de streaming (comme Kafka). [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* Ajout du codec de compression par défaut pour les parts dans `system.part_log`, sous le nom `default_compression_codec`. [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* Remplacement des entiers wide de boost multiprecision par l’implémentation de [https://github.com/cerevra/int](https://github.com/cerevra/int). [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* Conversion implicite de la clé primaire en not null dans MaterializeMySQL (comme dans MySQL). Corrige [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114). [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* Ajout du nouveau paramètre system&#95;events&#95;show&#95;zero&#95;values, comme proposé dans [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384). [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* L’obfuscateur prend désormais en charge le type UUID, comme proposé dans [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163). [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Création d’ensembles pour plusieurs `JOIN` et `IN` en parallèle. Cela peut légèrement améliorer les performances des requêtes comportant plusieurs expressions `IN subquery` différentes. [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Les TTL seront désormais appliqués lors de la fusion s’ils n’ont pas été matérialisés auparavant. [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* Le handler MySQL renvoie `OK` pour les requêtes telles que `SET @@var = value`. Cette instruction est ignorée. Cela est nécessaire, car certains drivers MySQL envoient la requête `SET @@` pour la configuration après le handshake [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422 . [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* Accélération du processus d’arrêt du serveur lorsqu’il existe des requêtes S3 en cours. [#14496](https://github.com/ClickHouse/ClickHouse/pull/14496) ([Pavel Kovalenko](https://github.com/Jokser)).
* Interdiction d’un argument time&#95;zone vide dans les fonctions de type `toStartOf*`. [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* Utilisation de std::filesystem::path dans ConfigProcessor pour concaténer les chemins de fichiers. [#14558](https://github.com/ClickHouse/ClickHouse/pull/14558) ([Bharat Nallan](https://github.com/bharatnc)).
