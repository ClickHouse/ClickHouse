<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Nouveau type de données `Object(<schema_format>)`, qui prend en charge le stockage de données semi-structurées (pour l'instant JSON uniquement). Les données sont écrites dans ces types sous forme de chaîne. Tous les chemins sont ensuite extraits selon le format des données semi-structurées et écrits sous forme de colonnes séparées dans les types les plus adaptés pour stocker l'ensemble de leurs valeurs. Ces colonnes peuvent être interrogées par des noms correspondant aux chemins dans les données sources. Par exemple `data.key1.key2` ou avec l'opérateur de cast `data.key1.key2::Int64`. [#23932](https://github.com/ClickHouse/ClickHouse/pull/23932) ([Anton Popov](https://github.com/CurtizJ)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* L&#39;appel à std::distance sur une grande liste dégrade les performances ; utilisez à la place une version dans Node, au prix d&#39;une consommation mémoire plus élevée : 80 MB/1000w Nodes. La logique est la suivante : chaque node de la liste possède une version de type size&#95;t, définie dans la méthode insert ou insertOrReplace à l&#39;aide de la variable membre current&#95;version. La version n&#39;est incrémentée que dans la méthode enableSnapshot. Lors d&#39;un snapshot, appelez snapshotSizeWithVersion pour obtenir la taille du snapshot et la version (snapshot&#95;up&#95;to&#95;version). Lors du parcours de la liste, si la version du node est inférieure ou égale à snapshot&#95;up&#95;to&#95;version, il est alors protégé contre la suppression ; si la version du node est supérieure à snapshot&#95;up&#95;to&#95;version, on peut en faire ce que l&#39;on veut. [#34486](https://github.com/ClickHouse/ClickHouse/pull/34486) ([zhanglistar](https://github.com/zhanglistar)).
* La compaction du magasin de log dans Nuraft doit acquérir un verrou interne, également utilisé par le processus normal de commit ; nous supprimons donc les logs inutiles dans la méthode `compact` de la classe Changelog dans un thread d&#39;arrière-plan. Voir les détails ici : https://github.com/ClickHouse-Extras/NuRaft/blob/1707a7572aa66ec5d0a2dbe2bf5effa3352e6b2d/src/handle&#95;commit.cxx#L560. [#34534](https://github.com/ClickHouse/ClickHouse/pull/34534) ([zhanglistar](https://github.com/zhanglistar)).
* Ne conservez pas le dernier snapshot en mémoire ; lisez-le plutôt si nécessaire. La lecture séquentielle atteint plus de 200 MBps, même sur HDD, en utilisant l&#39;appel système mmap. Écriture directe des données du snapshot sur disk avec la méthode de compression, sans conserver en mémoire ni les données d&#39;origine ni les données compressées. [#34584](https://github.com/ClickHouse/ClickHouse/pull/34584) ([zhanglistar](https://github.com/zhanglistar)).
* MergeTree améliore les performances d&#39;insert en remplaçant std::stable&#95;sort par pdqsort. [#34750](https://github.com/ClickHouse/ClickHouse/pull/34750) ([Maksim Kita](https://github.com/kitaisreal)).
* Améliore les performances de la fonction d&#39;aggregation `ANY` en opérant par batches. [#34760](https://github.com/ClickHouse/ClickHouse/pull/34760) ([Raúl Marín](https://github.com/Algunenano)).
* Améliore les performances des fonctions `detectCharset ` et `detectLanguageUnknown `. Améliore les performances de `DirectDictionary` si la dictionary source est `ClickHouse`. Améliore les performances du traitement des requêtes avec une grande clause `IN`. [#34888](https://github.com/ClickHouse/ClickHouse/pull/34888) ([Maksim Kita](https://github.com/kitaisreal)).
* Réduit le verrouillage sur la connexion en utilisant une statistique atomique. Notez qu&#39;il s&#39;agit d&#39;une statistique approximative. [#35010](https://github.com/ClickHouse/ClickHouse/pull/35010) ([zhanglistar](https://github.com/zhanglistar)).
