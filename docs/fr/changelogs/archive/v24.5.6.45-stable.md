<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#67902](https://github.com/ClickHouse/ClickHouse/issues/67902) : correction de l’erreur `Not-ready Set` après l’optimisation `PREWHERE` pour StorageMerge. [#65057](https://github.com/ClickHouse/ClickHouse/pull/65057) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#68252](https://github.com/ClickHouse/ClickHouse/issues/68252) : correction de `Not-ready Set` dans certaines tables système lors du filtrage à l’aide de sous-requêtes. [#66018](https://github.com/ClickHouse/ClickHouse/pull/66018) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#68064](https://github.com/ClickHouse/ClickHouse/issues/68064) : correction des littéraux booléens dans la requête envoyée à la base de données externe (pour des engines comme `PostgreSQL`). [#66282](https://github.com/ClickHouse/ClickHouse/pull/66282) ([vdimir](https://github.com/vdimir)).
* Rétroporté dans [#68158](https://github.com/ClickHouse/ClickHouse/issues/68158) : correction de cluster() pour le secret inter-serveurs (préserve l’utilisateur initial comme auparavant). [#66364](https://github.com/ClickHouse/ClickHouse/pull/66364) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#68115](https://github.com/ClickHouse/ClickHouse/issues/68115) : correction d’une possible erreur PARAMETER&#95;OUT&#95;OF&#95;BOUND lors de la lecture d’une sous-colonne Variant. [#66659](https://github.com/ClickHouse/ClickHouse/pull/66659) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#67886](https://github.com/ClickHouse/ClickHouse/issues/67886) : analyse correcte du nom de fichier/de l’URI contenant `::` s’il ne s&#39;agit pas d’une archive. [#67433](https://github.com/ClickHouse/ClickHouse/pull/67433) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#68272](https://github.com/ClickHouse/ClickHouse/issues/68272) : correction de l’insertion dans des engines de type stream (Kafka, RabbitMQ, NATS) via l’interface HTTP. [#67554](https://github.com/ClickHouse/ClickHouse/pull/67554) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#67807](https://github.com/ClickHouse/ClickHouse/issues/67807) : correction du rechargement des UDF SQL avec UNION. Auparavant, le redémarrage du serveur pouvait rendre une UDF invalide. [#67665](https://github.com/ClickHouse/ClickHouse/pull/67665) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#67836](https://github.com/ClickHouse/ClickHouse/issues/67836) : correction d’un possible débordement de pile dans la fonction `JSONMergePatch`. Cette fonction a été renommée de `jsonMergePatch` en `JSONMergePatch`, car le nom précédent était incorrect. L’ancien nom est toujours conservé pour des raisons de compatibilité. Amélioration du diagnostic des erreurs dans la fonction. Cela clôt [#67304](https://github.com/ClickHouse/ClickHouse/issues/67304). [#67756](https://github.com/ClickHouse/ClickHouse/pull/67756) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#67991](https://github.com/ClickHouse/ClickHouse/issues/67991) : validation des types de données expérimentaux/suspects dans ALTER ADD/MODIFY COLUMN. [#67911](https://github.com/ClickHouse/ClickHouse/pull/67911) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68207](https://github.com/ClickHouse/ClickHouse/issues/68207) : correction d’un résultat `count()` erroné lorsqu’une fonction non déterministe est présente dans le prédicat. [#67922](https://github.com/ClickHouse/ClickHouse/pull/67922) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#68091](https://github.com/ClickHouse/ClickHouse/issues/68091) : correction du calcul de la limite souple maximale du nombre de threads dans les environnements conteneurisés où le nombre de CPU utilisables est limité. [#67963](https://github.com/ClickHouse/ClickHouse/pull/67963) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#68122](https://github.com/ClickHouse/ClickHouse/issues/68122) : correction du mécanisme d’exclusion des parties non modifiées dans les mutations avec le nouvel analyseur. Auparavant, avec l’analyseur activé, les données d’une partie pouvaient être réécrites par une mutation même si, d’après le prédicat, cette mutation n’affectait pas cette partie. [#68052](https://github.com/ClickHouse/ClickHouse/pull/68052) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68171](https://github.com/ClickHouse/ClickHouse/issues/68171) : supprime une optimisation incorrecte qui retirait le tri dans les sous-requêtes utilisant `OFFSET`. Corrige [#67906](https://github.com/ClickHouse/ClickHouse/issues/67906). [#68099](https://github.com/ClickHouse/ClickHouse/pull/68099) ([Graham Campbell](https://github.com/GrahamCampbell)).
* Rétroporté dans [#68337](https://github.com/ClickHouse/ClickHouse/issues/68337) : tentative de correction d’un crash de Postgres lorsqu’une query est annulée. [#68288](https://github.com/ClickHouse/ClickHouse/pull/68288) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#68667](https://github.com/ClickHouse/ClickHouse/issues/68667) : correction des `LOGICAL_ERROR` lorsque les fonctions `sipHash64Keyed`, `sipHash128Keyed` ou `sipHash128ReferenceKeyed` sont appliquées à des tableaux ou des tuples vides. [#68630](https://github.com/ClickHouse/ClickHouse/pull/68630) ([Robert Schulze](https://github.com/rschu1ze)).
