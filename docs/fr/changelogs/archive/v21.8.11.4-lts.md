<div id="bug-fix-user-visible-misbehaviour-in-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#28756](https://github.com/ClickHouse/ClickHouse/issues/28756) : correction de l’optimisation de l’index NOT-IN lorsque toutes les colonnes clés ne sont pas utilisées. Cela corrige [#28120](https://github.com/ClickHouse/ClickHouse/issues/28120). [#28315](https://github.com/ClickHouse/ClickHouse/pull/28315) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#30825](https://github.com/ClickHouse/ClickHouse/issues/30825) : correction de &quot;Column is not under aggregate function and not in GROUP BY&quot; avec PREWHERE (corrige [#28461](https://github.com/ClickHouse/ClickHouse/issues/28461)). [#28502](https://github.com/ClickHouse/ClickHouse/pull/28502) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#29175](https://github.com/ClickHouse/ClickHouse/issues/29175) : correction des requêtes vers des bases de données externes (p. ex. MySQL) avec plusieurs colonnes dans IN ( p. ex. `(k,v) IN ((1, 2))` ) (mais notez que cela introduit une certaine incompatibilité descendante pour `clickhouse-copier`, car il utilise `alias de` pour l’élément de tuple). [#28888](https://github.com/ClickHouse/ClickHouse/pull/28888) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#30610](https://github.com/ClickHouse/ClickHouse/issues/30610) : correction de mauvaises optimisations de ORDER BY s’il contient WITH FILL. Cela clôt [#28908](https://github.com/ClickHouse/ClickHouse/issues/28908). Cela clôt [#26049](https://github.com/ClickHouse/ClickHouse/issues/26049). [#28910](https://github.com/ClickHouse/ClickHouse/pull/28910) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#30767](https://github.com/ClickHouse/ClickHouse/issues/30767) : correction du blocage des requêtes DDL sur une base de données Replicated lors de l’ajout d’une nouvelle réplique. [#29328](https://github.com/ClickHouse/ClickHouse/pull/29328) ([Kevin Michel](https://github.com/kmichel-aiven)).
* Rétroporté dans [#30205](https://github.com/ClickHouse/ClickHouse/issues/30205) : correction d’une condition de concurrence entre `LogSink::writeMarks()` et `LogSource` dans `StorageLog`. [#29946](https://github.com/ClickHouse/ClickHouse/pull/29946) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#30463](https://github.com/ClickHouse/ClickHouse/issues/30463) : prise en charge des arguments Nullable dans la fonction `initializeAggregation`. [#30177](https://github.com/ClickHouse/ClickHouse/pull/30177) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#30655](https://github.com/ClickHouse/ClickHouse/issues/30655) : correction de la fonction `[I]LIKE`. Clôt [#28661](https://github.com/ClickHouse/ClickHouse/issues/28661). [#30244](https://github.com/ClickHouse/ClickHouse/pull/30244) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#30289](https://github.com/ClickHouse/ClickHouse/issues/30289) : correction de l’analyse de l’option `preallocate` à partir de la configuration du layout pour ComplexKeyHashedDictionary et ComplexKeySparseHashedDictionary. [#30246](https://github.com/ClickHouse/ClickHouse/pull/30246) ([Maksim Kita](https://github.com/kitaisreal)).
* Rétroporté dans [#30525](https://github.com/ClickHouse/ClickHouse/issues/30525) : correction d’un segfault pouvant se produire si la session expirait pendant l’exécution de REPLACE PARTITION. [#30432](https://github.com/ClickHouse/ClickHouse/pull/30432) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Correction de la gestion des exceptions dans `parallel_view_processing`. Cela résout des problèmes et évite des plantages dans de rares cas limites, lorsque cette fonctionnalité est activée et qu’une exception (comme &quot;Memory limit exceeded ...&quot;) se produit au milieu du traitement d’une vue matérialisée. [#30472](https://github.com/ClickHouse/ClickHouse/pull/30472) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#30585](https://github.com/ClickHouse/ClickHouse/issues/30585): * Correction d’un interblocage sur ALTER avec une sous-requête scalaire sur la même table, clôture de [#30461](https://github.com/ClickHouse/ClickHouse/issues/30461). [#30492](https://github.com/ClickHouse/ClickHouse/pull/30492) ([Vladimir C](https://github.com/vdimir)).
* Rétroporté dans [#30607](https://github.com/ClickHouse/ClickHouse/issues/30607): L’optimisation de push down de Limit pouvait provoquer l’erreur `Cannot find column`. Corrige [#30438](https://github.com/ClickHouse/ClickHouse/issues/30438). [#30562](https://github.com/ClickHouse/ClickHouse/pull/30562) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#30753](https://github.com/ClickHouse/ClickHouse/issues/30753): Les fonctions de recherche insensible à la casse dans les chaînes UTF8, comme `positionCaseInsensitiveUTF8` et `countSubstringsCaseInsensitiveUTF8`, pouvaient trouver des sous-chaînes qui ne correspondaient pas réellement ; ce problème est corrigé. [#30663](https://github.com/ClickHouse/ClickHouse/pull/30663) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#30710](https://github.com/ClickHouse/ClickHouse/issues/30710): Correction de PREWHERE avec WHERE dans le cas d’un PREWHERE toujours `true`. [#30668](https://github.com/ClickHouse/ClickHouse/pull/30668) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#30770](https://github.com/ClickHouse/ClickHouse/issues/30770): Correction d’une condition de concurrence entre `REPLACE/MOVE PARTITION` et la fusion en arrière-plan dans `MergeTree` non répliqué, qui pouvait entraîner le maintien dans la partition d’une partie des données déplacées/remplacées. Corrige [#29327](https://github.com/ClickHouse/ClickHouse/issues/29327). [#30717](https://github.com/ClickHouse/ClickHouse/pull/30717) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#30857](https://github.com/ClickHouse/ClickHouse/issues/30857): Correction d’une ambiguïté lors de l’extraction du nom de l’auxiliary ZooKeeper à partir du chemin ZooKeeper dans `ReplicatedMergeTree`. Auparavant, le serveur pouvait ne pas démarrer avec `Unknown auxiliary ZooKeeper name` si le chemin ZooKeeper contenait un deux-points. Corrige [#29052](https://github.com/ClickHouse/ClickHouse/issues/29052). Il était également possible de spécifier un chemin ZooKeeper ne commençant pas par une barre oblique, mais cela est désormais déprécié et la création de nouvelles tables avec un tel chemin n’est plus autorisée. Les barres obliques et les deux-points dans les noms d’auxiliary ZooKeeper ne sont pas autorisés non plus. [#30822](https://github.com/ClickHouse/ClickHouse/pull/30822) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#30925](https://github.com/ClickHouse/ClickHouse/issues/30925): Correction du fait que l’index Set n’était pas utilisé dans les expressions AND/OR lorsqu’il y avait plus de deux opérandes. Corrige [#30416](https://github.com/ClickHouse/ClickHouse/issues/30416). [#30887](https://github.com/ClickHouse/ClickHouse/pull/30887) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#31151](https://github.com/ClickHouse/ClickHouse/issues/31151): Ignorer la vérification max&#95;partition&#95;size&#95;to&#95;drop dans le cas de ATTACH PARTITION ... FROM et MOVE PARTITION ... [#30995](https://github.com/ClickHouse/ClickHouse/pull/30995) ([Amr Alaa](https://github.com/amralaa-MSFT)).
* Rétroporté dans [#31040](https://github.com/ClickHouse/ClickHouse/issues/31040): L’utilisation de la fonction `formatRow` avec des formats autres que les formats de ligne provoquait un segfault. Son utilisation avec de tels formats n’est plus autorisée (car cela n’a pas de sens). [#31001](https://github.com/ClickHouse/ClickHouse/pull/31001) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#31132](https://github.com/ClickHouse/ClickHouse/issues/31132) : correction de JSONValue/Query avec des identifiants entre guillemets. Cela permet d’avoir des espaces dans le chemin JSON. Corrige [#30971](https://github.com/ClickHouse/ClickHouse/issues/30971). [#31003](https://github.com/ClickHouse/ClickHouse/pull/31003) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#31372](https://github.com/ClickHouse/ClickHouse/issues/31372) : correction de StorageMerge avec des alias et WHERE (cela ne fonctionnait auparavant pas du tout). Corrige [#28802](https://github.com/ClickHouse/ClickHouse/issues/28802). [#31044](https://github.com/ClickHouse/ClickHouse/pull/31044) ([Kseniia Sumarokova](https://github.com/kssenii)).
