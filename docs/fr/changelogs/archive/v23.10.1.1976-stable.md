<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Réécriture complète du stockage S3Queue : modification de la façon dont les informations sont conservées dans ZooKeeper, ce qui permet de réduire le nombre de requêtes à ZooKeeper ; ajout de la mise en cache de l’état de ZooKeeper dans les cas où nous savons qu’il ne changera pas ; amélioration du processus de polling depuis S3 pour le rendre moins agressif ; modification de la façon dont le TTL et la valeur max définis pour les fichiers suivis sont gérés, désormais via un processus en arrière-plan. Ajout des tables `system.s3queue` et `system.s3queue_log`. Clôture [#54998](https://github.com/ClickHouse/ClickHouse/issues/54998). [#54422](https://github.com/ClickHouse/ClickHouse/pull/54422) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Il n’existe plus d’option permettant de supprimer automatiquement les data parts corrompues. Cela clôture [#55174](https://github.com/ClickHouse/ClickHouse/issues/55174). [#55184](https://github.com/ClickHouse/ClickHouse/pull/55184) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Les data parts obsolètes en mémoire ne peuvent plus être lues depuis le write-ahead log. Si vous avez configuré des parts en mémoire auparavant, elles doivent être supprimées avant la mise à niveau. [#55186](https://github.com/ClickHouse/ClickHouse/pull/55186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Suppression de l’intégration avec Meilisearch. Raison : elle n’était compatible qu’avec l’ancienne version 0.18. La version récente de Meilisearch a changé le protocole et ne fonctionne plus. Remarque : nous apprécierions votre aide pour la rétablir. [#55189](https://github.com/ClickHouse/ClickHouse/pull/55189) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Renommage du concept de directory monitor en INSERT en arrière-plan. Tous les paramètres `*directory_monitor*` ont été renommés en `distributed_background_insert*`. **La rétrocompatibilité doit être préservée** (puisque les anciens paramètres ont été ajoutés comme alias). [#55978](https://github.com/ClickHouse/ClickHouse/pull/55978) ([Azat Khuzhin](https://github.com/azat)).
* Ne confondez pas send&#95;timeout et receive&#95;timeout. [#56035](https://github.com/ClickHouse/ClickHouse/pull/56035) ([Azat Khuzhin](https://github.com/azat)).
* La comparaison d’intervalles de temps avec des unités différentes déclenchera une exception. Cela clôture [#55942](https://github.com/ClickHouse/ClickHouse/issues/55942). Il est possible que vous vous soyez parfois appuyé sur le comportement précédent, dans lequel les valeurs numériques sous-jacentes étaient comparées indépendamment des unités. [#56090](https://github.com/ClickHouse/ClickHouse/pull/56090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Ajout de la fonction &quot;arrayFold(x1, ..., xn, accum -&gt; expression, array1, ..., arrayn, init&#95;accum)&quot;, qui applique une fonction lambda à plusieurs tableaux de même cardinalité et accumule le résultat dans un accumulateur. [#49794](https://github.com/ClickHouse/ClickHouse/pull/49794) ([Lirikl](https://github.com/Lirikl)).
* Ajout de la fonction d&#39;agrégation lttb, qui utilise l&#39;algorithme [Largest-Triangle-Three-Buckets](https://skemman.is/bitstream/1946/15343/3/SS_MSthesis.pdf) pour sous-échantillonner les données à des fins de visualisation. [#53145](https://github.com/ClickHouse/ClickHouse/pull/53145) ([Sinan](https://github.com/sinsinan)).
* La requête `CHECK TABLE` offre de meilleures performances et une meilleure ergonomie (envoie des mises à jour de progression, peut être annulée). Prise en charge de la vérification d&#39;une part spécifique avec `CHECK TABLE ... PART 'part_name'`. [#53404](https://github.com/ClickHouse/ClickHouse/pull/53404) ([vdimir](https://github.com/vdimir)).
* Ajout de la fonction `jsonMergePatch`. Lors du traitement de données JSON sous forme de chaînes, elle permet de fusionner ces chaînes (d&#39;objets JSON) en une seule chaîne contenant un unique objet JSON. [#54364](https://github.com/ClickHouse/ClickHouse/pull/54364) ([Memo](https://github.com/Joeywzr)).
* Ajout d&#39;une nouvelle fonction SQL, &quot;arrayRandomSample(arr, k)&quot;, qui renvoie un échantillon de k éléments du tableau d&#39;entrée. Une fonctionnalité similaire ne pouvait auparavant être obtenue qu&#39;avec une syntaxe moins pratique, par ex. &quot;SELECT arrayReduce(&#39;groupArraySample(3)&#39;, range(10))&quot;. [#54391](https://github.com/ClickHouse/ClickHouse/pull/54391) ([itayisraelov](https://github.com/itayisraelov)).
* Ajout de la nouvelle fonction `getHttpHeader`, qui permet d&#39;obtenir la valeur d&#39;un en-tête de requête HTTP utilisé pour une requête vers le ClickHouse server. Renvoie une chaîne vide si la requête n&#39;est pas effectuée via le protocole HTTP ou si cet en-tête n&#39;existe pas. [#54813](https://github.com/ClickHouse/ClickHouse/pull/54813) ([凌涛](https://github.com/lingtaolf)).
* Introduction des combinateurs d&#39;agrégation -ArgMin/-ArgMax, qui permettent d&#39;agréger uniquement sur les valeurs min/max. Un cas d&#39;usage est présenté dans [#54818](https://github.com/ClickHouse/ClickHouse/issues/54818). Cette PR réorganise également les combinateurs dans un dossier dédié. [#54947](https://github.com/ClickHouse/ClickHouse/pull/54947) ([Amos Bird](https://github.com/amosbird)).
* Permet de supprimer le cache du format Protobuf avec `SYSTEM DROP SCHEMA FORMAT CACHE [FOR Protobuf]`. [#55064](https://github.com/ClickHouse/ClickHouse/pull/55064) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Ajout d&#39;un authentificateur HTTP externe Basic. [#55199](https://github.com/ClickHouse/ClickHouse/pull/55199) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Ajout de la fonction `byteSwap`, qui inverse les octets des entiers non signés. C&#39;est particulièrement utile pour inverser des valeurs de types représentés en interne sous forme d&#39;entiers non signés, comme IPv4. [#55211](https://github.com/ClickHouse/ClickHouse/pull/55211) ([Priyansh Agrawal](https://github.com/Priyansh121096)).
* Ajout de la fonction `formatQuery()`, qui renvoie une version formatée (éventuellement sur plusieurs lignes) d&#39;une chaîne de requête SQL. Ajout également de la fonction `formatQuerySingleLine()`, qui fait la même chose, mais sans retours à la ligne dans la chaîne renvoyée. [#55239](https://github.com/ClickHouse/ClickHouse/pull/55239) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Ajout du format d&#39;entrée DWARF, qui lit les symboles de Débogage à partir d&#39;un exécutable, d&#39;une bibliothèque ou d&#39;un fichier objet ELF. [#55450](https://github.com/ClickHouse/ClickHouse/pull/55450) ([Michael Kolupaev](https://github.com/al13n321)).
* Permet d’enregistrer les enregistrements non analysés et les erreurs dans les moteurs RabbitMQ, NATS et FileLog. Ajout des colonnes virtuelles `_error` et `_raw_message` (pour NATS et RabbitMQ), ainsi que de `_raw_record` (pour FileLog), qui sont renseignées lorsque ClickHouse ne parvient pas à analyser un nouvel enregistrement. Le comportement est contrôlé par les paramètres de stockage `nats_handle_error_mode` pour NATS, `rabbitmq_handle_error_mode` pour RabbitMQ et `handle_error_mode` pour FileLog, de manière similaire à `kafka_handle_error_mode`. S’il est défini sur `default`, une exception est levée lorsque ClickHouse ne parvient pas à analyser un enregistrement ; s’il est défini sur `stream`, l’erreur et l’enregistrement brut sont enregistrés dans les colonnes virtuelles. Clôt [#36035](https://github.com/ClickHouse/ClickHouse/issues/36035). [#55477](https://github.com/ClickHouse/ClickHouse/pull/55477) ([Kruglov Pavel](https://github.com/Avogar)).
* Amélioration du client Keeper : ajout de la commande get&#95;all&#95;children&#95;number, qui renvoie le nombre total de nœuds enfants sous un chemin donné. [#55485](https://github.com/ClickHouse/ClickHouse/pull/55485) ([guoxiaolong](https://github.com/guoxiaolongzte)).
* Si une table possède une courbe de remplissage de l’espace dans sa clé, par exemple `ORDER BY mortonEncode(x, y)`, les conditions sur ses arguments, par exemple `x >= 10 AND x <= 20 AND y >= 20 AND y <= 30`, peuvent être utilisées pour l’indexation. Un paramètre `analyze_index_with_space_filling_curves` est ajouté pour activer ou désactiver cette analyse. Cela clôt [#41195](https://github.com/ClickHouse/ClickHouse/issues/41195). Suite de [#4538](https://github.com/ClickHouse/ClickHouse/issues/4538). Suite de [#6286](https://github.com/ClickHouse/ClickHouse/issues/6286). Suite de [#28130](https://github.com/ClickHouse/ClickHouse/issues/28130). Suite de [#41753](https://github.com/ClickHouse/ClickHouse/issues/41753). [#55642](https://github.com/ClickHouse/ClickHouse/pull/55642) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout du paramètre `optimize_trivial_approximate_count_query` pour utiliser une approximation de `count()` pour le moteur de stockage EmbeddedRocksDB. Active le comptage trivial pour StorageJoin. [#55806](https://github.com/ClickHouse/ClickHouse/pull/55806) ([Duc Canh Le](https://github.com/canhld94)).
* Amélioration du client Keeper : ajout de la commande get&#95;direct&#95;children&#95;number, qui renvoie le nombre de nœuds enfants directs sous un chemin. [#55898](https://github.com/ClickHouse/ClickHouse/pull/55898) ([xuzifu666](https://github.com/xuzifu666)).
* Ajout de l’instruction `SHOW SETTING setting_name`, qui est une version simplifiée de l’instruction existante `SHOW SETTINGS`. [#55979](https://github.com/ClickHouse/ClickHouse/pull/55979) ([Maksim Kita](https://github.com/kitaisreal)).
* Cette PR permet de transmettre des données au format Npy à ClickHouse. &#96;&#96;&#96; SELECT * FROM file(&#39;example&#95;array.npy&#39;, Npy). [#55982](https://github.com/ClickHouse/ClickHouse/pull/55982) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Cette PR implémente un nouveau paramètre appelé `force_optimize_projection_name` ; il prend un nom de projection comme argument. Si sa valeur est définie sur une chaîne non vide, ClickHouse vérifie que cette projection est utilisée au moins une fois dans la requête. Clôt [#55331](https://github.com/ClickHouse/ClickHouse/issues/55331). [#56134](https://github.com/ClickHouse/ClickHouse/pull/56134) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Ajout de l’option `query_plan_preserve_num_streams_after_window_functions` pour préserver le nombre de flux après l’évaluation des fonctions de fenêtre, afin de permettre un traitement parallèle des flux. [#50771](https://github.com/ClickHouse/ClickHouse/pull/50771) ([frinkr](https://github.com/frinkr)).
* Libère davantage de `num_streams` lorsque les données sont de petite taille. [#53867](https://github.com/ClickHouse/ClickHouse/pull/53867) ([Jiebin Sun](https://github.com/jiebinn)).
* Optimisation des RoaringBitmaps avant leur sérialisation. [#55044](https://github.com/ClickHouse/ClickHouse/pull/55044) ([UnamedRus](https://github.com/UnamedRus)).
* Les posting lists des index inversés sont désormais optimisées pour utiliser la plus petite représentation possible pour les bitmaps internes. Selon le caractère répétitif des données, cela peut réduire significativement l’espace occupé par les index inversés. [#55069](https://github.com/ClickHouse/ClickHouse/pull/55069) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Correction de la contention sur le verrou Context, ce qui améliore significativement les performances pour de nombreuses requêtes concurrentes de courte durée. [#55121](https://github.com/ClickHouse/ClickHouse/pull/55121) ([Maksim Kita](https://github.com/kitaisreal)).
* Amélioration de 30 % des performances de création des index inversés. Cela a été obtenu en remplaçant `std::unordered_map` par `absl::flat_hash_map`. [#55210](https://github.com/ClickHouse/ClickHouse/pull/55210) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Prise en charge du push down des filtres ORC (au niveau des row groups). [#55330](https://github.com/ClickHouse/ClickHouse/pull/55330) ([李扬](https://github.com/taiyang-li)).
* Améliore les performances de l’agrégation externe lorsqu’un grand nombre de fichiers temporaires est utilisé. [#55489](https://github.com/ClickHouse/ClickHouse/pull/55489) ([Maksim Kita](https://github.com/kitaisreal)).
* Définit par défaut une taille raisonnable pour le cache des marks des index secondaires afin d’éviter de recharger sans cesse les marks. [#55654](https://github.com/ClickHouse/ClickHouse/pull/55654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Évite la reconstruction inutile des granules d’index lors de la lecture des skip indexes. Cela corrige [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653)#issuecomment-1763766009 . [#55683](https://github.com/ClickHouse/ClickHouse/pull/55683) ([Amos Bird](https://github.com/amosbird)).
* Met en cache la fonction CAST dans le set pendant l’exécution afin d’améliorer les performances de la fonction `IN` lorsque le type d’élément du set ne correspond pas exactement au type de la colonne. [#55712](https://github.com/ClickHouse/ClickHouse/pull/55712) ([Duc Canh Le](https://github.com/canhld94)).
* Amélioration des performances pour `ColumnVector::insertMany` et `ColumnVector::insertManyFrom`. [#55714](https://github.com/ClickHouse/ClickHouse/pull/55714) ([frinkr](https://github.com/frinkr)).
* ... La récupération de valeurs à partir d’une map est très fréquente. En pratique, les structures de clés sont généralement les mêmes dans une même colonne de map ; il devient donc possible de prédire la position de la clé de la ligne suivante et de réduire le nombre de comparaisons. [#55929](https://github.com/ClickHouse/ClickHouse/pull/55929) ([lgbo](https://github.com/lgbo-ustc)).
* ... Correction d’un problème où l’élagage des champs de struct ne fonctionne pas dans certains cas. Par exemple &#96;&#96;&#96;sql INSERT INTO FUNCTION file(&#39;test&#95;parquet&#95;struct&#39;, Parquet, &#39;x Tuple(a UInt32, b UInt32, c String)&#39;) SELECT tuple(number, rand(), concat(&#39;testxxxxxxx&#39; toString(number))) FROM numbers(10);. [#56117](https://github.com/ClickHouse/ClickHouse/pull/56117) ([lgbo](https://github.com/lgbo-ustc)).
