  ### Version de ClickHouse v24.3.7.30-lts (c8a28cf4331) FIXME par rapport à v24.3.6.48-lts (b2d33c3c45d)
</div>

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#68103](https://github.com/ClickHouse/ClickHouse/issues/68103) : faire la distinction entre les booléens et les entiers lors de l’analyse des valeurs des paramètres personnalisés : `SET custom_a = true; SET custom_b = 1;`. [#62206](https://github.com/ClickHouse/ClickHouse/pull/62206) ([Vitaly Baranov](https://github.com/vitlibar)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#67931](https://github.com/ClickHouse/ClickHouse/issues/67931) : correction de l’erreur `Not-ready Set` après l’optimisation `PREWHERE` pour StorageMerge. [#65057](https://github.com/ClickHouse/ClickHouse/pull/65057) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#68062](https://github.com/ClickHouse/ClickHouse/issues/68062) : correction des littéraux booléens dans la requête envoyée à la base de données externe (pour des engines comme `PostgreSQL`). [#66282](https://github.com/ClickHouse/ClickHouse/pull/66282) ([vdimir](https://github.com/vdimir)).
* Rétroporté dans [#67812](https://github.com/ClickHouse/ClickHouse/issues/67812) : concerne uniquement le type de données Variant expérimental. Correction d’un crash avec le type Variant + AggregateFunction. [#67122](https://github.com/ClickHouse/ClickHouse/pull/67122) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#67848](https://github.com/ClickHouse/ClickHouse/issues/67848) : corrige [#66026](https://github.com/ClickHouse/ClickHouse/issues/66026). Évite le parcours des arguments de fonction de table non résolus dans `ReplaceTableNodeToDummyVisitor`. [#67522](https://github.com/ClickHouse/ClickHouse/pull/67522) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#68271](https://github.com/ClickHouse/ClickHouse/issues/68271) : correction de l’insertion dans des engines de type stream (Kafka, RabbitMQ, NATS) via l’interface HTTP. [#67554](https://github.com/ClickHouse/ClickHouse/pull/67554) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#67806](https://github.com/ClickHouse/ClickHouse/issues/67806) : correction du rechargement des SQL UDFs avec UNION. Auparavant, le redémarrage du serveur pouvait rendre une UDF invalide. [#67665](https://github.com/ClickHouse/ClickHouse/pull/67665) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#67834](https://github.com/ClickHouse/ClickHouse/issues/67834) : correction d’un dépassement de pile potentiel dans la fonction `JSONMergePatch`. Cette fonction a été renommée de `jsonMergePatch` en `JSONMergePatch`, car le nom précédent était erroné. L’ancien nom est toujours conservé pour assurer la compatibilité. Le diagnostic des erreurs dans la fonction a été amélioré. Cela clôt [#67304](https://github.com/ClickHouse/ClickHouse/issues/67304). [#67756](https://github.com/ClickHouse/ClickHouse/pull/67756) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#68206](https://github.com/ClickHouse/ClickHouse/issues/68206) : correction d’un résultat `count()` erroné lorsqu’une fonction non déterministe est présente dans le prédicat. [#67922](https://github.com/ClickHouse/ClickHouse/pull/67922) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#68089](https://github.com/ClickHouse/ClickHouse/issues/68089) : correction du calcul de la limite souple maximale du nombre de threads dans les environnements conteneurisés où le nombre de CPU utilisables est limité. [#67963](https://github.com/ClickHouse/ClickHouse/pull/67963) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#68120](https://github.com/ClickHouse/ClickHouse/issues/68120) : correction du skipping des parts non modifiées dans les mutations avec le nouvel analyseur. Auparavant, avec l’analyseur activé, les données d’une part pouvaient être réécrites par une mutation même si celle-ci n’affectait pas cette part selon le prédicat. [#68052](https://github.com/ClickHouse/ClickHouse/pull/68052) ([Anton Popov](https://github.com/CurtizJ)).
