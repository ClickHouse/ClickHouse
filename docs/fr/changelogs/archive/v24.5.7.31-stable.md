<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement erroné visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#68564](https://github.com/ClickHouse/ClickHouse/issues/68564) : correction d’un cas dans la fonction indexHint découvert par le fuzzer. [#66286](https://github.com/ClickHouse/ClickHouse/pull/66286) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68996](https://github.com/ClickHouse/ClickHouse/issues/68996) : correction de la borne supérieure de la fonction `fromModifiedJulianDay`. Elle devait être `9999-12-31`, mais avait été définie par erreur sur `9999-01-01`. [#67583](https://github.com/ClickHouse/ClickHouse/pull/67583) ([PHO](https://github.com/depressed-pho)).
* Rétroporté dans [#68865](https://github.com/ClickHouse/ClickHouse/issues/68865) : correction d’un crash dans le filtrage Parquet lorsque les types de données du fichier diffèrent sensiblement des types demandés (par ex. `... FROM file('a.parquet', Parquet, 'x String')`, alors que le fichier contient `x Int64`). Sans ce correctif, utilisez `input_format_parquet_filter_push_down = 0` comme solution de contournement. [#68131](https://github.com/ClickHouse/ClickHouse/pull/68131) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#69004](https://github.com/ClickHouse/ClickHouse/issues/69004) : après [https://github.com/ClickHouse/ClickHouse/pull/61984](https://github.com/ClickHouse/ClickHouse/pull/61984), `schema_inference_make_columns_nullable=0` peut toujours rendre des colonnes `Nullable` dans les formats Parquet/Arrow. Ce changement n’était pas rétrocompatible et les utilisateurs ont remarqué cette modification de comportement. Cette PR rétablit le fonctionnement précédent de `schema_inference_make_columns_nullable=0` (aucune colonne `Nullable` ne sera inférée) et introduit la nouvelle valeur `auto` pour ce paramètre, qui rendra les colonnes `Nullable` uniquement si les données contiennent des informations sur la nullabilité. [#68298](https://github.com/ClickHouse/ClickHouse/pull/68298) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68882](https://github.com/ClickHouse/ClickHouse/issues/68882) : corrige [#50868](https://github.com/ClickHouse/ClickHouse/issues/50868). De petites valeurs constantes `DateTime64` renvoyées par une sous-requête imbriquée à l’intérieur d’une requête distribuée étaient transformées à tort en NULL, provoquant ainsi des erreurs et des résultats de requête potentiellement incorrects. [#68323](https://github.com/ClickHouse/ClickHouse/pull/68323) ([Shankar](https://github.com/shiyer7474)).
* Rétroporté dans [#69023](https://github.com/ClickHouse/ClickHouse/issues/69023) : réajout des colonnes virtuelles ` _table` et `_database` aux tables distribuées. Elles étaient disponibles jusqu’à la version 24.3. [#68672](https://github.com/ClickHouse/ClickHouse/pull/68672) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68858](https://github.com/ClickHouse/ClickHouse/issues/68858) : correction d’une erreur possible, `Size of permutation (0) is less than required (...)`, lors de la permutation d’une colonne Variant. [#68681](https://github.com/ClickHouse/ClickHouse/pull/68681) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68784](https://github.com/ClickHouse/ClickHouse/issues/68784) : correction d’un problème avec les clés constantes matérialisées lors du hachage de maps avec des arrays comme clés dans les fonctions `sipHash(64/128)Keyed`. [#68731](https://github.com/ClickHouse/ClickHouse/pull/68731) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Rétroporté dans [#69154](https://github.com/ClickHouse/ClickHouse/issues/69154) : correction d’un résultat potentiellement incorrect lors de la fusion de l’état anyHeavy. [#68950](https://github.com/ClickHouse/ClickHouse/pull/68950) ([Raúl Marín](https://github.com/Algunenano)).
