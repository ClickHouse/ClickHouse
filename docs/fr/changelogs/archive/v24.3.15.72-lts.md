<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#72150](https://github.com/ClickHouse/ClickHouse/issues/72150) : cette PR fait en sorte que `RESTORE ON CLUSTER` attende que chaque table `ReplicatedMergeTree` ne soit plus en readonly avant d’y attacher des parts restaurées. Auparavant, il n’attendait pas et pouvait tenter d’attacher certaines parts presque en même temps qu’il vérifiait les autres répliques pendant le démarrage de la table. Dans de rares cas, certaines parts pouvaient ne pas être attachées du tout pendant `RESTORE ON CLUSTER` à cause de ce problème. [#62207](https://github.com/ClickHouse/ClickHouse/pull/62207) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#72408](https://github.com/ClickHouse/ClickHouse/issues/72408) : les parts dédupliquées pendant la requête `ATTACH PART` ne restent plus bloquées avec le préfixe `attaching_`. [#65636](https://github.com/ClickHouse/ClickHouse/pull/65636) ([Kirill](https://github.com/kirillgarbar)).
* Rétroporté dans [#71979](https://github.com/ClickHouse/ClickHouse/issues/71979) : après [ce problème](https://github.com/ClickHouse/ClickHouse/pull/59946#issuecomment-1943653197), il existe en production un certain nombre de répliques de table dont la valeur du nœud `metadata_version` est à la fois égale à `0` et différente de la version du nœud `metadata` de la table correspondante. Cela entraîne l’échec des requêtes `alter` sur ces répliques. [#69274](https://github.com/ClickHouse/ClickHouse/pull/69274) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#72396](https://github.com/ClickHouse/ClickHouse/issues/72396) : ajout du déséchappement manquant dans les named collections. Sans ce correctif, clickhouse-server ne peut pas démarrer. [#71308](https://github.com/ClickHouse/ClickHouse/pull/71308) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Rétroporté dans [#73354](https://github.com/ClickHouse/ClickHouse/issues/73354) : correction de l’erreur indiquant que la colonne &quot;attgenerated&quot; n’existe pas dans les anciennes versions de PostgreSQL, ce qui corrige [#60651](https://github.com/ClickHouse/ClickHouse/issues/60651). [#71396](https://github.com/ClickHouse/ClickHouse/pull/71396) ([0xMihalich](https://github.com/0xMihalich)).
* Rétroporté dans [#72141](https://github.com/ClickHouse/ClickHouse/issues/72141) : acquisition d’un verrou partagé zero-copy avant de déplacer une part vers un disque zero-copy afin d’éviter une éventuelle perte de données si Keeper n’est pas disponible. [#71845](https://github.com/ClickHouse/ClickHouse/pull/71845) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#72153](https://github.com/ClickHouse/ClickHouse/issues/72153) : autoriser uniquement les requêtes SELECT dans EXPLAIN AST lorsqu’il est utilisé à l’intérieur d’une sous-requête. Les autres types de requêtes entraînent une erreur logique : &#39;Bad cast from type DB::ASTCreateQuery to DB::ASTSelectWithUnionQuery&#39; ou `Inconsistent AST formatting`. [#71982](https://github.com/ClickHouse/ClickHouse/pull/71982) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#74382](https://github.com/ClickHouse/ClickHouse/issues/74382) : éviter une pause après `ALTER TABLE REPLACE/MOVE PARTITION FROM/TO TABLE`. Récupérer les bons paramètres pour la planification des tâches d’arrière-plan. [#72024](https://github.com/ClickHouse/ClickHouse/pull/72024) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#72112](https://github.com/ClickHouse/ClickHouse/issues/72112) : correction de la mise en forme des commandes alter `MOVE PARTITION ... TO TABLE ...` lorsque `format_alter_commands_with_parentheses` est activé. [#72080](https://github.com/ClickHouse/ClickHouse/pull/72080) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#72249](https://github.com/ClickHouse/ClickHouse/issues/72249) : correction d’un bug où `min_age_to_force_merge_on_partition_only` restait bloqué à tenter de fusionner à répétition la même partition, déjà fusionnée en une seule part, sans fusionner les partitions comportant plusieurs parts. [#72209](https://github.com/ClickHouse/ClickHouse/pull/72209) ([Christoph Wurm](https://github.com/cwurm)).
* Rétroporté dans [#72321](https://github.com/ClickHouse/ClickHouse/issues/72321) : correction d’une data race dans `GraceHashJoin`, pouvant entraîner l’absence de certaines lignes dans la sortie du join. [#72233](https://github.com/ClickHouse/ClickHouse/pull/72233) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#72500](https://github.com/ClickHouse/ClickHouse/issues/72500) : correction d’un échec lors de l’analyse des requêtes `BACKUP DATABASE db EXCEPT TABLES db.table`. [#72429](https://github.com/ClickHouse/ClickHouse/pull/72429) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#72977](https://github.com/ClickHouse/ClickHouse/issues/72977) : correction d’un crash potentiel lors d’une restauration de sauvegarde. [#72947](https://github.com/ClickHouse/ClickHouse/pull/72947) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#73153](https://github.com/ClickHouse/ClickHouse/issues/73153) : correction d’un crash dans les transactions avec un moteur de stockage non pris en charge. [#73045](https://github.com/ClickHouse/ClickHouse/pull/73045) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#73122](https://github.com/ClickHouse/ClickHouse/issues/73122) : correction d’une possible surestimation du suivi mémoire (l’écart entre `MemoryTracking` et `MemoryResident` continuait de croître). [#73081](https://github.com/ClickHouse/ClickHouse/pull/73081) ([Azat Khuzhin](https://github.com/azat)).

Auparavant, cela pouvait entraîner l’erreur logique `Invalid number of rows in Chunk` pendant l’analyse. [#73082](https://github.com/ClickHouse/ClickHouse/pull/73082) ([Pavel Kruglov](https://github.com/Avogar)).

[#73535](https://github.com/ClickHouse/ClickHouse/pull/73535) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#73800](https://github.com/ClickHouse/ClickHouse/issues/73800) : correction de l’analyse d’un glob enum suivi d’une plage. Corrige [#73473](https://github.com/ClickHouse/ClickHouse/issues/73473). [#73569](https://github.com/ClickHouse/ClickHouse/pull/73569) ([Konstantin Bogdanov](https://github.com/thevar1able)).
