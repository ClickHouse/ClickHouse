<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogues (comportements incorrects visibles par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#46228](https://github.com/ClickHouse/ClickHouse/issues/46228) : Quelques segfaults ont été signalés autour de `c-ares`. Toutes les stack traces récentes observées échouent lors de l’insertion dans `std::unodered_set<>`. Je pense avoir trouvé la cause racine : il semble qu’il s’agisse de requêtes non traitées. Avant cette PR, CH appelait `poll` pour attendre les descripteurs de fichier du canal `c-ares`. D’après la [documentation de poll](https://man7.org/linux/man-pages/man2/poll.2.html), une valeur de retour négative signifie qu’une erreur s’est produite. Dans ce cas, nous interrompions donc l’exécution et renvoyions un échec. Le problème est que `poll` renvoie également une valeur négative lorsqu’une interruption système se produit. Une interruption système ne signifie pas que le traitement a échoué ou s’est terminé, mais nous l’interrompions malgré tout parce que nous vérifiions simplement si la valeur était négative. Une fois l’exécution interrompue, toute la pile est détruite, y compris le `std::unordered_set<std::string>` transmis au paramètre `void *` du callback c-ares. Une fois la requête terminée par c-ares, le callback était invoqué et accédait à une adresse mémoire invalide, provoquant un segfault. [#45629](https://github.com/ClickHouse/ClickHouse/pull/45629) ([Arthur Passos](https://github.com/arthurpassos)).
* Rétroporté dans [#46967](https://github.com/ClickHouse/ClickHouse/issues/46967) : Rétrocompatibilité : autoriser la conversion implicite restrictive de UInt64 vers IPv4, requise pour l’expression &quot;INSERT ... VALUES ...&quot;. [#45865](https://github.com/ClickHouse/ClickHouse/pull/45865) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Rétroporté dans [#46220](https://github.com/ClickHouse/ClickHouse/issues/46220) : Correction de la lecture de colonnes imbriquées inexistantes sur plusieurs niveaux dans des compact parts. [#46045](https://github.com/ClickHouse/ClickHouse/pull/46045) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#46751](https://github.com/ClickHouse/ClickHouse/issues/46751) : Correctif complémentaire pour le remplacement des types IP de domaine (IPv4, IPv6) par des types natifs [https://github.com/ClickHouse/ClickHouse/pull/43221](https://github.com/ClickHouse/ClickHouse/pull/43221). [#46087](https://github.com/ClickHouse/ClickHouse/pull/46087) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Rétroporté dans [#46448](https://github.com/ClickHouse/ClickHouse/issues/46448) : Correction d’un possible `LOGICAL_ERROR` dans les insertions asynchrones avec des données invalides envoyées au format `VALUES`. [#46350](https://github.com/ClickHouse/ClickHouse/pull/46350) ([Anton Popov](https://github.com/CurtizJ)).

Ceci clôt [#46855](https://github.com/ClickHouse/ClickHouse/issues/46855). [#46856](https://github.com/ClickHouse/ClickHouse/pull/46856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
