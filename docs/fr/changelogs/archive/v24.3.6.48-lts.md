<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#66324](https://github.com/ClickHouse/ClickHouse/issues/66324) : ajout des paramètres manquants `input_format_csv_skip_first_lines/input_format_tsv_skip_first_lines/input_format_csv_try_infer_numbers_from_strings/input_format_csv_try_infer_strings_from_quoted_tuples` dans le cache d’inférence de schéma, car ils peuvent modifier le schéma obtenu. Cela évite des résultats incorrects de l’inférence de schéma lorsque ces paramètres sont modifiés. [#65980](https://github.com/ClickHouse/ClickHouse/pull/65980) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#66151](https://github.com/ClickHouse/ClickHouse/issues/66151) : correction d’un bug de dépassement de tampon dans l’implémentation de `unbin`/`unhex`. [#66106](https://github.com/ClickHouse/ClickHouse/pull/66106) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#66451](https://github.com/ClickHouse/ClickHouse/issues/66451) : correction d’un bug dans le client ZooKeeper : une session pouvait rester bloquée dans un état inutilisable après avoir reçu une erreur matérielle de ZooKeeper. Par exemple, cela pouvait se produire à cause de la &quot;soft memory limit&quot; dans ClickHouse Keeper. [#66140](https://github.com/ClickHouse/ClickHouse/pull/66140) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#66222](https://github.com/ClickHouse/ClickHouse/issues/66222) : correction d’un problème dans SumIfToCountIfVisitor avec les entiers signés. [#66146](https://github.com/ClickHouse/ClickHouse/pull/66146) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#66676](https://github.com/ClickHouse/ClickHouse/issues/66676) : correction de la gestion de la limite pour `system.numbers_mt` lorsqu’aucun index ne peut être utilisé. [#66231](https://github.com/ClickHouse/ClickHouse/pull/66231) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#66602](https://github.com/ClickHouse/ClickHouse/issues/66602) : correction de la façon dont le ClickHouse server détecte le nombre maximal de cœurs CPU utilisables, tel que défini par cgroups v2, lorsqu’il s’exécute dans un conteneur comme Docker. Plus précisément, les conteneurs exécutent souvent leur processus dans le cgroup racine, dont le nom est vide. Dans ce cas, ClickHouse ignorait les limites CPU définies par cgroups v2. [#66237](https://github.com/ClickHouse/ClickHouse/pull/66237) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#66356](https://github.com/ClickHouse/ClickHouse/issues/66356) : correction de l’erreur `Not-ready set` lorsqu’une sous-requête avec `IN` est utilisée dans la contrainte. [#66261](https://github.com/ClickHouse/ClickHouse/pull/66261) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66970](https://github.com/ClickHouse/ClickHouse/issues/66970) : correction de l’erreur `Column identifier is already registered` avec `group_by_use_nulls=true` et le nouvel analyseur. [#66400](https://github.com/ClickHouse/ClickHouse/pull/66400) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66967](https://github.com/ClickHouse/ClickHouse/issues/66967) : correction de l’erreur `Cannot find column` pour les requêtes avec une expression constante dans la clé `GROUP BY` et le nouvel analyseur activé. [#66433](https://github.com/ClickHouse/ClickHouse/pull/66433) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66718](https://github.com/ClickHouse/ClickHouse/issues/66718) : suivi correct de la mémoire pour `Allocator::realloc`. [#66548](https://github.com/ClickHouse/ClickHouse/pull/66548) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#66949](https://github.com/ClickHouse/ClickHouse/issues/66949) : correction d’un résultat incorrect pour les requêtes avec `WINDOW`. Cela pouvait se produire lorsque les colonnes `PARTITION` ont une sérialisation sparse et que les fonctions de fenêtre sont exécutées en parallèle. [#66579](https://github.com/ClickHouse/ClickHouse/pull/66579) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66946](https://github.com/ClickHouse/ClickHouse/issues/66946) : correction de l’erreur `Method getResultType is not supported for QUERY query node` lorsqu’une sous-requête scalaire était utilisée comme premier argument de IN (avec le nouvel analyseur). [#66655](https://github.com/ClickHouse/ClickHouse/pull/66655) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#67629](https://github.com/ClickHouse/ClickHouse/issues/67629) : correction d’un interblocage occasionnel dans Context::getDDLWorker. [#66843](https://github.com/ClickHouse/ClickHouse/pull/66843) ([Alexander Gololobov](https://github.com/davenger)).
* Rétroporté dans [#67193](https://github.com/ClickHouse/ClickHouse/issues/67193) : TRUNCATE DATABASE arrêtait la réplication comme s’il s’agissait d’une requête DROP DATABASE ; c’est corrigé. [#67129](https://github.com/ClickHouse/ClickHouse/pull/67129) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#67375](https://github.com/ClickHouse/ClickHouse/issues/67375) : correction de l’erreur `Cannot convert column because it is non constant in source stream but must be constant in result.` pour une requête qui lit depuis la table `Merge` au-dessus de la table `Distriburted` avec un seul shard. [#67146](https://github.com/ClickHouse/ClickHouse/pull/67146) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#67572](https://github.com/ClickHouse/ClickHouse/issues/67572) : correction de l’exécution des fonctions imbriquées avec évaluation en court-circuit. [#67520](https://github.com/ClickHouse/ClickHouse/pull/67520) ([Kruglov Pavel](https://github.com/Avogar)).
