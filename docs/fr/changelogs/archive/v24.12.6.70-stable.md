<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Rétroporté dans [#76694](https://github.com/ClickHouse/ClickHouse/issues/76694) : correction d’une contention inutile dans `parallel_hash` lorsque `max_rows_in_join = max_bytes_in_join = 0`. [#75155](https://github.com/ClickHouse/ClickHouse/pull/75155) ([Nikita Taranov](https://github.com/nickitat)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#76428](https://github.com/ClickHouse/ClickHouse/issues/76428) : correction de certains problèmes d’ergonomie de clickhouse-disks signalés par les utilisateurs. Clôt [#67136](https://github.com/ClickHouse/ClickHouse/issues/67136). [#73616](https://github.com/ClickHouse/ClickHouse/pull/73616) ([Daniil Ivanik](https://github.com/divanik)).
* Rétroporté dans [#76862](https://github.com/ClickHouse/ClickHouse/issues/76862) : ajout de la possibilité de recharger `max_remote_read_network_bandwidth_for_serve` et `max_remote_write_network_bandwidth_for_server` à chaud, sans redémarrer le serveur. [#74206](https://github.com/ClickHouse/ClickHouse/pull/74206) ([Kai Zhu](https://github.com/nauu)).
* Rétroporté dans [#76451](https://github.com/ClickHouse/ClickHouse/issues/76451) : permet d’analyser des points de terminaison comme `localhost:1234/handle` dans les fonctions de table `postgresql` ou `mysql`. Cela corrige une régression introduite dans [https://github.com/ClickHouse/ClickHouse/pull/52503](https://github.com/ClickHouse/ClickHouse/pull/52503). [#75944](https://github.com/ClickHouse/ClickHouse/pull/75944) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#76652](https://github.com/ClickHouse/ClickHouse/issues/76652) : ajout d’un paramètre du serveur `throw_on_unknown_workload` qui permet de choisir le comportement d’une query dont le paramètre `workload` est défini sur une valeur inconnue : soit autoriser un accès illimité (par défaut), soit renvoyer une error `RESOURCE_ACCESS_DENIED`. Cela est utile pour forcer toutes les queries à utiliser la planification des charges de travail. [#75999](https://github.com/ClickHouse/ClickHouse/pull/75999) ([Sergei Trifonov](https://github.com/serxa)).
* Rétroporté dans [#76671](https://github.com/ClickHouse/ClickHouse/issues/76671) : utilisation du mécanisme de repli approprié lorsqu’une copie multipartie vers S3 échoue pendant une sauvegarde avec Access Denied. Une copie multipartie peut générer une erreur Access Denied lorsque la sauvegarde est effectuée entre des buckets qui utilisent des identifiants d’authentification différents. [#76515](https://github.com/ClickHouse/ClickHouse/pull/76515) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#77200](https://github.com/ClickHouse/ClickHouse/issues/77200) : auparavant, la base de données replicated pouvait afficher dans les logs les identifiants d’authentification spécifiés dans une query. Ce comportement a été corrigé. Cela clôt [#77123](https://github.com/ClickHouse/ClickHouse/issues/77123). [#77133](https://github.com/ClickHouse/ClickHouse/pull/77133) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

* Rétroporté dans [#76856](https://github.com/ClickHouse/ClickHouse/issues/76856) : vider les tampons d&#39;écriture de sortie avant leur finalisation.
