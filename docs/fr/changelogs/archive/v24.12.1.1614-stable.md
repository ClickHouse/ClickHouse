<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Les fonctions `greatest` et `least` ignorent désormais les valeurs d’entrée NULL, alors qu’auparavant elles renvoyaient NULL si l’un des arguments était NULL. Par exemple, `SELECT greatest(1, 2, NULL)` renvoie désormais 2. Ce comportement est ainsi compatible avec PostgreSQL. [#65519](https://github.com/ClickHouse/ClickHouse/pull/65519) ([kevinyhzou](https://github.com/KevinyhZou)).
* L’intégration MongoDB legacy basée sur le driver Poco a été supprimée. Le paramètre serveur `use_legacy_mongodb_integration` est obsolète et n’a plus aucun effet. [#71997](https://github.com/ClickHouse/ClickHouse/pull/71997) ([Kirill Nikiforov](https://github.com/allmazz)).

  #### Nouvelle fonctionnalité

* Ajout d'une requête permettant d'attacher des tables MergeTree en tant que ReplicatedMergeTree et vice versa. [#65401](https://github.com/ClickHouse/ClickHouse/pull/65401) ([Kirill](https://github.com/kirillgarbar)).
* Implémentation de la commande SYSTEM LOAD PRIMARY KEY pour charger les index primaires de toutes les parties d'une table spécifiée, ou de toutes les tables si aucune table n'est précisée. Utile pour les benchmarks et pour éviter une latence supplémentaire lors de l'exécution des requêtes. [#66252](https://github.com/ClickHouse/ClickHouse/pull/66252) ([ZAWA_ll](https://github.com/Zawa-ll)).
* Ajout de l'instruction `SYSTEM LOAD PRIMARY KEY` pour charger les index primaires de toutes les parties d'une table spécifiée, ou de toutes les tables si aucune table n'est précisée. Peut être utile pour le benchmarking et pour éviter une latence supplémentaire lors de l'exécution des requêtes. [#67733](https://github.com/ClickHouse/ClickHouse/pull/67733) ([ZAWA_ll](https://github.com/Zawa-ll)).
* [Le format de stockage de données Iceberg](https://iceberg.apache.org/spec/#file-system-operations) offre à l'utilisateur de nombreuses options pour modifier le schéma de sa table. Cette pull request implémente la lecture d'une table au format Iceberg dont l'ordre des colonnes, les noms de colonnes et les extensions de types simples ont été modifiés. [#69445](https://github.com/ClickHouse/ClickHouse/pull/69445) ([Daniil Ivanik](https://github.com/divanik)).
* Ajout de la fonction `toUnixTimestamp64Second` qui convertit un `DateTime64` en valeur `Int64` avec une précision fixe à la seconde, permettant ainsi de retourner des valeurs négatives pour les dates antérieures au 1er janvier 1970 à 00:00:00 UTC. [#70597](https://github.com/ClickHouse/ClickHouse/pull/70597) ([zhanglistar](https://github.com/zhanglistar)).
* Ajout du paramètre `enforce_index_structure_match_on_partition_manipulation` pour autoriser l'attachement lorsque les projections et les index secondaires de la table source constituent un sous-ensemble de ceux de la table cible. Ferme [#70602](https://github.com/ClickHouse/ClickHouse/issues/70602). [#70603](https://github.com/ClickHouse/ClickHouse/pull/70603) ([zwy991114](https://github.com/zwy991114)).
* La sortie de la fonction `cast` diffère de celle d'Apache Spark, ce qui entraîne des divergences dans le projet gluten (voir https://github.com/apache/incubator-gluten/issues/7602). Cette PR ajoute la prise en charge du format de sortie texte de Spark, désactivée par défaut. [#70957](https://github.com/ClickHouse/ClickHouse/pull/70957) ([zhanglistar](https://github.com/zhanglistar)).
* Cette PR introduit un nouveau paramètre `allow_experimental_reverse_key` qui active la prise en charge de l'ordre de tri décroissant dans les clés de tri MergeTree. Utile pour l'analyse de séries temporelles, notamment pour les requêtes TopN. Exemple d'utilisation : ```sql CREATE TABLE example ( time DateTime, key Int32, value String ) ENGINE = MergeTree ORDER BY (time DESC, key); -- Ordre décroissant pour le champ 'time' SETTINGS allow_experimental_reverse_key = 1;. [#71095](https://github.com/ClickHouse/ClickHouse/pull/71095) ([Amos Bird](https://github.com/amosbird)).
* Intégration avec Iceberg REST Catalog. [#71542](https://github.com/ClickHouse/ClickHouse/pull/71542) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Ajout d'une option permettant de sélectionner le côté du join qui jouera le rôle de table interne (build) dans le plan de requête. Ce comportement est contrôlé par `query_plan_join_swap_table`, qui peut être défini sur `auto`. Dans ce mode, ClickHouse tente de choisir la table ayant le plus petit nombre de lignes. [#71577](https://github.com/ClickHouse/ClickHouse/pull/71577) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Ajout de la syntaxe ALTER USER {ADD|MODIFY|DROP SETTING}, ALTER USER {ADD|DROP PROFILE}, ainsi que les équivalents pour ALTER ROLE et ALTER PROFILE. [#72050](https://github.com/ClickHouse/ClickHouse/pull/72050) ([pufit](https://github.com/pufit)).
* Ajout de la fonction `arrayPrAUC`, qui calcule l'AUC (aire sous la courbe) pour la courbe Precision-Recall. [#72073](https://github.com/ClickHouse/ClickHouse/pull/72073) ([Emmanuel](https://github.com/emmanuelsdias)).
* Ajout d'un cache pour l'index primaire des tables `MergeTree` (activable via le paramètre de table `use_primary_key_cache`). Si le chargement différé et le cache sont activés pour l'index primaire, celui-ci sera chargé dans le cache à la demande (à l'instar du cache de marks) plutôt que d'être conservé indéfiniment en mémoire. Ajout du préchauffage de l'index primaire lors des insertions, fusions et récupérations de parties de données, ainsi qu'au redémarrage de la table (activable via le paramètre `prewarm_primary_key_cache`). [#72102](https://github.com/ClickHouse/ClickHouse/pull/72102) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#73593](https://github.com/ClickHouse/ClickHouse/issues/73593) : les instructions `SELECT` et `VIEW` prennent désormais en charge les alias, par exemple `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);`. Cela permet d'exécuter la requête TPC-H 15 sans modification. [#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout de la fonction `indexOfAssumeSorted` pour les types de tableaux. Optimise la recherche dans le cas d'un tableau trié en ordre non décroissant. [#72517](https://github.com/ClickHouse/ClickHouse/pull/72517) ([Eric Kurbanov](https://github.com/erickurbanov)).
* Possibilité d'utiliser un délimiteur comme second argument optionnel pour la fonction d'agrégation `groupConcat`. [#72540](https://github.com/ClickHouse/ClickHouse/pull/72540) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout du paramètre `http_response_headers` permettant de personnaliser les en-têtes de réponse HTTP. Par exemple, il est possible d'indiquer au navigateur d'afficher une image stockée dans la base de données. Ferme [#59620](https://github.com/ClickHouse/ClickHouse/issues/59620). [#72656](https://github.com/ClickHouse/ClickHouse/pull/72656) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout de la fonction `fromUnixTimestamp64Second` qui convertit une valeur de timestamp Unix Int64 en DateTime64. [#73146](https://github.com/ClickHouse/ClickHouse/pull/73146) ([Robert Schulze](https://github.com/rschu1ze)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* La consommation mémoire de `clickhouse disks remove --recursive` est réduite pour les disques de stockage objet. [#67323](https://github.com/ClickHouse/ClickHouse/pull/67323) ([Kirill](https://github.com/kirillgarbar)).
* Activation de la compilation JIT pour davantage d'expressions : abs/bitCount/sign/modulo/pmod/isNull/isNotNull/assumeNotNull/to(U)Int*/toFloat*, fonctions de comparaison (=, <, >, >=, <=), fonctions logiques (and, or). [#70598](https://github.com/ClickHouse/ClickHouse/pull/70598) ([李扬](https://github.com/taiyang-li)).
* Désormais, l'algorithme `parallel_hash` sera utilisé (si applicable) lorsque le paramètre `join_algorithm` est défini sur `default`. Les deux alternatives précédentes (`direct` et `hash`) restent prises en compte lorsque `parallel_hash` ne peut pas être utilisé. [#70788](https://github.com/ClickHouse/ClickHouse/pull/70788) ([Nikita Taranov](https://github.com/nickitat)).
* Ajout d'une option permettant d'extraire les expressions communes des clauses `WHERE` et `ON` afin de réduire le nombre de tables de hachage utilisées lors des jointures. Peut être activée via `optimize_extract_common_expressions = 1`. [#71537](https://github.com/ClickHouse/ClickHouse/pull/71537) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Permet l'utilisation des index sur `SELECT` avec `LowCardinality(String)`. [#71598](https://github.com/ClickHouse/ClickHouse/pull/71598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Lors de l'exécution d'une requête avec des répliques parallèles et un plan local activé, l'analyse d'index est ignorée sur les workers. Le coordinateur sélectionne les plages à lire pour les workers en se basant sur l'analyse d'index effectuée de son côté (sur l'initiateur de la requête). [#72109](https://github.com/ClickHouse/ClickHouse/pull/72109) ([Igor Nikonov](https://github.com/devcrafter)).
* Restauration de l'optimisation pour la lecture des sous-colonnes d'une colonne unique dans les parties compactes, issue de https://github.com/ClickHouse/ClickHouse/pull/57631. Elle avait été supprimée accidentellement. [#72285](https://github.com/ClickHouse/ClickHouse/pull/72285) ([Pavel Kruglov](https://github.com/Avogar)).
* Accélération du tri des colonnes `LowCardinality(String)` par dévirtualisation des appels dans le comparateur. [#72337](https://github.com/ClickHouse/ClickHouse/pull/72337) ([Alexander Gololobov](https://github.com/davenger)).
* Optimisation de la fonction argMin/Max pour certains types de données simples. [#72350](https://github.com/ClickHouse/ClickHouse/pull/72350) ([alesapin](https://github.com/alesapin)).
* Optimisation du verrouillage avec des verrous partagés dans le memory tracker afin de réduire la contention de verrous. [#72375](https://github.com/ClickHouse/ClickHouse/pull/72375) ([Jiebin Sun](https://github.com/jiebinn)).
* Ajout d'un nouveau paramètre, `use_async_executor_for_materialized_views`. Utilise une exécution asynchrone et potentiellement multithread des requêtes de vue matérialisée, ce qui peut accélérer le traitement des vues lors d'un INSERT, mais entraîne également une consommation mémoire plus élevée. [#72497](https://github.com/ClickHouse/ClickHouse/pull/72497) ([alesapin](https://github.com/alesapin)).
* Les valeurs par défaut des paramètres `max_size_to_preallocate_for_aggregation` et `max_size_to_preallocate_for_joins` ont été augmentées à `10^12`, de sorte que l'optimisation s'appliquera dans davantage de cas. [#72555](https://github.com/ClickHouse/ClickHouse/pull/72555) ([Nikita Taranov](https://github.com/nickitat)).
* Amélioration des performances de désérialisation des états des fonctions d'agrégation (dans le type de données `AggregateFunction` et dans les requêtes distribuées). Légère amélioration des performances d'analyse du format `RowBinary`. [#72818](https://github.com/ClickHouse/ClickHouse/pull/72818) ([Anton Popov](https://github.com/CurtizJ)).
