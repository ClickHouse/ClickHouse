<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#41283](https://github.com/ClickHouse/ClickHouse/issues/41283) : correction des colonnes inconnues inutilisées introduites par l’instruction WITH. Cela corrige [#37812](https://github.com/ClickHouse/ClickHouse/issues/37812). [#39131](https://github.com/ClickHouse/ClickHouse/pull/39131) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#40865](https://github.com/ClickHouse/ClickHouse/issues/40865) : correction d’un plantage lors de l’analyse de valeurs de type `Object` contenant des tableaux à dimension variable. [#40483](https://github.com/ClickHouse/ClickHouse/pull/40483) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#40804](https://github.com/ClickHouse/ClickHouse/issues/40804) : lors de l’insertion d’une nouvelle query dans `ProcessList`, des allocations mémoire ont lieu. Si la memory limit est atteinte pendant ces allocations, il n’est pas possible d’utiliser `OvercommitTracker`, car `ProcessList::mutex` est déjà verrouillé. Corrige [#40611](https://github.com/ClickHouse/ClickHouse/issues/40611). [#40677](https://github.com/ClickHouse/ClickHouse/pull/40677) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#40810](https://github.com/ClickHouse/ClickHouse/issues/40810) : dans [#40595](https://github.com/ClickHouse/ClickHouse/issues/40595), il a été signalé que la fonctionnalité `host_regexp` ne fonctionnait pas correctement avec la résolution de noms en adresses via `/etc/hosts`. C’est corrigé. [#40769](https://github.com/ClickHouse/ClickHouse/pull/40769) ([Arthur Passos](https://github.com/arthurpassos)).
* Rétroporté dans [#41134](https://github.com/ClickHouse/ClickHouse/issues/41134) : correction des droits d’accès pour `DESCRIBE TABLE url()` et quelques autres commandes `DESCRIBE TABLE <table_function>()`. [#40975](https://github.com/ClickHouse/ClickHouse/pull/40975) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#41617](https://github.com/ClickHouse/ClickHouse/issues/41617) : correction de possibles segfaults, de use-heap-after-free et de fuites mémoire dans les aggregate function combinators. Clôt [#40848](https://github.com/ClickHouse/ClickHouse/issues/40848). [#41083](https://github.com/ClickHouse/ClickHouse/pull/41083) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#41666](https://github.com/ClickHouse/ClickHouse/issues/41666) : les queries avec clause `OFFSET` dans une subquery et clause `WHERE` dans la query externe pouvaient renvoyer un résultat incorrect ; c’est corrigé. Corrige [#40416](https://github.com/ClickHouse/ClickHouse/issues/40416). [#41280](https://github.com/ClickHouse/ClickHouse/pull/41280) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#41361](https://github.com/ClickHouse/ClickHouse/issues/41361) : correction de l’erreur logique `Expected relative path` dans le disk object storage. Lié à [#41246](https://github.com/ClickHouse/ClickHouse/issues/41246). [#41297](https://github.com/ClickHouse/ClickHouse/pull/41297) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#41358](https://github.com/ClickHouse/ClickHouse/issues/41358) : ajout d’une vérification du column type avant l’insertion d’un UUID au format MsgPack. [#41309](https://github.com/ClickHouse/ClickHouse/pull/41309) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#41808](https://github.com/ClickHouse/ClickHouse/issues/41808) : des données malveillantes au format Native peuvent provoquer un crash. [#41441](https://github.com/ClickHouse/ClickHouse/pull/41441) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41805](https://github.com/ClickHouse/ClickHouse/issues/41805) : la fonction d&#39;agrégation `categorialInformationValue` avait des propriétés incorrectement définies, ce qui pouvait provoquer un déréférencement de pointeur nul à l&#39;exécution. Ceci clôt [#41443](https://github.com/ClickHouse/ClickHouse/issues/41443). [#41449](https://github.com/ClickHouse/ClickHouse/pull/41449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41505](https://github.com/ClickHouse/ClickHouse/issues/41505) : l&#39;écriture de données au format Apache `ORC` pouvait entraîner un dépassement de tampon. [#41458](https://github.com/ClickHouse/ClickHouse/pull/41458) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41644](https://github.com/ClickHouse/ClickHouse/issues/41644) : les requêtes avec `ORDER BY` et `1500 <= LIMIT <= max_block_size` pouvaient renvoyer un résultat incorrect avec des lignes manquantes en tête. Corrige [#41182](https://github.com/ClickHouse/ClickHouse/issues/41182). [#41576](https://github.com/ClickHouse/ClickHouse/pull/41576) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41641](https://github.com/ClickHouse/ClickHouse/issues/41641) : corrige une exception possible `pipeline stuck` pour les requêtes avec `OFFSET`. L&#39;erreur a été détectée avec `enable_optimize_predicate_expression = 0` et une condition toujours false dans `WHERE`. Corrige [#41383](https://github.com/ClickHouse/ClickHouse/issues/41383). [#41588](https://github.com/ClickHouse/ClickHouse/pull/41588) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41900](https://github.com/ClickHouse/ClickHouse/issues/41900) : corrige un crash possible dans `SELECT` depuis une table `Merge` avec le paramètre `optimize_monotonous_functions_in_order_by` activé. Corrige [#41269](https://github.com/ClickHouse/ClickHouse/issues/41269). [#41740](https://github.com/ClickHouse/ClickHouse/pull/41740) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
