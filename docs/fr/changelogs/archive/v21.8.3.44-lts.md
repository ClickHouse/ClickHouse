<div id="bug-fix">
  #### Correction de bogues
</div>

* Rétroporté dans [#27545](https://github.com/ClickHouse/ClickHouse/issues/27545) : désormais, une sous-requête scalaire renvoie toujours un résultat `Nullable` si son type peut être `Nullable`. C&#39;est nécessaire, car dans le cas d&#39;une sous-requête vide, le résultat doit être `Null`. Auparavant, il était possible d&#39;obtenir une erreur de types incompatibles (la déduction de type n&#39;exécute pas la sous-requête scalaire et pouvait utiliser un type non nullable). Une sous-requête scalaire avec un résultat vide qui ne peut pas être converti en `Nullable` (comme `Array` ou `Tuple`) génère désormais une erreur. Corrige [#25411](https://github.com/ClickHouse/ClickHouse/issues/25411). [#26423](https://github.com/ClickHouse/ClickHouse/pull/26423) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#26856](https://github.com/ClickHouse/ClickHouse/issues/26856) : ParallelFormattingOutputFormat : utilisation d&#39;un mutex pour gérer le join avec collector&#95;thread ([https://github.com/ClickHouse/ClickHouse/issues/26694](https://github.com/ClickHouse/ClickHouse/issues/26694)). [#26703](https://github.com/ClickHouse/ClickHouse/pull/26703) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#26941](https://github.com/ClickHouse/ClickHouse/issues/26941) : ne pas supprimer les données à l&#39;arrêt d&#39;une table ReplicatedMergeTree afin d&#39;éviter de créer une incohérence entre les données et les métadonnées. [#26716](https://github.com/ClickHouse/ClickHouse/pull/26716) ([nvartolomei](https://github.com/nvartolomei)).
* Rétroporté dans [#26981](https://github.com/ClickHouse/ClickHouse/issues/26981) : les paramètres des fonctions d&#39;agrégation pouvaient être perdus lors de l&#39;application de certains combinateurs, provoquant des exceptions comme `Conversion from AggregateFunction(topKArray, Array(String)) to AggregateFunction(topKArray(10), Array(String)) is not supported`. C&#39;est corrigé. Corrige [#26196](https://github.com/ClickHouse/ClickHouse/issues/26196) et [#26433](https://github.com/ClickHouse/ClickHouse/issues/26433). [#26814](https://github.com/ClickHouse/ClickHouse/pull/26814) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#26909](https://github.com/ClickHouse/ClickHouse/issues/26909) : corrige le chargement des identifiants de library-bridge. [#26834](https://github.com/ClickHouse/ClickHouse/pull/26834) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#26945](https://github.com/ClickHouse/ClickHouse/issues/26945) : corrige l&#39;erreur `Missing columns: 'xxx'` lorsqu&#39;une colonne `DEFAULT` référence une autre colonne non matérialisée sans expression `DEFAULT`. Corrige [#26591](https://github.com/ClickHouse/ClickHouse/issues/26591). [#26900](https://github.com/ClickHouse/ClickHouse/pull/26900) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#26997](https://github.com/ClickHouse/ClickHouse/issues/26997) : corrige la lecture des TLD personnalisés (le traitement s&#39;arrête avec un buffer plus petit ou un fichier plus volumineux). [#26948](https://github.com/ClickHouse/ClickHouse/pull/26948) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#27030](https://github.com/ClickHouse/ClickHouse/issues/27030) : désormais, l&#39;identifiant de partition dans des requêtes comme `ALTER TABLE ... PARTITION ID xxx` est validé. Corrige [#25718](https://github.com/ClickHouse/ClickHouse/issues/25718). [#26963](https://github.com/ClickHouse/ClickHouse/pull/26963) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#27053](https://github.com/ClickHouse/ClickHouse/issues/27053) : [RFC] corrige un empilement possible de mutations dû à une concurrence avec DROP&#95;RANGE. [#27002](https://github.com/ClickHouse/ClickHouse/pull/27002) ([Azat Khuzhin](https://github.com/azat)).
