<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Ne plus autoriser la définition de max&#95;parallel&#95;replicas à 0, car cela n&#39;a pas de sens. La définir à 0 pouvait entraîner des erreurs logiques inattendues. Clôt [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140). [#60430](https://github.com/ClickHouse/ClickHouse/pull/60430) ([Kruglov Pavel](https://github.com/Avogar)).
* Remplace le nom de la colonne `duration_ms` par `duration_microseconds` dans la table `system.zookeeper` afin de refléter le fait que la durée est exprimée avec une précision de la microseconde. [#60774](https://github.com/ClickHouse/ClickHouse/pull/60774) ([Duc Canh Le](https://github.com/canhld94)).
* Rejeter les requêtes INSERT entrantes lorsque les paramètres au niveau de la requête `async_insert` et `deduplicate_blocks_in_dependent_materialized_views` sont activés simultanément. Ce comportement est contrôlé par le paramètre `throw_if_deduplication_in_dependent_materialized_views_enabled_with_async_insert` et est activé par défaut. Il s&#39;agit de la suite de [https://github.com/ClickHouse/ClickHouse/pull/59699](https://github.com/ClickHouse/ClickHouse/pull/59699), nécessaire pour débloquer [https://github.com/ClickHouse/ClickHouse/pull/59915](https://github.com/ClickHouse/ClickHouse/pull/59915). [#60888](https://github.com/ClickHouse/ClickHouse/pull/60888) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* L&#39;utilitaire `clickhouse-copier` a été déplacé vers un dépôt distinct sur GitHub : [https://github.com/ClickHouse/copier](https://github.com/ClickHouse/copier). Il n&#39;est plus inclus dans le package, mais reste disponible en téléchargement séparé. Clôt : [#60734](https://github.com/ClickHouse/ClickHouse/issues/60734) Clôt : [#60540](https://github.com/ClickHouse/ClickHouse/issues/60540) Clôt : [#60250](https://github.com/ClickHouse/ClickHouse/issues/60250) Clôt : [#52917](https://github.com/ClickHouse/ClickHouse/issues/52917) Clôt : [#51140](https://github.com/ClickHouse/ClickHouse/issues/51140) Clôt : [#47517](https://github.com/ClickHouse/ClickHouse/issues/47517) Clôt : [#47189](https://github.com/ClickHouse/ClickHouse/issues/47189) Clôt : [#46598](https://github.com/ClickHouse/ClickHouse/issues/46598) Clôt : [#40257](https://github.com/ClickHouse/ClickHouse/issues/40257) Clôt : [#36504](https://github.com/ClickHouse/ClickHouse/issues/36504) Clôt : [#35485](https://github.com/ClickHouse/ClickHouse/issues/35485) Clôt : [#33702](https://github.com/ClickHouse/ClickHouse/issues/33702) Clôt : [#26702](https://github.com/ClickHouse/ClickHouse/issues/26702) ### Entrée de documentation pour les modifications visibles par l&#39;utilisateur. [#61058](https://github.com/ClickHouse/ClickHouse/pull/61058) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Pour améliorer la compatibilité avec MySQL, la fonction `locate` accepte désormais par défaut les arguments `(needle, haystack[, start_pos])`. Le comportement précédent `(haystack, needle, [, start_pos])` peut être rétabli en définissant `function_locate_has_mysql_compatible_argument_order = 0`. [#61092](https://github.com/ClickHouse/ClickHouse/pull/61092) ([Robert Schulze](https://github.com/rschu1ze)).
* Les parties de données en mémoire obsolètes sont dépréciées depuis la version 23.5 et ne sont plus prises en charge depuis la version 23.10. Le code restant est désormais supprimé. Suite de [#55186](https://github.com/ClickHouse/ClickHouse/issues/55186) et [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409). Il est peu probable que vous ayez utilisé des parties de données en mémoire, car elles n&#39;étaient disponibles qu&#39;avant la version 23.5, et uniquement si vous les aviez activées manuellement en spécifiant les `SETTINGS` correspondants pour une table MergeTree. Pour vérifier si vous avez des parties de données en mémoire, exécutez la requête suivante : `SELECT part_type, count() FROM system.parts GROUP BY part_type ORDER BY part_type`. Pour désactiver l&#39;utilisation des parties de données en mémoire, exécutez `ALTER TABLE ... MODIFY SETTING min_bytes_for_compact_part = DEFAULT, min_rows_for_compact_part = DEFAULT`. Avant de mettre à niveau depuis d&#39;anciennes versions de ClickHouse, vérifiez d&#39;abord que vous n&#39;avez pas de parties de données en mémoire. S&#39;il y a des parties de données en mémoire, désactivez-les d&#39;abord, puis attendez qu&#39;il n&#39;y en ait plus avant de poursuivre la mise à niveau. [#61127](https://github.com/ClickHouse/ClickHouse/pull/61127) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Interdire par défaut `SimpleAggregateFunction` dans `ORDER BY` des tables `MergeTree` (comme `AggregateFunction`, car ils ne sont pas comparables) ; utilisez `allow_suspicious_primary_key` pour les autoriser. [#61399](https://github.com/ClickHouse/ClickHouse/pull/61399) ([Azat Khuzhin](https://github.com/azat)).
* ClickHouse autorise des données binaires arbitraires dans le type de données String, qui est généralement en UTF-8. Les chaînes Parquet/ORC/Arrow ne prennent en charge que l&#39;UTF-8. C&#39;est pourquoi vous pouvez choisir le type de données Arrow à utiliser pour le type de données String de ClickHouse : String ou Binary. Cela est contrôlé par les settings `output_format_parquet_string_as_string`, `output_format_orc_string_as_string`, `output_format_arrow_string_as_string`. Bien que Binary soit plus correct et plus compatible, utiliser String par défaut correspondra aux attentes des utilisateurs dans la plupart des cas. Parquet/ORC/Arrow prend en charge de nombreuses méthodes de compression, notamment lz4 et zstd. ClickHouse prend en charge chacune de ces méthodes de compression. Certains outils moins performants ne prennent pas en charge la méthode de compression `lz4`, plus rapide, c&#39;est pourquoi nous utilisons `zstd` par défaut. Cela est contrôlé par les settings `output_format_parquet_compression_method`, `output_format_orc_compression_method` et `output_format_arrow_compression_method`. Nous avons remplacé la valeur par défaut par `zstd` pour Parquet et ORC, mais pas pour Arrow (qui est davantage destiné à des usages de bas niveau). [#61817](https://github.com/ClickHouse/ClickHouse/pull/61817) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Dans la nouvelle version de ClickHouse, les fonctions `geoDistance`, `greatCircleDistance` et `greatCircleAngle` utiliseront le type de données à virgule flottante Double de précision 64 bits pour les calculs internes et comme type de retour si tous les arguments sont de type Float64. Cela clôt [#58476](https://github.com/ClickHouse/ClickHouse/issues/58476). Dans les versions précédentes, la fonction utilisait toujours Float32. Vous pouvez revenir à l&#39;ancien comportement en définissant `geo_distance_returns_float64_on_float64_arguments` sur `false` ou en définissant `compatibility` sur `24.2` ou une version antérieure. [#61848](https://github.com/ClickHouse/ClickHouse/pull/61848) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Améliore les performances de la méthode d’agrégation sérialisée lorsqu’elle implique plusieurs colonnes [nullable]. Il s’agit d’une version générale de [#51399](https://github.com/ClickHouse/ClickHouse/issues/51399) qui ne compromet pas l’intégrité de l’abstraction. [#55809](https://github.com/ClickHouse/ClickHouse/pull/55809) ([Amos Bird](https://github.com/amosbird)).
* Construction paresseuse de la sortie de join afin d’améliorer les performances de ALL join. [#58278](https://github.com/ClickHouse/ClickHouse/pull/58278) ([LiuNeng](https://github.com/liuneng1994)).
* Améliorations des fonctions d’agrégation ArgMin / ArgMax / any / anyLast / anyHeavy, ainsi que des requêtes `ORDER BY {u8/u16/u32/u64/i8/i16/u32/i64) LIMIT 1`. [#58640](https://github.com/ClickHouse/ClickHouse/pull/58640) ([Raúl Marín](https://github.com/Algunenano)).
* Optimisation triviale du filtre de colonnes. Évite de filtrer avec `result_size_hint = -1` les colonnes de filtre dont le type de données sous-jacent n’est pas numérique. Le pic de mémoire peut être réduit à 44 % de la valeur initiale dans certains cas. [#59698](https://github.com/ClickHouse/ClickHouse/pull/59698) ([李扬](https://github.com/taiyang-li)).
* Si la clé primaire de la table contient principalement des colonnes inutiles, ne les conservez pas en mémoire. Ce comportement est contrôlé par un nouveau paramètre `primary_key_ratio_of_unique_prefix_values_to_skip_suffix_columns`, dont la valeur par défaut est `0.9`, ce qui signifie : pour une clé primaire composée, si une colonne change de valeur dans au moins 0.9 de tous les cas, les colonnes qui la suivent ne seront pas chargées. [#60255](https://github.com/ClickHouse/ClickHouse/pull/60255) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Exécute la fonction multiIf de manière colonnaire lorsque le type sous-jacent de result&#95;type est numérique. [#60384](https://github.com/ClickHouse/ClickHouse/pull/60384) ([李扬](https://github.com/taiyang-li)).
* Mutex bien plus rapides (presque 2x) (ils étaient plus lents à cause de ThreadFuzzer). [#60823](https://github.com/ClickHouse/ClickHouse/pull/60823) ([Azat Khuzhin](https://github.com/azat)).
* Déplace le drainage des connexions de prepare vers work, et draine plusieurs connexions en parallèle. [#60845](https://github.com/ClickHouse/ClickHouse/pull/60845) ([lizhuoyu5](https://github.com/lzydmxy)).
* Optimise insertManyFrom pour nullable number ou nullable string. [#60846](https://github.com/ClickHouse/ClickHouse/pull/60846) ([李扬](https://github.com/taiyang-li)).
* Optimise la fonction `dotProduct` pour éviter des copies mémoire inutiles et coûteuses. [#60928](https://github.com/ClickHouse/ClickHouse/pull/60928) ([Robert Schulze](https://github.com/rschu1ze)).
* Les opérations sur le cache du système de fichiers subiront moins la contention sur le verrou. [#61066](https://github.com/ClickHouse/ClickHouse/pull/61066) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimise ColumnString::replicate et empêche memcpySmallAllowReadWriteOverflow15Impl d’être optimisé en memcpy intégré. Ferme [#61074](https://github.com/ClickHouse/ClickHouse/issues/61074). ColumnString::replicate est 2.46x plus rapide sur x86-64. [#61075](https://github.com/ClickHouse/ClickHouse/pull/61075) ([李扬](https://github.com/taiyang-li)).
* Affichage 30x plus rapide pour les entiers 256 bits. [#61100](https://github.com/ClickHouse/ClickHouse/pull/61100) ([Raúl Marín](https://github.com/Algunenano)).
* Si une requête contenant une erreur de syntaxe incluait un sélecteur COLUMNS avec une expression régulière, cette expression régulière était compilée à chaque retour en arrière du parseur, au lieu de l’être une seule fois. C’était une erreur fondamentale. L’expression régulière compilée était placée dans l’AST. Or, le A de AST signifie &quot;abstract&quot; : il ne devrait donc pas contenir d’objets lourds. Des parties de l’AST peuvent être créées puis supprimées pendant le parsing, notamment lors d’un grand nombre de retours en arrière. Cela ralentit le parsing et permet donc à un utilisateur readonly de provoquer un DoS. Mais le principal problème est que cela entrave surtout les progrès des Fuzzers. [#61543](https://github.com/ClickHouse/ClickHouse/pull/61543) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout d’une nouvelle passe de l’analyseur pour optimiser les valeurs uniques. [#61564](https://github.com/ClickHouse/ClickHouse/pull/61564) ([LiuNeng](https://github.com/liuneng1994)).
