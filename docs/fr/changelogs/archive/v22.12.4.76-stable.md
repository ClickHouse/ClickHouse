* Rétroporté dans [#45904](https://github.com/ClickHouse/ClickHouse/issues/45904) : correction d’un bogue lié à une valeur par défaut non analysable pour une colonne EPHEMERAL dans les métadonnées de la table. * Rétroporté dans [#45321](https://github.com/ClickHouse/ClickHouse/issues/45321) : correction d’un bogue dans la normalisation d’une expression `DEFAULT` dans une instruction `CREATE TABLE`. Le deuxième argument de la fonction `in` (ou l’argument de droite de l’opérateur `IN`) pouvait être remplacé par le résultat de son évaluation pendant l’exécution de la requête CREATE. Corrige [#44496](https://github.com/ClickHouse/ClickHouse/issues/44496). [#44547](https://github.com/ClickHouse/ClickHouse/pull/44547) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#45000](https://github.com/ClickHouse/ClickHouse/issues/45000) : autre correctif pour l’erreur `Cannot read all data`, qui pouvait se produire lors de la lecture du dictionnaire `LowCardinality` depuis remote fs. Corrige [#44709](https://github.com/ClickHouse/ClickHouse/issues/44709). [#44875](https://github.com/ClickHouse/ClickHouse/pull/44875) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#45553](https://github.com/ClickHouse/ClickHouse/issues/45553) : corrige l’exception `SELECT ... FROM system.dictionaries` lorsqu’un dictionnaire a une structure incorrecte (par ex. un type incorrect dans la configuration XML). [#45399](https://github.com/ClickHouse/ClickHouse/pull/45399) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#46226](https://github.com/ClickHouse/ClickHouse/issues/46226) : plusieurs segfaults ont été signalés autour de `c-ares`. Toutes les stack traces récentes observées échouent lors de l’insertion dans `std::unodered_set<>`. Je pense avoir trouvé la cause racine : il semble qu’il s’agisse de requêtes non traitées. Avant cette PR, CH appelait `poll` pour attendre sur les descripteurs de fichier du canal `c-ares`. Selon la [documentation de poll](https://man7.org/linux/man-pages/man2/poll.2.html), une valeur de retour négative signifie qu’une erreur s’est produite. Pour cette raison, nous interrompions l’exécution et renvoyions un échec. Le problème est que `poll` renvoie également une valeur négative lorsqu’une interruption système se produit. Une interruption système ne signifie pas que le traitement a échoué ou s’est terminé, mais nous l’interrompions quand même parce que nous vérifiions simplement si la valeur était négative. Une fois l’exécution interrompue, toute la pile est détruite, y compris le `std::unordered_set<std::string>` passé au paramètre `void *` du callback c-ares. Une fois que c-ares terminait la requête, le callback était invoqué et accédait à une adresse mémoire invalide, provoquant un segfault. [#45629](https://github.com/ClickHouse/ClickHouse/pull/45629) ([Arthur Passos](https://github.com/arthurpassos)).
* Rétroporté dans [#46218](https://github.com/ClickHouse/ClickHouse/issues/46218) : correction de la lecture de colonnes imbriquées inexistantes à plusieurs niveaux dans les compact parts. [#46045](https://github.com/ClickHouse/ClickHouse/pull/46045) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#46446](https://github.com/ClickHouse/ClickHouse/issues/46446) : corrige un `LOGICAL_ERROR` possible dans les insertions asynchrones avec des données invalides envoyées au format `VALUES`. [#46350](https://github.com/ClickHouse/ClickHouse/pull/46350) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#46678](https://github.com/ClickHouse/ClickHouse/issues/46678) : corrige un traitement incorrect d’un argument constant `LowCardinality` dans la fonction `arrayMap`. Ce bogue pouvait entraîner un segfault dans une version release, ainsi qu’une erreur logique `Bad cast` dans une build de débogage. [#46569](https://github.com/ClickHouse/ClickHouse/pull/46569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#46872](https://github.com/ClickHouse/ClickHouse/issues/46872) : correction d’un bogue dans le type de données `Map`. Ceci clôt [#46855](https://github.com/ClickHouse/ClickHouse/issues/46855). [#46856](https://github.com/ClickHouse/ClickHouse/pull/46856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#46954](https://github.com/ClickHouse/ClickHouse/issues/46954) : correction du résultat des prédicats LIKE qui se traduisent par des recherches de sous-chaînes et contiennent des métacaractères non-LIKE entre guillemets. [#46875](https://github.com/ClickHouse/ClickHouse/pull/46875) ([Robert Schulze](https://github.com/rschu1ze)).
