<div id="clickhouse-release-v209476-stable-fixme-as-compared-to-v209345-stable">
  ### Version ClickHouse v20.9.4.76-stable FIXME par rapport à la v20.9.3.45-stable
</div>

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#16145](https://github.com/ClickHouse/ClickHouse/issues/16145) : il est désormais possible d’exécuter des requêtes `ALTER ... ON CLUSTER` независимоamment du paramètre `<internal_replication>` dans la configuration du cluster. [#16075](https://github.com/ClickHouse/ClickHouse/pull/16075) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#16312](https://github.com/ClickHouse/ClickHouse/issues/16312) : ajout de allow&#95;nondeterministic&#95;optimize&#95;skip&#95;unused&#95;shards (pour autoriser l’utilisation d’éléments non déterministes, comme rand() ou dictGet(), dans la clé de sharding). [#16105](https://github.com/ClickHouse/ClickHouse/pull/16105) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix">
  #### Correctifs
</div>

* Rétroporté dans [#15618](https://github.com/ClickHouse/ClickHouse/issues/15618) : signaler une erreur lorsqu’un seul paramètre est passé à ReplicatedMergeTree au lieu de l’ignorer. [#15516](https://github.com/ClickHouse/ClickHouse/pull/15516) ([nvartolomei](https://github.com/nvartolomei)).
* Rétroporté dans [#16201](https://github.com/ClickHouse/ClickHouse/issues/16201) : décrémenter la métrique `ReadonlyReplica` lors du détachement de tables en lecture seule. Cela corrige [#15598](https://github.com/ClickHouse/ClickHouse/issues/15598). [#15592](https://github.com/ClickHouse/ClickHouse/pull/15592) ([sundyli](https://github.com/sundy-li)).
* Rétroporté dans [#16229](https://github.com/ClickHouse/ClickHouse/issues/16229) : correction d’un bug avec les motifs glob dans la fonction de table S3 : la région issue de l’URL n’était pas appliquée à la configuration du client S3. [#15646](https://github.com/ClickHouse/ClickHouse/pull/15646) ([Vladimir Chebotarev](https://github.com/excitoon)).
* Rétroporté dans [#15870](https://github.com/ClickHouse/ClickHouse/issues/15870) : correction de l’erreur `Cannot add simple transform to empty Pipe`, qui se produisait lors de la lecture depuis une table `Buffer` dont la structure différait de celle de la table de destination. Cela pouvait se produire si la table de destination renvoyait un résultat vide pour la requête. Corrige [#15529](https://github.com/ClickHouse/ClickHouse/issues/15529). [#15662](https://github.com/ClickHouse/ClickHouse/pull/15662) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#15774](https://github.com/ClickHouse/ClickHouse/issues/15774) : correction d’une valeur par défaut trop faible du paramètre `max_replicated_logs_to_keep`, qui pouvait entraîner trop souvent la perte de répliques. Amélioration du processus de récupération des répliques perdues en choisissant la réplique la plus à jour à cloner. De plus, les anciennes parts ne sont plus supprimées de la réplique perdue, mais détachées à la place. [#15701](https://github.com/ClickHouse/ClickHouse/pull/15701) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#15798](https://github.com/ClickHouse/ClickHouse/issues/15798) : correction de certains cas de requêtes dans lesquelles seules des colonnes virtuelles sont sélectionnées. Auparavant, l’exception `Not found column _nothing in block` pouvait être levée. Corrige [#12298](https://github.com/ClickHouse/ClickHouse/issues/12298). [#15756](https://github.com/ClickHouse/ClickHouse/pull/15756) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#15868](https://github.com/ClickHouse/ClickHouse/issues/15868) : correction de l’inexactitude de `select count()` pour MaterializeMySQL. [#15767](https://github.com/ClickHouse/ClickHouse/pull/15767) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#15901](https://github.com/ClickHouse/ClickHouse/issues/15901) : correction de l’exception `Block structure mismatch` dans les requêtes `SELECT ... ORDER BY DESC` exécutées après une requête `ALTER MODIFY COLUMN`. Corrige [#15800](https://github.com/ClickHouse/ClickHouse/issues/15800). [#15852](https://github.com/ClickHouse/ClickHouse/pull/15852) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#15924](https://github.com/ClickHouse/ClickHouse/issues/15924) : une exception sera désormais levée lorsque `ALTER MODIFY COLUMN ... DEFAULT ...` comporte une valeur par défaut incompatible avec le type de colonne. Corrige [#15854](https://github.com/ClickHouse/ClickHouse/issues/15854). [#15858](https://github.com/ClickHouse/ClickHouse/pull/15858) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#15919](https://github.com/ClickHouse/ClickHouse/issues/15919) : correction d’éventuels interblocages dans RBAC. [#15875](https://github.com/ClickHouse/ClickHouse/pull/15875) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#16167](https://github.com/ClickHouse/ClickHouse/issues/16167) : correction d’un résultat vide incorrect pour une requête sur une table `Distributed` lorsque la requête contient `WHERE`, `PREWHERE` et `GLOBAL IN`. Corrige [#15792](https://github.com/ClickHouse/ClickHouse/issues/15792). [#15933](https://github.com/ClickHouse/ClickHouse/pull/15933) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#16356](https://github.com/ClickHouse/ClickHouse/issues/16356) : correction de l’échec de `DROP TABLE IF EXISTS` avec l’erreur `Table ... doesn't exist` lorsqu’une table est renommée de façon concurrente (pour le moteur de base de données Atomic). Correction d’un interblocage rare lors de l’exécution concurrente de certaines requêtes DDL sur plusieurs tables (comme `DROP DATABASE` et `RENAME TABLE`). Correction de l’échec de `DROP/DETACH DATABASE` avec `Table ... doesn't exist` lors de l’exécution concurrente de `DROP/DETACH TABLE`. [#15934](https://github.com/ClickHouse/ClickHouse/pull/15934) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#15971](https://github.com/ClickHouse/ClickHouse/issues/15971) : correction d’un crash lorsque la création de la base de données échoue. [#15954](https://github.com/ClickHouse/ClickHouse/pull/15954) ([Winter Zhang](https://github.com/zhang2014)).
* Rétroporté dans [#16022](https://github.com/ClickHouse/ClickHouse/issues/16022) : correction d’une ambiguïté dans l’analyse des profils de paramètres : `CREATE USER ... SETTINGS profile readonly` est désormais considéré comme l’utilisation d’un profil nommé `readonly`, et non d’un paramètre nommé `profile` avec la contrainte readonly. Cela corrige [#15628](https://github.com/ClickHouse/ClickHouse/issues/15628). [#15982](https://github.com/ClickHouse/ClickHouse/pull/15982) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#16218](https://github.com/ClickHouse/ClickHouse/issues/16218) : correction de segfaults rares lors d’insertions dans MaterializedView ou de sélections depuis celle-ci, avec suppression concurrente de la table cible (pour le moteur de base de données Atomic). [#15984](https://github.com/ClickHouse/ClickHouse/pull/15984) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#16026](https://github.com/ClickHouse/ClickHouse/issues/16026) : évite le blocage d’une réplique pendant 5 à 10 minutes lorsqu’une erreur de réplication survient après une période d’inactivité. [#15987](https://github.com/ClickHouse/ClickHouse/pull/15987) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#16091](https://github.com/ClickHouse/ClickHouse/issues/16091) : autorise l’utilisation du layout direct pour les dictionnaires avec des clés complexes. [#16007](https://github.com/ClickHouse/ClickHouse/pull/16007) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#16361](https://github.com/ClickHouse/ClickHouse/issues/16361) : correction de l’analyseur des noms de collation et de jeu de caractères, et prise en charge de `length = 0` pour le type String. [#16008](https://github.com/ClickHouse/ClickHouse/pull/16008) ([Winter Zhang](https://github.com/zhang2014)).
* Rétroporté dans [#16140](https://github.com/ClickHouse/ClickHouse/issues/16140) : correction du blocage de la requête `ALTER MODIFY ... ORDER BY` pour `ReplicatedVersionedCollapsingMergeTree`. Cela corrige [#15980](https://github.com/ClickHouse/ClickHouse/issues/15980). [#16011](https://github.com/ClickHouse/ClickHouse/pull/16011) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#16079](https://github.com/ClickHouse/ClickHouse/issues/16079) : corrige la régression [#15780](https://github.com/ClickHouse/ClickHouse/issues/15780) ; par exemple, `indexOf([1, 2, 3], toLowCardinality(1))` est désormais interdit alors que cela ne devrait pas l’être. [#16038](https://github.com/ClickHouse/ClickHouse/pull/16038) ([Mike Kot](https://github.com/myrrc)).
* Rétroporté dans [#16298](https://github.com/ClickHouse/ClickHouse/issues/16298) : correction de `dictGet` dans sharding&#95;key (et dans des cas similaires, c.-à-d. lorsque le contexte de la fonction est stocké de manière permanente). [#16205](https://github.com/ClickHouse/ClickHouse/pull/16205) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16232](https://github.com/ClickHouse/ClickHouse/issues/16232) : correction du cas où la mémoire pouvait être surallouée indépendamment de la limite. Cela clôt [#14560](https://github.com/ClickHouse/ClickHouse/issues/14560). [#16206](https://github.com/ClickHouse/ClickHouse/pull/16206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#16326](https://github.com/ClickHouse/ClickHouse/issues/16326) : correction d’une possible fuite de mémoire lors d’un `GROUP BY` avec des clés de type chaîne, causée par une erreur dans l’implémentation de `TwoLevelStringHashTable`. [#16264](https://github.com/ClickHouse/ClickHouse/pull/16264) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#16377](https://github.com/ClickHouse/ClickHouse/issues/16377) : correction de l’INSERT asynchrone sur Distributed avec prefer&#95;localhost&#95;replica=0 et internal&#95;replication. [#16358](https://github.com/ClickHouse/ClickHouse/pull/16358) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16432](https://github.com/ClickHouse/ClickHouse/issues/16432) : correction de GROUP BY avec les modificateurs totals/rollup/cube et les fonctions min/max sur les clés de GROUP BY. Corrige [#16393](https://github.com/ClickHouse/ClickHouse/issues/16393). [#16397](https://github.com/ClickHouse/ClickHouse/pull/16397) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#16449](https://github.com/ClickHouse/ClickHouse/issues/16449) : correction d’une double libération en cas d’exception dans la fonction `dictGet`. Cela pouvait se produire si le dictionnaire avait été chargé avec une erreur. [#16429](https://github.com/ClickHouse/ClickHouse/pull/16429) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
