<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#65463](https://github.com/ClickHouse/ClickHouse/issues/65463) : rechargement de la chaîne de certificats lors du rechargement du certificat. [#61671](https://github.com/ClickHouse/ClickHouse/pull/61671) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* Rétroporté dans [#65882](https://github.com/ClickHouse/ClickHouse/issues/65882) : démarrage systématique de Keeper avec un nombre suffisant de threads dans le pool global de threads. [#64444](https://github.com/ClickHouse/ClickHouse/pull/64444) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#65302](https://github.com/ClickHouse/ClickHouse/issues/65302) : rétablissement du comportement de ClickHouse pour le traitement et l’interprétation des Tuples au format CSV. Cette modification annule de fait [https://github.com/ClickHouse/ClickHouse/pull/60994](https://github.com/ClickHouse/ClickHouse/pull/60994) et ne la rend disponible qu’au travers de quelques paramètres : `output_format_csv_serialize_tuple_into_separate_columns`, `input_format_csv_deserialize_separate_columns_into_tuple` et `input_format_csv_try_infer_strings_from_quoted_tuples`. [#65170](https://github.com/ClickHouse/ClickHouse/pull/65170) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#65892](https://github.com/ClickHouse/ClickHouse/issues/65892) : prise en compte de la limite CPU du cgroup dans Keeper. [#65819](https://github.com/ClickHouse/ClickHouse/pull/65819) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="critical-bug-fix-crash-logical_error-data-loss-rbac">
  #### Correctif critique de bug (plantage, LOGICAL_ERROR, perte de données, RBAC)
</div>

* Rétroporté dans [#65283](https://github.com/ClickHouse/ClickHouse/issues/65283) : correction d’un plantage avec UniqInjectiveFunctionsEliminationPass et uniqCombined. [#65188](https://github.com/ClickHouse/ClickHouse/pull/65188) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#65370](https://github.com/ClickHouse/ClickHouse/issues/65370) : correction d’un bug dans ClickHouse Keeper provoquant une discordance de digest lors de la fermeture de la session. [#65198](https://github.com/ClickHouse/ClickHouse/pull/65198) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#65446](https://github.com/ClickHouse/ClickHouse/issues/65446) : utilisation du bon alignement mémoire pour le combinator Distinct. Auparavant, un plantage pouvait survenir en raison d’une allocation mémoire invalide lors de l’utilisation du combinator. [#65379](https://github.com/ClickHouse/ClickHouse/pull/65379) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#65708](https://github.com/ClickHouse/ClickHouse/issues/65708) : correction d’un plantage dans maxIntersections. [#65689](https://github.com/ClickHouse/ClickHouse/pull/65689) ([Raúl Marín](https://github.com/Algunenano)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#65352](https://github.com/ClickHouse/ClickHouse/issues/65352) : correction d’une possible interruption sur exception non gérée dans ~WriteBufferFromFileDescriptor, dans StatusFile. [#64206](https://github.com/ClickHouse/ClickHouse/pull/64206) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#65327](https://github.com/ClickHouse/ClickHouse/issues/65327) : correction d’une boucle de crash lorsque la restauration à partir d’une sauvegarde est bloquée par la création d’une MV avec un definer qui n’a pas encore été restauré. [#64595](https://github.com/ClickHouse/ClickHouse/pull/64595) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#65538](https://github.com/ClickHouse/ClickHouse/issues/65538) : correction d’un crash pour `ALTER TABLE ... ON CLUSTER ... MODIFY SQL SECURITY`. [#64957](https://github.com/ClickHouse/ClickHouse/pull/64957) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#65576](https://github.com/ClickHouse/ClickHouse/issues/65576) : correction d’un crash lors de la destruction d’AccessControl : ajout d’un arrêt explicite. [#64993](https://github.com/ClickHouse/ClickHouse/pull/64993) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#65159](https://github.com/ClickHouse/ClickHouse/issues/65159) : correction du déplacement des opérations arithmétiques hors de l’agrégation. Dans le nouvel analyseur, l’optimisation n’était appliquée qu’une seule fois. [#65104](https://github.com/ClickHouse/ClickHouse/pull/65104) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#65615](https://github.com/ClickHouse/ClickHouse/issues/65615) : correction de la réécriture des noms des fonctions d’agrégation dans le nouvel analyseur. [#65110](https://github.com/ClickHouse/ClickHouse/pull/65110) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#65728](https://github.com/ClickHouse/ClickHouse/issues/65728) : élimination récursive des fonctions injectives dans l’argument des fonctions `uniq*`. Cela fonctionnait auparavant correctement, mais a été cassé dans le nouvel analyseur. [#65140](https://github.com/ClickHouse/ClickHouse/pull/65140) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#65261](https://github.com/ClickHouse/ClickHouse/issues/65261) : correction d’un bug dans l’évaluation en court-circuit des dictionnaires Hashed et Hashed&#95;Array, qui pouvait lire un nombre non initialisé et entraîner diverses erreurs. [#65256](https://github.com/ClickHouse/ClickHouse/pull/65256) ([jsc0218](https://github.com/jsc0218)).
* Rétroporté dans [#65667](https://github.com/ClickHouse/ClickHouse/issues/65667) : désactivation de l’optimisation `non-intersecting-parts` pour les requêtes avec `FINAL` lorsque l’optimisation `read-in-order` est activée. Cela pouvait conduire à un résultat de la requête incorrect. Comme solution de contournement, désactivez `do_not_merge_across_partitions_select_final` et `split_parts_ranges_into_intersecting_and_non_intersecting_final` avant l’intégration de ce correctif. [#65505](https://github.com/ClickHouse/ClickHouse/pull/65505) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#65784](https://github.com/ClickHouse/ClickHouse/issues/65784) : correction d’un bug dans MergeJoin. Une colonne en sérialisation sparse pouvait être traitée comme une colonne de son type Nested alors que la conversion requise n’avait pas été effectuée. [#65632](https://github.com/ClickHouse/ClickHouse/pull/65632) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#65929](https://github.com/ClickHouse/ClickHouse/issues/65929) : pour les requêtes qui lisent depuis `PostgreSQL`, annulation de la requête interne `PostgreSQL` si la requête ClickHouse est terminée. Sinon, la requête `ClickHouse` ne peut pas être annulée tant que la requête interne `PostgreSQL` n’est pas terminée. [#65771](https://github.com/ClickHouse/ClickHouse/pull/65771) ([Maksim Kita](https://github.com/kitaisreal)).
* Rétroporté dans [#65824](https://github.com/ClickHouse/ClickHouse/issues/65824) : correction d’un bug dans la logique d’évaluation en court-circuit lorsque l’ancien analyseur et `dictGetOrDefault` sont utilisés. [#65802](https://github.com/ClickHouse/ClickHouse/pull/65802) ([jsc0218](https://github.com/jsc0218)).
