  ### Version ClickHouse v24.4.4.113-stable (d63a54957bd) FIXME par rapport à v24.4.3.25-stable (a915dd4eda4)

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#65884](https://github.com/ClickHouse/ClickHouse/issues/65884) : toujours démarrer Keeper avec un nombre suffisant de threads dans le pool global de threads. [#64444](https://github.com/ClickHouse/ClickHouse/pull/64444) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#65303](https://github.com/ClickHouse/ClickHouse/issues/65303) : rétablissement du comportement antérieur de ClickHouse pour le traitement et l’interprétation des Tuples au format CSV. Cette modification annule effectivement [https://github.com/ClickHouse/ClickHouse/pull/60994](https://github.com/ClickHouse/ClickHouse/pull/60994) et ne rend ce comportement disponible que via quelques paramètres : `output_format_csv_serialize_tuple_into_separate_columns`, `input_format_csv_deserialize_separate_columns_into_tuple` et `input_format_csv_try_infer_strings_from_quoted_tuples`. [#65170](https://github.com/ClickHouse/ClickHouse/pull/65170) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#65894](https://github.com/ClickHouse/ClickHouse/issues/65894) : prise en compte de la limite CPU du cgroup dans Keeper. [#65819](https://github.com/ClickHouse/ClickHouse/pull/65819) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="critical-bug-fix-crash-logical_error-data-loss-rbac">
  #### Correctif de bug critique (crash, LOGICAL_ERROR, perte de données, RBAC)
</div>

* Rétroporté dans [#65372](https://github.com/ClickHouse/ClickHouse/issues/65372) : correction d’un bug dans ClickHouse Keeper qui provoquait une incohérence de digest lors de la fermeture d’une session. [#65198](https://github.com/ClickHouse/ClickHouse/pull/65198) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#66883](https://github.com/ClickHouse/ClickHouse/issues/66883) : correction d’une taille inattendue d’une colonne à faible cardinalité dans les appels de fonction. [#65298](https://github.com/ClickHouse/ClickHouse/pull/65298) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#65435](https://github.com/ClickHouse/ClickHouse/issues/65435) : interdiction de la clause `QUALIFY` dans l’ancien analyseur. L’ancien analyseur ignorait `QUALIFY`, ce qui pouvait entraîner une suppression inattendue de données dans les mutations. [#65356](https://github.com/ClickHouse/ClickHouse/pull/65356) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#65448](https://github.com/ClickHouse/ClickHouse/issues/65448) : utilisation du bon alignement mémoire pour le combinateur Distinct. Auparavant, un crash pouvait se produire en raison d’une allocation mémoire invalide lorsque le combinateur était utilisé. [#65379](https://github.com/ClickHouse/ClickHouse/pull/65379) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#65710](https://github.com/ClickHouse/ClickHouse/issues/65710) : correction d’un crash dans maxIntersections. [#65689](https://github.com/ClickHouse/ClickHouse/pull/65689) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#66689](https://github.com/ClickHouse/ClickHouse/issues/66689) : correction de la réinitialisation de la clause VALID UNTIL dans la définition de l’utilisateur après un redémarrage. Résout [#66405](https://github.com/ClickHouse/ClickHouse/issues/66405). [#66409](https://github.com/ClickHouse/ClickHouse/pull/66409) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#67499](https://github.com/ClickHouse/ClickHouse/issues/67499) : correction d’un crash dans DistributedAsyncInsert lorsque la connexion est vide. [#67219](https://github.com/ClickHouse/ClickHouse/pull/67219) ([Pablo Marcos](https://github.com/pamarcos)).

[#65632](https://github.com/ClickHouse/ClickHouse/pull/65632) ([Nikita Taranov](https://github.com/nickitat)).
