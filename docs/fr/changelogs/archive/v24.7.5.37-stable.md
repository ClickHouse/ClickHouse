<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement erroné visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#68971](https://github.com/ClickHouse/ClickHouse/issues/68971) : corrige la borne supérieure de la fonction `fromModifiedJulianDay`. Elle aurait dû être `9999-12-31`, mais avait été définie par erreur sur `9999-01-01`. [#67583](https://github.com/ClickHouse/ClickHouse/pull/67583) ([PHO](https://github.com/depressed-pho)).
* Rétroporté dans [#68816](https://github.com/ClickHouse/ClickHouse/issues/68816) : corrige un crash dans le filtrage Parquet lorsque les types de données du fichier diffèrent sensiblement des types demandés (par ex. `... FROM file('a.parquet', Parquet, 'x String')`, alors que le fichier contient `x Int64`). Sans ce correctif, utilisez `input_format_parquet_filter_push_down = 0` comme solution de contournement. [#68131](https://github.com/ClickHouse/ClickHouse/pull/68131) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#69006](https://github.com/ClickHouse/ClickHouse/issues/69006) : après [https://github.com/ClickHouse/ClickHouse/pull/61984](https://github.com/ClickHouse/ClickHouse/pull/61984), `schema_inference_make_columns_nullable=0` peut encore rendre des colonnes `Nullable` dans les formats Parquet/Arrow. Ce changement n’était pas rétrocompatible et les utilisateurs ont remarqué la différence de comportement. Cette PR rétablit le fonctionnement précédent de `schema_inference_make_columns_nullable=0` (aucune colonne `Nullable` ne sera inférée) et introduit la nouvelle valeur `auto` pour ce paramètre, qui ne rendra les colonnes `Nullable` que si les données contiennent des informations de nullabilité. [#68298](https://github.com/ClickHouse/ClickHouse/pull/68298) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68884](https://github.com/ClickHouse/ClickHouse/issues/68884) : corrige [#50868](https://github.com/ClickHouse/ClickHouse/issues/50868). De petites valeurs constantes DateTime64 renvoyées par une sous-requête imbriquée dans une requête distribuée étaient incorrectement transformées en NULL, provoquant ainsi des erreurs et, potentiellement, des résultats de requête incorrects. [#68323](https://github.com/ClickHouse/ClickHouse/pull/68323) ([Shankar](https://github.com/shiyer7474)).
* Rétroporté dans [#69027](https://github.com/ClickHouse/ClickHouse/issues/69027) : rétablit les colonnes virtuelles ` _table` et `_database` dans les tables distribuées. Elles étaient disponibles jusqu’à la version 24.3. [#68672](https://github.com/ClickHouse/ClickHouse/pull/68672) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68862](https://github.com/ClickHouse/ClickHouse/issues/68862) : corrige l’erreur possible `Size of permutation (0) is less than required (...)` lors d’une permutation de colonne Variant. [#68681](https://github.com/ClickHouse/ClickHouse/pull/68681) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68788](https://github.com/ClickHouse/ClickHouse/issues/68788) : corrige un problème avec les clés constantes matérialisées lors du hachage de maps avec des arrays comme clés dans les fonctions `sipHash(64/128)Keyed`. [#68731](https://github.com/ClickHouse/ClickHouse/pull/68731) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Rétroporté dans [#68909](https://github.com/ClickHouse/ClickHouse/issues/68909) : corrige l’analyse des métadonnées de types complexes dans DeltaLake. Ferme [#68739](https://github.com/ClickHouse/ClickHouse/issues/68739). [#68836](https://github.com/ClickHouse/ClickHouse/pull/68836) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#69158](https://github.com/ClickHouse/ClickHouse/issues/69158) : corrige un résultat potentiellement erroné lors de la fusion de l’état anyHeavy. [#68950](https://github.com/ClickHouse/ClickHouse/pull/68950) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#69118](https://github.com/ClickHouse/ClickHouse/issues/69118) : corrige une erreur logique lorsqu’un `async insert` est vide. [#69080](https://github.com/ClickHouse/ClickHouse/pull/69080) ([Han Fei](https://github.com/hanfei1991)).
