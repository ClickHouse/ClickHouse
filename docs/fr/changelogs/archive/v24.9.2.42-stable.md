<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#70091](https://github.com/ClickHouse/ClickHouse/issues/70091) : ajout de `show_create_query_identifier_quoting_rule` pour définir le comportement de mise entre guillemets des identifiants dans le résultat de la requête SHOW CREATE. Valeurs possibles : - `user_display` : lorsque les identifiants sont des mots-clés. - `when_necessary` : lorsque les identifiants font partie de `{"distinct", "all", "table"}` ou qu’ils peuvent créer une ambiguïté : noms de colonnes, noms d’attributs de dictionnaire. - `always` : toujours mettre les identifiants entre guillemets. [#69448](https://github.com/ClickHouse/ClickHouse/pull/69448) ([tuanpach](https://github.com/tuanpach)).
* Rétroporté dans [#70100](https://github.com/ClickHouse/ClickHouse/issues/70100) : suite de [https://github.com/ClickHouse/ClickHouse/pull/69346](https://github.com/ClickHouse/ClickHouse/pull/69346). Le point 4 qui y est décrit fonctionne désormais également. [#69563](https://github.com/ClickHouse/ClickHouse/pull/69563) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#70048](https://github.com/ClickHouse/ClickHouse/issues/70048) : ajout d’une nouvelle colonne `readonly_duration` à la table `system.replicas`. Nécessaire pour distinguer les répliques `readonly` réelles des répliques sentinelles dans les alertes. [#69871](https://github.com/ClickHouse/ClickHouse/pull/69871) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
