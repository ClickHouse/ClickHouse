  # Journal des modifications de 2022

<div id="clickhouse-release-v212711-stable-fixme-as-compared-to-v21261-stable">
  ### Version ClickHouse v21.2.7.11-stable FIXME par rapport à la version v21.2.6.1-stable

<div id="bug-fix">
  #### Correctifs de bugs
</div>

* Rétroporté dans [#21206](https://github.com/ClickHouse/ClickHouse/issues/21206) : corrige la fuite de métadonnées lorsqu’un Replicated*MergeTree avec un cluster ZooKeeper personnalisé (non par défaut) est supprimé. [#21119](https://github.com/ClickHouse/ClickHouse/pull/21119) ([fastio](https://github.com/fastio)).
* Rétroporté dans [#21927](https://github.com/ClickHouse/ClickHouse/issues/21927) : corrige l’analyse du format Avro pour Kafka. Corrige [#21437](https://github.com/ClickHouse/ClickHouse/issues/21437). [#21438](https://github.com/ClickHouse/ClickHouse/pull/21438) ([Ilya Golshtein](https://github.com/ilejn)).
* Rétroporté dans [#21855](https://github.com/ClickHouse/ClickHouse/issues/21855) : corrige l’erreur possible ` Cannot find column` lorsque `optimize_skip_unused_shards` est activé et qu’aucun shard n’est utilisé. [#21579](https://github.com/ClickHouse/ClickHouse/pull/21579) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#21688](https://github.com/ClickHouse/ClickHouse/issues/21688) : corrige `fsync_part_directory` pour la fusion horizontale. [#21642](https://github.com/ClickHouse/ClickHouse/pull/21642) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#21795](https://github.com/ClickHouse/ClickHouse/issues/21795) : corrige l’annulation des requêtes distribuées (par exemple, un simple select sur plusieurs shards avec limit, c.-à-d. `select * from remote('127.{2,3}', system.numbers) limit 100`) avec `async_socket_for_remote=1`. [#21643](https://github.com/ClickHouse/ClickHouse/pull/21643) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#21879](https://github.com/ClickHouse/ClickHouse/issues/21879) : corrige des plantages possibles dans les fonctions d’agrégation avec le combinateur Distinct lors de l’utilisation de l’agrégation à deux niveaux. Il s’agit d’un correctif complémentaire à [https://github.com/ClickHouse/ClickHouse/pull/18365](https://github.com/ClickHouse/ClickHouse/pull/18365). Ne peut être reproduit qu’en environnement de production. Aucun cas de test n’est encore disponible. cc @CurtizJ. [#21818](https://github.com/ClickHouse/ClickHouse/pull/21818) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#21979](https://github.com/ClickHouse/ClickHouse/issues/21979) : annule [#15454](https://github.com/ClickHouse/ClickHouse/issues/15454), qui peut entraîner une augmentation significative de la consommation mémoire lors du chargement de dictionnaires externes de type hashé. Cela clôt [#21935](https://github.com/ClickHouse/ClickHouse/issues/21935). [#21948](https://github.com/ClickHouse/ClickHouse/pull/21948) ([Maksim Kita](https://github.com/kitaisreal)).
* Rétroporté dans [#22140](https://github.com/ClickHouse/ClickHouse/issues/22140) : la fonction `decrypt` ne vérifiait pas la taille minimale des données chiffrées en mode AEAD. Cela clôt [#21897](https://github.com/ClickHouse/ClickHouse/issues/21897). [#22064](https://github.com/ClickHouse/ClickHouse/pull/22064) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
