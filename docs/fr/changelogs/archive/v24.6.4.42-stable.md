<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#68066](https://github.com/ClickHouse/ClickHouse/issues/68066) : correction des littéraux booléens dans la requête envoyée à la base de données externe (pour des moteurs comme `PostgreSQL`). [#66282](https://github.com/ClickHouse/ClickHouse/pull/66282) ([vdimir](https://github.com/vdimir)).
* Rétroporté dans [#68566](https://github.com/ClickHouse/ClickHouse/issues/68566) : correction d’un cas de la fonction indexHint détecté par le fuzzer. [#66286](https://github.com/ClickHouse/ClickHouse/pull/66286) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68159](https://github.com/ClickHouse/ClickHouse/issues/68159) : correction de cluster() pour le secret inter-serveur (préserve l’utilisateur initial comme auparavant). [#66364](https://github.com/ClickHouse/ClickHouse/pull/66364) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#68116](https://github.com/ClickHouse/ClickHouse/issues/68116) : correction d’une possible erreur PARAMETER&#95;OUT&#95;OF&#95;BOUND lors de la lecture d’une sous-colonne Variant. [#66659](https://github.com/ClickHouse/ClickHouse/pull/66659) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#67887](https://github.com/ClickHouse/ClickHouse/issues/67887) : analyse correcte du nom de fichier/de l’URI contenant `::` s’il ne s’agit pas d’une archive. [#67433](https://github.com/ClickHouse/ClickHouse/pull/67433) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#68611](https://github.com/ClickHouse/ClickHouse/issues/68611) : corrige [#66026](https://github.com/ClickHouse/ClickHouse/issues/66026). Évite le parcours des arguments de table function non résolus dans `ReplaceTableNodeToDummyVisitor`. [#67522](https://github.com/ClickHouse/ClickHouse/pull/67522) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#68275](https://github.com/ClickHouse/ClickHouse/issues/68275) : correction de l’insertion dans des moteurs de type stream (Kafka, RabbitMQ, NATS) via l’interface HTTP. [#67554](https://github.com/ClickHouse/ClickHouse/pull/67554) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#67993](https://github.com/ClickHouse/ClickHouse/issues/67993) : validation des types de données expérimentaux/suspects dans ALTER ADD/MODIFY COLUMN. [#67911](https://github.com/ClickHouse/ClickHouse/pull/67911) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68208](https://github.com/ClickHouse/ClickHouse/issues/68208) : correction d’un résultat `count()` erroné lorsqu’une fonction non déterministe est présente dans le prédicat. [#67922](https://github.com/ClickHouse/ClickHouse/pull/67922) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#68093](https://github.com/ClickHouse/ClickHouse/issues/68093) : correction du calcul de la limite souple maximale du nombre de threads dans des environnements conteneurisés où le nombre de CPU utilisables est limité. [#67963](https://github.com/ClickHouse/ClickHouse/pull/67963) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#68124](https://github.com/ClickHouse/ClickHouse/issues/68124) : correction du saut des parts non modifiées dans les mutations avec le nouvel analyseur. Auparavant, avec l’analyseur activé, les données d’une part pouvaient être réécrites par une mutation même si celle-ci n’affectait pas cette part selon le prédicat. [#68052](https://github.com/ClickHouse/ClickHouse/pull/68052) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68221](https://github.com/ClickHouse/ClickHouse/issues/68221) : correction d’un déréférencement de pointeur NULL, déclenché par une requête spécialement conçue, qui faisait planter le serveur via hopEnd, hopStart, tumbleEnd et tumbleStart. [#68098](https://github.com/ClickHouse/ClickHouse/pull/68098) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Rétroporté dans [#68173](https://github.com/ClickHouse/ClickHouse/issues/68173) : suppression d’une optimisation incorrecte qui supprimait le tri dans les sous-requêtes utilisant `OFFSET`. Corrige [#67906](https://github.com/ClickHouse/ClickHouse/issues/67906). [#68099](https://github.com/ClickHouse/ClickHouse/pull/68099) ([Graham Campbell](https://github.com/GrahamCampbell)).
* Rétroporté dans [#68339](https://github.com/ClickHouse/ClickHouse/issues/68339) : tentative de correction d’un crash de Postgres lorsqu’une requête est annulée. [#68288](https://github.com/ClickHouse/ClickHouse/pull/68288) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#68396](https://github.com/ClickHouse/ClickHouse/issues/68396) : correction de l’absence du mode sync replica dans la requête `SYSTEM SYNC REPLICA`. [#68326](https://github.com/ClickHouse/ClickHouse/pull/68326) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#68668](https://github.com/ClickHouse/ClickHouse/issues/68668) : correction des `LOGICAL_ERROR` lorsque les fonctions `sipHash64Keyed`, `sipHash128Keyed` ou `sipHash128ReferenceKeyed` sont appliquées à des tableaux vides ou à des tuples. [#68630](https://github.com/ClickHouse/ClickHouse/pull/68630) ([Robert Schulze](https://github.com/rschu1ze)).
