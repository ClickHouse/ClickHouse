<div id="backward-incompatible-change">
  #### Modification non rétrocompatible
</div>

* Ajout de la prise en charge des commentaires multilignes imbriqués `/* comment /* comment */ */` en SQL. Cela est conforme à la norme SQL. [#14655](https://github.com/ClickHouse/ClickHouse/pull/14655) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Modification de la valeur par défaut du paramètre `format_regexp_escaping_rule` (lié au format `Regexp`) en `Raw` (c&#39;est-à-dire lire l&#39;intégralité du sous-motif comme une valeur) afin de rendre le comportement plus conforme à ce que les utilisateurs attendent. [#15426](https://github.com/ClickHouse/ClickHouse/pull/15426) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rend `multiple_joins_rewriter_version` obsolète. Supprime la première version du réécriveur de jointures. [#15472](https://github.com/ClickHouse/ClickHouse/pull/15472) ([Artem Zuikov](https://github.com/4ertus2)).

Cela clôt [#15349](https://github.com/ClickHouse/ClickHouse/issues/15349). [#15364](https://github.com/ClickHouse/ClickHouse/pull/15364) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Amélioration des performances des entiers 256 bits en utilisant `(u)int64_t` comme type de base pour les entiers larges. Les entiers larges d&#39;origine utilisent des types sur 8 bits comme base. [#14859](https://github.com/ClickHouse/ClickHouse/pull/14859) ([Artem Zuikov](https://github.com/4ertus2)).
* Verrouillage avec `mlock` du seul segment de code au démarrage de clickhouse-server. Dans les versions précédentes, toutes les régions mappées étaient verrouillées en mémoire, y compris les informations de débogage. Les informations de débogage sont généralement séparées dans un fichier distinct, mais si ce n&#39;est pas le cas, cela entraînait +2..3 GiB de consommation mémoire. [#14929](https://github.com/ClickHouse/ClickHouse/pull/14929) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nous utilisions auparavant la méthode fixed key pour regrouper sur une seule chaîne de longueur fixe. Ce n&#39;est pas nécessaire, car nous avons StringHashTable, qui applique une optimisation packedFix similaire pour les colonnes FixedString. Et nous devrions utiliser low&#95;cardinality&#95;key&#95;fixed&#95;string si possible. [#15034](https://github.com/ClickHouse/ClickHouse/pull/15034) ([Amos Bird](https://github.com/amosbird)).
* Correction de `DateTime <op> DateTime` qui choisissait par erreur l&#39;implémentation générique lente. Cela corrige [#15153](https://github.com/ClickHouse/ClickHouse/issues/15153). [#15178](https://github.com/ClickHouse/ClickHouse/pull/15178) ([Amos Bird](https://github.com/amosbird)).
* Utilisation d&#39;une seule requête S3 DeleteObjects au lieu de plusieurs DeleteObject dans une boucle. Aucun changement fonctionnel, cela est donc couvert par les tests existants comme integration/test&#95;log&#95;family&#95;s3. [#15238](https://github.com/ClickHouse/ClickHouse/pull/15238) ([ianton-ru](https://github.com/ianton-ru)).
* Multiplication 256 bits plus rapide. [#15418](https://github.com/ClickHouse/ClickHouse/pull/15418) ([Artem Zuikov](https://github.com/4ertus2)).
* Amélioration des performances de `quantileTDigest`. Cela corrige [#2668](https://github.com/ClickHouse/ClickHouse/issues/2668). [#15542](https://github.com/ClickHouse/ClickHouse/pull/15542) ([Kruglov Pavel](https://github.com/Avogar)).
* Utilisation explicite d&#39;un `disk` temporaire pour stocker les données temporaires de vertical merge. [#15639](https://github.com/ClickHouse/ClickHouse/pull/15639) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
