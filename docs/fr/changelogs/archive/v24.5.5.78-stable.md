<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#66768](https://github.com/ClickHouse/ClickHouse/issues/66768) : faire en sorte que `allow_experimental_analyzer` soit contrôlé par l’initiateur pour les requêtes distribuées. Cela garantit la compatibilité et l’exactitude lors des opérations sur des clusters composés de versions mixtes. [#65777](https://github.com/ClickHouse/ClickHouse/pull/65777) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="critical-bug-fix-crash-logical_error-data-loss-rbac">
  #### Correction de bug critique (plantage, LOGICAL_ERROR, perte de données, RBAC)
</div>

* Rétroporté dans [#66884](https://github.com/ClickHouse/ClickHouse/issues/66884) : correction d&#39;une taille inattendue d&#39;une colonne à faible cardinalité dans les appels de fonction. [#65298](https://github.com/ClickHouse/ClickHouse/pull/65298) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#66691](https://github.com/ClickHouse/ClickHouse/issues/66691) : correction de la clause VALID UNTIL dans la définition de l&#39;utilisateur, qui se réinitialisait après un redémarrage. Résout [#66405](https://github.com/ClickHouse/ClickHouse/issues/66405). [#66409](https://github.com/ClickHouse/ClickHouse/pull/66409) ([Nikolay Degterinsky](https://github.com/evillique)).
* Rétroporté dans [#67814](https://github.com/ClickHouse/ClickHouse/issues/67814) : concerne uniquement le type de données expérimental Variant. Correction d&#39;un plantage avec le type Variant + AggregateFunction. [#67122](https://github.com/ClickHouse/ClickHouse/pull/67122) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#67501](https://github.com/ClickHouse/ClickHouse/issues/67501) : correction d&#39;un plantage dans DistributedAsyncInsert lorsque la connexion est vide. [#67219](https://github.com/ClickHouse/ClickHouse/pull/67219) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#67850](https://github.com/ClickHouse/ClickHouse/issues/67850) : corrige [#66026](https://github.com/ClickHouse/ClickHouse/issues/66026). Évite de parcourir les arguments non résolus des fonctions de table dans `ReplaceTableNodeToDummyVisitor`. [#67522](https://github.com/ClickHouse/ClickHouse/pull/67522) ([Dmitry Novik](https://github.com/novikd)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#65350](https://github.com/ClickHouse/ClickHouse/issues/65350) : correction d’un arrêt possible en cas d’exception non gérée dans `~WriteBufferFromFileDescriptor` de StatusFile. [#64206](https://github.com/ClickHouse/ClickHouse/pull/64206) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#65621](https://github.com/ClickHouse/ClickHouse/issues/65621) : correction de l’erreur `Cannot find column` dans une distributed query avec `ARRAY JOIN` sur une colonne `Nested`. Corrige [#64755](https://github.com/ClickHouse/ClickHouse/issues/64755). [#64801](https://github.com/ClickHouse/ClickHouse/pull/64801) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#65933](https://github.com/ClickHouse/ClickHouse/issues/65933) : pour les requêtes lisant depuis `PostgreSQL`, annule la requête interne `PostgreSQL` si la requête ClickHouse est terminée. Sinon, la requête `ClickHouse` ne peut pas être annulée tant que la requête interne `PostgreSQL` n’est pas terminée. [#65771](https://github.com/ClickHouse/ClickHouse/pull/65771) ([Maksim Kita](https://github.com/kitaisreal)).
* Rétroporté dans [#66301](https://github.com/ClickHouse/ClickHouse/issues/66301) : meilleure gestion des conditions de join impliquant des vérifications `IS NULL` (par exemple, `ON (a = b AND (a IS NOT NULL) AND (b IS NOT NULL) ) OR ( (a IS NULL) AND (b IS NULL) )` est réécrit en `ON a <=> b`), correction d’une optimisation incorrecte lorsque des conditions autres que `IS NULL` sont présentes. [#65835](https://github.com/ClickHouse/ClickHouse/pull/65835) ([vdimir](https://github.com/vdimir)).
* Rétroporté dans [#66328](https://github.com/ClickHouse/ClickHouse/issues/66328) : ajout des settings manquants `input_format_csv_skip_first_lines/input_format_tsv_skip_first_lines/input_format_csv_try_infer_numbers_from_strings/input_format_csv_try_infer_strings_from_quoted_tuples` au cache de schema inference, car ils peuvent modifier le schéma résultant. Cela évite des résultats incorrects de schema inference lorsque ces settings sont modifiés. [#65980](https://github.com/ClickHouse/ClickHouse/pull/65980) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#66155](https://github.com/ClickHouse/ClickHouse/issues/66155) : correction d’un bug de dépassement de tampon dans l’implémentation de `unbin`/`unhex`. [#66106](https://github.com/ClickHouse/ClickHouse/pull/66106) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#66454](https://github.com/ClickHouse/ClickHouse/issues/66454) : correction d’un bug dans le client ZooKeeper : une session pouvait rester bloquée dans un état inutilisable après avoir reçu une erreur matérielle de ZooKeeper. Par exemple, cela peut se produire à cause de &quot;soft memory limit&quot; dans ClickHouse Keeper. [#66140](https://github.com/ClickHouse/ClickHouse/pull/66140) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#66226](https://github.com/ClickHouse/ClickHouse/issues/66226) : correction d’un problème dans SumIfToCountIfVisitor avec les entiers signés. [#66146](https://github.com/ClickHouse/ClickHouse/pull/66146) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#66680](https://github.com/ClickHouse/ClickHouse/issues/66680) : correction de la gestion de la limite pour `system.numbers_mt` lorsqu’aucun index ne peut être utilisé. [#66231](https://github.com/ClickHouse/ClickHouse/pull/66231) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#66604](https://github.com/ClickHouse/ClickHouse/issues/66604) : correction de la façon dont le ClickHouse server détecte le nombre maximal de CPU cores utilisables, tel que spécifié par cgroups v2, lorsque le server s’exécute dans un container tel que Docker. Plus précisément, les containers exécutent souvent leur processus dans le cgroup racine, qui a un nom vide. Dans ce cas, ClickHouse ignorait les limites de CPU définies par cgroups v2. [#66237](https://github.com/ClickHouse/ClickHouse/pull/66237) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#66360](https://github.com/ClickHouse/ClickHouse/issues/66360) : correction de l’erreur `Not-ready set` lorsqu’une sous-requête avec `IN` est utilisée dans la contrainte. [#66261](https://github.com/ClickHouse/ClickHouse/pull/66261) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66972](https://github.com/ClickHouse/ClickHouse/issues/66972) : correction de l’erreur `Column identifier is already registered` avec `group_by_use_nulls=true` et le nouvel analyseur. [#66400](https://github.com/ClickHouse/ClickHouse/pull/66400) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66969](https://github.com/ClickHouse/ClickHouse/issues/66969) : correction de l’erreur `Cannot find column` pour les requêtes avec une expression constante dans la clé `GROUP BY` et le nouvel analyseur activé. [#66433](https://github.com/ClickHouse/ClickHouse/pull/66433) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66720](https://github.com/ClickHouse/ClickHouse/issues/66720) : suivi correct de la mémoire pour `Allocator::realloc`. [#66548](https://github.com/ClickHouse/ClickHouse/pull/66548) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#66951](https://github.com/ClickHouse/ClickHouse/issues/66951) : correction d’un résultat incorrect pour les requêtes avec `WINDOW`. Cela pouvait se produire lorsque les colonnes `PARTITION` ont une sérialisation clairsemée et que les fonctions de fenêtre sont exécutées en parallèle. [#66579](https://github.com/ClickHouse/ClickHouse/pull/66579) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66757](https://github.com/ClickHouse/ClickHouse/issues/66757) : correction des erreurs `Unknown identifier` et `Column is not under aggregate function` pour les requêtes avec l’expression `(column IS NULL).` Le bug a été déclenché par [#65088](https://github.com/ClickHouse/ClickHouse/issues/65088), uniquement avec l’analyseur désactivé. [#66654](https://github.com/ClickHouse/ClickHouse/pull/66654) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#66948](https://github.com/ClickHouse/ClickHouse/issues/66948) : correction de l’erreur `Method getResultType is not supported for QUERY query node` lorsqu’une sous-requête scalaire était utilisée comme premier argument de `IN` (avec le nouvel analyseur). [#66655](https://github.com/ClickHouse/ClickHouse/pull/66655) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#67633](https://github.com/ClickHouse/ClickHouse/issues/67633) : correction d’un interblocage occasionnel dans Context::getDDLWorker. [#66843](https://github.com/ClickHouse/ClickHouse/pull/66843) ([Alexander Gololobov](https://github.com/davenger)).
* Rétroporté dans [#67481](https://github.com/ClickHouse/ClickHouse/issues/67481) : dans de rares cas, ClickHouse pouvait considérer des parts comme corrompues en raison de projections inattendues sur le disque. C’est désormais corrigé. [#66898](https://github.com/ClickHouse/ClickHouse/pull/66898) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#67197](https://github.com/ClickHouse/ClickHouse/issues/67197) : TRUNCATE DATABASE arrêtait la réplication comme s’il s’agissait d’une requête DROP DATABASE ; c’est corrigé. [#67129](https://github.com/ClickHouse/ClickHouse/pull/67129) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#67379](https://github.com/ClickHouse/ClickHouse/issues/67379) : correction de l’erreur `Cannot convert column because it is non constant in source stream but must be constant in result.` pour une requête qui lit depuis la table `Merge` sur une table `Distriburted` avec un shard. * Rétroporté dans [#67576](https://github.com/ClickHouse/ClickHouse/issues/67576) : correction de l’exécution des fonctions imbriquées à court-circuit. [#67520](https://github.com/ClickHouse/ClickHouse/pull/67520) ([Kruglov Pavel](https://github.com/Avogar)).
