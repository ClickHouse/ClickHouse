<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#68969](https://github.com/ClickHouse/ClickHouse/issues/68969) : corrige la borne supérieure de la fonction `fromModifiedJulianDay`. Elle aurait dû être `9999-12-31`, mais avait été définie par erreur sur `9999-01-01`. [#67583](https://github.com/ClickHouse/ClickHouse/pull/67583) ([PHO](https://github.com/depressed-pho)).
* Rétroporté dans [#68814](https://github.com/ClickHouse/ClickHouse/issues/68814) : corrige un crash dans le filtrage Parquet lorsque les types de données du fichier diffèrent fortement des types demandés (par ex. `... FROM file('a.parquet', Parquet, 'x String')`, alors que le fichier contient `x Int64`). Sans ce correctif, utilisez `input_format_parquet_filter_push_down = 0` comme solution de contournement. [#68131](https://github.com/ClickHouse/ClickHouse/pull/68131) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#69005](https://github.com/ClickHouse/ClickHouse/issues/69005) : après [https://github.com/ClickHouse/ClickHouse/pull/61984](https://github.com/ClickHouse/ClickHouse/pull/61984), `schema_inference_make_columns_nullable=0` peut encore rendre des colonnes `Nullable` dans les formats Parquet/Arrow. Ce changement n’était pas rétrocompatible et les utilisateurs ont remarqué la différence de comportement. Cette PR rétablit le comportement précédent de `schema_inference_make_columns_nullable=0` (aucune colonne `Nullable` ne sera inférée) et introduit une nouvelle valeur, `auto`, pour ce paramètre, afin de rendre les colonnes `Nullable` uniquement si les données contiennent des informations de nullabilité. [#68298](https://github.com/ClickHouse/ClickHouse/pull/68298) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68883](https://github.com/ClickHouse/ClickHouse/issues/68883) : corrige [#50868](https://github.com/ClickHouse/ClickHouse/issues/50868). De petites valeurs constantes DateTime64 renvoyées par une sous-requête imbriquée dans une requête distribuée étaient incorrectement transformées en NULL, provoquant ainsi des erreurs et possiblement des résultats de requête incorrects. [#68323](https://github.com/ClickHouse/ClickHouse/pull/68323) ([Shankar](https://github.com/shiyer7474)).
* Rétroporté dans [#69025](https://github.com/ClickHouse/ClickHouse/issues/69025) : réajoute les colonnes virtuelles ` _table` et `_database` aux tables distribuées. Elles étaient disponibles jusqu’à la version 24.3. [#68672](https://github.com/ClickHouse/ClickHouse/pull/68672) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#68860](https://github.com/ClickHouse/ClickHouse/issues/68860) : corrige l’erreur possible `Size of permutation (0) is less than required (...)` lors de la permutation d’une colonne Variant. [#68681](https://github.com/ClickHouse/ClickHouse/pull/68681) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#68786](https://github.com/ClickHouse/ClickHouse/issues/68786) : corrige un problème avec les clés constantes matérialisées lors du hachage de maps avec des arrays comme clés dans les fonctions `sipHash(64/128)Keyed`. [#68731](https://github.com/ClickHouse/ClickHouse/pull/68731) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Rétroporté dans [#69156](https://github.com/ClickHouse/ClickHouse/issues/69156) : corrige un résultat potentiellement incorrect lors de la fusion de l’état anyHeavy. [#68950](https://github.com/ClickHouse/ClickHouse/pull/68950) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#69116](https://github.com/ClickHouse/ClickHouse/issues/69116) : corrige une logical error en présence d’un async insert vide. [#69080](https://github.com/ClickHouse/ClickHouse/pull/69080) ([Han Fei](https://github.com/hanfei1991)).
