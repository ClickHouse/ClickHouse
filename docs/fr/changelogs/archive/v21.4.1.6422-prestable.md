<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Désormais, les répliques qui traitent la commande `ALTER TABLE ATTACH PART[ITION]` recherchent dans leurs dossiers `detached/` avant de récupérer les données depuis d&#39;autres répliques. Au niveau de l&#39;implémentation, une nouvelle commande `ATTACH_PART` est introduite dans le journal répliqué. Les parts sont recherchées et comparées à l&#39;aide de leurs checksums. [#18978](https://github.com/ClickHouse/ClickHouse/pull/18978) ([Mike Kot](https://github.com/myrrc)).
* La colonne `keys` de la table `system.dictionaries` a été remplacée par les colonnes `key.names` et `key.types`. Les colonnes `key.names`, `key.types`, `attribute.names`, `attribute.types` de la table `system.dictionaries` ne nécessitent pas le chargement du dictionnaire. [#21884](https://github.com/ClickHouse/ClickHouse/pull/21884) ([Maksim Kita](https://github.com/kitaisreal)).
* Correction de `cutToFirstSignificantSubdomainCustom()`/`firstSignificantSubdomainCustom()`, qui renvoyait un résultat incorrect pour les domaines à 3 niveaux ou plus présents dans la liste personnalisée de domaines de premier niveau. Pour les domaines d&#39;entrée correspondant à ces domaines de premier niveau personnalisés, le domaine de troisième niveau était considéré comme le premier domaine significatif. C&#39;est désormais corrigé. Ce changement peut introduire une incompatibilité si la fonction est utilisée, par exemple, dans la clé de sharding. [#21946](https://github.com/ClickHouse/ClickHouse/pull/21946) ([Azat Khuzhin](https://github.com/azat)).
* `toStartOfIntervalFunction` alignera les intervalles d&#39;heures sur minuit (dans les versions précédentes, ils étaient alignés sur le début de l&#39;Unix epoch). Par exemple, `toStartOfInterval(x, INTERVAL 11 HOUR)` divisera chaque journée en trois intervalles : 00:00:00..10:59:59, 11:00:00..21:59:59 et 22:00:00..23:59:59. Ce comportement est plus adapté aux besoins pratiques. Cela clôt [#9510](https://github.com/ClickHouse/ClickHouse/issues/9510). [#22060](https://github.com/ClickHouse/ClickHouse/pull/22060) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Prise en charge de l&#39;analyse parallèle pour les formats `CSVWithNames` et `TSVWithNames`. Cela corrige [#21085](https://github.com/ClickHouse/ClickHouse/issues/21085). [#21149](https://github.com/ClickHouse/ClickHouse/pull/21149) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Amélioration des performances grâce au remplacement de `memcpy` par une autre implémentation. Cela corrige [#18583](https://github.com/ClickHouse/ClickHouse/issues/18583). [#21520](https://github.com/ClickHouse/ClickHouse/pull/21520) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Prise en charge du formatage parallèle dans clickhouse-local et ailleurs. [#21630](https://github.com/ClickHouse/ClickHouse/pull/21630) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Optimisation des performances des requêtes du type `SELECT ... FINAL ... WHERE`. Désormais, dans les requêtes avec `FINAL`, il est possible de déplacer vers `PREWHERE` les colonnes présentes dans la clé de tri. ... [#21830](https://github.com/ClickHouse/ClickHouse/pull/21830) ([foolchi](https://github.com/foolchi)).
* `GROUP BY` plus rapide avec une faible valeur de `max_rows_to_group_by` et `group_by_overflow_mode='any'`. [#21856](https://github.com/ClickHouse/ClickHouse/pull/21856) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Évite les copies de données inutiles lors de l&#39;utilisation du codec `NONE`. Veuillez noter que le codec `NONE` est globalement peu utile : il est recommandé d&#39;utiliser systématiquement la Compression (`LZ4` est utilisée par défaut). Contrairement à une idée répandue, désactiver la compression n&#39;améliore pas nécessairement les performances (l&#39;effet inverse est possible). Le codec `NONE` est utile dans certains cas : - lorsque les données ne sont pas compressibles ; - pour des benchmarks synthétiques. [#22145](https://github.com/ClickHouse/ClickHouse/pull/22145) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout d&#39;un cache pour les fichiers lus avec le paramètre `min_bytes_to_use_mmap_io`. Cela apporte une amélioration significative des performances (2x et plus) lorsque la valeur du paramètre est faible, en évitant les appels fréquents à mmap/munmap et les défauts de page qui en résultent. Notez que les E/S mmap présentent des inconvénients majeurs qui les rendent moins fiables en production (par ex. blocage ou SIGBUS sur des disques défectueux ; utilisation de la mémoire moins contrôlable). Néanmoins, elles sont utiles pour les benchmarks. [#22206](https://github.com/ClickHouse/ClickHouse/pull/22206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Active la lecture via mmap IO pour les plages de fichiers à partir de 64 MiB (paramètre `min_bytes_to_use_mmap_io`). Cela peut entraîner une amélioration modérée des performances. [#22326](https://github.com/ClickHouse/ClickHouse/pull/22326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
