<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogues (comportement incorrect visible par l&#39;utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#45908](https://github.com/ClickHouse/ClickHouse/issues/45908) : correction d&#39;un bogue lié à une valeur par défaut impossible à analyser pour une colonne EPHEMERAL dans les métadonnées de la table. [#44026](https://github.com/ClickHouse/ClickHouse/pull/44026) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Rétroporté dans [#46238](https://github.com/ClickHouse/ClickHouse/issues/46238) : quelques segfaults ont été signalés autour de `c-ares`. Toutes les traces de pile récentes observées échouent lors de l&#39;insertion dans `std::unodered_set<>`. Je pense avoir trouvé la cause racine : il semble qu&#39;il s&#39;agisse de requêtes non traitées. Avant cette PR, CH appelait `poll` pour attendre sur les descripteurs de fichiers dans le canal `c-ares`. D&#39;après la [documentation de poll](https://man7.org/linux/man-pages/man2/poll.2.html), une valeur de retour négative signifie qu&#39;une erreur s&#39;est produite. Pour cette raison, nous interrompions l&#39;exécution et renvoyions un échec. Le problème est que `poll` renvoie également une valeur négative lorsqu&#39;une interruption système se produit. Une interruption système ne signifie pas que le traitement a échoué ou s&#39;est terminé, mais nous l&#39;interrompions malgré tout parce que nous vérifiions les valeurs négatives. Une fois l&#39;exécution interrompue, toute la pile est détruite, y compris le `std::unordered_set<std::string>` passé au paramètre `void *` du callback c-ares. Une fois que c-ares avait terminé la requête, le callback était invoqué et accédait à une adresse mémoire invalide, provoquant un segfault. [#45629](https://github.com/ClickHouse/ClickHouse/pull/45629) ([Arthur Passos](https://github.com/arthurpassos)).
* Rétroporté dans [#45727](https://github.com/ClickHouse/ClickHouse/issues/45727) : correction de la description de clé en cas de clés primaires dupliquées. Cela peut se produire dans les projections. Voir [#45590](https://github.com/ClickHouse/ClickHouse/issues/45590) pour plus de détails. [#45686](https://github.com/ClickHouse/ClickHouse/pull/45686) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#46394](https://github.com/ClickHouse/ClickHouse/issues/46394) : correction des requêtes `SYSTEM UNFREEZE` qui échouaient avec l&#39;exception `CANNOT_PARSE_INPUT_ASSERTION_FAILED`. [#46325](https://github.com/ClickHouse/ClickHouse/pull/46325) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#46442](https://github.com/ClickHouse/ClickHouse/issues/46442) : correction d&#39;un possible `LOGICAL_ERROR` dans les asynchronous inserts avec des données invalides envoyées au format `VALUES`. [#46350](https://github.com/ClickHouse/ClickHouse/pull/46350) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#46674](https://github.com/ClickHouse/ClickHouse/issues/46674) : correction d&#39;un traitement incorrect de l&#39;argument constant `LowCardinality` dans la fonction `arrayMap`. Ce bogue pouvait entraîner un segfault dans la version release, ainsi qu&#39;une logical error `Bad cast` dans une build de débogage. [#46569](https://github.com/ClickHouse/ClickHouse/pull/46569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#46879](https://github.com/ClickHouse/ClickHouse/issues/46879) : correction d&#39;un rapport MSan dans la fonction `maxIntersections`. Cela clôt [#43126](https://github.com/ClickHouse/ClickHouse/issues/43126). [#46847](https://github.com/ClickHouse/ClickHouse/pull/46847) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#46871](https://github.com/ClickHouse/ClickHouse/issues/46871) : correction d&#39;un bogue dans le type de données `Map`. Cela clôt [#46855](https://github.com/ClickHouse/ClickHouse/issues/46855). [#46856](https://github.com/ClickHouse/ClickHouse/pull/46856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
