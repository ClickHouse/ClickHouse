  ### Version de ClickHouse v24.5.4.49-stable (63b760955a0) FIXME par rapport à v24.5.3.5-stable (e0eb66f8e17)

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#65886](https://github.com/ClickHouse/ClickHouse/issues/65886) : toujours démarrer Keeper avec un nombre suffisant de threads dans le pool global de threads. [#64444](https://github.com/ClickHouse/ClickHouse/pull/64444) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#65304](https://github.com/ClickHouse/ClickHouse/issues/65304) : rétablissement du comportement précédent de ClickHouse pour le traitement et l’interprétation des Tuples au format CSV. Cette modification annule effectivement [https://github.com/ClickHouse/ClickHouse/pull/60994](https://github.com/ClickHouse/ClickHouse/pull/60994) et ne le rend disponible que via quelques paramètres : `output_format_csv_serialize_tuple_into_separate_columns`, `input_format_csv_deserialize_separate_columns_into_tuple` et `input_format_csv_try_infer_strings_from_quoted_tuples`. [#65170](https://github.com/ClickHouse/ClickHouse/pull/65170) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#65896](https://github.com/ClickHouse/ClickHouse/issues/65896) : prise en compte de la limite CPU du cgroup dans Keeper. [#65819](https://github.com/ClickHouse/ClickHouse/pull/65819) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="critical-bug-fix-crash-logical_error-data-loss-rbac">
  #### Correctif de bug critique (plantage, LOGICAL_ERROR, perte de données, RBAC)
</div>

* Rétroporté dans [#65287](https://github.com/ClickHouse/ClickHouse/issues/65287) : corrige un plantage avec UniqInjectiveFunctionsEliminationPass et uniqCombined. [#65188](https://github.com/ClickHouse/ClickHouse/pull/65188) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#65374](https://github.com/ClickHouse/ClickHouse/issues/65374) : corrige un bug dans ClickHouse Keeper provoquant une discordance de digest lors de la fermeture d’une session. [#65198](https://github.com/ClickHouse/ClickHouse/pull/65198) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Rétroporté dans [#65437](https://github.com/ClickHouse/ClickHouse/issues/65437) : interdit la clause `QUALIFY` dans l’ancien analyseur. L’ancien analyseur ignorait `QUALIFY`, ce qui pouvait entraîner une suppression de données inattendue dans les mutations. [#65356](https://github.com/ClickHouse/ClickHouse/pull/65356) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#65450](https://github.com/ClickHouse/ClickHouse/issues/65450) : utilise le bon alignement mémoire pour le combinateur Distinct. Auparavant, un plantage pouvait survenir en raison d’une allocation mémoire invalide lors de l’utilisation du combinateur. [#65379](https://github.com/ClickHouse/ClickHouse/pull/65379) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#65712](https://github.com/ClickHouse/ClickHouse/issues/65712) : corrige un plantage dans maxIntersections. [#65689](https://github.com/ClickHouse/ClickHouse/pull/65689) ([Raúl Marín](https://github.com/Algunenano)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#65681](https://github.com/ClickHouse/ClickHouse/issues/65681) : correction de l’erreur `duplicate alias` pour les requêtes distribuées avec `ARRAY JOIN`. [#64226](https://github.com/ClickHouse/ClickHouse/pull/64226) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#65331](https://github.com/ClickHouse/ClickHouse/issues/65331) : correction de la boucle de plantage lorsque la restauration à partir d’une sauvegarde est bloquée par la création d’une MV avec un définisseur qui n’a pas encore été restauré. [#64595](https://github.com/ClickHouse/ClickHouse/pull/64595) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#64835](https://github.com/ClickHouse/ClickHouse/issues/64835) : correction d’un bug pouvant empêcher le bon fonctionnement des TTL avec des expressions. [#64694](https://github.com/ClickHouse/ClickHouse/pull/64694) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#65542](https://github.com/ClickHouse/ClickHouse/issues/65542) : correction d’un crash avec `ALTER TABLE ... ON CLUSTER ... MODIFY SQL SECURITY`. [#64957](https://github.com/ClickHouse/ClickHouse/pull/64957) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#65580](https://github.com/ClickHouse/ClickHouse/issues/65580) : correction d’un crash lors de la destruction d’AccessControl : ajout d’un arrêt explicite. [#64993](https://github.com/ClickHouse/ClickHouse/pull/64993) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#65618](https://github.com/ClickHouse/ClickHouse/issues/65618) : correction d’une durée d’exécution potentiellement infinie des requêtes en cas d’alias cycliques. Corrige [#64849](https://github.com/ClickHouse/ClickHouse/issues/64849). [#65081](https://github.com/ClickHouse/ClickHouse/pull/65081) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#65617](https://github.com/ClickHouse/ClickHouse/issues/65617) : correction de la réécriture des noms de fonctions d’agrégation dans le nouvel analyseur. [#65110](https://github.com/ClickHouse/ClickHouse/pull/65110) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#65732](https://github.com/ClickHouse/ClickHouse/issues/65732) : élimination récursive de la fonction injective dans l’argument des fonctions `uniq*`. Cela fonctionnait correctement auparavant, mais a été cassé dans le nouvel analyseur. [#65140](https://github.com/ClickHouse/ClickHouse/pull/65140) ([Duc Canh Le](https://github.com/canhld94)).
* Rétroporté dans [#65265](https://github.com/ClickHouse/ClickHouse/issues/65265) : correction d’un bug dans l’évaluation en court-circuit des dictionnaires Hashed et Hashed&#95;Array, qui pouvait lire un nombre non initialisé et provoquer diverses erreurs. [#65256](https://github.com/ClickHouse/ClickHouse/pull/65256) ([jsc0218](https://github.com/jsc0218)).
* Rétroporté dans [#65663](https://github.com/ClickHouse/ClickHouse/issues/65663) : désactivation de l’optimisation `non-intersecting-parts` pour les requêtes avec `FINAL` lorsque l’optimisation `read-in-order` était activée. Cela pouvait entraîner un résultat de la requête incorrect. Comme solution de contournement, désactivez `do_not_merge_across_partitions_select_final` et `split_parts_ranges_into_intersecting_and_non_intersecting_final` avant l’intégration de ce correctif. [#65505](https://github.com/ClickHouse/ClickHouse/pull/65505) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#65788](https://github.com/ClickHouse/ClickHouse/issues/65788) : correction d’un bug dans MergeJoin. Une colonne en sérialisation sparse pouvait être traitée comme une colonne de son type Nested alors que la conversion requise n’avait pas été effectuée. [#65632](https://github.com/ClickHouse/ClickHouse/pull/65632) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#65812](https://github.com/ClickHouse/ClickHouse/issues/65812) : correction d’exceptions incorrectes dans la fonction `parseDateTime` avec les placeholders `%F` et `%D`. [#65768](https://github.com/ClickHouse/ClickHouse/pull/65768) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#65828](https://github.com/ClickHouse/ClickHouse/issues/65828) : correction d’un bug dans la logique de court-circuit lors de l’utilisation de l’ancien analyseur avec dictGetOrDefault. [#65802](https://github.com/ClickHouse/ClickHouse/pull/65802) ([jsc0218](https://github.com/jsc0218)).
