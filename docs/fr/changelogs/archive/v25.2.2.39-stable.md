<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Rétroporté dans [#77183](https://github.com/ClickHouse/ClickHouse/issues/77183) : désactivation des répliques parallèles par défaut lorsque l’analyseur est désactivé, quel que soit le paramètre `compatibility`. Il est toujours possible de modifier ce comportement en définissant explicitement `parallel_replicas_only_with_analyzer` sur `false`. [#77115](https://github.com/ClickHouse/ClickHouse/pull/77115) ([Igor Nikonov](https://github.com/devcrafter)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Rétroporté dans [#77358](https://github.com/ClickHouse/ClickHouse/issues/77358) : ajout du paramètre serveur `concurrent_threads_scheduler`, qui détermine la façon dont les slots CPU sont répartis entre les requêtes concurrentes. Il peut être défini sur `round_robin` (comportement précédent) ou `fair_round_robin` pour corriger le problème de répartition inéquitable du CPU entre les INSERTs et les SELECTs. [#75949](https://github.com/ClickHouse/ClickHouse/pull/75949) ([Sergei Trifonov](https://github.com/serxa)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#76999](https://github.com/ClickHouse/ClickHouse/issues/76999) : correction d’une perte de données lorsque async insert est activé et qu’un `insert into ... from file ...` est exécuté avec des tailles de block inégales : si la taille du premier block est &lt; async&#95;max&#95;size mais que celle du second est &gt; async&#95;max&#95;size, le second block n’est pas inséré. Ces données restent dans `squashing`. [#76343](https://github.com/ClickHouse/ClickHouse/pull/76343) ([Han Fei](https://github.com/hanfei1991)).
* Rétroporté dans [#76970](https://github.com/ClickHouse/ClickHouse/issues/76970) : correction de l’exception THERE&#95;IS&#95;NO&#95;COLUMN lors de la sélection d’un littéral booléen à partir de tables distribuées. [#76656](https://github.com/ClickHouse/ClickHouse/pull/76656) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Rétroporté dans [#77049](https://github.com/ClickHouse/ClickHouse/issues/77049) : correction de la gestion des exceptions lors de la désérialisation en parallèle des préfixes des sous-colonnes JSON. [#76809](https://github.com/ClickHouse/ClickHouse/pull/76809) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#77260](https://github.com/ClickHouse/ClickHouse/issues/77260) : correction d’un plantage possible dû à un rollback incorrect d’une JSON column en cas d’erreur pendant les async inserts. [#76908](https://github.com/ClickHouse/ClickHouse/pull/76908) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#77064](https://github.com/ClickHouse/ClickHouse/issues/77064) : correction du tri des valeurs `BFloat16`. Ceci clôt [#75487](https://github.com/ClickHouse/ClickHouse/issues/75487). Ceci clôt [#75669](https://github.com/ClickHouse/ClickHouse/issues/75669). [#77000](https://github.com/ClickHouse/ClickHouse/pull/77000) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#77222](https://github.com/ClickHouse/ClickHouse/issues/77222) : correction d’un bogue lié à JSON avec une sous-colonne Variant, en ajoutant une vérification pour ignorer les sous-colonnes éphémères lors du contrôle de cohérence des parts. [#72187](https://github.com/ClickHouse/ClickHouse/issues/72187). [#77034](https://github.com/ClickHouse/ClickHouse/pull/77034) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Rétroporté dans [#77250](https://github.com/ClickHouse/ClickHouse/issues/77250) : correction d’un plantage lors de la création d’une table Kafka avec exception. [#77121](https://github.com/ClickHouse/ClickHouse/pull/77121) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#77240](https://github.com/ClickHouse/ClickHouse/issues/77240) : prise en charge du nouveau JSON et des sous-colonnes dans les moteurs Kafka et RabbitMQ. [#77122](https://github.com/ClickHouse/ClickHouse/pull/77122) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#77386](https://github.com/ClickHouse/ClickHouse/issues/77386) : `SELECT toBFloat16(-0.0) == toBFloat16(0.0)` renvoie désormais correctement `true` (au lieu de `false` auparavant). * Rétroporté dans [#77379](https://github.com/ClickHouse/ClickHouse/issues/77379) : correction du nom de partition pour une valeur Bool.
