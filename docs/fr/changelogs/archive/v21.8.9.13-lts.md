<div id="improvement">
  #### Amélioration

* Rétroporté dans [#29941](https://github.com/ClickHouse/ClickHouse/issues/29941) : mise à jour des fichiers zoneinfo vers la version 2021c. [#29925](https://github.com/ClickHouse/ClickHouse/pull/29925) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="bug-fix">
  #### Correction de bogue
</div>

* Rétroporté dans [#29817](https://github.com/ClickHouse/ClickHouse/issues/29817) : autorise l’utilisation d’une colonne matérialisée comme clé de sharding dans une table distribuée, même si `insert_allow_materialized_columns=0`:. [#28637](https://github.com/ClickHouse/ClickHouse/pull/28637) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#29973](https://github.com/ClickHouse/ClickHouse/issues/29973) : corrige l’arrêt de `AccessControlManager`. Désormais, la configuration ne peut plus être rechargée après la destruction d’AccessControlManager. Cette PR corrige le test instable [test&#95;user&#95;directories/test.py::test&#95;relative&#95;path](https://clickhouse-test-reports.s3.yandex.net/0/f0e3122507ed8bea3f177495531c7d56bcb32466/integration_tests_\(thread\).html). [#29951](https://github.com/ClickHouse/ClickHouse/pull/29951) ([Vitaly Baranov](https://github.com/vitlibar)).

<div id="bug-fix-user-visible-misbehaviour-in-official-stable-release">
  #### Correction de bogue (dysfonctionnement observable par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#29676](https://github.com/ClickHouse/ClickHouse/issues/29676) : corrige les fusions verticales des projection parts. Cela corrige [#29253](https://github.com/ClickHouse/ClickHouse/issues/29253). Cette PR corrige également plusieurs problèmes de fusion/mutation de projections introduits dans [https://github.com/ClickHouse/ClickHouse/pull/25165](https://github.com/ClickHouse/ClickHouse/pull/25165). [#29337](https://github.com/ClickHouse/ClickHouse/pull/29337) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#29538](https://github.com/ClickHouse/ClickHouse/issues/29538) : corrige une possible erreur `Block structure mismatch` pour des sous-requêtes avec prédicat `HAVING` poussé vers le bas. Corrige [#29010](https://github.com/ClickHouse/ClickHouse/issues/29010). [#29475](https://github.com/ClickHouse/ClickHouse/pull/29475) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#29589](https://github.com/ClickHouse/ClickHouse/issues/29589) : dans ODBC bridge, ajoute des tentatives supplémentaires pour l’erreur Invalid cursor state. Cette erreur peut faire l’objet d’une nouvelle tentative. Clôt [#29473](https://github.com/ClickHouse/ClickHouse/issues/29473). [#29518](https://github.com/ClickHouse/ClickHouse/pull/29518) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#29593](https://github.com/ClickHouse/ClickHouse/issues/29593) : corrige un bogue dans la vérification `pathStartsWith`, dû à un bogue dans l’utilisation de `std::mismatch` : ` The behavior is undefined if the second range is shorter than the first range.`. [#29531](https://github.com/ClickHouse/ClickHouse/pull/29531) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#29628](https://github.com/ClickHouse/ClickHouse/issues/29628) : corrige un rare segfault dans la requête `ALTER MODIFY` lors de l’utilisation d’un identifiant de table incorrect dans une expression `DEFAULT` telle que `x.y.z...`. Corrige [#29184](https://github.com/ClickHouse/ClickHouse/issues/29184). [#29573](https://github.com/ClickHouse/ClickHouse/pull/29573) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#29752](https://github.com/ClickHouse/ClickHouse/issues/29752) : la condition du prédicat de filtrage pouvait être perdue après l’optimisation de push-down. [#29625](https://github.com/ClickHouse/ClickHouse/pull/29625) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#29840](https://github.com/ClickHouse/ClickHouse/issues/29840) : corrige le comportement incorrect du paramètre `materialized_postgresql_tables_list` au redémarrage du serveur. Problème identifié dans [#28529](https://github.com/ClickHouse/ClickHouse/issues/28529). [#29686](https://github.com/ClickHouse/ClickHouse/pull/29686) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#29847](https://github.com/ClickHouse/ClickHouse/issues/29847) : corrige l’accès concurrent à `LowCardinality` pendant `GROUP BY` (ce qui entraîne un SIGSEGV). [#29782](https://github.com/ClickHouse/ClickHouse/pull/29782) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#29911](https://github.com/ClickHouse/ClickHouse/issues/29911) : corrige un CAST incorrect dans la requête `ATTACH TABLE ... FROM 'path'` lorsqu’un littéral non-chaîne est utilisé à la place du chemin. Cela peut entraîner la lecture d’une mémoire non initialisée. [#29790](https://github.com/ClickHouse/ClickHouse/pull/29790) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#29867](https://github.com/ClickHouse/ClickHouse/issues/29867) : évite l’erreur `Timeout exceeded: elapsed 18446744073.709553 seconds`, qui peut se produire dans des cas extrêmement rares, vraisemblablement en raison d’un bogue du noyau. Corrige [#29154](https://github.com/ClickHouse/ClickHouse/issues/29154). [#29811](https://github.com/ClickHouse/ClickHouse/pull/29811) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#29877](https://github.com/ClickHouse/ClickHouse/issues/29877) : corrige la vérification de recréation des tables système (elle ne détectait pas les changements dans les valeurs de l’enum). [#29857](https://github.com/ClickHouse/ClickHouse/pull/29857) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#30210](https://github.com/ClickHouse/ClickHouse/issues/30210) : corrige une possible course critique entre `FileChecker` et `StorageLog`/`StorageStripeLog`. [#29959](https://github.com/ClickHouse/ClickHouse/pull/29959) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#30069](https://github.com/ClickHouse/ClickHouse/issues/30069) : corrige un crash de sample avec `tuple()`, clôt [#30004](https://github.com/ClickHouse/ClickHouse/issues/30004). [#30016](https://github.com/ClickHouse/ClickHouse/pull/30016) ([flynn](https://github.com/ucasfl)).
* Rétroporté dans [#30125](https://github.com/ClickHouse/ClickHouse/issues/30125) : une base de données `Memory` supprimée pouvait réapparaître après le redémarrage du server ; c’est corrigé ([#29795](https://github.com/ClickHouse/ClickHouse/issues/29795)). Ajout également du paramètre `force_remove_data_recursively_on_drop` comme solution de contournement pour l’erreur `Directory not empty` lors de la suppression d’une base de données `Ordinary` (car il n’est pas possible de supprimer manuellement les résidus de données dans un environnement cloud). [#30054](https://github.com/ClickHouse/ClickHouse/pull/30054) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#30263](https://github.com/ClickHouse/ClickHouse/issues/30263) : FlatDictionary et HashedDictionary corrigent le calcul de `bytes&#95;allocated` pour les attributs nullable. [#30238](https://github.com/ClickHouse/ClickHouse/pull/30238) ([Maksim Kita](https://github.com/kitaisreal)).
