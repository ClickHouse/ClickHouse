<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Rétroporté dans [#43484](https://github.com/ClickHouse/ClickHouse/issues/43484) : correction d&#39;une incompatibilité avec les versions précédentes dans la (dé)sérialisation des états des fonctions d&#39;agrégation `min`, `max`, `any*`, `argMin`, `argMax` avec un argument `String`. L&#39;incompatibilité a été introduite dans [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431) et affecte les branches 22.9, 22.10 et 22.11 (corrigé respectivement à partir des versions 22.9.6, 22.10.4 et 22.11.2). Certaines versions mineures des branches 22.3, 22.7 et 22.8 sont également affectées : 22.3.13...22.3.14 (corrigé à partir de 22.3.15), 22.8.6...22.8.9 (corrigé à partir de 22.8.10), 22.7.6 et suivantes (ne sera pas corrigé dans 22.7, nous recommandons de passer de 22.7.* à 22.8.10 ou à une version ultérieure). Cette note de version ne concerne pas les utilisateurs qui n&#39;ont jamais utilisé les versions affectées. Les versions incompatibles ajoutent un `'\0'` supplémentaire aux chaînes lors de la lecture des états des fonctions d&#39;agrégation mentionnées ci-dessus. Par exemple, si une ancienne version a enregistré l&#39;état de `anyState('foobar')` dans `state_column`, une version incompatible affichera alors `'foobar\0'` avec `anyMerge(state_column)`. Les versions incompatibles écrivent également les états des fonctions d&#39;agrégation sans le `'\0'` final. Les versions plus récentes (qui incluent le correctif) peuvent lire correctement les données écrites par toutes les versions, y compris les versions incompatibles, sauf dans un cas particulier. Si une version incompatible a enregistré un état avec une chaîne qui se termine réellement par un caractère nul, une version plus récente supprimera alors le `'\0'` final lors de la lecture de l&#39;état de la fonction d&#39;agrégation affectée. Par exemple, si une version incompatible a enregistré l&#39;état de `anyState('abrac\0dabra\0')` dans `state_column`, les versions incompatibles afficheront alors `'abrac\0dabra'` avec `anyMerge(state_column)`. Le problème affecte également les requêtes distribuées lorsqu&#39;une version incompatible fonctionne dans un cluster avec des versions plus anciennes ou plus récentes. [#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#42839](https://github.com/ClickHouse/ClickHouse/issues/42839) : mise à jour de tzdata vers 2022f. Le Mexique n’observera plus l’heure d’été, sauf à proximité de la frontière avec les États-Unis : [https://www.timeanddate.com/news/time/mexico-abolishes-dst-2022.html](https://www.timeanddate.com/news/time/mexico-abolishes-dst-2022.html). Chihuahua passera à UTC-6 toute l’année à partir du 2022-10-30. Les Fidji n’observent plus l’heure d’été. Voir [https://github.com/google/cctz/pull/235](https://github.com/google/cctz/pull/235) et [https://bugs.launchpad.net/ubuntu/+source/tzdata/+bug/1995209](https://bugs.launchpad.net/ubuntu/+source/tzdata/+bug/1995209). [#42796](https://github.com/ClickHouse/ClickHouse/pull/42796) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
