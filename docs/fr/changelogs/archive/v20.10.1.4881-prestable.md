<div id="backward-incompatible-change">
  #### Changement rétrocompatible non pris en charge
</div>

* Ajout de la prise en charge des commentaires multilignes imbriqués `/* comment /* comment */ */` en SQL. Cela est conforme à la norme SQL. [#14655](https://github.com/ClickHouse/ClickHouse/pull/14655) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Modification de la valeur par défaut du paramètre `format_regexp_escaping_rule` (lié au format `Regexp`) en `Raw` (c&#39;est-à-dire : lire l&#39;intégralité du sous-motif comme une valeur) afin d&#39;obtenir un comportement plus conforme aux attentes des utilisateurs. [#15426](https://github.com/ClickHouse/ClickHouse/pull/15426) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `multiple_joins_rewriter_version` devient obsolète. Suppression de la première version du réécriveur de jointures. [#15472](https://github.com/ClickHouse/ClickHouse/pull/15472) ([Artem Zuikov](https://github.com/4ertus2)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Activer les parts compactes par défaut pour les petites parts. Cela permettra de traiter des inserts fréquents avec une efficacité légèrement meilleure (de 4 à 100 fois). [#11913](https://github.com/ClickHouse/ClickHouse/pull/11913) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Amélioration des performances sur les valeurs 256 bits en utilisant `(u)int64_t` comme type de base pour les entiers larges. Les entiers larges d&#39;origine utilisent des types 8 bits comme base. [#14859](https://github.com/ClickHouse/ClickHouse/pull/14859) ([Artem Zuikov](https://github.com/4ertus2)).
* Verrouiller uniquement le segment de code avec `mlock` au démarrage de clickhouse-server. Dans les versions précédentes, toutes les régions mappées étaient verrouillées en mémoire, y compris les informations de Débogage. Les informations de Débogage sont généralement séparées dans un fichier distinct, mais lorsque ce n&#39;était pas le cas, cela entraînait une consommation mémoire supplémentaire de +2..3 GiB. [#14929](https://github.com/ClickHouse/ClickHouse/pull/14929) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nous choisissions auparavant la méthode fixed key pour effectuer un Group By sur une seule colonne de type Fixed String. C&#39;est inutile, puisque nous avons `StringHashTable`, qui applique une optimisation packedFix similaire pour les colonnes `FixedString`. Et nous devrions utiliser `low_cardinality_key_fixed_string` lorsque c&#39;est possible. [#15034](https://github.com/ClickHouse/ClickHouse/pull/15034) ([Amos Bird](https://github.com/amosbird)).
* Correction d&#39;un choix erroné de l&#39;implémentation générique lente pour `DateTime <op> DateTime`. Cela corrige [#15153](https://github.com/ClickHouse/ClickHouse/issues/15153). [#15178](https://github.com/ClickHouse/ClickHouse/pull/15178) ([Amos Bird](https://github.com/amosbird)).
* Utiliser une seule request S3 DeleteObjects au lieu de plusieurs DeleteObject dans une boucle. Aucun changement fonctionnel ; cela reste donc couvert par les tests existants, comme integration/test&#95;log&#95;family&#95;s3. [#15238](https://github.com/ClickHouse/ClickHouse/pull/15238) ([ianton-ru](https://github.com/ianton-ru)).
* Multiplication 256 bits plus rapide. [#15418](https://github.com/ClickHouse/ClickHouse/pull/15418) ([Artem Zuikov](https://github.com/4ertus2)).
* Amélioration des performances de `quantileTDigest`. Cela corrige [#2668](https://github.com/ClickHouse/ClickHouse/issues/2668). [#15542](https://github.com/ClickHouse/ClickHouse/pull/15542) ([Kruglov Pavel](https://github.com/Avogar)).
* Utiliser explicitement un disk temporaire pour stocker les données temporaires de la vertical merge. [#15639](https://github.com/ClickHouse/ClickHouse/pull/15639) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).

Cependant, les opérateurs binaires ne sont pas monotones, et cette PR tente de corriger cela. Cela peut également bénéficier à d’autres cas d’usage.
