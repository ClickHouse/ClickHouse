<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Le format de sortie Parquet convertit les colonnes Date et DateTime en types date/heure pris en charge par Parquet, au lieu de les écrire sous forme de nombres bruts. DateTime devient DateTime64(3) (au lieu de : UInt32) ; le paramètre `output_format_parquet_datetime_as_uint32` rétablit l’ancien comportement. Date devient Date32 (au lieu de : UInt16). [#70950](https://github.com/ClickHouse/ClickHouse/pull/70950) ([Michael Kolupaev](https://github.com/al13n321)).
* Les types non comparables (comme JSON/Object/AggregateFunction) ne sont plus autorisés par défaut dans ORDER BY ni dans les fonctions de comparaison `less/greater/equal/etc`. [#73276](https://github.com/ClickHouse/ClickHouse/pull/73276) ([Pavel Kruglov](https://github.com/Avogar)).
* `JSONEachRowWithProgress` écrira désormais la progression à chaque mise à jour. Dans les versions précédentes, la progression n’était affichée qu’après chaque bloc de résultat, ce qui la rendait inutile. Le mode d’affichage de la progression change : les valeurs nulles ne seront plus affichées. Gardez à l’esprit que la progression est envoyée même si les mises à jour sont fréquentes. Cela peut générer un volume de trafic important. Gardez également à l’esprit que la progression n’est pas vidée lorsque la sortie est compressée. Cela clôt [#70800](https://github.com/ClickHouse/ClickHouse/issues/70800). [#73834](https://github.com/ClickHouse/ClickHouse/pull/73834) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Le moteur de base de données obsolète `MaterializedMySQL` a été supprimé et n’est plus disponible. [#73879](https://github.com/ClickHouse/ClickHouse/pull/73879) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La source de dictionnaire `mysql` n’exécute plus la requête `SHOW TABLE STATUS`, car elle n’apporte aucune valeur pour les tables InnoDB, ni pour les versions récentes de MySQL. Cela clôt [#72636](https://github.com/ClickHouse/ClickHouse/issues/72636). Ce changement est rétrocompatible, mais il est placé dans cette catégorie afin d’attirer votre attention. [#73914](https://github.com/ClickHouse/ClickHouse/pull/73914) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Les tables `Merge` unifieront la structure des tables sous-jacentes en utilisant l’union de leurs colonnes et en en déduisant des types communs. Cela clôt [#64864](https://github.com/ClickHouse/ClickHouse/issues/64864). Dans certains cas, ce changement peut être incompatible avec les versions précédentes. Par exemple, lorsqu’il n’existe aucun type commun entre les tables, mais qu’une conversion vers le type de la première table reste possible, comme dans le cas de UInt64 et Int64 ou de tout type numérique vers String. Si vous souhaitez revenir à l’ancien comportement, définissez `merge_table_max_tables_to_look_for_schema_inference` sur `1` ou `compatibility` sur `24.12` ou une version antérieure. [#73956](https://github.com/ClickHouse/ClickHouse/pull/73956) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Les requêtes `CHECK TABLE` nécessitent désormais un privilège `CHECK` distinct. Dans les versions précédentes, il suffisait de disposer du privilège `SHOW TABLES` pour exécuter ces requêtes. Or, une requête `CHECK TABLE` peut être lourde, et les limites habituelles de complexité des requêtes `SELECT` ne s’y appliquent pas. Cela pouvait entraîner un risque de DoS. [#74471](https://github.com/ClickHouse/ClickHouse/pull/74471) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La fonction `h3ToGeo()` renvoie désormais les résultats dans l’ordre `(lat, lon)` (qui est l’ordre standard pour les fonctions géométriques). Les utilisateurs qui souhaitent conserver l’ordre de résultat legacy `(lon, lat)` peuvent définir le paramètre `h3togeo_lon_lat_result_order = true`. [#74719](https://github.com/ClickHouse/ClickHouse/pull/74719) ([Manish Gill](https://github.com/mgill25)).



<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Une interface SSH a été ajoutée. Il est désormais possible de se connecter au serveur ClickHouse à l’aide de n’importe quel client SSH et d’exécuter des requêtes de manière interactive en utilisant un PTY avec un `clickhouse-client` intégré. [#48902](https://github.com/ClickHouse/ClickHouse/pull/48902) ([George Gamezardashvili](https://github.com/InfJoker)).
* Ajout d’un cache en mémoire pour les granules d’index de skipping désérialisées. Cela devrait accélérer les requêtes répétées qui utilisent des index de skipping. La taille du nouveau cache est contrôlée par les paramètres du serveur `skipping_index_cache_size` et `skipping_index_cache_max_entries`. La motivation initiale de ce cache était les vector similarity indexes, qui sont désormais nettement plus rapides. [#70102](https://github.com/ClickHouse/ClickHouse/pull/70102) ([Robert Schulze](https://github.com/rschu1ze)).
* Implémentation du partition pruning des tables Iceberg pour les opérations de transformation de partition liées au temps dans Iceberg. [#72044](https://github.com/ClickHouse/ClickHouse/pull/72044) ([Daniil Ivanik](https://github.com/divanik)).
* Ajout de la possibilité de créer par défaut des index min-max (de skipping) pour les colonnes gérées par MergeTree à l’aide des paramètres `enable_minmax_index_for_all_numeric_columns` (pour les colonnes numériques) et `enable_minmax_index_for_all_string_columns` (pour les colonnes de type String). Pour le moment, ces deux paramètres sont désactivés ; il n’y a donc encore aucun changement de comportement. [#72090](https://github.com/ClickHouse/ClickHouse/pull/72090) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Ajout de la fonction d’aggregation `sequenceMatchEvents`, qui renvoie les timestamps des événements correspondants pour la plus longue chaîne d’événements du pattern. [#72349](https://github.com/ClickHouse/ClickHouse/pull/72349) ([UnamedRus](https://github.com/UnamedRus)).
* Les statements `SELECT` et `VIEW` prennent désormais en charge les alias, par exemple `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);`. Cela permet à la requête TPC-H 15 de s’exécuter sans modification. [#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout de la fonction `arrayNormalizedGini`. [#72823](https://github.com/ClickHouse/ClickHouse/pull/72823) ([flynn](https://github.com/ucasfl)).
* Lorsque `min_age_to_force_merge_seconds` et `min_age_to_force_merge_on_partition_only` sont tous deux activés, le part merging ignorera la limite maximale en octets. [#73656](https://github.com/ClickHouse/ClickHouse/pull/73656) ([Kai Zhu](https://github.com/nauu)).
* Prise en charge de la lecture des valeurs HALF&#95;FLOAT depuis Apache Arrow/Parquet/ORC (elles sont lues en Float32). Cela clôt [#72960](https://github.com/ClickHouse/ClickHouse/issues/72960). Gardez à l’esprit que le format half float IEEE-754 n’est pas identique à BFloat16. Clôt [#73835](https://github.com/ClickHouse/ClickHouse/issues/73835). [#73836](https://github.com/ClickHouse/ClickHouse/pull/73836) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La table `system.trace_log` contiendra deux nouvelles colonnes, `symbols` et `lines`, contenant une stack trace symbolisée. Cela facilite la collecte et l’export des informations de profilage. Ceci est contrôlé par la valeur de configuration du serveur `symbolize` dans `trace_log` et est activé par défaut. [#73896](https://github.com/ClickHouse/ClickHouse/pull/73896) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout d’une nouvelle fonction, `generateSerialID`, qui peut être utilisée pour générer des nombres auto-incrémentés dans les tables. Suite de [#64310](https://github.com/ClickHouse/ClickHouse/issues/64310) par [kazalika](https://github.com/kazalika). Cela clôt [#62485](https://github.com/ClickHouse/ClickHouse/issues/62485). [#73950](https://github.com/ClickHouse/ClickHouse/pull/73950) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout de la syntaxe `query1 PARALLEL WITH query2 PARALLEL WITH query3 ... PARALLEL WITH queryN` Cela signifie que les sous-requêtes `{query1, query2, ... queryN}` peuvent s’exécuter en parallèle les unes des autres (et c’est préférable). [#73983](https://github.com/ClickHouse/ClickHouse/pull/73983) ([Vitaly Baranov](https://github.com/vitlibar)).
* Désormais, l’interface Play affiche une barre de progression pendant l’exécution des requêtes. Elle permet d’annuler les requêtes. Elle affiche le nombre total d’enregistrements ainsi que des informations détaillées sur le débit. Le tableau peut être affiché de manière incrémentale dès l’arrivée des données. La compression HTTP est activée. Le rendu du tableau est devenu plus rapide. L’en-tête du tableau reste fixe. Il est possible de sélectionner des cellules et de s’y déplacer avec les touches fléchées. Correction d’un problème où le contour de la cellule sélectionnée la faisait paraître plus petite. Les cellules ne s’agrandissent plus au survol de la souris, mais uniquement lors de la sélection. Le moment où le rendu des données entrantes s’arrête est désormais déterminé côté client plutôt que côté serveur. Les groupes de chiffres dans les nombres sont désormais mis en évidence. Le design général a été revu et est devenu plus affirmé. L’interface vérifie si le serveur est joignable et si les identifiants sont corrects, puis affiche la version du serveur et son temps de fonctionnement. L’icône cloud est détourée dans toutes les polices, y compris dans Safari. Les grands entiers à l’intérieur de types de données imbriqués seront mieux affichés. Les valeurs inf/nan seront affichées correctement. Les types de données seront affichés au survol de l’en-tête d’une colonne. [#74204](https://github.com/ClickHouse/ClickHouse/pull/74204) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout de la possibilité de créer par défaut des index min-max (skipping) pour les colonnes gérées par MergeTree à l’aide des paramètres `add_minmax_index_for_numeric_columns` (pour les colonnes numériques) et `add_minmax_index_for_string_columns` (pour les colonne de type String). Pour l’instant, ces deux paramètres sont désactivés, il n’y a donc encore aucun changement de comportement. [#74266](https://github.com/ClickHouse/ClickHouse/pull/74266) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Ajout des champs `script_query_number` et `script_line_number` à `system.query_log`, à ClientInfo dans le native protocol, ainsi qu’aux server logs. Cela clôt [#67542](https://github.com/ClickHouse/ClickHouse/issues/67542). Remerciements à [pinsvin00](https://github.com/pinsvin00) pour avoir lancé plus tôt le développement de cette fonctionnalité dans [#68133](https://github.com/ClickHouse/ClickHouse/issues/68133). [#74477](https://github.com/ClickHouse/ClickHouse/pull/74477) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout de la prise en charge de l’opérateur moins pour DateTime64, afin d’autoriser la soustraction entre des valeurs DateTime64, ainsi qu’entre des valeurs DateTime. [#74482](https://github.com/ClickHouse/ClickHouse/pull/74482) ([Li Yin](https://github.com/liyinsg)).
* Rétroporté dans [#75020](https://github.com/ClickHouse/ClickHouse/issues/75020) : ajout de la possibilité d’appliquer des mutations non terminées (non materialized par un processus d’arrière-plan) lors de l’exécution des requêtes `SELECT`, immédiatement après leur soumission. Cela peut être activé en définissant `apply_mutations_on_fly`. [#74877](https://github.com/ClickHouse/ClickHouse/pull/74877) ([Anton Popov](https://github.com/CurtizJ)).





<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Commencer par comparer les lignes en utilisant d’abord les colonnes les plus susceptibles d’être différentes. [#63780](https://github.com/ClickHouse/ClickHouse/pull/63780) ([UnamedRus](https://github.com/UnamedRus)).
* Optimiser le format d’entrée RowBinary. Clôt [#63805](https://github.com/ClickHouse/ClickHouse/issues/63805). [#65059](https://github.com/ClickHouse/ClickHouse/pull/65059) ([Pavel Kruglov](https://github.com/Avogar)).
* Accélérer la désérialisation des chaînes grâce à des optimisations de bas niveau. [#65948](https://github.com/ClickHouse/ClickHouse/pull/65948) ([Nikita Taranov](https://github.com/nickitat)).
* Améliorer les performances du grace hash join en réordonnant la table de jointure de droite selon les clés. [#72237](https://github.com/ClickHouse/ClickHouse/pull/72237) ([kevinyhzou](https://github.com/KevinyhZou)).
* Permettre à `arrayROCAUC` et `arrayAUCPR` de calculer une aire partielle de la courbe complète, afin de paralléliser ce calcul sur de très grands jeux de données. [#72904](https://github.com/ClickHouse/ClickHouse/pull/72904) ([Emmanuel](https://github.com/emmanuelsdias)).
* Éviter de créer trop de threads inactifs. [#72920](https://github.com/ClickHouse/ClickHouse/pull/72920) ([Guo Wangyang](https://github.com/guowangy)).
* Le découpage par hash des blocs de la table de gauche a été supprimé de la phase probe de l’algorithme JOIN `parallel_hash`. [#73089](https://github.com/ClickHouse/ClickHouse/pull/73089) ([Nikita Taranov](https://github.com/nickitat)).
* Ne pas lister les clés du blob storage lorsqu’il n’y a qu’une expansion par accolades dans la table function. Clôt [#73333](https://github.com/ClickHouse/ClickHouse/issues/73333). [#73518](https://github.com/ClickHouse/ClickHouse/pull/73518) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Annuler « Annuler “Optimisation short-circuit pour les fonctions exécutées sur des arguments Nullable” ». Ajouter un chemin rapide pour les fonctions dont tous les types d’arguments sont numériques. Corrige des problèmes de performances dans https://github.com/ClickHouse/ClickHouse/pull/72258. [#73820](https://github.com/ClickHouse/ClickHouse/pull/73820) ([李扬](https://github.com/taiyang-li)).
* Ne pas appliquer `maskedExecute` aux colonnes qui ne sont pas des fonctions, et améliorer les performances de l’exécution short-circuit. [#73965](https://github.com/ClickHouse/ClickHouse/pull/73965) ([lgbo](https://github.com/lgbo-ustc)).
* Désactiver la détection d’en-tête pour Kafka/NATS/RabbitMQ/FileLog afin d’améliorer les performances. [#74006](https://github.com/ClickHouse/ClickHouse/pull/74006) ([Azat Khuzhin](https://github.com/azat)).
* Utiliser les wrappers de log par valeur et ne pas les allouer sur le tas. [#74034](https://github.com/ClickHouse/ClickHouse/pull/74034) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Exécuter le pipeline avec un degré de parallélisme plus élevé après l’agrégation avec grouping sets. [#74082](https://github.com/ClickHouse/ClickHouse/pull/74082) ([Nikita Taranov](https://github.com/nickitat)).
* Réduire la section critique dans `MergeTreeReadPool`. [#74202](https://github.com/ClickHouse/ClickHouse/pull/74202) ([Guo Wangyang](https://github.com/guowangy)).
* Optimiser la fonction `indexHint`. Désormais, les colonnes utilisées uniquement comme arguments de la fonction `indexHint` ne sont pas lues depuis la table. [#74314](https://github.com/ClickHouse/ClickHouse/pull/74314) ([Anton Popov](https://github.com/CurtizJ)).
* Amélioration des performances des parallel replicas. La désérialisation des paquets sur l’initiateur de query, pour les paquets non liés au protocole des parallel replicas, s’effectue désormais toujours dans le thread du pipeline. Auparavant, elle pouvait se produire dans un thread chargé de l’ordonnancement du pipeline, ce qui pouvait rendre l’initiateur moins réactif et retarder l’exécution du pipeline. [#74398](https://github.com/ClickHouse/ClickHouse/pull/74398) ([Igor Nikonov](https://github.com/devcrafter)).
* Rétroporté dans [#75069](https://github.com/ClickHouse/ClickHouse/issues/75069) : correction du calcul de la taille en mémoire pour les colonnes `LowCardinality`. [#74688](https://github.com/ClickHouse/ClickHouse/pull/74688) ([Nikita Taranov](https://github.com/nickitat)).
