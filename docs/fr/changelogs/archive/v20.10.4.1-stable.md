  ### Version de ClickHouse v20.10.4.1-stable FIXME par rapport à v20.10.3.30-stable
</div>

<div id="improvement">
  #### Amélioration
</div>

* Solution de contournement pour l&#39;utilisation de S3 avec le serveur nginx comme proxy. Actuellement, nginx n&#39;accepte pas les URL avec un chemin vide, comme [http://domain.com?delete](http://domain.com?delete), mais la version standard d&#39;aws-sdk-cpp produit ce type d&#39;URL. Ce commit utilise une version patchée d&#39;aws-sdk-cpp, qui, dans ce cas, génère des URL avec &quot;/&quot; comme chemin, comme [http://domain.com/?delete](http://domain.com/?delete). [#16813](https://github.com/ClickHouse/ClickHouse/pull/16813) ([ianton-ru](https://github.com/ianton-ru)).

<div id="bug-fix">
  #### Correction de bogues
</div>

* Rétroporté dans [#16492](https://github.com/ClickHouse/ClickHouse/issues/16492) : correction d’un bogue lié à la base de données MySQL. Lorsque le serveur MySQL utilisé comme moteur de base de données est indisponible, certaines requêtes lèvent une Exception, car elles tentent de récupérer les tables depuis un serveur désactivé, alors que ce n’est pas nécessaire. Par exemple, la requête `SELECT ... FROM system.parts` ne devrait fonctionner qu’avec les tables MergeTree et ne pas accéder du tout à la base de données MySQL. [#16032](https://github.com/ClickHouse/ClickHouse/pull/16032) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#16710](https://github.com/ClickHouse/ClickHouse/issues/16710) : correction d’un comportement incohérent où une partie des données renvoyées pouvait être supprimée parce que l’ensemble utilisé pour le filtrage n’avait pas été créé. [#16308](https://github.com/ClickHouse/ClickHouse/pull/16308) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#16505](https://github.com/ClickHouse/ClickHouse/issues/16505) : correction du traitement de très grandes entrées dans la file d’attente de réplication. De très grandes entrées peuvent apparaître dans les requêtes ALTER si la structure de la table est extrêmement volumineuse (près de 1 Mo). Cela corrige [#16307](https://github.com/ClickHouse/ClickHouse/issues/16307). [#16332](https://github.com/ClickHouse/ClickHouse/pull/16332) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#16471](https://github.com/ClickHouse/ClickHouse/issues/16471) : correction de DROP TABLE pour Distributed (condition de concurrence avec INSERT). [#16409](https://github.com/ClickHouse/ClickHouse/pull/16409) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16572](https://github.com/ClickHouse/ClickHouse/issues/16572) : correction de la croissance rapide des métadonnées lors de l’utilisation de MySQL Master -&gt; MySQL Slave -&gt; ClickHouse MaterializeMySQL Engine, avec `slave_parallel_worker` activé sur le MySQL Slave, grâce à une réduction correcte des ensembles GTID. Cela corrige [#15951](https://github.com/ClickHouse/ClickHouse/issues/15951). [#16504](https://github.com/ClickHouse/ClickHouse/pull/16504) ([TCeason](https://github.com/TCeason)).
* Rétroporté dans [#16551](https://github.com/ClickHouse/ClickHouse/issues/16551) : désormais, lors de l’analyse d’AVRO en entrée, LowCardinality est supprimé du type. Corrige [#16188](https://github.com/ClickHouse/ClickHouse/issues/16188). [#16521](https://github.com/ClickHouse/ClickHouse/pull/16521) ([Mike Kot](https://github.com/myrrc)).
* Rétroporté dans [#16749](https://github.com/ClickHouse/ClickHouse/issues/16749) : correction de [#16081](https://github.com/ClickHouse/ClickHouse/issues/16081). [#16613](https://github.com/ClickHouse/ClickHouse/pull/16613) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#16760](https://github.com/ClickHouse/ClickHouse/issues/16760) : correction de optimize&#95;read&#95;in&#95;order/optimize&#95;aggregation&#95;in&#95;order avec max&#95;threads&gt;0 et une expression dans ORDER BY. [#16637](https://github.com/ClickHouse/ClickHouse/pull/16637) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16741](https://github.com/ClickHouse/ClickHouse/issues/16741) : correction de l’opérateur `IN` sur plusieurs colonnes et tuples avec le paramètre `transform_null_in` activé. Corrige [#15310](https://github.com/ClickHouse/ClickHouse/issues/15310). [#16722](https://github.com/ClickHouse/ClickHouse/pull/16722) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#16893](https://github.com/ClickHouse/ClickHouse/issues/16893) : corrige de rares plantages silencieux lorsque le profileur de requêtes est activé et que ClickHouse est installé sur un système d’exploitation avec une version de glibc qui comporte (apparemment) des tables de désempilage asynchrones défectueuses pour certaines fonctions. Cela corrige [#15301](https://github.com/ClickHouse/ClickHouse/issues/15301). Cela corrige [#13098](https://github.com/ClickHouse/ClickHouse/issues/13098).
