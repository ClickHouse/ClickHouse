<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#58660](https://github.com/ClickHouse/ClickHouse/issues/58660) : lors de l&#39;exécution de certaines requêtes, qui nécessitent un grand nombre de flux pour lire les données, l&#39;erreur `"Paste JOIN requires sorted tables only"` était auparavant renvoyée. Désormais, dans ce cas, le nombre de flux est ramené à 1. [#58608](https://github.com/ClickHouse/ClickHouse/pull/58608) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#58817](https://github.com/ClickHouse/ClickHouse/issues/58817) : ajout de `SYSTEM JEMALLOC PURGE` pour purger les pages jemalloc inutilisées, et de `SYSTEM JEMALLOC [ ENABLE | DISABLE | FLUSH ] PROFILE` pour contrôler le profil jemalloc si le profiler est activé. Ajout également de commandes 4LW liées à jemalloc dans Keeper : `jmst` pour produire un dump des statistiques jemalloc, `jmfp`, `jmep`, `jmdp` pour contrôler le profil jemalloc si le profiler est activé. [#58665](https://github.com/ClickHouse/ClickHouse/pull/58665) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#59235](https://github.com/ClickHouse/ClickHouse/issues/59235) : permet d&#39;ignorer l&#39;évolution du schéma dans le moteur de table Iceberg et de lire toutes les données en utilisant soit le schéma spécifié par l&#39;utilisateur lors de la création de la table, soit le dernier schéma analysé à partir des métadonnées lors de la création de la table. Cela se fait via le paramètre `iceberg_engine_ignore_schema_evolution`, qui est désactivé par défaut. Notez que l&#39;activation de ce paramètre peut conduire à un résultat incorrect, car en cas d&#39;évolution du schéma, tous les fichiers de données seront lus avec le même schéma. [#59133](https://github.com/ClickHouse/ClickHouse/pull/59133) ([Kruglov Pavel](https://github.com/Avogar)).
