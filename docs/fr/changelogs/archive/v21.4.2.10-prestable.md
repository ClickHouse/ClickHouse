<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* La colonne `keys` de la table `system.dictionaries` a été remplacée par les colonnes `key.names` et `key.types`. Les colonnes `key.names`, `key.types`, `attribute.names` et `attribute.types` de la table `system.dictionaries` ne nécessitent pas que le dictionnaire soit chargé. [#21884](https://github.com/ClickHouse/ClickHouse/pull/21884) ([Maksim Kita](https://github.com/kitaisreal)).
* Correction de `cutToFirstSignificantSubdomainCustom()`/`firstSignificantSubdomainCustom()`, qui renvoyaient un résultat incorrect pour les domaines à 3 niveaux ou plus présents dans la liste personnalisée des top-level domains. Pour les domaines d&#39;entrée correspondant à ces top-level domains personnalisés, le domaine de troisième niveau était considéré comme le premier sous-domaine significatif. Ce problème est désormais corrigé. Ce changement peut introduire une incompatibilité si la fonction est utilisée, par exemple, dans la clé de sharding. [#21946](https://github.com/ClickHouse/ClickHouse/pull/21946) ([Azat Khuzhin](https://github.com/azat)).
* `toStartOfIntervalFunction` alignera les intervalles horaires sur minuit (dans les versions précédentes, ils étaient alignés sur le début de l&#39;epoch Unix). Par exemple, `toStartOfInterval(x, INTERVAL 11 HOUR)` divisera chaque journée en trois intervalles : 00:00:00..10:59:59, 11:00:00..21:59:59 et 22:00:00..23:59:59. Ce comportement est mieux adapté aux besoins pratiques. Cela corrige [#9510](https://github.com/ClickHouse/ClickHouse/issues/9510). [#22060](https://github.com/ClickHouse/ClickHouse/pull/22060) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Prise en charge du parsing parallèle pour les formats `CSVWithNames` et `TSVWithNames`. Cela clôt [#21085](https://github.com/ClickHouse/ClickHouse/issues/21085). [#21149](https://github.com/ClickHouse/ClickHouse/pull/21149) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Amélioration des performances en remplaçant `memcpy` par une autre implémentation. Cela clôt [#18583](https://github.com/ClickHouse/ClickHouse/issues/18583). [#21520](https://github.com/ClickHouse/ClickHouse/pull/21520) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Prise en charge de la mise en forme parallèle dans clickhouse-local ainsi que partout ailleurs. [#21630](https://github.com/ClickHouse/ClickHouse/pull/21630) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Optimisation des performances des requêtes comme `SELECT ... FINAL ... WHERE`. Désormais, dans les requêtes avec `FINAL`, il est possible de déplacer dans `PREWHERE` les colonnes présentes dans la clé de tri. ... [#21830](https://github.com/ClickHouse/ClickHouse/pull/21830) ([foolchi](https://github.com/foolchi)).
* `GROUP BY` plus rapide avec un `max_rows_to_group_by` faible et `group_by_overflow_mode='any'`. [#21856](https://github.com/ClickHouse/ClickHouse/pull/21856) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Évite les copies de données inutiles lors de l’utilisation du codec `NONE`. Veuillez noter que le codec `NONE` est généralement peu utile - il est recommandé de toujours utiliser la compression (`LZ4` est utilisée par défaut). Contrairement à une idée répandue, désactiver la compression n’améliore pas nécessairement les performances (l’effet inverse est possible). Le codec `NONE` est utile dans certains cas : - lorsque les données ne sont pas compressibles ; - pour des benchmarks synthétiques. [#22145](https://github.com/ClickHouse/ClickHouse/pull/22145) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Ajout d’un cache pour les fichiers lus avec le paramètre `min_bytes_to_use_mmap_io`. Cela apporte une amélioration significative des performances (2x et plus) lorsque la valeur du paramètre est faible, en évitant les appels fréquents à mmap/munmap et les défauts de page qui en résultent. Notez que mmap IO présente des inconvénients majeurs qui le rendent moins fiable en production (par ex. blocage ou SIGBUS sur des disques défectueux ; consommation mémoire moins contrôlable). Néanmoins, cela reste utile pour les benchmarks. [#22206](https://github.com/ClickHouse/ClickHouse/pull/22206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Activation de la lecture avec mmap IO pour les plages de fichiers à partir de 64 MiB (le paramètre `min_bytes_to_use_mmap_io`). Cela peut entraîner une amélioration modérée des performances. [#22326](https://github.com/ClickHouse/ClickHouse/pull/22326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
