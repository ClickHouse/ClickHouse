<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Changement du chemin ZooKeeper pour les marks zero-copy des données partagées. Correction de la suppression des marks dans ZooKeeper pour les parties renommées. [#32061](https://github.com/ClickHouse/ClickHouse/pull/32061) ([ianton-ru](https://github.com/ianton-ru)).
* * Prise en compte des sous-requêtes scalaires. Avec ce changement, les lignes lues dans les sous-requêtes scalaires sont désormais consignées dans le query&#95;log. Si la sous-requête scalaire est mise en cache (répétée ou appelée pour plusieurs lignes), les lignes lues ne sont comptabilisées qu&#39;une seule fois. Ce changement permet d&#39;interrompre des requêtes avec KILL et de signaler leur progression pendant l&#39;exécution de sous-requêtes scalaires. [#32271](https://github.com/ClickHouse/ClickHouse/pull/32271) ([Raúl Marín](https://github.com/Algunenano)).
* Ajout des fonctions `left`, `right`, `leftUTF8`, `rightUTF8`. Correction d&#39;une erreur dans l&#39;implémentation de la fonction `substringUTF8` avec un décalage négatif (à partir de la fin de la chaîne). Les fonctions `left` et `right` étaient auparavant implémentées dans le parseur. Notes de mise à niveau : les requêtes distribuées avec les fonctions `left` ou `right` sans alias peuvent lever une exception si le cluster contient différentes versions de clickhouse-server. Si vous mettez à niveau votre cluster et rencontrez cette erreur, vous devez terminer la mise à niveau afin de vous assurer que tous les nœuds ont la même version. Vous pouvez également ajouter des alias (`AS something`) aux colonnes de vos requêtes pour éviter ce problème. [#33407](https://github.com/ClickHouse/ClickHouse/pull/33407) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Implémentation de la sérialisation sparse. Elle peut réduire l’utilisation de l’espace disque et améliorer les performances de certaines requêtes sur les colonnes contenant beaucoup de valeurs par défaut (zéro). Elle peut être activée en définissant `ratio_of_defaults_for_sparse_serialization`. La sérialisation sparse sera choisie dynamiquement pour une colonne si le ratio entre le nombre de valeurs par défaut et le nombre total de valeurs dépasse ce seuil. La sérialisation (par défaut ou sparse) sera fixée pour chaque colonne dans une part, mais peut varier d’une part à l’autre. [#22535](https://github.com/ClickHouse/ClickHouse/pull/22535) ([Anton Popov](https://github.com/CurtizJ)).
* ajout de la fonction grouping sets, comme dans GROUP BY grouping sets (a, b, (a, b)). [#26869](https://github.com/ClickHouse/ClickHouse/pull/26869) ([taylor12805](https://github.com/taylor12805)).
* Ajout de la possibilité de lire depuis toutes les répliques d’un shard lors d’une distributed query. Pour l’activer, définissez `allow_experimental_parallel_reading_from_replicas=true` et `max_parallel_replicas` sur n’importe quelle valeur. Cela résout [#26748](https://github.com/ClickHouse/ClickHouse/issues/26748). [#29279](https://github.com/ClickHouse/ClickHouse/pull/29279) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Démarrage et arrêt des serveurs lorsque la configuration des hosts et des ports change. [#30549](https://github.com/ClickHouse/ClickHouse/pull/30549) ([Kevin Michel](https://github.com/kmichel-aiven)).
* Création de n’importe quel type de vue avec commentaire. ... [#31062](https://github.com/ClickHouse/ClickHouse/pull/31062) ([Vasily Nemkov](https://github.com/Enmk)).
* Implémentation du moteur de table Hive pour accéder à Apache Hive depuis ClickHouse. RFC associée : [#29245](https://github.com/ClickHouse/ClickHouse/issues/29245). [#31104](https://github.com/ClickHouse/ClickHouse/pull/31104) ([李扬](https://github.com/taiyang-li)).
* * Découverte automatique du cluster via Zoo/Keeper. [#31442](https://github.com/ClickHouse/ClickHouse/pull/31442) ([Vladimir C](https://github.com/vdimir)).
* Ajout de la prise en charge des disques basés sur Azure Blob Storage, de manière similaire à ce qui a été fait pour les disques basés sur AWS S3. L’implémentation actuelle prend en charge toutes les opérations de base sur les disques. [#31505](https://github.com/ClickHouse/ClickHouse/pull/31505) ([Jakub Kuklis](https://github.com/jkuklis)).
* * Ajout de la fonctionnalité &quot;TABLE OVERRIDE&quot; pour personnaliser les schémas des tables MaterializedMySQL. [#32325](https://github.com/ClickHouse/ClickHouse/pull/32325) ([Stig Bakken](https://github.com/stigsb)).
* Implémentation de l’inférence de schéma pour les formats d’entrée. Il est désormais possible d’omettre la structure (ou d’indiquer simplement `auto`) dans les fonctions de table `file`, `url`, `s3`, `hdfs` ainsi que dans les paramètres de `clickhouse-local`. Il est également possible d’omettre la structure dans la requête CREATE pour les moteurs de table `File`, `HDFS`, `S3`, `URL`, `Merge`, `Buffer`, `Distributed` et `ReplicatedMergeTree` (si de nouvelles répliques sont ajoutées). [#32455](https://github.com/ClickHouse/ClickHouse/pull/32455) ([Kruglov Pavel](https://github.com/Avogar)).
* Prise en charge de la clause TABLE OVERRIDE pour MaterializedPostgreSQL. RFC : [#31480](https://github.com/ClickHouse/ClickHouse/issues/31480). [#32749](https://github.com/ClickHouse/ClickHouse/pull/32749) ([Kseniia Sumarokova](https://github.com/kssenii)).

[#32946](https://github.com/ClickHouse/ClickHouse/pull/32946) ([Antonio Andelic](https://github.com/antonio2368)).

Toutes s’appuient sur une table croisée (histogramme sur des paires) pour leur implémentation. On peut les voir comme un coefficient de corrélation, mais pour n’importe quelles valeurs discrètes (pas nécessairement numériques).
