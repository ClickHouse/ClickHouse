<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Dépréciation de la fonctionnalité de metadata cache. Elle est expérimentale et nous ne l&#39;avons jamais utilisée. Cette fonctionnalité est dangereuse : [#51182](https://github.com/ClickHouse/ClickHouse/issues/51182). Suppression de la table système `system.merge_tree_metadata_cache`. Le metadata cache est toujours disponible dans cette version, mais sera bientôt supprimé. Cela clôt [#39197](https://github.com/ClickHouse/ClickHouse/issues/39197). [#51303](https://github.com/ClickHouse/ClickHouse/pull/51303) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Si un disque dynamique contient un nom, il doit être spécifié sous la forme `disk = disk(name = 'disk_name'`, ...) dans les arguments de la fonction disk. Dans la version précédente, il pouvait être spécifié sous la forme `disk = disk_<disk_name>(...)`, ce qui n&#39;est plus pris en charge. [#52820](https://github.com/ClickHouse/ClickHouse/pull/52820) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `clickhouse-benchmark` établira les connexions en parallèle lorsqu&#39;il est invoqué avec `--concurrency` supérieur à un. Auparavant, il était inutilisable si vous l&#39;exécutiez avec 1000 connexions simultanées entre l&#39;Europe et les États-Unis. Correction du calcul des QPS pour les connexions à latence élevée. Changement incompatible avec les versions précédentes : l&#39;option de sortie JSON de `clickhouse-benchmark` est supprimée. Si vous utilisiez cette option, vous pouvez extraire les données de `system.query_log` au format JSON comme solution de contournement. [#53293](https://github.com/ClickHouse/ClickHouse/pull/53293) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La colonne `microseconds` est supprimée de `system.text_log`, et la colonne `milliseconds` est supprimée de `system.metric_log`, car elles sont redondantes en présence de la colonne `event_time_microseconds`. [#53601](https://github.com/ClickHouse/ClickHouse/pull/53601) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Modification des chemins ZooKeeper pour les métadonnées du stockage `S3Queue`. [#54137](https://github.com/ClickHouse/ClickHouse/pull/54137) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Activer la compilation JIT pour AArch64, PowerPC, SystemZ et RISCV. [#38217](https://github.com/ClickHouse/ClickHouse/pull/38217) ([Maksim Kita](https://github.com/kitaisreal)).
* Ce patch fournira une méthode permettant de traiter tous les hash sets en parallèle avant la fusion. [#50748](https://github.com/ClickHouse/ClickHouse/pull/50748) ([Jiebin Sun](https://github.com/jiebinn)).
* Optimiser les performances de l&#39;aggregation d&#39;une clé String Nullable lors de l&#39;utilisation de aggregationmethodserialized. [#51399](https://github.com/ClickHouse/ClickHouse/pull/51399) ([LiuNeng](https://github.com/liuneng1994)).
* Les tests de performance de **SSB** sur la plateforme ICX (CPU Intel Xeon Platinum 8380, 80 cœurs, 160 threads) montrent que ce changement peut apporter un gain de **8.5%** sur le **QPS en moyenne géométrique** lorsque l&#39;analyzer expérimental est activé. Les détails sont présentés ci-dessous : ![image](https://github.com/ClickHouse/ClickHouse/assets/26588299/4e58bf8b-d276-408d-ad45-38c82d3cb918). [#52091](https://github.com/ClickHouse/ClickHouse/pull/52091) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Pushdown des filtres Parquet. Autrement dit, lors de la lecture de fichiers Parquet, les groupes de lignes (segments du fichier) sont ignorés en fonction de la condition WHERE et des valeurs min/max de chaque colonne. En particulier, si le fichier est approximativement trié selon une colonne donnée, les queries qui filtrent sur une plage courte de cette colonne seront nettement plus rapides. [#52951](https://github.com/ClickHouse/ClickHouse/pull/52951) ([Michael Kolupaev](https://github.com/al13n321)).
* Optimiser la fusion si tous les hashSets sont singleLevel dans UniqExactSet. [#52973](https://github.com/ClickHouse/ClickHouse/pull/52973) ([Jiebin Sun](https://github.com/jiebinn)).
* StorageJoin : ne pas créer de clone de hash join avec toutes les colonnes. [#53046](https://github.com/ClickHouse/ClickHouse/pull/53046) ([Duc Canh Le](https://github.com/canhld94)).
* Optimiser la lecture des petits groupes de lignes dans Parquet en les traitant par lots. Clôt [#53069](https://github.com/ClickHouse/ClickHouse/issues/53069). [#53281](https://github.com/ClickHouse/ClickHouse/pull/53281) ([Kruglov Pavel](https://github.com/Avogar)).
* Implémenter un input format ORC natif sans Arrow pour améliorer les performances. [#53324](https://github.com/ClickHouse/ClickHouse/pull/53324) ([李扬](https://github.com/taiyang-li)).
* Le dashboard demandera au server de compresser les données, ce qui est utile pour les longues plages temporelles sur des connexions Internet lentes. Par exemple, un chart avec 86400 points peut représenter 1.5 MB non compressés et 60 KB compressés avec `br`. [#53569](https://github.com/ClickHouse/ClickHouse/pull/53569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Optimiser `count` à partir de fichiers dans la plupart des input formats. Clôt [#44334](https://github.com/ClickHouse/ClickHouse/issues/44334). [#53637](https://github.com/ClickHouse/ClickHouse/pull/53637) ([Kruglov Pavel](https://github.com/Avogar)).
* Meilleure utilisation du pool de threads pour les sauvegardes et les restaurations. [#53649](https://github.com/ClickHouse/ClickHouse/pull/53649) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Supprimer le ralentissement inutile dans le check de performance du client. [#53695](https://github.com/ClickHouse/ClickHouse/pull/53695) ([Raúl Marín](https://github.com/Algunenano)).
