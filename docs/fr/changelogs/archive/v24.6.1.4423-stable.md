<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Active le chargement asynchrone des bases de données et des tables par défaut. Voir `async_load_databases` dans config.xml. Bien que ce changement soit entièrement compatible, il peut introduire une différence de comportement. Lorsque `async_load_databases` est false, comme dans les versions précédentes, le serveur n&#39;accepte pas les connexions tant que toutes les tables ne sont pas chargées. Lorsque `async_load_databases` est true, comme dans la nouvelle version, le serveur peut accepter des connexions avant que toutes les tables ne soient chargées. Si une requête est effectuée sur une table qui n&#39;est pas encore chargée, elle attendra le chargement de la table, ce qui peut prendre un temps considérable. Cela peut modifier le comportement du serveur s&#39;il fait partie d&#39;un grand système distribué derrière un load balancer. Dans le premier cas, le load balancer peut recevoir un refus de connexion et basculer rapidement vers un autre serveur. Dans le second cas, le load balancer peut se connecter à un serveur qui charge encore les tables, et la requête aura une latence plus élevée. De plus, si de nombreuses requêtes s&#39;accumulent en attente, cela peut entraîner un problème de &quot;thundering herd&quot; lorsqu&#39;elles commencent à être traitées simultanément. Cela ne fait une différence que pour des backends distribués fortement chargés. Vous pouvez définir `async_load_databases` sur false pour éviter ce problème. [#57695](https://github.com/ClickHouse/ClickHouse/pull/57695) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Certaines requêtes invalides échoueront plus tôt, dès l&#39;analyse syntaxique. Remarque : la prise en charge des expressions KQL intégrées (le langage Kusto experimental) a été désactivée lorsqu&#39;elles sont utilisées dans une table function `kql` sans littéral de chaîne, par exemple `kql(garbage | trash)` au lieu de `kql('garbage | trash')` ou `kql($$garbage | trash$$)`. Cette fonctionnalité a été introduite involontairement et ne devrait pas exister. [#61500](https://github.com/ClickHouse/ClickHouse/pull/61500) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Les &quot;inverted indexes&quot; ont été renommés en &quot;full-text indexes&quot;, une appellation moins technique et plus conviviale. Cela modifie également les métadonnées internes des tables et casse les tables avec des inverted indexes existants (experimental). Veuillez supprimer ces indexes avant la mise à niveau, puis les recréer après celle-ci. [#62884](https://github.com/ClickHouse/ClickHouse/pull/62884) ([Robert Schulze](https://github.com/rschu1ze)).
* L&#39;utilisation des fonctions `neighbor`, `runningAccumulate`, `runningDifferenceStartingWithFirstValue`, `runningDifference` est deprecated (car sujette aux erreurs). Il convient d&#39;utiliser à la place des window functions appropriées. Pour les réactiver, définissez `allow_deprecated_functions=1`. [#63132](https://github.com/ClickHouse/ClickHouse/pull/63132) ([Nikita Taranov](https://github.com/nickitat)).
* Les requêtes sur `system.columns` fonctionneront plus rapidement s&#39;il existe un grand nombre de columns, mais que `SHOW TABLES` n&#39;est pas accordé sur de nombreuses databases ou tables. Notez que dans les versions précédentes, si vous accordiez `SHOW COLUMNS` à des columns individuelles sans accorder `SHOW TABLES` aux tables correspondantes, la table `system.columns` affichait ces columns, mais dans la nouvelle version, elle ignorera entièrement la table. Suppression des messages du journal de trace &quot;Access granted&quot; et &quot;Access denied&quot;, qui ralentissaient les requêtes. [#63439](https://github.com/ClickHouse/ClickHouse/pull/63439) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Refonte du traitement parallèle dans le mode `Ordered` du stockage `S3Queue`. Cette PR n&#39;est pas rétrocompatible pour le mode Ordered si vous utilisiez les paramètres `s3queue_processing_threads_num` ou `s3queue_total_shards_num`. Le paramètre `s3queue_total_shards_num` est supprimé ; auparavant, il n&#39;était autorisé qu&#39;avec `s3queue_allow_experimental_sharded_mode`, qui est désormais deprecated. Un nouveau paramètre est ajouté : `s3queue_buckets`. [#64349](https://github.com/ClickHouse/ClickHouse/pull/64349) ([Kseniia Sumarokova](https://github.com/kssenii)).
* De nouvelles fonctions `snowflakeIDToDateTime`, `snowflakeIDToDateTime64`, `dateTimeToSnowflakeID` et `dateTime64ToSnowflakeID` ont été ajoutées. Contrairement aux fonctions existantes `snowflakeToDateTime`, `snowflakeToDateTime64`, `dateTimeToSnowflake` et `dateTime64ToSnowflake`, les nouvelles fonctions sont compatibles avec la fonction `generateSnowflakeID`, c.-à-d. qu&#39;elles acceptent les Snowflake IDs générés par `generateSnowflakeID` et produisent des Snowflake IDs du même type que `generateSnowflakeID` (c.-à-d. `UInt64`). En outre, les nouvelles fonctions utilisent par défaut l&#39;époque Unix (c.-à-d. le 1970-01-01), comme `generateSnowflakeID`. Si nécessaire, il est possible de passer une époque différente, par exemple celle de Twitter/X, le 2010-11-04, soit 1288834974657 ms après l&#39;époque Unix. Les anciennes fonctions de conversion sont dépréciées et seront supprimées après une période de transition : pour continuer à les utiliser, activez le paramètre `allow_deprecated_snowflake_conversion_functions`. [#64948](https://github.com/ClickHouse/ClickHouse/pull/64948) ([Robert Schulze](https://github.com/rschu1ze)).
