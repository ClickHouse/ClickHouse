<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#65351](https://github.com/ClickHouse/ClickHouse/issues/65351) : correction d’un arrêt brutal possible en cas d’exception non gérée dans ~WriteBufferFromFileDescriptor de StatusFile. [#64206](https://github.com/ClickHouse/ClickHouse/pull/64206) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#66037](https://github.com/ClickHouse/ClickHouse/issues/66037) : correction d’un plantage lors de la destruction d’AccessControl : ajout d’un arrêt explicite. [#64993](https://github.com/ClickHouse/ClickHouse/pull/64993) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#65782](https://github.com/ClickHouse/ClickHouse/issues/65782) : correction d’un bug dans MergeJoin. Une colonne dans une sérialisation sparse pouvait être traitée comme une colonne de son type Nested alors que la conversion requise n’avait pas été effectuée. [#65632](https://github.com/ClickHouse/ClickHouse/pull/65632) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#65926](https://github.com/ClickHouse/ClickHouse/issues/65926) : pour les requêtes qui lisent depuis `PostgreSQL`, annulation de la requête interne `PostgreSQL` si la requête ClickHouse est terminée. Sinon, la requête `ClickHouse` ne peut pas être annulée tant que la requête interne `PostgreSQL` n’est pas terminée. [#65771](https://github.com/ClickHouse/ClickHouse/pull/65771) ([Maksim Kita](https://github.com/kitaisreal)).
* Rétroporté dans [#65822](https://github.com/ClickHouse/ClickHouse/issues/65822) : correction d’un bug dans la logique de court-circuit lorsque l’ancien analyseur et dictGetOrDefault sont utilisés. [#65802](https://github.com/ClickHouse/ClickHouse/pull/65802) ([jsc0218](https://github.com/jsc0218)).
* Rétroporté dans [#66449](https://github.com/ClickHouse/ClickHouse/issues/66449) : correction d’un bug dans le client ZooKeeper : une session pouvait rester bloquée dans un état inutilisable après avoir reçu une erreur matérielle de ZooKeeper. Par exemple, cela pouvait se produire à cause de la « soft memory limit » dans ClickHouse Keeper. [#66140](https://github.com/ClickHouse/ClickHouse/pull/66140) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#66717](https://github.com/ClickHouse/ClickHouse/issues/66717) : suivi correct de la mémoire pour `Allocator::realloc`. [#66548](https://github.com/ClickHouse/ClickHouse/pull/66548) ([Antonio Andelic](https://github.com/antonio2368)).
