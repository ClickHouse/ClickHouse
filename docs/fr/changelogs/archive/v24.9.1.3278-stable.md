<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Autorise l’écriture de `SETTINGS` avant `FORMAT` dans une chaîne de requêtes avec `UNION` lorsque les sous-requêtes sont entre parenthèses. Cela clôt [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712). Modifie le comportement lorsqu’une requête comporte deux fois la clause SETTINGS dans une séquence. La clause SETTINGS la plus proche aura priorité pour la sous-requête correspondante. Dans les versions précédentes, la clause SETTINGS la plus externe pouvait prendre le pas sur la clause interne. [#60197](https://github.com/ClickHouse/ClickHouse/pull/60197) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* N’autorise pas la spécification explicite d’un UUID lors de la création d’une table dans une base de données Replicated. De même, n’autorise pas la spécification explicite du chemin ZooKeeper ni du nom de réplique pour les tables *MergeTree dans les bases de données Replicated. [#66104](https://github.com/ClickHouse/ClickHouse/pull/66104) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Réimplémente le type Dynamic. Désormais, lorsque la limite des types de données dynamiques est atteinte, les nouveaux types ne sont plus convertis en String, mais stockés dans une structure de données spéciale au format binaire, avec un type de donnée encodé en binaire. Désormais, tout type déjà inséré dans une colonne Dynamic peut être lu sous forme de sous-colonne. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Pavel Kruglov](https://github.com/Avogar)).
* Les expressions comme `a[b].c` sont prises en charge pour les Tuples nommés, ainsi que les indices nommés à partir d’expressions arbitraires, par exemple `expr().name`. Cela est utile pour traiter JSON. Cela clôt [#54965](https://github.com/ClickHouse/ClickHouse/issues/54965). Dans les versions précédentes, une expression de la forme `expr().name` était analysée comme `tupleElement(expr(), name)`, et l’analyseur de requêtes recherchait une colonne `name` plutôt que l’élément de tuple correspondant, tandis que dans la nouvelle version, cela devient `tupleElement(expr(), 'name')`. Dans la plupart des cas, la version précédente ne fonctionnait pas, mais on peut imaginer un scénario très inhabituel où ce changement pourrait entraîner une incompatibilité : si vous stockiez les noms des éléments de tuple dans une colonne ou un alias portant un nom différent de celui de l’élément de tuple : `SELECT 'b' AS a, CAST([tuple(123)] AS 'Array(Tuple(b UInt8))') AS t, t[1].a`. Il est très peu probable que vous ayez utilisé de telles requêtes, mais nous devons tout de même signaler ce changement comme potentiellement non rétrocompatible. [#68435](https://github.com/ClickHouse/ClickHouse/pull/68435) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Lorsque le paramètre `print_pretty_type_names` est activé, il affichera le type de donnée `Tuple` sous une forme Pretty dans les instructions `SHOW CREATE TABLE`, la fonction `formatQuery`, ainsi qu’en mode interactif dans `clickhouse-client` et `clickhouse-local`. Dans les versions précédentes, ce paramètre s’appliquait uniquement aux requêtes `DESCRIBE` et à `toTypeName`. Cela clôt [#65753](https://github.com/ClickHouse/ClickHouse/issues/65753). [#68492](https://github.com/ClickHouse/ClickHouse/pull/68492) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* La fonction `toStartOfInterval()` dispose désormais d’une nouvelle surcharge qui émule la fonction `time_bucket()` de TimescaleDB ainsi que la fonction `date_bin()` de PostgreSQL. ([#55619](https://github.com/ClickHouse/ClickHouse/issues/55619)). Elle permet d’aligner des valeurs de date ou de timestamp sur des multiples d’un intervalle donné à partir d’une origine *arbitraire* (au lieu de 0000-01-01 00:00:00.000 comme origine *fixe*). Par exemple, `SELECT toStartOfInterval(toDateTime('2023-01-01 14:45:00'), INTERVAL 1 MINUTE, toDateTime('2023-01-01 14:35:30'));` renvoie `2023-01-01 14:44:30`, soit un multiple d’intervalles d’une minute à partir de l’origine `2023-01-01 14:35:30`. [#56738](https://github.com/ClickHouse/ClickHouse/pull/56738) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout de la prise en charge de `ATTACH PARTITION ALL FROM`. [#61987](https://github.com/ClickHouse/ClickHouse/pull/61987) ([Kirill Nikiforov](https://github.com/allmazz)).
* Ajout du paramètre `input_format_try_infer_variants`, qui permet d’inférer le type Variant lors de l’inférence de schéma pour les formats texte lorsqu’il existe plusieurs types possibles pour les éléments de colonnes ou de tableaux. [#63798](https://github.com/ClickHouse/ClickHouse/pull/63798) ([Shaun Struwig](https://github.com/Blargian)).
* Introduction du format JSONCompactWithProgress, dans lequel ClickHouse produit chaque ligne sous la forme d’un objet JSON délimité par des sauts de ligne, incluant les métadonnées, les données, la progression, les totaux et les statistiques. [#66205](https://github.com/ClickHouse/ClickHouse/pull/66205) ([Alexey Korepanov](https://github.com/alexkorep)).
* Implémente le nouveau type de données JSON. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Pavel Kruglov](https://github.com/Avogar)).
* Ajout du paramètre `input_format_json_empty_as_default` qui, lorsqu’il est activé, traite les champs vides des entrées JSON comme des valeurs par défaut. Ferme [#59339](https://github.com/ClickHouse/ClickHouse/issues/59339). [#66782](https://github.com/ClickHouse/ClickHouse/pull/66782) ([Alexis Arnaud](https://github.com/a-a-f)).
* Ajout des fonctions `overlay` et `overlayUTF8`, qui remplacent une partie d’une chaîne par une autre. Exemple : `SELECT overlay('Hello New York', 'Jersey', 11)` renvoie `Hello New Jersey`. [#66933](https://github.com/ClickHouse/ClickHouse/pull/66933) ([李扬](https://github.com/taiyang-li)).
* Ajout d’une nouvelle commande, Lightweight Delete In Partition `DELETE FROM [db.]table [ON CLUSTER cluster] [IN PARTITION partition_expr] WHERE expr;` &#96;&#96;&#96; VM-114-29-tos :) select * from ads&#95;app&#95;poster&#95;ip&#95;source&#95;channel&#95;di&#95;replicated&#95;local;. [#67805](https://github.com/ClickHouse/ClickHouse/pull/67805) ([sunny](https://github.com/sunny19930321)).
* Implémentation de la comparaison des valeurs du type de données `Interval`, de sorte qu’elles sont désormais converties vers le plus petit supertype. [#68057](https://github.com/ClickHouse/ClickHouse/pull/68057) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Ajout du paramètre create&#95;if&#95;not&#95;exists afin d’utiliser par défaut le comportement IF NOT EXISTS lors des instructions CREATE. [#68164](https://github.com/ClickHouse/ClickHouse/pull/68164) ([Peter Nguyen](https://github.com/petern48)).
* Permet désormais de lire des tables Iceberg dans Azure et en local. [#68210](https://github.com/ClickHouse/ClickHouse/pull/68210) ([Daniil Ivanik](https://github.com/divanik)).
* Ajout des fonctions d’agrégation distinctDynamicTypes/distinctJSONPaths/distinctJSONPathsAndTypes pour une meilleure introspection du contenu des colonnes de type JSON. [#68463](https://github.com/ClickHouse/ClickHouse/pull/68463) ([Pavel Kruglov](https://github.com/Avogar)).
* Les entrées du query cache peuvent désormais être supprimées par tag. Par exemple, l&#39;entrée du query cache créée par `SELECT 1 SETTINGS use_query_cache = true, query_cache_tag = 'abc'` peut désormais être supprimée avec `SYSTEM DROP QUERY CACHE TAG 'abc'` (ou, bien sûr, simplement avec : `SYSTEM DROP QUERY CACHE`, ce qui videra l&#39;intégralité du query cache). [#68477](https://github.com/ClickHouse/ClickHouse/pull/68477) ([Michał Tabaszewski](https://github.com/pinsvin00)).
* Ajout du chiffrement du stockage pour les collections nommées. [#68615](https://github.com/ClickHouse/ClickHouse/pull/68615) ([Pablo Marcos](https://github.com/pamarcos)).
* Ajout de la fonction `ripeMD160`, qui calcule le hash cryptographique RIPEMD-160 d&#39;une chaîne. Exemple : `SELECT hex(ripeMD160('The quick brown fox jumps over the lazy dog'))` renvoie `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`. [#68639](https://github.com/ClickHouse/ClickHouse/pull/68639) ([Dergousov Maxim](https://github.com/m7kss1)).
* Ajout de la colonne virtuelle &#95;headers pour le moteur de table URL. Clôt le ticket [#65026](https://github.com/ClickHouse/ClickHouse/issues/65026). [#68867](https://github.com/ClickHouse/ClickHouse/pull/68867) ([flynn](https://github.com/ucasfl)).
* Ajout de la table `system.projections` pour suivre les projections disponibles. [#68901](https://github.com/ClickHouse/ClickHouse/pull/68901) ([Jordi Villar](https://github.com/jrdi)).
* Ajout de la nouvelle fonction `arrayZipUnaligned` pour la compatibilité avec Spark(arrays&#95;zip), qui permet de gérer des tableaux non alignés à partir de `arrayZip`. &#96;&#96;&#96; sql SELECT arrayZipUnaligned([1], [1, 2, 3]). [#69030](https://github.com/ClickHouse/ClickHouse/pull/69030) ([李扬](https://github.com/taiyang-li)).
* Ajout de la métrique `RealTimeMicroseconds` dans l&#39;en-tête HTTP `X-ClickHouse-Summary`. Cela permet de connaître le temps CPU d&#39;une requête sans avoir à le vérifier dans `system.query_log`. [#69032](https://github.com/ClickHouse/ClickHouse/pull/69032) ([Alejandro](https://github.com/alexon1234)).

* Ajout de l&#39;argument `scale` (par défaut : `true`) à la fonction `arrayAUC`, ce qui permet d&#39;ignorer l&#39;étape de normalisation (ticket [#69609](https://github.com/ClickHouse/ClickHouse/issues/69609)). [#69717](https://github.com/ClickHouse/ClickHouse/pull/69717) ([gabrielmcg44](https://github.com/gabrielmcg44)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Améliore les performances des jointures en réordonnant la table de droite par clés lorsque les clés de la table sont denses dans une jointure de hachage left ou inner. [#60341](https://github.com/ClickHouse/ClickHouse/pull/60341) ([kevinyhzou](https://github.com/KevinyhZou)).
* Améliore les performances de toutes les jointures en ajoutant `RowRefList` ou `RowRef` à AddedColumns pour une sortie différée ; dans `buildOutput`, `RowRefList`/`RowRef` est utilisé pour la sortie, et la condition `is_join_get` est supprimée de la boucle `buildOutput`. [#63677](https://github.com/ClickHouse/ClickHouse/pull/63677) ([kevinyhzou](https://github.com/KevinyhZou)).
* Charge les métadonnées du cache du système de fichiers de manière asynchrone au démarrage afin d&#39;accélérer les redémarrages. [#65736](https://github.com/ClickHouse/ClickHouse/pull/65736) ([Daniel Pozo Escalona](https://github.com/danipozo)).
* Les fonctions `array` et `map` ont été optimisées pour traiter beaucoup plus rapidement certains cas courants. [#67707](https://github.com/ClickHouse/ClickHouse/pull/67707) ([李扬](https://github.com/taiyang-li)).
* Optimisation légère de la lecture des chaînes ORC, en particulier lorsque la colonne ne contient aucun NULL. [#67794](https://github.com/ClickHouse/ClickHouse/pull/67794) ([李扬](https://github.com/taiyang-li)).
* Améliore les performances globales des merges en réduisant le surcoût lié aux étapes de planification des merges. [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* Accélère les requêtes vers S3 lorsqu&#39;aucun profile n&#39;est défini, qu&#39;aucun identifiant n&#39;est configuré et qu&#39;IMDS n&#39;est pas disponible (par exemple, lorsque vous interrogez un bucket public depuis une machine hors d&#39;un cloud). Cela clôt [#52771](https://github.com/ClickHouse/ClickHouse/issues/52771). [#68082](https://github.com/ClickHouse/ClickHouse/pull/68082) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nouvel algorithme pour déterminer, par hachage cohérent, l&#39;unité de distribution des marks entre les répliques. Différents nombres de marks sont choisis selon les patterns de lecture afin d&#39;améliorer les performances. [#68424](https://github.com/ClickHouse/ClickHouse/pull/68424) ([Nikita Taranov](https://github.com/nickitat)).
* Tente de dévirtualiser le reader de format dans RowInputFormatWithNamesAndTypes afin de voir si cela peut améliorer les performances. [#68437](https://github.com/ClickHouse/ClickHouse/pull/68437) ([李扬](https://github.com/taiyang-li)).
* Ajoute l&#39;implémentation du merge parallèle avec clé afin de maximiser l&#39;utilisation du CPU. [#68441](https://github.com/ClickHouse/ClickHouse/pull/68441) ([Jiebin Sun](https://github.com/jiebinn)).
* Ajoute le paramètre `output_format_orc_dictionary_key_size_threshold` pour permettre à l&#39;utilisateur d&#39;activer l&#39;encodage par dictionnaire pour une colonne de type chaîne dans le format de sortie ORC. Cela permet de réduire considérablement la taille du fichier ORC de sortie et d&#39;améliorer les performances de lecture. [#68591](https://github.com/ClickHouse/ClickHouse/pull/68591) ([李扬](https://github.com/taiyang-li)).
* Implémente la lecture des seuls fichiers requis pendant le partitionnement Hive. [#68963](https://github.com/ClickHouse/ClickHouse/pull/68963) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Introduit une nouvelle requête Keeper, RemoveRecursive, qui supprime un nœud avec tout son sous-arbre. [#69332](https://github.com/ClickHouse/ClickHouse/pull/69332) ([Mikhail Artemenko](https://github.com/Michicosun)).
* Accélère les performances d&#39;insert avec le vector similarity index en ajoutant les données à l&#39;index vectoriel en parallèle. [#69493](https://github.com/ClickHouse/ClickHouse/pull/69493) ([flynn](https://github.com/ucasfl)).
* Auparavant, la complexité algorithmique de la logique de déduplication des parts dans le traitement des announcements de parallel réplique était de O(n^2), ce qui pouvait prendre un temps notable pour les tables comportant de nombreuses parts (ou partitions). Ce changement ramène la complexité à O(n*log(n)). [#69596](https://github.com/ClickHouse/ClickHouse/pull/69596) ([Alexander Gololobov](https://github.com/davenger)).

<div id="improvement">
  #### Amélioration
</div>

* Renforcement de certaines parties du code liées à l’analyse syntaxique de petites entités. Les bogues (mineurs) suivants ont été identifiés et corrigés : - si une table `DeltaLake` est partitionnée par Bool, la valeur de partition est toujours interprétée comme false ; - la table `ExternalDistributed` n’utilisait qu’un seul shard parmi les adresses fournies ; la valeur du paramètre `max_threads` et d’autres similaires était affichée sous la forme `'auto(N)'` au lieu de `auto(N)`. [#52503](https://github.com/ClickHouse/ClickHouse/pull/52503) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Améliorations des vues matérialisées actualisables : mode append (`... REFRESH EVERY 1 MINUTE APPEND ...`) pour ajouter des lignes à une table existante au lieu d’écraser toute la table, tentatives de reprise (désactivées par défaut, configurées dans la section SETTINGS de la requête), requête `SYSTEM WAIT VIEW <name>` qui attend l’actualisation en cours, ainsi que quelques correctifs. [#58934](https://github.com/ClickHouse/ClickHouse/pull/58934) ([Michael Kolupaev](https://github.com/al13n321)).
* Utilisation de métriques spécifiques aux cgroups pour la comptabilisation de l’utilisation CPU au lieu de métriques à l’échelle du système. [#62003](https://github.com/ClickHouse/ClickHouse/pull/62003) ([Nikita Taranov](https://github.com/nickitat)).
* L’ordonnancement des E/S pour les disques S3 distants se fait désormais au niveau des flux de sockets HTTP (au lieu des requêtes S3 dans leur ensemble) afin de résoudre les problèmes de limitation liés à `bandwidth_limit`. [#65182](https://github.com/ClickHouse/ClickHouse/pull/65182) ([Sergei Trifonov](https://github.com/serxa)).
* Permet à un utilisateur d’avoir plusieurs méthodes d’authentification au lieu d’une seule. Permet de réinitialiser les méthodes d’authentification à la méthode ajoutée le plus récemment. Si vous souhaitez exécuter des instances en 24.8 et une en 24.9 pendant un certain temps, il est préférable de définir `max_authentication_methods_per_user = 1` durant cette période afin d’éviter d’éventuelles erreurs. [#65277](https://github.com/ClickHouse/ClickHouse/pull/65277) ([Arthur Passos](https://github.com/arthurpassos)).
* Les fonctions `upperUTF8` et `lowerUTF8` ne pouvaient auparavant convertir en majuscules / minuscules que les caractères cyrilliques. Cette limitation a désormais été supprimée et les caractères de langues arbitraires sont convertis en majuscules/minuscules. Exemple : `SELECT upperUTF8('Süden')` renvoie désormais `SÜDEN`. [#65761](https://github.com/ClickHouse/ClickHouse/pull/65761) ([李扬](https://github.com/taiyang-li)).
* Lorsqu’un lightweight delete se produit sur une table avec une ou plusieurs projections, les utilisateurs avaient jusqu’à présent le choix entre lever une exception (par défaut) ou supprimer la projection pour permettre le lightweight delete ; une troisième option permet désormais d’effectuer le lightweight delete puis de reconstruire la ou les projections. [#66169](https://github.com/ClickHouse/ClickHouse/pull/66169) ([Shichao](https://github.com/jsc0218)).
