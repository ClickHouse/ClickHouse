<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Corrige un problème où, dans certaines requêtes complexes avec des alias de colonnes identiques aux noms des expressions, une conversion incorrecte pouvait se produire. Cela corrige [#25447](https://github.com/ClickHouse/ClickHouse/issues/25447). Cela corrige [#26914](https://github.com/ClickHouse/ClickHouse/issues/26914). Ce correctif peut introduire une incompatibilité avec les versions précédentes : s&#39;il existe plusieurs expressions portant des noms identiques, une exception sera levée. Cela peut casser certains rares cas où `enable_optimize_predicate_expression` est défini. [#26639](https://github.com/ClickHouse/ClickHouse/pull/26639) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Dans clickhouse-local, toujours traiter les adresses locales avec un port comme des adresses distantes. [#26736](https://github.com/ClickHouse/ClickHouse/pull/26736) ([Raúl Marín](https://github.com/Algunenano)).
* Ne pas autoriser l&#39;application d&#39;une fonction d&#39;agrégation paramétrique avec le combinateur `-Merge` à l&#39;état d&#39;une fonction d&#39;agrégation si cet état a été produit par une fonction d&#39;agrégation avec des paramètres différents. Par exemple, l&#39;état de `fooState(42)(x)` ne peut pas être finalisé avec `fooMerge(s)` ou `fooMerge(123)(s)` ; les paramètres doivent être spécifiés explicitement sous la forme `fooMerge(42)(s)` et doivent être identiques. Cela n&#39;affecte pas certaines fonctions d&#39;agrégation spéciales comme `quantile` et `sequence*`, qui utilisent des paramètres uniquement pour la finalisation. [#26847](https://github.com/ClickHouse/ClickHouse/pull/26847) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Ne pas afficher les zéros non significatifs finaux dans la représentation textuelle des types `Decimal`. Exemple : `1.23` sera affiché au lieu de `1.230000` pour un Decimal avec une scale de 6. Cela clôt [#15794](https://github.com/ClickHouse/ClickHouse/issues/15794). Cela peut introduire une légère incompatibilité si vos applications dépendaient d&#39;une manière ou d&#39;une autre de ces zéros finaux. La sérialisation dans les formats de sortie peut être contrôlée avec le paramètre `output_format_decimal_trailing_zeros`. L&#39;implémentation de `toString` et la conversion en String sont modifiées sans condition. [#27680](https://github.com/ClickHouse/ClickHouse/pull/27680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
