<div id="backward-incompatible-change">
  #### Modification non rétrocompatible
</div>

* Correction d&#39;une incompatibilité de rétrocompatibilité dans la (dé)sérialisation des états des fonctions d’agrégation `min`, `max`, `any*`, `argMin`, `argMax` avec un argument `String`. L&#39;incompatibilité a été introduite dans [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431) et affecte les branches 22.9, 22.10 et 22.11 (corrigée respectivement à partir des versions 22.9.6, 22.10.4 et 22.11.2). Certaines versions mineures des branches 22.3, 22.7 et 22.8 sont également affectées : 22.3.13...22.3.14 (corrigée à partir de 22.3.15), 22.8.6...22.8.9 (corrigée à partir de 22.8.10), 22.7.6 et versions ultérieures (ne sera pas corrigée en 22.7, nous recommandons de mettre à niveau 22.7.* vers 22.8.10 ou une version ultérieure). Cette note de version ne concerne pas les utilisateurs qui n&#39;ont jamais utilisé les versions affectées. Les versions incompatibles ajoutent un `'\0'` supplémentaire aux chaînes lors de la lecture des états des fonctions d’agrégation mentionnées ci-dessus. Par exemple, si une ancienne version a enregistré l&#39;état de `anyState('foobar')` dans `state_column`, alors une version incompatible affichera `'foobar\0'` avec `anyMerge(state_column)`. Les versions incompatibles écrivent également les états des fonctions d’agrégation sans le `'\0'` final. Les versions plus récentes (celles qui incluent le correctif) peuvent lire correctement les données écrites par toutes les versions, y compris les versions incompatibles, sauf dans un cas limite. Si une version incompatible a enregistré un état avec une chaîne qui se termine effectivement par le caractère null, alors une version plus récente supprimera le `'\0'` final lors de la lecture de l&#39;état de la fonction d’agrégation affectée. Par exemple, si une version incompatible a enregistré l&#39;état de `anyState('abrac\0dabra\0')` dans `state_column`, alors les versions plus récentes afficheront `'abrac\0dabra'` avec `anyMerge(state_column)`. Le problème affecte également les requêtes distribuées lorsqu&#39;une version incompatible fonctionne dans un cluster avec des versions plus anciennes ou plus récentes. [#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)).

* résout le problème [#38075](https://github.com/ClickHouse/ClickHouse/issues/38075). À l’heure actuelle, `async insert` ne prend pas en charge la déduplication, car plusieurs petites insertions peuvent coexister dans une même part, ce qui correspond à plusieurs `block id`. La solution est simple : la modification consiste à : 1. marquer les offsets pour chaque insertion dans chaque chunk 2. calculer plusieurs `block_id` lorsque le sink reçoit un chunk 3. obtenir le verrou du numéro de bloc à partir de ces `block_id` 3.1. en cas d’échec, supprimer du bloc la ou les insertions dupliquées et le ou les `block_id` dupliqués, puis recalculer les `offsets` 3.2. en cas de réussite, valider les `block_id` et les autres éléments dans Keeper a. en cas d’échec, faire 3.1 b. en cas de réussite, tout est validé.
