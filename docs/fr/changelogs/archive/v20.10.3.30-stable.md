  ### Version ClickHouse v20.10.3.30-stable FIXME comparée à v20.10.2.20-stable
</div>

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#16313](https://github.com/ClickHouse/ClickHouse/issues/16313) : ajout de allow&#95;nondeterministic&#95;optimize&#95;skip&#95;unused&#95;shards (pour autoriser des fonctions non déterministes comme rand() ou dictGet() dans la clé de sharding). [#16105](https://github.com/ClickHouse/ClickHouse/pull/16105) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix">
  #### Correction de bogues
</div>

* Rétroporté dans [#16202](https://github.com/ClickHouse/ClickHouse/issues/16202) : décrémente la métrique `ReadonlyReplica` lors du détachement de tables en lecture seule. Cela corrige [#15598](https://github.com/ClickHouse/ClickHouse/issues/15598). [#15592](https://github.com/ClickHouse/ClickHouse/pull/15592) ([sundyli](https://github.com/sundy-li)).
* Rétroporté dans [#16177](https://github.com/ClickHouse/ClickHouse/issues/16177) : possibilité de déplacer une part vers un autre disque/volume si la première tentative a échoué. [#15723](https://github.com/ClickHouse/ClickHouse/pull/15723) ([Pavel Kovalenko](https://github.com/Jokser)).
* Rétroporté dans [#16323](https://github.com/ClickHouse/ClickHouse/issues/16323) : correction de l’échec de `DROP TABLE IF EXISTS` avec l’erreur `Table ... doesn't exist` lorsqu’une table est renommée de manière concurrente (pour le moteur de base de données Atomic). Correction d’un interblocage rare lors de l’exécution concurrente de certaines requêtes DDL sur plusieurs tables (comme `DROP DATABASE` et `RENAME TABLE`). Correction de l’échec de `DROP/DETACH DATABASE` avec `Table ... doesn't exist` lors de l’exécution concurrente de `DROP/DETACH TABLE`. [#15934](https://github.com/ClickHouse/ClickHouse/pull/15934) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#16359](https://github.com/ClickHouse/ClickHouse/issues/16359) : correction de l’analyseur des noms de collation et de jeu de caractères, et prise en charge de `length = 0` pour le type String. [#16008](https://github.com/ClickHouse/ClickHouse/pull/16008) ([Winter Zhang](https://github.com/zhang2014)).
* Rétroporté dans [#16299](https://github.com/ClickHouse/ClickHouse/issues/16299) : correction de `dictGet` dans `sharding_key` (et dans des endroits similaires, c.-à-d. lorsque le Context de la fonction est stocké de façon permanente). [#16205](https://github.com/ClickHouse/ClickHouse/pull/16205) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16234](https://github.com/ClickHouse/ClickHouse/issues/16234) : correction du cas où la mémoire peut être surallouée indépendamment de la limite. Cela clôt [#14560](https://github.com/ClickHouse/ClickHouse/issues/14560). [#16206](https://github.com/ClickHouse/ClickHouse/pull/16206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#16327](https://github.com/ClickHouse/ClickHouse/issues/16327) : correction d’une possible fuite mémoire lors d’un `GROUP BY` avec des clés de type String, causée par une erreur dans l’implémentation de `TwoLevelStringHashTable`. [#16264](https://github.com/ClickHouse/ClickHouse/pull/16264) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#16374](https://github.com/ClickHouse/ClickHouse/issues/16374) : correction de l’INSERT asynchrone Distributed avec `prefer_localhost_replica=0` et `internal_replication`. [#16358](https://github.com/ClickHouse/ClickHouse/pull/16358) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16419](https://github.com/ClickHouse/ClickHouse/issues/16419) : correction de `GROUP BY` avec les modificateurs `totals`/`rollup`/`cube` et les fonctions `min`/`max` sur les clés de `GROUP BY`. Corrige [#16393](https://github.com/ClickHouse/ClickHouse/issues/16393). [#16397](https://github.com/ClickHouse/ClickHouse/pull/16397) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#16448](https://github.com/ClickHouse/ClickHouse/issues/16448) : correction d’une double libération en cas d’exception dans la fonction `dictGet`. Cela pouvait se produire si le dictionnaire avait été chargé avec une erreur. [#16429](https://github.com/ClickHouse/ClickHouse/pull/16429) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
