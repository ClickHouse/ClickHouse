<div id="bug-fix">
  #### Correction de bugs
</div>

* Rétroporté dans [#22191](https://github.com/ClickHouse/ClickHouse/issues/22191) : correction d&#39;une condition de concurrence sur l&#39;objet SSL à l&#39;intérieur de SecureSocket dans Poco. [#21456](https://github.com/ClickHouse/ClickHouse/pull/21456) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Rétroporté dans [#22336](https://github.com/ClickHouse/ClickHouse/issues/22336) : correction d&#39;un `_shard_num` incorrect renvoyé par la fonction de table `clusterAllReplicas`. ferme [#21481](https://github.com/ClickHouse/ClickHouse/issues/21481). [#21498](https://github.com/ClickHouse/ClickHouse/pull/21498) ([flynn](https://github.com/ucasfl)).
* Rétroporté dans [#22092](https://github.com/ClickHouse/ClickHouse/issues/22092) : si une requête a une condition `WHERE` constante et que le paramètre `optimize_skip_unused_shards` est activé, tous les shards peuvent être ignorés et la requête peut renvoyer à tort un résultat vide. [#21550](https://github.com/ClickHouse/ClickHouse/pull/21550) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#22318](https://github.com/ClickHouse/ClickHouse/issues/22318) : suppression des colonnes inconnues de la table jointe dans `WHERE` pour les requêtes vers des moteurs de base de données externes (MySQL, PostgreSQL). ferme [#14614](https://github.com/ClickHouse/ClickHouse/issues/14614), ferme [#19288](https://github.com/ClickHouse/ClickHouse/issues/19288) (dup), ferme [#19645](https://github.com/ClickHouse/ClickHouse/issues/19645) (dup). [#21640](https://github.com/ClickHouse/ClickHouse/pull/21640) ([Vladimir C](https://github.com/vdimir)).
* Rétroporté dans [#22285](https://github.com/ClickHouse/ClickHouse/issues/22285) : début de l&#39;acceptation des connexions après l&#39;initialisation de DDLWorker et des dictionnaires. [#21676](https://github.com/ClickHouse/ClickHouse/pull/21676) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#21753](https://github.com/ClickHouse/ClickHouse/issues/21753) : correction de l&#39;exécution concurrente de `OPTIMIZE` et `DROP` pour `ReplicatedMergeTree`. [#21716](https://github.com/ClickHouse/ClickHouse/pull/21716) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#21809](https://github.com/ClickHouse/ClickHouse/issues/21809) : correction d&#39;un bug dans les moteurs de table ReplicatedMerge lorsque la requête `ALTER MODIFY COLUMN` ne change pas le type d&#39;une colonne Decimal si sa taille (32 bits ou 64 bits) ne change pas. [#21728](https://github.com/ClickHouse/ClickHouse/pull/21728) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#22188](https://github.com/ClickHouse/ClickHouse/issues/22188) : annulation des pools de connexions S3. [#21737](https://github.com/ClickHouse/ClickHouse/pull/21737) ([Vladimir Chebotarev](https://github.com/excitoon)).
* Rétroporté dans [#22240](https://github.com/ClickHouse/ClickHouse/issues/22240) : correction de l&#39;analyse d&#39;index des sous-requêtes scalaires. Cela corrige [#21717](https://github.com/ClickHouse/ClickHouse/issues/21717), introduit dans [https://github.com/ClickHouse/ClickHouse/pull/18896](https://github.com/ClickHouse/ClickHouse/pull/18896). [#21766](https://github.com/ClickHouse/ClickHouse/pull/21766) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#22050](https://github.com/ClickHouse/ClickHouse/issues/22050) : correction d&#39;un interblocage lors de la première exécution du modèle catboost. Ferme [#13832](https://github.com/ClickHouse/ClickHouse/issues/13832). [#21844](https://github.com/ClickHouse/ClickHouse/pull/21844) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#22464](https://github.com/ClickHouse/ClickHouse/issues/22464) : dans de rares cas, une fusion pour `CollapsingMergeTree` peut créer une granule de `index_granularity + 1` lignes. De ce fait, la vérification interne ajoutée dans [#18928](https://github.com/ClickHouse/ClickHouse/issues/18928) (affecte 21.2 et 21.3) peut échouer avec l’erreur `Incomplete granules are not allowed while blocks are granules size`. Cette erreur empêchait la fusion des parts. [#21976](https://github.com/ClickHouse/ClickHouse/pull/21976) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#22204](https://github.com/ClickHouse/ClickHouse/issues/22204) : point d’entrée Docker : éviter le `chown` de `.` lorsque `LOG_PATH` est vide. Corrige [#22100](https://github.com/ClickHouse/ClickHouse/issues/22100). [#22102](https://github.com/ClickHouse/ClickHouse/pull/22102) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#22278](https://github.com/ClickHouse/ClickHouse/issues/22278) : correction de l’attente des requêtes `OPTIMIZE` et `ALTER` pour les moteurs de table `ReplicatedMergeTree`. Désormais, la requête ne restera pas bloquée lorsque la table a été détachée ou redémarrée. [#22118](https://github.com/ClickHouse/ClickHouse/pull/22118) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#22266](https://github.com/ClickHouse/ClickHouse/issues/22266) : correction du nom du pool de threads en arrière-plan. [#22122](https://github.com/ClickHouse/ClickHouse/pull/22122) ([fastio](https://github.com/fastio)).
* Rétroporté dans [#22315](https://github.com/ClickHouse/ClickHouse/issues/22315) : correction du point d’entrée Docker lorsque `http_port` n’est pas présent dans la config. [#22132](https://github.com/ClickHouse/ClickHouse/pull/22132) ([Ewout](https://github.com/devwout)).
* Rétroporté dans [#22502](https://github.com/ClickHouse/ClickHouse/issues/22502) : correction de l’annulation de requête avec `use_hedged_requests=0` et `async_socket_for_remote=1`. [#22183](https://github.com/ClickHouse/ClickHouse/pull/22183) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#22369](https://github.com/ClickHouse/ClickHouse/issues/22369) : désormais, ClickHouse ne lèvera plus d’exception `LOGICAL_ERROR` lorsque l’on tente de muter une part déjà couverte. Corrige [#22013](https://github.com/ClickHouse/ClickHouse/issues/22013). [#22291](https://github.com/ClickHouse/ClickHouse/pull/22291) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#22530](https://github.com/ClickHouse/ClickHouse/issues/22530) : un dépassement de tampon (en lecture) était possible dans l’index de texte intégral `tokenbf_v1`. Les octets excédentaires ne sont pas utilisés, mais l’opération de lecture peut provoquer un crash dans de rares cas. Corrige [#19233](https://github.com/ClickHouse/ClickHouse/issues/19233). [#22421](https://github.com/ClickHouse/ClickHouse/pull/22421) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#22461](https://github.com/ClickHouse/ClickHouse/issues/22461) : ajout de la comptabilisation mémoire manquante dans les routines de parsing en parallèle. Dans les versions précédentes, un OOM était possible lorsque le resultset contenait de très gros blocks de données. Corrige [#22008](https://github.com/ClickHouse/ClickHouse/issues/22008). [#22425](https://github.com/ClickHouse/ClickHouse/pull/22425) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#22557](https://github.com/ClickHouse/ClickHouse/issues/22557) : correction d’un bug dans le partial merge join avec `LowCardinality`. Clôt [#22386](https://github.com/ClickHouse/ClickHouse/issues/22386) et [#22388](https://github.com/ClickHouse/ClickHouse/issues/22388). [#22510](https://github.com/ClickHouse/ClickHouse/pull/22510) ([Vladimir C](https://github.com/vdimir)).
* Rétroporté dans [#22606](https://github.com/ClickHouse/ClickHouse/issues/22606) : correction de la désérialisation d’une chaîne vide sans saut de ligne final au format TSV. Clôt [#20244](https://github.com/ClickHouse/ClickHouse/issues/20244). Contournement possible sans mise à jour de version : définir `input_format_null_as_default` à zéro. Cette valeur était de zéro dans les anciennes versions. [#22527](https://github.com/ClickHouse/ClickHouse/pull/22527) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#22575](https://github.com/ClickHouse/ClickHouse/issues/22575) : correction d’un UB en déverrouillant le rwlock de TinyLog depuis le même thread. [#22560](https://github.com/ClickHouse/ClickHouse/pull/22560) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#22648](https://github.com/ClickHouse/ClickHouse/issues/22648) : évite un UB dans les moteurs *Log lors du déverrouillage du rwlock depuis un autre thread. [#22583](https://github.com/ClickHouse/ClickHouse/pull/22583) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#22682](https://github.com/ClickHouse/ClickHouse/issues/22682) : correction de LOGICAL&#95;ERROR pour Log avec des types Nested sans colonnes dans la clause SELECT. [#22654](https://github.com/ClickHouse/ClickHouse/pull/22654) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#22699](https://github.com/ClickHouse/ClickHouse/issues/22699) : correction de l’attente des mutations sur plusieurs répliques pour les moteurs de table ReplicatedMergeTree. Auparavant, une requête de mutation/ALTER pouvait se terminer avant que la mutation ne soit réellement exécutée sur les autres répliques. [#22669](https://github.com/ClickHouse/ClickHouse/pull/22669) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#22740](https://github.com/ClickHouse/ClickHouse/issues/22740) : correction de blocages possibles dans les requêtes zk en cas d’exception OOM. Corrige [#22438](https://github.com/ClickHouse/ClickHouse/issues/22438). [#22684](https://github.com/ClickHouse/ClickHouse/pull/22684) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
