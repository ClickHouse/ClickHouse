<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Rétroporté [#41264](https://github.com/ClickHouse/ClickHouse/issues/41264) : mise en œuvre de la conversion automatique du moteur de base de données de `Ordinary` vers `Atomic`. Créez un fichier vide `convert_ordinary_to_atomic` dans le répertoire `flags`, et toutes les bases de données `Ordinary` seront automatiquement converties au prochain démarrage du serveur. Résout [#39546](https://github.com/ClickHouse/ClickHouse/issues/39546). [#39933](https://github.com/ClickHouse/ClickHouse/pull/39933) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté [#40886](https://github.com/ClickHouse/ClickHouse/issues/40886) : ajout d&#39;un paramètre permettant de désactiver la limite sur kafka&#95;num&#95;consumers. Ferme [#40331](https://github.com/ClickHouse/ClickHouse/issues/40331). [#40670](https://github.com/ClickHouse/ClickHouse/pull/40670) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="bug-fix">
  #### Correction de bogue
</div>

* rétroporté dans [#41273](https://github.com/ClickHouse/ClickHouse/issues/41273) : corrige des problèmes de sécurité mémoire dans les fonctions `encrypt` et `contingency` lorsqu’un Array de Nullable est utilisé comme argument. Cela corrige [#41004](https://github.com/ClickHouse/ClickHouse/issues/41004). [#40195](https://github.com/ClickHouse/ClickHouse/pull/40195) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* rétroporté dans [#40745](https://github.com/ClickHouse/ClickHouse/issues/40745) : * Corrige le cast lowcard de Nullable dans JoinSwitcher, clôt [#37385](https://github.com/ClickHouse/ClickHouse/issues/37385). [#37453](https://github.com/ClickHouse/ClickHouse/pull/37453) ([Vladimir C](https://github.com/vdimir)).
* rétroporté dans [#41812](https://github.com/ClickHouse/ClickHouse/issues/41812) : Mise à jour de `simdjson`. Cela corrige [#38621](https://github.com/ClickHouse/ClickHouse/issues/38621). [#38838](https://github.com/ClickHouse/ClickHouse/pull/38838) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* rétroporté dans [#41320](https://github.com/ClickHouse/ClickHouse/issues/41320) : Corrige les colonnes inconnues inutilisées introduites par l’instruction WITH. Cela corrige [#37812](https://github.com/ClickHouse/ClickHouse/issues/37812). [#39131](https://github.com/ClickHouse/ClickHouse/pull/39131) ([Amos Bird](https://github.com/amosbird)).
* rétroporté dans [#40904](https://github.com/ClickHouse/ClickHouse/issues/40904) : Corrige un interblocage potentiel dans WriteBufferFromS3 lors d’un échec de planification des tâches. [#40070](https://github.com/ClickHouse/ClickHouse/pull/40070) ([Maksim Kita](https://github.com/kitaisreal)).
* rétroporté dans [#41916](https://github.com/ClickHouse/ClickHouse/issues/41916) : Corrige un bogue rare avec le TTL de colonne pour la famille de moteurs MergeTree : en cas de vertical merge répété, l’erreur `Cannot unlink file ColumnName.bin ... No such file or directory.` pouvait se produire. [#40346](https://github.com/ClickHouse/ClickHouse/pull/40346) ([alesapin](https://github.com/alesapin)).
* rétroporté dans [#40903](https://github.com/ClickHouse/ClickHouse/issues/40903) : Le résolveur de proxy s’arrête après la première requête réussie vers le point de terminaison. [#40353](https://github.com/ClickHouse/ClickHouse/pull/40353) ([Maksim Kita](https://github.com/kitaisreal)).
* rétroporté dans [#40663](https://github.com/ClickHouse/ClickHouse/issues/40663) : Corrige une perte de données potentielle due à un bogue dans le SDK AWS ([https://github.com/aws/aws-sdk-cpp/issues/658](https://github.com/aws/aws-sdk-cpp/issues/658)). Le bogue ne peut être déclenché que lorsque ClickHouse est utilisé avec S3. [#40506](https://github.com/ClickHouse/ClickHouse/pull/40506) ([alesapin](https://github.com/alesapin)).
* rétroporté dans [#40901](https://github.com/ClickHouse/ClickHouse/issues/40901) : Corrige une fuite mémoire lors de l’envoi vers des MV sans contexte de requête (depuis Kafka/...). [#40732](https://github.com/ClickHouse/ClickHouse/pull/40732) ([Azat Khuzhin](https://github.com/azat)).
* rétroporté dans [#41637](https://github.com/ClickHouse/ClickHouse/issues/41637) : Corrige de possibles segfaults, des use-after-free sur le heap et une fuite mémoire dans les combinateurs de fonctions d’agrégation. Corrige [#40848](https://github.com/ClickHouse/ClickHouse/issues/40848). [#41083](https://github.com/ClickHouse/ClickHouse/pull/41083) ([Kruglov Pavel](https://github.com/Avogar)).
* rétroporté dans [#41664](https://github.com/ClickHouse/ClickHouse/issues/41664) : Les requêtes avec une clause `OFFSET` dans une sous-requête et une clause `WHERE` dans la requête externe pouvaient renvoyer un résultat incorrect ; c’est désormais corrigé. Corrige [#40416](https://github.com/ClickHouse/ClickHouse/issues/40416). [#41280](https://github.com/ClickHouse/ClickHouse/pull/41280) ([Alexander Tokmakov](https://github.com/tavplubix)).
* rétroporté dans [#41356](https://github.com/ClickHouse/ClickHouse/issues/41356) : Ajoute une vérification du type de colonne avant l’insertion d’UUID au format MsgPack. [#41309](https://github.com/ClickHouse/ClickHouse/pull/41309) ([Kruglov Pavel](https://github.com/Avogar)).
* Rétroporté dans [#41807](https://github.com/ClickHouse/ClickHouse/issues/41807) : des données malveillantes au format Native pourraient provoquer un plantage. [#41441](https://github.com/ClickHouse/ClickHouse/pull/41441) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41804](https://github.com/ClickHouse/ClickHouse/issues/41804) : la fonction d’agrégation `categorialInformationValue` avait des propriétés incorrectement définies, ce qui pouvait provoquer un déréférencement de pointeur NULL à l’exécution. Clôt [#41443](https://github.com/ClickHouse/ClickHouse/issues/41443). [#41449](https://github.com/ClickHouse/ClickHouse/pull/41449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41503](https://github.com/ClickHouse/ClickHouse/issues/41503) : l’écriture de données au format Apache `ORC` pourrait entraîner un dépassement de tampon. [#41458](https://github.com/ClickHouse/ClickHouse/pull/41458) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#41639](https://github.com/ClickHouse/ClickHouse/issues/41639) : correction d’une exception `pipeline stuck` possible pour les requêtes avec `OFFSET`. L’erreur a été constatée avec `enable_optimize_predicate_expression = 0` et une condition toujours false dans `WHERE`. Corrige [#41383](https://github.com/ClickHouse/ClickHouse/issues/41383). [#41588](https://github.com/ClickHouse/ClickHouse/pull/41588) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#41899](https://github.com/ClickHouse/ClickHouse/issues/41899) : correction d’un plantage possible dans un `SELECT` sur une table `Merge` avec le paramètre `optimize_monotonous_functions_in_order_by` activé. Corrige [#41269](https://github.com/ClickHouse/ClickHouse/issues/41269). [#41740](https://github.com/ClickHouse/ClickHouse/pull/41740) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
