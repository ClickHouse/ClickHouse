<div id="bug-fix-user-visible-misbehavior-in-official-stable-release">
  #### Correction de bogue (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#45903](https://github.com/ClickHouse/ClickHouse/issues/45903) : correction d’un bogue lié à une valeur par défaut non analysable pour une colonne EPHEMERAL dans les métadonnées de la table. [#44026](https://github.com/ClickHouse/ClickHouse/pull/44026) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Rétroporté dans [#46239](https://github.com/ClickHouse/ClickHouse/issues/46239) : quelques segfaults ont été signalés autour de `c-ares`. Toutes les traces de pile récentes observées échouent lors de l’insertion dans `std::unodered_set<>`. Je pense avoir trouvé la cause racine : il semble qu’il s’agisse de requêtes non traitées. Avant cette PR, CH appelait `poll` pour attendre sur les descripteurs de fichier du canal `c-ares`. D’après la [documentation de poll](https://man7.org/linux/man-pages/man2/poll.2.html), une valeur de retour négative signifie qu’une erreur s’est produite. Pour cette raison, nous interrompions l’exécution et renvoyions un échec. Le problème, c’est que `poll` renvoie également une valeur négative lorsqu’une interruption système se produit. Une interruption système ne signifie pas que le traitement a échoué ou s’est terminé, mais nous l’interrompions quand même, car nous vérifiions simplement si la valeur était négative. Une fois l’exécution interrompue, toute la pile est détruite, y compris le `std::unordered_set<std::string>` passé au paramètre `void *` du callback c-ares. Une fois que c-ares avait terminé la requête, le callback était invoqué et accédait à une adresse mémoire invalide, provoquant un segfault. [#45629](https://github.com/ClickHouse/ClickHouse/pull/45629) ([Arthur Passos](https://github.com/arthurpassos)).
* Rétroporté dans [#46216](https://github.com/ClickHouse/ClickHouse/issues/46216) : correction de la lecture de colonnes imbriquées inexistantes sur plusieurs niveaux dans les compact parts. [#46045](https://github.com/ClickHouse/ClickHouse/pull/46045) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#46444](https://github.com/ClickHouse/ClickHouse/issues/46444) : correction d’un `LOGICAL_ERROR` possible dans les asynchronous inserts avec des données invalides envoyées au format `VALUES`. [#46350](https://github.com/ClickHouse/ClickHouse/pull/46350) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#46676](https://github.com/ClickHouse/ClickHouse/issues/46676) : correction d’un traitement incorrect possible d’un argument constant `LowCardinality` dans la fonction `arrayMap`. Ce bogue pouvait entraîner un segfault en version release, ainsi qu’une logical error `Bad cast` dans un build de débogage. [#46569](https://github.com/ClickHouse/ClickHouse/pull/46569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
