<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Valider les types suspects/expérimentaux dans les types imbriqués. Auparavant, nous ne validions pas ces types (sauf JSON) dans les types imbriqués tels que Array/Tuple/Map. [#59385](https://github.com/ClickHouse/ClickHouse/pull/59385) ([Kruglov Pavel](https://github.com/Avogar)).
* La clause de tri `ORDER BY ALL` (introduite avec la v23.12) est remplacée par `ORDER BY *`. La syntaxe précédente était trop sujette aux erreurs pour les tables comportant une colonne `all`. [#59450](https://github.com/ClickHouse/ClickHouse/pull/59450) ([Robert Schulze](https://github.com/rschu1ze)).
* Renommer le paramètre `extract_kvp_max_pairs_per_row` en `extract_key_value_pairs_max_pairs_per_row`. Le bogue (abréviation inutile dans le nom du paramètre) a été introduit dans https://github.com/ClickHouse/ClickHouse/pull/43606. Corriger la documentation de ce paramètre. [#59683](https://github.com/ClickHouse/ClickHouse/pull/59683) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Renommer le paramètre extract&#95;kvp&#95;max&#95;pairs&#95;per&#95;row en extract&#95;key&#95;value&#95;pairs&#95;max&#95;pairs&#95;per&#95;row. Le bogue (abréviation inutile dans le nom du paramètre) a été introduit dans https://github.com/ClickHouse/ClickHouse/pull/43606. Corriger la documentation de ce paramètre. [#59960](https://github.com/ClickHouse/ClickHouse/pull/59960) ([jsc0218](https://github.com/jsc0218)).
* Ajouter une vérification de cohérence du nombre de threads et des tailles de blocs. [#60138](https://github.com/ClickHouse/ClickHouse/pull/60138) ([Raúl Marín](https://github.com/Algunenano)).



<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Ajout du nombre maximal d’échecs de connexion consécutifs au quota. [#54737](https://github.com/ClickHouse/ClickHouse/pull/54737) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* Ajout d’une nouvelle syntaxe permettant de spécifier l’utilisateur définisseur dans View/Materialized View. Cela permet d’exécuter des selects/inserts à partir de vues sans grants explicites sur les tables sous-jacentes. [#54901](https://github.com/ClickHouse/ClickHouse/pull/54901) ([pufit](https://github.com/pufit)).
* Prise en charge de Backup &amp; Restore pour AzureBlobStorage, ce qui résout [#50747](https://github.com/ClickHouse/ClickHouse/issues/50747). [#56988](https://github.com/ClickHouse/ClickHouse/pull/56988) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Mise en œuvre de la conversion automatique de tables MergeTree de différents types vers le moteur Replicated. Créez un fichier vide `convert_to_replicated` dans le répertoire de données de la table (`/clickhouse/store/xxx/xxxyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy/`) et la table sera convertie automatiquement au prochain démarrage du serveur. [#57798](https://github.com/ClickHouse/ClickHouse/pull/57798) ([Kirill](https://github.com/kirillgarbar)).
* Ajout de la table function `mergeTreeIndex`. Elle représente le contenu des fichiers d’index et de marks des tables `MergeTree`. Elle peut être utilisée pour l’introspection. Syntaxe : `mergeTreeIndex(database, table, [with_marks = true])` où `database.table` est une table existante utilisant le moteur `MergeTree`. [#58140](https://github.com/ClickHouse/ClickHouse/pull/58140) ([Anton Popov](https://github.com/CurtizJ)).
* Ajout de la fonction `seriesOutliersTukey` pour détecter les valeurs aberrantes dans des series data à l’aide de l’algorithme des clôtures de Tukey. [#58632](https://github.com/ClickHouse/ClickHouse/pull/58632) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* L’utilisateur peut désormais spécifier directement la chaîne de modèle dans la query en utilisant `format_schema_rows_template` comme alternative à `format_template_row`. Closes [#31363](https://github.com/ClickHouse/ClickHouse/issues/31363). [#59088](https://github.com/ClickHouse/ClickHouse/pull/59088) ([Shaun Struwig](https://github.com/Blargian)).
* Tentative de détection automatique du format de fichier lors de l’inférence de schéma s’il est inconnu dans les moteurs `file/s3/hdfs/url/azureBlobStorage`. Closes [#50576](https://github.com/ClickHouse/ClickHouse/issues/50576). [#59092](https://github.com/ClickHouse/ClickHouse/pull/59092) ([Kruglov Pavel](https://github.com/Avogar)).
* Ajout de la fonction `variantType` qui renvoie un Enum avec le nom du type de variant pour chaque row. [#59398](https://github.com/ClickHouse/ClickHouse/pull/59398) ([Kruglov Pavel](https://github.com/Avogar)).
* Ajout de la query `ALTER TABLE table FORGET PARTITION partition` qui supprime les nœuds ZooKeeper liés à une partition vide. [#59507](https://github.com/ClickHouse/ClickHouse/pull/59507) ([Sergei Trifonov](https://github.com/serxa)).
* Prise en charge du fichier de credentials JWT pour le table engine NATS. [#59543](https://github.com/ClickHouse/ClickHouse/pull/59543) ([Nickolaj Jepsen](https://github.com/nickolaj-jepsen)).
* Ajout de la nouvelle aggregate function `groupArrayIntersect`. Fait suite à : [#49862](https://github.com/ClickHouse/ClickHouse/issues/49862). [#59598](https://github.com/ClickHouse/ClickHouse/pull/59598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Mise en œuvre de la table system.dns&#95;cache, qui peut être utile pour le debugging des problèmes DNS. [#59856](https://github.com/ClickHouse/ClickHouse/pull/59856) ([Kirill Nikiforov](https://github.com/allmazz)).
* Le codec `LZ4HC` accepte désormais un nouveau niveau 2, plus rapide que l’ancien niveau minimal 3, au prix d’une compression plus faible. Dans les versions précédentes, `LZ4HC(2)` et les niveaux inférieurs étaient équivalents à `LZ4HC(3)`. Auteur : [Cyan4973](https://github.com/Cyan4973). [#60090](https://github.com/ClickHouse/ClickHouse/pull/60090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Implémentation de la table system.dns&#95;cache, qui peut être utile pour le débogage des problèmes DNS. Nouveau paramètre de serveur dns&#95;cache&#95;max&#95;size. [#60257](https://github.com/ClickHouse/ClickHouse/pull/60257) ([Kirill Nikiforov](https://github.com/allmazz)).
* Prise en charge d’une version à un seul argument pour la fonction de table merge, sous la forme `merge(['db_name', ] 'tables_regexp')`. [#60372](https://github.com/ClickHouse/ClickHouse/pull/60372) ([豪肥肥](https://github.com/HowePa)).
* Ajout d’une nouvelle syntaxe permettant de spécifier l’utilisateur definer dans View/Materialized View. Cela permet d’exécuter des SELECT/INSERT à partir de vues sans grant explicite sur les tables sous-jacentes. [#60439](https://github.com/ClickHouse/ClickHouse/pull/60439) ([pufit](https://github.com/pufit)).



<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Élimine les agrégateurs min/max/any/anyLast des clés GROUP BY dans la section SELECT. [#52230](https://github.com/ClickHouse/ClickHouse/pull/52230) ([JackyWoo](https://github.com/JackyWoo)).
* Fonctions de distance vectorisées utilisées pour la recherche vectorielle. [#58866](https://github.com/ClickHouse/ClickHouse/pull/58866) ([Robert Schulze](https://github.com/rschu1ze)).
* Poursuite de l&#39;optimisation des défauts de prédiction de branchement de la fonction if lorsque le type de résultat est float*/decimal*/int*, dans la continuité de https://github.com/ClickHouse/ClickHouse/pull/57885. [#59148](https://github.com/ClickHouse/ClickHouse/pull/59148) ([李扬](https://github.com/taiyang-li)).
* Optimise la fonction if lorsque le type d&#39;entrée est Map, avec une accélération d&#39;environ 10x. [#59413](https://github.com/ClickHouse/ClickHouse/pull/59413) ([李扬](https://github.com/taiyang-li)).
* Améliore les performances du type Int8 en implémentant le strict aliasing. [#59485](https://github.com/ClickHouse/ClickHouse/pull/59485) ([Raúl Marín](https://github.com/Algunenano)).
* Optimise conditionnellement les performances de sum/avg pour les types bigint et big decimal en réduisant les défauts de prédiction de branchement. [#59504](https://github.com/ClickHouse/ClickHouse/pull/59504) ([李扬](https://github.com/taiyang-li)).
* Améliore les performances des SELECT avec des mutations actives. [#59531](https://github.com/ClickHouse/ClickHouse/pull/59531) ([Azat Khuzhin](https://github.com/azat)).
* Fonction `isNotNull` optimisée avec AVX2. [#59621](https://github.com/ClickHouse/ClickHouse/pull/59621) ([李扬](https://github.com/taiyang-li)).
* Réutilise le résultat de `FunctionFactory::instance().get("isNotNull", context)` et de `FunctionFactory::instance().get("assumeNotNull", context)`. Veille à ce qu&#39;il ne soit appelé qu&#39;une seule fois pendant la durée de vie de `FunctionCoalesce`. [#59627](https://github.com/ClickHouse/ClickHouse/pull/59627) ([李扬](https://github.com/taiyang-li)).
* Améliore les performances de ASOF JOIN pour les données triées ou presque triées. [#59731](https://github.com/ClickHouse/ClickHouse/pull/59731) ([Maksim Kita](https://github.com/kitaisreal)).
* La clé primaire utilisera moins de mémoire. [#60049](https://github.com/ClickHouse/ClickHouse/pull/60049) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Améliore l&#39;utilisation de la mémoire pour la clé primaire et certaines autres opérations. [#60050](https://github.com/ClickHouse/ClickHouse/pull/60050) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Les clés primaires des tables seront chargées en mémoire de manière différée lors du premier accès. Ce comportement est contrôlé par le nouveau paramètre MergeTree `primary_key_lazy_load`, activé par défaut. Cela offre plusieurs avantages : - elles ne seront pas chargées pour les tables non utilisées ; - s&#39;il n&#39;y a pas assez de mémoire, une exception sera levée lors de la première utilisation plutôt qu&#39;au démarrage du serveur. Cela présente aussi plusieurs inconvénients : - la latence de chargement de la clé primaire sera supportée par la première requête plutôt qu&#39;avant l&#39;acceptation des connexions ; cela peut théoriquement introduire un problème d&#39;effet de troupeau. Cela clôt [#11188](https://github.com/ClickHouse/ClickHouse/issues/11188). [#60093](https://github.com/ClickHouse/ClickHouse/pull/60093) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Fonction vectorisée `dotProduct`, utile pour la recherche vectorielle. [#60202](https://github.com/ClickHouse/ClickHouse/pull/60202) ([Robert Schulze](https://github.com/rschu1ze)).

* L’exécution de `ALTER COLUMN MATERIALIZE` sur une colonne avec une expression `DEFAULT` ou `MATERIALIZED` écrit désormais les valeurs correctes : la valeur par défaut pour les parts existantes ayant une valeur par défaut, ou la valeur non par défaut pour les parts existantes ayant une valeur non par défaut. * Mise en œuvre de l’ajustement automatique des délais d’expiration des insertions asynchrones. Les paramètres suivants sont introduits : async&#95;insert&#95;poll&#95;timeout&#95;ms, async&#95;insert&#95;use&#95;adaptive&#95;busy&#95;timeout, async&#95;insert&#95;busy&#95;timeout&#95;min&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;max&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;increase&#95;rate, async&#95;insert&#95;busy&#95;timeout&#95;decrease&#95;rate. [#58486](https://github.com/ClickHouse/ClickHouse/pull/58486) ([Julia Kartseva](https://github.com/jkartseva)).
* Autorise la définition de `volume_priority` dans `storage_configuration`. [#58533](https://github.com/ClickHouse/ClickHouse/pull/58533) ([Andrey Zvonov](https://github.com/zvonand)).
* Ajout de la prise en charge du type Date32 dans le codec T64. [#58738](https://github.com/ClickHouse/ClickHouse/pull/58738) ([Hongbin Ma (Mahone)](https://github.com/binmahone)).
* Prise en charge de `LEFT JOIN`, `ALL INNER JOIN` et des sous-requêtes simples pour les répliques parallèles (uniquement avec l’analyseur). Le nouveau paramètre `parallel_replicas_prefer_local_join` choisit l’exécution locale de `JOIN` (par défaut) plutôt que `GLOBAL JOIN`. Toutes les tables doivent exister sur chaque réplique de `cluster_for_parallel_replicas`. Les nouveaux paramètres `min_external_table_block_size_rows` et `min_external_table_block_size_bytes` sont utilisés pour regrouper les petits blocs envoyés pour les tables temporaires (uniquement avec l’analyseur). [#58916](https://github.com/ClickHouse/ClickHouse/pull/58916) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Autorise les virgules finales dans les types comportant plusieurs éléments. [#59119](https://github.com/ClickHouse/ClickHouse/pull/59119) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Autorise le traitement parallèle et distribué pour le moteur de table `S3Queue`. Pour le traitement distribué, utilisez le paramètre `s3queue_total_shards_num` (par défaut `1`). Le paramètre `s3queue_processing_threads_num` n&#39;était auparavant pas autorisé pour le mode de traitement Ordered, mais il l&#39;est désormais. Avertissement : les paramètres `s3queue_processing_threads_num` (threads de traitement pour chaque shard) et `s3queue_total_shards_num` du mode Ordered modifient la façon dont les métadonnées sont stockées (en portant le nombre de nœuds `max_processed_file` à `s3queue_processing_threads_num * s3queue_total_shards_num`) ; ils doivent donc être identiques pour tous les shards et ne peuvent plus être modifiés dès lors qu&#39;au moins un shard a été créé. [#59167](https://github.com/ClickHouse/ClickHouse/pull/59167) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Autorise la création concurrente de tables dans `DatabaseReplicated` pendant `recoverLostReplica`. [#59277](https://github.com/ClickHouse/ClickHouse/pull/59277) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Les paramètres du moteur de table Distributed peuvent désormais être spécifiés dans le fichier de configuration du serveur (de façon similaire aux paramètres MergeTree), par ex. `<distributed> <flush_on_detach>false</flush_on_detach> </distributed>`. [#59291](https://github.com/ClickHouse/ClickHouse/pull/59291) ([Azat Khuzhin](https://github.com/azat)).
* Utilise MergeTree comme moteur de table par défaut. Cela améliore nettement l&#39;ergonomie et rapproche davantage le comportement de ClickHouse Cloud. [#59316](https://github.com/ClickHouse/ClickHouse/pull/59316) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Réessaie en cas de déconnexion et de session expirée lors de la lecture de `system.zookeeper`. Cela est utile lors de la lecture d&#39;un grand nombre de lignes de la table `system.zookeeper`, en particulier en présence de déconnexions injectées pour tester les pannes. [#59388](https://github.com/ClickHouse/ClickHouse/pull/59388) ([Alexander Gololobov](https://github.com/davenger)).
* N&#39;interprète pas les nombres avec des zéros initiaux comme des valeurs octales lorsque `input_format_values_interpret_expressions=0`. [#59403](https://github.com/ClickHouse/ClickHouse/pull/59403) ([Joanna Hulboj](https://github.com/jh0x)).
* Au démarrage et chaque fois que des fichiers de configuration sont modifiés, ClickHouse met à jour les limites strictes de mémoire de son memory tracker global. Ces limites sont calculées à partir de divers paramètres serveur et des limites cgroups (sous Linux). Auparavant, `/sys/fs/cgroup/memory.max` (pour cgroups v2) était codé en dur. Par conséquent, les limites mémoire cgroup v2 configurées pour des groupes imbriqués (hiérarchies), par ex. `/sys/fs/cgroup/my/nested/group/memory.max`, étaient ignorées. Ce problème est désormais corrigé. Le comportement des limites mémoire v1 reste inchangé. [#59435](https://github.com/ClickHouse/ClickHouse/pull/59435) ([Robert Schulze](https://github.com/rschu1ze)).
* De nouveaux événements de profil ont été ajoutés pour observer le temps passé à calculer les PK/projections/index secondaires pendant les `INSERT`. [#59436](https://github.com/ClickHouse/ClickHouse/pull/59436) ([Nikita Taranov](https://github.com/nickitat)).
* Autorise la définition d&#39;un point de départ pour S3Queue en mode Ordered lors de la création à l&#39;aide du paramètre `s3queue_last_processed_path`. [#59446](https://github.com/ClickHouse/ClickHouse/pull/59446) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Amélioration de Keeper : met uniquement en cache une quantité limitée de logs en mémoire, contrôlée par `latest_logs_cache_size_threshold` et `commit_logs_cache_size_threshold`. [#59460](https://github.com/ClickHouse/ClickHouse/pull/59460) ([Antonio Andelic](https://github.com/antonio2368)).
* Les commentaires des tables système sont désormais également disponibles dans `system.tables` dans `clickhouse-local`. [#59493](https://github.com/ClickHouse/ClickHouse/pull/59493) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* N&#39;infère plus par défaut les nombres à virgule flottante en notation exponentielle. Ajoute un paramètre `input_format_try_infer_exponent_floats` qui rétablit le comportement précédent (désactivé par défaut). Ferme [#59476](https://github.com/ClickHouse/ClickHouse/issues/59476). [#59500](https://github.com/ClickHouse/ClickHouse/pull/59500) ([Kruglov Pavel](https://github.com/Avogar)).
* Autoriser les opérations `alter` à être entourées de parenthèses. L&#39;ajout de parenthèses peut être contrôlé par la config `format_alter_operations_with_parentheses`. Par défaut, dans les requêtes formatées, les parenthèses sont ajoutées, car nous stockons à certains endroits les opérations `alter` formatées comme métadonnées (par ex. : mutations). La nouvelle syntaxe clarifie certaines requêtes dans lesquelles les opérations `alter` se terminent par une liste. Par ex. : `ALTER TABLE x MODIFY TTL date GROUP BY a, b, DROP COLUMN c` ne peut pas être analysée correctement avec l&#39;ancienne syntaxe. Avec la nouvelle syntaxe, la requête `ALTER TABLE x (MODIFY TTL date GROUP BY a, b), (DROP COLUMN c)` est sans ambiguïté. Les anciennes versions ne peuvent pas lire la nouvelle syntaxe ; son utilisation peut donc entraîner des problèmes si des versions plus récentes et plus anciennes de ClickHouse coexistent dans un même cluster. [#59532](https://github.com/ClickHouse/ClickHouse/pull/59532) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* La valeur par défaut précédente de `async_insert_max_data_size`, fixée à 1 MB, s&#39;est révélée trop faible. La nouvelle valeur est de 10 MiB. [#59536](https://github.com/ClickHouse/ClickHouse/pull/59536) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Auparavant, l&#39;ensemble du résultat était accumulé en mémoire et renvoyé sous la forme d&#39;un seul gros bloc. Ce changement devrait aider à réduire la consommation de mémoire lors de la lecture d&#39;un grand nombre de lignes depuis `system.zookeeper`, permettre d&#39;afficher une progression intermédiaire (combien de lignes ont été lues jusqu&#39;à présent) et éviter d&#39;atteindre le délai d&#39;attente de connexion lorsque le jeu de résultats est volumineux. [#59545](https://github.com/ClickHouse/ClickHouse/pull/59545) ([Alexander Gololobov](https://github.com/davenger)).
* Le tableau de bord comprend désormais les états compressé et non compressé du #hash des URL (compatibilité ascendante). Suite de [#59124](https://github.com/ClickHouse/ClickHouse/issues/59124). [#59548](https://github.com/ClickHouse/ClickHouse/pull/59548) ([Amos Bird](https://github.com/amosbird)).
* Mise à niveau d&#39;Intel QPL (utilisé par le codec `DEFLATE_QPL`) de v1.3.1 à v1.4.0. Un bug du mécanisme de timeout de polling a également été corrigé, car nous avons observé que, dans certains cas, le timeout ne fonctionnait pas correctement ; lorsqu&#39;un timeout se produit, IAA et le CPU peuvent traiter le buffer simultanément. Pour l&#39;instant, il est préférable de s&#39;assurer que le status du codec IAA n&#39;est pas `QPL_STS_BEING_PROCESSED`, puis de basculer vers le codec logiciel. [#59551](https://github.com/ClickHouse/ClickHouse/pull/59551) ([jasperzhu](https://github.com/jinjunzh)).
* Amélioration de Keeper : réduction supplémentaire de la taille du nœud de données. [#59592](https://github.com/ClickHouse/ClickHouse/pull/59592) ([Antonio Andelic](https://github.com/antonio2368)).
* Ne pas afficher d&#39;avertissement concernant la version du serveur dans ClickHouse Cloud, car ClickHouse Cloud gère automatiquement les mises à niveau sans interruption. [#59657](https://github.com/ClickHouse/ClickHouse/pull/59657) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Après l&#39;auto-extraction, le binaire temporaire est déplacé au lieu d&#39;être copié. [#59661](https://github.com/ClickHouse/ClickHouse/pull/59661) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Correction du déroulage de pile sur MacOS. Ceci clôt [#53653](https://github.com/ClickHouse/ClickHouse/issues/53653). [#59690](https://github.com/ClickHouse/ClickHouse/pull/59690) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
