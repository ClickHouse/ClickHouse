<div id="clickhouse-release-v208545-lts-fixme-as-compared-to-v208411-lts">
  ### Version de ClickHouse v20.8.5.45-lts FIXME par rapport à v20.8.4.11-lts
</div>

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#16146](https://github.com/ClickHouse/ClickHouse/issues/16146) : il est désormais possible d’exécuter des requêtes `ALTER ... ON CLUSTER` quelle que soit la valeur du paramètre `<internal_replication>` dans la configuration du cluster. [#16075](https://github.com/ClickHouse/ClickHouse/pull/16075) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#16310](https://github.com/ClickHouse/ClickHouse/issues/16310) : ajout de allow&#95;nondeterministic&#95;optimize&#95;skip&#95;unused&#95;shards (pour autoriser des expressions non déterministes comme rand() ou dictGet() dans la clé de sharding). [#16105](https://github.com/ClickHouse/ClickHouse/pull/16105) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix">
  #### Correction de bogues
</div>

* Rétroporté dans [#15620](https://github.com/ClickHouse/ClickHouse/issues/15620) : déclenche désormais une erreur lorsqu’un seul paramètre est passé à ReplicatedMergeTree, au lieu de l’ignorer. [#15516](https://github.com/ClickHouse/ClickHouse/pull/15516) ([nvartolomei](https://github.com/nvartolomei)).
* Rétroporté dans [#16203](https://github.com/ClickHouse/ClickHouse/issues/16203) : décrémente la métrique `ReadonlyReplica` lors du détachement de tables en lecture seule. Cela corrige [#15598](https://github.com/ClickHouse/ClickHouse/issues/15598). [#15592](https://github.com/ClickHouse/ClickHouse/pull/15592) ([sundyli](https://github.com/sundy-li)).
* Rétroporté dans [#16230](https://github.com/ClickHouse/ClickHouse/issues/16230) : correction d’un bug lié aux globs dans la S3 table function : la région extraite de l’URL n’était pas appliquée à la configuration du client S3. [#15646](https://github.com/ClickHouse/ClickHouse/pull/15646) ([Vladimir Chebotarev](https://github.com/excitoon)).
* Rétroporté dans [#15871](https://github.com/ClickHouse/ClickHouse/issues/15871) : corrige l’erreur `Cannot add simple transform to empty Pipe`, qui se produisait lors de la lecture depuis une table `Buffer` dont la structure diffère de celle de la table de destination. Cela pouvait se produire si la table de destination renvoyait un résultat vide pour la requête. Corrige [#15529](https://github.com/ClickHouse/ClickHouse/issues/15529). [#15662](https://github.com/ClickHouse/ClickHouse/pull/15662) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#15772](https://github.com/ClickHouse/ClickHouse/issues/15772) : correction d’une valeur par défaut trop faible pour le paramètre `max_replicated_logs_to_keep`, ce qui pouvait entraîner des pertes de répliques trop fréquentes. Améliore le processus de récupération des répliques perdues en choisissant pour le clonage la réplique la plus à jour. En outre, les anciennes parts de la réplique perdue ne sont plus supprimées, mais détachées. [#15701](https://github.com/ClickHouse/ClickHouse/pull/15701) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#15738](https://github.com/ClickHouse/ClickHouse/issues/15738) : corrige l’erreur `Cannot find column` qui peut survenir lors d’une insertion dans `MATERIALIZED VIEW` si la requête pour `MV` contient `ARRAY JOIN`. [#15717](https://github.com/ClickHouse/ClickHouse/pull/15717) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#15795](https://github.com/ClickHouse/ClickHouse/issues/15795) : corrige certains cas de requêtes dans lesquelles seules des colonnes virtuelles sont sélectionnées. Auparavant, l’exception `Not found column _nothing in block` pouvait être levée. Corrige [#12298](https://github.com/ClickHouse/ClickHouse/issues/12298). [#15756](https://github.com/ClickHouse/ClickHouse/pull/15756) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#15900](https://github.com/ClickHouse/ClickHouse/issues/15900) : corrige l’exception `Block structure mismatch` dans les requêtes `SELECT ... ORDER BY DESC` exécutées après une requête `ALTER MODIFY COLUMN`. Corrige [#15800](https://github.com/ClickHouse/ClickHouse/issues/15800). [#15852](https://github.com/ClickHouse/ClickHouse/pull/15852) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#15925](https://github.com/ClickHouse/ClickHouse/issues/15925) : désormais, une exception est levée lorsque `ALTER MODIFY COLUMN ... DEFAULT ...` définit une valeur par défaut incompatible avec le type de la colonne. Corrige [#15854](https://github.com/ClickHouse/ClickHouse/issues/15854). [#15858](https://github.com/ClickHouse/ClickHouse/pull/15858) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#15920](https://github.com/ClickHouse/ClickHouse/issues/15920) : corrige de possibles interblocages dans RBAC. [#15875](https://github.com/ClickHouse/ClickHouse/pull/15875) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#16168](https://github.com/ClickHouse/ClickHouse/issues/16168) : correction d’un résultat vide incorrect pour une requête issue d’une table `Distributed` lorsque la requête contient `WHERE`, `PREWHERE` et `GLOBAL IN`. Corrige [#15792](https://github.com/ClickHouse/ClickHouse/issues/15792). [#15933](https://github.com/ClickHouse/ClickHouse/pull/15933) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#16355](https://github.com/ClickHouse/ClickHouse/issues/16355) : correction de l’échec de `DROP TABLE IF EXISTS` avec l’erreur `Table ... doesn't exist` lorsque la table est renommée de façon concurrente (pour le moteur de base de données Atomic). Correction d’un interblocage rare lors de l’exécution concurrente de certaines requêtes DDL sur plusieurs tables (comme `DROP DATABASE` et `RENAME TABLE`). Correction de l’échec de `DROP/DETACH DATABASE` avec `Table ... doesn't exist` lors de l’exécution concurrente de `DROP/DETACH TABLE`. [#15934](https://github.com/ClickHouse/ClickHouse/pull/15934) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#15968](https://github.com/ClickHouse/ClickHouse/issues/15968) : correction d’un plantage lorsque la création de la base de données échoue. [#15954](https://github.com/ClickHouse/ClickHouse/pull/15954) ([Winter Zhang](https://github.com/zhang2014)).
* Rétroporté dans [#16025](https://github.com/ClickHouse/ClickHouse/issues/16025) : correction d’une ambiguïté dans l’analyse des settings profiles : `CREATE USER ... SETTINGS profile readonly` est désormais interprété comme l’utilisation d’un profil nommé `readonly`, et non comme un paramètre nommé `profile` avec la contrainte readonly. Cela corrige [#15628](https://github.com/ClickHouse/ClickHouse/issues/15628). [#15982](https://github.com/ClickHouse/ClickHouse/pull/15982) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#16219](https://github.com/ClickHouse/ClickHouse/issues/16219) : correction de rares segfaults lors d’insertions dans MaterializedView ou de sélections depuis celle-ci, avec suppression concurrente de la table cible (pour le moteur de base de données Atomic). [#15984](https://github.com/ClickHouse/ClickHouse/pull/15984) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Rétroporté dans [#16029](https://github.com/ClickHouse/ClickHouse/issues/16029) : évite le blocage d’une replica pendant 5 à 10 minutes lorsqu’une erreur de replication survient après une période d’inactivité. [#15987](https://github.com/ClickHouse/ClickHouse/pull/15987) ([filimonov](https://github.com/filimonov)).
* Rétroporté dans [#16088](https://github.com/ClickHouse/ClickHouse/issues/16088) : autorise l’utilisation de la disposition direct pour les dictionnaires à clé complexe. [#16007](https://github.com/ClickHouse/ClickHouse/pull/16007) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#16360](https://github.com/ClickHouse/ClickHouse/issues/16360) : correction de l’analyseur des noms de collation et de jeu de caractères, et prise en charge de `length = 0` pour le type String. [#16008](https://github.com/ClickHouse/ClickHouse/pull/16008) ([Winter Zhang](https://github.com/zhang2014)).
* Rétroporté dans [#16141](https://github.com/ClickHouse/ClickHouse/issues/16141) : correction du blocage de la requête `ALTER MODIFY ... ORDER BY` pour `ReplicatedVersionedCollapsingMergeTree`. Cela corrige [#15980](https://github.com/ClickHouse/ClickHouse/issues/15980). [#16011](https://github.com/ClickHouse/ClickHouse/pull/16011) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#16078](https://github.com/ClickHouse/ClickHouse/issues/16078) : correction de la régression [#15780](https://github.com/ClickHouse/ClickHouse/issues/15780) ; par exemple, `indexOf([1, 2, 3], toLowCardinality(1))` est désormais interdit alors que cela ne devrait pas l’être. [#16038](https://github.com/ClickHouse/ClickHouse/pull/16038) ([Mike Kot](https://github.com/myrrc)).
* Rétroporté dans [#16294](https://github.com/ClickHouse/ClickHouse/issues/16294) : correction de `dictGet` dans sharding&#95;key (et dans des cas similaires, c.-à-d. lorsque le contexte de la fonction est stocké de manière permanente). [#16205](https://github.com/ClickHouse/ClickHouse/pull/16205) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16233](https://github.com/ClickHouse/ClickHouse/issues/16233) : correction du cas où la mémoire pouvait être allouée au-delà de la limite. Ce correctif résout [#14560](https://github.com/ClickHouse/ClickHouse/issues/14560). [#16206](https://github.com/ClickHouse/ClickHouse/pull/16206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#16325](https://github.com/ClickHouse/ClickHouse/issues/16325) : correction d’une fuite de mémoire possible lors d’un `GROUP BY` avec des clés de type chaîne, due à une erreur dans l’implémentation de `TwoLevelStringHashTable`. [#16264](https://github.com/ClickHouse/ClickHouse/pull/16264) ([Amos Bird](https://github.com/amosbird)).
* Rétroporté dans [#16375](https://github.com/ClickHouse/ClickHouse/issues/16375) : correction de l’`INSERT` asynchrone sur Distributed avec prefer&#95;localhost&#95;replica=0 et internal&#95;replication. [#16358](https://github.com/ClickHouse/ClickHouse/pull/16358) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#16431](https://github.com/ClickHouse/ClickHouse/issues/16431) : correction de `GROUP BY` avec les modificateurs totals/rollup/cube et les fonctions min/max sur les clés de `GROUP BY`. Corrige [#16393](https://github.com/ClickHouse/ClickHouse/issues/16393). [#16397](https://github.com/ClickHouse/ClickHouse/pull/16397) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#16450](https://github.com/ClickHouse/ClickHouse/issues/16450) : correction d’une double libération en cas d’exception dans la fonction `dictGet`. Cela pouvait se produire si le dictionnaire se chargeait avec une erreur. [#16429](https://github.com/ClickHouse/ClickHouse/pull/16429) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
