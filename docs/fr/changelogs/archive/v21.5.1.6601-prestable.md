<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Modification de la comparaison entre les entiers et les nombres à virgule flottante lorsqu’un entier n’est pas représentable exactement dans un type de données à virgule flottante. Dans la nouvelle version, la comparaison renverra false, car une erreur d’arrondi se produira. Exemple : `9223372036854775808.0 != 9223372036854775808`, car le nombre `9223372036854775808` n’est pas représentable exactement sous forme de nombre à virgule flottante (et `9223372036854775808.0` est arrondi à `9223372036854776000.0`). Dans la version précédente, en revanche, la comparaison considérait ces nombres comme égaux, car si le nombre à virgule flottante `9223372036854776000.0` était reconverti en UInt64, il donnait `9223372036854775808`. À titre de référence, le langage de programmation Python considère lui aussi ces nombres comme égaux. Cependant, ce comportement dépendait du modèle de CPU (avec des résultats différents sur AMD64 et AArch64 pour certains nombres hors plage), nous rendons donc la comparaison plus précise. Les nombres entiers et les nombres à virgule flottante ne seront considérés comme égaux que si l’entier est représenté exactement dans le type à virgule flottante. [#22595](https://github.com/ClickHouse/ClickHouse/pull/22595) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
