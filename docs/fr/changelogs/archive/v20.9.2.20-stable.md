  ### Version ClickHouse v20.9.2.20-stable FIXME comparée à v20.8.1.4513-prestable
</div>

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Ajout de la fonction de table `view`, qui transforme une sous-requête en objet de type table. Cela facilite la réutilisation des requêtes. Par exemple, elle peut être utilisée dans les fonctions de table remote/cluster. [#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* Il est désormais possible d’écrire `select * apply(length) apply(max) from wide_string_table` pour trouver la longueur maximale de toutes les colonnes de type String. Les deux variantes suivantes sont également disponibles : [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* Ajout d’une fonction d’agrégation RankCorrelationSpearman qui calcule simplement un coefficient de corrélation des rangs. Dans la continuité de [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769). [#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Ajout d’un utilitaire de génération de base de données à partir de requêtes. Dans la continuité de [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973). [#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Optimisation des requêtes avec LIMIT/LIMIT BY/ORDER BY pour Distributed avec GROUP BY sharding&#95;key (avec optimize&#95;skip&#95;unused&#95;shards et optimize&#95;distributed&#95;group&#95;by&#95;sharding&#95;key). [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Amélioration
</div>

* Améliorations de StorageRabbitMQ : ajout de la gestion des défaillances de connexion et de canaux, gestion correcte des commits, gestion des échecs d&#39;insert, meilleurs exchanges, durabilité des files d&#39;attente et possibilité de reprise des files d&#39;attente, nouveaux paramètres de file d&#39;attente. Tests corrigés. [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Ajout de l&#39;autorisation `requirepass` pour Redis. [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* Ajout d&#39;un argument de précision pour le type DateTime. [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* Amélioration des performances du moteur Kafka en fournissant un thread indépendant pour chaque consumer. Pool de threads distinct pour les moteurs de streaming (comme Kafka). [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* Ajout du codec de compression par défaut pour les parts dans `system.part_log`, nommé `default_compression_codec`. [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* Remplacement des entiers larges de boost multiprecision par l&#39;implémentation de [https://github.com/cerevra/int](https://github.com/cerevra/int). [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* Conversion implicite de la clé primaire en Not null dans MaterializeMySQL (comme dans MySQL). Corrige [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114). [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* Ajout du nouveau paramètre `system_events_show_zero_values`, comme proposé dans [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384). [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Désormais, l&#39;obfuscateur prend en charge le type UUID, comme proposé dans [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163). [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Création des sets pour plusieurs `JOIN` et `IN` en parallèle. Cela peut légèrement améliorer les performances des requêtes comportant plusieurs expressions `IN subquery` différentes. [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Désormais, les TTL seront appliqués lors des merge s&#39;ils n&#39;ont pas été matérialisés auparavant. [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* Le handler MySQL renvoie `OK` pour des requêtes comme `SET @@var = value`. Cette instruction est ignorée. Cela est nécessaire, car certains drivers MySQL envoient une requête `SET @@` pour la configuration après le handshake [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422. [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* Les arguments `time_zone` vides ne sont pas autorisés dans les fonctions de type `toStartOf*`. [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* Rétroporté dans [#14873](https://github.com/ClickHouse/ClickHouse/issues/14873) : autorisation d&#39;utiliser une configuration de stockage multi-volume dans le stockage Distributed. [#14839](https://github.com/ClickHouse/ClickHouse/pull/14839) ([Pavel Kovalenko](https://github.com/Jokser)).
