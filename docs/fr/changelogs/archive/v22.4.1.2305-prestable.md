<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* La fonction `yandexConsistentHash` (algorithme de hachage cohérent de Konstantin &quot;kostik&quot; Oblakov) a été renommée en `kostikConsistentHash`. L&#39;ancien nom est conservé comme alias pour des raisons de compatibilité. Bien que ce changement soit rétrocompatible, nous pourrions supprimer cet alias dans les versions suivantes ; il est donc recommandé de mettre à jour les usages de cette fonction dans vos applications. [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* SETTINGS n&#39;est pas autorisé après FORMAT pour les requêtes INSERT (un paramètre de compatibilité, `allow_settings_after_format_in_insert`, permet d&#39;accepter ce type de requêtes, mais il est désactivé par défaut). [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* Le chemin haché des fichiers de cache a été modifié. [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Accélération du processus de chargement des parts de MergeTree afin de réduire le temps de démarrage de clickhouse-server. Grâce à cette amélioration, clickhouse-server a pu faire passer son temps de démarrage de 75 minutes à 20 secondes, avec 700k parts MergeTree. [#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* Les tailles des tables de hachage utilisées pendant l&#39;agrégation sont désormais collectées et réutilisées dans les requêtes suivantes afin d&#39;éviter leur redimensionnement. [#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* Plusieurs modifications ont été apportées pour améliorer les performances de ASOF JOIN (gain de 1,2x à 1,6x). La prise en charge des grands entiers a également été ajoutée. [#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* Le moteur de stockage URL télécharge désormais plusieurs fragments en parallèle si le point de terminaison prend en charge HTTP Range. Deux paramètres supplémentaires ont été ajoutés, `max_download_threads` et `max_download_buffer_size`, qui contrôlent le nombre maximal de threads qu&#39;une seule requête peut utiliser pour télécharger le fichier, ainsi que le nombre maximal d&#39;octets que chaque thread peut traiter. [#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* Parallélisation du téléversement multipart vers le stockage S3. [#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* Améliore les performances de ASOF JOIN lorsque la clé est un entier natif. [#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* Nouvelle optimisation du plan de requête. Les fonctions sont évaluées après `ORDER BY` lorsque c&#39;est possible. Par exemple, pour la requête `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5`, la fonction `sipHash64` serait évaluée après `ORDER BY` et `LIMIT`, ce qui apporte une accélération d&#39;environ 20x. [#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* Réduction de la portée du mutex pour le problème lié à setenv LIBHDFS3&#95;CONF [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292). [#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* Améliore les performances de la fonction `hasAll` grâce à des spécialisations pour SSE et AVX2. Auteur : @youennL-cs. [#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * L&#39;instruction explain de GLOBAL JOIN sur deux tables distribuées peut être jusqu&#39;à 100x plus rapide : explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2 optimisations : - Optimise une requête hive count triviale - Accélère les requêtes hive en mettant en cache les métadonnées des fichiers hive. [#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
