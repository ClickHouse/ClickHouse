<div id="backward-incompatible-change">
  #### Changement non rétrocompatible
</div>

* Ajout du type d’accès ` NAMED COLLECTION` (alias `USE NAMED COLLECTION`, `NAMED COLLECTION USAGE`). Cette PR n’est pas rétrocompatible, car ce type d’accès est désactivé par défaut (le type d’accès parent `NAMED COLLECTION ADMIN` l’étant lui aussi par défaut). Proposition dans [#50277](https://github.com/ClickHouse/ClickHouse/issues/50277). Pour l’accorder, utilisez `GRANT NAMED COLLECTION ON collection_name TO user` ou `GRANT NAMED COLLECTION ON * TO user` ; pour pouvoir accorder ces grants, `named_collection_admin` doit être activé dans la configuration (auparavant nommé `named_collection_control`, il restera donc disponible comme alias). [#50625](https://github.com/ClickHouse/ClickHouse/pull/50625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Correction d’une faute de frappe dans le nom de la colonne `last_removal_attemp_time` de `system.parts`. Elle s’appelle désormais `last_removal_attempt_time`. [#52104](https://github.com/ClickHouse/ClickHouse/pull/52104) ([filimonov](https://github.com/filimonov)).
* La version de `distributed_ddl_entry_format_version` passe par défaut à 5 (ce qui active la transmission de opentelemetry et de initial&#95;query&#95;idd). Cela empêchera le traitement des entrées existantes pour le distributed DDL après un **downgrade** (mais notez qu’en général, il ne devrait pas y avoir de telles entrées non traitées). [#52128](https://github.com/ClickHouse/ClickHouse/pull/52128) ([Azat Khuzhin](https://github.com/azat)).
* Vérification des métadonnées de projection de la même manière que les métadonnées ordinaires. Ce changement peut empêcher le serveur de démarrer si une table contient une projection invalide. Par exemple, une projection qui crée des colonnes positionnelles dans la PK (par ex. `projection p (select * order by 1, 4)`) n’est pas autorisée dans la PK d’une table et peut provoquer un crash lors d’un `insert`/merge). Supprimez ces projections avant la mise à jour. Corrige [#52353](https://github.com/ClickHouse/ClickHouse/issues/52353). [#52361](https://github.com/ClickHouse/ClickHouse/pull/52361) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* La fonctionnalité expérimentale `hashid` est supprimée en raison d’un bogue. La qualité de l’implémentation était discutable dès le départ, et elle n’a jamais dépassé le stade expérimental. Cela clôt [#52406](https://github.com/ClickHouse/ClickHouse/issues/52406). [#52449](https://github.com/ClickHouse/ClickHouse/pull/52449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La fonction `toDecimalString` est supprimée en raison d’une qualité d’implémentation insuffisante. Cela clôt [#52407](https://github.com/ClickHouse/ClickHouse/issues/52407). [#52450](https://github.com/ClickHouse/ClickHouse/pull/52450) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Performance Improvement
</div>

* Active par défaut les paramètres `move_all_conditions_to_prewhere` et `enable_multiple_prewhere_read_steps`. [#46365](https://github.com/ClickHouse/ClickHouse/pull/46365) ([Alexander Gololobov](https://github.com/davenger)).
* Améliore les performances de certaines requêtes en optimisant l’allocateur. [#46416](https://github.com/ClickHouse/ClickHouse/pull/46416) ([Azat Khuzhin](https://github.com/azat)).
* L’écriture des fichiers Parquet est désormais 10 fois plus rapide. Elle est maintenant multithreadée. La vitesse est presque la même qu’en lecture. [#49367](https://github.com/ClickHouse/ClickHouse/pull/49367) ([Michael Kolupaev](https://github.com/al13n321)).
* Active par défaut la sélection automatique du format de sérialisation sparse. Cela améliore les performances. Ce format est pris en charge depuis la version 22.1. Après ce changement, il se peut qu’il ne soit plus possible de revenir à une version antérieure à 22.1. Vous pouvez désactiver l’utilisation du format de sérialisation sparse en définissant le paramètre `ratio_of_defaults_for_sparse_serialization = 1` pour vos tables MergeTree. [#49631](https://github.com/ClickHouse/ClickHouse/pull/49631) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nous utilisons désormais des tâches de taille fixe dans `MergeTreePrefetchedReadPool`, comme dans `MergeTreeReadPool`. Nous utilisons également désormais un pool de connexions pour les requêtes S3. [#49732](https://github.com/ClickHouse/ClickHouse/pull/49732) ([Nikita Taranov](https://github.com/nickitat)).
* Davantage de pushdown du côté droit de la jointure. [#50532](https://github.com/ClickHouse/ClickHouse/pull/50532) ([Nikita Taranov](https://github.com/nickitat)).
* Améliore la jointure grace&#95;hash en réservant la taille de la table de hachage (nouvelle soumission). [#50875](https://github.com/ClickHouse/ClickHouse/pull/50875) ([lgbo](https://github.com/lgbo-ustc)).
* L’attente du verrou dans `OpenedFileCache` pouvait parfois être notable. Nous l’avons segmenté en plusieurs sous-maps (chacune avec son propre verrou) afin d’éviter la contention. [#51341](https://github.com/ClickHouse/ClickHouse/pull/51341) ([Nikita Taranov](https://github.com/nickitat)).
* Supprime une condition en double dans functionunixtimestamp64.h. [#51857](https://github.com/ClickHouse/ClickHouse/pull/51857) ([lcjh](https://github.com/ljhcage)).
* L’idée est que les conditions sur les colonnes PK seront probablement utilisées dans l’analyse de la PK et n’apporteront pas grand-chose de plus au filtrage PREWHERE. [#51958](https://github.com/ClickHouse/ClickHouse/pull/51958) ([Alexander Gololobov](https://github.com/davenger)).
* 1. Ajout d’un mécanisme de réécriture pour l’ancien et le nouvel analyseur. 2. Ajout du paramètre `optimize_uniq_to_count`, dont la valeur par défaut est 0. [#52004](https://github.com/ClickHouse/ClickHouse/pull/52004) ([JackyWoo](https://github.com/JackyWoo)).
* Les tests de performance de **OnTime** sur la plateforme ICX (CPU Intel Xeon Platinum 8380, 80 cœurs, 160 threads) montrent que ce changement pourrait améliorer de **11,6 %** le QPS de la requête **Q8**, sans impact sur les autres. [#52036](https://github.com/ClickHouse/ClickHouse/pull/52036) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Active `allow_vertical_merges_from_compact_to_wide_parts` par défaut. Cela réduira l’utilisation mémoire pendant les fusions. [#52295](https://github.com/ClickHouse/ClickHouse/pull/52295) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige une analyse incorrecte des projections qui invalide les clés primaires. Ce problème n’existe que lorsque `query_plan_optimize_primary_key = 1, query_plan_optimize_projection = 1`. Ce correctif résout [#48823](https://github.com/ClickHouse/ClickHouse/issues/48823). Ce correctif résout [#51173](https://github.com/ClickHouse/ClickHouse/issues/51173). [#52308](https://github.com/ClickHouse/ClickHouse/pull/52308) ([Amos Bird](https://github.com/amosbird)).
* Réduit le nombre d’appels système dans FileCache::loadMetadata. [#52435](https://github.com/ClickHouse/ClickHouse/pull/52435) ([Raúl Marín](https://github.com/Algunenano)).
