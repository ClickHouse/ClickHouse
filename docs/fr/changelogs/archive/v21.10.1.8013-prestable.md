<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Corrige le problème où, dans certaines query complexes avec des alias de colonnes identiques aux noms des expressions, un mauvais CAST peut se produire. Cela corrige [#25447](https://github.com/ClickHouse/ClickHouse/issues/25447). Cela corrige [#26914](https://github.com/ClickHouse/ClickHouse/issues/26914). Ce correctif peut introduire une incompatibilité avec les versions précédentes : s&#39;il existe plusieurs expressions portant des noms identiques, une exception sera levée. Cela peut casser certains cas rares lorsque `enable_optimize_predicate_expression` est défini. [#26639](https://github.com/ClickHouse/ClickHouse/pull/26639) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* N&#39;affiche plus les zéros finaux dans la représentation textuelle des types `Decimal`. Exemple : `1.23` sera affiché au lieu de `1.230000` pour un décimal de scale 6. Cela clôt [#15794](https://github.com/ClickHouse/ClickHouse/issues/15794). Cela peut introduire une légère incompatibilité si vos applications dépendaient, d&#39;une manière ou d&#39;une autre, de ces zéros finaux. La sérialisation dans les formats de sortie peut être contrôlée avec le paramètre `output_format_decimal_trailing_zeros`. L&#39;implémentation de `toString` et la conversion en String sont modifiées de manière inconditionnelle. [#27680](https://github.com/ClickHouse/ClickHouse/pull/27680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Désormais, les MergeTreeSettings `replicated_max_parallel_sends`, `replicated_max_parallel_sends_for_table`, `replicated_max_parallel_fetches`, `replicated_max_parallel_fetches_for_table` ne servent plus à rien. Ils n&#39;ont jamais bien fonctionné et ont été remplacés par `max_replicated_fetches_network_bandwidth`, `max_replicated_sends_network_bandwidth` et `background_fetches_pool_size`. [#28404](https://github.com/ClickHouse/ClickHouse/pull/28404) ([alesapin](https://github.com/alesapin)).
