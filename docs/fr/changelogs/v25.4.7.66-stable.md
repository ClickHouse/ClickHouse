<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#81442](https://github.com/ClickHouse/ClickHouse/issues/81442) : ajout d’un préfixe de conteneur aux chemins de données signalés dans system.tables pour les disques standards dans Azure Blob Storage, afin d’harmoniser le reporting avec S3 et GCP. [#79241](https://github.com/ClickHouse/ClickHouse/pull/79241) ([Julia Kartseva](https://github.com/jkartseva)).
* Rétroporté dans [#81220](https://github.com/ClickHouse/ClickHouse/issues/81220) : correction d’un crash : si une exception est levée lors d’une tentative de suppression d’un fichier temporaire (utilisé pour décharger des données temporaires sur disque) dans le destructeur, le programme peut se terminer. [#80776](https://github.com/ClickHouse/ClickHouse/pull/80776) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#81536](https://github.com/ClickHouse/ClickHouse/issues/81536) : mise à niveau de libxml2 vers 2.14.3. [#81187](https://github.com/ClickHouse/ClickHouse/pull/81187) ([larryluogit](https://github.com/larryluogit)).
* Rétroporté dans [#81409](https://github.com/ClickHouse/ClickHouse/issues/81409) : dans un système de fichiers avec journal, `mkdir` est écrit dans le journal du système de fichiers, qui est ensuite persisté sur disque. En cas de disque lent, cela peut prendre beaucoup de temps. Il est clairement préférable de sortir cela de la portée du verrou de réservation. [#81371](https://github.com/ClickHouse/ClickHouse/pull/81371) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#81486](https://github.com/ClickHouse/ClickHouse/issues/81486) : utilisation de `krb5` 1.21.3-final. [#81453](https://github.com/ClickHouse/ClickHouse/pull/81453) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#81478](https://github.com/ClickHouse/ClickHouse/issues/81478) : utilisation de `orc` 2.1.2. [#81455](https://github.com/ClickHouse/ClickHouse/pull/81455) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Rétroporté dans [#81666](https://github.com/ClickHouse/ClickHouse/issues/81666) : report de la lecture des fichiers manifest d’Iceberg jusqu’à la première requête de lecture. [#81619](https://github.com/ClickHouse/ClickHouse/pull/81619) ([Daniil Ivanik](https://github.com/divanik)).
* Rétroporté dans [#81930](https://github.com/ClickHouse/ClickHouse/issues/81930) : tentative de correction d’une erreur logique dans le cache du système de fichiers : &quot;Having zero bytes but range is not finished&quot;. [#81868](https://github.com/ClickHouse/ClickHouse/pull/81868) ([Kseniia Sumarokova](https://github.com/kssenii)).

  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#81446](https://github.com/ClickHouse/ClickHouse/issues/81446) : correction de l’utilisation des CTE dans les prédicats poussés vers le bas lorsque `allow_push_predicate_ast_for_distributed_subqueries` est activé. Corrige [#75647](https://github.com/ClickHouse/ClickHouse/issues/75647). Corrige [#79672](https://github.com/ClickHouse/ClickHouse/issues/79672). [#77316](https://github.com/ClickHouse/ClickHouse/pull/77316) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#79487](https://github.com/ClickHouse/ClickHouse/issues/79487) : correction d’une ancienne erreur logique liée à `transform`. [#78247](https://github.com/ClickHouse/ClickHouse/pull/78247) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#81243](https://github.com/ClickHouse/ClickHouse/issues/81243) : interdiction des types Dynamic et JSON dans IN. Avec l’implémentation actuelle de `IN`, cela peut entraîner des résultats incorrects. La prise en charge correcte de ces types dans `IN` est complexe et pourra être ajoutée à l’avenir. [#79282](https://github.com/ClickHouse/ClickHouse/pull/79282) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#81426](https://github.com/ClickHouse/ClickHouse/issues/81426) : correction des erreurs logiques concernant une portée d’origine inconnue pour une colonne, produites lors de la vérification du caractère corrélé de cette colonne. Corrige [#78183](https://github.com/ClickHouse/ClickHouse/issues/78183). Corrige [#79451](https://github.com/ClickHouse/ClickHouse/issues/79451). [#79727](https://github.com/ClickHouse/ClickHouse/pull/79727) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#81622](https://github.com/ClickHouse/ClickHouse/issues/81622) : désactivation du partitionnement Hive pour les lacs de données. [#80005](https://github.com/ClickHouse/ClickHouse/pull/80005) ([Daniil Ivanik](https://github.com/divanik)).
* Rétroporté dans [#80838](https://github.com/ClickHouse/ClickHouse/issues/80838) : correction d’erreurs logiques et de plantages possibles dans les projections avec des sous-colonnes. [#80333](https://github.com/ClickHouse/ClickHouse/pull/80333) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#81289](https://github.com/ClickHouse/ClickHouse/issues/81289) : correction d’un résultat incorrect lors de la lecture d’une colonne présente dans un sous-ensemble de tables du moteur Merge. [#80643](https://github.com/ClickHouse/ClickHouse/pull/80643) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#81341](https://github.com/ClickHouse/ClickHouse/issues/81341) : correction d’un plantage de clickhouse-local lors de la sortie de tuples ou de maps constants au format Parquet. [#81249](https://github.com/ClickHouse/ClickHouse/pull/81249) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#81366](https://github.com/ClickHouse/ClickHouse/issues/81366) : correction d’un cas limite dans une requête qui joint des tables vides et utilise des fonctions de fenêtre. Le bogue entraîne une explosion du nombre de flux parallèles, ce qui conduit à des OOM. Corrige [#79914](https://github.com/ClickHouse/ClickHouse/issues/79914). [#81353](https://github.com/ClickHouse/ClickHouse/pull/81353) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#81503](https://github.com/ClickHouse/ClickHouse/issues/81503) : Ne stockez pas en mémoire le contenu de plusieurs fichiers manifest. [#81470](https://github.com/ClickHouse/ClickHouse/pull/81470) ([Daniil Ivanik](https://github.com/divanik)).
* Rétroporté dans [#81726](https://github.com/ClickHouse/ClickHouse/issues/81726) : Les paramètres de requête `use_iceberg_partition_pruning` ne s&#39;appliquaient pas au stockage Iceberg, car celui-ci utilisait le contexte global plutôt que le contexte de requête. Ce n’est pas critique, car sa valeur par défaut est `true`. Cette PR corrige le problème. [#81673](https://github.com/ClickHouse/ClickHouse/pull/81673) ([Han Fei](https://github.com/hanfei1991)).
* Rétroporté dans [#81846](https://github.com/ClickHouse/ClickHouse/issues/81846) : Corrige un crash dans `ConcurrentHashJoin` avec `USING ()` vide et l’ancien analyseur activé. [#81754](https://github.com/ClickHouse/ClickHouse/pull/81754) ([Nikita Taranov](https://github.com/nickitat)).
* Rétroporté dans [#81906](https://github.com/ClickHouse/ClickHouse/issues/81906) : Correctif Keeper : empêche la validation de nouveaux journaux en présence d’une entrée invalide dans les journaux. Auparavant, si le leader appliquait certains journaux de manière incorrecte, il continuait à valider de nouveaux journaux, même si le follower détectait une incompatibilité de digest et s’arrêtait. [#81780](https://github.com/ClickHouse/ClickHouse/pull/81780) ([Antonio Andelic](https://github.com/antonio2368)).
