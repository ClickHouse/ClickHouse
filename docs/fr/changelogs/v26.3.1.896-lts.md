<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Corrige les métadonnées des projections normales afin que les projections avec des clés de tri sur plusieurs colonnes soient correctement reconnues. S’appuie sur [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429). [#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* Propage les versions de sérialisation des types de données aux types imbriqués. Par exemple, la version de sérialisation String `with_size_stream` n’était auparavant appliquée qu’aux colonne de type String de premier niveau et aux éléments Tuple. Désormais, elle s’applique à tout type String à l’intérieur de n’importe quel type imbriqué, comme Array/Map/Variant/JSON/etc. Ce comportement est contrôlé par le paramètre MergeTree `propagate_types_serialization_versions_to_nested_types`, désormais activé par défaut. Après ce changement, les nouvelles data parts créées ne peuvent plus être lues par les anciennes versions, mais les anciennes data parts peuvent être lues par la nouvelle version sans problème. Cela signifie que l’upgrade est sûre, mais pas le downgrade. [#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* Supprime le type de skip index `hypothesis`. Il s’agissait d’une fonctionnalité expérimentale peu connue et d’un intérêt pratique limité. La création de tables avec `INDEX ... TYPE hypothesis` produira désormais une erreur. [#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige un problème où les fichiers de skip index ne respectaient pas le paramètre replace&#95;long&#95;file&#95;name&#95;to&#95;hash, ce qui provoquait des erreurs « File name too long » et cassait la lecture des index portant des noms longs. Les noms de fichiers des skip index sont désormais hachés lorsqu’ils dépassent max&#95;file&#95;name&#95;length, comme pour les fichiers de colonnes. Ce changement reste rétrocompatible (les nouveaux serveurs lisent les anciennes data parts), mais un downgrade (ou d’anciens serveurs pendant une rolling upgrade) peut entraîner l’ignorance des index aux noms longs. [#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* Active async insert par défaut. ClickHouse regroupera désormais par lots tous les petits inserts par défaut. Ce paramètre est défini dans compatibility. Si vous définissez `compatibility=<version less than 26.2>`, la valeur par défaut redeviendra l’ancienne, `false`. Vous pouvez désactiver/activer async inserts à plusieurs niveaux : dans la configuration des profils utilisateurs, pour la session, pour la requête ou pour la table MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* Corrige la préséance de l’opérateur `NOT` pour qu’elle corresponde à la norme SQL : `NOT` a désormais une priorité inférieure à `IS NULL`, `BETWEEN`, `LIKE` et aux opérateurs arithmétiques. Par exemple, `NOT (x) IS NULL` est maintenant analysé comme `NOT (x IS NULL)` au lieu de `(NOT x) IS NULL`. Cela peut modifier le résultat des requêtes qui reposaient sur l’ancien comportement (non standard). [#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Modifie la valeur par défaut de `mysql_datatypes_support_level`, de vide à `decimal,datetime64,date2Date32`, ce qui active par défaut le mappage correct de MySQL `DATE` vers `Date32`, de `DECIMAL`/`NUMERIC` vers `Decimal`, et de `DATETIME`/`TIMESTAMP` avec précision vers `DateTime64`. Auparavant, les colonnes MySQL `DATE` étaient mappées vers `Date`, qui ne peut pas représenter les dates antérieures au 1970-01-01, ce qui provoquait une corruption des données. [#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Accepte un Array de noms de parts au lieu d’une Regexp pour `mergeTreeAnalyzeIndexes{,UUID}`, car les regexps sont lentes (*fonctionnalité expérimentale*). [#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* Supprime la fonction expérimentale `detectProgrammingLanguage`. [#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

Lorsqu’il est activé, les utilisateurs/rôles restaurés voient leurs grants limités à ce que l’utilisateur qui effectue la restauration est autorisé à accorder (même sémantique que `GRANT CURRENT GRANTS`), au lieu d’échouer avec `ACCESS_DENIED`. [#99369](https://github.com/ClickHouse/ClickHouse/pull/99369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Performance Improvement
</div>

* Optimise le saut de granules pour `pointInPolygon` avec de grands polygones et corrige l&#39;exception levée par l&#39;analyse d&#39;index de `pointInPolygon` lors de l&#39;élagage de la clé primaire. [#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Améliore les performances de la fonction `levenshteinDistance`. [#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)).
* Optimise les conversions par lot du type Decimal en évitant les appels de fonction pour chaque élément. [#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 1. Iceberg intègre désormais la fonctionnalité de préchargement asynchrone des métadonnées dans le cache. Elle peut être activée en définissant `iceberg_metadata_async_prefetch_period_ms` lors de la création de la table. Par ex. : `CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. Les requêtes SELECT sur des tables Iceberg peuvent désormais être exécutées en spécifiant le paramètre `iceberg_metadata_staleness_ms`, ce qui permet à ClickHouse de s’appuyer sur la version en cache des métadonnées si elle est plus récente que le seuil de péremption spécifié. Sinon, le catalogue Iceberg distant sera interrogé pour récupérer les métadonnées les plus récentes afin de traiter la requête (comme auparavant). Grâce à ce changement, il est possible de ramener à 0 les appels au catalogue Iceberg pendant le traitement des requêtes, ce qui devrait se traduire par un gain de performances visible. Exemple : `SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`. [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)).
* Le mode ordonné de S3Queue utilise S3 ListObjectsV2 StartAfter pour éviter de relister l’historique complet du préfixe, ce qui réduit les appels à ListObjects. [#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* En règle générale, le bloc d’origine est nécessaire pour la déduplication, mais pour les insertions synchrones, on peut l’omettre et économiser ainsi durablement de la mémoire. [#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* Activation des lectures parallèles depuis le moteur de table YTsaurus. [#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Utilisation d’une valeur spécifique à l’architecture pour la taille des lignes de cache au lieu d’une valeur codée en dur à 64. [#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
* Prise en charge de l’inversion des côtés des jointures ANTI, SEMI et FULL en fonction des statistiques de l’optimiseur. [#97498](https://github.com/ClickHouse/ClickHouse/pull/97498) ([Hechem Selmi](https://github.com/m-selmi)).
* Lecture depuis le dictionnaire du text index légèrement optimisée, ce qui améliore les performances globales de l’analyse du text index. [#97519](https://github.com/ClickHouse/ClickHouse/pull/97519) ([Anton Popov](https://github.com/CurtizJ)).
* Accélération de la décompression LZ4 des blocs de 16 octets sur ARM. [#97774](https://github.com/ClickHouse/ClickHouse/pull/97774) ([Raúl Marín](https://github.com/Algunenano)).
* Refactorisation de la tokenisation vers une nouvelle interface de callback `forEachToken` haute performance, en remplacement de l’ancienne API de style itérateur, afin de prendre en charge SIMD et les tokenizers avec état. Fait partie de [#90268](https://github.com/ClickHouse/ClickHouse/issues/90268). [#97871](https://github.com/ClickHouse/ClickHouse/pull/97871) ([Amos Bird](https://github.com/amosbird)).
* Amélioration des performances de l’analyse du text index pour les requêtes avec des conditions combinées impliquant à la fois des colonnes indexées et non indexées. Auparavant, l’optimisation de sortie anticipée pendant l’analyse de l’index était désactivée à tort dans de tels cas. [#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).
* Amélioration des performances des requêtes avec des expressions constantes qui génèrent des tableaux ou des maps très volumineux. [#98287](https://github.com/ClickHouse/ClickHouse/pull/98287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Correction de l’analyse des conditions de clé pour les clés primaires `DateTime64` comparées à des constantes entières, ce qui empêchait auparavant tout pruning de granules. [#98410](https://github.com/ClickHouse/ClickHouse/pull/98410) ([Amos Bird](https://github.com/amosbird)).
* Le paramètre `optimize_syntax_fuse_functions` est activé par défaut. [#98424](https://github.com/ClickHouse/ClickHouse/pull/98424) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Autorisation du partition pruning lorsque le prédicat contient n’importe quel opérateur de comparaison (`=`, `<`, `>`, `!=`) et que la clé de partition est encapsulée dans une chaîne de fonctions déterministes (par exemple, avec `PARTITION BY x` et des prédicats comme `cityHash64(x) % 5 > 2`, `toYYYYMM(x) < 2026`, `toYYYYMM(x) = 2026` ou `toYYYYMM(x) != 2026`, la clé de partition sera utilisée pour le pruning). Résout [#28800](https://github.com/ClickHouse/ClickHouse/issues/28800). [#98432](https://github.com/ClickHouse/ClickHouse/pull/98432) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Autorisation de l’optimisation de lecture ordonnée et du pruning sur la clé primaire lorsque le type cible de `CAST` est `Nullable` et que la conversion est monotone ; par exemple, avec `PRIMARY KEY x`, ClickHouse peut utiliser l’optimisation de lecture ordonnée pour `ORDER BY x::Nullable(UInt64)` et appliquer le pruning sur la clé primaire à des prédicats tels que `WHERE x::Nullable(UInt64) > 500000`. [#98482](https://github.com/ClickHouse/ClickHouse/pull/98482) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Autorise le pruning d’index et le pushdown des filtres lorsqu’une colonne entière est comparée à un littéral flottant ; par exemple, des prédicats comme `WHERE x < 10.5` peuvent désormais utiliser la clé primaire pour le pruning, et des filtres tels que `prime < 1e9` ou `number < 1e5` sont désormais poussés vers les fonctions de table `primes()` et `numbers()` au lieu de provoquer une exécution non bornée. Clôt [#85167](https://github.com/ClickHouse/ClickHouse/issues/85167). [#98516](https://github.com/ClickHouse/ClickHouse/pull/98516) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Optimise la fonction d’agrégation `avgWeighted` en utilisant des accumulateurs locaux au lieu d’un store-forwarding par ligne via l’aggregate state, avec un gain de performances pouvant atteindre 27 % pour les entrées Nullable. [#98793](https://github.com/ClickHouse/ClickHouse/pull/98793) ([Antonio Andelic](https://github.com/antonio2368)).
* Améliore les performances et réduit l’utilisation mémoire pour les fonctions de fenêtre parallèles dans certains scénarios, ainsi que pour les workloads `arrayFold` avec de grands Array. Cela peut aussi réduire la pression liée aux défauts de page et améliorer la stabilité sous des memory limits strictes pour les queries concernées. [#98892](https://github.com/ClickHouse/ClickHouse/pull/98892) ([filimonov](https://github.com/filimonov)).
* Ajoute icolumn::comparetrackat() pour les merges triés. [#99013](https://github.com/ClickHouse/ClickHouse/pull/99013) ([Artem Zuikov](https://github.com/4ertus2)).
* Optimise `INTERSECT ALL` et `EXCEPT ALL`. [#99097](https://github.com/ClickHouse/ClickHouse/pull/99097) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Prend en charge l’optimisation `read_in_order_use_virtual_row` pour les lectures en ordre inverse. [#99198](https://github.com/ClickHouse/ClickHouse/pull/99198) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Réduit la contention du cache dans les RIGHT et FULL JOIN en vérifiant si JoinUsedFlags est défini avant l’écriture. [#99274](https://github.com/ClickHouse/ClickHouse/pull/99274) ([Hechem Selmi](https://github.com/m-selmi)).
* Optimise `PrefetchingHelper::calcPrefetchLookAhead` en remplaçant les calculs en virgule flottante par une arithmétique entière pure, ce qui améliore l’organisation du cache d’instructions et réduit le surcoût en cycles pendant les boucles d’aggregation. [#99327](https://github.com/ClickHouse/ClickHouse/pull/99327) ([Riyane El Qoqui](https://github.com/riyaneel)).
* Améliore les performances des lacs de données. Dans les versions précédentes, la lecture depuis le stockage objet ne redimensionnait pas le pipeline en fonction du nombre de threads de traitement. [#99548](https://github.com/ClickHouse/ClickHouse/pull/99548) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

Le nouveau conteneur stocke 0 ou 1 enfant en ligne sans allocation sur le tas, ce qui couvre la majorité des nœuds Keeper. Cela réduit la taille de `KeeperMemNode` de 144 à 128 octets. [#99860](https://github.com/ClickHouse/ClickHouse/pull/99860) ([Antonio Andelic](https://github.com/antonio2368)).

[#99941](https://github.com/ClickHouse/ClickHouse/pull/99941) ([Pavel Kruglov](https://github.com/Avogar)).
