<div id="performance-improvement">
  #### Amélioration des performances

* Rétroporté dans [#83337](https://github.com/ClickHouse/ClickHouse/issues/83337) : tentative d’accélération de QueryTreeHash. [#82617](https://github.com/ClickHouse/ClickHouse/pull/82617) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

<div id="improvement">
  #### Amélioration
</div>

* Rétroporté dans [#82503](https://github.com/ClickHouse/ClickHouse/issues/82503) : ajout de la possibilité de recharger `max_local_read_bandwidth_for_server` et `max_local_write_bandwidth_for_server` à chaud, sans redémarrer le serveur. [#82083](https://github.com/ClickHouse/ClickHouse/pull/82083) ([Kai Zhu](https://github.com/nauu)).
* Rétroporté dans [#83012](https://github.com/ClickHouse/ClickHouse/issues/83012) : amélioration de Keeper : déplacement des fichiers de changelog entre des disques dans un thread d’arrière-plan. Auparavant, déplacer le changelog vers un autre disque bloquait entièrement Keeper jusqu’à la fin de l’opération. Cela entraînait une dégradation des performances lorsque le déplacement était long (par exemple, vers un S3 disk). [#82485](https://github.com/ClickHouse/ClickHouse/pull/82485) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#82856](https://github.com/ClickHouse/ClickHouse/issues/82856) : après [https://github.com/ClickHouse/ClickHouse/pull/73834](https://github.com/ClickHouse/ClickHouse/pull/73834), les formats des en-têtes `X-ClickHouse-Progress` et `X-ClickHouse-Summary` ont été modifiés pour omettre les valeurs nulles. Cette PR vise à rétablir le comportement précédent uniquement pour `X-ClickHouse-Summary`, car c’est plus logique. [#82727](https://github.com/ClickHouse/ClickHouse/pull/82727) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (dysfonctionnement visible par l’utilisateur dans une version stable officielle)

* Rétroporté dans [#79891](https://github.com/ClickHouse/ClickHouse/issues/79891) : corrige certains cas où l’index secondaire n’était pas appliqué avec l’analyseur. Corrige [#65607](https://github.com/ClickHouse/ClickHouse/issues/65607), corrige [#69373](https://github.com/ClickHouse/ClickHouse/issues/69373). [#78485](https://github.com/ClickHouse/ClickHouse/pull/78485) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Rétroporté dans [#83254](https://github.com/ClickHouse/ClickHouse/issues/83254) : corrige la désactivation de l’alignement sur les limites pour le tampon en cache dans les moteurs de table externes. Cela a été cassé dans [https://github.com/ClickHouse/ClickHouse/pull/81868](https://github.com/ClickHouse/ClickHouse/pull/81868). [#82493](https://github.com/ClickHouse/ClickHouse/pull/82493) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#82796](https://github.com/ClickHouse/ClickHouse/issues/82796) : corrige la désérialisation de `groupArraySample`/`groupArrayLast` en cas d’éléments vides (la désérialisation pouvait ignorer une partie du flux binaire si l’entrée était vide, ce qui peut entraîner une corruption à la lecture des données ainsi que UNKNOWN&#95;PACKET&#95;FROM&#95;SERVER dans le protocole TCP). Cela n’affecte ni les nombres ni les types date et heure. [#82763](https://github.com/ClickHouse/ClickHouse/pull/82763) ([Pedro Ferreira](https://github.com/PedroTadim)).
* Rétroporté dans [#83108](https://github.com/ClickHouse/ClickHouse/issues/83108) : corrige la sûreté vis-à-vis des exceptions dans la réécriture de union/intersect/except&#95;default&#95;mode. Clôt [#82664](https://github.com/ClickHouse/ClickHouse/issues/82664). [#82820](https://github.com/ClickHouse/ClickHouse/pull/82820) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#82991](https://github.com/ClickHouse/ClickHouse/issues/82991) : lors de l’utilisation d’une implémentation de Database sans mise en cache, les métadonnées de la table correspondante sont supprimées une fois les colonnes renvoyées et la référence est invalidée. [#82939](https://github.com/ClickHouse/ClickHouse/pull/82939) ([buyval01](https://github.com/buyval01)).
* Rétroporté dans [#83023](https://github.com/ClickHouse/ClickHouse/issues/83023) : corrige la modification du filtre pour les requêtes avec une expression JOIN sur une table utilisant le stockage `Merge`. Corrige [#82092](https://github.com/ClickHouse/ClickHouse/issues/82092). [#82950](https://github.com/ClickHouse/ClickHouse/pull/82950) ([Dmitry Novik](https://github.com/novikd)).
* Rétroporté dans [#83307](https://github.com/ClickHouse/ClickHouse/issues/83307) : corrige LOGICAL&#95;ERROR dans QueryMetricLog : Mutex cannot be NULL. [#82979](https://github.com/ClickHouse/ClickHouse/pull/82979) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#83080](https://github.com/ClickHouse/ClickHouse/issues/83080) : corrige un résultat incorrect de la fonction `formatDateTime` lorsque le spécificateur de format `%f` est utilisé avec des spécificateurs de format de taille variable (par ex. `%M`). [#83020](https://github.com/ClickHouse/ClickHouse/pull/83020) ([Robert Schulze](https://github.com/rschu1ze)).
* Corrige ce bug dans la version 25.3 (pour 25.4+, ce problème est sans objet) [#82601](https://github.com/ClickHouse/ClickHouse/issues/82601). [#83226](https://github.com/ClickHouse/ClickHouse/pull/83226) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Rétroporté dans [#83402](https://github.com/ClickHouse/ClickHouse/issues/83402) : corrige `no_sign_request` pour le client S3. Il peut être utilisé pour éviter explicitement de signer les requêtes S3. Il peut également être défini pour des points de terminaison spécifiques à l’aide de paramètres basés sur les points de terminaison. [#83379](https://github.com/ClickHouse/ClickHouse/pull/83379) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#83464](https://github.com/ClickHouse/ClickHouse/issues/83464) : correction de l&#39;exception `TOO_DEEP_SUBQUERIES` lorsque la définition de la CTE fait référence à une autre expression de table portant le même nom.
