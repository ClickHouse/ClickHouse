<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bug (comportement incorrect visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#97491](https://github.com/ClickHouse/ClickHouse/issues/97491) : lorsqu’une table n’a pas de statistiques définies, ClickHouse ne doit pas tenter de les lire. Cela évite un certain surcoût (100+ms) lié à la vérification de l’existence des fichiers de statistiques. (issue [#96068](https://github.com/ClickHouse/ClickHouse/issues/96068)). [#96233](https://github.com/ClickHouse/ClickHouse/pull/96233) ([Han Fei](https://github.com/hanfei1991)).
* Rétroporté dans [#97765](https://github.com/ClickHouse/ClickHouse/issues/97765) : corrige ColumnConst non matérialisé avant le squashing. [#97019](https://github.com/ClickHouse/ClickHouse/pull/97019) ([Hasyimi Bahrudin](https://github.com/hasyimibhar)).
* Rétroporté dans [#97409](https://github.com/ClickHouse/ClickHouse/issues/97409) : corrige les cas où des indexes affectaient le résultat des requêtes avec row policy/PREWHERE et FINAL. [#97076](https://github.com/ClickHouse/ClickHouse/pull/97076) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Rétroporté dans [#97450](https://github.com/ClickHouse/ClickHouse/issues/97450) : corrige l’exception `LOGICAL_ERROR` lors de la lecture de la sous-colonne `.size` d’un `Nullable(String)` clairsemé dans un Tuple avec PREWHERE. [#97264](https://github.com/ClickHouse/ClickHouse/pull/97264) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97469](https://github.com/ClickHouse/ClickHouse/issues/97469) : corrige un SEGFAULT dans supportsTrivialCountOptimization dû à un déréférencement de pointeur nul. [#97281](https://github.com/ClickHouse/ClickHouse/pull/97281) ([Pablo Marcos](https://github.com/pamarcos)).
* Rétroporté dans [#97440](https://github.com/ClickHouse/ClickHouse/issues/97440) : supprime la vérification TABLE&#95;UUID&#95;MISMATCH pour l’analyseur non activé. [#97323](https://github.com/ClickHouse/ClickHouse/pull/97323) ([Azat Khuzhin](https://github.com/azat)).
* Rétroporté dans [#97994](https://github.com/ClickHouse/ClickHouse/issues/97994) : suite de [https://github.com/ClickHouse/ClickHouse/pull/61135](https://github.com/ClickHouse/ClickHouse/pull/61135), mais avec un cache partitionné. [#97411](https://github.com/ClickHouse/ClickHouse/pull/97411) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Rétroporté dans [#97697](https://github.com/ClickHouse/ClickHouse/issues/97697) : corrige l’exception `LOGICAL_ERROR` dans la conversion d’Array vers `QBit` lorsque `nullable_source` d’un wrapper `Tuple` externe remplace la colonne Array convertie par un type de colonne incompatible. Ferme [#97389](https://github.com/ClickHouse/ClickHouse/issues/97389). [#97413](https://github.com/ClickHouse/ClickHouse/pull/97413) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97809](https://github.com/ClickHouse/ClickHouse/issues/97809) : corrige l’application du paramètre `type_json_allow_duplicated_key_with_literal_and_nested_object` aux chemins typés dans JSON. Ferme [#97278](https://github.com/ClickHouse/ClickHouse/issues/97278). [#97422](https://github.com/ClickHouse/ClickHouse/pull/97422) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#97580](https://github.com/ClickHouse/ClickHouse/issues/97580) : corrige `ACCESS_DENIED` pour les utilisateurs sans droit `CREATE TEMPORARY TABLE` lorsque l’optimisation `optimize_inverse_dictionary_lookup` réécrit les prédicats `dictGet(...)`. ClickHouse ignore désormais cette réécriture et exécute l’expression d’origine. Ferme [#97269](https://github.com/ClickHouse/ClickHouse/issues/97269). [#97484](https://github.com/ClickHouse/ClickHouse/pull/97484) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#97631](https://github.com/ClickHouse/ClickHouse/issues/97631) : correction d’un échec d’assertion (exception dans les builds de débogage/avec sanitizer) dans `Set` et `MergeTreeIndexSet` lors du traitement de colonnes comportant des sous-colonnes internes éparses (par ex. des colonnes `Tuple` provenant de parts MergeTree avec différents profils de sérialisation éparse). [#97493](https://github.com/ClickHouse/ClickHouse/pull/97493) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97799](https://github.com/ClickHouse/ClickHouse/issues/97799) : correction de l’exception LOGICAL&#95;ERROR lors de la lecture simultanée d’une colonne éparse et de sa sous-colonne. [#97515](https://github.com/ClickHouse/ClickHouse/pull/97515) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#97958](https://github.com/ClickHouse/ClickHouse/issues/97958) : correction d’une erreur logique liée à un stream manquant pendant un `INSERT SELECT` avec JSON et des buckets dans les données partagées. Clôt [#97331](https://github.com/ClickHouse/ClickHouse/issues/97331). [#97523](https://github.com/ClickHouse/ClickHouse/pull/97523) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#97879](https://github.com/ClickHouse/ClickHouse/issues/97879) : permet à l’optimisation read-in-order d’utiliser les politiques de ligne. Par exemple, une table avec `ORDER BY (key1, key2)` et une politique de ligne `USING key1 = 5` peut désormais répondre à des requêtes `ORDER BY key2` sans tri explicite. [#97538](https://github.com/ClickHouse/ClickHouse/pull/97538) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Rétroporté dans [#97739](https://github.com/ClickHouse/ClickHouse/issues/97739) : correction de l’exception `LOGICAL_ERROR` lors de l’utilisation de `isNull`/`isNotNull` sur des sous-colonnes de types `Nullable(Tuple(... Nullable(T) ...))`. Clôt [#97224](https://github.com/ClickHouse/ClickHouse/issues/97224). [#97582](https://github.com/ClickHouse/ClickHouse/pull/97582) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97603](https://github.com/ClickHouse/ClickHouse/issues/97603) : correction d’un déréférencement de pointeur nul lors de l’application de patch parts pendant les lightweight updates. [#97583](https://github.com/ClickHouse/ClickHouse/pull/97583) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97720](https://github.com/ClickHouse/ClickHouse/issues/97720) : `BaseSettings::readBinary` transmet l’index renvoyé par `accessor.find` à `field_infos[]` sans vérifier la valeur sentinelle signifiant « non trouvé » (c.-à-d. `-1`), ce qui peut provoquer un accès hors limites à `std::vector`. Le problème a été détecté grâce au durcissement de libcxx. Cela s’est probablement produit lors de la désérialisation du plan de requête lorsqu’un serveur plus récent envoie un paramètre inconnu à un serveur plus ancien. La méthode de lecture basée sur des chaînes gère déjà correctement ce cas ; il manquait simplement la même vérification dans `readBinary`. [#97585](https://github.com/ClickHouse/ClickHouse/pull/97585) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Rétroporté dans [#97757](https://github.com/ClickHouse/ClickHouse/issues/97757) : correction de `filterPartsByVirtualColumns` pour les prédicats toujours faux. [#97620](https://github.com/ClickHouse/ClickHouse/pull/97620) ([Bharat Nallan](https://github.com/bharatnc)).
* Rétroporté dans [#97689](https://github.com/ClickHouse/ClickHouse/issues/97689) : correction d’une exception d’erreur logique lors de `GROUP BY ... WITH ROLLUP/CUBE` lorsque les clés incluent `LowCardinality(Nullable(...))` à l’intérieur de `Nullable(Tuple(...))`. [#97647](https://github.com/ClickHouse/ClickHouse/pull/97647) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

[#97654](https://github.com/ClickHouse/ClickHouse/pull/97654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
