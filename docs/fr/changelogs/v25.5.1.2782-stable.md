<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* La fonction `geoToH3()` accepte désormais les entrées dans l’ordre (lat, lon,res) (qui est l’ordre standard des fonctions géométriques). Les utilisateurs qui souhaitent conserver l’ordre des résultats legacy (lon, lat,res) peuvent définir le paramètre `geotoh3_lon_lat_input_order = true`. [#78852](https://github.com/ClickHouse/ClickHouse/pull/78852) ([Pratima Patel](https://github.com/pratimapatel2008)).
* Les index de type `full_text` ont été renommés en `gin`. Cela correspond à une terminologie plus familière dans PostgreSQL et d’autres bases de données. Les index existants de type `full_text` peuvent toujours être chargés, mais ils lèveront une exception (suggérant d’utiliser des index `gin` à la place) lorsqu’on tente de les utiliser dans des recherches. [#79024](https://github.com/ClickHouse/ClickHouse/pull/79024) ([Robert Schulze](https://github.com/rschu1ze)).
* Ajout d’un paramètre de filesystem cache, `allow_dynamic_cache_resize`, `false` par défaut, pour permettre le redimensionnement dynamique du filesystem cache. Pourquoi : dans certains environnements (ClickHouse Cloud), tous les événements de scaling se produisent via le redémarrage du processus, et nous souhaitons que cette fonctionnalité soit explicitement désactivée afin de mieux contrôler le comportement, ainsi que par mesure de sécurité. Cette PR est marquée comme incompatible avec les versions précédentes, car dans les anciennes versions, le redimensionnement dynamique du cache fonctionnait par défaut sans paramètre spécifique. [#79148](https://github.com/ClickHouse/ClickHouse/pull/79148) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Suppression de la prise en charge des types d’index legacy `annoy` et `usearch`. Les deux sont des stubs depuis longtemps, c’est-à-dire que toute tentative d’utiliser ces index legacy renvoyait de toute façon une erreur. Si vous avez encore des index `annoy` et `usearch`, veuillez les supprimer. [#79802](https://github.com/ClickHouse/ClickHouse/pull/79802) ([Robert Schulze](https://github.com/rschu1ze)).
* Suppression du server setting `format_alter_commands_with_parentheses`. Ce paramètre a été introduit et désactivé par défaut dans la version 24.2. Il a été activé par défaut dans la version 25.2. Comme il n’existe plus de versions LTS ne prenant pas en charge le nouveau format, nous pouvons supprimer ce paramètre. [#79970](https://github.com/ClickHouse/ClickHouse/pull/79970) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).

* La recherche vectorielle de ClickHouse prend désormais en charge à la fois le pré-filtrage et le post-filtrage, et propose les paramètres associés pour un contrôle plus fin. <div id="performance-improvement">
  #### Amélioration des performances
</div>

* Accélère les indices secondaires en évaluant leurs expressions sur plusieurs granules à la fois. [#64109](https://github.com/ClickHouse/ClickHouse/pull/64109) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Introduction d’un seuil (contrôlé par le paramètre `parallel_hash_join_threshold`) pour revenir à l’algorithme `hash` lorsque la taille de la table de droite est inférieure à ce seuil. [#76185](https://github.com/ClickHouse/ClickHouse/pull/76185) ([Nikita Taranov](https://github.com/nickitat)).
* Améliore les performances de S3Queue/AzureQueue en permettant d’exécuter les `INSERT` de données en parallèle (activation possible avec le paramètre de file `parallel_inserts=true`). Auparavant, S3Queue/AzureQueue ne pouvait paralléliser que la première partie du pipeline (téléchargement, parsing) ; l’`INSERT` restait mono-thread. Or, les `INSERT` constituent presque toujours le goulot d’étranglement. Désormais, les performances évolueront presque linéairement avec `processing_threads_num`. [#77671](https://github.com/ClickHouse/ClickHouse/pull/77671) ([Azat Khuzhin](https://github.com/azat)).
* Modifie le format de part Compact pour enregistrer des marks pour chaque sous-flux afin de pouvoir lire des sous-colonnes individuellement. L’ancien format Compact reste pris en charge en lecture et peut être activé en écriture à l’aide du paramètre MergeTree `write_marks_for_substreams_in_compact_parts`. Il est désactivé par défaut pour des montées de version plus sûres, car il modifie le stockage des compact parts. Il sera activé par défaut dans l’une des prochaines versions. [#77940](https://github.com/ClickHouse/ClickHouse/pull/77940) ([Pavel Kruglov](https://github.com/Avogar)).
* Nouveau paramètre introduit : `use_skip_indexes_in_final_exact_mode`. Si une query sur une table `ReplacingMergeTree` comporte la clause FINAL, le fait de ne lire que les plages de table basées sur les skip indexes peut produire un résultat incorrect. Ce paramètre permet de garantir le renvoi de résultats corrects en analysant les parts les plus récentes qui chevauchent les plages de clé primaire renvoyées par le skip index. Définissez 0 pour désactiver, 1 pour activer. [#78350](https://github.com/ClickHouse/ClickHouse/pull/78350) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Nous utilisons désormais le nombre de répliques pour déterminer la taille des tâches de lecture lorsque les parallel replicas sont activées. Cela améliore la répartition du travail entre les répliques lorsque le volume de données à lire n’est pas très important. [#78695](https://github.com/ClickHouse/ClickHouse/pull/78695) ([Nikita Taranov](https://github.com/nickitat)).
* Autorise la fusion en parallèle des états `uniqExact` pendant l’étape finale de l’agrégation distribuée. [#78703](https://github.com/ClickHouse/ClickHouse/pull/78703) ([Nikita Taranov](https://github.com/nickitat)).
* Corrige une possible dégradation des performances lors de la fusion en parallèle des états `uniqExact` pour l’agrégation avec clé. [#78724](https://github.com/ClickHouse/ClickHouse/pull/78724) ([Nikita Taranov](https://github.com/nickitat)).
* Réduit le nombre d’appels à l’API List Blobs vers le stockage Azure. [#78860](https://github.com/ClickHouse/ClickHouse/pull/78860) ([Julia Kartseva](https://github.com/jkartseva)).
* Fusionne les conditions d’égalité de l’étape de filtrage du query plan dans la condition JOIN, lorsque c’est possible, afin de permettre leur utilisation comme clés de hash table. [#78877](https://github.com/ClickHouse/ClickHouse/pull/78877) ([Dmitry Novik](https://github.com/novikd)).
* Améliore les performances du parsing des chemins hive en utilisant `extractKeyValuePairs` au lieu de regex. [#79067](https://github.com/ClickHouse/ClickHouse/pull/79067) ([Arthur Passos](https://github.com/arthurpassos)).
* Corrige les performances de l’opération distribuée INSERT SELECT avec des parallel replicas. [#79441](https://github.com/ClickHouse/ClickHouse/pull/79441) ([Azat Khuzhin](https://github.com/azat)).
* Autorise le déplacement des conditions avec des sous-colonnes vers prewhere. [#79489](https://github.com/ClickHouse/ClickHouse/pull/79489) ([Pavel Kruglov](https://github.com/Avogar)).
* Empêche `LogSeriesLimiter` d’effectuer un nettoyage à chaque construction, évitant ainsi la contention sur les verrous et les régressions de performances dans les scénarios à forte concurrence. [#79864](https://github.com/ClickHouse/ClickHouse/pull/79864) ([filimonov](https://github.com/filimonov)).
* Active `compile_expressions` (compilateur JIT pour des fragments d&#39;expressions ordinaires) par défaut. Cela clôt [#51264](https://github.com/ClickHouse/ClickHouse/issues/51264), [#56386](https://github.com/ClickHouse/ClickHouse/issues/56386) et [#66486](https://github.com/ClickHouse/ClickHouse/issues/66486). [#79907](https://github.com/ClickHouse/ClickHouse/pull/79907) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Accélère les requêtes grâce à l&#39;optimisation triviale de `count`. [#79945](https://github.com/ClickHouse/ClickHouse/pull/79945) ([Raúl Marín](https://github.com/Algunenano)).
* Ajoute `__attribute__((always_inline))` à `convertDecimalsImpl`. [#79999](https://github.com/ClickHouse/ClickHouse/pull/79999) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Définit `input_format_parquet_bloom_filter_push_down` sur `true` par défaut. Corrige également une erreur dans l&#39;historique des modifications des paramètres. [#80058](https://github.com/ClickHouse/ClickHouse/pull/80058) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
