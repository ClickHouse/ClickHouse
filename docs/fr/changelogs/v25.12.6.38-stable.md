<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction de bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Rétroporté dans [#97329](https://github.com/ClickHouse/ClickHouse/issues/97329) : suppression d’une vérification superflue des permissions dans les requêtes `ATTACH` pour une vue avec SQL Security. Cela évite une possible escalade de privilèges lorsqu’un utilisateur attache une vue avec un `definer` sans validation des accès requis. [#94865](https://github.com/ClickHouse/ClickHouse/pull/94865) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#95816](https://github.com/ClickHouse/ClickHouse/issues/95816) : correction de l’inférence de type pour les colonnes qualifiées issues de tables source lorsque plusieurs jointures sont utilisées avec la clause `USING`. Auparavant, les jointures suivantes mettaient incorrectement à jour les types des colonnes source sous-jacentes vers un supertype commun, même lorsque la colonne n’était pas impliquée dans cette jointure (par exemple, dans `SELECT t2.a FROM t1 LEFT JOIN t2 USING (a) LEFT JOIN t3 USING (a)`, la colonne `t2.a` n’est utilisée que par la première jointure ; son type doit donc être le supertype de `t1.a` et `t2.a`, à l’exclusion de `t3.a`). Cela pouvait entraîner des erreurs logiques ou des plantages lorsque des fonctions attendaient des types de colonnes différents de ceux réellement présents dans le plan d’exécution. [#95157](https://github.com/ClickHouse/ClickHouse/pull/95157) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#96394](https://github.com/ClickHouse/ClickHouse/issues/96394) : correction d’une erreur logique dans certains cas lorsque `LIMIT/OFFSET` négatif est utilisé dans des requêtes distribuées. [#95357](https://github.com/ClickHouse/ClickHouse/pull/95357) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#96220](https://github.com/ClickHouse/ClickHouse/issues/96220) : correction d’un plantage lors de l’application de `tupleElement` à des tableaux de JSON. Clôt [#95581](https://github.com/ClickHouse/ClickHouse/issues/95581). [#95647](https://github.com/ClickHouse/ClickHouse/pull/95647) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#96054](https://github.com/ClickHouse/ClickHouse/issues/96054) : correction du squashing des données Delta Lake partitionnées. [#95773](https://github.com/ClickHouse/ClickHouse/pull/95773) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Rétroporté dans [#96084](https://github.com/ClickHouse/ClickHouse/issues/96084) : correction d’une erreur `NOT_SUPPORTED` pouvant survenir lors de l’utilisation de l’algorithme de jointure `direct` avec une table MergeTree vide. [#95935](https://github.com/ClickHouse/ClickHouse/pull/95935) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#96213](https://github.com/ClickHouse/ClickHouse/issues/96213) : correction des chemins ignorés dans le type de données JSON. Auparavant, avec `JSON(SKIP path)`, toutes les clés JSON ayant le préfixe `path` étaient ignorées, y compris des clés comme `"pathpath"` ; cela pouvait donc entraîner une perte de données pour ces chemins lors de l’insertion. C’est désormais corrigé, et seule la clé `"path"` est ignorée. [#95948](https://github.com/ClickHouse/ClickHouse/pull/95948) ([Pavel Kruglov](https://github.com/Avogar)).
* Rétroporté dans [#96080](https://github.com/ClickHouse/ClickHouse/issues/96080) : correction de la période des profileurs globaux (contrôlée par `global_profiler_real_time_period_ns` et `global_profiler_cpu_time_period_ns`). Au lieu de la valeur définie, une valeur tronquée était utilisée, ce qui faisait se réveiller le profileur plus souvent que prévu. [#96048](https://github.com/ClickHouse/ClickHouse/pull/96048) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96542](https://github.com/ClickHouse/ClickHouse/issues/96542) : correction de la révocation des rôles par défaut. [#96103](https://github.com/ClickHouse/ClickHouse/pull/96103) ([Vitaly Baranov](https://github.com/vitlibar)).
* Rétroporté dans [#96160](https://github.com/ClickHouse/ClickHouse/issues/96160) : correction d’un use-after-free dans l’analyse des index, dans le cas rare où `use_primary_key` est désactivé et où un très grand nombre de disjonctions de conditions utilisent l’index. [#96112](https://github.com/ClickHouse/ClickHouse/pull/96112) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#96157](https://github.com/ClickHouse/ClickHouse/issues/96157) : correction d’une utilisation d’une valeur non initialisée dans `formatDateTime` avec des formateurs à largeur non fixe, comme ceux de style MySQL et JODA. [#96133](https://github.com/ClickHouse/ClickHouse/pull/96133) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97153](https://github.com/ClickHouse/ClickHouse/issues/97153) : correction de `AccessRights::contains`, qui renvoyait des résultats incorrects en cas de révocations partielles. [#96170](https://github.com/ClickHouse/ClickHouse/pull/96170) ([pufit](https://github.com/pufit)).
* Rétroporté dans [#96280](https://github.com/ClickHouse/ClickHouse/issues/96280) : correction d’un interblocage possible dans ProcessList. Cela peut se produire en raison d’une inversion de verrou si le traqueur de surengagement mémoire se déclenche pendant l’ajout d’une tâche au vérificateur d’annulation. [#96182](https://github.com/ClickHouse/ClickHouse/pull/96182) ([Antonio Andelic](https://github.com/antonio2368)).
* Rétroporté dans [#96462](https://github.com/ClickHouse/ClickHouse/issues/96462) : correction d’un bogue où des requêtes impliquant des jointures externes (LEFT, RIGHT ou FULL) combinées à plusieurs INNER JOIN pouvaient renvoyer des résultats incorrects en raison d’un réordonnancement invalide des jointures. Lorsque la condition ON d’une jointure externe faisait référence à des colonnes de plusieurs tables déjà jointes, l’optimiseur ne tenait pas compte de toutes les dépendances entre tables et pouvait réordonner les jointures de manière incorrecte, ce qui produisait des lignes manquantes. Clôture [#95972](https://github.com/ClickHouse/ClickHouse/issues/95972). [#96193](https://github.com/ClickHouse/ClickHouse/pull/96193) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Rétroporté dans [#96562](https://github.com/ClickHouse/ClickHouse/issues/96562) : lorsqu’aucune statistique n’est définie pour une table, ClickHouse ne doit pas tenter d’y accéder. Cela évite un certain surcoût (plus de 100 ms) lié à la vérification de l’existence des fichiers de statistiques. (issue [#96068](https://github.com/ClickHouse/ClickHouse/issues/96068)). [#96233](https://github.com/ClickHouse/ClickHouse/pull/96233) ([Han Fei](https://github.com/hanfei1991)).
* Rétroporté dans [#96386](https://github.com/ClickHouse/ClickHouse/issues/96386) : correction d’un élagage des partitions incorrect pour la fonction `not IN` et `not has` dans certains cas. [#96241](https://github.com/ClickHouse/ClickHouse/pull/96241) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Rétroporté dans [#96327](https://github.com/ClickHouse/ClickHouse/issues/96327) : correction d’un `stack-use-after-scope` dans l’index de similarité vectorielle. [#96259](https://github.com/ClickHouse/ClickHouse/pull/96259) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#96532](https://github.com/ClickHouse/ClickHouse/issues/96532) : correction d’un livelock dans le thread du vérificateur d’annulation pour les requêtes avec des valeurs élevées de `max_execution_time`. [#96450](https://github.com/ClickHouse/ClickHouse/pull/96450) ([Sergei Trifonov](https://github.com/serxa)).
* Rétroporté dans [#96693](https://github.com/ClickHouse/ClickHouse/issues/96693) : validation de la witness version dans bech32 afin d’éviter un dépassement de tampon. [#96671](https://github.com/ClickHouse/ClickHouse/pull/96671) ([Raúl Marín](https://github.com/Algunenano)).
* Rétroporté dans [#97206](https://github.com/ClickHouse/ClickHouse/issues/97206) : corrige le retour de l’epoch (`1970-01-01`) par `min(timestamp)` via `_minmax_count_projection` après une fusion TTL lorsque toutes les lignes d’un bloc sont filtrées. [#96703](https://github.com/ClickHouse/ClickHouse/pull/96703) ([Raquel Barbadillo](https://github.com/rbarbadillo)).
* Rétroporté dans [#96919](https://github.com/ClickHouse/ClickHouse/issues/96919) : corrige l’échec des requêtes `ALTER TABLE DROP COLUMN` lorsqu’une lightweight update avait déjà été effectuée sur la même colonne. [#96861](https://github.com/ClickHouse/ClickHouse/pull/96861) ([Anton Popov](https://github.com/CurtizJ)).
* Rétroporté dans [#96938](https://github.com/ClickHouse/ClickHouse/issues/96938) : corrige l’exception `std::terminate` dans `indexOfAssumeSorted` lorsqu’elle est appelée avec des types incompatibles (par ex. un tableau `IPv4` avec une valeur de recherche entière). [#96877](https://github.com/ClickHouse/ClickHouse/pull/96877) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97049](https://github.com/ClickHouse/ClickHouse/issues/97049) : corrige l’exception `Bad cast from type DB::ColumnNullable to DB::ColumnString` lors de l’utilisation de fonctions de fenêtre avec `group_by_use_nulls = 1` et CUBE/ROLLUP/GROUPING SETS. [#96878](https://github.com/ClickHouse/ClickHouse/pull/96878) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Rétroporté dans [#97125](https://github.com/ClickHouse/ClickHouse/issues/97125) : corrige un crash (SEGFAULT) dans `clearCaches`, causé par le fait que `BlockIO::operator=` ne déplaçait pas `query_metadata_cache`, ce qui entraînait la destruction prématurée des instantanés de stockage en cache et un use-after-free du stockage `MergeTreeData`. [#96995](https://github.com/ClickHouse/ClickHouse/pull/96995) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
