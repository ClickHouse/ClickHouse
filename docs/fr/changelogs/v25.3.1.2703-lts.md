<div id="clickhouse-release-v25312703-lts-b684e195f96-fixme-as-compared-to-v25311-new-217f67ec3ad">
  ### Version de ClickHouse v25.3.1.2703-lts (b684e195f96) FIXME par rapport à v25.3.1.1-new (217f67ec3ad)
</div>

<div id="backward-incompatible-change">
  #### Changement incompatible avec les versions précédentes
</div>

* Interdire `TRUNCATE DATABASE` pour les bases de données Replicated. [#76651](https://github.com/ClickHouse/ClickHouse/pull/76651) ([Bharat Nallan](https://github.com/bharatnc)).
* Désactiver les répliques parallèles par défaut lorsque l’analyseur est désactivé, quel que soit le paramètre `compatibility`. Il reste possible de modifier ce comportement en définissant explicitement `parallel_replicas_only_with_analyzer` sur `false`. [#77115](https://github.com/ClickHouse/ClickHouse/pull/77115) ([Igor Nikonov](https://github.com/devcrafter)).
* Il n’est plus possible d’utiliser `NaN` ou `inf` comme valeurs flottantes pour les paramètres. [#77546](https://github.com/ClickHouse/ClickHouse/pull/77546) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="new-feature">
  #### Nouvelle fonctionnalité
</div>

* Une nouvelle implémentation du cache de pages en espace utilisateur, qui permet de mettre les données en cache dans la mémoire du processus au lieu de s’appuyer sur le cache de pages du système d’exploitation ; cela est utile lorsque les données sont stockées sur un système de fichiers virtuel distant sans cache de système de fichiers local. [#70509](https://github.com/ClickHouse/ClickHouse/pull/70509) ([Michael Kolupaev](https://github.com/al13n321)).
* Rétroporté dans [#77924](https://github.com/ClickHouse/ClickHouse/issues/77924) : prise en charge des types de données Decimal à faible cardinalité, correction de [#72256](https://github.com/ClickHouse/ClickHouse/issues/72256). [#72833](https://github.com/ClickHouse/ClickHouse/pull/72833) ([zhanglistar](https://github.com/zhanglistar)).
* Ajout du paramètre serveur `concurrent_threads_scheduler`, qui régit la manière dont les slots CPU sont distribués entre les requêtes concurrentes. Il peut être défini sur `round_robin` (comportement précédent) ou `fair_round_robin` pour corriger le problème de répartition inéquitable du CPU entre les INSERTs et les SELECTs. [#75949](https://github.com/ClickHouse/ClickHouse/pull/75949) ([Sergei Trifonov](https://github.com/serxa)).
* Ajout de la fonction `arraySymmetricDifference`. Elle renvoie tous les éléments de plusieurs arguments de type tableau qui ne figurent pas dans tous les arguments. Exemple : `SELECT arraySymmetricDifference([1, 2], [2, 3])` renvoie `[1, 3]`. (issue [#61673](https://github.com/ClickHouse/ClickHouse/issues/61673)). [#76231](https://github.com/ClickHouse/ClickHouse/pull/76231) ([Filipp Abapolov](https://github.com/pheepa)).
* Ajout de la fonction d’agrégation `estimatecompressionratio` — voir [#70801](https://github.com/ClickHouse/ClickHouse/issues/70801). [#76661](https://github.com/ClickHouse/ClickHouse/pull/76661) ([Tariq Almawash](https://github.com/talmawash)).
* Les événements de profil `FilterTransformPassedRows` et `FilterTransformPassedBytes` afficheront le nombre de lignes et d’octets filtrés pendant l’exécution de la requête. [#76662](https://github.com/ClickHouse/ClickHouse/pull/76662) ([Onkar Deshpande](https://github.com/onkar)).
* Ajout de la fonction de hachage keccak256, couramment utilisée dans les implémentations de blockchain, en particulier dans les systèmes basés sur l’EVM. [#76669](https://github.com/ClickHouse/ClickHouse/pull/76669) ([Arnaud Briche](https://github.com/arnaudbriche)).
* Cette fonctionnalité ajoute la possibilité de définir une liste d’en-têtes transmis depuis les en-têtes de la requête client vers l’authentificateur HTTP externe. [#77054](https://github.com/ClickHouse/ClickHouse/pull/77054) ([inv2004](https://github.com/inv2004)).
* Ajout de 3 nouvelles fonctions : `icebergTruncate`, conformément à la spécification [https://iceberg.apache.org/spec/#truncate-transform-details](https://iceberg.apache.org/spec/#truncate-transform-details), ainsi que `toYearNumSinceEpoch` et `toMonthNumSinceEpoch`. Prise en charge de la transformation `truncate` dans l’élagage des partitions pour le moteur `Iceberg`. [#77403](https://github.com/ClickHouse/ClickHouse/pull/77403) ([alesapin](https://github.com/alesapin)).
* Rétroporté dans [#77975](https://github.com/ClickHouse/ClickHouse/issues/77975) : le type de données `JSON` est prêt pour la production. Voir [https://jsonbench.com/](https://jsonbench.com/). Les types de données `Dynamic` et `Varaint` sont prêts pour la production. [#77785](https://github.com/ClickHouse/ClickHouse/pull/77785) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="experimental-feature">
  #### Fonctionnalité expérimentale
</div>

* Ajout de la prise en charge de l’autodécouverte dynamique des clusters. Cela étend la fonctionnalité existante d’autodécouverte des *nœuds*. ClickHouse peut désormais détecter et enregistrer automatiquement de nouveaux *clusters* sous un chemin ZooKeeper commun via `<multicluster_root_path>`. [#76001](https://github.com/ClickHouse/ClickHouse/pull/76001) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Autorise les merges de nettoyage automatiques de partitions entières après un timeout configurable, grâce au nouveau paramètre `enable_replacing_merge_with_cleanup_for_min_age_to_force_merge`. [#76440](https://github.com/ClickHouse/ClickHouse/pull/76440) ([Christoph Wurm](https://github.com/cwurm)).
* Ajout de la prise en charge de [Unity Catalog](https://www.databricks.com/product/unity-catalog) pour les tables DeltaLake sur AWS S3 et le système de fichiers local. [#76988](https://github.com/ClickHouse/ClickHouse/pull/76988) ([alesapin](https://github.com/alesapin)).
* Introduction d’une intégration expérimentale avec le catalogue de services AWS Glue pour les tables Iceberg. [#77257](https://github.com/ClickHouse/ClickHouse/pull/77257) ([alesapin](https://github.com/alesapin)).

<div id="performance-improvement">
  #### Amélioration des performances
</div>

* Appliquer l’attribut `preserve_most` à certains endroits du code. [#67778](https://github.com/ClickHouse/ClickHouse/pull/67778) ([Nikita Taranov](https://github.com/nickitat)).
* Implémenter le query condition cache afin d’améliorer les performances des requêtes utilisant des conditions répétées. La plage de la portion de données qui ne satisfait pas la condition est mémorisée en mémoire sous forme d’index temporaire. Les requêtes suivantes utiliseront cet index. clôture [#67768](https://github.com/ClickHouse/ClickHouse/issues/67768) ### Entrée de documentation pour les changements visibles par l’utilisateur. [#69236](https://github.com/ClickHouse/ClickHouse/pull/69236) ([zhongyuankai](https://github.com/zhongyuankai)).
* Remplacer Int256 et UInt256 par le i256 natif de clang dans les calculs arithmétiques, conformément aux tests de [#70502](https://github.com/ClickHouse/ClickHouse/issues/70502). [#73658](https://github.com/ClickHouse/ClickHouse/pull/73658) ([李扬](https://github.com/taiyang-li)).
* Dans certains cas (par ex. une colonne Array vide), les parties de données peuvent contenir des fichiers vides. Nous pouvons éviter d’écrire des blobs vides dans ObjectStorage et ne stocker que les métadonnées de ces fichiers lorsque la table réside sur un disque avec des stockages de métadonnées et d’objets séparés. [#75860](https://github.com/ClickHouse/ClickHouse/pull/75860) ([Alexander Gololobov](https://github.com/davenger)).
* Améliorer les performances de min/max pour Decimal32/Decimal64/DateTime64. [#76570](https://github.com/ClickHouse/ClickHouse/pull/76570) ([李扬](https://github.com/taiyang-li)).
* Expulser activement les données du cache lors de la suppression de parts. Ne pas laisser le cache croître jusqu’à sa taille maximale si la quantité de données est inférieure. [#76641](https://github.com/ClickHouse/ClickHouse/pull/76641) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* La compilation des requêtes (paramètre `compile_expressions`) tient désormais compte du type de machine. Cela accélère considérablement ces requêtes. [#76753](https://github.com/ClickHouse/ClickHouse/pull/76753) ([Robert Schulze](https://github.com/rschu1ze)).
* Rétroporté dans [#77880](https://github.com/ClickHouse/ClickHouse/issues/77880) : Optimiser arraySort. [#76850](https://github.com/ClickHouse/ClickHouse/pull/76850) ([李扬](https://github.com/taiyang-li)).
* Rétroporté dans [#77961](https://github.com/ClickHouse/ClickHouse/issues/77961) : Désactiver `filesystem_cache_prefer_bigger_buffer_size` lorsque le cache est utilisé passivement, par exemple pour les merges. [#77898](https://github.com/ClickHouse/ClickHouse/pull/77898) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### Correction d’un bogue (dysfonctionnement visible par l’utilisateur dans une version stable officielle)
</div>

* Correction d’un blocage lors du traitement d’un lot en attente pour un `INSERT` distribué asynchrone (dû par exemple à `No such file or directory`). [#72939](https://github.com/ClickHouse/ClickHouse/pull/72939) ([Azat Khuzhin](https://github.com/azat)).
* Amélioration de la conversion des datetime lors de l’analyse des index, en imposant un comportement de saturation pour les conversions implicites de Date vers DateTime. Cela corrige de potentielles imprécisions dans l’analyse des index dues aux limitations de plage des datetime. Cela corrige [#73307](https://github.com/ClickHouse/ClickHouse/issues/73307). Cela corrige également la conversion explicite `toDateTime` lorsque `date_time_overflow_behavior = 'ignore'`, qui est la valeur par défaut. [#73326](https://github.com/ClickHouse/ClickHouse/pull/73326) ([Amos Bird](https://github.com/amosbird)).
* Correction de divers bogues dus à une condition de concurrence entre les UUID et les noms de table (par exemple, cela corrige la concurrence entre `RENAME` et `RESTART REPLICA` ; en cas de `RENAME` concurrent avec `SYSTEM RESTART REPLICA`, il peut arriver que la mauvaise réplique soit redémarrée, ou qu’une des tables reste dans l’état `Table X is being restarted`). [#76308](https://github.com/ClickHouse/ClickHouse/pull/76308) ([Azat Khuzhin](https://github.com/azat)).
* Correction d’une perte de données lorsque async insert est activé et qu’un `insert into ... from file ...` utilise des tailles de bloc inégales : si la taille du premier bloc est &lt; async&#95;max&#95;size mais que celle du second bloc est &gt; async&#95;max&#95;size, le second bloc n’est pas inséré. Ces données restent dans `squashing`. [#76343](https://github.com/ClickHouse/ClickHouse/pull/76343) ([Han Fei](https://github.com/hanfei1991)).
* Le champ &#39;marks&#39; a été renommé en &#39;marks&#95;bytes&#39; dans `system.data_skipping_indices`. [#76374](https://github.com/ClickHouse/ClickHouse/pull/76374) ([Robert Schulze](https://github.com/rschu1ze)).
* Correction de la gestion du redimensionnement dynamique du cache du système de fichiers, qui provoquait des erreurs inattendues pendant l’éviction. [#76466](https://github.com/ClickHouse/ClickHouse/pull/76466) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Correction de l’initialisation de `used_flag` dans le hash en parallèle. Cela pouvait provoquer un plantage du serveur. [#76580](https://github.com/ClickHouse/ClickHouse/pull/76580) ([Nikita Taranov](https://github.com/nickitat)).
* Correction d’une erreur logique lors de l’appel de la fonction `defaultProfiles()` à l’intérieur d’une projection. [#76627](https://github.com/ClickHouse/ClickHouse/pull/76627) ([pufit](https://github.com/pufit)).
* Ne plus demander d’authentification basic interactive dans le navigateur dans la Web UI. Clôt [#76319](https://github.com/ClickHouse/ClickHouse/issues/76319). [#76637](https://github.com/ClickHouse/ClickHouse/pull/76637) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Correction de l’exception THERE&#95;IS&#95;NO&#95;COLUMN lors de la sélection d’un littéral booléen depuis des tables distribuées. [#76656](https://github.com/ClickHouse/ClickHouse/pull/76656) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Le sous-chemin à l’intérieur du répertoire de la table est désormais choisi de manière plus pertinente. [#76681](https://github.com/ClickHouse/ClickHouse/pull/76681) ([Daniil Ivanik](https://github.com/divanik)).
* Correction d’une erreur `Not found column in block` après modification d’une table avec une sous-colonne dans la PK. Après [https://github.com/ClickHouse/ClickHouse/pull/72644](https://github.com/ClickHouse/ClickHouse/pull/72644), nécessite [https://github.com/ClickHouse/ClickHouse/pull/74403](https://github.com/ClickHouse/ClickHouse/pull/74403). * Vider les tampons d’écriture de sortie avant leur finalisation. Corrige le `LOGICAL_ERROR` généré lors de la finalisation de certains formats de sortie, par ex. `JSONEachRowWithProgressRowOutputFormat`. [#76726](https://github.com/ClickHouse/ClickHouse/pull/76726) ([Antonio Andelic](https://github.com/antonio2368)).
* Ajout de la prise en charge des UUID binaires de MongoDB ([#74452](https://github.com/ClickHouse/ClickHouse/issues/74452)) - Correction du pushdown de WHERE vers MongoDB lors de l’utilisation de la table function ([#72210](https://github.com/ClickHouse/ClickHouse/issues/72210)) - Modification du type mapping MongoDB - ClickHouse afin que l’UUID binaire de MongoDB ne puisse être analysé qu’en UUID ClickHouse.
