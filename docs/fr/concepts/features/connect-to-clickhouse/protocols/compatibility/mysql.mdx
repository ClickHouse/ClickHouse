ClickHouse prend en charge le protocole de communication MySQL. Ainsi, certains clients ne disposant pas de connecteurs ClickHouse natifs peuvent utiliser le protocole MySQL à la place. Cette compatibilité a été validée avec les outils de BI suivants :

* [Looker Studio](/fr/integrations/connectors/data-visualization/looker-studio-and-clickhouse)
* [Tableau Online](/fr/integrations/connectors/data-visualization/tableau/tableau-online-and-clickhouse)
* [QuickSight](/fr/integrations/connectors/data-visualization/quicksight-and-clickhouse)

Si vous essayez d’autres clients ou intégrations non testés, gardez à l’esprit les limitations possibles suivantes :

* L’implémentation SSL peut ne pas être entièrement compatible ; des problèmes de [TLS SNI](https://www.cloudflare.com/learning/ssl/what-is-sni/) peuvent survenir.
* Un outil donné peut nécessiter des fonctionnalités du dialecte (par exemple, des fonctions ou des paramètres propres à MySQL) qui ne sont pas encore implémentées.

Si un driver natif est disponible (par exemple, [DBeaver](/fr/integrations/connectors/sql-clients/dbeaver)), il est toujours préférable de l’utiliser plutôt que l’interface MySQL. Par ailleurs, même si la plupart des bibliothèques clientes MySQL par langage devraient fonctionner correctement, rien ne garantit que l’interface MySQL puisse se substituer directement à une base de code contenant des requêtes MySQL existantes.

Si votre cas d’utilisation implique un outil particulier ne disposant pas de driver ClickHouse natif, que vous souhaitez l’utiliser via l’interface MySQL et que vous avez constaté certaines incompatibilités, veuillez [créer un ticket](https://github.com/ClickHouse/ClickHouse/issues) dans le dépôt ClickHouse.

<Note>
  Pour mieux prendre en charge le dialecte SQL des outils de BI ci-dessus, l’interface MySQL de ClickHouse exécute implicitement les requêtes SELECT avec le paramètre [prefer&#95;column&#95;name&#95;to&#95;alias = 1](/fr/reference/settings/session-settings/prefer#prefer_column_name_to_alias).
  Ce comportement ne peut pas être désactivé et peut, dans de rares cas limites, entraîner des différences de comportement entre les requêtes envoyées à l’interface de requêtes ordinaire de ClickHouse et celles envoyées à son interface MySQL.
</Note>

## Création de plusieurs utilisateurs MySQL dans ClickHouse Cloud {#creating-multiple-mysql-users-in-clickhouse-cloud}

Par défaut, un utilisateur intégré `mysql4<subdomain>` utilise le même mot de passe que l’utilisateur `default`. La partie `<subdomain>` correspond au premier segment de votre nom d’hôte ClickHouse Cloud. Ce format est nécessaire pour les outils qui établissent une connexion sécurisée, mais ne fournissent pas d’[informations SNI lors de leur poignée de main TLS](https://www.cloudflare.com/learning/ssl/what-is-sni). Sans indication supplémentaire dans le nom d’utilisateur, le routage interne est alors impossible (le client MySQL en ligne de commande fait partie de ces outils).

C’est pourquoi nous vous *recommandons vivement* de respecter le format `mysql4<subdomain>_<username>` lors de la création d’un utilisateur destiné à l’interface MySQL : `<subdomain>` permet d’identifier votre service Cloud et `<username>` est un suffixe de votre choix.

<Tip>
  Pour un nom d’hôte ClickHouse Cloud tel que `foobar.us-east1.aws.clickhouse.cloud`, la partie `<subdomain>` correspond à `foobar`. Un nom d’utilisateur MySQL personnalisé pourrait donc être `mysql4foobar_team1`.
</Tip>

Vous pouvez créer d’autres utilisateurs pour l’interface MySQL, par exemple si vous devez leur appliquer des paramètres supplémentaires.

1. Facultatif — créez un [settings profile](/fr/reference/statements/create/settings-profile) à appliquer à votre utilisateur personnalisé. Par exemple, créez `my_custom_profile` avec un paramètre supplémentaire qui s’appliquera par défaut lorsque vous vous connecterez avec l’utilisateur créé à l’étape suivante :

   ```sql
   CREATE SETTINGS PROFILE my_custom_profile SETTINGS prefer_column_name_to_alias=1;
   ```

   `prefer_column_name_to_alias` n’est utilisé qu’à titre d’exemple ; vous pouvez spécifier d’autres paramètres.

2. [Créez un utilisateur](/fr/reference/statements/create/user) au format suivant : `mysql4<subdomain>_<username>` ([voir ci-dessus](#creating-multiple-mysql-users-in-clickhouse-cloud)). Le mot de passe doit être au format double SHA1. Par exemple :

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$';
   ```

   ou, si vous souhaitez utiliser un profil personnalisé pour cet utilisateur :

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$' SETTINGS PROFILE 'my_custom_profile';
   ```

   où `my_custom_profile` est le nom du profil créé précédemment.

3. [Accordez](/fr/reference/statements/grant) au nouvel utilisateur les autorisations nécessaires pour interagir avec les tables ou les bases de données souhaitées. Par exemple, pour n’accorder l’accès qu’à `system.query_log` :

   ```sql
   GRANT SELECT ON system.query_log TO mysql4foobar_team1;
   ```

4. Connectez-vous à votre service ClickHouse Cloud via l’interface MySQL avec l’utilisateur créé.

### Dépannage des utilisateurs MySQL multiples dans ClickHouse Cloud {#troubleshooting-multiple-mysql-users-in-clickhouse-cloud}

Si vous avez créé un nouvel utilisateur MySQL et que l&#39;erreur suivante s&#39;affiche lors de la connexion avec le client CLI MySQL :

```sql
ERROR 2013 (HY000): Lost connection to MySQL server at 'reading authorization packet', system error: 54
```

Dans ce cas, assurez-vous que le nom d’utilisateur respecte le format `mysql4<subdomain>_<username>`, comme indiqué ([ci-dessus](#creating-multiple-mysql-users-in-clickhouse-cloud)).

## Activer l&#39;interface MySQL sur ClickHouse autogéré {#enabling-the-mysql-interface-on-self-managed-clickhouse}

Ajoutez le paramètre [mysql&#95;port](/fr/reference/settings/server-settings/settings/mysql#mysql_port) au fichier de configuration de votre serveur. Vous pouvez par exemple définir le port dans un nouveau fichier XML placé dans votre [dossier](/fr/concepts/features/configuration/server-config/configuration-files) `config.d/` :

```xml
<clickhouse>
    <mysql_port>9004</mysql_port>
</clickhouse>
```

Démarrez votre serveur ClickHouse et recherchez un message de journal semblable au suivant, qui mentionne Listening for MySQL compatibility protocol :

```bash
{} <Information> Application: Listening for MySQL compatibility protocol: 127.0.0.1:9004
```

## Connecter MySQL à ClickHouse {#connect-mysql-to-clickhouse}

La commande suivante montre comment connecter le client MySQL `mysql` à ClickHouse :

```bash
mysql --protocol tcp -h [hostname] -u [username] -P [port_number] [database_name]
```

Par exemple :

```bash
$ mysql --protocol tcp -h 127.0.0.1 -u default -P 9004 default
```

Sortie si la connexion a réussi :

```text
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 4
Server version: 20.2.1.1-ClickHouse

Copyright (c) 2000, 2019, Oracle and/or its affiliates. All rights reserved.

Oracle is a registered trademark of Oracle Corporation and/or its
affiliates. Other names may be trademarks of their respective
owners.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>
```

Pour assurer la compatibilité avec tous les clients MySQL, il est recommandé de spécifier le mot de passe de l&#39;utilisateur avec [double SHA1](/fr/concepts/features/configuration/settings/settings-users#user-namepassword) dans le fichier de configuration.
Si le mot de passe de l&#39;utilisateur est spécifié avec [SHA256](/fr/reference/functions/regular-functions/hash-functions#SHA256), certains clients ne pourront pas s&#39;authentifier (mysqljs et les anciennes versions des outils en ligne de commande MySQL et MariaDB).

Restrictions :

* les requêtes préparées ne sont pas prises en charge

* certains types de données sont envoyés sous forme de chaînes de caractères

Pour annuler une requête de longue durée, utilisez le statement `KILL QUERY connection_id` (il est remplacé par `KILL QUERY WHERE query_id = connection_id` lors de son traitement). Par exemple :

```bash
$ mysql --protocol tcp -h mysql_server -P 9004 default -u default --password=123 -e "KILL QUERY 123456;"
```
