ClickHouse prend en charge l’intégration avec plusieurs catalogues (Unity, Glue, Polaris, etc.). Ce guide vous explique comment interroger vos tables Iceberg dans [catalogue d’exécution du lakehouse aka BigLake Metastore](https://docs.cloud.google.com/biglake/docs/) via ClickHouse.

<Note>
  Cette fonctionnalité étant en bêta, vous devrez l’activer à l’aide de :
  `SET allow_database_iceberg = 1;`
</Note>

## Prérequis {#prerequisites}

Avant de créer une connexion entre ClickHouse et le Catalogue d’exécution Lakehouse (BigLake Metastore), assurez-vous de disposer des éléments suivants :

* Un **projet Google Cloud** avec le Catalogue d’exécution Lakehouse activé
* Des identifiants, au choix :
  * Une **clé de compte de service** : un fichier de clé JSON d’un compte de service disposant d’un accès au catalogue et au bucket GCS, créé via [Google Cloud Console](https://docs.cloud.google.com/iam/docs/keys-create-delete). C’est l’option recommandée pour les serveurs, car elle ne dépend pas d’une session utilisateur.
  * Des **identifiants Application Default** (ID client OAuth et secret client) pour une application, créés via [Google Cloud Console](https://docs.cloud.google.com/docs/authentication/provide-credentials-adc), ainsi qu’un **jeton d’actualisation** obtenu en suivant le flux OAuth avec les scopes appropriés (par ex. `https://www.googleapis.com/auth/bigquery` et le scope de stockage pour GCS)
* Un **chemin de warehouse** : un bucket GCS (et un préfixe facultatif) où vos tables sont stockées, par ex. `gs://your-bucket` ou `gs://your-bucket/prefix`

## Créer une connexion entre le Catalogue d’exécution Lakehouse et ClickHouse {#creating-a-connection}

Une fois les identifiants OAuth configurés, créez une base de données dans ClickHouse qui utilise le moteur de base de données [DataLakeCatalog](/fr/reference/engines/database-engines/datalake) :

```sql
SET allow_database_iceberg = 1;

CREATE DATABASE lakehouse_runtime_catalog
ENGINE = DataLakeCatalog('https://biglake.googleapis.com/iceberg/v1/restcatalog')
SETTINGS
    catalog_type = 'biglake',
    google_adc_client_id = '<client-id>',
    google_adc_client_secret = '<client-secret>',
    google_adc_refresh_token = '<refresh-token>',
    google_adc_quota_project_id = '<gcp-project-id>',
    warehouse = 'gs://<bucket_name>/<optional-prefix>';
```

Pour vous authentifier avec une clé de compte de service plutôt, transmettez le contenu du fichier de clé JSON dans `google_service_account_key` et le projet dans `google_project_id`. ClickHouse signe un JWT avec la clé, l’échange contre un jeton d’accès et le renouvelle automatiquement. Ce même jeton sert à lire les fichiers de données depuis GCS. La clé est masquée dans `SHOW CREATE DATABASE` ainsi que dans les logs.

```sql
CREATE DATABASE lakehouse_runtime_catalog
ENGINE = DataLakeCatalog('https://biglake.googleapis.com/iceberg/v1/restcatalog')
SETTINGS
    catalog_type = 'biglake',
    google_service_account_key = '{"type": "service_account", "client_email": "...", "private_key": "...", ...}',
    google_project_id = '<gcp-project-id>',
    warehouse = 'gs://<bucket_name>/<optional-prefix>';
```

`google_service_account_key` et les paramètres `google_adc_*` s’excluent mutuellement. Aucun d’eux ne peut être combiné avec le paramètre `disk`, car une table stockée sur un disque lit ses fichiers de données avec les identifiants du disque, et non avec ceux du catalogue.

## Interroger les tables du catalogue d’exécution du lakehouse avec ClickHouse {#querying-lakehouse-runtime-tables}

Une fois la connexion établie, vous pouvez interroger les tables enregistrées dans le catalogue d’exécution du lakehouse.

```sql
USE LAKEHOUSE_RUNTIME_CATALOG;

SHOW TABLES;
```

Exemple de sortie :

```response
┌─name──────────────────────────────────────┐
│lakehouse_runtime_catalog.my_iceberg_table │   
└───────────────────────────────────────────┘
```

```sql
SELECT count(*) FROM `lakehouse_runtime_catalog.my_iceberg_table`;
```

<Info>
  **Backticks requis**

  Les backticks sont requis, car ClickHouse ne prend pas en charge plus d’un espace de noms.
</Info>

Pour afficher la définition de la table :

```sql
SHOW CREATE TABLE `lakehouse_runtime_catalog.my_iceberg_table`;
```

## Chargement de données du Lakehouse dans ClickHouse {#loading-data-into-clickhouse}

Pour charger les données d&#39;une table du Lakehouse runtime catalog dans une table ClickHouse locale afin d&#39;accélérer les requêtes répétées, créez une table MergeTree et insérez les données depuis le catalogue :

```sql
CREATE TABLE clickhouse_table
(
    `id` Int64,
    `event_time` DateTime64(3),
    `user_id` String,
    `payload` String
)
ENGINE = MergeTree
ORDER BY (event_time, id);

INSERT INTO local_events
SELECT * FROM lakehouse_runtime_catalog.`icebench.my_iceberg_table`;
```

Après le chargement initial, interrogez `clickhouse_table` afin de réduire la latence. Réexécutez `INSERT INTO ... SELECT` pour actualiser les données depuis BigLake lorsque nécessaire.
