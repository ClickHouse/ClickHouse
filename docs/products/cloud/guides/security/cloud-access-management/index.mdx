ClickHouse Cloud access is controlled at multiple levels. A user may need access at more than one level to complete a task.

## Understand access levels {#understand-access-levels}

| Access level | What it controls | Examples |
|---|---|---|
| Organization | Whether a user can access the organization and manage organization-wide resources | Organization settings, users, billing, and API keys |
| Service and console | Which services and Cloud console features a user can access or manage | Service settings and SQL console |
| Database | Which SQL operations and data a user can access after connecting to a service | Permissions on databases, tables, columns, and rows |

<Info>
**Opening a console feature and accessing data are separate permissions**

Service and console permissions determine whether a user can open features such as SQL console. Database permissions determine what the user can query or modify after opening them.
</Info>

System and custom Cloud roles can grant organization and service permissions. For supported services, custom Cloud roles can also include database permissions. See [Manage database roles](/products/cloud/guides/security/cloud-access-management/manage-custom-roles#manage-database-roles) for current availability and requirements. For services that do not support this option, you can [manage database permissions directly with SQL](/products/cloud/guides/security/cloud-access-management/common-access-management-queries). Applications and workloads can instead use JWT authentication. Choose the guide for your task below.
