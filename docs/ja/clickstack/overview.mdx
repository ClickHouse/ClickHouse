**ClickStack** は、ClickHouse 上に構築された、SRE、開発者、そして彼らの AIエージェントのためのオープンソースのオブザーバビリティプラットフォームです。ログ、トレース、メトリクスをセッションリプレイとあわせて一か所で検索・クエリし、相関付けることができます。

調査は **ClickStack UI** で行えるほか、[MCPサーバー](/ja/clickstack/mcp) を介して独自のエージェントを接続することもできます。エージェントは、チームが普段使っている開発ツールから、UI で探索するのと同じデータを対象にテレメトリーの検索、トレースの追跡、SQL の実行を行えます。

情報量の豊富なログとトレーススパンにより、リクエストの詳細、カスタム属性、ビジネスコンテキストがワイドイベントとして保持されます。ClickHouse はこれらをメトリクスやセッションデータとともに保存するため、エンジニアとエージェントはサービスをまたいで手がかりを相関付け、影響を受けているリクエストや顧客を突き止めることができます。

<Tip>
  インフラストラクチャの管理は [ClickHouse オブザーバビリティ](/ja/clickstack/observability) に任せて、問題の調査に集中しましょう。[ClickHouse Cloud に登録](https://clickhouse.cloud/signUp?loc=docs-clickstack-overview-inline)して、今すぐ始めましょう。
</Tip>

<div id="features">
  ## 機能 {#features}
</div>

* [MCP](/ja/clickstack/mcp) を通じて独自のエージェントを接続し、テレメトリーの検索、障害の調査、ダッシュボードやアラートの管理が可能
* ClickStack UI でログ、メトリクス、セッションリプレイ、トレースを検索・相関付け
* スキーマ非依存で、既存の ClickHouse スキーマ上で動作
* high-cardinality なテレメトリーに対しても高速な検索と集計を実行
* 全文検索や `level:err` のような Lucene 形式のフィルタを利用可能。より詳細な分析には SQL も使用可能
* 数クリックでアラートを設定
* 複雑なクエリ言語なしで、高カーディナリティのイベントをダッシュボードで可視化
* JSON 文字列をネイティブにクエリ可能
* ログとトレースをライブテールし、常に最新のイベントを確認
* OpenTelemetry (OTel) を標準でサポート
* HTTP リクエストから DB クエリまで、正常性とパフォーマンスを監視 (APM)
* イベントデルタで異常やパフォーマンス低下を特定
* ログパターンの認識
* URL クエリパラメータを使用して、[ディープリンク](/ja/clickstack/url-parameters)から ClickStack ページを直接開く

## コンポーネント {#components}

ClickStack は、次の3つのコアコンポーネントで構成されています。

  <div style={{ flex: '1 1 240px' }}>
    1. **ClickStack UI** – オブザーバビリティデータの探索と可視化に特化した、purpose-built のフロントエンド
    2. **ClickHouse** – スタックの中核を担う高パフォーマンスな分析データベース
    3. **OpenTelemetry collector** – ログ、トレース、メトリクス向けの推奨スキーマを備えた、独自ビルドの設定済み collector
  </div>
</div>

これらのコンポーネントは、完全な **セルフマネージドの ClickStack Open Source** 構成としてまとめてデプロイできます。各コンポーネントがどのように連携し、アプリケーションの状態がどのように保存されるかについては、[アーキテクチャガイド](/ja/clickstack/architecture)を参照してください。

ブラウザ上で動作するホスト型の ClickStack UI も提供されています。これを使えば、UI 用のインフラストラクチャを別途デプロイすることなく、既存の ClickHouse デプロイメントに直接接続できます。

まずは [Getting Started ガイド](/ja/clickstack/getting-started/oss)に目を通し、その後 [サンプルデータセット](/ja/clickstack/example-datasets/index)を読み込んでください。また、[デプロイオプション](/ja/clickstack/deployment/oss)や[本番環境のベストプラクティス](/ja/clickstack/managing/production)に関するドキュメントもあわせてご覧ください。

<div id="clickstack-principles">
  ## 原則 {#clickstack-principles}
</div>

### 任意のエージェントを利用する {#bring-your-own-agents}

AI を活用した調査は、ClickStack の中核となるワークフローです。お好みのエージェントを [MCPサーバー](/ja/clickstack/mcp) 経由で接続すれば、開発環境を離れることなく、ログの検索、トレースの追跡、テレメトリーの探索を行えます。

一般的なタスクには調査ツールを利用でき、さらに SQL を使えば、エージェントが証拠を相関付けたり、定義済みのダッシュボードでは扱えない問いを掘り下げたりできます。エージェントとモデルはユーザー自身が選択でき、ClickStack はチームが利用しているものと同じテレメトリーと調査ツールへのアクセスを提供します。

<div id="clickstack-easy-to-setup">
  ### 数分で簡単にセットアップ {#clickstack-easy-to-setup}
</div>

ClickStack は、あらゆる ClickHouse インスタンスやスキーマですぐに使い始められ、必要な設定も最小限です。新規導入でも既存環境への統合でも、数分で稼働を開始できます。

### 使いやすく purpose-built な設計 {#user-friendly-purpose-built}

ClickStack UI は、検索、トレースの探索、チャート、ダッシュボード、アラートを 1 か所に集約しています。日常的な疑問には Lucene 形式のフィルタやビジュアルなクエリビルダーで対応し、分析をより細かく制御したい場合は SQL に切り替えられます。エンジニアとエージェントが同じデータを扱うため、調査の裏付けとなるエビデンスを自分の目で確認できます。

### エンドツーエンドのオブザーバビリティ {#end-to-end-observability}

フロントエンドのセッションリプレイをアプリケーションログ、分散トレース、メトリクスと関連付けることで、システム全体にわたって障害を追跡できます。ワイドイベントでは、リクエストの詳細、カスタム属性、ビジネス上のコンテキストがログやトレーススパンにまとめて保持されるため、影響を受けているリクエスト、サービス、顧客を容易に特定できます。

### ClickHouse 向けに設計 {#built-for-clickhouse}

ClickHouse の列指向ストレージ、圧縮、並列クエリ実行により、high-cardinality なテレメトリーが大量にあっても高速な検索と集計が可能です。また、クエリの同時実行によって、エンジニアとエージェントが同じデータを並列に調査できます。

<div id="open-telemetry-native">
  ### OpenTelemetry ネイティブ {#open-telemetry-native}
</div>

ClickStack は OpenTelemetry にネイティブ対応しており、すべてのデータを OpenTelemetry collector のエンドポイント経由で取り込みます。上級ユーザー向けには、ネイティブのファイルフォーマット、カスタムパイプライン、または Vector などのサードパーティツールを使って、ClickHouse に直接インジェストすることもサポートしています。

<div id="open-source-and-customizable">
  ### オープンソースで高いカスタマイズ性 {#open-source-and-customizable}
</div>

ClickStack は完全なオープンソースで、どこにでもデプロイできます。スキーマは柔軟でユーザー自身が変更可能であり、UI も変更を加えることなくカスタムスキーマに対応できるよう設計されています。collector、ClickHouse、UI を含む各コンポーネントは、インジェスト、クエリ、ストレージの要件に応じてそれぞれ個別にスケールできます。
