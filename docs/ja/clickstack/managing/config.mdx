ClickStack の各コンポーネントでは、以下の設定オプションを利用できます。

<div id="modifying-settings">
  ## オープンソース版の設定 {#modifying-settings}
</div>

### Docker {#docker}

[All in One](/ja/clickstack/deployment/all-in-one)、[ClickStack UI only](/ja/clickstack/deployment/hyperdx-only)、または [Local Mode](/ja/clickstack/deployment/local-mode-only) を使用している場合は、必要な設定を環境変数として渡すだけです (例) 。

```shell
docker run -e HYPERDX_APP_PORT=8081 -p 8081:8081 -p 4317:4317 -p 4318:4318 clickhouse/clickstack-all-in-one:latest
```

### Docker Compose {#docker-compose}

[Docker Compose](/ja/clickstack/deployment/docker-compose) のデプロイメントガイドを使用する場合は、[`.env`](https://github.com/ClickHouse/clickstack/blob/main/.env) ファイルを使って設定を変更できます。

または、[`docker-compose.yml`](https://github.com/ClickHouse/clickstack/blob/main/docker-compose.yml) ファイル内で設定を明示的に上書きすることもできます。例えば次のとおりです。

例:

```yaml
services:
  app:
    environment:
      HYPERDX_API_KEY: ${HYPERDX_API_KEY}
      HYPERDX_LOG_LEVEL: ${HYPERDX_LOG_LEVEL}
      # ... other settings
```

### Helm {#helm}

[Helm デプロイメントガイド](/ja/clickstack/deployment/helm)に従って、オペレーターと ClickStack チャートをインストールしてください。デプロイメントをカスタマイズする前に、現在のチャートの設定値を取得してください:

```shell
helm show values clickstack/clickstack > values.yaml
```

チャートの設定値を使用してアプリケーションと collector の環境をそれぞれ個別に設定してから、設定を適用します:

```shell
helm upgrade --install my-clickstack clickstack/clickstack -f values.yaml
```

サポートされている設定値、イングレス、リソース、シークレットの設定については、[Helm 設定](/ja/clickstack/deployment/helm-configuration)を参照してください。旧来の `hyperdx/hdx-oss-v2` チャートは、設定値の構造が異なります。

### 接続 {#connection-settings}

ログソースで使用するデータベース接続は、チーム設定で設定します。

| 設定                         | 説明                                                                                                                                                                                                                                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Connection Name`          | ログソース設定でこの接続を識別するための名前。                                                                                                                                                                                                                                                                         |
| `Host`                     | ポートを含む ClickHouse の HTTP(S) エンドポイント。collector のエクスポート先エンドポイントとは別のものです。                                                                                                                                                                                                                          |
| `Username`                 | ClickHouse のユーザー名。デフォルトは `default` です。                                                                                                                                                                                                                                                          |
| `Password`                 | ClickHouse のパスワード。デフォルトは空です。                                                                                                                                                                                                                                                                    |
| `Query Log Setting Prefix` | 現在のユーザーのメールアドレスをクエリログに記録するカスタム ClickHouse 設定のプレフィックス (任意) 。ClickHouse の `custom_settings_prefixes` 設定にも同じプレフィックスを含めてください。含めない場合、クエリは拒否されます。ユーザー識別子を含めずに、どのダッシュボード、アラート、その他の ClickStack 機能がクエリを発行したかを確認するには、[クエリ負荷の要因を特定する](/ja/clickstack/managing/performance-tuning#query-attribution)を参照してください。 |
| `Prometheus compatible`    | 利用可能な場合、Host をプロキシ経由の PromQL クエリ用の Prometheus 互換 API エンドポイントとして扱います。この接続は、ClickHouse をバックエンドとするログ、トレース、OTel メトリクスのログソースには使用できません。                                                                                                                                                               |

### データログソース設定 {#datasource-settings}

ClickStack UI では、ユーザーがオブザーバビリティの各データタイプ/主要領域ごとにログソースを定義する必要があります。

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

この設定は、以下のログの例のように、アプリケーション内の `Team Settings -> Sources` から行えます。

<div className="ch-image-md">
  <Frame>
    ![ClickStack UI のログソース設定](/images/use-cases/observability/hyperdx-25.webp)
  </Frame>
</div>

ClickStack UI がデータをクエリできるように、各ログソースにはテーブルとカラムのマッピングが必要です。メトリクスログソースでは、メトリクスの種類ごとに別々のテーブルを使用できます。`Enabled` トグルは既存のログソースを編集する際に表示されます。ログソースレベルの `Query Settings` には、名前と値のペアを最大 10 個まで指定できます。

ClickStack に付属する[デフォルトの OpenTelemetry (OTel) スキーマ](/ja/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema)を使用している場合、これらのカラムはログソースごとに自動的に推論できます。[スキーマを変更する](#clickhouse)場合やカスタムスキーマを使用する場合は、これらのマッピングを指定し、更新する必要があります。

<Note>
  collector は、[スキーマ設定](#collector-schema-and-retention)に応じて、スキーママイグレーション、または従来の exporter によるスキーマ作成のいずれかの方法でテーブルを作成します。カラムのマッピングは、[ログデータモデル](https://opentelemetry.io/docs/specs/otel/logs/data-model/)をはじめとする OpenTelemetry の規約に従います。
</Note>

各ログソースでは、以下の設定を利用できます。

<div id="materialized-views-settings">
  #### materialized view {#materialized-views-settings}
</div>

materialized view は Log および Trace のログソースに登録できます。対象となる集計クエリは、ログソーステーブルではなく事前集計済みのビューから応答されます。ビューの作成と登録については、[&quot;Materialized views&quot;](/ja/clickstack/managing/materialized-views) を参照してください。

登録した各ビューには、次の設定を構成します。

| 設定                       | 説明                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Database`               | materialized view のターゲットテーブルを含む ClickHouse データベース。                                                                                                      |
| `Table`                  | materialized view 自体ではなく、そのターゲットテーブル。                                                                                                                   |
| `Timestamp Column`       | ターゲットテーブルのタイムスタンプカラム。                                                                                                                                   |
| `Granularity`            | ターゲットテーブルのタイムスタンプカラムの時間バケット (例: `1 minute`) 。クエリがビューを使用できるのは、その時間バケットがこれと同じか、これより粗い場合のみです。                                                              |
| `Minimum Date`           | 任意。ビューにデータが含まれる最も早い日時。指定しない場合、ClickStack はログソーステーブルにデータが存在するすべての日付について、ビューにもデータが含まれると見なします。                                                             |
| `Dimension Columns`      | ビューで事前集計されないため、フィルタリングやグループ化に使用できるカラムのカンマ区切りリスト。                                                                                                        |
| `Pre-aggregated Columns` | ビューで事前集計されるカラム。各エントリでは、集計関数 (`avg`、`count`、`max`、`min`、`quantile`、`sum`、または `histogram`) とログソーステーブルのカラムを、ビュー内の対応するカラムにマッピングします。`count` ではログソースカラムは不要です。 |

これらの設定のほとんどは、ターゲットテーブルを選択するとビューのスキーマから推論されます。

### 相関ソース {#correlated-sources}

ClickStack でソース間の完全な相関付けを有効にするには、ログ、トレース、メトリクス、セッションの相関ソースを設定する必要があります。これにより、ClickStack UI は関連データを紐付け、イベントを表示する際により豊富なコンテキストを提供できます。

* `Logs`: トレースおよびメトリクスと相関付けることができます。
* `Traces`: ログ、セッション、およびメトリクスと相関付けることができます。
* `Metrics`: ログと相関付けることができます。
* `Sessions`: トレースと相関付けることができます。

これらの相関を設定すると、複数の機能が利用できるようになります。たとえば、ClickStack UI はトレースと並べて関連するログを表示したり、セッションに紐付いたメトリクスの異常を示したりできます。

### ClickHouse クライアント設定 {#clickhouse-client-settings}

チーム設定の **ClickHouse クライアント設定** セクションでは、チーム全体のクエリの動作を制御します。

| 設定                                  | デフォルト     | 説明                                                        |
| ----------------------------------- | --------- | --------------------------------------------------------- |
| `Search Row Limit`                  | `200`     | 検索ページおよびダッシュボードの検索タイルで、1 クエリあたりに返される行数。範囲: 1–100,000。     |

## OpenTelemetry collector {#otel-collector}

デプロイ手順については、[ClickStack OpenTelemetryコレクター](/ja/clickstack/ingesting-data/collector)を参照してください。collector 用の変数は、UI コンテナだけでなく collector コンテナにも設定してください。Compose では、`.env` で宣言した値がコンテナに渡されるのは、`docker-compose.yml` でその値が参照されている場合のみです。

<div id="clickhouse">
  ## ClickHouse {#clickhouse}
</div>

ClickStack Open Source には、複数テラバイト規模に対応するよう設計されたデフォルトの ClickHouse 設定が含まれていますが、ユーザーは自身のワークロードに合わせて自由に変更・最適化できます。

ClickHouse を効果的にチューニングするには、[パーツ](/ja/concepts/core-concepts/parts)、[パーティション](/ja/concepts/core-concepts/partitions)、[分片とレプリカ](/ja/guides/oss/deployment-and-scaling/shards)、さらに挿入時に[マージ](/ja/concepts/core-concepts/merges)がどのように発生するかといった、ストレージに関する重要な概念を理解しておく必要があります。[プライマリ索引](/ja/concepts/core-concepts/primary-indexes)、[スパースなセカンダリ索引](/ja/concepts/features/performance/skip-indexes/skipping-indexes)、およびデータスキッピングインデックスの基本に加え、[データライフサイクルの管理](/ja/guides/use-cases/observability/build-your-own/managing-data)の手法 (たとえば 有効期限 (TTL) を使ったライフサイクル管理) も確認することをお勧めします。

ClickStack は[スキーマのカスタマイズ](/ja/guides/use-cases/observability/build-your-own/schema-design)をサポートしており、カラム型の変更、新しいフィールド (たとえばログから) の抽出、コーデックや辞書の適用、さらにプロジェクションによるクエリ高速化を行えます。

さらに、materialized view は、データがその view のソーステーブルに書き込まれ、アプリケーションがターゲットテーブルから読み取る構成であれば、[インジェスト時にデータを変換またはフィルタリング](/ja/guides/use-cases/observability/build-your-own/schema-design#materialized-columns)するために利用できます。materialized view は、ClickStack で[ネイティブにクエリを高速化](/ja/clickstack/managing/materialized-views)する用途にも利用できます。

詳細については、スキーマ設計、索引戦略、データ管理のベストプラクティスに関する ClickHouse のドキュメントを参照してください。その大部分は ClickStack のデプロイメントにもそのまま適用できます。
