  このページでは **Self-managed ClickHouse Observability** について説明します。推奨される完全マネージド型のエクスペリエンスについては、[こちら](/ja/clickstack/observability/getting-started)のドキュメントを参照してください。
</Note>

ClickHouse Cloud 上に Self-managed ClickHouse Observability をデプロイし、インジェストパイプライン経由でテストイベントを送信して、そのイベントがオブザーバビリティ UI に表示されることを確認します。

ClickHouse Cloud が ClickHouse バックエンドを運用する一方で、インジェストパイプラインとスキーマは引き続きユーザー自身が管理できます。Self-managed ClickHouse Observability には次のような特長があります。

* ストレージとは独立したコンピュートの自動スケーリング
* オブジェクトストレージを活用した、低コストかつ実質無制限のデータ保持
* [warehouse](/ja/products/cloud/features/infrastructure/warehouses) による読み取りワークロードと書き込みワークロードの分離
* 統合認証
* 自動バックアップ
* セキュリティおよびコンプライアンス機能
* シームレスなアップグレード

## 始める前に {#before-you-begin}

[サポートされているインテグレーション](/ja/integrations/home)と独自のスキーマを使用して、データを ClickHouse に直接送信することもできます。

### ClickHouse Cloud サービスを作成する {#create-a-managed-clickstack-service}

ClickHouse Cloud クイックスタートの「[ClickHouse サービスを作成する](/ja/get-started/setup/cloud#1-create-a-clickhouse-service)」の手順を完了してください。次に進む前に、サービスが稼働中であることを確認してください。

  ### インジェスト環境の準備 {#prepare-your-ingestion-environment}

  * 新しい [OpenTelemetry Collector](/ja/clickstack/self-configured/ingesting-data/collector) を起動するには、[Docker](https://docs.docker.com/get-docker/) をインストールしてください。Kubernetes の場合は、[Helm](/ja/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured) を使用して collector をデプロイします。
  * 既存の collector を使用する場合は、[ゲートウェイロール](/ja/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)として実行し、そのディストリビューションに [ClickHouse exporter](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter) が含まれていることを確認してください。必要な設定は、本ガイドの手順の中で追加します。

      <Info>

        OpenTelemetry には、ログ、トレース、メトリクス、セッション用の事前設定済みスキーマが用意されています。
      </Info>

      <div className="ch-image-lg">
        <Frame>
          ![インジェストのソースとして OpenTelemetry を選択](/images/clickstack/getting-started/select_source_toggle.webp)
        </Frame>

      <Tabs>
        <Tab title="新しい collector を起動する">
          UI は `default` 管理者の認証情報を使って collector のコマンドを生成します。インジェスト用のアクセス権を管理権限と分離し、管理者パスワードに依存せずに済むよう、インジェスト専用の認証情報の使用を推奨します。

          <Accordion title="インジェスト専用の認証情報を作成する（推奨）">
            ClickHouse Cloud でサービスの SQL コンソールを開き、次のコマンドを実行します。

            ```sql
            CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
            GRANT SELECT, INSERT, CREATE DATABASE, CREATE TABLE, CREATE VIEW ON default.* TO `clickstack-ingest`;
            ```

            生成されたコマンド内の `CLICKHOUSE_USER="default"` を `CLICKHOUSE_USER="clickstack-ingest"` に置き換え、`CLICKHOUSE_PASSWORD` に専用ユーザーのパスワードを設定します。
          </Accordion>

          `default` 管理者の認証情報のまま進める場合は、**Start Collector** タブからコマンドをコピーします。サービスのエンドポイントは UI によってあらかじめ入力されています。パスワードのプレースホルダーをサービスのパスワードに置き換えてください。パスワードが手元にない場合は、[接続情報を確認またはリセット](/ja/products/cloud/guides/sql-console/connection-details)してください。

          コマンドの形式は次のとおりです。

          ```shell
          docker run -e CLICKHOUSE_ENDPOINT="https://<host>:8443" \
              -e CLICKHOUSE_USER="default" \
              -e CLICKHOUSE_PASSWORD="<your_password_here>" \
              -p 4317:4317 -p 4318:4318 \
              clickhouse/clickstack-otel-collector:latest
          ```

          `<host>` と `<your_password_here>` を ClickHouse Cloud サービスの値に置き換えてから、コマンドを実行します。

          collector はフォアグラウンドで実行されます。この端末は開いたままにし、本ガイドの以降のコマンドは別の端末で実行してください。

          <Note>
            このコマンドは OTLP ポートを認証なしで公開するため、ローカルでの評価のみを想定しています。本番トラフィックを送信する前に、[collector を保護](/ja/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)してください。
          </Note>
        </Tab>

        <Tab title="既存の collector を使用する">
          **Configure existing collector** を選択し、collector の設定を調整します。

          collector は、アプリケーションと ClickHouse Cloud の間のゲートウェイとして実行します。以下の設定では、必要な ClickHouse exporter と各シグナルのパイプラインを追加します。

          この例では、UI が生成した `default` の認証情報を使用しています。インジェスト専用の認証情報を使用する場合は、**新しい collector を起動する** タブにある任意のセットアップ手順に従ってください。そのうえで、両方の ClickHouse exporter ブロックで `username: default` を `username: clickstack-ingest` に置き換え、`password` に専用ユーザーのパスワードを設定します。

          <Info>
            **必要な collector コンポーネント**

            collector のディストリビューションには、[ClickHouse exporter](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter) と [routing コネクタ](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/connector/routingconnector) が含まれている必要があります。OpenTelemetry Collector Contrib ディストリビューションには、この両方が含まれています。
          </Info>

          この例では、OTLP レシーバー、バッチ処理とメモリ制限、Session Replay のルーティング、ClickHouse exporter を追加します。

          既存の OTLP レシーバーを再利用し、その認証設定と TLS 設定はそのまま維持してください。例と同じコンポーネント ID やパイプライン ID が設定内ですでに使われている場合は、ID が重複しないよう、マージするか名前を変更してください。ポート `4317` と `4318` で 2 つのレシーバーを実行すると、ポートが競合します。

          設定をマージしたら、既存のデプロイプロセスで collector をリロードまたは再起動します。

      curl -i "http://localhost:4318/v1/logs" \
        -H "Content-Type: application/json" \

      {
        "resourceLogs": [{

              "value": {"stringValue": "clickstack-docs-test"}
            }]
          },
          "scopeLogs": [{

              "timeUnixNano": "${NOW_NANO}",
              "severityText": "INFO",
              "body": {"stringValue": "ClickStack ingestion test"}

      [Vector](https://vector.dev) は、高パフォーマンスでベンダーニュートラルなオブザーバビリティ向けデータパイプラインです。柔軟性が高くリソース消費が少ないことから、特にログのインジェストで広く利用されています。

      Vector を使用する場合、スキーマはユーザー自身で定義します。OpenTelemetry の規約に従うことも、扱うイベントに固有のフィールドを使用することもできます。

      <Info>
        **既存の Vector パイプラインが必要です**

        入力パイプラインを構成した Vector をすでに運用している場合は、このガイドに沿って進めてください。パイプラインを通じて送信されるデータには、**タイムスタンプ列**またはそれと同等の時刻フィールドが含まれている必要があります。このフィールドは、オブザーバビリティ UI でデータソースを設定する際に選択します。

        以下の手順では、既存のパイプラインに ClickHouse シンクを追加します。
      </Info>

#### データベースとテーブルの作成 {#create-a-vector-database-and-table}

      Vector のシンクを設定する前に、データベースとテーブルを作成してください。

      ClickHouse Cloud でサービスの SQL コンソールを開き、データベースを作成します：

      たとえば、ログ用のデータベースを作成します：

      ```sql
      CREATE DATABASE IF NOT EXISTS logs
      ```

      次に、ログデータの構造に一致するスキーマを持つテーブルを作成します。以下の例では、一般的な Nginx アクセスログ形式を想定しています。

      ```sql
      CREATE TABLE logs.nginx_logs
      (
          `time_local` DateTime,
          `remote_addr` IPv4,
          `remote_user` LowCardinality(String),
          `request` String,
          `status` UInt16,
          `body_bytes_sent` UInt64,
          `http_referer` String,
          `http_user_agent` String,
          `http_x_forwarded_for` LowCardinality(String),
          `request_time` Float32,
          `upstream_response_time` Float32,
          `http_host` String
      )
      ENGINE = MergeTree
      ORDER BY (toStartOfMinute(time_local), status, remote_addr);
      ```

      テーブルは、Vector が生成する出力スキーマと一致している必要があります。推奨される[スキーマのベストプラクティス](/ja/concepts/best-practices/select-data-type)に従い、データに応じてスキーマを調整してください。

      ClickHouse における[主キー](/ja/concepts/core-concepts/primary-indexes)の仕組みを理解したうえで、アクセスパターンに基づいて並び替えキー (ordering key) を選択することを強く推奨します。主キーの選び方については、[パフォーマンスチューニング](/ja/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key)のガイドを参照してください。

#### ClickHouse シンクの設定 {#configure-the-vector-clickhouse-sink}

      テーブルを作成したら、Vector の設定に ClickHouse シンクを追加します。

      ```yaml
      sinks:
        clickhouse:
          type: clickhouse
          inputs:
            - your_input
          endpoint: "https://<host>:8443"
          database: logs
          table: nginx_logs
          format: json_each_row
          skip_unknown_fields: true
          auth:
            strategy: basic
            user: default
            password: "<your_password_here>"
      ```

      `your_input` を既存のパイプラインの入力に置き換えてください。`<host>` と `<your_password_here>` は、ご利用の ClickHouse Cloud サービスの値に置き換えてください。必要に応じて、出力先のデータベースまたはテーブルを変更してください。

      <Accordion title="インジェスト専用の認証情報を使用する（推奨）">
        本番環境では、専用のユーザーを作成し、Vector のターゲットテーブルへのアクセス権限を付与してください。ClickHouse Cloud でサービスの SQL コンソールを開き、次のコマンドを実行します。

        ```sql
        CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
        GRANT SELECT, INSERT ON logs.nginx_logs TO `clickstack-ingest`;
        ```

        Vector のシンクで `default` を `clickstack-ingest` に置き換え、`password` には専用ユーザーのパスワードを設定します。
      </Accordion>

      更新した設定を保存したら、既存のデプロイ手順に従って Vector を再読み込みまたは再起動します。

      Vector を使用したデータの取り込みのその他の例については [Vector によるデータの取り込み](/ja/clickstack/observability/ingesting-data/vector) を、詳細なオプションについては [Vector ClickHouse シンクのドキュメント](https://vector.dev/docs/reference/configuration/sinks/clickhouse/) を参照してください。

#### データソースの作成 {#create-a-vector-data-source}

      Vector パイプラインでデータを投入したテーブルに対して、データソースを作成します。初回ログイン時には、UI からデータソースの作成を求められます。

      フォームには、デフォルトの OpenTelemetry スキーマ向けの式があらかじめ入力されています。このガイドで作成した Nginx テーブルを使用する場合は、ログソースに次の値を設定してください。

      | 設定                | 値                                                                                                               |
      | ----------------- | --------------------------------------------------------------------------------------------------------------- |
      | **名前**            | `Nginx logs`                                                                                                    |
      | **ログソースのデータ型**    | ログ                                                                                                              |
      | **サーバー接続**        | `Default`                                                                                                       |
      | **データベース**        | `logs`                                                                                                          |
      | **テーブル**          | `nginx_logs`                                                                                                    |
      | **タイムスタンプ列**      | `time_local`                                                                                                    |
      | **デフォルトの SELECT** | `time_local, remote_addr, status, request`                                                                      |
      | **サービス名の式**       | `'nginx'`                                                                                                       |
      | **ログレベル式**        | `multiIf(status >= 500, 'ERROR', status >= 400, 'WARN', 'INFO')`                                                |
      | **ログ属性式**         | `map('http.remote_addr', toString(remote_addr), 'http.status_code', toString(status), 'http.request', request)` |
      | **リソース属性式**       | `map('service.name', 'nginx')`                                                                                  |
      | **表示用タイムスタンプ列**   | `time_local`                                                                                                    |
      | **トレースID式**       | `''`                                                                                                            |
      | **スパンID式**        | `''`                                                                                                            |
      | **暗黙的カラム式**       | `request`                                                                                                       |

      Nginx テーブルには `Body` カラムが存在しません。**Body Expression** を次のように設定してください:

      ```sql
      concat(
        remote_addr, ' ',
        remote_user, ' ',
        '[', formatDateTime(time_local, '%d/%b/%Y:%H:%i:%S %z'), '] ',
        '"', request, '" ',
        toString(status), ' ',
        toString(body_bytes_sent), ' ',
        '"', http_referer, '" ',
        '"', http_user_agent, '" ',
        '"', http_x_forwarded_for, '" ',
        toString(request_time), ' ',
        toString(upstream_response_time), ' ',
        '"', http_host, '"'
      )
      ```

      その他のソース設定については、[設定リファレンス](/ja/clickstack/self-configured/managing/config)を参照してください。
    </Step>
