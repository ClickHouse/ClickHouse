## 有効期限 (TTL) によるデータ保持期間 {#ttl-clickstack}

有効期限 (TTL) は、Self-managed ClickHouse Observability において効率的なデータ保持と管理を実現する重要な機能です。膨大な量のデータが絶えず生成される環境では、その重要性は特に高まります。有効期限 (TTL) を使用すると古いデータを自動的に期限切れにして削除できるため、手動で介入しなくてもストレージを最適に活用し、パフォーマンスを維持できます。この機能は、データベースを無駄のない状態に保ち、ストレージコストを削減し、関連性の高い最新のデータに絞り込むことでクエリの高速性と効率性を確保するうえで欠かせません。さらに、データのライフサイクルを体系的に管理することでデータ保持ポリシーへの準拠を支援し、オブザーバビリティソリューション全体の持続可能性とスケーラビリティを高めます。

**デフォルトでは、データは 30 日間保持されます。変更する場合は、[&quot;有効期限 (TTL) の変更&quot;](#modifying-ttl) を参照してください。**

ClickHouse では、有効期限 (TTL) はテーブル単位で制御されます。例として、ログのデフォルトスキーマを以下に示します。コレクターがテーブルを作成する際、`${TABLES_TTL}` は設定済みの保持期間 (変更しない限り 30 日) に置き換えられます。

ClickHouse のパーティション化を使用すると、カラムまたは SQL式に基づいてデータをディスク上で論理的に分離できます。データを論理的に分離することで、各パーティションを個別に操作できます。たとえば、有効期限 (TTL) ポリシーに従って期限切れになったパーティションを削除できます。

上記の例のとおり、パーティション化はテーブルの初回定義時に `PARTITION BY` 句で指定します。この句には任意のカラムに対する SQL式を記述でき、その評価結果によって各行の振り分け先パーティションが決まります。これにより、データはディスク上の各パーティションと (共通のフォルダ名プレフィックスを介して) 論理的に関連付けられ、パーティションごとに個別にクエリできるようになります。上記の例では、デフォルトの `otel_logs` スキーマは式 `toDate(Timestamp)` を使用して日単位でパーティション分割しています。ClickHouse に行が挿入されると、この式が各行に対して評価され、該当するパーティションが存在すればそこへルーティングされます (その日の最初の行であれば、パーティションが新たに作成されます) 。パーティション化とその他の用途の詳細については、[&quot;テーブルパーティション&quot;](/ja/concepts/core-concepts/partitions) を参照してください。

テーブルスキーマには、`TTL toDateTime(Timestamp) + ${TABLES_TTL}` と設定 `ttl_only_drop_parts = 1` も含まれています。前者の句により、設定済みの 有効期限 (TTL) (デフォルトは 30 日) を超えたデータは確実に削除されます。設定 `ttl_only_drop_parts = 1` により、すべてのデータが期限切れになったデータパーツのみが期限切れとして処理されます (行を部分的に削除することはありません) 。パーティション化によって異なる日のデータが &quot;マージ&quot; されることはないため、データを効率的に削除できます。

<Warning>
  **`ttl_only_drop_parts`**

  設定 [`ttl_only_drop_parts=1`](/ja/reference/settings/merge-tree-settings/other#ttl_only_drop_parts) を常に使用することを推奨します。この設定を有効にすると、ClickHouse はパーツ内のすべての行が期限切れになった時点でパーツ全体を削除します。有効期限 (TTL) 対象の行を部分的にクリーンアップする (`ttl_only_drop_parts=0` の場合は、リソースを大量に消費するミューテーションによって行われます) のではなくパーツ全体を削除することで、`merge_with_ttl_timeout` をより短く設定でき、システムパフォーマンスへの影響も抑えられます。有効期限 (TTL) による期限切れ処理の単位 (例：日) と同じ単位でデータをパーティション分割しておけば、各パーツには自然と定義された期間のデータのみが含まれます。これにより、`ttl_only_drop_parts=1` を効率的に適用できます。
</Warning>

デフォルトでは、有効期限 (TTL) が期限切れになったデータは、ClickHouse が[データパーツをマージする](/ja/reference/engines/table-engines/mergetree-family/mergetree#mergetree-data-storage)際に削除されます。ClickHouse はデータの期限切れを検出すると、スケジュール外のマージを実行します。

<Info>
  **有効期限 (TTL) のスケジュール**

  前述のとおり、有効期限 (TTL) は即座に適用されるのではなく、スケジュールに従って適用されます。MergeTree テーブルの設定 `merge_with_ttl_timeout` は、削除 有効期限 (TTL) を伴うマージを再実行するまでの最小遅延を秒単位で指定します。デフォルト値は 14400 秒 (4 時間) です。ただし、これはあくまで最小遅延であり、実際に 有効期限 (TTL) マージがトリガーされるまでにはさらに時間がかかる場合があります。値が小さすぎると、スケジュール外のマージが多数実行され、大量のリソースを消費するおそれがあります。有効期限 (TTL) による期限切れ処理は、コマンド `ALTER TABLE my_table MATERIALIZE TTL` で強制的に実行できます。
</Info>

## 有効期限 (TTL)の変更 {#modifying-ttl}

有効期限 (TTL) を変更するには、次のいずれかの方法を使用します。

1. **テーブルスキーマを変更する (推奨)&#x20;**。この方法では、[clickhouse-client](/ja/concepts/features/interfaces/client) や [Cloud SQL コンソール](/ja/products/cloud/features/sql-console-features/sql-console) などを使用して ClickHouseインスタンスに接続する必要があります。例えば、次の DDL を使用すると `otel_logs` テーブルの 有効期限 (TTL) を変更できます。

```sql
ALTER TABLE default.otel_logs
MODIFY TTL TimestampTime + toIntervalDay(7);
```

2. **OTel collector を変更する**。ClickStack OpenTelemetryコレクターは、ClickHouse にテーブルが存在しない場合、自動的にテーブルを作成します。これは ClickHouse exporter によって行われ、この exporter はデフォルトの 有効期限 (TTL) 式を制御するための `ttl` パラメータを公開しています。例：

```yaml
exporters:
 clickhouse:
   endpoint: tcp://localhost:9000?dial_timeout=10s&compress=lz4&async_insert=1
   ttl: 72h
```

### カラムレベルの有効期限 (TTL) {#column-level-ttl}

上記の例では、テーブルレベルでデータを期限切れにしています。データはカラムレベルで期限切れにすることもできます。この機能を使えば、データが古くなるにつれて、調査における価値が保持にかかるリソースのオーバーヘッドに見合わなくなったカラムを削除できます。たとえば、挿入時に抽出されていない新しい動的メタデータ (新しい Kubernetes ラベルなど) が追加される場合に備えて、`Body` カラムは保持しておくことを推奨します。一定の期間 (たとえば 1 か月) が経過すると、この追加メタデータが有用でないことが明らかになる場合があり、その場合は `Body` カラムを保持する価値は低くなります。

以下では、30 日後に `Body` カラムを削除する方法を示します。

```sql
CREATE TABLE otel_logs_v2
(
        `Body` String TTL Timestamp + INTERVAL 30 DAY,
        `Timestamp` DateTime,
 ...
)
ENGINE = MergeTree
ORDER BY (ServiceName, Timestamp)
```

<Note>
  カラムレベルの有効期限 (TTL) を指定するには、ユーザー自身でスキーマを定義する必要があります。OTel collector では指定できません。
</Note>
