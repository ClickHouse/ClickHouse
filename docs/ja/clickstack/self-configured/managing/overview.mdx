## ClickHouse のコアコンセプト {#core-concepts}

ほとんどの管理タスクでは、基盤となる ClickHouse データベースについての理解が必要です。管理作業やパフォーマンス関連の操作を行う前に、以下の ClickHouse のコアコンセプトを確認しておくことをお勧めします。

| コンセプト              | 説明                                                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **テーブル**           | データソースが基盤となる ClickHouse テーブルにどのように対応付けられるか。ClickHouse テーブルでは主に [`MergeTree`](/ja/reference/engines/table-engines/mergetree-family/mergetree) エンジンが使用されます。 |
| **パーツ**            | データが変更不可のパーツとしてどのように書き込まれ、時間の経過とともにマージされていくか。                                                                                                          |
| **パーティション**        | テーブルパーツを論理的にまとめたグループで、データ管理、クエリの実行、最適化を容易にします。                                                                                                         |
| **マージ**            | パーツを結合し、クエリ対象となるパーツ数を減らしてパフォーマンスを維持するバックグラウンドプロセス。                                                                                                     |
| **グラニュール**         | クエリ実行時に読み取りおよび枝刈りの対象となる最小のデータ単位。                                                                                                                       |
| **プライマリ (ソート) キー** | `ORDER BY` キーによって on-disk のデータ配置、圧縮、クエリの枝刈り動作がどのように決まるか。                                                                                               |

これらのコンセプトは ClickHouse のパフォーマンスを理解するうえで基本となるものであり、Self-managed ClickHouse Observability の運用時に適切な管理上の判断を下すのに役立ちます。
