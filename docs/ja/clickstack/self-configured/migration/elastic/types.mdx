<Note>
  このページでは **セルフマネージド型の ClickHouse Observability** について説明します。推奨されるデフォルトの利用形態である完全マネージド型の ClickHouse Observability では、データベーススキーマと型マッピングが自動的に処理されます。移行にあたってこれらの内部構造を設定する必要はありません。まずは [Elasticsearch 移行ガイド](/ja/clickstack/observability/migration/elastic)を参照してください。
</Note>

Elasticsearch と ClickHouse はいずれも多様なデータ型をサポートしていますが、基盤となるストレージとクエリモデルは根本的に異なります。このセクションでは、よく使用される Elasticsearch のフィールド型を、存在する場合は ClickHouse の同等の型に対応付け、移行の参考となる背景情報を示します。同等の型が存在しない場合は、代替手段または注記をコメント欄に記載しています。

### 注記 {#notes}

* **配列**: Elasticsearch では、すべてのフィールドがネイティブに配列をサポートしています。ClickHouse では配列を明示的に定義する必要があります (例: `Array(String)`) が、`an_array[1]` のように特定の位置を指定してアクセスやクエリを行えるという利点があります。
* **マルチフィールド**: Elasticsearch では、[同じフィールドを複数の方法で](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields#_multi_fields_with_multiple_analyzers)索引付けできます (例: `text` と `keyword` の両方)。ClickHouse では、このパターンを別々のカラムまたはビューを使ってモデル化する必要があります。
* **Map 型と JSON 型** - ClickHouse では、`resourceAttributes` や `logAttributes` のような動的なキーと値の構造をモデル化する際に、一般的に [`Map`](/ja/reference/data-types/map) 型が使用されます。この型では実行時に任意のキーを追加できるため、柔軟なスキーマレスのインジェストが可能です。これは考え方として Elasticsearch の JSON オブジェクトに近いものです。ただし、考慮すべき重要な制限があります。

  * **値の型の統一**: ClickHouse の [`Map`](/ja/reference/data-types/map) カラムでは、値の型を統一する必要があります (例: `Map(String, String)`)。型変換を行わずに異なる型の値を混在させることはできません。
  * **パフォーマンスコスト**: [`Map`](/ja/reference/data-types/map) 内のいずれかのキーにアクセスするだけでも Map 全体をメモリに読み込む必要があるため、パフォーマンスが低下する場合があります。
  * **サブカラムがない**: JSON とは異なり、[`Map`](/ja/reference/data-types/map) 内のキーは真のサブカラムとして表現されないため、ClickHouse による効率的な索引付け、圧縮、クエリが制限されます。

  ClickHouse の [`JSON`](/ja/reference/data-types/newjson) 型は、動的な属性を扱う際の [`Map`](/ja/reference/data-types/map) の代替となり、これらの制限のいくつかを解消します。

  * **真のカラム型ストレージ**: 各 JSON パスはサブカラムとして保存されるため、効率的な圧縮、フィルタリング、ベクトル化クエリ実行が可能です。
  * **混在型のサポート**: 異なるデータ型 (例: 整数、文字列、配列) を、型変換や型の統一を行わずに同じパスに共存させることができます。
  * **ファイルシステムのスケーラビリティ**: 動的キー (`max_dynamic_paths`) と型 (`max_dynamic_types`) に対する内部的な上限により、高カーディナリティのキーセットであっても、ディスク上のカラムファイルが爆発的に増加するのを防ぎます。
  * **高密度なストレージ**: null 値や欠損値はスパースに保存されるため、不要なオーバーヘッドが発生しません。

    [`JSON`](/ja/reference/data-types/newjson) 型はオブザーバビリティのワークロードに特に適しており、スキーマレスなインジェストの柔軟性と、ClickHouse のネイティブな型のパフォーマンスおよびスケーラビリティを兼ね備えています。そのため、動的な属性フィールドにおいて [`Map`](/ja/reference/data-types/map) を置き換えるのに最適です。

    JSON 型の詳細については、[JSON ガイド](/ja/guides/clickhouse/data-formats/json/intro) および [&quot;How we built a new powerful JSON data type for ClickHouse&quot;](https://clickhouse.com/blog/a-new-powerful-json-data-type-for-clickhouse) を参照してください。
