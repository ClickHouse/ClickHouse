<Note>
  このページでは **Self-managed ClickHouse Observability** について説明します。推奨される完全マネージド型の環境については、[こちら](/ja/clickstack/observability/overview)のドキュメントを参照してください。
</Note>

高スループットなサービスでは、毎秒数百万件のスパンが生成されることがあります。すべてのスパンを保存するとコストがかさむため、OpenTelemetry Collector の[テールサンプリングプロセッサー](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/processor/tailsamplingprocessor)を使用して、N 件に 1 件のスパンのみを保持するのが一般的です。保持された各スパンには、N の値を記録した `SampleRate` 属性が付与されます。

データをサンプリングすると、単純な集計では正しい結果が得られません。`count()` は実際に発生したイベント数の N 分の 1 しか返さず、`sum()` と `avg()` には偏りが生じ、パーセンタイルもずれます。その結果、ダッシュボード上のリクエスト数、スループット、エラー率が実際よりも低く表示され、誤った判断を招くおそれがあります。

Self-managed ClickHouse Observability は、サンプリングを考慮したクエリエンジンによってこの問題を解決します。トレースソースにサンプリング率の式を設定すると、クエリビルダーが SQL の集計を書き換え、各スパンをそのサンプルレートで重み付けします。これはダッシュボード、アラート、アドホックな検索のすべてに適用されます。

## 仕組み {#how-it-works}

トレースソースに `sampleRateExpression` が設定されている場合、クエリビルダーはこれを次のようにラップします。

```sql
greatest(toUInt64OrZero(toString(expr)), 1)
```

`SampleRate` 属性を持たないスパンの重みはデフォルトで 1 となるため、サンプリングされていないデータでは元のクエリと同一の結果が得られます。

続いて、クエリビルダーが集計を次のように書き換えます。

| 集計                 | 変更前                | 変更後 (サンプル補正済み)                            |
| ------------------ | ------------------ | ----------------------------------------- |
| count              | `count()`          | `sum(weight)`                             |
| count + 条件         | `countIf(cond)`    | `sumIf(weight, cond)`                     |
| avg                | `avg(col)`         | `sum(col * weight) / sum(weight)`         |
| sum                | `sum(col)`         | `sum(col * weight)`                       |
| quantile(p)        | `quantile(p)(col)` | `quantileTDigestWeighted(p)(col, weight)` |
| min / max          | 変更なし               | 変更なし                                      |
| count&#95;distinct | 変更なし               | 変更なし                                      |

<Note>
  サンプリング時のパーセンタイルには、近似計算を行う T-Digest スケッチである `quantileTDigestWeighted` が使用されます。結果は真の値に近くなりますが、厳密な値ではありません。
</Note>

## サンプリング率の式の設定 {#configuring}

**ソース設定** でトレースソースを開き、**Sample Rate Expression** フィールドに、スパンごとのサンプルレートを返す ClickHouse の式を入力します。

たとえば、OpenTelemetry のテールサンプリングプロセッサーがレートを `SpanAttributes['SampleRate']` に書き込む場合は、次のように設定します。

設定が完了すると、すべてのチャート、ダッシュボード、アラート、およびサービスダッシュボードのパネルに、サンプルレートに基づく重み付き集計が自動的に適用されます。個々のクエリを変更する必要はありません。
