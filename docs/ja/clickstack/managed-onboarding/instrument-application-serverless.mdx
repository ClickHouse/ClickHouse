<Info>
  **概要**

  小さなデモアプリケーションを実行し、サービスの「はじめに」ページにある AI プロンプトを使うか、2 か所を手動で編集してインストルメントします。あとは、ログ、トレース、メトリクスが ClickHouse オブザーバビリティに届く様子を確認するだけです。

  所要時間: 約 10 分
</Info>

ClickHouse オブザーバビリティのサービスが作成できました。このガイドでは、まだ何もデータのないサービスに、実行中のアプリケーションからテレメトリーが届くようになるまでの手順を説明します。

ClickHouse オブザーバビリティには、マネージドの OpenTelemetry エンドポイントが用意されています。アプリケーションはこのエンドポイントへテレメトリーを直接送信します。collector の運用も、スキーマの作成も、データベースのサイジングも不要です。インジェスト、スキーマ、ストレージ、最適化、スケーリングはすべて自動で処理されます。

## デモアプリケーション {#the-demo-application}

実際に近い環境でインストルメンテーションを試せるよう、このガイドでは [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) を使用します。これは、まさにこの用途のために提供しているデモアプリケーションです。Node.js と TypeScript で書かれた小規模なアプリで、公開 ClickHouse デモでホストされている HackerNews データセットに対してクエリを実行します。チャート、テーブル、検索ボックスはいずれも、バックエンドへの実際のリクエストによって動作しています。アプリのキャッシュにヒットしなかったリクエストは ClickHouse にもクエリを送るため、各トレースにはアウトバウンドの HTTPS スパンが追加されます。

デモには 2 つのバリアントが用意されています。

* **インストルメンテーションなし**: `main` ブランチ。このガイドでは、AI エージェントを使うか手動で、アプリケーションのビジネスロジックを変更することなく、インストルメンテーションをご自身で追加します。同じ手順はご自身のサービスにもそのまま適用できます。
* **計装済み**: `instrumented` ブランチ。とにかく早くテレメトリーを流して UI を試してみたい場合は、こちらをチェックアウトしてください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス。まだお持ちでない場合は、[Getting Started ガイド](/ja/clickstack/observability/getting-started)の手順に従って作成してください。
* Node.js 18 以降と npm。
* デモを実行するマシンとブラウザの両方から、サービスのテレメトリーエンドポイントにネットワークアクセスできること。

## デモアプリケーションをインストルメントする {#instrument-the-demo-application}

<Steps>
  <Step title="「はじめに」ページを開く" id="open-getting-started">
    ClickHouse オブザーバビリティのサービスを開きます。データが届くまでは **Start sending telemetry** ページが表示され、3 つの接続方法が示されます。

    <div className="ch-image-lg">
      <Frame>
        ![現在のサービスにまだデータがなく、Use an existing OpenTelemetry setup、Instrument with AI、Follow setup guides の 3 つのオプションが表示されている Start sending telemetry ページ](/images/clickstack/getting-started/observability-start-sending-telemetry.png)
      </Frame>
    </div>

    このガイドでは、コーディングエージェントに作業を任せる場合は **Instrument with AI** を、自分で編集する場合は **View connection details** を使用します。このページは開いたままにしておいてください。後でこのページに戻り、データが届いていることを確認します。
  </Step>

  <Step title="デモアプリケーションをクローンして実行する" id="clone-and-run-the-demo-application">

    ```bash
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    ```bash
    ./run.sh
    ```

    <Frame>
      <img src="/images/clickstack/getting-started/hackernews_main.webp" alt="ローカルで実行中の HackerNews Analyzer デモアプリケーション" />
    </Frame>

    この時点では、デモは実行されていますが、まだインストルメントされていません。そのため、サービスにはまだデモからのデータが表示されません。先に進む前に、Ctrl-C でデモを停止してください。
  </Step>

    いずれか1つの方法を選択してください。どの方法を選んでも、最終的には同じ計装済みのデモが完成します。

        <div className="ch-image-md">
          <Frame>
            ![インストルメンテーション用のプロンプトと、マスクされた CLICKSTACK_OTLP_ENDPOINT および CLICKSTACK_API_KEY の値が表示された Set it up with an AI agent ダイアログ](/images/clickstack/getting-started/observability-ai-agent-prompt.png)

        ```bash
        CLICKSTACK_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        CLICKSTACK_API_KEY=<your-api-key>
        ```

        このプロンプトは、これらの値を環境変数から読み取り、決してハードコードしないようエージェントに指示します。デモリポジトリでは、`.env` はバージョン管理の対象外になっています。ご自身のアプリケーションでは、gitignore に登録した `.env` またはシークレットストアを使用してください。

        エージェントが提案する変更は、適用する前に必ず確認してください。処理が完了したら、`./run.sh` でデモを再起動します。

        <Warning>
          ブラウザー SDK はエンドポイントと APIキーをブラウザーバンドルに埋め込むため、ネットワークタブを調べれば誰でもそれらを読み取れます。テスト用のサービスを使用し、`.env` はバージョン管理の対象外にしてください。
        </Warning>

### デモの接続先をサービスに設定する {#configure-environment}

        `.env` を開き、以下の値を設定します。エンドポイントと APIキーは、ダイアログに表示された値に置き換えてください。

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        これらは標準的な OpenTelemetry のエクスポーター変数です。アプリケーションのソースコードには何もハードコードされていません。

        `OTEL_EXPORTER_OTLP_ENDPOINT` の `https://` プレフィックスは残したまま、`/v1/logs`、`/v1/traces`、`/v1/metrics` を末尾に追加しないでください。シグナルごとのパスは SDK が付加します。`OTEL_EXPORTER_OTLP_HEADERS` には、`Bearer` プレフィックスを付けずに `authorization=<your-api-key>` を設定してください。

        インストルメンテーションの手順は、SDK のインストール、起動コマンドの切り替え、ブラウザー SDK の有効化の 3 つです。いずれもアプリケーションのビジネスロジックには一切手を加えません。

### Node SDK をインストールする {#install-node-sdk}

        ```bash
        npm install @hyperdx/node-opentelemetry
        ```

### run.sh でラッパーを有効にする {#enable-run-sh-wrapper}

        `run.sh` の末尾には `exec` 行が 2 つあります。通常の `node` の行をコメントアウトし、計装済みの行のコメントアウトを解除します。

        ```diff
         # BEFORE: plain node, no instrumentation:
        -exec node scripts/entrypoint.js
        +# exec node scripts/entrypoint.js

         # AFTER: same source, wrapped by opentelemetry-instrument:
        -# exec npx opentelemetry-instrument scripts/entrypoint.js
        +exec npx opentelemetry-instrument scripts/entrypoint.js
        ```

        起動は引き続き `scripts/entrypoint.js` 経由で行ってください。このシムが `require('console')` を呼び出すことで、コンソール出力のキャプチャが `console.log` をラップできるようになります。`opentelemetry-instrument` で `dist/server/index.js` を直接指定した場合、トレースは送信されますが、ログは警告なしに破棄されます。

### ブラウザー SDK を有効化する {#enable-browser-sdk}

        ```bash
        npm install @hyperdx/browser
        ```

        `src/web/telemetry.ts` で、import 文、`HyperDX.init` ブロック、および `recordAction` 内の `HyperDX.addAction` のコメントアウトを解除します。

        ```diff
        -// import HyperDX from '@hyperdx/browser';
        +import HyperDX from '@hyperdx/browser';

         export function initTelemetry(): void {
        -  // HyperDX.init({
        -  //   url: __OTLP_ENDPOINT__,
        -  //   apiKey: __OTLP_AUTH_TOKEN__,
        -  //   service: 'hn-analyzer-web',
        -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        -  //   consoleCapture: true,
        -  //   advancedNetworkCapture: true,
        -  // });
        +  HyperDX.init({
        +    url: __OTLP_ENDPOINT__,
        +    apiKey: __OTLP_AUTH_TOKEN__,
        +    service: 'hn-analyzer-web',
        +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        +    consoleCapture: true,
        +    advancedNetworkCapture: true,
        +  });
         }
        ```

        `__OTLP_ENDPOINT__` と `__OTLP_AUTH_TOKEN__` は、バックエンドが使用するのと同じ `OTEL_EXPORTER_OTLP_*` の値をもとに、`vite.config.ts` によって注入されるコンパイル時定数です。

        <Warning>
          ブラウザー SDK はエンドポイントと APIキーをブラウザーのバンドルに埋め込むため、ネットワークタブを確認すれば誰でもこれらを読み取れます。テスト用のサービスを使用し、`.env` はバージョン管理の対象外にしてください。
        </Warning>

        `./run.sh` でデモを再起動します。
      </Tab>

      <Tab title="計装済みのブランチを使用する" id="use-the-instrumented-branch">
        インストルメンテーションの手順を省略し、計装済みのデモから始める場合は、手動インストルメンテーションのタブで説明しているとおりに `.env` の `OTEL_EXPORTER_OTLP_*` の値を設定してから、[`instrumented` ブランチ](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented)をチェックアウトしてください。

        ```bash
        git checkout instrumented
        npm install
        ./run.sh
        ```

        SDK を取り除く目的がない限り、このブランチでは `./reset.sh` を実行しないでください。
      </Tab>
    </Tabs>
  </Step>

  <Step title="トラフィックを生成し、データが届いていることを確認する" id="confirm-data-is-arriving">

    サービスの **Start sending telemetry** ページに戻り、**Check for data** を選択します。テレメトリーが到着すると、サービスの状態が **Data received** に変わり、**Start exploring** を選択できるようになります。

      </Frame>

    ログ、トレース、メトリクス、セッションリプレイはすべて同じ場所に集約され、共通の検索構文で検索でき、自動的に相関付けられます。

## 何も表示されない場合 {#if-nothing-shows-up}

* `.env` 内の値を確認してください。エンドポイントは `https://` で始まり、ポート `4318` で終わっている必要があり、`/v1/...` の接尾辞は付けません。APIキーには完全な値を指定する必要があります。完全な値は **Reveal key** を選択するとコピーできます。
* 手動の手順で設定した場合は、`OTEL_EXPORTER_OTLP_HEADERS` が `Bearer` プレフィックスなしの `authorization=<your-api-key>` になっていること、また起動時のバナーに `Health check passed` の行が 3 つすべて表示されていることを確認してください。
* インストルメントした後にデモを再起動し、ブラウザのタブを再読み込みしたかを確認してください。セッションリプレイは、計装済みのバンドルが配信されるまで開始されません。
* **検索** で時間範囲を広げ、フィルタをすべて解除してください。デフォルトのログソースが **Logs** ではなく **Traces** に設定されている可能性があります。
* サービス側の問題かどうかを切り分けるには、**チーム設定 → マネージドテレメトリー** を開き、**Send a Test Log** を実行してください。そのログが **検索** に表示されれば、サービスはデータを正常に受信しており、問題はデモの設定にあります。

## 次のステップ {#next-steps}

これで、サービスに実際のアプリケーションのテレメトリーが格納されました。独自のサービスをインストルメントするには、サービスの **AI でインストルメントする** プロンプトを再利用するか、同じエンドポイントとAPIキーで[サポート済みの言語 SDKs](/ja/clickstack/observability/ingesting-data/sdks/index)を使用してください。

アプリケーションコードではなくインフラストラクチャからデータを収集する場合は、以下を参照してください。

* [Kubernetesの監視](/ja/clickstack/observability/example-datasets/kubernetes): クラスターのログとメトリクスを収集し、Kubernetesダッシュボードで確認します。
* [ローカルのログとメトリクス](/ja/clickstack/observability/example-datasets/local-data): macOS または Linux 上のローカルファイルとシステムメトリクスを収集します。

UI をさらに活用するには、以下を参照してください。

* [検索](/ja/clickstack/observability/features/search): Lucene 形式の構文または SQL で、ログとトレースをクエリします。
* [セッションリプレイ](/ja/clickstack/observability/features/session-replay): 機能の概要、SDK のオプション、プライバシー制御について説明します。
* [サンプルデータセット](/ja/clickstack/observability/example-datasets): より充実したデータセットと、ガイド付きの調査を紹介します。
