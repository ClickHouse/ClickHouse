**以下のガイドは、[all-in-one image の手順](/ja/clickstack/getting-started/oss)または [Local Mode Only](/ja/clickstack/deployment/local-mode-only) を使用して Open Source ClickStack をデプロイし、初期ユーザーの作成を完了していることを前提としています。あるいは、ローカル環境でのセットアップをすべて省略し、このデータセットを使用している ClickStack のホストデモ [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) に接続することもできます。**

このガイドでは、公開 ClickHouse playground の [sql.clickhouse.com](https://sql.clickhouse.com) でホストされているサンプルデータセットを使用します。このデータセットには、ローカルの ClickStack デプロイメントから接続できます。

<Warning>
  **ClickHouse オブザーバビリティではサポートされていません**

  ClickHouse オブザーバビリティではリモートデータベースはサポートされていません。そのため、このデータセットもサポート対象外です。
</Warning>

このデータセットには、公式 OpenTelemetry (OTel) デモの ClickHouse 版から取得した約 40 時間分のデータが含まれています。データは毎晩再生され、タイムスタンプは現在の時間帯に合わせて調整されるため、ClickStack UI に統合されたログ、トレース、メトリクスを使ってシステムの挙動を確認できます。

<Info>
  **データの違いについて**

  このデータセットは毎日午前 0 時から再生されるため、デモを確認するタイミングによって表示される可視化は異なる場合があります。
</Info>

<div id="demo-scenario">
  ## デモシナリオ {#demo-scenario}
</div>

このデモでは、望遠鏡や関連アクセサリを販売するEC サイトで発生したインシデントを調査します。

カスタマーサポートチームから、ユーザーがチェックアウト時の支払いを完了できない問題が発生しているとの報告がありました。この問題は、調査のために Site Reliability Engineering (SRE) チームにエスカレーションされています。

SRE チームは ClickStack UI を使用してログ、トレース、メトリクスを分析し、問題の診断と解決を進めます。その後、セッションデータを確認し、導き出した結論が実際のユーザー行動と一致しているかどうかを確かめます。

    `payment` サービスにキャッシュの問題があり、それがリソース消費の増加につながっていることはわかっていますが、根本原因はまだ完全には特定できていません。

    結果テーブルビューに戻り、エラーを含む期間を選択してデータを絞り込みます。可能であれば、エラー発生の数時間前からその後までを選択してください (問題がまだ続いている可能性があります) 。

  <Step title="チャートで背景情報をより詳しく把握する" id="using-charts-for-more-context">
    ClickStack では、ログ、トレース、メトリクスに含まれる任意の数値をチャート化して、より詳しいコンテキストを把握できます。

    ここまでで、次のことが判明しました。

    * 問題は payment サービスにある
    * キャッシュが満杯になっている
    * これによりリソース消費量が増加した
    * この問題により、Visa での支払いが完了しなくなった (少なくとも、完了までに長い時間がかかるようになった)

    <br />

    左側のメニューから `Chart Explorer` を選択します。カードの種類ごとに支払い完了までの所要時間をチャート化するため、以下の値を入力します。

    * `Data Source`: `Traces`
    * `Metric`: `Maximum`
    * `SQL Column`: `Duration`
    * `Where`: `ServiceName: payment`
    * `Timespan`: `Last 1 day`

    <br />

    `▶️` をクリックすると、支払いのパフォーマンスが時間の経過とともにどのように低下したかを確認できます。

    <div className="ch-image-lg">
      <Frame>
        ![ステップ 18](/images/use-cases/observability/hyperdx-demo/step_18.webp)
      </Frame>
    </div>

    `Group By` を `SpanAttributes['app.payment.card_type']` に設定すると (`card` と入力するだけで自動補完されます) 、Mastercard と比べて Visa のトランザクションでサービスのパフォーマンスがどのように低下したかを確認できます。

    <div className="ch-image-lg">
      <Frame>
        ![ステップ 19](/images/use-cases/observability/hyperdx-demo/step_19.webp)
      </Frame>
    </div>

    なお、エラーが発生した後は、応答が `0s` で返されるようになります。
  </Step>

  <Step title="メトリクスの探索に関する補足情報" id="exploring-metrics-for-more-context">
    最後に、キャッシュサイズをメトリクスとしてプロットし、時間の経過に伴う推移を確認して、さらに多くのコンテキストを得ましょう。

    次の値を入力します。

    * `Data Source`: `Metrics`
    * `Metric`: `Maximum`
    * `SQL Column`: `visa_validation_cache.size (gauge)` (`cache` と入力するだけで自動補完されます)
    * `Where`: `ServiceName: payment`
    * `Group By`: `<empty>`

    キャッシュサイズが 4〜5 時間かけて増加し (おそらくソフトウェアのデプロイ後) 、最大サイズの `100,000` に達したことがわかります。`Sample Matched Events` を見ると、エラーの発生はキャッシュがこの上限に達したタイミングと相関しており、それ以降はサイズが `0` と記録され、応答も `0s` で返されていることがわかります。

    <div className="ch-image-lg">
      <Frame>
        ![ステップ 20](/images/use-cases/observability/hyperdx-demo/step_20.webp)
      </Frame>
    </div>

    まとめると、ログ、トレース、そして最後にメトリクスを調査した結果、次の結論が得られました。

    * 問題は payment サービスにある
    * おそらくデプロイに起因するサービスの挙動の変化により、visa キャッシュが 4〜5 時間かけて徐々に増大し、最大サイズの `100,000` に達した。
    * キャッシュサイズの増大に伴い、リソース消費量が増加した。おそらく実装に問題があったためと考えられる
    * キャッシュの増大につれて、Visa 決済のパフォーマンスが低下した
    * 最大サイズに達した時点で、キャッシュは決済を拒否し、自身のサイズを `0` と報告するようになった。
  </Step>

  <Step title="セッションの使用" id="using-sessions">
    セッションを使用すると、ユーザー体験を再生し、ユーザーの視点からエラーがどのように発生したかを視覚的に確認できます。通常は根本原因の診断に使うものではありませんが、カスタマーサポートに報告された問題の確認に役立ち、より詳しい調査の始点としても活用できます。

    ClickStack UI では、セッションがトレースやログと関連付けられているため、根本的な原因を全体的に把握できます。

    例えば、サポートチームから決済の問題に遭遇したユーザーのメールアドレス `Ronny.Windler@gmail.com` が共有された場合、ログやトレースを直接検索するよりも、そのユーザーのセッションから調査を始めた方が効果的なことがよくあります。

    左側のメニューから `Client Sessions` タブに移動し、データソースが `Sessions`、期間が `Last 1 day` に設定されていることを確認します。

    <div className="ch-image-lg">
      <Frame>
        ![ステップ 21](/images/use-cases/observability/hyperdx-demo/step_21.webp)
      </Frame>
    </div>

    `SpanAttributes.userEmail: Ronny.Windler` で検索し、対象顧客のセッションを見つけます。セッションを選択すると、左側にその顧客のセッションのブラウザイベントと関連するスパンが表示され、右側にはユーザーのブラウザ上の操作画面が再レンダリングされて表示されます。

    <div className="ch-image-lg">
      <Frame>
        ![ステップ 22](/images/use-cases/observability/hyperdx-demo/step_22.webp)
      </Frame>
    </div>
  </Step>
