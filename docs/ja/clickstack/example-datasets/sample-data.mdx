このガイドでは、サンプルデータセットを使って ClickStack Open Source を紹介します。

以下の例では、[オールインワンイメージ](/ja/clickstack/getting-started/oss)を使用して ClickStack Open Source を起動し、[インジェスト API key](/ja/clickstack/getting-started/oss#copy-ingestion-api-key) をコピー済みであることを前提としています。

<Steps>
  <Step title="ClickStack UI にアクセスします" id="navigate-to-the-hyperdx-ui">
    [http://localhost:8080](http://localhost:8080) にアクセスして、ClickStack UI を開きます。

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack UI](/images/use-cases/observability/hyperdx.webp)
      </Frame>
    </div>
  </Step>

  <Step title="インジェスト API keyをコピー" id="copy-ingestion-api-key">
    [`Team Settings`](http://localhost:8080/team) に移動し、`API Keys` セクションから `Ingestion API Key` をコピーします。この APIキーを使用することで、OpenTelemetry collector 経由のデータ取り込みを安全に行えます。

    <div className="ch-image-lg">
      <Frame>
        ![APIキーをコピー](/images/use-cases/observability/copy_api_key.webp)
      </Frame>
    </div>
  </Step>

  <Step title="サンプルデータをダウンロード" id="download-sample-data">
    UI にサンプルデータを投入するには、次のファイルをダウンロードしてください。

    [サンプルデータ](https://storage.googleapis.com/hyperdx/sample.tar.gz)

    ```shell
    # curl
    curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
    # or
    # wget https://storage.googleapis.com/hyperdx/sample.tar.gz
    ```

    このファイルには、当社が公開している [OpenTelemetry demo](https://github.com/ClickHouse/opentelemetry-demo) (マイクロサービスで構成されたシンプルな EC サイト) のログ、メトリクス、トレースのサンプルが含まれています。このファイルを任意のディレクトリにコピーしてください。
  </Step>

  <Step title="サンプルデータを読み込む" id="load-sample-data">
    このデータを読み込むには、デプロイ済みの OpenTelemetry (OTel) collector の HTTP エンドポイントにデータを送信するだけです。

    まず、先ほどコピーした APIキーをエクスポートします。

    ```shell
    # export API key
    export CLICKSTACK_API_KEY=<YOUR_INGESTION_API_KEY>
    ```

    次のコマンドを実行して、データを OTel collector に送信します。

    ```shell
    for filename in $(tar -tf sample.tar.gz); do
      endpoint="http://localhost:4318/v1/${filename%.json}"
      echo "loading ${filename%.json}"
      tar -xOf sample.tar.gz "$filename" | while read -r line; do
        printf '%s\n' "$line" | curl -s -o /dev/null -X POST "$endpoint" \
        -H "Content-Type: application/json" \
        -H "authorization: ${CLICKSTACK_API_KEY}" \
        --data-binary @-
      done
    done
    ```

    これは、OTLP のログ、トレース、メトリクスのソースが OTel collector にデータを送信する状況をシミュレートするものです。本番環境では、これらのソースは言語別クライアントや、別の OTel collector であることもあります。

    `Search` ビューに戻ると、データの読み込みが始まっていることを確認できます (データが表示されない場合は、時間範囲を `Last 1 hour` に変更してください) 。

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack UI の検索](/images/use-cases/observability/hyperdx-10.webp)
      </Frame>
    </div>

    データの読み込みには数分かかります。読み込みが完了してから次のステップに進んでください。
  </Step>

  <Step title="セッションを探索" id="explore-sessions">
    ユーザーから、商品の支払いで問題が発生しているという報告を受けたとします。ClickStack UI のセッションリプレイ機能を使用すると、ユーザーの操作状況を確認できます。

    左側のメニューから [`Client Sessions`](http://localhost:8080/sessions?from=1747312320000\&to=1747312920000\&sessionSource=l1324572572) を選択します。

    <div className="ch-image-lg">
      <Frame>
        ![セッション](/images/use-cases/observability/hyperdx-11.webp)
      </Frame>
    </div>

    このビューでは、EC ストアのフロントエンドのセッションを確認できます。ユーザーがチェックアウトに進み、購入を完了しようとするまで、セッションは Anonymous のままです。

    メールアドレスが関連付けられたセッションの一部にはエラーが紐づいており、トランザクションが失敗したという報告を裏付けている可能性があります。

    失敗が発生していて、メールアドレスが関連付けられたトレースを選択します。表示されるビューでは、ユーザーのセッションをリプレイして問題を確認できます。再生ボタンを押してセッションを再生します。

    <div className="ch-image-lg">
      <Frame>
        ![セッションリプレイ](/images/use-cases/observability/hyperdx-12.webp)
      </Frame>
    </div>

    リプレイでは、ユーザーがサイト内を移動し、カートに商品を追加する様子を確認できます。支払いを完了しようとしているセッション後半まで、適宜スキップしてください。

    <Tip>
      エラーはすべてタイムライン上に赤色で示されます。
    </Tip>

    ユーザーは注文を確定できませんでしたが、目立ったエラーは表示されていません。左パネルの下部までスクロールすると、ユーザーのブラウザで発生したネットワークおよびコンソールのイベントが表示されます。`/api/checkout` の呼び出し時に 500 エラーがスローされていることがわかります。

    <div className="ch-image-lg">
      <Frame>
        ![セッション内のエラー](/images/use-cases/observability/hyperdx-13.webp)
      </Frame>
    </div>

    この `500` エラーを選択します。`Overview` と `Column Values` のいずれを見ても、予期しないエラーによって `Internal Error` が発生していること以外、問題の原因はわかりません。
  </Step>

  <Step title="トレースを探索" id="explore-traces">
    `Trace` タブに移動すると、分散トレース全体を確認できます。

    <div className="ch-image-lg">
      <Frame>
        ![セッショントレース](/images/use-cases/observability/hyperdx-14.webp)
      </Frame>
    </div>

    トレースを下にスクロールすると、エラーの発生元である `checkout` サービスのスパンを確認できます。`Payment` サービスのスパンを選択します。

    <div className="ch-image-lg">
      <Frame>
        ![スパン](/images/use-cases/observability/hyperdx-15.webp)
      </Frame>
    </div>

    `Column Values` タブを選択し、下にスクロールします。この問題はキャッシュが満杯になっていることに関連しているとわかります。

    <div className="ch-image-lg">
      <Frame>
        ![カラム値](/images/use-cases/observability/hyperdx-16.webp)
      </Frame>
    </div>

    上にスクロールしてトレースに戻ると、先ほどの設定によってログがスパンと相関付けられていることがわかります。これらのログから、さらに詳しいコンテキストを把握できます。

    <div className="ch-image-lg">
      <Frame>
        ![関連付けられたログ](/images/use-cases/observability/hyperdx-17.webp)
      </Frame>
    </div>

    以上から、payment サービスでキャッシュが満杯になり、支払いが完了できなくなっていることが特定できました。
  </Step>

  <Step title="ログを探索" id="explore-logs">
    さらに詳しく調べるには、[`Search` ビュー](http://localhost:8080/search)に戻ります。

    ソースから `Logs` を選択し、`payment` サービスでフィルタします。

    <div className="ch-image-lg">
      <Frame>
        ![ログ](/images/use-cases/observability/hyperdx-18.webp)
      </Frame>
    </div>

    この問題は発生して間もないものの、影響を受けた決済の件数が多いことがわかります。さらに、Visa 決済に関連するキャッシュが問題の原因となっているようです。
  </Step>

  <Step title="チャートのメトリクス" id="chart-metrics">
    コードにエラーが混入したことは明らかですが、メトリクスを使ってキャッシュサイズも確認してみましょう。`Chart Explorer` ビューに移動します。

    データソースとして `Metrics` を選択します。チャートビルダーで `visa_validation_cache.size (Gauge)` の `Maximum` をプロットするように設定し、実行ボタンを押します。キャッシュが最大サイズに達するまで増加し続け、その後エラーが発生するようになったことがはっきりとわかります。

    <div className="ch-image-lg">
      <Frame>
        ![メトリクス](/images/use-cases/observability/hyperdx-19.webp)
      </Frame>
    </div>
  </Step>
</Steps>
