## アドホックダッシュボードフィルタによるテーブルと時系列チャートのクリックフィルタ {#click-to-filter-tables-time-charts}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

アドホックダッシュボードフィルタが、テーブルタイルと時系列チャートでのクリックフィルタに対応しました。これまでこの操作は検索タイルでしか行えませんでした。今後は、クエリがビルダー、生のSQL、PromQL のいずれを使用している場合でも、テーブル、折れ線グラフ、積み上げ棒グラフ、積み上げ折れ線グラフの値をクリックしてフィルタ条件を追加できます。

テーブルでは、検索テーブルと同じように、フィルタ可能なセルにカーソルを合わせて「含める (include)」または「除外 (exclude)」を選択します。group-by カラムはフィルタ可能ですが、集約カラムはフィルタできません。他のタイルが同じ集約を使用している可能性は低いためです。また、条件には別名ではなく元の式が使用されるため、複数のタイルにまたがって適用できます。

group-by カラムの識別方法はクエリの種類によって異なります。

* ビルダーのテーブルでは、結果メタデータ内の各カラムの位置を使用します。ClickHouse が別名のない式を正規化するためです。
* 生のSQL クエリでは、マクロと変数を置換したうえで `node-sql-parser` でパースします。`GROUP BY` がカラムを別名、名前、正規化された式、または位置 (`GROUP BY 2` など) で参照している場合、そのカラムはフィルタ可能になります。
* PromQL のテーブルでは、時刻カラムを除き、数値以外のカラムをラベルとして扱います。

なお、`DateTime`、`Map`、`Array` カラムでのクリックフィルタにはまだ対応していません。これらには専用のロジックが必要です。

生のSQL チャートには、まだいくつか不完全な点があります。`node-sql-parser` は ClickHouse の方言を完全にはサポートしておらず、パラメトリック関数、`ARRAY JOIN`、一部の結合構文などには対応していません。解析に失敗した場合、またはクエリに `GROUP BY` がない場合、`GROUP BY ALL` を使用している場合、`SELECT *` を含む場合は、`String` カラムをフィルタ可能として扱う方式にフォールバックします。

このフォールバックは完全ではありません。クリックできないカラムが生じたり、他のタイルに存在しないフィルタキーが追加されたりする場合があります。CTE 由来のカラムも、他のタイルでは定義されていない可能性があるため、同様の問題が起こり得ます。その場合は該当する条件を削除してください。今後は、完全な ClickHouse SQL パーサーを導入してこの点を改善したいと考えています。

時系列チャートでは、系列のツールチップから、その系列のすべてのラベルでワンクリックでフィルタできるようになりました。たとえばチャートがサービス名と重大度でグループ化されている場合、系列をクリックすると両方の条件が追加されます。**Exclude** はラベルが 1 つの場合にのみ使用できます。たとえば `service = 'checkout'` と `severity = 'error'` を個別に除外すると、checkout のエラーだけでなく、checkout のすべてのログと全サービスのすべてのエラーが非表示になってしまうためです。PromQL の折れ線グラフでは、Prometheus から返されたラベルのうち `__name__` 以外を使用します。

## 線の補間方法の表示設定 {#line-interpolation-display-setting}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=149" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

表示設定に **Smooth**、**Linear**、**Step** の補間オプションが追加され、折れ線グラフで点をどのように結ぶかを選択できるようになりました。これまで、通常の折れ線グラフでは常に滑らかな曲線が、積み上げ折れ線グラフでは直線が使用されていました。これらは引き続きデフォルトとして使用されますが、データに合わせて、あるいはチャート間の見た目をそろえるために変更できるようになりました。

この設定は、チャートエディタ、外部 API、MCP で利用できます。また、エディタで積み上げ棒グラフまたは積み上げ折れ線グラフに切り替えても、保存済みタイルの表示形式が更新されないバグも修正しました。

## 検索ページのヒストグラムでのグループ化 {#search-page-histogram-group-by}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=194" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

検索ヒストグラムを任意のフィールドでグループ化できるようになりました。これまでは、ログソースに応じて常に重大度またはステータスコードで分割されていました。[@elizabetdev](https://github.com/elizabetdev) のデザインに基づく新しい **グループ化** コントロールでは、フィルタサイドバーと同じリストから複数のフィールドや Map のキーを選択できます。

フィールドを選択して適用するとヒストグラムが再グループ化され、各グループを示す凡例が表示されます。ログソースのデフォルトにリセットすることも、グループ化を解除して単純なイベント数を表示することもできます。目的のフィールドがリストにない場合や、計算値でグループ化したい場合は、SQL を直接入力できます。

ログソースを切り替えても、互換性のあるグループ化は選択されたまま維持されます。たとえば、両方のログソースで利用できる `ServiceName` フィールドや Map のキーはそのまま引き継がれます。互換性がない場合、ヒストグラムは新しいログソースのデフォルトにリセットされます。この動作は、ログソース切り替え時に互換性のあるフィルタを保持する仕組みと同じロジックを使用しています。

その後、[@elizabetdev](https://github.com/elizabetdev) による追加の変更で、このコントロールは共通の分割ボタンに移行され、ラベルと選択中の値が横並びで表示されるようになりました。

**関連 プルリクエスト:** [#3407](https://github.com/hyperdxio/hyperdx/pull/3407) 検索ページのヒストグラムにグループ化を追加、[#3430](https://github.com/hyperdxio/hyperdx/pull/3430) グループ化 分割ボタンを共通化

## ダッシュボードタイルの説明 {#descriptions-on-dashboard-tiles}

*デモ担当者: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=318" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

ダッシュボードタイルに説明を追加できるようになりました。チャートが何を示しているのか、どのように読み取ればよいのかを説明する際に便利です。説明は、タイル名の横にある情報アイコンにカーソルを合わせると表示されます。説明のないタイルの見た目はこれまでと変わりません。

外部ダッシュボード API に説明のサポートを追加してくれた [@felipe-carvalho12](https://github.com/felipe-carvalho12) に感謝します。これにより、ダッシュボードをコードとして管理する場合にも説明を設定できます。また、タイルエディタの **Chart Name** の横に **Description** 入力欄を追加しました。説明の上限は 1,024 文字です。

続く変更では、説明の格納場所をタイルのチャート設定内に移し、`name` と並べて保持するようにしたため、エディタで他の設定と一緒に保存されるようになりました。あわせて、外部 API から `series` を指定して送信したタイルで説明が失われるバグも修正しました。

## ユーザー設定でのタイムゾーン選択 {#time-zone-selection}

*デモ担当者: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=358" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

ClickStack でタイムゾーンを自由に選択できるようになりました。これまでは、ユーザー設定の **Use UTC time** スイッチで、UTC かブラウザのローカルタイムゾーンのどちらかしか選べませんでした。このスイッチは検索可能なセレクターに置き換わり、上部に **Local** と **UTC** が固定表示され、その下にブラウザがサポートするすべてのタイムゾーンが並びます。各タイムゾーンには現在のオフセットが表示され、検索も可能です。たとえば「los angeles」と入力すると `America/Los_Angeles` が見つかります。

選択したタイムゾーンは検索ページとダッシュボードに適用されます。サイドバーのバッジとタイムスタンプ列の列ヘッダーには、`PDT` のような短縮名が表示されます。米国式の略称がないタイムゾーンの場合は、`UTC+9` のような UTC オフセットが表示されます。ClickStack は IANA 名を保存し、ブラウザがそれを認識できない場合はローカル時刻にフォールバックします。

ただし、1 回の調査のためだけにタイムゾーンを切り替えたい場合、ユーザー設定から変更するのはまだ少し手間がかかります。今回の変更は、検索単位およびダッシュボード単位のオーバーライドに向けた土台となるものです。これにより、自分のデフォルトはローカルまたは UTC のままで、顧客のデータをその顧客のタイムゾーンで確認できるようになる予定です。なお、これらのオーバーライドはまだ実装されていません。

## MCP サービスヘルスツール {#mcp-service-health-tool}

*デモ担当者: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=463" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

MCPサーバーに `clickstack_service_health` ツールが追加されました。エージェントが書く生のSQLの多くがサービスのヘルスチェック用であることがわかったため、その用途に特化したツールを用意しました。これまでエージェントは、複数の `clickstack_table` および `clickstack_timeseries` 呼び出しの結果をつなぎ合わせたうえで、どの変化に対応が必要かを判断しなければなりませんでした。

このツールは、トレースソース内の各サービスについて、スループット、エラー率、p50/p95/p99 レイテンシ、上位のエラーグループを、過去のウィンドウと比較して返します。デフォルトの比較対象は前日の同じ時間帯ですが、エージェントは直前の 15 分間や前週の同じ時間帯など、別のウィンドウを選ぶこともできます。対応の必要性が高いサービスほど上位に表示され、`critical`、`degraded`、`healthy` のいずれかのステータスと、その理由を示す `error_rate_up`、`latency_up`、`traffic_drop` などのフラグが付与されます。固定のしきい値を用いるため、通常の変動がリグレッションとして誤検出されることはありません。

新規のエラーグループや増加中のエラーグループが先頭に表示され、初回検出時刻と最終検出時刻から、継続中のイシューなのか、すでに収まったバーストなのかを見分けやすくなっています。比較ウィンドウでトラフィックがなかった操作はロールアウトの可能性が高いものとしてマークされ、そのエラーは新規としてカウントされません。デフォルトではサーバースパンのみをカウントしますが、`spanKind: "all"` を指定するとすべてのスパンが対象になります。保持期間外などの理由で比較ウィンドウにデータがない場合は、さらに前の期間を試し、それでもデータがなければ比較なしのレポートにフォールバックします。

## MCP 品質スコアの改善 {#mcp-quality-score-improvements}

*デモ担当者: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=537" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

ClickStack の MCPサーバーのチェックには [Manufact](https://manufact.com) の MCP Quality Score を使用しています。MCPサーバーを運用している方は、ぜひ試してみてください。3 つの変更により、スコアは 80 から 94 に向上しました。

サーバーは、既存の `name` と `version` に加えて、タイトル、説明、Web サイトの URL、アイコンを `serverInfo` に含めるようになりました。アイコンにはアプリのロゴ SVG を使用しています。アイコンの URL は絶対 URL である必要があるため、`FRONTEND_URL` が設定されていない場合は省略されます。

すべてのツールで、4 つの動作ヒント (`readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint`) をすべて宣言するようになりました。以前は、各ツールで 1 つしか宣言していませんでした。読み取り専用ツール、upsert ツール、そして `delete_*` や `patch_dashboard` などの冪等な破壊的ツール向けに、3 つのプリセットを用意しています。upsert は、`id` を指定せずに呼び出すと毎回新しいオブジェクトが作成されるため、冪等ではありません。ツールがアクセスするのはチーム自身のメタデータと ClickHouse のデータのみであるため、`openWorldHint` はすべて `false` としています。また、4 つのヒントはすべて登録用の型で必須になったため、1 つでも欠けているとコンパイルエラーになります。

ツールの説明も整理しました。すべての入力に説明を付け、Claude Code の切り捨て上限である 2048 バイトを超えていた 4 つのツールの説明を短縮しました。たとえば、`clickstack_event_deltas` は 3318 バイトから 1796 バイトになりました。スキーマの制約を繰り返しているだけの記述は削除し、ID フィールドにはその ID を提供するツールを明記し、保存系ツールの副作用もドキュメント化しました。たとえば、新しい設定でタイルのアラートをサポートできない場合に、`patch_dashboard` がそのアラートを削除することも記載しています。

残りの 6 点は `outputSchema` に関するものです。現在、ツールは JSON を `structuredContent` ではなくテキストとして返しているため、この対応は今後の課題とします。

## MCPサーバーでのSQLクエリのバッチ実行 {#mcp-batch-sql-queries}

*デモ担当者: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=588" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

エージェントが生のSQLを必要とする場合、`clickstack_sql` で複数のクエリを1回の呼び出しでまとめて実行できるようになりました。クエリごとにラウンドトリップを行う必要はありません。従来どおり単一の `sql` クエリを渡すことも、最大10個のエントリを含む `queries` 配列を渡すこともできます。各エントリは独自の `sql` と、任意の `id`、`connectionId`、`sourceId` を持ちます。`startTime` と `endTime` はすべてのクエリで共通です。

クエリは5件ずつ並列に実行され、バッチ全体に60秒のデッドラインが設定されます。時間切れの時点でキューに残っているクエリは ClickHouse に送信されません。結果は入力順に、`ok`、`error`、`timeout` のいずれかのステータス付きで返されるため、1つのクエリが失敗してもバッチ全体が失敗することはありません。`isError` は、すべてのクエリが失敗した場合にのみ設定されます。応答サイズの上限はバッチ全体で100k文字で、既存の単一クエリの上限に合わせて、クエリあたり最大50kに制限されます。

呼び出しには `sql` または `queries` のどちらか一方のみを含める必要があり、両方を指定することはできません。`sql` が常に必須ではなくなったため、この検証はツールの必須リストではなくハンドラーで行います。

MCP のタスクも検討しましたが、現時点では見送っています。SDK の API が実験的であるうえ、`2026-07-28` の spec ではタスクが別の拡張機能に移されており、サーバー SDK がまだこれに対応していないためです。この変更はまだマージされていません。

**関連 プルリクエスト:** [#3421](https://github.com/hyperdxio/hyperdx/pull/3421) 複数の clickstack&#95;sql クエリを並列に実行 (オープン)
