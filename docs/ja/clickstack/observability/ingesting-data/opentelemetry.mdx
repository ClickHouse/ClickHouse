    OpenTelemetry SDKs またはお使いの環境内の collector を使用して、ログ、メトリクス、トレースを ClickHouse オブザーバビリティに送信できます。このサービスにはマネージドなインジェスト用 collector が含まれており、OTLP 経由でテレメトリーを受信して ClickHouse Cloud に書き込みます。

## 接続情報を取得する {#sending-otel-data}

    サービスを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。**OTLP HTTPエンドポイント** と **APIキー** をコピーしてください。**環境変数** タブと **Collector 設定** タブには、お使いのサービス向けの設定が表示されます。

    <div className="ch-image-lg">
      <Frame>
        ![マスクされた OTLP HTTPエンドポイントと APIキーが表示されたマネージドテレメトリー画面](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    マネージドテレメトリーに表示されているポートを含め、完全な HTTPS エンドポイントを使用してください。ベースの OTLP HTTP エンドポイントを指定する場合は、`/v1/logs`、`/v1/traces`、`/v1/metrics` などのシグナルパスを省略します。これらのパスはエクスポーターによって自動的に追記されます。

## アプリケーションから直接送信する {#sending-data-to-collector-managed}

    アプリケーションの言語に対応した OpenTelemetry のインストルメンテーションと OTLP HTTP エクスポーターをインストールし、初期化します。環境変数による設定に対応した SDK を使用する場合は、アプリケーションを起動する前に、アプリケーションの環境に以下の値を設定します。

    ```shell
    export OTEL_SERVICE_NAME='my-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    エンドポイントを Managed Telemetry に表示される値と完全に一致するものに、`YOUR_API_KEY` をサービスのAPIキーに置き換えてください。`%20` は、ヘッダー用の環境変数で `Bearer` とキーの間のスペースをエンコードしたものです。

    環境変数のサポート状況は SDK によって異なります。SDK でコード内での設定が必要な場合は、同じ HTTPSエンドポイント、OTLP HTTP プロトコル、および値が `Bearer YOUR_API_KEY` の `authorization` ヘッダーを指定してください。言語ごとのサポート状況やシグナル固有のオーバーライドについては、[OpenTelemetry エクスポーター設定リファレンス](https://opentelemetry.io/docs/languages/sdk-configuration/otlp-exporter/)を参照してください。

    これらの設定はエクスポートを構成するだけです。テレメトリーを生成するには、別途アプリケーションのインストルメンテーションが必要です。ブラウザのセッション記録については、[セッションリプレイガイド](/ja/clickstack/observability/features/session-replay)を参照してください。

## collector からデータを転送する {#forward-from-a-collector}

    OpenTelemetry collector ですでにテレメトリーを収集している場合は、OTLP HTTP エクスポーターを設定して、マネージドエンドポイントへ転送します。データの収集と処理には、既存のレシーバーとプロセッサをそのまま使用できます。

    collector のランタイム環境で、以下の環境変数を設定します。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_API_KEY='YOUR_API_KEY'
    ```

    両方のプレースホルダーを、マネージドテレメトリーに表示される値に置き換えてください。次のエクスポーターをコレクター設定に追加します。

    ```yaml
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "Bearer ${env:OTEL_EXPORTER_OTLP_API_KEY}"
    ```

    `service.pipelines` 配下で、転送したいログ、メトリクス、トレースの各パイプラインの `exporters` リストに `otlp_http/observability` を追加します。これを既存の設定にマージした後、collector を再起動または再デプロイして変更を反映してください。

    この例では、現在のエクスポーター名である `otlp_http` を使用しています。古いリリースの collector では `otlphttp` が使われている場合があるため、お使いのディストリビューションがサポートしている名前を使用してください。設定オプションについては、[OTLP HTTP エクスポーターのドキュメント](https://github.com/open-telemetry/opentelemetry-collector/tree/main/exporter/otlphttpexporter)を参照してください。

    ホストログとメトリクスを収集する完全な例については、[ローカルシステムのログとメトリクス](/ja/clickstack/observability/example-datasets/local-data)を参照してください。

## インジェストの確認 {#verify-ingestion}

    アプリケーションでテレメトリーを生成してから、ClickHouse オブザーバビリティで[検索](/ja/clickstack/observability/features/search)を開きます。**Logs** または **Traces** を選択し、新しいイベントが含まれる時間範囲を指定して、サービス名で検索します。

    データが表示されない場合は、SDK または collector のログにエクスポートエラーが出ていないか確認してください。エンドポイント、認証ヘッダー、プロトコルが正しいこと、およびアプリケーションまたは collector からマネージドエンドポイントに到達できることを確認します。また、ベースのエンドポイントやヘッダーをオーバーライドするシグナル固有のエクスポーター設定がないかも確認してください。

    マネージドテレメトリーの **Send a Test Log** を使用すると、サンプルログをサービスに送信できます。アプリケーションのインストルメンテーションとエクスポート設定が正しいかどうかは、アプリケーションのテレメトリーを別途確認して検証してください。

  <Tab title="セルフマネージド" id="self-managed">
    Self-managed ClickHouse Observability では、**OpenTelemetry (OTel) collector** がログ、メトリクス、トレース、session データを受信し、ClickHouse Cloud に書き込みます。collector には公式の [ClickStack ディストリビューション](#installing-otel-collector-managed-self-configured) の使用を推奨します。

    [言語 SDKs](/ja/clickstack/observability/ingesting-data/sdks)、またはインフラストラクチャのログやメトリクスを収集するエージェントから、この collector にデータを送信します。 たとえば、[エージェントの役割](/ja/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)で動作する OpenTelemetry コレクター、[Fluentd](https://www.fluentd.org/)、[Vector](https://vector.dev/) などが利用できます。 コレクターを一元管理したい場合は、[Bindplane](/ja/clickstack/observability/integration-partners/bindplane) を利用できます。Bindplane は ClickHouse オブザーバビリティの宛先に加え、テレメトリーの収集、処理、ルーティングのためのツールを提供しています。

## OpenTelemetry データの送信 {#sending-otel-data-self-configured}

### collector を ClickHouse Cloud に接続する {#installing-otel-collector-managed-self-configured}

    collector を [ゲートウェイロール](/ja/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) として設定し、HTTP または gRPC 経由で OTLP を受信して ClickHouse Cloud に転送するようにします。

    <Info>
      **ClickStack OpenTelemetryコレクターの使用を推奨します**

      ClickStack ディストリビューションは、ClickHouse オブザーバビリティに対応した処理とスキーマを提供します。デフォルトのスキーマを使用すると、ログソースの自動検出と事前設定済みのカラムマッピングが利用できます。
    </Info>

    ClickHouse Cloud でサービスを開き、[接続情報を取得](/ja/products/cloud/guides/sql-console/connection-details)します。次に、ClickStack ディストリビューションの collector のランタイム環境で、以下の環境変数を設定します。

    ```shell
    CLICKHOUSE_ENDPOINT="https://<host>:8443"
    CLICKHOUSE_USER="<ingestion-user>"
    CLICKHOUSE_PASSWORD="<ingestion-password>"
    ```

    `CLICKHOUSE_ENDPOINT` にはサービスの HTTPS データベースエンドポイントを指定し、[インジェスト専用ユーザー](/ja/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)の認証情報を使用します。設定を反映するには、collector を再起動または再デプロイしてください。collector は OTLP 経由でテレメトリーを受信し、ClickHouse Cloud サービスに書き込みます。

    別の collector ディストリビューションを使用する場合は、その ClickHouse exporter に同じエンドポイントと認証情報を設定してください。設定例については、[設定の変更](/ja/clickstack/self-configured/ingesting-data/collector#modifying-otel-collector-configuration-managed-self-configured)を参照してください。

    インストール手順については、[collector のデプロイ](/ja/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)を参照してください。 本番環境のトラフィックを送信する前に、[collector を保護](/ja/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)してください。 `OTLP_AUTH_TOKEN` を有効化する場合は、SDK と転送用コレクターがそのトークンを `authorization` ヘッダーで送信するように設定してください。

### collector にデータを送信する {#sending-data-to-collector-managed-self-configured}

    デフォルトの OTLP ポートを使用してローカルで collector を実行している場合は、OpenTelemetry インストルメンテーションの送信先を以下のエンドポイントに設定してください。アプリケーションやエージェントが別のホストまたは別のコンテナで動作している場合は、`localhost` を、その環境から接続可能な collector のホスト名に置き換えてください。

    * **HTTP (OTLP):** `http://localhost:4318`
    * **gRPC (OTLP):** `localhost:4317`

    環境変数による設定に対応した[言語 SDKs](/ja/clickstack/observability/ingesting-data/sdks)を使用する場合は、計装済みアプリケーションを起動する前にエンドポイントとプロトコルを設定してください。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    ```

    collector で認証が必要な場合は、`OTEL_EXPORTER_OTLP_HEADERS="authorization=<collector-token>"` も設定し、`<collector-token>` を collector の `OTLP_AUTH_TOKEN` の値に置き換えてください。完全マネージド型のエンドポイントで使用される `Bearer` プレフィックスは付けないでください。これらの設定はエクスポートを設定するためのものです。テレメトリーを生成するには、別途アプリケーションのインストルメンテーションが必要です。

    [OTel collector の contrib ディストリビューション](https://github.com/open-telemetry/opentelemetry-collector-contrib)を使用するエージェントは、OTLP 経由でログを転送できます。以下の例では、こちらの[構造化ログファイル](https://datasets-documentation.s3.eu-west-3.amazonaws.com/http_logs/access-structured.log.gz)を読み取ります。エージェントを起動する前に、このファイルをダウンロードし、`include` で指定したパスに伸長しておいてください。ゲートウェイで認証が必要な場合は、ゲートウェイのトークンを含む `authorization` ヘッダーをエージェントのエクスポーターに追加してください。

    ```yaml
    # clickhouse-agent-config.yaml
    receivers:
      filelog:
        include:
          - /opt/data/logs/access-structured.log
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.time_local
              layout: '%Y-%m-%d %H:%M:%S'
    exporters:
      # HTTP setup
      otlphttp/hdx:
        endpoint: 'http://localhost:4318'
        compression: gzip

      # gRPC setup (alternative)
      otlp/hdx:
        endpoint: 'localhost:4317'
        compression: gzip
    processors:
      batch:
        timeout: 5s
        send_batch_size: 10000
    service:
      telemetry:
        metrics:
          address: 0.0.0.0:9888 # Modified as 2 collectors running on same host
      pipelines:
        logs:
          receivers: [filelog]
          processors: [batch]
          exporters: [otlphttp/hdx]
    ```
