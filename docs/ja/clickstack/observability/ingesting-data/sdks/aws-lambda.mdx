非同期ハンドラーを使用する Node.js 関数では、ClickStack Node.js SDK を使用してください。その他のランタイムやコールバックベースのハンドラーでは、以下で説明する OpenTelemetry Lambda レイヤーを使用してください。

## Node.js の非同期ハンドラー {#nodejs-async-handlers}

SDK の要件である Node.js 22.15 以上を満たす Lambda Node.js ランタイムを使用してください。SDK をインストールし、デプロイパッケージに含めます。

```shell
npm install @clickhouse/clickstack-node
```

ハンドラーが読み込まれる前に SDK を初期化し、サービス名を設定するには、以下の Lambda 環境変数を設定します:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

呼び出しが完了する前にバッファリングされたテレメトリーがエクスポートされるよう、非同期ハンドラーを `withFlush` でラップします。

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

関数のハンドラーを `index.handler` に設定します。関数をバンドルする場合は、SDK と計装済みの依存関係をバンドルに含めず外部として扱い、デプロイパッケージに同梱してください。この構成では、自動計装用の Lambda レイヤーを併用しないでください。

Lambda 関数の環境設定に、以下の宛先用の変数を設定します。エンドポイントには関数から接続可能である必要があります。SDK は呼び出しのデッドラインより前に flush を完了します。なお、コールバックベースのハンドラーは `withFlush` ではサポートされていません。

### 宛先を設定する {#configure-destination}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版" />

    サービスで **チーム設定 → Data → Managed Telemetry** を開き、**OTLP HTTPエンドポイント** と **APIキー** をコピーします。エンドポイントには、ポート番号を含む完全なHTTPSエンドポイントを指定してください:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="セルフマネージド">
    collector の OTLP HTTPエンドポイントとインジェストキーを使用します。collector で TLS を設定していない場合は、`https://` の代わりに `http://` を使用してください。collector のセットアップ方法については、[OpenTelemetry によるデータの取り込み](/ja/clickstack/observability/ingesting-data/opentelemetry#self-managed)を参照してください。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## その他のランタイムとハンドラー {#other-runtimes-and-handlers}

公式の [Lambda 自動計装の手順](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/) に従って、使用するランタイム、アーキテクチャ、AWSリージョンに対応するレイヤーを選択し、インストルメンテーションラッパーを設定してください。

[OpenTelemetry Collector Lambda レイヤー](https://opentelemetry.io/docs/platforms/faas/lambda-collector/) を追加して設定します。アップストリームのドキュメントに記載されているとおり、アプリケーションの SDK エクスポーターの送信先はローカルの Collector のままにしておいてください。Collector からの送信接続は、以下の手順で設定します。

### Lambda Collector の宛先を設定する {#configure-lambda-collector-destination}

Lambda 関数の環境変数に `CLICKHOUSE_OTLP_ENDPOINT` と `CLICKHOUSE_INGESTION_API_KEY` を設定し、Collector の設定に次のエクスポーターを追加します。

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版" />

    サービスで **チーム設定 → Data → Managed Telemetry** を開き、**OTLP HTTP エンドポイント** と **APIキー** をコピーします。`CLICKHOUSE_OTLP_ENDPOINT` にはポート番号を含む完全な HTTPS エンドポイントを、`CLICKHOUSE_INGESTION_API_KEY` にはコピーしたキーを設定します。

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "Bearer ${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>

  <Tab title="セルフマネージド">
    `CLICKHOUSE_OTLP_ENDPOINT` には collector の OTLP HTTP エンドポイントを、`CLICKHOUSE_INGESTION_API_KEY` にはその collector のインジェストキーを設定します。このエンドポイントには Lambda 関数から接続可能である必要があります。宛先となる collector のセットアップについては、[OpenTelemetry によるデータの取り込み](/ja/clickstack/observability/ingesting-data/opentelemetry#self-managed)を参照してください。

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>
</Tabs>

送信対象とする各シグナルのパイプラインで、`exporters` リストに `otlphttp/clickhouse` を指定します。たとえば、アップストリームの `otlp` receiver を使用する場合は次のようになります。

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

これらの設定を Collector の設定にマージしてください。その際、既存の receiver とプロセッサーの設定はそのまま残します。続いて、アップストリームの Collector セットアップ手順に従い、設定ファイルを関数と一緒にパッケージ化して、`OPENTELEMETRY_COLLECTOR_CONFIG_URI` にその配置場所 (例: `/var/task/collector.yaml`) を設定してください。

## インジェストの確認 {#verify-ingestion}

関数をデプロイして呼び出します。ClickHouse オブザーバビリティで直近の時間範囲を選択し、Traces で関数のサービス名を探します。インストルメンテーションがログやメトリクスも出力する場合は、Logs と Metrics も確認してください。パイプラインを追加しただけでは、これらのシグナルの収集は自動的に有効になりません。

レイヤーの設定やトラブルシューティングについては、[OpenTelemetry Lambda のドキュメント](https://github.com/open-telemetry/opentelemetry-lambda)を参照してください。
