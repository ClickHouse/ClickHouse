ClickStack Node.js SDK は、アップストリームの OpenTelemetry SDK と自動計装をベースに構築されており、コンソール出力のキャプチャ、捕捉されない例外のキャプチャ、シャットダウン時のテレメトリーのフラッシュといった機能が追加されています。すでに OpenTelemetry を設定済みのアプリケーションでは、既存の SDK をそのまま使用したまま、[OTLP エクスポートを設定](/ja/clickstack/observability/ingesting-data/opentelemetry)できます。

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## インストール {#install}

Node.js **22.15 以降**を使用してください。アプリケーションに SDK をインストールします。

```shell
npm install @clickhouse/clickstack-node
```

このパッケージは ES モジュールと CommonJS の両方に対応しています。peer dependency である `@opentelemetry/api` は npm によって自動的にインストールされます。アプリケーションからこのパッケージを直接インポートする場合は、`@opentelemetry/api@~1.9.1` をインストールしてください。バージョン 1.10 は、この SDK がサポートするバージョン範囲外です。

## 宛先を設定する {#configure-destination}

アプリケーションを起動する前に環境変数を設定します。OTLP HTTPエンドポイントには、`/v1/traces`、`/v1/logs`、`/v1/metrics` を含まないベース URL を指定してください。これらのパスはエクスポーターによって追記されます。

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    **チーム設定 → Data → マネージドテレメトリー** を開き、**OTLP HTTPエンドポイント** と **APIキー** をコピーします。サービスに表示されている HTTPSエンドポイントとポートをそのまま使用してください。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```
  </Tab>

  <Tab title="セルフマネージド">
    collector の OTLP HTTPエンドポイントと、その OTLP レシーバーに設定済みのインジェスト key を使用します。collector のセットアップについては、[OpenTelemetry を使用したデータ取り込み](/ja/clickstack/observability/ingesting-data/opentelemetry#self-managed) を参照してください。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```

    このエンドポイントは、アプリケーションと collector が同じホスト上で実行されていることを前提としています。collector を別の場所で実行している場合は、アプリケーションから接続可能なアドレスに置き換えてください。
  </Tab>
</Tabs>

## アプリケーションを起動する {#start-application}

アプリケーションがインストルメント対象のライブラリをインポートする前に、SDK をプリロードしてください。

```shell
node --import @clickhouse/clickstack-node/register server.js
```

`server.js` は、お使いのアプリケーションのエントリーファイルに置き換えてください。このコマンドは、アプリケーションの起動前に SDK を読み込み、上記で設定した環境変数を使用します。CommonJS と ES モジュールのどちらのアプリケーションにも対応しています。

これで[インジェストを確認](#verify-ingestion)できます。以下の代替手段は、npm スクリプト経由で起動する場合や、コード内で SDK を設定する場合にのみ必要です。

<Accordion title="その他の起動方法">
  `--require` もサポートされています。`NODE_OPTIONS` を使用する場合は、ビルドツールが独自のテレメトリーパイプラインを開始しないよう、適用範囲をアプリケーションのコマンドに限定してください。

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  または、インストルメンテーションモジュールを作成してプリロードする方法もあります。この場合も、エクスポートの設定には前のセクションの環境変数が使用されます。

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  このガードにより、Pino の transport worker などのワーカースレッドが SDK インスタンスを追加で起動するのを防ぎます。

  パッケージの登録用エントリーポイントと独自のインストルメンテーションモジュールは、どちらか一方のみを使用してください。アプリケーション内で SDK を二重に初期化しないでください。静的な ES モジュールのインポートはモジュール本体より先に実行されるため、同じファイル内で `init` の呼び出しを静的インポートより上に記述しても、初期化の順序は保証されません。
</Accordion>

## インジェストを確認する {#verify-ingestion}

アプリケーションを起動し、計装済みのルートにリクエストを送信して、コンソールメッセージを出力します。ClickHouse オブザーバビリティで直近の時間範囲を選択し、ログまたはトレースで `my-node-app` を検索します。メトリクスは、エクスポート間隔が経過してから確認してください。

データが表示されない場合は、stderr に出力される SDK の診断情報、エンドポイントと認証の設定、ネットワーク接続を確認してください。また、インストルメンテーションがアプリケーションの依存関係より先に読み込まれるようにしてください。バンドラーがライブラリをインライン展開すると、そのライブラリは自動計装されません。SDK と計装対象の依存関係は external として扱い、バンドルに含めないでください。TypeScript、ES モジュール、フレームワーク、バンドラーの要件については、[SDK の互換性](https://github.com/ClickHouse/clickstack-node#compatibility)を参照してください。

## インストルメンテーションの設定 {#configure-instrumentation}

標準の OpenTelemetry 環境変数は、サンプリング、バッチ処理、エクスポーター、リソース属性に関するものも含め、アップストリームと同じ意味で使用できます。例:

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

コンソール出力はデフォルトで収集されます。HTTP ボディの収集はデフォルトで無効になっています。有効化するのは、アプリケーションが扱うデータの性質上問題がない場合に限ってください。

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

キャプチャされたボディには、個人データや認証情報が含まれる場合があります。SDK によるマスキングはベストエフォートであるため、必要に応じて collector 側のマスキングも引き続き使用してください。ヘッダーのキャプチャ、ボディのサイズ制限、サニタイズについては、[SDK のプライバシーオプション](https://github.com/ClickHouse/clickstack-node#privacy)を参照してください。

### 初期化オプション {#initialization-options}

インストルメンテーションモジュールで、以下のオプションを `init` に渡します。

| オプション                        | デフォルト                                | 用途                                                                                                      |
| ---------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `endpoint`                   | `http://localhost:4318`              | OTLP HTTP のベース URL。`OTEL_EXPORTER_OTLP_ENDPOINT` でオーバーライドされます                                           |
| `serviceName`                | `unknown_service:` の後に実行可能ファイル名を続けた値 | サービス名。`OTEL_SERVICE_NAME` または `OTEL_RESOURCE_ATTRIBUTES` 内の `service.name` でオーバーライドされます                 |
| `environment`                | 未設定                                  | `deployment.environment.name` を設定します。`OTEL_RESOURCE_ATTRIBUTES` 内に同じキーがある場合はそちらが優先されます                  |
| `apiKey`                     | 未設定                                  | 認証ヘッダーの値。`OTEL_EXPORTER_OTLP_HEADERS` がすでに空でない場合は、無関係なヘッダーしか含まれていなくても無視されます                             |
| `httpBodyCapture`            | `false`                              | HTTP ボディをキャプチャするかどうか。`CLICKSTACK_CAPTURE_HTTP_BODY` でオーバーライドされます                                        |
| `instrumentations`           | アップストリームの設定のデフォルト                    | `getNodeAutoInstrumentations` に渡す設定マップ。`enabled` を明示的に指定した場合、その値はインストルメンテーションの有効化/無効化を制御する環境変数よりも優先されます |
| `additionalInstrumentations` | `[]`                                 | デフォルトのバンドルに含まれないライブラリ向けに追加するインストルメンテーションのインスタンス                                                         |

環境変数が未設定または空の場合は、対応するオプションの値が適用されます。コンソール出力のキャプチャを無効化するには、`OTEL_NODE_DISABLED_INSTRUMENTATIONS` に `console` を追加します。すべてのデフォルト値については、[Node.js SDK リファレンス](https://github.com/ClickHouse/clickstack-node#quick-start)を参照してください。

プロセスを明示的に終了する場合や AWS Lambda ハンドラーで使用する場合については、[SDK ライフサイクルのドキュメント](https://github.com/ClickHouse/clickstack-node#lifecycle)を参照してください。

## アップストリーム SDK の使用 {#using-upstream-sdk}

アプリケーションですでに OpenTelemetry を設定している場合や、ClickStack SDK のオプションでは対応できないカスタムプロセッサや動作が必要な場合は、アップストリームの `NodeSDK` を使用し、上記の宛先への OTLP エクスポートを設定してください。手順は [アップストリーム SDK のセットアップ例](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly)に従ってください。追加で必要なローダーおよびライフサイクルの設定についても説明されています。なお、同一プロセス内で両方の SDK を初期化しないでください。

## HyperDX Node.js SDK からの移行 {#migration}

`@hyperdx/node-opentelemetry` を `@clickhouse/clickstack-node` に置き換え、新しい登録用エントリーポイントを使用してください。`HYPERDX_API_KEY` は `OTEL_EXPORTER_OTLP_HEADERS` に置き換え、上記で説明した宛先ごとの認証フォーマットを指定してください。

新しい SDK では、HyperDX のヘルパーやオプションがすべて引き継がれているわけではありません。ロガーのインテグレーション、エラーハンドラー、カスタムトレース属性、サンプリング設定を置き換える前に、[SDK 移行ガイド](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md)を確認してください。
