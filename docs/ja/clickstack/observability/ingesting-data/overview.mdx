    ClickHouse オブザーバビリティには、ログ、メトリクス、トレース、セッションリプレイのデータを受信して ClickHouse Cloud に書き込む**マネージド OpenTelemetry (OTel) collector** が含まれています。インジェスト用の collector、データベース、ClickStack UI は ClickHouse Cloud が運用します。ユーザー側では、アプリケーションをインストルメントし、アプリケーションまたはデータ収集エージェントからマネージドサービスにテレメトリーを送信するよう設定するだけです。

    </div>

    これらのコンポーネントの詳細については、[アーキテクチャ](/ja/clickstack/observability/architecture)を参照してください。

## 接続情報を確認する {#connection-details}

    サービスで **Team Settings → Data** を開き、**Managed Telemetry** セクションを探します。このセクションには、サービスにテレメトリーを送信するための OTLP エンドポイントと APIキーが表示されます。

    **URL**、**Collector config**、**Env vars** のいずれかを選択して必要な形式で接続情報を表示し、**Copy connection details** でコピーします。表示されたエンドポイントと認証設定を使用して、SDK または collector を設定してください。

    <div className="ch-image-lg">
      <Frame>
        ![マスクされた OTLP HTTPエンドポイントと APIキーを表示する Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    詳細は [マネージドテレメトリー](/ja/clickstack/observability/managing/config#managed-telemetry) を参照してください。**Send a Test Log** を使用すると、サンプルのログをサービスに送信できます。

## テレメトリーの送信方法を選択する {#sending-telemetry}

### アプリケーションのインストルメンテーション {#application-instrumentation}

    各言語の SDK は、リクエストのトレースやアプリケーションログなど、アプリケーション内部からテレメトリーを収集します。OTLP を使用して、マネージドエンドポイント、または環境内でサービスへ転送を行う collector にテレメトリーをエクスポートするよう SDK を設定します。

    既存の OpenTelemetry インストルメンテーションをそのまま使用できます。ClickStack SDK はブラウザのセッションリプレイなどの機能も提供しています。マネージド環境での設定例については、[セッションリプレイ](/ja/clickstack/observability/features/session-replay)を参照してください。

### インフラストラクチャと収集エージェント {#collection-agents}

    ホストメトリクス、コンテナログ、Kubernetes イベントなどのテレメトリーを収集するには、環境内で収集エージェントを実行します。OpenTelemetry collector は、収集対象に応じて、アプリケーションと並べて、ホスト上で、または Kubernetes DaemonSet として実行できます。

    サービスの接続情報を使用して、これらのエージェントがマネージド OTLP エンドポイントにテレメトリーを転送するよう設定します。また、アプリケーションのテレメトリーをこれらの collector 経由でルーティングし、ClickHouse オブザーバビリティに届く前に処理することもできます。

## インジェストを確認する {#verify-ingestion}

    アプリケーションまたは collector を設定したら、テレメトリーを生成して [検索](/ja/clickstack/observability/features/search) を開きます。**Logs** または **Traces** ソースを選択し、新しいイベントを含む時間範囲を指定してサービス名で検索し、データが届いていることを確認します。

  <Tab title="セルフマネージド">
    すべてのデータは **OpenTelemetry (OTel) collector** を介して Self-managed ClickHouse Observability に取り込まれます。この collector が、ログ、メトリクス、トレース、セッションデータの主要なエントリーポイントとなります。

    アプリケーションからテレメトリデータを受信するには、ユーザー側で OpenTelemetry Collector を実行します。Self-managed ClickHouse Observability では、ClickHouse と UI は ClickHouse Cloud 上でホストおよび管理され、認証と運用管理も統合された形で提供されます。

    <div className="ch-image-lg">
      <Frame>
        ![セルフマネージドの collector を経由して ClickHouse に流れる OTLP テレメトリーと、ClickHouse Cloud 上でホストされる ClickStack UI](/images/use-cases/observability/clickstack-self-managed-architecture.svg)
      </Frame>
    </div>

    collector は 2 つの OTLPエンドポイントを公開します。

    * **HTTP** - ポート `4318`
    * **gRPC** - ポート `4317`

    これらのエンドポイントには、[言語 SDKs](/ja/clickstack/observability/ingesting-data/sdks) から直接データを送信することも、OTel 互換のデータ収集エージェント (例: インフラストラクチャのメトリクスやログを収集する他の OTel コレクター) から送信することもできます。

    具体的には次のとおりです。

    * [**言語 SDKs**](/ja/clickstack/observability/ingesting-data/sdks) は、アプリケーション内部でテレメトリー (特に **トレース** と **ログ**) を収集し、OTLP エンドポイント経由で OpenTelemetry collector にエクスポートします。ClickHouse へのインジェストは collector が担います。利用可能な言語 SDKs の詳細については、[SDKs](/ja/clickstack/observability/ingesting-data/sdks) を参照してください。

    * **データ収集エージェント** は、エッジ (サーバー、Kubernetes ノード、またはアプリケーションと同じ環境) にデプロイされるエージェントです。インフラストラクチャのテレメトリー (例: ログ、メトリクス) を収集するか、SDK で計装済みのアプリケーションから直接イベントを受信します。後者の場合、エージェントはアプリケーションと同じホスト上で、多くはサイドカーまたは DaemonSet として実行されます。これらのエージェントは、[ゲートウェイ](/ja/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)として機能する中央の ClickStack OTel コレクターにデータを転送します。ゲートウェイは通常、クラスター、データセンター、またはリージョンごとに 1 つデプロイされます。[ゲートウェイ](/ja/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)はエージェントやアプリケーションから OTLP イベントを受信し、ClickHouse へのインジェストを処理します。詳細については [OTel collector](/ja/clickstack/self-configured/ingesting-data/collector) を参照してください。エージェントには、OTel collector の別インスタンスのほか、[Fluentd](https://www.fluentd.org/) や [Vector](https://vector.dev/) などの代替技術も使用できます。

    <Info>
      **OpenTelemetry との互換性**

      ClickStack は、テレメトリーと機能を強化した独自の言語 SDKs とカスタム OpenTelemetry collector を提供していますが、既存の OpenTelemetry SDKs やエージェントもそのままシームレスに使用できます。
    </Info>
