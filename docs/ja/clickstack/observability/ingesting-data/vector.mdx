    <Note>
      このガイドは **セルフマネージドの ClickHouse オブザーバビリティ** にのみ適用されます。Vector の ClickHouse シンクは、ユーザー自身が管理するテーブルに直接書き込みます。完全マネージド型の ClickHouse オブザーバビリティでは、OTLP によるインジェストが必要です。エンドポイントと認証の設定については、[OpenTelemetry を使用したデータ取り込み](/ja/clickstack/observability/ingesting-data/opentelemetry#fully-managed) を参照してください。
    </Note>

    [Vector](https://vector.dev) は、高パフォーマンスかつベンダーニュートラルなオブザーバビリティ向けデータパイプラインです。多様なソースからログやメトリクスを収集・変換・ルーティングする用途で広く使用されており、その柔軟性とリソース消費の少なさから、特にログのインジェストで高い人気を誇ります。

    Self-managed ClickHouse Observability で Vector を使用する場合、スキーマはユーザー自身で定義する必要があります。これらのスキーマは OpenTelemetry の規約に従ったものでも、ユーザー定義のイベント構造を表す完全にカスタムなものでも構いません。実際には、Vector によるインジェストは主に **ログ** に使用されます。ログの場合、ユーザーはデータを ClickHouse に書き込む前に、パースやエンリッチメントを完全に制御したいと考えることが多いためです。

    このガイドでは、Vector を使用して Self-managed ClickHouse Observability にデータをオンボーディングする方法を中心に説明します。説明を簡潔にするため、Vector のソースやパイプラインの設定については詳しく扱いません。その代わりに、ClickHouse にデータを書き込む**シンク**の設定と、生成されるスキーマを Self-managed ClickHouse Observability と互換性のあるものにする方法に焦点を当てます。

    このサービスで厳密に求められる要件は、データに**タイムスタンプ列** (または同等の時刻フィールド) が含まれていることだけです。この列は、オブザーバビリティ UI でデータソースを設定する際に指定できます。

## Vector によるデータ送信 {#sending-data-with-vector-self-configured}

    <br />

    以下のガイドは、Self-managed ClickHouse Observability サービスを作成済みで、サービスの認証情報を記録済みであることを前提としています。まだの場合は、Vector の設定を求められるまで、Self-managed ClickHouse Observability の[はじめに](/ja/clickstack/self-configured/getting-started/managed)ガイドに従ってください。

    <Steps>
      <Step title="データベースとテーブルの作成" id="create-a-database-table-self-configured">
        Vector では、データを取り込む前にテーブルとスキーマを定義しておく必要があります。

        まずデータベースを作成します。これは [ClickHouse Cloud コンソール](/ja/products/cloud/features/sql-console-features/sql-console) から行えます。

        以下の例では、データベース名として `logs` を使用します。

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        データを格納するテーブルを作成します。テーブルは、データの出力スキーマと一致させる必要があります。以下の例では、一般的な Nginx の構造を想定しています。[スキーマのベストプラクティス](/ja/concepts/best-practices/select-data-type)に従い、ご自身のデータに合わせて適宜調整してください。[主キーの概念](/ja/concepts/core-concepts/primary-indexes)を理解したうえで、[こちら](/ja/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key)に記載されているガイドラインに基づいて主キーを選択することを**強く推奨します**。

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Nginx の主キー**

          上記の主キーは、オブザーバビリティ UI における Nginx ログの一般的なアクセスパターンを想定したものです。本番環境のワークロードによっては、調整が必要になる場合があります。
        </Info>
      </Step>

      <Step title="Vector の設定に ClickHouse シンクを追加" id="add-clickhouse-sink-to-config-self-configured">
        Vector の設定を変更して ClickHouse シンクを追加し、既存のパイプラインからイベントを受け取るように `inputs` フィールドを更新します。

        この設定は、上流の Vector パイプラインで**データが移行先の ClickHouse スキーマに合わせてすでに整形されている**こと、つまりフィールドがパース済みで、正しく命名され、挿入に適した型が指定されていることを前提としています。未加工のログ行をパースし、サービスに適したスキーマへ正規化する一連の手順については、[**後述の Nginx の例**](#example-dataset-with-vector-self-configured)を参照してください。

        ```yaml
        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - your_input
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        デフォルトでは、各イベントを1行あたり1つのJSONオブジェクトとしてエンコードする **`json_each_row`** フォーマットの使用を推奨します。これは JSON データを取り込む際のサービスのデフォルトかつ推奨のフォーマットであり、文字列としてエンコードされた JSON オブジェクトなどの他のフォーマットよりも優先して使用してください。

        ClickHouse シンクは **Arrow ストリームエンコーディング** (現在ベータ) もサポートしています。より高いスループットが得られる場合がありますが、重要な制約があります。スキーマは起動時に一度だけフェッチされるため、データベースとテーブルは静的である必要があり、動的ルーティングもサポートされていません。そのため、Arrow エンコーディングは、構成が固定され明確に定義されたインジェストパイプラインに最適です。

        利用可能なシンクの設定オプションについては、[Vector のドキュメント](https://vector.dev/docs/reference/configuration/sinks/clickhouse)を確認することをお勧めします。

        <Note>
          上記の例では、Self-managed ClickHouse Observability の defaultユーザーを使用しています。本番環境へのデプロイメントでは、適切なアクセス許可と制限を設定した[インジェスト専用ユーザーを作成する](/ja/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)ことを推奨します。
        </Note>
      </Step>

      <Step title="オブザーバビリティUIに移動" id="navigate-to-clickstack-ui-self-configured">
        Self-managed ClickHouse Observability サービスに移動し、左側のメニューから &quot;ClickStack&quot; を選択します。オンボーディングを完了済みの場合は、新しいタブでオブザーバビリティ UI が起動し、自動的に認証されます。未完了の場合は、オンボーディングを進め、入力ソースとして Vector を選択した後に「Launch ClickStack」を選択してください。

        <div className="ch-image-lg">
          <Frame>
            ![Vector 用に ClickStack を起動](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="データソースを作成" id="create-a-datasource-managed-self-configured">
        ログのデータソースを作成します。データソースが1つも存在しない場合は、初回ログイン時に作成を求められます。すでに存在する場合は、チーム設定に移動して新しいデータソースを追加してください。

        <div className="ch-image-lg">
          <Frame>
            ![データソースの作成 - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        上記の設定は、`time_local` カラムをタイムスタンプとして使用する Nginx 形式のスキーマを前提としています。可能な限り、主キーで宣言されているタイムスタンプカラムを指定してください。このカラムの指定は必須です。

        また、`Default SELECT` を更新し、ログビューで返されるカラムを明示的に定義することを推奨します。サービス名、ログレベル、ボディカラムなどの追加フィールドが利用可能な場合は、これらも設定できます。タイムスタンプの表示カラムが、テーブルの主キーで使用され上記で設定したカラムと異なる場合は、表示カラムをオーバーライドすることもできます。

        上記の例では、データに `Body` カラムは存在しません。代わりに、利用可能なフィールドから Nginx のログ行を再構成する SQL式によって定義しています。

        その他のオプションについては、[設定リファレンス](/ja/clickstack/self-configured/managing/config)を参照してください。
      </Step>

      <Step title="データを探索" id="explore-the-data-managed-self-configured">
        ログビューに移動してデータを探索し、サービスの利用を開始しましょう。

        <div className="ch-image-lg">
          <Frame>
            ![オブザーバビリティ UI に表示された Nginx ログ](/images/clickstack/nginx-logs-vector-search.webp)
          </Frame>
        </div>
      </Step>
    </Steps>

## Vector を使用したサンプルデータセット {#example-dataset-with-vector-self-configured}

    より実践的な例として、以下では **Nginx のログファイル** を使用します。

    以下のガイドは、Self-managed ClickHouse Observability サービスをすでに作成し、サービスの認証情報を記録済みであることを前提としています。まだの場合は、Self-managed ClickHouse Observability の [はじめに](/ja/clickstack/self-configured/getting-started/managed) ガイドに従い、Vector の設定を求められるところまで進めてください。

    <Steps>
      <Step title="Vectorのインストール" id="installing-vector-self-configured">
        <InstallingVector />
      </Step>

      <Step title="サンプルデータをダウンロード" id="download-the-sample-data-self-configured">
        <VectorSampleData />
      </Step>

      <Step title="データベースとテーブルの作成" id="create-database-table-nginx-managed-self-configured">
        Vector では、データ取り込みを行う前にテーブルとスキーマを定義しておく必要があります。

        まず、データベースを作成します。作成は [ClickHouse Cloud コンソール](/ja/products/cloud/features/sql-console-features/sql-console) から行えます。

        データベース `logs` を作成します。

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        データを格納するテーブルを作成します。

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Nginx の主キー**

          上記の主キーは、オブザーバビリティ UI で Nginx ログを扱う際の一般的なアクセスパターンを想定しています。本番環境では、ワークロードに応じて調整が必要になる場合があります。
        </Info>
      </Step>

      <Step title="Vector の設定をコピー" id="copy-vector-configuration-self-configured">
        Vector の設定をコピーして `nginx.yaml` ファイルを作成し、`CLICKHOUSE_ENDPOINT` と `CLICKHOUSE_PASSWORD` を設定します。

        ```yaml
        data_dir: ./.vector-data
        sources:
          nginx_logs:
            type: file
            include:
              - access.log
            read_from: beginning

        transforms:
          decode_json:
            type: remap
            inputs:
              - nginx_logs
            source: |
              . = parse_json!(to_string!(.message))
              ts = parse_timestamp!(.time_local, format: "%d/%b/%Y:%H:%M:%S %z")
              # ClickHouse-friendly DateTime format
              .time_local = format_timestamp!(ts, format: "%F %T")

        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - decode_json
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        <Note>
          上記の例では、Self-managed ClickHouse Observability の defaultユーザーを使用しています。本番環境へのデプロイメントでは、適切なアクセス許可と制限を設定した[専用のインジェスト用ユーザーを作成する](/ja/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)ことを推奨します。
        </Note>
      </Step>

      <Step title="Vector を起動" id="start-vector-self-configured">
        ファイルのオフセットを記録するためのデータディレクトリを先に作成してから、次のコマンドで Vector を起動します。

        ```bash
        mkdir ./.vector-data
        vector --config nginx.yaml
        ```
      </Step>

      <Step title="オブザーバビリティUIに移動" id="navigate-to-clickstack-ui-nginx-managed-self-configured">
        Self-managed ClickHouse Observability のサービスに移動し、左側のメニューから「ClickStack」を選択します。オンボーディングをすでに完了している場合は、オブザーバビリティ UI が新しいタブで開き、自動的に認証されます。まだ完了していない場合は、オンボーディングを進め、入力ソースとして Vector を選択したうえで「Launch ClickStack」を選択してください。

        <div className="ch-image-lg">
          <Frame>
            ![Vector 用に ClickStack を起動する](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="データソースを作成" id="create-a-datasource-nginx-managed-self-configured">
        ログのデータソースを作成します。データソースが1つも存在しない場合は、初回ログイン時に作成を求められます。すでにデータソースがある場合は、チーム設定に移動して新しいデータソースを追加してください。

        <div className="ch-image-lg">
          <Frame>
            ![データソースの作成 - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        この設定は、`time_local` カラムをタイムスタンプとして使用する Nginx スキーマを前提としています。このカラムは主キーで宣言されているタイムスタンプカラムであり、必須です。

        また、デフォルトの select として `time_local, remote_addr, status, request` を指定しています。これにより、ログビューで返されるカラムが決まります。

        上記の例では、データ内に `Body` カラムは存在しません。代わりに、次の SQL式として定義しています:

        ```sql
        concat(
          remote_addr, ' ',
          remote_user, ' ',
          '[', formatDateTime(time_local, '%d/%b/%Y:%H:%M:%S %z'), '] ',
          '"', request, '" ',
          toString(status), ' ',
          toString(body_bytes_sent), ' ',
          '"', http_referer, '" ',
          '"', http_user_agent, '" ',
          '"', http_x_forwarded_for, '" ',
          toString(request_time), ' ',
          toString(upstream_response_time), ' ',
          '"', http_host, '"'
        )
        ```

        これにより、構造化されたフィールドからログ行が再構築されます。

        その他の利用可能なオプションについては、[設定リファレンス](/ja/clickstack/self-configured/managing/config)を参照してください。
      </Step>

      <Step title="データを探索" id="explore-the-data-nginx-managed-self-configured">
        `October 20th, 2025` の検索ビューに移動してデータを探索し、サービスの利用を開始しましょう。

          <Frame>
            ![オブザーバビリティ UI](/images/clickstack/nginx-logs-vector-search.webp)
          </Frame>
        </div>
      </Step>
