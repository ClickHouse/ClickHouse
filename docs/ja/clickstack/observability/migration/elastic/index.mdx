Elastic Stack から、推奨されるデフォルトの構成である **完全マネージド型 ClickHouse オブザーバビリティ** への移行を計画しましょう。まず「はじめに」と検索の比較を確認し、続いてデータ、エージェント、SDK の各移行ガイドに従ってください。手順が異なる箇所では、セルフマネージドのデプロイメント向けにセルフマネージド用のタブを参照してください。

| セクション                                                                     | 説明                                                      |
| ------------------------------------------------------------------------- | ------------------------------------------------------- |
| [はじめに](/ja/clickstack/observability/migration/elastic/intro)                 | 移行時の考慮事項とプラットフォーム間の違い                                   |
| [検索](/ja/clickstack/observability/migration/elastic/search)                  | 検索クエリの書き換え方と、スキーマおよび欠損フィールドの扱いの違い                       |
| [データの移行](/ja/clickstack/observability/migration/elastic/migrating-data)      | 並行インジェスト、保持期間、履歴データ移行の計画                                |
| [エージェントの移行](/ja/clickstack/observability/migration/elastic/migrating-agents) | Beats、Elastic Agent、OpenTelemetry コレクターの移行パスの選択         |
| [SDK の移行](/ja/clickstack/observability/migration/elastic/migrating-sdks)     | アプリケーションのインストルメンテーションを Elastic APM から OpenTelemetry へ移行 |

完全マネージド型 ClickHouse オブザーバビリティでは、基盤となるスキーマとストレージ構成が自動的に管理されます。これらの内部構造を自分で管理する場合は、[同等の概念](/ja/clickstack/self-configured/migration/elastic/concepts)と[型マッピング](/ja/clickstack/self-configured/migration/elastic/types)を参照してください。
