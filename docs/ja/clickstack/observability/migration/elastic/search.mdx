## ClickHouse Observability と Elastic における検索 {#search-in-clickstack-and-elastic-self-configured}

ClickHouse は SQL ネイティブなエンジンであり、高パフォーマンスな分析ワークロード向けにゼロから設計されています。一方、Elasticsearch が提供するのは SQL ライクなインターフェイスであり、SQL を内部の Elasticsearch クエリ DSL にトランスパイルして実行します。つまり SQL は第一級の機能として扱われておらず、[機能面での互換性](https://www.elastic.co/docs/explore-analyze/query-filter/languages/sql-limitations)も限定的です。

ClickHouse は完全な SQL をサポートするだけでなく、[`argMax`](/ja/reference/functions/aggregate-functions/argMax)、[`histogram`](/ja/reference/functions/aggregate-functions/parametric-functions#histogram)、[`quantileTiming`](/ja/reference/functions/aggregate-functions/quantileTiming) など、オブザーバビリティに特化したさまざまな関数で SQL を拡張しています。これにより、構造化ログ、メトリクス、トレースに対するクエリを簡潔に記述できます。

ログやトレースを手軽に探索できるよう、オブザーバビリティ UI では [Lucene スタイルの構文](/ja/clickstack/observability/features/search)を利用できます。フィールドと値の指定、範囲、ワイルドカードなどを用いて、テキストベースで直感的にフィルタリングできます。これは Elasticsearch の [Lucene 構文](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-query-string-query#query-string-syntax)や [Kibana Query Language](https://www.elastic.co/docs/reference/query-languages/kql) の一部の要素に相当します。

検索インターフェイスはこの使い慣れた構文をサポートしつつ、内部では効率的な SQL の `WHERE` 句に変換します。そのため、Kibana ユーザーにとって馴染みのある操作感を保ちながら、必要に応じて SQL の強力な機能を活用できます。ClickHouse の[文字列検索関数](/ja/reference/functions/regular-functions/string-search-functions)、[類似度関数](/ja/reference/functions/regular-functions/string-functions#stringJaccardIndex)、[日時関数](/ja/reference/functions/regular-functions/date-time-functions)も余すところなく利用できます。

以下の検索構文は、マネージドサービスとセルフマネージドサービスの両方に適用されます。フィールド名はスキーマによって異なります。例では、可能な限り標準的な OpenTelemetry のログフィールドを使用しています。

## ClickHouse Observability の検索構文と Elasticsearch のクエリ文字列の比較 {#clickstack-vs-elasticsearch-query-string-self-configured}

ClickHouse Observability と Elasticsearch は、どちらもログやトレースを直感的にフィルタリングできる柔軟なクエリ言語を備えています。Elasticsearch のクエリ文字列は自身の DSL およびインデックスエンジンと密接に統合されているのに対し、ClickHouse Observability は Lucene に着想を得た構文をサポートしており、内部的には ClickHouse SQL に変換されます。以下の表では、一般的な検索パターンが両システムでどのように動作するかをまとめ、構文上の共通点とバックエンドでの実行方法の違いを示します。

| **機能**               | **ClickHouse Observability の構文**   | **Elasticsearch の構文**              | **備考**                                                                                                                                                                                                   |
| -------------------- | ---------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| フリーテキスト検索            | `error`                            | `error`                            | ClickHouse Observability は、ソースに設定された全文検索用の expression (通常は `Body`) を検索し、デフォルトでは大文字と小文字を区別しない単語単位の一致で照合します。すべてのカラムが自動的に検索されるわけではありません。                                                                    |
| フィールド一致              | `SeverityText:error`               | `level:error`                      | スキーマ内のフィールド名を使用します。ClickHouse Observability では、引用符で囲まれていない文字列フィールドの検索は部分一致になります。等値比較を行うには、`SeverityText:"error"` のように値を引用符で囲みます。                                                                         |
| フレーズ検索               | `"disk full"`                      | `"disk full"`                      | 設定済みの全文検索用 expression 内でフレーズに一致します。                                                                                                                                                                      |
| フィールドのフレーズ一致         | `Body:"disk full"`                 | `message:"disk full"`              | ClickHouse Observability では、フィールド値を直接引用符で囲むと等値比較になります。つまり、長いメッセージ内のフレーズではなく、ボディ全体に一致します。                                                                                                                 |
| OR 条件                | `error OR warning`                 | `error OR warning`                 | 語句の論理 OR です。両システムともネイティブにサポートしています。                                                                                                                                                                      |
| AND 条件               | `error AND db`                     | `error AND db`                     | どちらも積集合に変換されます。ユーザーが記述する構文に違いはありません。                                                                                                                                                                     |
| 否定                   | `NOT error` または `-error`           | `NOT error` または `-error`           | 一致するイベントを除外します。                                                                                                                                                                                          |
| グループ化                | `(error OR fail) AND db`           | `(error OR fail) AND db`           | どちらも標準的なブール演算のグループ化です。                                                                                                                                                                                   |
| ワイルドカード              | `error*` または `*fail*`              | `error*`、`*fail*`                  | ClickHouse Observability は、フリーテキスト検索を含め、前方および後方のワイルドカードをサポートしています。`f*ail` のような中間のワイルドカードはサポートされていません。Elasticsearch はデフォルトで前方ワイルドカードを許可していますが、無効化も可能で、処理コストが高くなる場合があります。                                  |
| 範囲 (数値/日付)           | `Duration:[100 TO 200]`            | `duration:[100 TO 200]`            | 角括弧は上限と下限の両方を含みます。スキーマ内のフィールド名と単位を使用してください。                                                                                                                                                              |
| 上限または下限のない範囲 (数値/日付) | `Duration:>10` または `Duration:>=10` | `duration:>10` または `duration:>=10` | 比較演算子で片側が開いた範囲を表します。                                                                                                                                                                                     |
| 境界を含む/含まない           | `Duration:{100 TO 200}`            | `duration:{100 TO 200}`            | 波括弧は上限と下限の両方を除外します。                                                                                                                                                                                      |
| 存在チェック               | `LogAttributes.log.file.path:*`    | `_exists_:user` または `field:*`      | 文字列値の `Map` 属性の場合、ClickHouse Observability は値が空でないかどうかをチェックします。値に関係なくキーの存在を確認したい場合は、SQL の `mapContains` を使用してください。詳しくは[スキーマと欠損フィールド](#empty-value-differences-self-configured)を参照してください。                 |
| 正規表現                 | `match` 関数                         | `name:/joh?n(ath[oa]n)/`           | 現在、Lucene 構文ではサポートされていません。SQL で [`match`](/ja/reference/functions/regular-functions/string-search-functions#match) 関数やその他の[文字列検索関数](/ja/reference/functions/regular-functions/string-search-functions)を使用できます。 |
| あいまい一致               | `editDistance('quikc', field) = 1` | `quikc~`                           | 現在、Lucene 構文ではサポートされていません。SQL では距離関数 (例: `editDistance('rror', SeverityText) = 1`) や[その他の類似度関数](/ja/reference/functions/regular-functions/string-functions#jaroSimilarity)を使用できます。                          |
| 近接検索                 | サポートされていません                        | `"fox quick"~5`                    | 現在、Lucene 構文ではサポートされていません。                                                                                                                                                                               |
| ブースト                 | サポートされていません                        | `quick^2 fox`                      | 現時点では ClickHouse Observability ではサポートされていません。                                                                                                                                                            |
| フィールドのワイルドカード        | サポートされていません                        | `service.*:error`                  | 現時点では ClickHouse Observability ではサポートされていません。                                                                                                                                                            |
| 特殊文字のエスケープ           | 予約文字は `\` でエスケープします                | 同様                                 | 予約記号にはエスケープが必要です。                                                                                                                                                                                        |

## スキーマと欠損フィールド {#empty-value-differences-self-configured}

標準の OpenTelemetry スキーマでは、`Body`、`SeverityText`、`ServiceName` などのフィールドが使用され、ログ属性とリソース属性はそれぞれ `LogAttributes` と `ResourceAttributes` に格納されます。Elastic のフィールド名は、取り込み済みデータ内の対応するフィールドに読み替えてください。たとえば、`level:error` は `SeverityText:error` になります。

NULL 非許容カラムでは、省略された値はそのカラムのデフォルト値 (空文字列など) として表されます。そのため、`ServiceName` が空であっても、送信側が値を省略したのか、明示的に空文字列を送信したのかは区別できません。

カスタムテーブルを使用するセルフマネージドのデプロイメントでは、独自のカラム名を使用し、各カラムのデフォルト値と NULL 許容かどうかを確認してください。[`Nullable`](/ja/reference/data-types/nullable) カラムには `NULL` を格納できます。

SQL クエリでは、`ServiceName != ''` でサービス名が空でないかどうかをチェックできます。`Map` に格納された属性は、top-level のカラムとは別物です。属性キーが存在するかどうかを (値が空の場合も含めて) 確認するには、`mapContains(LogAttributes, 'log.file.path')` を使用してください。
