**ClickHouse オブザーバビリティ** は、オープンソースの ClickStack を基盤とした、SRE、開発者、そして彼らの AIエージェントのためのオブザーバビリティプラットフォームです。OpenTelemetry のログ、トレース、メトリクスをセッションリプレイとあわせて、単一のプラットフォーム上で検索、クエリ、相関付けできます。

調査は ClickStack UI から行えるほか、[ClickStack MCPサーバー](/ja/clickstack/observability/mcp) を介して独自のエージェントを接続することもできます。調査ツールでログを検索してトレースをたどり、さらに踏み込んだ分析には SQL を活用できます。情報量の多いログやトレーススパンには、リクエストの詳細、カスタム属性、ビジネスコンテキストが記録されるため、障害の原因究明に役立ちます。

バックエンドの運用を ClickHouse に任せる場合は **完全マネージド型** を、インジェストやデータベース設定をチームで管理する必要がある場合は **セルフマネージド** を選択してください。どちらも ClickHouse Cloud 上で稼働し、同じ ClickStack の調査体験を提供します。

## 仕組み {#how-it-works}

どちらの提供形態でも、アプリケーションをインストルメントし、環境からテレメトリーを収集します。収集したデータは ClickStack UI で探索できるほか、MCP 対応のエージェントを接続して、ログの検索、トレースの追跡、SQL の実行を行うこともできます。両者の違いは、こうした体験を支えるインジェストとデータベース設定を誰が管理するかという点にあります。

* **完全マネージド型:** テレメトリーをマネージドの OpenTelemetry エンドポイントに送信するか、既存の Datadog エージェントからはマネージドの Datadog 互換エンドポイントを利用します。インジェストのバックエンドは ClickHouse が運用し、スキーマ、コンピュート、スケーリング、パフォーマンスも ClickHouse が管理します。

### 提供形態の比較 {#compare-the-offerings}

どちらの提供形態でも、アプリケーションのインストルメントとテレメトリーの収集はお客様が行います。次の表は、バックエンドのうち ClickHouse が管理する範囲を示しています。ダッシュ (—) は、その部分をお客様が管理することを意味します。

| ClickHouse による管理                 | 完全マネージド型 | セルフマネージド |
| -------------------------------- | :------: | :------: |
| インジェストバックエンド                     |     ✓    |     —    |
| スキーマ、索引、圧縮                       |     ✓    |     —    |
| コンピュートのサイジング、スケーリング、ワークロードの分離    |     ✓    |     —    |
| データベースのパフォーマンスチューニング             |     ✓    |     —    |
| データベースのインフラストラクチャ、アップグレード、バックアップ |     ✓    |     ✓    |
| ClickStack UI および MCPサーバーのホスティング |     ✓    |     ✓    |

## 機能 {#features}

* [MCP](/ja/clickstack/observability/mcp) 経由で独自のエージェントを接続し、テレメトリーの検索、トレースの追跡、パターンや変化の分析、SQL の実行を行えます。
* ログ、トレース、メトリクス、セッションリプレイを 1 か所で検索し、相関付けられます。
* high-cardinality なテレメトリーに対しても、高速な検索と集計を実行できます。
* `level:err` のような[全文検索と Lucene 形式のフィルタ](/ja/clickstack/observability/features/search)を使用できるほか、より詳細な分析には SQL も利用できます。
* [AIノートブック](/ja/clickstack/observability/notebooks)でテレメトリーを探索したり、[自然言語の質問からチャート](/ja/clickstack/observability/text-to-chart)を作成したりできます。
* [ダッシュボード](/ja/clickstack/observability/features/dashboards/overview)を構築し、[アラート](/ja/clickstack/observability/features/alerts)を設定できます。
* ログやトレーススパン内の JSON フィールドやカスタム属性に対してクエリを実行できます。
* ブラウザ上の操作からバックエンドサービス、データベースクエリに至るまで、リクエストを一貫して追跡できます。
* [イベントパターン](/ja/clickstack/observability/features/event-patterns)で繰り返し発生する障害を特定し、[イベントデルタ](/ja/clickstack/observability/features/event-deltas)で変化を調査できます。
* 新しいイベントの到着に合わせて、ログとトレースをリアルタイムに表示 (ライブテール) できます。
* ご利用のプランに応じて、マネージドエンドポイントまたは独自のインジェスト用 collector を介して OpenTelemetry データを取り込めます。
* [ディープリンク](/ja/clickstack/observability/url-parameters)を使用して、検索結果や調査ビューを共有できます。

## 基本原則 {#clickstack-principles}

### 既存のエージェントを持ち込む {#bring-your-own-agents}

チームですでに使用しているエージェントや開発ツールを、MCP 経由で接続できます。エージェントは UI と同じテレメトリーを使って、ログの検索、トレースの追跡、パターンや変化の特定を行えます。さらに、SQL を実行して証拠を相関付けたり、調査ツールでは直接対応していない問いを掘り下げたりすることも可能です。

### 使いやすく purpose-built な設計 {#user-friendly-purpose-built}

ClickStack UI は、検索、トレースの探索、チャート、ダッシュボード、アラートを 1 つに統合しています。日常的な調査には Lucene 形式のフィルタやビジュアルなクエリビルダーを使い、分析をより細かく制御したい場合は SQL に切り替えられます。

### エンドツーエンドのオブザーバビリティ {#end-to-end-observability}

フロントエンドのセッションリプレイをアプリケーションログ、分散トレース、メトリクスと関連付けることで、システム全体にわたって障害を追跡できます。ワイドイベントでは、リクエストの詳細、カスタム属性、ビジネスコンテキストがログやトレーススパンにまとめて保持されるため、影響を受けているリクエスト、サービス、顧客を容易に特定できます。

### ClickHouse のための設計 {#built-for-clickhouse}

ClickHouse の列指向ストレージ、圧縮、並列クエリ実行により、high-cardinality なテレメトリーが大量にあっても、高速な検索と集計が可能です。また、クエリの同時実行に対応しているため、エンジニアとエージェントが同じデータを並列に調査できます。

### OpenTelemetry ネイティブ {#open-telemetry-native}

標準的な OpenTelemetry のインストルメンテーション、SDK、コレクターを使ってテレメトリーを送信できます。マネージド OTLP エンドポイントまたは独自のインジェスト用 collector を利用すれば、ベンダー独自の収集フォーマットを採用することなく、既存のインストルメンテーションをそのまま使ってログ、トレース、メトリクスを送信できます。
