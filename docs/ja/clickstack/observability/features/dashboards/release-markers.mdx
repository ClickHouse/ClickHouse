レイテンシーやエラーが急増したとき、まず確認したいのはたいてい「何かをリリースしたかどうか」です。ダッシュボードの時系列チャートなら、その場でこれを確認できます。リリースマーカーを有効にすると、サービスのあるバージョンがテレメトリーに初めて現れた時点に、各タイル上で破線の縦線が表示されます。

バージョン情報は、すでに送信しているテレメトリーから、タイルのログソースに設定された expression を通じて取得されます。CI との連携を構築する必要も、デプロイ時に何かをプッシュする必要もありません。

## マーカーを有効にする {#turn-on}

リリースマーカーはデフォルトでは無効になっています。ダッシュボードのオーバーフローメニューを開き、**Show release markers** を選択してください。

<div className="ch-image-sm">
  <Frame>
    ![View セクションの Show alert annotations の下に Show release markers 項目が表示されたダッシュボードのオーバーフローメニュー](/images/clickstack/dashboards/release-markers-menu.webp)
  </Frame>
</div>

このトグルを有効にすると、ダッシュボードの URL に `releaseMarkers=true` が追加されます。そのため、共有したリンクはマーカーが表示された状態で開きます。これはダッシュボードの設定ではなく表示状態であり、ダッシュボードには保存されません。無効にすると、このパラメータは URL から削除されます。

マーカーは、ログソースとしてログまたはトレースソースを使用する時系列タイルに描画されます。[アラートのアノテーション](/ja/clickstack/observability/features/alerts) も同じメニューから表示でき、リリースマーカーと同時に表示することも可能です。その場合、2 種類のマーカーは一緒に描画され、それぞれ独自のラベルが維持されます。

## バージョンの取得元を設定する {#version-expression}

デフォルトでは、ClickHouse オブザーバビリティは OpenTelemetry のリソース属性である `ResourceAttributes['service.version']` を読み取ります。サービスが [service リソースのセマンティック規約](https://opentelemetry.io/docs/specs/semconv/registry/attributes/service/) に準拠していれば、追加の設定なしでマーカーが機能します。

バージョンを別の場所から読み取るには、ログソースまたはトレースソースで **Service Version Expression** を設定します。ログソースは **Team Settings → Sources** で編集できます。ログソースではこのフィールドは **Configure Optional Fields** の中にあり、トレースソースではフォーム上の **Service Name Expression** のすぐ下に表示されます。

<div className="ch-image-lg">
  <Frame>
    ![ログソースの任意フィールド内にある Service Version Expression フィールド。デフォルトのプレースホルダー ResourceAttributes\['service.version'\] が表示されている](/images/clickstack/dashboards/service-version-expression.webp)
  </Frame>
</div>

この値は属性名ではなく SQL式であるため、よくある次の 2 つのケースに対応できます。

* **リリース識別子が別の属性にある場合。** GitOps では、リリースを識別するのは通常コンテナイメージのイメージタグで、`container.image.tag` として送信されます。ログソースの参照先を `ResourceAttributes['container.image.tag']` に変更するほうが、フリート全体でインストルメンテーションを変更するよりもはるかに低コストです。
* **同じテーブル内のサービス間で属性が統一されていない場合。** `coalesce` を使って複数の属性を順にフォールバックします。

```sql
coalesce(
  nullIf(ResourceAttributes['service.version'], ''),
  nullIf(ResourceAttributes['container.image.tag'], '')
)
```

このフィールドは、[sources API](/ja/clickstack/observability/api-reference) のログソースおよびトレースソースでも `serviceVersionExpression` として公開されているため、プログラムからログソースをプロビジョニングする際にも設定できます。セルフマネージドのデプロイメントについては、[ログ](/ja/clickstack/self-configured/managing/config#logs)および[トレース](/ja/clickstack/self-configured/managing/config#traces)のログソース設定の全一覧を参照してください。

## マーカーの意味 {#what-a-marker-means}

マーカーは、表示中のウィンドウ内で、あるバージョン値がタイルのデータに初めて現れたことを記録するものです。これはデプロイメントに近い概念ですが、あえて同じ意味にはしていません。デプロイメントマーカーではなくリリースマーカーと呼んでいるのはそのためです。

* バージョン文字列が変わらないデプロイでは、マーカーは一切生成されません。
* ルックバック期間を超えてアイドル状態にあったサービスでは、再びスケールアップした時点でマーカーが描画されます。

ウィンドウの開始時点ですでに稼働していたバージョンは識別され、実際には発生していないリリースとして描画されずに除外されます。そのため、クエリはウィンドウの開始時点より前 (30分前、またはウィンドウの10%のいずれか長い方) までさかのぼり、それ以前から稼働しているバージョンを特定します。

## タイルに表示されるリリース {#scoping}

リリースのクエリは、タイル自身のログソースに対し、タイル自身の述語を適用して実行されます。適用される述語は、タイルの `WHERE` 句、各系列のフィルタ、および[ダッシュボードフィルタ](/ja/clickstack/observability/features/dashboards/overview#custom-filters)です。タイルに表示されるマーカーは、そのタイルが何をチャートに描画しているかによって異なります。

| タイル               | マーカー                                       |
| :---------------- | :----------------------------------------- |
| 1 つのサービスに絞り込まれている | そのサービスのリリース                                |
| サービスごとにグループ化されている | チャートに描画されているすべてのサービスのリリース(各サービスの線と同じ色で表示)  |
| 複数のサービスを集約した線     | なし(ただし、表示期間内のリリースがすべて 1 つのサービスのものである場合を除く) |

3 番目のケースでは、マーカーのサービスに対応する線がチャート上に存在しないため、マーカーは表示されません。ただし、表示期間内のリリースがすべて単一のサービスのものである場合は、デフォルトのマーカー色で描画されます。

## 項目の多いチャートでマーカーを読み取る {#reading-markers}

マーカーのラベルにカーソルを合わせると、その時点のすべてのリリースが一覧表示されます。各リリースには、それをリリースしたサービス、バージョン、時刻が表示されます。

<div className="ch-image-sm">
  <Frame>
    ![2 つのサービスを表示したチャート上で、リリースマーカーのツールチップにサービス frontend とバージョン 2.0.2、およびそのバージョンが最初に出現した時刻が表示されている様子](/images/clickstack/dashboards/release-marker-tooltip.webp)
  </Frame>
</div>

マーカーは色によって系列と対応付けられますが、チャートの凡例に表示されるエントリは最大 4 つまでで、それ以降は「+N more」にまとめられます。そうなると、画面上には色を照合する手がかりがなくなります。ツールチップにはサービス名が直接表示されるため、タイルに描画される系列の数に関係なく識別できます。

間隔が狭すぎて個別にラベルを付けられないマーカーは、`N releases` と表示される 1 つのラベル付きアンカーにまとめられます。このアンカーにカーソルを合わせると、含まれるすべてのリリースが表示されます。複数のサービスにまたがるクラスターは、いずれかのサービスの色ではなくニュートラルな色で描画されます。これにより、特定のサービスに属するかのような誤解を与えずに、正確な件数を示せます。

マーカーの表示中も、プロット上を水平方向にドラッグしてズームできます。

## 制限事項 {#limitations}

* **時系列タイルのみ対応。** テーブル、数値、ヒートマップのタイルにはマーカーは描画されません。
* **ログソースとトレースソースのみ対応。** メトリクスソースはメトリクスの種類ごとに参照するテーブルが決まるため、再集約の対象となる単一のテーブルが存在せず、タイルのフィルタを意味のある形で適用することもできません。メトリクスデータに注釈を付けたい場合は、同じダッシュボード上にログタイルまたはトレースタイルを並べて配置してください。
* **空のバージョン値はスキップされます。** バージョンを出力しないサービスについては、マーカーは生成されません。タイルでバージョンの変更が 1 件も見つからない場合は、UI に `No releases found` と表示されます。そのため、機能が正常に動作していないのではないかと迷う必要はありません。
* 1 つのウィンドウで読み取られるのは、**最大 500 個の異なるバージョン**までです。
