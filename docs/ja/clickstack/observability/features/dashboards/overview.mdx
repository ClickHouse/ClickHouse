ClickHouse Observability ではイベントを可視化でき、UI にはチャート作成機能が組み込まれています。作成したチャートはダッシュボードに追加して、他のユーザーと共有できます。

可視化は、トレース、メトリクス、ログのほか、ユーザーが定義した任意のワイドイベントスキーマから作成できます。

## 可視化の作成 {#creating-visualizations}

**Chart Explorer** インターフェイスでは、メトリクス、トレース、ログを時系列で可視化でき、データ分析用の可視化をすばやく作成できます。このインターフェイスはダッシュボードの作成時にも使用されます。以下のセクションでは、Chart Explorer で可視化を作成する手順を説明します。

可視化を作成するには、まず **データソース** を選択し、次に **メトリクス** を選択します。必要に応じて **フィルタ式** と **グループ化** フィールドも指定します。概念的には、可視化は内部で SQL の `GROUP BY` クエリに対応しており、選択したディメンションごとに集約するメトリクスを定義する形になります。

<Tip>
  **AI によるチャートとダッシュボードの生成**

  ClickHouse Observability では、[text-to-chart](/ja/clickstack/observability/text-to-chart) 機能を使用して、自然言語のプロンプトからチャートを作成することもできます。表示したい内容を記述するだけで、UI が可視化を自動的に生成します。複数のタイルを含むダッシュボード全体を生成するには、[Text-to-Dashboard](/ja/clickstack/observability/text-to-dashboard) を使用してください。
</Tip>

たとえば、エラー数 (`count()`) をサービス名ごとにグループ化してチャートにできます。

以下の例では、[sql.clickhouse.com](https://sql.clickhouse.com) で公開されているリモートデータセットを使用します。**[play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) にアクセスして、これらの例を再現することもできます。**

    上部メニューで可視化の種類として `Time Series` を選択し、続いてデータセットとして `Traces` ([play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) を使用している場合は `Demo Traces`) を選択します。次の値を入力します。

    </Note>
  </Step>
</Steps>

## ダッシュボードの作成 {#creating-dashboards}

ダッシュボードを使用すると、関連する可視化をまとめて表示し、メトリクスを比較したりパターンを並べて調べたりすることで、システムにおける潜在的な根本原因を特定できます。ダッシュボードはアドホックな調査に使用することも、継続的な監視のために保存しておくこともできます。

グローバルフィルターはダッシュボード単位で適用でき、そのダッシュボード内のすべての可視化に自動的に反映されます。これにより、チャート間で一貫したドリルダウンが可能になり、サービスやテレメトリーの種類をまたいだイベントの相関分析が容易になります。

以下では、ログおよびトレースのデータソースを使用して、2つの可視化を含むダッシュボードを作成します。これらの手順は、[play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) で再現できるほか、[sql.clickhouse.com](https://sql.clickhouse.com) でホストされているデータセットに接続すればローカル環境でも再現できます。

  <Step title="スパンの所要時間を示すヒートマップタイルを追加する" id="create-a-tile-heatmap">
    ヒートマップタイルは、各 (時刻, 値) バケットに該当するイベントの件数を色付きのグリッドとしてプロットします。平均値や単一のパーセンタイルだけでなく、時間経過に伴う分布の**形状**を確認したい場合はヒートマップを使用します。レイテンシのヒートマップを使えば、二峰性の所要時間パターン、低速なテール部分のクラスター、急激なばらつきなど、Line チャートでは平均化されて埋もれてしまう特徴を把握できます。

    ヒートマップタイルを追加するには、次の手順を実行します。

    1. `Add` を選択します。
    2. 上部メニューから可視化タイプとして `Heatmap` を選択します。データソースのドロップダウンには、[ソースタイプが `Traces`](/ja/clickstack/observability/managing/config#datasource-settings) のソースのみが表示されます。ヒートマップにはトレースソースだけが持つスパンの所要時間カラムが必要なため、ログ、メトリクス、セッションのソースは除外されます。
    3. 任意のトレースソースを名前で選択します。名前自体は自由に付けられ、重要なのはタイプだけです。

    ソースを選択すると、ヒートマップには次の値があらかじめ入力されます。

    * **Value**: ソースの `Duration Expression` を現在の表示単位に合わせてスケーリングしたもの (例: 各イベントのスパンの所要時間をナノ秒からミリ秒に変換する `(Duration)/1e6`)
    * **Count**: `count()`

    4. チャート名を設定し、`Where` を使用して、パフォーマンスを観察したい特定のサービスまたは操作群にヒートマップの対象を絞り込みます。
    5. 対象とする期間に合わせて時間範囲を調整します。範囲を広げると、短い期間では見落としがちな分布の変化や二峰性のレイテンシパターンが明らかになります。

    以下の例は、`payment` サービスのスパンの所要時間を示しています。大半のスパンは 1 ミリ秒付近に集中しており、その上側により低速なスパンが散在しています。

    ヒートマップをさらにカスタマイズするには、**表示設定** をクリックしてドロワーを開き、**Scale** (Log または Linear)、**Value**、**Count** の式を設定します。利用可能なオプションの一覧は、イベントデルタのページの [Customize the heatmap](/ja/clickstack/observability/features/event-deltas#customize) に記載されています。そちらと同じドロワーが使用されます。

    `Run` をクリックしてチャートをプレビューし、`Save` をクリックします。

    <div className="ch-image-lg">
      <Frame>
        ![ServiceName フィルタと表示設定ボタンを備え、payment サービスのスパンの所要時間を表示しているヒートマップエディタ](/images/clickstack/observability-dashboard-heatmap-editor.png)
      </Frame>
    </div>

    保存したタイルは、ダッシュボード上でヒートマップとして表示されます。任意のセルにカーソルを合わせると、バケットの上限と下限およびイベント数が表示されます。

    <div className="ch-image-lg">
      <Frame>
        ![payment のスパンの所要時間ヒートマップタイルと、所要時間およびイベント数を示すツールチップを表示したダッシュボード](/images/clickstack/observability-dashboard-heatmap-tile.png)
      </Frame>
    </div>

    <Tip>
      **ヒートマップごとに 2 つの ClickHouse クエリを実行**

      ヒートマップは 2 つのクエリを順番に実行します。まず値の範囲を決定する小さな **bounds クエリ**、次にバケットごとのイベント数をカウントする **heatmap クエリ** です。どちらのクエリもエディタの **Generated SQL** で確認でき、内容を調べたりコピーしたりできます。
    </Tip>

  </Step>

### タイルの表示設定 {#tile-display-settings}

各タイルには、値の表示方法を制御するオプションをまとめた **表示設定** ドロワーがあります。このドロワーは、タイルエディターで **表示設定** をクリックすると開きます。利用できるオプションは可視化の種類によって異なります。

#### 数値タイルの色 {#number-tile-color}

数値タイルでは、厳選されたチャートパレットから固定の **Color** を選択できます。数値タイルを選択した状態で **表示設定** を開き、**Color** コントロール(アクセシビリティ用のラベルは **Number tile color**)でスウォッチを選択します。選択を解除すると、デフォルトのテキスト色が使用されます。

色は直接指定された16進数の色値ではなくパレットトークンとして保存されるため、同じタイルがライト、ダーク、IDE のいずれのテーマでも正しく表示されます。

**カテゴリ別トークン**(複数系列向けの色相):

| トークン               | ラベル        |
| ------------------ | ---------- |
| `chart-blue`       | Blue       |
| `chart-orange`     | Orange     |
| `chart-red`        | Red        |
| `chart-cyan`       | Cyan       |
| `chart-green`      | Green      |
| `chart-pink`       | Pink       |
| `chart-purple`     | Purple     |
| `chart-light-blue` | Light Blue |
| `chart-brown`      | Brown      |
| `chart-gray`       | Gray       |

**セマンティックトークン**(ステータス表示向け):

| トークン            | ラベル     |
| --------------- | ------- |
| `chart-success` | Success |
| `chart-warning` | Warning |
| `chart-error`   | Error   |

数値がステータスを表す場合(たとえば、エラー件数を `chart-error` で、正常率を `chart-success` で表示する場合)は、セマンティックトークンを使用してください。ステータスを示唆せずに、関連する KPI タイル同士を視覚的に区別したい場合は、カテゴリ別トークンを使用してください。

古い設定には、レガシーの数値トークン(`chart-1` ～ `chart-10`)が保存されている場合があります。UI はダッシュボードの読み込み時に、これらを上記の色相名のトークンに変換します。

同じパレットは、同じドロワー内の任意の **color rules** でも使用されます。color rules は表示値に対して順番に評価される条件で、最後に一致したルールが適用されます。どのルールにも一致しない場合は固定の色が適用され、それも未設定の場合はデフォルトのテキスト色が適用されます。

#### 数値タイルの背景チャート {#number-tile-background-chart}

数値タイルには**背景チャート**を表示できます。これは値の背後に描画されるトレンドのスパークラインで、選択した時間範囲における値の推移をひと目で把握できます。SLO やエラーバジェットのタイルのように、現在の値と同じくらい値の推移が重要な場合に役立ちます。

数値タイルを選択した状態で **表示設定** を開き、**Background chart** を **Line** または **Area** に設定します (オフにする場合は **None** を選択します) 。スパークラインはタイルのクエリを時間単位でバケット化したものから生成されるため、追加の設定は不要です。デフォルトではタイルの色が引き継がれますが、**Background color** を設定すると、パレット内の特定の色でオーバーライドできます。

<div className="ch-image-lg">
  <Frame>
    ![Background chart を Area に設定した数値タイルの表示設定ドロワー](/images/clickstack/dashboards/number-tile-background-chart.webp)
  </Frame>
</div>

背景チャートは、クエリビルダーで作成した数値タイルに適用されます。生のSQLの数値タイルは、バケット化に使える時間次元を持たない単一の値を返すため、このオプションは表示されますが無効になります。

テーブルタイルでは、**Alternate Row Background** を使って行をストライプ表示できます。1 行おきに色が付くため、列数の多いテーブルでも内容をスキャンしやすくなります。この設定はデフォルトでオフです。

テーブルタイルを選択した状態で **表示設定** を開き、**Alternate Row Background** をオンにします。ストライプ表示は見た目だけの変更なので、クエリビルダーと生のSQLのどちらのテーブルタイルでも使用できます。

<div className="ch-image-lg">
  <Frame>
    ![Alternate Row Background をオンにしたテーブルタイルの表示設定ドロワー](/images/clickstack/dashboards/table-tile-display-settings.webp)
  </Frame>
</div>

また、テーブルタイルではスクロール中もヘッダー行とデータの間の区切り線が保持されるため、列ヘッダーがデータと明確に区別されます。

#### ダッシュボード API: 数値タイルの色 {#api-number-tile-color}

外部 API(`POST` / `PUT` `/api/v2/dashboards`)でダッシュボードを作成または更新する場合は、ビルダーの数値タイル設定の `color` にパレットトークンを指定してください。直接指定された16進数の色値は受け付けられません。

```json
{
  "name": "Error rate KPIs",
  "tiles": [
    {
      "id": "65f5e4a3b9e77c001a222222",
      "name": "Errors",
      "x": 0,
      "y": 0,
      "w": 6,
      "h": 4,
      "config": {
        "displayType": "number",
        "sourceId": "<SOURCE_ID>",
        "select": [
          {
            "aggFn": "count",
            "where": "SeverityText:error",
            "whereLanguage": "lucene",
            "alias": "Errors"
          }
        ],
        "color": "chart-error",
        "backgroundChart": {
          "type": "area"
        }
      }
    }
  ]
}
```

`color` には、上記のカテゴリ別およびセマンティックのトークン一覧にある任意のトークン (例：`chart-blue` や `chart-success`) を指定できます。任意指定の `backgroundChart.color` を使用すると、同じトークン enum でスパークラインの色をオーバーライドできます。認証とベースURLについては、[APIリファレンス](/ja/clickstack/observability/api-reference)を参照してください。

## カスタムフィルタと変数 {#custom-filters}

すべてのダッシュボードで利用できる[フリーテキストフィルタ](#filter-dashboards)に加えて、保存済みダッシュボードではカスタムフィルタと変数を使用できます。これらは再利用可能なポイントアンドクリック形式のコントロールで、ダッシュボードの閲覧者は式を手動で記述しなくてもフィルタリングできます。値の取得元としては、ログソースからクエリしたカラム、手動で記述したリスト、SQL クエリ、Prometheus のラベル値、または自由に指定したキーと値の条件を使用できます。また、変数を使って、タイルがクエリするデータソースや接続を切り替えることもできます。全種類の一覧については[フィルタの種類](#filter-types)を参照してください。

### フィルタの種類 {#filter-types}

フィルタダイアログの **Type** セレクターでは、フィルタの値の取得元と、その値をタイルへ反映する方法を指定します。

| 種類                                       | 値の取得元                                            | ブロードキャスト     | 変数                                             |
| ---------------------------------------- | ------------------------------------------------ | ------------ | ---------------------------------------------- |
| [SQL式の値](#sql-expression-values-filters) | ソースへのクエリで取得した、式の異なる値                             | 任意(デフォルトで有効) | 任意                                             |
| [静的な値](#static-values-filters)           | 手動で記述したリスト                                       | なし           | 常に使用                                           |
| [SQLクエリの値](#sql-query-filters)           | SQLクエリの最初のカラム                                    | なし           | 常に使用                                           |
| [PromQL ラベルの値](#promql-label-filters)    | Prometheus ラベルの値                                 | なし           | 常に使用                                           |
| [アドホックなキーと値](#adhoc-filters)             | 1 つ以上のソースのキーと値から構築される `key operator value` 形式の条件 | 常に有効         | なし                                             |
| [データソース](#data-source-variables)         | チームのソース                                          | なし           | 常に使用([ソース参照](#source-connection-variables)として) |
| [接続](#connection-variables)              | チームの ClickHouse 接続                               | なし           | 常に使用([接続参照](#source-connection-variables)として)  |

#### SQL式の値 {#sql-expression-values-filters}

このフィルタのドロップダウンには、選択した **Data source** における **Filter expression** の異なる値が一覧表示されます。必要に応じて、**Dropdown values filter** で表示する値を絞り込むこともできます。メトリクスのソースを使用する場合は、**Metric type** も選択してください。SQL式の値フィルタでは、選択した値を[ブロードキャスト](#broadcast-filters)することも、[変数として利用できるように](#dashboard-variables)することも、その両方を行うこともできます。

#### 静的値 {#static-values-filters}

このフィルタのドロップダウンには、手動で入力した値の一覧が表示されます。**Options** に値を 1 つずつ入力し、Enter キーを押します。1 つのフィルタに設定できるオプションは最大 1000 個です。

静的値フィルタは常に変数として扱われ、ブロードキャストされることはありません。そのため、タイルからは `$__filter(SeverityText, $severity)` のように変数を参照して使用します。カラムに保存されていない値を扱う場合や、あらかじめ厳選した固定の一覧を使用する場合に便利です。

#### SQLクエリの値 {#sql-query-filters}

このフィルタのドロップダウンには、ClickHouse SQLクエリが返す最初のカラムの値が、クエリが行を返す順序で最大10,000件まで一覧表示されます。以下を設定します。

* **Connection** — クエリを実行する ClickHouse 接続、または[接続変数](#connection-variables)。
* **Source** — 任意。同じ接続上のログソース、または[データソース変数](#data-source-variables)。ログソースを選択すると、クエリで `$__sourceTable` と `$__filters` を使用できます。`$__filters` は、[生のSQLタイル](/ja/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro)と同様に、そのログソースに対するダッシュボードのブロードキャストフィルタの選択内容を適用します。
* **SQL query** — クエリ本体。[時間マクロ](/ja/clickstack/observability/features/dashboards/sql-visualizations#time-filter-macros)を使用でき、ダッシュボードの他の変数も参照できます。エディタでは、ダッシュボードの現在の時間範囲でクエリが返す値をプレビューできます。

例えば、次のクエリは、ダッシュボードの時間範囲内にイベントがログに記録されたサービスを、`environment` フィルタで選択された環境に絞り込んで一覧表示します。

```sql
SELECT DISTINCT ServiceName
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ResourceAttributes['deployment.environment'], $environment)
ORDER BY ServiceName
```

「SQLクエリの値」フィルタは常に変数として扱われ、ブロードキャストされることはありません。

#### PromQL ラベル値 {#promql-label-filters}

<PrivatePreviewBadge />

このフィルタのドロップダウンには、Prometheus ラベルの値が一覧表示されます。PromQL の **Data source** を選択し、ドロップダウンに表示する値の取得元となる **Label**(`job`、`instance`、`__name__` など)を入力します。必要に応じて **Series matchers** も入力します。これは `up{job="api"}` のような Prometheus の系列セレクターで、値を読み取る対象の系列を絞り込みます。Series matchers では、ダッシュボード内の他の変数を参照できます。

PromQL ラベル値フィルタは常に変数として扱われ、ブロードキャストされることはありません。PromQL タイルでは、`rate(http_requests_total{job=~"$job"}[$__rate_interval])` のようにラベルマッチャー内で参照します。値がどのようにレンダリングされるかについては、[変数の参照](#referencing-variables)を参照してください。

#### アドホックのキーと値 {#adhoc-filters}

アドホックフィルタでは、単一のドロップダウンの代わりに、閲覧者がソースのキーから `key operator value` 形式の条件リストを作成できます。キーは、SQL ソースではカラムとマップキー、Prometheus ソースではラベルです。閲覧者が入力するにつれて、キーと値の候補が表示されます。以下の項目を設定します。

* **Source type** — SQL(ログ、トレース、または session ソース)または Prometheus。
* **Data sources** — フィルタがキーと値の候補を取得するソース。
* **Keys and values filter** — 任意。SQL ソースのみ。キーと値の候補の抽出元となる行を絞り込む SQL または Lucene の条件です。ダッシュボードの他の変数を参照できます。
* **Applies to sources** — 条件のブロードキャスト先となるソース。空欄のままにすると、フィルタのデータソースのいずれかを使用するすべてのタイルにブロードキャストされます。
* **Unique name** — [ダッシュボードの URL](/ja/clickstack/observability/url-parameters#dashboard-filter-values) 内でフィルタの条件を識別する名前です。

SQL ソースの条件では、`=`、`!=`、`=~`(正規表現)、`!~`(正規表現)、`LIKE`、`NOT LIKE`、`IN` の演算子を使用できます。Prometheus ソースの条件では、`=`、`!=`、`=~`(正規表現)、`!~`(正規表現)、`IN` を使用できます。`LIKE` と `NOT LIKE` は SQL ソース専用です。

閲覧者は、ダッシュボード上のテーブル、時系列、検索の各タイルで値をクリックして条件を追加することもできます。

アドホック条件は常にブロードキャストされ、変数として参照することはできません。対象ソースを使用するチャートビルダータイルと PromQL タイルにはこれらの条件が自動的に適用され、生のSQLタイルでは [`$__filters` マクロ](/ja/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro) を通じて適用されます。

#### データソース {#data-source-variables}

データソース変数を使用すると、タイルがクエリを実行するソースを閲覧者が選択できるようになります。ドロップダウンに表示する **Source kinds** (例: ログソースのみ) を選択し、必要に応じて対象を 1 つの **Connection** に限定します。この Connection 自体に接続変数を指定することもできます。タイルやフィルタでの使用方法については、[データソース変数と接続変数](#source-connection-variables)を参照してください。

#### 接続 {#connection-variables}

接続変数を使用すると、生のSQLタイル、SQLクエリ値フィルタ、データソース変数で使用する ClickHouse 接続を閲覧者が選択できます。名前以外に設定項目はありません。

### データソース変数と接続変数 {#source-connection-variables}

データソース変数と接続変数は、クエリテキスト内の値ではなく、ログソースまたは接続IDの代わりとなる変数です。ログソースまたは接続のピッカーがこれらの変数に対応している箇所では、ダッシュボードの変数が **Variables** グループの下に一覧表示されます。いずれかを選択すると `$name` 参照が保存され、閲覧者が現在選択している値に解決されます。これにより、たとえば複数の環境のログや複数の ClickHouse クラスターを切り替えられるダッシュボードを 1 つで構築できます。

| 使用箇所             | データソース変数を受け付ける項目                 | 接続変数を受け付ける項目 |
| ---------------- | -------------------------------- | ------------ |
| チャートビルダーのタイル     | Source                           | —            |
| 生のSQLのタイル        | Source                           | Connection   |
| PromQL のタイル      | Source                           | —            |
| SQL式の値フィルタ       | Data source, Applies to sources  | —            |
| PromQL のラベル値フィルタ | Data source                      | —            |
| アドホックフィルタ        | Data sources, Applies to sources | —            |
| SQLクエリの値フィルタ     | Source                           | Connection   |
| データソース変数         | —                                | Connection   |

データソース変数は、そのソースの種類の少なくとも 1 つが適合する箇所でのみ選択肢として表示されます。たとえば PromQL タイルでは、PromQL ソースを許可するデータソース変数のみが表示されます。

タイルはログソースまたは接続がなければクエリを実行できないため、データソース変数と接続変数は常に単一選択かつ必須です。値が選択されるまで、その変数を参照するタイルとフィルタは待機状態になります。ダッシュボード全体を待機させたい場合は、**Block every tile** を有効にしてください。[ダッシュボードリンク](/ja/clickstack/observability/url-parameters#dashboard-filter-values)では、ログソースまたは接続を ID だけでなく名前でも指定できます。

<Note>
  データソース変数または接続変数を使用するタイルでは、アラートを利用できません。このようなタイルを保存すると、設定されていたアラートは削除されます。
</Note>

### 選択オプション {#filter-selection-options}

SQL式の値、静的な値、SQLクエリの値、PromQL ラベル値の各フィルタには、次の追加オプションがあります。

* **Single select** — 一度に選択できる値は 1 つだけです。
* **Required** — 変数またはブロードキャストを介してこのフィルタを使用するタイルは、フィルタで値が選択されるまで読み込まれません。
  * **Block every tile** — フィルタで値が選択されるまで、フィルタを使用するタイルだけでなく、ダッシュボード上のすべてのタイルをブロックします。

### チェーンフィルタ {#chained-filters}

フィルタ自体の設定ではダッシュボード内の他の変数を参照できるため、フィルタの値を別のフィルタの選択内容に連動させることができます。たとえば、`environment` フィルタで選択された環境内のサービスのみをサービスフィルタに一覧表示できます。変数は次の箇所で参照できます。

* SQL式の値フィルタの **Dropdown values filter** (例: `$__filter(ResourceAttributes['deployment.environment'], $environment)`)
* SQLクエリの値フィルタの **SQL query**
* PromQL ラベル値フィルタの **Series matchers** (例: `up{env="$env"}`)
* アドホックフィルタの **Keys and values filter**
* ログソースおよび接続のフィールド ([データソース変数と接続変数](#source-connection-variables)を使用)

参照先のフィルタの選択内容が変わると、依存するフィルタの値が再クエリされます。参照先の必須フィルタで何も選択されていない間は、それに依存するアドホックフィルタで条件を追加・編集できず、選択を待っているフィルタの名前が表示されます。

### ブロードキャスト {#broadcast-filters}

SQL式の値フィルタは選択内容をブロードキャストでき、アドホックフィルタは常にその条件をブロードキャストします。SQL式の値フィルタで **Broadcast filter condition** を有効にすると、選択した値がフィルタ条件としてダッシュボードのタイルに適用されます。各タイルで明示的にフィルタを参照する必要はありません。デフォルトでは、この条件はすべてのタイルに適用されます。**Applies to sources** を使用すると、適用対象を特定のソースを使用するタイルのみに限定できます。フィルタの式がダッシュボード上の一部のデータにしか意味を持たない場合に便利です。

チャートビルダーのタイルには、ブロードキャストフィルタが自動的に適用されます。生のSQLのタイルでは、[`$__filters` マクロ](/ja/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro) を含めたうえで、ログソースを選択しておく必要があります。手書きのクエリでは、条件をどこに挿入すべきかを UI が推論できないためです。

### 変数 {#dashboard-variables}

Static values、SQL query values、PromQL label values の各フィルタは常に変数として扱われます。SQL expression values フィルタは、**Available as variable** を有効にすると変数になります。変数を使うと、フィルタの選択値を `$variableName` としてタイルのクエリから参照できます。**Variable name** のデフォルトは、フィルタの表示名から使用できない文字を除いたものですが、上書きすることもできます。名前は英字で始める必要があり、使用できるのは英字、数字、アンダースコアのみです。

アドホックフィルタが変数になることはありません。また、データソース変数と接続変数は、クエリテキスト内の値ではなく、[ログソースまたは接続への参照](#source-connection-variables)です。

`WHERE` 条件をブロードキャストするだけでは目的に合わない場合は、変数を使用します。たとえば、値を `SELECT` 式、`HAVING` 句、結合キーで使用する場合や、フィルタ自体の式とは異なるカラムでタイルを絞り込む場合です。

#### 変数の参照 {#referencing-variables}

変数は、そのドロップダウンで現在選択されている値に展開されます。参照の形式によってレンダリング結果が決まります:

| 参照                  | 展開結果                                                                                                                            | 未選択時                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| `$name`, `${name}`  | 選択された値。コンテキストに応じて `sqlstring` または `lucene` フォーマットになります。`${name}_total` のように名前の直後に単語構成文字が続く場合は、波括弧で名前の範囲を区切ります。                  | `NULL`              |
| `${name:sqlstring}` | 選択された値を単一引用符で囲み、カンマで区切り、SQL の値としてエスケープしたもの。例: `'a', 'b'`                                                                        | `NULL`              |
| `${name:csv}`       | 引用符なしのカンマ区切り: `a,b`。SQL 向けのエスケープは行われません。                                                                                        | 空文字列                |
| `${name:regex}`     | 正規表現としてエスケープされた選択肢 (alternation): `(a\|b)`。                                                                                     | `.*`                |
| `${name:lucene}`    | Lucene 入力向けに、引用符で囲んだ語を `OR` で連結したもの: `("a" OR "b")`。                                                                            | `("")`              |
| `${name:promql}`    | PromQL タイルでのデフォルト。単一選択のフィルタの場合は選択された値になり、`label="$name"` の形で使用します。それ以外の場合は正規表現の選択肢 (alternation) になり、`label=~"$name"` の形で使用します。 | `.*` (単一選択の場合は空文字列) |

`$name` は何も選択されていない状態では `NULL` としてレンダリングされるため、SQL の述語を記述する箇所では以下のマクロの使用を推奨します。どちらのマクロも、対象の変数が未選択の間は `1=1` に展開されるため、クエリが無効になることはありません:

| マクロ                                           | 説明                                                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | `variable` で値が選択されている場合は `toString(<filter expression>) IN ($variable)` に、それ以外の場合は `1=1` に展開されます。 |
| `$__filter(<expression>, $<variable>)`        | `variable` で値が選択されている場合は `<expression> IN ($variable)` に、それ以外の場合は `1=1` に展開されます。                  |
| `$__conditionalAll(<condition>, $<variable>)` | 変数で値が選択されている場合は `<condition>` に、それ以外の場合は `1=1` に展開されます。                                           |

#### チャートビルダーのタイルで変数を使用する {#variables-in-builder-tiles}

チャートビルダーのSQL式入力欄では、すべて変数参照を使用できます。対象は `SELECT` カラムと系列ごとの式、`WHERE`、`GROUP BY`、`HAVING` です。エディタはダッシュボードの変数を自動補完し、現在の選択内容で各参照がどのように展開されるかを表示します。

SQLモードでは、変数の選択が空の場合でもクエリが有効になるよう、`$__filter` マクロと `$__conditionalAll` マクロの使用を推奨します。Lucene 入力ではマクロを使用できないため、代わりに未加工の変数を直接参照してください (例: `ServiceName:$service`) 。

Lucene 入力では、変数参照自体を引用符で囲むかどうかによって、複数値選択時の一致判定の方法が変わります。`$service` で `a,b` が選択されている場合は次のとおりです。

| 参照                       | 展開結果                                   | 一致判定の動作                                                                        |
| ------------------------ | -------------------------------------- | ------------------------------------------------------------------------------ |
| `ServiceName:$service`   | `ServiceName:("a" OR "b")`             | 部分文字列の一致 — SQL では `ServiceName ILIKE '%a%' OR ServiceName ILIKE '%b%'` に変換されます |
| `ServiceName:"$service"` | `(ServiceName:"a" OR ServiceName:"b")` | 選択された各値との完全一致                                                                  |

選択された値を部分文字列としてではなく `Field` と完全一致させたい場合は、変数参照を `Field:"$var"` のように引用符で囲んでください。

#### SQLタイルで変数を使用する {#variables-in-sql-tiles}

生のSQLタイルでも、同じ方法でクエリ内の任意の位置から変数を参照できます。

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

SQLタイルで使用できるマクロの一覧については、[SQLベースの可視化](/ja/clickstack/observability/features/dashboards/sql-visualizations#dashboard-variables)を参照してください。

<Note>
  ダッシュボード変数を参照しているタイルのアラートは、ダッシュボード上で選択された値ではなく、すべての変数が空の状態として評価されます。
</Note>

## 検索へのドリルダウン {#drilldown-to-search}

ダッシュボードタイルでは、検索ページへのドリルダウンが可能です。可視化内のデータポイントをクリックすると、次のオプションを含むコンテキストメニューが表示されます。

* **View All Events** — 選択した時間範囲のすべてのイベントを表示する検索ページに移動します。
* **Search** (系列の横にある虫眼鏡アイコン) — その系列の検索ページを開きます。
* **Copy label** — 系列のラベルをコピーします。
* **Focus** — チャート内の選択した系列にフォーカスします。

## プリセット {#presets}

UI には、すぐに使えるダッシュボードがあらかじめ用意されています。

### Services ダッシュボード {#services-dashboard}

Services ダッシュボードには、トレースデータに基づいて現在稼働中のサービスが表示されます。利用するには、トレースを収集し、有効な Traces データソースを設定しておく必要があります。

サービス名はトレースデータから自動検出されます。あらかじめ用意された一連の可視化は、**HTTP Service**、**Database**、**Errors** の 3 つのタブに分けて配置されています。

可視化は Lucene または SQL 構文でフィルタできます。また、時間ウィンドウを調整して、特定の期間に絞り込んだ分析も行えます。

### Kubernetesダッシュボード {#kubernetes-dashboard}

このダッシュボードでは、OpenTelemetry で収集した Kubernetes イベントを探索できます。高度なフィルタリングオプションを備えており、Kubernetes のポッド、デプロイメント、ノード名、ネームスペース、クラスターで絞り込めるほか、フリーテキスト検索も行えます。

Kubernetes データは「Pods」「Nodes」「Namespaces」の 3 つのタブに分かれているため、簡単に切り替えて閲覧できます。
