ClickHouse オブザーバビリティでは、生のSQLクエリに基づく可視化を作成できます。ダッシュボード単位の時間範囲、フィルタ、チャートのレンダリングとの連携を保ったまま、クエリロジックを完全に制御できます。

SQLベースの可視化は、組み込みの Chart Explorer では実現できない処理が必要な場合に役立ちます。たとえば、テーブルを結合する場合や、チャートビルダーではサポートされていない複雑な集計を構築する場合などです。

## SQLベースの可視化の作成 {#creating-a-raw-sql-chart}

SQLベースの可視化を作成するには、ダッシュボードタイルのエディタを開き、**SQL** を選択します。

<div className="ch-image-lg">
  <Frame>
    ![クエリの説明とマクロが表示されたSQL可視化エディタ](/images/clickstack/observability-sql-editor.png)
  </Frame>
</div>

続いて、次の手順を実行します。

1. クエリの実行先となる **接続** を選択します。
2. 必要に応じて **ログソース** を選択します。これにより、`$__filters` マクロを介してダッシュボードレベルのフィルタをチャートに適用できるようになります。
3. エディタでSQLクエリを記述します。クエリパラメータとマクロを使用すると、ダッシュボードの時間範囲、フィルタ、変数と連携できます。
4. **実行** をクリックして結果をプレビューし、**保存** をクリックして可視化を保存します。

## クエリパラメータ {#query-parameters}

[クエリパラメータ](/ja/reference/syntax#defining-and-using-query-parameters)を使用すると、SQL からダッシュボードで現在選択されている時間範囲と粒度を参照できます。クエリパラメータは、ClickHouse のパラメータ化クエリの構文 `{paramName:Type}` で記述します。

### 利用可能なパラメータ {#available-parameters}

利用できるパラメータはチャートの種類によって異なります。

**時系列チャート (積み上げ棒グラフを含む) ：**

| パラメーター                          | 型     | 説明                              |
| ------------------------------- | ----- | ------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | ダッシュボードの日付範囲の開始時刻 (エポックからのミリ秒)  |
| `{endDateMilliseconds:Int64}`   | Int64 | ダッシュボードの日付範囲の終了時刻 (エポックからのミリ秒)  |
| `{intervalSeconds:Int64}`       | Int64 | 時間バケットのサイズ (秒単位、粒度に基づく)         |
| `{intervalMilliseconds:Int64}`  | Int64 | 時間バケットのサイズ (ミリ秒単位、粒度に基づく)       |

**テーブル、円グラフ、Number チャート：**

| パラメーター                          | 型     | 説明                              |
| ------------------------------- | ----- | ------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | ダッシュボードの日付範囲の開始時刻 (エポックからのミリ秒)  |
| `{endDateMilliseconds:Int64}`   | Int64 | ダッシュボードの日付範囲の終了時刻 (エポックからのミリ秒)  |

## マクロ {#macros}

マクロは、よく使われる ClickHouse SQL の式に展開されるショートカットです。マクロには `$__` というプレフィックスが付いており、クエリが ClickHouse に送信される前に置換されます。

### 時間境界マクロ {#time-boundary-macros}

これらのマクロは、ダッシュボードの開始時刻または終了時刻を表す ClickHouse の式を返します。引数は取りません。

| マクロ              | 展開結果                                                                  | 列の型        |
| ---------------- | --------------------------------------------------------------------- | ---------- |
| `$__fromTime`    | `toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))` | DateTime   |
| `$__toTime`      | `toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))`   | DateTime   |
| `$__fromTime_ms` | `fromUnixTimestamp64Milli({startDateMilliseconds:Int64})`             | DateTime64 |
| `$__toTime_ms`   | `fromUnixTimestamp64Milli({endDateMilliseconds:Int64})`               | DateTime64 |
| `$__interval_s`  | `{intervalSeconds:Int64}`                                             | Int64      |

### 時間フィルタマクロ {#time-filter-macros}

これらのマクロは、カラムをダッシュボードの時間範囲で絞り込む `WHERE` 句のフラグメントを生成します。

| マクロ                                   | 説明                                         |
| ------------------------------------- | ------------------------------------------ |
| `$__timeFilter(column)`               | `DateTime` カラムをダッシュボードの時間範囲でフィルタします        |
| `$__timeFilter_ms(column)`            | `DateTime64`(ミリ秒)カラムをダッシュボードの時間範囲でフィルタします  |
| `$__dateFilter(column)`               | `Date` カラムをダッシュボードの時間範囲でフィルタします            |
| `$__dateTimeFilter(dateCol, timeCol)` | 別々の `Date` カラムと `DateTime` カラムを使用してフィルタします |
| `$__dt(dateCol, timeCol)`             | `$__dateTimeFilter` の別名                    |

`$__timeFilter(TimestampTime)` の**展開例**:

```sql
TimestampTime >= toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
AND TimestampTime <= toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
```

### 時間間隔マクロ {#time-interval-macros}

これらのマクロは、タイムスタンプ列をダッシュボードの粒度に合わせたインターバルごとにバケット化します。通常、時系列チャートの `SELECT` 句および `GROUP BY` 句で使用します。これらのマクロは、積み上げ棒グラフを含む **時系列** 可視化でのみ使用できます。

| マクロ                          | 説明                                                            |
| ---------------------------- | ------------------------------------------------------------- |
| `$__timeInterval(column)`    | `DateTime` カラムを `intervalSeconds` 単位のインターバルごとにバケット化します        |
| `$__timeInterval_ms(column)` | `DateTime64` カラムを `intervalMilliseconds` 単位のインターバルごとにバケット化します |

`$__timeInterval(TimestampTime)` の**展開例**：

```sql
toStartOfInterval(toDateTime(TimestampTime), INTERVAL {intervalSeconds:Int64} second)
```

### ダッシュボードフィルタマクロ {#dashboard-filter-macro}

| マクロ          | 説明                                         |
| ------------ | ------------------------------------------ |
| `$__filters` | ダッシュボードレベルのフィルター条件に置換されます (ログソースの選択が必要です)  |

チャートで**ログソース**が選択されており、ダッシュボードフィルタが有効な場合、`$__filters` は対応する SQL の `WHERE` 条件に展開されます。ログソースが選択されていない場合やフィルタが適用されていない場合は `(1=1)` に展開されるため、`WHERE` 句に常に安全に含めることができます。

`$__filters` で適用されるのは、**Broadcast filter condition** が有効になっているフィルタのみです。変数として公開されているフィルタは、後述のとおり明示的に参照します。

### ダッシュボード変数マクロ {#dashboard-variables}

ダッシュボードのフィルタが[変数として利用可能](/ja/clickstack/observability/features/dashboards/overview#dashboard-variables)な場合、選択された値はクエリ内のどこからでも参照できます。これらのマクロは、変数を1つ以上宣言しているダッシュボード内のタイルでのみ使用できます。

| マクロ                                           | 説明                                                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | `variable` で値が選択されている場合は `toString(<filter expression>) IN ($variable)` に、選択されていない場合は `1=1` に展開されます。 |
| `$__filter(<expression>, $<variable>)`        | `variable` で値が選択されている場合は `<expression> IN ($variable)` に、選択されていない場合は `1=1` に展開されます。                  |
| `$__conditionalAll(<condition>, $<variable>)` | 変数で値が選択されている場合は `<condition>` に、選択されていない場合は `1=1` に展開されます。                                           |

変数の値は `$name` または `${name}` として直接埋め込むこともでき、フォーマットを任意で指定できます(`${name:sqlstring}`(デフォルト)、`${name:csv}`、`${name:regex}`)。デフォルトのフォーマットでは、値が何も選択されていない状態で直接参照すると `NULL` としてレンダリングされます。そのため、述語を記述する箇所では上記のマクロを使用することを推奨します。

## クエリ結果のプロット方法 {#how-results-are-plotted}

UI は、カラム型に基づいて結果のカラムをチャートの各要素に自動的にマッピングします。マッピングのルールはチャートの種類によって異なります。

### 時系列チャート {#line-and-stacked-bar-charts}

| ロール         | 列の型                            | 説明                                   |
| ----------- | ------------------------------ | ------------------------------------ |
| **タイムスタンプ** | 最初の `Date` または `DateTime` カラム  | x 軸として使用されます。                        |
| **系列の値**    | すべての数値カラム                      | 各数値カラムはそれぞれ別の系列としてプロットされます。通常は集約値です。 |
| **グループ名**   | `String`、`Map`、または `Array` カラム | 任意。グループの値が異なる行は、それぞれ別の系列としてプロットされます。 |

### 円グラフ {#pie-chart}

| 役割           | 列の型                            | 説明                           |
| ------------ | ------------------------------ | ---------------------------- |
| **スライスの値**   | 最初の数値カラム                       | 各スライスのサイズを決定します。             |
| **スライスのラベル** | `String`、`Map`、または `Array` カラム | 任意。重複のない値それぞれがスライスのラベルになります。 |

### Number チャート {#number-chart}

| 役割     | 列の型   | 説明                      |
| ------ | -------- | ----------------------- |
| **数値** | 最初の数値カラム | 最初の数値カラムの最初の行の値が表示されます。 |

### 表形式のチャート {#table-chart}

結果のすべてのカラムが、そのまま表のカラムとして表示されます。

## 例 {#examples}

<Info>
  **例で使用するテーブル名**

  以下の例では `otel_logs` と `otel_traces` を使用しています。テーブル名とカラム名は、実際のデータに合わせて変更してください。[play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) で例を実行する場合は、`otel_v2.otel_logs` または `otel_v2.otel_traces` を使用してください。
</Info>

### 時系列チャート — サービスごとのログ件数の推移 {#example-line-chart}

このクエリは、ダッシュボードの粒度に合わせた時間間隔ごとに、サービス別のログイベント数を集計します。

```sql
SELECT
  toStartOfInterval(TimestampTime, INTERVAL {intervalSeconds:Int64} second) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

* `ts` (`DateTime`) は x 軸のタイムスタンプとして使用されます。
* `count` (数値) は系列の値としてプロットされます。
* `ServiceName` (文字列) によって、サービスごとに別々の線が描画されます。

### 時系列チャート — マクロを使用する場合 {#example-line-chart-macros}

同じクエリを、マクロを使用して簡潔に記述した例です。

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

### 時系列チャート — ダッシュボード変数を使用する {#example-line-chart-variables}

`ServiceName` に対する `service` 変数と、`SeverityText` に対する `severity` 変数を持つダッシュボードでは、このクエリによってチャートの対象が現在選択されているサービスに絞り込まれ、選択された重大度は除外されます。どちらのマクロも、対応する変数が未選択の間は `1=1` に展開されるため、閲覧者が値を選択するまで、チャートはフィルタなしでレンダリングされます。

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

### 積み上げ棒グラフ — 重大度別のエラー数 {#example-stacked-bar}

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  lower(SeverityText),
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND lower(SeverityText) IN ('error', 'warn')
  AND $__filters
GROUP BY SeverityText, ts
ORDER BY ts ASC
```

### 表形式のチャート — 最も遅いエンドポイント上位 10 件 {#example-table}

```sql
SELECT
  SpanName AS endpoint,
  avg(Duration) / 1000 AS avg_duration_ms,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY SpanName
ORDER BY avg_duration_ms DESC
LIMIT 10
```

### 円グラフ — サービス別のリクエスト分布 {#example-pie}

```sql
SELECT
  ServiceName,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY ServiceName
```

* `request_count` (数値) によって各スライスのサイズが決まります。
* `ServiceName` (文字列) は各スライスのラベルとして使用されます。

### Number チャート — エラー総数 {#example-number}

```sql
SELECT
  count() AS total_errors
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND SeverityText = 'error'
  AND $__filters
```

最初の行にある単一の数値 `total_errors` が表示されます。

## 注記 {#notes}

* SQLベースの可視化は `readonly` モードが有効な状態で実行されるため、`SELECT` クエリのみ実行できます。
* 各SQLベースの可視化で使用できるクエリは1つのみです。複数のクエリはサポートされていません。
* SQL エディタでは、クエリパラメータとマクロの両方で自動補完の候補が表示されます。
* SQLベースの可視化にダッシュボードのフィルタを適用するには、ログソースを選択する必要があります。正確にフィルタリングするため、ログソースはクエリ対象のテーブルと一致させてください。
* ダッシュボード変数にはログソースは不要です。値はタイル自体のログソースではなく、ダッシュボードのフィルタのドロップダウンから取得されます。
* ダッシュボード変数を参照するSQLタイルのアラートは、ダッシュボードで選択された値ではなく、すべての変数が空の状態で評価されます。
