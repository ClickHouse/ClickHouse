  **概要**

  このガイドでは、Telflo で管理されている OpenTelemetry コレクターから ClickHouse オブザーバビリティにテレメトリーを送信する方法を説明します。このガイドで学べる内容は次のとおりです。

  * Telflo のビジュアルエディターまたは CLI を使用してコレクター設定を作成する
  * 完全マネージド型またはセルフマネージドの ClickHouse オブザーバビリティにテレメトリーを送信する
  * コレクターのフリートに構成をリモートでデプロイする
  * ClickHouse オブザーバビリティでテレメトリーを参照できることを確認する

  所要時間: 15-20 分
</Info>

## Telflo とは？ {#what-is-telflo}

{/* vale on */}

Telflo は、OpenTelemetry コレクター向けのベンダー中立なコントロールプレーンで、フリート全体のコレクター構成を一元管理できます。ビジュアルエディター、パイプラインテスト、構成のリモートデプロイにより、大規模なフリートでも容易に管理できます。Telflo が管理するのは標準的なアップストリームの OpenTelemetry collector ビルドであり、Telflo 固有のディストリビューションや独自のエージェントは不要です。そのため、チームがすでに運用しているコレクターは同じビルドのまま使い続けられます。

Telflo はブラウザだけでなく、[コマンドラインインターフェイス](https://docs.telflo.com/docs/cli/)からも利用できます。これを [ClickStack MCPサーバー](/ja/clickstack/observability/mcp) と組み合わせれば、テレメトリーをクエリするエージェントが、そのテレメトリーを生成したパイプラインの修正まで行えるようになります。

{/* vale off */}

## Telflo + ClickHouse オブザーバビリティを選ぶ理由 {#why-telflo-clickstack}

{/* vale on */}

完全マネージド型の ClickHouse オブザーバビリティでは、インジェスト、スキーマ、ストレージ、スケーリングがすべて自動で処理されます。セルフマネージドの ClickHouse オブザーバビリティでは、インジェストとデータベースの設定をユーザー自身が管理し、基盤となるインフラストラクチャは ClickHouse Cloud が管理します。Telflo は、ホスト、クラスター、リージョンからいずれのデプロイメントにもテレメトリーを送信する OpenTelemetry コレクターを管理します。

Telflo の主な機能は次のとおりです。

* ホスト、コンテナ、Kubernetes にまたがる OpenTelemetry コレクターの一元管理
* ビジュアルなパイプライン編集と、フリート全体または特定のグループを対象とした段階的なロールアウト
* 本番環境のコレクターに反映する前の、サンプルテレメトリーによる変更の検証
* 同一のテレメトリーを ClickHouse オブザーバビリティとその他の宛先へ同時にルーティング
* フリートの可視化：オンラインのコレクター、各コレクターで実行中の内容、ドリフトが発生しているコレクターを把握

<Tip>
  **重要なポイント**

  * **ClickHouse オブザーバビリティは、データの保存と調査のためのエクスペリエンスを提供します**
  * **Telflo は、そこにデータを送るコレクターフリートを運用します**
</Tip>

## 前提条件 {#prerequisites}

* [完全マネージド型の ClickHouse オブザーバビリティサービス](/ja/clickstack/observability/getting-started)、または[セルフマネージドのデプロイメント](/ja/clickstack/self-configured/getting-started/managed)
* Telflo アカウント ([telflo.com でアカウントを作成](https://telflo.com))
* コレクターの実行環境：VM または Kubernetes クラスター
* **完全マネージド型**：**チーム設定 → Data → マネージドテレメトリー** で確認できる OTLP HTTPエンドポイントとインジェスト API key
* **セルフマネージド**：ClickHouse Cloud サービスのエンドポイント (ポート `8443`) と[インジェスト用ユーザー](/ja/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)、または既存のスタンドアロン collector のエンドポイントとその `OTLP_AUTH_TOKEN`
* Telflo が管理するコレクターから宛先エンドポイントへのネットワーク接続

## ClickHouse オブザーバビリティと Telflo の統合 {#integrate-telflo-clickstack}

{/* vale on */}

<Steps>
  <Step title="コレクター設定を作成する" id="build-configuration">
    1. Telflo にサインインします。**Configurations** 一覧で **New Configuration** をクリックし、続けて **Blank configuration** をクリックします。
    2. **Name Your Configuration** で名前を入力し、**Create** をクリックします。
    3. レシーバーを追加します。収集するテレメトリーの種類ごとに、パレットからキャンバスへレシーバーをドラッグします。
    4. プロセッサを追加します。**Memory Limiter** と **Batch** のほか、collector からデータを送出する前の整形に必要なプロセッサがあれば追加します。[Telflo がサポートするプロセッサの一覧](https://docs.telflo.com/docs/build/components#processors)を参照してください。
  </Step>

  <Step title="エクスポーターを追加する" id="add-exporter">
    デプロイメントに応じてエクスポーターを選択してください。完全マネージド型の ClickHouse オブザーバビリティは、マネージドの OTLP エンドポイント経由でテレメトリーを受け付けます。セルフマネージドのデプロイメントでは、ClickHouse に直接書き込むか、既に稼働している collector に OTLP で送信できます。

    <Tabs>
      <Tab title="完全マネージド型">
        <BetaBadge label="ベータ提供" />

        マネージドの OTLP エンドポイントを使用します。インジェスト、スキーマ、ストレージ、スケーリングは ClickHouse が担い、Telflo が管理するコレクターがお使いの環境からテレメトリーを収集して転送します。

        1. **OTLP/HTTP** エクスポーターをキャンバスにドラッグします。
        2. **Endpoint** に、ポート `4318` を含むマネージド OTLP HTTP エンドポイントを設定します (例: `https://<service-id>.otel.<region>.aws.clickhouse.com:4318`) 。
        3. **HTTP Headers** で **Add header** をクリックし、**Header name** に `Authorization`、**Header value** に `Bearer ${env:CLICKSTACK_INGESTION_KEY}` を入力します。コレクターのインストール時に、Telflo から環境変数の値の入力を求められます。`CLICKSTACK_INGESTION_KEY` にはインジェスト API キーを `Bearer` プレフィックスなしで指定してください。

        完全マネージド型のデプロイメントでは、直接書き込み型の ClickHouse exporter ではなく、OTLP エクスポーターを使用してください。
      </Tab>

      <Tab title="セルフマネージド">
        セルフマネージドの ClickHouse オブザーバビリティでは、インジェストをご自身で管理する必要があります。ClickHouse exporter による直接書き込みは、セルフマネージドのデプロイメントでのみ利用できます。ここで設定する collector は [インジェストゲートウェイ](/ja/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) として機能します。ClickHouse exporter とあわせて **OTLP** receiver を構成すると、ClickHouse Cloud サービスに書き込むようになります。SDK やエージェントのコレクターは、`4318` (HTTP) または `4317` (gRPC) でこの collector に OTLP を送信します。

        1. **ClickHouse** エクスポーターをキャンバスにドラッグします。
        2. **Endpoint** に ClickHouse Cloud サービスのエンドポイント (ポート `8443`) を入力し、**Database** を `default` に、**Username** をインジェスト用ユーザーに設定します。
        3. **Password** を `${env:CLICKHOUSE_PASSWORD}` に設定します。値はコレクターのインストール時に Telflo から入力を求められるため、設定にはパスワードそのものではなく環境変数への参照のみが含まれます。
        4. **Schema &amp; Tables** で、[テレメトリーテーブル](/ja/clickstack/self-configured/ingesting-data/schemas) がまだ存在しない場合は、**Create Schema on Startup** をオンのままにしておくと、エクスポーターがテーブルを作成します。テーブルの作成後はオフにしてください。

        **Batch** はエクスポーターの上流に配置してください。ClickHouse はバッチ挿入で最も高いパフォーマンスを発揮します。

        既に [スタンドアロンの OpenTelemetry collector](/ja/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured) を稼働している場合は、代わりに **OTLP/HTTP** エクスポーターを使用します。**Endpoint** をその collector の OTLP HTTP アドレス (ポート `4318`) に設定し、値を `${env:OTLP_AUTH_TOKEN}` とした `Authorization` ヘッダーを追加します。Telflo 管理のコレクターをインストールする際に、[collector に設定した認証トークン](/ja/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured) を指定してください。このトークンには `Bearer` プレフィックスを付けないでください。

        <div className="ch-image-lg">
          <Frame>
            ![ClickHouse exporter が設定された、Telflo エディター上のセルフマネージド collector パイプライン](/images/clickstack/telflo/telflo-configuration.webp)
          </Frame>
        </div>
      </Tab>
    </Tabs>

    シグナルごとに 1 つのパイプラインとなるよう、receiver からプロセッサーを経由してエクスポーターまでエッジをつなぎます。ステータス行には **config valid** または修正が必要なエラーの数が表示され、**YAML** タブでは生成された設定を確認できます。

    ロールアウトの前に、サンプルのテレメトリーを設定に流して出力結果を確認できます。詳しくは [Telflo でのテスト](https://docs.telflo.com/docs/testing/overview) を参照してください。また、やりたいことを説明するだけで、ツールバーの **AI** ボタンから開く Telflo AI アシスタントが設定の構築、検証、テストを代行することもできます。ご自身のエージェントからも、[Telflo CLI](https://docs.telflo.com/docs/cli/) を使って同様の操作が可能です。
  </Step>

  <Step title="バージョンを公開" id="publish-version">
    ツールバーの **Publish** をクリックします。公開済みのバージョンは読み取り専用です。引き続き編集するには、**Create New Version** をクリックしてください。
  </Step>

  <Step title="フリートを作成してロールアウトする" id="deploy-collectors">
    1. **Fleet** に移動して **New Fleet** をクリックし、コレクターの実行場所 (VM または Kubernetes) を選択します。**Name** を入力し、**Create fleet** をクリックします。
    2. フリートの **Deploy Groups** タブで、デプロイ先のグループの **Assign** をクリックし、パブリッシュ済みの設定とバージョンを選択します。フリート全体にロールアウトする前に、まず小規模なグループでインジェストを検証してください。
    3. グループの **Install** をクリックし、設定で参照している各環境変数の値を入力します。入力した値は Telflo によってインストールコマンドに追加されます。[Telflo のインストール手順](https://docs.telflo.com/docs/fleet-management/install-collectors)に従い、コレクターを実行する環境でこのコマンドを実行します。このコマンドには入力した値に加えてフリートのインストールトークンも含まれるため、機密情報として扱ってください。
    4. **Collectors** タブでは、コレクターのステータスが **Pending pickup**、**Applying**、**In sync** の順に遷移します。

    変更をロールアウトするには、新しいバージョンをパブリッシュしてグループに割り当てます。ロールバックするには、以前にデプロイしたバージョンを割り当てます。

    <div className="ch-image-lg">
      <Frame>
        ![ロールアウト後、すべてのコレクターが同期済みになった Telflo フリート](/images/clickstack/telflo/telflo-fleet.webp)
      </Frame>
    </div>
  </Step>

  <Step title="テレメトリーを確認する" id="verify-telemetry">
    ClickHouse Cloud コンソールで、対象サービスの ClickHouse オブザーバビリティを開きます。**検索** ビューでいずれかのサービスを検索し、メトリクスの確認には **Chart Explorer** を使用します。フリート内の残りのコレクターに設定を展開する前に、想定どおりのログ、トレース、メトリクスが届いていることを確認してください。
  </Step>
</Steps>

## 高度な設定 {#advanced-configuration}

### ファンアウトルーティング {#fan-out-routing}

同じテレメトリーを、長期保存用の ClickHouse オブザーバビリティ、移行期間中の別プラットフォーム、セキュリティ分析用の SIEM へ同時に送信できます。キャンバス上にエクスポーターを追加し、データの送信元となるパイプラインに接続してください。または、[Telflo のフローライブラリ](https://telflo.com/flows)にある既製のパイプラインを起点にすることもできます。

### 圧縮とパフォーマンス {#compression-and-performance}

* **OTLP/HTTP および OTLP エクスポーター**: **圧縮** は gzip のままにしてください。
* **ClickHouse exporter (セルフマネージドのみ)&#x20;**: **Async Insert** は有効のままにし、**圧縮** は lz4 のままにしたうえで、その前段に **Batch** プロセッサーを追加してください。詳しくは [挿入処理の最適化](/ja/clickstack/self-configured/ingesting-data/collector#optimizing-inserts-self-configured) を参照してください。

## 次のステップ {#next-steps}

* **ダッシュボードを作成する**: ClickHouse オブザーバビリティで、ログ、メトリクス、トレースの可視化を作成します
* **アラートを設定する**: ClickHouse オブザーバビリティで、重大な状態を検知するアラートを設定します
* **Telflo AIアシスタントで改善する**: パイプラインの調整やテストの提案を依頼できます
* **他のベンダーから移行する場合**: [flows](https://telflo.com/flows) で切り替えに対応できます。フリートで稼働中の既存エージェントを置き換え、比較検証の間は両方のバックエンドにデータを並行送信します
