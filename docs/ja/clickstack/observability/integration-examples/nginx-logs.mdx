OpenTelemetry collector を使用して Nginx から JSON 形式のアクセスログを収集し、ClickHouse オブザーバビリティに送信します。Nginx 環境がまだない場合でも、[デモデータセット](#demo-dataset)を使ってこのインテグレーションを試せます。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* 以下の collector コマンドを実行するための Docker、または既存の OpenTelemetry Collector Contrib のデプロイメント
* 独自のログを使用する場合は、既存の Nginx 環境、その設定を編集するためのアクセス許可、および collector からそのログファイルへのアクセス

Nginx をセットアップしたり独自のログを収集したりせずにインテグレーションを試す場合は、[デモデータセット](#demo-dataset)を使用してください。デモデータセットには、サンプルデータ用のスタンドアロンのコレクター設定が含まれています。

### 接続情報 {#demo-connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。**Copy connection details** で設定をまとめてコピーするか、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用する場合は、collector を実行する端末で次の変数を設定してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスの正確なエンドポイント (ポートを含む) とAPIキーに置き換えてください。エンドポイントには `/v1/logs` 接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に追記します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTPエンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを省略してください。セットアップ手順については、[セルフマネージド版スタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。Docker Desktop ホスト上で collector を実行する場合は、`localhost` ではなく `host.docker.internal` を使用してください。Linux では、共有 Docker ネットワークを使用して宛先コンテナの名前を指定するか、接続可能な別のホストアドレスを使用してください。

## 既存の Nginx との連携 {#existing-nginx}

Nginx のアクセスログを読み取れるホスト上で collector を実行します。collector はログをパースし、サービスの OTLP HTTP エンドポイントに転送します。

<Steps>
  <Step title="Nginxのログ形式を設定する" id="configure-nginx">
    `nginx.conf` で、Nginx が JSON 形式のアクセスログを出力するように設定します。

    `nginx.conf` ファイルは通常、次の場所にあります。

    * **Linux (apt/yum)**: `/etc/nginx/nginx.conf`
    * **macOS (Homebrew)**: `/usr/local/etc/nginx/nginx.conf` または `/opt/homebrew/etc/nginx/nginx.conf`
    * **Docker**: 通常、設定はボリュームとしてマウントされています

    既存の `http` ブロック内に次のディレクティブを追加します。その他の設定はそのまま残し、同じファイルを対象とする `access_log` ディレクティブがすでにある場合は置き換えてください。

    ```nginx
    log_format json_combined escape=json
    '{'
      '"time_local":"$time_local",'
      '"remote_addr":"$remote_addr",'
      '"remote_user":"$remote_user",'
      '"request":"$request",'
      '"status":$status,'
      '"body_bytes_sent":$body_bytes_sent,'
      '"request_time":$request_time,'
      '"upstream_response_time":"$upstream_response_time",'
      '"http_referer":"$http_referer",'
      '"http_user_agent":"$http_user_agent",'
      '"http_x_forwarded_for":"$http_x_forwarded_for",'
      '"http_host":"$http_host"'
    '}';

    access_log /var/log/nginx/access.log json_combined;
    ```

    このフォーマットはデモデータセットと同じフィールド名を使用しており、メソッド、URI、HTTP バージョンを含む `request` もその一つです。[Nginx は複数のアップストリームの応答時間を報告する場合がある](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#var_upstream_response_time)ため、`upstream_response_time` は文字列のまま保持しています。なお、デモデータセットではこのフィールドに単一の数値が格納されています。

    `nginx -t` で設定を検証したうえで、ご利用のデプロイメントにおける通常の手順で Nginx を再読み込みしてください。`server` または `location` ブロックで `access_log` をオーバーライドしている場合は、そのディレクティブも `json_combined` を使用するように更新してください。
  </Step>

  <Step title="collectorを設定する" id="custom-otel">
    [接続情報](#demo-connection-details)を取得し、collector を実行する端末でエンドポイントと API キーの環境変数を設定します。次の完全な設定を `nginx-monitoring.yaml` として保存します。

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx/access.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx
          - type: add
            field: resource["service.name"]
            value: nginx

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx:
          receivers: [filelog/nginx]
          processors: [memory_limiter, batch]
          exporters: [otlp_http/observability]
    ```

    この設定では、JSON形式の新しいアクセスログエントリを読み取り、元のタイムスタンプを保持したまま、`service.name` を `nginx` に設定します。ログは、上記の認証設定を使用して OTLP HTTPエンドポイントに転送されます。Nginx のエラーログには別途パーサーが必要なため、この設定の対象外です。
  </Step>

  <Step title="collectorを実行する" id="load-custom">
    以下のコマンドは、Docker ホスト上のログディレクトリが `/var/log/nginx` であることを前提としています。ログファイルが別の場所にある場合は、ログのマウント設定のホスト側パスを変更してください。Nginx をコンテナで実行している場合は、代わりにその共有ログボリュームを collector にマウントしてください。

    `nginx-monitoring.yaml` があるディレクトリで、次のコマンドを実行します。

    ```bash
    docker run --rm --name nginx-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/nginx:/var/log/nginx:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector はフォアグラウンドで実行されます。また、マウント済みのログファイルを読み取るアクセス許可が必要です。collector を実行したまま、別の端末またはブラウザから Nginx にリクエストを何件か送信し、新しいアクセスログエントリを書き込ませてください。
  </Step>

  <Step title="ClickHouse オブザーバビリティでログを確認する" id="verifying-logs">
    1. UI で **検索** を開き、**ログ** を選択します。
    2. `ServiceName:nginx` でフィルタし、リクエストを送信した期間を含む時間範囲を選択します。
    3. エントリを展開して **カラム値** を選択し、`LogAttributes` 配下の `request`、`request_time`、`upstream_response_time` などのフィールドを確認します。

    次の例は、デモデータセットを使用し、`ServiceName:nginx-demo` で絞り込んだ同じビューを示しています。

    <div className="ch-image-lg">
      <Frame>
        ![サービス名でフィルタした Nginx デモログ。展開したエントリにパース済みのログ属性が表示されている](/images/clickstack/observability-nginx-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルデータセットには、成功したリクエスト、エラー、アップストリームのレスポンス時間を含む、JSON 形式のアクセスログエントリが 14,743 件収録されています。Docker と ClickHouse オブザーバビリティのサービスが必要です。開始前に[接続用の環境変数](#demo-connection-details)を設定し、ダウンロードしたファイルと設定ファイルを同じディレクトリに置いてください。

<Steps>
  <Step title="サンプルデータセットをダウンロードする" id="download-sample">
    ```bash
    # ログをダウンロード
    curl -O https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/access.log
    ```
  </Step>

  <Step title="テスト用の コレクター設定を作成する" id="test-config">
    以下の設定一式を `nginx-demo.yaml` として保存します。collector はダウンロードしたアクセスログを読み込み、OTLP エンドポイントに転送します。

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx-demo/access.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx-demo
          - type: add
            field: resource["service.name"]
            value: nginx-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-21T16:34:27Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx-demo:
          receivers: [filelog/nginx]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      デモ専用の `transform/demo_timestamps` プロセッサーは、トラフィックパターンを維持したまま、サンプルのタイムスタンプをおおよそ直近 24 時間 (インジェストの 2 分前まで) の範囲にシフトします。元の `time_local` 属性とログのボディは変更されません。独自の Nginx ログを扱う場合は、元のタイムスタンプが保持されるよう、このプロセッサーを省略してください。
    </Note>

    スタンドアロンの collector の例では、これらの設定の検証に使用した OpenTelemetry Collector Contrib `0.161.0` を使用しています。
  </Step>

  <Step title="デモ collector を実行する" id="run-demo">
    `access.log` と `nginx-demo.yaml` があるディレクトリで、OpenTelemetry Collector Contrib イメージを実行します。

    ```bash
    docker run --rm --name nginx-demo-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/access.log:/var/log/nginx-demo/access.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    インジェストを確認し終えるまで、この端末は開いたままにしてください。マウントする 2 つのファイルは、いずれもコンテナから読み取れる必要があります。ログが表示されたら、**Ctrl+C** を押してデモ collector を停止します。このデモではファイルオフセットを永続化しないため、再実行するとタイムスタンプが改めてシフトされ、データセットが再度取り込まれます。
  </Step>

  <Step title="ClickHouse オブザーバビリティでログを確認する" id="verify-demo-logs">
    collector の起動後:

    1. UI を開きます。
    2. **Search** に移動し、**Logs** を選択して、`ServiceName:nginx-demo` でフィルタします。
    3. シフト後のデータセット全体が含まれるよう、時間範囲を **過去2日間** に設定します。

    ログエントリを展開して **Column Values** を選択すると、`LogAttributes` 配下のパース済みフィールドを確認できます。

    <div className="ch-image-lg">
      <Frame>
        ![サービス名でフィルタされた Nginx デモログと、パース済みのログ属性を表示した展開エントリ](/images/clickstack/observability-nginx-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### collector が起動しない {#troubleshooting-not-loading}

collector の端末出力に設定エラーが出ていないか確認してください。また、マウントしたパスに YAML ファイルが存在することも確認してください。OTLP エクスポーターの設定を使用している場合は、Docker を実行する端末で、エンドポイント用の変数と必要な認証用の変数が設定されているかを確認してください。

### ログが表示されない {#no-logs}

* collector の出力に認証エラーやエクスポートエラーがないか確認してください。OTLP エクスポーターを使用している場合は、エンドポイントと認証ヘッダーが[接続情報](#demo-connection-details)と一致しているか確認してください。
* Nginx が JSON 形式のアクセスログを書き込んでいること、および collector がそのログを読み取れることを確認してください。`start_at: end` を指定している場合は、collector の起動後に新しいリクエストを発生させてください。
* 選択中の **Logs** ログソースとサービス名フィルターを確認してください。デモデータセットの場合は `ServiceName:nginx-demo`、独自のログの場合は `ServiceName:nginx` を指定します。
* ログが含まれるように時間範囲を設定してください。デモの場合は、`transform/demo_timestamps` がパイプラインに含まれていることを確認したうえで、**過去2日間** を選択してください。

独自の Nginx ログの場合は、ホスト上のファイルを確認し、collector コンテナのマウントを調べてください。マウント先のパスが receiver の設定と一致していることを確認します。`CONTAINER_NAME` を collector コンテナの名前に置き換え、必要に応じてホスト側のパスを調整してください：

```bash
tail -f /var/log/nginx/access.log
docker inspect --format '{{json .Mounts}}' CONTAINER_NAME
```
