OpenTelemetry collector を使用して PostgreSQL の CSV ログを収集し、ClickHouse Observability に送信します。PostgreSQL をインストールせずにこのインテグレーションを試す場合は、[デモデータセット](#demo-dataset)をご利用ください。

## 前提条件 {#prerequisites}

* ClickHouse Observability サービス
* collector の例を実行するための Docker
* 独自のログを使用する場合は、PostgreSQL 14 以降、およびその設定ファイルとログファイルへのアクセス権
* デモを実行する場合は、サンプルをダウンロードするための `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ提供" />

    ClickHouse Observability を開き、**チーム設定 → Data → Managed Telemetry** に移動します。OTLP HTTP エンドポイントと APIキーをコピーしてください。**接続情報をコピー** で設定をまとめてコピーするか、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry の接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用するには、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスの正確なエンドポイント(ポートを含む)と APIキーに置き換えてください。エンドポイントには `/v1/logs` などの接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルごとのパスはエクスポーターが付加します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTP エンドポイント(例: `http://YOUR_COLLECTOR_HOST:4318`)と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージドの入門ガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。宛先の collector をこのコンピューター上で実行している場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドにはホストのマッピングが含まれています。

## 既存の PostgreSQL との連携 {#existing-postgres}

<Steps>
  <Step title="PostgreSQLのログを設定する" id="configure-postgres">
    データベース管理者として次の SQL を実行し、設定ファイルの場所を確認します。

    ```sql
    SHOW config_file;
    ```

    `postgresql.conf` で以下の設定を追加または更新します：

    ```conf
    logging_collector = on
    log_destination = 'csvlog'
    log_directory = '/var/log/postgresql'
    log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
    log_file_mode = 0640
    log_timezone = 'UTC'
    log_connections = on
    log_disconnections = on
    # Optional: log statements taking more than one second
    # log_min_duration_statement = 1000
    ```

    PostgreSQL が書き込みでき、collector が読み取れるように所有権とアクセス許可を設定して、ログディレクトリを作成します。コンテナ化された PostgreSQL の場合は、collector が同じファイルにアクセスできるよう、そのディレクトリをマウントしてください。なお、`log_filename` の末尾が `.log` であっても、CSV 出力のファイルには `.csv` 拡張子が付きます。

    ご利用のデプロイ手順に従って PostgreSQL を再起動します。例:

    ```bash
    sudo systemctl restart postgresql
    # Or, for Docker:
    docker restart <postgres-container>
    ```

    現在使用中の CSV ファイルを確認します。

    ```sql
    SELECT pg_current_logfile('csvlog');
    ```

    以下のパーサーは、[26 カラムの PostgreSQL CSV 形式](https://www.postgresql.org/docs/14/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-CSVLOG)を前提としています。それより前の PostgreSQL バージョンや、その他のログ形式を使用する場合は、別のパーサーが必要です。
  </Step>

  <Step title="collector を設定する" id="configure-collector">
    次の内容を `postgres-logs-monitoring.yaml` として保存します。

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql-*.csv
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql"

          - type: add
            field: resource["service.name"]
            value: "postgresql-service"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    receiver は複数行にまたがる CSV エントリをパースし、タイムスタンプとボディを保持したまま、`service.name` を `postgresql-service` として付与します。`database_name`、`error_severity`、`message`、`query` などのフィールドは、引き続きログ属性として利用できます。
  </Step>

  <Step title="collectorを実行する" id="run-collector">
    設定ファイルを含むディレクトリで、次のコマンドを実行します。必要に応じて、ホスト側のログディレクトリを変更してください。ログファイルがグループ読み取り権限で保護されている場合は、`--group-add LOG_GROUP_ID` を追加し、`LOG_GROUP_ID` には `ls -ln /var/log/postgresql` で表示される数値のグループ ID を指定します。

    ```bash
    docker run --rm --name postgres-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/postgresql:/var/log/postgresql:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    端末は開いたままにしておいてください。receiver は `start_at: end` を使用するため、collector の起動後に新しいデータベース接続を作成するか、エラーが発生するクエリを実行してください。

    ```sql
    SELECT 1 / 0;
    ```
  </Step>

  <Step title="ログを確認する" id="verify-logs">
    **検索**を開いて **Logs** を選択し、`ServiceName:postgresql-service` でフィルタしてから、**Last 15 minutes** を選択します。レコードを展開すると、PostgreSQL の属性と重大度を確認できます。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、接続アクティビティ、クエリ、サーバーエラーを含む 21,325 件の PostgreSQL CSV レコードが収録されています。

<Steps>
  <Step title="サンプルデータセットをダウンロード" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/postgres/postgresql.log
    ```
  </Step>

  <Step title="デモ用のcollectorを設定する" id="configure-demo">
    以下の内容を `postgres-logs-demo.yaml` として保存します。

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql-demo"

          - type: add
            field: resource["service.name"]
            value: "postgresql-demo"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-10T23:59:47Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    デモ専用のタイムスタンププロセッサーは、サンプルデータを過去 24 時間の範囲にシフトし、インジェストの 2 分前に終わるよう調整します。元のタイムスタンプ属性とログのボディは変更されません。独自の PostgreSQL ログを使用する場合は、このプロセッサーを省略してください。
  </Step>

  <Step title="デモ用のcollectorを実行する" id="run-demo">
    設定ファイルとダウンロードしたログファイルを格納したディレクトリで、次のコマンドを実行します。

    ```bash
    docker run --rm --name postgres-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/postgresql.log:/var/log/postgresql/postgresql.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    インジェストの確認中は、端末を開いたままにしておいてください。確認が終わったら、**Ctrl+C** で collector を停止します。デモを再度実行すると、タイムスタンプを更新したうえでサンプルデータが再度取り込まれます。
  </Step>

  <Step title="デモのログを確認する" id="verify-demo">
    **検索** を開いて **Logs** を選択し、`ServiceName:postgresql-demo` でフィルタしたうえで、**Last 2 days** を選択します。レコードを展開すると、`database_name`、`error_severity`、`message`、`query` などのフィールドを確認できます。

  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### collector が起動しない {#collector-fails-to-start}

collector の出力に設定エラーがないか確認してください。また、Docker を実行している端末で、設定ファイルのマウントと接続用の変数が正しいかを確認してください。

### ログが表示されない {#no-logs}

認証エラーやエクスポートエラーが発生していないか確認してください。`pg_current_logfile` で CSV のパスを確認し、ファイルが receiver の `include` パターンに一致していること、および collector がそれらのファイルを読み取れることを確認してください。`start_at: end` を指定している場合、収集されるのは新しいエントリのみです。デモでは、タイムスタンプ用のプロセッサーを追加したうえで、**Last 2 days** を選択してください。

### アクセス許可が拒否される {#permission-denied}

PostgreSQL は通常、所有者のみがアクセスできるログファイルを作成します。上記の設定では `log_file_mode = 0640` を指定して、グループによる読み取りを許可しています。`--group-add` を使用して、ファイルの所属グループを collector コンテナに追加してください。なお、既存のファイルのアクセス許可は変更されません。ディレクトリについても、グループによるアクセスが許可されていることを確認してください。

### CSV の構文解析エラー {#csv-parsing-errors}

このパーサーは、PostgreSQL 14 以降で出力される 26 個のカラムを前提としています。`log_destination = 'csvlog'` および `log_timezone = 'UTC'` が設定されていることを確認してください。古いバージョンやカスタムフォーマットを使用している場合は、ヘッダーを調整してください。なお、stderr 形式および JSON 形式のログには、この CSV パーサーを使用できません。
