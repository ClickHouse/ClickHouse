OpenTelemetry の自動計装を使用して Node.js アプリケーションからトレースを収集し、ClickHouse Observability に送信します。アプリケーションをインストルメントせずにこの連携を試す場合は、[デモデータセット](#demo-dataset)を使用してください。

## 前提条件 {#prerequisites}

* ClickHouse Observability サービス
* アプリケーション側: Node.js 22 以降と npm
* デモ用: Docker と `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版" />

    ClickHouse Observability を開き、**チーム設定 → Data → Managed Telemetry** に移動します。OTLP HTTP エンドポイントと APIキーをコピーしてください。**Copy connection details** で設定をまとめてコピーするか、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry の接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    アプリケーションまたはデモ用 collector を実行する端末で、次の接続変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスで確認したエンドポイント (ポート番号を含む) と APIキーにそのまま置き換えてください。エンドポイントには `/v1/traces` 接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルごとのパスはエクスポーターが自動的に付加します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTP エンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の設定からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージドの入門ガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## 既存の Node.js アプリケーションとの連携 {#existing-nodejs}

<Steps>
  <Step title="OpenTelemetry をインストールする" id="install-instrumentation">
    アプリケーションのディレクトリで、インストルメンテーションパッケージをインストールします。

    ```bash
    npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node@0.81.0
    ```

    この手順では、CommonJS アプリケーション向けの [OpenTelemetry 自動計装](https://opentelemetry.io/docs/zero-code/js/) を使用します。ネイティブ ES モジュールの場合は [ESM セットアップ](https://github.com/open-telemetry/opentelemetry-js/blob/main/doc/esm-support.md) が必要です。スパンの重複を避けるため、インストルメンテーションのセットアップは 1 つのアプリケーションにつき 1 つだけにしてください。
  </Step>

  <Step title="トレーシングを設定してアプリケーションを起動する" id="run-application">
    接続用の変数を設定した端末で、次のコマンドを実行します。

    ```bash
    export OTEL_SERVICE_NAME='nodejs-service'
    export OTEL_TRACES_EXPORTER='otlp'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="Authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='none'
    export OTEL_LOGS_EXPORTER='none'

    node --require @opentelemetry/auto-instrumentations-node/register app.js
    ```

    `app.js` はアプリケーションのエントリーポイントに置き換えてください。プリロードにより、アプリケーションがライブラリをインポートする前にインストルメンテーションが初期化されます。認証を使用しないセルフマネージドのエンドポイントの場合は、ヘッダーの export を省略し、`unset OTEL_EXPORTER_OTLP_HEADERS` を実行してください。

    エンドポイントはアプリケーションから接続可能である必要があります。アプリケーションがコンテナ内で実行されている場合、`localhost` はそのコンテナ自身を指します。
  </Step>

  <Step title="トラフィックを生成する" id="generate-traffic">
    アプリケーションが提供するエンドポイントにリクエストを送信します。たとえば、ポート `3000` で待ち受けているアプリケーションの場合は次のとおりです。

    ```bash
    curl http://localhost:3000/
    ```

    エクスポーターがスパンを送信するまで、数秒ほど待ちます。
  </Step>

  <Step title="トレースを確認する" id="verify-traces">
    **検索** を開き、**トレース** を選択して `ServiceName:nodejs-service` でフィルタし、**Last 15 minutes** を選択します。トレースを開くと、スパン、タイミング、属性を確認できます。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、`nodejs-demo-api` の 822 件のスパンが含まれています。実行中の Node.js アプリケーションは不要です。

<Steps>
  <Step title="サンプルデータセットをダウンロードする" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nodejs/nodejs-traces-sample.json
    ```
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo-collector">
    ダウンロード先のディレクトリに、以下の内容を `nodejs-traces-demo.yaml` として保存します。

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T17:59:15Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nodejs-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      デモ専用の `transform/demo_timestamps` プロセッサーは、スパンの所要時間とトラフィックパターンを維持したまま、このサンプルのタイムスタンプを、取り込みの 2 分前を終点とするおよそ直近 24 時間の範囲にシフトします。独自の Node.js トレースを送信する場合は、元のタイムスタンプが保持されるよう、このプロセッサーを含めないでください。サンプルを再送信すると、スパンが重複する場合があります。
    </Note>
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo-collector">
    <Note>
      送信先の collector がこのコンピューター上で動作している場合は、`OTEL_EXPORTER_OTLP_ENDPOINT` を `http://host.docker.internal:4318` に設定してください。以下のコマンドには Docker ホストのマッピングが含まれています。
    </Note>

    接続用の変数を設定した端末で、設定ファイルがあるディレクトリから OpenTelemetry Collector Contrib `0.161.0` を実行します。この端末は開いたままにしておいてください。

    ```bash
    docker run --rm --name nodejs-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nodejs-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    ローカルの receiver は、ポート `4318` で動作している既存の collector と競合しないよう、ポート `14318` を使用します。collector は、上記の認証設定を使って、設定済みのエンドポイントにトレースを転送します。
  </Step>

  <Step title="トレースを送信する" id="send-traces">
    別の端末を開き、ダウンロード先のディレクトリで、元のサンプルをローカルの collector に送信します。

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nodejs-traces-sample.json
    ```

    `{}` や `{"partialSuccess":{}}` のような空の成功レスポンスが返れば、ローカルの collector がリクエストを受け付けています。collector の出力にエクスポートエラーがないか確認し、バッチがサービスに届くまで数秒待ちます。完了したら **Ctrl+C** でデモ用 collector を停止します。
  </Step>

  <Step title="デモトレースを確認する" id="verify-demo-traces">
    **検索** を開いて **トレース** を選択し、`ServiceName:nodejs-demo-api` でフィルタリングします。シフト後のデータセット全体が表示されるよう、**Last 2 days** を選択してください。トレースを開くと、HTTP 属性を確認できます。

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability の検索画面に表示された Node.js デモトレース](/images/clickstack/observability-nodejs-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### アプリケーションのトレースが表示されない {#no-application-traces}

アプリケーションの出力にエクスポートエラーが出ていないか確認してください。また、エンドポイント、プロトコル、認証の設定に誤りがないか確認してください。インストルメンテーションはアプリケーションのライブラリより先に読み込み、リクエストを発生させたうえで、サービス名のフィルタと時間範囲を確認してください。ネイティブ ES モジュールを使用している場合は、リンク先の ESM のセットアップ手順に従ってください。

### デモのトレースが表示されない {#no-demo-traces}

デモ用 collector の出力に、認証エラーやエクスポートエラーが出ていないか確認してください。`curl` で成功の応答が返れば、ローカルで受け付けられたことになります。サービスへの転送には数秒かかる場合があるため、少し待ってから確認してください。パイプラインに `transform/demo_timestamps` が含まれていることを確認し、**Last 2 days** を選択してください。なお、サンプルを再送信するとデータが重複する可能性があります。
