OpenTelemetry の `filelog` receiver を使用して MongoDB サーバーログを収集し、ClickHouse Observability に送信します。MongoDB 環境がなくても、[デモデータセット](#demo-dataset)を使用してこの連携を試すことができます。

## 前提条件 {#prerequisites}

* ClickHouse Observability サービス
* Docker と `curl`
* 独自のログを使用する場合は、セルフマネージドの MongoDB 4.4 以降のデプロイメント (JSON ログファイルにアクセスできること)

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ提供" />

    ClickHouse Observability を開き、**チーム設定 → Data → Managed Telemetry** に移動します。OTLP HTTP エンドポイントと APIキーをコピーしてください。**Copy connection details** で設定をまとめてコピーでき、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry の接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用するため、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスの正確なエンドポイント (ポート番号を含む) と APIキーに置き換えてください。エンドポイントには `/v1/logs` などの接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルごとのパスはエクスポーターが自動的に付加します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTP エンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージド版のスタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。宛先の collector がこのコンピューター上で実行されている場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、このホストのマッピングが含まれています。

## 既存の MongoDB との連携 {#existing-mongodb}

<Steps>
  <Step title="MongoDB のロギング設定を確認する" id="verify-mongodb">
    MongoDB 4.4 以降では、サーバーログが構造化された JSON 形式で出力されます。MongoDB の設定ファイル内の `systemLog` セクションを確認してください。Linux での一般的なログのパスは `/var/log/mongodb/mongod.log` です。

    MongoDB が stdout にのみログを出力している場合は、`mongod.conf` でファイルへのロギングを設定します。

    ```yaml
    systemLog:
      destination: file
      path: /var/log/mongodb/mongod.log
      logAppend: true
    ```

    MongoDB が書き込みでき、collector が読み取れる権限でディレクトリを作成します。コンテナ環境でデプロイしている場合は、ログディレクトリを collector と共有し、MongoDB が設定ファイルを読み込むようにしてください。

    ご利用のデプロイ手順に従って MongoDB を再起動します。例:

    ```bash
    sudo systemctl restart mongod
    # Docker の場合:
    docker restart <mongodb-container>
    ```
  </Step>

  <Step title="collector を設定する" id="configure-collector">
    以下の内容を `mongodb-monitoring.yaml` として保存します。

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb"

          - type: add
            field: resource["service.name"]
            value: "mongodb-service"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, batch]
          exporters: [otlp_http/observability]
    ```

    このパーサーは MongoDB のタイムスタンプと重大度のフィールドを読み取り、`msg` をログのボディに移動したうえで、`c`、`ctx`、`id`、`attr` などのフィールドをログ属性として保持します。`$$date` は記載どおりに残してください。collector はエスケープされたドル記号を解決し、MongoDB の `$date` フィールドとして扱います。稼働中の receiver は、`start_at: end` の指定により新しいエントリのみを読み取ります。
  </Step>

  <Step title="collector を実行する" id="run-collector">
    [接続変数](#connection-details)を設定してから、設定ファイルのあるディレクトリで実行します。必要に応じて、ホスト側のログパスを調整してください。ファイルがグループ読み取り権限で設定されている場合は、`ls -ln /var/log/mongodb` で表示される数値のグループ ID を指定して `--group-add LOG_GROUP_ID` を追加します。

    ```bash
    docker run --rm --name mongodb-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/mongodb:/var/log/mongodb:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    端末は開いたままにし、サーバー上で操作を行って新しいログエントリを書き込ませます。テストが終わったら **Ctrl+C** で停止します。
  </Step>

  <Step title="ログを確認する" id="verify-logs">
    **検索** を開いて **Logs** を選択し、`ServiceName:mongodb-service` でフィルタリングしてから **Last 15 minutes** を選択します。タイムスタンプと重大度がパースされたサーバーメッセージが表示されるはずです。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、約24時間分、6,956 件の MongoDB サーバーログエントリが含まれています。collector は、メッセージと構造化された属性を保持したまま、タイムスタンプを現在時刻に合わせて更新します。

<Steps>
  <Step title="サンプルをダウンロードする" id="download-sample">
    ```bash
    curl -fL -o mongod.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/mongodb/mongod.log
    ```
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo">
    以下の内容を `mongodb-demo.yaml` として保存します。

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb-demo"

          - type: add
            field: resource["service.name"]
            value: "mongodb-demo"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:52.193Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo">
    [接続用の環境変数](#connection-details)を設定し、両方のファイルがあるディレクトリで次のコマンドを実行します。

    ```bash
    docker run --rm --name mongodb-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/mongod.log:/var/log/mongodb/mongod.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    取り込みを確認し終えるまで、端末は開いたままにしておいてください。完了したら **Ctrl+C** で停止します。デモを再実行すると、タイムスタンプが更新された状態でサンプルが改めて取り込まれます。
  </Step>

  <Step title="デモログを確認する" id="verify-demo">
    **検索** を開いて **Logs** を選択し、`ServiceName:mongodb-demo` でフィルタしたうえで **Last 2 days** を選択します。

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability の検索画面に表示された、パース済みのメッセージと重大度を含む MongoDB デモログ](/images/clickstack/observability-mongodb-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### ログが表示されない {#no-logs}

collector の出力に、ファイルのアクセス許可、パース、認証、エクスポートに関するエラーが出ていないか確認してください。また、サーバーがマウント済みのディレクトリにログを書き込んでいること、ファイル名が receiver の `include` リストと一致していることも確認してください。稼働中の設定では、新しく追加されたエントリのみが読み取られます。

### ログが正しくパースされない {#parsing-errors}

ファイルが1行に1つのJSONオブジェクトという形式になっていることを確認してください。

```bash
tail -n 1 /var/log/mongodb/mongod.log | python3 -m json.tool
```

このパーサーは MongoDB 4.4 以降の JSON ログを前提としています。レガシーなテキスト形式のログには別のパーサーが必要です。コレクター設定内の `$$date` のエスケープ処理は変更せずにそのまま残してください。
