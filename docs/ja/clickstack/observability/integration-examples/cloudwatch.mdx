OpenTelemetry collector で AWS CloudWatch のログを収集し、ClickHouse オブザーバビリティに送信します。AWS へのアクセスを設定せずにこのインテグレーションを試すには、[デモデータセット](#demo-dataset)を使用してください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* collector の例を実行するための Docker および Docker Compose、または既存の OpenTelemetry Collector Contrib のデプロイメント
* 独自のログを使用する場合: CloudWatchロググループが存在する AWS アカウント、AWS CLI v2、および以下のアクセス許可を持つ認証情報
* デモを実行する場合: サンプルのダウンロードに使用する `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。**Copy connection details** で設定をまとめてコピーするか、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用するには、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーを、サービスの正確なエンドポイント (ポートを含む) とAPIキーに置き換えてください。エンドポイントには `/v1/logs` などの接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に追記します。
  </Tab>

  <Tab title="セルフマネージド" id="self-managed">
    collector から接続可能な OTLP HTTPエンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージド版スタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。宛先の collector をこのコンピューター上で実行している場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、このホストのマッピングがあらかじめ含まれています。

## 既存のCloudWatchロググループとの連携 {#existing-cloudwatch}

<Steps>
  <Step title="AWS 認証情報を設定する" id="configure-aws">
    AWS SSO を使用する場合は、サインインしたうえで、collector を起動する端末で一時的な認証情報をエクスポートします：

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    プロファイル名とリージョンは、ご自身の環境に合わせて置き換えてください。すでに環境変数で認証情報を指定している場合は、`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY` (一時的な認証情報の場合は `AWS_SESSION_TOKEN` も) と `AWS_REGION` を設定してください。これらの認証情報は AWS のログの読み取りを許可するためのもので、宛先の OTLP 認証情報とは別物です。

    IAM アイデンティティには、以下のアクセス許可が必要です。`YOUR_REGION` と `YOUR_ACCOUNT_ID` を置き換えてください。必要に応じて、ロググループのリソースを収集対象のグループのみに絞り込んでください。

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    利用可能なロググループを一覧表示し、設定で使用する名前を確認します：

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="CloudWatchレシーバーを設定する" id="configure-receiver">
    この内容を `cloudwatch-logs.yaml` として保存します。`/aws/lambda/my-function` は、ご自身のアカウントのロググループに置き換えてください。その他のロググループは、必要に応じて `named` の下に追加します。

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    この設定では、直近1時間分のログから取得を開始し、その後1分ごとにポーリングします。初期ウィンドウを調整するには、`initial_lookback` を変更してください。チェックポイント用の永続ストレージがない場合、collector を再起動するとそのウィンドウが再度読み込まれ、データが重複する可能性があります。

    ロググループをプレフィックスで自動検出する場合は、代わりに `groups` ブロックを次の内容に置き換えます。

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    `named` または `autodiscover` のいずれかを使用してください。チェックポイントの永続化など、その他のオプションについては、[CloudWatchレシーバーのドキュメント](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver)を参照してください。
  </Step>

  <Step title="collector を起動する" id="start-collector">
    以下の内容を `docker-compose.yaml` として、`cloudwatch-logs.yaml` と同じディレクトリに保存します。

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    AWS 認証情報と[接続変数](#connection-details)を設定した端末で collector を起動し、その出力を確認します:

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="ログの確認" id="verify-logs">
    ClickHouse オブザーバビリティで **検索** を開き、**Logs** ログソースを選択して、`ServiceName:cloudwatch` でフィルタします。**Last 2 hours** を選択し、ログが表示されるまでポーリング間隔 1〜2 回分待ちます。

    次のリソース属性を確認します:

    * `aws.region`: AWSリージョン
    * `cloudwatch.log.group.name`: ロググループ
    * `cloudwatch.log.stream`: ログストリーム

    ログメッセージは `Body` に格納されます。receiver はメッセージをそのまま保持しますが、テキストの内容から重大度を推論することはありません。重大度に基づくダッシュボードパネルを利用するには、ログパイプライン側で `SeverityText` にデータを投入する必要があります。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、Lambda、ECS、バックグラウンドジョブのアクティビティ 24 時間分にわたる 12,785 件のログが含まれています。ロググループ、ストリーム、重大度の値も含まれています。この方法では、AWS 認証情報やデータベースへの直接アクセスは必要ありません。

<Steps>
  <Step title="サンプルをダウンロードする" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo-collector">
    次の内容を `cloudwatch-demo.yaml` という名前で、ダウンロード先のディレクトリに保存します。

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      このデモ設定は、ClickHouse の行形式で格納されたサンプルを読み取り、ログのボディ、重大度、属性を復元します。タイムスタンプの変換により、サンプルの時刻は過去約 24 時間の範囲にずらされ、最新のログが取り込み時刻の 2 分前になるよう調整されます。独自のログでは元のタイムスタンプを保持するため、上記の CloudWatch receiver の設定を使用してください。
    </Note>
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo-collector">
    [接続変数](#connection-details)を設定したうえで、ダウンロード先のディレクトリで次のコマンドを実行します。

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector がファイルを読み取ってエクスポートし終えるまで、端末は開いたままにしておきます。出力にエラーが出ていないか確認してください。新しいコンテナで再度実行すると、サンプルログが重複して取り込まれる場合があります。
  </Step>

  <Step title="デモログを確認する" id="verify-demo-logs">
    **Search** を開いて **Logs** ログソースを選択し、`ServiceName:cloudwatch-demo` でフィルタリングしたうえで **過去2日間** を選択します。ログを展開すると、ボディ、重大度、ロググループ、ストリームを確認できます。データを確認したら、**Ctrl+C** でデモ用 collector を停止します。

      <Frame>
        ![ClickHouse オブザーバビリティ に表示された CloudWatch デモログ](/images/clickstack/observability-cloudwatch-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### ログが表示されない {#no-logs}

* `docker compose logs otel-collector` を確認し、AWS の認証エラー、アクセス拒否エラー、OTLP のエクスポートエラーが発生していないか調べてください。
* `AWS_REGION` とロググループ名がアカウントと一致していること、およびロググループに `initial_lookback` の範囲内のイベントまたは起動後の新しいイベントが含まれていることを確認してください。
* `logs:DescribeLogGroups` と `logs:FilterLogEvents` に対する IAM 権限を確認してください。
* [接続情報](#connection-details)に記載されている宛先エンドポイントと認証設定を確認してください。
* **Logs** ログソース、サービス名フィルター、時間範囲を確認してください。デモの場合は **過去2日間** を選択してください。

### AWS 認証情報の期限切れ {#expired-credentials}

SSO を使用している場合は、再度サインインして新しい認証情報をエクスポートしたうえで、collector を再作成して新しい環境変数を読み込ませてください。

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

既存のコンテナを再起動しただけでは、認証情報は更新されません。その他の一時的な認証情報を使用している場合は、コンテナを再作成する前に、アクセスキー、シークレットキー、セッショントークンを更新してください。

### 古いログが表示されない {#older-logs}

この例では、過去 1 時間分のログから取得を開始します。`logs.initial_lookback` の値を増やすか、特定の開始時刻を指定する場合は、RFC3339 形式のタイムスタンプを指定した `logs.start_from` に置き換えてください。両方を同時に設定しないでください。設定を変更した後は collector を再起動してください。なお、同じ時間ウィンドウを再度読み取ると、重複が発生する可能性があります。

## 次のステップ {#next-steps}

* エラーの急増を検知できるよう、[アラート](/ja/clickstack/observability/features/alerts)を設定します。

* 本番環境では、一時的な認証情報を手動でエクスポートするのではなく、collector を実行する AWS インフラストラクチャで IAM role を使用してください。デプロイ方法については、[OpenTelemetry データの送信](/ja/clickstack/observability/ingesting-data/opentelemetry)を参照してください。
