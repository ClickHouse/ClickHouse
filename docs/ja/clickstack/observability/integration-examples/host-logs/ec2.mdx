OpenTelemetry collector で EC2 の syslog ファイルを収集し、インスタンスのメタデータを付与して ClickHouse オブザーバビリティへ送信します。EC2 インスタンスがなくても、[デモデータセット](#demo-dataset)を使用してこのインテグレーションを試せます。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* 独自のログを使用する場合は、syslog ファイルが存在する Linux EC2 インスタンス、そのインスタンスメタデータサービスへのアクセス、および collector のインストールと実行に必要なアクセス許可
* デモを実行する場合は Docker
* collector またはサンプルをダウンロードするための `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → Managed Telemetry** に移動します。OTLP HTTP エンドポイントと APIキーをコピーしてください。**Copy connection details** で設定をまとめてコピーでき、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry の接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例で使用するため、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスの正確なエンドポイント (ポート番号を含む) と APIキーに置き換えてください。エンドポイントには `/v1/logs` などの接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に付加します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTP エンドポイント (例：`http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の設定からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージド入門ガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

EC2 インスタンスからエンドポイントに接続できる必要があります。Docker デモの場合、ローカルのコンピューター上で動作する宛先 collector には `http://host.docker.internal:4318` で接続できます。このホストのマッピングはデモコマンドに含まれています。

## 既存の EC2 インスタンスとの連携 {#existing-ec2}

ログを収集したい EC2 インスタンス上で、以下の手順を実行してください。

<Steps>
  <Step title="インスタンスのメタデータとsyslogを確認する" id="verify-metadata">
    IMDSv2 を使用してインスタンスメタデータサービスにアクセスできることを確認します。

    ```bash
    TOKEN=$(curl -fsS --connect-timeout 5 -X PUT \
      -H 'X-aws-ec2-metadata-token-ttl-seconds: 300' \
      http://169.254.169.254/latest/api/token)
    curl -fsS --connect-timeout 5 -H "X-aws-ec2-metadata-token: $TOKEN" \
      http://169.254.169.254/latest/meta-data/instance-id
    ```

    応答にはインスタンスIDが含まれているはずです。collector はこのメタデータサービスを使用して、インスタンスID、インスタンスタイプ、リージョン、アベイラビリティゾーン、アカウントIDをログに付加します。以下の設定では EC2 のタグは収集されません。

    syslog ファイルの場所を特定し、そのフォーマットを確認します。

    ```bash
    # Ubuntu/Debian
    tail -20 /var/log/syslog

    # Amazon Linux/RHEL
    tail -20 /var/log/messages
    ```

    インスタンス上に実際に存在するパスを指定してください。ログが systemd ジャーナルにのみ書き込まれる場合は、[Systemd/Journald ガイド](/ja/clickstack/observability/integration-examples/systemd) を参照してログを収集してください。
  </Step>

  <Step title="collectorのインストール" id="install-collector">
    インスタンスのアーキテクチャに対応した OpenTelemetry Collector Contrib `0.161.0` をダウンロードします。

    ```bash
    case "$(uname -m)" in
      x86_64) ARCH=amd64 ;;
      aarch64) ARCH=arm64 ;;
      *) echo "Unsupported architecture"; exit 1 ;;
    esac
    curl -fLO "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz"
    tar -xzf "otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz" otelcol-contrib
    sudo install -m 755 otelcol-contrib /usr/local/bin/otelcol-contrib
    /usr/local/bin/otelcol-contrib --version
    ```
  </Step>

  <Step title="collector を設定する" id="configure-collector">
    該当する設定を `ec2-host-logs.yaml` として保存します。ファイル内のタイムスタンプのフォーマットに合わせて設定を選び、syslog のパスが異なる場合は `include` を調整してください。

    <Tabs>
      <Tab title="ISO タイムスタンプ">
        `2026-10-15T12:34:56.123456+00:00` のようなタイムスタンプの場合:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="従来の syslog">
        `Oct 15 12:34:56` のようなタイムスタンプの場合:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/messages]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```

        従来形式のタイムスタンプには年とタイムゾーンが含まれません。年はパーサーが推論します。ホストが UTC 以外でログを出力している場合は、`location` にホストの IANA タイムゾーンを設定してください。
      </Tab>
    </Tabs>

    この receiver は元のログ行を保持したまま、ホスト名、ユニット、PID (存在する場合)、メッセージを抽出します。`resourcedetection/ec2` プロセッサーは EC2 のリソース属性を付加します。インスタンスのタグも収集するには、[EC2 detector の設定](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/processor/resourcedetectionprocessor#aws-ec2)と必要なアクセス許可を参照してください。
  </Step>

  <Step title="collector を実行する" id="run-collector">
    このターミナルで[接続変数](#connection-details)を設定し、設定ファイルがあるディレクトリから実行します。collector が syslog ファイルを読み取るには、アクセス許可が必要です：

    ```bash
    sudo --preserve-env=OTEL_EXPORTER_OTLP_ENDPOINT,OTEL_EXPORTER_OTLP_AUTHORIZATION \
      /usr/local/bin/otelcol-contrib --config="$(pwd)/ec2-host-logs.yaml"
    ```

    ターミナル (端末) は開いたままにしておいてください。receiver は `start_at: end` を使用するため、起動後に syslog ファイルへ書き込まれる新しいアクティビティを発生させてください。継続的に収集するには、お使いのデプロイプロセスでサービスを設定し、そのサービスに接続用の変数を渡してください。
  </Step>

  <Step title="ログを確認する" id="verify-logs">
    **検索**を開いて **Logs** ログソースを選択し、`ServiceName:ec2-host-service` でフィルタして、**Last 15 minutes** を選択します。レコードを展開し、リソース属性に `cloud.provider`、`cloud.region`、`cloud.availability_zone`、`host.id`、`host.type` が含まれていることを確認します。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、24 時間分の syslog のログ行が 11,658 件含まれています。collector がシミュレートされた EC2 メタデータを付与し、タイムスタンプも更新するため、AWS アカウントは不要です。

<Steps>
  <Step title="サンプルをダウンロード" id="download-sample">
    ```bash
    mkdir -p ec2-demo
    cd ec2-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="デモ用のcollectorを設定する" id="configure-demo-collector">
    以下の内容を `ec2-host-logs-demo.yaml` という名前で、ダウンロード先のディレクトリに保存します。

    ```yaml
    receivers:
      filelog/ec2:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: ec2-demo
          - type: add
            field: resource["service.name"]
            value: ec2-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      resource/ec2_demo:
        attributes:
          - key: cloud.provider
            value: "aws"
            action: insert
          - key: cloud.platform
            value: "aws_ec2"
            action: insert
          - key: cloud.region
            value: "us-east-1"
            action: insert
          - key: cloud.availability_zone
            value: "us-east-1a"
            action: insert
          - key: host.id
            value: "i-0abc123def456789"
            action: insert
          - key: host.type
            value: "t3.medium"
            action: insert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/ec2:
          receivers: [filelog/ec2]
          processors: [memory_limiter, resource/ec2_demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      デモ専用のタイムスタンプ変換により、サンプルデータはおおよそ過去 24 時間の範囲にシフトされ、インジェストの 2 分前が終点となるよう調整されます。独自のログを取り込む場合は、元のタイムスタンプを保持できるよう [EC2 インスタンス設定](#existing-ec2)を使用してください。
    </Note>
  </Step>

  <Step title="デモ用のcollectorを実行する" id="run-demo-collector">
    [接続用の変数](#connection-details)を設定したうえで、ダウンロード先のディレクトリで次のコマンドを実行します：

    ```bash
    docker run --rm --name ec2-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/ec2-host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector がサンプルをエクスポートしている間は端末を開いたままにし、出力にエラーが出ていないか確認してください。新しいコンテナを再度起動すると、サンプルのログが重複する場合があります。
  </Step>

  <Step title="デモのログを確認する" id="verify-demo-logs">
    **検索** を開いて **Logs** ログソースを選択し、`ServiceName:ec2-demo` でフィルタしたうえで、**Last 2 days** を選択します。ログを展開し、シミュレートされたリソース属性を確認します。`cloud.region` が `us-east-1`、`host.id` が `i-0abc123def456789`、`host.type` が `t3.medium` になっているはずです。データを確認したら、**Ctrl+C** で collector を停止します。

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse オブザーバビリティの検索画面に表示された EC2 デモのログ](/images/clickstack/observability-ec2-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### EC2 メタデータが取得されない {#no-metadata}

EC2 インスタンス上でメタデータの確認を実行してください。IMDS が有効になっていること、またローカルのファイアウォールやプロキシの設定で `169.254.169.254` へのリクエストが許可されていることを確認してください。プロキシを使用している場合は、`NO_PROXY` でこのアドレスを除外してください。collector の出力にメタデータ検出に関するエラーが出ていないかも確認してください。なお、デモではシミュレートされたメタデータを使用するため、IMDS には接続しません。

### ログが表示されない {#no-logs}

* `include` で指定したパスが存在し、collector がそのパスを読み取れることを確認してください。
* 起動後に新しいログエントリを生成してください。`start_at: end` を指定すると、既存の内容はスキップされます。
* collector の出力に認証エラーやエクスポートエラーが出ていないかを確認し、インスタンスからエンドポイントに接続可能であることも確認してください。
* **Logs** ログソース、サービス名フィルタ、時間範囲の設定を確認してください。デモでは **Last 2 days** を選択してください。

### ログが正しくパースされない {#logs-not-parsing}

ファイルのタイムスタンプが、選択した設定と合っているか確認してください。従来形式の syslog を使用している場合は、ホストのタイムゾーンを正しく設定してください。収集対象は、設定済みのフォーマットに一致するファイルのみに限定してください。
