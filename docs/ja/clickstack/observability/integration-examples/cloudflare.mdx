## 概要 {#overview-self-configured}

    Cloudflare [Logpush](https://developers.cloudflare.com/logs/about/) は、HTTPリクエストログを Amazon S3 などの宛先にエクスポートします。これらのログを ClickStack に転送すると、次のことが可能になります。

    * エッジトラフィック、キャッシュのパフォーマンス、セキュリティイベントを、他のオブザーバビリティデータと併せて分析
    * ClickHouse SQL を使用してログをクエリ
    * Cloudflare のデフォルトの保持期間を超えてログを保持

    このガイドでは、[ClickPipes](/ja/integrations/clickpipes/home) を使用して、Cloudflare のログファイルを S3 から ClickHouse へ継続的に取り込みます。S3 は Cloudflare と ClickHouse の間で永続的なバッファとして機能し、exactly-once セマンティクスとデータのリプレイ (再処理) 機能を提供します。

    <Info>
      **代替手段: HTTP による直接インジェスト**

      Cloudflare Logpush は、ログを [HTTP エンドポイント](https://developers.cloudflare.com/logs/get-started/enable-destinations/http/) へ直接プッシュすることもできます。Cloudflare はログを改行区切りJSON (NDJSON) としてエクスポートし、ClickHouse は `JSONEachRow` によってこのフォーマットをネイティブに受け付けられるため、次の形式のエンドポイント URL を使用して、Logpush の宛先として ClickHouse Cloud の HTTP インターフェースを直接指定できます。

      ```text
      https://YOUR_CLICKHOUSE_HOST:8443/?query=INSERT+INTO+cloudflare_http_logs+FORMAT+JSONEachRow&header_Authorization=Basic+BASE64_CREDENTIALS
      ```

      `YOUR_CLICKHOUSE_HOST` を ClickHouse Cloud のホスト名に、`BASE64_CREDENTIALS` を Base64エンコード済みの認証情報 (`echo -n 'default:YOUR_PASSWORD' | base64`) に置き換えてください。

      この方法は S3、SQS、IAM の設定が不要なためセットアップは簡単ですが、Cloudflare Logpush は配信に失敗した場合に[履歴データをバックフィルできません](https://developers.cloudflare.com/logs/logpush/)。そのため、プッシュ時に ClickHouse が使用不可の状態だった場合、そのログは完全に失われます。
    </Info>

## 既存の Cloudflare Logpush との連携 {#existing-cloudflare-self-configured}

    このセクションでは、ログを S3 にエクスポートするよう Cloudflare Logpush が設定済みであることを前提としています。まだ設定していない場合は、先に [Cloudflare の AWS S3 セットアップガイド](https://developers.cloudflare.com/logs/get-started/enable-destinations/aws-s3/) に従って設定してください。

### 前提条件 {#prerequisites-self-configured}

    * 稼働中の **ClickHouse Cloud サービス** (ClickPipes は Cloud 専用の機能であり、ClickStack OSS では利用できません)
    * S3バケットへのログ書き込みが有効になっている Cloudflare Logpush
    * Cloudflare のログの書き込み先となる S3バケットの名前とリージョン

    <Steps>
      <Step title="S3 認証を設定する" id="configure-auth-self-configured">
        ClickPipes が S3バケットからデータを読み取るには、アクセス許可が必要です。[S3 データへの安全なアクセス](/ja/products/cloud/guides/data-sources/accessing-s3-data-securely)ガイドに従い、IAM role を使用したロールベースのアクセス、または認証情報ベースのアクセスのいずれかを設定してください。

        ClickPipes における S3 の認証およびアクセス許可の詳細については、[S3 ClickPipes リファレンスドキュメント](/ja/integrations/clickpipes/object-storage/amazon-s3/overview#access-control)を参照してください。
      </Step>

      <Step title="ClickPipesジョブを作成" id="create-clickpipes-self-configured">
        1. ClickHouse Cloud コンソール → **Data Sources** → **Create ClickPipe**
        2. **Source**: Amazon S3

        <div className="ch-image-lg">
          <Frame>
            ![Clickpipe s3](/images/clickstack/cloudflare/clickpipe-s3.webp)
          </Frame>
        </div>

        **接続:**

        * **S3 file path**: Cloudflare ログを保存しているバケットのパスを、ファイルにマッチするワイルドカード付きで指定します。Logpush で日次サブフォルダーを有効にしている場合は、`**` を使用してサブディレクトリをまたいでマッチさせます:
          * サブフォルダーなし: `https://your-bucket.s3.us-east-1.amazonaws.com/logs/*`
          * 日次サブフォルダーあり: `https://your-bucket.s3.us-east-1.amazonaws.com/logs/**/*`
        * **Authentication**: 認証方式を選択し、認証情報または IAM ロールの ARN を指定します

        **インジェスト設定:**

        **Incoming data** をクリックし、以下を設定します:

        * **Continuous ingestion** をオンにします
        * **Ordering**: Lexicographical order

        <div className="ch-image-lg">
          <Frame>
            ![継続的インジェスト](/images/clickstack/cloudflare/continuous-ingestion.webp)
          </Frame>
        </div>

        Cloudflare Logpush は日付ベースのファイル名 (例: `20250127/...`) でファイルを書き込むため、ファイル名は自然に辞書式順序で並びます。ClickPipes は 30 秒ごとに新しいファイルをポーリングし、最後に処理したファイルより名前が辞書順で後にあるファイルを取り込みます。

        **スキーママッピング:**

        **Parse information** をクリックします。ClickPipes がログファイルをサンプリングし、スキーマを自動検出します。マッピングされたカラムを確認し、必要に応じて型を調整してください。書き込み先テーブルの **Sorting key** を定義します。Cloudflare ログの場合は、`(EdgeStartTimestamp, ClientCountry, EdgeResponseStatus)` を指定するのがおすすめです。

        <div className="ch-image-lg">
          <Frame>
            ![解析情報](/images/clickstack/cloudflare/parse-information.webp)
          </Frame>
        </div>

        **Complete Setup** をクリックします。

        <Note>
          ClickPipes は作成直後、継続的なポーリングに切り替える前に、指定したパス内の**既存のすべてのファイル**を対象に初期ロードを実行します。バケットに大量の Cloudflare ログが蓄積されている場合、この初期ロードには時間がかかることがあります。
        </Note>
      </Step>

      <Step title="ClickStack UI のデータソースを設定する" id="configure-source-self-configured">
        ClickPipes は、Cloudflare ネイティブのフィールド名をそのまま使用して、Cloudflare ログをフラットなテーブルに取り込みます。これらのログを ClickStack UI で表示するには、Cloudflare のカラムを ClickStack UI のログビューにマッピングするカスタムデータソースを設定します。

        1. ClickStack UI を開き、**Team Settings** → **Sources** に移動します

        <div className="ch-image-lg">
          <Frame>
            ![ソースを追加](/images/clickstack/cloudflare/add-source.webp)
          </Frame>
        </div>

        2. **Add source** をクリックし、以下のとおり設定します。**Configure Optional Fields** をクリックすると、すべてのフィールドが表示されます:

        <div className="ch-image-lg">
          <Frame>
            ![任意フィールドの設定](/images/clickstack/cloudflare/configure-optional-fields.webp)
          </Frame>
        </div>

        | 設定                                 | 値                                                                                                                                                                                                                                                                                                                 |
        | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
        | **Name**                           | `Cloudflare Logs`                                                                                                                                                                                                                                                                                                 |
        | **Source Data Type**               | Log                                                                                                                                                                                                                                                                                                               |
        | **Database**                       | `default`                                                                                                                                                                                                                                                                                                         |
        | **Table**                          | `cloudflare_http_logs`                                                                                                                                                                                                                                                                                            |
        | **Timestamp Column**               | `toDateTime(EdgeStartTimestamp / 1000000000)`                                                                                                                                                                                                                                                                     |
        | **Default Select**                 | `EdgeStartTimestamp, ClientRequestMethod, ClientRequestURI, EdgeResponseStatus, ClientCountry`                                                                                                                                                                                                                    |
        | **Service Name Expression**        | `'cloudflare'`                                                                                                                                                                                                                                                                                                    |
        | **Log Level Expression**           | `multiIf(EdgeResponseStatus >= 500, 'ERROR', EdgeResponseStatus >= 400, 'WARN', 'INFO')`                                                                                                                                                                                                                          |
        | **Body Expression**                | `concat(ClientRequestMethod, ' ', ClientRequestURI, ' ', toString(EdgeResponseStatus))`                                                                                                                                                                                                                           |
        | **Log Attributes Expression**      | `map('http.method', ClientRequestMethod, 'http.status_code', toString(EdgeResponseStatus), 'http.url', ClientRequestURI, 'client.country', ClientCountry, 'client.ip', ClientIP, 'cache.status', CacheCacheStatus, 'bot.score', toString(BotScore), 'cloudflare.ray_id', RayID, 'cloudflare.colo', EdgeColoCode)` |
        | **Resource Attributes Expression** | `map('cloudflare.zone', ClientRequestHost)`                                                                                                                                                                                                                                                                       |
        | **Implicit Column Expression**     | `concat(ClientRequestMethod, ' ', ClientRequestURI)`                                                                                                                                                                                                                                                              |

        3. **Save Source** をクリックします

        <div className="ch-image-lg">
          <Frame>
            ![ソースを保存](/images/clickstack/cloudflare/save-source.webp)
          </Frame>
        </div>

        これにより、データの変換や複製を行うことなく、Cloudflare ネイティブのカラムが ClickStack UI のログビューアに直接マッピングされます。**Body** には `GET /api/v1/users 200` のようなリクエストの概要が表示され、Cloudflare のすべてのフィールドを検索可能な属性として利用できます。
      </Step>

      <Step title="ClickStack UIでデータを確認する" id="verify-hyperdx-self-configured">
        **検索**ビューに移動し、**Cloudflare Logs** ソースを選択します。データが含まれる期間を対象に時間範囲を設定すると、次のようなログエントリが表示されます。

        * Body カラムにリクエストの概要が表示される (例: `GET /api/v1/users 200`)
        * 重大度が HTTP ステータスに応じて色分けされる (2xx は INFO、4xx は WARN、5xx は ERROR)
        * `http.status_code`、`client.country`、`cache.status`、`bot.score` などの属性で検索できる

          <Frame>

          </Frame>

          </Frame>
        </div>
      </Step>

## デモデータセット {#demo-dataset-self-configured}

    本番環境の Cloudflare Logpush を設定する前にインテグレーションを試したい方のために、実際に近い HTTPリクエストのログを含むサンプルデータセットを用意しています。

    <Steps>
      <Step title="デモデータセットで ClickPipes を開始する" id="start-demo-self-configured">
        1. ClickHouse Cloud コンソール → **Data Sources** → **Create ClickPipe**
        2. **Source**: Amazon S3
        3. **Authentication**: Public
        4. **S3 file path**: `https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/cloudflare/cloudflare-http-logs.json`
        5. **Incoming data** をクリックします
        6. フォーマットとして **JSON** を選択します
        7. **Parse information** をクリックし、検出されたスキーマを確認します
        8. **Table name** を `cloudflare_http_logs` に設定します
        9. **Complete Setup** をクリックします

        このデータセットには、24 時間分、5,000 件の HTTP リクエストのログエントリが含まれています。複数の国からのトラフィック、キャッシュヒットとキャッシュミス、API や静的アセットへのリクエスト、エラーレスポンス、セキュリティイベントなど、実環境に近いパターンを再現しています。
      </Step>

      <Step title="ClickStack UI のデータソースを設定する" id="configure-demo-source-self-configured">
        [データソースの設定手順](#configure-source-self-configured)に従い、`cloudflare_http_logs` テーブルを参照する ClickStack UI のログソースを作成します。本番環境インテグレーションのセクションでログソースをすでに設定済みの場合、この手順は不要です。
      </Step>

      <Step title="デモデータを確認する" id="verify-demo-self-configured">
        ```sql
        SELECT count() FROM cloudflare_http_logs;
        -- 5000 が返されるはずです
        ```

        ClickStack UI の **Search** ビューに移動し、**Cloudflare Logs** ソースを選択して、時間範囲を **2026-02-23 00:00:00 - 2026-02-26 00:00:00** に設定します。

        リクエストの概要、検索可能な Cloudflare 属性、HTTP ステータスコードに基づく重大度レベルを含むログエントリが表示されます。

        <div className="ch-image-lg">
          <Frame>

          </Frame>
        </div>

        <div className="ch-image-lg">
          <Frame>
            ![ログビュー](/images/clickstack/cloudflare/log-view.webp)
          </Frame>

        <Info>
          **タイムゾーンの表示**

          ClickStack UI は、タイムスタンプをブラウザのローカルタイムゾーンで表示します。デモデータの期間は **2026-02-24 00:00:00 - 2026-02-25 00:00:00 (UTC)** です。時間範囲を広めに設定しておくことで、どの地域からでもデモログを確認できます。ログが表示されたら、範囲を 24 時間に絞り込むと、より見やすく可視化できます。

## トラブルシューティング {#troubleshooting-self-configured}

### ClickHouse にデータが表示されない {#no-data-self-configured}

    テーブルが作成され、データが格納されていることを確認します：

    ```sql
    SHOW TABLES FROM default LIKE 'cloudflare_http_logs';
    SELECT count() FROM cloudflare_http_logs;
    ```

    テーブルは存在するものの空である場合は、ClickPipes でエラーが発生していないか確認してください (ClickHouse Cloud コンソール → **データソース** → 対象の ClickPipe → **ログ**) 。プライベートバケットで認証の問題が発生している場合は、[S3 ClickPipes のアクセス制御に関するドキュメント](/ja/integrations/clickpipes/object-storage/amazon-s3/overview#access-control)を参照してください。

### ClickStack UI にログが表示されない {#no-hyperdx-self-configured}

    データが ClickHouse には存在するのに ClickStack UI に表示されない場合は、データソースの設定を確認してください。

    * ClickStack UI → **チーム設定** → **ソース** で、`cloudflare_http_logs` のソースが存在することを確認します
    * **タイムスタンプ列** が `toDateTime(EdgeStartTimestamp / 1000000000)` に設定されていることを確認します。Cloudflare のタイムスタンプはナノ秒単位のため、変換が必要です
    * ClickStack UI の時間範囲にデータの期間が含まれていることを確認します。デモデータセットの場合は、**2026-02-23 00:00:00 - 2026-02-26 00:00:00** を指定します

## 本番環境への移行 {#going-to-production-self-configured}

    このガイドでは、パブリックなデモデータセットを使用して Cloudflare ログを取り込む方法を説明します。本番環境へのデプロイメントでは、Cloudflare Logpush が独自の S3バケットに書き込むように設定し、安全にアクセスできるよう [IAM role ベースの認証](/ja/products/cloud/guides/data-sources/accessing-s3-data-securely) を使用して ClickPipes をセットアップしてください。ストレージコストとインジェスト量を抑えるため、[Logpush フィールド](https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/zone/http_requests/) は必要なものだけを選択してください。また、ファイルを整理しやすくするために Logpush で日別のサブフォルダーを有効化し、ClickPipes のパスパターンには `**/*` を指定してサブディレクトリをまたいで一致させるようにしてください。

    バックフィルや順序不同のファイルを処理するための [SQS ベースの unordered インジェスト](/ja/integrations/clickpipes/object-storage/amazon-s3/overview#continuous-ingestion-any-order) を含む高度な設定オプションについては、[S3 ClickPipes のドキュメント](/ja/integrations/clickpipes/object-storage/amazon-s3/overview) を参照してください。
  </Tab>
