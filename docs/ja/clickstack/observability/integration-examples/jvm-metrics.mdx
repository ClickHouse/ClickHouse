OpenTelemetry Java agent を使用して JVM メトリクスを収集し、ClickHouse オブザーバビリティに送信します。アプリケーションをインストルメントせずにこのインテグレーションを試す場合は、[デモデータセット](#demo-dataset)をご利用ください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* 独自のメトリクスを収集する場合: Java 8 以降のアプリケーション、およびその起動コマンドまたは環境変数を変更できる権限
* デモを実行する場合: Docker と `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。**接続情報をコピー** で設定をまとめてコピーするか、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    アプリケーションまたはデモ用 collector を起動する端末で、次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーを、サービスの実際のエンドポイント (ポートを含む) とAPIキーに置き換えてください。エンドポイントには `/v1/metrics` などの接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に追記します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTPエンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、Javaエージェントでは `OTEL_EXPORTER_OTLP_HEADERS` を、デモ用 collector ではエクスポーターの `headers` ブロックを省略してください。セットアップ手順については、[セルフマネージド版スタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントは、アプリケーションから接続可能である必要があります。Docker デモでは、collector コンテナからも接続できなければなりません。宛先の collector がこのコンピューター上で動作している場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、ホストのマッピングが含まれています。

## 既存の JVM アプリケーションとの連携 {#existing-jvm}

<Steps>
  <Step title="Javaエージェントをダウンロードする" id="download-agent">
    OpenTelemetry Java agent `2.22.0` をダウンロードします。

    ```bash
    curl -fLO https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/download/v2.22.0/opentelemetry-javaagent.jar
    ```
  </Step>

  <Step title="アプリケーションを設定して起動する" id="configure-jvm">
    [接続変数](#connection-details)を設定したうえで、エージェントを設定します。

    ```bash
    export OTEL_SERVICE_NAME='jvm-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='otlp'
    export OTEL_LOGS_EXPORTER='none'
    export OTEL_TRACES_EXPORTER='none'

    java -javaagent:./opentelemetry-javaagent.jar -jar my-application.jar
    ```

    `my-application.jar` は実際のアプリケーションの JAR に置き換え、必要に応じてエージェントのパスも調整してください。サービス名には、アプリケーションを識別できる名前を指定します。この設定で収集されるのはメトリクスのみです。アプリケーションがすでにトレースやログをエクスポートしている場合、それらのシグナルについては既存のエクスポーター設定をそのまま使用してください。

    サービスやコンテナで管理されているアプリケーションの場合は、既存の JVM 起動引数にエージェントを追加し、環境変数はデプロイメントの設定で指定してください。詳細は [Javaエージェントの設定ドキュメント](https://opentelemetry.io/docs/zero-code/java/agent/configuration/)を参照してください。
  </Step>

  <Step title="メトリクスを確認する" id="verify-metrics">
    エージェントがメトリクスをエクスポートするまで、2分以上待ちます。**Chart Explorer** を開き、**Metrics** ログソースを選択して、`jvm.memory.used` または `jvm.thread.count` を検索します。`ServiceName:jvm-service` でフィルタし、**Last 15 minutes** を選択します。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、5 分間隔でサンプリングされた 6,048 個の Gauge データポイントと、元のデータセットに含まれる 412 件のガベージコレクションイベントがすべて収録されています。メモリ、スレッド、クラス、CPU、GC のアクティビティを約 24 時間分カバーしています。Java アプリケーションやデータベースへの直接アクセスは不要です。

開始する前に、[接続変数](#connection-details)を設定してください。

<Steps>
  <Step title="サンプルメトリクスをダウンロードする" id="download-sample">
    [デモバンドルをダウンロード](/ja/assets/jvm-metrics-demo.zip)し、作業ディレクトリに展開します。バンドルには `jvm-metrics-demo.json` と `jvm-metrics-dashboard.json` が含まれています。
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo-collector">
    以下の内容を `jvm-metrics-demo.yaml` として保存します。

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: jvm-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-12-08T14:16:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      このデモ専用の変換は、メトリクス値と、各データポイントの開始・終了タイムスタンプ間の間隔を維持したまま、タイムスタンプを現在時刻に合わせて更新します。実際の JVM メトリクスを扱う場合は省略してください。バッチの上限は、宛先の collector が受け付けられるようアップロードのサイズを小さく抑えるためのものです。
    </Note>
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo-collector">
    設定ファイルがあるディレクトリで collector を実行し、この端末は開いたままにしておきます。

    ```bash
    docker run --rm --name jvm-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/jvm-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="サンプルを送信する" id="load-metrics">
    別の端末で、ダウンロード先のディレクトリから次のコマンドを実行します。

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @jvm-metrics-demo.json
    ```

    `{}` や `{"partialSuccess":{}}` などのレスポンスが返れば、ローカルの collector がリクエストを受け付けています。collector の端末でエクスポートエラーが出ていないか確認し、転送が完了するまで数秒待ってください。データを確認したら **Ctrl+C** で collector を停止します。サンプルを再送信すると、データポイントが重複する可能性があります。
  </Step>

  <Step title="メトリクスを確認する" id="verify-demo-metrics">
    [次のセクション](#dashboards)のダッシュボードをインポートし、`ServiceName:jvm-demo` でフィルタリングして、**過去2日間** を選択します。サンプルには Gauge と 合計 の両方のメトリクスが含まれています。データベースへの直接アクセスは不要です。
  </Step>
</Steps>

    2. `jvm-metrics-dashboard.json` をアップロードします。

      </Frame>

  <Step title="ダッシュボードを表示する" id="view-dashboard">
    サンプルデータの場合は、`ServiceName:jvm-demo` でフィルタし、**過去2日間** を選択します。

    ダッシュボードには、サンプルデータのヒープメモリ、GC による一時停止、スレッド、メタスペース、CPU、読み込まれたクラスが表示されます。

    <div className="ch-image-lg">
      <Frame>
        ![6 つのチャートすべてが表示された ClickHouse オブザーバビリティの JVM メトリクスデモダッシュボード](/images/clickstack/observability-jvm-metrics-dashboard.png)

    <Note>
      このサンプルでは古い JVM メトリクススキーマが使用されています。Javaエージェント `2.22.0` を使用する場合は、メモリ、スレッド、クラス、CPU時間のメトリクスにはメトリクス種別として合計 (sum) を、GC の所要時間にはヒストグラムを選択してください。メモリおよびカウント系のメトリクスは非単調な合計であるため、レートではなく現在値を使用してください。また、チャートのフィルタとグルーピングで `jvm.memory.type`、`jvm.memory.pool.name`、`jvm.thread.state`、`jvm.gc.name` を使用するよう更新してください。最新のスキーマについては、[JVM メトリクスの規約](https://opentelemetry.io/docs/specs/semconv/runtime/jvm-metrics/)を参照してください。
    </Note>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### エージェントが起動しない {#agent-not-starting}

`-javaagent` に指定したパスにエージェントの JAR が存在すること、アプリケーションがそのファイルを読み取れること、Java のバージョンが 8 以降であることを確認してください。また、アプリケーションの起動時の出力にエージェントのエラーが出ていないか確認してください。

### メトリクスが表示されない {#no-metrics}

* アプリケーションまたはデモ collector の出力に、認証エラーやエクスポートエラーが出ていないか確認してください。
* アプリケーションまたはコンテナからエンドポイントに接続可能であること、およびプロトコルが `http/protobuf` に設定されていることを確認してください。
* **Metrics** ログソース、サービス名フィルター、時間範囲を確認してください。デモの場合は **過去2日間** を選択してください。
* 既存の collector を使用している場合は、そのメトリクスパイプラインに OTLP レシーバーとメトリクスエクスポーターが含まれていることを確認してください。
* デモ collector がリクエストを受け付けているにもかかわらずデータが届かない場合は、その端末に転送エラーが出力されていないか確認してください。
