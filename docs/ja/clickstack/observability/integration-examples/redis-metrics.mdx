OpenTelemetry の Redisレシーバーを使用して Redis メトリクスを収集し、ClickHouse オブザーバビリティに送信します。Redis をインストールせずにこのインテグレーションを試す場合は、[デモデータセット](#demo-dataset)を使用してください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* collector の例を実行するための Docker、または既存の OpenTelemetry Collector Contrib のデプロイメント
* 独自のメトリクスを使用する場合：collector から接続可能な Redis インスタンス、および Redis で認証が必要な場合はその認証情報
* デモを実行する場合：サンプルをダウンロードして送信するための `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。**接続情報をコピー** で設定をまとめてコピーできるほか、**Reveal key** でマスクされたキーを表示することもできます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例で使用するため、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスの正確なエンドポイント (ポートを含む) とAPIキーに置き換えてください。エンドポイントには `/v1/metrics` 接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に追記します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTPエンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージドのスタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続可能である必要があります。宛先の collector がこのコンピューター上で実行されている場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドにはホストのマッピングが含まれています。

## 既存の Redis との連携 {#existing-redis}

<Steps>
  <Step title="Redis への接続を確認する" id="verify-redis">
    Redis CLI を利用できるホストから、Redis インスタンスの状態を確認します。

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    1 つ目のコマンドで `PONG` が、2 つ目のコマンドでサーバー情報が返されれば正常です。Redis でパスワードが必要な場合は、これらのコマンドを実行する前に端末で `REDISCLI_AUTH` を設定してください。Redis の ACL ユーザーを使用する場合は、`--user YOUR_REDIS_USER` も指定してください。
  </Step>

  <Step title="collector を設定する" id="configure-collector">
    以下の内容を `redis-metrics.yaml` として保存します。

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # Redis で認証が必要な場合はコメントを解除してください:
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    この receiver は、メモリ使用量、クライアント、処理済みコマンド数、キースペースのヒット数とミス数、期限切れまたは追い出されたキーなどの Redis メトリクスを 10 秒ごとに収集します。resource プロセッサーは、フィルタリングに使えるよう `service.name` を `redis-service` に設定します。

    Redis で認証が必要な場合は、receiver の該当フィールドのコメントを解除し、`REDIS_USERNAME` と `REDIS_PASSWORD` の一方または両方を設定してください。これらの認証情報は Redis への接続に使用されます。一方、OTLP の authorization 値は宛先の collector での認証に使用されます。TLS が有効な Redis の場合は、[Redisレシーバーのドキュメント](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver)に従って receiver の `tls` を設定してください。
  </Step>

  <Step title="collector を実行する" id="run-collector">
    [接続変数](#connection-details)と、collector コンテナから到達可能な Redis のアドレスを設定します。Redis がこのコンピューター上で動作している場合は、次のように設定します。

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    リモートの Redis の場合は、そのホスト名とポートを指定します。Redis が別のコンテナで動作している場合は、そのコンテナ名を指定し、以下のコマンドに `--network YOUR_NETWORK` を追加してください。

    `redis-metrics.yaml` があるディレクトリで、次のコマンドを実行します。

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    メトリクスの収集中は、この端末を開いたままにしてください。UI で確認する前に、少なくとも収集間隔 2 回分は待ってください。
  </Step>

  <Step title="メトリクスを確認する" id="verify-metrics">
    [ダッシュボード](#dashboards)をインポートし、そのチャートを **Metrics** ログソースにマッピングしたうえで、`ServiceName:redis-service` でフィルタします。**Last 15 minutes** を選択し、ダッシュボードを実行します。Redis インスタンスが正常であれば、エビクション数や拒否された接続数がゼロのままになることもあります。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

24 時間にわたって 5 分ごとにサンプリングされた 6,912 個の gauge および sum データポイントを使用して、このインテグレーションを試せます。このサンプルには、元のデータセットに含まれるキャッシュのウォームアップ、トラフィックスパイク、メモリ逼迫のパターンがそのまま残されています。Docker、`curl`、および宛先 collector の OTLP HTTP 接続情報が必要です。

開始する前に、[接続変数](#connection-details)を設定してください。

<Steps>
  <Step title="サンプルメトリクスをダウンロードする" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo-collector">
    以下の内容を `redis-metrics-demo.yaml` として保存します。

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      このデモ専用の transform は、メトリクス値と、各ポイントの開始・終了タイムスタンプ間の時間間隔を維持したまま、タイムスタンプを現在時刻に合わせて更新します。実際の Redis メトリクスを収集する場合は省略してください。batch の上限設定により、各アップロードのサイズを宛先 collector が受け付けられる範囲に抑えています。
    </Note>
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo-collector">
    設定ファイルを置いたディレクトリで collector を実行し、この端末は開いたままにしておきます。

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="サンプルを送信する" id="load-metrics">
    別の端末を開き、ダウンロード先のディレクトリで次のコマンドを実行します。

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    `{}` や `{"partialSuccess":{}}` などのレスポンスが返れば、ローカルの collector がリクエストを受け付けています。collector の端末でエクスポートエラーが出ていないか確認し、転送が完了するまで数秒待ちます。データを確認したら、**Ctrl+C** で collector を停止します。サンプルを再送信すると、ポイントが重複するおそれがあります。
  </Step>

  <Step title="メトリクスを確認する" id="verify-demo-metrics">
    [次のセクション](#dashboards)のダッシュボードをインポートし、`ServiceName:redis-demo` でフィルタリングして、**過去2日間** を選択します。サンプルには gauge と sum の両方のメトリクスが含まれています。データベースに直接アクセスする必要はありません。
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### collector が起動しない {#collector-fails-to-start}

collector の端末に設定エラーが出力されていないか確認してください。また、YAML ファイルがドキュメントに記載されたパスにマウントされていること、および Docker を実行する端末でエンドポイントと必須の認証用変数が設定されていることも確認してください。

### メトリクスが表示されない {#no-metrics}

* collector の出力に、Redis の接続エラーや OTLP のエクスポートエラーが出ていないか確認してください。
* collector のコンテナから Redis に接続可能であることを確認してください。コンテナで実行している場合は、想定どおりの Docker ネットワークを共有しているか確認してください。
* Redis の認証情報が正しいこと、およびユーザーが [Redisレシーバー](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver) に必要なコマンドを実行できることを確認してください。
* **Metrics** ログソース、サービス名フィルター、時間範囲を確認してください。デモの場合は **過去2日間** を選択し、タイムスタンプの変換がパイプラインに含まれていることを確認してください。
* マネージドサービスの場合は、OTLP HTTPエンドポイントと Bearer APIキーが **マネージドテレメトリー** に表示されている内容と一致しているか確認してください。セルフマネージドのコレクターの場合は、各コレクターの認証設定を使用してください。
