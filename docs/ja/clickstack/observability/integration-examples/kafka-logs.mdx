OpenTelemetry の `filelog` receiver で Kafka のブローカーログを収集し、ClickHouse オブザーバビリティに送信します。Kafka 環境をデプロイせずにこのインテグレーションを試す場合は、[デモデータセット](#demo-dataset)を利用してください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* Docker と `curl`
* 独自のログを使用する場合は、以下のフォーマットに一致する Kafka ブローカーのログファイルへのアクセス権

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動して、OTLP HTTPエンドポイントとAPIキーをコピーします。**Copy connection details** で設定をまとめてコピーすることも、**Reveal key** でマスクされたキーを表示することもできます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例で使用するため、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスのエンドポイント(ポートを含めて正確に)とAPIキーに置き換えてください。エンドポイントには `/v1/logs` 接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターによって追記されます。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTPエンドポイント(例: `http://YOUR_COLLECTOR_HOST:4318`)と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージドのスタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続可能である必要があります。宛先の collector がこのコンピューター上で実行されている場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、ホストのマッピングがあらかじめ含まれています。

## 既存の Kafka との連携 {#existing-kafka}

<Steps>
  <Step title="Kafkaのログ設定を確認する" id="verify-kafka">
    ブローカーログの場所を確認します。インストール方法やログ設定によって異なりますが、一般的には `$KAFKA_HOME/logs` や `/var/log/kafka` に配置されています。

    ```bash
    ls "$KAFKA_HOME/logs/"
    ls /var/log/kafka/
    ```

    主なファイルは `server.log` (ブローカーのイベント) 、`controller.log` (コントローラーのイベント) 、`state-change.log` (パーティションおよびレプリカの状態遷移) です。これらが別々のファイルとして出力されるのは、ログのアペンダーでそのように設定されている場合のみです。

    このガイドのパーサーは、次の Log4j テキストフォーマットを前提としています。

    ```text
    [2026-03-09 14:23:45,123] INFO [KafkaServer id=0] started (kafka.server.KafkaServer)
    ```

    ブローカーが stdout にのみログを出力している場合は、ブローカーのログ設定でファイルアペンダーを構成し、そのディレクトリを collector と共有してください。`filelog` receiver は、コンテナの stdout を直接読み取りません。ログのパターンが異なる場合は、パーサーを調整してください。
  </Step>

  <Step title="collectorを設定する" id="configure-collector">
    次の内容を `kafka-logs-monitoring.yaml` として保存します。

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
          - /var/log/kafka/controller.log
          - /var/log/kafka/state-change.log
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka
          - type: add
            field: resource["service.name"]
            value: kafka-service
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, batch]
          exporters: [otlp_http/observability]
    ```

    `location` には、ブローカーログで使用しているタイムゾーンを設定してください。この例では UTC を前提としています。複数行のエントリでは、スタックトレース全体がそのまま保持されます。collector は `start_at: end` により新しいエントリのみを読み取り、重大度テキストを小文字に正規化します。
  </Step>

  <Step title="collector を実行する" id="run-collector">
    [接続変数](#connection-details)を設定し、設定ディレクトリから実行します。必要に応じて、ホスト側のログのパスを調整してください。ファイルがグループ読み取り権限で保護されている場合は、`ls -ln /var/log/kafka` で表示される数値のグループIDを使用して `--group-add LOG_GROUP_ID` を追加します。

    ```bash
    docker run --rm --name kafka-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/kafka:/var/log/kafka:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    端末は開いたままにして、新しいログエントリが書き込まれるようなブローカーのアクティビティを発生させてください。テストが終わったら **Ctrl+C** で停止します。
  </Step>

  <Step title="ログを確認する" id="verify-logs">
    **検索** を開き、**Logs** を選択して `ServiceName:kafka-service` でフィルタし、**Last 15 minutes** を選択します。タイムスタンプと重大度がパースされたブローカーのメッセージが表示されるはずです。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、約 24 時間分にわたる Kafka ブローカーのログエントリが 6,376 件含まれています。collector は、メッセージとスタックトレースはそのままに、タイムスタンプのみを現在の時刻に合わせて更新します。

<Steps>
  <Step title="サンプルをダウンロードする" id="download-sample">
    ```bash
    curl -fL -o server.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/kafka/server.log
    ```
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo">
    以下の内容を `kafka-logs-demo.yaml` として保存します。

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka-demo
          - type: add
            field: resource["service.name"]
            value: kafka-demo
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:58.180Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo">
    [接続用の環境変数](#connection-details)を設定したうえで、両方のファイルがあるディレクトリで次のコマンドを実行します。

    ```bash
    docker run --rm --name kafka-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/server.log:/var/log/kafka/server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    取り込みを確認し終えるまで、端末は開いたままにしておいてください。終了するときは **Ctrl+C** で停止します。デモを再実行すると、タイムスタンプを更新したうえでサンプルが改めて取り込まれます。
  </Step>

  <Step title="デモログを確認する" id="verify-demo">
    **検索** を開いて **Logs** を選択し、`ServiceName:kafka-demo` でフィルタしたうえで、**Last 2 days** を選択します。

      <Frame>

      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### ログが表示されない {#no-logs}

collector の出力に、ファイルのアクセス許可、パース、認証、またはエクスポートに関するエラーが出ていないか確認してください。ブローカーがマウント済みのディレクトリに書き込んでいること、およびファイル名が receiver の `include` リストと一致していることも確認してください。稼働中の設定では、新しいエントリのみが読み取られます。

### ログが正しくパースされない {#parsing-errors}

ブローカーのログエントリを、想定されるフォーマットと比較してください:

```bash
tail -n 20 /var/log/kafka/server.log
```

ログのフォーマットが異なる場合は、正規表現と複数行の開始パターンを調整してください。タイムスタンプパーサーの `location` には、ブローカーのログ出力で使用されているタイムゾーンを設定してください。
