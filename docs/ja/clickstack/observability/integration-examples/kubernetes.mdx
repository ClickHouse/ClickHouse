2 つの OpenTelemetry コレクター (各ノードで動作するデーモンセットと、クラスター全体のデータを収集する単一のデプロイメント) を使用して、コンテナのログ、ノードおよびクラスターのメトリクス、Kubernetes イベントを収集します。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* Linux ノードで構成され、ワークロード、クラスター ロール、および hostPath マウントを作成するアクセス許可を持つ Kubernetes クラスター
* 対象のクラスター向けに設定済みの `kubectl`、およびインストール済みの Helm 3
* コレクターから、サービスの OTLP HTTPエンドポイント、Kubernetes API、およびキューブレットへのネットワークアクセス

これらのコレクターが収集するのはインフラストラクチャのデータです。アプリケーションのメトリクスとトレースを送信するには、アプリケーションを別途インストルメントしてください。詳しくは [OpenTelemetry インテグレーション](/ja/clickstack/observability/ingesting-data/opentelemetry)を参照してください。

## 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    エンドポイントはポート番号を含めて表示どおりに指定し、`/v1/logs` や `/v1/metrics` などの接尾辞は付けないでください。
  </Tab>

  <Tab title="セルフマネージド" id="self-managed">
    クラスターから接続可能な collector の OTLP HTTPエンドポイントと、その認証設定を使用します。認証を無効にしている場合は、`OTEL_EXPORTER_OTLP_AUTHORIZATION` に空文字列を設定し、後述のエクスポーター設定から `headers` ブロックを省略してください。詳細は[セルフマネージドのセットアップガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## コレクターのデプロイ {#deploy-collectors}

<Steps>
  <Step title="名前空間と接続設定を作成する" id="connection-settings">
    `kubectl` が目的のクラスターを指していることを確認します。

    ```bash
    kubectl config current-context
    kubectl create namespace observability --dry-run=client -o yaml | kubectl apply -f -

    kubectl create configmap observability-connection -n observability \
      --from-literal=endpoint="$OTEL_EXPORTER_OTLP_ENDPOINT" \
      --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic observability-connection -n observability \
      --from-literal=authorization="$OTEL_EXPORTER_OTLP_AUTHORIZATION" \
      --dry-run=client -o yaml | kubectl apply -f -
    ```

    両方のコレクターとも、`observability` 名前空間でこれらの設定を使用します。
  </Step>

  <Step title="共有設定を保存する" id="shared-configuration">
    以下の内容を `k8s_common.yaml` として保存します：

    ```yaml
    image:
      repository: otel/opentelemetry-collector-contrib
      tag: "0.161.0"
    command:
      name: otelcol-contrib
    resources:
      limits:
        memory: 512Mi
    presets:
      kubernetesAttributes:
        enabled: true
    extraEnvs:
      - name: OTEL_EXPORTER_OTLP_ENDPOINT
        valueFrom:
          configMapKeyRef:
            name: observability-connection
            key: endpoint
      - name: OTEL_EXPORTER_OTLP_AUTHORIZATION
        valueFrom:
          secretKeyRef:
            name: observability-connection
            key: authorization
    service:
      enabled: false
    ports:
      otlp:
        enabled: false
      otlp-http:
        enabled: false
      jaeger-compact:
        enabled: false
      jaeger-thrift:
        enabled: false
      jaeger-grpc:
        enabled: false
      zipkin:
        enabled: false
    config:
      receivers:
        otlp: null
        jaeger: null
        zipkin: null
        prometheus: null
      exporters:
        debug: null
        otlp_http/observability:
          endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
          headers:
            authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
          compression: gzip
      processors:
        batch:
          timeout: 5s
          send_batch_size: 500
          send_batch_max_size: 500
      service:
        pipelines:
          logs:
            receivers: []
            exporters: [otlp_http/observability]
          metrics:
            receivers: []
            exporters: [otlp_http/observability]
          traces: null
    ```

    チャートのプリセットによって、各 collector に必要なレシーバー、Kubernetes メタデータプロセッサー、RBAC ルール、マウントが追加されます。共有設定では、ログとメトリクスをご利用のサービスに転送し、使用しないアプリケーションインジェスト用レシーバーを無効にします。
  </Step>

  <Step title="ノードのデータ収集を設定する" id="daemonset-configuration">
    以下の内容を `k8s_daemonset.yaml` として保存します：

    ```yaml
    mode: daemonset
    presets:
      logsCollection:
        enabled: true
        storeCheckpoints: true
      hostMetrics:
        enabled: true
      kubeletMetrics:
        enabled: true
    config:
      receivers:
        kubeletstats:
          insecure_skip_verify: true
    ```

    デーモンセットはコンテナのログを読み取り、ホストおよびキューブレットのメトリクスを収集します。チェックポイントにより、collector を再起動してもログの読み取り位置が保持されます。このプリセットでは、ノード上にチェックポイントを書き込むため、collector を root として実行します。そのため、クラスターのポッドセキュリティ設定で、このプリセットによるホストのマウントが許可されている必要があります。

    この例では、キューブレットの証明書を collector が信頼していないクラスターを想定し、キューブレットの証明書検証をスキップしています。クラスターが信頼済みのキューブレット証明書を提供している場合は、`insecure_skip_verify` を `false` に設定し、適切な CA を設定してください。
  </Step>

  <Step title="クラスターのデータ収集を設定する" id="deployment-configuration">
    以下の内容を `k8s_deployment.yaml` として保存します。

    ```yaml
    mode: deployment
    replicaCount: 1
    presets:
      kubernetesEvents:
        enabled: true
      clusterMetrics:
        enabled: true
    ```

    クラスターのメトリクスとイベントが重複して収集されないよう、レプリカ数は 1 のままにしてください。
  </Step>

  <Step title="Helm リリースをインストールする" id="install-collectors">
    3つの設定ファイルが置かれているディレクトリで、以下のコマンドを実行します。この例では、OpenTelemetry Collector チャート `0.175.1` と Collector Contrib `0.161.0` を使用しています。

    ```bash
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update open-telemetry

    helm upgrade --install observability-nodes open-telemetry/opentelemetry-collector \
      --version 0.175.1 --namespace observability \
      -f k8s_common.yaml -f k8s_daemonset.yaml --wait

    helm upgrade --install observability-cluster open-telemetry/opentelemetry-collector \
      --version 0.175.1 --namespace observability \
      -f k8s_common.yaml -f k8s_deployment.yaml --wait
    ```

    コレクターを確認します。

    ```bash
    kubectl get pods -n observability
    kubectl logs -n observability -l app.kubernetes.io/instance=observability-nodes --tail=50
    kubectl logs -n observability -l app.kubernetes.io/instance=observability-cluster --tail=50
    ```

    ノードにスケジューリングを制限する taint が設定されている場合は、監視対象のノードに応じて、`k8s_daemonset.yaml` に適切な `tolerations` を追加してください。
  </Step>

  <Step title="データを確認する" id="verify-data">
    収集間隔が数回経過するまで待ってから、ClickHouse オブザーバビリティを開きます。

    * **検索** で **Logs** ログソースと **Last 15 minutes** を選択します。コンテナのログを展開し、`k8s.namespace.name`、`k8s.pod.name`、`k8s.node.name` などの属性を確認します。
    * **Chart Explorer** で **Metrics** ログソースを選択し、`k8s.` または `system.` で始まるメトリクスを探します。
    * Kubernetes のイベントは発生に応じて **Logs** ログソースに表示されるので、そちらで確認します。イベントの量はクラスターのアクティビティによって変わります。
  </Step>
</Steps>

## アプリケーションのメタデータ {#application-metadata}

計装済みアプリケーションでは、Kubernetes の Downward API を使用してポッドのメタデータを追加します。この `env` リストをアプリケーションコンテナの既存の設定にマージし、既存のリソース属性はそのまま維持してください。

```yaml
env:
  - name: OTEL_SERVICE_NAME
    value: my-app
  - name: POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
  - name: POD_UID
    valueFrom:
      fieldRef:
        fieldPath: metadata.uid
  - name: POD_NAMESPACE
    valueFrom:
      fieldRef:
        fieldPath: metadata.namespace
  - name: NODE_NAME
    valueFrom:
      fieldRef:
        fieldPath: spec.nodeName
  - name: OTEL_RESOURCE_ATTRIBUTES
    value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME)
```

Kubernetes メタデータプロセッサーは、収集したコンテナのログにワークロードのメタデータを付与してデータを拡充します。これらのアプリケーション変数により、アプリケーションの OpenTelemetry SDK が送信するテレメトリーにポッドのアイデンティティが関連付けられます。

## トラブルシューティング {#troubleshooting}

### コレクターが起動しない {#collectors-not-starting}

`kubectl describe pod -n observability POD_NAME` でポッドのイベントを確認してください。あわせて、イメージのプル、スケジューリングの制約、ポッドのセキュリティ制限に問題がないか、また ConfigMap と Secret がリリースと同じ名前空間に存在するかを確認してください。

### ログやメトリクスが表示されない {#no-data}

collector のログに認証エラーやエクスポートエラーが出ていないか確認してください。また、宛先エンドポイントにクラスターから接続可能であることも確認してください。キューブレットのエラーについては、ポート `10250` への疎通、証明書の設定、および生成された RBAC のアクセス許可を確認してください。コンテナログの収集には、ノードの `/var/log/pods` ディレクトリへのアクセスが必要です。制限の厳しいノード環境やサーバーレスのノード環境では、これらのホストマウントがサポートされない場合があります。

### 接続設定を変更した場合 {#connection-settings-changed}

ConfigMap または Secret を更新した後は、コレクターを再起動して環境変数を再読み込みしてください：

```bash
kubectl rollout restart daemonset -n observability -l app.kubernetes.io/instance=observability-nodes
kubectl rollout restart deployment -n observability -l app.kubernetes.io/instance=observability-cluster
```
