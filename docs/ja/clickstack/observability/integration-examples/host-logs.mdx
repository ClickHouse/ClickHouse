OpenTelemetry collector を使用してホストの syslog ファイルを収集し、ClickHouse オブザーバビリティに送信します。自身のホストからログを収集せずにこのインテグレーションを試す場合は、[デモデータセット](#demo-dataset)を使用してください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* collector の例を実行するための Docker、または既存の OpenTelemetry Collector Contrib のデプロイメント
* 独自のログを使用する場合は、syslog ファイルと、collector がそれらを読み取るためのアクセス許可
* デモを実行する場合は、サンプルをダウンロードするための `curl`

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。**Copy connection details** で設定をまとめてコピーできます。また、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用するには、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスのエンドポイント(ポートを含む)とAPIキーに正確に置き換えてください。エンドポイントには `/v1/logs` などの接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に追記します。
  </Tab>

  <Tab title="セルフマネージド" id="self-managed">
    collector の接続可能な OTLP HTTPエンドポイント(例: `http://YOUR_COLLECTOR_HOST:4318`)と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを省略してください。セットアップ手順については、[セルフマネージド版の導入ガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。宛先の collector がこのコンピューター上で動作している場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、ホストのマッピング設定が含まれています。

## 既存ホストとの連携 {#existing-hosts}

<Steps>
  <Step title="syslogファイルの場所を確認する" id="locate-syslog">
    一般的な保存場所は、Ubuntu/Debian では `/var/log/syslog`、RHEL 系システムでは `/var/log/messages`、macOS のテキストログでは `/var/log/system.log` です。お使いのホスト上に存在するファイルを確認してください。

    ```bash
    tail -20 /var/log/syslog
    ```

    パスは必要に応じて置き換えてください。Linux ホストが systemd ジャーナルにのみ書き込む場合は、[Systemd/Journald ガイド](/ja/clickstack/observability/integration-examples/systemd)を参照してください。このガイドはテキストファイルを読み取る方法を扱うもので、macOS の統合ログストア (unified log store) は収集対象外です。
  </Step>

  <Step title="collector を設定する" id="configure-collector">
    該当する設定を `host-logs.yaml` として保存します。どちらを使うかは、ファイル内のタイムスタンプの形式に応じて選択してください。必要に応じて、`include` を `/var/log/host/messages` または `/var/log/host/system.log` に変更します。他のファイルを追加する場合は、同じフォーマットのファイルに限ってください。

    <Tabs>
      <Tab title="ISO タイムスタンプ">
        `2026-10-15T12:34:56.123456+00:00` のようなタイムスタンプで始まる行の場合:

        ```yaml
        receivers:
          filelog/host:
            include: [/var/log/host/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: host-logs
              - type: add
                field: resource["service.name"]
                value: host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/host:
              receivers: [filelog/host]
              processors: [memory_limiter, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="従来の syslog">
        `Oct 15 12:34:56` のようなタイムスタンプで始まる行の場合:

        ```yaml
        receivers:
          filelog/host:
            include: [/var/log/host/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: host-logs
              - type: add
                field: resource["service.name"]
                value: host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/host:
              receivers: [filelog/host]
              processors: [memory_limiter, batch]
              exporters: [otlp_http/observability]
        ```

        従来形式のタイムスタンプには年とタイムゾーンが含まれません。年はパーサーが推論します。ホストが UTC でログを出力していない場合は、`location` をホストの IANA タイムゾーン(`America/Chicago` など)に設定してください。
      </Tab>
    </Tabs>

    この receiver は `hostname`、`unit`、`pid`(存在する場合)、`message` を抽出し、元の行は `Body` に保持します。また、`service.name` を `host-service` に設定し、ホスト名を `host.name` にコピーします。これらのテキスト形式には重大度フィールドがないため、この設定ではメッセージテキストから重大度を推論しません。
  </Step>

  <Step title="collectorを起動する" id="run-collector">
    [接続変数](#connection-details)を設定します。`host-logs.yaml` があるディレクトリで、次のコマンドを実行します。

    ```bash
    docker run --rm --name host-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/host-logs.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log:/var/log/host:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    macOS では、`-v /private/var/log:/var/log/host:ro` を使用し、Docker Desktop にそのディレクトリへのアクセスを許可してください。また、選択したログファイルを collector が読み取れることを確認してください。

    この端末は開いたままにしておいてください。`start_at: end` を指定している場合、receiver は起動後に書き込まれた新しい行のみを収集します。選択したログファイルに書き込みが発生するよう、通常どおりの操作を行ってください。
  </Step>

  <Step title="ログを確認する" id="verify-logs">
    **検索**を開いて **Logs** ログソースを選択し、`ServiceName:host-service` でフィルタして、**Last 15 minutes** を選択します。ログを展開すると、パースされたホスト名、ユニット、PID、メッセージを確認できます。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、24 時間分の syslog 11,658 行が含まれています。ブートメッセージ、SSH アクティビティ、ファイアウォールによるブロック、スケジュールされたジョブ、サービスの再起動などが記録されています。

<Steps>
  <Step title="サンプルをダウンロードする" id="download-sample">
    ```bash
    mkdir -p host-demo
    cd host-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo-collector">
    ダウンロード先のディレクトリに、次の内容を `host-logs-demo.yaml` として保存します。

    ```yaml
    receivers:
      filelog/host:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: host-demo
          - type: add
            field: resource["service.name"]
            value: host-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/host:
          receivers: [filelog/host]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      このデモ専用のタイムスタンプ変換により、サンプルはインジェスト時刻の 2 分前を終点とする、おおよそ直近 24 時間の範囲にシフトされます。独自のログには、元のタイムスタンプを保持できるよう [既存ホスト向けの設定](#existing-hosts) を使用してください。
    </Note>
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo-collector">
    [接続変数](#connection-details) を設定してから、ダウンロード先のディレクトリで次のコマンドを実行します。

    ```bash
    docker run --rm --name host-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector がサンプルをエクスポートしている間は端末を開いたままにし、出力にエラーがないか確認してください。新しいコンテナをもう一度起動すると、サンプルログが重複して取り込まれる可能性があります。
  </Step>

  <Step title="デモログを確認する" id="verify-demo-logs">
    **検索** を開き、**Logs** ログソースを選択して `ServiceName:host-demo` でフィルタリングし、**過去2日間** を選択します。ログを展開すると、パースされた属性を確認できます。データを確認したら、**Ctrl+C** で collector を停止します。

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse オブザーバビリティ の検索画面に表示されたホストのデモログ](/images/clickstack/observability-host-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### collector が起動しない {#collector-fails-to-start}

collector の端末に設定エラーが出力されていないか確認してください。また、マウント済みのパスに YAML ファイルが存在すること、および Docker を実行する端末で接続変数が設定されていることを確認してください。

### ログが表示されない {#no-logs}

* ファイルがホスト上に存在し、マウントされたパスが `include` と一致していることを確認してください。
* ファイルのアクセス許可を確認してください。macOS の場合は、Docker Desktop のファイル共有設定も確認してください。
* リアルタイムのログを取り込む場合は、collector の起動後に新しいエントリを生成してください。`start_at: end` を指定すると、既存の内容はスキップされます。
* collector の出力に認証エラーやエクスポートエラーがないか確認してください。
* **Logs** ログソース、サービス名フィルター、時間範囲を確認してください。デモでは **過去2日間** を選択してください。

### ログが正しくパースされない {#logs-not-parsing}

ファイル内の行と、選択したタイムスタンプのフォーマットを比較してください。一致する設定を使用し、必要に応じて従来形式の syslog のタイムゾーンを調整してください。また、範囲の広いファイル glob を指定すると、無関係なアプリケーションのログ形式まで収集してしまうため、避けてください。

## 次のステップ {#next-steps}

* 認証の失敗やサービスのエラーを検知する[アラート](/ja/clickstack/observability/features/alerts)を設定します。
* `host.name` またはパースされた `unit` 属性でフィルタし、特定のホストやサービスを詳しく調査します。
* デプロイ方法については、[OpenTelemetry データの送信](/ja/clickstack/observability/ingesting-data/opentelemetry)を参照してください。
