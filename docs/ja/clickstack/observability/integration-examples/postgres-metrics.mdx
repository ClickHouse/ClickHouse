OpenTelemetry の PostgreSQL レシーバーを使用して PostgreSQL のメトリクスを収集し、ClickHouse オブザーバビリティに送信します。[デモデータセット](#demo-dataset)を使用すると、PostgreSQL をインストールせずにこのインテグレーションを試せます。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* Docker と `curl`
* 独自のメトリクスを使用する場合は、collector から接続可能な PostgreSQL 14 以降と監視用ユーザー

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動して、OTLP HTTPエンドポイントとAPIキーをコピーします。**Copy connection details** で設定をまとめてコピーするか、**Reveal key** でマスクされたキーを表示できます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用するには、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスのエンドポイント (ポートを含む) とAPIキーの正確な値に置き換えてください。エンドポイントには `/v1/metrics` 接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターが自動的に追記します。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTPエンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを削除してください。セットアップ手順については、[セルフマネージドのスタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。宛先の collector がこのコンピューター上で動作している場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、このホストのマッピングがあらかじめ含まれています。

## 既存の PostgreSQL との連携 {#existing-postgres}

<Steps>
  <Step title="監視用ユーザーを設定する" id="monitoring-permissions">
    PostgreSQL 管理者として、監視用ユーザーがまだない場合は作成し、統計情報へのアクセス権限を付与します。

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    監視対象の各データベースに対して `CONNECT` 権限を付与してください。また、ネットワークおよび `pg_hba.conf` の設定で、PostgreSQL が collector からの接続を受け付けるようにしてください。

    OTLP の接続変数を設定したのと同じ端末で、データベースの接続変数を設定します。

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    PostgreSQL が Docker ホスト上で稼働している場合は、`host.docker.internal:5432` を使用します。共有 Docker ネットワーク上のコンテナの場合は、データベースコンテナのホスト名を指定し、collector の実行コマンドに `--network YOUR_NETWORK` を追加します。
  </Step>

  <Step title="collector を設定する" id="configure-collector">
    以下の内容を `postgres-metrics.yaml` として保存します。`databases` リストは実際のデータベース名に置き換えてください。

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    この設定では TLS が有効になり、サーバー証明書が検証されます。プライベート CA を使用する場合は、`tls.ca_file` を設定し、CA ファイルを collector にマウントしてください。TLS なしのローカル PostgreSQL サーバーに接続する場合は、`tls.insecure: true` を設定します。この場合、データベース接続の TLS は無効になります。詳しくは [PostgreSQL レシーバーの設定](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration)を参照してください。
  </Step>

  <Step title="collector を実行する" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    端末は開いたままにして、収集間隔が少なくとも 2 回経過するまで待ちます。テストが終わったら、**Ctrl+C** で collector を停止します。
  </Step>

  <Step title="メトリクスを確認する" id="verify-metrics">
    **Chart Explorer** を開き、**Metrics** ログソースを選択して `ServiceName:postgresql-service` でフィルタリングし、**Last 15 minutes** を選択します。`postgresql.backends`、`postgresql.commits`、`postgresql.db_size` などのメトリクスが表示されていることを確認してください。
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、24 時間分のデータを 5 分間隔でサンプリングした、8,928 個の gauge および sum のデータポイントが含まれています。元のデータセットに含まれる接続数のスパイク、キャッシュアクティビティ、ロールバック、デッドロックはそのまま保持されています。サンプルに含まれるのはデータベースレベルのメトリクスのみですが、実環境から収集する場合はテーブルおよびインデックスのメトリクスも取得できます。

開始する前に、[接続変数](#connection-details)を設定してください。

<Steps>
  <Step title="サンプルメトリクスをダウンロードする" id="download-sample">
    [サンプルバンドルをダウンロード](/ja/assets/postgres-metrics-demo.zip) (約 64 KB) し、`postgres-metrics-demo.json` を作業ディレクトリに展開します。
  </Step>

  <Step title="デモ用 collector を設定する" id="configure-demo-collector">
    以下の内容を `postgres-metrics-demo.yaml` として保存します。

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      このデモ専用の transform は、メトリクス値と、各データポイントの開始・終了タイムスタンプ間の時間間隔を保ったまま、タイムスタンプを現在時刻に合わせて更新します。実環境の PostgreSQL メトリクスを収集する場合は省略してください。batch の上限設定により、アップロードサイズを宛先の collector が処理できる範囲に抑えています。
    </Note>
  </Step>

  <Step title="デモ用 collector を実行する" id="run-demo-collector">
    設定ファイルを配置したディレクトリで collector を実行します。この端末は開いたままにしておいてください。

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="サンプルを送信する" id="load-metrics">
    別の端末を開き、ダウンロード先のディレクトリで次のコマンドを実行します。

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    `{}` や `{"partialSuccess":{}}` などのレスポンスが返れば、ローカルの collector がリクエストを受け付けています。collector の端末でエクスポートエラーが出ていないか確認し、転送が完了するまで数秒待ちます。データを確認したら、**Ctrl+C** で collector を停止します。サンプルを再送信するとデータポイントが重複する可能性があるため注意してください。
  </Step>

  <Step title="メトリクスを確認する" id="verify-demo-metrics">
    [次のセクション](#dashboards)のダッシュボードをインポートし、`ServiceName:postgresql-demo` でフィルタして **過去2日間** を選択します。サンプルには gauge と sum の両方のメトリクスが含まれているため、データベースに直接アクセスする必要はありません。
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### collector が起動しない {#collector-fails-to-start}

collector の出力に設定エラーがないか確認してください。また、設定ファイルがマウントされていること、および Docker を実行している端末で接続変数が設定されていることを確認してください。

### メトリクスが表示されない {#no-metrics}

collector の出力に、データベース接続エラーやエクスポートエラーが出ていないか確認してください。コンテナからデータベースのホスト名に接続可能であること、データベース名が正しいこと、PostgreSQL が監視用ユーザーからの接続を許可していることを確認してください。あわせて、**Metrics** ログソース、サービス名フィルター、時間範囲の設定も確認してください。

### 認証エラーまたは TLS エラー {#authentication-errors}

監視用ユーザーに `pg_monitor` および `CONNECT` のアクセス許可が付与されていることを確認してください。PostgreSQL に到達可能なホストから `psql` を使用して、データベースの認証情報をテストします。

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

receiver の TLS 設定をサーバー側の設定に合わせ、必要な CA 証明書をマウントしてください。エクスポートエラーが発生する場合は、OTLP エンドポイントと認可情報がサービスの接続情報と一致しているか確認してください。
