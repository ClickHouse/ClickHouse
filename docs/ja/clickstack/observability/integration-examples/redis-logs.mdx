OpenTelemetry collector を使用して Redis のサーバーログを収集し、ClickHouse オブザーバビリティに送信します。Redis をインストールせずにこのインテグレーションを試す場合は、[デモデータセット](#demo-dataset)を使用してください。

## 前提条件 {#prerequisites}

* ClickHouse オブザーバビリティのサービス
* collector の例を実行するための Docker、または既存の OpenTelemetry Collector Contrib のデプロイメント
* 独自のログを使用する場合は、既存の Redis 環境と、そのログファイルへのアクセス権

### 接続情報 {#connection-details}

<Tabs>
  <Tab title="完全マネージド型">
    <BetaBadge label="ベータ版サービス" />

    ClickHouse オブザーバビリティを開き、**チーム設定 → Data → マネージドテレメトリー** に移動します。OTLP HTTPエンドポイントとAPIキーをコピーしてください。**接続情報をコピー** で設定をまとめてコピーできるほか、**Reveal key** でマスクされたキーを表示することもできます。

    <div className="ch-image-lg">
      <Frame>
        ![マネージドテレメトリーの接続情報](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    以下の OTLP エクスポーターの例を使用するには、collector を実行する端末で次の変数を設定します。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    プレースホルダーは、サービスの正確なエンドポイント (ポートを含む) とAPIキーに置き換えてください。エンドポイントには `/v1/logs` 接尾辞を付けず、ベースの HTTP エンドポイントを指定します。シグナルのパスはエクスポーターによって追記されます。
  </Tab>

  <Tab title="セルフマネージド">
    collector の接続可能な OTLP HTTPエンドポイント (例: `http://YOUR_COLLECTOR_HOST:4318`) と認証設定を使用します。collector で認証が不要な場合は、以下の構成からエクスポーターの `headers` ブロックを省略してください。セットアップ手順については、[セルフマネージド版スタートガイド](/ja/clickstack/self-configured/getting-started/managed)を参照してください。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

エンドポイントには collector コンテナから接続できる必要があります。宛先の collector がこのコンピューター上で動作している場合は、`http://host.docker.internal:4318` を使用してください。以下の Docker コマンドには、このホストのマッピングが含まれています。

## 既存の Redis との連携 {#existing-redis}

<Steps>
  <Step title="Redisのログ設定を確認する" id="verify-redis">
    Redis のログの出力先を確認します。

    ```bash
    redis-cli CONFIG GET logfile
    ```

    Redis のログの主な出力先：

    * **Linux (apt/yum)**: `/var/log/redis/redis-server.log`
    * **macOS (Homebrew)**: `/usr/local/var/log/redis.log` または `/opt/homebrew/var/log/redis.log`
    * **Docker**: 通常は stdout に出力されますが、`/data/redis.log` に書き込むよう設定することもできます

    Redis のログが stdout に出力されている場合は、`redis.conf` を編集してファイルに書き込むよう設定します：

    ```bash
    # Log to file instead of stdout
    logfile /var/log/redis/redis-server.log

    # Set log level (options: debug, verbose, notice, warning)
    loglevel notice
    ```

    ログディレクトリが存在し、Redis がそのディレクトリに書き込めることを確認してください。設定を変更したら、ご利用の環境のサービス名を指定して Redis を再起動します。

    ```bash
    # For systemd
    sudo systemctl restart redis

    # For Docker
    docker restart <redis-container>
    ```
  </Step>

  <Step title="collectorの設定" id="configure-collector">
    次の内容を `redis-monitoring.yaml` として保存します。

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis/redis-server.log
        start_at: end
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis
          - type: add
            field: resource["service.name"]
            value: redis-service

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, batch]
          exporters: [otlp_http/observability]
    ```

    この設定では、プロセス ID、ロール、タイムスタンプ、ログレベル、メッセージをパースします。また、`service.name` を `redis-service` に設定し、ダッシュボードで利用できるよう Redis のログレベルを `SeverityText` にマッピングします。Redis の notice メッセージ (`*`) は `info` に、警告 (`#`) は `warn` に、debug/verbose メッセージ (`.` と `-`) は `debug` にマッピングされます。

    Redis のログのタイムスタンプにはタイムゾーンが含まれていません。`location` には、`America/Chicago` のように Redis サーバーのタイムゾーンを設定してください。この例では `UTC` を使用しています。元のタイムスタンプとログ本文はそのまま保持されます。`start_at: end` を指定すると、collector が初めてファイルを開いた際には新しいエントリのみが読み込まれます。
  </Step>

  <Step title="collectorを実行する" id="run-collector">
    [接続変数](#connection-details)を設定してから、`redis-monitoring.yaml` があるディレクトリで次のコマンドを実行します。ホストのログディレクトリのパスと、receiver の `include` に指定するファイル名は、ご使用の環境に合わせて調整してください。

    ```bash
    docker run --rm --name redis-monitoring-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/redis:/var/log/redis:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    この端末は開いたままにして、新しいログエントリが書き込まれるような Redis の操作を発生させてください。collector には、マウント済みのファイルに対する読み取り権限が必要です。
  </Step>

  <Step title="ログを確認する" id="verify-logs">
    **検索**を開き、**Logs** を選択して、`ServiceName:redis-service` でフィルタします。新しいログが含まれる時間範囲を選択します。エントリを展開すると、`SeverityText` と、`LogAttributes` 配下のパース済みフィールドを確認できます。

    <div className="ch-image-lg">
      <Frame>
        ![検索ビューに表示された Redis ログ](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## デモデータセット {#demo-dataset}

このサンプルには、10,000 件の Redis サーバーログエントリが含まれています。始める前に、[接続変数](#connection-details)を設定してください。

<Steps>
  <Step title="サンプルデータセットをダウンロード" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-server.log
    ```
  </Step>

  <Step title="デモ用collectorの設定" id="configure-demo">
    以下の内容を、ダウンロード先のディレクトリに `redis-demo.yaml` として保存します。

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis-demo/redis-server.log
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis-demo
          - type: add
            field: resource["service.name"]
            value: redis-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-28T14:59:22Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      デモ専用の `transform/demo_timestamps` プロセッサーは、トラフィックパターンを維持したまま、サンプルの時刻をおおよそ過去 24 時間の範囲 (インジェストの 2 分前まで) にシフトします。元のタイムスタンプ属性とログ本文は変更されません。独自の Redis ログを取り込む場合は、このプロセッサーを使用しないでください。
    </Note>
  </Step>

  <Step title="デモ用のcollectorを実行する" id="run-demo">
    `redis-server.log` と `redis-demo.yaml` が置かれているディレクトリで、次のコマンドを実行します。

    ```bash
    docker run --rm --name redis-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/redis-server.log:/var/log/redis-demo/redis-server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    インジェストを確認している間は、端末を開いたままにしてください。確認が終わったら、**Ctrl+C** で collector を停止します。この例ではファイルのオフセットを永続化しないため、デモを再度実行すると、タイムスタンプを更新したうえでサンプルが再度取り込まれます。
  </Step>

  <Step title="デモのログを確認する" id="verify-demo-logs">
    **検索** を開いて **Logs** を選択し、`ServiceName:redis-demo` でフィルタして **過去2日間** を選択します。ログエントリを展開すると、パースされた属性と重大度を確認できます。

      <Frame>
        ![検索ビューに表示された Redis ログの例](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## トラブルシューティング {#troubleshooting}

### collector が起動しない {#collector-fails-to-start}

collector を実行している端末に設定エラーが出力されていないか確認してください。また、YAML ファイルがドキュメントに記載されたパスにマウントされていること、そして Docker を実行する端末でエンドポイントと必要な認証用の変数が設定されていることも確認してください。

### ログが表示されない {#no-logs}

* collector の出力に認証エラーやエクスポートエラーが出ていないか確認し、接続情報が正しいことを確認してください。
* `redis-cli CONFIG GET logfile` を実行して、Redis がファイルにログを書き込んでいることを確認してください。また、collector がそのファイルを読み取れること、マウント済みのパスが receiver の `include` パスと一致していることも確認してください。
* `start_at: end` を指定している場合は、collector の起動後に新しいログエントリを生成してください。
* **Logs** ログソース、サービス名フィルター、時間範囲を確認してください。デモの場合は、パイプラインに `transform/demo_timestamps` を含め、**過去2日間** を選択してください。

### ログが正しくパースされない {#logs-not-parsing}

この receiver は、Redis 標準の `pid:role timestamp level message` フォーマットを前提としています。ログファイルを確認し、フォーマットが異なる場合は正規表現を調整してください。また、時刻パーサーの `location` には Redis サーバーのタイムゾーンを設定してください。
