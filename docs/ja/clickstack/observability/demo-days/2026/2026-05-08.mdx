## Webhook におけるシークレットの取り扱いの改善 {#improved-handling-of-secrets-in-webhooks}

*デモ担当者: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/aD7sT5dc470" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Webhook の URL やヘッダーには、認証情報が平文のまま含まれていることがよくあります。Slack の Webhook URL ではパスにシークレットトークンが含まれ、HTTP Webhook では通常、認証のために Authorization ヘッダーが必要です。このリリースまでは、Webhook の一覧表示および編集に使用される HyperDX の内部 API が、リクエストのたびにこれらの情報をすべて返していました。そのため、認証済みのチームメンバーであれば誰でも、API にアクセスするだけでシークレットを閲覧できる状態でした。

今回の変更では、パブリック API ですでに採用されているものと同じマスキング方式を適用しています。Webhook URL はパスが `****` に置換された状態で返されるため、Slack トークン(またはパスに埋め込まれたその他のキー)がサーバーの外に出ることはありません。また、どのヘッダーにシークレットが含まれているかを確実に判別する方法がないため、ヘッダーもデフォルトでマスキングされます。すべての値が `****` に置換され、表示されるのはヘッダー名のみです。

編集フォームでは、マスキングされた値を「変更なし」として扱います。そのままにすれば保存済みの値が維持され、変更すれば新しい値が保存され、空にすればフィールド自体が削除されます。これにより、よくあるケース(1 つのフィールドだけを編集する場合)でも操作の流れがわかりやすく、実際のシークレットがブラウザとの間でやり取りされることも一切ありません。

## アラートの追加メタデータ {#extra-metadata-in-alerts}

*デモ担当者: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/evEd7Cc9e1c" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

コミュニティ Slack で寄せられた要望に応え、アラートに自由形式のコンテキストを追加できるようになりました。しきい値の変更履歴、ランブックへのリンク、オンコール担当者向けのメモなどを記載できます。この情報は AI による要約の信頼できる根拠としても役立ちます。発火中のアラートに対応する LLM は、クエリだけから意図を推測するのではなく、運用者自身の判断理由を踏まえて回答できるようになります。

メモフィールドは Markdown のレンダリングに対応しているため、折りたたみセクション、リスト、リンクをいずれも利用できます。メモはアラート設定に保存され、アラートが表示されるすべての場所に表示されます。UX はまだ確定しておらず、現在の Markdown 表示はあくまで出発点です。表示方法についてのフィードバックをお待ちしています。

あわせて、この PR では保存済み検索における発火中アラートの UX も改善しています。アラートが発火している場合は、アラート ボタンのベルアイコンに赤いドットが表示されます。また、ダイアログボックスでは単にリンクを示すだけでなく、どのアラートが有効になっているかが強調表示されます。さらに、同じ状態に対する視覚的な表現が、ダッシュボードタイルですでに採用されているものと統一されました。

**関連 プルリクエスト:** [#2210](https://github.com/hyperdxio/hyperdx/pull/2210) [HDX-3044] アラートに任意のメモフィールドを追加

## 今後のテーマ候補 {#possible-themes}

*デモ担当者: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/JZYGz6ZOPf4" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

これはハッカソンでの実験で、IDE に着想を得た 3 つのテーマを ClickStack UI に追加したものです。Nord (北極を思わせるブルー) 、Catppuccin (パステル調) 、One Dark (Atom 風) の 3 種類で、それぞれにライトとダークのバリアントがあります。元になったテーマからカラートークンを生成する方法を試したところ、ほぼ再現できましたが、サイドバーの色や線のコントラストなど、まだ調整が必要な粗い部分がいくつか残りました。

この PR は最終的にマージされず、クローズされました。チームは ClickUI への移行を進めていますが、ClickUI は現在単一のテーマしかサポートしていません。また、複数のトークンセットを並行して保守すると継続的な作業が発生し、各組み合わせでコントラストをきちんと検証しようとすれば、その負担はさらに大きくなります。そのため、ClickUI 自体が複数テーマに対応するまで見送ることになりました。

ただし、この実験から得られたデザイン上の知見のうち 1 つは、今後この取り組みを再開する際に念頭に置いておく価値があると考えています。最初のイテレーションでは HyperDX のロゴをテーマごとに色替えしていましたが、これではブランドイメージが損なわれてしまいました。より適切なのは、ライトテーマではダークロゴを、ダークテーマではライトロゴを表示し、緑色の HyperDX ワードマーク自体には手を加えないというアプローチです。

**関連するプルリクエスト:** [#2191](https://github.com/hyperdxio/hyperdx/pull/2191) feat: add IDE-inspired themes (Nord, Catppuccin, One Dark)
