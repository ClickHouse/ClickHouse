## ダッシュボードフィルタの新しい種類 {#new-types-of-dashboard-filter}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/VnlNxvcvg-g" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

これまで、ダッシュボードフィルタで利用できる値は、ClickHouse のカラムからドロップダウンの選択肢を取得する「クエリ値」の 1 種類のみでした。今回から、フィルタと変数のモーダルでさらに 2 つの種類を選択できるようになりました。

静的値では、フィルタの作成時に選択肢を直接入力できます。たとえば環境フィルタであれば、クエリを用意しなくても `dev`、`staging`、`prod` を選択肢として提示できます。静的リストフィルタには `expression` がないため、変数モードのみに対応しており、ブロードキャストモード用の SQL 条件に変換することはできません。

PromQL ラベル値は、PromQL ログソースの `<label>/values` エンドポイントから選択肢を取得します。対象のラベルを選択し、必要に応じてマッチャーで絞り込むことができます。マッチャーからは他の変数も参照できるため、フィルタ同士を連動させることが可能です。環境を選択すると次のフィルタに表示されるインスタンスがそれに応じて絞り込まれ、PromQL チャートも順次フィルタリングされます。

どちらの種類も変数として公開できるため、フィルタで `WHERE` 句以外の動作も制御できます。デモでは、`ServiceName` と `SeverityText` を選択肢とする静的フィルタをチャートの group-by 次元として使用しています。ドロップダウンで値を選択すると、チャートのグループ化の基準を任意の組み合わせで切り替えられます。

## PromQL チャート向けのカスタム凡例テンプレート {#custom-legend-templates-for-promql-charts}

*デモ担当者 [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/2rR_kRAEvWw" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Vladimir の指摘のとおり、PromQL の凡例は読みにくいものでした。デフォルトでは、メトリクス名に続けて、返された系列間で値が異なるすべてのラベルを表示します。そのため、多数の系列を返すクエリでは凡例が長い文字列になり、内容を把握するにはクリックして確認する必要がありました。

チャートの表示設定で凡例テンプレートを指定できるようになりました。Handlebars テンプレートなので、本当に必要なラベルだけを参照して、凡例とツールチップの両方に短い系列名を表示できます。

テンプレートで存在しないラベルを参照した場合、その部分は空としてレンダリングされます。結果が空になる場合や、系列間で一意にならない場合は、系列を区別するラベルをすべて表示する形にフォールバックします。そのため、見分けのつかない系列が 2 つ並ぶことはありません。

**関連するプルリクエスト:** [#3055](https://github.com/hyperdxio/hyperdx/pull/3055) PromQL 系列の凡例でカスタムテンプレートをサポート

## 相対的な日付範囲をダッシュボードのデフォルトとして保存する {#saving-a-relative-date-range-as-a-dashboard-default}

*デモ担当者: [@knudtty](https://github.com/knudtty)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/8KzwsEG-KSg" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

ダッシュボードのデフォルトとして、相対的な日付範囲を保存できるようになりました。表示したい時間範囲を設定して「Save Query and Filters as default」をクリックすると、以降はその範囲でダッシュボードが開きます。

重要なのは、範囲が相対的であるという点です。「過去 6 時間」を保存しておけば、固定の期間に縛られて表示が古くなることはなく、いつ開いても適切な範囲が表示されます。ダッシュボード上で範囲を変更して過去 7 日間を確認することも引き続き可能です。別のページに移動してから戻ってくると、保存したデフォルトの範囲で表示されます。

**関連プルリクエスト:** [#3073](https://github.com/hyperdxio/hyperdx/pull/3073) ダッシュボードで相対的な日付範囲を保存可能に

## 保存済み検索やダッシュボードタイルを使用しないアラート {#alerts-without-a-saved-search-or-dashboard-tile}

*デモ担当者: [@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/wuK7geV7F94" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

これまでは、すべてのアラートに紐づく対象が必要でした。ログの場合は保存済み検索、メトリクスの場合はダッシュボードタイルです。しかしこの方式では、数千件規模の Grafana アラートを移行する際に対応しきれません。

インラインアラートにより、この要件はなくなりました。Chart Explorer のアクションバーに **Create alert** アクションが追加されたため、メトリクスやイベントのチャートを作成し、事前に何も保存せずにそのチャートから直接アラートを設定できます。また、アラートページからインラインアラートを作成することもできます。アラートを保存済み検索やダッシュボードに関連付けたくない場合は、こちらの方法を使用してください。

インラインアラートは、ダッシュボードタイルが保存するのとまったく同じ形状で、独自の `chartConfig` をアラートドキュメントに永続化します。そのため、別系統のコードパスではなく、タイルアラートと同じコードパスで評価されます。`line`、`stacked_bar`、`number` の各表示形式で、ビルダーと生のSQLの両方に対応しています。なお、PromQL は現時点ではサポートされていません。

同じ `source: 'inline'` の形状は、外部 API v2 および MCP の `save_alert` ツールでも受け付けられます。v2 ダッシュボードと同じタイル設定のダイアレクトを使用するため、アラートをプログラムから大規模に作成できます。ルーターはダッシュボードタイルのコンバーターを再利用しているため、2 つのインターフェース間でドリフトが生じません。

**関連 プルリクエスト:** [#3010](https://github.com/hyperdxio/hyperdx/pull/3010) 保存済み検索やダッシュボードタイルを使用しないアラート作成のサポート (バックエンド) 、[#3069](https://github.com/hyperdxio/hyperdx/pull/3069) インラインのチャートアラートを作成・編集するための UI、[#3043](https://github.com/hyperdxio/hyperdx/pull/3043) 外部 API v2 および MCP におけるチャートアラートのサポート

## アラート名とタグ {#alert-names-and-tags}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/nIJGusSLBuk" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

アラートに独自の名前とタグを設定できるようになりました。ダッシュボードタイルまたは保存済み検索のアラートフォームに名前とタグの入力欄が追加されています。新しく作成したアラートの名前には、デフォルトでチャートまたは保存済み検索の名前が使われ、タグは配置先のダッシュボードまたは保存済み検索から継承されます。

アラートページにはこの名前が表示され、検索やフィルタもこの名前に基づいて行われます。データベースに既に存在する、名前が未設定のアラートについては、従来どおり参照先の保存済み検索またはダッシュボードから名前が導出されます。

`team/tags` エンドポイントが返すタグに、ダッシュボードと保存済み検索のタグに加えて、アラートドキュメントのタグも含まれるようになりました。これにより、アラートでのみ使用されているタグも、次のアラートにタグを付ける際に候補として表示されます。

これは、タグによる検索とフィルタに対応したまま、アラートページにページネーションを導入するための下準備です。それを実現するには、ダッシュボードや保存済み検索のコレクションと結合するのではなく、アラートドキュメント自体に名前とタグを持たせる必要があります。なお、ページネーションはまだ実装されていません。

## 探索のプロトタイプ {#an-explore-prototype}

*デモ担当者: [@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/vlGMKp5Eroc" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

**これは探索的な取り組みであり、リリースを確約するものではありません。**

このプロトタイプは、検索ページと Chart Explorer の両方を置き換える、単一の探索ページです。現在、HyperDX リポジトリでドラフトとして公開されています。これらのページを置き換えるかもしれませんし、3 つ目のページとして併存するかもしれません。あるいは、最終的に何も実現しない可能性もあります。

このプロトタイプが取り組む課題は、現在の 2 つのページ間の行き来です。顧客からは、検索で調べていた内容を Chart Explorer に引き継ぐのが面倒だという声が寄せられています。移動先でデータソースを選択し直し、同じクエリを組み直さなければならないことがよくあるためです。探索ではこれを 1 つのページで完結させます。ページ自体を移動するのではなく、イベント、パターン、差分、チャートの間でビューを切り替える仕組みです。

2 つ目のテーマは、クエリ言語に慣れていないユーザーのハードルを下げることです。テーブルへのカラムの追加、ソート、group-by の選択はドロップダウンで行え、必要なときには SQL も引き続き使えます。group-by は現状の課題をよく表しています。検索ページのヒストグラムはステータスコードでグループ化されたまま変更できないため、別の軸でグループ化したい場合は Chart Explorer に移動するしかありません。探索では、イベントビューで group-by を設定し、小さなヒストグラムで物足りなければ時系列チャートや棒グラフに切り替え、集約を `p99` などに変更して、その結果をダッシュボードに保存できます。

フィルタバーは、Lucene と SQL の両方を抽象化した小さなクエリビルダーです。フィールドを選び、オペレーターを選び、値を入力するだけで使えます。上級ユーザー向けには、フル機能のクエリエディターとマクロも用意されています。そもそもクエリ言語を 2 つ持つこと自体が適切なのかどうかも、まだ結論の出ていない検討事項の 1 つです。

未解決の点は数多く残っています。PromQL にはまだ対応しておらず、メトリクスをこのページで扱うべきか、それとも 1 つのページに詰め込みすぎになるのかも決まっていません。このプロトタイプは、ログとトレースの体験に重点を置いています。
