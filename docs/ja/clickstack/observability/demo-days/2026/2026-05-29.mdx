## バージョンを考慮したスキーマフィルタリングの改善 {#version-aware-improved-schema-filtering}

*デモ担当者: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/bAVaBnfJ82Y" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack は、direct&#95;read 最適化を ClickHouse 26.2 以降のバージョンでのみ適用するようになりました。これらのバージョンでは、オープンソース版のスキーマに追加された別名カラムを全文検索索引が正しくサポートしています。以前は、この最適化が正しく動作しない古いバージョンでも適用が試みられることがありました。バージョンチェックはクエリ実行時にスキーマを検査して行われます。また、別名カラム自体もデフォルトでオープンソース版のスキーマに含まれるようになりました。

あわせて、自動補完用の materialized view をテキスト索引への直接クエリに置き換える、現在進行中の作業も紹介されました。現状では両者の処理が重複しており、取り込みの負荷を増大させています。ベンチマークでテキストインデックスを使用するクエリに十分なパフォーマンスがあると確認できれば、materialized view を簡素化または廃止できます。さらに Aaron は、将来の ClickHouse テキスト索引に位置依存エンコーディングが導入されることで、キー・バリューのフィルタルックアップの精度がさらに向上する可能性について、チームからの質問に答えました。

## ログパースの改善 {#better-log-parsing}

*デモ担当者: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/vhkMlddahu4" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

あるお客様のログでは、イベントのボディが `level` フィールドを含む JSON オブジェクトになっていました。重大度の推論ロジックは 2 つの処理を行っていました。1 つはボディを JSON としてパースして属性を抽出する処理、もう 1 つは OTel レベルで重大度が設定されていない場合に文字列マッチングへフォールバックする処理です。この文字列マッチングが、ボディ内のアラートマネージャー名に含まれる「alert」という単語を拾ってしまい、ログレベルを誤って分類していました。

今回の修正では、ガード条件を追加しました。ボディが JSON としてパースでき、すでに level フィールドを含んでいる場合は、文字列による推論ステップを完全にスキップします。約 1 年前に構築したスモークテストスイートのおかげで、新しいテストケースを追加するだけで修正を検証し、関連するエッジケースも検出できました。これこそ、このテストスイートが本来想定していた使い方です。

**関連するプルリクエスト:** [#2363](https://github.com/hyperdxio/hyperdx/pull/2363) fix(log-parser): skip string inference when body parses as JSON with a level field

## 新しい系列カラーパレット {#new-series-color-palette}

*デモ担当者: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/YzECP3diWvg" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Elizabet は、Alex によるカラーピッカーの開発を支援するため、HyperDX と ClickStack の両テーマでデータ可視化用のカラーパレットを統一する作業に取り組みました。これまでは 2 つのテーマがそれぞれ別のパレットを持ち、テーマごとに例外ルールも設けられていたため、色の扱いが必要以上に複雑になっていました。そこで、両方のテーマで使える単一のパレットを目指しました。

彼女は色覚シミュレーションツールを使い、業界標準のパレット (Tableau、Observable、IBM) についてコントラストとアクセシビリティを検証しました。ClickHouse のパレットは結果が芳しくなく、緑色が白背景に対して十分なコントラストを確保できていませんでした。Tableau と Observable はいずれも少なくとも 1 つのチェックで不合格となり、IBM のパレットはすべてのチェックに合格したものの、5 色しかないため色数が足りませんでした。総合的には、青色をわずかに調整した Observable のパレットが最も理想に近く、今後はこれを両テーマで共通して使用します。

**関連するプルリクエスト:** [#2362](https://github.com/hyperdxio/hyperdx/pull/2362) refactor(theme): rename chart palette tokens to hue names + unify across themes

## 追従固定ヘッダーを備えた新しいページレイアウト {#new-page-layout-with-sticky-header}

*デモ担当者: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/e7d3ocqi4Ac" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

新たに PageHeader と PageLayout の 2 つのコンポーネントを用意し、ダッシュボード、サービスマップ、クライアントセッション、Kubernetes、ClickHouse ダッシュボードといった主要ページすべてに導入しました。これにより、すべてのページでパディング、ヘッダー下の境界線、タイトル構造が統一されました。従来は、左側にタイトル、右側にコントロールを配置したページもあれば、タイトル自体がないページもあり、ページごとに統一感がありませんでした。

追従固定の動作は prop で有効にするオプトイン方式です。sticky スロットに渡した要素はスクロール時もヘッダーの下に固定され、それ以外の要素は通常どおりスクロールします。何も渡さない場合は、パンくずリストまたはページオプションのみが自動的に追従固定されます。

## 新しいデータソースセレクターと系列のカラーピッカー {#new-datasource-selector-and-color-picking-for-series}

*デモ担当者: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/DKfJs9onl50" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Alex による UI の改善が 2 点あります。まず、データソースセレクターが整理され、クリックすると選択可能なデータソースのみが表示されるようになりました。スキーマの表示や新しいログソースの作成といった管理アクションは、独立したケバブメニューに移されています。これにより、選択と設定の操作が分離されました。以前から ToDo リストに挙がっていた対応であり、チームから寄せられたフィードバックにも応えるものです。

また、数値タイルに静的なカラーピッカーが追加され、メトリクスに特定の色を割り当てられるようになりました。しきい値やカラムに応じて赤・緑・黄に切り替わる条件付きカラールールも現在開発中です。Elizabet による統一パレットが導入されると、どちらも現在の「color 1, 2, 3」というラベルではなく、適切な名前の付いた色を使用するようになります。Grafana などのツールから移行してきたユーザーにとっては、大きな改善となるはずです。

**関連プルリクエスト:** [#2365](https://github.com/hyperdxio/hyperdx/pull/2365) feat(source-picker): chip + kebab menu UX, [#2265](https://github.com/hyperdxio/hyperdx/pull/2265) feat(app): number tile static color picker
