## ClickCannon のデータ生成機能のアップデート {#clickcannon-data-generation-update}

*デモ担当者: [@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Zljd07_4uF4" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

[ClickCannon](https://github.com/clickhouse/clickcannon) は、社内でサイジング作業に使用しているツールです。大量の OpenTelemetry データを生成しながらクエリを同時実行し、特定の取り込みおよびクエリのワークロードに対してお客様が必要とするリソースを見積もります。OpenHouse でこのツールを一般公開し、Spencer が最新版を紹介しました。

ディスク上にデータを事前に用意しなくても、ジェネレーターをインラインで設定できるようになりました。ジェネレーターを有効化し、スレッド数、ブロックあたりの行数、1 秒あたりの合計行数、いくつかのメモリ制約を設定するだけです。これまでこのツールを共有しにくくしていた、2 テラバイトものテストデータを事前にディスクへ配置する作業も不要になりました。

今後は、ユーザーが独自にサイジングを行う際にも、ClickCannon の利用を積極的に案内していく予定です。リポジトリは [https://github.com/clickhouse/clickcannon](https://github.com/clickhouse/clickcannon) で公開されています。

## 全画面タイルの日付入力とログソース単位のフィルタ {#date-input-for-full-screen-tiles-and-source-scoped-filters}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Mop1EYtGwKc" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ダッシュボードに関する 2 つの改善が同時にリリースされました。1 つ目として、単一のタイルを全画面表示すると、ダッシュボード全体の時間範囲とは独立した専用の時刻ピッカーと粒度セレクターが使えるようになりました。これにより、ダッシュボード上の他のタイルをすべてリフレッシュすることなく、特定のメトリクス (たとえば ClickHouse クラスター ダッシュボード上の 1 つのチャート) の長期間の履歴を拡大して確認できます。また、ブラウザのタブタイトルにダッシュボード名が表示されるようになりました。

2 つ目は、ダッシュボードフィルタをログソース単位で適用できる機能です。フィルタをすべてのタイルに一律に適用するのではなく、特定のソースを使用するタイルにのみブロードキャストするよう制限できます。たとえばログとトレースが混在するダッシュボードでは、無関係なタイルにフィルタが適用されてしまうのを防げます。

**関連プルリクエスト:** [#2302](https://github.com/hyperdxio/hyperdx/pull/2302) feat: Minor dashboard improvements、[#2331](https://github.com/hyperdxio/hyperdx/pull/2331) feat: Add source scoping to dashboard filters

## lower(Body) に定義されたテキスト索引を認識 {#text-index-recognised-on-lower-body}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/l0GpNBP859o" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

大文字と小文字を区別しない検索について、小規模ながら実質的な効果のある正確性の修正です。ログソースで、プリプロセッサ引数を指定せずに `lower(Body)` に対してテキスト索引が定義されている場合、これまでクエリプランナーは `hasAllTokens(Body, ...)` という条件を生成していました。この式は索引の式と一致しないため、テキスト索引が使用されず、クエリはスキャンにフォールバックしていました。

現在は、索引の式と一致する `hasAllTokens(lower(Body), ...)` としてクエリが生成されます。これにより、このように設定されたログソースでは、大文字と小文字を区別しない検索がテキスト索引によって正しく高速化されるようになりました。

**関連 プルリクエスト:** [#2326](https://github.com/hyperdxio/hyperdx/pull/2326) feat: support text index on lower(Body) with no preprocessor

## イベントデルタの操作がよりシンプルに {#simpler-event-deltas-experience}

*デモ担当者: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/BrIHHFz_Aw8" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

これまでイベントデルタでは、余分なステップが 1 つ必要でした。ヒートマップ上でドラッグして範囲を選択する前に、ボタンをクリックして比較モードに切り替える必要があったのです。このステップは不要になりました。読み込み時に分布の棒グラフがすぐに表示され、ヒートマップ上で領域をドラッグした瞬間に、選択範囲と背景を比較する比較モードへと棒グラフが切り替わります。選択範囲の外側をクリックすると、全スパンのビューに戻ります。

元の変更は数週間前に OSS に取り込まれていましたが、その一部が Managed ClickStack には反映されていませんでした。この差異が解消され、両エディションで同じシンプルな操作フローを利用できるようになりました。

**関連 プルリクエスト:** [#1899](https://github.com/hyperdxio/hyperdx/pull/1899) feat: always-on attribute distribution mode

## ダッシュボードの目次と一括折りたたみ {#dashboard-table-of-contents-and-bulk-collapse}

*デモ担当者: [@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Pojo5zf_hrE" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ダッシュボードのセクションが数個を超えると (セクションは大規模なダッシュボードを整理するための仕組みなので、セクションが増えること自体は望ましいことです)、ダッシュボード内の移動が煩わしくなります。そこで Tom は、すべてのセクションを一覧表示し、セクション間を直接ジャンプできる目次を右サイドバーに追加しました。さらに、すべてのセクションの内容をまとめて非表示にできる一括折りたたみ・展開コントロールも追加されたため、長いダッシュボードを最後までスクロールしなくても、その構成をひと目で把握できます。

まだドラフト段階ですが、ClickHouse クラスターや Kubernetes のビュー向けに提供している、複数のセクションで構成されたダッシュボードですでに活躍しています。

**関連するプルリクエスト:** [#2350](https://github.com/hyperdxio/hyperdx/pull/2350) feat(dashboard): add Table of Contents right rail with bulk collapse/expand

## カラムのリサイズをセッション間で永続化 {#column-resize-persisted-across-sessions}

*デモ担当者: [@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/7l-Rz1tFlq8" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

昨日お客様から、結果テーブルでカラムのサイズを変更したら、その設定が保持されるようにしてほしいという要望が寄せられました。これに対応しました。変更後の幅はテーブル ID ごとにローカルストレージへ保存されるため、テーブルごとに独立したカラムレイアウトが維持されます。ブラウザを閉じて後で開き直しても、カラムは前回の状態のままです。また、テーブルにカラムを追加または削除しても、他のカラムの幅がリセットされることはありません。

**関連するプルリクエスト:** [#2327](https://github.com/hyperdxio/hyperdx/pull/2327) fix: persist column widths in search results table
