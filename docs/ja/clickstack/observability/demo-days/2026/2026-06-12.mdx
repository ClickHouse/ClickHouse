スキーマ移行ツールは、現在活発に開発が進められている ClickStack の新機能で、UI から直接 ClickHouse のスキーマ移行を実行・監視できます。デモでは、Warren がマイグレーターを有効にして `body` カラムに全文検索索引を作成し、その後、リアルタイムのログ出力で進捗を確認しながらその索引を削除しています。

## アラートと MCP 向けのソースレベルフィルター {#source-level-filters-for-alerts-and-mcp}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/z0Lbggcy6dU" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Drew が、ClickStack 全体でのソースフィルター対応の大幅な拡張をデモします。ソースフィルターを必要とするダッシュボードタイルや生のSQLタイルにもアラートを設定できるようになりました。フィルタが指定されていない場合や、クエリに挿入用のフィルタマクロが含まれていない場合には、わかりやすいインラインガイダンスが表示されます。保存済み検索のアラートも同様に動作します。

ソースフィルターはサービスマップ全体で適用されるようになり、選択内容は関連付けられた検索ページやトレースのサイドパネルにも引き継がれます。

MCP もソースフィルターに対応しました。エージェントはフィルタの要件を自動検出し、利用可能な値を取得して、フィルタをクエリツールに渡せます。フィルタの値は相互にプルーニングされるため、あるフィルタでの選択に応じて、他のフィルタで選択可能な値が絞り込まれます。必須フィルタが省略された場合、MCP はそれらを自動的に選択し、適用した値を報告します。初期の評価結果では、ソースフィルターを使用しないソースへの目立った影響は確認されていません。

**関連 プルリクエスト:** [#2459](https://github.com/hyperdxio/hyperdx/pull/2459) feat: show icon on tiles with excluded source-scoped filters, [#2331](https://github.com/hyperdxio/hyperdx/pull/2331) feat: Add source scoping to dashboard filters

## Datadogレシーバー {#datadog-receiver}

*デモ担当者: [@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/P0VVuN_yL6Q" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Spencer が Datadogレシーバーの改善点をデモで紹介します。

これまで Datadog のログペイロードは、その大部分がメッセージ本文内の非構造化 JSON として取り込まれていました。現在は、この receiver がトレースID、スパンID、タイムスタンプ、HTTPリクエストのメタデータといった主要なフィールドを抽出し、標準の OpenTelemetry リソース属性およびログ属性に昇格させるようになりました。

さらに、Datadog の 64 ビットの数値トレースIDが 128 ビットの OpenTelemetry フォーマットに拡張されるため、ClickStack 内でトレースを正しく相関付けられるようになります。この receiver は ClickStack コレクターのディストリビューションに同梱される予定で、エンドツーエンドのトレース相関に関する追加テストも計画されています。

Alex が、ClickStack のトレースビューアーで開発中のスパンリンク対応をデモします。スパンリンクは、あるスパンから別のトレース内の関連スパンを参照できるようにする OpenTelemetry の概念で、トレーシング機能の中でも特に要望の多いものです。

現在の実装では、リンクされたスパンとその属性がトレースパネル内に直接表示されます。デザインや表示方法は引き続き改良中のため、あくまで開発途上の機能としてご覧ください。
