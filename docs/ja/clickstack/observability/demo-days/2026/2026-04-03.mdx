## ダッシュボードと保存済み検索の新しい一覧ページ {#new-dashboard-and-saved-search-listing-pages}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/dQCkNZElwcg" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ダッシュボードと保存済み検索は、サイドバーから専用の一覧ページに移動しました。チーム内でダッシュボードがある程度増えてくると、従来のサイドバー方式ではすぐに扱いにくくなっていました。新しいページでは、すべての項目がタグごとに整理されたカードビューで表示され、名前検索とタグによるフィルタリングも組み込まれています。よりコンパクトなリストビューに切り替えることもできます。

お気に入り機能も加わりました。ダッシュボードや保存済み検索にスターを付けると、一覧ページの上部に固定されるとともに、サイドバーにも表示されてすばやくアクセスできます。以前と同様の使い勝手を保ちながら、他のユーザーのナビゲーションを煩雑にすることもありません。また、一覧ページの各カードにはアラートのステータスアイコンと「作成者 / 更新者」のメタデータが表示されるため、誰が何を管理しているか、発火中のアラートがあるかどうかをひと目で把握できます。

さらに、新しいテンプレートギャラリーも追加されました。Node.js、Python、Go、Java の OTel ランタイムメトリクスを対象とした 4 つのあらかじめ用意されたダッシュボードを、数クリックでインポートできます。インポート時にタグと対象のメトリクスログソースを編集できるため、既存のタグ体系にそのまま組み込めます。

## フィルタのためのフィルタ {#filters-for-filters}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Tfe9kJygoEg" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ダッシュボード変数のフィルタに、独自のフィルタ条件を指定できるようになりました。動機となったユースケースは単純です。Node.js 用のダッシュボードに「サービス名」のドロップダウンがある場合、そこには環境内のすべてのサービスではなく、Node.js のサービスだけを表示したいはずです。ダッシュボード変数にフィルタ条件を直接設定することで、表示対象を絞り込めるようになりました。

また、フィルタのセレクターが複数選択に対応しました。サービスごとにグループ化したダッシュボードでは、ドロップダウンから複数の値をまとめて選択できるため、比較がぐっと実用的になります。

**関連するプルリクエスト:** [#1969](https://github.com/hyperdxio/hyperdx/pull/1969) Add conditions to ダッシュボード フィルタ; Support filter multi-select

## 事前定義ダッシュボードの RBAC {#rbac-for-predefined-dashboards}

*デモ担当者: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/AZ94-quHEuw" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack のプリセットダッシュボードにも、ロールベースのアクセス制御が適用されるようになりました。これまでこれらの組み込みダッシュボードには RBAC がまったく適用されておらず、割り当てられたロールに関係なく、どのユーザーでもアクセスできる状態でした。今回の変更で、この抜け穴が解消されています。

きめ細かな閲覧アクセス許可も期待どおりに機能します。特定のサービスへの読み取り専用アクセスを設定したロールでは、ユーザーに表示されるプリセットダッシュボードが、それらのサービスに関連するものだけに制限されます。このロールのユーザーはダッシュボードとそのフィルタを閲覧できますが、フィルタのコントロールはロックされ、編集できません。デモでは、特定のサービスにスコープを限定した &quot;services&quot; の閲覧アクセス許可を持つカスタムロールを作成し、そのロールでログインしたユーザーに、アクセスが許可されたダッシュボードとフィルタの状態だけが表示される様子を紹介しています。

## 検索の最適化 {#optimizations-for-searching}

*デモ担当者: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/uVD2FKzoHjM" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickHouse の「順序に従った読み取り (Read in Order) 」最適化は、ORDER BY がテーブルの主キーと一致する場合にデータを順次読み取り、LIMIT に達した時点で読み取りを打ち切ることで、検索クエリを高速化します。しかしベンチマーク測定の結果、この最適化があっても、大規模なデータセットでは検索が必要以上のデータをフェッチしていることが判明しました。原因は、走査されるパーツの数にあります。最適化が有効であっても、テーブルが十分に大きければパーツ数も多くなるため、ClickHouse は結局、必要以上のデータを読み取ってしまいます。

そこで、検索クエリ用のウィンドウ化クエリ配列の先頭に、1 分間の時間ウィンドウを追加しました。ほとんどの検索では、必要なデータは直近 1 分間に含まれています。そのため、まずこのウィンドウを検索することで、ほぼ即座に結果を返せます。ここで何も見つからなかった場合は、従来どおり段階的に広いウィンドウへとフォールバックします。また、これとは別に、`otel_traces` スキーマではタイムスタンプ列に `toDateTime(Timestamp)` という expression が使われており、これが認識されていなかったため、ORDER BY 最適化が正しく適用されていませんでした。この問題も修正済みです。

**関連 プルリクエスト:** [#2019](https://github.com/hyperdxio/hyperdx/pull/2019) 検索に 1 分間のウィンドウを使用、[#2014](https://github.com/hyperdxio/hyperdx/pull/2014) otel&#95;traces における ORDER BY 最適化の不具合を修正

## 行のコピーとフィルタサイズの設定 {#copy-row-and-configurable-filter-sizes}

*デモ担当者: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/e_IIKG3f6SE" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

行ビューアーに「JSON としてコピー」ボタンが追加され、ログの行全体をワンクリックで取得できるようになりました。このボタンはサイドバーのフルビューにも表示されます。行を LLM のプロンプトに貼り付けて、このログがコード内のどこで出力されるかを尋ねたり、テキストを手動で全選択することなく、インシデントレポート用にイベント全体を記録したりする際に便利です。

サイドバーでフェッチするフィルタキーの数を、クエリ設定のチーム設定として変更できるようになりました。これまでは上限が固定されていたため、大規模なデータセットでは利用可能なフィルタ属性のごく一部しか表示されませんでした。今後はチームでこの上限を引き上げることで、より多くのリソース属性やログ属性を表示できます。また、この変更には仮想化の改善も含まれており、多数のフィルタグループを表示している場合でもフィルタパネルを高速にレンダリングできます。

## ダッシュボードのタブとグループ {#tabs-and-groups-in-dashboards}

*デモ担当者: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/tyumDlJuDTg" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ダッシュボードタイルをグループにまとめられるようになりました。従来は「セクション」と「グループ」という 2 種類のコンテナタイプがあり、どちらを使うかをユーザーが事前に決める必要がありましたが、今回の変更でこのモデルは置き換えられます。グループという単一の概念に統一されたことで、構成がよりシンプルになりました。グループはデフォルトで折りたたみ可能で、必要に応じて枠線を表示したり、タブを追加したりできます。各タブはそれぞれ独自のタイルを持ち、タイルはドラッグハンドルを使ってグループ間で移動できます。

デモでは、グループのカスタマイズオプション (折りたたみ可否のオン/オフ、枠線の表示/非表示、タブの有効/無効) を切り替える様子を紹介しています。デモ時点では、この PR はまだレビュー中で、デザインに関するフィードバックを集めている段階でした。マージされれば、従来の 2 種類のコンテナタイプによるモデルに比べ、ダッシュボード作成者はより柔軟でわかりやすい構成要素を利用できるようになるはずです。

**関連 プルリクエスト:** [#1972](https://github.com/hyperdxio/hyperdx/pull/1972) タブと折りたたみ/枠線オプションを備えたダッシュボードグループ、[#2015](https://github.com/hyperdxio/hyperdx/pull/2015) セクションとグループを単一のグループに統合

## ClickStack CLI {#clickstack-cli}

*デモ担当者: [@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/9XqJNhstabw" title="YouTube ビデオプレーヤー" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack CLI (`hdx`) は、端末を離れることなくログやトレースの検索、tail 表示、調査を行える新しい TUI です。ブラウザと同じ Web セッションの仕組みで HyperDX インスタンスに接続するため、APIキーを別途管理する必要はありません。インスタンスの URL とメールアドレスを指定して `hdx auth login` を一度実行すれば、以降は認証済みの状態が維持されます。

TUI では Web アプリと同じ検索インターフェイスを利用できます。クエリ構文やログソースの選択方法も同じで、個々のログエントリの詳細を掘り下げることもできます。特に注目すべきはトレースのウォーターフォールビューで、ログエントリをクリックすると、分散トレース全体が端末上に直接レンダリングされます。デモでは、エージェント型の利用に関する初期段階の実験も紹介しています。CLI のスキーマのイントロスペクション出力へのアクセスと、ClickHouse プロキシ経由でクエリを実行する機能を AIエージェントに与えることで、エージェントが自律的に問題を調査できるようになります。さらにデモでは、エージェントが Web セッションを使用して Playwright 経由で HyperDX UI を操作し、レンダリングされたチャートからメトリクスを取得して、ログで見つけた内容と突き合わせる様子も示しています。

**関連 プルリクエスト:** [#2043](https://github.com/hyperdxio/hyperdx/pull/2043) @hyperdx/cli パッケージを追加 — イベントの検索と tail 表示を行う端末 TUI
