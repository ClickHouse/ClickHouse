      このガイドでは、[HyperDX Chrome拡張機能](https://github.com/kyreddie/hyperdx-chrome-extension)を使用して、任意の Web サイトにブラウザー SDK を挿入する方法を説明します。対象アプリケーションのソースコードを変更する必要はありません。拡張機能を一度設定すれば、あとはサイトを閲覧するだけで、ClickHouse オブザーバビリティでセッションリプレイを確認できます。

## 概要 {#overview}

    [HyperDX Chrome拡張機能](https://github.com/kyreddie/hyperdx-chrome-extension)は、閲覧中のページに [@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) SDK を挿入します。third-party のアプリケーション、本番環境向けのビルド、厳格な Content Security Policy (CSP) が設定されたローカル開発サーバーなど、コードベースを変更せずにサイト上でセッションリプレイ、RUM、トレース伝播をデバッグしたい場合に便利です。

    SDK は拡張機能に同梱されている (約 480 KB) ため、ページが実行時に CDN からスクリプトを読み込む必要はありません。拡張機能はまず外部の `chrome-extension://` スクリプトによる挿入を試み、CSP によって拡張機能オリジンのスクリプトがブロックされた場合はインラインインジェクションにフォールバックします。

    自分で管理するデモアプリケーションをインストルメントする[セッションリプレイのデモ](/ja/clickstack/observability/example-datasets/session-replay)とは異なり、この方法では Chrome で開いた対応ページをインストルメントします。なお、一部のページではスクリプトの挿入が制限されています。セッションデータは、一般ユーザーとしてサイトを操作することで生成されます。

    セッションリプレイの概要と、ClickHouse オブザーバビリティにおける位置付けについては、[セッションリプレイ](/ja/clickstack/observability/features/session-replay)の機能ページを参照してください。

## 前提条件 {#prerequisites}

    * Google Chrome または Chromium ベースのブラウザ (Edge、Brave など)
    * 既存の完全マネージド型 ClickHouse オブザーバビリティサービス。詳しくは[完全マネージド型の Getting Started ガイド](/ja/clickstack/observability/getting-started)を参照してください。

## デモの実行 {#running-the-demo}

    <Steps>
      <Step title="拡張機能のリポジトリをクローンする" id="clone-extension">
        ```shell
        git clone https://github.com/kyreddie/hyperdx-chrome-extension
        cd hyperdx-chrome-extension
        ```
      </Step>

      <Step title="拡張機能をインストールする" id="install-extension">
        1. Chrome を開き、`chrome://extensions` にアクセスします。
        2. 右上の **Developer mode** を有効にします。
        3. **Load unpacked** をクリックします。
        4. クローンした `hyperdx-chrome-extension` ディレクトリを選択します。

        ツールバーに **HyperDX Browser Extension** として拡張機能が表示されます。
      </Step>

      <Step title="接続情報を取得する" id="get-connection-details">
        ClickHouse オブザーバビリティのサービスを開き、**チーム設定 → Managed Telemetry** に移動します。拡張機能の設定に使用する **OTLP HTTP エンドポイント** と **APIキー** をコピーします。

        提供された HTTPS エンドポイントはポートを含めてそのまま使用し、末尾に `/v1/logs` や `/v1/traces` を付け加えないでください。

        <div className="ch-image-lg">
          <Frame>
            ![チーム設定の Managed Telemetry に、マスクされた OTLP HTTP エンドポイントと APIキーが表示されている画面](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>
      </Step>

      <Step title="拡張機能を設定する" id="configure-extension">
        Chrome ツールバーの **HyperDX Browser Extension** アイコンをクリックし、各設定を入力します。

        | フィールド                         | 完全マネージド型での設定値                         | 備考                                                     |
        | ----------------------------- | ------------------------------------- | ------------------------------------------------------ |
        | **HyperDXの監視を有効にする**          | オン                                    | 挿入全体のオン／オフを切り替えるマスタートグル                                |
        | **サービス名**                     | `my-frontend-app`                     | 必須 — ClickHouse オブザーバビリティ上でサービスを識別するための名前              |
        | **APIキー**                     | マネージドテレメトリーの APIキー                    | 必須。**チーム設定 → Managed Telemetry** からコピーします              |
        | **コレクターの URL**                | マネージドテレメトリーの OTLP HTTP エンドポイント        | 拡張機能のデフォルト URL を **Managed Telemetry** のエンドポイントに置き換えます |
        | **Environment**               | `development`                         | 任意 — リソース属性 `deployment.environment` を設定します            |
        | **Trace Propagation Targets** | `/api\.myapp\.domain/i, /localhost/i` | 任意 — トレースヘッダーを伝播する対象を指定する、カンマ区切りの JavaScript 正規表現パターン  |
        | **一致するURLにのみ挿入する**            | オフ                                    | 有効にすると、インストルメントするサイトを限定できます                            |
        | **Capture console logs**      | オフ                                    | 有効にすると、ブラウザのコンソール出力を転送します                              |
        | **Advanced network capture**  | オフ                                    | 有効にすると、ネットワークリクエストを詳細に収集します                            |

        **Save Configuration** をクリックしてから、インストルメントしたいタブを再読み込みします。
      </Step>

      <Step title="サイトを閲覧してセッションを生成する" id="browse-site">
        Chrome で任意の Web サイトまたはローカルアプリケーションを開きます (例：フロントエンドの開発サーバーであれば [http://localhost:3000](http://localhost:3000)) 。

        リンクのクリック、フォームの送信、エラーの発生、ビュー間の移動など、普段どおりにページを操作します。設定が有効であれば、拡張機能はページが読み込まれるたびに Browser SDK を自動的に挿入します。
      </Step>

      <Step title="セッションリプレイを表示する" id="view-session-replay">
        ClickHouse オブザーバビリティのサービスで、左サイドバーから **クライアントセッション** を開きます。閲覧を行った時間帯を含む時間範囲を選択します。

        セッションが所要時間とイベント数とともに一覧に表示されます。▶️ ボタンをクリックすると、セッションをリプレイできます。

        **Highlighted** モードと **All Events** モードを切り替えると、タイムラインに表示する詳細度を調整できます。
      </Step>
    </Steps>

## URL フィルタリング {#url-filtering}

    デフォルトでは、監視が有効になっている間、拡張機能はアクセスしたすべてのページにSDKを挿入します。挿入先を特定のサイトに限定するには、**一致するURLにのみ挿入する**をオンにし、パターンを1行に1つずつ (またはカンマ区切りで) 追加します。

    | パターン                       | 一致する対象                         |
    | -------------------------- | ------------------------------ |
    | `http://homedepot.com/*`   | `homedepot.com` の HTTP のみ      |
    | `*://homedepot.com/*`      | `homedepot.com` の HTTP と HTTPS |
    | `*://*.homedepot.com/*`    | `www.homedepot.com` などのサブドメイン  |
    | `https://localhost:3000/*` | ポート3000で動作するローカル開発サーバー         |

    URL パターンを保存したら、タブを再読み込みしてください。

## 挿入の確認 {#verify-injection}

    監視対象のページで DevTools の **Console** タブを開き、ページを再読み込みして、次の出力を確認します:

    ```text
    [HyperDX Extension] Configuration valid, injecting HyperDX
    [HyperDX Extension] Injected via extension scripts
    [HyperDX Extension] HyperDX initialized
    ```

    拡張機能由来のスクリプトが CSP によってブロックされた場合、拡張機能はフォールバックメッセージをログに記録し、インラインインジェクションで再試行します。

## トラブルシューティング {#troubleshooting}

    <Accordion title="ClickHouse オブザーバビリティにセッションが表示されない">
      1. ブラウザのコンソールで、`[HyperDX Extension]` のログメッセージやエラーが出力されていないか確認します
      2. **HyperDXの監視を有効にする** がオンになっていること、および **サービス名** が設定されていることを確認します
      3. **コレクターの URL** と **APIキー** が、サービスの **チーム設定 → Managed Telemetry** に表示されている値と一致していることを確認します
      4. クライアントセッションビューで時間範囲を調整します (例: **Last 15 minutes**)
      5. ブラウザでハードリフレッシュを実行します: `Cmd+Shift+R` (Mac) または `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="chrome-extension://invalid/ のエラー">
      `chrome://extensions` で拡張機能を再読み込みしてから、タブをハードリロードしてください。この問題は、タブを開いたまま拡張機能が更新または再読み込みされた場合に発生します。
    </Accordion>

    <Accordion title="サイトへの挿入なし">
      1. 監視が有効になっていて、サービス名が設定済みであることを確認してください
      2. **一致するURLにのみ挿入する**がオンになっている場合は、現在のページのURLがいずれかのパターンに一致していることを確認してください
      3. 一部のサイトでは、CSP によって拡張機能由来のスクリプト挿入とインラインスクリプト挿入の両方がブロックされます。そのようなページでは挿入できない場合があります
    </Accordion>

    <Accordion title="HyperDX: コンソールに apiKey がありません">
      **チーム設定 → Managed Telemetry** で確認できるAPIキーを入力して設定を保存し、監視対象のページを再読み込みしてください。完全マネージド型のインジェストには、このキーが必要です。
    </Accordion>

## プライバシー {#privacy}

    この拡張機能は、アクセスしたページにオブザーバビリティ用のコードを挿入します。デバッグが許可されているサイトでのみ使用してください。APIキーは他者と共有したり、バージョン管理システムにコミットしたりしないでください。

## 概要 {#overview-self-configured}

    [HyperDX Chrome拡張機能](https://github.com/kyreddie/hyperdx-chrome-extension) は、訪問したページに [@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) SDK を注入します。サイトのコードベースを変更せずに、セッションリプレイ、RUM、またはトレース伝播をデバッグしたい場合に便利です。例えば、third-party のアプリケーション、本番環境のビルド、厳格な Content Security Policy (CSP) が設定されたローカル開発サーバーなどが該当します。

    自身で管理するデモアプリケーションをインストルメントする[セッションリプレイのデモ](/ja/clickstack/observability/example-datasets/session-replay)とは異なり、この方法では Chrome で開いたサポート対象のページをインストルメントします。ただし、一部のページではスクリプトの挿入が制限されています。セッションデータは、一般ユーザーとしてサイトを操作することで生成されます。

    セッションリプレイの概要とその仕組みについては、[セッションリプレイ](/ja/clickstack/observability/features/session-replay)の機能ページを参照してください。

    * Google Chrome または Chromium ベースのブラウザ (Edge、Brave など)

    * ブラウザから接続可能な collector の OTLP HTTP エンドポイントと、認証トークン (設定済みの場合) 。

        | **Collector URL**                | collector の OTLP HTTP エンドポイント         | 拡張機能のデフォルト URL を置き換えます。`http://localhost:4318` は collector が自分のマシン上にある場合にのみ使用します |
        | **Environment**                  | `development`                         | 任意。`deployment.environment` リソース属性を設定します                                         |

    </Accordion>

    <Accordion title="chrome-extension://invalid/ エラー">
      `chrome://extensions` で拡張機能を再読み込みしてから、タブをハードリロードしてください。この問題は、タブを開いたまま拡張機能が更新または再読み込みされた場合に発生します。
    </Accordion>

    <Accordion title="サイトへの挿入なし">
      1. 監視が有効になっており、サービス名が設定されていることを確認してください
      2. **一致するURLにのみ挿入する** がオンになっている場合は、現在のページのURLがいずれかのパターンに一致していることを確認してください
      3. 一部のサイトでは、CSP によって拡張機能からのスクリプト挿入とインラインスクリプトの挿入がいずれもブロックされます。そのようなページでは挿入できない場合があります
    </Accordion>

    <Accordion title="HyperDX: コンソールに apiKey がありません">
      collector で認証が必要な場合は、**API Key** にトークンを入力して設定を保存し、監視対象のページを再読み込みしてください。挿入メッセージだけで判断せず、ブラウザのネットワークリクエストと collector のログを確認して、エクスポートのエラーが発生していないかを調べてください。
    </Accordion>

## プライバシー {#privacy-self-configured}

    この拡張機能は、閲覧中のページにオブザーバビリティ用のコードを挿入します。デバッグが許可されているサイトでのみ使用してください。APIキーを共有したり、バージョン管理システムにコミットしたりしないでください。
