      **TL;DR**

      [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) をクローンし、`.env` にマネージド OTLP HTTP エンドポイントとAPIキーを設定したうえで、エージェント用のプロンプトを貼り付けます。バックエンドで OpenTelemetry をインポートする必要はありません。エージェントがプロセス起動時に `@hyperdx/node-opentelemetry` を組み込みます。

      所要時間: 約 10 分
    </Note>

    HackerNews Analyzer は、パブリックな ClickHouse デモでホストされている HackerNews データセットに対してクエリを実行する Node.js アプリです。ダッシュボードを操作すると、バックエンドへのリクエストが発生します。アプリのキャッシュにヒットしなかったリクエストは ClickHouse にもクエリを実行し、トレースにアウトバウンドの HTTPS スパンが追加されます。

    このデモでは、バックエンドの自動計装、ClickHouse クエリのスパン、ブラウザのセッションリプレイを 1 つのアプリにまとめています。

## 前提条件 {#prerequisites}

    * [HackerNews Analyzer とその依存関係](https://github.com/ClickHouse/hn-news-analyzer#readme)に対応したバージョンの Node.js および npm。
    * 作成済みの完全マネージド型 ClickHouse Observability サービス。[完全マネージド型の Getting Started ガイド](/ja/clickstack/observability/getting-started)を参照してください。
    * アプリサーバーとブラウザの両方から、マネージドのテレメトリーエンドポイントへのネットワークアクセス。

## リポジトリのクローン {#clone-the-repository}

    [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) をクローンし、依存関係をインストールして、env テンプレートをコピーします。

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    以降の手順で `.env` に値を設定し、その後このディレクトリからインストルメントします。

## アプリケーションをインストルメントする {#instrument-the-application}

    <Steps>
      <Step title="アプリケーションを実行" id="run-the-application">
        クローンした `hn-news-analyzer` ディレクトリでアプリを起動します。ClickHouse データソースはデフォルトでパブリックな読み取り専用のデモクラスターに接続するため、追加の設定なしでそのまま動作します。

        ```bash
        ./run.sh
        ```

        [http://localhost:5001](http://localhost:5001) を開きます。年のセレクター、サマリー統計、アクティビティチャート、上位ユーザーと上位ドメインのテーブル、検索ボックスが表示されます。年を切り替えたり、ストーリーの詳細を表示したりして、自由に操作してみてください。

        </Frame>

        この時点でアプリケーションは動作していますが、まだインストルメントされていません。以下のインストルメンテーション手順を完了すると、アプリがテレメトリーを送信するようになります。
      </Step>

      <Step title="環境を設定する" id="configure-environment">
        ClickHouse Observability のサービスを開き、**チーム設定 → Managed Telemetry** に移動します。**OTLP HTTP エンドポイント** と **APIキー** をコピーします。

        <div className="ch-image-lg">
          <Frame>
            ![チーム設定の Managed Telemetry に、マスクされた OTLP HTTP エンドポイントと APIキーが表示されている画面](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        アプリの `.env` ファイルに次の設定値を記述し、エンドポイントと APIキーのプレースホルダーを実際の値に置き換えます。

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        `OTEL_EXPORTER_OTLP_ENDPOINT` では `https://` プレフィックスを残し、`/v1/logs`、`/v1/traces`、`/v1/metrics` は追記しないでください。シグナルのパスは SDK 側で付加されます。`OTEL_EXPORTER_OTLP_HEADERS` には `Bearer` プレフィックスを付けずに `authorization=<your-api-key>` を設定してください。このキーは、アプリからブラウザー SDK にもそのまま渡されます。

        ブラウザー SDK も同じエンドポイントと APIキーを使用します。`vite.config.ts` によってこれらはブラウザー向けバンドルに埋め込まれるため、サイトの訪問者が内容を確認できます。このデモのテスト専用のサービスを使用し、`.env` はバージョン管理の対象から除外してください。

          <Tab title="手動インストルメンテーション" id="instrument-manually">
            インストルメンテーションは、SDK のインストール、起動コマンドの切り替え、ブラウザー SDK の有効化の 3 つのステップで構成されます。いずれもアプリケーションのビジネスロジックには影響しません。

### Node SDK をインストールする {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### run.sh でラッパーを有効化する {#enable-run-sh-wrapper}

            `run.sh` の末尾には 2 つの `exec` 行があります。通常の `node` 行をコメントアウトし、計装済みの行のコメントを解除します。

            ```diff
             # BEFORE: plain node, no instrumentation:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # AFTER: same source, wrapped by opentelemetry-instrument:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            起動は引き続き `scripts/entrypoint.js` 経由で行ってください。このシムが `require('console')` を呼び出すことで、コンソールキャプチャが `console.log` をラップできるようになります。`opentelemetry-instrument` で `dist/server/index.js` を直接指定すると、トレースは送信されますが、ログは警告なしに破棄されます。

### ブラウザー SDK を有効化する {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            `src/web/telemetry.ts` で、import 文、`HyperDX.init` ブロック、および `recordAction` 内の `HyperDX.addAction` のコメントを解除します。

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` と `__OTLP_AUTH_TOKEN__` はコンパイル時定数で、バックエンドと同じ `OTEL_EXPORTER_OTLP_*` の値をもとに `vite.config.ts` によって注入されます。
          </Tab>

          <Tab title="計装済みブランチを使用する" id="use-the-instrumented-branch">
            インストルメンテーションの手順を省略して計装済みのアプリケーションから始める場合は、[`instrumented` ブランチ](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented)をチェックアウトします。

            ```bash
            git checkout instrumented
            npm install
            ```

            SDK を取り除きたい場合を除き、このブランチでは `./reset.sh` を実行しないでください。
          </Tab>
        </Tabs>
      </Step>

      <Step title="トラフィックを生成してテレメトリーを確認する" id="generate-traffic-and-view-telemetry">
        アプリケーションを再起動して、新しい起動コマンドと新たにビルドしたブラウザ用バンドルを反映させます。

        ```bash
        # Ctrl-C the previous run, then:
        ./run.sh
        ```

        起動時のバナーに、`/v1/traces`、`/v1/metrics`、`/v1/logs` それぞれについて `Health check passed` の行が計3行出力されていることを確認します。Vite が更新されたバンドルを配信するようにブラウザのタブを再読み込みし、年を切り替えたりストーリーをクリックしたりしてトラフィックを発生させます。

        ClickHouse Observability サービスを開きます。

        1. **検索** に移動し、**Logs** ログソースを選択して、時間範囲を **Last 15 minutes** に設定します。`ServiceName` を `hn-analyzer-api` でフィルタすると、バックエンドのログが表示されます。

        <Frame>
          <img src="/images/clickstack/getting-started/observability-hackernews-logs.png" alt="hn-analyzer-api でフィルタされたバックエンドのログを表示している ClickHouse Observability の検索画面" />
        </Frame>

        2. **Traces** ログソースを選択し、`hn-analyzer-api` からのリクエストを開きます。Express ハンドラーのスパン、`sql-clickhouse.clickhouse.com` 宛ての子 HTTP スパン (実際のネットワーク所要時間を含む) 、そして同じトレースに関連付けられた `console.log` レコードが表示されます。

        <Frame>
          <img src="/images/clickstack/getting-started/observability-hackernews-traces.png" alt="ブラウザのリクエスト、バックエンドのスパン、関連付けられたログ、ClickHouse への HTTPリクエストを表示している ClickHouse Observability のトレース" />
        </Frame>

        3. **クライアントセッション** を開き、`hn-analyzer-web` のセッションを選択してから **セッションリプレイ** を開き、ブラウザ上での操作を確認します。

        <Frame>
          <img src="/images/clickstack/getting-started/observability-hackernews-sessions.png" alt="ダッシュボードのリフレッシュと検索イベントを含む HackerNews Analyzer を表示している ClickHouse Observability のセッションリプレイ" />
        </Frame>

        4. **Chart Explorer** を開き、**時系列** と **Metrics** ログソースを選択して、アプリが出力するメトリクスを選びます。`ResourceAttributes.service.name:"hn-analyzer-api"` でフィルタし、テストを実施した期間を含む時間範囲を指定してから **実行** をクリックして、メトリクスデータが存在することを確認します。
      </Step>

    <Note>

    <Note>
      **TL;DR**

      [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) をクローンし、`.env` に OTLP エンドポイントとトークンを記入したら、エージェント用のプロンプトを貼り付けます。バックエンドで OpenTelemetry をインポートする必要はありません。エージェントがプロセス起動時に `@hyperdx/node-opentelemetry` を組み込みます。

      所要時間: 約 10 分

    HackerNews Analyzer は、パブリックな ClickHouse デモでホストされている HackerNews データセットに対してクエリを実行する Node.js アプリです。チャート、テーブル、検索ボックスはすべて実際の ClickHouse クエリで動作しているため、あらゆる操作でトレースが生成されます。その主要なスパンは、バックエンドから ClickHouse への HTTPS 呼び出しです。

    ブラウザのみのアプリをインストルメントして ClickHouse Observability にテレメトリーを送信する [セッションリプレイのデモ](/ja/clickstack/observability/example-datasets/session-replay) とは、目的が異なります。このデモでは、バックエンドの自動計装、ClickHouse クエリのスパン、セッションリプレイを 1 つのアプリでまとめて取得できます。

## 前提条件 {#prerequisites-self-configured}

    * Node 18 以上と npm
    * 既存のセルフマネージド ClickHouse Observability サービスと、稼働中のインジェスト用 collector
    * アプリサーバーとブラウザの両方から接続可能な collector の OTLP HTTP エンドポイント。`http://localhost:4318` は、collector が同じマシン上で稼働している場合にのみ使用してください。
    * collector の `OTLP_AUTH_TOKEN`(設定している場合)。ヘッダーは `Bearer` プレフィックスを付けずに `authorization=<token>` と設定します。collector で認証が不要な場合は、`authorization=` を空のままにします。これらは collector のインジェスト用認証情報であり、ClickHouseデータベースの認証情報ではありません。

    次のステップで `.env` を記入した後、このディレクトリでインストルメントを行います。
