ClickStack Node.js SDK は、アップストリームの OpenTelemetry SDK と自動計装をベースに構築されており、コンソール出力の収集、捕捉されない例外の収集、シャットダウン時のテレメトリーのフラッシュといった機能を追加で提供します。すでに OpenTelemetry を設定済みのアプリケーションでは、既存の SDK をそのまま使い続けながら、[OTLP エクスポートを設定](/ja/clickstack/ingesting-data/opentelemetry)できます。

## インストール {#install}

Node.js は **22.15 以降**を使用してください。アプリケーションに SDK をインストールします。

```shell
npm install @clickhouse/clickstack-node
```

このパッケージは ES モジュールと CommonJS の両方をサポートしています。peer dependency である `@opentelemetry/api` は npm によって自動的にインストールされます。アプリケーションからこのパッケージを直接インポートする場合は、`@opentelemetry/api@~1.9.1` をインストールしてください。バージョン 1.10 はこの SDK のサポート範囲外です。

## 宛先を設定する {#configure-destination}

アプリケーションを起動する前に、環境変数を設定してください。エンドポイントには、`/v1/traces`、`/v1/logs`、`/v1/metrics` を含まないベースの OTLP HTTP エンドポイントを指定します。これらのパスはエクスポーターが自動的に追記します。

collector の OTLP HTTP エンドポイントと、その OTLP レシーバーに設定済みのインジェストキーを使用してください。collector のセットアップについては、[OpenTelemetry によるデータの取り込み](/ja/clickstack/ingesting-data/opentelemetry)を参照してください。

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
export OTEL_SERVICE_NAME='my-node-app'
```

このエンドポイントは、アプリケーションとcollectorが同じホスト上で動作していることを前提としています。collectorを別の場所で実行している場合は、アプリケーションから接続可能なアドレスに置き換えてください。

## アプリケーションを起動する {#start-application}

アプリケーションがインストルメント対象のライブラリをインポートする前に、SDK をプリロードしてください。

```shell
node --import @clickhouse/clickstack-node/register server.js
```

`server.js` は、お使いのアプリケーションのエントリーファイルに置き換えてください。このコマンドは、アプリケーションの起動前に SDK を読み込み、上記で設定した環境変数を使用します。CommonJS と ES モジュールのどちらのアプリケーションにも対応しています。

これで[インジェストを確認](#verify-ingestion)できます。以下の代替手段は、npm スクリプト経由で起動する場合や、コード内で SDK を設定する場合にのみ必要です。

<Accordion title="その他の起動方法">
  `--require` もサポートされています。`NODE_OPTIONS` を使用する場合は、ビルドツールが独自のテレメトリーパイプラインを起動しないよう、適用範囲をアプリケーションのコマンドに限定してください。

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  または、インストルメンテーションモジュールを作成してプリロードする方法もあります。この場合も、エクスポートは前のセクションの環境変数で設定されます。

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  このガードにより、Pino のトランスポート worker などのワーカースレッドが SDK インスタンスを追加で起動することを防げます。

  パッケージの登録用エントリーポイントと独自のインストルメンテーションモジュールは、どちらか一方のみを使用してください。アプリケーション内で 2 つ目の SDK を初期化しないでください。静的な ES モジュールのインポートはモジュール本体より先に実行されるため、同じファイル内で静的インポートより上に `init` の呼び出しを記述しても、初期化の順序は保証されません。
</Accordion>

## インジェストを確認する {#verify-ingestion}

アプリケーションを起動し、計装済みのルートにリクエストを送信して、コンソールメッセージを出力します。ClickStack で直近の時間範囲を選択し、Logs または Traces で `my-node-app` を検索します。メトリクスは、エクスポート間隔が経過するのを待ってから確認してください。

データが表示されない場合は、stderr に出力される SDK の診断情報、エンドポイントと認証、ネットワーク接続を確認してください。インストルメンテーションは、アプリケーションの依存関係より先に読み込まれるようにする必要があります。バンドラーによってインライン展開されたライブラリは自動計装されないため、SDK と計装対象の依存関係はバンドル対象外 (external) にしてください。TypeScript、ES モジュール、フレームワーク、バンドラーの要件については、[SDK の互換性](https://github.com/ClickHouse/clickstack-node#compatibility)を参照してください。

## インストルメンテーションの設定 {#configure-instrumentation}

標準の OpenTelemetry 環境変数は、サンプリング、バッチ処理、エクスポーター、リソース属性に関するものも含め、アップストリームと同じ意味で使用できます。例:

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

コンソール出力はデフォルトで収集されます。HTTP ボディの収集はデフォルトで無効になっています。アプリケーションが扱うデータの性質上、問題がない場合にのみ有効化してください。

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

収集されたボディには、個人情報や認証情報が含まれる可能性があります。SDK によるマスキングはベストエフォートで行われるため、必要に応じて collector 側でのマスキングも引き続き実施してください。ヘッダーの収集、ボディサイズの上限、サニタイズについては、[SDK のプライバシーオプション](https://github.com/ClickHouse/clickstack-node#privacy)を参照してください。

### 初期化オプション {#initialization-options}

インストルメンテーションモジュール内で、以下のオプションを `init` に渡します:

| オプション                        | デフォルト                              | 用途                                                                                                  |
| ---------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------- |
| `endpoint`                   | `http://localhost:4318`            | OTLP HTTP のベース URL。`OTEL_EXPORTER_OTLP_ENDPOINT` によってオーバーライドされます                                    |
| `serviceName`                | `unknown_service:` に実行可能ファイル名を続けた値 | サービス名。`OTEL_SERVICE_NAME` または `OTEL_RESOURCE_ATTRIBUTES` 内の `service.name` によってオーバーライドされます          |
| `environment`                | 未設定                                | `deployment.environment.name` を設定します。`OTEL_RESOURCE_ATTRIBUTES` 内に同じキーがある場合はそちらが優先されます              |
| `apiKey`                     | 未設定                                | 認証ヘッダー値。`OTEL_EXPORTER_OTLP_HEADERS` がすでに空でない場合は、無関係なヘッダーしか含まれていなくても無視されます                          |
| `httpBodyCapture`            | `false`                            | HTTP ボディを収集します。`CLICKSTACK_CAPTURE_HTTP_BODY` によってオーバーライドされます                                       |
| `instrumentations`           | アップストリームの設定のデフォルト                  | `getNodeAutoInstrumentations` 用の設定マップ。明示的に指定した `enabled` の値は、インストルメンテーションの有効化/無効化を制御する環境変数よりも優先されます |
| `additionalInstrumentations` | `[]`                               | デフォルトのバンドルに含まれないライブラリ向けの追加インストルメンテーションインスタンス                                                        |

環境変数が未設定または空の場合は、対応するオプションの値が適用されます。コンソール出力の収集を無効化するには、`OTEL_NODE_DISABLED_INSTRUMENTATIONS` に `console` を含めてください。すべてのデフォルト値については、[Node.js SDK リファレンス](https://github.com/ClickHouse/clickstack-node#quick-start)を参照してください。

プロセスを明示的に終了する場合や AWS Lambda ハンドラーで使用する場合については、[SDK ライフサイクルのドキュメント](https://github.com/ClickHouse/clickstack-node#lifecycle)を参照してください。

## アップストリームの SDK を使用する {#using-upstream-sdk}

アプリケーションですでに OpenTelemetry を設定している場合や、ClickStack SDK のオプションでは対応できないカスタムプロセッサや動作が必要な場合は、アップストリームの `NodeSDK` を使用し、上記の宛先への OTLP エクスポートを設定してください。手順は[アップストリーム SDK のセットアップ例](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly)に従ってください。追加で必要なローダーおよびライフサイクルの設定についても説明されています。同一プロセス内で両方の SDK を初期化しないでください。

## HyperDX Node.js SDK からの移行 {#migration}

`@hyperdx/node-opentelemetry` を `@clickhouse/clickstack-node` に置き換え、新しい登録用エントリーポイントを使用してください。また、`HYPERDX_API_KEY` の代わりに `OTEL_EXPORTER_OTLP_HEADERS` を使用し、上記で説明した宛先に応じた認証フォーマットを指定してください。

新しい SDK では、HyperDX のヘルパーやオプションがすべて引き継がれているわけではありません。ロガーのインテグレーション、エラーハンドラー、カスタムトレース属性、サンプリング設定を置き換える前に、[SDK 移行ガイド](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md)を確認してください。
