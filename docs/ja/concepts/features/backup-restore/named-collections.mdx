SQL で作成された[名前付きコレクション](/ja/concepts/features/configuration/server-config/named-collections)は、
`system.named_collections` テーブルを介してバックアップにエクスポートし、そこから復元できます。
エクスポートされたコレクションには、シークレット値を含むすべての値が含まれます。そのため、コレクションのバックアップと
復元は専用の権限と設定によって制御されます。これらについては本ページで説明します。

サーバー設定ファイルで定義されたコレクションは設定からレンダリングされるため、
バックアップに含まれることはありません。また、バックアップしたコレクションを復元しても、設定で定義された同名の
コレクションが上書きされることはありません。

## コレクションの選択 {#selecting-the-collections}

`BACKUP` クエリは、`system.named_collections`
テーブルを選択対象に含む場合に名前付きコレクションをエクスポートします。

* 明示的な指定: `BACKUP TABLE system.named_collections`。この場合、必要な権限 (後述) が
  必須となります。
* `DATABASE system` または `ALL` 要素による暗黙的な指定。デフォルトでは、このようなバックアップは
  ユーザーがコレクションの値を読み取れる場合にのみコレクションをエクスポートし、読み取れない場合は警告を出力してスキップします。これにより、
  すべてをバックアップする権限はあるものの値の読み取りは許可されていないユーザーでも、
  `BACKUP ALL` を引き続き実行できます。

テーブルのデータを除外する選択 (`BACKUP TABLE system.named_collections EXCEPT DATA FROM
TABLE system.named_collections`、または `EXCEPT DATA FROM TABLES
system.named_collections` を指定したワイルドカード要素) では、バックアップにはテーブル定義のみが保存されます。コレクションは一切
エクスポートされず、後述の権限も一切必要ありません。

## 必要な権限 {#required-privileges}

コレクションをエクスポートすると、その値がバックアップに書き込まれます。そのため、`system.named_collections` から値を読み取る場合と同じ権限が必要です:
[`SHOW NAMED COLLECTIONS`](/ja/reference/statements/grant#named-collection-admin)、
`SHOW NAMED COLLECTIONS SECRETS`、および
[`displaySecretsInShowAndSelect`](/ja/reference/statements/grant#displaysecretsinshowandselect)。
これは名前付きコレクションのストレージが暗号化されている場合も同様です。エントリは暗号文としてコピーされますが、同じキーを持つサーバーであればそれらをコレクションとして復元でき、復元後はその値を読み取れるようになります。

コレクションを復元するには、
[`CREATE NAMED COLLECTION`](/ja/reference/statements/grant#named-collection-admin) 権限が必要です。上記の権限は不要です。オペレーターはバックアップの内容を読み取る権限がなくても復元を実行でき、そうした復元時のエラーやログにコレクション名が出力されることはありません。

`BACKUP ON CLUSTER` および `RESTORE ON CLUSTER` では、クエリが他のホストに送出される前に、開始元ホスト上で開始元ユーザーの権限がチェックされます。ローリングアップグレード中は、この機能に対応したバージョンを実行しているホストであっても、この機能に対応していないバージョンを実行しているイニシエーターから送出されたクエリに対しては、コレクションのエクスポートや復元を一切行いません。そのようなイニシエーターでは権限をチェックできないためです。この場合、エクスポートはスキップされ(明示的に選択されている場合は拒否され)、コレクションのエントリの復元は拒否されます。

## `backup_named_collections` {#backup-named-collections}

型: `Bool`。任意。デフォルトでは未設定です。

`BACKUP` クエリで名前付きコレクションをエクスポートするかどうかを制御します。

* 未設定 (デフォルト): `TABLE system.named_collections` 要素を明示的に指定した場合はコレクションをエクスポートし、
  必要な権限が求められます。`DATABASE system` または `ALL` 要素の場合は、ユーザーが権限を保持しているときにのみコレクションをエクスポートし、
  保持していないときは警告を出力してスキップします。
* `true`: クエリでテーブルが選択されている場合は常にバックアップにコレクションをエクスポートし、権限が不足している場合は
  暗黙的な選択であってもエラーになります。
* `false`: `system.named_collections` テーブルを明示的に指定した場合でも、バックアップにコレクションを一切エクスポートせず、
  権限も一切必要としません。

```sql
-- Fails instead of skipping the collections when the privileges are missing:
BACKUP ALL TO Disk('backups', 'everything') SETTINGS backup_named_collections = 1

-- Never exports the collections:
BACKUP ALL TO Disk('backups', 'no_collections') SETTINGS backup_named_collections = 0
```

## `restore_named_collections` {#restore-named-collections}

型: `Bool`。デフォルト: `true`。

`RESTORE` クエリで、バックアップに含まれる名前付きコレクションを復元するかどうかを指定します。
[`restore_table_data`](/ja/concepts/features/backup-restore/restore-settings) などの関連設定とは異なり、`structure_only` を指定した場合でもデフォルト値は
`true` のままです。これは、コレクションは定義情報であり、エンジンがコレクションを参照するテーブル (例: `ENGINE = URL(collection)`) は、そのコレクションがなければ作成できないためです。

```sql
-- Restores everything except the named collections:
RESTORE ALL FROM Disk('backups', 'everything') SETTINGS restore_named_collections = 0
```

## `create_named_collection` {#create-named-collection}

型: `String`。デフォルト: `'if-not-exists'`。

既に存在する名前付きコレクションを `RESTORE` がどのように扱うかを指定します。

* `'if-not-exists'` (デフォルト) : 既存のコレクションを保持し、バックアップ側のコレクションはスキップされます。
* `'create'`: 既存のコレクションがある場合、復元は失敗します。
* `'replace'`: 既存のコレクションをバックアップ側のコレクションで置換します。サーバー構成で定義されたコレクションは置換できないため、
  復元は失敗します。

```sql
RESTORE TABLE system.named_collections FROM Disk('backups', 'everything')
SETTINGS create_named_collection = 'replace'
```

## 暗号化された名前付きコレクションのストレージ {#encrypted-storage}

[名前付きコレクション用の暗号化ストレージ](/ja/concepts/features/configuration/server-config/named-collections)
(`local_encrypted` または `zookeeper_encrypted`) を使用している場合、エントリはストレージに保持されている
暗号文のままバックアップにコピーされ、その後ろに認証コードが付加されます。そのため、バックアップ内に平文の値が
含まれることは一切なく、エントリが改ざんされていた場合は、復号が行われる前の段階で復元が失敗します。

このようなバックアップを復元するには、名前付きコレクションのストレージが同様に暗号化されており、かつコレクションの
暗号化に使用されたキーを保持しているサーバーが必要です。復元されたエントリは、復元先サーバーのキーで
再暗号化されます。暗号化されたエントリを含むバックアップは、暗号化されていないストレージには復元できません。
そのキーを保持する暗号化ストレージを設定するか、`restore_named_collections = 0` を指定してコレクションの復元をスキップしてください。
