組み込みのWeb SQL UI (ClickHouseの各HTTPポートの[`/play`](/ja/concepts/features/connect-to-clickhouse/protocols/http)パスで配信される`play.html`) では、タブをノートブックに変換できます。ノートブックはセルを順番に並べたもので、各セルには、クエリとその実行結果、またはMarkdown形式のテキストが入ります。Jupyter、Observable、Hex、Deepnoteと同じ形式のドキュメントで、一連のクエリとそれらをつなぐ思考過程を1つのページにまとめるという目的も共通しています。

ノートブックモードはタブごとに設定できます。あるタブをノートブックとして使いながら、別のタブは通常の単一クエリ用編集者のままにしておけます。再読み込み後も、各タブのノートブックは保持されます。

## セルの追加 {#adding-cells}

タブは最初、クエリセルが1つだけの状態で始まり、見た目は通常の編集者とまったく同じです。ヘッダーもセルの装飾もなく、ノートブックであることはわかりません。クエリが結果を返すと、その下に大きな `[+]` ボタンが表示されます。このボタンは結果の妨げにならないよう、あえて控えめに表示されています。クリックすると展開され、追加できる2種類のセルが表示されます。

* **Query** — 新しいクエリセルです。すぐに編集者にフォーカスが移るため、そのまま入力を始められます。
* **Text** — 新しいMarkdownセルです。編集モードで開きます。

2つ目のセルを追加すると、そのタブでノートブックモードが有効になります。

## セルヘッダー {#cell-headers}

セルが2つ以上になると、各セルには `1. Query` や `2. Text` のように、その位置と種類を示すヘッダーが表示されます。クエリセルでは、実行が処理中の間はステータスドットが表示され、失敗した場合は赤いドットが表示されます。完了したセルにはマークは表示されません。結果がすぐ下に表示されるためです。

ヘッダーのアクションは、セルにマウスオーバーするかフォーカスを当てると表示されます。

| アクション     | 意味                                                 |
| --------- | -------------------------------------------------- |
| `▶`       | このセルを実行します (クエリセルのみ)                               |
| `✎`       | このセルを編集します。編集者をこのセルに移すか、テキストセルをソース表示に戻します        |
| `＋`       | このセルの前に新しいセルを挿入します。同じ Query/Text の選択肢がインラインで表示されます |
| `↑` / `↓` | セルを上下に移動します                                        |
| `✕`       | セルを削除します                                           |

共有編集者はクエリセルに配置されるため、タブには常に少なくとも1つのクエリセルが残ります。そのため、最後に残ったクエリセルでは `✕` が無効になります。

## クエリセル {#query-cells}

ページ上のクエリ編集者は常に1つだけです。これは構文ハイライト、自動補完、クエリパラメーターの入力欄を備えたフル機能の編集者です。ノートブックモードでは、編集者はその時点で有効なクエリセルにドッキングされ、フォーカスがある間だけ表示されます。フォーカスが外れるとすぐにそのセルも折りたたまれるため、閲覧中のノートブックには開いたテキストエリアが一切表示されません。折りたたまれたクエリをクリックすると、そのセルに編集者が戻ります(編集者が別のセルにあった場合は、そこから移動します)。クエリパラメーターの入力欄や補完候補など、編集者内でフォーカスが移動しても折りたたまれることはありません。

折りたたまれたクエリセルでは、クエリが単一行で表示されます。構文ハイライトが適用され、連続する空白文字(インデントや改行を含む)は1つのスペースにまとめられ、収まりきらない末尾は右端でフェードアウトします。セル自体には背景がないため、折りたたまれたセルは別の入力ボックスではなく、ページ上のテキストとして読めます。

`Run` ボタン、進捗行、およびコピー/ダウンロードのアクションは、ページヘッダーから移動し、編集中のクエリの下、つまりクエリとその結果の間にドッキングされます。これらが表す実行の結果はこの位置に表示されるため、どのセルをどう実行するかが一目でわかります。これらは編集者に属するため、セルにフォーカスが移ったり外れたりするのに合わせて、編集者とともに表示・非表示が切り替わります。

ノートブックモードでは、結果はよりコンパクトに表示されます。フォントが小さくなり、セルのパディングもそれに合わせて縮小され、テーブルの高さはビューポートの高さの最大4分の1になります。クエリ編集者のサイズ変更とまったく同じように、結果の下端をドラッグすると表示領域を広げたり狭めたりできます。テキストセルの Markdown 編集者にも同じハンドルがあります。テーブル自体が縦横両方向のスクロールコンテナとなるため、細いスクロールバーはテーブル自身の端に表示されます。行数の多い結果や幅の広い結果があっても、ノートブックの残りの部分が下に押し下げられたり、横に広がったりすることはなく、スクロール中も列ヘッダーはテーブルの上端に固定されたままです。ヘッダーがテーブルの最上部に位置するため、カラムの型は、ページ全体をスクロールするテーブルのようにヘッダーの上ではなく、ヘッダーのすぐ下に、最初の行に重なる形で表示されます。

実行方法は従来と変わりません。`Ctrl/Cmd+Enter`(または `Run` ボタン)で、編集者内のクエリ、すなわち有効なセルのクエリが実行されます。1つのタブで同時に実行できるクエリは1つだけです。同じタブの別のセルで実行を開始するか、`Stop` を押すと、前の実行は終了します。

`Logs` ビューと `Metrics` ビュー、および進捗行のリソースメーターは、それらが表す結果を持つセルに属します。各セルは独自の選択状態とメーターを保持し、共有のトグルには有効なセルが生成した内容が表示されます。セルを切り替えると、そのセル独自のログ、メトリクス、メーターが再び表示されます。クエリの実行中、この行は実行中のセルにとどまります。次のクエリを書くために編集者を別のセルに移動しても、リアルタイムの進捗表示が消えることはなく、トグルの対象が別のセルの結果に切り替わることもありません。

カラムの色分け、ピン留めされたカラム、そして[結果の構造](/ja/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/result-shaping)(ソート、フィルタ、ページ)もセルに属します。これらは結果に対して設定されるため、その結果に紐づきます。セルの結果をソートまたはフィルタリングすると、そのセルが再実行されます。編集者が別のセルにあった場合は、先に編集者がそのセルに移動します。`Run all` によって複数のテーブルが生成されたセルでは、それらのテーブル間で1つの設定が共有され、各セルはそれぞれ独自の設定を保持します。共有リンクとブラウザの履歴には有効なセルの設定が含まれ、それ以外のセルの設定はそれぞれのセルとともに保持されます。

## テキストセル {#text-cells}

テキストセルには Markdown を記述します。編集中は、テキスト領域にソースが表示され、マーカーが強調表示されます。見出し、強調、コードスパン、リンク、リストの箇条書き記号、引用は色分けされますが、レンダリングによってマーカーが隠れることはなく、常にソースを直接編集できます。テキスト領域は内容に合わせて広がります。

テキスト領域から離れると (別の場所をクリックするか、`Escape` または `Ctrl/Cmd+Enter` を押すと) 、編集が終了し、レンダリングされた Markdown に置き換わります。レンダリングされたテキストをクリックすると、編集に戻ります。

テキストセルには、編集時も表示時もクエリと同じ等幅フォントが使用されます。そのため、ノートブック全体を統一感のあるドキュメントとして読むことができ、セルをソースとレンダリング結果の間で切り替えてもフォントは変わりません。

見出し、強調、インラインコードとフェンス付きコード、リンクと画像、URL の自動リンク、番号付きリストと箇条書きリスト、引用、水平線、パイプ区切りの表に対応しています。テキストセル内の生の HTML はレンダリングされず、エスケープされます。また、リンクと画像の URL は `http`、`https`、`mailto`、相対参照に制限されます。`[guide](guide.md)` や `![pic](images/pic.png)` のような通常の相対リンクは機能しますが、`javascript:` や `data:` のようなスキーム、およびプロトコル相対 URL の `//host/...` (相対参照ではなく別のオリジンを指します) は、通常のテキストのまま表示されます。

## 永続化 {#persistence}

タブのノートブック全体 (すべてのセルとその内容、および小さな結果スナップショット) は、ワークスペースの他のデータとともに IndexedDB に保存され、再読み込み時に復元されます。保存と復元は、[Web SQL UI](/ja/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql) で説明されているのと同じくベストエフォートで行われ、結果サイズにも同じ制限が適用されます。

URL とブラウザーの履歴は、有効なセルに連動します。`#` フラグメントにはそのセルのクエリが含まれ、戻る・進む操作で、以前表示したセル (およびタブ) 間を移動できます。ノートブックの URL を共有すると、ノートブック全体ではなく、有効なセルのクエリが共有されます。

タブを複製すると、結果を除くノートブック全体が複製されます。

タブバーの保存ボタンでタブを Markdown として保存すると、ノートブックのすべてのセルが順番に書き出されます。各クエリセルはフェンス付きコードブロックとして書き出され、その後にパラメータと結果テーブルが続きます。各テキストセルは、情報文字列に `markdown` を指定したフェンス付きコードブロックとして書き出されます。この形式のドキュメントを読み込むと、すべてのタブと各タブ内のすべてのセルが復元されます。結果は復元されないため、読み込まれたクエリセルは未実行の状態になります。
