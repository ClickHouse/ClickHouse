ドキュメント検索ページは、組み込まれたリファレンスドキュメントをインスタントに検索できる、軽量な自己完結型のウェブUIです。任意の ClickHouse HTTP ポートの `/docs` パスで提供されます。

任意の ClickHouse HTTP ポートの `/docs` にアクセスすると開けます (例: `http://localhost:8123/docs`) 。

## 機能概要 {#what-it-does}

このページは、入力に応じて HTTP 経由で [`system.documentation`](/ja/reference/system-tables/documentation) テーブルにクエリを発行し、選択したエンティティの Markdown をレンダリングします。`system.documentation` を参照するため、このテーブルが公開するすべてのエンティティ (関数、集約関数、テーブル関数、テーブルエンジン、データベースエンジン、データ型、設定、フォーマット、圧縮コーデック、プロファイルイベント、メトリクス、システムテーブル自体など) を網羅しており、表示内容は常に実行中のサーバーに埋め込まれたドキュメントと一致します。

検索ボックスに入力すると、一致した項目が種類ごとに色分けされたリストに表示され、項目を選択するとそのドキュメントがレンダリングされます。レンダリングには次の機能が含まれます。

* エンティティのタイトル横に表示される鉛筆アイコンのリンク。`system.documentation` の `source` カラムをもとに、GitHub 上のソースファイルを開きます。
* [`/play`](/ja/concepts/features/connect-to-clickhouse/protocols/http) UI と同じ埋め込みレキサー (`Lexer.wasm`) による、コードブロックの ClickHouse SQL 構文ハイライト。
* [KaTeX](https://katex.org/) による TeX 数式の表示 (例：`corr` ページの数式) 。
* `:::note`/`:::tip`/… の注記ブロック、共有用リンク付きの見出しアンカー、およびコードブロックにマウスを重ねると表示される「Copy」ボタン。
* 相対リンクの解決。リンク先がドキュメント化された別のエンティティとして存在する場合はアプリ内リンクに、存在しない場合は `https://clickhouse.com/docs` へのリンクになります。「Related」および「Alias of」の参照もアプリ内リンクになります。

現在の検索語、開いているエンティティ、セクションは URL フラグメントに反映されるため、特定のページやセクションへ直接リンクでき、ブラウザの戻る/進む操作でも状態が復元されます。ライト/ダークテーマの切り替え機能 (自動検出対応) は `/play` と共通です。

## 接続 {#connecting}

ヘッダーには、`/play` とまったく同じく `URL`、`user`、`password` の入力欄があります。ページが ClickHouse から配信されている場合、`URL` のデフォルト値は現在のオリジンになります。ページをローカルファイルとして開いた場合は `http://localhost:8123/` がデフォルトとなるため、ローカルで開いたページからリモートサーバーに接続することもできます。クロスリンク用の名前キャッシュは、接続が変更されると自動的に再構築されます。

## アセット {#assets}

ページを HTTP 経由で配信する場合、Markdown レンダラー ([Marked](https://marked.js.org/)) 、数式レンダラー (KaTeX とそのフォント) 、SQL レキサーを含むすべてのアセットは、ClickHouse バイナリ自体から配信されます。ClickHouse の HTTP オリジンでは third-party の CDN を一切読み込まないため、ページは自己完結型でオフラインでも動作し、ページが扱う認証情報と同じ環境で third-party のネットワークコードが実行されることもありません。

## セキュリティ上の考慮事項 {#security}

このページは、ヘッダーに入力された認証情報を使用して ClickHouse の HTTP エンドポイントにクエリを発行します。そのため、HTTP プロトコルに関する注意事項がここでも同様に当てはまります。

* 信頼できない環境では、認証情報を保護するため、`/docs` は必ず HTTPS 経由で提供してください。
* HTTP プロトコルへのアクセスを制限する場合と同様に、ネットワークレベル(ファイアウォール、リバースプロキシ、または `listen_host` 設定)でアクセスを制限してください。

`system.documentation` にはサーバーに埋め込まれた静的なリファレンスドキュメントのみが含まれているため、このページを通じてテーブル内のデータが公開されることはありません。
