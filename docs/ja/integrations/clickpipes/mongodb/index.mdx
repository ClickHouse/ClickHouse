ClickPipes を使用すると、MongoDB データベースから ClickHouse Cloud にデータを取り込めます。ソースとなる MongoDB データベースは、オンプレミスでホストすることも、MongoDB Atlas などのサービスを使ってクラウドでホストすることもできます。

MongoDB ClickPipes は、ClickPipes UI を使用して手動でデプロイおよび管理できるほか、[OpenAPI](/ja/integrations/clickpipes/programmatic-access/openapi) や [Terraform](/ja/integrations/clickpipes/programmatic-access/terraform) を使用してプログラムでデプロイおよび管理することもできます。

## 前提条件 {#prerequisites}

開始するには、まず MongoDB データベースがレプリケーション用に正しく構成されていることを確認する必要があります。構成手順は MongoDB のデプロイ方法によって異なるため、以下の該当するガイドに従ってください。

1. [MongoDB Atlas](/ja/integrations/clickpipes/mongodb/source/atlas)

2. [Generic MongoDB](/ja/integrations/clickpipes/mongodb/source/generic)

3. [Amazon DocumentDB](/ja/integrations/clickpipes/mongodb/source/documentdb)

ソースの MongoDB データベースの設定が完了したら、ClickPipe の作成に進むことができます。

#### 詳細設定を行う {#advanced-settings}

必要に応じて詳細設定を行えます。各設定の概要は以下のとおりです。

* **Sync interval**: ClickPipes が変更を確認するためにソースデータベースをポーリングする間隔です。これは宛先の ClickHouse サービスのコストに影響するため、コストを重視する場合は高めの値 (`3600` 超) に設定することを推奨します。
* **Pull batch size**: 1 回のバッチで取得する行数です。これはベストエフォートの設定であり、常に適用されるとは限りません。
* **Snapshot number of tables in parallel**: 初回スナップショット時に並列に取得するテーブル数です。テーブル数が多い場合に、並列に取得するテーブル数を制御するのに役立ちます。

### テーブルを設定する {#configure-the-tables}

5. ここでは、ClickPipe の移行先データベースを選択できます。既存のデータベースを選択することも、新しいデータベースを作成することもできます。

   <div className="ch-image-lg">
     <Frame>
       ![移行先データベースを選択](/images/integrations/data-ingestion/clickpipes/mongodb/select-destination-db.webp)
     </Frame>
   </div>

6. ソースの MongoDB データベースから複製するテーブルを選択できます。テーブルの選択時に、宛先の ClickHouse データベースでのテーブル名を変更することもできます。

コレクションは次の 2 つのモードで複製できます。

* **デフォルトインジェスト**: ドキュメントは JSON型としてそのまま ClickHouse に取り込まれます。この場合、書き込み先テーブルには `id` 用の専用カラムと、ドキュメント全体を格納する `doc` カラムが作成されます。
* **構造化インジェスト**: ドキュメントは、コレクション共通のスキーマに従ってテーブルの行として取り込まれます。このスキーマは、パイプ作成時にサンプルから推論されます。このモードは、コレクションの **Map document to columns** をオンにすると有効になります。

構造化インジェストが有効な場合、**Column settings** セクションには、サンプル内で検出されたフィールドと、推論された ClickHouse の型が一覧表示されます。カラムとして複製するフィールドを選択できます。なお、`_id` ドキュメントキーは常に `String` 型で含まれます。

<div className="ch-image-md">
  <Frame>
    ![コレクションの構造化インジェスト設定](/images/integrations/data-ingestion/clickpipes/mongodb/mongodb-structured-ingestion.webp)
  </Frame>
</div>

MongoDB のコレクションはポリモーフィック (同じコレクション内のドキュメントが異なるスキーマを持ち得る) であるため、構造化インジェストでは外れ値となるレコードを処理する必要があります。

* **欠損フィールド:** すべての構造化カラムは `Nullable` として取り込まれるため、ドキュメントにフィールドが存在しない場合、対応するカラムの値は `NULL` になります。

* **余分なフィールド:** 推論されたスキーマに含まれないフィールドは、`_peerdb_malformed_data` カラムに JSON として格納され、フィールドごとに 1 つのキーが作成されます。各キーには `"unexpected_field": true` が含まれ、元の値は `value` に格納されます。

  ```json
  {
    "rating": {
      "unexpected_field": true,
      "value": 4.5
    }
  }
  ```

  このデータは簡単にクエリ・分析できます。たとえば、テーブル内で検出された予期しないフィールドを一覧表示するには、次のようにします。

  ```sql
  SELECT DISTINCT arrayJoin(JSONAllPaths(_peerdb_malformed_data)) AS malformed
  FROM movies
  WHERE malformed LIKE '%.unexpected_field';
  ```

  📝 注記: 余分なフィールドの値を `_peerdb_malformed_data` カラムに含めたくない場合は、コレクションの **Hide unexpected values** オプションを有効にしてください。

* **フィールドの型の不一致:** カラムの型と一致しない値も `_peerdb_malformed_data` カラムに格納され、フィールドごとに 1 つのキーが作成されます。各キーには `"type_mismatch": true` が含まれ、元の値は `value` に格納されます。対応するカラムは `NULL` に設定されます。

  ```json
  {
    "year": {
      "type_mismatch": true,
      "value": "two thousand nineteen"
    }
  }
  ```

  値が想定される型と一致したかどうかにかかわらずフィールドを読み取るには、カラムとそのフォールバック値を組み合わせます。

  ```sql
  SELECT name, coalesce(year, _peerdb_malformed_data.year.value)
  FROM movies;
  ```

📝 注記: `_peerdb_malformed_data` に含まれるフィールドは、JSON カラムによるインジェストにフォールバックした外れ値とみなせます。

構造化インジェストではテーブル作成前にスキーマを推論するため、これを有効にすると、構造化カラムに基づいてカスタムの partition-by 式やカスタムの sorting key を定義できます。
すべての構造化カラムは `Nullable` として取り込まれます。パーティションキーの式を記述する場合や、sorting key でこれらのカラムを使用する場合は、この点に注意してください。このような場合、書き込み先テーブルは `allow_nullable_key` 設定を有効にして作成されます。

📝 どちらのインジェストモードでも、削除イベントで削除された値を宛先の ClickHouse に記録したい場合は、**Persist deleted documents** オプションをオンにできます。なお、これにはソースコレクションで `changeStreamPreAndPostImage` が有効になっている必要があります。

## 注意事項 {#caveats}

このコネクタを使用する際は、以下の点にご注意ください。

* MongoDB バージョン 5.1.0 以降が必要です。
* CDC (変更データキャプチャ) には MongoDB のネイティブな変更ストリーム API を使用しており、リアルタイムの変更の取得には MongoDB の oplog を利用します。
* MongoDB のドキュメントは、デフォルトで JSON type として ClickHouse にレプリケートされます。これにより、スキーマを柔軟に管理できるほか、ClickHouse の豊富な JSON 演算子をクエリや分析に活用できます。JSON データのクエリについて詳しくは、[こちら](/ja/reference/data-types/newjson)をご覧ください。
