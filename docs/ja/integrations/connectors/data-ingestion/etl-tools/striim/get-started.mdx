このガイドでは、サインアップの手順と、ソースデータベースから ClickHouseインスタンスへのデータの複製を開始する方法を説明します。完全な例については、[SQL Server サンプルパイプライン](/ja/integrations/connectors/data-ingestion/etl-tools/striim/sample-pipeline)を参照してください。

## 前提条件 {#prerequisites}

| **必要なもの**  | **詳細**                                                                                                                                                                                                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ClickHouse | 稼働中の ClickHouse Cloud サービスまたはセルフマネージドのデプロイメントと、データベースおよびユーザーを作成できる管理者アクセス権。`CoalescingMergeTree` を使用するには ClickHouseサーバー 25.6 以降が必要です。                                                                                                                                                               |
| ソース        | CDC (変更データキャプチャ) と必要なリーダーのアクセス許可を設定するための、ソースデータシステムへの管理者アクセス権。                                                                                                                                                                                                                                      |
| ネットワーク経路   | AWS 上の Striim からソースおよび ClickHouse への承認済みのネットワーク経路。必要に応じて、Striim for ClickHouse では IP 許可リスト、AWS PrivateLink、または SSH トンネリングによるプライベート接続を利用できます。詳細については、Striim のドキュメント「[Security and Networking](https://www.striim.com/docs/striimforclickhouse/en/security-and-networking-for-striim.html)」を参照してください。 |

## Striim アカウントを作成する {#create-your-striim-account}

Striim で直接サインアップするか、AWS Marketplace 経由でサインアップします。14 日間の無料試用は、アカウントを有効化した時点で開始されます。無料試用にクレジットカードは必要ありません。

1. [Striim for ClickHouse のサインアップフォーム](https://go2.striim.com/trial-clickhouse)を開き、必要事項を入力して **Sign up** を選択します。
2. アカウント有効化メールを開いてアカウントを有効化し、Striim のクラウドコンソールにサインインします。

組織で AWS Marketplace を通じて購入する場合は、[Subscribe and sign up](https://www.striim.com/docs/striimforclickhouse/en/subscribe-and-sign-up.html#id211623) の手順に従ってください。AWS Marketplace で Striim for ClickHouse をサブスクライブした後、Striim アカウントのセットアップを完了します。

## サービスを作成する {#create-your-service}

サービスとは、ClickHouse にデータを書き込むパイプラインの構築・実行・監視を行う、AWS 上のマネージドな Striim 環境です。1 つのアカウントで同時に有効にできる Striim for ClickHouse サービスは 1 つだけです。

1. Striim for ClickHouse に初めてサインインしたときは、**Get Started** を選択します。または、サイドバーで **Marketplace** を選択し、**Striim for ClickHouse** の下にある **Create** を選択します。
2. 次の項目を設定します。
   * **Service Name:** ワークロードまたは環境を識別するための名前。
   * **AWS Region:** サービスを実行するリージョン。レイテンシと cross-region 転送料金を抑えるため、可能であれば ClickHouse と同じリージョンを選択してください。利用できない場合は、最も近いリージョンを選択します。
3. 名前とリージョンは作成後に変更できません。どちらかを変更するには、サービスを削除して新たに作成する必要があります。
4. **Create a service** を選択します。プロビジョニングには数分かかる場合があります。新しいサービスには、デフォルトで **Premium** プランが適用されます。プランは **Billing** ページで変更できます。
5. サービスの準備ができたら、起動方法を選択します。
   * **Start building with Striim Clara AI:** Striim が管理する Clara AI を使用して起動します。APIキーは不要です。
   * **Review your service settings before launch:** 起動前に、独自のAIプロバイダーの設定、ユーザー管理、SSH または AWS PrivateLink のセットアップを行います。

2 回目以降のサインインでは、**Services** の一覧からサービスを開き、パイプラインの構築や設定の管理を行います。

## ClickHouse の移行先を準備する {#prepare-your-clickhouse-target}

<Steps>
  <Step title="接続情報を取得する" id="get-connection-details">
    ClickHouse Cloud では、対象のサービスを選択して **Connect** をクリックし、**HTTPS** を選ぶと、ホストとポート (8443) が表示されます。自己管理型 ClickHouse の場合は、管理者にホストとポートを確認してください。
  </Step>

  <Step title="移行先データベースを選択または作成する" id="create-target-database">
    Striim は移行先データベースを作成しません。データベースが存在しない場合、アプリケーションは起動時に停止します。既存のデータベースを使用するか、新たに作成してください。

    ```sql
    CREATE DATABASE IF NOT EXISTS <your_database>;
    ```
  </Step>

  <Step title="Striim 専用のユーザーを作成する" id="create-target-user">
    デフォルトの管理ユーザーではなく、専用のユーザーを使用してください。

    ```sql
    CREATE USER <user> IDENTIFIED BY '<password>';
    ```

    自己管理型 ClickHouse では、SSL X.509 認証を設定することもできます。
  </Step>

  <Step title="必要な権限を付与する" id="grant-target-privileges">
    [Striim のドキュメント](https://www.striim.com/docs/striimforclickhouse/en/initial-setup-to-write-to-clickhouse.html)に記載されている、以下の権限をユーザーに付与します。

    ```sql
    GRANT CREATE TABLE ON <your_database>.* TO <user>;
    GRANT ALTER TABLE ON <your_database>.* TO <user>;
    GRANT DROP TABLE ON <your_database>.* TO <user>;
    GRANT TRUNCATE ON <your_database>.* TO <user>;
    GRANT CREATE DATABASE ON *.* TO <user>;
    GRANT SHOW TABLES ON *.* TO <user>;
    GRANT SHOW DATABASES ON *.* TO <user>;
    GRANT SELECT ON information_schema.* TO <user>;
    GRANT SELECT ON system.tables TO <user>;
    GRANT SELECT ON system.columns TO <user>;
    GRANT SELECT ON system.parts TO <user>;
    GRANT SELECT, INSERT, UPDATE, DELETE ON <your_database>.* TO <user>;
    ```
  </Step>
</Steps>

### 推奨される ClickHouse 構成 {#recommended-clickhouse-configuration}

| 設定         | **ClickHouse Cloud**                                              | **セルフマネージド**                                               |
| ---------- | ----------------------------------------------------------------- | ---------------------------------------------------------- |
| ポート        | 8443 (デフォルトで開放済み。ClickHouse Cloud が管理)                            | 必要に応じて開放: 8123 (HTTP)、9000 (ネイティブ)、8443 (HTTPS)、9440 (TLS) |
| 暗号化        | 常に TLS                                                            | TLS は各自で設定し、接続プロファイルの `EnableSSL` プロパティで有効化                |
| データベースエンジン | `Shared`                                                          | `Atomic` (デフォルト)                                           |
| 認証         | ユーザー名とパスワード                                                       | ユーザー名とパスワード、または SSL X.509 (相互TLS)                          |
| プライベート接続   | AWS PrivateLink (ClickHouse Cloud の Scale プランおよび Enterpriseプランのみ) | SSH トンネルまたは IP 許可リスト                                       |

## 接続プロファイルを作成する {#create-a-connection-profile}

パイプラインから名前で参照できる ClickHouse 接続プロファイルを作成します。接続プロファイルウィザードで、次の項目を設定します。

| **プロパティ**                            | **値**                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| 接続 URL                               | 前のセクションで確認したホストとポートを使用した `jdbc:clickhouse://<host>:<port>` (ClickHouse Cloud の場合はポート 8443)  |
| 認証タイプ                                | パスワード (デフォルト) または SSL X.509                                                                 |
| ユーザー名 / パスワード                        | 前のステップで ClickHouse の移行先を準備する際に作成した、Striim for ClickHouse 専用ユーザーの情報                          |
| クライアント SSL 証明書、クライアント SSL 秘密鍵、CA 証明書 | SSL X.509 の場合のみ必須です。秘密鍵は PKCS#8 PEM 形式である必要があります。                                           |

認証情報や証明書をローテーションするには、**Connection Profiles** を開き、プロファイルを編集して変更を保存します。

AWS PrivateLink を使用する場合は、ClickHouse Cloud から提供された接続 URL をそのまま使用してください。Striim サービスからホスト名がプライベート エンドポイントに名前解決されるよう、Route 53 のプライベートホストゾーンを設定します。詳細は [Initial setup to write to ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/initial-setup-to-write-to-clickhouse.html) を参照してください。

## ソースを準備する {#prepare-your-source}

セットアップ手順はソースの種類ごとに異なります。Striim for ClickHouse ドキュメントの [Sources](https://www.striim.com/docs/striimforclickhouse/en/sources.html) で該当するソースを探し、その設定に関するトピックの手順に従ってください。CDC (変更データキャプチャ) に対応したソースでは、ソース側で変更キャプチャを有効化し、そのソースのページに記載されている権限を付与した Striim 専用のユーザーを作成する必要がある場合があります。先に進む前に、以下を控えておいてください。

* ホスト、ポート、および Striim ユーザーの認証情報。
* 複製するスキーマとテーブル。可能であれば、スキーマ全体ではなく特定のテーブルを選択してください。
* Striim が AWS からソースに到達できること (ファイアウォール、VPC、PrivateLink、SSH、または IP 許可リスト) 。
* ご利用のプラン：Oracle、SQL Server、Snowflake、Salesforce の CDC には Premium プランが必要です。

## パイプラインの構築と開始 {#build-and-start-a-pipeline}

パイプラインは、次のいずれかの方法で作成できます。

* **Striim Clara AI:** **Ask Clara** を選択し、作成したいパイプラインを説明します。例: 「&lt;schema.table&gt; を対象に、&lt;source&gt; から ClickHouse へのパイプラインを構築してください。」Clara が読み取り戦略と接続情報の入力を求め、TQL の実行計画を生成します。実行計画を確認して **Accept TQL** を選択し、続いて **Deploy and Start this App** を選択します。詳細は [Build your first application](https://www.striim.com/docs/striimforclickhouse/en/build-your-first-application.html) を参照してください。
* **自動パイプラインウィザード:** 相互に関連付けられた 2 つのアプリケーション (初期ロード用と CDC 用) を作成します。初期ロードが完了すると、Striim が CDC アプリケーションを自動的に開始します。[以下の手順を参照してください](#using-the-automated-pipeline-wizard)。
* **Flow Designer:** アプリケーションを視覚的に作成・編集し、データが ClickHouse に到達する前に変換処理を追加できます。また、アプリケーションの TQL をエクスポートして編集し、更新した設定をインポートすることもできます。

### 自動パイプラインウィザードの使用 {#using-the-automated-pipeline-wizard}

1. **Apps &gt; Create an App** を選択し、ソースを検索して選択します。
2. **Get Started** を選択し、ソースで利用可能な場合は自動パイプライン (初期ロード + CDC (変更データキャプチャ) ) を選択します。
3. パイプライン名を入力し、ネームスペースを選択して **Next** を選択します。
4. ソース接続のプロパティを入力します。各設定項目の横にはインラインヘルプが表示されます。Striim が接続を検証するため、エラーが発生した場合は、すべて解消してから次に進んでください。
5. システムスキーマ以外で、複製するスキーマを選択し、**Next** を選択します。
6. 各スキーマ内のテーブルを選択し、**Next** を選択します。
7. ClickHouse 接続プロファイルと **テーブルエンジン** を選択します。エンジンの動作については、[ClickHouse へのデータの格納方法](#how-data-lands-in-clickhouse) を参照してください。
8. テーブルのマッピングを確認し、必要に応じて編集してから **Save &amp; Start** を選択します。

Striim はまず初期ロードを実行します。初期ロードが完了すると、Striim は初期ロード用アプリケーションを休止し、関連付けられた CDC アプリケーションを自動的に開始します。

初期ロード中は、ソーステーブルに対して DDL 文を実行しないでください。初期ロードの開始時点から CDC アプリケーションが追いつくまで、ソース側の変更ログまたはストリームを保持しておいてください。パイプラインが停止した場合は、再開する前にエラー内容と提示される修正アクションを確認してください。

## ClickHouse でデータを確認する {#verify-data-in-clickhouse}

1. Striim の監視ビューで、イベントの読み取りと書き込みが行われていることを確認します。Clara に現在の遅延を問い合わせることもできます。

2. ClickHouse で、Striim が作成したテーブルを確認します。

   ```sql
   SHOW CREATE TABLE <your_database>.<your_table>;
   ```

3. ソースと行数を比較します。`ReplacingMergeTree` テーブルの場合は、次のセクションに示すクエリを使用してください。

4. ソース側で小さな変更 (テスト用の行に対する挿入、更新、削除) を加え、その変更が ClickHouse に反映されることを確認します。

## ClickHouse へのデータの格納方法 {#how-data-lands-in-clickhouse}

ClickHouse の移行先を設定する際に、**テーブルエンジン** を選択します。ClickHouse Writer のデフォルトは **`MergeTree`** です。選択したエンジンによって、変更の適用方法と、Striim がターゲットテーブルを作成できるかどうかが決まります。

| **テーブルエンジン**                                      | **動作**                                                                      | **最適な用途**                                                            |
| ------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `ReplacingMergeTree`                              | 更新と削除は、バージョンとソフトデリートフラグを持つ新しい行として書き込まれ、バックグラウンドマージまたは `FINAL` によって重複排除されます。 | 更新時に行全体のイメージを送信する CDC ソース。最もシンプルでスループットが最も高い CDC パターンであり、再適用しても安全です。 |
| `MergeTree`                                       | デフォルトでは追記のみです。Mode = `MERGE` の場合、更新と削除がテーブルに適用されます (軽量削除またはミューテーションによる削除)。  | 初期ロード、ログやイベント、または行を物理的に削除し、追加のカラムを設けたくない場合の CDC。                     |
| `CollapsingMergeTree`                             | sign カラムを書き込みます。+1 は現在の状態、-1 は取り消しを表します。                                    | 変更前と変更後の両方のイメージを送信する CDC ソース。復旧後に再適用すると安全ではありません。                    |
| `CoalescingMergeTree`                             | 行の部分更新を行います。`NULL` は「変更しない」ことを意味します。サーバー 25.6 以降と、`Nullable` の非キーカラムが必要です。  | 部分的な行を送信する CDC ソース。                                                  |
| `SummingMergeTree`                                | 挿入のみです。`UPDATE` または `DELETE` を受け取るとアプリケーションが停止します。                          | カウンターなど、追記のみの数値集約。                                                   |
| `AggregatingMergeTree`、`Replicated`、`Distributed` | データの書き込みのみです。デプロイ前にターゲットテーブルを自分で作成しておく必要があります。                              | マテリアライズドビューのバッキングテーブル、クラスター構成やシャーディング構成のセルフマネージドなデプロイメント。            |

スキーマの自動作成とスキーマ進化を利用するには、`MergeTree`、`ReplacingMergeTree`、`CollapsingMergeTree`、`CoalescingMergeTree`、または `SummingMergeTree` を使用してください。`ReplacingMergeTree` の場合、Striim は `__STRIIM_VERSION` カラムと `__STRIIM_ISDELETED` カラムを追加し、`CollapsingMergeTree` の場合は `__STRIIM_SIGN` カラムを追加します。`ReplacingMergeTree` テーブルに対しては `FINAL` を付けてクエリを実行し、ソフトデリートされた行を除外してください。

```sql
SELECT * FROM <your_database>.<your_table> FINAL WHERE __STRIIM_ISDELETED = 0;
```

ソースのデータ型は ClickHouse の型に自動的にマッピングされます。詳細は[サポートされているデータ型](https://www.striim.com/docs/striimforclickhouse/en/clickhouse-writer-programmer-s-reference.html#supported-data-types-787538)を参照してください。

## パイプラインを監視する {#monitor-your-pipeline}

Striim はウェブUIで ClickHouse Writer のメトリクスを公開しています。受け付けたイベント数、ClickHouse で確認応答済みのイベント数、移行先の鮮度、最終書き込みアクティビティ、バッチ数、テーブルごとのマージ時間などを確認できます。システムアラートは自動的に有効になります。メール、Slack、Microsoft Teams で通知するカスタムアラートも追加できます。また、Clara に「What is the current lag on my application? (アプリケーションの現在の遅延はどのくらいですか？) 」のように質問することもできます。

## トラブルシューティング {#troubleshooting}

<Accordion title="起動時に、存在しないデータベース名を示してアプリケーションが停止する">
  Striim は移行先データベースを作成しません。ClickHouse でデータベースを作成してから再起動してください。
</Accordion>

<Accordion title="テーブルまたはカラムが見つからないが、同じスキーマが他の環境では動作する">
  カラム名は常に case-sensitive です。データベース名とテーブル名はサーバーのファイルシステムに従います (一般的な Linux では case-sensitive です) 。ClickHouse で定義されているとおりの大文字・小文字で指定してください。
</Accordion>

<Accordion title="再起動後に CollapsingMergeTree で重複や負の合計値が発生する">
  配信は at-least-once であり、このエンジンには重複排除の仕組みがありません。復旧機能を使用する場合は、`ReplacingMergeTree`、または Mode = `MERGE` を指定した `MergeTree` の使用を推奨します。
</Accordion>

<Accordion title="PrivateLink: Connection timed out">
  VPC エンドポイントのセキュリティグループでポート 443、8443、9440、3306 へのインバウンドが許可されていること、およびアウトバウンドルールで接続が許可されていることを確認してください。
</Accordion>

<Accordion title="PrivateLink: Connection reset by peer">
  ClickHouse Cloud で、AWS エンドポイントの ID をサービスの許可リストに追加してください。
</Accordion>

<Accordion title="心当たりのない例外でアプリケーションが失敗する">
  Clara にエラーの説明と修正案の提示を依頼してください。本番環境に変更を加える前に、その推奨内容を必ず確認してください。
</Accordion>
