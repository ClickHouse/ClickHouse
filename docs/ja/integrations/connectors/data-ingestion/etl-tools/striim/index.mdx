[Striim for ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/introducing-striim-for-clickhouse.html) は、データベース、データウェアハウス、データレイク、SaaS アプリケーションのデータを ClickHouse に取り込むフルマネージドの SaaS です。Oracle、Microsoft SQL Server、Snowflake といったエンタープライズ向けのソースにも対応しています。既存のレコードを読み込んだ後は、CDC (変更データキャプチャ) によって挿入・更新・削除をストリーミングし、AI ワークロード、ダッシュボード、データアプリケーションで利用する ClickHouse のデータを常に最新の状態に保ちます。

Striim for ClickHouse は AWS 上の Striim Cloud でホストされています。セルフサービスでサインアップでき、請求は使用量に応じた月額課金で、年間契約は不要です。striim.com または AWS Marketplace からサインアップして 14 日間の無料試用を開始すれば、自然言語のプロンプト、ウィザード、フローデザイナーのいずれかでパイプラインを構築できます。

## 主な機能 {#key-features}

* **変更データキャプチャと初期ロード:** 既存データをロードした後、挿入・更新・削除を継続的にリアルタイムでレプリケーションするモードに切り替えます。自動化されたパイプラインウィザードを使うと、両フェーズの作成と関連付けを行い、初期ロードからCDC (変更データキャプチャ) レプリケーションへ自動的に移行できます。
* **ClickHouse Writer:** パイプラインごとにテーブルエンジン (`MergeTree`、`ReplacingMergeTree`、`CollapsingMergeTree`、`CoalescingMergeTree` など) を選択できます。Striimは宛先テーブルを作成し、選択したエンジンに応じて更新と削除を処理するほか、sorting keyも設定します。
* **スキーマの処理:** サポート対象のソースでは、ソースに基づいて移行先のスキーマを自動作成します。また、サポート対象のCDCソースでは、一部のDDL変更 (`CREATE TABLE`、`ADD COLUMN`、`ALTER TABLE ... MODIFY COLUMN`、`DROP COLUMN`、`DROP TABLE`、`TRUNCATE TABLE`) を移行先に反映します。
* **転送中のデータ処理:** ソースとClickHouseの間で、データのフィルタ、拡充、変換を行えます。
* **AIによる運用支援:** 対話型AIエージェントのStriim Clara AIは、自然言語による説明からパイプラインを構築し、遅延やスループットを報告するとともに、障害の原因を説明します。本番環境にデプロイする前に、生成された内容を必ず確認してください。
* **プライベート接続:** ソースおよびClickHouseへの接続には、AWS PrivateLink、SSHトンネル、IP許可リストを利用できます。
* **監視とアラート:** パイプライン監視機能が組み込まれており、アラートをメール、Slack、Microsoft Teams、StriimのウェブUIに通知できます。

## ユースケース {#use-cases}

| **ユースケース**    | **Striim for ClickHouse の活用方法**                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| リアルタイム分析      | CDC (変更データキャプチャ) リーダーが ClickHouse テーブルを常に最新の状態に保つため、対話型ダッシュボードには前回のバッチサイクル時点ではなく、数秒前のアクティビティが反映されます。                  |
| AIエージェントと RAG | ベクトル検索や MCPサーバーで使用されるテーブルも含め、ClickHouse テーブルを常に最新の状態に保つため、エージェントは最新の運用データを参照できます。                                     |
| 特徴量ストアとモデル推論  | 不正検知やパーソナライゼーションなど、ほぼリアルタイムでスコアリングを行うモデル向けに、エンティティ単位の特徴量を常に最新の状態に保ちます。                                                |
| データウェアハウジング   | Oracle、SQL Server、Snowflake、Salesforce などのソースから、中間のステージングレイヤーやストリーミングレイヤーを介さずに ClickHouse へ直接データを連携します。               |
| オブザーバビリティ     | データベースやアプリケーションのログをテレメトリーと同じ ClickHouse インスタンスにストリーミングするため、両者を横断してクエリできます。ClickStack や OpenTelemetry によるインジェストを補完します。 |

## 運用上の考慮事項 {#operational-considerations}

* 配信は at-least-once (少なくとも 1 回) 方式です。再起動や復旧の後、書き込み済みのイベントが再度書き込まれる可能性があります。最終的なデータレコードはテーブルエンジンによって異なります ([ClickHouse へのデータの格納方法](/ja/integrations/connectors/data-ingestion/etl-tools/striim/get-started#how-data-lands-in-clickhouse)を参照してください) 。
* スキーマ進化では、カラムのリネームや NULL 許容性の変更はサポートされていません。また、`AggregatingMergeTree`、`Replicated`、`Distributed` の移行先には適用されません。`VersionedCollapsingMergeTree` と `GraphiteMergeTree` はサポートされていません。
* 一部のソースの型は ClickHouse にマッピングできないため、スキーマの自動作成時にスキップされます。例：`SQL Server GEOGRAPHY`、`GEOMETRY`、`HIERARCHYID`、`SQL_VARIANT`、`Oracle BFILE`、`LONG`、`LONG RAW`、`SDO_GEOMETRY`、`UROWID`、`MySQL GEOMETRY`、`SET`。
