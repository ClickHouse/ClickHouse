<Update label="2026年8月31日">
  今週は、台北とマレーシアに新たな AWS リージョンを追加して ClickHouse Cloud のグローバルな対応範囲を拡大し、Private Service Connect の Global Access をサポートするとともに、SAML ユーザーが組織間を移動しやすくしました。

  ### 新しい AWS リージョン：台北とマレーシア {#new-aws-regions-taipei-and-malaysia}

  ClickHouse Cloud が AWS 台北 (`ap-east-2`) および AWS マレーシア (`ap-southeast-5`) で利用可能になりました。どちらも ClickPipes をサポートする Private Region として設定されています。詳細については、[サポート対象リージョンのドキュメント](/ja/cloud/reference/supported-regions)および[Private Region に関する注意事項](/ja/cloud/reference/supported-regions#private-regions)をご覧ください。

  ### ClickPipes：Private Service Connect が Global Access をサポート {#private-service-connect-supports-global-access}

  ClickPipes が、Private Service Connect (PSC) を使用した**クロスリージョン**のプライベート接続で Global Access をサポートするようになりました。有効にすると、ClickPipes はサービスが稼働している GCP リージョンとは異なるリージョンにある PSC エンドポイントに接続できます。これには、ClickHouse Cloud でネイティブにサポートされていないリージョン (*例：* `asia-northeast3` (ソウル)) も含まれます。

  ### SAML 組織間の切り替え {#switch-between-saml-organizations}

  複数の SAML 組織に所属する SAML ユーザーは、組織切り替えツールから直接組織を切り替えられるようになりました。この際、バックグラウンドで再認証が行われます。各組織の URL をブックマークしたり、手動でログアウトして再度ログインしたりする必要はなくなりました。メインの組織をブックマークし、そこから切り替えるだけです。これは SAML 間の切り替えを対象としており、既存の非 SAML 組織の切り替えに変更はありません。
</Update>

<Update label="2026年8月17日">
  今週の更新では、プラットフォームの対応範囲を拡大し、運用の可視性を向上させました。Managed Postgres は一部のデザインパートナー向けに GCP で利用可能になり、ClickStack リソースは公式 Terraform プロバイダーで管理できるようになりました。また、新しい請求通知により、クレジットの期限切れやサービス中断の前に早期通知を受け取れるようになりました。さらに、ClickHouse Agents のトレーシングを改善し、SAML サインインもよりスムーズになりました。

  ### Managed Postgres が GCP で利用可能に {#managed-postgres-now-available-on-gcp}

  [ClickHouse Cloud Managed Postgres](/ja/products/managed-postgres/overview) が、すべてのパブリック GCP リージョンで一部のデザインパートナー向けに利用可能になりました。最初のプライベートリージョンは `us-west1` です。これにより、GCP 上で構築するお客様にも Managed Postgres を提供します。プライベートプレビューは 2026-08 を予定しています。

  ### Terraform で ClickStack リソースを管理 {#manage-clickstack-resources-with-terraform}

  ClickStack のサポートが、公式 [`ClickHouse/clickhouse` Terraform プロバイダー](https://registry.terraform.io/providers/ClickHouse/clickhouse/latest/docs#clickstack-alpha) バージョン 3.25.0 でベータ提供されるようになりました。チームは、標準の `terraform plan` および `terraform apply` ワークフローを使用して、ダッシュボード、アラート、ログソース、保存済み検索、接続、webhook を作成、更新、インポート、削除できます。このインテグレーションは、Managed ClickStack とセルフホストのデプロイメントの両方をサポートします。

  ### クレジットと支払いに関する新しい請求通知 {#new-billing-notifications-for-credits-and-payments}

  請求通知は ClickHouse Cloud Notification Center で管理され、コンソール、メール、Slack を通じて配信されます。前払いまたはトライアルのクレジットがまもなく期限切れになる、または使い切られる場合に加え、クレジットの追加、支払い方法の変更、アカウントが未払い猶予期間に入った際にも事前通知を受け取れます。これにより、サービスが中断される前に、更新、クレジットの追加、支払いに関する問題の解決により多くの時間を確保できます。

  ### ClickHouse Agents から Langfuse セッションのトレースを開く {#open-langfuse-session-traces-from-clickhouse-agents}

  組織管理者は、[ClickHouse Agents](/ja/products/cloud/features/ai-ml/agents/index) のチャットから対応する Langfuse セッションを直接開き、会話全体のトレースを確認できるようになりました。これにより、エージェントの動作を調査し、複数ステップの実行をデバッグしやすくなります。この改善は、新しく作成されたチャットで パブリックベータ として利用可能です。

  ### SAML リダイレクトによる重複アカウントの防止 {#saml-redirects-help-prevent-duplicate-accounts}

  組織で SAML が設定されている状態で、ユーザーが Google または Microsoft を使用してサインインしようとすると、ClickHouse Cloud は正しい SAML サインインフローにリダイレクトするようになりました。これにより、既存のアカウントにアクセスするつもりだったユーザーが、誤って別の組織を作成することを防げます。
</Update>

<Update label="2026年7月13日">
  今週の更新には、通常の HTTPS 経由でのスティッキーなレプリカルーティング、カスタム請求期間開始日、オブジェクトストレージ ClickPipes の新しい初期ロード制御が含まれます。

  <div id="sticky-replica-routing-over-https-private-preview">
    ### HTTPS 経由でのスティッキーなレプリカルーティング (プライベートプレビュー)
  </div>

  通常のサービス URL に `?session_id=` パラメーターを追加することで、特別なホスト名や DNS の変更なしに、標準 HTTPS 経由でクエリを特定のレプリカに固定できるようになりました。これにより、一時テーブルなどのセッションスコープのオブジェクトをクエリ間で利用可能な状態に保ち、繰り返しのクエリでウォーム状態のレプリカローカルキャッシュに到達しやすくなります。Enterprise のすべてのお客様と、ご要望に応じて Scale のお客様を対象に、プライベートプレビューとして順次提供されます。既存のサブドメインベースのルーティングは引き続き機能しますが、最終的にはこの方式に移行します。[レプリカ対応ルーティング](/ja/products/cloud/features/infrastructure/replica-aware-routing)のドキュメントをご覧ください。

  <div id="custom-billing-period-start-dates">
    ### カスタム請求期間開始日
  </div>

  組織の請求日、つまり各請求期間が開始する月内の日付について、たとえば請求書を暦月に合わせるために、変更をリクエストできるようになりました。希望する日付を記載してサポートチケットを作成してください。請求日は UTC で適用され、各請求書には請求日から翌月の同じ日付の直前までの利用量が含まれます。

  <div id="skip-initial-load-for-object-storage-clickpipes">
    ### オブジェクトストレージ ClickPipes の初期ロードをスキップ
  </div>

  オブジェクトストレージ [ClickPipes](/ja/integrations/clickpipes/home) (S3、GCS、Azure Blob Storage) では、パイプの作成時に初期ロードを制御する 2 つの方法が提供されるようになりました。指定したオブジェクトキーまでのファイルを含めてスキップする **Start after** と、既存のファイルを完全にスキップして新しいオブジェクト通知のみを処理する **Skip initial load** です。以前は、新しいパイプは常にパス内のすべてのファイルをバックフィルしていました。この 2 つのオプションは相互排他的であり、特定のパイプに対して永続的です。スキップしたバックフィルを後で実行することはできません。UI、Cloud API、Terraform v3.18.0 以降で利用可能です。
</Update>

  <div id="clickhouse-managed-postgres-public-beta">
    ### ClickHouse Managed Postgres (パブリックベータ)
  </div>

  <div id="horizontal-autoscaling-private-preview">
    ### 水平オートスケーリング (プライベートプレビュー)
  </div>

  水平オートスケーリングは、ClickHouse Cloud クラスター内のレプリカ数を自動的に調整します。需要が急増した際には積極的にスケールアウトし、負荷が低下するにつれて段階的にスケールインするため、変動が大きく高い同時実行性を要するワークロードを抱えるチームは、クラスターのサイズを手動で調整する必要がなくなります。プライベートプレビューでは同時実行クエリ数に基づいてスケーリングを行い、CPU およびメモリのシグナルはパブリックベータでの対応が予定されています。ClickHouse 26.2 以降をご利用の Enterprise および Scale ティアのお客様が対象です。

  注意: 初回GAリリース時点では、水平オートスケーリングと垂直オートスケーリングは相互に排他的です。水平オートスケーリングが有効になるのは、垂直オートスケーリングが無効になっている場合 (つまり、サービスが固定サイズに設定されている場合) に限られます。同様に、垂直オートスケーリングが有効になるのは、レプリカ数が固定されている場合に限られます。この動作は将来のリリースでより柔軟になる予定です。

  <div id="clickstack-mcp-server-open-source">
    ### ClickStack MCPサーバー (オープンソース)
  </div>

  新しいオープンソースの ClickStack MCPサーバーは、ClickStack と ClickHouse 上に構築された構造化されたオブザーバビリティ調査ツールを外部の AI エージェントに提供します。ログ、メトリクス、トレースに対するセマンティックなプリミティブを公開し、ログのパターン分析、トレースの外れ値調査、相関分析、クロスシグナルのデバッグをサポートします。また、ダッシュボード、検索、アラートを永続化しながら、より深い探索のためのネイティブ SQL アクセスも維持します。Claude Code、Cursor、Codex、またはカスタムフレームワークなどのエージェントを接続できます。

  詳細については、[ClickStack MCPサーバーのドキュメント](/ja/clickstack/mcp)および[オブザーバビリティMCPサーバー + AIノートブックのブログ記事](https://clickhouse.com/blog/observability-mcp-server-ai-notebooks#clickstack-mcp-server)を参照してください。

  <div id="executable-user-defined-functions">
    ### 実行可能ユーザー定義関数
  </div>

  {/* vale on */}

  Pythonで関数を記述し、zip圧縮してクラスターにアップロードするだけで、組み込み関数と同様にSQLから呼び出せるようになりました。ClickHouseは長期稼働するサンドボックスプロセスのプールを維持し、クエリ速度で行をパイプ処理します。そのため、アドホッククエリ、join、さらにはinsertのたびに発火するmaterialized viewなど、SQLが使えるあらゆる場所で関数を呼び出せます。モデルコードはデータのすぐそばに置かれ、デプロイはCloud consoleのアップロード画面一つで完結します。

  その機能を示すために、[デモ](https://github.com/ClickHouse/stock-anomaly-udf)を作成しました。StockHouseのリアルタイム株式取引データをもとに、小規模なPyTorchオートエンコーダーをトレーニングし、取引ティックが取り込まれる際に異常スコアを付与します。必要なのはUDF一つとDDLステートメント一つだけで、残りはすべて通常のSQLです。さらに、ネットワークアクセスUDF (プライベートベータ) のプレビューもこっそり盛り込みました。この機能を使うと、UDFからアウトバウンドのHTTPS呼び出しが可能になります。これを活用してニュースやSEC提出書類を取得し、特定の取引が異常に見える理由をClaudeに分類させています。

  詳細については、[アナウンスブログ](https://clickhouse.com/blog/executable-udfs-clickhouse-cloud-beta)または[ドキュメント](/ja/products/cloud/features/sql-console-features/user-defined-functions)をご覧ください。
</Update>

  <div id="python-client-v100">
    ### Python クライアント v1.0.0
  </div>

  ClickHouse 向け Python クライアントである [clickhouse-connect](/ja/integrations/language-clients/python/index) のメジャーバージョンリリースです。主なハイライトは次のとおりです。

  * ClickHouse-specific SQL をより深くサポートする、充実した SQLAlchemy dialect
  * aiohttp 上に構築されたネイティブ async client。streaming を含め、すべての機能を同等にサポート
  * DateTime、DateTime64、固定幅数値の insert、Maps、Decimals、BigDecimals における大幅なパフォーマンス改善
  * 新しい `tz_mode` と `tz_source` パラメータによる timezone 処理の再設計
  * Variant カラムへのネイティブ書き込み
  * オプションの dependencies (numpy、pandas、pyarrow、polars) の lazy import により、最小構成での import を 4 倍高速化
  * Experimental な Python 3.14 free-threading サポート

  **破壊的変更:** Python &lt; 3.9 および Pandas 1.x のサポートを終了しました。timezone に関するその他の破壊的変更については、[リリースノート](https://github.com/ClickHouse/clickhouse-connect/releases) を確認してください。

  <div id="sql-based-charting-and-alerting-in-clickstack">
    ### ClickStack における SQL ベースのチャート作成とアラート
  </div>

  [ClickStack](/ja/clickstack/overview) で、任意の ClickHouse SQL クエリを使ってチャートとアラートを作成できるようになりました。ユーザーはダッシュボードやアラートビルダーで raw SQL を直接記述でき、window functions、CTE、マルチステージクエリ、ClickHouse ネイティブの分析関数を完全にサポートします。SQL アラートでは、アラートの判定ロジック全体をクエリ自体に組み込めるため、異常検知、遅行平均、統計的なスパイク検知が可能になります。すべての ClickStack デプロイメント (Cloud、Private、BYOC、OSS) で利用できます。詳細は [SQL-based visualizations](/ja/clickstack/features/dashboards/sql-visualizations) および [SQL アラート結果の解釈](/ja/clickstack/features/alerts#sql-result-interpretation) を参照してください。

  <div id="postgres-query-insights-private-preview">
    ### Postgres クエリインサイト (プライベートプレビュー)
  </div>

  [ClickHouse Managed Postgres](/ja/products/managed-postgres/overview) (プライベートプレビュー) で、新しい **クエリインサイト** タブが利用できるようになりました。影響度に基づいてすべてのクエリパターンを順位付けし、それぞれが遅い理由を次の 3 つの画面で示します。

  * **概要** — 1 画面で確認できるデータベースの健全性
  * **Patterns** — 実行時間、CPU、エラー、P95 で並べ替え可能なテーブル
  * **Per-pattern flyout** — レイテンシのパーセンタイル、CPU と I/O、キャッシュとディスク、一時スピル、並列ワーカー不足、WAL ボリューム

  オープンソースの Postgres 拡張機能である [pg&#95;stat&#95;ch](https://github.com/ClickHouse/pg_stat_ch) を基盤としています。

<Update label="2026年4月10日">
  <div id="centralized-marketplace-billing">
    ### 一元化されたマーケットプレイス請求
  </div>

  お客様は、単一のクラウド マーケットプレイス サブスクリプション (AWS、Azure、GCP) を通じて、複数の組織にまたがる請求を統合できるようになりました。主な更新内容は次のとおりです。

  * **Marketplace Subscription Sharing:** 組織の請求をクレジットカード請求から、別の組織の既存のマーケットプレイス サブスクリプションに切り替えられるようになり、追加のマーケットプレイス サブスクリプションを設定する必要がなくなりました。統合されるのは PAYG の利用分のみであり、前払いクレジットは含まれません。
  * **Update Marketplace Subscriptions:** 組織のマーケットプレイス サブスクリプションを、別の組織で使用されているものに切り替えられます。
  * **Backup Payment Method:** マーケットプレイス請求を利用している組織では、プライマリのマーケットプレイス サブスクリプションが解約または期限切れになった場合のバックアップとして、クレジットカードを追加できるようになりました。

  詳細は [請求ドキュメント](/ja/products/cloud/reference/billing/managing-payment-methods) をご覧ください。
