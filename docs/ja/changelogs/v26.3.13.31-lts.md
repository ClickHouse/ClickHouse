* [#106045](https://github.com/ClickHouse/ClickHouse/issues/106045) でバックポート: 設定 `show_data_lake_catalogs_in_system_tables` は `show_remote_databases_in_system_tables` にリネームされ、対象範囲も拡張されました。値が 0 (デフォルト) の場合、データレイクのカタログに加えて、`MySQL` および `PostgreSQL` のデータベースも `system.tables`、`system.columns`、`system.completions` に表示されなくなります。古い設定名はエイリアスとして引き続き使用できます。 [#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="new-feature">
  #### 新機能
</div>

* [#104562](https://github.com/ClickHouse/ClickHouse/issues/104562) でバックポート: リフレッシャブルmaterialized view 向けに `SYSTEM PAUSE VIEW [db.]name` および `SYSTEM PAUSE VIEWS` クエリを追加しました。`SYSTEM STOP VIEW` とは異なり、`SYSTEM PAUSE VIEW` は現在実行中の refresh を中断しません。進行中の refresh は完了まで継続され、以降の refresh のみが抑止されます。この状態は `SYSTEM START VIEW` または `SYSTEM START VIEWS` で解除され、これらは stop 状態と pause 状態の両方を一律にクリアするようになりました。[#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="improvement">
  #### 改善

* [#105589](https://github.com/ClickHouse/ClickHouse/issues/105589)でバックポート: APPEND モードの Replicated リフレッシャブルmaterialized view は、リフレッシュ中に ZooKeeper への接続が一時的に失われても、二重にリフレッシュされなくなりました。[#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)) 。

* [#105802](https://github.com/ClickHouse/ClickHouse/issues/105802) でバックポート: `INSERT INTO FUNCTION hdfs(...)` 経由で HDFS に Parquet (および ORC や Arrow などのトレーラーを持つ他のフォーマット) を書き込む際のデータ破損を修正しました。26.1 以降、`WriteBufferFromHDFS` は `finalize()` 時に作業バッファを flush していなかったため、各ファイルの末尾最大 `DBMS_DEFAULT_BUFFER_SIZE` バイトが黙って失われ、Parquet の `PAR1` footer も含まれていました。このようなファイルを読み取ると `Not a Parquet file (wrong magic bytes at the end of file)` が返されました。[#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* [#105668](https://github.com/ClickHouse/ClickHouse/issues/105668) でバックポート: `catalog_type = 'glue'` を持つ `DataLakeCatalog` データベースからの長時間実行される `INSERT ... SELECT` やその他の読み取りが、テーブルメタデータの読み込み時点で取得された STS セッション認証情報の有効期限を過ぎると、`Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. Only integer types are supported by `__bitWrapperFunc`&quot; がスローされる問題を修正しました。この場合、スキップ索引は通常の filter パスにフォールバックするようになりました。 [#105384](https://github.com/ClickHouse/ClickHouse/pull/105384) ([Groene AI](https://github.com/groeneai)).
