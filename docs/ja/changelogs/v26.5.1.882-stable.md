  ### ClickHouse リリース v26.5.1.882-stable (5b96a8d8a5e) FIXME v26.5.1.1-new (a7b13e00eb1) との比較
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `date_time_input_format` と `cast_string_to_date_time_mode` のデフォルトが `basic` から `best_effort` に変更されました。これまで basic 以外の datetime 文字列 (例: `2024 April 4`、`Apr 15, 2020 10:30:00`) をパースできず失敗していたクエリも、デフォルトで成功するようになる場合があります。従来の厳密なパース動作を維持するには、これらの設定を `basic` に設定するか、`compatibility` を使用してください。 [#89334](https://github.com/ClickHouse/ClickHouse/pull/89334) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* この変更は取り消されました。 [#90043](https://github.com/ClickHouse/ClickHouse/pull/90043) ([Raúl Marín](https://github.com/Algunenano)).
* Tuple 要素名 `null` は、Nullable の null map に使われる subcolumn 名と競合し、subcolumn の解決が曖昧になるため、使用できなくなりました。 [#98377](https://github.com/ClickHouse/ClickHouse/pull/98377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 動的ディスクで `from_env`、`from_zk`、`include` を使用できないようにする設定 `dynamic_disk_allow_from_env`、`dynamic_disk_allow_from_zk`、`dynamic_disk_allow_include` が追加されました。以前はデフォルトで許可されていた動作が、デフォルトで禁止されるようになったため、後方互換性を持たない変更です。 [#99138](https://github.com/ClickHouse/ClickHouse/pull/99138) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 廃止された Arrow ベースの Parquet リーダーおよび writer は、今後は使用できません。代わりに native 実装が使用されます。 [#100949](https://github.com/ClickHouse/ClickHouse/pull/100949) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `SHOW CREATE TABLE t` は、同名の永続 table と一時テーブル `t` が存在し、database が指定されていない場合、一時テーブルを優先するようになりました。これは既存の `DESCRIBE TABLE` の動作に合わせたものです。さらに、`DESCRIBE TEMPORARY TABLE` 構文もサポートされました。 [#100966](https://github.com/ClickHouse/ClickHouse/pull/100966) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* HTTP connections による pre-authentication 時の memory usage を制限するため、デフォルトの `http_max_fields` が 1,000,000 から 1,000 に、`http_max_field_name_size` が 128 KB から 4 KB に引き下げられました。あわせて `http_max_request_header_size` と `http_headers_read_timeout` 設定が追加されました。従来のより高い limits に依存しているユーザーは、設定によって元に戻すことができます。 [#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).
* `system.metric_log` に `histograms` の Nested カラムが追加され、登録されているすべての histogram metric の snapshot が各行に記録されるようになりました。さらに、ゼロ値を出力するかどうかを制御する新しい設定 `system_metric_log_show_zero_values_in_histograms` も追加されました。`system.histogram_metric_log` table は非推奨になりました。 [#103770](https://github.com/ClickHouse/ClickHouse/pull/103770) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* window functions `RANK` と `DENSE_RANK` は、SQL 標準に従い、引数を受け付けず `NUMBER_OF_ARGUMENTS_DOESNT_MATCH` を返すようになりました。以前は、`RANK(x) OVER (ORDER BY id)` のようなクエリが、引数を無視したまま暗黙的に受け入れられていましたが、これはユーザーの混乱を招く原因として頻繁に見られました。以前の寛容な動作に戻すには、`allow_rank_dense_rank_arguments = 1` を設定してください。 Closes [#49526](https://github.com/ClickHouse/ClickHouse/issues/49526). [#104324](https://github.com/ClickHouse/ClickHouse/pull/104324) ([Groene AI](https://github.com/groeneai)).
* 明示的な time zone を指定しない `DateTime` または `DateTime64` への `CAST` は、ソース引数の time zone を保持するようになりました (ソースが明示的な time zone を持つ `DateTime`/`DateTime64` の場合) 。これは `toDateTime`/`toDateTime64` 関数の動作に合わせたものです。 Closes [#55072](https://github.com/ClickHouse/ClickHouse/issues/55072). [#104433](https://github.com/ClickHouse/ClickHouse/pull/104433) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* デフォルトの x86 ビルドターゲットを x86-64-v2 (SSE4.2) に戻しました。以前の x86-64-v3 (AVX2) への切り替えをロールバックしました。 [#104971](https://github.com/ClickHouse/ClickHouse/pull/104971) ([Raúl Marín](https://github.com/Algunenano)).
* `kql` table function を削除しました。KQL ダイアレクトでクエリを実行するには、`SET dialect = 'kusto'` を使用してください。 [#105101](https://github.com/ClickHouse/ClickHouse/pull/105101) ([Alexey Milovidov](https://github.com/alexey-milovidov)).





<div id="new-feature">
  #### 新機能
</div>

* `filesystem` table function を追加しました。これにより、ディレクトリ構造をテーブルとして表現し、SQL でファイルのメタデータや内容を問い合わせられます。元の実装は https://github.com/ClickHouse/ClickHouse/pull/42039 の @perst20 によるものです。[#42039](https://github.com/ClickHouse/ClickHouse/issues/42039) を参照してください。[#50208](https://github.com/ClickHouse/ClickHouse/issues/50208) を参照してください。[#53610](https://github.com/ClickHouse/ClickHouse/pull/53610) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* パラメータ kafka&#95;autodetect&#95;client&#95;rack が導入されました。設定すると、クラウド基盤から availability zone を検出し、ゾーン間通信を避けるため `client.rack` の librdkafka パラメータとして渡します。[#81323](https://github.com/ClickHouse/ClickHouse/pull/81323) ([Ilya Golshtein](https://github.com/ilejn)).
* object storage の読み取り操作を追跡するため、`system.blob_storage_log` に `Read` イベントタイプを追加しました。これは新しい設定 `enable_blob_storage_log_for_read_operations` で制御されます。[#96867](https://github.com/ClickHouse/ClickHouse/pull/96867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `bech32Encode` にオプションのエンコーディング種別パラメータ (`'bech32'` / `'bech32m'`) を追加し、`bech32Decode` に非 SegWit アドレスエンコーディング (例: Cosmos SDK、Injective、Osmosis) 向けの raw デコードモードを追加しました。[#98986](https://github.com/ClickHouse/ClickHouse/pull/98986) ([Yash ](https://github.com/Onyx2406)).
* 新しい `system.zookeeper_watches` テーブルにより、ユーザーは clickhouse-server が発行した ZooKeeper のウォッチを確認できるようになりました。[#99277](https://github.com/ClickHouse/ClickHouse/pull/99277) ([Den Kalantaevskii](https://github.com/Diskein)).
* すべてのテーブルをまたいで合計した、distributed queries に関与する分片数をカウントする `Shards` プロファイルイベントを追加しました。[#99470](https://github.com/ClickHouse/ClickHouse/pull/99470) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Nullable なブール式に対する SQL の真理値 predicates、`IS TRUE`、`IS FALSE`、`IS UNKNOWN`、`IS NOT TRUE`、`IS NOT FALSE`、`IS NOT UNKNOWN` をサポートしました。[#99997](https://github.com/ClickHouse/ClickHouse/pull/99997) ([ibrahim karimeddin](https://github.com/ibrahimkarimeddin)).
* WASM UDF を DETERMINISTIC として宣言できるようになり、定数畳み込みの対象にできるようになりました。[#100005](https://github.com/ClickHouse/ClickHouse/pull/100005) ([Vasily Chekalkin](https://github.com/bacek)).
* `parallel_replicas_prefer_local_replica` 設定を追加しました。無効にすると、並列レプリカは負荷分散アルゴリズムのみに基づいて選択されるため、`max_parallel_replicas = 1` の queries でも別のホストに振り向けられるようになります。[#100139](https://github.com/ClickHouse/ClickHouse/pull/100139) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 送信 HTTP connection 上の TCP ソケットバッファサイズを制御するため、`{disk,storage,http}_connections_rcvbuf` と `{disk,storage,http}_connections_sndbuf` の server settings を追加しました。これにより、operator はカーネルの自動調整を上書きし、connection ごとの memory usage に上限を設定できます。[#100478](https://github.com/ClickHouse/ClickHouse/pull/100478) ([Sema Checherinda](https://github.com/CheSema)).
* `CREATE OR REPLACE TABLE` と同じアトミックスワップのセマンティクスで `CREATE OR REPLACE MATERIALIZED VIEW` をサポートしました。inner table、`TO` table、`POPULATE`、`REFRESH`、`ON CLUSTER` で動作します。[#100539](https://github.com/ClickHouse/ClickHouse/pull/100539) ([DQ](https://github.com/il9ue)).
* `arrayMap`、`arrayFilter` などの higher-order functions に、関数名をそのまま渡せるようになりました。たとえば、`arrayMap(negate, [1, 2, 3])` は `arrayMap(x -> negate(x), [1, 2, 3])` と同等になりました。[#101033](https://github.com/ClickHouse/ClickHouse/pull/101033) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* サーバー自身がネイティブプロトコル経由でインライン `INSERT` データを解析できるように、設定 `send_table_structure_on_insert_with_inline_data` とクライアントオプション `--inline-insert-data` を追加しました。これにより、table structure を受け取るための往復を回避でき、多数の小さな insert のパフォーマンスが向上します。[#101034](https://github.com/ClickHouse/ClickHouse/pull/101034) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* SQL クエリのトークン化と syntax highlighting のために、`tokenizeQuery` 関数と `highlightQuery` 関数を追加しました。`tokenizeQuery` は、バイトオフセットとトークン型を含む lexer トークンを返します。`highlightQuery` は、ハイライトカテゴリ (keyword、identifier、function、number、string など) を含む、パーサーベースの syntax highlighting 範囲を返します。[#101054](https://github.com/ClickHouse/ClickHouse/pull/101054) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* RFC 3986 のセマンティクスに従って、`url` table function および `URL` table engine で relative URLs を解決するための設定 `url_base` を追加しました。[#101113](https://github.com/ClickHouse/ClickHouse/pull/101113) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* S3 GET リクエストの connection lifetime と消費バイト数を観測するため、`s3_read_request_duration_microseconds` と `s3_read_request_bytes` のヒストグラムメトリクスを追加しました。これらは `system.histogram_metrics` と Prometheus エンドポイント で確認できます。[#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)).
* iceberg tables 向けの query condition cache。[#102115](https://github.com/ClickHouse/ClickHouse/pull/102115) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Keeper の snapshot 進捗追跡を基盤とし、インクリメンタル読み取りに対応した `Paimon`、`PaimonS3`、`PaimonAzure`、`PaimonHDFS`、`PaimonLocal` table engines を追加しました。インクリメンタルモードでは、最後にコミットされた snapshot 以降の新しい行のみを返します。特定 snapshot の差分読み取りには `paimon_target_snapshot_id` を使用でき、クエリごとの snapshot 上限は `max_consume_snapshots` で指定できます。バックグラウンドでの メタデータのリフレッシュ は `paimon_metadata_refresh_interval_sec` で設定可能です。`allow_experimental_paimon_storage_engine` で制御されます。[#102343](https://github.com/ClickHouse/ClickHouse/pull/102343) ([XiaoBinMu](https://github.com/Binnn-MX)).
* Nullable columns で NULL 値 を正確にカウントするための NullCount statistics type を追加しました。これにより、`PREWHERE` の最適化が改善され、パーツ剪枝 も向上します。[#102356](https://github.com/ClickHouse/ClickHouse/pull/102356) ([zoomxi](https://github.com/zoomxi)).
* `prettyPrintJSON` 関数を使って、文字列を人が読みやすい JSON に整形できるようになりました。従来は JSON の整形に client side で追加の手順が必要だったダッシュボードやレポートで有用です。[#62523](https://github.com/ClickHouse/ClickHouse/issues/62523) をクローズします。[#102594](https://github.com/ClickHouse/ClickHouse/pull/102594) ([Dmitry Prokofyev](https://github.com/prokofyevDmitry)).
* `LIMIT BY` 句で負の値をサポートし、各グループの先頭ではなく末尾から行を選択できるようになりました。たとえば、`LIMIT -2 BY id` は `id` ごとに最後の 2 行を返します。負の offsets (`LIMIT -1 OFFSET -1 BY id`) や、符号が混在する場合 (`LIMIT -2 OFFSET 1 BY id`) もサポートされます。[#103222](https://github.com/ClickHouse/ClickHouse/pull/103222) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 新しい Kafka table setting `kafka_map_virtual_columns_on_write` を追加しました。これを有効にすると、Kafka table schema 内の `_key`、`_timestamp`、`_headers.name`、`_headers.value` という名前のカラムは、`INSERT` 時に対応する Kafka の message key、timestamp、headers として出力され、message payload には含まれなくなります。[#103243](https://github.com/ClickHouse/ClickHouse/pull/103243) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* リフレッシャブルmaterialized view向けに、`SYSTEM PAUSE VIEW [db.]name` および `SYSTEM PAUSE VIEWS` クエリを追加しました。`SYSTEM STOP VIEW` とは異なり、`SYSTEM PAUSE VIEW` は現在実行中のリフレッシュを中断しません。進行中のリフレッシュは完了まで継続され、その後のリフレッシュのみが抑止されます。これは `SYSTEM START VIEW` または `SYSTEM START VIEWS` で解除でき、これらは停止状態と一時停止状態の両方を一律にクリアするようになりました。 [#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 新しい設定 &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;join&#96; を追加しました。これは &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;group&#95;by&#96; および &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;sort&#96; に対応するものです。ハッシュ結合におけるディスクへのスピルしきい値を、利用可能メモリに対する割合で表します。絶対値の &#96;max&#95;bytes&#95;before&#95;external&#95;join&#96; と併用した場合は、算出されたしきい値のうち小さい方が適用されます。 [#103862](https://github.com/ClickHouse/ClickHouse/pull/103862) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 文字列内で N 番目に一致した正規表現のバイト位置を返す関数 `regexpPosition` (PostgreSQL 互換の別名 `regexpInstr` および `regexp_instr` を含む) を追加しました。開始オフセット、一致後を返すモード、正規表現フラグ、キャプチャグループの選択をサポートします。 [#104172](https://github.com/ClickHouse/ClickHouse/pull/104172) ([Abhinav Agarwal](https://github.com/aagarwal-gtr)).
* NullCount カラム STATISTICS をパーツ剪枝に使用できるようになりました。NullCount 統計を持つ Nullable カラムに対して IS NULL または IS NOT NULL 条件を含むクエリでは、統計によって一致する行が存在しないことが示される場合、パーツ全体をスキップできます。 [#104214](https://github.com/ClickHouse/ClickHouse/pull/104214) ([zoomxi](https://github.com/zoomxi)).
* 素数判定のための新しい関数 `isPrime` と `isProbablePrime` を追加しました。`isPrime` は `UInt64` までの符号なし整数に対して正確な結果を返します。`isProbablePrime` は `UInt128` と `UInt256` もサポートします。これらのより広い型では、`0` は確実に合成数、`1` はおそらく素数を意味します。`isProbablePrime` のオプションの第 2 引数 `rounds` は信頼度を制御し、デフォルトの `25` ラウンドでは、ランダムな合成数に対する偽陽性率を `10^-15` 未満に抑えます。 [#104234](https://github.com/ClickHouse/ClickHouse/pull/104234) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* clickhouse コマンドラインツールで、Clear と /clear は誤ってクエリとして実行されるのではなく、ターミナルをクリアするようになりました。 [#104318](https://github.com/ClickHouse/ClickHouse/pull/104318) ([Tyler Hannan](https://github.com/tylerhannan)).
* `SELECT` クエリで、`file` table function がパスの `Array(String)` を受け取れるようになりました。 [#104442](https://github.com/ClickHouse/ClickHouse/pull/104442) ([Yue](https://github.com/niyue)).
* `system.functions` table に `deterministic` および `higher_order` カラムを追加しました。 [#104479](https://github.com/ClickHouse/ClickHouse/pull/104479) ([Pedro Ferreira](https://github.com/PedroTadim)).



<div id="experimental-feature">
  #### 実験的機能
</div>

* `/webterminal` に、WebSocket 経由でブラウザ上の対話型 `clickhouse-client` セッションを提供する実験的なウェブターミナルインターフェイスを追加しました。デフォルトでは無効です。有効にするには、`allow_experimental_webterminal` サーバー設定を使用してください。[#100277](https://github.com/ClickHouse/ClickHouse/pull/100277) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WASM UDF で、より多くの数値型を型強制変換できるようになりました。より小さい整数型は、より大きい整数型に型強制変換できます。たとえば Int8 から UInt64 です。任意の整数型は浮動小数点型に型強制変換できます。たとえば Int32 から F32 です。[#100435](https://github.com/ClickHouse/ClickHouse/pull/100435) ([Vasily Chekalkin](https://github.com/bacek)).
* Iceberg の Geo 型をサポートしました。[#103113](https://github.com/ClickHouse/ClickHouse/pull/103113) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 実験的なウェブターミナル (`allow_experimental_webterminal`) は、`clickhouse.com`、`clickhouse.cloud`、およびそれらのサブドメインからクロスオリジンで埋め込み可能になりました。以前は、同一オリジンでない親からの `postMessage` は受信時に拒否され、送信時には黙って破棄されていたため、ターミナルは実質的に `play.clickhouse.com` 以外では埋め込みできませんでした。許可されるオリジンのリストは明示的な allowlist (https のみ、hostname 固定) であるため、信頼できないオリジンは引き続き拒否されます。[#105191](https://github.com/ClickHouse/ClickHouse/pull/105191) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `cramersV`、`cramersVBiasCorrected`、`theilsU`、`contingency` をウィンドウ関数と組み合わせて使用した場合の処理を最適化しました。[#83521](https://github.com/ClickHouse/ClickHouse/issues/83521) をクローズします。[#93384](https://github.com/ClickHouse/ClickHouse/pull/93384) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `ORDER BY ... LIMIT N` クエリの性能向上のため、`use_top_k_dynamic_filtering` および `use_skip_indexes_for_top_k` 設定をデフォルトで有効化しました。[#99537](https://github.com/ClickHouse/ClickHouse/pull/99537) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ピークメモリ使用量を削減するため、UNION ALL で同時にアクティブになるストリーム数を制限しました。[#100176](https://github.com/ClickHouse/ClickHouse/pull/100176) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `tupleElement(dictGet('dict', ('a', 'b', 'c'), key), N)` を `dictGet('dict', 'a', key)` に書き換えるクエリ最適化を追加し、不要な Dictionary 属性の取得を回避できるようにしました。これは `optimize_dictget_tuple_element` 設定で制御されます (デフォルトで有効) 。[#100186](https://github.com/ClickHouse/ClickHouse/pull/100186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ユーザー空間ページキャッシュをわずかに最適化しました。[#100300](https://github.com/ClickHouse/ClickHouse/pull/100300) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

ILLEGAL_COLUMN: Cannot add column ...: column with this name already exists` が発生する問題を修正しました。[#105290](https://github.com/ClickHouse/ClickHouse/pull/105290) ([Groene AI](https://github.com/groeneai)).
