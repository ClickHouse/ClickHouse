<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* [#43485](https://github.com/ClickHouse/ClickHouse/issues/43485)でバックポート: `String` 引数を持つ `min`、`max`、`any*`、`argMin`、`argMax` 集約関数の state の (de)serialization における後方互換性の問題を修正しました。この非互換性は [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431) で導入され、22.9、22.10、22.11 のブランチに影響します (それぞれ 22.9.6、22.10.4、22.11.2 以降で修正済み) 。22.3、22.7、22.8 ブランチの一部のマイナーリリースも影響を受けます: 22.3.13...22.3.14 (22.3.15 以降で修正済み) 、22.8.6...22.8.9 (22.8.10 以降で修正済み) 、22.7.6 以降 (22.7 では修正されないため、22.7.* から 22.8.10 以降へのアップグレードを推奨します) 。このリリースノートは、影響を受けるバージョンを一度も使用していないユーザーには関係ありません。非互換バージョンでは、上記の集約関数の state を読み取る際に、文字列の末尾に余分な `'\0'` を追加します。たとえば、古いバージョンが `anyState('foobar')` の state を `state_column` に保存していた場合、非互換バージョンでは `anyMerge(state_column)` の結果として `'foobar\0'` が出力されます。また、非互換バージョンはこれらの集約関数の state を末尾の `'\0'` なしで書き込みます。新しいバージョン (この修正を含むもの) は、1 つの特殊なケースを除き、非互換バージョンを含むすべてのバージョンで書き込まれたデータを正しく読み取れます。非互換バージョンが、実際に null 文字で終わる文字列を持つ state を保存した場合、新しいバージョンは影響を受ける集約関数の state を読み取る際に、末尾の `'\0'` を取り除きます。たとえば、非互換バージョンが `anyState('abrac\0dabra\0')` の state を `state_column` に保存した場合、非互換バージョンでは `anyMerge(state_column)` の結果として `'abrac\0dabra'` が出力されます。この問題は、非互換バージョンが古いバージョンまたは新しいバージョンと同じクラスター内で動作している場合の distributed queries にも影響します。[#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)) 。
