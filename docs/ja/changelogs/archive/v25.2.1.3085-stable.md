<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

*  (`config.xml` を更新していないインストールも含めて) デフォルトで `async_load_databases` を完全に有効化しました。 [#74772](https://github.com/ClickHouse/ClickHouse/pull/74772) ([Azat Khuzhin](https://github.com/azat)).
* `JSONCompactEachRowWithProgress` および `JSONCompactStringsEachRowWithProgress` フォーマットを追加しました。[#69989](https://github.com/ClickHouse/ClickHouse/issues/69989) の続きです。`JSONCompactWithNames` と `JSONCompactWithNamesAndTypes` は `"totals"` を出力しなくなりました。これは実装ミスだったようです。 [#75037](https://github.com/ClickHouse/ClickHouse/pull/75037) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ALTER コマンド一覧の曖昧さをなくすため、format&#95;alter&#95;operations&#95;with&#95;parentheses のデフォルトを true に変更しました (https://github.com/ClickHouse/ClickHouse/pull/59532 を参照) 。この変更により、24.3 より前のクラスターとのレプリケーションが壊れます。古いリリースを使用しているクラスターをアップグレードする場合は、サーバー設定でこの設定を無効にするか、先に 24.3 へアップグレードしてください。 [#75302](https://github.com/ClickHouse/ClickHouse/pull/75302) ([Raúl Marín](https://github.com/Algunenano)).
* cache 設定内の設定を検証するようにしました。存在しない設定は以前は無視されていましたが、今後はエラーになるため、削除する必要があります。 [#75452](https://github.com/ClickHouse/ClickHouse/pull/75452) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 正規表現を使ったログメッセージのフィルタリング機能を削除しました。この実装には data race があったため、削除する必要がありました。 [#75577](https://github.com/ClickHouse/ClickHouse/pull/75577) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).



<div id="new-feature">
  #### 新機能
</div>

* 同じクエリ内の複数の grace JOIN が合計のメモリ使用量を監視し、MEMORY&#95;LIMIT&#95;EXCEEDED を防ぐために、外部ストレージへの spilling を適応的にトリガーできる新しい設定 `enable_adaptive_memory_spill_scheduler` を追加しました。[#72728](https://github.com/ClickHouse/ClickHouse/pull/72728) ([lgbo](https://github.com/lgbo-ustc)).
* 2 つの文字列の一部を比較するための新しい文字列比較関数 `stringCompare` を追加しました。例: `SELECT stringCompare('Saxony', 'Anglo-Saxon', 0, 6, 5) AS result` は、「文字列 &#39;Saxon&#39; と &#39;Anglo-Saxon&#39; の 6 バイトを、1 つ目の文字列ではオフセット 0、2 つ目の文字列ではオフセット 5 から開始して、辞書順で比較する」ことを意味します。[#74070](https://github.com/ClickHouse/ClickHouse/pull/74070) ([lgbo](https://github.com/lgbo-ustc)).
* 未完了の mutations (バックグラウンドプロセスで materialize されていないもの) を、送信直後から `SELECT` クエリの実行中に適用できる機能を追加しました。これは `apply_mutations_on_fly` を設定することで有効にできます。[#74877](https://github.com/ClickHouse/ClickHouse/pull/74877) ([Anton Popov](https://github.com/CurtizJ)).
* `toStartOfInterval` の datetime 引数が負の場合に、これまで想定外だったいくつかのケースを修正しました。これは、新しい関数 toStartOfIntervalAllowNegative を実装することで対応しており、動作はほぼ同じですが、返り値は Date32/DateTime64 のみです。[#74933](https://github.com/ClickHouse/ClickHouse/pull/74933) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 新しい関数 initialQueryStartTime を追加しました。これは現在のクエリの開始時刻を返します。この値は distributed query 中のすべての分片で同一です。[#75087](https://github.com/ClickHouse/ClickHouse/pull/75087) ([Roman Lomonosov](https://github.com/lomik)).
* バックアップから table/database を即座に Attach できる新しいデータベースエンジン `DatabaseBackup` を追加しました。[#75725](https://github.com/ClickHouse/ClickHouse/pull/75725) ([Maksim Kita](https://github.com/kitaisreal)).
* データベース層を介さずに table を ATTACH できるようにしました (UUID hack を回避) 。[#75788](https://github.com/ClickHouse/ClickHouse/pull/75788) ([Azat Khuzhin](https://github.com/azat)).
* ライセンス上の問題により v24.10 で削除されていた QPL codec を復元しました。[#76021](https://github.com/ClickHouse/ClickHouse/pull/76021) ([Konstantin Bogdanov](https://github.com/thevar1able)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `materialize ttl` で `ttl_only_drop_parts` が考慮されるよう再導入しました。TTL の再計算に必要なカラムだけを読み取り、パーツを空のパーツに置き換えることで削除します。[#72751](https://github.com/ClickHouse/ClickHouse/pull/72751) ([Andrey Zvonov](https://github.com/zvonand)).
* `LowCardinality` カラムのメモリ内サイズ計算を修正しました。[#74688](https://github.com/ClickHouse/ClickHouse/pull/74688) ([Nikita Taranov](https://github.com/nickitat)).
* S3 上の wide パーツで JSON カラム全体を読み取る際の性能を改善しました。これは、サブカラムのプレフィックスのデシリアライゼーション向け prefetches、デシリアライズ済みプレフィックスの cache、サブカラムのプレフィックスの並列デシリアライゼーションを追加することで実現しています。これにより、`SELECT data FROM table` のようなクエリでは S3 からの JSON カラム読み取りが 4 倍、`SELECT data FROM table LIMIT 10` のようなクエリでは約 10 倍高速化されます。[#74827](https://github.com/ClickHouse/ClickHouse/pull/74827) ([Pavel Kruglov](https://github.com/Avogar)).
* オプティマイザによって join の左右が入れ替えられた場合に `ConcurrentHashJoin` で発生する二重の事前割り当てを修正しました。[#75149](https://github.com/ClickHouse/ClickHouse/pull/75149) ([Nikita Taranov](https://github.com/nickitat)).
* `max_rows_in_join = max_bytes_in_join = 0` の場合に `parallel_hash` で発生する不要な競合を修正しました。[#75155](https://github.com/ClickHouse/ClickHouse/pull/75155) ([Nikita Taranov](https://github.com/nickitat)).
* 一部の join シナリオでわずかに性能を改善しました。出力行数を事前計算し、そのためのメモリを事前確保します。[#75376](https://github.com/ClickHouse/ClickHouse/pull/75376) ([Alexander Gololobov](https://github.com/davenger)).
* `plain_rewritable` メタデータファイルは小さいため、大きなデフォルトバッファは不要です。指定されたパスに見合ったサイズの書き込みバッファを使用することで、多数の active parts がある場合のメモリ使用効率を改善します。 ### ユーザー向け変更に関するドキュメントエントリ。[#75758](https://github.com/ClickHouse/ClickHouse/pull/75758) ([Julia Kartseva](https://github.com/jkartseva)).
* 同時実行制御により、INSERT と SELECT の間で CPU リソースの配分が不公平になる可能性があることが判明しました。`max_threads` = 1 の INSERT にはすべての CPU slots が無条件に (競合なしで) 割り当てられる一方、高い `max_threads` 値を持つ SELECT は単一スレッドしか使えず、性能が低下していました。[#75941](https://github.com/ClickHouse/ClickHouse/pull/75941) ([Sergei Trifonov](https://github.com/serxa)).
* [#76849](https://github.com/ClickHouse/ClickHouse/issues/76849) でバックポート: パーツ削除時に cache からデータを積極的に退避させるようにしました。データ量が少ない場合に、cache が最大サイズまで肥大化しないようにします。[#76641](https://github.com/ClickHouse/ClickHouse/pull/76641) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* システムログのフラッシュ失敗回数に関するProfileEventを追加。[#75466](https://github.com/ClickHouse/ClickHouse/pull/75466) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 復号化および解凍処理のチェックとログ記録を追加。[#75471](https://github.com/ClickHouse/ClickHouse/pull/75471) ([Vitaly Baranov](https://github.com/vitlibar))。
* `parseTimeDelta` 関数でマイクロ記号 (U+00B5) をサポートしました。マイクロ記号 (U+00B5) とギリシャ文字のミュー (U+03BC) の両方がマイクロ秒の有効な表現として認識されるようになり、ClickHouse の動作が Go の実装 ([time.go](https://github.com/golang/go/blob/ad7b46ee4ac1cee5095d64b01e8cf7fcda8bee5e/src/time/time.go#L983C19-L983C20) および [time/format.go](https://github.com/golang/go/blob/ad7b46ee4ac1cee5095d64b01e8cf7fcda8bee5e/src/time/format.go#L1608-L1609) を参照) に準拠しました。[#75472](https://github.com/ClickHouse/ClickHouse/pull/75472) ([Vitaly Orlov](https://github.com/orloffv)).
* サーバー設定 (`send_settings_to_client`) をクライアント設定 (`apply_settings_from_server`) に置き換えました。この設定は、クライアント側のコード (例：INSERT データのパースやクエリ出力のフォーマット) がサーバーの `users.xml` およびユーザープロファイルの設定を使用するかどうかを制御します。無効の場合、クライアントのコマンドライン、セッション、およびクエリの設定のみが使用されます。なお、これはネイティブクライアントにのみ適用され (HTTP などには適用されません) 、サーバー上で行われるクエリ処理の大部分には適用されません。[#75478](https://github.com/ClickHouse/ClickHouse/pull/75478) ([Michael Kolupaev](https://github.com/al13n321)).
* Keeper の改善：パフォーマンス向上のため、インメモリストレージへのコミット時のダイジェスト計算を無効化しました。`keeper_server.digest_enabled_on_commit` 設定で有効化できます。リクエストの前処理時にはダイジェストが引き続き計算されます。[#75490](https://github.com/ClickHouse/ClickHouse/pull/75490) ([Antonio Andelic](https://github.com/antonio2368)).
* 可能な場合に JOIN ON からフィルター式をプッシュダウンするようにしました。[#75536](https://github.com/ClickHouse/ClickHouse/pull/75536) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 構文エラー時のエラーメッセージを改善しました。以前は、クエリが大きすぎる場合に、長さ制限を超えるトークンが非常に大きな文字列リテラルであると、その原因に関するメッセージが2つの例の間に埋もれてしまっていました。UTF-8 を含むクエリがエラーメッセージ内で誤って切り取られる問題を修正しました。クエリフラグメントの過剰なクォートを修正しました。[#75473](https://github.com/ClickHouse/ClickHouse/issues/75473) を解決します。[#75561](https://github.com/ClickHouse/ClickHouse/pull/75561) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ストレージ `S3(Azure)Queue` にプロファイルイベントを追加しました。[#75618](https://github.com/ClickHouse/ClickHouse/pull/75618) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 互換性のためにサーバーからクライアントへの設定送信を無効化しました (`send_settings_to_client=false`) 。この機能は、使いやすさ向上のため後でクライアント設定として再実装される予定です。[#75648](https://github.com/ClickHouse/ClickHouse/pull/75648) ([Michael Kolupaev](https://github.com/al13n321)).
* バックグラウンドスレッドで定期的に読み取られる各種ソースの情報を使用して内部 memory tracker を補正する機能を有効化するための設定 `memory_worker_correct_memory_tracker` を追加しました。[#75714](https://github.com/ClickHouse/ClickHouse/pull/75714) ([Antonio Andelic](https://github.com/antonio2368)).
* PrometheusRemoteReadProtocol でアナライザーを使用するようにしました。[#75729](https://github.com/ClickHouse/ClickHouse/pull/75729) ([Dmitry Novik](https://github.com/novikd)).
* `system.processes` にカラム `normalized_query_hash` を追加しました。注：`normalizedQueryHash` 関数を使用してその場で簡単に計算できますが、これは今後の変更に備えるために必要です。[#75756](https://github.com/ClickHouse/ClickHouse/pull/75756) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 存在しなくなったデータベース上に作成された `Merge` テーブルがある場合でも、`system.tables` へのクエリがエラーをスローしないようにしました。複雑な処理を許可しないため、`Hive` テーブルから `getTotalRows` メソッドを削除しました。[#75772](https://github.com/ClickHouse/ClickHouse/pull/75772) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Web UI にインタラクティブなデータベースナビゲーション機能が追加されました。[#75777](https://github.com/ClickHouse/ClickHouse/pull/75777) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ストレージポリシーにおいて読み取り専用ディスクと読み書き可能ディスクを組み合わせること (複数のボリュームまたは複数のディスクとして) を許可しました。これにより、ボリューム全体からデータを読み取りながら、INSERT は書き込み可能なディスクを優先するようになります (Copy-on-Write ストレージポリシー) 。[#75862](https://github.com/ClickHouse/ClickHouse/pull/75862) ([Azat Khuzhin](https://github.com/azat)).
* バックアップの start&#95;time/end&#95;time をマイクロ秒単位で保存するようにしました。[#75929](https://github.com/ClickHouse/ClickHouse/pull/75929) ([Aleksandr Musorin](https://github.com/AVMusorin)).
