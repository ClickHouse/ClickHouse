<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `String` 引数を持つ `min`、`max`、`any*`、`argMin`、`argMax` 集約関数の状態の (de)シリアライゼーション における後方非互換性を修正しました。この非互換性は [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431) で導入され、22.9、22.10、22.11 の各ブランチに影響します (それぞれ 22.9.6、22.10.4、22.11.2 以降で修正済み) 。また、22.3、22.7、22.8 ブランチの一部のマイナーリリースにも影響があります: 22.3.13...22.3.14 (22.3.15 以降で修正済み) 、22.8.6...22.8.9 (22.8.10 以降で修正済み) 、22.7.6 以降 (22.7 では修正されないため、22.7.* から 22.8.10 以降へのアップグレードを推奨します) 。このリリースノートは、影響を受けるバージョンを一度も使用したことがないユーザーには関係ありません。非互換バージョンでは、前述の集約関数の状態を読み取る際に、文字列の末尾に余分な `'\0'` が追加されます。たとえば、古いバージョンが `anyState('foobar')` の状態を `state_column` に保存した場合、非互換バージョンでは `anyMerge(state_column)` に対して `'foobar\0'` が出力されます。また、非互換バージョンは、これらの集約関数の状態を末尾の `'\0'` なしで書き込みます。新しいバージョン (この修正を含むもの) は、1 つの特殊なケースを除き、非互換バージョンを含むすべてのバージョンによって書き込まれたデータを正しく読み取れます。特殊なケースとは、非互換バージョンが実際に null 文字で終わる文字列を含む状態を保存した場合です。このとき、新しいバージョンは、影響を受ける集約関数の状態を読み取る際に末尾の `'\0'` を取り除きます。たとえば、非互換バージョンが `anyState('abrac\0dabra\0')` の状態を `state_column` に保存した場合、新しいバージョンでは `anyMerge(state_column)` に対して `'abrac\0dabra'` が出力されます。この問題は、非互換バージョンが古いバージョンまたは新しいバージョンと同じクラスター内で動作している場合の分散クエリにも影響します。[#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)).

<div id="new-feature">
  #### 新機能
</div>

* `grace_hash` `join_algorithm` を追加しました。[#38191](https://github.com/ClickHouse/ClickHouse/pull/38191) ([BigRedEye](https://github.com/BigRedEye))。
* `enable_memory_bound_merging_of_aggregation_results` が設定されている場合、イニシエーターでのマージで、ローカル aggregation 結果のマージと同じメモリ制約方式を使用するようになりました。[#40879](https://github.com/ClickHouse/ClickHouse/pull/40879) ([Nikita Taranov](https://github.com/nickitat))。
* BSONEachRow 入出力フォーマットを追加しました。このフォーマットでは、ClickHouse は各行を個別の BSON Document としてフォーマット/解析し、各カラムはカラム名をキーとする単一の BSON フィールドとしてフォーマット/解析されます。[#42033](https://github.com/ClickHouse/ClickHouse/pull/42033) ([mark-polokhov](https://github.com/mark-polokhov))。
* クローズ: [#37631](https://github.com/ClickHouse/ClickHouse/issues/37631)。[#42265](https://github.com/ClickHouse/ClickHouse/pull/42265) ([刘陶峰](https://github.com/taofengliu))。
* 固定精度の Decimal 演算用に `multiplyDecimal` および `divideDecimal` 関数を追加しました。[#42438](https://github.com/ClickHouse/ClickHouse/pull/42438) ([Andrey Zvonov](https://github.com/zvonand))。
* 現在移動中のパーツの一覧を含む `system.moves` テーブルを追加しました。[#42660](https://github.com/ClickHouse/ClickHouse/pull/42660) ([Sergei Trifonov](https://github.com/serxa))。
* Keeper の feature として、埋め込み Prometheus エンドポイントのサポートを追加しました。[#43087](https://github.com/ClickHouse/ClickHouse/pull/43087) ([Antonio Andelic](https://github.com/antonio2368))。
* 2 つの日付、または日時の値の間の差分を、完全な単位数として表した値を計算する age 関数を追加しました。[#41115](https://github.com/ClickHouse/ClickHouse/issues/41115) をクローズしました。[#43123](https://github.com/ClickHouse/ClickHouse/pull/43123) ([Roman Vasin](https://github.com/rvasin))。
* 設定 `max_streams_for_merge_tree_reading` および `allow_asynchronous_read_from_io_pool_for_merge_tree` を追加しました。設定 `max_streams_for_merge_tree_reading` は MergeTree テーブルの読み取りストリーム数を制限します。設定 `allow_asynchronous_read_from_io_pool_for_merge_tree` は、バックグラウンド I/O プールによる `MergeTree` テーブルからの読み取りを有効にします。これは、`max_streams_to_max_threads_ratio` または `max_streams_for_merge_tree_reading` と併用すると、I/O ボトルネックのあるクエリで性能が向上する可能性があります。[#43260](https://github.com/ClickHouse/ClickHouse/pull/43260) ([Nikolai Kochetov](https://github.com/KochetovNicolai))。
* `data_skipping_indices` system table に索引式を追加しました。[#43308](https://github.com/ClickHouse/ClickHouse/pull/43308) ([Guillaume Tassery](https://github.com/YiuRULE))。
* 新しい hash function [xxh3](https://github.com/Cyan4973/xxHash) を追加しました。また、ライブラリの更新により、arm での `xxHash32` および `xxHash64` の性能も向上しました。[#43411](https://github.com/ClickHouse/ClickHouse/pull/43411) ([Nikita Taranov](https://github.com/nickitat))。
* * 一時データ (外部ソート、集約、JOIN 用) が、リモートディスクのファイルシステムキャッシュとストレージを共有し、キャッシュを追い出してしまう可能性がありました。[#42158](https://github.com/ClickHouse/ClickHouse/issues/42158) をクローズしました。[#43457](https://github.com/ClickHouse/ClickHouse/pull/43457) ([Vladimir C](https://github.com/vdimir)).
* システムテーブル `databases` にカラム `engine_full` を追加し、ユーザーがシステムテーブル経由でデータベースの完全なエンジン定義にアクセスできるようにしました。[#43468](https://github.com/ClickHouse/ClickHouse/pull/43468) ([凌涛](https://github.com/lingtaolf)).
* 新規ユーザー作成時のパスワード複雑性ルールとチェックを追加しました。[#43719](https://github.com/ClickHouse/ClickHouse/pull/43719) ([Nikolay Degterinsky](https://github.com/evillique)).
* Spark の concat&#95;ws と同様の関数 concatWithSeparator を追加しました。[#43749](https://github.com/ClickHouse/ClickHouse/pull/43749) ([李扬](https://github.com/taiyang-li)).
* MergeTree 設定に制約を追加しました。[#43903](https://github.com/ClickHouse/ClickHouse/pull/43903) ([Sergei Trifonov](https://github.com/serxa)).
* 区切り文字として &#95; を含む数値リテラルをサポートしました。[#43925](https://github.com/ClickHouse/ClickHouse/pull/43925) ([jh0x](https://github.com/jh0x)).
* すべての JSON input formats でネストされた JSON オブジェクトを String として parse できるようにする新しい設定 `input_format_json_read_objects_as_strings` を追加しました。この設定はデフォルトで無効です。[#44052](https://github.com/ClickHouse/ClickHouse/pull/44052) ([Kruglov Pavel](https://github.com/Avogar)).

* この PR では、次のクエリによるパーツ削除の方式を変更しました: truncate table、alter table drop part、alter table drop partition。これらのクエリは、古いパーツを覆う空のパーツを作成するようになりました。これにより、truncate クエリは排他的ロックなしで動作し、同時実行の read がロックされなくなります。さらに、これらすべてのクエリで永続性も実現しました。リクエストが成功した場合、後からパーツが復活することはありません。なお、アトミック性が実現されるのは transaction スコープ内に限られます。[#41145](https://github.com/ClickHouse/ClickHouse/pull/41145) ([Sema Checherinda](https://github.com/CheSema)).

* issue [#38075](https://github.com/ClickHouse/ClickHouse/issues/38075) を修正しました。現時点では、非同期 INSERT は重複排除をサポートしていません。これは、複数の小さな insert が 1 つの part に共存し、複数の `block id` に対応するためです。この対応は比較的単純で、変更内容は次のとおりです。1. 各 chunk 内のすべての insert について offsets を mark する 2. sinker が chunk を受信した際に複数の `block_id` を計算する 3. それらの `block_id` に対して block number lock を取得する 3.1. 失敗した場合は、重複した insert と重複した `block_id` を block から削除し、`offsets` を再計算する 3.2. 成功した場合は、`block_id` などの項目を keeper に commit する a. 失敗した場合は 3.1 を実行する b. 成功した場合は、すべて成功となる。[#43304](https://github.com/ClickHouse/ClickHouse/pull/43304) ([Han Fei](https://github.com/hanfei1991)).
* client で、より正確で即応性の高い CPU 負荷表示に対応しました。[#43307](https://github.com/ClickHouse/ClickHouse/pull/43307) ([Sergei Trifonov](https://github.com/serxa)).
