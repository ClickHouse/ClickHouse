<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* テーブル `system.dictionaries` のカラム `keys` は、カラム `key.names` および `key.types` に置き換えられました。`system.dictionaries` テーブルのカラム `key.names`、`key.types`、`attribute.names`、`attribute.types` は、Dictionary がロードされていなくても参照できます。[#21884](https://github.com/ClickHouse/ClickHouse/pull/21884) ([Maksim Kita](https://github.com/kitaisreal)).
* カスタムのトップレベルドメインリストに含まれる 3 階層以上のドメインに対して、`cutToFirstSignificantSubdomainCustom()`/`firstSignificantSubdomainCustom()` が誤った結果を返す問題を修正しました。これらのカスタムトップレベルドメインに一致する入力ドメインでは、第 3 レベルのドメインが最初の主要サブドメインと見なされていました。これは修正されました。この変更により、たとえばシャーディングキーでこの関数を使用している場合は非互換性が生じる可能性があります。[#21946](https://github.com/ClickHouse/ClickHouse/pull/21946) ([Azat Khuzhin](https://github.com/azat)).
* `toStartOfIntervalFunction` は、時間単位のインターバルを深夜 0 時に揃えるようになります (以前のバージョンでは Unix epoch の開始時点に揃えられていました) 。たとえば、`toStartOfInterval(x, INTERVAL 11 HOUR)` は 1 日を 3 つのインターバル、00:00:00..10:59:59、11:00:00..21:59:59、22:00:00..23:59:59 に分割します。この挙動のほうが実際の用途に適しています。これにより [#9510](https://github.com/ClickHouse/ClickHouse/issues/9510) はクローズされます。[#22060](https://github.com/ClickHouse/ClickHouse/pull/22060) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* `MergeTree*` エンジン向けに仮想カラム `_partition_id` を追加しました。`_partition_id` によるパーティションの絞り込みが可能になります。パーティション ID の文字列を計算する `partitionID()` 関数も追加しました。[#21401](https://github.com/ClickHouse/ClickHouse/pull/21401) ([Amos Bird](https://github.com/amosbird)).

* `zookeeper-dump-tree` に `ctime` オプションを追加しました。これにより、node の作成時刻を dump できます。[#21842](https://github.com/ClickHouse/ClickHouse/pull/21842) ([Ilya](https://github.com/HumanUser)).
* &#39;dictGet&#39;、&#39;dictHas&#39; 関数は、DDL で作成された Dictionaries に対して、database 名が指定されていない場合は current database 名を使用するようになりました。[#21632](https://github.com/ClickHouse/ClickHouse/issues/21632) をクローズします。[#21859](https://github.com/ClickHouse/ClickHouse/pull/21859) ([Maksim Kita](https://github.com/kitaisreal)).
* `PolygonDictionary` の attribute で `Nullable` 型をサポートしました。[#21890](https://github.com/ClickHouse/ClickHouse/pull/21890) ([Maksim Kita](https://github.com/kitaisreal)).
* table function `dictionary` を追加しました。これは `Dictionary` エンジンと同様に動作します。[#21560](https://github.com/ClickHouse/ClickHouse/issues/21560) をクローズします。[#21910](https://github.com/ClickHouse/ClickHouse/pull/21910) ([Maksim Kita](https://github.com/kitaisreal)).
* `DateTime` または `DateTime64` data types の timezone 名を返す `timezoneOf` 関数を追加しました。これは [#9959](https://github.com/ClickHouse/ClickHouse/issues/9959) をクローズするものではありません。あわせて、関数名の不整合を修正し、別名 `timezone` と `timeZone`、`toTimezone` と `toTimeZone`、`timezoneOf` と `timeZoneOf` を追加しました。[#22001](https://github.com/ClickHouse/ClickHouse/pull/22001) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 別名ではなく元のカラム名を使用するための `prefer_column_name_to_alias` setting を追加しました。これは、一般的な databases の alias 規則との互換性を高めるために必要です。これは [#9715](https://github.com/ClickHouse/ClickHouse/issues/9715) および [#9887](https://github.com/ClickHouse/ClickHouse/issues/9887) に対応するものです。[#22044](https://github.com/ClickHouse/ClickHouse/pull/22044) ([Amos Bird](https://github.com/amosbird)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `CSVWithNames` および `TSVWithNames` フォーマットで並列パースをサポートしました。これにより [#21085](https://github.com/ClickHouse/ClickHouse/issues/21085) はクローズされます。 [#21149](https://github.com/ClickHouse/ClickHouse/pull/21149) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `memcpy` を別の実装に置き換えることで、パフォーマンスを改善しました。これにより [#18583](https://github.com/ClickHouse/ClickHouse/issues/18583) はクローズされます。 [#21520](https://github.com/ClickHouse/ClickHouse/pull/21520) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* clickhouse-local など全体で並列フォーマットをサポートしました。 [#21630](https://github.com/ClickHouse/ClickHouse/pull/21630) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `SELECT ... FINAL ... WHERE` のようなクエリのパフォーマンスを最適化しました。これにより、`FINAL` を含むクエリでは、sorting key に含まれるカラムを `PREWHERE` に移動できるようになりました。... [#21830](https://github.com/ClickHouse/ClickHouse/pull/21830) ([foolchi](https://github.com/foolchi)).
* `max_rows_to_group_by` が小さく、`group_by_overflow_mode='any'` の場合の `GROUP BY` を高速化しました。 [#21856](https://github.com/ClickHouse/ClickHouse/pull/21856) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* codec `NONE` 使用時の不要なデータコピーを回避しました。codec `NONE` はほとんどの場合有用ではないため、常に圧縮を使用することを推奨します (デフォルトは `LZ4` です) 。一般に考えられているのとは異なり、圧縮を無効にしてもパフォーマンスが向上するとは限らず、逆効果になることもあります。`NONE` codec が有用なのは、次のような一部のケースです。- データが圧縮できない場合。- 合成 benchmark の場合。 [#22145](https://github.com/ClickHouse/ClickHouse/pull/22145) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `min_bytes_to_use_mmap_io` 設定で読み取るファイル向けに cache を追加しました。これにより、mmap/munmap の頻繁な呼び出しとそれに伴うページフォールトを回避できるため、この設定値が小さい場合に大幅な (2 倍以上の) パフォーマンス改善が得られます。mmap I/O には、本番環境では信頼性を損なう大きな欠点があることに注意してください (たとえば、不良ディスクでハングしたり SIGBUS が発生したりする、メモリ使用量を制御しにくい、など) 。それでも benchmark では有効です。 [#22206](https://github.com/ClickHouse/ClickHouse/pull/22206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 64 MiB 以上のファイル範囲に対して mmap I/O による読み取りを有効にしました (設定: `min_bytes_to_use_mmap_io`) 。これにより、ある程度のパフォーマンス改善が見込まれます。 [#22326](https://github.com/ClickHouse/ClickHouse/pull/22326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* NULL のタプル、たとえば `(NULL, NULL)` が、右辺に非 NULL のタプルを持つ `IN` operator の左辺にある場合、たとえば `SELECT (NULL, NULL) IN ((0, 0), (3, 1))` では、型の不整合に関する例外をスローする代わりに 0 を返すようにしました。この expression は、`SELECT (NULL, NULL) = (8, 0) OR (NULL, NULL) = (3, 2) OR (NULL, NULL) = (0, 0) OR (NULL, NULL) = (3, 1)` のような式の最適化によって現れることもあります。これにより [#22017](https://github.com/ClickHouse/ClickHouse/issues/22017) がクローズされます。[#22063](https://github.com/ClickHouse/ClickHouse/pull/22063) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
