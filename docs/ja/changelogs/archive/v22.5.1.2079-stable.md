<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更

* BoringSSL モジュールを公式の FIPS compliant バージョンに更新しました。これにより、ClickHouse は FIPS compliant になります。 [#35914](https://github.com/ClickHouse/ClickHouse/pull/35914) ([Deleted user](https://github.com/ghost)).
* background merges、mutations、および `OPTIMIZE` では、`SelectedRows` と `SelectedBytes` メトリクスが加算されなくなりました。一方で、従来どおり `MergedRows` と `MergedUncompressedBytes` には引き続き加算されます。 [#37040](https://github.com/ClickHouse/ClickHouse/pull/37040) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).



<div id="new-feature">

* `GROUP BY` 句での GROUPING SETS のサポートを追加しました。[#33186](https://github.com/ClickHouse/ClickHouse/issues/33186) の後続対応です。この実装では、grouping sets を並列処理できます。[#33631](https://github.com/ClickHouse/ClickHouse/pull/33631) ([Dmitry Novik](https://github.com/novikd)) 。

* 一時テーブルで合計行数と合計バイト数を表示できるようになりました。[#36401](https://github.com/ClickHouse/ClickHouse/issues/36401)。[#36439](https://github.com/ClickHouse/ClickHouse/pull/36439) ([chen](https://github.com/xiedeyantu)).

* ウィンドウ関数 nth&#95;value を追加しました。[#36601](https://github.com/ClickHouse/ClickHouse/pull/36601) ([Nikolay](https://github.com/ndchikin)).
* MySQLDump 入力フォーマットを追加しました。これは dump 内の 1 つのテーブルに対応する INSERT クエリから、すべてのデータを読み取ります。複数のテーブルがある場合、デフォルトでは最初のテーブルのデータを読み取ります。[#36667](https://github.com/ClickHouse/ClickHouse/pull/36667) ([Kruglov Pavel](https://github.com/Avogar)).

* **説明:** これはリモートファイルアクセスのリクエスト数を記録する system table で、storage and compute の separation 構成において、パフォーマンス変動の原因分析に役立ちます。現在の system table structure は次のとおりです。クエリがリモートファイルの segment を読み取ると、1 件のレコードが生成されます。Read type には **READ&#95;FROM&#95;FS&#95;AND&#95;DOWNLOADED&#95;TO&#95;CACHE、READ&#95;FROM&#95;CACHE、READ&#95;FROM&#95;FS&#95;BYPASSING&#95;CACHE** があり、クエリがその segment を cache から読み取ったのか、リモートファイルから読み取ったのかを示します。[#36802](https://github.com/ClickHouse/ClickHouse/pull/36802) ([Han Shukai](https://github.com/KinderRiven)).
* `h3Line`、`h3Distance`、`h3HexRing` 関数を追加しました。[#37030](https://github.com/ClickHouse/ClickHouse/pull/37030) ([Bharat Nallan](https://github.com/bharatnc)).
* 関連 issue - [#35101](https://github.com/ClickHouse/ClickHouse/issues/35101)。[#37033](https://github.com/ClickHouse/ClickHouse/pull/37033) ([qieqieplus](https://github.com/qieqieplus)).
* system.certificates テーブルを追加しました。[#37142](https://github.com/ClickHouse/ClickHouse/pull/37142) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* ソートカラムのコンパレータに JIT コンパイルを使用することで、ORDER BY、MergeJoin、MergeTree への挿入のパフォーマンスを改善しました。 [#34469](https://github.com/ClickHouse/ClickHouse/pull/34469) ([Maksim Kita](https://github.com/kitaisreal)).
* 最初のコミットではインライン化のしきい値を引き上げます。後続のコミットでは、より高いパフォーマンスが確認されたものについてインライン化によりクエリを改善します。これにより、コンパイル時間や binary サイズを増やすことなく、プログラムを最適化できます。 [#34544](https://github.com/ClickHouse/ClickHouse/pull/34544) ([Daniel Kutenin](https://github.com/danlark1)).
* OR LIKE の連鎖を multiMatchAny に変換します。十分に動作確認できた段階で有効化する予定です。 [#34932](https://github.com/ClickHouse/ClickHouse/pull/34932) ([Daniel Kutenin](https://github.com/danlark1)).
* &#39;select countDistinct(a) from t&#39; を &#39;select count(1) from (select a from t groupBy a)&#39; に書き換えます。 [#35993](https://github.com/ClickHouse/ClickHouse/pull/35993) ([zhanglistar](https://github.com/zhanglistar)).
* `system.asynchronous_metric_log` の構造を変更しました。必要な容量は約 10 分の 1 になります。これにより [#36357](https://github.com/ClickHouse/ClickHouse/issues/36357) をクローズします。`event_time_microseconds` フィールドは不要なため削除されました。 [#36360](https://github.com/ClickHouse/ClickHouse/pull/36360) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* デフォルトの `HashJoin` は右テーブルの行の挿入をスレッドセーフに行えないため、単一スレッドで実行されます。右テーブルが大きい場合、CPU 使用率が低く、join 処理が非常に遅くなります。 [#36415](https://github.com/ClickHouse/ClickHouse/pull/36415) ([lgbo](https://github.com/lgbo-ustc)).
* パスに globs が含まれ、一致した directory に大量のファイルがある場合の、storage `File` および table functions `file` からの読み取り性能を改善しました。 [#36647](https://github.com/ClickHouse/ClickHouse/pull/36647) ([Anton Popov](https://github.com/CurtizJ)).
* input format `HiveText` に並列パースを適用し、ローカルファイル読み取り時の HiveText のパースを 2 倍高速化できるようにしました。 [#36650](https://github.com/ClickHouse/ClickHouse/pull/36650) ([李扬](https://github.com/taiyang-li)).
* mutex のスコープを狭めることで、ファイルディスクリプタ cache のパフォーマンスを改善しました。 [#36682](https://github.com/ClickHouse/ClickHouse/pull/36682) ([Anton Kozlov](https://github.com/tonickkozlov)).
* この PR では、WindowView の `WATCH` クエリを改善しています: 1. `fire_condition` シグナルを呼び出すことで、クエリ結果が返されるまでの latency を低減。2. `isCancelled()` をより頻繁に確認することで、クエリのキャンセル操作 (ctrl-c) を高速化。 [#37226](https://github.com/ClickHouse/ClickHouse/pull/37226) ([vxider](https://github.com/Vxider)).
* GROUP BY 式なしで使用される場合の `avg`、`sum` aggregate functions のパフォーマンスを改善しました。 [#37257](https://github.com/ClickHouse/ClickHouse/pull/37257) ([Maksim Kita](https://github.com/kitaisreal)).
* dynamic dispatch を使用して、単項算術関数 (`bitCount`、`bitNot`、`abs`、`intExp2`、`intExp10`、`negate`、`roundAge`、`roundDuration`、`roundToExp2`、`sign`) のパフォーマンスを改善しました。 [#37289](https://github.com/ClickHouse/ClickHouse/pull/37289) ([Maksim Kita](https://github.com/kitaisreal)).
