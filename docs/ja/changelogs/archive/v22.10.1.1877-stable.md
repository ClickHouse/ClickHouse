<div id="2022-changelog">
  # 2022年 変更履歴
</div>

<div id="clickhouse-release-v221011877-stable-98ab5a3c189-fixme-as-compared-to-v22912603-stable-3030d4c7ff0">
  ### ClickHouse リリース v22.10.1.1877-stable (98ab5a3c189) FIXME v22.9.1.2603-stable (3030d4c7ff0) との比較
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* cache コマンド名を変更: `show caches` -&gt; `show filesystem caches`、`describe cache` -&gt; `describe filesystem cache`。 [#41508](https://github.com/ClickHouse/ClickHouse/pull/41508) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `LIVE VIEW` に対する `WITH TIMEOUT` 句のサポートを削除しました。これにより [#40557](https://github.com/ClickHouse/ClickHouse/issues/40557) をクローズします。 [#42173](https://github.com/ClickHouse/ClickHouse/pull/42173) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新機能
</div>

* BLAKE3 hash-function library を例として、Rust code のサポートを ClickHouse に追加しました。 [#33435](https://github.com/ClickHouse/ClickHouse/pull/33435) ([BoloniniD](https://github.com/BoloniniD)).
* これは Kusto Query Language の初期実装です (MVP) 。 [#37961](https://github.com/ClickHouse/ClickHouse/pull/37961) ([Yong Wang](https://github.com/kashwy)).
* * 設定 `max_temporary_data_on_disk_size_for_user`/`max_temporary_data_on_disk_size_for_query` を使用して、ディスク上に保存される一時データの量を制限できるようになりました。 [#40893](https://github.com/ClickHouse/ClickHouse/pull/40893) ([Vladimir C](https://github.com/vdimir)).
* `javaHash` で Java の整数のハッシュ化をサポートしました。[#41131](https://github.com/ClickHouse/ClickHouse/pull/41131) ([JackyWoo](https://github.com/JackyWoo)).
* この PR では、BoringSSL サブモジュールと同様に、OpenSSL のインハウスビルドをサポートしました。ビルドフラグ ENABLE&#95;CH&#95;BUNDLE&#95;BORINGSSL を使用して、BoringSSL と OpenSSL を切り替えられます。デフォルトでは、BoringSSL のインハウスビルドが使用されます。[#41142](https://github.com/ClickHouse/ClickHouse/pull/41142) ([MeenaRenganathan22](https://github.com/MeenaRenganathan22)).
* 構成可能なプロトコル設定を追加しました。[#41198](https://github.com/ClickHouse/ClickHouse/pull/41198) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* ON CLUSTER DDL に OpenTelemetry のサポートを追加しました (`distributed_ddl_entry_format_version` を 4 に設定する必要があります) 。[#41484](https://github.com/ClickHouse/ClickHouse/pull/41484) ([Frank Chen](https://github.com/FrankChen021)).
* JSONObjectEachRow フォーマットで、オブジェクト名をカラム値として書き込み・parseするための setting `format_json_object_each_row_column_for_object_name` を追加しました。[#41703](https://github.com/ClickHouse/ClickHouse/pull/41703) ([Kruglov Pavel](https://github.com/Avogar)).
* Morton Coding (ZCurve) のエンコード/デコード関数を追加しました。[#41753](https://github.com/ClickHouse/ClickHouse/pull/41753) ([Constantine Peresypkin](https://github.com/pkit)).
* UUID のさまざまなバイナリ形式のサポートを実装し、特に広く使われている 2 つの形式、すなわちデフォルトのビッグエンディアン形式と、[RFC 4122](https://datatracker.ietf.org/doc/html/rfc4122#section-4.1.1) で規定された Microsoft の mixed-endian 形式に対応しました。[#42108](https://github.com/ClickHouse/ClickHouse/pull/42108) ([ltrk2](https://github.com/ltrk2)).
* 複数の正規分布に従う観測値グループに対して統計検定を行い、すべてのグループの平均が同じかどうかを判定する aggregate function `analysisOfVariance` (`anova`) を追加しました。Original PR [#37872](https://github.com/ClickHouse/ClickHouse/issues/37872)。[#42131](https://github.com/ClickHouse/ClickHouse/pull/42131) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `SET setting_name = DEFAULT` のサポートを追加しました。[#42187](https://github.com/ClickHouse/ClickHouse/pull/42187) ([Filatenkov Artur](https://github.com/FArthur-cmd)).
* * RFC に準拠する `URL` 関数を追加しました。含まれる関数: `cutToFirstSignificantSubdomainCustomRFC`, `cutToFirstSignificantSubdomainCustomWithWWWRFC`, `cutToFirstSignificantSubdomainRFC`, `cutToFirstSignificantSubdomainWithWWWRFC`, `domainRFC`, `domainWithoutWWWRFC`, `firstSignificantSubdomainCustomRFC`, `firstSignificantSubdomainRFC`, `portRFC`, `topLevelDomainRFC`。[#42274](https://github.com/ClickHouse/ClickHouse/pull/42274) ([Quanfa Fu](https://github.com/dentiscalprum)).
* 指定した分布に従うランダムな値を生成する関数 (`randUniform`, `randNormal`, `randLogNormal`, `randExponential`, `randChiSquared`, `randStudentT`, `randFisherF`, `randBernoulli`, `randBinomial`, `randNegativeBinomial`, `randPoisson`) を追加しました。これにより [#21834](https://github.com/ClickHouse/ClickHouse/issues/21834) がクローズされました。[#42411](https://github.com/ClickHouse/ClickHouse/pull/42411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* スタックオーバーフローの問題を解消し、必要なスタックサイズを小さくするため、operator precedence element parser を実装しました。[#34892](https://github.com/ClickHouse/ClickHouse/pull/34892) ([Nikolay Degterinsky](https://github.com/evillique))。
* DISTINCT in order の最適化で、データストリームのソート特性を活用するようにしました。この改善により、適用可能な場合は DISTINCT でも順序どおりの読み取りが可能になります (以前は DISTINCT のカラムに対して ORDER BY を指定する必要がありました) 。[#41014](https://github.com/ClickHouse/ClickHouse/pull/41014) ([Igor Nikonov](https://github.com/devcrafter))。
* ColumnVector: AVX512VBMI を使用して UInt8 の索引を最適化しました。[#41247](https://github.com/ClickHouse/ClickHouse/pull/41247) ([Guo Wangyang](https://github.com/guowangy))。
* ICX デバイス (Intel Xeon Platinum 8380 CPU、80 コア、160 スレッド) 上での **SSB** (Star Schema Benchmark) の性能実験では、この変更により全サブケースの QPS の幾何平均が **2.95 倍** 改善される可能性があることが示されました。[#41675](https://github.com/ClickHouse/ClickHouse/pull/41675) ([Zhiguo Zhou](https://github.com/ZhiguoZh))。
* LowCardinality(String) の Tuple における JSONExtract の低速化を修正しました。[#41726](https://github.com/ClickHouse/ClickHouse/pull/41726) ([AlfVII](https://github.com/AlfVII))。
* AArch64 ビルドに ldapr capabilities を追加しました。これは Graviton 2 以降、Azure、および GCP インスタンスでサポートされています。clang-15 で [比較的最近](https://github.com/llvm/llvm-project/commit/9609b5daffe9fd28d83d83da895abc5113f76c24) 利用可能になった機能です。[#41778](https://github.com/ClickHouse/ClickHouse/pull/41778) ([Daniel Kutenin](https://github.com/danlark1))。
* 文字列比較時に、一方の argument が空の定数文字列である場合のパフォーマンスを改善しました。[#41870](https://github.com/ClickHouse/ClickHouse/pull/41870) ([Jiebin Sun](https://github.com/jiebinn))。
* 一部のケースで aggregate state を共有するようにし、ColumnAggregateFunction の insertFrom を最適化しました。[#41960](https://github.com/ClickHouse/ClickHouse/pull/41960) ([flynn](https://github.com/ucasfl))。
* 「パーツが多すぎる」のしきい値を緩和しました。これにより [#6551](https://github.com/ClickHouse/ClickHouse/issues/6551) はクローズされます。現在の ClickHouse では、平均パーツサイズが十分に大きい場合 (少なくとも 10 GiB) 、パーティション内でより多くのパーツを許可します。これにより、ディスクシェルフやオブジェクトストレージを使用すれば、単一サーバー上の単一テーブルの単一パーティションに最大 PB 規模のデータを保持できるようになります。[#42002](https://github.com/ClickHouse/ClickHouse/pull/42002) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* AzureBlobStorage への書き込みをより効率的にしました (バッファサイズごとに block を書き込むのではなく、`max_single_part_upload_size` を尊重します) 。この非効率性は [#41754](https://github.com/ClickHouse/ClickHouse/issues/41754) で言及されていました。[#42041](https://github.com/ClickHouse/ClickHouse/pull/42041) ([Kseniia Sumarokova](https://github.com/kssenii))。
* process list と query&#95;log 内の thread id を一意にし、無駄を避けるようにしました。[#42180](https://github.com/ClickHouse/ClickHouse/pull/42180) ([Alexey Milovidov](https://github.com/alexey-milovidov))。

<div id="improvement">
  #### 改善
</div>

* `allow_experimental_analyzer` 設定のもとで、クエリ分析およびプランニング向けの新しいインフラストラクチャが追加されました。 [#31796](https://github.com/ClickHouse/ClickHouse/pull/31796) ([Maksim Kita](https://github.com/kitaisreal)).
* * サブクエリ内で `(EXPLAIN SELECT ...)` 式をサポートしました。`SELECT * FROM (EXPLAIN PIPELINE SELECT col FROM TABLE ORDER BY col)` のようなクエリが有効になりました。[#40630](https://github.com/ClickHouse/ClickHouse/pull/40630) ([Vladimir C](https://github.com/vdimir)).
* 現時点では、クエリスコープで `async_insert_max_data_size` や `async_insert_busy_timeout_ms` を変更しても意味がなく、ユーザー体験を損ねていました。たとえば、データをまれにしか insert しないユーザーが、デフォルト設定を調整するためのサーバー設定にアクセスできない場合です。[#40668](https://github.com/ClickHouse/ClickHouse/pull/40668) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 埋め込み Keeper は常にバックグラウンドで起動するようになり、ClickHouse はクォーラムを達成していなくても起動できるようになりました。[#40991](https://github.com/ClickHouse/ClickHouse/pull/40991) ([Antonio Andelic](https://github.com/antonio2368)).
* リモートファイルシステムからの読み取りを改善し、reads/writes 用の threadpool サイズを設定可能にしました。[#41070](https://github.com/ClickHouse/ClickHouse/issues/41070) をクローズします。[#41011](https://github.com/ClickHouse/ClickHouse/pull/41011) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 以前の connection が期限切れになった場合に、新しい connection をより迅速に再確立できるようにしました。以前はデフォルトで毎分起動する task があったため、table がその程度の時間、readonly 状態になる可能性がありました。[#41092](https://github.com/ClickHouse/ClickHouse/pull/41092) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* WindowTransform/arratReduce*/initializeAggregation/aggregate functions のバージョニングで、すべての集約関数コンビネータの組み合わせをサポートしました。以前は `ForEach/Resample/Map` のような combinators はこれらの箇所で動作せず、使用すると `State function ... inserts results into non-state column` のような例外が発生していました。[#41107](https://github.com/ClickHouse/ClickHouse/pull/41107) ([Kruglov Pavel](https://github.com/Avogar)).
* projections がゼロコピー レプリケーションで使用できるようになりました。[#41147](https://github.com/ClickHouse/ClickHouse/pull/41147) ([alesapin](https://github.com/alesapin)).
* * 復号に失敗した場合 (例: 誤った秘密鍵で復号した場合) に、例外をスローする代わりに NULL を返す関数 `tryDecrypt` を追加しました。 [#41206](https://github.com/ClickHouse/ClickHouse/pull/41206) ([Duc Canh Le](https://github.com/canhld94)).
* ディスクごとに、予約で確保されていない空き容量を確認できるよう、`system.disks` テーブルに `unreserved_space` カラムを追加しました。[#41254](https://github.com/ClickHouse/ClickHouse/pull/41254) ([filimonov](https://github.com/filimonov)).
* ast argument からの S3 認証ヘッダーをサポートしました。[#41261](https://github.com/ClickHouse/ClickHouse/pull/41261) ([Kseniia Sumarokova](https://github.com/kssenii)).
* &#39;IDENTIFIED WITH no&#95;password&#39; が明示的に指定されない限り、パスワードなしのユーザーを作成できないようにする設定 &#39;allow&#95;implicit&#95;no&#95;password&#39; を追加しました。[#41341](https://github.com/ClickHouse/ClickHouse/pull/41341) ([Nikolay Degterinsky](https://github.com/evillique)).
* keeper-improvement: スナップショットを S3 にアップロードする機能を追加しました。S3 の情報は `keeper_server.s3_snapshot` 内で定義できます。[#41342](https://github.com/ClickHouse/ClickHouse/pull/41342) ([Antonio Andelic](https://github.com/antonio2368)).
* Keeper と内部 ZooKeeper client で MultiRead をサポートしました。[#41410](https://github.com/ClickHouse/ClickHouse/pull/41410) ([Antonio Andelic](https://github.com/antonio2368)).
* IN Operator で、Decimal 型と浮動小数点 literal の比較をサポートしました。[#41544](https://github.com/ClickHouse/ClickHouse/pull/41544) ([liang.huang](https://github.com/lhuang09287750)).
* cache config で Readable size の値を使用できるようにしました。[#41688](https://github.com/ClickHouse/ClickHouse/pull/41688) ([Kseniia Sumarokova](https://github.com/kssenii)).
* input format 用の error ロガーで、パストラバーサル攻撃を防ぐため file path を検証するようにしました。[#41694](https://github.com/ClickHouse/ClickHouse/pull/41694) ([Kruglov Pavel](https://github.com/Avogar)).
* ClickHouse では、cache が非同期に更新されるまでの一定期間 (デフォルトでは 15 Seconds) 、古い DNS エントリが cache されることがありました。この間も ClickHouse は connection の確立を試み、error が発生する可能性がありました。この挙動を修正しました。[#41707](https://github.com/ClickHouse/ClickHouse/pull/41707) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `clickhouse-client`/`clickhouse-local` に、fzf 系ユーティリティ (fzf/sk) を使った対話的な history 検索を追加しました (`FZF_DEFAULT_OPTS`/`SKIM_DEFAULT_OPTIONS` を使って動作を追加で設定することもできます) 。[#41730](https://github.com/ClickHouse/ClickHouse/pull/41730) ([Azat Khuzhin](https://github.com/azat)).
* client が無効な certificate を持つ secure server に接続する場合は、&#39;--accept-certificate&#39; flag を指定したときのみ続行できるようにしました。[#41743](https://github.com/ClickHouse/ClickHouse/pull/41743) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* 既存の関数 &quot;tryBase64Decode()&quot; と同様の関数 &quot;tryBase58Decode()&quot; を追加しました。[#41824](https://github.com/ClickHouse/ClickHouse/pull/41824) ([Robert Schulze](https://github.com/rschu1ze)).
* 異なる主キーを持つパーティションを置き換える際のフィードバックを改善しました。[#34798](https://github.com/ClickHouse/ClickHouse/issues/34798) を修正しました。[#41838](https://github.com/ClickHouse/ClickHouse/pull/41838) ([Salvatore](https://github.com/tbsal)).
* `/etc/security/limits.conf` の制限を反映させるため、起動時の `clickhouse su` コマンドを `sudo -u` に戻しました。[#41847](https://github.com/ClickHouse/ClickHouse/pull/41847) ([Eugene Konkov](https://github.com/ekonkov)).
* 並列パースを修正し、segmentator が max&#95;block&#95;size をチェックするようにしました。[#41852](https://github.com/ClickHouse/ClickHouse/pull/41852) ([Vitaly Baranov](https://github.com/vitlibar)).
* テーブルが削除された直後だった場合にそのテーブルをスキップできるよう、TABLE&#95;IS&#95;DROPPED Exception を報告しないようにしました。[#41908](https://github.com/ClickHouse/ClickHouse/pull/41908) ([AlfVII](https://github.com/AlfVII)).
* オプション enable&#95;extended&#95;results&#95;for&#95;datetime&#95;functions を改善し、toStartOfDay、toStartOfHour、toStartOfFifteenMinutes、toStartOfTenMinutes、toStartOfFiveMinutes、toStartOfMinute、timeSlot 関数が DateTime64 型の結果を返せるようにしました。[#41910](https://github.com/ClickHouse/ClickHouse/pull/41910) ([Roman Vasin](https://github.com/rvasin)).
* テキストフォーマットにおける DateTime の型推論を改善しました。これにより、setting `date_time_input_format` が尊重されるようになり、数値を timestamp として DateTime 型に推論しようとしなくなりました。[#41389](https://github.com/ClickHouse/ClickHouse/issues/41389) をクローズしました。[#42206](https://github.com/ClickHouse/ClickHouse/issues/42206) をクローズしました。[#41912](https://github.com/ClickHouse/ClickHouse/pull/41912) ([Kruglov Pavel](https://github.com/Avogar)).
* `perform_ttl_move_on_insert`=false で insert する際の紛らわしい警告を削除しました。[#41980](https://github.com/ClickHouse/ClickHouse/pull/41980) ([Vitaly Baranov](https://github.com/vitlibar)).
* `count(*)` と同様に、ユーザーが `countState(*)` を記述できるようにしました。これにより [#9338](https://github.com/ClickHouse/ClickHouse/issues/9338) をクローズしました。[#41983](https://github.com/ClickHouse/ClickHouse/pull/41983) ([Amos Bird](https://github.com/amosbird)).
* * rankCorr のサイズオーバーフローを修正しました。 [#42020](https://github.com/ClickHouse/ClickHouse/pull/42020) ([Duc Canh Le](https://github.com/canhld94)).
* Sentry の config で、より便利なレポートのために、環境名として任意の文字列を指定できるオプションを追加しました。 [#42037](https://github.com/ClickHouse/ClickHouse/pull/42037) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* system table `asynchronous_insert_log ` を追加しました。これには、内部状態をより詳しく確認できるよう、非同期挿入に関する情報 (`wait_for_async_insert=0` を指定した fire-and-forget モードでの queries の結果を含む) が含まれます。 [#42040](https://github.com/ClickHouse/ClickHouse/pull/42040) ([Anton Popov](https://github.com/CurtizJ)).
* CSV から範囲外の Date をパースする際の問題を修正しました。 [#42044](https://github.com/ClickHouse/ClickHouse/pull/42044) ([Andrey Zvonov](https://github.com/zvonand)).
* parseDataTimeBestEffort が、日付と時刻の間のカンマをサポートするようになりました。 [#42038](https://github.com/ClickHouse/ClickHouse/issues/42038) をクローズします。 [#42049](https://github.com/ClickHouse/ClickHouse/pull/42049) ([flynn](https://github.com/ucasfl)).
* &#39;Accept-Encoding&#39; で lz4、bz2、snappy の各方式をサポートしました。 [#42071](https://github.com/ClickHouse/ClickHouse/pull/42071) ([Nikolay Degterinsky](https://github.com/evillique)).
* BLAKE3 関数に関する軽微な修正を複数行いました。 [#42073](https://github.com/ClickHouse/ClickHouse/pull/42073) ([BoloniniD](https://github.com/BoloniniD)).
* `ReplicatedMergeTree` の stale replica の復旧プロセスを改善しました。失われたレプリカに正常なレプリカには存在しないパーツがあっても、そのパーツが正常なレプリカの replication queue に従って今後現れるはずであれば、失われたレプリカはそれらのパーツを detach せずに保持します。 [#42134](https://github.com/ClickHouse/ClickHouse/pull/42134) ([Alexander Tokmakov](https://github.com/tavplubix)).
* S3 への BACKUP で、パスやデータ structure をそのまま使用できるようにしました。 [#42232](https://github.com/ClickHouse/ClickHouse/pull/42232) ([Azat Khuzhin](https://github.com/azat)).
* date&#95;diff 関数で Date32 arguments を使用できるようにしました。また、開始日が Unix epoch より前で終了日が Unix epoch より後の DateTime64 arguments を使用した場合の date&#95;diff 関数の問題も修正しました。 [#42308](https://github.com/ClickHouse/ClickHouse/pull/42308) ([Roman Vasin](https://github.com/rvasin)).
* 大きなパーツを minio に upload する際、&#39;Complete Multipart Upload&#39; に時間がかかることがあります。Minio は 10 秒ごとに heartbeat を送信します ([https://github.com/minio/minio/pull/7198](https://github.com/minio/minio/pull/7198) を参照) 。しかし clickhouse はそれより早く timeout します。これは、デフォルトの送受信 timeout が 5 秒に [set](https://github.com/ClickHouse/ClickHouse/blob/cc24fcd6d5dfb67f5f66f5483e986bd1010ad9cf/src/IO/S3/PocoHTTPClient.cpp#L123) されているためです。 [#42321](https://github.com/ClickHouse/ClickHouse/pull/42321) ([filimonov](https://github.com/filimonov)).
* backups の宛先の新しい type として `S3` を追加しました。 [#42333](https://github.com/ClickHouse/ClickHouse/pull/42333) ([Vitaly Baranov](https://github.com/vitlibar)).
* Decimal のような複雑な types を持つ aggregate state types で、まれに発生する無効な cast を修正しました。これにより [#42408](https://github.com/ClickHouse/ClickHouse/issues/42408) が修正されます。 [#42417](https://github.com/ClickHouse/ClickHouse/pull/42417) ([Amos Bird](https://github.com/amosbird)).
