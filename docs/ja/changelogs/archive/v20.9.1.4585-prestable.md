  ### ClickHouse リリース v20.9.1.4585-prestable FIXME (v20.8.1.4513-prestable との比較)
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* バックグラウンドプールおよびレプリケーションキュー内の有効期限 (TTL) 付きマージ数を制御するため、MergeTree settings (`max_replicated_merges_with_ttl_in_queue` および `max_number_of_merges_with_ttl_in_pool`) が追加されました。この変更が古いバージョンとの互換性を損なうのは、delete TTL を使用している場合のみです。それ以外では、レプリケーションの互換性は維持されます。すべての分片レプリカを一度に更新するか、すべてのレプリカの更新が完了するまで `SYSTEM STOP TTL MERGES` を実行することで、非互換性の問題を回避できます。レプリケーションキューに非互換のエントリが入ってしまった場合は、まず `SYSTEM STOP TTL MERGES` を実行し、その後、非互換な有効期限 (TTL) マージが割り当てられたパーティションに対して `ALTER TABLE ... DETACH PARTITION ...` を実行してください。続いて、そのパーティションを単一のレプリカに再度アタッチしてください。 [#14490](https://github.com/ClickHouse/ClickHouse/pull/14490) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### 新機能
</div>

* サブクエリをテーブルオブジェクトに変換するテーブル関数 `view` を追加しました。これにより、クエリを受け渡ししやすくなります。たとえば、remote/cluster テーブル関数で利用できます。[#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* `select * apply(length) apply(max) from wide_string_table` と書くことで、すべての String 型のカラムの最大長を調べられるようになりました。さらに、次の 2 つのバリアントも利用できます。 [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* `system.query_log` および `system.query_thread_log` テーブルに `query_start_time_microseconds` フィールドを追加しました。[#14252](https://github.com/ClickHouse/ClickHouse/pull/14252) ([Bharat Nallan](https://github.com/bharatnc)).
* 順位相関係数を単純に計算する集約関数 RankCorrelationSpearman を追加しました。[#11769](https://github.com/ClickHouse/ClickHouse/issues/11769) の続きです。[#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* クエリユーティリティによるデータベース生成機能を追加しました。[#10973](https://github.com/ClickHouse/ClickHouse/issues/10973) の続きです。[#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `optimize_skip_unused_shards` および `optimize_distributed_group_by_sharding_key` 有効時に、`sharding_key` で GROUP BY する Distributed に対する LIMIT/LIMIT BY/ORDER BY を含むクエリを最適化しました。 [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### 改善
</div>

* StorageRabbitMQ を改善しました。connection と channels の障害処理、適切な commit、insert 失敗時の処理、exchange の改善、queue の永続化と再開機能、新しい queue 設定を追加しました。テストも修正しました。 [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Redis の requirepass 認証を追加しました。 [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* DateTime 型に精度 argument を追加しました。 [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* 各 consumer に独立した thread を割り当てることで、Kafka エンジンの性能を改善しました。ストリーミングエンジン (Kafka など) 用に個別の thread pool も追加しました。 [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* `system.part_log` に、パーツのデフォルトの圧縮 codec を表す `default_compression_codec` を追加しました。 [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* boost multiprecision の wide 整数を、[https://github.com/cerevra/int](https://github.com/cerevra/int) の実装に置き換えました。 [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* MaterializeMySQL で、主キーを暗黙的に Not null に変換するようにしました (MySQL と同様) 。 [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114) を修正しました。 [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384) で提案された新しい設定 system&#95;events&#95;show&#95;zero&#95;values を追加しました。 [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* obfuscator が、[#13163](https://github.com/ClickHouse/ClickHouse/issues/13163) で提案された UUID 型をサポートするようになりました。 [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* 複数の `JOIN` と `IN` に対する Set の作成を並列に行うようにしました。これにより、複数の異なる `IN subquery` expression を含むクエリの性能がわずかに向上する可能性があります。 [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* これまで materialized されていなかった 有効期限 (TTL) は、マージ中に適用されるようになりました。 [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* MySQL ハンドラーは、`SET @@var = value` のようなクエリに対して `OK` を返すようになりました。このようなステートメントは無視されます。これは、一部の MySQL ドライバーが handshake 後の setup のために `SET @@` クエリを送信するため必要です [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422 。 [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* 進行中の S3 requests がある場合の server のシャットダウン処理を高速化しました。 [#14496](https://github.com/ClickHouse/ClickHouse/pull/14496) ([Pavel Kovalenko](https://github.com/Jokser)).
* `toStartOf*` 系の関数で、空の time&#95;zone argument を禁止しました。 [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* ConfigProcessor で、file path の連結に std::filesystem::path を使用するようにしました。 [#14558](https://github.com/ClickHouse/ClickHouse/pull/14558) ([Bharat Nallan](https://github.com/bharatnc)).

<div id="bug-fix">
  #### バグ修正
</div>

* lambda での arrayJoin() のキャプチャを修正しました (LOGICAL&#95;ERROR) 。[#13792](https://github.com/ClickHouse/ClickHouse/pull/13792) ([Azat Khuzhin](https://github.com/azat)).
* グローバルではない Level で実行した場合の GRANT ALL ステートメントを修正しました。[#13987](https://github.com/ClickHouse/ClickHouse/pull/13987) ([Vitaly Baranov](https://github.com/vitlibar)).
* `ALIAS` column type での `CODEC` を禁止しました。[#13911](https://github.com/ClickHouse/ClickHouse/issues/13911) を修正しています。[#14263](https://github.com/ClickHouse/ClickHouse/pull/14263) ([Bharat Nallan](https://github.com/bharatnc)).
* SSD cache の複合 key external dictionaries における tuple サイズのチェックを改善しました。これにより [#13981](https://github.com/ClickHouse/ClickHouse/issues/13981) を修正しています。[#14313](https://github.com/ClickHouse/ClickHouse/pull/14313) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ネストされた interpreter を含むクエリにおける QueryPlan の lifetime (EXPLAIN PIPELINE graph=1 用) を修正しました。[#14315](https://github.com/ClickHouse/ClickHouse/pull/14315) ([Azat Khuzhin](https://github.com/azat)).
* REFRESH コマンドを伴う ALTER LIVE VIEW クエリ中に発生する例外を修正しました。[#14320](https://github.com/ClickHouse/ClickHouse/pull/14320) ([Bharat Nallan](https://github.com/bharatnc)).
* `AS table_function` で作成された table に対する `ALTER` クエリ実行中のクラッシュを修正しました。[#14212](https://github.com/ClickHouse/ClickHouse/issues/14212) を修正しています。[#14326](https://github.com/ClickHouse/ClickHouse/pull/14326) ([alesapin](https://github.com/alesapin)).
* `PipelineExecutor` 自体で例外が発生した場合、クエリの実行を停止するようにしました。これにより、まれに発生するクエリのハングを防止できる可能性があります。[#14334](https://github.com/ClickHouse/ClickHouse/pull/14334) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* `PipelineExecutor` 自体で例外が発生した場合、クエリの実行を停止するようにしました。これにより、まれに発生するクエリのハングを防止できる可能性があります。[#14334](https://github.com/ClickHouse/ClickHouse/issues/14334) の続きです。[#14402](https://github.com/ClickHouse/ClickHouse/pull/14402) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* table に単一の part しかないパーティションがある場合に、マージ の割り当てが誤るバグを修正しました。[#14444](https://github.com/ClickHouse/ClickHouse/pull/14444) ([alesapin](https://github.com/alesapin)).
* SysVinit の proxy restart/start/stop/reload を systemd に対応させました (systemd が使用されている場合) 。[#14460](https://github.com/ClickHouse/ClickHouse/pull/14460) ([Azat Khuzhin](https://github.com/azat)).
* `topK` 集約関数 における配列サイズの overflow チェックを追加しました。このチェックがないと、ユーザーが細工した parameter を持つクエリを送信し、server crash を引き起こす可能性があります。これにより [#14452](https://github.com/ClickHouse/ClickHouse/issues/14452) をクローズします。[#14467](https://github.com/ClickHouse/ClickHouse/pull/14467) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
