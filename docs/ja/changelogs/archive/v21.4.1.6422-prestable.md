  ### ClickHouse リリース v21.4.1.6422-prestable FIXME (v21.3.1.6185-prestable との比較)

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `ALTER TABLE ATTACH PART[ITION]` コマンドを処理するレプリカは、他のレプリカからデータをフェッチする前に `detached/` フォルダ内を検索するようになりました。実装上の詳細として、replicated log に新しいコマンド `ATTACH_PART` が導入されています。パーツはチェックサムで検索および比較されます。[#18978](https://github.com/ClickHouse/ClickHouse/pull/18978) ([Mike Kot](https://github.com/myrrc)).
* table `system.dictionaries` のカラム `keys` は、`key.names` および `key.types` に置き換えられました。また、table `system.dictionaries` のカラム `key.names`、`key.types`、`attribute.names`、`attribute.types` は、Dictionary をロードしていなくても参照できます。[#21884](https://github.com/ClickHouse/ClickHouse/pull/21884) ([Maksim Kita](https://github.com/kitaisreal)).
* `cutToFirstSignificantSubdomainCustom()` / `firstSignificantSubdomainCustom()` が、カスタム top-level domain リストに含まれる 3 階層以上のドメインに対して誤った結果を返す問題を修正しました。これらのカスタム top-level domain に一致する入力ドメインでは、第 3 レベルのドメインが最初の有意なドメインと見なされていました。現在は修正されています。この変更により、たとえばこの関数を分片キーで使用している場合、互換性の問題が生じる可能性があります。[#21946](https://github.com/ClickHouse/ClickHouse/pull/21946) ([Azat Khuzhin](https://github.com/azat)).
* `toStartOfIntervalFunction` は、時間インターバルを深夜に揃えるようになります (以前のバージョンでは Unix epoch の開始時点に揃えられていました) 。たとえば、`toStartOfInterval(x, INTERVAL 11 HOUR)` は各日を 3 つのインターバル、00:00:00..10:59:59、11:00:00..21:59:59、22:00:00..23:59:59 に分割します。この挙動のほうが実用上のニーズに適しています。これにより [#9510](https://github.com/ClickHouse/ClickHouse/issues/9510) はクローズされます。[#22060](https://github.com/ClickHouse/ClickHouse/pull/22060) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

  #### 新機能

* S3 ストレージ上の ReplicatedMergeTree 向けゼロコピー レプリケーション。 [#16240](https://github.com/ClickHouse/ClickHouse/pull/16240) ([ianton-ru](https://github.com/ianton-ru)).
* `RangeHashedDictionary` で `dictHas` 関数をサポート。 [#6680](https://github.com/ClickHouse/ClickHouse/issues/6680) を修正。 [#19816](https://github.com/ClickHouse/ClickHouse/pull/19816) ([Maksim Kita](https://github.com/kitaisreal)).

* レプリケーションに使用される HTTP 接続のタイムアウトを、他の HTTP タイムアウトとは独立してカスタマイズできるようにしました。 [#20088](https://github.com/ClickHouse/ClickHouse/pull/20088) ([nvartolomei](https://github.com/nvartolomei)).
* `ComplexKeyCache`、`SSDCache`、`SSDComplexKeyCache` dictionary に非同期更新を追加。`Cache`、`ComplexKeyCache`、`SSDCache`、`SSDComplexKeyCache` dictionary で Nullable 型をサポート。`dictGet`、`dictGetOrDefault` 関数で複数の属性を取得できるようにしました。 [#21517](https://github.com/ClickHouse/ClickHouse/issues/21517) を修正。 [#20595](https://github.com/ClickHouse/ClickHouse/pull/20595) ([Maksim Kita](https://github.com/kitaisreal)).
* `system.query_log` の対応するクエリについて、`query_kind` カラムに `Grant,` `Revoke`、`System` の値を追加 ... [#21102](https://github.com/ClickHouse/ClickHouse/pull/21102) ([Vasily Nemkov](https://github.com/Enmk)).
* 新しい SQL コマンド ALTER TABLE &#39;table&#95;name&#39; UNFREEZE [PARTITION &#39;part&#95;expr&#39;] WITH NAME &#39;backup&#95;name&#39; を追加。 [#21142](https://github.com/ClickHouse/ClickHouse/pull/21142) ([Pavel Kovalenko](https://github.com/Jokser)).
* `ExecutablePool` Dictionary ソースを追加。 [#14528](https://github.com/ClickHouse/ClickHouse/issues/14528) をクローズ。 [#21321](https://github.com/ClickHouse/ClickHouse/pull/21321) ([Maksim Kita](https://github.com/kitaisreal)).
* * IPv4 または IPv6 アドレスが指定された CIDR ネットワークプレフィックスに含まれるかどうかを判定する関数 `isIPAddressInRange` を追加しました。[#21329](https://github.com/ClickHouse/ClickHouse/pull/21329) ([PHO](https://github.com/depressed-pho)).
* `MergeTree*` エンジンに `_partition_id` 仮想カラムを追加しました。`_partition_id` によるパーティションのプルーニングが可能になりました。パーティション ID の文字列を計算する `partitionID()` 関数も追加しました。[#21401](https://github.com/ClickHouse/ClickHouse/pull/21401) ([Amos Bird](https://github.com/amosbird)).
* `system.clusters` に新しいカラム `slowdowns_count` を追加しました。hedged requests の使用時に、このレプリカの応答が遅かったため別のレプリカに切り替えた回数を表示します。また、`system.clusters` に `errors_count` の実際の値も表示するようにしました。[#21480](https://github.com/ClickHouse/ClickHouse/pull/21480) ([Kruglov Pavel](https://github.com/Avogar)).
* clickhouse-format に `--backslash` オプションを追加しました。これにより、整形済みクエリの各行末にバックスラッシュを追加できます。[#21494](https://github.com/ClickHouse/ClickHouse/pull/21494) ([flynn](https://github.com/ucasfl)).
* CREATE/ALTER USER コマンドに、新しいオプション句 GRANTEES を追加しました。[#21641](https://github.com/ClickHouse/ClickHouse/pull/21641) ([Vitaly Baranov](https://github.com/vitlibar)).
* `zookeeper-dump-tree` に `ctime` オプションを追加しました。これにより、node の作成時刻をダンプできます。[#21842](https://github.com/ClickHouse/ClickHouse/pull/21842) ([Ilya](https://github.com/HumanUser)).
* &#39;dictGet&#39;、&#39;dictHas&#39; 関数は、DDL で作成された Dictionary で database 名が指定されていない場合、current database 名を使用するようになりました。[#21632](https://github.com/ClickHouse/ClickHouse/issues/21632) をクローズしました。[#21859](https://github.com/ClickHouse/ClickHouse/pull/21859) ([Maksim Kita](https://github.com/kitaisreal)).
* `PolygonDictionary` の attribute で `Nullable` 型をサポートしました。[#21890](https://github.com/ClickHouse/ClickHouse/pull/21890) ([Maksim Kita](https://github.com/kitaisreal)).
* table function `dictionary` を追加しました。これは `Dictionary` エンジンと同じように動作します。[#21560](https://github.com/ClickHouse/ClickHouse/issues/21560) をクローズしました。[#21910](https://github.com/ClickHouse/ClickHouse/pull/21910) ([Maksim Kita](https://github.com/kitaisreal)).
* `DateTime` または `DateTime64` data types の timezone 名を返す `timezoneOf` 関数を追加しました。これは [#9959](https://github.com/ClickHouse/ClickHouse/issues/9959) をクローズするものではありません。あわせて関数名の不整合を修正し、別名 `timezone` と `timeZone`、`toTimezone` と `toTimeZone`、`timezoneOf` と `timeZoneOf` を追加しました。[#22001](https://github.com/ClickHouse/ClickHouse/pull/22001) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 別名ではなく元のカラム名を使用するための `prefer_column_name_to_alias` setting を追加しました。これは、一般的なデータベースのエイリアス規則との互換性を高めるために必要です。これは [#9715](https://github.com/ClickHouse/ClickHouse/issues/9715) および [#9887](https://github.com/ClickHouse/ClickHouse/issues/9887) に対応するものです。[#22044](https://github.com/ClickHouse/ClickHouse/pull/22044) ([Amos Bird](https://github.com/amosbird)).
* `dictGetHierarchy`、`dictIsIn` 関数の性能を改善しました。`dictGetChildren(dictionary, key)`、`dictGetDescendants(dictionary, key, level)` 関数も追加しました。`dictGetChildren` 関数は、すべての child を索引の Array として返します。これは `dictGetHierarchy` の逆変換です。`dictGetDescendants` 関数は、`dictGetChildren` を再帰的に `level` 回適用した場合と同様に、すべての子孫を返します。`level` の値が 0 の場合は無限大と同等です。[#14656](https://github.com/ClickHouse/ClickHouse/issues/14656) をクローズしました。[#22096](https://github.com/ClickHouse/ClickHouse/pull/22096) ([Maksim Kita](https://github.com/kitaisreal)).
* 関数 `dictGetOrNull` を追加しました。これは `dictGet` と同様に動作しますが、Dictionary 内でキーが見つからない場合は `NULL` を返します。[#22375](https://github.com/ClickHouse/ClickHouse/issues/22375) をクローズしました。[#22413](https://github.com/ClickHouse/ClickHouse/pull/22413) ([Maksim Kita](https://github.com/kitaisreal)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `CSVWithNames` および `TSVWithNames` フォーマットでの並列パースをサポートしました。これにより [#21085](https://github.com/ClickHouse/ClickHouse/issues/21085) をクローズします。 [#21149](https://github.com/ClickHouse/ClickHouse/pull/21149) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `memcpy` を別実装に置き換えることで、パフォーマンスを改善しました。これにより [#18583](https://github.com/ClickHouse/ClickHouse/issues/18583) をクローズします。 [#21520](https://github.com/ClickHouse/ClickHouse/pull/21520) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* clickhouse-local およびその他の箇所で、並列フォーマットをサポートしました。 [#21630](https://github.com/ClickHouse/ClickHouse/pull/21630) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `SELECT ... FINAL ... WHERE` のようなクエリのパフォーマンスを最適化しました。これにより、`FINAL` を含むクエリでは、sorting key に含まれるカラムを `PREWHERE` に移動できるようになりました。 ... [#21830](https://github.com/ClickHouse/ClickHouse/pull/21830) ([foolchi](https://github.com/foolchi)).
* `max_rows_to_group_by` が小さく、`group_by_overflow_mode='any'` の場合の `GROUP BY` を高速化しました。 [#21856](https://github.com/ClickHouse/ClickHouse/pull/21856) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* codec `NONE` 使用時の不要なデータコピーを回避しました。なお、codec `NONE` はほとんどの場合有用ではなく、常に圧縮 (デフォルトでは `LZ4`) を使用することを推奨します。一般に考えられているのとは異なり、圧縮を無効にしてもパフォーマンスが向上するとは限りません (逆効果になる可能性もあります) 。`NONE` codec が有用なのは、たとえば次のような場合です: - データを圧縮できない場合。- 合成ベンチマークの場合。 [#22145](https://github.com/ClickHouse/ClickHouse/pull/22145) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `min_bytes_to_use_mmap_io` setting で読み取るファイル向けの cache を追加しました。これにより、setting の値が小さい場合でも、頻繁な mmap/munmap 呼び出しとそれに伴うページフォールトを回避できるため、大幅な (2 倍以上の) パフォーマンス改善が得られます。なお、mmap I/O には、production では信頼性が低くなる大きな欠点があります (例: 障害のあるディスクでのハングや SIGBUS、制御しにくい memory usage) 。それでも、ベンチマークでは有効です。 [#22206](https://github.com/ClickHouse/ClickHouse/pull/22206) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 64 MiB 以上の file 範囲に対して mmap I/O による読み取りを有効にしました (setting `min_bytes_to_use_mmap_io`) 。中程度のパフォーマンス改善につながる可能性があります。 [#22326](https://github.com/ClickHouse/ClickHouse/pull/22326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* データ型 `Map` における整数キーのサポートを改善しました。[#21157](https://github.com/ClickHouse/ClickHouse/pull/21157) ([Anton Popov](https://github.com/CurtizJ)).
