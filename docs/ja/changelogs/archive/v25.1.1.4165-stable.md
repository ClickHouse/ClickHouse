  # 2025 変更履歴

<div id="clickhouse-release-v25114165-stable-8629bc54796-fixme-as-compared-to-v25111-new-204fd5b5431">
  ### ClickHouse リリース v25.1.1.4165-stable (8629bc54796) FIXME as compared to v25.1.1.1-new (204fd5b5431)
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* Parquet 出力フォーマットでは、Date および DateTime カラムは生の数値として書き込まれるのではなく、Parquet がサポートする date/time 型に変換されるようになりました。DateTime は DateTime64(3) になります (以前は UInt32) 。設定 `output_format_parquet_datetime_as_uint32` を使用すると、以前の動作に戻せます。Date は Date32 になります (以前は UInt16) 。 [#70950](https://github.com/ClickHouse/ClickHouse/pull/70950) ([Michael Kolupaev](https://github.com/al13n321)).
* デフォルトで、比較不可能な型 (JSON/Object/AggregateFunction など) は ORDER BY および比較関数 `less/greater/equal/etc` で使用できなくなりました。 [#73276](https://github.com/ClickHouse/ClickHouse/pull/73276) ([Pavel Kruglov](https://github.com/Avogar)).
* `JSONEachRowWithProgress` は、進捗が発生するたびに進捗を書き出すようになります。以前のバージョンでは、進捗は結果の各 block の後でしか表示されず、実用的ではありませんでした。進捗の表示方法も変更され、値が 0 の場合は表示されません。進捗は頻繁に発生する場合でも送信される点に注意してください。そのため、大量のトラフィックが発生する可能性があります。また、出力が compressed の場合、進捗は flush されない点にも注意してください。これにより [#70800](https://github.com/ClickHouse/ClickHouse/issues/70800) がクローズされます。 [#73834](https://github.com/ClickHouse/ClickHouse/pull/73834) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 廃止された `MaterializedMySQL` データベースエンジンは削除され、利用できなくなりました。 [#73879](https://github.com/ClickHouse/ClickHouse/pull/73879) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `mysql` Dictionary ソースは、`SHOW TABLE STATUS` クエリを実行しなくなりました。これは、InnoDB テーブルでは、少なくとも最近の MySQL バージョンにおいては何の値も提供しないためです。これにより [#72636](https://github.com/ClickHouse/ClickHouse/issues/72636) がクローズされます。この変更自体は後方互換性がありますが、見落とされないようこのカテゴリに含めています。 [#73914](https://github.com/ClickHouse/ClickHouse/pull/73914) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `Merge` テーブルは、基になるテーブルのカラムのユニオンを使用し、共通の型を導出することで、それらの構造を統一するようになります。これにより [#64864](https://github.com/ClickHouse/ClickHouse/issues/64864) がクローズされます。状況によっては、この変更が後方互換性を損なう可能性があります。たとえば、テーブル間に共通の型は存在しないものの、UInt64 と Int64、または任意の数値型と String のように、最初のテーブルの型への変換は依然として可能な場合です。以前の動作に戻したい場合は、`merge_table_max_tables_to_look_for_schema_inference` を `1` に設定するか、`compatibility` を `24.12` 以前に設定してください。 [#73956](https://github.com/ClickHouse/ClickHouse/pull/73956) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `CHECK TABLE` クエリでは、個別の `CHECK` grant が必要になりました。以前のバージョンでは、これらのクエリを実行するには `SHOW TABLES` grant があれば十分でした。しかし、`CHECK TABLE` クエリは高負荷になる可能性があり、`SELECT` クエリに対する通常の query complexity 制限も適用されません。そのため、DoS の可能性がありました。 [#74471](https://github.com/ClickHouse/ClickHouse/pull/74471) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 関数 `h3ToGeo()` は、結果を `(lat, lon)` の順序 (幾何関数における標準的な順序) で返すようになりました。従来の結果順序 `(lon, lat)` を維持したい場合は、設定 `h3togeo_lon_lat_result_order = true` を使用できます。 [#74719](https://github.com/ClickHouse/ClickHouse/pull/74719) ([Manish Gill](https://github.com/mgill25)).



<div id="new-feature">
  #### 新機能
</div>

* SSH インターフェイスが追加されました。これにより、任意の SSH クライアントを使用して ClickHouse server に接続し、埋め込みの `clickhouse-client` を使って PTY 上で対話的にクエリを実行できるようになりました。[#48902](https://github.com/ClickHouse/ClickHouse/pull/48902) ([George Gamezardashvili](https://github.com/InfJoker)).
* デシリアライズされたスキッピング索引のインデックスグラニュール向けに in-memory cache が追加されました。これにより、スキッピング索引を使う繰り返し実行されるクエリが高速化されるはずです。新しい cache のサイズは、server settings `skipping_index_cache_size` および `skipping_index_cache_max_entries` で制御されます。もともとこの cache の主な目的はベクトル類似度索引の高速化で、これにより大幅に性能が向上しました。[#70102](https://github.com/ClickHouse/ClickHouse/pull/70102) ([Robert Schulze](https://github.com/rschu1ze)).
* Iceberg における時間関連の transform パーティション操作に対する Iceberg table のパーティション pruning を実装しました。[#72044](https://github.com/ClickHouse/ClickHouse/pull/72044) ([Daniil Ivanik](https://github.com/divanik)).
* `enable_minmax_index_for_all_numeric_columns` (数値カラム向け) および `enable_minmax_index_for_all_string_columns` (String 型のカラム向け) 設定により、MergeTree が管理するカラムに対して既定で min-max (スキッピング) 索引を作成する機能を追加しました。現時点では両方の設定が無効になっているため、まだ動作の変更はありません。[#72090](https://github.com/ClickHouse/ClickHouse/pull/72090) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* pattern 内で最長のイベントチェーンに一致したイベントの timestamps を返す集約関数 `sequenceMatchEvents` を追加しました。[#72349](https://github.com/ClickHouse/ClickHouse/pull/72349) ([UnamedRus](https://github.com/UnamedRus)).
* `SELECT` 文および `VIEW` 文で別名がサポートされるようになりました。たとえば `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);` のように使用できます。これにより、TPC-H query 15 を変更せずに実行できます。[#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 関数 `arrayNormalizedGini` を追加しました。[#72823](https://github.com/ClickHouse/ClickHouse/pull/72823) ([flynn](https://github.com/ucasfl)).
* `min_age_to_force_merge_seconds` と `min_age_to_force_merge_on_partition_only` の両方が有効な場合、パーツマージは最大バイト数の制限を無視します。[#73656](https://github.com/ClickHouse/ClickHouse/pull/73656) ([Kai Zhu](https://github.com/nauu)).
* Apache Arrow/Parquet/ORC から HALF&#95;FLOAT 値を読み取れるようになりました (Float32 として読み込まれます) 。これにより [#72960](https://github.com/ClickHouse/ClickHouse/issues/72960) がクローズされます。IEEE-754 half float は BFloat16 と同じではない点に注意してください。あわせて [#73835](https://github.com/ClickHouse/ClickHouse/issues/73835) もクローズされます。[#73836](https://github.com/ClickHouse/ClickHouse/pull/73836) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `system.trace_log` テーブルに、シンボル化された stack trace を含む 2 つの新しいカラム `symbols` と `lines` が追加されます。これにより、プロファイル情報の収集とエクスポートが容易になります。これは `trace_log` 内の server configuration 値 `symbolize` によって制御され、既定で有効です。[#73896](https://github.com/ClickHouse/ClickHouse/pull/73896) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* テーブル内で自動増分番号を生成するために使用できる新しい関数 `generateSerialID` を追加しました。これは [#64310](https://github.com/ClickHouse/ClickHouse/issues/64310) の継続で、[kazalika](https://github.com/kazalika) によるものです。これにより [#62485](https://github.com/ClickHouse/ClickHouse/issues/62485) がクローズされます。[#73950](https://github.com/ClickHouse/ClickHouse/pull/73950) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 構文 `query1 PARALLEL WITH query2 PARALLEL WITH query3 ... PARALLEL WITH queryN` を追加しました。これにより、サブクエリ `{query1, query2, ... queryN}` を互いに並列に実行できるようになります (しかも、それが推奨されます) 。[#73983](https://github.com/ClickHouse/ClickHouse/pull/73983) ([Vitaly Baranov](https://github.com/vitlibar)).
* Play UI で、クエリ実行中に進捗バーが表示されるようになりました。これによりクエリをキャンセルできます。レコード総数と速度に関する詳細情報も表示されます。テーブルは、データが到着し次第インクリメンタルに描画できます。HTTP 圧縮を有効にしました。テーブル描画も高速化されました。テーブルヘッダーは sticky になりました。セルを選択し、矢印キーで移動できます。選択したセルの枠線によってセルが小さく見える問題を修正しました。セルはマウスホバーでは拡大せず、選択時のみ拡大するようになりました。受信中データの描画をいつ止めるかは、サーバー側ではなくクライアント側で判断されます。数値の桁区切りを強調表示します。全体的なデザインも刷新し、より力強いものになりました。サーバーに到達可能かどうか、認証情報が正しいかどうかを確認し、サーバーのバージョンと稼働時間を表示します。Cloud アイコンは、Safari を含むすべてのフォントで輪郭付きで表示されます。ネストされたデータ型内の大きな整数も、より適切に描画されます。inf/nan も正しく表示されます。マウスをカラムヘッダーに重ねるとデータ型が表示されます。[#74204](https://github.com/ClickHouse/ClickHouse/pull/74204) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `add_minmax_index_for_numeric_columns` (数値カラム用) および `add_minmax_index_for_string_columns` (String 型のカラム用) 設定を使って、MergeTree によって管理されるカラムに対して、デフォルトで min-max (skipping) 索引を作成する機能を追加しました。現時点では両方の設定は無効のため、動作に変更はありません。[#74266](https://github.com/ClickHouse/ClickHouse/pull/74266) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* `system.query_log`、ネイティブプロトコルの ClientInfo、および server logs に `script_query_number` と `script_line_number` フィールドを追加しました。これにより [#67542](https://github.com/ClickHouse/ClickHouse/issues/67542) はクローズされます。この機能のきっかけとなった提案を以前 [#68133](https://github.com/ClickHouse/ClickHouse/issues/68133) で行った [pinsvin00](https://github.com/pinsvin00) に謝意を表します。[#74477](https://github.com/ClickHouse/ClickHouse/pull/74477) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* DateTime64 の減算演算子をサポートし、DateTime64 値同士の減算に加えて、DateTime との減算も可能にしました。[#74482](https://github.com/ClickHouse/ClickHouse/pull/74482) ([Li Yin](https://github.com/liyinsg)).
* [#75020](https://github.com/ClickHouse/ClickHouse/issues/75020) でバックポート: 未完了の (バックグラウンドプロセスでまだマテリアライズされていない) mutations を、`SELECT` クエリの送信直後の実行中に即座に適用できるようにしました。これは `apply_mutations_on_fly` を設定することで有効にできます。[#74877](https://github.com/ClickHouse/ClickHouse/pull/74877) ([Anton Popov](https://github.com/CurtizJ)).





<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* 最も不一致である可能性が高いカラムから先に行を比較するようにしました。[#63780](https://github.com/ClickHouse/ClickHouse/pull/63780) ([UnamedRus](https://github.com/UnamedRus)).
* RowBinary input format を最適化しました。[#63805](https://github.com/ClickHouse/ClickHouse/issues/63805) をクローズします。[#65059](https://github.com/ClickHouse/ClickHouse/pull/65059) ([Pavel Kruglov](https://github.com/Avogar)).
* 低レベルの最適化により、文字列のデシリアライゼーションを高速化しました。[#65948](https://github.com/ClickHouse/ClickHouse/pull/65948) ([Nikita Taranov](https://github.com/nickitat)).
* 右側の結合テーブルをオプションで再配置することで、Grace Hash Join のパフォーマンスを改善しました。[#72237](https://github.com/ClickHouse/ClickHouse/pull/72237) ([kevinyhzou](https://github.com/KevinyhZou)).
* `arrayROCAUC` と `arrayAUCPR` で曲線全体の部分領域を計算できるようにし、大規模なデータセットに対してその計算を並列化できるようにしました。[#72904](https://github.com/ClickHouse/ClickHouse/pull/72904) ([Emmanuel](https://github.com/emmanuelsdias)).
* アイドル状態のスレッドを過剰に生成しないようにしました。[#72920](https://github.com/ClickHouse/ClickHouse/pull/72920) ([Guo Wangyang](https://github.com/guowangy)).
* `parallel_hash` JOIN algorithm の probe phase から、ハッシュによる左テーブルのブロック分割を削除しました。[#73089](https://github.com/ClickHouse/ClickHouse/pull/73089) ([Nikita Taranov](https://github.com/nickitat)).
* table function で波かっこ展開しか使用していない場合、ブロブストレージのキーを列挙しないようにしました。[#73333](https://github.com/ClickHouse/ClickHouse/issues/73333) をクローズします。[#73518](https://github.com/ClickHouse/ClickHouse/pull/73518) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 「Nullable arguments 上で実行される functions の short circuit optimization の Revert の Revert」を取り消しました。すべての argument type が数値型である functions 向けの高速パスを追加しました。https://github.com/ClickHouse/ClickHouse/pull/72258 のパフォーマンス問題を修正しました。[#73820](https://github.com/ClickHouse/ClickHouse/pull/73820) ([李扬](https://github.com/taiyang-li)).
* 関数ではないカラムには `maskedExecute` を適用しないようにし、short circuit execution のパフォーマンスを改善しました。[#73965](https://github.com/ClickHouse/ClickHouse/pull/73965) ([lgbo](https://github.com/lgbo-ustc)).
* パフォーマンス向上のため、Kafka/NATS/RabbitMQ/FileLog の header 検出を無効にしました。[#74006](https://github.com/ClickHouse/ClickHouse/pull/74006) ([Azat Khuzhin](https://github.com/azat)).
* log wrappers を値として扱い、ヒープに割り当てないようにしました。[#74034](https://github.com/ClickHouse/ClickHouse/pull/74034) ([Mikhail Artemenko](https://github.com/Michicosun)).
* grouping sets による集約後、より高い並列度で pipeline を実行するようにしました。[#74082](https://github.com/ClickHouse/ClickHouse/pull/74082) ([Nikita Taranov](https://github.com/nickitat)).
* `MergeTreeReadPool` のクリティカルセクションを短縮しました。[#74202](https://github.com/ClickHouse/ClickHouse/pull/74202) ([Guo Wangyang](https://github.com/guowangy)).
* 関数 `indexHint` を最適化しました。これにより、関数 `indexHint` の argument としてのみ使用されるカラムは、table から読み込まれなくなりました。[#74314](https://github.com/ClickHouse/ClickHouse/pull/74314) ([Anton Popov](https://github.com/CurtizJ)).
* 並列レプリカのパフォーマンス改善。並列レプリカのプロトコルに関係しないパケットについては、クエリ イニシエーターでのパケットのデシリアライゼーションが常に pipeline thread で行われるようになりました。以前は pipeline の scheduling を担当する thread で行われることがあり、その結果、イニシエーターの応答性が低下し、pipeline の実行が遅れる可能性がありました。[#74398](https://github.com/ClickHouse/ClickHouse/pull/74398) ([Igor Nikonov](https://github.com/devcrafter)).
* [#75069](https://github.com/ClickHouse/ClickHouse/issues/75069)でバックポート: `LowCardinality` カラムのメモリ内のサイズ計算を修正しました。[#74688](https://github.com/ClickHouse/ClickHouse/pull/74688) ([Nikita Taranov](https://github.com/nickitat)).





<div id="improvement">
  #### 改善
</div>

* `ConstantNode` で `Field` の代わりに `ColumnPtr` を保持することで、新しいアナライザ インフラストラクチャのパフォーマンスを改善しました。[#62245](https://github.com/ClickHouse/ClickHouse/issues/62245) に関連します。[#63198](https://github.com/ClickHouse/ClickHouse/pull/63198) ([Dmitry Novik](https://github.com/novikd))。
* DateTime64 型のカラムに対して bloom&#95;filter インデックスを作成できるようにしました。[#66416](https://github.com/ClickHouse/ClickHouse/pull/66416) ([Yutong Xiao](https://github.com/YutSean))。
* トレーサビリティ向上のため、OpenTelemetry span logs テーブルに HTTP headers を追加しました。[#70516](https://github.com/ClickHouse/ClickHouse/pull/70516) ([jonymohajanGmail](https://github.com/jonymohajanGmail))。
* orc ファイルの書き込みで、常に `GMT` time zone を使うのではなく、任意の time zone を使えるようにしました。[#70615](https://github.com/ClickHouse/ClickHouse/pull/70615) ([kevinyhzou](https://github.com/KevinyhZou))。
* クラウド間で backups を書き込む際に、I/O scheduling の設定を反映するようにしました。[#71093](https://github.com/ClickHouse/ClickHouse/pull/71093) ([János Benjamin Antal](https://github.com/antaljanosbenjamin))。
* 対応する Dictionary への requests を遅らせないよう、MySQL および Postgres の Dictionary レプリカへの connection をバックグラウンドで再確立するようにしました。[#71101](https://github.com/ClickHouse/ClickHouse/pull/71101) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* system.asynchronous&#95;metrics に metric のエイリアス名を追加しました。[#71164](https://github.com/ClickHouse/ClickHouse/pull/71164) ([megao](https://github.com/jetgm))。
* インタラクティブ メトリクスを改善しました。並列レプリカからのメトリクスが完全に表示されない問題を修正しました。メトリクスは最新の更新順に表示し、同じ場合は名前の辞書順で表示します。古いメトリクスは表示しません。[#71631](https://github.com/ClickHouse/ClickHouse/pull/71631) ([Julia Kartseva](https://github.com/jkartseva))。
* 歴史的な経緯により、クエリ `ALTER TABLE MOVE PARTITION TO TABLE` では、専用の `ALTER_MOVE_PARTITION` ではなく、`SELECT` と `ALTER DELETE` の権限をチェックしていました。この PR では、このアクセス種別を使用するようにしました。互換性のため、`SELECT` と `ALTER DELETE` が granted されている場合は、この permission も暗黙的に granted されますが、この動作は future releases で削除されます。[#16403](https://github.com/ClickHouse/ClickHouse/issues/16403) をクローズします。[#71632](https://github.com/ClickHouse/ClickHouse/pull/71632) ([pufit](https://github.com/pufit))。
* `use_hive_partitioning` をデフォルトで有効にしました。[#71636](https://github.com/ClickHouse/ClickHouse/pull/71636) ([Yarik Briukhovetskyi](https://github.com/yariks5s))。
* ソート順が壊れるのを許容する代わりに、ソートキー内のカラムを materialize しようとした場合は exception を投げるようにしました。なお、[#71777](https://github.com/ClickHouse/ClickHouse/issues/71777) は未解決のままです。[#71891](https://github.com/ClickHouse/ClickHouse/pull/71891) ([Peter Nguyen](https://github.com/petern48))。
* ハッシュ結合 algorithm が有効な場合に、より汎用的な join planning algorithm を使用できるようにしました。[#71926](https://github.com/ClickHouse/ClickHouse/pull/71926) ([János Benjamin Antal](https://github.com/antaljanosbenjamin))。
* `EXPLAIN QUERY TREE` で secrets を隠すようにしました。[#72025](https://github.com/ClickHouse/ClickHouse/pull/72025) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* databases および tables の metadata files を保存するために、設定可能なディスクを使用できるようにしました。ディスク名は `database_disk.disk` config parameter で設定できます。[#72027](https://github.com/ClickHouse/ClickHouse/pull/72027) ([Tuan Pham Anh](https://github.com/tuanpach))。
* native reader で parquet の整数 logical type をサポートしました。[#72105](https://github.com/ClickHouse/ClickHouse/pull/72105) ([Arthur Passos](https://github.com/arthurpassos))。
