<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* cache を組み合わせ可能にし、特定のファイル (idx、mrk など) を退避対象から除外できるようにするとともに、古い cache バージョンを削除しました。これにより、Azure blob storage ディスク、ローカル ディスク、StaticWeb ディスクなどの上に cache を設定できるようになりました。この PR は、cache の設定が変更されており、cache を動作させるには設定ファイルの更新が必要なため、後方互換性を持たないものとしてマークされています。古い cache は新しい設定でも引き続き使用されます。古い cache 設定のままでもサーバーは問題なく起動します。[#36140](https://github.com/ClickHouse/ClickHouse/issues/36140) をクローズしました。[#37889](https://github.com/ClickHouse/ClickHouse/issues/37889) をクローズしました。[#36171](https://github.com/ClickHouse/ClickHouse/pull/36171) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 現在、関連するすべての Dictionary ソース が `remote_url_allow_hosts` 設定に従うようになりました。これはすでに HTTP、Cassandra、Redis では対応済みでした。今回、ClickHouse、MongoDB、MySQL、PostgreSQL が追加されました。ホストのチェックは、DDL から作成された Dictionary に対してのみ行われます。[#39184](https://github.com/ClickHouse/ClickHouse/pull/39184) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Date32 と DateTime64 の範囲を拡張し、1900 年から 2299 年までの日付をサポートするようにしました。以前のバージョンでサポートされていた範囲は 1925 年から 2283 年までだけでした。実装では、ユリウス暦からグレゴリオ暦への歴史的な移行を考慮するのではなく、プロレプティック・グレゴリオ暦 ([ISO 8601](https://en.wikipedia.org/wiki/ISO_8601):2004 (clause 3.2.1 The Gregorian calendar) に準拠) を使用しています。この変更は、範囲外の引数に対する実装依存の動作に影響します。たとえば、以前のバージョンでは `1899-01-01` の値は `1925-01-01` に切り詰められていましたが、新しいバージョンでは `1900-01-01` に切り詰められます。また、インターバルは実装依存の時点を基準に数えられるため、`INTERVAL 3 QUARTER` を渡した場合の `toStartOfInterval` の丸め動作も、最大で 1 四半期分変わります。[#28216](https://github.com/ClickHouse/ClickHouse/issues/28216) をクローズし、[#38393](https://github.com/ClickHouse/ClickHouse/issues/38393) を改善しました。[#39425](https://github.com/ClickHouse/ClickHouse/pull/39425) ([Roman Vasin](https://github.com/rvasin)).



<div id="new-feature">
  #### 新機能
</div>

* 設定 `exact_rows_before_limit` (0/1) を追加しました。有効にすると、ClickHouse は統計 `rows_before_limit_at_least` に対して正確な値を返しますが、その代わりに limit 前のデータを最後まで完全に読み取る必要があります。これにより [#6613](https://github.com/ClickHouse/ClickHouse/issues/6613) がクローズされます。[#25333](https://github.com/ClickHouse/ClickHouse/pull/25333) ([kevin wan](https://github.com/MaxWk)).
* 非圧縮 cache と marks cache に SLRU cache policy を追加しました。[#34651](https://github.com/ClickHouse/ClickHouse/pull/34651) ([alexX512](https://github.com/alexX512)).
* Intel® In-Memory Analytics Accelerator (Intel® IAA) は、次世代の Intel® Xeon® Scalable プロセッサ (&quot;Sapphire Rapids&quot;) で利用可能なハードウェアアクセラレータです。これは、データの圧縮・伸長やフィルタリングといった analytics で一般的な操作を高速化することを目的としています。ClickHouse には、Intel® IAA のオフロード技術を利用して高性能な DEFLATE 実装を提供する、新しい &quot;DeflateQpl&quot; 圧縮 codec が追加されました。この codec は [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl) を使用しており、ハードウェアアクセラレータへのアクセスを抽象化するとともに、ハードウェアアクセラレータが利用できない場合はソフトウェア fallback を使用します。DEFLATE は一般に、ClickHouse のデフォルト codec である LZ4 よりも高い圧縮率を実現するため、その結果としてディスク I/O を削減し、main memory consumption も低減します。[#36654](https://github.com/ClickHouse/ClickHouse/pull/36654) ([jasperzhu](https://github.com/jinjunzh)).
* 高 RPS 時のパフォーマンス向上を目的として、すべてのクエリで使用される thread の総数を制限する `concurrent&#95;threads&#95;soft&#95;limit` parameter を追加しました。[#37285](https://github.com/ClickHouse/ClickHouse/pull/37285) ([Roman Vasin](https://github.com/rvasin)).
* クエリによって作成される同時実行 thread の総数を制限するための concurrency control logic を追加しました。[#37558](https://github.com/ClickHouse/ClickHouse/pull/37558) ([Sergei Trifonov](https://github.com/serxa)).
* Distributed および Replicated engine のテーブルに対する parallel distributed insert select のサポートを追加しました [#34670](https://github.com/ClickHouse/ClickHouse/issues/34670)。[#39107](https://github.com/ClickHouse/ClickHouse/pull/39107) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* テキストフォーマットからのスキーマ推論を制御する新しい設定を追加しました: - `input_format_try_infer_dates` - 文字列から Date を推論します。 - `input_format_try_infer_datetimes` - 文字列から DateTime を推論します。 - `input_format_try_infer_integers` - `Float64` ではなく `Int64` を推論します。 - `input_format_json_try_infer_numbers_from_strings` - JSON フォーマット内の JSON string から数値を推論します。[#39186](https://github.com/ClickHouse/ClickHouse/pull/39186) ([Kruglov Pavel](https://github.com/Avogar)).
* この機能により、console で JSON 形式の log output を提供できるようになります。これにより、ログ分析ツールでのインジェストやクエリが容易になります。[#39277](https://github.com/ClickHouse/ClickHouse/pull/39277) ([Mallik Hassan](https://github.com/SadiHassan)).
* Intel® In-Memory Analytics Accelerator (Intel® IAA) は、次世代の Intel® Xeon® Scalable プロセッサ (&quot;Sapphire Rapids&quot;) で利用可能なハードウェアアクセラレータです。これは、データの圧縮・伸長やフィルタリングといった analytics で一般的な操作を高速化することを目的としています。ClickHouse には、Intel® IAA のオフロード技術を利用して高性能な DEFLATE 実装を提供する、新しい &quot;DeflateQpl&quot; 圧縮 codec が追加されました。この codec は [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl) を使用しており、ハードウェアアクセラレータへのアクセスを抽象化するとともに、ハードウェアアクセラレータが利用できない場合はソフトウェア fallback を使用します。DEFLATE は一般に、ClickHouse のデフォルト codec である LZ4 よりも高い圧縮率を実現するため、その結果としてディスク I/O を削減し、main memory consumption も低減します。[#39494](https://github.com/ClickHouse/ClickHouse/pull/39494) ([Robert Schulze](https://github.com/rschu1ze)).
* 長時間実行されるクエリや継続的なクエリの実行中に現在時刻を取得できる関数 `nowInBlock` を追加しました。[#39522](https://github.com/ClickHouse/ClickHouse/issues/39522) をクローズします。補足: `now64InBlock` と `todayInBlock` という関数はありません。[#39533](https://github.com/ClickHouse/ClickHouse/pull/39533) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* * 進捗レポート (`X-ClickHouse-Summary`) に result&#95;rows と result&#95;bytes を追加しました。 [#39567](https://github.com/ClickHouse/ClickHouse/pull/39567) ([Raúl Marín](https://github.com/Algunenano)).
* `executable()` テーブル関数に対して設定を指定できるようになりました。[#39681](https://github.com/ClickHouse/ClickHouse/pull/39681) ([Constantine Peresypkin](https://github.com/pkit))。
* データベースエンジンを `Ordinary` から `Atomic` に自動変換する機能を実装しました。`flags` ディレクトリに空の `convert_ordinary_to_atomic` ファイルを作成すると、次回のサーバー起動時にすべての `Ordinary` データベースが自動的に変換されます。[#39546](https://github.com/ClickHouse/ClickHouse/issues/39546) を解決します。[#39933](https://github.com/ClickHouse/ClickHouse/pull/39933) ([Alexander Tokmakov](https://github.com/tavplubix))。
* 特定のカラムに対するスキーマ推論で構造ヒントを指定できる新しい設定 `schema_inference_hints` を追加しました。[#39569](https://github.com/ClickHouse/ClickHouse/issues/39569) をクローズしました。[#40068](https://github.com/ClickHouse/ClickHouse/pull/40068) ([Kruglov Pavel](https://github.com/Avogar))。



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* * 複雑なクエリで analyze が停止した場合に中断するようにしました。[#38185](https://github.com/ClickHouse/ClickHouse/pull/38185) ([Vladimir C](https://github.com/vdimir)).
* 入力ストリームのソート記述に基づいてソート方法を推定し、入力ストリームがすでにソート済みであればソートをスキップするようにしました。[#38719](https://github.com/ClickHouse/ClickHouse/pull/38719) ([Igor Nikonov](https://github.com/devcrafter)).
* `ORDER BY` と組み合わせた `DISTINCT` で、`DISTINCT` のカラムが `ORDER BY` のカラムと一致する場合 (またはそのプレフィックスになっている場合) 、メモリ使用量が大幅に改善され、クエリ実行時間も短縮されます。[#39432](https://github.com/ClickHouse/ClickHouse/pull/39432) ([Igor Nikonov](https://github.com/devcrafter)).
* `cluster` および類似のテーブル関数の実行時に、リモートテーブルの構造を取得するためローカルノードを最優先で使用するようにしました。[#39440](https://github.com/ClickHouse/ClickHouse/pull/39440) ([Mingliang Pan](https://github.com/liangliangpan)).
* `DistinctSortedTransform` は、ソート記述が DISTINCT カラムに適用可能な場合にのみ使用し、そうでない場合は通常の DISTINCT 実装にフォールバックするようにしました。これにより、`DistinctSortedTransform` の実行時に必要なチェックを減らせます。[#39528](https://github.com/ClickHouse/ClickHouse/pull/39528) ([Igor Nikonov](https://github.com/devcrafter)).
* `DistinctSortedTransform` はソートを活用できておらず、実質的に通常の `DISTINCT` 実装と同様に動作していました。この修正により、メモリ使用量が大幅に削減されます。[#39538](https://github.com/ClickHouse/ClickHouse/pull/39538) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector: AVX512VBMI2 compress store を使った filter を最適化しました。[#39633](https://github.com/ClickHouse/ClickHouse/pull/39633) ([Guo Wangyang](https://github.com/guowangy)).
* KeyCondition: マルチスレッド環境で applyFunction を最適化しました。[#39812](https://github.com/ClickHouse/ClickHouse/pull/39812) ([Guo Wangyang](https://github.com/guowangy)).
* AVX512 VBMI2 を備えたシステムでは、この PR により SSB benchmark のクエリ 3.1、3.2、3.3 (SF=100) のパフォーマンスが約 6% 向上します。Intel Icelake Xeon 8380 の 2 ソケット構成でテストしました。[#40033](https://github.com/ClickHouse/ClickHouse/pull/40033) ([Robert Schulze](https://github.com/rschu1ze)).
* * 登録済みの UDFs がない場合は、UDFs の AST を走査しないようにしました。[#40069](https://github.com/ClickHouse/ClickHouse/pull/40069) ([Raúl Marín](https://github.com/Algunenano)).
* * CurrentMemoryTracker の alloc と free を最適化しました。[#40078](https://github.com/ClickHouse/ClickHouse/pull/40078) ([Raúl Marín](https://github.com/Algunenano)).



<div id="improvement">
  #### 改善

* MergeTree における PK の解析方法を変更しました。[#25563](https://github.com/ClickHouse/ClickHouse/pull/25563) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* * `Replicated` database の DDL クエリ結果テーブルの構造を改善しました (分片名とレプリカ名のカラムを分離し、status をより明確化)  - `distributed_ddl_entry_format_version` が 3 (デフォルト値) に設定されている場合、`CREATE TABLE ... ON CLUSTER` クエリはまずイニシエーター上で正規化されることがあります。これは、イニシエーターがクエリで指定されたクラスターに属していない場合、`ON CLUSTER` クエリが動作しない可能性があることを意味します。[#37318](https://github.com/ClickHouse/ClickHouse/issues/37318)、[#39500](https://github.com/ClickHouse/ClickHouse/issues/39500) を修正 - database が `Replicated` で、クラスター名がデータベース名と同じ場合は `ON CLUSTER` clause を無視 - [#35570](https://github.com/ClickHouse/ClickHouse/issues/35570) に関連 - `Replicated` データベースエンジンに関するその他の軽微な修正 - `Replicated` database の起動時にメタデータの整合性を確認し、ローカルのメタデータと Keeper 内のメタデータが不一致の場合はレプリカの復旧を開始します。[#24880](https://github.com/ClickHouse/ClickHouse/issues/24880) を解決。[#37198](https://github.com/ClickHouse/ClickHouse/pull/37198) ([Alexander Tokmakov](https://github.com/tavplubix)) 。

* `timeSlots` が DateTime64 をサポートするようになりました。DateTime64 の使用時には、サブ秒のDurationおよびスロットサイズを利用できます。[#37951](https://github.com/ClickHouse/ClickHouse/pull/37951) ([Andrey Zvonov](https://github.com/zvonand)).

* * 関数登録マクロのインターフェイス (`FUNCTION_REGISTER*`) を簡素化し、registerFunctions.cpp で extern 関数を追加して呼び出す手順を不要にしました。これにより、新しい関数のインクリメンタルビルドも高速化されます。[#38615](https://github.com/ClickHouse/ClickHouse/pull/38615) ([Li Yin](https://github.com/liyinsg)).
* * rocksdb を使用する `LEFT SEMI` および `LEFT ANTI` direct join に対応しました。[#38956](https://github.com/ClickHouse/ClickHouse/pull/38956) ([Vladimir C](https://github.com/vdimir)) 。
