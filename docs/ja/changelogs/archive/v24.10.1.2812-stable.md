  # 2024年の変更履歴
</div>

<div id="clickhouse-release-v241012812-stable-9cd0a3738d5-fixme-as-compared-to-v241011-new-b12a3677418">
  ### ClickHouse リリース v24.10.1.2812-stable (9cd0a3738d5)、v24.10.1.1-new (b12a3677418) との比較 FIXME
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* 括弧内にサブクエリを含む `UNION` のクエリ連鎖で、`FORMAT` の前に `SETTINGS` を記述できるようにしました。これにより [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712) を修正しました。あわせて、1 つのクエリで SETTINGS clause が連続して 2 回指定された場合の動作も変更しました。対応するサブクエリでは、最も近い SETTINGS clause が優先されます。以前のバージョンでは、最も外側の SETTINGS clause が内側のものより優先されることがありました。[#68614](https://github.com/ClickHouse/ClickHouse/pull/68614) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `[PRE]WHERE` clause のフィルタ条件の並べ替えが、デフォルトで許可されるようになりました。これは `allow_reorder_prewhere_conditions` を `false` に設定することで無効にできます。[#70657](https://github.com/ClickHouse/ClickHouse/pull/70657) ([Nikita Taranov](https://github.com/nickitat)).
* `mapKeys`/`mapValues` で `LowCardinality` 型を保持するようにし、`optimize_functions_to_subcolumns` 最適化を修正しました (以前は `Invalid column type for ColumnUnique::insertRangeFrom. Expected String, got LowCardinality(String)` エラーを引き起こす可能性がありました) 。[#70716](https://github.com/ClickHouse/ClickHouse/pull/70716) ([Azat Khuzhin](https://github.com/azat)).
* 互換性のないライセンスを持つ `idxd-config` ライブラリを削除しました。これに伴い、実験的な Intel DeflateQPL コーデックも削除されます。[#70987](https://github.com/ClickHouse/ClickHouse/pull/70987) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新機能
</div>

* MongoDB インテグレーションをリファクタリング: 非推奨の Poco::MongoDB から新しいドライバー mongocxx への移行、非推奨の旧プロトコルのサポート削除、URI による接続のサポート、すべての MongoDB 型のサポート、MongoDB 側での WHERE および ORDER BY ステートメントのサポート、MongoDB でサポートされていない式に対する制限。 [#63279](https://github.com/ClickHouse/ClickHouse/pull/63279) ([Kirill Nikiforov](https://github.com/allmazz)).
* clickhouse-client に新しい `--progress-table` オプションを追加し、クエリ実行中に変化するメトリクスを表形式で表示できるようにしました。新しい `--enable-progress-table-toggle` は `--progress-table` オプションに関連付けられており、コントロールキー (Space) を押すと進捗テーブルの表示をトグルします。 [#63689](https://github.com/ClickHouse/ClickHouse/pull/63689) ([Maria Khristenko](https://github.com/mariaKhr)).
* これにより、ワイルドカードプレフィックスへのアクセスを許可できます。`GRANT SELECT ON db.table_pefix_* TO user`。 [#65311](https://github.com/ClickHouse/ClickHouse/pull/65311) ([pufit](https://github.com/pufit)).
* 個々のクエリについて、メモリおよび system.events テーブルのメトリクス値の履歴を含み、定期的にディスクへフラッシュされる system.query&#95;metric&#95;log を追加。 [#66532](https://github.com/ClickHouse/ClickHouse/pull/66532) ([Pablo Marcos](https://github.com/pamarcos)).
* 暗黙の SELECT によりシンプルな SELECT クエリを書けるようになり、電卓スタイルの式を有効にできます。たとえば `ch "1 + 2"` です。これは新しい設定 `implicit_select` で制御されます。 [#68502](https://github.com/ClickHouse/ClickHouse/pull/68502) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* clickhouse local の --copy モードを、フォーマット変換のショートカットとしてサポート。 [#68503](https://github.com/ClickHouse/ClickHouse/issues/68503). [#68583](https://github.com/ClickHouse/ClickHouse/pull/68583) ([Denis Hananein](https://github.com/denis-hananein)).
* `arrayUnion` 関数をサポート。 [#68989](https://github.com/ClickHouse/ClickHouse/pull/68989) ([Peter Nguyen](https://github.com/petern48)).
* 集約関数 `quantileExactWeightedInterpolated` をサポート。これは quantileExactWeighted に基づく補間版です。すでに `quantileExactInterpolatedWeighted` があるのに、なぜ新しい `quantileExactWeightedInterpolated` が必要なのか疑問に思う人もいるかもしれません。理由は、新しいほうが従来のものより高精度だからです。ちなみに、これは Apache Gluten における Spark 互換性のためのものです。 [#69619](https://github.com/ClickHouse/ClickHouse/pull/69619) ([李扬](https://github.com/taiyang-li)).
* 関数 `arrayElementOrNull` をサポート。配列の index が範囲外、または map の key が見つからない場合は null を返します。 [#69646](https://github.com/ClickHouse/ClickHouse/pull/69646) ([李扬](https://github.com/taiyang-li)).
* `config.xml` ファイル内の新しい `message_regexp` および `message_regexp_negative` フィールドで正規表現を指定し、ログをフィルタリングできるようにしました。ログは、開発者にとって最も直感的になるよう、整形済みで色付けされていないテキストに適用されます。 [#69657](https://github.com/ClickHouse/ClickHouse/pull/69657) ([Peter Nguyen](https://github.com/petern48)).
* Dynamic 型の内部型に対して関数を実行することで、ほとんどの関数で Dynamic 型をサポート。 [#69691](https://github.com/ClickHouse/ClickHouse/pull/69691) ([Pavel Kruglov](https://github.com/Avogar)).
* 文字列の RIPEMD-160 暗号学的ハッシュを計算する `RIPEMD160` 関数を再追加。例: `SELECT HEX(RIPEMD160('The quick brown fox jumps over the lazy dog'))` は `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B` を返します。 [#70087](https://github.com/ClickHouse/ClickHouse/pull/70087) ([Dergousov Maxim](https://github.com/m7kss1)).
* object storage の table engine およびデータレイク向けに、ETag + file path から生成した hash を cache key として、読み取りファイルを cache できるようにしました。 [#70135](https://github.com/ClickHouse/ClickHouse/pull/70135) ([Kseniia Sumarokova](https://github.com/kssenii)).
* HDFS 上の Iceberg テーブルの読み取りをサポートしました。[#70268](https://github.com/ClickHouse/ClickHouse/pull/70268) ([flynn](https://github.com/ucasfl)).
* 設定 `input_format_binary_read_json_as_string/output_format_binary_write_json_as_string` により、RowBinary フォーマットで JSON type をバイナリ文字列として読み書きできるようにしました。[#70288](https://github.com/ClickHouse/ClickHouse/pull/70288) ([Pavel Kruglov](https://github.com/Avogar)).
* Native format で JSON カラムを単一の String カラムとしてシリアライズ/デシリアライズできるようにしました。出力には設定 `output_format_native_write_json_as_string` を使用します。入力では、カラムデータの前にシリアル化バージョン `1` を使用します。[#70312](https://github.com/ClickHouse/ClickHouse/pull/70312) ([Pavel Kruglov](https://github.com/Avogar)).
* 標準的な CTE である `with insert` をサポートしました。これまでは `insert ... with ...` のみサポートしていました。[#70593](https://github.com/ClickHouse/ClickHouse/pull/70593) ([Shichao Jin](https://github.com/jsc0218)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `pointInPolygon` で minmax 索引をサポート。 [#62085](https://github.com/ClickHouse/ClickHouse/pull/62085) ([JackyWoo](https://github.com/JackyWoo)).
* Parquet のブルームフィルタのサポートを追加。 [#62966](https://github.com/ClickHouse/ClickHouse/pull/62966) ([Arthur Passos](https://github.com/arthurpassos)).
* INSERT が SELECT に影響しないよう、ロックフリーでパーツをリネームするようにしました (パーツロックが原因) 。通常条件で `fsync_part_directory` を使用した場合、INSERT と SELECT を並列に実行した際の SELECT の QPS は 2 倍に向上し、高負荷時にはさらに大きな効果があります。なお、現時点では `ReplicatedMergeTree` のみが対象です。 [#64955](https://github.com/ClickHouse/ClickHouse/pull/64955) ([Azat Khuzhin](https://github.com/azat)).
* `materialize ttl` で `ttl_only_drop_parts` を尊重するようにしました。TTL を再計算するために必要なカラムだけを読み取り、空のパーツに置き換えることでパーツを削除します。 [#65488](https://github.com/ClickHouse/ClickHouse/pull/65488) ([Andrey Zvonov](https://github.com/zvonand)).
* パフォーマンス向上のために `IDisk` と `IObjectStorage` をリファクタリングしました。`plain` および `plain_rewritable` object storage のテーブルは、より高速に初期化されるようになります。 [#68146](https://github.com/ClickHouse/ClickHouse/pull/68146) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ロック競合を最小限に抑えるため、ThreadPool でのスレッド作成を最適化しました。高負荷時のジョブスケジューリングやスレッド管理の遅延を避けるため、スレッド作成はクリティカルセクションの外で実行されるようになりました。これにより、高い同時実行負荷下での ClickHouse の応答性が大幅に向上します。 [#68694](https://github.com/ClickHouse/ClickHouse/pull/68694) ([filimonov](https://github.com/filimonov)).
* ORC から LowCardinality の String 型のカラムを読み取れるようにしました。 [#69481](https://github.com/ClickHouse/ClickHouse/pull/69481) ([李扬](https://github.com/taiyang-li)).
* データをスパースカラムに直接パースできるようにしました。 [#69828](https://github.com/ClickHouse/ClickHouse/pull/69828) ([Anton Popov](https://github.com/CurtizJ)).
* single-threaded モードで、Parquet の行グループの並列読み取りと行グループのプリフェッチをサポートしました。 [#69862](https://github.com/ClickHouse/ClickHouse/pull/69862) ([LiuNeng](https://github.com/liuneng1994)).
* 欠損値が多いフォーマット (例: `JSONEachRow`) のパース性能を改善しました。 [#69875](https://github.com/ClickHouse/ClickHouse/pull/69875) ([Anton Popov](https://github.com/CurtizJ)).
* `part_log`、`query_views_log`、`filesystem_cache_log` などの system logs の `ProfileEvents` に `LowCardinality` を使用するようにしました。 [#70152](https://github.com/ClickHouse/ClickHouse/pull/70152) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* FromUnixTimestamp/ToUnixTimestamp 関数のパフォーマンスを改善しました。 [#71042](https://github.com/ClickHouse/ClickHouse/pull/71042) ([kevinyhzou](https://github.com/KevinyhZou)).

<div id="improvement">
  #### 改善
</div>

* パラメータ化された SQL 別名を許可しました。[#50665](https://github.com/ClickHouse/ClickHouse/pull/50665) ([Anton Kozlov](https://github.com/tonickkozlov)).
* [#57616](https://github.com/ClickHouse/ClickHouse/issues/57616) を修正しました。この問題は、正の数の引数がすべて自動的に `uint64` 型と判定されるため、`summapfiltered` で `int` 型のデータと一致できなくなることが原因で発生します。`uint64` のパラメータはユーザーが明示的に指定したものではないため、この不一致は非常に分かりにくいものでした。さらに、引数が `[1,2,3,toint8(-3)]` の場合、`getleastsupertype()`` によってこれらのパラメータは一律に `int` 型として扱われるため、`&#39;1,2,3&#39;`も`summapfiltered`の`uint&#96; 型データと一致しなくなります。[#58408](https://github.com/ClickHouse/ClickHouse/pull/58408) ([Chen768959](https://github.com/Chen768959)).
* `ALTER TABLE .. REPLACE PARTITION` は、他のパーティションで発生している mutations/merges を待機しなくなりました。[#59138](https://github.com/ClickHouse/ClickHouse/pull/59138) ([Vasily Nemkov](https://github.com/Enmk)).
* リフレッシュ可能なマテリアライズドビューが Replicated データベースでサポートされるようになりました。[#60669](https://github.com/ClickHouse/ClickHouse/pull/60669) ([Michael Kolupaev](https://github.com/al13n321)).
* `data/database_name/` ディレクトリ内のテーブル用シンボリックリンクは、default disk 上の `store/...` ディレクトリではなく、storage policy に応じてテーブルデータの実際のパスに対して作成されるようになりました。[#61777](https://github.com/ClickHouse/ClickHouse/pull/61777) ([Kirill](https://github.com/kirillgarbar)).
* グローバルな Context オブジェクトに設定の更新を適用するようにしました。これにより [#62308](https://github.com/ClickHouse/ClickHouse/issues/62308) のような問題が修正されます。[#62944](https://github.com/ClickHouse/ClickHouse/pull/62944) ([Amos Bird](https://github.com/amosbird)).
* 並列レプリカアルゴリズムの動作を制御する設定を見直しました。簡単に振り返ると、ClickHouse には複数のレプリカを使った並列読み取りのための 4 つの異なるアルゴリズムがあり、それが設定 `parallel_replicas_mode` に反映されています。デフォルト値は `read_tasks` です。さらに、トグル式の設定 `enable_parallel_replicas` が追加されました。[#63151](https://github.com/ClickHouse/ClickHouse/pull/63151) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `ReadSettings` がユーザー設定の値を使わず、デフォルト値だけを使っていた問題を修正しました。[#65625](https://github.com/ClickHouse/ClickHouse/pull/65625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* JSON から Enum フィールドをパースする際、整数を含む文字列が対応する Enum 要素として解釈されるようになりました。これにより [#65119](https://github.com/ClickHouse/ClickHouse/issues/65119) をクローズします。[#66801](https://github.com/ClickHouse/ClickHouse/pull/66801) ([scanhex12](https://github.com/scanhex12)).
* `TRIM` で `LEADING` または `TRAILING` の空文字列を no-op として扱えるようにしました。[#67792](https://github.com/ClickHouse/ClickHouse/issues/67792) をクローズします。[#68455](https://github.com/ClickHouse/ClickHouse/pull/68455) ([Peter Nguyen](https://github.com/petern48)).
* クエリを使ったテーブル作成 `CREATE TABLE ... CLONE AS ...` をサポートしました。これにより、source table のスキーマを複製し、その後すべてのパーティションを新しく作成されたテーブルに attach します。この機能は `MergeTree` ファミリーのテーブルでのみサポートされます。[#65015](https://github.com/ClickHouse/ClickHouse/issues/65015) をクローズします。[#69091](https://github.com/ClickHouse/ClickHouse/pull/69091) ([tuanpach](https://github.com/tuanpach)).
* Gluten ClickHouse では、Spark の timestamp 型は ClickHouse の datetime64(6) 型にマッピングされます。timestamp `'2012-01-01 00:11:22'` を文字列にキャストすると、Spark は `'2012-01-01 00:11:22'` を返しますが、Gluten ClickHouse は `'2012-01-01 00:11:22.000000'` を返します。 [#69179](https://github.com/ClickHouse/ClickHouse/pull/69179) ([Wenzheng Liu](https://github.com/lwz9103)).
* `enable_analyzer` が `true` に設定されている場合、定数式の計算には常に新しいアナライザを使用するようになりました。定数式のために `SELECT` クエリを使わずに、`executable()` テーブル関数の引数を計算できるようになりました。 [#69292](https://github.com/ClickHouse/ClickHouse/pull/69292) ([Dmitry Novik](https://github.com/novikd)).
* 安全でない識別子を許可しない `enable_secure_identifiers` を追加しました。 [#69411](https://github.com/ClickHouse/ClickHouse/pull/69411) ([tuanpach](https://github.com/tuanpach)).
* SHOW CREATEクエリの結果における識別子のクォート動作を定義する `show_create_query_identifier_quoting_rule` を追加しました。設定可能な値: - `user_display`: 識別子がキーワードの場合。 - `when_necessary`: 識別子が `{"distinct", "all", "table"}` のいずれかである場合、または曖昧さを招く可能性がある場合: カラム名、Dictionary 属性名。 - `always`: 常に識別子をクォートします。 [#69448](https://github.com/ClickHouse/ClickHouse/pull/69448) ([tuanpach](https://github.com/tuanpach)).
* [https://github.com/ClickHouse/ClickHouse/pull/69346](https://github.com/ClickHouse/ClickHouse/pull/69346) のフォローアップです。そこで説明されているポイント 4 も動作するようになりました。 [#69563](https://github.com/ClickHouse/ClickHouse/pull/69563) ([Vitaly Baranov](https://github.com/vitlibar)).
* Avro Union と ClickHouse Variant 型の間の汎用 SerDe を実装しました。[#69713](https://github.com/ClickHouse/ClickHouse/issues/69713) を解決します。 [#69712](https://github.com/ClickHouse/ClickHouse/pull/69712) ([Jiří Kozlovský](https://github.com/jirislav)).

CREATE TABLE AS では、PRIMARY KEY、ORDER BY、および同様の句もコピーされるようになりました。現時点では、これは MergeTree family のテーブルエンジンでのみサポートされています。 2. たとえば、これまでは次の SQL ステートメントで例外が発生していましたが、この PR で修正されました。宛先テーブルのテーブル定義に `ORDER BY` または `PRIMARY KEY` の式が指定されていない場合は、ソーステーブルからコピーします。 [#69739](https://github.com/ClickHouse/ClickHouse/pull/69739) ([sakulali](https://github.com/sakulali)).

* `clickhouse-client` や他の CLI アプリケーションで、server の過負荷が原因で起動が遅い場合に、その間に `SELECT` などのクエリを入力し始めると、以前のバージョンでは挨拶メッセージの表示前に端末エコーの残りが表示され、`ClickHouse local version 24.10.1.1.` ではなく `SELECTClickHouse local version 24.10.1.1.` のようになっていました。これを修正しました。これにより [#31696](https://github.com/ClickHouse/ClickHouse/issues/31696) をクローズします。[#69856](https://github.com/ClickHouse/ClickHouse/pull/69856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
