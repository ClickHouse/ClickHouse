<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* 関数 `yandexConsistentHash` (Konstantin &quot;kostik&quot; Oblakov による一貫性ハッシュアルゴリズム) は `kostikConsistentHash` にリネームされました。以前の名前も互換性のためエイリアスとして残されています。この変更自体は後方互換ですが、今後のリリースでこのエイリアスが削除される可能性があるため、アプリ内でこの関数を使用している箇所は更新することを推奨します。 [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* INSERT クエリでは FORMAT の後に SETTINGS を指定できないようにしました (このようなクエリを受け付けるための互換性 setting `allow_settings_after_format_in_insert` はありますが、デフォルトでは OFF です) 。 [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* cache ファイルのハッシュ化されたパスを変更しました。 [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* clickhouse-server の起動を高速化するため、MergeTree のパーツ読み込み処理を高速化しました。この改善により、700k 個の MergeTree パーツがある場合でも、clickhouse-server の起動時間を 75 分から 20 秒に短縮できました。 [#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* aggregation 中に使用される hash tables のサイズを収集し、後続のクエリで利用することで、hash tables のリサイズを回避できるようになりました。 [#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* ASOF JOIN のパフォーマンスを改善する複数の変更を行いました (1.2～1.6 倍高速化) 。また、大きな整数型の使用もサポートしました。 [#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* URL storage engine が、endpoint で HTTP Range がサポートされている場合に、複数の chunk を並列にダウンロードするようになりました。さらに、`max_download_threads` と `max_download_buffer_size` という 2 つの設定が追加され、単一のクエリがファイルのダウンロードに使用できるスレッド数の上限と、各スレッドが処理できる最大バイト数を制御できるようになりました。 [#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* S3 storage への multipart upload の並列化。 [#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* key が native integer の場合の ASOF JOIN のパフォーマンスを改善しました。 [#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* 新しいクエリプラン最適化。可能な場合、関数は `ORDER BY` の後に評価されます。たとえば、クエリ `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5` では、関数 `sipHash64` は `ORDER BY` と `LIMIT` の後に評価されるため、約 20 倍高速化されます。 [#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* setenv LIBHDFS3&#95;CONF 関連の issue [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292) に対し、mutex のスコープを狭めました。 [#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* SSE および AVX2 向けの特殊化により、`hasAll` 関数のパフォーマンスを改善しました。Author @youennL-cs. [#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * 2 つの分散テーブルに対する GLOBAL JOIN の explain ステートメントを 100 倍高速化できます: explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2 つの最適化: - 自明な count hive クエリを最適化 - hive file のメタデータをキャッシュすることで hive クエリを高速化。 [#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
