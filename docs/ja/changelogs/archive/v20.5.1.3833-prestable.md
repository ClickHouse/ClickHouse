<div id="clickhouse-release-v20513833-prestable-fixme-as-compared-to-v20413177-prestable">
  ### ClickHouse release v20.5.1.3833-prestable FIXME (v20.4.1.3177-prestable との比較)
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `experimental_use_processors` 設定を削除しました。デフォルトで有効になります。 [#10924](https://github.com/ClickHouse/ClickHouse/pull/10924) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* `input_format_with_names_use_header` 設定はデフォルトで有効になります。これにより、入力フォーマット `-WithNames` および `-WithNamesAndTypes` のパースに影響があります。 [#10937](https://github.com/ClickHouse/ClickHouse/pull/10937) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* user-level setting が誤った場所に指定されている場合のチェックを追加しました。user-level setting は、特定のユーザープロファイルの `users.xml` 内の `<profile>` セクション (またはデフォルト設定の場合は `<default>`) に指定する必要があります。server は、log に例外メッセージを出して起動しなくなります。これにより [#9051](https://github.com/ClickHouse/ClickHouse/issues/9051) を修正します。このチェックをスキップしたい場合は、設定を適切な場所へ移動するか、`config.xml` に `<skip_check_for_incorrect_settings>1</skip_check_for_incorrect_settings>` を追加してください。 [#11449](https://github.com/ClickHouse/ClickHouse/pull/11449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* COUNT(DISTINCT) および `uniq` 集約関数ファミリーは、Nullable ではない結果を返すようになりました。渡された値がすべて NULL の場合は、代わりに 0 を返します。これにより SQL 互換性が向上します。 [#11661](https://github.com/ClickHouse/ClickHouse/pull/11661) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### 新機能

* 外部 Dictionary として Cassandra をサポートしました。[#4978](https://github.com/ClickHouse/ClickHouse/pull/4978) ([favstovol](https://github.com/favstovol)).
* `SimpleAggregateFunction` で `sumMap` もサポートされるようになりました。[#10000](https://github.com/ClickHouse/ClickHouse/pull/10000) ([Ildus Kurbangaliev](https://github.com/ildus)).
* OpenCL サポートと bitonic ソートアルゴリズムを追加しました。これは、単一カラムの整数型データのソートに使用できます。ビルドフラグ `-DENABLE_OPENCL=1` を指定してビルドする必要があります。ほかのアルゴリズムではなく bitonic ソートアルゴリズムを使用するには、設定オプション `special_sort` に `bitonic_sort` を設定し、OpenCL が利用可能であることを確認する必要があります。[#10232](https://github.com/ClickHouse/ClickHouse/pull/10232) ([Margarita Konnova [MARK]](https://github.com/margaritiko)).
* PostgreSQL ワイヤプロトコルの実装。[#10242](https://github.com/ClickHouse/ClickHouse/pull/10242) ([Movses Elbakian](https://github.com/MovElb)).
* `FINAL` 付きの SELECT は並列に実行されるようになりました。使用するスレッド数を制限するための設定 `max_final_threads` を追加しました。[#10463](https://github.com/ClickHouse/ClickHouse/pull/10463) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).

* WHERE 句の条件を満たす期限切れの行の一部を削除できるようになりました。さらに、GROUP BY 句で指定した集約結果で期限切れの行を置き換えられるようになりました。[#10537](https://github.com/ClickHouse/ClickHouse/pull/10537) ([expl0si0nn](https://github.com/expl0si0nn)).

* * Arrow IPC Fileフォーマット (入力/出力) を追加 - Parquet入力フォーマットにおける `resetParser()` の誤動作を修正 - RandomAccessFiles向けORCのゼロコピー最適化を追加 - ParquetおよびORC入力フォーマットに不足していたhalffloat型を追加 ... [#10580](https://github.com/ClickHouse/ClickHouse/pull/10580) ([Zhanna](https://github.com/FawnD2)).

* 改行、空白、および/またはカンマで区切られた JSON オブジェクトの数列を受け付ける新しい入力フォーマット `JSONAsString` を追加しました。[#10607](https://github.com/ClickHouse/ClickHouse/pull/10607) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* テーブルの sorting key に基づく GROUP BY の最適化。 [#9113](https://github.com/ClickHouse/ClickHouse/pull/9113) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* aggregate functions から算術演算を切り出す新しい最適化。 [#10047](https://github.com/ClickHouse/ClickHouse/pull/10047) ([Ruslan](https://github.com/kamalov-ruslan)).
* この機能により、GROUP BY 句内の他のキーに対する関数が排除されます。 [#10051](https://github.com/ClickHouse/ClickHouse/pull/10051) ([Victor Grishanin](https://github.com/xPoSx)).
* 最適な関数実装を選択して振り分けるための runtime CPU 検出を追加しました。あわせて、複数ターゲット向けの codegeneration もサポートしました。これにより [#1017](https://github.com/ClickHouse/ClickHouse/issues/1017) をクローズします。 [#10058](https://github.com/ClickHouse/ClickHouse/pull/10058) ([DimasKovas](https://github.com/DimasKovas)).
* subqueries から重複する ORDER BY と DISTINCT を削除します。 [#10067](https://github.com/ClickHouse/ClickHouse/pull/10067) ([Mikhail Malafeev](https://github.com/demo-99)).
* MergeJoin で左テーブルのより大きなパーツをソートするようにしました。左側の block をメモリ内にバッファします。左側 block のバッファサイズを管理するための `partial_merge_join_left_table_buffer_bytes` setting を追加しました。 [#10601](https://github.com/ClickHouse/ClickHouse/pull/10601) ([Artem Zuikov](https://github.com/4ertus2)).
* external dictionaries を読み取る任意の関数について、呼び出しごとに Dictionary の取得とアクセス権の確認を 1 回だけ行うようにしました。 [#10928](https://github.com/ClickHouse/ClickHouse/pull/10928) ([Vitaly Baranov](https://github.com/vitlibar)).
* 不要なデータ移動をいくつか削減し、radix sort を改善しました。 [#10981](https://github.com/ClickHouse/ClickHouse/pull/10981) ([Arslan Gumerov](https://github.com/g-arslan)).
* `sum` aggregate function を使用し、GROUP BY キーを持たない queries を数倍高速に実行できるようにしました。 [#10992](https://github.com/ClickHouse/ClickHouse/pull/10992) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* デフォルトで clickhouse binary の mlock を有効にしました。これにより、高い I/O 負荷時に clickhouse executable がページアウトされるのを防ぎます。 [#11139](https://github.com/ClickHouse/ClickHouse/pull/11139) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `ORDER BY` と小さい `LIMIT` (`max_block_size` 未満) を含む queries のパフォーマンスを改善しました。 [#11171](https://github.com/ClickHouse/ClickHouse/pull/11171) ([Provet](https://github.com/Provet)).
* INSERT SELECT 経由の INSERT queries、または小さい blocks が生成される場合 (parallel parsing で典型的) に `clickhouse-client` を使った INSERT のパフォーマンスを改善しました。これにより [#11275](https://github.com/ClickHouse/ClickHouse/issues/11275) を修正します。DEFAULT フィールドで制約が機能していなかった問題を修正しました。これにより [#11273](https://github.com/ClickHouse/ClickHouse/issues/11273) を修正します。TEMPORARY tables で制約が無視されていた問題を修正しました。これにより [#11274](https://github.com/ClickHouse/ClickHouse/issues/11274) を修正します。 [#11276](https://github.com/ClickHouse/ClickHouse/pull/11276) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Pretty formats 使用時の対話型モードにおける `clickhouse-client` のパフォーマンスを改善しました。以前のバージョンでは、UTF-8 string の表示幅の計算にかなりの時間を要することがありました。これにより [#11323](https://github.com/ClickHouse/ClickHouse/issues/11323) をクローズします。 [#11323](https://github.com/ClickHouse/ClickHouse/pull/11323) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* &quot;any&quot; 関数からすべての操作を切り出す新しい最適化。 [#11529](https://github.com/ClickHouse/ClickHouse/pull/11529) ([Ruslan](https://github.com/kamalov-ruslan)).
* AggregatingMergeTree でのマージを高速化しました。これにより、1年以上前に [#4348](https://github.com/ClickHouse/ClickHouse/issues/4348) (バージョン 19.3) で導入されたパフォーマンス低下を修正します。[#11534](https://github.com/ClickHouse/ClickHouse/pull/11534) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 複数のレプリカで、マージ、ミューテーション、パーティションの削除・移動・置換を同時実行で割り当てられるようにしました。これにより [#10367](https://github.com/ClickHouse/ClickHouse/issues/10367) をクローズします。[#11639](https://github.com/ClickHouse/ClickHouse/pull/11639) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* この最適化により、SELECT 句内の GROUP BY キーに対する min/max/any 集約関数を省略します。[#11667](https://github.com/ClickHouse/ClickHouse/pull/11667) ([Victor Grishanin](https://github.com/xPoSx)) 。
