<div id="clickhouse-release-v23611524-stable-d1c7e13d088-fixme-as-compared-to-v23513174-stable-2fec796e73e">
  ### ClickHouse リリース v23.6.1.1524-stable (d1c7e13d088) FIXME、v23.5.1.3174-stable (2fec796e73e) と比較
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* fs cache の機能 `do_not_evict_index_and_mark_files` を削除しました。この機能はかえって状況を悪化させるだけでした。 [#51253](https://github.com/ClickHouse/ClickHouse/pull/51253) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 実験的な LIVE VIEW に対する ALTER のサポートを削除しました。 [#51287](https://github.com/ClickHouse/ClickHouse/pull/51287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新機能
</div>

* 設定 `session_timezone` を追加しました。明示的に指定されていない場合、セッションのデフォルトのタイムゾーンとして使用されます。 [#44149](https://github.com/ClickHouse/ClickHouse/pull/44149) ([Andrey Zvonov](https://github.com/zvonand)).
* overlay データベースエンジンと、ディレクトリをデータベースとして表現する機能を追加しました。このコミットでは 4 つのデータベースが追加されます: 1. DatabaseOverlay: IDatabase インターフェイスを実装します。FileSystem や Memory など、複数のデータベースを組み合わせることができます。内部では他のデータベースへのポインタを持つベクターを保持し、成功するまで順番にそれらへリクエストをプロキシします。 2. DatabaseFilesystem: ファイルシステム上に保存されたファイルを読み取り専用で扱えます。内部では、ユーザーがテーブルを要求したときにファイルを暗黙的に読み込むために TableFunctionFile を使用します。TableFunctionFile の呼び出し結果は内部でキャッシュされ、高速にアクセスできます。 3. DatabaseS3: S3 storage を読み取り専用で扱えます。S3 からテーブルを暗黙的に読み込むために TableFunctionS3 を使用します 4. DatabaseHDFS: hdfs storage を扱えます。hdfs からテーブルを暗黙的に読み込むために TableFunctionHDFS を使用します。 [#48821](https://github.com/ClickHouse/ClickHouse/pull/48821) ([alekseygolub](https://github.com/alekseygolub)).
* `use_mysql_types_in_show_columns` という新しい設定を追加し、クライアントが MySQL compatibility port 経由で接続している場合に、`SHOW COLUMNS` SQL ステートメントで MySQL 相当の型を表示できるようにしました。 [#49577](https://github.com/ClickHouse/ClickHouse/pull/49577) ([Thomas Panetti](https://github.com/tpanetti)).
* オプション `--rename_files_after_processing <pattern>` を追加しました。これにより [#34207](https://github.com/ClickHouse/ClickHouse/issues/34207) を解決します。 [#49626](https://github.com/ClickHouse/ClickHouse/pull/49626) ([alekseygolub](https://github.com/alekseygolub)).
* 1. `TableFunctionRedis` を追加 3. テーブルエンジン Redis を追加 4. Redis 関連のツールと型を含む `RedisCommon` を追加 5. Redis への `equals` および `in` フィルタープッシュダウンをサポート。 [#50150](https://github.com/ClickHouse/ClickHouse/pull/50150) ([JackyWoo](https://github.com/JackyWoo)).
* 設定 `s3_skip_empty_files`, `hdfs_skip_empty_files`, `engine_file_skip_empty_files`, `engine_url_skip_empty_files` を使って、file/s3/url/hdfs テーブル関数で空のファイルをスキップできるようにしました。 [#50364](https://github.com/ClickHouse/ClickHouse/pull/50364) ([Kruglov Pavel](https://github.com/Avogar)).
* Clickhouse-client は、&quot;--host&quot;、&quot;--port&quot;、&quot;--user&quot; などの代わりに接続情報を指定して呼び出せるようになりました。 [#50689](https://github.com/ClickHouse/ClickHouse/pull/50689) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* コーデック DEFLATE&#95;QPL は、設定 &quot;allow&#95;experimental&#95;codecs&quot; ではなくサーバー設定 &quot;enable&#95;deflate&#95;qpl&#95;codec&quot; (デフォルト: false) で制御されるようになりました。これにより QPL&#95;DEFLATE は実験的機能ではなくなりました。 [#50775](https://github.com/ClickHouse/ClickHouse/pull/50775) ([Robert Schulze](https://github.com/rschu1ze)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* グローバルオブジェクトではなくスレッドローカルな timer&#95;id を使用することで、有効化されたクエリプロファイラのパフォーマンスを改善しました。 [#48778](https://github.com/ClickHouse/ClickHouse/pull/48778) ([Jiebin Sun](https://github.com/jiebinn)).
* CapnProto の入出力フォーマットを書き直して、パフォーマンスを改善しました。Map のカラム名と CapnProto のフィールドを大文字小文字を区別せずに扱うようにし、ネストした構造のフィールドの読み書きを修正しました。 [#49752](https://github.com/ClickHouse/ClickHouse/pull/49752) ([Kruglov Pavel](https://github.com/Avogar)).
* 並列スレッドでの Parquet 書き込みパフォーマンスを最適化しました。 [#50102](https://github.com/ClickHouse/ClickHouse/pull/50102) ([Hongbin Ma](https://github.com/binmahone)).
* ### ユーザー向け変更に関するドキュメントエントリ `parallelize_output_from_storages` を、MATERIALIZED VIEW の処理および block が 1 つしかないストレージに対して無効化しました。 [#50214](https://github.com/ClickHouse/ClickHouse/pull/50214) ([Azat Khuzhin](https://github.com/azat)).
* PR https://github.com/ClickHouse/ClickHouse/pull/46558 をマージしました (すでにソート済みのデータの処理を回避) 。block がすでにソート済みであれば、ソート時の block の並べ替えを回避します。 [#50697](https://github.com/ClickHouse/ClickHouse/pull/50697) ([Maksim Kita](https://github.com/kitaisreal)).
* 以前の PR ([#50062](https://github.com/ClickHouse/ClickHouse/issues/50062)、[#50307](https://github.com/ClickHouse/ClickHouse/issues/50307)) では、toYear/toYYYYMM を含む predicates を、等価でありながら converter を使わない形に変換する最適化パターンを提案していました。この変換は、SSB など一部の workloads に大きなパフォーマンス改善をもたらす可能性がありました。しかし、issue [#50628](https://github.com/ClickHouse/ClickHouse/issues/50628) が示したように、これら 2 つの PR には query results が不完全になるおそれのある問題が含まれていたため、最終的に [#50629](https://github.com/ClickHouse/ClickHouse/issues/50629) で Revert されました。 [#50951](https://github.com/ClickHouse/ClickHouse/pull/50951) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* `system.zookeeper` テーブルからの読み取りを高速化するため、ZooKeeper への複数の list リクエストを並列に実行するようにしました。 [#51042](https://github.com/ClickHouse/ClickHouse/pull/51042) ([Alexander Gololobov](https://github.com/davenger)).
* タイムゾーン用の DateTime ルックアップテーブルの初期化を高速化しました。これは、特に debug build では負荷が高いため、`clickhouse client` の起動時間や接続時間の短縮につながるはずです。 [#51347](https://github.com/ClickHouse/ClickHouse/pull/51347) ([Alexander Gololobov](https://github.com/davenger)).



<div id="improvement">
  #### 改善
</div>

* CIDR ::ffff:0:0/96 (IPv4マップアドレス) に対して、IPv6をIPv4アドレスにキャストできるようになりました。[#49759](https://github.com/ClickHouse/ClickHouse/pull/49759) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* MongoDB 5.1以降をサポートするよう MongoDB プロトコルを更新しました。旧プロトコル (3.6未満) のバージョンへのサポートも引き続き維持されます。[#45621](https://github.com/ClickHouse/ClickHouse/issues/45621)、[#49879](https://github.com/ClickHouse/ClickHouse/issues/49879) をクローズ。[#50061](https://github.com/ClickHouse/ClickHouse/pull/50061) ([Nikolay Degterinsky](https://github.com/evillique)).
* `ReplicatedMergeTree` におけるマージ選択およびクリーンアップタスクのスケジューリングを改善しました。マージやクリーンアップの対象がない場合、タスクが過度に頻繁に実行されなくなります。設定 `max_merge_selecting_sleep_ms`、`merge_selecting_sleep_slowdown_factor`、`max_cleanup_delay_period`、`cleanup_thread_preferred_points_per_iteration` を追加しました。[#31919](https://github.com/ClickHouse/ClickHouse/issues/31919) をクローズする予定です。[#50107](https://github.com/ClickHouse/ClickHouse/pull/50107) ([Alexander Tokmakov](https://github.com/tavplubix)).
* アナライザーでの並列レプリカをサポートしました。[#50441](https://github.com/ClickHouse/ClickHouse/pull/50441) ([Raúl Marín](https://github.com/Algunenano)).
* スキーマ推論で読み取るバイト数を制限するための設定 `input_format_max_bytes_to_read_for_schema_inference` を追加しました。[#50577](https://github.com/ClickHouse/ClickHouse/issues/50577) をクローズ。[#50592](https://github.com/ClickHouse/ClickHouse/pull/50592) ([Kruglov Pavel](https://github.com/Avogar)).
* スキーマ推論において設定 `input_format_as_default` が反映されるようになりました。[#50602](https://github.com/ClickHouse/ClickHouse/pull/50602) ([Kruglov Pavel](https://github.com/Avogar)).
* クロスジョインを通じたフィルタープッシュダウンを実装しました。[#50605](https://github.com/ClickHouse/ClickHouse/pull/50605) ([Han Fei](https://github.com/hanfei1991)).
* 実際の lz4 バージョンが使用されるようになりました。[#50621](https://github.com/ClickHouse/ClickHouse/pull/50621) ([Nikita Taranov](https://github.com/nickitat)).
* CSV/TSV/CustomSeparated フォーマットにおいて、設定 `input_format_csv_skip_trailing_empty_lines`、`input_format_tsv_skip_trailing_empty_lines`、`input_format_custom_skip_trailing_empty_lines` を使用して末尾の空行をスキップできるようになりました (デフォルトは無効) 。[#49315](https://github.com/ClickHouse/ClickHouse/issues/49315) をクローズ。[#50635](https://github.com/ClickHouse/ClickHouse/pull/50635) ([Kruglov Pavel](https://github.com/Avogar)).
* 関数 `toDateOrDefault|OrNull()` および `accurateCast[OrDefault|OrNull]()` が数値引数を正しく解析するようになりました。[#50709](https://github.com/ClickHouse/ClickHouse/pull/50709) ([Dmitry Kardymon](https://github.com/kardymonds)).
* これまで CSV 入力フォーマットは、空白または `\t` を区切り文字とする CSV ファイルを解析できませんでしたが (これらの区切り文字は Spark でサポートされています) 、本改善によりサポートされるようになりました。[#50712](https://github.com/ClickHouse/ClickHouse/pull/50712) ([KevinyhZou](https://github.com/KevinyhZou)).
* 設定 `number_of_mutations_to_delay` および `number_of_mutations_to_throw` がデフォルトで有効になり、それぞれ 500 および 1000 に設定されるようになりました。[#50726](https://github.com/ClickHouse/ClickHouse/pull/50726) ([Anton Popov](https://github.com/CurtizJ)).
* Keeper の改善: Keeper API 向けのフィーチャーフラグを追加しました。各フィーチャーフラグは `keeper_server.feature_flags` 設定で定義することで有効または無効にできます。例えば、`CheckNotExists` リクエストを有効にするには、Keeper 上で `keeper_server.feature_flags.check_not_exists` を `1` に設定します。[#50796](https://github.com/ClickHouse/ClickHouse/pull/50796) ([Antonio Andelic](https://github.com/antonio2368)).
* ダッシュボードで欠損値が正しく表示されるようになりました。[#50831](https://github.com/ClickHouse/ClickHouse/issues/50831) をクローズ。[#50832](https://github.com/ClickHouse/ClickHouse/pull/50832) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* CPU に関連する CGroups メトリクスが、使いやすさ向上のため `CGroupMaxCPU` という単一のメトリクスに統合されました。CGroups の制限が設定されている場合、`Normalized` CPU 使用率メトリクスは CPU の総数ではなく CGroups の制限値を基準に正規化されるようになりました。[#50836](https://github.com/ClickHouse/ClickHouse/issues/50836) をクローズ。[#50835](https://github.com/ClickHouse/ClickHouse/pull/50835) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 「パーツが多すぎる」に関するしきい値を現代的な基準に緩和しました。長時間実行されるインサートクエリ中にバックプレッシャーを返すようにしました。[#50856](https://github.com/ClickHouse/ClickHouse/pull/50856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 関数 `parseDateTimeBestEffort*()` および `parseDateTime64BestEffort*()` において、syslog タイムスタンプ形式の日時引数を使用できるようになりました。[#50925](https://github.com/ClickHouse/ClickHouse/pull/50925) ([Victor Krasnov](https://github.com/sirvickr)).
* ファイルが既に存在する場合、`INTO OUTFILE` に対して `APPEND` または `TRUNCATE` の使用を提案するようになりました。[#50950](https://github.com/ClickHouse/ClickHouse/pull/50950) ([alekar](https://github.com/alekar)).
* スタンドアロンの Keeper バイナリに組み込みの keeper-client を追加しました。[#50964](https://github.com/ClickHouse/ClickHouse/pull/50964) ([pufit](https://github.com/pufit)).
* clickhouse-client のコマンドラインパラメーター `--password` は、1回のみ指定できるようになりました。[#50966](https://github.com/ClickHouse/ClickHouse/pull/50966) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* 同期的な HEAD リクエストによるデータレイクの低速化を修正しました (ファイル数が多い場合に Iceberg/Deltalake/Hudi が遅くなる問題に関連) 。[#50976](https://github.com/ClickHouse/ClickHouse/pull/50976) ([Kseniia Sumarokova](https://github.com/kssenii)).
* クラスター上のバックアップ中にパーツの同一性を確認するため、`system.parts` の `hash_of_all_files` を使用するようになりました。[#50997](https://github.com/ClickHouse/ClickHouse/pull/50997) ([Vitaly Baranov](https://github.com/vitlibar)).
* システムテーブル `zookeeper_connection` の `connected_time` はコネクションが確立された時刻を標準フォーマットで示します。また、確立されたコネクションセッションの継続時間 (秒単位) を示す `session_uptime_elapsed_seconds` が追加されました。[#51026](https://github.com/ClickHouse/ClickHouse/pull/51026) ([郭小龙](https://github.com/guoxiaolongzte)).
* `system.parts`、`system.projection_parts`、およびエラーメッセージにおいて、チェックサムの前半・後半が正しい順序で表示されるようになりました。[#51040](https://github.com/ClickHouse/ClickHouse/pull/51040) ([Vitaly Baranov](https://github.com/vitlibar)).
* `Replicated` データベースにシャードが1つしかなく、基となるテーブルが `ReplicatedMergeTree` の場合、`ALTER PARTITION` クエリおよびミューテーションをレプリケートしないようになりました。[#51049](https://github.com/ClickHouse/ClickHouse/pull/51049) ([Alexander Tokmakov](https://github.com/tavplubix)).
* ソースデータのチャンクサイズを使用し、各スレッドでインクリメンタルな合計サイズ計算を行うことで、file/s3/hdfs/url テーブル関数のプログレスバーを改善しました。また、`*Cluster` 関数のプログレスバーも修正しました。[#47250](https://github.com/ClickHouse/ClickHouse/issues/47250) をクローズ。[#51088](https://github.com/ClickHouse/ClickHouse/pull/51088) ([Kruglov Pavel](https://github.com/Avogar)).
* プログレスバーの精度向上のため、TCP プロトコルの Progress パケットに `total_bytes_to_read` を追加しました。[#51158](https://github.com/ClickHouse/ClickHouse/pull/51158) ([Kruglov Pavel](https://github.com/Avogar)).
* ファイルシステムキャッシュを持つディスク上のデータパーツの検証が改善されました。[#51164](https://github.com/ClickHouse/ClickHouse/pull/51164) ([Anton Popov](https://github.com/CurtizJ)).
* cacheの設定 `do_not_evict_index_and_mark_files` を無効化しました (`23.5` で有効化されていました) 。[#51222](https://github.com/ClickHouse/ClickHouse/pull/51222) ([Kseniia Sumarokova](https://github.com/kssenii)).
* fsキャッシュにおいて `current_elements_num` が正しくない場合がある問題を修正しました。[#51242](https://github.com/ClickHouse/ClickHouse/pull/51242) ([Kseniia Sumarokova](https://github.com/kssenii)).
* ゼロコピーレプリケーション時にレプリカ間で負荷をより均等に分散するため、マージ/mutationの実行前にランダムなsleepを追加しました。[#51282](https://github.com/ClickHouse/ClickHouse/pull/51282) ([alesapin](https://github.com/alesapin)).
* 関数 `transform` および値マッチングを使用した `CASE` がすべてのデータ型をサポートするようになりました。[#29730](https://github.com/ClickHouse/ClickHouse/issues/29730)、[#32387](https://github.com/ClickHouse/ClickHouse/issues/32387)、[#50827](https://github.com/ClickHouse/ClickHouse/issues/50827)、[#31336](https://github.com/ClickHouse/ClickHouse/issues/31336)、[#40493](https://github.com/ClickHouse/ClickHouse/issues/40493) をクローズしました。[#51351](https://github.com/ClickHouse/ClickHouse/pull/51351) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `compile_expressions` 設定の使用を安全でないものにするLLVMのバグを発見しました。この設定はデフォルトで無効化されています。[#51368](https://github.com/ClickHouse/ClickHouse/pull/51368) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Issue [#50220](https://github.com/ClickHouse/ClickHouse/issues/50220) は `grace_hash` joinにおけるコアダンプを報告しています。ローカル環境で例外を再現することに成功し、一時ファイルの作成失敗に起因する問題であることが判明しました。これは https://github.com/ClickHouse/ClickHouse/pull/49816 および https://github.com/ClickHouse/ClickHouse/pull/49483 によって引き起こされたものと考えられます。[#51382](https://github.com/ClickHouse/ClickHouse/pull/51382) ([lgbo](https://github.com/lgbo-ustc)).
