<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* 型として `seconds` を使用する設定の解析方法を変更し、浮動小数点値 (例: `max_execution_time=0.5`) をサポートするようにしました。Infinity または NaN の値は例外を発生させます。 [#37187](https://github.com/ClickHouse/ClickHouse/pull/37187) ([Raúl Marín](https://github.com/Algunenano)).
* 実験的な型 `Object` のカラムのバイナリシリアライゼーションのフォーマットを変更しました。新しいフォーマットにより、サードパーティのクライアントで実装しやすくなります。 [#37482](https://github.com/ClickHouse/ClickHouse/pull/37482) ([Anton Popov](https://github.com/CurtizJ)).
* 設定 `output_format_json_named_tuples_as_objects` をデフォルトで有効にしました。これにより、JSON フォーマットで名前付きタプルを JSON オブジェクトとしてシリアライズできます。 [#37756](https://github.com/ClickHouse/ClickHouse/pull/37756) ([Anton Popov](https://github.com/CurtizJ)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* ORDER BY に複数のカラムがある場合の MergeTree への insert のパフォーマンスを改善しました。 [#35762](https://github.com/ClickHouse/ClickHouse/pull/35762) ([Maksim Kita](https://github.com/kitaisreal)).
* StorageHive に読み取りメソッド `threadpool` を適用しました。 [#36328](https://github.com/ClickHouse/ClickHouse/pull/36328) ([李扬](https://github.com/taiyang-li)).
* `FINAL` を伴うクエリの実行をよりデータ並列化するため、データパーツをパーツ全体ではなくレイヤーに分割してスレッド間に分散するようにしました。 [#36396](https://github.com/ClickHouse/ClickHouse/pull/36396) ([Nikita Taranov](https://github.com/nickitat)).
* ワイドパーツの読み取り時に、必要なカラムの marks のみを読み込むようにしました。 [#36879](https://github.com/ClickHouse/ClickHouse/pull/36879) ([Anton Kozlov](https://github.com/tonickkozlov)).
* 読み取るすべてのカラムがパーティションキーである場合、hive ファイルを実際に読み取ることなく、ファイルの行番号からカラムを構築するようにしました。 [#37103](https://github.com/ClickHouse/ClickHouse/pull/37103) ([lgbo](https://github.com/lgbo-ustc)).
* `dictGetDescendants`、`dictGetChildren` 関数のパフォーマンスを改善しました。親から children への一時的な階層索引を、クエリ実行中の関数呼び出しごとではなく、クエリごとに作成するようにしました。また、`HIERARHICAL` 属性に `BIDIRECTIONAL` を指定できるようになり、dictionary が親から children への索引をメモリ内に保持するため、`dictGetDescendants`、`dictGetChildren` 関数でクエリごとに一時索引を作成しなくなります。[#32481](https://github.com/ClickHouse/ClickHouse/issues/32481) をクローズします。 [#37148](https://github.com/ClickHouse/ClickHouse/pull/37148) ([Maksim Kita](https://github.com/kitaisreal)).
* Native、Protobuf、CapnProto、JSONEachRow、TSKV、および WithNames/WithNamesAndTypes という接尾辞を持つすべてのフォーマットについて、カラムのサブセットを select する際のパフォーマンスとメモリ使用量を改善しました。従来、これらのフォーマットのファイルからカラムの一部だけを select する場合でも、すべてのカラムが読み込まれてメモリに格納されていました。現在は必要なカラムのみが読み込まれます。この PR では、カラムのサブセットを select した場合に例外がスローされるのを防ぐため、`input_format_skip_unknown_fields` をデフォルトで有効にしています。 [#37192](https://github.com/ClickHouse/ClickHouse/pull/37192) ([Kruglov Pavel](https://github.com/Avogar)).
* 単一カラムでの sort のパフォーマンスを改善しました。 [#37195](https://github.com/ClickHouse/ClickHouse/pull/37195) ([Maksim Kita](https://github.com/kitaisreal)).
* hive ファイルの caching で複数の disks をサポートしました。 [#37279](https://github.com/ClickHouse/ClickHouse/pull/37279) ([lgbo](https://github.com/lgbo-ustc)).
* 配列ノルムおよび距離関数のパフォーマンスを 2～4 倍改善しました。 [#37394](https://github.com/ClickHouse/ClickHouse/pull/37394) ([Alexander Gololobov](https://github.com/davenger)).
* 動的ディスパッチを使用する数値比較関数のパフォーマンスを改善しました。 [#37399](https://github.com/ClickHouse/ClickHouse/pull/37399) ([Maksim Kita](https://github.com/kitaisreal)).
* LIMIT を伴う ORDER BY のパフォーマンスを改善しました。 [#37481](https://github.com/ClickHouse/ClickHouse/pull/37481) ([Maksim Kita](https://github.com/kitaisreal)).
* 動的ディスパッチ基盤を使用する `hasAll` 関数のパフォーマンスを改善しました。 [#37484](https://github.com/ClickHouse/ClickHouse/pull/37484) ([Maksim Kita](https://github.com/kitaisreal)).
* `greatCircleAngle`、`greatCircleDistance`、`geoDistance` 関数のパフォーマンスを改善しました。 [#37524](https://github.com/ClickHouse/ClickHouse/pull/37524) ([Maksim Kita](https://github.com/kitaisreal)).
* LIKE 関数や MATCH 関数などで使用される re2 pattern の内部 caching を最適化しました。 [#37544](https://github.com/ClickHouse/ClickHouse/pull/37544) ([Robert Schulze](https://github.com/rschu1ze)).
* avx512 命令を使用して、filter ビットマスク生成関数を一体的に改善しました。 [#37588](https://github.com/ClickHouse/ClickHouse/pull/37588) ([yaqi-zhao](https://github.com/yaqi-zhao)).
* 集約関数の引数としてスパースカラム (`MergeTree` テーブルで実験的な設定 `ratio_of_defaults_for_sparse_serialization` を有効にすると利用可能) を使用する場合の、集約処理のパフォーマンスを改善しました。[#37617](https://github.com/ClickHouse/ClickHouse/pull/37617) ([Anton Popov](https://github.com/CurtizJ)).
* 引数が 2 つの関数 `COALESCE` を最適化しました。[#37666](https://github.com/ClickHouse/ClickHouse/pull/37666) ([Anton Popov](https://github.com/CurtizJ)).
* `multiIf` に条件が 1 つしかない場合、より高性能な関数 `if` に置き換えるようにしました。[#37695](https://github.com/ClickHouse/ClickHouse/pull/37695) ([Anton Popov](https://github.com/CurtizJ)).
* 集約状態の破棄をスレッドプールに回せるようになりました。LIMIT を含み、状態が大きいクエリでは大幅な高速化が得られます。たとえば `select uniq(number) from numbers_mt(1e7) group by number limit 100` は約 2.5 倍高速になりました。[#37855](https://github.com/ClickHouse/ClickHouse/pull/37855) ([Nikita Taranov](https://github.com/nickitat)).
* ソートキューの特殊化により、単一カラムのソートのパフォーマンスを改善しました。[#37990](https://github.com/ClickHouse/ClickHouse/pull/37990) ([Maksim Kita](https://github.com/kitaisreal)).
* テーブル数が多い場合にバックグラウンドで発生する過剰な CPU 使用率を修正しました。[#38028](https://github.com/ClickHouse/ClickHouse/pull/38028) ([Maksim Kita](https://github.com/kitaisreal)).
* 動的ディスパッチにより `not` 関数のパフォーマンスを改善しました。[#38058](https://github.com/ClickHouse/ClickHouse/pull/38058) ([Maksim Kita](https://github.com/kitaisreal)).
* 主要ライブラリ向けに、NEON による高速化パスを多数追加しました。[#38093](https://github.com/ClickHouse/ClickHouse/pull/38093) ([Daniel Kutenin](https://github.com/danlark1)).

* 自己展開型の実行可能ファイルを追加。 [#34755](https://github.com/ClickHouse/ClickHouse/issues/34755). [#35775](https://github.com/ClickHouse/ClickHouse/pull/35775) ([Filatenkov Artur](https://github.com/FArthur-cmd)).

* disks 機能を追加( ls - ディスク上のファイルを一覧表示, C - 設定ファイルを指定, list-disks - ディスク名を一覧表示, disk - 名前で操作対象のディスクを指定, help - ヘルプメッセージを表示 copy - ディスク上の `from_path` にあるデータを `to_path` にコピー link - ディスク上で `from_path` から `to_path` へのハードリンクを作成 list - ディスク上のファイルを一覧表示 move - ディスク上のファイルまたはディレクトリを `from_path` から `to_path` に移動 read - ディスク上のファイル `from_path` を `to_path` または stdout に読み出し remove - ディスク上のファイルまたはディレクトリとその配下をすべて削除. write - ディスク上の`from_path`のファイル、または stdin を `to_path` に書き込み)。 [#36060](https://github.com/ClickHouse/ClickHouse/pull/36060) ([Artyom Yurkov](https://github.com/Varinara)).
* volume 内のディスク向けに `least_used` 負荷分散アルゴリズムを実装 (マルチディスク設定) 。 [#36686](https://github.com/ClickHouse/ClickHouse/pull/36686) ([Azat Khuzhin](https://github.com/azat)).
* * `send_progress_in_http_headers=0` のとき、HTTP endpoint が `X-ClickHouse-Summary` header で完全な統計を返すように変更しました (以前はすべて 0 を返していました) 。- 進行状況がすでに送信されている場合 (`send_progress_in_http_headers=1`) は、HTTP endpoint が `X-ClickHouse-Exception-Code` header を返すように変更しました - `TIMEOUT_EXCEEDED` error 時に、HTTP endpoint が `HTTP_INTERNAL_SERVER_ERROR` (500) ではなく `HTTP_REQUEST_TIMEOUT` (408) を返すように変更しました。 [#36884](https://github.com/ClickHouse/ClickHouse/pull/36884) ([Raúl Marín](https://github.com/Algunenano)).
* ユーザーが付与済みロールから grants を確認できるようにしました。[#36941](https://github.com/ClickHouse/ClickHouse/pull/36941) ([nvartolomei](https://github.com/nvartolomei)).
* 積分を数値計算せず、代わりに CDF 関数を使用するようにしました。これにより実行速度が向上し、精度も上がります。これにより [#36714](https://github.com/ClickHouse/ClickHouse/issues/36714) を修正しました。[#36953](https://github.com/ClickHouse/ClickHouse/pull/36953) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 関数に Nothing に対するデフォルト実装を追加しました。これにより、引数の 1 つが Nothing の場合、ほとんどの関数は型が Nothing のカラムを返すようになりました。また、引数に空の配列を取る arrayMap/arrayFilter などの関数に関する問題も解消されます。以前は `select arrayMap(x -> 2 * x, []);` のようなクエリは、lambda 内の関数が型 `Nothing` を扱えないため失敗していましたが、現在は型 `Array(Nothing)` の空配列を返します。さらに、arrayFilter/arrayFill などの関数で Nullable 型の配列もサポートしました。以前は `select arrayFilter(x -> x % 2, [1, NULL])` のようなクエリは失敗していましたが、現在は動作します (lambda の結果が NULL の場合、その値は結果に含まれません) 。[#37000](https://github.com/ClickHouse/ClickHouse/issues/37000) をクローズします。[#37048](https://github.com/ClickHouse/ClickHouse/pull/37048) ([Kruglov Pavel](https://github.com/Avogar)).
* 分片にローカルのレプリカがある場合、ローカルの実行計画と、すべてのリモートレプリカから読み取るための実行計画を作成するようになりました。これらは、読み取りを調整する共有イニシエーターを持ちます。[#37204](https://github.com/ClickHouse/ClickHouse/pull/37204) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 関数 CompressedWriteBuffer::nextImpl() には、データ挿入時に頻繁に発生する不要な書き込みコピーのステップがありました。この patch による違いは次のとおりです。- 変更前: 1. &quot;working&#95;buffer&quot; を &quot;compressed&#95;buffer&quot; に圧縮 2. それを &quot;out&quot; に書き込みコピー - 変更後: &quot;working&#95;buffer&quot; を直接 &quot;out&quot; に圧縮。[#37242](https://github.com/ClickHouse/ClickHouse/pull/37242) ([jasperzhu](https://github.com/jinjunzh)).
* 非定数の SQL 関数 (NOT) (I)LIKE および MATCH をサポートしました。[#37251](https://github.com/ClickHouse/ClickHouse/pull/37251) ([Robert Schulze](https://github.com/rschu1ze)).
* Client は、接続に成功するまで DNS resolution で返されたすべての IP アドレスを順に試行するようになりました。[#37273](https://github.com/ClickHouse/ClickHouse/pull/37273) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* * 設定オプション &quot;mark&#95;cache&#95;size&quot; が明示的に設定されていなくても、サーバーの起動を中止しないようにしました。 [#37326](https://github.com/ClickHouse/ClickHouse/pull/37326) ([Robert Schulze](https://github.com/rschu1ze)).
* Arrow/Parquet/ORC フォーマットで、Binary の代わりに String type を使用できるようにしました。この PR では、そのための 3 つの新しい設定 `output_format_arrow_string_as_string`、`output_format_parquet_string_as_string`、`output_format_orc_string_as_string` を導入しています。これらすべての設定のデフォルト値は `false` です。[#37327](https://github.com/ClickHouse/ClickHouse/pull/37327) ([Kruglov Pavel](https://github.com/Avogar)).
* 設定 `input_format_max_rows_to_read_for_schema_inference` を、glob 内の各ファイルごとではなく、すべてのファイルから読み取る合計行数に対して適用するようにしました。以前はこの設定が glob 内の各ファイルに個別に適用されていたため、nulls が非常に多い場合、各ファイルの先頭 `input_format_max_rows_to_read_for_schema_inference` 行を読んでも何も得られないことがありました。あわせて、この設定のデフォルト値を 25000 に引き上げました。[#37332](https://github.com/ClickHouse/ClickHouse/pull/37332) ([Kruglov Pavel](https://github.com/Avogar)).
* カラム宣言で、型の直後に `NULL`/`NOT NULL` を指定できるようにしました。[#37337](https://github.com/ClickHouse/ClickHouse/pull/37337) ([Igor Nikonov](https://github.com/devcrafter)).
* file segment PARTIALLY&#95;DOWNLOADED の読み取りバッファ取得を最適化しました。[#37338](https://github.com/ClickHouse/ClickHouse/pull/37338) ([chen](https://github.com/xiedeyantu)).
