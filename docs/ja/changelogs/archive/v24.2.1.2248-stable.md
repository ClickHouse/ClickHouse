<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* ネストされた型内の疑わしい型や実験的な型を検証するようにしました。従来は、Array/Tuple/Map のようなネストされた型内では、そのような型 (JSON を除く) は検証していませんでした。 [#59385](https://github.com/ClickHouse/ClickHouse/pull/59385) ([Kruglov Pavel](https://github.com/Avogar)).
* ソート句 `ORDER BY ALL` (v23.12 で導入) は `ORDER BY *` に置き換えられました。従来の構文は、`all` というカラムを持つテーブルではエラーを起こしやすすぎました。 [#59450](https://github.com/ClickHouse/ClickHouse/pull/59450) ([Robert Schulze](https://github.com/rschu1ze)).
* 設定 `extract_kvp_max_pairs_per_row` を `extract_key_value_pairs_max_pairs_per_row` にリネームしました。このバグ (設定名で不要な略語を使っていたこと) は https://github.com/ClickHouse/ClickHouse/pull/43606 で導入されました。この設定のドキュメントも修正しました。 [#59683](https://github.com/ClickHouse/ClickHouse/pull/59683) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 設定 `extract_kvp_max_pairs_per_row` を `extract_key_value_pairs_max_pairs_per_row` にリネームしました。このバグ (設定名で不要な略語を使っていたこと) は https://github.com/ClickHouse/ClickHouse/pull/43606 で導入されました。この設定のドキュメントも修正しました。 [#59960](https://github.com/ClickHouse/ClickHouse/pull/59960) ([jsc0218](https://github.com/jsc0218)).
* スレッド数とブロックサイズに対する妥当性チェックを追加しました。 [#60138](https://github.com/ClickHouse/ClickHouse/pull/60138) ([Raúl Marín](https://github.com/Algunenano)).



<div id="new-feature">
  #### 新機能
</div>

* QUOTA に最大連続ログイン失敗回数を追加しました。 [#54737](https://github.com/ClickHouse/ClickHouse/pull/54737) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* View/Materialized View で definer user を指定できる新しい構文を追加しました。これにより、基になるテーブルに対する明示的な grant なしで、ビューからの SELECT/INSERT を実行できます。 [#54901](https://github.com/ClickHouse/ClickHouse/pull/54901) ([pufit](https://github.com/pufit)).
* AzureBlobStorage に対する Backup &amp; Restore のサポートにより、[#50747](https://github.com/ClickHouse/ClickHouse/issues/50747) を解決しました。 [#56988](https://github.com/ClickHouse/ClickHouse/pull/56988) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 異なる種類の MergeTree テーブルを Replicated エンジンに自動変換する機能を実装しました。テーブルのデータディレクトリ (`/clickhouse/store/xxx/xxxyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy/`) に空の `convert_to_replicated` ファイルを作成すると、そのテーブルは次回の server 起動時に自動的に変換されます。 [#57798](https://github.com/ClickHouse/ClickHouse/pull/57798) ([Kirill](https://github.com/kirillgarbar)).
* table function `mergeTreeIndex` を追加しました。これは `MergeTree` テーブルの 索引 および marks ファイルの内容を表します。イントロスペクションに使用できます。Syntax: `mergeTreeIndex(database, table, [with_marks = true])`。ここで `database.table` は `MergeTree` エンジンを持つ既存のテーブルです。 [#58140](https://github.com/ClickHouse/ClickHouse/pull/58140) ([Anton Popov](https://github.com/CurtizJ)).
* Tukey&#39;s fences アルゴリズムを使用して時系列データの外れ値を検出する関数 `seriesOutliersTukey` を追加しました。 [#58632](https://github.com/ClickHouse/ClickHouse/pull/58632) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* ユーザーは `format_template_row` の代わりに `format_schema_rows_template` を使用して、クエリ内で template string を直接指定できるようになりました。[#31363](https://github.com/ClickHouse/ClickHouse/issues/31363) をクローズします。 [#59088](https://github.com/ClickHouse/ClickHouse/pull/59088) ([Shaun Struwig](https://github.com/Blargian)).
* `file/s3/hdfs/url/azureBlobStorage` エンジンで file format が不明な場合、schema inference 中に自動検出を試みるようにしました。[#50576](https://github.com/ClickHouse/ClickHouse/issues/50576) をクローズします。 [#59092](https://github.com/ClickHouse/ClickHouse/pull/59092) ([Kruglov Pavel](https://github.com/Avogar)).
* 各行について Variant 型 の型名に対応する Enum を返す関数 `variantType` を追加しました。 [#59398](https://github.com/ClickHouse/ClickHouse/pull/59398) ([Kruglov Pavel](https://github.com/Avogar)).
* 空のパーティションに関連する ZooKeeper ノードを削除するクエリ `ALTER TABLE table FORGET PARTITION partition` を追加しました。 [#59507](https://github.com/ClickHouse/ClickHouse/pull/59507) ([Sergei Trifonov](https://github.com/serxa)).
* NATS table engine で JWT credentials file をサポートしました。 [#59543](https://github.com/ClickHouse/ClickHouse/pull/59543) ([Nickolaj Jepsen](https://github.com/nickolaj-jepsen)).
* 新しい aggregate function `groupArrayIntersect` を追加しました。関連: [#49862](https://github.com/ClickHouse/ClickHouse/issues/49862)。 [#59598](https://github.com/ClickHouse/ClickHouse/pull/59598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* DNS の問題のデバッグに役立つ `system.dns_cache` テーブルを実装しました。 [#59856](https://github.com/ClickHouse/ClickHouse/pull/59856) ([Kirill Nikiforov](https://github.com/allmazz)).
* コーデック `LZ4HC` が新たにレベル 2 を受け付けるようになりました。これは、圧縮率は下がるものの、これまでの最小レベル 3 より高速です。以前のバージョンでは、`LZ4HC(2)` 以下は `LZ4HC(3)` と同じ扱いでした。著者: [Cyan4973](https://github.com/Cyan4973). [#60090](https://github.com/ClickHouse/ClickHouse/pull/60090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* DNS の問題のデバッグに役立つ system.dns&#95;cache テーブルを実装しました。新しいサーバー設定 dns&#95;cache&#95;max&#95;size も追加されました。 [#60257](https://github.com/ClickHouse/ClickHouse/pull/60257) ([Kirill Nikiforov](https://github.com/allmazz)).
* merge table function で、`merge(['db_name', ] 'tables_regexp')` のような 1 引数版をサポートしました。 [#60372](https://github.com/ClickHouse/ClickHouse/pull/60372) ([豪肥肥](https://github.com/HowePa)).
* View/Materialized View で definer user を指定できる新しい構文を追加しました。これにより、基になるテーブルに対する明示的な grants がなくても、views 経由で selects/inserts を実行できます。 [#60439](https://github.com/ClickHouse/ClickHouse/pull/60439) ([pufit](https://github.com/pufit)).

[#58486](https://github.com/ClickHouse/ClickHouse/pull/58486) ([Julia Kartseva](https://github.com/jkartseva)).

* T64 codec で Date32 型をサポートしました。 [#58738](https://github.com/ClickHouse/ClickHouse/pull/58738) ([Hongbin Ma (Mahone)](https://github.com/binmahone)).
* 並列レプリカで `LEFT JOIN`、`ALL INNER JOIN`、および単純なサブクエリをサポートしました (アナライザ使用時のみ) 。新しい設定 `parallel_replicas_prefer_local_join` では、ローカル `JOIN` 実行 (デフォルト) と `GLOBAL JOIN` のどちらを使用するかを選択できます。すべてのテーブルは `cluster_for_parallel_replicas` のすべてのレプリカ上に存在している必要があります。新しい設定 `min_external_table_block_size_rows` と `min_external_table_block_size_bytes` は、一時テーブル向けに送信される小さなブロックをまとめるために使用されます (アナライザ使用時のみ) 。 [#58916](https://github.com/ClickHouse/ClickHouse/pull/58916) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 複数の項目を持つ型で、末尾のカンマを許可しました。 [#59119](https://github.com/ClickHouse/ClickHouse/pull/59119) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* `S3Queue` テーブルエンジンで並列処理および分散処理を利用できるようにしました。分散処理には設定 `s3queue_total_shards_num` (デフォルトは `1`) を使用します。これまで Ordered processing mode では設定 `s3queue_processing_threads_num` は使用できませんでしたが、現在は使用可能です。警告: ordered mode における設定 `s3queue_processing_threads_num` (各分片あたりの処理スレッド数) および `s3queue_total_shards_num` は、メタデータの保存方法を変更します (`max_processed_file` ノード数が `s3queue_processing_threads_num * s3queue_total_shards_num` に等しくなります) 。そのため、これらの値はすべての分片で同一である必要があり、少なくとも 1 つの分片が作成された後は変更できません。[#59167](https://github.com/ClickHouse/ClickHouse/pull/59167) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `recoverLostReplica` 中に `DatabaseReplicated` でのテーブルの同時作成を可能にしました。[#59277](https://github.com/ClickHouse/ClickHouse/pull/59277) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* Distributed テーブルエンジンの設定をサーバー設定ファイルで指定できるようになりました (MergeTree settings と同様) 。例: `<distributed> <flush_on_detach>false</flush_on_detach> </distributed>`。[#59291](https://github.com/ClickHouse/ClickHouse/pull/59291) ([Azat Khuzhin](https://github.com/azat)).
* デフォルトのテーブルエンジンとして MergeTree を使用するようにしました。これにより使い勝手が大幅に向上し、ClickHouse Cloud により近い動作になります。[#59316](https://github.com/ClickHouse/ClickHouse/pull/59316) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `system.zookeeper` の読み取り時に、切断や期限切れのセッションを再試行するようにしました。これは、特に障害注入による切断がある状況で `system.zookeeper` テーブルから多数の行を読み取る場合に役立ちます。[#59388](https://github.com/ClickHouse/ClickHouse/pull/59388) ([Alexander Gololobov](https://github.com/davenger)).
* `input_format_values_interpret_expressions=0` の場合、先頭に 0 が付いた数値を 8 進数として解釈しないようにしました。[#59403](https://github.com/ClickHouse/ClickHouse/pull/59403) ([Joanna Hulboj](https://github.com/jh0x)).
* 起動時および設定ファイルが変更されるたびに、ClickHouse は total memory tracker のハードメモリ制限を更新するようになりました。これらの制限は、各種サーバー設定と cgroups の制限 (Linux 上) に基づいて計算されます。以前は `/sys/fs/cgroup/memory.max` (cgroups v2 用) がハードコードされていました。その結果、ネストされたグループ (階層) 向けに設定された cgroup v2 のメモリ制限、たとえば `/sys/fs/cgroup/my/nested/group/memory.max` は無視されていました。現在は修正されています。v1 のメモリ制限の挙動は変わりません。[#59435](https://github.com/ClickHouse/ClickHouse/pull/59435) ([Robert Schulze](https://github.com/rschu1ze)).
* `INSERT` 時に PK/projections/セカンダリ索引 の計算に費やされた時間を観測するため、新しい profile events を追加しました。[#59436](https://github.com/ClickHouse/ClickHouse/pull/59436) ([Nikita Taranov](https://github.com/nickitat)).
* 設定 `s3queue_last_processed_path` を使って、作成時に Ordered mode の S3Queue の開始位置を指定できるようにしました。[#59446](https://github.com/ClickHouse/ClickHouse/pull/59446) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Keeper の改善: `latest_logs_cache_size_threshold` および `commit_logs_cache_size_threshold` で制御される一定量の logs のみをメモリ内に cache するようにしました。[#59460](https://github.com/ClickHouse/ClickHouse/pull/59460) ([Antonio Andelic](https://github.com/antonio2368)).
* `clickhouse-local` の `system.tables` でもシステムテーブルの comments を利用できるようにしました。[#59493](https://github.com/ClickHouse/ClickHouse/pull/59493) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* デフォルトでは、指数表記の浮動小数点数を推論しないようにしました。以前の挙動を復元する設定 `input_format_try_infer_exponent_floats` を追加しました (デフォルトでは無効) 。Closes [#59476](https://github.com/ClickHouse/ClickHouse/issues/59476). [#59500](https://github.com/ClickHouse/ClickHouse/pull/59500) ([Kruglov Pavel](https://github.com/Avogar)).
* alter 操作を括弧で囲めるようにしました。括弧を出力するかどうかは `format_alter_operations_with_parentheses` config で制御できます。デフォルトでは、整形されたクエリでは括弧が出力されます。これは、整形済みの alter 操作を一部の箇所でメタデータとして保存しているためです (例: mutations) 。新しい構文により、alter 操作がリストで終わる一部のクエリがより明確になります。たとえば、`ALTER TABLE x MODIFY TTL date GROUP BY a, b, DROP COLUMN c` は古い構文では正しく解析できません。新しい構文では、クエリ `ALTER TABLE x (MODIFY TTL date GROUP BY a, b), (DROP COLUMN c)` の意図が明確です。古いバージョンは新しい構文を読み取れないため、新旧のバージョンの ClickHouse が単一のクラスター内で混在している場合、この新しい構文を使うと問題が発生する可能性があります。 [#59532](https://github.com/ClickHouse/ClickHouse/pull/59532) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* `async_insert_max_data_size` の従来のデフォルト値である 1 MB は小さすぎることが分かりました。新しい値は 10 MiB です。 [#59536](https://github.com/ClickHouse/ClickHouse/pull/59536) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
