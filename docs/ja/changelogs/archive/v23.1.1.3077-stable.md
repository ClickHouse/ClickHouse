<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* クエリ `SYSTEM RESTART DISK` を削除しました。 [#44647](https://github.com/ClickHouse/ClickHouse/pull/44647) ([alesapin](https://github.com/alesapin)).
* Float32 型でも Float64 型でもないカラムに対する Gorilla 圧縮を禁止しました。 [#45252](https://github.com/ClickHouse/ClickHouse/pull/45252) ([Robert Schulze](https://github.com/rschu1ze)).
* HASHED/SPARSE&#95;HASHED 辞書の PREALLOCATE を削除しました。 [#45388](https://github.com/ClickHouse/ClickHouse/pull/45388) ([Azat Khuzhin](https://github.com/azat)).
* 非推奨の構文で作成された `*MergeTree` テーブルでは、並列クォーラムインサートが正しく動作しない可能性があります。そのため、このようなテーブルに対する並列クォーラムインサートのサポートは完全に無効化されました。新しい構文で作成されたテーブルには影響しません。 [#45430](https://github.com/ClickHouse/ClickHouse/pull/45430) ([Alexander Tokmakov](https://github.com/tavplubix)).

* `quantileInterpolatedWeighted`/`quantilesInterpolatedWeighted` 関数を追加しました。[#38252](https://github.com/ClickHouse/ClickHouse/pull/38252) ([Bharat Nallan](https://github.com/bharatnc)).
* 効率的なテキスト検索に向けた新しいセカンダリ索引タイプとして、実験的な転置索引を追加しました。[#38667](https://github.com/ClickHouse/ClickHouse/pull/38667) ([larryluogit](https://github.com/larryluogit)).

* 正規表現ツリーをたどってキーを抽出するための Dictionary ソースを追加しました。[#40878](https://github.com/ClickHouse/ClickHouse/pull/40878) ([Vage Ogannisian](https://github.com/nooblose)).
* パラメーター化ビュー機能を追加し、View table engine に対してクエリパラメータを指定できるようになりました。[#40907](https://github.com/ClickHouse/ClickHouse/issues/40907) を解決します。[#41687](https://github.com/ClickHouse/ClickHouse/pull/41687) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).

* `Replicated` database の停止したレプリカのメタデータを削除する `SYSTEM DROP DATABASE REPLICA` を追加しました。[#41794](https://github.com/ClickHouse/ClickHouse/issues/41794) を解決します。[#42807](https://github.com/ClickHouse/ClickHouse/pull/42807) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Spark の explode 関数のように、ARRAY JOIN が Map type をサポートするようになりました。[#43239](https://github.com/ClickHouse/ClickHouse/pull/43239) ([李扬](https://github.com/taiyang-li)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* HashedDictionary に分片のサポートを追加し、並列ロードを可能にしました (分片数に応じて、ほぼ線形にスケールします) 。 [#40003](https://github.com/ClickHouse/ClickHouse/pull/40003) ([Azat Khuzhin](https://github.com/azat)).
* `MergeTree` テーブルの起動時に、非アクティブなパーツを読み込まないようにしました。 [#42181](https://github.com/ClickHouse/ClickHouse/pull/42181) ([Anton Popov](https://github.com/CurtizJ)).
* * クエリのパースを高速化しました。[#42284](https://github.com/ClickHouse/ClickHouse/pull/42284) ([Raúl Marín](https://github.com/Algunenano)).
* `expr` が `LowCardinality` カラムの場合、OR チェーン `expr = x1 OR ... OR expr = xN` は常に `expr IN (x1, ..., xN)` に置き換えられます。この場合、設定 `optimize_min_equality_disjunction_chain_length` は無視されます。 [#42889](https://github.com/ClickHouse/ClickHouse/pull/42889) ([Guo Wangyang](https://github.com/guowangy)).
* > 元の変更履歴 元の実装では、ThreadGroupStatus:: finished&#95;threads&#95;counters&#95;memory のメモリは、一時的な std::vector に移動することで解放されており、その一時オブジェクトはほどなく寿命を迎えて破棄されます。この方法でも問題なく動作しますが、やや分かりにくい実装です。コードの可読性を高めるため、このコミットでは、まず vector のサイズを 0 にしてから capacity を縮小することで、vector が確保しているメモリを解放するようにしました。 [#43586](https://github.com/ClickHouse/ClickHouse/pull/43586) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* [#42214](https://github.com/ClickHouse/ClickHouse/issues/42214) の後続対応として、この PR では自動ベクトル化の実現により、カラム単位の三値論理評価の最適化を図っています。この [マイクロベンチマーク](https://github.com/ZhiguoZh/ClickHouse/blob/20221123-ternary-logic-opt-example/src/Functions/examples/associative_applier_perf.cpp) の性能テストでは、ICX デバイス (Intel Xeon Platinum 8380 CPU) で最大 **21 倍**の**性能向上**が確認されました。 [#43669](https://github.com/ClickHouse/ClickHouse/pull/43669) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 多数の小さなファイルがある場合の storage `S3` および table function `s3` からの読み取りレイテンシを改善しました。これにより、storage `S3` からの読み取り時に設定 `remote_filesystem_read_method` と `remote_filesystem_read_prefetch` が有効になりました。 [#43726](https://github.com/ClickHouse/ClickHouse/pull/43726) ([Anton Popov](https://github.com/CurtizJ)).
* * 可能な場合は、system.tables で閲覧ロックを取得しないようにした。 [#43840](https://github.com/ClickHouse/ClickHouse/pull/43840) ([Raúl Marín](https://github.com/Algunenano)).
* ICX デバイス (Intel Xeon Platinum 8380 CPU、80 コア、160 スレッド) での SSB (Star Schema Benchmark) の性能評価では、この変更により ThreadPoolImpl::mutex のロック競合を **75%** 削減でき、CPU 使用率が向上し、全体の性能が **2.4%** 改善されることが示されました。 [#44308](https://github.com/ClickHouse/ClickHouse/pull/44308) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 現在は、キャッシュされた HT サイズが十分に大きい場合にのみ最適化が適用されます (しきい値は経験的に決定され、ハードコードされています) 。 [#44455](https://github.com/ClickHouse/ClickHouse/pull/44455) ([Nikita Taranov](https://github.com/nickitat)).
* ... 現状では、構造体の 1 つのフィールドだけを読み取りたい場合でも、構造体フィールド全体が読み込まれます。 [#44484](https://github.com/ClickHouse/ClickHouse/pull/44484) ([lgbo](https://github.com/lgbo-ustc)).
* remote fs からの非同期読み取りのパフォーマンスをわずかに改善しました。 [#44868](https://github.com/ClickHouse/ClickHouse/pull/44868) ([Kseniia Sumarokova](https://github.com/kssenii)).
* より高速な共有 (RW) mutex 実装に切り替えました。スレッド同期が多いクエリや、競合の激しいデータ構造では、性能が向上する可能性があります。 [#45007](https://github.com/ClickHouse/ClickHouse/pull/45007) ([Sergei Trifonov](https://github.com/serxa)).
* 次に対する fast path を追加しました: - col like &#39;%%&#39; - col like &#39;%&#39; - col not like &#39;%&#39; - col not like &#39;%&#39; - match(col, &#39;.*&#39;). [#45244](https://github.com/ClickHouse/ClickHouse/pull/45244) ([李扬](https://github.com/taiyang-li)).
* todo。 [#45289](https://github.com/ClickHouse/ClickHouse/pull/45289) ([Nikita Taranov](https://github.com/nickitat)).

<div id="improvement">
  #### 改善

* Kafka/RabbitMQ/NATS のストリーミングエンジンをリファクタリングして改善し、すべてのフォーマットをサポートするようにしました。また、フォーマットにも若干のリファクタリングを加えました: - 接尾辞/プレフィックス付きの行ベースフォーマットでメッセージを生成する際の不具合を修正しました。これにより、各メッセージはすべての区切り文字を含めて完全にフォーマットされ、入力フォーマットで再度パースできるようになりました。 - Native、Parquet、ORC などのブロックベースフォーマットをサポートしました。各ブロックは個別のメッセージとしてフォーマットされます。1 つのメッセージ内の行数はブロックサイズに依存するため、設定 `max_block_size` で制御できます。 - 新しいエンジン設定 `kafka_max_rows_per_message/rabbitmq_max_rows_per_message/nats_max_rows_per_message` を追加しました。これらは、行ベースフォーマットで 1 つのメッセージにフォーマットされる行数を制御します。デフォルト値は 1 です。 - NATS テーブルエンジンでのメモリ消費量が多い問題を修正しました。 - NATS producer で任意のバイナリデータをサポートしました (以前は末尾に \0 を含む文字列でしか動作しませんでした) 。 - ドキュメントに不足していた Kafka/RabbitMQ/NATS エンジン設定を追加しました。 - Kafka/RabbitMQ/NATS での生成と消費をリファクタリングし、WriteBuffers/ReadBuffers のセマンティクスから分離しました。 - 出力フォーマットをリファクタリングしました: Kafka/RabbitMQ/NATS で各行ごとに使用していたコールバックを削除し (現在はそこでコールバックを使用していません) 、IRowOutputFormat を直接使用できるようにし、行末の区切り文字と行間の区切り文字を明確にし、出力フォーマットをリセットして再度フォーマットを開始できるようにしました - formatRow 関数に適切な実装を追加しました (フォーマットのリファクタリング後の追加改善) 。 [#42777](https://github.com/ClickHouse/ClickHouse/pull/42777) ([Kruglov Pavel](https://github.com/Avogar)).
* 新しいインフラストラクチャで `optimize_or_like_chain` をサポートしました。 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) の一部です。 [#42797](https://github.com/ClickHouse/ClickHouse/pull/42797) ([Dmitry Novik](https://github.com/novikd)).
* Asterisk および ColumnMatcher パーサーを改善しました。 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) の一部です。 [#42884](https://github.com/ClickHouse/ClickHouse/pull/42884) ([Nikolay Degterinsky](https://github.com/evillique)).
* QueryTree ベースで `optimize_redundant_functions_in_order_by` を実装しました。 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) の一部です。 [#42970](https://github.com/ClickHouse/ClickHouse/pull/42970) ([Dmitry Novik](https://github.com/novikd)).
* 新しいアナライザアーキテクチャで `optimize_group_by_function_keys` をサポートしました。あわせて、GROUPING SETS のキー最適化もサポートしました。 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) の一部です。 [#43261](https://github.com/ClickHouse/ClickHouse/pull/43261) ([Dmitry Novik](https://github.com/novikd)).

* CapnProto フォーマットで `Nested` テーブルを `Struct` の `List` として読み書きできるようにしました。`Decimal32/64` は `Int32/64` として読み書きします。 [#43319](https://github.com/ClickHouse/ClickHouse/issues/43319) をクローズしました。 [#43379](https://github.com/ClickHouse/ClickHouse/pull/43379) ([Kruglov Pavel](https://github.com/Avogar)).

* 冗長なソートを削除しました。たとえば、サブクエリ内の ORDER BY clause に関連するソートです。これはクエリプラン上に実装されています。`ORDER BY` clause に関しては `optimize_duplicate_order_by_and_distinct` と同様の最適化を行いますが、より汎用的です。というのも、ORDER BY clause が原因のものに限らず、あらゆる冗長なソート手順に適用され、さらに任意の深さのサブクエリにも適用されるためです。[#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) に関連します。[#43905](https://github.com/ClickHouse/ClickHouse/pull/43905) ([Igor Nikonov](https://github.com/devcrafter)).
