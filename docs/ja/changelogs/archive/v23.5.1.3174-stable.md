<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* ローカルオブジェクトストレージが S3 オブジェクトストレージと一貫した動作をするようにし、append に関する問題を修正し ([#48465](https://github.com/ClickHouse/ClickHouse/issues/48465) をクローズ) 、独立したストレージとして設定できるようにしました。この変更は後方互換性がありません。ローカルオブジェクトストレージ上の cache が以前のバージョンと互換性がないためです。[#48791](https://github.com/ClickHouse/ClickHouse/pull/48791) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Date&#95;trunc 関数が常に DateTime 型を返すようにしました。[#48851](https://github.com/ClickHouse/ClickHouse/pull/48851) ([Shane Andrade](https://github.com/mauidude)).
* 実験的機能「in-memory data parts」を削除しました。データフォーマット自体は引き続きサポートされますが、設定は no-op となり、代わりに compact パーツ または wide パーツ が使用されます。これにより [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409) をクローズします。[#49429](https://github.com/ClickHouse/ClickHouse/pull/49429) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 設定 parallelize&#95;output&#95;from&#95;storages および input&#95;format&#95;parquet&#95;preserve&#95;order のデフォルト値を変更しました。これにより、ClickHouse はファイル (CSV や Parquet など) から読み取る際に行を並べ替えられるようになり、多くのケースでパフォーマンスが大幅に向上します。順序を保持する以前の動作に戻すには、`parallelize_output_from_storages = 0`、`input_format_parquet_preserve_order = 1` を使用してください。[#49479](https://github.com/ClickHouse/ClickHouse/pull/49479) ([Michael Kolupaev](https://github.com/al13n321)).
* projections を本番環境で利用可能にしました。SELECT クエリに対して projections を選択するかどうかを制御するため、`optimize_use_projections` 設定を追加しました。`allow_experimental_projection_optimization` 設定は廃止されたもので、何も行いません。[#49719](https://github.com/ClickHouse/ClickHouse/pull/49719) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* joinGet() を非決定論的としてマークしました (dictGet も同様) 。[#49843](https://github.com/ClickHouse/ClickHouse/pull/49843) ([Azat Khuzhin](https://github.com/azat)).
* 「`groupArray` returns cannot be nullable」を取り消しました (`Nullable` 型に対する `groupArray`/`groupArrayLast`/`groupArraySample` のバイナリ互換性が壊れ、`TOO_LARGE_ARRAY_SIZE` または `CANNOT_READ_ALL_DATA` につながる可能性が高いためです) 。[#49971](https://github.com/ClickHouse/ClickHouse/pull/49971) ([Azat Khuzhin](https://github.com/azat)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* デフォルトでマークと主キーを圧縮するようにしました。これにより、コールドクエリの実行時間が大幅に短縮されます。アップグレードに関する注意: 圧縮マークおよび圧縮主キーのサポートはバージョン 22.9 で追加されました。圧縮マークまたは圧縮主キーを有効にした場合、あるいはこれらがデフォルトで有効になっているバージョン 23.5 以降をインストールした場合は、22.8 以前のバージョンにダウングレードできなくなります。`<merge_tree>` セクションのサーバー設定ファイルで `compress_marks` および `compress_primary_key` 設定を指定することで、圧縮マークまたは圧縮主キーを明示的に無効にすることもできます。**アップグレードに関する注意:** 22.9 より前のバージョンからアップグレードする場合は、すべてのレプリカを一度にアップグレードするか、アップグレード前に圧縮を無効にするか、あるいは 23.3 のような、圧縮マークはサポートしているもののデフォルトでは有効になっていない中間バージョンを経由してアップグレードする必要があります。[#42587](https://github.com/ClickHouse/ClickHouse/pull/42587) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 複数のファイルから読み取る際に、各ファイルごとの並列パーススレッド数を減らすようにし、[#42192](https://github.com/ClickHouse/ClickHouse/issues/42192) を解決しました。[#46661](https://github.com/ClickHouse/ClickHouse/pull/46661) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 何も挿入されない場合は、`ANY` ハッシュ結合にブロックを格納しないようにしました。[#48633](https://github.com/ClickHouse/ClickHouse/pull/48633) ([vdimir](https://github.com/vdimir)).
* JIT コンパイル時の aggregate combinator `-If` を修正しました。[#48120](https://github.com/ClickHouse/ClickHouse/issues/48120) をクローズします。[#49083](https://github.com/ClickHouse/ClickHouse/pull/49083) ([Igor Nikonov](https://github.com/devcrafter)).
* リモートテーブルからの読み取りでは、ワークスティーリングを機能させるため、part 全体を読み取る代わりにより小さなタスクを使用するようにしました * タスクサイズは読み取るカラムのサイズによって決まります * S3 からの読み取りでは常に 1mb バッファを使用します * cache セグメントの境界を 1mb に揃えることで、小さなタスクでも十分なサイズを確保できます。これにより断片化の防止にもつながるはずです。[#49287](https://github.com/ClickHouse/ClickHouse/pull/49287) ([Nikita Taranov](https://github.com/nickitat)).
* local filesystem からの読み取りに使用する読み取りバッファのデフォルトサイズを、より適切な値に変更しました。また、2 つの新しい設定 `max_read_buffer_size_local_fs` と `max_read_buffer_size_remote_fs` が導入されました。[#49321](https://github.com/ClickHouse/ClickHouse/pull/49321) ([Nikita Taranov](https://github.com/nickitat)).
* `SPARSE_HASHED`/`HASHED` dictionaries のメモリ使用量と速度を改善しました (たとえば、`SPARSE_HASHED` は現在 2.6 倍少ないメモリで動作し、約 2 倍高速です) 。[#49380](https://github.com/ClickHouse/ClickHouse/pull/49380) ([Azat Khuzhin](https://github.com/azat)).
* aggregate projection は、通常の読み取りよりも少ないグラニュールを読む場合にのみ使用するようにしました。これは、クエリがテーブルの主キーにはヒットするものの、projection にはヒットしない場合に有効です。[#49150](https://github.com/ClickHouse/ClickHouse/issues/49150) を修正しました。[#49417](https://github.com/ClickHouse/ClickHouse/pull/49417) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* PODArray::resize&#95;fill() の呼び出し元を最適化しました。[#49459](https://github.com/ClickHouse/ClickHouse/pull/49459) ([Azat Khuzhin](https://github.com/azat)).
* 適切な場合に LowCardinality を適用して、system.query&#95;log および system.query&#95;thread&#95;log ログテーブルを最適化しました。これらのテーブルに対するクエリはより高速になります。[#49530](https://github.com/ClickHouse/ClickHouse/pull/49530) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* local Parquet files の読み取り性能を改善しました (並列読み取りによるものです) 。[#49539](https://github.com/ClickHouse/ClickHouse/pull/49539) ([Michael Kolupaev](https://github.com/al13n321)).
* 特定の状況において `RIGHT/FULL JOIN` の性能を最大 2 倍向上させました。特に、小さい左テーブルと大きい右テーブルを join する場合に効果があります。 [#49585](https://github.com/ClickHouse/ClickHouse/pull/49585) ([lgbo](https://github.com/lgbo-ustc)).
