  # 2023年 変更履歴

<div id="clickhouse-release-v231011976-stable-13adae0e42f-fixme-as-compared-to-v23911854-stable-8f9a227de1f">
  ### ClickHouse リリース v23.10.1.1976-stable (13adae0e42f) FIXME v23.9.1.1854-stable (8f9a227de1f) との比較
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* S3Queue ストレージを全面的に書き直しました。ZooKeeper で情報を保持する方法を変更し、ZooKeeper へのリクエスト数を削減しました。また、状態が変わらないことがわかっている場合には ZooKeeper の状態をキャッシュするようにし、S3 からのポーリング処理が過度に積極的にならないよう改善しました。さらに、追跡対象ファイルに対する TTL と max の管理方法を変更し、現在はバックグラウンドプロセスで処理されるようになっています。`system.s3queue` と `system.s3queue_log` テーブルを追加しました。[#54998](https://github.com/ClickHouse/ClickHouse/issues/54998) をクローズします。[#54422](https://github.com/ClickHouse/ClickHouse/pull/54422) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 壊れたデータパーツを自動的に削除するオプションは廃止されました。これにより [#55174](https://github.com/ClickHouse/ClickHouse/issues/55174) はクローズされます。[#55184](https://github.com/ClickHouse/ClickHouse/pull/55184) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 廃止されたインメモリのデータパーツは、先行書き込みログから読み取れなくなりました。以前にインメモリのパーツを設定していた場合は、アップグレード前に削除する必要があります。[#55186](https://github.com/ClickHouse/ClickHouse/pull/55186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Meilisearch とのインテグレーションを削除しました。理由: 古いバージョン 0.18 にしか対応していなかったためです。最近の Meilisearch ではプロトコルが変更され、現在は動作しません。注: これを復活させるためのご協力をいただけると幸いです。[#55189](https://github.com/ClickHouse/ClickHouse/pull/55189) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* directory monitor の概念を background INSERT にリネームしました。すべての `*directory_monitor*` 設定は `distributed_background_insert*` にリネームされました。**後方互換性は維持されます** (古い設定は alias として追加されているため) 。[#55978](https://github.com/ClickHouse/ClickHouse/pull/55978) ([Azat Khuzhin](https://github.com/azat)).
* send&#95;timeout と receive&#95;timeout を取り違えないようにしました。[#56035](https://github.com/ClickHouse/ClickHouse/pull/56035) ([Azat Khuzhin](https://github.com/azat)).
* 単位の異なるインターバル同士の比較は、例外をスローするようになります。これにより [#55942](https://github.com/ClickHouse/ClickHouse/issues/55942) はクローズされます。これまでは、単位に関係なく基になる numeric values が比較される以前の動作に、場合によっては依存していた可能性があります。[#56090](https://github.com/ClickHouse/ClickHouse/pull/56090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新機能
</div>

* 同じカーディナリティを持つ複数の配列にラムダ関数を適用し、その結果をアキュムレータに集約する関数 &quot;arrayFold(x1, ..., xn, accum -&gt; expression, array1, ..., arrayn, init&#95;accum)&quot; を追加しました。[#49794](https://github.com/ClickHouse/ClickHouse/pull/49794) ([Lirikl](https://github.com/Lirikl)).
* 可視化のためにデータをダウンサンプリングする [Largest-Triangle-Three-Buckets](https://skemman.is/bitstream/1946/15343/3/SS_MSthesis.pdf) アルゴリズムを使用する集約関数 lttb を追加しました。[#53145](https://github.com/ClickHouse/ClickHouse/pull/53145) ([Sinan](https://github.com/sinsinan)).
* `CHECK TABLE` クエリの性能と使い勝手が向上しました (進捗更新を送信し、キャンセル可能です) 。また、`CHECK TABLE ... PART 'part_name'` による特定の part のチェックもサポートしました。[#53404](https://github.com/ClickHouse/ClickHouse/pull/53404) ([vdimir](https://github.com/vdimir)).
* 関数 `jsonMergePatch` を追加しました。JSON データを文字列として扱う場合、これらの文字列 (JSON オブジェクトを表す文字列) をマージし、1 つの JSON オブジェクトを含む単一の文字列にできます。[#54364](https://github.com/ClickHouse/ClickHouse/pull/54364) ([Memo](https://github.com/Joeywzr)).
* 新しい SQL 関数 &quot;arrayRandomSample(arr, k)&quot; を追加しました。これは入力配列から k 個の要素のサンプルを返します。以前は、同様の機能は &quot;SELECT arrayReduce(&#39;groupArraySample(3)&#39;, range(10))&quot; のような、より扱いにくい構文でしか実現できませんでした。[#54391](https://github.com/ClickHouse/ClickHouse/pull/54391) ([itayisraelov](https://github.com/itayisraelov)).
* ClickHouse server へのリクエストで使用された HTTP リクエストヘッダーの値を取得する新しい関数 `getHttpHeader` を追加しました。リクエストが HTTP プロトコル経由で行われていない場合、または該当するヘッダーが存在しない場合は空文字列を返します。[#54813](https://github.com/ClickHouse/ClickHouse/pull/54813) ([凌涛](https://github.com/lingtaolf)).
* 最小値/最大値でのみ集約できる -ArgMin/-ArgMax 集約関数コンビネータを導入しました。使用例の 1 つは [#54818](https://github.com/ClickHouse/ClickHouse/issues/54818) にあります。この PR では、集約関数コンビネータを専用フォルダーに再編成しました。[#54947](https://github.com/ClickHouse/ClickHouse/pull/54947) ([Amos Bird](https://github.com/amosbird)).
* `SYSTEM DROP SCHEMA FORMAT CACHE [FOR Protobuf]` により、Protobuf フォーマットの cache を削除できるようにしました。[#55064](https://github.com/ClickHouse/ClickHouse/pull/55064) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* 外部 HTTP Basic authenticator を追加しました。[#55199](https://github.com/ClickHouse/ClickHouse/pull/55199) ([Aleksei Filatov](https://github.com/aalexfvk)).
* 符号なし整数のバイト順を逆転する関数 `byteSwap` を追加しました。これは特に、IPv4 のように内部的に符号なし整数として表現される型の値を反転するのに便利です。[#55211](https://github.com/ClickHouse/ClickHouse/pull/55211) ([Priyansh Agrawal](https://github.com/Priyansh121096)).
* SQL クエリ文字列の整形済みバージョン (複数行にまたがる可能性があります) を返す関数 `formatQuery()` を追加しました。あわせて、同様の処理を行いつつ、返される文字列に改行を含まない関数 `formatQuerySingleLine()` も追加しました。[#55239](https://github.com/ClickHouse/ClickHouse/pull/55239) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* ELF の実行可能ファイル/ライブラリ/object file からデバッグシンボルを読み取る DWARF input format を追加しました。[#55450](https://github.com/ClickHouse/ClickHouse/pull/55450) ([Michael Kolupaev](https://github.com/al13n321)).
* RabbitMQ、NATS、FileLog エンジンで、パースされなかったレコードとエラーを保存できるようにしました。ClickHouse が新しいレコードのパースに失敗したときに値が入る仮想カラム `_error` と `_raw_message` (NATS と RabbitMQ 用) 、`_raw_record` (FileLog 用) を追加しました。この動作は、NATS ではストレージ設定 `nats_handle_error_mode`、RabbitMQ では `rabbitmq_handle_error_mode`、FileLog では `kafka_handle_error_mode` と同様の `handle_error_mode` で制御されます。`default` に設定すると、ClickHouse がレコードのパースに失敗した際に例外がスローされます。`stream` に設定すると、エラーと生のレコードが仮想カラムに保存されます。[#36035](https://github.com/ClickHouse/ClickHouse/issues/36035) をクローズしました。[#55477](https://github.com/ClickHouse/ClickHouse/pull/55477) ([Kruglov Pavel](https://github.com/Avogar)).
* Keeper client の改善: 特定の path 配下にあるすべての子ノード数を返す get&#95;all&#95;children&#95;number コマンドを追加しました。[#55485](https://github.com/ClickHouse/ClickHouse/pull/55485) ([guoxiaolong](https://github.com/guoxiaolongzte)).
* テーブルのキーに空間充填曲線がある場合、たとえば `ORDER BY mortonEncode(x, y)` のようなときは、その引数に対する条件、たとえば `x >= 10 AND x <= 20 AND y >= 20 AND y <= 30` を indexing に利用できます。この解析を有効または無効にする設定 `analyze_index_with_space_filling_curves` を追加しました。これにより [#41195](https://github.com/ClickHouse/ClickHouse/issues/41195) をクローズします。[#4538](https://github.com/ClickHouse/ClickHouse/issues/4538) の継続。[#6286](https://github.com/ClickHouse/ClickHouse/issues/6286) の継続。[#28130](https://github.com/ClickHouse/ClickHouse/issues/28130) の継続。[#41753](https://github.com/ClickHouse/ClickHouse/issues/41753) の継続。[#55642](https://github.com/ClickHouse/ClickHouse/pull/55642) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ストレージ EmbeddedRocksDB で `count()` の近似を使用するための設定 `optimize_trivial_approximate_count_query` を追加しました。StorageJoin では trivial count を有効にしました。[#55806](https://github.com/ClickHouse/ClickHouse/pull/55806) ([Duc Canh Le](https://github.com/canhld94)).
* Keeper client の改善: path 配下にある直接の子ノード数を返す get&#95;direct&#95;children&#95;number コマンドを追加しました。[#55898](https://github.com/ClickHouse/ClickHouse/pull/55898) ([xuzifu666](https://github.com/xuzifu666)).
* 既存のステートメント `SHOW SETTINGS` を簡略化したステートメント `SHOW SETTING setting_name` を追加しました。[#55979](https://github.com/ClickHouse/ClickHouse/pull/55979) ([Maksim Kita](https://github.com/kitaisreal)).
* この PR により、Npyフォーマットのデータを ClickHouse に渡せるようになりました。&#96;&#96;&#96; SELECT * FROM file(&#39;example&#95;array.npy&#39;, Npy). [#55982](https://github.com/ClickHouse/ClickHouse/pull/55982) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* この PR では、`force_optimize_projection_name` という新しい設定を実装しました。これは引数として projection 名を受け取ります。値が空でない文字列に設定されている場合、ClickHouse はその projection がクエリ内で少なくとも 1 回使用されていることを確認します。[#55331](https://github.com/ClickHouse/ClickHouse/issues/55331) をクローズしました。[#56134](https://github.com/ClickHouse/ClickHouse/pull/56134) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* 並列ストリーム処理を可能にするため、ウィンドウ関数の評価後もストリーム数を保持するオプション `query_plan_preserve_num_streams_after_window_functions` を追加しました。[#50771](https://github.com/ClickHouse/ClickHouse/pull/50771) ([frinkr](https://github.com/frinkr)).
* データ量が少ない場合に、より多くの `num_streams` を解放するようにしました。[#53867](https://github.com/ClickHouse/ClickHouse/pull/53867) ([Jiebin Sun](https://github.com/jiebinn)).
* RoaringBitmaps がシリアライゼーション前に最適化されるようになりました。[#55044](https://github.com/ClickHouse/ClickHouse/pull/55044) ([UnamedRus](https://github.com/UnamedRus)).
* 転置索引内の posting lists は、内部 bitmap に対して可能な限り最小の表現を使用するよう最適化されました。データの繰り返しが多い場合、これにより転置索引の使用領域を大幅に削減できる可能性があります。[#55069](https://github.com/ClickHouse/ClickHouse/pull/55069) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Context ロックの競合を修正し、短時間で終了する同時実行クエリが多数ある場合のパフォーマンスを大幅に改善しました。[#55121](https://github.com/ClickHouse/ClickHouse/pull/55121) ([Maksim Kita](https://github.com/kitaisreal)).
* 転置索引の作成パフォーマンスを 30% 改善しました。これは `std::unordered_map` を `absl::flat_hash_map` に置き換えることで実現されています。[#55210](https://github.com/ClickHouse/ClickHouse/pull/55210) ([Harry Lee](https://github.com/HarryLeeIBM)).
* ORC フィルタープッシュダウン (rowgroup レベル) をサポートしました。[#55330](https://github.com/ClickHouse/ClickHouse/pull/55330) ([李扬](https://github.com/taiyang-li)).
* 一時ファイルが大量にある場合の external aggregation のパフォーマンスを改善しました。[#55489](https://github.com/ClickHouse/ClickHouse/pull/55489) ([Maksim Kita](https://github.com/kitaisreal)).
* marks を何度も読み込むことを避けるため、セカンダリ索引用の marks cache に対してデフォルトで適切なサイズを設定するようにしました。[#55654](https://github.com/ClickHouse/ClickHouse/pull/55654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* スキップ索引の読み取り時に不要なインデックスグラニュールの再構築を回避するようにしました。これにより [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653)#issuecomment-1763766009 に対処しています。[#55683](https://github.com/ClickHouse/ClickHouse/pull/55683) ([Amos Bird](https://github.com/amosbird)).
* 実行中に Set 内の CAST 関数をキャッシュし、Set の element type が column type と完全には一致しない場合の関数 `IN` のパフォーマンスを改善しました。[#55712](https://github.com/ClickHouse/ClickHouse/pull/55712) ([Duc Canh Le](https://github.com/canhld94)).
* `ColumnVector::insertMany` および `ColumnVector::insertManyFrom` のパフォーマンスを改善しました。[#55714](https://github.com/ClickHouse/ClickHouse/pull/55714) ([frinkr](https://github.com/frinkr)).
* ... map から values を取得する処理は広く使われています。実際には、同じ map カラム内では key の構造は通常同じであるため、次の行の key 位置を予測して比較回数を減らせるようにしました。[#55929](https://github.com/ClickHouse/ClickHouse/pull/55929) ([lgbo](https://github.com/lgbo-ustc)).
* ... 一部のケースで struct フィールドのプルーニングが機能しない issue を修正しました。例えば &#96;&#96;&#96;sql INSERT INTO FUNCTION file(&#39;test&#95;parquet&#95;struct&#39;, Parquet, &#39;x Tuple(a UInt32, b UInt32, c String)&#39;) SELECT tuple(number, rand(), concat(&#39;testxxxxxxx&#39; toString(number))) FROM numbers(10);. [#56117](https://github.com/ClickHouse/ClickHouse/pull/56117) ([lgbo](https://github.com/lgbo-ustc)).

* lifetime フィールドが設定された direct Dictionary は、作成時に拒否されるようになります。修正: [#27861](https://github.com/ClickHouse/ClickHouse/issues/27861)。 [#49043](https://github.com/ClickHouse/ClickHouse/pull/49043) ([Rory Crispin](https://github.com/RoryCrispin))。

* reload 後に正しい server settings が表示されるようにしました。 [#53774](https://github.com/ClickHouse/ClickHouse/pull/53774) ([helifu](https://github.com/helifu))。
* クエリで `-` と同様に、数学記号のマイナス文字 `−` もサポートしました。 [#54100](https://github.com/ClickHouse/ClickHouse/pull/54100) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* Replicated データベースエンジンに replica groups を追加しました。[#53620](https://github.com/ClickHouse/ClickHouse/issues/53620) をクローズ。 [#54421](https://github.com/ClickHouse/ClickHouse/pull/54421) ([Nikolay Degterinsky](https://github.com/evillique))。

* クエリを完全に失敗させるよりも、再試行可能な S3 error は再試行したほうが適切です。デフォルトで `s3&#95;retry&#95;attempts` の値を大きくしました。 [#54770](https://github.com/ClickHouse/ClickHouse/pull/54770) ([Sema Checherinda](https://github.com/CheSema))。
* 多数の一時ファイルが生成された場合の external aggregation のメモリ消費を最適化しました。 [#54798](https://github.com/ClickHouse/ClickHouse/pull/54798) ([Nikita Taranov](https://github.com/nickitat))。
* 負荷分散 `test&#95;hostname&#95;levenshtein&#95;distance` を追加しました。 [#54826](https://github.com/ClickHouse/ClickHouse/pull/54826) ([JackyWoo](https://github.com/JackyWoo))。
* Zookeeper の distributed DDL queue から DDL を実行する際に、スキップ可能なエントリをキャッシュするようにしました。 [#54828](https://github.com/ClickHouse/ClickHouse/pull/54828) ([Duc Canh Le](https://github.com/canhld94))。
* ログ内でのシークレットの秘匿を改善しました。 [#55089](https://github.com/ClickHouse/ClickHouse/pull/55089) ([Vitaly Baranov](https://github.com/vitlibar)).
* `system.parts_columns` テーブルにフィールド `substreams` と `filenames` を追加しました。 [#55108](https://github.com/ClickHouse/ClickHouse/pull/55108) ([Anton Popov](https://github.com/CurtizJ)).
* 当面、プロジェクション解析はクエリプランに対してのみ実行されます。設定 `query_plan_optimize_projection` は廃止されました (かなり前からデフォルトで有効でした) 。 [#55112](https://github.com/ClickHouse/ClickHouse/pull/55112) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 関数 &quot;untuple()&quot; を名前付き要素を持つタプルに対して呼び出し、さらにその関数自体にエイリアスがある場合 (例: &quot;select untuple(tuple(1)::Tuple(element&#95;alias Int)) AS untuple&#95;alias&quot;) 、結果のカラム名は untuple のエイリアスとタプル要素のエイリアスから生成されるようになりました (この例では &quot;untuple&#95;alias.element&#95;alias&quot;) 。 [#55123](https://github.com/ClickHouse/ClickHouse/pull/55123) ([garcher22](https://github.com/garcher22)).
* 設定 `describe_include_virtual_columns` を追加しました。これにより、テーブルの仮想カラムを `DESCRIBE` クエリの結果に含められます。設定 `describe_compact_output` も追加しました。これを `true` に設定すると、`DESCRIBE` クエリは追加情報なしでカラム名と型のみを返します。 [#55129](https://github.com/ClickHouse/ClickHouse/pull/55129) ([Anton Popov](https://github.com/CurtizJ)).
* `optimize_throw_if_noop=1` を指定した `OPTIMIZE` が、実際の原因は異なるパーツ間でプロジェクションが異なることであるにもかかわらず、`unknown reason` エラーで失敗することがありました。この挙動を修正しました。 [#55130](https://github.com/ClickHouse/ClickHouse/pull/55130) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
