<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* 軽微: `backup_threads` と `restore_threads` のサーバー設定が 0 以外の値になるよう強制しました。[#80224](https://github.com/ClickHouse/ClickHouse/pull/80224) ([Raúl Marín](https://github.com/Algunenano)).
* `String` に対する `bitNot()` を修正し、ゼロ終端文字列を返すようにしました。[#80791](https://github.com/ClickHouse/ClickHouse/pull/80791) ([Azat Khuzhin](https://github.com/azat)).
* [#82079](https://github.com/ClickHouse/ClickHouse/issues/82079) でバックポート: 以前は、`countMatches` 関数は、pattern が空文字列との一致を許容する場合でも、最初の空一致でカウントを停止していました。この問題を解消するため、`countMatches` は空一致が発生した場合、1 文字進めて処理を継続するようになりました。従来の動作を維持したいユーザーは、設定 `count_matches_stop_at_empty_match` を有効にできます。[#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* 既存の `Pipe::resize` の実装では、パイプライントポロジーに単一の `Resize` または `StrictResize` ノードを挿入して作成し、それがすべての入力ストリーム (アップストリームノード) を統一された出力ストリーム群 (ダウンストリームノード) へ接続する中央ハブとして機能します。この設計により、特にコア数の多い環境では、パイプライングラフの実行中に `ExecutingGraph::Node::status_mutex` の競合が発生します。パイプラインが数十から数百のストリームにスケールすると、この競合が問題になります。 [#77562](https://github.com/ClickHouse/ClickHouse/pull/77562) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* [#81959](https://github.com/ClickHouse/ClickHouse/issues/81959) でバックポート: ブロックの圧縮・展開およびシリアライゼーション・デシリアライゼーションを、ネットワーク接続に紐づく単一スレッドではなく、パイプラインスレッドにオフロードするオプションを導入しました。これは設定 `enable_parallel_blocks_marshalling` で制御されます。イニシエーターとリモートノード間で大量のデータを転送する分散クエリの高速化が期待されます。 [#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* DELETE FROM ... WHERE 1 クエリを TRUNCATE に置き換え。 (元に戻されました) 。 [#78739](https://github.com/ClickHouse/ClickHouse/pull/78739) ([scanhex12](https://github.com/scanhex12)).
* すべての bloom filter 型のパフォーマンスを改善しました。 [#79800](https://github.com/ClickHouse/ClickHouse/pull/79800) ([Delyan Kratunov](https://github.com/dkratunov)).
* 一方のセットが空の場合の `UniqExactSet::merge` にハッピーパスを導入しました。あわせて、LHS セットが二段階で RHS が単一レベルの場合、RHS を二段階へ変換しないようにしました。 [#79971](https://github.com/ClickHouse/ClickHouse/pull/79971) ([Nikita Taranov](https://github.com/nickitat)).
* デフォルトでログ出力を非同期にしました。これを無効にするには、`<logger>` の下で `<async>false</async>` を設定してください。 [#80125](https://github.com/ClickHouse/ClickHouse/pull/80125) ([Raúl Marín](https://github.com/Algunenano)).
* 二段階ハッシュテーブル使用時のメモリ再利用効率を改善し、ページフォールトを削減しました。 [#80245](https://github.com/ClickHouse/ClickHouse/pull/80245) ([Jiebin Sun](https://github.com/jiebinn)).
* QueryConditionCache における不要な更新を回避し、ロック競合を減らしました。 [#80247](https://github.com/ClickHouse/ClickHouse/pull/80247) ([Jiebin Sun](https://github.com/jiebinn)).
* `concatenateBlocks` の軽微な最適化。parallel hash join に有効かもしれません。 [#80328](https://github.com/ClickHouse/ClickHouse/pull/80328) ([李扬](https://github.com/taiyang-li)).
* 主キー範囲から mark ranges を選択する際、主キーが関数でラップされていると binary search は使用できません。この PR ではこの制限を改善し、主キーが常に単調な function chain でラップされている場合、または RPN に常に true となる要素が含まれている場合でも、binary search を適用できるようにしました。この PR は [#45536](https://github.com/ClickHouse/ClickHouse/issues/45536) をクローズします。 [#80597](https://github.com/ClickHouse/ClickHouse/pull/80597) ([zoomxi](https://github.com/zoomxi)).
* Kafka エンジンのシャットダウンを高速化しました (複数の Kafka table がある場合の余分な 3 秒の遅延を削除) 。 [#80796](https://github.com/ClickHouse/ClickHouse/pull/80796) ([Azat Khuzhin](https://github.com/azat)).
* 非同期 INSERT: メモリ使用量を削減し、insert クエリのパフォーマンスを改善しました。 [#80972](https://github.com/ClickHouse/ClickHouse/pull/80972) ([Raúl Marín](https://github.com/Algunenano)).
* ログ table が無効な場合、プロセッサのプロファイリングを行わないようにしました。 [#81256](https://github.com/ClickHouse/ClickHouse/pull/81256) ([Raúl Marín](https://github.com/Algunenano)).
* ソースが要求されたものと完全に一致する場合の toFixedString を高速化しました。 [#81257](https://github.com/ClickHouse/ClickHouse/pull/81257) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### 改善

* `EXPLAIN SYNTAX` は新しいアナライザを使用するようになりました。クエリツリーから構築された AST を返します。クエリツリーを AST に変換する前に実行するパスの数を制御するオプション `query_tree_passes` を追加しました。[#74536](https://github.com/ClickHouse/ClickHouse/pull/74536) ([Vladimir Cherkasov](https://github.com/vdimir)).

* エラー `AuthenticationRequired` の発生後に S3 の認証情報を更新するようになりました。[#77353](https://github.com/ClickHouse/ClickHouse/pull/77353) ([Vitaly Baranov](https://github.com/vitlibar)).
* `system.asynchronous_metrics` に Dictionary のメトリクスを追加しました。`DictionaryMaxUpdateDelay` - Dictionary 更新の最大遅延 (秒) 。`DictionaryTotalFailedUpdates` - すべての Dictionary における、最後に正常に loading されて以降の error 数。[#78175](https://github.com/ClickHouse/ClickHouse/pull/78175) ([Vlad](https://github.com/codeworse)).
* 分散クエリにおけるシャーディングキーの最適化を改善しました。[#78452](https://github.com/ClickHouse/ClickHouse/pull/78452) ([fhw12345](https://github.com/fhw12345)).
* StorageKafka2 に対して、ClickHouse Keeper を使用した Kafka rebalance のようなロジックを実装しました。各レプリカでは、permanent lock と temporary lock の 2 種類の partition lock をサポートします。レプリカは permanent lock を可能な限り長く保持しようとします。任意の時点で、レプリカ上の permanent lock の数は `all_topic_partitions / active_replicas_count` (ここで `all_topic_partitions` は全 partitions 数、`active_replicas_count` はアクティブな replicas 数) を超えません。これを超える場合、レプリカはいくつかの partitions を解放します。一部の partitions はレプリカによって一時的に保持されます。レプリカ上の temporary lock の最大数は動的に変化し、他の replicas がいくつかの partitions を permanent lock として取得できるようにします。temporary lock を更新する際、レプリカはそれらをすべて解放し、再度いくつかを取得しようとします。[#78726](https://github.com/ClickHouse/ClickHouse/pull/78726) ([Daria Fomina](https://github.com/sinfillo)).
* 壊れたテーブルを保存するために作成された可能性があるデータベースに関する警告を追加しました。[#78841](https://github.com/ClickHouse/ClickHouse/pull/78841) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* S3Queue エンジンに &#95;time 仮想カラムを追加しました。[#78926](https://github.com/ClickHouse/ClickHouse/pull/78926) ([Anton Ivashkin](https://github.com/ianton-ru)).
* CPU 過負荷時の connection drop を制御する settings をホットリロード可能にしました。[#79052](https://github.com/ClickHouse/ClickHouse/pull/79052) ([Alexey Katsman](https://github.com/alexkats)).
* Azure blob storage の plain disk について、system.tables に報告される data path に コンテナー のプレフィックスを追加し、S3 および GCP と一貫した報告になるようにしました。[#79241](https://github.com/ClickHouse/ClickHouse/pull/79241) ([Julia Kartseva](https://github.com/jkartseva)).
* ClickHouse は `param_<name>` (underscore) に加えて、`param-<name>` (dash) もクエリパラメータとして受け付けるようになりました。これにより [#63093](https://github.com/ClickHouse/ClickHouse/issues/63093) をクローズします。[#79429](https://github.com/ClickHouse/ClickHouse/pull/79429) ([Engel Danila](https://github.com/aaaengel)).

* これまで `input_format_parquet_max_block_size = 0` の場合、ClickHouse が停止することがありました。現在はこの挙動が修正されています。これにより [#79394](https://github.com/ClickHouse/ClickHouse/issues/79394) をクローズします。[#79601](https://github.com/ClickHouse/ClickHouse/pull/79601) ([abashkeev](https://github.com/abashkeev)).
