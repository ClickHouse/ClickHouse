  ### ClickHouse リリース v26.4.1.1141-stable (7156188a3ba) FIXME v26.4.1.1-new (aa5df024249) との比較

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `IN` 演算子は `Bool` 型に対して正確な値のセマンティクスを使用するようになりました。セット内の `0` と `1` のみが `Bool` 値に一致します。以前は、`IN` セット内の `255` を超える数値が `Bool` との比較時に誤って true に丸められていたため、`SELECT CAST(1, 'Bool') IN (256)` は 1 を返していました。現在は正しく `0` を返します。[#92980](https://github.com/ClickHouse/ClickHouse/issues/92980) をクローズします。[#93115](https://github.com/ClickHouse/ClickHouse/pull/93115) ([Ashrith Bandla](https://github.com/ashrithb)).
* `stem` 関数を使うことで、`String`、`FixedString`、`Array([Fixed]String)`、`Nullable`、`LowCardinality`、`Const` のカラム内にあるすべての単語/トークンを簡単に語幹化できるようになりました。[#99137](https://github.com/ClickHouse/ClickHouse/pull/99137) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* H3 ライブラリが v4 に更新され、長さ、面積、その他のメトリクス計算の精度が向上しました。新しい結果は以前のものと異なるため、この変更には後方互換性がありません。[#100348](https://github.com/ClickHouse/ClickHouse/pull/100348) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [#99793](https://github.com/ClickHouse/ClickHouse/issues/99793) で導入された `system.query_log` の `skip_indexes` カラムを差し戻しました。[#101018](https://github.com/ClickHouse/ClickHouse/pull/101018) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WITH 式リストの要素で、SELECT を裸の Identifier として使用することを禁止しました。[#101059](https://github.com/ClickHouse/ClickHouse/pull/101059) ([Aruj Bansal](https://github.com/arujbansal)).
* `QBit` のバイナリシリアライゼーションのエンディアンを修正し、little-endian フォーマットを使用するようにしました。[#101378](https://github.com/ClickHouse/ClickHouse/pull/101378) ([Raufs Dunamalijevs](https://github.com/rienath)).
* このパッチでは、Merge table における virtual の扱いが変更されます。基になるテーブルに `_table` または `_database` が含まれている場合、これらのカラムはストレージから読み取られます。そうでない場合は、読み取りステップの後に expression ステップで補完されます。[#101742](https://github.com/ClickHouse/ClickHouse/pull/101742) ([Mikhail Artemenko](https://github.com/Michicosun)).
* `IN` 演算子は、複合型 (`Tuple`、`Array`、`Map`) 内での情報損失を伴う `Decimal` 変換も拒否するようになり、トップレベルの scalar 比較と一貫した動作になりました。以前は、精度チェックはトップレベルの scalar 値に対してのみ適用されていました。たとえば、`CAST('33.3', 'Decimal64(1)') IN (33.33)` は正しく `0` を返していましたが、`CAST(['33.3'], 'Array(Decimal64(1))') IN ([33.33])` は、情報損失を伴う変換が `Array` 内で発生していたため、誤って `1` を返していました。現在は、どちらのケースでも正しく `0` を返します。[#101812](https://github.com/ClickHouse/ClickHouse/pull/101812) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* [#103357](https://github.com/ClickHouse/ClickHouse/issues/103357) でバックポート: HTTP connections による pre-authentication 段階のメモリ使用量を制限するため、デフォルトの `http_max_fields` を 1,000,000 から 1,000 に、`http_max_field_name_size` を 128 KB から 4 KB に引き下げました。さらに、`http_max_request_header_size` と `http_headers_read_timeout` 設定を追加しました。以前のより高い上限に依存している Users は、設定で元に戻せます。[#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).

<div id="new-feature">
  #### 新機能
</div>

* Arrow Flight SQL のサポートを追加しました。[#91170](https://github.com/ClickHouse/ClickHouse/pull/91170) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* Keeper ベースのスナップショット進捗追跡を備えた `Paimon` テーブルエンジンのインクリメンタル読み取りをサポートしました。これには、`paimon_target_snapshot_id` による対象スナップショットの差分読み取りが含まれ、型マッピング、パーティションプルーニング、インクリメンタル読み取りの各シナリオに対するテストカバレッジも拡張されています。[#93655](https://github.com/ClickHouse/ClickHouse/pull/93655) ([XiaoBinMu](https://github.com/Binnn-MX)).
* ClickHouse で、SELECT クエリにおいて min/max 統計に基づきデータパーツ全体をプルーニングできるようになりました。[#94140](https://github.com/ClickHouse/ClickHouse/pull/94140) ([zoomxi](https://github.com/zoomxi)).
* 互換性設定 `use_strict_insert_block_limits` のもとで、まとめる処理における `max_insert_block_size_rows`、`max_insert_block_size_bytes`、`min_insert_block_size_rows`、`min_insert_block_size_bytes` の新しい動作を実装しました。[#94207](https://github.com/ClickHouse/ClickHouse/pull/94207) ([Kirill Kopnev](https://github.com/Fgrtue)).
* 各 lag における数値 Array の正規化自己相関を計算する関数 `arrayAutocorrelation(arr [, max_lag])` を追加しました。整数、浮動小数点、および 10 進 Array 型をサポートします。[#94776](https://github.com/ClickHouse/ClickHouse/pull/94776) ([Wenyu Chen](https://github.com/wenyuchen96)).
* SQL 関数 `obfuscateQuery` を追加しました。[#98010](https://github.com/ClickHouse/ClickHouse/issues/98010) をクローズします。[#98305](https://github.com/ClickHouse/ClickHouse/pull/98305) ([Xuewei Wang](https://github.com/Sallery-X)).
* 2 つの新しい MergeTree 設定 `replicated_fetches_min_part_level` と `replicated_fetches_min_part_level_timeout_seconds` を追加しました。これにより、レプリカは新しく挿入された (未マージの) パーツを他のレプリカから取得せずに済むようになり、大量インジェスト時のレプリケーションのオーバーヘッドを削減できます。[#98625](https://github.com/ClickHouse/ClickHouse/pull/98625) ([tanner-bruce](https://github.com/tanner-bruce)).
* JSON カラムに対する MergeTree スキップ索引のサポートを追加しました。JSONAllPaths と bloom&#95;filter、tokenbf&#95;v1、ngrambf&#95;v1、および text (転置) 索引タイプを使用し、各 granule に含まれる JSON パスの集合に基づいて granule をスキップできるようにします。[#98886](https://github.com/ClickHouse/ClickHouse/pull/98886) ([Pavel Kruglov](https://github.com/Avogar)).
* `printf` 関数が非定数のフォーマット文字列をサポートするようになり、カラム値に基づいて行ごとに異なるフォーマットパターンを使えるようになりました。[#98991](https://github.com/ClickHouse/ClickHouse/pull/98991) ([Yash ](https://github.com/Onyx2406)).
* このパッチでは、挿入順にデータを再編成する新しい projection 索引 (`commit_order`) を追加しました。[#99004](https://github.com/ClickHouse/ClickHouse/pull/99004) ([Mikhail Artemenko](https://github.com/Michicosun)).
* テキスト文字列内で検索語に一致した箇所を HTML タグ (デフォルトは `<em>`/`</em>`) で囲む `highlight()` 関数を追加しました。ASCII の大文字小文字を区別しない一致、重複する一致の自動マージ、カスタムの開始/終了タグをサポートします。[#99131](https://github.com/ClickHouse/ClickHouse/pull/99131) ([Peng](https://github.com/fastio)).
* MergeTree の Map カラム向けに bucketed serialization を追加しました (`map_serialization_version = 'with_buckets'`) 。キーはハッシュベースの bucket に分割されるため、単一のキー (`m['key']`) を読み取る際はカラム全体ではなく 1 つの bucket だけを読めばよくなり、map のサイズに応じて単一キーのルックアップが 2～49 倍高速化されます。bucket の数と bucketing 戦略は、新しい MergeTree 設定 `map_serialization_version`、`max_buckets_in_map`、`map_buckets_strategy`、`map_buckets_coefficient`、`map_buckets_min_avg_size` で制御できます。`map_serialization_version_for_zero_level_parts` 設定により、マージ済みパーツでは bucket を使用しつつ、inserts では書き込み overhead を避けるために基本的なシリアライゼーションを維持できます。`mapKeys/mapValues` 上のスキップ索引は bucketed serialization でサポートされます。`optimize_functions_to_subcolumns` パスは、bucket が利用可能な場合に `m['key']` をキーごとの subcolumn 読み取りに書き換えます。[#99200](https://github.com/ClickHouse/ClickHouse/pull/99200) ([Pavel Kruglov](https://github.com/Avogar)).
* 公開 ClickHouse サービスを不正利用から保護するため、正規化クエリ hash による QUOTA を実装しました。1. QUOTA のキー type として `NORMALIZED_QUERY_HASH` をサポートしました。これにより、一意な正規化クエリごとに個別の QUOTA bucket が作成され、`CREATE QUOTA q KEYED BY normalized_query_hash` でそれぞれの異なるクエリを独立して追跡できます。2. QUOTA の resource type として `QUERIES_PER_NORMALIZED_HASH` をサポートしました。これにより、一定の interval 内で任意の単一の正規化クエリの最大実行回数を制限でき、`MAX queries_per_normalized_hash = 100` によって 1 つのクエリパターンが 100 回を超えて実行されるのを防げます。[#99586](https://github.com/ClickHouse/ClickHouse/pull/99586) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ユーザーは `NATURAL JOIN` 構文を使って join クエリを記述できるようになりました。これにより、同じ名前を持つすべてのカラムが自動的に照合され、結果ではそれらのカラムが重複排除されます。[#99840](https://github.com/ClickHouse/ClickHouse/pull/99840) ([Peter Nguyen](https://github.com/petern48)).
* `SET session&#95;timezone` の別名として `SET TIME ZONE &#39;tz&#39;` をサポートしました。[#99883](https://github.com/ClickHouse/ClickHouse/pull/99883) ([phulv94](https://github.com/phulv94)).
* Web UI (`play.html`) で parameterized query をサポートしました。`{name:Type}` のようなクエリパラメータを検出し、その値を入力するための入力フィールドを表示します。[#100041](https://github.com/ClickHouse/ClickHouse/pull/100041) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `FROM` 内のテーブル expression として SQL 標準の `VALUES` 句をサポートしました。例: `SELECT * FROM (VALUES (1, 'a'), (2, 'b')) AS t(id, val)`。[#100143](https://github.com/ClickHouse/ClickHouse/pull/100143) ([Desel72](https://github.com/Desel72)).
* `EXTRACT` operator に PostgreSQL 互換の単位 `EPOCH`、`DOW`、`DOY`、`ISODOW`、`ISOYEAR`、`WEEK`、`CENTURY`、`DECADE`、`MILLENNIUM` を追加しました。また、これまでエラーになっていた `EXTRACT(WEEK FROM date)` も修正しました。[#100274](https://github.com/ClickHouse/ClickHouse/pull/100274) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `TO` 範囲修飾子を持つ SQL 標準の compound interval literal をサポートしました。例: `INTERVAL '1:30' HOUR TO MINUTE`。内部的には複数の interval の合計に分解されます。[#100453](https://github.com/ClickHouse/ClickHouse/pull/100453) ([Desel72](https://github.com/Desel72)).
* HTTP 接続プールソケットのカーネル TCP 受信および送信バッファメモリ (`sk_rmem_alloc`、`sk_wmem_alloc`) に関する非同期メトリクスを追加しました。これは p50/p75/p90/p95 パーセンタイルおよび connection group ごとの合計として報告されます。[#100575](https://github.com/ClickHouse/ClickHouse/pull/100575) ([Sema Checherinda](https://github.com/CheSema)).
* ClickHouse Keeper 向けの jemalloc profiling web UI を追加しました。HTTP control ポートの `/jemalloc` で利用できます。[#100606](https://github.com/ClickHouse/ClickHouse/pull/100606) ([murphy-4o](https://github.com/murphy-4o)).
* ordered モードおよび順不同モード向けに、コマンド `SYSTEM FLUSH OBJECT STORAGE QUEUE db.table PATH 'x'` を実装しました。[#100709](https://github.com/ClickHouse/ClickHouse/pull/100709) ([Bharat Nallan](https://github.com/bharatnc)).
* `JSON` カラム内のすべての値を `Array(String)` として返す関数 `JSONAllValues` を追加しました。値はテキスト表現にシリアライズされ、path 名で順序付けされます。さらに、`JSON` カラム上の `JSONAllValues` 式に対するテキスト索引のサポートも追加しました。`JSONAllValues(json_column)` にテキスト索引を作成すると、`JSON` の subcolumns に対するクエリのフィルタリング (例: `json_column.key1 = 'value'`) に自動的に使用されます。[#100730](https://github.com/ClickHouse/ClickHouse/pull/100730) ([Anton Popov](https://github.com/CurtizJ)).
* `clickhouse-keeper-client` に `watch` コマンドを追加し、`get`、`exists`、`ls` コマンドでの watch をサポートしました。[#100834](https://github.com/ClickHouse/ClickHouse/pull/100834) ([Den Kalantaevskii](https://github.com/Diskein)).
* ClickHouse Keeper に getChildrenRecursive (ListRecursive) リクエストを追加し、clickhouse-keeper-client に lsr コマンドを追加しました。これにより [#99916](https://github.com/ClickHouse/ClickHouse/issues/99916) をクローズします。[#100998](https://github.com/ClickHouse/ClickHouse/pull/100998) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 2 次元配列 (行列) を受け取り、それを転置する新しい関数 `arrayTranspose` を追加しました: &#96;&#96;&#96; SELECT arrayTranspose([[1, 2, 3], [4, 5, 6]]). [#101214](https://github.com/ClickHouse/ClickHouse/pull/101214) ([Vitaly Baranov](https://github.com/vitlibar)).
* Auto&#95;statistics&#95;types MergeTree setting のデフォルトが &quot;minmax, uniq&quot; になりました — 新しいテーブルでは、適切なすべてのカラムに対して minmax および uniq の STATISTICS が自動的に作成されます - materialize&#95;statistics&#95;on&#95;insert のデフォルトは false になりました — STATISTICS は insert time ではなく merge 時に構築されるようになり、insert overhead が削減されます。以前の動作に戻すには、set materialize&#95;statistics&#95;on&#95;insert = 1 を使用してください。[#101275](https://github.com/ClickHouse/ClickHouse/pull/101275) ([Han Fei](https://github.com/hanfei1991)).
* クロスレプリカのレプリケーションラグによるデータ欠落を減らすため、materialized view の依存関係チェーン向けに `prefer_dependency_replica` refresh setting を追加しました。[#101591](https://github.com/ClickHouse/ClickHouse/pull/101591) ([Seva Potapov](https://github.com/seva-potapov)).
* phrase search (連続した token 列) 用の `hasPhrase` (別名 `matchPhrase`) 関数を追加しました。検索は brute-force であり、つまり現時点ではテキスト索引ではサポートされていません。[#101997](https://github.com/ClickHouse/ClickHouse/pull/101997) ([Elmi Ahmadov](https://github.com/ahmadov)).
* [#103507](https://github.com/ClickHouse/ClickHouse/issues/103507) でバックポート: S3 GET リクエストの connection lifetime と消費バイト数を観測するため、`s3_read_request_duration_microseconds` および `s3_read_request_bytes` ヒストグラムメトリクスを追加しました。これらは `system.histogram_metrics` および Prometheus エンドポイントで確認できます。[#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)).
* `stem` 関数は Experimental ではなくなりました (以前は setting `allow_experimental_nlp_functions` を enabled にする必要がありました) 。[#102399](https://github.com/ClickHouse/ClickHouse/pull/102399) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* `Date` および `Date32` の値に、`+` 演算子を使って `Time` および `Time64` の値を加算できるようになり、結果として `DateTime` または `DateTime64` が得られるようになりました。たとえば、`SELECT toDate('2024-01-15') + toTime('14:30:25')` は `2024-01-15 14:30:25` を返します。結果はセッションタイムゾーンで計算され、範囲外の結果は `date_time_overflow_behavior` 設定に従って処理されます。[#95914](https://github.com/ClickHouse/ClickHouse/issues/95914) をクローズしました。[#102421](https://github.com/ClickHouse/ClickHouse/pull/102421) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 新しい system table `system.histogram_metric_log` が追加されました。このテーブルは、すべてのヒストグラムメトリクス (例: S3/Azure のレイテンシ、Keeper のリクエスト処理ステージの Duration) を定期的にスナップショットします。また、`system.histogram_metrics` の `value` カラムは、Prometheus のデータモデルにより柔軟に対応し、互換性も高めるため、`Float64` に変更されました。[#103046](https://github.com/ClickHouse/ClickHouse/pull/103046) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* 完了済みの mutation がある ReplicatedMergeTree テーブルに対する readonly 操作中のロック競合を低減しました。[#95771](https://github.com/ClickHouse/ClickHouse/pull/95771) ([Eduard Karacharov](https://github.com/korowa)).
* projections の読み取り時に `optimize_read_in_order` を尊重するようにしました。[#89453](https://github.com/ClickHouse/ClickHouse/issues/89453) をクローズします。[#95885](https://github.com/ClickHouse/ClickHouse/pull/95885) ([Andrey Zvonov](https://github.com/zvonand)).
* HashJoin および ConcurrentHashJoin に対する небольшоеではなく、いくつかの改善を行いました。[#96663](https://github.com/ClickHouse/ClickHouse/pull/96663) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 入力データの重複がほとんどない場合に `LowCardinality` カラムの最適化を無効にすることで、`DISTINCT` transform を最適化しました。[#97113](https://github.com/ClickHouse/ClickHouse/pull/97113) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* この PR には、[#97723](https://github.com/ClickHouse/ClickHouse/issues/97723) の `like` クエリに対する性能最適化が含まれています。[#98149](https://github.com/ClickHouse/ClickHouse/pull/98149) ([Elmi Ahmadov](https://github.com/ahmadov)).
* ベクトル化された数学関数 (`exp`、`log`、`sigmoid`、`tanh`) は、AArch64 (NEON/SVE 使用時) および FreeBSD/Darwin で高速化されました。これらの環境では、従来はより遅いスカラー fallback が使われていました。[#98230](https://github.com/ClickHouse/ClickHouse/pull/98230) ([Raúl Marín](https://github.com/Algunenano)).
* `^(abc-1|abc-2)` のようなリテラル文字列の正規表現の選択肢で MergeTree の主キーカラムをフィルタするクエリで、選択肢が共通のプレフィックスを持つ場合に、主キー pruning を利用できるようになりました。[#98988](https://github.com/ClickHouse/ClickHouse/pull/98988) ([Yash ](https://github.com/Onyx2406)).
* `ORDER BY ... LIMIT` の top-k dynamic filtering を一般化し、Nullable、String、COLLATE 型をサポートしました。[#99033](https://github.com/ClickHouse/ClickHouse/pull/99033) ([murphy-4o](https://github.com/murphy-4o)).
