<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* nullable columns を非 Nullable 型に変換する際、ALTER MODIFY COLUMN で明示的な DEFAULT の指定が必要になりました。以前は、このような ALTER が cannot convert null to not null エラーで止まることがありましたが、現在は NULL がそのカラムの default expression に置き換えられます。[#5985](https://github.com/ClickHouse/ClickHouse/issues/5985) を解決します。[#84770](https://github.com/ClickHouse/ClickHouse/pull/84770) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Ngram tokenizer は、設定された長さ N より短い ngram を返さなくなりました。Search では、検索トークンが空の場合、行は返されません。[#89757](https://github.com/ClickHouse/ClickHouse/pull/89757) ([George Larionov](https://github.com/george-larionov)).
* カラムを `String` から `Nullable(String)` に ALTER する場合、データに対する mutation は実行されません。しかし、`uniq` aggregate function では異なるデータ構造が使われます。nullable column では、ネストされた uniq アグリゲーターを持つ `AggregateFunctionNull` が使われます。`AggregateFunctionNull` は追加の bool フラグを serialize するため、statistics ファイルとの互換性が失われます。この修正では、シリアライゼーション時に nullable column かどうかを記録するフラグを追加します。statistics のフォーマットは変更されており、古いフォーマットの statistics があるとサーバーは crash します。この PR [https://github.com/ClickHouse/ClickHouse/pull/90904](https://github.com/ClickHouse/ClickHouse/pull/90904) ではこの crash を修正し、既存の statistics が legacy フォーマットを使用している場合は exception を投げます。exception を回避するには、statistics を再生成するために ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL を実行する必要があります。[#90311](https://github.com/ClickHouse/ClickHouse/pull/90311) ([Han Fei](https://github.com/hanfei1991)).
* settings `allow_not_comparable_types_in_order_by`/`allow_not_comparable_types_in_comparison_functions` を削除しました。比較不可能な型を order by や comparison function で許可すると、論理エラーや予期しない結果につながる可能性があります。[#90028](https://github.com/ClickHouse/ClickHouse/issues/90028) を解決します。[#90527](https://github.com/ClickHouse/ClickHouse/pull/90527) ([Pavel Kruglov](https://github.com/Avogar)).
* setting `check_query_single_value_result` のデフォルトを `true` から `false` に変更しました。これにより、`CHECK TABLE` は集計結果 (1 = okay, 0 = errors found) ではなく、part ごとの詳細な結果を返すようになります。従来の動作と比べると、こちらのほうがユーザーの意図に沿っている可能性が高いです。[#91009](https://github.com/ClickHouse/ClickHouse/pull/91009) ([Robert Schulze](https://github.com/rschu1ze)).
* implicit indices に関する複数の修正を行いました。表示または保存されるスキーマ (keeper metadata) には、settings `add_minmax_index_for_numeric_columns` や `add_minmax_index_for_string_columns` によって作成されるものなど、implicit indices は含まれなくなります。このため、新しいバージョンで ReplicatedMergeTree table が作成または更新され、一方で古いリリースのレプリカが存在する場合、メタデータエラーが発生する可能性があります。このような場合は、クラスターの upgrade が完全に完了するまで、古いレプリカに DDL を送信してください。[#91429](https://github.com/ClickHouse/ClickHouse/pull/91429) ([Raúl Marín](https://github.com/Algunenano)).
* `receive_timeout` によってクエリが timeout した場合、clickhouse-client が非ゼロの終了コード (159 - TIMEOUT&#95;EXCEEDED) を返すように更新しました。以前は、timeouts でも終了コード 0 (success) が返されていたため、スクリプトや自動化で timeout failure を検出するのが困難でした。[#91432](https://github.com/ClickHouse/ClickHouse/pull/91432) ([Sav](https://github.com/sberss)).
* object storage からの読み取り効率を高めるため、転置テキスト索引のストレージレイアウトを改善しました。転置テキスト索引を持つ table での merge の性能も改善しました。バージョン 25.12 より前に Experimental なテキスト索引を使用していた場合は、upgrade の前にその索引を drop し、新しいバージョンで再構築する必要があります。[#91518](https://github.com/ClickHouse/ClickHouse/pull/91518) ([Anton Popov](https://github.com/CurtizJ)).
* これらのテーブルではマージ動作が未定義となるため、空の `ORDER BY` キーを持つ特殊な `MergeTree` テーブル (`ReplacingMergeTree`、`CollapsingMergeTree` など) は作成できなくなりました。それでもそのようなテーブルを作成する必要がある場合は、`allow_suspicious_primary_key` 設定を有効にしてください。[#91569](https://github.com/ClickHouse/ClickHouse/pull/91569) ([Anton Popov](https://github.com/CurtizJ)).
* シフト量が型のサイズとちょうど同じ場合に、関数 bitShiftLeft と bitShiftRight が 0 または空の値を返すよう修正しました。[#91943](https://github.com/ClickHouse/ClickHouse/pull/91943) ([Pablo Marcos](https://github.com/pamarcos)).
* [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380) のフォローアップです。この PR では、プロジェクションでの位置引数の無効化を後方互換性のない変更として扱います。さらに、プロジェクション内に位置引数が存在する場合でも ClickHouse クラスターを安全にアップグレードできるよう、`enable_positional_arguments_for_projections` 設定が導入されました。[#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="new-feature">
  #### 新機能
</div>

* Users は、S3/Azure Queue テーブルで、従来のファイルを保持または削除するオプションに加え、処理済みファイルを移動またはタグ付けするよう設定できるようになりました。 [#72944](https://github.com/ClickHouse/ClickHouse/issues/72944) を解決しました。 [#86907](https://github.com/ClickHouse/ClickHouse/pull/86907) ([Murat Khairulin](https://github.com/mxwell)).
* `windowFunnel` aggregate function に `allow_reentry` オプションを追加しました。strict&#95;order とともに有効にすると、順序に違反するイベントがあってもファネル分析を停止せず、それらを無視します。これにより、リフレッシュを伴うユーザージャーニー (A-&gt;A-&gt;B) や戻る操作を含む遷移 (A-&gt;B-&gt;A-&gt;C) でも、コンバージョン率を過少計上することなく処理できます。 [#86916](https://github.com/ClickHouse/ClickHouse/pull/86916) ([Lee ChaeRok](https://github.com/LeeChaeRok)).
* CLI client で、`--no-server-client-version-message` または `false` を指定することで、&#39;ClickHouse server version is older than ClickHouse client. It may indicate that the server is out of date and can be upgraded.&#39; というメッセージを抑制できるようになりました。 [#87784](https://github.com/ClickHouse/ClickHouse/pull/87784) ([Larry Snizek](https://github.com/larry-cdn77)).
* ZooKeeper との Keeper 互換性: statistics 付き create。 [#88797](https://github.com/ClickHouse/ClickHouse/pull/88797) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* ClickHouse Keeper で ZooKeeper の永続ウォッチをサポートしました。継続部分 第2部: [https://github.com/ClickHouse/ClickHouse/pull/78207](https://github.com/ClickHouse/ClickHouse/pull/78207)。 [#88813](https://github.com/ClickHouse/ClickHouse/pull/88813) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* ジオメトリ型の面積と周長を計算する Functions。 [#89047](https://github.com/ClickHouse/ClickHouse/pull/89047) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 本番環境での問題の Debug と決定論的なプロファイリングのために、XRay を使用して runtime にインストルメンテーションを追加します。 [#74249](https://github.com/ClickHouse/ClickHouse/issues/74249) を解決しました。 [#89173](https://github.com/ClickHouse/ClickHouse/pull/89173) ([Pablo Marcos](https://github.com/pamarcos)).
* 指定した値と属性が一致する辞書キーを返す `dictGetKeys` function を実装しました。これは、`max_reverse_dictionary_lookup_cache_size_bytes` setting で調整されるクエリごとの逆方向ルックアップ cache を使用して、繰り返しのルックアップを高速化します。 [#89197](https://github.com/ClickHouse/ClickHouse/pull/89197) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `--login` を使用して、Cloud の credentials で ClickHouse Cloud インスタンスにアクセスできるようになりました。 [#89261](https://github.com/ClickHouse/ClickHouse/pull/89261) ([Krishna Mannem](https://github.com/kcmannem)).
* 入力 JSON を JSON type 内の明示的な型付きパスにキャストできない場合に、JSON type への insert/型変換で例外を無効化する setting `type_json_skip_invalid_typed_paths` を追加しました。型付きパスの null/ゼロ値にフォールバックします。 [#89886](https://github.com/ClickHouse/ClickHouse/pull/89886) ([Max Justus Spransy](https://github.com/maxjustus)).
* MergeTree テーブルに対する `direct` (ネストループ) join をサポートしました。使用するには、setting で唯一のオプションとして次を指定します: `join_algorithm = 'direct'`。 [#89920](https://github.com/ClickHouse/ClickHouse/pull/89920) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Iceberg に対する `CREATE` 操作での `ORDER BY` と、`INSERT` での sorting をサポートしました。 [#89916](https://github.com/ClickHouse/ClickHouse/issues/89916) を解決しました。 [#90141](https://github.com/ClickHouse/ClickHouse/pull/90141) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* この PR では、`ALTER TABLE ... ADD PROJECTION` の新しい `WITH SETTINGS` 句を通じて、プロジェクションレベルの設定を追加しました。これらの設定により、プロジェクションごとに特定の MergeTree ストレージパラメータ (例: `index_granularity`、`index_granularity_bytes`) を上書きできるようになります。[#90158](https://github.com/ClickHouse/ClickHouse/pull/90158) ([Amos Bird](https://github.com/amosbird)) 。
* データマスキングポリシーのパーサーを追加しました。[#90552](https://github.com/ClickHouse/ClickHouse/pull/90552) ([pufit](https://github.com/pufit)) 。
* [#73900](https://github.com/ClickHouse/ClickHouse/issues/73900) および [#38775](https://github.com/ClickHouse/ClickHouse/issues/38775) の一環として、`HMAC(algorithm, message, key)` SQL 関数を追加しました。[#90837](https://github.com/ClickHouse/ClickHouse/pull/90837) ([Mikhail f. Shiryaev](https://github.com/Felixoid)) 。
* 第 1 引数が定数 Array の場合に、`has()` 関数で主キーとデータスキッピングインデックスを使用できるようにしました。[#90980](https://github.com/ClickHouse/ClickHouse/issues/90980) をクローズします。[#91023](https://github.com/ClickHouse/ClickHouse/pull/91023) ([Nihal Z. Miaji](https://github.com/nihalzp)) 。
* 新しい入出力フォーマット `Buffers` を実装しました。このフォーマットは `Native` に似ていますが、`Native` と異なり、カラム名、カラム型、追加のメタデータは保存しません。[#84017](https://github.com/ClickHouse/ClickHouse/issues/84017) をクローズします。[#91156](https://github.com/ClickHouse/ClickHouse/pull/91156) ([Nihal Z. Miaji](https://github.com/nihalzp)) 。
* Cluster table function でのファイル並列読み取り時のストリーム数を制御する設定 `max_streams_for_files_processing_in_cluster_functions` を追加しました。[#90223](https://github.com/ClickHouse/ClickHouse/issues/90223) をクローズします。[#91323](https://github.com/ClickHouse/ClickHouse/pull/91323) ([Pavel Kruglov](https://github.com/Avogar)) 。

<div id="experimental-feature">
  #### 実験的機能
</div>

* `automatic_parallel_replicas_mode` 設定で制御される新しいロジックが導入され、並列レプリカを使用してクエリを自動実行できるようになりました。通常の単一ノード実行時には、ClickHouse は後で計画段階で参照される統計情報を収集します。統計情報から並列レプリカの利用が有効と見込まれる場合、ClickHouse は対象のクエリを並列レプリカで自動的に実行します。現在サポートされているクエリは、まだかなり限定的です。[#87541](https://github.com/ClickHouse/ClickHouse/pull/87541) ([Nikita Taranov](https://github.com/nickitat)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* クエリが行数制限に達した際に即座に失敗するようにしました。[#61872](https://github.com/ClickHouse/ClickHouse/issues/61872) を解決します。[#62804](https://github.com/ClickHouse/ClickHouse/pull/62804) ([Sean Haynes](https://github.com/seandhaynes)).
* クエリプラン内の未使用カラムを削除する最適化を追加しました。[#75152](https://github.com/ClickHouse/ClickHouse/issues/75152) を解決します。[#76487](https://github.com/ClickHouse/ClickHouse/pull/76487) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Https://github.com/clickhouse/clickhouse/pull/84477 では、並列分散実行のために `insert select from s3cluster()` クエリで使用できる select クエリに関する制約が追加されました。この変更により、従来から可能だった where を利用できます。[#84611](https://github.com/ClickHouse/ClickHouse/pull/84611) ([Igor Nikonov](https://github.com/devcrafter)).
* ハッシュテーブルの反復処理中にキーを先読みして、キャッシュミスを最小限に抑えます。[#84708](https://github.com/ClickHouse/ClickHouse/pull/84708) ([lgbo](https://github.com/lgbo-ustc)).
* points 配列の末尾のみをソートし、単調な入力ではソートを省略することで AggregateFunctionHistogram を最適化し、約 10% の高速化を実現しました。[#85760](https://github.com/ClickHouse/ClickHouse/pull/85760) ([MakarDev](https://github.com/MakarDev)).
* ClickHouse は、`AND` と `OR` が混在するフィルタ条件を含む WHERE clauses に対しても、スキップ索引を使って索引解析を行えるようになりました。従来は、スキップ索引を利用するには WHERE clause がフィルタ条件の conjunction (AND) である必要がありました。新しい設定 `use_skip_indexes_for_disjunctions` (デフォルト: on) でこの機能を制御できます。(issue [#75228](https://github.com/ClickHouse/ClickHouse/issues/75228))。[#87781](https://github.com/ClickHouse/ClickHouse/pull/87781) ([Shankar Iyer](https://github.com/shankar-iyer)).
* `like`、`equals`、`has` などの関数を含む predicates に対するフィルタリング性能を、テキスト索引から構築した追加の事前フィルタを活用することで改善しました。この最適化は `query_plan_text_index_add_hint` 設定で有効になります。`Map` Data type のカラムに対するテキスト索引の利用も改善しました。[#88550](https://github.com/ClickHouse/ClickHouse/pull/88550) ([Anton Popov](https://github.com/CurtizJ)).
* 事前計算した可能な key values の Set に対してより高速なルックアップを行うことで、繰り返される逆引き Dictionary ルックアップを最適化しました。[#7968](https://github.com/ClickHouse/ClickHouse/issues/7968) をクローズします。[#88971](https://github.com/ClickHouse/ClickHouse/pull/88971) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Nullable type のカラムに対する sparse シリアライゼーションのサポートを追加しました。これは [#44539](https://github.com/ClickHouse/ClickHouse/issues/44539) の継続です。[#88999](https://github.com/ClickHouse/ClickHouse/pull/88999) ([Amos Bird](https://github.com/amosbird)).
* `ANTI` JOIN に対する JOIN Runtime Filters をサポートしました。あわせて、ロック競合を減らすために runtime filters の実装をリファクタリングしました。[#89710](https://github.com/ClickHouse/ClickHouse/pull/89710) ([Dmitry Novik](https://github.com/novikd)).
* LEFT/INNER JOIN演算 において、左テーブルから順序どおりに読み続けられるようになり、後続のステップで利用できます。これは設定 `query_plan_read_in_order_through_join` で無効にできます。また、LEFT/INNER JOIN に対して virtual row を用いた読み取り最適化 (設定 `read_in_order_use_virtual_row` を参照) もサポートしました。[#89815](https://github.com/ClickHouse/ClickHouse/pull/89815) ([Vladimir Cherkasov](https://github.com/vdimir)).
* スキップ索引と動的しきい値フィルタを使用して `ORDER BY...LIMIT N` クエリを最適化し、処理行数を大幅に削減します。[#89835](https://github.com/ClickHouse/ClickHouse/pull/89835) ([Shankar Iyer](https://github.com/shankar-iyer)).
* topK の性能と動作を改善しました。[#90091](https://github.com/ClickHouse/ClickHouse/pull/90091) ([Raúl Marín](https://github.com/Algunenano)).
* Decimal の比較操作のパフォーマンスを改善しました。[#28192](https://github.com/ClickHouse/ClickHouse/issues/28192) を解決します。[#90153](https://github.com/ClickHouse/ClickHouse/pull/90153) ([Konstantin Bogdanov](https://github.com/thevar1able)) 。
* [https://github.com/ClickHouse/ClickHouse/pull/84423](https://github.com/ClickHouse/ClickHouse/pull/84423) に続き、Paimon 関数でパーティション pruning をサポートしました。[#90253](https://github.com/ClickHouse/ClickHouse/pull/90253) ([JIaQi](https://github.com/JiaQiTang98)) 。
* 上限を大きくした場合の遅延 materialized columns のパフォーマンスを改善しました。[#90309](https://github.com/ClickHouse/ClickHouse/pull/90309) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 大規模な `minmax` 索引 (数百万 granules) が存在する場合、索引解析のレイテンシーが低下します。[#90428](https://github.com/ClickHouse/ClickHouse/pull/90428) ([Shankar Iyer](https://github.com/shankar-iyer)) 。
* dynamic dispatch により、論理関数で高度な SIMD 操作を使用するようにしました。[#90432](https://github.com/ClickHouse/ClickHouse/pull/90432) ([Raúl Marín](https://github.com/Algunenano)) 。
* 結果カラムを不要にゼロ初期化しないようにして、JIT 関数の実行パフォーマンスを改善しました。[#90449](https://github.com/ClickHouse/ClickHouse/pull/90449) ([Raúl Marín](https://github.com/Algunenano)) 。
* dynamic dispatch により T64 の圧縮解除を高速化しました。[#90610](https://github.com/ClickHouse/ClickHouse/pull/90610) ([Raúl Marín](https://github.com/Algunenano)) 。
* MergeTree reader のインプレース filtering を最適化しました。[#87119](https://github.com/ClickHouse/ClickHouse/issues/87119) を解決します。[#90630](https://github.com/ClickHouse/ClickHouse/pull/90630) ([Xiaozhe Yu](https://github.com/wudidapaopao)) 。
* クエリが行 limits に達した時点で即座に失敗するようにしました。[#61872](https://github.com/ClickHouse/ClickHouse/issues/61872) を解決します。[#90767](https://github.com/ClickHouse/ClickHouse/pull/90767) ([Sean Haynes](https://github.com/seandhaynes)) 。
* INNER JOIN 向けのシンプルな DPsize join 並べ替えアルゴリズムを実装しました。どのアルゴリズムをどの順序で使うかは、新しい experimental setting で制御します。たとえば `query_plan_optimize_join_order_algorithm='dpsize,greedy'` は、まず DPsize を試し、fallback として greedy に切り替えることを意味します。[#91002](https://github.com/ClickHouse/ClickHouse/pull/91002) ([Alexander Gololobov](https://github.com/davenger)) 。
* 選択される merge 候補の幅を狭めるための追加ヒューリスティックを導入しました。より小規模な merge を実行すると write amplification は増加しますが、同時に `TOO_MANY_PARTS` エラーの回避に役立つ場合があります。[#91163](https://github.com/ClickHouse/ClickHouse/pull/91163) ([Mikhail Artemenko](https://github.com/Michicosun)) 。
* glob パターンを使って作成された S3 table で、`_path` filter 値の pushdown によりクエリパフォーマンスを改善しました。これにより S3 の listing 操作を回避できます。これは `s3_path_filter_limit` setting で制御されます。[#91165](https://github.com/ClickHouse/ClickHouse/pull/91165) ([Eduard Karacharov](https://github.com/korowa)) 。
* dynamic dispatch により、 (WHERE clauses 内での) カラムから bool への変換を高速化しました。[#91203](https://github.com/ClickHouse/ClickHouse/pull/91203) ([Raúl Marín](https://github.com/Algunenano)) 。
* dynamic dispatch により、単一の数値 block の sorting を高速化しました。[#91213](https://github.com/ClickHouse/ClickHouse/pull/91213) ([Raúl Marín](https://github.com/Algunenano)) 。
