  # 2025年の変更履歴
</div>

<div id="clickhouse-release-v25312703-lts-b684e195f96-fixme-as-compared-to-v25311-new-217f67ec3ad">
  ### ClickHouse リリース v25.3.1.2703-lts (b684e195f96) FIXME (v25.3.1.1-new (217f67ec3ad) と比較した場合)
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* Replicated データベースに対する `TRUNCATE DATABASE` を禁止。 [#76651](https://github.com/ClickHouse/ClickHouse/pull/76651) ([Bharat Nallan](https://github.com/bharatnc)).
* `compatibility` 設定にかかわらず、アナライザが無効な場合はデフォルトで並列レプリカを無効に変更。`parallel_replicas_only_with_analyzer` を明示的に `false` に設定すれば、この動作は引き続き変更できます。 [#77115](https://github.com/ClickHouse/ClickHouse/pull/77115) ([Igor Nikonov](https://github.com/devcrafter)).
* 設定値として浮動小数点値に `NaN` または `inf` を使用することは、できなくなりました。 [#77546](https://github.com/ClickHouse/ClickHouse/pull/77546) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="new-feature">
  #### 新機能
</div>

* OS page cache に依存する代わりに、in-process memory にデータをキャッシュできる Userspace Page Cache の新しい実装を追加しました。これは、データがローカルファイルシステムキャッシュを伴わないリモートの仮想ファイルシステムに保存されている場合に有用です。[#70509](https://github.com/ClickHouse/ClickHouse/pull/70509) ([Michael Kolupaev](https://github.com/al13n321)).
* [#77924](https://github.com/ClickHouse/ClickHouse/issues/77924) でバックポート: low cardinality の Decimal data types をサポートし、[#72256](https://github.com/ClickHouse/ClickHouse/issues/72256) を修正しました。[#72833](https://github.com/ClickHouse/ClickHouse/pull/72833) ([zhanglistar](https://github.com/zhanglistar)).
* 同時実行クエリ間で CPU slots をどのように分配するかを制御する `concurrent_threads_scheduler` server setting を追加しました。`round_robin` (従来の動作) または `fair_round_robin` に設定でき、INSERT と SELECT の間で CPU が不公平に分配される問題に対処できます。[#75949](https://github.com/ClickHouse/ClickHouse/pull/75949) ([Sergei Trifonov](https://github.com/serxa)).
* 関数 `arraySymmetricDifference` を追加しました。これは、複数の Array argument のうち、すべての arguments に共通して現れない要素をすべて返します。Example: `SELECT arraySymmetricDifference([1, 2], [2, 3])` は `[1, 3]` を返します。(issue [#61673](https://github.com/ClickHouse/ClickHouse/issues/61673)). [#76231](https://github.com/ClickHouse/ClickHouse/pull/76231) ([Filipp Abapolov](https://github.com/pheepa)).
* `estimatecompressionratio` aggregate function を追加しました。[#70801](https://github.com/ClickHouse/ClickHouse/issues/70801) を参照してください。[#76661](https://github.com/ClickHouse/ClickHouse/pull/76661) ([Tariq Almawash](https://github.com/talmawash)).
* `FilterTransformPassedRows` および `FilterTransformPassedBytes` profile events により、クエリ実行中に filter された行数とバイト数が表示されるようになりました。[#76662](https://github.com/ClickHouse/ClickHouse/pull/76662) ([Onkar Deshpande](https://github.com/onkar)).
* 特に EVM ベースのシステムにおけるブロックチェーン実装で一般的に使われる、keccak256 hash function を追加しました。[#76669](https://github.com/ClickHouse/ClickHouse/pull/76669) ([Arnaud Briche](https://github.com/arnaudbriche)).
* この機能により、クライアントリクエストの headers から外部 HTTP authenticator に forwarded される headers のリストを定義できるようになりました。[#77054](https://github.com/ClickHouse/ClickHouse/pull/77054) ([inv2004](https://github.com/inv2004)).
* 3 つの新しい関数を追加しました。`icebergTruncate` は仕様に準拠しています。[https://iceberg.apache.org/spec/#truncate-transform-details](https://iceberg.apache.org/spec/#truncate-transform-details)、`toYearNumSinceEpoch` および `toMonthNumSinceEpoch` です。さらに、`Iceberg` engine の partition pruning で `truncate` transform をサポートしました。[#77403](https://github.com/ClickHouse/ClickHouse/pull/77403) ([alesapin](https://github.com/alesapin)).
* [#77975](https://github.com/ClickHouse/ClickHouse/issues/77975) でバックポート: `JSON` data type が production-ready になりました。[https://jsonbench.com/](https://jsonbench.com/) を参照してください。`Dynamic` および `Varaint` data types も production ready になりました。[#77785](https://github.com/ClickHouse/ClickHouse/pull/77785) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="experimental-feature">
  #### 実験的機能
</div>

* 動的なクラスターの自動検出をサポートしました。これは既存の *ノード* 自動検出機能を拡張するものです。ClickHouse は、`<multicluster_root_path>` を使用して、共通の ZooKeeper パス配下にある新しい *クラスター* を自動的に検出して登録できるようになりました。[#76001](https://github.com/ClickHouse/ClickHouse/pull/76001) ([Anton Ivashkin](https://github.com/ianton-ru)).
* 新しい設定 `enable_replacing_merge_with_cleanup_for_min_age_to_force_merge` により、設定可能なタイムアウト経過後に、パーティション全体に対する自動クリーンアップマージを実行できるようになりました。[#76440](https://github.com/ClickHouse/ClickHouse/pull/76440) ([Christoph Wurm](https://github.com/cwurm)).
* AWS S3 およびローカルファイルシステム上の Delta Lake テーブルで [Unity Catalog](https://www.databricks.com/product/unity-catalog) をサポートしました。[#76988](https://github.com/ClickHouse/ClickHouse/pull/76988) ([alesapin](https://github.com/alesapin)).
* Iceberg テーブル向けに、AWS Glue サービスカタログとの実験的なインテグレーションを導入しました。[#77257](https://github.com/ClickHouse/ClickHouse/pull/77257) ([alesapin](https://github.com/alesapin)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* コード内の一部箇所で `preserve_most` 属性を適用しました。[#67778](https://github.com/ClickHouse/ClickHouse/pull/67778) ([Nikita Taranov](https://github.com/nickitat)).
* 繰り返し使われる条件によるクエリパフォーマンス向上のため、query condition cache を実装しました。条件を満たさないデータ範囲を、メモリ上の一時的な索引として記憶します。後続のクエリではこの索引を利用します。close [#67768](https://github.com/ClickHouse/ClickHouse/issues/67768) ### ユーザー向け変更のドキュメントエントリ。[#69236](https://github.com/ClickHouse/ClickHouse/pull/69236) ([zhongyuankai](https://github.com/zhongyuankai)).
* [#70502](https://github.com/ClickHouse/ClickHouse/issues/70502) のテストに基づき、算術演算で Int256 と UInt256 を clang 組み込みの i256 に置き換えました。[#73658](https://github.com/ClickHouse/ClickHouse/pull/73658) ([李扬](https://github.com/taiyang-li)).
* 一部のケース (例: 空の array column) では、データパーツに空のファイルが含まれることがあります。テーブルが、メタデータとオブジェクトストレージが分離されたディスク上にある場合、そのようなファイルについては ObjectStorage への空のブロブの書き込みをスキップし、メタデータのみを保存できるようにしました。[#75860](https://github.com/ClickHouse/ClickHouse/pull/75860) ([Alexander Gololobov](https://github.com/davenger)).
* Decimal32/Decimal64/DateTime64 の min/max のパフォーマンスを改善しました。[#76570](https://github.com/ClickHouse/ClickHouse/pull/76570) ([李扬](https://github.com/taiyang-li)).
* パーツ削除時に cache からデータを積極的に退避させるようにしました。データ量が少ない場合に、cache が最大サイズまで肥大化しないようにしました。[#76641](https://github.com/ClickHouse/ClickHouse/pull/76641) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* クエリのコンパイル (設定 `compile_expressions`) で、マシンタイプを考慮するようになりました。これにより、この種のクエリが大幅に高速化されます。[#76753](https://github.com/ClickHouse/ClickHouse/pull/76753) ([Robert Schulze](https://github.com/rschu1ze)).
* [#77880](https://github.com/ClickHouse/ClickHouse/issues/77880) でバックポート: arraySort を最適化しました。[#76850](https://github.com/ClickHouse/ClickHouse/pull/76850) ([李扬](https://github.com/taiyang-li)).
* [#77961](https://github.com/ClickHouse/ClickHouse/issues/77961) でバックポート: マージなどで cache が受動的に使われる場合は、`filesystem_cache_prefer_bigger_buffer_size` を無効化しました。[#77898](https://github.com/ClickHouse/ClickHouse/pull/77898) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="improvement">
  #### 改善
</div>

* 並列レプリカが有効な場合、table function を対応する `-Cluster` 版に置き換えるようにしました。[#65024](https://github.com/ClickHouse/ClickHouse/issues/65024) を修正しました。[#70659](https://github.com/ClickHouse/ClickHouse/pull/70659) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* tuple カラム内のフィールドについて、カラム名の大文字・小文字を区別しないカラム照合を尊重するようにしました。[https://github.com/apache/incubator-gluten/issues/8324](https://github.com/apache/incubator-gluten/issues/8324) を解決しました。[#73780](https://github.com/ClickHouse/ClickHouse/pull/73780) ([李扬](https://github.com/taiyang-li)).
* codec Gorilla のパラメータが、今後は常に `.sql` ファイル内のテーブルメタデータに保存されるようになりました。これにより [#70072](https://github.com/ClickHouse/ClickHouse/issues/70072) を解決します。[#74814](https://github.com/ClickHouse/ClickHouse/pull/74814) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* [#77949](https://github.com/ClickHouse/ClickHouse/issues/77949) でバックポート: SSH プロトコルを再度有効化しました。いくつかの重大な脆弱性を修正し、カスタム pager の使用や `server-logs-file` の指定ができないようにしました。クライアントオプションを環境変数経由で渡す機能はデフォルトで無効化されました (`config.xml` の `ssh-server.enable_client_options_passing` を使えば引き続き利用可能です) 。progress table、クエリのキャンセル、補完、profile events progress、stdin、および `send_logs_level` オプションをサポートしました。これにより [#74340](https://github.com/ClickHouse/ClickHouse/issues/74340) を解決します。[#74989](https://github.com/ClickHouse/ClickHouse/pull/74989) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* パース機能を強化しました (Sequence ID parsing: マニフェストファイル内の sequence identifier をパースする機能を追加、および Avro metadata parsing: 将来の拡張を容易にするため、Avro メタデータパーサーを再設計) 。[#75010](https://github.com/ClickHouse/ClickHouse/pull/75010) ([Daniil Ivanik](https://github.com/divanik)).
* gauge/counter メトリクスタイプはすでにサポートされていますが、一部のメトリクス (たとえば keeper へのリクエストの response time) には不十分なため、histogram metric タイプのサポートを追加しました。このインターフェイスは Prometheus client に近い形になっており、値に対応する bucket 内のカウンターを増やすには `observe(value)` を呼び出すだけです。ヒストグラムメトリクスは system.histogram&#95;metrics を通じて公開されます。[#75736](https://github.com/ClickHouse/ClickHouse/pull/75736) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* system.opentelemetry&#95;span&#95;log のデフォルト ORDER BY から trace&#95;id を削除しました。[#75907](https://github.com/ClickHouse/ClickHouse/pull/75907) ([Azat Khuzhin](https://github.com/azat)).
* 暗号化 (XML attribute `encrypted_by`) を任意の configuration file (config.xml、users.xml、ネストされた configuration files) に適用できるようになりました。以前は最上位の config.xml ファイルでのみ機能していました。[#75911](https://github.com/ClickHouse/ClickHouse/pull/75911) ([Mikhail Gorshkov](https://github.com/mgorshkov)).
* 出力カラムが左テーブルに結び付いている場合に join を in サブクエリへ変換しますが、まず一意性を確保する step が必要なため、その step が追加されるまではデフォルトで無効化しました。[#75942](https://github.com/ClickHouse/ClickHouse/pull/75942) ([Shichao Jin](https://github.com/jsc0218)).
* `system.warnings` テーブルを改善し、追加・更新・削除できる動的な warning messages をいくつか追加しました。[#76029](https://github.com/ClickHouse/ClickHouse/pull/76029) ([Bharat Nallan](https://github.com/bharatnc)).
* この PR により、`DROP` 操作は順序上すべて先に来る必要があるため、`ALTER USER user1 ADD PROFILES a, DROP ALL PROFILES` というクエリは実行できなくなりました。[#76242](https://github.com/ClickHouse/ClickHouse/pull/76242) ([pufit](https://github.com/pufit)).
* SYNC REPLICA に関する各種改善 (エラーメッセージの改善、テストの強化、妥当性チェックの追加) 。[#76307](https://github.com/ClickHouse/ClickHouse/pull/76307) ([Azat Khuzhin](https://github.com/azat)).
* バックアップ中に Access Denied により S3 へのマルチパートコピーが失敗した場合に、適切なフォールバックを使用するようにしました。異なる認証情報を持つバケット間でバックアップを行うと、マルチパートコピーで Access Denied エラーが発生することがあります。 [#76515](https://github.com/ClickHouse/ClickHouse/pull/76515) ([Antonio Andelic](https://github.com/antonio2368)).
* ClickHouseサーバーのシャットダウンを高速化しました (2.5 秒の遅延を解消) 。 [#76550](https://github.com/ClickHouse/ClickHouse/pull/76550) ([Azat Khuzhin](https://github.com/azat)).
* librdkafka をバージョン 2.8.0 にアップグレードし、Kafkaテーブルのシャットダウンシーケンスを改善して、テーブル削除やサーバー再起動時の遅延を削減しました。`engine=Kafka` は、テーブル削除時にコンシューマグループから明示的に離脱しなくなりました。代わりに、コンシューマは `session_timeout_ms` (デフォルト: 45 秒) のあいだ非アクティブな状態が続いたあと自動的に削除されるまで、グループに残ります。 [#76621](https://github.com/ClickHouse/ClickHouse/pull/76621) ([filimonov](https://github.com/filimonov)).
* S3 リクエスト設定の検証を修正しました。 [#76658](https://github.com/ClickHouse/ClickHouse/pull/76658) ([Vitaly Baranov](https://github.com/vitlibar)).
* ReadBufferFromS3 およびその他のリモート読み取りバッファで過剰な割り当てを回避し、メモリ消費を半減しました。 [#76692](https://github.com/ClickHouse/ClickHouse/pull/76692) ([Sema Checherinda](https://github.com/CheSema)).
* `server_settings` や `settings` などのシステムテーブルには便利な `default` 値カラムがありますが、`merge_tree_settings` と `replicated_merge_tree_settings` ではそのカラムが有効になっていませんでした。 [#76942](https://github.com/ClickHouse/ClickHouse/pull/76942) ([Diego Nieto](https://github.com/lesandie)).
* `CurrentMetrics::QueryPreempted` と同じロジックを持つ `ProfileEvents::QueryPreempted` を追加しました。 [#77015](https://github.com/ClickHouse/ClickHouse/pull/77015) ([VicoWu](https://github.com/VicoWu)).
* 以前は replicated データベースで、クエリで指定された認証情報がログに出力されることがありました。この挙動を修正しました。これにより [#77123](https://github.com/ClickHouse/ClickHouse/issues/77123) はクローズされます。 [#77133](https://github.com/ClickHouse/ClickHouse/pull/77133) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* zstd を 1.5.5 から 1.5.7 に更新しました。このバージョンには優れた[パフォーマンス改善](https://github.com/facebook/zstd/releases/tag/v1.5.7)が含まれています。 [#77137](https://github.com/ClickHouse/ClickHouse/pull/77137) ([Pradeep Chhetri](https://github.com/chhetripradeep)).
* plain&#95;rewritable disk で `ALTER TABLE DROP PARTITION` を許可しました。 [#77138](https://github.com/ClickHouse/ClickHouse/pull/77138) ([Julia Kartseva](https://github.com/jkartseva)).
* ゼロコピー レプリケーションの場合に、マージ/ミューテーションの実行前に、part size に関係なく最大 500ms までランダムにスリープできるようにしました。 [#77165](https://github.com/ClickHouse/ClickHouse/pull/77165) ([Alexey Katsman](https://github.com/alexkats)).
* `TRUNCATE` を `INTO OUTFILE` とともに使用した場合の atomic rename をサポートしました。[#70323](https://github.com/ClickHouse/ClickHouse/issues/70323) を解決します。 [#77181](https://github.com/ClickHouse/ClickHouse/pull/77181) ([Onkar Deshpande](https://github.com/onkar)).
* Iceberg で読み込むメタデータファイルを、storage/table function の設定 `iceberg_metadata_file_path ` で明示的に指定できるようにしました。[#47412](https://github.com/ClickHouse/ClickHouse/issues/47412) を修正します。 [#77318](https://github.com/ClickHouse/ClickHouse/pull/77318) ([alesapin](https://github.com/alesapin)).
* この変更を元に戻しました。 [#77399](https://github.com/ClickHouse/ClickHouse/pull/77399) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* バックアップ/復元設定 `allow_s3_native_copy` が、3 つの設定可能な値をサポートするようになりました: - `False` - S3 ネイティブコピーは使用されません; - `True` (従来のデフォルト) - ClickHouse はまず S3 ネイティブコピーを試行し、失敗した場合は読み取り+書き込み方式にフォールバックします; - `'auto'` (新しいデフォルト) - ClickHouse はまずソースと宛先の認証情報を比較します。同じ場合は S3 ネイティブコピーを試行し、その後必要に応じて読み取り+書き込み方式にフォールバックすることがあります。異なる場合は、直接読み取り+書き込み方式に進みます。 [#77401](https://github.com/ClickHouse/ClickHouse/pull/77401) ([Vitaly Baranov](https://github.com/vitlibar)).
* スキッピング索引 cache が元に戻されました。 [#77447](https://github.com/ClickHouse/ClickHouse/pull/77447) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* wide パーツ内の JSON カラムのプリフェッチ時のメモリ使用量を削減。 [#77640](https://github.com/ClickHouse/ClickHouse/pull/77640) ([Pavel Kruglov](https://github.com/Avogar)).
* DeltaLake テーブルエンジン用の delta kernel で、AWS セッショントークンと環境認証情報の使用をサポート。 [#77661](https://github.com/ClickHouse/ClickHouse/pull/77661) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### バグ修正 (正式な安定版リリースにおけるユーザーに影響する不具合)
</div>

* async distributed INSERT の保留中バッチの処理中に停止する問題を修正しました (たとえば `No such file or directory` が原因の場合) 。[#72939](https://github.com/ClickHouse/ClickHouse/pull/72939) ([Azat Khuzhin](https://github.com/azat)).
* 暗黙的な Date から DateTime への変換で飽和動作を強制することにより、索引解析中の datetime 変換を改善しました。これにより、datetime の range 制限に起因する索引解析の不正確さの可能性を解消します。これで [#73307](https://github.com/ClickHouse/ClickHouse/issues/73307) を修正します。また、デフォルト値である `date_time_overflow_behavior = 'ignore'` の場合の明示的な `toDateTime` 変換も修正します。 [#73326](https://github.com/ClickHouse/ClickHouse/pull/73326) ([Amos Bird](https://github.com/amosbird)).
* UUID と table 名の競合によって発生する各種 bug を修正しました (たとえば `RENAME` と `RESTART REPLICA` の競合を修正します。`RENAME` と `SYSTEM RESTART REPLICA` が同時実行された場合、誤ったレプリカを再起動してしまったり、いずれかの table が `Table X is being restarted` 状態のままになったりする可能性があります) 。[#76308](https://github.com/ClickHouse/ClickHouse/pull/76308) ([Azat Khuzhin](https://github.com/azat)).
* 非同期 INSERT を有効にし、block size が異なる `insert into ... from file ...` を実行した場合に発生する data loss を修正しました。最初の block size が &lt; async&#95;max&#95;size で、2 番目の block が &gt; async&#95;max&#95;size の場合、2 番目の block は挿入されません。これらの data は `squashing` に残されたままになります。[#76343](https://github.com/ClickHouse/ClickHouse/pull/76343) ([Han Fei](https://github.com/hanfei1991)).
* `system.data_skipping_indices` 内の field &#39;marks&#39; を &#39;marks&#95;bytes&#39; にリネームしました。[#76374](https://github.com/ClickHouse/ClickHouse/pull/76374) ([Robert Schulze](https://github.com/rschu1ze)).
* エビクション中に予期しない error が発生する、動的なファイルシステムキャッシュの resize 処理を修正しました。[#76466](https://github.com/ClickHouse/ClickHouse/pull/76466) ([Kseniia Sumarokova](https://github.com/kssenii)).
