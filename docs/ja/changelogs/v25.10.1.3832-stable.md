<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* デフォルトの `schema_inference_make_columns_nullable` 設定を変更し、すべてを Nullable にするのではなく、Parquet/ORC/Arrow のメタデータに含まれるカラムの `Nullable` 情報を尊重するようにしました。テキストフォーマットについては変更ありません。 [#71499](https://github.com/ClickHouse/ClickHouse/pull/71499) ([Michael Kolupaev](https://github.com/al13n321)).
* この PR により、query result cache は `log_comment` 設定を無視するようになったため、クエリの `log_comment` だけを変更してもキャッシュミスは発生しなくなります。ユーザーが `log_comment` を変えることで意図的に cache を分割していた可能性はわずかにあります。この変更はその動作を変えるため、後方互換性はありません。この用途には `query_cache_tag` 設定を使用してください。 [#79878](https://github.com/ClickHouse/ClickHouse/pull/79878) ([filimonov](https://github.com/filimonov)).
* 以前のバージョンでは、演算子の実装関数と同名のテーブル関数を含むクエリで、フォーマットに一貫性がありませんでした。 [#81601](https://github.com/ClickHouse/ClickHouse/issues/81601) をクローズ。 [#81977](https://github.com/ClickHouse/ClickHouse/issues/81977) をクローズ。 [#82834](https://github.com/ClickHouse/ClickHouse/issues/82834) をクローズ。 [#82835](https://github.com/ClickHouse/ClickHouse/issues/82835) をクローズ。EXPLAIN SYNTAX クエリでは演算子はフォーマットされません。この新しい動作は、構文を説明するという目的をより適切に反映しています。`clickhouse-format`、`formatQuery` などは、クエリ内でそれらが関数形式で使われていた場合、関数を演算子としてフォーマットしません。 [#82825](https://github.com/ClickHouse/ClickHouse/pull/82825) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* JOIN の結合キーで Dynamic type を使用することを禁止しました。Dynamic type を非 Dynamic type と比較すると、予期しない結果につながる可能性があるためです。Dynamic カラムを必要な型にキャストすることを推奨します。 [#86358](https://github.com/ClickHouse/ClickHouse/pull/86358) ([Pavel Kruglov](https://github.com/Avogar)).
* Storage&#95;metadata&#95;write&#95;full&#95;object&#95;key server option はデフォルトで有効になり、現在は無効化できません。これは後方互換性のある変更です。注意喚起のために label を付けました。この変更は 25.x releases とのみ前方互換性があります。つまり、新しい release を rollback する必要がある場合、downgrade できるのは 25.x release のいずれかに限られます。 [#87335](https://github.com/ClickHouse/ClickHouse/pull/87335) ([Sema Checherinda](https://github.com/CheSema)).
* 挿入レートが低い場合に ZooKeeper 上の znode の保存数を減らすため、replicated&#95;deduplication&#95;window&#95;seconds を 1 週間から 1 時間に短縮しました。 [#87414](https://github.com/ClickHouse/ClickHouse/pull/87414) ([Sema Checherinda](https://github.com/CheSema)).
* 設定 `query_plan_use_new_logical_join_step` を `query_plan_use_logical_join_step` にリネームしました。 [#87679](https://github.com/ClickHouse/ClickHouse/pull/87679) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 新しい構文により、トークナイザーの parameter をより柔軟に指定できるようになりました。 [#87997](https://github.com/ClickHouse/ClickHouse/pull/87997) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 既存の関数 `hasToken` との整合性を高めるため、関数 `searchAny` と `searchAll` を `hasAnyTokens` と `hasAllTokens` にリネームしました。 [#88109](https://github.com/ClickHouse/ClickHouse/pull/88109) ([Robert Schulze](https://github.com/rschu1ze)).
* ファイルシステムキャッシュから `cache_hits_threshold` を削除しました。この機能は、SLRU cache policy が存在する前に外部コントリビューターによって追加されたものですが、現在はそれがあるため、両方をサポートする意味はありません。 [#88344](https://github.com/ClickHouse/ClickHouse/pull/88344) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `min_free_disk_ratio_to_perform_insert` と `min_free_disk_bytes_to_perform_insert` の設定の動作に、軽微な変更が 2 つあります: - `insert` を拒否するかどうかの判定に、available bytes ではなく unreserved bytes を使用します。background merges と mutations の予約量が設定されたしきい値に比べて小さい場合、これはおそらくそれほど重要ではありませんが、こちらのほうがより適切と思われます。 - これらの設定はシステムテーブルには適用しません。これは、`query_log` のようなテーブルは引き続き更新されるようにしたいためです。これによりデバッグがかなり容易になります。システムテーブルに書き込まれるデータは通常、実際のデータに比べて小さいため、`min_free_disk_ratio_to_perform_insert` のしきい値が妥当であれば、より長く書き込みを継続できるはずです。 [#88468](https://github.com/ClickHouse/ClickHouse/pull/88468) ([c-end](https://github.com/c-end)).
* Keeper の内部レプリケーションで async mode を有効化しました。Keeper は従来と同じ動作を維持しつつ、パフォーマンスが向上する可能性があります。23.9 より前のバージョンから更新する場合は、まず 23.9+ に更新してから 25.10+ に更新する必要があります。また、更新前に `keeper_server.coordination_settings.async_replication` を 0 に設定し、更新完了後に有効化することもできます。 [#88515](https://github.com/ClickHouse/ClickHouse/pull/88515) ([Antonio Andelic](https://github.com/antonio2368)).

* `LIMIT BY ALL` 構文のサポートを追加しました。`GROUP BY ALL` や `ORDER BY ALL` と同様に、`LIMIT BY ALL` は SELECT clause 内のすべての非 aggregate expressions を `LIMIT BY` キーとして自動的に展開します。たとえば、`SELECT id, name, count(*) FROM table GROUP BY id LIMIT 1 BY ALL` は `SELECT id, name, count(*) FROM table GROUP BY id LIMIT 1 BY id, name` と同等です。この feature により、選択したすべての非 aggregate カラムを明示的に列挙しなくても、それらすべてを対象に制限したい場合の queries を簡潔にできます。[#59152](https://github.com/ClickHouse/ClickHouse/issues/59152) をクローズします。[#84079](https://github.com/ClickHouse/ClickHouse/pull/84079) ([Surya Kant Ranjan](https://github.com/iit2009046)).
* ClickHouse で Apache Paimon をクエリするためのサポートを追加しました。このインテグレーションにより、ClickHouse ユーザーは Paimon のデータレイクストレージを直接利用できるようになります。[#84423](https://github.com/ClickHouse/ClickHouse/pull/84423) ([JIaQi](https://github.com/JiaQiTang98)).
* `studentTTestOneSample` aggregate function を追加しました。[#85436](https://github.com/ClickHouse/ClickHouse/pull/85436) ([Dylan](https://github.com/DylanBlakemore)).
* histogram の buckets の上限と累積値を argument として受け取り、quantile の位置が見つかった bucket の上限と下限の間で linear interpolation を行う aggregate function `quantilePrometheusHistogram` を追加しました。従来の histogram に対する PromQL の `histogram_quantile()` 関数と同様に動作します。[#86294](https://github.com/ClickHouse/ClickHouse/pull/86294) ([Stephen Chi](https://github.com/stephchi0)).
* `MergeTree` table の適切なすべてのカラムに対して統計情報を自動作成する機能を追加しました。作成する統計情報の types をカンマ区切りで格納する table レベル setting `auto_statistics_types` も追加しました (例: `auto_statistics_types = 'minmax, uniq, countmin'`) 。[#87241](https://github.com/ClickHouse/ClickHouse/pull/87241) ([Anton Popov](https://github.com/CurtizJ)).
* Delta Lake の metadata files 用の system table。[#87263](https://github.com/ClickHouse/ClickHouse/pull/87263) ([scanhex12](https://github.com/scanhex12)).
* zookeeper の切断と再接続を強制する SYSTEM RECONNECT ZOOKEEPER コマンドを追加しました (https://github.com/ClickHouse/ClickHouse/issues/87317)。[#87318](https://github.com/ClickHouse/ClickHouse/pull/87318) ([Pradeep Chhetri](https://github.com/chhetripradeep)).
* setting `max_named_collection_num_to_warn` および `max_named_collection_num_to_throw` によって named collections の数を制限できるようにしました。新しい Metric `NamedCollection` と error `TOO_MANY_NAMED_COLLECTIONS` も追加しました。[#87343](https://github.com/ClickHouse/ClickHouse/pull/87343) ([Pablo Marcos](https://github.com/pamarcos)).
* `startsWith` および `endsWith` 関数の、最適化された case-insensitive バリアント `startsWithCaseInsensitive`、`endsWithCaseInsensitive`、`startsWithCaseInsensitiveUTF8`、`endsWithCaseInsensitiveUTF8` を追加しました。[#87374](https://github.com/ClickHouse/ClickHouse/pull/87374) ([Guang Zhao](https://github.com/zheguang)).
* server configuration の &quot;resources&#95;and&#95;workloads&quot; セクションを使用して、SQL で WORKLOAD と RESOURCE の定義を指定する方法を追加しました。[#87430](https://github.com/ClickHouse/ClickHouse/pull/87430) ([Sergei Trifonov](https://github.com/serxa)).
* `Alias` engine は、別のテーブルへの proxy を作成します。すべての読み取りおよび書き込み操作はターゲットテーブルに転送され、alias 自体にはデータは保存されず、ターゲットテーブルへの参照のみを保持します。[#87965](https://github.com/ClickHouse/ClickHouse/pull/87965) ([Kai Zhu](https://github.com/nauu)).
* セミコロンを新しい行ではなく末尾の行に配置するようにクエリを整形する `--semicolons_inline` オプションを追加しました。[#88018](https://github.com/ClickHouse/ClickHouse/pull/88018) ([Jan Rada](https://github.com/ZelvaMan)).
* パーツを wide パーツとして作成するための最小レベルを指定できる、新しいテーブル設定 `min_level_for_wide_part` を追加しました。[#88179](https://github.com/ClickHouse/ClickHouse/pull/88179) ([Christoph Wurm](https://github.com/cwurm)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* Query Condition Cache (QCC) と索引解析の順序およびインテグレーションをリファクタリングし、クエリパフォーマンスを改善しました。QCC のフィルタリングは主キーおよびスキップ索引の解析より前に適用されるようになり、不要な索引計算を削減します。索引解析は複数の範囲フィルターをサポートするよう拡張され、そのフィルタリング結果は QCC に書き戻されるようになりました。これにより、索引解析が実行時間の大半を占めるクエリ、特にスキップ索引 (ベクトル索引や転置索引など) に依存するクエリが大幅に高速化されます。 [#82380](https://github.com/ClickHouse/ClickHouse/pull/82380) ([Amos Bird](https://github.com/amosbird)).
* MergeTree テーブル内のトップレベルの String 型のカラムに対して、オプションの `.size` サブカラムのシリアライゼーションを追加し、圧縮率を向上させるとともに効率的なサブカラムアクセスを可能にしました。さらに、シリアル化バージョンの制御と空文字列の式最適化のための新しい MergeTree settings を導入しました。 [#82850](https://github.com/ClickHouse/ClickHouse/pull/82850) ([Amos Bird](https://github.com/amosbird)).
* 小規模なクエリを高速化するため、多数のマイクロ最適化を行いました。 [#83096](https://github.com/ClickHouse/ClickHouse/pull/83096) ([Raúl Marín](https://github.com/Algunenano)).
* ネイティブプロトコルでログと profile events を圧縮するようにしました。100 を超えるレプリカを持つクラスターでは、非圧縮の profile events が 1..10 MB/秒に達し、低速なインターネット接続では進行状況バーの反応が鈍くなります。これにより [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533) をクローズします。 [#83586](https://github.com/ClickHouse/ClickHouse/pull/83586) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [StringZilla](https://github.com/ashvardanian/StringZilla) ライブラリを使用し、利用可能な場合は SIMD CPU 命令を活用することで、大文字小文字を区別する文字列検索 (`WHERE URL LIKE '%google%'` のようなフィルタリング操作など) のパフォーマンスを改善しました。 [#84161](https://github.com/ClickHouse/ClickHouse/pull/84161) ([Raúl Marín](https://github.com/Algunenano)).
* `SimpleAggregateFunction(anyLast)` 型のカラムを持つテーブルに対して FINAL を付けて集約 MergeTree テーブルから select する際の、メモリ割り当てとメモリコピーを削減しました。 [#84428](https://github.com/ClickHouse/ClickHouse/pull/84428) ([Duc Canh Le](https://github.com/canhld94)).
* OR 条件を含む JOIN predicates をプッシュダウンするためのロジックを追加しました。例: TPC-H Q7 において、2 つのテーブル n1 と n2 に対する `(n1.n_name = 'FRANCE' AND n2.n_name = 'GERMANY') OR (n1.n_name = 'GERMANY' AND n2.n_name = 'FRANCE')` のような条件から、各テーブル向けに個別の部分フィルターを抽出します。n1 には `n1.n_name = 'FRANCE' OR n1.n_name = 'GERMANY'`、n2 には `n2.n_name = 'GERMANY' OR n2.n_name = 'FRANCE'` を抽出します。 [#84735](https://github.com/ClickHouse/ClickHouse/pull/84735) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 新しいデフォルト設定 `optimize_rewrite_like_perfect_affix` により、接頭辞または接尾辞付きの `LIKE` のパフォーマンスを改善しました。 [#85920](https://github.com/ClickHouse/ClickHouse/pull/85920) ([Guang Zhao](https://github.com/zheguang)).
* 複数の文字列/数値カラムでグループ化する際に、大きなシリアライズ済みキーが原因で発生していたパフォーマンス低下を修正しました。https://github.com/ClickHouse/ClickHouse/pull/83884#issuecomment-3187972297 cc @mkmkme をクローズします。これは https://github.com/ClickHouse/ClickHouse/pull/83884 のフォローアップです。 [#85924](https://github.com/ClickHouse/ClickHouse/pull/85924) ([李扬](https://github.com/taiyang-li)).
* DB::SharedMutex を改善しました。 [#87491](https://github.com/ClickHouse/ClickHouse/pull/87491) ([Raúl Marín](https://github.com/Algunenano)).
* 出現頻度の低いトークンを主に含むドキュメントに対するテキスト索引構築のパフォーマンスを改善しました。 [#87546](https://github.com/ClickHouse/ClickHouse/pull/87546) ([Anton Popov](https://github.com/CurtizJ)).
* Field デストラクタの一般的なケースを高速化しました。 [#87631](https://github.com/ClickHouse/ClickHouse/pull/87631) ([Raúl Marín](https://github.com/Algunenano)).
* join 最適化時の runtime hash table 統計の再計算をスキップするようにしました。新しい profile events `JoinOptimizeMicroseconds` と `QueryPlanOptimizeMicroseconds` を追加しました。[#87683](https://github.com/ClickHouse/ClickHouse/pull/87683) ([Vladimir Cherkasov](https://github.com/vdimir)).
* `marks` を cache に保存できるようにし、MergeTreeLazy reader で direct I/O を回避するようにしました。[#87989](https://github.com/ClickHouse/ClickHouse/pull/87989) ([Nikita Taranov](https://github.com/nickitat)).
* `is_deleted` カラムを持つ `ReplacingMergeTree` table に対する `FINAL` clause 付きの SELECT クエリが、既存の 2 つの最適化による parallelization の改善により、より高速に実行されるようになりました: 1) `part` が 1 つしかない table のパーティションに対する `do_not_merge_across_partitions_select_final` 最適化 2) table のその他の選択 範囲 を `intersecting / non-intersecting` に 分割 し、交差する 範囲 のみが FINAL merging transform を通過するようにしました。[#88090](https://github.com/ClickHouse/ClickHouse/pull/88090) ([Shankar Iyer](https://github.com/shankar-iyer)).
* fail point を使用しない場合の影響を軽減しました。[#88196](https://github.com/ClickHouse/ClickHouse/pull/88196) ([Raúl Marín](https://github.com/Algunenano)).
* `uuid` で filter した場合の `system.tables` に対する full scan を回避するようにしました (logs または ZooKeeper パス から UUID しか得られない場合に有用です) 。[#88379](https://github.com/ClickHouse/ClickHouse/pull/88379) ([Azat Khuzhin](https://github.com/azat)).
* 関数 `tokens`、`hasAllTokens`、`hasAnyTokens` のパフォーマンスを改善しました。[#88416](https://github.com/ClickHouse/ClickHouse/pull/88416) ([Anton Popov](https://github.com/CurtizJ)).
* Iceberg で Read in order をサポートしました。[#88454](https://github.com/ClickHouse/ClickHouse/pull/88454) ([scanhex12](https://github.com/scanhex12)).
* 一部のケースで join のパフォーマンスをわずかに向上させるため、`AddedColumns::appendFromBlock` を inline 化しました。[#88455](https://github.com/ClickHouse/ClickHouse/pull/88455) ([Nikita Taranov](https://github.com/nickitat)).
* [#89182](https://github.com/ClickHouse/ClickHouse/issues/89182)でバックポート: JOIN と ARRAY JOIN で lazy カラムの レプリケーション を実装しました。一部の 出力フォーマット で、Sparse や Replicated のような特殊なカラム表現を full columns に変換しないようにしました。これにより、メモリ内での不要なデータコピーを回避します。[#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar)).
