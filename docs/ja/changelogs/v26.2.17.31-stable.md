<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* [#103353](https://github.com/ClickHouse/ClickHouse/issues/103353) でバックポート: 認証前の HTTP 接続によるメモリ使用量を制限するため、デフォルトの `http_max_fields` を 1,000,000 から 1,000 に、`http_max_field_name_size` を 128 KB から 4 KB に引き下げました。`http_max_request_header_size` および `http_headers_read_timeout` 設定も追加しました。以前のより高い上限を前提としているユーザーは、設定でこれらの値を元に戻せます。[#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).

<div id="new-feature">
  #### 新機能
</div>

* [#103503](https://github.com/ClickHouse/ClickHouse/issues/103503) でバックポート: S3 GET リクエストの接続ライフタイムと消費バイト数を観測するための `s3_read_request_duration_microseconds` および `s3_read_request_bytes` のヒストグラムメトリクスを追加。`system.histogram_metrics` と Prometheus エンドポイントで確認できます。[#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)).

<div id="improvement">
  #### 改善
</div>

* [#102957](https://github.com/ClickHouse/ClickHouse/issues/102957) でバックポート: `MAX_BLOCK_NUMBER` を約10億から約21億 (`Int32` の最大値) に引き上げます。1秒あたり約60回の insert が発生する高負荷のインスタンスでは、数か月でブロック番号が従来の上限を超える可能性があり、その結果、`DROP PARTITION` やミューテーションなどの操作で新しいパーツが気付かれないままスキップされるおそれがありました。この変更により、Keeper の sequence number の安全な範囲内に収めたまま、より大きなヘッドルームを確保できます。[#102243](https://github.com/ClickHouse/ClickHouse/pull/102243) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* [#103198](https://github.com/ClickHouse/ClickHouse/issues/103198) でバックポート: system.stack&#95;trace でスレッドごとの untracked&#95;memory を公開します。[#103065](https://github.com/ClickHouse/ClickHouse/pull/103065) ([Azat Khuzhin](https://github.com/azat)).
* [#103380](https://github.com/ClickHouse/ClickHouse/issues/103380) でバックポート: `max_network_bandwidth_for_user`/`max_network_bandwidth_for_all_users` をリモートファイルシステムの読み取り/書き込みに適用します。[#103080](https://github.com/ClickHouse/ClickHouse/pull/103080) ([Azat Khuzhin](https://github.com/azat)).
