<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* 通常のプロジェクションのメタデータを修正し、複数カラムのソートキーを持つプロジェクションが正しく認識されるようにしました。 [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429) をベースにしています。 [#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* ネストされたデータ型にも、データ型のシリアル化バージョンを伝播するようにしました。たとえば、以前は String のシリアル化バージョン `with_size_stream` は最上位の String 型のカラムと Tuple 要素にのみ適用されていました。現在は、Array/Map/Variant/JSON など、あらゆる Nested 型内の String 型にも適用されます。この動作は MergeTree setting `propagate_types_serialization_versions_to_nested_types` で制御され、現在はデフォルトで有効です。この変更後、新しく作成された data パーツ は古いバージョンでは読み取れませんが、古いパーツは新しいバージョンでも問題なく読み取れます。つまり、アップグレードは安全ですが、ダウングレードは安全ではありません。 [#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* `hypothesis` スキップ索引タイプを削除しました。これは実用性が限られた、わかりにくい実験的機能でした。今後は、`INDEX ... TYPE hypothesis` を使ってテーブルを作成するとエラーになります。 [#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* スキップ索引ファイルが replace&#95;long&#95;file&#95;name&#95;to&#95;hash setting を考慮せず、名前の長い索引で &quot;File name too long&quot; エラーや索引の読み取り不具合を引き起こしていた問題を修正しました。スキップ索引のファイル名は、カラムファイルと同様に、max&#95;file&#95;name&#95;length を超える場合はハッシュ化されるようになりました。これは後方互換です (新しいサーバーは古いパーツを読み取れます) が、ダウングレード時 (または rolling upgrade 中の古いサーバー) には、名前の長い索引が無視される可能性があります。 [#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* 非同期 INSERT をデフォルトで有効にしました。これにより、ClickHouse は今後、小さな insert をデフォルトでバッチ処理します。この設定は compatibility の配下にあります。`compatibility=<version less than 26.2>` を設定した場合、デフォルト値は従来どおり `false` になります。非同期 INSERT は、設定ファイル内のユーザープロファイル、セッション、クエリ、または MergeTree テーブルの各レベルでオフ/オンできます。 [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* `NOT` 演算子の優先順位を SQL 標準に合わせて修正しました。`NOT` は `IS NULL`、`BETWEEN`、`LIKE`、および算術演算子よりも結合順位が低くなりました。たとえば、`NOT (x) IS NULL` は、以前の `(NOT x) IS NULL` ではなく、現在は `NOT (x IS NULL)` として解析されます。これにより、以前の (標準外の) 動作に依存していたクエリの結果が変わる可能性があります。 [#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `mysql_datatypes_support_level` のデフォルト値を空から `decimal,datetime64,date2Date32` に変更し、MySQL の `DATE` を `Date32`、`DECIMAL`/`NUMERIC` を `Decimal`、精度付きの `DATETIME`/`TIMESTAMP` を `DateTime64` にデフォルトで正しくマッピングできるようにしました。以前は MySQL の `DATE` カラムは `Date` にマッピングされていましたが、これは 1970-01-01 より前の日付を表現できず、データ破損の原因になっていました。 [#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `mergeTreeAnalyzeIndexes{,UUID}` では、regexp の代わりに part 名の配列を受け付けるようにしました。正規表現は低速なためです (*Experimental feature*) 。 [#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* 実験的な `detectProgrammingLanguage` 関数を削除しました。 [#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* `mergeTreeTextIndex(database, table, index)` テーブル関数を追加しました。これにより、テキスト索引から直接データを読み取れます。この関数は、イントロスペクションや、テキスト索引データに対する集計の実行に利用できます。 [#97003](https://github.com/ClickHouse/ClickHouse/pull/97003) ([Anton Popov](https://github.com/CurtizJ)).

* Iceberg table に対する `ALTER TABLE ... EXECUTE expire_snapshots('<timestamp>')` を実装しました。 [#97904](https://github.com/ClickHouse/ClickHouse/pull/97904) ([murphy-4o](https://github.com/murphy-4o)).
* Parquet メタデータ用の新しい SLRU キャッシュを追加し、メタデータを読むためだけにファイルを再ダウンロードする必要をなくすことで、読み取り性能を向上させました。 [#98140](https://github.com/ClickHouse/ClickHouse/pull/98140) ([Grant Holly](https://github.com/grantholly-clickhouse)).
* `<protocols>` 内の各 `type=http` エントリで、別個の `<http_handlers_*>` config セクションを指すカスタム `<handlers>` キーを指定できるようにし、ポートごとに異なる HTTP ルーティングルールを使えるようにしました。 [#98414](https://github.com/ClickHouse/ClickHouse/pull/98414) ([Amos Bird](https://github.com/amosbird)).
* `EXPLAIN [PLAN]` コマンドに関する 2 つの改善。 [#98500](https://github.com/ClickHouse/ClickHouse/pull/98500) ([Kirill Kopnev](https://github.com/Fgrtue)).
* `restore_access_entities_with_current_grants` サーバー設定を追加しました。有効にすると、復元されたユーザー/ロールの権限は、復元を実行するユーザーが付与できる範囲に制限されます (`GRANT CURRENT GRANTS` と同じセマンティクス) 。そのため、`ACCESS_DENIED` で失敗する代わりに復元が実行されます。[#98795](https://github.com/ClickHouse/ClickHouse/pull/98795) ([pufit](https://github.com/pufit)).
* Unicode の大文字・小文字の折りたたみとダイアクリティカルマークの除去を行う `caseFoldUTF8` 関数と `removeDiacriticsUTF8` 関数を追加しました。[#98973](https://github.com/ClickHouse/ClickHouse/pull/98973) ([George Larionov](https://github.com/george-larionov)).
* `SymbolIndex`、`addressToSymbol`、`system.symbols`、`buildId` が、Mach-O シンボルテーブルをパースすることで macOS でも動作するようになりました。[#99014](https://github.com/ClickHouse/ClickHouse/pull/99014) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* NFKC 正規化とケースフォールディングを組み合わせる、NFKC&#95;Casefold Unicode 正規化用の文字列関数 `normalizeUTF8NFKCCasefold` を追加しました。[#99276](https://github.com/ClickHouse/ClickHouse/pull/99276) ([George Larionov](https://github.com/george-larionov)).
* 全文索引および `tokens` 関数向けに `unicode_word` トークナイザーを追加しました。Unicode の単語境界規則を使ってテキストを分割します。ASCII の単語はコネクタ文字 (アンダースコア、コロン、ドット、シングルクォート) を含めて構成され、非 ASCII の Unicode 文字は 1 文字ずつのトークンになります。設定可能な stop words のデフォルトは、一般的な CJK の句読点です。[#99357](https://github.com/ClickHouse/ClickHouse/pull/99357) ([Amos Bird](https://github.com/amosbird)).
* `skip_unavailable_shards` が有効なときに、警告なしでスキップできる利用不能な分片の数を制限するため、`max_skip_unavailable_shards_num` と `max_skip_unavailable_shards_ratio` 設定を追加しました。利用不能な分片の数または比率が設定したしきい値を超えると、黙って不完全な結果を返すのではなく、例外が発生します。[#99369](https://github.com/ClickHouse/ClickHouse/pull/99369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* サブクエリ式で `SOME` keyword を使用できるようになりました。動作は `ANY` と同一です。[#99842](https://github.com/ClickHouse/ClickHouse/pull/99842) ([Artem Kytkin](https://github.com/Vinceent)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* 大きなポリゴンに対する `pointInPolygon` の granule スキップを最適化し、主キーのプルーニング時に `pointInPolygon` の索引解析で例外が発生する問題を修正しました。[#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `levenshteinDistance` 関数のパフォーマンスを改善しました。[#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)).
* 要素ごとの関数呼び出しを避けることで、バッチの Decimal 型変換を最適化しました。[#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 1. Iceberg に、メタデータを非同期で事前に cache に読み込む機能が追加されました。これは、テーブル作成時に `iceberg_metadata_async_prefetch_period_ms` を設定することで有効にできます。例: `CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. Iceberg table に対する SELECT クエリで、`iceberg_metadata_staleness_ms` パラメータを指定して実行できるようになりました。これにより、cache 内のメタデータが指定した staleness より新しい場合、ClickHouse はそのメタデータを利用できます。そうでない場合は、リクエストを処理するため、最新のメタデータを取得する目的でリモートの Iceberg カタログに問い合わせます (従来どおりの動作です) 。この変更により、リクエスト処理中の Iceberg カタログへの呼び出しを 0 まで減らせるため、目に見える性能向上が期待されます。例: `SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`. [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)).
* S3Queue の Ordered mode では、S3 ListObjectsV2 の StartAfter を使用してプレフィックス全体の履歴を再列挙するのを避け、ListObjects の呼び出し回数を削減します。[#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* 一般に、deduplication には元の block が必要ですが、同期 insert ではこれを省略できるため、メモリを大幅に節約できます。[#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* YTsaurus table engine からの並列 read を有効化しました。[#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* cache line size には、64 というハードコードされた値ではなく、アーキテクチャ固有の値を使用するようにしました。[#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
* オプティマイザの統計情報に基づいて、ANTI、SEMI、FULL joins の左右を入れ替えられるようにしました。[#97498](https://github.com/ClickHouse/ClickHouse/pull/97498) ([Hechem Selmi](https://github.com/m-selmi)).
* テキスト索引 Dictionary からの読み取りをわずかに最適化し、テキスト索引解析全体のパフォーマンスを向上させました。[#97519](https://github.com/ClickHouse/ClickHouse/pull/97519) ([Anton Popov](https://github.com/CurtizJ)).
* ARM における 16 バイト block の LZ4 展開を高速化しました。[#97774](https://github.com/ClickHouse/ClickHouse/pull/97774) ([Raúl Marín](https://github.com/Algunenano)).
* トークン化を新しい高性能な `forEachToken` コールバックインターフェイスにリファクタリングし、SIMD と Stateful なトークナイザーをサポートするため、従来のイテレータ形式の API を置き換えました。[#90268](https://github.com/ClickHouse/ClickHouse/issues/90268) の一部です。[#97871](https://github.com/ClickHouse/ClickHouse/pull/97871) ([Amos Bird](https://github.com/amosbird)).
* 索引付きカラムと索引なしカラムの両方を含む複合条件を持つクエリで、テキスト索引解析のパフォーマンスを改善しました。従来は、このようなケースで索引解析中の早期終了最適化が誤って無効化されていました。[#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).
* 非常に長い配列や map を生成する定数式を含むクエリのパフォーマンスを改善しました。[#98287](https://github.com/ClickHouse/ClickHouse/pull/98287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 整数定数と比較される `DateTime64` 主キーに対する key condition 解析を修正しました。従来は、その結果として granule pruning が行われませんでした。[#98410](https://github.com/ClickHouse/ClickHouse/pull/98410) ([Amos Bird](https://github.com/amosbird)).
* 設定 `optimize_syntax_fuse_functions` がデフォルトで有効になりました。[#98424](https://github.com/ClickHouse/ClickHouse/pull/98424) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* predicate に任意の比較演算子 (`=`, `<`, `>`, `!=`) が含まれ、かつ partition key が決定論的な function chain でラップされている場合に、partition pruning を行えるようにしました (たとえば、`PARTITION BY x` で `cityHash64(x) % 5 > 2`、`toYYYYMM(x) < 2026`、`toYYYYMM(x) = 2026`、`toYYYYMM(x) != 2026` のような predicates では、いずれも pruning に partition key が使用されます) 。[#28800](https://github.com/ClickHouse/ClickHouse/issues/28800) をクローズします。[#98432](https://github.com/ClickHouse/ClickHouse/pull/98432) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `CAST` の対象型が `Nullable` で、かつ変換が monotonic な場合に、read-in-order 最適化と主キー pruning を行えるようにしました。たとえば `PRIMARY KEY x` の場合、ClickHouse は `ORDER BY x::Nullable(UInt64)` に対して read-in-order 最適化を使用でき、`WHERE x::Nullable(UInt64) > 500000` のような predicates には主キー pruning を適用できます。[#98482](https://github.com/ClickHouse/ClickHouse/pull/98482) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 整数型のカラムを浮動小数点リテラルと比較する際に、インデックス pruning と filter pushdown を有効にしました。たとえば、`WHERE x < 10.5` のような predicate では pruning のために主キーを使用できるようになり、`prime < 1e9` や `number < 1e5` のような filter も、無制限実行を引き起こす代わりに `primes()` および `numbers()` table function に対して pushdown されるようになりました。[#85167](https://github.com/ClickHouse/ClickHouse/issues/85167) をクローズしました。[#98516](https://github.com/ClickHouse/ClickHouse/pull/98516) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* aggregate state を介した行ごとのストアフォワーディングではなくローカルアキュムレーターを使うことで、`avgWeighted` aggregate function を最適化し、Nullable 入力で最大 27% の性能向上を実現しました。[#98793](https://github.com/ClickHouse/ClickHouse/pull/98793) ([Antonio Andelic](https://github.com/antonio2368)).
* 特定のシナリオにおける並列 window functions や、大きな Array に対する arrayFold workload で、性能を向上させるとともにメモリ使用量を削減しました。これにより、該当する queries ではページフォールトの負荷が軽減され、厳しいメモリ制限下での安定性向上も期待できます。[#98892](https://github.com/ClickHouse/ClickHouse/pull/98892) ([filimonov](https://github.com/filimonov)).
