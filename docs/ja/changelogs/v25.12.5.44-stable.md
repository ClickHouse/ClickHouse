<div id="improvement">
  #### 改善
</div>

* [#94935](https://github.com/ClickHouse/ClickHouse/issues/94935)でバックポート: dirty pages サイズと `max_server_memory_usage` の比率が `memory_worker_purge_dirty_pages_threshold_ratio` を超えた場合に、jemalloc アリーナのパージを強制実行するようにしました。[#93500](https://github.com/ClickHouse/ClickHouse/pull/93500) ([Eduard Karacharov](https://github.com/korowa))。
* [#95133](https://github.com/ClickHouse/ClickHouse/issues/95133)でバックポート: `FINAL` クエリで使用されるスキップ索引が主キーの一部であるカラムに対するものである場合、他のパーツで主キーの積集合を確認する追加のステップは不要なため、実行しないようになりました。[#85897](https://github.com/ClickHouse/ClickHouse/issues/85897) を解決します。[#93899](https://github.com/ClickHouse/ClickHouse/pull/93899) ([Shankar Iyer](https://github.com/shankar-iyer))。
* [#94709](https://github.com/ClickHouse/ClickHouse/issues/94709)でバックポート: S3 および Azure Blob Storage 向けの BACKUP/RESTORE で、SQL で定義した named collections をサポートしました。[#94604](https://github.com/ClickHouse/ClickHouse/issues/94604) をクローズします。[#94605](https://github.com/ClickHouse/ClickHouse/pull/94605) ([Pablo Marcos](https://github.com/pamarcos))。
* [#94988](https://github.com/ClickHouse/ClickHouse/issues/94988)でバックポート: CPU が逼迫している状況では、スケジューラが MemoryWorker スレッドを優先するようにしました。これは ClickHouse プロセスを致命的な事態から保護するためです。[#94864](https://github.com/ClickHouse/ClickHouse/pull/94864) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov))。
* [#95167](https://github.com/ClickHouse/ClickHouse/issues/95167)でバックポート: jemalloc の dirty pages のパージを、MemoryWorker のメインスレッドとは別のスレッドで実行するようにしました。パージが遅いと RSS 使用量の更新が遅れ、プロセスがメモリ不足で kill される可能性があります。総メモリ使用量の比率に基づいて dirty pages のパージを開始するための新しい config `memory_worker_purge_total_memory_threshold_ratio` を導入しました。[#94902](https://github.com/ClickHouse/ClickHouse/pull/94902) ([Antonio Andelic](https://github.com/antonio2368))。
* [#95438](https://github.com/ClickHouse/ClickHouse/issues/95438)でバックポート: `view_duration_ms` は、グループ内のスレッド時間の合計ではなく、グループがアクティブだった時間を表示するようになりました。[#94966](https://github.com/ClickHouse/ClickHouse/pull/94966) ([Sema Checherinda](https://github.com/CheSema))。
* [#95365](https://github.com/ClickHouse/ClickHouse/issues/95365)でバックポート: TTL の drop part merges で `max_parts_to_merge_at_once` を尊重するようにしました。[#95315](https://github.com/ClickHouse/ClickHouse/pull/95315) ([Kseniia Sumarokova](https://github.com/kssenii))。

* [#95759](https://github.com/ClickHouse/ClickHouse/issues/95759)でバックポート: `system.query_log.exception` で stderr のキャプチャを有効にし、UDF のデバッグを改善しました。従来、UDF の stderr はファイルにしか記録されず、クエリログには出力されなかったため、デバッグは事実上不可能でした。現在は、stderr がデフォルトで例外をトリガーし、例外送出前に最大 1MB まで完全に蓄積されるようになったため、完全な Python トレースバックとエラーメッセージが `system.query_log.exception` に記録され、効果的なトラブルシューティングが可能になりました。 [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
