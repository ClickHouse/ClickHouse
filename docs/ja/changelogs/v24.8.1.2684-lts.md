  ### ClickHouse リリース v24.8.1.2684-lts (161c62fd295) FIXME v24.8.1.1-new (3f8b27d7acc) との比較
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `clickhouse-client` と `clickhouse-local` は、デフォルトで単一クエリモードではなくマルチクエリモードを使用するようになりました。たとえば、`clickhouse-client -q "SELECT 1; SELECT 2"` はそのまま動作するようになり、以前のように `--multiquery` (または `-n`) を追加する必要はありません。`--multiquery/-n` スイッチは廃止されました。マルチクエリ文内の INSERT クエリは、FORMAT clause に応じて特別に扱われます。FORMAT が `VALUES` の場合 (最も一般的なケース) 、INSERT ステートメントの終端はクエリ末尾のセミコロン `;` で表されます。それ以外のすべての FORMAT (たとえば `CSV` や `JSONEachRow`) では、INSERT ステートメントの終端はクエリ末尾の 2 つの改行 `\n\n` で表されます。[#63898](https://github.com/ClickHouse/ClickHouse/pull/63898) ([FFish](https://github.com/wxybear)).
* 以前のバージョンでは、データ型名の末尾に `WithDictionary` を付けることで、`LowCardinality` data types に対する別構文を使用できました。これは初期段階の実装であり、文書化されたことも一般公開されたこともありませんでした。現在は非推奨です。この構文を使用していた場合は、テーブルに対して ALTER を実行し、データ型名を `LowCardinality` にリネームする必要があります。[#66842](https://github.com/ClickHouse/ClickHouse/pull/66842) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 分散 destination table と組み合わせて使用されるストレージ `Buffer` の論理エラーを修正しました。これは後方互換性を持たない変更です。クエリ内に同じテーブルが複数回現れる場合 (たとえば self-join) 、分散 destination table とともに `Buffer` を使用するクエリは動作しなくなる可能性があります。[#67015](https://github.com/ClickHouse/ClickHouse/pull/67015) ([vdimir](https://github.com/vdimir)).
* 以前のバージョンでは、gamma function に基づくランダム分布の関数 (Chi-Squared、Student、Fisher など) を、ゼロに近い負の argument で呼び出すと、計算に長時間かかったり無限ループになったりすることがありました。新しいバージョンでは、これらの関数をゼロまたは負の argument で呼び出すと exception が発生します。これにより [#67297](https://github.com/ClickHouse/ClickHouse/issues/67297) はクローズされます。[#67326](https://github.com/ClickHouse/ClickHouse/pull/67326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* system table `text_log` はデフォルトで enabled になりました。これは以前のバージョンと完全に互換性がありますが、ローカルディスクの Disk usage がわずかに増加したことに気付くかもしれません (この system table が使用するディスク容量はごくわずかです) 。[#67428](https://github.com/ClickHouse/ClickHouse/pull/67428) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 以前のバージョンでは、`arrayWithConstant` は非常に大きな Array の生成を求められると低速になることがありました。新しいバージョンでは、1 つの Array あたり 1 GB に制限されます。これにより [#32754](https://github.com/ClickHouse/ClickHouse/issues/32754) はクローズされます。[#67741](https://github.com/ClickHouse/ClickHouse/pull/67741) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* REPLACE modifier のフォーマットを修正しました (括弧の省略を禁止) 。[#67774](https://github.com/ClickHouse/ClickHouse/pull/67774) ([Azat Khuzhin](https://github.com/azat)).
* [#68349](https://github.com/ClickHouse/ClickHouse/issues/68349) でバックポート: Dynamic type を再実装しました。これにより、動的 data types の上限に達した場合でも、新しい types は String にキャストされず、バイナリ形式でバイナリエンコードされた data type を持つ特別な data structure に格納されます。これで、Dynamic カラム にこれまでに一度でも挿入された任意の type を subcolumn として読み取れるようになりました。[#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="new-feature">
  #### 新機能
</div>

* Kafka へのコミットに依存せず、Keeper に offsets を保存するための新しい experimental Kafka storage engine を追加しました。 [#57625](https://github.com/ClickHouse/ClickHouse/pull/57625) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 新しい TimeSeries table engine を追加しました。- デフォルト: `CREATE TABLE tbl ENGINE=TimeSeries` - または、内部テーブルのエンジンを指定して使用できます。 [#64183](https://github.com/ClickHouse/ClickHouse/pull/64183) ([Vitaly Baranov](https://github.com/vitlibar)).
* 左テーブルと右テーブルの両方のカラムを含む不等条件に対して、より多くの join strictness (`LEFT/RIGHT SEMI/ANTI/ANY JOIN`) をサポートしました。たとえば、t1.y &lt; t2.y のような条件です (設定 `allow_experimental_join_condition` を参照) 。 [#64281](https://github.com/ClickHouse/ClickHouse/pull/64281) ([lgbo](https://github.com/lgbo-ustc)).
* S3 table engine 向けに `_etag` 仮想カラムを追加しました。[#65312](https://github.com/ClickHouse/ClickHouse/issues/65312) を修正。 [#65386](https://github.com/ClickHouse/ClickHouse/pull/65386) ([skyoct](https://github.com/skyoct)).
* このプルリクエストでは、さまざまなエンジン (`File`, `URL`, `S3`, `AzureBlobStorage`, `HDFS`) 向けに Hive-style partitioning を導入しています。Hive-style partitioning では、データをパーティション化されたサブディレクトリに整理することで、大規模な datasets のクエリと管理を効率化できます。現時点では、適切な名前とデータを持つ仮想カラムを作成するのみです。後続の PR で、適切なデータフィルタリング (性能向上) が導入される予定です。 [#65997](https://github.com/ClickHouse/ClickHouse/pull/65997) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Spark との互換性のために関数 printf を追加しました。 [#66257](https://github.com/ClickHouse/ClickHouse/pull/66257) ([李扬](https://github.com/taiyang-li)).
* [#68450](https://github.com/ClickHouse/ClickHouse/issues/68450) でバックポート: 新しい JSON data type を実装しました。 [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Kruglov Pavel](https://github.com/Avogar)).
* 新しい server setting `disable_insertion_and_mutation` を追加しました。これを true に設定すると、このノードはすべての insertions と mutations (ALTER TABLE の delete/update/drop partition) を拒否します。非同期 INSERT も含まれます。 [#66519](https://github.com/ClickHouse/ClickHouse/pull/66519) ([Xu Jia](https://github.com/XuJia0210)).
* テストに役立つよう、external engines と table functions を Null engine に置き換えるオプション `restore_replace_external_engines_to_null` および `restore_replace_external_table_functions_to_null` を追加しました。これは RESTORE と明示的なテーブル作成で動作するはずです。 [#66536](https://github.com/ClickHouse/ClickHouse/pull/66536) ([Ilya Yatsishin](https://github.com/qoega)).
* 関数 readWKTLineString を使用して、WKT 形式の MULTILINESTRING geometry を読み取るサポートを追加しました。 [#67647](https://github.com/ClickHouse/ClickHouse/pull/67647) ([Jacob Reckhard](https://github.com/jacobrec)).
* 新しい table function `fuzzQuery` を追加しました。この関数を使用すると、指定した query string にランダムな変化を加えられます。Example: `SELECT query FROM fuzzQuery('SELECT 1') LIMIT 5;`. [#67655](https://github.com/ClickHouse/ClickHouse/pull/67655) ([pufit](https://github.com/pufit)).
* すべての detached partitions を削除するクエリ `DROP DETACHED PARTITION ALL` をサポートしました。 [#67885](https://github.com/ClickHouse/ClickHouse/pull/67885) ([Duc Canh Le](https://github.com/canhld94)).
* query cache に対する tagging (ネームスペース) メカニズムを追加しました。タグが異なる同じクエリは、query cache では別のものとして扱われます。Example: `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'abc'` と `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'def'` は、異なる query cache entries を作成するようになりました。 [#68235](https://github.com/ClickHouse/ClickHouse/pull/68235) ([sakulali](https://github.com/sakulali)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* 並列レプリカ向けに、適応的な read task size の計算方法 (ここで adaptive とは、読み取るカラムのサイズに応じて決まることを意味します) を使用します。 [#60377](https://github.com/ClickHouse/ClickHouse/pull/60377) ([Nikita Taranov](https://github.com/nickitat)).
* `plain_rewritable` ディスクのディレクトリメタデータを、オブジェクトストレージ内の MergeTree データとは分離して `__meta` レイアウトに保存します。`plain_rewritable` ディスクをフラットなディレクトリ構造に移行します。 [#65751](https://github.com/ClickHouse/ClickHouse/pull/65751) ([Julia Kartseva](https://github.com/jkartseva)).
* `compile_expressions` (通常の式の断片向け JIT コンパイラ) をデフォルトで有効にします。これにより [#51264](https://github.com/ClickHouse/ClickHouse/issues/51264) と [#56386](https://github.com/ClickHouse/ClickHouse/issues/56386) が解決されます。 [#66486](https://github.com/ClickHouse/ClickHouse/pull/66486) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* すべてのサブカラムに必要なメモリを事前に確保することで、String/Array/Map/Variant/Dynamic 型のカラムをまとめる処理を改善しました。 [#67043](https://github.com/ClickHouse/ClickHouse/pull/67043) ([Kruglov Pavel](https://github.com/Avogar)).
* system flush logs を高速化し、シャットダウン時にログをフラッシュするようにしました。 [#67472](https://github.com/ClickHouse/ClickHouse/pull/67472) ([Sema Checherinda](https://github.com/CheSema)).
* [#68496](https://github.com/ClickHouse/ClickHouse/issues/68496) でバックポート: マージの各スケジューリングステップのオーバーヘッドを削減することで、マージ全体のパフォーマンスを改善しました。 [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* `optimize_functions_to_subcolumns` 設定はデフォルトで有効です。 [#68053](https://github.com/ClickHouse/ClickHouse/pull/68053) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### 改善
</div>

* ClickHouse server で新しい設定 `max_keep_alive_requests` がサポートされました。server への keep-alive HTTP connection では、これは `keep_alive_timeout` と組み合わせて動作します。つまり、アイドルタイムアウトがまだ切れていなくても、特定の connection ですでに `max_keep_alive_requests` 回を超えるリクエストが処理されている場合、その connection は server によって閉じられます。[#61793](https://github.com/ClickHouse/ClickHouse/pull/61793) ([Nikita Taranov](https://github.com/nickitat)).
* 新しいバージョンでは、SOURCES は Table Engine のロジックに基づいてチェックされます。table engine の grant はデフォルトで無効ですが、source に権限が付与されていない場合、代わりに table engine のプロンプトが表示されてしまい、誤解を招いていました。[#65419](https://github.com/ClickHouse/ClickHouse/pull/65419) ([jsc0218](https://github.com/jsc0218)).
* 統計タイプ `count_min` (count-min sketches) が追加され、`col = 'val'` のような等価 predicates の selectivity 推定を提供します。サポートされているデータ型は string、date、datatime、および numeric types です。[#65521](https://github.com/ClickHouse/ClickHouse/pull/65521) ([JackyWoo](https://github.com/JackyWoo)).
* 上書きできるようにするため、image 内では keeper 用のログを明示的に渡さないようにしました。[#65564](https://github.com/ClickHouse/ClickHouse/pull/65564) ([Azat Khuzhin](https://github.com/azat)).
* `clickhouse-local` ではデフォルトで `Atomic` database を使用するようになりました。[#50647](https://github.com/ClickHouse/ClickHouse/issues/50647) の項目 1 と 5 に対応しています。[#44817](https://github.com/ClickHouse/ClickHouse/issues/44817) をクローズします。[#65860](https://github.com/ClickHouse/ClickHouse/pull/65860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `rows_before_aggregation` が有効な場合に、クエリの response に統計 `rows_before_aggregation_at_least` を追加しました。この統計は、aggregation 前に読み取られた行数を表します。distributed query の文脈では、`limit` を使わずに `group by` または `max` aggregation function を使用した場合、`rows_before_aggregation_at_least` はクエリがヒットした行数を反映することがあります。[#66084](https://github.com/ClickHouse/ClickHouse/pull/66084) ([morning-color](https://github.com/morning-color)).
* `BACKUP` および `RESTORE` クエリ向けに `use_same_password_for_base_backup` settings が導入され、password で保護されたアーカイブへの/からの incremental backups の作成と restore が可能になりました。[#66214](https://github.com/ClickHouse/ClickHouse/pull/66214) ([Samuele](https://github.com/sguerrini97)).
* ATTACH クエリでは async&#95;load&#95;databases を無視するようにしました (以前は、table が attached される前に ATTACH が返る可能性がありました) 。[#66240](https://github.com/ClickHouse/ClickHouse/pull/66240) ([Azat Khuzhin](https://github.com/azat)).
* [Replicated]MergeTreeSink は `onCancel()` method で delayed&#95;chunk を正しくキャンセルする必要があります。[#66279](https://github.com/ClickHouse/ClickHouse/pull/66279) ([Sema Checherinda](https://github.com/CheSema)).
* 拒否された接続 (リソース不足時) のログとメトリクスが追加されました。[#66410](https://github.com/ClickHouse/ClickHouse/pull/66410) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 設定 `allow_experimental_analyzer` は `enable_analyzer` に名前変更されました。古い名前はエイリアスとして維持されます。[#66438](https://github.com/ClickHouse/ClickHouse/pull/66438) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* MongoDB engine でネイティブの UUID type をサポートしました。[#66671](https://github.com/ClickHouse/ClickHouse/pull/66671) ([Azat Khuzhin](https://github.com/azat)).
* マージ時 (特定のエンジン向け) および `OPTIMIZE DEDUPLICATE` クエリで projections を制御するための新しい `MergeTree` 設定 `deduplicate_merge_projection_mode` を追加しました。サポートされるオプションは次のとおりです: `throw` (projection が *MergeTree engine で完全にサポートされていない場合に例外をスローする) 、`drop` (projection 自体を一貫性を保ってマージできない場合、マージ中に projection を削除する) 、`rebuild` (projection を最初から再構築する。高コストな操作です) 。 [#66672](https://github.com/ClickHouse/ClickHouse/pull/66672) ([jsc0218](https://github.com/jsc0218)).
* レプリケーションラグおよび復旧時間のメトリクスを追加しました。 [#66703](https://github.com/ClickHouse/ClickHouse/pull/66703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* S3DiskNoKeyErrors メトリクスを追加しました。 [#66704](https://github.com/ClickHouse/ClickHouse/pull/66704) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* COMMENT clause がすべての table engines で動作するようにしました。 [#66832](https://github.com/ClickHouse/ClickHouse/pull/66832) ([Joe Lynch](https://github.com/joelynch)).
* `BAD_ARGUMENTS` および `ILLEGAL_TYPE_OF_ARGUMENT` について、適切な場合はより正確な error codes を使うようにしました。 [#66851](https://github.com/ClickHouse/ClickHouse/pull/66851) ([Yohann Jardin](https://github.com/yohannj)).
* 関数 `mapFromArrays` が第 1 argument として `Map(K, V)` を受け取れるようになりました。たとえば、`SELECT mapFromArrays(map('a', 4, 'b', 4), ['aa', 'bb'])` が動作し、`{('a',4):'aa',('b',4):'bb'}` を返します。また、第 1 argument が Array の場合、実際の配列の値が `NULL` でない限り、`Array(Nullable(T))` または `Array(LowCardinality(Nullable(T)))` 型も使えるようになりました。 [#67103](https://github.com/ClickHouse/ClickHouse/pull/67103) ([李扬](https://github.com/taiyang-li)).
* clickhouse-local が ~/.clickhouse-local から configuration を読み取るようになりました。 [#67135](https://github.com/ClickHouse/ClickHouse/pull/67135) ([Azat Khuzhin](https://github.com/azat)).
* 設定 `input_format_orc_read_use_writer_time_zone` の名前を `input_format_orc_reader_timezone` に変更し、ユーザーが reader timezone を設定できるようにしました。 [#67175](https://github.com/ClickHouse/ClickHouse/pull/67175) ([kevinyhzou](https://github.com/KevinyhZou)).
* 接続直後に peer によって HTTP connection がリセットされた場合の &#39;Socket is not connected&#39; error のレベルを下げました。これにより [#34218](https://github.com/ClickHouse/ClickHouse/issues/34218) をクローズします。 [#67177](https://github.com/ClickHouse/ClickHouse/pull/67177) ([vdimir](https://github.com/vdimir)).
* `DROP DATABASE` クエリでの tables の削除を高速化し、`database_catalog_drop_table_concurrency` のデフォルト値を 16 に引き上げました。 [#67228](https://github.com/ClickHouse/ClickHouse/pull/67228) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* config から system.dashboards 用の dashboards を読み込めるようにしました (設定すると、デフォルトの dashboards プリセットを上書きします) 。 [#67232](https://github.com/ClickHouse/ClickHouse/pull/67232) ([Azat Khuzhin](https://github.com/azat)).
* SQL の window functions は従来 snake case です。ClickHouse は camelCase を使っているため、新しい別名 `denseRank()` と `percentRank()` を追加しました。これらの新しい関数は、元の `dense_rank()` および `percent_rank()` 関数とまったく同じように呼び出せます。snake case と camelCase の両方の syntax は引き続き使用できます。さらに、各関数に対する新しいテストも追加しました。これにより [#67042](https://github.com/ClickHouse/ClickHouse/issues/67042) をクローズします。 [#67334](https://github.com/ClickHouse/ClickHouse/pull/67334) ([Peter Nguyen](https://github.com/petern48)).
* `.xml`、`.yml`、`.yaml` 以外の設定ファイルでは、フォーマットを自動検出するようにしました。ファイルが `&lt;` で始まる場合は XML、それ以外は YAML の可能性があります。`PIPE: /dev/fd/X` のような通常のファイルではないものは、XML として解析します。 [#67391](https://github.com/ClickHouse/ClickHouse/pull/67391) ([sakulali](https://github.com/sakulali)).
* 関数 `formatDateTime` と `formatDateTimeInJodaSyntax` で、フォーマットパラメータがオプションとして扱われるようになりました。指定されていない場合は、フォーマット文字列 `%Y-%m-%d %H:%i:%s` と `yyyy-MM-dd HH:mm:ss` が使用されます。例: `SELECT parseDateTime('2021-01-04 23:12:34')` は DateTime 値 `2021-01-04 23:12:34` を返すようになりました (以前は例外が発生していました) 。 [#67399](https://github.com/ClickHouse/ClickHouse/pull/67399) ([Robert Schulze](https://github.com/rschu1ze)).
* タイムアウトまたは接続切断が原因で発生した場合、KeeperMap 内の Keeper リクエストを自動的に再試行するようにしました。 [#67448](https://github.com/ClickHouse/ClickHouse/pull/67448) ([Antonio Andelic](https://github.com/antonio2368)).
* カスタムテーブルのディスク使用方法を見直しました。 [#67684](https://github.com/ClickHouse/ClickHouse/pull/67684) ([Sema Checherinda](https://github.com/CheSema)).
* 高度なダッシュボードにさまざまな改善を加えました。これにより [#67697](https://github.com/ClickHouse/ClickHouse/issues/67697) をクローズします。これにより [#63407](https://github.com/ClickHouse/ClickHouse/issues/63407) をクローズします。これにより [#51129](https://github.com/ClickHouse/ClickHouse/issues/51129) をクローズします。これにより [#61204](https://github.com/ClickHouse/ClickHouse/issues/61204) をクローズします。 [#67701](https://github.com/ClickHouse/ClickHouse/pull/67701) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Join tables のメモリ使用量を削減するため、Join table engine で OPTIMIZE クエリをサポートしました。 [#67883](https://github.com/ClickHouse/ClickHouse/pull/67883) ([Duc Canh Le](https://github.com/canhld94)).
* レプリケーションラグと復旧時間のメトリクスを追加しました。 [#67913](https://github.com/ClickHouse/ClickHouse/pull/67913) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* ClickHouse の再起動後に stacktraces の適切な introspection とシンボル化を可能にするため、aarch64 Linux ビルドに `'-no-pie'` を追加しました。 [#67916](https://github.com/ClickHouse/ClickHouse/pull/67916) ([filimonov](https://github.com/filimonov)).
