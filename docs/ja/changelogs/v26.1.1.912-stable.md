<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* フォーマッタにおける alias の誤った置換によって生じる不整合なフォーマットを修正しました。[#82833](https://github.com/ClickHouse/ClickHouse/issues/82833)、[#82832](https://github.com/ClickHouse/ClickHouse/issues/82832)、[#68296](https://github.com/ClickHouse/ClickHouse/issues/68296) をクローズします。この変更は後方互換性を持たない可能性があります。アナライザが無効の場合、alias を参照する IN を含む特定の CREATE VIEW クエリを処理できません。非互換性を回避するには、アナライザを有効にしてください (24.3 以降はデフォルトで有効です) 。[#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* コーデック `DEFLATE_QPL` および `ZSTD_QAT` が削除されました。アップグレード前に、`DEFLATE_QPL` または `ZSTD_QAT` で圧縮された既存データを別のコーデックに変換することを推奨します。なお、これらのコーデックを使用するには、設定 `enable_deflate_qpl_codec` および `enable_zstd_qat_codec` を有効にする必要がありました。[#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze))。
* `system.query_log.exception` での stderr キャプチャを有効にすることで UDF のデバッグを修正しました。以前は UDF の stderr はファイルにのみ記録され、クエリログには出力されなかったため、デバッグが不可能でした。現在は stderr がデフォルトで例外をトリガーし、スローする前に完全に蓄積 (最大 1MB) されるため、Python のトレースバックやエラーメッセージが `system.query_log.exception` に表示され、効果的なトラブルシューティングが可能になります。[#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210))。
* `JOIN USING ()` 句における空のカラムリストが構文エラーとして扱われるようになりました。以前はクエリ実行時に `INVALID_JOIN_ON_EXPRESSION` となるはずでしたが、`Join` ストレージとの結合など一部のケースでは `LOGICAL_ERROR` が発生していました。[#82502](https://github.com/ClickHouse/ClickHouse/issues/82502) をクローズします。[#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir))。
* JSON の advanced shared data をデフォルトで有効にしました。この変更により、バージョン 25.8 未満へのダウングレードはできなくなります。これらのバージョンは JSON カラムを含む新しいデータパーツを読み取れないためです。安全にアップグレードするには、`compatibility` 設定を以前のバージョンに設定するか、MergeTree の設定 `dynamic_serialization_version='v2', object_serialization_version='v2'` を指定することを推奨します。[#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar))。
* JSON 型の SKIP REGEXP でデフォルトで部分一致を使用するようにしました。[#79250](https://github.com/ClickHouse/ClickHouse/issues/79250) をクローズします。[#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar))。
* 「単純な ALIAS カラムへの INSERT を許可する」を差し戻しました (ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154) を差し戻し) 。カスタムフォーマットで動作せず、設定によるガードもありません。[#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat))。
* データレイクカタログがオブジェクトストレージにアクセスできない場合にエラーをスローする設定を追加しました。[#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12))。
* `Lazy` データベースエンジンが削除され、使用できなくなりました。[#91231](https://github.com/ClickHouse/ClickHouse/issues/91231) をクローズします。[#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* `metric_log` の `transposed_with_wide_view` モードを削除しました。バグにより使用不可能なためです。このモードで `system.metric_log` を定義することはできなくなりました。これは [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412) を部分的に差し戻すものです。[#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* ワークロードの CPU スケジューリングがデフォルトでプリエンプティブになりました。`cpu_slot_preemption` サーバー設定を参照してください。[#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa))。
* 破損したパーツを防ぐために索引ファイル名をエスケープするようにしました。この変更により、ClickHouse は以前のバージョンで作成された非 ASCII 文字を含む名前の索引を読み込めなくなります。対処するには、MergeTree の設定 `escape_index_filenames` を使用してください。[#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano))。
* フォーマット設定 `exact_rows_before_limit`、`rows_before_aggregation`、`cross_to_inner_join_rewrite`、`regexp_dict_allow_hyperscan`、`regexp_dict_flag_case_insensitive`、`regexp_dict_flag_dotall`、`dictionary_use_async_executor` が通常の (非フォーマット) 設定に変更されました。これは純粋に内部的な変更であり、ユーザーに見える副作用はありません。ただし、Iceberg、DeltaLake、Kafka、S3、S3Queue、Azure、Hive、RabbitMQ、Set、FileLog、NATS のテーブルエンジン定義でこれらの設定を指定していた場合 (可能性は低いですが) は例外です。以前はこれらの設定が無視されていましたが、現在はそのような定義でエラーがスローされます。[#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze))。
* `joinGet/joinGetOrNull` 関数が、基となる Join テーブルに対して `SELECT` 権限を強制するようになりました。この変更以降、`joinGet('db.table', 'column', key)` を実行するには、Join テーブルで定義されたキーカラムと取得する属性カラムの両方に対して `SELECT` 権限が必要です。これらの権限がないクエリは `ACCESS_DENIED` で失敗します。移行するには、テーブル全体へのアクセスには `GRANT SELECT ON db.join_table TO user`、カラムレベルのアクセスには `GRANT SELECT(key_col, attr_col) ON db.join_table TO user` を使用して必要な権限を付与してください。この変更は、明示的な `SELECT` 権限が以前に設定されていなかった `joinGet`/`joinGetOrNull` に依存するすべてのユーザーおよびアプリケーションに影響します。[#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir))。
* `CREATE TABLE ... AS ...` クエリに対して `SHOW COLUMNS` を確認するようにしました。以前は `SHOW TABLES` を確認していましたが、この種の権限チェックには不適切な権限でした。[#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit))。





<div id="new-feature">
  #### 新機能
</div>

* CH Keeper 向けの HTTP API と埋め込み Web UI。[#78181](https://github.com/ClickHouse/ClickHouse/pull/78181) ([pufit](https://github.com/pufit)).
* 複数のレプリカにまたがる分散索引解析。共有ストレージやクラスター内の大量データで効果があります。[#86786](https://github.com/ClickHouse/ClickHouse/pull/86786) ([Azat Khuzhin](https://github.com/azat)).
* `<interactive_history_legacy_keymap>true</interactive_history_legacy_keymap>` を有効にすると、CLI クライアントは従来どおり通常検索で Ctrl R にフォールバックでき、Ctrl T ではあいまい検索を行います。[#87785](https://github.com/ClickHouse/ClickHouse/pull/87785) ([Larry Snizek](https://github.com/larry-cdn77)).
* 非同期 INSERT の重複排除が、依存する materialized view でも動作するようになりました。block&#95;id の衝突が発生した場合、元の block は block&#95;id に関連する行が除外されるようにフィルタリングされ、残りの行は関連するすべての materialized view の select クエリで変換されます。これにより、競合する行を含まない元の block が再構築されます。[#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* `clickhouse client` がサーバー接続時に TLS SNI を上書きできるようになりました。[#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).
* Array カラムのテキスト索引をサポートしました。[#89895](https://github.com/ClickHouse/ClickHouse/pull/89895) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* 新しい system table `zookeeper&#95;info`。 [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014) を修正しました。[#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* functions で Variant 型をサポートするため、FunctionVariantAdaptor を実装しました。[#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* Prometheus の `/metrics` エンドポイントに `ClickHouse_Info` メトリクスを追加しました。主にバージョン情報を含み、詳細なバージョン情報の推移を追跡するチャートを作成できます。[#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* keeper 向けに、クラスター構成を変更できる新しい 4 文字コマンド `rcfg` を導入しました。このコマンドは、標準の `reconfigure` リクエストよりも幅広い構成変更を行えます。コマンドは引数として `json` 文字列を受け取ります。TCP インターフェイスに送信するバイト列全体は次のようになります: `rcfg{json_string_length_big_endian}{json_string}`。コマンド例: `{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`。[#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* 指定した区切り文字で分割された文字列内の部分文字列の順序を逆にする関数 `reverseBySeparator` を追加しました。[#91463](https://github.com/ClickHouse/ClickHouse/issues/91463) をクローズ。[#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* projection index 機能を簡素化・拡張するための新しい構文とフレームワークを導入しました。これは https://github.com/ClickHouse/ClickHouse/pull/81021 の後続です。[#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* paimon REST カタログをサポートしました。https://github.com/ClickHouse/ClickHouse/pull/84423 の継続です。[#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* 挿入される blocks の形成をより細かく制御する新しい設定 `max_insert_block_size_bytes` を追加しました。[#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* `ignore_on_cluster_for_replicated_database` 設定が有効な場合、Replicated database に対して `ON CLUSTER` clause を使用した DDL queries を実行できるようになりました。この場合、クラスター名は無視されます。[#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* `mergeTreeAnalyzeIndex()` function を実装しました。[#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* 新しい設定 `use_primary_key` を追加しました。これを `false` に設定すると、主キーに基づく Granule pruning を無効にできます。[#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `icebergLocalCluster` table function。[#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Parquet リーダー v3 における datalakes prewhere および multistage prewhere により、[#89101](https://github.com/ClickHouse/ClickHouse/issues/89101) を解決しました。[#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 2 つの Point 間の [cosine distance](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance) を近似する `cosineDistanceTransposed` function を追加しました。[#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* cache をクリアする従来のステートメント `SYSTEM DROP [...] CACHE` は、cache を無効化するステートメントであるかのような誤解を招いていました。ClickHouse は、より明確なステートメント `SYSTEM CLEAR [...] CACHE` をサポートするようになりました。古い構文も引き続き利用できます。[#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* 各 data part 内のファイル数を示す files カラムを system.parts table に追加しました。[#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* Concurrency 制御のための max-min fair scheduler を追加しました。多数の queries が限られた CPU slots を奪い合う高オーバーサブスクリプション環境で、より高い公平性を実現します。短時間で終了する queries は、時間の経過とともにより多くの slots を蓄積した長時間実行 queries によって不利になりません。`concurrent_threads_scheduler` server setting の `max_min_fair` 値で有効になります。[#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* JOIN へのフィルターのプッシュダウンをさらに拡充しました。[#85556](https://github.com/ClickHouse/ClickHouse/pull/85556) ([Nikita Taranov](https://github.com/nickitat)).
* `partition by` が sorting key と一致するか、そのプレフィックスである場合の window functions 向けソート順最適化を無効化し、並列実行のパフォーマンスを向上させました。[#87299](https://github.com/ClickHouse/ClickHouse/pull/87299) ([Nikita Taranov](https://github.com/nickitat)).
* 外側のフィルターがビューにプッシュダウンされるようになり、ローカルノードとリモートノードの両方で PREWHERE を適用できるようになりました。[#88189](https://github.com/ClickHouse/ClickHouse/issues/88189) を解決しました。[#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).
* より多くの関数で JIT コンパイルを実装しました。[#73509](https://github.com/ClickHouse/ClickHouse/issues/73509) をクローズしました。[#88770](https://github.com/ClickHouse/ClickHouse/pull/88770) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 小数の `LIMIT` および `OFFSET` に対するパフォーマンスとメモリ使用量を最適化しました。[#91167](https://github.com/ClickHouse/ClickHouse/pull/91167) ([Ahmed Gouda](https://github.com/0xgouda)).
* Parquet Reader V3 Prefetcher で、より高速なランダム読み取りロジックが使われない問題を修正しました。[#90890](https://github.com/ClickHouse/ClickHouse/issues/90890) をクローズしました。[#91435](https://github.com/ClickHouse/ClickHouse/pull/91435) ([Arsen Muk](https://github.com/arsenmuk)).
* `icebergCluster` のパフォーマンスを向上させました。[#91462](https://github.com/ClickHouse/ClickHouse/issues/91462) をクローズしました。[#91537](https://github.com/ClickHouse/ClickHouse/pull/91537) ([Yang Jiang](https://github.com/Ted-Jiang)).
* 定数フィルターでは仮想カラムによるフィルタリングを行わないようにしました。[#91588](https://github.com/ClickHouse/ClickHouse/pull/91588) ([c-end](https://github.com/c-end)).
* `LowCardinality` カラムに対する `DISTINCT` のパフォーマンスを向上させました。[#5917](https://github.com/ClickHouse/ClickHouse/issues/5917) をクローズしました。[#91639](https://github.com/ClickHouse/ClickHouse/pull/91639) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* distinctJSONPaths aggregate function を最適化し、JSON カラム全体ではなくデータパーツから JSON path のみを読み取るようにしました。[#92196](https://github.com/ClickHouse/ClickHouse/pull/92196) ([Pavel Kruglov](https://github.com/Avogar)).
* 適応型書き込みバッファを有効にすることで、非常に列数の多いテーブルの wide パーツにおける INSERT/merges のメモリ使用量を削減しました。また、暗号化ディスクに対する適応型書き込みバッファのサポートも追加しました。[#92250](https://github.com/ClickHouse/ClickHouse/pull/92250) ([Azat Khuzhin](https://github.com/azat)).
* フィルターが片側の入力だけを使用する場合について、join の ON 条件からのプッシュダウンに対応するケースを増やしました。`ANY`、`SEMI`、`ANTI` joins をサポートしました。[#92584](https://github.com/ClickHouse/ClickHouse/pull/92584) ([Dmitry Novik](https://github.com/novikd)).
* `SEMI JOIN` でフィルターをプッシュダウンするために、等価な sets を使用できるようにしました。[#85239](https://github.com/ClickHouse/ClickHouse/issues/85239) をクローズしました。[#92837](https://github.com/ClickHouse/ClickHouse/pull/92837) ([Dmitry Novik](https://github.com/novikd)).
* テキスト索引と `sparseGrams` トークナイザーを使用した全文検索のパフォーマンスを向上させ、索引内で検索するトークン数を削減しました。[#93078](https://github.com/ClickHouse/ClickHouse/pull/93078) ([Anton Popov](https://github.com/CurtizJ)).
* クエリパイプライン内でデータをパーティション化するために &quot;fastrange&quot; (Daniel Lemire) 方式を使用するようにしました。これにより、並列ソートや JOIN のパフォーマンス向上が期待できます。[#93080](https://github.com/ClickHouse/ClickHouse/pull/93080) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 同一の要素が連続して現れることが多いケースで、`uniqExact` を最適化しました。[#93268](https://github.com/ClickHouse/ClickHouse/pull/93268) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 関数 `isValidASCII` は、すべて ASCII の入力値に対して true になるケース向けに最適化されました。[#93347](https://github.com/ClickHouse/ClickHouse/pull/93347) ([Robert Schulze](https://github.com/rschu1ze)).
* 関数 `isValidASCII` は、すべて ASCII の入力値に対して true になるケース向けに最適化されました。[#93611](https://github.com/ClickHouse/ClickHouse/pull/93611) ([Robert Schulze](https://github.com/rschu1ze)).
* 右側が空の場合、ハッシュ結合の左側の読み取りをスキップするようにしました。以前は最初の空でないブロックが見つかるまで左側を読み取っていましたが、フィルタリングや集約の負荷が高い場合には多くの処理が発生する可能性がありました。[#94062](https://github.com/ClickHouse/ClickHouse/pull/94062) ([Alexander Gololobov](https://github.com/davenger)).
* read-in-order 最適化で、WHERE 条件によって ORDER BY カラムが定数になる場合を認識し、効率的な逆順読み取りが可能になりました。これにより、&#96;WHERE tenant=&#39;42&#39; ORDER BY tenant, event&#95;time DESC&#96; のようなマルチテナントクエリでは、完全なソートを行わずに InReverseOrder を使用できるようになります。&quot;。[#94103](https://github.com/ClickHouse/ClickHouse/pull/94103) ([matanper](https://github.com/matanper)).
* メモリ消費を最適化するため、値パラメータを ASTLiteral の children ではなく文字列と整数のペアで保持する、Enum AST 専用の class を導入しました。[#94178](https://github.com/ClickHouse/ClickHouse/pull/94178) ([Ilya Yatsishin](https://github.com/qoega)).
