<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* この PR における変更点: 1. 新しい argument `unexpected_quoting_character_strategy` を関数に導入し、引用符で囲まれていないキーまたは値の読み取り時に `quoting_character` が予期せず見つかった場合の動作を制御できるようにしました。値には `invalid`、`accept`、`promote` のいずれかを指定できます。Invalid はキーを破棄してキー待機状態に戻ります。Accept はそれをキーの一部として扱います。Promote は直前の文字を破棄し、引用符付きキーとしてパースを開始します。デフォルトの動作 (おそらく唯一の動作でもあるはず) は `INVALID` であるべきだと考えていますが、2023 年に https://github.com/ClickHouse/ClickHouse/pull/56423 で `PROMOTE` ロジックが実装されました。そのため、ある程度の後方互換性を確保するために、この設定を追加しました。2. 引用符付きの値をパースした後は、ペアの区切り文字が見つかった場合にのみ次のキーをパースします。 [#80657](https://github.com/ClickHouse/ClickHouse/pull/80657) ([Arthur Passos](https://github.com/arthurpassos)).
* これまで、関数 `countMatches` は、pattern が空一致を許容していても、最初の空一致でカウントを停止していました。この問題に対処するため、`countMatches` は空一致が発生した場合、1 文字分進めて実行を継続するようになりました。従来の動作を維持したい場合は、設定 `count_matches_stop_at_empty_match` を有効にできます。 [#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov)).
* これまで、BACKUP クエリ、merges、mutations は、ローカル (`max_local_read_bandwidth_for_server` と `max_local_write_bandwidth_for_server`) およびリモート (`max_remote_read_network_bandwidth_for_server` と `max_remote_write_network_bandwidth_for_server`) のトラフィックに対してサーバー全体のスロットラーを使用しておらず、専用の server settings (`max_backup_bandwidth_for_server`、`max_mutations_bandwidth_for_server`、`max_merges_bandwidth_for_server`) によってのみスロットリングされていました。現在は、両方の種類のスロットラーを同時に使用します。 [#81753](https://github.com/ClickHouse/ClickHouse/pull/81753) ([Sergei Trifonov](https://github.com/serxa)).
* insert 可能なカラムを持たない table は作成できなくなりました。 [#81835](https://github.com/ClickHouse/ClickHouse/pull/81835) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* これまで、アーカイブを使用する cluster functions はアーカイブ全体をレプリカに送信していたため、アーカイブ内の読み取りをクラスターで並列化できませんでした (たとえば単一のアーカイブでは、それを丸ごと 1 つのレプリカに送って処理させるだけになり、他のすべてのレプリカは idle のままとなって非効率でした) 。新しい設定 `cluster_function_process_archive_on_multiple_nodes` を追加しました。デフォルト値は `true` です。`true` に設定すると、cluster functions でのアーカイブ処理の性能が向上します。互換性のため、また以前のバージョンでアーカイブ付きの cluster functions を使用していて 25.7+ にアップグレードする際のエラーを避けるためには、`false` に設定する必要があります。 [#82355](https://github.com/ClickHouse/ClickHouse/pull/82355) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `SYSTEM RESTART REPLICAS` クエリにより、その database へのアクセス権がない場合でも Lazy database 内の tables が起動され、しかもそれらの tables が concurrently に drop されている最中に発生していました。Note: 現在、`SYSTEM RESTART REPLICAS` は `SHOW TABLES` の permission を持つ databases 内の replicas のみを再起動するようになっており、これは自然な動作です。 [#83321](https://github.com/ClickHouse/ClickHouse/pull/83321) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### 新機能
</div>

* 型 `Float32` および `Float64` のカラム向けに、非可逆ながら誤差境界付きの圧縮コーデックである SZ3 を追加しました。[#67161](https://github.com/ClickHouse/ClickHouse/pull/67161) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Iceberg のスキーマ進化で複合型をサポートしました。[#73714](https://github.com/ClickHouse/ClickHouse/pull/73714) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* **NumericIndexedVector**: ビットスライス化された Roaring-bitmap 圧縮を基盤とする新しいベクターデータ構造で、構築、解析、要素ごとの算術演算のための 20 を超える関数を備えています。ストレージを削減し、スパースデータに対する JOIN、フィルタ、集計を高速化できます。[#70582](https://github.com/ClickHouse/ClickHouse/issues/70582) および、VLDB 2024 の T. Xiong と Y. Wang による [“Large-Scale Metric Computation in Online Controlled Experiment Platform” paper](https://arxiv.org/abs/2405.08411) を実装しています。[#74193](https://github.com/ClickHouse/ClickHouse/pull/74193) ([FriendLey](https://github.com/FriendLey)).
* &#39;format&#95;schema&#95;source&#39; 設定を追加しました。これは &#39;format&#95;schema&#39; のソースを定義します。[#80874](https://github.com/ClickHouse/ClickHouse/pull/80874) ([Tuan Pham Anh](https://github.com/tuanpach)).
* 新しいデータ型 Time ([H]HH:MM:SS) および Time64 ([H]HH:MM:SS[.fractional]) と、基本的な CAST 関数、および他のデータ型とやり取りするための関数を追加しました。レガシー関数 `ToTime` との互換性のための設定も追加しました。[#81217](https://github.com/ClickHouse/ClickHouse/pull/81217) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* ワークロード設定 `max_waiting_queries` がサポートされるようになりました。これはクエリキューのサイズ制限に使用できます。上限に達すると、それ以降のすべてのクエリは `SERVER_OVERLOADED` エラーで終了されます。[#81250](https://github.com/ClickHouse/ClickHouse/pull/81250) ([Oleg Doronin](https://github.com/dorooleg)).
* USE DATABASE {name} と記述できるようになりました。[#81307](https://github.com/ClickHouse/ClickHouse/pull/81307) ([Yarik Briukhovetskyi](https://github.com/yariks5s)) 。
* 金融関数 `financialInternalRateOfReturnExtended` (`XIRR`)、`financialInternalRateOfReturn` (`IRR`)、`financialNetPresentValueExtended` (`XNPV`)、`financialNetPresentValue` (`NPV`) を追加しました。[#81599](https://github.com/ClickHouse/ClickHouse/pull/81599) ([Joanna Hulboj](https://github.com/jh0x))。
* 利用可能なコーデックを確認するための新しい system table `system.codecs` を追加しました。(issue [#81525](https://github.com/ClickHouse/ClickHouse/issues/81525))。[#81600](https://github.com/ClickHouse/ClickHouse/pull/81600) ([Jimmy Aguilar Mena](https://github.com/Ergus))。
* 2 つの polygons が交差しているかどうかを確認する地理空間関数 `polygonIntersectsCartesian` と `polygonIntersectsSpherical` を追加しました。[#81882](https://github.com/ClickHouse/ClickHouse/pull/81882) ([Paul Lamb](https://github.com/plamb))。
* `MergeTree` ファミリーのテーブル向けに論理更新のサポートを追加しました。論理更新は、新しい構文 `UPDATE <table> SET col1 = val1, col2 = val2, ... WHERE <condition>` で使用できます。また、論理更新による論理削除の実装も追加しました。これは `lightweight_delete_mode = 'lightweight_update'` を設定することで有効にできます。[#82004](https://github.com/ClickHouse/ClickHouse/pull/82004) ([Anton Popov](https://github.com/CurtizJ))。
* `lag` および `lead` window functions をサポートしました。[#9887](https://github.com/ClickHouse/ClickHouse/issues/9887) をクローズします。[#82108](https://github.com/ClickHouse/ClickHouse/pull/82108) ([Dmitry Novik](https://github.com/novikd))。
* MergeTree ファミリーのテーブルで `_part_granule_offset` 仮想カラムをサポートしました。このカラムは、各行が属する granule/mark の、その data part 内での 0 始まりの索引を示します。これにより [#79572](https://github.com/ClickHouse/ClickHouse/issues/79572) に対応します。[#82341](https://github.com/ClickHouse/ClickHouse/pull/82341) ([Amos Bird](https://github.com/amosbird))。
* `insert` クエリでの Iceberg への書き込みを導入しました。[#82692](https://github.com/ClickHouse/ClickHouse/pull/82692) ([Konstantin Vedernikov](https://github.com/scanhex12))。
* `Float32` および `Float64` 型のカラム向けに、非可逆ながら誤差が保証された圧縮コーデックとして SZ3 を追加しました。[#83088](https://github.com/ClickHouse/ClickHouse/pull/83088) ([Konstantin Vedernikov](https://github.com/scanhex12))。
* ClickHouse client に AI を活用した SQL 生成を追加しました。ユーザーは、クエリの先頭に &quot;??&quot; を付けることで、自然言語の説明から SQL クエリを生成できるようになりました。OpenAI および Anthropic プロバイダーをサポートし、自動スキーマ検出にも対応しています。[#83314](https://github.com/ClickHouse/ClickHouse/pull/83314) ([Kaushik Iska](https://github.com/iskakaushik))。
* フィールド ID による Iceberg data files の読み取りに対応しました。これにより [#83065](https://github.com/ClickHouse/ClickHouse/issues/83065) をクローズします。[#83653](https://github.com/ClickHouse/ClickHouse/pull/83653) ([Konstantin Vedernikov](https://github.com/scanhex12))。
* sRGB 色空間と OkLCH 色空間の間で色を変換する SQL 関数 `colorSRGBToOkLCH` および `colorOkLCHToSRGB` を追加しました。[#83679](https://github.com/ClickHouse/ClickHouse/pull/83679) ([Fgrtue](https://github.com/Fgrtue))。
* [#84005](https://github.com/ClickHouse/ClickHouse/issues/84005) にバックポート: AI を活用した SQL 生成で、利用可能な場合は環境変数 ANTHROPIC&#95;API&#95;KEY および OPENAI&#95;API&#95;KEY を自動的に推論できるようになりました。これにより、この機能を設定不要で利用できるようになります。[#83787](https://github.com/ClickHouse/ClickHouse/pull/83787) ([Kaushik Iska](https://github.com/iskakaushik))。



<div id="experimental-feature">
  #### 実験的機能
</div>

* テキスト索引を検索するための汎用ツールとして、`searchAny` 関数と `searchAll` 関数を追加しました。 [#80641](https://github.com/ClickHouse/ClickHouse/pull/80641) ([Elmi Ahmadov](https://github.com/ahmadov)).
* テキスト索引で `string` トークナイザーがサポートされるようになりました。 [#81752](https://github.com/ClickHouse/ClickHouse/pull/81752) ([Elmi Ahmadov](https://github.com/ahmadov)).
* `text` 索引のデフォルトの index granularity 値を 64 に変更しました。これにより、内部ベンチマークにおける平均的なテストクエリの想定パフォーマンスが向上します。 [#82162](https://github.com/ClickHouse/ClickHouse/pull/82162) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* 256-bit bitmap は state の出力 labels を順序付きで保持しますが、出力 state は hash table 内での出現順にディスクへ保存されます。そのため、ディスクから読み取る際に label が誤った次の state を指していました。 [#82783](https://github.com/ClickHouse/ClickHouse/pull/82783) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 現在、FST tree は非圧縮のままディスクに保存されます。このため、ディスクへの書き込み時とディスクからの読み取り時の両方で、パフォーマンス低下や I/O bandwidth の増大を招く可能性があります。 [#83093](https://github.com/ClickHouse/ClickHouse/pull/83093) ([Elmi Ahmadov](https://github.com/ahmadov)).
* バグのため、`searchAny` と `searchAll` を削除しました。詳しくは [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385) を参照してください。 [#83117](https://github.com/ClickHouse/ClickHouse/pull/83117) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 最近、fuzzer によって `searchAny` 関数および `searchAll` 関数に関する issue が発見されました ([#82385](https://github.com/ClickHouse/ClickHouse/issues/82385) を参照) 。この Exception は、`searchAny` または `searchAll` 関数が同じカラムに対して異なるテキスト索引パラメータを受け取ると発生します。この状況が起こり得るのは、同じカラムに対して 2 つの異なるテキスト索引が存在する場合のみです。この PR では、テキスト索引に対して同じカラムを定義できるのは 1 回のみに制限しましたが、カラムを包む wrapper (例: `lower(column)`) は引き続き許可されています。 [#83303](https://github.com/ClickHouse/ClickHouse/pull/83303) ([Elmi Ahmadov](https://github.com/ahmadov)).



<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `-If` combinator の軽微な最適化。[#78454](https://github.com/ClickHouse/ClickHouse/pull/78454) ([李扬](https://github.com/taiyang-li)).
* ネットワーク接続に紐づく単一スレッドではなく、ブロックの圧縮/伸長およびシリアライゼーション/デシリアライゼーションをパイプラインスレッドにオフロードするオプションを導入しました。これは設定 `enable_parallel_blocks_marshalling` で制御されます。イニシエーターとリモートノード間で大量のデータを転送する分散クエリの高速化が見込まれます。[#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* ベクトル類似度索引を使用するベクトル検索クエリは、ストレージ読み取りの削減と CPU 使用率の低減により、より低レイテンシで完了するようになりました。[#79103](https://github.com/ClickHouse/ClickHouse/pull/79103) ([Shankar Iyer](https://github.com/shankar-iyer)).
* `filterPartsByQueryConditionCache` で `merge_tree_min_{rows,bytes}_for_seek` を尊重するようにし、索引でフィルタリングする他のメソッドと挙動を揃えました。[#80312](https://github.com/ClickHouse/ClickHouse/pull/80312) ([李扬](https://github.com/taiyang-li)).
* TOTALS ステップ後のパイプラインをマルチスレッド化しました。[#80331](https://github.com/ClickHouse/ClickHouse/pull/80331) ([UnamedRus](https://github.com/UnamedRus)).
* 各シャードで INSERT SELECT が独立して実行されるモードでは、並列 distributed INSERT SELECT がデフォルトで有効になりました。`parallel_distributed_insert_select` 設定を参照してください。[#80425](https://github.com/ClickHouse/ClickHouse/pull/80425) ([Igor Nikonov](https://github.com/devcrafter)).
* パフォーマンス向上のため、いくつかの jemalloc 設定を調整しました。[#81807](https://github.com/ClickHouse/ClickHouse/pull/81807) ([Antonio Andelic](https://github.com/antonio2368)).
* Redis および KeeperMap ストレージで、キーによるフィルタを修正しました。[#81833](https://github.com/ClickHouse/ClickHouse/pull/81833) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* JOIN の入力および出力ブロックの最小ブロックサイズ (行数) を制御する新しい設定 `min_joined_block_size_rows` を追加しました (`min_joined_block_size_bytes` に相当。デフォルト値は 65409) 。join algorithm が対応している場合、小さなブロックはまとめられます。[#81886](https://github.com/ClickHouse/ClickHouse/pull/81886) ([Nikita Taranov](https://github.com/nickitat)).
* 集計クエリに NOT NULL カラムに対する単一の `COUNT()` 関数しか含まれない場合、ハッシュテーブルのプロービング中に集計ロジックが完全にインライン化されます。これにより、集計状態の割り当てや維持が不要になり、メモリ使用量と CPU オーバーヘッドが大幅に削減されます。これは [#81982](https://github.com/ClickHouse/ClickHouse/issues/81982) に部分的に対応するものです。[#82104](https://github.com/ClickHouse/ClickHouse/pull/82104) ([Amos Bird](https://github.com/amosbird)).
* `HashJoin` のパフォーマンスを最適化し、キーとなるカラムが 1 つだけという一般的なケースで、ハッシュマップに対する追加ループを削除しました。さらに、常に `true`/`false` となる場合は `null_map` と `join_mask` のチェックも省略されます。[#82308](https://github.com/ClickHouse/ClickHouse/pull/82308) ([Nikita Taranov](https://github.com/nickitat)).
* `ATTACH PARTITION` によってすべての cache が削除されることはなくなりました。[#82377](https://github.com/ClickHouse/ClickHouse/pull/82377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 等価クラスを使って冗長な JOIN演算 を削除し、相関サブクエリ向けに生成される実行計画を最適化しました。すべての相関カラムに対して等価な式が存在する場合、`query_plan_correlated_subqueries_use_substitution` 設定が有効であれば `CROSS JOIN` は生成されません。[#82435](https://github.com/ClickHouse/ClickHouse/pull/82435) ([Dmitry Novik](https://github.com/novikd)).
* 相関サブクエリが関数 `EXISTS` の引数になっている場合は、必要なカラムだけを読み取るようになりました。[#82443](https://github.com/ClickHouse/ClickHouse/pull/82443) ([Dmitry Novik](https://github.com/novikd)).
* 非同期ロギングを導入。 [#82516](https://github.com/ClickHouse/ClickHouse/pull/82516) ([Raúl Marín](https://github.com/Algunenano)).
* ネイティブプロトコルで logs と profile events を圧縮。100 以上のレプリカを持つクラスターでは、非圧縮の profile events は 1..10 MB/秒に達し、低速なインターネット接続では進捗バーの動作が重くなります。これにより [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533) を解消します。 [#82535](https://github.com/ClickHouse/ClickHouse/pull/82535) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* QueryTreeHash を若干高速化。 [#82617](https://github.com/ClickHouse/ClickHouse/pull/82617) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* フォールスシェアリングを減らすため、ProfileEvents の カウンター にアラインメントを追加。 [#82697](https://github.com/ClickHouse/ClickHouse/pull/82697) ([Jiebin Sun](https://github.com/jiebinn)).
* 各分片で INSERT SELECT を独立して実行するモードでは、parallel distributed INSERT SELECT がデフォルトで有効になります。`parallel_distributed_insert_select` 設定を参照してください。 [#83040](https://github.com/ClickHouse/ClickHouse/pull/83040) ([Igor Nikonov](https://github.com/devcrafter)).
* [#82308](https://github.com/ClickHouse/ClickHouse/issues/82308) の `null_map` と `JoinMask` に対する最適化を、複数の選言を含む JOIN のケースにも適用しました。あわせて、`KnownRowsHolder` データ構造も最適化しました。 [#83041](https://github.com/ClickHouse/ClickHouse/pull/83041) ([Nikita Taranov](https://github.com/nickitat)).
* フラグアクセスのたびにハッシュを計算しないよう、JOIN フラグには単純な `std::vector<std::atomic_bool>` を使用します。 [#83043](https://github.com/ClickHouse/ClickHouse/pull/83043) ([Nikita Taranov](https://github.com/nickitat)).
* `HashJoin` が `lazy` 出力モードを使用する場合、結果カラム用メモリを事前確保しないようにしました。これは、特に一致数が少ない場合に非効率だからです。また、JOIN 完了後には一致数を正確に把握できるため、より適切に事前確保できます。 [#83304](https://github.com/ClickHouse/ClickHouse/pull/83304) ([Nikita Taranov](https://github.com/nickitat)).
* パイプライン構築時のポートヘッダーにおけるメモリコピーを最小化。元の [PR](https://github.com/ClickHouse/ClickHouse/pull/70105) は [heymind](https://github.com/heymind) によるものです。 [#83381](https://github.com/ClickHouse/ClickHouse/pull/83381) ([Raúl Marín](https://github.com/Algunenano)).
* RocksDB の初期ロードにおける Keeper を改善。 [#83390](https://github.com/ClickHouse/ClickHouse/pull/83390) ([Antonio Andelic](https://github.com/antonio2368)).
* 高い同時実行負荷時のロック競合を減らすため、ストレージスナップショットデータの作成中にロックを保持しないようにしました。 [#83510](https://github.com/ClickHouse/ClickHouse/pull/83510) ([Duc Canh Le](https://github.com/canhld94)).
* パースエラーが発生しない場合に serializer を再利用することで、ProtobufSingle 入力フォーマットの性能を改善。 [#83613](https://github.com/ClickHouse/ClickHouse/pull/83613) ([Eduard Karacharov](https://github.com/korowa)).
* パイプライン構築の性能を改善。 [#83631](https://github.com/ClickHouse/ClickHouse/pull/83631) ([Raúl Marín](https://github.com/Algunenano)).
* MergeTreeReadersChain::getSampleBlock を最適化。 [#83875](https://github.com/ClickHouse/ClickHouse/pull/83875) ([Raúl Marín](https://github.com/Algunenano)).
