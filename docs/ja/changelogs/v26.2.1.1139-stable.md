<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* statistics のストレージフォーマットを改善しました。すべての statistics は単一のファイルに保存されるようになりました。[#93414](https://github.com/ClickHouse/ClickHouse/pull/93414) ([Anton Popov](https://github.com/CurtizJ)).
* S3(Azure)Queue のインメモリメタデータを制限しました。システムテーブルは `azure_queue` から `azure_queue_metadata_cache` へ、`system.s3queue` から `s3queue_metadata_cache` へリネームされました。[#95809](https://github.com/ClickHouse/ClickHouse/pull/95809) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `Variant` 型の不一致時に発生する論理エラーを修正しました。[#95811](https://github.com/ClickHouse/ClickHouse/pull/95811) ([Bharat Nallan](https://github.com/bharatnc)).
* 破壊的変更: この変更により、すべての insert で deduplication がデフォルトで ON になります。以前は非同期 INSERT と MV では OFF、同期 insert では ON でした。これは、両方の insert 方式でデフォルトを統一するためです。クラスターで deduplication を明示的に無効にしている場合は、従来の動作を維持するために `deduplicate_insert='backward_compatible_choice'` を明示的に設定する必要があります。`deduplicate_blocks_in_dependent_materialized_views` についても同様です。[#95970](https://github.com/ClickHouse/ClickHouse/pull/95970) ([Sema Checherinda](https://github.com/CheSema)).
* PostgreSQL の `DATE` カラムは、ClickHouse では `Date32` として推論されるようになりました (以前のバージョンでは `Date` として推論されており、その結果、狭い範囲を超える値で overflow が発生していました) 。また、`Date32` の値を PostgreSQL に書き戻して insert できるようになりました。[#73084](https://github.com/ClickHouse/ClickHouse/issues/73084) をクローズします。[#95999](https://github.com/ClickHouse/ClickHouse/pull/95999) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `do_not_merge_across_partitions_select_final` 設定の意味を、より明確にしました。以前は、この機能は config で設定が明示されていない場合に自動的に有効になることがありました。そのため繰り返し混乱を招き、残念ながら production でいくつかの問題も引き起こしていました。現在はルールがよりシンプルです。`do_not_merge_across_partitions_select_final=1` は無条件でこの機能を有効にします。`do_not_merge_across_partitions_select_final=0` の場合、自動判定は新しい設定 `enable_automatic_decision_for_merging_across_partitions_for_final=1` のときにのみ使用され、それ以外では使用されません。従来の動作をできるだけ維持するため、デフォルト値は `do_not_merge_across_partitions_select_final=0` および `enable_automatic_decision_for_merging_across_partitions_for_final=1` に設定されました。[#96110](https://github.com/ClickHouse/ClickHouse/pull/96110) ([Nikita Taranov](https://github.com/nickitat)).
* S3 のスキーマ検証を追加しました。これにより [#96089](https://github.com/ClickHouse/ClickHouse/issues/96089) をクローズします。[#96194](https://github.com/ClickHouse/ClickHouse/pull/96194) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* ORDER BY およびその他のテーブル key expressions で subqueries を使用することを禁止しました。[#96847](https://github.com/ClickHouse/ClickHouse/pull/96847) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `apply_row_policy_after_final` をデフォルトで有効にしました。もともと `optimize_move_to_prewhere_if_final=0` の場合、ROW POLICY と PREWHERE はどちらも FINAL を考慮し、FINAL の後に適用されていました。これは [#87303](https://github.com/ClickHouse/ClickHouse/issues/87303) によって壊され、ROW POLICY filter について `optimize_move_to_prewhere_if_final` が無視されるようになっていました。これを修正するため、この PR では [#91065](https://github.com/ClickHouse/ClickHouse/issues/91065) で導入された設定 `apply_row_policy_after_final` を有効にしています。`apply_row_policy_after_final` を有効にすると、ROW POLICY は以前と同様、デフォルトで FINAL を引き続き考慮します。この PR は `optimize_move_to_prewhere_if_final=1` の動作を変更するため、互換性のない変更です。今後、FINAL の前に ROW POLICY を適用するには、`optimize_move_to_prewhere_if_final` ではなく `apply_row_policy_after_final` を使用する必要があります。[#97279](https://github.com/ClickHouse/ClickHouse/pull/97279) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).



<div id="new-feature">
  #### 新機能
</div>

* 時間ベースのワンタイムパスワードを認証方式としてサポート。 [#71273](https://github.com/ClickHouse/ClickHouse/pull/71273) ([Vladimir Cherkasov](https://github.com/vdimir)).
* cache 内のデータファイルとシステムファイルを別々のセグメントに分割できるようにしました。 [#87834](https://github.com/ClickHouse/ClickHouse/pull/87834) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* メタデータの読み取りだけのためにファイルを再ダウンロードする必要をなくし、読み取り性能を向上させるため、Parquet メタデータ用の新しい SLRU cache を追加しました。この cache は `SYSTEM DROP PARQUET METADATA CACHE` で削除できます。[#89102](https://github.com/ClickHouse/ClickHouse/issues/89102) を解決。 [#89750](https://github.com/ClickHouse/ClickHouse/pull/89750) ([Grant Holly](https://github.com/grantholly-clickhouse)).
* UDF の loading status と configuration を監視するための新しい system table `system.user_defined_functions` を追加。 [#90340](https://github.com/ClickHouse/ClickHouse/pull/90340) ([Xu Jia](https://github.com/XuJia0210)).
* default&#95;dictionary&#95;database setting を追加しました。これにより、データベース修飾子なしで参照される external dictionaries を、指定した default database で ClickHouse が解決できるようになります。これにより、XML で定義されたグローバル Dictionary から SQL で定義されたデータベース単位の Dictionary への移行が簡単になり、既存の Dictionary クエリ (例: dictGet(&#39;name&#39;, …)) を変更せずに引き続き利用できます。 [#91412](https://github.com/ClickHouse/ClickHouse/pull/91412) ([Dmitrii Plotnikov](https://github.com/dimbo4ka)).
* `DatabaseReplicated` で補助的な ZooKeeper をサポート。 [#91683](https://github.com/ClickHouse/ClickHouse/pull/91683) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* 新しい table function `primes` と、素数を昇順で含む新しい system table `system.primes` を実装。 [#90839](https://github.com/ClickHouse/ClickHouse/issues/90839) をクローズ。 [#92776](https://github.com/ClickHouse/ClickHouse/pull/92776) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 非同期 INSERT が並列クォーラムをサポート。挿入されたデータはクォーラムにレプリケートされます。重複が見つかった場合、クエリは以前に挿入されたデータもレプリケートされるまで待機します。 [#93356](https://github.com/ClickHouse/ClickHouse/pull/93356) ([Sema Checherinda](https://github.com/CheSema)).
* sRGB から OKLAB へ、またその逆方向に値を変換する関数 `colorOKLABToSRGB`、`colorSRGBToOKLAB` を追加。 [#93361](https://github.com/ClickHouse/ClickHouse/pull/93361) ([Pranav Tiwari](https://github.com/pranavt84)).
* insert&#95;deduplicate と async&#95;insert&#95;deduplicate を上書きする新しい deduplicate&#95;insert。 [#94413](https://github.com/ClickHouse/ClickHouse/pull/94413) ([Sema Checherinda](https://github.com/CheSema)).
* SQL で一部の関数を括弧なしで使えるようにしました。 [#52102](https://github.com/ClickHouse/ClickHouse/issues/52102) をクローズ。 [#94678](https://github.com/ClickHouse/ClickHouse/pull/94678) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* server setting `insert_deduplication_version` により、統一された deduplication hash への移行が可能になります。 [#95409](https://github.com/ClickHouse/ClickHouse/pull/95409) ([Sema Checherinda](https://github.com/CheSema)).
* 新しい configuration options: logger.startup&#95;console&#95;level と logger.shutdown&#95;console&#95;level。これにより、それぞれ ClickHouse の起動時と停止時にコンソール log level を上書きできます。 [#95919](https://github.com/ClickHouse/ClickHouse/pull/95919) ([Garrett Thomas](https://github.com/garrettthomaskth)).
* xxh3&#95;128 hashing function を追加。 [#96055](https://github.com/ClickHouse/ClickHouse/pull/96055) ([Raúl Marín](https://github.com/Algunenano)).
* 結果パーツを commit せずに merges をシミュレートする `OPTIMIZE <table> DRY RUN PARTS <part names>` クエリを追加しました。テスト用途、たとえば新バージョンでの merge の正しさの検証、merge 関連バグの決定論的な再現、merge パフォーマンスの信頼性の高い benchmarking に役立ちます。[#96122](https://github.com/ClickHouse/ClickHouse/pull/96122) ([Anton Popov](https://github.com/CurtizJ)).
* tables で使用中の named collections の dropping を防ぐため、setting `check_named_collection_dependencies` で default で enabled になる新しい check を追加しました。[#96181](https://github.com/ClickHouse/ClickHouse/pull/96181) ([Pablo Marcos](https://github.com/pamarcos)).
* `lazy_load_tables` database setting を追加しました。enabled の場合、database の起動時に tables はロードされず、代わりに軽量な `StorageTableProxy` が作成され、実際の table engine は最初のアクセス時に materialized されます。[#96283](https://github.com/ClickHouse/ClickHouse/pull/96283) ([xiaohuanlin](https://github.com/xiaohuanlin)).
* Users は ClickHouse から直接 ClickStack を利用できるようになり、debugging やローカル開発に役立ちます。[#96597](https://github.com/ClickHouse/ClickHouse/pull/96597) ([Aaron Knudtson](https://github.com/knudtty)).
* server 内の既存の failpoints と、それらが enabled か not かを確認するための `system.fail_points` を追加しました。これによりテストの自動化がしやすくなります。[#96762](https://github.com/ClickHouse/ClickHouse/pull/96762) ([Pedro Ferreira](https://github.com/PedroTadim)).
* Google BigLake カタログ インテグレーション。これにより [#95339](https://github.com/ClickHouse/ClickHouse/issues/95339) を close します。[#97104](https://github.com/ClickHouse/ClickHouse/pull/97104) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* deduplication hashes の移行を開始しました。[#97562](https://github.com/ClickHouse/ClickHouse/pull/97562) ([Sema Checherinda](https://github.com/CheSema)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* ColumnVector::replicateにdynamic dispatchを実装し、一部のハッシュジョイン操作を高速化しました。[#79573](https://github.com/ClickHouse/ClickHouse/pull/79573) ([Raúl Marín](https://github.com/Algunenano)).
* 複雑な述語を含む場合のParallelHashJoinのパフォーマンスを改善しました。以前は非結合行を1つのスレッドで処理していましたが、これは最適ではありませんでした。この最適化では、非結合行の処理を複数のスレッドに並列化します。`parallel_non_joined_rows_processing`設定で切り替え可能で、デフォルトで有効です。[#92068](https://github.com/ClickHouse/ClickHouse/pull/92068) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 主キーにおける任意の決定論的な式をデータスキッピングに使用できるようになりました（例：`ORDER BY cityHash64(user_id)`、`ORDER BY length(user_id)`）。決定論的な式の場合、ClickHouseはその式をクエリの定数に適用し、`=`、`IN`、`has`などの述語に対して主キー索引の結果を利用できます。式が単射でもある場合（例：`ORDER BY hex(p)`や`ORDER BY reverse(tuple(reverse(p), hex(p)))`）、否定形の`!=`、`NOT IN`、`NOT has`に対しても索引を効果的に使用できます。[#10685](https://github.com/ClickHouse/ClickHouse/issues/10685)をクローズ。[#82161](https://github.com/ClickHouse/ClickHouse/issues/82161)をクローズ。[#92952](https://github.com/ClickHouse/ClickHouse/pull/92952) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* JSON型のパースをわずかに最適化しました。[#93614](https://github.com/ClickHouse/ClickHouse/pull/93614) ([Pavel Kruglov](https://github.com/Avogar)).
* オブジェクトからstd::optional<TokenIterator> begin/endを削除することで、ASTLiteralのメモリフットプリントを改善しました。ハイライトが使用されておらずVALUESのパースもない場合、これらのフィールドは使用されないため、この最適化は有効です。[#93974](https://github.com/ClickHouse/ClickHouse/pull/93974) ([Ilya Yatsishin](https://github.com/qoega)).
* 名前付きTuple ASTオブジェクトのメモリ消費を最適化しました。カラム名を汎用のASTリテラルノードに持たせる代わりに、Tupleオブジェクト内に文字列として格納するようにしました。[#94704](https://github.com/ClickHouse/ClickHouse/pull/94704) ([Ilya Yatsishin](https://github.com/qoega)).
* 追加のリンカーオプションにより、仮想関数の非仮想化が改善されました。[#94737](https://github.com/ClickHouse/ClickHouse/pull/94737) ([Nikita Taranov](https://github.com/nickitat)).
* ZooKeeperリクエストをバッチ処理することで、パーツ数の多いReplicatedMergeTreeテーブルのレプリカクローンのパフォーマンスを改善しました。[#94847](https://github.com/ClickHouse/ClickHouse/pull/94847) ([c-end](https://github.com/c-end)).
* `FINAL`クエリが主キー条件でフィルタリングした後にスキップ索引を使用する場合、`PrimaryKeyExpand`処理ステップは最初に絞り込まれた主キー範囲のみを交差チェックするようになりました。[#94903](https://github.com/ClickHouse/ClickHouse/pull/94903) ([Shankar Iyer](https://github.com/shankar-iyer)).
* `for`ループの外でstd::vectorを作成し、事前にメモリを確保するようにしました。これにより、各イテレーションでのメモリ確保を回避できます。[#95178](https://github.com/ClickHouse/ClickHouse/pull/95178) ([Alexey Bakharew](https://github.com/alexbakharew)).
* 読み取りステップにすでにPREWHEREフィルタが存在する場合、新しいフィルタを追加できません。この変更により、ランタイムフィルタもPREWHEREにプッシュできるよう、PREWHERE最適化をJOINランタイムフィルタ最適化の後まで遅延させるようにしました。[#95838](https://github.com/ClickHouse/ClickHouse/pull/95838) ([Alexander Gololobov](https://github.com/davenger)).
* x86上でdynamic dispatchを使用することで、T64コーデックの圧縮を高速化しました。[#95881](https://github.com/ClickHouse/ClickHouse/pull/95881) ([Raúl Marín](https://github.com/Algunenano)).
* 条件が揃う場合（NULLでない、-Ifでない、GROUP BYなし、IPv6やStringでない）に挿入をバッチ処理することで、数値型に対する`uniq`を高速化しました。[#95904](https://github.com/ClickHouse/ClickHouse/pull/95904) ([Raúl Marín](https://github.com/Algunenano)).
* `ZooKeeper::observeOperations`がZooKeeper受信スレッドのCPU消費の20%以上を占めていることが判明しました。この変更では以下の対策を実施しています：1. `AggregatedZooKeeperLog::stats`において、`SipHash`の代わりに10倍以上高速な`CityHash64`を使用。2. `Coordination::ErrorCounter`において、`std::unordered_map`と`std::mutex`の代わりに`std::array<std::atomic<UInt32>, N>`を使用。[#95962](https://github.com/ClickHouse/ClickHouse/pull/95962) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* ProfileEvents::Counterの64バイトアライメントを元に戻しました。[#96097](https://github.com/ClickHouse/ClickHouse/pull/96097) ([Azat Khuzhin](https://github.com/azat)).
* CachedOnDiskReadBufferFromFile構造体のサイズを50分の1に削減しました。[#96098](https://github.com/ClickHouse/ClickHouse/pull/96098) ([Azat Khuzhin](https://github.com/azat)).
* HashTable::resizeにおいて、データが空の場合は古いデータをコピーしないようにしました。[#96180](https://github.com/ClickHouse/ClickHouse/pull/96180) ([Raúl Marín](https://github.com/Algunenano)).
* `RIGHT OUTER` JOINに対するJOINランタイムフィルタをサポートしました。[#96183](https://github.com/ClickHouse/ClickHouse/pull/96183) ([Hechem Selmi](https://github.com/m-selmi)).
* 以前は、テキスト索引の直接読み取り最適化はすべてのパーツにマテリアライズされたテキスト索引がある場合にのみ適用されていました。この変更では部分的なサポートを追加しています。一部のパーツにマテリアライズされたテキスト索引がある場合、そのパーツはテキスト索引を使用し、テキスト索引のないパーツは元のフィルタ式の実行にフォールバックします。[#96411](https://github.com/ClickHouse/ClickHouse/pull/96411) ([Anton Popov](https://github.com/CurtizJ)).
* 重複排除が無効の場合のINSERT時におけるメモリ使用量のリグレッションを回避しました。[#96503](https://github.com/ClickHouse/ClickHouse/pull/96503) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `long double`が十分なプラットフォームでは`wide_integer_impl.h`にboost/multiprecisionヘッダーをインクルードしないようにし、ビルド時間を改善しました。TODO: パフォーマンスに変化がない場合はカテゴリをBUILDに変更。[#96633](https://github.com/ClickHouse/ClickHouse/pull/96633) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [#97942](https://github.com/ClickHouse/ClickHouse/issues/97942)にバックポート：一般的に重複排除には元のブロックが必要ですが、同期挿入の場合はそれを省略してメモリを節約できます。[#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* フィルタリングを高速化するため、システムログテーブルの時刻カラムに`minmax`セカンダリ索引を、`query_id`/`initial_query_id`カラムに`bloom_filter`索引を追加しました。[#96712](https://github.com/ClickHouse/ClickHouse/pull/96712) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* LZ4：x86における32バイトブロックの展開を高速化しました。[#96778](https://github.com/ClickHouse/ClickHouse/pull/96778) ([Raúl Marín](https://github.com/Algunenano)).
* 遅延マテリアライゼーション最適化が、`UNION ALL`クエリの最初のブランチだけでなく、すべてのブランチに適用されるようになりました。`UNION ALL`を使って異なる`MergeTree`テーブルからのソート済み・件数制限付き読み取りを組み合わせるクエリは、すべてのブランチでカラムの遅延読み取りの恩恵を受け、I/Oが削減されます。[#96832](https://github.com/ClickHouse/ClickHouse/pull/96832) ([Federico Ginosa](https://github.com/menxit)).
* 不要なデータコピーを削除し、数値カラムに対してベクトル化されたmin/max計算を有効にすることで、INSERT時のminmaxスキップ索引の計算を最適化しました。[#97392](https://github.com/ClickHouse/ClickHouse/pull/97392) ([Raúl Marín](https://github.com/Algunenano)).
* [#98184](https://github.com/ClickHouse/ClickHouse/issues/98184) にバックポート済み: 索引付きカラムと非索引カラムの両方を含む複合条件を持つクエリに対するテキスト索引解析のパフォーマンスを改善しました。以前は、このようなケースで索引解析中の早期終了最適化が誤って無効化されていました。[#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ))

<div id="performance-optimization">
  #### パフォーマンス最適化
</div>

* `concurrent_threads_scheduler` のデフォルトが、`fair_round_robin` から `max_min_fair` に変更されました。これにより、高負荷時には割り当てスロット数の少ないクエリが優先されるため、公平性が向上し、短時間で終了するクエリが長時間実行されるクエリに引きずられにくくなります。[#95300](https://github.com/ClickHouse/ClickHouse/pull/95300) ([Sergei Trifonov](https://github.com/serxa)).
