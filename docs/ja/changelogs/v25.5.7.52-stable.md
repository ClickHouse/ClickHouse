<div id="improvement">
  #### 改善
</div>

* [#83014](https://github.com/ClickHouse/ClickHouse/issues/83014) にバックポート: Keeper の改善: 変更ログファイルをバックグラウンドスレッドでディスク間移動するようにしました。従来は、変更ログを別のディスクに移動すると、移動が完了するまで Keeper 全体がブロックされていました。移動に長時間かかる場合 (たとえば S3 ディスク への移動) 、これにより性能が低下していました。[#82485](https://github.com/ClickHouse/ClickHouse/pull/82485) ([Antonio Andelic](https://github.com/antonio2368))。
* [#83268](https://github.com/ClickHouse/ClickHouse/issues/83268) にバックポート: `clickhouse-benchmark` の `--reconnect` オプションの誤ったデフォルト値を修正しました。この値は [#79465](https://github.com/ClickHouse/ClickHouse/issues/79465) で誤って変更されていました。[#82677](https://github.com/ClickHouse/ClickHouse/pull/82677) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* [#83152](https://github.com/ClickHouse/ClickHouse/issues/83152) にバックポート: `system.s3queue_log` にカラム `commit_time`、`commit_id` を追加しました。[#83016](https://github.com/ClickHouse/ClickHouse/pull/83016) ([Kseniia Sumarokova](https://github.com/kssenii))。
* [#83634](https://github.com/ClickHouse/ClickHouse/issues/83634) にバックポート: `distributed_ddl_output_mode='*_only_active'` の場合、`max_replication_lag_to_enqueue` を超えるレプリケーションラグがある新規または復旧したレプリカを待機しないようにしました。これにより、新しいレプリカが初期化または復旧の完了後にアクティブになったものの、初期化中に大量のレプリケーションログを蓄積していた場合に、`DDL task is not finished on some hosts` を回避しやすくなります。あわせて、レプリケーションログが `max_replication_lag_to_enqueue` 未満になるまで待機する `SYSTEM SYNC DATABASE REPLICA STRICT` クエリも実装しました。[#83302](https://github.com/ClickHouse/ClickHouse/pull/83302) ([Alexander Tokmakov](https://github.com/tavplubix))。
