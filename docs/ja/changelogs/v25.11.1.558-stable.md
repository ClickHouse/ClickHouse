<div id="clickhouse-release-v25111558-stable-16f22f3d744-fixme-as-compared-to-v251111-new-ae414ae37fc">
  ### ClickHouse リリース v25.11.1.558-stable (16f22f3d744) FIXME (v25.11.1.1-new (ae414ae37fc) との比較)
</div>

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* `Geometry` 型を導入しました。この型で `WKB` および `WKT` フォーマットの読み取りをサポートします。以前のバージョンでは `Geometry` 型は `String` の別名でしたが、現在は完全な機能を備えた型になっています。[#83344](https://github.com/ClickHouse/ClickHouse/pull/83344) ([scanhex12](https://github.com/scanhex12)).
* 非推奨の Object 型を削除しました。[#85718](https://github.com/ClickHouse/ClickHouse/pull/85718) ([Pavel Kruglov](https://github.com/Avogar)).
* MergeTree テーブルの Wide data part 内の Variant 型 subcolumn 用に作成されるファイル名をエスケープするようにしました。この変更により、Variant/Dynamic/JSON data types を使用する古いテーブルとの互換性は失われます。これにより、Variant 内で特殊記号を含む型 (たとえば `\` を含む特定の timezone を持つ DateTime) を保存できるようになります。エスケープは MergeTree setting `escape_variant_subcolumn_filenames` を変更することで無効にできます (互換性を維持するには、MergeTree の config でこの setting を無効にするか、`compatibility` setting を upgrade 前のバージョンに設定してください) 。[#69590](https://github.com/ClickHouse/ClickHouse/issues/69590) を解決します。[#87300](https://github.com/ClickHouse/ClickHouse/pull/87300) ([Pavel Kruglov](https://github.com/Avogar)).
* 廃止された `LIVE VIEW` feature を削除しました。`LIVE VIEW` を使用している場合、新しいバージョンへの upgrade はできません。[#88706](https://github.com/ClickHouse/ClickHouse/pull/88706) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* clients が例外をより確実に解析できるよう、HTTP results response での exception tagging をサポートしました。[#75175](https://github.com/ClickHouse/ClickHouse/issues/75175) を解決します。フォーマット間の一貫性を保つため、setting `http_write_exception_in_output_format` はデフォルトで無効になっています。[#88818](https://github.com/ClickHouse/ClickHouse/pull/88818) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* 共有 object storage path 上に複数の `plain-rewritable` disk を作成することを禁止しました。異なる metadata storage transaction が衝突した際に、undefined な動作を引き起こす可能性があるためです。[#89038](https://github.com/ClickHouse/ClickHouse/pull/89038) ([Mikhail Artemenko](https://github.com/Michicosun)).
* String データ型に対して、with&#95;size&#95;stream シリアライゼーション フォーマットをデフォルトで有効にしました。この変更自体は後方互換性がありますが、新しいシリアライゼーション フォーマットはバージョン 25.10 以降でのみサポートされるため、25.10 より前のバージョンにはダウングレードできません。25.9 以前へダウングレードできるようにしておきたい場合は、server configuration の merge&#95;tree セクションで serialization&#95;info&#95;version を basic に、string&#95;serialization&#95;version を single&#95;stream に設定してください。[#89329](https://github.com/ClickHouse/ClickHouse/pull/89329) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Kafka storage の SASL settings の優先順位を修正しました。CREATE TABLE queries で指定したテーブルレベルの SASL settings が、configuration files 内の consumer/producer 固有の settings を正しく override するようになりました。[#89401](https://github.com/ClickHouse/ClickHouse/pull/89401) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 要素サイズに揃っていないサイズの data を compressing した際に発生する `Fatal` を修正しました (T64 codec) 。[#89282](https://github.com/ClickHouse/ClickHouse/issues/89282) を解決します。[#89432](https://github.com/ClickHouse/ClickHouse/pull/89432) ([yanglongwei](https://github.com/ylw510)).

<div id="new-feature">
  #### 新機能
</div>

* ユーザーの権限借用をサポートするため、新しい SQL ステートメント `EXECUTE AS` を追加しました。[#39048](https://github.com/ClickHouse/ClickHouse/issues/39048) を解決します。[#70775](https://github.com/ClickHouse/ClickHouse/pull/70775) ([Shankar](https://github.com/shiyer7474))。
* Array 内で必要な数の次元を展開し、Tuple カラム内のポインタを入れ替える `flipCoordinates` 関数を追加しました。[#79469](https://github.com/ClickHouse/ClickHouse/issues/79469) を解決します。[#79634](https://github.com/ClickHouse/ClickHouse/pull/79634) ([Sachin Kumar Singh](https://github.com/sachinkumarsingh092))。
* Unicode 文字とそのプロパティの一覧を含む `system.unicode` テーブルを追加しました。[#80055](https://github.com/ClickHouse/ClickHouse/issues/80055) をクローズします。[#80857](https://github.com/ClickHouse/ClickHouse/pull/80857) ([wxybear](https://github.com/wxybear))。
* Prometheus HTTP Query API の一部をサポートしました。有効にするには、設定ファイルの `<prometheus>` セクションに、type `query_api` のルールを追加します。サポートされるハンドラーは `/api/v1/query_range` と `/api/v1/query` です。[#86132](https://github.com/ClickHouse/ClickHouse/pull/86132) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov))。
* `IS NOT DISTINCT FROM` (`<=>`) 演算子を強化し、逆の `IS DISTINCT FROM` と、異なる型の互換性のある数値オペランド (例: `Nullable(UInt32)` と `Nullable(Int64)`) をサポートしました。[#87581](https://github.com/ClickHouse/ClickHouse/pull/87581) ([yanglongwei](https://github.com/ylw510))。
* データ型で指定されたパラメータに関係なく、merge 後の Wide part に含まれる動的 subcolumns の数を制限できるようにする、新しい MergeTree setting `merge_max_dynamic_subcolumns_in_wide_part` を追加しました。[#87646](https://github.com/ClickHouse/ClickHouse/pull/87646) ([Pavel Kruglov](https://github.com/Avogar))。
* `cume_dist` window function のサポートを追加しました。[#86920](https://github.com/ClickHouse/ClickHouse/issues/86920) を修正します。[#88102](https://github.com/ClickHouse/ClickHouse/pull/88102) ([Manuel](https://github.com/raimannma))。
* テキスト索引の構築時に、新しい argument `preprocessor` を追加できるようになりました。この argument は、各 document をトークン化の前に変換する任意の expression です。[#88272](https://github.com/ClickHouse/ClickHouse/pull/88272) ([Jimmy Aguilar Mena](https://github.com/Ergus))。
* `X-ClickHouse-Progress` と `X-ClickHouse-Summary` に `memory_usage` フィールドを追加しました。これにより、client side でクエリの memory usage をリアルタイムに収集できます。[#88393](https://github.com/ClickHouse/ClickHouse/pull/88393) ([Christoph Wurm](https://github.com/cwurm))。
* テーブルの一部を選択するために、小数の `LIMIT` と `OFFSET` をサポートしました。[#81892](https://github.com/ClickHouse/ClickHouse/issues/81892) をクローズします。[#88755](https://github.com/ClickHouse/ClickHouse/pull/88755) ([Ahmed Gouda](https://github.com/0xgouda))。
* INTO OUTFILE 用の親ディレクトリを自動作成する setting `into&#95;outfile&#95;create&#95;parent&#95;directories` を追加し、出力パスが存在しない場合のエラーを防止します。これにより、クエリ結果を入れ子のディレクトリに書き込む workflow を簡素化できます。[#88610](https://github.com/ClickHouse/ClickHouse/issues/88610) を解決します。[#88795](https://github.com/ClickHouse/ClickHouse/pull/88795) ([Saksham](https://github.com/Saksham10-11))。
* Microsoft OneLake カタログのインテグレーション。[#89366](https://github.com/ClickHouse/ClickHouse/pull/89366) ([scanhex12](https://github.com/scanhex12))。
* 一時テーブルで `CREATE OR REPLACE` 構文をサポートしました。[#35888](https://github.com/ClickHouse/ClickHouse/issues/35888) をクローズします。[#89450](https://github.com/ClickHouse/ClickHouse/pull/89450) ([Aleksandr Musorin](https://github.com/AVMusorin))。
* Array `arr` から `elem` に等しいすべての要素を削除する `arrayRemove(arr, elem)` をサポートしました。[#52099](https://github.com/ClickHouse/ClickHouse/issues/52099) を解決します。[#89585](https://github.com/ClickHouse/ClickHouse/pull/89585) ([tiwarysaurav](https://github.com/tiwarysaurav)).
* `send_profile_events` 設定を追加しました。これにより、profile events を使用しない場合、clients は Network traffic を削減できます。[#89588](https://github.com/ClickHouse/ClickHouse/pull/89588) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* message payload をパースする前に envelope header のバイト列 (例: AWS Glue Schema Registry の 19 バイトのプレフィックス) をスキップするための `kafka_schema_registry_skip_bytes` 設定を Kafka table engine に追加しました。これにより、メタデータ header を追加するスキーマレジストリからのメッセージを ClickHouse で取り込めるようになります。[#89621](https://github.com/ClickHouse/ClickHouse/pull/89621) ([Taras Polishchuk](https://github.com/wake-up-neo)).
* クエリごとに、近傍 part のデータのバックグラウンドダウンロードを無効にできるようにしました。[#89524](https://github.com/ClickHouse/ClickHouse/issues/89524) を修正します。[#89668](https://github.com/ClickHouse/ClickHouse/pull/89668) ([tanner-bruce](https://github.com/tanner-bruce)).
* 平均値を計算する `midpoint` scalar 関数を導入しました。[#89029](https://github.com/ClickHouse/ClickHouse/issues/89029) を解決します。[#89679](https://github.com/ClickHouse/ClickHouse/pull/89679) ([simonmichal](https://github.com/simonmichal)).
* web UI でダウンロードボタンを利用できるようになりました。UI に一部しか表示されていない場合でも、結果全体をダウンロードできます。[#89768](https://github.com/ClickHouse/ClickHouse/pull/89768) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* コマンド形式のディスクリプタを必要とする Dremio やその他の Arrow Flight サーバーをサポートするため、`arrow_flight_request_descriptor_type` 設定を追加しました。[#89523](https://github.com/ClickHouse/ClickHouse/issues/89523) を修正します。[#89826](https://github.com/ClickHouse/ClickHouse/pull/89826) ([Shreyas Ganesh](https://github.com/shreyasganesh0)).
* 新しい `argAndMin` 関数と `argAndMax` 関数により、argument と、それに対応する minimum または maximum の値の両方を取得できるようになりました。[#89884](https://github.com/ClickHouse/ClickHouse/pull/89884) ([AbdAlRahman Gad](https://github.com/AbdAlRahmanGad)).
* `send_profile_events` 設定を追加しました。これにより、profile events を使用しない場合、clients は Network traffic を削減できます。[#89972](https://github.com/ClickHouse/ClickHouse/pull/89972) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* ClickHouse の新しいプラットフォームとして、e2k (Elbrus-2000) の Experimental サポートを追加しました。[#90159](https://github.com/ClickHouse/ClickHouse/pull/90159) ([Ramil Sattarov](https://github.com/r-a-sattarov)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* RIGHT および FULL JOIN で ConcurrentHashJoin を使用するようになりました。これにより、これらの JOIN はより高い並列度で実行されます。さまざまなケースで RIGHT JOIN と FULL JOIN が最大 2 倍高速化されます。[#78027](https://github.com/ClickHouse/ClickHouse/issues/78027) を解決しました。[#78462](https://github.com/ClickHouse/ClickHouse/pull/78462) ([Yarik Briukhovetskyi](https://github.com/yariks5s))。
* ConstantNode 内の大きな値に対する最適化。[#72880](https://github.com/ClickHouse/ClickHouse/issues/72880) をクローズしました。[#81104](https://github.com/ClickHouse/ClickHouse/pull/81104) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* 10K 超の part を持つテーブルで、広範なパーティションプルーニングを伴う `SELECT` クエリが最大 8 倍高速化されました。[#85535](https://github.com/ClickHouse/ClickHouse/pull/85535) ([James Morrison](https://github.com/jawm))。
* aarch64 およびその他の arch/kernel の組み合わせで発生しうる vsdo の問題を修正しました。[#86096](https://github.com/ClickHouse/ClickHouse/pull/86096) ([Tomas Hulata](https://github.com/tombokombo))。
* クエリが aggregation state (小さな整数で group by する場合) に fixed hash map を使用する際、ClickHouse が aggregation state を並列にマージしてクエリを高速化するようになりました。[#63666](https://github.com/ClickHouse/ClickHouse/issues/63666) を解決しました。[#87366](https://github.com/ClickHouse/ClickHouse/pull/87366) ([Jianfei Hu](https://github.com/incfly))。
* Distributed execution: ファイル単位ではなく、行グループ ID 単位でタスクをより適切に分割します。[#87508](https://github.com/ClickHouse/ClickHouse/pull/87508) ([scanhex12](https://github.com/scanhex12))。
* コードを簡素化し、[選択アルゴリズム](https://clickhouse.com/blog/lz4-compression-in-clickhouse#how-to-choose-the-best-algorithm)を調整することで、LZ4 の展開速度を向上させました。[#88360](https://github.com/ClickHouse/ClickHouse/pull/88360) ([Raúl Marín](https://github.com/Algunenano))。
* S3 はキー名のプレフィックスに基づいてオブジェクトを内部的にパーティション分割し、各パーティションの高いリクエストレートにも自動的にスケールします。この変更では、2 つの新しい BACKUP 設定 data&#95;file&#95;name&#95;generator と data&#95;file&#95;name&#95;prefix&#95;length が導入されます。data&#95;file&#95;name&#95;generator=checksum の場合、バックアップデータファイルは内容のハッシュを使って命名されます。例: checksum = `abcd1234ef567890abcd1234ef567890` かつ `data_file_name_prefix_length = 3` の場合、生成されるパスは `abc/d1234ef567890abcd1234ef567890` になります。このキー分布により、S3 パーティション間の負荷分散が向上し、スロットリングのリスクが低減されます。[#88418](https://github.com/ClickHouse/ClickHouse/pull/88418) ([Julia Kartseva](https://github.com/jkartseva))。
* JOIN および ARRAY JOIN で lazy columns の複製を実装しました。一部の出力フォーマットで、Sparse や Replicated などの特殊なカラム表現を通常のカラムに変換しないようにします。これにより、メモリ内での不要なデータコピーを回避します。[#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar))。
* Dictionary ブロックをキャッシュし、トークンのルックアップに二分探索ではなくハッシュテーブルを使用することで、テキスト索引の性能を向上させました。[#88786](https://github.com/ClickHouse/ClickHouse/pull/88786) ([Elmi Ahmadov](https://github.com/ahmadov))。
* Parquet リーダー v3 がデフォルトで有効になりました。[#88827](https://github.com/ClickHouse/ClickHouse/pull/88827) ([Michael Kolupaev](https://github.com/al13n321))。
* クエリで optimize&#95;read&#95;in&#95;order と query&#95;plan&#95;optimize&#95;lazy&#95;materialization を同時に活用できるようになりました。[#88767](https://github.com/ClickHouse/ClickHouse/issues/88767) を解決しました。[#88866](https://github.com/ClickHouse/ClickHouse/pull/88866) ([Manuel](https://github.com/raimannma))。
* `DISTINCT` を含むクエリで集約プロジェクションを使用するようにしました。[#86925](https://github.com/ClickHouse/ClickHouse/issues/86925) をクローズします。[#88894](https://github.com/ClickHouse/ClickHouse/pull/88894) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* posting lists はデータサイズの大部分を占めるため、これらをキャッシュすることで連続実行時のパフォーマンスが向上します。[#88912](https://github.com/ClickHouse/ClickHouse/pull/88912) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 入力のソート順が LIMIT BY キーと一致する場合に、streaming LIMIT BY transform を実行するようにしました。[#88969](https://github.com/ClickHouse/ClickHouse/pull/88969) ([Eduard Karacharov](https://github.com/korowa)).
* サーバー以外のバイナリでは、デフォルトで ThreadFuzzer を無効にしました。[#89115](https://github.com/ClickHouse/ClickHouse/pull/89115) ([Raúl Marín](https://github.com/Algunenano)).
* 一部のケースで、ANY LEFT JOIN または ANY RIGHT JOIN を ALL INNER JOIN に書き換えられるようにしました。[#89403](https://github.com/ClickHouse/ClickHouse/pull/89403) ([Dmitry Novik](https://github.com/novikd)).
* 非同期ログ記録時の各エントリあたりのアトミック操作を削減しました。[#89651](https://github.com/ClickHouse/ClickHouse/pull/89651) ([Sergei Trifonov](https://github.com/serxa)).
* 複数の join を含むクエリでランタイムフィルタが有効な場合、複数のランタイムフィルタが追加されると、新たに追加されたフィルタステップを他の BuildRuntimeFilterStep より前にプッシュダウンする必要があります。[#89725](https://github.com/ClickHouse/ClickHouse/pull/89725) ([Alexander Gololobov](https://github.com/davenger)).
* HashSetTable::merge のオーバーヘッドを削減することで、一部の countDistinct 操作をわずかに高速化しました。[#89727](https://github.com/ClickHouse/ClickHouse/pull/89727) ([Raúl Marín](https://github.com/Algunenano)).
* RIGHT JOIN と FULL JOIN で ConcurrentHashJoin を使用するようになりました。これにより、これらの join 型はより高い並列度で実行されます。RIGHT JOIN と FULL JOIN のさまざまなケースで、最大 2 倍改善します。[#78027](https://github.com/ClickHouse/ClickHouse/issues/78027) を解決します。[#89737](https://github.com/ClickHouse/ClickHouse/pull/89737) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 遅延マテリアライゼーションの行数上限を 10 から 100 に引き上げました。[#89772](https://github.com/ClickHouse/ClickHouse/pull/89772) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
