<div id="improvement">
  #### 改善
</div>

* [#104736](https://github.com/ClickHouse/ClickHouse/issues/104736)でバックポート: apply&#95;row&#95;policy&#95;after&#95;final または apply&#95;prewhere&#95;after&#95;final が有効な場合、行ポリシーおよび PREWHERE 内の複合 AND 条件を分解し、主キー索引解析のためにソートキーに関する単純条件を抽出できるようになりました。従来は、遅延フィルターにソートキーの述語と非ソートキーの述語が混在している場合 (例: x &gt; 1 AND y != &#39;foo&#39;) 、式全体が索引解析から除外されていました。これにより、ネストした AND 式からでも、ソートキーに関する単純条件 (x &gt; 1 など) を抽出してグラニュールの枝刈りに利用できるようになりました。 [#98513](https://github.com/ClickHouse/ClickHouse/pull/98513) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* [#104933](https://github.com/ClickHouse/ClickHouse/issues/104933)でバックポート: 行ポリシーがソートキーカラムのみに依存し、かつ決定論的である場合、その行ポリシーの `FINAL` 後への遅延適用をスキップし、その結果として行ポリシーが強制していた対応する `PREWHERE` の遅延もスキップするようになりました。 [#102884](https://github.com/ClickHouse/ClickHouse/pull/102884) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* [#104323](https://github.com/ClickHouse/ClickHouse/issues/104323)でバックポート: APPEND モードの Replicated リフレッシャブルmaterialized view で、リフレッシュ中に ZooKeeper との接続が一時的に失われても、リフレッシュが 2 回実行されることはなくなりました。 [#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)).
* [#104700](https://github.com/ClickHouse/ClickHouse/issues/104700)でバックポート: 大規模な非ASCIIデータセットの処理時 (たとえばテキスト索引のビルド中) に、累積された出力バッファが 2 GiB を超えると発生していた &#96;lowerUTF8&#96; / &#96;upperUTF8&#96; の例外を修正し、過度に長い単一行は明確なエラーで拒否するようにしました。 [#104229](https://github.com/ClickHouse/ClickHouse/pull/104229) ([Shaohua Wang](https://github.com/tiandiwonder)).

* [#104799](https://github.com/ClickHouse/ClickHouse/issues/104799)でバックポート: キー argument が `Nullable` の場合に `dictGetOrDefault` で発生する null pointer dereference を修正しました。[#98460](https://github.com/ClickHouse/ClickHouse/pull/98460) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [#104346](https://github.com/ClickHouse/ClickHouse/issues/104346)でバックポート: JIT expression compilation における 2 つのバグを修正しました。`nativeCast` の type checking における copy-paste error により integer-to-integer と float-to-float の cast 分岐に到達できなくなっていた問題と、LLVM `PassBuilder` に誤って `nullptr` の TargetMachine が渡され、ターゲット固有の optimization passes が登録されなかった問題です。[#98660](https://github.com/ClickHouse/ClickHouse/pull/98660) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [#104962](https://github.com/ClickHouse/ClickHouse/issues/104962)でバックポート: `DataLakeCatalog` が `auth_header` 設定の検証時に server の `http_forbid_headers` configuration を考慮するようになりました。[#98827](https://github.com/ClickHouse/ClickHouse/pull/98827) ([Michael Anastasakis](https://github.com/michael-anastasakis)).
* [#104469](https://github.com/ClickHouse/ClickHouse/issues/104469)でバックポート: `IN (subquery)` を含む filter が query optimizer によって PREWHERE に移動された際に発生する &quot;Not-ready Set&quot; 例外を修正しました。[#100375](https://github.com/ClickHouse/ClickHouse/pull/100375) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* [#104404](https://github.com/ClickHouse/ClickHouse/issues/104404) でバックポート: join の並べ替えにより、INNER JOIN のフィルタ (outer join の保持される側だけを参照するもの) が outer join の ON 句に押し込まれ、不正なクエリ結果が発生する問題を修正しました。[#101504](https://github.com/ClickHouse/ClickHouse/pull/101504) ([Vladimir Cherkasov](https://github.com/vdimir)).
