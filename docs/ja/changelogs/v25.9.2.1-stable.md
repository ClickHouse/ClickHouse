  ### ClickHouse リリース v25.9.2.1-stable (c2a9511f7bc) FIXME v25.9.1.1-new (524fe1daa94) と比較

<div id="backward-incompatible-change">
  #### 後方互換性を持たない変更
</div>

* IPv4/IPv6 に対する無意味な二項演算を無効化: IPv4/IPv6 と非整数型の加算 / 減算を無効にしました。従来は浮動小数点型との演算は許可されていましたが、その他の一部の型 (DateTime など) では論理エラーが発生していました。 [#86336](https://github.com/ClickHouse/ClickHouse/pull/86336) ([Raúl Marín](https://github.com/Algunenano)).
* 設定 `allow_dynamic_metadata_for_data_lakes` を非推奨にしました。これにより、すべての Iceberg テーブルは各クエリの実行前にストレージから最新のテーブルスキーマを取得するようになりました。 [#86366](https://github.com/ClickHouse/ClickHouse/pull/86366) ([Daniil Ivanik](https://github.com/divanik)).
* 転置テキスト索引は、RAM に収まらないデータセットにも対応できるよう、ゼロから再設計されました。 [#86485](https://github.com/ClickHouse/ClickHouse/pull/86485) ([Anton Popov](https://github.com/CurtizJ)).

<div id="new-feature">
  #### 新機能
</div>

* テーブルエンジン Alias をサポート。 [#76569](https://github.com/ClickHouse/ClickHouse/pull/76569) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* ある配列から別の配列を集合として差し引く関数 `arrayExcept` を追加。 [#82368](https://github.com/ClickHouse/ClickHouse/pull/82368) ([Joanna Hulboj](https://github.com/jh0x)).
* database レプリカに関する情報を含む新しいシステムテーブル `database_replicas` を追加。 [#83408](https://github.com/ClickHouse/ClickHouse/pull/83408) ([Konstantin Morozov](https://github.com/k-morozov)).
* ユーザーは、NATS エンジン向けの新しい設定 `nats_stream` と `nats_consumer` を指定することで、NATS JetStream を使ってメッセージをコンシュームできるようになりました。 [#84799](https://github.com/ClickHouse/ClickHouse/pull/84799) ([Dmitry Novikov](https://github.com/dmitry-sles-novikov)).
* 新しい `system.aggregated_zookeeper_log` テーブルを追加。このテーブルには、session id、親 path、操作 type ごとにグループ化された ZooKeeper 操作の統計情報 (例: 操作回数、平均 latency、エラー) が含まれ、定期的にディスクへフラッシュされます。 [#85102](https://github.com/ClickHouse/ClickHouse/pull/85102) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 文字列に ASCII 文字のみが含まれているかを確認する `isValidASCII` 関数を追加。Close [#85377](https://github.com/ClickHouse/ClickHouse/issues/85377)。 [#85786](https://github.com/ClickHouse/ClickHouse/pull/85786) ([rajat mohan](https://github.com/rajatmohan22)).
* クエリ設定内で単独の setting 名を `1` と同等に扱うようにしました (例: `SELECT ... SETTINGS use_query_cache` は `use_query_cache = 1` と等価) 。 [#85800](https://github.com/ClickHouse/ClickHouse/pull/85800) ([thraeka](https://github.com/thraeka)).
* 新しい設定オプション: `logger.startupLevel` と `logger.shutdownLevel` により、それぞれ ClickHouse の起動時と停止時の log level を上書きできます。 [#85967](https://github.com/ClickHouse/ClickHouse/pull/85967) ([Lennard Eijsackers](https://github.com/Blokje5)).
* 集約関数 `timeSeriesChangesToGrid` と `timeSeriesResetsToGrid`。`timeSeriesRateToGrid` と同様の動作をし、開始 timestamp、終了 timestamp、step、look back window の parameter と、timestamps および values に対する 2 つの arguments を受け取りますが、各 window で必要なサンプル数は 2 ではなく少なくとも 1 です。parameter で定義された time grid 内の各 timestamp について、指定した window 内でサンプル値が変化または減少した回数を数える PromQL の `changes`/`resets` を計算します。return type は Array(Nullable(Float64)) です。 [#86010](https://github.com/ClickHouse/ClickHouse/pull/86010) ([Stephen Chi](https://github.com/stephchi0)).
* Iceberg テーブルエンジンでの `ALTER UPDATE`。 [#86059](https://github.com/ClickHouse/ClickHouse/pull/86059) ([scanhex12](https://github.com/scanhex12)).
* SELECT ステートメント中に Iceberg metadata files を取得するためのシステムテーブル `iceberg_metadata_log` を追加。 [#86152](https://github.com/ClickHouse/ClickHouse/pull/86152) ([scanhex12](https://github.com/scanhex12)).
* 一時テーブルと同じ構文で temporary view を作成できるようになりました。 [#86432](https://github.com/ClickHouse/ClickHouse/pull/86432) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* ディスク設定に対応した Iceberg および Delta Lake テーブル。これにより、既存のディスクを使用する user tables を指定できます。Iceberg で使用する特定の disks を許可する設定 `allowed_disks_for_table_engines` を追加。例: `CREATE TABLE test ENGINE = Iceberg('path/inside/disk') SETTING datalake_disk_name = '<some_user_disk>';` ### ユーザー向け変更の documentation エントリ。 [#86778](https://github.com/ClickHouse/ClickHouse/pull/86778) ([scanhex12](https://github.com/scanhex12)).
* `system.warnings` テーブルに CPU とメモリに関する警告を追加しました。[#86838](https://github.com/ClickHouse/ClickHouse/pull/86838) ([Bharat Nallan](https://github.com/bharatnc)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* `func(primary_column) = 'xx'` や `column in (xxx)` のような条件に対する PREWHERE optimization を改善しました。[#85529](https://github.com/ClickHouse/ClickHouse/pull/85529) ([李扬](https://github.com/taiyang-li)).
* JOIN の書き換えを実装しました。1. 一致行または非一致行に対してフィルタ条件が常に false となる場合、`LEFT ANY JOIN` および `RIGHT ANY JOIN` を `SEMI`/`ANTI` JOIN に変換します。この最適化は、新しい設定 `query_plan_convert_any_join_to_semi_or_anti_join` で制御されます。2. 片側の非一致行に対してフィルタ条件が常に false となる場合、`FULL ALL JOIN` を `LEFT ALL JOIN` または `RIGHT ALL JOIN` に変換します。[#86028](https://github.com/ClickHouse/ClickHouse/pull/86028) ([Dmitry Novik](https://github.com/novikd)).
* 論理削除の実行後の vertical merge のパフォーマンスを改善しました。[#86169](https://github.com/ClickHouse/ClickHouse/pull/86169) ([Anton Popov](https://github.com/CurtizJ)).
* `LEFT/RIGHT` join に非一致の行が多数ある場合の `HashJoin` のパフォーマンスをわずかに改善しました。[#86312](https://github.com/ClickHouse/ClickHouse/pull/86312) ([Nikita Taranov](https://github.com/nickitat)).
* RadixSort: compiler が SIMD を利用しやすくし、CPU がより効果的に prefetch できるようにしました。Intel CPU でのみ software prefetching を使用するため、dynamic dispatch を利用します。これは、@taiyang-li による [https://github.com/ClickHouse/ClickHouse/pull/77029](https://github.com/ClickHouse/ClickHouse/pull/77029) の作業を継続するものです。[#86378](https://github.com/ClickHouse/ClickHouse/pull/86378) ([Raúl Marín](https://github.com/Algunenano)).
* Join の並べ替えで statistics を使用するようになりました。この機能は、`allow_statistics_optimize = 1` および `query_plan_optimize_join_order_limit = 10` を設定することで有効にできます。[#86822](https://github.com/ClickHouse/ClickHouse/pull/86822) ([Han Fei](https://github.com/hanfei1991)).
* table 内に多数のパーツがある場合の高速クエリのパフォーマンスを改善しました (`deque` ではなく `devector` を使用して `MarkRanges` を最適化) 。[#86933](https://github.com/ClickHouse/ClickHouse/pull/86933) ([Azat Khuzhin](https://github.com/azat)).
* join モードでパッチパートを適用する際のパフォーマンスを改善しました。[#87094](https://github.com/ClickHouse/ClickHouse/pull/87094) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### 改善
</div>

* Azure blob storage 上の Unity Catalog をサポートしました。 [#80013](https://github.com/ClickHouse/ClickHouse/pull/80013) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* パフォーマンス向上のために JOIN を自動で並べ替える、Experimental な JOIN 順序最適化を追加しました (`query_plan_optimize_join_order_limit` 設定で制御) 。この JOIN 順序最適化は現時点では STATISTICS のサポートが限定的で、主にストレージエンジンによる行数推定に依存している点に注意してください。より高度な STATISTICS の収集機能やカーディナリティ推定は、今後のリリースで追加される予定です。**アップグレード後に JOIN クエリで問題が発生した場合**は、`SET query_plan_use_new_logical_join_step = 0` を設定して新しい実装を一時的に無効化し、調査のために issue を報告してください。**USING clause からの Identifier 解決に関する注意**: `OUTER JOIN ... USING` clause における併合済みカラムの解決方法を、より一貫したものに変更しました。以前は、OUTER JOIN で USING カラムと修飾付きカラム (`a, t1.a, t2.a`) の両方を選択した場合、USING カラムが誤って `t1.a` に解決され、左側に一致がない右テーブルの行では 0/NULL が表示されていました。現在は、USING clause の Identifier は常に併合済みカラムに解決され、修飾付き Identifier は、クエリ内に他の Identifier が存在するかどうかにかかわらず、常に未併合のカラムに解決されます。例: &#96;&#96;&#96;sql SELECT a, t1.a, t2.a FROM (SELECT 1 as a WHERE 0) t1 FULL JOIN (SELECT 2 as a) t2 USING (a) -- 変更前: a=0, t1.a=0, t2.a=2 (誤り - &#39;a&#39; は t1.a に解決されていた)  -- 変更後: a=2, t1.a=0, t2.a=2 (正しい - &#39;a&#39; は併合される) 。 [#80848](https://github.com/ClickHouse/ClickHouse/pull/80848) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 読み取り時にスキップ索引を使って data parts をフィルタリングし、不要な索引読み取りを減らせるようにしました。これは新しい設定 `use_skip_indexes_on_data_read` で制御されます (デフォルトでは無効) 。これにより [#75774](https://github.com/ClickHouse/ClickHouse/issues/75774) に対応します。これには [#81021](https://github.com/ClickHouse/ClickHouse/issues/81021) と共通する基盤整備も一部含まれています。 [#81526](https://github.com/ClickHouse/ClickHouse/pull/81526) ([Amos Bird](https://github.com/amosbird)).
* S3 の再試行戦略を設定可能にし、config XML ファイルを変更した際に S3 disk の設定をホットリロードできるようにしました。 [#82642](https://github.com/ClickHouse/ClickHouse/pull/82642) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* oneof の一部が存在することを示すために、特別なカラムを使用できるようになりました。 [#82885](https://github.com/ClickHouse/ClickHouse/pull/82885) ([Ilya Golshtein](https://github.com/ilejn)).
* 新しい Kafka table engine に対して誤った設定が指定された場合に、ユーザーにより明確な案内を表示するようにしました。 [#83701](https://github.com/ClickHouse/ClickHouse/pull/83701) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Time 型に time zones を指定できなくなりました。 [#84689](https://github.com/ClickHouse/ClickHouse/pull/84689) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* `best_effort` フォーマットで Time[64] をパースするロジックを簡素化し、あわせていくつかのバグも回避しました。 [#84730](https://github.com/ClickHouse/ClickHouse/pull/84730) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* materialized view の作成時に、`TO` の後でクエリパラメータを使用できるようになりました。例: `CREATE MATERIALIZED VIEW mv TO {to_table:Identifier} AS SELECT * FROM src_table`。 [#84899](https://github.com/ClickHouse/ClickHouse/pull/84899) ([Diskein](https://github.com/Diskein)).
* jemalloc を新しいバージョンに更新しました。jemalloc の内部ツールに基づく割り当てプロファイリングを改善しました。グローバルな jemalloc プロファイラは、config `jemalloc_enable_global_profiler` で有効化できるようになりました。サンプリングされたグローバルな割り当てと解放は、config `jemalloc_collect_global_profile_samples_in_trace_log` を有効にすることで、`JemallocSample` 型として `system.trace_log` に保存できます。jemalloc profiling は、setting `jemalloc_enable_profiler` を使って各クエリごとに個別に有効化できるようになりました。`system.trace_log` への samples の保存は、setting `jemalloc_collect_profile_samples_in_trace_log` を使ってクエリ単位で制御できます。 [#85438](https://github.com/ClickHouse/ClickHouse/pull/85438) ([Antonio Andelic](https://github.com/antonio2368)).
* deltaLakeAzureCluster 関数 (クラスター向けの deltaLakeAzure に相当) と deltaLakeS3Cluster 関数 (deltaLakeCluster のエイリアス) を追加しました。[#85358](https://github.com/ClickHouse/ClickHouse/issues/85358) を解決します。 [#85547](https://github.com/ClickHouse/ClickHouse/pull/85547) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Backup の場合と同様に、通常の copy 操作にも setting `azure_max_single_part_copy_size` を適用するようにしました。 [#85767](https://github.com/ClickHouse/ClickHouse/pull/85767) ([Ilya Golshtein](https://github.com/ilejn)).
* S3 object storage において、retryable errors 発生時に S3 クライアント threads の速度を抑えるようにしました。これにより、従来の setting `backup_slow_all_threads_after_retryable_s3_error` を S3 disk にも拡張し、より汎用的な `s3_slow_all_threads_after_retryable_error` に名称変更しました。 [#85918](https://github.com/ClickHouse/ClickHouse/pull/85918) ([Julia Kartseva](https://github.com/jkartseva)).
* settings `allow_experimental_variant/dynamic/json` および `enable_variant/dynamic/json` を廃止されたものとしてマークしました。これにより、3 つの types はすべて無条件で有効になります。 [#85934](https://github.com/ClickHouse/ClickHouse/pull/85934) ([Pavel Kruglov](https://github.com/Avogar)).
* S3(Azure)Queue table engine を改善し、重複が発生する可能性なく ZooKeeper connection の切断を乗り越えられるようにしました。S3Queue setting `use_persistent_processing_nodes` の有効化が必要です (`ALTER TABLE MODIFY SETTING` で変更可能) 。 [#85995](https://github.com/ClickHouse/ClickHouse/pull/85995) ([Kseniia Sumarokova](https://github.com/kssenii)).
* setting `query_condition_cache_selectivity_threshold` (デフォルト値: 1.0) を追加しました。これにより、選択性の低い predicates のスキャン結果は query condition cache への insert 対象から除外されます。その結果、cache ヒット率は低下するものの、query condition cache のメモリ消費を削減できます。 [#86076](https://github.com/ClickHouse/ClickHouse/pull/86076) ([zhongyuankai](https://github.com/zhongyuankai)).
* `http_handlers` において、完全な URL 文字列 (schema および host:port を含む `full_url` directive) による filtering をサポートしました。 [#86155](https://github.com/ClickHouse/ClickHouse/pull/86155) ([Azat Khuzhin](https://github.com/azat)).
* Delta Lake 書き込み機能に、デフォルトで無効な experimental setting `allow_experimental_delta_lake_writes` を追加しました。 [#86180](https://github.com/ClickHouse/ClickHouse/pull/86180) ([Kseniia Sumarokova](https://github.com/kssenii)).
* init.d script における systemd の検出を修正しました (&quot;Install packages&quot; チェックの修正) 。 [#86187](https://github.com/ClickHouse/ClickHouse/pull/86187) ([Azat Khuzhin](https://github.com/azat)).
* 新しい次元付き metric `startup_scripts_failure_reason` を追加しました。この metric は、startup scripts の失敗につながる異なる error 種別を区別するために必要です。特に alerting の目的では、一時的なエラー (たとえば `MEMORY_LIMIT_EXCEEDED` や `KEEPER_EXCEPTION`) と一時的でないエラーを区別する必要があります。 [#86202](https://github.com/ClickHouse/ClickHouse/pull/86202) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Iceberg 書き込みで複数の data files をサポートしました。 [#86275](https://github.com/ClickHouse/ClickHouse/pull/86275) ([scanhex12](https://github.com/scanhex12)).
* Iceberg の書き込みで、より多くのパーティション型をサポートしました。これにより [#86206](https://github.com/ClickHouse/ClickHouse/issues/86206) をクローズしました。[#86298](https://github.com/ClickHouse/ClickHouse/pull/86298) ([scanhex12](https://github.com/scanhex12)).
* Iceberg table のパーティションで `identity()` 関数を省略できるようにしました。[#86314](https://github.com/ClickHouse/ClickHouse/pull/86314) ([scanhex12](https://github.com/scanhex12)).
* 特定のチャネルに対してのみ JSON ログを有効化できるようにしました。そのためには、`logger.formatting.channel` を `syslog`/`console`/`errorlog`/`log` のいずれかに設定します。[#86331](https://github.com/ClickHouse/ClickHouse/pull/86331) ([Azat Khuzhin](https://github.com/azat)).
* Delta Lake で挿入される data files に対して、行数/バイト数の上限を追加しました。これは設定 `delta_lake_insert_max_rows_in_data_file` および `delta_lake_insert_max_bytes_in_data_file` で制御されます。[#86357](https://github.com/ClickHouse/ClickHouse/pull/86357) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `WHERE` 句でネイティブな数値を使用できるようにしました。これらはすでに論理関数の引数としては使用可能です。これにより、filter-push-down と PREWHERE への移動最適化が簡単になります。[#86390](https://github.com/ClickHouse/ClickHouse/pull/86390) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* メタデータが破損したカタログに対して `SYSTEM DROP REPLICA` を実行した場合に発生するエラーを修正しました。[#86391](https://github.com/ClickHouse/ClickHouse/pull/86391) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Azure ではアクセスの Provisioning にかなり時間がかかる場合があるため、ディスクアクセスチェック (`skip_access_check=0`) に追加の再試行を加えました。[#86419](https://github.com/ClickHouse/ClickHouse/pull/86419) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 設定 `evaluation_time` を `promql_evaluation_time` にリネームしました。[#86459](https://github.com/ClickHouse/ClickHouse/pull/86459) ([Vitaly Baranov](https://github.com/vitlibar)).
* Iceberg の drop 時にファイルを削除するための設定を追加しました。これにより [#86211](https://github.com/ClickHouse/ClickHouse/issues/86211) をクローズしました。[#86501](https://github.com/ClickHouse/ClickHouse/pull/86501) ([scanhex12](https://github.com/scanhex12)).
* Iceberg の書き込み時のメモリ使用量を削減しました。[#86544](https://github.com/ClickHouse/ClickHouse/pull/86544) ([scanhex12](https://github.com/scanhex12)).
* `today()` 関数を大文字小文字を区別しないようにし、`NOW()` などの他の日付/時刻関連関数との一貫性を持たせました。[#86561](https://github.com/ClickHouse/ClickHouse/pull/86561) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* `timeSeries*()` 関数の staleness window を左開右閉にしました。[#86588](https://github.com/ClickHouse/ClickHouse/pull/86588) ([Vitaly Baranov](https://github.com/vitlibar)).
* `FailedInternal*Query` profile events を追加しました。[#86627](https://github.com/ClickHouse/ClickHouse/pull/86627) ([Shane Andrade](https://github.com/mauidude)).
* 設定ファイル経由で追加された、名前にドットを含むユーザーの処理を修正しました。[#86633](https://github.com/ClickHouse/ClickHouse/pull/86633) ([Mikhail Koviazin](https://github.com/mkmkme)).
* クエリのメモリ使用量に関する非同期メトリクス (`QueriesMemoryUsage` および `QueriesPeakMemoryUsage`) を追加しました。[#86669](https://github.com/ClickHouse/ClickHouse/pull/86669) ([Azat Khuzhin](https://github.com/azat)).
* QPS やその他の一定間隔ごとのメトリクスをより正確に報告するために、`clickhouse-benchmark --precise` フラグを使用できるようになりました。これは、クエリの実行時間がレポート間隔 `--delay D` に近い場合でも、一貫した QPS を得るのに役立ちます。[#86684](https://github.com/ClickHouse/ClickHouse/pull/86684) ([Sergei Trifonov](https://github.com/serxa)).
* Linux スレッドの nice 値を設定可能にし、一部のスレッド (merge/mutate、query、materialized view、ZooKeeper client) に高いまたは低い優先度を割り当てられるようにしました。[#86703](https://github.com/ClickHouse/ClickHouse/pull/86703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
