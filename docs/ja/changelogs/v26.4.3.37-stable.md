<div id="new-feature">
  #### 新機能
</div>

* [#104390](https://github.com/ClickHouse/ClickHouse/issues/104390)でバックポート: リフレッシャブルmaterialized view用に `SYSTEM PAUSE VIEW [db.]name` および `SYSTEM PAUSE VIEWS` クエリを追加しました。`SYSTEM STOP VIEW` とは異なり、`SYSTEM PAUSE VIEW` は現在実行中のリフレッシュを中断しません。進行中のリフレッシュは完了まで継続され、以降のリフレッシュのみが防止されます。この状態は `SYSTEM START VIEW` または `SYSTEM START VIEWS` で解除され、これらは停止状態と一時停止状態の両方を同様にクリアするようになりました。[#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### パフォーマンス改善
</div>

* [#104423](https://github.com/ClickHouse/ClickHouse/issues/104423)でバックポート: クエリごとの `AsyncReadCounters` をロックレス化することで、非同期リモートFS読み取りパスでのロック競合を軽減しました。[#104374](https://github.com/ClickHouse/ClickHouse/pull/104374) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="improvement">
  #### 改善
</div>

* [#104036](https://github.com/ClickHouse/ClickHouse/issues/104036) でバックポート: 行ポリシーがソートキーのカラムのみに依存し、かつ決定論的な場合、`FINAL` 後への行ポリシーの遅延を行わないようにし、その際に行ポリシーによって強制されていた対応する `PREWHERE` の遅延もスキップするようにしました。 [#102884](https://github.com/ClickHouse/ClickHouse/pull/102884) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* [#104386](https://github.com/ClickHouse/ClickHouse/issues/104386) でバックポート: リフレッシャブルmaterialized view が継続的にリフレッシュされている場合のバックアップの耐障害性を、グローバルな状態ではなく、スナップショット取得時点のテーブル状態に基づいて判断することで改善しました。 [#103384](https://github.com/ClickHouse/ClickHouse/pull/103384) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* [#104596](https://github.com/ClickHouse/ClickHouse/issues/104596) でバックポート: APPEND モードの Replicated リフレッシャブルmaterialized view は、リフレッシュ中に ZooKeeper への接続が一時的に失われた場合でも、二重にリフレッシュされなくなりました。 [#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)).
* [#104704](https://github.com/ClickHouse/ClickHouse/issues/104704) でバックポート: 大きな非 ASCII データセット (たとえばテキスト索引のビルド時) の処理中に、累積された出力バッファが 2 GiB を超えることで発生していた &#96;lowerUTF8&#96; / &#96;upperUTF8&#96; の例外を修正し、過度に長い単一行は明確なエラーで拒否するようにしました。 [#104229](https://github.com/ClickHouse/ClickHouse/pull/104229) ([Shaohua Wang](https://github.com/tiandiwonder)).
* [#105026](https://github.com/ClickHouse/ClickHouse/issues/105026) でバックポート: 新しい設定 `defer_partition_pruning_after_final` (デフォルトは `1`) により、26.3 で導入された `FINAL` 配下でパーティションプルーニングをスキップする動作をオプトアウト可能にしました。これを `0` に設定すると、26.3 より前のパーティションプルーニング動作に戻ります。これは、同じ PK の行がパーティションをまたがらないイベントログのワークロードで大幅な高速化につながります。`compatibility = '26.2'` を設定すると、自動的に `0` に切り替わります。 [#104705](https://github.com/ClickHouse/ClickHouse/pull/104705) ([Nikita Fomichev](https://github.com/fm4v)).

* [#105065](https://github.com/ClickHouse/ClickHouse/issues/105065) でバックポート: フィルターが左側のカラムに依存している場合に、未準備の Set が渡されるケースを CI で発見し、これを修正しました。[#102966](https://github.com/ClickHouse/ClickHouse/issues/102966) をクローズします。[#103029](https://github.com/ClickHouse/ClickHouse/pull/103029) ([Yarik Briukhovetskyi](https://github.com/yariks5s))。
* [#105174](https://github.com/ClickHouse/ClickHouse/issues/105174) でバックポート: `processInsertQuery` の最後で `sendProgress` を無条件に実行していたことが原因で、古いクライアントが `remote()` または分散テーブル経由で新しいサーバーに insert する際に `UNEXPECTED_PACKET_FROM_SERVER` で失敗する、後方互換性の破壊を修正しました。[#103148](https://github.com/ClickHouse/ClickHouse/pull/103148) ([Sema Checherinda](https://github.com/CheSema))。

* [#104743](https://github.com/ClickHouse/ClickHouse/issues/104743) でバックポート: `Variant` 型への `JSONExtract` で、JSON の小数値が暗黙に切り捨てられていた不具合を修正しました。従来は、`JSONExtract('{"x": 3.14}', 'x', 'Variant(Int64, Float64)')` は `Int64=3` を返し、`JSONExtract('{"x": 3.14}', 'x', 'Variant(String, Int64)')` も `Int64=3` を返しており、小数部が失われていました。現在は小数値が損失なく保持されます。`Float64`/`Decimal` のメンバーが存在する場合はそれが使われ、そうでない場合は `String` メンバーが元の JSON を保持します。整数メンバーのみを含む `Variant` 型 (例: `Variant(Int64, Int32)`) と、整数への直接抽出 (`JSONExtract(json, 'Int64')`、`JSONExtractInt` など) の動作は変わりません。[#103620](https://github.com/ClickHouse/ClickHouse/pull/103620) ([Groene AI](https://github.com/groeneai)).
