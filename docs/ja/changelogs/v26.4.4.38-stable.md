* [#106046](https://github.com/ClickHouse/ClickHouse/issues/106046)でバックポート: 設定 `show_data_lake_catalogs_in_system_tables` は `show_remote_databases_in_system_tables` にリネームされ、対象範囲も拡大されました。値が 0 (デフォルト) の場合、データレイクのカタログに加えて、`MySQL` および `PostgreSQL` のデータベースも `system.tables`、`system.columns`、`system.completions` では非表示になります。古い設定名はエイリアスとして引き続き使用できます。[#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)) 。

* [#105242](https://github.com/ClickHouse/ClickHouse/issues/105242) でバックポート: `HTTPConnectionPool*TCP{Rcv,Snd}BufBytes_{p50,p75,p90,p95}` の async メトリクスを、`system.histogram_metrics` 内のバケットベースのヒストグラム `http_pool_tcp_buf_bytes` (ラベル `group`、`direction`) に置き換えました。グループごとの async メトリクスの合計は維持されます。 [#103704](https://github.com/ClickHouse/ClickHouse/pull/103704) ([Sema Checherinda](https://github.com/CheSema)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">

* [#105366](https://github.com/ClickHouse/ClickHouse/issues/105366) でバックポート: 右テーブルでキーごとに複数の行があり、サイズ制限によって出力ブロックが分割される場合に、RIGHT ANY JOIN が誤った結果を返す問題を修正しました。[#99431](https://github.com/ClickHouse/ClickHouse/issues/99431) をクローズ。[#102064](https://github.com/ClickHouse/ClickHouse/pull/102064) ([Vladimir Cherkasov](https://github.com/vdimir)).
* [#105358](https://github.com/ClickHouse/ClickHouse/issues/105358) でバックポート: Nested 型のデシリアライゼーション中に Avro リーダーでスタックオーバーフローをチェックするようにしました。[#102417](https://github.com/ClickHouse/ClickHouse/pull/102417) ([Pavel Kruglov](https://github.com/Avogar)).
* [#105512](https://github.com/ClickHouse/ClickHouse/issues/105512) でバックポート: クライアントから提供された Native フォーマットのデータが途中で切れている、または不正な形式である場合に、`LOGICAL_ERROR` ではなく `INCORRECT_DATA` をスローするようにしました。[#102975](https://github.com/ClickHouse/ClickHouse/pull/102975) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* [#105409](https://github.com/ClickHouse/ClickHouse/issues/105409) でバックポート: `StorageObjectStorageQueue` (`S3Queue`, `AzureQueue`) で、部分的に処理されたファイルをオブジェクトストレージから最後まで読み込むまでシャットダウンがブロックされる問題を修正しました。これにより、シャットダウン時にはソースがただちに読み取りを中止するようになりました。重複排除により、シャットダウン前にすでに宛先テーブルへストリーミングされていた行は、次回起動時にファイルが再試行されても重複しません。[#103126](https://github.com/ClickHouse/ClickHouse/pull/103126) ([Tuan Pham Anh](https://github.com/tuanpach)).
* [#105804](https://github.com/ClickHouse/ClickHouse/issues/105804) でバックポート: `INSERT INTO FUNCTION hdfs(...)` 経由で HDFS に Parquet (および ORC や Arrow などのトレーラーを持つ他のフォーマット) を書き込む際のデータ破損を修正しました。26.1 以降、`WriteBufferFromHDFS` は `finalize()` 時に作業バッファを flush していなかったため、各ファイルの末尾最大 `DBMS_DEFAULT_BUFFER_SIZE` バイトが黙って失われており、その中には Parquet の `PAR1` フッターも含まれていました。このようなファイルを読み込むと、`Not a Parquet file (wrong magic bytes at the end of file)` が返されていました。[#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* [#106284](https://github.com/ClickHouse/ClickHouse/issues/106284) でバックポート: deltaLakeAzure の resolve における URL エンコードされたパスの処理を修正しました。[#103525](https://github.com/ClickHouse/ClickHouse/pull/103525) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* [#105426](https://github.com/ClickHouse/ClickHouse/issues/105426) でバックポート: **`additional_table_filters`** を、**並列レプリカ** とアナライザを使用し、かつクエリプランのシリアライゼーションを行わない場合は無効化しました。**従来は、これにより誤った結果が生じる可能性がありました**。[#104296](https://github.com/ClickHouse/ClickHouse/pull/104296) ([Azat Khuzhin](https://github.com/azat)).
* [#106242](https://github.com/ClickHouse/ClickHouse/issues/106242) でバックポート: `ALTER TABLE ... DROP PARTITION ID 'patch-...'` の後に `DETACH`/`ATTACH TABLE` を行うと、壊れたパッチパートが生じる問題を修正しました。従来は、空のカバリングパートが `partition.dat` と `source_parts.dat` なしで書き込まれていたため、次回のアタッチまたはサーバー再起動後に `system.detached_parts` に `broken-on-start_patch-...` エントリが作成されていました。[#93132](https://github.com/ClickHouse/ClickHouse/issues/93132) をクローズ。[#102103](https://github.com/ClickHouse/ClickHouse/issues/102103) をクローズ。[#104353](https://github.com/ClickHouse/ClickHouse/pull/104353) ([Groene AI](https://github.com/groeneai)).
* [#105753](https://github.com/ClickHouse/ClickHouse/issues/105753)でバックポート: `LEFT ANTI JOIN` で、非一致の行に対して左側のキー値を重複して返すのではなく、右側の join キーカラムがデフォルト値で正しく返されるようになりました。以前は、`SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` が、非一致行に対して本来はデフォルト値 (`Int32` では `0`、`String` では `''`、`Nullable` では `NULL`) を返すべきところ、`r = a.x` を返すことがありました。影響を受けていたのは join キーカラムのみで、右側のキー以外のカラムは従来から正しくデフォルト値になっていました。オプティマイザが左右を入れ替えた場合には、同じ bug が `RIGHT ANTI JOIN` でも発生していました。[#99959](https://github.com/ClickHouse/ClickHouse/issues/99959) をクローズします。[#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* [#105665](https://github.com/ClickHouse/ClickHouse/issues/105665)でバックポート: `catalog_type = 'glue'` の `DataLakeCatalog` database からの長時間実行される `INSERT ... SELECT` やその他の読み取りで、テーブルメタデータの読み込み時に取得された STS session の credentials が有効期限を過ぎると、`Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)` により失敗する問題を修正しました。[#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* [#105979](https://github.com/ClickHouse/ClickHouse/issues/105979)でバックポート: `TYPE set(N)` スキップ索引を持つ `SELECT` で、WHERE atom の結果型が `Float`、`BFloat16`、またはその他の非整数型 (たとえば `WHERE c0 + 0.1` や `WHERE log(c0)`) の場合に、`BAD_ARGUMENTS` exception &quot;It&#39;s a bug! Only integer types are supported by `__bitWrapperFunc`&quot; が throw される問題を修正しました。この場合、スキップ索引は通常の filter パスにフォールバックするようになりました。[#105384](https://github.com/ClickHouse/ClickHouse/pull/105384) ([Groene AI](https://github.com/groeneai)).
