* [#106038](https://github.com/ClickHouse/ClickHouse/issues/106038) でバックポート: 設定 `show_data_lake_catalogs_in_system_tables` は `show_remote_databases_in_system_tables` にリネームされ、適用範囲も拡大されました。値が 0 (デフォルト) の場合、データレイクのカタログに加えて、`MySQL` および `PostgreSQL` のデータベースも `system.tables`、`system.columns`、`system.completions` で非表示になります。古い設定名はエイリアスとして引き続き使用できます。[#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)).

* [#105770](https://github.com/ClickHouse/ClickHouse/issues/105770) でバックポート: Keeper にさまざまな変更を加え、全体で約 2 倍高速化しました (バッチ処理の改善、リーダーへのメッセージのパイプライン化、ログ追記のパイプライン化) 。 [#101757](https://github.com/ClickHouse/ClickHouse/pull/101757) ([Michael Kolupaev](https://github.com/al13n321)).
* [#106585](https://github.com/ClickHouse/ClickHouse/issues/106585) でバックポート: 主キーカラムに対する `IN` サブクエリを含む `PREWHERE` で、グラニュールの絞り込みに主キー索引が使われず、関連するグラニュールだけを読む代わりにテーブル全体のスキャンが発生していた問題を修正しました。 [#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* [#106233](https://github.com/ClickHouse/ClickHouse/issues/106233) でバックポート: `KeeperMemoryStorage` を使用する ClickHouse Keeper で、受信したスナップショットの適用時のピークメモリ使用量を削減しました。 [#105851](https://github.com/ClickHouse/ClickHouse/pull/105851) ([Antonio Andelic](https://github.com/antonio2368)).
* [#106123](https://github.com/ClickHouse/ClickHouse/issues/106123) でバックポート: `NuRaft` の未コミットなログエントリの受け入れ制限と、append-entries の backward-probe スロットリング向けの Keeper `coordination_settings` を追加しました。 [#106108](https://github.com/ClickHouse/ClickHouse/pull/106108) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### バグ修正 (正式な安定版リリースにおけるユーザーに影響する不具合)
</div>

* [#105806](https://github.com/ClickHouse/ClickHouse/issues/105806)でバックポート: `INSERT INTO FUNCTION hdfs(...)` を介して HDFS に Parquet (および ORC や Arrow など、末尾にトレーラーを持つ他のフォーマット) を書き込む際に発生するデータ破損を修正しました。26.1 以降、`WriteBufferFromHDFS` が `finalize()` 時に作業用バッファを flush していなかったため、各ファイルの末尾最大 `DBMS_DEFAULT_BUFFER_SIZE` バイトが失われ、Parquet の `PAR1` フッターも含まれていました。このようなファイルを読み取ると、`Not a Parquet file (wrong magic bytes at the end of file)` が返されていました。[#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* [#105755](https://github.com/ClickHouse/ClickHouse/issues/105755)でバックポート: `LEFT ANTI JOIN` が、左側のキー値を複製するのではなく、一致しない行に対して右側の join key カラムをデフォルト値で正しく返すようになりました。以前は、`SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` が、本来デフォルト値 (`Int32` なら `0`、`String` なら `''`、`Nullable` なら `NULL`) を返すべき一致しない行で `r = a.x` を返すことがありました。影響を受けていたのは join key カラムのみで、キーではない右側カラムはすでに正しくデフォルト値になっていました。同じバグは、オプティマイザが左右を入れ替えた場合の `RIGHT ANTI JOIN` でも発生していました。[#99959](https://github.com/ClickHouse/ClickHouse/issues/99959) をクローズしました。[#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* [#105670](https://github.com/ClickHouse/ClickHouse/issues/105670)でバックポート: `catalog_type = 'glue'` を指定した `DataLakeCatalog` database からの長時間実行される `INSERT ... SELECT` やその他の読み取り処理が、テーブルのメタデータ読み込み時に取得した STS session credentials の有効期限が切れると、`Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)` を伴って失敗する問題を修正しました。[#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* [#105768](https://github.com/ClickHouse/ClickHouse/issues/105768)でバックポート: `ARRAY JOIN` と併用した場合に一部のケースで発生していた、負の `LIMIT BY` における論理エラーを修正しました。[#105403](https://github.com/ClickHouse/ClickHouse/pull/105403) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* [#105622](https://github.com/ClickHouse/ClickHouse/issues/105622)でバックポート: binary または string カラム内の破損した中間 offsets を含む Arrow または ArrowStream ファイルの読み取り時に発生する heap-buffer-overflow と、geo タグ付き Arrow カラムの読み取り時に発生する null ポインタ逆参照を修正しました。[#105449](https://github.com/ClickHouse/ClickHouse/pull/105449) ([Raúl Marín](https://github.com/Algunenano)).
* [#105884](https://github.com/ClickHouse/ClickHouse/issues/105884)でバックポート: デフォルト引数が `Nullable` expression で、`short_circuit_function_evaluation` が有効な状態で、見つかった辞書キーと見つからなかった辞書キーが混在している場合に、`dictGetOrDefault` が `CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN` を throw する問題を修正しました。[#105461](https://github.com/ClickHouse/ClickHouse/pull/105461) ([Raúl Marín](https://github.com/Algunenano)).
* [#106489](https://github.com/ClickHouse/ClickHouse/issues/106489)でバックポート: ALTER 後に compressed Memory table から Dynamic subcolumns を読み取る際に発生する SIGSEGV を修正しました。[#104901](https://github.com/ClickHouse/ClickHouse/issues/104901) をクローズしました。[#105464](https://github.com/ClickHouse/ClickHouse/pull/105464) ([Pavel Kruglov](https://github.com/Avogar)).
* [#105876](https://github.com/ClickHouse/ClickHouse/issues/105876) でバックポート: `GROUP BY ... WITH ROLLUP`、`WITH CUBE`、または `WITH TOTALS` を Nullable な引数とともに使用した際に、`uniqStateOrNull` / `uniqStateOrDefault` / `uniqOrNullState` (および `uniq` に対する同様の combinator chain) で発生するサーバーの segfault を修正しました。 [#105470](https://github.com/ClickHouse/ClickHouse/pull/105470) ([Groene AI](https://github.com/groeneai)).
* [#105973](https://github.com/ClickHouse/ClickHouse/issues/105973) でバックポート: JSON type の `singleValueOrNull` のデシリアライゼーションで発生する SEGFAULT を修正しました。[#103630](https://github.com/ClickHouse/ClickHouse/issues/103630) をクローズします。 [#105535](https://github.com/ClickHouse/ClickHouse/pull/105535) ([Pavel Kruglov](https://github.com/Avogar)).
* [#105724](https://github.com/ClickHouse/ClickHouse/issues/105724) でバックポート: select() の FD&#95;SETSIZE 制限に達したことによって replxx で発生する crash を修正しました (poll() に置換) 。SSH/ウェブターミナル が enabled の場合、サーバーが crash する可能性がある点に注意してください。 [#105559](https://github.com/ClickHouse/ClickHouse/pull/105559) ([Azat Khuzhin](https://github.com/azat)).
* [#106559](https://github.com/ClickHouse/ClickHouse/issues/106559) でバックポート: `CREATE TABLE ... TO INNER UUID '...' ...` で、ステートメントに `ENGINE` 句がない場合に発生する client crash を修正しました。これによりパーサーは、null pointer を逆参照する代わりに、適切な `BAD_ARGUMENTS` error を報告するようになりました。 [#105579](https://github.com/ClickHouse/ClickHouse/pull/105579) ([Groene AI](https://github.com/groeneai)).
* [#105731](https://github.com/ClickHouse/ClickHouse/issues/105731) でバックポート: Hive のパーティション値抽出が `cast_string_to_date_time_mode` setting を尊重するようになり、デフォルトで partition key 内の timezone 接尾辞付き ISO 8601 timestamp (例: `+0000`、`+00:00`、`Z`) を受け入れるようになりました。 [#105584](https://github.com/ClickHouse/ClickHouse/pull/105584) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [#105814](https://github.com/ClickHouse/ClickHouse/issues/105814) でバックポート: `use_query_condition_cache = 1` (default) のときに `SELECT` クエリで発生していた、件数が実際より少なく数えられる不具合を修正しました。bloom-filter スキップ索引を持つカラムに対して `PREWHERE pk_prefix = X WHERE non_pk IN (...)` という shape のクエリを実行すると、`pk_prefix = X` predicate に対する `QueryConditionCache` が汚染され、その後の無害な `SELECT count() ... WHERE pk_prefix = X` が誤って少ない件数を返していました。影響を受けるのは 26.x のすべての releases です。 [#104781](https://github.com/ClickHouse/ClickHouse/issues/104781). [#105686](https://github.com/ClickHouse/ClickHouse/pull/105686) ([Groene AI](https://github.com/groeneai)).

* [#106065](https://github.com/ClickHouse/ClickHouse/issues/106065) でバックポート: 新しいアナライザで、`IN Array(...)` filter を含む distributed queries で発生する `Cannot find column` error を修正しました。 [#105894](https://github.com/ClickHouse/ClickHouse/pull/105894) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* [#106551](https://github.com/ClickHouse/ClickHouse/issues/106551) でバックポート: `postgresql` table function、PostgreSQL table engine、または PostgreSQL ソースを持つ Dictionary 経由で PostgreSQL から読み込むクエリがキャンセルされ (たとえば KILL QUERY) 、さらにリモートの PostgreSQL クエリのキャンセルに失敗した場合に発生しうるサーバークラッシュを修正しました。[#105949](https://github.com/ClickHouse/ClickHouse/pull/105949) ([Rory Shanks](https://github.com/rorylshanks)).
