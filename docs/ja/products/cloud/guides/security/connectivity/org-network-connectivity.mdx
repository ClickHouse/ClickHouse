組織内の安全なネットワーク接続を利用すると、ある ClickHouse Cloud サービスから、同じ組織・同じリージョン内にある別のサービスに対して [`remoteSecure()`](/ja/reference/functions/table-functions/remote) でクエリを実行できます。トラフィックはパブリックインターネットを経由せず ClickHouse Cloud のプライベートネットワーク内で完結するため、読み取り元のサービスが [PrivateLink](/ja/products/cloud/guides/security/connectivity/private-networking/aws-privatelink) や [IP アクセスリスト](/ja/products/cloud/guides/security/connectivity/setting-ip-filters) で制限されている場合でも利用できます。

主に次のようなケースで利用します。

* サービスへのアクセスが PrivateLink または厳格な IP アクセスリストで制限されており、パブリックエンドポイント経由で `remoteSecure()` を使用できない場合
* セキュリティ要件上、サービス間のトラフィックをパブリックインターネット経由で送信することが認められていない場合
* サービス同士が [ウェアハウス](/ja/products/cloud/features/infrastructure/warehouses)(コンピュート間の分離)でデータを共有していないものの、サービスをまたいでクエリを実行する必要がある場合

<Note>
  この機能は現在プライベートプレビュー段階にあり、各接続は当社チームが設定します。ご参加を希望される場合は、ClickHouseのアカウント担当チームまたは [ClickHouse サポート](https://clickhouse.com/support/program) までお問い合わせください。
</Note>

## 仕組み {#how-it-works}

このガイドでは、次の2つの用語を使用します。

* **Producer**: 読み取り対象のテーブルを保持するサービス。
* **Consumer**: `remoteSecure()` を実行して Producer からデータを読み取るサービス。

ClickHouse Cloud は、Consumer から Producer への一方向の接続を作成します。Consumer は ClickHouse Cloud が管理する証明書で認証し、Producer は標準の `GRANT` を使用して、Consumer が読み取れるテーブルを制御します。パスワードの作成やローテーションは不要です。

クエリは、次の3つのチェックをすべて通過する必要があります。

1. **ネットワーク**: 接続が確立された Consumer のみが、プライベートネットワーク経由で Producer にアクセスできます。
2. **アイデンティティ**: Consumer は、自身のホスト名に紐付けられた証明書で認証します。
3. **テーブルのアクセス許可**: Producer は `GRANT` を使用して、Consumer が読み取れるテーブルを決定します。権限が付与されていないテーブルにアクセスすると、アクセス拒否エラーが返されます。

## 前提条件 {#prerequisites}

* 両方のサービスが、同じ ClickHouse Cloud 組織、クラウドプロバイダー、リージョンに属していること。たとえば、AWS `us-east-2` のサービスから AWS `us-west-2` のサービスには接続できません。接続を作成する前に、当社のチームがサービスの要件適合性を確認します。
* どちらのサービスも規制対象 (HIPAA または PCI) のサービスではないこと。
* 両方のサービスのサービス ID とホスト名を把握していること。いずれも、コンソールの各サービスの **設定** ページで確認できます。
* 両方のサービスで管理者として SQL を実行できること。

<Tip>
  本番環境への影響を避けるため、まずはテスト用サービスで試してください。Consumer では、最初の接続の作成時にローリング再起動が 1 回発生します。
</Tip>

## 接続の設定 {#setup}

### サービスの詳細を送付する {#send-service-details}

プライベートプレビュー期間中は、接続を設定するためのコンソール UI は提供されていません。ClickHouse の担当者に以下の情報をお送りください。

* Producer と Consumer それぞれのサービス ID。どちらが Producer でどちらが Consumer かを明記し、双方向でクエリを実行する必要があるかどうかもあわせてお知らせください。
* Consumer のローリング再起動を実施しても差し支えない時間帯。2 回目以降の接続では、再起動は一切発生しません。

### ClickHouse による接続の作成 {#clickhouse-creates-connection}

ClickHouse は、両方のサービスが要件を満たしていることを確認したうえで接続を作成します。続いて、Producer 上に `rt_<Consumer service ID>` という名前の証明書認証ユーザーを作成し、実際のユーザー名をお客様にお知らせします。

### Consumer にテーブルへのアクセス権を付与する {#grant-access}

以下のテストクエリを実行するか、Producer 上で自身のテーブルに対する select 権限を付与してください。

```sql
CREATE TABLE default.rs_demo_events (id UInt32, val String) ENGINE = MergeTree ORDER BY id;

INSERT INTO default.rs_demo_events VALUES (1, 'hello'), (2, 'from the Producer');

GRANT SELECT ON default.rs_demo_events TO `rt_<Consumer service ID>`;

CREATE TABLE default.rs_demo_no_grant (id UInt32) ENGINE = MergeTree ORDER BY id;
```

### Consumer からクエリを実行する {#query-from-consumer}

Consumer 上で以下を実行します。プライベートプレビュー段階の名前付きコレクション機能は、ClickHouse 側で有効化します。以下の SQL は、Producer を参照する[名前付きコレクション](/ja/concepts/features/configuration/server-config/named-collections)を作成し、それを経由してクエリを実行します。Producer のホスト名には、コンソールに表示されているホスト名 (Producer に直接接続する際に使用するものと同じ) を指定してください。

```sql
CREATE NAMED COLLECTION IF NOT EXISTS my_producer AS
    host = '<Producer hostname>',
    port = 9440,
    user = 'rt_<Consumer service ID>',
    database = 'default';

SELECT * FROM remoteSecure(my_producer, table = 'rs_demo_events');

SELECT * FROM remoteSecure(my_producer, table = 'rs_demo_no_grant');
```

テストクエリを実行した場合、最初のクエリは結果を返す一方で、2 番目のクエリはアクセス許可が不足しているためにアクセス拒否エラーになったことがわかるはずです。

## 制限事項 {#limitations}

### スコープ {#scope}

* クエリは読み取り専用です。Consumer は `remoteSecure()` を介して `SELECT` を実行できますが、Producer に `INSERT` することはできません。
* 両方のサービスが、同じ組織、同じクラウドプロバイダー、同じリージョンに属している必要があります。cross-region および組織をまたぐ接続には今後対応する予定です。
* 1 つの接続が対象とするのは 1 つのサービスのみです。[ウェアハウス](/ja/products/cloud/features/infrastructure/warehouses) を使用している場合でも、あるサービスへの接続は、そのデータを共有する他のサービスには適用されません。サービスごとに個別の接続が必要です。
* 接続は一方向です。双方向でクエリを実行するには、接続が 2 つ必要です。
* 読み取りは Producer 側で実行されます。これは現在の [`remoteSecure()`](/ja/reference/functions/table-functions/remote) テーブル関数と同様です。

### アイドル化 {#idling}

* アイドル状態または停止状態の Producer は、`remoteSecure()` クエリを受けても起動しません。この場合、クエリは接続拒否となります。Consumer から Producer へ確実にクエリを実行する必要がある場合は、Producer の[アイドル化](/ja/products/cloud/features/autoscaling/idling)を無効にしてください。ただし、その場合 Producer は常時稼働し、コンピュートの料金が継続的に発生します。
* 長時間実行される `remoteSecure()` クエリは、実行中に Consumer がアイドル状態になると失敗する可能性があります。

### エラーメッセージ {#error-messages}

ほとんどの障害は、原因を特定できるメッセージではなく、接続拒否、ハンドシェイクの拒否、タイムアウトといった汎用的なネットワークエラーとして表示されます。後述の[トラブルシューティング](#troubleshooting)表を参照してください。また、エラーメッセージの改善に役立てるため、表示されたエラーの内容をぜひお知らせください。

### サービスの削除 {#deleting-a-service}

接続が存在していても、どちらのサービスも削除できます。プライベートプレビュー期間中にいずれかのサービスを削除した場合は、こちらで接続をクリーンアップできるよう、ご連絡ください。

## トラブルシューティング {#troubleshooting}

| 表示される内容                           | 考えられる原因                                        | 対処方法                                                                                    |
| --------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------- |
| アクセス拒否                     | Consumer 側のユーザーにテーブルの権限が付与されていない               | [Consumer にテーブルへのアクセス権を付与する](#grant-access) の手順に従い、Producer 側で `GRANT SELECT` を実行してください |
| 認証に失敗しました                         | 名前付きコレクションに指定したユーザーが、当社が作成したユーザーと一致していない       | 当社からお送りしたユーザー名を確認してください                                                                 |
| 接続拒否                              | Producer がアイドル状態または停止している、あるいはこの方向の接続が設定されていない | Producer を起動してください。すでに稼働している場合は、接続の方向について当社にご確認ください                                     |
| クエリがハングする、または明確なエラーが出ないままタイムアウトする | 接続のセットアップがまだ完了していない可能性がある                      | 両方のサービス ID を添えて当社までお問い合わせください                                                           |

## よくある質問 {#faq}

<AccordionGroup>
  <Accordion title="追加料金はかかりますか？" id="cost">
    課金対象は使用したコンピュートのみです。これには Producer がアイドル化していない時間も含まれます。
  </Accordion>

  <Accordion title="パスワードや証明書を管理する必要はありますか？" id="credentials">
    いいえ。Consumer は、ClickHouse Cloud が管理する証明書を使用して認証します。
  </Accordion>

  <Accordion title="トラフィックはパブリックインターネットを経由しますか？" id="public-internet">
    いいえ。トラフィックは ClickHouse Cloud のプライベートネットワーク内にとどまります。そのため、Producer が PrivateLink のトラフィックのみを受け付ける場合や、IP アクセスリストで何も許可していない場合でも動作します。
  </Accordion>

  <Accordion title="Producer から Consumer のデータを読み取ることはできますか？" id="reverse-reads">
    逆方向の 2 つ目の接続を依頼しない限り、できません。
  </Accordion>

  <Accordion title="これを有効にするとサービスは再起動されますか？" id="restarts">
    Consumer で最初の接続を作成すると、ローリング再起動が 1 回トリガーされます。Producer は再起動されません。また、以降の接続の追加や取り消しによって再起動が発生することはありません。
  </Accordion>

  <Accordion title="アクセスを削除するにはどうすればよいですか？" id="remove-access">
    テーブルへのアクセスを削除するには、Producer で `REVOKE` を実行します。接続自体を削除する場合は、プライベートプレビュー期間中は ClickHouse の担当者にお問い合わせください。
  </Accordion>
</AccordionGroup>
