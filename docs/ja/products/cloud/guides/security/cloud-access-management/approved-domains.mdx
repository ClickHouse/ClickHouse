承認済みドメインを使用すると、新しいユーザーがメールドメインに基づいて ClickHouse Cloud の組織に参加できるようになります。所有しているドメインを検証すると、一致するユーザーを自動的に追加するか招待を送信できるほか、デフォルトロールを割り当てることもできます。

このガイドでは、ドメインの追加と検証、登録の設定、および承認済みドメインの管理方法について説明します。

## はじめる前に {#before-you-begin}

組織設定を管理するアクセス許可と、ドメインの DNS 設定に TXT レコードを追加できる権限が必要です。

<Note>
  承認済みドメインは、SAML SSO または SCIM を使用していない組織で利用できます。identity provider を使用している組織では、[SAML SSO のセットアップ](/ja/products/cloud/guides/security/cloud-access-management/saml-sso-setup)ガイドの手順に従ってください。
</Note>

## 仕組み {#how-it-works}

ユーザーが初めて ClickHouse Cloud アカウントを作成すると、ClickHouse はそのユーザーのメールドメインを承認済みドメインと照合します。ドメインが一致した各組織では、その組織で設定済みの登録方法とデフォルトロールが適用されます。

| 登録方法                   | 動作                                                 |
| ---------------------- | -------------------------------------------------- |
| **Join automatically** | ユーザーは組織に追加されます。その後、コンソール上でアクセス権を確認し、組織を開くよう求められます。 |
| **Send an invite**     | ユーザーに招待が届きます。組織に参加するには、その招待を承諾する必要があります。           |

登録は新規アカウントにのみ適用されます。既存のユーザーを追加するには、[招待を送信](/ja/products/cloud/guides/security/cloud-access-management/manage-cloud-users)してください。

メールドメインは完全一致である必要があります。たとえば、`example.com` は `user@example.com` には一致しますが、`user@team.example.com` には一致しません。サブドメインは個別に追加して検証してください。

複数の組織が同じドメインを承認している場合は、各組織がそれぞれの登録設定を適用します。複数の組織に自動的に追加されたユーザーは、開く組織を選択できます。

## ドメインを追加して所有権確認する {#add-and-verify-a-domain}

<Steps>
  <Step title="承認済みドメインを開く" id="open-approved-domains">
    ClickHouse Cloud コンソールで組織の設定を開きます。**承認済みドメイン** で **Add domain** をクリックします。
  </Step>

  <Step title="ドメインを追加する" id="add-your-domain">
    `example.com` などのメールドメインを入力し、**Add** をクリックします。

    1 つの組織に登録できるドメインは、所有権確認待ちのものを含めて最大 20 個です。`gmail.com` などのパブリックなメールドメインや使い捨てメールドメインは承認できません。
  </Step>

  <Step title="登録方法とデフォルトロールを設定する" id="configure-enrollment-and-default-roles">
    ドメインごとに、**自動登録** の方法と **デフォルトロール** を選択します。

    新しいドメインの初期設定は、Send an invite と Member ロールです。登録は所有権確認が完了してから開始されます。

    ロールは **カスタムロールを含め** 1 つ以上選択できます。一覧には、割り当て権限のあるロールのみが表示されます。**管理者** など、組織を管理できるロールは選択できません。

    選択したロールが削除された場合や割り当てできなくなった場合、そのロールはドメインから外されます。選択したロールが 1 つも残っていない場合、新規ユーザーには Member ロールが付与されます。
  </Step>

  <Step title="DNS レコードを追加する" id="add-the-dns-record">
    コンソールに表示される値を使用して、DNS プロバイダーで TXT レコードを作成します。

    | フィールド         | 値                                                         |
    | ------------- | --------------------------------------------------------- |
    | Name/Host     | 表示されている **TXT record name**：`@`、またはドメイン自体を表すプロバイダー側の同等の指定 |
    | Value/Content | `clickhouse-verification=` で始まる **TXT record value** 全体   |

    このレコードは、既存の TXT レコードを残したまま追加してください。
  </Step>

  <Step title="ドメインを所有権確認する" id="verify-the-domain">
    ClickHouse Cloud に戻り、所有権未確認のドメインの横にあるリフレッシュアイコンをクリックします。所有権確認が完了すると、ステータスが **Verified** に変わります。

    DNS の変更が反映されるまでには時間がかかる場合があります。すぐに所有権確認が完了しない場合は、しばらく待ってから再度お試しください。
  </Step>
</Steps>

## 登録設定を更新する {#update-enrollment-settings}

**承認済みドメイン** を開き、対象ドメインの **デフォルトロール** または **自動登録** の設定を変更します。変更内容は自動的に保存され、以降の登録に適用されます。

既存メンバーのロールを更新する場合は、[ユーザーのロール割り当てを管理する](/ja/products/cloud/guides/security/cloud-access-management/manage-cloud-users#manage-role-assignments) の手順に従ってください。

## ドメインを削除する {#remove-a-domain}

**承認済みドメイン**を開き、対象ドメインの横にあるゴミ箱アイコンをクリックします。

ドメインを削除すると、以降はそのドメインによる登録ができなくなります。既存のメンバーと招待はそのまま残ります。必要に応じて、メンバーの削除や招待の取り消しを別途行ってください。

## 制限事項 {#limitations}

* 登録は、ユーザーが初めてアカウントを作成したときにのみ行われます。既存のユーザーが遡って追加されることはありません。
* 組織から退出したユーザーや組織から削除されたユーザーは、サインインしても自動的に再追加されることはありません。
* 既存のメンバーや有効期限内の招待が重複して作成されることはありません。
* 組織のメンバーシップに関する制限は引き続き適用されます。
* SAML SSO を設定するか SCIM を有効にすると、承認済みドメインによる登録は行われなくなります。

## トラブルシューティング {#troubleshooting}

### 承認済みドメインが表示されない、または編集できない {#approved-domains-missing}

SAML SSO を使用している組織では、このセクションは表示されません。承認済みドメインを編集するには、組織設定を管理するアクセス許可が必要です。

### ドメインの所有権確認が失敗する {#domain-verification-fails}

TXTレコードが正しいドメインに設定されているか、またコンソールに表示されている現在の値と一致しているかを確認してください。DNSの変更が反映されるまでしばらく待ってから、再試行してください。

コンソールにトークンが古いと表示された場合は、確認用の値を現在表示されている値に置き換えてください。確認リクエストの期限が切れている場合は、所有権確認をやり直してください。

### ドメインが拒否される {#domain-rejected}

対象のドメインがパブリックなメールや使い捨てメールのドメインでないこと、また組織に登録されているドメインが検証済み・未検証を合わせて20件未満であることを確認してください。

### ユーザーが追加されない {#user-not-added}

次の点を確認してください。

* ユーザーが新しい ClickHouse Cloud アカウントを作成していること。
* ユーザーのメールドメインが、検証済みドメインと完全に一致していること。
* 組織で SAML SSO や SCIM を使用していないこと。
* 組織でメンバーの招待が許可されていること。

**Send an invite** を選択している場合、ユーザーが招待を承諾するまでメンバーにはなりません。既存のアカウントの場合は、**ユーザーとロール** から招待を送信してください。
