サービスの削除保護は、無効にするまで削除をブロックするサービス単位の設定です。Cloudコンソール、[ClickHouse Cloud API](/ja/cloud/manage/api/api-overview)、Terraform のいずれからも誤って削除されないようにしたい ClickHouse Cloud サービスで使用してください。

<Note>
  この機能は ClickHouse Cloud サービスが対象です。[ClickHouse Managed Postgres](/ja/cloud/managed-postgres) サービスには適用されません。
</Note>

保護はデフォルトで無効です。保護を無効にしても、サービスが削除されることはありません。保護されたサービスはそのまま稼働を続け、クエリ、スケーリング、その他の設定にも影響はありません。

保護が有効な間は、削除リクエストが拒否されます。保護を無効にするまで、`DELETE /v1/organizations/{organizationId}/services/{serviceId}` は HTTP `409` を返します。また、サービスを削除するには、事前にサービスを停止しておく必要があります。削除はその後、非同期で実行されます。

## 変更できるユーザー {#who-can-change-it}

保護の有効化と無効化には、[`control-plane:service:delete`](/ja/cloud/security/console-roles) アクセス許可が必要です。このアクセス許可は組織の管理者に付与されています。詳細は[コンソールのロールと権限](/ja/cloud/security/console-roles)を参照してください。

保護を有効にするには、組織で削除保護が利用可能であることも必要です。ClickHouse Cloud の組織では利用可能です。組織で利用できない場合、`deletionProtection` を `true` に設定する作成または更新のリクエストは HTTP `400` を返します。保護の無効化ではこのチェックは行われません。`deletionProtection` を `false` に設定するリクエストは、すでに保護されているサービスに対するものであっても受け付けられます。

| 操作                                        | アクセス許可                                                                                              |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- |
| コンソールのスイッチをオンまたはオフにする                     | サービスに対する `control-plane:service:delete`                                                             |
| 既存のサービスで `deletionProtection` を設定する       | サービスに対する `control-plane:service:manage` および `control-plane:service:delete`                          |
| サービスに現在設定されている値を送信する                      | `control-plane:service:manage` のみ。現在と同じ値を送信する場合、`control-plane:service:delete` は不要です                |
| `deletionProtection: true` を指定してサービスを作成する | `control-plane:organization:create-service`、および組織内のすべてのサービスに対して付与済みの `control-plane:service:delete` |
| サービスを削除する                                 | サービスに対する `control-plane:service:delete`。サービスが停止しており、かつ保護が無効になっている必要があります                            |

ClickStack サービスはクラウド API では更新できません。削除保護の有効化と無効化はコンソールから行ってください。

## コンソールで保護のオン/オフを切り替える {#console}

サービスを開き、**設定** に移動します。**削除保護** のスイッチを切り替えます。変更は即座に保存されます。

このスイッチは、対象サービスに対する `control-plane:service:delete` 権限を持つすべてのユーザーが操作できます。保護がオンの間は、スイッチをオフにするまでコンソールから削除操作を実行できません。

## クラウド API で設定する {#cloud-api}

サービスオブジェクトには、ブール型のフィールド `deletionProtection` があります。このフィールドは、サービスの作成時 (`POST /v1/organizations/{organizationId}/services`) または更新時 (`PATCH /v1/organizations/{organizationId}/services/{serviceId}`) に設定できます。取得および一覧取得のレスポンスにもこのフィールドが含まれます。このフィールドが存在しない場合、サービスは保護されません。

保護を有効にするには、次のようにします:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": true}'
```

保護されたサービスを削除するには、保護をオフにしてからサービスを停止し、停止が完了するのを待ってから削除します。`"command": "stop"` を指定した `PATCH .../state` には `control-plane:service:manage` 権限が必要です。また、このリクエストはサービスの停止完了を待たずに応答を返します。サービスがまだ `stopping` 状態のときに削除を実行すると、削除は拒否されます。保護されたサービスに対して削除を実行すると `409` が返され、サービスは削除されずに残ります。

保護をオフにします:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": false}'
```

停止をリクエストします：

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID/state" \
  -d '{"command": "stop"}'
```

`result.state` が `stopped` になるまで待ってから、削除します:

```bash
while [ "$(curl --silent --user "$KEY_ID:$KEY_SECRET" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  | jq -r '.result.state')" != "stopped" ]; do
  sleep 5
done

curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X DELETE \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID"
```

## Terraform {#terraform}

<Note>
  `deletion_protection` は、最新リリースのプロバイダー [v3.43.0](https://github.com/ClickHouse/terraform-provider-clickhouse/releases/tag/v3.43.0) には含まれていません。この属性は [terraform-provider-clickhouse#799](https://github.com/ClickHouse/terraform-provider-clickhouse/pull/799) で追加され、マージ済みですが、まだリリースには含まれていません。そのため、以下の例を v3.43.0 で実行すると、サポートされていない引数としてエラーになります。この属性を含む、v3.43.0 より後のプロバイダーリリースを使用してください。
</Note>

`clickhouse_service` リソースでは `deletion_protection` を指定できます。これが `true` の間は、`terraform destroy` や、サービスの置換を伴う変更はすべて失敗します。サービスを削除するには、まず `false` に設定してその変更だけを単独で適用し、その後にサービスを削除してください。

設定から `deletion_protection` を削除しても、現在の設定値は変更されません。

```hcl
resource "clickhouse_service" "example" {
  # ...

  deletion_protection = true
}
```

サービスの作成時に `deletion_protection = true` を設定するには、組織内のすべてのサービスを削除できるAPIキーが必要です。作成後にこの設定を変更するには、対象のサービスに対する削除のアクセス許可が必要です。
