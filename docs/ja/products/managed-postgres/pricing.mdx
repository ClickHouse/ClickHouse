ClickHouse Managed Postgres はローカル NVMe ストレージを基盤としており、従来のネットワーク接続型ストレージアーキテクチャに伴うコスト増なしで、本番環境での使用に適した性能とネイティブな ClickHouse 連携を提供します。このページでは、このサービスの料金モデル、利用可能なインスタンスタイプ、ティアごとの比較について説明します。

<Tip>
  **料金計算ツール**

  正確な料金については、[料金計算ツール](https://clickhouse.com/pricing?service=postgres#pricing-calculator) を使用して、ワークロードに最適な構成と料金を確認してください。
</Tip>

<div id="price-performance">
  ## 価格対性能 {#price-performance}
</div>

このサービスはローカルのNVMeストレージ上で稼働するため、多くのワークロードで、従来のネットワーク接続型ストレージアーキテクチャと比べて大幅に優れた価格対性能を実現できます。類似したハードウェアプロファイルにおける他の Postgres プロバイダーとのベンチマーク比較については、[PostgresBench](https://postgresbench.clickhouse.com/)を参照してください。

同等のワークロードでは、必要なコンピュート量が最大で2〜4分の1になる場合があります。プロバイダー間で料金を比較する際は、こうした潜在的な効率向上を考慮する必要がありますが、実際の改善幅はワークロードによって異なるため、具体的なアプリケーションに対して検証してください。

<div id="pricing-model">
  ## 料金モデル {#pricing-model}
</div>

このサービスはローカル NVMe ストレージ上で稼働するため、料金はコンピュート料金とディスク料金を個別に課金するのではなく、CPU、メモリ、ストレージを含む VM 構成全体に基づいて決まります。

1 vCPU / 8 GB RAM / 59 GB NVMe から 96 vCPU / 768 GB RAM / 60 TB NVMe ストレージまで、50 を超える構成が用意されており、コンピュート負荷の高い Postgres ワークロードにも、大容量ストレージを必要とする Postgres ワークロードにも柔軟に対応できます。

### インスタンスタイプ {#instance-types}

インスタンス構成は、ワークロードの特性に応じてインフラストラクチャを選択しやすくするため、3 つのカテゴリに分類されています。すべてのインスタンスタイプがすべてのリージョンで利用できるわけではありません。GCP はプライベートプレビュー段階です。

* **メモリ最適化:** メモリと CPU の比率が 1:8 で、メモリ集約型のワークロード向けに設計されています。AWS では、x86 ベースの `r8id` および `r6id` ファミリーと、ARM64 (AWS Graviton ベース) の `r8gd` および `r6gd` ファミリーをサポートしています。GCP では、x86 ベースの `n2` および `n2d` ファミリーをサポートしています。大規模なワーキングセット、高いキャッシュヒット率が求められるケース、メモリバウンドなデータベースワークロードに最適です。
* **ストレージ最適化:** コンピュートを比例して増やすことなく、大容量のローカルNVMeストレージを必要とするワークロード向けに設計されています。AWS では、ARM64 (AWS Graviton ベース) の `i8g` および `i8ge` ファミリーと、x86 ベースの `i7i` および `i7ie` ファミリーをサポートしており、最大 60 TB のローカルNVMeストレージを備えた構成も用意されています。GCP では、x86 ベースの `z3` ファミリーをサポートしています。大規模なデータセット、時系列ワークロード、ログやイベントの保存、ストレージ負荷の高い OLTP ワークロードに最適です。
* **CPU 最適化:** メモリと CPU の比率が 1:4 で、計算集約型のワークロード向けに設計されています。AWS では、x86 ベースの `m8id` および `m6id` ファミリーと、ARM64 (AWS Graviton ベース) の `m8gd` および `m6gd` ファミリーをサポートしています。GCP では、x86 ベースの `n2` および `n2d` ファミリーをサポートしています。同時実行数の多いトランザクション対応ワークロードや、CPU バウンドなクエリに最適です。

## クラウドプロバイダー別料金 {#cloud-provider-pricing}

### AWS の料金体系 {#aws-pricing}

AWS では Managed Postgres が一般提供されており、**2026年11月9日**から次のとおり請求されます。

* **バックアップ:** プロビジョニング済みのディスクと同じ容量のバックアップストレージが含まれます。それを超えるバックアップストレージは、お使いのリージョンにおける ClickHouse Cloud のストレージ料金で請求されます (例: `us-east-1` では 1 TB・月あたり $25.30) 。詳細は [バックアップと復元](/ja/products/managed-postgres/backup-and-restore) を参照してください。
* **データ転送:** [ClickHouse Cloud のデータ転送料金](/ja/products/cloud/reference/billing/network-data-transfer) に基づいて請求されます。アプリケーションと Managed Postgres が同一リージョンにある場合や、ClickPipes を使用する際に Managed Postgres と ClickHouse が同一リージョンにある場合は、ネットワークコストを低く抑えられます。
* **ClickPipes:** Managed Postgres から ClickHouse Cloud へのデータ複製にかかるコンピュートは無料です。Managed Postgres から ClickPipes へのエグレスは標準の [データ転送料金](/ja/products/cloud/reference/billing/network-data-transfer) で計測されるため、Managed Postgres と ClickHouse Cloud が同一リージョンにあればネットワーク料金は発生しません。
* **WalShadow:** プライベートプレビュー期間中は、Managed Postgres から ClickHouse Cloud へのデータ複製を無料でご利用いただけます。

<Note>
  データ転送は、宛先 IP をクラウドプロバイダーが公開している IP アドレス範囲と照合して分類されます。宛先の IP がお使いのリージョンの公開範囲に含まれない場合、その宛先が同じクラウドプロバイダー上でホストされていても (例: 独自の IP ブロックを使用するピア (BYOIP)) 、トラフィックはパブリックインターネットへのエグレスとして計測されます。このようなピアに接続する場合は、分類を確認いたしますので [サポート](https://clickhouse.com/support/program) までお問い合わせください。
</Note>

### GCP プライベートプレビューの料金 {#gcp-private-preview-pricing}

GCP 上の ClickHouse Managed Postgres は、プライベートプレビュー期間中は無料です。プライベートプレビュー終了後の料金は現在策定中です。詳細については、最終的な料金体系の見込みをお伝えしますのでお問い合わせください。GCP プライベートプレビューのウェイトリストには[こちら](https://clickhouse.com/cloud/postgres#gcp-waitlist)から登録できます。

## サービスの無効化 {#service-deactivation}

Managed Postgres サービスの無効化は、ClickHouse Cloud サービスの停止に相当します。組織が請求コンプライアンスを満たさなくなった場合に、他の ClickHouse Cloud サービスと同じ条件およびタイミングで無効化されます。たとえば、請求方法が設定されないまま無料試用期間が終了した場合や、支払いに失敗した場合などが該当します。詳しいルールについては、[ClickHouse Cloud の請求コンプライアンス](/ja/products/cloud/reference/billing/billing-compliance)を参照してください。

サービスが無効化されると、次のようになります。

* 既存の接続はブロックされます。
* 新規接続もブロックされます。
* サービスの料金は請求されません。
* データとバックアップは削除されずに保持されます。データおよびバックアップの保持期間については、[請求コンプライアンス](/ja/products/cloud/reference/billing/billing-compliance)を参照してください。

サービスを再開するには、次の手順を実行します。

1. 組織の未払い残高を支払います。
2. サービスの **設定** タブを開き、**Start** をクリックします。詳しくは[設定](/ja/products/managed-postgres/settings#service-actions)を参照してください。

**Start** ボタンは、サービスが無効化されている場合にのみ表示されます。組織の請求が未払いの間は、このボタンは無効になっています。支払いが完了するとボタンが有効になるので、クリックしてサービスを再開してください。

## 料金に関する免責事項 {#pricing-disclaimers}

* データベースをオンラインのまま維持するため、スケーリングとメンテナンス操作では、新しいインスタンスが古いインスタンスと並列に短時間稼働します。移行が完了するまでの間は、古いインスタンスと新しいインスタンスの両方に対する料金が一時的に重複して発生する場合があります。この期間の長さは、インスタンスタイプとストレージ容量によって異なります。
* 選択したインスタンスタイプの容量が一部のアベイラビリティゾーンで一時的に制限されている場合、選択した高可用性構成を維持するために、サービスは古い世代の同等のインスタンスタイプにフォールバックすることがあります。この場合、対象のインスタンスタイプの料金が適用されます。
