<div id="description">
  ## 説明
</div>

`BACKUP` または `RESTORE` のすべての操作について、現在の状態やその他のプロパティを一覧表示します。なお、このテーブルは永続的ではなく、最後にサーバーが再起動されて以降に実行された操作のみが表示されます。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `id` ([String](/ja/sql-reference/data-types/string)) — 操作 ID。`SETTINGS id=...` で指定することも、ランダムに生成された UUID にすることもできます。
* `name` ([String](/ja/sql-reference/data-types/string)) — 操作名。`Disk('backups', 'my_backup')` のような文字列です。
* `base_backup_name` ([String](/ja/sql-reference/data-types/string)) — ベースバックアップの操作名。`Disk('backups', 'my_base_backup')` のような文字列です。
* `query_id` ([String](/ja/sql-reference/data-types/string)) — バックアップを開始したクエリの Query ID。
* `status` ([Enum8(&#39;CREATING&#95;BACKUP&#39; = 0, &#39;BACKUP&#95;CREATED&#39; = 1, &#39;BACKUP&#95;FAILED&#39; = 2, &#39;RESTORING&#39; = 3, &#39;RESTORED&#39; = 4, &#39;RESTORE&#95;FAILED&#39; = 5, &#39;BACKUP&#95;CANCELLED&#39; = 6, &#39;RESTORE&#95;CANCELLED&#39; = 7)](/ja/sql-reference/data-types/enum)) — バックアップまたは復元操作のステータス。
* `error` ([String](/ja/sql-reference/data-types/string)) — エラーメッセージ (存在する場合) 。
* `start_time` ([DateTime64(6)](/ja/sql-reference/data-types/datetime64)) — 操作の開始時刻。
* `end_time` ([DateTime64(6)](/ja/sql-reference/data-types/datetime64)) — 操作の完了時刻。
* `num_files` ([UInt64](/ja/sql-reference/data-types/int-uint)) — バックアップに保存されているファイル数。
* `total_size` ([UInt64](/ja/sql-reference/data-types/int-uint)) — バックアップに保存されているファイルの合計サイズ。
* `num_entries` ([UInt64](/ja/sql-reference/data-types/int-uint)) — バックアップ内のエントリ数。つまり、バックアップがフォルダーとして保存されている場合は、そのフォルダー内のファイル数です。
* `uncompressed_size` ([UInt64](/ja/sql-reference/data-types/int-uint)) — バックアップの非圧縮サイズ。
* `compressed_size` ([UInt64](/ja/sql-reference/data-types/int-uint)) — バックアップの圧縮サイズ。
* `files_read` ([UInt64](/ja/sql-reference/data-types/int-uint)) — このバックアップから RESTORE 中に読み取られたファイル数を返します。
* `bytes_read` ([UInt64](/ja/sql-reference/data-types/int-uint)) — このバックアップから RESTORE 中に読み取られたファイルの合計サイズを返します。
* `ProfileEvents` ([Map(LowCardinality(String), UInt64)](/ja/sql-reference/data-types/map)) — この操作中に収集されたすべてのプロファイルイベント。
* `settings` ([Map(LowCardinality(String), String)](/ja/sql-reference/data-types/map)) — この操作で実際に使用されたバックアップ/復元固有の設定 (`SETTINGS` 句の値で、デフォルトを含む) 。機密性の高い設定は公開されません。
* `engine_settings` ([Map(LowCardinality(String), String)](/ja/sql-reference/data-types/map)) — バックアップエンジンの reader/writer が実際に使用した設定 (例: S3 `allow_native_copy`) 。フラットなマップでは表現できない複数のエンジンが操作に関与する場合は空になります。これには、インクリメンタルバックアップと復元、lightweight snapshot restores、および内部ではない `ON CLUSTER` 操作が含まれます。

{/*AUTOGENERATED_END*/ }

<div id="restore-atomicity">
  ## 復元のアトミック性
</div>

`RESTORE` はトランザクション処理ではなく、失敗してもロールバックされません。各テーブルでは、選択されたすべてのパーツがコピーされてからアタッチされますが、アタッチのフェーズ自体にはトランザクション性がありません。パーツは 1 つずつ順に可視状態になります。テーブルはそれぞれ独立して処理されます。

**テーブル同士は独立しています。** 復元が完了したテーブルは、同じコマンド内の別のテーブルがその後失敗しても、そのまま残ります。

```sql
RESTORE TABLE db.t0, TABLE db.t1
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

このコマンドが、`db.t0` の復元が完全に完了したあと、`db.t1` の復元がまだ完了していない段階で失敗した場合でも、`db.t0` は復元されたままです。

**`PARTITIONS` 句はコミット境界ではありません。** これは、テーブルのどのパーツを復元するかを指定するだけです。

```sql
RESTORE TABLE db.t0 PARTITIONS '2026-06-01', '2026-06-02', '2026-06-03'
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

テーブルの選択したすべてのパーツは、まずコピーされ、すべての準備が整ってから一度にアタッチされます。したがって、このコマンドがコピー段階で失敗した場合、たとえばパーティション `2026-06-01` のコピーは完了していても、`2026-06-02` と `2026-06-03` がまだ完了していなければ、`2026-06-01` は**コミットされず**、このコマンドによって復元されたデータはテーブルに一切反映されません。コピー段階が完了してアタッチ手順が始まると、パーツは1つずつコミットされるため、アタッチ中に失敗すると、ロールバックなしでテーブルが部分的に復元された状態になることがあります。

パーティションごとに独立してコミットするには (つまり、完了したパーティションを後続の障害後も保持し、個別に再試行できるようにするには) 、パーティションごとに個別の `RESTORE` を実行し、最初の実行後は `SETTINGS allow_non_empty_tables = true` を使用します。
