<div id="description">
  ## 説明
</div>

サーバーでサポートされている Dictionary レイアウトの一覧と、各レイアウトの埋め込みドキュメントが含まれます。Dictionary レイアウトは、Dictionary がメモリ内 (またはディスク上) にどのように格納され、どのように参照されるかを決定するもので、`CREATE DICTIONARY` クエリの `LAYOUT` 句で指定します。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `name` ([String](/ja/sql-reference/data-types/string)) — `LAYOUT` 句で指定するDictionary レイアウトの名前。
* `is_complex` ([UInt8](/ja/sql-reference/data-types/int-uint)) — そのレイアウトで複合キー (複数の属性、または非整数型で構成されるキー) が必要かどうか。
* `description` ([String](/ja/sql-reference/data-types/string)) — そのDictionary レイアウトの概要説明。
* `syntax` ([String](/ja/sql-reference/data-types/string)) — `CREATE DICTIONARY` クエリの `LAYOUT` 句でのレイアウトの指定方法。
* `examples` ([String](/ja/sql-reference/data-types/string)) — 使用例。
* `introduced_in` ([String](/ja/sql-reference/data-types/string)) — そのレイアウトが最初に導入された ClickHouse のバージョン。形式は major.minor。
* `related` ([Array](/ja/sql-reference/data-types/array)([String](/ja/sql-reference/data-types/string))) — 関連するDictionary レイアウトの名前。

{/*AUTOGENERATED_END*/ }

<div id="example">
  ## 例
</div>

```sql title="Query"
SELECT name, is_complex, syntax
FROM system.dictionary_layouts
WHERE name IN ('flat', 'hashed', 'complex_key_hashed')
ORDER BY name
```

```text title="Response"
┌─name───────────────┬─is_complex─┬─syntax───────────────────────────────────────────────────┐
│ complex_key_hashed │          1 │ LAYOUT(COMPLEX_KEY_HASHED())                             │
│ flat               │          0 │ LAYOUT(FLAT([INITIAL_ARRAY_SIZE n] [MAX_ARRAY_SIZE n]))  │
│ hashed             │          0 │ LAYOUT(HASHED())                                         │
└────────────────────┴────────────┴──────────────────────────────────────────────────────────┘
```
