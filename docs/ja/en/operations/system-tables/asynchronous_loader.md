<div id="description">
  ## 説明
</div>

最近の非同期ジョブ (例: テーブルのロード) の情報とステータスが含まれます。このテーブルには、各ジョブごとに1行が格納されます。このテーブルの情報を可視化するツールとして `utils/async_loader_graph` があります。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `job` ([String](/ja/sql-reference/data-types/string)) — ジョブ名 (一意でない場合があります) 。
* `job_id` ([UInt64](/ja/sql-reference/data-types/int-uint)) — ジョブの一意な ID。
* `dependencies` ([Array(UInt64)](/ja/sql-reference/data-types/array)) — このジョブの前に完了している必要があるジョブの ID の一覧。
* `dependencies_left` ([UInt64](/ja/sql-reference/data-types/int-uint)) — まだ完了していない依存関係の現在の数。
* `status` ([Enum8(&#39;PENDING&#39; = 0, &#39;OK&#39; = 1, &#39;FAILED&#39; = 2, &#39;CANCELED&#39; = 3)](/ja/sql-reference/data-types/enum)) — ジョブの現在のロードステータス。PENDING: ロードジョブはまだ開始されていません。OK: ロードジョブは実行され、正常に完了しました。FAILED: ロードジョブは実行されましたが、失敗しました。CANCELED: ロードジョブは、削除または依存関係の障害により実行されません。
* `is_executing` ([UInt8](/ja/sql-reference/data-types/int-uint)) — このジョブは現在 ワーカー によって実行中です。
* `is_blocked` ([UInt8](/ja/sql-reference/data-types/int-uint)) — このジョブは依存関係の完了を待機しています。
* `is_ready` ([UInt8](/ja/sql-reference/data-types/int-uint)) — このジョブは実行可能な状態で、ワーカー を待機しています。
* `elapsed` ([Float64](/ja/sql-reference/data-types/float)) — 実行開始からの経過 Seconds。ジョブがまだ開始されていない場合は 0 です。ジョブが完了している場合は合計実行時間です。
* `pool_id` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 現在このジョブに割り当てられている プール の ID。
* `pool` ([String](/ja/sql-reference/data-types/string)) — `pool_id` の プール 名。
* `priority` ([Int64](/ja/sql-reference/data-types/int-uint)) — `pool_id` の プール の優先度。
* `execution_pool_id` ([UInt64](/ja/sql-reference/data-types/int-uint)) — ジョブが実行される プール の ID。実行開始前は、最初に割り当てられた プール の ID と同じです。
* `execution_pool` ([String](/ja/sql-reference/data-types/string)) — `execution_pool_id` の プール 名。
* `execution_priority` ([Int64](/ja/sql-reference/data-types/int-uint)) — `execution_pool_id` の プール の優先度。
* `ready_seqno` ([Nullable(UInt64)](/ja/sql-reference/data-types/nullable)) — 実行可能状態のジョブでは NULL ではない です。ワーカー は自身の プール の 実行待ちキュー から次に実行するジョブを取得します。実行可能状態のジョブが複数ある場合は、`ready_seqno` の値が最も小さいジョブが選択されます。
* `waiters` ([UInt64](/ja/sql-reference/data-types/int-uint)) — このジョブを待機している threads の数。
* `exception` ([Nullable(String)](/ja/sql-reference/data-types/nullable)) — 失敗またはキャンセルされたジョブでは NULL ではない です。クエリ実行中に発生したエラーメッセージ、またはこのジョブのキャンセルにつながった error と、ジョブ名による dependency failure chain を保持します。
* `schedule_time` ([DateTime64(6)](/ja/sql-reference/data-types/datetime64)) — ジョブが作成され、実行するようスケジュールされた時刻 (通常はすべての依存関係とともに) 。
* `enqueue_time` ([Nullable(DateTime64(6))](/ja/sql-reference/data-types/nullable)) — ジョブが実行可能状態になり、その プール の 実行待ちキュー にエンキューされた時刻。ジョブがまだ実行可能状態でない場合は Null です。
* `start_time` ([Nullable(DateTime64(6))](/ja/sql-reference/data-types/nullable)) — ワーカー が 実行待ちキュー からジョブをデキューし、実行を開始した時刻。ジョブがまだ開始されていない場合は Null です。
* `finish_time` ([Nullable(DateTime64(6))](/ja/sql-reference/data-types/nullable)) — ジョブの実行が完了した時刻。ジョブがまだ完了していない場合は Null です。

{/*AUTOGENERATED_END*/ }

保留中のジョブは、次のいずれかの状態を取る場合があります。

* `is_executing` (`UInt8`) - ジョブは現在、ワーカーによって実行中です。
* `is_blocked` (`UInt8`) - ジョブは依存関係の完了を待っています。
* `is_ready` (`UInt8`) - ジョブは実行可能な状態で、ワーカーの割り当てを待っています。
* `elapsed` (`Float64`) - 実行開始からの経過Seconds。ジョブがまだ開始されていない場合は 0。ジョブが完了している場合は合計実行時間。

各ジョブには関連付けられたプールがあり、そのプール内で開始されます。各プールには固定の優先度と、変更可能な最大ワーカー数があります。優先度が高い (`priority` の値が低い) ジョブほど先に実行されます。より高い優先度のジョブが少なくとも 1 つ実行可能状態または実行中である間は、より低い優先度のジョブは開始されません。ジョブの優先度は、優先化することで引き上げることができます (ただし引き下げることはできません) 。たとえば、受信したクエリがそのテーブルを必要とする場合、テーブルの loading や起動のためのジョブは優先化されます。ジョブは実行中に優先化することもできますが、`execution_pool` から新しく割り当てられた `pool` へ移されることはありません。優先度逆転を避けるため、ジョブは新しいジョブの作成時に `pool` を使用します。すでに開始されているジョブが、より高い優先度のジョブによってプリエンプトされることはなく、開始後は必ず完了まで実行されます。

* `pool_id` (`UInt64`) - 現在そのジョブに割り当てられているプールの ID。

* `pool` (`String`) - `pool_id` のプール名。

* `priority` (`Int64`) - `pool_id` のプールの優先度。

* `execution_pool_id` (`UInt64`) - ジョブが実行されるプールの ID。実行開始前に最初に割り当てられたプールと同じです。

* `execution_pool` (`String`) - `execution_pool_id` のプール名。

* `execution_priority` (`Int64`) - `execution_pool_id` のプールの優先度。

* `ready_seqno` (`Nullable(UInt64)`) - 実行可能状態のジョブでは NULL ではありません。ワーカーは、自身のプールの実行待ちキューから次に実行するジョブを取り出します。実行可能状態のジョブが複数ある場合は、`ready_seqno` の値が最も小さいジョブが選ばれます。

* `waiters` (`UInt64`) - このジョブを待機しているスレッド数。

* `exception` (`Nullable(String)`) - 失敗またはキャンセルされたジョブでは NULL ではありません。クエリ実行中に発生したエラーメッセージ、またはこのジョブのキャンセルにつながったエラーと、ジョブ名による依存関係の障害連鎖を保持します。

ジョブの lifetime における各時点:

* `schedule_time` (`DateTime64`) - ジョブが作成され、実行するようスケジュールされた時刻 (通常はそのすべての依存関係とともに) 。
* `enqueue_time` (`Nullable(DateTime64)`) - ジョブが実行可能状態になり、そのプールの実行待ちキューにエンキューされた時刻。ジョブがまだ実行可能状態でない場合は NULL。
* `start_time` (`Nullable(DateTime64)`) - ワーカーが実行待ちキューからそのジョブをデキューし、実行を開始した時刻。ジョブがまだ開始されていない場合は NULL。
* `finish_time` (`Nullable(DateTime64)`) - ジョブの実行が完了した時刻。ジョブがまだ完了していない場合は NULL。
