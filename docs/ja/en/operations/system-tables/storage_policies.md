<div id="description">
  ## 説明
</div>

[サーバー設定](../../engines/table-engines/mergetree-family/mergetree.md#table_engine-mergetree-multiple-volumes_configure) で定義されているストレージポリシーとボリュームに関する情報が含まれます。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `policy_name` ([String](/ja/sql-reference/data-types/string)) — ストレージポリシーの名前。
* `volume_name` ([String](/ja/sql-reference/data-types/string)) — ボリュームの名前。
* `volume_priority` ([UInt64](/ja/sql-reference/data-types/int-uint)) — ボリュームの優先度。
* `disks` ([Array(String)](/ja/sql-reference/data-types/array)) — このストレージポリシーに含まれるすべてのディスク名の一覧。
* `volume_type` ([Enum8(&#39;JBOD&#39; = 0, &#39;SINGLE&#95;DISK&#39; = 1, &#39;UNKNOWN&#39; = 2)](/ja/sql-reference/data-types/enum)) — ボリュームの種類。JBOD または単一ディスクです。
* `max_data_part_size` ([UInt64](/ja/sql-reference/data-types/int-uint)) — このボリューム内のいずれかのディスクに格納できるパーツの最大サイズ。
* `move_factor` ([Float32](/ja/sql-reference/data-types/float)) — 使用可能な空き領域がこの値を下回ると、データは自動的に次のボリュームへ移動し始めます (存在する場合。デフォルトは 0.1) 。
* `prefer_not_to_merge` ([UInt8](/ja/sql-reference/data-types/int-uint)) — この設定は使用しないでください。このボリューム上でのデータパーツのマージを無効にします (これは有害で、パフォーマンス低下につながります) 。
* `perform_ttl_move_on_insert` ([UInt8](/ja/sql-reference/data-types/int-uint)) — データパーツの INSERT 時の TTL move を無効にします。デフォルトでは (有効な場合) 、TTL move ルールですでに期限切れになっているデータパーツを insert すると、move ルールで指定されたボリューム/ディスクに直ちに配置されます。
* `load_balancing` ([Enum8(&#39;ROUND&#95;ROBIN&#39; = 0, &#39;LEAST&#95;USED&#39; = 1)](/ja/sql-reference/data-types/enum)) — ディスクの負荷分散ポリシー。`round_robin` または `least_used`。

{/*AUTOGENERATED_END*/ }

<div id="volume-selection-on-insert">
  ## `INSERT` 時のボリューム選択
</div>

`INSERT` で新しいデータパーツが作成されると、ClickHouse は以下のルールを順番に試して
宛先ディスクを選択します。**そのパーツ用の領域を予約できる** 最初の一致ルールが
採用されます。そうでない場合 (ルールが適用されない、空き容量がない、または
`max_data_part_size` を超えている場合) は、次のルールの評価に進みます。

1. **TTL move rule** — 挿入される行に対して `TTL <expr> TO VOLUME 'X'` (または `TO DISK 'X'`)
   句の時刻がすでに経過しており、**かつ**
   **TTL 宛先ボリューム** (`TO DISK 'X'` の場合はディスク `X` を含むボリューム) で
   `perform_ttl_move_on_insert = 1` (デフォルト) になっている場合、そのパーツは
   直接その宛先に書き込まれます。そこでの予約に失敗した場合、`insert` は
   ステップ 2～4 にフォールバックします。警告はログに記録されますが、`INSERT` は
   この理由だけでは失敗しません。
2. **`max_data_part_size`** — ボリュームは、自身の
   `max_data_part_size` より大きいパーツを拒否します。これはボリュームごとに確認されます。
   これは、ディスクを直接対象とするステップ 1 の `TTL ... TO DISK 'X'` の予約には
   適用されません。
3. **`volume_priority`** — 残っているボリュームのうち、
   `volume_priority` の値が最も小さいものが選択されます。明示的な
   `<volume_priority>` がないボリュームは、設定内での出現順に並べられます。
4. **`load_balancing`** — ボリュームが選択されると、その
   ボリューム内のディスクは `load_balancing` ポリシー
   (`round_robin` または `least_used`) に従って選択されます。

:::note Override
`min_free_disk_bytes_to_perform_insert` または
`min_free_disk_ratio_to_perform_insert` がゼロ以外の場合、上記の優先順位は
無視されます。`INSERT` は最も小さい
`volume_priority` を持つボリュームだけを試し、そのボリューム内のどのディスクも
しきい値を満たさない場合は `NOT_ENOUGH_SPACE` をスローします。
`system` データベースへの `insert` はこの制限の対象外です。
:::

:::note
`perform_ttl_move_on_insert` は、ソースボリュームではなく **TTL 宛先** ボリュームから
読み取られます。`TO DISK 'X'` ルールでは、このフラグは
ディスク `X` を含むボリュームから読み取られます。ポリシー内の他のボリュームに
設定しても、`insert` 経路には影響しません。
:::

「すでに
期限切れ」の TTL move rule が適用される場合でも、`insert` を `volume_priority` に確実に従わせるには、
TTL 宛先ボリューム (`TO DISK 'X'` の場合は
ディスク `X` を含むボリューム) で `perform_ttl_move_on_insert = 0` を設定します。
すると、そのパーツはまず priority-N ボリュームに書き込まれ、
バックグラウンドの移動タスクによって TTL 宛先へ移動されます (
`system.moves` で確認できます) 。詳しくは
[`perform_ttl_move_on_insert` setting on the MergeTree engine](/ja/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-multiple-volumes_configure)
を参照してください。
