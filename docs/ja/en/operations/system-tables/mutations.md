<div id="description">
  ## 説明
</div>

このテーブルには、[MergeTree](/ja/engines/table-engines/mergetree-family/mergetree.md) テーブルの [ミューテーション](/ja/sql-reference/statements/alter/index.md#mutations) とその進行状況に関する情報が含まれています。各 ミューテーション コマンドは 1 行に対応します。

<div id="columns">
  ## カラム：
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/ja/sql-reference/data-types/string)) — ミューテーション が適用されたデータベース名。
* `table` ([String](/ja/sql-reference/data-types/string)) — ミューテーション が適用されたテーブル名。
* `mutation_id` ([String](/ja/sql-reference/data-types/string)) — ミューテーション の ID。レプリケートテーブルでは、これらの ID は ClickHouse Keeper の `<table_path_in_clickhouse_keeper>/mutations/` ディレクトリ内の znode 名に対応します。非レプリケートテーブルでは、ID はテーブルのデータディレクトリ内のファイル名に対応します。
* `command` ([String](/ja/sql-reference/data-types/string)) — ミューテーション コマンド文字列 (クエリ内の `ALTER TABLE [db.]table` より後ろの部分) 。
* `create_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — ミューテーション コマンドが実行のために送信された日付と時刻。
* `block_numbers.partition_id` ([Array(String)](/ja/sql-reference/data-types/array)) — レプリケートテーブルの ミューテーション では、この配列にパーティション ID が含まれます (各パーティションにつき 1 レコード) 。非レプリケートテーブルの ミューテーション では、この配列は空です。
* `block_numbers.number` ([Array(Int64)](/ja/sql-reference/data-types/array)) — レプリケートテーブルの ミューテーション では、この配列には各パーティションにつき 1 レコードが含まれ、ミューテーション が取得したブロック番号が格納されます。各パーティションでは、この番号より小さい番号のブロックを含むパーツだけが ミューテーション の対象になります。非レプリケートテーブルでは、すべてのパーティションのブロック番号が単一の数列を形成します。つまり、非レプリケートテーブルの ミューテーション では、このカラムには ミューテーション が取得した単一のブロック番号を持つ 1 レコードが含まれます。
* `parts_in_progress_names` ([Array(String)](/ja/sql-reference/data-types/array)) — 現在 ミューテーション 中のデータパーツ名の配列。
* `parts_to_do_names` ([Array(String)](/ja/sql-reference/data-types/array)) — ミューテーション を完了するために処理が必要なデータパーツ名の配列。
* `parts_to_do` ([Int64](/ja/sql-reference/data-types/int-uint)) — ミューテーション を完了するために処理が必要なデータパーツ数。注意: `parts_to_do` = 0 であっても、レプリケートテーブルの ミューテーション がまだ完了していない場合があります。これは、あとで ミューテーション が必要になる新しいデータパーツを作成している、長時間実行中の INSERT が原因です。
* `parts_postpone_reasons` ([Map(String, String)](/ja/sql-reference/data-types/map)) — パーツ 名と、その処理が延期されている理由の対応を表すマップ。
* `is_done` ([UInt8](/ja/sql-reference/data-types/int-uint)) — ミューテーション が完了しているかどうかを示すフラグ。設定可能な値: ミューテーション が完了している場合は 1、ミューテーション がまだ進行中の場合は 0。
* `is_killed` ([UInt8](/ja/sql-reference/data-types/int-uint)) — ミューテーション が kill されたかどうかを示します。ClickHouse Cloud でのみ利用可能。注意: is&#95;killed=1 であっても、ミューテーション が完全に終了しているとは限りません。is&#95;killed=1 かつ is&#95;done=0 の状態が長期間続くことがあります。これは、別の長時間実行中の ミューテーション が、kill された ミューテーション をブロックしている場合に発生します。これは正常な状況です。
* `latest_failed_part` ([String](/ja/sql-reference/data-types/string)) — 直近で ミューテーション できなかった パーツ の名前。
* `latest_fail_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — 直近の パーツ ミューテーション failure が発生した日付と時刻。
* `latest_fail_reason` ([String](/ja/sql-reference/data-types/string)) — 直近の パーツ ミューテーション failure を引き起こした例外メッセージ。
* `latest_fail_error_code_name` ([String](/ja/sql-reference/data-types/string)) — 直近の パーツ ミューテーション failure を引き起こした例外のエラーコード。

{/*AUTOGENERATED_END*/ }

:::note

* パーツ名が `parts_postpone_reasons` に含まれておらず、まだミューテーションが適用されていない場合、そのパーツはまだミューテーション対象としてスケジュールされていないことを意味します。

* パーツ名 `all_parts` は、まだミューテーションが適用されていないすべてのパーツを表します。
  :::

* `is_killed` ([UInt8](/ja/sql-reference/data-types/int-uint.md)) — ミューテーションが強制終了されたかどうかを示します。**ClickHouse Cloud でのみ利用できます。**

:::note
`is_killed=1` であっても、ミューテーションが完全に終了しているとは限りません。`is_killed=1` かつ `is_done=0` の状態のまま、ミューテーションが長時間残ることがあります。これは、別の長時間実行中のミューテーションが、強制終了されたミューテーションをブロックしている場合に発生します。これは正常な状況です。
:::

* `is_done` ([UInt8](/ja/sql-reference/data-types/int-uint.md)) — ミューテーションが完了したかどうかを示すフラグです。設定可能な値:
  * ミューテーションが完了している場合は `1`、
  * ミューテーションがまだ進行中の場合は `0`。

:::note
`parts_to_do = 0` であっても、長時間実行される `INSERT` クエリによってミューテーション対象の新しいデータパーツが作成されるため、レプリケートテーブルのミューテーションがまだ完了していない可能性があります。
:::

一部のデータパーツのミューテーションで問題が発生した場合、次のカラムに追加情報が含まれます。

* `latest_failed_part` ([String](/ja/sql-reference/data-types/string.md)) — 直近でミューテーションできなかったパーツの名前。
* `latest_fail_time` ([DateTime](/ja/sql-reference/data-types/datetime.md)) — 直近のパーツに対するミューテーション失敗の日時。
* `latest_fail_reason` ([String](/ja/sql-reference/data-types/string.md)) — 直近のパーツに対するミューテーション失敗の原因となった例外メッセージ。

<div id="monitoring-mutations">
  ## ミューテーションの監視
</div>

`system.mutations` テーブルの進行状況を確認するには、次のクエリを使用します。

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

注: これには `system.*` テーブルに対する閲覧権限が必要です。

:::tip Cloud での利用
ClickHouse Cloud では、各ノードの `system.mutations` テーブルにクラスター内のすべてのミューテーションが含まれているため、`clusterAllReplicas` は不要です。
:::
