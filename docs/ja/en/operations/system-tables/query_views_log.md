<div id="description">
  ## 説明
</div>

クエリの実行時に実行される依存VIEWに関する情報 (VIEWの種類や実行時間など) が含まれます。

ログ記録を開始するには、次の手順を実行します。

1. [query&#95;views&#95;log](../../operations/server-configuration-parameters/settings.md#query_views_log) セクションでパラメーターを設定します。
2. [log&#95;query&#95;views](/ja/operations/settings/settings#log_query_views) を 1 に設定します。

データのフラッシュ間隔は、[query&#95;views&#95;log](../../operations/server-configuration-parameters/settings.md#query_views_log) サーバー設定セクションの `flush_interval_milliseconds` パラメーターで設定します。フラッシュを強制的に実行するには、[SYSTEM FLUSH LOGS](/ja/sql-reference/statements/system#flush-logs) クエリを使用します。

ClickHouse はテーブルからデータを自動的に削除しません。詳細については、[Introduction](/ja/operations/system-tables/overview#system-tables-introduction) を参照してください。

`query_views_log` テーブルに記録されるクエリ数を減らすには、[log&#95;queries&#95;probability](/ja/operations/settings/settings#log_queries_probability)) 設定を使用できます。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — クエリを実行するサーバーのホスト名。
* `event_date` ([Date](/ja/sql-reference/data-types/date)) — VIEW の最後のイベントが発生した日付。
* `event_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — VIEW の実行が終了した日時。
* `event_time_microseconds` ([DateTime64(6)](/ja/sql-reference/data-types/datetime64)) — VIEW の実行が終了した日時 (マイクロ秒精度) 。
* `view_duration_ms` ([UInt64](/ja/sql-reference/data-types/int-uint)) — VIEW の実行時間 (各ステージの合計、ミリ秒単位) 。
* `initial_query_id` ([String](/ja/sql-reference/data-types/string)) — 初期クエリの ID (分散クエリ実行用) 。
* `view_name` ([String](/ja/sql-reference/data-types/string)) — VIEW の名前。
* `view_uuid` ([UUID](/ja/sql-reference/data-types/uuid)) — VIEW の UUID。
* `view_type` ([Enum8(&#39;Default&#39; = 1, &#39;Materialized&#39; = 2, &#39;Live&#39; = 3, &#39;Window&#39; = 4)](/ja/sql-reference/data-types/enum)) — VIEW のタイプ。値: &#39;Default&#39; = 1 — Default VIEW。このログには出力されないはずです。&#39;Materialized&#39; = 2 — materialized VIEW、&#39;Live&#39; = 3 — Live VIEW。
* `view_query` ([String](/ja/sql-reference/data-types/string)) — VIEW によって実行されたクエリ。
* `view_target` ([String](/ja/sql-reference/data-types/string)) — VIEW のターゲットテーブルの名前。
* `read_rows` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 読み取られた行数。
* `read_bytes` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 読み取られたバイト数。
* `written_rows` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 書き込まれた行数。
* `written_bytes` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 書き込まれたバイト数。
* `peak_memory_usage` ([Int64](/ja/sql-reference/data-types/int-uint)) — この VIEW のコンテキストにおける、割り当て済みメモリ量と解放済みメモリ量の差の最大値。
* `ProfileEvents` ([Map(LowCardinality(String), UInt64)](/ja/sql-reference/data-types/map)) — さまざまなメトリクスを測定する ProfileEvents。それぞれの説明は `system.events` テーブルにあります。
* `status` ([Enum8(&#39;QueryStart&#39; = 1, &#39;QueryFinish&#39; = 2, &#39;ExceptionBeforeStart&#39; = 3, &#39;ExceptionWhileProcessing&#39; = 4)](/ja/sql-reference/data-types/enum)) — VIEW のステータス。値: &#39;QueryStart&#39; = 1 — VIEW 実行の開始に成功。これは表示されないはずです。&#39;QueryFinish&#39; = 2 — VIEW 実行の正常終了、&#39;ExceptionBeforeStart&#39; = 3 — VIEW 実行開始前の例外、&#39;ExceptionWhileProcessing&#39; = 4 — VIEW 実行中の例外。
* `exception_code` ([Int32](/ja/sql-reference/data-types/int-uint)) — 例外のコード。
* `exception` ([String](/ja/sql-reference/data-types/string)) — 例外メッセージ。
* `stack_trace` ([String](/ja/sql-reference/data-types/string)) — スタックトレース。クエリが正常に完了した場合は空文字列です。

**別名:**

* `ProfileEvents.Names` — `mapKeys(ProfileEvents)` の別名。
* `ProfileEvents.Values` — `mapValues(ProfileEvents)` の別名。

{/*AUTOGENERATED_END*/ }
