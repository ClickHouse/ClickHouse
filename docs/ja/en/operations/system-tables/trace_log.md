<div id="description">
  ## 説明
</div>

[サンプリングクエリプロファイラ](../../operations/optimizing-performance/sampling-query-profiler.md)によって収集されたスタックトレースが格納されます。

ClickHouse は、サーバー設定の [trace&#95;log](../../operations/server-configuration-parameters/settings.md#trace_log) セクションが設定されている場合にこのテーブルを作成します。あわせて参照: 設定 [query&#95;profiler&#95;real&#95;time&#95;period&#95;ns](../../operations/settings/settings.md#query_profiler_real_time_period_ns)、[query&#95;profiler&#95;cpu&#95;time&#95;period&#95;ns](../../operations/settings/settings.md#query_profiler_cpu_time_period_ns)、[memory&#95;profiler&#95;step](../../operations/settings/settings.md#memory_profiler_step)、
[memory&#95;profiler&#95;sample&#95;probability](../../operations/settings/settings.md#memory_profiler_sample_probability)、[trace&#95;profile&#95;events](../../operations/settings/settings.md#trace_profile_events)。

ログを分析するには、`addressToLine`、`addressToLineWithInlines`、`addressToSymbol`、`demangle` のイントロスペクション関数を使用します。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — クエリを実行しているサーバーのホスト名。
* `event_date` ([Date](/ja/sql-reference/data-types/date)) — サンプリング時点の日付。
* `event_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — サンプリング時点のタイムスタンプ。
* `event_time_microseconds` ([DateTime64(6)](/ja/sql-reference/data-types/datetime64)) — サンプリング時点のタイムスタンプ (マイクロ秒精度) 。
* `timestamp_ns` ([UInt64](/ja/sql-reference/data-types/int-uint)) — サンプリング時点のタイムスタンプ (ナノ秒単位) 。
* `revision` ([UInt32](/ja/sql-reference/data-types/int-uint)) — ClickHouse server のビルドリビジョン。`clickhouse-client` でサーバーに接続すると、`Connected to ClickHouse server version 19.18.1.` のような文字列が表示されます。このフィールドに含まれるのは、サーバーの `version` ではなく `revision` です。
* `trace_type` ([Enum8(&#39;Real&#39; = 0, &#39;CPU&#39; = 1, &#39;Memory&#39; = 2, &#39;MemorySample&#39; = 3, &#39;MemoryPeak&#39; = 4, &#39;ProfileEvent&#39; = 5, &#39;JemallocSample&#39; = 6, &#39;MemoryAllocatedWithoutCheck&#39; = 7, &#39;Instrumentation&#39; = 8)](/ja/sql-reference/data-types/enum)) — trace の種類: `Real` は wall-clock time に基づく stack traces の収集を表します。`CPU` は CPU time に基づく stack traces の収集を表します。`Memory` は、メモリ割り当てが次の watermark を超えたときに、割り当てと解放を収集することを表します。`MemorySample` は、ランダムな割り当てと解放の収集を表します。`MemoryPeak` は、Peak memory usage の更新の収集を表します。`ProfileEvent` は、profile events の増分の収集を表します。`JemallocSample` は、jemalloc samples の収集を表します。`MemoryAllocatedWithoutCheck` は、すべての memory limit を無視して行われる大きな割り当て (&gt;16MiB) の収集を表します (ClickHouse 開発者専用) 。`Instrumentation` は、XRay による instrumentation を通じて収集された traces を表します。
* `cpu_id` ([UInt64](/ja/sql-reference/data-types/int-uint)) — CPU 識別子。
* `thread_id` ([UInt64](/ja/sql-reference/data-types/int-uint)) — スレッド識別子。
* `thread_name` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — スレッド名。
* `query_id` ([String](/ja/sql-reference/data-types/string)) — `query_log` システムテーブルから、実行されていたクエリの詳細を取得するために使用できるクエリ識別子。
* `trace` ([Array(UInt64)](/ja/sql-reference/data-types/array)) — サンプリング時点の stack trace。各要素は ClickHouse server process 内の仮想メモリアドレスです。
* `size` ([Int64](/ja/sql-reference/data-types/int-uint)) — trace type が Memory、MemorySample、MemoryAllocatedWithoutCheck、または MemoryPeak の場合は割り当てられたメモリ量、それ以外の trace type では 0 です。
* `ptr` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 割り当てられた chunk のアドレス。
* `memory_context` ([Enum8(&#39;Unknown&#39; = -1, &#39;Global&#39; = 0, &#39;User&#39; = 1, &#39;Process&#39; = 2, &#39;Thread&#39; = 3, &#39;Max&#39; = 4)](/ja/sql-reference/data-types/enum)) — Memory Tracker のコンテキスト (Memory/MemoryPeak のみ) : `Unknown` context は、この trace&#95;type では定義されていません。`Global` は server context を表します。`User` は user/merge context を表します。`Process` は process (つまり query) context を表します。`Thread` は thread (特定の process の thread) context を表します。`Max` は、memory tracker がブロックされていないことを示す特別な値です (blocked&#95;context カラム用) 。
* `memory_blocked_context` ([Enum8(&#39;Unknown&#39; = -1, &#39;Global&#39; = 0, &#39;User&#39; = 1, &#39;Process&#39; = 2, &#39;Thread&#39; = 3, &#39;Max&#39; = 4)](/ja/sql-reference/data-types/enum)) — メモリトラッカーがブロックされている対象のContext (ClickHouse 開発者専用) 。`Unknown` context はこの trace&#95;type では定義されていません。`Global` はサーバーコンテキストを表します。`User` はユーザー/merge コンテキストを表します。`Process` はプロセス (つまりクエリ) コンテキストを表します。`Thread` はスレッド (特定のプロセスのスレッド) コンテキストを表します。`Max` は特殊な値で、メモリトラッカーがブロックされていないことを意味します (blocked&#95;context カラム用) 。
* `event` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — trace type が ProfileEvent の場合は、更新された profile event の名前です。その他の trace type では空文字列です。
* `increment` ([Int64](/ja/sql-reference/data-types/int-uint)) — trace type が ProfileEvent の場合は、profile event の増分量です。その他の trace type では 0 です。
* `symbols` ([Array(LowCardinality(String))](/ja/sql-reference/data-types/array)) — シンボル化が有効な場合、`trace` に対応するデマングル済みのシンボル名が含まれます。シンボル化は、サーバー設定ファイルの `trace_log` の `symbolize` 設定で有効または無効にできます。
* `lines` ([Array(LowCardinality(String))](/ja/sql-reference/data-types/array)) — シンボル化が有効な場合、`trace` に対応する、行番号付きファイル名の文字列が含まれます。
* `function_id` ([Nullable(Int32)](/ja/sql-reference/data-types/nullable)) — trace type が Instrumentation の場合、elf-binary の xray&#95;instr&#95;map セクションで関数に割り当てられた ID です。
* `function_name` ([Nullable(String)](/ja/sql-reference/data-types/nullable)) — trace type が Instrumentation の場合、インストルメントされた関数の名前です。
* `handler` ([Nullable(String)](/ja/sql-reference/data-types/nullable)) — trace type が Instrumentation の場合、インストルメントされた関数のハンドラーです。
* `entry_type` ([Nullable(Enum8(&#39;Entry&#39; = 0, &#39;Exit&#39; = 1))](/ja/sql-reference/data-types/nullable)) — trace type が Instrumentation の場合、インストルメントされた関数のエントリタイプです。
* `duration_nanoseconds` ([Nullable(UInt64)](/ja/sql-reference/data-types/nullable)) — trace type が Instrumentation の場合、関数の実行時間をナノ秒単位で表します。

**別名:**

* `build_id` — `'E2EEB60ED9503BFFA825B628D480CCDC40B2D416'` のエイリアス。

{/*AUTOGENERATED_END*/ }

シンボル化は、サーバーの設定ファイルにある `trace_log` の `symbolize` で有効または無効にできます。

<div id="chrome-event-trace-format">
  ## Chrome Event Trace Format への変換
</div>

プロファイリングデータは、次のクエリを使って Chrome&#39;s Event Trace Format に変換できます。クエリを `chrome_trace.sql` ファイルに保存してください。

```sql
WITH traces AS (
    SELECT * FROM system.trace_log
    WHERE event_date >= today() AND trace_type = 'Instrumentation' AND handler = 'profile'
    ORDER BY event_time, entry_type
)
SELECT
    format(
        '{{"traceEvents": [{}\n]}}',
        arrayStringConcat(
            groupArray(
                format(
                    '\n{{"name": "{}", "cat": "clickhouse", "ph": "{}", "ts": {}, "pid": 1, "tid": {}, "args": {{"query_id": "{}", "cpu_id": {}, "stack": [{}]}}}},',
                    function_name,
                    if(entry_type = 0, 'B', 'E'),
                    timestamp_ns/1000,
                    toString(thread_id),
                    query_id,
                    cpu_id,
                    arrayStringConcat(arrayMap((x, y) -> concat('"', x, ': ', y, '", '), lines, symbols))
                )
            )
        )
    )
FROM traces;
```

それを ClickHouse Client で実行し、[Perfetto](https://ui.perfetto.dev/) または [speedscope](https://www.speedscope.app/) にインポートできる `trace.json` ファイルとしてエクスポートします。

```bash
echo $(clickhouse client --query "$(cat chrome_trace.sql)") > trace.json
```

よりコンパクトで情報量の少ないトレースにしたい場合は、スタック部分を省略できます。
