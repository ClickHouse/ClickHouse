<div id="description">
  ## 説明
</div>

`MergeTree` テーブルの読み取り時に収集される、サンプリングされた選択性の統計情報が含まれます。このテーブルにデータが格納されるのは、[`predicate_statistics_sample_rate`](/ja/operations/settings/settings#predicate_statistics_sample_rate) が `0` より大きい場合のみです。

このテーブルを使用すると、実際のワークロードでユーザー指定の述語がどの程度選択的か、またプライマリキーやスキップ索引によるフィルタリング後にどれだけのグラニュールが残るかを確認できます。このデータは、ワークロードに基づく索引およびプロジェクションの推奨に使用する入力データとして意図されています。

<div id="row-shapes">
  ## 行の形式
</div>

1 つのクエリは、`system.predicate_statistics_log` に 2 種類の行を生成できます。

* **フィルタ行**: `MergeTreeSelectProcessor` の prewhere/filter ステップごとに出力されます。`predicate_expression`、`input_rows`、`passed_rows`、`filter_selectivity`、および述語全体に対応するカラム `total_input_rows`、`total_passed_rows`、`total_selectivity` に値が入ります。索引関連のカラムは空です。
* **索引行**: `ReadFromMergeTree` の読み取りステップごとに出力されます。`index_names`、`index_types`、`total_granules`、`granules_after`、`index_selectivities` の各 Array に値が入り、索引ステージ (主キー、パーティション、スキップ索引) ごとに 1 つのエントリが格納されます。述語関連のカラムは空です。

同じクエリに対応するフィルタ行と索引行は、同じ `query_id` と `table` を共有するため、両方が必要な場合は結合できます。

<div id="sampling-and-overhead">
  ## サンプリングとオーバーヘッド
</div>

サンプリングは [`predicate_statistics_sample_rate`](/ja/operations/settings/settings#predicate_statistics_sample_rate) で制御します。

* `0` は収集を無効にします。
* `1` はすべてのクエリをサンプリングします。
* `N > 1` は、`query_id` をハッシュ化して、クエリのおよそ `1 / N` をサンプリングします。

値が小さいほど生成されるデータは増えますが、読み取りパスでの CPU 負荷が増し、システムログへの書き込みも増えます。設定を有効にしたあと、行をすぐに表示する必要がある場合は [`SYSTEM FLUSH LOGS`](/ja/sql-reference/statements/system#flush-logs) を使用してください。

<div id="columns">
  ## カラム
</div>

* `hostname` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — クエリを実行するサーバーのホスト名。
* `event_date` ([Date](/ja/sql-reference/data-types/date)) — イベントの日付。
* `event_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — このログエントリが書き込まれた時刻のタイムスタンプ。
* `database` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — ターゲットテーブルのデータベース名。
* `table` ([LowCardinality(String)](/ja/sql-reference/data-types/lowcardinality)) — ターゲットテーブルのテーブル名。
* `query_id` ([String](/ja/sql-reference/data-types/string)) — query&#95;log への関連付けに使用する Query ID。
* `predicate_expression` ([String](/ja/sql-reference/data-types/string)) — この prewhere/filter ステップで処理されるフィルタ式全体 (ActionsDAG ダンプ) 。
* `input_rows` ([UInt64](/ja/sql-reference/data-types/int-uint)) — この prewhere/filter ステップに入る行数。
* `passed_rows` ([UInt64](/ja/sql-reference/data-types/int-uint)) — この prewhere/filter ステップを通過した行数。
* `filter_selectivity` ([Float64](/ja/sql-reference/data-types/float)) — このステップの選択性: passed&#95;rows / input&#95;rows。
* `total_input_rows` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 最初の prewhere ステップに入る行数 (グラニュール から読み取られた総行数) 。
* `total_passed_rows` ([UInt64](/ja/sql-reference/data-types/int-uint)) — すべての prewhere ステップを通過した行数 (クエリに渡される行数) 。
* `total_selectivity` ([Float64](/ja/sql-reference/data-types/float)) — 述語全体の選択性: total&#95;passed&#95;rows / total&#95;input&#95;rows。
* `index_names` ([Array(LowCardinality(String))](/ja/sql-reference/data-types/array)) — 適用された索引名 (例: [&#39;PrimaryKey&#39;, &#39;idx&#95;bf&#95;status&#39;])  (索引の行のみ) 。
* `index_types` ([Array(LowCardinality(String))](/ja/sql-reference/data-types/array)) — 適用された索引の種類: PrimaryKey, Skip, MinMax, Partition (索引の行のみ) 。
* `total_granules` ([Array(UInt64)](/ja/sql-reference/data-types/array)) — 各 索引 stage に入る グラニュール 数 (索引の行のみ) 。
* `granules_after` ([Array(UInt64)](/ja/sql-reference/data-types/array)) — 各 索引 stage の後に残る グラニュール 数 (索引の行のみ) 。
* `index_selectivities` ([Array(Float64)](/ja/sql-reference/data-types/array)) — 索引ごとの選択性: granules&#95;after / total&#95;granules (索引の行のみ) 。

<div id="example">
  ## 例
</div>

```sql
SET predicate_statistics_sample_rate = 1;

SELECT *
FROM hits
WHERE URL LIKE '%/product/%' AND EventDate >= today() - 7
FORMAT Null;

SYSTEM FLUSH LOGS predicate_statistics_log;

SELECT
    query_id,
    predicate_expression,
    round(filter_selectivity, 3) AS step_selectivity,
    round(total_selectivity, 3) AS query_selectivity,
    index_names,
    index_selectivities
FROM system.predicate_statistics_log
WHERE table = 'hits'
ORDER BY event_time DESC
LIMIT 10;
```
