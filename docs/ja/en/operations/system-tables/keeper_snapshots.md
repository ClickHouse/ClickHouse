<div id="description">
  ## 説明
</div>

このノードがプロセス内 ClickHouse Keeper を実行するように設定されていない場合、このテーブルは存在しません。このテーブルには、プロセス内 Keeper ステートマシンが追跡する Raft スナップショットファイルごとに 1 行が含まれており、現在リーダーから受信中のスナップショットも含まれます。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `last_log_index` ([UInt64](../../sql-reference/data-types/int-uint.md)) — スナップショットに含まれる最後のログ索引。
* `path` ([String](../../sql-reference/data-types/string.md)) — ディスク上のスナップショットファイルのパス。
* `disk_name` ([String](../../sql-reference/data-types/string.md)) — スナップショットを保存しているディスクの名前。
* `size_bytes` ([UInt64](../../sql-reference/data-types/int-uint.md)) — ディスク上のスナップショットファイルのサイズ。
* `last_modified_at` ([DateTime](../../sql-reference/data-types/datetime.md)) — スナップショットファイルの最終更新時刻。
* `is_received` ([Bool](../../sql-reference/data-types/boolean.md)) — 現在リーダーからスナップショットを受信中の場合は `true`。このような行では、`size_bytes` と `last_modified_at` は現時点までに書き込まれた部分ファイルの状態を反映するため、実際より小さく示されることがあります。
* `exists_on_disk` ([Bool](../../sql-reference/data-types/boolean.md)) — スナップショットファイルが現在ディスク上に存在するかどうか。確定済みのスナップショット (`is_received` = `false`) では、ファイルが外部で削除されたか破損していない限り、常に `true` です。受信中のスナップショット (`is_received` = `true`) では、まだ 1 バイトも書き込まれていない場合は `false` になることがあります。

{/*AUTOGENERATED_END*/ }

例:

```sql
SELECT * FROM system.keeper_snapshots ORDER BY last_log_index;
```

│           2000 │ snapshot_2000.bin.zstd        │ default   │      48217 │ 2026-05-22 14:15:00 │ false       │ true           │
└────────────────┴───────────────────────────────┴───────────┴────────────┴─────────────────────┴─────────────┴────────────────┘
