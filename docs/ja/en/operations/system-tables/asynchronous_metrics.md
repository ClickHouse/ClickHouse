<div id="systemasynchronous_metrics">
  # system.asynchronous_metrics
</div>

<SystemTableCloud />

<div id="description">
  ## 説明
</div>

バックグラウンドで定期的に計算されるメトリクスが含まれます。たとえば、使用中のRAM量などです。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `metric` ([String](../../sql-reference/data-types/string.md)) — メトリクス名。
* `value` ([Float64](../../sql-reference/data-types/float.md)) — メトリクスの値。
* `description` ([String](../../sql-reference/data-types/string.md) - メトリクスの説明)

{/*AUTOGENERATED_END*/ }

<div id="metric-descriptions">
  ## メトリクスの説明
</div>

以下の説明は、C++ のソースコードから `utils/generate-async-metrics-docs` によって生成されています。唯一の信頼できる情報源は、`src/Common/AsynchronousMetrics.cpp`、`src/Interpreters/ServerAsynchronousMetrics.cpp`、および `src/Coordination/KeeperAsynchronousMetrics.cpp` の各メトリクス登録の横にある文字列リテラルです。可変の接尾辞 (per-disk、per-CPU、per-interface、...) を含むメトリクス名は、`*name*` プレースホルダーを使って示されます。実行中の server では、これらは具体的な接尾辞に置き換えられて報告されます。

<div id="asynchronousheavymetricscalculationtimespent">
  ### AsynchronousHeavyMetricsCalculationTimeSpent
</div>

非同期の高負荷な (テーブル関連の) メトリクスの計算に要した時間 (秒) です (これは非同期メトリクスのオーバーヘッドです) 。

<div id="asynchronousheavymetricsupdateinterval">
  ### AsynchronousHeavyMetricsUpdateInterval
</div>

テーブル関連の高負荷メトリクスの更新間隔

<div id="asynchronousmetricscalculationtimespent">
  ### AsynchronousMetricsCalculationTimeSpent
</div>

非同期メトリクスの計算に費やされた時間 (単位：秒) 。これは非同期メトリクスによるオーバーヘッドです。

<div id="asynchronousmetricsupdateinterval">
  ### AsynchronousMetricsUpdateInterval
</div>

メトリクスの更新間隔

<div id="asyncloggingmetric_firstqueuesize">
  ### AsyncLogging*metric_first*QueueSize
</div>

このチャネルでログ出力待ちのキューに入っている非同期メッセージ数

<div id="blockactivetime_name">
  ### BlockActiveTime_*name*
</div>

ブロックデバイスで I/O リクエストがキューに入っていた時間 (秒) です。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが対象です。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockactivetimeperop_name">
  ### BlockActiveTimePerOp_*name*
</div>

`BlockActiveTime` メトリクスと同様ですが、操作ごとの時間を算出するため、値を I/O 操作数で割っています。

<div id="blockdiscardbytes_name">
  ### BlockDiscardBytes_*name*
</div>

ブロックデバイスで破棄されたバイト数です。これらの操作は SSD に関連します。ディスカード操作は ClickHouse では使用されませんが、システム上の他のプロセスで使用される場合があります。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockdiscardmerges_name">
  ### BlockDiscardMerges_*name*
</div>

ブロックデバイスに対して要求され、OS の I/O スケジューラによってまとめられたディスカード操作の数です。これらの操作は SSD に関連します。ディスカード操作は ClickHouse では使用されませんが、システム上のほかのプロセスで使用されることがあります。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockdiscardops_name">
  ### BlockDiscardOps_*name*
</div>

ブロックデバイスに対して要求された discard 操作の回数です。これらの操作は主に SSD に関係します。discard 操作は ClickHouse では使用されませんが、システム上の他のプロセスで使用されることがあります。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockdiscardtime_name">
  ### BlockDiscardTime_*name*
</div>

ブロックデバイスに要求された discard operations に費やされた時間を、すべての操作について合計した値です。単位は秒です。これらの操作は SSD に関連します。discard operations は ClickHouse では使用されませんが、システム上の他のプロセスで使用されることがあります。これはシステム全体のメトリックであり、clickhouse-server だけでなく、host machine 上のすべてのプロセスが含まれます。Source: `/sys/block`。詳細は https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockinflightops_name">
  ### BlockInFlightOps_*name*
</div>

この値は、デバイスドライバーに発行されたものの、まだ完了していない I/O リクエスト数を示します。キューに入っていても、まだデバイスドライバーに発行されていない I/O リクエストは含まれません。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。詳しくは https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockqueuetime_name">
  ### BlockQueueTime_*name*
</div>

この値は、このブロックデバイスで I/O リクエストが待機した時間をミリ秒単位でカウントします。待機中の I/O リクエストが複数ある場合、この値は、待機時間 (ミリ秒) と待機中のリクエスト数の積に応じて増加します。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockqueuetimeperop_name">
  ### BlockQueueTimePerOp_*name*
</div>

`BlockQueueTime` メトリクスと同様ですが、値を I/O 操作回数で割ることで、1 操作あたりの時間を算出します。

<div id="blockreadbytes_name">
  ### BlockReadBytes_*name*
</div>

ブロックデバイスから読み取られたバイト数です。I/O を節約する OS page cache の利用により、ファイルシステムから読み取られたバイト数より少なくなる場合があります。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。取得元: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockreadmerges_name">
  ### BlockReadMerges_*name*
</div>

ブロックデバイスに対して要求され、OS の I/O スケジューラによって統合された読み取り操作の数です。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。取得元: `/sys/block`。詳しくは https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockreadops_name">
  ### BlockReadOps_*name*
</div>

ブロックデバイスに対して要求された読み取り操作の回数です。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockreadtime_name">
  ### BlockReadTime_*name*
</div>

ブロックデバイスに要求された読み取り操作に費やされた時間を秒単位で示したもので、すべての操作の合計です。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockwritebytes_name">
  ### BlockWriteBytes_*name*
</div>

ブロックデバイスに書き込まれたバイト数です。I/O を節約する OS page cache の利用により、filesystem に書き込まれたバイト数より少なくなる場合があります。ライトスルーキャッシュにより、ブロックデバイスへの書き込みは、対応する filesystem への書き込みより後で発生することがあります。これはシステム全体のメトリクスであり、clickhouse-server だけでなく、host machine 上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockwritemerges_name">
  ### BlockWriteMerges_*name*
</div>

ブロックデバイスに対して要求され、OS の I/O スケジューラによってまとめて処理された書き込み操作の回数です。これはシステム全体のメトリックであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="blockwriteops_name">
  ### BlockWriteOps_*name*
</div>

ブロックデバイスに要求された書き込み操作の回数です。これはシステム全体のメトリックであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが対象です。ソース: `/sys/block`。詳細は https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください

<div id="blockwritetime_name">
  ### BlockWriteTime_*name*
</div>

ブロックデバイスに要求された書き込み操作に費やされた時間の合計を、秒単位で表したものです。これはシステム全体のメトリックであり、clickhouse-server だけでなく、ホストマシン上のすべてのプロセスが含まれます。ソース: `/sys/block`。詳しくは https://www.kernel.org/doc/Documentation/block/stat.txt を参照してください。

<div id="cgroupmaxcpu">
  ### CGroupMaxCPU
</div>

CGroups における CPU コアの最大数。

<div id="cgroupmemorytotal">
  ### CGroupMemoryTotal
</div>

cgroup 内のメモリの総量です (バイト単位) 。0 の場合、制限は OSMemoryTotal と同じです。

<div id="cgroupmemoryused">
  ### CGroupMemoryUsed
</div>

cgroup で使用されているメモリ量 (バイト単位) です。cgroup v2 では anon + sock + 再利用不可のカーネルメモリ、cgroup v1 では RSS を指します。いずれの場合も、カーネルの OS page cache (ファイルベースの cache) は含まれません。

<div id="cgroupmemoryusedwithoutpagecache">
  ### CGroupMemoryUsedWithoutPageCache
</div>

ClickHouseのユーザー空間ページキャッシュを除いた、cgroupで使用中のメモリ量 (バイト単位) です。これは、CGroupMemoryUsedからユーザー空間ページキャッシュのサイズを差し引いた値です。ユーザー空間ページキャッシュが無効な場合、この値はCGroupMemoryUsedと同じになります。

<div id="cgroupsystemtime">
  ### CGroupSystemTime
</div>

CPUコアがOSカーネル (system) コードの実行に費やしていた時間の比率。

<div id="cgroupsystemtimenormalized">
  ### CGroupSystemTimeNormalized
</div>

この値は `CGroupSystemTime` と似ていますが、利用可能な CPU コア数で割ることで、コア数に関係なく [0..1] の区間で測定されます。これにより、クラスター内の複数のサーバーにまたがってこのメトリックの値を平均する場合でも、CPU コア数が一様でなくても、平均的なリソース使用状況のメトリックを得ることができます。指定されている場合は、実際の CPU コア数の代わりに、Cgroup CPU QUOTA をその period で割った値を使用できます。その場合、このメトリックの値は一時的に 1 を超えることがあります。

<div id="cgroupusertime">
  ### CGroupUserTime
</div>

CPUコアがユーザー空間のコードを実行していた時間の比率です。これには、CPU内部の要因 (メモリロード、パイプラインの停止、ブランチ予測ミス、別のSMTコアの実行) によって、CPUが十分に活用されていなかった時間も含まれます。

<div id="cgroupusertimenormalized">
  ### CGroupUserTimeNormalized
</div>

この値は `CGroupUserTime` に似ていますが、利用可能な CPU コア数で割ることで、コア数に関係なく [0..1] の範囲で測定されます。これにより、クラスター内の複数のサーバーでコア数が均一でない場合でも、このメトリクスの値を平均し、平均的なリソース使用状況を表すメトリクスを得ることができます。指定した場合は、実際の CPU コア数の代わりに、Cgroup CPU QUOTA をその周期で割った値を使用できます。その場合、このメトリクスの値は一時的に 1 を超えることがあります。

<div id="cpufrequencymhz_core_id">
  ### CPUFrequencyMHz_*core_id*
</div>

CPUの現在の周波数です。単位はMHzです。最近のCPUの多くは、省電力やTurbo Boostのために周波数を動的に調整します。

<div id="dictionarymaxupdatedelay">
  ### DictionaryMaxUpdateDelay
</div>

Dictionary 更新の最大遅延 (秒)

<div id="dictionarytotalfailedupdates">
  ### DictionaryTotalFailedUpdates
</div>

最後に正常に読み込まれて以降、すべての Dictionary で発生したエラーの数。

<div id="diskavailable_name">
  ### DiskAvailable_*name*
</div>

ディスク上で利用可能なバイト数 (仮想ファイルシステム) 。リモートファイルシステムではこの情報を提供しない場合があり、16 EiB のような大きな値が表示されることがあります。

<div id="diskgetobjectthrottleravailable_name">
  ### DiskGetObjectThrottlerAvailable_*name*
</div>

ディスク (仮想ファイルシステム) で、スロットリング制限に達することなく現在発行できる GetObject リクエストの数。ローカルファイルシステムでは、この情報を提供しない場合があります。

<div id="diskgetobjectthrottlerrps_name">
  ### DiskGetObjectThrottlerRPS_*name*
</div>

ディスク上の GetObject リクエストのスロットリング上限 (仮想ファイルシステム、1 秒あたりのリクエスト数) 。ローカルファイルシステムでは、この情報が提供されない場合があります。

<div id="diskputobjectthrottleravailable_name">
  ### DiskPutObjectThrottlerAvailable_*name*
</div>

ディスク (仮想ファイルシステム) でスロットリング制限に達せずに現在発行できる PutObject リクエスト数。ローカルファイルシステムでは、この情報を取得できない場合があります。

<div id="diskputobjectthrottlerrps_name">
  ### DiskPutObjectThrottlerRPS_*name*
</div>

ディスク上の PutObject リクエストのスロットリング制限 (1 秒あたりのリクエスト数、仮想ファイルシステム) 。ローカルファイルシステムでは、この情報は提供されない場合があります。

<div id="disktotal_name">
  ### DiskTotal_*name*
</div>

ディスク (仮想ファイルシステム) の総容量をバイト単位で表したものです。リモートファイルシステムではこの情報を取得できない場合があり、16 EiB のような大きな値が表示されることがあります。

<div id="diskunreserved_name">
  ### DiskUnreserved_*name*
</div>

マージ、フェッチ、移動用の予約を差し引いた、ディスク (仮想ファイルシステム) 上の利用可能なバイト数です。リモートファイルシステムではこの情報を提供しない場合があり、16 EiB のような大きな値が表示されることがあります。

<div id="diskused_name">
  ### DiskUsed_*name*
</div>

ディスク (仮想ファイルシステム) で使用されているバイト数です。リモートファイルシステムでは、この情報が提供されない場合があります。

<div id="edaci_correctable">
  ### EDAC*i*_Correctable
</div>

訂正可能な ECC メモリエラーの件数です。この値が多い場合は RAM の不良を示しており、直ちに交換する必要があります。訂正済みエラーが多数発生している状態では、サイレントエラーも発生し得るため、データ破損につながるおそれがあります。出典: `/sys/devices/system/edac/mc/`

<div id="edaci_uncorrectable">
  ### EDAC*i*_Uncorrectable
</div>

修正不能な ECC メモリエラーの数です。この値が 0 以外の場合、RAM に障害があることを示しており、データ破損の可能性があるため、直ちに交換する必要があります。ソース: `/sys/devices/system/edac/mc/`

<div id="executableuserdefinedfunctionmemoryresidentbytes">
  ### ExecutableUserDefinedFunctionMemoryResidentBytes
</div>

実行可能および実行可能プールの user-defined function と、その子孫プロセスに属するすべての稼働中プロセスについて、常駐セットサイズ (VmRSS) を合計した値です。単位はバイトです。アイドル状態の実行可能プール worker も含まれます。共有ページはプロセスごとに1回ずつカウントされるため、この合計値は上限値であり、UDF プロセスの実際の物理メモリ使用量 (重複を除いた量) を上回る場合があります。

<div id="executableuserdefinedfunctionprocesses">
  ### ExecutableUserDefinedFunctionProcesses
</div>

実行可能および実行可能プールのユーザー定義関数のために生成された、子孫プロセスを含む稼働中のプロセス数。

<div id="filesystemcachebytes">

<div id="filesystemmainpathavailablebytes">

システム全体の負荷を、1 分間の指数平滑移動平均で表した値です。この負荷は、すべてのプロセスにまたがるスレッド (OS kernel の scheduling entities) のうち、現在 CPU 上で実行中のもの、I/O を待機中のもの、または実行可能な状態でありながらこの時点ではまだスケジュールされていないものの数を表します。この数値には、clickhouse-server だけでなく、すべてのプロセスが含まれます。システムが過負荷状態にあり、多くのプロセスが実行可能でありながら CPU または I/O を待っている場合、この数値は CPU コア数を上回ることがあります。

<div id="loadaverage15">
  ### LoadAverage15
</div>

システム全体の負荷を、15 分間の指数平滑化で平均した値です。この負荷は、現在 CPU で実行中、I/O を待機中、または実行可能な状態にあるもののこの時点ではまだスケジューリングされていない、すべてのプロセスにまたがるスレッド数 (OS kernel の scheduling entities) を表します。この数には、clickhouse-server だけでなく、すべてのプロセスが含まれます。システムが過負荷状態にあり、実行可能なプロセスが CPU または I/O を待っている場合、この数は CPU コア数を上回ることがあります。

<div id="loadaverage5">
  ### LoadAverage5
</div>

システム全体の負荷を、5分間の指数平滑移動平均で表した値です。この負荷は、現在 CPU で実行中か、I/O を待機中か、あるいは実行可能な状態にありながら現時点ではまだスケジュールされていない、全プロセスにまたがるスレッド数 (OS kernel のスケジューリングエンティティ) を表します。この数値には、`clickhouse-server` だけでなく、すべてのプロセスが含まれます。システムが過負荷の状態で、多くのプロセスが実行可能でありながら CPU または I/O を待っている場合、この数値は CPU コア数を上回ることがあります。

この値は `OSUserTime` に似ていますが、CPU コア数で割ることで、コア数にかかわらず [0..1] の範囲で測定できるようになっています。これにより、クラスター内の複数のサーバーでこのメトリクスの値を平均する際、コア数が均一でなくても、平均的なリソース使用状況を表すメトリクスを得ることができます。指定されている場合は、実際の CPU コア数の代わりに、Cgroup CPU QUOTA をその周期で割った値を使用できます。その場合、このメトリクスの値が一時的に 1 を超えることがあります。
