<div id="description">
  ## 説明
</div>

ローカルサーバー上にあるレプリケートテーブルの情報とステータスが含まれます。
このテーブルは監視に利用できます。Replicated* テーブルごとに1行が含まれます。

<div id="columns">
  ## カラム
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/ja/sql-reference/data-types/string)) — データベース名。
* `table` ([String](/ja/sql-reference/data-types/string)) — テーブル名。
* `uuid` ([UUID](/ja/sql-reference/data-types/uuid)) — テーブル UUID。
* `engine` ([String](/ja/sql-reference/data-types/string)) — テーブルエンジン名。
* `is_leader` ([UInt8](/ja/sql-reference/data-types/int-uint)) — そのレプリカがリーダーかどうか。複数のレプリカが同時にリーダーになることがあります。レプリカがリーダーになるのを防ぐには、merge&#95;tree 設定 `replicated&#95;can&#95;become&#95;leader` を使用できます。リーダーはバックグラウンドマージのスケジューリングを担当します。書き込みは、リーダーかどうかに関係なく、利用可能で ZK にセッションを持つ任意のレプリカに対して実行できる点に注意してください。
* `can_become_leader` ([UInt8](/ja/sql-reference/data-types/int-uint)) — そのレプリカがリーダーになれるかどうか。
* `is_readonly` ([UInt8](/ja/sql-reference/data-types/int-uint)) — そのレプリカが read-only モードかどうか。config に ClickHouse Keeper のセクションがない場合、ClickHouse Keeper でのセッション再初期化時に不明な error が発生した場合、および ClickHouse Keeper でのセッション再初期化中に、このモードが有効になります。
* `readonly_start_time` ([Nullable(DateTime)](/ja/sql-reference/data-types/nullable)) — レプリカが readonly モードに移行した timestamp。レプリカが readonly モードでない場合は Null。
* `is_session_expired` ([UInt8](/ja/sql-reference/data-types/int-uint)) — ClickHouse Keeper とのセッションが期限切れかどうか。基本的には `is_readonly` と同じです。
* `future_parts` ([UInt32](/ja/sql-reference/data-types/int-uint)) — まだ実行されていない INSERT やマージの結果として生成されるデータパーツの数。
* `parts_to_check` ([UInt32](/ja/sql-reference/data-types/int-uint)) — 検証待ちキュー内のデータパーツ数。part が破損している疑いがある場合、その part は検証キューに追加されます。
* `zookeeper_name` ([String](/ja/sql-reference/data-types/string)) — テーブルのメタデータが保存されている [Zoo]Keeper クラスター (補助的なものを含む場合があります) の名前
* `zookeeper_path` ([String](/ja/sql-reference/data-types/string)) — ClickHouse Keeper 内のテーブルデータへのパス。
* `replica_name` ([String](/ja/sql-reference/data-types/string)) — ClickHouse Keeper 内のレプリカ名。同じテーブルの異なるレプリカは異なる名前を持ちます。
* `replica_path` ([String](/ja/sql-reference/data-types/string)) — ClickHouse Keeper 内のレプリカデータへのパス。&#39;zookeeper&#95;path/replicas/replica&#95;path&#39; を連結したものと同じです。
* `columns_version` ([Int32](/ja/sql-reference/data-types/int-uint)) — テーブル構造のバージョン番号。ALTER が何回実行されたかを示します。レプリカごとにバージョンが異なる場合、一部のレプリカでまだすべての ALTER が実行されていないことを意味します。
* `queue_size` ([UInt32](/ja/sql-reference/data-types/int-uint)) — 実行待ちの操作のキューサイズ。操作には、データブロックの INSERT、マージ、およびその他いくつかの actions が含まれます。通常は future&#95;parts と一致します。
* `inserts_in_queue` ([UInt32](/ja/sql-reference/data-types/int-uint)) — 実行が必要なデータブロックの insert 数。Insertion は通常かなり速くレプリケートされます。この数が大きい場合は、何らかの問題があることを意味します。
* `merges_in_queue` ([UInt32](/ja/sql-reference/data-types/int-uint)) — 実行待ちのマージ数。マージに時間がかかることがあるため、この値が長時間 0 より大きいままになる場合があります。
* `part_mutations_in_queue` ([UInt32](/ja/sql-reference/data-types/int-uint)) — 実行待ちの mutations 数。
* `queue_oldest_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — `queue_size` が 0 より大きい場合、最も古い操作がキューに追加された時刻を示します。
* `inserts_oldest_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — `queue_oldest_time` を参照してください。
* `merges_oldest_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — `queue_oldest_time` を参照してください。
* `part_mutations_oldest_time` ([DateTime](/ja/sql-reference/data-types/datetime)) — `queue_oldest_time` を参照してください。
* `oldest_part_to_get` ([String](/ja/sql-reference/data-types/string)) — レプリケーションキュー内の最も古い GET&#95;PARTS エントリから取得された、他のレプリカから取得するパーツ名。
* `oldest_part_to_merge_to` ([String](/ja/sql-reference/data-types/string)) — レプリケーションキュー内の最も古い MERGE&#95;PARTS エントリから取得された、マージ先の結果パーツ名。
* `oldest_part_to_mutate_to` ([String](/ja/sql-reference/data-types/string)) — レプリケーションキュー内の最も古い MUTATE&#95;PARTS エントリから取得された、mutation 後の結果パーツ名。
* `log_max_index` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 一般的なアクティビティログ内の最大エントリ番号。このカラムと後続の 3 つ (`log_pointer`、`total_replicas`、`active_replicas`) は、ClickHouse Keeper とのアクティブなセッションがある場合にのみ 0 以外の値を持ちます。
* `log_pointer` ([UInt64](/ja/sql-reference/data-types/int-uint)) — レプリカが実行キューにコピーした一般的なアクティビティログ内の最大エントリ番号に 1 を加えた値。log&#95;pointer が log&#95;max&#95;index より大幅に小さい場合は、何らかの問題があります。
* `last_queue_update` ([DateTime](/ja/sql-reference/data-types/datetime)) — キューが最後に更新された日時。
* `absolute_delay` ([UInt64](/ja/sql-reference/data-types/int-uint)) — 現在のレプリカの遅延の大きさ (秒) 。
* `total_replicas` ([UInt32](/ja/sql-reference/data-types/int-uint)) — このテーブルで認識されているレプリカの総数。
* `active_replicas` ([UInt32](/ja/sql-reference/data-types/int-uint)) — ClickHouse Keeper にセッションを持つこのテーブルのレプリカ数 (つまり、正常に動作しているレプリカ数) 。
* `lost_part_count` ([UInt64](/ja/sql-reference/data-types/int-uint)) — テーブル作成以降に、このテーブルで全レプリカ合計で失われた data parts の数。値は ClickHouse Keeper に永続化され、増加することしかありません。
* `last_queue_update_exception` ([String](/ja/sql-reference/data-types/string)) — キューに壊れたエントリが含まれている場合に設定されます。特に、ClickHouse がバージョン間の backward compatibility を破り、新しいバージョンで書き込まれた log entries を古いバージョンで解析できない場合に重要です。
* `zookeeper_exception` ([String](/ja/sql-reference/data-types/string)) — ClickHouse Keeper から情報を取得中に error が発生した場合の、最後の exception メッセージ。
* `replica_is_active` ([Map(String, UInt8)](/ja/sql-reference/data-types/map)) — レプリカ名と、そのレプリカがアクティブかどうかの対応を表す Map。

**別名:**

* `readonly_duration` — `if(isNull(readonly_start_time), NULL, now() - readonly_start_time)` の別名。

{/*AUTOGENERATED_END*/ }
