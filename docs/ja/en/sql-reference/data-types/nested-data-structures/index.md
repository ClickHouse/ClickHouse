ネストされたデータ構造は、1 つのセルの中にテーブルが入っているようなものです。ネストされたデータ構造のパラメータ、つまりカラム名と型は、[CREATE TABLE](../../../sql-reference/statements/create/table.md) クエリと同じ方法で指定します。テーブルの各行は、ネストされたデータ構造内の任意の数の行に対応できます。

:::tip[カラム名にドットを使用しないでください]
ドットを含むカラム名、共通のドットプレフィックスを持つカラム、`Array` 型のカラムは、`flatten_nested = 1` (デフォルト) の場合、それぞれフラット化された Nested 構造の一部として解釈されることがあります。その結果、INSERT 時に配列長の予期しない検証や、名前変更の制限が発生する可能性があります。

可能であれば、カラム名にドットは使用しないでください。
意図的に `Nested` のセマンティクスが必要な場合を除き、カラム名ではドットの代わりにアンダースコア (`_`) などの区切り文字を使用してください。
:::

例:

```sql
CREATE TABLE test.visits(
  CounterID UInt32,
  StartDate Date,
  Sign Int8,
  IsNew UInt8,
  VisitID UInt64,
  UserID UInt64,
--highlight-start
  Goals Nested(
    ID UInt32,
    Serial UInt32,
    EventTime DateTime,
    Price Int64,
    OrderID String,
    CurrencyID UInt32
  )
--highlight-end
)
ENGINE = CollapsingMergeTree(Sign)
ORDER BY (StartDate, intHash32(UserID), (CounterID, StartDate, intHash32(UserID), VisitID));
```

上記の `CREATE TABLE` DDL ステートメントでは、コンバージョン、つまり達成された目標に関するデータを含む `Goals` のネストされたデータ構造を宣言しています。
&#39;visits&#39; テーブルの各行は、0 件以上のコンバージョンに対応します。

[`flatten_nested`](/ja/operations/settings/settings#flatten_nested) 設定が `0` の場合 (デフォルトでは `flatten_nested=1`) 、任意のレベルのネストがサポートされます。

ほとんどの場合、ネストされたデータ構造を扱う際には、そのカラムをドット区切りのカラム名で指定します。
これらのカラムは、対応する型の配列を構成します。
1 つのネストされたデータ構造に属するすべてのカラム配列は、同じ長さです。

たとえば:

```sql
SELECT
    Goals.ID,
    Goals.EventTime
FROM test.visits
WHERE CounterID = 101500 AND length(Goals.ID) < 5
ORDER BY VisitID
LIMIT 10
```

<div id="filtering-nested-columns-in-where">
  ### WHERE で Nested カラムを絞り込む
</div>

`Nested` 構造の各カラムは `Array` として格納されるため、`WHERE` 句で参照すると、個々の要素ではなく各行の配列全体が返されます。ネストされたカラムをスカラー値と直接比較することはできないため、代わりに [配列関数](/ja/sql-reference/functions/array-functions) を使う必要があります。

たとえば、次のクエリは単に行を返さないのでは **なく**、例外を発生させます。これは、`Goals.ID` の型が `Array(UInt32)` であり、`equals(Array(UInt32), UInt32)` が有効な比較ではないためです:

```sql
-- WRONG: compares the entire Array to a scalar
SELECT * FROM test.visits
WHERE Goals.ID = 591325;
```

```text
Code: 43. DB::Exception: Illegal types of arguments (`Array(UInt32)`, `UInt32`)
of function `equals`. (ILLEGAL_TYPE_OF_ARGUMENT)
```

Array に特定の値が含まれているかどうかを確認するには、[`has`](/ja/sql-reference/functions/array-functions#has) を使用します。

```sql
-- Find visits that have at least one goal with ID 591325
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE has(Goals.ID, 591325);
```

条件が複雑な場合は、[`arrayExists`](/ja/sql-reference/functions/array-functions#arrayExists) を使用します。

```sql
-- Find visits that have at least one goal with ID greater than 1000000
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE arrayExists(id -> id > 1000000, Goals.ID);
```

`length` を使って配列の長さで絞り込んだり、`notEmpty` を使って空の配列を除外したりできます:

```sql
-- Visits with at least 3 goals
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE length(Goals.ID) >= 3;

-- Visits with at least one goal (non-empty array)
SELECT CounterID, VisitID, Goals.ID
FROM test.visits
WHERE notEmpty(Goals.ID);
```

行全体ではなくネスト構造の個々の要素でフィルタリングするには、まず `ARRAY JOIN` を使って配列を展開します。
`ARRAY JOIN` の後は各要素がそれぞれ отдельの行になるため、`WHERE` 句はスカラー値に適用されます。
詳細については、[`ARRAY JOIN` 句](/ja/sql-reference/statements/select/array-join) を参照してください。例:

```sql
SELECT
    Goal.ID,
    Goal.EventTime
FROM test.visits
ARRAY JOIN Goals AS Goal
WHERE CounterID = 101500 AND length(Goals.ID) < 5
ORDER BY VisitID, Goal.Serial
LIMIT 10
```

<div id="inserting-data">
  ### データの挿入
</div>

`INSERT` クエリでは、ネストされたデータ構造の各サブカラム配列を、それぞれ独立したカラム配列であるかのように個別に渡す必要があります。挿入時には、それらの長さがすべて同じであることがシステムによって確認されます。

各ネストされたサブカラムは、ドット記法 (`Goals.ID`、`Goals.Serial`、...) を使ってカラムリストに記載し、対応する値は配列として指定します。

```sql
INSERT INTO test.visits
    (CounterID, StartDate, Sign, IsNew, VisitID, UserID,
     Goals.ID, Goals.Serial, Goals.EventTime, Goals.Price, Goals.OrderID, Goals.CurrencyID)
VALUES
    -- A visit with two goals: each nested sub-column gets an array of length 2
    (101500, '2014-03-18', 1, 1, 2001, 200001,
     [1073752, 591325], [1, 2],
     ['2014-03-18 10:00:00', '2014-03-18 10:05:00'],
     [100, 200], ['order_a', 'order_b'], [1, 2]),
    -- A visit with no goals: all nested sub-columns get empty arrays
    (101500, '2014-03-18', 1, 0, 2002, 200002,
     [], [], [], [], [], []);
```

1 行内のすべてのネストされたサブカラム配列は、同じ長さである必要があります。長さが一致しないとエラーになります：

```sql
-- ERROR: Goals.ID has 2 elements, but Goals.Serial has 1
INSERT INTO test.visits
    (CounterID, StartDate, Sign, IsNew, VisitID, UserID,
     Goals.ID, Goals.Serial, Goals.EventTime, Goals.Price, Goals.OrderID, Goals.CurrencyID)
VALUES
    (101500, '2014-03-18', 1, 1, 2003, 200003,
     [1073752, 591325], [1],
     ['2014-03-18 12:00:00'], [0], [''], [0]);
```

`DESCRIBE`クエリでは、ネストされたデータ構造内のカラムも同様に個別に表示されます。

<div id="alter-limitations">
  ### ALTER の制限
</div>

ネストされたデータ構造に対する`ALTER`クエリには、次の制限があります。

**サブカラムの追加**は通常どおり可能です。既存の`Nested`構造に新しいサブカラムを追加できます。

```sql
ALTER TABLE test.visits ADD COLUMN Goals.Revenue Float64;
```

**サブカラムの削除**は、個々のサブカラムにも適用できます:

```sql
ALTER TABLE test.visits DROP COLUMN Goals.Revenue;
```

**型の変更**はサブカラムでも可能で、ミューテーション (データの書き換え) がトリガーされます:

```sql
ALTER TABLE test.visits MODIFY COLUMN Goals.Price Int32;
```

**名前の変更**には制限があります。同じネスト構造内のサブカラムであれば、名前を変更できます。

```sql
-- OK: stays within the Goals structure
ALTER TABLE test.visits RENAME COLUMN Goals.Price TO Goals.Amount;
```

ただし、**できない**こともあります。

* ネスト構造全体そのものをリネームすること (例: `Goals` を `Conversions` に変更) 。
* サブカラムを別のネスト構造へ移動すること (例: `Goals.ID` を `OtherNested.ID` に移動) 。
* サブカラムをネスト構造の外へ移動したり、ネスト構造内へ移動したりすること (例: `Goals.ID` を `GoalID` に移動、またはその逆) 。
