<div id="overview">
  ## 概要
</div>

:::note
このセクションで説明する関数は、最大のパフォーマンスが得られるよう最適化されており、ほとんどの場合 RFC-3986 標準には準拠していません。
RFC-3986 を実装している関数には、関数名の末尾に `RFC` が付き、一般に低速です。
:::

一般に、ユーザー文字列や `@` 記号を含まない公開登録済みドメインを扱う場合は、非 `RFC` の関数バリアントを使用できます。
以下の表は、URL 内のどの記号を、それぞれの `RFC` および非 `RFC` バリアントでパースできるか (`✔`) またはできないか (`✗`) を示しています。

| 記号          | non-`RFC` | `RFC` |   |
| ----------- | --------- | ----- | - |
| &#39; &#39; | ✗         | ✗     |   |
| \t          | ✗         | ✗     |   |
| &lt;        | ✗         | ✗     |   |
| &gt;        | ✗         | ✗     |   |
| %           | ✗         | ✔*    |   |
| &#123;      | ✗         | ✗     |   |
| &#125;      | ✗         | ✗     |   |
|             |           | ✗     | ✗ |
| &#92;&#92;  | ✗         | ✗     |   |
| ^           | ✗         | ✗     |   |
| ~           | ✗         | ✔*    |   |
| [           | ✗         | ✗     |   |
| ]           | ✗         | ✔     |   |
| ;           | ✗         | ✔*    |   |
| =           | ✗         | ✔*    |   |
| &amp;       | ✗         | ✔*    |   |

`*` が付いた記号は RFC 3986 におけるサブ区切り文字であり、`@` 記号に続くユーザー情報で使用できます。

URL 関数には 2 種類あります。

* URL の一部を抽出する関数。該当する部分が URL に存在しない場合は、空文字列が返されます。
* URL の一部を削除する関数。URL に対応する部分がない場合、URL は変更されません。
