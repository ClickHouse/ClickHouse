## 説明 {#description}

[`JSONEachRow`](/ja/reference/formats/JSON/JSONEachRow)/[`JSONStringsEachRow`](/ja/reference/formats/JSON/JSONStringsEachRow)とは異なり、ClickHouse は各イベントを個別の JSON オブジェクトとしてストリーミングし、進捗情報も出力します。

関連する `JSONStringsEachRowWithProgress` フォーマットも同じ種類のトップレベルオブジェクトを使用しますが、フィールドの値は文字列としてシリアル化されます。

Compact 版の姉妹フォーマットである `JSONCompactEachRowWithProgress` と `JSONCompactStringsEachRowWithProgress` も、ストリームオブジェクトの種類は同じで、進捗・`LIMIT`・例外に関する注意点も共通です。ただし、`row` / `totals` / `min` / `max` のペイロードは、名前付きオブジェクトではなく値の配列になります。

## ストリームオブジェクト {#stream-objects}

レスポンスの各行は 1 つの JSON オブジェクトです。クライアントはトップレベルのキーに応じて処理を振り分けてください。

| トップレベルのキー                    | 出現タイミング                                                                | 形状                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `meta`                       | 最初の `row` の前に 1 回 (`progress` オブジェクトがこれより先に出力される場合があります)               | `{"meta":[{"name":...,"type":...}, ...]}` — カラム名と型                                     |
| `row`                        | 結果の行ごとに 1 回                                                            | `{"row":{...}}` — その行のカラム値                                                             |
| `progress`                   | クエリの実行中に定期的に                                                           | `{"progress":{...}}` — `read_rows`、`read_bytes`、`total_rows_to_read` などのカウンター          |
| `totals`                     | totals が存在する場合                                                         | `{"totals":{...}}` — totals 行の値                                                        |
| `min` / `max`                | 極値が存在する場合                                                              | `{"min":{...}}` / `{"max":{...}}` — 極値の行の値                                             |
| `rows_before_limit_at_least` | クエリに `LIMIT` が含まれる場合                                                   | `{"rows_before_limit_at_least":N}` — `LIMIT` がなかった場合の行数の下限推定値 (行が除外されたことを示すものではありません)  |
| `rows_before_aggregation`    | クエリが集約を行い、かつ `rows_before_aggregation` カウンターが有効な場合                     | `{"rows_before_aggregation":N}`                                                        |
| `exception`                  | HTTP 経由で `http_write_exception_in_output_format=1` が指定されており、クエリが失敗した場合 | `{"exception":"..."}` — エラーテキストは `row` の下にネストされず、**トップレベルの文字列**として出力されます               |

`rows_before_limit_at_least` オブジェクトは、クエリに `LIMIT` が含まれていれば、実際には LIMIT によって行が除外されなかった場合でも出力されます。これは `LIMIT` がなかった場合の行数の下限推定値であり (意味は `JSON` フォーマットと同じです) 、クライアントはこれを行が除外された根拠として扱ってはいけません。

`meta` は最初の `row` の前に 1 回出力されますが、`progress` オブジェクトが `meta` より先に届く場合があります。トップレベルの `exception` オブジェクトが出力されるのは、HTTP 経由で `http_write_exception_in_output_format=1` が指定されている場合のみです。それ以外の場合、エラーはトランスポート層を通じて通知されます。出力される場合は `row` の下にネストされず、独立したトップレベルのオブジェクトとなります。

## 使用例 {#example-usage}

```json
{"meta":[{"name":"num","type":"UInt8"},{"name":"str","type":"String"},{"name":"arr","type":"Array(UInt8)"}]}
{"row":{"num":42,"str":"hello","arr":[0,1]}}
{"row":{"num":43,"str":"hello","arr":[0,1,2]}}
{"row":{"num":44,"str":"hello","arr":[0,1,2,3]}}
{"progress":{"read_rows":"3","read_bytes":"24","written_rows":"0","written_bytes":"0","total_rows_to_read":"3"}}
```

`meta` より前に `progress` オブジェクトが出力される場合もあります。HTTP 経由で `http_write_exception_in_output_format=1` が設定されている場合、失敗したクエリの出力は、(`row` の下にネストされない) 独立したトップレベルのオブジェクトで終わります。

```json
{"exception":"Code: 62. DB::Exception: Syntax error: failed at position 1 (SELECT) (line 1, col 1): ..."}
```
