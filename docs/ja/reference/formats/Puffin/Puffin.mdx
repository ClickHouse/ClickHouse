## 説明 {#description}

[Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/) ファイルの読み取りおよび書き込みに使用するフォーマットです。

このフォーマットは、`deletion-vector-v1` ブロブに含まれる削除された行位置を公開します。`apache-datasketches-theta-v1` など他の種類のブロブは、Puffin 仕様の要求どおりスキップされます。これらを確認するには `PuffinMetadata` を使用してください。
Puffin ファイルに複数の `deletion-vector-v1` ブロブが含まれている場合、このフォーマットはブロブごとに 1 行を出力します。

固定の出力カラム:

* `referenced_data_file` (`String`) - 削除ベクトルの適用対象となるデータファイルの場所 (`referenced-data-file` ブロブプロパティ) 
* `deleted_rows` (`Array(UInt64)`) - 削除ベクトルの roaring bitmap に基づいて削除された 64 ビットの行位置

出力フォーマットとして使用する場合、入力には、このフォーマットが読み取り時に生成するのと同じ 2 つのカラム、すなわち参照先データファイル (`String` または `LowCardinality(String)`) と、削除された行位置 (1 行につき 1 つの位置を表す整数、または整数の配列) が必要です。ファイルには、参照先データファイルごとに 1 つの `deletion-vector-v1` ブロブが、データファイルの場所順に格納されます。そのため、複数の削除ベクトルを含む Puffin ファイルをそのままコピーできます。同じ参照先データファイルを持つすべての行の位置は 1 つの削除ベクトルにマージされ、重複排除およびソートされます。負の位置、Iceberg の削除ベクトルの上限を超える位置、および空のデータファイルの場所は拒否されます。ブロブのメタデータは、Apache Iceberg が削除ベクトルを書き込む場合と同じ形で書き込まれます。`fields` は `[2147483645]` (`_pos` メタデータカラムの id) 、`snapshot-id` と `sequence-number` は `-1` となり、`referenced-data-file` と `cardinality` プロパティが設定されます。フッターは非圧縮のため、生成されたファイルは Iceberg v3 テーブルに削除ベクトルの削除ファイルとして登録でき、Apache Spark などの他のエンジンでも読み取れます。マニフェストの `content_offset` および `content_size_in_bytes` フィールドに使用する各ブロブの `offset` と `length` は、書き込み済みのファイルに対して `PuffinMetadata` を使用して取得してください。

設定 `output_format_puffin_blob_type` を `apache-datasketches-theta-v1` にすると、このフォーマットは代わりに Apache Iceberg と同じ形でカラム統計情報を書き込みます。各入力カラムは 1 つの `apache-datasketches-theta-v1` ブロブとなり、カラムの非 null 値に対するコンパクトな Apache DataSketches Theta スケッチ (デフォルトのシードとサイズ) を含みます。また、`ndv` プロパティには推定された異なる値の数が設定されます。値はカラム型に応じた Iceberg の単一値バイナリシリアライゼーションでスケッチに投入されるため、Apache Spark が書き込んだスケッチとマージできます。型の対応は次のとおりです: `Bool` は `boolean`、`Int8`、`UInt8`、`Int16`、`UInt16`、`Int32` は `int`、`UInt32`、`Int64`、`UInt64` は `long` (`Int64` の範囲を超える `UInt64` の値はビット列をそのまま保持) 、`Float32` は `float`、`Float64` は `double`、`Date` と `Date32` は `date`、精度 6 桁までの `DateTime` と `DateTime64` は `timestamp` (マイクロ秒単位) 、`String` は `string`、`FixedString` は `fixed`、`UUID` は `uuid`、`Decimal` は `decimal`。これらの型の `Nullable` および `LowCardinality` もサポートされます。Iceberg と同様に、空文字列は無視されます。ブロブの `fields` は設定 `output_format_puffin_field_ids` から、`snapshot-id` と `sequence-number` は設定 `output_format_puffin_snapshot_id` と `output_format_puffin_sequence_number` から取得されます。リーダーは統計情報を、これらの設定で指定されたカラムとスナップショットに関連付けるため、3 つの設定はいずれも必須です。結果は Iceberg の統計ファイルとして登録できます。

`deleted_rows` が要求された場合、宣言された `cardinality` がマテリアライズの絶対上限を超える削除ベクトルは拒否されます。フッターの `deletion-vector-v1` プロパティ (`cardinality` が符号なし整数としてパースできるかどうかを含む) は常に検証されます。`referenced_data_file` のみを選択した場合は on-disk のペイロード I/O が行われないため、エンベロープ、CRC、roaring のデシリアライズ、およびマテリアライズの上限チェックもスキップされます。これは、パスのみを射影する場合にブロブサイズの上限まで読み取ってしまわないようにするための意図的な動作です。

on-disk の `deletion-vector-v1` ブロブの長さは、絶対上限 (Iceberg の 2 GiB のコンテンツサイズチェックに準拠) によって制限されます。`deleted_rows` が要求された場合、リーダーはペイロード全体を割り当てる前にエンベロープヘッダー (結合長とマジック) を先読みします。CRC は、上限付きの読み取りが完了した後に検証されます。

LZ4 圧縮および非圧縮の puffin フッターがサポートされています。フッターペイロードサイズ (および宣言された LZ4 コンテンツサイズ) は、該当する場合、圧縮率と絶対上限によって制限されます。大きすぎるフッターは割り当て前に拒否されます。

要求できる出力カラムは一部に限られます。想定外のカラム名または型を含むユーザー提供の構造は、フォーマットの作成時に拒否されます。

## 使用例 {#example-usage}

参照先のデータファイルで削除された行位置を読み取ります：

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

削除された位置を個別の行に展開します。

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

削除ベクトルを読み取る前に、`PuffinMetadata` を使用してフッター内のブロブディスクリプタを確認します。

2 つのデータファイルの削除ベクトルを 1 つの Puffin ファイルに書き込みます：

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

2つのカラムの Theta スケッチを Iceberg 統計ファイルとして書き込みます：

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
