## 説明 {#description}

`Pretty` フォーマットは、データを Unicode アートのテーブルとして出力し、
端末で色を表示するために ANSI エスケープシーケンスを使用します。
テーブル全体の罫線が描画され、各行は端末上で 2 行分を使用します。
各結果ブロックは個別のテーブルとして出力されます。
これは、結果をバッファリングせずにブロックを出力できるようにするために必要です (すべての値の表示幅を事前に計算するにはバッファリングが必要になるためです) 。

[NULL](/ja/reference/syntax) は `ᴺᵁᴸᴸ` として出力されます。

## 使用例 {#example-usage}

例 ([`PrettyCompact`](/ja/reference/formats/Pretty/PrettyCompact) フォーマットで表示した場合) :

```sql title="Query"
SELECT * FROM t_null
```

```response title="Response"
┌─x─┬────y─┐
│ 1 │ ᴺᵁᴸᴸ │
└───┴──────┘
```

どの `Pretty` フォーマットでも、行はエスケープされません。代わりに、値およびカラム名に含まれる印字不可能な制御文字 (C0 制御文字 `0x00`-`0x1F` および `DEL` `0x7F`) は、デフォルトで対応する Unicode の &quot;Control Pictures&quot; (`U+2400`-`U+2421`) として表示されます。これにより、制御文字が目に見える形で表示され、テーブルのレイアウトが崩れるのを防ぎます。たとえば、NUL は `␀` と表示されます。

```sql title="Query"
SELECT 'String with a NUL \0 character' AS Escaping_test FORMAT PrettyCompact
```

```response title="Response"
┌─Escaping_test─────────────────┐
│ String with a NUL ␀ character │
└───────────────────────────────┘
```

`TAB`、改行、`ESC` は例外で、常にそのまま出力されます。端末はこれらを読み飛ばさずに解釈するためです。タブは次のタブストップまで位置を進め、ANSI エスケープシーケンスを使えばデータに視覚表現を持たせることができます。改行も通常どおり行を改めます。[`output_format_pretty_multiline_fields`](/ja/reference/settings/formats#output_format_pretty_multiline_fields) が有効な場合はテーブルのセル内で改行され、それ以外の場合はそのまま出力されます。ただし、カラム名はこの例外のさらに例外です。ヘッダーとフッターは 1 行で表示されるため、名前に含まれる改行は他の制御文字と同様に置き換えられます。

制御文字を置き換えずにそのまま出力するには、[`output_format_pretty_display_control_characters`](/ja/reference/settings/formats#output_format_pretty_display_control_characters) を無効にします。

```sql title="Query"
SELECT 'String with a NUL \0 character' AS Escaping_test FORMAT PrettyCompact
SETTINGS output_format_pretty_display_control_characters = 0
```

その場合、レスポンスには代わりに生の `NUL` バイトがそのまま含まれます。端末はこのバイトを表示せずに読み飛ばすため、文字は見えなくなり、
その行は計測された罫線よりも 1 文字分だけ幅が広くなります。これが、Control Picture を表示することで回避できる
テーブルの崩れです。

端末に大量のデータをダンプしすぎないよう、最初の `10,000` 行のみが出力されます。
行数が `10,000` 以上の場合は、&quot;Showed first 10 000&quot; というメッセージが出力されます。

<Note>
  このフォーマットはクエリ結果の出力にのみ適しており、データのパースには適していません。
</Note>

Pretty フォーマットは、合計値 (`WITH TOTALS` を使用した場合) と極値 (&#39;extremes&#39; が 1 に設定されている場合) の出力をサポートしています。
この場合、合計値と極値はメインデータの後に、それぞれ別のテーブルとして出力されます。
この動作は、[`PrettyCompact`](/ja/reference/formats/Pretty/PrettyCompact) フォーマットを使用する次の例で示されています。

```sql title="Query"
SELECT EventDate, count() AS c 
FROM test.hits 
GROUP BY EventDate 
WITH TOTALS 
ORDER BY EventDate 
FORMAT PrettyCompact
```

```response title="Response"
┌──EventDate─┬───────c─┐
│ 2014-03-17 │ 1406958 │
│ 2014-03-18 │ 1383658 │
│ 2014-03-19 │ 1405797 │
│ 2014-03-20 │ 1353623 │
│ 2014-03-21 │ 1245779 │
│ 2014-03-22 │ 1031592 │
│ 2014-03-23 │ 1046491 │
└────────────┴─────────┘

Totals:
┌──EventDate─┬───────c─┐
│ 1970-01-01 │ 8873898 │
└────────────┴─────────┘

Extremes:
┌──EventDate─┬───────c─┐
│ 2014-03-17 │ 1031592 │
│ 2014-03-23 │ 1406958 │
└────────────┴─────────┘
```
