トランザクション制御文 `BEGIN TRANSACTION`、`COMMIT`、`ROLLBACK`、`SET TRANSACTION SNAPSHOT` は、`MergeTree` テーブルに対する複数のクエリを 1 つのトランザクションにまとめます。
トランザクション内のクエリは、他のトランザクションがコミットした変更について、一貫性のある単一のスナップショットを読み取ります。
トランザクション外での書き込みは分離されません。トランザクション外で実行された `INSERT`、`TRUNCATE TABLE`、`ALTER TABLE ... DELETE` は、実行中のトランザクションの次のクエリから参照できます。そのため、安定したビューを得るには、書き込み側もトランザクションを使用する必要があります (例: [`implicit_transaction`](/ja/reference/settings/session-settings/implicit#implicit_transaction) を使用する) 。
トランザクションによる変更は `COMMIT` 後に初めて他のトランザクションから参照可能になり、`ROLLBACK` を実行すると破棄されます。
トランザクション外で実行されるクエリからは、実行中のトランザクションの変更がコミット前に参照できます。

## 構文 {#syntax}

```sql
BEGIN TRANSACTION
START TRANSACTION
COMMIT
ROLLBACK
SET TRANSACTION SNAPSHOT snapshot
```

トランザクションは session に属し、1 つの session が持てるトランザクションは最大 1 つです。
HTTP 経由では、トランザクション内のすべてのクエリを同じ `session_id` で送信してください。`session_id` を指定しないリクエストはそれぞれ専用の session で実行され、その session はリクエストの終了とともに終了します。
session の終了時点でまだ実行中のトランザクションはロールバックされます。

## BEGIN TRANSACTION {#begin-transaction}

現在のセッションでトランザクションを開始します。`START TRANSACTION` はこのステートメントの別名で、v24.3.0 で導入されました。

ネストされたトランザクションはサポートされていません。トランザクション内で `BEGIN TRANSACTION` を実行すると、`INVALID_TRANSACTION` 例外がスローされます。

## COMMIT {#commit}

現在のトランザクションをコミットし、その変更を他のトランザクションから参照できるようにします。
現在のトランザクションが存在しない状態で `COMMIT` を実行すると、`INVALID_TRANSACTION` 例外がスローされます。

トランザクション内のクエリが失敗すると、そのトランザクションはロールバックされます。一方、構文エラーなどによりパースできないクエリや、クエリパラメータが欠損または無効なクエリは実行されず、トランザクションは継続中のままとなります。そのため、後続の `COMMIT` でトランザクションはそのままコミットされます。
ロールバックされたトランザクションを `ROLLBACK` で終了するまでは、`COMMIT` およびそれ以降のクエリはすべて `INVALID_TRANSACTION` 例外をスローします。この状態でも実行できるのは、`ROLLBACK`、`SET TRANSACTION SNAPSHOT`、および `EXPLAIN ANALYZE` を除く `EXPLAIN` クエリのみです。

`COMMIT` が何を待機するかは、[`wait_changes_become_visible_after_commit_mode`](/ja/reference/settings/session-settings/other#wait_changes_become_visible_after_commit_mode) 設定で制御します。

## ROLLBACK {#rollback}

現在のトランザクションをロールバックし、その変更を破棄します。
現在のトランザクションが存在しない状態で `ROLLBACK` を実行すると、`INVALID_TRANSACTION` 例外がスローされます。

## SET TRANSACTION SNAPSHOT {#set-transaction-snapshot}

現在のトランザクションが読み取るスナップショットを、コミットシーケンス番号 (CSN) `snapshot` に変更します。たとえば、以前のトランザクションで [`transactionLatestSnapshot`](/ja/reference/functions/regular-functions/other-functions#transactionLatestSnapshot) が返した値を指定できます。
変更後、トランザクションからは自身の変更、トランザクション外で書き込まれたデータ、およびその CSN までにコミットされたトランザクションの変更が参照できます。
読み取れるのはサーバーがまだ保持しているパーツのみで、それらのパーツが削除されないよう保護されるわけではありません。マージ、ミューテーション、または別のクエリによってパーツが削除された時点より前に開始された実行中のトランザクションがなくなると、サーバーはそのパーツを削除できるようになり、それより前のスナップショットからはその行が参照できなくなります。
履歴データの反復可能読み取り (repeatable read) を目的として `SET TRANSACTION SNAPSHOT` を使用しないでください。
現在のトランザクションがない状態で `SET TRANSACTION SNAPSHOT` を実行すると、`INVALID_TRANSACTION` 例外がスローされます。

`0` から `32` までの値は予約されており、次の 2 つを除いて `INVALID_TRANSACTION` 例外をスローします。
`1` を指定すると、トランザクション外で書き込まれたデータとトランザクション自身の変更のみが可視になります。`3` を指定すると、まだコミットされていないトランザクションのパーツや、トランザクションによって削除またはロールバックされたパーツを含め、テーブルのすべてのパーツが可視になります。

## トランザクション内のクエリ {#queries-inside-a-transaction}

トランザクション内では、`SELECT`、`INSERT`、`DELETE`、`OPTIMIZE`、`TRUNCATE TABLE`、`SET`、`EXPLAIN` の各クエリに加え、`ALTER TABLE` のミューテーションおよびパーティション操作を実行できます。
それ以外のクエリ (たとえば `CREATE TABLE`、`UPDATE`、`ALTER TABLE ... ADD COLUMN`) は `NOT_IMPLEMENTED` 例外をスローします。トランザクションをサポートしていないテーブル (たとえば `ReplicatedMergeTree` テーブルや `Memory` テーブル、`system.transactions`) に対するクエリも同様です。

トランザクション内では非同期挿入はサポートされていません。一方で [`async_insert`](/ja/reference/settings/session-settings/async-insert#async_insert) はデフォルトで有効になっているため、`SET async_insert = 0` などで `async_insert` を無効化しない限り、トランザクション内の `INSERT ... VALUES` や `INSERT ... SELECT` は `NOT_IMPLEMENTED` 例外をスローします。

[`throw_on_unsupported_query_inside_transaction`](/ja/reference/settings/session-settings/throw-on#throw_on_unsupported_query_inside_transaction) を `0` に設定すると、これらのクエリの一部は例外をスローせず、トランザクションの外で実行されます。そのため、`ROLLBACK` を実行しても取り消されません。たとえば、`CREATE TABLE` や `Memory` テーブルへの `INSERT` がこれに該当します。

[`implicit_transaction`](/ja/reference/settings/session-settings/implicit#implicit_transaction) を有効にすると、トランザクションの外で実行されるクエリはそれぞれ個別のトランザクション内で実行されます。このトランザクションは、クエリが成功するとコミットされ、失敗するとロールバックされます。

## 例 {#examples}

挿入のロールバック:

```sql title="Query"
CREATE TABLE t (n UInt64) ENGINE = MergeTree ORDER BY n;
SET async_insert = 0;

BEGIN TRANSACTION;
INSERT INTO t VALUES (1);
SELECT count() FROM t;
ROLLBACK;
SELECT count() FROM t;
```

```text title="Response"
┌─count()─┐
│       1 │
└─────────┘
┌─count()─┐
│       0 │
└─────────┘
```

挿入をコミットする例：

```sql title="Query"
BEGIN TRANSACTION;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```text title="Response"
┌─n─┐
│ 2 │
└───┘
```
