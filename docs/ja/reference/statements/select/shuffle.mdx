`SHUFFLE` 句は、クエリ結果の行を一様ランダムな順序で返します。[ORDER BY](/ja/reference/statements/select/order-by) 句の代わりに使用するもので、ORDER BY 句と併用することはできません。

`ORDER BY rand()` と同じ結果を返しますが、計算量は O(n * log(n)) ではなく O(n) です。

`SHUFFLE` は、`LIMIT` なしで使用してすべての行の順序をランダム化することも、`LIMIT n` と組み合わせて `n` 行の一様ランダムなサンプル (これもランダムな順序で返されます) を取得することもできます。`LIMIT n` を指定した場合、各ストリームは `n` 行のみを保持するため、メモリ使用量はクエリ結果の行数に関係なく O(n) となります。`OFFSET` および `LIMIT BY` は、`ORDER BY` の場合と同様に使用できます。

<Note>
  これは実験的機能です。使用するには、設定 [`allow_experimental_shuffle_query`](/ja/reference/settings/session-settings#allow_experimental_shuffle_query) を有効化してください。
</Note>

## 実装の詳細 {#implementation-details}

ランダムな選択はその都度 (ジャストインタイムで) 行われ、行に対してランダムな値が事前に生成または保存されることはありません。`LIMIT` がない場合、各行は `max_threads` 個のストリームのうちランダムに選ばれた 1 つに送られます。各ストリームは Fisher-Yates アルゴリズムによって並列にシャッフルされ (CPU キャッシュに収まる単位で処理されます)、最後にストリームが連結されます。`LIMIT n` がある場合、各ストリームはリザーバサンプリングによって `n` 行の一様ランダムなサンプルを保持します。このとき、サンプルに入り得ない行は参照されずにスキップされます。その後、サンプルがマージされます。各ストリームから取り出す行数は、各ストリームの行数に対する非復元抽出によって決定されます。分散クエリでは、リモートサーバーがデータをシャッフルし、ソート済みのランダムなキーを行に付与します。イニシエーターはシャッフルされたストリームをこのキーに基づいてマージします。この処理に必要なメモリは O(1) です。

`LIMIT` がない場合、`SHUFFLE` はすべての行をメモリ上に保持します。`ORDER BY` とは異なり、データをディスクに退避することはありません。

ランダムな値がクエリ内の他の箇所で使用されておらず、かつ外部ソートが無効な場合、`ORDER BY rand()` および `ORDER BY rand64()` は `SHUFFLE` と同じ方法で実行できます (設定 `query_plan_use_shuffle_for_order_by_rand`)。外部ソートが設定されている場合は、有限の `LIMIT` が指定されていてもこの最適化は無効化されます。サンプルがメモリに収まらない可能性があり、`SHUFFLE` はディスクにスピルできないためです。有限の上限が指定された `ORDER BY rand64()` では、ランダムな値のすべてのビットを保持するため、ソートが引き続き使用されます。

## 例 {#examples}

```sql
SET allow_experimental_shuffle_query = 1;

SELECT number FROM numbers(5) SHUFFLE;
```

```text
┌─number─┐
│      3 │
│      0 │
│      4 │
│      1 │
│      2 │
└────────┘
```

ランダムにサンプリングした3行：

```sql
SELECT number FROM numbers(1000000) SHUFFLE LIMIT 3;
```

```text
┌─number─┐
│ 493721 │
│  20857 │
│ 871324 │
└────────┘
```

`FROM` 句の後に置かれた `SHUFFLE` はキーワードとして扱われます。`shuffle` をテーブルの別名として使用するには、`AS shuffle` と記述してください。
