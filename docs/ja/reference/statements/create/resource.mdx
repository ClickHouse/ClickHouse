導入バージョン: v24.11.0

[ワークロードスケジューリング](/ja/concepts/features/configuration/server-config/workload-scheduling) 用のリソースを作成します。リソースとは、ディスクの読み取りや CPU時間など、[`CREATE WORKLOAD`](/ja/reference/statements/create/workload) で作成されたワークロード間でスケジューリングされるアクセスの種類を指します。

## 構文 {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`、`IF NOT EXISTS`、`ON CLUSTER` は [`CREATE WORKLOAD`](/ja/reference/statements/create/workload#syntax) の場合と同様に動作します。

## アクセスモード {#access-modes}

| アクセスモード                                       | スケジューリング対象のアクセス                                                                                                           | 導入バージョン  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | ディスク `disk_name` に対する読み取りまたは書き込み。[リソース](/ja/concepts/features/configuration/server-config/workload-scheduling#resources) を参照 | v24.11.0 |
| `READ ANY DISK`, `WRITE ANY DISK`             | 任意のディスクに対する読み取りまたは書き込み                                                                                                    | v24.11.0 |
| `MASTER THREAD`, `WORKER THREAD`              | CPU。[CPU スケジューリング](/ja/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling) を参照                 | v25.4.0  |
| `QUERY`                                       | クエリスロット。[クエリスロットのスケジューリング](/ja/concepts/features/configuration/server-config/workload-scheduling#query_scheduling) を参照       | v25.6.0  |
| `MEMORY RESERVATION`                          | メモリ。[メモリ予約](/ja/concepts/features/configuration/server-config/workload-scheduling#memory-reservations) を参照                   | v26.6.2  |

1 つのリソースに指定するアクセスモードは、ディスク、CPU スレッド、`QUERY`、`MEMORY RESERVATION` のいずれか 1 種類に統一する必要があります。`MASTER THREAD`、`WORKER THREAD`、`QUERY`、`MEMORY RESERVATION` は、それぞれ最大 1 つのリソースにしか属することができません。`CREATE OR REPLACE RESOURCE` ではリソースの種類を変更できないため、リソースを削除してから再作成してください。

<Note>
  `MEMORY RESERVATION` は実験的な機能です。SQL インターフェースや動作は今後のリリースで変更される可能性があります。
</Note>

## ストレージ {#storage}

リソースはワークロードと同様の方法で保存されます。詳しくは[ストレージ](/ja/reference/statements/create/workload#storage)を参照してください。リソースの一覧は [`system.resources`](/ja/reference/system-tables/resources) テーブルで確認できます。

## 権限 {#privileges}

`CREATE RESOURCE` を実行するには、`CREATE RESOURCE` 権限が必要です。`CREATE OR REPLACE RESOURCE` の場合は、これに加えて `DROP RESOURCE` 権限も必要です。

## 例 {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"

└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
