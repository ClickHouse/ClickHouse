導入バージョン: v24.11.0

ワークロードを作成します。ワークロードとは、[ワークロードスケジューリング](/ja/concepts/features/configuration/server-config/workload-scheduling)がワークロード間でリソースを共有する際に用いる階層内のノードです。スケジューリング対象となるリソースは [`CREATE RESOURCE`](/ja/reference/statements/create/resource) で作成します。

## 構文 {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - 既存のワークロードの定義を置き換えます。`IF NOT EXISTS` と併用することはできません。
* `IF NOT EXISTS` - `name` という名前のワークロードが既に存在する場合、このクエリは何も行いません。
* `IN parent_name` - ワークロード `parent_name` の子としてワークロードを作成します。`IN` を指定しないワークロードはルートワークロードになります。ワークロードの循環は拒否されます。
* `SETTINGS` - ワークロードのスケジューリング設定です。`weight`、`priority`、`max_concurrent_threads`、`max_bytes_per_second` などがあり、詳細は [ワークロード階層](/ja/concepts/features/configuration/server-config/workload-scheduling#workloads) で説明しています。`FOR resource_name` を付けた設定はそのリソースにのみ適用され、付けない場合はすべてのリソースに適用されます。不明な設定を指定するとエラーになります。

ワークロードとリソースは名前空間が別々であるため、ワークロードとリソースに同じ名前を付けることができます。クエリは、その [`workload`](/ja/reference/settings/session-settings/other#workload) 設定で指定されたワークロード内で実行されます。詳しくは [ワークロードの指定](/ja/concepts/features/configuration/server-config/workload-scheduling#workload-markup) を参照してください。

<Note>
  メモリ予約スケジューリング (`MEMORY RESERVATION` リソース、およびワークロード設定 `max_memory`、`max_memory_ratio`、`max_memory_before_spill`、`max_memory_to_spill_ratio`) は実験的な機能です。[メモリ予約](/ja/concepts/features/configuration/server-config/workload-scheduling#memory-reservations) を参照してください。
</Note>

## ストレージ {#storage}

ワークロードはディスク上の [`workload_path`](/ja/reference/settings/server-settings/settings/workload#workload_path) に保存されます。[`workload_zookeeper_path`](/ja/reference/settings/server-settings/settings/workload#workload_zookeeper_path) が設定されている場合は、ZooKeeper 上のそのパスに保存されます。ZooKeeperストレージを使用する場合、定義は自動的にレプリケーションされるため、`ON CLUSTER` は拒否されます。[サーバー構成で定義された](/ja/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads)ワークロードは、SQL で置換または削除できません。ワークロードの一覧は [`system.workloads`](/ja/reference/system-tables/workloads) テーブルで確認できます。

## 権限 {#privileges}

`CREATE WORKLOAD` を実行するには `CREATE WORKLOAD` 権限が必要です。`CREATE OR REPLACE WORKLOAD` を実行するには、これに加えて `DROP WORKLOAD` 権限も必要です。

## 例 {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
