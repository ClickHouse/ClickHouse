複数のステートメントを並列に実行できます。

## 構文 {#syntax}

```sql
statement1 PARALLEL WITH statement2 [PARALLEL WITH statement3 ...]
```

ステートメント `statement1`、`statement2`、`statement3`、... を互いに並列実行します。組み合わせることができるのは、結果セットを返さず、入力データも必要としないステートメントのみです。詳しくは[制限](#restrictions)を参照してください。

多くの場合、ステートメントを並列に実行する方が、同じステートメントを単に順番に実行するよりも高速です。たとえば、`statement1 PARALLEL WITH statement2 PARALLEL WITH statement3` は、`statement1; statement2; statement3` より高速になる可能性があります。

## 例 {#examples}

2 つのテーブルを並列に作成します：

```sql
CREATE TABLE table1(x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2(y String) ENGINE = MergeTree ORDER BY tuple();
```

2つのテーブルを並列に削除します:

```sql
DROP TABLE table1
PARALLEL WITH
DROP TABLE table2;
```

## 制限 {#restrictions}

`SELECT` のように結果セットを返すステートメントや、入力データを必要とするステートメントは、`INCORRECT_QUERY` エラーで拒否されます。

[`ON CLUSTER`](/ja/reference/statements/distributed-ddl) で実行される DDL や、[`Replicated`](/ja/reference/engines/database-engines/replicated) データベースの DDLログを介して実行される DDL はステータステーブルを返すため、これらも拒否されます。ただし、拒否されるのはホストへの送信後であり、ホスト側ではそのまま実行されます。[`distributed_ddl_output_mode`](/ja/reference/settings/session-settings/distributed-ddl#distributed_ddl_output_mode) が `none` または `none_only_active` の場合は、組み合わせて使用できます：

```sql
SET distributed_ddl_output_mode = 'none';

CREATE TABLE table1 ON CLUSTER default (x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2 ON CLUSTER default (y String) ENGINE = MergeTree ORDER BY tuple();
```

## 設定 {#settings}

設定 [max&#95;threads](/ja/reference/settings/session-settings/max-threads#max_threads) は、起動するスレッド数を制御します。

## UNION との比較 {#comparison-with-union}

`PARALLEL WITH` 句は、オペランドを並列実行するという点で [UNION](/ja/reference/statements/select/union) とやや似ています。ただし、いくつか違いがあります。

* `PARALLEL WITH` はオペランドを実行しても結果を返さず、いずれかで例外が発生した場合にそれを再スローできるだけです。
* `PARALLEL WITH` は、結果セットを返さず入力データも必要としないステートメントを組み合わせます。一方、`UNION` は `SELECT` クエリを組み合わせます。
