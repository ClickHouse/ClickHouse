## check_part_use_direct_io {#check_part_use_direct_io}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "1"},{"label": "新しい設定。ローカルディスク上のデータパーツを、OS page cache を経由せずに direct I\/O でチェックします。"}]}]} />

ローカルディスク上のデータパーツをチェックする際 (`CHECK TABLE`、読み取りに失敗したパーツのチェック、
欠損しているチェックサムの再計算) 、OS page cache を経由せずに direct I/O (`O_DIRECT` オプション) でファイルを読み取ります。
これにより、ページキャッシュ内の不正なデータが原因で、正常なパーツが破損しているように見えるのを防ぎます。
Packed ストレージのパーツ (`min_bytes_for_full_part_storage` を参照) と、`OPTIMIZE ... DRY RUN` によって書き込まれたパーツは、
引き続きページキャッシュ経由で読み取られます。
ファイルシステムが direct I/O をサポートしていない場合は、ページキャッシュ経由でファイルを読み取ります。

direct read がページキャッシュ経由の読み取りより遅い環境では、この設定を無効化してください。
direct read では、データがすでにキャッシュされている場合でも、常にストレージデバイスへのアクセスが発生します。
たとえば Amazon EBS ボリュームでは、ページキャッシュに収まるサイズのテーブルでも、チェックが数倍遅くなることがあります。

## check_sample_column_is_correct {#check_sample_column_is_correct}

<SettingsInfoBlock type="Bool" default_value="1" />

サンプリングまたはサンプリング式に使用するカラムのデータ型が正しいかどうかを、テーブル作成時にチェックするようにします。データ型は、符号なし[整数型](/ja/reference/data-types/int-uint)のいずれかである必要があります: `UInt8`, `UInt16`,
`UInt32`, `UInt64`.

設定可能な値:

* `true`  — チェックが有効です。
* `false` — テーブル作成時のチェックは無効です。

デフォルト値: `true`.

デフォルトでは、ClickHouseサーバーはテーブル作成時に、サンプリングまたはサンプリング式に使用するカラムのデータ型をチェックします。すでに誤ったサンプリング式を持つテーブルがあり、起動時にサーバーが例外を発生させないようにしたい場合は、`check_sample_column_is_correct` を `false` に設定してください。
