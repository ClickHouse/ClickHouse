## database_replicated_allow_only_replicated_engine {#database_replicated_allow_only_replicated_engine}

<SettingsInfoBlock type="Bool" default_value="0" />

`Replicated` エンジンを使用するデータベースでは、ディスク上に保存する自身のデータを複製するテーブル、
またはディスク上に自身のデータを保存しないテーブルのみ作成を許可します。

この制限が適用されるのは、リモートディスク上のデータを含め、テーブル自身が所有する on-disk データのみです。
インメモリデータや外部システムによって管理されるデータの耐久性は保証されません。

例えば、`ReplicatedMergeTree`、`Memory` や `Buffer` などのインメモリエンジン、`Merge` や `Alias` などの metadata-only エンジン、
`S3` や `AzureBlobStorage` などの外部ストレージエンジンやデータレイクエンジンは
許可されます。一方、`MergeTree`、`Log`、`File`、`Set` など、テーブルデータをディスク上に保存する非レプリケーションエンジンは、
書き込み可能なストレージポリシーがリモートディスクを使用している場合であっても拒否されます。ただし、`SETTINGS persistent = 0` を指定して作成された `Set` テーブルおよび `Join` テーブルは、
データをメモリ上にのみ保持するため許可されます。

`Distributed`、`Remote`、`RemoteSecure` テーブルは許可されます。これらのテーブルが任意で持つローカルのバックグラウンド `INSERT` キューは
一時的な送信バッファであり、テーブル自体のデータではありません。このキューはレプリケーションされませんが、
`distributed_foreground_insert = 1` を設定すればキューを使用せずに済みます。

Cloud でのデフォルト値: `1`。

## database_replicated_allow_replicated_engine_arguments {#database_replicated_allow_replicated_engine_arguments}

<SettingsInfoBlock type="UInt64" default_value="0" />

## database_replicated_always_detach_permanently {#database_replicated_always_detach_permanently}

<SettingsInfoBlock type="Bool" default_value="0" />

データベースエンジンが Replicated の場合、DETACH TABLE は DETACH TABLE PERMANENTLY として実行されます

## database_replicated_enforce_synchronous_settings {#database_replicated_enforce_synchronous_settings}

<SettingsInfoBlock type="Bool" default_value="0" />

一部のクエリで同期的な待機を強制します (関連項目: database&#95;atomic&#95;wait&#95;for&#95;drop&#95;and&#95;detach&#95;synchronously、mutations&#95;sync、alter&#95;sync) 。これらの設定を有効にすることは推奨されません。

## database_replicated_initial_query_timeout_sec {#database_replicated_initial_query_timeout_sec}

<SettingsInfoBlock type="UInt64" default_value="300" />

初期 DDL クエリが、Replicated database で以前の DDL queue のエントリが処理されるまで待機する時間を、秒単位で設定します。

設定可能な値:

* 正の整数。
* 0 — 無制限。
