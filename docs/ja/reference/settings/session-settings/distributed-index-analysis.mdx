## distributed_index_analysis_on_stateless_workers {#distributed_index_analysis_on_stateless_workers}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "0"},{"label": "新しい設定"}]}]} />

分散実行計画 (`make_distributed_plan`) として実行され、worker を保持している、またはリースできる初期クエリにおいて、`distributed_index_analysis` とは独立してステートレスワーカー上で分散索引解析を実行します。worker は、共有テーブルのオブジェクトストレージ上にあるテーブルを解析します。現時点では、この設定を有効にするとレプリカ上での索引解析 (`distributed_index_analysis`) が無効になります。そのため、worker が引き受けない読み取りや他のクエリの読み取りは、ローカルで解析されます。worker には streaming exchange が必要です。`Persisted` のエクスチェンジを使用する場合 (`distributed_plan_force_exchange_kind` で指定した場合、またはストリーミングリスナーが設定されていない場合)、読み取りはローカルで解析されます。MergeTreeの設定 `distributed_index_analysis_min_parts_to_activate` および `distributed_index_analysis_min_indexes_bytes_to_activate` が適用されます。

## distributed_index_analysis_only_on_coordinator {#distributed_index_analysis_only_on_coordinator}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "0"},{"label": "新しい設定"}]}]} />

有効にすると、分散索引解析はコーディネーター上でのみ実行されます。
これにより、述語にサブクエリ (例: `IN (SELECT ...)`) が含まれる場合に、O(N^2) の派生クエリが生成されるのを防げます。
そうしないと、各フォロワー レプリカがそれぞれ独立して独自の分散索引解析をトリガーしてしまうためです。
ただし、サブクエリで大きなテーブルを使用する場合は、分散索引解析の効率が低下します。
