## use_columns_cache {#use_columns_cache}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "MergeTree テーブル向けのカラムキャッシュを有効にする新しい実験的設定です。デフォルトでは無効です。"}]}]} />

カラムキャッシュを使用するかどうかを指定します。0 または 1 を指定できます。デフォルトは 0 (無効) です。
カラムキャッシュは、`MergeTree` テーブルからデシリアライズされたカラムを保持することで、頻繁にアクセスされるデータを毎回伸長・デシリアライズする必要をなくします。これにより、同じデータに対して繰り返し実行されるクエリのレイテンシを大幅に低減できます。キャッシュのキーは、テーブルの UUID、データパーツ名、カラム名、および約 65536 行分の連続したグラニュールからなるストライプです。

エントリはテーブルの UUID をキーとするため、キャッシュが有効になるのは、`Atomic`、`Replicated`、`Shared` (ClickHouse Cloud のデフォルトのデータベースエンジン) など、UUID を割り当てるデータベース内のテーブルに限られます。レガシーな `Ordinary` データベース内の `MergeTree` テーブルは UUID が nil であるため、この設定は警告なしに無視されます。

現時点では、キャッシュは wide パーツにのみ適用されます。compact パーツ内のデータはカラムキャッシュへの読み書きの対象外となるため、読み取りが高速化されるかどうかはパーツのフォーマットによって異なります。

1 つのエントリは、1 つのストライプ内の連続したグラニュールの範囲を保持します。グラニュールは最初の行から最後の行まで読み取られて初めてキャッシュに格納され、読み取り時にはグラニュール単位でキャッシュから返されます。また、異なる読み取りによって書き込まれた範囲はマージされるため、パーツを異なるマーク範囲に分割して読み取る場合でも、エントリは共有されます。

## use_constant_folding_in_index_analysis {#use_constant_folding_in_index_analysis}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.7"},{"label": "0"},{"label": "MergeTree の索引解析時に、各パーツごとのフィルタ条件へパーティション単位の定数を畳み込み、パーティション値に依存する分岐を持つフィルタの プルーニング を改善するための新しい設定。"}]}]} />

パーツごとの主キーおよびスキップ索引の解析時に、パーティション単位の定数をフィルタ条件に代入します。

パーティションキーが、主キーカラムまたはスキップ索引のカラムと一緒にフィルタに現れる場合、この設定により、索引解析時に各パーツ内でパーティション値を個別に畳み込めるようになります。特に、異なるパーティションを対象とする分岐を含む OR 条件のフィルタで有効です。たとえば、`PARTITION BY a` と `ORDER BY b` の場合:

```sql
SELECT * FROM t WHERE (a = 1 AND b >= 1) OR (a = 2 AND b > 10) OR (a = 3 AND b > 10)
```

パーティション `a = 1` のパートでは、この条件は `b >= 1` に畳み込まれます。一方、パーティション `a = 2` と `a = 3` では `b > 10` に畳み込まれるため、各パートは実際に適用される述語に基づいて解析されます。

設定可能な値:

* 0 — 無効。
* 1 — 有効。

## use_indexes_refiner_in_read_pools {#use_indexes_refiner_in_read_pools}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "スキップ索引またはプロジェクション索引によって完全に除外されたマーク範囲を、MergeTree 読み取りプールで読み取りタスクが作成される前に削除する新しい設定。"}]}]} />

MergeTree 読み取りプール内で、データ読み取り時に評価される索引を適用します。スキップ索引 (`use_skip_indexes_on_data_read` を参照) またはプロジェクション索引 (`optimize_use_projection_filtering` を参照) によって完全に除外されたマーク範囲は、読み取り時にグラニュール単位でスキップする代わりに、その範囲の読み取りタスクが作成される前に削除されます。

## use_strict_insert_block_limits {#use_strict_insert_block_limits}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "0"},{"label": "INSERT 時に厳密な最小／最大の挿入範囲を使用するための新しい設定です。min < max の場合は、max の制限が優先されます。"}]}]} />

有効にすると、最小および最大の挿入ブロックサイズ制限の両方が厳密に適用されます。

ブロックは次の場合に生成されます:

* 最小しきい値 (AND): min&#95;insert&#95;block&#95;size&#95;rows と min&#95;insert&#95;block&#95;size&#95;bytes の両方に達した場合。
* 最大しきい値 (OR): max&#95;insert&#95;block&#95;size&#95;rows または max&#95;insert&#95;block&#95;size&#95;bytes のいずれかに達した場合。

無効な場合、ブロックは次の場合に生成されます:

* 最小しきい値 (OR): min&#95;insert&#95;block&#95;size&#95;rows または min&#95;insert&#95;block&#95;size&#95;bytes のいずれかに達した場合。

**注**: max の設定が min の設定より小さい場合は、max の制限が優先され、最小しきい値に達する前にブロックが生成されます。

**注**: この設定は非同期 INSERT では自動的に無効になります。これは、非同期 INSERT ではエントリごとの重複排除トークンが付加され、これが厳密な制限の適用に必要なブロックの分割と両立しないためです。

デフォルトでは無効です。

## use_uncompressed_cache {#use_uncompressed_cache}

<SettingsInfoBlock type="Bool" default_value="0" />

非圧縮ブロックのキャッシュを使用するかどうかを指定します。`0` または `1` を受け付けます。既定値は `0` (無効) です。
非圧縮キャッシュ (MergeTree family のテーブルでのみ有効) を使用すると、多数の短いクエリを扱う際のレイテンシを大幅に低減し、スループットを向上させることができます。短いリクエストを頻繁に送信するユーザーには、この設定を有効にしてください。また、[uncompressed&#95;cache&#95;size](/ja/reference/settings/server-settings/settings/uncompressed-cache#uncompressed_cache_size) 設定パラメータ (設定ファイルでのみ設定可能) にも注意してください。これは非圧縮キャッシュブロックのサイズです。既定では 8 GiB です。非圧縮キャッシュは必要に応じて格納され、使用頻度の低いデータは自動的に削除されます。

ある程度大きな量のデータ (100 万行以上) を読み取るクエリでは、本当に小さなクエリのための領域を確保するために、非圧縮キャッシュは自動的に無効になります。つまり、`use_uncompressed_cache` 設定は常に `1` のままにしておくことができます。
