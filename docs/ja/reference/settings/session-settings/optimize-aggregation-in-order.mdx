## optimize_aggregation_in_order {#optimize_aggregation_in_order}

<SettingsInfoBlock type="Bool" default_value="0" />

[MergeTree](/ja/reference/engines/table-engines/mergetree-family/mergetree) テーブルにおいて、対応する順序でデータを集約する [SELECT](/ja/reference/statements/select/index) クエリでの [GROUP BY](/ja/reference/statements/select/group-by) 最適化を有効にします。

この設定は、引数でソート済みのテーブルに対して、`GROUP BY` なしで単一の `uniqExact` (または `count(DISTINCT)`) を実行する場合にも適用されます。この場合、異なる値は順序どおりに到着した時点でカウントされるため、メモリには保持されません。複数のスレッドを使用する場合、読み取りは sorting key の範囲ごとに分割され、各範囲が並列にカウントされます。分割できない場合 (例えば、引数が floating-point の場合や sorting key の関数である場合) は、通常の集約が使用されます。

プロジェクションは、集約の順序よりも先に選択されます。[プロジェクション](/ja/reference/engines/table-engines/mergetree-family/mergetree#projections) がテーブルよりも少ないグラニュールしか読み取らない場合、`GROUP BY` キーでソートされていなくてもそのプロジェクションが使用されます。その場合、集約は順序どおりには行われず、すべてのグループがメモリに保持されます。

設定可能な値:

* 0 — `GROUP BY` 最適化は無効です。
* 1 — `GROUP BY` 最適化は有効です。

## optimize_aggregation_in_order_limit {#optimize_aggregation_in_order_limit}

有効時に順序付き集約がアクティブであれば、十分な数のグループが生成された時点で早期終了できるよう、`LIMIT` を集約ステップに適用します。これにより、`ORDER BY` が `GROUP BY` キーのプレフィックスに一致する場合、読み取るデータ量を削減できます。`rows_before_limit_at_least` で報告される値が少なくなる可能性があります。正確な件数が必要な場合は、`exact_rows_before_limit` を使用してください。
