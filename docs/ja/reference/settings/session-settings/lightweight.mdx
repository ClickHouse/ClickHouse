## lightweight_delete_mode {#lightweight_delete_mode}

<SettingsInfoBlock type="LightweightDeleteMode" default_value="alter_update" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "alter_update"},{"label": "新しい設定"}]}]} />

論理削除の一部として実行される、内部的な update クエリのモードです。

設定可能な値:

* `alter_update` - 高コストなミューテーションを作成する `ALTER UPDATE` クエリを実行します。
* `lightweight_update` - 可能であれば論理更新を実行し、できない場合は `ALTER UPDATE` を実行します。
* `lightweight_update_force` - 可能であれば論理更新を実行し、できない場合は例外をスローします。

`DELETE FROM ... ON CLUSTER` では、実行する各ホストが自身の設定に基づいてモードを決定します。そのため、
プロファイルに異なるデフォルト値が設定されているホストでは、削除が異なるモードで実行される場合があります。レプリケーションされた
分片では 1 つのレプリカだけで実行されるため、そのレプリカの設定によってモードが決まります。一方、実行を開始したクエリの
session で値を設定した場合は、その値が優先されます。`distributed_ddl_entry_format_version` が 2 以上であれば、
分散 DDL エントリに session での設定変更が含まれるためです。デフォルト値はこの条件を満たします。
設定値に制約を設けているホストでは、値が制約の範囲内に収まるよう調整されます。

## lightweight_deletes_sync {#lightweight_deletes_sync}

<SettingsInfoBlock type="UInt64" default_value="2" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "24.4"},{"label": "2"},{"label": "'mutation_sync' と同じですが、論理削除の実行だけを制御します"}]}]} />

[`mutations_sync`](/ja/reference/settings/session-settings/mutations#mutations_sync) と同じですが、論理削除の実行だけを制御します。

設定可能な値:

| 値   | 説明                                                           |
| --- | ------------------------------------------------------------ |
| `0` | ミューテーションは非同期で実行されます。                                         |
| `1` | クエリは、現在のサーバー上で論理削除が完了するまで待機します。                              |
| `2` | クエリは、すべてのレプリカ (存在する場合) で論理削除が完了するまで待機します。                    |
| `3` | クエリは、アクティブなレプリカのみを待機します。非アクティブなレプリカは、アクティブになった時点で論理削除を適用します。 |

Cloud でのデフォルト値: `1`.
