## azure_validate_etag_on_read {#azure_validate_etag_on_read}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新しい設定。S3 における `s3_validate_etag_on_read` と同様に、すべての `GET` を `If-Match` で一覧取得時の `ETag` に固定し、レスポンスの `ETag` を検証することで、読み取り中に Azure のブロブがインプレースで同時に上書きされたことを検出します。`compatibility` に 26.10 より前のバージョンを指定すると、以前の動作 (検証なし) に戻ります。"}]}]} />

`azureBlobStorage` / `azureBlobStorageCluster` テーブル関数または `AzureBlobStorage` テーブルエンジンを使用して Azure Blob Storage からブロブを読み取る際、すべての `GET` リクエストを、一覧取得時に確認されたブロブの世代に固定します。具体的には、その `ETag` を `If-Match` に指定して送信し、レスポンスの `ETag` をチェックします。1 つのファイルを読み取る際には、範囲指定の `GET` リクエストが多数発行されます。その途中でブロブがインプレースで上書きされると (たとえば外部の書き込み元が固定キーを書き換えた場合)、この設定がなければ、読み取り結果がブロブの異なる 2 つの世代から継ぎ合わされ、チェックサムの破損やパースエラーとして現れることがあります。また、一覧取得時に記録されたサイズは読み取り範囲の終端としても使用されるため、その値が正しいのは記録時点の世代に対してのみです。不一致が検出された場合、不整合なデータを返すのではなく、`AZURE_OBJECT_CHANGED_DURING_READ` エラーで読み取りが失敗します。上書き中のブロブを意図的に読み取り、かつ読み取り結果の不整合を許容できるワークロードの場合にのみ、この設定を無効にしてください。
