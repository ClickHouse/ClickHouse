アナライザは、v24.3 以降デフォルトで使用されているクエリ分析およびプランニングのインフラストラクチャです。v26.9 でこの設定は唯一サポートされる値である `1` に固定され、`compatibility` 設定でも元に戻せなくなりました。v26.10 では、この設定によって切り替えられていた旧クエリ分析が削除されました。後方互換性のため、`0` を設定してもエラーにはならず、`1` に置き換えられます。そのため、`enable_analyzer = 0` を設定したままのクエリ、セッション設定、設定プロファイル、クライアント設定も引き続き動作し、アナライザが使用されます。旧クエリ分析でのクエリの動作やパフォーマンスと比較するには、v26.9 より前の ClickHouse バージョンを使用してください。

## allow_experimental_logsql_dialect {#allow_experimental_logsql_dialect}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "LogsQL ダイアレクト（VictoriaLogs のログクエリ言語）を有効にする新しい設定。"}]}]} />

VictoriaLogs のログクエリ言語である LogsQL を有効にします。このダイアレクトで記述したクエリは、`logsql_table` 設定で指定したテーブルに対する SELECT クエリに変換されます。

使用方法:

```sql
SET allow_experimental_logsql_dialect = 1;
SET logsql_table = 'logs';
SET dialect = 'logsql';

_time:1h error | stats by (host) count()
```

単独で完結した `SET` クエリは、ダイアレクトを元に戻せるよう、引き続き通常の SQL としてパースされます。一方、単に `set` という単語で始まるだけの LogsQL クエリは、本来の意味のまま扱われます。
`logsql_time_column` および `logsql_message_column` 設定では、`_time` フィールドおよびデフォルト (メッセージ) フィールドが参照するカラムを指定します。

すべてのフィールドを文字列として保存する VictoriaLogs とは異なり、変換後のクエリは既存のテーブルスキーマに対して実行されます。このため、主に以下の点で仕様が異なります。

* テキストフィルタ (単語、フレーズ、プレフィックス、正規表現) は `String` 型のカラムを前提としており、数値カラムをテキストに変換することはありません。
* 数値比較フィルタは数値カラムをネイティブに比較します (比較対象のリテラルが `Int128` または `Decimal256(38)` に収まる限り、整数値および小数値は厳密に比較されます。それを超える値、たとえば `UInt256` フィールド内の 1e38 を超える整数は `Float64` の精度で比較され、`stats by (<field>:<step>)` の整数バケットのステップも同様です) 。`String` カラムでは、単純な数値テキストのみが行ごとにパースされます。LogsQL の数値文法で表された値 (例: `10KiB`、`1h30m`) は行ごとにはパースされません。
* 数値統計関数 (`sum`、`avg`、`median`、`quantile`、`stddev`、`rate_sum`) は、VictoriaLogs と同様に各フィールドの数値をパースし、数値でない値はスキップします。値は `Float64` として扱われるため、数値カラムは厳密な値ではなく `Float64` の精度で集計されます。
* `math` パイプのオペランドには数値カラムが必要です。`String` カラムは型変換されません。
* クエリ結果は文字列ではなく、基になるカラムの型のまま返されます。
