## weight_lowering_cpu_seconds {#weight_lowering_cpu_seconds}

<SettingsInfoBlock type="Double" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "新しいクエリ設定: `fair` ワークロードスケジューラにおいて、クエリの重みを引き下げる基準となる、到達 CPU 秒数のしきい値。"}]}]} />

`fair` ワークロードスケジューラ向けの設定です。クエリの到達 CPU 秒数がこの値に達すると、その重みが `weight_lowering_factor` に従って引き下げられます。CPU リソースに適用されます。`0`(または任意の負の値)を指定すると、CPU しきい値は無効になります。到達 CPU とは、スケジューラが付与したサービス量のことで、CPU が実際に消費された時点ではなく、リクエストが付与された時点で計上されます。そのため、実際の消費量よりもアクティブなスロットごとに最大 1 クォンタム(`cpu_slot_quantum_ns`)分先行する場合があります。この設定が意味を持つのは、CPU スロットのプリエンプション(`cpu_slot_preemption = 1`、デフォルト)が有効な場合のみです。プリエンプションが無効な場合、CPU スロットには実際の CPU 時間ではなくスロットごとの固定コストが割り当てられるため、このしきい値は他の `fair` CPU 設定と同様に、実際の CPU 消費量を反映しなくなります。

## weight_lowering_factor {#weight_lowering_factor}

<SettingsInfoBlock type="Double" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新しいクエリ設定: `fair` ワークロードスケジューラにおいて、クエリが重み引き下げのしきい値を超えた時点でそのクエリの重みに適用される係数です。"}]}]} />

`fair` ワークロードスケジューラ向けの設定です。クエリが以下のいずれかの `weight_lowering_*` しきい値を超えると、その実効重みにこの係数が 1 回だけ乗算されます ((0, 1) の範囲の値を指定すると重みが下がり、より短いクエリや新しいクエリが優先的にスケジューリングされるようになります) 。複数のしきい値の効果が重なることはなく、最初に超えたしきい値によって引き下げが全量適用されます。`1.0` を指定すると引き下げは無効になります。値は `[0, 1]` の範囲に制限されるため、この係数はクエリの重みを下げることしかできず、上げることはありません。

## weight_lowering_io_bytes {#weight_lowering_io_bytes}

<SettingsInfoBlock type="Double" default_value="0" />

`fair` ワークロードスケジューラでは、クエリの I/O 量がこのバイト数に達すると、そのクエリの重みが `weight_lowering_factor` に従って引き下げられます。I/O リソースに適用されます。`0`(または任意の負の値)を指定すると、I/O のしきい値は無効になります。
