## iceberg_insert_max_bytes_in_data_file {#iceberg_insert_max_bytes_in_data_file}

<SettingsInfoBlock type="UInt64" default_value="536870912" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "536870912"},{"label": "Iceberg テーブルプロパティ `write.target-file-size-bytes` のドキュメント記載のデフォルト値（512 MiB）に合わせました。https:\/\/iceberg.apache.org\/docs\/1.5.2\/configuration\/ を参照してください。"}]}, {"id": "row-2","items": [{"label": "25.9"},{"label": "1073741824"},{"label": "新しい設定"}]}]} />

挿入操作時の iceberg parquet データファイルの最大バイト数です。

デフォルト値は、Iceberg テーブルプロパティ `write.target-file-size-bytes` のドキュメント記載のデフォルト値 (512 MiB) に合わせています。
https://iceberg.apache.org/docs/1.5.2/configuration/ を参照してください。この上限は、それまでにファイルへ書き込まれたサイズ、つまり圧縮サイズと比較されます。
そのため、未完了の Parquet 行グループやエンコード中の行グループなど、ライターがまだバッファに保持している分だけ、ファイルが上限を超える場合があります。
なお、`iceberg_insert_max_rows_in_data_file` は
サイズとは無関係にファイルを制限します。

## iceberg_insert_single_manifest_for_all_partitions {#iceberg_insert_single_manifest_for_all_partitions}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新しい設定"}]}]} />

パーティション分割されたIcebergテーブルへの `INSERT` で、パーティションごとに1つずつマニフェストファイルを書き込むのではなく、Spark
や PyIceberg と同様に、対象となるすべてのパーティションをまとめて1つのマニフェストファイルに書き込みます。これは挿入ストリーム単位で適用されます。各ストリームは独自のマニフェストを持つ独自の
スナップショットをそれぞれコミットするため、`INSERT` で書き込まれるマニフェストが厳密に1つになるのは `max_insert_threads = 1` の場合に限られます。
さらに、`OPTIMIZE TABLE ... MANIFEST` によって、異なるパーティションのマニフェストも1つにマージされます。
`ALTER TABLE ... DROP PARTITION` では、マニフェストを他のパーティションと共有しているパーティションは削除できません。
