## hdfs_create_new_file_on_insert {#hdfs_create_new_file_on_insert}

<SettingsInfoBlock type="Bool" default_value="0" />

HDFS エンジンのテーブルで、insert のたびに新しいファイルを作成するかどうかを切り替えます。有効にすると、insert のたびに次のような名前の新しい HDFS ファイルが作成されます。

initial: `data.Parquet.gz` -&gt; `data.1.Parquet.gz` -&gt; `data.2.Parquet.gz` など。

設定可能な値:

* 0 — `INSERT` クエリで新しいデータがファイルの末尾に追記されます。
* 1 — `INSERT` クエリで新しいファイルが作成されます。

## hdfs_skip_hidden_files {#hdfs_skip_hidden_files}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新しい設定: 他の Hive エコシステムのリーダーと同様に、glob でファイルを一覧表示する際、glob を含まないプレフィックスより下の階層に `_` または `.` で始まるパスセグメントを持つファイルをスキップします。`partition_strategy = 'hive'` を指定したテーブルでは、このようなパスは常にスキップされます。"}]}]} />

[HDFS](/ja/reference/engines/table-engines/integrations/hdfs) エンジンを使用するテーブルで glob によりファイルを一覧表示する際に、隠しパスをスキップするかどうかを有効または無効にします。隠しパスとは、パスのうち glob を含まないプレフィックスより下の階層に、`_` または `.` で始まるパスセグメントを持つファイルを指します。`=` を含むセグメントはパーティションディレクトリ (例: パーティション列 `_p` に対する `_p=1`) であり、隠しパスとはみなされません。Hive エコシステムのライター (Hive、Spark、Trino) は、書き込み中の出力をこのようなパス (`_temporary/`、`.spark-staging-<id>/`、`_SUCCESS`) の下にステージングしたり、マーカーファイルを書き込んだりするため、これらを読み取るとライターのコミットとの間で競合状態が発生します。glob を含まないプレフィックス内のセグメントはチェックされません。`partition_strategy = 'hive'` を指定したテーブルでは、この設定に関係なく隠しパスは常にスキップされます。

設定可能な値:

* 0 — glob に一致するすべてのファイルを読み取ります。
* 1 — glob を含まないプレフィックスより下の階層に隠しパスセグメントを持つファイルをスキップします。

## hdfs_truncate_on_insert {#hdfs_truncate_on_insert}

<SettingsInfoBlock type="Bool" default_value="0" />

HDFS エンジンのテーブルで insert を実行する前に、切り詰めを有効または無効にします。無効の場合、HDFS 内のファイルがすでに存在している状態で insert を実行しようとすると、例外がスローされます。

設定可能な値:

* 0 — `INSERT` クエリは新しいデータをファイルの末尾に追加します。
* 1 — `INSERT` クエリはファイルの既存の内容を新しいデータで置き換えます。
