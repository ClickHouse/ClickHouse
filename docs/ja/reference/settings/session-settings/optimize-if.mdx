## optimize_if_chain_to_multiif {#optimize_if_chain_to_multiif}

<SettingsInfoBlock type="Bool" default_value="0" />

if(cond1, then1, if(cond2, ...)) の連鎖を multiIf に置き換えます。現在のところ、数値型に対してはメリットがありません。

## optimize_if_transform_const_strings_to_lowcardinality {#optimize_if_transform_const_strings_to_lowcardinality}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "`if`\/`multiIf`\/`transform` の定数分岐の結果を `LowCardinality` に最適化できるようにする新しい設定です。デフォルトでは無効です。"}]}]} />

有効にすると、結果の分岐 (およびデフォルト値) が定数文字列である `if`、`multiIf`、`transform` 関数は、`String` ではなく `LowCardinality(String)` を返します。
ブロックごとに `LowCardinality` の辞書を構築する処理は、その辞書が後続の処理で再利用されない場合、通常の `String` の結果よりも遅くなる可能性があるため、デフォルトでは無効になっています。
式全体が定数である場合 (条件や入力も定数である場合) 、この最適化は適用されません。定数を `LowCardinality` にしても利点はなく、また定数の `String` 引数を想定する関数 (例: `arrayReduce`、`joinGet`、`tupleElement`) が引き続き正しく動作するようにするためです。

結果の分岐はすべて定数である必要があります。そのため、`if(cond1, 'a', if(cond2, 'b', 'c'))` のようなネストされた `if` のチェーンは通常の `String` のままです。外側の `if` の else 分岐が定数ではなく、別の `if` であるためです。`LowCardinality(String)` を得るには、`multiIf(cond1, 'a', cond2, 'b', 'c')` のように記述してください。

`optimize_if_transform_strings_to_enum` が有効な場合、この設定は効果を持ちません。`Enum` への書き換えが優先され、上記の明示的な `multiIf` 形式であっても、結果は `String` (または `Nullable(String)`) のままとなります。

## optimize_if_transform_strings_to_enum {#optimize_if_transform_strings_to_enum}

<SettingsInfoBlock type="Bool" default_value="0" />

If と Transform の String 型のargumentを enum に置き換えます。分散クエリで不整合な変更が発生して失敗するおそれがあるため、既定では無効です。
