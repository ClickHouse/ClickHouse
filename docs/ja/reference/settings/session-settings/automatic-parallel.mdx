## automatic_parallel_replicas_ignore_thresholds {#automatic_parallel_replicas_ignore_thresholds}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新しい設定: テスト用に、自動並列レプリカのコストモデルにおける読み取りスレッド数の上限を無視します。これにより、小さな読み取りは上限によって short-circuit されず、比較によって判定されるようになります。"}]}]} />

自動並列レプリカのコストモデルをテストするための設定です。1 回の読み取りが有効に使用できるスレッド数の上限 (`merge_tree_min_bytes_per_task_for_remote_reading` から導出) を無視します。通常この上限は、`max_threads` を使い切れないほど小さな読み取りに対して、比較の両辺を同じ値に制限します。その結果、比較は `0 > output_bytes / replicas` に帰着し、コストモデルが参照される前にクエリの判定が確定してしまいます。

この設定は、意図的に `automatic_parallel_replicas_min_bytes_per_replica` には影響しません。このゲートを無効化したい場合は、まさにそのための設定である `automatic_parallel_replicas_min_bytes_per_replica` を 0 に設定してください。また、読み取りタスクのサイジングを変更することも、ドリフトしたSTATISTICSの再収集を抑止することもありません。古くなったSTATISTICSに基づく判定は、コストモデルによる判定とは言えないためです。

## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "自動並列レプリカは、読み取りの半分を超える部分をすべてのレプリカで重複して実行することになるクエリについて、適用を見送るようになりました。以前は上限がなく、1 を指定すると引き続きその動作になります。"}]}]} />

クエリの読み取り量のうち、レプリカ間で分割されずにすべてのレプリカで読み取られてもよい部分の割合を、全体に対する比率で指定します。この比率を超えると、自動並列レプリカはそのクエリへの適用を見送ります。

分割されるのは、並列レプリカが協調して行う読み取りのみです。同じサブツリーに対するそれ以外の読み取りは、各レプリカですべて実行されます。これらの読み取りにかかる実時間はどちらの場合も変わらないため、コストモデルによる比較には反映されません。しかし、クラスター全体ではこれらの読み取りに `max_parallel_replicas` 倍の処理を行うことになります。この設定は、そうした無駄の上限を定めるものです。デフォルトの 0.5 では、協調読み取りが全読み取り量の半分未満のクエリは、時間比較の結果にかかわらず、引き続き 1 つのノード上で実行されます。

1 に設定すると重複読み取りの量を問わず受け入れるようになり、時間のみを比較する従来の動作に戻ります。

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.1"},{"label": "1048576"},{"label": "テスト結果に基づく、より適切なデフォルト値"}]}, {"id": "row-2","items": [{"label": "25.12"},{"label": "0"},{"label": "新しい設定"}]}]} />

並列レプリカを自動的に有効化するための、レプリカごとの読み取りバイト数のしきい値です (`automatic_parallel_replicas_mode`=1 の場合にのみ適用されます) 。0 はしきい値なしを意味します。
読み取る合計バイト数は、収集された統計情報に基づいて推定されます。

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "新しい設定"}]}]} />

統計情報に基づいて、並列レプリカによる実行へ自動的に切り替える機能を有効にします。`enable_parallel_replicas = 1`、`parallel_replicas_local_plan = 1` が必要で、さらに `cluster_for_parallel_replicas` を指定する必要があります。`enable_parallel_replicas = 2` の場合は並列レプリカが強制的に使用され、自動モードは適用されません。
0 - 無効、1 - 有効、2 - 統計の収集のみ有効 (並列レプリカによる実行への切り替えは無効) 。

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新しい設定。自動並列レプリカは、レプリカが担当する処理の境界をクエリ実行計画ごとに記憶するようになりました。以前は、この境界を特定するために、すべてのクエリで並列レプリカを用いたクエリ実行計画を構築していました。"}]}]} />

自動並列レプリカが、レプリカの担当する処理がどこまでかをクエリ実行計画ごとに記憶できるようにします。これにより、STATISTICSから並列レプリカを使用しないと判断されるクエリが繰り返し実行された場合に、
並列レプリカを用いたクエリ実行計画を構築することなく
判断できるようになります。

無効にすると、記憶された境界は使用されなくなります。並列レプリカを用いたクエリ実行計画の構築コストをベンチマークで測定する場合は、
`automatic_parallel_replicas_undecided_retry_after_executions = 0` も設定してください。前回の構築が判断に至らずに終了したクエリ実行計画は、
この設定とは無関係にスキップされるためです。

## automatic_parallel_replicas_statistics_drift_ratio {#automatic_parallel_replicas_statistics_drift_ratio}

<SettingsInfoBlock type="Float" default_value="1.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1.5"},{"label": "新しい設定。従来この比率は 2 で固定されており、変更できませんでした。現在はデータの変化に応じてSTATISTICSがより早く再収集されます。"}]}]} />

読み取りで選択される行数が、自動並列レプリカによるSTATISTICS収集時に選択された行数からどの程度乖離してもよいかを、大きい方と小さい方の比率で指定します。この比率を超えるとSTATISTICSは古くなったとみなされ、そのSTATISTICSに基づいて判断するのではなく、STATISTICSが再収集されます。

対象となる行はイニシエーターの索引解析で選択される行です。そのため、レプリカが読み取り時にのみ行う枝刈り (例えば各レプリカ自身のクエリ条件キャッシュによるもの) は考慮されません。比率を低くすると、テーブルの変化に応じてSTATISTICSがより早く再収集されます。1 より大きい値を指定してください。

## automatic_parallel_replicas_undecided_retry_after_executions {#automatic_parallel_replicas_undecided_retry_after_executions}

<SettingsInfoBlock type="UInt64" default_value="10" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "10"},{"label": "新しい設定。自動並列レプリカは、直前の構築が判定なしで終了したクエリプランについて、一定回数の実行の間、並列レプリカを使用した実行計画の構築をスキップするようになりました。以前は実行のたびに構築していました。"}]}]} />

自動並列レプリカにおいて、クエリプランの直前の構築が判定なしで終了した場合に、並列レプリカを使用した実行計画の構築をスキップする実行回数を指定します。判定なしとなるのは、2つの実行計画を比較できなかった場合、並列レプリカを使用して構築した実行計画でプランナーが並列レプリカを使用しなかった場合
、実行計画のいずれかのステップがSTATISTICSを収集できない場合、または収集で何も計測されなかった場合です。同時実行される実行は交代で再構築を担当し、`automatic_parallel_replicas_undecided_retry_after_executions + 1` 回につき 1 回の実行が実行計画を再構築します。
あるクエリプランでこのような結果が初めて発生した後は、最初の実行によって他のSTATISTICSキャッシュにデータが投入され、プランニングの判断が変わる可能性があるため、念のため次の実行で直ちに実行計画を再構築します。

0 を指定すると、判定なしの結果の後の延期が無効になります。この設定は `automatic_parallel_replicas_remember_boundary` とは独立しています。後者は、STATISTICSに基づいて判定された実行計画の構築を省略するための設定です。
