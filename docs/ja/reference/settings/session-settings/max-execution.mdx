これらの設定は [system.settings](/ja/reference/system-tables/settings) で確認でき、[ソースコード](https://github.com/ClickHouse/ClickHouse/blob/master/src/Core/Settings.cpp) から自動生成されています。

## max_execution_speed {#max_execution_speed}

<SettingsInfoBlock type="UInt64" default_value="0" />

1 秒あたりの実行行数の上限です。各データブロックで
[`timeout_before_checking_execution_speed`](/ja/reference/settings/session-settings/other#timeout_before_checking_execution_speed)
の期限が切れるたびにチェックされます。実行速度が高すぎる場合は、実行速度が抑制されます。

## max_execution_speed_bytes {#max_execution_speed_bytes}

<SettingsInfoBlock type="UInt64" default_value="0" />

1 秒あたりの実行バイト数の最大値です。各データブロックで
[`timeout_before_checking_execution_speed`](/ja/reference/settings/session-settings/other#timeout_before_checking_execution_speed)
の期限が切れるたびにチェックされます。実行速度が高すぎる場合は、実行速度が抑制されます。

## max_execution_time {#max_execution_time}

<SettingsInfoBlock type="Seconds" default_value="0" />

クエリ実行時間の最大値 (秒) です。

クエリの実行時間が指定した秒数を超えた場合の動作は、
既定で `throw` に設定されている `timeout_overflow_mode` によって決まります。

<Note>
  タイムアウトの確認が行われ、クエリを停止できるのは、データ処理中の所定の箇所に限られます。
  現在のところ、集約状態のマージ中やクエリ解析の大部分では停止できません
  (リモートレプリカへの接続確立は停止できる箇所の 1 つです)。そのため、実際の実行時間は
  この設定値より長くなります。
</Note>

## max_execution_time_leaf {#max_execution_time_leaf}

<SettingsInfoBlock type="Seconds" default_value="0" />

[`max_execution_time`](/ja/reference/settings/session-settings/max-execution#max_execution_time) と意味としては似ていますが、
分散クエリまたはリモートクエリのリーフノードにのみ適用されます。

たとえば、リーフノードでの実行時間を `10s` に制限しつつ、
初期ノードでは制限を設けたくない場合は、ネストされたサブクエリの設定に
`max_execution_time` を指定する代わりに、次のようにします:

```sql
SELECT count()
FROM cluster(cluster, view(SELECT * FROM t SETTINGS max_execution_time = 10));
```

クエリ設定として `max_execution_time_leaf` を指定できます:

```sql
SELECT count()
FROM cluster(cluster, view(SELECT * FROM t)) SETTINGS max_execution_time_leaf = 10;
```
