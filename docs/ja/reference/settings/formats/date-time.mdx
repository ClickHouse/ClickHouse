## date_time_64_output_format_cut_trailing_zeros_align_to_groups_of_thousands {#date_time_64_output_format_cut_trailing_zeros_align_to_groups_of_thousands}

<SettingsInfoBlock type="Bool" default_value="0" />

`DateTime64`値の末尾のゼロを動的に削除し、すべての有効桁を保持できるよう、出力スケールを次の3の倍数 ([0, 3, 6, 9]) に切り上げます。小数部がすべてゼロの場合は省略されます。

## date_time_input_format {#date_time_input_format}

<SettingsInfoBlock type="DateTimeInputFormat" default_value="best_effort" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.5"},{"label": "best_effort"},{"label": "使い勝手の向上"}]}]} />

日付と時刻のテキスト表現を解釈するパーサーを選択できます。

この設定は、[日付と時刻を扱う関数](/ja/reference/functions/regular-functions/date-time-functions)には適用されません。

設定可能な値:

* `'best_effort'` — 拡張パースを有効にします。

  ClickHouse は、基本的な `YYYY-MM-DD HH:MM:SS` フォーマットと、すべての [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) の日付・時刻フォーマットをパースできます。たとえば、`'2018-06-08T01:02:03.000Z'` です。

* `'best_effort_us'` — `best_effort` に似ています (違いについては [parseDateTimeBestEffortUS](/ja/reference/functions/regular-functions/type-conversion-functions#parseDateTimeBestEffortUS) を参照)

* `'basic'` — 基本パーサーを使用します。

  ClickHouse がパースできるのは、基本的な `YYYY-MM-DD HH:MM:SS` または `YYYY-MM-DD` フォーマットだけです。たとえば、`2019-08-20 10:18:56` または `2019-08-20` です。

## date_time_output_format {#date_time_output_format}

<SettingsInfoBlock type="DateTimeOutputFormat" default_value="simple" />

日付と時刻のテキスト表現に対して、異なる出力フォーマットを選択できます。

設定可能な値:

* `simple` - シンプルな出力フォーマット。

  ClickHouse は日付と時刻を `YYYY-MM-DD hh:mm:ss` フォーマットで出力します。たとえば、`2019-08-20 10:18:56` です。計算は、データ型のタイムゾーン (存在する場合) またはサーバーのタイムゾーンに従って行われます。

* `iso` - ISO 出力フォーマット。

  ClickHouse は日付と時刻を [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) の `YYYY-MM-DDThh:mm:ssZ` フォーマットで出力します。たとえば、`2019-08-20T10:18:56Z` です。出力は UTC であることに注意してください (`Z` は UTC を意味します) 。

* `unix_timestamp` - Unix timestamp 出力フォーマット。

  ClickHouse は日付と時刻を [Unix timestamp](https://en.wikipedia.org/wiki/Unix_time) フォーマットで出力します。たとえば、`1566285536` です。

## date_time_overflow_behavior {#date_time_overflow_behavior}

<SettingsInfoBlock type="DateTimeOverflowBehavior" default_value="ignore" />

[Date](/ja/reference/data-types/date)、[Date32](/ja/reference/data-types/date32)、[DateTime](/ja/reference/data-types/datetime)、[DateTime64](/ja/reference/data-types/datetime64)、[Time](/ja/reference/data-types/time)、[Time64](/ja/reference/data-types/time64)、または数値 (整数および浮動小数点数) を `Date`、`Date32`、`DateTime`、`DateTime64`、`Time`、`Time64` に変換する際、その値を結果の型で表現できない場合の動作を定義します。`Decimal` 値は `DateTime64` と `Time64` にのみ変換でき、これらの変換もこの設定に従います。`Decimal` を `Date`、`Date32`、`DateTime`、`Time` に変換しようとした場合は、この設定に関係なく拒否されます。この設定は、入力形式によるパースを含め、テキストから `Date` または `DateTime` をパースする場合にも適用されます。

設定可能な値:

* `ignore` — オーバーフローを通知せずに無視します。日付・時刻型同士の変換では結果は未定義です (値がラップアラウンドする可能性があります) 。数値の場合は、結果の型の範囲の境界値に飽和されます。
* `throw` — オーバーフローが発生した場合に例外をスローします。
* `saturate` — 結果を飽和させます。値が変換先の型で表現可能な最小値より小さい場合は、表現可能な最小値が結果となります。値が変換先の型で表現可能な最大値より大きい場合は、表現可能な最大値が結果となります。

厳密なキャスト (`accurateCast`、`accurateCastOrNull`、`accurateCastOrDefault`) はこの設定の影響を受けません。表現できない値は常に、それぞれ拒否される、`NULL` として返される、デフォルト値に置換される、という扱いになります。

この設定は、`INSERT ... VALUES` の式テンプレートや `INSERT ... SELECT` で行われる変換を含め、`CAST` および変換関数による変換に適用されます。一方、`Values` 形式がテンプレートを使わずに評価する定数式 (`input_format_values_interpret_expressions` によって有効化されるフォールバック) と `values` テーブル関数は、`DateTime64` と `Time64` の場合にのみこの設定に従います。これらで `Date`、`Date32`、`DateTime`、`Time` カラムに範囲外の数値を入れた場合、この設定は適用されません。`values` テーブル関数はその値を拒否し、`Values` 形式も同様に拒否します。ただし、`input_format_null_as_default` が有効な場合、`Values` 形式はカラムのデフォルト値を挿入します。

デフォルト値: `ignore`。
