これらの設定はClickHouseサーバーの設定項目であり、ClickHouseのソースコードから自動生成されています。

## use_minimalistic_part_header_in_zookeeper {#use_minimalistic_part_header_in_zookeeper}

廃止された設定であり、何の効果もありません。[Replicated](/ja/reference/engines/table-engines/mergetree-family/replication) テーブルは、常に単一の `znode` を使ってデータパーツのヘッダーをコンパクトに保存します。古いバージョンで書き込まれた、`columns` と `checksums` の子 `znodes` に分かれた形式のパーツヘッダーも、引き続き読み取れます。

## use_separate_cache_arena {#use_separate_cache_arena}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />

cache の割り当て (mark cache、非圧縮 cache、page cache) 専用の jemalloc アリーナを有効にします。
cache データをクエリ処理時の割り当てから分離し、メモリの断片化を軽減します。

## use_shared_merge_tree_log_pipeline {#use_shared_merge_tree_log_pipeline}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />

ClickHouse Cloud でのみ利用可能です。有効にすると、システムログは `SharedMergeTree` パイプラインを通じて書き込まれ、
`system` データベースは Shared データベースになるため、すべてのレプリカが同じログテーブルを参照できます。

ログが flush されるたびに、`s3`(または `azureBlobStorage`)テーブル関数によって `Native` ファイルが、そのログの世代(カラムとキーのハッシュ)に対応するフォルダーに書き込まれます。
パイプラインは世代ごとに、そのフォルダーを読み取るキュー `system._<log>_s3queue_<hash>`、materialized view `system._<log>_mv_<hash>`、および `SharedMergeTree` テーブル `system.<log>_<hash>` を保持します。
`system.<log>` は全世代を対象とする `Merge` テーブルです。スキーマが変わると新しい世代が作成されます。一方、設定、有効期限 (TTL)、インデックスは
ログの設定にある `smt_settings`、`smt_ttl`、`smt_indices` キーから取得され、既存のテーブルに対してその場で変更されます。
これらのオブジェクトは、ログの最初の flush 時、または `prepare_system_log_tables_on_startup` を使用した場合は起動時に作成されます。
テーブルの sorting key は、ログのキーの先頭に `hostname` を加えたものです。これにより、各レプリカの行をキーで読み取れます。
ログの設定にある `smt_order_by` および `smt_partition_by` キーを指定すると、テーブルのキーが置き換えられます。

この設定が有効な間、ローカルの `system` データベースは `system_local` にリネームされます。サーバー構成に `shared_database_catalog`
および `<shared_log_pipeline><endpoint>` が必要です。
関連項目: `shared_log_pipeline.enable_sync_flush`、`shared_log_pipeline.flush_timeout_seconds`。
