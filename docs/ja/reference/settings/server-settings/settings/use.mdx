これらの設定はClickHouseサーバーの設定項目であり、ClickHouseのソースコードから自動生成されています。

## use_minimalistic_part_header_in_zookeeper {#use_minimalistic_part_header_in_zookeeper}

廃止された設定であり、何の効果もありません。[Replicated](/ja/reference/engines/table-engines/mergetree-family/replication) テーブルは、常に単一の `znode` を使ってデータパーツのヘッダーをコンパクトに保存します。古いバージョンで書き込まれた、`columns` と `checksums` の子 `znodes` に分かれた形式のパーツヘッダーも、引き続き読み取れます。

## use_separate_cache_arena {#use_separate_cache_arena}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />

cache の割り当て (mark cache、非圧縮 cache、page cache) 専用の jemalloc アリーナを有効にします。
cache データをクエリ処理時の割り当てから分離し、メモリの断片化を軽減します。

## use_shared_merge_tree_log_pipeline {#use_shared_merge_tree_log_pipeline}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />

ClickHouse Cloud でのみ利用できます。有効にすると、`system.*_log` テーブルは S3 ベースのパイプラインを介した `SharedMergeTree` で管理されます。
各ログ `<log>` について、起動時に次のオブジェクトが自動的に作成されます。

* `system.<log>_s3` — 直接の flush 先となる `S3` バックのテーブルです。各
  `SYSTEM FLUSH LOGS` 呼び出しでは、ここに新しいパーティション化済みファイルが書き込まれます。
* `system.<log>_s3queue` — `<log>_s3` からファイルを取り込み、
  行を下流へストリーミングする `S3Queue` テーブル (ordered mode) です。各ノードは
  `partition_regex` ベースのパーティション化によって、自身のファイルだけを処理します。
* `system.<log>_mv` — `<log>_s3queue` から
  最終的な `SharedMergeTree` テーブルへ行をルーティングする `MATERIALIZED VIEW` です。
* `system.<log>` — 行が蓄積され、クエリ対象となる最終的な `SharedMergeTree` テーブルです。

スキーマまたは設定の変更時には、影響を受けるテーブルは `<log>_0`、`<log>_1` などにリネームされたうえで、
既存の `SystemLog` のローテーション動作に合わせて再作成されます。

サーバー設定で `<shared_log_pipeline><endpoint>` を設定する必要があります。
関連項目: `shared_log_pipeline.enable_sync_flush`, `shared_log_pipeline.flush_timeout_seconds`.
