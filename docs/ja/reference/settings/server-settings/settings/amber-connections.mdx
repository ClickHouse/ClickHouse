これらはClickHouseサーバーを設定するための設定項目であり、ClickHouseのソースコードから自動生成されています。

## amber_connections_hard_limit {#amber_connections_hard_limit}

<SettingsInfoBlock type="UInt64" default_value="200000" changeable_without_restart="No" />この上限に達した状態で作成を試みると、例外がスローされます。0 に設定するとハードリミットが無効になります。この上限は Amber 接続に適用されます。

## amber_connections_rcvbuf {#amber_connections_rcvbuf}

<SettingsInfoBlock type="UInt64" default_value="204800" changeable_without_restart="Yes" />Amber 接続で使用する SO&#95;RCVBUF オプションのサイズです。デフォルトは 204800 (200 KB) です。オブジェクトストレージへは同一リージョン内でアクセスするため、帯域幅遅延積は 100 KB を大きく下回ります。そのため、小さな上限値でも十分なスループットが得られ、さらにカーネルの自動調整によって socket ごとに割り当てられる数 MiB 規模のバッファも回避できます。受信バッファにカーネルのTCP自動チューニングを使用するには、0 に設定します。注意: この設定を 0 に戻しても、自動調整が有効になるのは新しく作成された接続のみです。既存のプールされた接続は、再作成されるまで固定のバッファサイズを保持します。

## amber_connections_sndbuf {#amber_connections_sndbuf}

<SettingsInfoBlock type="UInt64" default_value="0" changeable_without_restart="Yes" />Amber 接続で使用する SO&#95;SNDBUF オプションのサイズです。0 より大きい値を設定すると、送信バッファについてカーネルのTCP自動チューニングをオーバーライドします。0 の場合はカーネルのデフォルト (自動調整) が使用されます。注記: この設定を 0 に戻しても、自動調整が復元されるのは新たに作成された接続のみです。既存のプールされた接続は、再作成されるまで固定のバッファサイズを維持します。

## amber_connections_soft_limit {#amber_connections_soft_limit}

<SettingsInfoBlock type="UInt64" default_value="5000" changeable_without_restart="No" />この上限を超えた接続は、生存時間 (TTL) が大幅に短くなります。この上限は Amber 接続に適用されます。

## amber_connections_store_limit {#amber_connections_store_limit}

<SettingsInfoBlock type="UInt64" default_value="10000" changeable_without_restart="No" />再利用のために pool に保持されるアイドル状態の接続の最大数です。保持されている接続数がこの値に達すると、それ以降の接続は保持されず、使用後にリセットされます。この上限は使用中の接続数を制限するものではありません。0 に設定すると接続キャッシュが無効になります。この上限は Amber の接続に適用されます。

## amber_connections_warn_limit {#amber_connections_warn_limit}

<SettingsInfoBlock type="UInt64" default_value="8000" changeable_without_restart="No" />使用中の接続数がこの上限を超えると、警告メッセージがログに書き込まれます。この上限は Amber 接続に適用されます。
