これらの設定は ClickHouse サーバーを構成するもので、ClickHouse のソースコードから自動生成されています。

## reader_executor_memory_pressure_critical_level_pct {#reader_executor_memory_pressure_critical_level_pct}

<SettingsInfoBlock type="UInt64" default_value="95" changeable_without_restart="Yes" />experimental `ReaderExecutor` が `Critical` メモリ逼迫レベル (読み取りウィンドウを最も積極的に縮小するレベル) へ移行するメモリ逼迫のthresholdです。スコープ、range、および順序の規則については `reader_executor_memory_pressure_elevated_level_pct` を参照してください。

## reader_executor_memory_pressure_elevated_level_pct {#reader_executor_memory_pressure_elevated_level_pct}

<SettingsInfoBlock type="UInt64" default_value="75" changeable_without_restart="Yes" />experimental `ReaderExecutor` が `Elevated` メモリ逼迫レベルに移行し、読み取り window の縮小を開始する、memory tracker の hard limit に対する割合で表したメモリ逼迫の threshold です。これらの threshold は 3 つの scope、すなわち server 全体 (`max_server_memory_usage`)、USER (`max_memory_usage_for_user`)、クエリ (`max_memory_usage`) に対してそれぞれ独立に適用され、reader はそのうち最も高い値を採用します。そのため、server が idle であっても、自身の制限に近づいたクエリが 1 つあればその window は縮小されます。hard limit が設定されていない scope は何も寄与しません。値は `[1, 100]` の範囲内で、かつ `elevated <= high <= critical` を満たす必要があります。範囲外の値や順序が不正な組み合わせは、起動時および `SYSTEM RELOAD CONFIG` 時に拒否されます。0 が拒否されるのは、`elevated` が 0 だと hard limit のない scope も含めてすべての scope が `Elevated` になってしまうためです。

## reader_executor_memory_pressure_high_level_pct {#reader_executor_memory_pressure_high_level_pct}

<SettingsInfoBlock type="UInt64" default_value="90" changeable_without_restart="Yes" />experimental な `ReaderExecutor` が `High` メモリ逼迫レベルに移行する際のメモリ逼迫の threshold です。scope、range、および順序の規則については `reader_executor_memory_pressure_elevated_level_pct` を参照してください。
