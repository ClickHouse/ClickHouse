この章で説明する関数を使用すると、クエリのプロファイリングのために [ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format) と [DWARF](https://en.wikipedia.org/wiki/DWARF) を調査できます。

<Note>
  これらの関数は低速であり、セキュリティ上の考慮が必要になる場合があります。
</Note>

イントロスペクション関数を正しく動作させるには:

* `clickhouse-common-static-dbg` パッケージをインストールします。

* [allow&#95;introspection&#95;functions](/ja/reference/settings/session-settings/allow#allow_introspection_functions) 設定を 1 に設定します。

  セキュリティ上の理由から、イントロスペクション関数はデフォルトで無効になっています。

ClickHouse はプロファイラレポートを [trace&#95;log](/ja/reference/system-tables/trace_log) システムテーブルに保存します。テーブルとプロファイラが正しく設定されていることを確認してください。

## addressToLine {#addressToLine}

導入バージョン: v20.1.0

ClickHouse のメイン実行可能ファイル内の命令のアドレスを、ClickHouse のソースコードのファイル名と行番号に変換します。

アドレスは、ClickHouse のメイン実行可能ファイル内のオフセットである必要があります。これは、`system.trace_log`、`system.stack_trace`、`system.crash_log` の `trace` カラム、および `system.error_log` の `last_error_trace` カラムにアドレスが保存される形式です。
この関数を使ってサーバープロセスのメモリ配置を把握できないように、実行時のアドレス (仮想メモリアドレス) は受け付けません。
メイン実行可能ファイル外のフレームは `0` として保存され、この関数はそれらに対して空の結果を返します。

<Note>
  この関数は処理が遅く、使用にあたってはセキュリティ上の考慮事項に注意が必要です。
</Note>

このイントロスペクション関数を有効にするには、次の手順を実行します。

* `clickhouse-common-static-dbg` パッケージをインストールします。
* [`allow_introspection_functions`](/ja/reference/settings/session-settings/allow#allow_introspection_functions) を `1` に設定します。

<Note>
  この関数は非決定的です。同じ引数に対して異なる結果を返すことがあります。
</Note>

**構文**

```sql
addressToLine(address_of_binary_instruction)
```

**引数**

* `address_of_binary_instruction` — メインの ClickHouse 実行可能ファイル内の命令のオフセット。`system.trace_log` などのテーブルの `trace` カラムに保存されている値です。[`UInt64`](/ja/reference/data-types/int-uint)

**戻り値**

ソースコードのファイル名と行番号をコロンで区切った文字列 (例：`/build/obj-x86_64-linux-gnu/../src/Common/ThreadPool.cpp:199`) を返します。指定されたアドレスに対応するデバッグ情報が見つからない場合はバイナリの名前を返し、`0` の場合は空文字列を返します。[`String`](/ja/reference/data-types/string)

**例**

## addressToLineWithInlines {#addressToLineWithInlines}

導入バージョン: v22.2.0

`addressToLine` に似ていますが、すべてのインライン関数を含む Array を返します。
このため、`addressToLine` より低速です。

アドレスは、ClickHouse のメイン実行可能ファイル内のオフセットである必要があります。これは、`system.trace_log`、`system.stack_trace`、`system.crash_log` の `trace` カラム、および `system.error_log` の `last_error_trace` カラムにアドレスが保存される際の形式です。
この関数でサーバープロセスのメモリ配置を調べられないように、実行時のアドレス (仮想メモリアドレス) は受け付けません。
メイン実行可能ファイル外のフレームは `0` として保存され、この関数はそれらに対して空の結果を返します。

このイントロスペクション関数を有効にするには:

* `clickhouse-common-static-dbg` パッケージをインストールします。
* 設定 [`allow_introspection_functions`](/ja/reference/settings/session-settings/allow#allow_introspection_functions) の値を `1` に設定します。

<Note>
  この関数は非決定的です。同じ引数に対して異なる結果を返す場合があります。
</Note>

**構文**

```sql
addressToLineWithInlines(address_of_binary_instruction)
```

**引数**

* `address_of_binary_instruction` — `system.trace_log` や同様のテーブルの `trace` カラムに格納されている、メインの ClickHouse 実行可能ファイル内の命令のオフセット。[`UInt64`](/ja/reference/data-types/int-uint)

**戻り値**

最初の要素が、コロンで区切られたソースコードのファイル名と行番号である配列を返します。2 番目、3 番目以降の要素には、インライン関数のソースコードのファイル名、行番号、および関数名が含まれます。デバッグ情報が見つからなかった場合は、バイナリ名のみを要素に持つ配列が返されます。`0` に対しては、空の配列が返されます。[`Array(String)`](/ja/reference/data-types/array)

**例**

## addressToSymbol {#addressToSymbol}

導入バージョン: v20.1.0

メインの ClickHouse 実行可能ファイル内の命令アドレスを、ClickHouse のオブジェクトファイル内のシンボルに変換します。

アドレスは、メインの ClickHouse 実行可能ファイル内のオフセットである必要があります。これは、`system.trace_log`、`system.stack_trace`、`system.crash_log` の `trace` カラム、および `system.error_log` の `last_error_trace` カラムに保存されるアドレスの形式です。

メインの実行可能ファイルの外部にあるフレームは `0` として保存され、この関数はそれらに対して空の結果を返します。

<Note>
  この関数は非決定的です。同じ引数に対して異なる結果を返すことがあります。
</Note>

**構文**

```sql
addressToSymbol(address_of_binary_instruction)
```

**引数**

* `address_of_binary_instruction` — ClickHouseのメイン実行可能ファイル内の命令のオフセット。`system.trace_log`などのテーブルの`trace`カラムに格納されています。[`UInt64`](/ja/reference/data-types/int-uint)

## getQueryProfileEvent {#getQueryProfileEvent}

導入バージョン: v26.11.0

現在のクエリの[プロファイルイベント](/ja/reference/system-tables/events)の現在値を返します。

値は、`system.query_log` の `ProfileEvents` カラムと同様に、クエリを実行するすべてのスレッドの値を累積したものです。
この関数は非決定的です。クエリ実行中にデータの[ブロック](/ja/resources/develop-contribute/introduction/architecture#block)ごとに1回評価されるため、
同じブロック内のすべての行に同じ値が返され、クエリの進行に伴って値が増加します。
これを利用して、それまでに読み取った行数やバイト数など、クエリの進捗情報を出力や挿入されたデータに付加できます。

分散クエリでは、各サーバーが自身の担当する処理部分の値を返します。
`RealTimeMicroseconds` や `OSReadBytes` など、一部のイベントは定期的にしか更新されないため、値の反映が遅れる場合があります。

<Note>
  この関数は非決定的です。同じ引数に対して異なる結果を返す場合があります。
</Note>

**構文**

```sql
getQueryProfileEvent(event_name)
```

**引数**

* `event_name` — `system.events` に記載されているプロファイルイベントの名前。[`const String`](/ja/reference/data-types/string)

**戻り値**

現在のクエリにおけるプロファイルイベントの現在の値。[`UInt64`](/ja/reference/data-types/int-uint)

**例**

**読み取りの進捗**

```sql title=Query
SELECT number, getQueryProfileEvent('SelectedRows') AS selected_rows
FROM numbers_mt(10)
SETTINGS max_block_size = 3, max_threads = 1
```

```response title=Response
┌─number─┬─selected_rows─┐
│      0 │             3 │
│      1 │             3 │
│      2 │             3 │
│      3 │             6 │
│      4 │             6 │
│      5 │             6 │
│      6 │             9 │
│      7 │             9 │
│      8 │             9 │
│      9 │            10 │
└────────┴───────────────┘
```

## isMergeTreePartCoveredBy {#isMergeTreePartCoveredBy}

導入バージョン: v25.6.0

第1引数のパーツが第2引数のパーツに包含されているかどうかを確認する関数です。

**構文**

```sql
isMergeTreePartCoveredBy(nested_part, covering_part)
```

**引数**

* `nested_part` — 想定されるネストされたパーツの名前。[`String`](/ja/reference/data-types/string)
* `covering_part` — 惡定されるカバリングパーツの名前。[`String`](/ja/reference/data-types/string)

**戻り値**

カバーしている場合は `1`、そうでない場合は `0` を返します。[`UInt8`](/ja/reference/data-types/int-uint)

**例**

**基本的な例**

```sql title=Query
WITH 'all_12_25_7_4' AS lhs, 'all_7_100_10_20' AS rhs
SELECT isMergeTreePartCoveredBy(rhs, lhs), isMergeTreePartCoveredBy(lhs, rhs);
```

```response title=Response
┌─isMergeTreePartCoveredBy(rhs, lhs)─┬─isMergeTreePartCoveredBy(lhs, rhs)─┐
│                                  0 │                                  1 │
└────────────────────────────────────┴────────────────────────────────────┘
```

## logTrace {#logTrace}

導入バージョン: v20.12.0

サーバーログにトレースログメッセージを出力します。

この関数は定数引数のみを受け付けるため、呼び出しはクエリ分析中に評価され、その結果に置き換えられます。したがって、メッセージはクエリの分析中に一度だけ出力され、処理される
[Block](/ja/resources/develop-contribute/introduction/architecture#block)ごとに出力されるわけではありません。行数と設定 `max_block_size` は、ログに出力されるメッセージ数に影響しません。

**構文**

```sql
logTrace(message)
```

**引数**

* `message` — サーバーログに出力されるメッセージ。[`const String`](/ja/reference/data-types/string)

**戻り値**

常に `0` を返します。[`UInt8`](/ja/reference/data-types/int-uint)

**例**

**基本例**

```sql title=Query
SELECT logTrace('logTrace message');
```

```response title=Response
┌─logTrace('logTrace message')─┐
│                            0 │
└──────────────────────────────┘
```

