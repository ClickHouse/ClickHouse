## evalMLMethod {#evalmlmethod}

学習済みの回帰モデルを使用した予測には、`evalMLMethod` 関数を使用します。詳しくは `linearRegression` のリンクを参照してください。

## stochasticLinearRegression {#stochasticlinearregression}

[stochasticLinearRegression](/ja/reference/functions/aggregate-functions/stochasticLinearRegression) 集約関数は、線形モデルと MSE 損失関数を用いた確率的勾配降下法を実装します。新しいデータに対する予測には `evalMLMethod` を使用します。

## stochasticLogisticRegression {#stochasticlogisticregression}

[stochasticLogisticRegression](/ja/reference/functions/aggregate-functions/stochasticLogisticRegression) 集約関数は、二値分類問題に対する確率的勾配降下法を実装します。新しいデータに対する予測には `evalMLMethod` を使用します。

## assignCentroid {#assignCentroid}

導入バージョン: v26.8.0

ベクトルに最も近い(L2)セントロイドの id を返します。セントロイドは、定数の配列の配列として指定でき、この場合 id はその配列内の 0 始まりの位置を表します。または、属性 `cid` と `vec` を持つ `Dictionary` の名前として指定でき、この場合 id は `cid` になります。

<Note>
  この関数は非決定的です。同じ引数に対して異なる結果を返すことがあります。
</Note>

**構文**

```sql
assignCentroid(vec, centroids | dict_name)
```

**引数**

* `vec` — 割り当て対象のベクトル。その次元数はセントロイドの次元数と一致する必要があります。`Float32` 以外の要素型は `Float32` に変換されます (スコアリングkernelが使用する型です) 。[`Array(Float32)`](/ja/reference/data-types/array) または [`Array(Float64)`](/ja/reference/data-types/array) または [`Array(BFloat16)`](/ja/reference/data-types/array) または [`Array(Int8)`](/ja/reference/data-types/array) または [`Array(UInt8)`](/ja/reference/data-types/array)
* `centroids` — スコアリング対象のセントロイドで、定数である必要があります。`vec` で受け付けられる任意の要素型 (同じ型である必要はありません) を持つ、サイズが等しく空でない配列の配列として指定する場合、id はその配列内の0始まりの位置になります。または、`UInt32` に収まるunsigned integer typeの属性 `cid` と `Array(Float32)` 型の属性 `vec` を持つ `Dictionary` の名前として指定する場合、id は `cid` になります。この辞書は一度だけ読み込まれ、reloadされるまでキャッシュされます。[`Array(Array(Float32))`](/ja/reference/data-types/array) または [`Array(Array(Float64))`](/ja/reference/data-types/array) または [`Array(Array(BFloat16))`](/ja/reference/data-types/array) または [`Array(Array(Int8))`](/ja/reference/data-types/array) または [`Array(Array(UInt8))`](/ja/reference/data-types/array) または [`String`](/ja/reference/data-types/string)

**戻り値**

最も近いセントロイドの id。[`UInt32`](/ja/reference/data-types/int-uint)

**例**

**Inline のセントロイド**

```sql title=Query
SELECT assignCentroid([1.0, 2.0]::Array(Float32), [[0.0, 0.0], [1.0, 2.0]]::Array(Array(Float32)))
```

```response title=Response
1
```

## evalMLMethod {#evalMLMethod}

導入バージョン: v20.1.0

学習済みの機械学習モデルを入力された特徴量に適用し、予測を生成します。

**構文**

```sql
evalMLMethod(model, x1[, x2, ...])
```

**引数**

* `model` — 学習済みの機械学習モデル。[`AggregateFunctionState`](/ja/reference/data-types/aggregatefunction)
* `x1, x2, ...` — 予測に用いる特徴量の値。[`Float*`](/ja/reference/data-types/float) または [`(U)Int*`](/ja/reference/data-types/int-uint)

**戻り値**

学習済みモデルに基づいて予測された値を返します。[`Float64`](/ja/reference/data-types/float)

**例**

**使用例**

```sql title=Query
CREATE TABLE trips (pickup_datetime DateTime('UTC'), trip_distance Float64, total_amount Float64) ENGINE = Memory;

-- A fare of 3, plus 2.5 for every unit of distance.
INSERT INTO trips
SELECT toDateTime('2020-01-01 00:00:00', 'UTC') + number * 60, number % 10 + 1, 2.5 * (number % 10 + 1) + 3
FROM numbers(1000);

-- One model per year of the data.
CREATE TABLE models ENGINE = Memory AS
SELECT
    toYear(pickup_datetime) AS year,
    stochasticLinearRegressionState(0.01, 0.0, 10, 'SGD')(total_amount, trip_distance) AS model
FROM trips
GROUP BY year;

SELECT
    trip_distance,
    round(evalMLMethod(model, trip_distance), 2) AS predicted,
    total_amount
FROM trips
LEFT JOIN models ON year = toYear(pickup_datetime)
ORDER BY pickup_datetime
LIMIT 5
```

```response title=Response
┌─trip_distance─┬─predicted─┬─total_amount─┐
│             1 │      4.05 │          5.5 │
│             2 │      6.79 │            8 │
│             3 │      9.53 │         10.5 │
│             4 │     12.28 │           13 │
│             5 │     15.02 │         15.5 │
└───────────────┴───────────┴──────────────┘
```

## naiveBayesClassifier {#naiveBayesClassifier}

導入バージョン: v25.11.0

[`NAIVE_BAYES`](/ja/reference/statements/create/dictionary/layouts/naive-bayes) Dictionary を使用して入力テキストを分類します。`dictGet(dictionary_name, class_attribute, input_text)` と同じ予測クラス値を返します。ここで、class&#95;attribute は Dictionary の[レイアウト](/ja/reference/statements/create/dictionary/layouts/naive-bayes#layout-parameters)で設定されたクラスラベル属性の名前です。`dictGet` とは異なり、戻り値の型はクラス属性の宣言型ではなく常に `UInt32` であり、`input_text` は `String` である必要があります (キー型変換は適用されません) 。

<Note>
  この関数は非決定論的です。同じ引数に対して異なる結果を返すことがあります。
</Note>

**構文**

```sql
naiveBayesClassifier(dictionary_name, input_text)
```

**引数**

* `dictionary_name` — NAIVE&#95;BAYES レイアウトの Dictionary 名。[`String`](/ja/reference/data-types/string)
* `input_text` — 分類対象のテキスト。[`String`](/ja/reference/data-types/string)

**戻り値**

予測されたクラスID。[`UInt32`](/ja/reference/data-types/int-uint)

**例**

**テキストを分類**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT naiveBayesClassifier('sentiment', 'a good and great film') AS class_id;
```

```response title=Response
┌─class_id─┐
│        0 │
└──────────┘
```

## naiveBayesClassifierWithAllProbs {#naiveBayesClassifierWithAllProbs}

導入バージョン: v26.7.0

[`NAIVE_BAYES`](/ja/reference/statements/create/dictionary/layouts/naive-bayes) Dictionaryを使用して入力テキストを分類し、すべてのクラスとその確率を、確率の高い順に返します。

<Note>
  この関数は非決定論的です。同じ引数に対して異なる結果を返すことがあります。
</Note>

**構文**

```sql
naiveBayesClassifierWithAllProbs(dictionary_name, input_text)
```

**引数**

* `dictionary_name` — NAIVE&#95;BAYES レイアウトを使用するDictionary名。[`String`](/ja/reference/data-types/string)
* `input_text` — 分類対象のテキスト。[`String`](/ja/reference/data-types/string)

**戻り値**

確率の高い順に並んだ (class&#95;id, probability) の Tuple からなる Array。[`Array(Tuple(UInt32, Float64))`](/ja/reference/data-types/array)

**例**

**各クラスの確率**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT arrayMap(p -> (p.1, round(p.2, 4)), naiveBayesClassifierWithAllProbs('sentiment', 'a good and great film')) AS predictions;
```

```response title=Response
┌─predictions─────────────┐
│ [(0,0.9677),(1,0.0323)] │
└─────────────────────────┘
```

## naiveBayesClassifierWithProb {#naiveBayesClassifierWithProb}

導入バージョン: v26.7.0

[`NAIVE_BAYES`](/ja/reference/statements/create/dictionary/layouts/naive-bayes) Dictionary を使用して入力テキストを分類し、予測されたクラスとその確率を返します。

<Note>
  この関数は非決定論的です。同じ引数に対しても異なる結果を返す場合があります。
</Note>

**構文**

```sql
naiveBayesClassifierWithProb(dictionary_name, input_text)
```

**引数**

* `dictionary_name` — NAIVE&#95;BAYES レイアウトを持つ Dictionary の名前。[`String`](/ja/reference/data-types/string)
* `input_text` — 分類対象のテキスト。[`String`](/ja/reference/data-types/string)

**戻り値**

(class&#95;id, probability) から成る Tuple。[`Tuple(UInt32, Float64)`](/ja/reference/data-types/tuple)

**例**

**確率とともに分類**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

WITH naiveBayesClassifierWithProb('sentiment', 'a good and great film') AS p
SELECT (p.1, round(p.2, 4)) AS prediction;
```

```response title=Response
┌─prediction─┐
│ (0,0.9677) │
└────────────┘
```

## predictXGBoost {#predictXGBoost}

導入バージョン: v26.10.0

[`XGBOOST`](/ja/reference/statements/create/dictionary/layouts/xgboost) Dictionary を使用して、特徴量ベクトルから数値ターゲットを予測します。特徴量は位置依存で渡され、Dictionary のキーカラムを宣言した順序で指定します。`XGBOOST` Dictionary をクエリする方法はこの関数のみです。この Dictionary は行ではなく学習済みモデルを保持しているため、汎用的な Dictionary インターフェイス (`dictGet`、`dictHas`、`SELECT * FROM dict`) はサポートされていません。XGBoost インテグレーションは実験的な機能であるため、`enable_xgboost` 設定を有効にする必要があります。

**構文**

```sql
predictXGBoost(dictionary_name, feature1[, feature2, ...][, params])
```

**引数**

* `dictionary_name` — XGBOOST レイアウトを使用する Dictionary の名前。作成方法と指定可能な学習パラメータについては、[XGBOOST 辞書レイアウト](/ja/reference/statements/create/dictionary/layouts/xgboost)を参照してください。[`String`](/ja/reference/data-types/string)
* `featureN` — 数値の特徴量。Dictionary のキーの順序に従って位置で指定します。NULL の特徴量は欠損値としてモデルに渡され、XGBoost が学習時と同じ方法で処理するため、予測結果が NULL になることはありません。[`(U)Int*`](/ja/reference/data-types/int-uint) または [`Float*`](/ja/reference/data-types/float) または [`Nullable((U)Int*)`](/ja/reference/data-types/nullable) または [`Nullable(Float*)`](/ja/reference/data-types/nullable)
* `params` — 任意。XGBoost の予測パラメータを指定する定数の Map で、パラメータ名を整数値に対応付けます (例: `map('type', 0, 'iteration_end', 0)`) 。指定可能なパラメータはすべて整数またはブール値のため、小数値を指定するとエラーになります。指定可能なキーについては[予測パラメータ](/ja/reference/statements/create/dictionary/layouts/xgboost#prediction-parameters)を参照してください。[`Map(String, (U)Int8/16/32/64)`](/ja/reference/data-types/map)

**戻り値**

モデルの予測値を Float64 型で行ごとに 1 つ返します。[`Float64`](/ja/reference/data-types/float)

**例**

**予測**

```sql title=Query
-- A model trained on the linear target y = 2 * x1 + 3 * x2. The XGBoost integration is experimental.
SET enable_xgboost = 1;

CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO training_data SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y FROM numbers(100);

CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(objective 'reg:squarederror' num_iterations 100 max_depth 6))
LIFETIME(0);

-- The ground truth is 2 * 1 + 3 * 2 = 8.
SELECT round(predictXGBoost('model', 1.0, 2.0), 1) AS prediction;
```

```response title=Response
┌─prediction─┐
│          8 │
└────────────┘
```

**パラメータを指定して予測する**

```sql title=Query
-- The raw margin of the model above, before the objective's transformation. For `reg:squarederror` it is the
-- prediction itself, while for `binary:logistic` it is the log-odds rather than the probability.
SELECT round(predictXGBoost('model', 1.0, 2.0, map('type', 1)), 1) AS margin;
```

```response title=Response
┌─margin─┐
│      8 │
└────────┘
```
