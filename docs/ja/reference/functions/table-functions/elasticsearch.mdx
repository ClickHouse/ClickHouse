[Elasticsearch](https://www.elastic.co/elasticsearch) のインデックス内のドキュメントに対して `SELECT` クエリを実行できます。各ドキュメントは 1 行として返され、その `_source` は [JSON](/ja/reference/data-types/newjson) 型の単一カラムとして公開されます。また、ドキュメント ID とインデックス名は仮想カラムとして参照できます。この関数は読み取り専用です。

## 構文 {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  Elasticsearch インテグレーションは実験的機能です。[`enable_elasticsearch`](/ja/reference/settings/session-settings/enable#enable_elasticsearch) 設定を使用して有効化してください。

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## 引数 {#arguments}

| 引数             | 説明                                                                                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | Elasticsearch クラスターのベースURL(例: `https://localhost:9200`)。認証情報、クエリ文字列、フラグメントを含まない `http` または `https` の URL を指定する必要があります。                                                                       |
| `index`        | 読み取るインデックス。Elasticsearch の point in time API が受け付ける形式であれば、エイリアス、カンマ区切りのリスト、ワイルドカードパターンも指定できます。どのインデックスにも一致しないパターンを指定するとエラーになります。                                                             |
| `user`         | HTTP 基本認証のユーザー名(任意)。                                                                                                                                                                         |
| `password`     | HTTP 基本認証のパスワード(任意。`user` の指定が必要)。                                                                                                                                                           |
| `query('...')` | 読み取るドキュメントを選択するための、JSON 形式の Elasticsearch [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) オブジェクト(任意)。位置引数の後に指定する必要があります。デフォルト: `{"match_all": {}}`。 |

`url`、`index`、`user`、`password` の各引数は `key = value` 形式で指定することもできます。位置引数はこの順序で各引数に割り当てられます。同じ引数を位置引数とキーの両方で指定した場合(または同じキーを 2 回指定した場合)はエラーになります。

以下の引数は `key = value` 形式(または名前付きコレクションのキー)で指定できます。

| キー             | 説明                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `user`         | HTTP 基本認証のユーザー名。                                                                                                             |
| `password`     | HTTP 基本認証のパスワード。                                                                                                             |
| `bearer_token` | `Authorization: Bearer <token>` として送信されるトークン(例: Elasticsearch の service account トークン)。                                       |
| `api_key`      | `Authorization: ApiKey <api_key>` として送信される Elasticsearch のAPIキー。値には、APIキー作成 API が返す base64-encoded の `id:api_key` 文字列を指定します。 |

名前付きコレクションには `query` キーを含めることができます。この値をオーバーライドするには、コレクション名の後に `query('...')` または `query = '...'` を指定します。

さらに、このテーブル関数では以下も指定できます。

| キー          | 説明                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| `structure` | `'name JSON'` 形式のテーブル構造。`JSON` 型のカラムを 1 つだけ含める必要があります。また、`_id` と `_index` は予約された名前です。デフォルト: `'document JSON'`。 |

読み取り設定 `keep_alive` と `page_size` は、末尾の `SETTINGS` 句で指定できます。各設定の説明については [`Elasticsearch` テーブルエンジン](/ja/reference/engines/table-engines/integrations/elasticsearch#creating-a-table)を参照してください。

## 認証 {#authentication}

指定できる認証方式は最大1つです。

1. **基本認証**：`user` と `password` を指定します。
2. **Bearerトークン**：`bearer_token` を指定します。
3. **APIキー**：`api_key` を指定します。

いずれも指定しない場合、リクエストは匿名で送信されます。これは Elasticsearch でセキュリティが無効になっている場合にのみ動作します。

クエリごとに認証情報を指定しなくて済むよう、認証情報は[名前付きコレクション](/ja/concepts/features/configuration/server-config/named-collections)に保存してください。名前付きコレクションから作成した永続テーブル (`Elasticsearch` テーブルエンジン、または `CREATE TABLE ... AS elasticsearch(...)` で作成したもの) は、そのコレクションの依存オブジェクトとして登録されます。そのため、テーブルが存在する間は `DROP NAMED COLLECTION` を実行できません。

## 仮想カラム {#virtual-columns}

* `_id` — ドキュメントの ID。型: `String`。
* `_index` — ドキュメントの読み取り元のインデックス名。型: `LowCardinality(String)`。

クエリが仮想カラムのみを読み取る場合、ドキュメントの `_source` は Elasticsearch に要求されません。`_source` を保存しないインデックス (マッピングで `_source` フィールドが無効化されているもの) は、仮想カラム経由でのみ読み取れます。このようなインデックスから `JSON` カラムを読み取るクエリは、空のドキュメントを返さずにエラーで失敗します。

## 例 {#examples}

インデックス内のドキュメント数をカウントします：

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

ドキュメントのフィールドを `JSON` カラムのサブカラムとして読み取ります。

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

Query DSL オブジェクトを使って Elasticsearch 側でフィルタを適用し、ページサイズを調整します:

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

名前付きコレクションを使用する場合:

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## 制限事項 {#limitations}

* この関数は読み取り専用であり、`INSERT` はサポートされていません。
* 述語はプッシュダウンされません。`WHERE` 条件は、ドキュメントのダウンロード後に ClickHouse 側で適用されます。Elasticsearch 側でフィルタリングするには、`query` 引数を使用してください。
* `query` は 1 ページ分の `size` を指定して送信されます。`k` を指定しない `knn` クエリのように結果が `size` に依存するクエリでは、返されるドキュメントの集合が `page_size` によって変わります。このようなパラメータは明示的に指定してください。
* 各ページは個別の検索リクエストとして送信され、Elasticsearch は `query` 内の `now-1h` のような日付演算をリクエストのたびに評価し直します。特定の時点 (point in time) によってドキュメントは凍結されますが、時刻は凍結されません。そのため、時刻に依存する `query` では、移動する境界付近のドキュメントが警告なしに読み飛ばされる可能性があります。`query` では絶対日付を使用してください。
* 各読み取りでは、特定の時点 (point in time) をオープンし、`_shard_doc` でソートした `search_after` を用いて結果をページングし、最後に特定の時点をクローズします。いずれかの分片で失敗したページリクエストや、Elasticsearch でタイムアウトしたページリクエストは、部分的な結果を返さずにエラーを送出します。
* Elasticsearch 7.12 以降が必要です。この関数は point in time API と `_shard_doc` ソートフィールドに依存しているため、それより古いバージョンや OpenSearch では最初のリクエストが拒否されます。
* `page_size` には、Elasticsearch のインデックス設定 `index.max_result_window`(デフォルトは `10000`)を超える値は指定できません。
