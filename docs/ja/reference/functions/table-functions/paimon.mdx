Amazon S3、Azure、HDFS、またはローカルに保存された Apache [Paimon](https://paimon.apache.org/) テーブルへの読み取り専用のテーブル形式インターフェイスを提供します。

## 構文 {#syntax}

```sql
paimon(url [,access_key_id, secret_access_key] [,format] [,structure] [,compression] [,extra_credentials])

paimonS3(url [,access_key_id, secret_access_key] [,format] [,structure] [,compression] [,extra_credentials])

paimonAzure(connection_string|storage_account_url, container_name, blobpath, [,account_name], [,account_key] [,format] [,compression_method])

paimonHDFS(path_to_table, [,format] [,compression_method])

paimonLocal(path_to_table, [,format] [,compression_method])
```

## 引数 {#arguments}

引数の説明は、それぞれテーブル関数 `s3`、`azureBlobStorage`、`HDFS`、`file` の引数の説明と同じです。
`format` は、Paimon テーブル内のデータファイルのフォーマットを表します。

`paimonS3` では、ClickHouse Cloud でロールベースアクセス用の `role_arn` を渡すために、オプションの `extra_credentials` パラメータを使用できます。設定手順については、[Secure S3](/ja/products/cloud/guides/data-sources/accessing-s3-data-securely) を参照してください。

### 戻り値 {#returned-value}

指定した構造を持ち、指定したPaimonテーブルのデータを読み取るためのテーブル。

## 制限事項 {#limitations}

読み取り時のマージは実装されていないため、主キーを持つテーブルは、Paimon 自体がマージを行わずに読み取るケースに限り読み取れます。バケットが
読み取られるのは、そのすべてのデータファイルがレベル 0 より上にあり、retract 行を含まないことが判明しており、かつ同一レベルにある場合です。
`deletion-vectors.enabled` または `'merge-engine' = 'first-row'` を指定している場合は、ファイルが複数のレベルにまたがっていてもかまいません。また、
`batch-scan-mode` が `none` 以外のモードに設定されていない限り、Paimon と同様に、レベル 0 のファイルはコンパクションされるまで読み取られません。
それ以外のバケットを読み取ろうとすると例外がスローされます。Paimon でフルコンパクション (`compact_strategy => 'full'`) を実行すると、読み取れるようになります。

削除ベクターは適用されないため、**削除ベクターを含むスナップショットは読み取れません**。仮に読み取れたとしても、結果には後続の `DELETE` 文や `UPDATE` 文で削除された行が
残ったままになります。そのため、インデックスマニフェストに削除ベクターが記載されているスナップショットを読み取ろうとすると、`deletion-vectors.enabled` を無効にした後であっても例外がスローされます。
Paimon でフルコンパクション (`compact_strategy => 'full'`) を実行すると削除ベクターが適用され、それ以降に作成された
スナップショットは再び読み取れるようになります。

各データファイルは書き込み時のスキーマで読み取られ、その最上位のカラムは Paimon のフィールド ID によって現在のスキーマと照合されます。そのため、
リネームされたカラムや、削除後に同じ名前で再追加されたカラムも、Spark と同様に読み取れます。

`ROW` カラム内のフィールドは、Paimon のフィールド ID ではなく名前でデータファイルと照合されます。そのため、**`ROW` 内のフィールドがリネームされる前、
またはそのようなフィールドが削除されて同じ名前 (大文字と小文字を区別せずに比較) の別のフィールドが追加される前に書き込まれたデータファイルは読み取れません**。
仮に読み取れたとしても、結果ではリネームされたフィールドが `NULL` になり、再追加されたフィールドには削除されたフィールドの値が入ってしまいます。そのため、このようなデータファイルを読み取ろうとすると例外がスローされます。フィールドの追加と削除はサポートされています。
Paimon で現在のスキーマを使ってテーブルを書き換える (例: `INSERT OVERWRITE <table> SELECT * FROM <table>`) と、
それ以降に作成されたスナップショットは読み取れるようになります。

## named collection を定義する {#defining-a-named-collection}

以下は、URL と認証情報を保存するための named collection を設定する例です。

```xml
<clickhouse>
    <named_collections>
        <paimon_conf>
            <url>http://test.s3.amazonaws.com/clickhouse-bucket/</url>
            <access_key_id>test</access_key_id>
            <secret_access_key>test</secret_access_key>
            <format>auto</format>
            <structure>auto</structure>
        </paimon_conf>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM paimonS3(paimon_conf, filename = 'test_table')
DESCRIBE paimonS3(paimon_conf, filename = 'test_table')
```

## 別名 {#aliases}

現在、テーブル関数 `paimon` は `paimonS3` の別名です。

## 仮想カラム {#virtual-columns}

* `_path` — ファイルのパス。型: `LowCardinality(String)`.
* `_file` — ファイル名。型: `LowCardinality(String)`.
* `_size` — ファイルサイズ (バイト単位) 。型: `Nullable(UInt64)`. ファイルサイズが不明な場合、値は `NULL` です。
* `_time` — ファイルの最終更新時刻。型: `Nullable(DateTime)`. 時刻が不明な場合、値は `NULL` です。
* `_etag` — ファイルの etag。型: `LowCardinality(String)`. etag が不明な場合、値は `NULL` です。
