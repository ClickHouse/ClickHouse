<div id="description">
  ## 説明
</div>

現在のユーザー自身のクエリログレコードを表示します。`query_log.database` および `query_log.table` のサーバー設定で指定されたクエリログテーブル (デフォルトは `system.query_log`) を読み取り、実行開始ユーザーが `currentUser()` と一致する行のみを返します (実行開始ユーザーは、`initial_user` が設定されている場合はそこから、そうでない場合は `user` から取得されます) 。

クエリログテーブル自体とは異なり、`system.user_query_log` は権限なしで読み取れるため、ユーザーは他のユーザーのクエリへのアクセス権を付与されなくても、自身のクエリを確認できます。

これは、クエリログがローカルに保存されている場合にのみサポートされます。`query_log.engine` が `Distributed`、または読み取りを別のサーバーに委任するその他のエンジンとして設定されている場合、`system.user_query_log` はそのテーブルからの読み取りを拒否して例外をスローします。必要なアクセスチェックを ClickHouse プロトコルのサーバー境界を越えて適用できないためです。その場合は、`query_log.enable_user_query_log = 0` を設定してテーブルを無効にしてください。

このテーブルは、`query_log.enable_user_query_log` サーバー設定で無効にできます。クエリログが設定されていない場合、またはそのテーブルがまだ作成されていない場合、`system.user_query_log` は空です。

定数と比較するクエリログのパーティションおよびキーカラム (`event_date`、`event_time`、`query_start_time`、`query_id`、`type`、および同様のスカラーカラム) に対する条件は、基盤となるクエリログテーブルにプッシュダウンされます。そのため、以下の例のような通常のルックアップではパーティションプルーニングが維持され、保持されているログ全体はスキャンされません。

<Warning>
  このテーブルを提供する ClickHouse バージョンにアップグレードする前に、`system.user_query_log` という名前のテーブルが作成されていた場合、既存のテーブルをリネームまたは削除するか、`query_log.enable_user_query_log` を `0` に設定するまで、サーバーは起動しません。
</Warning>

<div id="example">
  ## 例
</div>

```sql
SELECT
    query_start_time,
    query_duration_ms,
    query
FROM system.user_query_log
ORDER BY query_start_time DESC
LIMIT 10;
```
