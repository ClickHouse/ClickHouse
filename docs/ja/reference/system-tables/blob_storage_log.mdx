## 説明 {#description}

アップロードや削除など、さまざまなブロブストレージ操作に関する情報を記録したログエントリが含まれます。

このテーブルはいつでも安全に truncate または drop できます。

## カラム {#columns}

* `hostname` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — クエリを実行するサーバーのホスト名。
* `clickhouse_version` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — この行を生成した ClickHouse サーバーのバージョン。
* `system_processor` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — この行を生成した ClickHouse サーバーの CPU アーキテクチャ。
* `event_date` ([Date](/ja/reference/data-types/date)) — イベントの日付。
* `event_time` ([DateTime](/ja/reference/data-types/datetime)) — イベントの時刻。
* `event_time_microseconds` ([DateTime64(6)](/ja/reference/data-types/datetime64)) — マイクロ秒精度のイベント時刻。
* `event_type` ([Enum8(&#39;Upload&#39; = 1, &#39;Delete&#39; = 2, &#39;MultiPartUploadCreate&#39; = 3, &#39;MultiPartUploadWrite&#39; = 4, &#39;MultiPartUploadComplete&#39; = 5, &#39;MultiPartUploadAbort&#39; = 6, &#39;Read&#39; = 7, &#39;Copy&#39; = 8)](/ja/reference/data-types/enum)) — イベントの種類。設定可能な値: &#39;Upload&#39;, &#39;Delete&#39;, &#39;MultiPartUploadCreate&#39;, &#39;MultiPartUploadWrite&#39;, &#39;MultiPartUploadComplete&#39;, &#39;MultiPartUploadAbort&#39;, &#39;Read&#39;, &#39;Copy&#39;
* `query_id` ([String](/ja/reference/data-types/string)) — イベントに関連付けられたクエリの識別子 (存在する場合) 。
* `thread_id` ([UInt64](/ja/reference/data-types/int-uint)) — 操作を実行するスレッドの識別子。
* `thread_name` ([String](/ja/reference/data-types/string)) — 操作を実行するスレッドの名前。
* `disk_name` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — 関連するディスクの名前。
* `bucket` ([String](/ja/reference/data-types/string)) — バケットの名前。
* `remote_path` ([String](/ja/reference/data-types/string)) — リモートリソースへのパス。
* `local_path` ([String](/ja/reference/data-types/string)) — リモートリソースを参照する、ローカルシステム上のメタデータファイルへのパス。
* `source_bucket` ([String](/ja/reference/data-types/string)) — &#39;Copy&#39; イベントにおけるコピー元オブジェクトのバケット名。その他のイベントでは空。
* `source_remote_path` ([String](/ja/reference/data-types/string)) — &#39;Copy&#39; イベントにおけるデータのコピー元オブジェクトへのパス。その他のイベントでは空。
* `data_size` ([UInt64](/ja/reference/data-types/int-uint)) — 操作で扱われるデータのサイズ。
* `elapsed_microseconds` ([UInt64](/ja/reference/data-types/int-uint)) — 操作の経過時間 (マイクロ秒) 。
* `connection_id` ([UInt64](/ja/reference/data-types/int-uint)) — 操作に使用された HTTP 接続の識別子で、サーバープロセス内で一意です。1 つの接続を追跡するには、この値でグループ化してください。OS はソケットが閉じられるとすぐにポートやソケットの inode を再利用するため、それらでは連続する接続を区別できません。この行を単一の HTTP リクエストに対応付けられない場合は 0 になります。具体的には、操作が HTTP 接続を使用しなかった場合、複数の接続を使用した場合 (再試行された書き込みは、すべての試行を含む経過時間を持つ 1 行として記録されるため、単一の接続では表せません) 、または 1 つのリクエストを他の行と共有した場合 (バッチ削除ではオブジェクトごとに 1 行の `Delete` 行が書き込まれ、接続はそのうち最初の行にのみ対応付けられます) です。すべての `connection_*` カラムは、`connection_id` が 0 でない場合にのみ意味を持ち、それ以外の場合はすべて 0 になります。
* `connection_local_port` ([UInt16](/ja/reference/data-types/int-uint)) — その接続のローカル TCP ポート。同時点で開いているソケットの間でのみ一意です。同じ時点で取得したパケットキャプチャや /proc/net/tcp の行と突き合わせる際に使用します。
* `connection_socket_inode` ([UInt64](/ja/reference/data-types/int-uint)) — fstat が報告する、その接続のソケット inode。ポートと同様の注意点があり、ソケットが開いている間のみ一意です。macOS のように OS がソケットの inode を公開しない場合は 0。
* `connection_requests` ([UInt32](/ja/reference/data-types/int-uint)) — この接続が今回のリクエストより前に送信していたリクエスト数。`connection_id` が 0 でない場合、0 はこれがその接続の最初のリクエストであったことを示します。
* `connection_age_microseconds` ([UInt64](/ja/reference/data-types/int-uint)) — 接続の TCP socket が確立されてからの経過時間。再接続のたびにリセットされるため、session オブジェクトではなく socket の存続期間を表します。
* `connection_idle_microseconds` ([UInt64](/ja/reference/data-types/int-uint)) — この操作に割り当てられるまでに、接続が pool 内でアイドル状態だった時間。接続の最初のリクエストでは 0 となり、`connection_id` が 0 の場合も 0 となります。
* `error_code` ([Int32](/ja/reference/data-types/int-uint)) — 操作のエラーコード。エラーがなかった場合は 0。
* `error` ([String](/ja/reference/data-types/string)) — イベントに関連付けられたエラーメッセージ (存在する場合) 。

## 例 {#example}

ブロブストレージでファイルをアップロードし、イベントが記録されるとします：

```sql
SELECT * FROM system.blob_storage_log WHERE query_id = '7afe0450-504d-4e4b-9a80-cd9826047972' ORDER BY event_date, event_time_microseconds \G
```

```text
Row 1:
──────
hostname:                clickhouse.eu-central1.internal
event_date:              2023-10-31
event_time:              2023-10-31 16:03:40
event_time_microseconds: 2023-10-31 16:03:40.481437
event_type:              Upload
query_id:                7afe0450-504d-4e4b-9a80-cd9826047972
thread_id:               2381740
disk_name:               disk_s3
bucket:                  bucket1
remote_path:             rrr/kxo/tbnqtrghgtnxkzgtcrlutwuslgawe
local_path:              store/654/6549e8b3-d753-4447-8047-d462df6e6dbe/tmp_insert_all_1_1_0/checksums.txt
data_size:               259
error:
```

この例では、アップロード操作は ID `7afe0450-504d-4e4b-9a80-cd9826047972` の `INSERT` クエリに関連付けられています。ローカルのメタデータファイル `store/654/6549e8b3-d753-4447-8047-d462df6e6dbe/tmp_insert_all_1_1_0/checksums.txt` は、ディスク `disk_s3` 上のバケット `bucket1` 内のリモートパス `rrr/kxo/tbnqtrghgtnxkzgtcrlutwuslgawe` を参照しており、サイズは 259 バイトです。
