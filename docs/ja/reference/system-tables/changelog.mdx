## 説明 {#description}

ClickHouse の厳選された変更ログ (リポジトリ内の `CHANGELOG.md`) のエントリを格納します。各機能リリースのエントリが 1 件につき 1 行として格納されるため、リリースノートを SQL でクエリできます。

## カラム {#columns}

* `version` ([Tuple(major UInt16, minor UInt8, patch UInt16)](/ja/reference/data-types/tuple)) — エントリが属するリリースのバージョン。比較可能なタプルとして表されます。キュレーションされた変更ログは機能リリースを対象としているため、`patch` は 0 になります。
* `release_date` ([Date](/ja/reference/data-types/date)) — リリース日。
* `is_lts` ([UInt8](/ja/reference/data-types/int-uint)) — 長期サポートリリースの場合は 1。
* `category` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — エントリが属する変更ログのセクション。例: &#39;New Feature&#39;、&#39;Performance Improvement&#39;、&#39;Bug Fix&#39;。
* `description` ([String](/ja/reference/data-types/string)) — 変更履歴エントリの本文。
* `pull_requests` ([Array(UInt32)](/ja/reference/data-types/array)) — エントリが参照するプルリクエストの番号。
* `authors` ([Array(String)](/ja/reference/data-types/array)) — 参照されているプルリクエストの著者。

## 例 {#example}

JSON 関連の最近の変更を、新しいリリースから順に検索します。

```sql
SELECT version, category, description
FROM system.changelog
WHERE description ILIKE '%JSON%' AND version >= (26, 1, 0)
ORDER BY version DESC
LIMIT 3
```
