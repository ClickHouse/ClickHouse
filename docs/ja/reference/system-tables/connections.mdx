## 説明 {#description}

ネイティブTCPおよびHTTPのクエリインターフェイスで開かれているクライアント接続を表示します。
クエリの実行中、接続は `active` になります。次のクエリを待機している間、接続は `idle` になります。

このテーブルには、次の接続は表示されません。

* 他のプロトコルの接続 (例: MySQL、PostgreSQL、gRPC)
* サーバー間接続
* クエリを実行しなかったHTTP接続 (例: `/ping` や Prometheus の接続)

サーバーが接続を収集するのは、サーバー設定 `collect_connection_metrics` が `true` の場合のみです。この設定が `false` の場合、テーブルは空になります。
この設定は再起動なしで変更できます (`SYSTEM RELOAD CONFIG`) 。

* 設定を `false` に変更すると、テーブルは空になり、サーバーは新規接続の登録を停止します。
* 設定を `true` に変更すると、開いている接続は次のクエリ実行時にテーブルに表示されます。

TCP接続は、認証後にテーブルに追加され、接続が閉じられると削除されます。
HTTP 接続は、最初のクエリ実行時にテーブルに追加され、socket が閉じられると削除されます。
そのため、HTTP keep-alive 接続は、リクエストとリクエストの間は `idle` としてテーブルに表示されます。

`SHOW CONNECTIONS` 権限を持たないユーザーには、そのユーザー自身の接続のみが表示されます。
このチェックでは、名前ではなくユーザー ID が使用されます。そのため、リネームされたユーザーは引き続き自身の接続を参照でき、古い名前で作成された新しいユーザーにはそれらの接続は表示されません。

`connection_id` はランダムな UUID です。そのためサーバー間で重複せず、たとえば `clusterAllReplicas` を使用して複数のレプリカのテーブルを結合できます。

`connected_time` はTCPとHTTPのどちらでも同じ意味を持ち、サーバーが socket の処理を開始した時刻を表します。
この時刻は、TCPハンドシェイク、認証、最初のクエリよりも前です。そのため、接続がテーブルに表示された時刻よりも早くなる場合があります。

## カラム {#columns}

* `connection_id` ([UUID](/ja/reference/data-types/uuid)) — 接続の一意な識別子 (ランダムな UUID) 。`clusterAllReplicas` などで参照した場合でも、サーバー間で一意です。TCP接続では認証後に識別子が割り当てられ、HTTP 接続では最初のクエリ実行時に割り当てられます。
* `protocol` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — 接続のプロトコル。TCP (ネイティブプロトコル) または HTTP のいずれかです。
* `client_address` ([IPv6](/ja/reference/data-types/ipv6)) — クライアントの IPアドレス。プロキシ経由の場合、サーバーが PROXY プロトコルまたは `X-Forwarded-For` ヘッダーを信頼していれば、元のクライアントのアドレスになります。HTTP の場合は、最後のリクエストのアドレスです。
* `client_port` ([UInt16](/ja/reference/data-types/int-uint)) — クライアントの TCP ポート。プロキシ経由の場合、サーバーが PROXY プロトコルまたは `X-Forwarded-For` ヘッダーを信頼していれば、そこから取得したポートになります。HTTP の場合は、最後のリクエストのポートです。
* `server_port` ([UInt16](/ja/reference/data-types/int-uint)) — 接続を受け付けたサーバーのポート。
* `user` ([String](/ja/reference/data-types/string)) — 認証済みユーザーの名前。HTTP 接続の場合は、最後のリクエストのユーザーです。keep-alive 接続では、リクエストごとに個別に認証が行われます。ユーザーがリネームされた場合、次の認証までこのカラムには旧名が表示されます。なお、アクセスチェックには名前ではなくユーザー ID が使用されます。
* `status` ([LowCardinality(String)](/ja/reference/data-types/lowcardinality)) — 接続のステータス。`active`: クエリを実行中です。`idle`: 接続は開いた状態で、次のクエリまたは次の HTTPリクエストを待機しています。
* `query_id` ([String](/ja/reference/data-types/string)) — 実行中のクエリの識別子。接続がアイドル状態の場合は空です。
* `client_name` ([String](/ja/reference/data-types/string)) — クライアントアプリケーションの名前。TCPクライアントの場合はハンドシェイク時に送信される名前です。HTTP の場合は、最後のリクエストの `User-Agent` ヘッダーの値です。
* `client_version_major` ([UInt64](/ja/reference/data-types/int-uint)) — TCP ハンドシェイクで取得したクライアントのメジャーバージョン。HTTP 接続では 0 です。
* `client_version_minor` ([UInt64](/ja/reference/data-types/int-uint)) — TCP ハンドシェイクで取得したクライアントのマイナーバージョン。HTTP 接続では 0 です。
* `client_version_patch` ([UInt64](/ja/reference/data-types/int-uint)) — TCP ハンドシェイクで取得したクライアントのパッチバージョン。HTTP 接続では 0 です。
* `connected_time` ([DateTime](/ja/reference/data-types/datetime)) — サーバーが socket の処理を開始した時刻。TCP と HTTP のいずれでも基準は同じで、ハンドシェイク、認証、最初のクエリよりも前の時点を指します。
* `last_query_time` ([Nullable(DateTime)](/ja/reference/data-types/nullable)) — この接続で最後に実行されたクエリの開始時刻。この接続でまだクエリが実行されていない場合は NULL です。

## 例 {#examples}

```sql
SELECT connection_id, protocol, user, status, query_id, client_name, connected_time, last_query_time
FROM system.connections
FORMAT Vertical;
```

```sql
SELECT hostName(), protocol, status, count()
FROM clusterAllReplicas(default, system.connections)
GROUP BY ALL;
```
