## 説明 {#description}

システム内で発生したイベント数に関する情報が含まれています。たとえば、このテーブルでは、ClickHouseサーバーの起動以降に処理された `SELECT` クエリの数を確認できます。

## イベントの説明 {#event-descriptions}

### ACMEAPIRequests {#acmeapirequests}

発行された ACME API リクエストの数。

### ACMECertificateOrders {#acmecertificateorders}

発行された ACME 証明書オーダー数。

### AdaptiveAggregationBucketsRetired {#adaptiveaggregationbucketsretired}

マージ全体の完了に先立ち、マージと変換が終わった直後に作業用メモリ (アリーナの slot、ステージされた chunk への参照) が解放された二段階バケットの数。

### AdaptiveAggregationDrainedRecords {#adaptiveaggregationdrainedrecords}

アダプティブ集約がマージ時に共有テーブルへドレインした遅延レコードの数。

### AdaptiveAggregationGiveUps {#adaptiveaggregationgiveups}

アダプティブ集約において、ストリームが保持する個別キーの数が少なかったため、フリーズを断念したスレッドの数。

### AdaptiveAggregationLocalFreezes {#adaptiveaggregationlocalfreezes}

アダプティブ集約が凍結しきい値に達して凍結したローカルハッシュテーブルの数。

### AdaptiveAggregationPressureDrainedRecords {#adaptiveaggregationpressuredrainedrecords}

メモリ逼迫時にアダプティブ集約が早期にドレインしたステージ済みレコード数。

### AdaptiveAggregationPressureStandDowns {#adaptiveaggregationpressurestanddowns}

アダプティブ集約において、メモリ逼迫が external aggregation の threshold を超えたため、学習 phase から完全に離脱したスレッドの数です。これらのスレッドのローカルテーブルは、通常の external aggregation を経由してスピルします。

### AdaptiveAggregationPressureSweeps {#adaptiveaggregationpressuresweeps}

アダプティブ集約が、メモリ逼迫のためにステージ済みレコードを早期にドレインした回数。

### AdaptiveAggregationProbeBypasses {#adaptiveaggregationprobebypasses}

アダプティブ集約において、凍結されたローカルテーブルにヒットする行がほとんどなかったため、そのテーブルへのプローブを停止したスレッドの数。

### AdaptiveAggregationResidueReleases {#adaptiveaggregationresiduereleases}

ベースラインアルゴリズムに戻ったスレッドが、その影響でスピルしそうになったために、アダプティブ集約が共有ドレインテーブルを書き出した回数。

### AdaptiveAggregationSealedChunks {#adaptiveaggregationsealedchunks}

アダプティブ集約が、バッファリングされた staging バッチから結合して確定した chunk の数。

### AdaptiveAggregationSealNormalizations {#adaptiveaggregationsealnormalizations}

アダプティブ集約のシール処理が、ラップされた表現 (Const、Replicated、Sparse、LowCardinality) から、ドレインが消費する密な形式へ正規化したステージ済み引数カラムの数。

### AdaptiveAggregationSharedTableSpills {#adaptiveaggregationsharedtablespills}

アダプティブ集約が、メモリ逼迫下でパーツ数の上限に達したために共有ドレインテーブルを書き出した回数。

### AdaptiveAggregationSpillBacklogSheds {#adaptiveaggregationspillbacklogsheds}

ステージ済みのレコードがまだ残っている状態で、baseline アルゴリズム上のスレッド (thaw によってそこへ戻されたもの、または自ら退いたもの) がスピルしようとしたため、アダプティブ集約がステージ済みのバックログを破棄した回数。

### AdaptiveAggregationStagedBytes {#adaptiveaggregationstagedbytes}

アダプティブ集約がマージ時のドレインに向けてステージングしたキーのバイト数。

### AdaptiveAggregationStagedChunkPiecesOverBound {#adaptiveaggregationstagedchunkpiecesoverbound}

アダプティブ集約が publish した、分割済みステージング chunk のピースのうち、分割の目的であった bound を依然として超えているものの数です。chunk はバケット境界に沿って分割され、単独で bound を超えているバケット内ではさらにレコード単位で分割されます。そのため、これはステージングされたバイト数だけで bound を超えてしまう単一のレコードに相当します。このようなピースは丸ごと claim されるため、その drain は圧力パーツをその分だけ超過する可能性があります。

### AdaptiveAggregationStagedChunkSplits {#adaptiveaggregationstagedchunksplits}

1 つの chunk のドレイン量が pressure part の bound を超えると見積もられたため、アダプティブ集約が publication 時にバケット境界で分割した staged chunk の数。

### AdaptiveAggregationStagedClaimsClosedAtBound {#adaptiveaggregationstagedclaimsclosedatbound}

アダプティブ集約のドレインによるステージ済み chunk の claim のうち、ある chunk を追加すると batch が pressure パーツの bound を超えてしまうため、その chunk を次の claim に残して閉じられた claim の数。bound はドレインされる時点の batch に対して適用されるため、いずれも bound をわずかに下回る 2 つの chunk (パーツの半分を数レコードだけ超える、cut された chunk の 2 つの断片) は、1 つではなく 2 つのテーブルへドレインされます。ただし、単独で bound を超える先頭の chunk だけは、無条件に claim されます。

### AdaptiveAggregationStagedRecords {#adaptiveaggregationstagedrecords}

アダプティブ集約が deduplication の前にステージングした遅延レコード数。

### AdaptiveAggregationStagedRecordsMerged {#adaptiveaggregationstagedrecordsmerged}

アダプティブ集約が、パブリッシュ時およびシール時に重複キーとしてマージし、削除したステージング済みレコードの数。

### AdaptiveAggregationThaws {#adaptiveaggregationthaws}

ステージングされたストリームに繰り返しが多いと判明したために、アダプティブ集約がローカルテーブルを解凍した回数。

top-K 集約のヒープが凍結され、通常の集約にフォールバックした回数。ヒープが観測 window 内でほとんど何も棄却しなかった (例: 異なる grouping key の数が LIMIT を超えない) か、あるいはヒープの boundary にある同値集合 (決して追い出すことができない) が肥大化してヒープを超えたかのいずれかです (`enable_group_by_top_k_optimization` を参照) 。

### AggregationTopKKeysEvicted {#aggregationtopkkeysevicted}

集約中に、上限付きの top-K ヒープから追い出されたグループ化キーの数 (`enable_group_by_top_k_optimization` を参照) 。

### AggregationTopKKeysPruned {#aggregationtopkkeyspruned}

追い出された grouping key のうち、中間ハッシュテーブルからも削除され、その aggregate state が破棄されたものの数 (`enable_group_by_top_k_optimization` を参照) 。aggregation method が key を削除できない場合や、key のプレフィックスのみがランク付けの対象となっている場合は、`AggregationTopKKeysEvicted` よりも小さくなります。これらの場合、heap は引き続き行をスキップしますが、ハッシュテーブルには受け入れたグループがすべて残ります。

### DataAfterMergeDiffersFromReplica {#dataaftermergediffersfromreplica}

マージ後のデータが、別のレプリカ上のデータとバイト単位で一致しなかった回数です。原因としては、次のようなものが考えられます。

1. サーバーの更新後に、新しいバージョンの圧縮ライブラリを使用している。
2. 別の圧縮方式を使用している。
3. 圧縮アルゴリズムが決定論的でない (可能性は極めて低い) 。
4. コード内の論理エラーにより、マージアルゴリズムが決定論的でなくなっている。

6. ハードウェアの問題により、メモリ内のデータが破損している。
7. サーバーの起動後に、元データが手動で変更された。
8. ZooKeeper に保存されているチェックサムが手動で変更された。
9. &#39;enable&#95;mixed&#95;granularity&#95;parts&#39; のようなパーツのフォーマットに関する設定が、レプリカごとに異なる。
   サーバーはこの状況を正常に検出しており、バイト単位で同一の結果にするため、レプリカからマージ済みパーツをダウンロードします。
