## 説明 {#description}

このテーブルには、即座に計算でき、Prometheus フォーマットでエクスポート可能な次元メトリクスが含まれています。常に最新の状態に保たれています。

## メトリクスの説明 {#metric_descriptions}

### merge_failures {#merge_failures}

起動以降に失敗したマージの総数。

### startup_scripts_failure_reason {#startup_scripts_failure_reason}

起動スクリプトの失敗をエラー種別ごとに示します。起動スクリプトが失敗すると1に設定され、エラー名のラベルが付与されます。

### merge_tree_parts {#merge_tree_parts}

MergeTree データパーツの数。パーツの状態、パーツのタイプ、およびプロジェクションパーツかどうかによってラベル付けされます。

### `filesystem_cache_evictions_total` {#filesystem-cache-evictions-total}

ファイルシステムキャッシュから追い出されたファイルセグメントの数。キャッシュ名ごとにラベル付けされます。デフォルトでは無効になっているため、`expose_prometheus_eviction_metrics` で有効にします。

### `filesystem_cache_evicted_bytes_total` {#filesystem-cache-evicted-bytes-total}

キャッシュ名ごとにラベル付けされた、ファイルシステムキャッシュから追い出されたファイルセグメントの合計バイト数。デフォルトでは無効です。`expose_prometheus_eviction_metrics` を使用して有効にします。

### `filesystem_cache_evictions_by_user_total` {#filesystem-cache-evictions-by-user-total}

ファイルシステムキャッシュから追い出されたファイルセグメントの数。キャッシュ名とユーザー ID ごとにラベル付けされます。デフォルトでは無効で、`expose_prometheus_eviction_metrics` と `expose_prometheus_eviction_metrics_per_user` で有効にできます。

### `filesystem_cache_evicted_bytes_by_user_total` {#filesystem-cache-evicted-bytes-by-user-total}

ファイルシステムキャッシュから追い出されたファイルセグメントの合計バイト数。キャッシュ名とユーザー ID ごとにラベル付けされます。デフォルトでは無効です。`expose_prometheus_eviction_metrics` と `expose_prometheus_eviction_metrics_per_user` で有効にします。

### `object_storage_queue_failures_total` {#object-storage-queue-failures-total}

データベース、テーブル、処理ステージ (`read`、`set_processing`、`insert`、`commit`、`after_processing`) 、エラーコードごとにラベル付けされた `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) の失敗回数。`after_processing` ステージの場合、この値は `after_processing` アクション (削除、タグ付け、移動) が完了しなかったオブジェクトの数を表します。

### `object_storage_queue_permanently_failed_files_total` {#object-storage-queue-permanently-failed-files-total}

再試行をすべて使い果たした後 (または再試行が無効な場合) に、永続的に処理を断念した `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) ファイルの数。データベースおよびテーブルでラベル付けされます。各ファイルは、そのデータが今後処理されることのないファイルを表します。

### `object_storage_queue_newest_seen_object_timestamp_seconds` {#object-storage-queue-newest-seen-object-timestamp-seconds}

`ObjectStorageQueue` (`S3Queue`/`AzureQueue`) テーブルでこれまでに検出された最新オブジェクトの最終更新時刻を表すUnix タイムスタンプ。データベースおよびテーブルでラベル付けされます。この系列は、テーブルが削除またはデタッチされると削除されます。リネーム後は、サーバーが再起動されるまで旧名の系列が残ります。

### `object_storage_queue_newest_committed_object_timestamp_seconds` {#object-storage-queue-newest-committed-object-timestamp-seconds}

`ObjectStorageQueue` (`S3Queue`/`AzureQueue`) テーブルでこれまでに完全に処理された最新のオブジェクトの最終更新時刻を表すUnix タイムスタンプ。データベースおよびテーブルでラベル付けされます。この系列は、テーブルが削除またはデタッチされると削除されます。リネームした場合、旧名の系列はサーバーが再起動されるまで残ります。

### `object_storage_queue_processed_files_total` {#object-storage-queue-processed-files-total}

このサーバー上のこの `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) テーブルで処理済みとしてコミットされたファイルの数。データベースおよびテーブルでラベル付けされます。

### `object_storage_queue_last_poll_timestamp_seconds` {#object-storage-queue-last-poll-timestamp-seconds}

このサーバー上の `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) テーブルのバックグラウンドストリーミングスレッドが、処理対象のファイルを探すサイクル、またはそのサイクル内のバッチを最後に開始した時刻を示すUnix タイムスタンプです。データベースとテーブルのラベルが付与されます。この値は、テーブルが自身を Keeper にアクティブとして登録した後のサイクル開始時に設定され、さらにサイクル内の各バッチの開始前にも更新されます。そのため、サイクルでファイルが見つからなかった場合や失敗した場合、また大量のバックログを処理している間も値は進みます。登録に失敗した場合、値は進みません。値 0 は、テーブルの起動以降一度もポーリングが行われていないことを示します。テーブルに準備完了状態のアタッチ済み materialized view が存在しない間、ストリーミングが停止または一時停止されている間、あるいはサーバー上でストリーミングが無効化されている間は、テーブルが消費を行わないため値は進みません。テーブルのすべてのストリーミングスレッドが同じ系列に書き込むため、いずれかのスレッドによる最新のサイクルが反映されます。この系列は、テーブルが削除またはデタッチされると削除されます。リネームした場合、旧名の系列はサーバーを再起動するまで残ります。

### `system_log_flushes_total` {#system-log-flushes-total}

システムログのインメモリバッファを対応するテーブルへ flush しようとした試行回数です。付与されるラベルは、システムログのデータベースとテーブル、および結果 (`success`、`failure`) です。

### `system_log_flushed_rows_total` {#system-log-flushed-rows-total}

システムログの flush が成功した際に書き込まれた行数。付与されるラベルは、そのシステムログのデータベースとテーブルです。

### `system_log_dropped_rows_total` {#system-log-dropped-rows-total}

システムログで失われた行の数です。付与されるラベルは、システムログのデータベース、テーブル、および理由です。理由は、インメモリバッファが `max_size_rows` に達したため受け付けられなかった行を表す `queue_full`(次回の flush のためにバッファが取り出される時点で更新されます)と、flush に失敗した行を表す `flush_failed` のいずれかです。

## カラム {#columns}

* `metric` ([String](/ja/reference/data-types/string)) — メトリクス名。
* `value` ([Float64](/ja/reference/data-types/float)) — メトリクス値。
* `description` ([String](/ja/reference/data-types/string)) — メトリクスの説明。
* `labels` ([Map(String, String)](/ja/reference/data-types/map)) — メトリクスラベル。

**別名:**

* `name` — `metric` の別名。

## 例 {#example}

次のようなクエリを使うと、すべての次元メトリクスをPrometheusフォーマットでエクスポートできます。

```sql
SELECT
  metric AS name,
  toFloat64(value) AS value,
  description AS help,
  labels,
  'gauge' AS type
FROM system.dimensional_metrics
FORMAT Prometheus
```
