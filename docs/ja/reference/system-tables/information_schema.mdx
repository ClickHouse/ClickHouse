`INFORMATION_SCHEMA` (または `information_schema`) は、データベースオブジェクトのメタデータに対する、ある程度標準化された[DBMS 非依存のビュー](https://en.wikipedia.org/wiki/Information_schema)を提供するシステムデータベースです。`INFORMATION_SCHEMA` のビューは、通常のシステムテーブルと比べると一般に機能が限定的ですが、ツールはこれらを利用して、DBMS をまたいで基本的な情報を取得できます。`INFORMATION_SCHEMA` のビューの構造と内容は、後方互換性を維持しながら発展していくことが想定されています。つまり、新しい機能のみが追加され、既存の機能は変更または削除されません。内部実装の観点では、`INFORMATION_SCHEMA` のビューは通常、[system.columns](/ja/reference/system-tables/columns)、[system.databases](/ja/reference/system-tables/databases)、[system.tables](/ja/reference/system-tables/tables) などの通常のシステムテーブルに対応付けられています。

```sql
SHOW TABLES FROM INFORMATION_SCHEMA;

-- or:
SHOW TABLES FROM information_schema;
```

他のデータベースとの互換性のため、`INFORMATION_SCHEMA.columns` のような大文字と小文字を区別しない同等のビューも提供されています。同様に、これらのビュー内のすべてのカラムについても、小文字 (たとえば `table_name`) と大文字 (`TABLE_NAME`) の両方のバリアントが提供されています。

## SCHEMATA {#schemata}

* `default_character_set_schema` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — `NULL`。未サポートです。
* `default_character_set_name` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — `NULL`。未サポートです。

## TABLES {#tables}

[system.tables](/ja/reference/system-tables/tables) システムテーブルから読み取られるカラムが含まれます。

カラム:

* `table_catalog` ([String](/ja/reference/data-types/string)) — テーブルが存在するデータベースの名前。
* `table_schema` ([String](/ja/reference/data-types/string)) — テーブルが存在するデータベースの名前。
* `table_name` ([String](/ja/reference/data-types/string)) — テーブル名。
* `table_type` ([String](/ja/reference/data-types/string)) — テーブルの種類。設定可能な値:
  * `BASE TABLE`
  * `VIEW`
  * `FOREIGN TABLE`
  * `LOCAL TEMPORARY`
  * `SYSTEM VIEW`
* `table_rows` ([Nullable](/ja/reference/data-types/nullable)([UInt64](/ja/reference/data-types/int-uint))) — 行の総数。判定できない場合は NULL。
* `data_length` ([Nullable](/ja/reference/data-types/nullable)([UInt64](/ja/reference/data-types/int-uint))) — ディスク上のデータのサイズ。判定できない場合は NULL。
* `index_length` ([Nullable](/ja/reference/data-types/nullable)([UInt64](/ja/reference/data-types/int-uint))) — 主キー、セカンダリ索引、およびすべてのマークの合計サイズ。
* `table_collation` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — テーブルのデフォルトの照合順序。常に `utf8mb4_0900_ai_ci` です。
* `table_comment` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — テーブル作成時に使用されるコメント。

**例**

```sql title="Query"
SELECT table_catalog, 
       table_schema, 
       table_name, 
       table_type, 
       table_collation, 
       table_comment
FROM INFORMATION_SCHEMA.TABLES
WHERE (table_schema = currentDatabase() OR table_schema = '')
  AND table_name NOT LIKE '%inner%'
LIMIT 1 
FORMAT Vertical;
```

```text title="Response"
Row 1:
──────
table_catalog:   default
table_schema:    default
table_name:      describe_example
table_type:      BASE TABLE
table_collation: utf8mb4_0900_ai_ci
table_comment:   
```

## VIEWS {#views}

テーブルエンジン [View](/ja/reference/engines/table-engines/special/view) を使用している場合、[system.tables](/ja/reference/system-tables/tables) システムテーブルから読み取られるカラムが含まれます。

カラム:

{/*AUTOGENERATED_START*/}

* `table_catalog` ([String](/ja/reference/data-types/string)) — テーブルが存在するデータベースの名前。
* `table_schema` ([String](/ja/reference/data-types/string)) — テーブルが存在するデータベースの名前。
* `table_name` ([String](/ja/reference/data-types/string)) — テーブル名。
* `view_definition` ([String](/ja/reference/data-types/string)) — ビューの `SELECT` クエリ。
* `check_option` ([String](/ja/reference/data-types/string)) — `NONE`、チェックは行われません。
* `is_updatable` ([Enum8](/ja/reference/data-types/enum)) — `NO`、ビューは更新されません。
* `is_insertable_into` ([Enum8](/ja/reference/data-types/enum)) — 作成されたビューが[マテリアライズド](/ja/reference/statements/create/view#materialized-view)かどうかを示します。設定可能な値:
  * `NO` — 作成されたビューはマテリアライズドではありません。
  * `YES` — 作成されたビューはマテリアライズドです。
* `is_trigger_updatable` ([Enum8](/ja/reference/data-types/enum)) — `NO`、トリガーは更新されません。
* `is_trigger_deletable` ([Enum8](/ja/reference/data-types/enum)) — `NO`、トリガーは削除されません。
* `is_trigger_insertable_into` ([Enum8](/ja/reference/data-types/enum)) — `NO`、トリガーにはデータは挿入されません。

{/*AUTOGENERATED_END*/}

**例**

```sql title="Query"
CREATE VIEW v (n Nullable(Int32), f Float64) AS SELECT n, f FROM t;
CREATE MATERIALIZED VIEW mv ENGINE = Null AS SELECT * FROM system.one;
SELECT table_catalog,
       table_schema,
       table_name,
       view_definition,
       check_option,
       is_updatable,
       is_insertable_into,
       is_trigger_updatable,
       is_trigger_deletable,
       is_trigger_insertable_into
FROM information_schema.views
WHERE table_schema = currentDatabase() 
LIMIT 1
FORMAT Vertical;
```

```text title="Response"

table_schema:               default
table_name:                 mv
```

## COLLATIONS {#collations}

使用可能な照合順序に関する情報を提供します。[system.collations](/ja/reference/system-tables/collations) の照合順序に加え、MySQL 互換性のための 2 行が含まれます。`utf8mb4_0900_ai_ci` は、MySQL プロトコルがハンドシェイク時、`SCHEMATA.DEFAULT_COLLATION_NAME`、および `TABLES.TABLE_COLLATION` で通知する照合順序です。`binary` は、MySQL プロトコルが結果セットのメタデータ内の数値カラムやその他の非文字列カラムに設定する疑似照合順序です。これにより、通知された照合順序に従ってこのビューを参照する MySQL 対応クライアントは、これらの照合順序を見つけられます。

カラム:

* `collation_name` ([String](/ja/reference/data-types/string)) — 照合順序の名前。
* `character_set_name` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — 関連付けられた文字セット (`utf8mb4_0900_ai_ci` では `utf8mb4`、`binary` では `binary`、それ以外は `NULL`) 。MySQL 互換性のために提供されます。
* `id` ([Nullable](/ja/reference/data-types/nullable)([UInt64](/ja/reference/data-types/int-uint))) — MySQL の照合順序 ID (`utf8mb4_0900_ai_ci` では `255`、`binary` では `63`、それ以外は `NULL`) 。MySQL 互換性のために提供されます。
* `is_default` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — 照合順序がその文字セットのデフォルトかどうか (両方の MySQL 互換性行では `Yes`、それ以外は `NULL`) 。MySQL 互換性のために提供されます。
* `is_compiled` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — 照合順序がサーバーにコンパイルされているかどうか (両方の MySQL 互換性行では `Yes`、それ以外は `NULL`) 。MySQL 互換性のために提供されます。
* `sortlen` ([Nullable](/ja/reference/data-types/nullable)([UInt64](/ja/reference/data-types/int-uint))) — 最小ソート長 (`utf8mb4_0900_ai_ci` では `0`、`binary` では `1`、それ以外は `NULL`) 。MySQL 互換性のために提供されます。
* `pad_attribute` ([Nullable](/ja/reference/data-types/nullable)([String](/ja/reference/data-types/string))) — パディング属性 (`NO PAD` または `PAD SPACE`) 。両方の MySQL 互換性行では `NO PAD`、それ以外は `NULL` です。MySQL 互換性のために提供されます。

## CHARACTER_SETS {#character_sets}

MySQL ツールとの互換性を保つため、文字セット (`utf8`、`utf8mb4`、`ascii`、`binary`) の静的な一覧を提供します。ClickHouse 自体は UTF-8 を使用します。

カラム:

* `character_set_name` ([String](/ja/reference/data-types/string)) — 文字セット名。

## ENGINES {#engines}

利用可能なテーブルエンジンに関する情報を提供します。この情報は [system.table&#95;engines](/ja/reference/system-tables/table_engines) システムテーブルから取得されます。MySQL との互換性のために提供されています。

カラム:

* `engine` ([String](/ja/reference/data-types/string)) — テーブルエンジン名。
* `support` ([String](/ja/reference/data-types/string)) — [default&#95;table&#95;engine](/operations/settings/settings#default_table_engine) に設定されているエンジンの場合は `DEFAULT`、それ以外は `YES`。

## USER_PRIVILEGES {#user_privileges}

グローバル権限に関する情報を提供します。この情報は [system.grants](/ja/reference/system-tables/grants) システムテーブル(データベースが指定されていない行)から読み取られます。

`*_PRIVILEGES` ビューには、ワイルドカードを含まない通常の(取り消しではない)権限のみが表示されます。部分的な取り消し、ワイルドカードによる権限付与(例: `GRANT SELECT ON db_prefix*.*`)、およびパラメータ化された権限種別における特定の名前付きオブジェクトへの権限(例: `GRANT TABLE ENGINE ON TinyLog`)は、MySQL 互換のフォーマットでは表現できないため表示されません。そのため、部分的な取り消しによって制限されている被付与者であっても、制限のない権限が付与されているものとして表示されます。パラメータ化された種別の `ON *` 権限は、通常のグローバル権限として表示されます。正確な情報は `system.grants` を参照してください。MySQL とは異なり、これらのビューにはすべてのユーザーとロールの権限が表示され、参照するには `system.grants` へのアクセス権が必要です。アクセス権がない場合、クエリは `ACCESS_DENIED` 例外で失敗します。ClickHouse は権限を付与したユーザーを記録しないため、`GRANTOR` カラムは存在しません。

カラム:

* `grantee` ([String](/ja/reference/data-types/string)) — 権限が付与されたユーザーまたはロール。MySQL フォーマット `'name'@'%'` で表されます。MySQL にはロールに相当するものがないため、ロールもユーザーと同じ形式で表示されます。
* `table_catalog` ([String](/ja/reference/data-types/string)) — 常に `def`。
* `privilege_type` ([String](/ja/reference/data-types/string)) — 権限の名前(例: `SELECT`、`ALTER UPDATE`)。完全な一覧は [system.privileges](/ja/reference/system-tables/privileges) を参照してください。
* `is_grantable` ([String](/ja/reference/data-types/string)) — 権限が `WITH GRANT OPTION` 付きで付与されている場合は `YES`、それ以外の場合は `NO`。
* `grantee_type` ([String](/ja/reference/data-types/string)) — `USER` または `ROLE`。非標準のカラムです。ClickHouse ではユーザーとロールに同じ名前を付けられるため、このカラムでそうした被付与者を区別します。
