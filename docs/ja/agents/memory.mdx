## メモリの仕組み {#how-it-works}

メインの会話と並行して、小規模なメモリエージェントが動作します。このエージェントは最近のメッセージを読み取って記憶すべき内容を判断し、ユーザーごとのストアにエントリを書き込みます。
次の会話では、これらのエントリがコンテキストとして利用可能になるため、同じことを繰り返し伝えなくても、メインのエージェントがそれを参照できます。

ユーザーにとっては、これが会話の継続性として現れます。たとえば、SQL の出力は小文字が好みであることや、会計年度が 3 月に終わることを一度エージェントに伝えておけば、以降の会話ではそれに沿った応答が返されます。

## メモリエントリの管理 {#manage-your-memories}

左側のナビゲーションにある **メモリエントリ** (脳) アイコンからメモリパネルを開きます。パネルには保存済みのメモリエントリが一覧表示され、エントリの作成、編集、削除、フィルタを行うためのコントロールが用意されています。

メモリはユーザーごとに非公開です。他のユーザーのエージェントがあなたのエントリを参照することはなく、あなたのエージェントが他のユーザーのエントリを参照することもありません。

### メモリを作成する {#create-memory}

パネル上部の **+** ボタンをクリックして **Create Memory** ダイアログを開きます。**キー** (英小文字とアンダースコアのみ使用可) と**値**を入力し、**Create** をクリックします。

## メモリの切り替え {#toggle-memory}

メモリパネル上部の **メモリを使用** チェックボックスで、メモリのオン/オフを切り替えます。保存されたくない機密性の高い話題を扱う場合や、パーソナライズが不要な単発の会話では、メモリを無効化してください。

メモリがオフの間、エージェントはメモリストアの読み取りも書き込みも行いません。

## メモリのベストプラクティス {#memory-best-practices}

メモリは次のような情報に役立ちます。

* 繰り返し使われる慣例: 好みの日付形式、ビジネス上の定義、命名パターンなど。
* プロジェクトのコンテキスト: 普段クエリを実行するサービスやデータベース、注目しているダッシュボードなど。
* コミュニケーションスタイル: 簡潔な応答か饒舌な応答か、コード中心の応答か文章中心の応答か。

メモリはデータベースとしての利用を想定していません。たとえば、大量のリファレンス資料をまとめて保存する場所ではありません。
そのような用途には、[スキル](/ja/agents/builder/skills)を使用するか、資料をエージェントの指示に組み込んでください。
また、過去のチャットを検索するためのものでもありません。その役割は会話履歴そのものが担います。
