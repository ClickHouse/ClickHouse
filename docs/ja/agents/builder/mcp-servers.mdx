Model Context Protocol (MCP) は、ツールやデータソースを AI モデルに公開するためのオープン標準です。MCPサーバーを ClickHouse Agent に接続すると、エージェントはそのサーバーが公開するあらゆる機能にアクセスできるようになります。イシュートラッカー、オブザーバビリティバックエンド、社内 API、third-party の SaaS など、MCP エンドポイントを備えたものであれば何でも利用できます。

## MCPサーバーをアタッチする {#attach-an-mcp-server}

エージェントビルダーで **MCPサーバー** セクションを開き、**サーバーを追加** をクリックします。サーバーのURLと認証設定を入力し、サーバーが提供するツールのうち、このエージェントに使用させるものを選択します。最後にエージェントを保存します。

1つのエージェントに複数のサーバーをアタッチできます。エージェントが呼び出したツールはすべて会話内にログとして記録されるため、ユーザーはエージェントが実行した内容を確認できます。

## トランスポート {#transport}

ClickHouse Agents は、本番環境での使用に適した MCP トランスポートである Streamable HTTP で通信します。アタッチするサーバーは、ClickHouse Cloud から HTTP(S) 経由で接続可能である必要があります。

## 認証 {#authentication}

MCPサーバーでは認証情報が必要になる場合があります。Agents は次の方式をサポートしています。

* **Bearerトークン** およびその他の静的ヘッダー - サーバーの設定時に指定する固定値です。
* **OAuth 2.0** - 対話型のフローです。ユーザー本人 (またはアクセス権を持つ任意のユーザー) がサーバー上のツールを初めて呼び出すと、ブラウザーでサインインウィンドウが開きます。トークンは自動的に管理およびリフレッシュされます。
* **ユーザーごとの認証情報** - サーバー設定内の変数を、呼び出し元ユーザーのプロファイルの値で置き換えます。これにより、各ユーザーは共有の service account ではなく、それぞれ自身のアイデンティティで認証されます。

ユーザーが入力した認証情報は暗号化して保存され、そのユーザーのスコープに限定されます。あるユーザーの認証情報が、別のユーザーのエージェント実行から参照されることはありません。

## 制限 {#limits}

1 回のエージェント実行で参照できるのは、リクエストあたり最大 50 個の異なる MCPサーバーのターゲットと、最大 100 個の展開後のツール設定です。これを超える数が必要なエージェントは、[サブエージェント](/ja/agents/builder/subagents)を使って分割してください。
