コードインタープリターを使用すると、エージェントはマネージドなサンドボックス内でコードを実行できます。計算、データ変換、フォーマット変換、グラフ描画など、自然言語よりもコードで処理するほうが適したタスク全般に活用できます。

## コードインタープリターを有効化する {#enable-it}

エージェントビルダーで **Capabilities** セクションの **Run Code** を有効にし、保存します。エージェントは、ユーザーのリクエストとエージェントの指示に基づいて、コードを実行するタイミングを判断します。

## サポートされている言語 {#supported-languages}

サンドボックスは Unix 環境で、2 つの汎用ランタイムといくつかのシェルユーティリティが用意されています。

* **Python 3** - データ処理タスクのデフォルトです。
* **Node.js (JavaScript)** - エージェントが JS での処理を選ぶ場合に使用します。
* **Bash** と **sh** - コマンドの連結や簡単な I/O に使うシェルスクリプト。
* **AWK** と **sed** - 行単位のテキスト処理。
* **bc** - 任意精度の数値計算。

データのパース、変換、計算を伴う処理では、エージェントはまず Python を使用します。

<Tip>
  シェルツールは、ワンライナーで済ませることに明確なメリットがあるタスクに限って使用してください。
</Tip>

## ファイル {#files}

ユーザーは会話にファイルをアップロードでき、アップロードしたファイルにはコードインタープリターがサンドボックスの作業ディレクトリ内からアクセスできます。また、コードから出力ファイル (CSV、グラフ、アーカイブなど) を書き込むこともでき、書き込まれたファイルはダウンロード可能な添付ファイルとして会話内に表示されます。

## サンドボックスの分離 {#sandbox-isolation}

各実行は、ネットワークアクセスも永続ストレージもない一時的なサンドボックス内で行われます。セッション間で状態は共有されません。エージェントが明示的に再読み込みしない限り、ある実行で作成された変数やファイルが次の実行に引き継がれることはありません。

プランに応じたリソース制限 (メモリ、1 回の実行あたりのファイル数、月間リクエストクォータ) が適用されます。エラーと stderr は、stdout とあわせて会話内に表示されます。

## 使用するタイミング {#when-to-use-it}

言語モデルが推論だけでは確実に導き出せない決定論的な計算が必要な場合は、コードインタープリターを活用してください。
代表的なケースは次のとおりです。

* ユーザーがアップロードした CSV ファイルや JSONファイルのパース
* 要約統計量の算出や簡単なシミュレーションの実行
* フォーマット間の変換 (Parquet、JSON、CSV)
* クエリ結果からのグラフの生成

<Tip>
  モデルがコンテキストからすでに回答できるタスクには使用しないでください。
  コードを実行するとレイテンシーが増加し、クォータも消費されます。
</Tip>
