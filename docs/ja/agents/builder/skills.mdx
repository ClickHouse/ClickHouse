スキルとは、エージェントが必要に応じて適用できる、再利用可能な指示のパッケージです。ブランドスタイルガイド、コードレビューのチェックリスト、特定のワークフロー向けのランブックなど、複数のエージェントで繰り返し使う手順はスキルにまとめましょう。各エージェントのシステムプロンプトに同じ指示を重複して記述する必要がなくなります。

## スキルの構成 {#anatomy-of-a-skill}

スキルは、冒頭に短いフロントマターのヘッダーを持つ Markdown ファイルです。

```markdown
---
name: revenue-report
description: Generates the weekly revenue report using our standard segments
always-apply: false
user-invocable: true
---

When asked to generate a revenue report:
1. Filter to the requested period.
2. Apply the standard MRR formula:
     SUM(CASE
       WHEN billing_cycle = 'monthly' THEN amount
       WHEN billing_cycle = 'yearly'  THEN amount / 12
       ELSE 0
     END)
3. Break down by segment: Enterprise, Mid-Market, SMB.
4. Render the result as a Markdown table.
```

フロントマターの設定項目のうち、特に重要なものは次のとおりです。

* **`name`** - kebab-case 形式の識別子です。
* **`description`** - モデルがこのスキルを使うべき場面を判断するための短い概要です。最も重要なフィールドとして扱い、具体的に記述してください。説明が曖昧だと、誤ったスキルが呼び出される原因になります。
* **`always-apply`** - `true` の場合、スキルは都度選択されるのではなく、すべてのターンにあらかじめ組み込まれます。always-apply スキルはメッセージごとにコンテキストを消費するため、使用は必要最小限にとどめてください。
* **`user-invocable`** - `true` (デフォルト) の場合、スキルは `$` ポップオーバーに表示され、手動で選択できます。

`SKILL.md` とそのアセットを含む `.zip` をアップロードすれば、リファレンスドキュメント、サンプルクエリ、小規模なスクリプトなどの補助ファイルをスキルと一緒にバンドルできます。

## スキルを使用する {#use-a-skill}

会話の中でエージェントがスキルを利用する方法は 3 つあります。

* **ユーザーによる呼び出し** - コンポーザーで `$` を押し、ポップオーバーからスキルを選択します。スキルの内容は次のターンに向けてあらかじめ読み込まれます。
* **モデルによる自動選択** - スキルの `description` をもとに、エージェントが適用するタイミングを自ら判断します。
* **always-apply** - このモードに設定されたスキルは、毎ターン自動的に読み込まれます。

## スキルの管理 {#manage-skills}

クラウドコンソールの［スキル］パネルでは、スキルのインライン作成、`.md` ファイルや `.zip` ファイルのアップロード、自分のユーザーで有効にするスキルの管理を行えます。自分が所有するスキルはデフォルトで有効になっています。スキルを無効化すると、スキル自体は削除されずに、ポップオーバーとモデルのカタログから除外されます。

スキルは他のユーザーと共有できます ([共有とアクセス](/ja/agents/sharing-and-access)を参照) 。

## スキルと指示の違い {#skills-vs-instructions}

* **エージェントへの指示**は、そのエージェントが何者で、全体としてどのように振る舞うかを定義します。そのエージェントには常に適用されます。
* **スキル**は状況に応じて使われるもので、必要な場面でのみ適用され、対象は特定のワークフローに限定されます。

同じ段階的な指示が複数のエージェントで何度も繰り返される場合や、毎ターンではなく特定のユーザーリクエストに対してのみトリガーしたい場合は、スキルを使用してください。
