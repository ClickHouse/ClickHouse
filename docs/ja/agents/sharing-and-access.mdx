Agents は階層型のアクセス許可モデルを採用しています。ロールはユーザーが利用できる機能そのものを制御し、リソースレベルのアクセスリストは特定のエージェントやその他のリソースを使用できるユーザーを制御します。また、管理者権限は全体の管理を担うユーザーを制御します。

## ロール {#roles}

ロールとは、1 人以上のユーザーに割り当てられる機能アクセス許可のまとまりです。デフォルトのロールは次のとおりです。

* **ユーザー** - エージェントの実行とチャットを利用できます。エージェントの構築、スキルの作成、リソースの共有などを行えるかどうかは、割り当てられたロールの機能ごとのトグルによって決まります。
* **管理者** - ユーザーロールのすべての権限に加えて、組織レベルの管理機能 (ユーザーの管理、マーケットプレイスの設定、アクセス許可の付与) を利用できます。

管理者は、独自のトグルを設定したカスタムロールを作成し、より細かくアクセスを制御できます。

## リソースの共有 {#resource-sharing}

エージェント、プロンプト、スキルにはそれぞれアクセスリストがあります。アクセスレベルはプリンシパルごとに次の 3 つです。

* **閲覧者** - リソースを使用できますが、変更はできません。
* **編集者** - リソースの設定 (指示、アタッチ済みのツール、モデルなど) を変更できます。
* **所有者** - 編集者の権限に加えて、リソースの削除や共有設定の変更が可能です。

リソースを作成すると、デフォルトで作成者が所有者になります。明示的に共有していないリソースはすべてプライベートとなり、作成者本人のみがアクセスできます。

## プリンシパル {#principals}

アクセス権は次の対象に付与できます。

* **個々のユーザー** - ユーザー単位で 1 人ずつ付与します。
* **グループ** - チームや組織単位です。後からユーザーがグループに参加または脱退すると、そのユーザーのアクセス権は自動的に更新されます。
* **組織全体** - 組織内の全員がそのリソースを閲覧できます。ただし、これを許可するロールレベルのトグルが有効になっている必要があります。

組織全体に公開されたリソースは、[マーケットプレイス](/ja/agents/marketplace)で検索・発見できるようになります。

## エージェントを共有する {#share-an-agent}

エージェントビルダーの下部にある **共有** アイコンをクリックします。アイコン上のバッジには、現在アクセス権を持つユーザーまたはグループの数が表示されます。

共有先のユーザーが次にページを再読み込みすると、利用可能なエージェントの一覧にそのエージェントが表示されます。アクセス権を取り消すには、同じモーダルで該当する行を削除します。共有先のユーザーは直ちにアクセス権を失います。進行中の会話は最後まで続行されますが、新しい会話は開始できなくなります。

## デフォルトのエージェント {#default-agent}

任意のエージェントを 1 つ、デフォルトとして指定できます。新しい会話は、別のエージェントを選択しない限り、そのエージェントで開始されます。また、管理者は、デフォルトを自分で選択していないユーザー向けに、組織全体のデフォルトを設定することもできます。

## 管理者操作 {#admin-operations}

管理者のみが実行できる操作は次のとおりです。

* ロールの作成と編集
* マーケットプレイスのカテゴリの設定と、おすすめエージェントの選定
* 組織レベルでの機能の有効化・無効化 (メモリ、ウェブ検索、コードインタープリター、マーケットプレイスなど)
* 他のユーザーへの管理者権限の付与

ClickHouse Cloud では、組織の管理者が管理パネルを利用できます。管理パネルが表示されない場合は、組織の管理者または ClickHouse Cloud Support に連絡してアクセスをリクエストしてください。

## 注意点 {#gotchas}

* **エージェントを削除すると、すべての共有が解除されます。** 共有先のユーザーはアクセスできなくなります。そのエージェントとの保存済みの会話は引き続き閲覧できますが、会話を続けることはできません。
* **共有エージェントを編集すると、そのエージェントを使用しているすべてのユーザーに影響します。** 他のユーザーに影響を与えずに試行錯誤したい場合は、コピーを作成して使用してください。
* **ユーザーのロールを取り消しても、そのユーザーが作成したリソースは削除されません。** そのユーザーのエージェント、プロンプト、スキルは引き続きアクセスリストに残ります。ユーザーを完全にオフボーディングする前に、所有権を移管してください。
