### ClickPipes {#clickpipes}

        [ClickPipes](/ja/integrations/clickpipes/home) は、多様なソースからのデータの取り込みを数回のクリックで簡単に行えるマネージドインテグレーションプラットフォームです。ClickPipes は、極めて負荷の高いワークロードにも対応できるよう設計された堅牢でスケーラブルなアーキテクチャにより、安定したパフォーマンスと信頼性を実現します。長期的なストリーミング用途にも、一回限りのデータ読み込みジョブにも利用できます。

### SQL コンソールでデータを追加する {#add-data-using-the-sql-console}

        多くのデータベース管理システムと同様に、ClickHouse はテーブルを論理的に**データベース**へまとめて管理します。ClickHouse で新しいデータベースを作成するには、[`CREATE DATABASE`](/ja/reference/statements/create/database) コマンドを使用します。

        ```sql
        CREATE DATABASE IF NOT EXISTS helloworld
        ```

        次のコマンドを実行して、`helloworld` データベースに `my_first_table` という名前のテーブルを作成します。

        ```sql
        CREATE TABLE helloworld.my_first_table
        (
            user_id UInt32,
            message String,
            timestamp DateTime,
            metric Float32
        )
        ENGINE = MergeTree()
        PRIMARY KEY (user_id, timestamp)
        ```

        上記の例では、`my_first_table` は次の 4 つのカラムを持つ [`MergeTree`](/ja/reference/engines/table-engines/mergetree-family/mergetree) テーブルです。

        * `user_id`:  32 ビットの符号なし整数 ([UInt32](/ja/reference/data-types/int-uint))
        * `message`: [String](/ja/reference/data-types/string) データ型。他のデータベースシステムにおける `VARCHAR`、`BLOB`、`CLOB` などの型に相当します
        * `timestamp`: 特定の時点を表す [DateTime](/ja/reference/data-types/datetime) 値
        * `metric`: 32 ビットの浮動小数点数 ([Float32](/ja/reference/data-types/float))

        <Info>
          **テーブルエンジン**

          テーブルエンジンによって、次の点が決まります。

          * データをどのように、どこに保存するか
          * どのクエリをサポートするか
          * データをレプリケーションするかどうか

          <br />

          テーブルエンジンには多くの選択肢がありますが、単一ノードのClickHouseサーバー上でシンプルなテーブルを作成する場合は、通常 [`MergeTree`](/ja/reference/engines/table-engines/mergetree-family/mergetree) を選択することになるでしょう。
        </Info>

#### 主キーの簡単な紹介 {#a-brief-intro-to-primary-keys}

        先に進む前に、ClickHouse における主キーの仕組みを理解しておくことが重要です (主キーの実装は
        意外に感じられるかもしれません！) 。

        * ClickHouse の主キーは、テーブル内の行ごと&#x306B;***一意ではありません***

        ClickHouse テーブルの主キーは、データがディスクに書き込まれる際のソート順を決定します。8,192 行または 10MB の
        データ (**インデックス粒度**と呼ばれます) ごとに、主キーのインデックスファイルにエントリが 1 つ作成されます。この粒度の概念により、
        メモリに容易に収まる**スパースインデックス**が構成され、各グラニュールは `SELECT` クエリの実行中に処理される
        最小単位のカラムデータのストライプを表します。

        主キーは `PRIMARY KEY` パラメータを使用して定義できます。`PRIMARY KEY` を指定せずにテーブルを定義した場合、
        `ORDER BY` 句で指定したタプルが主キーになります。`PRIMARY KEY` と `ORDER BY` の両方を指定する場合、主キーはソート順の部分集合でなければなりません。

        主キーは sorting key でもあり、`(user_id, timestamp)` のタプルです。したがって、各
        カラムファイルに保存されるデータは、まず `user_id`、次に `timestamp` の順でソートされます。

        ClickHouse の中核となる概念の詳細解説については、[「コアコンセプト」](/ja/concepts/core-concepts/index) を参照してください。

#### テーブルにデータを挿入する {#insert-data-into-your-table}

        ClickHouse でも、おなじみの [`INSERT INTO TABLE`](/ja/reference/statements/insert-into) コマンドを使用できます。ただし、[`MergeTree`](/ja/reference/engines/table-engines/mergetree-family/mergetree) テーブルへの挿入のたびに、ストレージ内に **パーツ** が 1 つ作成される点を理解しておくことが重要です。

        <Tip>
          **ClickHouse のベストプラクティス**

          1 回のバッチでは大量の行を挿入してください。一度に数万行、場合によっては数百万
          行を挿入しても問題ありません。ClickHouse はその程度のデータ量を容易に処理できます。さらに、サービスへの書き込みリクエスト数が減るため、[コストの削減にもつながります](/ja/concepts/best-practices/selecting-an-insert-strategy#batch-inserts-if-synchronous)。
        </Tip>

        <br />

        簡単な例ではありますが、一度に複数の行を挿入してみましょう。

        ```sql
        INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
            (101, 'Hello, ClickHouse!',                                 now(),       -1.0    ),
            (102, 'Insert a lot of rows per batch',                     yesterday(), 1.41421 ),
            (102, 'Sort your data based on your commonly-used queries', today(),     2.718   ),
            (101, 'Granules are the smallest chunks of data read',      now() + 5,   3.14159 )
        ```

        <Note>
          `timestamp` カラムには、さまざまな [**Date**](/ja/reference/data-types/date) 関数および [**DateTime**](/ja/reference/data-types/datetime) 関数を使ってデータが投入されている点に注目してください。ClickHouse には便利な関数が数百種類用意されており、[**関数**セクションで確認できます](/ja/reference/functions/index)。
        </Note>

        正しく動作したことを確認しましょう。

        ```sql
        SELECT * FROM helloworld.my_first_table
        ```

### ClickHouse クライアントでデータを追加する {#add-data-using-the-clickhouse-client}

        [**clickhouse クライアント**](/ja/concepts/features/interfaces/client) というコマンドラインツールを使用して、ClickHouse Cloud サービスに接続することもできます。接続情報を確認するには、左側のメニューで `Connect` をクリックします。表示されたダイアログのドロップダウンから `Native` を選択します。

        <div className="ch-image-lg">
          <Frame>
            ![clickhouse クライアントの接続情報](/images/_snippets/client_details.webp)
          </Frame>
        </div>

        <br />

        1. [ClickHouse](/ja/get-started/setup/self-managed/quick-install) をインストールします。

        2. ホスト名、ユーザー名、パスワードをご自身の値に置き換えて、次のコマンドを実行します。

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password>
        ```

        スマイルマークのプロンプトが表示されれば、クエリを実行する準備は完了です！

        ```response
        :)
        ```

        3. 次のクエリを実行して試してみましょう：

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        ```

        レスポンスが見やすいテーブルフォーマットで返されることを確認してください：

        ```response
        ┌─user_id─┬─message────────────────────────────────────────────┬───────────timestamp─┬──metric─┐
        │     102 │ Insert a lot of rows per batch                     │ 2022-03-21 00:00:00 │ 1.41421 │
        │     102 │ Sort your data based on your commonly-used queries │ 2022-03-22 00:00:00 │   2.718 │
        │     101 │ Hello, ClickHouse!                                 │ 2022-03-22 14:04:09 │      -1 │
        │     101 │ Granules are the smallest chunks of data read      │ 2022-03-22 14:04:14 │ 3.14159 │
        └─────────┴────────────────────────────────────────────────────┴─────────────────────┴─────────┘

        4 rows in set. Elapsed: 0.008 sec.
        ```

        4. [`FORMAT`](/ja/reference/statements/select/format) 句を追加して、[ClickHouse がサポートする多数の出力形式](/ja/reference/formats/index)のいずれかを指定します。

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        FORMAT TabSeparated
        ```

        上記のクエリでは、結果が tab-separated 形式で出力されます：

        ```response
        Query id: 3604df1c-acfd-4117-9c56-f86c69721121

        102 Insert a lot of rows per batch      2022-03-21 00:00:00     1.41421
        102 Sort your data based on your commonly-used queries  2022-03-22 00:00:00     2.718
        101 Hello, ClickHouse!  2022-03-22 14:04:09     -1
        101 Granules are the smallest chunks of data read       2022-03-22 14:04:14     3.14159

        4 rows in set. Elapsed: 0.005 sec.
        ```

        5. `clickhouse client` を終了するには、**exit** コマンドを入力します。

        <br />

        ```bash
        exit
        ```

### ファイルをアップロード {#upload-a-file}

        データベースを使い始める際によくある作業の 1 つが、手元のファイルにあるデータを挿入することです。挿入用に、
        クリックストリームデータを表すサンプルデータをオンラインで公開しています。このデータには、ユーザー ID、アクセスされた URL、
        イベントのタイムスタンプが含まれています。

        `data.csv` という名前の CSV ファイルに、次のテキストが含まれているとします:

        ```bash title="data.csv"
        102,This is data in a file,2022-02-22 10:43:28,123.45
        101,It is comma-separated,2022-02-23 00:00:00,456.78
        103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
        ```

        1. 次のコマンドで、データを `my_first_table` に挿入します。

        <br />

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password> \
        --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
        ```

        2. SQL コンソールからクエリを実行すると、新しい行がテーブルに追加されていることを確認できます。

        <br />

          </Frame>
        </div>
