Choose the server-side instrumentation for your Next.js deployment:

- **Self-hosted, Node.js runtime:** use the ClickStack Node.js SDK.
- **Vercel or the Edge runtime:** use `@vercel/otel`.

For browser telemetry and session replay, use the [Browser SDK guide](/clickstack/ingesting-data/sdks/browser).

## Self-hosted Next.js {#self-hosted-nextjs}

Use Node.js 22.15 or later and install the SDK:

```shell
npm install @clickhouse/clickstack-node
```

Create `instrumentation.ts` in your project root, or in `src` if your application uses that directory. Initialize the SDK only in the Node.js runtime:

```typescript
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { init } = await import('@clickhouse/clickstack-node');
    init();
  }
}
```

Add the SDK to `serverExternalPackages` in your existing Next.js configuration so it is loaded outside the server bundle:

```javascript
// next.config.mjs
export default {
  serverExternalPackages: ['@clickhouse/clickstack-node'],
};
```

Configure the destination below and set `OTEL_SERVICE_NAME` to identify your application. Do not also preload the SDK or initialize another OpenTelemetry SDK. For additional options, see the [Node.js guide](/clickstack/ingesting-data/sdks/nodejs).

For termination and deployment considerations, see the [SDK's Next.js guidance](https://github.com/ClickHouse/clickstack-node#nextjs).

## Vercel and Edge runtime {#vercel-or-edge}

Use `@vercel/otel` following the [Next.js OpenTelemetry setup instructions](https://nextjs.org/docs/app/guides/open-telemetry). Use this setup instead of the ClickStack Node.js SDK initialization above.

Configure [OTLP export](https://github.com/vercel/otel/tree/main/packages/otel#registerotelconfig-configuration) using the connection settings below. Replace any example destinations and signal-specific endpoint overrides, and set the variables in your deployment configuration.

If your Vercel deployment already uses a tracing integration, configure a [custom exporter](https://nextjs.org/docs/app/guides/open-telemetry#custom-exporters) for this destination; endpoint environment variables alone do not override that integration.

## Configure your destination {#configure-destination}

Set a service name for either instrumentation option:

```shell
export OTEL_SERVICE_NAME='my-nextjs-app'
```

Set the OTLP HTTP endpoint and ingestion key for your ClickStack collector. Use `http://` if your collector does not have TLS configured. For collector setup, see [Ingesting with OpenTelemetry](/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## Verify ingestion {#verify-ingestion}

Start your application and make requests to a server-rendered page or API route. In ClickStack, select a recent time range and find your application's service name in Traces.
