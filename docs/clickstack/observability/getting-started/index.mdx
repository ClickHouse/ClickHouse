Get started with ClickHouse Observability, send a test event, and confirm that the event is available in the observability UI.

The service provides a managed telemetry endpoint. Send data from your applications, agents, or an existing OpenTelemetry Collector to this endpoint.

If you manage your own ingestion pipeline and schema, follow the [self-configured getting-started guide](/clickstack/self-configured/getting-started/managed).

## Before you begin {#before-you-begin}

You need a fully managed ClickHouse Observability service and access to its telemetry endpoint and API key.

### Create a service {#create-a-service}

If you don't have a service yet, start with [Create a ClickHouse service](/get-started/setup/cloud#1-create-a-clickhouse-service) in the ClickHouse Cloud quickstart. Once your service is running, open ClickHouse Observability. If the service has no data yet, the **Getting Started** page opens automatically. Choose one of the three paths below to send telemetry.

## Set up ClickHouse Observability {#set-up-clickhouse-observability}

Choose the path that matches your environment.

<Tabs>
<Tab title="Use an existing OpenTelemetry setup">

<Image img="/images/clickstack/getting-started/observability-connection-details.png" alt="Set up OpenTelemetry dialog with URL, Collector config, and Env vars options and masked connection details" size="md" />

Use this path if your application, agent, or collector already produces OpenTelemetry data.

1. Select **View connection details** on the getting started page.
2. Copy the configuration for your telemetry sender. The connection details provide **URL**, **Collector config**, and **Env vars** options.

3. Configure your sender to export telemetry to the managed endpoint using the provided authentication details.
4. Generate normal activity in your application, then confirm that the resulting data appears in [Search](/clickstack/observability/features/search).

You can also find these connection details under **Team Settings → Data → Managed Telemetry**.

<Tip>
For an optional quick check, select **send a test log** on the getting started page. The button immediately sends a test log from the UI; it does not verify your application's or collector's configuration.
</Tip>

</Tab>
<Tab title="Instrument with AI">

<Image img="/images/clickstack/getting-started/observability-ai-instrumentation.png" alt="Set it up with an AI agent dialog showing the instrumentation prompt and masked endpoint and API key environment variables" size="md" />

Use this path if you have application code and want your coding assistant to help add OpenTelemetry instrumentation.

1. Under **Instrument with AI**, select **Copy prompt** to open the **Set it up with an AI agent** dialog.
2. Copy the prompt from the dialog and paste it into your coding assistant with access to your application code, such as Cursor, Copilot, or Claude Code.
3. Set `CLICKSTACK_OTLP_ENDPOINT` and `CLICKSTACK_API_KEY` using the values provided in the dialog. Store them in a `.env` file excluded from version control or in your secrets store.
4. Review and apply the suggested instrumentation, then run your application and generate an event.

For a complete example with application code and an instrumentation prompt, follow the [HackerNews Analyzer demo](/clickstack/observability/example-datasets/instrument-application). It walks through sending application logs, traces, metrics, and browser session replay to your managed service.

</Tab>
<Tab title="Follow setup guides">

<Image img="/images/clickstack/getting-started/observability-setup-guides.png" alt="Send data dialog with searchable setup guides for languages, frameworks, infrastructure, and collectors" size="md" />

Use this path if you want instructions for a specific application or infrastructure source.

1. Select **Browse setup guides**.
2. Choose the guide for your language, framework, or infrastructure.
3. Follow its instrumentation and configuration steps, then generate telemetry from that source.

For managed configuration examples, start with [Kubernetes monitoring](/clickstack/observability/example-datasets/kubernetes), [local logs and metrics](/clickstack/observability/example-datasets/local-data), or the [HackerNews Analyzer application](/clickstack/observability/example-datasets/instrument-application). If you want to try ingestion without instrumenting an application, use [otelgen](/clickstack/observability/example-datasets/otelgen) or [telemetrygen](/clickstack/observability/example-datasets/telemetrygen).

</Tab>
</Tabs>

## Verify ingestion and start exploring {#verify-ingestion}

After completing your chosen path, select **Start exploring** to open [Search](/clickstack/observability/features/search). Look for an event you generated and confirm that it is present before continuing.

For logs, select the **Logs** source and a time range that includes when you sent the event. The example below shows a log sent using the UI's **send a test log** button, with `example-service` as its service name. Expand an event to inspect its attributes.

<Image img="/images/clickstack/getting-started/observability-verify-ingestion.png" alt="Search showing a UI test log for example-service with its event attributes expanded" size="lg" />
