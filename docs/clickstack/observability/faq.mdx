This page answers frequently asked questions about ClickHouse Observability capabilities, including data collection, alerting, dashboards and drill-downs, and metrics discovery.

## Data collection {#data-collection}

<Accordion title="Do I need to run an OpenTelemetry collector?">
ClickHouse Observability provides a managed OpenTelemetry ingestion collector. Applications and telemetry generators can send data directly to its endpoint.

You may still need a collector in your own environment to read log files or gather host and Kubernetes metrics, then forward that data to the managed collector. See [Local logs and metrics](/clickstack/observability/example-datasets/local-data) and [Monitoring Kubernetes](/clickstack/observability/example-datasets/kubernetes) for examples.
</Accordion>

<Accordion title="Where do I find my telemetry endpoint and API key?">
In your ClickHouse Observability service, open **Team Settings → Managed Telemetry** and copy the OTLP endpoint and API key. Use these connection details when configuring your SDK, collector, or telemetry generator.

Follow the endpoint format required by the tool you are using. The [sample data and demos](/clickstack/observability/example-datasets) include configuration examples for each tool.
</Accordion>

## Alerting {#alerting}

<Accordion title="What types of alerts does ClickHouse Observability support?">
ClickHouse Observability supports two types of alerts:

- [Search alerts](/clickstack/observability/features/alerts#search-alerts): trigger notifications when the count of matching log or trace results within a time window exceeds or falls below a threshold.
- [Dashboard chart alerts](/clickstack/observability/features/alerts#dashboard-alerts): trigger notifications when a metric plotted on a dashboard tile crosses a defined threshold.

Both alert types evaluate results against configured thresholds. For full details, see [Alerts](/clickstack/observability/features/alerts).
</Accordion>

<Accordion title="Can I alert on complex metric conditions such as ratios, p95/p99, or multi-metric formulas?">
Build the calculation as a dashboard chart, then attach a threshold alert to that chart. The [chart builder](/clickstack/observability/features/dashboards/overview#navigate-chart-explorer) supports calculations such as ratios and percentiles.

For calculations that require SQL, use a [SQL-based chart alert](/clickstack/observability/features/alerts#sql-based-alerts). SQL alerts support Line, Stacked Bar, and Number charts. Save the dashboard to activate the alert.
</Accordion>

## Dashboards and drill-downs {#dashboards-and-drill-downs}

<Accordion title="Are prebuilt dashboards included?">
Yes. Open **Dashboards** to find the **Services**, **Kubernetes**, and **LLM** preset dashboards. These dashboards display data when the relevant telemetry is being ingested and the selected time range includes that data.

You can also create custom dashboards using your ingested logs, traces, and metrics. See [Dashboards](/clickstack/observability/features/dashboards/overview) for how to build charts and organize them into dashboards.
</Accordion>

<Accordion title="Does ClickHouse Observability support parameterized dashboards or dashboard variables?">
Yes, ClickHouse Observability supports dashboards parameterized by custom filters and variables, populated by data queried from ClickHouse. These filters allow you to dynamically scope some or all of the tiles on a dashboard to a specific value (e.g., a service name, environment, or host).

For details on creating dashboards and applying filters, see [Dashboards](/clickstack/observability/features/dashboards/overview).
</Accordion>

<Accordion title="What drill-down capabilities are available?">
ClickHouse Observability supports the following drill-down workflows:

- [Dashboard-level filtering](/clickstack/observability/features/dashboards/overview#filter-dashboards): Dashboard-level Lucene or SQL filters apply to tiles with **Apply filters** enabled. You can also adjust the dashboard time range.
- Custom dashboard filters: custom dashboards support explicit filter controls that are populated with values from your data, allowing users to scope participating tiles without writing queries manually.
- Click-to-view events: clicking on data in a dashboard tile and selecting **View Events** navigates to the [Search](/clickstack/observability/features/search) page with relevant filters for log and trace data.
- [Table row-click drilldowns](/clickstack/observability/features/dashboards/row-click-drilldowns): a table tile can be configured so that clicking a row opens the Search page or another dashboard, carrying the row's values through as filters. This supports multi-level workflows, such as a service inventory that drills into a per-service detail dashboard.

<Note>
Use [Search](/clickstack/observability/features/search) to inspect individual logs and traces. Use Chart Explorer to explore metrics.
</Note>
</Accordion>

## Metrics discovery {#metrics-discovery}

<Accordion title="Is there a UI for browsing and searching metrics?">
![Metric Attribute Explorer](/images/clickstack/faq/metrics-explorer-fully-managed.png)

Metric names are discoverable via the metric name dropdown in the [chart builder](/clickstack/observability/features/dashboards/overview#navigate-chart-explorer). When a metric is selected, the Metric Attribute Explorer panel displays the metric's description, units, and available attributes along with their values. This allows you to browse attributes and add them as filters or group-by fields directly from the panel.

There is not currently a dedicated metrics search page similar to the log search experience.
</Accordion>
