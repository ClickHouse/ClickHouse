<Tab title="ClickHouse Observability">

[`otelgen`](https://github.com/krzko/otelgen) is a small Go CLI that generates synthetic OTLP logs, traces and metrics. Use it to send test data to fully managed ClickHouse Observability and explore the results in Search and Chart Explorer.

<Steps>
<Step title="Prerequisites" id="prerequisites-managed">

You need an existing fully managed ClickHouse Observability service and network access to its managed telemetry endpoint. See the [fully managed Getting Started guide](/clickstack/observability/getting-started).
</Step>
<Step title="Install otelgen" id="install-otelgen-managed">

Install with Homebrew:

```shell
brew install krzko/tap/otelgen
```

Or install with Go:

```shell
go install github.com/krzko/otelgen@latest
```
</Step>
<Step title="Set environment variables" id="set-env-vars-managed">

Open your ClickHouse Observability service and go to **Team Settings → Managed Telemetry**. Copy the **OTLP HTTP endpoint** and **API key**.

<Image img="/images/clickstack/getting-started/observability-managed-telemetry.png" alt="Managed Telemetry in Team Settings showing the masked OTLP HTTP endpoint and API key" size="lg" />

Set the endpoint to its host and port, removing the `https://` prefix. For example, `https://YOUR_OTEL_ENDPOINT:4318` becomes `YOUR_OTEL_ENDPOINT:4318`. Do not append a signal path such as `/v1/logs`.

```shell
export OTEL_ENDPOINT='YOUR_OTEL_ENDPOINT:4318'
printf "API key: "
read -r -s OTEL_API_KEY
printf "\n"
export OTEL_API_KEY
```

The commands below use `--protocol http` without `--insecure`, so `otelgen` connects over HTTPS with certificate verification. Removing `https://` from the endpoint argument does not disable TLS. Your managed telemetry API key authenticates each request.
</Step>
<Step title="Generate traces" id="generate-traces-managed">

Send a short burst of multi-span traces:

```shell
otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
  --header "authorization=Bearer ${OTEL_API_KEY}" \
  --protocol http \
  --rate 2 --duration 10 \
  traces multi
```

`--rate` is traces per second and `--duration` is the run length in seconds. Omit `--insecure` so the connection uses HTTPS with certificate verification.
</Step>
<Step title="Generate logs" id="generate-logs-managed">

```shell
otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
  --header "authorization=Bearer ${OTEL_API_KEY}" \
  --protocol http \
  --rate 2 \
  logs multi --duration 10
```
</Step>
<Step title="Generate metrics" id="generate-metrics-managed">

Run the following command to generate metrics, then press `Ctrl+C` after a few seconds to stop it.

```shell
otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
  --header "authorization=Bearer ${OTEL_API_KEY}" \
  --protocol http \
  --rate 2 \
  metrics sum
```

`otelgen` also supports `gauge`, `histogram`, `up-down-counter` and `exponential-histogram` subcommands under `metrics`.
</Step>
<Step title="Verify in ClickHouse Observability" id="verify-managed">

In your ClickHouse Observability service, open **Search** and switch between the **Logs** and **Traces** sources to confirm new events. Set the time range to **Last 15 minutes** and look for the default service name `otelgen`.

Open **Chart Explorer**, select **Metrics**, and chart `otelgen.metrics.sum` to verify metrics ingestion.
</Step>
</Steps>

<Tab title="Self configured">

[`otelgen`](https://github.com/krzko/otelgen) is a small Go CLI that generates synthetic OTLP logs, traces and metrics. Use it to confirm that an existing ClickStack OpenTelemetry collector is accepting data and that events surface in the observability UI.

This guide assumes the collector is already running with OTLP endpoints on `4317` (gRPC) and `4318` (HTTP).

<Steps>
<Step title="Prerequisites" id="prerequisites-managed-self-configured">

This guide assumes you have completed the [Getting Started Guide for ClickHouse Observability — Self Configured](/clickstack/self-configured/getting-started/managed) and have an OpenTelemetry collector running with the OTLP gRPC (`4317`) and HTTP (`4318`) endpoints reachable from the machine you run `otelgen` on. If you [secured the collector](/clickstack/observability/ingesting-data/collector#securing-the-collector) with an `OTLP_AUTH_TOKEN`, keep that value handy.
</Step>
<Step title="Install otelgen" id="install-otelgen-managed-self-configured">

Install with Homebrew:

```shell
brew install krzko/tap/otelgen
```

Or install with Go:

```shell
go install github.com/krzko/otelgen@latest
```
</Step>
<Step title="Set environment variables" id="set-env-vars-managed-self-configured">

Export the collector endpoint and, if the collector is secured, the auth token:

```shell
export OTEL_ENDPOINT=<host>:4317
export OTLP_AUTH_TOKEN=<your_otlp_auth_token>
```

Use the host and port of your collector. For a collector running on the same machine, this is `localhost:4317`.

<Info>
**Unsecured collector**

The ClickStack OpenTelemetry collector is unauthenticated by default. If you haven't followed [Securing the collector](/clickstack/observability/ingesting-data/collector#securing-the-collector) to set an `OTLP_AUTH_TOKEN`, skip `OTLP_AUTH_TOKEN` here and drop the `--header` flag from the commands below.
</Info>
</Step>
<Step title="Generate traces" id="generate-traces-managed-self-configured">

Send a short burst of multi-span traces:

```shell
otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
  --header "authorization=${OTLP_AUTH_TOKEN}" \
  --protocol grpc --insecure \
  --rate 2 --duration 10 \
  traces multi
```

`--rate` is traces per second and `--duration` is the run length in seconds. `--insecure` disables TLS on the gRPC connection, which is needed when pointing `otelgen` at the collector's plaintext OTLP port.
</Step>
<Step title="Generate logs" id="generate-logs-managed-self-configured">

```shell
otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
  --header "authorization=${OTLP_AUTH_TOKEN}" \
  --protocol grpc --insecure \
  --rate 2 --duration 10 \
  logs multi
```
</Step>
<Step title="Generate metrics" id="generate-metrics-managed-self-configured">

The metrics subcommands don't honor `--duration`. Run the command and press `Ctrl+C` after a few seconds to stop it.

```shell
otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
  --header "authorization=${OTLP_AUTH_TOKEN}" \
  --protocol grpc --insecure \
  --rate 2 \
  metrics sum
```

`otelgen` also supports `gauge`, `histogram`, `up-down-counter` and `exponential-histogram` subcommands under `metrics`.
</Step>
<Step title="Verify in the observability UI" id="verify-managed-self-configured">

Open the observability UI from the ClickHouse Cloud console. In the `Search` view, switch the source between `Logs` and `Traces` to confirm new events. Set the time range to `Last 15 minutes`. Open the `Chart Explorer`, select `Metrics`, and chart one of the metric names produced by `otelgen` (for example `otelgen.metrics.sum`) to verify metrics ingestion.
</Step>
</Steps>
