Explore ClickHouse Observability using sample logs, sessions, traces, and metrics from an e-commerce store. Both deployment modes use the same dataset and investigation workflow.

Before you begin, complete the [fully managed getting started guide](/clickstack/observability/getting-started) or the [self-managed getting started guide](/clickstack/self-configured/getting-started/managed).

<Steps>
<Step title="Configure your connection" id="configure-your-connection">

Choose your deployment and set the following variables in the terminal where you will load the sample data.

<Tabs>
<Tab title="Fully managed">

<BetaBadge label="Beta offering" />

Open **Team Settings → Data** and find **Managed Telemetry**. Under **OpenTelemetry Collector**, use the **URL** option to copy the OTLP HTTP endpoint and API key. Select **Reveal key** to view the full values.

Set the base endpoint without a signal path such as `/v1/logs`. Include the `Bearer` prefix in the authorization value:

```shell
export CLICKSTACK_OTLP_ENDPOINT='<your-managed-otlp-http-endpoint>'
export CLICKSTACK_AUTHORIZATION='Bearer <your-api-key>'
```

You do not need to deploy a collector for this example.

</Tab>
<Tab title="Self-managed" id="self-managed">

You need a running ClickStack OpenTelemetry collector connected to your ClickHouse Cloud service. Follow the [Ingesting with OpenTelemetry guide](/clickstack/observability/ingesting-data/opentelemetry#self-managed) to configure the connection, or the [deployment guide](/clickstack/self-configured/deployment/managed) to start a collector.

Set the collector's OTLP HTTP endpoint, reachable from the machine running the upload command. Use the base URL without a signal path such as `/v1/logs`:

```shell
export CLICKSTACK_OTLP_ENDPOINT='http://<collector-host>:4318'
export CLICKSTACK_AUTHORIZATION=''
```

If the collector requires authentication, set `CLICKSTACK_AUTHORIZATION` to its receiver token. For a ClickStack collector secured with `OTLP_AUTH_TOKEN`, use that value without a `Bearer` prefix. Leave the value empty for a receiver that does not require authentication. Do not use your ClickHouse database password here.

</Tab>
</Tabs>
</Step>
<Step title="Download sample data" id="download-sample-data">

In order to populate the UI with sample data, download the following file:

[Sample data](https://storage.googleapis.com/hyperdx/sample.tar.gz)

```shell
# curl
curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
# or
# wget https://storage.googleapis.com/hyperdx/sample.tar.gz
```

This file contains example logs, metrics, and traces from our public [OpenTelemetry demo](https://github.com/ClickHouse/opentelemetry-demo) - a simple e-commerce store with microservices. Copy this file to a directory of your choosing.
</Step>
<Step title="Load sample data" id="load-sample-data">

Run the following commands in **Bash** from the directory containing `sample.tar.gz`. They send the sample data to the endpoint configured above, adding an authorization header only when one is required.

```bash
set -eo pipefail

auth_headers=()
if [ -n "${CLICKSTACK_AUTHORIZATION:-}" ]; then
  auth_headers=(-H "Authorization: ${CLICKSTACK_AUTHORIZATION}")
fi

for filename in $(tar -tf sample.tar.gz); do
  endpoint="${CLICKSTACK_OTLP_ENDPOINT%/}/v1/${filename%.json}"
  echo "loading ${filename%.json}"
  tar -xOf sample.tar.gz "$filename" | while read -r line; do
    printf '%s\n' "$line" | curl --fail-with-body -sS -X POST "$endpoint" \
      -H "Content-Type: application/json" \
      "${auth_headers[@]}" \
      --data-binary @-
  done
done
```

This simulates OTLP log, trace, and metric sources sending data. In production, these sources may be application SDKs, agents, or OpenTelemetry Collectors.

In the ClickHouse Cloud console, select your service and open ClickHouse Observability.

Return to [Search](/clickstack/observability/features/search) to view the loaded data. Select the **Logs** source and a time range that includes the sample events' timestamps. The screenshot below shows sample logs arriving in **Live Tail**:

<Step title="Explore logs" id="explore-logs">

To investigate other payment failures, return to [Search](/clickstack/observability/features/search).

Select **Logs** as the source and choose `payment` under the **ServiceName** filter. Use a time range that includes the session you investigated.

<Frame>

The results include the expired-card error from the session we investigated, as well as repeated `Visa cache full: cannot add new item.` errors. To see when errors occur across the payment service, chart these error logs over time.
</Step>
<Step title="Chart payment errors" id="chart-payment-errors">

Open **Chart Explorer**, select **Time Series**, and choose **Logs** as the data source. Select **Count of Events** as the aggregation.

In **Where**, select **Lucene** and enter the following filter:

```text
SeverityText:"error" ServiceName:"payment"
```

Set a time range covering the sample data and select **Run**.

<div className="ch-image-lg">

<Frame>

![Chart Explorer counting payment service error logs over time using a Lucene filter](/images/clickstack/getting-started/observability-sample-data-payment-errors-chart.png)

</Frame>

</div>

The chart shows the number of matching error logs in each time interval. It includes all errors from the `payment` service, including expired-card and cache-full errors. These are log-event counts, not a count of unique failed payments.
</Step>
