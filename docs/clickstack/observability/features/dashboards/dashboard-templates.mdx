ClickHouse Observability includes a library of pre-built dashboard templates that help you visualize common infrastructure and application telemetry. Charts display data once your ClickHouse service receives the telemetry required by the template.

## Browsing available templates {#browsing-templates}

To browse the built-in template library, navigate to **Dashboards** and click **Browse dashboard templates**.

<Image img="/images/clickstack/observability-browse-dashboard-templates.png" alt="Browse Dashboard Templates Button" size="lg"/>

This opens the template gallery, where templates are organized by category. Click **Import** on the template you want to use.

<Image img="/images/clickstack/observability-dashboard-template-gallery.png" alt="Dashboard Template Gallery" size="lg"/>

## Importing a template {#importing-a-template}

In **Step 2: Map Data**, review the **Dashboard Name** and **Tags**, then confirm the data source in the **To** column for each tile and filter. Sources may already be selected. In the example below, the Node.js Runtime Metrics template maps its charts and service filter to the **Metrics** source. Click **Finish Import** to create the dashboard.

<Image img="/images/clickstack/observability-import-dashboard-template.png" alt="Dashboard Template Import" size="lg"/>

## Pre-built templates {#pre-built-templates}

### Browser RUM {#browser-rum}

The **Browser RUM** (real user monitoring) template provides Core Web Vitals, page-load percentiles, traffic breakdowns, and error tracking. It uses browser sessions instrumented with the HyperDX Browser SDK or OpenTelemetry RUM instrumentation that emits `rum.sessionId`.

### OTel runtime metrics {#otel-runtime-metrics}

The built-in OTel Runtime Metrics templates are designed for applications instrumented with [OpenTelemetry runtime metrics](https://opentelemetry.io/docs/specs/semconv/runtime/).

| Template                | Description                                                                                              |
|-------------------------|----------------------------------------------------------------------------------------------------------|
| **.NET Runtime Metrics** | Garbage collection, heap fragmentation, exceptions, thread pool usage, and CPU metrics for .NET applications                 |
| **Go Runtime Metrics**   | Memory usage, allocations, GC targets, CPU utilization, and goroutine metrics for Go applications                     |
| **JVM Runtime Metrics**  | Heap memory, CPU utilization, threads, and GC metrics for JVM-based applications     |
| **Node.js Runtime Metrics** | Event loop delay, heap usage, CPU utilization, and V8 memory for Node.js applications               |
| **Python Runtime Metrics** | CPU utilization, memory usage, GC collections, and thread count for Python applications |

Notes:

- Each template is configured with a [custom filter](/clickstack/observability/features/dashboards/overview#custom-filters) for services whose [`telemetry.sdk.language`](https://opentelemetry.io/docs/specs/semconv/registry/attributes/telemetry/#telemetry-sdk-language) resource attribute matches the dashboard's runtime.
- Metric names can vary between OpenTelemetry SDK versions. If your SDK emits different metric names, [edit the visualizations](/clickstack/observability/features/dashboards/overview#dashboards-editing-visualizations) to match your data.

## Self-configured schemas {#self-configured-schemas}

For self-configured deployments with custom metric table schemas, adjust the template's service filter to query the appropriate service-name and resource-attribute columns. For high-volume workloads, consider [materializing frequently queried attributes](/clickstack/self-configured/managing/performance-tuning#materialize-frequently-queried-attributes), such as `ResourceAttributes['telemetry.sdk.language']`, to reduce filter load times.
