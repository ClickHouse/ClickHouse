Monitor Temporal Cloud metrics in ClickHouse Observability using the OTel Prometheus receiver. Includes a pre-built dashboard.
</Info>

## Prerequisites {#prerequisites}

- A ClickHouse Observability service
- Existing Temporal Cloud account
- Docker on a host with HTTPS access to Temporal Cloud and your OTLP endpoint

### Connection details {#connection-details}

For a managed service, open ClickHouse Observability and go to **Team Settings → Data → Managed Telemetry**. Copy your OTLP HTTP endpoint and API key. You can use **Copy connection details** to copy the configuration, or **Reveal key** to view the masked key.

<Image img="/images/clickstack/getting-started/observability-managed-telemetry.png" alt="Managed Telemetry connection details"/>

For the OTLP exporter examples below, set these variables in the terminal where you will run the collector:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
```

Replace the placeholders with the exact endpoint, including its port, and API key from your service. Use the base HTTP endpoint without a `/v1/metrics` suffix; the exporter appends the signal path.

For self-configured deployments, use your collector's reachable OTLP HTTP endpoint (for example, `http://YOUR_COLLECTOR_HOST:4318`) and authentication settings. If your collector does not require authentication, omit the exporter's `headers` block from the configurations below. See the [self-configured getting-started guide](/clickstack/self-configured/getting-started/managed) for setup guidance.

The endpoint must be reachable from the collector container. For a destination collector running on this computer, use `http://host.docker.internal:4318`. The Docker commands below include the host mapping.

## Integration with existing Temporal Cloud {#existing-temporal}

<Steps>
<Step title="Create Temporal Cloud key" id="create-temporal-cloud-key">

Create a Temporal Cloud service account with the **Metrics Read-Only** role and generate an API key, following the [Authentication guide](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication). An Account Owner or Global Admin must create the service account and key.

<Warning>
**Key file**

Store the Temporal API key in a file `temporal.key` in the same directory as the config file created below. Store only the key, without a `Bearer` prefix or surrounding spaces. This is separate from your ClickHouse Observability API key. Ensure the collector can read the mounted file.
</Warning>
</Step>
<Step title="Configure the OTel collector" id="custom-otel">

Run a standalone OpenTelemetry Collector with the Prometheus receiver to scrape Temporal Cloud and forward metrics to your service.

Create a file named `temporal-metrics.yaml` with the following configuration:
```yaml title="temporal-metrics.yaml"
receivers:
  prometheus/temporal:
    config:
      scrape_configs:
      - job_name: 'temporal-cloud'
        scrape_interval: 60s
        scrape_timeout: 30s
        honor_timestamps: true
        scheme: https
        authorization:
          type: Bearer
          credentials_file: /etc/otelcol-contrib/temporal.key
        static_configs:
          - targets: ['metrics.temporal.io']
        metrics_path: '/v1/metrics'

processors:
  memory_limiter:
    check_interval: 1s
    limit_mib: 400
    spike_limit_mib: 100
  batch:
    timeout: 5s
    send_batch_size: 500
    send_batch_max_size: 500
  resource:
    attributes:
      - key: service.name
        value: "temporal"
        action: upsert

exporters:
  otlp_http/observability:
    endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
    headers:
      authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

service:
  pipelines:
    metrics/temporal:
      receivers: [prometheus/temporal]
      processors:
        - memory_limiter
        - resource
        - batch
      exporters:
        - otlp_http/observability
```

This configuration:

- Connects to Temporal Cloud at `metrics.temporal.io`
- Collects metrics every 60 seconds
- Collects [key performance metrics](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)
- **Sets the required `service.name` resource attribute** per [OpenTelemetry semantic conventions](https://opentelemetry.io/docs/specs/semconv/resource/#service)
- Sends metrics to your OTLP endpoint via a dedicated pipeline

For multiple Temporal Cloud accounts, customize `service.name` to distinguish them (for example, `temporal-prod` and `temporal-dev`).
</Step>
<Step title="Run the collector" id="run-collector">

From the directory containing `temporal-metrics.yaml` and `temporal.key`, set the [connection variables](#connection-details) and run:

```bash
docker run --rm --name temporal-metrics-collector \
  --add-host=host.docker.internal:host-gateway \
  --memory=512m \
  -e OTEL_EXPORTER_OTLP_ENDPOINT \
  -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
  -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
  -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
  otel/opentelemetry-collector-contrib:0.161.0 \
  --config=/etc/otelcol-contrib/config.yaml
```

Leave the terminal open and check for scrape or export errors. Allow a few minutes for Temporal Cloud metrics to appear. Stop the collector with **Ctrl+C** when finished testing.

</Step>
<Step title="Verify metrics in ClickHouse Observability" id="verifying-metrics">

Once configured, log into ClickHouse Observability and verify metrics are flowing:

1. Open **Chart Explorer** and select your **Metrics** source
2. Filter for `ServiceName:temporal`, select **Last 15 minutes**, and search for metrics starting with `temporal` (e.g., `temporal_cloud_v1_workflow_success_count`, `temporal_cloud_v1_poll_timeout_count`)
3. You should see metric data points appearing at your configured collection interval

</Step>
</Steps>

## Troubleshooting {#troubleshooting}

### Collector fails to start {#collector-fails-to-start}

Check the terminal output for configuration errors. Confirm both mounted files exist and the collector can read `temporal.key`. Ensure the OTLP connection variables are set in the terminal where Docker runs.

### No metrics appearing {#no-metrics}

Check collector logs:

```bash
docker logs temporal-metrics-collector
```

Look for scrape, authentication, or export errors. Confirm the host can reach `https://metrics.temporal.io/v1/metrics` and your OTLP endpoint. In **Chart Explorer**, check the **Metrics** source, `ServiceName:temporal` filter, and time range. Temporal metrics can take a few minutes to become available and depend on activity in your account.

### Authentication errors {#auth-errors}

For Temporal scrape errors, confirm `temporal.key` contains a valid API key for a service account with the **Metrics Read-Only** role. For OTLP export errors, check your ClickHouse Observability endpoint and authorization value. These are separate credentials.
