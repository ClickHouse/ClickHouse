Use ClickStack to inspect request traces and metrics from [Loom](https://github.com/ClickHouse/loom), a memory and code search server for AI agents.

## Before you begin {#before-you-begin}

- A running Loom server.
- A [ClickStack Open Source deployment](/clickstack/deployment/oss) with an OTLP HTTP receiver reachable from the Loom server.

## How it works {#how-it-works}

Loom exports telemetry to the ClickStack OpenTelemetry Collector over OTLP HTTP. The collector writes the telemetry to ClickHouse, where it is available in ClickStack.

## Configure the Loom exporter {#configure-loom-exporter}

Find the ClickStack ingestion API key under **Team Settings → API Keys**. Configure these environment variables on the Loom server, replace the example URL and key, then restart Loom:

```bash
export LOOM_OTEL_EXPORTER=otlp
export LOOM_OTEL_EXPORTER_OTLP_ENDPOINT='http://clickstack-collector:4318'
export LOOM_OTEL_EXPORTER_OTLP_HEADERS='authorization=<YOUR_INGESTION_API_KEY>'
```

Use a collector base URL reachable from Loom. Loom appends `/v1/traces` and `/v1/metrics` to it. If Loom sends to an intermediary collector, use the headers that receiver expects as comma-separated `key=value` pairs. Omit the headers setting if the receiver requires none.

## Verify telemetry in ClickStack {#verify-telemetry}

Check Loom's resolved exporter settings. Replace the example Loom URL if the server is on a different host or port.

```bash
curl -sS 'http://localhost:7777/v1/health?include=otel'
```

Check that `otel.mode` is `otlp` and `otel.endpoint` is the configured collector URL.

Make a Loom request, such as a memory search, to generate a trace. In ClickStack, open **Search**, choose the **Traces** source, and filter for the service name `loom` (`service.name` in OpenTelemetry). If `LOOM_OTEL_SERVICE_NAME` is set, filter for that value.
