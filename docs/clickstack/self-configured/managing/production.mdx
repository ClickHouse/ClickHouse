When using Self Configured ClickHouse Observability in production, consider the following security, stability, and configuration practices.

[Self Configured ClickHouse Observability](/clickstack/self-configured/getting-started/managed) applies industry-standard [security practices](/products/cloud/features/security) by default - including enhanced encryption, authentication and connectivity, and managed access controls, as well as providing the following benefits:

- Automatic scaling of compute independent of storage
- Low-cost and effectively unlimited retention based on object storage
- The ability to [independently isolate read and write workloads](/clickstack/self-configured/managing/isolating-read-write) with Warehouses.
- Integrated authentication
- Automated [backups](/products/cloud/features/backups/overview)
- Seamless upgrades

**Follow these [best practices](/products/cloud/guides/production-readiness) for ClickHouse Cloud when using Self Configured ClickHouse Observability.**

## Secure ingestion {#secure-ingestion-managed}

By default, the ClickStack OpenTelemetry Collector isn't secured when deployed outside of the Open Source distributions and doesn't require authentication on its OTLP ports.

To secure ingestion, specify an authentication token when deploying the collector using the `OTLP_AUTH_TOKEN` environment variable. See ["Securing the collector"](/clickstack/self-configured/ingesting-data/collector#securing-the-collector) for further details.

### Create an ingestion user {#create-a-database-ingestion-user-managed}

It's recommended to create a dedicated user for the OTel collector for ingestion into ClickHouse Cloud and ensuring ingestion is sent to a specific database e.g. `otel`. See ["Creating an ingestion user"](/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user) for further details.

## Configure Time To Live (TTL) {#configure-ttl-managed}

Ensure the [Time To Live (TTL)](/clickstack/self-configured/managing/ttl) has been [appropriately configured](/clickstack/self-configured/managing/ttl#modifying-ttl) for your Self Configured ClickHouse Observability deployment. This controls how long data is retained for - the default of 3 days often needs to be modified.

### Isolating observability workloads {#isolating-workloads}

If you're adding Self Configured ClickHouse Observability to an **existing ClickHouse Cloud service** that already supports other workloads, such as real-time application analytics, isolating observability traffic is strongly recommended.

Use [**Managed Warehouses**](/products/cloud/features/infrastructure/warehouses) to create a **child service** dedicated to observability. This allows you to:

- Isolate ingest and query load from existing applications
- Scale observability workloads independently
- Prevent observability queries from impacting production analytics
- Share the same underlying datasets across services when needed

This approach ensures your existing workloads remain unaffected while allowing observability workloads to scale independently as observability data grows.

### Isolating read and write workloads {#isolating-read-write}

Warehouses also allow ingest and query workloads to be separated onto dedicated compute, with ingestion targeting a read-write service and the observability UI running on a read-only service. This is the recommended production topology for larger deployments. See ["Isolating read and write workloads"](/clickstack/self-configured/managing/isolating-read-write).

For larger deployments or custom sizing guidance, please contact support for a more precise estimate.

## Query-user permissions {#user-permissions}

A ClickHouse user used by an external query client only needs to be a `readonly` user with access to change the following settings:

- `max_rows_to_read` (at least up to 1 million)
- `read_overflow_mode`
- `cancel_http_readonly_queries_on_client_close`
- `wait_end_of_query`

By default, the `default` user in ClickHouse Cloud will have these permissions available however you're recommended to create a new user with these permissions.
