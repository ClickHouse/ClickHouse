## max_avg_part_size_for_too_many_parts {#max_avg_part_size_for_too_many_parts}

<SettingsInfoBlock type="UInt64" default_value="1073741824" />

A verificação de &#39;partes em excesso&#39;, de acordo com &#39;parts&#95;to&#95;delay&#95;insert&#39; e
&#39;parts&#95;to&#95;throw&#95;insert&#39;, ficará ativa somente se o tamanho médio da parte (na
partição em questão) não for maior que o limiar especificado. Se ele for
maior que o limiar especificado, os INSERTs não serão nem atrasados nem
rejeitados. Isso permite ter centenas de terabytes em uma única tabela em um
único servidor se as partes forem mescladas com sucesso em partes maiores. Isso
não afeta os limiares de partes inativas nem o total de partes.

## max_compress_block_size {#max_compress_block_size}

<SettingsInfoBlock type="UInt64" default_value="0" />

O tamanho máximo dos blocos de dados não comprimidos antes da compressão para gravação
em uma tabela. Você também pode especificar essa configuração nas configurações globais
(consulte a configuração [max&#95;compress&#95;block&#95;size](/pt-BR/reference/settings/merge-tree-settings/max#max_compress_block_size)).
O valor especificado quando a tabela é criada substitui o valor global
dessa configuração.

Para uma coluna de valores de tamanho fixo, o tamanho do bloco é arredondado para baixo até um múltiplo do tamanho do valor em bytes, mas nunca fica abaixo de um valor.

## max_concurrent_queries {#max_concurrent_queries}

<SettingsInfoBlock type="UInt64" default_value="0" />

Número máximo de consultas executadas simultaneamente relacionadas à tabela MergeTree.
As consultas ainda estarão sujeitas a outras configurações de `max_concurrent_queries`.

Valores possíveis:

* Inteiro positivo.
* `0` — Sem limite.

Valor padrão: `0` (sem limite).

**Exemplo**

```xml

```

## max_file_name_length {#max_file_name_length}

<SettingsInfoBlock type="UInt64" default_value="127" />

O comprimento máximo do nome do arquivo para mantê-lo como está, sem aplicar hash.
Só tem efeito se a configuração `replace_long_file_name_to_hash` estiver habilitada.
O valor desta configuração não inclui o comprimento da extensão do arquivo. Portanto,
recomenda-se defini-la abaixo do comprimento máximo do nome do arquivo (geralmente 255
bytes), com alguma folga para evitar erros no filesystem.

## max_table_size_bytes_compressed {#max_table_size_bytes_compressed}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "Nova configuração para limitar o número total de bytes comprimidos em todas as partes de dados ativas e inativas da tabela."}]}]} />

Se o número total de bytes comprimidos (o tamanho em disco) de todas as partes de dados ativas
e inativas da tabela exceder esse valor, um `INSERT` será
interrompido com a exceção `Table size limit exceeded`. As partes inativas
também são contabilizadas porque o objetivo dessa configuração é limitar o
uso de disco. Observe que as partes inativas são removidas em segundo plano (consulte a
configuração `old_parts_lifetime`), portanto, o tamanho observado pode diminuir ao longo do tempo.
O limite é verificado no início do `INSERT` e quando novas partes de dados
são confirmadas no conjunto de trabalho, incluindo os resultados de merges em segundo plano
e mutações. Inserts realizados por visões materializadas também são verificados. O
limite não é verificado durante fetches replicados, o que permite uma condição de corrida
quando inserts paralelos em várias réplicas ultrapassam o limite. A confirmação de
partes de dados vazias é sempre permitida, portanto, os dados podem ser removidos de uma tabela
que excede o limite, por exemplo, com `TRUNCATE` ou `ALTER TABLE ... DROP
PARTITION`.

Valores possíveis:

* Qualquer inteiro positivo.
* 0 — ilimitado.

É útil para serviços multilocatários, temporários e de demonstração.

## max_table_size_rows {#max_table_size_rows}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "Nova configuração para limitar o número total de linhas nas partes de dados ativas da tabela."}]}]} />

Se o número total de linhas nas partes de dados ativas da tabela exceder este
valor, um `INSERT` será interrompido com a exceção `Table size limit exceeded`.
O limite é verificado no início do `INSERT` e quando novas partes de dados são
incorporadas ao conjunto de trabalho, incluindo os resultados de merges e
mutações em segundo plano (portanto, uma mutação que aumente o tamanho da tabela
além do limite será repetida sem ser concluída). Os inserts realizados por
visões materializadas também são verificados. O limite não é verificado durante
fetch replicado, o que permite uma condição de corrida quando inserts
paralelos em várias réplicas ultrapassam o limite. A incorporação de partes de
dados vazias é sempre permitida, portanto é possível remover dados de uma tabela
que excede o limite, por exemplo, com `TRUNCATE` ou `ALTER TABLE ... DROP PARTITION`.

Valores possíveis:

* Qualquer inteiro positivo.
* 0 — ilimitado.

É útil para serviços multilocatários, temporários e de demonstração.
