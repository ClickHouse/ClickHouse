<div id="always_fetch_merged_part">
  ## always_fetch_merged_part
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

Se true, esta réplica nunca mescla partes e sempre busca partes mescladas
em outras réplicas.

Valores possíveis:

* true, false

<div id="always_fetch_mutated_part">
  ## always_fetch_mutated_part
</div>

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nova configuração para fazer uma réplica buscar partes submetidas a mutações em vez de executar mutações localmente"}]}]} />

Se true, esta réplica nunca executa entradas `MUTATE_PART` do log de replicação
(mutações regulares, como `ALTER TABLE ... UPDATE/DELETE`) e sempre
baixa de outras réplicas as partes resultantes das mutações.

Pelo menos uma réplica deve ter essa configuração desativada; caso contrário, as mutações
não poderão ser concluídas.

Essa configuração não afeta partes de patch criadas por atualizações leves:
elas ainda são aplicadas localmente durante a mesclagem das partes. Ative também
`always_fetch_merged_part` para transferir as mesclagens (incluindo a
aplicação de partes de patch) para outras réplicas.

Como esta réplica não executa mutações e o status de falha de mutação
é local a cada réplica, uma espera síncrona nessa réplica
não pode detectar falhas de mutação ocorridas nas réplicas que executam
a mutação. Portanto, mutações síncronas (`mutations_sync` = 1
ou 2) e consultas `ALTER` síncronas que alteram dados
(`alter_sync` = 1 ou 2) são rejeitadas nessa réplica com o
erro `SUPPORT_IS_DISABLED`, em vez de aguardar indefinidamente caso a
mutação falhe. Use `mutations_sync` = 0 (`alter_sync` = 0) ou execute
essas consultas em uma réplica que execute mutações.

Valores possíveis:

* true, false
