## max_bytes_to_buffer_for_packed_part {#max_bytes_to_buffer_for_packed_part}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Nova configuração. Limita a memória ocupada pelos dados armazenados em buffer de uma parte empacotada durante a gravação, movendo-os para dados temporários. 0 mantém todos os dados em memória, como antes."}]}]} />

Quantidade máxima de memória ocupada pelos dados armazenados em buffer de uma parte de dados empacotada enquanto ela é gravada
por um insert, uma mesclagem ou uma mutação. Uma parte empacotada mantém os dados de todos os seus arquivos em memória até
que a parte seja finalizada. Quando os dados armazenados em buffer excedem esse limite, os dados dos maiores arquivos são
movidos para arquivos temporários no armazenamento temporário do servidor (`tmp_path`, `tmp_policy` ou
`temporary_data_in_cache`) e lidos novamente na finalização. Os arquivos temporários são contabilizados em
`max_temporary_data_on_disk_size_for_query` e `max_temporary_data_on_disk_size_for_user`.
O último bloco (até 64 KiB) de cada arquivo que ainda está sendo gravado não pode ser movido; por isso, uma parte
com muitos arquivos gravados simultaneamente, como uma parte wide com muitas colunas, pode ocupar mais memória.
Os dados de uma parte são movidos para um único arquivo temporário, cujos buffers de gravação (cerca de 2 MiB com o valor padrão de
`temporary_files_buffer_size`) permanecem em memória até que a parte seja finalizada.
O limite se aplica separadamente à parte e a cada uma de suas projeções. 0 significa ilimitado.

## max_bytes_to_merge_at_max_space_in_pool {#max_bytes_to_merge_at_max_space_in_pool}

<SettingsInfoBlock type="UInt64" default_value="161061273600" />

O tamanho total máximo das partes (em bytes) que pode ser mesclado em uma única parte, se
houver recursos suficientes disponíveis. Corresponde aproximadamente ao maior
tamanho de parte possível criado por uma mesclagem automática em segundo plano. (0 significa que as mesclagens serão desabilitadas)

Valores possíveis:

* Qualquer inteiro não negativo.

O scheduler de mesclagem analisa periodicamente os tamanhos e o número de partes nas
partições e, se houver recursos livres suficientes no pool, inicia
mesclagens em segundo plano. As mesclagens ocorrem até que o tamanho total das partes de origem seja
maior que `max_bytes_to_merge_at_max_space_in_pool`.

Mesclagens iniciadas por [OPTIMIZE FINAL](/pt-BR/reference/statements/optimize)
ignoram `max_bytes_to_merge_at_max_space_in_pool` (somente o espaço livre em disco
é levado em consideração).

## max_bytes_to_merge_at_min_space_in_pool {#max_bytes_to_merge_at_min_space_in_pool}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

O tamanho total máximo das partes (em bytes) que podem ser mescladas em uma única parte, com o
mínimo de recursos disponíveis no pool em segundo plano.

Valores possíveis:

* Qualquer número inteiro positivo.

`max_bytes_to_merge_at_min_space_in_pool` define o tamanho total máximo das
partes que podem ser mescladas apesar da falta de espaço disponível em disco (no pool).
Isso é necessário para reduzir o número de partes pequenas e a chance de
erros `Too many parts`.
As mesclagens reservam espaço em disco ao dobrar o tamanho total das partes mescladas.
Assim, com uma pequena quantidade de espaço livre em disco, pode ocorrer uma situação em que
há espaço livre, mas esse espaço já está reservado por grandes mesclagens em andamento,
de modo que outras mesclagens não consigam ser iniciadas, e o número de partes pequenas cresça
a cada inserção.
