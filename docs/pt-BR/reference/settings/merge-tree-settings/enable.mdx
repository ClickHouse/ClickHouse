## enable_adaptive_codec_selection {#enable_adaptive_codec_selection}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nova configuração."}]}]} />

Quando habilitada, a execução de mesclagem e mutações escolhe um codec por bloco para colunas que usam o codec padrão (sem cláusula `CODEC` ou com `CODEC(Default)`).
Os candidatos são o codec padrão da tabela (consulte a configuração `default_compression_codec`), `NONE` e codecs especializados adequados ao tipo da coluna.
O menor resultado é escolhido. Portanto, a compressão nunca é pior que a padrão, e blocos incompressíveis são armazenados brutos.
Uma coluna cujo codec padrão inclui criptografia (por exemplo, `AES_128_GCM_SIV`) nunca é selecionada de forma adaptativa, de modo que a criptografia é sempre aplicada.
Os codecs por bloco são informados pela função de tabela [`mergeTreeCodecBlockCounts`](/pt-BR/reference/functions/table-functions/index).

## enable_mixed_granularity_parts {#enable_mixed_granularity_parts}

<SettingsInfoBlock type="Bool" default_value="1" />

Ativa ou desativa a transição para o controle do tamanho do grânulo com a
configuração `index_granularity_bytes`. Antes da versão 19.11, existia apenas a
configuração `index_granularity` para restringir o tamanho do grânulo. A
configuração `index_granularity_bytes` melhora o desempenho do ClickHouse ao
selecionar dados de tabelas com linhas grandes (dezenas ou centenas de megabytes).
Se você tiver tabelas com linhas grandes, poderá ativar essa configuração para as tabelas
a fim de melhorar a eficiência das consultas `SELECT`.
