## check_part_use_direct_io {#check_part_use_direct_io}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "1"},{"label": "Nova configuração. Verifica partes de dados em discos locais com E/S direta (direct I/O), ignorando o cache de páginas do sistema operacional."}]}]} />

Ao verificar uma parte de dados em um disco local (`CHECK TABLE`, verificação de uma parte cuja leitura falhou,
recálculo de checksums ausentes), seus arquivos são lidos com E/S direta (opção `O_DIRECT`),
ignorando o cache de páginas do sistema operacional, para evitar que dados incorretos no cache de páginas façam uma parte íntegra parecer corrompida.
Partes em armazenamento empacotado (consulte `min_bytes_for_full_part_storage`) e a parte gravada por `OPTIMIZE ... DRY RUN`
continuam sendo lidas por meio do cache de páginas.
Se o sistema de arquivos não suportar E/S direta, os arquivos serão lidos por meio do cache de páginas.

## check_sample_column_is_correct {#check_sample_column_is_correct}

<SettingsInfoBlock type="Bool" default_value="1" />

Habilita a verificação, durante a criação da tabela, de que o tipo de dados de uma coluna de amostragem ou de uma expressão de amostragem está correto. O tipo de dados deve ser um dos [tipos inteiros](/pt-BR/reference/data-types/int-uint): `UInt8`, `UInt16`,
`UInt32`, `UInt64`.

Valores possíveis:

* `true`  — A verificação está habilitada.
* `false` — A verificação é desabilitada durante a criação da tabela.

Valor padrão: `true`.

Por padrão, o servidor ClickHouse verifica, durante a criação da tabela, o tipo de dados de uma coluna de amostragem ou de uma expressão de amostragem. Se você já tiver tabelas com expressões de amostragem incorretas e não quiser que o servidor lance uma exceção durante a inicialização, defina `check_sample_column_is_correct` como `false`.
