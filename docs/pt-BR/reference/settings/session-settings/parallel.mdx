## parallel_distributed_insert_select {#parallel_distributed_insert_select}

<SettingsInfoBlock type="UInt64" default_value="2" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.7"},{"label": "2"},{"label": "Habilita `INSERT ... SELECT` distribuído em paralelo por padrão"}]}]} />

Habilita a consulta `INSERT ... SELECT` distribuída em paralelo.

Ao executar consultas `INSERT INTO distributed_table_a SELECT ... FROM distributed_table_b`, se ambas as tabelas usarem o mesmo cluster e forem [replicadas](/pt-BR/reference/engines/table-engines/mergetree-family/replication) ou não replicadas, essa consulta será processada localmente em cada shard.

Valores possíveis:

* `0` — Desativado.
* `1` — `SELECT` será executado em cada shard a partir da tabela subjacente do engine Distributed.
* `2` — `SELECT` e `INSERT` serão executados em cada shard, a partir da/para a tabela subjacente do engine Distributed.

Desde a v25.4, `INSERT ... SELECT` de uma origem `ReplicatedMergeTree` ou `SharedMergeTree` também pode ser paralelizado entre réplicas. Para habilitar:

* `parallel_distributed_insert_select = 2`
* `enable_parallel_replicas = 1`

<Note>
  A consulta reescrita, incluindo todas as expressões do `SELECT` (subconsultas, UDFs etc.), é executada nos shards com as credenciais da configuração do cluster — o mesmo modelo de confiança de outros processamentos no lado do shard, como as subconsultas de um `IN` não `GLOBAL`. Configure um secret entre servidores (o elemento `secret` da configuração do cluster) se as leituras no lado do shard precisarem ser autorizadas com as permissões do usuário que fez a chamada.
</Note>

## parallel_hash_join_threshold {#parallel_hash_join_threshold}

<SettingsInfoBlock type="UInt64" default_value="100000" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "100000"},{"label": "Nova configuração"}]}, {"id": "row-2","items": [{"label": "25.4"},{"label": "0"},{"label": "Nova configuração"}]}, {"id": "row-3","items": [{"label": "25.3"},{"label": "0"},{"label": "Nova configuração"}]}]} />

Para um hash join `INNER`, `LEFT`, `RIGHT` ou `FULL`, este limiar determina como a tabela hash é construída.
Se o número estimado de linhas na right table estiver abaixo do limiar, a junção constrói a tabela hash como uma única parte, em uma única thread.
No limiar ou acima dele, e também quando não há estimativa, a junção divide a tabela hash em partes preenchidas simultaneamente por até `max_threads` threads (uma thread com `max_threads = 1`).
Com `0`, a tabela hash é sempre dividida.
Com `hash_join_layout` definido como `serial` ou `parallel`, este limiar não é usado: a junção constrói uma única parte ou divide a tabela hash, independentemente da estimativa.
A estimativa vem do plano de consulta ou das estatísticas de execuções anteriores da mesma junção (veja `collect_hash_table_stats_during_joins`).
O plano de consulta estima 0 linhas para uma right table sabidamente vazia, como uma tabela `MergeTree` sem partes de dados.
Junções `ASOF` nunca recebem uma estimativa e, com `query_plan_optimize_join_order_limit = 0`, nenhuma junção recebe.

## parallel_non_joined_rows_processing {#parallel_non_joined_rows_processing}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "1"},{"label": "Nova configuração para habilitar o processamento em paralelo de linhas sem correspondência em hash join parallel_hash RIGHT\/FULL."}]}]} />

Permite que várias threads processem, em paralelo, linhas sem correspondência da right table durante RIGHT e FULL JOINs.
Isso pode acelerar a fase de linhas sem correspondência em hash joins com right tables grandes que constroem a tabela hash em várias threads (consulte `parallel_hash_join_threshold`).
Quando desabilitada, ou quando a tabela hash é construída em uma única thread, as linhas sem correspondência são processadas por uma única thread.
Em todos os casos, as linhas sem correspondência são retornadas sem ordem fixa. Use `ORDER BY` quando a consulta precisar de uma ordem estável.

## parallel_replica_offset {#parallel_replica_offset}

<SettingsInfoBlock type="UInt64" default_value="0" />

Esta é uma configuração interna que não deve ser usada diretamente e representa um detalhe de implementação do modo de &#39;parallel replicas&#39;.
