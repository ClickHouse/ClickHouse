## iceberg_manifest_decode_concurrency {#iceberg_manifest_decode_concurrency}

**Aliases**: `iceberg_delete_manifest_decode_concurrency`

<SettingsInfoBlock type="NonZeroUInt64" default_value="4" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "4"},{"label": "Nova configuração que limita quantos arquivos de manifesto do Iceberg são decodificados de forma concorrente, tanto para manifests de exclusão quanto de dados. Substitui `iceberg_delete_manifest_decode_concurrency` (mantido como alias). O valor `2` aproxima o data path anterior à 26.9, que decodificava um manifest por vez com o fetch do próximo já in-flight; com `compatibility` igual ou inferior a 26.8, a decodificação de exclusões também roda com 2 em vez do padrão lançado de 4, preservando o envelope de memória do data path antigo ao custo de alguma sobreposição na decodificação de exclusões."}]}]} />

Número máximo de arquivos de manifesto do Iceberg decodificados de forma concorrente durante a leitura de uma table.

Todos os manifests de exclusão são decodificados antes que qualquer arquivo de dados seja lido; os manifests de dados são decodificados enquanto a lista de arquivos de dados da consulta é produzida, e novos só são decodificados à medida que a consulta consome as entries já decodificadas. Decodificar vários manifests ao mesmo tempo sobrepõe os round-trips ao armazenamento de objetos ao trabalho de pruning por entry.

Valores mais altos elevam o pico de memória quando o cache de Iceberg metadata files está desabilitado ou cheio, já que cada manifest in-flight passa a manter seu próprio conteúdo decodificado.

Deve ser maior que zero; `1` decodifica os manifests um de cada vez.
