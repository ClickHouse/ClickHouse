## s3_upload_checksum_algorithm {#s3_upload_checksum_algorithm}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": ""},{"label": "Nova configuração para escolher o algoritmo de checksum em uploads para o S3."}]}]} />

O algoritmo de checksum usado quando o ClickHouse envia dados para o `S3`. `CRC32` e `SHA256` são enviados como headers flexíveis `x-amz-checksum-*`, enquanto o `MD5` é enviado no header `Content-MD5`.

Por padrão, o valor é vazio e o ClickHouse deixa que o AWS SDK calcule o `Content-MD5`. No modo FIPS, o `MD5` não está disponível, de modo que o SDK simplesmente o omite e o upload acaba sem nenhum checksum: nesse caso, defina `CRC32` ou `SHA256` para anexar um checksum flexível. Onde essa configuração se aplica, um `MD5` explícito passa a ser rejeitado.

Para buckets que não sejam `S3Express`, `s3_disable_checksum` suprime essa configuração. Ela entra em vigor no momento em que o cliente `S3` é criado, portanto vale para usos com escopo de consulta, como a table function `s3` e `BACKUP ... TO S3`; um `SET` posterior por consulta não reconfigura um cliente de longa duração já criado, como um disco `S3`.

Buckets `S3Express` exigem um checksum flexível e não aceitam `Content-MD5`: um `CRC32` ou `SHA256` explícito é respeitado, um valor vazio usa `CRC32` e um `MD5` explícito é rejeitado.

Endpoints do `GCS` (`storage.googleapis.com`) ignoram completamente essa configuração e mantêm o comportamento de `Content-MD5` do SDK, porque o `GCS` rejeita requisições assinadas com `SigV4` que carregam os headers `x-amz-checksum-*` da AWS.

Cópias server-side ignoram essa configuração.

## s3_upload_part_size_multiply_factor {#s3_upload_part_size_multiply_factor}

<SettingsInfoBlock type="UInt64" default_value="2" />

Multiplique `s3_min_upload_part_size` por esse fator sempre que `s3_multiply_parts_count_threshold` partes forem enviadas em uma única gravação no S3.

## s3_upload_part_size_multiply_parts_count_threshold {#s3_upload_part_size_multiply_parts_count_threshold}

<SettingsInfoBlock type="UInt64" default_value="500" />

Sempre que esse número de partes for enviado ao S3, s3&#95;min&#95;upload&#95;part&#95;size será multiplicado por s3&#95;upload&#95;part&#95;size&#95;multiply&#95;factor.
