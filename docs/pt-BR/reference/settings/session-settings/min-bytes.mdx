## min_bytes_before_external_group_by {#min_bytes_before_external_group_by}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "Nova configuração: o tamanho mínimo do estado de agregação de uma thread antes que o `GROUP BY` externo o grave em disco, para que uma consulta que já esteja acima do limiar não grave cada bloco como um arquivo separado."}]}]} />

O tamanho mínimo, em bytes, do estado de agregação de uma thread antes que o `GROUP BY` externo o grave em disco.

Quando a memória da consulta ultrapassa `max_bytes_before_external_group_by` ou `max_bytes_ratio_before_external_group_by` por causa de outros operadores (por exemplo, uma junção hash que mantém uma tabela grande), cada thread acabaria gravando em disco cada bloco que agrega como um pequeno arquivo separado. Ler de volta muitos arquivos pequenos consome mais memória do que a economizada com as gravações. Com esta configuração, a thread continua agregando até que seu próprio estado atinja o tamanho especificado e só então o grava como um único arquivo.

A memória usada acima do limiar fica limitada a este valor multiplicado pelo número de threads.

Valores possíveis:

* Um inteiro positivo, o tamanho em bytes.
* `0` — sem valor mínimo; o estado é gravado assim que o limiar é atingido.

## min_bytes_to_use_direct_io {#min_bytes_to_use_direct_io}

<SettingsInfoBlock type="UInt64" default_value="0" />

O volume mínimo de dados necessário para usar acesso de E/S direct ao disco de armazenamento.

O ClickHouse usa essa configuração ao ler dados de tabelas. Se o volume total de armazenamento de todos os dados a serem lidos exceder `min_bytes_to_use_direct_io` bytes, o ClickHouse lê os dados do disco de armazenamento com a opção `O_DIRECT`.

Valores possíveis:

* 0 — A E/S direct está desativada.
* Inteiro positivo.

## min_bytes_to_use_mmap_io {#min_bytes_to_use_mmap_io}

<SettingsInfoBlock type="UInt64" default_value="0" />

Esta é uma configuração experimental. Define a quantidade mínima de memória para ler arquivos grandes sem copiar dados do kernel para o espaço do usuário. O valor recomendado é de cerca de 64 MB, porque [mmap/munmap](https://en.wikipedia.org/wiki/Mmap) é lento. Isso só faz sentido para arquivos grandes e só ajuda se os dados estiverem no cache de páginas.

Valores possíveis:

* Inteiro positivo.
* 0 — Arquivos grandes são lidos apenas com a cópia de dados do kernel para o espaço do usuário.
