## http_allow_database_as_path {#http_allow_database_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nova configuração para reconhecer um nome de banco de dados no caminho da URL de requisições HTTP."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Habilitada por padrão: a interface HTTP interpreta o componente `\/database\/` do caminho da URL como banco de dados atual."}]}]} />

Quando habilitada, a interface HTTP reconhece o componente `/database/` no caminho da URL e o usa como banco de dados atual.

Esta é uma configuração por usuário que controla se uma requisição roteada baseada em caminho é interpretada. O roteamento em si é controlado globalmente pela configuração `http_allow_path_requests` no nível do servidor (habilitada por padrão), que deve ser habilitada para que a interface HTTP encaminhe uma requisição baseada em caminho (como `/my_db/my_table.csv`) ao manipulador de consultas — essa decisão de roteamento é tomada antes da autenticação da requisição e, portanto, não pode depender de uma configuração por usuário. Quando `http_allow_path_requests` está desativada, caminhos desconhecidos retornam um `404` simples. Após o roteamento, essa configuração é verificada novamente com base nas configurações efetivas do usuário autenticado, podendo ser desabilitada seletivamente por usuário, função ou perfil.

## http_allow_filters_as_path {#http_allow_filters_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nova configuração para reconhecer filtros `name=value` no estilo Hive no caminho da URL de requisições HTTP."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Habilitada por padrão: a interface HTTP interpreta componentes de caminho `\/name=value\/` como filtros combinados com `AND`."}]}]} />

Quando habilitada, a interface HTTP reconhece componentes `/name=value/` no caminho (estilo de particionamento Hive) e os converte em filtros combinados com AND. Os operadores `>`, `<`, `>=`, `<=`, `!=`, `<>` também são reconhecidos.

Assim como [`http_allow_database_as_path`](/pt-BR/reference/settings/session-settings/http#http_allow_database_as_path), esta é uma configuração por usuário; o roteamento de requisições baseadas em caminho é controlado globalmente pela configuração `http_allow_path_requests` no nível do servidor (o roteamento ocorre antes da autenticação).

## http_allow_filters_as_unrecognized_url_parameters {#http_allow_filters_as_unrecognized_url_parameters}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "Nova configuração para tratar parâmetros de URL não reconhecidos como expressões de filtro em requisições HTTP."}]}]} />

Quando habilitado, qualquer parâmetro de URL que não seja reconhecido como um parâmetro, uma configuração ou um prefixo `param_*` conhecido é tratado como um filtro e combinado com AND. São aceitas duas formas:

* Um `name=value` simples é convertido na igualdade `` `name` = 'value' `` (o identificador é delimitado por crases, e o valor é colocado entre aspas como um literal de string).
* Um operador de comparação (`!=`, `>`, `<`, `>=`, `<=`, `<>`) faz com que o parâmetro seja tratado como uma comparação: ele pode ser separado no parâmetro (`?a!=2`, `?a>=2`) ou escrito inline quando a URL não contém `=` para separá-lo (`?a<>2`, `?f(x)>3`); nesse caso, o `name[=value]` recomposto é convertido em uma expressão SQL completa.

Desabilitada por padrão, ao contrário das outras configurações `http_allow_*`: ela se aplica a todas as requisições da interface HTTP, incluindo o endpoint `/?query=...`, portanto habilitá-la transforma qualquer parâmetro de URL não reconhecido que um cliente acrescente (um id de requisição, uma assinatura, um parâmetro para evitar cache) em um filtro da consulta. Com isso, um nome de configuração digitado incorretamente deixa de ser reportado como `UNKNOWN_SETTING` e passa a falhar com `UNKNOWN_IDENTIFIER` (ou, se o nome coincidir com o de uma coluna, filtra o resultado silenciosamente), e o valor do parâmetro passa a fazer parte do texto da consulta, onde não é mascarado como ocorre com o `Request URI` no log.

## http_allow_table_as_file {#http_allow_table_as_file}

<SettingsInfoBlock type="Bool" default_value="1" />

Quando habilitada, a interface HTTP reconhece o último componente do caminho da URL como um nome de tabela nas formas `table`, `table.format` ou `table.format.compression`. O caminho é interpretado como `SELECT * FROM table`.

Assim como [`http_allow_database_as_path`](/pt-BR/reference/settings/session-settings/http#http_allow_database_as_path), esta é uma configuração por usuário; o roteamento de requisições baseadas em caminho é controlado globalmente pela configuração `http_allow_path_requests` no nível do servidor (o roteamento ocorre antes da autenticação).

## http_make_head_request {#http_make_head_request}

<SettingsInfoBlock type="Bool" default_value="1" />

A configuração `http_make_head_request` permite executar uma solicitação `HEAD` ao ler dados via HTTP para obter informações sobre o arquivo a ser lido, como seu tamanho. Como ela é habilitada por padrão, pode ser desejável desabilitar essa configuração nos casos em que o servidor não oferece suporte a solicitações `HEAD`.

## http_native_compression_disable_checksumming_on_decompress {#http_native_compression_disable_checksumming_on_decompress}

<SettingsInfoBlock type="Bool" default_value="0" />

Ativa ou desativa a verificação de checksum ao descomprimir os dados de HTTP POST do cliente. Usado apenas para o formato de compressão nativo do ClickHouse (não é usado com `gzip` ou `deflate`).

Para mais informações, leia a [descrição da interface HTTP](/pt-BR/concepts/features/interfaces/http).

## http_x_clickhouse_format_overrides_output_format {#http_x_clickhouse_format_overrides_output_format}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "Controla se o cabeçalho HTTP `X-ClickHouse-Format` é um alias de `output_format` (substituindo a cláusula `FORMAT` da consulta), como ocorre desde a 26.8, ou de `default_format`, como ocorria antes da 26.8. Esta entrada documenta retroativamente a mudança da 26.8 para que `compatibility` com versões anteriores à 26.8 restaure o comportamento antigo do cabeçalho."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "Configuração adicionada na 26.10 para controlar a mudança no cabeçalho HTTP `X-ClickHouse-Format` lançada na 26.8. A mudança semântica relevante está registrada no bloco da 26.8, de modo que `compatibility = '26.7'` a reverte, enquanto `compatibility = '26.8'` e `'26.9'` mantêm o comportamento desses lançamentos; esta entrada existe para que a verificação de upgrade aceite o nome recém-introduzido."}]}]} />

Controla a qual configuração o cabeçalho HTTP `X-ClickHouse-Format` corresponde.

Se habilitada (o padrão), o cabeçalho funciona como alias da configuração `output_format`: trata-se de uma substituição explícita do formato de resposta, que prevalece sobre a cláusula `FORMAT` da consulta e sobre a extensão de arquivo no caminho da URL.

Se desabilitada, o cabeçalho funciona como alias da configuração `default_format`, como ocorria antes da versão 26.8: ele apenas define o formato usado quando a consulta não tem cláusula `FORMAT` e nenhuma outra substituição de formato é aplicada.

Em ambos os casos, o cabeçalho substitui o parâmetro de URL de mesmo nome (`output_format` ou `default_format`, respectivamente) e nunca altera a forma como o corpo da requisição de um `INSERT` é convertido.

Esta é uma configuração de compatibilidade da interface HTTP: o cabeçalho é processado antes de a consulta ser convertida, portanto a configuração deve ser fornecida por meio de um parâmetro de URL ou de um perfil de usuário, e não por uma cláusula `SETTINGS` dentro da consulta. Assim como as próprias `output_format` e `default_format`, ela sempre pode ser alterada no modo somente leitura (`readonly = 1`), de modo que um usuário somente leitura pode passá-la como parâmetro de URL.

## http_zlib_compression_level {#http_zlib_compression_level}

<SettingsInfoBlock type="Int64" default_value="3" />

Define o nível de compressão de dados na resposta a uma requisição HTTP se [enable&#95;http&#95;compression = 1](/pt-BR/reference/settings/session-settings/enable#enable_http_compression).

Valores possíveis: números de 1 a 12. Níveis acima de `9` exigem a compilação padrão com `libdeflate`; uma compilação sem `libdeflate` oferece suporte aos níveis de 1 a 9.
