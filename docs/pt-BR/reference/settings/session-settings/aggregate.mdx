## aggregate_function_input_format {#aggregate_function_input_format}

<SettingsInfoBlock type="AggregateFunctionInputFormat" default_value="state" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "state"},{"label": "Nova configuração para controlar o formato de entrada de AggregateFunction durante operações de INSERT. Valor da configuração definido como state por padrão"}]}]} />

Como os input formats leem colunas do tipo `AggregateFunction`.

Valores possíveis:

* `state` — o estado serializado da função de agregação, tal como os output formats o gravam (o padrão).
* `value` — um valor do argumento da função de agregação, ou uma tupla dos argumentos caso haja vários. O valor é agregado para formar o estado.
* `array` — um array de valores, conforme descrito na opção `value` acima. Todos os elementos do array são agregados para formar o estado.

Nos modos `value` e `array`, o formato lê a coluna como se ela tivesse o tipo dos valores: `T` para `AggregateFunction(f, T)`, `Tuple(T1, T2)` para `AggregateFunction(f, T1, T2)`, ou um `Array` desse tipo no modo `array`. Os valores são gravados na representação que o formato usa para aquele tipo: um número ou uma string em um Text format, um JSON array nos JSON formats, o binary encoding do tipo em `RowBinary` ou `Native`, uma coluna desse tipo em `Parquet`, e assim por diante. Isso vale para todos os input formats e também para `AggregateFunction` aninhado em `Array`, `Tuple` ou `Map`.

**Exemplos**

Para uma tabela com a estrutura:

```sql
CREATE TABLE example (
    user_id UInt64,
    avg_session_length AggregateFunction(avg, UInt32)
);
```

Com `aggregate_function_input_format = 'value'`:

```sql
INSERT INTO example FORMAT CSV
123,456
```

```sql
INSERT INTO example FORMAT JSONEachRow
{"user_id": 123, "avg_session_length": 456}
```

Com `aggregate_function_input_format = 'array'`:

```sql
INSERT INTO example FORMAT CSV
123,"[456,789,101]"
```

```sql
INSERT INTO example FORMAT JSONEachRow
{"user_id": 123, "avg_session_length": [456, 789, 101]}
```

Nota: os formatos `value` e `array` são mais lentos que o formato padrão `state`, pois exigem a criação e a agregação de valores durante a inserção.

## aggregate_functions_null_for_empty {#aggregate_functions_null_for_empty}

<SettingsInfoBlock type="Bool" default_value="0" />

Ativa ou desativa a reescrita de todas as funções de agregação em uma consulta, adicionando o sufixo [-OrNull](/pt-BR/reference/functions/aggregate-functions/combinators#-ornull) a elas. Ative esta opção para compatibilidade com o padrão SQL.
Isso é implementado por meio da reescrita da consulta (semelhante à configuração [count&#95;distinct&#95;implementation](/pt-BR/reference/settings/session-settings/count-distinct#count_distinct_implementation)) para obter resultados consistentes em consultas distribuídas.

Possíveis valores:

* 0 — Desabilitado.
* 1 — Habilitado.

**Exemplo**

Considere a seguinte consulta com funções de agregação:

```sql
SELECT SUM(-1), MAX(0) FROM system.one WHERE 0;
```

Com `aggregate_functions_null_for_empty = 0`, o resultado seria:

```text
┌─SUM(-1)─┬─MAX(0)─┐
│       0 │      0 │
└─────────┴────────┘
```

Com `aggregate_functions_null_for_empty = 1`, o resultado seria:

```text
┌─SUMOrNull(-1)─┬─MAXOrNull(0)─┐
│          NULL │         NULL │
└───────────────┴──────────────┘
```
