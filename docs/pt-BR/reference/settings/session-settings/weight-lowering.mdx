## weight_lowering_age_seconds {#weight_lowering_age_seconds}

<SettingsInfoBlock type="Double" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "Nova configuração de consulta: limiar de idade (tempo de relógio) a partir do qual o peso de uma consulta é reduzido no scheduler de carga de trabalho `fair`."}]}]} />

Para o scheduler de carga de trabalho `fair`: quando a consulta atinge esse número de segundos em execução (tempo de relógio), seu peso é reduzido por `weight_lowering_factor`. `0` (ou qualquer valor negativo) desabilita o limiar de idade.

## weight_lowering_cpu_seconds {#weight_lowering_cpu_seconds}

<SettingsInfoBlock type="Double" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "Nova configuração de consulta: limiar de segundos de CPU acumulados a partir do qual o peso de uma consulta é reduzido no scheduler de carga de trabalho `fair`."}]}]} />

Para o scheduler de carga de trabalho `fair`: quando a consulta acumular essa quantidade de segundos de CPU, seu peso é reduzido por `weight_lowering_factor`. Aplica-se a recursos de CPU. `0` (ou qualquer valor negativo) desativa o limiar de CPU. A CPU acumulada corresponde ao serviço concedido pelo scheduler, contabilizado no momento em que uma requisição é concedida, e não à medida que a CPU é efetivamente usada; por isso, ela se adianta ao consumo real em no máximo um quantum (`cpu_slot_quantum_ns`) por slot ativo. Isso só faz sentido com a preempção de CPU slots habilitada (`cpu_slot_preemption = 1`, o padrão); sem preempção, os CPU slots têm um custo fixo por slot, e não o tempo real de CPU, de modo que esse limiar — assim como as demais configurações de CPU do `fair` — deixa de refletir o consumo real de CPU.

## weight_lowering_factor {#weight_lowering_factor}

<SettingsInfoBlock type="Double" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nova configuração de consulta: fator aplicado ao peso de uma consulta quando ela ultrapassa um limiar de redução de peso no scheduler de carga de trabalho `fair`."}]}]} />

Para o scheduler de carga de trabalho `fair`: quando a consulta ultrapassa qualquer um dos limiares `weight_lowering_*` abaixo, seu peso efetivo é multiplicado por este fator uma única vez (valores em (0, 1) reduzem o peso, fazendo o agendamento favorecer consultas mais curtas/recentes). Os limiares não se acumulam — o primeiro a ser atingido aplica a redução integral. `1.0` desabilita a redução. O valor é restrito ao intervalo `[0, 1]`, de modo que o fator só pode reduzir o peso de uma consulta, nunca aumentá-lo.

## weight_lowering_io_bytes {#weight_lowering_io_bytes}

<SettingsInfoBlock type="Double" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "Nova configuração de consulta: limiar de bytes de E/S atingidos a partir do qual o peso de uma consulta é reduzido no scheduler de carga de trabalho `fair`."}]}]} />

Para o scheduler de carga de trabalho `fair`: depois que a consulta atinge essa quantidade de bytes de E/S, seu peso é reduzido por `weight_lowering_factor`. Aplica-se a recursos de E/S. `0` (ou qualquer valor negativo) desabilita o limiar de E/S.
