## async_insert_deduplicate {#async_insert_deduplicate}

<SettingsInfoBlock type="Bool" default_value="0" />

Para consultas INSERT assíncronas na tabela replicada, especifica que a desduplicação dos blocos inseridos deve ser realizada.

Essa configuração só tem efeito quando [`deduplicate_insert`](/pt-BR/reference/settings/session-settings/deduplicate-insert#deduplicate_insert) está definido como `backward_compatible_choice`.

## async_insert_select_as_async_insert {#async_insert_select_as_async_insert}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Habilita a inserção assíncrona para consultas `INSERT ... SELECT` por padrão."}]}]} />

Define se um `INSERT ... SELECT` iniciado pelo usuário pode usar a fila de inserção assíncrona quando `async_insert` estiver habilitado e a consulta for elegível (um único bloco pequeno inserido em um destino da família `MergeTree` sem visões dependentes). Quando desabilitado, o `INSERT ... SELECT` é sempre executado de forma síncrona, independentemente de `async_insert`. Inserções internas (view materializada atualizável, `POPULATE`, `CREATE TABLE ... AS SELECT`) são sempre síncronas e ignoram esta configuração.
