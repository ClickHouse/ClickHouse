## external_storage_push_down_limit {#external_storage_push_down_limit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "Nova configuração para aplicar antecipadamente o `LIMIT` da consulta à consulta enviada a um banco de dados externo, quando for seguro. previous_value=false, de modo que `compatibility` com versões anteriores à 26.10 restaura o comportamento anterior (sem aplicação antecipada)."}]}]} />

Permite aplicar antecipadamente a cláusula `LIMIT` da consulta à consulta enviada a um banco de dados externo (como MySQL, PostgreSQL ou SQLite).

A aplicação antecipada não é feita nas bridges genéricas ODBC/JDBC, pois elas não expõem a sintaxe remota de `LIMIT`, e alguns dos bancos de dados compatíveis sequer aceitam a cláusula `LIMIT`.

O `LIMIT` só é aplicado antecipadamente quando há garantia de que isso é seguro, ou seja, quando todas as cláusulas que logicamente se aplicam antes dele são copiadas para a consulta externa sem alterações. Mais precisamente, a consulta deve ser um `SELECT` simples sobre uma única tabela:

* não há `JOIN`, `ARRAY JOIN`, `SAMPLE` nem `FINAL` (caso contrário, linhas poderiam ser removidas ou transformadas localmente, o que torna a limitação prévia indesejada);
* a cláusula `WHERE`, se houver, é totalmente compatível e copiada sem alterações para a consulta reescrita (caso contrário, a filtragem após o `LIMIT` remoto descartaria algumas linhas);
* não há nenhuma outra cláusula ou modificador (como `DISTINCT`, `GROUP BY`, `ORDER BY`, `LIMIT BY`, `WITH TIES` etc.) que possa comprometer a lógica de limitação prévia remota devido a reordenação, agregação ou filtragem de dados;
* `OFFSET` é permitido: ele é aplicado localmente, portanto as linhas ignoradas também precisam ser lidas, e o limite enviado ao banco de dados externo é `offset + length`;
* a lista do `SELECT` mapeia cada linha de origem para exatamente uma linha de resultado, ou seja, não contém funções de agregação, funções de janela nem `arrayJoin` (também escrito como `unnest`), pois elas são avaliadas localmente sobre todas as linhas lidas da tabela externa;
* não há filtro aplicado localmente sobre as linhas lidas da tabela externa, como uma política de linha ou `additional_table_filters` (esse filtro é executado antes do `LIMIT`, portanto a limitação prévia remota poderia descartar linhas que ele manteria).

Isso reduz a quantidade de dados lidos do banco de dados externo e enviados por ele. Desative esta configuração para restaurar o comportamento anterior em caso de problemas de compatibilidade.
