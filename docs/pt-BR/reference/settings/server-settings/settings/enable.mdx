Essas configurações são usadas para configurar o servidor ClickHouse e são geradas automaticamente a partir do código-fonte do ClickHouse.

<div id="enable_azure_sdk_logging">
  ## enable_azure_sdk_logging
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />Habilita o logging do SDK do Azure

<div id="enable_read_through_distributed_cache">
  ## enable_read_through_distributed_cache
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Yes" />Só tem efeito no ClickHouse Cloud. Permite a leitura do cache distribuído. É uma configuração no nível do servidor, aplicada sem reinicialização, para que as operações em segundo plano que não têm um perfil de consulta próprio (mesclagens, mutações, flushes de tabelas `Buffer`) também a respeitem. Consultas individuais podem substituí-la com a configuração `force_read_through_distributed_cache`.

<div id="enable_silk_runtime">
  ## enable_silk_runtime
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />Habilita o suporte experimental ao runtime de fibras silk: inicializa o scheduler de fibras silk na inicialização do servidor, permitindo que os subsistemas compatíveis executem seus jobs em fibras

<div id="enable_webterminal">
  ## enable_webterminal
</div>

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />Habilita a interface do terminal web no endpoint HTTP `/webterminal`. Disponibiliza uma sessão interativa do `clickhouse-client` no navegador via WebSocket. Quando `false`, as solicitações para `/webterminal` retornam o código de status HTTP `403 Forbidden`.

<div id="enable_write_through_distributed_cache">
  ## enable_write_through_distributed_cache
</div>

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Yes" />Tem efeito apenas no ClickHouse Cloud. Permite gravar no cache distribuído (a gravação no S3 também será realizada pelo cache distribuído). É uma configuração no nível do servidor, aplicada sem reinicialização, para que as operações em segundo plano sem um perfil de consulta próprio (mesclagens, mutações, flushes de tabelas `Buffer`) também a sigam. Consultas individuais podem substituí-la com a configuração `force_write_through_distributed_cache`.
