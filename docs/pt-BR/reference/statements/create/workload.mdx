Introduzido em: v24.11.0

Cria uma carga de trabalho: um nó da hierarquia que o [escalonamento de cargas de trabalho](/pt-BR/concepts/features/configuration/server-config/workload-scheduling) usa para compartilhar recursos entre cargas de trabalho. Os recursos a serem escalonados são criados com [`CREATE RESOURCE`](/pt-BR/reference/statements/create/resource).

## Sintaxe {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - substitui a definição de uma carga de trabalho existente. Não pode ser combinado com `IF NOT EXISTS`.
* `IF NOT EXISTS` - se já existir uma carga de trabalho chamada `name`, a consulta não faz nada.
* `IN parent_name` - cria a carga de trabalho como filha da carga de trabalho `parent_name`. Uma carga de trabalho sem `IN` é uma carga de trabalho raiz. Um ciclo de cargas de trabalho é rejeitado.
* `SETTINGS` - configurações de agendamento da carga de trabalho, por exemplo `weight`, `priority`, `max_concurrent_threads` ou `max_bytes_per_second`, descritas em [Hierarquia de Cargas de Trabalho](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#workloads). Uma configuração com `FOR resource_name` se aplica somente a esse recurso; caso contrário, aplica-se a todos os recursos. Uma configuração desconhecida gera um erro.

Cargas de trabalho e recursos têm namespaces separados, portanto uma carga de trabalho e um recurso podem ter o mesmo nome. Uma consulta é executada na carga de trabalho indicada pela configuração [`workload`](/pt-BR/reference/settings/session-settings/other#workload); consulte [Marcação de carga de trabalho](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#workload-markup).

<Note>
  O escalonamento de reservas de memória é experimental, incluindo o recurso `MEMORY RESERVATION` e as configurações de carga de trabalho `max_memory`, `max_memory_ratio`, `max_memory_before_spill` e `max_memory_to_spill_ratio`. Consulte [Reservas de memória](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#memory-reservations).
</Note>

## Armazenamento {#storage}

As cargas de trabalho são armazenadas em disco em [`workload_path`](/pt-BR/reference/settings/server-settings/settings/workload#workload_path) ou, se essa configuração estiver definida, no ZooKeeper em [`workload_zookeeper_path`](/pt-BR/reference/settings/server-settings/settings/workload#workload_zookeeper_path). Com o armazenamento no ZooKeeper, `ON CLUSTER` é rejeitado, pois as definições são replicadas automaticamente. Cargas de trabalho [definidas na configuração do servidor](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads) não podem ser substituídas nem removidas via SQL. A tabela [`system.workloads`](/pt-BR/reference/system-tables/workloads) lista as cargas de trabalho.

## Privilégios {#privileges}

`CREATE WORKLOAD` requer o privilégio `CREATE WORKLOAD`. `CREATE OR REPLACE WORKLOAD` também requer o privilégio `DROP WORKLOAD`.

## Exemplo {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
