Introduzido em: v22.7.0

Adiciona um [data skipping index](/pt-BR/reference/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-data_skipping-indexes) a uma tabela da família `MergeTree`. É uma forma independente de [`ALTER TABLE ... ADD INDEX`](/pt-BR/reference/statements/alter/skipping-index#add-index) e exige o mesmo privilégio `ALTER ADD INDEX`.

## Sintaxe {#syntax}

```sql
CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [db.]table [ON CLUSTER cluster] expression TYPE type [GRANULARITY value]
```

* `expression` - a expressão indexada, opcionalmente entre parênteses. Uma lista entre parênteses `(expr1, expr2, ...)` cria um único índice sobre todas as expressões, assim como `INDEX name (expr1, expr2, ...)` faz em `CREATE TABLE`.
* `TYPE type [GRANULARITY value]` - como na cláusula `INDEX` de `CREATE TABLE`; consulte [tipos de índice de exclusão](/pt-BR/reference/engines/table-engines/mergetree-family/mergetree#skip-index-types).
* `IF NOT EXISTS` - se a tabela já tiver um índice chamado `name`, a consulta não faz nada.

Assim como `ADD INDEX`, a instrução altera apenas os metadados da tabela. Para criar o índice para os dados já existentes na tabela, execute [`ALTER TABLE ... MATERIALIZE INDEX`](/pt-BR/reference/statements/alter/skipping-index#materialize-index).

## Compatibilidade com SQL {#sql-compatibility}

Para manter a compatibilidade com outros sistemas de banco de dados:

* `ASC` e `DESC` após as expressões de uma lista entre parênteses são ignorados.
* `CREATE UNIQUE INDEX` é rejeitado, a menos que [`create_index_ignore_unique`](/pt-BR/reference/settings/session-settings/create#create_index_ignore_unique) seja `1`. Nesse caso, `UNIQUE` é ignorado e um índice comum é criado.
* `CREATE INDEX` sem `TYPE` é rejeitado, a menos que [`allow_create_index_without_type`](/pt-BR/reference/settings/session-settings/allow#allow_create_index_without_type) seja `1`. Nesse caso, a consulta não tem efeito.

## Exemplo {#example}

```sql title="Query"
CREATE TABLE t (id UInt64, s String) ENGINE = MergeTree ORDER BY id;
INSERT INTO t SELECT number, toString(number) FROM numbers(1000);
CREATE INDEX idx_s ON t (s) TYPE bloom_filter GRANULARITY 1;
ALTER TABLE t MATERIALIZE INDEX idx_s SETTINGS mutations_sync = 1;
SELECT name, type, expr, granularity FROM system.data_skipping_indices WHERE database = currentDatabase() AND table = 't';
```

```text title="Response"
┌─name──┬─type─────────┬─expr─┬─granularity─┐
│ idx_s │ bloom_filter │ s    │           1 │
└───────┴──────────────┴──────┴─────────────┘
```
