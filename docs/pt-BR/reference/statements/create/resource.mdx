Introduzido em: v24.11.0

Cria um recurso para [escalonamento de cargas de trabalho](/pt-BR/concepts/features/configuration/server-config/workload-scheduling): um tipo de acesso, como leituras de disco ou tempo de CPU, que é escalonado entre as cargas de trabalho criadas com [`CREATE WORKLOAD`](/pt-BR/reference/statements/create/workload).

## Sintaxe {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`, `IF NOT EXISTS` e `ON CLUSTER` funcionam da mesma forma que em [`CREATE WORKLOAD`](/pt-BR/reference/statements/create/workload#syntax).

## Modos de acesso {#access-modes}

| Modo de acesso                                | Acesso agendado                                                                                                                                     | Introduzido em |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | Leituras ou gravações no disco `disk_name`; consulte [Recursos](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#resources)       | v24.11.0       |
| `READ ANY DISK`, `WRITE ANY DISK`             | Leituras ou gravações em qualquer disco                                                                                                             | v24.11.0       |
| `MASTER THREAD`, `WORKER THREAD`              | CPU; consulte [Agendamento de CPU](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)                               | v25.4.0        |
| `QUERY`                                       | Slots de consulta; consulte [Agendamento de slots de consulta](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#query_scheduling) | v25.6.0        |
| `MEMORY RESERVATION`                          | Memória; consulte [Reservas de memória](/pt-BR/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)                     | v26.6.2        |

Os modos de acesso de um recurso devem ser todos do mesmo tipo: disco, threads de CPU, `QUERY` ou `MEMORY RESERVATION`. Cada um dos modos `MASTER THREAD`, `WORKER THREAD`, `QUERY` e `MEMORY RESERVATION` pode pertencer a, no máximo, um recurso. `CREATE OR REPLACE RESOURCE` não altera o tipo de um recurso: para isso, remova-o com DROP e crie-o novamente.

<Note>
  `MEMORY RESERVATION` é experimental: sua interface SQL e seu comportamento podem mudar em versões futuras.
</Note>

## Armazenamento {#storage}

Os recursos são armazenados da mesma forma que as cargas de trabalho; consulte [Armazenamento](/pt-BR/reference/statements/create/workload#storage). A tabela [`system.resources`](/pt-BR/reference/system-tables/resources) lista os recursos.

## Privilégios {#privileges}

`CREATE RESOURCE` exige o privilégio `CREATE RESOURCE`. `CREATE OR REPLACE RESOURCE` também exige o privilégio `DROP RESOURCE`.

## Exemplo {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
