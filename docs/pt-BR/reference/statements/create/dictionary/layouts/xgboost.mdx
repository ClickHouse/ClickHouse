O dicionário `xgboost` (`XGBOOST`) treina um modelo de gradient boosting do [XGBoost](https://xgboost.readthedocs.io/) no momento do carregamento, a partir de uma tabela de origem com linhas de treinamento, e então prevê um destino numérico para qualquer vetor de recursos que você fornecer. As colunas de recursos formam a chave do dicionário, e o único atributo é o destino que o modelo aprende.

Ele é indicado para regressão tabular e classificação binária com recursos numéricos — por exemplo, para prever um valor a partir de várias medições ou pontuar linhas em relação a um destino aprendido. Objetivos multiclasse não são suportados (consulte [Parâmetros de layout](#layout-parameters)).

<Note>
  A integração com o XGBoost é experimental. Habilite-a com a configuração `enable_xgboost` antes de criar um dicionário `XGBOOST` ou chamar `predictXGBoost`:

  ```sql
  SET enable_xgboost = 1;
  ```

  Somente `CREATE DICTIONARY` é suportado: um dicionário `XGBOOST` definido em um arquivo de configuração do servidor não é carregado.
</Note>

[`predictXGBoost`](/pt-BR/reference/functions/regular-functions/machine-learning-functions) é a única forma de consultar o dicionário: a função recebe os recursos como argumentos individuais, retorna a predição e aceita [parâmetros de predição](#prediction-parameters) adicionais. Como o dicionário armazena um modelo treinado em vez de linhas, a interface genérica de dicionários — [`dictGet`](/pt-BR/reference/functions/regular-functions/ext-dict-functions#dictGet), `dictHas` e `SELECT * FROM dict` — não é suportada e retorna um erro.

## Guia de início rápido {#quickstart}

Neste exemplo, treinamos um regressor com o destino linear `y = 2*x1 + 3*x2`.

**1. Crie uma tabela de origem** com as linhas de treinamento: as colunas de recursos seguidas do destino:

```sql
CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64)
ENGINE = MergeTree ORDER BY tuple();
```

**2. Insira os dados de treinamento:**

```sql
INSERT INTO training_data
SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y
FROM numbers(100);
```

**3. Crie o dicionário** com o layout `XGBOOST` — as colunas de recursos formam a chave e `y` é o atributo de destino:

```sql
CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(
    objective 'reg:squarederror'
    num_iterations 100
    max_depth 6
))
LIFETIME(0);
```

`PRIMARY KEY (x1, x2)` define `x1` e `x2` como os recursos. O destino que o modelo aprende é `y`, inferido como a única coluna que não faz parte da chave; os parâmetros em `LAYOUT` são hiperparâmetros do XGBoost (consulte [Parâmetros de layout](#layout-parameters)).

**4. Predição** — `predictXGBoost` recebe os recursos por posição e retorna a predição:

```sql
SELECT predictXGBoost('model', 1.0, 2.0) AS prediction;
```

O valor real é `2*1 + 3*2 = 8`, então a predição do modelo fica próxima de `8`.

## Como funciona {#how-it-works}

**Treinamento (no momento do carregamento).** Cada linha da origem é uma observação `(features..., target)`. Quando o dicionário é carregado, a origem é lida bloco a bloco e, em seguida, o modelo é treinado uma única vez sobre todo o conjunto. Os valores dos recursos e do destino são lidos como números de ponto flutuante; por isso, as colunas de chave devem ser numéricas e o atributo de destino deve ser de ponto flutuante (consulte [Estrutura do dicionário](#dictionary-structure)).

<Warning>
  **O treinamento mantém todo o conjunto de treinamento em memória.** Ler a origem em blocos não caracteriza treinamento fora da memória (out-of-core): cada bloco é acumulado em vez de consumido, de modo que todo o conjunto de treinamento já está residente em memória antes da primeira rodada de boosting e permanece assim até a última.
</Warning>

**Predição (no momento da execução da consulta).** Para fazer uma predição, o modelo recebe o vetor de recursos — na mesma ordem em que as colunas de chave foram declaradas —, passa esse vetor pelo booster treinado e retorna um `Float64`. Um recurso `NULL` é passado ao modelo como valor ausente, que o XGBoost trata conforme aprendeu durante o treinamento; assim, a predição nunca é `NULL`. Quando todos os recursos são constantes, o modelo é avaliado uma vez por bloco, e não uma vez por linha.

**O modelo não é persistido.** Ele existe apenas em memória, enquanto o dicionário estiver carregado, e é treinado novamente a partir da origem a cada carregamento — inclusive após a reinicialização do servidor.

**Retreinamento do modelo.** Como cada carregamento treina o modelo do zero, `SYSTEM RELOAD DICTIONARY` o retreina com base no conteúdo atual da tabela de origem:

```sql
INSERT INTO training_data VALUES (5, 10, 40);
SYSTEM RELOAD DICTIONARY model;
```

Um `LIFETIME` diferente de zero também retreina o modelo, já que uma recarga acionada pelo ciclo de vida é um carregamento comum. Use-o para atualizar o modelo periodicamente à medida que os dados de treinamento aumentam.

## Estrutura do dicionário {#dictionary-structure}

Um dicionário `XGBOOST` tem uma estrutura fixa:

* A `PRIMARY KEY` é composta por uma ou mais colunas de um tipo numérico nativo (inteiros e números de ponto flutuante), que representam os recursos. No momento da execução da consulta, essa &quot;chave&quot; é o vetor de recursos que você fornece para obter a predição, e não uma chave de consulta armazenada. A ordem dos recursos segue a ordem de declaração das colunas da chave, e `predictXGBoost` associa seus argumentos posicionais a essa ordem.
* Além delas, declare **exatamente um atributo do tipo `Float32` ou `Float64`**: o destino que o modelo aprende. Ele é sempre inferido como a única coluna que não faz parte da chave de recursos. Não há parâmetro para nomeá-lo, e declarar mais de um atributo gera um erro.

Uma coluna que não atenda a esses requisitos é rejeitada quando o dicionário é carregado, e não no momento em que você o cria.

## Parâmetros de layout {#layout-parameters}

Somente os parâmetros listados abaixo são aceitos; qualquer outro nome faz o carregamento falhar, de modo que erros de digitação são detectados quando o modelo é treinado, em vez de serem ignorados silenciosamente. `num_iterations` é tratado pelo ClickHouse (veja sua descrição); todos os demais parâmetros são encaminhados ao booster do XGBoost sem alterações, como string, e seguem o valor padrão e o intervalo de valores do próprio XGBoost — consulte a [referência de parâmetros do XGBoost](https://xgboost.readthedocs.io/en/stable/parameter.html).

| Parâmetro                                                     | Descrição                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `num_iterations`                                              | Número de rodadas de boosting (quantas árvores treinar). Um inteiro positivo, usado como contagem do loop de treinamento em vez de ser encaminhado ao booster. Padrão: `100`.                                                                                                                                                                                    |
| `booster`                                                     | Tipo de booster: `gbtree`, `gblinear` ou `dart`.                                                                                                                                                                                                                                                                                                                 |
| `objective`                                                   | Objetivo de aprendizado, por exemplo, `reg:squarederror` ou `binary:logistic`. Deve ser um objetivo que preveja um único valor por linha; objetivos multiclasse (`multi:softmax`, `multi:softprob`) são rejeitados.                                                                                                                                              |
| `seed`                                                        | Seed de números aleatórios. Fora isso, o treinamento é determinístico; portanto, este parâmetro só altera o modelo quando um parâmetro estocástico (`subsample`, `sampling_method`, qualquer `colsample_*`) também é definido.                                                                                                                                   |
| `verbosity`                                                   | Nível de detalhamento dos logs do XGBoost: `0` (silencioso), `1` (avisos, o padrão) ou `2` (informações). O nível de depuração `3` é rejeitado, pois os monitores de tempo que ele ativa não são thread-safe. Afeta apenas quais mensagens o XGBoost registra, nunca o modelo treinado. Consulte [Notas](#notes) para saber para onde as mensagens são enviadas. |
| `nthread`                                                     | Número de threads paralelas usadas no treinamento. É aceito e encaminhado, mas atualmente não tem efeito: o XGBoost incluído é compilado sem OpenMP, então o treinamento e a predição sempre são executados em uma única thread.                                                                                                                                 |
| `eta`                                                         | Redução do tamanho do passo aplicada após cada rodada de boosting. Somente esta grafia é aceita; o alias `learning_rate` do XGBoost, não.                                                                                                                                                                                                                        |
| `gamma`                                                       | Redução mínima da perda necessária para fazer uma nova divisão em uma folha.                                                                                                                                                                                                                                                                                     |
| `max_depth`                                                   | Profundidade máxima de uma árvore.                                                                                                                                                                                                                                                                                                                               |
| `min_child_weight`                                            | Soma mínima do peso das instâncias (hessiana) necessária em um nó filho.                                                                                                                                                                                                                                                                                         |
| `max_delta_step`                                              | Passo delta máximo permitido para a saída de cada folha.                                                                                                                                                                                                                                                                                                         |
| `subsample`                                                   | Fração das linhas de treinamento amostradas em cada rodada de boosting.                                                                                                                                                                                                                                                                                          |
| `sampling_method`                                             | Método de amostragem de linhas: `uniform` ou `gradient_based`. Só tem efeito se `subsample` for definido com um valor menor que `1`.                                                                                                                                                                                                                             |
| `colsample_bytree` / `colsample_bylevel` / `colsample_bynode` | Fração de colunas (recursos) amostradas por árvore / por nível / por divisão.                                                                                                                                                                                                                                                                                    |
| `lambda`                                                      | Termo de regularização L2 sobre os pesos. Somente esta grafia é aceita; o alias `reg_lambda` do XGBoost, não.                                                                                                                                                                                                                                                    |
| `alpha`                                                       | Termo de regularização L1 sobre os pesos. Somente esta grafia é aceita; o alias `reg_alpha` do XGBoost, não.                                                                                                                                                                                                                                                     |
| `tree_method`                                                 | Algoritmo de construção da árvore: `auto`, `exact`, `approx` ou `hist`.                                                                                                                                                                                                                                                                                          |
| `scale_pos_weight`                                            | Equilibra pesos positivos e negativos; útil para classes desbalanceadas.                                                                                                                                                                                                                                                                                         |
| `grow_policy`                                                 | Como novos nós são adicionados à árvore: `depthwise` ou `lossguide`.                                                                                                                                                                                                                                                                                             |
| `max_leaves`                                                  | Número máximo de nós folha (usado com `grow_policy` `lossguide`).                                                                                                                                                                                                                                                                                                |
| `max_bin`                                                     | Número máximo de bins discretos usados para agrupar recursos contínuos (usado com `tree_method` `hist`).                                                                                                                                                                                                                                                         |
| `num_parallel_tree`                                           | Número de árvores geradas por rodada de boosting (um valor `> 1` treina uma floresta aleatória com boosting).                                                                                                                                                                                                                                                    |

Os nomes dos parâmetros não diferenciam maiúsculas de minúsculas, e cada um pode ser informado apenas uma vez. Os valores devem ser um inteiro positivo, um número de ponto flutuante ou uma string entre aspas: um literal negativo é rejeitado pelo próprio DDL do dicionário, antes mesmo de chegar ao layout; portanto, não é possível definir um `seed` negativo.

Por exemplo, um dicionário que também define o tamanho do passo `eta`:

```sql
CREATE DICTIONARY model_tuned (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(
    objective 'reg:squarederror'
    num_iterations 100
    max_depth 6
    eta 0.3
))
LIFETIME(0);
```

## Parâmetros de predição {#prediction-parameters}

`predictXGBoost` aceita, após os recursos, um `Map` constante opcional no final com parâmetros de predição do XGBoost, construído com `map`:

```sql
SELECT predictXGBoost('model', 1.0, 2.0, map('type', 0, 'iteration_end', 0));
```

Os nomes dos parâmetros correspondem aos parâmetros de predição de `XGBoosterPredictFromDMatrix` do XGBoost. Somente as chaves abaixo são aceitas; qualquer outra chave faz a consulta falhar. Todos os parâmetros são inteiros ou booleanos, portanto os valores do `Map` devem ser de um tipo inteiro.

| Parâmetro         | Descrição                                                                                                                                                                                                                                                                                                        | Padrão |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `type`            | Tipo de predição. Somente `0` (valor) e `1` (margem) são aceitos, porque `predictXGBoost` retorna um único `Float64` por linha. Os demais tipos do XGBoost (`2`/`3` para contribuições SHAP, `4`/`5` para interações entre recursos, `6` para índice de folha) emitem vários valores por linha e são rejeitados. | `0`    |
| `iteration_begin` | Primeira rodada de boosting a ser incluída na predição, contada a partir de `0` (inclusivo). Não pode exceder o número de iterações de boosting usadas no treinamento do modelo (`num_iterations`).                                                                                                            | `0`    |
| `iteration_end`   | Posição imediatamente após a última rodada de boosting a ser incluída (exclusivo); assim, `iteration_end 1` usa apenas a primeira rodada, e `0` usa todas as rodadas. Tem os mesmos limites que `iteration_begin`.                                                                                         | `0`    |

## Notas {#notes}

* **Semântica de dicionário computacional.** Este é um dicionário *computacional*: ele armazena um modelo treinado, e não linhas, e `predictXGBoost` é a única forma de consultá-lo. A interface genérica de dicionários não é suportada e retorna um erro: `dictGet` (não há atributo armazenado para consultar — a &quot;chave&quot; é um vetor de recursos a partir do qual se faz a predição), `dictHas` (nenhuma chave é armazenada), `SELECT * FROM dict` e a junção do dicionário como uma tabela. Como `predictXGBoost` é o único ponto de entrada, a configuração `enable_xgboost` deve estar habilitada em toda predição.

* **Somente colunas numéricas.** Toda coluna de recurso (chave) deve ser de um tipo numérico nativo, e o atributo de destino deve ser `Float32` ou `Float64`. Os valores são lidos como números de ponto flutuante durante o treinamento e a predição. Os argumentos de recursos de `predictXGBoost` também podem ser `Nullable`; consulte [Como funciona](#how-it-works).

* **`system.dictionaries` não reporta itens armazenados.** O dicionário treina um modelo em vez de armazenar linhas; por isso, `element_count` é `0`, assim como em um dicionário `direct`, e `bytes_allocated` também é `0`: o modelo treinado pertence ao XGBoost, que não informa quanta memória ocupa. `query_count` e `found_rate` contam as linhas passadas ao modelo por `predictXGBoost`; uma chamada cujos recursos são todos constantes é avaliada uma vez por bloco e, portanto, conta uma linha por bloco, e não uma por linha.

* **Uma recarga com falha mantém o modelo anterior.** Se o retreinamento falhar — a tabela de origem deixou de existir, seu schema mudou, um hiperparâmetro deixou de ser aceito —, o dicionário não começa a falhar nas predições. Ele continua servindo o último modelo treinado com sucesso e registra o erro. Compare `last_successful_update_time` com `last_exception` em `system.dictionaries` para saber se o modelo ainda reflete os dados de origem atuais:

  ```sql
  SELECT name, status, last_successful_update_time, last_exception
  FROM system.dictionaries
  WHERE name = 'model';
  ```

* **As mensagens do XGBoost vão para o log do servidor.** Elas são gravadas no logger `XGBoost`, no nível definido pelo próprio XGBoost, e são anexadas à consulta que treina ou faz a predição; por isso, também aparecem em `system.text_log`. Aumente `verbosity` para ver mais mensagens.

* **A ordem dos recursos importa.** `predictXGBoost` associa seus argumentos posicionais de recursos às colunas de chave na ordem de declaração, e o número de argumentos de recursos deve corresponder ao número de colunas de chave.
