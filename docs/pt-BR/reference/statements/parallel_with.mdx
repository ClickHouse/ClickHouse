Permite executar várias instruções em paralelo.

## Sintaxe {#syntax}

```sql
statement1 PARALLEL WITH statement2 [PARALLEL WITH statement3 ...]
```

Executa as instruções `statement1`, `statement2`, `statement3`, ... em paralelo. Somente instruções que não retornam um conjunto de resultados nem esperam dados de entrada podem ser combinadas; consulte [Restrições](#restrictions).

Em muitos casos, executar instruções em paralelo pode ser mais rápido do que simplesmente executá-las em sequência. Por exemplo, `statement1 PARALLEL WITH statement2 PARALLEL WITH statement3` provavelmente será mais rápido do que `statement1; statement2; statement3`.

## Exemplos {#examples}

Cria duas tabelas em paralelo:

```sql
CREATE TABLE table1(x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2(y String) ENGINE = MergeTree ORDER BY tuple();
```

Remove duas tabelas em paralelo:

```sql
DROP TABLE table1
PARALLEL WITH
DROP TABLE table2;
```

## Restrições {#restrictions}

Uma instrução que retorna um conjunto de resultados, como `SELECT`, ou que espera dados de entrada é rejeitada com o erro `INCORRECT_QUERY`.

Uma DDL executada com [`ON CLUSTER`](/pt-BR/reference/statements/distributed-ddl) ou por meio do log DDL de um banco de dados [`Replicated`](/pt-BR/reference/engines/database-engines/replicated) retorna uma tabela de status e, por isso, também é rejeitada, mas somente depois de ter sido enviada aos hosts, que a executam mesmo assim. Ela pode ser combinada se [`distributed_ddl_output_mode`](/pt-BR/reference/settings/session-settings/distributed-ddl#distributed_ddl_output_mode) for `none` ou `none_only_active`:

```sql
SET distributed_ddl_output_mode = 'none';

CREATE TABLE table1 ON CLUSTER default (x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2 ON CLUSTER default (y String) ENGINE = MergeTree ORDER BY tuple();
```

## Configurações {#settings}

A configuração [max&#95;threads](/pt-BR/reference/settings/session-settings/max-threads#max_threads) controla quantas threads são criadas.

## Comparação com UNION {#comparison-with-union}

A cláusula `PARALLEL WITH` é um pouco parecida com [UNION](/pt-BR/reference/statements/select/union), que também executa seus operandos em paralelo. No entanto, há algumas diferenças:

* `PARALLEL WITH` não retorna nenhum resultado da execução de seus operandos; se houver alguma exceção, apenas a propaga novamente;
* `PARALLEL WITH` combina instruções que não retornam um conjunto de resultados nem esperam dados de entrada, enquanto `UNION` combina consultas `SELECT`.
