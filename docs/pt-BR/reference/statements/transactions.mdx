As instruções de controle de transação `BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK` e `SET TRANSACTION SNAPSHOT` agrupam várias consultas sobre tabelas `MergeTree` em uma única transação.
As consultas de uma transação leem um único snapshot consistente das alterações com commit realizado por outras transações.
Gravações fora de transações não são isoladas: um `INSERT`, `TRUNCATE TABLE` ou `ALTER TABLE ... DELETE` executado fora de uma transação fica visível para a próxima consulta de uma transação em execução. Portanto, para obter uma visão estável, os processos de gravação também precisam usar transações, por exemplo, com [`implicit_transaction`](/pt-BR/reference/settings/session-settings/implicit#implicit_transaction).
Outras transações só veem as alterações de uma transação após o `COMMIT`, e o `ROLLBACK` as descarta.
Consultas executadas fora de uma transação podem ver as alterações de uma transação em execução antes que ela receba commit.

## Sintaxe {#syntax}

```sql
BEGIN TRANSACTION
START TRANSACTION
COMMIT
ROLLBACK
SET TRANSACTION SNAPSHOT snapshot
```

Uma transação pertence a uma sessão, e uma sessão tem no máximo uma transação.
Via HTTP, envie todas as consultas de uma transação com o mesmo `session_id`: uma requisição sem `session_id` é executada em uma sessão própria, que termina junto com a requisição.
Se a sessão terminar enquanto a transação ainda estiver em execução, a transação será revertida.

## BEGIN TRANSACTION {#begin-transaction}

Inicia uma transação na sessão atual. `START TRANSACTION` é um alias, introduzido na v24.3.0.

Transações aninhadas não são suportadas: executar `BEGIN TRANSACTION` dentro de uma transação lança uma exceção `INVALID_TRANSACTION`.

## COMMIT {#commit}

Faz o commit da transação atual e torna suas alterações visíveis para outras transações.
Executar `COMMIT` sem uma transação atual lança uma exceção `INVALID_TRANSACTION`.

Se uma consulta dentro da transação falhar, a transação é revertida. Uma consulta que não pode ser analisada, por exemplo devido a um erro de sintaxe, ou cujos parâmetros de consulta estejam ausentes ou sejam inválidos, não é executada e mantém a transação em andamento; assim, um `COMMIT` posterior ainda faz o commit dela.
Até que um `ROLLBACK` encerre uma transação que foi revertida, `COMMIT` e as demais consultas subsequentes lançam uma exceção `INVALID_TRANSACTION`. Apenas `ROLLBACK`, `SET TRANSACTION SNAPSHOT` e as consultas `EXPLAIN`, exceto `EXPLAIN ANALYZE`, continuam sendo executadas.

A configuração [`wait_changes_become_visible_after_commit_mode`](/pt-BR/reference/settings/session-settings/other#wait_changes_become_visible_after_commit_mode) controla o que o `COMMIT` aguarda.

## ROLLBACK {#rollback}

Reverte a transação atual e descarta suas alterações.
Executar `ROLLBACK` sem uma transação ativa lança uma exceção `INVALID_TRANSACTION`.

## SET TRANSACTION SNAPSHOT {#set-transaction-snapshot}

Altera o snapshot lido pela transação atual para o número de sequência de commit (CSN) `snapshot`, por exemplo, um valor retornado por [`transactionLatestSnapshot`](/pt-BR/reference/functions/regular-functions/other-functions#transactionLatestSnapshot) em uma transação anterior.
A partir daí, a transação passa a ver suas próprias alterações, os dados gravados fora de transações e as alterações das transações com commit realizado até esse CSN.
Ela lê apenas as partes que o servidor ainda mantém e não as protege contra remoção: depois que uma mesclagem, uma mutação ou outra consulta remove uma parte e não resta nenhuma transação em execução iniciada antes dessa remoção, o servidor pode excluir essa parte, e um snapshot anterior deixa de ver as linhas dela.
Não dependa de `SET TRANSACTION SNAPSHOT` para obter leituras repetíveis de dados históricos.
Executar `SET TRANSACTION SNAPSHOT` sem uma transação atual lança uma exceção `INVALID_TRANSACTION`.

Os valores de `0` a `32` são reservados e lançam uma exceção `INVALID_TRANSACTION`, com duas exceções:
`1` torna visíveis apenas os dados gravados fora de transações e as próprias alterações da transação, e `3` torna visíveis todas as partes de uma tabela, incluindo as partes de transações que ainda não receberam commit e as partes que transações removeram ou reverteram.

## Consultas dentro de uma transação {#queries-inside-a-transaction}

Uma transação pode executar consultas `SELECT`, `INSERT`, `DELETE`, `OPTIMIZE`, `TRUNCATE TABLE`, `SET` e `EXPLAIN`, além de mutações `ALTER TABLE` e operações de partição.
Outras consultas, como `CREATE TABLE`, `UPDATE` ou `ALTER TABLE ... ADD COLUMN`, lançam uma exceção `NOT_IMPLEMENTED`, assim como consultas sobre tabelas que não oferecem suporte a transações, como tabelas `ReplicatedMergeTree` ou `Memory`, ou `system.transactions`.

Inserções assíncronas não são suportadas dentro de uma transação, e [`async_insert`](/pt-BR/reference/settings/session-settings/async-insert#async_insert) vem habilitado por padrão. Por isso, um `INSERT ... VALUES` ou `INSERT ... SELECT` dentro de uma transação lança uma exceção `NOT_IMPLEMENTED`, a menos que `async_insert` seja desabilitado, por exemplo com `SET async_insert = 0`.

Com [`throw_on_unsupported_query_inside_transaction`](/pt-BR/reference/settings/session-settings/throw-on#throw_on_unsupported_query_inside_transaction) definido como `0`, algumas dessas consultas são executadas fora da transação em vez de lançar uma exceção, de modo que o `ROLLBACK` não as desfaz: por exemplo, um `CREATE TABLE` ou um `INSERT` em uma tabela `Memory`.

Com [`implicit_transaction`](/pt-BR/reference/settings/session-settings/implicit#implicit_transaction) habilitado, cada consulta executada fora de uma transação roda em sua própria transação, que recebe commit quando a consulta é bem-sucedida e é revertida quando ela falha.

## Exemplos {#examples}

Reverter um insert:

```sql title="Query"
CREATE TABLE t (n UInt64) ENGINE = MergeTree ORDER BY n;
SET async_insert = 0;

BEGIN TRANSACTION;
INSERT INTO t VALUES (1);
SELECT count() FROM t;
ROLLBACK;
SELECT count() FROM t;
```

```text title="Response"
┌─count()─┐
│       1 │
└─────────┘
┌─count()─┐
│       0 │
└─────────┘
```

Fazer commit de um insert:

```sql title="Query"
BEGIN TRANSACTION;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```text title="Response"
┌─n─┐
│ 2 │
└───┘
```
