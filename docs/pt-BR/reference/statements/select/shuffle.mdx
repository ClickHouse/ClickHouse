A cláusula `SHUFFLE` retorna as linhas do resultado da consulta em ordem aleatória uniforme. Ela é usada no lugar da cláusula [ORDER BY](/pt-BR/reference/statements/select/order-by) e não pode ser combinada com ela.

Ela retorna o mesmo resultado que `ORDER BY rand()`, mas executa em tempo O(n) em vez de O(n * log(n)).

`SHUFFLE` pode ser usada sem `LIMIT`, para embaralhar a ordem de todas as linhas, ou com `LIMIT n`, para obter uma amostra aleatória uniforme de `n` linhas (também retornadas em ordem aleatória). Com `LIMIT n`, cada stream mantém apenas `n` linhas, de modo que o uso de memória é O(n), independentemente do número de linhas no resultado da consulta. `OFFSET` e `LIMIT BY` podem ser usados da mesma forma que com `ORDER BY`.

<Note>
  Esta é uma funcionalidade experimental. Para habilitá-la, use a configuração [`allow_experimental_shuffle_query`](/pt-BR/reference/settings/session-settings#allow_experimental_shuffle_query).
</Note>

## Detalhes de Implementação {#implementation-details}

As escolhas aleatórias são feitas sob demanda: nenhum valor aleatório é gerado ou armazenado antecipadamente para as linhas. Sem `LIMIT`, cada linha é enviada para um stream aleatório dentre `max_threads` streams, cada stream é embaralhado em paralelo com o algoritmo de Fisher-Yates (em partes que cabem no cache da CPU) e os streams são concatenados. Com `LIMIT n`, cada stream mantém uma amostra uniformemente aleatória de `n` linhas por meio de amostragem por reservatório (reservoir sampling), que descarta, sem examiná-las, as linhas que não têm como entrar na amostra; em seguida, as amostras são mescladas: o número de linhas retiradas de cada stream é sorteado como uma amostragem sem reposição a partir das quantidades de linhas dos streams. Em uma consulta distribuída, os servidores remotos embaralham seus dados e anexam chaves aleatórias ordenadas às linhas, e o iniciador mescla os streams embaralhados por essas chaves, o que exige memória O(1).

Sem `LIMIT`, `SHUFFLE` mantém todas as linhas em memória. Ao contrário de `ORDER BY`, ele não descarrega dados em disco.

`ORDER BY rand()` e `ORDER BY rand64()` podem ser executados da mesma forma que `SHUFFLE` (configuração `query_plan_use_shuffle_for_order_by_rand`) quando o valor aleatório não é usado em nenhuma outra parte da consulta e a ordenação externa está desabilitada. Quando a ordenação externa está configurada, essa otimização é desativada mesmo com um `LIMIT` finito, pois a amostra ainda pode exceder a memória e `SHUFFLE` não consegue descarregar dados em disco. `ORDER BY rand64()` com um limite finito mantém a ordenação para preservar todos os bits dos valores aleatórios.

## Exemplos {#examples}

```sql
SET allow_experimental_shuffle_query = 1;

SELECT number FROM numbers(5) SHUFFLE;
```

```text
┌─number─┐
│      3 │
│      0 │
│      4 │
│      1 │
│      2 │
└────────┘
```

Uma amostra aleatória de três linhas:

```sql
SELECT number FROM numbers(1000000) SHUFFLE LIMIT 3;
```

```text
┌─number─┐
│ 493721 │
│  20857 │
│ 871324 │
└────────┘
```

`SHUFFLE` é uma palavra-chave quando usada após a cláusula `FROM`. Para usar `shuffle` como alias de tabela, escreva `AS shuffle`.
