```sql
ALTER TABLE [db.]table [ON CLUSTER cluster] DELETE WHERE filter_expr
```

Exclui os dados que correspondem à expressão de filtro especificada. Implementado como uma [mutação](/pt-BR/reference/statements/alter/index#mutations).

<Warning>
  O prefixo `ALTER TABLE` indica que esta é uma operação pesada, ao contrário de consultas semelhantes em bancos de dados OLTP. `ALTER TABLE ... DELETE` regrava cada parte de dados que contém linhas correspondentes à expressão de filtro, gerando uma quantidade substancial de E/S de gravação. Use-o com moderação, pois ele pode afetar o desempenho de `SELECT`.

  Para tabelas `MergeTree`, considere usar a [consulta `DELETE FROM`](/pt-BR/reference/statements/delete), que realiza uma exclusão leve e pode ser consideravelmente mais rápida. Para workloads que exigem exclusões ou correções frequentes, considere usar [`ReplacingMergeTree`](/pt-BR/concepts/features/operations/update/replacing-merge-tree) ou [`CollapsingMergeTree`](/pt-BR/reference/engines/table-engines/mergetree-family/collapsingmergetree).
</Warning>

A `filter_expr` deve ser do tipo `UInt8`. A consulta exclui as linhas da tabela para as quais essa expressão assume um valor diferente de zero.

Uma consulta pode conter vários comandos separados por vírgulas.

A sincronia do processamento da consulta é definida pela configuração [mutations&#95;sync](/pt-BR/reference/settings/session-settings/mutations#mutations_sync). Por padrão, ela é assíncrona.
