## Descrição {#description}

[Vortex](https://vortex.dev/) é um formato de arquivo colunar extensível para dados comprimidos compatíveis com Apache Arrow,
projetado para varreduras rápidas e acesso aleatório. O ClickHouse oferece suporte à leitura e à gravação de arquivos Vortex.

## Correspondência de tipos de dados {#data-types-matching-vortex}

A tabela abaixo mostra os tipos de dados do Vortex e os [tipos de dados](/pt-BR/reference/data-types/index) correspondentes do ClickHouse
em consultas `INSERT` e `SELECT`.

| Tipo de dados do Vortex (`INSERT`) | Tipo de dados do ClickHouse                                                               | Tipo de dados do Vortex (`SELECT`)                                |
| ---------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `Bool`                             | [Bool](/pt-BR/reference/data-types/boolean)                                                     | `Bool`                                                            |
| `I8`, `U8`                         | [Int8/UInt8](/pt-BR/reference/data-types/int-uint)                                              | `I8`, `U8`                                                        |
| `I16`, `U16`                       | [Int16/UInt16](/pt-BR/reference/data-types/int-uint)                                            | `I16`, `U16`                                                      |
| `I32`, `U32`                       | [Int32/UInt32](/pt-BR/reference/data-types/int-uint)                                            | `I32`, `U32`                                                      |
| `I64`, `U64`                       | [Int64/UInt64](/pt-BR/reference/data-types/int-uint)                                            | `I64`, `U64`                                                      |
| `F32`                              | [Float32](/pt-BR/reference/data-types/float)                                                    | `F32`                                                             |
| `F64`                              | [Float64](/pt-BR/reference/data-types/float)                                                    | `F64`                                                             |
| `Utf8`, `Binary`                   | [String](/pt-BR/reference/data-types/string)                                                    | `Utf8` (`Binary` com `output_format_vortex_string_as_string = 0`) |
| `Binary`                           | [FixedString](/pt-BR/reference/data-types/fixedstring)                                          | `Binary`                                                          |
| `Decimal`                          | [Decimal](/pt-BR/reference/data-types/decimal)                                                  | `Decimal`                                                         |
| `vortex.date`                      | [Date32](/pt-BR/reference/data-types/date32)                                                    | `vortex.date`                                                     |
| `vortex.timestamp`                 | [DateTime](/pt-BR/reference/data-types/datetime)/[DateTime64](/pt-BR/reference/data-types/datetime64) | `vortex.timestamp`                                                |
| `vortex.time`                      | [Time64](/pt-BR/reference/data-types/time64)                                                    | `vortex.time`                                                     |
| `List`                             | [Array](/pt-BR/reference/data-types/array)                                                      | `List`                                                            |
| `Struct`                           | [Tuple](/pt-BR/reference/data-types/tuple)                                                      | `Struct`                                                          |
| `Null`                             | [Nullable(Nothing)](/pt-BR/reference/data-types/special-data-types/nothing)                     | `Null`                                                            |

Outros tipos não são suportados. Em particular, colunas [Map](/pt-BR/reference/data-types/map),
[Int128/UInt128/Int256/UInt256](/pt-BR/reference/data-types/int-uint), [IPv6](/pt-BR/reference/data-types/ipv6)
e [Interval](/pt-BR/reference/data-types/special-data-types/interval) não podem ser gravadas em arquivos Vortex.
Colunas [String](/pt-BR/reference/data-types/string) são gravadas como `Utf8`, que o Vortex comprime melhor
do que `Binary`. O Vortex exige que os valores `Utf8` sejam UTF-8 válido, enquanto as strings do ClickHouse são sequências
arbitrárias de bytes; portanto, gravar um valor que não seja UTF-8 válido lança uma exceção. Com
`output_format_vortex_string_as_string = 0`, as strings passam a ser gravadas como `Binary`. O Vortex não possui
um tipo binário de tamanho fixo, por isso [FixedString](/pt-BR/reference/data-types/fixedstring) é sempre gravado como `Binary`;
na leitura, a inferência de esquema o interpreta como [String](/pt-BR/reference/data-types/string).
Colunas [LowCardinality](/pt-BR/reference/data-types/lowcardinality) são gravadas com seu tipo subjacente
(o próprio Vortex escolhe, de forma adaptativa, a codificação por dicionário e outras codificações).
Colunas [DateTime](/pt-BR/reference/data-types/datetime) são gravadas como `vortex.timestamp` com precisão de segundos,
portanto são lidas como [DateTime64](/pt-BR/reference/data-types/datetime64) com escala 0.
Um `vortex.timestamp` armazena uma unidade, e não uma escala, então apenas as escalas que correspondem exatamente a uma unidade -
0, 3, 6 e 9 - são preservadas na inferência de esquema; qualquer outra escala é gravada na unidade imediatamente mais ampla e
inferida com a escala dessa unidade, de modo que [DateTime64](/pt-BR/reference/data-types/datetime64)`(1)` e `(2)` são lidos
como `DateTime64(3)`, `(4)` e `(5)` como `DateTime64(6)`, e `(7)` e `(8)` como `DateTime64(9)`. Os valores
são reescalados e mantêm seu significado; apenas a escala declarada é ampliada, e especificar o tipo explicitamente faz com que
ele seja lido sem alterações. O mesmo vale para [Time64](/pt-BR/reference/data-types/time64).
`vortex.time` representa uma hora do dia, enquanto [Time/Time64](/pt-BR/reference/data-types/time64) no ClickHouse também armazena
valores negativos e valores de 24 horas ou mais; gravar um desses valores lança uma exceção em vez de gravar um valor incorreto.
Colunas [IPv4](/pt-BR/reference/data-types/ipv4) são gravadas como `U32` porque o Vortex não possui um tipo para endereços IP,
então a inferência de esquema as lê como [UInt32](/pt-BR/reference/data-types/int-uint). Especifique o tipo explicitamente
para ler essa coluna como `IPv4`: `SELECT * FROM file('data.vortex', Vortex, 'ip IPv4')`.

Os tipos de dados das colunas da tabela do ClickHouse não precisam corresponder aos dos campos de dados do Vortex.
Ao inserir dados, o ClickHouse interpreta os tipos de dados de acordo com a tabela acima e, em seguida,
[converte](/pt-BR/reference/functions/regular-functions/type-conversion-functions#CAST) os dados para o tipo de dado definido para a
coluna da tabela do ClickHouse.

## Exemplo de uso {#example-usage}

Você pode consultar dados de um arquivo Vortex:

```sql
SELECT * FROM file('data.vortex');
```

E para gravar dados em um arquivo Vortex:

```sql
SELECT * FROM numbers(3) INTO OUTFILE 'numbers.vortex' FORMAT Vortex;
```

## Configurações de formato {#format-settings}

| Configuração                            | Descrição                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Padrão            |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `input_format_vortex_filter_push_down`  | Envia as partes traduzíveis da condição `WHERE` para dentro da varredura, para que uma consulta seletiva leia e decodifique menos dados. Somente a parte traduzida da condição é aplicada dentro da varredura: uma condição apenas parcialmente traduzível é ampliada para outra que preserve pelo menos todas as linhas correspondentes; assim, linhas sem correspondência ainda podem ser lidas e decodificadas, e o ClickHouse reaplica o filtro completo em seguida. Atualmente, o pushdown oferece suporte a colunas de nível superior dos tipos inteiro, ponto flutuante, string/binary, `Bool`, `Date`, `Date32` e `DateTime64`. | `1`               |
| `input_format_vortex_preserve_order`    | Retorna as linhas na ordem em que aparecem no arquivo. Por padrão, as divisões de linhas de um arquivo são decodificadas em paralelo e retornadas assim que ficam prontas, portanto a ordem das linhas não é garantida; com essa configuração ativada, uma divisão lenta retém as que vêm depois dela.                                                                                                                                                                                                                                                                                                                                  | `0`               |
| `output_format_vortex_string_as_string` | Grava colunas [String](/pt-BR/reference/data-types/string) como `Utf8` em vez de `Binary`. Um valor que não seja UTF-8 válido lança uma exceção; desative a configuração para gravar esses dados como `Binary`.                                                                                                                                                                                                                                                                                                                                                                                                                               | `1`               |
| `max_parsing_threads`                   | O número de threads que decodificam arquivos Vortex (compartilhadas pelos arquivos lidos em paralelo por uma mesma consulta). `1` desabilita o pool de threads: nesse caso, o arquivo é lido dentro de `read`, na thread do pipeline de consulta.                                                                                                                                                                                                                                                                                                                                                                                       | número de núcleos |
| `max_download_threads`                  | O número de threads que leem o arquivo. Com `0`, as leituras compartilham as threads de decodificação.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `4`               |

Assim como em outros formatos colunares, apenas as colunas usadas pela consulta são lidas do arquivo, e
as colunas ausentes no arquivo são preenchidas com valores default.

## Desempenho {#performance}

Um arquivo é lido em paralelo. A varredura o divide em intervalos de linhas (alinhados aos limites dos fragmentos das
colunas solicitadas, com no máximo 100 000 linhas cada), que são lidos, filtrados e decodificados concorrentemente:
a decodificação é executada em até `max_parsing_threads` threads do mesmo pool usado pelo leitor de `Parquet`,
as leituras, em até `max_download_threads` threads, e a conversão de um fragmento decodificado em
colunas do ClickHouse ocorre na mesma thread que o decodificou. Os fragmentos são retornados assim que ficam
prontos; portanto, a ordem das linhas não é garantida, a menos que `input_format_vortex_preserve_order` esteja habilitado. As
leituras de segmentos próximos no arquivo são mescladas em uma única requisição (até 4 MiB para arquivos
locais e 16 MiB para armazenamento remoto). O pushdown de filtros reduz a quantidade de dados lidos e decodificados
em consultas seletivas.
