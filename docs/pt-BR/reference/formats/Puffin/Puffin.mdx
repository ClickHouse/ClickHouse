## Descrição {#description}

Formato para leitura e gravação de arquivos [Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/).

O formato expõe as posições das linhas excluídas a partir de blobs `deletion-vector-v1`. Blobs de outros tipos, como `apache-datasketches-theta-v1`, são ignorados, conforme exige a especificação Puffin; use `PuffinMetadata` para visualizá-los.
Se um arquivo puffin contiver vários blobs `deletion-vector-v1`, o formato gera uma linha para cada um desses blobs.

Colunas de saída fixas:

* `referenced_data_file` (`String`) - localização do arquivo de dados ao qual o vetor de exclusão se aplica (propriedade de blob `referenced-data-file`)
* `deleted_rows` (`Array(UInt64)`) - posições de linha de 64 bits excluídas de acordo com o roaring bitmap do vetor de exclusão

Quando usado como formato de saída, a entrada deve ter as mesmas duas colunas que o formato produz na leitura: o arquivo de dados referenciado (`String` ou `LowCardinality(String)`) e as posições das linhas excluídas (um inteiro, uma posição por linha, ou um array de inteiros). O arquivo contém um blob `deletion-vector-v1` para cada arquivo de dados referenciado distinto, ordenados pela localização do arquivo de dados, de modo que um arquivo Puffin com vários vetores de exclusão pode ser copiado sem alterações. As posições de todas as linhas com o mesmo arquivo de dados referenciado são mescladas em um único vetor de exclusão, deduplicadas e ordenadas; posições negativas, posições acima do limite do vetor de exclusão do Iceberg e localizações de arquivo de dados vazias são rejeitadas. Os metadados do blob são gravados da mesma forma que o Apache Iceberg grava vetores de exclusão: `fields` é `[2147483645]` (o id da coluna de metadados `_pos`), `snapshot-id` e `sequence-number` são `-1`, e as propriedades `referenced-data-file` e `cardinality` são definidas. O rodapé não é comprimido, de modo que o arquivo resultante pode ser registrado em uma tabela Iceberg v3 como um arquivo de exclusão do tipo vetor de exclusão e lido por outros engines, como o Apache Spark. Use `PuffinMetadata` no arquivo gravado para obter o `offset` e o `length` de cada blob para os campos de manifesto `content_offset` e `content_size_in_bytes`.

Com a configuração `output_format_puffin_blob_type` definida como `apache-datasketches-theta-v1`, o formato passa a gravar estatísticas de colunas da mesma forma que o Apache Iceberg: cada coluna de entrada se torna um blob `apache-datasketches-theta-v1` com um sketch Theta compacto do Apache DataSketches (seed e tamanho padrão) sobre os valores não nulos da coluna, e a propriedade `ndv` é definida como o número estimado de valores distintos. Os valores são fornecidos ao sketch na serialização binária de valor único do Iceberg correspondente ao tipo da coluna, de modo que os sketches podem ser mesclados com os gravados pelo Apache Spark: `Bool` como `boolean`, `Int8`, `UInt8`, `Int16`, `UInt16` e `Int32` como `int`, `UInt32`, `Int64` e `UInt64` como `long` (valores de `UInt64` acima do intervalo de `Int64` mantêm seus bits), `Float32` como `float`, `Float64` como `double`, `Date` e `Date32` como `date`, `DateTime` e `DateTime64` com até 6 dígitos de precisão como `timestamp` (em microssegundos), `String` como `string`, `FixedString` como `fixed`, `UUID` como `uuid` e `Decimal` como `decimal`; `Nullable` e `LowCardinality` desses tipos também são suportados. Strings vazias são ignoradas, assim como no Iceberg. Os `fields` dos blobs são obtidos da configuração `output_format_puffin_field_ids`, e `snapshot-id` e `sequence-number`, das configurações `output_format_puffin_snapshot_id` e `output_format_puffin_sequence_number`; as três configurações são obrigatórias, porque os leitores associam as estatísticas às colunas e ao snapshot indicados por elas. O resultado pode ser registrado como um arquivo de estatísticas do Iceberg.

Vetores de exclusão cuja `cardinality` declarada exceda um teto absoluto de materialização são rejeitados quando `deleted_rows` é solicitado. As propriedades `deletion-vector-v1` do rodapé (incluindo a verificação de que `cardinality` é um inteiro sem sinal válido) são sempre validadas. Selecionar apenas `referenced_data_file` evita a E/S da carga útil em disco e, portanto, também dispensa o envelope, o CRC, a desserialização do roaring e o teto de materialização — intencionalmente, para que uma projeção apenas de caminhos não leia até o limite de tamanho do blob.

O comprimento em disco do blob `deletion-vector-v1` é limitado por um teto absoluto (alinhado com a verificação de tamanho de conteúdo de 2 GiB do Iceberg). Quando `deleted_rows` é solicitado, o leitor inspeciona o cabeçalho do envelope (comprimento combinado e magic) antes de alocar a carga útil completa; o CRC é verificado após a leitura limitada.

Há suporte para rodapés Puffin comprimidos com LZ4 e não comprimidos. O tamanho da carga útil do rodapé (e o tamanho de conteúdo LZ4 declarado) é limitado, quando aplicável, por uma razão de compressão e por um teto absoluto; rodapés muito grandes são rejeitados antes da alocação.

Apenas um subconjunto das colunas de saída pode ser solicitado. Uma estrutura fornecida pelo usuário com nomes ou tipos de coluna inesperados é rejeitada durante a criação do formato.

## Exemplo de uso {#example-usage}

Leia as posições das linhas excluídas usando o arquivo de dados referenciado:

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

Expanda as posições excluídas em linhas individuais:

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

Use `PuffinMetadata` para inspecionar os descritores de blobs do rodapé antes de ler os vetores de exclusão.

Grave os vetores de exclusão de dois arquivos de dados em um único arquivo Puffin:

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

Grave os sketches Theta de duas colunas como um arquivo de estatísticas do Iceberg:

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
