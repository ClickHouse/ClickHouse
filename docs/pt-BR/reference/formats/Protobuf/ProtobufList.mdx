## Descrição {#description}

O formato `ProtobufList` agrupa as linhas em uma única mensagem [Protocol Buffers](/pt-BR/reference/formats/Protobuf/Protobuf) delimitada por comprimento, chamada `Envelope`. Cada linha é codificada como uma submensagem com o número de campo 1.

## Exemplo de uso {#example-usage}

Salve o schema a seguir como `schemafile.proto`. Declare o campo `row` como `repeated` para que um decodificador Protobuf que use esse schema consiga ler todas as linhas do envelope.

```capnp title="schemafile.proto"
syntax = "proto3";
message Envelope {
  message MessageType {
    string name = 1;
  }
  repeated MessageType row = 1;
}
```

No mesmo diretório, execute estes comandos para gravar duas linhas em um arquivo e, em seguida, lê-las.

```bash
clickhouse local --query "SELECT name FROM values('name String', 'Ada', 'Grace') ORDER BY name
    SETTINGS format_schema = 'schemafile:MessageType' FORMAT ProtobufList" > people.bin

clickhouse local --structure 'name String' --input-format ProtobufList \
    --format_schema 'schemafile:MessageType' --query 'SELECT name FROM table' < people.bin
```

```text
Ada
Grace
```

O tipo de mensagem especificado em `format_schema` é resolvido primeiro procurando por ele como um tipo aninhado dentro de uma mensagem `Envelope` de nível superior. Se nenhuma correspondência for encontrada ali — seja porque o schema não tem uma mensagem `Envelope`, seja porque o `Envelope` não contém uma mensagem com o nome solicitado — a mensagem de nível superior com esse nome é usada diretamente.
