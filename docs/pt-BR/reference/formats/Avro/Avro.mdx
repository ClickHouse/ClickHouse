## Descrição {#description}

[Apache Avro](https://avro.apache.org/) é um formato de serialização orientado a linhas que usa codificação binária para processamento eficiente de dados. O formato `Avro` oferece suporte à leitura e à gravação de [arquivos de dados Avro](https://avro.apache.org/docs/current/specification/#object-container-files). Esse formato requer mensagens autodescritivas com um esquema incorporado. Se você estiver usando Avro com um registro de esquemas, consulte o formato [`AvroConfluent`](/pt-BR/reference/formats/Avro/AvroConfluent).

## Configurações de formato {#format-settings}

| Configuração                               | Descrição                                                                                                                                                                                 | Valor padrão |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `input_format_avro_allow_missing_fields`   | Se deve usar um valor padrão em vez de gerar um erro quando um campo não for encontrado no esquema.                                                                                       | `0`          |
| `input_format_avro_null_as_default`        | Se deve usar um valor padrão em vez de gerar um erro ao inserir um valor `null` em uma coluna que não aceita `null`.                                                                      | `0`          |
| `output_format_avro_codec`                 | Algoritmo de compressão para arquivos de saída Avro. Valores possíveis: `null`, `deflate`, `snappy`, `zstd`, `bzip2`, `xz`.                                                               |              |
| `output_format_avro_sync_interval`         | Frequência do marcador de sincronização em arquivos Avro (em bytes).                                                                                                                      | `16384`      |
| `output_format_avro_string_column_pattern` | Expressão regular para identificar colunas `String` para o mapeamento para o tipo string do Avro. Por padrão, as colunas `String` do ClickHouse são gravadas como o tipo `bytes` do Avro. |              |
| `output_format_avro_rows_in_file`          | Número máximo de linhas por arquivo de saída Avro. Quando esse limite é atingido, um novo arquivo é criado (se o sistema de armazenamento oferecer suporte à divisão de arquivos).        | `1`          |

## Exemplos {#examples}

### Leitura de dados Avro {#reading-avro-data}

Para ler dados de um arquivo Avro para uma tabela do ClickHouse:

```bash
$ cat file.avro | clickhouse-client --query="INSERT INTO {some_table} FORMAT Avro"
```

O esquema raiz do arquivo Avro submetido à ingestão deve ser do tipo `record`.

Para encontrar a correspondência entre as colunas da tabela e os campos do esquema Avro, o ClickHouse compara seus nomes.
Essa comparação diferencia maiúsculas de minúsculas, e os campos não usados são ignorados.

Os tipos de dados das colunas da tabela do ClickHouse podem diferir dos campos correspondentes dos dados Avro inseridos. Ao inserir dados, o ClickHouse interpreta os tipos de dados de acordo com a tabela acima e, em seguida, [faz a conversão](/pt-BR/reference/functions/regular-functions/type-conversion-functions#CAST) dos dados para o tipo da coluna correspondente.

Um registro (record) com exatamente dois campos `bytes`, chamados `metadata` e `value` (que é a forma como o Iceberg v3 armazena um `variant` em Avro), é lido em uma coluna [`Dynamic`](/pt-BR/reference/data-types/dynamic) ou [`JSON`](/pt-BR/reference/data-types/newjson) com a [codificação binária de variant](https://github.com/apache/parquet-format/blob/master/VariantEncoding.md), da mesma forma que uma coluna `VARIANT` do formato `Parquet`.

Ao importar dados, quando um campo não é encontrado no esquema e a configuração [`input_format_avro_allow_missing_fields`](/pt-BR/reference/settings/formats/input-format#input_format_avro_allow_missing_fields) está habilitada, o valor padrão será usado em vez de gerar um erro.

### Análise sintática paralela {#parallel-parsing}

Quando [`input_format_parallel_parsing`](/pt-BR/reference/settings/formats/input-format#input_format_parallel_parsing) está habilitado, um arquivo de contêiner de objetos Avro é dividido nos limites de seus blocos (marcadores de sincronização) e os blocos são interpretados em várias threads. Como blocos inteiros são armazenados em buffer e decodificados concorrentemente, o pico de memória aumenta conforme o número de threads de parsing; defina `input_format_parallel_parsing = 0` para interpretar os dados sequencialmente e manter o consumo de memória baixo. Isso não se aplica ao [`AvroConfluent`](/pt-BR/reference/formats/Avro/AvroConfluent), que não é um arquivo de contêiner de objetos.

### Gravando dados em Avro {#writing-avro-data}

Para gravar dados de uma tabela do ClickHouse em um arquivo Avro:

```bash
$ clickhouse-client --query="SELECT * FROM {some_table} FORMAT Avro" > file.avro
```

Os nomes das colunas devem:

* Começar com `[A-Za-z_]`
* Ser seguidos apenas por `[A-Za-z0-9_]`

A compressão de saída e o intervalo de sincronização de arquivos Avro podem ser configurados, respectivamente, com as configurações [`output_format_avro_codec`](/pt-BR/reference/settings/formats/output-format#output_format_avro_codec) e [`output_format_avro_sync_interval`](/pt-BR/reference/settings/formats/output-format#output_format_avro_sync_interval).
