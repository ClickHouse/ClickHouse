O motor `Elasticsearch` permite ler documentos de um índice no [Elasticsearch](https://www.elastic.co/elasticsearch). Cada documento é retornado como uma linha: seu `_source` é exposto como uma única coluna do tipo [JSON](/pt-BR/reference/data-types/newjson), e o ID do documento e o nome do índice ficam disponíveis como colunas virtuais.

O motor é read-only. Os documentos são obtidos em páginas por meio da API `_search`, usando um [ponto no tempo](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results#search-after) para que a consulta enxergue um snapshot consistente do índice, mesmo enquanto ele estiver sendo modificado.

É necessário usar o Elasticsearch 7.12 ou posterior, pois o motor depende da API de ponto no tempo e do campo de ordenação `_shard_doc`. O OpenSearch não é suportado, já que não possui o campo `_shard_doc`. Servidores mais antigos rejeitam a primeira requisição com um erro.

## Criando uma tabela {#creating-a-table}

```sql
CREATE TABLE [IF NOT EXISTS] [db.]table_name
[(
    name1 JSON
)]
ENGINE = Elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...])
[SETTINGS keep_alive = 60, page_size = 10000]
```

<Note>
  A integração com o Elasticsearch é experimental. Habilite-a com a configuração [`enable_elasticsearch`](/pt-BR/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

A lista de colunas é opcional. Quando omitida, a tabela tem uma única coluna `document` do tipo `JSON`. Quando especificada, deve conter exatamente uma coluna, cujo tipo deve ser `JSON`, opcionalmente com dicas de tipo e caminhos ignorados. Colunas `MATERIALIZED`, `ALIAS` e `EPHEMERAL` não são suportadas, e os nomes `_id` e `_index` são reservados para as colunas virtuais.

**Parâmetros do mecanismo**

* `url` — A URL base do cluster Elasticsearch, por exemplo, `https://localhost:9200`. Deve ser uma URL `http` ou `https` sem credenciais, string de consulta ou fragmento.
* `index` — O índice a ser lido. Também pode ser um alias, um data stream, uma lista separada por vírgulas, um pattern com curingas ou uma expressão de cálculo de datas como `<logs-{now/d}>`, conforme aceito pela API de ponto no tempo do Elasticsearch. O valor é o nome literal e não deve ser codificado para URL. Um pattern que não corresponda a nenhum índice gera um erro.
* `user`, `password` — Credenciais opcionais para autenticação básica HTTP.
* `query('...')` — Um objeto opcional da [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) do Elasticsearch, em JSON, que seleciona os documentos a serem lidos. Deve vir após os argumentos posicionais. Padrão: `{"match_all": {}}`.

Os parâmetros também podem ser passados como uma [coleção nomeada](/pt-BR/concepts/features/configuration/server-config/named-collections) com substituições `key = value`. Consulte a [função de tabela `elasticsearch`](/pt-BR/reference/functions/table-functions/elasticsearch#arguments) para ver a lista completa de chaves e a descrição dos [métodos de autenticação](/pt-BR/reference/functions/table-functions/elasticsearch#authentication).

**Configurações do mecanismo**

| Configuração | Padrão  | Descrição                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keep_alive` | `60`    | Por quanto tempo, em segundos, o Elasticsearch mantém o ponto no tempo aberto entre duas requisições de página consecutivas.                                                                                                                                                                                                                                                                                      |
| `page_size`  | `10000` | O número de documentos solicitados ao Elasticsearch por requisição. Cada página se torna um bloco, portanto esta configuração também define o tamanho do bloco da leitura; [`max_block_size`](/pt-BR/reference/settings/session-settings/max#max_block_size) não tem efeito. Valores acima da configuração de índice `index.max_result_window` do Elasticsearch (`10000` por padrão) são rejeitados pelo Elasticsearch. |

As configurações não podem ser alteradas com `ALTER TABLE ... MODIFY SETTING`. Para alterá-las, recrie a tabela.

## Colunas virtuais {#virtual-columns}

* `_id` — O ID do documento. Tipo: `String`.
* `_index` — O nome do índice do qual o documento foi lido. Tipo: `LowCardinality(String)`.

Quando uma consulta lê apenas colunas virtuais, o `_source` do documento não é solicitado ao Elasticsearch. Um índice que não armazena `_source` (ou seja, cujo campo `_source` está desabilitado no mapeamento) só pode ser lido por meio das colunas virtuais: uma consulta que lê a coluna `JSON` de um índice desse tipo falha com um erro, em vez de retornar documentos vazios.

## Exemplo de uso {#usage-example}

```sql
CREATE TABLE logs
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*', 'elastic', 'changeme')
SETTINGS page_size = 5000;

SELECT _index, _id, document.message
FROM logs
WHERE document.level = 'error'
LIMIT 10;
```

Filtre no Elasticsearch usando um objeto Query DSL:

```sql
CREATE TABLE errors_since_october
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*',
                       query('{"bool": {"filter": [{"term": {"level": "error"}}, {"range": {"@timestamp": {"gte": "2026-10-01T00:00:00Z"}}}]}}'),
                       api_key = '...');
```

Use datas absolutas no `query`: expressões de cálculo de datas como `now-1h` são reavaliadas a cada página, o que pode fazer com que alguns documentos sejam ignorados. Consulte as [limitações da função de tabela `elasticsearch`](/pt-BR/reference/functions/table-functions/elasticsearch#limitations).
