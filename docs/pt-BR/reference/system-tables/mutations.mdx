<div id="description">
  ## Descrição
</div>

A tabela contém informações sobre [mutações](/pt-BR/reference/statements/alter/index#mutations) de tabelas [MergeTree](/pt-BR/reference/engines/table-engines/mergetree-family/mergetree) e o andamento delas. Cada comando de mutação é representado por uma única linha.

<div id="columns">
  ## Colunas:
</div>

{/*AUTOGENERATED_START*/}

* `database` ([String](/pt-BR/reference/data-types/string)) — O nome do banco de dados ao qual a mutação foi aplicada.
* `table` ([String](/pt-BR/reference/data-types/string)) — O nome da tabela à qual a mutação foi aplicada.
* `mutation_id` ([String](/pt-BR/reference/data-types/string)) — O ID da mutação. Para tabelas replicadas, esses IDs correspondem aos nomes de znodes no diretório `<table_path_in_clickhouse_keeper>/mutations/` do ClickHouse Keeper. Para tabelas não replicadas, os IDs correspondem aos nomes de arquivos no diretório de dados da tabela.
* `command` ([String](/pt-BR/reference/data-types/string)) — A string de comando da mutação (a parte da consulta após ALTER TABLE [db.]table).
* `create_time` ([DateTime](/pt-BR/reference/data-types/datetime)) — A data e a hora em que o comando de mutação foi enviado para execução.
* `finish_time` ([DateTime](/pt-BR/reference/data-types/datetime)) — A data e a hora em que a mutação foi concluída. Zero se a mutação ainda não foi concluída ou se o horário de sua conclusão for desconhecido. Para tabelas não replicadas, o valor é rastreado na memória e é redefinido quando a tabela é recarregada (por exemplo, na reinicialização do servidor). Para tabelas replicadas, o valor é por réplica; após uma reinicialização, o horário de conclusão da mutação concluída mais recentemente é restaurado do Keeper, enquanto mutações concluídas mais antigas informam zero.
* `block_numbers.partition_id` ([Array(String)](/pt-BR/reference/data-types/array)) — Para mutações de tabelas replicadas, o array contém os IDs das partições&#39; (um registro para cada partição). Para mutações de tabelas não replicadas, o array fica vazio.
* `block_numbers.number` ([Array(Int64)](/pt-BR/reference/data-types/array)) — Para mutações de tabelas replicadas, o array contém um registro para cada partição com o número do bloco adquirido pela mutação. Na partição, somente as partes que contêm blocos com números menores que esse serão alteradas. Em tabelas não replicadas, os números dos blocos em todas as partições formam uma única sequência. Isso significa que, para mutações de tabelas não replicadas, a coluna conterá um registro com um único número de bloco adquirido pela mutação.
* `parts_in_progress_names` ([Array(String)](/pt-BR/reference/data-types/array)) — Um array com os nomes das partes de dados que estão sendo alteradas no momento.
* `parts_to_do_names` ([Array(String)](/pt-BR/reference/data-types/array)) — Um array com os nomes das partes de dados que precisam ser alteradas para que a mutação seja concluída.
* `parts_to_do` ([Int64](/pt-BR/reference/data-types/int-uint)) — O número de partes de dados que precisam ser alteradas para que a mutação seja concluída. Observação: mesmo que `parts_to_do` = 0, uma mutação de tabela replicada pode ainda não ter sido concluída devido a um INSERT de longa duração que está criando uma nova parte de dados que precisará ser alterada.
* `parts_postpone_reasons` ([Map(String, String)](/pt-BR/reference/data-types/map)) — Um map que associa nomes de partes aos motivos pelos quais foram adiadas.
* `is_done` ([UInt8](/pt-BR/reference/data-types/int-uint)) — O sinalizador que indica se a mutação foi concluída. Valores possíveis: 1 se a mutação foi concluída; 0 se a mutação ainda está em andamento.
* `is_killed` ([UInt8](/pt-BR/reference/data-types/int-uint)) — Indica se uma mutação foi interrompida. Disponível apenas no ClickHouse Cloud. Observação: is&#95;killed=1 não significa necessariamente que a mutação tenha sido totalmente finalizada. É possível que uma mutação permaneça por um período prolongado em um estado em que is&#95;killed=1 e is&#95;done=0. Isso pode ocorrer se outra mutação de longa duração estiver bloqueando a mutação interrompida. Essa é uma situação normal.
* `latest_failed_part` ([String](/pt-BR/reference/data-types/string)) — O nome da parte mais recente que não pôde ser alterada.
* `latest_fail_time` ([DateTime](/pt-BR/reference/data-types/datetime)) — A data e a hora da falha mais recente ao alterar uma parte.
* `latest_fail_reason` ([String](/pt-BR/reference/data-types/string)) — A mensagem de exceção que causou a falha mais recente ao alterar uma parte.
* `latest_fail_error_code_name` ([String](/pt-BR/reference/data-types/string)) — O código de erro da exceção que causou a falha mais recente ao alterar uma parte.

{/*AUTOGENERATED_END*/}

<Note>
  * Se o nome de uma parte não estiver em `parts_postpone_reasons` e ela ainda não tiver sido alterada, isso significa que a parte ainda não foi agendada para mutação.
  * O nome da parte `all_parts` representa todas as partes que ainda não foram alteradas.
</Note>

* `is_killed` ([UInt8](/pt-BR/reference/data-types/int-uint)) — Indica se uma mutação foi interrompida. **Disponível apenas no ClickHouse Cloud.**

<Note>
  `is_killed=1` não significa necessariamente que a mutação foi completamente finalizada. É possível que uma mutação permaneça em um estado em que `is_killed=1` e `is_done=0` por um período prolongado. Isso pode acontecer se outra mutação de longa duração estiver bloqueando a mutação interrompida. Essa é uma situação normal.
</Note>

* `is_done` ([UInt8](/pt-BR/reference/data-types/int-uint)) — O sinalizador que indica se a mutação foi concluída ou não. Valores possíveis:
  * `1` se a mutação foi concluída,
  * `0` se a mutação ainda está em andamento.

<Note>
  Mesmo se `parts_to_do = 0`, é possível que uma mutação em uma tabela replicada ainda não tenha sido concluída devido a uma consulta `INSERT` de longa duração, que criará uma nova parte de dados que precisará ser alterada.
</Note>

Se houve problemas ao alterar algumas partes de dados, as colunas a seguir contêm informações adicionais:

* `latest_failed_part` ([String](/pt-BR/reference/data-types/string)) — O nome da parte mais recente que não pôde ser alterada.
* `latest_fail_time` ([DateTime](/pt-BR/reference/data-types/datetime)) — A data e a hora da falha mais recente ao alterar uma parte.
* `latest_fail_reason` ([String](/pt-BR/reference/data-types/string)) — A mensagem de exceção que causou a falha mais recente ao alterar uma parte.

<div id="monitoring-mutations">
  ## Monitorando mutações
</div>

Para acompanhar o progresso na tabela `system.mutations`, use a seguinte consulta:

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- ou

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

Observação: isso exige permissões de leitura nas tabelas `system.*`.

<Tip>
  **Uso no Cloud**

  No ClickHouse Cloud, a tabela `system.mutations` em cada nó contém todas as mutações do cluster, e não há necessidade de `clusterAllReplicas`.
</Tip>
