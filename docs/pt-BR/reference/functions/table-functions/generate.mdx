Gera dados aleatórios com um schema especificado.
Permite preencher tabelas de teste com esses dados.
Há suporte para todos os tipos de dados que podem ser armazenados em uma tabela, incluindo `JSON`, `Dynamic`, `Variant`, `BFloat16`, `Time` e `Time64`.
Não há suporte para os tipos `AggregateFunction`, `Interval`, `Nothing` e `QBit`.

## Sintaxe {#syntax}

```sql
generateRandom(['name TypeName[, name TypeName]...', [, 'random_seed'[, 'max_string_length'[, 'max_array_length']]]][, SETTINGS setting = value[, ...]])
```

## Argumentos {#arguments}

| Argumento           | Descrição                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `name`              | Nome da coluna correspondente.                                                                                        |
| `TypeName`          | Tipo da coluna correspondente.                                                                                        |
| `random_seed`       | Defina manualmente a semente aleatória para gerar resultados estáveis. Se `NULL` — a semente é gerada aleatoriamente. |
| `max_string_length` | Comprimento máximo de todas as strings geradas. O padrão é `10`.                                                      |
| `max_array_length`  | Número máximo de elementos de todos os arrays ou maps gerados. O padrão é `10`.                                       |

## Configurações {#settings}

`SETTINGS` é o último argumento da chamada e controla como são gerados os valores `Nullable`, `Variant`, `Dynamic` e `JSON`.

| Configuração               | Tipo     | Padrão   | Descrição                                                                                                                                                                                                                                                |
| -------------------------- | -------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `null_ratio`               | `Float`  | `0.0625` | Probabilidade de um valor `Nullable`, `Variant` ou `Dynamic` ser `NULL` e probabilidade inicial de uma chave `JSON` estar ausente de uma linha — uma minoria das chaves esparsas fica ausente com frequência várias vezes maior. Deve estar em `[0, 1]`. |
| `max_json_depth`           | `UInt64` | `3`      | Profundidade máxima de aninhamento dos objetos `JSON` gerados: `1` significa objetos sem aninhamento; objetos dentro de arrays contam como um nível. Deve estar em `[1, 32]`.                                                                            |
| `max_json_keys_per_object` | `UInt64` | `8`      | Número máximo de chaves geradas em um nível de um objeto `JSON`; o objeto raiz recebe pelo menos metade desse número. `0` significa que apenas caminhos tipados são gerados. No máximo `1000`.                                                           |

```sql
SELECT * FROM generateRandom('x JSON', 3, 4, 2, SETTINGS max_json_depth = 1, max_json_keys_per_object = 3) LIMIT 3 FORMAT JSONEachRow;
```

```text
{"x":{"cursor":"","id":[],"parent":-3723905664592977020}}
{"x":{"cursor":"","id":[7037090064212902336]}}
{"x":{"id":[287913403506346525],"parent":-4417942528676528098}}
```

`SETTINGS` também pode ser o único argumento, preservando a estrutura da tabela de inserção:

```sql
INSERT INTO test_table SELECT * FROM generateRandom(SETTINGS null_ratio = 0.5) LIMIT 10;
```

## Valor retornado {#returned-value}

Um objeto de tabela com o esquema solicitado.

## Gerando JSON {#generating-json}

Uma coluna `JSON` gerada se comporta como um fluxo de documentos com o mesmo schema: o conjunto de chaves e o tipo
de cada chave são determinados pela semente aleatória e permanecem iguais em toda a coluna, enquanto os valores,
as chaves ausentes e os tamanhos dos arrays variam de uma linha para outra. A profundidade dos objetos é limitada por
`max_json_depth`, o número de chaves por nível por `max_json_keys_per_object`, e cada chave tem uma probabilidade
`null_ratio` de estar ausente em uma linha. Os valores nas folhas assumem os tipos que o parser de JSON infere em documentos
reais: `Int64`, `UInt64`, `Float64`, `Bool`, `String`, `Date`, `DateTime`, arrays desses tipos, arrays
de objetos e arrays mistos; algumas chaves têm um tipo diferente em uma pequena fração das linhas, como
acontece com dados coletados de uma aplicação.

A declaração de tipo determina o schema gerado: os caminhos tipados estão sempre presentes com o tipo
declarado, os caminhos excluídos por `SKIP` e `SKIP REGEXP` nunca são gerados, e os limites de `max_dynamic_paths` e
`max_dynamic_types` são respeitados. Assim, os caminhos que excedem `max_dynamic_paths` ficam nos dados compartilhados da
coluna.

```sql
SELECT * FROM generateRandom('x JSON', 1) LIMIT 3 FORMAT JSONEachRow;
```

```text
{"x":{"product_id":"2050-12-17 01:46:35","stage":"g|(&Ql","started":{"group":-80611897324989285}}}
{"x":{"product_id":"2013-10-17 22:35:26","stage":"^ipx|,=a5N","started":{"group":-1326235429680389454}}}
{"x":{"product_id":"1974-11-17 22:22:46","stage":"(U]p'l`","started":{"group":-344141642787805595}}}
```

A definição da estrutura também pode ficar a cargo da tabela de inserção, o que é útil para preencher uma tabela com
colunas dos tipos `JSON`, `Dynamic` ou `Variant`:

```sql
CREATE TABLE t (x JSON) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO t SELECT * FROM generateRandom() LIMIT 10;
```
