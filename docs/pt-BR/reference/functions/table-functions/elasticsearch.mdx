Permite executar consultas `SELECT` em documentos de um índice do [Elasticsearch](https://www.elastic.co/elasticsearch). Cada documento é retornado como uma linha: seu `_source` é exposto como uma única coluna do tipo [JSON](/pt-BR/reference/data-types/newjson), e o ID do documento e o nome do índice ficam disponíveis como colunas virtuais. A função é read-only.

## Sintaxe {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  A integração com o Elasticsearch é experimental. Para habilitá-la, use a configuração [`enable_elasticsearch`](/pt-BR/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## Argumentos {#arguments}

| Argumento      | Descrição                                                                                                                                                                                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | A URL base do cluster Elasticsearch, por exemplo, `https://localhost:9200`. Deve ser uma URL `http` ou `https` sem credenciais, string de consulta ou fragmento.                                                                                          |
| `index`        | O índice a ser lido. Também pode ser um alias, uma lista separada por vírgulas ou um pattern com wildcard, conforme aceito pela API de ponto no tempo do Elasticsearch. Um pattern que não corresponda a nenhum índice gera um erro.                      |
| `user`         | O nome de usuário para autenticação básica HTTP (opcional).                                                                                                                                                                                               |
| `password`     | A senha para autenticação básica HTTP (opcional; requer `user`).                                                                                                                                                                                          |
| `query('...')` | Um objeto [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) do Elasticsearch, em JSON, que seleciona os documentos a serem lidos (opcional). Deve vir após os argumentos posicionais. Padrão: `{"match_all": {}}`. |

Os argumentos `url`, `index`, `user` e `password` também podem ser informados no formato `key = value`. Os argumentos posicionais preenchem essas posições nessa ordem, e especificar um argumento tanto de forma posicional quanto como chave (ou a mesma chave duas vezes) gera um erro.

Os seguintes argumentos podem ser especificados no formato `key = value` (ou como chaves de uma coleção nomeada):

| Chave          | Descrição                                                                                                                                                                               |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | O nome de usuário para autenticação básica HTTP.                                                                                                                                        |
| `password`     | A senha para autenticação básica HTTP.                                                                                                                                                  |
| `bearer_token` | Um token enviado como `Authorization: Bearer <token>`, por exemplo, um token de service account do Elasticsearch.                                                                       |
| `api_key`      | Uma chave de API do Elasticsearch, enviada como `Authorization: ApiKey <api_key>`. O valor é a string `id:api_key` codificada em base64 retornada pela API de criação de chaves de API. |

Uma coleção nomeada pode conter a chave `query`. Para substituí-la, passe `query('...')` ou `query = '...'` após o nome da coleção.

Além disso, a função de tabela aceita:

| Chave       | Descrição                                                                                                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `structure` | A estrutura da tabela no formato `'name JSON'`. A estrutura deve conter exatamente uma coluna do tipo `JSON`; os nomes `_id` e `_index` são reservados. Padrão: `'document JSON'`. |

As configurações de leitura `keep_alive` e `page_size` podem ser passadas em uma cláusula `SETTINGS` no final da consulta; a descrição delas está disponível no [motor de tabela `Elasticsearch`](/pt-BR/reference/engines/table-engines/integrations/elasticsearch#creating-a-table).

## Autenticação {#authentication}

É possível fornecer no máximo um método de autenticação:

1. **Autenticação básica**. Informe `user` e `password`.
2. **Token Bearer**. Informe `bearer_token`.
3. **Chave de API**. Informe `api_key`.

Se nenhum deles for informado, a requisição é enviada de forma anônima, o que só funciona quando a segurança está desabilitada no Elasticsearch.

Armazene as credenciais em uma [coleção nomeada](/pt-BR/concepts/features/configuration/server-config/named-collections) para não precisar especificá-las em cada consulta. Uma tabela permanente criada a partir de uma coleção nomeada (com o motor de tabela `Elasticsearch` ou com `CREATE TABLE ... AS elasticsearch(...)`) é registrada como dependência da coleção, portanto o `DROP NAMED COLLECTION` fica bloqueado enquanto a tabela existir.

## Colunas virtuais {#virtual-columns}

* `_id` — O ID do documento. Tipo: `String`.
* `_index` — O nome do índice do qual o documento foi lido. Tipo: `LowCardinality(String)`.

Quando uma consulta lê apenas colunas virtuais, o `_source` do documento não é solicitado ao Elasticsearch. Um índice que não armazena `_source` (ou seja, cujo campo `_source` está desabilitado no mapeamento) só pode ser lido por meio das colunas virtuais: uma consulta que lê a coluna `JSON` de um índice assim falha com um erro, em vez de retornar documentos vazios.

## Exemplos {#examples}

Conte os documentos de um índice:

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

Leia os campos dos documentos como subcolunas da coluna `JSON`:

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

Filtre no lado do Elasticsearch com um objeto Query DSL e ajuste o tamanho da página:

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

Use uma coleção nomeada:

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## Limitações {#limitations}

* A função é read-only; `INSERT` não é suportado.
* Os predicados não são aplicados antecipadamente. Uma condição `WHERE` é aplicada no ClickHouse depois que os documentos são baixados; use o argumento `query` para filtrar no lado do Elasticsearch.
* A `query` é enviada com o `size` de uma página. Uma consulta cujo resultado depende de `size`, como uma consulta `knn` sem `k`, retorna um conjunto de documentos que depende de `page_size`. Especifique esses parâmetros explicitamente.
* Cada página é uma requisição de busca separada, e o Elasticsearch reavalia expressões de data como `now-1h` na `query` a cada requisição. O ponto no tempo congela os documentos, mas não o relógio; por isso, uma `query` dependente do tempo pode ignorar silenciosamente documentos próximos à fronteira móvel. Use datas absolutas na `query`.
* Cada leitura abre um ponto no tempo, percorre os resultados página a página com `search_after`, ordenados por `_shard_doc`, e encerra o ponto no tempo ao final. Uma requisição de página que falhe em qualquer shard, ou que exceda o tempo limite no Elasticsearch, lança um erro em vez de retornar resultados parciais.
* É necessário o Elasticsearch 7.12 ou posterior: a função depende da API de ponto no tempo e do campo de ordenação `_shard_doc`; por isso, versões mais antigas e o OpenSearch rejeitam a primeira requisição.
* `page_size` não pode exceder a configuração de índice `index.max_result_window` do Elasticsearch (`10000` por padrão).
