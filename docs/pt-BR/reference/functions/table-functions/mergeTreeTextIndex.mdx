Representa o dicionário de um índice de texto em tabelas MergeTree.
Retorna tokens com os metadados da posting list.
Pode ser usado para introspecção.

## Sintaxe {#syntax}

```sql
mergeTreeTextIndex(database, table, index_name)
```

## Argumentos {#arguments}

| Argumento    | Descrição                                               |
| ------------ | ------------------------------------------------------- |
| `database`   | O nome do banco de dados de onde ler o índice de texto. |
| `table`      | O nome da tabela de onde ler o índice de texto.         |
| `index_name` | O índice de texto a ser lido.                           |

## Valor retornado {#returned-value}

Um objeto de tabela contendo tokens e seus metadados de lista de postings.

Se o índice usar o tokenizador `keyValuePairs`, cada token será um par `(key, value)` de uma coluna `Map`, e o resultado terá duas colunas adicionais, `token_key` e `token_value`, com as partes decodificadas do token.

As listas de postings dos tokens são retornadas nas seguintes colunas virtuais. Elas não são retornadas por `SELECT *` e precisam ser selecionadas explicitamente.

| Coluna      | Tipo            | Descrição                                                                                                |
| ----------- | --------------- | -------------------------------------------------------------------------------------------------------- |
| `row_id`    | `UInt32`        | O número de uma linha da parte de dados (veja `_part_offset`) presente na lista de postings do token.    |
| `positions` | `Array(UInt32)` | As posições do token na linha. Existe somente se o índice tiver o argumento `support_phrase_search = 1`. |

Se qualquer uma dessas colunas for selecionada, o resultado terá uma linha para cada linha da lista de postings de cada token, de forma semelhante a um `ARRAY JOIN` da lista de postings: as demais colunas do token são repetidas em cada uma dessas linhas.

As listas de postings são retornadas exatamente como estão armazenadas no índice da parte de dados; portanto, incluem as linhas excluídas por `DELETE` leve (veja `_row_exists`) até que a parte seja mesclada.

## Exemplo de uso {#usage-example}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha)
)
ENGINE = MergeTree
ORDER BY id;

INSERT INTO tab SELECT number, concatWithSeparator(' ', 'apple', 'banana') FROM numbers(500);
INSERT INTO tab SELECT 500 + number, concatWithSeparator(' ', 'cherry', 'date') FROM numbers(500);

SELECT * FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s);
```

## Exemplo de uso: listas de postings {#usage-example-posting-lists}

```sql title="Query"
CREATE TABLE tab
(
    id UInt64,
    s String,
    INDEX idx_s (s) TYPE text(tokenizer = splitByNonAlpha, support_phrase_search = 1)
)
ENGINE = MergeTree
ORDER BY id
SETTINGS allow_experimental_text_index_phrase_search = 1;

INSERT INTO tab VALUES (0, 'apple banana apple'), (1, 'banana cherry'), (2, 'cherry apple');

SELECT token, row_id, positions FROM mergeTreeTextIndex(currentDatabase(), tab, idx_s) ORDER BY token, row_id;
```

```text title="Response"
   ┌─token──┬─row_id─┬─positions─┐
1. │ apple  │      0 │ [0,2]     │
2. │ apple  │      2 │ [1]       │
3. │ banana │      0 │ [1]       │
4. │ banana │      1 │ [0]       │
5. │ cherry │      1 │ [1]       │
6. │ cherry │      2 │ [0]       │
   └────────┴────────┴───────────┘
```
