## evalMLMethod {#evalmlmethod}

A previsão com modelos de regressão ajustados usa a função `evalMLMethod`. Veja o link em `linearRegression`.

## stochasticLinearRegression {#stochasticlinearregression}

A função de agregação [stochasticLinearRegression](/pt-BR/reference/functions/aggregate-functions/stochasticLinearRegression) implementa o método de descida estocástica do gradiente usando um modelo linear e a função de perda MSE. Usa `evalMLMethod` para fazer previsões em novos dados.

A função de agregação [stochasticLogisticRegression](/pt-BR/reference/functions/aggregate-functions/stochasticLogisticRegression) implementa o método de descida estocástica do gradiente para o problema de classificação binária. Usa `evalMLMethod` para fazer previsões com novos dados.

## assignCentroid {#assignCentroid}

Introduzido em: v26.8.0

Retorna o id do centróide mais próximo (L2) de um vetor. Os centróides são fornecidos como uma matriz constante de matrizes de números de ponto flutuante, em que o id é a posição, começando em 0, nessa matriz, ou como o nome de um `Dicionário` que contém os atributos `cid` e `vec`, em que o id é `cid`.

<Note>
  Esta função não é determinística: pode retornar resultados diferentes para os mesmos argumentos.
</Note>

**Sintaxe**

```sql
assignCentroid(vec, centroids | dict_name)
```

**Argumentos**

* `vec` — Vetor a ser atribuído. Sua dimensão deve corresponder à dimensão dos centroides. Tipos diferentes de `Float32` são convertidos para `Float32`, que é o tipo usado pelo kernel de pontuação. [`Array(Float32)`](/pt-BR/reference/data-types/array) ou [`Array(Float64)`](/pt-BR/reference/data-types/array) ou [`Array(BFloat16)`](/pt-BR/reference/data-types/array)
* `centroids` — Os centroides em relação aos quais a pontuação é calculada, que devem ser constantes. Podem ser fornecidos como um array de arrays de números de ponto flutuante não vazios e de mesmo tamanho; nesse caso, o id é a posição baseada em 0 nesse array. Também podem ser fornecidos como o nome de um `Dicionário` com um atributo `cid` de tipo inteiro sem sinal compatível com `UInt32` e um atributo `vec` do tipo `Array(Float32)`; nesse caso, o id é `cid`. O dicionário é lido uma vez e armazenado em cache até ser recarregado. [`Array(Array(Float32))`](/pt-BR/reference/data-types/array) ou [`Array(Array(Float64))`](/pt-BR/reference/data-types/array) ou [`Array(Array(BFloat16))`](/pt-BR/reference/data-types/array) ou [`String`](/pt-BR/reference/data-types/string)

**Valor retornado**

O id do centroide mais próximo. [`UInt32`](/pt-BR/reference/data-types/int-uint)

**Exemplos**

**Centroides inline**

```sql title=Query
SELECT assignCentroid([1.0, 2.0]::Array(Float32), [[0.0, 0.0], [1.0, 2.0]]::Array(Array(Float32)))
```

```response title=Response
1
```

## evalMLMethod {#evalMLMethod}

Introduzido em: v20.1.0

Aplica um modelo de machine learning treinado às features de entrada para gerar previsões.

**Sintaxe**

```sql
evalMLMethod(model, x1[, x2, ...])
```

**Argumentos**

* `model` — O modelo de machine learning treinado. [`AggregateFunctionState`](/pt-BR/reference/data-types/aggregatefunction)
* `x1, x2, ...` — Valores das características para a predição. [`Float*`](/pt-BR/reference/data-types/float) ou [`(U)Int*`](/pt-BR/reference/data-types/int-uint)

**Valor retornado**

Retorna o valor previsto com base no modelo treinado. [`Float64`](/pt-BR/reference/data-types/float)

**Exemplos**

**Exemplo de uso**

```sql title=Query
CREATE TABLE trips (pickup_datetime DateTime('UTC'), trip_distance Float64, total_amount Float64) ENGINE = Memory;

-- A fare of 3, plus 2.5 for every unit of distance.
INSERT INTO trips
SELECT toDateTime('2020-01-01 00:00:00', 'UTC') + number * 60, number % 10 + 1, 2.5 * (number % 10 + 1) + 3
FROM numbers(1000);

-- One model per year of the data.
CREATE TABLE models ENGINE = Memory AS
SELECT
    toYear(pickup_datetime) AS year,
    stochasticLinearRegressionState(0.01, 0.0, 10, 'SGD')(total_amount, trip_distance) AS model
FROM trips
GROUP BY year;

SELECT
    trip_distance,
    round(evalMLMethod(model, trip_distance), 2) AS predicted,
    total_amount
FROM trips
LEFT JOIN models ON year = toYear(pickup_datetime)
ORDER BY pickup_datetime
LIMIT 5
```

```response title=Response
┌─trip_distance─┬─predicted─┬─total_amount─┐
│             1 │      4.05 │          5.5 │
│             2 │      6.79 │            8 │
│             3 │      9.53 │         10.5 │
│             4 │     12.28 │           13 │
│             5 │     15.02 │         15.5 │
└───────────────┴───────────┴──────────────┘
```

## naiveBayesClassifier {#naiveBayesClassifier}

Introduzido em: v25.11.0

Classifica o texto de entrada usando um [`NAIVE_BAYES`](/pt-BR/reference/statements/create/dictionary/layouts/naive-bayes) Dicionário. Retorna o mesmo valor de classe previsto por `dictGet(dictionary_name, class_attribute, input_text)`, em que class&#95;attribute é o nome do atributo do rótulo de classe configurado no [layout](/pt-BR/reference/statements/create/dictionary/layouts/naive-bayes#layout-parameters) do dicionário. Diferentemente de `dictGet`, o tipo do resultado é sempre `UInt32`, em vez do tipo declarado do atributo de classe, e `input_text` deve ser uma `String` (nenhuma conversão do tipo de chave é aplicada).

<Note>
  Esta função é não determinística: pode retornar resultados diferentes para os mesmos argumentos.
</Note>

**Sintaxe**

```sql
naiveBayesClassifier(dictionary_name, input_text)
```

**Argumentos**

* `dictionary_name` — Nome de um dicionário com o layout NAIVE&#95;BAYES. [`String`](/pt-BR/reference/data-types/string)
* `input_text` — Texto a ser classificado. [`String`](/pt-BR/reference/data-types/string)

**Valor retornado**

ID da classe prevista. [`UInt32`](/pt-BR/reference/data-types/int-uint)

**Exemplos**

**Classificação de texto**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT naiveBayesClassifier('sentiment', 'a good and great film') AS class_id;
```

```response title=Response
┌─class_id─┐
│        0 │
└──────────┘
```

## naiveBayesClassifierWithAllProbs {#naiveBayesClassifierWithAllProbs}

Introduzido em: v26.7.0

Classifica o texto de entrada usando um dicionário [`NAIVE_BAYES`](/pt-BR/reference/statements/create/dictionary/layouts/naive-bayes) e retorna todas as classes com suas probabilidades, em ordem da mais provável para a menos provável.

<Note>
  Esta função é não determinística: pode retornar resultados diferentes para os mesmos argumentos.
</Note>

**Sintaxe**

```sql
naiveBayesClassifierWithAllProbs(dictionary_name, input_text)
```

**Argumentos**

* `dictionary_name` — Nome de um dicionário com o layout NAIVE&#95;BAYES. [`String`](/pt-BR/reference/data-types/string)
* `input_text` — Texto a ser classificado. [`String`](/pt-BR/reference/data-types/string)

**Valor retornado**

Array de tuplas `(class&#95;id, probability)` ordenadas da mais provável para a menos provável. [`Array(Tuple(UInt32, Float64))`](/pt-BR/reference/data-types/array)

**Exemplos**

**Todas as probabilidades de classe**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT arrayMap(p -> (p.1, round(p.2, 4)), naiveBayesClassifierWithAllProbs('sentiment', 'a good and great film')) AS predictions;
```

```response title=Response
┌─predictions─────────────┐
│ [(0,0.9677),(1,0.0323)] │
└─────────────────────────┘
```

## predictXGBoost {#predictXGBoost}

Introduzido em: v26.10.0

Prevê um valor numérico de destino para um vetor de características usando um dicionário [`XGBOOST`](/pt-BR/reference/statements/create/dictionary/layouts/xgboost). As características são passadas por posição, na ordem em que as colunas de chave do dicionário foram declaradas. Esta é a única forma de consultar um dicionário `XGBOOST`: ele armazena um modelo treinado, e não linhas, por isso a interface genérica de dicionário (`dictGet`, `dictHas`, `SELECT * FROM dict`) não é suportada. A integração com o XGBoost é experimental, portanto a configuração `enable_xgboost` precisa estar habilitada.

**Sintaxe**

```sql
predictXGBoost(dictionary_name, feature1[, feature2, ...][, params])
```

**Argumentos**

* `dictionary_name` — Nome de um dicionário com o layout XGBOOST. Consulte o [layout de dicionário XGBOOST](/pt-BR/reference/statements/create/dictionary/layouts/xgboost) para saber como criá-lo e quais parâmetros de treinamento ele aceita. [`String`](/pt-BR/reference/data-types/string)
* `featureN` — Valores numéricos das características, em posição correspondente à ordem das chaves do dicionário. Uma característica NULL é passada ao modelo como valor ausente, que o XGBoost trata conforme foi treinado; assim, a predição nunca é NULL. [`(U)Int*`](/pt-BR/reference/data-types/int-uint) ou [`Float*`](/pt-BR/reference/data-types/float) ou [`Nullable((U)Int*)`](/pt-BR/reference/data-types/nullable) ou [`Nullable(Float*)`](/pt-BR/reference/data-types/nullable)
* `params` — Map constante opcional de parâmetros de predição do XGBoost, que associa o nome de cada parâmetro a um valor inteiro, por exemplo, `map('type', 0, 'iteration_end', 0)`. Todos os parâmetros aceitos são inteiros ou booleanos; por isso, valores fracionários são rejeitados. Consulte [parâmetros de predição](/pt-BR/reference/statements/create/dictionary/layouts/xgboost#prediction-parameters) para ver as chaves aceitas. [`Map(String, (U)Int8/16/32/64)`](/pt-BR/reference/data-types/map)

**Valor retornado**

A predição do modelo como Float64, uma por linha. [`Float64`](/pt-BR/reference/data-types/float)

**Exemplos**

**Predição**

```sql title=Query
-- A model trained on the linear target y = 2 * x1 + 3 * x2. The XGBoost integration is experimental.
SET enable_xgboost = 1;

CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO training_data SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y FROM numbers(100);

CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(objective 'reg:squarederror' num_iterations 100 max_depth 6))
LIFETIME(0);

-- The ground truth is 2 * 1 + 3 * 2 = 8.
SELECT round(predictXGBoost('model', 1.0, 2.0), 1) AS prediction;
```

```response title=Response
┌─prediction─┐
│          8 │
└────────────┘
```

**Previsão com parâmetros**

```sql title=Query
-- The raw margin of the model above, before the objective's transformation. For `reg:squarederror` it is the
-- prediction itself, while for `binary:logistic` it is the log-odds rather than the probability.
SELECT round(predictXGBoost('model', 1.0, 2.0, map('type', 1)), 1) AS margin;
```

```response title=Response
┌─margin─┐
│      8 │
└────────┘
```
