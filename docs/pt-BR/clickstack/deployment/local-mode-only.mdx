Semelhante à [imagem all-in-one](/pt-BR/clickstack/deployment/all-in-one), esta imagem Docker completa reúne todos os componentes do ClickStack:

* **ClickHouse**
* **Interface do ClickStack**
* **collector do OpenTelemetry (OTel)** (expondo OTLP nas portas `4317` e `4318`)
* **MongoDB** (para o estado persistente da aplicação)

**No entanto, a autenticação de usuários está desabilitada para esta distribuição da Interface do ClickStack**

<div id="suitable-for">
  ### Indicado para {#suitable-for}
</div>

* Demonstrações
* Depuração
* Desenvolvimento em que a Interface do ClickStack é usada

## Etapas de implantação {#deployment-steps}

<br />

<Steps>
  <Step title="Implantar com Docker" id="deploy-with-docker">
    O modo local implanta a Interface do ClickStack na porta 8080.

    ```shell
    docker run -p 8080:8080 clickhouse/clickstack-local:latest
    ```
  </Step>

  <Step title="Acessar a Interface do ClickStack" id="navigate-to-hyperdx-ui">
    Acesse [http://localhost:8080](http://localhost:8080) para abrir a Interface do ClickStack.

    **Você não precisará criar um usuário, pois a autenticação não está habilitada neste modo de implantação.**

    Conecte-se ao seu próprio cluster ClickHouse externo, como o ClickHouse Cloud.

    <div className="ch-image-md">
      <Frame>
        ![Criar login](/images/use-cases/observability/hyperdx-2.webp)
      </Frame>
    </div>

    Crie uma fonte de dados, mantenha todos os valores default e preencha o campo `Table` com o valor `otel_logs`. As demais configurações devem ser detectadas automaticamente, e você poderá clicar em `Save New Source`.

    <div className="ch-image-md">
      <Frame>
        ![Criar fonte de logs](/images/use-cases/observability/hyperdx-logs.webp)
      </Frame>
    </div>
  </Step>
</Steps>
