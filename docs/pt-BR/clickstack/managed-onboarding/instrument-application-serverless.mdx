<Info>
  **Resumo**

  Execute uma pequena aplicação de demonstração, instrumente-a com o prompt de IA da página Primeiros Passos do seu serviço ou com duas edições manuais e acompanhe a chegada de logs, rastros e métricas ao ClickHouse Observability.

  Tempo necessário: cerca de 10 minutos
</Info>

Você já criou seu serviço do ClickHouse Observability. Este guia mostra como sair desse serviço vazio e passar a receber telemetria de uma aplicação em execução.

O ClickHouse Observability oferece um endpoint OpenTelemetry gerenciado, para o qual sua aplicação envia a telemetria diretamente. Não é preciso executar um coletor, criar um schema nem dimensionar um banco de dados. A ingestão, os esquemas, o armazenamento, a otimização e o escalonamento ficam por nossa conta.

## A aplicação de demonstração {#the-demo-application}

Para que você tenha algo realista para instrumentar, este guia usa o [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), uma aplicação de demonstração que disponibilizamos exatamente para essa finalidade. Trata-se de uma pequena aplicação em Node.js e TypeScript que consulta o dataset do HackerNews hospedado na demonstração pública do ClickHouse. Cada gráfico, tabela e caixa de busca é alimentado por uma requisição real ao backend. As requisições que não encontram resultado no cache da aplicação também consultam o ClickHouse, o que adiciona um span HTTPS de saída a cada trace.

A demonstração está disponível em duas variantes:

* **Não instrumentada**, no branch `main`. Neste guia, você mesmo adiciona a instrumentação, seja com um agente de IA ou manualmente, sem alterar a regra de negócio da aplicação. As mesmas etapas se aplicam aos seus próprios serviços.
* **Pré-instrumentada**, no branch `instrumented`. Faça o checkout deste branch se quiser apenas ver a telemetria fluindo rapidamente e explorar a UI.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability. Se você ainda não tiver um, siga o [Guia de primeiros passos](/pt-BR/clickstack/observability/getting-started).
* Node.js 18 ou superior e npm.
* Acesso de rede ao endpoint de telemetria do seu serviço, tanto da máquina que executa a demonstração quanto do seu navegador.

### Aponte a demonstração para o seu serviço {#configure-environment}

        Abra o arquivo `.env` e defina os valores a seguir, substituindo o endpoint e a chave de API pelos valores exibidos na caixa de diálogo:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Estas são variáveis padrão do exportador do OpenTelemetry. Nada fica fixo no código-fonte da aplicação.

        Mantenha o prefixo `https://` em `OTEL_EXPORTER_OTLP_ENDPOINT` e não acrescente `/v1/logs`, `/v1/traces` ou `/v1/metrics`. Os SDKs adicionam os caminhos de cada sinal. Defina `OTEL_EXPORTER_OTLP_HEADERS` como `authorization=<your-api-key>`, sem o prefixo `Bearer`.

        A partir daí, a instrumentação tem três partes: instalar o SDK, trocar o comando de inicialização e habilitar o SDK do navegador. Nenhuma delas altera a regra de negócio da aplicação.

### Instale o SDK do Node {#install-node-sdk}

        ```bash
        npm install @hyperdx/node-opentelemetry
        ```

### Habilite o contêiner no run.sh {#enable-run-sh-wrapper}

        No final do `run.sh` há duas linhas `exec`. Comente a linha que executa apenas `node` e descomente a linha instrumentada:

        ```diff
         # BEFORE: plain node, no instrumentation:
        -exec node scripts/entrypoint.js
        +# exec node scripts/entrypoint.js

         # AFTER: same source, wrapped by opentelemetry-instrument:
        -# exec npx opentelemetry-instrument scripts/entrypoint.js
        +exec npx opentelemetry-instrument scripts/entrypoint.js
        ```

        Continue iniciando a aplicação por meio de `scripts/entrypoint.js`. Esse shim chama `require('console')` para que a captura do console envolva o `console.log`. Apontar o `opentelemetry-instrument` diretamente para `dist/server/index.js` envia os rastros, mas descarta os logs silenciosamente.

### Habilitar o SDK do navegador {#enable-browser-sdk}

        ```bash
        npm install @hyperdx/browser
        ```

        Em `src/web/telemetry.ts`, descomente o import, o bloco `HyperDX.init` e `HyperDX.addAction` em `recordAction`:

        ```diff
        -// import HyperDX from '@hyperdx/browser';
        +import HyperDX from '@hyperdx/browser';

         export function initTelemetry(): void {
        -  // HyperDX.init({
        -  //   url: __OTLP_ENDPOINT__,
        -  //   apiKey: __OTLP_AUTH_TOKEN__,
        -  //   service: 'hn-analyzer-web',
        -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        -  //   consoleCapture: true,
        -  //   advancedNetworkCapture: true,
        -  // });
        +  HyperDX.init({
        +    url: __OTLP_ENDPOINT__,
        +    apiKey: __OTLP_AUTH_TOKEN__,
        +    service: 'hn-analyzer-web',
        +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        +    consoleCapture: true,
        +    advancedNetworkCapture: true,
        +  });
         }
        ```

        `__OTLP_ENDPOINT__` e `__OTLP_AUTH_TOKEN__` são constantes de tempo de compilação injetadas pelo `vite.config.ts` a partir dos mesmos valores `OTEL_EXPORTER_OTLP_*` usados pelo backend.

        <Warning>
          O SDK do navegador incorpora o endpoint e a chave de API no bundle do navegador, onde qualquer pessoa que inspecione a aba Rede pode vê-los. Use um serviço destinado a testes e mantenha o `.env` fora do controle de versão.
        </Warning>

        Execute a demonstração novamente com `./run.sh`.
      </Tab>

## Se nada aparecer {#if-nothing-shows-up}

* Verifique os valores em `.env`. O endpoint deve começar com `https://`, terminar com a porta `4318` e não ter o sufixo `/v1/...`. A chave de API deve ser o valor completo, que você pode copiar depois de selecionar **Reveal key**.
* Se você seguiu o caminho manual, confirme que `OTEL_EXPORTER_OTLP_HEADERS` está definido como `authorization=<your-api-key>`, sem o prefixo `Bearer`, e que o banner de inicialização exibe as três linhas `Health check passed`.
* Confirme que você reiniciou a demonstração depois de instrumentá-la e que recarregou a aba do navegador. A reprodução de sessão só começa quando o pacote instrumentado passa a ser servido.
* Amplie o intervalo de tempo em **Busca** e remova todos os filtros. A fonte de dados padrão pode estar definida como **Traces** em vez de **Logs**.
* Para descartar um problema no próprio serviço, acesse **Team Settings → Telemetria Gerenciada** e use **Send a Test Log**. Se esse log aparecer em **Busca**, o serviço está recebendo dados e o problema está na configuração da demonstração.

## Próximos passos {#next-steps}

Seu serviço agora contém telemetria de uma aplicação real. Para instrumentar seus próprios serviços, reutilize o prompt **Instrumentar com IA** do seu serviço ou use os [SDKs de linguagem compatíveis](/pt-BR/clickstack/observability/ingesting-data/sdks/index) com o mesmo endpoint e a mesma chave de API.

Para coletar dados da infraestrutura em vez do código da aplicação:

* [Monitoramento do Kubernetes](/pt-BR/clickstack/observability/example-datasets/kubernetes): colete logs e métricas do cluster e explore o Painel do Kubernetes.
* [Logs e métricas locais](/pt-BR/clickstack/observability/example-datasets/local-data): colete arquivos locais e métricas do sistema no MacOS ou no Linux.

Para explorar mais recursos da UI:

* [Busca](/pt-BR/clickstack/observability/features/search): consulte logs e rastros com sintaxe no estilo Lucene ou com SQL.
* [Reprodução de sessão](/pt-BR/clickstack/observability/features/session-replay): visão geral da funcionalidade, opções do SDK e controles de privacidade.
* [Conjuntos de dados de exemplo](/pt-BR/clickstack/observability/example-datasets): conjuntos de dados mais completos e investigações guiadas.
