<Note>
  **Você está no caminho autogerenciado**

  Você optou por configurar o ClickHouse Observability por conta própria, usando a [experiência autogerenciada](/pt-BR/clickstack/self-configured/overview). Neste caminho, você executa o coletor OpenTelemetry, gerencia a ingestão no seu serviço do ClickHouse Cloud, ajusta o schema e separa as cargas de trabalho de ingestão e de consulta usando warehouses. Consulte [Coletor OpenTelemetry](/pt-BR/clickstack/self-configured/ingesting-data/collector), [Ajuste de desempenho](/pt-BR/clickstack/self-configured/managing/performance-tuning) e [Isolando cargas de trabalho de leitura e gravação](/pt-BR/clickstack/self-configured/managing/isolating-read-write).

  Prefere uma experiência serverless, em que o ClickHouse cuida da ingestão, dos esquemas e da capacidade computacional para você? Nesse caso, use a experiência padrão do ClickHouse Observability e siga o guia [Instrumente sua aplicação com OpenTelemetry](/pt-BR/clickstack/managed-onboarding/instrument-application-serverless).
</Note>

Este guia mostra como instrumentar uma pequena aplicação Node.js com OpenTelemetry e enviar seus logs, métricas, rastros e reproduções de sessão para o ClickHouse Observability por meio do coletor que você executa. O backend é instrumentado sem nenhuma alteração no código-fonte da aplicação.

O [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) é uma aplicação Node.js que consulta o dataset do HackerNews hospedado na demonstração pública do ClickHouse. Cada gráfico, tabela e caixa de pesquisa é alimentado por uma consulta real ao ClickHouse, de modo que cada interação gera um rastro cujo span principal é a chamada HTTPS do backend para o ClickHouse.

Este guia pressupõe que você já concluiu [Configurando seu OpenTelemetry Collector](/pt-BR/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) e que tem um coletor do ClickStack em execução e acessível a partir da máquina em que você executa esta aplicação. **Certifique-se de ter anotado o endpoint OTLP dele** e o `OTLP_AUTH_TOKEN` que você definiu ao implantá-lo. Você vai inserir esses valores no `.env` antes de instrumentar.

## Pré-requisitos {#prerequisites}

* Um coletor do ClickStack acessível a partir desta máquina. Se você ainda não implantou um, siga primeiro [Configurando seu OpenTelemetry Collector](/pt-BR/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector).
* O endpoint OTLP/HTTP desse coletor (geralmente na porta `4318`) e o `OTLP_AUTH_TOKEN` configurado nele. Use-os como `OTEL_EXPORTER_OTLP_ENDPOINT` e `OTEL_EXPORTER_OTLP_HEADERS=authorization=<token>`.
* Node 18+ e npm.

## Clone o repositório {#clone-the-repository}

Clone o [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), instale as dependências e copie o modelo de arquivo de ambiente:

```bash
git clone https://github.com/ClickHouse/hn-news-analyzer.git
cd hn-news-analyzer
npm install
cp .env.example .env
```

Você preencherá o `.env` nas próximas etapas e, em seguida, instrumentará a aplicação a partir deste diretório.
