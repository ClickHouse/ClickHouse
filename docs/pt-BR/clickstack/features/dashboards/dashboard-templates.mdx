O ClickStack inclui uma biblioteca de templates de dashboards pré-configurados que oferecem visibilidade imediata de métricas comuns de infraestrutura e aplicações.

## Navegando pelos templates disponíveis {#browsing-templates}

Para navegar pela biblioteca integrada de templates, vá para **Dashboards** e clique em **Explorar templates de dashboard**.

<div className="ch-image-lg">
  <Frame>
    ![Botão Explorar templates de dashboard](/images/use-cases/observability/browse-dashboard-template.webp)
  </Frame>
</div>

Isso abre a galeria de templates, onde os templates são organizados por categoria. Clique em **Importar** para iniciar o fluxo de importação desse template.

<div className="ch-image-lg">
  <Frame>
    ![Galeria de templates de dashboard](/images/use-cases/observability/dashboard-template-gallery.webp)
  </Frame>
</div>

## Importando um template {#importing-a-template}

Para importar um template, é preciso definir uma fonte de dados para cada visualização do dashboard. Selecione uma fonte de dados no menu suspenso de cada visualização e clique em `Finish Import`.

<div className="ch-image-lg">
  <Frame>
    ![Importação de template de dashboard](/images/use-cases/observability/import-dashboard-template.webp)
  </Frame>
</div>

### Métricas de Runtime do OTel {#otel-runtime-metrics}

Os templates integrados de Métricas de Runtime do OTel foram projetados para aplicações instrumentadas com [métricas de tempo de execução do OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/runtime/).

| Template                    | Descrição                                                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **.NET Runtime Metrics**    | Coletas de GC, tamanho do heap, uso do pool de threads e contagens de assemblies para aplicações .NET                  |
| **Go Runtime Metrics**      | Contagens de goroutines, tempos de pausa do GC, uso do heap e estatísticas de memória para aplicações Go               |
| **JVM Runtime Metrics**     | Memória heap e não heap, duração do GC, contagens de threads e carregamento de classes para aplicações baseadas em JVM |
| **Node.js Runtime Metrics** | Atraso do event loop, uso do heap, utilização de CPU e memória do V8 para aplicações Node.js                           |

Observações:

* Cada template é configurado com um [filtro personalizado](/pt-BR/clickstack/features/dashboards/overview#custom-filters) para serviços cujo atributo de recurso [`telemetry.sdk.language`](https://opentelemetry.io/docs/specs/semconv/registry/attributes/telemetry/#telemetry-sdk-language) corresponde ao tempo de execução do dashboard.
  * Em ambientes com esquemas personalizados de tabelas de métricas do ClickHouse, talvez seja necessário ajustar esse filtro para consultar as colunas corretas de nome do serviço e de atributos de recurso.
  * Em ambientes de alto volume, é possível reduzir o tempo de carregamento do filtro [materializando](/pt-BR/clickstack/managing/performance-tuning#materialize-frequently-queried-attributes) a coluna `ResourceAttributes['telemetry.sdk.language']`.
* Os templates seguem as Convenções Semânticas do OTel vigentes no momento da publicação e são atualizados periodicamente conforme a especificação do OTel evolui. Para serviços instrumentados com SDKs do OTel mais antigos, pode ser necessário [editar](/pt-BR/clickstack/features/dashboards/overview#dashboards-editing-visualizations) as visualizações para usar nomes de métricas mais antigos.
