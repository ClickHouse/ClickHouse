Para funções Node.js com manipuladores assíncronos, use o SDK Node.js do ClickStack. Para outros tempos de execução ou manipuladores baseados em callbacks, use as camadas Lambda do OpenTelemetry descritas a seguir.

## Manipuladores assíncronos em Node.js {#nodejs-async-handlers}

Use um tempo de execução Node.js do Lambda que atenda ao requisito mínimo do SDK, o Node.js 22.15. Instale o SDK e inclua-o no seu pacote de implantação:

```shell
npm install @clickhouse/clickstack-node
```

Defina estas variáveis de ambiente do Lambda para inicializar o SDK antes do carregamento do seu manipulador e para nomear o seu serviço:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

Envolva seu manipulador assíncrono com `withFlush` para que a telemetria armazenada em buffer seja exportada antes que a invocação retorne:

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

Defina o manipulador da função como `index.handler`. Se você empacotar a função em um bundle, mantenha o SDK e as dependências instrumentadas como externos e inclua-os no pacote de implantação. Não habilite também uma camada Lambda de instrumentação automática nesta configuração.

Defina as variáveis de destino abaixo na configuração de ambiente da função Lambda. O endpoint deve estar acessível a partir da sua função. O SDK conclui o flush antes do prazo da invocação; manipuladores baseados em callback não são suportados por `withFlush`.

### Configure o destino {#configure-destination}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra **Team Settings → Dados → Telemetria Gerenciada** no seu serviço e copie o **endpoint OTLP HTTP** e a **chave de API**. Use o endpoint HTTPS completo, incluindo a porta:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP e a chave de ingestão do seu coletor. Se o coletor não tiver TLS configurado, use `http://` em vez de `https://`. Para configurar o coletor, consulte [Ingestão com OpenTelemetry](/pt-BR/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## Outros tempos de execução e manipuladores {#other-runtimes-and-handlers}

Siga as [instruções oficiais de instrumentação automática do Lambda](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/) para selecionar as camadas adequadas ao seu tempo de execução, à sua arquitetura e à sua região AWS, e para configurar o contêiner de instrumentação.

Adicione e configure a [camada Lambda do Coletor OpenTelemetry](https://opentelemetry.io/docs/platforms/faas/lambda-collector/). Mantenha os exportadores do SDK da aplicação apontados para o coletor local, conforme descrito na documentação upstream. Em seguida, configure a conexão de saída do coletor, como mostrado abaixo.

### Configure o destino do coletor Lambda {#configure-lambda-collector-destination}

Defina `CLICKHOUSE_OTLP_ENDPOINT` e `CLICKHOUSE_INGESTION_API_KEY` nas variáveis de ambiente da sua função Lambda. Adicione o seguinte exportador à configuração do seu coletor.

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra **Team Settings → Dados → Telemetria Gerenciada** no seu serviço e copie o **endpoint OTLP HTTP** e a **chave de API**. Defina `CLICKHOUSE_OTLP_ENDPOINT` com o endpoint HTTPS completo, incluindo a porta, e `CLICKHOUSE_INGESTION_API_KEY` com a chave.

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "Bearer ${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>

  <Tab title="Autogerenciado">
    Defina `CLICKHOUSE_OTLP_ENDPOINT` com o endpoint OTLP HTTP do seu coletor e `CLICKHOUSE_INGESTION_API_KEY` com a chave de ingestão correspondente. O endpoint deve estar acessível a partir da sua função Lambda. Para configurar o coletor de destino, consulte [Ingestão com OpenTelemetry](/pt-BR/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>
</Tabs>

Adicione `otlphttp/clickhouse` à lista `exporters` de cada pipeline de sinal que você deseja enviar. Por exemplo, com o receptor `otlp` upstream:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

Mescle estas configurações na configuração do seu coletor, preservando as configurações de receptor e de processador. Empacote a configuração com sua função e defina `OPENTELEMETRY_COLLECTOR_CONFIG_URI` com o caminho do arquivo, como `/var/task/collector.yaml`, seguindo as instruções de configuração do coletor na documentação upstream.

## Verifique a ingestão {#verify-ingestion}

Implante e invoque sua função. No ClickHouse Observability, selecione um intervalo de tempo recente e localize o nome do serviço da sua função em Traces. Confira também Logs e Metrics, caso sua instrumentação emita esses sinais; adicionar um pipeline não habilita automaticamente a coleta deles.

Para a configuração da camada e a solução de problemas, consulte a [documentação do OpenTelemetry Lambda](https://github.com/open-telemetry/opentelemetry-lambda).
