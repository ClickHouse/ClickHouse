O Elastic Stack oferece dois tipos de SDK de linguagem para instrumentar aplicações:

1. **[Agentes APM oficiais da Elastic](https://www.elastic.co/docs/reference/apm-agents/)** – São desenvolvidos especificamente para uso com o Elastic Stack. Se você usa esses agentes, planeje a transição para a [instrumentação OpenTelemetry](https://opentelemetry.io/docs/languages/) da sua linguagem, incluindo os spans e atributos personalizados usados pela sua aplicação.

2. **[Elastic Distributions of OpenTelemetry (SDKs do EDOT)](https://www.elastic.co/docs/reference/opentelemetry/edot-sdks/)** – São as distribuições da Elastic dos SDKs padrão do OpenTelemetry, disponíveis para .NET, Java, Node.js, PHP e Python. Se a sua aplicação já usa um SDK do EDOT, não é necessário reinstrumentar o código. Basta reconfigurar o SDK para exportar os dados de telemetria para o seu endpoint OTLP do ClickHouse Observability. Consulte [&quot;Migrando SDKs EDOT&quot;](#migrating-edot-sdks-self-configured) para mais detalhes.

## Migrando SDKs EDOT {#migrating-edot-sdks-self-configured}

As Elastic Distributions of the OpenTelemetry SDKs (SDKs do EDOT) são versões personalizadas dos SDKs oficiais do OpenTelemetry. Por exemplo, o [EDOT Python SDK](https://www.elastic.co/docs/reference/opentelemetry/edot-sdks/python/) é uma distribuição do [OpenTelemetry Python SDK](https://opentelemetry.io/docs/languages/python/) personalizada pelo fornecedor, projetada para funcionar perfeitamente com o Elastic Observability.

Como esses SDKs são baseados nas bibliotecas padrão do OpenTelemetry, a migração para o ClickHouse Observability é simples: não é necessário refazer a instrumentação. Basta ajustar a configuração para enviar os dados de telemetria ao endpoint OTLP do seu ClickHouse Observability.

A configuração segue os mecanismos padrão do OpenTelemetry. Em Python, isso normalmente é feito por meio de variáveis de ambiente, conforme descrito na [documentação de instrumentação sem código do OpenTelemetry](https://opentelemetry.io/docs/zero-code/python/configuration/).

Uma configuração típica de um SDK do EDOT pode ser semelhante a esta:

```shell
export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
export OTEL_EXPORTER_OTLP_ENDPOINT=https://my-deployment.ingest.us-west1.gcp.cloud.es.io
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=ApiKey P....l"
```

Para migrar, atualize as configurações de conexão OTLP no ambiente da sua aplicação e reinicie-a. Os exemplos abaixo usam OTLP HTTP com codificação protobuf.

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Copie o endpoint OTLP HTTP e a chave de API em **Team Settings → Data → Managed Telemetry**:

    ```shell
    export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    Use o endpoint exatamente como fornecido, incluindo a porta e sem sufixo de sinal, como `/v1/traces`. O valor do cabeçalho usa `%20` para codificar o espaço após `Bearer`. Consulte [Enviando dados do OpenTelemetry](/pt-BR/clickstack/observability/ingesting-data/opentelemetry) para obter os detalhes de conexão.
  </Tab>

  <Tab title="Autogerenciado">
    Aponte o SDK para o endpoint OTLP HTTP acessível do coletor que receberá os dados:

    ```shell
    export OTEL_RESOURCE_ATTRIBUTES='service.name=YOUR_APP_NAME'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_COLLECTOR_TOKEN'
    ```

    Se você protegeu o coletor receptor com `OTLP_AUTH_TOKEN`, use esse token como valor de autorização. Use `localhost` somente quando a aplicação e o coletor compartilharem o mesmo namespace de rede. Para um coletor com TLS habilitado, use o endpoint HTTPS dele e configure o SDK para confiar no certificado correspondente. Consulte [Protegendo o coletor](/pt-BR/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).

    Se a autenticação do coletor estiver desabilitada, remova o cabeçalho anterior do Elastic:

    ```shell
    unset OTEL_EXPORTER_OTLP_HEADERS
    ```
  </Tab>
</Tabs>

Se a sua aplicação define variáveis específicas por sinal para endpoint OTLP, protocolo ou cabeçalho, atualize-as também, pois elas têm precedência sobre as configurações genéricas acima. Ao definir o nome do serviço, preserve os atributos de recurso já existentes.
