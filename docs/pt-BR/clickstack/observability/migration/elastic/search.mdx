## Busca no ClickHouse Observability e no Elastic {#search-in-clickstack-and-elastic-self-configured}

O ClickHouse é um mecanismo nativo de SQL, projetado desde o início para cargas de trabalho analíticas de alto desempenho. Já o Elasticsearch oferece uma interface semelhante a SQL, que transpila o SQL para a query DSL subjacente do Elasticsearch — ou seja, o SQL não é tratado como cidadão de primeira classe, e a [paridade de funcionalidades](https://www.elastic.co/docs/explore-analyze/query-filter/languages/sql-limitations) é limitada.

O ClickHouse não só oferece suporte completo a SQL como também o amplia com um conjunto de funções voltadas à observabilidade, como [`argMax`](/pt-BR/reference/functions/aggregate-functions/argMax), [`histogram`](/pt-BR/reference/functions/aggregate-functions/parametric-functions#histogram) e [`quantileTiming`](/pt-BR/reference/functions/aggregate-functions/quantileTiming), que simplificam a consulta de logs estruturados, métricas e traces.

Para a exploração simples de logs e traces, a UI de observabilidade oferece uma [sintaxe no estilo Lucene](/pt-BR/clickstack/observability/features/search) para filtragem intuitiva baseada em texto, com consultas por campo e valor, intervalos, caracteres curinga e muito mais. Ela é comparável à [sintaxe Lucene](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-query-string-query#query-string-syntax) do Elasticsearch e a elementos da [Kibana Query Language](https://www.elastic.co/docs/reference/query-languages/kql).

A interface de busca oferece suporte a essa sintaxe familiar, mas a converte internamente em cláusulas `WHERE` SQL eficientes. Assim, a experiência continua familiar para usuários do Kibana, sem abrir mão de todo o poder do SQL quando necessário. Isso permite explorar toda a gama de [funções de busca em strings](/pt-BR/reference/functions/regular-functions/string-search-functions), [funções de similaridade](/pt-BR/reference/functions/regular-functions/string-functions#stringJaccardIndex) e [funções de data e hora](/pt-BR/reference/functions/regular-functions/date-time-functions) do ClickHouse.

A sintaxe de pesquisa abaixo se aplica tanto a serviços gerenciados quanto a autogerenciados. Os nomes dos campos dependem do seu schema; os exemplos usam campos de log padrão do OpenTelemetry, quando aplicável.

## Sintaxe de pesquisa do ClickHouse Observability vs. string de consulta do Elasticsearch {#clickstack-vs-elasticsearch-query-string-self-configured}

Tanto o ClickHouse Observability quanto o Elasticsearch oferecem linguagens de consulta flexíveis para filtrar logs e traces de forma intuitiva. Enquanto a string de consulta do Elasticsearch é fortemente integrada à sua DSL e ao seu mecanismo de indexação, o ClickHouse Observability oferece suporte a uma sintaxe inspirada no Lucene que, internamente, é traduzida para SQL do ClickHouse. A tabela abaixo mostra como padrões de busca comuns se comportam nos dois sistemas, destacando as semelhanças na sintaxe e as diferenças na execução no backend.

| **Recurso**                            | **Sintaxe do ClickHouse Observability**        | **Sintaxe do Elasticsearch**      | **Comentários**                                                                                                                                                                                                                                                                                                   |
| -------------------------------------- | ---------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Busca de texto livre                   | `error`                                        | `error`                           | O ClickHouse Observability pesquisa a expressão de texto completo configurada na fonte, geralmente `Body`, com correspondência de palavras inteiras sem diferenciar maiúsculas de minúsculas por padrão. Ele não pesquisa automaticamente todas as colunas.                                                       |
| Correspondência de campo               | `SeverityText:error`                           | `level:error`                     | Use o nome do campo do seu schema. No ClickHouse Observability, buscas em campos de string sem aspas correspondem a substrings; para igualdade, coloque o valor entre aspas, por exemplo `SeverityText:"error"`.                                                                                                  |
| Busca por frase                        | `"disk full"`                                  | `"disk full"`                     | Corresponde à frase na expressão de texto completo configurada.                                                                                                                                                                                                                                                   |
| Correspondência de frase em campo      | `Body:"disk full"`                             | `message:"disk full"`             | No ClickHouse Observability, um valor de campo diretamente entre aspas usa igualdade: ele corresponde ao corpo inteiro, e não a uma frase dentro de uma mensagem mais longa.                                                                                                                                      |
| Condições OR                           | `error OR warning`                             | `error OR warning`                | OR lógico de termos; ambos os sistemas oferecem suporte nativo.                                                                                                                                                                                                                                                   |
| Condições AND                          | `error AND db`                                 | `error AND db`                    | Ambos são traduzidos para interseção; não há diferença na sintaxe para o usuário.                                                                                                                                                                                                                                 |
| Negação                                | `NOT error` ou `-error`                        | `NOT error` ou `-error`           | Exclui os eventos correspondentes.                                                                                                                                                                                                                                                                                |
| Agrupamento                            | `(error OR fail) AND db`                       | `(error OR fail) AND db`          | Agrupamento booleano padrão em ambos.                                                                                                                                                                                                                                                                             |
| Caracteres curinga                     | `error*` ou `*fail*`                           | `error*`, `*fail*`                | O ClickHouse Observability oferece suporte a caracteres curinga no início e no fim, inclusive em buscas de texto livre; caracteres curinga internos, como `f*ail`, não são suportados. O Elasticsearch permite caracteres curinga no início por padrão, mas eles podem ser desativados e podem ter custo elevado. |
| Intervalos (numéricos/data)            | `Duration:[100 TO 200]`                        | `duration:[100 TO 200]`           | Colchetes incluem ambos os limites. Use o nome do campo e as unidades do seu schema.                                                                                                                                                                                                                              |
| Intervalos sem limite (numéricos/data) | `Duration:>10` ou `Duration:>=10`              | `duration:>10` ou `duration:>=10` | Operadores de comparação expressam intervalos abertos.                                                                                                                                                                                                                                                            |
| Inclusivo/exclusivo                    | `Duration:{100 TO 200}`                        | `duration:{100 TO 200}`           | Chaves excluem ambos os limites.                                                                                                                                                                                                                                                                                  |
| Verificação de existência              | `LogAttributes.log.file.path:*`                | `_exists_:user` ou `field:*`      | Para um atributo `Map` com valores do tipo string, o ClickHouse Observability verifica se há um valor não vazio. Use `mapContains` em SQL se precisar verificar a presença da chave independentemente do valor; consulte [Schema e campos ausentes](#empty-value-differences-self-configured).                    |
| Regex                                  | função `match`                                 | `name:/joh?n(ath[oa]n)/`          | Atualmente não suportado na sintaxe Lucene. Você pode usar SQL e a função [`match`](/pt-BR/reference/functions/regular-functions/string-search-functions#match) ou outras [funções de busca em strings](/pt-BR/reference/functions/regular-functions/string-search-functions).                                                |
| Correspondência aproximada             | `editDistance('quikc', field) = 1`             | `quikc~`                          | Atualmente não suportado na sintaxe Lucene. Funções de distância podem ser usadas em SQL, por exemplo, `editDistance('rror', SeverityText) = 1`, ou [outras funções de similaridade](/pt-BR/reference/functions/regular-functions/string-functions#jaroSimilarity).                                                     |
| Busca por proximidade                  | Não suportado                                  | `"fox quick"~5`                   | Atualmente não suportado na sintaxe Lucene.                                                                                                                                                                                                                                                                       |
| Boosting                               | Não suportado                                  | `quick^2 fox`                     | Atualmente não suportado no ClickHouse Observability.                                                                                                                                                                                                                                                             |
| Wildcard em campos                     | Não suportado                                  | `service.*:error`                 | Atualmente não suportado no ClickHouse Observability.                                                                                                                                                                                                                                                             |
| Escape de caracteres especiais         | Faça o escape de caracteres reservados com `\` | Igual                             | É necessário fazer o escape de símbolos reservados.                                                                                                                                                                                                                                                               |

## Schema e campos ausentes {#empty-value-differences-self-configured}

O schema padrão do OpenTelemetry usa campos como `Body`, `SeverityText` e `ServiceName`, com atributos de log e de recurso em `LogAttributes` e `ResourceAttributes`. Converta os nomes de campos do Elastic para os campos correspondentes nos seus dados ingeridos — por exemplo, `level:error` passa a ser `SeverityText:error`.

Em colunas não anuláveis, um valor omitido é representado pelo valor padrão da coluna, como uma string vazia. Por isso, um `ServiceName` vazio não permite saber se o remetente omitiu o valor ou enviou explicitamente uma string vazia.

Em implantações autogerenciadas com tabelas personalizadas, use os seus próprios nomes de colunas e verifique os valores padrão e se as colunas aceitam nulos. Colunas [`Nullable`](/pt-BR/reference/data-types/nullable) podem conter `NULL`.

Em consultas SQL, `ServiceName != ''` verifica se há um nome de serviço não vazio. Atributos armazenados em um `Map` são diferentes das colunas de nível superior: use `mapContains(LogAttributes, 'log.file.path')` para verificar se uma chave de atributo existe, mesmo quando o valor dela está vazio.
