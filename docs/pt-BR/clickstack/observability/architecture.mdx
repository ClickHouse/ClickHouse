O ClickHouse Observability é executado inteiramente no **ClickHouse Cloud** e oferece um backend de observabilidade totalmente gerenciado, preservando o mesmo modelo de dados e a mesma experiência de usuário do ClickStack. Para implantações autogerenciadas, consulte a [arquitetura autogerenciada](/pt-BR/clickstack/self-configured/architecture).

Nesse modelo, **o ClickHouse, a interface do ClickStack e o coletor de ingestão OpenTelemetry (OTel)** são hospedados, operados e protegidos pelo ClickHouse Cloud. Cabe aos usuários instrumentar suas aplicações e enviar a telemetria do próprio ambiente para o serviço gerenciado.

### Coletor OpenTelemetry: ingestão de dados {#open-telemetry-collector-managed}

O ClickHouse Observability inclui um coletor OpenTelemetry (OTel) gerenciado para fazer a ingestão de telemetria de forma aberta e padronizada. No seu serviço, abra **Team Settings → Dados → Telemetria Gerenciada** para copiar o endpoint OTLP e a chave de API. Consulte [Enviando dados do OpenTelemetry](/pt-BR/clickstack/observability/ingesting-data/opentelemetry) para ver as instruções de conexão e autenticação.

O coletor exporta a telemetria para o ClickHouse Cloud em lotes eficientes, usando esquemas de tabela otimizados para cada sinal de telemetria.

O coletor de ingestão é gerenciado pelo ClickHouse Cloud. Ainda assim, talvez você precise de coletores no seu próprio ambiente para reunir telemetria, como métricas de host ou logs do Kubernetes, e encaminhá-la ao endpoint gerenciado.

### ClickHouse Cloud: o motor {#clickhouse-cloud}

No centro do ClickHouse Observability está o ClickHouse Cloud, uma versão serverless do ClickHouse — um banco de dados orientado a colunas projetado para analytics em tempo real em larga escala. Ele viabiliza a ingestão e a consulta de dados de observabilidade, permitindo:

* Busca rápida em grandes volumes de eventos
* Ingestão de telemetria high-cardinality em larga escala
* Compressão orientada a colunas para dados de observabilidade
* Suporte nativo a dados JSON semiestruturados, permitindo a evolução dinâmica do esquema
* Um poderoso motor SQL com centenas de funções analíticas integradas

O ClickHouse Cloud trata os dados de observabilidade como eventos amplos, permitindo uma correlação profunda entre logs, métricas e rastros em uma única estrutura unificada.

Em relação ao ClickHouse de Código Aberto, ele oferece diversos benefícios adicionais para observabilidade:

* Escalonamento automático da capacidade computacional, independente do armazenamento
* Armazenamento de objetos para reter telemetria independentemente da capacidade computacional
* Autenticação integrada
* Funcionalidades de segurança e conformidade
* Upgrades sem interrupções

### Interface do ClickStack: a interface {#hyperdx}

A Interface do ClickStack é a interface de usuário do ClickStack. Ela oferece:

* Busca em linguagem natural e no estilo Lucene
* Acompanhamento ao vivo (live tailing) para depuração em real-time
* Visões unificadas de logs, métricas e rastros
* Reprodução de sessão para observabilidade do frontend
* Criação de dashboards e configuração de alertas
* Interface de consultas SQL para análises avançadas

Projetada especificamente para o ClickHouse, a Interface do ClickStack combina uma busca poderosa com fluxos de trabalho intuitivos, permitindo que você identifique anomalias, investigue problemas e obtenha insights rapidamente.

No ClickHouse Observability, a UI é integrada ao sistema de autenticação do console do ClickHouse Cloud.

### Isolamento entre ingestão e consultas {#ingestion-query-isolation}

O ClickHouse Observability usa capacidade computacional separada para ingestão e execução de consultas. A capacidade computacional de gravação processa a telemetria recebida e a manutenção de dados em segundo plano. A capacidade computacional de leitura atende a buscas, dashboards, notebooks e consultas de alertas. Ambas acessam o mesmo armazenamento de objetos subjacente.

Essa separação reduz a disputa por recursos entre as cargas de trabalho de ingestão e de consulta. Se a capacidade computacional de gravação ficar temporariamente indisponível, a capacidade computacional de leitura poderá continuar consultando os dados armazenados, embora a telemetria mais recente possa chegar com atraso. Se a capacidade computacional de leitura ficar indisponível, a ingestão poderá continuar, mas as buscas e a avaliação de alertas poderão ser interrompidas.

### Escalonamento {#scaling}

O ClickHouse Cloud ajusta a capacidade conforme as cargas de trabalho mudam. Os coletores gerenciados escalam horizontalmente para absorver o tráfego de ingestão, enquanto a capacidade computacional de gravação e a de leitura escalam de forma independente uma da outra e do armazenamento.

O escalonamento não é instantâneo. Aumentos repentinos na ingestão podem atrasar o momento em que a nova telemetria fica disponível para busca, e picos de consultas podem elevar os tempos de resposta enquanto a capacidade se ajusta. Separar as cargas de trabalho ajuda a limitar o impacto de uma sobre a outra.

### Bufferização e recuperação da ingestão {#ingestion-buffering-recovery}

O coletor gerenciado tenta primeiro gravar a telemetria no ClickHouse. Se o ClickHouse não puder aceitar gravações temporariamente, o pipeline de ingestão pode armazenar lotes no Amazon S3 para reaplicação posterior. Esse buffer temporário de ingestão é separado do armazenamento de objetos que o ClickHouse usa para a telemetria armazenada. Quando as gravações são retomadas, os dados armazenados em buffer são ingeridos no ClickHouse.

Durante a recuperação, a telemetria recente pode aparecer com atraso ou fora de ordem enquanto o backlog é processado. Essa bufferização permite a recuperação de interrupções temporárias de gravação, mas não oferece failover cross-region nem garante a entrega em todos os cenários de falha.

Ainda é possível perder alguns dados, como os que estavam apenas na memória de um coletor no momento em que ele parou ou lotes que não puderam ser gravados nem no ClickHouse nem no S3. Configure seus agentes de envio e coletores para tentar novamente as exportações que falharem e, quando houver suporte, use filas persistentes para reter a telemetria durante interrupções.
