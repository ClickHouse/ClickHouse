Colete logs CSV do PostgreSQL com um coletor OpenTelemetry e envie-os para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar instalar o PostgreSQL.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Docker para executar os exemplos do coletor
* Para usar seus próprios logs, PostgreSQL 14 ou mais recente e acesso aos respectivos arquivos de configuração e de log
* Para a demonstração, `curl` para baixar a amostra

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy detalhes de conexão** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você executará o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/logs`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado">
    Use um endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, remova o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos da versão autogerenciada](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint deve estar acessível a partir do contêiner do coletor. Para um coletor de destino em execução neste computador, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento do host.

## Integração com um PostgreSQL existente {#existing-postgres}

<Steps>
  <Step title="Configure o logging do PostgreSQL" id="configure-postgres">
    Localize seu arquivo de configuração executando esta instrução SQL como administrador do banco de dados:

    ```sql
    SHOW config_file;
    ```

    Adicione ou atualize estas configurações no `postgresql.conf`:

    ```conf
    logging_collector = on
    log_destination = 'csvlog'
    log_directory = '/var/log/postgresql'
    log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
    log_file_mode = 0640
    log_timezone = 'UTC'
    log_connections = on
    log_disconnections = on
    # Optional: log statements taking more than one second
    # log_min_duration_statement = 1000
    ```

    Crie o diretório de log com proprietário e permissões que permitam ao PostgreSQL gravar nele e ao coletor lê-lo. Se o PostgreSQL for executado em contêiner, monte esse diretório para que o coletor possa acessar os mesmos arquivos. A saída em CSV usa a extensão `.csv`, ainda que `log_filename` termine em `.log`.

    Reinicie o PostgreSQL usando seu processo de implantação, por exemplo:

    ```bash
    sudo systemctl restart postgresql
    # Or, for Docker:
    docker restart <postgres-container>
    ```

    Verifique o arquivo CSV ativo:

    ```sql
    SELECT pg_current_logfile('csvlog');
    ```

    O analisador sintático abaixo pressupõe o [formato CSV do PostgreSQL com 26 colunas](https://www.postgresql.org/docs/14/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-CSVLOG). Versões anteriores do PostgreSQL e outros formatos de log exigem um analisador sintático diferente.
  </Step>

  <Step title="Configure o coletor" id="configure-collector">
    Salve o conteúdo a seguir como `postgres-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql-*.csv
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql"

          - type: add
            field: resource["service.name"]
            value: "postgresql-service"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    O receptor analisa sintaticamente entradas CSV multilinha, preserva seus timestamps e corpos e adiciona `service.name` com o valor `postgresql-service`. Campos como `database_name`, `error_severity`, `message` e `query` continuam disponíveis como atributos de log.
  </Step>

  <Step title="Execute o coletor" id="run-collector">
    No diretório que contém a configuração, execute o comando a seguir. Ajuste o diretório de logs do host, se necessário. Se os arquivos de log tiverem permissão de leitura para o grupo, adicione `--group-add LOG_GROUP_ID`, usando o ID numérico do grupo exibido por `ls -ln /var/log/postgresql`.

    ```bash
    docker run --rm --name postgres-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/postgresql:/var/log/postgresql:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto. Como o receptor usa `start_at: end`, depois de iniciar o coletor, crie uma nova conexão com o banco de dados ou execute uma consulta que gere um erro:

    ```sql
    SELECT 1 / 0;
    ```
  </Step>

  <Step title="Verifique os logs" id="verify-logs">
    Abra a página **Busca**, selecione **Logs**, filtre por `ServiceName:postgresql-service` e selecione **Last 15 minutes**. Expanda um registro para inspecionar os atributos do PostgreSQL e a severidade.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 21,325 registros CSV do PostgreSQL com atividade de conexão, consultas e erros do servidor.

<Steps>
  <Step title="Baixe o conjunto de dados de exemplo" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/postgres/postgresql.log
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo">
    Salve o conteúdo a seguir como `postgres-logs-demo.yaml`:

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql-demo"

          - type: add
            field: resource["service.name"]
            value: "postgresql-demo"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-10T23:59:47Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    O processador de timestamp usado apenas na demonstração desloca a amostra para as últimas 24 horas, terminando dois minutos antes da ingestão. Os atributos de timestamp originais e os corpos dos logs permanecem inalterados. Não use este processador com seus próprios logs do PostgreSQL.
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo">
    No diretório que contém a configuração e o arquivo de log baixado, execute:

    ```bash
    docker run --rm --name postgres-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/postgresql.log:/var/log/postgresql/postgresql.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto enquanto verifica a ingestão. Ao terminar, interrompa o coletor com **Ctrl+C**. Ao executar a demonstração novamente, a amostra é reingerida com timestamps atualizados.
  </Step>

  <Step title="Verifique os logs de demonstração" id="verify-demo">
    Abra **Busca**, selecione **Logs**, filtre por `ServiceName:postgresql-demo` e selecione **Last 2 days**. Expanda um registro para inspecionar campos como `database_name`, `error_severity`, `message` e `query`.

## Solução de problemas {#troubleshooting}

### O coletor não inicia {#collector-fails-to-start}

Verifique se há erros de configuração na saída do coletor. Confira também a montagem da configuração e as variáveis de conexão no terminal em que o Docker está sendo executado.

### Nenhum log é exibido {#no-logs}

Verifique se há erros de autenticação ou de exportação. Confirme o caminho do CSV com `pg_current_logfile`, certifique-se de que os arquivos correspondem ao pattern `include` do receptor e verifique se o coletor consegue lê-los. Com `start_at: end`, apenas novas entradas são coletadas. Para a demonstração, inclua o processador de timestamp e selecione **Last 2 days**.

### Permissão negada {#permission-denied}

Por padrão, o PostgreSQL cria arquivos de log acessíveis apenas ao proprietário. A configuração acima usa `log_file_mode = 0640` para permitir leituras pelo grupo; adicione o grupo do arquivo ao contêiner do coletor com `--group-add`. Os arquivos existentes mantêm as permissões anteriores. Certifique-se de que o diretório também permita o acesso do grupo.

### Erros de análise sintática de CSV {#csv-parsing-errors}

O analisador sintático espera 26 colunas do PostgreSQL 14 ou posterior. Verifique se `log_destination = 'csvlog'` e `log_timezone = 'UTC'`. Ajuste o cabeçalho para versões anteriores ou formatos personalizados; logs em stderr e JSON não são compatíveis com este analisador sintático de CSV.
