Colete logs do AWS CloudWatch com um coletor OpenTelemetry e envie-os para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para experimentar a integração sem precisar configurar o acesso à AWS.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Docker com Docker Compose para executar os exemplos do coletor ou uma implantação existente do OpenTelemetry Collector Contrib
* Para seus próprios logs, uma AWS account com grupos de logs do CloudWatch, AWS CLI v2 e credenciais com as permissões listadas abaixo
* Para a demonstração, `curl` para baixar a amostra

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você executará o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela chave de API correspondente. Use o endpoint HTTP base, sem o sufixo `/v1/logs`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado" id="self-managed">
    Use o endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, omita o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos para ambientes autogerenciados](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint deve estar acessível a partir do contêiner do coletor. Para um coletor de destino em execução neste computador, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento do host.

## Integração com grupos de logs do CloudWatch existentes {#existing-cloudwatch}

<Steps>
  <Step title="Configure as credenciais da AWS" id="configure-aws">
    Para o AWS SSO, faça login e exporte as credenciais temporárias no terminal em que você iniciará o coletor:

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    Substitua o nome do perfil e a região pelos seus próprios valores. Se você já usa credenciais de ambiente, defina `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` e `AWS_SESSION_TOKEN` (para credenciais temporárias), além de `AWS_REGION`. Essas credenciais autorizam a leitura de logs da AWS e são independentes das credenciais OTLP do seu destino.

    A identidade do IAM precisa das seguintes permissões. Substitua `YOUR_REGION` e `YOUR_ACCOUNT_ID` e, quando for o caso, restrinja o recurso de grupo de logs aos grupos que você pretende coletar:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Liste os grupos de logs disponíveis para escolher os nomes a serem usados na configuração:

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="Configure o receptor do CloudWatch" id="configure-receiver">
    Salve este arquivo como `cloudwatch-logs.yaml`. Substitua `/aws/lambda/my-function` por um grupo de logs da sua conta e adicione outros grupos em `named`, conforme necessário.

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    Esta configuração começa pela última hora de logs e, depois, faz uma consulta a cada minuto. Altere `initial_lookback` para ajustar a janela inicial. Sem armazenamento persistente de pontos de verificação, reiniciar o coletor pode fazer com que essa janela seja lida novamente, gerando registros duplicados.

    Para, em vez disso, descobrir grupos por prefixo, substitua o bloco `groups` por:

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    Use `named` ou `autodiscover`. Para outras opções, incluindo pontos de verificação persistentes, consulte a [documentação do receptor do CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver).
  </Step>

  <Step title="Inicie o coletor" id="start-collector">
    Salve este arquivo como `docker-compose.yaml` no mesmo diretório que `cloudwatch-logs.yaml`:

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    No terminal em que você definiu as credenciais da AWS e as [variáveis de conexão](#connection-details), inicie o coletor e acompanhe a saída:

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Verifique os logs" id="verify-logs">
    Abra a página **Busca** no ClickHouse Observability, selecione a fonte de dados **Logs** e aplique o filtro `ServiceName:cloudwatch`. Selecione **Last 2 hours** e aguarde um ou dois intervalos de consulta até que os logs apareçam.

    Procure os seguintes atributos de recurso:

    * `aws.region`: a região AWS
    * `cloudwatch.log.group.name`: o grupo de logs
    * `cloudwatch.log.stream`: o stream de logs

    A mensagem de log aparece em `Body`. O receptor preserva a mensagem, mas não infere a severidade a partir do texto. Para usar painéis de dashboard baseados em severidade, o seu pipeline de logs precisa popular `SeverityText`.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 12,785 logs que abrangem 24 horas de atividade do Lambda, do ECS e de jobs em segundo plano. Ela inclui grupos de logs, streams e valores de severidade. Esta opção não exige credenciais da AWS nem acesso direto ao banco de dados.

<Steps>
  <Step title="Baixe a amostra" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo-collector">
    Salve o conteúdo abaixo como `cloudwatch-demo.yaml` no diretório de download:

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      A configuração de demonstração lê o formato de linha do ClickHouse usado na amostra e restaura o corpo, a severidade e os atributos dos logs. A transformação de timestamp desloca a amostra para aproximadamente as últimas 24 horas, terminando dois minutos antes da ingestão. Para os seus próprios logs, use a configuração do receptor do CloudWatch mostrada acima, para que os timestamps originais sejam preservados.
    </Note>
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo-collector">
    Defina as [variáveis de conexão](#connection-details) e execute este comando no diretório de download:

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto enquanto o coletor lê e exporta o arquivo. Verifique se há erros na saída. Executar um novo contêiner outra vez pode duplicar os logs de amostra.
  </Step>

  <Step title="Verifique os logs de demonstração" id="verify-demo-logs">
    Abra **Search**, selecione sua fonte de dados **Logs**, filtre por `ServiceName:cloudwatch-demo` e selecione **Last 2 days**. Expanda um log para inspecionar o corpo, a severidade, o grupo de logs e o stream. Depois de verificar os dados, interrompa o coletor de demonstração com **Ctrl+C**.

    <div className="ch-image-lg">
      <Frame>
        ![Logs de demonstração do CloudWatch no ClickHouse Observability](/images/clickstack/observability-cloudwatch-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### Nenhum log é exibido {#no-logs}

* Verifique a saída de `docker compose logs otel-collector` em busca de erros de autenticação da AWS, de acesso negado ou de exportação OTLP.
* Confirme se `AWS_REGION` e os nomes dos grupos de logs correspondem à sua conta e se os grupos contêm eventos dentro do período de `initial_lookback` ou novos eventos após a inicialização.
* Verifique as permissões do IAM para `logs:DescribeLogGroups` e `logs:FilterLogEvents`.
* Confira o endpoint de destino e as configurações de autenticação em [Detalhes de conexão](#connection-details).
* Verifique a fonte de dados **Logs**, o filtro por nome do serviço e o intervalo de tempo. Para a demonstração, selecione **Last 2 days**.

### Credenciais da AWS expiradas {#expired-credentials}

Se você usa SSO, faça login e exporte novas credenciais; em seguida, recrie o coletor para que ele receba as novas variáveis de ambiente:

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

Reiniciar apenas o contêiner existente não atualiza suas credenciais. No caso de outras credenciais temporárias, renove a chave de acesso, a chave secreta e o token de sessão antes de recriá-lo.

### Logs antigos ausentes {#older-logs}

O exemplo começa com uma janela retroativa de uma hora. Aumente `logs.initial_lookback` ou substitua-o por `logs.start_from`, usando um timestamp RFC3339 para definir um horário de início específico. Não defina os dois. Reinicie o coletor depois de alterar a configuração; reler uma janela de tempo pode gerar duplicatas.
