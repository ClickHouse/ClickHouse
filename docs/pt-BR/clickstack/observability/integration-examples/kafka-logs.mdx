Colete os logs do broker do Kafka com o receptor `filelog` do OpenTelemetry e envie-os para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar de uma implantação do Kafka.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Docker e `curl`
* Para usar seus próprios logs, acesso aos arquivos de log do broker Kafka no formato abaixo

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você vai executar o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela chave de API correspondente. Use o endpoint HTTP base, sem o sufixo `/v1/logs`; o exportador acrescenta o caminho do sinal automaticamente.
  </Tab>

  <Tab title="Autogerenciado">
    Use um endpoint OTLP HTTP do seu coletor que esteja acessível (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`), além das configurações de autenticação correspondentes. Se o seu coletor não exigir autenticação, omita o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos da versão autogerenciada](/pt-BR/clickstack/self-configured/getting-started/managed) para obter instruções de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint deve estar acessível a partir do contêiner do coletor. Se o coletor de destino estiver em execução neste computador, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento de host.

## Integração com um Kafka existente {#existing-kafka}

<Steps>
  <Step title="Verifique a configuração de logging do Kafka" id="verify-kafka">
    Localize os logs do broker. Os locais mais comuns são `$KAFKA_HOME/logs` e `/var/log/kafka`, dependendo da sua instalação e da configuração de logging:

    ```bash
    ls "$KAFKA_HOME/logs/"
    ls /var/log/kafka/
    ```

    Os arquivos mais comuns são `server.log` (eventos do broker), `controller.log` (eventos do controlador) e `state-change.log` (transições de partição e de réplica). Arquivos separados só existem quando estão configurados nos seus appenders de logging.

    O analisador sintático deste guia espera o seguinte formato de texto do Log4j:

    ```text
    [2026-03-09 14:23:45,123] INFO [KafkaServer id=0] started (kafka.server.KafkaServer)
    ```

    Se o seu broker gravar logs apenas em stdout, configure um file appender na configuração de logging do broker e compartilhe esse diretório com o coletor. O receptor `filelog` não lê o stdout do contêiner diretamente. Ajuste o analisador sintático caso o seu pattern de logging seja diferente.
  </Step>

  <Step title="Configure o coletor" id="configure-collector">
    Salve o conteúdo a seguir como `kafka-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
          - /var/log/kafka/controller.log
          - /var/log/kafka/state-change.log
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka
          - type: add
            field: resource["service.name"]
            value: kafka-service
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, batch]
          exporters: [otlp_http/observability]
    ```

    Defina `location` como o fuso horário usado pelos logs do broker; o exemplo considera UTC. As entradas multilinha preservam os rastreamentos de pilha completos. O coletor lê as novas entradas com `start_at: end` e normaliza o texto de severidade para minúsculas.
  </Step>

  <Step title="Execute o coletor" id="run-collector">
    Defina as [variáveis de conexão](#connection-details) e, em seguida, execute o comando a partir do diretório de configuração. Ajuste o caminho dos logs no host, se necessário. Para arquivos com permissão de leitura para o grupo, adicione `--group-add LOG_GROUP_ID`, usando o ID numérico do grupo exibido por `ls -ln /var/log/kafka`.

    ```bash
    docker run --rm --name kafka-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/kafka:/var/log/kafka:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto e gere atividade no broker que grave novas entradas de log. Ao concluir os testes, pressione **Ctrl+C** para encerrar.
  </Step>

  <Step title="Verifique os logs" id="verify-logs">
    Abra **Busca**, selecione **Logs**, filtre por `ServiceName:kafka-service` e selecione **Last 15 minutes**. Você deverá ver as mensagens do broker com os timestamps convertidos e a severidade.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 6,376 entradas de log de brokers Kafka, abrangendo aproximadamente 24 horas. O coletor atualiza os timestamps dessas entradas, preservando as mensagens e os stack traces.

<Steps>
  <Step title="Baixe a amostra" id="download-sample">
    ```bash
    curl -fL -o server.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/kafka/server.log
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo">
    Salve o conteúdo abaixo como `kafka-logs-demo.yaml`:

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka-demo
          - type: add
            field: resource["service.name"]
            value: kafka-demo
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:58.180Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo">
    Defina as [variáveis de conexão](#connection-details) e execute o comando a partir do diretório que contém os dois arquivos:

    ```bash
    docker run --rm --name kafka-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/server.log:/var/log/kafka/server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto enquanto verifica a ingestão. Ao terminar, interrompa com **Ctrl+C**. Ao executar a demonstração novamente, a amostra é reingerida com timestamps atualizados.
  </Step>

  <Step title="Verifique os logs de demonstração" id="verify-demo">
    Abra **Busca**, selecione **Logs**, filtre por `ServiceName:kafka-demo` e selecione **Last 2 days**.

      </Frame>
    </div>
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### Nenhum log é exibido {#no-logs}

Verifique a saída do coletor em busca de erros de permissão de arquivo, de parsing, de autenticação ou de exportação. Confirme se o seu broker grava no diretório montado e se os nomes dos arquivos correspondem à lista `include` do receptor. A configuração ativa lê apenas as novas entradas.

### Logs não são analisados corretamente {#parsing-errors}

Compare uma entrada de log do broker com o formato esperado:

```bash
tail -n 20 /var/log/kafka/server.log
```

Ajuste a expressão regular e o pattern de início multilinha caso o seu formato de logging seja diferente. Defina o `location` do analisador sintático de timestamp como o fuso horário de logging do seu broker.
