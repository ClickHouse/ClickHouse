Colete métricas de brokers Kafka com o OpenTelemetry JMX Metric Gatherer e envie-as para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar de uma implantação do Kafka.

## Pré-requisitos {#prerequisites}

* Um serviço ClickHouse Observability
* Docker com Docker Compose e `curl`
* Para coletar suas próprias métricas, um broker Kafka com JMX remoto habilitado e acessível pelo gatherer

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Defina estas variáveis no terminal em que você executará o JMX gatherer ou o coletor de demonstração:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/metrics`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, omita o argumento `-Dotel.exporter.otlp.headers` do JMX gatherer e o bloco `headers` do coletor de demonstração. Consulte o [guia de primeiros passos autogerenciado](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint precisa estar acessível a partir do contêiner do gatherer ou do coletor. Para um coletor de destino em execução neste computador, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento de host.

## Integração com uma implantação existente do Kafka {#existing-kafka}

<Steps>
  <Step title="Verifique o endpoint JMX do broker" id="verify-jmx">
    Use o endpoint JMX remoto configurado para o seu broker. Para um broker que expõe JMX na porta `9999`:

    ```bash
    export KAFKA_JMX_URL='service:jmx:rmi:///jndi/rmi://YOUR_KAFKA_HOST:9999/jmxrmi'
    export KAFKA_BROKER_ID='broker-0'
    ```

    Substitua o hostname e o ID do broker pelos seus próprios valores. O hostname RMI anunciado pelo broker também precisa estar acessível a partir do gatherer. Se o broker usar portas separadas para o registro e para o RMI, libere ambas na rede. O gatherer apenas lê o JMX; ele não precisa da porta de cliente do Kafka (`9092`).

    Para contêineres em uma rede Docker compartilhada, use o hostname do contêiner do broker. Para um broker executado no host Docker, use `host.docker.internal` e configure o broker para anunciar um hostname acessível a partir do contêiner. Mantenha o acesso JMX restrito à sua rede de monitoramento e preserve as configurações de autenticação e TLS do seu broker.
  </Step>

  <Step title="Baixe o JMX Metric Gatherer" id="download-jmx">
    ```bash
    curl -fL -o opentelemetry-jmx-metrics.jar \
      https://github.com/open-telemetry/opentelemetry-java-contrib/releases/download/v1.32.0/opentelemetry-jmx-metrics.jar
    ```
  </Step>

  <Step title="Configure o gatherer" id="configure-gatherer">
    Salve o conteúdo abaixo como `compose.yaml` no mesmo diretório do JAR baixado:

    ```yaml
    services:
      kafka-jmx-gatherer:
        image: eclipse-temurin:11-jre
        extra_hosts:
          - "host.docker.internal:host-gateway"
        environment:
          - KAFKA_JMX_URL
          - KAFKA_BROKER_ID
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        volumes:
          - ./opentelemetry-jmx-metrics.jar:/app/opentelemetry-jmx-metrics.jar:ro
        command:
          - sh
          - -c
          - >-
            exec java
            -Dotel.jmx.service.url="$${KAFKA_JMX_URL}"
            -Dotel.jmx.target.system=kafka
            -Dotel.jmx.interval.milliseconds=10000
            -Dotel.metrics.exporter=otlp
            -Dotel.exporter.otlp.protocol=http/protobuf
            -Dotel.exporter.otlp.endpoint="$${OTEL_EXPORTER_OTLP_ENDPOINT}"
            -Dotel.exporter.otlp.headers="authorization=$${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
            -Dotel.resource.attributes="service.name=kafka-service,kafka.broker.id=$${KAFKA_BROKER_ID}"
            -jar /app/opentelemetry-jmx-metrics.jar
    ```

    Se o broker estiver em uma rede Docker existente, conecte `kafka-jmx-gatherer` a essa rede na sua configuração do Compose. Para JMX autenticado, adicione as propriedades `otel.jmx.username` e `otel.jmx.password`; para TLS, configure o repositório de certificados confiáveis adequado. Consulte a [configuração de autenticação e TLS do gatherer](https://github.com/open-telemetry/opentelemetry-java-contrib/tree/v1.32.0/jmx-metrics#configuration).
  </Step>

  <Step title="Inicie a coleta" id="run-gatherer">
    Defina as [variáveis de conexão](#connection-details) e as variáveis do broker neste terminal e, em seguida, execute o comando a partir do diretório que contém o `compose.yaml`:

    ```bash
    docker compose up kafka-jmx-gatherer
    ```

    Mantenha o terminal aberto e fique atento a erros de conexão JMX ou erros de exportação OTLP. O gatherer faz a coleta a cada 10 segundos. Aguarde pelo menos dois intervalos de coleta antes de verificar o seu serviço. Ao terminar os testes, interrompa-o com **Ctrl+C**.

    Para vários brokers, execute um gatherer por broker, cada um com sua própria URL JMX e seu próprio `kafka.broker.id`.
  </Step>

  <Step title="Verifique as métricas" id="verify-metrics">
    Abra o **Chart Explorer**, selecione sua fonte de dados **Metrics**, filtre por `ServiceName:kafka-service` e selecione **Last 15 minutes**. Procure por `kafka.partition.count`, `kafka.partition.under_replicated` ou `kafka.message.count`. Métricas relacionadas a tráfego só apresentam valores significativos quando há atividade no broker.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 6,282 pontos de gauge e de soma, coletados a cada cinco minutos ao longo de aproximadamente 29 horas. Ela preserva os padrões do dataset original de picos de tráfego, latência de requisições, defasagem do consumidor e saúde das partições. Não é necessário ter uma implantação do Kafka nem acesso direto ao banco de dados.

Defina as [variáveis de conexão](#connection-details) antes de começar.

<Steps>
  <Step title="Baixe as métricas de amostra" id="download-sample">
    [Baixe o pacote de amostra](/pt-BR/assets/kafka-metrics-demo.zip) (cerca de 53 KB) e extraia `kafka-metrics-demo.json` para o seu diretório de trabalho.
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo-collector">
    Salve o conteúdo a seguir como `kafka-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: kafka-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-06T22:14:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      O processador transform, usado apenas na demonstração, atualiza os timestamps, preservando os valores de métricas e o intervalo entre os timestamps de início e de fim de cada ponto. Remova-o ao usar métricas do Kafka em tempo real. O limite de lote mantém os envios pequenos o suficiente para o coletor de destino.
    </Note>
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo-collector">
    No diretório que contém a configuração, execute o coletor e deixe este terminal aberto:

    ```bash
    docker run --rm --name kafka-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Envie a amostra" id="load-metrics">
    Em outro terminal, execute este comando no diretório de download:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @kafka-metrics-demo.json
    ```

    Uma resposta como `{}` ou `{"partialSuccess":{}}` indica que o coletor local aceitou a requisição. Verifique se há erros de exportação no terminal do coletor e aguarde alguns segundos até que os dados sejam encaminhados. Depois de verificar os dados, interrompa o coletor com **Ctrl+C**. Enviar a amostra novamente pode gerar pontos duplicados.
  </Step>

  <Step title="Verifique as métricas" id="verify-demo-metrics">
    Importe o dashboard da [próxima seção](#dashboards), filtre por `ServiceName:kafka-demo` e selecione **Last 2 days**. A amostra inclui métricas de gauge e de soma; não é necessário acesso direto ao banco de dados.
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### Falha na conexão JMX {#jmx-connection-fails}

Verifique a saída do gatherer com `docker compose logs kafka-jmx-gatherer`. Confirme que o JMX está habilitado, que tanto o registro quanto o endpoint RMI anunciado estão acessíveis e que as credenciais JMX e o repositório de certificados confiáveis configurados correspondem aos do broker. Ao usar hostnames de contêineres, os contêineres devem estar na mesma rede prevista.

### Nenhuma métrica aparece {#no-metrics}

* Verifique a saída do gatherer ou do coletor de demonstração em busca de erros de conexão, de autenticação ou de exportação.
* Confira o endpoint OTLP HTTP e a autenticação com base nos detalhes de conexão do seu serviço.
* Verifique a fonte de dados **Metrics**, o filtro por nome do serviço e o intervalo de tempo. Para a demonstração, use **Last 2 days**.
* Para um coletor existente, confirme que o pipeline de métricas inclui o receptor OTLP e um exportador de métricas.
* Confira os nomes das métricas ativas no **Chart Explorer** antes de usar o dashboard de demonstração.

### Conflitos de porta JMX em comandos de cliente do Kafka {#port-conflicts}

Se você executar comandos de cliente do Kafka dentro do contêiner do broker, remova a definição das configurações JMX herdadas do broker para esse comando, de modo que o cliente não tente fazer bind na mesma porta:

```bash
env -u JMX_PORT -u KAFKA_JMX_OPTS kafka-topics --list --bootstrap-server YOUR_KAFKA_HOST:9092
```
