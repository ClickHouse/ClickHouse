Colete métricas do PostgreSQL com o receptor PostgreSQL do OpenTelemetry e envie-as para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar instalar o PostgreSQL.

## Pré-requisitos {#prerequisites}

* Um serviço ClickHouse Observability
* Docker e `curl`
* Para coletar suas próprias métricas: PostgreSQL 14 ou mais recente, acessível a partir do coletor, e um usuário de monitoramento

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você vai executar o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela respectiva chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/metrics`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP do seu coletor, que deve estar acessível (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`), e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, omita o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos para a versão autogerenciada](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint deve estar acessível a partir do contêiner do coletor. Para um coletor de destino em execução neste computador, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento de host.

## Integração com um PostgreSQL existente {#existing-postgres}

<Steps>
  <Step title="Configure o usuário de monitoramento" id="monitoring-permissions">
    Como administrador do PostgreSQL, crie um usuário de monitoramento, caso ainda não tenha um, e conceda acesso às estatísticas:

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    Conceda `CONNECT` em cada banco de dados que você deseja monitorar. Certifique-se de que o PostgreSQL aceite conexões do coletor, verificando as configurações de rede e o `pg_hba.conf`.

    Defina as variáveis de conexão com o banco de dados no mesmo terminal em que definiu as variáveis de conexão OTLP:

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    Se o PostgreSQL estiver no host do Docker, use `host.docker.internal:5432`. Para contêineres em uma rede Docker compartilhada, use o hostname do contêiner do banco de dados e adicione `--network YOUR_NETWORK` ao comando do coletor.
  </Step>

  <Step title="Configure o coletor" id="configure-collector">
    Salve o conteúdo abaixo como `postgres-metrics.yaml`. Substitua a lista `databases` pelos nomes dos seus bancos de dados:

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    Esta configuração habilita o TLS e verifica o certificado do servidor. Se você usa uma CA privada, defina `tls.ca_file` e monte o arquivo da CA no coletor. Para um servidor PostgreSQL local sem TLS, defina `tls.insecure: true`; isso desabilita o TLS na conexão com o banco de dados. Consulte a [configuração do receptor PostgreSQL](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration).
  </Step>

  <Step title="Execute o coletor" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto e aguarde pelo menos dois intervalos de coleta. Ao concluir os testes, interrompa o coletor com **Ctrl+C**.
  </Step>

  <Step title="Verifique as métricas" id="verify-metrics">
    Abra o **Chart Explorer**, selecione sua fonte de dados **Metrics**, filtre por `ServiceName:postgresql-service` e selecione **Last 15 minutes**. Procure por `postgresql.backends`, `postgresql.commits` ou `postgresql.db_size`.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 8,928 pontos de gauge e soma, coletados a cada cinco minutos ao longo de 24 horas. Ela preserva os picos de conexões, a atividade de cache, as reversões e os deadlocks do dataset original. A amostra inclui métricas no nível do banco de dados; a coleta em tempo real também fornece métricas de tabelas e índices.

Defina as [variáveis de conexão](#connection-details) antes de começar.

<Steps>
  <Step title="Baixe as métricas de amostra" id="download-sample">
    [Baixe o pacote de amostra](/pt-BR/assets/postgres-metrics-demo.zip) (cerca de 64 KB) e extraia `postgres-metrics-demo.json` no seu diretório de trabalho.
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo-collector">
    Salve o conteúdo abaixo como `postgres-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      A transformação, usada apenas na demonstração, atualiza os timestamps, preservando os valores de métricas e o intervalo entre os timestamps de início e fim de cada ponto. Remova-a ao coletar métricas reais do PostgreSQL. O limite de lote mantém os envios pequenos o bastante para o coletor de destino.
    </Note>
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo-collector">
    No diretório que contém a configuração, execute o coletor e mantenha este terminal aberto:

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Envie a amostra" id="load-metrics">
    Em outro terminal, execute este comando no diretório onde o arquivo foi baixado:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    Uma resposta como `{}` ou `{"partialSuccess":{}}` indica que o coletor local aceitou a requisição. Verifique se há erros de exportação no terminal do coletor e aguarde alguns segundos até que os dados sejam encaminhados. Depois de verificar os dados, interrompa o coletor com **Ctrl+C**. Enviar a amostra novamente pode gerar pontos duplicados.
  </Step>

  <Step title="Verifique as métricas" id="verify-demo-metrics">
    Importe o dashboard da [próxima seção](#dashboards), filtre por `ServiceName:postgresql-demo` e selecione **Last 2 days**. A amostra inclui métricas de gauge e de soma; não é necessário acesso direto ao banco de dados.
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### O coletor não inicia {#collector-fails-to-start}

Verifique se há erros de configuração na saída do coletor. Confirme se o arquivo de configuração está montado e se as variáveis de conexão estão definidas no terminal em que o Docker é executado.

### Nenhuma métrica aparece {#no-metrics}

Verifique se há erros de conexão com o banco de dados ou erros de exportação na saída do coletor. Confirme que o hostname do banco de dados está acessível a partir do contêiner, que os nomes dos bancos de dados estão corretos e que o PostgreSQL permite a conexão do usuário de monitoramento. Verifique também sua fonte de dados **Metrics**, o filtro por nome do serviço e o intervalo de tempo.

### Erros de autenticação ou TLS {#authentication-errors}

Confirme se o usuário de monitoramento tem as permissões `pg_monitor` e `CONNECT`. Teste as credenciais do banco de dados com `psql` a partir de um host que tenha acesso ao PostgreSQL:

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

Ajuste as configurações de TLS do receptor de acordo com o seu servidor e monte o certificado de CA, se necessário. Em caso de erros de exportação, confira o endpoint OTLP e a autorização com base nos detalhes de conexão do seu serviço.
