Colete métricas do Redis com o receptor Redis do OpenTelemetry e envie-as para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para experimentar a integração sem precisar instalar o Redis.

## Pré-requisitos {#prerequisites}

* Um serviço ClickHouse Observability
* Docker para executar os exemplos do coletor ou uma implantação existente do OpenTelemetry Collector Contrib
* Para suas próprias métricas, uma instância do Redis acessível a partir do coletor e as credenciais, caso o Redis exija autenticação
* Para a demonstração, `curl` para baixar e enviar a amostra

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta Beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Managed Telemetry**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão do Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP a seguir, defina estas variáveis no terminal em que você executará o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela respectiva chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/metrics`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, omita o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos autogerenciado](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint precisa estar acessível a partir do contêiner do coletor. Para um coletor de destino em execução neste computador, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento de host.

## Integração com um Redis existente {#existing-redis}

<Steps>
  <Step title="Verifique a conexão com o Redis" id="verify-redis">
    Em um host com acesso à Redis CLI, verifique sua instância do Redis:

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    O primeiro comando deve retornar `PONG`, e o segundo, informações do servidor. Se o Redis exigir senha, defina `REDISCLI_AUTH` no terminal antes de executar esses comandos. Para usuários de ACL do Redis, passe também `--user YOUR_REDIS_USER`.
  </Step>

  <Step title="Configure o coletor" id="configure-collector">
    Salve o conteúdo abaixo como `redis-metrics.yaml`:

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # Descomente se o Redis exigir autenticação:
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    O receptor coleta métricas do Redis a cada 10 segundos, incluindo uso de memória, clientes, comandos processados, acertos e falhas no keyspace e chaves expiradas ou removidas. O processador de recurso define `service.name` como `redis-service` para permitir a filtragem.

    Se o Redis exigir autenticação, descomente os campos correspondentes do receptor e defina `REDIS_USERNAME` e/ou `REDIS_PASSWORD`. Essas credenciais são usadas na conexão com o Redis; já o valor de autorização OTLP faz a autenticação no coletor de destino. Para Redis com TLS habilitado, configure as opções `tls` do receptor conforme descrito na [documentação do Receptor Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
  </Step>

  <Step title="Execute o coletor" id="run-collector">
    Defina as [variáveis de conexão](#connection-details) e o endereço do Redis acessível a partir do contêiner do coletor. Para um Redis em execução neste computador:

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    Para um Redis remoto, use o hostname e a porta dele. Para um Redis em outro contêiner, use o nome do contêiner e adicione `--network YOUR_NETWORK` ao comando abaixo.

    No diretório que contém `redis-metrics.yaml`, execute:

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha este terminal aberto durante a coleta de métricas. Aguarde pelo menos dois intervalos de coleta antes de conferir a UI.
  </Step>

  <Step title="Verifique as métricas" id="verify-metrics">
    Importe o [dashboard](#dashboards), mapeie os gráficos dele para sua fonte de dados **Metrics** e filtre por `ServiceName:redis-service`. Selecione **Last 15 minutes** e execute o dashboard. Em uma instância saudável do Redis, remoções (evictions) e conexões rejeitadas podem continuar em zero.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

Experimente a integração com 6,912 pontos de dados do tipo gauge e sum, amostrados a cada cinco minutos ao longo de 24 horas. A amostra preserva os padrões de aquecimento de cache, picos de tráfego e memory-pressure do dataset original. Você precisará do Docker, do `curl` e dos detalhes de conexão OTLP HTTP do coletor de destino.

Defina as [variáveis de conexão](#connection-details) antes de começar.

<Steps>
  <Step title="Baixe as métricas de amostra" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo-collector">
    Salve o conteúdo abaixo como `redis-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      A transformada, usada apenas na demonstração, atualiza os timestamps preservando os valores de métricas e o intervalo entre os timestamps de início e fim de cada ponto. Remova-a ao coletar métricas reais do Redis. O limite de lote mantém os envios pequenos o suficiente para o coletor de destino.
    </Note>
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo-collector">
    No diretório que contém a configuração, execute o coletor e deixe este terminal aberto:

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="Envie a amostra" id="load-metrics">
    Em outro terminal, execute este comando no diretório onde o arquivo foi baixado:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    Uma resposta como `{}` ou `{"partialSuccess":{}}` indica que o coletor local aceitou a requisição. Verifique se há erros de exportação no terminal do coletor e aguarde alguns segundos pelo encaminhamento. Depois de verificar os dados, interrompa o coletor com **Ctrl+C**. Enviar a amostra novamente pode gerar pontos duplicados.
  </Step>

  <Step title="Verifique as métricas" id="verify-demo-metrics">
    Importe o dashboard da [próxima seção](#dashboards), filtre por `ServiceName:redis-demo` e selecione **Last 2 days**. A amostra inclui métricas dos tipos gauge e sum; não é necessário acesso direto ao banco de dados.
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### O coletor não inicia {#collector-fails-to-start}

Verifique se há erros de configuração no terminal do coletor. Confirme se o arquivo YAML está montado no caminho documentado e se o endpoint e as variáveis de autenticação obrigatórias estão definidos no terminal em que você executa o Docker.

### Nenhuma métrica aparece {#no-metrics}

* Verifique a saída do coletor em busca de erros de conexão com o Redis ou de exportação OTLP.
* Confirme se o Redis está acessível a partir do contêiner do coletor. No caso de contêineres, verifique se eles compartilham a rede Docker esperada.
* Verifique as credenciais do Redis e se o usuário pode executar os comandos exigidos pelo [receptor Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
* Verifique a fonte de dados **Metrics**, o filtro por nome de serviço e o intervalo de tempo. Para a demonstração, selecione **Last 2 days** e confirme que a transformada de timestamp está incluída no pipeline.
* Para serviços gerenciados, confira o endpoint OTLP HTTP e a chave de API Bearer em **Managed Telemetry**. Para coletores autogerenciados, use as respectivas configurações de autenticação.
