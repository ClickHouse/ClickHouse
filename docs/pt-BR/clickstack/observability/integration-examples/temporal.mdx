O Temporal oferece uma abstração para criar aplicações simples, sofisticadas e resilientes.

<Info>
  **TL;DR**

  Monitore as métricas do Temporal Cloud no ClickHouse Observability com o Receptor do Prometheus do OTel. Inclui um dashboard pré-configurado.
</Info>

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Uma conta existente no Temporal Cloud
* Docker em um host com acesso HTTPS ao Temporal Cloud e ao seu endpoint OTLP

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você executará o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela respectiva chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/metrics`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado">
    Use um endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, remova o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos autogerenciado](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint deve estar acessível a partir do contêiner do coletor. Para um coletor de destino em execução nesta máquina, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento do host.

## Integração com um Temporal Cloud existente {#existing-temporal}

<Steps>
  <Step title="Criar a chave do Temporal Cloud" id="create-temporal-cloud-key">
    Crie uma service account do Temporal Cloud com a função **Metrics Read-Only** e gere uma chave de API, seguindo o [guia de autenticação](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication). A service account e a chave devem ser criadas por um Account Owner ou Global Admin.

    <Warning>
      **Arquivo da chave**

      Armazene a chave de API do Temporal em um arquivo `temporal.key` no mesmo diretório do arquivo de configuração criado abaixo. Armazene apenas a chave, sem o prefixo `Bearer` nem espaços antes ou depois. Essa chave é diferente da sua chave de API do ClickHouse Observability. Certifique-se de que o coletor tenha permissão de leitura no arquivo montado.
    </Warning>
  </Step>

  <Step title="Configurar o coletor OTel" id="custom-otel">
    Execute um Coletor OpenTelemetry autônomo com o Receptor do Prometheus para fazer scrape do Temporal Cloud e encaminhar as métricas para o seu serviço.

    Crie um arquivo chamado `temporal-metrics.yaml` com a seguinte configuração:

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    Esta configuração:

    * Conecta-se ao Temporal Cloud em `metrics.temporal.io`
    * Coleta métricas a cada 60 segundos
    * Coleta as [principais métricas de desempenho](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)
    * **Define o atributo de recurso obrigatório `service.name`** conforme as [convenções semânticas do OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/resource/#service)
    * Envia as métricas para o seu endpoint OTLP por meio de um pipeline dedicado

    Se você tiver várias contas do Temporal Cloud, personalize `service.name` para diferenciá-las (por exemplo, `temporal-prod` e `temporal-dev`).
  </Step>

  <Step title="Executar o coletor" id="run-collector">
    No diretório que contém `temporal-metrics.yaml` e `temporal.key`, defina as [variáveis de conexão](#connection-details) e execute:

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto e verifique se há erros de scrape ou de exportação. Pode levar alguns minutos até que as métricas do Temporal Cloud apareçam. Ao terminar os testes, interrompa o coletor com **Ctrl+C**.
  </Step>

  <Step title="Verificar as métricas no ClickHouse Observability" id="verifying-metrics">
    Após a configuração, faça login no ClickHouse Observability e verifique se as métricas estão chegando:

    1. Abra o **Chart Explorer** e selecione sua fonte de dados **Metrics**
    2. Filtre por `ServiceName:temporal`, selecione **Last 15 minutes** e pesquise métricas que começam com `temporal` (por exemplo, `temporal_cloud_v1_workflow_success_count`, `temporal_cloud_v1_poll_timeout_count`)
    3. Os pontos de dados das métricas devem aparecer de acordo com o intervalo de coleta configurado

    <div className="ch-image-md">
      <Frame>
        ![Métricas do Temporal](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### O coletor não inicia {#collector-fails-to-start}

Verifique se há erros de configuração na saída do terminal. Confirme que os dois arquivos montados existem e que o coletor consegue ler `temporal.key`. Certifique-se de que as variáveis de conexão OTLP estejam definidas no terminal em que o Docker é executado.

### Nenhuma métrica é exibida {#no-metrics}

Verifique os logs do coletor:

```bash
docker logs temporal-metrics-collector
```

Procure erros de scrape, de autenticação ou de exportação. Confirme se o host consegue acessar `https://metrics.temporal.io/v1/metrics` e o seu endpoint OTLP. No **Chart Explorer**, verifique a fonte de dados **Metrics**, o filtro `ServiceName:temporal` e o intervalo de tempo. As métricas do Temporal podem levar alguns minutos para ficar disponíveis e dependem da atividade na sua conta.

### Erros de autenticação {#auth-errors}

Para erros de scrape do Temporal, confirme se `temporal.key` contém uma chave de API válida de uma service account com a função **Metrics Read-Only**. Para erros de exportação OTLP, verifique o endpoint do ClickHouse Observability e o valor de autorização. Trata-se de credenciais distintas.
