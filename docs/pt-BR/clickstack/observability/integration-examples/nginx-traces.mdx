Capture rastreamentos distribuídos do Nginx com o Módulo OpenTelemetry para Nginx e envie-os ao ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar instalar o Nginx.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Para seus próprios rastros, uma instalação do Nginx com o módulo OpenTelemetry e permissão para atualizar a configuração dele; o exemplo com Docker abaixo usa `nginx:1.27-otel`
* Para o conjunto de dados de demonstração, `curl` e Docker

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint e a chave de API usando **Copy connection details** ou selecione **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    O módulo do Nginx exporta via **OTLP/gRPC**, normalmente na porta **4317**. A demonstração em JSON usa **OTLP/HTTP**, normalmente na porta **4318**. Use o endpoint do protocolo correspondente, incluindo `https://` quando o TLS for necessário:

    ```bash
    export OTEL_EXPORTER_OTLP_GRPC_ENDPOINT='https://YOUR_OTEL_HOST:4317'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelos detalhes de conexão do seu serviço. Use o endpoint HTTP base, sem `/v1/traces`; o exportador do coletor adiciona esse caminho.
  </Tab>

  <Tab title="Autogerenciado">
    Use os endpoints OTLP e as configurações de autenticação do seu coletor. Se o coletor não exigir autenticação, omita a diretiva `header authorization` do Nginx e o bloco `headers` do coletor de demonstração. Consulte o [guia de primeiros passos para a versão autogerenciada](/pt-BR/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_GRPC_ENDPOINT='http://YOUR_COLLECTOR_HOST:4317'
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint gRPC precisa estar acessível a partir do Nginx. No Docker Desktop, use `host.docker.internal` para acessar um coletor em execução no host. Para contêineres em uma rede Docker compartilhada, use o nome do contêiner do coletor. Use `http://` para um endpoint local sem TLS.

## Integração com um Nginx existente {#existing-nginx}

<Steps>
  <Step title="Instale o Módulo OpenTelemetry para Nginx" id="install-module">
    A imagem `nginx:1.27-otel` inclui o `ngx_otel_module.so`. Para uma instalação fora do Docker, siga as instruções de instalação indicadas na [documentação do módulo OpenTelemetry para Nginx](https://nginx.org/en/docs/ngx_otel_module.html).
  </Step>

  <Step title="Configure o tracing do Nginx" id="configure-nginx">
    O exemplo de Docker a seguir usa um template para que o script de inicialização do contêiner substitua as variáveis de ambiente de conexão. Salve-o como `nginx.conf.template`. O bloco `location` com `return 200` serve como um teste rápido de funcionamento; na sua aplicação, mantenha a configuração de servidor e de roteamento já existente e adicione as diretivas de tracing mostradas aqui.

    ```nginx
    load_module modules/ngx_otel_module.so;

    events {
        worker_connections 1024;
    }

    http {
        otel_exporter {
            endpoint ${OTEL_EXPORTER_OTLP_GRPC_ENDPOINT};
            header authorization "${OTEL_EXPORTER_OTLP_AUTHORIZATION}";
        }

        otel_service_name "nginx-proxy";
        otel_trace on;

        server {
            listen 80;

            location / {
                otel_trace_context propagate;
                otel_span_name "$request_method $uri";
                otel_span_attr http.status_code $status;
                otel_span_attr http.request.method $request_method;
                otel_span_attr http.route $uri;
                return 200 "Nginx tracing is enabled\n";
            }
        }
    }
    ```

    Salve o seguinte como `compose.yaml` no mesmo diretório:

    ```yaml
    services:
      nginx:
        image: nginx:1.27-otel
        ports:
          - "8081:80"
        environment:
          OTEL_EXPORTER_OTLP_GRPC_ENDPOINT: ${OTEL_EXPORTER_OTLP_GRPC_ENDPOINT}
          OTEL_EXPORTER_OTLP_AUTHORIZATION: ${OTEL_EXPORTER_OTLP_AUTHORIZATION}
          NGINX_ENVSUBST_OUTPUT_DIR: /etc/nginx
          NGINX_ENVSUBST_FILTER: ^OTEL_EXPORTER_OTLP_
        volumes:
          - ./nginx.conf.template:/etc/nginx/templates/nginx.conf.template:ro
    ```

    O filtro de substituição preserva variáveis do Nginx, como `$request_method` e `$uri`. O Nginx não substitui automaticamente variáveis de ambiente do shell em um `nginx.conf` montado diretamente. Fora do Docker, substitua os marcadores de posição de conexão pelos valores reais antes de validar a configuração e restrinja o acesso ao arquivo que contém a chave.
  </Step>

  <Step title="Valide e inicie o Nginx" id="run-nginx">
    Defina as [variáveis de conexão](#connection-details) no mesmo terminal e execute:

    ```bash
    docker compose run --rm nginx nginx -t
    docker compose up -d nginx
    curl http://localhost:8081/
    ```

    Cada requisição gera um span com o método, o caminho, o código de status e a duração. Em uma implantação existente, envie requisições para a URL da sua aplicação. Após alterar o template ou as variáveis de ambiente, execute `docker compose up -d --force-recreate nginx` para aplicar as mudanças.
  </Step>

  <Step title="Verifique os rastros na UI" id="verifying-traces">
    Abra **Busca**, selecione **Traces** e filtre por `ServiceName:nginx-proxy`. Selecione um intervalo de tempo que abranja suas requisições e aguarde alguns segundos pela exportação. Abra um trace para inspecionar seus spans e atributos HTTP.

    <div className="ch-image-lg">
      <Frame>
        ![Rastreamentos do Nginx na Visualização de pesquisa](/images/clickstack/observability-nginx-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 1,000 spans do Nginx distribuídos em nove endpoints, com requisições bem-sucedidas, erros HTTP e latências variadas. Defina as [variáveis de conexão](#connection-details) antes de enviá-la.

<Steps>
  <Step title="Baixe o conjunto de dados de exemplo" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nginx-traces-sample.json
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo-collector">
    Salve o conteúdo a seguir como `nginx-traces-demo.yaml` no diretório de download:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T19:36:05Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nginx-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      O processador `transform/demo_timestamps`, usado apenas nesta demonstração, desloca a amostra para aproximadamente as últimas 24 horas, terminando dois minutos antes da ingestão, sem alterar a duração dos spans nem o padrão de tráfego. Não use esse processador com seus próprios rastreamentos do Nginx, para que os timestamps originais sejam mantidos. Reenviar a amostra pode gerar spans duplicados.
    </Note>
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo-collector">
    <Note>
      Se o coletor de destino estiver em execução neste computador, defina `OTEL_EXPORTER_OTLP_ENDPOINT` como `http://host.docker.internal:4318`. O comando abaixo já inclui o mapeamento de host do Docker.
    </Note>

    Execute o OpenTelemetry Collector Contrib `0.161.0` a partir do diretório que contém a configuração, no mesmo terminal em que você definiu as variáveis de conexão. Mantenha esse terminal aberto:

    ```bash
    docker run --rm --name nginx-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    O receptor local usa a porta `14318` para evitar conflito com um coletor já existente na porta `4318`. O coletor encaminha os rastros para o endpoint configurado, usando as configurações de autenticação definidas acima.
  </Step>

  <Step title="Envie os rastros" id="send-traces">
    Em outro terminal, a partir do diretório de download, envie a amostra original para o coletor local:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nginx-traces-sample.json
    ```

    Uma resposta de sucesso vazia, como `{}` ou `{"partialSuccess":{}}`, indica que o coletor local aceitou a requisição. Verifique se há erros de exportação na saída do coletor e aguarde alguns segundos até que o lote chegue ao seu serviço. Ao terminar, pare o coletor de demonstração com **Ctrl+C**.
  </Step>

  <Step title="Verifique os rastros de demonstração" id="verify-demo-traces">
    Abra **Busca**, selecione **Traces**, filtre por `ServiceName:nginx-proxy` e selecione **Last 2 days** para incluir todo o dataset deslocado. Abra um trace para inspecionar os atributos HTTP.

    <div className="ch-image-lg">
      <Frame>
        ![Exemplo de rastreamentos do Nginx na visualização de pesquisa](/images/clickstack/observability-nginx-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### O Nginx não inicia {#nginx-fails-to-start}

Execute `docker compose run --rm nginx nginx -t` para validar a configuração gerada. Uma diretiva `otel_*` desconhecida ou um arquivo de módulo ausente indica que o módulo não está instalado ou não foi carregado. Verifique se você está usando a imagem `-otel` e se o template está montado no caminho indicado na documentação.

### Nenhum trace aparece {#no-traces}

* Verifique o endpoint gRPC e qualquer autenticação exigida pelo coletor de destino. Os serviços gerenciados usam o prefixo `Bearer`. Não use o endpoint HTTP com o módulo do Nginx.
* Confirme que o endpoint está acessível a partir do contêiner do Nginx e que o esquema dele corresponde à configuração TLS do destino.
* Gere requisições; uma instância idle do Nginx não produz spans de requisição.
* Verifique **Traces**, o filtro por nome do serviço e o intervalo de tempo selecionado. Na demonstração, confirme que `transform/demo_timestamps` está incluído no pipeline do coletor e selecione **Last 2 days**.
* Na demonstração, verifique no terminal do coletor se há erros de autenticação ou de exportação. Compare o endpoint HTTP e o valor de autorização com os seus detalhes de conexão.
* Inspecione os erros do Nginx com `docker compose logs nginx`. Fora do Docker, consulte o log de erros do Nginx.
