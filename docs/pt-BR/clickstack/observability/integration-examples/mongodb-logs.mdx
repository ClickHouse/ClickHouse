Colete os logs do servidor MongoDB com o receptor `filelog` do OpenTelemetry e envie-os para o ClickHouse Observability. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar de uma implantação do MongoDB.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Docker e `curl`
* Para usar seus próprios logs, uma implantação autogerenciada do MongoDB 4.4 ou mais recente, com acesso aos respectivos arquivos de log em JSON

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copy connection details** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você vai executar o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/logs`; o exportador acrescenta o caminho do sinal.
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, remova o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos autogerenciado](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

O endpoint precisa estar acessível a partir do contêiner do coletor. Para um coletor de destino em execução nesta máquina, use `http://host.docker.internal:4318`. Os comandos Docker abaixo já incluem o mapeamento de host.

## Integração com um MongoDB existente {#existing-mongodb}

<Steps>
  <Step title="Verifique a configuração de logging do MongoDB" id="verify-mongodb">
    O MongoDB 4.4 e versões mais recentes geram logs de servidor em JSON estruturado. Verifique a seção `systemLog` no arquivo de configuração do MongoDB. No Linux, um caminho de log comum é `/var/log/mongodb/mongod.log`.

    Se o MongoDB enviar logs apenas para o stdout, configure o logging em arquivo no `mongod.conf`:

    ```yaml
    systemLog:
      destination: file
      path: /var/log/mongodb/mongod.log
      logAppend: true
    ```

    Crie o diretório com permissões que permitam ao MongoDB gravar nele e ao coletor lê-lo. Em implantações com contêineres, compartilhe o diretório de logs com o coletor e certifique-se de que o MongoDB carregue o arquivo de configuração.

    Reinicie o MongoDB de acordo com o seu processo de implantação, por exemplo:

    ```bash
    sudo systemctl restart mongod
    # Ou, para Docker:
    docker restart <mongodb-container>
    ```
  </Step>

  <Step title="Configure o coletor" id="configure-collector">
    Salve o seguinte conteúdo como `mongodb-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb"

          - type: add
            field: resource["service.name"]
            value: "mongodb-service"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, batch]
          exporters: [otlp_http/observability]
    ```

    O analisador sintático lê os campos de timestamp e severidade do MongoDB, move `msg` para o corpo do log e mantém campos como `c`, `ctx`, `id` e `attr` como atributos do log. Mantenha `$$date` exatamente como está: o coletor converte o cifrão escapado no campo `$date` do MongoDB. Com `start_at: end`, o receptor lê apenas as novas entradas.
  </Step>

  <Step title="Execute o coletor" id="run-collector">
    Defina as [variáveis de conexão](#connection-details) e execute o comando a partir do diretório de configuração. Ajuste o caminho de log do host, se necessário. Se os arquivos tiverem permissão de leitura para o grupo, adicione `--group-add LOG_GROUP_ID`, usando o ID numérico do grupo exibido por `ls -ln /var/log/mongodb`.

    ```bash
    docker run --rm --name mongodb-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/mongodb:/var/log/mongodb:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto e gere atividade no servidor para produzir novas entradas de log. Ao terminar os testes, interrompa com **Ctrl+C**.
  </Step>

  <Step title="Verifique os logs" id="verify-logs">
    Abra **Busca**, selecione **Logs**, filtre por `ServiceName:mongodb-service` e selecione **Last 15 minutes**. Devem aparecer mensagens do servidor com timestamps e severidade já interpretados.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 6,956 entradas de log do servidor MongoDB, abrangendo aproximadamente 24 horas. O coletor atualiza os timestamps dessas entradas, preservando as mensagens e os atributos estruturados.

<Steps>
  <Step title="Baixe a amostra" id="download-sample">
    ```bash
    curl -fL -o mongod.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/mongodb/mongod.log
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo">
    Salve o seguinte conteúdo como `mongodb-demo.yaml`:

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb-demo"

          - type: add
            field: resource["service.name"]
            value: "mongodb-demo"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:52.193Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo">
    Defina as [variáveis de conexão](#connection-details) e execute o comando a partir do diretório que contém os dois arquivos:

    ```bash
    docker run --rm --name mongodb-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/mongod.log:/var/log/mongodb/mongod.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto enquanto verifica a ingestão. Ao terminar, interrompa com **Ctrl+C**. Se você executar a demonstração novamente, a amostra será ingerida outra vez com timestamps atualizados.
  </Step>

  <Step title="Verifique os logs de demonstração" id="verify-demo">
    Abra **Busca**, selecione **Logs**, filtre por `ServiceName:mongodb-demo` e selecione **Last 2 days**.

## Solução de problemas {#troubleshooting}

### Nenhum log aparece {#no-logs}

Verifique a saída do coletor em busca de erros de permissão de arquivo, de parsing, de autenticação ou de exportação. Confirme que o seu servidor grava no diretório montado e que os nomes dos arquivos correspondem à lista `include` do receptor. A configuração ativa lê apenas novas entradas.

### Falha no parsing dos logs {#parsing-errors}

Verifique se o arquivo contém um objeto JSON por linha:

```bash
tail -n 1 /var/log/mongodb/mongod.log | python3 -m json.tool
```

O analisador sintático espera logs em JSON do MongoDB 4.4+. Logs de texto legados exigem outro analisador sintático. Mantenha o escape de `$$date` na configuração do coletor.
