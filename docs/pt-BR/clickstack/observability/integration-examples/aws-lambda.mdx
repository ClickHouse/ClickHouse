Colete logs de funções e de extensões com a Rotel Lambda Extension e envie-os diretamente para o ClickHouse Observability via OTLP. A extensão é executada junto com sua função Lambda, então não é preciso usar um coletor separado. Você também pode adicionar instrumentação do OpenTelemetry para coletar rastros.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Uma função AWS Lambda que use implantação via ZIP e um tempo de execução compatível com a [Rotel Lambda Extension](https://github.com/streamfold/rotel-lambda-extension)
* AWS CLI v2 configurada para a região da sua função, caso utilize os exemplos de CLI
* Permissão para atualizar as camadas e as variáveis de ambiente da função
* Acesso de rede da função Lambda ao seu endpoint OTLP, incluindo acesso de saída para funções em uma VPC

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta em versão beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Dados → Telemetria Gerenciada**. Copie o endpoint OTLP HTTP e a chave de API.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão da Telemetria Gerenciada](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Use o endpoint exatamente como exibido, incluindo a porta, como valor de `ROTEL_OTLP_EXPORTER_ENDPOINT` abaixo. Use o endpoint HTTP base, sem o sufixo `/v1/logs`, e defina o protocolo como `http`. O serviço gerenciado exige o cabeçalho `Authorization=Bearer YOUR_API_KEY`.
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP e as configurações de autenticação do seu coletor. Omita `ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS` se o destino não exigir autenticação. O endpoint deve estar acessível a partir do Lambda; `localhost` se refere ao ambiente de execução do Lambda. Consulte o [guia de configuração da versão autogerenciada](/pt-BR/clickstack/self-configured/getting-started/managed).

    Use estes valores de destino nos exemplos de variáveis de ambiente do Lambda e de `rotel.env` abaixo:

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_COLLECTOR_HOST:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=YOUR_INGESTION_KEY"
    ```
  </Tab>
</Tabs>

## Integração com funções Lambda existentes {#existing-lambda}

<Steps>
  <Step title="Escolha a camada adequada da Rotel Lambda Extension" id="choose-layer">
    Escolha uma camada compatível com a arquitetura da sua função (`amd64` ou `arm64`), com o tempo de execução e com a região AWS. Copie o ARN completo e versionado da camada nas [versões do Rotel](https://github.com/streamfold/rotel-lambda-extension/releases). Use esse ARN nos exemplos abaixo; as versões das camadas e a disponibilidade variam conforme a região.
  </Step>

  <Step title="Adicione a camada Rotel à sua função Lambda" id="add-layer">
    Substitua `YOUR_ROTEL_LAYER_ARN` pelo ARN selecionado e `my-function` pelo nome da sua função.

##### Opção 1: Console da AWS {#console}

    1. Abra o console do AWS Lambda
    2. Acesse a sua função Lambda
    3. Role até a seção **Layers** e clique em **Add a layer**
    4. Selecione **Specify an ARN**
    5. Insira o ARN da camada do Rotel:
       ```text
       YOUR_ROTEL_LAYER_ARN
       ```
    6. Clique em **Add**

##### Opção 2: AWS CLI {#cli}

    Exporte a lista atual de camadas:

    ```bash
    aws lambda get-function-configuration \
      --function-name my-function \
      --query 'Layers[].Arn || `[]`' \
      --output json > layers.json
    ```

    Adicione o ARN da camada Rotel como uma string ao array em `layers.json`, mantendo as entradas existentes. Em seguida, aplique a lista completa:

    ```bash
    aws lambda update-function-configuration \
      --function-name my-function \
      --layers file://layers.json
    aws lambda wait function-updated --function-name my-function
    ```

##### Opção 3: AWS SAM {#sam}

    ```yaml
    Resources:
      MyFunction:
        Type: AWS::Serverless::Function
        Properties:
          # ... other configuration ...
          Layers:
            # Keep any existing layer entries here.
            - YOUR_ROTEL_LAYER_ARN
    ```
  </Step>

  <Step title="Configure a extensão para exportar dados para o ClickHouse Observability" id="configure-extension">
    No console do Lambda, abra **Configuration → Environment variables** e adicione as configurações abaixo, mantendo as variáveis já existentes. Estes são valores de configuração do Lambda, e não comandos a serem executados no seu terminal local. Ao inserir os valores no console, omita as aspas que aparecem nos exemplos.

##### Configuração básica (variáveis de ambiente) {#basic-config}

    Adicione estas variáveis de ambiente à sua função Lambda:

    ```bash
    # OTLP HTTP endpoint from Connection details
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http

    # Required for managed ingestion
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer YOUR_API_KEY"

    # Optional: Service name (defaults to Lambda function name)
    ROTEL_OTEL_RESOURCE_ATTRIBUTES="service.name=my-lambda-api,service.version=1.0.0"
    ```

##### Configuração avançada (usando um arquivo .env) {#advanced-config}

    Para configurações mais complexas, crie um arquivo `rotel.env` no pacote da sua função Lambda:

    **rotel.env:**

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer YOUR_API_KEY"
    ROTEL_OTEL_RESOURCE_ATTRIBUTES="service.name=my-lambda-api,deployment.environment=production"
    ```

    Em seguida, defina a variável de ambiente para que aponte para este arquivo:

    ```bash
    ROTEL_ENV_FILE=/var/task/rotel.env
    ```

##### Usando o AWS Secrets Manager ou o Parameter Store {#secrets}

    Você pode armazenar a chave de API no AWS Secrets Manager ou no Parameter Store e referenciar o ARN correspondente em `rotel.env`. Os exemplos abaixo usam autenticação totalmente gerenciada e pressupõem que o segredo contenha apenas a chave de API; o Rotel adiciona o prefixo `Bearer` a partir da configuração. Para um coletor autogerenciado que usa uma chave de ingestão, omita o prefixo `Bearer `. Substitua os nomes de região, conta e segredo usados nos exemplos pelos seus:

    **Exemplo com o AWS Secrets Manager:**

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer ${arn:aws:secretsmanager:us-east-1:123456789012:secret:observability-api-key-abc123}"
    ```

    **Exemplo com o AWS Parameter Store:**

    ```bash
    ROTEL_OTLP_EXPORTER_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
    ROTEL_OTLP_EXPORTER_PROTOCOL=http
    ROTEL_OTLP_EXPORTER_CUSTOM_HEADERS="Authorization=Bearer ${arn:aws:ssm:us-east-1:123456789012:parameter/observability-api-key}"
    ```

    **Permissões do IAM necessárias:**

    Adicione estas permissões ao perfil de execução da sua função Lambda:

    Para o Secrets Manager:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "secretsmanager:GetSecretValue",
            "secretsmanager:BatchGetSecretValue"
          ],
          "Resource": "arn:aws:secretsmanager:us-east-1:123456789012:secret:observability-api-key-*"
        }
      ]
    }
    ```

    Para o Parameter Store:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "ssm:GetParameters"
          ],
          "Resource": "arn:aws:ssm:us-east-1:123456789012:parameter/observability-api-key"
        }
      ]
    }
    ```

    <Note>
      A recuperação de secrets ocorre durante a inicialização e pode aumentar a latência de cold start. Consulte a [configuração de secrets do Rotel](https://github.com/streamfold/rotel-lambda-extension#secrets) para conhecer os formatos suportados e as permissões necessárias. Chaves de criptografia customer-managed também podem exigir a permissão `kms:Decrypt`.
    </Note>
  </Step>

  <Step title="Teste a integração" id="test-integration">
    Invoque sua função Lambda com um evento que ela aceite e certifique-se de que o handler grave um log. Substitua esta carga útil de exemplo caso sua função espere um evento diferente:

    ```bash
    aws lambda invoke \
      --function-name my-function \
      --cli-binary-format raw-in-base64-out \
      --payload '{"test": "data"}' \
      response.json
    ```

    Verifique se há erros nos logs da Lambda:

    ```bash
    aws logs tail /aws/lambda/my-function --follow
    ```
  </Step>

  <Step title="Verifique os logs" id="verify-logs">
    Abra a **Busca** no ClickHouse Observability, selecione sua fonte de dados **Logs** e filtre por `ServiceName:my-lambda-api` se tiver usado o nome de serviço do exemplo. Caso contrário, use o nome da sua função Lambda. Selecione **Last 15 minutes**.

    <div className="ch-image-lg">
      <Frame>
        ![Visualização de logs do Lambda](/images/clickstack/lambda/lambda-log-view.webp)
      </Frame>
    </div>

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes do log do Lambda](/images/clickstack/lambda/lambda-log.webp)
      </Frame>
    </div>

    Procure estes atributos principais nos logs:

    * `service.name`: o nome do serviço que você configurou ou, por padrão, o nome da função Lambda
    * `faas.name`: nome da função AWS Lambda
    * `faas.invocation_id`: ID único da invocação
    * `cloud.provider`: &quot;aws&quot;
    * `cloud.platform`: &quot;aws&#95;lambda&quot;
  </Step>
</Steps>

## Desativando o CloudWatch Logs (otimização de custos) {#disable-cloudwatch}

Por padrão, o AWS Lambda envia todos os logs para o CloudWatch Logs, o que pode sair caro em grande escala. Depois de confirmar que os logs estão chegando ao ClickHouse Observability, você pode desativar o logging do CloudWatch para reduzir custos.

<Steps>
  <Step title="Remova as permissões do CloudWatch do perfil de execução" id="remove-permissions">
    1. Abra o AWS Console e acesse **AWS Lambda**
    2. Acesse sua função Lambda
    3. Selecione **Configuration** → **Permissões**
    4. Clique no nome do perfil de execução para abrir o console do IAM
    5. Remova as permissões de gravação do CloudWatch Logs usadas por esta função. Se o perfil for compartilhado, passe a usar um perfil dedicado antes de fazer essa alteração:
       * Se estiver usando uma política personalizada, edite-a para remover `logs:CreateLogGroup`, `logs:CreateLogStream` e `logs:PutLogEvents`
       * Se estiver usando a política gerenciada da AWS `AWSLambdaBasicExecutionRole`, remova-a do perfil
    6. Salve o perfil
  </Step>

  <Step title="Verifique se o logging do CloudWatch está desativado" id="verify-disabled">
    Invoque sua função novamente e verifique se:

    1. Nenhum evento novo aparece no grupo de logs do CloudWatch da função
    2. Os logs continuam aparecendo no ClickHouse Observability

    ```bash
    aws logs tail /aws/lambda/my-function --since 5m --follow
    ```
  </Step>
</Steps>

## Adicionando instrumentação automática do OpenTelemetry {#auto-instrumentation}

O Rotel pode receber telemetria de uma camada de instrumentação específica da linguagem instalada junto com ele. Siga as [instruções de instrumentação automática do Rotel](https://github.com/streamfold/rotel-lambda-extension#auto-instrumentation) e a documentação da camada de linguagem indicada nelas para escolher uma camada compatível e definir `AWS_LAMBDA_EXEC_WRAPPER`.

Ao adicionar a instrumentação, mantenha a camada do Rotel e todas as camadas já existentes. Depois de invocar a função, selecione sua fonte de dados **Rastros** no ClickHouse Observability e filtre pelo nome do serviço configurado. A correlação entre logs e rastros exige que a instrumentação da aplicação inclua os IDs de rastro e de span nos logs.
