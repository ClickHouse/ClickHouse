Colete arquivos de syslog do EC2 com um coletor OpenTelemetry e envie-os ao ClickHouse Observability com os metadados da instância. Use o [conjunto de dados de demonstração](#demo-dataset) para testar a integração sem precisar de uma instância EC2.

## Pré-requisitos {#prerequisites}

* Um serviço do ClickHouse Observability
* Para seus próprios logs, uma instância EC2 Linux com arquivos de syslog, acesso ao serviço de metadados da instância e permissão para instalar e executar o coletor
* Para a demonstração, o Docker
* `curl` para baixar o coletor ou a amostra

### Detalhes de conexão {#connection-details}

<Tabs>
  <Tab title="Totalmente gerenciado">
    <BetaBadge label="Oferta Beta" />

    Abra o ClickHouse Observability e acesse **Team Settings → Data → Managed Telemetry**. Copie o endpoint OTLP HTTP e a chave de API. Você pode usar **Copiar detalhes de conexão** para copiar a configuração ou **Reveal key** para exibir a chave mascarada.

    <div className="ch-image-lg">
      <Frame>
        ![Detalhes de conexão do Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Para os exemplos de exportador OTLP abaixo, defina estas variáveis no terminal em que você vai executar o coletor:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    Substitua os marcadores de posição pelo endpoint exato do seu serviço, incluindo a porta, e pela respectiva chave de API. Use o endpoint HTTP base, sem o sufixo `/v1/logs`; o exportador acrescenta o caminho do sinal automaticamente.
  </Tab>

  <Tab title="Autogerenciado">
    Use o endpoint OTLP HTTP acessível do seu coletor (por exemplo, `http://YOUR_COLLECTOR_HOST:4318`) e as respectivas configurações de autenticação. Se o seu coletor não exigir autenticação, omita o bloco `headers` do exportador nas configurações abaixo. Consulte o [guia de primeiros passos do modo autogerenciado](/pt-BR/clickstack/self-configured/getting-started/managed) para obter orientações de configuração.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Sua instância EC2 precisa conseguir acessar o endpoint. Na demonstração com Docker, um coletor de destino no seu próprio computador fica acessível em `http://host.docker.internal:4318`; o comando da demonstração já inclui o mapeamento de host.

## Integração com uma instância EC2 existente {#existing-ec2}

Execute estas etapas na instância EC2 da qual você deseja coletar os logs.

<Steps>
  <Step title="Verifique os metadados da instância e o syslog" id="verify-metadata">
    Verifique se o serviço de metadados da instância está acessível via IMDSv2:

    ```bash
    TOKEN=$(curl -fsS --connect-timeout 5 -X PUT \
      -H 'X-aws-ec2-metadata-token-ttl-seconds: 300' \
      http://169.254.169.254/latest/api/token)
    curl -fsS --connect-timeout 5 -H "X-aws-ec2-metadata-token: $TOKEN" \
      http://169.254.169.254/latest/meta-data/instance-id
    ```

    A resposta deve conter o ID da sua instância. O coletor usa esse serviço de metadados para adicionar aos seus logs o ID da instância, o tipo, a região, a zona de disponibilidade e o ID da conta. A configuração abaixo não coleta rótulos (tags) do EC2.

    Localize o seu arquivo de syslog e verifique o formato dele:

    ```bash
    # Ubuntu/Debian
    tail -20 /var/log/syslog

    # Amazon Linux/RHEL
    tail -20 /var/log/messages
    ```

    Use o caminho que existir na sua instância. Se ela gravar apenas no journal do systemd, use o [guia de Systemd/Journald](/pt-BR/clickstack/observability/integration-examples/systemd) para fazer a coleta.
  </Step>

  <Step title="Instale o coletor" id="install-collector">
    Baixe o Coletor OpenTelemetry Contrib `0.161.0` para a arquitetura da sua instância:

    ```bash
    case "$(uname -m)" in
      x86_64) ARCH=amd64 ;;
      aarch64) ARCH=arm64 ;;
      *) echo "Unsupported architecture"; exit 1 ;;
    esac
    curl -fLO "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz"
    tar -xzf "otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz" otelcol-contrib
    sudo install -m 755 otelcol-contrib /usr/local/bin/otelcol-contrib
    /usr/local/bin/otelcol-contrib --version
    ```
  </Step>

  <Step title="Configure o coletor" id="configure-collector">
    Salve a configuração correspondente como `ec2-host-logs.yaml`. Escolha-a de acordo com o formato de timestamp do seu arquivo e ajuste `include` se o caminho do seu syslog for diferente.

    <Tabs>
      <Tab title="Timestamps ISO">
        Para timestamps como `2026-10-15T12:34:56.123456+00:00`:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="Syslog tradicional">
        Para timestamps como `Oct 15 12:34:56`:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/messages]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```

        Os timestamps tradicionais não incluem o ano nem o fuso horário. O analisador sintático infere o ano; defina `location` com o fuso horário IANA do seu host caso ele não registre logs em UTC.
      </Tab>
    </Tabs>

    O receptor preserva a linha de log original e extrai o hostname, a unidade, o PID (quando houver) e a mensagem. O processador `resourcedetection/ec2` adiciona atributos de recurso do EC2. Para coletar também os rótulos da instância, consulte a [configuração do detector EC2](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/processor/resourcedetectionprocessor#aws-ec2) e os requisitos de permissão correspondentes.
  </Step>

  <Step title="Execute o coletor" id="run-collector">
    Defina as [variáveis de conexão](#connection-details) neste terminal e execute o comando a partir do diretório que contém a configuração. O coletor precisa de permissão para ler o arquivo de syslog:

    ```bash
    sudo --preserve-env=OTEL_EXPORTER_OTLP_ENDPOINT,OTEL_EXPORTER_OTLP_AUTHORIZATION \
      /usr/local/bin/otelcol-contrib --config="$(pwd)/ec2-host-logs.yaml"
    ```

    Mantenha o terminal aberto. O receptor usa `start_at: end`; portanto, gere novas atividades que gravem no arquivo de syslog após a inicialização. Para uma coleta contínua, configure um serviço por meio do seu processo de implantação e forneça as variáveis de conexão a esse serviço.
  </Step>

  <Step title="Verifique os logs" id="verify-logs">
    Abra a página **Busca**, selecione a fonte de dados **Logs**, filtre por `ServiceName:ec2-host-service` e selecione **Last 15 minutes**. Expanda um registro e confira `cloud.provider`, `cloud.region`, `cloud.availability_zone`, `host.id` e `host.type` nos atributos de recurso.
  </Step>
</Steps>

## Conjunto de dados de demonstração {#demo-dataset}

A amostra contém 11,658 linhas de syslog, cobrindo um período de 24 horas. O coletor adiciona metadados simulados da instância EC2 e atualiza os timestamps; não é necessário ter uma conta AWS.

<Steps>
  <Step title="Baixar a amostra" id="download-sample">
    ```bash
    mkdir -p ec2-demo
    cd ec2-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="Configure o coletor de demonstração" id="configure-demo-collector">
    Salve o conteúdo como `ec2-host-logs-demo.yaml` no diretório de download:

    ```yaml
    receivers:
      filelog/ec2:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: ec2-demo
          - type: add
            field: resource["service.name"]
            value: ec2-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      resource/ec2_demo:
        attributes:
          - key: cloud.provider
            value: "aws"
            action: insert
          - key: cloud.platform
            value: "aws_ec2"
            action: insert
          - key: cloud.region
            value: "us-east-1"
            action: insert
          - key: cloud.availability_zone
            value: "us-east-1a"
            action: insert
          - key: host.id
            value: "i-0abc123def456789"
            action: insert
          - key: host.type
            value: "t3.medium"
            action: insert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/ec2:
          receivers: [filelog/ec2]
          processors: [memory_limiter, resource/ec2_demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      A transformação de timestamp, usada apenas na demonstração, desloca a amostra para aproximadamente as últimas 24 horas, terminando dois minutos antes da ingestão. Para seus próprios logs, use a [configuração da instância EC2](#existing-ec2) para preservar os timestamps originais.
    </Note>
  </Step>

  <Step title="Execute o coletor de demonstração" id="run-demo-collector">
    Defina as [variáveis de conexão](#connection-details) e, em seguida, execute a partir do diretório de download:

    ```bash
    docker run --rm --name ec2-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/ec2-host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    Mantenha o terminal aberto enquanto o coletor exporta os dados de exemplo e verifique a saída em busca de erros. Iniciar outro contêiner do zero pode duplicar os logs de exemplo.
  </Step>

  <Step title="Verifique os logs de demonstração" id="verify-demo-logs">
    Abra a página **Busca**, selecione sua fonte de dados **Logs**, filtre por `ServiceName:ec2-demo` e selecione **Last 2 days**. Expanda um log e confira os atributos de recurso simulados: `cloud.region` é `us-east-1`, `host.id` é `i-0abc123def456789` e `host.type` é `t3.medium`. Depois de verificar os dados, interrompa o coletor com **Ctrl+C**.

      <Frame>
        ![Logs de demonstração do EC2 na Busca do ClickHouse Observability](/images/clickstack/observability-ec2-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## Solução de problemas {#troubleshooting}

### Metadados da instância EC2 ausentes {#no-metadata}

Execute a verificação de metadados na própria instância EC2. Certifique-se de que o IMDS esteja habilitado e de que as configurações locais de firewall ou proxy permitam requisições para `169.254.169.254`. Se você usa um proxy, exclua esse endereço com `NO_PROXY`. Verifique se há erros de detecção de metadados na saída do coletor. A demonstração usa metadados simulados e não se comunica com o IMDS.

### Nenhum log aparece {#no-logs}

* Confirme se o caminho em `include` existe e se o coletor tem permissão para lê-lo.
* Gere novas entradas de log após a inicialização; `start_at: end` ignora o conteúdo já existente.
* Verifique a saída do coletor em busca de erros de autenticação ou de exportação e confirme se o endpoint está acessível a partir da instância.
* Confira a fonte de dados **Logs**, o filtro de nome do serviço e o intervalo de tempo. Use **Last 2 days** para a demonstração.

### Logs não são analisados (parsing) corretamente {#logs-not-parsing}

Compare os timestamps do seu arquivo com a configuração selecionada. Para syslog tradicional, defina o fuso horário correto do host. Colete apenas arquivos que correspondam ao formato configurado.
