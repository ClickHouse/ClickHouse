Os mapas de serviços mostram visualmente como seus serviços interagem. O ClickHouse Observability monta o grafo associando spans de cliente (requisições de saída) a spans de servidor (requisições de entrada) dentro do mesmo trace, reconstruindo o caminho das requisições entre os serviços.

Clique em **Mapa de serviços** no painel de navegação à esquerda para abrir o grafo completo. Os serviços passam a aparecer assim que você começar a [ingerir dados de rastreamento](/pt-BR/clickstack/observability/ingesting-data/overview) com OpenTelemetry.

## Explorando o mapa de serviços {#exploring-the-service-map}

Cada nó representa um serviço, identificado pelo atributo de recurso `service.name`. As arestas (linhas tracejadas) conectam serviços nos quais um span de cliente em um deles corresponde a um span de servidor em outro. O tamanho do nó reflete o volume relativo de tráfego. No modo **Error rate**, os nós vermelhos indicam serviços com erros no intervalo de tempo selecionado. Use a legenda no canto superior direito para alternar entre **Latency**, **Error rate** e **Throughput**.

A barra de ferramentas acima do mapa permite filtrar e ajustar a visualização.

**Seletor de fontes** — escolha a fonte de traces usada para gerar o mapa, como **Traces**.

**Controle deslizante de amostragem** — ajuste a taxa de amostragem para equilibrar desempenho e acurácia. Taxas mais baixas carregam mais rápido em clusters com grande volume de dados.

**Seletor de intervalo de datas** — defina a janela de tempo dos dados de rastreamento usados para gerar o mapa.

Use os botões **+/-** no canto inferior esquerdo do mapa ou role a página para aumentar e diminuir o zoom.

## Mapas de serviços no nível do trace {#trace-level-service-maps}

Ao inspecionar um trace individual, selecione a aba **Mapa de serviços** para ver como essa requisição específica transitou entre os serviços. Volte para a aba **Trace** para retornar à visualização em cascata.
