As páginas do ClickHouse Observability podem ser abertas por meio de deep links com parâmetros de consulta na URL, permitindo ir direto para uma busca, um dashboard ou um painel específico a partir de um sistema externo (uma notificação de alerta, um runbook, uma tarefa de CI, uma mensagem de conversa etc.).

Os exemplos desta página usam `<YOUR_CLICKSTACK_URL>`. Substitua esse valor pela URL base da sua UI de observabilidade.

<Note>
  Para facilitar a leitura, os exemplos mostram os parâmetros de consulta sem codificação de URL. Ao gerar links programaticamente, aplique a codificação de URL ao valor de cada parâmetro de consulta.
</Note>

<Info>
  **Parâmetro de ID do Serviço Cloud**

  Ao usar a UI do Cloud, os links devem incluir o parâmetro `?chcServiceId=` para identificar qual Serviço do ClickHouse Cloud deve ser carregado, caso o usuário autenticado que acessar o link tenha permissão para usar mais de um Serviço do ClickHouse Cloud.

  Exemplo: abrir a Busca em um Serviço Cloud específico

  ```text
  <YOUR_CLICKSTACK_URL>/search?chcServiceId=abc123
  ```
</Info>

## Busca — `/search` {#search}

A principal visualização de pesquisa de logs/traces. Consulte [Busca](/pt-BR/clickstack/observability/features/search) para obter detalhes sobre a sintaxe de pesquisa.

| Parâmetro       | Formato                                                                    | Descrição                                                                                                                                                                                                |
| --------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`        | string                                                                     | A fonte de dados a ser pesquisada — aceita um ID de fonte de dados ou o **nome** de uma fonte de dados (por exemplo, `Logs`). Somente fontes de dados de log e de trace são compatíveis com esta página. |
| `where`         | string                                                                     | Texto da consulta de filtro, em sintaxe Lucene ou SQL (consulte `whereLanguage`).                                                                                                                        |
| `whereLanguage` | `lucene` | `sql`                                                           | Linguagem de consulta em que `where` está escrito.                                                                                                                                                       |
| `select`        | string                                                                     | Lista de colunas/expressões SQL a serem exibidas na tabela de resultados.                                                                                                                                |
| `filters`       | `{"type":"sql","condition":"<column> IN ('<value1>', '<value2>', ...)"}[]` | Filtros de facetas estruturados, aplicados além de `where`.                                                                                                                                              |
| `orderBy`       | string                                                                     | Expressão SQL de ordenação da tabela de resultados.                                                                                                                                                      |
| `mode`          | `results` | `delta` | `pattern`                                            | Modo de análise ativo. `delta` está disponível apenas para fontes de traces.                                                                                                                             |
| `isLive`        | `true` | `false`                                                           | Indica se o live tail está habilitado (padrão: `true`).                                                                                                                                                  |
| `traceId`       | string                                                                     | Abre diretamente a visualização de trace em cascata do ID do trace informado.                                                                                                                            |
| `from`, `to`    | milissegundos desde a época Unix                                           | Intervalo de tempo absoluto. Se omitido, o padrão são os últimos 15 minutos.                                                                                                                             |

Uma pesquisa salva também pode ser aberta diretamente em `/search/<savedSearchId>`.

### Exemplo: Buscar erros do serviço `checkout` na fonte de dados `Logs` em um intervalo de tempo {#example-search-errors}

```text
<YOUR_CLICKSTACK_URL>/search?source=Logs&from=1735689600000&to=1735693200000&where=level:error&filters=[{"type":"sql","condition":"ServiceName IN ('checkout')"}]
```

### Exemplo: Acessar diretamente a visualização em cascata de um trace {#example-search-trace}

```text
<YOUR_CLICKSTACK_URL>/search?source=Traces&traceId=ba7217967eb90d040b7eb39f97ecc5c4
```

## Dashboards — `/dashboards/<dashboardId>` {#dashboards}

Um dashboard salvo. Omita `<dashboardId>` (`/dashboards`) para abrir um dashboard temporário, não salvo. Consulte [Dashboards](/pt-BR/clickstack/observability/features/dashboards/overview) para obter detalhes sobre como criar dashboards.

| Parâmetro           | Formato                                                                                                                             | Descrição                                                                                                                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `from`, `to`        | milissegundos desde a época Unix                                                                                                    | Intervalo de tempo aplicado a todos os blocos. Se omitido, o padrão são os últimos 15 minutos.                                                                                                                |
| `where`             | string                                                                                                                              | Texto da consulta do filtro no nível do dashboard, aplicado a todos os blocos.                                                                                                                                |
| `whereLanguage`     | `lucene` | `sql`                                                                                                                    | Linguagem de consulta em que `where` está escrito.                                                                                                                                                            |
| `filters`           | array JSON de entradas de valores de filtro                                                                                         | Os valores selecionados nos [filtros personalizados e variáveis](/pt-BR/clickstack/observability/features/dashboards/overview#custom-filters) do dashboard. Consulte [Valores de filtro](#dashboard-filter-values). |
| `granularity`       | `auto` | `30 second` | `1 minute` | `5 minute` | `10 minute` | `15 minute` | `30 minute` | `1 hour` | `12 hour` | `1 day` | `7 day` | Tamanho do bucket para blocos de séries temporais. `auto` escolhe um tamanho de bucket com base no intervalo de tempo selecionado.                                                                            |
| `highlightedTileId` | string                                                                                                                              | Rola a página até um bloco específico e o destaca — útil ao criar links a partir de um alerta.                                                                                                                |

### Valores de filtro {#dashboard-filter-values}

O parâmetro `filters` é um array JSON. Cada entrada define a seleção de um filtro, em uma das seguintes formas:

| Entrada                                                                                                           | Usada para                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{"type":"variable","name":"<variableName>","values":["<value1>","<value2>"]}`                                    | Filtros que são variáveis: valores estáticos, valores de consulta SQL, valores de rótulo PromQL, variáveis de fonte de dados e de conexão, além de filtros de valores de expressão SQL com **Available as variable** habilitado. `name` é o nome da variável do filtro.                                                                       |
| `{"type":"adhoc","name":"<uniqueName>","conditions":[{"key":"<key>","operator":"<operator>","value":"<value>"}]}` | [Filtros ad hoc](/pt-BR/clickstack/observability/features/dashboards/overview#adhoc-filters). `name` é o nome único do filtro, e `operator` é um dos seguintes: `=`, `!=`, `=~`, `!~`, `LIKE`, `NOT LIKE` ou `IN`. `LIKE` e `NOT LIKE` se aplicam apenas a fontes de dados SQL — os filtros ad hoc do Prometheus ignoram condições que os utilizam. |
| `{"type":"sql","condition":"<expression> IN ('<value1>', '<value2>')"}`                                           | Filtros de valores de expressão SQL que não são variáveis. A expressão da condição deve corresponder à **Filter expression** do filtro.                                                                                                                                                                                                       |

Aplicam-se as seguintes regras:

* Uma entrada de variável tem precedência sobre uma entrada `sql` que se refira ao mesmo filtro. Links criados antes da existência de variáveis, que usam entradas `sql` para todos os filtros, continuam funcionando.
* Para variáveis de fonte de dados e de conexão, um valor pode ser o **nome** da fonte de dados ou da conexão em vez do seu ID. Os nomes são comparados primeiro de forma exata e, em seguida, sem distinguir maiúsculas de minúsculas. Isso mantém os links estáveis entre ambientes em que a mesma fonte de dados tem IDs diferentes.
* Um filtro de seleção única usa apenas o primeiro valor.
* Entradas malformadas ou que não correspondam a nenhum filtro do dashboard são ignoradas.

### Exemplo: Abrir um dashboard em um intervalo de tempo com um bloco destacado {#example-dashboard-highlight}

Útil para criar um link de uma notificação de alerta diretamente para o bloco que a disparou.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?from=1735689600000&to=1735693200000&highlightedTileId=chart-1
```

### Exemplo: Selecionar valores em filtros que são variáveis {#example-dashboard-variables}

Seleciona `checkout` e `payments` no filtro cujo nome de variável é `service` e `ERROR` no filtro cujo nome de variável é `severity`.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?filters=[{"type":"variable","name":"service","values":["checkout","payments"]},{"type":"variable","name":"severity","values":["ERROR"]}]
```

### Exemplo: Selecionar uma fonte de dados e uma conexão pelo nome {#example-dashboard-source-variable}

Seleciona a fonte de dados `Production Logs` em uma variável de fonte de dados chamada `logs` e a conexão `Production` em uma variável de conexão chamada `cluster`.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?filters=[{"type":"variable","name":"logs","values":["Production Logs"]},{"type":"variable","name":"cluster","values":["Production"]}]
```

### Exemplo: Adicionar condições de filtragem ad hoc {#example-dashboard-adhoc}

Adiciona duas condições a um filtro ad hoc com o nome único `adhoc`: `ServiceName` igual a `checkout` ou `payments`, e `SeverityText` diferente de `DEBUG`.

```text
<YOUR_CLICKSTACK_URL>/dashboards/64f1c2a1e8b9f3a1b0d2e5c7?filters=[{"type":"adhoc","name":"adhoc","conditions":[{"key":"ServiceName","operator":"IN","value":"checkout"},{"key":"ServiceName","operator":"IN","value":"payments"},{"key":"SeverityText","operator":"!=","value":"DEBUG"}]}]
```

## Chart Explorer — `/chart` {#chart-explorer}

Um criador de gráficos ad hoc e compartilhável.

| Parâmetro    | Formato                          | Descrição                                                                                                                                                                                         |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config`     | JSON                             | A configuração completa do gráfico (fonte de dados, select, where, tipo de gráfico etc.). Normalmente é gerada pelos links de &quot;Compartilhar&quot; do próprio app, e não escrita manualmente. |
| `from`, `to` | milissegundos desde a época Unix | Intervalo de tempo. Se omitido, assume por padrão os últimos 15 minutos.                                                                                                                          |

### Exemplo: Abrir a configuração de um gráfico de latência p99 para um intervalo de tempo {#example-chart-config}

```text
<YOUR_CLICKSTACK_URL>/chart?granularity=auto&from=1785759381784&to=1785762981785&config={"name":"","select":[{"aggFn":"quantile","aggCondition":"","aggConditionLanguage":"lucene","valueExpression":"Duration","level":0.99,"alias":"p99"}],"where":"","whereLanguage":"lucene","displayType":"line","alignDateRangeToGranularity":true,"source":"68814eb5d40a9d0449afc1f2","connection":"68814b6fd40a9d0449afbe78","groupBy":"ServiceName"}
```

## Reprodução de sessão — `/sessions` {#session-replay}

Navegação e reprodução de sessões. Consulte [Reprodução de sessão](/pt-BR/clickstack/observability/features/session-replay) para obter detalhes sobre a funcionalidade.

| Parâmetro       | Formato                          | Descrição                                                                               |
| --------------- | -------------------------------- | --------------------------------------------------------------------------------------- |
| `sessionSource` | string                           | ID ou nome da fonte de dados de sessões.                                                |
| `where`         | string                           | Texto da consulta usada para filtrar a lista de sessões.                                |
| `whereLanguage` | `lucene` | `sql`                 | Linguagem de consulta em que `where` foi escrito.                                       |
| `from`, `to`    | milissegundos desde a época Unix | Intervalo de tempo da lista de sessões. Se omitido, o padrão são os últimos 15 minutos. |
| `sid`           | string                           | Abre uma sessão específica pelo ID.                                                     |
| `sfrom`, `sto`  | milissegundos desde a época Unix | Janela de tempo da sessão aberta (usado com `sid`).                                     |

### Exemplo: Navegar pelas reproduções de sessão em um intervalo de tempo {#example-sessions-time-range}

```text
<YOUR_CLICKSTACK_URL>/sessions?from=1735689600000&to=1735693200000
```

## Serviços — `/services` {#services}

Dashboards de HTTP, banco de dados e erros por serviço.

| Parâmetro       | Formato                                                                    | Descrição                                                                          |
| --------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `tab`           | `http` | `database` | `errors`                                             | Subaba do dashboard de serviço que é exibida. Padrão: `http`                       |
| `source`        | string                                                                     | ID da fonte de traces.                                                             |
| `service`       | string                                                                     | Nome do serviço selecionado.                                                       |
| `where`         | string                                                                     | Texto da consulta de filtro.                                                       |
| `whereLanguage` | `lucene` | `sql`                                                           | Linguagem de consulta em que `where` foi escrito (nesta página, o padrão é `sql`). |
| `filters`       | `{"type":"sql","condition":"<column> IN ('<value1>', '<value2>', ...)"}[]` | Valores da barra de filtros do dashboard.                                          |
| `from`, `to`    | milissegundos desde a época Unix                                           | Intervalo de tempo. Se omitido, o padrão são os últimos 15 minutos.                |

### Exemplo: Visualizar o dashboard do banco de dados de um serviço em um intervalo de tempo {#example-services-database}

```text
<YOUR_CLICKSTACK_URL>/services?tab=database&service=checkout&from=1735689600000&to=1735693200000
```

### Exemplo: Visualizar o dashboard de erros de um serviço {#example-services-errors}

```text
<YOUR_CLICKSTACK_URL>/services?tab=errors&service=payments
```
