O ClickHouse Observability inclui controle de acesso baseado em funções (RBAC), o que permite definir funções personalizadas com permissões granulares sobre [dashboards](/pt-BR/clickstack/observability/features/dashboards/overview), [buscas salvas](/pt-BR/clickstack/observability/features/search), fontes de dados, [alertas](/pt-BR/clickstack/observability/features/alerts), webhooks e notebooks. As permissões funcionam em dois níveis: acesso por recurso (sem acesso, leitura ou gerenciamento para cada tipo de recurso) e regras granulares opcionais que restringem o acesso a recursos individuais por nome, rótulo ou ID. O serviço vem com três papéis predefinidos, e você pode criar funções personalizadas de acordo com as necessidades da sua equipe.

## Pré-requisitos de acesso de usuários {#user-access-prerequisites}

O serviço faz a autenticação por meio do ClickHouse Cloud. Os usuários devem pertencer à sua organização do ClickHouse Cloud e ter acesso ao serviço de Observability. Consulte [Gerenciar usuários da nuvem](/pt-BR/products/cloud/guides/security/cloud-access-management/manage-cloud-users) para saber como gerenciar os membros da organização.

Os níveis de acesso ao Console SQL do Cloud correspondem aos seguintes níveis de acesso ao Observability:

| Acesso ao Console SQL do Cloud              | Acesso ao Observability                                                                                   |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **SQL Console Admin** (Acesso total)        | Acesso total ao serviço. Obrigatório para habilitar [alertas](/pt-BR/clickstack/observability/features/alerts). |
| **SQL Console Read Only** (Somente leitura) | Pode visualizar dados de observabilidade e criar dashboards.                                              |
| **Sem acesso**                              | Não pode acessar o serviço.                                                                               |

Abra **Team Settings → Membros e funções** para ver os membros da equipe e suas funções atuais no Observability. Selecione **Gerenciar no console** para gerenciar os membros da organização no ClickHouse Cloud.

## Papéis predefinidos {#built-in-roles}

O serviço inclui três papéis do sistema, que não podem ser editados nem excluídos. Por padrão, a função de administrador é atribuída ao criador da equipe.

| Permissão                         | Admin | Membro | ReadOnly |
| --------------------------------- | :---: | :----: | :------: |
| Ler todos os recursos             |   ✓   |    ✓   |     ✓    |

| Gerenciar buscas salvas           |   ✓   |    ✓   |          |
| Gerenciar fontes de dados         |   ✓   |    ✓   |          |
| Gerenciar alertas                 |   ✓   |    ✓   |          |
| Gerenciar webhooks                |   ✓   |    ✓   |          |
| Gerenciar notebooks               |   ✓   |    ✓   |          |

## Atribuição de funções a membros da equipe {#assigning-roles}

A aba **Membros e funções** em **Team Settings** lista os membros da equipe e a função atual de cada um. Para alterar uma função, clique em **Editar** ao lado do nome do usuário e selecione uma nova função. Cada usuário tem exatamente uma função.

### Função padrão de novo usuário {#default-new-user-role}

Em **Team Settings** → **Membros e funções**, use a opção **Função Padrão de Novo Usuário**, abaixo da lista de funções, para escolher a função atribuída aos usuários que ingressam automaticamente na equipe. Se nenhuma função padrão for definida, os novos usuários recebem a função **Membro**.

## Permissões de função {#role-permissions}

### Permissões de recursos {#resource-permissions}

Cada função concede um nível de acesso por tipo de recurso. Os três níveis são:

| Nível de acesso | O que permite                                                                     |
| --------------- | --------------------------------------------------------------------------------- |
| **Sem Acesso**  | O tipo de recurso fica totalmente oculto para a função.                           |
| **Leitura**     | Visualizar o recurso e sua configuração, mas não criá-lo, editá-lo nem excluí-lo. |
| **Gerenciar**   | Controle total — criar, editar e excluir recursos desse tipo.                     |

Os tipos de recurso que você pode controlar são:

* **[Dashboards](/pt-BR/clickstack/observability/features/dashboards/overview)** — layouts de dashboards e gráficos salvos.
* **[Buscas salvas](/pt-BR/clickstack/observability/features/search)** — consultas persistidas de logs/traces/eventos.
* **Fontes de dados** — fontes usadas para consultar dados de observabilidade.
* **[Alertas](/pt-BR/clickstack/observability/features/alerts)** — regras de alerta e suas configurações de notificação.
* **Webhooks** — destinos de notificação de saída (como Slack, PagerDuty e endpoints HTTP genéricos) para os quais os [alertas](/pt-BR/clickstack/observability/features/alerts) enviam notificações. Não se trata da API de observabilidade.
* **Notebooks** — notebooks colaborativos de investigação.

### Permissões administrativas {#administrative-permissions}

Além das permissões de recursos, cada função inclui duas configurações administrativas:

* **Usuários** (Sem Acesso · Leitura) — controla se a função pode visualizar os membros da equipe e suas funções. Para gerenciar os membros da organização, use **Gerenciar no console**.
* **Equipe** (Leitura · Gerenciar) — controla se a função pode visualizar ou modificar configurações da equipe, como políticas de segurança e a configuração de RBAC.

### Regras de acesso granulares {#fine-grained-access-rules}

Dashboards, Buscas Salvas, Fontes de dados e Notebooks oferecem controles granulares que restringem o acesso a recursos individuais dentro de uma categoria. Use-os quando precisar limitar uma função a recursos específicos, em vez de conceder acesso irrestrito a todo um tipo de recurso.

#### Acesso padrão vs. controles granulares {#access-control-modes}

Cada tipo de recurso tem um **modo de controle de acesso**:

* **Acesso Padrão** — aplica um único nível de acesso (Sem Acesso, Leitura ou Gerenciar) a todos os recursos desse tipo.
* **Controles Granulares** — permite definir regras de acesso que correspondem a recursos específicos com base em condições. Recursos que não correspondem a nenhuma regra ficam, por padrão, sem acesso.

Para alternar entre os modos, clique na seta para expandir um tipo de recurso no editor de funções e, em seguida, use o botão de alternância do **modo de controle de acesso**.

#### Configurando regras de acesso {#configuring-access-rules}

Cada regra de acesso é composta por uma **condição** e um **nível de acesso**. As condições identificam recursos com base em suas propriedades:

<div className="ch-image-md">
  <Frame>
    ![Dica de ferramenta da condição: identifique recursos por Name ou Rótulo (exibidos no título) ou por ID (encontrado na URL)](/images/clickstack/rbac/condition-tip.webp)
  </Frame>
</div>

| Campo de condição | Operadores       | O que corresponde                                                                                                                                                         | Exemplo                                                                                             |
| ----------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **Name**          | `is`, `contains` | O nome de exibição do recurso — por exemplo, o título do dashboard.                                                                                                       | Name contains `production` — corresponde a qualquer dashboard com &quot;production&quot; no título. |
| **Rótulo**           | `is`, `contains` | Rótulos atribuídos ao recurso pelo painel de rótulos no canto superior direito da visualização do recurso. Disponível apenas para Dashboards, Buscas Salvas e Notebooks. | Rótulo is `critical` — corresponde a recursos com o rótulo &quot;critical&quot;.                       |
| **ID**            | `is`, `contains` | O identificador do recurso, exibido na barra de URL ao abrir o recurso.                                                                                                   | ID is `abc123` — corresponde a um único recurso específico.                                         |

A captura de tela a seguir mostra o ID do dashboard destacado na barra de URL e um rótulo &quot;TESTING&quot; visível no painel de rótulos (canto superior direito).

<div className="ch-image-lg">
  <Frame>
    ![Dashboard mostrando o ID do recurso na barra de URL e um rótulo no canto superior direito](/images/clickstack/rbac/dashboard-id-and-tag-example.webp)
  </Frame>
</div>

Você pode adicionar várias regras por tipo de recurso. Cada regra é avaliada de forma independente, com lógica OR — um recurso fica acessível se corresponder a **qualquer** regra. Recursos que não correspondem a nenhuma regra ficam inacessíveis.

<div className="ch-image-md">
  <Frame>
    ![Dica de ferramenta de regras de acesso com lógica OR](/images/clickstack/rbac/access-rules-tip.webp)
  </Frame>
</div>

**Exemplo**: para conceder a uma função acesso read-only a dashboards de teste, expanda Dashboards, mude para Controles Granulares e adicione duas regras:

* **Name** `contains` `testing` com nível de acesso **Leitura**
* **Rótulo** `is` `testing` com nível de acesso **Leitura**

Qualquer dashboard que corresponda a uma das regras fica acessível.

<div className="ch-image-md">
  <Frame>
    ![Duas regras de acesso granulares combinadas com OR: Name contains testing com acesso Leitura e Rótulo is testing com acesso Leitura](/images/clickstack/rbac/dashboard-fine-grained-example.webp)
  </Frame>
</div>

## Políticas de segurança {#security-policies}

Em **Team Settings → Membros e funções → Políticas de segurança**, a opção **Desativar exportação de dados** oculta os controles de download e cópia de dados de log, incluindo os detalhes das linhas, para todos os membros da equipe. Os usuários ainda podem selecionar texto na tela, e a API e o servidor MCP continuam retornando dados. Essa configuração não impede o acesso aos dados subjacentes.

Os controles de IA Generativa ficam em **Team Settings → API e agentes → Configurar IA Generativa**. Consulte [Configurar IA Generativa](/pt-BR/clickstack/observability/managing/config#generative-ai) para mais detalhes.
