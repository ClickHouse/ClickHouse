Abra **Team Settings** no ClickHouse Observability para gerenciar o acesso aos dados, as conexões de API e de agente, as integrações e as configurações de consulta. As seções abaixo correspondem às abas da aplicação. O ClickHouse cuida da ingestão, dos esquemas, da infraestrutura e do escalonamento.

## Dados {#data}

Abra **Team Settings → Dados** para ver suas fontes de dados e os detalhes de conexão para o envio de telemetria.

### Fontes {#datasource-settings}

A seção **Fontes** lista as fontes de dados fornecidas pelo seu serviço gerenciado:

| Fonte de dados | Dados                                      |
| -------------- | ------------------------------------------ |
| **Logs**       | Eventos de log                             |
| **Traces**     | Spans de rastreamento distribuído          |
| **Metrics**    | Dados de métricas                          |
| **Sessions**   | Dados de reprodução de sessão do navegador |

Cada fonte de dados exibe a conexão de leitura associada e, quando aplicável, o nome da tabela. Use o interruptor à direita de uma fonte de dados para ativá-la ou desativá-la. Ao desativar uma fonte de dados, sua configuração é mantida, mas ela deixa de aparecer nos seletores de fontes e não é mais selecionada automaticamente. Isso não interrompe a ingestão de telemetria nem exclui os dados armazenados. Para disponibilizá-la novamente nos seletores, basta ativá-la outra vez.

### Telemetria Gerenciada {#managed-telemetry}

Abaixo de **Fontes**, a seção **Telemetria Gerenciada** mostra o status do armazenamento e do coletor OpenTelemetry, além dos detalhes de conexão para enviar dados ao seu serviço.

* Selecione **URL**, **Collector config** ou **Env vars** para visualizar os detalhes de conexão no formato desejado.
* Use **Copy connection details** para copiar a configuração. Selecione **Reveal key** quando precisar visualizar as credenciais mascaradas.
* Use **Send a Test Log** para enviar um log de amostra ao serviço.

Para obter instruções sobre como configurar suas aplicações e coletores, consulte [Ingestão de dados](/pt-BR/clickstack/observability/ingesting-data/overview).

### Lista de Acesso por IP {#ip-access-list}

Em **Telemetria Gerenciada**, use **Lista de Acesso por IP → Editar** para controlar quais endereços IP ou intervalos CIDR podem acessar os endpoints do seu coletor.

### Endpoints privados {#private-endpoints}

Use **Configurar endpoint privado** para configurar a conectividade privada com o seu coletor. Em implantações na AWS, essa configuração usa o AWS PrivateLink. O link **endpoints privados** abre os endpoints privados da organização no Console do Cloud.

### Zona de perigo {#service-settings}

**Excluir warehouse** exclui o warehouse de Observabilidade e todos os seus serviços. Os serviços de leitura são excluídos primeiro e, em seguida, o serviço primário. Use esta opção somente quando não precisar mais do warehouse nem de seus dados.

## Membros e funções {#members-and-roles}

Abra **Team Settings → Membros e funções** para revisar as funções RBAC e a função padrão atribuída a novos usuários. Use **Gerenciar no console** para gerenciar os membros da equipe no ClickHouse Cloud. Consulte [Controle de acesso baseado em funções](/pt-BR/clickstack/observability/managing/rbac).

## API &amp; Agents {#api-and-agents}

Acesse **Team Settings → API &amp; Agents** para gerenciar chaves de ingestão, encontrar identificadores de serviço, conectar agentes e configurar recursos de IA.

### API keys de ingestão {#ingestion-api-keys}

A seção **Chaves de API** exibe seu **Team ID**, seu **ID do Serviço** e as chaves de ingestão. As chaves de ingestão autenticam a telemetria enviada ao coletor OpenTelemetry.

Informe um nome e selecione **Create key** para emitir uma chave para uma fonte de dados ou um ambiente. As chaves existentes contam com os controles **Reveal key**, **Copy key**, **Freeze** e **Revoke**. As alterações entram em vigor em cerca de um minuto.

O link **Manage Chaves de API**, à parte, abre as configurações da organização do ClickHouse Cloud referentes às chaves usadas com a API de gerenciamento.

### Conectar um agente {#connect-an-agent}

Em **Connect your AI agents**, use **Enable MCP for this service** para controlar o servidor MCP remoto. Selecione seu cliente e copie a configuração gerada, que inclui o ID do Serviço para que as requisições do agente sejam direcionadas ao seu serviço. **Manage sessions** abre o Console do Cloud, onde você pode revisar as sessões MCP. O endpoint MCP na nuvem usa OAuth: faça login com sua conta do ClickHouse Cloud quando o cliente solicitar. Consulte [Conectar um cliente MCP](/pt-BR/clickstack/observability/mcp#managed-connecting-a-client) para ver as instruções de configuração e a lista de clientes compatíveis.

### Use a API {#use-the-api}

Use a [API do ClickHouse Observability](/pt-BR/clickstack/observability/api-reference) para gerenciar dashboards, alertas e outros recursos de forma programática. As requisições à API são autenticadas com o ID e o secret de uma chave de API do ClickHouse Cloud, por meio de autenticação básica HTTP. Consulte [Autenticação da API](/pt-BR/clickstack/observability/api-reference#authentication) para conhecer as permissões necessárias e a configuração da chave.

As credenciais de API são diferentes da API key de ingestão disponível em **Dados → Telemetria Gerenciada**. Os clientes MCP usam OAuth em vez de qualquer uma dessas chaves.

### Exportar para Terraform {#export-to-terraform}

**Exportar para Terraform** está marcado como **Experimental**. Selecione os tipos de recurso que deseja incluir e use **Download import file** para adicioná-los a um projeto Terraform. A UI fornece o comando para gerar a configuração dos recursos com o provedor ClickHouse. As conexões gerenciadas pela plataforma são exportadas como `locals` somente para referência.

Os alertas em pesquisas salvas e em painéis do dashboard são exportados. Um arquivo que contém um alerta de painel requer a versão 3.28.0 ou posterior do Provedor Terraform do ClickHouse. Alertas do Chart Explorer não são exportados, assim como alertas de painel cujo painel não tenha um nome único e não vazio no respectivo dashboard. A configuração gerada para um alerta de painel define `dashboard_id` e `tile_id` como valores literais: substitua-os por referências ao recurso `clickhouse_clickstack_dashboard` antes de aplicá-la.

### Configurar IA Generativa {#generative-ai}

Use **Configure IA Generativa** para habilitar ou desativar as funcionalidades de IA Generativa do serviço, entre elas o Chart AI Assistant no Chart Explorer e os [AI Notebooks](/pt-BR/clickstack/observability/notebooks).

## Integrações {#integrations}

Abra **Team Settings → Integrações** para gerenciar webhooks. Selecione **Add Webhook** para adicionar uma integração para notificações de alerta. Consulte [Alertas](/pt-BR/clickstack/observability/features/alerts) para saber como configurar alertas.

## Configurações de consulta {#query-settings}

Abra **Team Settings → configurações de consulta** para ajustar a forma como a aplicação consulta o ClickHouse. Clique em **Editar** ao lado de uma configuração para alterá-la. A aba aparece marcada como **Experimental** na UI.

| Configuração                          | Finalidade                                                                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **Search Row Limit**                  | Limita o número de linhas retornadas por consulta na página Busca e nos painéis do dashboard de busca.                              |
| **Query Timeout (seconds)**           | Define o tempo máximo de execução de uma consulta.                                                                                  |
| **Max Rows to Read (METADATA ONLY)**  | Limita o número de linhas da tabela varridas por consultas de metadados.                                                            |
| **Filter Keys Fetch Limit**           | Controla quantas chaves de filtro são obtidas quando você seleciona **More filters** na página Busca.                               |
| **Field Metadata Queries**            | Controla se a aplicação obtém metadados de campos do ClickHouse.                                                                    |
| **Parallelize Queries When Possible** | Permite que consultas elegíveis baseadas em janelas sejam executadas em paralelo. Isso pode aumentar o pico de carga no ClickHouse. |

A aba também inclui controles para o limiar de bloqueio flexível do histograma de busca e para as durações das janelas de busca. Use **Reset to default** para restaurar os valores padrão das configurações de consulta.

## Migração de esquema {#schema-migrations}

Abra **Team Settings → Migração de esquema** para ver o histórico de migrações.

Para as configurações de fonte de dados e schema em ambientes autogerenciados, consulte [Configurações de fonte de dados e schema em ambientes autogerenciados](/pt-BR/clickstack/self-configured/managing/config).
