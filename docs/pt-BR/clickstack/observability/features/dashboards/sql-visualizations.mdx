O ClickHouse Observability oferece suporte a visualizações baseadas em consultas SQL brutas. Com isso, você tem controle total sobre a lógica da consulta e, ao mesmo tempo, mantém a integração com os intervalos de tempo e filtros do dashboard e com a renderização de gráficos.

As visualizações baseadas em SQL são úteis quando você precisa ir além do Chart Explorer nativo — por exemplo, para fazer junções entre tabelas ou criar agregações complexas que não são suportadas pelo criador de gráficos.

## Criando uma visualização baseada em SQL {#creating-a-raw-sql-chart}

Para criar uma visualização baseada em SQL, abra o editor de um painel do dashboard e selecione **SQL**.

<div className="ch-image-lg">
  <Frame>
    ![Editor de visualização SQL com instruções de consulta e macros](/images/clickstack/observability-sql-editor.png)
  </Frame>
</div>

Em seguida:

1. Selecione a **Conexão** em que a consulta será executada.
2. Opcionalmente, selecione uma **Fonte de dados** — isso permite aplicar filtros no nível do painel ao seu gráfico por meio da macro `$__filters`.
3. Escreva sua consulta SQL no editor, usando parâmetros de consulta e macros para integrá-la ao intervalo de tempo, aos filtros e às variáveis do dashboard.
4. Clique em **Executar** para pré-visualizar os resultados e, depois, em **Salvar** para salvar a visualização.

## Parâmetros de consulta {#query-parameters}

Os [parâmetros de consulta](/pt-BR/reference/syntax#defining-and-using-query-parameters) permitem que seu SQL faça referência ao intervalo de tempo e à granularidade atuais do dashboard. Eles seguem a sintaxe de consultas parametrizadas do ClickHouse: `{paramName:Type}`.

### Parâmetros disponíveis {#available-parameters}

Os parâmetros disponíveis dependem do tipo de gráfico:

**Gráficos de série temporal (incluindo barras empilhadas):**

| Parâmetro                       | Tipo  | Descrição                                                                  |
| ------------------------------- | ----- | -------------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Início do intervalo de datas do dashboard (milissegundos desde o epoch)    |
| `{endDateMilliseconds:Int64}`   | Int64 | Fim do intervalo de datas do dashboard (milissegundos desde o epoch)       |
| `{intervalSeconds:Int64}`       | Int64 | Tamanho do intervalo de tempo em segundos (com base na granularidade)      |
| `{intervalMilliseconds:Int64}`  | Int64 | Tamanho do intervalo de tempo em milissegundos (com base na granularidade) |

**Gráficos de tabela, de pizza e numéricos:**

| Parâmetro                       | Tipo  | Descrição                                                               |
| ------------------------------- | ----- | ----------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | Início do intervalo de datas do dashboard (milissegundos desde o epoch) |
| `{endDateMilliseconds:Int64}`   | Int64 | Fim do intervalo de datas do dashboard (milissegundos desde o epoch)    |

## Macros {#macros}

Macros são atalhos que se expandem em expressões comuns do SQL do ClickHouse. Elas começam com o prefixo `$__` e são substituídas antes de a consulta ser enviada ao ClickHouse.

### Macros de limite de tempo {#time-boundary-macros}

Essas macros retornam uma expressão do ClickHouse que representa o horário de início ou de término do dashboard. Elas não recebem argumentos.

| Macro            | Expande para                                                          | Tipo da coluna |
| ---------------- | --------------------------------------------------------------------- | -------------- |
| `$__fromTime`    | `toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))` | DateTime       |
| `$__toTime`      | `toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))`   | DateTime       |
| `$__fromTime_ms` | `fromUnixTimestamp64Milli({startDateMilliseconds:Int64})`             | DateTime64     |
| `$__toTime_ms`   | `fromUnixTimestamp64Milli({endDateMilliseconds:Int64})`               | DateTime64     |
| `$__interval_s`  | `{intervalSeconds:Int64}`                                             | Int64          |

### Macros de filtro de tempo {#time-filter-macros}

Essas macros geram um fragmento de cláusula `WHERE` que filtra uma coluna pelo intervalo de tempo do dashboard.

| Macro                                 | Descrição                                                                     |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| `$__timeFilter(column)`               | Filtra uma coluna `DateTime` pelo intervalo do dashboard                      |
| `$__timeFilter_ms(column)`            | Filtra uma coluna `DateTime64` (em milissegundos) pelo intervalo do dashboard |
| `$__dateFilter(column)`               | Filtra uma coluna `Date` pelo intervalo do dashboard                          |
| `$__dateTimeFilter(dateCol, timeCol)` | Filtra usando colunas `Date` e `DateTime` separadas                           |
| `$__dt(dateCol, timeCol)`             | Nome alternativo para `$__dateTimeFilter`                                     |

**Exemplo de expansão** de `$__timeFilter(TimestampTime)`:

```sql
TimestampTime >= toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
AND TimestampTime <= toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
```

### Macros de intervalo de tempo {#time-interval-macros}

Essas macros agrupam uma coluna de timestamp em intervalos correspondentes à granularidade do dashboard. Normalmente, são usadas nas cláusulas `SELECT` e `GROUP BY` de gráficos de série temporal. Essas macros estão disponíveis apenas para visualizações do tipo **série temporal**, incluindo barras empilhadas.

| Macro                        | Descrição                                                              |
| ---------------------------- | ---------------------------------------------------------------------- |
| `$__timeInterval(column)`    | Agrupa uma coluna `DateTime` em intervalos de `intervalSeconds`        |
| `$__timeInterval_ms(column)` | Agrupa uma coluna `DateTime64` em intervalos de `intervalMilliseconds` |

**Exemplo de expansão** de `$__timeInterval(TimestampTime)`:

```sql
toStartOfInterval(toDateTime(TimestampTime), INTERVAL {intervalSeconds:Int64} second)
```

### Macro de filtro do dashboard {#dashboard-filter-macro}

| Macro        | Descrição                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| `$__filters` | Substituído pelas condições de filtragem no nível do dashboard (requer que uma Fonte de dados esteja selecionada) |

Quando uma **Fonte de dados** está selecionada no gráfico e há filtros de dashboard ativos, `$__filters` se expande para as condições `WHERE` SQL correspondentes. Quando nenhuma fonte de dados está selecionada ou nenhum filtro está aplicado, ele se expande para `(1=1)`; portanto, é sempre seguro incluí-lo em uma cláusula `WHERE`.

Somente os filtros com a opção **Condição de filtragem por difusão** habilitada são aplicados por `$__filters`. Filtros expostos como variáveis são referenciados explicitamente, conforme descrito abaixo.

### Macros de variáveis de dashboard {#dashboard-variables}

Quando um filtro de dashboard está [disponível como variável](/pt-BR/clickstack/observability/features/dashboards/overview#dashboard-variables), seus valores selecionados podem ser referenciados em qualquer parte da consulta. Essas macros só estão disponíveis em blocos de um dashboard que declare pelo menos uma variável.

| Macro                                         | Descrição                                                                                                                                     |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | É expandida para `toString(<filter expression>) IN ($variable)` quando há valores selecionados para `variable` e, caso contrário, para `1=1`. |
| `$__filter(<expression>, $<variable>)`        | É expandida para `<expression> IN ($variable)` quando há valores selecionados para `variable` e, caso contrário, para `1=1`.                  |
| `$__conditionalAll(<condition>, $<variable>)` | É expandida para `<condition>` quando a variável tem uma seleção e, caso contrário, para `1=1`.                                               |

Os valores de uma variável também podem ser interpolados diretamente como `$name` ou `${name}`, com um formato opcional: `${name:sqlstring}` (o padrão), `${name:csv}` ou `${name:regex}`. No formato padrão, uma referência direta é renderizada como `NULL` enquanto nenhum valor estiver selecionado; por isso, prefira as macros acima sempre que um predicado for esperado.

## Como os resultados da consulta são plotados {#how-results-are-plotted}

A UI mapeia automaticamente as colunas do resultado para os elementos do gráfico com base no tipo de coluna. As regras de mapeamento variam de acordo com o tipo de gráfico.

### Gráficos de série temporal {#line-and-stacked-bar-charts}

| Função             | Tipo da coluna                       | Descrição                                                                                   |
| ------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------- |
| **Timestamp**      | Primeira coluna `Date` ou `DateTime` | Usada como eixo x.                                                                          |
| **Valor da série** | Todas as colunas numéricas           | Cada coluna numérica é plotada como uma série separada. Normalmente, são valores agregados. |
| **Nomes de grupo** | Colunas `String`, `Map` ou `Array`   | Opcional. Linhas com valores de grupo diferentes são plotadas como séries separadas.        |

### Gráfico de pizza {#pie-chart}

| Função              | Tipo da coluna                     | Descrição                                               |
| ------------------- | ---------------------------------- | ------------------------------------------------------- |
| **Valor da fatia**  | Primeira coluna numérica           | Determina o tamanho de cada fatia.                      |
| **Rótulo da fatia** | Colunas `String`, `Map` ou `Array` | Opcional. Cada valor único se torna um rótulo de fatia. |

### Gráfico numérico {#number-chart}

| Função     | Tipo de coluna           | Descrição                                                    |
| ---------- | ------------------------ | ------------------------------------------------------------ |
| **Número** | Primeira coluna numérica | Exibe o valor da primeira linha da primeira coluna numérica. |

### Gráfico de tabela {#table-chart}

Todas as colunas do resultado são exibidas diretamente como colunas da tabela.

## Exemplos {#examples}

<Info>
  **Nomes de tabelas nos exemplos**

  Os exemplos usam `otel_logs` e `otel_traces`. Ajuste os nomes das tabelas e colunas de acordo com os seus dados. Ao executar os exemplos em [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com), use `otel_v2.otel_logs` ou `otel_v2.otel_traces`.
</Info>

### Gráfico de série temporal — contagem de logs ao longo do tempo por serviço {#example-line-chart}

Esta consulta conta os eventos de log por serviço, agrupando-os em intervalos de tempo que correspondem à granularidade do dashboard.

```sql
SELECT
  toStartOfInterval(TimestampTime, INTERVAL {intervalSeconds:Int64} second) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

* `ts` (`DateTime`) é usado como timestamp do eixo x.
* `count` (numérico) é plotado como o valor da série.
* `ServiceName` (string) gera uma linha separada para cada serviço.

### Gráfico de série temporal — com macros {#example-line-chart-macros}

A mesma consulta, escrita com macros para ficar mais concisa:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

### Gráfico de série temporal — usando variáveis do painel {#example-line-chart-variables}

Considere um dashboard com uma variável `service` em `ServiceName` e uma variável `severity` em `SeverityText`: esta consulta restringe o gráfico ao serviço selecionado no momento e exclui as severidades selecionadas. Ambas as macros se expandem para `1=1` enquanto a respectiva variável não tiver nenhuma seleção, de modo que o gráfico é renderizado sem filtros até que o usuário escolha um valor.

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

### Gráfico de barras empilhadas — contagem de erros por severidade {#example-stacked-bar}

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  lower(SeverityText),
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND lower(SeverityText) IN ('error', 'warn')
  AND $__filters
GROUP BY SeverityText, ts
ORDER BY ts ASC
```

### Gráfico de tabela — os 10 endpoints mais lentos {#example-table}

```sql
SELECT
  SpanName AS endpoint,
  avg(Duration) / 1000 AS avg_duration_ms,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY SpanName
ORDER BY avg_duration_ms DESC
LIMIT 10
```

### Gráfico de pizza — distribuição de requisições por serviço {#example-pie}

```sql
SELECT
  ServiceName,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY ServiceName
```

* `request_count` (numérico) determina o tamanho de cada fatia.
* `ServiceName` (string) define o rótulo de cada fatia.

### Gráfico numérico — contagem total de erros {#example-number}

```sql
SELECT
  count() AS total_errors
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND SeverityText = 'error'
  AND $__filters
```

É exibido o único valor numérico `total_errors` da primeira linha.

## Notas {#notes}

* As visualizações baseadas em SQL são executadas com o modo `readonly` habilitado — somente consultas `SELECT` são permitidas.
* Cada visualização baseada em SQL aceita uma única consulta; não há suporte a múltiplas consultas.
* O Editor SQL oferece sugestões de preenchimento automático tanto para parâmetros de consulta quanto para macros.
* É necessário selecionar uma fonte de dados para aplicar os filtros do dashboard às visualizações baseadas em SQL. A fonte de dados deve corresponder à tabela consultada para garantir uma filtragem precisa.
* As variáveis do painel não exigem uma fonte de dados — os valores vêm das listas suspensas de filtros do dashboard, e não da fonte de dados do próprio bloco.
* Os alertas em um bloco SQL que referencia uma variável do painel são avaliados com todas as variáveis em estado vazio, e não com os valores selecionados no dashboard.
