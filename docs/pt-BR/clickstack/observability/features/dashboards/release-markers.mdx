Diante de um pico de latência ou de erros, a primeira pergunta costuma ser se algo foi para produção. Os gráficos temporais do dashboard podem responder a isso ali mesmo: ative os marcadores de versão e cada bloco exibirá uma linha vertical tracejada no momento em que uma versão de um serviço apareceu pela primeira vez na telemetria.

As versões vêm da telemetria que você já envia e são lidas por meio de uma expressão na fonte de dados do bloco. Não é preciso configurar nenhuma integração de CI nem enviar nada no momento da implantação.

## Ativar os marcadores {#turn-on}

Os marcadores de versão vêm desativados por padrão. Abra o menu de overflow de um dashboard e selecione **Show release markers**.

<div className="ch-image-sm">
  <Frame>
    ![Menu de overflow do dashboard com o item Show release markers na seção View, abaixo de Show alert annotations](/images/clickstack/dashboards/release-markers-menu.webp)
  </Frame>
</div>

O botão de alternância adiciona `releaseMarkers=true` à URL do dashboard, de modo que um link compartilhado já abre com os marcadores ativados. Trata-se de um estado de visualização, e não de uma configuração do dashboard: ele não é salvo com o dashboard, e desativá-lo remove o parâmetro da URL.

Os marcadores aparecem em blocos de séries temporais cuja fonte de dados é uma fonte de logs ou de traces. As [anotações de alertas](/pt-BR/clickstack/observability/features/alerts) ficam no mesmo menu e podem ser exibidas simultaneamente — os dois conjuntos de marcadores são desenhados juntos, e cada um mantém seus próprios rótulos.

## Configure a origem da versão {#version-expression}

Por padrão, o ClickHouse Observability lê `ResourceAttributes['service.version']`, o atributo de recurso do OpenTelemetry. Se seus serviços seguirem as [convenções semânticas de recurso de serviço](https://opentelemetry.io/docs/specs/semconv/registry/attributes/service/), os marcadores funcionam sem nenhuma configuração adicional.

Para ler a versão de outro lugar, defina **Service Version Expression** na fonte de dados de logs ou de traces. Edite a fonte de dados em **Team Settings → Sources**. Em uma fonte de dados de logs, o campo fica em **Configure Optional Fields**; em uma fonte de traces, ele aparece diretamente no formulário, abaixo de **Service Name Expression**.

<div className="ch-image-lg">
  <Frame>
    ![Campo Service Version Expression nos campos opcionais de uma fonte de dados de logs, mostrando o marcador de posição padrão ResourceAttributes\['service.version'\]](/images/clickstack/dashboards/service-version-expression.webp)
  </Frame>
</div>

O valor é uma expressão SQL, e não um nome de atributo, o que permite atender a dois casos comuns:

* **O identificador do lançamento está em outro atributo.** Com GitOps, o que identifica um lançamento geralmente é a tag de imagem do contêiner, recebida como `container.image.tag`. Apontar a fonte de dados para `ResourceAttributes['container.image.tag']` sai bem mais barato do que alterar a instrumentação de toda a frota.
* **Os serviços de uma mesma tabela não usam o mesmo atributo.** Use `coalesce` para recorrer a um atributo alternativo quando o anterior não estiver disponível:

```sql
coalesce(
  nullIf(ResourceAttributes['service.version'], ''),
  nullIf(ResourceAttributes['container.image.tag'], '')
)
```

O campo também é exposto como `serviceVersionExpression` nas fontes de dados de logs e de traces na [API de fontes de dados](/pt-BR/clickstack/observability/api-reference), permitindo defini-lo ao provisionar fontes de dados programaticamente. Para implantações autogerenciadas, consulte a lista completa de configurações das fontes de dados de [logs](/pt-BR/clickstack/self-configured/managing/config#logs) e de [traces](/pt-BR/clickstack/self-configured/managing/config#traces).

## O que um marcador significa {#what-a-marker-means}

Um marcador registra que um valor de versão apareceu pela primeira vez nos dados do bloco dentro da janela visível. Isso se aproxima de uma implantação, mas, deliberadamente, não afirma a mesma coisa. É por isso que eles são marcadores de versão, e não marcadores de implantação:

* Uma implantação que não altera a string de versão não gera nenhum marcador.
* Um serviço que fica ocioso por mais tempo do que o período de retrospectiva gera um marcador quando volta a escalar.

A versão que já estava em execução quando a janela começou é identificada e descartada, em vez de ser exibida como um lançamento que nunca aconteceu. Para isso, a consulta retrocede a um ponto anterior ao início da janela (30 minutos ou 10% da janela, o que for maior) para encontrar a versão vigente.

## Quais versões um bloco exibe {#scoping}

A consulta de versões é executada na própria fonte de dados do bloco, com os predicados do próprio bloco: sua cláusula `WHERE`, o filtro de cada série e quaisquer [filtros de dashboard](/pt-BR/clickstack/observability/features/dashboards/overview#custom-filters). O que um bloco exibe depende do que ele representa no gráfico:

| Bloco                             | Marcadores                                                                         |
| :-------------------------------- | :--------------------------------------------------------------------------------- |
| Filtrado para um único serviço    | As versões desse serviço                                                           |
| Agrupado por serviço              | As versões de cada serviço exibido no gráfico, cada uma na cor da respectiva linha |
| Linha agregada de vários serviços | Nenhum, a menos que todas as versões na janela sejam de um único serviço           |

No terceiro caso, o serviço de um marcador não tem uma linha correspondente no gráfico, por isso os marcadores são removidos. Se todas as versões na janela forem de um único serviço, os marcadores são exibidos na cor padrão.

## Leitura de marcadores em um gráfico com muitos dados {#reading-markers}

Passe o cursor sobre o rótulo de um marcador para listar todas as versões naquele ponto, cada uma com o serviço que a publicou, sua versão e o horário.

<div className="ch-image-sm">
  <Frame>
    ![Dica de ferramenta ao passar o cursor sobre um marcador de versão, indicando o serviço frontend e a versão 2.0.2 com o horário em que a versão apareceu pela primeira vez, em um gráfico de dois serviços](/images/clickstack/dashboards/release-marker-tooltip.webp)
  </Frame>
</div>

A cor associa um marcador à sua série, mas a legenda de um gráfico exibe no máximo quatro entradas antes de agrupar o restante em &quot;+N more&quot; e, a partir daí, não há nada na tela que permita identificar a cor. A dica de ferramenta nomeia o serviço explicitamente, por isso funciona independentemente de quantas séries o bloco exiba no gráfico.

Marcadores próximos demais para serem rotulados individualmente são agrupados em uma única âncora com o rótulo `N releases`; ao passar o cursor sobre ela, todos são listados. Um agrupamento que abrange vários serviços é desenhado em uma cor neutra, em vez de usar a cor de um deles, para que a contagem continue correta sem sugerir um proprietário.

Arrastar horizontalmente sobre a área do gráfico continua aplicando zoom enquanto os marcadores estão visíveis.

## Limitações {#limitations}

* **Apenas blocos de séries temporais.** Tabelas, números e mapas de calor não exibem marcadores.
* **Apenas fontes de dados de logs e de traces.** Uma fonte de dados de métricas resolve sua tabela de acordo com o tipo de métrica; portanto, não há uma única tabela para reagregar nem como tornar os filtros de um bloco significativos para ela. Para anotar dados de métricas, coloque um bloco de logs ou de traces ao lado deles no mesmo dashboard.
* **Valores de versão vazios são ignorados.** Um serviço que não emite versão não gera marcadores. Se um bloco não encontrar nenhuma mudança de versão, a UI exibe `No releases found`, em vez de deixar você na dúvida se a funcionalidade está com defeito.
* **Até 500 versões distintas** são lidas por janela.
