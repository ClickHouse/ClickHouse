## Filtros no nível da fonte de dados para alertas e MCP {#source-level-filters-for-alerts-and-mcp}

*Demonstração por [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/z0Lbggcy6dU" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Drew demonstra uma ampla expansão do suporte a filtros de fonte em todo o ClickStack. Agora é possível configurar alertas em painéis do dashboard e em blocos de SQL bruto que exigem filtros de fonte, com orientações claras em linha quando há filtros ausentes ou quando uma consulta não contém uma macro de filtro para injeção. Os alertas de pesquisas salvas têm o mesmo comportamento.

Os filtros de fonte agora são respeitados em toda a experiência do mapa de serviços, e as seleções são propagadas para as páginas de busca vinculadas e para os painéis laterais de trace.

O MCP também passou a reconhecer filtros de fonte. Os agentes podem descobrir os requisitos de filtro, obter os valores disponíveis e passar filtros para as ferramentas de consulta. Os valores de filtro são eliminados de forma cruzada, de modo que uma seleção restringe os valores compatíveis dos demais filtros. Quando filtros obrigatórios são omitidos, o MCP pode selecioná-los automaticamente e informar quais valores foram aplicados. Os resultados iniciais da avaliação não indicam impacto mensurável em fontes de dados que não utilizam filtros de fonte.

**PRs relacionados:** [#2459](https://github.com/hyperdxio/hyperdx/pull/2459) feat: show icon on tiles with excluded source-scoped filters, [#2331](https://github.com/hyperdxio/hyperdx/pull/2331) feat: Add source scoping to dashboard filters

## Receptor Datadog {#datadog-receiver}

*Demonstração por [@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/P0VVuN_yL6Q" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Spencer demonstra melhorias no receptor Datadog.

Antes, os payloads de log do Datadog eram ingeridos, em grande parte, como JSON não estruturado no corpo da mensagem. Agora, o receptor extrai campos importantes, como IDs de trace, IDs de span, timestamps e metadados de requisições HTTP, e os promove a atributos padrão de recurso e de log do OpenTelemetry.

Os IDs de trace numéricos de 64 bits do Datadog também passam a ser expandidos para o formato de 128 bits do OpenTelemetry, o que permite a correlação correta de traces no ClickStack. A previsão é que o receptor seja incluído na distribuição do coletor do ClickStack, e há testes adicionais planejados para a correlação de traces de ponta a ponta.
