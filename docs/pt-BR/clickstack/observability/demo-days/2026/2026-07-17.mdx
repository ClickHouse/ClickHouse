## Melhorias na dica de ferramenta dos gráficos {#chart-tooltip-improvements}

*Demonstração por [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/EsnGp9RPSKM" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

As dicas de ferramenta dos gráficos no ClickStack ganharam uma grande melhoria de usabilidade. Agora, ao clicar em um gráfico, a dica de ferramenta fica fixada no lugar em vez de desaparecer quando você afasta o mouse, para que você consiga de fato ler os dados. A dica de ferramenta fixada mostra todos os valores da série e, se houver muitos, é possível rolar a lista em vez de vê-la truncada.

Agora também é possível copiar valores diretamente da dica de ferramenta, um recurso que surgiu do feedback de clientes. Antes, os clientes conseguiam ver os dados de que precisavam, mas não tinham como copiá-los; agora, basta clicar em um valor para copiá-lo para a área de transferência.

Tudo isso se baseia em um upgrade do Recharts, que renderiza as dicas de ferramenta por meio de um portal, e não dentro do próprio contêiner do gráfico. Isso faz mais diferença em dashboards com muitos gráficos próximos uns dos outros, já que as dicas de ferramenta deixam de ser comprimidas ou recortadas pelos gráficos vizinhos.

**PRs relacionados:** [#2642](https://github.com/hyperdxio/hyperdx/pull/2642) feat(charts): pin chart tooltip on click with inline drill-down actions

## Execução de avaliações de MCP a partir de um PR {#running-mcp-evals-from-a-pr}

*Demonstração por [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/YcDm1Mnw-Qc" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Agora a equipe pode executar avaliações de MCP diretamente a partir de um PR no GitHub, e não apenas localmente. Assim, qualquer pessoa consegue ver como uma alteração de código afeta a qualidade do MCP antes do merge. Esta é a primeira versão da configuração, que integra o pipeline de avaliações ao CI para que ele seja executado automaticamente e publique uma pontuação combinada no próprio PR.

Para saber mais sobre como funciona o framework de avaliações de MCP do ClickStack, confira a publicação no blog [benchmarking do servidor MCP do ClickStack com as avaliações do HDX](https://clickhouse.com/blog/benchmarking-the-clickstack-mcp-server-with-hdx-evals).

**PRs relacionados:** [#2628](https://github.com/hyperdxio/hyperdx/pull/2628) feat(evals): M1 CI skeleton — run MCP evals end to end in GitHub Actions

## Suporte a métricas no servidor MCP {#metrics-support-in-the-mcp-server}

*Demonstração por [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/GqJWQN3P86c" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

O servidor MCP agora entende métricas, e não apenas logs e traces, e conta com um framework de avaliações próprio para medir o quão bem ele as utiliza. Esta mudança adiciona geradores para os cinco tipos de métrica suportados pelo ClickStack (gauge, soma, histograma, histograma exponencial e summary), além de novos cenários de avaliação que só podem ser resolvidos com métricas, como um vazamento de memória na JVM que é praticamente impossível de diagnosticar apenas com logs e traces.

Os primeiros resultados mostram que o servidor MCP com suporte a métricas resolve esses cenários visivelmente mais rápido do que o servidor MCP padrão, baseado apenas em SQL, principalmente porque precisa de menos chamadas de ferramentas para chegar à resposta. Ainda há ajustes a fazer (em alguns cenários, a correspondência de padrões do LLM se confunde com notações diferentes para a mesma métrica), mas a direção é clara: dar ao agente acesso direto a métricas viabiliza investigações que antes estavam fora de alcance.

**PRs relacionados:** [#2645](https://github.com/hyperdxio/hyperdx/pull/2645) feat(evals): support metric types and seeding

## Melhorias no seletor de fonte {#source-picker-improvements}

*Demonstração por [@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/XTQygZSMUTs" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Escolher a fonte de dados certa costumava ser um exercício de rolar a lista e adivinhar. Em instâncias com listas longas de fontes de dados, ao abrir a lista suspensa não havia nenhuma indicação visual de qual fonte de dados estava de fato selecionada. Esta atualização adiciona uma marca de seleção ao lado da fonte de dados selecionada no momento, seguindo o padrão já existente da seleção múltipla, para que você saiba de relance qual delas está ativa antes de começar a executar consultas.

É uma mudança pequena, mas elimina aquele momento de &quot;peraí, qual delas estou vendo?&quot; que vai se acumulando ao longo do dia de trabalho.

**PRs relacionados:** [#2651](https://github.com/hyperdxio/hyperdx/pull/2651) feat(app): clarify selected source in source picker

## Conversão do criador de gráficos para SQL {#chart-builder-to-sql-conversion}

*Demonstração por [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/IBNdi1rgiTc" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Até então, trocar o construtor de consultas visual pelo modo de SQL bruto significava começar do zero. Se você tivesse montado uma consulta com filtros e group-bys no construtor e esbarrasse em algo que ele não conseguia expressar, ao mudar para o modo SQL você caía em um editor vazio.

Agora, ao alternar para o modo SQL, sua consulta do construtor passa pelo mesmo pipeline que renderiza o gráfico. Assim, você chega ao modo SQL com a consulta equivalente já escrita usando as macros adequadas, em vez de valores fixos no código. A conversão inversa (de SQL de volta para o construtor) ainda não está disponível, mas já está no roadmap.

**PRs relacionados:** [#2634](https://github.com/hyperdxio/hyperdx/pull/2634) feat: Auto-convert builder charts to Raw SQL, [#2666](https://github.com/hyperdxio/hyperdx/pull/2666) fix(charts): Keep selected source when switching from builder to SQL mode

## Novo mecanismo de obtenção de filtros {#new-filter-fetching-mechanism}

*Demonstração por [@knudtty](https://github.com/knudtty)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/z31cAIJA3B4" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

A obtenção da lista de valores de filtro disponíveis ganhou uma camada de roteamento mais inteligente. Em vez de uma única estratégia fixa, o novo sistema verifica o que está disponível no schema, em especial se existem índices de texto, e escolhe a forma mais eficiente de montar a lista de filtros.

Quando há índices de texto disponíveis, o ClickStack os consulta diretamente em vez de recorrer às tabelas de rollup. Isso também significa menos rollups para manter e menor risco da pressão de memória que alguns clientes enfrentaram com a abordagem antiga. O recurso exige o ClickHouse 26.3; quem ainda não estiver nessa versão continuará usando a abordagem atual baseada em rollup até fazer o upgrade, quando o novo mecanismo passa a ser usado automaticamente.

**PRs relacionados:** [#2643](https://github.com/hyperdxio/hyperdx/pull/2643) feat: rework getAllKeyValues and add filters populated from text indices

## Dashboard de RUM aprimorado {#improved-rum-dashboard}

*Demonstração por [@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/roNhRzLvXro" title="Reprodutor de vídeo do YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

O dashboard de RUM no navegador agora conta com codificação por cores, acompanhada de uma legenda em Markdown que explica o significado de cada cor (com margem para deixar essa legenda ainda mais clara futuramente). Os blocos numéricos de métricas como sessões com erros agora são coloridos com base em limiares configuráveis, de modo que as áreas problemáticas saltam aos olhos em vez de se perderem em meio a um mar de números neutros.

**PRs relacionados:** [#2671](https://github.com/hyperdxio/hyperdx/pull/2671) feat(dashboards): color-code Browser RUM web vitals, page-load &amp; error tiles
