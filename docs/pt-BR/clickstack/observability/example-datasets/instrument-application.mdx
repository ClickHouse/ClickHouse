    O HackerNews Analyzer é um aplicativo Node.js que consulta o dataset do HackerNews hospedado na demonstração pública do ClickHouse. As interações com o dashboard geram requisições ao backend. As requisições que não encontram dados no cache do aplicativo também consultam o ClickHouse, adicionando ao trace um span HTTPS de saída.

    Esta demonstração combina instrumentação automática do backend, spans de consultas do ClickHouse e reprodução de sessão do navegador em um único aplicativo.

## Pré-requisitos {#prerequisites}

    * Versões do Node.js e do npm compatíveis com o [HackerNews Analyzer e suas dependências](https://github.com/ClickHouse/hn-news-analyzer#readme).
    * Um serviço ClickHouse Observability totalmente gerenciado já existente. Consulte o [guia de primeiros passos da versão totalmente gerenciada](/pt-BR/clickstack/observability/getting-started).
    * Acesso de rede ao endpoint de telemetria gerenciado, tanto a partir do servidor da aplicação quanto do seu navegador.

## Clone o repositório {#clone-the-repository}

    Clone o [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer), instale as dependências e copie o modelo de arquivo env:

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    Você preencherá o `.env` nas próximas etapas e, em seguida, fará a instrumentação a partir deste diretório.

## Instrumente a aplicação {#instrument-the-application}

    <Steps>
      <Step title="Execute a aplicação" id="run-the-application">
        No diretório `hn-news-analyzer` clonado, inicie a aplicação. Por padrão, a fonte de dados do ClickHouse usa o cluster de demonstração público read-only, então a aplicação é executada sem nenhuma configuração adicional:

        ```bash
        ./run.sh
        ```

        Abra [http://localhost:5001](http://localhost:5001). Você verá um seletor de ano, estatísticas resumidas, um gráfico de atividade, tabelas com os principais usuários e domínios e uma caixa de busca. Explore à vontade: alterne entre os anos e confira as histórias em detalhes.

        <Frame>
          <img src="/images/clickstack/getting-started/hackernews_main.webp" alt="A aplicação HackerNews Analyzer em execução localmente" />
        </Frame>

        Neste ponto, a aplicação está em execução, mas ainda não está instrumentada. Ela passará a enviar telemetria depois que você concluir as etapas de instrumentação abaixo.
      </Step>

      <Step title="Configurar ambiente" id="configure-environment">
        Abra o seu serviço ClickHouse Observability e acesse **Team Settings → Managed Telemetry**. Copie o **OTLP HTTP endpoint** e a **API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Managed Telemetry em Team Settings exibindo o endpoint OTLP HTTP e a chave de API mascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        No arquivo `.env` da aplicação, defina os valores a seguir, substituindo os marcadores de posição do endpoint e da chave de API:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        Mantenha o prefixo `https://` em `OTEL_EXPORTER_OTLP_ENDPOINT` e não acrescente `/v1/logs`, `/v1/traces` ou `/v1/metrics`. Os SDKs acrescentam os caminhos de cada sinal. Defina `OTEL_EXPORTER_OTLP_HEADERS` como `authorization=<your-api-key>`, sem o prefixo `Bearer`; a aplicação também repassa essa chave diretamente ao SDK do navegador.

        O SDK do navegador usa o mesmo endpoint e a mesma chave de API. O `vite.config.ts` os incorpora ao pacote do navegador, onde qualquer visitante pode inspecioná-los. Use um serviço destinado a testar esta demonstração e mantenha o `.env` fora do controle de versão.
      </Step>

          <Tab title="Instrumentação manual" id="instrument-manually">
            A instrumentação tem três etapas: instalar os SDKs, trocar o comando de inicialização e habilitar o SDK do navegador. Nada disso altera a regra de negócio da aplicação.

### Instale o SDK do Node {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### Habilite o wrapper no run.sh {#enable-run-sh-wrapper}

            O final do `run.sh` tem duas linhas `exec`. Comente a linha com `node` simples e descomente a instrumentada:

            ```diff
             # BEFORE: plain node, no instrumentation:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # AFTER: same source, wrapped by opentelemetry-instrument:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            Continue iniciando por meio de `scripts/entrypoint.js`. Esse shim chama `require('console')` para que a captura do console encapsule `console.log`. Apontar o `opentelemetry-instrument` diretamente para `dist/server/index.js` envia os rastros, mas descarta os logs silenciosamente.

### Habilite o SDK do navegador {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            Em `src/web/telemetry.ts`, descomente o import, o bloco `HyperDX.init` e `HyperDX.addAction` em `recordAction`:

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` e `__OTLP_AUTH_TOKEN__` são constantes de tempo de compilação injetadas pelo `vite.config.ts` a partir dos mesmos valores `OTEL_EXPORTER_OTLP_*` usados pelo backend.
          </Tab>

          <Tab title="Usar um branch pré-instrumentado" id="use-the-instrumented-branch">

            ```bash

            npm install
            ```

            Não execute `./reset.sh` neste branch, a menos que queira remover os SDKs.

    O HackerNews Analyzer é uma aplicação Node.js que consulta o dataset do HackerNews hospedado na demonstração pública do ClickHouse. Cada gráfico, tabela e caixa de busca executa uma consulta real no ClickHouse, de modo que cada interação gera um trace cujo span principal é a chamada HTTPS do backend para o ClickHouse.

    O objetivo aqui é diferente do da [demonstração de reprodução de sessão](/pt-BR/clickstack/observability/example-datasets/session-replay), que instrumenta uma aplicação executada apenas no navegador e envia telemetria para o ClickHouse Observability. Aqui, você obtém instrumentação automática do backend, spans de consultas do ClickHouse e reprodução de sessão na mesma aplicação.

## Pré-requisitos {#prerequisites-self-configured}

    * Node 18+ e npm
    * Um serviço ClickHouse Observability autogerenciado existente e um coletor de ingestão em execução.
    * O endpoint OTLP HTTP do coletor, acessível tanto pelo servidor da aplicação quanto pelo seu navegador. Use `http://localhost:4318` somente quando o coletor estiver em execução na mesma máquina.
    * O `OTLP_AUTH_TOKEN` do coletor, se estiver configurado. Defina os cabeçalhos como `authorization=<token>`, sem o prefixo `Bearer`. Se o coletor não exigir autenticação, deixe `authorization=` vazio. Essas são as credenciais de ingestão do coletor, e não as credenciais do seu banco de dados ClickHouse.
