<Info>
  **Resumo**

  Este guia mostra como instrumentar uma aplicação web para reprodução de sessão usando o SDK do navegador e o ClickHouse Observability, seja totalmente gerenciado ou autogerenciado. Ao contrário de outros conjuntos de dados de exemplo, que carregam dados pré-gerados, esta demonstração oferece uma aplicação interativa na qual você gera os dados de sessão com suas próprias interações.

  Tempo necessário: 10-15 minutos
</Info>

## Visão geral {#overview}

A [aplicação de demonstração de reprodução de sessão](https://github.com/ClickHouse/clickstack-session-replay-demo) é um explorador de documentação desenvolvido com JavaScript puro. Ela mostra o quão mínima a instrumentação de reprodução de sessão pode ser: uma única tag de script e uma única chamada de inicialização bastam para capturar as interações do usuário automaticamente.

O repositório inclui duas branches:

* **`main`** — totalmente instrumentada e pronta para uso imediato
* **`pre-instrumented`** — uma versão limpa, sem instrumentação, com comentários no código indicando onde adicioná-la

Este guia usa primeiro a branch `main` para mostrar a reprodução de sessão em ação e, em seguida, apresenta o código de instrumentação passo a passo para que você possa aplicar o mesmo padrão à sua própria aplicação.

Para saber mais sobre o que é a reprodução de sessão e como ela se encaixa no ClickStack, consulte a página da funcionalidade [Reprodução de sessão](/pt-BR/clickstack/observability/features/session-replay).

## Pré-requisitos {#prerequisites}

* Docker instalado e em execução, com o Docker Compose disponível
* Porta 3000 livre para o aplicativo de demonstração
* Um serviço ClickHouse Observability já existente, totalmente gerenciado ou autogerenciado
* Acesso à rede a partir do seu navegador até o endpoint de telemetria configurado abaixo

## Executando a demonstração {#running-the-demo}

<Steps>

  <Step title="Configure a conexão" id="configure-connection">
    Escolha o seu modo de implantação:

    <Tabs>
      <Tab title="Totalmente gerenciado">
        <BetaBadge label="Oferta Beta" />

        Você precisa de um [serviço totalmente gerenciado](/pt-BR/clickstack/observability/getting-started) já existente. O ClickHouse fornece o coletor de ingestão.

        No seu serviço ClickHouse Observability, abra **Team Settings → Data → Managed Telemetry** e copie o **OTLP HTTP endpoint** e a **API key**.

        <div className="ch-image-lg">
          <Frame>
            ![Managed Telemetry exibindo o endpoint OTLP HTTP e a chave de API mascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        Defina `CLICKSTACK_UI_URL` com a URL da UI do seu serviço gerenciado. Para abrir os replays diretamente, copie a URL do navegador em **Client Sessions**. Substitua os marcadores de posição abaixo pelos seus detalhes de conexão e execute estes comandos no terminal:

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
        export CLICKSTACK_API_KEY='Bearer YOUR_API_KEY'
        export CLICKSTACK_UI_URL='YOUR_OBSERVABILITY_UI_URL'
        ```

        Mantenha o prefixo `https://` e omita caminhos de sinal como `/v1/traces`. Na ingestão totalmente gerenciada, inclua o prefixo `Bearer `, conforme mostrado acima.

        `CLICKSTACK_UI_URL` controla os links **Open Observability** da demonstração e é independente do endpoint de ingestão de telemetria.

        O servidor repassa o endpoint de telemetria e a chave de API ao SDK do navegador. Como a chave de ingestão fica visível no navegador, use um serviço de teste para esta demonstração.
      </Tab>

      <Tab title="Autogerenciado">
        Você precisa de um [serviço autogerenciado](/pt-BR/clickstack/self-configured/getting-started/managed) já existente e de um Coletor OpenTelemetry do ClickStack em execução e conectado a ele. Consulte [Ingestão com OpenTelemetry](/pt-BR/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured) para obter instruções de conexão ou o [guia de implantação](/pt-BR/clickstack/self-configured/deployment/managed#start-a-collector-existing) para iniciar um coletor.

        O endpoint OTLP HTTP do coletor deve estar acessível a partir do seu navegador, com o CORS permitindo `http://localhost:3000`. A UI deve oferecer suporte ao atributo `session.id` do novo SDK em Client Sessions; consulte os [requisitos de compatibilidade do SDK](https://github.com/ClickHouse/clickstack-browser#clickstack-versions).

        Defina `CLICKSTACK_OTEL_ENDPOINT` com o endpoint OTLP HTTP do seu coletor, sem um caminho de sinal como `/v1/traces`. Defina `CLICKSTACK_UI_URL` com a URL de **Client Sessions** copiada da UI do seu serviço autogerenciado.

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
        export CLICKSTACK_API_KEY='YOUR_COLLECTOR_TOKEN'
        export CLICKSTACK_UI_URL='YOUR_CLIENT_SESSIONS_URL'
        ```

        Use o token de autenticação configurado no receptor do seu coletor. Para um Coletor do ClickStack protegido com `OTLP_AUTH_TOKEN`, use esse valor sem o prefixo `Bearer`. Se o seu receptor não exigir autenticação, defina `CLICKSTACK_API_KEY` como uma string vazia. Não use aqui a senha do seu banco de dados ClickHouse.

        O token de ingestão é repassado ao SDK do navegador e fica visível no navegador. Já as credenciais do banco de dados ClickHouse usadas pelo coletor permanecem no próprio coletor.
      </Tab>

## A instrumentação {#instrumentation}

A aplicação de demonstração mostra o pouco código necessário para habilitar a reprodução de sessão. Bastam duas adições à aplicação. Os exemplos abaixo usam o novo SDK do ClickStack para navegador:

**1. Inclua o SDK (`app/public/index.html`):**

```html
<script src="https://cdn.jsdelivr.net/npm/@clickhouse/clickstack-browser@1.0.0/dist/clickstack.iife.js" integrity="sha384-NW4JhbuY4Thx4fMuqFwKvifcPn7ad9dJ7DU/MTxhkoHeadG27i4F38Yo1Gz6y0WA" crossorigin="anonymous"></script>
```

**2. Inicialize o SDK do navegador (`app/public/js/app.js`):**

```javascript
window.ClickStack.init({
  endpoint: window.CLICKSTACK_CONFIG.endpoint,
  apiKey: window.CLICKSTACK_CONFIG.apiKey,
  serviceName: 'clickhouse-session-replay-demo',
  console: 'debug',
});
```

`app/server.js` fornece `window.CLICKSTACK_CONFIG` a partir das variáveis de ambiente `CLICKSTACK_OTEL_ENDPOINT`, `CLICKSTACK_API_KEY` e `CLICKSTACK_UI_URL`. O SDK usa o endpoint e a chave de API, enquanto os links da demonstração usam a URL da UI. O SDK captura reprodução de sessão, logs do console, requisições de rede e erros sem alterar a regra de negócio da aplicação.

Textos e valores de entrada são mascarados por padrão. Consulte os [controles de privacidade do SDK do navegador](/pt-BR/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy) antes de alterar as configurações de mascaramento.

### Experimente você mesmo {#try-it-yourself}

Para instrumentar a aplicação do zero, interrompa a demonstração em execução com `Ctrl+C` e mude para o branch `pre-instrumented`:

```shell
git checkout pre-instrumented
```

Este branch contém a mesma aplicação sem o SDK do navegador habilitado. Comentários no código em `app/public/index.html` e `app/public/js/app.js` indicam onde adicionar os dois trechos acima. Mantenha as variáveis de conexão configuradas anteriormente e, em seguida, recompile e inicie a aplicação:

```shell
docker compose --profile demo up --build --no-deps demo-app
```

Recarregue a demonstração no navegador e interaja com ela para gerar uma nova sessão.

## Solução de problemas {#troubleshooting}

### As sessões não aparecem {#sessions-not-appearing}

1. Procure erros no console do navegador
2. Verifique se o aplicativo de demonstração está em execução: `docker compose ps demo-app`
3. Confirme que `CLICKSTACK_OTEL_ENDPOINT` e `CLICKSTACK_API_KEY` estão definidas no terminal usado para iniciar o aplicativo. Se você alterá-las, execute novamente o comando de inicialização e recarregue a aba do navegador.
4. Em implantações autogerenciadas, verifique os erros de exportação do coletor, a configuração de CORS e os requisitos de compatibilidade do SDK descritos acima
5. Ajuste o intervalo de tempo na visualização Sessões de Cliente (experimente **Last 15 minutes**)
6. Force a atualização do navegador: `Cmd+Shift+R` (Mac) ou `Ctrl+Shift+R` (Windows/Linux)

### Erros 401 Não autorizado {#401-errors}

A chave de API não está configurada corretamente. Verifique se você:

1. Exportou `CLICKSTACK_API_KEY` no seu terminal com o valor correspondente ao seu modo de implantação
2. Iniciou o aplicativo de demonstração no **mesmo terminal** em que fez a exportação
3. No modo totalmente gerenciado, usou a API key de ingestão disponível em **Team Settings → Data → Managed Telemetry** com o prefixo `Bearer `. No modo autogerenciado, usou o token do receptor do seu coletor sem esse prefixo.

## Limpeza {#cleanup}

Feche as abas da demonstração no navegador para interromper a telemetria do navegador e pressione `Ctrl+C` no terminal em que a aplicação está sendo executada. Para interrompê-la a partir de outro terminal, execute este comando no diretório do repositório:

```bash
docker compose stop demo-app
```

Isso encerra a aplicação local; a telemetria já ingerida no seu serviço continua armazenada nele.
