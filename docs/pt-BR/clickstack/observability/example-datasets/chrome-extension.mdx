      **TL;DR**

      Este guia mostra como injetar o SDK do navegador em qualquer site usando a [extensão HyperDX para Chrome](https://github.com/kyreddie/hyperdx-chrome-extension). Não é necessário alterar o código-fonte da aplicação de destino: basta configurar a extensão uma única vez, navegar pelo site e visualizar as reproduções de sessão no ClickHouse Observability.

      Tempo necessário: 10-15 minutos
    </Info>

## Visão geral {#overview}

    A [extensão HyperDX para Chrome](https://github.com/kyreddie/hyperdx-chrome-extension) injeta o SDK [@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) nas páginas que você visita. Ela é útil quando você precisa depurar a reprodução de sessão, o RUM ou a propagação de rastreamento em um site sem modificar a base de código dele — por exemplo, uma aplicação de terceiros, uma compilação de produção ou um servidor de desenvolvimento local com uma Content Security Policy (CSP) restritiva.

    O SDK vem empacotado dentro da extensão (~480 KB), portanto as páginas não precisam carregar scripts de uma CDN em tempo de execução. A extensão tenta primeiro a injeção externa de script via `chrome-extension://` e recorre à injeção inline como alternativa quando a CSP bloqueia scripts com origem na extensão.

    Ao contrário da [Demonstração de Reprodução de Sessão](/pt-BR/clickstack/observability/example-datasets/session-replay), que instrumenta uma aplicação de demonstração sob seu controle, esta abordagem instrumenta as páginas compatíveis que você abre no Chrome; algumas páginas restringem a injeção de scripts. Você gera dados de sessão interagindo com o site como um usuário comum.

    Para mais informações sobre a reprodução de sessão e como ela se encaixa no ClickHouse Observability, consulte a página da funcionalidade [Reprodução de sessão](/pt-BR/clickstack/observability/features/session-replay).

## Pré-requisitos {#prerequisites}

    * Google Chrome ou um navegador baseado em Chromium (Edge, Brave etc.)
    * Um serviço ClickHouse Observability totalmente gerenciado já existente. Consulte o [guia de primeiros passos da versão totalmente gerenciada](/pt-BR/clickstack/observability/getting-started).

## Executar a demonstração {#running-the-demo}

    <Steps>
      <Step title="Clone o repositório da extensão" id="clone-extension">
        ```shell
        git clone https://github.com/kyreddie/hyperdx-chrome-extension
        cd hyperdx-chrome-extension
        ```
      </Step>

      <Step title="Instale a extensão" id="install-extension">
        1. Abra o Chrome e acesse `chrome://extensions`.
        2. Ative o **Developer mode** (canto superior direito).
        3. Clique em **Load unpacked**.
        4. Selecione o diretório `hyperdx-chrome-extension` que você clonou.

        A extensão aparecerá na barra de ferramentas como **HyperDX Browser Extension**.
      </Step>

      <Step title="Obtenha os detalhes de conexão" id="get-connection-details">
        Abra o seu serviço ClickHouse Observability e acesse **Team Settings → Managed Telemetry**. Copie o **OTLP HTTP endpoint** e a **API key** para usar na configuração da extensão.

        Use o endpoint HTTPS completo fornecido, incluindo a porta, sem acrescentar `/v1/logs` ou `/v1/traces`.

        <div className="ch-image-lg">
          <Frame>
            ![Managed Telemetry em Team Settings mostrando o endpoint OTLP HTTP e a chave de API mascarados](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>
      </Step>

      <Step title="Configure a extensão" id="configure-extension">
        Clique no ícone **HyperDX Browser Extension** na barra de ferramentas do Chrome e preencha as configurações:

        | Campo                            | Configuração totalmente gerenciada              | Observações                                                                                            |
        | -------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
        | **Enable HyperDX Monitoring**    | Ativado                                         | Chave principal da injeção                                                                             |
        | **Service Name**                 | `my-frontend-app`                               | Obrigatório — identifica o serviço no ClickHouse Observability                                         |
        | **API Key**                      | Sua chave de API de telemetria gerenciada       | Obrigatório; copie de **Team Settings → Managed Telemetry**                                            |
        | **Collector URL**                | Seu endpoint OTLP HTTP de telemetria gerenciada | Substitua a URL padrão da extensão pelo endpoint de **Managed Telemetry**                              |
        | **Environment**                  | `development`                                   | Opcional — define o atributo de recurso `deployment.environment`                                       |
        | **Trace Propagation Targets**    | `/api\.myapp\.domain/i, /localhost/i`           | Opcional — padrões de regex JavaScript, separados por vírgula, para a propagação do cabeçalho de trace |
        | **Only inject on matching URLs** | Desativado                                      | Ative para limitar os sites instrumentados                                                             |
        | **Capture console logs**         | Desativado                                      | Ative para encaminhar a saída do console do navegador                                                  |
        | **Advanced network capture**     | Desativado                                      | Ative para capturar as requisições de rede em detalhes                                                 |

        Clique em **Save Configuration** e recarregue as abas que deseja instrumentar.
      </Step>

      <Step title="Navegue em um site e gere uma sessão" id="browse-site">
        Abra qualquer site ou aplicação local no Chrome — por exemplo, [http://localhost:3000](http://localhost:3000) para um servidor de desenvolvimento de frontend.

        Interaja normalmente com a página: clique em links, envie formulários, provoque erros e navegue entre as telas. Quando a configuração é válida, a extensão injeta o Browser SDK automaticamente a cada carregamento de página.
      </Step>

      <Step title="Veja a reprodução da sua sessão" id="view-session-replay">
        No seu serviço ClickHouse Observability, abra **Client Sessions** na barra lateral esquerda. Escolha um intervalo de tempo que inclua sua atividade de navegação.

        Sua sessão deverá aparecer na lista, com a duração e a contagem de eventos. Clique no botão ▶️ para reproduzi-la.

        Alterne entre os modos **Highlighted** e **All Events** para ajustar o nível de detalhe na linha do tempo.
      </Step>
    </Steps>

## Filtragem de URL {#url-filtering}

    Por padrão, a extensão injeta o SDK em todas as páginas que você visitar enquanto o monitoramento estiver habilitado. Para restringir a injeção a sites específicos, ative **Injetar apenas em URLs correspondentes** e adicione um padrão por linha (ou separados por vírgula):

    | Pattern                    | Corresponde a                                   |
    | -------------------------- | ----------------------------------------------- |
    | `http://homedepot.com/*`   | Apenas HTTP em `homedepot.com`                  |
    | `*://homedepot.com/*`      | HTTP e HTTPS em `homedepot.com`                 |
    | `*://*.homedepot.com/*`    | Subdomínios como `www.homedepot.com`            |
    | `https://localhost:3000/*` | Servidor de desenvolvimento local na porta 3000 |

    Recarregue a aba após salvar os padrões de URL.

## Verificar a injeção {#verify-injection}

    Abra o DevTools em uma página monitorada (aba **Console**), recarregue a página e procure por:

    ```text
    [HyperDX Extension] Configuration valid, injecting HyperDX
    [HyperDX Extension] Injected via extension scripts
    [HyperDX Extension] HyperDX initialized
    ```

    Se os scripts originados da extensão forem bloqueados pela CSP, a extensão registra uma mensagem de fallback e faz uma nova tentativa com injeção inline.

## Solução de problemas {#troubleshooting}

    <Accordion title="Sessões não aparecem no ClickHouse Observability">
      1. Verifique no console do navegador se há mensagens de log ou erros com `[HyperDX Extension]`
      2. Confirme se a opção **Ativar Monitoramento do HyperDX** está ativada e se o campo **Nome do serviço** está preenchido
      3. Confirme se a **URL do Coletor** e a **Chave de API** correspondem aos valores em **Team Settings → Managed Telemetry** no seu serviço
      4. Ajuste o intervalo de tempo na visualização Sessões de Cliente (experimente **Últimos 15 minutos**)
      5. Force a atualização do navegador: `Cmd+Shift+R` (Mac) ou `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="Erros de chrome-extension://invalid/">
      Recarregue a extensão em `chrome://extensions` e, em seguida, faça uma atualização forçada da aba. Isso acontece quando a extensão é atualizada ou recarregada com abas ainda abertas.
    </Accordion>

    <Accordion title="Sem injeção em um site">
      1. Verifique se o monitoramento está habilitado e se há um nome de serviço configurado
      2. Se a opção **Injetar apenas em URLs correspondentes** estiver ativada, confirme se a URL da página atual corresponde a um dos seus padrões
      3. Alguns sites bloqueiam, via CSP, tanto a injeção de scripts com origem na extensão quanto a de scripts em linha — nessas páginas, talvez não seja possível fazer a injeção
    </Accordion>

    <Accordion title="HyperDX: apiKey ausente no console">
      Insira a chave de API disponível em **Team Settings → Managed Telemetry**, salve a configuração e recarregue a página monitorada. Essa chave é obrigatória para a ingestão totalmente gerenciada.
    </Accordion>

## Privacidade {#privacy}

    A extensão injeta código de observabilidade nas páginas que você visita. Use-a apenas em sites que você tem permissão para depurar. Não compartilhe chaves de API nem faça commit delas no controle de versão.

        | **Capture console logs**         | Off                                    | Ative para encaminhar a saída do console do navegador                                                 |
        | **Advanced network capture**     | Off                                    | Ative para capturar as requisições de rede em detalhes                                                |

        Clique em **Save Configuration** e, em seguida, recarregue as abas que você deseja instrumentar.
