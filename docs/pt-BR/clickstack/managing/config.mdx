As opções de configuração a seguir estão disponíveis para cada componente do ClickStack:

<div id="modifying-settings">
  ## Configurações para distribuições de código aberto {#modifying-settings}
</div>

### Docker {#docker}

Se estiver usando [All in One](/pt-BR/clickstack/deployment/all-in-one), [Somente a Interface do ClickStack](/pt-BR/clickstack/deployment/hyperdx-only) ou [Local Mode](/pt-BR/clickstack/deployment/local-mode-only), basta informar a configuração desejada por meio de uma variável de ambiente, por exemplo.

```shell
docker run -e HYPERDX_APP_PORT=8081 -p 8081:8081 -p 4317:4317 -p 4318:4318 clickhouse/clickstack-all-in-one:latest
```

### Docker Compose {#docker-compose}

Se você estiver usando o guia de implantação do [Docker Compose](/pt-BR/clickstack/deployment/docker-compose), poderá usar o arquivo [`.env`](https://github.com/ClickHouse/clickstack/blob/main/.env) para modificar as configurações.

Como alternativa, sobrescreva explicitamente as configurações no arquivo [`docker-compose.yml`](https://github.com/ClickHouse/clickstack/blob/main/docker-compose.yml), por exemplo.

Exemplo:

```yaml
services:
  app:
    environment:
      HYPERDX_API_KEY: ${HYPERDX_API_KEY}
      HYPERDX_LOG_LEVEL: ${HYPERDX_LOG_LEVEL}
      # ... other settings
```

### Helm {#helm}

Use o [guia de implantação com Helm](/pt-BR/clickstack/deployment/helm) para instalar os operators e o chart do ClickStack. Obtenha os valores do chart atual antes de personalizar uma implantação:

```shell
helm show values clickstack/clickstack > values.yaml
```

Defina separadamente o ambiente da aplicação e o do coletor por meio dos valores do chart e, em seguida, aplique sua configuração:

```shell
helm upgrade --install my-clickstack clickstack/clickstack -f values.yaml
```

Consulte [Configuração do Helm](/pt-BR/clickstack/deployment/helm-configuration) para ver os valores compatíveis e as configurações de Entrada, recursos e Secret. O chart mais antigo `hyperdx/hdx-oss-v2` usa uma estrutura de valores diferente.

## Aplicação da Interface do ClickStack {#hyperdx}

### Conexões {#connection-settings}

Configure a conexão com o banco de dados usada pelas suas fontes de dados em Team Settings.

| Configuração               | Descrição                                                                                                                                                                                                                                                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Connection Name`          | Nome usado para identificar esta conexão nas configurações da fonte.                                                                                                                                                                                             |
| `Host`                     | Endpoint HTTP(S) do ClickHouse, incluindo a porta. Ele é diferente do endpoint de exportação do coletor.                                                                                                                                                         |
| `Username`                 | Nome de usuário do ClickHouse; o padrão é `default`.                                                                                                                                                                                                             |
| `Password`                 | Senha do ClickHouse; por padrão, fica vazia.                                                                                                                                                                                                                     |
| `Query Log Setting Prefix` | Prefixo opcional para uma configuração personalizada do ClickHouse que registra o e-mail do usuário atual nos logs de consultas. Inclua o mesmo prefixo na configuração `custom_settings_prefixes` do ClickHouse; caso contrário, as consultas serão rejeitadas. |
| `Prometheus compatible`    | Quando disponível, trata o Host como um endpoint de API compatível com o Prometheus para consultas PromQL encaminhadas via proxy. Esta conexão não pode ser usada para fontes de dados de logs, rastros ou métricas OTel armazenadas no ClickHouse.              |

### Configurações da fonte de dados {#datasource-settings}

A Interface do ClickStack depende de o usuário definir uma fonte para cada um dos tipos/pilares de dados de observabilidade:

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

Essa configuração pode ser feita no aplicativo em `Team Settings -> Sources`, como mostrado abaixo para logs:

<div className="ch-image-md">
  <Frame>
    ![Configuração de fonte da Interface do ClickStack](/images/use-cases/observability/hyperdx-25.webp)
  </Frame>
</div>

Cada fonte precisa de mapeamentos de tabelas e colunas para que a Interface do ClickStack possa consultar seus dados. Fontes de métricas podem usar tabelas separadas para diferentes tipos de métrica. A opção `Enabled` aparece ao editar uma fonte existente; as `Query Settings` no nível da fonte aceitam até dez pares nome/valor.

Se você estiver usando o [schema padrão do OpenTelemetry (OTel)](/pt-BR/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema) distribuído com o ClickStack, essas colunas poderão ser inferidas automaticamente para cada uma das fontes. Se estiver [modificando o schema](#clickhouse) ou usando um schema personalizado, será necessário especificar e atualizar esses mapeamentos.

<Note>
  O coletor cria as tabelas por meio de migrations de esquema ou da criação de schema legada gerenciada pelo exportador, dependendo da sua [configuração de schema](#collector-schema-and-retention). Os mapeamentos de colunas seguem as convenções do OpenTelemetry, incluindo o [modelo de dados de logs](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
</Note>

#### PromQL {#promql-source-settings}

Quando o PromQL está habilitado, você pode criar uma fonte de dados PromQL. ## Coletor OpenTelemetry {#otel-collector}

Consulte [Coletor OpenTelemetry do ClickStack](/pt-BR/clickstack/ingesting-data/collector) para ver as instruções de implantação. Defina as variáveis do coletor no contêiner do coletor, e não apenas no contêiner da UI. No Compose, declarar um valor no `.env` só o repassa a um contêiner se o `docker-compose.yml` fizer referência a ele.

### Conexão e autenticação {#collector-connection-and-authentication}

| Variável                                    | Padrão                                             | Descrição                                                                                                                                                                                                                                          |
| ------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLICKHOUSE_ENDPOINT`                       | Específico da implantação                          | URL de conexão do exportador do ClickHouse. O Compose e o all-in-one usam `tcp://ch-server:9000?dial_timeout=10s`. Para o ClickHouse Cloud, use o endpoint nativo seguro, por exemplo, `tcp://<host>:9440?secure=true`. Ele não se limita a HTTPS. |
| `CLICKHOUSE_USER`                           | `default` na ferramenta de migração                | Nome de usuário do ClickHouse. Defina explicitamente em um coletor independente para que tanto as migrations quanto os exportadores usem a conta correta.                                                                                          |
| `CLICKHOUSE_PASSWORD`                       | Vazio                                              | Senha da conta do ClickHouse.                                                                                                                                                                                                                      |
| `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE` | `default` em implantações empacotadas e migrations | Banco de dados de destino. Defina explicitamente em um coletor independente.                                                                                                                                                                       |
| `OPAMP_SERVER_URL`                          | Não definido no modo independente                  | URL OpAMP da Interface do ClickStack, normalmente `http://<app>:4320`. Quando definida, o coletor usa o supervisor para obter a configuração e as chaves de ingestão da equipe. Quando não definida, ele usa a configuração independente.          |
| `OTLP_AUTH_TOKEN`                           | Não definido                                       | Token bearer estático para ingestão OTLP no modo independente. Ignorado quando a autenticação OIDC está selecionada.                                                                                                                               |
| `OIDC_ISSUER_URL`                           | Não definido                                       | Habilita a autenticação OIDC para ingestão OTLP no modo independente. Tem precedência sobre `OTLP_AUTH_TOKEN`.                                                                                                                                     |
| `OIDC_AUDIENCE`                             | Não definido                                       | Audiência obrigatória quando `OIDC_ISSUER_URL` está definido; a inicialização falha se ela for omitida.                                                                                                                                            |

Sem OpAMP, OIDC ou `OTLP_AUTH_TOKEN`, o receptor OTLP independente fica sem autenticação. A conta do ClickHouse precisa de permissão para inserir telemetria e, quando a criação de schema ou as migrations estiverem habilitadas, para criar ou alterar os objetos de banco de dados necessários.

### Exportação, agrupamento em lotes e configuração personalizada {#collector-export-and-batching}

| Variável                                 | Padrão                 | Descrição                                                                                                                                                                                           |
| ---------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HYPERDX_OTEL_EXPORTER_TIMEOUT`          | `5s`                   | Tempo limite de exportação para o ClickHouse.                                                                                                                                                       |
| `HYPERDX_OTEL_BATCH_SEND_BATCH_SIZE`     | `10000`                | Número de itens que dispara o envio de um lote.                                                                                                                                                     |
| `HYPERDX_OTEL_BATCH_SEND_BATCH_MAX_SIZE` | `0`                    | Tamanho máximo do lote; `0` significa sem limite de tamanho.                                                                                                                                        |
| `HYPERDX_OTEL_BATCH_TIMEOUT`             | `5s`                   | Tempo máximo de espera antes do envio de um lote.                                                                                                                                                   |
| `CUSTOM_OTELCOL_CONFIG_FILE`             | Não definido           | Caminho para um arquivo YAML montado, mesclado com a configuração do coletor no modo independente ou OpAMP. Consulte [configuração personalizada do coletor](/pt-BR/clickstack/ingesting-data/collector). |
| `HYPERDX_LOG_LEVEL`                      | Depende da implantação | Nível de log interno do coletor. Defina-o explicitamente para um coletor independente, por exemplo, `info`. O Compose define `debug`; o all-in-one força `error`.                                   |
| `OTEL_SUPERVISOR_LOGS`                   | `false`                | Defina como `true` para encaminhar a saída do coletor por meio do supervisor OpAMP. Aplica-se apenas ao modo supervisor.                                                                            |
| `OTEL_AGENT_FEATURE_GATE_ARG`            | Não definido           | Argumento adicional de feature gate do coletor. O antigo valor `--feature-gates=clickhouse.json` está obsoleto; use `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_JSON_ENABLE=true` no lugar dele.              |

### Schema e retenção {#collector-schema-and-retention}

| Variável                                       | Padrão                                  | Descrição                                                                                                                                                                                                                                                 |
| ---------------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HYPERDX_OTEL_EXPORTER_CREATE_LEGACY_SCHEMA`   | `false`; o Compose substitui por `true` | Usa a criação de schema legado gerenciada pelo exportador em vez da ferramenta de migração.                                                                                                                                                               |
| `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_JSON_ENABLE` | `false`                                 | Habilita o modo JSON do exportador e seleciona a criação de schema legado. Esquemas com tipagem JSON não são recomendados para cargas de trabalho típicas de observabilidade; consulte [Map vs Tipo JSON](/pt-BR/clickstack/ingesting-data/schema/map-vs-json). |
| `HYPERDX_OTEL_EXPORTER_TABLES_TTL`             | `720h`                                  | Retenção padrão (uma duração Go, como `720h`, ou em dias, como `30d`) para tabelas criadas por migrations e pelos exportadores legados gerados via OpAMP. A configuração do exportador legado independente usa um valor fixo de `720h`.                   |
| `HYPERDX_OTEL_EXPORTER_LOGS_TTL`               | `HYPERDX_OTEL_EXPORTER_TABLES_TTL`      | Retenção de logs para tabelas gerenciadas pela migração.                                                                                                                                                                                                  |
| `HYPERDX_OTEL_EXPORTER_TRACES_TTL`             | `HYPERDX_OTEL_EXPORTER_TABLES_TTL`      | Retenção de rastros para tabelas gerenciadas pela migração.                                                                                                                                                                                               |
| `HYPERDX_OTEL_EXPORTER_METRICS_TTL`            | `HYPERDX_OTEL_EXPORTER_TABLES_TTL`      | Retenção de métricas para tabelas gerenciadas pela migração.                                                                                                                                                                                              |
| `HYPERDX_OTEL_EXPORTER_SESSIONS_TTL`           | `HYPERDX_OTEL_EXPORTER_TABLES_TTL`      | Retenção de sessões para tabelas gerenciadas pela migração.                                                                                                                                                                                               |
| `HYPERDX_OTEL_EXPORTER_RECONCILE_TABLE_TTL`    | `false`                                 | Permite, de forma opcional, aplicar os TTLs configurados às tabelas existentes gerenciadas pela migração. Revise as alterações de retenção antes de habilitar esta opção: TTLs mais curtos podem remover dados existentes.                                |

Os TTLs por sinal e a configuração de reconciliação se aplicam à ferramenta de migração, que é ignorada quando a criação de schema legado está habilitada.

### TLS da migração {#collector-migration-tls}

Estas variáveis configuram a conexão com o ClickHouse usada pela ferramenta de migração. Elas não configuram automaticamente o TLS dos exportadores; ao usar certificados personalizados, configure os exportadores do coletor separadamente.

| Variável                              | Padrão       | Descrição                                                                                                |
| ------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------- |
| `CLICKHOUSE_TLS_CA_FILE`              | Não definido | Caminho para o arquivo do certificado de CA.                                                             |
| `CLICKHOUSE_TLS_CERT_FILE`            | Não definido | Caminho do certificado do cliente para TLS mútuo.                                                        |
| `CLICKHOUSE_TLS_KEY_FILE`             | Não definido | Caminho da chave privada do cliente para TLS mútuo.                                                      |
| `CLICKHOUSE_TLS_SERVER_NAME_OVERRIDE` | Não definido | Nome do servidor usado na verificação de certificados.                                                   |
| `CLICKHOUSE_TLS_INSECURE_SKIP_VERIFY` | `false`      | Desabilita a verificação do certificado do servidor quando `true`. Use apenas para solução de problemas. |

### Métricas compatíveis com Prometheus {#collector-prometheus-metrics}

| Variável                                 | Padrão                                                            | Descrição                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ENABLE_PROMQL`                          | `false`                                                           | Habilita a criação do schema PromQL na ferramenta de migração. No modo OpAMP, habilite também o PromQL na API e no frontend.                                                                                                                                                            |
| `CLICKHOUSE_PROMETHEUS_METRICS_ENDPOINT` | Não definido no modo independente; `ch-server:9363` no all-in-one | Endpoint compatível com Prometheus. Aceita `host:port`, `http://host:port` ou `https://host:port`; não inclua um caminho. Quando definido, habilita a gravação remota no modo independente. O entrypoint deriva `HYPERDX_PROMETHEUS_SCHEME` e `HYPERDX_PROMETHEUS_TLS_INSECURE` da URL. |

<div id="clickhouse">
  ## ClickHouse {#clickhouse}
</div>

O ClickStack Open Source vem com uma configuração padrão do ClickHouse projetada para operar em escala de vários terabytes, mas os usuários podem modificá-la e otimizá-la conforme sua carga de trabalho.

Para ajustar o ClickHouse com eficácia, é importante entender conceitos-chave de armazenamento, como [partes](/pt-BR/concepts/core-concepts/parts), [partições](/pt-BR/concepts/core-concepts/partitions), [shards e réplicas](/pt-BR/guides/oss/deployment-and-scaling/shards) e como as [mesclagens](/pt-BR/concepts/core-concepts/merges) ocorrem durante a inserção. Recomendamos revisar os fundamentos de [índices primários](/pt-BR/concepts/core-concepts/primary-indexes), [índices secundários esparsos](/pt-BR/concepts/features/performance/skip-indexes/skipping-indexes) e índices de salto de dados, além de técnicas de [gerenciamento do ciclo de vida dos dados](/pt-BR/guides/use-cases/observability/build-your-own/managing-data), por exemplo, usando TTL.

O ClickStack oferece suporte à [personalização do schema](/pt-BR/guides/use-cases/observability/build-your-own/schema-design) — você pode modificar tipos de coluna, extrair novos campos (por exemplo, de logs), aplicar codecs e dicionários, e acelerar consultas usando projeções.

Além disso, visões materializadas podem ser usadas para [transformar ou filtrar dados durante a ingestão](/pt-BR/guides/use-cases/observability/build-your-own/schema-design#materialized-columns), desde que os dados sejam gravados na tabela de origem da visão e a aplicação leia da tabela de destino. Visões materializadas também podem ser usadas para [acelerar consultas nativamente](/pt-BR/clickstack/managing/materialized-views) no ClickStack.

Para mais detalhes, consulte a documentação do ClickHouse sobre design de schema, estratégias de indexação e melhores práticas de gerenciamento de dados — a maior parte delas se aplica diretamente a implantações do ClickStack.
