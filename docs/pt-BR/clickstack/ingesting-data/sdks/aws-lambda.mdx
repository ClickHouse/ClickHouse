Para funções Node.js com manipuladores assíncronos, use o SDK Node.js do ClickStack. Para outros tempos de execução ou manipuladores baseados em callback, use as camadas Lambda do OpenTelemetry descritas a seguir.

## Manipuladores assíncronos do Node.js {#nodejs-async-handlers}

Use um tempo de execução Node.js do Lambda que atenda à versão mínima do Node.js exigida pelo SDK (22.15). Instale o SDK e inclua-o no seu pacote de implantação:

```shell
npm install @clickhouse/clickstack-node
```

Defina estas variáveis de ambiente do Lambda para inicializar o SDK antes do carregamento do seu manipulador e para nomear o seu serviço:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

Envolva seu manipulador assíncrono com `withFlush` para que a telemetria armazenada em buffer seja exportada antes do retorno da invocação:

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

Defina o manipulador da função como `index.handler`. Se você empacotar a função em um bundle, mantenha o SDK e as dependências instrumentadas como externas e inclua-as no pacote de implantação. Não habilite também uma camada Lambda de instrumentação automática nesta configuração.

Defina as variáveis de destino abaixo na configuração de ambiente da função Lambda. O endpoint deve estar acessível a partir da sua função. O SDK conclui o flush antes do prazo da invocação; manipuladores baseados em callback não são compatíveis com `withFlush`.

### Configure o destino {#configure-destination}

Defina o endpoint OTLP HTTP e a chave de ingestão do seu Coletor do ClickStack. Use `http://` se o seu coletor não tiver TLS configurado. Para configurar o coletor, consulte [Ingestão com OpenTelemetry](/pt-BR/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## Outros tempos de execução e manipuladores {#other-runtimes-and-handlers}

Siga as [instruções oficiais de instrumentação automática para Lambda](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/) para selecionar as camadas adequadas ao seu tempo de execução, à sua arquitetura e à sua região AWS, e configure o contêiner de instrumentação.

Adicione e configure a [camada Lambda do Coletor OpenTelemetry](https://opentelemetry.io/docs/platforms/faas/lambda-collector/). Mantenha os exportadores do SDK da aplicação apontando para o coletor local, conforme descrito na documentação upstream. Em seguida, configure a conexão de saída do coletor, conforme mostrado abaixo.

### Configure o destino do coletor Lambda {#configure-lambda-collector-destination}

Defina `CLICKHOUSE_OTLP_ENDPOINT` e `CLICKHOUSE_INGESTION_API_KEY` nas variáveis de ambiente da sua função Lambda. Adicione o seguinte exportador à configuração do seu coletor.

Defina `CLICKHOUSE_OTLP_ENDPOINT` como o endpoint OTLP HTTP do seu coletor do ClickStack e `CLICKHOUSE_INGESTION_API_KEY` como a chave de ingestão correspondente. O endpoint deve estar acessível a partir da sua função Lambda.

```yaml
exporters:
  otlphttp/clickhouse:
    endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
    headers:
      Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
```

Use `otlphttp/clickhouse` na lista `exporters` de cada pipeline de sinal que você deseja enviar. Por exemplo, com o receptor `otlp` do upstream:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

Mescle essas configurações na configuração do seu coletor, preservando as configurações de receptor e de processador. Empacote a configuração junto com sua função e defina `OPENTELEMETRY_COLLECTOR_CONFIG_URI` com o caminho do arquivo, como `/var/task/collector.yaml`, conforme as instruções de configuração do coletor na documentação upstream.

## Verificar a ingestão {#verify-ingestion}

Implante e invoque sua função. No ClickStack, selecione um intervalo de tempo recente e localize o nome do serviço da sua função em Traces. Confira também Logs e Metrics, caso sua instrumentação emita esses sinais; adicionar um pipeline não habilita a coleta deles automaticamente.

Para configuração da camada e solução de problemas, consulte a [documentação do OpenTelemetry Lambda](https://github.com/open-telemetry/opentelemetry-lambda).
