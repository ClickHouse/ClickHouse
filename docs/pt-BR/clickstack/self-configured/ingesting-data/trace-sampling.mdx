Serviços de alta taxa de processamento podem gerar milhões de spans por segundo. Armazenar todos os spans é caro, por isso é comum que as equipes executem o [processador de amostragem ao final](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/processor/tailsamplingprocessor) do Coletor OpenTelemetry para manter apenas 1 a cada N spans. Cada span mantido inclui um atributo `SampleRate` que registra o valor de N.

Com os dados amostrados, agregações simples produzem resultados incorretos: `count()` retorna N vezes menos eventos do que os que de fato ocorreram, `sum()` e `avg()` ficam enviesados e os percentis se deslocam. Os dashboards passam a exibir contagens de requisições, vazão e taxas de erro artificialmente baixas.

O Self-managed ClickHouse Observability resolve esse problema com uma engine de consulta que leva a amostragem em conta. Ao configurar uma expressão da taxa de amostragem em uma fonte de traces, o construtor de consultas reescreve as agregações SQL para ponderar cada span pela respectiva taxa de amostragem — em dashboards, alertas e buscas ad hoc.

## Como funciona {#how-it-works}

Quando uma fonte de traces tem uma `sampleRateExpression` configurada, o construtor de consultas a encapsula da seguinte forma:

```sql
greatest(toUInt64OrZero(toString(expr)), 1)
```

Spans sem o atributo `SampleRate` recebem peso 1 por padrão, de modo que dados não amostrados produzem resultados idênticos aos das consultas originais.

Em seguida, o construtor de consultas reescreve as agregações:

| Agregação          | Antes              | Depois (corrigido pela amostragem)        |
| ------------------ | ------------------ | ----------------------------------------- |
| count              | `count()`          | `sum(weight)`                             |
| count + condição   | `countIf(cond)`    | `sumIf(weight, cond)`                     |
| avg                | `avg(col)`         | `sum(col * weight) / sum(weight)`         |
| sum                | `sum(col)`         | `sum(col * weight)`                       |
| quantile(p)        | `quantile(p)(col)` | `quantileTDigestWeighted(p)(col, weight)` |
| min / max          | sem alteração      | sem alteração                             |
| count&#95;distinct | sem alteração      | sem alteração                             |

<Note>
  Com amostragem, os percentis usam `quantileTDigestWeighted`, um sketch T-Digest aproximado. Os resultados são próximos, mas não exatos.
</Note>

## Configurando a expressão da taxa de amostragem {#configuring}

Abra sua fonte de traces em **configurações da fonte** e, no campo **expressão da taxa de amostragem**, insira a expressão do ClickHouse que resulta na taxa de amostragem de cada span.

Por exemplo, se o processador de amostragem ao final do OpenTelemetry gravar a taxa em `SpanAttributes['SampleRate']`:

Depois que essa expressão for configurada, todos os gráficos, dashboards, alertas e painéis do dashboard de serviço passam a aplicar automaticamente agregações ponderadas pela taxa de amostragem. Não é preciso alterar nenhuma consulta individualmente.
