  Esta página aborda o **Self-managed ClickHouse Observability**. Para a experiência totalmente gerenciada, que é a recomendada, consulte a documentação [aqui](/pt-BR/clickstack/observability/getting-started).

Este **guia é destinado a quem já usa o ClickHouse Cloud**. Se você ainda não conhece o ClickHouse Cloud, recomendamos nosso guia [Primeiros Passos](/pt-BR/clickstack/self-configured/getting-started/managed) do Self-managed ClickHouse Observability.

Neste padrão de implantação, tanto o ClickHouse quanto a Interface do ClickStack são hospedados no ClickHouse Cloud, o que minimiza o número de componentes que o usuário precisa hospedar por conta própria.

Além de reduzir o gerenciamento de infraestrutura, este padrão de implantação garante que a autenticação seja integrada ao SSO/SAML do ClickHouse Cloud. Diferentemente das implantações auto-hospedadas, também não é necessário provisionar uma instância do MongoDB para armazenar o estado da aplicação, como dashboards, buscas salvas, configurações do usuário e alertas. Os usuários também contam com:

* Escalonamento automático de capacidade computacional independente do armazenamento
* Retenção de baixo custo e praticamente ilimitada, baseada em armazenamento de objetos
* A possibilidade de [isolar cargas de trabalho de leitura e gravação de forma independente](/pt-BR/clickstack/self-configured/managing/isolating-read-write) com Warehouses.
* Autenticação integrada
* Backups automatizados
* Recursos de segurança e conformidade
* Upgrades sem interrupções

Neste modo, a ingestão de dados fica inteiramente a cargo do usuário. Você pode ingerir dados no Self-managed ClickHouse Observability usando seu próprio coletor OpenTelemetry hospedado, ingestão direta a partir de bibliotecas de cliente, motores de tabela nativos do ClickHouse (como Kafka ou S3), pipelines de ETL ou ClickPipes, o serviço de ingestão gerenciado do ClickHouse Cloud. Essa abordagem oferece a forma mais simples e de melhor desempenho de operar o ClickStack.

### Indicado para {#suitable-for}

Este padrão de implantação é ideal nos seguintes cenários:

1. Você já tem dados de observabilidade no ClickHouse Cloud e deseja visualizá-los com o ClickStack.
2. Você opera uma implantação de observabilidade de grande porte e precisa do desempenho dedicado e da escalabilidade do ClickStack executado no ClickHouse Cloud.
3. Você já usa o ClickHouse Cloud para analytics e deseja instrumentar sua aplicação com as bibliotecas de instrumentação do ClickStack, enviando dados para o mesmo cluster. Nesse caso, recomendamos usar [warehouses](/pt-BR/products/cloud/features/infrastructure/warehouses) para isolar a capacidade computacional das cargas de trabalho de observabilidade.

### Crie um banco de dados e uma tabela {#create-database-and-tables}

            O Vector exige que uma tabela e um schema sejam definidos antes da ingestão de dados.

            Primeiro, crie um banco de dados. Isso pode ser feito pelo [console do ClickHouse Cloud](/pt-BR/products/cloud/features/sql-console-features/sql-console).

            Por exemplo, crie um banco de dados para logs:

            ```sql
            CREATE DATABASE IF NOT EXISTS logs
            ```

            Em seguida, crie uma tabela cujo schema corresponda à estrutura dos seus dados de log. O exemplo abaixo considera o formato clássico de log de acesso do Nginx:

            ```sql
            CREATE TABLE logs.nginx_logs
            (
                `time_local` DateTime,
                `remote_addr` IPv4,
                `remote_user` LowCardinality(String),
                `request` String,
                `status` UInt16,
                `body_bytes_sent` UInt64,
                `http_referer` String,
                `http_user_agent` String,
                `http_x_forwarded_for` LowCardinality(String),
                `request_time` Float32,
                `upstream_response_time` Float32,
                `http_host` String
            )
            ENGINE = MergeTree
            ORDER BY (toStartOfMinute(time_local), status, remote_addr);
            ```

            Sua tabela deve estar alinhada ao schema de saída produzido pelo Vector. Ajuste o schema conforme necessário para seus dados, seguindo as [boas práticas de schema](/pt-BR/concepts/best-practices/select-data-type) recomendadas.

            Recomendamos fortemente que você entenda como as [chaves primárias](/pt-BR/concepts/core-concepts/primary-indexes) funcionam no ClickHouse e escolha uma chave de ordenação com base nos seus padrões de acesso. Consulte as orientações [específicas do ClickStack](/pt-BR/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key) sobre como escolher uma chave primária.

            Depois de criar a tabela, copie o trecho de configuração exibido. Ajuste a entrada para consumir seus pipelines existentes e, se necessário, a tabela de destino e o banco de dados. As credenciais já devem vir preenchidas.

### Concessão de acesso ao Self-managed ClickHouse Observability {#configure-access}

1. Navegue até o seu serviço no console do ClickHouse Cloud
2. Acesse **Settings** → **SQL Console Access**
3. Defina o nível de permissão adequado para cada usuário:
   * **Service Admin → Full Access** - Obrigatório para habilitar alertas
   * **Service Read Only → Read Only** - Pode visualizar dados de observabilidade e criar dashboards
   * **No access** - Não pode acessar a interface do ClickStack

### Usando o ClickStack com recursos computacionais somente para leitura {#clickstack-read-only-compute}

A interface do ClickStack pode ser executada inteiramente em um serviço do ClickHouse Cloud read-only. Essa é a configuração recomendada quando você quer isolar as cargas de trabalho de ingestão e de consulta.

#### Como o ClickStack seleciona a capacidade computacional {#how-clickstack-selects-compute}

A Interface do ClickStack sempre se conecta ao serviço do ClickHouse a partir do qual ela é iniciada no console do ClickHouse Cloud.

Isso significa que:

* Se você abrir o ClickStack a partir de um serviço read-only, todas as consultas emitidas pela Interface do ClickStack serão executadas nessa capacidade computacional read-only.
* Se você abrir o ClickStack a partir de um serviço de leitura e escrita, o ClickStack usará a capacidade computacional desse serviço.

Não é necessária nenhuma configuração adicional no ClickStack para impor o comportamento read-only.

#### Configuração recomendada {#recommended-setup}

Para executar o ClickStack em recursos computacionais read-only:

1. Crie ou identifique um Serviço do ClickHouse Cloud no warehouse configurado como read-only.
2. No console do ClickHouse Cloud, selecione o serviço read-only.
3. Inicie o ClickStack pelo menu de navegação à esquerda.

Após a inicialização, a Interface do ClickStack será vinculada automaticamente a esse serviço read-only.

Observe que dashboards, buscas salvas, alertas e fontes de dados ficam restritos ao serviço a partir do qual o ClickStack foi iniciado. Portanto, qualquer item salvo em outro serviço do warehouse não estará disponível aqui e precisará ser recriado. Fontes de dados que usam o schema padrão do OpenTelemetry são detectadas automaticamente, então a busca nesses dados funciona de imediato; já as fontes de dados personalizadas ou configuradas manualmente não são detectadas e precisam ser configuradas novamente.

Para conhecer a topologia completa — incluindo para onde direcionar a ingestão, em qual serviço executar DDL e como os alertas se comportam —, consulte [&quot;Isolando cargas de trabalho de leitura e gravação&quot;](/pt-BR/clickstack/self-configured/managing/isolating-read-write).

## Escolha de schema: Map vs JSON {#schema-choice-map-vs-json}

Por padrão, o ClickStack armazena atributos em colunas `Map(LowCardinality(String), String)`. Este é o schema recomendado para cargas de trabalho de observabilidade. Combinado com a [serialização de mapas em buckets](/pt-BR/reference/data-types/map#bucketed-map-serialization) e com índices de texto nas chaves e valores do map, ele permite consultas seletivas sem a sobrecarga de ingestão por chave das subcolunas JSON dinâmicas.

Um schema baseado no tipo `JSON` está disponível em Beta para avaliação em cargas de trabalho com um conjunto pequeno e estável de chaves de atributo. Ele **não é recomendado** como padrão. Consulte [Map vs Tipo JSON](/pt-BR/clickstack/self-configured/ingesting-data/schema/map-vs-json) para ver a comparação completa e as variáveis de ambiente necessárias para habilitar o suporte a JSON.
