<Note>
  Esta página trata do **Self-managed ClickHouse Observability**. Para a experiência totalmente gerenciada, que é a recomendada, consulte a documentação [aqui](/pt-BR/clickstack/observability/integration-examples/kubernetes).
</Note>

Este guia mostra como coletar logs, métricas de infraestrutura e eventos do Kubernetes de um cluster no Self-managed ClickHouse Observability e, em seguida, visualizá-los no Painel do Kubernetes integrado.

O padrão é o convencional do OpenTelemetry: dois coletores implantados por meio do [Chart do Helm do OpenTelemetry](https://github.com/open-telemetry/opentelemetry-helm-charts/tree/main/charts/opentelemetry-collector), cada um encaminhando dados via OTLP para o seu coletor gateway do ClickStack. Um **Conjunto de Daemon** (DaemonSet) é executado em cada nó para coletar logs de contêineres e métricas do kubelet. Uma **Implantação** (Deployment) com uma única réplica coleta eventos do Kubernetes e métricas de todo o cluster. Para mais informações sobre a função de gateway, consulte [Funções do coletor](/pt-BR/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured).

Este guia pressupõe que você já concluiu o guia [Configurando seu OpenTelemetry Collector](/pt-BR/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) e que tem um coletor gateway do ClickStack em execução.

Para cargas de trabalho executadas no Kubernetes, o próprio coletor gateway deve ser implantado **no mesmo cluster, usando o Chart do Helm upstream do OpenTelemetry com a imagem do Coletor do ClickStack**. Para instalá-lo, siga o procedimento com Helm descrito em [Implantação do coletor](/pt-BR/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured). **Não se esqueça de anotar esse endpoint OTLP**.

<Steps>
  <Step title="Prepare os pré-requisitos" id="gather-prerequisites">
    Você precisará de:

    * Um **cluster do Kubernetes** (v1.20+ recomendado) com o `kubectl` configurado para ele.
    * **[Helm](https://helm.sh/) v3+**.
    * O **endpoint OTLP** do seu coletor gateway do ClickStack, acessível de dentro do cluster, por exemplo, `http://clickstack-otel-collector.observability.svc.cluster.local:4318`. O coletor deve ser implantado em um local acessível pelos seus Conjuntos de Daemon e pela sua Implantação, normalmente no mesmo cluster ou por meio de um serviço do tipo `LoadBalancer`.
    * O valor de `OTLP_AUTH_TOKEN` que você definiu ao implantar o coletor gateway. Se você não protegeu o coletor, pode pular a etapa do Secret abaixo e remover o cabeçalho `authorization` dos manifestos.

    <Info>
      **Onde o gateway é executado**

      Para uma implantação local no cluster, execute o coletor gateway como um `Deployment` ou `StatefulSet` do Kubernetes dentro do mesmo cluster e acesse-o pelo DNS do serviço in-cluster correspondente. Para um gateway executado fora do cluster, use a URL acessível externamente.
    </Info>
  </Step>

  <Step title="Crie o Secret de autenticação e o ConfigMap" id="create-secret-and-configmap">
    Escolha o namespace em que os coletores serão executados e, em seguida, crie um Secret contendo o `OTLP_AUTH_TOKEN` e um ConfigMap que aponte para o seu gateway:

    ```shell
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    export OTEL_COLLECTOR_ENDPOINT="http://clickstack-otel-collector.observability.svc.cluster.local:4318"
    export NAMESPACE=observability

    kubectl create namespace ${NAMESPACE} --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic clickstack-otlp-secret \
      --from-literal=OTLP_AUTH_TOKEN=${OTLP_AUTH_TOKEN} \
      -n ${NAMESPACE}

    kubectl create configmap otel-config-vars \
      --from-literal=YOUR_OTEL_COLLECTOR_ENDPOINT=${OTEL_COLLECTOR_ENDPOINT} \
      -n ${NAMESPACE}
    ```

    Os dois coletores abaixo leem esses valores por meio de `extraEnvs`, de modo que o mesmo Secret e o mesmo ConfigMap são reutilizados por ambos.
  </Step>

  <Step title="Adicione o repositório Helm do OpenTelemetry" id="add-otel-helm-repo">
    ```shell
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update
    ```
  </Step>

  <Step title="Implante o coletor do cluster" id="deploy-cluster-collector">
    Esta é uma Implantação de réplica única que coleta **eventos do Kubernetes** e **métricas de todo o cluster** (contagens de nós, fases de pods, status de implantações etc.). Executar mais de uma réplica geraria dados duplicados.

    Salve o conteúdo a seguir como `k8s_deployment.yaml`:

    <Accordion title="k8s_deployment.yaml">
      ```yaml
      # k8s_deployment.yaml
      mode: deployment

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # Queremos apenas um destes coletores - mais do que isso produziria dados duplicados
      replicaCount: 1

      presets:
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        # Coleta eventos do Kubernetes por meio do k8sobject receiver.
        kubernetesEvents:
          enabled: true
        # Coleta métricas em nível de cluster por meio do k8s_cluster receiver.
        clusterMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"
        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    Instale-o:

    ```shell
    helm install k8s-otel-deployment open-telemetry/opentelemetry-collector \
      -f k8s_deployment.yaml \
      -n ${NAMESPACE}
    ```
  </Step>

  <Step title="Implante o coletor de nó" id="deploy-node-collector">
    Este é um Conjunto de Daemon executado em cada nó para coletar **logs de contêiner**, **métricas de host** e **métricas do agente de nó do Kubernetes** (utilização de CPU e memória por pod e por contêiner em relação a requests e limits).

    Salve o conteúdo a seguir como `k8s_daemonset.yaml`:

    <Accordion title="k8s_daemonset.yaml">
      ```yaml
      # k8s_daemonset.yaml
      mode: daemonset

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # Necessário para usar as métricas de utilização de CPU/memória do kubeletstats
      clusterRole:
        create: true
        rules:
          - apiGroups:
              - ''
            resources:
              - nodes/proxy
            verbs:
              - get

      presets:
        logsCollection:
          enabled: true
        hostMetrics:
          enabled: true
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        kubeletMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        receivers:
          # Métricas adicionais do kubelet, expressas como utilização em relação a requests e limits.
          kubeletstats:
            collection_interval: 20s
            auth_type: 'serviceAccount'
            endpoint: '${env:K8S_NODE_NAME}:10250'
            insecure_skip_verify: true
            metrics:
              k8s.pod.cpu_limit_utilization:
                enabled: true
              k8s.pod.cpu_request_utilization:
                enabled: true
              k8s.pod.memory_limit_utilization:
                enabled: true
              k8s.pod.memory_request_utilization:
                enabled: true
              k8s.pod.uptime:
                enabled: true
              k8s.node.uptime:
                enabled: true
              k8s.container.cpu_limit_utilization:
                enabled: true
              k8s.container.cpu_request_utilization:
                enabled: true
              k8s.container.memory_limit_utilization:
                enabled: true
              k8s.container.memory_request_utilization:
                enabled: true
              container.uptime:
                enabled: true

        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"

        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    Faça a instalação:

    ```shell
    helm install k8s-otel-daemonset open-telemetry/opentelemetry-collector \
      -f k8s_daemonset.yaml \
      -n ${NAMESPACE}
    ```

    Confirme que ambas as releases estão íntegras:

    ```shell
    kubectl get pods -n ${NAMESPACE} -l app.kubernetes.io/name=opentelemetry-collector
    ```

    Você deverá ver um pod do Kubernetes da Implantação e um pod do Kubernetes do Conjunto de Daemon por nó, todos com o estado `Running`.
  </Step>

  <Step title="Encaminhe atributos do Kubernetes para suas aplicações (recomendado)" id="forward-k8s-attributes">
    Para correlacionar seus logs de aplicação, métricas e rastros com metadados do Kubernetes (nome do pod, namespace, nó, implantação), encaminhe os metadados para sua aplicação por meio de `OTEL_RESOURCE_ATTRIBUTES`. Em seguida, o processador `k8sattributes` do Conjunto de Daemon enriquecerá a telemetria recebida com os atributos correspondentes do pod e do nó.

    ```yaml
    # my_app_deployment.yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: app-deployment
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: app
      template:
        metadata:
          labels:
            app: app
            service.name: <MY_APP_NAME>
        spec:
          containers:
            - name: app-container
              image: my-image
              env:
                - name: POD_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.name
                - name: POD_UID
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.uid
                - name: POD_NAMESPACE
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.namespace
                - name: NODE_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: spec.nodeName
                - name: DEPLOYMENT_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.labels['deployment']
                - name: OTEL_RESOURCE_ATTRIBUTES
                  value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME),k8s.deployment.name=$(DEPLOYMENT_NAME)
    ```
  </Step>

  <Step title="Confirme na interface do ClickStack" id="confirm-in-ui">
    Abra seu serviço no [console do ClickHouse Cloud](https://console.clickhouse.cloud) e selecione **ClickStack** no menu à esquerda.

    <div className="ch-image-lg">
      <Frame>
        ![Iniciar o ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    Na visualização **Search**, altere a fonte de dados para `Logs` e defina o intervalo de tempo como **Last 15 minutes**. Em poucos segundos, os logs dos contêineres de todo o cluster devem aparecer, enriquecidos com atributos como `k8s.namespace.name`, `k8s.pod.name` e `k8s.node.name`.

    <div className="ch-image-lg">
      <Frame>
        ![Visualização de pesquisa do ClickStack com logs do Kubernetes](/images/use-cases/observability/clickstack-search-with-k8-logs.webp)
      </Frame>
    </div>

    Para visualizar métricas e eventos de infraestrutura em contexto, abra o dashboard integrado **Kubernetes** em **Dashboards** -&gt; **Kubernetes**. As abas `Pods`, `Nodes` e `Namespaces` devem estar todas preenchidas.

    <div className="ch-image-lg">
      <Frame>
        ![Painel do Kubernetes do ClickStack](/images/use-cases/observability/clickstack-dashboard-kubernetes.webp)
      </Frame>
    </div>

    Se nada aparecer:

    * Verifique se os pods do Conjunto de Daemon e da Implantação estão no estado `Running` e acompanhe os logs deles com `kubectl logs -n ${NAMESPACE} <pod>`.
    * Confirme que o `YOUR_OTEL_COLLECTOR_ENDPOINT` está acessível de dentro do cluster (execute `kubectl exec` em um dos pods do coletor e faça um `curl` para o endpoint).
    * Verifique se o `OTLP_AUTH_TOKEN` no Secret corresponde ao valor definido no coletor gateway.
  </Step>
