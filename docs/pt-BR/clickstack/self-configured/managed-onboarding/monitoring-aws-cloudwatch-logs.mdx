<Note>
  Esta página aborda o **Self-managed ClickHouse Observability**. Para a experiência totalmente gerenciada recomendada, consulte a documentação [aqui](/pt-BR/clickstack/observability/integration-examples/cloudwatch).
</Note>

Este guia mostra como encaminhar logs do AWS CloudWatch para o Self-managed ClickHouse Observability usando o [receptor `awscloudwatch`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver) do OpenTelemetry e, em seguida, visualizá-los na Interface do ClickStack.

Vamos executar um coletor separado que consulta o CloudWatch por meio da API da AWS e encaminha os eventos para o seu Coletor do ClickStack via OTLP. Mantenha esse coletor na mesma AWS account e região dos grupos de logs para minimizar a latência e o custo das chamadas de API.

Este guia pressupõe que você já concluiu o guia [Configurando seu OpenTelemetry Collector](/pt-BR/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) e tem um Coletor do ClickStack em execução.

O Coletor do ClickStack pode ser implantado como um **contêiner Docker** (consulte [Configurando seu OpenTelemetry Collector](/pt-BR/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)) ou como um **release do Helm** no Kubernetes, usando o Chart do Helm upstream do OpenTelemetry com a imagem do Coletor do ClickStack (consulte [Implantação do coletor](/pt-BR/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)). **Anote o endpoint OTLP** e o `OTLP_AUTH_TOKEN` definido durante a implantação.

<Steps>
  <Step title="Prepare os pré-requisitos" id="gather-prerequisites">
    Você vai precisar de:

    * Uma **AWS account** com um ou mais grupos de logs do CloudWatch e credenciais com as permissões do IAM listadas abaixo.
    * Um host com **Docker** instalado, acesso à API da AWS e acesso de rede de saída ao seu coletor do ClickStack. Normalmente, trata-se de uma instância EC2 na mesma AWS account e região dos grupos de logs.
    * O **endpoint OTLP** do seu coletor do ClickStack, acessível a partir deste host. Se ele estiver em execução no Docker na mesma máquina, use `http://host.docker.internal:4318` (consulte o bloco de destaque em [Configure o receptor do CloudWatch](#configure-receiver)). Para um coletor remoto, use a URL completa dele, por exemplo, `https://otel.example.com:4318`.
    * O valor de `OTLP_AUTH_TOKEN` que você definiu no seu coletor do ClickStack. Se você não o protegeu, pode remover o cabeçalho `authorization` da configuração abaixo.
  </Step>

  <Step title="Configure as credenciais da AWS" id="configure-aws">
    O receptor obtém as credenciais da AWS das variáveis de ambiente padrão. Exporte-as no host em que o coletor será executado.

    **Para usuários do AWS SSO:**

    ```shell
    aws sso login --profile YOUR_PROFILE_NAME
    eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
    aws sts get-caller-identity
    ```

    **Para usuários do IAM com credenciais de longo prazo:**

    ```shell
    export AWS_ACCESS_KEY_ID="your-access-key-id"
    export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
    export AWS_REGION="us-east-1"
    aws sts get-caller-identity
    ```

    As credenciais precisam da seguinte política do IAM para ler os logs do CloudWatch:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    Substitua `YOUR_ACCOUNT_ID` pelo ID da sua AWS account.

    <Info>
      **Credenciais de produção**

      Em produção, prefira credenciais vinculadas à instância a chaves de longa duração: uma IAM role no EC2, IRSA no EKS ou uma task role no ECS. A mesma configuração do coletor mostrada abaixo funciona sem nenhuma variável de ambiente de credencial quando o receptor consegue obter as credenciais do serviço de metadados da instância.
    </Info>
  </Step>

  <Step title="Configure o receptor do CloudWatch" id="configure-receiver">
    Exporte o endpoint e o token de autenticação do seu Coletor do ClickStack e, em seguida, crie um arquivo `otel-collector-config.yaml`.

    <Info>
      **Configuração no mesmo host**

      O exemplo abaixo pressupõe que o Coletor do ClickStack e este coletor do CloudWatch sejam executados no mesmo host, de modo que o receptor se conecta a ele por meio de `host.docker.internal` (o endereço do host Docker visto de dentro de um contêiner). Se o seu Coletor do ClickStack estiver em outro lugar (um serviço in-cluster, uma URL pública, um IP privado), substitua o endereço dele em `OTEL_COLLECTOR_ENDPOINT` abaixo.
    </Info>

    ```shell
    export OTEL_COLLECTOR_ENDPOINT="http://host.docker.internal:4318"
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    ```

    <Accordion title="Descubra os grupos de logs disponíveis na sua conta">
      Antes de editar a configuração, liste os grupos de logs existentes na sua região para escolher nomes reais (e confirmar que a região está correta):

      ```shell
      aws logs describe-log-groups --region eu-central-1 \
        --query 'logGroups[].logGroupName' --output table
      ```

      Exemplo de saída:

      ```text
      -------------------------------
      |      DescribeLogGroups      |
      +-----------------------------+
      |  /aws-glue/jobs/error       |
      |  /aws-glue/jobs/logs-v2     |
      |  /aws-glue/jobs/output      |
      |  /aws-glue/sessions/error   |
      |  /aws-glue/sessions/output  |
      +-----------------------------+
      ```

      Use os nomes desta lista diretamente no bloco `groups.named` do Exemplo 1 abaixo. Para a conta acima, a seção de grupos nomeados ficaria assim:

      ```yaml
      groups:
        named:
          /aws-glue/jobs/error:
          /aws-glue/jobs/logs-v2:
          /aws-glue/jobs/output:
          /aws-glue/sessions/error:
          /aws-glue/sessions/output:
      ```

      Como alternativa, se os grupos desejados tiverem um prefixo em comum (aqui, `/aws-glue/`), use o Exemplo 2 com `prefix: /aws-glue/` em vez de listá-los um a um.
    </Accordion>

    **Exemplo 1: Grupos de logs nomeados (recomendado)**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws-glue/jobs/error:
              /aws-glue/jobs/output:
              /aws-glue/sessions/error:

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    **Exemplo 2: Descoberta automática de grupos de logs por prefixo**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            autodiscover:
              limit: 100
              prefix: /aws-glue/

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    Principais configurações a ajustar:

    * `region` para corresponder à região onde estão seus grupos de logs.
    * `poll_interval` (padrão `1m`). Valores menores fornecem logs quase em real-time, ao custo de mais chamadas de API à AWS.
    * `groups.named` para uma lista explícita, ou `groups.autodiscover.prefix` para capturar todos os grupos que correspondem a um prefixo.

    Para ver todas as opções disponíveis, consulte a [documentação do receptor do CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver).

    <Info>
      **Apenas logs recentes**

      Na primeira execução, o receptor registra um ponto de verificação no horário atual e obtém apenas os logs a partir desse momento. Não é feita carga de dados históricos dos logs anteriores.
    </Info>
  </Step>

  <Step title="Inicie o coletor receptor" id="start-collector">
    Crie um `docker-compose.yaml` junto ao `otel-collector-config.yaml`. A entrada `extra_hosts` permite que o contêiner acesse um coletor do ClickStack em execução no mesmo host por meio de `host.docker.internal`; já o bind mount na sintaxe longa gera um erro explícito se o arquivo de configuração estiver ausente, em vez de criar silenciosamente um diretório vazio:

    ```shell
    cat > docker-compose.yaml <<'EOF'
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:latest
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_COLLECTOR_ENDPOINT
          - OTLP_AUTH_TOKEN
        extra_hosts:
          - "host.docker.internal:host-gateway"
        restart: unless-stopped
    EOF
    ```

    Inicie o coletor:

    ```shell
    docker compose up -d
    ```

    Acompanhe os logs em tempo real para confirmar que ele está fazendo polling do CloudWatch e exportando os dados para o seu Coletor do ClickStack:

    ```shell
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="Confirme na interface do ClickStack" id="confirm-in-ui">
    Abra seu serviço no [console do ClickHouse Cloud](https://console.clickhouse.cloud) e selecione **ClickStack** no menu à esquerda.

    <div className="ch-image-lg">
      <Frame>
        ![Iniciar o ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    Na visualização **Search**, altere a fonte de dados para `Logs` e defina o intervalo de tempo como **Last 15 minutes**. Os eventos do CloudWatch devem aparecer após alguns intervalos de poll.

    <div className="ch-image-lg">
      <Frame>
        ![Visualização de pesquisa do ClickStack com logs do CloudWatch](/images/clickstack/cloudwatch/log-search-view-clickstack.webp)
      </Frame>
    </div>

    Cada evento inclui o grupo e o stream de origem como atributos de recurso:

    * `ResourceAttributes['aws.region']`: a região AWS (por exemplo, `eu-central-1`)
    * `ResourceAttributes['cloudwatch.log.group.name']`: o grupo de logs de origem
    * `ResourceAttributes['cloudwatch.log.stream']`: o stream de logs de origem
    * `Body`: a linha de log original

    Altere a pesquisa para `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body` para incluir esses atributos:

    <div className="ch-image-lg">
      <Frame>
        ![Visualização de pesquisa do ClickStack com logs e atributos do CloudWatch](/images/clickstack/cloudwatch/log-search-attributes-clickstack.webp)
      </Frame>
    </div>

    Selecione uma entrada de log para inspecionar seus metadados:

    <div className="ch-image-lg">
      <Frame>
        ![Atributos do CloudWatch na visualização de detalhes do log](/images/clickstack/cloudwatch/error-log-column-values-clickstack.webp)
      </Frame>
    </div>

    Se nada aparecer:

    * Execute `aws sts get-caller-identity` no host do coletor para confirmar que as credenciais são válidas.
    * Acompanhe os logs do coletor com `docker compose logs -f otel-collector` e procure por `AccessDeniedException` (IAM), erros de `security token` (credenciais SSO expiradas), `ResourceNotFoundException` (erro de digitação no nome do grupo de logs ou região incorreta) ou `connection refused` (o endpoint do seu coletor do ClickStack não está acessível de dentro do contêiner; consulte a nota sobre `host.docker.internal` em [Configurar o receptor do CloudWatch](#configure-receiver)).
    * Verifique se `OTEL_COLLECTOR_ENDPOINT` está acessível de dentro do contêiner: `docker compose exec otel-collector wget -qO- ${OTEL_COLLECTOR_ENDPOINT}/v1/logs -S 2>&1 | head -5`.
    * Confirme que `OTLP_AUTH_TOKEN` corresponde ao valor definido no seu coletor do ClickStack.
  </Step>

  </Step>
