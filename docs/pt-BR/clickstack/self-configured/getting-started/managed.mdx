Implante o Self-managed ClickHouse Observability no ClickHouse Cloud, envie um evento de teste pelo seu pipeline de ingestão e confirme que o evento está disponível na UI de observabilidade.

O ClickHouse Cloud opera o backend do ClickHouse, enquanto você mantém o controle do pipeline de ingestão e do schema. O Self-managed ClickHouse Observability oferece:

* Escalonamento automático da capacidade computacional, independente do armazenamento
* Retenção de baixo custo e praticamente ilimitada, com base em armazenamento de objetos
* Isolamento independente das cargas de trabalho de leitura e escrita com [warehouses](/pt-BR/products/cloud/features/infrastructure/warehouses)
* Autenticação integrada
* Backups automatizados
* Funcionalidades de segurança e conformidade
* Upgrades sem interrupções

## Antes de começar {#before-you-begin}

Você também pode enviar dados diretamente para o ClickHouse usando uma [integração compatível](/pt-BR/integrations/home) e o seu próprio schema.

### Crie um serviço do ClickHouse Cloud {#create-a-managed-clickstack-service}

Conclua a etapa [Criar um serviço do ClickHouse](/pt-BR/get-started/setup/cloud#1-create-a-clickhouse-service) do guia de início rápido do ClickHouse Cloud. Antes de continuar, verifique se o serviço está em execução.

  ### Prepare seu ambiente de ingestão {#prepare-your-ingestion-environment}

  * Para iniciar um novo [Coletor OpenTelemetry](/pt-BR/clickstack/self-configured/ingesting-data/collector), instale o [Docker](https://docs.docker.com/get-docker/). No Kubernetes, implante o coletor com o [Helm](/pt-BR/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured).
  * Para usar um coletor existente, execute-o na [função de gateway](/pt-BR/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) e verifique se a distribuição dele inclui o [exportador do ClickHouse](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter). A configuração necessária será adicionada ao longo deste guia.

          A UI gera o comando do coletor com as credenciais de administrador `default`. Recomendamos usar credenciais de ingestão dedicadas, para manter o acesso de ingestão separado da administração e não depender da senha de administrador.

          <Accordion title="Criar credenciais de ingestão dedicadas (recomendado)">
            No ClickHouse Cloud, abra o console SQL do seu serviço e execute:

            ```sql
            CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
            GRANT SELECT, INSERT, CREATE DATABASE, CREATE TABLE, CREATE VIEW ON default.* TO `clickstack-ingest`;
            ```

            No comando gerado, substitua `CLICKHOUSE_USER="default"` por `CLICKHOUSE_USER="clickstack-ingest"` e defina `CLICKHOUSE_PASSWORD` com a senha do usuário dedicado.
          </Accordion>

          Para continuar com as credenciais de administrador `default`, copie o comando da aba **Start Collector**. A UI já preenche o endpoint do serviço. Substitua o placeholder da senha pela senha do seu serviço. Caso não a tenha mais, [obtenha ou redefina os detalhes de conexão](/pt-BR/products/cloud/guides/sql-console/connection-details).

          O comando segue este formato:

          ```shell
          docker run -e CLICKHOUSE_ENDPOINT="https://<host>:8443" \
              -e CLICKHOUSE_USER="default" \
              -e CLICKHOUSE_PASSWORD="<your_password_here>" \
              -p 4317:4317 -p 4318:4318 \
              clickhouse/clickstack-otel-collector:latest
          ```

          Substitua `<host>` e `<your_password_here>` pelos valores do seu Serviço do ClickHouse Cloud e execute o comando.

          O coletor é executado em primeiro plano. Mantenha este terminal aberto e use um segundo terminal para os demais comandos deste guia.

          <Note>
            Este comando expõe as portas OTLP sem autenticação e se destina apenas à avaliação local. Antes de enviar tráfego de produção, [proteja o coletor](/pt-BR/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).

  ## Configurar o Self-managed ClickHouse Observability {#set-up-managed-clickstack-vector}

  <Steps titleSize="h3">
    <Step title="Selecione Vector e configure a ingestão" id="choose-an-ingestion-source-vector">
      No seu serviço do ClickHouse Cloud, abra o ClickHouse Observability. Na página **Primeiros Passos**, clique em **Iniciar ingestão**.

      <div className="ch-image-lg">
        <Frame>
          ![Iniciar ingestão](/images/clickstack/getting-started/start_ingestion.webp)
        </Frame>
      </div>

      Na página **Choose an ingestion source**, selecione [Vector](https://vector.dev/).

      <div className="ch-image-lg">
        <Frame>
          ![Selecione Vector como fonte de dados de ingestão](/images/clickstack/getting-started/select_source_vector_toggle.webp)
        </Frame>
      </div>

      [Vector](https://vector.dev) é um pipeline de dados de observabilidade de alto desempenho e independente de fornecedor, especialmente popular para a ingestão de logs graças à sua flexibilidade e ao baixo consumo de recursos.

      Ao usar o Vector, é você quem define o schema. Ele pode seguir as convenções do OpenTelemetry ou usar campos específicos dos seus eventos.

      <Info>
        **É necessário ter um pipeline do Vector existente**

        Siga este guia se você já executa o Vector com um pipeline de entrada. Os dados enviados pelo pipeline devem incluir uma **coluna de timestamp** ou um campo de tempo equivalente, que você selecionará ao configurar a fonte de dados na UI de observabilidade.

        As etapas a seguir adicionam um destino do ClickHouse ao seu pipeline existente.
      </Info>

#### Crie um banco de dados e uma tabela {#create-a-vector-database-and-table}

      Crie um banco de dados e uma tabela antes de configurar o destino do Vector.

      No ClickHouse Cloud, abra o SQL Console do seu serviço e crie um banco de dados:

      Por exemplo, crie um banco de dados para logs:

      ```sql
      CREATE DATABASE IF NOT EXISTS logs
      ```

      Em seguida, crie uma tabela cujo schema corresponda à estrutura dos seus dados de log. O exemplo abaixo pressupõe o formato clássico de log de acesso do Nginx:

      ```sql
      CREATE TABLE logs.nginx_logs
      (
          `time_local` DateTime,
          `remote_addr` IPv4,
          `remote_user` LowCardinality(String),
          `request` String,
          `status` UInt16,
          `body_bytes_sent` UInt64,
          `http_referer` String,
          `http_user_agent` String,
          `http_x_forwarded_for` LowCardinality(String),
          `request_time` Float32,
          `upstream_response_time` Float32,
          `http_host` String
      )
      ENGINE = MergeTree
      ORDER BY (toStartOfMinute(time_local), status, remote_addr);
      ```

      Sua tabela deve estar alinhada ao schema de saída produzido pelo Vector. Ajuste o schema conforme necessário para seus dados, seguindo as [boas práticas de schema](/pt-BR/concepts/best-practices/select-data-type) recomendadas.

      Recomendamos fortemente que você entenda como funcionam as [chaves primárias](/pt-BR/concepts/core-concepts/primary-indexes) no ClickHouse e escolha uma chave de ordenação com base nos seus padrões de acesso. Consulte as orientações de [ajuste de desempenho](/pt-BR/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key) sobre como escolher uma chave primária.

#### Configure o destino do ClickHouse {#configure-the-vector-clickhouse-sink}

      Com a tabela criada, adicione um destino ClickHouse à configuração do Vector:

      ```yaml
      sinks:
        clickhouse:
          type: clickhouse
          inputs:
            - your_input
          endpoint: "https://<host>:8443"
          database: logs
          table: nginx_logs
          format: json_each_row
          skip_unknown_fields: true
          auth:
            strategy: basic
            user: default
            password: "<your_password_here>"
      ```

      Substitua `your_input` pela entrada do seu pipeline atual. Substitua `<host>` e `<your_password_here>` pelos valores do seu serviço do ClickHouse Cloud. Se necessário, altere o banco de dados de destino ou a tabela.

      <Accordion title="Use credenciais dedicadas à ingestão (recomendado)">
        Em produção, crie um usuário dedicado e conceda a ele acesso à tabela de destino do Vector. No ClickHouse Cloud, abra o SQL Console do seu serviço e execute:

        ```sql
        CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
        GRANT SELECT, INSERT ON logs.nginx_logs TO `clickstack-ingest`;
        ```

        Substitua `default` por `clickstack-ingest` no destino do Vector e defina `password` como a senha do usuário dedicado.
      </Accordion>

      Salve a configuração atualizada e, em seguida, recarregue ou reinicie o Vector seguindo seu processo de implantação atual.

      Para mais exemplos de ingestão de dados com o Vector, consulte [Ingestão com o Vector](/pt-BR/clickstack/observability/ingesting-data/vector) ou a [documentação do destino ClickHouse do Vector](https://vector.dev/docs/reference/configuration/sinks/clickhouse/) para opções avançadas.

#### Criar uma fonte de dados {#create-a-vector-data-source}

      Crie uma fonte de dados para a tabela populada pelo seu pipeline do Vector. A UI solicitará que você crie uma no primeiro acesso.

      O formulário já vem preenchido com as expressões do schema padrão do OpenTelemetry. Para a tabela do Nginx criada neste guia, configure a fonte de dados com os seguintes valores:

      | Configuração                          | Valor                                                                                                           |
      | ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
      | **Nome**                              | `Nginx logs`                                                                                                    |
      | **Tipo de dados da fonte**            | Log                                                                                                             |
      | **Conexão com o Servidor**            | `Default`                                                                                                       |
      | **Banco de dados**                    | `logs`                                                                                                          |
      | **Tabela**                            | `nginx_logs`                                                                                                    |
      | **Coluna de Timestamp**               | `time_local`                                                                                                    |
      | **SELECT padrão**                     | `time_local, remote_addr, status, request`                                                                      |
      | **Expressão do nome do serviço**      | `'nginx'`                                                                                                       |
      | **Expressão de nível de log**         | `multiIf(status >= 500, 'ERROR', status >= 400, 'WARN', 'INFO')`                                                |
      | **Expressão de Atributos de Log**     | `map('http.remote_addr', toString(remote_addr), 'http.status_code', toString(status), 'http.request', request)` |
      | **Expressão de Atributos de Recurso** | `map('service.name', 'nginx')`                                                                                  |
      | **Coluna de Timestamp Exibida**       | `time_local`                                                                                                    |
      | **Expressão do ID do trace**          | `''`                                                                                                            |
      | **Expressão de ID do span**           | `''`                                                                                                            |
      | **Expressão de coluna implícita**     | `request`                                                                                                       |

      A tabela do Nginx não contém uma coluna `Body`. Defina **Body Expression** como:

      ```sql
      concat(
        remote_addr, ' ',
        remote_user, ' ',
        '[', formatDateTime(time_local, '%d/%b/%Y:%H:%i:%S %z'), '] ',
        '"', request, '" ',
        toString(status), ' ',
        toString(body_bytes_sent), ' ',
        '"', http_referer, '" ',
        '"', http_user_agent, '" ',
        '"', http_x_forwarded_for, '" ',
        toString(request_time), ' ',
        toString(upstream_response_time), ' ',
        '"', http_host, '"'
      )
      ```

      Para outras configurações da fonte de dados, consulte a [referência de configuração](/pt-BR/clickstack/self-configured/managing/config).
    </Step>

    </Step>
