O [ClickHouse Managed Postgres](/pt-BR/products/managed-postgres/overview) é um serviço Postgres totalmente gerenciado no ClickHouse Cloud. É a fonte Postgres mais rápida de conectar ao ClickPipes: a replicação lógica já vem habilitada em todas as instâncias, os endereços IP do ClickPipes são liberados por padrão e os detalhes de conexão ficam no mesmo console do seu serviço ClickHouse.

Há três maneiras de começar a replicar a partir de uma instância do ClickHouse Managed Postgres. Todas criam um ClickPipe do Postgres comum, portanto tudo o que consta na [documentação do ClickPipe do Postgres](/pt-BR/integrations/clickpipes/postgres/index) se aplica assim que o pipe estiver em execução.

## Opção 1: sincronizar com o ClickHouse a partir do serviço Postgres {#sync-to-clickhouse}

Abra seu ClickHouse Managed serviço Postgres no ClickHouse Cloud console e clique em **Sync to ClickHouse** na barra lateral. O assistente já preenche a source connection e permite escolher o serviço ClickHouse de destino, o método de replicação e as tabelas a serem replicadas. Não é necessário configurar usuário, publication ou rede.

Siga o guia [Sync to ClickHouse](/pt-BR/products/managed-postgres/clickpipes) para um passo a passo detalhado. Para replicação de baixa latência, você também pode escolher o [WalShadow](/pt-BR/products/managed-postgres/walshadow), um engine de replicação nativo que faz a leitura em nível de sistema de arquivos, atualmente em private preview.

## Opção 2: selecionar o ClickHouse Managed Postgres como fonte no ClickPipes {#clickpipes-source}

Se preferir começar pelo lado do destino, abra seu serviço ClickHouse, acesse **Data Sources** e escolha **ClickHouse Managed Postgres** na lista de fontes. Em seguida, informe os detalhes de conexão da sua instância Postgres, assim como faria com qualquer outra fonte Postgres.

### Detalhes de conexão {#connection-details}

Abra seu serviço ClickHouse Managed Postgres e clique em **Connect** para ver o host, a porta, o banco de dados, o usuário e a senha. Use a conexão direta com o Postgres, e não o botão **via PgBouncer**: o ClickPipes não oferece suporte a replicação por meio do PgBouncer nem de qualquer outro pooler de conexões. Consulte [Connection](/pt-BR/products/managed-postgres/connection) para mais detalhes.

Com o [clickhousectl](/pt-BR/concepts/features/interfaces/cli), o comando `clickhousectl cloud postgres get <postgres-id>` mostra o hostname e o nome de usuário. Ele nunca retorna a senha: ela é exibida apenas uma vez, pelo `cloud postgres create`, e o comando `clickhousectl cloud postgres reset-password <postgres-id> --generate` define uma nova.

### Criando um usuário com permissões {#creating-a-user-with-permissions}

Você pode se conectar com o usuário padrão `postgres`. Em produção, recomendamos um usuário de replicação dedicado e somente leitura, exatamente como faria com qualquer outra fonte Postgres. Conecte-se à sua instância com `psql` e execute:

1. Crie um usuário dedicado para o ClickPipes:

   ```sql
   CREATE USER clickpipes_user PASSWORD 'some-password';
   ```

2. Conceda ao usuário acesso somente leitura em nível de schema. O exemplo a seguir mostra as permissões para o schema `public`. Repita esses comandos para cada schema que contenha tabelas que você deseja replicar:

   ```sql
   GRANT USAGE ON SCHEMA "public" TO clickpipes_user;
   GRANT SELECT ON ALL TABLES IN SCHEMA "public" TO clickpipes_user;
   ALTER DEFAULT PRIVILEGES IN SCHEMA "public" GRANT SELECT ON TABLES TO clickpipes_user;
   ```

3. Conceda privilégios de replicação ao usuário:

   ```sql
   ALTER USER clickpipes_user WITH REPLICATION;
   ```

4. Crie uma [publicação](https://www.postgresql.org/docs/current/logical-replication-publication.html) com as tabelas que você deseja replicar. Recomendamos fortemente incluir na publicação apenas as tabelas necessárias, para evitar sobrecarga de desempenho.

<Warning>
  Qualquer tabela incluída na publicação deve ter uma **primary key** definida *ou* ter sua **replica identity** configurada como `FULL`. Consulte as [FAQs do Postgres](/pt-BR/integrations/clickpipes/postgres/faq#how-should-i-scope-my-publications-when-setting-up-replication) para orientações sobre como definir o escopo.
</Warning>

* Para criar uma publicação para tabelas específicas:

  ```sql
  CREATE PUBLICATION clickpipes FOR TABLE table_to_replicate, table_to_replicate2;
  ```

* Para criar uma publicação para todas as tabelas de um schema específico:

  ```sql
  CREATE PUBLICATION clickpipes FOR TABLES IN SCHEMA "public";
  ```

### Replicação lógica {#logical-replication}

A replicação lógica já vem habilitada em toda instância do ClickHouse Managed Postgres. Não há configuração `wal_level` nem parameter group a ser alterado. Você pode confirmar com:

```sql
SHOW wal_level; -- should be logical
```

### Acesso de rede {#network-access}

O ClickHouse Managed Postgres aceita conexões do ClickPipes por padrão. Se você configurou [filtros de IP](/pt-BR/products/managed-postgres/security#ip-whitelisting) no seu serviço Postgres, adicione os [endereços IP estáticos do ClickPipes](/pt-BR/integrations/clickpipes/networking/static-ips) da região do seu **serviço ClickHouse** à lista de permissões. Com o clickhousectl, adicione uma regra por endereço na porta direta do Postgres e execute `clickhousectl cloud postgres get <postgres-id>` para conferir o resultado:

```bash
clickhousectl cloud postgres update <postgres-id> \
  --add-ip-allow '<clickpipes-ip>:5432=clickpipes'
```

### TLS {#tls}

As instâncias do ClickHouse Managed Postgres apresentam um certificado assinado por uma CA exclusiva da instância e sem confiança pública. O ClickPipes ativa a verificação de certificados por padrão, portanto a verificação da conexão falha até que você faça uma das seguintes ações:

* Baixe o pacote de certificados da CA na aba **Settings** do seu serviço Postgres e forneça-o em **Upload CA** nas configurações de conexão do ClickPipe. Esta é a opção recomendada. Consulte [Conexão TLS verificada](/pt-BR/products/managed-postgres/connection#verified-tls) para saber onde encontrar o pacote.
* Ative **Skip certificate verification** nas configurações de conexão do ClickPipe. A conexão permanece criptografada, mas a identidade do servidor não é verificada.

Se você criar o pipe com clickhousectl, baixe o pacote e passe-o com `--ca-certificate`, conforme mostrado na [opção 3](#clickhousectl).

## Opção 3: Criar o pipe com clickhousectl {#clickhousectl}

O [clickhousectl](/pt-BR/concepts/features/interfaces/cli) cria o mesmo pipe pela linha de comando. Primeiro, configure o usuário e a publicação `clickpipes` conforme descrito na [opção 2](#clickpipes-source). Se, em vez disso, você usar o usuário padrão `postgres`, omita `--publication-name` e a CLI criará uma publicação para as tabelas mapeadas. Para criar um pipe, é necessária uma [chave de API](/pt-BR/products/cloud/features/admin-features/api/openapi); o login via OAuth é read-only.

Consulte o hostname e, em seguida, salve o bundle de CA da instância:

```bash
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output pg-ca.pem
```

Crie o pipe no serviço do ClickHouse de destino, passando o bundle de CA com `--ca-certificate`:

```bash
clickhousectl cloud clickpipe create postgres <clickhouse-service-id> \
  --name events-sync \
  --host <postgres-hostname> \
  --pg-database postgres \
  --username clickpipes_user \
  --password '<password>' \
  --ca-certificate pg-ca.pem \
  --publication-name clickpipes \
  --table-mapping public.events:events
```

O pipe cria tabelas `ReplacingMergeTree`. Para ler o estado atual, use `SELECT ... FROM events FINAL WHERE _peerdb_is_deleted = 0`. Para o passo a passo completo, incluindo como aguardar até que o pipe atinja o status `Running` e como verificar os dados, consulte a visualização da CLI no [guia do ClickPipe do Postgres](/pt-BR/integrations/clickpipes/postgres/index).
