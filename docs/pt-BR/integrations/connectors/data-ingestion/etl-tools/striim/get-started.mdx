Use este guia para se cadastrar e começar a replicar dados do seu banco de dados da fonte de dados para a sua instância do ClickHouse. Para ver um exemplo completo, consulte o [pipeline de exemplo do SQL Server](/pt-BR/integrations/connectors/data-ingestion/etl-tools/striim/sample-pipeline).

## Pré-requisitos {#prerequisites}

| **Você precisa de** | **Detalhes**                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ClickHouse          | Um serviço do ClickHouse Cloud em execução ou uma implantação autogerenciada, com acesso de administrador para criar um banco de dados e um usuário. O `CoalescingMergeTree` requer o servidor do ClickHouse 25.6 ou posterior.                                                                                                                                                                                                        |
| Fonte de dados              | Acesso de administrador ao sistema de dados da fonte de dados para configurar o CDC e as permissões de leitor necessárias.                                                                                                                                                                                                                                                                                                                     |
| Caminho de rede     | Um caminho de rede aprovado entre o Striim na AWS e sua fonte de dados, bem como o ClickHouse. Se necessário, o Striim for ClickHouse oferece conectividade privada por meio de restrição de acesso por lista de IPs permitidos, AWS PrivateLink ou tunelamento SSH. Consulte a documentação do Striim sobre [Segurança e Rede](https://www.striim.com/docs/striimforclickhouse/en/security-and-networking-for-striim.html) para mais detalhes |

## Crie sua conta Striim {#create-your-striim-account}

Cadastre-se diretamente na Striim ou pelo AWS Marketplace. Seu período de teste gratuito de 14 dias começa quando você ativa sua conta. Não é necessário cartão de crédito para o teste.

1. Abra o [formulário de cadastro do Striim for ClickHouse](https://go2.striim.com/trial-clickhouse), preencha os dados obrigatórios e selecione **Sign up**.
2. Abra o e-mail de ativação da conta, ative a conta e faça login no console de nuvem da Striim.

Se sua organização faz compras pelo AWS Marketplace, siga as instruções em [Subscribe and sign up](https://www.striim.com/docs/striimforclickhouse/en/subscribe-and-sign-up.html#id211623) e conclua a configuração da conta Striim depois de assinar o Striim for ClickHouse no AWS Marketplace.

## Crie seu serviço {#create-your-service}

Um serviço é um ambiente Striim gerenciado na AWS no qual você cria, executa e monitora pipelines que gravam dados no ClickHouse. Sua conta pode ter apenas um serviço Striim for ClickHouse ativo por vez.

1. No seu primeiro login no Striim for ClickHouse, selecione **Get Started**. Como alternativa, selecione **Marketplace** na barra lateral. Em **Striim for ClickHouse**, selecione **Create**.
2. Configure o seguinte:
   * **Service Name:** um nome que identifique a carga de trabalho ou o ambiente.
   * **AWS Region:** a região em que o serviço é executado. Sempre que possível, selecione a mesma região do seu ClickHouse para reduzir a latência e as cobranças de transferência cross-region. Caso contrário, selecione a região disponível mais próxima.
3. O nome e a região não podem ser alterados após a criação. Para alterar qualquer um deles, é necessário excluir o serviço e criar um novo.
4. Selecione **Create a service**. O provisionamento pode levar vários minutos. Novos serviços usam o plano **Premium** por padrão. Você pode alterar o plano na página **Billing**.
5. Quando o serviço estiver pronto, escolha como iniciá-lo:
   * **Start building with Striim Clara AI:** inicie com o Clara AI gerenciado pela Striim. Não é necessária uma chave de API.
   * **Review your service settings before launch:** configure seu próprio provedor de IA, gerencie usuários ou configure SSH ou AWS PrivateLink antes de iniciar.

Nos logins seguintes, abra o serviço na lista **Services** para criar pipelines ou gerenciar as configurações dele.

## Prepare o destino ClickHouse {#prepare-your-clickhouse-target}

<Steps>
  <Step title="Obtenha os detalhes de conexão" id="get-connection-details">
    No ClickHouse Cloud, selecione o seu serviço, clique em **Conectar** e escolha **HTTPS** para ver o host e a porta (8443). No ClickHouse autogerenciado, solicite o host e a porta ao seu administrador.
  </Step>

  <Step title="Escolha ou crie o banco de dados de destino" id="create-target-database">
    O Striim não cria o banco de dados de destino, e a aplicação é interrompida durante a inicialização caso ele não exista. Use um banco de dados existente ou crie um:

    ```sql
    CREATE DATABASE IF NOT EXISTS <your_database>;
    ```
  </Step>

  <Step title="Crie um usuário dedicado para o Striim" id="create-target-user">
    Use um usuário dedicado em vez do usuário administrativo padrão:

    ```sql
    CREATE USER <user> IDENTIFIED BY '<password>';
    ```

    No ClickHouse autogerenciado, você também pode configurar a autenticação SSL X.509.
  </Step>

  <Step title="Conceda os privilégios necessários" id="grant-target-privileges">
    Conceda ao usuário os seguintes privilégios, conforme indicado na [documentação do Striim](https://www.striim.com/docs/striimforclickhouse/en/initial-setup-to-write-to-clickhouse.html):

    ```sql
    GRANT CREATE TABLE ON <your_database>.* TO <user>;
    GRANT ALTER TABLE ON <your_database>.* TO <user>;
    GRANT DROP TABLE ON <your_database>.* TO <user>;
    GRANT TRUNCATE ON <your_database>.* TO <user>;
    GRANT CREATE DATABASE ON *.* TO <user>;
    GRANT SHOW TABLES ON *.* TO <user>;
    GRANT SHOW DATABASES ON *.* TO <user>;
    GRANT SELECT ON information_schema.* TO <user>;
    GRANT SELECT ON system.tables TO <user>;
    GRANT SELECT ON system.columns TO <user>;
    GRANT SELECT ON system.parts TO <user>;
    GRANT SELECT, INSERT, UPDATE, DELETE ON <your_database>.* TO <user>;
    ```
  </Step>
</Steps>

### Configuração recomendada do ClickHouse {#recommended-clickhouse-configuration}

| Configuração            | **ClickHouse Cloud**                                                        | **Autogerenciado**                                                                                |
| ----------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Porta                   | 8443 (aberta por padrão; gerenciada pelo ClickHouse Cloud)                  | Abra conforme necessário: 8123 (HTTP), 9000 (nativa), 8443 (HTTPS), 9440 (TLS)                    |
| Criptografia            | Sempre TLS                                                                  | Configure o TLS por conta própria e habilite-o no perfil de conexão com a propriedade `EnableSSL` |
| Motor de banco de dados | `Shared`                                                                    | `Atomic` (padrão)                                                                                 |
| Autenticação            | Nome de usuário e senha                                                     | Nome de usuário e senha ou SSL X.509 (TLS mútuo)                                                  |
| Conectividade privada   | AWS PrivateLink (somente nos planos Scale e Enterprise do ClickHouse Cloud) | Túnel SSH ou restrição de acesso por lista de IPs permitidos                                      |

## Criar um perfil de conexão {#create-a-connection-profile}

Crie um perfil de conexão do ClickHouse para que os pipelines possam referenciá-lo pelo nome. No assistente de perfil de conexão, configure o seguinte:

| **Propriedade**                                                     | **Valor**                                                                                                                |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| URL de conexão                                                      | `jdbc:clickhouse://<host>:<port>`, usando o host e a porta da seção anterior (porta 8443 para o ClickHouse Cloud)        |
| Tipo de autenticação                                                | Password (padrão) ou SSL X.509                                                                                           |
| Nome de usuário / Senha                                             | Dados do usuário dedicado do Striim for ClickHouse que você criou na etapa anterior ao preparar o ClickHouse de destino. |
| Certificado SSL do cliente, Chave SSL do cliente, Certificado de CA | Obrigatório apenas para SSL X.509. A chave privada deve estar no formato PKCS#8 PEM.                                     |

Para rotacionar credenciais ou certificados, abra **Connection Profiles**, edite o perfil e salve as alterações.

Para o AWS PrivateLink, mantenha a URL de conexão fornecida pelo ClickHouse Cloud. Configure uma zona hospedada privada no Route 53 para que, a partir do seu serviço Striim, o hostname seja resolvido para o endpoint privado. Consulte [Initial setup to write to ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/initial-setup-to-write-to-clickhouse.html).

## Prepare sua fonte de dados {#prepare-your-source}

Cada tipo de fonte de dados tem sua própria configuração. Localize sua fonte de dados em [Fontes de dados](https://www.striim.com/docs/striimforclickhouse/en/sources.html) na documentação do Striim for ClickHouse e siga o tópico de configuração correspondente. Para fontes de dados compatíveis com CDC (Change Data Capture, captura de dados de alterações), talvez seja necessário habilitar a captura de alterações na fonte de dados e criar um usuário dedicado para o Striim com os privilégios indicados para essa fonte de dados. Antes de continuar, anote o seguinte:

* Host, porta e credenciais do usuário do Striim.
* Os schemas e as tabelas que você deseja replicar. Sempre que possível, selecione tabelas específicas em vez de schemas inteiros.
* A confirmação de que o Striim consegue acessar a fonte de dados a partir da AWS (firewall, VPC, PrivateLink, SSH ou allowlist de IPs).
* Seu plano: o CDC para Oracle, SQL Server, Snowflake e Salesforce exige o plano Premium.

## Criar e iniciar um pipeline {#build-and-start-a-pipeline}

Você pode criar um pipeline usando um dos seguintes métodos:

* **Striim Clara AI:** Selecione **Ask Clara** e descreva o pipeline. Por exemplo: “Build a pipeline from &lt;source&gt; to ClickHouse for &lt;schema.table&gt;.” A Clara solicita a estratégia de leitura e os detalhes de conexão e, em seguida, gera um plano TQL. Revise o plano, selecione **Accept TQL** e, depois, **Deploy and Start this App**. Consulte [Build your first application](https://www.striim.com/docs/striimforclickhouse/en/build-your-first-application.html).
* **Assistente de pipeline automatizado:** Crie duas aplicações vinculadas: uma para a carga inicial e outra para o CDC. O Striim inicia a aplicação de CDC automaticamente assim que a carga inicial é concluída. [Veja o procedimento abaixo](#using-the-automated-pipeline-wizard).
* **Flow Designer:** Crie e edite aplicações visualmente e adicione transformações antes que os dados cheguem ao ClickHouse. Também é possível exportar o TQL de uma aplicação, editá-lo e importar a configuração atualizada.

### Usando o assistente de pipeline automatizado {#using-the-automated-pipeline-wizard}

1. Selecione **Apps &gt; Create an App** e, em seguida, pesquise e selecione sua fonte de dados.
2. Selecione **Get Started** e escolha o pipeline automatizado (carga inicial mais CDC), quando disponível para sua fonte de dados.
3. Insira um nome para o pipeline, selecione um namespace e clique em **Next**.
4. Insira as propriedades da conexão com a fonte de dados. Uma ajuda em linha é exibida ao lado de cada configuração. O Striim valida a conexão; é preciso corrigir eventuais falhas antes de continuar.
5. Selecione os schemas a serem replicados, excluindo os schemas de sistema, e clique em **Next**.
6. Selecione as tabelas de cada schema e clique em **Next**.
7. Selecione seu perfil de conexão do ClickHouse e um **motor de tabela**. Consulte [Como os dados chegam ao ClickHouse](#how-data-lands-in-clickhouse) para entender o comportamento de cada motor.
8. Revise os mapeamentos de tabelas. Edite-os, se necessário, e clique em **Save &amp; Start**.

O Striim executa primeiro a carga inicial. Após a conclusão, o Striim coloca a aplicação de carga inicial em estado de repouso e inicia automaticamente a aplicação de CDC vinculada.

Não execute instruções DDL nas tabelas da fonte de dados durante a carga inicial. Mantenha os logs de alterações ou streams da fonte de dados desde o início da carga inicial até que a aplicação de CDC esteja sincronizada. Se o pipeline for interrompido, analise o erro e as eventuais ações corretivas sugeridas antes de retomá-lo.

## Verifique os dados no ClickHouse {#verify-data-in-clickhouse}

1. Na tela de monitoramento do Striim, confirme que os eventos estão sendo lidos e gravados. Você também pode perguntar à Clara qual é a defasagem atual.

2. No ClickHouse, inspecione a tabela criada pelo Striim:

   ```sql
   SHOW CREATE TABLE <your_database>.<your_table>;
   ```

3. Compare as contagens de linhas com as da fonte de dados. Para tabelas `ReplacingMergeTree`, use a consulta mostrada na próxima seção.

4. Faça uma pequena alteração na fonte de dados (um insert, um update e uma exclusão em uma linha de teste) e confirme que ela aparece no ClickHouse.

## Como os dados chegam ao ClickHouse {#how-data-lands-in-clickhouse}

Selecione **motor de tabela** ao configurar o destino ClickHouse. Por padrão, o componente de escrita do ClickHouse usa **`MergeTree`**. O motor determina como as alterações são aplicadas e se o Striim pode criar a tabela de destino.

| **Motor de tabela**                                 | **Comportamento**                                                                                                                                                             | **Ideal para**                                                                                                                                                     |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ReplacingMergeTree`                                | Atualizações e exclusões são gravadas como novas linhas com uma versão e um sinalizador de exclusão lógica; são desduplicadas por mesclagens em segundo plano ou por `FINAL`. | Fontes de dados CDC que enviam a imagem completa da linha em cada atualização. É o padrão de CDC mais simples e de maior vazão; pode ser reaplicado com segurança. |
| `MergeTree`                                         | Somente acréscimo por padrão. Com Mode = `MERGE`, atualizações e exclusões são aplicadas à tabela (exclusão leve ou por mutação).                                             | Cargas iniciais, logs e eventos, ou CDC quando você quer que as linhas sejam removidas fisicamente, sem colunas extras.                                            |
| `CollapsingMergeTree`                               | Grava uma coluna de sinal: +1 para o estado atual, -1 para cancelar.                                                                                                          | Fontes de dados CDC que enviam as imagens anterior e posterior. Não é seguro reaplicar após uma recuperação.                                                       |
| `CoalescingMergeTree`                               | Atualizações parciais de linha; `NULL` significa &quot;manter inalterado&quot;. Requer servidor 25.6 ou posterior e colunas não chave `Nullable`.                             | Fontes de dados CDC que enviam linhas parciais.                                                                                                                    |
| `SummingMergeTree`                                  | Somente inserção. A aplicação é interrompida ao receber `UPDATE` ou `DELETE`.                                                                                                 | Funções agregadas numéricas somente de acréscimo, como contadores.                                                                                                 |
| `AggregatingMergeTree`, `Replicated`, `Distributed` | Somente gravação de dados. Você deve criar as tabelas de destino antes da implantação.                                                                                        | Tabelas de suporte para visões materializadas; implantações autogerenciadas em cluster e com sharding.                                                             |

Para criação automática de schema e evolução do esquema, use `MergeTree`, `ReplacingMergeTree`, `CollapsingMergeTree`, `CoalescingMergeTree` ou `SummingMergeTree`. Para `ReplacingMergeTree`, o Striim adiciona as colunas `__STRIIM_VERSION` e `__STRIIM_ISDELETED`; para `CollapsingMergeTree`, a coluna `__STRIIM_SIGN`. Consulte as tabelas `ReplacingMergeTree` com `FINAL` e exclua as linhas com exclusão lógica:

```sql
SELECT * FROM <your_database>.<your_table> FINAL WHERE __STRIIM_ISDELETED = 0;
```

Os tipos de dados de origem são mapeados automaticamente para tipos do ClickHouse. Consulte [Tipos de dados suportados](https://www.striim.com/docs/striimforclickhouse/en/clickhouse-writer-programmer-s-reference.html#supported-data-types-787538).

## Monitore seu pipeline {#monitor-your-pipeline}

O Striim publica métricas do componente de escrita do ClickHouse na interface web, incluindo eventos aceitos, eventos confirmados pelo ClickHouse, atualidade do destino, última atividade de escrita, contagens de lotes e tempos de mesclagem por tabela. Os alertas do sistema são habilitados automaticamente, e você pode adicionar alertas personalizados por e-mail, Slack ou Microsoft Teams. Também é possível fazer perguntas à Clara, por exemplo: &quot;Qual é a defasagem atual da minha aplicação?&quot;

## Solução de problemas {#troubleshooting}

<Accordion title="A aplicação é interrompida na inicialização indicando um banco de dados ausente">
  O Striim não cria o banco de dados de destino. Crie-o no ClickHouse e reinicie a aplicação.
</Accordion>

<Accordion title="Tabela ou coluna não encontrada, embora o mesmo schema funcione em outro ambiente">
  Os nomes de colunas sempre diferenciam maiúsculas de minúsculas; já os nomes de bancos de dados e tabelas seguem o sistema de arquivos do servidor (que, em sistemas Linux típicos, diferencia maiúsculas de minúsculas). Use exatamente as maiúsculas e minúsculas definidas no ClickHouse.
</Accordion>

<Accordion title="CollapsingMergeTree mostra duplicatas ou somas negativas após um restart">
  A entrega é at-least-once e esse motor não faz desduplicação. Se você usa recuperação, prefira `ReplacingMergeTree` ou `MergeTree` com Mode = `MERGE`.
</Accordion>

<Accordion title="PrivateLink: Connection timed out">
  Verifique se o grupo de segurança do endpoint de VPC permite tráfego de entrada nas portas 443, 8443, 9440 e 3306 e se as regras de saída permitem a conexão.
</Accordion>

<Accordion title="PrivateLink: Connection reset by peer">
  Adicione o ID do endpoint da AWS à lista de permissões do serviço no ClickHouse Cloud.
</Accordion>

<Accordion title="A aplicação falha com uma exceção desconhecida">
  Peça à Clara que explique o erro e sugira correções. Revise as recomendações antes de fazer alterações em produção.
</Accordion>
