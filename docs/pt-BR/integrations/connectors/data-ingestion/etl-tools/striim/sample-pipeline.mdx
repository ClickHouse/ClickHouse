Os dados operacionais no SQL Server costumam ser a fonte de verdade para pedidos, pagamentos e estoque, mas o SQL Server não foi projetado para consultas analíticas pesadas. Neste passo a passo, você replica uma tabela do SQL Server para o ClickHouse com um pipeline automatizado: o Striim carrega as linhas existentes e, em seguida, transmite cada insert, atualização e exclusão à medida que ocorrem. Depois, você consulta o resultado no ClickHouse.

Consulte [Introducing Automated Pipelines for Effortless Data Replication](https://www.striim.com/blog/automated-pipelines-5-0/) para ver um passo a passo completo.

O CDC (Change Data Capture) do SQL Server requer o plano **Premium** do Striim for ClickHouse.

## O que você vai criar {#what-you-will-build}

SQL Server (`sales.orders`) &gt; carga inicial com o Striim, seguida de CDC &gt; ClickHouse (`sales.orders`, `ReplacingMergeTree`)

## Antes de começar {#before-you-begin}

* Um serviço Striim for ClickHouse em execução no plano Premium (consulte [Primeiros passos](/pt-BR/integrations/connectors/data-ingestion/etl-tools/striim/get-started)).
* Uma instância do SQL Server acessível a partir do Striim, com o SQL Server Agent em execução, e permissão para habilitar o Change Data Capture. As etapas a seguir funcionam tanto no SQL Server em uma VM quanto no Amazon RDS for SQL Server.
* Um serviço do ClickHouse, um banco de dados chamado `sales`, um usuário do Striim com os privilégios necessários e um perfil de conexão com o ClickHouse.

## Etapa 1: Preparar o SQL Server {#step-1-prepare-sql-server}

Crie um banco de dados e uma tabela de exemplo com algumas linhas. Esses dados iniciais servem apenas como ilustração, para que você possa reproduzir o exemplo.

```sql
CREATE DATABASE salesdb;
GO
USE salesdb;
GO
CREATE SCHEMA sales;
GO
CREATE TABLE sales.orders (
  order_id    INT           NOT NULL PRIMARY KEY,
  customer_id INT           NOT NULL,
  status      VARCHAR(20)   NOT NULL,
  total       DECIMAL(10,2) NOT NULL,
  placed_at   DATETIME2     NOT NULL
);
INSERT INTO sales.orders VALUES
  (1, 101, 'NEW',     120.50, SYSDATETIME()),
  (2, 102, 'NEW',      75.00, SYSDATETIME()),
  (3, 103, 'NEW',     310.25, SYSDATETIME());
GO
```

Habilite o Change Data Capture (CDC) no banco de dados e crie um usuário para o Striim. O Striim habilita o CDC em cada tabela selecionada quando a aplicação é iniciada.

<Tabs>
  <Tab title="SQL Server em uma VM" id="enable-cdc-vm">
    ```sql
    USE salesdb;
    EXEC sys.sp_cdc_enable_db;
    ```
  </Tab>

  <Tab title="Amazon RDS for SQL Server" id="enable-cdc-rds">
    ```sql
    EXEC msdb.dbo.rds_cdc_enable_db 'salesdb';
    ```
  </Tab>
</Tabs>

Crie o usuário do Striim em `salesdb`:

```sql
USE salesdb;
CREATE LOGIN striim WITH PASSWORD = '<strong password>';
CREATE USER striim FOR LOGIN striim;
EXEC sp_addrolemember @rolename = db_owner, @membername = striim;
```

O modo de autenticação do SQL Server deve estar habilitado para o usuário do Striim. A documentação do Striim recomenda `db_owner` para o usuário leitor. Depois que o pipeline for iniciado, você pode confirmar que o CDC está ativo com `EXEC sys.sp_cdc_help_change_data_capture`. Consulte [Configuring SQL Server to use MS SQL Reader](https://www.striim.com/docs/striimforclickhouse/en/configuring-sql-server-to-use-ms-sql-reader.html) para ver os pré-requisitos de VMs no Azure e informações sobre grupos de disponibilidade Always On.

## Etapa 2: Crie o pipeline automatizado {#step-2-create-the-automated-pipeline}

1. No Striim, selecione **Apps &gt; Create an App**.
2. Pesquise e selecione **SQL Server** como fonte de dados. Selecione **ClickHouse** como destino.
3. Selecione **Primeiros passos** e escolha o pipeline automatizado (carga inicial mais CDC).
4. Dê um nome ao pipeline, por exemplo `SqlServerToClickHouse`, escolha um namespace e selecione **Next**.
5. Insira os detalhes de conexão do SQL Server: host e porta (`<host>:1433`), nome do banco de dados `salesdb` e o usuário `striim`. Selecione **Next**. O Striim valida a conexão. Se a validação falhar, selecione **Back** e corrija as configurações; é necessário passar na validação para continuar.
6. Selecione os esquemas a serem replicados. Escolha `sales`; não selecione esquemas do sistema.
7. Selecione as tabelas a serem replicadas de cada esquema. Escolha `orders`.
8. Selecione seu perfil de conexão com o ClickHouse e defina **Table Engine** como **`ReplacingMergeTree`**. Esse motor é adequado para fontes de dados de CDC que enviam a imagem completa da linha a cada atualização.
9. Opcionalmente, edite o mapeamento de tabelas. Confirme que `sales.orders` está mapeada para `sales.orders` no ClickHouse.
10. Revise as configurações e selecione **Save &amp; Start**.

![Revise a configuração do pipeline automatizado de SQL Server para ClickHouse](/images/integrations/striim/automated-pipeline-wizard.png)

*Exemplo da tela de revisão do assistente. Para este passo a passo, use `salesdb`, `sales.orders` e `ReplacingMergeTree`, conforme descrito acima.*

O Striim cria duas aplicações vinculadas. Primeiro, executa a carga inicial e a coloca em estado inativo quando todas as linhas tiverem sido copiadas; em seguida, inicia automaticamente a aplicação de CDC e exibe a contagem de eventos à medida que as alterações são transmitidas. Se alguma das fases encontrar um problema, o pipeline é interrompido e exibe as correções recomendadas.

![Monitore a aplicação de Change Data Capture em execução](/images/integrations/striim/pipeline-monitoring.png)

<Warning>
  Não execute DDL nas tabelas da fonte de dados enquanto a carga inicial estiver em andamento e certifique-se de que o SQL Server retenha os dados de alteração (a retenção padrão é de três dias) desde o início da carga inicial até que a aplicação de CDC tenha alcançado o estado atual.
</Warning>

## Etapa 3: Verifique a carga inicial no ClickHouse {#step-3-verify-the-initial-load-in-clickhouse}

O Striim criou a tabela de destino com o motor `ReplacingMergeTree` e duas colunas de metadados. Inspecione-a:

```sql
SHOW CREATE TABLE sales.orders;
```

Com base no mapeamento de tipos de dados do Striim, você deverá ver `order_id` e `customer_id` como `Int32`, `status` como `String`, `total` como `Decimal(10, 2)`, `placed_at` como `DateTime64`, as colunas `__STRIIM_VERSION` (`UInt64`) e `__STRIIM_ISDELETED` (`UInt8`), `ENGINE = ReplacingMergeTree(__STRIIM_VERSION, __STRIIM_ISDELETED)` e `ORDER BY order_id`.

```sql
SELECT order_id, customer_id, status, total
FROM sales.orders FINAL
WHERE __STRIIM_ISDELETED = 0
ORDER BY order_id;
```

Você deverá ver as três linhas carregadas do SQL Server.

## Etapa 4: Transmitir as alterações {#step-4-stream-changes}

Faça alterações no SQL Server:

```sql
USE salesdb;
UPDATE sales.orders SET status = 'SHIPPED' WHERE order_id = 2;
DELETE FROM sales.orders WHERE order_id = 3;
INSERT INTO sales.orders VALUES (4, 104, 'NEW', 42.00, SYSDATETIME());
```

Execute novamente a mesma consulta no ClickHouse. Os pedidos 1, 2 e 4 devem estar presentes, o pedido 2 deve exibir `SHIPPED` e o pedido 3 não deve aparecer. A exclusão é armazenada como uma linha de exclusão lógica (soft delete). A consulta usa `FINAL` para selecionar a versão mais recente e `__STRIIM_ISDELETED = 0` para excluir as linhas removidas. Os marcadores de exclusão são mantidos por padrão; as mesclagens em segundo plano, por si só, não garantem sua remoção física. Consulte [`ReplacingMergeTree`](/pt-BR/reference/engines/table-engines/mergetree-family/replacingmergetree#is_deleted) para entender o comportamento de limpeza. Você também pode acompanhar as contagens de eventos e a atualidade dos dados no destino na visão de monitoramento do Striim ou perguntar à Clara qual é a defasagem atual.

## Crie o mesmo pipeline com o Striim Clara {#build-the-same-pipeline-with-striim-clara}

Em vez de usar o assistente, você pode descrever o pipeline na página Início, por exemplo: &quot;Crie um pipeline do SQL Server para o ClickHouse com carga inicial e Change Data Capture para a tabela sales.orders.&quot; O Clara solicita os detalhes de conexão, gera um plano TQL e só faz a implantação depois que você seleciona **Accept TQL**.

## Limpeza {#clean-up}

* Pare e cancele a implantação dos dois aplicativos do Striim na página Apps.
* O SQL Server continua capturando dados de alteração mesmo depois que você cancela a implantação dos aplicativos do Striim com as configurações padrão do leitor. Para interromper a captura de dados deste exemplo, execute `sys.sp_cdc_disable_table` para `sales.orders`, ou `sys.sp_cdc_disable_db` se nenhuma outra tabela do banco de dados precisar de CDC. Consulte a [documentação](https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sys-sp-cdc-disable-table-transact-sql) do SQL Server para mais detalhes. Como alternativa, siga o [procedimento Auto Disable Table CDC](https://www.striim.com/docs/striimforclickhouse/en/sql-server-operational-considerations.html) do Striim.
* Exclua as tabelas de exemplo com `DROP TABLE sales.orders;` nos dois sistemas.
