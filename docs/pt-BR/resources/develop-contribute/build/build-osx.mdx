<Info>
  **Este guia de compilação é destinado a colaboradores que modificam o próprio ClickHouse.**

  Se você não estiver alterando o código-fonte do ClickHouse, poderá instalar uma versão pré-compilada do ClickHouse conforme descrito em [Quick Start](/pt-BR/get-started/setup/install).
</Info>

O ClickHouse pode ser compilado em macOS x86&#95;64 (Intel) e arm64 (Apple Silicon) no macOS 10.15 (Catalina) ou superior.

Como compilador, há suporte apenas ao Clang do Homebrew.

## Instale os pré-requisitos {#install-prerequisites}

Primeiro, consulte a [documentação geral de pré-requisitos](/pt-BR/resources/develop-contribute/introduction/developer-instruction).

Em seguida, instale o [Homebrew](https://brew.sh/) e execute

Depois, execute:

```bash
brew update
brew install ccache cmake ninja libtool gettext llvm lld binutils grep findutils nasm bash rust rustup
```

<Note>
  Assim como o `llvm`, o `rustup` do Homebrew é keg-only, portanto seu diretório `bin` não é adicionado automaticamente ao `PATH`. Exporte-o da mesma forma que o `PATH` do `llvm` é exportado em [Compilar o ClickHouse](#build-clickhouse):

  ```bash
  export PATH=$(brew --prefix rustup)/bin:$PATH
  ```

  O ClickHouse também fixa a versão da toolchain do Rust usada pelo módulo contrib `corrosion`. Instale-a e selecione-a seguindo a seção [Instalar o compilador Rust](/pt-BR/development/build#install-the-rust-compiler-optional) do guia de compilação para Linux. Caso contrário, o `cmake` falhará no módulo contrib `corrosion` com o erro `Cannot find nightly-<date> Rust toolchain`.
</Note>

<Note>
  A Apple usa, por padrão, um sistema de arquivos que não diferencia maiúsculas de minúsculas. Embora isso normalmente não afete a compilação (especialmente compilações do zero), pode atrapalhar operações com arquivos, como `git mv`.
  Para desenvolvimento sério no macOS, certifique-se de que o código-fonte esteja armazenado em um volume de disco que diferencie maiúsculas de minúsculas; por exemplo, consulte [estas instruções](https://brianboyko.medium.com/a-case-sensitive-src-folder-for-mac-programmers-176cc82a3830).
</Note>

## Compile o ClickHouse {#build-clickhouse}

Para compilar, é necessário usar o compilador Clang do Homebrew:

```bash
cd ClickHouse
mkdir build
export PATH=$(brew --prefix llvm)/bin:$PATH
cmake -S . -B build
cmake --build build
# The resulting binary will be created at: build/programs/clickhouse
```

<Note>
  Um simples `brew install llvm` sempre instala o lançamento mais recente do LLVM disponível no Homebrew, que pode ser mais novo do que a versão do Clang fixada para as compilações de CI e Linux (consulte [Instalar o compilador Clang](/pt-BR/development/build#install-the-clang-compiler)). Um Clang mais novo pode habilitar diagnósticos de `-Weverything` que ainda não são suprimidos na compilação, fazendo-a falhar com `-Werror`. Se isso acontecer, em vez de desabilitar os avisos, instale a versão principal fixada, por exemplo, por meio de uma fórmula versionada (`brew install llvm@<version>`), caso o Homebrew ainda a disponibilize.
</Note>

<Note>
  Se você estiver recebendo erros `ld: archive member '/' not a mach-o file in ...` durante a etapa de vinculação, talvez seja necessário
  usar o llvm-ar definindo a flag `-DCMAKE_AR=/opt/homebrew/opt/llvm/bin/llvm-ar`.
</Note>

## Observações {#caveats}

Se você pretende executar o `clickhouse-server`, aumente a variável `maxfiles` do sistema.

<Note>
  Você precisará usar sudo.
</Note>

Para isso, crie o arquivo `/Library/LaunchDaemons/limit.maxfiles.plist` com o seguinte conteúdo:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
        "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
  <dict>
    <key>Label</key>
    <string>limit.maxfiles</string>
    <key>ProgramArguments</key>
    <array>
      <string>launchctl</string>
      <string>limit</string>
      <string>maxfiles</string>
      <string>524288</string>
      <string>524288</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>ServiceIPC</key>
    <false/>
  </dict>
</plist>
```

Defina as permissões corretas para o arquivo:

```bash
sudo chown root:wheel /Library/LaunchDaemons/limit.maxfiles.plist
```

Verifique se o arquivo está correto:

```bash
plutil /Library/LaunchDaemons/limit.maxfiles.plist
```

Carregue o arquivo (ou reinicie):

```bash
sudo launchctl load -w /Library/LaunchDaemons/limit.maxfiles.plist
```

Para verificar se está funcionando, use os comandos `ulimit -n` ou `launchctl limit maxfiles`.
