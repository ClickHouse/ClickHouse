  ### Lançamento do ClickHouse v23.10.1.1976-stable (13adae0e42f) FIXME em comparação com a v23.9.1.1854-stable (8f9a227de1f)

<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* O armazenamento S3Queue foi totalmente reescrito: a forma de manter informações no ZooKeeper foi alterada, o que reduz o número de solicitações ao ZooKeeper; foi adicionado cache do estado do ZooKeeper nos casos em que sabemos que esse estado não mudará; o processo de polling do S3 foi aprimorado para ser menos agressivo; a forma de manter o TTL e o valor máximo definidos para arquivos rastreados foi alterada, e agora isso é feito por um processo em segundo plano. Foram adicionadas as tabelas `system.s3queue` e `system.s3queue_log`. Fecha [#54998](https://github.com/ClickHouse/ClickHouse/issues/54998). [#54422](https://github.com/ClickHouse/ClickHouse/pull/54422) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Não existe mais a opção de remover automaticamente partes de dados corrompidas. Isso fecha [#55174](https://github.com/ClickHouse/ClickHouse/issues/55174). [#55184](https://github.com/ClickHouse/ClickHouse/pull/55184) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* As partes de dados obsoletas em memória não podem mais ser lidas do write-ahead log. Se você configurou partes em memória anteriormente, elas precisam ser removidas antes da atualização. [#55186](https://github.com/ClickHouse/ClickHouse/pull/55186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Removida a integração com o Meilisearch. Motivo: ela era compatível apenas com a versão antiga 0.18. A versão mais recente do Meilisearch mudou o protocolo e não funciona mais. Observação: gostaríamos muito que você ajudasse a trazê-la de volta. [#55189](https://github.com/ClickHouse/ClickHouse/pull/55189) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* O conceito de monitor de diretório foi renomeado para background INSERT. Todas as configurações `*directory_monitor*` foram renomeadas para `distributed_background_insert*`. **A compatibilidade retroativa deve ser preservada** (já que as configurações antigas foram adicionadas como alias). [#55978](https://github.com/ClickHouse/ClickHouse/pull/55978) ([Azat Khuzhin](https://github.com/azat)).
* Não confunda send&#95;timeout e receive&#95;timeout. [#56035](https://github.com/ClickHouse/ClickHouse/pull/56035) ([Azat Khuzhin](https://github.com/azat)).
* A comparação de intervalos de tempo com unidades diferentes passará a gerar uma exceção. Isso fecha [#55942](https://github.com/ClickHouse/ClickHouse/issues/55942). Você pode ter ocasionalmente dependido do comportamento anterior, em que os valores numéricos subjacentes eram comparados independentemente das unidades. [#56090](https://github.com/ClickHouse/ClickHouse/pull/56090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Novo recurso
</div>

* Adiciona a função &quot;arrayFold(x1, ..., xn, accum -&gt; expression, array1, ..., arrayn, init&#95;accum)&quot;, que aplica uma função lambda a vários arrays com a mesma cardinalidade e acumula o resultado em um acumulador. [#49794](https://github.com/ClickHouse/ClickHouse/pull/49794) ([Lirikl](https://github.com/Lirikl)).
* Adicionada a função de agregação lttb, que usa o algoritmo [Largest-Triangle-Three-Buckets](https://skemman.is/bitstream/1946/15343/3/SS_MSthesis.pdf) para fazer downsampling de dados para visualização. [#53145](https://github.com/ClickHouse/ClickHouse/pull/53145) ([Sinan](https://github.com/sinsinan)).
* A consulta `CHECK TABLE` tem melhor desempenho e usabilidade (envia atualizações de progresso e pode ser cancelada). Há suporte para verificar uma part específica com `CHECK TABLE ... PART 'part_name'`. [#53404](https://github.com/ClickHouse/ClickHouse/pull/53404) ([vdimir](https://github.com/vdimir)).
* Adicionada a função `jsonMergePatch`. Ao trabalhar com dados JSON como strings, ela fornece uma forma de mesclar essas strings (de objetos JSON) em uma única string contendo um único objeto JSON. [#54364](https://github.com/ClickHouse/ClickHouse/pull/54364) ([Memo](https://github.com/Joeywzr)).
* Adicionada uma nova função SQL, &quot;arrayRandomSample(arr, k)&quot;, que retorna uma amostra de k elementos do array de entrada. Antes, uma funcionalidade semelhante só podia ser obtida com uma sintaxe menos conveniente, por exemplo, &quot;SELECT arrayReduce(&#39;groupArraySample(3)&#39;, range(10))&quot;. [#54391](https://github.com/ClickHouse/ClickHouse/pull/54391) ([itayisraelov](https://github.com/itayisraelov)).
* Adicionada a nova função `getHttpHeader` para obter o valor do header da requisição HTTP usado em uma requisição ao servidor ClickHouse. Retorna uma string vazia se a requisição não for feita pelo protocolo HTTP ou se esse header não existir. [#54813](https://github.com/ClickHouse/ClickHouse/pull/54813) ([凌涛](https://github.com/lingtaolf)).
* Introduzidos os combinators de agregação -ArgMin/-ArgMax, que permitem agregar apenas pelos valores mínimos/máximos. Um caso de uso pode ser visto em [#54818](https://github.com/ClickHouse/ClickHouse/issues/54818). Este PR também reorganiza os combinators em uma pasta dedicada. [#54947](https://github.com/ClickHouse/ClickHouse/pull/54947) ([Amos Bird](https://github.com/amosbird)).
* Permite limpar o cache do formato Protobuf com `SYSTEM DROP SCHEMA FORMAT CACHE [FOR Protobuf]`. [#55064](https://github.com/ClickHouse/ClickHouse/pull/55064) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Adiciona autenticador externo HTTP Basic. [#55199](https://github.com/ClickHouse/ClickHouse/pull/55199) ([Aleksei Filatov](https://github.com/aalexfvk)).
* Adicionada a função `byteSwap`, que inverte os bytes de inteiros sem sinal. Isso é particularmente útil para inverter valores de tipos representados internamente como inteiros sem sinal, como IPv4. [#55211](https://github.com/ClickHouse/ClickHouse/pull/55211) ([Priyansh Agrawal](https://github.com/Priyansh121096)).
* Adicionada a função `formatQuery()`, que retorna uma versão formatada (possivelmente com várias linhas) de uma string de consulta SQL. Também foi adicionada a função `formatQuerySingleLine()`, que faz o mesmo, mas a string retornada não conterá quebras de linha. [#55239](https://github.com/ClickHouse/ClickHouse/pull/55239) ([Salvatore Mesoraca](https://github.com/aiven-sal)).
* Adicionado o formato de entrada DWARF, que lê símbolos de depuração de um arquivo executável/biblioteca/arquivo objeto ELF. [#55450](https://github.com/ClickHouse/ClickHouse/pull/55450) ([Michael Kolupaev](https://github.com/al13n321)).
* Permite salvar registros não convertidos e erros nos motores RabbitMQ, NATS e FileLog. Adiciona as colunas virtuais `_error` e `_raw_message` (para NATS e RabbitMQ), e `_raw_record` (para FileLog), que são preenchidas quando o ClickHouse não consegue analisar um novo registro. O comportamento é controlado pelas configurações de armazenamento `nats_handle_error_mode` para NATS, `rabbitmq_handle_error_mode` para RabbitMQ e `handle_error_mode` para FileLog, de forma semelhante a `kafka_handle_error_mode`. Se estiver definido como `default`, uma exceção será lançada quando o ClickHouse não conseguir analisar um registro; se estiver definido como `stream`, o erro e o registro bruto serão salvos nas colunas virtuais. Fecha [#36035](https://github.com/ClickHouse/ClickHouse/issues/36035). [#55477](https://github.com/ClickHouse/ClickHouse/pull/55477) ([Kruglov Pavel](https://github.com/Avogar)).
* Melhoria no cliente Keeper: adiciona o comando get&#95;all&#95;children&#95;number, que retorna o número total de nós filhos sob um path específico. [#55485](https://github.com/ClickHouse/ClickHouse/pull/55485) ([guoxiaolong](https://github.com/guoxiaolongzte)).
* Se uma tabela tiver uma curva de preenchimento espacial em sua chave, por exemplo, `ORDER BY mortonEncode(x, y)`, as condições sobre seus argumentos, por exemplo, `x >= 10 AND x <= 20 AND y >= 20 AND y <= 30`, podem ser usadas para indexação. Foi adicionada a configuração `analyze_index_with_space_filling_curves` para habilitar ou desabilitar essa análise. Isso fecha [#41195](https://github.com/ClickHouse/ClickHouse/issues/41195). Continuação de [#4538](https://github.com/ClickHouse/ClickHouse/issues/4538). Continuação de [#6286](https://github.com/ClickHouse/ClickHouse/issues/6286). Continuação de [#28130](https://github.com/ClickHouse/ClickHouse/issues/28130). Continuação de [#41753](https://github.com/ClickHouse/ClickHouse/issues/41753). [#55642](https://github.com/ClickHouse/ClickHouse/pull/55642) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona a configuração `optimize_trivial_approximate_count_query` para usar a aproximação de `count()` no armazenamento EmbeddedRocksDB. Habilita a contagem trivial para StorageJoin. [#55806](https://github.com/ClickHouse/ClickHouse/pull/55806) ([Duc Canh Le](https://github.com/canhld94)).
* Melhoria no cliente Keeper: adiciona o comando get&#95;direct&#95;children&#95;number, que retorna o número de nós filhos diretos sob um path. [#55898](https://github.com/ClickHouse/ClickHouse/pull/55898) ([xuzifu666](https://github.com/xuzifu666)).
* Adiciona a instrução `SHOW SETTING setting_name`, que é uma versão mais simples da instrução existente `SHOW SETTINGS`. [#55979](https://github.com/ClickHouse/ClickHouse/pull/55979) ([Maksim Kita](https://github.com/kitaisreal)).
* Este PR possibilita passar dados em formato Npy para o ClickHouse. &#96;&#96;&#96; SELECT * FROM file(&#39;example&#95;array.npy&#39;, Npy). [#55982](https://github.com/ClickHouse/ClickHouse/pull/55982) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Este PR implementa uma nova configuração chamada `force_optimize_projection_name`, que recebe o nome da projeção como argumento. Se o valor estiver definido como uma string não vazia, o ClickHouse verifica se essa projeção é usada na consulta pelo menos uma vez. Fecha [#55331](https://github.com/ClickHouse/ClickHouse/issues/55331). [#56134](https://github.com/ClickHouse/ClickHouse/pull/56134) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Adicionada a opção `query_plan_preserve_num_streams_after_window_functions` para preservar o número de streams após a avaliação de funções de janela, permitindo o processamento paralelo de streams. [#50771](https://github.com/ClickHouse/ClickHouse/pull/50771) ([frinkr](https://github.com/frinkr)).
* Libera mais `num_streams` quando os dados são pequenos. [#53867](https://github.com/ClickHouse/ClickHouse/pull/53867) ([Jiebin Sun](https://github.com/jiebinn)).
* Otimização de RoaringBitmaps antes da serialização. [#55044](https://github.com/ClickHouse/ClickHouse/pull/55044) ([UnamedRus](https://github.com/UnamedRus)).
* As posting lists em índices invertidos agora são otimizadas para usar a menor representação possível para bitmaps internos. Dependendo da repetitividade dos dados, isso pode reduzir significativamente o consumo de espaço dos índices invertidos. [#55069](https://github.com/ClickHouse/ClickHouse/pull/55069) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Corrige a contenção no bloqueio de Context, o que melhora significativamente o desempenho de muitas consultas concorrentes de curta duração. [#55121](https://github.com/ClickHouse/ClickHouse/pull/55121) ([Maksim Kita](https://github.com/kitaisreal)).
* Melhoria de 30% no desempenho da criação de índices invertidos. Isso foi alcançado substituindo `std::unordered_map` por `absl::flat_hash_map`. [#55210](https://github.com/ClickHouse/ClickHouse/pull/55210) ([Harry Lee](https://github.com/HarryLeeIBM)).
* Suporte a pushdown de filtro em ORC (no nível de row group). [#55330](https://github.com/ClickHouse/ClickHouse/pull/55330) ([李扬](https://github.com/taiyang-li)).
* Melhora o desempenho da agregação externa com muitos arquivos temporários. [#55489](https://github.com/ClickHouse/ClickHouse/pull/55489) ([Maksim Kita](https://github.com/kitaisreal)).
* Define por padrão um tamanho razoável para o cache de marcas de índices secundários para evitar recarregar as marcas repetidamente. [#55654](https://github.com/ClickHouse/ClickHouse/pull/55654) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Evita a reconstrução desnecessária de grânulos de índice ao ler skip indexes. Isso corrige [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653)#issuecomment-1763766009 . [#55683](https://github.com/ClickHouse/ClickHouse/pull/55683) ([Amos Bird](https://github.com/amosbird)).
* Armazena em cache a função CAST em Set durante a execução para melhorar o desempenho da função `IN` quando o tipo de elemento do Set não corresponde exatamente ao tipo da coluna. [#55712](https://github.com/ClickHouse/ClickHouse/pull/55712) ([Duc Canh Le](https://github.com/canhld94)).
* Melhoria de desempenho para `ColumnVector::insertMany` e `ColumnVector::insertManyFrom`. [#55714](https://github.com/ClickHouse/ClickHouse/pull/55714) ([frinkr](https://github.com/frinkr)).
* ... Obter valores de um map é algo muito usado. Na prática, as estruturas de chave geralmente são as mesmas na mesma coluna map, então podemos tentar prever a posição da chave da próxima linha e reduzir as comparações. [#55929](https://github.com/ClickHouse/ClickHouse/pull/55929) ([lgbo](https://github.com/lgbo-ustc)).
* ... Corrige um problema em que a poda de campos de struct não funciona em alguns casos. Por exemplo &#96;&#96;&#96;sql INSERT INTO FUNCTION file(&#39;test&#95;parquet&#95;struct&#39;, Parquet, &#39;x Tuple(a UInt32, b UInt32, c String)&#39;) SELECT tuple(number, rand(), concat(&#39;testxxxxxxx&#39; toString(number))) FROM numbers(10);. [#56117](https://github.com/ClickHouse/ClickHouse/pull/56117) ([lgbo](https://github.com/lgbo-ustc)).
