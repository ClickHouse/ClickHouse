<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Adiciona suporte a comentários multilinha aninhados `/* comment /* comment */ */` em SQL. Isso está em conformidade com o padrão SQL. [#14655](https://github.com/ClickHouse/ClickHouse/pull/14655) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Altera o valor padrão da configuração `format_regexp_escaping_rule` (relacionada ao formato `Regexp`) para `Raw` (isso significa ler o subpadrão inteiro como um valor), para tornar o comportamento mais próximo do que os usuários esperam. [#15426](https://github.com/ClickHouse/ClickHouse/pull/15426) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Torna `multiple_joins_rewriter_version` obsoleto. Remove a primeira versão do reescritor de junções. [#15472](https://github.com/ClickHouse/ClickHouse/pull/15472) ([Artem Zuikov](https://github.com/4ertus2)).

O limite é aplicado apenas a leituras locais, **excluindo** o estágio final de merge no nó raiz. * Adiciona novo recurso: SHOW DATABASES LIKE &#39;xxx&#39;. [#14521](https://github.com/ClickHouse/ClickHouse/pull/14521) ([hexiaoting](https://github.com/hexiaoting)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Habilita partes compactas por padrão para partes pequenas. Isso permitirá processar inserções frequentes com um pouco mais de eficiência (4..100 vezes). [#11913](https://github.com/ClickHouse/ClickHouse/pull/11913) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhora o desempenho de valores de 256 bits usando `(u)int64_t` como tipo básico para inteiros de largura estendida. Os inteiros de largura estendida originais usam tipos de 8 bits como base. [#14859](https://github.com/ClickHouse/ClickHouse/pull/14859) ([Artem Zuikov](https://github.com/4ertus2)).
* Faz `mlock` apenas no segmento de código ao iniciar o clickhouse-server. Em versões anteriores, todas as regiões mapeadas eram bloqueadas na memória, incluindo informações de depuração. As informações de depuração geralmente são divididas em um arquivo separado, mas, quando isso não acontecia, o uso de memória aumentava em +2..3 GiB. [#14929](https://github.com/ClickHouse/ClickHouse/pull/14929) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Costumávamos escolher o método fixed key para agrupar por uma única `FixedString`. Isso é desnecessário, já que temos `StringHashTable`, que faz uma otimização `packedFix` semelhante para colunas `FixedString`. E devemos usar `low_cardinality_key_fixed_string` sempre que possível. [#15034](https://github.com/ClickHouse/ClickHouse/pull/15034) ([Amos Bird](https://github.com/amosbird)).
* Corrige `DateTime <op> DateTime`, que estava escolhendo por engano a implementação genérica lenta. Isso corrige [#15153](https://github.com/ClickHouse/ClickHouse/issues/15153). [#15178](https://github.com/ClickHouse/ClickHouse/pull/15178) ([Amos Bird](https://github.com/amosbird)).
* Usa uma única requisição `DeleteObjects` ao S3 em vez de várias `DeleteObject` em loop. Não há nenhuma alteração de funcionalidade, portanto isso é coberto por testes existentes, como `integration/test_log_family_s3`. [#15238](https://github.com/ClickHouse/ClickHouse/pull/15238) ([ianton-ru](https://github.com/ianton-ru)).
* Multiplicação de 256 bits mais rápida. [#15418](https://github.com/ClickHouse/ClickHouse/pull/15418) ([Artem Zuikov](https://github.com/4ertus2)).
* Melhora o desempenho de `quantileTDigest`. Isso corrige [#2668](https://github.com/ClickHouse/ClickHouse/issues/2668). [#15542](https://github.com/ClickHouse/ClickHouse/pull/15542) ([Kruglov Pavel](https://github.com/Avogar)).
* Usa explicitamente um disco temporário para armazenar dados temporários de mesclagem vertical. [#15639](https://github.com/ClickHouse/ClickHouse/pull/15639) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
