<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Passa a permitir escrever `SETTINGS` antes de `FORMAT` em uma cadeia de consultas com `UNION` quando as subconsultas estão entre parênteses. Isso corrige [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712). Também altera o comportamento quando uma consulta tem a cláusula SETTINGS especificada duas vezes em sequência. A cláusula SETTINGS mais próxima terá preferência para a subconsulta correspondente. Nas versões anteriores, a cláusula SETTINGS mais externa podia ter preferência sobre a cláusula interna. [#68614](https://github.com/ClickHouse/ClickHouse/pull/68614) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* A reordenação das condições de filtro da cláusula `[PRE]WHERE` agora é permitida por padrão. Isso pode ser desativado definindo `allow_reorder_prewhere_conditions` como `false`. [#70657](https://github.com/ClickHouse/ClickHouse/pull/70657) ([Nikita Taranov](https://github.com/nickitat)).
* Corrige a otimização `optimize_functions_to_subcolumns` (anteriormente, ela podia levar ao erro `Invalid column type for ColumnUnique::insertRangeFrom. Expected String, got LowCardinality(String)`), preservando o tipo `LowCardinality` em `mapKeys`/`mapValues`. [#70716](https://github.com/ClickHouse/ClickHouse/pull/70716) ([Azat Khuzhin](https://github.com/azat)).
* Remove a biblioteca `idxd-config`, que tem uma licença incompatível. Isso também remove o codec experimental Intel DeflateQPL. [#70987](https://github.com/ClickHouse/ClickHouse/pull/70987) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Novo recurso
</div>

* Integração com MongoDB refatorada: migração para o novo driver mongocxx a partir do Poco::MongoDB obsoleto, remoção do suporte ao protocolo antigo obsoleto, suporte a conexão por URI, suporte a todos os tipos do MongoDB, suporte a instruções WHERE e ORDER BY no lado do MongoDB, restrição para expressões não suportadas pelo MongoDB. [#63279](https://github.com/ClickHouse/ClickHouse/pull/63279) ([Kirill Nikiforov](https://github.com/allmazz)).
* Uma nova opção `--progress-table` no clickhouse-client imprime uma tabela com métricas que mudam durante a execução da consulta; a nova opção `--enable-progress-table-toggle` está associada à opção `--progress-table` e alterna a exibição da tabela de progresso ao pressionar a tecla de controle (Space). [#63689](https://github.com/ClickHouse/ClickHouse/pull/63689) ([Maria Khristenko](https://github.com/mariaKhr)).
* Isso permite conceder acesso a prefixos curinga. `GRANT SELECT ON db.table_pefix_* TO user`. [#65311](https://github.com/ClickHouse/ClickHouse/pull/65311) ([pufit](https://github.com/pufit)).
* Adiciona system.query&#95;metric&#95;log, que contém o histórico de memória e de valores de métricas da tabela system.events para consultas individuais, gravados periodicamente em disco. [#66532](https://github.com/ClickHouse/ClickHouse/pull/66532) ([Pablo Marcos](https://github.com/pamarcos)).
* Uma consulta SELECT simples pode ser escrita com SELECT implícito para habilitar expressões no estilo calculadora, por exemplo, `ch "1 + 2"`. Isso é controlado por uma nova configuração, `implicit_select`. [#68502](https://github.com/ClickHouse/ClickHouse/pull/68502) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Suporte ao modo `--copy` para clickhouse local como atalho para conversão de formato [#68503](https://github.com/ClickHouse/ClickHouse/issues/68503). [#68583](https://github.com/ClickHouse/ClickHouse/pull/68583) ([Denis Hananein](https://github.com/denis-hananein)).
* Adiciona suporte para a função `arrayUnion`. [#68989](https://github.com/ClickHouse/ClickHouse/pull/68989) ([Peter Nguyen](https://github.com/petern48)).
* Suporte para a função agregada `quantileExactWeightedInterpolated`, que é uma versão interpolada baseada em `quantileExactWeighted`. Algumas pessoas podem se perguntar por que precisamos de uma nova `quantileExactWeightedInterpolated`, já que já temos `quantileExactInterpolatedWeighted`. O motivo é que a nova é mais precisa do que a antiga. Além disso, ela serve para compatibilidade com Spark no Apache Gluten. [#69619](https://github.com/ClickHouse/ClickHouse/pull/69619) ([李扬](https://github.com/taiyang-li)).
* Suporte para a função `arrayElementOrNull`. Ela retorna NULL se o índice do array estiver fora do intervalo ou se a chave do mapa não for encontrada. [#69646](https://github.com/ClickHouse/ClickHouse/pull/69646) ([李扬](https://github.com/taiyang-li)).
* Permite que os usuários especifiquem expressões regulares por meio dos novos campos `message_regexp` e `message_regexp_negative` no arquivo `config.xml` para filtrar o logging. O logging é aplicado ao texto formatado sem cores para proporcionar a experiência mais intuitiva aos desenvolvedores. [#69657](https://github.com/ClickHouse/ClickHouse/pull/69657) ([Peter Nguyen](https://github.com/petern48)).
* Suporte ao tipo Dynamic na maioria das funções, executando-as sobre tipos internos dentro de Dynamic. [#69691](https://github.com/ClickHouse/ClickHouse/pull/69691) ([Pavel Kruglov](https://github.com/Avogar)).
* A função `RIPEMD160` foi readicionada e calcula o hash criptográfico RIPEMD-160 de uma string. Exemplo: `SELECT HEX(RIPEMD160('The quick brown fox jumps over the lazy dog'))` retorna `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`. [#70087](https://github.com/ClickHouse/ClickHouse/pull/70087) ([Dergousov Maxim](https://github.com/m7kss1)).
* Permite armazenar em cache arquivos lidos para motores de tabela de armazenamento de objetos e lagos de dados usando o hash de ETag + caminho do arquivo como chave de cache. [#70135](https://github.com/ClickHouse/ClickHouse/pull/70135) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Suporta a leitura de tabelas Iceberg no HDFS. [#70268](https://github.com/ClickHouse/ClickHouse/pull/70268) ([flynn](https://github.com/ucasfl)).
* Permite ler/gravar o tipo JSON como binary string no formato RowBinary com as configurações `input_format_binary_read_json_as_string/output_format_binary_write_json_as_string`. [#70288](https://github.com/ClickHouse/ClickHouse/pull/70288) ([Pavel Kruglov](https://github.com/Avogar)).
* Permite serializar/desserializar a coluna JSON como uma única coluna String no formato Native. Para saída, use a configuração `output_format_native_write_json_as_string`. Para entrada, use a versão de serialização `1` antes dos dados da coluna. [#70312](https://github.com/ClickHouse/ClickHouse/pull/70312) ([Pavel Kruglov](https://github.com/Avogar)).
* Suporta CTE padrão, `with insert`, enquanto antes suportava apenas `insert ... with ...`. [#70593](https://github.com/ClickHouse/ClickHouse/pull/70593) ([Shichao Jin](https://github.com/jsc0218)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Suporte a índice minmax para `pointInPolygon`. [#62085](https://github.com/ClickHouse/ClickHouse/pull/62085) ([JackyWoo](https://github.com/JackyWoo)).
* Adiciona suporte a filtros de Bloom no Parquet. [#62966](https://github.com/ClickHouse/ClickHouse/pull/62966) ([Arthur Passos](https://github.com/arthurpassos)).
* Renomeação sem bloqueio de partes para evitar que INSERT afete SELECT (devido ao bloqueio de partes) (em circunstâncias normais, com `fsync_part_directory`, o QPS de SELECT com INSERT em paralelo aumentou 2x; sob carga pesada, o efeito é ainda maior). Observe que, por enquanto, isso inclui apenas `ReplicatedMergeTree`. [#64955](https://github.com/ClickHouse/ClickHouse/pull/64955) ([Azat Khuzhin](https://github.com/azat)).
* Respeita `ttl_only_drop_parts` em `materialize ttl`; lê apenas as colunas necessárias para recalcular o TTL e remover partes substituindo-as por uma vazia. [#65488](https://github.com/ClickHouse/ClickHouse/pull/65488) ([Andrey Zvonov](https://github.com/zvonand)).
* Refatora `IDisk` e `IObjectStorage` para melhorar o desempenho. Tabelas em armazenamentos de objetos `plain` e `plain_rewritable` serão inicializadas mais rapidamente. [#68146](https://github.com/ClickHouse/ClickHouse/pull/68146) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Otimiza a criação de threads no ThreadPool para minimizar a contenção de bloqueios. A criação de threads agora é realizada fora da seção crítica para evitar atrasos no agendamento de tarefas e no gerenciamento de threads sob alta carga. Isso torna o ClickHouse muito mais responsivo sob carga concorrente intensa. [#68694](https://github.com/ClickHouse/ClickHouse/pull/68694) ([filimonov](https://github.com/filimonov)).
* Habilita a leitura de colunas String LowCardinality em ORC. [#69481](https://github.com/ClickHouse/ClickHouse/pull/69481) ([李扬](https://github.com/taiyang-li)).
* Adiciona a capacidade de fazer parse de dados diretamente em colunas esparsas. [#69828](https://github.com/ClickHouse/ClickHouse/pull/69828) ([Anton Popov](https://github.com/CurtizJ)).
* Suporta leitura em paralelo de row groups do Parquet e prefetching de row groups no modo de thread única. [#69862](https://github.com/ClickHouse/ClickHouse/pull/69862) ([LiuNeng](https://github.com/liuneng1994)).
* Melhora o desempenho do parsing de formats com alto número de valores ausentes (por exemplo, `JSONEachRow`). [#69875](https://github.com/ClickHouse/ClickHouse/pull/69875) ([Anton Popov](https://github.com/CurtizJ)).
* Usa `LowCardinality` para `ProfileEvents` em logs do sistema, como `part_log`, `query_views_log` e `filesystem_cache_log`. [#70152](https://github.com/ClickHouse/ClickHouse/pull/70152) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhora o desempenho das funções FromUnixTimestamp/ToUnixTimestamp. [#71042](https://github.com/ClickHouse/ClickHouse/pull/71042) ([kevinyhzou](https://github.com/KevinyhZou)).

<div id="improvement">
  #### Melhoria
</div>

* Permitir aliases SQL parametrizados. [#50665](https://github.com/ClickHouse/ClickHouse/pull/50665) ([Anton Kozlov](https://github.com/tonickkozlov)).
* Corrigido [#57616](https://github.com/ClickHouse/ClickHouse/issues/57616): esse problema ocorre porque todos os argumentos numéricos positivos são identificados automaticamente como do tipo `uint64`, o que impede a correspondência com dados do tipo `int` em `summapfiltered`. Essa falta de correspondência é de fato confusa, já que os parâmetros `uint64` não são especificados pelo usuário. Além disso, se os argumentos forem `[1,2,3,toint8(-3)]`, devido a `getleastsupertype()`, esses parâmetros serão tratados uniformemente como do tipo `int`, fazendo com que `'1,2,3'` também não corresponda a dados do tipo `uint` em `summapfiltered`. [#58408](https://github.com/ClickHouse/ClickHouse/pull/58408) ([Chen768959](https://github.com/Chen768959)).
* `ALTER TABLE .. REPLACE PARTITION` não espera mais por mutações/mesclagens que ocorram em outras partições. [#59138](https://github.com/ClickHouse/ClickHouse/pull/59138) ([Vasily Nemkov](https://github.com/Enmk)).
* Views materializadas atualizáveis agora têm suporte em bancos de dados Replicated. [#60669](https://github.com/ClickHouse/ClickHouse/pull/60669) ([Michael Kolupaev](https://github.com/al13n321)).
* Links simbólicos para tabelas no diretório `data/database_name/` agora são criados para os caminhos reais dos dados da tabela, de acordo com a política de armazenamento, em vez do diretório `store/...` no disco padrão. [#61777](https://github.com/ClickHouse/ClickHouse/pull/61777) ([Kirill](https://github.com/kirillgarbar)).

* Foram reformuladas as configurações que controlam o comportamento dos algoritmos de réplicas paralelas. Resumindo: o ClickHouse tem quatro algoritmos diferentes para leitura paralela envolvendo múltiplas réplicas, o que se reflete na configuração `parallel_replicas_mode`; o valor padrão dela é `read_tasks`. Além disso, foi adicionada a configuração de alternância `enable_parallel_replicas`. [#63151](https://github.com/ClickHouse/ClickHouse/pull/63151) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

Isso fecha [#65119](https://github.com/ClickHouse/ClickHouse/issues/65119). [#66801](https://github.com/ClickHouse/ClickHouse/pull/66801) ([scanhex12](https://github.com/scanhex12)).

Esse recurso é compatível apenas com tabelas da família `MergeTree`. Fecha [#65015](https://github.com/ClickHouse/ClickHouse/issues/65015). [#69091](https://github.com/ClickHouse/ClickHouse/pull/69091) ([tuanpach](https://github.com/tuanpach)).

* `isort` é um organizador simples de importações em Python, para atender aos requisitos da [pep-8](https://peps.python.org/pep-0008/#imports). Isso permitirá reduzir conflitos durante a sincronização e padronizar o código. O bloco de importação é dividido nos sub-blocos: `standard library` -&gt; `third-party libraries` -&gt; `local imports` -&gt; `.local imports`. Cada sub-bloco é ordenado alfabeticamente, com os sub-sub-blocos `import X` -&gt; `from X import Y`. [#70038](https://github.com/ClickHouse/ClickHouse/pull/70038) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
