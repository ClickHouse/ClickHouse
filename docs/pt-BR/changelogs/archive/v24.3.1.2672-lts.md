<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Não permitir que `max&#95;parallel&#95;replicas` seja definido como 0, pois isso não faz sentido. Defini-lo como 0 pode levar a erros lógicos inesperados. Fecha [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140). [#60430](https://github.com/ClickHouse/ClickHouse/pull/60430) ([Kruglov Pavel](https://github.com/Avogar)).
* Alterado o nome da coluna de `duration_ms` para `duration_microseconds` na tabela `system.zookeeper` para refletir o fato de que a duração está em resolução de microssegundos. [#60774](https://github.com/ClickHouse/ClickHouse/pull/60774) ([Duc Canh Le](https://github.com/canhld94)).
* Rejeitar consultas INSERT recebidas quando as configurações de nível de consulta `async_insert` e `deduplicate_blocks_in_dependent_materialized_views` estiverem habilitadas ao mesmo tempo. Esse comportamento é controlado pela configuração `throw_if_deduplication_in_dependent_materialized_views_enabled_with_async_insert` e vem habilitado por padrão. Esta é uma continuação de [https://github.com/ClickHouse/ClickHouse/pull/59699](https://github.com/ClickHouse/ClickHouse/pull/59699), necessária para desbloquear [https://github.com/ClickHouse/ClickHouse/pull/59915](https://github.com/ClickHouse/ClickHouse/pull/59915). [#60888](https://github.com/ClickHouse/ClickHouse/pull/60888) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* O utilitário `clickhouse-copier` foi movido para um repositório separado no GitHub: [https://github.com/ClickHouse/copier](https://github.com/ClickHouse/copier). Ele não está mais incluído no pacote, mas continua disponível para download separadamente. Isto fecha: [#60734](https://github.com/ClickHouse/ClickHouse/issues/60734) Isto fecha: [#60540](https://github.com/ClickHouse/ClickHouse/issues/60540) Isto fecha: [#60250](https://github.com/ClickHouse/ClickHouse/issues/60250) Isto fecha: [#52917](https://github.com/ClickHouse/ClickHouse/issues/52917) Isto fecha: [#51140](https://github.com/ClickHouse/ClickHouse/issues/51140) Isto fecha: [#47517](https://github.com/ClickHouse/ClickHouse/issues/47517) Isto fecha: [#47189](https://github.com/ClickHouse/ClickHouse/issues/47189) Isto fecha: [#46598](https://github.com/ClickHouse/ClickHouse/issues/46598) Isto fecha: [#40257](https://github.com/ClickHouse/ClickHouse/issues/40257) Isto fecha: [#36504](https://github.com/ClickHouse/ClickHouse/issues/36504) Isto fecha: [#35485](https://github.com/ClickHouse/ClickHouse/issues/35485) Isto fecha: [#33702](https://github.com/ClickHouse/ClickHouse/issues/33702) Isto fecha: [#26702](https://github.com/ClickHouse/ClickHouse/issues/26702) ### Entrada de documentação para alterações voltadas ao usuário. [#61058](https://github.com/ClickHouse/ClickHouse/pull/61058) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Para aumentar a compatibilidade com o MySQL, a função `locate` agora aceita, por padrão, os argumentos `(needle, haystack[, start_pos])`. O comportamento anterior `(haystack, needle, [, start_pos])` pode ser restaurado definindo `function_locate_has_mysql_compatible_argument_order = 0`. [#61092](https://github.com/ClickHouse/ClickHouse/pull/61092) ([Robert Schulze](https://github.com/rschu1ze)).
* As partes de dados em memória obsoletas foram descontinuadas desde a versão 23.5 e deixaram de ser suportadas desde a versão 23.10. Agora, o código restante foi removido. Continuação de [#55186](https://github.com/ClickHouse/ClickHouse/issues/55186) e [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409). É improvável que você tenha usado partes de dados em memória, porque elas estavam disponíveis apenas antes da versão 23.5 e somente quando eram habilitadas manualmente pela especificação dos SETTINGS correspondentes para uma tabela MergeTree. Para verificar se você tem partes de dados em memória, execute a seguinte consulta: `SELECT part_type, count() FROM system.parts GROUP BY part_type ORDER BY part_type`. Para desativar o uso de partes de dados em memória, execute `ALTER TABLE ... MODIFY SETTING min_bytes_for_compact_part = DEFAULT, min_rows_for_compact_part = DEFAULT`. Antes de atualizar a partir de lançamentos antigos do ClickHouse, primeiro verifique se você não tem partes de dados em memória. Se houver partes de dados em memória, primeiro desative-as, depois aguarde até não haver mais partes de dados em memória e prossiga com a atualização. [#61127](https://github.com/ClickHouse/ClickHouse/pull/61127) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Proibir `SimpleAggregateFunction` em `ORDER BY` de tabelas `MergeTree` por padrão (assim como `AggregateFunction`, elas são proibidas porque não são comparáveis; use `allow_suspicious_primary_key` para permiti-las). [#61399](https://github.com/ClickHouse/ClickHouse/pull/61399) ([Azat Khuzhin](https://github.com/azat)).
* O ClickHouse permite dados binários arbitrários no tipo de dados String, que normalmente é UTF-8. Strings de Parquet/ORC/Arrow suportam apenas UTF-8. Por isso, você pode escolher qual tipo de dados do Arrow usar para o tipo de dados String do ClickHouse: String ou Binary. Isso é controlado pelas configurações `output_format_parquet_string_as_string`, `output_format_orc_string_as_string`, `output_format_arrow_string_as_string`. Embora Binary seja mais correto e compatível, usar String por padrão corresponderá às expectativas dos usuários na maioria dos casos. Parquet/ORC/Arrow suporta muitos métodos de compressão, incluindo lz4 e zstd. O ClickHouse oferece suporte a todos os métodos de compressão. Algumas ferramentas inferiores não oferecem suporte ao método de compressão `lz4`, que é mais rápido, por isso definimos `zstd` como padrão. Isso é controlado pelas configurações `output_format_parquet_compression_method`, `output_format_orc_compression_method` e `output_format_arrow_compression_method`. Alteramos o padrão para `zstd` em Parquet e ORC, mas não em Arrow (que é voltado a usos de baixo nível). [#61817](https://github.com/ClickHouse/ClickHouse/pull/61817) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Na nova versão do ClickHouse, as funções `geoDistance`, `greatCircleDistance` e `greatCircleAngle` usarão o tipo de dados de ponto flutuante de dupla precisão de 64 bits nos cálculos internos e no tipo de retorno se todos os argumentos forem Float64. Isso encerra [#58476](https://github.com/ClickHouse/ClickHouse/issues/58476). Em versões anteriores, a função sempre usava Float32. Você pode voltar ao comportamento antigo definindo `geo_distance_returns_float64_on_float64_arguments` como `false` ou `compatibility` como `24.2` ou anterior. [#61848](https://github.com/ClickHouse/ClickHouse/pull/61848) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Melhora o desempenho do método de agregação serializada ao envolver várias colunas [Nullable]. Esta é uma versão geral de [#51399](https://github.com/ClickHouse/ClickHouse/issues/51399) que não compromete a integridade da abstração. [#55809](https://github.com/ClickHouse/ClickHouse/pull/55809) ([Amos Bird](https://github.com/amosbird)).
* Construção lazy da saída do join para melhorar o desempenho de joins ALL. [#58278](https://github.com/ClickHouse/ClickHouse/pull/58278) ([LiuNeng](https://github.com/liuneng1994)).
* Melhorias nas funções de agregação ArgMin / ArgMax / any / anyLast / anyHeavy, bem como em consultas `ORDER BY {u8/u16/u32/u64/i8/i16/u32/i64) LIMIT 1`. [#58640](https://github.com/ClickHouse/ClickHouse/pull/58640) ([Raúl Marín](https://github.com/Algunenano)).
* Otimização trivial no filtro de colunas. Evita filtrar com `result_size_hint = -1` colunas de filtro cujo tipo subjacente não é numérico. O pico de memória pode ser reduzido para 44% do original em alguns casos. [#59698](https://github.com/ClickHouse/ClickHouse/pull/59698) ([李扬](https://github.com/taiyang-li)).
* Se a chave primária da tabela contiver principalmente colunas inúteis, não as mantenha em memória. Isso é controlado por uma nova configuração `primary_key_ratio_of_unique_prefix_values_to_skip_suffix_columns`, com valor padrão `0.9`, o que significa que, para uma chave primária composta, se uma coluna mudar de valor em pelo menos 90% das vezes, as colunas seguintes não serão carregadas. [#60255](https://github.com/ClickHouse/ClickHouse/pull/60255) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Executa a função multiIf de forma colunar quando o tipo subjacente de result&#95;type é numérico. [#60384](https://github.com/ClickHouse/ClickHouse/pull/60384) ([李扬](https://github.com/taiyang-li)).
* Mutexes mais rápidos (quase 2x) (estavam mais lentos por causa do ThreadFuzzer). [#60823](https://github.com/ClickHouse/ClickHouse/pull/60823) ([Azat Khuzhin](https://github.com/azat)).
* Move o esvaziamento de conexões de prepare para work e esvazia várias conexões em paralelo. [#60845](https://github.com/ClickHouse/ClickHouse/pull/60845) ([lizhuoyu5](https://github.com/lzydmxy)).
* Otimiza o insertManyFrom de números Nullable ou strings Nullable. [#60846](https://github.com/ClickHouse/ClickHouse/pull/60846) ([李扬](https://github.com/taiyang-li)).
* Função `dotProduct` otimizada para eliminar cópias de memória desnecessárias e custosas. [#60928](https://github.com/ClickHouse/ClickHouse/pull/60928) ([Robert Schulze](https://github.com/rschu1ze)).
* As operações com o cache do sistema de arquivos sofrerão menos com a contenção de locks. [#61066](https://github.com/ClickHouse/ClickHouse/pull/61066) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Otimiza ColumnString::replicate e evita que memcpySmallAllowReadWriteOverflow15Impl seja otimizado para a memcpy embutida. Fecha [#61074](https://github.com/ClickHouse/ClickHouse/issues/61074). ColumnString::replicate fica 2,46x mais rápido em x86-64. [#61075](https://github.com/ClickHouse/ClickHouse/pull/61075) ([李扬](https://github.com/taiyang-li)).
* Impressão 30x mais rápida para inteiros de 256 bits. [#61100](https://github.com/ClickHouse/ClickHouse/pull/61100) ([Raúl Marín](https://github.com/Algunenano)).
* Se uma consulta com erro de sintaxe continha um matcher `COLUMNS` com uma expressão regular, a expressão regular era compilada todas as vezes durante o retrocesso do parser, em vez de ser compilada apenas uma vez. Isso era um erro conceitual grave. A regexp compilada era colocada na AST. Mas a letra A em AST significa &quot;abstract&quot;, ou seja, ela não deve conter objetos pesados. Partes da AST podem ser criadas e descartadas durante o parsing, inclusive com uma grande quantidade de retrocessos. Isso causa lentidão no parsing e, consequentemente, permite DoS por um usuário readonly. Mas o principal problema é que isso impede o avanço dos fuzzers. [#61543](https://github.com/ClickHouse/ClickHouse/pull/61543) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona uma nova etapa no analisador para otimizar casos de valor único. [#61564](https://github.com/ClickHouse/ClickHouse/pull/61564) ([LiuNeng](https://github.com/liuneng1994)).
