<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* O cache agora é componível, permitindo não remover determinados arquivos (como idx, mrk, ..), e a versão antiga do cache foi removida. Agora é possível configurar o cache sobre um disco do Azure blob storage, um disco Local, um disco StaticWeb etc. Este PR está marcado como incompatível com versões anteriores porque a configuração do cache foi alterada e, para que ele funcione, é necessário atualizar o arquivo de configuração. O cache antigo ainda será usado com a nova configuração. O servidor iniciará normalmente com a configuração antiga do cache. Fecha [#36140](https://github.com/ClickHouse/ClickHouse/issues/36140). Fecha [#37889](https://github.com/ClickHouse/ClickHouse/issues/37889). [#36171](https://github.com/ClickHouse/ClickHouse/pull/36171) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Agora, todas as fontes de dicionário relevantes respeitam a configuração `remote_url_allow_hosts`. Isso já havia sido feito para HTTP, Cassandra e Redis. Foram adicionados ClickHouse, MongoDB, MySQL e PostgreSQL. O host é verificado apenas para dicionários criados a partir de DDL. [#39184](https://github.com/ClickHouse/ClickHouse/pull/39184) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* O intervalo de Date32 e DateTime64 foi ampliado para oferecer suporte a datas de 1900 a 2299. Em versões anteriores, o intervalo compatível ia apenas de 1925 a 2283. A implementação usa o calendário gregoriano proléptico (em conformidade com a [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601):2004 (cláusula 3.2.1 The Gregorian calendar)) em vez de considerar as transições históricas do calendário juliano para o gregoriano. Essa alteração afeta o comportamento específico da implementação para argumentos fora do intervalo. Por exemplo, se em versões anteriores o valor `1899-01-01` era limitado para `1925-01-01`, na nova versão ele será limitado para `1900-01-01`. Isso altera o comportamento do arredondamento com `toStartOfInterval` se você passar `INTERVAL 3 QUARTER` até um trimestre, porque os intervalos são contados a partir de um ponto no tempo específico da implementação. Fecha [#28216](https://github.com/ClickHouse/ClickHouse/issues/28216), melhora [#38393](https://github.com/ClickHouse/ClickHouse/issues/38393). [#39425](https://github.com/ClickHouse/ClickHouse/pull/39425) ([Roman Vasin](https://github.com/rvasin)).



<div id="new-feature">
  #### Novo recurso
</div>

* Adicionada uma configuração `exact_rows_before_limit` (0/1). Quando habilitada, o ClickHouse fornecerá o valor exato da estatística `rows_before_limit_at_least`, mas com o custo de exigir a leitura completa dos dados antes do limite. Isso resolve [#6613](https://github.com/ClickHouse/ClickHouse/issues/6613). [#25333](https://github.com/ClickHouse/ClickHouse/pull/25333) ([kevin wan](https://github.com/MaxWk)).
* Adicionada a política de cache SLRU para o cache não comprimido e o cache de marks. [#34651](https://github.com/ClickHouse/ClickHouse/pull/34651) ([alexX512](https://github.com/alexX512)).
* O Intel® In-Memory Analytics Accelerator (Intel® IAA) é um acelerador de hardware disponível na próxima geração de processadores Intel® Xeon® Scalable (&quot;Sapphire Rapids&quot;). Seu objetivo é acelerar operações comuns de analytics, como (des)compressão de dados e filtragem. O ClickHouse passou a contar com o novo codec de compressão &quot;DeflateQpl&quot;, que utiliza a tecnologia de offloading do Intel® IAA para fornecer uma implementação DEFLATE de alto desempenho. O codec usa a [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl), que abstrai o acesso ao acelerador de hardware ou, alternativamente, a um fallback de software caso o acelerador de hardware não esteja disponível. Em geral, o DEFLATE oferece taxas de compressão mais altas do que o codec padrão LZ4 do ClickHouse e, como resultado, reduz a E/S de disco e o consumo de memória principal. [#36654](https://github.com/ClickHouse/ClickHouse/pull/36654) ([jasperzhu](https://github.com/jinjunzh)).
* Adicionado o parâmetro concurrent&#95;threads&#95;soft&#95;limit para aumentar o desempenho em cenários de RPS alto, limitando o número total de threads para todas as consultas. [#37285](https://github.com/ClickHouse/ClickHouse/pull/37285) ([Roman Vasin](https://github.com/rvasin)).
* Adicionada lógica de controle de concorrência para limitar o número total de threads concorrentes criadas por consultas. [#37558](https://github.com/ClickHouse/ClickHouse/pull/37558) ([Sergei Trifonov](https://github.com/serxa)).
* Adicionado suporte a insert select distribuído em paralelo em tabelas com engine Distributed e Replicated [#34670](https://github.com/ClickHouse/ClickHouse/issues/34670). [#39107](https://github.com/ClickHouse/ClickHouse/pull/39107) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Adicionadas novas configurações para controlar a inferência de esquema a partir de formatos de texto: - `input_format_try_infer_dates` - tenta inferir datas a partir de strings. - `input_format_try_infer_datetimes` - tenta inferir datetimes a partir de strings. - `input_format_try_infer_integers` - tenta inferir `Int64` em vez de `Float64`. - `input_format_json_try_infer_numbers_from_strings` - tenta inferir números a partir de strings JSON em formatos JSON. [#39186](https://github.com/ClickHouse/ClickHouse/pull/39186) ([Kruglov Pavel](https://github.com/Avogar)).
* Este recurso fornecerá saída de log em formato JSON no console. O objetivo é facilitar a ingestão e a consulta em ferramentas de análise de logs. [#39277](https://github.com/ClickHouse/ClickHouse/pull/39277) ([Mallik Hassan](https://github.com/SadiHassan)).

Observação: não existem as funções `now64InBlock` nem `todayInBlock`. [#39533](https://github.com/ClickHouse/ClickHouse/pull/39533) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* * Interrompe a análise que ficava travada em consultas complexas. [#38185](https://github.com/ClickHouse/ClickHouse/pull/38185) ([Vladimir C](https://github.com/vdimir)).
* Determina a forma de ordenação com base na descrição de ordenação do fluxo de entrada. Ignora a ordenação se o fluxo de entrada já estiver ordenado. [#38719](https://github.com/ClickHouse/ClickHouse/pull/38719) ([Igor Nikonov](https://github.com/devcrafter)).
* `DISTINCT` em conjunto com `ORDER BY` melhora significativamente o uso de memória e o tempo de execução da consulta se as colunas de `DISTINCT` corresponderem às colunas de `ORDER BY` (ou formarem um prefixo delas). [#39432](https://github.com/ClickHouse/ClickHouse/pull/39432) ([Igor Nikonov](https://github.com/devcrafter)).
* Usa o nó local como primeira prioridade para obter a estrutura da tabela remota ao executar `cluster` e funções de tabela semelhantes. [#39440](https://github.com/ClickHouse/ClickHouse/pull/39440) ([Mingliang Pan](https://github.com/liangliangpan)).
* Usa `DistinctSortedTransform` apenas quando a descrição de ordenação for aplicável às colunas de `DISTINCT`; caso contrário, recorre à implementação comum de `DISTINCT`. Isso permite fazer menos verificações durante a execução de `DistinctSortedTransform`. [#39528](https://github.com/ClickHouse/ClickHouse/pull/39528) ([Igor Nikonov](https://github.com/devcrafter)).
* `DistinctSortedTransform` não aproveitava a ordenação, ou seja, funcionava como uma implementação comum de `DISTINCT`. A correção reduz significativamente o uso de memória. [#39538](https://github.com/ClickHouse/ClickHouse/pull/39538) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector: otimiza o filtro com compress store AVX512VBMI2. [#39633](https://github.com/ClickHouse/ClickHouse/pull/39633) ([Guo Wangyang](https://github.com/guowangy)).
* KeyCondition: otimiza applyFunction em cenários multithread. [#39812](https://github.com/ClickHouse/ClickHouse/pull/39812) ([Guo Wangyang](https://github.com/guowangy)).
* Para sistemas com AVX512 VBMI2, este PR melhora o desempenho em cerca de 6% nas consultas 3.1, 3.2 e 3.3 do benchmark SSB (SF=100). Testado em Intel Icelake Xeon 8380 * 2 socket. [#40033](https://github.com/ClickHouse/ClickHouse/pull/40033) ([Robert Schulze](https://github.com/rschu1ze)).
* * Não percorre a AST de UDFs se nenhuma estiver registrada. [#40069](https://github.com/ClickHouse/ClickHouse/pull/40069) ([Raúl Marín](https://github.com/Algunenano)).
* * Otimiza a alocação e a liberação de CurrentMemoryTracker. [#40078](https://github.com/ClickHouse/ClickHouse/pull/40078) ([Raúl Marín](https://github.com/Algunenano)).
