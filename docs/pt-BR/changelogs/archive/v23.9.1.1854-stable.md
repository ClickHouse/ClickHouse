<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* A opção de configuration `status_info` e o status de Dictionaries foram removidos do handler Prometheus padrão. [#54090](https://github.com/ClickHouse/ClickHouse/pull/54090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* O metadata cache experimental de partes foi removido da codebase. [#54215](https://github.com/ClickHouse/ClickHouse/pull/54215) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* A setting `input_format_json_try_infer_numbers_from_strings` foi desabilitada por padrão, para que não se tente inferir números a partir de strings em JSON formats por padrão, evitando possíveis parsing errors quando os sample data contêm strings que parecem números. [#55099](https://github.com/ClickHouse/ClickHouse/pull/55099) ([Kruglov Pavel](https://github.com/Avogar)).
* Os Bloom filter indexes de IPv6 criados antes de março de 2023 não são compatíveis com a versão atual e precisam ser recriados. [#54200](https://github.com/ClickHouse/ClickHouse/pull/54200) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).



<div id="new-feature">
  #### Novo recurso
</div>

* Adicionado um novo tipo de autenticação baseado em chaves SSH. Funciona apenas com o protocolo TCP nativo. [#41109](https://github.com/ClickHouse/ClickHouse/pull/41109) ([George Gamezardashvili](https://github.com/InfJoker)).
* Adicionado suporte a agendamento de E/S para discos remotos. A configuração de armazenamento para os tipos de disco `s3`, `s3_plain`, `hdfs` e `azure_blob_storage` agora pode conter os elementos `read_resource` e `write_resource`, com nomes de recursos. As políticas de agendamento desses recursos podem ser configuradas em uma seção separada da configuração do servidor, `resources`. As queries podem ser marcadas usando a configuração `workload` e classificadas usando a seção `workload_classifiers` da configuração do servidor, para atender a diferentes objetivos de agendamento de recursos. Mais detalhes em docs/en/operations/workload-scheduling.md. [#47009](https://github.com/ClickHouse/ClickHouse/pull/47009) ([Sergei Trifonov](https://github.com/serxa)).
* Adicionada uma nova coluna &#95;block&#95;number, que resolve [#44532](https://github.com/ClickHouse/ClickHouse/issues/44532). [#47532](https://github.com/ClickHouse/ClickHouse/pull/47532) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Adicionadas as opções `partial_result_update_duration_ms` e `max_rows_in_partial_result` para exibir atualizações de um resultado parcial da tabela de saída em tempo real durante a execução da query. [#48607](https://github.com/ClickHouse/ClickHouse/pull/48607) ([Alexey Perevyshin](https://github.com/alexX512)).
* Adicionado suporte a modos de correspondência case-insensitive e dot-all em dicionários RegExpTree. [#50906](https://github.com/ClickHouse/ClickHouse/pull/50906) ([Johann Gan](https://github.com/johanngan)).
* Adicionado suporte a `ALTER TABLE MODIFY COMMENT`. Observação: algo semelhante foi adicionado por um contributor externo há muito tempo, mas o recurso não funcionava de forma alguma e só confundia os usuários. Isso fecha [#36377](https://github.com/ClickHouse/ClickHouse/issues/36377). [#51304](https://github.com/ClickHouse/ClickHouse/pull/51304) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionado &quot;GCD&quot;, também conhecido como &quot;greatest common denominator&quot;, como um novo codec de compressão de dados. O codec calcula o GCD de todos os valores da coluna e, em seguida, divide cada valor pelo GCD. O codec GCD é um codec de preparação de dados (semelhante a Delta e DoubleDelta) e não pode ser usado isoladamente. Ele funciona com dados dos tipos inteiro, decimal e data/hora. Um caso de uso viável para o codec GCD são valores de coluna que variam (aumentam/diminuem) em múltiplos do GCD, por exemplo 24 - 28 - 16 - 24 - 8 - 24 (assumindo GCD = 4). [#53149](https://github.com/ClickHouse/ClickHouse/pull/53149) ([Alexander Nam](https://github.com/seshWCS)).
* Foram adicionados dois novos aliases de tipo, &quot;DECIMAL(P)&quot; (como atalho para &quot;DECIMAL(P, 0&quot;) e &quot;DECIMAL&quot; (como atalho para &quot;DECIMAL(10, 0)&quot;). Isso torna o ClickHouse mais compatível com o SQL dialect do MySQL. [#53328](https://github.com/ClickHouse/ClickHouse/pull/53328) ([Val Doroshchuk](https://github.com/valbok)).
* Adicionada uma nova tabela de log do sistema, `backup_log`, para rastrear todas as operações `BACKUP` e `RESTORE`. [#53638](https://github.com/ClickHouse/ClickHouse/pull/53638) ([Victor Krasnov](https://github.com/sirvickr)).
* Adicionada uma configuração de formato, &quot;output&#95;format&#95;markdown&#95;escape&#95;special&#95;characters&quot; (padrão: false). A configuração controla se caracteres especiais como &quot;!&quot;, &quot;#&quot;, &quot;$&quot; etc. são escapados (ou seja, prefixados com uma barra invertida) no formato de saída &quot;Markdown&quot;. [#53860](https://github.com/ClickHouse/ClickHouse/pull/53860) ([irenjj](https://github.com/irenjj)).
* Adicionada a função `decodeHTMLComponent`. [#54097](https://github.com/ClickHouse/ClickHouse/pull/54097) ([Bharat Nallan](https://github.com/bharatnc)).
* Adicionado `peak_threads_usage` à tabela `query_log`. [#54335](https://github.com/ClickHouse/ClickHouse/pull/54335) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* Adicionado suporte a SHOW FUNCTIONS no `clickhouse-client`. [#54337](https://github.com/ClickHouse/ClickHouse/pull/54337) ([Julia Kartseva](https://github.com/wat-ze-hex)).
* Este PR melhora a inferência de esquema em formatos JSON: 1) Agora é possível inferir Tuples nomeadas a partir de objetos JSON sem o tipo JSON experimental, com a setting `input_format_json_try_infer_named_tuples_from_objects` em formatos JSON. Antes, sem o tipo JSON experimental, só era possível inferir objetos JSON como Strings ou Maps; agora, podemos inferir Tuple nomeada. O tipo Tuple resultante conterá todas as chaves dos objetos lidos na amostra de dados durante a inferência de esquema. Isso pode ser útil para ler dados JSON estruturados sem objetos esparsos. A setting é habilitada por padrão. 2) Permite fazer parsing de JSON array em uma coluna do tipo String com a setting `input_format_json_read_arrays_as_strings`. Isso pode ajudar na leitura de arrays com valores de tipos diferentes. 3) Permite usar o tipo String para chaves JSON com tipos desconhecidos (`null`/`[]`/`{}`) na amostra de dados com a setting `input_format_json_infer_incomplete_types_as_strings`. Agora, em formatos JSON, podemos ler qualquer valor em uma coluna String e evitar o erro `Cannot determine type for column 'column_name' by first 25000 rows of data, most likely this column contains only Nulls or empty Arrays/Maps` durante a inferência de esquema usando o tipo String para tipos desconhecidos, para que os dados sejam lidos com sucesso. [#54427](https://github.com/ClickHouse/ClickHouse/pull/54427) ([Kruglov Pavel](https://github.com/Avogar)).
* Adicionada a função &quot;toDaysSinceYearZero&quot; com o alias &quot;TO&#95;DAYS()&quot; (para compatibilidade com MySQL), que retorna o número de dias decorridos desde 0001-01-01. [#54479](https://github.com/ClickHouse/ClickHouse/pull/54479) ([Robert Schulze](https://github.com/rschu1ze)).
* Adicionadas as funções YYYYMMDDtoDate(), YYYYMMDDtoDate32(), YYYYMMDDhhmmssToDateTime() e YYYYMMDDhhmmssToDateTime64(). Elas convertem uma data ou data com hora codificada como inteiro (por exemplo, 20230911) em uma data ou data com hora nativa. Assim, elas oferecem a funcionalidade oposta às funções existentes YYYYMMDDToDate(), YYYYMMDDToDateTime(), YYYYMMDDhhmmddToDateTime(), YYYYMMDDhhmmddToDateTime64(). [#54509](https://github.com/ClickHouse/ClickHouse/pull/54509) ([Robert Schulze](https://github.com/rschu1ze)).
* Adicionado o tipo de nó de escalonamento de E/S &quot;bandwidth&#95;limit&quot;. Ele permite especificar as restrições `max_speed` e `max_burst` no tráfego que passa por esse nó. Mais detalhes em docs/en/operations/workload-scheduling.md. [#54618](https://github.com/ClickHouse/ClickHouse/pull/54618) ([Sergei Trifonov](https://github.com/serxa)).
* A função `toDaysSinceYearZero()` agora oferece suporte a argumentos do tipo `DateTime` e `DateTime64`. [#54856](https://github.com/ClickHouse/ClickHouse/pull/54856) ([Serge Klochkov](https://github.com/slvrtrn)).
* Permite URLs no estilo S3 para as funções de tabela `s3`, `gcs`, `oss`. A URL é convertida automaticamente em HTTP. Exemplo: `'s3://clickhouse-public-datasets/hits.csv'` é convertida para `'https://clickhouse-public-datasets.s3.amazonaws.com/hits.csv'`. [#54931](https://github.com/ClickHouse/ClickHouse/pull/54931) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Adicionadas várias funções de distância entre strings, incluindo `byteHammingDistance`, `byteJaccardIndex` e `byteEditDistance`. ### Entrada de documentação para mudanças visíveis ao usuário. [#54935](https://github.com/ClickHouse/ClickHouse/pull/54935) ([flynn](https://github.com/ucasfl)).
* Adiciona a nova configuração `print_pretty_type_names` para imprimir de forma legível tipos profundamente aninhados, como Tuple/Maps/Arrays. [#55095](https://github.com/ClickHouse/ClickHouse/pull/55095) ([Kruglov Pavel](https://github.com/Avogar)).

* A biblioteca usada para processar (codificar/decodificar) valores em base64 foi substituída de Turbo-Base64 para aklomp-base64. Ambas têm aceleração por SIMD em x86 e ARM, mas 1. a licença da última (BSD-2) é mais favorável para o ClickHouse, já que a Turbo64 mudou nesse meio-tempo para GPL-3, 2. com mais estrelas no GitHub, a aklomp-base64 parece ser uma opção mais preparada para o futuro, 3. a aklomp-base64 tem uma API ligeiramente melhor (o que é, discutivelmente, subjetivo) e 4. a aklomp-base64 não exige contornos para bugs (como inicialização sem thread safety). Nota: a aklomp-base64 rejeita valores em base64 sem padding, enquanto a Turbo-Base64 os decodifica na base do melhor esforço. A RFC-4648 deixa em aberto se o padding é obrigatório ou não, mas, dependendo do contexto, isso pode ser uma mudança de comportamento à qual convém ficar atento. [#54119](https://github.com/ClickHouse/ClickHouse/pull/54119) ([Mikhail Koviazin](https://github.com/mkmkme)).
