<div id="clickhouse-release-v209220-stable-fixme-as-compared-to-v20814513-prestable">
  ### Lançamento do ClickHouse v20.9.2.20-stable FIXME em comparação com o v20.8.1.4513-prestable
</div>

<div id="new-feature">
  #### Novo Recurso
</div>

* Adicionada a função de tabela `view`, que transforma uma subconsulta em um objeto de tabela. Isso facilita reutilizar consultas. Por exemplo, ela pode ser usada em funções de tabela remote/cluster. [#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* Agora podemos escrever `select * apply(length) apply(max) from wide_string_table` para descobrir o comprimento máximo de todas as colunas String. As duas variantes a seguir também são fornecidas: [#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* Adicionada a função de agregação RankCorrelationSpearman, que simplesmente calcula um coeficiente de correlação por postos. Continuação de [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769). [#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Adicionado o utilitário de geração de banco de dados por consulta. Continuação de [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973). [#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Otimiza consultas com LIMIT/LIMIT BY/ORDER BY em Distributed com GROUP BY `sharding_key` (em `optimize_skip_unused_shards` e `optimize_distributed_group_by_sharding_key`). [#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Melhoria
</div>

* Melhorias no StorageRabbitMQ: adicionado tratamento para falhas de connection e channels, commits adequados, tratamento de falhas de insert, melhorias em exchanges, durabilidade da queue e possibilidade de retomar a queue, além de novas configurações de queue. Testes corrigidos. [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Adicionada a autorização `requirepass` do Redis. [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* Adicionado o argumento de precision para o tipo DateTime. [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* Melhorado o desempenho do motor Kafka com o uso de uma thread independente para cada consumer. Thread pool separada para motores de streaming (como Kafka). [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* Adicionado o compression codec padrão para partes em `system.part_log` com o nome `default_compression_codec`. [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* Substituídos os inteiros wide do boost multiprecision pela implementação de [https://github.com/cerevra/int](https://github.com/cerevra/int). [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* Conversão implícita da primary key para not null no MaterializeMySQL (assim como no MySQL). Corrige [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114). [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* Adicionada a nova configuração system&#95;events&#95;show&#95;zero&#95;values, como proposto em [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384). [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Agora o ofuscador oferece suporte ao tipo UUID, como proposto em [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163). [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* Criação de sets para múltiplos `JOIN` e `IN` em paralelo. Isso pode melhorar ligeiramente o desempenho de consultas com várias expressões `IN subquery` diferentes. [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Agora os TTLs serão aplicados durante o merge se não tiverem sido materializados anteriormente. [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* O handler do MySQL retorna `OK` para consultas como `SET @@var = value`. Essa statement é ignorada. Isso é necessário porque alguns drivers MySQL enviam a consulta `SET @@` para configuração após o handshake [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422 . [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* Não permitir argumento `time_zone` vazio em funções do tipo `toStartOf*`. [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* Retroportado em [#14873](https://github.com/ClickHouse/ClickHouse/issues/14873): permitir o uso de multi-volume storage configuration no armazenamento Distributed. [#14839](https://github.com/ClickHouse/ClickHouse/pull/14839) ([Pavel Kovalenko](https://github.com/Jokser)).
