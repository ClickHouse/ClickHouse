<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Remove o recurso `do_not_evict_index_and_mark_files` do cache de sistema de arquivos. Esse recurso só estava piorando as coisas. [#51253](https://github.com/ClickHouse/ClickHouse/pull/51253) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Remove o suporte a ALTER para LIVE VIEW experimental. [#51287](https://github.com/ClickHouse/ClickHouse/pull/51287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### Novo recurso
</div>

* Adiciona a configuração `session_timezone`, usada como fuso horário padrão da sessão quando não for especificada explicitamente. [#44149](https://github.com/ClickHouse/ClickHouse/pull/44149) ([Andrey Zvonov](https://github.com/zvonand)).
* Adiciona o database engine overlay e a representação de um diretório como banco de dados. Este commit adiciona 4 bancos de dados: 1. DatabaseOverlay: implementa a interface IDatabase. Permite combinar vários bancos de dados, como FileSystem e Memory. Internamente, armazena um vetor com ponteiros para outros bancos de dados e encaminha as requisições para eles, um por vez, até que sejam executadas com sucesso. 2. DatabaseFilesystem: permite interação read-only com arquivos armazenados no sistema de arquivos. Internamente, usa TableFunctionFile para carregar implicitamente o arquivo quando um usuário solicita a tabela. O resultado da chamada de TableFunctionFile é armazenado em cache internamente para fornecer acesso rápido. 3. DatabaseS3: permite interação read-only com o armazenamento S3. Usa TableFunctionS3 para carregar implicitamente a tabela do S3. 4. DatabaseHDFS: permite interagir com o armazenamento HDFS. Usa TableFunctionHDFS para carregar implicitamente a tabela do HDFS. [#48821](https://github.com/ClickHouse/ClickHouse/pull/48821) ([alekseygolub](https://github.com/alekseygolub)).
* Adiciona uma nova configuração chamada `use_mysql_types_in_show_columns` para alterar a instrução SQL `SHOW COLUMNS` e exibir tipos equivalentes do MySQL quando um cliente estiver conectado pela porta de compatibilidade MySQL. [#49577](https://github.com/ClickHouse/ClickHouse/pull/49577) ([Thomas Panetti](https://github.com/tpanetti)).
* Adiciona a opção `--rename_files_after_processing <pattern>`. Isso fecha [#34207](https://github.com/ClickHouse/ClickHouse/issues/34207). [#49626](https://github.com/ClickHouse/ClickHouse/pull/49626) ([alekseygolub](https://github.com/alekseygolub)).
* 1. Adiciona `TableFunctionRedis` 3. Adiciona o table engine Redis 4. Adiciona `RedisCommon`, que contém ferramentas e tipos relacionados ao Redis 5. Suporta pushdown dos filtros `equals` e `in` no Redis. [#50150](https://github.com/ClickHouse/ClickHouse/pull/50150) ([JackyWoo](https://github.com/JackyWoo)).
* Permite ignorar arquivos vazios nas table functions file/s3/url/hdfs usando as configurações `s3_skip_empty_files`, `hdfs_skip_empty_files`, `engine_file_skip_empty_files`, `engine_url_skip_empty_files`. [#50364](https://github.com/ClickHouse/ClickHouse/pull/50364) ([Kruglov Pavel](https://github.com/Avogar)).
* `clickhouse-client` agora pode ser chamado com uma conexão em vez de &quot;--host&quot;, &quot;--port&quot;, &quot;--user&quot; etc. [#50689](https://github.com/ClickHouse/ClickHouse/pull/50689) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* O codec DEFLATE&#95;QPL agora é controlado pela configuração do servidor &quot;enable&#95;deflate&#95;qpl&#95;codec&quot; (padrão: false) em vez da configuração &quot;allow&#95;experimental&#95;codecs&quot;. Isso torna QPL&#95;DEFLATE não experimental. [#50775](https://github.com/ClickHouse/ClickHouse/pull/50775) ([Robert Schulze](https://github.com/rschu1ze)).



<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Melhora o desempenho com o QueryProfiler habilitado usando `timer_id` local da thread em vez de um objeto global. [#48778](https://github.com/ClickHouse/ClickHouse/pull/48778) ([Jiebin Sun](https://github.com/jiebinn)).
* Reescreve o formato de entrada/saída CapnProto para melhorar o desempenho. Mapeia nomes de colunas e campos do CapnProto sem diferenciar maiúsculas de minúsculas e corrige a leitura/gravação de campos de estruturas aninhadas. [#49752](https://github.com/ClickHouse/ClickHouse/pull/49752) ([Kruglov Pavel](https://github.com/Avogar)).
* Otimiza o desempenho de escrita em Parquet para threads em paralelo. [#50102](https://github.com/ClickHouse/ClickHouse/pull/50102) ([Hongbin Ma](https://github.com/binmahone)).
* ### Entrada de documentação para mudanças voltadas ao usuário Desabilita `parallelize_output_from_storages` para processar MATERIALIZED VIEWs e armazenamentos com apenas um bloco. [#50214](https://github.com/ClickHouse/ClickHouse/pull/50214) ([Azat Khuzhin](https://github.com/azat)).
* Faz merge do PR https://github.com/ClickHouse/ClickHouse/pull/46558 (Evitar processar dados já ordenados). Evita a permutação de blocos durante a ordenação se o bloco já estiver ordenado. [#50697](https://github.com/ClickHouse/ClickHouse/pull/50697) ([Maksim Kita](https://github.com/kitaisreal)).
* Nos PRs anteriores ([#50062](https://github.com/ClickHouse/ClickHouse/issues/50062), [#50307](https://github.com/ClickHouse/ClickHouse/issues/50307)), foi proposto um padrão de otimização que transforma os predicados com toYear/toYYYYMM em uma forma equivalente, mas sem conversor. Essa transformação poderia trazer um ganho significativo de desempenho para algumas cargas de trabalho, como SSB. No entanto, como a issue [#50628](https://github.com/ClickHouse/ClickHouse/issues/50628) indicou, esses dois PRs introduziriam problemas que poderiam resultar em resultados de consulta incompletos e, por isso, foram revertidos em [#50629](https://github.com/ClickHouse/ClickHouse/issues/50629). [#50951](https://github.com/ClickHouse/ClickHouse/pull/50951) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Faz várias solicitações de listagem ao ZooKeeper em paralelo para acelerar a leitura da tabela system.zookeeper. [#51042](https://github.com/ClickHouse/ClickHouse/pull/51042) ([Alexander Gololobov](https://github.com/davenger)).
* Acelera a inicialização das tabelas de lookup de DateTime para fusos horários. Isso deve reduzir o tempo de inicialização/conexão do clickhouse client, especialmente em compilação de depuração, já que isso é bastante pesado. [#51347](https://github.com/ClickHouse/ClickHouse/pull/51347) ([Alexander Gololobov](https://github.com/davenger)).

Fecha [#50577](https://github.com/ClickHouse/ClickHouse/issues/50577). [#50592](https://github.com/ClickHouse/ClickHouse/pull/50592) ([Kruglov Pavel](https://github.com/Avogar)).

* As configurações `number_of_mutations_to_delay` e `number_of_mutations_to_throw` agora estão habilitadas por padrão com os valores 500 e 1000, respectivamente. [#50726](https://github.com/ClickHouse/ClickHouse/pull/50726) ([Anton Popov](https://github.com/CurtizJ)).
* Melhoria no Keeper: adição de feature flags para a API do Keeper. Cada feature flag pode ser desabilitada ou habilitada definindo-a na configuração `keeper_server.feature_flags`. Por exemplo, para habilitar a requisição `CheckNotExists`, `keeper_server.feature_flags.check_not_exists` deve ser definido como `1` no Keeper. [#50796](https://github.com/ClickHouse/ClickHouse/pull/50796) ([Antonio Andelic](https://github.com/antonio2368)).

As métricas de uso de CPU `Normalized` passarão a ser normalizadas em relação aos limites de CGroups em vez do número total de CPUs, quando esses limites estiverem definidos. Fecha [#50836](https://github.com/ClickHouse/ClickHouse/issues/50836). [#50835](https://github.com/ClickHouse/ClickHouse/pull/50835) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Corrige a lentidão em data lakes causada por requisições head síncronas. (Relacionado à lentidão do Iceberg/Deltalake/Hudi com grande quantidade de arquivos). [#50976](https://github.com/ClickHouse/ClickHouse/pull/50976) ([Kseniia Sumarokova](https://github.com/kssenii)).

[#51026](https://github.com/ClickHouse/ClickHouse/pull/51026) ([郭小龙](https://github.com/guoxiaolongzte)).
