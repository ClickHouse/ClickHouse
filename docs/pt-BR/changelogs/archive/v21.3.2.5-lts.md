<div id="clickhouse-release-v21325-lts-fixme-as-compared-to-v21215869-prestable">

<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Agora, todos os nomes de função sem distinção entre maiúsculas e minúsculas serão convertidos para minúsculas durante a análise da consulta. Isso é necessário para o roteamento de consultas para projeções. [#20174](https://github.com/ClickHouse/ClickHouse/pull/20174) ([Amos Bird](https://github.com/amosbird)).
* Agora, não é mais permitido criar tabelas MergeTree na sintaxe antiga com TTL de tabela, porque isso é simplesmente ignorado. O Attach de tabelas antigas ainda é possível. [#20282](https://github.com/ClickHouse/ClickHouse/pull/20282) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### Novo recurso
</div>

* Adicionado o mecanismo de banco de dados `Replicated` experimental. Ele replica consultas DDL entre vários hosts. [#16193](https://github.com/ClickHouse/ClickHouse/pull/16193) ([Alexander Tokmakov](https://github.com/tavplubix)).
* A desduplicação de consultas distribuídas é uma continuação de [#16033](https://github.com/ClickHouse/ClickHouse/issues/16033) e resolve parcialmente a proposta [#13574](https://github.com/ClickHouse/ClickHouse/issues/13574). [#17348](https://github.com/ClickHouse/ClickHouse/pull/17348) ([xjewer](https://github.com/xjewer)).

A configuração `min_marks_to_honor_max_concurrent_queries` determina que a configuração anterior só seja aplicada se a consulta ler pelo menos esse número de marcas. [#19544](https://github.com/ClickHouse/ClickHouse/pull/19544) ([Amos Bird](https://github.com/amosbird)).

* Adicionada a função timezoneOffset(datetime), que retorna o deslocamento em relação ao UTC em segundos. Isso fecha [#issue:19850](https://github.com/ClickHouse/ClickHouse/issues/19850). [#19962](https://github.com/ClickHouse/ClickHouse/pull/19962) ([keenwolf](https://github.com/keen-wolf)).

* ... Adiciona a função de agregação `deltaSum` para somar as diferenças entre linhas consecutivas. [#20057](https://github.com/ClickHouse/ClickHouse/pull/20057) ([Russ Frank](https://github.com/rf)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Adicionado SELECT FINAL paralelo para uma part com level&gt;0 quando a configuração `do_not_merge_across_partitions_select_final` é 1. [#19375](https://github.com/ClickHouse/ClickHouse/pull/19375) ([Kruglov Pavel](https://github.com/Avogar)).
* Melhorado o desempenho de colunas bitmap durante junções. [#19407](https://github.com/ClickHouse/ClickHouse/pull/19407) ([templarzq](https://github.com/templarzq)).
* Reimplementado parcialmente o servidor HTTP para reduzir a quantidade de cópias dos dados de entrada e saída. Isso traz um ganho de desempenho de até 1,5x ao inserir registros longos via HTTP. [#19516](https://github.com/ClickHouse/ClickHouse/pull/19516) ([Ivan](https://github.com/abyss7)).
* Melhorado o desempenho de funções de agregação com aliasing mais estrito. [#19946](https://github.com/ClickHouse/ClickHouse/pull/19946) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrigido o caso em que o parser de DataType pode ter complexidade exponencial (encontrado por fuzzer). Isso fecha [#20096](https://github.com/ClickHouse/ClickHouse/issues/20096). [#20132](https://github.com/ClickHouse/ClickHouse/pull/20132) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionada a configuração `compress` para tabelas `Memory`. Se estiver habilitada, a tabela usará menos RAM. Em algumas máquinas e datasets, ela também pode ser mais rápida em SELECT, mas nem sempre esse é o caso. Isso fecha [#20093](https://github.com/ClickHouse/ClickHouse/issues/20093). Observação: há motivos pelos quais tabelas Memory podem ser mais lentas que MergeTree: (1) ausência de compressão (2) tamanho estático dos blocos (3) ausência de índices e prewhere... [#20168](https://github.com/ClickHouse/ClickHouse/pull/20168) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Não fazer squash excessivo dos blocos em INSERT SELECT ao inserir em uma tabela Memory. Em versões anteriores, uma representação ineficiente dos dados era criada na tabela Memory após INSERT SELECT. Isso fecha [#13052](https://github.com/ClickHouse/ClickHouse/issues/13052). [#20169](https://github.com/ClickHouse/ClickHouse/pull/20169) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhorado o desempenho da agregação por vários campos de tamanho fixo (não confirmado). [#20454](https://github.com/ClickHouse/ClickHouse/pull/20454) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelerada a leitura de tabelas `Memory` em casos extremos (quando a velocidade de leitura está na ordem de 50 GB/sec) por meio da simplificação do pipeline e, consequentemente, de menor contenção de locks no agendamento do pipeline. [#20468](https://github.com/ClickHouse/ClickHouse/pull/20468) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhorado o desempenho de GROUP BY com múltiplas chaves de tamanho fixo. [#20472](https://github.com/ClickHouse/ClickHouse/pull/20472) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* A configuração `distributed_aggregation_memory_efficient` está habilitada por padrão. Ela reduzirá o uso de memória e melhorará o desempenho de consultas distribuídas. [#20599](https://github.com/ClickHouse/ClickHouse/pull/20599) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Pequena melhoria no código de agregação. [#20978](https://github.com/ClickHouse/ClickHouse/pull/20978) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionadas novamente as especializações vectorConstant de intDiv/module para melhor desempenho. Isso corrige [#21293](https://github.com/ClickHouse/ClickHouse/issues/21293) . A regressão foi introduzida em [https://github.com/ClickHouse/ClickHouse/pull/18145](https://github.com/ClickHouse/ClickHouse/pull/18145) . [#21307](https://github.com/ClickHouse/ClickHouse/pull/21307) ([Amos Bird](https://github.com/amosbird)).

<div id="improvement">
  #### Melhoria
</div>

* Corrigida a criação de `TTL` nos casos em que sua expressão é uma função e coincide com a chave `ORDER BY`. Agora é permitido definir agregação personalizada para as colunas da chave primária em `TTL` com `GROUP BY`. Incompatibilidade retroativa: para colunas da chave primária que não estão em `GROUP BY` e não são definidas explicitamente, agora é aplicada a função `any` em vez de `max` quando o TTL expira. Além disso, se você usar TTL com `WHERE` ou `GROUP BY`, poderá ver exceções durante merges ao fazer rolling update. [#15450](https://github.com/ClickHouse/ClickHouse/pull/15450) ([Anton Popov](https://github.com/CurtizJ)).
* Hedged Requests para consultas remotas. Quando a configuração `use_hedged_requests` está habilitada (por padrão), é possível estabelecer várias conexões com diferentes réplicas para a consulta. Uma nova conexão é habilitada caso a(s) conexão(ões) existente(s) com a(s) réplica(s) não tenha(m) sido estabelecida(s) dentro de `hedged_connection_timeout` ou nenhum dado tenha sido recebido dentro de `receive_data_timeout`. A consulta usa a primeira conexão que envia um pacote de progresso não vazio (ou pacote de dados, se `allow_changing_replica_until_first_data_packet`); as outras conexões são canceladas. Há suporte para consultas com `max_parallel_replicas > 1`. [#19291](https://github.com/ClickHouse/ClickHouse/pull/19291) ([Kruglov Pavel](https://github.com/Avogar)).
* Imprime frames inline para stacktraces fatais. [#19317](https://github.com/ClickHouse/ClickHouse/pull/19317) ([Ivan](https://github.com/abyss7)).
* Não ignore silenciosamente erros de gravação. [#19451](https://github.com/ClickHouse/ClickHouse/pull/19451) ([Azat Khuzhin](https://github.com/azat)).
* Adicionado suporte a `PREWHERE` quando as tabelas têm expressões de segurança em nível de linha especificadas. [#19576](https://github.com/ClickHouse/ClickHouse/pull/19576) ([Denis Glazachev](https://github.com/traceon)).
* Adicionada a interface IStoragePolicy. [#19608](https://github.com/ClickHouse/ClickHouse/pull/19608) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* Adicionada a capacidade de limitar INSERT em Distributed com base na quantidade de bytes pendentes para envio assíncrono (foram adicionadas as configurações `bytes_to_delay_insert`/`max_delay_to_insert` e `bytes_to_throw_insert` para o engine `Distributed`). [#19673](https://github.com/ClickHouse/ClickHouse/pull/19673) ([Azat Khuzhin](https://github.com/azat)).
* Mover condições que não estão relacionadas a JOIN para a cláusula WHERE. [#18720](https://github.com/ClickHouse/ClickHouse/issues/18720). [#19685](https://github.com/ClickHouse/ClickHouse/pull/19685) ([hexiaoting](https://github.com/hexiaoting)).
* Adicionada uma diretiva de config separada para o profile Buffer. [#19721](https://github.com/ClickHouse/ClickHouse/pull/19721) ([Azat Khuzhin](https://github.com/azat)).
* Mostrar tabelas MaterializeMySQL em `system.parts`. [#19770](https://github.com/ClickHouse/ClickHouse/pull/19770) ([Stig Bakken](https://github.com/stigsb)).
* Inicializar MaxDDLEntryID com o último valor após a reinicialização. Antes deste PR, MaxDDLEntryID permanecia zero até que uma nova DDLTask fosse processada. [#19924](https://github.com/ClickHouse/ClickHouse/pull/19924) ([Amos Bird](https://github.com/amosbird)).
* Adicionada a conversão da estrutura do bloco para INSERT em tabelas Distributed caso ela não corresponda. [#19947](https://github.com/ClickHouse/ClickHouse/pull/19947) ([Azat Khuzhin](https://github.com/azat)).
* Se o usuário chamar a função `JSONExtract` com o tipo `Float32` solicitado, permitir conversão imprecisa para o tipo de resultado. Por exemplo, o número `0.1` em JSON tem precisão dupla e não pode ser representado em Float32, mas o usuário ainda quer obtê-lo. Versões anteriores retornavam 0 para o tipo não-Nullable e NULL para o tipo Nullable para indicar que a conversão era imprecisa. A lógica estava 100% correta, mas isso surpreendia os usuários e gerava dúvidas. Isso fecha [#13962](https://github.com/ClickHouse/ClickHouse/issues/13962). [#19960](https://github.com/ClickHouse/ClickHouse/pull/19960) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
