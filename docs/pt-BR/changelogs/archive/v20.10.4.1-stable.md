<div id="improvement">
  #### Melhoria
</div>

* Solução alternativa para usar o S3 com o servidor Nginx como proxy. Atualmente, o Nginx não aceita URLs com caminho vazio, como [http://domain.com?delete](http://domain.com?delete), mas o aws-sdk-cpp original produz esse tipo de URL. Este commit usa uma versão modificada do aws-sdk-cpp, que, nesses casos, gera URLs com &quot;/&quot; como caminho, como [http://domain.com/?delete](http://domain.com/?delete). [#16813](https://github.com/ClickHouse/ClickHouse/pull/16813) ([ianton-ru](https://github.com/ianton-ru)).

<div id="bug-fix">
  #### Correção de bug
</div>

* Retroportado em [#16492](https://github.com/ClickHouse/ClickHouse/issues/16492): Corrige um bug com banco de dados MySQL. Quando o servidor MySQL usado como engine de banco de dados fica indisponível, algumas consultas geram Exception porque tentam obter tabelas de um servidor desabilitado, embora isso seja desnecessário. Por exemplo, a consulta `SELECT ... FROM system.parts` deve funcionar apenas com tabelas MergeTree e não acessar o banco de dados MySQL de forma alguma. [#16032](https://github.com/ClickHouse/ClickHouse/pull/16032) ([Kruglov Pavel](https://github.com/Avogar)).
* Retroportado em [#16710](https://github.com/ClickHouse/ClickHouse/issues/16710): Corrige o comportamento inconsistente em que parte dos dados retornados podia ser descartada porque o set para filtragem não era criado. [#16308](https://github.com/ClickHouse/ClickHouse/pull/16308) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Retroportado em [#16505](https://github.com/ClickHouse/ClickHouse/issues/16505): Corrige o processamento de entradas muito grandes na fila de replicação. Entradas muito grandes podem aparecer em consultas ALTER se a estrutura da tabela for extremamente grande (próxima de 1 MB). Isso corrige [#16307](https://github.com/ClickHouse/ClickHouse/issues/16307). [#16332](https://github.com/ClickHouse/ClickHouse/pull/16332) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Retroportado em [#16471](https://github.com/ClickHouse/ClickHouse/issues/16471): Corrige DROP TABLE para Distributed (condição de corrida com INSERT). [#16409](https://github.com/ClickHouse/ClickHouse/pull/16409) ([Azat Khuzhin](https://github.com/azat)).
* Retroportado em [#16572](https://github.com/ClickHouse/ClickHouse/issues/16572): Corrige o rápido crescimento dos metadados ao usar MySQL Master -&gt; MySQL Slave -&gt; ClickHouse MaterializeMySQL Engine, com `slave_parallel_worker` habilitado no MySQL Slave, reduzindo corretamente os conjuntos GTID. Isso corrige [#15951](https://github.com/ClickHouse/ClickHouse/issues/15951). [#16504](https://github.com/ClickHouse/ClickHouse/pull/16504) ([TCeason](https://github.com/TCeason)).
* Retroportado em [#16551](https://github.com/ClickHouse/ClickHouse/issues/16551): Agora, ao fazer o parsing de AVRO na entrada, o LowCardinality é removido do tipo. Corrige [#16188](https://github.com/ClickHouse/ClickHouse/issues/16188). [#16521](https://github.com/ClickHouse/ClickHouse/pull/16521) ([Mike Kot](https://github.com/myrrc)).
* Retroportado em [#16749](https://github.com/ClickHouse/ClickHouse/issues/16749): Corrige [#16081](https://github.com/ClickHouse/ClickHouse/issues/16081). [#16613](https://github.com/ClickHouse/ClickHouse/pull/16613) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

[#16637](https://github.com/ClickHouse/ClickHouse/pull/16637) ([Azat Khuzhin](https://github.com/azat)).
