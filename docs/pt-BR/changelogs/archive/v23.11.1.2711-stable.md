<div id="backward-incompatible-change">
  #### Mudança incompatível com versões anteriores
</div>

* Os formatadores `%l`/`%k`/`%c` na função `parseDateTime()` agora conseguem analisar horas/meses sem zeros à esquerda; por exemplo, `select parseDateTime('2023-11-26 8:14', '%F %k:%i')` agora funciona. Defina `parsedatetime_parse_without_leading_zeros = 0` para restaurar o comportamento anterior, que exigia dois dígitos. A função `formatDateTime` agora também consegue exibir horas/meses sem zeros à esquerda. Isso é controlado pela configuração `formatdatetime_format_without_leading_zeros`, mas permanece desativado por padrão para não quebrar casos de uso existentes. [#55872](https://github.com/ClickHouse/ClickHouse/pull/55872) ([Azat Khuzhin](https://github.com/azat)).
* Agora não é mais possível usar a função de agregação `avgWeighted` com argumentos do tipo `Decimal`. Solução alternativa: converta os argumentos para `Float64`. Isso fecha [#43928](https://github.com/ClickHouse/ClickHouse/issues/43928). Isso fecha [#31768](https://github.com/ClickHouse/ClickHouse/issues/31768). Isso fecha [#56435](https://github.com/ClickHouse/ClickHouse/issues/56435). Se você usou essa função dentro de visões materializadas ou projeções com argumentos `Decimal`, entre em contato com support@clickhouse.com. Foi corrigido um erro na função de agregação `sumMap`, e ela ficou cerca de 1.5..2 vezes mais lenta. Isso não faz diferença, porque a função já é ruim de qualquer forma. Isso fecha [#54955](https://github.com/ClickHouse/ClickHouse/issues/54955). Isso fecha [#53134](https://github.com/ClickHouse/ClickHouse/issues/53134). Isso fecha [#55148](https://github.com/ClickHouse/ClickHouse/issues/55148). Corrigido um bug na função `groupArraySample` - ela usava a mesma semente aleatória quando mais de um estado de agregação era gerado em uma consulta. [#56350](https://github.com/ClickHouse/ClickHouse/pull/56350) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* O arquivo de configuração padrão do servidor ClickHouse passou a ter `access_management` (manipulação de usuários por consultas SQL) e `named_collection_control` (manipulação de named collection por consultas SQL) habilitados para o usuário `default` por padrão. Isso fecha [#56482](https://github.com/ClickHouse/ClickHouse/issues/56482). [#56619](https://github.com/ClickHouse/ClickHouse/pull/56619) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Várias melhorias para RESPECT/IGNORE NULLS. [#57189](https://github.com/ClickHouse/ClickHouse/pull/57189) ([Raúl Marín](https://github.com/Algunenano)).
* Removida a otimização optimize&#95;move&#95;functions&#95;out&#95;of&#95;any. [#57190](https://github.com/ClickHouse/ClickHouse/pull/57190) ([Raúl Marín](https://github.com/Algunenano)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Suporte à avaliação paralela de funções de janela. Corrige [#34688](https://github.com/ClickHouse/ClickHouse/issues/34688). [#39631](https://github.com/ClickHouse/ClickHouse/pull/39631) ([Dmitry Novik](https://github.com/novikd)).
* Aumenta o valor padrão de `max_concurrent_queries` de 100 para 1000. Isso faz sentido quando há um grande número de clientes se conectando, enviando ou recebendo dados lentamente, de modo que o servidor não fica limitado por CPU, ou quando o número de núcleos de CPU é maior que 100. Além disso, habilita o controle de concorrência por padrão e define o número total desejado de threads de processamento de consultas como o dobro do número de núcleos de CPU. Isso melhora o desempenho em cenários com um número muito grande de consultas simultâneas. [#46927](https://github.com/ClickHouse/ClickHouse/pull/46927) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige a filtragem pela condição `IN(...)` para o table engine `Merge`. [#54905](https://github.com/ClickHouse/ClickHouse/pull/54905) ([Nikita Taranov](https://github.com/nickitat)).
* Uma melhoria aplicada quando o cache está cheio e há leituras grandes. [#55158](https://github.com/ClickHouse/ClickHouse/pull/55158) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Adiciona a possibilidade de desabilitar checksum para S3 para evitar leitura excessiva do arquivo de entrada (esse novo comportamento pode ser habilitado com `s3_disable_checksum=true`). [#55559](https://github.com/ClickHouse/ClickHouse/pull/55559) ([Azat Khuzhin](https://github.com/azat)).
* Agora lemos de forma síncrona de tabelas remotas quando os dados estão no page cache (como fazemos com tabelas locais). É mais rápido, não requer sincronização dentro do thread pool, não evita fazer `seek`s no sistema de arquivos local e reduz a espera por CPU. [#55841](https://github.com/ClickHouse/ClickHouse/pull/55841) ([Nikita Taranov](https://github.com/nickitat)).
* ... Este PR dá sequência a [#55929](https://github.com/ClickHouse/ClickHouse/issues/55929) e trará cerca de 30% de aceleração. - reduz a memória reservada - reduz a chamada `resize`. [#55957](https://github.com/ClickHouse/ClickHouse/pull/55957) ([lgbo](https://github.com/lgbo-ustc)).
* Os experimentos de desempenho do **OnTime** no equipamento ICX (CPU Intel Xeon Platinum 8380, 80 núcleos, 160 threads) mostram que essa mudança pode trazer melhorias de **7.4%, 5.9%, 4.7%, 3.0% e 4.6%** no QPS das consultas Q2, Q3, Q4, Q5 e Q6, respectivamente, sem impactar as demais. [#56079](https://github.com/ClickHouse/ClickHouse/pull/56079) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Limita o número de threads ocupadas dentro do query profiler. Se houver mais, elas ignorarão o profiling. [#56105](https://github.com/ClickHouse/ClickHouse/pull/56105) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WindowTransform reduz a quantidade de chamadas de função virtual. [#56120](https://github.com/ClickHouse/ClickHouse/pull/56120) ([Maksim Kita](https://github.com/kitaisreal)).
* Permite pruning recursivo de campos de Tuple em ORC para acelerar a varredura. [#56122](https://github.com/ClickHouse/ClickHouse/pull/56122) ([李扬](https://github.com/taiyang-li)).
* Este pull request adiciona suporte a countRows para o formato de dados Npy. Agora, com a configuração `optimize_count_from_files=1`, consultas como `select count() from file(data.npy)` funcionarão muito mais rápido devido ao cache dos resultados. [#56304](https://github.com/ClickHouse/ClickHouse/pull/56304) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Consultas com agregação e um grande número de streams usarão menos memória durante a construção do plano. [#57074](https://github.com/ClickHouse/ClickHouse/pull/57074) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhora o desempenho da execução de consultas em casos de uso com muitos usuários. [#57106](https://github.com/ClickHouse/ClickHouse/pull/57106) ([Andrej Hoos](https://github.com/adikus)).
* Melhoria trivial no ARRAY JOIN, com reutilização de alguns resultados intermediários. [#57183](https://github.com/ClickHouse/ClickHouse/pull/57183) ([李扬](https://github.com/taiyang-li)).
* Há casos em que o desenrolamento da pilha era lento. [#57221](https://github.com/ClickHouse/ClickHouse/pull/57221) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Agora usamos o pool de leitura padrão para ler do armazenamento externo quando `max_streams = 1`. Isso é benéfico quando os prefetches de leitura estão habilitados. [#57334](https://github.com/ClickHouse/ClickHouse/pull/57334) ([Nikita Taranov](https://github.com/nickitat)).
