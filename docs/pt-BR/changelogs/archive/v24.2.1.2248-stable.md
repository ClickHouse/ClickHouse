<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Valida tipos suspeitos/experimentais em tipos aninhados. Antes, esses tipos (exceto JSON) não eram validados em tipos aninhados como Array/Tuple/Map. [#59385](https://github.com/ClickHouse/ClickHouse/pull/59385) ([Kruglov Pavel](https://github.com/Avogar)).
* A cláusula de ordenação `ORDER BY ALL` (introduzida na v23.12) foi substituída por `ORDER BY *`. A sintaxe anterior era muito propensa a erros em tabelas com uma coluna `all`. [#59450](https://github.com/ClickHouse/ClickHouse/pull/59450) ([Robert Schulze](https://github.com/rschu1ze)).
* Renomeia a configuração `extract_kvp_max_pairs_per_row` para `extract_key_value_pairs_max_pairs_per_row`. O bug (abreviação desnecessária no nome da configuração) foi introduzido em https://github.com/ClickHouse/ClickHouse/pull/43606. Corrige a documentação dessa configuração. [#59683](https://github.com/ClickHouse/ClickHouse/pull/59683) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Renomeia a configuração extract&#95;kvp&#95;max&#95;pairs&#95;per&#95;row para extract&#95;key&#95;value&#95;pairs&#95;max&#95;pairs&#95;per&#95;row. O bug (abreviação desnecessária no nome da configuração) foi introduzido em https://github.com/ClickHouse/ClickHouse/pull/43606. Corrige a documentação dessa configuração. [#59960](https://github.com/ClickHouse/ClickHouse/pull/59960) ([jsc0218](https://github.com/jsc0218)).
* Adiciona uma verificação de consistência para o número de threads e os tamanhos de bloco. [#60138](https://github.com/ClickHouse/ClickHouse/pull/60138) ([Raúl Marín](https://github.com/Algunenano)).



<div id="new-feature">
  #### Novo recurso
</div>

* Adicionado o número máximo de falhas consecutivas de login à cota. [#54737](https://github.com/ClickHouse/ClickHouse/pull/54737) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* Adicionada uma nova sintaxe que permite especificar o usuário definidor em View/Materialized View. Isso permite executar instruções SELECT/inserts a partir de views sem grants explícitos para tabelas subjacentes. [#54901](https://github.com/ClickHouse/ClickHouse/pull/54901) ([pufit](https://github.com/pufit)).

* Implementada a conversão automática de tabelas MergeTree de diferentes tipos para o engine Replicated. Crie um arquivo vazio `convert_to_replicated` no diretório de dados da tabela (`/clickhouse/store/xxx/xxxyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy/`) e a tabela será convertida automaticamente na próxima inicialização do servidor. [#57798](https://github.com/ClickHouse/ClickHouse/pull/57798) ([Kirill](https://github.com/kirillgarbar)).
* Adicionada a função de tabela `mergeTreeIndex`. Ela representa o conteúdo dos arquivos de índice e de marcas das tabelas `MergeTree`. Pode ser usada para introspecção. Sintaxe: `mergeTreeIndex(database, table, [with_marks = true])`, em que `database.table` é uma tabela existente com engine `MergeTree`. [#58140](https://github.com/ClickHouse/ClickHouse/pull/58140) ([Anton Popov](https://github.com/CurtizJ)).
* Adicionada a função `seriesOutliersTukey` para detectar valores atípicos em dados de série usando o algoritmo de cercas de Tukey. [#58632](https://github.com/ClickHouse/ClickHouse/pull/58632) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* Agora o usuário pode especificar a template string diretamente na consulta usando `format_schema_rows_template` como alternativa a `format_template_row`. Fecha [#31363](https://github.com/ClickHouse/ClickHouse/issues/31363). [#59088](https://github.com/ClickHouse/ClickHouse/pull/59088) ([Shaun Struwig](https://github.com/Blargian)).
* Passa a detectar automaticamente o formato do arquivo durante a inferência de esquema se ele for desconhecido nos motores `file/s3/hdfs/url/azureBlobStorage`. Fecha [#50576](https://github.com/ClickHouse/ClickHouse/issues/50576). [#59092](https://github.com/ClickHouse/ClickHouse/pull/59092) ([Kruglov Pavel](https://github.com/Avogar)).
* Adicionada a função `variantType`, que retorna um Enum com o nome do tipo da variante para cada linha. [#59398](https://github.com/ClickHouse/ClickHouse/pull/59398) ([Kruglov Pavel](https://github.com/Avogar)).
* Adicionada a instrução `ALTER TABLE table FORGET PARTITION partition`, que remove nós do ZooKeeper relacionados a uma partição vazia. [#59507](https://github.com/ClickHouse/ClickHouse/pull/59507) ([Sergei Trifonov](https://github.com/serxa)).
* Suporte a arquivo de credenciais JWT para o table engine NATS. [#59543](https://github.com/ClickHouse/ClickHouse/pull/59543) ([Nickolaj Jepsen](https://github.com/nickolaj-jepsen)).
* Adicionada a nova função de agregação `groupArrayIntersect`. Continuação de: [#49862](https://github.com/ClickHouse/ClickHouse/issues/49862). [#59598](https://github.com/ClickHouse/ClickHouse/pull/59598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Implementada a tabela `system.dns&#95;cache`, que pode ser útil para depuração de problemas de DNS. [#59856](https://github.com/ClickHouse/ClickHouse/pull/59856) ([Kirill Nikiforov](https://github.com/allmazz)).

Em versões anteriores, `LZ4HC(2)` e valores menores eram equivalentes a `LZ4HC(3)`. Autor: [Cyan4973](https://github.com/Cyan4973). [#60090](https://github.com/ClickHouse/ClickHouse/pull/60090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Implementada a tabela system.dns&#95;cache, que pode ser útil para depurar problemas de DNS. Nova configuração do servidor dns&#95;cache&#95;max&#95;size. [#60257](https://github.com/ClickHouse/ClickHouse/pull/60257) ([Kirill Nikiforov](https://github.com/allmazz)).
* Adicionado suporte à versão com um único argumento para a função de tabela merge, como em `merge(['db_name', ] 'tables_regexp')`. [#60372](https://github.com/ClickHouse/ClickHouse/pull/60372) ([豪肥肥](https://github.com/HowePa)).
* Adicionada uma nova sintaxe que permite especificar o usuário definidor em View/Materialized View. Isso permite executar instruções SELECT/INSERT a partir de views sem privilégios explícitos para as tabelas subjacentes. [#60439](https://github.com/ClickHouse/ClickHouse/pull/60439) ([pufit](https://github.com/pufit)).



<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Elimina os agregadores min/max/any/anyLast das chaves de GROUP BY na seção SELECT. [#52230](https://github.com/ClickHouse/ClickHouse/pull/52230) ([JackyWoo](https://github.com/JackyWoo)).
* Funções de distância vetorizadas usadas na busca vetorial. [#58866](https://github.com/ClickHouse/ClickHouse/pull/58866) ([Robert Schulze](https://github.com/rschu1ze)).
* Continua otimizando erros de predição de desvio na função if quando o tipo de resultado é float*/decimal*/int*, em continuação a https://github.com/ClickHouse/ClickHouse/pull/57885. [#59148](https://github.com/ClickHouse/ClickHouse/pull/59148) ([李扬](https://github.com/taiyang-li)).
* Otimiza a função if quando o tipo de entrada é map, com ganho de velocidade de ~10x. [#59413](https://github.com/ClickHouse/ClickHouse/pull/59413) ([李扬](https://github.com/taiyang-li)).
* Melhora o desempenho do tipo Int8 com a implementação de strict aliasing. [#59485](https://github.com/ClickHouse/ClickHouse/pull/59485) ([Raúl Marín](https://github.com/Algunenano)).
* Otimiza condicionalmente o desempenho de sum/avg para tipos bigint e big decimal, reduzindo erros de predição de desvio. [#59504](https://github.com/ClickHouse/ClickHouse/pull/59504) ([李扬](https://github.com/taiyang-li)).
* Melhora o desempenho de instruções SELECT com mutações ativas. [#59531](https://github.com/ClickHouse/ClickHouse/pull/59531) ([Azat Khuzhin](https://github.com/azat)).
* Função `isNotNull` otimizada com AVX2. [#59621](https://github.com/ClickHouse/ClickHouse/pull/59621) ([李扬](https://github.com/taiyang-li)).
* Reutiliza o resultado de `FunctionFactory::instance().get("isNotNull", context)` e `FunctionFactory::instance().get("assumeNotNull", context)`. Garante que isso seja chamado apenas uma vez durante o ciclo de vida de `FunctionCoalesce`. [#59627](https://github.com/ClickHouse/ClickHouse/pull/59627) ([李扬](https://github.com/taiyang-li)).
* Melhora o desempenho de ASOF JOIN para dados ordenados ou quase ordenados. [#59731](https://github.com/ClickHouse/ClickHouse/pull/59731) ([Maksim Kita](https://github.com/kitaisreal)).
* A chave primária usará menos memória. [#60049](https://github.com/ClickHouse/ClickHouse/pull/60049) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhora o uso de memória da chave primária e de algumas outras operações. [#60050](https://github.com/ClickHouse/ClickHouse/pull/60050) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* As chaves primárias das tabelas serão carregadas na memória de forma lazy no primeiro acesso. Isso é controlado pela nova configuração de MergeTree `primary_key_lazy_load`, ativada por padrão. Isso traz várias vantagens: - elas não serão carregadas para tabelas que não são usadas; - se não houver memória suficiente, uma exceção será lançada no primeiro uso, em vez de na inicialização do servidor. Isso também traz várias desvantagens: - a latência do carregamento da chave primária será paga na primeira consulta, em vez de antes de aceitar conexões; isso, em teoria, pode introduzir um problema de thundering herd. Isso fecha [#11188](https://github.com/ClickHouse/ClickHouse/issues/11188). [#60093](https://github.com/ClickHouse/ClickHouse/pull/60093) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Função vetorizada `dotProduct`, útil para busca vetorial. [#60202](https://github.com/ClickHouse/ClickHouse/pull/60202) ([Robert Schulze](https://github.com/rschu1ze)).
* Como mostrado na Fig. 1, a substituição de &quot;&amp;&amp;&quot; por &quot;&amp;&quot; pode gerar código SIMD. ![imagem](https://github.com/ClickHouse/ClickHouse/assets/26588299/a5a72ac4-6dc6-4d52-835a-4f512e55f0b9) Fig. 1. [#60498](https://github.com/ClickHouse/ClickHouse/pull/60498) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).

* Adicionado suporte a view parametrizada com analisador, para não analisar `create parameterized view`. A lógica existente de view parametrizada foi refatorada para também não analisar `create parameterized view`. [#54211](https://github.com/ClickHouse/ClickHouse/pull/54211) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* Não considere a parte de dados como corrompida se a projeção estiver corrompida. Fecha [#56593](https://github.com/ClickHouse/ClickHouse/issues/56593). [#56864](https://github.com/ClickHouse/ClickHouse/pull/56864) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Adicionado suporte a curto-circuito para a função `dictGetOrDefault`. Fecha [#52098](https://github.com/ClickHouse/ClickHouse/issues/52098). [#57767](https://github.com/ClickHouse/ClickHouse/pull/57767) ([jsc0218](https://github.com/jsc0218)).
* Executar `ALTER COLUMN MATERIALIZE` em uma coluna com expressão `DEFAULT` ou `MATERIALIZED` agora grava os valores corretos: o valor padrão para partes existentes com valor padrão, ou o valor não padrão para partes existentes com valor não padrão. Antes, o valor padrão era gravado em todas as partes existentes. [#58023](https://github.com/ClickHouse/ClickHouse/pull/58023) ([Duc Canh Le](https://github.com/canhld94)).
* Ativada uma lógica de backoff (por exemplo, exponencial). Isso permitirá reduzir o uso de CPU, o uso de memória e o tamanho dos arquivos de log. [#58036](https://github.com/ClickHouse/ClickHouse/pull/58036) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Adicionada uma melhoria na contagem de InitialQuery. [#58195](https://github.com/ClickHouse/ClickHouse/pull/58195) ([Unalian](https://github.com/Unalian)).
* Adicionado suporte a argumentos posicionais negativos. Fecha [#57736](https://github.com/ClickHouse/ClickHouse/issues/57736). [#58292](https://github.com/ClickHouse/ClickHouse/pull/58292) ([flynn](https://github.com/ucasfl)).
* Implementado ajuste automático para timeouts de inserção assíncrona. As seguintes configurações foram introduzidas: async&#95;insert&#95;poll&#95;timeout&#95;ms, async&#95;insert&#95;use&#95;adaptive&#95;busy&#95;timeout, async&#95;insert&#95;busy&#95;timeout&#95;min&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;max&#95;ms, async&#95;insert&#95;busy&#95;timeout&#95;increase&#95;rate, async&#95;insert&#95;busy&#95;timeout&#95;decrease&#95;rate. [#58486](https://github.com/ClickHouse/ClickHouse/pull/58486) ([Julia Kartseva](https://github.com/jkartseva)).
* Permitida a definição de `volume_priority` em `storage_configuration`. [#58533](https://github.com/ClickHouse/ClickHouse/pull/58533) ([Andrey Zvonov](https://github.com/zvonand)).
* Adicionado suporte ao tipo Date32 no codec T64. [#58738](https://github.com/ClickHouse/ClickHouse/pull/58738) ([Hongbin Ma (Mahone)](https://github.com/binmahone)).
* Adicionado suporte a `LEFT JOIN`, `ALL INNER JOIN` e subconsultas simples para réplicas paralelas (somente com o analisador). A nova configuração `parallel_replicas_prefer_local_join` escolhe a execução local de `JOIN` (padrão) em vez de `GLOBAL JOIN`. Todas as tabelas devem existir em cada réplica de `cluster_for_parallel_replicas`. As novas configurações `min_external_table_block_size_rows` e `min_external_table_block_size_bytes` são usadas para agrupar pequenos blocos enviados para tabelas temporárias (somente com o analisador). [#58916](https://github.com/ClickHouse/ClickHouse/pull/58916) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Permitidas vírgulas finais em tipos com vários itens. [#59119](https://github.com/ClickHouse/ClickHouse/pull/59119) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* Permite processamento paralelo e processamento distribuído para o mecanismo de tabela `S3Queue`. Para usar processamento distribuído, use a configuração `s3queue_total_shards_num` (o padrão é `1`). Antes, a configuração `s3queue_processing_threads_num` não era permitida no modo de processamento Ordered; agora, é permitida. Aviso: as configurações `s3queue_processing_threads_num` (threads de processamento por shard) e `s3queue_total_shards_num` no modo ordered alteram a forma como os metadados são armazenados (fazendo com que o número de nós `max_processed_file` seja igual a `s3queue_processing_threads_num * s3queue_total_shards_num`), portanto elas devem ser iguais em todos os shards e não podem ser alteradas depois que pelo menos um shard for criado. [#59167](https://github.com/ClickHouse/ClickHouse/pull/59167) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Permite a criação concorrente de tabelas em `DatabaseReplicated` durante `recoverLostReplica`. [#59277](https://github.com/ClickHouse/ClickHouse/pull/59277) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* As configurações do mecanismo de tabela Distributed agora podem ser especificadas no arquivo de configuração do servidor (de forma semelhante às configurações do MergeTree), por exemplo, `<distributed> <flush_on_detach>false</flush_on_detach> </distributed>`. [#59291](https://github.com/ClickHouse/ClickHouse/pull/59291) ([Azat Khuzhin](https://github.com/azat)).
* Usa o MergeTree como mecanismo de tabela padrão. Isso melhora bastante a usabilidade e a aproxima da experiência do ClickHouse Cloud. [#59316](https://github.com/ClickHouse/ClickHouse/pull/59316) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Passa a tentar novamente em caso de desconexões e sessões expiradas ao ler `system.zookeeper`. Isso é útil ao ler muitas linhas da tabela `system.zookeeper`, especialmente na presença de desconexões induzidas por falha. [#59388](https://github.com/ClickHouse/ClickHouse/pull/59388) ([Alexander Gololobov](https://github.com/davenger)).
* Não interpreta números com zeros à esquerda como octais quando `input_format_values_interpret_expressions=0`. [#59403](https://github.com/ClickHouse/ClickHouse/pull/59403) ([Joanna Hulboj](https://github.com/jh0x)).
* Na inicialização e sempre que os arquivos de configuração são alterados, o ClickHouse atualiza os limites rígidos de memória do seu rastreador total de memória. Esses limites são calculados com base em várias configurações do servidor e nos limites de cgroups (no Linux). Antes, `/sys/fs/cgroup/memory.max` (para cgroups v2) estava fixado no código. Como resultado, os limites de memória do cgroup v2 configurados para grupos aninhados (hierarquias), por exemplo `/sys/fs/cgroup/my/nested/group/memory.max`, eram ignorados. Isso foi corrigido. O comportamento dos limites de memória v1 permanece inalterado. [#59435](https://github.com/ClickHouse/ClickHouse/pull/59435) ([Robert Schulze](https://github.com/rschu1ze)).
* Novos profile events foram adicionados para observar o tempo gasto no cálculo de PK/projeções/índices secundários durante `INSERT`-s. [#59436](https://github.com/ClickHouse/ClickHouse/pull/59436) ([Nikita Taranov](https://github.com/nickitat)).
* Permite definir um ponto inicial para o S3Queue com o modo Ordered no momento da criação, usando a configuração `s3queue_last_processed_path`. [#59446](https://github.com/ClickHouse/ClickHouse/pull/59446) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Melhoria no Keeper: armazena em cache na memória apenas uma determinada quantidade de logs, controlada por `latest_logs_cache_size_threshold` e `commit_logs_cache_size_threshold`. [#59460](https://github.com/ClickHouse/ClickHouse/pull/59460) ([Antonio Andelic](https://github.com/antonio2368)).
* Comentários para tabelas de sistema agora também estão disponíveis em `system.tables` no `clickhouse-local`. [#59493](https://github.com/ClickHouse/ClickHouse/pull/59493) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Não infere floats em notação exponencial por padrão. Adiciona a configuração `input_format_try_infer_exponent_floats`, que restaura o comportamento anterior (desabilitada por padrão). Fecha [#59476](https://github.com/ClickHouse/ClickHouse/issues/59476). [#59500](https://github.com/ClickHouse/ClickHouse/pull/59500) ([Kruglov Pavel](https://github.com/Avogar)).
* Permitir que operações ALTER sejam envolvidas por parênteses. A emissão de parênteses pode ser controlada pela config `format_alter_operations_with_parentheses`. Por padrão, em consultas formatadas, os parênteses são emitidos, pois armazenamos as operações ALTER formatadas em alguns lugares como metadata (por exemplo, mutações). A nova sintaxe deixa mais claras algumas consultas em que operações ALTER terminam com uma lista. Por exemplo, `ALTER TABLE x MODIFY TTL date GROUP BY a, b, DROP COLUMN c` não pode ser analisada corretamente com a sintaxe antiga. Na nova sintaxe, a consulta `ALTER TABLE x (MODIFY TTL date GROUP BY a, b), (DROP COLUMN c)` fica clara. Versões antigas não conseguem ler a nova sintaxe; portanto, usá-la pode causar problemas se versões mais novas e mais antigas do ClickHouse estiverem misturadas em um único cluster. [#59532](https://github.com/ClickHouse/ClickHouse/pull/59532) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* O valor padrão anterior de `async_insert_max_data_size`, igual a 1 MB, mostrou-se pequeno demais. O novo valor passa a ser 10 MiB. [#59536](https://github.com/ClickHouse/ClickHouse/pull/59536) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Antes, o resultado inteiro era acumulado na memória e retornado como um único fragmento grande. Essa mudança deve ajudar a reduzir o consumo de memória ao ler muitas linhas de `system.zookeeper`, permitir mostrar o progresso intermediário (quantas linhas foram lidas até agora) e evitar timeout de connection quando o conjunto de resultados for grande. [#59545](https://github.com/ClickHouse/ClickHouse/pull/59545) ([Alexander Gololobov](https://github.com/davenger)).
* Agora o dashboard entende tanto o estado comprimido quanto o descomprimido do #hash das URLs (compatibilidade retroativa). Continuação de [#59124](https://github.com/ClickHouse/ClickHouse/issues/59124). [#59548](https://github.com/ClickHouse/ClickHouse/pull/59548) ([Amos Bird](https://github.com/amosbird)).
* Intel QPL (usado pelo codec `DEFLATE_QPL`) foi atualizado da v1.3.1 para a v1.4.0. Também foi corrigido um bug no mecanismo de polling de timeout, pois observamos que, em alguns casos, o timeout não funcionava corretamente; se isso acontecesse, IAA e CPU poderiam processar o buffer de forma concorrente. Por enquanto, é melhor garantir que o status do codec IAA não seja QPL&#95;STS&#95;BEING&#95;PROCESSED e então fazer fallback para o codec de software. [#59551](https://github.com/ClickHouse/ClickHouse/pull/59551) ([jasperzhu](https://github.com/jinjunzh)).

* Não mostrar um aviso sobre a versão do servidor no ClickHouse Cloud, porque o ClickHouse Cloud faz upgrades contínuos automaticamente. [#59657](https://github.com/ClickHouse/ClickHouse/pull/59657) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Verificar overflow de pilha em parsers mesmo que o usuário tenha configurado incorretamente a setting `max_parser_depth` com um valor muito alto. Isso fecha [#59622](https://github.com/ClickHouse/ClickHouse/issues/59622). [#59697](https://github.com/ClickHouse/ClickHouse/pull/59697) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* Adicionadas as configurações `split_parts_ranges_into_intersecting_and_non_intersecting_final` e `split_intersecting_parts_ranges_into_layers_final`. Essas configurações são necessárias para desativar otimizações em queries com `FINAL` e devem ser usadas apenas para depuração.
