<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* As funções `greatest` e `least` agora ignoram valores de entrada NULL, mas antes retornavam NULL se um dos argumentos fosse NULL. Por exemplo, `SELECT greatest(1, 2, NULL)` agora retorna 2. Isso torna o comportamento compatível com o PostgreSQL. [#65519](https://github.com/ClickHouse/ClickHouse/pull/65519) ([kevinyhzou](https://github.com/KevinyhZou)).
* A integração legada com o MongoDB baseada no driver Poco foi removida. A configuração do servidor `use_legacy_mongodb_integration` está obsoleta e não tem mais efeito. [#71997](https://github.com/ClickHouse/ClickHouse/pull/71997) ([Kirill Nikiforov](https://github.com/allmazz)).

* Implementado o comando SYSTEM LOAD PRIMARY KEY para carregar os índices primários de todas as partes de uma tabela especificada, ou de todas as tabelas caso nenhuma seja especificada. Isso pode ser útil para benchmarking e para evitar latência adicional durante a execução de consultas. [#67733](https://github.com/ClickHouse/ClickHouse/pull/67733) ([ZAWA_ll](https://github.com/Zawa-ll)).
* O formato de armazenamento de dados [Iceberg](https://iceberg.apache.org/spec/#file-system-operations) oferece ao usuário amplas opções para modificar o esquema de sua tabela. Neste pull request, foi implementada a leitura de tabelas no formato Iceberg em cenários onde a ordem das colunas, os nomes das colunas e extensões de tipos simples foram alterados. * Adicionada a função `toUnixTimestamp64Second`, que converte um `DateTime64` em um valor `Int64` com precisão fixa em segundos, possibilitando o retorno de valores negativos para datas anteriores a 00:00:00 UTC de quinta-feira, 1º de janeiro de 1970. * Adicionada a nova configuração `enforce_index_structure_match_on_partition_manipulation` para permitir a operação de attach quando as projeções e os índices secundários da tabela de origem forem um subconjunto daqueles presentes na tabela de destino. Fecha [#70602](https://github.com/ClickHouse/ClickHouse/issues/70602). [#70603](https://github.com/ClickHouse/ClickHouse/pull/70603) ([zwy991114](https://github.com/zwy991114)).
* A saída da função `cast` difere do Apache Spark, o que causa divergências no projeto gluten; consulte https://github.com/apache/incubator-gluten/issues/7602. Este PR adiciona suporte ao formato de saída de texto do Spark, desabilitado por padrão. [#70957](https://github.com/ClickHouse/ClickHouse/pull/70957) ([zhanglistar](https://github.com/zhanglistar)).
* Este PR introduz a nova configuração `allow_experimental_reverse_key`, que habilita suporte à ordem de classificação decrescente nas chaves de ordenação do MergeTree. Isso é útil para análise de séries temporais, especialmente em consultas TopN. Exemplo de uso: ```sql CREATE TABLE example ( time DateTime, key Int32, value String ) ENGINE = MergeTree ORDER BY (time DESC, key); -- Ordem decrescente para o campo 'time' SETTINGS allow_experimental_reverse_key = 1;. [#71095](https://github.com/ClickHouse/ClickHouse/pull/71095) ([Amos Bird](https://github.com/amosbird)).
* Integração com o Iceberg REST Catalog. [#71542](https://github.com/ClickHouse/ClickHouse/pull/71542) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Adicionada uma opção para selecionar qual lado do join atuará como tabela interna (build) no plano de consulta. Isso é controlado por `query_plan_join_swap_table`, que pode ser definido como `auto`. Nesse modo, o ClickHouse tentará escolher a tabela com o menor número de linhas. [#71577](https://github.com/ClickHouse/ClickHouse/pull/71577) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Adicionada sintaxe ALTER USER {ADD|MODIFY|DROP SETTING}, ALTER USER {ADD|DROP PROFILE}, e o equivalente para ALTER ROLE e ALTER PROFILE. [#72050](https://github.com/ClickHouse/ClickHouse/pull/72050) ([pufit](https://github.com/pufit)).
* Adicionada a função `arrayPrAUC`, que calcula a AUC (Área Sob a Curva) para a curva de Precisão-Recall. [#72073](https://github.com/ClickHouse/ClickHouse/pull/72073) ([Emmanuel](https://github.com/emmanuelsdias)).
* Adicionado cache para o índice primário de tabelas `MergeTree` (pode ser habilitado pela configuração de tabela `use_primary_key_cache`). Se o carregamento lazy e o cache estiverem habilitados para o índice primário, ele será carregado no cache sob demanda (semelhante ao cache de marks), em vez de ser mantido permanentemente na memória. Adicionado prewarm do índice primário em inserções, merges e fetches de partes de dados, bem como na reinicialização da tabela (pode ser habilitado pela configuração `prewarm_primary_key_cache`). [#72102](https://github.com/ClickHouse/ClickHouse/pull/72102) ([Anton Popov](https://github.com/CurtizJ)).
* Retroportado em [#73593](https://github.com/ClickHouse/ClickHouse/issues/73593): os comandos `SELECT` e `VIEW` agora suportam aliases, por exemplo, `SELECT b FROM (SELECT number, number*2 FROM numbers(2)) AS x (a, b);`. Isso permite que a consulta 15 do TPC-H seja executada sem modificações. [#72480](https://github.com/ClickHouse/ClickHouse/pull/72480) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Adicionada a função `indexOfAssumeSorted` para tipos de array. Otimiza a busca em arrays ordenados em ordem não decrescente. [#72517](https://github.com/ClickHouse/ClickHouse/pull/72517) ([Eric Kurbanov](https://github.com/erickurbanov)).
* Permite o uso de um delimitador como segundo argumento opcional da função de agregação `groupConcat`. [#72540](https://github.com/ClickHouse/ClickHouse/pull/72540) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Nova configuração `http_response_headers`, que permite personalizar os cabeçalhos de resposta HTTP. Por exemplo, é possível instruir o navegador a renderizar uma imagem armazenada no banco de dados. Fecha [#59620](https://github.com/ClickHouse/ClickHouse/issues/59620). [#72656](https://github.com/ClickHouse/ClickHouse/pull/72656) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionada a função `fromUnixTimestamp64Second`, que converte um valor Unix timestamp Int64 em um DateTime64. [#73146](https://github.com/ClickHouse/ClickHouse/pull/73146) ([Robert Schulze](https://github.com/rschu1ze)).

<div id="performance-improvement">
  #### Melhoria de Desempenho
</div>

* O uso de memória do `clickhouse disks remove --recursive` foi reduzido para disks de armazenamento de objetos. [#67323](https://github.com/ClickHouse/ClickHouse/pull/67323) ([Kirill](https://github.com/kirillgarbar)).
* Habilitada a compilação JIT para mais expressões: abs/bitCount/sign/modulo/pmod/isNull/isNotNull/assumeNotNull/to(U)Int*/toFloat*, funções de comparação (=, <, >, >=, <=), funções lógicas (and, or). [#70598](https://github.com/ClickHouse/ClickHouse/pull/70598) ([李扬](https://github.com/taiyang-li)).
* Agora o algoritmo `parallel_hash` será utilizado (quando aplicável) ao definir a configuração `join_algorithm` como `default`. As duas alternativas anteriores (`direct` e `hash`) ainda são consideradas quando `parallel_hash` não puder ser usado. [#70788](https://github.com/ClickHouse/ClickHouse/pull/70788) ([Nikita Taranov](https://github.com/nickitat)).
* Adicionada opção para extrair expressões comuns das cláusulas `WHERE` e `ON`, a fim de reduzir o número de tabelas hash utilizadas durante as junções. Pode ser habilitada com `optimize_extract_common_expressions = 1`. [#71537](https://github.com/ClickHouse/ClickHouse/pull/71537) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Permite o uso de índices em `SELECT` com `LowCardinality(String)`. [#71598](https://github.com/ClickHouse/ClickHouse/pull/71598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Durante a execução de consultas com réplicas paralelas e plano local habilitado, a análise de índice é ignorada nos workers. O coordinator escolherá os intervalos a serem lidos pelos workers com base na análise de índice realizada em seu lado (no initiator da consulta). [#72109](https://github.com/ClickHouse/ClickHouse/pull/72109) ([Igor Nikonov](https://github.com/devcrafter)).
* Restaurada a otimização para leitura de subcolunas de uma única coluna em compact parts, proveniente de https://github.com/ClickHouse/ClickHouse/pull/57631. Havia sido removida acidentalmente. [#72285](https://github.com/ClickHouse/ClickHouse/pull/72285) ([Pavel Kruglov](https://github.com/Avogar)).
* Acelerada a ordenação de colunas `LowCardinality(String)` por meio da desvirtualização de chamadas no comparador. [#72337](https://github.com/ClickHouse/ClickHouse/pull/72337) ([Alexander Gololobov](https://github.com/davenger)).
* Otimizada a função argMin/Max para alguns tipos de dados simples. [#72350](https://github.com/ClickHouse/ClickHouse/pull/72350) ([alesapin](https://github.com/alesapin)).
* Otimizado o uso de locks compartilhados no memory tracker para reduzir a contenção de locks. [#72375](https://github.com/ClickHouse/ClickHouse/pull/72375) ([Jiebin Sun](https://github.com/jiebinn)).
* Adicionada uma nova configuração, `use_async_executor_for_materialized_views`. Utiliza execução assíncrona e potencialmente multithread de consultas de visão materializada, podendo acelerar o processamento de views durante INSERT, mas também consumindo mais memória. [#72497](https://github.com/ClickHouse/ClickHouse/pull/72497) ([alesapin](https://github.com/alesapin)).
* Os valores padrão das configurações `max_size_to_preallocate_for_aggregation` e `max_size_to_preallocate_for_joins` foram aumentados para `10^12`, de modo que a otimização será aplicada em mais casos. [#72555](https://github.com/ClickHouse/ClickHouse/pull/72555) ([Nikita Taranov](https://github.com/nickitat)).
* Melhorado o desempenho da desserialização de estados de aggregate functions (no tipo de dados `AggregateFunction` e em consultas distribuídas). Leve melhoria no desempenho do parsing do formato `RowBinary`. [#72818](https://github.com/ClickHouse/ClickHouse/pull/72818) ([Anton Popov](https://github.com/CurtizJ)).
