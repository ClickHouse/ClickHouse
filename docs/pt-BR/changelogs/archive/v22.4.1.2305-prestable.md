<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* A função `yandexConsistentHash` (algoritmo de hash consistente de Konstantin &quot;kostik&quot; Oblakov) foi renomeada para `kostikConsistentHash`. O nome antigo foi mantido como alias por compatibilidade. Embora essa alteração seja retrocompatível, podemos remover o alias em lançamentos posteriores, por isso é recomendável atualizar o uso dessa função em seus aplicativos. [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Não permitir SETTINGS após FORMAT em consultas INSERT (há a configuração de compatibilidade `allow_settings_after_format_in_insert` para aceitar essas consultas, mas ela fica desativada por padrão). [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* Alterado o caminho com hash dos arquivos de cache. [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Acelera o processo de carregamento de partes do MergeTree para reduzir o tempo de inicialização do clickhouse-server. Com essa melhoria, o clickhouse-server conseguiu diminuir o tempo de inicialização de 75 minutos para 20 segundos, com 700 mil partes do MergeTree. [#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* Os tamanhos das tabelas hash usadas durante a agregação agora são coletados e utilizados em consultas posteriores para evitar o redimensionamento dessas tabelas hash. [#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* Várias alterações para melhorar o desempenho do ASOF join (de 1,2x a 1,6x mais rápido). Também adiciona suporte ao uso de inteiros grandes. [#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* O mecanismo de armazenamento URL agora baixa vários fragmentos em paralelo se o endpoint oferecer suporte a HTTP Range. Duas configurações adicionais foram incluídas, `max_download_threads` e `max_download_buffer_size`, que controlam o número máximo de threads que uma única consulta pode usar para baixar o arquivo e o número máximo de bytes que cada thread pode processar. [#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* Paralelização do upload multipartido para armazenamento S3. [#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* Melhora o desempenho do ASOF JOIN se a chave for um inteiro nativo. [#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* Uma nova otimização do plano de consulta. Avalia funções após `ORDER BY` quando possível. Por exemplo, para a consulta `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5`, a função `sipHash64` seria avaliada após `ORDER BY` e `LIMIT`, o que proporciona uma aceleração de ~20x. [#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* Reduz o escopo do mutex no problema relacionado a setenv LIBHDFS3&#95;CONF [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292). [#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* Melhora o desempenho da função `hasAll` usando especializações para SSE e AVX2. Autor: @youennL-cs. [#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * A instrução explain de GLOBAL JOIN entre duas tabelas distribuídas pode ser até 100x mais rápida: explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2 otimizações: - Otimiza consultas triviais de contagem no Hive - Acelera consultas no Hive por meio de caching dos metadados de arquivos do Hive. [#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
