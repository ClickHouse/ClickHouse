<div id="backward-incompatible-change">
  #### Backward Incompatible Change
</div>

* Corrige formatação inconsistente causada por uma substituição incorreta de aliases no formatador. Fecha [#82833](https://github.com/ClickHouse/ClickHouse/issues/82833). Fecha [#82832](https://github.com/ClickHouse/ClickHouse/issues/82832). Fecha [#68296](https://github.com/ClickHouse/ClickHouse/issues/68296). Esta mudança é potencialmente incompatível com versões anteriores: quando o analyzer está desabilitado, certas consultas CREATE VIEW com IN referenciando um alias não podem ser processadas. Para evitar a incompatibilidade, habilite o analyzer (habilitado por padrão desde a versão 24.3). [#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Os codecs `DEFLATE_QPL` e `ZSTD_QAT` foram removidos. Recomenda-se converter os dados existentes compactados com `DEFLATE_QPL` ou `ZSTD_QAT` para outro codec antes de realizar o upgrade. Note que, para utilizar esses codecs, as configurações `enable_deflate_qpl_codec` e `enable_zstd_qat_codec` precisavam estar habilitadas. [#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze)).
* Corrige o debugging de UDF habilitando a captura do stderr em `system.query_log.exception`. Anteriormente, o stderr de UDF era registrado apenas em arquivos e não ficava exposto nos logs de consulta, tornando o debugging inviável. Agora o stderr dispara exceções por padrão e é totalmente acumulado (até 1 MB) antes de ser lançado, de modo que tracebacks completos do Python e mensagens de erro aparecem em `system.query_log.exception` para troubleshooting eficaz. [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
* Uma lista de colunas vazia na cláusula `JOIN USING ()` agora é considerada um erro de sintaxe. Anteriormente, o comportamento esperado era retornar `INVALID_JOIN_ON_EXPRESSION` durante a execução da consulta. Em alguns casos, como ao realizar join com o storage `Join`, isso resultava em `LOGICAL_ERROR`. Fecha [#82502](https://github.com/ClickHouse/ClickHouse/issues/82502). [#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Habilita shared data avançado para JSON por padrão. Após essa mudança, o downgrade para versões anteriores à 25.8 não será possível, pois essas versões não conseguirão ler as novas partes de dados com coluna JSON. Para upgrades seguros, recomenda-se definir a configuração `compatibility` para a versão anterior ou definir as configurações MergeTree `dynamic_serialization_version='v2', object_serialization_version='v2'`. [#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar)).
* Passa a usar correspondência parcial para SKIP REGEXP no tipo JSON por padrão. Fecha [#79250](https://github.com/ClickHouse/ClickHouse/issues/79250). [#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar)).
* Reverte &quot;Allow INSERT into simple ALIAS columns&quot; (Reverte ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154)). Não funciona com formatos personalizados e não está protegido por uma configuração. [#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat)).
* Configuração para lançar erro quando o catálogo do data lake não tiver acesso ao armazenamento de objetos. [#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* O database engine `Lazy` foi removido e não está mais disponível. Fecha [#91231](https://github.com/ClickHouse/ClickHouse/issues/91231). [#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Remove o modo `transposed_with_wide_view` do `metric_log` — inutilizável devido a um bug. Não é mais possível definir `system.metric_log` com esse modo. Reverte parcialmente [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412). [#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* O CPU scheduling para workloads agora é preemptivo por padrão. Consulte a server setting `cpu_slot_preemption`. [#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa)).
* Aplica escape nos nomes de arquivos de índice para evitar partes corrompidas. Com essa mudança, o ClickHouse falhará ao carregar índices cujos nomes contenham caracteres não-ASCII criados por versões anteriores. Para contornar isso, utilize a configuração do merge tree `escape_index_filenames`. [#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano)).
* As configurações de formato `exact_rows_before_limit`, `rows_before_aggregation`, `cross_to_inner_join_rewrite`, `regexp_dict_allow_hyperscan`, `regexp_dict_flag_case_insensitive`, `regexp_dict_flag_dotall` e `dictionary_use_async_executor` foram convertidas em configurações regulares (não de formato). Trata-se de uma mudança puramente interna sem efeitos visíveis ao usuário, exceto no caso (improvável) de alguma dessas configurações ter sido especificada nas definições de table engine Iceberg, DeltaLake, Kafka, S3, S3Queue, Azure, Hive, RabbitMQ, Set, FileLog ou NATS. Nesses casos, essas configurações eram anteriormente ignoradas; agora tais definições lançam um erro. [#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze)).
* As funções `joinGet/joinGetOrNull` agora exigem privilégios de `SELECT` na tabela Join subjacente. Após essa mudança, a execução de `joinGet('db.table', 'column', key)` requer que o usuário possua privilégio de `SELECT` tanto nas colunas de chave definidas na tabela Join quanto na coluna de atributo recuperada. Consultas sem esses privilégios falharão com `ACCESS_DENIED`. Para migrar, conceda as permissões necessárias usando `GRANT SELECT ON db.join_table TO user` para acesso completo à tabela, ou `GRANT SELECT(key_col, attr_col) ON db.join_table TO user` para acesso em nível de coluna. Essa mudança afeta todos os usuários e aplicações que dependem de `joinGet`/`joinGetOrNull` nos quais grants explícitos de `SELECT` não estavam configurados anteriormente. [#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Passa a verificar `SHOW COLUMNS` para consultas `CREATE TABLE ... AS ...`. Anteriormente, verificava `SHOW TABLES`, que é um grant incorreto para esse tipo de verificação de permissão. [#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit)).

* A desduplicação de insert assíncrono agora funciona com visões materializadas dependentes. Quando ocorre uma colisão por block&#95;id, o bloco original é filtrado para remover as linhas associadas ao block&#95;id, e as linhas restantes são transformadas com todas as consultas SELECT relevantes das visões materializadas; isso reconstrói o bloco original sem as linhas conflitantes. [#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* Adicionada a capacidade de o clickhouse client substituir o TLS SNI ao se conectar ao servidor. [#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).

* Nova tabela de sistema zookeeper&#95;info. Corrige [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014). [#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* Implementa o FunctionVariantAdaptor para oferecer suporte ao tipo Variant em funções. [#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* Adiciona uma métrica `ClickHouse_Info` ao endpoint `/metrics` do Prometheus, contendo principalmente informações de versão, para que seja possível criar gráficos que acompanhem informações detalhadas de versão ao longo do tempo. [#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* Introduz um novo comando de quatro letras, `rcfg`, para o Keeper, que permite alterar a configuração do cluster. Esse comando oferece possibilidades mais amplas de alteração da configuração do que a solicitação padrão `reconfigure`. O comando recebe uma string `json` como argumento. O conjunto completo de bytes enviados para a interface TCP deve ter esta aparência: `rcfg{json_string_length_big_endian}{json_string}`. Alguns exemplos do comando podem ser assim: `{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`. [#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* Adiciona a função `reverseBySeparator`, que inverte a ordem das substrings em uma string separada por um separador especificado. Fecha [#91463](https://github.com/ClickHouse/ClickHouse/issues/91463). [#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* Introduz uma nova sintaxe e um novo framework para simplificar e estender o recurso de índice de projeção. Isso dá continuidade a https://github.com/ClickHouse/ClickHouse/pull/81021. [#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* Adiciona suporte ao REST catalog do Paimon, dando continuidade a https://github.com/ClickHouse/ClickHouse/pull/84423. [#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* Adiciona a nova configuração `max_insert_block_size_bytes`, que controla com mais precisão a formação dos blocos inseridos. [#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* É possível executar consultas DDL com a cláusula `ON CLUSTER` para um banco de dados Replicated se a configuração `ignore_on_cluster_for_replicated_database` estiver habilitada. Nesse caso, o nome do cluster será ignorado. [#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* Implementa a função `mergeTreeAnalyzeIndex()`. [#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* Adiciona a nova configuração `use_primary_key`. Defina-a como `false` para desabilitar o Granule pruning com base na chave primária. [#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Função de tabela `icebergLocalCluster`. [#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* O prewhere para data lakes e o prewhere em múltiplos estágios no leitor de Parquet v3 resolvem [#89101](https://github.com/ClickHouse/ClickHouse/issues/89101). [#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Adicionada a função `cosineDistanceTransposed`, que aproxima a [distância de cosseno](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance) entre dois pontos. [#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* A instrução anterior para limpar caches, `SYSTEM DROP [...] CACHE`, dava a falsa impressão de que a instrução desabilitava o cache. O ClickHouse agora oferece suporte à instrução `SYSTEM CLEAR [...] CACHE`, que é mais clara. A sintaxe antiga continua disponível. [#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* Adiciona a coluna files à tabela system.parts, que mostra o número de arquivos em cada data part. [#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* Adiciona um scheduler max-min fair para controle de concorrência. Ele oferece melhor equidade em cenários de alta superalocação, quando muitas consultas competem por CPU slots limitados. Consultas de curta duração não são penalizadas por consultas de longa duração que acumularam mais slots ao longo do tempo. Habilitado pelo valor `max_min_fair` da configuração de servidor `concurrent_threads_scheduler`. [#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

[#87299](https://github.com/ClickHouse/ClickHouse/pull/87299) ([Nikita Taranov](https://github.com/nickitat)).
* O filtro externo é aplicado com pushdown na view, o que permite aplicar PREWHERE em nós locais e remotos. Resolve [#88189](https://github.com/ClickHouse/ClickHouse/issues/88189). [#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).

* Corrige o uso da lógica mais rápida de leitura aleatória no Parquet Reader V3 Prefetcher. Fecha [#90890](https://github.com/ClickHouse/ClickHouse/issues/90890). [#91435](https://github.com/ClickHouse/ClickHouse/pull/91435) ([Arsen Muk](https://github.com/arsenmuk)).

Adiciona suporte a buffers de escrita adaptativos para disks criptografados. [#92250](https://github.com/ClickHouse/ClickHouse/pull/92250) ([Azat Khuzhin](https://github.com/azat)).
* Suporta mais casos de pushdown a partir da condição ON de join quando o filtro usa entradas de apenas um lado. Suporta junções `ANY`, `SEMI`, `ANTI`. [#92584](https://github.com/ClickHouse/ClickHouse/pull/92584) ([Dmitry Novik](https://github.com/novikd)).
* Permite usar sets equivalentes para fazer pushdown de filtros em `SEMI JOIN`. Fecha [#85239](https://github.com/ClickHouse/ClickHouse/issues/85239). [#92837](https://github.com/ClickHouse/ClickHouse/pull/92837) ([Dmitry Novik](https://github.com/novikd)).
* Melhora o desempenho da busca de texto completo com text index e o tokenizer `sparseGrams`, reduzindo o número de tokens pesquisados no índice. [#93078](https://github.com/ClickHouse/ClickHouse/pull/93078) ([Anton Popov](https://github.com/CurtizJ)).
* Usa o método &quot;fastrange&quot; (Daniel Lemire) para particionar dados dentro do query pipeline. Isso pode melhorar a ordenação paralela e as junções. [#93080](https://github.com/ClickHouse/ClickHouse/pull/93080) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Otimização de `uniqExact` no caso em que elementos idênticos aparecem com frequência em sequência. [#93268](https://github.com/ClickHouse/ClickHouse/pull/93268) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* A função `isValidASCII` foi otimizada para casos positivos, ou seja, valores de entrada compostos apenas por ASCII. [#93347](https://github.com/ClickHouse/ClickHouse/pull/93347) ([Robert Schulze](https://github.com/rschu1ze)).
* A função `isValidASCII` foi otimizada para casos positivos, ou seja, valores de entrada compostos apenas por ASCII. [#93611](https://github.com/ClickHouse/ClickHouse/pull/93611) ([Robert Schulze](https://github.com/rschu1ze)).
* A leitura do lado esquerdo do hash join agora é ignorada quando o lado direito está vazio. Antes, o lado esquerdo era lido até o primeiro block não vazio, o que podia gerar muito trabalho em casos de filtragem intensa ou aggregation. [#94062](https://github.com/ClickHouse/ClickHouse/pull/94062) ([Alexander Gololobov](https://github.com/davenger)).
* A otimização de leitura em ordem agora reconhece quando as colunas de ORDER BY são constantes devido às condições do WHERE, permitindo leituras eficientes em ordem reversa. Isso beneficia queries multi-tenant como &#96;WHERE tenant=&#39;42&#39; ORDER BY tenant, event&#95;time DESC&#96;, que agora podem usar InReverseOrder em vez de exigir uma ordenação completa.&quot;. [#94103](https://github.com/ClickHouse/ClickHouse/pull/94103) ([matanper](https://github.com/matanper)).
* Introdução de uma classe AST especializada para Enum, para armazenar parâmetros de valor em pares string/integer em vez de filhos ASTLiteral, otimizando o consumo de memória. [#94178](https://github.com/ClickHouse/ClickHouse/pull/94178) ([Ilya Yatsishin](https://github.com/qoega)).

</div>

* Suporte a múltiplas colunas como chave primária no StorageEmbeddedRocksDB. Fecha [#32819](https://github.com/ClickHouse/ClickHouse/issues/32819). [#33917](https://github.com/ClickHouse/ClickHouse/pull/33917) ([usurai](https://github.com/usurai)).
* Impede que os cabeçalhos `x-amz-server-side-encryption` sejam propagados para requisições S3 `HeadObject`, `UploadPart` e `CompleteMultipartUpload`, pois não são suportados. [#64577](https://github.com/ClickHouse/ClickHouse/pull/64577) ([Francisco J. Jurado Moreno](https://github.com/Beetelbrox)).
* Adicionada a sintaxe `ALTER TABLE <table> ATTACH PART <part_name> FROM <directory_name>` para a consulta `ALTER`. Ela permite anexar partes a partir de qualquer subdiretório do diretório `detached/`. Pode ser útil para reintegrar partes com prefixos personalizados (como `broken-on-start`, `unexpected`, etc.) que foram desanexadas por engano, sem necessidade de intervenção manual. Anteriormente, era necessário renomear manualmente os diretórios no sistema de arquivos. [#74816](https://github.com/ClickHouse/ClickHouse/pull/74816) ([Anton Popov](https://github.com/CurtizJ)).
* Rastreamento de particionamento hive para o modo ordenado no S3Queue. Resolve [#71161](https://github.com/ClickHouse/ClickHouse/issues/71161). [#81040](https://github.com/ClickHouse/ClickHouse/pull/81040) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Otimiza a reserva de espaço no cache do sistema de arquivos. `FileCache::collectCandidatesForEviction` será executado sem bloqueio exclusivo. [#82764](https://github.com/ClickHouse/ClickHouse/pull/82764) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Suporte à estratégia de rotação composta (tamanho + tempo) para o log do servidor. [#87620](https://github.com/ClickHouse/ClickHouse/pull/87620) ([Jianmei Zhang](https://github.com/zhangjmruc)).
* O cliente CLI agora pode especificar `<warnings>false</warnings>` em vez do argumento de linha de comando `--no-warnings`. [#87783](https://github.com/ClickHouse/ClickHouse/pull/87783) ([Larry Snizek](https://github.com/larry-cdn77)).
* Adiciona suporte à função de agregação `avg()` com valores Date, DateTime e Time como argumentos. Fecha [#82267](https://github.com/ClickHouse/ClickHouse/issues/82267). [#87845](https://github.com/ClickHouse/ClickHouse/pull/87845) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).

* Suporte a mais engines de tabela e tipos de fontes de dados em subconsultas correlacionadas. Fecha [#80775](https://github.com/ClickHouse/ClickHouse/issues/80775). [#90175](https://github.com/ClickHouse/ClickHouse/pull/90175) ([Dmitry Novik](https://github.com/novikd)).
* Se o esquema de uma view parametrizada for especificado explicitamente, ele é exibido. Fecha [#88875](https://github.com/ClickHouse/ClickHouse/issues/88875), [#81385](https://github.com/ClickHouse/ClickHouse/issues/81385).
