  ### Lançamento do ClickHouse v26.5.1.882-stable (5b96a8d8a5e) FIXME em comparação com v26.5.1.1-new (a7b13e00eb1)

<div id="backward-incompatible-change">
  #### Mudança Incompatível com Versões Anteriores
</div>

* Os valores padrão de `date_time_input_format` e `cast_string_to_date_time_mode` foram alterados de `basic` para `best_effort`. Consultas que antes não conseguiam interpretar strings de data e hora fora do formato básico (por exemplo, `2024 April 4`, `Apr 15, 2020 10:30:00`) agora podem ser bem-sucedidas por padrão. Para manter o comportamento antigo de parsing estrito, defina essas configurações como `basic` (ou use `compatibility`). [#89334](https://github.com/ClickHouse/ClickHouse/pull/89334) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Esta alteração foi revertida. [#90043](https://github.com/ClickHouse/ClickHouse/pull/90043) ([Raúl Marín](https://github.com/Algunenano)).
* O nome de elemento de Tuple `null` agora é proibido porque entra em conflito com o nome de subcoluna usado para mapas de null de Nullable, causando resolução ambígua de subcoluna. [#98377](https://github.com/ClickHouse/ClickHouse/pull/98377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona as configurações `dynamic_disk_allow_from_env`, `dynamic_disk_allow_from_zk` e `dynamic_disk_allow_include` para impedir o uso de `from_env`, `from_zk` e `include` em discos dinâmicos. Alteração incompatível com versões anteriores, pois passa a proibir por padrão um comportamento que antes era permitido por padrão. [#99138](https://github.com/ClickHouse/ClickHouse/pull/99138) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Não é mais possível usar o leitor e o gravador de Parquet obsoletos baseados em Arrow. A implementação nativa será usada no lugar. [#100949](https://github.com/ClickHouse/ClickHouse/pull/100949) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `SHOW CREATE TABLE t` agora dá preferência à tabela temporária quando existem tanto uma tabela permanente quanto uma tabela temporária chamadas `t` e nenhum banco de dados é especificado, em conformidade com o comportamento existente de `DESCRIBE TABLE`. Além disso, a sintaxe `DESCRIBE TEMPORARY TABLE` agora é suportada. [#100966](https://github.com/ClickHouse/ClickHouse/pull/100966) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* O valor padrão de `http_max_fields` foi reduzido de 1.000.000 para 1.000, e o de `http_max_field_name_size`, de 128 KB para 4 KB, para limitar o uso de memória na pré-autenticação por conexões HTTP. Foram adicionadas as configurações `http_max_request_header_size` e `http_headers_read_timeout`. Usuários que dependem dos limites mais altos anteriores podem restaurá-los por meio de configurações. [#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).
* Foi adicionada uma coluna aninhada `histograms` a `system.metric_log` que registra instantâneos de cada métrica de histograma registrada por linha, com uma nova configuração `system_metric_log_show_zero_values_in_histograms` para controlar a emissão de valores zero. Descontinua a tabela `system.histogram_metric_log`. [#103770](https://github.com/ClickHouse/ClickHouse/pull/103770) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* As window functions `RANK` e `DENSE_RANK` agora rejeitam argumentos e lançam `NUMBER_OF_ARGUMENTS_DOESNT_MATCH`, em conformidade com o padrão SQL. Antes, consultas como `RANK(x) OVER (ORDER BY id)` eram aceitas silenciosamente, com o argumento sendo ignorado, o que era uma fonte frequente de confusão para os usuários. Para restaurar o comportamento mais permissivo anterior, defina `allow_rank_dense_rank_arguments = 1`. Fecha [#49526](https://github.com/ClickHouse/ClickHouse/issues/49526). [#104324](https://github.com/ClickHouse/ClickHouse/pull/104324) ([Groene AI](https://github.com/groeneai)).
* `CAST` para `DateTime` ou `DateTime64` sem um fuso horário explícito agora preserva o fuso horário do argumento de origem (quando a origem é um `DateTime`/`DateTime64` com um fuso horário explícito), em conformidade com o comportamento das funções `toDateTime`/`toDateTime64`. Fecha [#55072](https://github.com/ClickHouse/ClickHouse/issues/55072). [#104433](https://github.com/ClickHouse/ClickHouse/pull/104433) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Revertido o alvo de compilação x86 padrão para x86-64-v2 (SSE4.2). A mudança anterior para x86-64-v3 (AVX2) foi desfeita. [#104971](https://github.com/ClickHouse/ClickHouse/pull/104971) ([Raúl Marín](https://github.com/Algunenano)).
* Removida a função de tabela `kql`. Use `SET dialect = 'kusto'` para executar consultas no dialeto KQL. [#105101](https://github.com/ClickHouse/ClickHouse/pull/105101) ([Alexey Milovidov](https://github.com/alexey-milovidov)).





<div id="new-feature">
  #### Novo recurso
</div>

* Adicionada a table function `filesystem`. Ela permite representar a estrutura do filesystem como uma tabela, para consultar metadados e conteúdo de arquivos com SQL. Originalmente em https://github.com/ClickHouse/ClickHouse/pull/42039 por @perst20. Veja [#42039](https://github.com/ClickHouse/ClickHouse/issues/42039). Veja [#50208](https://github.com/ClickHouse/ClickHouse/issues/50208). [#53610](https://github.com/ClickHouse/ClickHouse/pull/53610) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Introduzido o parâmetro kafka&#95;autodetect&#95;client&#95;rack. Se definido, ele detecta a zona de disponibilidade a partir dos recursos da nuvem e a repassa como parâmetro client.rack do librdkafka para evitar comunicações entre zonas. [#81323](https://github.com/ClickHouse/ClickHouse/pull/81323) ([Ilya Golshtein](https://github.com/ilejn)).
* Adicionado o tipo de evento `Read` a `system.blob_storage_log` para rastrear operações de leitura em armazenamento de objetos, controlado pela nova configuração `enable_blob_storage_log_for_read_operations`. [#96867](https://github.com/ClickHouse/ClickHouse/pull/96867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionado um parâmetro opcional de variante de codificação a `bech32Encode` (`'bech32'` / `'bech32m'`) e um modo de decodificação bruta a `bech32Decode` para codificação de endereços não SegWit (por exemplo, Cosmos SDK, Injective, Osmosis). [#98986](https://github.com/ClickHouse/ClickHouse/pull/98986) ([Yash ](https://github.com/Onyx2406)).
* Os usuários agora podem ver os watches do ZooKeeper emitidos pelo clickhouse-server usando a nova tabela `system.zookeeper_watches`. [#99277](https://github.com/ClickHouse/ClickHouse/pull/99277) ([Den Kalantaevskii](https://github.com/Diskein)).
* Adicionado o evento de perfil `Shards`, que conta o número de shards envolvidos em consultas distribuídas, somado em todas as tabelas. [#99470](https://github.com/ClickHouse/ClickHouse/pull/99470) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionado suporte aos predicados SQL de valor de verdade `IS TRUE`, `IS FALSE`, `IS UNKNOWN`, `IS NOT TRUE`, `IS NOT FALSE` e `IS NOT UNKNOWN` para expressões booleanas Nullable. [#99997](https://github.com/ClickHouse/ClickHouse/pull/99997) ([ibrahim karimeddin](https://github.com/ibrahimkarimeddin)).
* WASM UDF pode ser declarada como DETERMINISTIC e ser objeto de constant folding. [#100005](https://github.com/ClickHouse/ClickHouse/pull/100005) ([Vasily Chekalkin](https://github.com/bacek)).
* Adicionada a configuração `parallel_replicas_prefer_local_replica`: quando desabilitada, as parallel replicas são selecionadas exclusivamente pelo algoritmo de load balancing, permitindo que até consultas com `max_parallel_replicas = 1` sejam direcionadas para outro host. [#100139](https://github.com/ClickHouse/ClickHouse/pull/100139) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionadas as server settings `{disk,storage,http}_connections_rcvbuf` e `{disk,storage,http}_connections_sndbuf` para controlar os tamanhos dos buffers de socket TCP em conexões HTTP de saída, permitindo que operadores sobrescrevam o autotuning do kernel e limitem o uso de memória por conexão. [#100478](https://github.com/ClickHouse/ClickHouse/pull/100478) ([Sema Checherinda](https://github.com/CheSema)).
* Suporte a `CREATE OR REPLACE MATERIALIZED VIEW` com a mesma semântica de troca atômica de `CREATE OR REPLACE TABLE`. Funciona com tabelas internas, tabelas `TO`, `POPULATE`, `REFRESH` e `ON CLUSTER`. [#100539](https://github.com/ClickHouse/ClickHouse/pull/100539) ([DQ](https://github.com/il9ue)).
* Agora é possível passar nomes simples de funções para funções de ordem superior como `arrayMap`, `arrayFilter` etc. Por exemplo, `arrayMap(negate, [1, 2, 3])` agora é equivalente a `arrayMap(x -> negate(x), [1, 2, 3])`. [#101033](https://github.com/ClickHouse/ClickHouse/pull/101033) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona a configuração `send_table_structure_on_insert_with_inline_data` e a opção de cliente `--inline-insert-data` para permitir que o servidor analise por conta própria os dados inline de `INSERT` pelo protocolo nativo, evitando a ida e volta para receber a estrutura da tabela e melhorando o desempenho em muitos inserts pequenos. [#101034](https://github.com/ClickHouse/ClickHouse/pull/101034) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona as funções `tokenizeQuery` e `highlightQuery` para tokenização de consultas SQL e destaque de sintaxe. `tokenizeQuery` retorna tokens do lexer com offsets em bytes e tipos de token; `highlightQuery` retorna intervalos de destaque de sintaxe baseados no parser com categorias de destaque (palavra-chave, identificador, função, número, string etc.). [#101054](https://github.com/ClickHouse/ClickHouse/pull/101054) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona a configuração `url_base` para resolver URLs relativas na table function `url` e no motor de tabela `URL`, seguindo a semântica da RFC 3986. [#101113](https://github.com/ClickHouse/ClickHouse/pull/101113) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona as histogram metrics `s3_read_request_duration_microseconds` e `s3_read_request_bytes` para observar o tempo de vida da conexão de requisição GET ao S3 e os bytes consumidos, visíveis em `system.histogram_metrics` e no endpoint do Prometheus. [#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)).
* Cache de condição de consulta para tabelas Iceberg. [#102115](https://github.com/ClickHouse/ClickHouse/pull/102115) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* Adiciona os motores de tabela `Paimon`, `PaimonS3`, `PaimonAzure`, `PaimonHDFS` e `PaimonLocal` com suporte a Incremental read com rastreamento do progresso de snapshot pelo Keeper. O modo incremental retorna apenas novas linhas desde o último snapshot confirmado. Leituras delta de snapshot direcionadas estão disponíveis por meio de `paimon_target_snapshot_id`, e limites de snapshot por consulta por meio de `max_consume_snapshots`. A atualização de metadata em segundo plano é configurável com `paimon_metadata_refresh_interval_sec`. Controlado por `allow_experimental_paimon_storage_engine`. [#102343](https://github.com/ClickHouse/ClickHouse/pull/102343) ([XiaoBinMu](https://github.com/Binnn-MX)).
* Adiciona o tipo de estatística NullCount para contagem precisa de valores NULL em colunas Nullable. Isso permite melhorar a otimização `PREWHERE` e o part pruning. [#102356](https://github.com/ClickHouse/ClickHouse/pull/102356) ([zoomxi](https://github.com/zoomxi)).
* Agora você pode formatar uma string em JSON legível por humanos com a função `prettyPrintJSON`. Útil para dashboards ou relatórios em que antes a formatação de JSON exigia uma etapa extra no lado do cliente. Fecha [#62523](https://github.com/ClickHouse/ClickHouse/issues/62523). [#102594](https://github.com/ClickHouse/ClickHouse/pull/102594) ([Dmitry Prokofyev](https://github.com/prokofyevDmitry)).
* Suporte a valores negativos na cláusula `LIMIT BY` para selecionar linhas do *fim* de cada grupo, em vez do início. Por exemplo, `LIMIT -2 BY id` retorna as duas últimas linhas por `id`. Offsets negativos (`LIMIT -1 OFFSET -1 BY id`) e sinais mistos (`LIMIT -2 OFFSET 1 BY id`) também são suportados. [#103222](https://github.com/ClickHouse/ClickHouse/pull/103222) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Adiciona uma nova configuração da tabela Kafka, `kafka_map_virtual_columns_on_write`. Quando habilitada, colunas chamadas `_key`, `_timestamp`, `_headers.name` e `_headers.value` no schema da tabela Kafka são produzidas como a key, o timestamp e os headers correspondentes da mensagem Kafka no `INSERT`, e são excluídas do message payload. [#103243](https://github.com/ClickHouse/ClickHouse/pull/103243) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionadas as consultas `SYSTEM PAUSE VIEW [db.]name` e `SYSTEM PAUSE VIEWS` para views materializadas atualizáveis. Ao contrário de `SYSTEM STOP VIEW`, `SYSTEM PAUSE VIEW` não interrompe a atualização em execução — a atualização em andamento pode ser concluída, e apenas as atualizações subsequentes são impedidas. Isso é revertido por `SYSTEM START VIEW` ou `SYSTEM START VIEWS`, que agora limpam de forma uniforme tanto o estado de parada quanto o de pausa. [#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Adicionada uma nova configuração &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;join&#96;, espelhando &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;group&#95;by&#96; e &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;sort&#96;. Ela define o limite de spill para disco para hash join como uma fração da memória disponível; em conjunto com o valor absoluto &#96;max&#95;bytes&#95;before&#95;external&#95;join&#96;, aplica-se o menor dos dois limites resultantes. [#103862](https://github.com/ClickHouse/ClickHouse/pull/103862) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adicionada a função `regexpPosition` (com aliases compatíveis com PostgreSQL `regexpInstr` e `regexp_instr`) que retorna a posição em bytes da enésima correspondência de regex em uma string. Suporta deslocamento inicial, modo de retorno após a correspondência, flags de regex e seleção de grupo de captura. [#104172](https://github.com/ClickHouse/ClickHouse/pull/104172) ([Abhinav Agarwal](https://github.com/aagarwal-gtr)).
* As estatísticas de coluna NullCount agora podem ser usadas para part pruning. Consultas com predicados IS NULL ou IS NOT NULL em colunas Nullable que tenham estatísticas NullCount podem ignorar partes de dados inteiras quando as estatísticas comprovam que não existem linhas correspondentes. [#104214](https://github.com/ClickHouse/ClickHouse/pull/104214) ([zoomxi](https://github.com/zoomxi)).
* Novas funções `isPrime` e `isProbablePrime` para verificações de primalidade. `isPrime` retorna um resultado exato para inteiros sem sinal de até `UInt64`. `isProbablePrime` também oferece suporte a `UInt128` e `UInt256`; para esses tipos mais amplos, `0` significa definitivamente composto e `1` significa provavelmente primo. O segundo argumento opcional de `isProbablePrime`, `rounds`, controla o nível de confiança, com o padrão de `25` rodadas limitando a taxa de falsos positivos para um número composto aleatório a menos de `10^-15`. [#104234](https://github.com/ClickHouse/ClickHouse/pull/104234) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Clear e /clear agora limpam o terminal nas ferramentas de linha de comando do ClickHouse, em vez de serem executados como uma consulta por engano. [#104318](https://github.com/ClickHouse/ClickHouse/pull/104318) ([Tyler Hannan](https://github.com/tylerhannan)).
* Permite que a table function `file` aceite um `Array(String)` de paths em consultas `SELECT`. [#104442](https://github.com/ClickHouse/ClickHouse/pull/104442) ([Yue](https://github.com/niyue)).
* Adicionadas as colunas `deterministic` e `higher_order` à tabela `system.functions`. [#104479](https://github.com/ClickHouse/ClickHouse/pull/104479) ([Pedro Ferreira](https://github.com/PedroTadim)).



<div id="experimental-feature">
  #### Funcionalidade Experimental
</div>

* Adicionada uma interface experimental de terminal web em `/webterminal` que oferece uma sessão interativa de `clickhouse-client` no navegador via WebSocket. Desativada por padrão; habilite-a com a configuração do servidor `allow_experimental_webterminal`. [#100277](https://github.com/ClickHouse/ClickHouse/pull/100277) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* UDF WASM agora pode aplicar coerção a mais tipos numéricos. Inteiros menores podem sofrer coerção para inteiros maiores. Por exemplo, Int8 para UInt64. Qualquer inteiro pode sofrer coerção para float. Por exemplo, Int32 para F32. [#100435](https://github.com/ClickHouse/ClickHouse/pull/100435) ([Vasily Chekalkin](https://github.com/bacek)).
* Suporte a tipos Geo para Iceberg. [#103113](https://github.com/ClickHouse/ClickHouse/pull/103113) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* O terminal web experimental (`allow_experimental_webterminal`) agora pode ser embutido em contextos cross-origin de `clickhouse.com`, `clickhouse.cloud` e seus subdomínios. Antes, `postMessage` de qualquer parent com origem diferente era rejeitado na entrada e descartado silenciosamente na saída, o que na prática impedia embutir o terminal fora de `play.clickhouse.com`. A lista de origens aceitas é uma allowlist explícita (somente https, vinculada ao hostname), portanto origens não confiáveis continuam sendo rejeitadas. [#105191](https://github.com/ClickHouse/ClickHouse/pull/105191) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Otimiza `cramersV`, `cramersVBiasCorrected`, `theilsU` e `contingency` quando usados com funções de janela. Fecha [#83521](https://github.com/ClickHouse/ClickHouse/issues/83521). [#93384](https://github.com/ClickHouse/ClickHouse/pull/93384) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Habilita por padrão as configurações `use_top_k_dynamic_filtering` e `use_skip_indexes_for_top_k` para melhorar o desempenho de consultas `ORDER BY ... LIMIT N`. [#99537](https://github.com/ClickHouse/ClickHouse/pull/99537) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Limita a quantidade de streams ativos simultaneamente em UNION ALL para reduzir o pico de uso de memória. [#100176](https://github.com/ClickHouse/ClickHouse/pull/100176) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona uma otimização de consulta que reescreve `tupleElement(dictGet('dict', ('a', 'b', 'c'), key), N)` como `dictGet('dict', 'a', key)`, evitando buscar atributos desnecessários do Dicionário. Controlada pela configuração `optimize_dictget_tuple_element` (habilitada por padrão). [#100186](https://github.com/ClickHouse/ClickHouse/pull/100186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Otimiza levemente o userspace page cache. [#100300](https://github.com/ClickHouse/ClickHouse/pull/100300) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelera a análise de índice que envolve conversão de tipos e aplicação de funções. Fecha [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653). [#100366](https://github.com/ClickHouse/ClickHouse/pull/100366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Acelera consultas muito grandes em tabelas `Merge` sobre um grande número de tabelas subjacentes. Fecha [#32465](https://github.com/ClickHouse/ClickHouse/issues/32465). [#100369](https://github.com/ClickHouse/ClickHouse/pull/100369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Adiciona as configurações `max_threads_min_free_memory_per_thread` e `max_insert_threads_min_free_memory_per_thread` para reduzir automaticamente o paralelismo da consulta quando o servidor estiver com pouca memória livre. [#100383](https://github.com/ClickHouse/ClickHouse/pull/100383) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhora o uso de memória em sistemas com pouca memória (&lt; 4 GiB). [#100389](https://github.com/ClickHouse/ClickHouse/pull/100389) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Habilita a bufferização nas etapas de ordenação no initiator para consultas distribuídas com ordenação. [#100661](https://github.com/ClickHouse/ClickHouse/pull/100661) ([Nikita Taranov](https://github.com/nickitat)).
* Melhoria de desempenho em partial&#95;merge&#95;join. [#100945](https://github.com/ClickHouse/ClickHouse/pull/100945) ([Artem Zuikov](https://github.com/4ertus2)).
* Reduz levemente a superalocação de memória em `partial_merge` JOIN. [#100963](https://github.com/ClickHouse/ClickHouse/pull/100963) ([Artem Zuikov](https://github.com/4ertus2)).
* Otimiza alocações/desalocações ao armazenar em cache as configurações de sampling em vez de percorrer toda a hierarquia do memory tracker. [#101267](https://github.com/ClickHouse/ClickHouse/pull/101267) ([Azat Khuzhin](https://github.com/azat)).
* Reduz a sobrecarga de alocação de memória durante uploads multipart para o S3 por meio da pré-alocação de contêineres internos de rastreamento. [#101799](https://github.com/ClickHouse/ClickHouse/pull/101799) ([Gagan Dhakrey](https://github.com/gagandhakrey)).
* Remove a vtable dos tipos de campo de configuração, reduzindo o tamanho da cópia de `Settings` em ~28x e melhorando a localidade de cache por meio de um layout de array tipado para todos os tipos de configuração. [#102269](https://github.com/ClickHouse/ClickHouse/pull/102269) ([Raúl Marín](https://github.com/Algunenano)).
* Adiciona prefetch por software na fase de sondagem do hash join para reduzir a latência de acesso à memória em tabelas hash grandes, controlado pela configuração `enable_software_prefetch_in_join`. [#102444](https://github.com/ClickHouse/ClickHouse/pull/102444) ([Xiaozhe Yu](https://github.com/wudidapaopao)).
* Otimiza o layout do MemoryTracker (melhora seu desempenho em ~25%). [#103464](https://github.com/ClickHouse/ClickHouse/pull/103464) ([Azat Khuzhin](https://github.com/azat)).
* Reescreve os predicados `coalesce(a, b, ...) <op> const` e `ifNull(a, b) <op> const` antes da análise de índices, para que a chave primária por coluna e os índices de salto em cada argumento possam podar grânulos. Controlado pela nova configuração `allow_key_condition_coalesce_rewrite` (ativada por padrão). [#103468](https://github.com/ClickHouse/ClickHouse/pull/103468) ([Manuel](https://github.com/raimannma)).
* Usa o recurso de arena superdimensionada do jemalloc para reduzir falhas de página. [#103958](https://github.com/ClickHouse/ClickHouse/pull/103958) ([Nikita Taranov](https://github.com/nickitat)).
* Melhorou significativamente o desempenho das consultas ao ler catálogos Iceberg com grandes arquivos de metadados JSON, otimizando o processamento de barras escapadas. [#103998](https://github.com/ClickHouse/ClickHouse/pull/103998) ([Mohaidoss](https://github.com/mohaidoss)).
* Evita a sobrecarga do cache não comprimido de índices quando o cache está desabilitado (configuração de servidor `index_uncompressed_cache_size = 0`, que é o padrão). [#104063](https://github.com/ClickHouse/ClickHouse/pull/104063) ([Michael Kolupaev](https://github.com/al13n321)).
