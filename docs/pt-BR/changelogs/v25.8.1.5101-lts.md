<div id="backward-incompatible-change">
  #### Alteração incompatível com versões anteriores
</div>

* Desativa, por padrão, o uso de aspas em inteiros de 64 bits nos formatos JSON. [#74079](https://github.com/ClickHouse/ClickHouse/pull/74079) ([Pavel Kruglov](https://github.com/Avogar)).
* Infere `Array(Dynamic)` em vez de `Tuple` sem nome para arrays de valores com tipos diferentes em JSON. Para usar o comportamento anterior, desative a configuração `input_format_json_infer_array_of_dynamic_from_array_of_different_types`. [#80859](https://github.com/ClickHouse/ClickHouse/pull/80859) ([Pavel Kruglov](https://github.com/Avogar)).
* Move as métricas de latência do S3 para histogramas, por homogeneidade e simplicidade. [#82305](https://github.com/ClickHouse/ClickHouse/pull/82305) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* Exige backticks ao redor de identificadores com pontos em expressões padrão para evitar que sejam interpretados como identificadores compostos. [#83162](https://github.com/ClickHouse/ClickHouse/pull/83162) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* A materialização tardia é habilitada apenas com o analisador, para evitar a manutenção sem o analisador, que, pela nossa experiência, apresenta alguns problemas (por exemplo, ao usar `indexHint()` em condições). [#83791](https://github.com/ClickHouse/ClickHouse/pull/83791) ([Igor Nikonov](https://github.com/devcrafter)).
* Grava valores do tipo `Enum` como `BYTE_ARRAY` com tipo lógico `ENUM` no formato de saída Parquet por padrão. [#84169](https://github.com/ClickHouse/ClickHouse/pull/84169) ([Pavel Kruglov](https://github.com/Avogar)).
* Habilita, por padrão, a configuração do MergeTree `write_marks_for_substreams_in_compact_parts`. Isso melhora significativamente o desempenho da leitura de subcolunas a partir de partes Compact recém-criadas. Servidores com versão inferior à 25.5 não poderão ler novas partes Compact. [#84171](https://github.com/ClickHouse/ClickHouse/pull/84171) ([Pavel Kruglov](https://github.com/Avogar)).
* O valor padrão anterior de `concurrent_threads_scheduler` era `round_robin`, o que se mostrou injusto na presença de um grande número de consultas de thread única (por exemplo, INSERTs). Essa mudança torna `fair_round_robin`, uma alternativa mais segura, o scheduler padrão. [#84747](https://github.com/ClickHouse/ClickHouse/pull/84747) ([Sergei Trifonov](https://github.com/serxa)).
* O ClickHouse oferece suporte à sintaxe Heredoc no estilo PostgreSQL: `$tag$ string contents... $tag$`, também conhecida como literais de string delimitados por cifrões. Em versões anteriores, havia menos restrições para tags: elas podiam conter caracteres arbitrários, incluindo pontuação e espaços em branco. Isso introduz ambiguidade de parsing com identificadores que também podem começar com um caractere de cifrão. Ao mesmo tempo, o PostgreSQL permite apenas caracteres de palavra em tags. Para resolver o problema, agora restringimos as tags Heredoc para conter apenas caracteres de palavra. Fecha [#84731](https://github.com/ClickHouse/ClickHouse/issues/84731). [#84846](https://github.com/ClickHouse/ClickHouse/pull/84846) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* As funções `azureBlobStorage`, `deltaLakeAzure` e `icebergAzure` foram atualizadas para validar corretamente as permissões `AZURE`. Todas as funções na variante de cluster (funções `-Cluster`) agora verificam permissões em relação às respectivas contrapartes sem cluster. Além disso, as funções `icebergLocal` e `deltaLakeLocal` agora aplicam verificações da permissão `FILE`. [#84938](https://github.com/ClickHouse/ClickHouse/pull/84938) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* Habilita, por padrão, a configuração `allow_dynamic_metadata_for_data_lakes` (configuração em nível de Table Engine). [#85044](https://github.com/ClickHouse/ClickHouse/pull/85044) ([Daniil Ivanik](https://github.com/divanik)).

  #### Novo recurso

* Não apenas tabelas Merge, mas todas as tabelas agora oferecem suporte à coluna virtual &#95;table. [#63665](https://github.com/ClickHouse/ClickHouse/pull/63665) ([Xiaozhe Yu](https://github.com/wudidapaopao)).

Para usá-lo, defina `dialect='promql'` no clickhouse-client, aponte-o para a tabela TimeSeries usando a configuração `promql_table_name='X'` e execute consultas como `rate(ClickHouseProfileEvents_ReadCompressedBytes[1m])[5m:1m]`. Além disso, você pode encapsular a consulta PromQL em SQL: `SELECT * FROM prometheusQuery('up', ...);`. Até o momento, apenas as funções `rate`, `delta` e `increase` são suportadas. Sem operadores unários/binários. Sem API HTTP. [#75036](https://github.com/ClickHouse/ClickHouse/pull/75036) ([Vitaly Baranov](https://github.com/vitlibar)).

Novas configurações de workload para throttling de CPU foram adicionadas: `max_cpus`, `max_cpu_share` e `max_burst_cpu_seconds`. Mais detalhes: [https://clickhouse.com/docs/operations/workload-scheduling#cpu&#95;scheduling](https://clickhouse.com/docs/operations/workload-scheduling#cpu_scheduling). [#80879](https://github.com/ClickHouse/ClickHouse/pull/80879) ([Sergei Trifonov](https://github.com/serxa)).

Uma nova configuração `parallel_replicas_support_projection` foi adicionada para controlar se o suporte a projeções está habilitado. <div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Engine de tabela `azureBlobStorage`: armazena em cache e reutiliza tokens de authentication de identidade gerenciada quando possível para evitar throttling. [#79860](https://github.com/ClickHouse/ClickHouse/pull/79860) ([Nick Blakely](https://github.com/niblak)).
* Adicionada uma nova lógica (controlada pela configuração `enable_producing_buckets_out_of_order_in_aggregation`, habilitada por padrão) que permite enviar alguns buckets fora de ordem durante a aggregation com uso eficiente de memória. Quando alguns buckets de aggregation levam significativamente mais tempo para fazer merge do que outros, isso melhora o desempenho ao permitir que o initiator faça merge de buckets com IDs de bucket mais altos nesse meio-tempo. A desvantagem é um uso de memória potencialmente maior (não deve ser significativo). [#80179](https://github.com/ClickHouse/ClickHouse/pull/80179) ([Nikita Taranov](https://github.com/nickitat)).
* Nova implementação do leitor de Parquet. Em geral, ela é mais rápida e oferece suporte a pushdown de filtro em nível de página e PREWHERE. Atualmente, é Experimental. Use a configuração `input_format_parquet_use_native_reader_v3` para habilitar. [#82789](https://github.com/ClickHouse/ClickHouse/pull/82789) ([Michael Kolupaev](https://github.com/al13n321)).
* Processa `max_joined_block_rows` fora do loop principal do hash JOIN. Desempenho ligeiramente melhor para ALL JOIN. [#83216](https://github.com/ClickHouse/ClickHouse/pull/83216) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Substitui o client HTTP curl pelo client HTTP poco para Azure blob storage. Foram introduzidas várias configurações para esses clients, espelhando configurações do S3. Também foram introduzidos timeouts de conexão agressivos para Azure e S3. Melhor introspection em profile events e métricas do Azure. O novo client é habilitado por padrão e oferece latencies muito melhores para queries frias sobre o Azure Blob Storage. O client `Curl` antigo pode ser restaurado definindo `azure_sdk_use_native_client=false`. [#83294](https://github.com/ClickHouse/ClickHouse/pull/83294) ([alesapin](https://github.com/alesapin)).
* Melhora significativamente o desempenho da leitura de subcolumns de `JSON` a partir de shared data no MergeTree ao implementar novas serializations para shared data de `JSON` no MergeTree. [#83777](https://github.com/ClickHouse/ClickHouse/pull/83777) ([Pavel Kruglov](https://github.com/Avogar)).
* Processa primeiro índices min-max com maior granularity. Fecha [#75381](https://github.com/ClickHouse/ClickHouse/issues/75381). [#83798](https://github.com/ClickHouse/ClickHouse/pull/83798) ([Maruth Goyal](https://github.com/maruthgoyal)).
* Queries de busca vetorial que usam um índice de similaridade vetorial são concluídas com menor latência devido à redução de leituras de armazenamento e do uso de CPU. [#83803](https://github.com/ClickHouse/ClickHouse/pull/83803) ([Shankar Iyer](https://github.com/shankar-iyer)).
* Implementa addManyDefaults para combinators If. [#83870](https://github.com/ClickHouse/ClickHouse/pull/83870) ([Raúl Marín](https://github.com/Algunenano)).
* Calcula a coluna-chave serializada de forma colunar ao agrupar por várias colunas de string ou número. [#83884](https://github.com/ClickHouse/ClickHouse/pull/83884) ([李扬](https://github.com/taiyang-li)).
* Testa -falign-functions=64 na tentativa de obter testes de desempenho mais estáveis. [#83920](https://github.com/ClickHouse/ClickHouse/pull/83920) ([Azat Khuzhin](https://github.com/azat)).
* O índice de filtro de Bloom agora é usado para condições como `has([c1, c2, ...], column)`, em que `column` não é do tipo `Array`. Isso melhora o desempenho dessas queries, tornando-as tão eficientes quanto o operador `IN`. [#83945](https://github.com/ClickHouse/ClickHouse/pull/83945) ([Doron David](https://github.com/dorki)).
* Reduz chamadas desnecessárias de memcpy em CompressedReadBufferBase::readCompressedData. [#83986](https://github.com/ClickHouse/ClickHouse/pull/83986) ([Raúl Marín](https://github.com/Algunenano)).
* JOINs `All` `LEFT/INNER` serão convertidos automaticamente para `RightAny` se o lado direito for determinado funcionalmente pelas colunas-chave da junção (todas as linhas têm valores únicos de chave de junção). [#84010](https://github.com/ClickHouse/ClickHouse/pull/84010) ([Nikita Taranov](https://github.com/nickitat)).
* Processa os índices em ordem crescente de tamanho de arquivo. A ordenação final dos índices prioriza os índices minmax e vetoriais (devido à simplicidade e à seletividade, respectivamente) e, em seguida, os índices menores. Dentro dos índices minmax/vetoriais, os menores também são priorizados. [#84094](https://github.com/ClickHouse/ClickHouse/pull/84094) ([Maruth Goyal](https://github.com/maruthgoyal)).
* Otimiza `largestTriangleThreeBuckets` removendo dados temporários. [#84479](https://github.com/ClickHouse/ClickHouse/pull/84479) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Otimiza a desserialização de strings simplificando o código. Fecha [#38564](https://github.com/ClickHouse/ClickHouse/issues/38564). [#84561](https://github.com/ClickHouse/ClickHouse/pull/84561) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Anteriormente, os dados do índice de texto eram separados em vários segmentos (cada segmento tinha, por padrão, 256 MiB). Isso podia reduzir o consumo de memória durante a construção do índice de texto, mas aumentava o espaço necessário em disco e o tempo de resposta da consulta. [#84590](https://github.com/ClickHouse/ClickHouse/pull/84590) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Corrigido o cálculo do tamanho mínimo da tarefa para réplicas paralelas. [#84752](https://github.com/ClickHouse/ClickHouse/pull/84752) ([Nikita Taranov](https://github.com/nickitat)).
* Melhorado o desempenho da aplicação de partes de patch no modo `Join`. [#85040](https://github.com/ClickHouse/ClickHouse/pull/85040) ([Anton Popov](https://github.com/CurtizJ)).
* Remove o byte nulo. Fecha [#85062](https://github.com/ClickHouse/ClickHouse/issues/85062). Alguns bugs menores foram corrigidos. As funções `structureToProtobufSchema` e `structureToCapnProtoSchema` não inseriam corretamente um byte terminador nulo e usavam uma quebra de linha no lugar dele. Isso fazia com que faltasse uma quebra de linha na saída e podia levar a estouros de buffer ao usar outras funções que dependem do byte nulo (como `logTrace`, `demangle`, `extractURLParameter`, `toStringCutToZero` e `encrypt`/`decrypt`). O layout de dicionário `regexp_tree` não suportava o processamento de strings com bytes nulos. A função `formatRowNoNewline`, chamada com o formato `Values` ou com qualquer outro formato sem quebra de linha no fim das linhas, cortava erroneamente o último caractere da saída. A função `stem` continha um erro de segurança contra exceções que podia levar a um vazamento de memória em um cenário muito raro. A função `initcap` funcionava incorretamente para argumentos `FixedString`: ela não reconhecia o início de uma palavra no começo da string se a string anterior em um bloco terminasse com um caractere de palavra. Corrigida uma vulnerabilidade de segurança do formato Apache `ORC`, que podia levar à exposição de memória não inicializada. Alterado o comportamento da função `replaceRegexpAll` e do alias correspondente, `REGEXP_REPLACE`: agora ela pode fazer uma correspondência vazia no fim da string mesmo que a correspondência anterior tenha processado a string inteira, como no caso de `^a*|a*$` ou `^|.*` — isso corresponde à semântica de JavaScript, Perl, Python, PHP e Ruby, mas difere da semântica do PostgreSQL. A implementação de muitas funções foi simplificada e otimizada. A documentação de várias funções estava incorreta e agora foi corrigida. Tenha em mente que a saída de `byteSize` para colunas String e tipos complexos compostos por colunas String mudou (de 9 bytes por string vazia para 8 bytes por string vazia), e isso é normal. [#85063](https://github.com/ClickHouse/ClickHouse/pull/85063) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Otimiza a materialização de constantes nos casos em que ela é feita apenas para retornar uma única linha. [#85071](https://github.com/ClickHouse/ClickHouse/pull/85071) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Melhora o processamento paralelo de arquivos com o backend delta-kernel-rs. [#85642](https://github.com/ClickHouse/ClickHouse/pull/85642) ([Azat Khuzhin](https://github.com/azat)).

<div id="improvement">
  #### Melhoria
</div>

* Exibir o número de intervalos a serem lidos na saída de `EXPLAIN indexes = 1`. [#79938](https://github.com/ClickHouse/ClickHouse/pull/79938) ([Christoph Wurm](https://github.com/cwurm)).
* Introduzir configurações para definir o tamanho do bloco de compressão do ORC e atualizar seu valor padrão de 64KB para 256KB, para manter a consistência com o Spark ou o Hive. [#80602](https://github.com/ClickHouse/ClickHouse/pull/80602) ([李扬](https://github.com/taiyang-li)).
* Adicionar o arquivo `columns_substreams.txt` à Wide part para rastrear todos os subfluxos armazenados na part.
