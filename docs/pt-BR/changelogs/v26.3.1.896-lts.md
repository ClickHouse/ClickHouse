<div id="backward-incompatible-change">
  #### Mudança incompatível com versões anteriores
</div>

* Corrige os metadados das projeções normais para que projeções com chaves de ordenação de múltiplas colunas sejam reconhecidas corretamente. Complementa [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429). [#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* Propaga as versões de serialização dos tipos de dados para tipos de dados aninhados. Por exemplo, a versão de serialização de String `with_size_stream` antes era aplicada apenas a colunas String de nível superior e a elementos de Tuple. Agora, ela é aplicada a qualquer tipo String dentro de qualquer tipo aninhado, como Array/Map/Variant/JSON/etc. Esse comportamento é controlado pelo setting do MergeTree `propagate_types_serialization_versions_to_nested_types`, que agora está habilitado por padrão. Após essa mudança, partes de dados recém-criadas não podem ser lidas por versões mais antigas, mas partes antigas podem ser lidas pela nova versão sem problemas. Isso significa que o upgrade é seguro, mas o downgrade não. [#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* Remove o tipo de skip index `hypothesis`. Era um recurso experimental obscuro, com utilidade prática limitada. Criar tabelas com `INDEX ... TYPE hypothesis` agora produzirá um erro. [#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige um problema em que arquivos de índice de skip index não respeitavam o setting replace&#95;long&#95;file&#95;name&#95;to&#95;hash, causando erros de &quot;File name too long&quot; e falhas na leitura de índices com nomes longos. Os nomes de arquivos de skip index agora passam por hash quando excedem max&#95;file&#95;name&#95;length, de forma semelhante aos arquivos de coluna. Isso é compatível com versões anteriores (novos servidores leem partes antigas), mas fazer downgrade (ou usar servidores antigos durante uma atualização gradual) pode fazer com que índices com nomes longos sejam ignorados. [#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* Ativa async insert por padrão. O ClickHouse agora fará batching de todos os inserts pequenos por padrão. Esse setting é definido em compatibility. Se você definir `compatibility=<version less than 26.2>`, o valor padrão será o anterior, `false`. Você pode desativar/ativar async inserts em vários níveis: na configuração, em profiles de usuários, para a sessão, para a consulta ou para a tabela MergeTree. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* Corrige a precedência do operador `NOT` para corresponder ao padrão SQL: `NOT` agora tem precedência menor que `IS NULL`, `BETWEEN`, `LIKE` e operadores aritméticos. Por exemplo, `NOT (x) IS NULL` agora é interpretado como `NOT (x IS NULL)` em vez de `(NOT x) IS NULL`. Isso pode alterar o resultado de consultas que dependiam do comportamento anterior (fora do padrão). [#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Altera o valor padrão de `mysql_datatypes_support_level` de vazio para `decimal,datetime64,date2Date32`, habilitando por padrão o mapeamento correto de `DATE` do MySQL para `Date32`, `DECIMAL`/`NUMERIC` para `Decimal` e `DATETIME`/`TIMESTAMP` com precision para `DateTime64`. Antes, colunas `DATE` do MySQL eram mapeadas para `Date`, que não pode representar datas anteriores a 1970-01-01, causando corrupção de dados. [#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Aceita um array de nomes de partes em vez de regexp para `mergeTreeAnalyzeIndexes{,UUID}`, já que o uso de regexps é lento (*recurso experimental*). [#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* Remove a função experimental `detectProgrammingLanguage`. [#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### Melhoria de desempenho
</div>

* Otimize o descarte de grânulos para `pointInPolygon` em polígonos grandes e corrija a análise de índice de `pointInPolygon`, que lançava exceção durante a poda da chave primária. [#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Melhore o desempenho da função `levenshteinDistance`. [#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)).
* Otimize as conversões em lote do tipo Decimal, evitando chamadas de função para cada elemento. [#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 1. O Iceberg passa a contar com o recurso de pré-carregamento assíncrono de metadados no cache. Isso pode ser habilitado definindo `iceberg_metadata_async_prefetch_period_ms` na criação da tabela. Ex.: `CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. Agora, consultas SELECT em tabelas Iceberg podem ser executadas especificando o parâmetro `iceberg_metadata_staleness_ms`, o que permite ao ClickHouse usar a versão em cache dos metadados se ela estiver mais recente do que a antiguidade máxima especificada. Caso contrário, o catálogo remoto do Iceberg será consultado para obter os metadados mais recentes a fim de processar a solicitação (como funcionava antes). Com essa mudança, conseguimos reduzir a 0 as chamadas ao catálogo do Iceberg durante o processamento da solicitação, o que deve trazer um ganho visível de desempenho. Exemplo: `SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`. [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)).
* O modo ordenado do S3Queue usa S3 ListObjectsV2 StartAfter para evitar relistar todo o histórico do prefixo, reduzindo as chamadas para ListObjects. [#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* Em geral, o bloco original é necessário para desduplicação, mas, para inserção síncrona, podemos omiti-lo e economizar memória de vez. [#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* Habilita leituras paralelas no YTsaurus table engine. [#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* Usa um valor específico da arquitetura para o tamanho da linha de cache, em vez de um valor fixo de 64. [#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
* Passa a oferecer suporte à troca dos lados de junções ANTI, SEMI e FULL com base nas estatísticas do otimizador. [#97498](https://github.com/ClickHouse/ClickHouse/pull/97498) ([Hechem Selmi](https://github.com/m-selmi)).
* Otimiza levemente a leitura do Dicionário do índice de texto, melhorando o desempenho geral da análise do índice de texto. [#97519](https://github.com/ClickHouse/ClickHouse/pull/97519) ([Anton Popov](https://github.com/CurtizJ)).
* Acelera a descompressão LZ4 de blocos de 16 bytes em ARM. [#97774](https://github.com/ClickHouse/ClickHouse/pull/97774) ([Raúl Marín](https://github.com/Algunenano)).
* Refatora a tokenização para uma nova interface de callback `forEachToken` de alto desempenho, substituindo a API antiga no estilo iterador para oferecer suporte a SIMD e tokenizadores com estado. Parte de [#90268](https://github.com/ClickHouse/ClickHouse/issues/90268). [#97871](https://github.com/ClickHouse/ClickHouse/pull/97871) ([Amos Bird](https://github.com/amosbird)).
* Melhora o desempenho da análise do índice de texto para consultas com condições combinadas envolvendo colunas indexadas e não indexadas. Antes, a otimização de saída antecipada durante a análise do índice era desabilitada incorretamente nesses casos. [#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).
* Melhora o desempenho de consultas com expressões constantes que geram arrays ou mapas muito longos. [#98287](https://github.com/ClickHouse/ClickHouse/pull/98287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Corrige a análise da condição da chave para chaves primárias `DateTime64` comparadas com constantes inteiras, o que antes resultava em ausência de poda de grânulos. [#98410](https://github.com/ClickHouse/ClickHouse/pull/98410) ([Amos Bird](https://github.com/amosbird)).
* A configuração `optimize_syntax_fuse_functions` vem habilitada por padrão. [#98424](https://github.com/ClickHouse/ClickHouse/pull/98424) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Permite a poda de partições quando o predicado contém qualquer operador de comparação (`=`, `<`, `>`, `!=`) e a chave de partição está encapsulada em uma cadeia de funções determinísticas (por exemplo, `PARTITION BY x` e predicados como `cityHash64(x) % 5 > 2`, `toYYYYMM(x) < 2026`, `toYYYYMM(x) = 2026` ou `toYYYYMM(x) != 2026` passarão a usar a chave de partição para poda). Fecha [#28800](https://github.com/ClickHouse/ClickHouse/issues/28800). [#98432](https://github.com/ClickHouse/ClickHouse/pull/98432) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Permite a otimização de leitura em ordem e a poda pela chave primária quando o tipo de destino de `CAST` é `Nullable` e a conversão é monotônica; por exemplo, com `PRIMARY KEY x`, o ClickHouse pode usar a otimização de leitura em ordem para `ORDER BY x::Nullable(UInt64)` e aplicar a poda pela chave primária a predicados como `WHERE x::Nullable(UInt64) > 500000`. [#98482](https://github.com/ClickHouse/ClickHouse/pull/98482) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Permite poda de índice e pushdown de filtro quando uma coluna inteira é comparada com um literal de ponto flutuante; por exemplo, predicados como `WHERE x < 10.5` agora podem usar a chave primária para poda, e filtros como `prime < 1e9` ou `number < 1e5` agora são aplicados por pushdown nas funções de tabela `primes()` e `numbers()`, em vez de causar execução sem limites. Fecha [#85167](https://github.com/ClickHouse/ClickHouse/issues/85167). [#98516](https://github.com/ClickHouse/ClickHouse/pull/98516) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Otimiza a função de agregação `avgWeighted` usando acumuladores locais em vez de store-forwarding por linha via estado agregado, melhorando o desempenho em até 27% para entradas Nullable. [#98793](https://github.com/ClickHouse/ClickHouse/pull/98793) ([Antonio Andelic](https://github.com/antonio2368)).
* Melhora o desempenho e reduz o uso de memória para funções de janela paralelas em determinados cenários e para workloads de arrayFold com arrays grandes. Isso também pode reduzir a pressão de page faults e melhorar a estabilidade sob limites de memória apertados para as queries afetadas. [#98892](https://github.com/ClickHouse/ClickHouse/pull/98892) ([filimonov](https://github.com/filimonov)).
* Adiciona icolumn::comparetrackat() para merges ordenados. [#99013](https://github.com/ClickHouse/ClickHouse/pull/99013) ([Artem Zuikov](https://github.com/4ertus2)).
* Otimiza `INTERSECT ALL` e `EXCEPT ALL`. [#99097](https://github.com/ClickHouse/ClickHouse/pull/99097) ([Raufs Dunamalijevs](https://github.com/rienath)).
* Adiciona suporte à otimização `read_in_order_use_virtual_row` para leituras em ordem reversa. [#99198](https://github.com/ClickHouse/ClickHouse/pull/99198) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Reduz a contenção de cache em RIGHT e FULL JOINs verificando se JoinUsedFlags está definido antes da gravação. [#99274](https://github.com/ClickHouse/ClickHouse/pull/99274) ([Hechem Selmi](https://github.com/m-selmi)).
* Otimiza `PrefetchingHelper::calcPrefetchLookAhead` substituindo matemática de ponto flutuante por aritmética inteira pura, melhorando o layout do cache de instruções e reduzindo a sobrecarga de ciclos durante loops de agregação. [#99327](https://github.com/ClickHouse/ClickHouse/pull/99327) ([Riyane El Qoqui](https://github.com/riyaneel)).
* Melhora o desempenho de lagos de dados. Em versões anteriores, a leitura de armazenamento de objetos n&#39;o redimensionava o pipeline para o número de threads de processamento. [#99548](https://github.com/ClickHouse/ClickHouse/pull/99548) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

O novo contêiner armazena de 0 a 1 filho inline, sem alocação em heap, o que cobre a maioria dos nós do Keeper. Isso reduz o tamanho de `KeeperMemNode` de 144 para 128 bytes. [#99860](https://github.com/ClickHouse/ClickHouse/pull/99860) ([Antonio Andelic](https://github.com/antonio2368)).
* Retroportado em [#100600](https://github.com/ClickHouse/ClickHouse/issues/100600): Evita o cálculo desnecessário da subcoluna `.size` de String durante a enumeração de subcolunas. [#99941](https://github.com/ClickHouse/ClickHouse/pull/99941) ([Pavel Kruglov](https://github.com/Avogar)).
