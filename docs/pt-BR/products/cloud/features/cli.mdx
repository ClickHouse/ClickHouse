A CLI do ClickHouse (`clickhousectl`, alias `chctl`) permite gerenciar o ClickHouse Cloud a partir de um terminal, de um script ou de um agente de programação. Esta página trata dos recursos da CLI voltados ao Cloud. Para conhecer todos os grupos de comandos, o desenvolvimento local e o comportamento completo da ferramenta, consulte a [referência do clickhousectl](/pt-BR/concepts/features/interfaces/cli).

## O que você pode gerenciar {#what-you-can-manage}

Os comandos `clickhousectl cloud` abrangem:

* **Serviços:** crie, escale, inicie e interrompa serviços do ClickHouse Cloud e execute SQL neles por meio da API de consultas.
* **[Managed Postgres](/pt-BR/products/managed-postgres/overview) (Beta):** crie serviços Postgres, réplicas de leitura e restaurações para um ponto no tempo, além de alterar suas configurações.
* **[ClickPipes](/pt-BR/integrations/clickpipes/home):** faça a ingestão de dados a partir de armazenamento de objetos, Kafka, Kinesis, Pub/Sub, Postgres, MySQL, MongoDB e BigQuery.
* **[ClickStack](/pt-BR/clickstack/overview):** gerencie fontes de dados, dashboards, alertas, webhooks, pesquisas salvas e funções em um serviço [Managed ClickStack](/pt-BR/clickstack/deployment/managed).
* **Funções definidas pelo usuário:** teste UDFs executáveis localmente e depois implante-as em um serviço Cloud.
* **Backups:** liste backups, altere o agendamento de backups e restaure um backup em um novo serviço.
* **Acesso à organização:** organizações, membros, convites, chaves de API e registro de atividades.

Execute `clickhousectl cloud <command> --help` para ver as flags de qualquer comando e as permissões de chave de API que ele exige.

## Instalação {#installation}

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

O script instala `~/.local/bin/clickhousectl` e um alias `chctl`. Certifique-se de que `~/.local/bin` esteja no seu `PATH`. Para npm, pip, uv e outros métodos de instalação, consulte [Instalação](/pt-BR/concepts/features/interfaces/cli#installation).

## Autenticação {#authentication}

O login via OAuth no navegador é read-only. Para criar ou alterar recursos, é necessária uma [chave de API](/pt-BR/products/cloud/features/admin-features/api/openapi) com uma função que permita essa alteração.

```bash
# Read-only: OAuth device flow in your browser
clickhousectl cloud auth login

# Read and write: prompts for the API key and secret, keeping the secret out of shell history
clickhousectl cloud auth login --interactive

# Alternative for scripts
clickhousectl cloud auth login --api-key <key> --api-secret <secret>
```

O login verifica as credenciais e exibe a identidade. Você pode confirmá-la a qualquer momento com `clickhousectl cloud auth whoami`. Se você pertencer a várias organizações, adicione `--org-id <org-id>` (ou `--org-name <name>`) aos comandos do Cloud. Em CI, defina `CLICKHOUSE_CLOUD_API_KEY` e `CLICKHOUSE_CLOUD_API_SECRET` em vez de fazer login. Consulte [Autenticação](/pt-BR/concepts/features/interfaces/cli#authentication) para saber mais sobre a precedência de credenciais e o logout.

## Exemplos {#examples}

### Criar e consultar um serviço {#create-and-query-a-service}

```bash
# Create a service. Save the initial password; it is printed only once.
# Omitting --ip-allow allows all addresses (0.0.0.0/0).
clickhousectl cloud service create --name analytics \
  --provider aws --region us-east-1 \
  --ip-allow '203.0.113.10/32=Office'

# Look up the service ID, then run SQL over the Query API
CH_ID=$(clickhousectl cloud service get --name analytics --json | jq -r .id)
clickhousectl cloud service query "$CH_ID" --query "SELECT version()"
```

A criação retorna antes de o serviço entrar em execução. Execute `clickhousectl cloud service get "$CH_ID"` periodicamente até que `state` seja `running`.

Na primeira consulta feita com chave de API, o clickhousectl adiciona sua chave de API ao Endpoint da API de Consultas do serviço, criando o endpoint, se necessário; nenhuma chave nova é criada. Para que a operação falhe nesse caso, passe `--no-auto-enable`. Com OAuth, `service query` executa apenas instruções `SELECT` read-only. A API de consultas expira após cerca de 30 segundos; portanto, use o `clickhouse client` para consultas longas e cargas em massa.

### Criar um serviço gerenciado de Postgres {#create-a-managed-postgres-service}

```bash
clickhousectl cloud postgres create --name app-db \
  --provider aws --region us-east-1 --size c6gd.xlarge --pg-version 18 \
  --ip-allow '203.0.113.10/32:5432=Office'
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output ca.pem
```

Somente `create` retorna a senha e a string de conexão, então guarde-as. Se `--ip-allow` for omitido, as portas 5432 e 6432 ficarão abertas para todos os endereços. Aguarde até que `state` seja `running` e, em seguida, conecte-se com `psql` usando o certificado de CA.

### Inspecionar ClickPipes, ClickStack e backups {#inspect-clickpipes-clickstack-and-backups}

```bash
clickhousectl cloud clickpipe list "$CH_ID"
clickhousectl cloud clickstack source list <clickstack-service-id>
clickhousectl cloud backup list "$CH_ID"
```

Esses comandos de leitura funcionam com OAuth. Para criar um ClickPipe ou alterar um recurso do ClickStack, é necessária uma chave de API; consulte os guias do repositório abaixo.

### Implantar uma função definida pelo usuário {#deploy-a-user-defined-function}

```bash
# Uploads clickhouse/udfs/my_udf/, waits for the build, then attaches that version to the service
clickhousectl cloud udf deploy my_udf --service "$CH_ID"
```

Teste a função primeiro em um servidor local com `clickhousectl local udf deploy my_udf`.

## Saída JSON e agentes de programação {#json-output}

Os comandos do Cloud aceitam `--json`, e a CLI seleciona JSON automaticamente ao detectar um agente de programação. Nesse caso, `cloud service query` passa a usar `JSONEachRow` por padrão; por isso, scripts que interpretam a saída desse comando devem informar `--format`, por exemplo `--format TabSeparated`. Consulte [Saída JSON](/pt-BR/concepts/features/interfaces/cli#json-output) e [Códigos de saída](/pt-BR/concepts/features/interfaces/cli#exit-codes). Instale as ClickHouse Agent Skills com `clickhousectl skills`.
