A proteção contra exclusão de serviço é uma configuração por serviço que bloqueia a exclusão até que você a desative. Use-a nos serviços do ClickHouse Cloud que você quer proteger contra remoção acidental pelo Console do Cloud, pela [API do ClickHouse Cloud](/pt-BR/cloud/manage/api/api-overview) ou pelo Terraform.

<Note>
  Isso se aplica a serviços do ClickHouse Cloud. Não se aplica a serviços do [ClickHouse Managed Postgres](/pt-BR/cloud/managed-postgres).
</Note>

A proteção vem desativada por padrão. Desativá-la não exclui o serviço. Um serviço protegido continua em execução, e as consultas, o escalonamento e as demais configurações permanecem inalterados.

Enquanto a proteção estiver ativada, as requisições de exclusão são recusadas. `DELETE /v1/organizations/{organizationId}/services/{serviceId}` retorna HTTP `409` até que você desative a proteção. Além disso, o serviço precisa estar parado para poder ser excluído. Em seguida, a exclusão é executada de forma assíncrona.

## Quem pode alterá-la {#who-can-change-it}

Ativar ou desativar a proteção requer a permissão [`control-plane:service:delete`](/pt-BR/cloud/security/console-roles). Os administradores da organização têm essa permissão. Consulte [Papéis e permissões do console](/pt-BR/cloud/security/console-roles).

Para ativar a proteção, também é necessário que a proteção contra exclusão esteja disponível para a organização. As organizações do ClickHouse Cloud contam com esse recurso. Uma operação de criação ou atualização que define `deletionProtection` como `true` retorna HTTP `400` quando a organização não conta com ele. A desativação da proteção não passa por essa verificação: uma requisição que define `deletionProtection` como `false` é aceita, inclusive para um serviço que já está protegido.

| Ação                                                 | Permissão                                                                                                                    |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Ativar ou desativar a opção no console               | `control-plane:service:delete` no serviço                                                                                    |
| Definir `deletionProtection` em um serviço existente | `control-plane:service:manage` e `control-plane:service:delete` no serviço                                                   |
| Enviar o valor que o serviço já tem                  | Apenas `control-plane:service:manage`. Repetir o valor atual não exige `control-plane:service:delete`                        |
| Criar um serviço com `deletionProtection: true`      | `control-plane:organization:create-service` e `control-plane:service:delete` concedida para todos os serviços da organização |
| Excluir o serviço                                    | `control-plane:service:delete` no serviço. O serviço precisa estar parado e a proteção precisa estar desativada              |

Os serviços ClickStack não podem ser atualizados pela Cloud API. Ative ou desative a proteção contra exclusão desses serviços no console.

## Ativar ou desativar a proteção no console {#console}

Abra o serviço e acesse **Configurações**. Em **Proteção contra exclusão**, use a chave de alternância. A alteração é salva imediatamente.

A chave fica disponível para qualquer pessoa com a permissão `control-plane:service:delete` nesse serviço. Com a proteção ativada, o console bloqueia a ação de exclusão até que você desative a chave.

## Configure com a Cloud API {#cloud-api}

O objeto de serviço tem um campo booleano, `deletionProtection`. Defina-o ao criar um serviço (`POST /v1/organizations/{organizationId}/services`) ou ao atualizar um serviço existente (`PATCH /v1/organizations/{organizationId}/services/{serviceId}`). As respostas das operações de consulta (get) e listagem (list) incluem esse campo. Quando ele está ausente, o serviço não está protegido.

Ative a proteção:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": true}'
```

Para excluir um serviço protegido, desative a proteção, interrompa o serviço, aguarde até que ele pare por completo e, em seguida, exclua-o. `PATCH .../state` com `"command": "stop"` requer `control-plane:service:manage` e retorna antes de o serviço ter parado. Uma exclusão solicitada enquanto o serviço ainda está em `stopping` é rejeitada. Uma exclusão de um serviço protegido retorna `409` e o serviço permanece inalterado.

Desative a proteção:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": false}'
```

Solicite a interrupção:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID/state" \
  -d '{"command": "stop"}'
```

Aguarde até que `result.state` seja `stopped` e, em seguida, exclua:

```bash
while [ "$(curl --silent --user "$KEY_ID:$KEY_SECRET" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  | jq -r '.result.state')" != "stopped" ]; do
  sleep 5
done

curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X DELETE \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID"
```

## Terraform {#terraform}

<Note>
  `deletion_protection` não está disponível na versão mais recente publicada do provider, a [v3.43.0](https://github.com/ClickHouse/terraform-provider-clickhouse/releases/tag/v3.43.0). O atributo foi adicionado em [terraform-provider-clickhouse#799](https://github.com/ClickHouse/terraform-provider-clickhouse/pull/799), que já foi mesclado, mas ainda não faz parte de nenhum lançamento. O exemplo abaixo falha na v3.43.0 com um erro de argumento sem suporte. Use um lançamento do provider posterior à v3.43.0 que inclua o atributo.
</Note>

O recurso `clickhouse_service` aceita `deletion_protection`. Enquanto ele estiver definido como `true`, o `terraform destroy` e qualquer alteração que exija substituir o serviço falharão. Defina-o como `false` e aplique essa alteração separadamente; depois, destrua o serviço.

Remover `deletion_protection` da configuração não altera o valor atual da configuração.

```hcl
resource "clickhouse_service" "example" {
  # ...

  deletion_protection = true
}
```

Para definir `deletion_protection = true` ao criar um serviço, é necessária uma chave de API com permissão para excluir todos os serviços da organização. Para alterar essa configuração posteriormente, é necessária permissão de exclusão nesse serviço.
