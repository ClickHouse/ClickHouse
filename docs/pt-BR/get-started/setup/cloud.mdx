### Adicionar dados com o Console SQL {#add-data-using-the-sql-console}

        Assim como a maioria dos sistemas de gerenciamento de bancos de dados, o ClickHouse agrupa logicamente as tabelas em **bancos de dados**. Use o comando [`CREATE DATABASE`](/pt-BR/reference/statements/create/database) para criar um novo banco de dados no ClickHouse:

        ```sql
        CREATE DATABASE IF NOT EXISTS helloworld
        ```

        Execute o seguinte comando para criar uma tabela chamada `my_first_table` no banco de dados `helloworld`:

        ```sql
        CREATE TABLE helloworld.my_first_table
        (
            user_id UInt32,
            message String,
            timestamp DateTime,
            metric Float32
        )
        ENGINE = MergeTree()
        PRIMARY KEY (user_id, timestamp)
        ```

        No exemplo acima, `my_first_table` é uma tabela [`MergeTree`](/pt-BR/reference/engines/table-engines/mergetree-family/mergetree) com quatro colunas:

        * `user_id`:  um inteiro sem sinal de 32 bits ([UInt32](/pt-BR/reference/data-types/int-uint))
        * `message`: um tipo de dado [String](/pt-BR/reference/data-types/string), que substitui tipos como `VARCHAR`, `BLOB`, `CLOB` e outros de demais sistemas de banco de dados
        * `timestamp`: um valor [DateTime](/pt-BR/reference/data-types/datetime), que representa um instante no tempo
        * `metric`: um número de ponto flutuante de 32 bits ([Float32](/pt-BR/reference/data-types/float))

        <Info>
          **Motores de tabela**

          Os motores de tabela determinam:

          * Como e onde os dados são armazenados
          * Quais consultas são compatíveis
          * Se os dados são replicados ou não

          <br />

          Há muitos motores de tabela à disposição, mas, para uma tabela simples em um servidor do ClickHouse de nó único, [`MergeTree`](/pt-BR/reference/engines/table-engines/mergetree-family/mergetree) provavelmente será a sua escolha.
        </Info>

#### Breve introdução às chaves primárias {#a-brief-intro-to-primary-keys}

        Antes de prosseguir, é importante entender como as chaves primárias funcionam no ClickHouse (a implementação
        das chaves primárias pode surpreender!):

        * as chaves primárias no ClickHouse ***não são únicas*** para cada linha de uma tabela

        A chave primária de uma tabela do ClickHouse determina como os dados são ordenados ao serem gravados em disco. A cada 8,192 linhas ou 10MB de
        dados (o que se chama de **granularidade do índice**), é criada uma entrada no arquivo de índice da chave primária. Esse conceito de granularidade
        gera um **índice esparso** que cabe facilmente na memória, e os grânulos representam um stripe com a menor quantidade de
        dados de coluna processada durante consultas `SELECT`.

        A chave primária pode ser definida com o parâmetro `PRIMARY KEY`. Se você definir uma tabela sem especificar uma `PRIMARY KEY`,
        a chave passa a ser a tupla especificada na cláusula `ORDER BY`. Se você especificar tanto uma `PRIMARY KEY` quanto um `ORDER BY`, a chave primária deverá ser um subconjunto da ordenação.

        A chave primária também é a sorting key, que é uma tupla de `(user_id, timestamp)`.  Portanto, os dados armazenados em cada
        arquivo de coluna serão ordenados por `user_id` e, em seguida, por `timestamp`.

        Para uma análise aprofundada dos conceitos fundamentais do ClickHouse, consulte [&quot;Conceitos fundamentais&quot;](/pt-BR/concepts/core-concepts/index).

#### Inserir dados na sua tabela {#insert-data-into-your-table}

        Você pode usar o já conhecido comando [`INSERT INTO TABLE`](/pt-BR/reference/statements/insert-into) com o ClickHouse, mas é importante entender que cada insert em uma tabela [`MergeTree`](/pt-BR/reference/engines/table-engines/mergetree-family/mergetree) cria uma **parte** no armazenamento.

        <Tip>
          **Melhor prática do ClickHouse**

          Insira um grande número de linhas por lote — dezenas de milhares ou até milhões de
          linhas de uma só vez. Não se preocupe: o ClickHouse lida facilmente com esse volume de dados, e isso vai [economizar dinheiro](/pt-BR/concepts/best-practices/selecting-an-insert-strategy#batch-inserts-if-synchronous), já que menos solicitações de gravação serão enviadas ao seu serviço.
        </Tip>

        <br />

        Mesmo em um exemplo simples, vamos inserir mais de uma linha por vez:

        ```sql
        INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
            (101, 'Hello, ClickHouse!',                                 now(),       -1.0    ),
            (102, 'Insert a lot of rows per batch',                     yesterday(), 1.41421 ),
            (102, 'Sort your data based on your commonly-used queries', today(),     2.718   ),
            (101, 'Granules are the smallest chunks of data read',      now() + 5,   3.14159 )
        ```

        <Note>
          Observe que a coluna `timestamp` é populada com várias funções de [**Date**](/pt-BR/reference/data-types/date) e [**DateTime**](/pt-BR/reference/data-types/datetime). O ClickHouse oferece centenas de funções úteis, que você pode [consultar na seção **Funções**](/pt-BR/reference/functions/index).
        </Note>

        Vamos verificar se funcionou:

        ```sql
        SELECT * FROM helloworld.my_first_table
        ```

### Adicionar dados com o Cliente ClickHouse {#add-data-using-the-clickhouse-client}

        Você também pode se conectar ao seu serviço do ClickHouse Cloud usando uma ferramenta de linha de comando chamada [**clickhouse client**](/pt-BR/concepts/features/interfaces/client). Clique em `Connect` no menu à esquerda para acessar esses detalhes. Na caixa de diálogo, selecione `Native` no menu suspenso:

        <div className="ch-image-lg">
          <Frame>
            ![detalhes de conexão do cliente clickhouse](/images/_snippets/client_details.webp)
          </Frame>
        </div>

        <br />

        1. Instale o [ClickHouse](/pt-BR/get-started/setup/self-managed/quick-install).

        2. Execute o comando, substituindo o hostname, o nome de usuário e a senha pelos seus:

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password>
        ```

        Se aparecer o prompt com a carinha sorridente, você já pode executar consultas!

        ```response
        :)
        ```

        3. Experimente executar a seguinte consulta:

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        ```

        Observe que a resposta é retornada em um formato de tabela bem organizado:

        ```response
        ┌─user_id─┬─message────────────────────────────────────────────┬───────────timestamp─┬──metric─┐
        │     102 │ Insert a lot of rows per batch                     │ 2022-03-21 00:00:00 │ 1.41421 │
        │     102 │ Sort your data based on your commonly-used queries │ 2022-03-22 00:00:00 │   2.718 │
        │     101 │ Hello, ClickHouse!                                 │ 2022-03-22 14:04:09 │      -1 │
        │     101 │ Granules are the smallest chunks of data read      │ 2022-03-22 14:04:14 │ 3.14159 │
        └─────────┴────────────────────────────────────────────────────┴─────────────────────┴─────────┘

        4 rows in set. Elapsed: 0.008 sec.
        ```

        4. Adicione uma cláusula [`FORMAT`](/pt-BR/reference/statements/select/format) para especificar um dos [diversos formatos de saída compatíveis com o ClickHouse](/pt-BR/reference/formats/index):

        <br />

        ```sql
        SELECT *
        FROM helloworld.my_first_table
        ORDER BY timestamp
        FORMAT TabSeparated
        ```

        Na consulta acima, a saída é retornada no formato tab-separated:

        ```response
        Query id: 3604df1c-acfd-4117-9c56-f86c69721121

        102 Insert a lot of rows per batch      2022-03-21 00:00:00     1.41421
        102 Sort your data based on your commonly-used queries  2022-03-22 00:00:00     2.718
        101 Hello, ClickHouse!  2022-03-22 14:04:09     -1
        101 Granules are the smallest chunks of data read       2022-03-22 14:04:14     3.14159

        4 rows in set. Elapsed: 0.005 sec.
        ```

        5. Para sair do `clickhouse client`, digite o comando **exit**:

        <br />

        ```bash
        exit
        ```

### Enviar um arquivo {#upload-a-file}

        Uma tarefa comum ao dar os primeiros passos com um banco de dados é inserir dados que você já tem em arquivos. Disponibilizamos online alguns
        dados de amostra que representam dados de clickstream e que você pode inserir: eles incluem um ID de usuário, a URL visitada e
        o timestamp do evento.

        Suponha que tenhamos o seguinte texto em um arquivo CSV chamado `data.csv`:

        ```bash title="data.csv"
        102,This is data in a file,2022-02-22 10:43:28,123.45
        101,It is comma-separated,2022-02-23 00:00:00,456.78
        103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
        ```

        1. O comando a seguir insere os dados em `my_first_table`:

        <br />

        ```bash
        ./clickhouse client --host HOSTNAME.REGION.CSP.clickhouse.cloud \
        --secure --port 9440 \
        --user default \
        --password <password> \
        --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
        ```

        2. Observe que as novas linhas já aparecem na tabela ao consultá-la no SQL Console:

        <br />
