<Info>
  **Usuários do Windows**

  O ClickHouse roda nativamente em Linux e macOS. No Windows, execute estas etapas dentro do
  [Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/about).
</Info>

A ClickHouse CLI (`clickhousectl`, alias `chctl`) instala e gerencia versões locais
do ClickHouse, executa servidores locais do ClickHouse e do Postgres, executa consultas
e gerencia o ClickHouse Cloud. Esta página mostra como instalar a CLI,
iniciar um servidor local do ClickHouse e se conectar a ele.

Se você usou o script de [instalação rápida](/pt-BR/get-started/setup/self-managed/quick-install),
o `clickhousectl` já está instalado. Pule para
[Instale o ClickHouse](#cli-install-clickhouse).

<Steps>
  <Step title="Instale a CLI do ClickHouse" id="install-the-cli">
    O script de instalação é compatível com macOS e Linux em x86&#95;64 e ARM64:

    ```bash
    curl -fsSL https://clickhouse.com/cli | sh
    ```

    O script instala o `clickhousectl` em `~/.local/bin` e cria um alias `chctl`
    no mesmo diretório. Se o script informar que `~/.local/bin` não está no seu `PATH`, adicione-o
    e inclua a mesma linha no arquivo de perfil do seu shell (`~/.bashrc`, `~/.zshrc`) para as próximas
    sessões:

    ```bash
    export PATH="$HOME/.local/bin:$PATH"
    ```

    <Accordion title="Outros métodos de instalação">
      | Ferramenta                                   | Comando                         |
      | -------------------------------------------- | ------------------------------- |
      | npm                                          | `npm install -g clickhousectl`  |
      | uv                                           | `uv tool install clickhousectl` |
      | pipx                                         | `pipx install clickhousectl`    |
      | pip                                          | `pip install clickhousectl`     |
      | cargo-binstall                               | `cargo binstall clickhousectl`  |
      | Cargo, a partir do código-fonte (Rust 1.94+) | `cargo install clickhousectl`   |

      Somente o script de instalação e o npm criam o alias `chctl`.
    </Accordion>

    Para verificar se há um lançamento mais recente da CLI e instalá-lo:

    ```bash
    clickhousectl update --check
    clickhousectl update
    ```
  </Step>

  <Step title="Instale o ClickHouse" id="cli-install-clickhouse">
    Instale a versão mais recente do ClickHouse e defina-a como padrão:

    ```bash
    clickhousectl local use latest
    ```

    `local use` instala a versão caso ela ainda não esteja presente, define-a como sua
    versão padrão e cria um link simbólico `clickhouse` em `~/.local/bin`, permitindo que você execute o
    binário `clickhouse` diretamente. Assim, qualquer etapa posterior desta documentação que execute um
    comando `clickhouse` funcionará sem alterações, desde que `~/.local/bin` esteja no seu `PATH`.

    Você também pode selecionar o lançamento de suporte de longo prazo (LTS) mais recente ou uma
    versão específica:

    ```bash
    clickhousectl local use lts             # Latest LTS release
    clickhousectl local use 26.8            # Latest 26.8.x.x release
    clickhousectl local use 26.8.1.1760     # Exact version
    ```

    Para ver quais versões secundárias estão disponíveis para download e quais versões você
    já tem instaladas:

    ```bash
    clickhousectl local list --remote
    clickhousectl local list
    ```

    <Info>
      **use vs. install**

      `clickhousectl local use <version>` instala uma versão *e* a define como sua
      versão padrão, atualizando o link simbólico `clickhouse`. `clickhousectl local install <version>`
      apenas baixa uma versão; ela só passa a ser a padrão se você ainda não tiver
      nenhuma versão padrão definida, e o link simbólico não é atualizado. Para definir a versão padrão sem criar nem
      atualizar o link simbólico, use `clickhousectl local use <version> --no-global`.
    </Info>
  </Step>

  <Step title="Inicie o clickhouse-server" id="cli-start-clickhouse-server">
    O `clickhousectl` restringe o escopo dos servidores locais ao diretório em que você o executa. Crie um
    diretório de projeto e inicie um servidor nele:

    ```bash
    mkdir my-project && cd my-project
    clickhousectl local server start
    ```

    ```response
    Server 'default' started in background (PID: 14705)
      HTTP port: 8123
      TCP port:  9000
      Version:   26.9.1.1312
    ```

    O servidor é executado em segundo plano e se chama `default`. Seus dados ficam em
    `./.clickhouse/`, então execute os comandos `clickhousectl local` seguintes a partir do mesmo
    diretório; o `clickhousectl` não procura em diretórios pai. O servidor escuta
    na porta HTTP `8123` e na porta TCP `9000` ou, se elas estiverem ocupadas, em portas livres.
    Para escolher as portas, use `--http-port` e `--tcp-port`. Para executar mais de um
    servidor, dê um nome a cada um, como em `clickhousectl local server start dev`.

    Para verificar se ele está em execução:

    ```bash
    clickhousectl local server list
    ```

    ```response
    | Name    | Status  | PID   | Version     | HTTP Port | TCP Port |
    |---------|---------|-------|-------------|-----------|----------|
    | default | running | 14705 | 26.9.1.1312 | 8123      | 9000     |

    1 server, 1 running
    ```
  </Step>

  <Step title="Inicie o clickhouse-client" id="cli-start-clickhouse-client">
    No mesmo diretório, conecte-se ao servidor com o `clickhouse-client`:

    ```bash
    clickhousectl local client
    ```

    O comando `local client` se conecta ao servidor chamado `default` e usa a mesma
    versão do ClickHouse que o servidor. Para se conectar a outro servidor, informe um nome,
    como em `clickhousectl local client dev`. Você verá algo semelhante a isto:

    ```response
    ClickHouse client version 26.9.1.1312 (official build).
    Connecting to localhost:9000 as user default.
    Connected to ClickHouse server version 26.9.1.

    local-host :)
    ```

    Agora você já pode começar a enviar comandos SQL para o ClickHouse! Digite `exit` para
    sair do cliente.

    Para executar uma única consulta sem abrir uma sessão interativa, use `-q`:

    ```bash
    clickhousectl local client -q "SELECT version()"
    ```

    <Tip>
      O guia [Criando tabelas no ClickHouse](/pt-BR/get-started/quickstarts/creating-tables) mostra, passo a passo, como criar tabelas e inserir dados.
    </Tip>
  </Step>

  <Step title="Pare o servidor" id="cli-stop-clickhouse-server">
    O servidor continua em execução em segundo plano até que você o interrompa. Para interrompê-lo, use o
    mesmo diretório:

    ```bash
    clickhousectl local server stop
    ```

    Ao parar o servidor, os dados dele são preservados para a próxima execução de `clickhousectl local server start`.

    <Warning>
      `clickhousectl local server remove` exclui permanentemente os dados de um servidor parado.
    </Warning>
  </Step>
</Steps>

## Próximos passos {#next-steps}

* **Execute o Postgres localmente.** Com o Docker em execução, inicie um servidor Postgres local
  e conecte-se a ele com `psql`:

  ```bash
  clickhousectl local postgres start
  clickhousectl local postgres client
  ```

* **Conecte-se ao ClickHouse Cloud.** Crie uma conta ou faça login em uma conta
  existente. O login pelo navegador é read-only; para criar ou alterar recursos do Cloud, é necessária uma
  chave de API, solicitada pelo comando `clickhousectl cloud auth login --interactive`.

  ```bash
  clickhousectl cloud auth signup
  clickhousectl cloud auth login
  ```

* **Conheça o restante da CLI.** Consulte a [referência do clickhousectl](/pt-BR/concepts/features/interfaces/cli)
  ou execute `clickhousectl --help`.
