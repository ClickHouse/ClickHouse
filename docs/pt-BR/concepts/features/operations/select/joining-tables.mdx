## Tipos de JOIN e rigor {#join-types-and-strictness}

Todo JOIN tem um tipo e um rigor. O tipo determina quais linhas sem correspondência são incluídas no resultado. O rigor determina quantas correspondências são retornadas para cada linha. Os algoritmos capazes de executar um JOIN dependem de ambos. Para a sintaxe completa e os JOINs adicionais `SEMI`, `ANTI`, `CROSS` e `PASTE`, consulte a [referência da cláusula `JOIN`](/pt-BR/reference/statements/select/join#supported-types-of-join).

### `INNER JOIN` {#inner-join}

<div className="ch-image-sm">
  <Frame>
    ![Diagrama de Venn de um INNER JOIN: é retornada apenas a interseção das linhas das tabelas à esquerda e da direita com chaves de junção correspondentes, como o produto cartesiano das linhas correspondentes](/images/guides/join-algorithms/inner-join.png)
  </Frame>
</div>

Para cada par de linhas com chaves de junção correspondentes, um `INNER JOIN` retorna as colunas da linha da esquerda combinadas com as colunas da linha da direita. Se uma linha tiver mais de uma correspondência, todas elas serão retornadas, de modo que o resultado contém o produto cartesiano das linhas com a mesma chave. A palavra-chave `INNER` pode ser omitida.

### `LEFT`, `RIGHT` e `FULL OUTER JOIN` {#outer-join}

<div className="ch-image-lg">
  <Frame>
    ![Diagramas de Venn de LEFT, RIGHT e FULL OUTER JOIN: cada um retorna o produto cartesiano das linhas correspondentes, mais as linhas sem correspondência da tabela à esquerda, da right table ou de ambas as tabelas](/images/guides/join-algorithms/outer-join.png)
  </Frame>
</div>

Um outer JOIN retorna as mesmas linhas que um `INNER JOIN` e, além delas, as linhas sem correspondência:

* Um `LEFT OUTER JOIN` também retorna cada linha da tabela à esquerda que não tem correspondência, preenchendo as colunas da tabela à direita com valores default.
* Um `RIGHT OUTER JOIN` também retorna cada linha da tabela à direita que não tem correspondência, preenchendo as colunas da tabela à esquerda com valores default.
* Um `FULL OUTER JOIN` retorna as linhas sem correspondência de ambas as tabelas.

A configuração [`join_use_nulls`](/pt-BR/reference/settings/session-settings/join#join_use_nulls) faz com que o ClickHouse retorne `NULL` em vez de valores default. A palavra-chave `OUTER` pode ser omitida.

### Rigor `ALL` e `ANY` {#all-and-any-strictness}

<div className="ch-image-lg">
  <Frame>
    ![Diagramas de Venn de LEFT, RIGHT e INNER ANY JOIN: cada um retorna as linhas correspondentes sem produto cartesiano, além das linhas sem correspondência da tabela à esquerda ou da right table, no caso de LEFT e RIGHT](/images/guides/join-algorithms/any-join.png)
  </Frame>
</div>

Com o rigor `ALL`, um JOIN retorna todas as correspondências, conforme descrito para os tipos de JOIN acima. Com o rigor `ANY`, um JOIN retorna no máximo uma correspondência para cada linha e não gera produto cartesiano:

* Um `LEFT ANY JOIN` retorna cada linha do lado esquerdo uma única vez, combinada com uma linha correspondente do lado direito ou com valores default.
* Um `RIGHT ANY JOIN` retorna cada linha do lado direito uma única vez, combinada com uma linha correspondente do lado esquerdo ou com valores default.
* Um `INNER ANY JOIN` retorna apenas linhas com correspondência e usa cada linha de qualquer uma das tabelas no máximo uma vez.

Quando há várias linhas correspondentes, não é definido qual delas o `ANY` retorna. A configuração [`join_any_take_last_row`](/pt-BR/reference/settings/session-settings/join#join_any_take_last_row) altera qual linha é selecionada. JOINs `ANY FULL` não são suportados. Quando uma consulta não especifica o rigor, aplica-se a configuração [`join_default_strictness`](/pt-BR/reference/settings/session-settings/join#join_default_strictness).

A consulta a seguir mostra um `LEFT ANY JOIN`. A tabela do lado direito contém duas linhas para cada uma das chaves `2` e `3`:

```sql
WITH
    left_table AS (SELECT * FROM VALUES('c UInt32', 1, 2, 3)),
    right_table AS (SELECT * FROM VALUES('c UInt32', 2, 2, 3, 3, 4))
SELECT
    l.c AS l_c,
    r.c AS r_c
FROM left_table AS l
LEFT ANY JOIN right_table AS r ON l.c = r.c;
```

```response
┌─l_c─┬─r_c─┐
│   1 │   0 │
│   2 │   2 │
│   3 │   3 │
└─────┴─────┘
```

Com o rigor `ALL`, a mesma consulta retorna cinco linhas, pois cada uma das chaves `2` e `3` corresponde a duas linhas da tabela à direita. Com `INNER ANY JOIN`, ela retorna apenas as linhas das chaves `2` e `3`.

### `ASOF JOIN` {#asof-join}

<div className="ch-image-sm">
  <Frame>
    ![Diagrama de Venn de um ASOF JOIN: linhas cujas chaves de junção não correspondem exatamente são unidas, retornando a correspondência mais próxima para cada linha, sem produto cartesiano](/images/guides/join-algorithms/asof-join.png)
  </Frame>
</div>

Um `ASOF JOIN` une linhas que não têm correspondência exata. No ClickHouse, `ASOF` é um tipo de rigor combinado com um JOIN `INNER` ou `LEFT`. A cláusula `ON` contém condições de igualdade e exatamente uma condição de correspondência mais próxima, que usa `>`, `>=`, `<` ou `<=`. Para cada linha do lado esquerdo, o ClickHouse seleciona, entre as linhas do lado direito que satisfazem as condições de igualdade, aquela mais próxima de acordo com a condição de correspondência mais próxima. Cada linha do lado esquerdo é unida a, no máximo, uma linha do lado direito.

O `ASOF JOIN` é normalmente usado com séries temporais. A consulta a seguir une cada negociação à cotação mais recente do mesmo símbolo no momento da negociação ou antes dele:

```sql
WITH
    trades AS (SELECT * FROM VALUES('symbol String, volume UInt32, time DateTime',
        ('ABC', 200, '2023-02-22 14:09:05'),
        ('ABC', 300, '2023-02-22 14:09:28'))),
    quotes AS (SELECT * FROM VALUES('symbol String, time DateTime, price Decimal(10, 2)',
        ('ABC', '2023-02-22 14:09:00', 32.11),
        ('ABC', '2023-02-22 14:09:10', 32.12),
        ('ABC', '2023-02-22 14:09:20', 32.15),
        ('ABC', '2023-02-22 14:09:30', 32.20)))
SELECT
    t.symbol,
    t.volume,
    t.time AS trade_time,
    q.time AS closest_quote_time,
    q.price AS quote_price,
    t.volume * q.price AS final_price
FROM trades AS t
ASOF LEFT JOIN quotes AS q ON t.symbol = q.symbol AND t.time >= q.time
ORDER BY trade_time;
```

```response
┌─symbol─┬─volume─┬──────────trade_time─┬──closest_quote_time─┬─quote_price─┬─final_price─┐
│ ABC    │    200 │ 2023-02-22 14:09:05 │ 2023-02-22 14:09:00 │       32.11 │        6422 │
│ ABC    │    300 │ 2023-02-22 14:09:28 │ 2023-02-22 14:09:20 │       32.15 │        9645 │
└────────┴────────┴─────────────────────┴─────────────────────┴─────────────┴─────────────┘
```

A negociação das `14:09:05` é unida à cotação das `14:09:00`, e a negociação das `14:09:28` é unida à cotação das `14:09:20`. As cotações das `14:09:10` e das `14:09:30` não são a cotação anterior mais próxima de nenhuma negociação.

Para saber quais tipos de coluna são compatíveis com a coluna de correspondência mais próxima e conhecer a sintaxe `USING`, consulte [Uso do ASOF JOIN](/pt-BR/reference/statements/select/join#asof-join-usage).
