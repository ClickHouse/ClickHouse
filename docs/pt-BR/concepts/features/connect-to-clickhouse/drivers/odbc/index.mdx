O driver ODBC do ClickHouse oferece uma interface em conformidade com os padrões para conectar aplicações compatíveis com ODBC ao
ClickHouse. Ele implementa a API ODBC e permite que aplicações, ferramentas de BI e ambientes de script executem consultas
SQL, obtenham resultados e interajam com o ClickHouse por meio de mecanismos já conhecidos.

O driver se comunica com o servidor do ClickHouse usando o [protocolo HTTP](/pt-BR/concepts/features/connect-to-clickhouse/protocols/http), que é o principal
protocolo compatível em todas as implantações do ClickHouse. Isso permite que o driver funcione de forma consistente em diversos
ambientes, incluindo instalações locais, serviços gerenciados em nuvem e ambientes em que apenas o acesso via HTTP está
disponível.

O código-fonte do driver está disponível no
[repositório ClickHouse-ODBC no GitHub](https://github.com/ClickHouse/clickhouse-odbc).

<Tip>
  Para obter melhor compatibilidade, recomendamos fortemente atualizar seu servidor do ClickHouse para a versão 24.11 ou posterior.
</Tip>

<Note>
  Este driver está em desenvolvimento ativo. Algumas funcionalidades do ODBC talvez ainda não estejam totalmente implementadas. A versão atual
  se concentra em oferecer a conectividade essencial e as funcionalidades principais do ODBC, com funcionalidades adicionais previstas para versões
  futuras.

  Seu feedback é muito valioso e ajuda a definir a prioridade de novas funcionalidades e melhorias. Se você encontrar
  limitações, funcionalidades ausentes ou comportamentos inesperados, compartilhe suas observações ou solicitações de funcionalidades no
  rastreador de issues em
  [https://github.com/ClickHouse/clickhouse-odbc/issues](https://github.com/ClickHouse/clickhouse-odbc/issues)
</Note>

## Testes {#testing}

Você pode testar o driver executando este script simples do PowerShell. Copie o texto abaixo, defina sua URL, usuário e senha e
cole o texto no prompt de comando do PowerShell — após executar `$reader.GetValue(0)`, a versão do seu servidor ClickHouse
deverá ser exibida.

```powershell
$url = "http://127.0.0.1:8123/"
$username = "default"
$password = ""
$conn = New-Object System.Data.Odbc.OdbcConnection("`
    Driver={ClickHouse ODBC Driver (Unicode)};`
    Url=$url;`
    Username=$username;`
    Password=$password")
$conn.Open()
$cmd = $conn.CreateCommand()
$cmd.CommandText = "select version()"
$reader = $cmd.ExecuteReader()
$reader.Read()
$reader.GetValue(0)
$reader.Close()
$conn.Close()
```

## Parâmetros de configuração {#configuration-parameters}

Os parâmetros abaixo representam as configurações mais utilizadas para estabelecer uma conexão com o driver ODBC do ClickHouse.
Eles abrangem as opções essenciais de autenticação, comportamento da conexão e tratamento de dados. A lista completa de
parâmetros compatíveis está disponível na página do projeto no GitHub
[https://github.com/ClickHouse/clickhouse-odbc](https://github.com/ClickHouse/clickhouse-odbc).

* `Url`: Especifica o endpoint HTTP(S) completo do servidor do ClickHouse, incluindo o protocolo, o host, a porta e o
  caminho opcional.
* `Username`: O nome de usuário utilizado para autenticação no servidor do ClickHouse.
* `Password`: A senha associada ao nome de usuário especificado. Se não for informada, o driver se conecta sem autenticação
  por senha.
* `Database`: O banco de dados padrão a ser usado na conexão.
* `Timeout`: O tempo máximo (em segundos) que o driver aguarda uma resposta do servidor antes de abortar a requisição.
* `ClientName`: Um identificador personalizado enviado ao servidor do ClickHouse como parte dos metadados do cliente. Útil para rastrear ou
  distinguir o tráfego de diferentes aplicações. Este parâmetro passa a fazer parte do cabeçalho User-Agent nas requisições HTTP
  geradas pelo driver.
* `Compression`: Habilita ou desabilita a compressão HTTP dos payloads de requisição e resposta. Quando habilitada, pode reduzir
  o uso de largura de banda e melhorar o desempenho com grandes conjuntos de resultados.
* `SqlCompatibilitySettings`: Habilita configurações de consulta que fazem o ClickHouse se comportar de forma mais parecida com um banco de dados
  relacional tradicional. Isso é útil quando as consultas são geradas automaticamente por ferramentas de terceiros, como o Power BI. Essas
  ferramentas geralmente desconhecem certos comportamentos específicos do ClickHouse e podem gerar consultas que resultam em erros ou
  resultados inesperados. Consulte [Configurações do ClickHouse usadas pelo parâmetro de configuração SqlCompatibilitySettings
  ](#sql-compatibility-settings) para mais detalhes.

Veja a seguir alguns exemplos de strings de conexão completas passadas ao driver para estabelecer uma conexão.

* Um servidor do ClickHouse instalado localmente em uma instância WSL

```plaintext
Driver={ClickHouse ODBC Driver (Unicode)};Url=http://localhost:8123/;Username=default
```

* Uma instância do ClickHouse Cloud.

```plaintext
Driver={ClickHouse ODBC Driver (Unicode)};Url=https://you-instance-url.gcp.clickhouse.cloud:8443/;Username=default;Password=your-password
```

## Integração com o Microsoft Power BI {#powerbi-integration}

Você pode usar o Driver ODBC para conectar o Microsoft Power BI a um Servidor do ClickHouse. O Power BI oferece duas opções de
conexão: o conector ODBC genérico e o Conector do ClickHouse, ambos incluídos nas instalações padrão do Power BI.

Os dois conectores usam ODBC internamente, mas diferem em recursos:

* Conector do ClickHouse (recomendado)
  Usa ODBC internamente, mas oferece suporte ao modo DirectQuery. Nesse modo, o Power BI gera consultas SQL automaticamente e
  recupera apenas os dados necessários para cada visualização ou operação de filtro.

* Conector ODBC
  Oferece suporte apenas ao modo Import. O Power BI executa a consulta fornecida pelo usuário (ou seleciona a tabela inteira) e importa o
  conjunto de resultados completo para o Power BI. Cada atualização posterior reimporta todo o conjunto de dados.

Escolha o conector de acordo com o seu caso de uso. O DirectQuery é mais indicado para dashboards interativos com grandes conjuntos de dados.
Escolha o modo Import quando precisar de cópias locais completas dos dados.

Para mais informações sobre como integrar o Microsoft Power BI ao ClickHouse, consulte a [página da documentação do ClickHouse sobre a integração com o Power
BI](/pt-BR/integrations/connectors/data-visualization/powerbi-and-clickhouse).

## Configurações de compatibilidade com SQL {#sql-compatibility-settings}

O ClickHouse tem seu próprio dialeto SQL, e, em alguns casos, ele se comporta de forma diferente de outros bancos de dados, como MS SQL
Server, MySQL ou PostgreSQL. Muitas vezes, essas diferenças são uma vantagem, pois introduzem uma sintaxe aprimorada que facilita
o uso das funcionalidades do ClickHouse.

No entanto, o driver ODBC é frequentemente usado em ambientes nos quais as consultas são geradas por ferramentas de terceiros, como o Power
BI, em vez de escritas pelos usuários. Essas consultas geralmente se baseiam em um subconjunto mínimo do padrão SQL. Nesses casos,
os desvios do ClickHouse em relação ao padrão SQL podem não funcionar como esperado e gerar resultados inesperados ou erros.
O driver ODBC oferece um parâmetro de configuração adicional, `SqlCompatibilitySettings`, que habilita configurações de consulta específicas
para aproximar o comportamento do ClickHouse do SQL padrão.

### Configurações do ClickHouse habilitadas pelo parâmetro de configuração SqlCompatibilitySettings {#sql-compatibility-settings-list}

Esta seção descreve quais configurações o driver ODBC modifica e por quê.

**[cast&#95;keep&#95;nullable](/pt-BR/reference/settings/session-settings/cast#cast_keep_nullable)**

Por padrão, o ClickHouse não permite converter tipos anuláveis em tipos não anuláveis. No entanto, muitas ferramentas de BI não
fazem distinção entre tipos anuláveis e não anuláveis ao realizar conversões de tipos. Por isso, não é incomum
ver ferramentas de BI gerarem consultas como a seguinte:

```sql
SELECT sum(CAST(value, 'Int32'))
FROM values
```

Por padrão, quando a coluna `value` é anulável, esta consulta falha com a mensagem:

```plaintext
DB::Exception: Cannot convert NULL value to non-Nullable type: while executing 'FUNCTION CAST(__table1.value :: 2,
'Int32'_String :: 1) -> CAST(__table1.value, 'Int32'_String) Int32 : 0'. (CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN)
```

Habilitar `cast_keep_nullable` altera o comportamento de `CAST` para que ele preserve a nulabilidade de seus argumentos. Isso
aproxima o comportamento do ClickHouse do de outros bancos de dados e do padrão SQL para esse tipo de conversão.

**[prefer&#95;column&#95;name&#95;to&#95;alias](/pt-BR/reference/settings/session-settings/prefer#prefer_column_name_to_alias)**

O ClickHouse permite referenciar expressões na mesma lista `SELECT` por meio de seus aliases. Por exemplo, esta consulta evita
repetições e é mais fácil de escrever:

```sql
SELECT
    sum(value) AS S,
    count() AS C,
    S / C
FROM test
```

Esta funcionalidade é amplamente utilizada, mas outros bancos de dados normalmente não resolvem aliases dessa forma na mesma lista `SELECT`,
e essas consultas resultariam em erro. Os problemas ficam mais evidentes quando um alias tem o mesmo nome que uma coluna. Por exemplo:

```sql
SELECT
    sum(value) AS value,
    avg(value)
FROM test
```

Qual `value` deve ser agregado por `avg(value)`? Por padrão, o ClickHouse dá preferência ao alias, o que, na prática, transforma isso em uma
agregação aninhada, algo que a maioria das ferramentas não espera.

Isoladamente, isso raramente é um problema, mas algumas ferramentas de BI geram consultas com subconsultas que reutilizam aliases de coluna. Por
exemplo, o Power BI costuma gerar consultas semelhantes à seguinte:

```sql
SELECT
    sum(C1) AS C1,
    count(C1) AS C2
FROM
(
    SELECT sum(value) AS C1
    FROM test
    GROUP BY group_index
) AS TBL
```

Referências a `C1` podem gerar o seguinte erro:

```plaintext
Code: 184. DB::Exception: Received from localhost:9000. DB::Exception: Aggregate function sum(C1) AS C1 is found
inside another aggregate function in query. (ILLEGAL_AGGREGATION)
```

Outros bancos de dados normalmente não resolvem aliases no mesmo nível dessa forma e, em vez disso, tratam `C1` como uma coluna da
subconsulta. Para preservar um comportamento semelhante no ClickHouse e permitir que essas consultas sejam executadas sem erros, o driver ODBC
habilita `prefer_column_name_to_alias`.

Na maioria dos casos, habilitar essas configurações não deve causar problemas. No entanto, usuários com a configuração readonly definida como `1`
não podem alterar nenhuma configuração, nem mesmo em consultas `SELECT`. Para esses usuários, habilitar `SqlCompatibilitySettings` resultará
em erro. A seção a seguir explica como fazer esse parâmetro de configuração funcionar para usuários somente leitura.

## Como fazer as configurações de compatibilidade com SQL funcionarem para usuários somente leitura {#readonly-users}

Ao se conectar ao ClickHouse por meio do driver ODBC com o parâmetro `SqlCompatibilitySettings` habilitado, um usuário com
a configuração readonly definida como `1` receberá um erro, pois o driver tenta modificar as configurações de consulta:

```plaintext
Code: 164. DB::Exception: Cannot modify 'cast_keep_nullable' setting in readonly mode. (READONLY)
Code: 164. DB::Exception: Cannot modify 'prefer_column_name_to_alias' setting in readonly mode. (READONLY)
```

Isso acontece porque usuários em modo somente leitura não têm permissão para alterar configurações, nem mesmo em consultas `SELECT` individuais.
Há várias maneiras de resolver isso.

**Opção 1. Definir `readonly` como `2`**

Esta é a opção mais simples. Definir `readonly` como `2` permite alterar configurações e, ao mesmo tempo, mantém o usuário em modo
somente leitura.

```sql
ALTER USER your_odbc_user MODIFY SETTING
    readonly = 2
```

Na maioria dos casos, definir `readonly` como 2 é a forma mais simples e recomendada de resolver esse problema. Se
isso não funcionar no seu caso, use a segunda opção.

**Opção 2. Alterar as configurações do usuário para que correspondam às configurações definidas pelo Driver ODBC.**

Esta opção também é simples: atualize as configurações do usuário para que já correspondam ao que o Driver ODBC tenta definir.

```sql
ALTER USER your_odbc_user MODIFY SETTING
    cast_keep_nullable = 1,
    prefer_column_name_to_alias = 1
```

Com essa alteração, o driver ODBC ainda pode tentar aplicar as configurações, mas, como os valores já coincidem, nenhuma
alteração efetiva é feita e o erro é evitado.

Esta opção também é simples, mas exige manutenção: versões mais recentes do driver podem alterar a lista de configurações ou adicionar
novas por questões de compatibilidade. Se você fixar essas configurações no seu usuário ODBC, talvez precise atualizá-las sempre que o
driver ODBC passar a aplicar configurações adicionais.
