O ClickHouse oferece suporte ao protocolo de comunicação MySQL. Isso permite que determinados clientes que não possuem connectors nativos do ClickHouse utilizem o protocolo MySQL. Esse suporte foi validado com as seguintes ferramentas de BI:

* [Looker Studio](/pt-BR/integrations/connectors/data-visualization/looker-studio-and-clickhouse)
* [Tableau Online](/pt-BR/integrations/connectors/data-visualization/tableau/tableau-online-and-clickhouse)
* [QuickSight](/pt-BR/integrations/connectors/data-visualization/quicksight-and-clickhouse)

Se você estiver testando outros clientes ou integrações não validados, tenha em mente que podem existir as seguintes limitações:

* A implementação de SSL pode não ser totalmente compatível; podem ocorrer problemas com [TLS SNI](https://www.cloudflare.com/learning/ssl/what-is-sni/).
* Uma ferramenta específica pode exigir funcionalidades do dialect (por exemplo, funções ou configurações específicas do MySQL) que ainda não foram implementadas.

Se houver um driver nativo disponível (por exemplo, [DBeaver](/pt-BR/integrations/connectors/sql-clients/dbeaver)), é sempre preferível usá-lo em vez da Interface MySQL. Além disso, embora a maioria dos clientes por linguagem do MySQL deva funcionar bem, não há garantia de que a Interface MySQL substitua diretamente o MySQL em uma base de código com consultas MySQL existentes.

Se o seu caso de uso envolve uma ferramenta específica que não possui um driver nativo do ClickHouse, você deseja utilizá-la por meio da Interface MySQL e encontrou incompatibilidades, [abra uma issue](https://github.com/ClickHouse/ClickHouse/issues) no repositório do ClickHouse.

<Note>
  Para oferecer melhor suporte ao dialeto SQL das ferramentas de BI acima, a Interface MySQL do ClickHouse executa implicitamente consultas SELECT com a configuração [prefer&#95;column&#95;name&#95;to&#95;alias = 1](/pt-BR/reference/settings/session-settings/prefer#prefer_column_name_to_alias).
  Isso não pode ser desativado e, em casos extremos raros, pode gerar comportamentos diferentes entre consultas enviadas à interface normal do ClickHouse e à interface MySQL.
</Note>

## Criando vários usuários MySQL no ClickHouse Cloud {#creating-multiple-mysql-users-in-clickhouse-cloud}

Por padrão, existe um usuário integrado `mysql4<subdomain>`, que usa a mesma senha do usuário `default`. A parte `<subdomain>` é o primeiro segmento do hostname do seu ClickHouse Cloud. Esse formato é necessário para funcionar com ferramentas que implementam conexão segura, mas não fornecem [informações de SNI no handshake TLS](https://www.cloudflare.com/learning/ssl/what-is-sni), o que impossibilita o roteamento interno sem uma indicação extra no nome de usuário (o cliente de console do MySQL é uma dessas ferramentas).

Por isso, *recomendamos fortemente* seguir o formato `mysql4<subdomain>_<username>` ao criar um novo usuário que será usado com a Interface MySQL, em que `<subdomain>` é uma indicação para identificar seu Serviço Cloud e `<username>` é um sufixo arbitrário de sua escolha.

<Tip>
  Para um hostname do ClickHouse Cloud como `foobar.us-east1.aws.clickhouse.cloud`, a parte `<subdomain>` corresponde a `foobar`, e um nome de usuário MySQL personalizado poderia ser `mysql4foobar_team1`.
</Tip>

Você pode criar usuários adicionais para usar com a Interface MySQL se, por exemplo, precisar aplicar configurações extras.

1. Opcional: crie um [perfil de configurações](/pt-BR/reference/statements/create/settings-profile) para aplicar ao seu usuário personalizado. Por exemplo, `my_custom_profile`, com uma configuração extra que será aplicada por padrão quando nos conectarmos com o usuário que criaremos mais adiante:

   ```sql
   CREATE SETTINGS PROFILE my_custom_profile SETTINGS prefer_column_name_to_alias=1;
   ```

   `prefer_column_name_to_alias` é usado apenas como exemplo; você pode usar outras configurações.

2. [Crie um usuário](/pt-BR/reference/statements/create/user) no seguinte formato: `mysql4<subdomain>_<username>` ([veja acima](#creating-multiple-mysql-users-in-clickhouse-cloud)). A senha deve estar no formato SHA1 duplo. Por exemplo:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$';
   ```

   ou, se quiser usar um perfil personalizado para esse usuário:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$' SETTINGS PROFILE 'my_custom_profile';
   ```

   em que `my_custom_profile` é o nome do perfil que você criou anteriormente.

3. [Conceda](/pt-BR/reference/statements/grant) ao novo usuário as permissões necessárias para interagir com as tabelas ou bancos de dados desejados. Por exemplo, se quiser conceder acesso apenas a `system.query_log`:

   ```sql
   GRANT SELECT ON system.query_log TO mysql4foobar_team1;
   ```

4. Use o usuário criado para se conectar ao seu serviço do ClickHouse Cloud pela Interface MySQL.

### Solução de problemas com vários usuários MySQL no ClickHouse Cloud {#troubleshooting-multiple-mysql-users-in-clickhouse-cloud}

Se você criou um novo usuário MySQL e recebe o seguinte erro ao se conectar pelo cliente MySQL CLI:

```sql
ERROR 2013 (HY000): Lost connection to MySQL server at 'reading authorization packet', system error: 54
```

Nesse caso, certifique-se de que o nome de usuário siga o formato `mysql4<subdomain>_<username>`, conforme descrito ([acima](#creating-multiple-mysql-users-in-clickhouse-cloud)).

## Habilitando a interface MySQL no ClickHouse autogerenciado {#enabling-the-mysql-interface-on-self-managed-clickhouse}

Adicione a configuração [mysql&#95;port](/pt-BR/reference/settings/server-settings/settings/mysql#mysql_port) ao arquivo de configuração do seu servidor. Por exemplo, você pode definir a porta em um novo arquivo XML na sua [pasta](/pt-BR/concepts/features/configuration/server-config/configuration-files) `config.d/`:

```xml
<clickhouse>
    <mysql_port>9004</mysql_port>
</clickhouse>
```

Inicie o seu servidor do ClickHouse e procure uma mensagem de log semelhante à seguinte, que menciona Listening for MySQL compatibility protocol:

```bash
{} <Information> Application: Listening for MySQL compatibility protocol: 127.0.0.1:9004
```

## Conectar o MySQL ao ClickHouse {#connect-mysql-to-clickhouse}

O comando a seguir mostra como conectar o cliente MySQL `mysql` ao ClickHouse:

```bash
mysql --protocol tcp -h [hostname] -u [username] -P [port_number] [database_name]
```

Por exemplo:

```bash
$ mysql --protocol tcp -h 127.0.0.1 -u default -P 9004 default
```

Saída quando a conexão é bem-sucedida:

```text
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 4
Server version: 20.2.1.1-ClickHouse

Copyright (c) 2000, 2019, Oracle and/or its affiliates. All rights reserved.

Oracle is a registered trademark of Oracle Corporation and/or its
affiliates. Other names may be trademarks of their respective
owners.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>
```

Para garantir a compatibilidade com todos os clientes MySQL, recomenda-se especificar a senha do usuário com [SHA1 duplo](/pt-BR/concepts/features/configuration/settings/settings-users#user-namepassword) no arquivo de configuração.
Se a senha do usuário for especificada com [SHA256](/pt-BR/reference/functions/regular-functions/hash-functions#SHA256), alguns clientes não conseguirão se autenticar (mysqljs e versões antigas das ferramentas de linha de comando MySQL e MariaDB).

Restrições:

* consultas preparadas não são suportadas

* alguns tipos de dados são enviados como strings

Para cancelar uma consulta demorada, use a instrução `KILL QUERY connection_id` (ela é substituída por `KILL QUERY WHERE query_id = connection_id` durante o processamento). Por exemplo:

```bash
$ mysql --protocol tcp -h mysql_server -P 9004 default -u default --password=123 -e "KILL QUERY 123456;"
```
