<div id="description">
  ## Descrição
</div>

Esta tabela não existe se este nó não estiver configurado para executar um ClickHouse Keeper no mesmo processo. Ela contém uma linha por arquivo de snapshot do Raft rastreado pela máquina de estados do Keeper no mesmo processo, incluindo snapshots que estão sendo recebidos no momento a partir do líder.

<div id="columns">
  ## Colunas
</div>

{/*AUTOGENERATED_START*/ }

* `last_log_index` ([UInt64](../../sql-reference/data-types/int-uint.md)) — Último índice de log coberto pelo snapshot.
* `path` ([String](../../sql-reference/data-types/string.md)) — Caminho do arquivo de snapshot no disk.
* `disk_name` ([String](../../sql-reference/data-types/string.md)) — Nome do disk que armazena o snapshot.
* `size_bytes` ([UInt64](../../sql-reference/data-types/int-uint.md)) — Tamanho do arquivo de snapshot no disk.
* `last_modified_at` ([DateTime](../../sql-reference/data-types/datetime.md)) — Data e hora da última modificação do arquivo de snapshot.
* `is_received` ([Bool](../../sql-reference/data-types/boolean.md)) — `true` se o snapshot estiver sendo recebido no momento a partir do leader. Para essas linhas, `size_bytes` e `last_modified_at` refletem o arquivo parcial conforme foi gravado até o momento e podem reportar um valor menor que o real.
* `exists_on_disk` ([Bool](../../sql-reference/data-types/boolean.md)) — Indica se o arquivo de snapshot está presente no disk no momento. Sempre `true` para snapshots finalizados (`is_received` = `false`), a menos que o arquivo tenha sido removido fora do sistema ou esteja corrompido; pode ser `false` para snapshots que ainda estão sendo recebidos (`is_received` = `true`) antes que qualquer byte seja gravado.

{/*AUTOGENERATED_END*/ }

Exemplo:

```sql
SELECT * FROM system.keeper_snapshots ORDER BY last_log_index;
```
