<div id="description">
  ## Descrição
</div>

Contém estatísticas amostrais de seletividade coletadas durante a leitura de tabelas `MergeTree`. A tabela só é preenchida quando [`predicate_statistics_sample_rate`](/pt-BR/operations/settings/settings#predicate_statistics_sample_rate) é maior que `0`.

Use esta tabela para verificar quão seletivos são os predicados definidos pelo usuário em workloads reais e quantos grânulos restam após a filtragem por chave primária ou índice de salto. Esses dados servem como entrada para recomendações de índice e projeção orientadas pelo workload.

<div id="row-shapes">
  ## Formatos de linhas
</div>

Uma única consulta pode produzir dois tipos de linhas em `system.predicate_statistics_log`:

* **Linhas de filtro**, emitidas em cada etapa de prewhere/filtro no `MergeTreeSelectProcessor`. Elas preenchem `predicate_expression`, `input_rows`, `passed_rows`, `filter_selectivity` e as colunas do predicado como um todo: `total_input_rows`, `total_passed_rows`, `total_selectivity`. As colunas relacionadas a índices ficam vazias.
* **Linhas de índice**, emitidas em cada etapa de leitura no `ReadFromMergeTree`. Elas preenchem os arrays `index_names`, `index_types`, `total_granules`, `granules_after` e `index_selectivities`, com uma entrada por estágio de índice (chave primária, partição, índices de salto). As colunas relacionadas a predicados ficam vazias.

As linhas de filtro e as linhas de índice da mesma consulta compartilham o mesmo `query_id` e a mesma `table`, portanto podem ser combinadas quando ambas forem necessárias.

<div id="sampling-and-overhead">
  ## Amostragem e sobrecarga
</div>

A amostragem é controlada por [`predicate_statistics_sample_rate`](/pt-BR/operations/settings/settings#predicate_statistics_sample_rate):

* `0` desativa a coleta.
* `1` faz a amostragem de todas as consultas.
* `N > 1` faz a amostragem de aproximadamente `1 / N` das consultas, com base no hash de `query_id`.

Valores menores produzem mais dados, mas aumentam o processamento de CPU no caminho de leitura e o número de gravações no log do sistema. Depois de habilitar essa configuração, use [`SYSTEM FLUSH LOGS`](/pt-BR/sql-reference/statements/system#flush-logs) se precisar que as linhas apareçam imediatamente.

<div id="columns">
  ## Colunas
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/pt-BR/sql-reference/data-types/lowcardinality)) — Hostname do servidor que executa a consulta.
* `event_date` ([Date](/pt-BR/sql-reference/data-types/date)) — Data do evento.
* `event_time` ([DateTime](/pt-BR/sql-reference/data-types/datetime)) — Timestamp de quando esta entrada de log foi gravada.
* `database` ([LowCardinality(String)](/pt-BR/sql-reference/data-types/lowcardinality)) — Nome do banco de dados da tabela de destino.
* `table` ([LowCardinality(String)](/pt-BR/sql-reference/data-types/lowcardinality)) — Nome da tabela de destino.
* `query_id` ([String](/pt-BR/sql-reference/data-types/string)) — ID da consulta para relacioná-la com query&#95;log.
* `predicate_expression` ([String](/pt-BR/sql-reference/data-types/string)) — Expressão de filtro completa processada por esta etapa de prewhere/filter (dump do ActionsDAG).
* `input_rows` ([UInt64](/pt-BR/sql-reference/data-types/int-uint)) — Linhas que entram nesta etapa de prewhere/filter.
* `passed_rows` ([UInt64](/pt-BR/sql-reference/data-types/int-uint)) — Linhas que permanecem após esta etapa de prewhere/filter.
* `filter_selectivity` ([Float64](/pt-BR/sql-reference/data-types/float)) — Seletividade desta etapa: passed&#95;rows / input&#95;rows.
* `total_input_rows` ([UInt64](/pt-BR/sql-reference/data-types/int-uint)) — Linhas que entram na primeira etapa de prewhere (total de linhas lidas dos grânulos).
* `total_passed_rows` ([UInt64](/pt-BR/sql-reference/data-types/int-uint)) — Linhas que permanecem após todas as etapas de prewhere (linhas entregues à consulta).
* `total_selectivity` ([Float64](/pt-BR/sql-reference/data-types/float)) — Seletividade de todo o predicado: total&#95;passed&#95;rows / total&#95;input&#95;rows.
* `index_names` ([Array(LowCardinality(String))](/pt-BR/sql-reference/data-types/array)) — Nomes dos índices aplicados, por exemplo [&#39;PrimaryKey&#39;, &#39;idx&#95;bf&#95;status&#39;] (apenas para linhas de índice).
* `index_types` ([Array(LowCardinality(String))](/pt-BR/sql-reference/data-types/array)) — Tipos de índices aplicados: PrimaryKey, Skip, MinMax, Partition (apenas para linhas de índice).
* `total_granules` ([Array(UInt64)](/pt-BR/sql-reference/data-types/array)) — Grânulos que entram em cada estágio de índice (apenas para linhas de índice).
* `granules_after` ([Array(UInt64)](/pt-BR/sql-reference/data-types/array)) — Grânulos restantes após cada estágio de índice (apenas para linhas de índice).
* `index_selectivities` ([Array(Float64)](/pt-BR/sql-reference/data-types/array)) — Seletividade por índice: granules&#95;after / total&#95;granules (apenas para linhas de índice).

<div id="example">
  ## Exemplo
</div>

```sql
SET predicate_statistics_sample_rate = 1;

SELECT *
FROM hits
WHERE URL LIKE '%/product/%' AND EventDate >= today() - 7
FORMAT Null;

SYSTEM FLUSH LOGS predicate_statistics_log;

SELECT
    query_id,
    predicate_expression,
    round(filter_selectivity, 3) AS step_selectivity,
    round(total_selectivity, 3) AS query_selectivity,
    index_names,
    index_selectivities
FROM system.predicate_statistics_log
WHERE table = 'hits'
ORDER BY event_time DESC
LIMIT 10;
```
