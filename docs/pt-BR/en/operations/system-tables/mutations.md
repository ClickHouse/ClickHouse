<div id="description">
  ## Descrição
</div>

A tabela contém informações sobre as [mutações](/pt-BR/sql-reference/statements/alter/index.md#mutations) de tabelas [MergeTree](/pt-BR/engines/table-engines/mergetree-family/mergetree.md) e seu andamento. Cada comando de mutação é representado por uma única linha.

<div id="columns">
  ## Colunas:
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/pt-BR/sql-reference/data-types/string)) — O nome do banco de dados ao qual a mutação foi aplicada.
* `table` ([String](/pt-BR/sql-reference/data-types/string)) — O nome da tabela à qual a mutação foi aplicada.
* `mutation_id` ([String](/pt-BR/sql-reference/data-types/string)) — O ID da mutação. Para tabelas replicadas, esses IDs correspondem aos nomes de znode no diretório `<table_path_in_clickhouse_keeper>/mutations/` no ClickHouse Keeper. Para tabelas não replicadas, os IDs correspondem aos nomes de arquivo no diretório de dados da tabela.
* `command` ([String](/pt-BR/sql-reference/data-types/string)) — A string do comando de mutação (a parte da consulta após ALTER TABLE [db.]table).
* `create_time` ([DateTime](/pt-BR/sql-reference/data-types/datetime)) — Data e hora em que o comando de mutação foi enviado para execução.
* `block_numbers.partition_id` ([Array(String)](/pt-BR/sql-reference/data-types/array)) — Para mutações de tabelas replicadas, o array contém os IDs das partições (um registro para cada partição). Para mutações de tabelas não replicadas, o array está vazio.
* `block_numbers.number` ([Array(Int64)](/pt-BR/sql-reference/data-types/array)) — Para mutações de tabelas replicadas, o array contém um registro para cada partição, com o número do bloco obtido pela mutação. Somente partes que contêm blocos com números menores que esse serão alteradas na partição. Em tabelas não replicadas, os números de bloco em todas as partições formam uma única sequência. Isso significa que, para mutações de tabelas não replicadas, a coluna conterá um registro com um único número de bloco obtido pela mutação.
* `parts_in_progress_names` ([Array(String)](/pt-BR/sql-reference/data-types/array)) — Um array com os nomes das partes de dados que estão sendo alteradas no momento.
* `parts_to_do_names` ([Array(String)](/pt-BR/sql-reference/data-types/array)) — Um array com os nomes das partes de dados que precisam ser alteradas para que a mutação seja concluída.
* `parts_to_do` ([Int64](/pt-BR/sql-reference/data-types/int-uint)) — O número de partes de dados que precisam ser alteradas para que a mutação seja concluída. Observação: mesmo que `parts_to_do` = 0, uma mutação de tabela replicada talvez ainda não tenha sido concluída devido a um INSERT de longa duração que está criando uma nova parte de dados que precisará ser alterada.
* `parts_postpone_reasons` ([Map(String, String)](/pt-BR/sql-reference/data-types/map)) — Um map de nomes de partes para os motivos pelos quais elas foram adiadas.
* `is_done` ([UInt8](/pt-BR/sql-reference/data-types/int-uint)) — O indicador de se a mutação foi concluída ou não. Possíveis valores: 1 se a mutação foi concluída, 0 se a mutação ainda está em andamento.
* `is_killed` ([UInt8](/pt-BR/sql-reference/data-types/int-uint)) — Indica se uma mutação foi interrompida. Disponível apenas no ClickHouse Cloud. Observação: is&#95;killed=1 não significa necessariamente que a mutação tenha sido completamente finalizada. É possível que uma mutação permaneça em um estado em que is&#95;killed=1 e is&#95;done=0 por um período prolongado. Isso pode ocorrer se outra mutação de longa duração estiver bloqueando a mutação interrompida. Essa é uma situação normal.
* `latest_failed_part` ([String](/pt-BR/sql-reference/data-types/string)) — O nome da parte mais recente que não pôde ser alterada.
* `latest_fail_time` ([DateTime](/pt-BR/sql-reference/data-types/datetime)) — A data e hora da falha mais recente de mutação de parte.
* `latest_fail_reason` ([String](/pt-BR/sql-reference/data-types/string)) — A mensagem da exceção que causou a falha mais recente de mutação de parte.
* `latest_fail_error_code_name` ([String](/pt-BR/sql-reference/data-types/string)) — O código de erro da exceção que causou a falha mais recente de mutação de parte.

{/*AUTOGENERATED_END*/ }

:::note

* Se um nome de parte não estiver em `parts_postpone_reasons` e ainda não tiver sofrido mutação, isso significa que a parte ainda não foi agendada para mutação.

* O nome de parte `all_parts` representa todas as partes que ainda não sofreram mutação.
  :::

* `is_killed` ([UInt8](/pt-BR/sql-reference/data-types/int-uint.md)) — Indica se uma mutação foi interrompida. **Disponível apenas no ClickHouse Cloud.**

:::note
`is_killed=1` não significa necessariamente que a mutação tenha sido completamente finalizada. É possível que uma mutação permaneça em um estado em que `is_killed=1` e `is_done=0` por um período prolongado. Isso pode acontecer se outra mutação de longa duração estiver bloqueando a mutação interrompida. Essa é uma situação normal.
:::

* `is_done` ([UInt8](/pt-BR/sql-reference/data-types/int-uint.md)) — O sinalizador que indica se a mutação foi concluída ou não. Valores possíveis:
  * `1` se a mutação foi concluída,
  * `0` se a mutação ainda está em andamento.

:::note
Mesmo se `parts_to_do = 0`, é possível que uma mutação de uma tabela replicada ainda não tenha sido concluída por causa de uma consulta `INSERT` de longa duração, que criará uma nova parte de dados que precisará ser alterada.
:::

Se houve problemas ao alterar algumas partes de dados, as colunas a seguir contêm informações adicionais:

* `latest_failed_part` ([String](/pt-BR/sql-reference/data-types/string.md)) — O nome da parte mais recente que não pôde ser alterada.
* `latest_fail_time` ([DateTime](/pt-BR/sql-reference/data-types/datetime.md)) — A data e a hora da falha mais recente na alteração de uma parte.
* `latest_fail_reason` ([String](/pt-BR/sql-reference/data-types/string.md)) — A mensagem de exceção que causou a falha mais recente na alteração de uma parte.

<div id="monitoring-mutations">
  ## Monitoramento de mutações
</div>

Para acompanhar o progresso na tabela `system.mutations`, use a consulta a seguir:

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

Observação: isso requer permissões de leitura nas tabelas `system.*`.

:::tip Uso no Cloud
No ClickHouse Cloud, a tabela `system.mutations` em cada nó contém todas as mutações do cluster, e não é necessário usar `clusterAllReplicas`.
:::
