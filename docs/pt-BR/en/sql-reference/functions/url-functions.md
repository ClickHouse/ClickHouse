<div id="overview">
  ## Visão geral
</div>

:::note
As funções mencionadas nesta seção são otimizadas para desempenho máximo e, em sua maioria, não seguem o padrão RFC-3986.
As funções que implementam a RFC-3986 têm `RFC` acrescido ao nome da função e, em geral, são mais lentas.
:::

Em geral, você pode usar as variantes de função sem `RFC` ao trabalhar com domínios registrados publicamente que não contenham nem informações de usuário nem símbolos `@`.
A tabela abaixo detalha quais símbolos em uma URL podem (`✔`) ou não podem (`✗`) ser interpretados pelas respectivas variantes com `RFC` e sem `RFC`:

| Símbolo     | non-`RFC` | `RFC` |   |
| ----------- | --------- | ----- | - |
| &#39; &#39; | ✗         | ✗     |   |
| \t          | ✗         | ✗     |   |
| &lt;        | ✗         | ✗     |   |
| &gt;        | ✗         | ✗     |   |
| %           | ✗         | ✔*    |   |
| &#123;      | ✗         | ✗     |   |
| &#125;      | ✗         | ✗     |   |
|             |           | ✗     | ✗ |
| &#92;&#92;  | ✗         | ✗     |   |
| ^           | ✗         | ✗     |   |
| ~           | ✗         | ✔*    |   |
| [           | ✗         | ✗     |   |
| ]           | ✗         | ✔     |   |
| ;           | ✗         | ✔*    |   |
| =           | ✗         | ✔*    |   |
| &amp;       | ✗         | ✔*    |   |

Os símbolos marcados com `*` são subdelimitadores na RFC 3986 e são permitidos em informações de usuário após o símbolo `@`.

Há dois tipos de funções de URL:

* Funções que extraem partes de uma URL. Se a parte relevante não estiver presente na URL, uma string vazia será retornada.
* Funções que removem parte de uma URL. Se a URL não tiver nada semelhante, ela permanecerá inalterada.
