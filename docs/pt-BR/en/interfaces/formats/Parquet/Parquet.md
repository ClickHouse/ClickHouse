<div id="description">
  ## Descrição
</div>

[Apache Parquet](https://parquet.apache.org/) é um formato de armazenamento colunar amplamente utilizado no ecossistema Hadoop. O ClickHouse oferece suporte a operações de leitura e gravação nesse formato.

Ao gravar um arquivo Parquet, os tipos de dados sem um tipo Parquet correspondente são convertidos para o tipo disponível mais próximo:

| tipo de dado do ClickHouse                                             | tipo Parquet                                        |
| ---------------------------------------------------------------------- | --------------------------------------------------- |
| [IPv4](/pt-BR/sql-reference/data-types/ipv4.md)                              | `UINT_32`                                           |
| [IPv6](/pt-BR/sql-reference/data-types/ipv6.md)                              | `FIXED_LEN_BYTE_ARRAY` (16 bytes)                   |
| [Date](/pt-BR/sql-reference/data-types/date.md) (16 bits)                    | `DATE` (32 bits)                                    |
| [DateTime](/pt-BR/sql-reference/data-types/datetime.md) (32 bits, segundos)  | `TIMESTAMP` (64 bits, milissegundos)                |
| [Int128/UInt128/Int256/UInt256](/pt-BR/sql-reference/data-types/int-uint.md) | `FIXED_LEN_BYTE_ARRAY` (16/32 bytes, little-endian) |
| [Point](/pt-BR/sql-reference/data-types/geo.md#point)                        | `BYTE_ARRAY` (WKB) + metadados do GeoParquet        |
| [LineString](/pt-BR/sql-reference/data-types/geo.md#linestring)              | `BYTE_ARRAY` (WKB) + metadados do GeoParquet        |
| [Polygon](/pt-BR/sql-reference/data-types/geo.md#polygon)                    | `BYTE_ARRAY` (WKB) + metadados do GeoParquet        |
| [MultiLineString](/pt-BR/sql-reference/data-types/geo.md#multilinestring)    | `BYTE_ARRAY` (WKB) + metadados do GeoParquet        |
| [MultiPolygon](/pt-BR/sql-reference/data-types/geo.md#multipolygon)          | `BYTE_ARRAY` (WKB) + metadados do GeoParquet        |

Arrays podem ser aninhados e podem ter um valor do tipo `Nullable` como argumento. Os tipos `Tuple` e `Map` também podem ser aninhados.

Os tipos de dado das colunas da tabela do ClickHouse podem diferir dos campos correspondentes dos dados Parquet inseridos. Ao inserir dados, o ClickHouse interpreta os tipos de dado de acordo com a tabela acima e depois [converte](/pt-BR/sql-reference/functions/type-conversion-functions#CAST) os dados para o tipo de dado definido para a coluna da tabela do ClickHouse. Por exemplo, uma coluna Parquet `UINT_32` pode ser lida como uma coluna [IPv4](/pt-BR/sql-reference/data-types/ipv4.md) no ClickHouse.

Para alguns tipos Parquet, não há um tipo do ClickHouse com correspondência próxima. Eles são lidos da seguinte forma:

* `TIME` (hora do dia) é lido como um timestamp. Por exemplo, `10:23:13.000` torna-se `1970-01-01 10:23:13.000`.
* `TIMESTAMP`/`TIME` com `isAdjustedToUTC=false` é um horário de relógio local (campos de ano, mês, dia, hora, minuto, segundo e subsegundo em um fuso horário local, independentemente de qual fuso horário específico seja considerado local), assim como o SQL `TIMESTAMP WITHOUT TIME ZONE`. O ClickHouse o lê como se fosse um timestamp UTC. Por exemplo, `2025-09-29 18:42:13.000` (representando a leitura de um relógio local) torna-se `2025-09-29 18:42:13.000` (`DateTime64(3, 'UTC')`, representando um ponto no tempo). Se convertido para String, ele mostra corretamente ano, mês, dia, hora, minuto, segundo e subsegundo, que então podem ser interpretados como estando em algum fuso horário local em vez de UTC. Contraintuitivamente, mudar o tipo de `DateTime64(3, 'UTC')` para `DateTime64(3)` não ajudaria, pois ambos os tipos representam um ponto no tempo, e não uma leitura de relógio, mas `DateTime64(3)` seria formatado incorretamente usando o fuso horário local.
* `INTERVAL` atualmente é lido como `FixedString(12)`, com a representação binária bruta do intervalo de tempo, conforme codificada no arquivo Parquet.

<div id="geo-types">
  ## Tipos geo (GeoParquet)
</div>

O ClickHouse oferece suporte à leitura e à gravação de colunas de geometria de acordo com a especificação [GeoParquet](https://geoparquet.org/). As colunas de geometria são armazenadas como payloads `BYTE_ARRAY` codificados em [WKB](https://libgeos.org/specifications/wkb/) (ou em WKT na leitura), com uma chave JSON `geo` nos metadados Parquet no nível do arquivo que descreve a codificação, o tipo de geometria e o CRS de cada coluna de geometria.

<div id="read">
  ### Comportamento de leitura
</div>

Na leitura, as colunas de geometria são mapeadas para os [tipos de dados geo](/pt-BR/sql-reference/data-types/geo.md) correspondentes do ClickHouse:

* Uma coluna declarada como `Point`, `LineString`, `Polygon`, `MultiLineString` ou `MultiPolygon` é lida como o tipo geo correspondente do ClickHouse.
* Uma coluna com vários tipos de geometria ou com tipo de geometria desconhecido é lida como o tipo [`Geometry`](/pt-BR/sql-reference/data-types/geo.md#geometry), que é um `Variant` que abrange todos os tipos geo compatíveis.
* Se o tipo de coluna solicitado for `String`, os metadados do GeoParquet serão ignorados e o payload bruto da geometria codificada será retornado como está — bytes WKB ou WKT, de acordo com a codificação declarada pela coluna do GeoParquet. Isso também se aplica se a configuração [`input_format_parquet_allow_geoparquet_parser`](/pt-BR/operations/settings/settings-formats.md#input_format_parquet_allow_geoparquet_parser) estiver definida como `0`.

<div id="write">
  ### Comportamento de escrita
</div>

Ao gravar, colunas de nível superior do tipo `Point`, `LineString`, `Polygon`, `MultiLineString` ou `MultiPolygon` são codificadas como `BYTE_ARRAY` (WKB), e os metadados JSON `geo` apropriados são anexados ao rodapé do arquivo Parquet. Um [`Geometry`](/pt-BR/sql-reference/data-types/geo.md#geometry) `Variant` de nível superior também é codificado como um payload `BYTE_ARRAY` em WKB (seus subvalores são convertidos em WKB e armazenados como uma coluna `Nullable(String)`), mas nenhum metadado `geo` é emitido para ele, portanto o resultado não é reconhecido como uma coluna de geometria GeoParquet na leitura. Outros tipos relacionados a geo, como [`Ring`](/pt-BR/sql-reference/data-types/geo.md#ring), são gravados usando sua representação subjacente nativa, sem metadados GeoParquet. Esse comportamento pode ser desativado por completo definindo [`output_format_parquet_geometadata`](/pt-BR/operations/settings/settings-formats.md#output_format_parquet_geometadata) como `0`; nesse caso, até mesmo os tipos geo compatíveis são gravados usando sua representação subjacente nativa (`Point` como `Tuple(Float64, Float64)`, `LineString` como `Array(Point)`, `Polygon` como `Array(Array(Point))` etc.) e nenhum metadado GeoParquet é emitido.

As colunas `Geometry` devem aparecer na raiz do esquema ou aninhadas dentro de `Tuple` (`struct`); aninhá-las dentro de `Array` ou `Map` não tem suporte. `Nullable` também não tem suporte para colunas geo.

Insira os dados:

```sql

```

<div id="reading-data">
  ### Leitura de dados
</div>

Leia os dados usando o formato `Parquet`:

```sql
SELECT *
FROM football
INTO OUTFILE 'football.parquet'
FORMAT Parquet
```

:::tip
Parquet é um formato binário que não é exibido de forma legível para humanos no terminal. Use `INTO OUTFILE` para gerar arquivos Parquet.
:::

Para trocar dados com o Hadoop, você pode usar o [`motor de tabela HDFS`](/pt-BR/engines/table-engines/integrations/hdfs.md).
