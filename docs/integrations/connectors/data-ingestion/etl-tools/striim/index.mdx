[Striim for ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/introducing-striim-for-clickhouse.html) is a fully-managed SaaS that brings data from databases, data warehouses, data lakes, and SaaS applications into ClickHouse, including enterprise sources such as Oracle, Microsoft SQL Server and Snowflake. Load existing records, then use change data capture (CDC) to stream inserts, updates and deletes, keeping ClickHouse data current for AI workloads, dashboards and data applications.

Striim for ClickHouse is hosted on Striim Cloud in AWS, with self-service signup, monthly usage-based billing and no annual commitment. Sign up at striim.com or through AWS Marketplace, start a 14-day free trial and build a pipeline using a natural language prompt, a wizard or the flow designer.

## Key features {#key-features}

- **Change data capture and initial load:** Load existing data, then switch to continuous real-time replication of inserts, updates and deletes. Automated pipeline wizards help create and link both phases and transition automatically from initial load to CDC replication.
- **ClickHouse writer:** Choose the table engine per pipeline (`MergeTree`, `ReplacingMergeTree`, `CollapsingMergeTree`, `CoalescingMergeTree` and others). Striim creates target tables, handles updates and deletes for the engine you pick, and sets sorting keys.
- **Schema handling:** Automatic target schema creation from the source for supported sources, and propagation of selected DDL changes (`CREATE TABLE`, `ADD COLUMN`, `ALTER TABLE ... MODIFY COLUMN`, `DROP COLUMN`, `DROP TABLE`, and `TRUNCATE TABLE`) for supported CDC sources.
- **In-flight processing:** Filter, enrich and transform data between source and ClickHouse.
- **AI-assisted operations:** Striim Clara AI, a conversational AI agent, builds pipelines from a natural-language description, reports lag and throughput, and explains failures. Review generated output before deploying to production.
- **Private connectivity:** AWS PrivateLink, SSH tunnels and IP allowlisting to sources and ClickHouse.
- **Monitoring and alerts:** Built-in pipeline monitoring and alerts sent by email, Slack, Microsoft Teams, and the Striim web UI.

## Use cases {#use-cases}

| **Use case** | **How Striim for ClickHouse fits** |
| --- | --- |
| Real-time analytics | CDC readers keep ClickHouse tables current, so interactive dashboards reflect activity from seconds ago rather than the last batch cycle. |
| AI agents and RAG | Keeps ClickHouse tables current, including those used for vector search or an MCP server, so agents read recent operational data. |
| Feature stores and model inference | Keeps entity-level features current for models scoring in near real time, such as fraud detection or personalization. |
| Data warehousing | Direct path from sources such as Oracle, SQL Server, Snowflake and Salesforce into ClickHouse without an intermediate staging or streaming layer. |
| Observability | Streams database and application logs into the same ClickHouse instance as telemetry, so both can be queried together. Complements ClickStack and OpenTelemetry ingestion. |

## Operational considerations {#operational-considerations}

- Delivery is at-least-once. After a restart or recovery, already-written events can be written again. Resultant data records depend on the table engine (see [How data lands in ClickHouse](/integrations/connectors/data-ingestion/etl-tools/striim/get-started#how-data-lands-in-clickhouse)).
- Schema evolution does not support column renames or nullability changes, and does not apply to `AggregatingMergeTree`, `Replicated` or `Distributed` targets. `VersionedCollapsingMergeTree` and `GraphiteMergeTree` are not supported.
- Some source types do not map to ClickHouse and are skipped during automatic schema creation, for example `SQL Server GEOGRAPHY`, `GEOMETRY`, `HIERARCHYID` and `SQL_VARIANT`; `Oracle BFILE`, `LONG`, `LONG RAW`, `SDO_GEOMETRY` and `UROWID`; `MySQL GEOMETRY` and `SET`.
