<Note>
In the ClickHouse Cloud console and documentation, "table" and "collection" are used interchangeably for MongoDB.
</Note>

You can use ClickPipes to ingest data from your MongoDB database into ClickHouse Cloud. The source MongoDB database can be hosted on-premises or in the cloud using services like MongoDB Atlas.

MongoDB ClickPipes can be deployed and managed manually using the ClickPipes UI, as well as programmatically using [OpenAPI](/integrations/clickpipes/programmatic-access/openapi) and [Terraform](/integrations/clickpipes/programmatic-access/terraform).

## Prerequisites {#prerequisites}

To get started, you first need to ensure that your MongoDB database is correctly configured for replication. The configuration steps depend on how you're deploying MongoDB, so please follow the relevant guide below:

1. [MongoDB Atlas](/integrations/clickpipes/mongodb/source/atlas)

2. [Generic MongoDB](/integrations/clickpipes/mongodb/source/generic)

3. [Amazon DocumentDB](/integrations/clickpipes/mongodb/source/documentdb)

Once your source MongoDB database is set up, you can continue creating your ClickPipe.

#### Configure advanced settings {#advanced-settings}

You can configure the advanced settings if needed. A brief description of each setting is provided below:

- **Sync interval**: This is the interval at which ClickPipes will poll the source database for changes. This has an implication on the destination ClickHouse service, for cost-sensitive users we recommend to keep this at a higher value (over `3600`).
- **Pull batch size**: The number of rows to fetch in a single batch. This is a best effort setting and may not be respected in all cases.
- **Snapshot number of tables in parallel**: This is the number of tables that will be fetched in parallel during the initial snapshot. This is useful when you have a large number of tables and you want to control the number of tables fetched in parallel.

### Configure the tables {#configure-the-tables}

5. Here you can select the destination database for your ClickPipe. You can either select an existing database or create a new one.

   <Image img="/images/integrations/data-ingestion/clickpipes/mongodb/select-destination-db.webp" alt="Select destination database" size="lg" border/>

6. You can select the tables you want to replicate from the source MongoDB database. While selecting the tables, you can also choose to rename the tables in the destination ClickHouse database.

Collections can be replicated in two modes:

- **Default ingestion**: Documents are ingested as-is into ClickHouse as JSON type. In this case, the destination table will have a dedicated column for `id` and another `doc` containing the full document.
- **Structured ingestion**: Documents are ingested as rows in a table following a common schema for the collection. This schema is inferred from a sample at pipe creation time. This mode is enabled by toggling **Map document to columns** for the collection.

When structured ingestion is enabled, the **Column settings** section lists the fields found in the sample with their inferred ClickHouse types. You can select which fields to replicate as columns with the `_id` document key always included with type `String`.

<Image img="/images/integrations/data-ingestion/clickpipes/mongodb/mongodb-structured-ingestion.webp" alt="Structured ingestion settings for a collection" size="md" border/>

The fact that MongoDB collections are polymorphic (i.e., documents within the same collection can have different schema) means that structured ingestion needs to handle outlier records:

- **Missing fields:** All structured columns are ingested as `Nullable`, so if a document is missing a field, the corresponding column will have a `NULL` value.
- **Extra fields:** Fields that are not part of the inferred schema are stored as JSON in the `_peerdb_malformed_data` column, with one key per field. Each key contains `"unexpected_field": true` and the original value under `value`:

  ```json
  {
    "rating": {
      "unexpected_field": true,
      "value": 4.5
    }
  }
  ```

  This data can be easily queried and analyzed. For example, to list the unexpected fields found in a table:

  ```sql
  SELECT DISTINCT arrayJoin(JSONAllPaths(_peerdb_malformed_data)) AS malformed
  FROM movies
  WHERE malformed LIKE '%.unexpected_field';
  ```

  📝 Note: If you don't want extra field values to be present in the `_peerdb_malformed_data` column, you can enable the **Hide unexpected values** option for the collection.

- **Field type mismatch:** Values whose type doesn't match the column type are also stored in the `_peerdb_malformed_data` column, with one key per field. Each key contains `"type_mismatch": true` and the original value under `value`. The corresponding column is set to `NULL`:

  ```json
  {
    "year": {
      "type_mismatch": true,
      "value": "two thousand nineteen"
    }
  }
  ```

  To read a field whether or not its value matched the expected type, combine the column with its fallback value:

  ```sql
  SELECT name, coalesce(year, _peerdb_malformed_data.year.value)
  FROM movies;
  ```


📝 Note: You can regard fields included in `_peerdb_malformed_data` as outliers falling back to JSON column ingestion.

Given that structured ingestion infers the schema ahead of table creation, enabling it allows for custom partition-by expressions and custom sorting keys to be defined based on the structured columns.
All structured columns are ingested as `Nullable`. Take this into account when writing a partitioning key expression or using them in a sorting key. In these cases, the destination table is created with the `allow_nullable_key` setting.

📝 In both ingestion modes, you can toggle the **Persist deleted documents** option if you want delete events to capture the deleted values at destination ClickHouse. Note that this requires the source collection to have `changeStreamPreAndPostImage` enabled. 

<Image img="/images/integrations/data-ingestion/clickpipes/mongodb/mongodb-persist-deleted-documents.webp" alt="Persist deleted documents option" size="lg" border/>

## What's next? {#whats-next}

Once you've set up your ClickPipe to replicate data from MongoDB to ClickHouse Cloud, you can focus on how to query and model your data for optimal performance.

## Caveats {#caveats}

Here are a few caveats to note when using this connector:

- We require MongoDB version 5.1.0+.
- We use MongoDB's native Change Streams API for CDC, which relies on the MongoDB oplog to capture real-time changes. 
- Documents from MongoDB are replicated into ClickHouse as JSON type by default. This allows for flexible schema management and makes it possible to use the rich set of JSON operators in ClickHouse for querying and analytics. You can learn more about querying JSON data [here](/reference/data-types/newjson).
