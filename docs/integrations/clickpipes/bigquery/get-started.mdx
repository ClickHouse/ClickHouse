## Pre-requisites {#pre-requisites}

* You must have privileges to manage [service accounts](https://docs.cloud.google.com/iam/docs/service-account-overview) and [IAM roles](https://docs.cloud.google.com/iam/docs/roles-overview) in your GCP project, or get assistance from an administrator. We recommend creating a dedicated service account with the minimum required set of [permissions](/integrations/clickpipes/bigquery/overview#permissions) following the [official documentation](https://docs.cloud.google.com/iam/docs/service-accounts-create).

* An initial load requires a Google Cloud Storage (GCS) bucket for staging. We recommend creating a dedicated bucket for your ClickPipe following the [Google Cloud instructions](https://docs.cloud.google.com/storage/docs/creating-buckets).

* For continuous replication, grant the service account the [BigQuery Read Session User role](/integrations/clickpipes/bigquery/overview#bigquery) on the project. Check the [requirements for your replication method](/integrations/clickpipes/bigquery/overview#cdc) before selecting tables.

<Steps>
<Step title="Select the data source" id="1-select-the-data-source">

**1.** In ClickHouse Cloud, select **Data sources** in the main navigation menu and click **Create ClickPipe**.

    <Image img="/images/integrations/data-ingestion/clickpipes/cp_step0.webp" alt="Select imports" size="lg" border/>

**2.** Click the **BigQuery** tile.

    <Image img="/images/integrations/data-ingestion/clickpipes/bigquery/cp_step1.webp" alt="Select BigQuery tile" size="lg" border/>
</Step>
<Step title="Set up your ClickPipe connection" id="2-setup-your-clickpipe-connection">

Provide the connection details for your BigQuery project. If you are running an initial load, provide a staging GCS bucket.

**1.** Upload the `.json` key for the service account you created for ClickPipes. Ensure the service account has the minimum required set of [permissions](/integrations/clickpipes/bigquery/overview#permissions).

    <Image img="/images/integrations/data-ingestion/clickpipes/bigquery/cp_step2.webp" alt="Upload service account key" size="lg" border/>    

**2.** Select the **Replication mode**: [initial load only](/integrations/clickpipes/bigquery/overview#initial-load), **Initial load + CDC**, or **CDC only**. For a CDC mode, choose a [query based or events based method](/integrations/clickpipes/bigquery/overview#cdc).

    <Image img="/images/integrations/data-ingestion/clickpipes/bigquery/select-replication-mode.png" alt="BigQuery replication mode options: initial load only, initial load plus CDC, and CDC only" size="lg" border/>

**3.** If you are running an initial load, provide the path to the GCS bucket for staging data.

**4.** Click **Next** to validate.
</Step>
<Step title="Configure your ClickPipe" id="3-configure-your-clickpipe">

Set the following values for the phases you selected. Initial load settings apply only when the ClickPipe imports existing data; CDC settings apply only when it continues replicating changes.

<Image img="/images/integrations/data-ingestion/clickpipes/bigquery/configure-pipe.png" alt="BigQuery ClickPipe settings for sync interval, initial load, and CDC" size="lg" border/>

| Setting | What it controls |
|---------|------------------|
| Sync interval (seconds) | How often ClickPipes checks each source table for new changes. |
| Parallel threads for initial load | Maximum number of parts of one table that ClickPipes loads at the same time. |
| Snapshot number of rows per partition | Target number of rows in each part of the initial load. ClickPipes may adjust this value for large tables. |
| Snapshot number of tables in parallel | Maximum number of source tables ClickPipes loads at the same time. |
| CDC number of tables in parallel | Maximum number of tables ClickPipes reads and sends to ClickHouse concurrently. |
| CDC safety buffer (seconds) | How far behind the current BigQuery time ClickPipes ends each CDC query. This gives recent writes time to become available before ClickPipes reads them. |
| CDC maximum single query window (seconds) | Maximum time range covered by one CDC query. ClickPipes splits longer periods into separate queries. For events based replication, keep this at or below 86,400 seconds, BigQuery's [one-day limit](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions). |
</Step>
<Step title="Configure tables" id="4-configure-tables">

**1.** Select the ClickHouse database where you want the BigQuery tables to be replicated to. You can select an existing database or create a new one.

**2.** Select the source tables. You can change each destination table name and choose which columns to replicate under **Column settings**. Only datasets that the service account can access appear in the list.

    <Image img="/images/integrations/data-ingestion/clickpipes/bigquery/select-table-settings.png" alt="Select a BigQuery source table and configure its destination name, CDC watermark, sorting key, and advanced settings" size="lg" border/>

**3.** Set the CDC option for each table. The screenshot shows query based settings. Select a **CDC watermark column** of type `TIMESTAMP`, keep it among the replicated columns, and update its value whenever the row changes. With events based replication, select either [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) or [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) instead. [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) requires `enable_change_history = TRUE` on the source table.

**4.** Review the **Sorting key**. If rows can be updated or deleted, choose stable columns that identify each row. For [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes), the source table must have a primary key or you must set a sorting key here. ClickHouse uses the sorting key to organize data for queries; without one, it uses `tuple()` and has no primary index.

**5.** Open **Advanced settings** to choose the ClickHouse table **Engine** or an optional partitioning key for the initial load. This partitioning key does not set the destination table's `PARTITION BY` expression.

</Step>
<Step title="Configure permissions" id="6-configure-permissions">

Finally, you can configure permissions for the internal ClickPipes user.

**Permissions:** ClickPipes will create a dedicated user for writing data into a destination table. You can select a role for this internal user using a custom role or one of the predefined roles:
- `Full access`: full access to the cluster. Required if you use materialized views or dictionary with the destination table.
- `Only destination`: insert permissions to the destination table only.
</Step>
<Step title="Complete setup" id="7-complete-setup">

Click **Create ClickPipe** to complete the setup. You'll be redirected to the overview page, where you can the progress of the initial load and click through to see the details for your BigQuery ClickPipes.

<Image img="/images/integrations/data-ingestion/clickpipes/bigquery/cp_step5.webp" alt="Permissions" size="lg" border/>
</Step>
</Steps>
