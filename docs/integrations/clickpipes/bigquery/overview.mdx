## Features {#features}

### Initial load {#initial-load}

An initial load copies selected tables from a BigQuery [dataset](https://docs.cloud.google.com/bigquery/docs/datasets-intro) to ClickHouse. You can run it on its own or follow it with continuous replication. The load uses a Google Cloud Storage (GCS) bucket that you provide for staging. An initial-load-only ClickPipe stops when the load finishes.

<Note>
ClickPipes uses BigQuery [`EXPORT DATA`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/export-statements) queries to copy data to the staging bucket. BigQuery charges for running those queries, and GCS storage charges apply.
</Note>

### Continuous replication {#cdc}

After the initial load, a BigQuery ClickPipe can poll for new data and apply it to ClickHouse. You can also start continuous replication without an initial load. Choose a replication method based on how the source table changes. These examples show the query shape; ClickPipes selects the configured columns and event metadata.

| Method | Use it when | What ClickPipes replicates | Example query |
|--------|-------------|----------------------------|---------------|
| Query based | Each inserted or updated row has a `TIMESTAMP` column that advances when the row changes. | Rows whose watermark value is newer than the last value replicated. Deletes are not detected. | `SELECT * FROM dataset.orders WHERE TIMESTAMP(updated_at) > @start AND TIMESTAMP(updated_at) <= @end` |
| [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) | The table only needs new rows replicated. | Rows inserted or appended to the table, including inserts from `MERGE`. Updates and deletes are not replicated. | [`SELECT * FROM APPENDS(TABLE dataset.orders, @start, @end)`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) |
| [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) | Inserts, updates, and deletes must be reflected in ClickHouse. | Changes reported by BigQuery change history, including changes from `MERGE` and table truncation. | [`SELECT * FROM CHANGES(TABLE dataset.orders, @start, @end)`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) |

For query based replication, select a watermark column for each table. It must be a `TIMESTAMP` column and must be included in the replicated columns. Set it when inserting or updating a row. If a row changes without a newer watermark value, ClickPipes will not pick up that change. Use [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) if you need deletes replicated.

Both events based methods require regular BigQuery tables. [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) does not require change history to be enabled. To use [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes), enable change history on each source table before creating the ClickPipe:

```sql
ALTER TABLE `project.dataset.table` SET OPTIONS (enable_change_history = TRUE);
```

[`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) also requires a BigQuery primary key or a custom sorting key configured for the destination table. Choose columns that identify a row so ClickPipes can apply updates and deletes to the correct row. BigQuery does not enforce primary key constraints, so the source data must keep those values unique.

<Note>
[`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) and [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) can read only changes within the source table's [BigQuery time travel window](https://docs.cloud.google.com/bigquery/docs/time-travel), which is seven days by default and can be as short as two days. If replication falls behind that window, run a fresh initial load to restore a complete copy. BigQuery charges for queries made by all three methods. Enabling change history for [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) also adds BigQuery storage costs.
</Note>

## Access control {#access-control}

### Authentication {#authentication}

#### Service account credentials {#service-account-credentials}

ClickPipes authenticates to your Google Cloud project using a [service account key](https://docs.cloud.google.com/iam/docs/keys-create-delete). We recommend creating a dedicated service account with the minimum required set of [permissions](#permissions) to allow ClickPipes to export data from BigQuery, load it into the staging GCS bucket, and read it into ClickHouse.

### Permissions {#permissions}

#### BigQuery {#bigquery}

The service account needs these BigQuery roles:

* [`roles/bigquery.dataViewer`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.dataViewer)
* [`roles/bigquery.jobUser`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.jobUser)

For continuous replication, also grant [`roles/bigquery.readSessionUser`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.readSessionUser) on the Google Cloud project. ClickPipes uses the [BigQuery Storage Read API](https://docs.cloud.google.com/bigquery/docs/reference/storage#permissions) to create read sessions and read CDC query results. This role cannot be granted at the dataset level; keep `roles/bigquery.dataViewer` on the source datasets or tables so the service account can read their data.

To further scope access, we recommend using [IAM conditions](https://docs.cloud.google.com/bigquery/docs/conditions) to restrict the resources the role has access to. For example, you can restrict the `dataViewer` role to the specific dataset containing the tables you want to sync:

```bash
resource.name.startsWith("projects/<PROJECT_ID>/datasets/<DATASET_NAME>")
```

#### Cloud Storage {#cloud-storage}

The service account must have the following Cloud Storage roles: 

* [`roles/storage.objectAdmin`](https://docs.cloud.google.com/storage/docs/access-control/iam-roles#storage.objectAdmin)
* [`roles/storage.bucketViewer`](https://docs.cloud.google.com/storage/docs/access-control/iam-roles#storage.bucketViewer)

To further scope access, we recommend using [IAM conditions](https://docs.cloud.google.com/bigquery/docs/conditions) to restrict the resources the role has access to. For example, you can restrict the `objectAdmin` and `bucketViewer` roles to the dedicated bucket created for ClickPipes syncs.

```bash
resource.name.startsWith("projects/_/buckets/<BUCKET_NAME>")
```
