NumericIndexedVector 是一种抽象数据结构，封装向量并支持向量聚合及按元素操作。Bit-Sliced Index 是其存储方法。有关其理论基础和适用场景，请参阅论文 [Large-Scale Metric Computation in Online Controlled Experiment Platform](https://arxiv.org/pdf/2405.08411)。

<div id="bit-sliced-index">
  ## BSI
</div>

在 BSI (Bit-Sliced Index) 存储方法中，数据先以 [Bit-Sliced Index](https://dl.acm.org/doi/abs/10.1145/253260.253268) 的形式存储，再使用 [Roaring Bitmap](https://github.com/RoaringBitmap/RoaringBitmap) 进行压缩。聚合操作和按元素操作都可直接在压缩后的数据上执行，从而显著提升存储和查询效率。

一个向量包含索引及其对应的值。以下是这种数据结构在 BSI 存储模式下的一些特性和约束：

* 索引类型可以是 `UInt8`、`UInt16` 或 `UInt32` 之一。**注意：**考虑到 Roaring Bitmap 的 64 位实现性能，BSI 格式不支持 `UInt64`/`Int64`。
* 值类型可以是 `Int8`、`Int16`、`Int32`、`Int64`、`UInt8`、`UInt16`、`UInt32`、`UInt64`、`Float32` 或 `Float64` 之一。**注意：**值类型不会自动扩展。例如，如果使用 `UInt8` 作为值类型，任何超过 `UInt8` 容量的求和都会导致溢出，而不会提升到更高类型；同样，整数上的运算会产生整数结果 (例如，除法不会自动转换为浮点结果) 。因此，预先规划和设计值类型非常重要。在实际场景中，通常会使用浮点类型 (`Float32`/`Float64`) 。
* 只有索引类型和值类型都相同的两个向量才能进行操作。
* 底层存储采用 Bit-Sliced Index，使用 bitmap 存储索引，而 Roaring Bitmap 则是 bitmap 的具体实现。最佳实践是尽可能将索引集中到少数几个 Roaring Bitmap 容器中，以最大化压缩率和查询性能。
* Bit-Sliced Index 机制会将值转换为二进制。对于浮点类型，这种转换采用定点表示，因此可能会带来精度损失。精度可通过自定义小数部分使用的比特数来调整，默认值为 24 比特，足以满足大多数场景。你可以在使用带有 `-State` 的聚合函数 `groupNumericIndexedVector` 构造 NumericIndexedVector 时，自定义整数部分和小数部分的比特数。
* 索引有三种情况：非零值、零值和不存在。在 NumericIndexedVector 中，只会存储非零值和零值。此外，在两个 NumericIndexedVector 之间进行按元素操作时，不存在的索引值会被视为 0。在除法场景下，当除数为零时，结果为零。

<div id="create-numeric-indexed-vector-object">
  ## 创建 numericIndexedVector 对象
</div>

创建这种结构有两种方式：一种是使用带有 `-State` 的聚合函数 `groupNumericIndexedVector`。
你可以添加 `-if` 后缀，以接受额外条件。
该聚合函数只会处理满足该条件的行。
另一种方式是使用 `numericIndexedVectorBuild` 基于 map 构建。
`groupNumericIndexedVectorState` 函数允许通过参数自定义整数位数和小数位数，而 `numericIndexedVectorBuild` 不支持。

<div id="group-numeric-indexed-vector">
  ## groupNumericIndexedVector
</div>

由两列数据构造 NumericIndexedVector，并以 `Float64` 类型返回所有值的总和。如果添加 `State` 后缀，则返回一个 NumericIndexedVector 对象。

**语法**

```sql
groupNumericIndexedVectorState(col1, col2)
groupNumericIndexedVectorState(type, integer_bit_num, fraction_bit_num)(col1, col2)
```

**参数**

* `type`: String，可选。指定存储格式。目前仅支持 `'BSI'`。
* `integer_bit_num`: `UInt32`，可选。仅在 `'BSI'` 存储格式下生效，表示整数部分使用的位数。当索引类型为整数类型时，其默认值对应存储该索引所需的位数。例如，如果索引类型为 UInt16，则默认的 `integer_bit_num` 为 16。对于 Float32 和 Float64 索引类型，integer&#95;bit&#95;num 的默认值为 40，因此可表示的数据整数部分范围为 `[-2^39, 2^39 - 1]`。取值范围为 `[0, 64]`。
* `fraction_bit_num`: `UInt32`，可选。仅在 `'BSI'` 存储格式下生效，表示小数部分使用的位数。当值类型为整数时，默认值为 0；当值类型为 Float32 或 Float64 时，默认值为 24。取值范围为 `[0, 24]`。
* 另外还有一个限制：integer&#95;bit&#95;num + fraction&#95;bit&#95;num 的取值范围为 [0, 64]。
* `col1`: 索引列。支持的类型：`UInt8`/`UInt16`/`UInt32`/`Int8`/`Int16`/`Int32`。
* `col2`: 值列。支持的类型：`Int8`/`Int16`/`Int32`/`Int64`/`UInt8`/`UInt16`/`UInt32`/`UInt64`/`Float32`/`Float64`。

**返回值**

一个 `Float64` 值，表示所有值的总和。

**示例**

测试数据：

```text
UserID  PlayTime
1       10
2       20
3       30
```

查询与结果：

