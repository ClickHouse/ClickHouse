<div id="common-issues-with-data-conversion">
  ## 数据转换中的常见问题
</div>

ClickHouse 通常采用与 [C++ 程序相同的行为](https://en.cppreference.com/w/cpp/language/implicit_conversion)。

`to<type>` 函数和 [cast](#CAST) 在某些情况下表现不同，例如对于 [LowCardinality](../data-types/lowcardinality.md)：[cast](#CAST) 会移除 [LowCardinality](../data-types/lowcardinality.md) 特性，而 `to<type>` 函数不会。对于 [Nullable](../data-types/nullable.md) 也是如此。这种行为与 SQL 标准不兼容，但可以通过 [cast&#95;keep&#95;nullable](../../operations/settings/settings.md/#cast_keep_nullable) 设置进行更改。

:::note
如果将某种数据类型的值转换为更小的数据类型 (例如从 `Int64` 转为 `Int32`) ，或在不兼容的数据类型之间转换 (例如从 `String` 转为 `Int`) ，请注意可能发生数据丢失。请务必仔细检查结果是否符合预期。
:::

示例：

```sql
SELECT
    toTypeName(toLowCardinality('') AS val) AS source_type,
    toTypeName(toString(val)) AS to_type_result_type,
    toTypeName(CAST(val, 'String')) AS cast_result_type

┌─source_type────────────┬─to_type_result_type────┬─cast_result_type─┐
│ LowCardinality(String) │ LowCardinality(String) │ String           │
└────────────────────────┴────────────────────────┴──────────────────┘

SELECT
    toTypeName(toNullable('') AS val) AS source_type,
    toTypeName(toString(val)) AS to_type_result_type,
    toTypeName(CAST(val, 'String')) AS cast_result_type

┌─source_type──────┬─to_type_result_type─┬─cast_result_type─┐
│ Nullable(String) │ Nullable(String)    │ String           │
└──────────────────┴─────────────────────┴──────────────────┘

SELECT
    toTypeName(toNullable('') AS val) AS source_type,
    toTypeName(toString(val)) AS to_type_result_type,
    toTypeName(CAST(val, 'String')) AS cast_result_type
SETTINGS cast_keep_nullable = 1

┌─source_type──────┬─to_type_result_type─┬─cast_result_type─┐
│ Nullable(String) │ Nullable(String)    │ Nullable(String) │
└──────────────────┴─────────────────────┴──────────────────┘
```

<div id="to-string-functions">
  ## 关于 `toString` 函数的说明
</div>

`toString` 函数家族支持在数字、字符串 (但不包括 FixedString) 、日期和日期时间之间进行转换。
所有这些函数都只接受一个参数。

* 在转换为字符串或从字符串转换时，会按与 TabSeparated 格式 (以及几乎所有其他文本格式) 相同的规则对值进行格式化或解析。如果字符串无法解析，则会抛出异常，并取消请求。
* 在将日期转换为数字或反向转换时，日期对应自 Unix 纪元开始以来的天数。
* 在将日期时间转换为数字或反向转换时，日期时间对应自 Unix 纪元开始以来的秒数。
* `DateTime` 参数的 `toString` 函数可以接受第二个 String 参数，其中包含时区名称，例如：`Europe/Amsterdam`。在这种情况下，时间会按指定时区进行格式化。

<div id="to-date-and-date-time-functions">
  ## 关于 `toDate`/`toDateTime` 函数的注意事项
</div>

`toDate`/`toDateTime` 函数的日期和日期时间格式定义如下：

```response
YYYY-MM-DD
YYYY-MM-DD hh:mm:ss
```

作为例外情况，如果将 UInt32、Int32、UInt64 或 Int64 数值类型转换为 Date，且该数值大于或等于 65536，则会将其解释为 Unix 时间戳 (而非天数) ，并向下取整到日期。
这样就支持了常见的写法 `toDate(unix_timestamp)`；否则这会报错，并且必须写成更繁琐的 `toDate(toDateTime(unix_timestamp))`。

日期与日期时间之间的转换采用自然的方式进行：要么补上空时间，要么去掉时间部分。

数值类型之间的转换遵循与 C++ 中不同数值类型之间赋值相同的规则。

**示例**

```sql title="Query"
SELECT
    now() AS ts,
    time_zone,
    toString(ts, time_zone) AS str_tz_datetime
FROM system.time_zones
WHERE time_zone LIKE 'Europe%'
LIMIT 10
```

│ 2023-09-08 19:14:59 │ Europe/Astrakhan  │ 2023-09-08 23:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Athens     │ 2023-09-08 22:14:59 │
