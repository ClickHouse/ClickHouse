<div id="overview">
  ## 概述
</div>

:::note
本节提到的函数经过优化，旨在实现最高性能，因此大多数情况下并不遵循 RFC-3986 标准。
实现 RFC-3986 的函数会在函数名后附加 `RFC`，而且通常速度更慢。
:::

处理公开注册的域名时，如果其中既不包含用户信息字符串，也不包含 `@` 符号，通常可以使用非 `RFC` 函数变体。
下表说明了 URL 中哪些符号可以 (`✔`) 或不可以 (`✗`) 被相应的 `RFC` 和非 `RFC` 变体解析：

| Symbol      | non-`RFC` | `RFC` |   |
| ----------- | --------- | ----- | - |
| &#39; &#39; | ✗         | ✗     |   |
| \t          | ✗         | ✗     |   |
| &lt;        | ✗         | ✗     |   |
| &gt;        | ✗         | ✗     |   |
| %           | ✗         | ✔*    |   |
| &#123;      | ✗         | ✗     |   |
| &#125;      | ✗         | ✗     |   |
|             |           | ✗     | ✗ |
| &#92;&#92;  | ✗         | ✗     |   |
| ^           | ✗         | ✗     |   |
| ~           | ✗         | ✔*    |   |
| [           | ✗         | ✗     |   |
| ]           | ✗         | ✔     |   |
| ;           | ✗         | ✔*    |   |
| =           | ✗         | ✔*    |   |
| &amp;       | ✗         | ✔*    |   |

带 `*` 标记的符号是 RFC 3986 中的子分隔符，可用于 `@` 符号后的用户信息。

URL 函数分为两类：

* 提取 URL 某一部分的函数。如果 URL 中不存在相应部分，则返回空字符串。
* 删除 URL 某一部分的函数。如果 URL 中没有对应内容，则 URL 保持不变。
