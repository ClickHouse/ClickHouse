<div id="description">
  ## 描述
</div>

如果此节点未配置为运行进程内的 ClickHouse Keeper，则此表不存在。该表中每一行对应一个由进程内 Keeper 状态机跟踪的 Raft 快照文件，其中也包括当前正从 leader 接收的快照。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `last_log_index` ([UInt64](../../sql-reference/data-types/int-uint.md)) — 快照覆盖的最后一个日志索引。
* `path` ([String](../../sql-reference/data-types/string.md)) — 磁盘上的快照文件路径。
* `disk_name` ([String](../../sql-reference/data-types/string.md)) — 存储该快照的磁盘名称。
* `size_bytes` ([UInt64](../../sql-reference/data-types/int-uint.md)) — 磁盘上快照文件的大小。
* `last_modified_at` ([DateTime](../../sql-reference/data-types/datetime.md)) — 快照文件的最后修改时间。
* `is_received` ([Bool](../../sql-reference/data-types/boolean.md)) — 如果当前正在从 leader 接收快照，则为 `true`。对于此类行，`size_bytes` 和 `last_modified_at` 反映的是截至目前已写入的部分文件，因此其值可能偏小。
* `exists_on_disk` ([Bool](../../sql-reference/data-types/boolean.md)) — 快照文件当前是否存在于磁盘上。对于已完成的快照 (`is_received` = `false`) ，始终为 `true`，除非该文件通过带外方式被删除或已损坏；对于正在接收的快照 (`is_received` = `true`) ，在尚未写入任何字节之前可能为 `false`。

{/*AUTOGENERATED_END*/ }

示例：

```sql
SELECT * FROM system.keeper_snapshots ORDER BY last_log_index;
```

```text
│           2000 │ snapshot_2000.bin.zstd        │ default   │      48217 │ 2026-05-22 14:15:00 │ false       │ true           │
└────────────────┴───────────────────────────────┴───────────┴────────────┴─────────────────────┴─────────────┴────────────────┘
```
