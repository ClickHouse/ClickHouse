<div id="description">
  ## 描述
</div>

`system.iceberg_metadata_log` 表会记录 ClickHouse 读取 Iceberg 表时的元数据访问和解析事件。它会提供每个已处理元数据文件或条目的详细信息，这对于调试、审计以及理解 Iceberg 表结构的演进非常有用。

该表会记录从 Iceberg 表读取的每个元数据文件和条目，包括根元数据文件、manifest 列表和 manifest 条目。它可帮助用户追踪 ClickHouse 如何解读 Iceberg 表的元数据，并诊断与 schema 演进、文件解析或查询计划相关的问题。

:::note
该表主要用于调试。
:::

<div id="controlling-log-verbosity">
  ### 控制日志详细级别
</div>

你可以使用 [`iceberg_metadata_log_level`](../../operations/settings/settings.md#iceberg_metadata_log_level) 设置来控制记录哪些元数据事件。

要记录当前查询中使用的所有元数据：

```sql
SELECT * FROM my_iceberg_table SETTINGS iceberg_metadata_log_level = 'manifest_file_entry';

SYSTEM FLUSH LOGS iceberg_metadata_log;

SELECT content_type, file_path, row_in_file
FROM system.iceberg_metadata_log
WHERE query_id = '{previous_query_id}';
```

要仅记录当前查询使用的根元数据 JSON 文件：

```sql
SELECT * FROM my_iceberg_table SETTINGS iceberg_metadata_log_level = 'metadata';

SYSTEM FLUSH LOGS iceberg_metadata_log;

SELECT content_type, file_path, row_in_file
FROM system.iceberg_metadata_log
WHERE query_id = '{previous_query_id}';
```

更多信息请参阅 [`iceberg_metadata_log_level`](../../operations/settings/settings.md#iceberg_metadata_log_level) 设置的说明。

<div id="good-to-know">
  ### 须知
</div>

* 仅当你需要详细检查 Iceberg 表时，才在查询级别使用 `iceberg_metadata_log_level`。否则，日志表中可能会写入过多元数据，并导致性能下降。
* 该表包含重复条目，因为它主要用于调试，且不保证每个实体只有唯一一条记录。内容和剪枝状态分别存储在不同的行中，因为它们是在程序执行的不同时间点收集的。读取元数据时会收集内容，检查元数据是否需要剪枝时会收集剪枝状态。**切勿依赖此表本身进行去重。**
* 如果你使用的 `content_type` 比 `ManifestListMetadata` 更详细，Iceberg 元数据缓存会对 manifest 列表禁用。
* 同样，如果你使用的 `content_type` 比 `ManifestFileMetadata` 更详细，Iceberg 元数据缓存会对 manifest 文件禁用。
* 如果 SELECT 查询被取消或执行失败，日志表中仍可能包含失败前已处理元数据的条目，但不会包含尚未处理的元数据实体信息。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 执行查询的服务器主机名。
* `event_date` ([Date](/zh/sql-reference/data-types/date)) — 条目的日期。
* `event_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 事件时间。
* `query_id` ([String](/zh/sql-reference/data-types/string)) — 查询 ID。
* `content_type` ([Enum8(&#39;None&#39; = 0, &#39;Metadata&#39; = 1, &#39;ManifestListMetadata&#39; = 2, &#39;ManifestListEntry&#39; = 3, &#39;ManifestFileMetadata&#39; = 4, &#39;ManifestFileEntry&#39; = 5)](/zh/sql-reference/data-types/enum)) — 内容类型。
* `table_path` ([String](/zh/sql-reference/data-types/string)) — 表路径。
* `file_path` ([String](/zh/sql-reference/data-types/string)) — 文件路径。
* `content` ([String](/zh/sql-reference/data-types/string)) — JSON 格式的内容 (JSON 文件内容、Avro 元数据或 Avro 条目) 。
* `row_in_file` ([Nullable(UInt64)](/zh/sql-reference/data-types/nullable)) — 文件中的行号。
* `pruning_status` ([Nullable(Enum8(&#39;NotPruned&#39; = 0, &#39;PartitionPruned&#39; = 1, &#39;MinMaxIndexPruned&#39; = 2))](/zh/sql-reference/data-types/nullable)) — 该文件的分区剪枝或 min-max 索引剪枝状态。

{/*AUTOGENERATED_END*/ }

<div id="content-type-values">
  ### `content_type` 值
</div>

* `None`：无内容。
* `Metadata`：根元数据文件。
* `ManifestListMetadata`：manifest 列表的元数据。
* `ManifestListEntry`：manifest 列表中的条目。
* `ManifestFileMetadata`：manifest 文件的元数据。
* `ManifestFileEntry`：manifest 文件中的条目。
