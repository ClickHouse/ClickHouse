<div id="description">
  ## 说明
</div>

存储已执行查询的元数据和统计信息，例如开始时间、耗时、错误消息、资源使用情况以及其他执行细节。它不存储查询结果。

你可以在服务器配置的 [query&#95;log](../../operations/server-configuration-parameters/settings.md#query_log) 部分修改查询日志设置。

你可以通过设置 [log&#95;queries = 0](/zh/operations/settings/settings#log_queries) 来禁用查询日志。我们不建议关闭日志，因为此表中的信息对于排查问题非常重要。

数据的刷新周期在服务器设置的 [query&#95;log](../../operations/server-configuration-parameters/settings.md#query_log) 部分通过 `flush_interval_milliseconds` 参数设置。要强制刷新，请使用 [SYSTEM FLUSH LOGS](/zh/sql-reference/statements/system#flush-logs) 查询。

ClickHouse 不会自动从该表中删除数据。更多详情请参阅 [Introduction](/zh/operations/system-tables/overview#system-tables-introduction)。

`system.query_log` 表会记录两类查询：

1. 由客户端直接运行的初始查询。
2. 由其他查询发起的子查询 (用于分布式查询执行) 。对于这类查询，有关父查询的信息会显示在 `initial_*` 列中。

每个查询会在 `query_log` 表中生成一行或两行，具体取决于查询的状态 (请参见 `type` 列) ：

1. 如果查询执行成功，则会创建两行，类型分别为 `QueryStart` 和 `QueryFinish`。
2. 如果在查询处理期间发生错误，则会创建两个事件，类型分别为 `QueryStart` 和 `ExceptionWhileProcessing`。
3. 如果在启动查询之前发生错误，则会创建一个类型为 `ExceptionBeforeStart` 的事件。

你可以使用 [log&#95;queries&#95;probability](/zh/operations/settings/settings#log_queries_probability) 设置来减少记录到 `query_log` 表中的查询数量。

你可以使用 [log&#95;formatted&#95;queries](/zh/operations/settings/settings#log_formatted_queries) 设置将格式化后的查询记录到 `formatted_query` 列中。

* `hostname` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 执行该查询的服务器主机名。
* `type` ([Enum8(&#39;QueryStart&#39; = 1, &#39;QueryFinish&#39; = 2, &#39;ExceptionBeforeStart&#39; = 3, &#39;ExceptionWhileProcessing&#39; = 4)](/zh/sql-reference/data-types/enum)) — 执行查询时发生的事件类型。取值：`QueryStart` — 查询执行成功启动，`QueryFinish` — 查询执行成功结束，`ExceptionBeforeStart` — 查询执行开始前发生异常，`ExceptionWhileProcessing` — 查询执行过程中发生异常。
* `event_date` ([Date](/zh/sql-reference/data-types/date)) — 查询开始日期。
* `event_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 查询开始时间。
* `event_time_microseconds` ([DateTime64(6)](/zh/sql-reference/data-types/datetime64)) — 具有微秒精度的查询开始时间。
* `query_start_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 查询执行开始时间。
* `query_start_time_microseconds` ([DateTime64(6)](/zh/sql-reference/data-types/datetime64)) — 具有微秒精度的查询执行开始时间。
* `query_duration_ms` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 以毫秒为单位的查询执行耗时。
* `read_rows` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 查询中所有参与的表和 table function 读取的总行数。包括普通子查询，以及用于 IN 和 JOIN 的子查询。对于 distributed queries，read&#95;rows 包括在所有副本上读取的总行数。每个副本都会发送其 read&#95;rows 值，而作为查询发起方的服务器会汇总所有接收到的值和本地值。cache volume 不会影响此值。
* `read_bytes` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 查询中所有参与的表和 table function 读取的总字节数。包括普通子查询，以及用于 IN 和 JOIN 的子查询。对于 distributed queries，read&#95;bytes 包括在所有副本上读取的总字节数。每个副本都会发送其 read&#95;bytes 值，而作为查询发起方的服务器会汇总所有接收到的值和本地值。cache volume 不会影响此值。
* `written_rows` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 查询写入的行数，包括由管道触发的下游 insert 写入的任何行，例如已 attached 的 materialized view。对于同步 insert，这些下游行记录在 `query_kind` = `Insert` 条目上；对于 asynchronous insert，这些行记录在 `query_kind` = `AsyncInsertFlush` 条目上，而面向 client 的 `Insert` 条目只记录从 client 接收的行数。对于不写入行的查询，该值为 0。
* `written_bytes` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 查询写入的字节数 (uncompressed) ，包括由管道触发的下游 insert 写入的任何字节，例如已 attached 的 materialized view。对于同步 insert，这些下游字节记录在 `query_kind` = `Insert` 条目上；对于 asynchronous insert，这些字节记录在 `query_kind` = `AsyncInsertFlush` 条目上，而面向 client 的 `Insert` 条目只记录从 client 接收的字节数。对于不写入数据的查询，该值为 0。
* `result_rows` ([UInt64](/zh/sql-reference/data-types/int-uint)) — SELECT 查询结果中的行数，或 insert 写入的行数。对于同步 insert，这包括在 `query_kind` = `Insert` 条目上由管道触发的下游 insert (例如已 attached 的 materialized view) 写入的行；对于 asynchronous insert，这些下游行记录在 `query_kind` = `AsyncInsertFlush` 条目上，而面向 client 的 `Insert` 条目只记录从 client 接收的行数。
* `result_bytes` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 用于存储查询结果的 RAM 字节数。
* `memory_usage` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 查询的内存消耗。
* `current_database` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 当前数据库的名称。
* `query` ([String](/zh/sql-reference/data-types/string)) — 查询字符串。
* `formatted_query` ([String](/zh/sql-reference/data-types/string)) — 格式化后的查询字符串。
* `normalized_query_hash` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 数值哈希值；例如，对于仅字面量值不同的查询，该值是相同的。
* `query_kind` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 查询类型。
* `databases` ([Array(LowCardinality(String))](/zh/sql-reference/data-types/array)) — 查询中涉及的数据库名称。
* `tables` ([Array(LowCardinality(String))](/zh/sql-reference/data-types/array)) — 查询中涉及的表名称。
* `columns` ([Array(LowCardinality(String))](/zh/sql-reference/data-types/array)) — 查询中涉及的列名称。
* `partitions` ([Array(LowCardinality(String))](/zh/sql-reference/data-types/array)) — 查询中涉及的分区名称。
* `projections` ([Array(LowCardinality(String))](/zh/sql-reference/data-types/array)) — 查询执行期间使用的 projections 名称。
* `views` ([Array(LowCardinality(String))](/zh/sql-reference/data-types/array)) — 查询中涉及的 (materialized 或 live) 视图名称。
* `exception_code` ([Int32](/zh/sql-reference/data-types/int-uint)) — 异常代码。
* `exception` ([String](/zh/sql-reference/data-types/string)) — 异常消息。
* `stack_trace` ([String](/zh/sql-reference/data-types/string)) — 堆栈跟踪。如果查询成功完成，则为空字符串。
* `is_initial_query` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 查询类型。可能的值：1 — 查询由客户端发起，0 — 查询由另一个查询作为分布式查询执行的一部分发起。
* `connection_address` ([IPv6](/zh/sql-reference/data-types/ipv6)) — 建立 connection 的客户端 IP 地址。通过代理连接时，该值将是代理的地址。
* `connection_port` ([UInt16](/zh/sql-reference/data-types/int-uint)) — 建立 connection 的客户端端口。通过代理连接时，该值将是代理的端口。
* `user` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 发起当前查询的用户名。
* `query_id` ([String](/zh/sql-reference/data-types/string)) — 查询 ID。
* `address` ([IPv6](/zh/sql-reference/data-types/ipv6)) — 用于发起查询的 IP 地址。通过代理连接且设置了 `auth_use_forwarded_address` 时，该值将是客户端地址而非代理地址。
* `port` ([UInt16](/zh/sql-reference/data-types/int-uint)) — 用于发起查询的客户端端口。通过代理连接且设置了 `auth_use_forwarded_address` 时，该值将是客户端端口而非代理端口。
* `initial_user` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 运行初始查询的用户名 (用于分布式查询执行) 。
* `initial_query_id` ([String](/zh/sql-reference/data-types/string)) — 初始查询的 ID (用于分布式查询执行) 。
* `initial_address` ([IPv6](/zh/sql-reference/data-types/ipv6)) — 发起父查询时使用的 IP 地址。
* `initial_port` ([UInt16](/zh/sql-reference/data-types/int-uint)) — 用于发起父查询的客户端端口。
* `initial_query_start_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 初始查询的开始时间 (用于分布式查询执行) 。
* `initial_query_start_time_microseconds` ([DateTime64(6)](/zh/sql-reference/data-types/datetime64)) — 精确到微秒的初始查询开始时间 (用于分布式查询执行) 。
* `authenticated_user` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 在会话中通过身份验证的用户名。
* `interface` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 发起该查询的接口。可能的值：1 — TCP，2 — HTTP。
* `is_secure` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 表示查询是否通过安全接口执行的标志。
* `os_user` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 运行 clickhouse-client 的操作系统用户名。
* `client_hostname` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 运行 clickhouse-client 或其他 TCP 客户端的客户端机器主机名。
* `client_name` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — clickhouse-client 或其他 TCP 客户端的名称。
* `client_agent` ([LowCardinality(String)](/zh/sql-reference/data-types/lowcardinality)) — 调用该客户端的 AI 编码 agent (例如 `claude-code` 或 `cursor`) ，通过环境变量检测得出。如果未检测到 agent，则为空。

* `client_version_major` ([UInt32](/zh/sql-reference/data-types/int-uint)) — clickhouse-client 或其他 TCP 客户端的主版本号。
* `client_version_minor` ([UInt32](/zh/sql-reference/data-types/int-uint)) — clickhouse-client 或其他 TCP 客户端的次版本号。
* `client_version_patch` ([UInt32](/zh/sql-reference/data-types/int-uint)) — clickhouse-client 或其他 TCP 客户端版本中的补丁号部分。

**Cloud 示例**

在 ClickHouse Cloud 中，`system.query_log` 在每个节点上都是本地的；要查看所有条目，必须通过 [`clusterAllReplicas`](/zh/sql-reference/table-functions/cluster) 发起查询。

例如，要聚合 “default” 集群中每个副本上的 query&#95;log 行，可以这样编写：

```sql
SELECT * 
FROM clusterAllReplicas('default', system.query_log)
WHERE event_time >= now() - toIntervalHour(1)
LIMIT 10
SETTINGS skip_unavailable_shards = 1;
```
