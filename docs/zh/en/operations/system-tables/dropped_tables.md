<div id="description">
  ## 描述
</div>

包含已执行 `drop table` 但尚未完成数据清理的表的相关信息。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `index` ([UInt32](/zh/sql-reference/data-types/int-uint)) — `marked_dropped_tables` 队列中的索引。
* `database` ([String](/zh/sql-reference/data-types/string)) — 数据库名称。
* `table` ([String](/zh/sql-reference/data-types/string)) — 表名称。
* `uuid` ([UUID](/zh/sql-reference/data-types/uuid)) — 表 UUID。
* `engine` ([String](/zh/sql-reference/data-types/string)) — 表引擎名称。
* `metadata_dropped_path` ([String](/zh/sql-reference/data-types/string)) — `metadata_dropped` 目录中该表元数据文件的路径。
* `table_dropped_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 计划下一次尝试删除表数据的时间。通常等于表被删除的时间加上 `database_atomic_delay_before_drop_table_sec`。

{/*AUTOGENERATED_END*/ }

<div id="example">
  ## 示例
</div>

下面的示例说明如何获取 `dropped_tables` 的相关信息。

```sql
SELECT *
FROM system.dropped_tables\G
```

```text
Row 1:
──────

table:                 test

table_dropped_time:    2023-03-16 23:43:31
```
