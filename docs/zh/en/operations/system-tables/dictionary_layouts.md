<div id="description">
  ## 描述
</div>

包含服务器支持的字典布局列表，以及每种布局的内置文档。字典布局决定了字典在内存中 (或磁盘上) 的存储方式和查找方式；它在 `CREATE DICTIONARY` 查询的 `LAYOUT` 子句中指定。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `name` ([String](/zh/sql-reference/data-types/string)) — 字典布局的名称，即在 LAYOUT 子句中指定的名称。
* `is_complex` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 该布局是否需要复杂键 (即由多个属性组成的键，或非整数类型的键) 。
* `description` ([String](/zh/sql-reference/data-types/string)) — 对字典布局功能的概括性描述。
* `syntax` ([String](/zh/sql-reference/data-types/string)) — 在 CREATE DICTIONARY 查询的 LAYOUT 子句中指定该布局的写法。
* `examples` ([String](/zh/sql-reference/data-types/string)) — 使用示例。
* `introduced_in` ([String](/zh/sql-reference/data-types/string)) — 首次引入该布局的 ClickHouse 版本，格式为 major.minor。
* `related` ([Array](/zh/sql-reference/data-types/array)([String](/zh/sql-reference/data-types/string))) — 相关字典布局的名称。

{/*AUTOGENERATED_END*/ }

<div id="example">
  ## 示例
</div>

```sql title="Query"
SELECT name, is_complex, syntax
FROM system.dictionary_layouts
WHERE name IN ('flat', 'hashed', 'complex_key_hashed')
ORDER BY name
```

```text title="Response"
┌─name───────────────┬─is_complex─┬─syntax───────────────────────────────────────────────────┐
│ complex_key_hashed │          1 │ LAYOUT(COMPLEX_KEY_HASHED())                             │
│ flat               │          0 │ LAYOUT(FLAT([INITIAL_ARRAY_SIZE n] [MAX_ARRAY_SIZE n]))  │
│ hashed             │          0 │ LAYOUT(HASHED())                                         │
└────────────────────┴────────────┴──────────────────────────────────────────────────────────┘
```
