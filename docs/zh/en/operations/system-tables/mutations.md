<div id="description">
  ## 描述
</div>

该表包含 [MergeTree](/zh/engines/table-engines/mergetree-family/mergetree.md) 表的 [变更](/zh/sql-reference/statements/alter/index.md#mutations) 及其进度信息。每条变更命令对应一行。

<div id="columns">
  ## 列：
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/zh/sql-reference/data-types/string)) — 应用了该变更的数据库名称。
* `table` ([String](/zh/sql-reference/data-types/string)) — 应用了该变更的表名称。
* `mutation_id` ([String](/zh/sql-reference/data-types/string)) — 变更的 ID。对于复制表，这些 ID 对应于 ClickHouse Keeper 中 `<table_path_in_clickhouse_keeper>/mutations/` 目录下的 znode 名称。对于非复制表，这些 ID 对应于表数据目录中的文件名。
* `command` ([String](/zh/sql-reference/data-types/string)) — 变更命令字符串 (即查询中 ALTER TABLE [db.]table 之后的部分) 。
* `create_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 提交变更命令执行的日期和时间。
* `block_numbers.partition_id` ([Array(String)](/zh/sql-reference/data-types/array)) — 对于复制表的变更，该数组包含各分区的 ID (每个分区对应一条记录) 。对于非复制表的变更，该数组为空。
* `block_numbers.number` ([Array(Int64)](/zh/sql-reference/data-types/array)) — 对于复制表的变更，该数组为每个分区包含一条记录，以及该变更获取到的块编号。只有在该分区中包含编号小于此编号的块的数据分片才会被变更。对于非复制表，所有分区中的块编号构成一个统一序列。这意味着，对于非复制表的变更，该列将包含一条记录，其中带有该变更获取到的单个块编号。
* `parts_in_progress_names` ([Array(String)](/zh/sql-reference/data-types/array)) — 当前正在进行变更的数据分片名称数组。
* `parts_to_do_names` ([Array(String)](/zh/sql-reference/data-types/array)) — 为完成该变更仍需变更的数据分片名称数组。
* `parts_to_do` ([Int64](/zh/sql-reference/data-types/int-uint)) — 为完成该变更仍需变更的数据分片数量。注意：即使 `parts_to_do` = 0，复制表的变更也可能仍未完成，因为某个长时间运行的 INSERT 正在创建一个后续也需要变更的新数据分片。
* `parts_postpone_reasons` ([Map(String, String)](/zh/sql-reference/data-types/map)) — 从数据分片名称到其被延后的原因的映射。
* `is_done` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 表示变更是否已完成的标志。Possible values：1 表示变更已完成，0 表示变更仍在进行中。
* `is_killed` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 表示变更是否已被终止。Only available in ClickHouse Cloud。注意：is&#95;killed=1 并不一定表示该变更已完全结束。变更可能会在 is&#95;killed=1 且 is&#95;done=0 的状态下持续较长时间。如果另一个长时间运行的变更阻塞了这个已被终止的变更，就可能出现这种情况。这是正常现象。
* `latest_failed_part` ([String](/zh/sql-reference/data-types/string)) — 最近一个无法完成变更的数据分片名称。
* `latest_fail_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 最近一次数据分片变更失败的日期和时间。
* `latest_fail_reason` ([String](/zh/sql-reference/data-types/string)) — 导致最近一次数据分片变更失败的异常消息。
* `latest_fail_error_code_name` ([String](/zh/sql-reference/data-types/string)) — 导致最近一次数据分片变更失败的异常错误代码名称。

{/*AUTOGENERATED_END*/ }

:::note

* 如果某个 分片 的名称不在 `parts_postpone_reasons` 中，且尚未应用变更，则表示该 分片 还未被安排执行变更。

* 分片 名称 `all_parts` 表示所有尚未应用变更的 分片。
  :::

* `is_killed` ([UInt8](/zh/sql-reference/data-types/int-uint.md)) — 表示某个变更是否已被终止。**仅在 ClickHouse Cloud 中可用。**

:::note
`is_killed=1` 并不一定意味着该变更已完全结束。变更可能会在较长一段时间内一直处于 `is_killed=1` 且 `is_done=0` 的状态。如果另一个运行时间较长的变更阻塞了这个已被终止的变更，就会出现这种情况。这是正常现象。
:::

* `is_done` ([UInt8](/zh/sql-reference/data-types/int-uint.md)) — 表示变更是否已完成的标志。可能的值：
  * 如果变更已完成，则为 `1`，
  * 如果变更仍在进行中，则为 `0`。

:::note
即使 `parts_to_do = 0`，复制表的变更也可能仍未完成，这是因为可能存在长时间运行的 `INSERT` 查询，它会创建一个还需要进行变更的新的数据分片。
:::

如果某些数据分片在变更过程中出现问题，则以下列会包含附加信息：

* `latest_failed_part` ([String](/zh/sql-reference/data-types/string.md)) — 最近一个无法变更的数据分片的名称。
* `latest_fail_time` ([DateTime](/zh/sql-reference/data-types/datetime.md)) — 最近一次数据分片变更失败的日期和时间。
* `latest_fail_reason` ([String](/zh/sql-reference/data-types/string.md)) — 导致最近一次数据分片变更失败的异常消息。

<div id="monitoring-mutations">
  ## 监控变更
</div>

要跟踪 `system.mutations` 表中的执行进度，请使用以下查询：

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

注意：这需要对 `system.*` 表具有只读权限。

:::tip Cloud 使用
在 ClickHouse Cloud 中，每个节点上的 `system.mutations` 表都包含整个集群中的所有变更，因此无需使用 `clusterAllReplicas`。
:::
