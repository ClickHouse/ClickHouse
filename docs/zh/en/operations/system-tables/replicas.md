<div id="description">
  ## 说明
</div>

包含驻留在本地服务器上的复制表的信息和状态。
此表可用于监控。表中每个 Replicated* 表各占一行。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/zh/sql-reference/data-types/string)) — 数据库名称。
* `table` ([String](/zh/sql-reference/data-types/string)) — 表名称。
* `uuid` ([UUID](/zh/sql-reference/data-types/uuid)) — 表 UUID。
* `engine` ([String](/zh/sql-reference/data-types/string)) — 表引擎名称。
* `is_leader` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 副本是否为 leader。多个副本可以同时为 leader。可以使用 merge&#95;tree 设置 replicated&#95;can&#95;become&#95;leader 来阻止副本成为 leader。leader 负责调度后台合并。请注意，无论是否为 leader，都可以向任何可用且在 ZK 中有会话的副本执行写入。
* `can_become_leader` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 副本是否可以成为 leader。
* `is_readonly` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 副本是否处于只读模式。如果 config 中没有 ClickHouse Keeper 相关节、在 ClickHouse Keeper 中重新初始化会话时发生未知错误，或者正在 ClickHouse Keeper 中重新初始化会话，都会开启此模式。
* `readonly_start_time` ([Nullable(DateTime)](/zh/sql-reference/data-types/nullable)) — 副本切换到 readonly 模式时的 timestamp。如果副本不处于 readonly 模式，则为 NULL。
* `is_session_expired` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 与 ClickHouse Keeper 的会话是否已过期。基本上等同于 `is_readonly`。
* `future_parts` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 尚未完成的 INSERT 或合并操作完成后将出现的 parts 数量。
* `parts_to_check` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 队列中等待校验的 parts 数量。如果怀疑某个 part 可能已损坏，就会将其加入校验队列。
* `zookeeper_name` ([String](/zh/sql-reference/data-types/string)) — 存储该表元数据的 [Zoo]Keeper 集群 (可能是辅助集群) 的名称
* `zookeeper_path` ([String](/zh/sql-reference/data-types/string)) — ClickHouse Keeper 中表数据的路径。
* `replica_name` ([String](/zh/sql-reference/data-types/string)) — ClickHouse Keeper 中的副本名称。同一张表的不同副本名称不同。
* `replica_path` ([String](/zh/sql-reference/data-types/string)) — ClickHouse Keeper 中副本数据的路径。等同于拼接 &#39;zookeeper&#95;path/replicas/replica&#95;path&#39;。
* `columns_version` ([Int32](/zh/sql-reference/data-types/int-uint)) — 表结构的版本号。表示执行过多少次 ALTER。如果各副本的版本不同，说明某些副本尚未完成全部 ALTER 操作。
* `queue_size` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 等待执行的操作队列大小。操作包括插入数据块、合并以及其他一些操作。它通常与 future&#95;parts 一致。
* `inserts_in_queue` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 等待执行的数据块插入数量。插入通常会很快完成复制。如果该数值很大，说明存在问题。
* `merges_in_queue` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 等待执行的合并数量。有时合并耗时较长，因此该值可能会长时间大于 0。
* `part_mutations_in_queue` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 等待执行的变更数量。
* `queue_oldest_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 如果 `queue_size` 大于 0，则显示队列中最早加入的操作的时间。
* `inserts_oldest_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 参见 `queue_oldest_time`。
* `merges_oldest_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 参见 `queue_oldest_time`。
* `part_mutations_oldest_time` ([DateTime](/zh/sql-reference/data-types/datetime)) — 参见 `queue_oldest_time`。
* `oldest_part_to_get` ([String](/zh/sql-reference/data-types/string)) — 复制队列中最早的 GET&#95;PARTS 条目对应的、需要从其他副本拉取的 part 名称。
* `oldest_part_to_merge_to` ([String](/zh/sql-reference/data-types/string)) — 复制队列中最早的 MERGE&#95;PARTS 条目对应的、要合并生成的结果 part 名称。
* `oldest_part_to_mutate_to` ([String](/zh/sql-reference/data-types/string)) — 复制队列中最早的 MUTATE&#95;PARTS 条目对应的、要变更生成的结果 part 名称。
* `log_max_index` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 通用活动日志中的最大条目编号。此列以及后面三列 (`log_pointer`、`total_replicas`、`active_replicas`) 只有在与 ClickHouse Keeper 存在活动会话时才为非零值。
* `log_pointer` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 副本已复制到其执行队列中的通用活动日志最大条目编号再加一。如果 log&#95;pointer 远小于 log&#95;max&#95;index，则说明存在问题。
* `last_queue_update` ([日期时间](/zh/sql-reference/data-types/datetime)) — 队列上次更新时间。
* `absolute_delay` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 当前副本的延迟秒数。
* `total_replicas` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 此表已知副本的总数。
* `active_replicas` ([UInt32](/zh/sql-reference/data-types/int-uint)) — 此表中在 ClickHouse Keeper 中拥有会话的副本数 (即正常工作的副本数) 。
* `lost_part_count` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 自建表以来，该表所有副本累计丢失的数据 part 数量。该值持久保存在 ClickHouse Keeper 中，并且只会增加。
* `last_queue_update_exception` ([String](/zh/sql-reference/data-types/string)) — 当队列中包含损坏条目时的异常信息。当 ClickHouse 在不同版本之间破坏向后兼容性，导致较新版本写入的日志条目无法被旧版本解析时，这一点尤为重要。
* `zookeeper_exception` ([String](/zh/sql-reference/data-types/string)) — 如果在从 ClickHouse Keeper 拉取信息时发生错误，则为最后一条异常消息。
* `replica_is_active` ([Map(String, UInt8)](/zh/sql-reference/data-types/map)) — 副本名称到副本是否处于活动状态的映射。

**别名：**

* `readonly_duration` — `if(isNull(readonly_start_time), NULL, now() - readonly_start_time)` 的别名。

{/*AUTOGENERATED_END*/ }
