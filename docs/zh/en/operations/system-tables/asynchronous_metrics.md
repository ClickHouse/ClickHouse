  # system.asynchronous_metrics
</div>

<SystemTableCloud />

<div id="description">
  ## 描述
</div>

包含在后台定期计算的指标。例如，已使用的 RAM 数量。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `metric` ([String](../../sql-reference/data-types/string.md)) — 指标名称。
* `value` ([Float64](../../sql-reference/data-types/float.md)) — 指标值。
* `description` ([String](../../sql-reference/data-types/string.md) - 指标说明)

{/*AUTOGENERATED_END*/ }

以下说明由 `utils/generate-async-metrics-docs` 基于 C++ 源代码生成。唯一权威来源是 `src/Common/AsynchronousMetrics.cpp`、`src/Interpreters/ServerAsynchronousMetrics.cpp` 和 `src/Coordination/KeeperAsynchronousMetrics.cpp` 中每个指标注册项旁边的字符串字面量。包含可变后缀 (按 disk、按 CPU、按 interface 等) 的指标名称会显示为 `*name*` 占位符；运行中的服务器会上报填入具体后缀后的实际名称。

<div id="blockactivetime_name">
  ### BlockActiveTime_*name*
</div>

块设备存在 IO 请求排队时的持续时间 (单位：秒) 。这是一个系统级指标，包含主机上所有进程的活动，而不只是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockactivetimeperop_name">
  ### BlockActiveTimePerOp_*name*
</div>

与 `BlockActiveTime` 指标类似，但该值会除以 IO 操作数，以计算每次操作的耗时。

<div id="blockdiscardbytes_name">
  ### BlockDiscardBytes_*name*
</div>

块设备上被丢弃的字节数。这些操作与 SSD 有关。ClickHouse 不使用丢弃操作，但系统中的其他进程可能会使用。这是一个系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。请参阅 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockdiscardmerges_name">
  ### BlockDiscardMerges_*name*
</div>

由操作系统 IO 调度器向块设备发起并合并的 discard 操作次数。这些操作与 SSD 相关。ClickHouse 不使用 discard 操作，但系统上的其他进程可能会使用。这是一个系统级指标，包含主机上的所有进程，而不仅仅是 clickhouse-server。来源：`/sys/block`。请参阅 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockdiscardops_name">
  ### BlockDiscardOps_*name*
</div>

向块设备发起的 discard 操作次数。此类操作与 SSD 相关。ClickHouse 不会使用 discard 操作，但系统中的其他进程可能会使用。这是系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockdiscardtime_name">
  ### BlockDiscardTime_*name*
</div>

从块设备发起的丢弃操作累计耗时 (单位：秒) ，为所有此类操作时间的总和。这些操作与 SSD 相关。ClickHouse 不使用丢弃操作，但系统中的其他进程可能会使用。这是一个系统级指标，包含主机上的所有进程，而不仅仅是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockinflightops_name">
  ### BlockInFlightOps_*name*
</div>

该值统计的是已提交给设备驱动程序但尚未完成的 I/O 请求数量。它不包括仍在队列中、但尚未提交给设备驱动程序的 I/O 请求。这是一个系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockqueuetime_name">
  ### BlockQueueTime_*name*
</div>

该值表示此块设备上的 IO 请求累计等待了多少毫秒。如果有多个 IO 请求同时在等待，该值会按“等待毫秒数 × 等待请求数”累计增加。这是一个系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockqueuetimeperop_name">
  ### BlockQueueTimePerOp_*name*
</div>

与 `BlockQueueTime` 指标类似，但其值会除以 IO 操作次数，以计算每次操作的耗时。

<div id="blockreadbytes_name">
  ### BlockReadBytes_*name*
</div>

从块设备读取的字节数。由于使用了可减少 IO 的操作系统页缓存，该值可能低于从文件系统读取的字节数。这是一个系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockreadmerges_name">
  ### BlockReadMerges_*name*
</div>

由操作系统 IO 调度器合并的块设备读请求次数。这是一个系统级指标，包含主机上的所有进程，而不仅仅是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockreadops_name">
  ### BlockReadOps_*name*
</div>

请求从块设备读取的操作数。这是一个系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。请参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockreadtime_name">
  ### BlockReadTime_*name*
</div>

从块设备发起的读操作所耗费的时间 (以秒为单位) ，为所有操作的总和。这是一个系统级指标，包含主机上的所有进程，而不仅仅是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockwritebytes_name">
  ### BlockWriteBytes_*name*
</div>

写入块设备的字节数。由于使用了可节省 IO 的操作系统页缓存，它可能小于写入文件系统的字节数。由于直写缓存，块设备上的写入可能会晚于文件系统中对应的写入。这是一个系统级指标，包含主机上的所有进程，而不仅仅是 clickhouse-server。来源：`/sys/block`。另见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockwritemerges_name">
  ### BlockWriteMerges_*name*
</div>

由操作系统 IO 调度器向块设备发起并合并的写操作次数。这是一项系统级指标，包含主机上的所有进程，而不只是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockwriteops_name">
  ### BlockWriteOps_*name*
</div>

从块设备发起的写操作次数。这是一个系统级指标，包含主机上所有进程的活动，而不只是 clickhouse-server。来源：`/sys/block`。请参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="blockwritetime_name">
  ### BlockWriteTime_*name*
</div>

以秒为单位，表示块设备写入操作耗费的时间总和，汇总了所有相关操作。这是一个系统级指标，包含主机上所有进程，而不仅仅是 clickhouse-server。来源：`/sys/block`。参见 https://www.kernel.org/doc/Documentation/block/stat.txt

<div id="cgroupmaxcpu">
  ### CGroupMaxCPU
</div>

根据 CGroups 确定的最大 CPU 核心数。

<div id="cgroupmemorytotal">
  ### CGroupMemoryTotal
</div>

cgroup 中的内存总量，单位为字节。若该值为 0，则限制与 OSMemoryTotal 相同。

<div id="cgroupmemoryused">
  ### CGroupMemoryUsed
</div>

cgroup 中已使用的内存量，以字节为单位。在 cgroup v2 中，它指 anon + sock + 不可回收的内核内存；在 cgroup v1 中，它指 RSS。两种情况下都不包括内核 OS page cache (文件后备缓存) 。

<div id="cgroupmemoryusedwithoutpagecache">
  ### CGroupMemoryUsedWithoutPageCache
</div>

cgroup 中已使用的内存量 (单位为字节) ，不包括 ClickHouse 用户态页缓存。该值等于 CGroupMemoryUsed 减去用户态页缓存的大小。禁用用户态页缓存时，该值等于 CGroupMemoryUsed。

<div id="cgroupsystemtime">
  ### CGroupSystemTime
</div>

CPU 核心运行操作系统内核 (system) 代码所占的时间比例。

<div id="cgroupsystemtimenormalized">
  ### CGroupSystemTimeNormalized
</div>

该值与 `CGroupSystemTime` 类似，但会除以可用 CPU 核心数，因此无论核心数多少，结果都落在 [0..1] 区间内。这样一来，即使集群中多台服务器的核心数不一致，你也可以对该指标在这些服务器上的值取平均，仍然得到平均资源利用率指标。如果指定了相关设置，也可以用 Cgroup CPU 配额除以其周期所得的值来代替实际的 CPU 核心数；在这种情况下，该指标的值在某些时刻可能会超过 1。

<div id="cgroupusertime">
  ### CGroupUserTime
</div>

CPU 核心运行用户态代码的时间占比。这也包括因 CPU 内部原因 (如内存加载、流水线停顿、分支预测错误、运行另一个 SMT 核心) 而未得到充分利用的那部分时间。

<div id="cgroupusertimenormalized">
  ### CGroupUserTimeNormalized
</div>

该值与 `CGroupUserTime` 类似，但会除以可用的 CPU 核心数，因此无论核心数多少，都可将其度量在 [0..1] 区间内。这样一来，即使 cluster 中多个 server 的核心数并不一致，你仍然可以对该指标在这些 server 上的值求平均，并得到平均资源利用率指标。如果指定了 Cgroup CPU 配额，也可以用其除以 period 的结果来代替实际的 CPU 核心数；在这种情况下，该指标的值在某些时刻可能会超过 1。

<div id="cpufrequencymhz_core_id">
  ### CPUFrequencyMHz_*core_id*

CPU 当前的频率，单位为 MHz。大多数现代 CPU 会为了节能和实现 Turbo Boost 而动态调整频率。

<div id="diskputobjectthrottleravailable_name">

<div id="diskputobjectthrottlerrps_name">

磁盘上 PutObject 请求的限流上限，以每秒请求数表示 (虚拟文件系统) 。本地文件系统可能不提供此信息。

<div id="disktotal_name">
  ### DiskTotal_*name*
</div>

磁盘 (虚拟文件系统) 的总大小，以字节为单位。远程文件系统可能不提供此信息，因此会显示一个很大的值，例如 16 EiB。

<div id="diskunreserved_name">

磁盘 (虚拟文件系统) 上扣除为合并、拉取和移动预留空间后剩余的可用字节数。远程文件系统可能不提供此信息，因此可能会显示 16 EiB 这样的大数值。

<div id="diskused_name">
  ### DiskUsed_*name*
</div>

磁盘 (虚拟文件系统) 上的已用字节数。远程文件系统不一定总能提供此信息。

<div id="edaci_correctable">
  ### EDAC*i*_Correctable
</div>

可纠正的 ECC 内存错误数量。该值较高通常表明 RAM 有问题，必须立即更换，因为在已纠正错误大量出现时，也可能同时发生静默错误，从而导致数据损坏。来源：`/sys/devices/system/edac/mc/`

<div id="edaci_uncorrectable">
  ### EDAC*i*_Uncorrectable
</div>

不可纠正的 ECC 内存错误数量。该值非零表示 RAM 已出现故障，必须立即更换，因为这意味着可能发生数据损坏。来源：`/sys/devices/system/edac/mc/`

<div id="executableuserdefinedfunctionmemoryresidentbytes">
  ### ExecutableUserDefinedFunctionMemoryResidentBytes
</div>

所有可执行用户自定义函数、可执行池用户自定义函数及其后代进程中仍在运行的进程的常驻集大小 (VmRSS) 之和，单位为字节。空闲的 executable&#95;pool 工作线程也包括在内。共享页会按每个进程计一次，因此该总和只是一个上限，可能高于 UDF 进程实际独占的物理内存占用。
