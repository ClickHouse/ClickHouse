<div id="description">
  ## 描述
</div>

包含[服务器配置](../../engines/table-engines/mergetree-family/mergetree.md#table_engine-mergetree-multiple-volumes_configure)中定义的存储策略和卷的相关信息。

<div id="columns">
  ## 列
</div>

{/*AUTOGENERATED_START*/ }

* `policy_name` ([String](/zh/sql-reference/data-types/string)) — 存储策略的名称。
* `volume_name` ([String](/zh/sql-reference/data-types/string)) — 卷的名称。
* `volume_priority` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 卷的优先级。
* `disks` ([Array(String)](/zh/sql-reference/data-types/array)) — 此存储策略包含的所有磁盘名称列表。
* `volume_type` ([Enum8(&#39;JBOD&#39; = 0, &#39;SINGLE&#95;DISK&#39; = 1, &#39;UNKNOWN&#39; = 2)](/zh/sql-reference/data-types/enum)) — 卷的类型，即 JBOD 或单磁盘。
* `max_data_part_size` ([UInt64](/zh/sql-reference/data-types/int-uint)) — 可存储在该卷任一磁盘上的数据分区片段的最大大小。
* `move_factor` ([Float32](/zh/sql-reference/data-types/float)) — 当可用空间低于该因子时，数据会自动开始移动到下一个卷 (如果存在)  (默认值为 0.1) 。
* `prefer_not_to_merge` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 不应使用此设置。它会禁用此卷上的数据分区片段合并 (这会带来负面影响并导致性能下降) 。
* `perform_ttl_move_on_insert` ([UInt8](/zh/sql-reference/data-types/int-uint)) — 禁用在数据分区片段 INSERT 时执行 TTL move。默认情况下 (如果启用) ，如果插入的数据分区片段已根据 TTL move 规则过期，它会立即移动到 move 规则中声明的卷/磁盘。
* `load_balancing` ([Enum8(&#39;ROUND&#95;ROBIN&#39; = 0, &#39;LEAST&#95;USED&#39; = 1)](/zh/sql-reference/data-types/enum)) — 磁盘负载均衡策略，`round_robin` 或 `least_used`。

{/*AUTOGENERATED_END*/ }

<div id="volume-selection-on-insert">
  ## `INSERT` 时的卷选择
</div>

当 `INSERT` 创建新的数据分区片段时，ClickHouse 会按顺序尝试以下规则来选择
目标磁盘。第一个既匹配**又能为该数据分区片段预留空间**的规则会生效；否则 (规则不适用、没有可用
空间，或超过了 `max_data_part_size`) ，则继续评估下一条
规则。

1. **TTL move 规则** — 如果某个 `TTL <expr> TO VOLUME 'X'` (或 `TO DISK 'X'`)
   子句对于正在插入的行而言对应的时间点已经过去，**并且**
   **TTL 目标卷**上的 `perform_ttl_move_on_insert = 1` (默认值)
   (对于 `TO DISK 'X'`，即包含磁盘 `X` 的卷) ，则该数据分区片段
   会直接写入该目标位置。如果在那里预留失败，
   insert 会回退到步骤 2–4；系统会记录一条警告日志，但 `INSERT`
   不会仅因此失败。
2. **`max_data_part_size`** — 卷会拒绝大于其
   `max_data_part_size` 的数据分区片段。该检查按卷进行；它不会限制
   步骤 1 中直接以磁盘为目标的 `TTL ... TO DISK 'X'`
   预留。
3. **`volume_priority`** — 在其余卷中，将选择
   `volume_priority` 值最低的那个。未显式设置
   `<volume_priority>` 的卷，会按其在配置中的位置排序。
4. **`load_balancing`** — 选定卷后，该卷内的磁盘
   会根据其 `load_balancing` 策略
   (`round_robin` 或 `least_used`) 进行选择。

:::note Override
如果 `min_free_disk_bytes_to_perform_insert` 或
`min_free_disk_ratio_to_perform_insert` 不为零，则上述
优先次序会被跳过。`INSERT` 只会尝试
`volume_priority` 最低的那个卷；如果该卷中没有磁盘
满足阈值，则会抛出 `NOT_ENOUGH_SPACE`。插入到 `system`
database 的操作不受此限制。
:::

:::note
`perform_ttl_move_on_insert` 是从 **TTL 目标**卷读取的，
而不是从源卷读取。对于 `TO DISK 'X'` 规则，该标志会从
包含磁盘 `X` 的卷中读取。在该策略的其他任何卷上设置它
都不会影响 insert 路径。
:::

如果要强制 insert 在“已
过期”的 TTL move 规则生效时仍遵循 `volume_priority`，请在 TTL
目标卷上将 `perform_ttl_move_on_insert = 0` (对于 `TO DISK 'X'`，则设置在包含
磁盘 `X` 的卷上) 。这样该数据分区片段会先写入优先级为 N 的卷，然后
由后台移动任务再移动到 TTL 目标 (可通过
`system.moves` 观察到) 。请参阅
[MergeTree 引擎中的 `perform_ttl_move_on_insert` 设置](/zh/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-multiple-volumes_configure)。
