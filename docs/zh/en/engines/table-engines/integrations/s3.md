此引擎提供与 [亚马逊 S3](https://aws.amazon.com/s3/) 生态系统的集成。它与 [HDFS](/zh/engines/table-engines/integrations/hdfs) 引擎类似，但提供 S3 特定功能。

<div id="example">
  ## 示例
</div>

```sql
CREATE TABLE s3_engine_table (name String, value UInt32)
    ENGINE=S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/test-data.csv.gz', 'CSV', 'gzip')
    SETTINGS input_format_with_names_use_header = 0;

INSERT INTO s3_engine_table VALUES ('one', 1), ('two', 2), ('three', 3);

SELECT * FROM s3_engine_table LIMIT 2;
```

```text
┌─name─┬─value─┐
│ one  │     1 │
│ two  │     2 │
└──────┴───────┘
```

<div id="creating-a-table">
  ## 创建表
</div>

```sql
CREATE TABLE s3_engine_table (name String, value UInt32)
    ENGINE = S3(path [, NOSIGN | aws_access_key_id, aws_secret_access_key,] format, [compression], [partition_strategy], [partition_columns_in_data_file], [extra_credentials])
    [PARTITION BY expr]
    [SETTINGS ...]
```

<div id="parameters">
  ### 引擎参数
</div>

* `path` — 存储桶 URL 及文件路径。在 readonly 模式下支持以下通配符：`*`、`**`、`?`、`{abc,def}` 和 `{N..M}`，其中 `N`、`M` 表示数字，`'abc'`、`'def'` 表示字符串。更多信息请参见[下文](#wildcards-in-path)。
* `NOSIGN` - 如果使用此关键字代替凭证，则所有请求都不会被签名。
* `format` — 文件的[格式](/zh/sql-reference/formats#formats-overview)。
* `aws_access_key_id`, `aws_secret_access_key` - [AWS](https://aws.amazon.com/) 账户用户的长期凭证。您可以使用它们对请求进行身份验证。该参数为可选项。如果未指定凭证，则会使用配置文件中的凭证。更多信息请参见 [Using S3 for Data Storage](../mergetree-family/mergetree.md#table_engine-mergetree-s3)。
* `compression` — 压缩类型。支持的值：`none`、`gzip/gz`、`brotli/br`、`xz/LZMA`、`zstd/zst`。该参数为可选项。默认会根据文件扩展名自动检测压缩类型。
* `partition_strategy` – 可选值：`WILDCARD` 或 `HIVE`。`WILDCARD` 要求路径中包含 `{_partition_id}`，其值会替换为分区键。`HIVE` 不允许使用通配符，假定该路径是表的根路径，并生成 Hive 风格的分区目录，以 Snowflake ID 作为文件名、文件格式作为扩展名。默认值取自 `file_like_engine_default_partition_strategy` 设置 (对于早于 `26.6` 的 `compatibility` 设置为 `WILDCARD`，否则为 `HIVE`) 。
* `partition_columns_in_data_file` - 仅在 `HIVE` 分区策略下使用。用于告知 ClickHouse 是否应预期分区列会写入数据文件。默认为 `false`。
* `storage_class_name` - 可选值：`STANDARD` 或 `INTELLIGENT_TIERING`，可用于指定 [AWS S3 Intelligent Tiering](https://aws.amazon.com/s3/storage-classes/intelligent-tiering/)。
* `extra_credentials` - 可选。用于传递 `role_arn`，以便在 ClickHouse Cloud 中实现基于角色的访问控制。有关配置步骤，请参见 [Secure S3](/zh/cloud/data-sources/secure-s3)。

<div id="data-cache">
  ### 数据缓存
</div>

`S3` 表引擎支持将数据缓存到本地磁盘。
有关文件系统缓存的配置选项和用法，请参见本[节](/zh/operations/storing-data.md/#using-local-cache)。
缓存基于存储对象的 path 和 ETag，因此 ClickHouse 不会读取过时的缓存版本。

要启用缓存，请使用设置 `filesystem_cache_name = '<name>'` 和 `enable_filesystem_cache = 1`。

```sql
SELECT *
FROM s3('http://minio:10000/clickhouse//test_3.csv', 'minioadmin', 'minioadminpassword', 'CSV')
SETTINGS filesystem_cache_name = 'cache_for_s3', enable_filesystem_cache = 1;
```

可以在配置文件中通过两种方式定义缓存。

1. 将以下内容添加到 ClickHouse 配置文件中：

```xml
<clickhouse>
    <filesystem_caches>
        <cache_for_s3>
            <path>path to cache directory</path>
            <max_size>10Gi</max_size>
        </cache_for_s3>
    </filesystem_caches>
</clickhouse>
```

2. 复用 clickhouse `storage_configuration` 部分中的 cache 配置 (以及相应的 cache 存储) ，[此处有详细说明](/zh/operations/storing-data.md/#using-local-cache)

<div id="partition-by">
  ### PARTITION BY
</div>

`PARTITION BY` — 可选。在大多数情况下，您不需要分区键；即使需要，通常也不需要比按月更细的分区键。分区不会加速查询 (这不同于 `ORDER BY` 表达式) 。绝不要使用粒度过细的分区。不要按客户标识符或名称对数据进行分区 (应将客户标识符或名称作为 `ORDER BY` 表达式中的第一列) 。

对于按月分区，请使用 `toYYYYMM(date_column)` 表达式，其中 `date_column` 是一个类型为 [Date](/zh/sql-reference/data-types/date.md) 的日期列。这里的分区名称采用 `"YYYYMM"` 格式。

<div id="partition-strategy">
  #### 分区策略
</div>

`WILDCARD`：将文件路径中的 `{_partition_id}` 通配符替换为实际的分区键。不支持读取。仅在 `compatibility` 设置早于 `26.6` 时才会默认选择该策略；否则默认策略为 `HIVE` (参见 `file_like_engine_default_partition_strategy` 设置) 。

`HIVE` 支持以 Hive 风格进行读写分区。读取通过递归 glob 模式实现，等价于 `SELECT * FROM s3('table_root/**.parquet')`。
写入时会按以下格式生成文件：`<prefix>/<key1=val1/key2=val2...>/<snowflakeid>.<toLower(file_format)>`。

注意：使用 `HIVE` 分区策略时，`use_hive_partitioning` 设置不会生效。

`HIVE` 分区策略示例：

```sql
arthur :) CREATE TABLE t_03363_parquet (year UInt16, country String, counter UInt8)
ENGINE = S3(s3_conn, filename = 't_03363_parquet', format = Parquet, partition_strategy='hive')
```

<div id="querying-partitioned-data">
  ### 查询分区数据
</div>

本示例使用 [docker compose recipe](https://github.com/ClickHouse/examples/tree/5fdc6ff72f4e5137e23ea075c88d3f44b0202490/docker-compose-recipes/recipes/ch-and-minio-S3)，其中集成了 ClickHouse 和 MinIO。你也可以通过替换端点和身份验证值，使用 S3 复现相同的查询。

请注意，`ENGINE` 配置中的 S3 端点将参数标记 `{_partition_id}` 用作 S3 对象 (文件名) 的一部分，而这些 SELECT 查询正是针对生成后的对象名进行的 (例如 `test_3.csv`) 。

:::note
如示例所示，目前还不直接支持从已分区的 S3 表中查询，但可以通过使用 S3 表函数查询各个分区来实现。

将分区数据写入 S3 的主要用例，是为了便于将这些数据传输到另一个 ClickHouse 系统中 (例如，从本地部署系统迁移到 ClickHouse
Cloud) 。由于 ClickHouse 数据集通常非常庞大，而网络可靠性有时也并不理想，因此按子集传输数据会更合理，这正是采用分区写入的原因。
:::

<div id="inserting-data">
  ## 插入数据
</div>

请注意，只能向新文件中插入行。没有合并周期，也没有文件拆分操作。文件一旦写入，后续插入就会失败。为避免这种情况，你可以使用 `s3_truncate_on_insert` 和 `s3_create_new_file_on_insert` 设置。更多详情请参见[这里](/zh/integrations/s3#inserting-data)。

<div id="virtual-columns">
  ## 虚拟列
</div>

* `_path` — 文件路径。类型：`LowCardinality(String)`。
* `_file` — 文件名。类型：`LowCardinality(String)`。
* `_size` — 文件大小 (以字节为单位) 。类型：`Nullable(UInt64)`。如果大小未知，则值为 `NULL`。
* `_time` — 文件的最后修改时间。类型：`Nullable(DateTime)`。如果时间未知，则值为 `NULL`。
* `_etag` — 文件的 ETag。类型：`LowCardinality(String)`。如果 ETag 未知，则值为 `NULL`。
* `_tags` — 文件的标签。类型：`Map(String, String)`。如果没有标签，则值为空映射 &#96;{}&#39;。

有关虚拟列的更多信息，请参见[此处](../../../engines/table-engines/index.md#table_engines-virtual_columns)。

<div id="wildcards-in-path">
  ## 路径中的通配符
</div>

`path` 参数可以使用类似 bash 的通配符来指定多个文件。待处理的文件必须存在，并且其完整路径需匹配该路径模式。文件列表是在执行 `SELECT` 时确定的 (而不是在 `CREATE` 时) 。

* `*` — 匹配任意数量的任意字符 (不包括 `/`) ，也可以匹配空字符串。
* `**` — 匹配任意数量的任意字符 (包括 `/`) ，也可以匹配空字符串。
* `?` — 匹配任意单个字符。
* `{some_string,another_string,yet_another_one}` — 匹配字符串 `'some_string'`、`'another_string'`、`'yet_another_one'` 中的任意一个。
* `{N..M}` — 匹配从 N 到 M 范围内的任意数字，包含两个端点。N 和 M 可以带前导零，例如 `000..078`。

带有 `{}` 的写法与 [remote](../../../sql-reference/table-functions/remote.md) 表函数类似。

:::note
如果文件列表包含带前导零的数字范围，请对每一位分别使用大括号写法，或使用 `?`。
:::

**通配符示例 1**

使用名为 `file-000.csv`、`file-001.csv`、...、`file-999.csv` 的文件创建表：

```sql
CREATE TABLE big_table (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/my_folder/file-{000..999}.csv', 'CSV');
```

**通配符示例 2**

假设我们在 S3 上有多个 CSV 格式文件，其 URI 如下：

* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/some&#95;folder/some&#95;file&#95;1.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/some&#95;folder/some&#95;file&#95;2.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/some&#95;folder/some&#95;file&#95;3.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/another&#95;folder/some&#95;file&#95;1.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/another&#95;folder/some&#95;file&#95;2.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/another&#95;folder/some&#95;file&#95;3.csv&#39;

可以通过多种方式创建一个包含这 6 个文件的表：

1. 指定文件后缀范围：

```sql
CREATE TABLE table_with_range (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/{some,another}_folder/some_file_{1..3}', 'CSV');
```

2. 获取所有带有 `some_file_` 前缀的文件 (两个文件夹中都不应存在带有此前缀的多余文件) ：

```sql
CREATE TABLE table_with_question_mark (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/{some,another}_folder/some_file_?', 'CSV');
```

3. 获取两个文件夹中的所有文件 (所有文件都应满足查询中所述的 format 和 schema) ：

```sql
CREATE TABLE table_with_asterisk (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/{some,another}_folder/*', 'CSV');
```

  ## 存储设置
</div>

* [s3&#95;truncate&#95;on&#95;insert](/zh/operations/settings/settings.md#s3_truncate_on_insert) - 允许在插入前截断文件。默认禁用。

<div id="settings">
  ## 与 S3 相关的设置
</div>

以下设置可在查询执行前设置，或写入配置文件。

* `s3_max_single_part_upload_size` — 使用 singlepart upload 向 S3 上传时，对象的最大大小。默认值为 `32Mb`。
* `s3_min_upload_part_size` — 在 [S3 Multipart upload](https://docs.aws.amazon.com/AmazonS3/latest/dev/uploadobjusingmpu.html) 的分段上传过程中，待上传分段的最小大小。默认值为 `16Mb`。
* `s3_max_redirects` — 允许的 S3 重定向跳转次数上限。默认值为 `10`。
* `s3_single_read_retries` — 单次读取的最大重试次数。默认值为 `4`。
* `s3_max_put_rps` — 触发限流前每秒允许的最大 PUT 请求速率。默认值为 `0` (无限制) 。
* `s3_max_put_burst` — 达到每秒请求数限制前可同时发出的最大请求数。默认情况下 (值为 `0`) ，等于 `s3_max_put_rps`。
* `s3_max_get_rps` — 触发限流前每秒允许的最大 GET 请求速率。默认值为 `0` (无限制) 。
* `s3_max_get_burst` — 达到每秒请求数限制前可同时发出的最大请求数。默认情况下 (值为 `0`) ，等于 `s3_max_get_rps`。
* `s3_upload_part_size_multiply_factor` - 每当单次写入 S3 上传了 `s3_multiply_parts_count_threshold` 个分片时，就将 `s3_min_upload_part_size` 乘以该因子。默认值为 `2`。
* `s3_upload_part_size_multiply_parts_count_threshold` - 每当上传到 S3 的分片数达到该值时，`s3_min_upload_part_size` 就会乘以 `s3_upload_part_size_multiply_factor`。默认值为 `500`。
* `s3_max_inflight_parts_for_one_file` - 限制单个对象可并发执行的 PUT 请求数量。该数量应受到限制。值 `0` 表示无限制。默认值为 `20`。每个传输中的分片都会占用一个大小为 `s3_min_upload_part_size` 的缓冲区，前 `s3_upload_part_size_multiply_factor` 个分片如此；当文件足够大时，占用会更高，参见 `upload_part_size_multiply_factor`。在默认设置下，对于小于 `8G` 的文件，单个上传文件的内存占用不超过 `320Mb`。更大的文件占用会更高。

安全注意事项：如果恶意用户可以指定任意 S3 URL，则必须将 `s3_max_redirects` 设为 `0`，以避免 [SSRF](https://en.wikipedia.org/wiki/Server-side_request_forgery) 攻击；或者，也必须在服务器配置中指定 `remote_host_filter`。

<div id="endpoint-settings">
  ## 基于端点的设置
</div>

以下设置可在给定端点的配置文件中指定 (将按 URL 的精确前缀匹配) ：

* `endpoint` — 指定端点前缀。必填。
* `access_key_id` and `secret_access_key` — 指定给定端点使用的凭证。可选。
* `use_environment_credentials` — 如果设置为 `true`，S3 客户端将尝试从环境变量和 [亚马逊 EC2](https://en.wikipedia.org/wiki/Amazon_Elastic_Compute_Cloud) 元数据中获取给定端点的凭证。可选，默认值为 `false`。
* `region` — 指定 S3 区域名称。可选。
* `use_insecure_imds_request` — 如果设置为 `true`，S3 客户端在从亚马逊 EC2 元数据获取凭证时将使用不安全的 IMDS 请求。可选，默认值为 `false`。
* `expiration_window_seconds` — 用于检查基于过期时间的凭证是否已过期的宽限期。可选，默认值为 `120`。
* `no_sign_request` - 忽略所有凭证，使请求不带签名。适用于访问公共存储桶。
* `header` — 向发往给定端点的请求添加指定的 HTTP 请求头。可选，可指定多次。
* `access_header` - 在没有来自其他来源的凭证时，向发往给定端点的请求添加指定的 HTTP 请求头。
* `server_side_encryption_customer_key_base64` — 如果指定，将设置访问使用 SSE-C 加密的 S3 对象所需的请求头。可选。
* `server_side_encryption_kms_key_id` - 如果指定，将设置访问使用 [SSE-KMS encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html) 的 S3 对象所需的请求头。如果指定空字符串，将使用 AWS 托管的 S3 密钥。可选。
* `server_side_encryption_kms_encryption_context` - 如果与 `server_side_encryption_kms_key_id` 一起指定，则将设置 SSE-KMS 的相应加密上下文请求头。可选。
* `server_side_encryption_kms_bucket_key_enabled` - 如果与 `server_side_encryption_kms_key_id` 一起指定，则将设置用于为 SSE-KMS 启用 S3 存储桶密钥的请求头。可选，可以是 `true` 或 `false`，默认不设置 (与存储桶级别设置保持一致) 。
* `max_single_read_retries` — 单次读取的最大重试次数。默认值为 `4`。可选。
* `max_put_rps`, `max_put_burst`, `max_get_rps` and `max_get_burst` - 用于特定端点而非每个查询的限流设置 (参见上文说明) 。可选。

**示例：**

```xml

    <endpoint-name>
        <endpoint>https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/</endpoint>
        <!-- <access_key_id>ACCESS_KEY_ID</access_key_id> -->
```

<div id="working-with-archives">
  ## 使用归档文件
</div>

假设我们在 S3 上有几个归档文件，其 URI 如下：

* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-10.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-11.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-12.csv.zip&#39;

可以通过 :: 从这些归档文件中提取数据。URL 部分和 :: 后面的部分都可以使用通配符 (后者用于指定归档内文件的名称) 。

```sql
SELECT *
FROM s3(
   'https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-1{0..2}.csv.zip :: *.csv'
);
```

:::note
ClickHouse 支持三种归档格式：
ZIP
TAR
7Z
ZIP 和 TAR 归档可从任何受支持的存储位置访问，而 7Z 归档只能从安装 ClickHouse 的本地文件系统中读取。
:::

<div id="accessing-public-buckets">
  ## 访问公共存储桶
</div>

ClickHouse 会尝试从多种不同类型的来源获取凭证。
有时，访问某些公共存储桶时，这会引发问题，导致客户端返回 `403` 错误码。
可以使用 `NOSIGN` 关键字来避免此问题，强制客户端忽略所有凭证，并且不对请求进行签名。

```sql
CREATE TABLE big_table (name String, value UInt32)
    ENGINE = S3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv', NOSIGN, 'CSVWithNames');
```

<div id="role-based-access">
  ## 基于角色的访问控制
</div>

在 ClickHouse Cloud 中，您可以使用基于角色的访问控制对 S3 进行身份验证，而无需使用访问密钥。有关配置步骤，请参见 [Secure S3](/zh/cloud/data-sources/secure-s3)。

配置完成后，可以通过 `extra_credentials` 参数传递 `roleARN`：

```sql
CREATE TABLE my_s3_table(name String, value UInt32)
ENGINE = S3('https://my-bucket.s3.amazonaws.com/data/*.csv', extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001'), 'CSV')
```

也可以在提供 `role_arn` 时一并指定可选的 `external_id`。该值会作为 AWS STS `AssumeRole` 调用中的 `ExternalId` 参数传入，从而使该角色的信任策略能够要求提供共享密钥，以缓解[混淆代理问题](https://docs.aws.amazon.com/IAM/latest/UserGuide/confused-deputy.html)：

```sql
CREATE TABLE my_s3_table(name String, value UInt32)
ENGINE = S3('https://my-bucket.s3.amazonaws.com/data/*.csv', extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001', external_id = 'my-external-id'), 'CSV')
```
