## 记忆的工作原理 {#how-it-works}

一个小型记忆 agent 会与主对话并行运行。它会读取最近的消息，判断哪些内容值得记住，并将条目写入 per-user 存储。
在下一次对话中，主 agent 可以将这些条目作为上下文直接引用，您无需重复说明。

对您而言，这体现为一种连续性：只需告诉 agent 一次，您希望 SQL 输出使用小写，且您的财年截至三月，之后的对话就会自动遵循这些偏好。

## 管理您的记忆条目 {#manage-your-memories}

点击左侧导航中的 **记忆条目** (大脑) 图标，即可打开记忆面板。面板中会列出您已存储的记忆条目，并提供创建、编辑、删除和过滤条目的控件。

点击面板顶部的 **+** 按钮，打开 **Create Memory** 对话框。输入 **键** (仅限小写字母和下划线) 和 **值**，然后点击 **Create**。

## 开启或关闭记忆 {#toggle-memory}

通过记忆面板顶部的 **使用记忆** 复选框开启或关闭记忆功能。如果涉及不希望被存储的敏感话题，或者是个性化帮助不大的一次性对话，可以禁用该功能。

关闭记忆后，agent 既不会从您的记忆存储中读取内容，也不会向其中写入内容。

## 记忆最佳实践 {#memory-best-practices}

记忆适用于以下场景：

* 反复出现的约定：偏好的日期格式、业务定义、命名模式。
* 项目上下文：您通常查询哪个服务或数据库，以及您关注哪些仪表盘。
* 沟通风格：回复是简洁还是详尽，以代码为主还是以文字为主。

记忆并不是数据库。例如，它不适合用来存放大量参考资料。
此类资料应改用[技能](/zh/agents/builder/skills)承载，或直接写入agent的指令中。
记忆也不用于检索过往聊天内容，这一作用由会话历史本身承担。
