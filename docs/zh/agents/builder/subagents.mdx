子智能体是父智能体为处理自包含子任务而调用的子级智能体。子智能体拥有独立的上下文窗口和各自附加的工具，运行完成后向父智能体返回精简的结果。父智能体始终看不到子智能体的中间步骤，只能看到最终答案。

使用子智能体可以让父智能体保持专注。耗时较长的研究过程、重度依赖工具的探索以及专门的审查步骤，会产生大量消耗 token 的中间状态。将这些状态隔离在父智能体的上下文之外，效果会更好。

## 启用子智能体 {#enable-subagents}

在智能体构建器中，打开**高级设置**，然后开启**子智能体**开关。此时会再出现两个控件：

* **允许自我派生** - 开启后，智能体可以派生自身的副本来并行处理工作。适用于 fan-out 模式 (一个父智能体，多个相同的工作智能体) 。
* **附加子智能体** - 选择允许此父智能体委派任务的其他特定智能体。父智能体会在运行时根据任务决定调用哪个子智能体 (也可能不调用) 。

保存设置。智能体运行时，会新增一个用于调用子智能体的工具。

## 何时适合使用子智能体 {#when-a-subagent-helps}

* **研究类子任务** - 父智能体将复杂问题拆解，把其中一部分交给专门处理该部分的子智能体，再汇总各子智能体的响应。
* **工具密集型处理** - 代码解释器会话、多步骤的网页搜索循环，或任何会让中间工具输出占用父智能体上下文的操作。
* **专项评审** - 一个智能体负责生成，另一个负责评审，评审者的完整推理过程保留在其自身的上下文窗口中。

简单的调用不宜使用子智能体，因为交接会增加延迟和 token 消耗。

## 子智能体与智能体链 {#subagents-vs-agent-chain}

子智能体是一种运行时委派机制——由父智能体在运行时动态决定。智能体链则是一个预先定义的智能体图，其中的智能体按固定顺序运行。路由是动态的，就用子智能体；路由是固定的，就用智能体链。

## 限制 {#limits}

* 每个父智能体最多可列出 **10** 个子智能体。
* 从根智能体起最多 **5** 跳深度。
* 单次运行最多加载 **50** 个唯一的子智能体目标。
* 每个请求最多包含 **100** 个展开后的子智能体配置。

您引用的子智能体必须对运行该父智能体的用户可见。如果引用解析到无法访问或已删除的智能体，则会被静默跳过——因此在设计父智能体时，应确保其能够妥善处理子智能体缺失的情况。
