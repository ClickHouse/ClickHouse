内置的 Web SQL 界面 (`play.html`，通过任意 ClickHouse HTTP 端口的 [`/play`](/zh/concepts/features/connect-to-clickhouse/protocols/http) 路径提供) 支持在横向滚动表时，让结果中选定的列始终保持可见。固定列会停靠在结果区域的近侧边缘，不会随滚动移出视野。这样，键列 (例如标识符、名称或日期) 就能始终显示在您正在查看的最右侧各列旁边。

## 固定列 {#pinning-a-column}

每个列标题左侧都有一个 📌 图钉图标。单击该图标即可固定该列，再次单击则取消固定。该图标是一个真正的按钮，因此键盘用户可以按 Tab 键定位到它，并通过键盘切换开关，同时它还会向辅助技术报告自身的固定状态。

在带有悬停指针的设备 (如鼠标) 上，该图标仅在鼠标悬停于列标题上或开关获得焦点时显示，其余时候不会干扰操作；在触摸屏及其他无法悬停的粗略指针设备上，该图标始终显示，以便直接点按。已固定的列会始终以完整亮度显示其图标，以表明该列已被固定。

## 何时可使用固定功能 {#when-pinning-is-available}

只有当表宽到需要横向滚动时，才会提供固定功能。如果整个表都能在视口中完整显示，就不存在会被滚出视野的列，因此固定开关处于禁用状态，也不会纳入键盘 Tab 键的焦点顺序。一旦结果出现横向滚动 (例如结果较宽、窗口较窄，或流式结果在横向上不断扩展) ，这些开关便会激活。

## 固定列在滚动时的行为 {#how-a-pinned-column-behaves-when-scrolling}

横向滚动时，固定列会随内容一起滑动，直到即将移出视口；此时它会吸附在较近的一侧边缘 (左侧的列吸附在左边缘，右侧的列吸附在右边缘) ，并保持可见。多个固定列会按原有顺序依次排列在边缘处，每一列都以边框与滚动内容分隔。固定列的单元格会覆盖在其下方滚动经过的普通单元格之上 (包括已选中的单元格) ，因此始终清晰可读。

## 在同一结果内共享 {#shared-across-a-result}

固定状态按列名跟踪，并在同一结果下的所有结果表之间共享：执行 `Run all` (多查询) 时，每条语句都会渲染出一张表，而这些表共享同一个固定列集合。这一点与 per-column 的[颜色编码模式](/zh/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/color-coding)相同。在其中一张表中固定名为 `id` 的列后，其他表中名为 `id` 的列也会随之固定；之后再次运行同一查询时，只要返回的结果中仍包含该列，它同样会保持固定。

固定列集合归属于其所固定的结果，即归属于查询选项卡；如果该选项卡是[笔记本](/zh/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/notebook)，则归属于其中的单个单元格。因此，在某个单元格中固定一列，不会影响其他单元格或其他选项卡，它们各自保留独立的固定设置。

## 持久化 {#persistence}

固定列集合会记录在页面 URL、浏览器历史记录以及其所属单元格的结果快照中，因此无论是重新加载页面、共享链接，还是在浏览器中前进或后退，固定列集合都会保留。在当前未打开编辑器的单元格中切换列的固定状态时，也会同步更新该单元格已保存的副本，因此重新加载后该状态依然保留。为保持紧凑，仅存储已固定的列——空集不会向 URL 或历史记录状态写入任何内容。

## 限制 {#limitations}

* 纵向 (转置) 单行布局中没有可横向滚动的列，因此不支持列固定。
