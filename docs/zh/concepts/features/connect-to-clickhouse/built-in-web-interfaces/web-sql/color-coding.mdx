内置 Web SQL 界面 (`play.html`，通过任意 ClickHouse HTTP 端口的 [`/play`](/zh/concepts/features/connect-to-clickhouse/protocols/http) 路径提供) 可以为结果单元格着色，让列中的规律一目了然。每一列都有自己的颜色编码模式，可单独切换。

## 切换模式 {#switching-the-mode}

每个列标题右侧都有一个 🌈 图标。点击该图标，即可在该列的可用模式之间循环切换。在支持悬停的指针设备 (如鼠标) 上，该图标仅在鼠标悬停于列标题时显示，平时不会干扰视线；而触摸屏等粗略指针设备不支持悬停，因此该图标始终显示，便于直接点按。

列可用的模式取决于其类型：

* 数值列以及 `Date`/`DateTime`/`Date32`/`DateTime64` 列按 `bar` → `heatmap` → `categorical` → `none` 的顺序循环切换。
* 其他所有列在 `none` 和 `categorical` 之间切换。

数值列的默认模式为 `bar`，其他所有列 (包括日期和时间列) 的默认模式均为 `none`。

## 模式 {#modes}

* **`bar`** — 在单元格中绘制一条与值成比例的横向条形。对于数值列，条形从零基线开始延伸；对于 `Date`/`DateTime` 列，条形则覆盖该列的 `min`..`max` 范围，因为零基线对时间戳没有意义。
* **`heatmap`** — 用颜色填充整个单元格背景，颜色表示该值在列的最小值和最大值之间的相对位置。
* **`categorical`** — 根据单元格值的哈希结果生成颜色并填充单元格背景，因此相同的值颜色相同，不同的值颜色不同。此模式适用于任何列类型。
* **`none`** — 不使用颜色编码。

`Date`、`DateTime`、`Date32` 和 `DateTime64` 列按其时间值着色，且统一以 UTC 解析，因此颜色刻度不受查看者浏览器时区的影响。

`heatmap` 和 `categorical` 的背景色使用 `oklch` 色彩空间，仅改变色相，而明度和彩度在每个主题下保持固定，因此无论使用浅色还是深色主题，单元格文本都清晰可读。即使某一行内容折行显示为多行，背景也会填满整个单元格。

## 选中时的 categorical 强调 {#categorical-emphasis}

在 `categorical` 模式下，选中某个单元格后，其他具有相同值的单元格会以更粗的字体和全对比度的文本颜色 (深色主题下为纯白色，浅色主题下为纯黑色) 突出显示。被选中的单元格本身不会突出显示。这样可以一目了然地看出某个值在该列中还出现在哪些位置。

## 持久化 {#persistence}

所选模式会按列保存在页面 URL 和浏览器历史记录中，因此在重新加载页面、共享链接或在浏览器中前进/后退时，这些模式都会保留。为使 URL 和历史记录状态保持紧凑，仅存储非默认的选择。

与[固定列](/zh/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/pinned-columns)一样，这些模式归属于其所着色的结果：即归属于查询选项卡；若该选项卡是[笔记本](/zh/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/notebook)，则归属于其中的各个单元格。同一次 `Run all` (多查询) 执行所生成的各个表共享这些模式，而其他单元格和其他选项卡则各自保留自己的模式。

## 限制 {#limitations}

* 纵向 (转置) 单行布局不显示颜色编码。
* 色阶不会区分 `DateTime64(9)` 中小于 1 微秒的差值，因为这类差值在渐变中没有视觉意义。
