内置 Web SQL 界面 (`play.html`，由任意 ClickHouse HTTP 端口的 [`/play`](/zh/concepts/features/connect-to-clickhouse/protocols/http) 路径提供) 可以将一个选项卡转换为笔记本：即由单元组成的有序序列，每个单元要么是带有独立结果的查询，要么是一段 Markdown 文本。这种文档形态与 Jupyter、Observable、Hex 和 Deepnote 相同，用途也一致——将一连串查询以及查询之间的推理过程集中保存在同一页面中。

笔记本模式以选项卡为单位启用。一个选项卡可以作为笔记本使用，而另一个选项卡仍可保持为普通的单查询编辑器；每个选项卡在页面重新加载后都会保留各自的笔记本。

## 添加单元 {#adding-cells}

选项卡最初只有一个查询单元，外观与普通编辑器完全相同：没有标题栏，没有单元边框等装饰，也看不出笔记本的存在。查询生成结果后，其下方会出现一个较大的 `[+]` 按钮。该按钮刻意采用低调的样式，以免喧宾夺主、干扰结果的查看。点击该按钮，会展开两种可添加的单元：

* **Query** — 新建查询单元。新单元会立即获得编辑器焦点，可直接开始输入。
* **Text** — 新建 Markdown 单元，打开后即处于编辑模式。

添加第二个单元后，该选项卡即进入笔记本模式。

## 单元标题栏 {#cell-headers}

当存在两个或更多单元时，每个单元都会显示一个标题栏，标明其位置和类型，例如 `1. Query` 或 `2. Text`。查询单元在运行过程中还会显示一个状态点，运行失败时则显示红点；已完成的单元不做任何标记，因为其结果就显示在正下方。

当鼠标悬停在单元上或单元获得焦点时，标题栏中会显示以下操作：

| 操作        | 含义                                     |
| --------- | -------------------------------------- |
| `▶`       | 执行此单元的连续序列 (仅限查询单元)                       |
| `✎`       | 编辑此单元：接管编辑器，或将文本单元切换回源文本             |
| `＋`       | 在此单元之前插入新单元；同样会以内联方式显示 Query/Text 选项 |
| `↑` / `↓` | 将单元上移或下移                              |
| `✕`       | 删除该单元                                 |

每个选项卡始终至少保留一个查询单元，因为共享编辑器就位于其中，所以最后一个查询单元上的 `✕` 处于禁用状态。

## 查询单元 {#query-cells}

页面上始终只有一个查询编辑器——即具备语法高亮、自动补全和查询参数输入框的完整编辑器。在笔记本模式下，它会停靠在当前活跃的查询单元中，并且仅在获得焦点时显示：一旦焦点离开，该单元也会随之折叠，因此在阅读笔记本时，页面上不会出现任何展开的文本区域。点击已折叠的查询即可让编辑器回到该单元 (如果编辑器原本位于另一个单元，则会将其移过来) 。焦点在编辑器内部移动——例如移到查询参数输入框或某个补全候选结果上——不会导致其折叠。

已折叠的查询单元会以单行形式显示其查询：保留语法高亮，连续的空白字符 (包括缩进和换行符) 会被压缩为一个空格，内容过长时末尾会在右侧淡出。它本身没有背景，因此已折叠的单元在页面上看起来就是一段文本，而不是另一个输入框。

`Run` 按钮、进度行以及复制/下载操作会从页面顶部移出，停靠在正在编辑的查询下方，位于查询与其结果之间——这正是它们所描述的那次连续序列所在的位置，也让如何运行该单元一目了然。它们属于编辑器，因此会随着单元获得或失去焦点而一同出现或消失。

在笔记本模式下，结果显示得更紧凑：字体更小，单元格填充也相应缩小，表格高度最多为视口高度的四分之一。拖动结果的底边即可调整其占用的空间，方式与调整查询编辑器大小完全相同；文本单元的 Markdown 编辑器也有同样的拖动手柄。表格本身就是滚动容器 (垂直和水平方向均是如此) ，因此其细滚动条位于表格自身的边缘，较长或较宽的结果既不会把笔记本的其余部分向下推，也不会撑宽页面，并且滚动时列标题会固定在表格顶部。由于表头此时位于表格的最顶端，列的类型会显示在表头下方、覆盖在前几行之上，而不像在随页面滚动的表格中那样显示在表头上方。

运行方式与以往相同：`Ctrl/Cmd+Enter` (或 `Run` 按钮) 会运行编辑器中的查询，即当前活跃单元的查询。每个选项卡同一时间只能运行一个查询；在同一选项卡的另一个单元中启动连续序列，或按下 `Stop`，都会结束之前的连续序列。

`Logs` 和 `Metrics` 视图以及进度行中的资源计量器，归属于它们所描述的结果所在的单元：每个单元都保留各自的选择和计量器，而共享的开关显示的是当前活跃单元产生的内容。切换单元时，会恢复该单元自己的日志、指标和计量器。查询运行期间，进度行会保留在正在运行查询的单元中——将编辑器移到另一个单元去编写下一个查询，既不会清空实时进度，也不会让这些开关转而指向另一个单元的结果。

列颜色编码、固定列以及[结果结构](/zh/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/result-shaping) (包括排序、过滤器和分页) 同样归属于单元：它们是针对某个结果设定的，因此会跟随该结果。对某个单元的结果进行排序或过滤会重新运行该单元；如果编辑器位于其他单元中，会先将其移过来。如果某个单元通过 `Run all` 生成了多个表，这些表共用同一套设置，而各个单元之间则互不影响；共享链接和浏览器历史记录携带的是当前活跃单元的设置，其他单元的设置则随各自的单元保存。

## 文本单元 {#text-cells}

文本单元用于存放 Markdown。编辑时，文本区域会显示源文本，并高亮其中的标记——标题、强调、代码片段、链接、列表符号和引用块都会着色，但不会被渲染成最终格式——因此你编辑的始终是源文本。文本区域会随内容自动增高。

离开文本区域 (点击其他位置、按 `Escape` 或 `Ctrl/Cmd+Enter`) 即可结束编辑，文本区域随即替换为渲染后的 Markdown。点击渲染后的文本即可切换回编辑状态。

无论处于哪种状态，文本单元都使用与查询相同的等宽字体，因此整个笔记本读起来浑然一体，单元在源文本与渲染结果之间切换时字体也不会跳变。

支持标题、强调、内联代码和围栏代码块、链接和图片、自动链接的 URL、有序和无序列表、引用块、水平分隔线以及管道表格。文本单元中的原始 HTML 会被转义而非渲染；链接和图片的 URL 仅限 `http`、`https`、`mailto` 和相对目标——普通的相对链接 (例如 `[guide](guide.md)` 或 `![pic](images/pic.png)`) 可以正常使用，而 `javascript:`、`data:` 之类的 URL 方案，以及协议相对的 `//host/...` (它指向另一个源，而非相对目标) ，都会保留为纯文本。

## 持久化 {#persistence}

选项卡中的整个笔记本 (包括每个单元及其内容，以及小型结果快照) 会与工作区的其余部分一起存储在 IndexedDB 中，并在重新加载时恢复。其尽力而为的保存机制和结果大小限制与 [Web SQL 界面](/zh/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql) 中所述相同。

URL 和浏览器历史记录跟随当前活动的单元：`#` 片段携带该单元的查询，后退和前进会在您访问过的单元 (及选项卡) 之间切换。共享笔记本的 URL 时，共享的只是当前活动单元的查询，而不是整个笔记本。

为选项卡创建副本时会复制整个笔记本，但不包括结果。

将选项卡保存为 Markdown (通过标签栏中的保存按钮) 时，会按顺序写入笔记本的每个单元：每个查询单元写为一个围栏代码块，后跟其参数和结果表；每个文本单元写为一个信息字符串为 `markdown` 的围栏代码块。加载此类文档时，会恢复每个选项卡及其所有单元；但结果不会恢复，因此加载后的查询单元初始处于未运行状态。
