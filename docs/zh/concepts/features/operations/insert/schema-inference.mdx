对于几乎所有受支持的[输入格式](/zh/reference/formats/index)，ClickHouse 都能自动确定输入数据的结构。
本文将介绍何时会使用 schema 推断、schema 推断在不同输入格式下如何工作，以及可通过哪些设置对其进行控制。

## 用法 {#usage}

当 ClickHouse 需要读取特定数据格式的数据，但其结构未知时，就会使用 schema 推断。

## 表函数 [file](/zh/reference/functions/table-functions/file)、[s3](/zh/reference/functions/table-functions/s3)、[url](/zh/reference/functions/table-functions/url)、[hdfs](/zh/reference/functions/table-functions/hdfs)、[azureBlobStorage](/zh/reference/functions/table-functions/azureBlobStorage) {#table-functions-file-s3-url-hdfs-azureblobstorage}

这些表函数支持可选参数 `structure`，用于指定输入数据的结构。如果未指定该参数，或将其设置为 `auto`，则会根据数据自动推断结构。

**示例：**

假设 `user_files` 目录中有一个 JSONEachRow 格式的文件 `hobbies.jsonl`，内容如下：

```json
{"id" :  1, "age" :  25, "name" :  "Josh", "hobbies" :  ["football", "cooking", "music"]}
{"id" :  2, "age" :  19, "name" :  "Alan", "hobbies" :  ["tennis", "art"]}
{"id" :  3, "age" :  32, "name" :  "Lana", "hobbies" :  ["fitness", "reading", "shopping"]}
{"id" :  4, "age" :  47, "name" :  "Brayan", "hobbies" :  ["movies", "skydiving"]}
```

无需指定数据结构，ClickHouse 即可读取这些数据：

```sql
SELECT * FROM file('hobbies.jsonl')
```

```response
┌─id─┬─age─┬─name───┬─hobbies──────────────────────────┐
│  1 │  25 │ Josh   │ ['football','cooking','music']   │
│  2 │  19 │ Alan   │ ['tennis','art']                 │
│  3 │  32 │ Lana   │ ['fitness','reading','shopping'] │
│  4 │  47 │ Brayan │ ['movies','skydiving']           │
└────┴─────┴────────┴──────────────────────────────────┘
```

注意：`JSONEachRow` 格式是根据文件扩展名 `.jsonl` 自动推断出来的。

可以使用 `DESCRIBE` 查询查看自动推断出的结构：

```sql
DESCRIBE file('hobbies.jsonl')
```

```response
┌─name────┬─type────────────────────┬─default_type─┬─default_expression─┬─comment─┬─codec_expression─┬─ttl_expression─┐
│ id      │ Nullable(Int64)         │              │                    │         │                  │                │
│ age     │ Nullable(Int64)         │              │                    │         │                  │                │
│ name    │ Nullable(String)        │              │                    │         │                  │                │
│ hobbies │ Array(Nullable(String)) │              │                    │         │                  │                │
└─────────┴─────────────────────────┴──────────────┴────────────────────┴─────────┴──────────────────┴────────────────┘
```

## 表引擎 [File](/zh/reference/engines/table-engines/special/file)、[S3](/zh/reference/engines/table-engines/integrations/s3)、[URL](/zh/reference/engines/table-engines/special/url)、[HDFS](/zh/reference/engines/table-engines/integrations/hdfs)、[azureBlobStorage](/zh/reference/engines/table-engines/integrations/azureBlobStorage) {#table-engines-file-s3-url-hdfs-azureblobstorage}

如果 `CREATE TABLE` 查询中未指定列，表的结构将根据数据自动推断。

**示例：**

以文件 `hobbies.jsonl` 为例。我们可以基于该文件中的数据创建一个使用 `File` 引擎的表：

```sql
CREATE TABLE hobbies ENGINE=File(JSONEachRow, 'hobbies.jsonl')
```

```response

```

```sql
SELECT * FROM hobbies
```

```response
│  4 │  47 │ Brayan │ ['movies','skydiving']           │
```


## clickhouse-local {#clickhouse-local}

`clickhouse-local` 有一个可选参数 `-S/--structure`，用于指定输入数据的结构。如果未指定该参数或将其设置为 `auto`，则会根据数据自动推断结构。

**示例：**

以文件 `hobbies.jsonl` 为例。我们可以使用 `clickhouse-local` 查询该文件中的数据：

```shell
clickhouse-local --file='hobbies.jsonl' --table='hobbies' --query='DESCRIBE TABLE hobbies'
```

```response
id    Nullable(Int64)
age    Nullable(Int64)
name    Nullable(String)
hobbies    Array(Nullable(String))
```

```shell
clickhouse-local --file='hobbies.jsonl' --table='hobbies' --query='SELECT * FROM hobbies'
```

```response
1    25    Josh    ['football','cooking','music']
2    19    Alan    ['tennis','art']
3    32    Lana    ['fitness','reading','shopping']
4    47    Brayan    ['movies','skydiving']
```

## 使用插入目标表的结构 {#using-structure-from-insertion-table}

当使用表函数 `file/s3/url/hdfs` 向表中插入数据时，
可以选择直接使用插入目标表的结构，而不是从数据中提取结构。
由于 schema 推断可能需要一定时间，这样做可以提升插入性能。此外，如果表的 schema 已经过优化，这一做法也很有用，
因为这样就不会进行任何类型转换。

专门的设置 [use&#95;structure&#95;from&#95;insertion&#95;table&#95;in&#95;table&#95;functions](/zh/reference/settings/session-settings/use#use_structure_from_insertion_table_in_table_functions)
用于控制此行为。它有 3 个可选值：

* 0 - 表函数从数据中提取结构。
* 1 - 表函数使用插入目标表的结构。
* 2 - ClickHouse 自动判断是使用插入目标表的结构，还是使用 schema 推断。默认值。

**示例 1：**

创建表 `hobbies1`，其结构如下：

```sql
CREATE TABLE hobbies1
(
    `id` UInt64,
    `age` LowCardinality(UInt8),
    `name` String,
    `hobbies` Array(String)
)
ENGINE = MergeTree
ORDER BY id;
```

然后从文件 `hobbies.jsonl` 插入数据：

```sql
INSERT INTO hobbies1 SELECT * FROM file(hobbies.jsonl)
```

在这种情况下，文件中的所有列都会原样插入到表中，因此 ClickHouse 将直接使用插入目标表的结构，而不进行 schema 推断。

**示例 2：**

创建具有以下结构的表 `hobbies2`：

```sql
CREATE TABLE hobbies2
(
  `id` UInt64,
  `age` LowCardinality(UInt8),
  `hobbies` Array(String)
)
  ENGINE = MergeTree
ORDER BY id;
```

然后从文件 `hobbies.jsonl` 中插入数据：

```sql
INSERT INTO hobbies2 SELECT id, age, hobbies FROM file(hobbies.jsonl)
```

在这种情况下，`SELECT` 查询中的所有列都存在于表中，因此 ClickHouse 会使用插入目标表的结构。
请注意，这仅适用于支持读取部分列子集的输入格式，例如 JSONEachRow、TSKV、Parquet 等 (因此对 TSV 格式等不适用) 。

**示例 3：**

我们创建一个结构如下的表 `hobbies3`：

```sql
CREATE TABLE hobbies3
(
  `identifier` UInt64,
  `age` LowCardinality(UInt8),
  `hobbies` Array(String)
)
  ENGINE = MergeTree
ORDER BY identifier;
```

然后从文件 `hobbies.jsonl` 中插入数据：

```sql
INSERT INTO hobbies3 SELECT id, age, hobbies FROM file(hobbies.jsonl)
```

在这种情况下，`SELECT` 查询中使用了列 `id`，但该表中没有此列 (表中对应的列名为 `identifier`) ，
因此 ClickHouse 无法使用插入目标表的结构，而是会使用 schema 推断。

**示例 4：**

创建表 `hobbies4`，其结构如下：

```sql
CREATE TABLE hobbies4
(
  `id` UInt64,
  `any_hobby` Nullable(String)
)
  ENGINE = MergeTree
ORDER BY id;
```

然后从文件 `hobbies.jsonl` 中插入数据：

```sql
INSERT INTO hobbies4 SELECT id, empty(hobbies) ? NULL : hobbies[1] FROM file(hobbies.jsonl)
```

在这种情况下，`SELECT` 查询在将 `hobbies` 列插入表之前对其执行了一些操作，因此 ClickHouse 无法使用插入目标表的结构，而是会使用 schema 推断。

## Schema 推断缓存 {#schema-inference-cache}

对于大多数输入格式，schema 推断需要读取部分数据来确定其结构，这一过程可能会耗费一定时间。
为避免 ClickHouse 每次从同一文件读取数据时都重复推断相同的 schema，推断模式会被缓存；再次访问同一文件时，ClickHouse 将直接使用缓存中的 schema。

以下专用设置用于控制该缓存：

* `schema_inference_cache_max_elements_for_{file/s3/hdfs/url/azure}` - 对应表函数可缓存的 schema 的最大数量。默认值为 `4096`。这些设置需要在服务器配置中设置。
* `schema_inference_use_cache_for_{file,s3,hdfs,url,azure}` - 用于开启/关闭 schema 推断缓存。这些设置可以在查询中使用。

修改数据或更改格式设置都可能导致文件的 schema 发生变化。
因此，schema 推断缓存通过文件来源、格式名称、所用的格式设置以及文件的最后修改时间来标识 schema。

说明：在 `url` 表函数中通过 url 访问的某些文件可能不包含最后修改时间信息；针对这种情况，提供了专用设置
`schema_inference_cache_require_modification_time_for_url`。禁用此设置后，对于此类文件，即使没有最后修改时间，也可以使用缓存中的 schema。

此外，系统表 [schema&#95;inference&#95;cache](/zh/reference/system-tables/schema_inference_cache) 包含缓存中当前的所有 schema；系统查询 `SYSTEM CLEAR SCHEMA CACHE [FOR File/S3/URL/HDFS]`
则可用于清理所有数据源或特定数据源的模式缓存。

## 文本格式 {#text-formats}

对于文本格式，ClickHouse 会逐行读取数据，按照格式提取列值，
然后借助一些递归解析器和启发式方法来确定每个值的类型。schema 推断时从数据中读取的最大行数和最大字节数
分别由设置 `input_format_max_rows_to_read_for_schema_inference` (默认值为 25000) 和 `input_format_max_bytes_to_read_for_schema_inference` (默认值为 32Mb) 控制。
默认情况下，所有推断类型均为 [Nullable](/zh/reference/data-types/nullable)，但您可以通过设置 `schema_inference_make_columns_nullable` 来更改这一行为 (示例参见[设置](#settings-for-text-formats)部分) 。

### JSON 格式 {#json-formats}

在 JSON 格式中，ClickHouse 会按照 JSON 规范解析值，然后尝试为其推断最合适的数据类型。

下面我们来看看它的工作原理、可以推断出哪些类型，以及在 JSON 格式中可以使用哪些特定设置。

### CSV {#csv}

在 CSV 格式中，ClickHouse 根据分隔符从行中提取列值。除数字和字符串外，ClickHouse 要求所有类型的值都用双引号括起来。如果值位于双引号中，ClickHouse 会尝试使用递归解析器解析
引号内的数据，然后尝试为其确定最合适的数据类型。如果值不在双引号中，ClickHouse 会尝试将其解析为数字，
如果该值不是数字，则 ClickHouse 会将其视为字符串。

如果您不希望 ClickHouse 借助解析器和启发式方法来尝试确定复杂类型，可以禁用设置 `input_format_csv_use_best_effort_in_schema_inference`，
此时 ClickHouse 会将所有列都视为字符串类型。

如果启用了设置 `input_format_csv_detect_header`，ClickHouse 会在推断 schema 时尝试检测包含列名 (可能还包括类型) 的请求头。此设置默认启用。

### TSV/TSKV {#tsv-tskv}

### Template {#template}

使用 Template 格式时，ClickHouse 首先根据指定的模板从行中提取所有列值，然后尝试根据每个值的转义规则推断其
数据类型。

**示例**

假设有一个文件 `resultset`，内容如下：

```bash
<result_before_delimiter>
${data}<result_after_delimiter>
```

以及一个文件 `row_format`，内容如下：

```text
<row_before_delimiter>${column_1:CSV}<field_delimiter_1>${column_2:Quoted}<field_delimiter_2>${column_3:JSON}<row_after_delimiter>
```

接下来，我们可以执行以下查询：

```sql
SET format_template_rows_between_delimiter = '<row_between_delimiter>\n',
       format_template_row = 'row_format',
       format_template_resultset = 'resultset_format'

DESC format(Template, $$<result_before_delimiter>
<row_before_delimiter>42.42<field_delimiter_1>'Some string 1'<field_delimiter_2>[1, null, 2]<row_after_delimiter>
<row_between_delimiter>
<row_before_delimiter>\N<field_delimiter_1>'Some string 3'<field_delimiter_2>[1, 2, null]<row_after_delimiter>
<result_after_delimiter>
$$)
```

### Regexp {#regexp}

与 Template 类似，ClickHouse 在处理 Regexp 格式时，首先根据指定的正则表达式从行中提取所有列值，然后尝试根据指定的转义规则推断

### 文本格式设置 {#settings-for-text-formats}

#### input_format_max_rows_to_read_for_schema_inference/input_format_max_bytes_to_read_for_schema_inference {#input-format-max-rows-to-read-for-schema-inference}

这些设置控制 schema 推断过程中读取的数据量。
读取的行数/字节数越多，schema 推断耗时就越长，但正确判断类型的可能性也越大 (尤其是数据中包含大量空值时) 。

默认值：

* `input_format_max_rows_to_read_for_schema_inference` 的默认值为 `25000`。
* `input_format_max_bytes_to_read_for_schema_inference` 的默认值为 `33554432` (32 Mb) 。

#### column_names_for_schema_inference {#column-names-for-schema-inference}

为不包含显式列名的格式指定 schema 推断时使用的列名列表。指定的列名将替代默认列名 `c1,c2,c3,...`。格式为：`column1,column2,column3,...`。

**示例**

```sql
DESC format(TSV, 'Hello, World!    42    [1, 2, 3]') settings column_names_for_schema_inference = 'str,int,arr'
```


#### schema_inference_make_columns_nullable $ {#schema-inference-make-columns-nullable}

* 1 - 所有推断类型都将是 `Nullable`，

#### input_format_try_infer_datetimes {#input-format-try-infer-datetimes}

## 自描述格式 {#self-describing-formats}

自描述格式在数据本身中包含了数据结构信息，
这些信息可以采用带有描述信息的头部、二进制类型树或某种表的形式。
为了从此类格式的文件中自动推断 schema，ClickHouse 会读取数据中包含
类型信息的部分，并将其转换为 ClickHouse 表的 schema。

### 带有 -WithNamesAndTypes 后缀的格式 {#formats-with-names-and-types}

ClickHouse 支持一些带有 -WithNamesAndTypes 后缀的文本格式。此后缀表示实际数据之前有两行额外内容，分别包含列名和类型。
对此类格式进行 schema 推断时，ClickHouse 会读取前两行并提取列名和类型。

**示例**

```sql
DESC format(TSVWithNamesAndTypes,
$$num    str    arr
UInt8    String    Array(UInt8)
42    Hello, World!    [1,2,3]
$$)
```

```response
┌─name─┬─type─────────┬─default_type─┬─default_expression─┬─comment─┬─codec_expression─┬─ttl_expression─┐
│ num  │ UInt8        │              │                    │         │                  │                │
│ str  │ String       │              │                    │         │                  │                │
│ arr  │ Array(UInt8) │              │                    │         │                  │                │
└──────┴──────────────┴──────────────┴────────────────────┴─────────┴──────────────────┴────────────────┘
```

### 带有元数据的 JSON 格式 {#json-with-metadata}

某些 JSON 输入格式 ([JSON](/zh/reference/formats/JSON/JSON)、[JSONCompact](/zh/reference/formats/JSON/JSONCompact)、[JSONColumnsWithMetadata](/zh/reference/formats/JSON/JSONColumnsWithMetadata)) 包含记录列名和类型的元数据。
在对此类格式进行 schema 推断时，ClickHouse 会读取这些元数据。

**示例**

```sql
DESC format(JSON, $$
{
    "meta":

            "name": "num",

        },
        {
            "name": "str",
            "type": "String"
        },

            "name": "arr",

        }
    ],

    "data":
    [
        {
            "num": 42,
            "str": "Hello, World",
            "arr": [1,2,3]
        }
    ],

    "rows": 1,

    "statistics":
    {
        "elapsed": 0.005723915,
        "rows_read": 1,
        "bytes_read": 1
    }
}
$$)
```

```response
┌─name─┬─type─────────┬─default_type─┬─default_expression─┬─comment─┬─codec_expression─┬─ttl_expression─┐

└──────┴──────────────┴──────────────┴────────────────────┴─────────┴──────────────────┴────────────────┘
```

### Avro {#avro}

读取 Avro 格式时，ClickHouse 从数据中读取其模式，并根据以下类型映射将其转换为 ClickHouse schema：

| Avro 数据类型                          | ClickHouse 数据类型                                                       |
| ---------------------------------- | --------------------------------------------------------------------- |
| `boolean`                          | [Bool](/zh/reference/data-types/boolean)                                 |
| `int`                              | [Int32](/zh/reference/data-types/int-uint)                               |
| `int (date)` *                     | [Date32](/zh/reference/data-types/date32)                                |
| `long`                             | [Int64](/zh/reference/data-types/int-uint)                               |
| `float`                            | [Float32](/zh/reference/data-types/float)                                |
| `double`                           | [Float64](/zh/reference/data-types/float)                                |
| `bytes`, `string`                  | [String](/zh/reference/data-types/string)                                |
| `fixed`                            | [FixedString(N)](/zh/reference/data-types/fixedstring)                   |
| `enum`                             | [Enum](/zh/reference/data-types/enum)                                    |
| `array(T)`                         | [Array(T)](/zh/reference/data-types/array)                               |
| `union(null, T)`, `union(T, null)` | [Nullable(T)](/zh/reference/data-types/date)                             |
| `null`                             | [Nullable(Nothing)](/zh/reference/data-types/special-data-types/nothing) |
| `string (uuid)` *                  | [UUID](/zh/reference/data-types/uuid)                                    |
| `binary (decimal)` *               | [Decimal(P, S)](/zh/reference/data-types/decimal)                        |

## 强类型二进制格式 {#strong-typed-binary-formats}

在此类格式中，每个已序列化的值都包含其类型信息 (可能还包含名称信息) ，但不包含整张表的信息。
对此类格式进行 schema 推断时，ClickHouse 会逐行读取数据 (最多读取 `input_format_max_rows_to_read_for_schema_inference` 行或 `input_format_max_bytes_to_read_for_schema_inference` 字节) ，从数据中提取
每个值的类型 (可能还包括名称) ，然后将这些类型转换为 ClickHouse 类型。

### MsgPack {#msgpack}

MsgPack 格式的行之间没有分隔符。要对此格式使用 schema 推断，应通过设置 `input_format_msgpack_number_of_columns` 指定表中的列数。
ClickHouse 使用以下类型映射：

| MessagePack 数据类型 (`INSERT`)                                        | ClickHouse 数据类型                              |
| ------------------------------------------------------------------ | -------------------------------------------- |
| `int N`, `uint N`, `negative fixint`, `positive fixint`            | [Int64](/zh/reference/data-types/int-uint)      |
| `bool`                                                             | [UInt8](/zh/reference/data-types/int-uint)      |
| `fixstr`, `str 8`, `str 16`, `str 32`, `bin 8`, `bin 16`, `bin 32` | [String](/zh/reference/data-types/string)       |
| `float 32`                                                         | [Float32](/zh/reference/data-types/float)       |
| `float 64`                                                         | [Float64](/zh/reference/data-types/float)       |
| `uint 16`                                                          | [Date](/zh/reference/data-types/date)           |
| `uint 32`                                                          | [日期时间](/zh/reference/data-types/datetime)       |
| `uint 64`                                                          | [DateTime64](/zh/reference/data-types/datetime) |
| `fixarray`, `array 16`, `array 32`                                 | [Array](/zh/reference/data-types/array)         |
| `fixmap`, `map 16`, `map 32`                                       | [Map](/zh/reference/data-types/map)             |

默认情况下，所有推断类型均封装在 `Nullable` 中，但可以通过设置 `schema_inference_make_columns_nullable` 更改此行为。

### BSONEachRow {#bsoneachrow}

在 BSONEachRow 中，每行数据都表示为一个 BSON 文档。在 schema 推断过程中，ClickHouse 逐个读取 BSON 文档，从中提取
值、名称和类型，再按照以下类型映射将这些类型转换为 ClickHouse 类型：

| BSON 类型                                                                  | ClickHouse 类型                                                                        |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `\x08` 布尔类型                                                              | [Bool](/zh/reference/data-types/boolean)                                                |
| `\x10` int32                                                             | [Int32](/zh/reference/data-types/int-uint)                                              |
| `\x12` int64                                                             | [Int64](/zh/reference/data-types/int-uint)                                              |
| `\x01` 双精度浮点数                                                            | [Float64](/zh/reference/data-types/float)                                               |
| `\x09` 日期时间                                                              | [DateTime64](/zh/reference/data-types/datetime64)                                       |
| `\x05` 二进制数据 (二进制子类型为 `\x00`) 、`\x02` 字符串、`\x0E` 符号、`\x0D` JavaScript 代码 | [String](/zh/reference/data-types/string)                                               |
| `\x07` ObjectId，                                                         | [FixedString(12)](/zh/reference/data-types/fixedstring)                                 |
| `\x05` 二进制数据 (UUID 子类型为 `\x04`，大小 = 16)                                  | [UUID](/zh/reference/data-types/uuid)                                                   |
| `\x04` array                                                             | [Array](/zh/reference/data-types/array)/[Tuple](/zh/reference/data-types/tuple) (嵌套类型不同时)  |
| `\x03` 文档                                                                | [命名元组](/zh/reference/data-types/tuple)/[Map](/zh/reference/data-types/map) (键为 String 类型)  |

默认情况下，所有推断类型均封装在 `Nullable` 中，但可以通过 `schema_inference_make_columns_nullable` 设置更改此行为。

## schema 推断模式 {#schema-inference-modes}

对一组数据文件进行 schema 推断时，可使用 2 种模式：`default` 和 `union`。
具体模式由 `schema_inference_mode` 设置控制。

### 默认模式 {#default-schema-inference-mode}

在默认模式下，ClickHouse 假定所有文件的 schema 相同，并尝试逐个读取文件以推断 schema，直到推断成功。

示例：

假设有 3 个文件 `data1.jsonl`、`data2.jsonl` 和 `data3.jsonl`，内容如下：

`data1.jsonl`：

```json
{"field1" :  1, "field2" :  null}
{"field1" :  2, "field2" :  null}
{"field1" :  3, "field2" :  null}
```

`data2.jsonl`：

```json
{"field1" :  4, "field2" :  "Data4"}
{"field1" :  5, "field2" :  "Data5"}
{"field1" :  6, "field2" :  "Data5"}
```

`data3.jsonl`：

```json
{"field1" :  7, "field2" :  "Data7", "field3" :  [1, 2, 3]}
{"field1" :  8, "field2" :  "Data8", "field3" :  [4, 5, 6]}
{"field1" :  9, "field2" :  "Data9", "field3" :  [7, 8, 9]}
```

下面尝试对这 3 个文件进行 schema 推断：

```sql title="Query"
:) DESCRIBE file('data{1,2,3}.jsonl') SETTINGS schema_inference_mode='default'
```

```response title="Response"
┌─name───┬─type─────────────┐
│ field1 │ Nullable(Int64)  │
│ field2 │ Nullable(String) │
└────────┴──────────────────┘
```

如上所示，结果中没有来自文件 `data3.jsonl` 的 `field3` 字段。
这是因为 ClickHouse 首先尝试从文件 `data1.jsonl` 推断 schema，但由于字段 `field2` 中的值全为空值而失败，
随后尝试从 `data2.jsonl` 推断 schema 并成功，因此未读取文件 `data3.jsonl` 中的数据。

### 联合模式 {#default-schema-inference-mode-1}

在联合模式下，ClickHouse 假定各文件的 schema 可能不同，因此会推断所有文件的 schema，再将它们合并为一个统一的 schema。

假设有 3 个文件 `data1.jsonl`、`data2.jsonl` 和 `data3.jsonl`，内容如下：

`data1.jsonl`：

```json
{"field1" :  1}
{"field1" :  2}
{"field1" :  3}
```

`data2.jsonl`：

```json
{"field2" :  "Data4"}
{"field2" :  "Data5"}
{"field2" :  "Data5"}
```

`data3.jsonl`：

```json
{"field3" :  [1, 2, 3]}
{"field3" :  [4, 5, 6]}
{"field3" :  [7, 8, 9]}
```

下面尝试对这 3 个文件进行 schema 推断：

```sql title="Query"
:) DESCRIBE file('data{1,2,3}.jsonl') SETTINGS schema_inference_mode='union'
```

```response title="Response"
┌─name───┬─type───────────────────┐
│ field1 │ Nullable(Int64)        │
│ field2 │ Nullable(String)       │
│ field3 │ Array(Nullable(Int64)) │
└────────┴────────────────────────┘
```

可以看到，我们获得了所有文件中的全部字段。

注意：

* 由于部分文件可能缺少最终 schema 中的某些列，联合模式仅支持可读取列子集的格式 (如 JSONEachRow、Parquet、TSVWithNames 等) ，不支持其他格式 (如 CSV、TSV、JSONCompactEachRow 等) 。
* 如果 ClickHouse 无法从某个文件中推断出 schema，则会抛出异常。
* 如果文件数量很多，读取所有文件的 schema 可能会耗费大量时间。

## 自动格式检测 {#automatic-format-detection}

如果未指定数据格式，且无法通过文件扩展名确定，ClickHouse 将尝试根据文件内容检测其格式。

**示例：**

假设 `data` 的内容如下：

```csv
"a","b"
1,"Data1"
2,"Data2"
3,"Data3"
```

无需指定格式或结构，即可查看和查询此文件：

```sql
:) desc file(data);
```

```response
┌─name─┬─type─────────────┐
│ a    │ Nullable(Int64)  │
│ b    │ Nullable(String) │
└──────┴──────────────────┘
```

```sql
:) select * from file(data);
```

```response
┌─a─┬─b─────┐
│ 1 │ Data1 │
│ 2 │ Data2 │
│ 3 │ Data3 │
└───┴───────┘
```

<Note>
  ClickHouse 只能自动识别部分格式，且识别过程需要一定时间，因此建议始终显式指定格式。
</Note>
