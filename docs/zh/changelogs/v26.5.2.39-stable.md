  ### ClickHouse 发布 v26.5.2.39-稳定版本 (8462fd8f3de) FIXME，相较于 v26.5.1.882-稳定版本 (5b96a8d8a5e)

<div id="backward-incompatible-change">
  #### 向后不兼容变更
</div>

* 已在 [#106038](https://github.com/ClickHouse/ClickHouse/issues/106038) 中回移：设置 `show_data_lake_catalogs_in_system_tables` 已重命名为 `show_remote_databases_in_system_tables`，且适用范围已扩大：当其值为 0 (默认值) 时，除数据湖目录外，`MySQL` 和 `PostgreSQL` 数据库也会在 `system.tables`、`system.columns` 和 `system.completions` 中被隐藏。旧设置名称保留为别名。[#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)) 。

<div id="improvement">
  #### 改进
</div>

* 已在 [#105770](https://github.com/ClickHouse/ClickHouse/issues/105770) 中回移：对 Keeper 进行了多项优化，使其整体速度提升约 2 倍 (包括更高效的批次处理、向 leader 的消息流水线传输，以及日志追加的流水线化) 。[#101757](https://github.com/ClickHouse/ClickHouse/pull/101757) ([Michael Kolupaev](https://github.com/al13n321)).
* 已在 [#106585](https://github.com/ClickHouse/ClickHouse/issues/106585) 中回移：修复了在主键列上使用带 `IN` 子查询的 `PREWHERE` 时，未使用主键索引进行粒度剪枝的问题；该问题会导致执行全表扫描，而不是只读取相关粒度。[#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 已在 [#106233](https://github.com/ClickHouse/ClickHouse/issues/106233) 中回移：降低了在 ClickHouse Keeper 中使用 `KeeperMemoryStorage` 应用接收的快照时的峰值内存占用。[#105851](https://github.com/ClickHouse/ClickHouse/pull/105851) ([Antonio Andelic](https://github.com/antonio2368)).
* 已在 [#106123](https://github.com/ClickHouse/ClickHouse/issues/106123) 中回移：为 Keeper 新增了 `coordination_settings`，用于限制 `NuRaft` 未提交日志条目的准入，以及对 `append-entries` 反向探测进行限流。[#106108](https://github.com/ClickHouse/ClickHouse/pull/106108) ([Antonio Andelic](https://github.com/antonio2368)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常表现)
</div>

* 已在 [#105806](https://github.com/ClickHouse/ClickHouse/issues/105806) 中回移：修复通过 `INSERT INTO FUNCTION hdfs(...)` 向 HDFS 写入 Parquet (以及其他带尾部的格式，如 ORC 和 Arrow) 时发生的数据损坏问题。自 26.1 起，`WriteBufferFromHDFS` 在 `finalize()` 时不会 flush 其工作缓冲区，导致每个文件最后最多 `DBMS_DEFAULT_BUFFER_SIZE` 字节被静默丢失，其中包括 Parquet 的 `PAR1` 页脚。读取此类文件时会返回 `Not a Parquet file (wrong magic bytes at the end of file)`。[#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* 已在 [#105755](https://github.com/ClickHouse/ClickHouse/issues/105755) 中回移：`LEFT ANTI JOIN` 现在会为未匹配的行正确返回右侧连接键列的默认值，而不是重复左侧键值。此前，`SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` 对于未匹配的行可能返回 `r = a.x`，而实际上应返回默认值 (`Int32` 为 `0`，`String` 为 `''`，`Nullable` 为 `NULL`) 。只有连接键列受影响；右侧非键列此前已能正确返回默认值。当优化器交换两侧时，同样的 bug 也会出现在 `RIGHT ANTI JOIN` 中。关闭 [#99959](https://github.com/ClickHouse/ClickHouse/issues/99959)。[#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* 已在 [#105670](https://github.com/ClickHouse/ClickHouse/issues/105670) 中回移：对 `catalog_type = 'glue'` 的 `DataLakeCatalog` database 执行长时间运行的 `INSERT ... SELECT` 及其他读取操作时，一旦在加载表 metadata 时获取的 STS session credentials 超过有效期，就会失败并报错 `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)`。[#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* 已在 [#105768](https://github.com/ClickHouse/ClickHouse/issues/105768) 中回移：修复在某些情况下与 `ARRAY JOIN` 一起使用时，负数 `LIMIT BY` 会触发 logical error 的问题。[#105403](https://github.com/ClickHouse/ClickHouse/pull/105403) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 已在 [#105622](https://github.com/ClickHouse/ClickHouse/issues/105622) 中回移：修复读取 Arrow 或 ArrowStream 文件时的 heap-buffer-overflow 问题，该问题会在 binary 或 string 列中间 offsets 损坏时发生；同时修复读取带有 geo 标签的 Arrow 列时的空指针解引用问题。[#105449](https://github.com/ClickHouse/ClickHouse/pull/105449) ([Raúl Marín](https://github.com/Algunenano)).
* 已在 [#105884](https://github.com/ClickHouse/ClickHouse/issues/105884) 中回移：修复在默认参数为 `Nullable` expression、启用 `short_circuit_function_evaluation` 且字典键同时包含命中和未命中时，`dictGetOrDefault` 抛出 `CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN` 的问题。[#105461](https://github.com/ClickHouse/ClickHouse/pull/105461) ([Raúl Marín](https://github.com/Algunenano)).
* 已在 [#106489](https://github.com/ClickHouse/ClickHouse/issues/106489) 中回移：修复 ALTER 后从压缩的 Memory 表读取 Dynamic subcolumns 时发生的 SIGSEGV。关闭 [#104901](https://github.com/ClickHouse/ClickHouse/issues/104901)。[#105464](https://github.com/ClickHouse/ClickHouse/pull/105464) ([Pavel Kruglov](https://github.com/Avogar)).
* 已在 [#105876](https://github.com/ClickHouse/ClickHouse/issues/105876) 中回移：修复了在结合 `GROUP BY ... WITH ROLLUP`、`WITH CUBE` 或 `WITH TOTALS` 并传入 Nullable 参数时，使用 `uniqStateOrNull` / `uniqStateOrDefault` / `uniqOrNullState` (以及 `uniq` 上类似的组合器链) 会触发的 server segfault。 [#105470](https://github.com/ClickHouse/ClickHouse/pull/105470) ([Groene AI](https://github.com/groeneai)).
* 已在 [#105973](https://github.com/ClickHouse/ClickHouse/issues/105973) 中回移：修复了 `singleValueOrNull` 在 JSON type 反序列化时的 SEGFAULT。关闭 [#103630](https://github.com/ClickHouse/ClickHouse/issues/103630)。 [#105535](https://github.com/ClickHouse/ClickHouse/pull/105535) ([Pavel Kruglov](https://github.com/Avogar)).
* 已在 [#105724](https://github.com/ClickHouse/ClickHouse/issues/105724) 中回移：修复了 replxx 因触及 select() 的 FD&#95;SETSIZE 限制而崩溃的问题 (已改为使用 poll()) 。请注意，启用 SSH/Web 终端时，这可能会导致 server 崩溃。 [#105559](https://github.com/ClickHouse/ClickHouse/pull/105559) ([Azat Khuzhin](https://github.com/azat)).
