<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常表现)
</div>

* 已在 [#108450](https://github.com/ClickHouse/ClickHouse/issues/108450) 中回移：修复在 `JOIN ON` 中使用 `arrayJoin()` 时行数统计错误的问题：结果会按数组长度被额外多乘一次。[#104785](https://github.com/ClickHouse/ClickHouse/pull/104785) ([Shaohua Wang](https://github.com/tiandiwonder)) 。
* 已在 [#108263](https://github.com/ClickHouse/ClickHouse/issues/108263) 中回移：修复空 merged part 上 text index 出现 &quot;Too many marks&quot; 的问题。[#106867](https://github.com/ClickHouse/ClickHouse/pull/106867) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#107911](https://github.com/ClickHouse/ClickHouse/issues/107911) 中回移：修复合并包含 `Variant` 列的已排序块时可能发生的崩溃 (`Source column is not Map` / `SIGSEGV`) ：该 `Variant` 列包含一个 `Map` 变体，且其本地存储顺序与全局顺序不一致。[#107011](https://github.com/ClickHouse/ClickHouse/pull/107011) ([Groene AI](https://github.com/groeneai)) 。
* 已在 [#108168](https://github.com/ClickHouse/ClickHouse/issues/108168) 中回移：修复读取 MsgPack、BSON、ORC、Parquet、JSON、DeltaLake、Iceberg 和 Paimon 格式中深度嵌套的 schema 或值时，可能导致服务器栈溢出 (崩溃) 的问题。现在这类深度嵌套输入会被拒绝，并抛出异常。[#107341](https://github.com/ClickHouse/ClickHouse/pull/107341) ([Raúl Marín](https://github.com/Algunenano)) 。
* 已在 [#108226](https://github.com/ClickHouse/ClickHouse/issues/108226) 中回移：修复 `windowFunnel` 中的堆缓冲区溢出 (服务器崩溃) 问题：使用超出范围的事件类型完成特制的聚合函数状态时会触发，任何用户只需一次 `SELECT` 即可触发该问题。[#107412](https://github.com/ClickHouse/ClickHouse/pull/107412) ([uwezkhan](https://github.com/uwezkhan)) 。
* 已在 [#108503](https://github.com/ClickHouse/ClickHouse/issues/108503) 中回移：在 `update()` 内部重建的新 snapshot 已通过 `createBuilder` 捕获了 C++ S3 client 的当前凭证，因此当版本匹配时应保留该 snapshot 而不是将其丢弃，这样下一次内核操作就会在具有最新凭证的 engine 上运行，不会超过 STS TTL。[#107480](https://github.com/ClickHouse/ClickHouse/pull/107480) ([Elmi Ahmadov](https://github.com/ahmadov)) 。
* 已在 [#108239](https://github.com/ClickHouse/ClickHouse/issues/108239) 中回移：为 Elf 和 DWARF 解析补充缺失的边界检查。[#107579](https://github.com/ClickHouse/ClickHouse/pull/107579) ([Michael Kolupaev](https://github.com/al13n321)) 。
* 已在 [#108162](https://github.com/ClickHouse/ClickHouse/issues/108162) 中回移：读取由 Apache Arrow Java &lt; 19.0.0 (包括 Apache Spark) 生成、包含空 `String`/`Binary` 列的 Arrow/ArrowStream 数据时，不再抛出 `INCORRECT_DATA`。[#107764](https://github.com/ClickHouse/ClickHouse/pull/107764) ([Raúl Marín](https://github.com/Algunenano)) 。
* 已在 [#108208](https://github.com/ClickHouse/ClickHouse/issues/108208) 中回移：修复 set 跳过索引无法在 LowCardinality 列上剪枝粒度的问题。[#107868](https://github.com/ClickHouse/ClickHouse/pull/107868) ([Konstantin Bogdanov](https://github.com/thevar1able)) 。
* 已在 [#108308](https://github.com/ClickHouse/ClickHouse/issues/108308) 中回移：修复在带有 `Dynamic` 键的 `Map` 上调用 `has` 时发生的崩溃问题 (release 构建中为 SIGSEGV，debug 构建中为类型不匹配断言) ：当 lookup argument 为 `LowCardinality` 时会触发，例如 `has(map('a'::Dynamic, ...), toLowCardinality('b'))`。[#107956](https://github.com/ClickHouse/ClickHouse/pull/107956) ([Groene AI](https://github.com/groeneai)) 。
* 已在 [#108398](https://github.com/ClickHouse/ClickHouse/issues/108398) 中回移：修复了带有 PREWHERE 的 Map 子列性能回退问题。关闭 [#107912](https://github.com/ClickHouse/ClickHouse/issues/107912)。由以下变更引起：[https://github.com/ClickHouse/ClickHouse/pull/99200](https://github.com/ClickHouse/ClickHouse/pull/99200)。[#107988](https://github.com/ClickHouse/ClickHouse/pull/107988) ([Pavel Kruglov](https://github.com/Avogar)) 。
* 已在 [#108136](https://github.com/ClickHouse/ClickHouse/issues/108136) 中回移：修复了使用多个线程读取 `Dynamic` 列时的性能回退问题。由 [https://github.com/ClickHouse/ClickHouse/pull/100730](https://github.com/ClickHouse/ClickHouse/pull/100730) 引起。关闭 [#107942](https://github.com/ClickHouse/ClickHouse/issues/107942)。[#107997](https://github.com/ClickHouse/ClickHouse/pull/107997) ([Pavel Kruglov](https://github.com/Avogar)) 。
* 已在 [#108200](https://github.com/ClickHouse/ClickHouse/issues/108200) 中回移：始终运行访问缓存的批次完成处理器，即使批次为空也是如此。[#108124](https://github.com/ClickHouse/ClickHouse/pull/108124) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#108322](https://github.com/ClickHouse/ClickHouse/issues/108322) 中回移：修复了在错误时机丢失 ZooKeeper 连接时，可刷新materialized view 卡住的问题。[#108234](https://github.com/ClickHouse/ClickHouse/pull/108234) ([Michael Kolupaev](https://github.com/al13n321)) 。
* 已在 [#108485](https://github.com/ClickHouse/ClickHouse/issues/108485) 中回移：当 `format_display_secrets_in_show_and_select` 被禁用时 (默认设置) ，在 `EXPLAIN actions`、`EXPLAIN header` 和 `EXPLAIN PIPELINE` 的输出中隐藏 `encrypt`、`decrypt` 和 `HMAC` 等函数的敏感参数。[#108386](https://github.com/ClickHouse/ClickHouse/pull/108386) ([Raúl Marín](https://github.com/Algunenano)) 。
* 已在 [#108780](https://github.com/ClickHouse/ClickHouse/issues/108780) 中回移：修复了 `ssl_certificate` 用户识别逻辑，使单个 `*` 通配符恰好只匹配一个名称组件 (RFC 6125 6.4.3) 。此前，`CN` 或 `DNS:` SAN subject 中的通配符 (例如 `*.corp.example.com`) 也会匹配 `evil.deep.corp.example.com` 这类多标签名称，从而使持有更深层子域证书的用户能够以该通配符用户身份进行认证。`URI:` SAN 的匹配规则保持不变。[#108472](https://github.com/ClickHouse/ClickHouse/pull/108472) ([Groene AI](https://github.com/groeneai)) 。
* 已在 [#108697](https://github.com/ClickHouse/ClickHouse/issues/108697) 中回移：修复了一处元数据泄露问题，其中 `DESCRIBE loop('db', 'table')` 和 `DESCRIBE loop(<inner table function>)` 绕过了 `SHOW COLUMNS` / source 访问检查，使未授权用户能够读取表的列 schema。[#108624](https://github.com/ClickHouse/ClickHouse/pull/108624) ([Groene AI](https://github.com/groeneai)) 。
