  ### ClickHouse 版本 v25.10.1.3832-稳定版本 (f95c1af632a) FIXME，较 v25.10.1.1-new (5b1dfb14925)

<div id="backward-incompatible-change">
  #### 不向后兼容的变更
</div>

* 将默认的 `schema_inference_make_columns_nullable` 设置更改为：尊重 Parquet/ORC/Arrow metadata 中列的 `Nullable` 属性信息，而不是将所有列都设为 Nullable。text formats 无变化。[#71499](https://github.com/ClickHouse/ClickHouse/pull/71499) ([Michael Kolupaev](https://github.com/al13n321)).
* 此 PR 使查询结果缓存忽略 `log_comment` 设置，因此仅修改查询的 `log_comment` 将不再导致查询结果缓存未命中。少数用户可能曾通过修改 `log_comment` 有意对缓存进行分段。此变更会改变这一行为，因此不向后兼容。请改用 `query_cache_tag` 设置来实现此目的。[#79878](https://github.com/ClickHouse/ClickHouse/pull/79878) ([filimonov](https://github.com/filimonov)).
* 在早期版本中，如果查询里包含与 operators 的实现函数同名的 table functions，其格式化结果会不一致。关闭 [#81601](https://github.com/ClickHouse/ClickHouse/issues/81601)。关闭 [#81977](https://github.com/ClickHouse/ClickHouse/issues/81977)。关闭 [#82834](https://github.com/ClickHouse/ClickHouse/issues/82834)。关闭 [#82835](https://github.com/ClickHouse/ClickHouse/issues/82835)。EXPLAIN SYNTAX 查询将不再格式化 operators——这一新行为更符合语法解释的目的。对于 `clickhouse-format`、`formatQuery` 及类似工具，如果查询中以函数形式写出了这些内容，则不会再将 functions 格式化为 operators。[#82825](https://github.com/ClickHouse/ClickHouse/pull/82825) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 禁止在 JOIN 连接键中使用 Dynamic 类型。当 Dynamic 类型与非 Dynamic 类型进行比较时，可能会导致异常结果。更好的做法是将 Dynamic 列转换为所需类型。[#86358](https://github.com/ClickHouse/ClickHouse/pull/86358) ([Pavel Kruglov](https://github.com/Avogar)).
* Storage&#95;metadata&#95;write&#95;full&#95;object&#95;key server 选项现已默认启用，且无法再关闭。这是一个向后兼容的变更。我加这个标签是为了提醒注意。此变更仅与 25.x 发行版前向兼容。这意味着，如果你必须回滚新发行版，则只能降级到某个 25.x 发行版。[#87335](https://github.com/ClickHouse/ClickHouse/pull/87335) ([Sema Checherinda](https://github.com/CheSema)).
* 将 replicated&#95;deduplication&#95;window&#95;seconds 从 1 周缩短到 1 小时，以便在插入速率较低时减少 ZooKeeper 中 znode 的存储数量。[#87414](https://github.com/ClickHouse/ClickHouse/pull/87414) ([Sema Checherinda](https://github.com/CheSema)).
* 将设置 `query_plan_use_new_logical_join_step` 重命名为 `query_plan_use_logical_join_step`。[#87679](https://github.com/ClickHouse/ClickHouse/pull/87679) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 新语法让 tokenizer parameter 的表达能力更强。[#87997](https://github.com/ClickHouse/ClickHouse/pull/87997) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 将函数 `searchAny` 和 `searchAll` 重命名为 `hasAnyTokens` 和 `hasAllTokens`，以更好地与现有函数 `hasToken` 保持一致。[#88109](https://github.com/ClickHouse/ClickHouse/pull/88109) ([Robert Schulze](https://github.com/rschu1ze)).
* 从文件系统缓存中移除 `cache_hits_threshold`。这个功能是在我们有 SLRU cache policy 之前由一位外部 contributor 添加的，而现在既然已经有了 SLRU cache policy，就没有必要同时支持两者了。[#88344](https://github.com/ClickHouse/ClickHouse/pull/88344) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `min_free_disk_ratio_to_perform_insert` 和 `min_free_disk_bytes_to_perform_insert` 这两个设置的工作方式有两处细微调整：- 使用未预留字节数而不是可用字节数来判断是否应拒绝 insert。如果为后台 merges 和 mutations 预留的空间相对配置的阈值较小，这一点可能不是特别关键，但这样看起来更准确。- 不再将这些设置应用于系统表。原因是我们仍然希望 `query_log` 这样的表继续更新。这对调试很有帮助。写入系统表的数据量通常远小于实际数据，因此在合理的 `min_free_disk_ratio_to_perform_insert` 阈值下，它们通常可以持续更长时间。[#88468](https://github.com/ClickHouse/ClickHouse/pull/88468) ([c-end](https://github.com/c-end)) 。
* 为 Keeper 的内部复制启用异步模式。Keeper 将保持与之前相同的行为，同时可能带来性能提升。如果你是从 23.9 之前的版本升级，则需要先升级到 23.9+，再升级到 25.10+。你也可以在升级前将 `keeper_server.coordination_settings.async_replication` 设置为 0，并在升级完成后再启用它。[#88515](https://github.com/ClickHouse/ClickHouse/pull/88515) ([Antonio Andelic](https://github.com/antonio2368)) 。

* 新增一种方式，可通过 server configuration 的 `resources_and_workloads` 部分在 SQL 中提供 WORKLOAD 和 RESOURCE 定义。[#87430](https://github.com/ClickHouse/ClickHouse/pull/87430) ([Sergei Trifonov](https://github.com/serxa)) 。

<div id="performance-improvement">
  #### 性能提升
</div>

* 通过重构 Query Condition Cache (QCC) 与索引分析的执行顺序及集成方式，提升了查询性能。现在会先应用 QCC 筛选，再进行主键和跳过索引分析，从而减少不必要的索引计算。索引分析现已支持多个范围过滤器，其筛选结果也会回写到 QCC 中。这显著加快了那些执行时间主要耗费在索引分析上的查询——尤其是依赖跳过索引 (如向量索引或倒排索引) 的查询。[#82380](https://github.com/ClickHouse/ClickHouse/pull/82380) ([Amos Bird](https://github.com/amosbird)).
* 为 MergeTree 表中的顶层 String 列新增了可选的 `.size` 子列序列化，以提升压缩效果并实现高效的子列访问。同时引入了新的 MergeTree 设置，用于控制序列化版本以及针对空字符串的表达式优化。[#82850](https://github.com/ClickHouse/ClickHouse/pull/82850) ([Amos Bird](https://github.com/amosbird)).
* 通过一系列微优化，加快了小型查询的执行速度。[#83096](https://github.com/ClickHouse/ClickHouse/pull/83096) ([Raúl Marín](https://github.com/Algunenano)).
* 在 native protocol 中压缩日志和 profile events。在拥有 100+ 副本的集群中，未压缩的 profile events 会占用 1..10 MB/sec，而在较慢的 Internet 连接下，进度条会响应迟缓。此更改关闭了 [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533)。[#83586](https://github.com/ClickHouse/ClickHouse/pull/83586) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 使用 [StringZilla](https://github.com/ashvardanian/StringZilla) 库，并在可用时利用 SIMD CPU 指令，提升了区分大小写的字符串搜索性能 (如筛选操作，例如 `WHERE URL LIKE '%google%'`) 。[#84161](https://github.com/ClickHouse/ClickHouse/pull/84161) ([Raúl Marín](https://github.com/Algunenano)).
* 当对聚合 MergeTree 表执行带 FINAL 的 select，且该表包含类型为 `SimpleAggregateFunction(anyLast)` 的列时，减少了内存分配和内存拷贝。[#84428](https://github.com/ClickHouse/ClickHouse/pull/84428) ([Duc Canh Le](https://github.com/canhld94)).
* 提供了下推 JOIN 析取谓词的逻辑。示例：在 TPC-H Q7 中，对于 2 个表 n1 和 n2 上类似 `(n1.n_name = 'FRANCE' AND n2.n_name = 'GERMANY') OR (n1.n_name = 'GERMANY' AND n2.n_name = 'FRANCE')` 的条件，我们会为每个表分别提取部分过滤器：对 n1 提取 `n1.n_name = 'FRANCE' OR n1.n_name = 'GERMANY'`，对 n2 提取 `n2.n_name = 'GERMANY' OR n2.n_name = 'FRANCE'`。[#84735](https://github.com/ClickHouse/ClickHouse/pull/84735) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 通过新的默认设置 `optimize_rewrite_like_perfect_affix`，提升了带前缀或后缀的 `LIKE` 的性能。[#85920](https://github.com/ClickHouse/ClickHouse/pull/85920) ([Guang Zhao](https://github.com/zheguang)).
* 修复了按多个字符串/数值列分组时，由于序列化后的键过大导致的性能下降问题。关闭 https://github.com/ClickHouse/ClickHouse/pull/83884#issuecomment-3187972297 cc @mkmkme。这是 https://github.com/ClickHouse/ClickHouse/pull/83884 的后续修复。[#85924](https://github.com/ClickHouse/ClickHouse/pull/85924) ([李扬](https://github.com/taiyang-li)).
* 改进了 DB::SharedMutex。[#87491](https://github.com/ClickHouse/ClickHouse/pull/87491) ([Raúl Marín](https://github.com/Algunenano)).
* 提升了为主要包含低频 token 的文档构建文本索引的性能。[#87546](https://github.com/ClickHouse/ClickHouse/pull/87546) ([Anton Popov](https://github.com/CurtizJ)).
* 加快了 Field 析构函数常见路径的执行速度。[#87631](https://github.com/ClickHouse/ClickHouse/pull/87631) ([Raúl Marín](https://github.com/Algunenano)).
* 在 join 优化期间，跳过运行时哈希表统计信息的重新计算。新增 profile events `JoinOptimizeMicroseconds` 和 `QueryPlanOptimizeMicroseconds`。[#87683](https://github.com/ClickHouse/ClickHouse/pull/87683) ([Vladimir Cherkasov](https://github.com/vdimir))。
* 为 MergeTreeLazy 读取器启用将 marks 保存到缓存，并避免使用直接 IO。[#87989](https://github.com/ClickHouse/ClickHouse/pull/87989) ([Nikita Taranov](https://github.com/nickitat))。
* 对带有 `is_deleted` 列的 `ReplacingMergeTree` 表执行带 `FINAL` 子句的 SELECT 查询时，现在速度更快了，这得益于在现有 2 项优化基础上改进了并行化：1) 对于仅包含单个 `分片` 的表分区，应用 `do_not_merge_across_partitions_select_final` 优化；2) 将表中其他选定范围拆分为 `相交 / 不相交`，且只有相交范围才需要经过 FINAL merging transform。[#88090](https://github.com/ClickHouse/ClickHouse/pull/88090) ([Shankar Iyer](https://github.com/shankar-iyer))。
* 降低未使用 fail points 带来的影响。[#88196](https://github.com/ClickHouse/ClickHouse/pull/88196) ([Raúl Marín](https://github.com/Algunenano))。
* 避免在按 `uuid` 过滤 `system.tables` 时执行 full scan (如果你手头只有来自 logs 或 ZooKeeper path 的 UUID，这会很有用) 。[#88379](https://github.com/ClickHouse/ClickHouse/pull/88379) ([Azat Khuzhin](https://github.com/azat))。
* 改进了函数 `tokens`、`hasAllTokens`、`hasAnyTokens` 的性能。[#88416](https://github.com/ClickHouse/ClickHouse/pull/88416) ([Anton Popov](https://github.com/CurtizJ))。
* 为 Iceberg 支持按顺序读取。[#88454](https://github.com/ClickHouse/ClickHouse/pull/88454) ([scanhex12](https://github.com/scanhex12))。
* 将 `AddedColumns::appendFromBlock` 内联，以在某些情况下略微提升 join 性能。[#88455](https://github.com/ClickHouse/ClickHouse/pull/88455) ([Nikita Taranov](https://github.com/nickitat))。
* 已在 [#89182](https://github.com/ClickHouse/ClickHouse/issues/89182) 中回移：在 JOIN 和 ARRAY JOIN 中实现惰性列复制。在某些输出格式中，避免将 Sparse 和 Replicated 等特殊列表示转换为普通列。这样可避免不必要的内存数据拷贝。[#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar))。





<div id="improvement">
  #### 改进
</div>

* 允许在 Keeper 中覆盖配置时配置服务器级别的限流。关闭 [#73964](https://github.com/ClickHouse/ClickHouse/issues/73964)。[#74066](https://github.com/ClickHouse/ClickHouse/pull/74066) ([JIaQi](https://github.com/JiaQiTang98))。
* `mannWhitneyUTest` 在两个样本均只包含相同值时不再抛出异常，现在会返回有效结果，与 SciPy 保持一致。关闭 [#79814](https://github.com/ClickHouse/ClickHouse/issues/79814)。[#80009](https://github.com/ClickHouse/ClickHouse/pull/80009) ([DeanNeaht](https://github.com/DeanNeaht))。
* 重写磁盘对象存储事务：元数据事务提交后，将删除之前的远程 blob。[#81787](https://github.com/ClickHouse/ClickHouse/pull/81787) ([Sema Checherinda](https://github.com/CheSema))。
* 修复了优化前后结果类型的 LowCardinality 不同时，冗余等值表达式优化过程中的问题。[#82651](https://github.com/ClickHouse/ClickHouse/pull/82651) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* 当 HTTP 客户端在 `Expect: 100-continue` 之外还设置了 `X-ClickHouse-100-Continue: defer` 请求头时，ClickHouse 会等到配额验证通过后才向客户端发送 `100 Continue` 响应，从而避免因传输最终会被丢弃的请求体而浪费网络带宽。这对 INSERT 查询尤为相关——查询可通过 URL 查询字符串发送，而数据则在请求体中传输。在未发送完整请求体的情况下中止请求会阻止 HTTP/1.1 的连接复用，但与大数据量 INSERT 的总耗时相比，重新建立连接引入的额外延迟通常可以忽略不计。[#84304](https://github.com/ClickHouse/ClickHouse/pull/84304) ([c-end](https://github.com/c-end))。
* 客户端自动补全改为使用 `system.completions`，而非发起多次系统表查询，速度更快且结果更一致。[#84694](https://github.com/ClickHouse/ClickHouse/pull/84694) ([|2ustam](https://github.com/RuS2m))。
* 通过在运行时从右子树构建布隆过滤器并将其传递给左子树的扫描操作，加速部分 JOIN 查询。这对类似 `SELECT avg(o_totalprice) FROM orders, customer, nation WHERE c_custkey = o_custkey AND c_nationkey=n_nationkey AND n_name = 'FRANCE'` 的查询尤为有效。[#84772](https://github.com/ClickHouse/ClickHouse/pull/84772) ([Alexander Gololobov](https://github.com/davenger))。
