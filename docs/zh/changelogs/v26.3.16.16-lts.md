  ### ClickHouse 发布 v26.3.16.16-长期支持版 (f3c09372ed9) FIXME，与 v26.3.15.4-长期支持版 (3c767441a1e) 相比

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 已在 [#108281](https://github.com/ClickHouse/ClickHouse/issues/108281) 中回移：JDBC、ODBC 和 NATS 连接字符串中的凭证现会在查询日志和 `SHOW CREATE` 输出中被屏蔽，防止敏感信息意外泄露。对于 URI 风格的连接字符串 (例如 {scheme}://{user}:{password}@{host}) ，仅屏蔽密码部分，其余部分仍保持可见，以便于调试。`nats_token` 设置现在也会被屏蔽。[#99344](https://github.com/ClickHouse/ClickHouse/pull/99344) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)) 。
* 已在 [#108446](https://github.com/ClickHouse/ClickHouse/issues/108446) 中回移：修复在 `JOIN ON` 中使用 `arrayJoin()` 时返回行数错误的问题：结果会被按数组长度额外再乘一次。 [#104785](https://github.com/ClickHouse/ClickHouse/pull/104785) ([Shaohua Wang](https://github.com/tiandiwonder)).
* 已在 [#107482](https://github.com/ClickHouse/ClickHouse/issues/107482) 中回移：修复了向量搜索查询使用 vector index，同时又使用另一个跳过索引 (如 `minmax`) 且 `use_skip_indexes_on_data_read = 1` 时出现的异常。 [#106473](https://github.com/ClickHouse/ClickHouse/pull/106473) ([Shankar Iyer](https://github.com/shankar-iyer)).
* 已在 [#108259](https://github.com/ClickHouse/ClickHouse/issues/108259) 中回移：修复空 merged part 上 text index 的 &quot;Too many marks&quot; 问题。 [#106867](https://github.com/ClickHouse/ClickHouse/pull/106867) ([Azat Khuzhin](https://github.com/azat)).
* 已在 [#108170](https://github.com/ClickHouse/ClickHouse/issues/108170) 中回移：修复了 `Block structure mismatch in UnionStep stream` logical error (在 debug/sanitizer 构建中会导致 server 中止，在 release 构建中则表现为 `Code: 49`) 。该问题会在 `UNION`/`INTERSECT`/`EXCEPT` 的某个分支将 `Sparse` 序列化列读取出来、而同级分支将同一列作为完整列读取时发生 (例如推送到 materialized view 时) 。 [#107041](https://github.com/ClickHouse/ClickHouse/pull/107041) ([Groene AI](https://github.com/groeneai)).
* 已在 [#108222](https://github.com/ClickHouse/ClickHouse/issues/108222) 中回移：修复了 `windowFunnel` 中的 heap buffer overflow (server 崩溃) 问题：当以超出范围的事件类型完成一个精心构造的聚合函数状态时，任何用户只需一次 `SELECT` 即可触发。 [#107412](https://github.com/ClickHouse/ClickHouse/pull/107412) ([uwezkhan](https://github.com/uwezkhan)).
* 已在 [#108501](https://github.com/ClickHouse/ClickHouse/issues/108501) 中回移：在 `update()` 内部重建的新 snapshot 已通过 `createBuilder` 捕获了 C++ S3 client 当前的凭证；版本匹配时应保留它而不是将其丢弃，这样下一次内核操作就会在刚更新过凭证的 engine 上运行，不会超出 STS TTL。 [#107480](https://github.com/ClickHouse/ClickHouse/pull/107480) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 已在 [#108638](https://github.com/ClickHouse/ClickHouse/issues/108638) 中回移：修复了 `ReplicatedMergeTree` 表的 `RESTORE`，使来自备份的重复内容分片会被保留，而不是被静默去重。 [#107652](https://github.com/ClickHouse/ClickHouse/pull/107652) ([Pablo Marcos](https://github.com/pamarcos)).
* 已在 [#108203](https://github.com/ClickHouse/ClickHouse/issues/108203) 中回移：修复集合跳过索引无法在 LowCardinality 列上裁剪粒度的问题。 [#107868](https://github.com/ClickHouse/ClickHouse/pull/107868) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 已在 [#108304](https://github.com/ClickHouse/ClickHouse/issues/108304) 中回移：修复了在键为 `Dynamic` 的 `Map` 上对 `has` 进行调用时发生的崩溃 (在 release 构建中为 SIGSEGV，在 debug 构建中为类型不匹配断言) ；当 lookup 参数为 `LowCardinality` 时会触发，例如 `has(map('a'::Dynamic, ...), toLowCardinality('b'))`。 [#107956](https://github.com/ClickHouse/ClickHouse/pull/107956) ([Groene AI](https://github.com/groeneai)).
* 已在 [#108196](https://github.com/ClickHouse/ClickHouse/issues/108196) 中回移：始终运行访问缓存的批次完成 handlers，即使批次为空也不例外。 [#108124](https://github.com/ClickHouse/ClickHouse/pull/108124) ([Azat Khuzhin](https://github.com/azat)).
* 已在 [#108320](https://github.com/ClickHouse/ClickHouse/issues/108320) 中回移：修复了可刷新materialized view 在错误时机丢失 ZooKeeper 连接后卡住的问题。[#108234](https://github.com/ClickHouse/ClickHouse/pull/108234) ([Michael Kolupaev](https://github.com/al13n321)).
* 已在 [#108481](https://github.com/ClickHouse/ClickHouse/issues/108481) 中回移：当禁用 `format_display_secrets_in_show_and_select` (默认设置) 时，在 `EXPLAIN actions`、`EXPLAIN header` 和 `EXPLAIN PIPELINE` 输出中隐藏 `encrypt`、`decrypt` 和 `HMAC` 等函数的敏感参数。[#108386](https://github.com/ClickHouse/ClickHouse/pull/108386) ([Raúl Marín](https://github.com/Algunenano)).
* 已在 [#108693](https://github.com/ClickHouse/ClickHouse/issues/108693) 中回移：修复了一处元数据泄露问题，其中 `DESCRIBE loop('db', 'table')` 和 `DESCRIBE loop(<inner table function>)` 会绕过 `SHOW COLUMNS` / source 访问权限检查，从而让无权限用户读取表的列 schema。[#108624](https://github.com/ClickHouse/ClickHouse/pull/108624) ([Groene AI](https://github.com/groeneai)).
