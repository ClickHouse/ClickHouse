<div id="improvement">
  #### 改进

* 已在 [#88480](https://github.com/ClickHouse/ClickHouse/issues/88480) 中回移：在服务端 (原生) 复制到备份目标端时，使用带有备份专用设置 (例如 `backup_slow_all_threads_after_retryable_s3_error`) 的 S3 storage client。将 `s3_slow_all_threads_after_retryable_error` 标记为 Obsolete。[#87660](https://github.com/ClickHouse/ClickHouse/pull/87660) ([Julia Kartseva](https://github.com/jkartseva)).
* 已在 [#88302](https://github.com/ClickHouse/ClickHouse/issues/88302) 中回移：更新 azure sdk，纳入在复制和 create container 功能中出现的 `Content-Length` 修复。[#88278](https://github.com/ClickHouse/ClickHouse/pull/88278) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 已在 [#88783](https://github.com/ClickHouse/ClickHouse/issues/88783) 中回移：修复了 `GLOBAL IN` 导致的内存泄漏 ([https://github.com/ClickHouse/ClickHouse/issues/88615](https://github.com/ClickHouse/ClickHouse/issues/88615)) 。[#88617](https://github.com/ClickHouse/ClickHouse/pull/88617) ([pranavmehta94](https://github.com/pranavmehta94)).
* 已在 [#88766](https://github.com/ClickHouse/ClickHouse/issues/88766) 中回移：为 `clickhouse-keeper` 的 postinstall script 添加一个步骤，以启用开机自启动。[#88746](https://github.com/ClickHouse/ClickHouse/pull/88746) ([YenchangChan](https://github.com/YenchangChan)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 已在 [#88226](https://github.com/ClickHouse/ClickHouse/issues/88226) 中回移：修复了一处崩溃问题：某些用户提交到 `AggregateFunction(quantileDD)` 列的有效数据可能导致合并操作无限递归。[#86560](https://github.com/ClickHouse/ClickHouse/pull/86560) ([Raphaël Thériault](https://github.com/raphael-theriault-swi)).
* 已在 [#88229](https://github.com/ClickHouse/ClickHouse/issues/88229) 中回移：修复了在存在行级策略时 move-to-prewhere 优化不生效的问题。此修复是 [#85118](https://github.com/ClickHouse/ClickHouse/issues/85118) 的延续。关闭 [#69777](https://github.com/ClickHouse/ClickHouse/issues/69777)。关闭 [#83748](https://github.com/ClickHouse/ClickHouse/issues/83748)。[#87303](https://github.com/ClickHouse/ClickHouse/pull/87303) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 已在 [#88391](https://github.com/ClickHouse/ClickHouse/issues/88391) 中回移：在 AzureBlobStorage 中，现会优先尝试 native copy，并在出现 &#39;Unauthroized&#39; 错误时回退到 read &amp; write (在 AzureBlobStorage 中，如果 source 和 destination 使用的是不同的 storage account，就会收到 &#39;Unauthorized&#39; 错误) 。同时修复了在 configuration 中定义端点时 `use&#95;native&#95;copy` 未正确生效的问题。[#87826](https://github.com/ClickHouse/ClickHouse/pull/87826) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 已在 [#88692](https://github.com/ClickHouse/ClickHouse/issues/88692) 中回移：如果 argument 类型不允许用于 GROUP BY，则不要从 GROUP BY 中移除 injective functions。[#87958](https://github.com/ClickHouse/ClickHouse/pull/87958) ([Pavel Kruglov](https://github.com/Avogar)).
* 已在 [#88438](https://github.com/ClickHouse/ClickHouse/issues/88438) 中回移：修复了在查询中使用 `session_timezone` setting 时，基于日期时间的键在粒度/分区裁剪上不正确的问题。[#87987](https://github.com/ClickHouse/ClickHouse/pull/87987) ([Eduard Karacharov](https://github.com/korowa)).
* 已在 [#88422](https://github.com/ClickHouse/ClickHouse/issues/88422) 中回移：对于 [https://github.com/ClickHouse/ClickHouse/pull/84503](https://github.com/ClickHouse/ClickHouse/pull/84503) 中引入的授权检查，会在评估前先进行 URI 规范化。[#88089](https://github.com/ClickHouse/ClickHouse/pull/88089) ([pufit](https://github.com/pufit)).
* 已在 [#88176](https://github.com/ClickHouse/ClickHouse/issues/88176) 中回移：修复了在附加了包含无效表的外部 database (`PostgreSQL`/`SQLite`/...) 时，读取 `system.tables` 可能触发未捕获异常的问题。[#88105](https://github.com/ClickHouse/ClickHouse/pull/88105) ([Azat Khuzhin](https://github.com/azat)).
* 已在 [#88258](https://github.com/ClickHouse/ClickHouse/issues/88258) 中回移：现在如果 cluster 中存在不活跃副本，`ON CLUSTER` 查询所需时间会更短。[#88153](https://github.com/ClickHouse/ClickHouse/pull/88153) ([alesapin](https://github.com/alesapin)).
* 已在 [#88208](https://github.com/ClickHouse/ClickHouse/issues/88208) 中回移：修复了在没有 cgroups 的情况下运行 ClickHouse 的问题 (异步指标曾意外地使 cgroups 成为必需项) 。[#88164](https://github.com/ClickHouse/ClickHouse/pull/88164) ([Azat Khuzhin](https://github.com/azat)).
* 已在 [#88285](https://github.com/ClickHouse/ClickHouse/issues/88285) 中回移：修复了 `ColumnLowCardinality` 中 `is_shared` 标志传播不正确的问题。如果某列在哈希值已预先计算并缓存到 `ReverseIndex` 后又插入了新值，可能会导致错误的 group-by 结果。[#88213](https://github.com/ClickHouse/ClickHouse/pull/88213) ([Nikita Taranov](https://github.com/nickitat)).
* 已回移至 [#88461](https://github.com/ClickHouse/ClickHouse/issues/88461)：修复了 workload setting `max_cpu_share`。现在即使未设置 `max_cpus` workload setting，也可以使用它。[#88217](https://github.com/ClickHouse/ClickHouse/pull/88217) ([Neerav](https://github.com/neeravsalaria)) 。
* 已回移至 [#88338](https://github.com/ClickHouse/ClickHouse/issues/88338)：现在，关联子查询将支持对象存储。[#88290](https://github.com/ClickHouse/ClickHouse/pull/88290) ([alesapin](https://github.com/alesapin)) 。
* 已回移至 [#88358](https://github.com/ClickHouse/ClickHouse/issues/88358)：避免在访问 `system.projections` 和 `system.data_skipping_indices` 时尝试初始化 DataLake database。[#88330](https://github.com/ClickHouse/ClickHouse/pull/88330) ([Azat Khuzhin](https://github.com/azat)) 。
* 已回移至 [#88432](https://github.com/ClickHouse/ClickHouse/issues/88432)：修复了 `countMatches` 函数中的二次复杂度问题。关闭 [#88400](https://github.com/ClickHouse/ClickHouse/issues/88400)。[#88401](https://github.com/ClickHouse/ClickHouse/pull/88401) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 已回移至 [#88650](https://github.com/ClickHouse/ClickHouse/issues/88650)：节点数 &gt; 10 的大型集群在执行 restore 时，很可能因错误 `[941] 67c45db4-4df4-4879-87c5-25b8d1e0d414 <Trace>: RestoreCoordinationOnCluster The version of node /clickhouse/backups/restore-7c551a77-bd76-404c-bad0-3213618ac58e/stage/num_hosts changed (attempt #9), will try again` 而失败。`num_hosts` 节点会被多个主机同时覆盖。此修复使控制重试次数的设置变为动态。关闭 [#87721](https://github.com/ClickHouse/ClickHouse/issues/87721)。[#88484](https://github.com/ClickHouse/ClickHouse/pull/88484) ([Mikhail f. Shiryaev](https://github.com/Felixoid)) 。
