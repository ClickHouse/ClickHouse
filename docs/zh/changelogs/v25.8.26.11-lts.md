<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 回移于 [#108866](https://github.com/ClickHouse/ClickHouse/issues/108866)：修复了对包含存在循环依赖表的备份执行 `RESTORE` 时，server 异常中止的问题。[#103824](https://github.com/ClickHouse/ClickHouse/pull/103824) ([Konstantin Bogdanov](https://github.com/thevar1able))。
* 回移于 [#108847](https://github.com/ClickHouse/ClickHouse/issues/108847)：增量备份不再将 `S3` credentials 存储在 `.backup` metadata 文件的 `<base_backup>` 定位符中。使用 `use_same_s3_credentials_for_base_backup = 1` 创建的备份，或其显式 base backup credentials 与该 backup 定位符一致的备份，会存储一个非 secret 标记，并且在恢复时无需额外的 restore 设置；对于使用不同的显式 base backup credentials 或额外 base 身份验证 arguments 创建的备份，请通过 `base_backup` setting 将其传递给 `RESTORE`。旧版本创建且嵌入了 credentials 的备份仍可恢复。[#107357](https://github.com/ClickHouse/ClickHouse/pull/107357) ([Pablo Marcos](https://github.com/pamarcos))。
* 回移于 [#107889](https://github.com/ClickHouse/ClickHouse/issues/107889)：修复了 MySQL interface 在 `MySQL Connector/J` 8.2.0 及更高版本 (包括 9.x) 中无法使用的问题。`OK` packet 的 `info` field 现在采用长度编码，与 MySQL 服务器保持一致，因此 JDBC 驱动可以正常连接。[#107693](https://github.com/ClickHouse/ClickHouse/pull/107693) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 回移于 [#108763](https://github.com/ClickHouse/ClickHouse/issues/108763)：修复了 `ssl_certificate` 用户识别逻辑，使单个 `*` 通配符恰好只匹配一个名称 component (RFC 6125 6.4.3) 。此前，`CN` 或 `DNS:` SAN subject 中的通配符 (例如 `*.corp.example.com`) 也会匹配 `evil.deep.corp.example.com` 这类多标签名称，从而使持有更深层 subdomain 证书的用户能够以该通配符用户身份进行身份验证。`URI:` SAN 的匹配逻辑保持不变。[#108472](https://github.com/ClickHouse/ClickHouse/pull/108472) ([Groene AI](https://github.com/groeneai))。
* 回移于 [#108896](https://github.com/ClickHouse/ClickHouse/issues/108896)：修复了当 `max_parser_depth` 设置为较大值时，由深度嵌套的 expressions (如 `[[[ ... ]]]` 或 `array(array( ... ))`) 导致的 server crash (stack overflow) 问题。[#108493](https://github.com/ClickHouse/ClickHouse/pull/108493) ([Raúl Marín](https://github.com/Algunenano))。
* 回移于 [#109141](https://github.com/ClickHouse/ClickHouse/issues/109141)：修复了在使用 `GROUPING SETS`、`ROLLUP` 或 `CUBE` 且 `max_threads > 1` 时，合并 `uniqExact` aggregate states 会触发 segmentation fault 的问题。[#108928](https://github.com/ClickHouse/ClickHouse/pull/108928) ([Raúl Marín](https://github.com/Algunenano))。
