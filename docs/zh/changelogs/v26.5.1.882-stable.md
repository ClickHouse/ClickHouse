<div id="backward-incompatible-change">
  #### 不兼容变更
</div>

* 将 `date_time_input_format` 和 `cast_string_to_date_time_mode` 的默认值从 `basic` 改为 `best_effort`。此前无法解析非 basic 日期时间字符串 (例如 `2024 April 4`、`Apr 15, 2020 10:30:00`) 的查询，现在默认可能会成功。若要保留原先的严格解析行为，请将这些设置设为 `basic` (或使用 `compatibility`) 。[#89334](https://github.com/ClickHouse/ClickHouse/pull/89334) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 此变更已回退。[#90043](https://github.com/ClickHouse/ClickHouse/pull/90043) ([Raúl Marín](https://github.com/Algunenano)).
* 现在禁止将 Tuple 元素命名为 `null`，因为它会与 Nullable 的 null map 所使用的子列名称冲突，从而导致子列解析歧义。[#98377](https://github.com/ClickHouse/ClickHouse/pull/98377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增设置 `dynamic_disk_allow_from_env`、`dynamic_disk_allow_from_zk`、`dynamic_disk_allow_include`，用于禁止在动态磁盘中使用 `from_env`、`from_zk`、`include`。这是一次不向后兼容的变更，因为它默认禁止了过去默认允许的行为。[#99138](https://github.com/ClickHouse/ClickHouse/pull/99138) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 你已无法再使用已废弃的基于 Arrow 的 Parquet reader 和 writer，系统将改用原生实现。[#100949](https://github.com/ClickHouse/ClickHouse/pull/100949) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 现在，当同名为 `t` 的永久表和临时表同时存在且未指定数据库时，`SHOW CREATE TABLE t` 会优先选择临时表，这与现有的 `DESCRIBE TABLE` 行为一致。此外，现已支持 `DESCRIBE TEMPORARY TABLE` 语法。[#100966](https://github.com/ClickHouse/ClickHouse/pull/100966) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 将默认 `http_max_fields` 从 1,000,000 降至 1,000，并将 `http_max_field_name_size` 从 128 KB 降至 4 KB，以限制 HTTP 连接在身份验证前的内存使用。新增了 `http_max_request_header_size` 和 `http_headers_read_timeout` 设置。依赖此前较高限制的用户可通过设置恢复原值。[#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).
* 向 `system.metric_log` 新增了一个 `histograms` 嵌套列，用于在每一行中记录所有已注册直方图指标的快照，并新增 `system_metric_log_show_zero_values_in_histograms` 设置来控制是否输出零值。这也弃用了 `system.histogram_metric_log` 表。[#103770](https://github.com/ClickHouse/ClickHouse/pull/103770) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 窗口函数 `RANK` 和 `DENSE_RANK` 现在会拒绝带参数的调用，并抛出 `NUMBER_OF_ARGUMENTS_DOESNT_MATCH`，以符合 SQL 标准。此前，像 `RANK(x) OVER (ORDER BY id)` 这样的查询会在忽略参数的情况下被静默接受，这常常让用户感到困惑。若要恢复先前更宽松的行为，请设置 `allow_rank_dense_rank_arguments = 1`。关闭 [#49526](https://github.com/ClickHouse/ClickHouse/issues/49526)。[#104324](https://github.com/ClickHouse/ClickHouse/pull/104324) ([Groene AI](https://github.com/groeneai)).
* 在未显式指定时区的情况下，将 `CAST` 转换为 `DateTime` 或 `DateTime64` 时，现在会保留源参数的时区 (前提是源参数是带显式时区的 `DateTime`/`DateTime64`) ，这与 `toDateTime`/`toDateTime64` 函数的行为一致。关闭 [#55072](https://github.com/ClickHouse/ClickHouse/issues/55072)。[#104433](https://github.com/ClickHouse/ClickHouse/pull/104433) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 将默认的 x86 构建目标回退到 x86-64-v2 (SSE4.2) 。此前切换到 x86-64-v3 (AVX2) 的更改已被撤销。[#104971](https://github.com/ClickHouse/ClickHouse/pull/104971) ([Raúl Marín](https://github.com/Algunenano)) 。
* 已移除 `kql` 表函数。请使用 `SET dialect = 'kusto'` 以 KQL dialect 运行查询。[#105101](https://github.com/ClickHouse/ClickHouse/pull/105101) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。





<div id="new-feature">
  #### 新特性
</div>

* 添加了表函数 `filesystem`。它可以将目录结构表示为一张表，并支持使用 SQL 查询文件的元数据和内容。最初由 @perst20 在 https://github.com/ClickHouse/ClickHouse/pull/42039 中提交。参见 [#42039](https://github.com/ClickHouse/ClickHouse/issues/42039)。参见 [#50208](https://github.com/ClickHouse/ClickHouse/issues/50208)。[#53610](https://github.com/ClickHouse/ClickHouse/pull/53610) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 引入了参数 kafka&#95;autodetect&#95;client&#95;rack。设置后，可通过云平台设施自动发现可用区，并将其作为 librdkafka 的 client.rack 参数进行传递，以避免跨可用区通信。[#81323](https://github.com/ClickHouse/ClickHouse/pull/81323) ([Ilya Golshtein](https://github.com/ilejn)).
* 向 `system.blob_storage_log` 添加了 `Read` 事件类型，用于跟踪对象存储读取操作，由新设置 `enable_blob_storage_log_for_read_operations` 控制。[#96867](https://github.com/ClickHouse/ClickHouse/pull/96867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为 `bech32Encode` 添加了可选的编码变体参数 (`'bech32'` / `'bech32m'`) ，并为 `bech32Decode` 添加了原始解码模式，用于非 SegWit 地址编码 (例如 Cosmos SDK、Injective、Osmosis) 。[#98986](https://github.com/ClickHouse/ClickHouse/pull/98986) ([Yash ](https://github.com/Onyx2406)).
* 用户现在可以通过新的 `system.zookeeper_watches` 表查看 clickhouse-server 发出的 ZooKeeper watches。[#99277](https://github.com/ClickHouse/ClickHouse/pull/99277) ([Den Kalantaevskii](https://github.com/Diskein)).
* 添加了 `Shards` profile event，用于统计分布式查询中涉及的 shards 数量，并对所有表的结果求和。[#99470](https://github.com/ClickHouse/ClickHouse/pull/99470) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为 Nullable 布尔表达式添加了对 SQL 真值 predicates `IS TRUE`、`IS FALSE`、`IS UNKNOWN`、`IS NOT TRUE`、`IS NOT FALSE` 和 `IS NOT UNKNOWN` 的支持。[#99997](https://github.com/ClickHouse/ClickHouse/pull/99997) ([ibrahim karimeddin](https://github.com/ibrahimkarimeddin)).
* WASM UDF 现在可以声明为 DETERMINISTIC，并可参与常量折叠。[#100005](https://github.com/ClickHouse/ClickHouse/pull/100005) ([Vasily Chekalkin](https://github.com/bacek)).
* 添加了 `parallel_replicas_prefer_local_replica` 设置：禁用后，并行副本将完全按负载均衡算法选择，因此即使是 `max_parallel_replicas = 1` 的查询也可以被路由到另一台主机。[#100139](https://github.com/ClickHouse/ClickHouse/pull/100139) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 添加了 `{disk,storage,http}_connections_rcvbuf` 和 `{disk,storage,http}_connections_sndbuf` 服务器设置，用于控制出站 HTTP 连接的 TCP socket 缓冲区大小，使运维人员能够覆盖内核 autotuning，并限制每个连接的内存使用量。[#100478](https://github.com/ClickHouse/ClickHouse/pull/100478) ([Sema Checherinda](https://github.com/CheSema)).
* 支持 `CREATE OR REPLACE MATERIALIZED VIEW`，具有与 `CREATE OR REPLACE TABLE` 相同的原子交换语义。适用于内部表、`TO` 表、`POPULATE`、`REFRESH` 和 `ON CLUSTER`。[#100539](https://github.com/ClickHouse/ClickHouse/pull/100539) ([DQ](https://github.com/il9ue)).
* 允许将裸函数名传递给高阶函数，例如 `arrayMap`、`arrayFilter` 等。例如，`arrayMap(negate, [1, 2, 3])` 现在等价于 `arrayMap(x -> negate(x), [1, 2, 3])`。[#101033](https://github.com/ClickHouse/ClickHouse/pull/101033) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 添加设置 `send_table_structure_on_insert_with_inline_data` 和 `--inline-insert-data` 客户端选项，使服务器能够通过原生协议自行解析内联 INSERT 数据，从而避免为获取表结构而进行往返通信，并提升大量小批量 insert 的性能。[#101034](https://github.com/ClickHouse/ClickHouse/pull/101034) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 添加 `tokenizeQuery` 和 `highlightQuery` 函数，用于 SQL 查询的标记化和语法高亮。`tokenizeQuery` 返回包含字节偏移和标记类型的词法分析标记；`highlightQuery` 返回基于解析器的语法高亮范围及高亮类别 (关键字、标识符、函数、数字、字符串等) 。[#101054](https://github.com/ClickHouse/ClickHouse/pull/101054) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 添加 `url_base` 设置，用于在 `url` 表函数和 `URL` 表引擎中解析相对 URL，并遵循 RFC 3986 语义。[#101113](https://github.com/ClickHouse/ClickHouse/pull/101113) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 添加 `s3_read_request_duration_microseconds` 和 `s3_read_request_bytes` 直方图指标，用于观测 S3 GET 请求的连接生命周期和消耗的字节数，可在 `system.histogram_metrics` 和 Prometheus endpoint 中查看。[#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)).
* 为 Iceberg 表添加查询条件缓存。[#102115](https://github.com/ClickHouse/ClickHouse/pull/102115) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 添加 `Paimon`、`PaimonS3`、`PaimonAzure`、`PaimonHDFS` 和 `PaimonLocal` 表引擎，支持基于 Keeper 快照进度跟踪的增量读取。增量模式仅返回自上次已提交快照以来的新行。还可通过 `paimon_target_snapshot_id` 读取指定目标快照的增量数据，并通过 `max_consume_snapshots` 为每个查询设置快照数量上限。后台元数据刷新可通过 `paimon_metadata_refresh_interval_sec` 配置。受 `allow_experimental_paimon_storage_engine` 控制。[#102343](https://github.com/ClickHouse/ClickHouse/pull/102343) ([XiaoBinMu](https://github.com/Binnn-MX)).
* 添加 NullCount 统计类型，用于准确统计 Nullable 列中的 NULL 值。这将改进 `PREWHERE` 优化，并提升 part pruning 效果。[#102356](https://github.com/ClickHouse/ClickHouse/pull/102356) ([zoomxi](https://github.com/zoomxi)).
* 现在可以使用 `prettyPrintJSON` 函数将字符串格式化为人类可读的 JSON。这对仪表板或报表很有帮助，因为此前 JSON 美化需要在客户端侧额外执行一步。关闭 [#62523](https://github.com/ClickHouse/ClickHouse/issues/62523)。[#102594](https://github.com/ClickHouse/ClickHouse/pull/102594) ([Dmitry Prokofyev](https://github.com/prokofyevDmitry)).
* `LIMIT BY` 子句现已支持负值，从而可从每个分组的*末尾*而非开头选择行。例如，`LIMIT -2 BY id` 会返回每个 `id` 的最后两行。同时也支持负 OFFSET (`LIMIT -1 OFFSET -1 BY id`) 和符号混用 (`LIMIT -2 OFFSET 1 BY id`) 。[#103222](https://github.com/ClickHouse/ClickHouse/pull/103222) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 添加新的 Kafka 表设置 `kafka_map_virtual_columns_on_write`。启用后，Kafka 表 schema 中名为 `_key`、`_timestamp`、`_headers.name` 和 `_headers.value` 的列会在 `INSERT` 时生成为对应的 Kafka 消息 key、timestamp 和 请求头，并且会从消息负载中排除。[#103243](https://github.com/ClickHouse/ClickHouse/pull/103243) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为可刷新materialized view 新增了 `SYSTEM PAUSE VIEW [db.]name` 和 `SYSTEM PAUSE VIEWS` 查询。与 `SYSTEM STOP VIEW` 不同，`SYSTEM PAUSE VIEW` 不会中断当前正在进行的刷新——正在执行的刷新会继续完成，仅阻止后续刷新。可通过 `SYSTEM START VIEW` 或 `SYSTEM START VIEWS` 撤销；这两个命令现在都会统一清除 stopped 和 paused 状态。[#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 新增设置 &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;join&#96;，与 &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;group&#95;by&#96; 和 &#96;max&#95;bytes&#95;ratio&#95;before&#95;external&#95;sort&#96; 类似。它将 hash joins 的落盘阈值表示为可用内存的比例；与绝对值设置 &#96;max&#95;bytes&#95;before&#95;external&#95;join&#96; 结合使用时，以计算结果中较小的阈值为准。[#103862](https://github.com/ClickHouse/ClickHouse/pull/103862) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增函数 `regexpPosition` (以及与 PostgreSQL 兼容的别名 `regexpInstr` 和 `regexp_instr`) ，用于返回字符串中第 N 次 Regex 匹配的字节位置。支持起始偏移、匹配后返回模式、Regex 标志以及捕获组选择。[#104172](https://github.com/ClickHouse/ClickHouse/pull/104172) ([Abhinav Agarwal](https://github.com/aagarwal-gtr)).
* NullCount 列统计信息现可用于数据分区片段裁剪。对于带有 NullCount 统计信息的 Nullable 列，包含 IS NULL 或 IS NOT NULL 谓词的查询现在可以跳过整个数据分区片段，只要统计信息能够证明其中不存在匹配行。[#104214](https://github.com/ClickHouse/ClickHouse/pull/104214) ([zoomxi](https://github.com/zoomxi)).
* 新增用于质数判定的函数 `isPrime` 和 `isProbablePrime`。`isPrime` 对最大到 `UInt64` 的无符号整数返回精确结果。`isProbablePrime` 还支持 `UInt128` 和 `UInt256`；对于这些更大位宽的类型，`0` 表示确定为合数，`1` 表示可能为质数。`isProbablePrime` 的可选第二个参数 `rounds` 用于控制置信度，默认 `25` 轮可将随机合数的误报率限制在 `10^-15` 以下。[#104234](https://github.com/ClickHouse/ClickHouse/pull/104234) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 在 ClickHouse 命令行客户端工具中，Clear 和 /clear 现在会清空终端，而不是被当作误写的查询执行。[#104318](https://github.com/ClickHouse/ClickHouse/pull/104318) ([Tyler Hannan](https://github.com/tylerhannan)).
* 允许 `file` 表函数在 `SELECT` 查询中接受由路径组成的 `Array(String)`。[#104442](https://github.com/ClickHouse/ClickHouse/pull/104442) ([Yue](https://github.com/niyue)).
* 为 `system.functions` 表新增 `deterministic` 和 `higher_order` 列。[#104479](https://github.com/ClickHouse/ClickHouse/pull/104479) ([Pedro Ferreira](https://github.com/PedroTadim)).



<div id="experimental-feature">
  #### Experimental 功能
</div>

* 新增了一个位于 `/webterminal` 的实验性 Web 终端界面，可通过 WebSocket 在浏览器中提供交互式 `clickhouse-client` 会话。默认禁用；可通过 `allow_experimental_webterminal` 服务器设置启用。[#100277](https://github.com/ClickHouse/ClickHouse/pull/100277) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WASM UDF 现在可以对更多数值类型进行类型强制转换。较小的整数类型可以强制转换为较大的整数类型，例如 Int8 到 UInt64。任何整数类型都可以强制转换为浮点类型，例如 Int32 到 F32。[#100435](https://github.com/ClickHouse/ClickHouse/pull/100435) ([Vasily Chekalkin](https://github.com/bacek)).
* 支持 Iceberg 的 Geo 类型。[#103113](https://github.com/ClickHouse/ClickHouse/pull/103113) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 实验性 Web 终端 (`allow_experimental_webterminal`) 现在可以从 `clickhouse.com`、`clickhouse.cloud` 及其子域名跨源嵌入。此前，来自任何非同源父窗口的 `postMessage` 都会在入站时被拒绝，并在出站时被静默丢弃，导致该终端实际上无法在 `play.clickhouse.com` 之外嵌入。可接受的来源列表是一个显式允许列表 (仅限 https，且基于 hostname 精确限定) ，因此不受信任的来源仍会被拒绝。[#105191](https://github.com/ClickHouse/ClickHouse/pull/105191) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="performance-improvement">
  #### 性能提升
</div>

* 优化 `cramersV`、`cramersVBiasCorrected`、`theilsU` 和 `contingency` 与窗口函数一起使用时的性能。关闭 [#83521](https://github.com/ClickHouse/ClickHouse/issues/83521)。[#93384](https://github.com/ClickHouse/ClickHouse/pull/93384) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 默认启用 `use_top_k_dynamic_filtering` 和 `use_skip_indexes_for_top_k` 设置，以提升 `ORDER BY ... LIMIT N` 查询的性能。[#99537](https://github.com/ClickHouse/ClickHouse/pull/99537) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 限制 UNION ALL 中同时活跃的流，以降低峰值内存占用。[#100176](https://github.com/ClickHouse/ClickHouse/pull/100176) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增一项查询优化，将 `tupleElement(dictGet('dict', ('a', 'b', 'c'), key), N)` 重写为 `dictGet('dict', 'a', key)`，以避免拉取不必要的字典属性。由 `optimize_dictget_tuple_element` 设置控制 (默认启用) 。[#100186](https://github.com/ClickHouse/ClickHouse/pull/100186) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对用户态页缓存做了小幅优化。[#100300](https://github.com/ClickHouse/ClickHouse/pull/100300) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 加快涉及类型转换和函数应用的索引分析。关闭 [#55653](https://github.com/ClickHouse/ClickHouse/issues/55653)。[#100366](https://github.com/ClickHouse/ClickHouse/pull/100366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 加快对基于大量底层表的 `Merge` 表执行超大查询的速度。关闭 [#32465](https://github.com/ClickHouse/ClickHouse/issues/32465)。[#100369](https://github.com/ClickHouse/ClickHouse/pull/100369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增 `max_threads_min_free_memory_per_thread` 和 `max_insert_threads_min_free_memory_per_thread` 设置，以便在服务器可用内存不足时自动降低查询并行度。[#100383](https://github.com/ClickHouse/ClickHouse/pull/100383) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 改进低内存系统 (&lt; 4 GiB) 上的内存占用表现。[#100389](https://github.com/ClickHouse/ClickHouse/pull/100389) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为带排序的分布式查询在发起端的排序步骤启用缓冲。[#100661](https://github.com/ClickHouse/ClickHouse/pull/100661) ([Nikita Taranov](https://github.com/nickitat)).
* 提升 partial&#95;merge&#95;join 的性能。[#100945](https://github.com/ClickHouse/ClickHouse/pull/100945) ([Artem Zuikov](https://github.com/4ertus2)).
* 小幅减少了 `partial_merge` JOIN 中的内存过度分配。[#100963](https://github.com/ClickHouse/ClickHouse/pull/100963) ([Artem Zuikov](https://github.com/4ertus2)).
* 通过缓存 sampling 设置而非遍历整个 memory tracker 层级，优化内存分配/释放。[#101267](https://github.com/ClickHouse/ClickHouse/pull/101267) ([Azat Khuzhin](https://github.com/azat)).
