<div id="backward-incompatible-change">
  #### 向后不兼容变更
</div>

* ALTER MODIFY COLUMN 现在在将 Nullable 列转换为非 Nullable 类型时，要求显式指定 DEFAULT。此前，这类 ALTER 可能会因 cannot convert null to not null 错误而卡住；现在，NULL 会被替换为该列的默认表达式。解决了 [#5985](https://github.com/ClickHouse/ClickHouse/issues/5985)。[#84770](https://github.com/ClickHouse/ClickHouse/pull/84770) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Ngram 分词器将不再返回长度小于所设 N 值的 ngram。当搜索标记为空时，Text Search 将不返回任何行。[#89757](https://github.com/ClickHouse/ClickHouse/pull/89757) ([George Larionov](https://github.com/george-larionov)).
* 当将列从 `String` ALTER 为 `Nullable(String)` 时，我们不会对数据执行变更。但对于 `uniq` aggregate function，它使用不同的数据结构：对于 Nullable 列，它会使用 `AggregateFunctionNull`，并嵌套一个 uniq 聚合器。`AggregateFunctionNull` 会额外序列化一个 bool 标志，这会导致统计信息文件不兼容。修复方法是在序列化时增加一个标志，用于记录该列是否为 Nullable。统计信息格式已经发生变化；如果存在旧格式的统计信息，服务器将会 crash。此 PR [https://github.com/ClickHouse/ClickHouse/pull/90904](https://github.com/ClickHouse/ClickHouse/pull/90904) 将修复该 crash，并在现有统计信息使用 legacy 格式时抛出异常。为避免异常，应运行 ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL 重新生成统计信息以修复此问题。[#90311](https://github.com/ClickHouse/ClickHouse/pull/90311) ([Han Fei](https://github.com/hanfei1991)).
* 移除 settings `allow_not_comparable_types_in_order_by`/`allow_not_comparable_types_in_comparison_functions`。允许在 ORDER BY 或 comparison functions 中使用不可比较类型，可能会导致 logical error 和异常结果。解决了 [#90028](https://github.com/ClickHouse/ClickHouse/issues/90028)。[#90527](https://github.com/ClickHouse/ClickHouse/pull/90527) ([Pavel Kruglov](https://github.com/Avogar)).
* 将 setting `check_query_single_value_result` 的默认值从 `true` 改为 `false`。这会使 `CHECK TABLE` 返回每个 part 的详细结果，而不是聚合结果 (1 = 正常，0 = 发现错误) 。相比之前的行为，这样可能更符合用户预期。[#91009](https://github.com/ClickHouse/ClickHouse/pull/91009) ([Robert Schulze](https://github.com/rschu1ze)).
* 对隐式索引进行了多项修复。显示或存储的 schema (keeper metadata) 将不再包含隐式索引，例如通过 settings `add_minmax_index_for_numeric_columns` 或 `add_minmax_index_for_string_columns` 创建的那些。当在较新版本中创建或更新 ReplicatedMergeTree 表，而某个副本仍运行旧版本时，这可能会导致 metadata 错误。对于这类情况，请在整个 cluster 完成 upgrade 之前，继续向旧副本发送 DDL。[#91429](https://github.com/ClickHouse/ClickHouse/pull/91429) ([Raúl Marín](https://github.com/Algunenano)).
* 更新 ClickHouse 客户端，使其在查询因 `receive_timeout` 而超时时返回非零退出码 (159 - TIMEOUT&#95;EXCEEDED) 。此前，超时会返回退出码 0 (成功) ，这使脚本和自动化难以检测超时故障。[#91432](https://github.com/ClickHouse/ClickHouse/pull/91432) ([Sav](https://github.com/sberss)).
* 改进了 inverted text index 的存储布局，使其在从 object storage 读取时更高效。提升了带有 inverted text index 的表在 merge 时的性能。如果你在 25.12 版本之前使用过 Experimental text index，则需要在 upgrade 之前先删除该索引，并在新版本上重新构建。[#91518](https://github.com/ClickHouse/ClickHouse/pull/91518) ([Anton Popov](https://github.com/CurtizJ)).
* 现在禁止创建 `ORDER BY` 键为空的特殊 `MergeTree` 表 (例如 `ReplacingMergeTree`、`CollapsingMergeTree` 等) ，因为这些表中的合并行为未定义。如果仍需创建此类表，请启用 `allow_suspicious_primary_key` 设置。[#91569](https://github.com/ClickHouse/ClickHouse/pull/91569) ([Anton Popov](https://github.com/CurtizJ)).
* 修复函数 bitShiftLeft 和 bitShiftRight，使其在移位位数恰好等于该类型大小时返回 0 或空值。[#91943](https://github.com/ClickHouse/ClickHouse/pull/91943) ([Pablo Marcos](https://github.com/pamarcos)).
* 对 [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380) 的后续补充。此 PR 将在投影中禁用位置参数标记为一项向后不兼容的变更。此外，它还引入了 `enable_positional_arguments_for_projections` 设置，以便在投影中存在位置参数时安全升级 ClickHouse 集群。[#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="new-feature">
  #### 新特性
</div>

* 用户现在可以将 S3/Azure Queue 表配置为移动或标记已处理的文件，除了此前的保留或删除文件选项之外。解决了 [#72944](https://github.com/ClickHouse/ClickHouse/issues/72944)。[#86907](https://github.com/ClickHouse/ClickHouse/pull/86907) ([Murat Khairulin](https://github.com/mxwell)).
* 为 `windowFunnel` 聚合函数添加 `allow_reentry` 选项。在启用 strict&#95;order 时，它会忽略违反顺序的事件，而不是停止 funnel 分析。这样即可处理包含刷新 (A-&gt;A-&gt;B) 或回退导航 (A-&gt;B-&gt;A-&gt;C) 的用户路径，而不会低报转化率。[#86916](https://github.com/ClickHouse/ClickHouse/pull/86916) ([Lee ChaeRok](https://github.com/LeeChaeRok)).
* ClickHouse 命令行客户端现在可以通过指定 `--no-server-client-version-message` 或 `false` 来隐藏 &#39;ClickHouse server version is older than ClickHouse client. It may indicate that the server is out of date and can be upgraded.&#39; 提示消息。[#87784](https://github.com/ClickHouse/ClickHouse/pull/87784) ([Larry Snizek](https://github.com/larry-cdn77)).
* Keeper 与 ZooKeeper 的兼容性：支持 create with statistics。[#88797](https://github.com/ClickHouse/ClickHouse/pull/88797) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* ClickHouse Keeper 支持 ZooKeeper 持久 watches。续篇第 2 部分：[https://github.com/ClickHouse/ClickHouse/pull/78207](https://github.com/ClickHouse/ClickHouse/pull/78207)。[#88813](https://github.com/ClickHouse/ClickHouse/pull/88813) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 新增用于计算 geometry type 面积和周长的函数。[#89047](https://github.com/ClickHouse/ClickHouse/pull/89047) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 支持在 runtime 使用 XRay 添加 instrumentation，以便在 production 中 debug 问题并进行确定性 profile。解决了 [#74249](https://github.com/ClickHouse/ClickHouse/issues/74249)。[#89173](https://github.com/ClickHouse/ClickHouse/pull/89173) ([Pablo Marcos](https://github.com/pamarcos)).
* 实现 `dictGetKeys` 函数，返回 attribute 等于指定值的 dictionary key。它使用按查询生效的反向 lookup cache，并可通过 `max_reverse_dictionary_lookup_cache_size_bytes` setting 进行调优，以加快重复 lookups。[#89197](https://github.com/ClickHouse/ClickHouse/pull/89197) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 可使用 Cloud credentials 通过 `--login` 访问 ClickHouse Cloud instances。[#89261](https://github.com/ClickHouse/ClickHouse/pull/89261) ([Krishna Mannem](https://github.com/kcmannem)).
* 添加 setting `type_json_skip_invalid_typed_paths`，用于在输入 JSON 无法转换为 JSON type 中显式类型化 paths 时，禁用 inserts/type casts 到 JSON type 产生的异常。此时会回退为该类型化 path 的 null/zero 值。[#89886](https://github.com/ClickHouse/ClickHouse/pull/89886) ([Max Justus Spransy](https://github.com/maxjustus)).
* 为 MergeTree tables 支持 `direct` (nested loop) join。要使用它，请在 setting 中将其指定为唯一选项：`join_algorithm = 'direct'`。[#89920](https://github.com/ClickHouse/ClickHouse/pull/89920) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 在 iceberg 的 `CREATE` 操作中支持 `ORDER BY`，并在 `INSERT` 中支持排序。解决了 [#89916](https://github.com/ClickHouse/ClickHouse/issues/89916)。[#90141](https://github.com/ClickHouse/ClickHouse/pull/90141) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 此 PR 引入了 projection 级别的设置，可通过 `ALTER TABLE ... ADD PROJECTION` 中新的 WITH SETTINGS 子句进行配置。这些设置允许针对每个 projection 覆盖某些 MergeTree 存储参数 (例如 `index&#95;granularity`、`index&#95;granularity&#95;bytes`) 。[#90158](https://github.com/ClickHouse/ClickHouse/pull/90158) ([Amos Bird](https://github.com/amosbird)).
* 新增数据脱敏策略解析器。[#90552](https://github.com/ClickHouse/ClickHouse/pull/90552) ([pufit](https://github.com/pufit)).
* 新增 `HMAC(algorithm, message, key)` SQL 函数，作为 [#73900](https://github.com/ClickHouse/ClickHouse/issues/73900) 和 [#38775](https://github.com/ClickHouse/ClickHouse/issues/38775) 的一部分。[#90837](https://github.com/ClickHouse/ClickHouse/pull/90837) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* 为 `has()` 函数新增支持：当第一个参数为常量数组时，可使用主键和数据跳过索引。关闭 [#90980](https://github.com/ClickHouse/ClickHouse/issues/90980)。[#91023](https://github.com/ClickHouse/ClickHouse/pull/91023) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 实现了新的输入输出格式 `Buffers`。该格式与 `Native` 类似；但不同于 `Native`，它不存储列名、列类型或任何额外元数据。关闭 [#84017](https://github.com/ClickHouse/ClickHouse/issues/84017)。[#91156](https://github.com/ClickHouse/ClickHouse/pull/91156) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 新增设置 `max_streams_for_files_processing_in_cluster_functions`，用于控制 cluster 表函数中并行读取文件时的流数量。关闭 [#90223](https://github.com/ClickHouse/ClickHouse/issues/90223)。[#91323](https://github.com/ClickHouse/ClickHouse/pull/91323) ([Pavel Kruglov](https://github.com/Avogar)).

<div id="experimental-feature">
  #### Experimental 功能
</div>

* 引入了一项新逻辑，可根据设置 `automatic_parallel_replicas_mode` 自动使用并行副本执行查询。在正常的单节点执行过程中，ClickHouse 会收集统计信息，供后续规划阶段参考。如果统计信息表明使用并行副本可能有益，ClickHouse 就会自动以并行副本方式执行该查询。目前支持的查询类型仍然相当有限。[#87541](https://github.com/ClickHouse/ClickHouse/pull/87541) ([Nikita Taranov](https://github.com/nickitat)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 当查询达到行数限制时立即失败。解决了 [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872)。[#62804](https://github.com/ClickHouse/ClickHouse/pull/62804) ([Sean Haynes](https://github.com/seandhaynes)) 。
* 新增优化，可在查询计划中移除未使用的列。解决了 [#75152](https://github.com/ClickHouse/ClickHouse/issues/75152)。[#76487](https://github.com/ClickHouse/ClickHouse/pull/76487) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)) 。
* Https://github.com/clickhouse/clickhouse/pull/84477 为可在 `insert select from s3cluster()` 查询中用于并行分布式执行的 select 查询增加了约束。此次变更允许使用 where，这在此前是可行的。[#84611](https://github.com/ClickHouse/ClickHouse/pull/84611) ([Igor Nikonov](https://github.com/devcrafter)) 。
* 在哈希表迭代期间预取键，以尽量减少缓存未命中。[#84708](https://github.com/ClickHouse/ClickHouse/pull/84708) ([lgbo](https://github.com/lgbo-ustc)) 。
* 通过仅对 points 数组的尾部排序，并对单调输入跳过排序，优化 AggregateFunctionHistogram，实现约 10% 的性能提升。[#85760](https://github.com/ClickHouse/ClickHouse/pull/85760) ([MakarDev](https://github.com/MakarDev)) 。
* ClickHouse 现在可使用跳过索引对 WHERE 子句中由 `AND` 和 `OR` 混合连接的过滤条件执行索引分析。此前，WHERE 子句必须是过滤条件的合取 (AND) 才能利用跳过索引。新增设置 `use_skip_indexes_for_disjunctions` (默认：开启) 用于控制此功能。 (issue [#75228](https://github.com/ClickHouse/ClickHouse/issues/75228)) 。[#87781](https://github.com/ClickHouse/ClickHouse/pull/87781) ([Shankar Iyer](https://github.com/shankar-iyer)) 。
* 通过利用基于文本索引构建的额外预过滤器，提升了 `like`、`equals`、`has` 等函数谓词的筛选性能。可通过 `query_plan_text_index_add_hint` 设置启用此优化。同时改进了文本索引在 `Map` 数据类型列上的使用。[#88550](https://github.com/ClickHouse/ClickHouse/pull/88550) ([Anton Popov](https://github.com/CurtizJ)) 。
* 通过对预先计算出的可能键值集合进行更快的查找，优化了重复的反向字典查找。关闭了 [#7968](https://github.com/ClickHouse/ClickHouse/issues/7968)。[#88971](https://github.com/ClickHouse/ClickHouse/pull/88971) ([Nihal Z. Miaji](https://github.com/nihalzp)) 。
* 为 Nullable 类型的列新增稀疏序列化支持。这是对 [#44539](https://github.com/ClickHouse/ClickHouse/issues/44539) 的延续。[#88999](https://github.com/ClickHouse/ClickHouse/pull/88999) ([Amos Bird](https://github.com/amosbird)) 。
* 为 `ANTI` JOIN 支持 JOIN 运行时过滤器。同时重构了运行时过滤器实现，以减少锁竞争。[#89710](https://github.com/ClickHouse/ClickHouse/pull/89710) ([Dmitry Novik](https://github.com/novikd)) 。
* 支持在 LEFT/INNER JOIN 操作中保持从左表按顺序读取，供后续步骤利用。可使用设置 `query_plan_read_in_order_through_join` 禁用。还支持 LEFT/INNER JOIN 的 virtual row 读取优化 (参见设置 `read_in_order_use_virtual_row`) 。[#89815](https://github.com/ClickHouse/ClickHouse/pull/89815) ([Vladimir Cherkasov](https://github.com/vdimir)) 。
* 通过使用跳过索引和动态阈值过滤器优化 `ORDER BY...LIMIT N` 查询，显著减少处理的行数。[#89835](https://github.com/ClickHouse/ClickHouse/pull/89835) ([Shankar Iyer](https://github.com/shankar-iyer)) 。
* 改进了 topK 的性能和行为。[#90091](https://github.com/ClickHouse/ClickHouse/pull/90091) ([Raúl Marín](https://github.com/Algunenano)) 。
* 改进了 Decimal 比较操作的性能。修复了 [#28192](https://github.com/ClickHouse/ClickHouse/issues/28192)。[#90153](https://github.com/ClickHouse/ClickHouse/pull/90153) ([Konstantin Bogdanov](https://github.com/thevar1able)) 。
* 为 Paimon 函数支持分区裁剪，延续了 [https://github.com/ClickHouse/ClickHouse/pull/84423](https://github.com/ClickHouse/ClickHouse/pull/84423) 中的工作。[#90253](https://github.com/ClickHouse/ClickHouse/pull/90253) ([JIaQi](https://github.com/JiaQiTang98)) 。
* 通过提高限制值，改进了惰性 materialized 列的性能。[#90309](https://github.com/ClickHouse/ClickHouse/pull/90309) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 当存在大型 `minmax` 索引 (数百万个粒度) 时，用户应能感受到索引分析延迟降低。[#90428](https://github.com/ClickHouse/ClickHouse/pull/90428) ([Shankar Iyer](https://github.com/shankar-iyer)) 。
* 通过动态分发为逻辑函数使用高级 SIMD 操作。[#90432](https://github.com/ClickHouse/ClickHouse/pull/90432) ([Raúl Marín](https://github.com/Algunenano)) 。
* 通过避免不必要地将结果列初始化为零，提升了 JIT 函数的执行性能。[#90449](https://github.com/ClickHouse/ClickHouse/pull/90449) ([Raúl Marín](https://github.com/Algunenano)) 。
* 通过动态分发加速 T64 解压缩。[#90610](https://github.com/ClickHouse/ClickHouse/pull/90610) ([Raúl Marín](https://github.com/Algunenano)) 。
* 优化了 MergeTree reader 的原地筛选。修复了 [#87119](https://github.com/ClickHouse/ClickHouse/issues/87119)。[#90630](https://github.com/ClickHouse/ClickHouse/pull/90630) ([Xiaozhe Yu](https://github.com/wudidapaopao)) 。
* 当查询达到行数限制时快速失败。修复了 [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872)。[#90767](https://github.com/ClickHouse/ClickHouse/pull/90767) ([Sean Haynes](https://github.com/seandhaynes)) 。
* 为 INNER JOIN 实现了简单的 DPsize JOIN 重排序算法。新增 Experimental setting 用于控制按何种顺序使用哪些算法，例如 `query_plan_optimize_join_order_algorithm='dpsize,greedy'` 表示先尝试 DPsize，失败时再回退到 greedy。[#91002](https://github.com/ClickHouse/ClickHouse/pull/91002) ([Alexander Gololobov](https://github.com/davenger)) 。
* 引入了额外的启发式方法，以减少所选 merge 方案的宽度。执行更多较窄的 merge 会增加写放大，但同时也有助于避免触发 `TOO_MANY_PARTS` 错误。[#91163](https://github.com/ClickHouse/ClickHouse/pull/91163) ([Mikhail Artemenko](https://github.com/Michicosun)) 。
* 通过下推 `_path` 过滤器值，提升了使用 glob pattern 创建的 S3 表的查询性能，从而避免 S3 列表操作。该行为由 `s3_path_filter_limit` setting 控制。[#91165](https://github.com/ClickHouse/ClickHouse/pull/91165) ([Eduard Karacharov](https://github.com/korowa)) 。
* 通过动态分发加速将列转换为 Bool (在 WHERE 子句中) 的过程。[#91203](https://github.com/ClickHouse/ClickHouse/pull/91203) ([Raúl Marín](https://github.com/Algunenano)) 。
* 通过动态分发加速对单个数值块的排序。[#91213](https://github.com/ClickHouse/ClickHouse/pull/91213) ([Raúl Marín](https://github.com/Algunenano)) 。

* 允许向 `ALIAS` 列 (即仅引用物理列、不包含任何表达式的列) 执行 `INSERT`。关闭 [#80060](https://github.com/ClickHouse/ClickHouse/issues/80060)。[#84154](https://github.com/ClickHouse/ClickHouse/pull/84154) ([Shaurya Mohan](https://github.com/ShauryaMohan)).
* 修复了 prewhere 中的一些 bug，涉及 Time 和 Time64 Data type 的 supertype。解决 [#84544](https://github.com/ClickHouse/ClickHouse/issues/84544)。[#84715](https://github.com/ClickHouse/ClickHouse/pull/84715) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
