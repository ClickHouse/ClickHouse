  ### ClickHouse 发布版本 v26.4.3.37-稳定版本 (a5dd9c96830) FIXME，与 v26.4.2.10-稳定版本 (184f682d431) 相比

<div id="new-feature">
  #### 新特性
</div>

* 已在 [#104390](https://github.com/ClickHouse/ClickHouse/issues/104390) 中回移：为可刷新materialized view 新增了 `SYSTEM PAUSE VIEW [db.]name` 和 `SYSTEM PAUSE VIEWS` 查询。与 `SYSTEM STOP VIEW` 不同，`SYSTEM PAUSE VIEW` 不会中断当前正在进行的 refresh——进行中的 refresh 会被允许完成，只会阻止后续的 refresh。可通过 `SYSTEM START VIEW` 或 `SYSTEM START VIEWS` 恢复；它们现在都会统一清除 stopped 和 paused 状态。[#103252](https://github.com/ClickHouse/ClickHouse/pull/103252) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。

<div id="performance-improvement">
  #### 性能提升
</div>

* 已在 [#104423](https://github.com/ClickHouse/ClickHouse/issues/104423) 中回移：通过将每个查询的 `AsyncReadCounters` 改为无锁，减少了异步远程 FS 读取路径上的锁竞争。[#104374](https://github.com/ClickHouse/ClickHouse/pull/104374) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。

<div id="improvement">
  #### 改进
</div>

* 已在 [#104036](https://github.com/ClickHouse/ClickHouse/issues/104036) 中回移：当 `FINAL` 之后的 ROW POLICY 仅依赖排序键列且具有确定性时，跳过对该 ROW POLICY 的延后处理；同时在这种情况下，跳过由该 ROW POLICY 强制触发的相应 `PREWHERE` 延后处理。[#102884](https://github.com/ClickHouse/ClickHouse/pull/102884) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 已在 [#104386](https://github.com/ClickHouse/ClickHouse/issues/104386) 中回移：当 可刷新materialized view 持续刷新时，通过基于快照表的状态而非全局状态进行决策，提升 backups 的稳健性。[#103384](https://github.com/ClickHouse/ClickHouse/pull/103384) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 已在 [#104596](https://github.com/ClickHouse/ClickHouse/issues/104596) 中回移：处于 APPEND 模式的 Replicated 可刷新materialized view 在刷新过程中如果与 ZooKeeper 的连接短暂中断，将不再刷新两次。[#104051](https://github.com/ClickHouse/ClickHouse/pull/104051) ([Michael Kolupaev](https://github.com/al13n321)).
* 已在 [#104704](https://github.com/ClickHouse/ClickHouse/issues/104704) 中回移：修复 &#96;lowerUTF8&#96; / &#96;upperUTF8&#96; 在处理大型非 ASCII 数据集 (例如构建文本索引期间) 时的异常：当累计输出 buffer 超过 2 GiB 时会报错；同时会以明确的错误信息拒绝过长的单行。[#104229](https://github.com/ClickHouse/ClickHouse/pull/104229) ([Shaohua Wang](https://github.com/tiandiwonder)).
* 已在 [#105026](https://github.com/ClickHouse/ClickHouse/issues/105026) 中回移：新增 setting `defer_partition_pruning_after_final` (默认值为 `1`) ，使 26.3 引入的在 `FINAL` 下跳过分区剪枝的行为可以选择退出。将其设为 `0` 可恢复 26.3 之前的分区剪枝行为——对于同一 PK 的行不会跨分区的事件日志 workloads，性能会显著提升。`compatibility = '26.2'` 会自动将其切换为 `0`。[#104705](https://github.com/ClickHouse/ClickHouse/pull/104705) ([Nikita Fomichev](https://github.com/fm4v)).

* 已在 [#104743](https://github.com/ClickHouse/ClickHouse/issues/104743) 中回移：修复了将 `JSONExtract` 提取为 `Variant` 类型时会悄悄截断 JSON 小数的问题。此前，`JSONExtract('{"x": 3.14}', 'x', 'Variant(Int64, Float64)')` 返回 `Int64=3`，而 `JSONExtract('{"x": 3.14}', 'x', 'Variant(String, Int64)')` 返回 `Int64=3`，导致小数部分丢失。现在会无损保留小数值：如果存在 `Float64`/`Decimal` 成员，则由其接收；否则由 `String` 成员保留原始 JSON。仅包含整数成员的 `Variant` 类型 (例如 `Variant(Int64, Int32)`) 以及直接提取整数 (`JSONExtract(json, 'Int64')`、`JSONExtractInt` 等) 的行为保持不变。[#103620](https://github.com/ClickHouse/ClickHouse/pull/103620) ([Groene AI](https://github.com/groeneai)).
