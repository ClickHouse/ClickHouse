<div id="improvement">

* 已在 [#82862](https://github.com/ClickHouse/ClickHouse/issues/82862) 中回移：在 [https://github.com/ClickHouse/ClickHouse/pull/73834](https://github.com/ClickHouse/ClickHouse/pull/73834) 之后，`X-ClickHouse-Progress` 和 `X-ClickHouse-Summary` 请求头的格式被修改为省略零值。此 PR 仅打算恢复 `X-ClickHouse-Summary` 之前的行为，因为这样更合理。[#82727](https://github.com/ClickHouse/ClickHouse/pull/82727) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov))。
* 已在 [#84037](https://github.com/ClickHouse/ClickHouse/issues/84037) 中回移：使用 cgroup 提供的信息 (如果适用，即启用了 `memory_worker_use_cgroup` 且 cgroups 可用) 来修正内存跟踪器 (`memory_worker_correct_memory_tracker`) 。[#83981](https://github.com/ClickHouse/ClickHouse/pull/83981) ([Azat Khuzhin](https://github.com/azat))。

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 已回移至 [#83144](https://github.com/ClickHouse/ClickHouse/issues/83144)：不要在 `lowCardinalityKeys` 函数中使用共享字典中无关的部分。[#83118](https://github.com/ClickHouse/ClickHouse/pull/83118) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 已回移至 [#83766](https://github.com/ClickHouse/ClickHouse/issues/83766)：Keeper 修复：在会话关闭删除 ephemeral 节点时，正确更新 watch 总数。[#83583](https://github.com/ClickHouse/ClickHouse/pull/83583) ([Antonio Andelic](https://github.com/antonio2368)) 。
* 已回移至 [#84109](https://github.com/ClickHouse/ClickHouse/issues/84109)：对 Avro Schema Registry 的身份验证详细信息进行脱敏，避免用户看到这些信息，也避免其出现在日志中。[#83713](https://github.com/ClickHouse/ClickHouse/pull/83713) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)) 。
* 已回移至 [#83917](https://github.com/ClickHouse/ClickHouse/issues/83917)：修复以下问题：如果创建 MergeTree 表时设置了 `add_minmax_index_for_numeric_columns=1` 或 `add_minmax_index_for_string_columns=1`，之后该索引在 ALTER 操作期间被 materialized，会导致 Replicated 数据库无法在新副本上正确初始化。[#83751](https://github.com/ClickHouse/ClickHouse/pull/83751) ([Nikolay Degterinsky](https://github.com/evillique)) 。
* 已回移至 [#83874](https://github.com/ClickHouse/ClickHouse/issues/83874)：引入 backward compatibility 设置，以便在名称冲突时允许新的 analyzer 在 WITH 子句中引用外层别名。修复 [#82700](https://github.com/ClickHouse/ClickHouse/issues/82700)。[#83797](https://github.com/ClickHouse/ClickHouse/pull/83797) ([Dmitry Novik](https://github.com/novikd)) 。
* 已回移至 [#84092](https://github.com/ClickHouse/ClickHouse/issues/84092)：从备份恢复时，definer 用户可能未被备份，这会导致整个备份失效。为修复此问题，我们将恢复期间对创建目标表的权限检查延后，仅在运行时检查。[#83818](https://github.com/ClickHouse/ClickHouse/pull/83818) ([pufit](https://github.com/pufit)) 。
* 已回移至 [#84224](https://github.com/ClickHouse/ClickHouse/issues/84224)：启用 analyzer 后，允许在 `remote` 表函数的 `view(...)` 参数中引用任意表。修复 [#78717](https://github.com/ClickHouse/ClickHouse/issues/78717)。修复 [#79377](https://github.com/ClickHouse/ClickHouse/issues/79377)。[#83844](https://github.com/ClickHouse/ClickHouse/pull/83844) ([Dmitry Novik](https://github.com/novikd)) 。
* 已回移至 [#84129](https://github.com/ClickHouse/ClickHouse/issues/84129)：修复一个罕见问题：`MATERIALIZE COLUMN` 查询可能导致 `checksums.txt` 中出现异常文件，并最终产生 detached 状态的数据分区片段。[#84007](https://github.com/ClickHouse/ClickHouse/pull/84007) ([alesapin](https://github.com/alesapin)) 。
* 已回移至 [#84272](https://github.com/ClickHouse/ClickHouse/issues/84272)：修复了查询条件缓存与递归 CTE 一起使用时结果错误的问题 (issue [#81506](https://github.com/ClickHouse/ClickHouse/issues/81506)) 。[#84026](https://github.com/ClickHouse/ClickHouse/pull/84026) ([zhongyuankai](https://github.com/zhongyuankai)) 。
* 已回移至 [#84288](https://github.com/ClickHouse/ClickHouse/issues/84288)：修复罕见的 ClickHouse 崩溃问题：当表包含 projection、`lightweight_mutation_projection_mode = 'rebuild'`，且用户执行 lightweight delete 删除表中任意块内的所有行时，会触发该问题。[#84158](https://github.com/ClickHouse/ClickHouse/pull/84158) ([alesapin](https://github.com/alesapin)) 。
