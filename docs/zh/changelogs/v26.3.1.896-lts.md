<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 修正了普通 projections 的 metadata，使具有多列 sorting key 的 projections 能被正确识别。基于 [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429)。[#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* 将 data types 的 serialization versions 传播到嵌套 data types。例如，String serialization version `with_size_stream` 之前只应用于顶层 String columns 和 Tuple 元素。现在，它会应用到任何 nested type (如 Array/Map/Variant/JSON 等) 中的任意 String 类型。此行为由 MergeTree setting `propagate_types_serialization_versions_to_nested_types` 控制，该设置现已默认启用。此变更后，新创建的 parts 无法被旧版本读取，但旧 parts 可以被新版本正常读取。这意味着 upgrade 是安全的，但 downgrade 不安全。[#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* 移除了 `hypothesis` 跳过索引类型。它是一个冷门的 Experimental 功能，实际用途有限。现在，使用 `INDEX ... TYPE hypothesis` 创建表将产生 error。[#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了跳过索引文件未遵循 replace&#95;long&#95;file&#95;name&#95;to&#95;hash setting 的问题，该问题会导致 “File name too long” error，并使长名称的 indices 无法正确读取。现在，当跳过索引文件名超过 max&#95;file&#95;name&#95;length 时，会像 column files 一样进行哈希处理。这与旧版本兼容 (新 server 可以读取旧 parts) ，但 downgrade 时 (或 rolling upgrade 期间的旧 server) 可能会导致长名称的 indices 被忽略。[#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* 默认开启 async insert。现在，clickhouse 默认会对所有小型 inserts 进行 Batching。此 setting 受 compatibility 控制。如果你设置 `compatibility=<version less than 26.2>`，则默认值会恢复为之前的 `false`。你可以在多个层级关闭或开启异步插入：配置中的 users profiles、session、query，或 mergetree table。[#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* 修正了 `NOT` operator 的 优先次序，使其符合 SQL 标准：`NOT` 现在比 `IS NULL`、`BETWEEN`、`LIKE` 和算术 operators 的绑定更弱。例如，`NOT (x) IS NULL` 现在会被解析为 `NOT (x IS NULL)`，而不是 `(NOT x) IS NULL`。这可能会改变依赖先前 (非标准) 行为的 queries 结果。[#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 将 `mysql_datatypes_support_level` 的 default value 从空改为 `decimal,datetime64,date2Date32`，默认启用将 MySQL `DATE` 正确映射为 `Date32`、将 `DECIMAL`/`NUMERIC` 映射为 `Decimal`，以及将带 precision 的 `DATETIME`/`TIMESTAMP` 映射为 `DateTime64`。此前，MySQL `DATE` columns 会被映射为 `Date`，而后者无法表示 1970-01-01 之前的日期，从而导致数据损坏。[#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `mergeTreeAnalyzeIndexes{,UUID}` 现在接受 part names 数组而不是 Regexp，因为 regexps 很慢 (*Experimental 功能*) 。[#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* 移除了实验性的 `detectProgrammingLanguage` function。[#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* 现在可以通过 `naturalSortKey(s)` 使用自然排序键函数。[#90322](https://github.com/ClickHouse/ClickHouse/pull/90322) ([Nazarii Piontko](https://github.com/nazarii-piontko)).

* 为 JSON type 支持 `has()` 函数，用于检查路径是否存在，类似于 Map。[#96927](https://github.com/ClickHouse/ClickHouse/pull/96927) ([DQ](https://github.com/il9ue)).
* 新增 `mergeTreeTextIndex(database, table, index)` table function，可直接从 text index 读取数据。该函数可用于内部信息查看，或在 text index 数据之上执行 aggregations。[#97003](https://github.com/ClickHouse/ClickHouse/pull/97003) ([Anton Popov](https://github.com/CurtizJ)).
* 新增 `table_readonly` MergeTree setting，可将表标记为只读，从而阻止 insert 和修改操作。[#97652](https://github.com/ClickHouse/ClickHouse/pull/97652) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增设置 `use_partition_pruning` 及其别名 `use_partition_key`。将其设为 `false` 可禁用基于分区键的分区裁剪。[#97888](https://github.com/ClickHouse/ClickHouse/pull/97888) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 为 Iceberg 表实现了 `ALTER TABLE ... EXECUTE expire_snapshots('<timestamp>')`。[#97904](https://github.com/ClickHouse/ClickHouse/pull/97904) ([murphy-4o](https://github.com/murphy-4o)).
* 新增用于 Parquet metadata 的 SLRU 缓存，通过消除仅为读取 metadata 而重新下载文件的需求来提升读取性能。[#98140](https://github.com/ClickHouse/ClickHouse/pull/98140) ([Grant Holly](https://github.com/grantholly-clickhouse)).
* 允许 `<protocols>` 中的每个 `type=http` 条目指定自定义 `<handlers>` 键，并指向独立的 `<http_handlers_*>` config 部分，从而支持为不同端口配置不同的 HTTP 路由规则。[#98414](https://github.com/ClickHouse/ClickHouse/pull/98414) ([Amos Bird](https://github.com/amosbird)).
* `EXPLAIN [PLAN]` 命令的两项改进。[#98500](https://github.com/ClickHouse/ClickHouse/pull/98500) ([Kirill Kopnev](https://github.com/Fgrtue)).
* 添加 `restore_access_entities_with_current_grants` 服务器设置。启用后，恢复的用户/角色所拥有的授权将被限制在执行恢复操作的用户有权授予的范围内 (语义与 `GRANT CURRENT GRANTS` 相同) ，而不会因 `ACCESS_DENIED` 而失败。[#98795](https://github.com/ClickHouse/ClickHouse/pull/98795) ([pufit](https://github.com/pufit)).
* 添加 caseFoldUTF8 和 removeDiacriticsUTF8 函数，用于 Unicode 大小写折叠和去除变音符号。[#98973](https://github.com/ClickHouse/ClickHouse/pull/98973) ([George Larionov](https://github.com/george-larionov)).
* `SymbolIndex`、`addressToSymbol`、`system.symbols` 和 `buildId` 现在可通过解析 Mach-O 符号表在 macOS 上运行。[#99014](https://github.com/ClickHouse/ClickHouse/pull/99014) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 添加 `normalizeUTF8NFKCCasefold` 字符串函数，用于 NFKC&#95;Casefold Unicode 规范化，将 NFKC 规范化与大小写折叠结合起来。[#99276](https://github.com/ClickHouse/ClickHouse/pull/99276) ([George Larionov](https://github.com/george-larionov)).
* 为全文索引和 `tokens` 函数添加 `unicode_word` 分词器。它使用 Unicode 单词边界规则拆分文本：ASCII 单词可包含连接符字符 (下划线、冒号、点、单引号) ，而非 ASCII 的 Unicode 字符会被拆分为单字符标记。可配置的停用词默认使用常见的 CJK 标点符号。[#99357](https://github.com/ClickHouse/ClickHouse/pull/99357) ([Amos Bird](https://github.com/amosbird)).
* 添加了 `max_skip_unavailable_shards_num` 和 `max_skip_unavailable_shards_ratio` 设置，用于限制在启用 `skip_unavailable_shards` 时可静默跳过的分片数量。如果不可用分片的数量或比例超过配置的阈值，则会抛出异常，而不是静默返回不完整的结果。[#99369](https://github.com/ClickHouse/ClickHouse/pull/99369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 用户现在可以在子查询表达式中使用 `SOME` 关键字。其行为与 `ANY` 完全相同。[#99842](https://github.com/ClickHouse/ClickHouse/pull/99842) ([Artem Kytkin](https://github.com/Vinceent)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 优化 `pointInPolygon` 在大型多边形场景下的粒度跳过，并修复 `pointInPolygon` 在主键剪枝期间进行索引分析时抛出异常的问题。[#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)) 。
* 提升 `levenshteinDistance` 函数的性能。[#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)) 。
* 通过避免对每个元素单独调用函数，优化批次 Decimal 类型转换。[#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)) 。
* 1. Iceberg 新增了一项功能，可将 metadata 异步预填充到 cache 中。可在创建表时通过设置 `iceberg_metadata_async_prefetch_period_ms` 启用。例如：`CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. 现在，对 Iceberg 表的 Select queries 可通过指定 `iceberg_metadata_staleness_ms` parameter 执行；如果 cache 中的 metadata 版本比指定的 staleness 更新，ClickHouse 将直接使用该 cache 版本。否则，会查询远程 Iceberg catalog 以获取最新 metadata 来处理该 request (这也是此前的工作方式) 。通过这一变更，我们可以在 request 处理期间将对 Iceberg catalog 的调用降至 0，预计会带来明显的性能提升。Example：`SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`。 [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)) 。
* S3Queue ordered 模式使用 S3 ListObjectsV2 StartAfter 来避免重复列出完整的前缀历史，从而减少 ListObjects 调用。[#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* 一般来说，原始块对于去重是必需的，但对于同步 insert，可以省略它，从而彻底节省这部分内存。[#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* 为 YTsaurus table engine 启用并行读取。[#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* 使用与架构相关的缓存行大小值，而不是硬编码为 64。[#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
* 支持基于优化器统计信息交换 ANTI、SEMI 和 FULL join 的两侧。[#97498](https://github.com/ClickHouse/ClickHouse/pull/97498) ([Hechem Selmi](https://github.com/m-selmi)).
* 小幅优化了从文本索引字典读取的过程，提升了文本索引分析的整体性能。[#97519](https://github.com/ClickHouse/ClickHouse/pull/97519) ([Anton Popov](https://github.com/CurtizJ)).
* 提升了 ARM 上 16 字节块的 LZ4 解压速度。[#97774](https://github.com/ClickHouse/ClickHouse/pull/97774) ([Raúl Marín](https://github.com/Algunenano)).
* 将分词重构为新的高性能 forEachToken 回调接口，替换旧的迭代器风格 API，以支持 SIMD 和有状态分词器。属于 [#90268](https://github.com/ClickHouse/ClickHouse/issues/90268) 的一部分。[#97871](https://github.com/ClickHouse/ClickHouse/pull/97871) ([Amos Bird](https://github.com/amosbird)).
* 改进了在 queries 同时包含已索引列和未索引列组合条件时的文本索引分析性能。此前，在这类情况下，索引分析期间的提前退出优化会被错误地禁用。[#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ)).
* 提升了包含会生成超长数组或映射的常量表达式的 queries 性能。[#98287](https://github.com/ClickHouse/ClickHouse/pull/98287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了 `DateTime64` 主键与整数常量比较时的键条件分析问题，此前这会导致无法进行粒度剪枝。[#98410](https://github.com/ClickHouse/ClickHouse/pull/98410) ([Amos Bird](https://github.com/amosbird)).
* 设置 `optimize_syntax_fuse_functions` 默认启用。[#98424](https://github.com/ClickHouse/ClickHouse/pull/98424) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 当 predicate 包含任意比较运算符 (`=`, `<`, `>`, `!=`) ，且 partition key 被包裹在确定性函数链中时，允许进行 partition pruning (例如，`PARTITION BY x` 以及诸如 `cityHash64(x) % 5 > 2`、`toYYYYMM(x) < 2026`、`toYYYYMM(x) = 2026` 或 `toYYYYMM(x) != 2026` 之类的 predicates，都将使用 partition key 进行剪枝) 。关闭 [#28800](https://github.com/ClickHouse/ClickHouse/issues/28800)。[#98432](https://github.com/ClickHouse/ClickHouse/pull/98432) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 当 `CAST` 目标类型为 `Nullable` 且转换是单调的时，允许进行 read-in-order 优化和主键剪枝；例如，对于 `PRIMARY KEY x`，ClickHouse 可以对 `ORDER BY x::Nullable(UInt64)` 使用 read-in-order 优化，并可对诸如 `WHERE x::Nullable(UInt64) > 500000` 之类的 predicates 应用主键剪枝。[#98482](https://github.com/ClickHouse/ClickHouse/pull/98482) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 允许在整数列与 Float 字面量比较时进行索引裁剪和过滤条件下推；例如，`WHERE x < 10.5` 这样的谓词现在可以使用主键进行裁剪，而 `prime < 1e9` 或 `number < 1e5` 这样的过滤条件现在也可下推到 `primes()` 和 `numbers()` 表函数，而不再导致无限制执行。关闭 [#85167](https://github.com/ClickHouse/ClickHouse/issues/85167)。[#98516](https://github.com/ClickHouse/ClickHouse/pull/98516) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 通过使用本地累加器，而不是对每一行经由 aggregate state 进行存储转发，优化 `avgWeighted` 聚合函数，对 Nullable 输入的性能提升最高可达 27%。[#98793](https://github.com/ClickHouse/ClickHouse/pull/98793) ([Antonio Andelic](https://github.com/antonio2368)).
* 在某些场景下提升并行窗口函数的性能并降低内存使用量，同时也提升了处理大数组的 arrayFold workload 的性能。这还可以降低缺页压力，并在受影响查询的内存限制较紧时提升稳定性。[#98892](https://github.com/ClickHouse/ClickHouse/pull/98892) ([filimonov](https://github.com/filimonov)).
* 为有序合并添加 icolumn::comparetrackat()。[#99013](https://github.com/ClickHouse/ClickHouse/pull/99013) ([Artem Zuikov](https://github.com/4ertus2)).
* 优化 `INTERSECT ALL` 和 `EXCEPT ALL`。[#99097](https://github.com/ClickHouse/ClickHouse/pull/99097) ([Raufs Dunamalijevs](https://github.com/rienath)).
* 为逆序读取支持 `read_in_order_use_virtual_row` 优化。[#99198](https://github.com/ClickHouse/ClickHouse/pull/99198) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 通过在写入前检查 JoinUsedFlags 是否已设置，减少 RIGHT 和 FULL JOIN 中的缓存争用。[#99274](https://github.com/ClickHouse/ClickHouse/pull/99274) ([Hechem Selmi](https://github.com/m-selmi)).
* 通过将浮点运算替换为纯整数运算，优化 `PrefetchingHelper::calcPrefetchLookAhead`，从而改善指令缓存布局，并减少 aggregation 循环期间的周期开销。[#99327](https://github.com/ClickHouse/ClickHouse/pull/99327) ([Riyane El Qoqui](https://github.com/riyaneel)).
* 提升数据湖的性能。在之前的版本中，从对象存储读取时不会将管道调整到与处理线程数一致。[#99548](https://github.com/ClickHouse/ClickHouse/pull/99548) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 通过将 `absl::flat_hash_set` 替换为 `CompactChildrenSet` 来存储节点的子节点，降低 Keeper 的内存消耗。新容器可将 0–1 个子节点以内联方式存储，无需堆分配，这覆盖了绝大多数 Keeper 节点。这将 `KeeperMemNode` 的大小从 144 字节减少到 128 字节。[#99860](https://github.com/ClickHouse/ClickHouse/pull/99860) ([Antonio Andelic](https://github.com/antonio2368)).
* 已在 [#100600](https://github.com/ClickHouse/ClickHouse/issues/100600) 中回移：避免在枚举子列期间对 String `.size` 子列进行不必要的计算。[#99941](https://github.com/ClickHouse/ClickHouse/pull/99941) ([Pavel Kruglov](https://github.com/Avogar)).
