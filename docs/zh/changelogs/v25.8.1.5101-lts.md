  ### ClickHouse 版本 v25.8.1.5101-lts (4f2b50b8c92) FIXME，与 v25.8.1.1-new (d4d4c9f77fa) 相比

<div id="backward-incompatible-change">
  #### 向后不兼容变更
</div>

* 默认禁用在 JSON 格式中为 64 位整数加引号。[#74079](https://github.com/ClickHouse/ClickHouse/pull/74079) ([Pavel Kruglov](https://github.com/Avogar))。
* 对于 JSON 中包含不同类型值的数组，现在会推断为 `Array(Dynamic)`，而不是未命名 `Tuple`。如需使用之前的行为，请禁用设置 `input_format_json_infer_array_of_dynamic_from_array_of_different_types`。[#80859](https://github.com/ClickHouse/ClickHouse/pull/80859) ([Pavel Kruglov](https://github.com/Avogar))。
* 将 S3 延迟指标改为使用直方图，以提高一致性并简化实现。[#82305](https://github.com/ClickHouse/ClickHouse/pull/82305) ([Miсhael Stetsyuk](https://github.com/mstetsyuk))。
* 现在要求在默认表达式中，对带点号的标识符使用反引号包裹，以防其被解析为复合标识符。[#83162](https://github.com/ClickHouse/ClickHouse/pull/83162) ([Pervakov Grigorii](https://github.com/GrigoryPervakov))。
* 为避免在未使用 analyzer 的情况下继续维护惰性物化，Lazy materialization 现仅在启用 analyzer 时可用——根据我们的经验，不使用 analyzer 时存在一些问题 (例如在条件中使用 `indexHint()` 时) 。[#83791](https://github.com/ClickHouse/ClickHouse/pull/83791) ([Igor Nikonov](https://github.com/devcrafter))。
* 默认在 Parquet 输出格式中，将 `Enum` 类型的值写为带有 `ENUM` logical type 的 `BYTE_ARRAY`。[#84169](https://github.com/ClickHouse/ClickHouse/pull/84169) ([Pavel Kruglov](https://github.com/Avogar))。
* 默认启用 MergeTree 设置 `write_marks_for_substreams_in_compact_parts`。这将显著提升从新创建的 Compact parts 读取子列的性能。低于 25.5 版本的服务器将无法读取新的 Compact parts。[#84171](https://github.com/ClickHouse/ClickHouse/pull/84171) ([Pavel Kruglov](https://github.com/Avogar))。
* 此前，`concurrent_threads_scheduler` 的默认值为 `round_robin`，但在存在大量单线程查询 (例如 `INSERT`) 时，已证明这种方式并不公平。此次变更将更安全的替代方案 `fair_round_robin` 调度器设为默认值。[#84747](https://github.com/ClickHouse/ClickHouse/pull/84747) ([Sergei Trifonov](https://github.com/serxa))。
* ClickHouse 支持 PostgreSQL 风格的 Heredoc 语法：`$tag$ string contents... $tag$`，也称为 dollar-quoted 字符串字面量。在之前的版本中，对 tag 的限制较少：它可以包含任意字符，包括标点和空白字符。这会与同样可以美元符号开头的标识符产生解析歧义。同时，PostgreSQL 仅允许 tag 包含单词字符。为解决这一问题，我们现在将 Heredoc tag 限制为只能包含单词字符。关闭了 [#84731](https://github.com/ClickHouse/ClickHouse/issues/84731)。[#84846](https://github.com/ClickHouse/ClickHouse/pull/84846) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 函数 `azureBlobStorage`、`deltaLakeAzure` 和 `icebergAzure` 已更新，可正确校验 `AZURE` 权限。现在所有集群变体函数 (`-Cluster` 函数) 都会针对其对应的非集群版本校验权限。此外，`icebergLocal` 和 `deltaLakeLocal` 函数现在也会强制执行 `FILE` 权限检查。[#84938](https://github.com/ClickHouse/ClickHouse/pull/84938) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov))。
* 默认启用 `allow_dynamic_metadata_for_data_lakes` 设置 (表引擎级设置) 。[#85044](https://github.com/ClickHouse/ClickHouse/pull/85044) ([Daniil Ivanik](https://github.com/divanik))。

<div id="performance-improvement">
  #### 性能提升
</div>

* `azureBlobStorage` 表引擎：尽可能缓存并复用托管身份的身份验证令牌，以避免限流。 [#79860](https://github.com/ClickHouse/ClickHouse/pull/79860) ([Nick Blakely](https://github.com/niblak)).
* 新增了一项逻辑 (由设置 `enable_producing_buckets_out_of_order_in_aggregation` 控制，默认启用) ，允许在内存高效的聚合过程中乱序发送部分桶。当某些聚合桶的 merge 明显比其他桶更耗时时，这一改动可让 initiator 在此期间合并 bucket id 更高的桶，从而提升性能。缺点是内存使用量可能略有增加 (通常不会太明显) 。 [#80179](https://github.com/ClickHouse/ClickHouse/pull/80179) ([Nikita Taranov](https://github.com/nickitat)).
* 全新的 Parquet reader 实现。整体速度更快，并支持页级过滤器下推和 PREWHERE。目前为 Experimental。使用设置 `input_format_parquet_use_native_reader_v3` 启用。 [#82789](https://github.com/ClickHouse/ClickHouse/pull/82789) ([Michael Kolupaev](https://github.com/al13n321)).
* 在 hash JOIN 主循环之外处理 `max_joined_block_rows`。可略微提升 ALL JOIN 的性能。 [#83216](https://github.com/ClickHouse/ClickHouse/pull/83216) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 将 Azure Blob 存储的 curl http client 替换为 poco http client。为这些 client 新增了多项设置，与 S3 的设置保持一致。同时为 Azure 和 S3 引入了更激进的连接 timeout。增强了对 Azure profile events 和 metrics 的内部信息。新 client 默认启用，可显著改善 Azure Blob 存储上冷 queries 的 latencies。可通过设置 `azure_sdk_use_native_client=false` 切回旧的 `Curl` client。 [#83294](https://github.com/ClickHouse/ClickHouse/pull/83294) ([alesapin](https://github.com/alesapin)).
* 通过为 MergeTree 中的 `JSON` shared data 实现新的 serializations，显著提升了从 shared data 读取 `JSON` subcolumns 的性能。 [#83777](https://github.com/ClickHouse/ClickHouse/pull/83777) ([Pavel Kruglov](https://github.com/Avogar)).
* 优先处理 granularity 更高的 min-max indexes。关闭 [#75381](https://github.com/ClickHouse/ClickHouse/issues/75381)。 [#83798](https://github.com/ClickHouse/ClickHouse/pull/83798) ([Maruth Goyal](https://github.com/maruthgoyal)).
* 使用向量相似度索引的 vector search queries 因存储读取减少和 CPU usage 降低，可在更低 latency 下完成。 [#83803](https://github.com/ClickHouse/ClickHouse/pull/83803) ([Shankar Iyer](https://github.com/shankar-iyer)).
* 为 If combinators 实现 addManyDefaults。 [#83870](https://github.com/ClickHouse/ClickHouse/pull/83870) ([Raúl Marín](https://github.com/Algunenano)).
* 在按多个字符串列或数字列进行 group by 时，以列式方式计算序列化后的 key。 [#83884](https://github.com/ClickHouse/ClickHouse/pull/83884) ([李扬](https://github.com/taiyang-li)).
* 尝试使用 `-falign-functions=64`，以获得更稳定的性能测试结果。 [#83920](https://github.com/ClickHouse/ClickHouse/pull/83920) ([Azat Khuzhin](https://github.com/azat)).
* bloom filter 索引现已可用于 `has([c1, c2, ...], column)` 这类条件，其中 `column` 不是 `Array` 类型。这提升了此类 queries 的性能，使其与 `IN` operator 一样高效。 [#83945](https://github.com/ClickHouse/ClickHouse/pull/83945) ([Doron David](https://github.com/dorki)).
* 减少了 CompressedReadBufferBase::readCompressedData 中不必要的 memcpy 调用。 [#83986](https://github.com/ClickHouse/ClickHouse/pull/83986) ([Raúl Marín](https://github.com/Algunenano)).
* 如果右侧由连接键列函数性唯一确定 (即所有行的连接键值都唯一) ，则 `All` `LEFT/INNER` JOIN 将自动转换为 `RightAny`。 [#84010](https://github.com/ClickHouse/ClickHouse/pull/84010) ([Nikita Taranov](https://github.com/nickitat)).
* 按文件大小升序处理索引。整体索引顺序会优先考虑 minmax 和向量索引 (分别基于其简单性和选择性) ，随后再处理较小的索引。在 minmax/向量索引内部，也会优先选择较小的索引。[#84094](https://github.com/ClickHouse/ClickHouse/pull/84094) ([Maruth Goyal](https://github.com/maruthgoyal)).
* 通过移除临时数据优化 `largestTriangleThreeBuckets`。[#84479](https://github.com/ClickHouse/ClickHouse/pull/84479) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 通过简化代码优化字符串反序列化。关闭 [#38564](https://github.com/ClickHouse/ClickHouse/issues/38564)。[#84561](https://github.com/ClickHouse/ClickHouse/pull/84561) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 之前，text index 数据会被拆分为多个分段 (默认每个分段大小为 256 MiB) 。这可能会降低构建 text index 时的内存消耗，但会增加磁盘空间需求，并延长查询响应时间。[#84590](https://github.com/ClickHouse/ClickHouse/pull/84590) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 修复了并行副本最小 task size 的计算问题。[#84752](https://github.com/ClickHouse/ClickHouse/pull/84752) ([Nikita Taranov](https://github.com/nickitat)).
* 提升了 `Join` 模式下应用补丁分区片段的性能。[#85040](https://github.com/ClickHouse/ClickHouse/pull/85040) ([Anton Popov](https://github.com/CurtizJ)).
* 移除了零字节。关闭 [#85062](https://github.com/ClickHouse/ClickHouse/issues/85062)。同时还修复了一些小问题。函数 `structureToProtobufSchema`、`structureToCapnProtoSchema` 之前未能正确写入以零结尾的字节，而是错误地使用了换行符代替。这会导致输出中缺少换行符，并且在使用依赖零字节的其他函数时可能引发缓冲区溢出 (例如 `logTrace`、`demangle`、`extractURLParameter`、`toStringCutToZero` 和 `encrypt`/`decrypt`) 。`regexp_tree` dictionary layout 不支持处理包含零字节的字符串。使用 `Values` format 或其他任何行尾不带换行符的 format 调用 `formatRowNoNewline` 函数时，会错误地截掉输出的最后一个字符。函数 `stem` 中存在一个异常安全性错误，在极少数情况下可能导致内存泄漏。`initcap` 函数对 `FixedString` argument 的处理方式不正确：如果一个块中的前一个字符串以单词字符结尾，它就无法识别当前字符串开头的单词起始位置。修复了 Apache `ORC` format 的一个安全漏洞，该漏洞可能导致未初始化内存泄露。修改了函数 `replaceRegexpAll` 及其对应别名 `REGEXP_REPLACE` 的行为：现在即使前一次匹配已处理完整个字符串，它仍然可以在字符串末尾执行空匹配，例如 `^a*|a*$` 或 `^|.*` 这类情况——这与 JavaScript、Perl、Python、PHP、Ruby 的语义一致，但不同于 PostgreSQL 的语义。许多函数的实现已被简化并优化。多个函数的文档原先有误，现已修正。请注意，`byteSize` 对 String columns 以及由 String columns 组成的复杂 types 的输出已经发生变化 (空字符串从每个 9 字节变为每个 8 字节) ，这是正常现象。[#85063](https://github.com/ClickHouse/ClickHouse/pull/85063) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 优化了仅为返回单行而进行常量 materialization 的场景。[#85071](https://github.com/ClickHouse/ClickHouse/pull/85071) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 改进了使用 delta-kernel-rs backend 时的并行文件处理。[#85642](https://github.com/ClickHouse/ClickHouse/pull/85642) ([Azat Khuzhin](https://github.com/azat)).
