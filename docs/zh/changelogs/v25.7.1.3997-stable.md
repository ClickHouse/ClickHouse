<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 此 PR 中的更改：1. 为该函数引入了一个新 argument `unexpected_quoting_character_strategy`，用于控制在读取未加引号的键或值时，如果意外遇到 `quoting_character` 会发生什么。其取值可以是：`invalid`、`accept` 或 `promote`。Invalid 会丢弃该键并返回等待键的状态。Accept 会将其视为键的一部分。Promote 会丢弃前一个字符，并开始按带引号的键进行解析。我认为默认行为 (也可能是唯一合理的行为) 应该是 `INVALID`，但在 2023 年的 https://github.com/ClickHouse/ClickHouse/pull/56423 中实现了 `PROMOTE` 逻辑。因此，为了在一定程度上保持向后兼容，我添加了这个设置。2. 在解析完带引号的值后，只有在发现键值对分隔符时才解析下一个键。 [#80657](https://github.com/ClickHouse/ClickHouse/pull/80657) ([Arthur Passos](https://github.com/arthurpassos)).
* 之前，即使模式接受空匹配，函数 `countMatches` 也会在第一次空匹配时停止计数。为解决这个问题，`countMatches` 现在会在发生空匹配时向前推进一个字符并继续执行。希望保留旧行为的用户可以启用设置 `count_matches_stop_at_empty_match`。 [#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 之前，BACKUP 查询、合并和变更操作不会使用服务器级限流器来限制本地 (`max_local_read_bandwidth_for_server` 和 `max_local_write_bandwidth_for_server`) 以及远程 (`max_remote_read_network_bandwidth_for_server` 和 `max_remote_write_network_bandwidth_for_server`) 流量，而只会受到专用服务器设置 (`max_backup_bandwidth_for_server`、`max_mutations_bandwidth_for_server` 和 `max_merges_bandwidth_for_server`) 的限流。现在，它们会同时使用这两类限流器。 [#81753](https://github.com/ClickHouse/ClickHouse/pull/81753) ([Sergei Trifonov](https://github.com/serxa)).
* 禁止创建没有可插入列的表。 [#81835](https://github.com/ClickHouse/ClickHouse/pull/81835) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* 带归档文件的集群函数过去会把整个归档文件发送给副本，导致归档内的读取无法在集群中并行化 (例如，若只有一个归档文件，就会把整个归档文件发送给某一个副本处理，而其他所有副本都会处于空闲状态，这样效率很低) 。新增了一个设置 `cluster_function_process_archive_on_multiple_nodes`，默认值为 `true`。如果设置为 `true`，可提高集群函数处理归档文件时的性能。如果在早期版本中使用带归档文件的集群函数，那么在升级到 25.7+ 时，为了保持兼容性并避免出错，应将其设置为 `false`。 [#82355](https://github.com/ClickHouse/ClickHouse/pull/82355) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `SYSTEM RESTART REPLICAS` 查询过去会唤醒 Lazy database 中的表，即使没有该 database 的访问权限也会如此，而且当时这些表可能正在被并发删除。注意：现在 `SYSTEM RESTART REPLICAS` 只会重启你在其中拥有 `SHOW TABLES` 权限的数据库中的副本，这是更符合预期的行为。 [#83321](https://github.com/ClickHouse/ClickHouse/pull/83321) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### 新特性
</div>

* 为类型为 `Float32` 和 `Float64` 的列新增 SZ3，它是一种有损但误差有界的压缩编解码器。[#67161](https://github.com/ClickHouse/ClickHouse/pull/67161) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 在 Iceberg schema 演进中支持复杂类型。[#73714](https://github.com/ClickHouse/ClickHouse/pull/73714) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* **NumericIndexedVector**：一种新的向量数据结构，基于位切片的 Roaring-bitmap 压缩，并提供了 20 多个用于构建、分析和逐点算术运算的函数。它可以减少存储占用，并加速稀疏数据上的 join、过滤和聚合。实现见 [#70582](https://github.com/ClickHouse/ClickHouse/issues/70582) 以及 VLDB 2024 上 T. Xiong 和 Y. Wang 的论文 [“Large-Scale Metric Computation in Online Controlled Experiment Platform”](https://arxiv.org/abs/2405.08411)。[#74193](https://github.com/ClickHouse/ClickHouse/pull/74193) ([FriendLey](https://github.com/FriendLey)).
* 新增 &#39;format&#95;schema&#95;source&#39; 设置，用于定义 &#39;format&#95;schema&#39; 的来源。[#80874](https://github.com/ClickHouse/ClickHouse/pull/80874) ([Tuan Pham Anh](https://github.com/tuanpach)).
* 新增数据类型：Time ([H]HH:MM:SS) 和 Time64 ([H]HH:MM:SS[.fractional]) ，以及一些基础类型转换函数和与其他数据类型交互的函数。还新增了用于兼容旧版函数 `ToTime` 的设置。[#81217](https://github.com/ClickHouse/ClickHouse/pull/81217) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 现已支持工作负载设置 `max_waiting_queries`。它可用于限制查询队列的大小。如果达到该限制，后续所有查询都将因 `SERVER_OVERLOADED` 错误而被终止。[#81250](https://github.com/ClickHouse/ClickHouse/pull/81250) ([Oleg Doronin](https://github.com/dorooleg)).
* 现在可以使用 USE DATABASE {name}。 [#81307](https://github.com/ClickHouse/ClickHouse/pull/81307) ([Yarik Briukhovetskyi](https://github.com/yariks5s)) 。
* 添加金融函数：`financialInternalRateOfReturnExtended` (`XIRR`) 、`financialInternalRateOfReturn` (`IRR`) 、`financialNetPresentValueExtended` (`XNPV`) 、`financialNetPresentValue` (`NPV`) 。[#81599](https://github.com/ClickHouse/ClickHouse/pull/81599) ([Joanna Hulboj](https://github.com/jh0x)) 。
* 新增系统表 `system.codecs`，用于查看可用的编解码器。 (issue [#81525](https://github.com/ClickHouse/ClickHouse/issues/81525)) 。[#81600](https://github.com/ClickHouse/ClickHouse/pull/81600) ([Jimmy Aguilar Mena](https://github.com/Ergus)) 。
* 添加地理空间函数 `polygonIntersectsCartesian` 和 `polygonIntersectsSpherical`，用于检查两个多边形是否相交。[#81882](https://github.com/ClickHouse/ClickHouse/pull/81882) ([Paul Lamb](https://github.com/plamb)) 。
* 为 `MergeTree` 家族表添加了对轻量级更新的支持。轻量级更新可通过以下新语法使用：`UPDATE <table> SET col1 = val1, col2 = val2, ... WHERE <condition>`。还通过轻量级更新实现了轻量级删除。可通过设置 `lightweight_delete_mode = 'lightweight_update'` 启用。[#82004](https://github.com/ClickHouse/ClickHouse/pull/82004) ([Anton Popov](https://github.com/CurtizJ)) 。
* 支持 `lag` 和 `lead` 窗口函数。关闭了 [#9887](https://github.com/ClickHouse/ClickHouse/issues/9887)。[#82108](https://github.com/ClickHouse/ClickHouse/pull/82108) ([Dmitry Novik](https://github.com/novikd)) 。
* 在 MergeTree 家族表中支持 `_part_granule_offset` 虚拟列。该列表示每一行在其数据分区片段内所属粒度/标记的零基索引。这解决了 [#79572](https://github.com/ClickHouse/ClickHouse/issues/79572)。[#82341](https://github.com/ClickHouse/ClickHouse/pull/82341) ([Amos Bird](https://github.com/amosbird)) 。
* 为 `insert` 查询引入了对 Iceberg 写入的支持。[#82692](https://github.com/ClickHouse/ClickHouse/pull/82692) ([Konstantin Vedernikov](https://github.com/scanhex12)) 。
* 为类型为 `Float32` 和 `Float64` 的列添加 SZ3 作为一种有损但误差有界的压缩编解码器。[#83088](https://github.com/ClickHouse/ClickHouse/pull/83088) ([Konstantin Vedernikov](https://github.com/scanhex12)) 。
* 为 ClickHouse client 添加 AI 驱动的 SQL 生成功能。现在，用户只需在查询前加上 &quot;??&quot;，即可根据自然语言描述生成 SQL 查询。支持 OpenAI 和 Anthropic 提供商，并具备自动 schema 发现功能。[#83314](https://github.com/ClickHouse/ClickHouse/pull/83314) ([Kaushik Iska](https://github.com/iskakaushik)) 。
* 支持按字段 id 读取 Iceberg 数据文件。这关闭了 [#83065](https://github.com/ClickHouse/ClickHouse/issues/83065)。[#83653](https://github.com/ClickHouse/ClickHouse/pull/83653) ([Konstantin Vedernikov](https://github.com/scanhex12)) 。
* 添加了 SQL 函数 `colorSRGBToOkLCH` 和 `colorOkLCHToSRGB`，用于在 sRGB 和 OkLCH 色彩空间之间转换颜色。[#83679](https://github.com/ClickHouse/ClickHouse/pull/83679) ([Fgrtue](https://github.com/Fgrtue)) 。
* 已在 [#84005](https://github.com/ClickHouse/ClickHouse/issues/84005) 中回移：AI 驱动的 SQL 生成功能现在在可用时可从环境变量 ANTHROPIC&#95;API&#95;KEY 和 OPENAI&#95;API&#95;KEY 自动推断，从而提供零配置即可使用此功能的选项。[#83787](https://github.com/ClickHouse/ClickHouse/pull/83787) ([Kaushik Iska](https://github.com/iskakaushik)) 。



<div id="experimental-feature">
  #### Experimental 功能
</div>

* 新增函数 `searchAny` 和 `searchAll`，作为搜索文本索引的通用工具。[#80641](https://github.com/ClickHouse/ClickHouse/pull/80641) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 文本索引现已支持 `string` 分词器。[#81752](https://github.com/ClickHouse/ClickHouse/pull/81752) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 将 `text` 索引的默认索引粒度值调整为 64。这提升了内部基准测试中平均测试查询的预期性能。[#82162](https://github.com/ClickHouse/ClickHouse/pull/82162) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* 256-bit bitmap 会按顺序存储某个状态的出边标记，但出边状态保存到磁盘时的顺序却是它们在哈希表中出现的顺序。因此，从磁盘读取时，某个标记可能会指向错误的下一状态。[#82783](https://github.com/ClickHouse/ClickHouse/pull/82783) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 目前，FST 树以未压缩形式保存到磁盘。这可能导致写入和读取磁盘时性能下降，或占用更高的 I/O 带宽。[#83093](https://github.com/ClickHouse/ClickHouse/pull/83093) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 由于存在一个 bug，已移除 `searchAny` 和 `searchAll`。参见 [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385)。[#83117](https://github.com/ClickHouse/ClickHouse/pull/83117) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 最近，fuzzer 在 `searchAny` 和 `searchAll` 函数中发现了一个问题 (参见 [#82385](https://github.com/ClickHouse/ClickHouse/issues/82385)) 。当 `searchAny` 或 `searchAll` 函数对同一列使用不同的文本索引参数时，就会触发此异常。只有同一列上存在两个不同的文本索引时，才可能出现这种情况。此 PR 限制同一列在文本索引中只能定义一次，但列上的 wrapper (例如 `lower(column)`) 仍然允许使用。[#83303](https://github.com/ClickHouse/ClickHouse/pull/83303) ([Elmi Ahmadov](https://github.com/ahmadov)).



<div id="performance-improvement">
  #### 性能提升
</div>

* 对 -If 组合器进行了小幅优化。[#78454](https://github.com/ClickHouse/ClickHouse/pull/78454) ([李扬](https://github.com/taiyang-li)).
* 新增一个选项，可将块的 (解) 压缩和 (反) 序列化卸载到管道线程中执行，而不是由与网络 connection 关联的单个线程处理。该选项由设置 `enable_parallel_blocks_marshalling` 控制。这应能加快在 initiator 与远程节点之间传输大量数据的分布式查询。[#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* 使用向量相似度索引的向量搜索查询因减少了存储读取和 CPU usage，能够以更低延迟完成。[#79103](https://github.com/ClickHouse/ClickHouse/pull/79103) ([Shankar Iyer](https://github.com/shankar-iyer)).
* 在 `filterPartsByQueryConditionCache` 中遵循 `merge_tree_min_{rows,bytes}_for_seek`，使其与其他按索引过滤的方法保持一致。[#80312](https://github.com/ClickHouse/ClickHouse/pull/80312) ([李扬](https://github.com/taiyang-li)).
* 使 TOTALS 步骤之后的管道变为多线程。[#80331](https://github.com/ClickHouse/ClickHouse/pull/80331) ([UnamedRus](https://github.com/UnamedRus)).
* 在每个分片上独立执行 INSERT SELECT 的模式下，并行分布式 INSERT SELECT 现默认启用，参见 `parallel_distributed_insert_select` 设置。[#80425](https://github.com/ClickHouse/ClickHouse/pull/80425) ([Igor Nikonov](https://github.com/devcrafter)).
* 调整了一些 jemalloc 配置以提升性能。[#81807](https://github.com/ClickHouse/ClickHouse/pull/81807) ([Antonio Andelic](https://github.com/antonio2368)).
* 修复了 Redis 和 KeeperMap storages 按键过滤的问题。[#81833](https://github.com/ClickHouse/ClickHouse/pull/81833) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* 新增设置 `min_joined_block_size_rows` (类似于 `min_joined_block_size_bytes`；默认值为 65409) ，用于控制 JOIN 输入和输出块的最小大小 (按行数计，如果 join algorithm 支持) 。较小的块会被合并成更大的块。[#81886](https://github.com/ClickHouse/ClickHouse/pull/81886) ([Nikita Taranov](https://github.com/nickitat)).
* 当聚合查询仅包含一个作用于 NOT NULL 列的 `COUNT()` 函数时，聚合逻辑会在哈希表探测期间完全内联。这避免了分配和维护任何聚合状态，从而显著降低内存使用量和 CPU 开销。此更改部分解决了 [#81982](https://github.com/ClickHouse/ClickHouse/issues/81982)。[#82104](https://github.com/ClickHouse/ClickHouse/pull/82104) ([Amos Bird](https://github.com/amosbird)).
* 通过移除仅有一个键列这一典型场景下对哈希映射的额外循环，优化了 `HashJoin` 的性能；此外，当 `null_map` 和 `join_mask` 始终为 `true`/`false` 时，也会省去相应检查。[#82308](https://github.com/ClickHouse/ClickHouse/pull/82308) ([Nikita Taranov](https://github.com/nickitat)).
* `ATTACH PARTITION` 不再导致丢弃所有缓存。[#82377](https://github.com/ClickHouse/ClickHouse/pull/82377) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 通过使用等价类消除冗余的 JOIN 操作，优化了相关子查询生成的 plan。如果所有相关列都有等价 expression，则在启用 `query_plan_correlated_subqueries_use_substitution` 设置时，不会生成 `CROSS JOIN`。[#82435](https://github.com/ClickHouse/ClickHouse/pull/82435) ([Dmitry Novik](https://github.com/novikd)).
* 当相关子查询作为函数 `EXISTS` 的 argument 出现时，只读取所需的列。[#82443](https://github.com/ClickHouse/ClickHouse/pull/82443) ([Dmitry Novik](https://github.com/novikd)).
* 引入异步日志。[#82516](https://github.com/ClickHouse/ClickHouse/pull/82516) ([Raúl Marín](https://github.com/Algunenano)).
* 在原生协议中压缩日志和 profile events。在拥有 100+ 副本的集群上，未压缩的 profile events 会占用 1..10 MB/sec，而且在较慢的互联网连接下进度条会变得很卡。这修复了 [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533)。[#82535](https://github.com/ClickHouse/ClickHouse/pull/82535) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 略微提升 QueryTreeHash 的速度。[#82617](https://github.com/ClickHouse/ClickHouse/pull/82617) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 在 ProfileEvents 的 Counter 中添加对齐，以减少伪共享。[#82697](https://github.com/ClickHouse/ClickHouse/pull/82697) ([Jiebin Sun](https://github.com/jiebinn)).
* 默认启用并行 distributed INSERT SELECT，即在每个分片上独立执行 INSERT SELECT 的模式，参见 `parallel_distributed_insert_select` 设置。[#83040](https://github.com/ClickHouse/ClickHouse/pull/83040) ([Igor Nikonov](https://github.com/devcrafter)).
* 将 [#82308](https://github.com/ClickHouse/ClickHouse/issues/82308) 中针对 `null_map` 和 `JoinMask` 的优化应用到了包含多个析取条件的 JOIN 场景中。此外，还优化了 `KnownRowsHolder` 数据结构。[#83041](https://github.com/ClickHouse/ClickHouse/pull/83041) ([Nikita Taranov](https://github.com/nickitat)).
* 对 join flags 使用普通的 `std::vector<std::atomic_bool>`，以避免每次访问 flags 时都计算哈希。[#83043](https://github.com/ClickHouse/ClickHouse/pull/83043) ([Nikita Taranov](https://github.com/nickitat)).
* 当 `HashJoin` 使用 `lazy` 输出模式时，不再提前为结果列预分配内存。这样做效果不佳，尤其是在匹配数量较少时。此外，在连接完成后我们能够准确知道匹配数量，因此可以更精确地进行预分配。[#83304](https://github.com/ClickHouse/ClickHouse/pull/83304) ([Nikita Taranov](https://github.com/nickitat)).
* 在管道构建期间尽量减少端口请求头中的内存拷贝。原始 [PR](https://github.com/ClickHouse/ClickHouse/pull/70105) 由 [heymind](https://github.com/heymind) 提交。[#83381](https://github.com/ClickHouse/ClickHouse/pull/83381) ([Raúl Marín](https://github.com/Algunenano)).
* 改进了 Keeper 对 rocksdb 初始加载的处理。[#83390](https://github.com/ClickHouse/ClickHouse/pull/83390) ([Antonio Andelic](https://github.com/antonio2368)).
* 在创建存储快照数据时避免持有锁，以减少高并发负载下的锁竞争。[#83510](https://github.com/ClickHouse/ClickHouse/pull/83510) ([Duc Canh Le](https://github.com/canhld94)).
* 在未发生解析错误时，通过复用序列化器提升了 ProtobufSingle 输入格式的性能。[#83613](https://github.com/ClickHouse/ClickHouse/pull/83613) ([Eduard Karacharov](https://github.com/korowa)).
* 提升管道构建性能。[#83631](https://github.com/ClickHouse/ClickHouse/pull/83631) ([Raúl Marín](https://github.com/Algunenano)).
* 优化 MergeTreeReadersChain::getSampleBlock。[#83875](https://github.com/ClickHouse/ClickHouse/pull/83875) ([Raúl Marín](https://github.com/Algunenano)).





<div id="improvement">
  #### 改进
</div>

* 为数据源引入了两种新的访问类型：`READ` 和 `WRITE`，并弃用了此前所有与数据源相关的访问类型。此前使用的是 `GRANT S3 ON *.* TO user`，现在改为：`GRANT READ, WRITE ON S3 TO user`。这也允许为数据源分别授予 `READ` 和 `WRITE` 权限，例如：`GRANT READ ON * TO user`、`GRANT WRITE ON S3 TO user`。该功能由设置 `access_control_improvements.enable_read_write_grants` 控制，默认禁用。[#73659](https://github.com/ClickHouse/ClickHouse/pull/73659) ([pufit](https://github.com/pufit)).
* 在提交分片前，先验证其 checksum.txt 文件是否一致。[#76625](https://github.com/ClickHouse/ClickHouse/pull/76625) ([Sema Checherinda](https://github.com/CheSema)).
* 在 s3&#95;plain&#95;rewritable 中实现 `moveFile` 和 `replaceFile` 方法，使其可用作数据库磁盘。[#79424](https://github.com/ClickHouse/ClickHouse/pull/79424) ([Tuan Pham Anh](https://github.com/tuanpach)).
* 允许为 PostgreSQL、MySQL 和 DataLake 数据库创建备份。此类数据库的备份只会保存定义，不会保存其中的数据。[#79982](https://github.com/ClickHouse/ClickHouse/pull/79982) ([Nikolay Degterinsky](https://github.com/evillique)).
* 为 Iceberg TableEngine 增加位置删除支持。[#80237](https://github.com/ClickHouse/ClickHouse/pull/80237) ([YanghongZhong](https://github.com/yahoNanJing)).
* 设置 `allow_experimental_join_condition` 已标记为 Obsolete。[#80566](https://github.com/ClickHouse/ClickHouse/pull/80566) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 为 ClickHouse 异步指标新增压力指标。[#80779](https://github.com/ClickHouse/ClickHouse/pull/80779) ([Xander Garbett](https://github.com/Garbett1)).
