* 已回移到 [#91754](https://github.com/ClickHouse/ClickHouse/issues/91754)：修复在以 `localhost` 作为目标主机时，使用 `remote` 表函数的 `ALTER UPDATE` 查询的访问校验问题。[#90761](https://github.com/ClickHouse/ClickHouse/pull/90761) ([pufit](https://github.com/pufit)) 。
* 已回移到 [#97815](https://github.com/ClickHouse/ClickHouse/issues/97815)：相关 issue #[https://github.com/ClickHouse/support-escalation/issues/6365](https://github.com/ClickHouse/support-escalation/issues/6365)。[#92339](https://github.com/ClickHouse/ClickHouse/pull/92339) ([Tuan Pham Anh](https://github.com/tuanpach)) 。
* 已回移到 [#97327](https://github.com/ClickHouse/ClickHouse/issues/97327)：移除了对启用 SQL Security 的视图执行 `ATTACH` 查询时不必要的跳过权限检查逻辑。这可防止用户在未验证所需访问权限的情况下，通过附加带有 definer 的视图造成潜在的权限提升。[#94865](https://github.com/ClickHouse/ClickHouse/pull/94865) ([pufit](https://github.com/pufit)) 。
* 已回移到 [#95814](https://github.com/ClickHouse/ClickHouse/issues/95814)：修复在多个 JOIN 配合 `USING` 子句使用时，对源表中带限定名列的类型推断问题。此前，后续 JOIN 会错误地将底层源列的类型更新为共同超类型，即使该列并未参与该 JOIN (例如，在 `SELECT t2.a FROM t1 LEFT JOIN t2 USING (a) LEFT JOIN t3 USING (a)` 中，`t2.a` 列仅用于第一个 JOIN，因此它的类型应为 `t1.a` 和 `t2.a` 的超类型，不应包含 `t3.a`) 。当函数预期的列类型与执行计划中实际出现的类型不一致时，这可能导致逻辑错误或崩溃。[#95157](https://github.com/ClickHouse/ClickHouse/pull/95157) ([Vladimir Cherkasov](https://github.com/vdimir)) 。
* 已回移到 [#95484](https://github.com/ClickHouse/ClickHouse/issues/95484)：`mergeTreeProjection` 表函数缺少访问检查，导致没有表上 SELECT 权限 (但具有表函数权限) 的用户也能从其投影中读取数据。此修复补充了与 `mergeTreeIndex` 和 `mergeTreeAnalyzeIndexes` 相同的访问检查。[#95480](https://github.com/ClickHouse/ClickHouse/pull/95480) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 已回移到 [#96052](https://github.com/ClickHouse/ClickHouse/issues/96052)：修复对已分区 delta lake 数据进行 squashing 时的问题。[#95773](https://github.com/ClickHouse/ClickHouse/pull/95773) ([Kseniia Sumarokova](https://github.com/kssenii)) 。
* 已回移到 [#96209](https://github.com/ClickHouse/ClickHouse/issues/96209)：修复 JSON 数据类型中的 skipping paths 问题。此前，使用 `JSON(SKIP path)` 时，所有以前缀 `path` 开头的 JSON 键都会被跳过，甚至包括 `"pathpath"` 这样的键，因此可能导致这些路径的数据在插入时丢失。现在该问题已修复，只有键 `"path"` 会被跳过。[#95948](https://github.com/ClickHouse/ClickHouse/pull/95948) ([Pavel Kruglov](https://github.com/Avogar)) 。
* 已在 [#96076](https://github.com/ClickHouse/ClickHouse/issues/96076) 中回移：修复全局 profiler 的周期问题 (由 `global_profiler_real_time_period_ns` 和 `global_profiler_cpu_time_period_ns` 控制) 。此前实际使用的是截断后的值，而不是设置的值，导致 profiler 的唤醒频率高于预期。[#96048](https://github.com/ClickHouse/ClickHouse/pull/96048) ([Antonio Andelic](https://github.com/antonio2368)) 。
