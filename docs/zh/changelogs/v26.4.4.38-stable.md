* 已在 [#106046](https://github.com/ClickHouse/ClickHouse/issues/106046) 中回移：设置 `show_data_lake_catalogs_in_system_tables` 已重命名为 `show_remote_databases_in_system_tables`，并扩大了适用范围：当其值为 0 (默认值) 时，除数据湖目录外，`MySQL` 和 `PostgreSQL` 数据库也会在 `system.tables`、`system.columns` 和 `system.completions` 中被隐藏。旧设置名保留为别名。[#104416](https://github.com/ClickHouse/ClickHouse/pull/104416) ([Pablo Marcos](https://github.com/pamarcos)) 。

  #### 改进

* 已在 [#106583](https://github.com/ClickHouse/ClickHouse/issues/106583) 中回移：修复了在主键列上带有 `IN` 子查询的 `PREWHERE` 未使用主键索引进行粒度剪枝的问题，否则会导致执行全表扫描，而不是仅读取相关粒度。 [#102570](https://github.com/ClickHouse/ClickHouse/pull/102570) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 已在 [#105242](https://github.com/ClickHouse/ClickHouse/issues/105242) 中回移：将异步指标 `HTTPConnectionPool*TCP{Rcv,Snd}BufBytes_{p50,p75,p90,p95}` 替换为 `system.histogram_metrics` 中基于桶的直方图 `http_pool_tcp_buf_bytes` (标记为 `group`、`direction`) 。按组汇总的异步指标仍予以保留。 [#103704](https://github.com/ClickHouse/ClickHouse/pull/103704) ([Sema Checherinda](https://github.com/CheSema)).

* 已在 [#105366](https://github.com/ClickHouse/ClickHouse/issues/105366) 中回移：修复在右表中每个键对应多行、且输出块因大小限制被拆分时，`RIGHT ANY JOIN` 返回错误结果的问题。关闭 [#99431](https://github.com/ClickHouse/ClickHouse/issues/99431)。[#102064](https://github.com/ClickHouse/ClickHouse/pull/102064) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 已在 [#105358](https://github.com/ClickHouse/ClickHouse/issues/105358) 中回移：在 Avro reader 对 Nested 类型进行反序列化时检查 stack overflow。[#102417](https://github.com/ClickHouse/ClickHouse/pull/102417) ([Pavel Kruglov](https://github.com/Avogar)).
* 已在 [#105512](https://github.com/ClickHouse/ClickHouse/issues/105512) 中回移：当客户端提供的 Native 格式数据被截断或格式不正确时，抛出 `INCORRECT_DATA` 而不是 `LOGICAL_ERROR`。[#102975](https://github.com/ClickHouse/ClickHouse/pull/102975) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 已在 [#105409](https://github.com/ClickHouse/ClickHouse/issues/105409) 中回移：修复 `StorageObjectStorageQueue` (`S3Queue`, `AzureQueue`) 在部分已处理文件尚未从对象存储完整读取前阻塞关闭的问题。现在该 source 会在关闭时立即中止读取；去重可确保在关闭前已流式传输到目标表的行，在下次启动重试该文件时不会重复写入。[#103126](https://github.com/ClickHouse/ClickHouse/pull/103126) ([Tuan Pham Anh](https://github.com/tuanpach)).
* 已在 [#105804](https://github.com/ClickHouse/ClickHouse/issues/105804) 中回移：修复通过 `INSERT INTO FUNCTION hdfs(...)` 向 HDFS 写入 Parquet (以及其他带尾部的格式，如 ORC 和 Arrow) 时发生的数据损坏问题。自 26.1 起，`WriteBufferFromHDFS` 在 `finalize()` 时不会 flush 其工作缓冲区，因此每个文件末尾最多 `DBMS_DEFAULT_BUFFER_SIZE` 字节会被静默丢失，其中包括 Parquet 的 `PAR1` footer。读取此类文件时会返回 `Not a Parquet file (wrong magic bytes at the end of file)`。[#103268](https://github.com/ClickHouse/ClickHouse/pull/103268) ([Groene AI](https://github.com/groeneai)).
* 已在 [#106284](https://github.com/ClickHouse/ClickHouse/issues/106284) 中回移：修复 deltaLakeAzure 解析 URL 编码路径时的问题。[#103525](https://github.com/ClickHouse/ClickHouse/pull/103525) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 已在 [#105426](https://github.com/ClickHouse/ClickHouse/issues/105426) 中回移：在启用 **并行副本** 和 analyzer、且不使用查询计划序列化时，禁用 **`additional_table_filters`**。**此前这可能导致错误结果**。[#104296](https://github.com/ClickHouse/ClickHouse/pull/104296) ([Azat Khuzhin](https://github.com/azat)).
* 已在 [#106242](https://github.com/ClickHouse/ClickHouse/issues/106242) 中回移：修复在执行 `ALTER TABLE ... DROP PARTITION ID 'patch-...'` 后再执行 `DETACH`/`ATTACH TABLE` 时损坏的 patch part。此前，空的 covering part 在写入时缺少 `partition.dat` 和 `source_parts.dat`，导致在下次 attach 或 server 重启后，`system.detached_parts` 中出现 `broken-on-start_patch-...` 条目。关闭 [#93132](https://github.com/ClickHouse/ClickHouse/issues/93132)。关闭 [#102103](https://github.com/ClickHouse/ClickHouse/issues/102103)。[#104353](https://github.com/ClickHouse/ClickHouse/pull/104353) ([Groene AI](https://github.com/groeneai)).
* 已在 [#105753](https://github.com/ClickHouse/ClickHouse/issues/105753) 中回移：`LEFT ANTI JOIN` 现在会为不匹配的行正确返回右侧连接键列的默认值，而不再重复左侧键值。此前，`SELECT a.x AS l, b.x AS r FROM a LEFT ANTI JOIN b ON a.x = b.x` 对于不匹配的行可能返回 `r = a.x`，而正确结果应为默认值 (`Int32` 为 `0`，`String` 为 `''`，`Nullable` 为 `NULL`) 。只有连接键列受此问题影响；非键右侧列此前就已能正确返回默认值。优化器交换两侧时，`RIGHT ANTI JOIN` 也会出现同样的 bug。关闭 [#99959](https://github.com/ClickHouse/ClickHouse/issues/99959)。[#105278](https://github.com/ClickHouse/ClickHouse/pull/105278) ([Groene AI](https://github.com/groeneai)).
* 已在 [#105665](https://github.com/ClickHouse/ClickHouse/issues/105665) 中回移：对 `catalog_type = 'glue'` 的 `DataLakeCatalog` database 执行长时间运行的 `INSERT ... SELECT` 以及其他读取操作时，一旦加载表 metadata 时获取的 STS session credentials 超过有效期，就会失败并报出 `Code: 117. DB::Exception: IOError: Code: 499. DB::Exception: Unable to parse ExceptionName: ExpiredToken Message: The provided token has expired. (S3_ERROR) ... While executing ParquetBlockInputFormat: While executing ReadFromObjectStorage. (INCORRECT_DATA)`。[#105381](https://github.com/ClickHouse/ClickHouse/pull/105381) ([Pratima Patel](https://github.com/pratimapatel2008)).
* 已在 [#105979](https://github.com/ClickHouse/ClickHouse/issues/105979) 中回移：修复了以下问题：当带有 `TYPE set(N)` 跳过索引的 `SELECT` 包含一个结果类型为 `Float`、`BFloat16` 或其他任意非整数类型的 `WHERE` 原子条件时，会抛出 `BAD_ARGUMENTS` 异常 &quot;It&#39;s a bug! Only integer types are supported by `__bitWrapperFunc`&quot; (例如 `WHERE c0 + 0.1` 或 `WHERE log(c0)`) 。在这种情况下，跳过索引现在会回退到常规过滤路径。[#105384](https://github.com/ClickHouse/ClickHouse/pull/105384) ([Groene AI](https://github.com/groeneai)).
* 已在 [#105621](https://github.com/ClickHouse/ClickHouse/issues/105621) 中回移：修复了读取 Arrow 或 ArrowStream 文件时的问题：binary 或字符串列中损坏的中间 offsets 会导致 heap-buffer-overflow，而读取带有地理标签的 Arrow 列时会发生空指针解引用。[#105449](https://github.com/ClickHouse/ClickHouse/pull/105449) ([Raúl Marín](https://github.com/Algunenano)).
