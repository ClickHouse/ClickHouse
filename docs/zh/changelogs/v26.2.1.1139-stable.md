<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 改进了统计信息的存储格式。现在所有统计信息都存储在单个文件中。[#93414](https://github.com/ClickHouse/ClickHouse/pull/93414) ([Anton Popov](https://github.com/CurtizJ)).
* 限制了 S3(Azure)Queue 的内存元数据。系统表已从 `azure_queue` 重命名为 `azure_queue_metadata_cache`，并将 `system.s3queue` 重命名为 `s3queue_metadata_cache`。[#95809](https://github.com/ClickHouse/ClickHouse/pull/95809) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 修复了 `Variant` 类型不匹配时的逻辑错误。[#95811](https://github.com/ClickHouse/ClickHouse/pull/95811) ([Bharat Nallan](https://github.com/bharatnc)).
* 破坏性变更：此次更改后，默认会对所有插入开启去重。此前，异步插入和 MV 默认关闭去重，而同步插入默认开启。此举的目的是让两种插入方式使用相同的默认值。如果你的 cluster 上显式禁用了去重，则必须显式设置 `deduplicate_insert='backward_compatible_choice'` 以保留旧行为。`deduplicate_blocks_in_dependent_materialized_views` 也是如此。[#95970](https://github.com/ClickHouse/ClickHouse/pull/95970) ([Sema Checherinda](https://github.com/CheSema)).
* 来自 PostgreSQL 的 `DATE` 列现在会在 ClickHouse 中推断为 `Date32` (在此前版本中会被推断为 `Date`，这会导致超出较小范围的值发生 overflow) 。现已支持将 `Date32` 值再写回 PostgreSQL。关闭 [#73084](https://github.com/ClickHouse/ClickHouse/issues/73084)。[#95999](https://github.com/ClickHouse/ClickHouse/pull/95999) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `do_not_merge_across_partitions_select_final` setting 的语义现在更明确了。此前，如果未在 config 中显式设置，该功能可能会被自动启用。这一行为多次引发困惑，并且遗憾的是在 production 中造成了一些问题。现在规则更简单了：`do_not_merge_across_partitions_select_final=1` 会无条件启用该功能。如果 `do_not_merge_across_partitions_select_final=0`，则仅当新的 setting `enable_automatic_decision_for_merging_across_partitions_for_final=1` 时才会使用自动模式，否则不使用。为了尽可能保留旧行为，默认值设为了 `do_not_merge_across_partitions_select_final=0` 和 `enable_automatic_decision_for_merging_across_partitions_for_final=1`。[#96110](https://github.com/ClickHouse/ClickHouse/pull/96110) ([Nikita Taranov](https://github.com/nickitat)).
* 添加了 S3 schema 校验。此项更改关闭了 [#96089](https://github.com/ClickHouse/ClickHouse/issues/96089)。[#96194](https://github.com/ClickHouse/ClickHouse/pull/96194) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 禁止在 ORDER BY 和其他表键表达式中使用 subqueries。[#96847](https://github.com/ClickHouse/ClickHouse/pull/96847) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 默认启用 `apply_row_policy_after_final`。最初，当 `optimize_move_to_prewhere_if_final=0` 时，ROW POLICY 和 PREWHERE 都会遵循 FINAL，并在 FINAL 之后应用。这一行为被 [#87303](https://github.com/ClickHouse/ClickHouse/issues/87303) 破坏了：该变更在 ROW POLICY 过滤器上忽略了 `optimize_move_to_prewhere_if_final`。为修复此问题，此 PR 启用了在 [#91065](https://github.com/ClickHouse/ClickHouse/issues/91065) 中引入的 setting `apply_row_policy_after_final`。启用 `apply_row_policy_after_final` 后，ROW POLICY 将像之前一样默认继续遵循 FINAL。此 PR 是一项不兼容变更，因为它改变了 `optimize_move_to_prewhere_if_final=1` 时的行为。现在，如需让 ROW POLICY 在 FINAL 之前应用，应使用 `apply_row_policy_after_final`，而不是 `optimize_move_to_prewhere_if_final`。[#97279](https://github.com/ClickHouse/ClickHouse/pull/97279) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).



<div id="new-feature">
  #### 新特性
</div>

* 支持将基于时间的一次性密码用作身份验证方法。[#71273](https://github.com/ClickHouse/ClickHouse/pull/71273) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 支持将缓存中的数据文件和系统文件拆分为独立分段。[#87834](https://github.com/ClickHouse/ClickHouse/pull/87834) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* 新增用于 Parquet 元数据的 SLRU 缓存，无需仅为读取元数据而重新下载文件，从而提升读取性能。该缓存可通过 `SYSTEM DROP PARQUET METADATA CACHE` 清空。解决了 [#89102](https://github.com/ClickHouse/ClickHouse/issues/89102)。[#89750](https://github.com/ClickHouse/ClickHouse/pull/89750) ([Grant Holly](https://github.com/grantholly-clickhouse)).
* 新增系统表 `system.user_defined_functions`，用于监控 UDF 的加载状态和配置。[#90340](https://github.com/ClickHouse/ClickHouse/pull/90340) ([Xu Jia](https://github.com/XuJia0210)).
* 新增 default&#95;dictionary&#95;database 设置，使 ClickHouse 能够在指定的默认数据库中解析未显式指定数据库名的外部字典引用。这简化了从 XML 定义的全局字典迁移到 SQL 定义的按数据库划分字典的过程，使现有字典查询 (例如 dictGet(&#39;name&#39;, …)) 无需修改即可继续使用。[#91412](https://github.com/ClickHouse/ClickHouse/pull/91412) ([Dmitrii Plotnikov](https://github.com/dimbo4ka)).
* `DatabaseReplicated` 支持辅助 ZooKeeper。[#91683](https://github.com/ClickHouse/ClickHouse/pull/91683) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* 新增表函数 `primes` 和系统表 `system.primes`，其中包含按升序排列的质数。关闭了 [#90839](https://github.com/ClickHouse/ClickHouse/issues/90839)。[#92776](https://github.com/ClickHouse/ClickHouse/pull/92776) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 异步插入支持并行 quorum。插入的数据会复制到 quorum；如果发现重复项，查询会等待，直到此前插入的数据也完成复制。[#93356](https://github.com/ClickHouse/ClickHouse/pull/93356) ([Sema Checherinda](https://github.com/CheSema)).
* 新增函数 `colorOKLABToSRGB` 和 `colorSRGBToOKLAB`，用于在 sRGB 和 OKLAB 之间相互转换值。[#93361](https://github.com/ClickHouse/ClickHouse/pull/93361) ([Pranav Tiwari](https://github.com/pranavt84)).
* 新增 deduplicate&#95;insert，用于覆盖 insert&#95;deduplicate 和 async&#95;insert&#95;deduplicate。[#94413](https://github.com/ClickHouse/ClickHouse/pull/94413) ([Sema Checherinda](https://github.com/CheSema)).
* 允许某些函数在 SQL 中不带括号使用。关闭了 [#52102](https://github.com/ClickHouse/ClickHouse/issues/52102)。[#94678](https://github.com/ClickHouse/ClickHouse/pull/94678) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* 服务器设置 `insert_deduplication_version` 使迁移到统一的去重哈希成为可能。[#95409](https://github.com/ClickHouse/ClickHouse/pull/95409) ([Sema Checherinda](https://github.com/CheSema)).
* 新增配置选项：logger.startup&#95;console&#95;level 和 logger.shutdown&#95;console&#95;level，分别用于在 ClickHouse 启动和关闭期间覆盖控制台日志级别。[#95919](https://github.com/ClickHouse/ClickHouse/pull/95919) ([Garrett Thomas](https://github.com/garrettthomaskth)).
* 新增 xxh3&#95;128 哈希函数。[#96055](https://github.com/ClickHouse/ClickHouse/pull/96055) ([Raúl Marín](https://github.com/Algunenano)).
* 新增 `OPTIMIZE <table> DRY RUN PARTS <part names>` 查询，用于在不提交结果分片的情况下模拟合并。它可用于测试：验证新版本中的合并正确性、以确定性方式复现与合并相关的 bug，以及可靠地对合并性能进行基准测试。[#96122](https://github.com/ClickHouse/ClickHouse/pull/96122) ([Anton Popov](https://github.com/CurtizJ)).
* 新增一项默认启用的检查，可通过设置 `check_named_collection_dependencies` 避免删除被表使用的 named collections。[#96181](https://github.com/ClickHouse/ClickHouse/pull/96181) ([Pablo Marcos](https://github.com/pamarcos)).
* 新增 `lazy_load_tables` 数据库设置。启用后，表不会在数据库启动期间加载——系统会改为创建一个轻量级的 `StorageTableProxy`，并在首次访问时将真正的表引擎实体化。[#96283](https://github.com/ClickHouse/ClickHouse/pull/96283) ([xiaohuanlin](https://github.com/xiaohuanlin)).
* 用户现在可以直接从 ClickHouse 使用 ClickStack，这对调试和本地开发很有帮助。[#96597](https://github.com/ClickHouse/ClickHouse/pull/96597) ([Aaron Knudtson](https://github.com/knudtty)).
* 新增 `system.fail_points`，用于检查 server 中现有的 failpoints 及其是否启用。这将有助于实现测试自动化。[#96762](https://github.com/ClickHouse/ClickHouse/pull/96762) ([Pedro Ferreira](https://github.com/PedroTadim)).
* 新增 Google BigLake catalog integration。此项变更关闭了 [#95339](https://github.com/ClickHouse/ClickHouse/issues/95339)。[#97104](https://github.com/ClickHouse/ClickHouse/pull/97104) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 开始迁移去重哈希值。[#97562](https://github.com/ClickHouse/ClickHouse/pull/97562) ([Sema Checherinda](https://github.com/CheSema)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 通过为 ColumnVector::replicate 实现动态调度，加速部分哈希连接操作。[#79573](https://github.com/ClickHouse/ClickHouse/pull/79573) ([Raúl Marín](https://github.com/Algunenano))。
* 针对复杂谓词场景下的 ParallelHashJoin 进行性能提升。此前，未连接行的处理在单个线程中完成，效率欠佳；本次优化将未连接行的处理并行化，分散到多个线程执行。可通过 `parallel_non_joined_rows_processing` 设置开关，默认启用。[#92068](https://github.com/ClickHouse/ClickHouse/pull/92068) ([Yarik Briukhovetskyi](https://github.com/yariks5s))。
* 允许在主键中使用任意确定性表达式进行数据跳过（例如 `ORDER BY cityHash64(user_id)` / `ORDER BY length(user_id)`）。对于确定性表达式，ClickHouse 可将该表达式应用于查询常量，并将结果用于主键索引，以支持 `=`、`IN` 和 `has` 等谓词。若表达式同时具有单射性（例如 `ORDER BY hex(p)` 或 `ORDER BY reverse(tuple(reverse(p), hex(p)))`），则还可有效利用索引处理其否定形式：`!=`、`NOT IN` 和 `NOT has`。关闭 [#10685](https://github.com/ClickHouse/ClickHouse/issues/10685)。关闭 [#82161](https://github.com/ClickHouse/ClickHouse/issues/82161)。[#92952](https://github.com/ClickHouse/ClickHouse/pull/92952) ([Nihal Z. Miaji](https://github.com/nihalzp))。
* 小幅优化 JSON 类型的解析性能。[#93614](https://github.com/ClickHouse/ClickHouse/pull/93614) ([Pavel Kruglov](https://github.com/Avogar))。
* 通过从对象中移除 std::optional<TokenIterator> begin/end，降低 ASTLiteral 的内存占用。在不使用语法高亮且无 VALUES 解析的场景下，这些字段本不会被用到，因此该优化具有实际意义。[#93974](https://github.com/ClickHouse/ClickHouse/pull/93974) ([Ilya Yatsishin](https://github.com/qoega))。
* 优化具名 Tuple AST 对象的内存消耗。将列名以字符串形式直接存储在 Tuple 对象中，而非保留在通用 AST 字面量节点中。[#94704](https://github.com/ClickHouse/ClickHouse/pull/94704) ([Ilya Yatsishin](https://github.com/qoega))。
* 通过额外的链接器选项改进了去虚拟化效果。[#94737](https://github.com/ClickHouse/ClickHouse/pull/94737) ([Nikita Taranov](https://github.com/nickitat))。
* 通过批量处理 ZooKeeper 请求，提升含大量 parts 的 ReplicatedMergeTree 表的副本克隆性能。[#94847](https://github.com/ClickHouse/ClickHouse/pull/94847) ([c-end](https://github.com/c-end))。
* 若 `FINAL` 查询先使用主键条件进行过滤，再对其他条件使用跳过索引，则 `PrimaryKeyExpand` 处理步骤现在仅对初始筛选出的主键范围进行交集检查。[#94903](https://github.com/ClickHouse/ClickHouse/pull/94903) ([Shankar Iyer](https://github.com/shankar-iyer))。
* 将 std::vector 的创建移至 `for` 循环外部并提前分配内存，避免每次迭代时重复分配。[#95178](https://github.com/ClickHouse/ClickHouse/pull/95178) ([Alexey Bakharew](https://github.com/alexbakharew))。
* 当读取步骤已存在 PREWHERE 过滤器时，无法再添加新的过滤器。本次变更将 PREWHERE 优化推迟到 JOIN 运行时过滤器优化之后执行，从而使运行时过滤器也能被下推至 PREWHERE。[#95838](https://github.com/ClickHouse/ClickHouse/pull/95838) ([Alexander Gololobov](https://github.com/davenger))。
* 通过在 x86 上使用动态调度，加速 T64 编解码器的压缩速度。[#95881](https://github.com/ClickHouse/ClickHouse/pull/95881) ([Raúl Marín](https://github.com/Algunenano))。
* 在满足条件时（非 null、非 -If、无 GROUP BY、无 IPv6 或 String 类型），通过批量插入加速数值类型上的 `uniq` 操作。[#95904](https://github.com/ClickHouse/ClickHouse/pull/95904) ([Raúl Marín](https://github.com/Algunenano))。
* 经分析，`ZooKeeper::observeOperations` 占 ZooKeeper 接收线程 CPU 消耗的 20% 以上。本次变更通过以下方式加以改善：1. 对于 `AggregatedZooKeeperLog::stats`，使用 `CityHash64` 替代 `SipHash`，速度提升超过 10 倍；2. 对于 `Coordination::ErrorCounter`，使用 `std::array<std::atomic<UInt32>, N>` 替代 `std::unordered_map` 和 `std::mutex`。[#95962](https://github.com/ClickHouse/ClickHouse/pull/95962) ([Miсhael Stetsyuk](https://github.com/mstetsyuk))。
* 回退 ProfileEvents::Counter 的 64 字节对齐设置。[#96097](https://github.com/ClickHouse/ClickHouse/pull/96097) ([Azat Khuzhin](https://github.com/azat))。
* 将 CachedOnDiskReadBufferFromFile 结构体的大小缩减至原来的 1/50。[#96098](https://github.com/ClickHouse/ClickHouse/pull/96098) ([Azat Khuzhin](https://github.com/azat))。
* HashTable::resize 时，若旧数据为空则跳过复制操作。[#96180](https://github.com/ClickHouse/ClickHouse/pull/96180) ([Raúl Marín](https://github.com/Algunenano))。
* 为 `RIGHT OUTER` JOIN 添加运行时过滤器支持。[#96183](https://github.com/ClickHouse/ClickHouse/pull/96183) ([Hechem Selmi](https://github.com/m-selmi))。
* 此前，文本索引直接读取优化仅在所有 parts 均具有 materialized 文本索引时才会生效。本次变更新增部分支持：若部分 parts 具有 materialized 文本索引，这些 parts 将使用该索引，而不具有 materialized 文本索引的 parts 则回退到执行原始过滤器表达式。[#96411](https://github.com/ClickHouse/ClickHouse/pull/96411) ([Anton Popov](https://github.com/CurtizJ))。
* 避免在未启用去重时，INSERT 操作出现内存用量回退的问题。[#96503](https://github.com/ClickHouse/ClickHouse/pull/96503) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 在支持足够精度 `long double` 的平台上，避免在 `wide_integer_impl.h` 中引入 boost/multiprecision 头文件，从而缩短构建时间。TODO: 若性能无变化，请将分类改为 BUILD。[#96633](https://github.com/ClickHouse/ClickHouse/pull/96633) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 已在 [#97942](https://github.com/ClickHouse/ClickHouse/issues/97942) 中回移：通常情况下，去重需要保留原始块，但对于同步插入，可以省略该块以节省内存。[#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema))。
* 为系统日志表的时间列添加了 `minmax` 二级索引，并为 `query_id`/`initial_query_id` 列添加了 `bloom_filter` 索引，以加快筛选速度。[#96712](https://github.com/ClickHouse/ClickHouse/pull/96712) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* LZ4：加速 x86 上 32 字节块的解压速度。[#96778](https://github.com/ClickHouse/ClickHouse/pull/96778) ([Raúl Marín](https://github.com/Algunenano))。
* 延迟物化优化现已应用于 `UNION ALL` 查询的所有分支，而不仅限于第一个分支。通过 `UNION ALL` 组合多个来自不同 `MergeTree` 表的有序限制读取的查询，现在每个分支都能受益于延迟列读取，从而减少 I/O 开销。[#96832](https://github.com/ClickHouse/ClickHouse/pull/96832) ([Federico Ginosa](https://github.com/menxit))。
* 通过移除不必要的数据复制并为数值列启用向量化 min/max 计算，优化 INSERT 期间 minmax 跳过索引的计算效率。[#97392](https://github.com/ClickHouse/ClickHouse/pull/97392) ([Raúl Marín](https://github.com/Algunenano))。
* 已在 [#98184](https://github.com/ClickHouse/ClickHouse/issues/98184) 中回移：提升了针对同时涉及已索引列与未索引列的组合条件查询的文本索引分析性能。此前，在此类情况下，索引分析过程中的提前退出优化被错误地禁用。[#98096](https://github.com/ClickHouse/ClickHouse/pull/98096) ([Anton Popov](https://github.com/CurtizJ))。
