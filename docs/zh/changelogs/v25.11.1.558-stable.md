<div id="backward-incompatible-change">
  #### 向后不兼容变更
</div>

* 引入 `Geometry` 类型。支持读取其 `WKB` 和 `WKT` 格式。在此前版本中，`Geometry` 类型是 `String` 的别名，但现在它已成为功能完备的类型。[#83344](https://github.com/ClickHouse/ClickHouse/pull/83344) ([scanhex12](https://github.com/scanhex12)).
* 移除已弃用的 Object 类型。[#85718](https://github.com/ClickHouse/ClickHouse/pull/85718) ([Pavel Kruglov](https://github.com/Avogar)).
* 对 MergeTree 表的 Wide 数据分区片段中为 Variant 类型 subcolumns 创建的文件名进行转义。此更改会破坏旧表中 Variant/Dynamic/JSON 数据类型的兼容性。它修复了在 Variant 中存储包含特殊符号的类型时的问题 (例如带有特定 timezone 且包含 `\` 的 DateTime) 。可以通过修改 MergeTree setting `escape_variant_subcolumn_filenames` 来禁用转义 (若要保持兼容性，请在 MergeTree 的 config 中禁用此 setting，或在 upgrade 前将 `compatibility` setting 设为之前的版本) 。解决了 [#69590](https://github.com/ClickHouse/ClickHouse/issues/69590)。[#87300](https://github.com/ClickHouse/ClickHouse/pull/87300) ([Pavel Kruglov](https://github.com/Avogar)).
* 移除已废弃的 `LIVE VIEW` 功能。如果你使用了 `LIVE VIEW`，将无法升级到新版本。[#88706](https://github.com/ClickHouse/ClickHouse/pull/88706) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为 HTTP 响应结果支持异常标记，以便 clients 能更可靠地解析异常。解决了 [#75175](https://github.com/ClickHouse/ClickHouse/issues/75175)。为保持各 formats 之间的一致性，setting `http_write_exception_in_output_format` 默认处于禁用状态。[#88818](https://github.com/ClickHouse/ClickHouse/pull/88818) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* 禁止在共享 object storage 路径上创建多个 `plain-rewritable` disks，因为这可能会在不同 metadata storage 事务发生冲突时导致 undefined behavior。[#89038](https://github.com/ClickHouse/ClickHouse/pull/89038) ([Mikhail Artemenko](https://github.com/Michicosun)).
* 默认对 String 类型启用 with&#95;size&#95;stream serialization format。此更改向后兼容，但新的 serialization format 仅从 25.10 版本开始支持，这意味着将无法降级到 25.10 之前的版本。如果你希望保留降级到 25.9 及更早版本的可能性，请在 server configuration 的 merge&#95;tree 部分中将 serialization&#95;info&#95;version 配置为 basic，并将 string&#95;serialization&#95;version 配置为 single&#95;stream。[#89329](https://github.com/ClickHouse/ClickHouse/pull/89329) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复 Kafka storage SASL settings 的优先次序问题。现在，在 CREATE TABLE queries 中指定的表级 SASL settings 会正确覆盖 configuration files 中面向 consumer/producer 的 settings。[#89401](https://github.com/ClickHouse/ClickHouse/pull/89401) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 修复了在压缩数据时，如果大小未按元素大小对齐会出现 `Fatal` 的问题 (在 T64 codec 中) 。解决了 [#89282](https://github.com/ClickHouse/ClickHouse/issues/89282)。[#89432](https://github.com/ClickHouse/ClickHouse/pull/89432) ([yanglongwei](https://github.com/ylw510)).

<div id="new-feature">
  #### 新特性
</div>

* 新增 SQL 语句 EXECUTE AS，以支持用户身份模拟。解决了 [#39048](https://github.com/ClickHouse/ClickHouse/issues/39048)。[#70775](https://github.com/ClickHouse/ClickHouse/pull/70775) ([Shankar](https://github.com/shiyer7474)).
* 新增 `flipCoordinates` 函数，可展开数组中所需数量的维度，并交换 Tuple 列中的指针。解决了 [#79469](https://github.com/ClickHouse/ClickHouse/issues/79469)。[#79634](https://github.com/ClickHouse/ClickHouse/pull/79634) ([Sachin Kumar Singh](https://github.com/sachinkumarsingh092)).
* 新增 `system.unicode` 表，包含 Unicode 字符及其属性列表。关闭了 [#80055](https://github.com/ClickHouse/ClickHouse/issues/80055)。[#80857](https://github.com/ClickHouse/ClickHouse/pull/80857) ([wxybear](https://github.com/wxybear)).
* 支持部分 Prometheus HTTP Query API。要启用此功能，请在 configuration file 的 `<prometheus>` 部分中添加一条类型为 `query_api` 的规则。支持的 handlers 包括 `/api/v1/query_range` 和 `/api/v1/query`。[#86132](https://github.com/ClickHouse/ClickHouse/pull/86132) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 增强了 `IS NOT DISTINCT FROM` (`<=>`) 运算符：新增对反向 `IS DISTINCT FROM` 的支持，以及对不同类型但兼容的数值操作数的支持 (例如 `Nullable(UInt32)` 和 `Nullable(Int64)`) 。[#87581](https://github.com/ClickHouse/ClickHouse/pull/87581) ([yanglongwei](https://github.com/ylw510)).
* 新增 MergeTree setting `merge_max_dynamic_subcolumns_in_wide_part`，可在 merge 后限制 Wide part 中动态 subcolumns 的数量，而不受数据类型中指定参数的影响。[#87646](https://github.com/ClickHouse/ClickHouse/pull/87646) ([Pavel Kruglov](https://github.com/Avogar)).
* 新增对 `cume_dist` window function 的支持。修复了 [#86920](https://github.com/ClickHouse/ClickHouse/issues/86920)。[#88102](https://github.com/ClickHouse/ClickHouse/pull/88102) ([Manuel](https://github.com/raimannma)).
* 用户现在可以在 text index 构建中添加新的 argument `preprocessor`。该 argument 是一个任意 expression，会在 tokenization 之前转换每个文档。[#88272](https://github.com/ClickHouse/ClickHouse/pull/88272) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* 向 `X-ClickHouse-Progress` 和 `X-ClickHouse-Summary` 新增 `memory_usage` 字段。这可用于在客户端实时收集查询的 memory usage。[#88393](https://github.com/ClickHouse/ClickHouse/pull/88393) ([Christoph Wurm](https://github.com/cwurm)).
* 新增对小数 `LIMIT` 和 `OFFSET` 的支持，可用于选择表的一部分数据。关闭了 [#81892](https://github.com/ClickHouse/ClickHouse/issues/81892)。[#88755](https://github.com/ClickHouse/ClickHouse/pull/88755) ([Ahmed Gouda](https://github.com/0xgouda)).
* 新增 setting into&#95;outfile&#95;create&#95;parent&#95;directories，可自动为 INTO OUTFILE 创建父目录，避免输出路径不存在时出错。这简化了将查询结果写入嵌套 directories 的 workflow。解决了 [#88610](https://github.com/ClickHouse/ClickHouse/issues/88610)。[#88795](https://github.com/ClickHouse/ClickHouse/pull/88795) ([Saksham](https://github.com/Saksham10-11)).
* 新增 Microsoft OneLake catalog integration。[#89366](https://github.com/ClickHouse/ClickHouse/pull/89366) ([scanhex12](https://github.com/scanhex12)).
* 支持 temporary tables 的 `CREATE OR REPLACE` 语法。关闭了 [#35888](https://github.com/ClickHouse/ClickHouse/issues/35888)。[#89450](https://github.com/ClickHouse/ClickHouse/pull/89450) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* 支持 `arrayRemove(arr, elem)`，用于从数组 `arr` 中删除所有等于 `elem` 的元素。解决了 [#52099](https://github.com/ClickHouse/ClickHouse/issues/52099)。[#89585](https://github.com/ClickHouse/ClickHouse/pull/89585) ([tiwarysaurav](https://github.com/tiwarysaurav)).
* 新增 `send_profile_events` 设置，使客户端可以在未使用 profile events 时减少网络流量。[#89588](https://github.com/ClickHouse/ClickHouse/pull/89588) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* 为 Kafka 表引擎新增 `kafka_schema_registry_skip_bytes` 设置，用于在解析消息载荷前跳过封装头字节 (例如 AWS Glue Schema Registry 的 19 字节前缀) 。这样 ClickHouse 就能够消费带有 schema registries 添加的元数据请求头的消息。[#89621](https://github.com/ClickHouse/ClickHouse/pull/89621) ([Taras Polishchuk](https://github.com/wake-up-neo)).
* 允许按查询禁用邻近分片数据的后台下载。修复了 [#89524](https://github.com/ClickHouse/ClickHouse/issues/89524)。[#89668](https://github.com/ClickHouse/ClickHouse/pull/89668) ([tanner-bruce](https://github.com/tanner-bruce)).
* 引入 `midpoint` 标量函数，用于计算平均值。解决了 [#89029](https://github.com/ClickHouse/ClickHouse/issues/89029)。[#89679](https://github.com/ClickHouse/ClickHouse/pull/89679) ([simonmichal](https://github.com/simonmichal)).
* Web UI 现已提供下载按钮。即使 UI 只显示部分结果，也会下载完整结果。[#89768](https://github.com/ClickHouse/ClickHouse/pull/89768) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增 `arrow_flight_request_descriptor_type` 设置，以支持需要命令式描述符的 Dremio 和其他 Arrow Flight server。修复了 [#89523](https://github.com/ClickHouse/ClickHouse/issues/89523)。[#89826](https://github.com/ClickHouse/ClickHouse/pull/89826) ([Shreyas Ganesh](https://github.com/shreyasganesh0)).
* 现在可以使用新的 `argAndMin` 和 `argAndMax` 函数，同时获取参数及其对应的最小值或最大值。[#89884](https://github.com/ClickHouse/ClickHouse/pull/89884) ([AbdAlRahman Gad](https://github.com/AbdAlRahmanGad)).
* 新增 `send_profile_events` 设置，使客户端可以在未使用 profile events 时减少网络流量。[#89972](https://github.com/ClickHouse/ClickHouse/pull/89972) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* Experimental 支持 e2k (Elbrus-2000) 作为 ClickHouse 的新平台。[#90159](https://github.com/ClickHouse/ClickHouse/pull/90159) ([Ramil Sattarov](https://github.com/r-a-sattarov)).

<div id="performance-improvement">
  #### 性能提升
</div>

* RIGHT 和 FULL JOIN 现在使用 ConcurrentHashJoin；这意味着这两类 JOIN 现在可以以更高的并行度运行。在多种 RIGHT 和 FULL JOIN 场景下，性能最高可提升 2 倍。解决了 [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027)。[#78462](https://github.com/ClickHouse/ClickHouse/pull/78462) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 针对 ConstantNode 中大值的优化。关闭了 [#72880](https://github.com/ClickHouse/ClickHouse/issues/72880)。[#81104](https://github.com/ClickHouse/ClickHouse/pull/81104) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* 对于具有 10K+ 个 parts 的表，在大量使用分区裁剪的情况下，`SELECT` 查询速度最高可提升 8 倍。[#85535](https://github.com/ClickHouse/ClickHouse/pull/85535) ([James Morrison](https://github.com/jawm)).
* 修复了 aarch64 以及其他一些可能的架构/内核组合上的 vsdo 问题。[#86096](https://github.com/ClickHouse/ClickHouse/pull/86096) ([Tomas Hulata](https://github.com/tombokombo)).
* 当查询对小整数进行 GROUP BY，并在聚合状态中使用固定哈希映射时，ClickHouse 会并行合并聚合状态以加速查询。解决了 [#63666](https://github.com/ClickHouse/ClickHouse/issues/63666)。[#87366](https://github.com/ClickHouse/ClickHouse/pull/87366) ([Jianfei Hu](https://github.com/incfly)).
* Distributed 执行：按行组 ID 而不是按文件拆分任务，效果更好。[#87508](https://github.com/ClickHouse/ClickHouse/pull/87508) ([scanhex12](https://github.com/scanhex12)).
* 通过简化代码并调整[选择算法](https://clickhouse.com/blog/lz4-compression-in-clickhouse#how-to-choose-the-best-algorithm)，提升了 LZ4 解压速度。[#88360](https://github.com/ClickHouse/ClickHouse/pull/88360) ([Raúl Marín](https://github.com/Algunenano)).
* S3 会基于键名前缀在内部对对象进行分区，并可针对每个分区的高请求速率自动扩展。此次变更引入了两个新的 BACKUP 设置：data&#95;file&#95;name&#95;generator 和 data&#95;file&#95;name&#95;prefix&#95;length。当 data&#95;file&#95;name&#95;generator=checksum 时，备份数据文件会使用其内容的哈希值命名。示例：对于 checksum = `abcd1234ef567890abcd1234ef567890` 且 `data_file_name_prefix_length = 3`，生成的路径将为：`abc/d1234ef567890abcd1234ef567890`。这种键分布可增强 S3 各分区间的负载均衡，并降低发生限流的风险。[#88418](https://github.com/ClickHouse/ClickHouse/pull/88418) ([Julia Kartseva](https://github.com/jkartseva)).
* 在 JOIN 和 ARRAY JOIN 中实现惰性列复制。在某些输出格式中，避免将 Sparse 和 Replicated 等特殊列表示转换为普通列。这可避免内存中不必要的数据拷贝。[#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar)).
* 通过缓存字典块，并使用哈希表而非二分查找进行令牌查找，提升了文本索引性能。[#88786](https://github.com/ClickHouse/ClickHouse/pull/88786) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Parquet reader v3 默认已启用。[#88827](https://github.com/ClickHouse/ClickHouse/pull/88827) ([Michael Kolupaev](https://github.com/al13n321)).
* 查询现在可以同时受益于 optimize&#95;read&#95;in&#95;order 和 query&#95;plan&#95;optimize&#95;lazy&#95;materialization。解决了 [#88767](https://github.com/ClickHouse/ClickHouse/issues/88767)。[#88866](https://github.com/ClickHouse/ClickHouse/pull/88866) ([Manuel](https://github.com/raimannma)).
* 对带有 `DISTINCT` 的查询使用 aggregate projection。关闭 [#86925](https://github.com/ClickHouse/ClickHouse/issues/86925)。[#88894](https://github.com/ClickHouse/ClickHouse/pull/88894) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 由于倒排列表在数据体量中占比最大，对其进行缓存可提升连续执行时的性能。[#88912](https://github.com/ClickHouse/ClickHouse/pull/88912) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 当输入排序顺序与 LIMIT BY 键一致时，运行流式 LIMIT BY 转换。[#88969](https://github.com/ClickHouse/ClickHouse/pull/88969) ([Eduard Karacharov](https://github.com/korowa)).
* 默认在非 server 二进制文件中禁用 ThreadFuzzer。[#89115](https://github.com/ClickHouse/ClickHouse/pull/89115) ([Raúl Marín](https://github.com/Algunenano)).
* 在某些情况下，允许将 ANY LEFT JOIN 或 ANY RIGHT JOIN 重写为 ALL INNER JOIN。[#89403](https://github.com/ClickHouse/ClickHouse/pull/89403) ([Dmitry Novik](https://github.com/novikd)).
* 减少异步日志中每个条目的原子操作次数。[#89651](https://github.com/ClickHouse/ClickHouse/pull/89651) ([Sergei Trifonov](https://github.com/serxa)).
* 当在包含多个 JOIN 的查询中启用运行时过滤器，且添加了多个运行时过滤器时，需要将新添加的过滤器步骤下推到其他 BuildRuntimeFilterStep 之上。[#89725](https://github.com/ClickHouse/ClickHouse/pull/89725) ([Alexander Gololobov](https://github.com/davenger)).
* 通过减少 HashSetTable::merge 的额外开销，略微加快某些 countDistinct 操作。[#89727](https://github.com/ClickHouse/ClickHouse/pull/89727) ([Raúl Marín](https://github.com/Algunenano)).
* RIGHT 和 FULL JOIN 现在使用 ConcurrentHashJoin；这意味着这些 JOIN 类型现在会以更高的并行度运行。在多种 RIGHT 和 FULL JOIN 场景下，性能提升最高可达 2 倍。解决 [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027)。[#89737](https://github.com/ClickHouse/ClickHouse/pull/89737) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 将延迟物化的行数上限从 10 提高到 100。[#89772](https://github.com/ClickHouse/ClickHouse/pull/89772) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
