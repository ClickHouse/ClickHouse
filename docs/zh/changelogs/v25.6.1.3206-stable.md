<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 次要：强制将 backup&#95;threads 和 restore&#95;threads 服务器级设置设为非零值。[#80224](https://github.com/ClickHouse/ClickHouse/pull/80224) ([Raúl Marín](https://github.com/Algunenano))。

* 已在 [#82079](https://github.com/ClickHouse/ClickHouse/issues/82079) 中回移：此前，即使 pattern 接受空匹配，函数 `countMatches` 也会在首次空匹配时停止计数。为解决此问题，`countMatches` 现在会在发生空匹配时向前推进一个字符后继续执行。想要保留旧行为的用户可以启用设置 `count_matches_stop_at_empty_match`。[#81676](https://github.com/ClickHouse/ClickHouse/pull/81676) ([Elmi Ahmadov](https://github.com/ahmadov))。

<div id="performance-improvement">
  #### 性能提升
</div>

* 现有的 `Pipe::resize` 实现会在管道拓扑中插入一个 `Resize` 或 `StrictResize` 节点，并由此创建单个此类节点；该节点随后充当中心枢纽，将所有输入流 (上游节点) 连接到一组统一的输出流 (下游节点) 。这种设计会在管道图执行期间造成对 ` ExecutingGraph::Node::status_mutex` 的争用，在高核数环境中尤为明显。当管道扩展到数十甚至数百个流时，这种争用会导致：[#77562](https://github.com/ClickHouse/ClickHouse/pull/77562) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 已在 [#81959](https://github.com/ClickHouse/ClickHouse/issues/81959) 中回移：新增一个选项，可将块的 (解) 压缩和 (反) 序列化卸载到管道线程中，而不是交由与网络连接关联的单个线程处理。由设置 `enable_parallel_blocks_marshalling` 控制。这应当可以加速在发起节点与远程节点之间传输大量数据的分布式查询。[#78694](https://github.com/ClickHouse/ClickHouse/pull/78694) ([Nikita Taranov](https://github.com/nickitat)).
* 将 DELETE FROM ... WHERE 1 查询替换为 TRUNCATE。 (已回退) 。[#78739](https://github.com/ClickHouse/ClickHouse/pull/78739) ([scanhex12](https://github.com/scanhex12)).
* 提升所有布隆过滤器类型的性能。[#79800](https://github.com/ClickHouse/ClickHouse/pull/79800) ([Delyan Kratunov](https://github.com/dkratunov)).
* 在 `UniqExactSet::merge` 中引入了一条快速路径：当其中一个集合为空时可直接处理。另外，如果 LHS 集合是两级的而 RHS 是单级的，现在不会再将 RHS 转换为两级。[#79971](https://github.com/ClickHouse/ClickHouse/pull/79971) ([Nikita Taranov](https://github.com/nickitat)).
* 默认启用异步日志。你可以通过在 `<logger>` 下设置 `<async>false</async>` 来禁用它。[#80125](https://github.com/ClickHouse/ClickHouse/pull/80125) ([Raúl Marín](https://github.com/Algunenano)).
* 在使用 twolevel 哈希表时，提高内存复用效率并减少缺页错误。[#80245](https://github.com/ClickHouse/ClickHouse/pull/80245) ([Jiebin Sun](https://github.com/jiebinn)).
* 避免 QueryConditionCache 中不必要的更新，并减少锁争用。[#80247](https://github.com/ClickHouse/ClickHouse/pull/80247) ([Jiebin Sun](https://github.com/jiebinn)).
* 对 `concatenateBlocks` 做了一个小优化。也许对并行 hash join 有帮助。[#80328](https://github.com/ClickHouse/ClickHouse/pull/80328) ([李扬](https://github.com/taiyang-li)).
* 从主键范围中选择 mark ranges 时，如果主键被函数包装，就无法使用二分查找。这个 PR 改进了这一限制：当主键被始终单调的函数链包装时，或者当 RPN 包含一个始终为真的元素时，仍然可以使用二分查找。该 PR 关闭了 [#45536](https://github.com/ClickHouse/ClickHouse/issues/45536)。[#80597](https://github.com/ClickHouse/ClickHouse/pull/80597) ([zoomxi](https://github.com/zoomxi)).
* 提升 Kafka 引擎的关闭速度 (在存在多个 Kafka 表时移除额外的 3 秒延迟) 。[#80796](https://github.com/ClickHouse/ClickHouse/pull/80796) ([Azat Khuzhin](https://github.com/azat)).
* Async insert：降低内存使用并提升 insert 查询性能。[#80972](https://github.com/ClickHouse/ClickHouse/pull/80972) ([Raúl Marín](https://github.com/Algunenano)).
* 如果日志表被禁用，则不要对处理器做 profile。[#81256](https://github.com/ClickHouse/ClickHouse/pull/81256) ([Raúl Marín](https://github.com/Algunenano)).
* 当源值恰好就是所需内容时，加速 toFixedString。[#81257](https://github.com/ClickHouse/ClickHouse/pull/81257) ([Raúl Marín](https://github.com/Algunenano)).
* 如果用户未受限制，则不要处理配额值。[#81549](https://github.com/ClickHouse/ClickHouse/pull/81549) ([Raúl Marín](https://github.com/Algunenano)).
* 将 ProcfsMetricsProvider 设为 thread&#95;local，以便在各任务之间保持文件打开。[#81576](https://github.com/ClickHouse/ClickHouse/pull/81576) ([Raúl Marín](https://github.com/Algunenano)).
* 修复了内存跟踪中的性能下降问题。[#81694](https://github.com/ClickHouse/ClickHouse/pull/81694) ([Michael Kolupaev](https://github.com/al13n321)).





<div id="improvement">
  #### 改进
</div>

* `EXPLAIN SYNTAX` 现在使用新的 analyzer。它返回基于查询树构建的 AST。新增选项 `query_tree_passes`，用于控制在将查询树转换为 AST 之前执行的 passes 次数。[#74536](https://github.com/ClickHouse/ClickHouse/pull/74536) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 默认在文件系统缓存中使用 SLRU cache policy。[#75072](https://github.com/ClickHouse/ClickHouse/pull/75072) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 在出现 `AuthenticationRequired` 错误后刷新 S3 凭证。[#77353](https://github.com/ClickHouse/ClickHouse/pull/77353) ([Vitaly Baranov](https://github.com/vitlibar)).
* 向 `system.asynchronous_metrics` 添加了字典指标：`DictionaryMaxUpdateDelay` - 字典更新的最大延迟 (秒) 。 - `DictionaryTotalFailedUpdates` - 自上次成功加载以来，所有字典中的错误总数。[#78175](https://github.com/ClickHouse/ClickHouse/pull/78175) ([Vlad](https://github.com/codeworse)).
* 改进了分布式查询中的分片键优化。[#78452](https://github.com/ClickHouse/ClickHouse/pull/78452) ([fhw12345](https://github.com/fhw12345)).
* 为 StorageKafka2 实现了类似 Kafka rebalance 的逻辑，并使用 ClickHouse Keeper。对于每个副本，支持两种分区锁：永久锁和临时锁。副本会尽可能长时间持有永久锁；在任意时刻，单个副本上的永久锁数量都不会超过 `all_topic_partitions / active_replicas_count` (其中 `all_topic_partitions` 表示全部 partitions 的数量，`active_replicas_count` 表示活跃副本的数量) 。如果超过该值，副本就会释放一些 partitions。副本还会临时持有部分 partitions。单个副本上临时锁的最大数量会动态调整，以便其他副本有机会将部分 partitions 转为永久锁。在更新临时锁时，副本会先全部释放，再尝试重新获取其中一些锁。[#78726](https://github.com/ClickHouse/ClickHouse/pull/78726) ([Daria Fomina](https://github.com/sinfillo)).
* 添加了关于那些可能是为保存损坏表而创建的数据库的警告。[#78841](https://github.com/ClickHouse/ClickHouse/pull/78841) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 在 S3Queue 引擎中添加了 &#95;time 虚拟列。[#78926](https://github.com/ClickHouse/ClickHouse/pull/78926) ([Anton Ivashkin](https://github.com/ianton-ru)).
* 使控制在 CPU 过载时断开连接的设置支持热重载。[#79052](https://github.com/ClickHouse/ClickHouse/pull/79052) ([Alexey Katsman](https://github.com/alexkats)).
* 为 Azure Blob 存储中普通磁盘在 system.tables 里上报的数据路径添加容器前缀，使其与 S3 和 GCP 的上报保持一致。[#79241](https://github.com/ClickHouse/ClickHouse/pull/79241) ([Julia Kartseva](https://github.com/jkartseva)).
* 现在，ClickHouse 除了支持 `param_<name>` (下划线) 外，也支持将查询参数写成 `param-<name>` (短横线) 。这解决了 [#63093](https://github.com/ClickHouse/ClickHouse/issues/63093)。[#79429](https://github.com/ClickHouse/ClickHouse/pull/79429) ([Engel Danila](https://github.com/aaaengel)).
