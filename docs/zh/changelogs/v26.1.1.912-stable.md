  ### ClickHouse 发布版 v26.1.1.912-稳定版本 (4c47e680f55) FIXME，较 v26.1.1.1-new (1f0c87b97de)
</div>

<div id="backward-incompatible-change">
  #### 不兼容变更
</div>

* 修复格式化器中因错误替换别名导致的格式不一致问题。关闭 [#82833](https://github.com/ClickHouse/ClickHouse/issues/82833)、[#82832](https://github.com/ClickHouse/ClickHouse/issues/82832)、[#68296](https://github.com/ClickHouse/ClickHouse/issues/68296)。此变更存在潜在的不兼容风险：当 analyzer 被禁用时，某些在 IN 子句中引用别名的 CREATE VIEW 查询将无法处理。为避免不兼容问题，请启用 analyzer (自 24.3 起默认启用) 。[#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 编解码器 `DEFLATE_QPL` 和 `ZSTD_QAT` 已被移除。建议用户在升级前将使用 `DEFLATE_QPL` 或 `ZSTD_QAT` 压缩的现有数据转换为其他编解码器。请注意，使用这些编解码器需要启用 `enable_deflate_qpl_codec` 和 `enable_zstd_qat_codec` 配置项。[#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze))。
* 通过在 `system.query_log.exception` 中启用 stderr 捕获，修复了 UDF 调试问题。此前，UDF 的 stderr 仅写入文件，不会暴露在查询日志中，导致调试无从进行。现在 stderr 默认触发异常，并在抛出前完整累积 (最多 1MB) ，因此完整的 Python 堆栈跟踪和错误信息将出现在 `system.query_log.exception` 中，便于有效地进行故障排查。[#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210))。
* `JOIN USING ()` 子句中的空列列表现在被视为语法错误。此前，该情况在查询执行时应报 `INVALID_JOIN_ON_EXPRESSION`，但在某些情况下 (例如与 `Join` 存储引擎进行连接时) 会导致 `LOGICAL_ERROR`，关闭 [#82502](https://github.com/ClickHouse/ClickHouse/issues/82502)。[#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir))。
* 默认启用 JSON 的高级共享数据功能。此变更后，将无法降级至 25.8 以下版本，因为这些版本无法读取包含 JSON 列的新 data parts。为确保安全升级，建议将 `compatibility` 配置项设置为上一版本，或将 MergeTree 配置项设置为 `dynamic_serialization_version='v2', object_serialization_version='v2'`。[#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar))。
* 默认对 JSON 类型中的 SKIP REGEXP 使用部分匹配。关闭 [#79250](https://github.com/ClickHouse/ClickHouse/issues/79250)。[#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar))。
* 回滚&quot;允许向简单别名列执行 INSERT&quot; (回滚 ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154)) 。该功能与自定义格式不兼容，且未通过配置项加以保护。[#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat))。
* 新增配置项：当数据湖目录无法访问对象存储时抛出错误。[#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12))。
* `Lazy` 数据库引擎已被移除，不再可用。关闭 [#91231](https://github.com/ClickHouse/ClickHouse/issues/91231)。[#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 移除 `metric_log` 的 `transposed_with_wide_view` 模式——该模式因存在缺陷而无法使用。现在无法再以此模式定义 `system.metric_log`。此变更部分回滚了 [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412)。[#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 工作负载的 CPU 调度现在默认采用抢占式模式。详见 `cpu_slot_preemption` 服务器配置项。[#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa))。
* 对索引文件名进行转义以防止 parts 损坏。此变更后，ClickHouse 将无法加载由旧版本创建的、名称中包含非 ASCII 字符的索引。如需处理此问题，可使用 MergeTree 配置项 `escape_index_filenames`。[#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano))。
* 格式配置项 `exact_rows_before_limit`、`rows_before_aggregation`、`cross_to_inner_join_rewrite`、`regexp_dict_allow_hyperscan`、`regexp_dict_flag_case_insensitive`、`regexp_dict_flag_dotall` 和 `dictionary_use_async_executor` 现已更改为常规 (非格式) 配置项。这是一项纯内部变更，不会对用户产生可见影响，但有一种例外情况 (概率较低) ：若您在 Iceberg、DeltaLake、Kafka、S3、S3Queue、Azure、Hive、RabbitMQ、Set、FileLog 或 NATS 表引擎定义中指定了上述任意配置项，则此前这些配置项会被忽略，现在此类定义将抛出错误。[#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze))。
* `joinGet/joinGetOrNull` 函数现在会对底层 Join 表强制执行 `SELECT` 特权检查。此变更后，执行 `joinGet('db.table', 'column', key)` 要求用户同时拥有 Join 表中键列和所查询属性列的 `SELECT` 特权。缺少相应特权的查询将以 `ACCESS_DENIED` 失败。迁移时，可使用 `GRANT SELECT ON db.join_table TO user` 授予完整的表访问权限，或使用 `GRANT SELECT(key_col, attr_col) ON db.join_table TO user` 授予列级访问权限。此变更影响所有依赖 `joinGet`/`joinGetOrNull` 且此前未显式配置 `SELECT` 授权的用户和应用程序。[#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir))。
* 对 `CREATE TABLE ... AS ...` 查询改为检查 `SHOW COLUMNS` 权限。此前检查的是 `SHOW TABLES`，对于此类权限检查而言授权不正确。[#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit))。





<div id="new-feature">
  #### 新特性
</div>

* 为 CH Keeper 提供 HTTP API 和嵌入式 Web UI。[#78181](https://github.com/ClickHouse/ClickHouse/pull/78181) ([pufit](https://github.com/pufit)).
* 在多个副本上支持分布式索引分析。这对共享存储和集群中的海量数据尤其有益。[#86786](https://github.com/ClickHouse/ClickHouse/pull/86786) ([Azat Khuzhin](https://github.com/azat)).
* 使用 `<interactive_history_legacy_keymap>true</interactive_history_legacy_keymap>` 时，命令行客户端现在可以像以前一样回退为使用 Ctrl R 进行普通搜索，而 Ctrl T 则执行模糊搜索。[#87785](https://github.com/ClickHouse/ClickHouse/pull/87785) ([Larry Snizek](https://github.com/larry-cdn77)).
* 异步 insert 去重现在可与依赖的 materialized views 配合使用。当发生 block&#95;id 冲突时，会过滤原始块以移除与该 block&#95;id 关联的行，并使用所有相关 materialized views 的 select 查询对剩余行进行转换，从而重建出不包含冲突行的原始块。[#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* 新增了 `clickhouse client` 在连接到服务器时覆盖 TLS SNI 的能力。[#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).
* 为数组列添加文本索引支持。[#89895](https://github.com/ClickHouse/ClickHouse/pull/89895) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* 新增系统表 zookeeper&#95;info。修复了 [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014)。[#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 实现 FunctionVariantAdaptor，以支持函数中的 Variant 类型。[#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* 在 Prometheus `/metrics` 端点新增 `ClickHouse_Info` 指标，主要包含版本信息，因此可以构建图表来跟踪详细版本信息随时间的变化。[#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* 为 keeper 引入了一个新的四字母命令 `rcfg`，可用于更改集群配置。与标准的 `reconfigure` 请求相比，该命令为配置变更提供了更广泛的能力。该命令接受 `json` 字符串作为参数。发送到 TCP 接口的完整字节序列应如下所示：`rcfg{json_string_length_big_endian}{json_string}`。该命令的一些示例如下：`{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`。[#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* 添加函数 `reverseBySeparator`，该函数会反转由指定分隔符分隔的字符串中各个子字符串的顺序。关闭 [#91463](https://github.com/ClickHouse/ClickHouse/issues/91463)。[#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* 引入了新的语法和框架，以简化并扩展 projection index 功能。这是对 https://github.com/ClickHouse/ClickHouse/pull/81021 的后续改进。[#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* 支持 paimon REST catalog，延续自 https://github.com/ClickHouse/ClickHouse/pull/84423。[#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* 新增设置 `max_insert_block_size_bytes`，可更细致地控制插入块的形成。[#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* 如果启用了 `ignore_on_cluster_for_replicated_database` 设置，则可以对 Replicated database 执行带有 `ON CLUSTER` 子句的 DDL queries。在这种情况下，集群名称将被忽略。[#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* 实现了 `mergeTreeAnalyzeIndex()` 函数。[#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* 新增设置 `use_primary_key`。将其设为 `false` 可禁用基于主键的粒度剪枝。[#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 新增 `icebergLocalCluster` 表函数。[#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Parquet reader v3 中的 Datalakes prewhere 和 multistage prewhere 修复了 [#89101](https://github.com/ClickHouse/ClickHouse/issues/89101)。[#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 新增 `cosineDistanceTransposed` 函数，用于近似计算两个点之间的[余弦距离](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance)。[#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* 先前用于清除缓存的语句 `SYSTEM DROP [...] CACHE` 容易让人误以为该语句会禁用缓存。ClickHouse 现已支持更直观的 `SYSTEM CLEAR [...] CACHE` 语句。旧语法仍然可用。[#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* 为 system.parts 表新增 files 列，用于显示每个数据分区片段中的文件数量。[#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* 新增用于并发控制的 max-min 公平调度器。在高过度订阅场景下 (即许多 queries 竞争有限的 CPU 插槽时) ，可提供更好的公平性。短时运行的查询不会因为长期运行且随时间累积了更多插槽的查询而受到不利影响。可通过将 `concurrent_threads_scheduler` server setting 设为 `max_min_fair` 启用。[#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 更多过滤条件可下推到 JOIN 中。[#85556](https://github.com/ClickHouse/ClickHouse/pull/85556) ([Nikita Taranov](https://github.com/nickitat)).
* 当 `partition by` 与排序键相同或是其前缀时，禁用窗口函数的排序顺序优化，以提升并行执行性能。[#87299](https://github.com/ClickHouse/ClickHouse/pull/87299) ([Nikita Taranov](https://github.com/nickitat)).
* 将外层过滤器下推到视图中，从而可以在本地和远程节点上应用 PREWHERE。解决了 [#88189](https://github.com/ClickHouse/ClickHouse/issues/88189)。[#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).
* 为更多函数实现 JIT 编译。关闭 [#73509](https://github.com/ClickHouse/ClickHouse/issues/73509)。[#88770](https://github.com/ClickHouse/ClickHouse/pull/88770) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 优化分数形式的 `LIMIT` 和 `OFFSET` 的性能与内存使用。[#91167](https://github.com/ClickHouse/ClickHouse/pull/91167) ([Ahmed Gouda](https://github.com/0xgouda)).
* 修复 Parquet Reader V3 Prefetcher 未使用更快随机读取逻辑的问题。关闭 [#90890](https://github.com/ClickHouse/ClickHouse/issues/90890)。[#91435](https://github.com/ClickHouse/ClickHouse/pull/91435) ([Arsen Muk](https://github.com/arsenmuk)).
* 提升 `icebergCluster` 的性能。关闭 [#91462](https://github.com/ClickHouse/ClickHouse/issues/91462)。[#91537](https://github.com/ClickHouse/ClickHouse/pull/91537) ([Yang Jiang](https://github.com/Ted-Jiang)).
* 对于常量过滤条件，不再按虚拟列进行过滤。[#91588](https://github.com/ClickHouse/ClickHouse/pull/91588) ([c-end](https://github.com/c-end)).
* 提升 `LowCardinality` 列上 `DISTINCT` 的性能。关闭 [#5917](https://github.com/ClickHouse/ClickHouse/issues/5917)。[#91639](https://github.com/ClickHouse/ClickHouse/pull/91639) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 优化 distinctJSONPaths 聚合函数，使其只从数据分区片段中读取 JSON 路径，而不是整个 JSON 列。[#92196](https://github.com/ClickHouse/ClickHouse/pull/92196) ([Pavel Kruglov](https://github.com/Avogar)).
* 通过启用自适应写入缓冲区，降低超宽表在 INSERT/merge 使用 wide parts 时的内存占用。为加密 disks 增加了自适应写入缓冲区支持。[#92250](https://github.com/ClickHouse/ClickHouse/pull/92250) ([Azat Khuzhin](https://github.com/azat)).
* 支持更多从 join ON 条件下推的场景，即过滤器仅使用一侧输入时。支持 `ANY`、`SEMI`、`ANTI` joins。[#92584](https://github.com/ClickHouse/ClickHouse/pull/92584) ([Dmitry Novik](https://github.com/novikd)).
* 允许使用等价 sets 为 `SEMI JOIN` 下推过滤器。关闭 [#85239](https://github.com/ClickHouse/ClickHouse/issues/85239)。[#92837](https://github.com/ClickHouse/ClickHouse/pull/92837) ([Dmitry Novik](https://github.com/novikd)).
* 通过减少在索引中搜索的标记数量，提升了使用 text index 和 `sparseGrams` 分词器的全文检索性能。[#93078](https://github.com/ClickHouse/ClickHouse/pull/93078) ([Anton Popov](https://github.com/CurtizJ)).
* 在查询管道内对数据进行分区时使用 “fastrange” (Daniel Lemire) 方法。这可以提升并行排序和 JOIN 的性能。[#93080](https://github.com/ClickHouse/ClickHouse/pull/93080) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对 `uniqExact` 进行了优化，适用于相同元素经常连续出现的场景。 [#93268](https://github.com/ClickHouse/ClickHouse/pull/93268) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对函数 `isValidASCII` 在正向结果场景下进行了优化，即输入值全部由 ASCII 字符组成时。 [#93347](https://github.com/ClickHouse/ClickHouse/pull/93347) ([Robert Schulze](https://github.com/rschu1ze)).
* 对函数 `isValidASCII` 在正向结果场景下进行了优化，即输入值全部由 ASCII 字符组成时。 [#93611](https://github.com/ClickHouse/ClickHouse/pull/93611) ([Robert Schulze](https://github.com/rschu1ze)).
* 当右侧为空时，跳过读取 hash join 的左侧。此前我们会持续读取左侧，直到遇到第一个非空块；而在存在大量筛选或聚合的情况下，这可能会带来很大的开销。 [#94062](https://github.com/ClickHouse/ClickHouse/pull/94062) ([Alexander Gololobov](https://github.com/davenger)).
* 读取顺序优化现在能够识别因 WHERE 条件而变为常量的 ORDER BY 列，从而实现高效的逆序读取。这让多租户查询 (例如 &#96;WHERE tenant=&#39;42&#39; ORDER BY tenant, event&#95;time DESC&#96;) 也能从中受益，现在可以使用 InReverseOrder，而无需再进行完整排序。&quot;. [#94103](https://github.com/ClickHouse/ClickHouse/pull/94103) ([matanper](https://github.com/matanper)).
* 引入了专用的 Enum AST 类，以字符串、整数对的形式存储值参数，而不再使用 ASTLiteral 子节点，从而优化内存占用。 [#94178](https://github.com/ClickHouse/ClickHouse/pull/94178) ([Ilya Yatsishin](https://github.com/qoega)).





<div id="improvement">
  #### 改进
</div>

* 支持在 StorageEmbeddedRocksDB 中使用多列作为主键。关闭 [#32819](https://github.com/ClickHouse/ClickHouse/issues/32819)。[#33917](https://github.com/ClickHouse/ClickHouse/pull/33917) ([usurai](https://github.com/usurai))。
* 阻止 `x-amz-server-side-encryption` 请求头被传播到 `HeadObject`、`UploadPart` 和 `CompleteMultipartUpload` S3 请求，因为这些请求不支持该请求头。[#64577](https://github.com/ClickHouse/ClickHouse/pull/64577) ([Francisco J. Jurado Moreno](https://github.com/Beetelbrox))。
* 为 `ALTER` 查询新增语法 `ALTER TABLE <table> ATTACH PART <part_name> FROM <directory_name>`。该语法允许从 `detached/` 目录的任意子目录中附加分片，适用于重新附加带有自定义前缀（如 `broken-on-start`、`unexpected` 等）的分片——这些分片可能是被误分离的，无需人工干预即可直接附加回来。此前，此类操作需要在文件系统上手动重命名目录。[#74816](https://github.com/ClickHouse/ClickHouse/pull/74816) ([Anton Popov](https://github.com/CurtizJ))。
* 在 S3Queue 的 ordered 模式中支持追踪 hive 分区。解决 [#71161](https://github.com/ClickHouse/ClickHouse/issues/71161)。[#81040](https://github.com/ClickHouse/ClickHouse/pull/81040) ([Anton Ivashkin](https://github.com/ianton-ru))。
* 优化文件系统缓存中的空间预留机制。`FileCache::collectCandidatesForEviction` 将在不持有独占锁的情况下执行。[#82764](https://github.com/ClickHouse/ClickHouse/pull/82764) ([Kseniia Sumarokova](https://github.com/kssenii))。
