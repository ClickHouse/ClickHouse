<div id="improvement">
  #### 改进
</div>

* 已在 [#90983](https://github.com/ClickHouse/ClickHouse/issues/90983) 中回移：由于 [https://github.com/ClickHouse/ClickHouse/pull/90311](https://github.com/ClickHouse/ClickHouse/pull/90311)，statistics 的格式已发生变化；如果存在旧格式的 statistics，服务器会崩溃。此 PR 会修复该崩溃，并在现有 statistics 使用旧版格式时抛出异常。为避免异常，应运行 `ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL` 以重新生成 statistics，从而修复该问题。[#90904](https://github.com/ClickHouse/ClickHouse/pull/90904) ([Han Fei](https://github.com/hanfei1991)).
* 已在 [#91193](https://github.com/ClickHouse/ClickHouse/issues/91193) 中回移：现在，当 HTTP 客户端连接达到 `hard_limit` 时，会抛出 `HTTP_CONNECTION_LIMIT_REACHED` 异常。对于 disk connections，该值设为 `20000`。[#91016](https://github.com/ClickHouse/ClickHouse/pull/91016) ([Sema Checherinda](https://github.com/CheSema)).
* 已在 [#91254](https://github.com/ClickHouse/ClickHouse/issues/91254) 中回移：修复了这样一个潜在问题：对于包含许多 subcolumns 的 JSON columns，在读取 column samples 时，会无条件使用线程池，从而可能导致线程池饥饿；现在会遵循 `merge_tree_use_prefixes_deserialization_thread_pool` 设置。[#91208](https://github.com/ClickHouse/ClickHouse/pull/91208) ([Raufs Dunamalijevs](https://github.com/rienath)).
