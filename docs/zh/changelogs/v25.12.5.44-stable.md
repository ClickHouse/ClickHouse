<div id="improvement">
  #### 改进
</div>

* 已在 [#94935](https://github.com/ClickHouse/ClickHouse/issues/94935) 中回移：当脏页大小与 `max_server_memory_usage` 的比率超过 `memory_worker_purge_dirty_pages_threshold_ratio` 时，强制清理 jemalloc arenas。[#93500](https://github.com/ClickHouse/ClickHouse/pull/93500) ([Eduard Karacharov](https://github.com/korowa))。
* 已在 [#95133](https://github.com/ClickHouse/ClickHouse/issues/95133) 中回移：如果 `FINAL` 查询中使用的跳过索引位于主键中的某一列上，则无需额外检查其他 parts 中的主键交集，现已不再执行该步骤。解决了 [#85897](https://github.com/ClickHouse/ClickHouse/issues/85897)。[#93899](https://github.com/ClickHouse/ClickHouse/pull/93899) ([Shankar Iyer](https://github.com/shankar-iyer))。
* 已在 [#94709](https://github.com/ClickHouse/ClickHouse/issues/94709) 中回移：为 S3 和 Azure Blob 存储中的 BACKUP/RESTORE 增加对 SQL 定义的命名集合的支持。关闭 [#94604](https://github.com/ClickHouse/ClickHouse/issues/94604)。[#94605](https://github.com/ClickHouse/ClickHouse/pull/94605) ([Pablo Marcos](https://github.com/pamarcos))。
* 已在 [#94988](https://github.com/ClickHouse/ClickHouse/issues/94988) 中回移：确保调度器在 CPU 资源紧张时优先调度 MemoryWorker 线程，因为它能保护 ClickHouse 进程免受致命风险。[#94864](https://github.com/ClickHouse/ClickHouse/pull/94864) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov))。
* 已在 [#95167](https://github.com/ClickHouse/ClickHouse/issues/95167) 中回移：在独立于 MemoryWorker 主线程的另一个线程中执行 jemalloc 脏页清理。如果清理较慢，可能会延迟 RSS 使用量的更新，从而导致进程因内存不足而被杀死。引入新的配置项 `memory_worker_purge_total_memory_threshold_ratio`，根据总内存使用量的比率启动脏页清理。[#94902](https://github.com/ClickHouse/ClickHouse/pull/94902) ([Antonio Andelic](https://github.com/antonio2368))。
* 已在 [#95438](https://github.com/ClickHouse/ClickHouse/issues/95438) 中回移：现在 `view_duration_ms` 显示的是 group 处于活动状态的时间，而不是其中各线程耗时的总和。[#94966](https://github.com/ClickHouse/ClickHouse/pull/94966) ([Sema Checherinda](https://github.com/CheSema))。
* 已在 [#95365](https://github.com/ClickHouse/ClickHouse/issues/95365) 中回移：在 TTL 删除分片合并中遵循 `max_parts_to_merge_at_once`。[#95315](https://github.com/ClickHouse/ClickHouse/pull/95315) ([Kseniia Sumarokova](https://github.com/kssenii))。

<div id="bugfix">
  #### 缺陷修复

* 已在 [#95759](https://github.com/ClickHouse/ClickHouse/issues/95759) 中回移：通过在 `system.query_log.exception` 中启用 stderr 捕获，修复了 UDF 调试问题。此前，UDF 的 stderr 只会记录到文件中，不会写入查询日志，因此无法进行调试。现在，stderr 默认会触发异常，并且会在抛出异常前完整累积 (最多 1MB) ，因此完整的 Python 回溯和错误信息都会出现在 `system.query_log.exception` 中，便于有效进行故障排查。 [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
