  ### ClickHouse 版本 v26.1.12.23-稳定版本 (e5aa07a1b9a) FIXME，与 v26.1.11.9-稳定版本 (1784404a5ac) 相比

<div id="backward-incompatible-change">
  #### 向后不兼容的更改
</div>

* 已在 [#103351](https://github.com/ClickHouse/ClickHouse/issues/103351) 中回移：将默认的 `http_max_fields` 从 1,000,000 下调至 1,000，并将 `http_max_field_name_size` 从 128 KB 下调至 4 KB，以限制 HTTP 连接在身份验证前的内存使用。新增了 `http_max_request_header_size` 和 `http_headers_read_timeout` 设置。依赖此前较高限制的用户可通过设置将其恢复。 [#103285](https://github.com/ClickHouse/ClickHouse/pull/103285) ([Sema Checherinda](https://github.com/CheSema)).

<div id="new-feature">
  #### 新特性
</div>

* 已在 [#103501](https://github.com/ClickHouse/ClickHouse/issues/103501) 中回移：新增 `s3_read_request_duration_microseconds` 和 `s3_read_request_bytes` 直方图指标，用于观测 S3 GET 请求连接整个生命周期的耗时和消耗的字节数，可在 `system.histogram_metrics` 和 Prometheus 端点中查看。[#102058](https://github.com/ClickHouse/ClickHouse/pull/102058) ([Sema Checherinda](https://github.com/CheSema)) 。

<div id="improvement">
  #### 改进
</div>

* 已在 [#103196](https://github.com/ClickHouse/ClickHouse/issues/103196) 中回移：在 system.stack&#95;trace 中暴露每个线程的 untracked&#95;memory。[#103065](https://github.com/ClickHouse/ClickHouse/pull/103065) ([Azat Khuzhin](https://github.com/azat))。
* 已在 [#103378](https://github.com/ClickHouse/ClickHouse/issues/103378) 中回移：将 `max_network_bandwidth_for_user`/`max_network_bandwidth_for_all_users` 应用于远程文件系统的读写。[#103080](https://github.com/ClickHouse/ClickHouse/pull/103080) ([Azat Khuzhin](https://github.com/azat))。

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 已回移到 [#103374](https://github.com/ClickHouse/ClickHouse/issues/103374)：修复了在惰性列复制 (`enable_lazy_columns_replication`) 生成的 `ColumnReplicated` 列流入带有延迟到达输入的归并排序管道时，merge 算法发生崩溃的问题 (`Logical error: isConst/isSparse/isReplicated assertTypeEquality`) 。[#101036](https://github.com/ClickHouse/ClickHouse/pull/101036) ([Groene AI](https://github.com/groeneai)).
* 已回移到 [#103185](https://github.com/ClickHouse/ClickHouse/issues/103185)：修复了在 JSON 列上创建的 min-max 索引因使用错误极值而导致查询结果错误的问题。关闭 [#101700](https://github.com/ClickHouse/ClickHouse/issues/101700)。[#101918](https://github.com/ClickHouse/ClickHouse/pull/101918) ([Pavel Kruglov](https://github.com/Avogar)).
* 已回移到 [#103146](https://github.com/ClickHouse/ClickHouse/issues/103146)：修复了多个并发 `CREATE TABLE IF NOT EXISTS` 查询针对同一个 Shared database 上的同一张 `S3Queue` 表时触发的 `LOGICAL_ERROR` 异常。[#102610](https://github.com/ClickHouse/ClickHouse/pull/102610) ([Nikita Taranov](https://github.com/nickitat)).
* 已回移到 [#103003](https://github.com/ClickHouse/ClickHouse/issues/103003)：修复了 ClusterDiscovery 中的一个 server 异常，该异常会在静态 cluster (在 config 中定义) 暂时没有存活节点时发生。[#102661](https://github.com/ClickHouse/ClickHouse/pull/102661) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 已回移到 [#102970](https://github.com/ClickHouse/ClickHouse/issues/102970)：修复了时区调整后发生溢出时，日期 data type 推断错误的问题。关闭 [#102601](https://github.com/ClickHouse/ClickHouse/issues/102601)。[#102674](https://github.com/ClickHouse/ClickHouse/pull/102674) ([Pavel Kruglov](https://github.com/Avogar)).
* 已回移到 [#103302](https://github.com/ClickHouse/ClickHouse/issues/103302)：修复了扁平化 Dynamic 类型在二进制编码 data types 下的 serialization 问题。关闭 [#101911](https://github.com/ClickHouse/ClickHouse/issues/101911)。[#102692](https://github.com/ClickHouse/ClickHouse/pull/102692) ([Pavel Kruglov](https://github.com/Avogar)).
* 已回移到 [#103493](https://github.com/ClickHouse/ClickHouse/issues/103493)：修复了 S3 requests 失败时未触发重试、反而报出 `ios_base::clear: unspecified iostream_category error` 的问题；原因是 Poco `BufferedStreamBuf::flushBuffer` 未处理来自套接字层的短写入。[#102894](https://github.com/ClickHouse/ClickHouse/pull/102894) ([Sema Checherinda](https://github.com/CheSema)).
* 已回移到 [#103224](https://github.com/ClickHouse/ClickHouse/issues/103224)：修复了在执行轻量级删除后，`minmax_count_projection` 和简单的 `COUNT(*)` 优化会被永久禁用的问题，即使带有轻量级删除掩码的所有 parts 都已 merge 掉也是如此。[#102900](https://github.com/ClickHouse/ClickHouse/pull/102900) ([Anton Popov](https://github.com/CurtizJ)).
* 已回移到 [#103020](https://github.com/ClickHouse/ClickHouse/issues/103020)：在新的 analyzer 中，将 row policy 的 OR 链优化为 IN。[#102915](https://github.com/ClickHouse/ClickHouse/pull/102915) ([Azat Khuzhin](https://github.com/azat)).
* 已回移到 [#103237](https://github.com/ClickHouse/ClickHouse/issues/103237)：不带 materialized views 的普通 INSERT 不再请求过多的 ConcurrencyControl 槽位和线程 (使用 `max_threads` 而非 `max_insert_threads`) ，从而避免在高 INSERT 吞吐量的 clusters 上出现 CC 槽位饥饿和线程数暴增。[#102961](https://github.com/ClickHouse/ClickHouse/pull/102961) ([Sema Checherinda](https://github.com/CheSema)).
* 在 [#103326](https://github.com/ClickHouse/ClickHouse/issues/103326) 中回移：在 `HMAC` SQL 函数中隐藏密钥。修复 [#102927](https://github.com/ClickHouse/ClickHouse/issues/102927)。[#102997](https://github.com/ClickHouse/ClickHouse/pull/102997) ([Mikhail f. Shiryaev](https://github.com/Felixoid)) 。
* 在 [#103201](https://github.com/ClickHouse/ClickHouse/issues/103201) 中回移：重新引入 ArrowMemoryPool，以便抛出 MEMORY&#95;LIMIT&#95;EXCEEDED，避免触发内核 OOM。[#102999](https://github.com/ClickHouse/ClickHouse/pull/102999) ([Azat Khuzhin](https://github.com/azat)) 。
* 在 [#103359](https://github.com/ClickHouse/ClickHouse/issues/103359) 中回移：将预认证 TCP Hello 数据包中的字符串限制为 64 KB，并新增 `handshake_timeout_milliseconds` 服务器设置以限制总握手时间，从而防止未认证客户端消耗过多内存或无限期占用线程。[#103284](https://github.com/ClickHouse/ClickHouse/pull/103284) ([Sema Checherinda](https://github.com/CheSema)) 。
* 在 [#103650](https://github.com/ClickHouse/ClickHouse/issues/103650) 中回移：修复 Parquet ColumnIndex 统计信息中 String 列出现 min&#95;value &gt; max&#95;value 的问题。[#103334](https://github.com/ClickHouse/ClickHouse/pull/103334) ([Saurabh Kumar Ojha](https://github.com/saurabhojha)) 。
* 在 [#103410](https://github.com/ClickHouse/ClickHouse/issues/103410) 中回移：检查 Native format 中格式错误的扁平化 Dynamic 数据。[#103392](https://github.com/ClickHouse/ClickHouse/pull/103392) ([Pavel Kruglov](https://github.com/Avogar)) 。
* 在 [#103635](https://github.com/ClickHouse/ClickHouse/issues/103635) 中回移：从 `url` 表函数填充 `_time` 列。[#103437](https://github.com/ClickHouse/ClickHouse/pull/103437) ([Nikita Taranov](https://github.com/nickitat)) 。
