<div id="improvement">
  #### 改进
</div>

* 已在 [#72060](https://github.com/ClickHouse/ClickHouse/issues/72060) 中回移：当通过 Dictionary 存储、dictionary 表函数，或直接对字典本身执行 `SELECT` 来获取数据时，现在只需具备该字典的 `SELECT` 权限或 `dictGet` 权限即可。这与此前为防止绕过 ACL 所做的尝试保持一致：[https://github.com/ClickHouse/ClickHouse/pull/57362](https://github.com/ClickHouse/ClickHouse/pull/57362) 和 [https://github.com/ClickHouse/ClickHouse/pull/65359](https://github.com/ClickHouse/ClickHouse/pull/65359)。同时，这也使后者具备了向后兼容性。[#72051](https://github.com/ClickHouse/ClickHouse/pull/72051) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 已在 [#71981](https://github.com/ClickHouse/ClickHouse/issues/71981) 中回移：在[这个 issue](https://github.com/ClickHouse/ClickHouse/pull/59946#issuecomment-1943653197)之后，生产环境中不少表副本出现了这样一种情况：其 `metadata_version` 节点值既等于 `0`，又与对应表的 `metadata` 节点版本不一致。这会导致 `alter` 查询在这类副本上失败。[#69274](https://github.com/ClickHouse/ClickHouse/pull/69274) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 已在 [#72142](https://github.com/ClickHouse/ClickHouse/issues/72142) 中回移：在将分片移动到 zero-copy 磁盘之前先获取 zero-copy 共享锁，以防在 Keeper 不可用时发生潜在的数据丢失。[#71845](https://github.com/ClickHouse/ClickHouse/pull/71845) ([Aleksei Filatov](https://github.com/aalexfvk)).
* 已在 [#72038](https://github.com/ClickHouse/ClickHouse/issues/72038) 中回移：修复在 `DateTime64` 类型主键的 `WHERE` 条件中使用 toDayOfWeek 时出现的异常。[#71849](https://github.com/ClickHouse/ClickHouse/pull/71849) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* 已在 [#72032](https://github.com/ClickHouse/ClickHouse/issues/72032) 中回移：修复当第一个参数为常量时，`MergeTree` 表在 `ORDER BY` 中使用 binary monotonic function 会触发 `Illegal type` 错误的问题。修复了 [#71941](https://github.com/ClickHouse/ClickHouse/issues/71941)。[#71966](https://github.com/ClickHouse/ClickHouse/pull/71966) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 已在 [#72155](https://github.com/ClickHouse/ClickHouse/issues/72155) 中回移：限制在子查询中使用的 EXPLAIN AST 仅允许 SELECT 查询。其他类型的查询会导致逻辑错误：&#39;Bad cast from type DB::ASTCreateQuery to DB::ASTSelectWithUnionQuery&#39; 或 `Inconsistent AST formatting`。[#71982](https://github.com/ClickHouse/ClickHouse/pull/71982) ([Pavel Kruglov](https://github.com/Avogar)).
* 已在 [#72114](https://github.com/ClickHouse/ClickHouse/issues/72114) 中回移：修复启用 `format_alter_commands_with_parentheses` 时，`MOVE PARTITION ... TO TABLE ...` alter 命令的格式化问题。[#72080](https://github.com/ClickHouse/ClickHouse/pull/72080) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
