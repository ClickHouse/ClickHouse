<div id="backward-incompatible-change">
  #### 向后不兼容变更
</div>

* 现在，处理 `ALTER TABLE ATTACH PART[ITION]` 命令的副本会先在其 `detached/` 文件夹中查找，再从其他副本拉取数据。作为实现细节，复制日志中引入了一条新命令 `ATTACH_PART`。系统会根据校验和搜索并比较 parts。[#18978](https://github.com/ClickHouse/ClickHouse/pull/18978) ([Mike Kot](https://github.com/myrrc)).
* 表 `system.dictionaries` 中的列 `keys` 已被替换为 `key.names` 和 `key.types`。`system.dictionaries` 表中的 `key.names`、`key.types`、`attribute.names`、`attribute.types` 列不再要求字典已加载。[#21884](https://github.com/ClickHouse/ClickHouse/pull/21884) ([Maksim Kita](https://github.com/kitaisreal)).
* 修复了 `cutToFirstSignificantSubdomainCustom()`/`firstSignificantSubdomainCustom()` 在自定义顶级域名列表中包含三级及以上域名时返回错误结果的问题。对于匹配这些自定义顶级域名的输入域名，此前会将三级域名视为第一个有效域名。现已修复。如果该函数用于例如分片键，此变更可能会引入不兼容性。[#21946](https://github.com/ClickHouse/ClickHouse/pull/21946) ([Azat Khuzhin](https://github.com/azat)).
* `toStartOfIntervalFunction` 现在会将按小时划分的时间间隔对齐到午夜 (在之前的版本中，它们会对齐到 Unix 纪元的起点) 。例如，`toStartOfInterval(x, INTERVAL 11 HOUR)` 会将每天划分为三个时间段：00:00:00..10:59:59、11:00:00..21:59:59 和 22:00:00..23:59:59。此行为更符合实际需求。此变更关闭了 [#9510](https://github.com/ClickHouse/ClickHouse/issues/9510)。[#22060](https://github.com/ClickHouse/ClickHouse/pull/22060) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* 新增表函数 `dictionary`。其工作方式与 `Dictionary` 引擎相同。关闭 [#21560](https://github.com/ClickHouse/ClickHouse/issues/21560)。[#21910](https://github.com/ClickHouse/ClickHouse/pull/21910) ([Maksim Kita](https://github.com/kitaisreal)).
* 新增函数 `timezoneOf`，返回 `DateTime` 或 `DateTime64` 数据类型的时区名称。这并未关闭 [#9959](https://github.com/ClickHouse/ClickHouse/issues/9959)。同时修复了函数命名不一致的问题：新增别名 `timezone` 和 `timeZone`，以及 `toTimezone` 和 `toTimeZone`、`timezoneOf` 和 `timeZoneOf`。[#22001](https://github.com/ClickHouse/ClickHouse/pull/22001) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增 `prefer_column_name_to_alias` 设置，以使用原始列名而不是别名。这是为了更好地兼容常见数据库的别名规则。对应 [#9715](https://github.com/ClickHouse/ClickHouse/issues/9715) 和 [#9887](https://github.com/ClickHouse/ClickHouse/issues/9887)。[#22044](https://github.com/ClickHouse/ClickHouse/pull/22044) ([Amos Bird](https://github.com/amosbird)).
* 提升了 `dictGetHierarchy`、`dictIsIn` 函数的性能。新增函数 `dictGetChildren(dictionary, key)` 和 `dictGetDescendants(dictionary, key, level)`。函数 `dictGetChildren` 以索引数组的形式返回所有子节点。它是 `dictGetHierarchy` 的逆向变换。函数 `dictGetDescendants` 返回所有后代，相当于递归应用 `dictGetChildren` `level` 次。`level` 值为 0 等同于无穷大。关闭 [#14656](https://github.com/ClickHouse/ClickHouse/issues/14656)。[#22096](https://github.com/ClickHouse/ClickHouse/pull/22096) ([Maksim Kita](https://github.com/kitaisreal)).
* 新增函数 `dictGetOrNull`。其用法与 `dictGet` 类似，但如果在字典中找不到键，则返回 `Null`。关闭了 [#22375](https://github.com/ClickHouse/ClickHouse/issues/22375)。[#22413](https://github.com/ClickHouse/ClickHouse/pull/22413) ([Maksim Kita](https://github.com/kitaisreal)) 。



<div id="performance-improvement">
  #### 性能提升
</div>

* 支持对 `CSVWithNames` 和 `TSVWithNames` 格式进行并行解析。此更改关闭了 [#21085](https://github.com/ClickHouse/ClickHouse/issues/21085)。[#21149](https://github.com/ClickHouse/ClickHouse/pull/21149) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。
* 通过将 `memcpy` 替换为另一种实现提升了性能。此更改关闭了 [#18583](https://github.com/ClickHouse/ClickHouse/issues/18583)。[#21520](https://github.com/ClickHouse/ClickHouse/pull/21520) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 在 clickhouse-local 及其他场景中支持并行格式化。[#21630](https://github.com/ClickHouse/ClickHouse/pull/21630) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。
* 优化 `SELECT ... FINAL ... WHERE` 这类查询的性能。现在，在带有 `FINAL` 的查询中，允许将属于排序键的列移到 `PREWHERE`。... [#21830](https://github.com/ClickHouse/ClickHouse/pull/21830) ([foolchi](https://github.com/foolchi)) 。
* 当 `max_rows_to_group_by` 较小且 `group_by_overflow_mode='any'` 时，`GROUP BY` 性能更好。[#21856](https://github.com/ClickHouse/ClickHouse/pull/21856) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 使用 codec `NONE` 时可避免不必要的数据拷贝。请注意，codec `NONE` 基本没什么用——建议始终使用压缩 (默认使用 `LZ4`) 。与常见看法相反，禁用压缩未必会提升性能 (甚至可能适得其反) 。`NONE` codec 在某些情况下是有用的：- 当数据不可压缩时；- 用于合成基准测试。[#22145](https://github.com/ClickHouse/ClickHouse/pull/22145) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 为使用 `min_bytes_to_use_mmap_io` 设置读取的文件添加缓存。通过避免频繁调用 mmap/munmap 及其带来的缺页错误，当该设置值较小时，它可以显著提升性能 (2 倍及以上) 。请注意，mmap IO 有一些明显缺点，导致它在生产环境中的可靠性较低 (例如，故障磁盘可能导致挂起或 SIGBUS；内存使用也较难控制) 。不过，它在基准测试中表现不错。[#22206](https://github.com/ClickHouse/ClickHouse/pull/22206) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 对 64 MiB 以上的文件范围启用 mmap IO 读取 (设置 `min_bytes_to_use_mmap_io`) 。这可能会带来一定的性能提升。[#22326](https://github.com/ClickHouse/ClickHouse/pull/22326) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。

* 为 `visitParam/visitParamExtract{UInt, Int, Bool, Float, Raw, String}` 添加别名 `simpleJSONExtract/simpleJSONHas`。修复 [#21383](https://github.com/ClickHouse/ClickHouse/issues/21383)。 [#21519](https://github.com/ClickHouse/ClickHouse/pull/21519) ([fastio](https://github.com/fastio)).

* 如果 PODArray 实例化时使用的元素大小既不是 16 的因数，也不是 16 的倍数，则可能发生缓冲区溢出。当前发行版中不存在此类 bug。 [#21533](https://github.com/ClickHouse/ClickHouse/pull/21533) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
