<div id="backward-incompatible-change">
  #### Backward Incompatible Change
</div>

* 设置 `print_pretty_type_names` 现已默认启用。你可以将其关闭以保留旧行为，或者执行 `SET compatibility = '23.12'`。[#57726](https://github.com/ClickHouse/ClickHouse/pull/57726) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* MergeTree setting `clean_deleted_rows` 已弃用，现已不再生效。默认不允许在 `OPTIMIZE` 中使用 `CLEANUP` 关键字 (除非启用了 `allow_experimental_replacing_merge_with_cleanup`) 。[#58316](https://github.com/ClickHouse/ClickHouse/pull/58316) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 函数 `reverseDNSQuery` 已不再可用。此更改关闭了 [#58368](https://github.com/ClickHouse/ClickHouse/issues/58368)。[#58369](https://github.com/ClickHouse/ClickHouse/pull/58369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 启用了一系列改动，以改进配置文件中的 access control。这些改动会影响行为，请检查 `config.xml` 中 `access_control_improvements` 部分的配置。如果你不太确定，请保持配置文件中的值与上一版本一致。[#58584](https://github.com/ClickHouse/ClickHouse/pull/58584) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对于 `PASTE JOIN`，子查询现在可以不使用别名。[#58654](https://github.com/ClickHouse/ClickHouse/pull/58654) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 修复了 `sumMapFiltered` 处理 NaN 值时的问题。现在 NaN 值会排在末尾 (而非随机位置) ，并且会被视为与任何值都不同。`-0` 现在也会被视为等同于 `0`；由于值为 0 的项会被丢弃，因此 `-0` 的项也会被丢弃。[#58959](https://github.com/ClickHouse/ClickHouse/pull/58959) ([Raúl Marín](https://github.com/Algunenano)).
* 函数 `visibleWidth` 现在会按照文档说明执行。在之前的版本中，它只是像 `lengthUTF8` 函数一样，在字符串序列化后统计码点，但不会考虑零宽字符、组合字符、全宽字符、选项卡和删除符。现在其行为已相应调整。如果你想保留旧行为，可将 `function_visible_width_behavior` 设置为 `0`，或者将 `compatibility` 设置为 `23.12` 或更低版本。[#59022](https://github.com/ClickHouse/ClickHouse/pull/59022) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Kusto dialect 已被禁用，直到以下两个 bug 修复为止：[#59037](https://github.com/ClickHouse/ClickHouse/issues/59037) 和 [#59036](https://github.com/ClickHouse/ClickHouse/issues/59036)。[#59305](https://github.com/ClickHouse/ClickHouse/pull/59305) ([Alexey Milovidov](https://github.com/alexey-milovidov)).



<div id="new-feature">
  #### 新功能
</div>

* 当目标表的分区表达式不会对 part 进行重新分区或拆分时，允许将来自不同分区表达式的表的分区附加至该目标表。[#39507](https://github.com/ClickHouse/ClickHouse/pull/39507) ([Arthur Passos](https://github.com/arthurpassos))。
* 新增语句 `SYSTEM RELOAD ASYNCHRONOUS METRICS`，用于更新异步指标，主要用于测试和开发场景。[#53710](https://github.com/ClickHouse/ClickHouse/pull/53710) ([Robert Schulze](https://github.com/rschu1ze))。
* 部分设置（目前为 `min_compress_block_size` 和 `max_compress_block_size`）现在支持在列级别指定，且列级别设置优先于对应的表级别设置。示例：`CREATE TABLE tab (col String SETTINGS (min_compress_block_size = 81920, max_compress_block_size = 163840)) ENGINE = MergeTree ORDER BY tuple();`。[#55201](https://github.com/ClickHouse/ClickHouse/pull/55201) ([Duc Canh Le](https://github.com/canhld94))。
* 新增聚合函数 `quantileDDSketch` 及对应的 `quantilesDDSketch` 和 `medianDDSketch`，基于 DDSketch 算法 https://www.vldb.org/pvldb/vol12/p2195-masson.pdf。### 面向用户变更的文档说明。[#56342](https://github.com/ClickHouse/ClickHouse/pull/56342) ([Srikanth Chekuri](https://github.com/srikanthccv))。
* 新增函数 `seriesDecomposeSTL()`，可将时间序列分解为季节性、趋势和残差三个分量。[#57078](https://github.com/ClickHouse/ClickHouse/pull/57078) ([Bhavna Jindal](https://github.com/bhavnajindal))。
* 为 MaterializedMySQL 引入 MySQL Binlog 客户端：单个 binlog 连接即可服务于多个数据库。[#57323](https://github.com/ClickHouse/ClickHouse/pull/57323) ([Val Doroshchuk](https://github.com/valbok))。
* Intel QuickAssist Technology（QAT）提供硬件加速的压缩与加密能力。ClickHouse 新增了压缩 codec `ZSTD_QAT`，利用 QAT 加速 zstd 压缩。该 codec 使用 [Intel 的 QATlib](https://github.com/intel/qatlib) 和 [Intel 的 QAT ZSTD Plugin](https://github.com/intel/QAT-ZSTD-Plugin)。目前仅压缩支持硬件加速（若 QAT 无法初始化则自动回退至软件实现），解压缩始终在软件中执行。[#57509](https://github.com/ClickHouse/ClickHouse/pull/57509) ([jasperzhu](https://github.com/jinjunzh))。
* 实现了 S3 磁盘对象存储键的新生成方式。现在可在磁盘描述中通过 `key_template` 选项以 `re2` 正则表达式语法定义键的格式。[#57663](https://github.com/ClickHouse/ClickHouse/pull/57663) ([Sema Checherinda](https://github.com/CheSema))。
* 表 system.dropped_tables_parts 包含 system.dropped_tables 中各表的 parts（即已删除但尚未被清理的表）。[#58038](https://github.com/ClickHouse/ClickHouse/pull/58038) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* 实现了 Variant 数据类型，用于表示多种数据类型的联合体。类型 `Variant(T1, T2, ..., TN)` 表示该类型每一行的值为 `T1`、`T2`、……或 `TN` 之一，或为 NULL。Variant 类型需通过设置 `allow_experimental_variant_type` 启用。参考：[#54864](https://github.com/ClickHouse/ClickHouse/issues/54864)。[#58047](https://github.com/ClickHouse/ClickHouse/pull/58047) ([Kruglov Pavel](https://github.com/Avogar))。
* 新增设置 `max_materialized_views_size_for_table`，用于限制挂载到单张表的 materialized view 数量上限。[#58068](https://github.com/ClickHouse/ClickHouse/pull/58068) ([zhongyuankai](https://github.com/zhongyuankai))。
* `clickhouse-format` 改进：* 支持带 `VALUES` 的 INSERT 查询 * 支持注释（使用 `--comments` 输出注释）* 新增 `--max_line_length` 选项，仅对超长查询进行多行格式化。[#58246](https://github.com/ClickHouse/ClickHouse/pull/58246) ([vdimir](https://github.com/vdimir))。
* 为 `distributed_ddl_output_mode` 新增 `null_status_on_timeout_only_active` 和 `throw_only_active` 模式，从而无需等待非活跃副本。[#58350](https://github.com/ClickHouse/ClickHouse/pull/58350) ([Alexander Tokmakov](https://github.com/tavplubix))。
* 新增表 `system.database_engines`。[#58390](https://github.com/ClickHouse/ClickHouse/pull/58390) ([Bharat Nallan](https://github.com/bharatnc))。
* 为 SYSTEM SYNC REPLICA LIGHTWEIGHT 查询新增 FROM <Replicas> 修饰符。该修饰符确保仅等待指定源副本的数据拉取和删除范围操作，以及不在 ZooKeeper 中或 source_replica 为空的副本。[#58393](https://github.com/ClickHouse/ClickHouse/pull/58393) ([Jayme Bird](https://github.com/jaymebrd))。
* 新增函数 `arrayShingles()`，用于计算子数组，例如 `arrayShingles([1, 2, 3, 4, 5], 3)` 返回 `[[1,2,3],[2,3,4],[3,4,5]]`。[#58396](https://github.com/ClickHouse/ClickHouse/pull/58396) ([Zheng Miao](https://github.com/zenmiao7))。
* 新增函数 `punycodeEncode()`、`punycodeDecode()`、`idnaEncode()` 和 `idnaDecode()`，可按照 IDNA 标准将国际化域名转换为 ASCII 表示形式。[#58454](https://github.com/ClickHouse/ClickHouse/pull/58454) ([Robert Schulze](https://github.com/rschu1ze))。
* 新增字符串相似度函数 `dramerauLevenshteinDistance()`、`jaroSimilarity()` 和 `jaroWinklerSimilarity()`。[#58531](https://github.com/ClickHouse/ClickHouse/pull/58531) ([Robert Schulze](https://github.com/rschu1ze))。
* 新增两个设置：`output_format_compression_level` 用于调整输出压缩级别；`output_format_compression_zstd_window_log` 用于在输出压缩方法为 `zstd` 时显式设置压缩窗口大小并启用长距离模式。适用于 `INTO OUTFILE` 及向表函数 `file`、`url`、`hdfs`、`s3` 和 `azureBlobStorage` 写入数据的场景。[#58539](https://github.com/ClickHouse/ClickHouse/pull/58539) ([Duc Canh Le](https://github.com/canhld94))。
* 当输出目标不是终端时，自动禁用 Pretty 格式中的 ANSI escape sequences。为设置 `output_format_pretty_color` 新增 `auto` 模式。[#58614](https://github.com/ClickHouse/ClickHouse/pull/58614) ([Shaun Struwig](https://github.com/Blargian))。
* 新增设置 `update_insert_deduplication_token_in_dependent_materialized_views`，允许在向依赖的 materialized view 插入数据时，以表标识符更新 insert deduplication token。关闭 [#59165](https://github.com/ClickHouse/ClickHouse/issues/59165)。[#59238](https://github.com/ClickHouse/ClickHouse/pull/59238) ([Maksim Kita](https://github.com/kitaisreal))。





<div id="performance-improvement">
  #### 性能提升
</div>

* 更加缓存友好的 final 实现。行为变更说明：此前，带有 `FINAL` modifier 且以单个 stream 读取的查询 (例如 `max_threads=1`) ，即使未显式提供 `ORDER BY` clause，也会输出已排序的结果。当 `enable_vertical_final = true` 时 (默认即如此) ，这一行为将不再存在。[#54366](https://github.com/ClickHouse/ClickHouse/pull/54366) ([Duc Canh Le](https://github.com/canhld94)).
* 当输入为 array(map)/array(array(num)/array(array(string))/array(bigint)/array(decimal) 时，优化数组元素函数。当前实现会导致过多的重新分配。该优化可带来约 6 倍的提速，尤其是在输入类型为 array(map) 时。[#56403](https://github.com/ClickHouse/ClickHouse/pull/56403) ([李扬](https://github.com/taiyang-li)).
* 从 S3 读取时绕过 `Poco::BasicBufferedStreamBuf` 抽象 (即 `ReadBufferFromIStream`) ，以避免额外的数据拷贝。[#56961](https://github.com/ClickHouse/ClickHouse/pull/56961) ([Nikita Taranov](https://github.com/nickitat)).
* 在 Compact parts 中，当从同一列读取多个 subcolumn 时，只读取该列一次。[#57631](https://github.com/ClickHouse/ClickHouse/pull/57631) ([Kruglov Pavel](https://github.com/Avogar)).
* 重写 `sum(column + literal)` 函数的 AST。[#57853](https://github.com/ClickHouse/ClickHouse/pull/57853) ([Jiebin Sun](https://github.com/jiebinn)).
* 函数 `match()` 的求值现在会利用 skipping indices `ngrambf_v1` 和 `tokenbf_v1`。[#57882](https://github.com/ClickHouse/ClickHouse/pull/57882) ([凌涛](https://github.com/lingtaolf)).
* 并行副本的默认 coordinator 已重写，以提升 cache locality (相同的 mark ranges 几乎总会分配给相同的 replicas) 。work stealing 期间也会使用一致性哈希，因此预计 tail latency 将有所改善。已在上百个 replicas 上测试验证了线性 scalability。[#57968](https://github.com/ClickHouse/ClickHouse/pull/57968) ([Nikita Taranov](https://github.com/nickitat)).
* MergeTree FINAL 不再比较来自同一非 L0 part 的行。[#58142](https://github.com/ClickHouse/ClickHouse/pull/58142) ([Duc Canh Le](https://github.com/canhld94)).
* 加速 iota 调用 (用连续数字填充数组) 。[#58271](https://github.com/ClickHouse/ClickHouse/pull/58271) ([Raúl Marín](https://github.com/Algunenano)).
* 函数 `match()` 的求值现在会利用倒排索引。[#58284](https://github.com/ClickHouse/ClickHouse/pull/58284) ([凌涛](https://github.com/lingtaolf)).
* 加速非数值类型的 MIN/MAX。[#58334](https://github.com/ClickHouse/ClickHouse/pull/58334) ([Raúl Marín](https://github.com/Algunenano)).
* 为无 key 的 aggregation 启用 JIT 编译。关闭 [#41461](https://github.com/ClickHouse/ClickHouse/issues/41461)。最初为 [#53757](https://github.com/ClickHouse/ClickHouse/issues/53757)。[#58440](https://github.com/ClickHouse/ClickHouse/pull/58440) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 在支持最高 AVX2 (以及 BMI2) 的 Intel server 上进行的 **OnTime** 性能实验表明，此变更可通过将热点 ***DB::MergeTreeRangeReader::ReadResult::optimize*** 的 cycle 占比**分别从 11.48% 降至 1.09%**以及**从 8.09% 降至 0.67%**，有效将 **Q2** 和 **Q3** 的 QPS 分别提升 **5.0%** 和 **3.7%**，同时对其他项没有影响。[#58800](https://github.com/ClickHouse/ClickHouse/pull/58800) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 在 `clickhouse-local` 中少用一个线程。[#58968](https://github.com/ClickHouse/ClickHouse/pull/58968) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `uniqExact` 的大型聚合状态将在分布式查询中并行合并。[#59009](https://github.com/ClickHouse/ClickHouse/pull/59009) ([Nikita Taranov](https://github.com/nickitat)).
* 从 `MergeTree` 表读取后，内存占用降低。[#59290](https://github.com/ClickHouse/ClickHouse/pull/59290) ([Anton Popov](https://github.com/CurtizJ)).
* 垂直合并期间的内存占用降低。[#59340](https://github.com/ClickHouse/ClickHouse/pull/59340) ([Anton Popov](https://github.com/CurtizJ)).





<div id="improvement">
  #### 改进
</div>

* 在 macOS 上启用 MySQL/MariaDB。此更改关闭了 [#21191](https://github.com/ClickHouse/ClickHouse/issues/21191)。[#46316](https://github.com/ClickHouse/ClickHouse/pull/46316) ([Robert Schulze](https://github.com/rschu1ze))。
* 不再将带前导零的数字解释为八进制。[#55575](https://github.com/ClickHouse/ClickHouse/pull/55575) ([Joanna Hulboj](https://github.com/jh0x))。
* 将基于 std ostream 的 HTTP 出站缓冲替换为 CH Buffer。为各接口添加字节计数指标。[#56064](https://github.com/ClickHouse/ClickHouse/pull/56064) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* 默认禁用 `max_rows_in_set_to_optimize_join`。[#56396](https://github.com/ClickHouse/ClickHouse/pull/56396) ([vdimir](https://github.com/vdimir))。
* 新增 `<host_name>` config 参数，可避免 DDLWorker 解析主机名。这降低了 cluster 定义发生变更时 queue 卡住的可能性。关闭了 [#57573](https://github.com/ClickHouse/ClickHouse/issues/57573)。[#57603](https://github.com/ClickHouse/ClickHouse/pull/57603) ([Nikolay Degterinsky](https://github.com/evillique))。
* 将文件系统缓存的 `load_metadata_threads` 提高到 16。这将加快 server 启动速度。[#57732](https://github.com/ClickHouse/ClickHouse/pull/57732) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 改进 `multiIf` 函数在类型为 Nullable 时的性能。[#57745](https://github.com/ClickHouse/ClickHouse/pull/57745) ([KevinyhZou](https://github.com/KevinyhZou))。
* 新增对 merges/mutations 的带宽限制能力 (`max_mutations_bandwidth_for_server`/`max_merges_bandwidth_for_server`) 。[#57877](https://github.com/ClickHouse/ClickHouse/pull/57877) ([Azat Khuzhin](https://github.com/azat))。
* 将系统表 `system.server_settings` 中原先未文档化的 (boolean) 列 `is_hot_reloadable` 替换为 (Enum8) 列 `changeable_without_restart`，其 possible values 为 `No`、`Yes`、`IncreaseOnly` 和 `DecreaseOnly`。同时补充了该列的文档。[#58029](https://github.com/ClickHouse/ClickHouse/pull/58029) ([skyoct](https://github.com/skyoct))。
* ClusterDiscovery 支持设置用户名和密码，关闭了 [#58063](https://github.com/ClickHouse/ClickHouse/issues/58063)。[#58123](https://github.com/ClickHouse/ClickHouse/pull/58123) ([vdimir](https://github.com/vdimir))。
* 在 ALTER TABLE ... PART 中支持查询参数。[#58297](https://github.com/ClickHouse/ClickHouse/pull/58297) ([Azat Khuzhin](https://github.com/azat))。
* 为 Kafka 表按需动态创建消费者 (但在最后一次使用后会保留一段时间，由 `kafka_consumers_pool_ttl_ms` 控制) 。这应能修复 `system.kafka_consumers` 的统计信息问题 (当没有人读取 Kafka 表时，它不会消费消息，从而导致持续的内存泄漏以及表 detach 缓慢) ；同时，此 PR 也再次默认启用了 `system.kafka_consumers` 的统计信息。[#58310](https://github.com/ClickHouse/ClickHouse/pull/58310) ([Azat Khuzhin](https://github.com/azat))。
* 新增 Sparkbar 作为 sparkbar 的别名。[#58335](https://github.com/ClickHouse/ClickHouse/pull/58335) ([凌涛](https://github.com/lingtaolf))。
* 避免在上传到 GCS 后发送 ComposeObject 请求。[#58343](https://github.com/ClickHouse/ClickHouse/pull/58343) ([Azat Khuzhin](https://github.com/azat))。
* 正确处理配置 XML 中名称里包含点号的键。[#58354](https://github.com/ClickHouse/ClickHouse/pull/58354) ([Azat Khuzhin](https://github.com/azat))。
* 为系统表的所有列添加了注释 (简要说明) 。这样做有几个原因： - 我们经常使用系统表，而开发者有时很难理解某个列的用途和含义。 - 我们经常变更系统表 (新增列或修改现有列) ，但相关文档往往总是过期。例如，看看 [`system.parts`](https://clickhouse.com/docs/en/operations/system-tables/parts) 的文档页面，其中缺少很多列 - 我们希望最终能够直接从 ClickHouse 生成文档。[#58356](https://github.com/ClickHouse/ClickHouse/pull/58356) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 允许为任意类型的对象存储配置任意元数据类型。[#58357](https://github.com/ClickHouse/ClickHouse/pull/58357) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 使函数 `format` 在参数为常量时返回常量结果。这关闭了 [#58355](https://github.com/ClickHouse/ClickHouse/issues/58355)。[#58358](https://github.com/ClickHouse/ClickHouse/pull/58358) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 在 `clickhouse-local` 中 Attach 所有系统表，包括 `system.parts`。这关闭了 [#58312](https://github.com/ClickHouse/ClickHouse/issues/58312)。[#58359](https://github.com/ClickHouse/ClickHouse/pull/58359) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 函数 `transform` 现已支持 `Enum` 数据类型。这关闭了 [#58241](https://github.com/ClickHouse/ClickHouse/issues/58241)。[#58360](https://github.com/ClickHouse/ClickHouse/pull/58360) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
