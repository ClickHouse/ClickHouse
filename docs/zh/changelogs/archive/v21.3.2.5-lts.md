  ### ClickHouse 版本 v21.3.2.5-长期支持版 FIXME (相比 v21.2.1.5869-prestable)

<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 现在，所有不区分大小写的函数名都会在查询分析期间转换为小写。这是投影查询路由所必需的。[#20174](https://github.com/ClickHouse/ClickHouse/pull/20174) ([Amos Bird](https://github.com/amosbird)).
* 现在，不再允许使用带有表生存时间 (TTL) 的旧语法创建 MergeTree 表，因为该语法实际上会被忽略。仍然可以 Attach 旧表。[#20282](https://github.com/ClickHouse/ClickHouse/pull/20282) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### 新特性
</div>

* 新增 Experimental `Replicated` 数据库引擎。它会在多个主机之间复制 DDL 查询。[#16193](https://github.com/ClickHouse/ClickHouse/pull/16193) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Distributed query 去重是对 [#16033](https://github.com/ClickHouse/ClickHouse/issues/16033) 的后续改进，并部分解决了提案 [#13574](https://github.com/ClickHouse/ClickHouse/issues/13574)。[#17348](https://github.com/ClickHouse/ClickHouse/pull/17348) ([xjewer](https://github.com/xjewer)).
* 新增了对 DiskS3 元数据文件进行备份/恢复的能力。[#18377](https://github.com/ClickHouse/ClickHouse/pull/18377) ([Pavel Kovalenko](https://github.com/Jokser)).
* * 已包含在此拉取请求中。[#18508](https://github.com/ClickHouse/ClickHouse/pull/18508) ([PHO](https://github.com/depressed-pho)).
* 新增了 `file()` 函数，可将文件读取为 String。这修复了 [#issue:18851](https://github.com/ClickHouse/ClickHouse/issues/18851)。[#19204](https://github.com/ClickHouse/ClickHouse/pull/19204) ([keenwolf](https://github.com/keen-wolf)) 。
* 使用 `MergeTree*` 引擎的表现在新增了两个用于控制查询并发的表级设置。设置 `max_concurrent_queries` 用于限制与该表相关的并发执行查询数。设置 `min_marks_to_honor_max_concurrent_queries` 则表示，只有当查询至少读取这么多个标记时，才会应用前一个设置。[#19544](https://github.com/ClickHouse/ClickHouse/pull/19544) ([Amos Bird](https://github.com/amosbird)) 。
* * 在 [#18454](https://github.com/ClickHouse/ClickHouse/issues/18454) 中提到：新增函数 `htmlOrxmlCoarseParse`；支持解析 `<script></script>`；支持解析 `<style></style>`；支持解析 `<![CDATA[]]>`；支持空白折叠；支持解析任意 `<content>` 格式；HyperScan 支持 SIMD；全部在单次遍历中完成。[#19600](https://github.com/ClickHouse/ClickHouse/pull/19600) ([zlx19950903](https://github.com/zlx19950903)) 。
* 新增配额类型 QUERY&#95;SELECTS 和 QUERY&#95;INSERTS。[#19603](https://github.com/ClickHouse/ClickHouse/pull/19603) ([JackyWoo](https://github.com/JackyWoo)) 。
* ExecutableDictionarySource 新增 `implicit&#95;key` 选项。修复了 [#14527](https://github.com/ClickHouse/ClickHouse/issues/14527)。[#19677](https://github.com/ClickHouse/ClickHouse/pull/19677) ([Maksim Kita](https://github.com/kitaisreal)) 。
* S3 client 新增对 Server Side Encryption Customer Keys (`x-amz-server-side-encryption-customer-(key/md5)` 请求头) 的支持。参见[此链接](https://docs.aws.amazon.com/AmazonS3/latest/dev/ServerSideEncryptionCustomerKeys.html)。关闭了 [#19428](https://github.com/ClickHouse/ClickHouse/issues/19428)。[#19748](https://github.com/ClickHouse/ClickHouse/pull/19748) ([Vladimir Chebotarev](https://github.com/excitoon)) 。
* 函数 `reinterpretAs` 已更新，支持大整数。修复了 [#19691](https://github.com/ClickHouse/ClickHouse/issues/19691)。[#19858](https://github.com/ClickHouse/ClickHouse/pull/19858) ([Maksim Kita](https://github.com/kitaisreal)) 。
* 新增设置 `insert_shard_id`，支持从分布式表向特定分片插入数据。[#19961](https://github.com/ClickHouse/ClickHouse/pull/19961) ([flynn](https://github.com/ucasfl)) 。
* 新增 `timezoneOffset(datetime)` 函数，返回相对 UTC 的秒数偏移量。此项关闭了 [#issue:19850](https://github.com/ClickHouse/ClickHouse/issues/19850)。[#19962](https://github.com/ClickHouse/ClickHouse/pull/19962) ([keenwolf](https://github.com/keen-wolf)) 。
* 在 `system.part_log` 表中新增 `event_time_microseconds` 列。[#20027](https://github.com/ClickHouse/ClickHouse/pull/20027) ([Bharat Nallan](https://github.com/bharatnc)) 。
* ... 新增聚合函数 `deltaSum`，用于对连续行之间的差值求和。[#20057](https://github.com/ClickHouse/ClickHouse/pull/20057) ([Russ Frank](https://github.com/rf)) 。
* 新增两个设置：当非活跃 parts 过多时，可在插入期间延迟处理或抛出错误。这在 server 无法足够快地清理 parts 时很有用。[#20178](https://github.com/ClickHouse/ClickHouse/pull/20178) ([Amos Bird](https://github.com/amosbird)) 。
* 新增 File 表引擎设置：`engine_file_empty_if_not_exists` 和 `engine_file_truncate_on_insert`。[#20620](https://github.com/ClickHouse/ClickHouse/pull/20620) ([M0r64n](https://github.com/M0r64n)) 。

<div id="performance-improvement">
  #### 性能提升
</div>

* 当 `do_not_merge_across_partitions_select_final` 设置为 1 时，为单个 level&gt;0 的分片添加并行 select final。 [#19375](https://github.com/ClickHouse/ClickHouse/pull/19375) ([Kruglov Pavel](https://github.com/Avogar)).
* 提升了 bitmap 列在 joins 期间的性能。 [#19407](https://github.com/ClickHouse/ClickHouse/pull/19407) ([templarzq](https://github.com/templarzq)).
* 对 HTTP server 进行了部分重构，以减少对传入和传出数据的复制。这使通过 HTTP 插入长记录时的性能最高可提升 1.5 倍。 [#19516](https://github.com/ClickHouse/ClickHouse/pull/19516) ([Ivan](https://github.com/abyss7)).
* 通过更严格的别名规则提升了 aggregate functions 的性能。 [#19946](https://github.com/ClickHouse/ClickHouse/pull/19946) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了 DataType parser 可能出现指数级复杂度的情况 (由 fuzzer 发现) 。这关闭了 [#20096](https://github.com/ClickHouse/ClickHouse/issues/20096)。 [#20132](https://github.com/ClickHouse/ClickHouse/pull/20132) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为 `Memory` 表添加了 `compress` 设置。启用后，表占用的 RAM 会更少。在某些机器和数据集上，SELECT 也可能更快，但并非总是如此。这关闭了 [#20093](https://github.com/ClickHouse/ClickHouse/issues/20093)。注意：`Memory` 表有时会比 MergeTree 更慢，原因包括：(1) 缺少压缩 (2) 块大小固定 (3) 缺少索引和 prewhere... [#20168](https://github.com/ClickHouse/ClickHouse/pull/20168) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 如果插入目标是 `Memory` 表，则在 INSERT SELECT 时不要过度 squash 块。在之前的版本中，INSERT SELECT 之后会在 `Memory` 表中产生低效的数据表示。这关闭了 [#13052](https://github.com/ClickHouse/ClickHouse/issues/13052)。 [#20169](https://github.com/ClickHouse/ClickHouse/pull/20169) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 提升了按多个定长字段进行 aggregation 的性能 (未经确认) 。 [#20454](https://github.com/ClickHouse/ClickHouse/pull/20454) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 在极端情况下 (读取速度达到 50 GB/sec 量级时) ，通过简化管道并相应减少管道调度中的锁竞争，加快了从 `Memory` 表读取的速度。 [#20468](https://github.com/ClickHouse/ClickHouse/pull/20468) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 提升了 GROUP BY 多个定长键时的性能。 [#20472](https://github.com/ClickHouse/ClickHouse/pull/20472) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 设置 `distributed_aggregation_memory_efficient` 默认启用。它将降低内存使用量并提升分布式查询的性能。 [#20599](https://github.com/ClickHouse/ClickHouse/pull/20599) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对 aggregation 相关代码做了些许优化。 [#20978](https://github.com/ClickHouse/ClickHouse/pull/20978) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 重新加入 intDiv/module vectorConstant 特化以获得更好的性能。这修复了 [#21293](https://github.com/ClickHouse/ClickHouse/issues/21293)。该回归问题是在 [https://github.com/ClickHouse/ClickHouse/pull/18145](https://github.com/ClickHouse/ClickHouse/pull/18145) 中引入的。 [#21307](https://github.com/ClickHouse/ClickHouse/pull/21307) ([Amos Bird](https://github.com/amosbird)).

<div id="improvement">
  #### 改进
</div>

* 修复了在 `TTL` 表达式为函数且与 `ORDER BY` 键相同时创建 `TTL` 的问题。现在，允许在带有 `GROUP BY` 的 `TTL` 中为主键列设置自定义聚合。向后不兼容：对于不在 `GROUP BY` 中且当前未显式设置的主键列，在 TTL 过期时，现在会应用 `any` 函数而不是 `max`。此外，如果在滚动更新期间使用带有 `WHERE` 或 `GROUP BY` 的 TTL，可能会在 merges 时看到异常。[#15450](https://github.com/ClickHouse/ClickHouse/pull/15450) ([Anton Popov](https://github.com/CurtizJ)).
* 为远程查询引入 Hedged Requests。启用 `use_hedged_requests` 设置后 (默认启用) ，允许为同一查询与不同副本建立多个连接。如果现有连接未能在 `hedged_connection_timeout` 内与副本建立，或在 `receive_data_timeout` 内未收到数据，则会启用新连接。查询会使用第一个发送非空 progress packet 的连接 (如果启用了 `allow_changing_replica_until_first_data_packet`，则也可以是 data packet) ；其他连接会被取消。支持 `max_parallel_replicas > 1` 的查询。[#19291](https://github.com/ClickHouse/ClickHouse/pull/19291) ([Kruglov Pavel](https://github.com/Avogar)).
* 为致命 stacktrace 打印内联帧。[#19317](https://github.com/ClickHouse/ClickHouse/pull/19317) ([Ivan](https://github.com/abyss7)).
* 不再静默忽略写入错误。[#19451](https://github.com/ClickHouse/ClickHouse/pull/19451) ([Azat Khuzhin](https://github.com/azat)).
* 为指定了行级安全表达式的表新增 `PREWHERE` 支持。[#19576](https://github.com/ClickHouse/ClickHouse/pull/19576) ([Denis Glazachev](https://github.com/traceon)).
* 添加 IStoragePolicy interface。[#19608](https://github.com/ClickHouse/ClickHouse/pull/19608) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* 新增了根据异步发送待处理字节数对 INSERT 到 Distributed 进行限流的能力 (为 `Distributed` engine 新增了 `bytes_to_delay_insert`/`max_delay_to_insert` 和 `bytes_to_throw_insert` 设置) 。[#19673](https://github.com/ClickHouse/ClickHouse/pull/19673) ([Azat Khuzhin](https://github.com/azat)).
* 将与 JOIN 无关的条件移到 WHERE clause 中。[#18720](https://github.com/ClickHouse/ClickHouse/issues/18720). [#19685](https://github.com/ClickHouse/ClickHouse/pull/19685) ([hexiaoting](https://github.com/hexiaoting)).
* 为 Buffer profile 添加单独的 config 指令。[#19721](https://github.com/ClickHouse/ClickHouse/pull/19721) ([Azat Khuzhin](https://github.com/azat)).
* 在 `system.parts` 中显示 MaterializeMySQL 表。[#19770](https://github.com/ClickHouse/ClickHouse/pull/19770) ([Stig Bakken](https://github.com/stigsb)).
* 重启后会将 MaxDDLEntryID 初始化为最后一个值。在此 PR 之前，MaxDDLEntryID 会一直保持为零，直到处理新的 DDLTask。[#19924](https://github.com/ClickHouse/ClickHouse/pull/19924) ([Amos Bird](https://github.com/amosbird)).
* 为插入到分布式表时 block 结构不匹配的情况增加了转换支持。[#19947](https://github.com/ClickHouse/ClickHouse/pull/19947) ([Azat Khuzhin](https://github.com/azat)).
* 如果用户调用 `JSONExtract` 函数并请求 `Float32` 类型，则允许不精确地转换为结果类型。例如，JSON 中的数字 `0.1` 是双精度的，无法表示为 Float32，但用户仍然希望得到该值。此前版本会对非 `Nullable` 类型返回 0，对 `Nullable` 类型返回 NULL，以表明该转换不精确。这个逻辑在语义上完全正确，但会让用户感到意外，并引发疑问。此更改关闭了 [#13962](https://github.com/ClickHouse/ClickHouse/issues/13962)。[#19960](https://github.com/ClickHouse/ClickHouse/pull/19960) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 现在可以通过 mysql 副本的 config 部分中的 `opt_reconnect` 参数控制 `MYSQL_OPT_RECONNECT` 选项的值。[#19998](https://github.com/ClickHouse/ClickHouse/pull/19998) ([Alexander Kazakov](https://github.com/Akazz)).
* 在 IDisk::getType() 中返回 `DiskType` 而不是 `String`，以与其余存储接口保持一致。[#19999](https://github.com/ClickHouse/ClickHouse/pull/19999) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* 修复了 executable 字典中的数据竞争问题，该问题仅会在误用时出现 (即 script 忽略输入而返回数据时) 。[#20045](https://github.com/ClickHouse/ClickHouse/pull/20045) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 在 `system.tables` 中显示 MaterializeMySQL 表的完整详细信息。[#20051](https://github.com/ClickHouse/ClickHouse/pull/20051) ([Stig Bakken](https://github.com/stigsb)).
* 支持对 system.zookeeper 路径进行 IN 查询。[#20105](https://github.com/ClickHouse/ClickHouse/pull/20105) ([小路](https://github.com/nicelulu)).
* 1. 在配额计算中，SHOW TABLES 现在视为一次查询，而不是两次查询。 2. SYSTEM 查询现在也会计入配额。 3. 修复了配额消耗中时间间隔结束时间的计算问题。 [#20106](https://github.com/ClickHouse/ClickHouse/pull/20106) ([Vitaly Baranov](https://github.com/vitlibar)).
* * 修复适用于 DateTime64 的 toDateTime64(toDate()/toDateTime())——实现 DateTime64 的钳位，使其行为与 DateTime 一致。[#20131](https://github.com/ClickHouse/ClickHouse/pull/20131) ([Azat Khuzhin](https://github.com/azat)) 。
* 现在可在启动时通过提供 `CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT` 来配置 `access_management` 设置，默认值为禁用 (`0`) ，这也是此前的默认值。[#20139](https://github.com/ClickHouse/ClickHouse/pull/20139) ([Marquitos](https://github.com/sonirico)).
* 已将 `CacheDictionary`、`ComplexCacheDictionary`、`SSDCacheDictionary`、`SSDComplexKeyDictionary` 更新为使用 LRUHashMap 作为底层索引。[#20164](https://github.com/ClickHouse/ClickHouse/pull/20164) ([Maksim Kita](https://github.com/kitaisreal)).
* bitmap 函数现已支持所有原生整数类型。[#20171](https://github.com/ClickHouse/ClickHouse/pull/20171) ([Amos Bird](https://github.com/amosbird)).
* 将 count(constant)、sum(1) 规范化为 count()。这对于 projection 查询路由是必需的。[#20175](https://github.com/ClickHouse/ClickHouse/pull/20175) ([Amos Bird](https://github.com/amosbird)).
* 对 `avg` 聚合函数内部的算术表达式执行代数优化。关闭 [#20092](https://github.com/ClickHouse/ClickHouse/issues/20092)。[#20183](https://github.com/ClickHouse/ClickHouse/pull/20183) ([flynn](https://github.com/ucasfl)).
* 无锁的 `SYSTEM FLUSH DISTRIBUTED`。[#20215](https://github.com/ClickHouse/ClickHouse/pull/20215) ([Azat Khuzhin](https://github.com/azat)).
* 从整数到 Decimal 类型的隐式转换在整数值无法容纳进 Decimal 类型时也可能成功。现在会抛出 `ARGUMENT_OUT_OF_BOUND`。[#20232](https://github.com/ClickHouse/ClickHouse/pull/20232) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 不再允许对明确禁止的函数进行提前常量折叠。[#20303](https://github.com/ClickHouse/ClickHouse/pull/20303) ([Azat Khuzhin](https://github.com/azat)).
* 使 FQDN 和其他与 DNS 相关的函数能够在 alpine 镜像中正常工作。[#20336](https://github.com/ClickHouse/ClickHouse/pull/20336) ([filimonov](https://github.com/filimonov)).
* 修复了 distributed DDL task 的执行与 DDL queue 清理之间的竞争问题。现在，如果存在活动工作线程，就无法从 ZooKeeper 中移除 DDL task。修复了 [#20016](https://github.com/ClickHouse/ClickHouse/issues/20016)。[#20448](https://github.com/ClickHouse/ClickHouse/pull/20448) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 改进了由 Arrays 和 Tuples 组合而成的数据类型的序列化。改进了枚举数据类型与 Protobuf 枚举类型的匹配。修复了 `Map` 数据类型的序列化。省略的值现在会使用默认值填充。[#20506](https://github.com/ClickHouse/ClickHouse/pull/20506) ([Vitaly Baranov](https://github.com/vitlibar)).
* [https://github.com/ClickHouse/ClickHouse/issues/20576](https://github.com/ClickHouse/ClickHouse/issues/20576)。[#20596](https://github.com/ClickHouse/ClickHouse/pull/20596) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 函数 &#39;reinterpretAs(x, Type)&#39; 已重命名为 &#39;reinterpret(x, Type)&#39;。[#20611](https://github.com/ClickHouse/ClickHouse/pull/20611) ([Maksim Kita](https://github.com/kitaisreal)).
* 在加载 mysql 源的配置时，ClickHouse 现在会将具有相同优先级的副本列表随机打乱，以确保选择 mysql 端点时采用轮询逻辑。此更改关闭了 [#20629](https://github.com/ClickHouse/ClickHouse/issues/20629)。[#20632](https://github.com/ClickHouse/ClickHouse/pull/20632) ([Alexander Kazakov](https://github.com/Akazz)).
* 使用 distributed&#95;group&#95;by&#95;no&#95;merge 时，仅在发起端对已排序的块执行合并。[#20882](https://github.com/ClickHouse/ClickHouse/pull/20882) ([Azat Khuzhin](https://github.com/azat)).
* * 查询 system.parts &amp; system.parts&#95;columns 时，仅填充请求的列。解决了 [#19570](https://github.com/ClickHouse/ClickHouse/issues/19570)。... [#21035](https://github.com/ClickHouse/ClickHouse/pull/21035) ([Anmol Arora](https://github.com/anmolarora)) 。
* 可用性改进：`DateTime64` 的解析更加一致：现在可以识别以带标度整数形式指定的亚秒分辨率 Unix timestamp (例如 `1111111111222`，而不是 `1111111111.222`) 。此更改修复了 [#13194](https://github.com/ClickHouse/ClickHouse/issues/13194)。[#21053](https://github.com/ClickHouse/ClickHouse/pull/21053) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* MySQL 字典源现在会在发生异常连接故障时进行重试 (即查询期间与 MySQL 服务器的连接丢失) ；这种情况有时会出现在 SSL/TLS 连接中。[#21237](https://github.com/ClickHouse/ClickHouse/pull/21237) ([Alexander Kazakov](https://github.com/Akazz)) 。
* 如果某一列被 materialized view 引用，则禁止删除该列。修复了 [#21164](https://github.com/ClickHouse/ClickHouse/issues/21164)。[#21303](https://github.com/ClickHouse/ClickHouse/pull/21303) ([flynn](https://github.com/ucasfl)) 。
* 提升了对 mysql 客户端的兼容性：1. mysql jdbc 2. mycli。[#21367](https://github.com/ClickHouse/ClickHouse/pull/21367) ([Amos Bird](https://github.com/amosbird)) 。
* 表函数的压缩方法现已支持不区分大小写。同时修复了 `LZMA` 压缩方法只能以大写形式检查的问题。[#21416](https://github.com/ClickHouse/ClickHouse/pull/21416) ([Vladimir Chebotarev](https://github.com/excitoon)) 。
