  ### ClickHouse 发布 v24.10.1.2812-稳定版本 (9cd0a3738d5) FIXME，相较于 v24.10.1.1-new (b12a3677418)
</div>

<div id="backward-incompatible-change">
  #### 不兼容变更
</div>

* 当子查询位于括号内时，现在允许在带有 `UNION` 的查询链中将 `SETTINGS` 写在 `FORMAT` 之前。这修复了 [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712)。同时还更改了在同一查询序列中两次指定 SETTINGS clause 时的行为：离相应子查询最近的 SETTINGS clause 将优先生效。在此前的版本中，最外层的 SETTINGS clause 可能会覆盖内层的设置。 [#68614](https://github.com/ClickHouse/ClickHouse/pull/68614) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 现在默认允许对 `[PRE]WHERE` clause 中的过滤条件重新排序。可通过将 `allow_reorder_prewhere_conditions` 设置为 `false` 来禁用。 [#70657](https://github.com/ClickHouse/ClickHouse/pull/70657) ([Nikita Taranov](https://github.com/nickitat)).
* 修复了 `optimize_functions_to_subcolumns` 优化问题 (此前可能导致 `Invalid column type for ColumnUnique::insertRangeFrom. Expected String, got LowCardinality(String)` 错误) ，方式是在 `mapKeys`/`mapValues` 中保留 `LowCardinality` 类型。 [#70716](https://github.com/ClickHouse/ClickHouse/pull/70716) ([Azat Khuzhin](https://github.com/azat)).
* 移除了 `idxd-config` 库，因为其许可证不兼容。同时也移除了 Experimental 的 Intel DeflateQPL codec。 [#70987](https://github.com/ClickHouse/ClickHouse/pull/70987) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新特性
</div>

* MongoDB 集成已重构：从已弃用的 Poco::MongoDB 迁移到新的驱动 mongocxx，移除了对已弃用旧协议的支持，支持通过 URI 连接，支持所有 MongoDB 类型，支持在 MongoDB 端执行 WHERE 和 ORDER BY 语句，并对 MongoDB 不支持的 expression 施加限制。 [#63279](https://github.com/ClickHouse/ClickHouse/pull/63279) ([Kirill Nikiforov](https://github.com/allmazz)).
* clickhouse-client 新增 `--progress-table` 选项，可打印一张展示查询执行期间指标变化的表；同时新增与 `--progress-table` 选项关联的 `--enable-progress-table-toggle`，按下控制键 (Space) 即可切换进度表的渲染。 [#63689](https://github.com/ClickHouse/ClickHouse/pull/63689) ([Maria Khristenko](https://github.com/mariaKhr)).
* 现已允许授予对通配符前缀的访问权限。`GRANT SELECT ON db.table_pefix_* TO user`。 [#65311](https://github.com/ClickHouse/ClickHouse/pull/65311) ([pufit](https://github.com/pufit)).
* 新增 system.query&#95;metric&#95;log，其中包含各个查询的内存历史记录以及来自表 system.events 的指标值，并会定期写入磁盘。 [#66532](https://github.com/ClickHouse/ClickHouse/pull/66532) ([Pablo Marcos](https://github.com/pamarcos)).
* 现在支持省略 SELECT 来编写简单查询，以启用计算器风格的表达式，例如 `ch "1 + 2"`。此行为由新设置 `implicit_select` 控制。 [#68502](https://github.com/ClickHouse/ClickHouse/pull/68502) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 支持将 clickhouse local 的 `--copy` 模式用作格式转换的快捷方式 [#68503](https://github.com/ClickHouse/ClickHouse/issues/68503)。 [#68583](https://github.com/ClickHouse/ClickHouse/pull/68583) ([Denis Hananein](https://github.com/denis-hananein)).
* 新增对 `arrayUnion` 函数的支持。 [#68989](https://github.com/ClickHouse/ClickHouse/pull/68989) ([Peter Nguyen](https://github.com/petern48)).
* 支持聚合函数 `quantileExactWeightedInterpolated`，它是基于 quantileExactWeighted 的插值版本。考虑到我们已经有 `quantileExactInterpolatedWeighted`，有些人可能会疑惑为什么还需要新的 `quantileExactWeightedInterpolated`。原因是新函数比旧函数更准确。顺便一提，这是为了兼容 Apache Gluten 中的 spark。 [#69619](https://github.com/ClickHouse/ClickHouse/pull/69619) ([李扬](https://github.com/taiyang-li)).
* 支持函数 `arrayElementOrNull`。当数组索引越界或未找到 map 键时，它会返回 null。 [#69646](https://github.com/ClickHouse/ClickHouse/pull/69646) ([李扬](https://github.com/taiyang-li)).
* 允许用户通过 `config.xml` 文件中新增的 `message_regexp` 和 `message_regexp_negative` 字段指定正则表达式，以过滤日志。为提供最直观的开发者体验，日志过滤应用于格式化后的无颜色文本。 [#69657](https://github.com/ClickHouse/ClickHouse/pull/69657) ([Peter Nguyen](https://github.com/petern48)).
* 支持在大多数函数中使用 Dynamic 类型，方法是在 Dynamic 内部类型上执行这些函数。 [#69691](https://github.com/ClickHouse/ClickHouse/pull/69691) ([Pavel Kruglov](https://github.com/Avogar)).
* 重新添加了 `RIPEMD160` 函数，该函数可计算字符串的 RIPEMD-160 加密哈希。例如：`SELECT HEX(RIPEMD160('The quick brown fox jumps over the lazy dog'))` 返回 `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`。 [#70087](https://github.com/ClickHouse/ClickHouse/pull/70087) ([Dergousov Maxim](https://github.com/m7kss1)).
* 允许为对象存储表引擎和数据湖缓存读取的文件，并使用 ETag + 文件路径的哈希作为缓存键。 [#70135](https://github.com/ClickHouse/ClickHouse/pull/70135) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 支持读取 HDFS 上的 Iceberg 表。[#70268](https://github.com/ClickHouse/ClickHouse/pull/70268) ([flynn](https://github.com/ucasfl)).
* 允许在设置 `input_format_binary_read_json_as_string/output_format_binary_write_json_as_string` 启用时，在 RowBinary format 中将 JSON type 作为 binary string 进行读写。[#70288](https://github.com/ClickHouse/ClickHouse/pull/70288) ([Pavel Kruglov](https://github.com/Avogar)).
* 允许在 Native format 中将 JSON 列序列化/反序列化为单个 String 列。输出时，使用设置 `output_format_native_write_json_as_string`。输入时，在列数据前使用 serialization version `1`。[#70312](https://github.com/ClickHouse/ClickHouse/pull/70312) ([Pavel Kruglov](https://github.com/Avogar)).
* 支持标准 CTE 写法 `with insert`，此前仅支持 `insert ... with ...`。[#70593](https://github.com/ClickHouse/ClickHouse/pull/70593) ([Shichao Jin](https://github.com/jsc0218)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 为 `pointInPolygon` 增加 minmax 索引支持。[#62085](https://github.com/ClickHouse/ClickHouse/pull/62085) ([JackyWoo](https://github.com/JackyWoo)).
* 新增对 Parquet 布隆过滤器的支持。[#62966](https://github.com/ClickHouse/ClickHouse/pull/62966) ([Arthur Passos](https://github.com/arthurpassos)).
* 将 parts 重命名改为无锁方式，以避免 INSERT 因 parts 锁影响 SELECT (通常情况下，在启用 `fsync_part_directory` 时，INSERT 与 SELECT 并行执行可使 SELECT 的 QPS 提升 2 倍；在高负载下效果更明显) 。注意，目前仅 `ReplicatedMergeTree` 包含此改动。[#64955](https://github.com/ClickHouse/ClickHouse/pull/64955) ([Azat Khuzhin](https://github.com/azat)).
* 在 `materialize ttl` 上遵循 `ttl_only_drop_parts`；仅读取重新计算 TTL 所需的列，并通过将 parts 替换为空 part 来删除它们。[#65488](https://github.com/ClickHouse/ClickHouse/pull/65488) ([Andrey Zvonov](https://github.com/zvonand)).
* 重构 `IDisk` 和 `IObjectStorage` 以提升性能。来自 `plain` 和 `plain_rewritable` 对象存储的表初始化速度将更快。[#68146](https://github.com/ClickHouse/ClickHouse/pull/68146) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 优化了 ThreadPool 中的线程创建，以尽量减少锁争用。现在，线程创建在临界区外执行，从而避免高负载条件下作业调度和线程管理出现延迟。这使 ClickHouse 在高并发负载下的响应速度显著提升。[#68694](https://github.com/ClickHouse/ClickHouse/pull/68694) ([filimonov](https://github.com/filimonov)).
* 支持从 ORC 读取 LowCardinality String 列。[#69481](https://github.com/ClickHouse/ClickHouse/pull/69481) ([李扬](https://github.com/taiyang-li)).
* 新增可将数据直接解析到稀疏列中的能力。[#69828](https://github.com/ClickHouse/ClickHouse/pull/69828) ([Anton Popov](https://github.com/CurtizJ)).
* 支持并行读取 Parquet 行组，并在单线程模式下预取行组。[#69862](https://github.com/ClickHouse/ClickHouse/pull/69862) ([LiuNeng](https://github.com/liuneng1994)).
* 提升了在缺失值较多时的 formats 解析性能 (例如 `JSONEachRow`) 。[#69875](https://github.com/ClickHouse/ClickHouse/pull/69875) ([Anton Popov](https://github.com/CurtizJ)).
* 在 `part_log`、`query_views_log`、`filesystem_cache_log` 等系统日志中，对 `ProfileEvents` 使用 `LowCardinality`。[#70152](https://github.com/ClickHouse/ClickHouse/pull/70152) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 提升了 FromUnixTimestamp/ToUnixTimestamp 函数的性能。[#71042](https://github.com/ClickHouse/ClickHouse/pull/71042) ([kevinyhzou](https://github.com/KevinyhZou)).

<div id="improvement">
  #### 改进
</div>

* 允许参数化 SQL 别名。 [#50665](https://github.com/ClickHouse/ClickHouse/pull/50665) ([Anton Kozlov](https://github.com/tonickkozlov)).
* 修复了 [#57616](https://github.com/ClickHouse/ClickHouse/issues/57616)：该问题的原因是，所有正数参数都会被自动识别为 `uint64` 类型，导致在 `summapfiltered` 中无法匹配 `int` 类型的数据。这种不匹配确实容易让人困惑，因为这些 `uint64` 参数并不是由用户显式指定的。另外，如果参数是 `[1,2,3,toint8(-3)]`，由于 `getleastsupertype()`，这些参数会被统一视为 `int` 类型，从而导致 `'1,2,3'` 同样无法匹配 `summapfiltered` 中的 `uint` 类型数据。 [#58408](https://github.com/ClickHouse/ClickHouse/pull/58408) ([Chen768959](https://github.com/Chen768959)).
* `ALTER TABLE .. REPLACE PARTITION` 现在不再等待其他分区中发生的变更/合并操作。 [#59138](https://github.com/ClickHouse/ClickHouse/pull/59138) ([Vasily Nemkov](https://github.com/Enmk)).
* Replicated 数据库现已支持可刷新materialized view。 [#60669](https://github.com/ClickHouse/ClickHouse/pull/60669) ([Michael Kolupaev](https://github.com/al13n321)).
* 现在会在 `data/database_name/` directory 中为表数据的实际路径创建符号链接；具体路径取决于 storage policy，而不再是 default disk 上的 `store/...` directory。 [#61777](https://github.com/ClickHouse/ClickHouse/pull/61777) ([Kirill](https://github.com/kirillgarbar)).
* 在全局 Context 对象中应用 configuration 更新。此改动修复了 [#62308](https://github.com/ClickHouse/ClickHouse/issues/62308) 等问题。 [#62944](https://github.com/ClickHouse/ClickHouse/pull/62944) ([Amos Bird](https://github.com/amosbird)).
* 重构了用于控制并行副本算法行为的设置。简要回顾一下：ClickHouse 有四种涉及多个副本的并行读取算法，这体现在设置 `parallel_replicas_mode` 中，其默认值为 `read_tasks`。此外，还新增了开关设置 `enable_parallel_replicas`。 [#63151](https://github.com/ClickHouse/ClickHouse/pull/63151) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了 `ReadSettings` 未使用用户设置值、而只使用默认值的问题。 [#65625](https://github.com/ClickHouse/ClickHouse/pull/65625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 从 JSON 解析枚举 field 时，包含整数的字符串将被解释为对应的枚举元素。此改动关闭了 [#65119](https://github.com/ClickHouse/ClickHouse/issues/65119)。 [#66801](https://github.com/ClickHouse/ClickHouse/pull/66801) ([scanhex12](https://github.com/scanhex12)).
* 允许对空字符串执行 `TRIM` 的 `LEADING` 或 `TRAILING` 操作，并将其视为空操作。关闭 [#67792](https://github.com/ClickHouse/ClickHouse/issues/67792)。 [#68455](https://github.com/ClickHouse/ClickHouse/pull/68455) ([Peter Nguyen](https://github.com/petern48)).
* 支持通过查询创建表：`CREATE TABLE ... CLONE AS ...`。它会克隆源表的 schema，然后将所有分区附加到新创建的表上。此功能仅支持 `MergeTree` 家族的表。关闭 [#65015](https://github.com/ClickHouse/ClickHouse/issues/65015)。 [#69091](https://github.com/ClickHouse/ClickHouse/pull/69091) ([tuanpach](https://github.com/tuanpach)).
* 在 Gluten ClickHouse 中，Spark 的 timestamp 类型会映射到 ClickHouse 的 datetime64(6) 类型。将时间戳 &#39;2012-01-01 00:11:22&#39; 转换为字符串时，Spark 返回 &#39;2012-01-01 00:11:22&#39;，而 Gluten ClickHouse 返回 &#39;2012-01-01 00:11:22.000000&#39;。[#69179](https://github.com/ClickHouse/ClickHouse/pull/69179) ([Wenzheng Liu](https://github.com/lwz9103)) 。
* 当 `enable_analyzer` 设置为 `true` 时，始终使用新的 analyzer 计算常量表达式。支持在不通过 `SELECT` 查询进行常量表达式计算的情况下，计算 `executable()` 表函数参数。[#69292](https://github.com/ClickHouse/ClickHouse/pull/69292) ([Dmitry Novik](https://github.com/novikd)) 。
* 新增 `enable_secure_identifiers`，用于禁止不安全的标识符。[#69411](https://github.com/ClickHouse/ClickHouse/pull/69411) ([tuanpach](https://github.com/tuanpach)) 。
* 新增 `show_create_query_identifier_quoting_rule`，用于定义 show create 查询结果中标识符的引号规则。可选值：- `user_display`：当标识符是关键字时。- `when_necessary`：当标识符是 `{"distinct", "all", "table"}` 之一，或可能造成歧义时：列名、字典属性名。- `always`：始终为标识符加引号。[#69448](https://github.com/ClickHouse/ClickHouse/pull/69448) ([tuanpach](https://github.com/tuanpach)) 。
* 对 [https://github.com/ClickHouse/ClickHouse/pull/69346](https://github.com/ClickHouse/ClickHouse/pull/69346) 的后续修复。该处描述的第 4 点现也已生效。[#69563](https://github.com/ClickHouse/ClickHouse/pull/69563) ([Vitaly Baranov](https://github.com/vitlibar)) 。
* 实现了 Avro Union 与 ClickHouse Variant 类型之间的通用 SerDe。已解决 [#69713](https://github.com/ClickHouse/ClickHouse/issues/69713)。[#69712](https://github.com/ClickHouse/ClickHouse/pull/69712) ([Jiří Kozlovský](https://github.com/jirislav)) 。
