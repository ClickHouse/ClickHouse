<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 移除系统表 `generate_series` 和 `generateSeries`。这些表是在此处误加的：[#59390](https://github.com/ClickHouse/ClickHouse/issues/59390)。[#71091](https://github.com/ClickHouse/ClickHouse/pull/71091) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 移除 `StorageExternalDistributed`。关闭 [#70600](https://github.com/ClickHouse/ClickHouse/issues/70600)。### 面向用户变更的文档条目。[#71176](https://github.com/ClickHouse/ClickHouse/pull/71176) ([flynn](https://github.com/ucasfl)) 。
* 修复了 JSON 子列文件中特殊符号未转义而可能导致的 `No such file or directory` 错误。[#71182](https://github.com/ClickHouse/ClickHouse/pull/71182) ([Pavel Kruglov](https://github.com/Avogar)) 。
* Kafka、NATS 和 RabbitMQ 表引擎现在在 `SOURCES` 层级中分别由各自独立的授权控制。请为所有使用这些引擎类型创建表的非 `default` 数据库用户添加相应授权。[#71250](https://github.com/ClickHouse/ClickHouse/pull/71250) ([Christoph Wurm](https://github.com/cwurm)) 。
* 在执行完整的变更查询前先进行检查 (包括子查询) 。这可以防止误执行无效查询，并避免积累会阻塞有效变更的无效变更。[#71300](https://github.com/ClickHouse/ClickHouse/pull/71300) ([Christoph Wurm](https://github.com/cwurm)) 。
* 将文件系统缓存设置 `skip_download_if_exceeds_query_cache` 重命名为 `filesystem_cache_skip_download_if_exceeds_per_query_cache_write_limit`。[#71578](https://github.com/ClickHouse/ClickHouse/pull/71578) ([Kseniia Sumarokova](https://github.com/kssenii)) 。
* 移除 `deltaSumTimestamp` 对 `Enum` 以及 `UInt128` 和 `UInt256` 参数的支持。移除 `deltaSumTimestamp` 的第二个 (“timestamp”) 参数对 `Int8`、`UInt8`、`Int16` 和 `UInt16` 的支持。[#71790](https://github.com/ClickHouse/ClickHouse/pull/71790) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。

<div id="new-feature">
  #### 新特性
</div>

* 新增数据类型 `BFloat16`，用于表示 16 位浮点数，具有 8 位指数、符号位和 7 位尾数。此更改关闭了 [#44206](https://github.com/ClickHouse/ClickHouse/issues/44206) 和 [#49937](https://github.com/ClickHouse/ClickHouse/issues/49937)。[#64712](https://github.com/ClickHouse/ClickHouse/pull/64712) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* ~~新增一个选项，用于选择 join 的哪一侧在查询计划中充当内部表。该选项由 `query_plan_join_inner_table_selection` 控制，可设置为 `auto`。在此模式下，ClickHouse 将尝试选择行数最少的表。~~ 已重新提交 [https://github.com/ClickHouse/ClickHouse/pull/71577](https://github.com/ClickHouse/ClickHouse/pull/71577)。[#68682](https://github.com/ClickHouse/ClickHouse/pull/68682) ([Vladimir Cherkasov](https://github.com/vdimir)) 。
* 添加了 `CHECK GRANT` 查询，用于检查当前用户/角色是否已被授予特定权限，以及相应的表/列是否存在于内存中。[#68885](https://github.com/ClickHouse/ClickHouse/pull/68885) ([Unalian](https://github.com/Unalian)) 。
* 添加了用于描述 workload 和资源管理的 SQL 语法。[https://clickhouse.com/docs/en/operations/workload-scheduling](https://clickhouse.com/docs/en/operations/workload-scheduling)。[#69187](https://github.com/ClickHouse/ClickHouse/pull/69187) ([Sergei Trifonov](https://github.com/serxa)) 。
* 添加了服务器设置 `async_load_system_database`，允许服务器在 system database 未完全加载时启动。如果系统表很多，这有助于更快启动 ClickHouse。[#69847](https://github.com/ClickHouse/ClickHouse/pull/69847) ([Sergei Trifonov](https://github.com/serxa)) 。
* 允许每种身份验证方法拥有各自的过期时间，并将该设置从用户实体中移除。[#70090](https://github.com/ClickHouse/ClickHouse/pull/70090) ([Arthur Passos](https://github.com/arthurpassos)) 。
* 将外部用户角色从查询发起节点传递到 cluster 中的其他节点。当只有发起节点能够访问外部身份验证器 (如 LDAP) 时，这会很有帮助。[#70332](https://github.com/ClickHouse/ClickHouse/pull/70332) ([Andrey Zvonov](https://github.com/zvonand)) 。
* 支持从 String 执行 alter 到 JSON。此 PR 还将 JSON 和 Dynamic 类型的序列化更改为新的 V2 版本。旧版 V1 仍可通过启用设置 `merge_tree_use_v1_object_and_dynamic_serialization` 继续使用 (可在升级期间使用，以便在需要时无问题回滚版本) 。[#70442](https://github.com/ClickHouse/ClickHouse/pull/70442) ([Pavel Kruglov](https://github.com/Avogar)) 。
* 为用于用户身份验证的 S3 endpoints 添加了一种新的请求头类型 (`access_header`) 。这样可以获取一个最低优先级的访问请求头，它会被来自任何其他来源的 `access_key_id` 覆盖 (例如表 schema 或 named collection) 。[#71011](https://github.com/ClickHouse/ClickHouse/pull/71011) ([MikhailBurdukov](https://github.com/MikhailBurdukov)) 。
* settings tiers 的初始实现。[#71145](https://github.com/ClickHouse/ClickHouse/pull/71145) ([Raúl Marín](https://github.com/Algunenano)) 。
* 添加了对 ORDER BY WITH FILL 中 staleness 子句的支持。[#71151](https://github.com/ClickHouse/ClickHouse/pull/71151) ([Mikhail Artemenko](https://github.com/Michicosun)) 。
* 通过对 JSON string 进行序列化/反序列化，实现了从 Map/Tuple/Object 到新 JSON 的简单 CAST。[#71320](https://github.com/ClickHouse/ClickHouse/pull/71320) ([Pavel Kruglov](https://github.com/Avogar)) 。
* 为聚合函数 `any` 新增别名 `anyRespectNulls`、`firstValueRespectNulls` 和 `anyValueRespectNulls`。还为聚合函数 `anyLast` 新增了别名 `anyLastRespectNulls` 和 `lastValueRespectNulls`。这样就可以使用更自然的纯驼峰命名语法，而不是驼峰加下划线混用的语法，例如：使用 `SELECT anyLastRespectNullsStateIf` 而不是 `anyLast_respect_nullsStateIf`。[#71403](https://github.com/ClickHouse/ClickHouse/pull/71403) ([Peter Nguyen](https://github.com/petern48)).
* 新增配置参数 `date_time_utc`，使 JSON 日志格式化支持 RFC 3339/ISO8601 格式的 UTC 日期时间。[#71560](https://github.com/ClickHouse/ClickHouse/pull/71560) ([Ali](https://github.com/xogoodnow)).
* 优化了在数据分区片段的粒度为常量时索引粒度值的内存占用。新增了一个始终为数据分区片段选择固定粒度的选项 (设置 `use_const_adaptive_granularity`) ，有助于确保这部分内存始终得到优化。在大规模负载场景下 (共享存储中的数万亿行) ，这有助于避免因数据分区片段元数据 (索引粒度值) 导致的内存占用持续增长。[#71786](https://github.com/ClickHouse/ClickHouse/pull/71786) ([Anton Popov](https://github.com/CurtizJ)).
* 将 `allowed_feature_tier` 实现为一个全局开关，用于禁用所有 Experimental / Beta 功能。[#71841](https://github.com/ClickHouse/ClickHouse/pull/71841) ([Raúl Marín](https://github.com/Algunenano)).
* 新增 `iceberg[S3;HDFS;Azure]Cluster`、`deltaLakeCluster`、`hudiCluster` 表函数。[#72045](https://github.com/ClickHouse/ClickHouse/pull/72045) ([Mikhail Artemenko](https://github.com/Michicosun)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 新增 2 个设置：`short_circuit_function_evaluation_for_nulls` 和 `short_circuit_function_evaluation_for_nulls_threshold`。当数据块中 NULL 值的占比超过指定阈值时，可在 `Nullable` 列上以短路方式执行函数。这意味着函数只会对非 NULL 值所在的行执行。该功能仅适用于这样一类函数：只要任一参数为 NULL，该行的返回值就为 NULL。[#60129](https://github.com/ClickHouse/ClickHouse/pull/60129) ([李扬](https://github.com/taiyang-li)).
* 现在，对于 `join_algorithm='parallel_hash'`，在线程间分发输入块以进行并行处理时，不再复制输入块中的列。[#67782](https://github.com/ClickHouse/ClickHouse/pull/67782) ([Nikita Taranov](https://github.com/nickitat)).
* 优化了用于非相交 parts 的 `Replacing` merge 算法。[#70977](https://github.com/ClickHouse/ClickHouse/pull/70977) ([Anton Popov](https://github.com/CurtizJ)).
* 不再为指标和 `system.detached_parts` 列出位于 readonly 和 write-once 磁盘上的 detached parts。[#71086](https://github.com/ClickHouse/ClickHouse/pull/71086) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 默认不再计算 heavy asynchronous metrics。该功能在 [#40332](https://github.com/ClickHouse/ClickHouse/issues/40332) 中引入，但仅为单个客户保留这样一个高开销的后台任务并不合适。[#71087](https://github.com/ClickHouse/ClickHouse/pull/71087) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 通过缩小临界区，提升 `system.query_metric_log` 收集时间间隔的性能和准确性。[#71473](https://github.com/ClickHouse/ClickHouse/pull/71473) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="improvement">
  #### 改进
</div>

* 使用常量数组和常量捕获参数的高阶函数将返回常量。[#58400](https://github.com/ClickHouse/ClickHouse/pull/58400) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 通过生成虚拟行实现按顺序读取优化，从而在归并排序期间读取更少的数据，尤其在存在多个 parts 时非常有用。[#62125](https://github.com/ClickHouse/ClickHouse/pull/62125) ([Shichao Jin](https://github.com/jsc0218)).
* 查询计划步骤名称 (`EXPLAIN PLAN json=1`) 和管道处理器名称 (`EXPLAIN PIPELINE compact=0,graph=1`) 现在都带有唯一 id 作为后缀。这样就可以将处理器 profiler 输出和 OpenTelemetry 链路追踪与 EXPLAIN 输出对应起来。[#63518](https://github.com/ClickHouse/ClickHouse/pull/63518) ([qhsong](https://github.com/qhsong)).
* 新增了在写入 Azure Blob 存储后检查对象是否存在的选项，由设置 `check_objects_after_upload` 控制。[#64847](https://github.com/ClickHouse/ClickHouse/pull/64847) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 修复了 HashTable destroyElements 中 use-after-dtor 的逻辑问题。[#65279](https://github.com/ClickHouse/ClickHouse/pull/65279) ([cangyin](https://github.com/cangyin)).
* 在 `clickhouse-local` 中默认使用 `Atomic` 数据库。解决了 [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647) 中的第 1 和第 5 项。关闭了 [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817)。[#68024](https://github.com/ClickHouse/ClickHouse/pull/68024) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 写入缓冲区必须显式取消或完成。发生异常时会中断 HTTP 协议，以便向客户端告知错误。[#68800](https://github.com/ClickHouse/ClickHouse/pull/68800) ([Sema Checherinda](https://github.com/CheSema)).
* 通过创建 replica&#95;dir 来报告正在运行的 DDLWorker 主机，并在 DDLWorker 中将副本标记为活跃。[#69658](https://github.com/ClickHouse/ClickHouse/pull/69658) ([tuanpach](https://github.com/tuanpach)).
* 1. 重构 `DDLQueryStatusSource`：* 将 `DDLQueryStatusSource` 重命名为 `DistributedQueryStatusSource`，并将其设为基类 * 创建两个派生自 `DDLQueryStatusSource` 的子类 `DDLOnClusterQueryStatusSource` 和 `ReplicatedDatabaseQueryStatusSource`，分别用于查询来自 `DDL On Cluster` 和 Replicated 数据库的 DDL 任务状态。2. 在 `DDLOnClusterQueryStatusSource&#96;` 中支持停止等待离线主机。[#69660](https://github.com/ClickHouse/ClickHouse/pull/69660) ([tuanpach](https://github.com/tuanpach)).
* 默认不允许在 ORDER BY/GROUP BY/PARTITION BY/PRIMARY KEY 中使用 Variant/Dynamic 类型，因为这可能导致意外结果。[#69731](https://github.com/ClickHouse/ClickHouse/pull/69731) ([Pavel Kruglov](https://github.com/Avogar)).
* 改进了 `ON CLUSTER` 备份和恢复的错误处理与取消机制：- 如果某台主机上的备份或恢复失败，会自动取消其他主机上的对应操作 - 不会再因为部分主机失败而其他主机继续执行，进而产生奇怪的错误 - 如果某台主机上的备份或恢复被取消，也会自动取消其他主机上的对应操作 - 修复了 `test_disallow_concurrency` 相关问题，现在禁用并发应能更可靠地生效 - 现在备份和恢复对 ZooKeeper 断连的容错能力大幅增强。[#70027](https://github.com/ClickHouse/ClickHouse/pull/70027) ([Vitaly Baranov](https://github.com/vitlibar)).
* 默认启用 `parallel_replicas_local_plan`。在查询发起节点上构建完整的本地执行计划，能够以更少的资源消耗提升并行副本性能，并带来更多应用查询优化的机会。[#70171](https://github.com/ClickHouse/ClickHouse/pull/70171) ([Igor Nikonov](https://github.com/devcrafter)).
* 在重启线程中而非 attach 线程中修复 ZooKeeper 里的 metadata&#95;version 记录。[#70297](https://github.com/ClickHouse/ClickHouse/pull/70297) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 新增了在 http&#95;handlers 中设置用户/密码的能力 (用于 `dynamic_query_handler`/`predefined_query_handler`) 。[#70725](https://github.com/ClickHouse/ClickHouse/pull/70725) ([Azat Khuzhin](https://github.com/azat)).
* 为 S3Queue 存储中的某些设置支持 `ALTER TABLE ... MODIFY/RESET SETTING ...`。[#70811](https://github.com/ClickHouse/ClickHouse/pull/70811) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 列出目录时不再调用对象存储 API，因为这样可能不划算。取而代之的是，将文件名列表存储在内存中。代价是初始加载时间增加，以及需要更多内存来存储文件名。[#70823](https://github.com/ClickHouse/ClickHouse/pull/70823) ([Julia Kartseva](https://github.com/jkartseva)).
* 为 `clickhouse-compressor` 添加了 `--threads` 参数，从而支持并行压缩数据。[#70860](https://github.com/ClickHouse/ClickHouse/pull/70860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了由于系统调用受限，Docker 容器中的 ClickHouse 会将 &quot;get&#95;mempolicy: Operation not permitted&quot; 打印到 stderr 的问题。[#70900](https://github.com/ClickHouse/ClickHouse/pull/70900) ([filimonov](https://github.com/filimonov)).
* 新增了重新加载客户端证书的能力，方式与重新加载服务器证书的流程相同。[#70997](https://github.com/ClickHouse/ClickHouse/pull/70997) ([Roman Antonov](https://github.com/Romeo58rus)).
* 重构了用于 DataLake Storages 的文件内部结构。[#71012](https://github.com/ClickHouse/ClickHouse/pull/71012) ([Daniil Ivanik](https://github.com/divanik)).
* 使 Replxx 客户端的历史记录大小可配置。[#71014](https://github.com/ClickHouse/ClickHouse/pull/71014) ([Jiří Kozlovský](https://github.com/jirislav)).
* 新增设置 `prewarm_mark_cache`，可在插入、合并、抓取 parts 以及表启动时，将标记加载到标记缓存中。[#71053](https://github.com/ClickHouse/ClickHouse/pull/71053) ([Anton Popov](https://github.com/CurtizJ)).
* Parquet 原生读取器支持布尔值。[#71055](https://github.com/ClickHouse/ClickHouse/pull/71055) ([Arthur Passos](https://github.com/arthurpassos)).
* 与 S3 交互时会对更多错误进行重试，例如 &quot;Malformed message&quot;。[#71088](https://github.com/ClickHouse/ClickHouse/pull/71088) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 降低了部分 S3 相关消息的日志级别。[#71090](https://github.com/ClickHouse/ClickHouse/pull/71090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 支持写入文件名中包含空格的 hdfs 文件。[#71105](https://github.com/ClickHouse/ClickHouse/pull/71105) ([exmy](https://github.com/exmy)).
* `system.session_log` 已相当可用。此更改关闭了 [#51760](https://github.com/ClickHouse/ClickHouse/issues/51760)。[#71150](https://github.com/ClickHouse/ClickHouse/pull/71150) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了使用并行副本的查询中的 RIGHT / FULL joins。现在，RIGHT joins 可以结合并行副本执行 (right table 的读取会分布到各节点) 。FULL joins 无法在节点间并行化，因此会在本地执行。[#71162](https://github.com/ClickHouse/ClickHouse/pull/71162) ([Igor Nikonov](https://github.com/devcrafter)).
* 新增了用于限制复制表、字典和视图数量的设置。[#71179](https://github.com/ClickHouse/ClickHouse/pull/71179) ([Kirill](https://github.com/kirillgarbar)).
* 如果前者可用，则使用 `AWS_CONTAINER_AUTHORIZATION_TOKEN_FILE` 而不是 `AWS_CONTAINER_AUTHORIZATION_TOKEN`。修复了 [#71074](https://github.com/ClickHouse/ClickHouse/issues/71074)。[#71269](https://github.com/ClickHouse/ClickHouse/pull/71269) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 从 RMT 重启线程中移除了创建 metadata&#95;version ZooKeeper 节点的逻辑。唯一需要创建该节点的场景，是用户从早于 20.4 的版本直接升级到晚于 24.10 的版本。ClickHouse 不支持跨度超过一年的升级，因此此时应抛出异常并要求用户逐步升级，而不是创建该节点。[#71385](https://github.com/ClickHouse/ClickHouse/pull/71385) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 在高级仪表板中新增了按主机划分的仪表盘 `Overview (host)` 和 `Cloud overview (host)`。[#71422](https://github.com/ClickHouse/ClickHouse/pull/71422) ([alesapin](https://github.com/alesapin)).
* `removeObject` 和 `removeObjects` 方法不是幂等的。由于网络错误发生重试时，结果可能会是 `object not found`，因为对象已在之前的尝试中被删除。[#71529](https://github.com/ClickHouse/ClickHouse/pull/71529) ([Sema Checherinda](https://github.com/CheSema)).
* 新增了函数 `parseDateTime64`、`parseDateTime64OrNull` 和 `parseDateTime64OrZero`。与现有函数 `parseDateTime` (及其变体) 相比，它们返回的是 `DateTime64` 类型的值，而不是 `DateTime`。[#71581](https://github.com/ClickHouse/ClickHouse/pull/71581) ([kevinyhzou](https://github.com/KevinyhZou)).
* 允许 clickhouse 在指定文件参数时作为 `--queries-file` 使用。[#71589](https://github.com/ClickHouse/ClickHouse/pull/71589) ([Raúl Marín](https://github.com/Algunenano)).
* 对内存中的 index&#95;granularity Array 进行 shrink to fit，以减少 MergeTree 表引擎家族的内存占用。[#71595](https://github.com/ClickHouse/ClickHouse/pull/71595) ([alesapin](https://github.com/alesapin)).
* `clickhouse-local` 默认使用隐式 SELECT，因此可将其当作计算器使用。改进了隐式 SELECT 模式下的语法高亮。[#71620](https://github.com/ClickHouse/ClickHouse/pull/71620) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 命令行客户端应用程序现在即使对于多语句也会进行语法高亮。[#71622](https://github.com/ClickHouse/ClickHouse/pull/71622) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 命令行应用程序现在会在发生错误时返回非零退出码。在之前的版本中，`disks` 应用程序在出错时返回零，其他应用程序在出现错误 256 (`PARTITION_ALREADY_EXISTS`) 和 512 (`SET_NON_GRANTED_ROLE`) 时也返回零。[#71623](https://github.com/ClickHouse/ClickHouse/pull/71623) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 当 user/group 以 ID 形式给出时，`clickhouse su` 会失败。此补丁修复后也接受 `UID:GID`。### 面向用户变更的文档条目。[#71626](https://github.com/ClickHouse/ClickHouse/pull/71626) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
