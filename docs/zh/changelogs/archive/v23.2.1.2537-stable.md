<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 为函数 &quot;toDayOfWeek()&quot; (别名：&quot;DAYOFWEEK&quot;) 新增了一个 mode 参数，用于指定一周是从周一还是周日开始，以及计数是从 0 还是 1 开始。为与其他日期时间函数保持一致，mode 参数被插入到 time 和 time zone 参数之间。这会破坏现有的 (此前未文档说明的) 2 参数语法 &quot;toDayOfWeek(time, time&#95;zone)&quot; 的用法。修复方法是将该函数改写为 &quot;toDayOfWeek(time, 0, time&#95;zone)&quot;。[#45233](https://github.com/ClickHouse/ClickHouse/pull/45233) ([Robert Schulze](https://github.com/rschu1ze)).
* 将设置 `max_query_cache_size` 重命名为 `filesystem_cache_max_download_size`。[#45614](https://github.com/ClickHouse/ClickHouse/pull/45614) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 修复了客户端上 FORMAT 的设置应用问题。[#46003](https://github.com/ClickHouse/ClickHouse/pull/46003) ([Azat Khuzhin](https://github.com/azat)).
* default user 默认将不再拥有访问类型 `SHOW NAMED COLLECTION` 的 permissions (例如，default user 默认将无法再像以前那样对其他用户执行 grant ALL，因此此 PR 属于向后不兼容变更) 。[#46010](https://github.com/ClickHouse/ClickHouse/pull/46010) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 移除了对设置 `materialized_postgresql_allow_automatic_update` 的支持 (该设置默认关闭) 。修复了 integration tests。[#46106](https://github.com/ClickHouse/ClickHouse/pull/46106) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 略微提升了 `countDigits` 在真实 datasets 上的性能。该变更关闭了 [#44518](https://github.com/ClickHouse/ClickHouse/issues/44518)。在之前的版本中，`countDigits(0)` 返回 `0`；现在返回 `1`，这更准确，也符合现有文档。[#46187](https://github.com/ClickHouse/ClickHouse/pull/46187) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* 增大 HTTP Transfer Encoding 的 chunk 大小，以提升通过 HTTP 接口执行大型查询时的性能。[#45593](https://github.com/ClickHouse/ClickHouse/pull/45593) ([Geoff Genz](https://github.com/genzgd)).
* 修复了从包含大量 `Array`/`Map`/`Nested` 列的表中读取数据时，短 `SELECT` 查询的性能问题。[#45630](https://github.com/ClickHouse/ClickHouse/pull/45630) ([Anton Popov](https://github.com/CurtizJ)).
* 允许对 Compact 格式的 parts 使用 Vertical merge algorithm。这将使 ClickHouse server 在后台操作中占用更少内存。此更改关闭了 [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084)。[#45681](https://github.com/ClickHouse/ClickHouse/pull/45681) ([Anton Popov](https://github.com/CurtizJ)).
* 通过使用批次读取器优化 Parquet reader。[#45878](https://github.com/ClickHouse/ClickHouse/pull/45878) ([LiuNeng](https://github.com/liuneng1994)).
* 提升 ColumnArray::filter 处理大整数和 Decimal 时的性能。[#45949](https://github.com/ClickHouse/ClickHouse/pull/45949) ([李扬](https://github.com/taiyang-li)).
* 此更改可有效降低从 ColumnNullable(UInt8) 获取过滤器的开销，并提升整体查询性能。为了评估该更改的影响，我们采用了 TPC-H 基准测试，但将列类型从非 Nullable 改为 Nullable，并以查询 QPS 作为性能指标进行测量。[#45962](https://github.com/ClickHouse/ClickHouse/pull/45962) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 将虚拟列 `_part` 和 `_partition_id` 设为 `LowCardinality(String)` 类型。关闭了 [#45964](https://github.com/ClickHouse/ClickHouse/issues/45964)。[#45975](https://github.com/ClickHouse/ClickHouse/pull/45975) ([flynn](https://github.com/ucasfl)).
* 在标度不变时提升 Decimal 转换性能。[#46095](https://github.com/ClickHouse/ClickHouse/pull/46095) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 这项引入的逻辑会在 PREWHERE 条件由多个条件的合取组成时生效 (cond1 AND cond2 AND ...) 。它会将需要读取相同列的条件分组为多个步骤。每一步之后，都会计算完整条件中对应的那一部分，并可能对结果行进行过滤。这样一来，后续步骤中需要读取的行数会更少，从而节省 IO 带宽并减少计算量。目前这项逻辑默认仍处于禁用状态。待确认不会引入任何回归后，它将在未来的发行版中的某个版本里默认启用，因此强烈建议先用于测试。可通过 2 个设置进行控制：&quot;enable&#95;multiple&#95;prewhere&#95;read&#95;steps&quot; 和 &quot;move&#95;all&#95;conditions&#95;to&#95;prewhere&quot;。[#46140](https://github.com/ClickHouse/ClickHouse/pull/46140) ([Alexander Gololobov](https://github.com/davenger)).
* 允许提高读取数据时的预取。 [#46168](https://github.com/ClickHouse/ClickHouse/pull/46168) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 将 arrayExists(x -&gt; x = 1, arr) 改写为 has(arr, 1)，可使性能提升 1.34 倍。 [#46188](https://github.com/ClickHouse/ClickHouse/pull/46188) ([李扬](https://github.com/taiyang-li)).
* 修复非远程 disk 上 vertical merges 的 memory usage 过高问题。对远程 disk 遵循 `max_insert_delayed_streams_for_parallel_write`。 [#46275](https://github.com/ClickHouse/ClickHouse/pull/46275) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 将 zstd 更新到 v1.5.4。它在性能和压缩率方面有一些小幅改进。如果你运行的是不同 ClickHouse 版本的副本，可能会看到带有说明信息的合理错误消息 `Data after merge/mutation is not byte-identical to data on another replicas.`。这些消息是正常的，无需担心。 [#46280](https://github.com/ClickHouse/ClickHouse/pull/46280) ([Raúl Marín](https://github.com/Algunenano)).
* 允许对 Compact 格式的 parts 使用 Vertical merge algorithm。这将使 ClickHouse server 在后台操作中占用更少内存。此项变更关闭了 [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084)。 [#46282](https://github.com/ClickHouse/ClickHouse/pull/46282) ([Anton Popov](https://github.com/CurtizJ)).
* 修复由 [#39737](https://github.com/ClickHouse/ClickHouse/issues/39737) 导致的性能下降问题。 [#46309](https://github.com/ClickHouse/ClickHouse/pull/46309) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 即使在 replication queue 很大的情况下，`replicas_status` handle 也能快速响应。 [#46310](https://github.com/ClickHouse/ClickHouse/pull/46310) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
