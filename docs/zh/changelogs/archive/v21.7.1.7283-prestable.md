<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 改进了带有显式定义的大型集合的查询性能。新增了兼容性设置 `legacy_column_name_of_tuple_literal`。在将集群从低于 21.7 的版本滚动更新到更高版本时，建议将其设置为 `true`。否则，更新期间，`IN` 子句中带有显式定义集合的分布式查询可能会失败。 [#25371](https://github.com/ClickHouse/ClickHouse/pull/25371) ([Anton Popov](https://github.com/CurtizJ)).
* clickhouse-keeper 中最大缓冲区大小的变更与前后版本均不兼容。最好现在就处理 (在生产环境之前) ，不要等到以后。 [#25421](https://github.com/ClickHouse/ClickHouse/pull/25421) ([alesapin](https://github.com/alesapin)).



<div id="new-feature">
  #### 新特性
</div>

* 添加对 HDFS 上 VFS 的支持。[#11058](https://github.com/ClickHouse/ClickHouse/pull/11058) ([overshov](https://github.com/overshov)).
* 提供了一种在数据 (可能) 仍然存在、但 ZooKeeper 元数据丢失时恢复复制表的方法。解决了 [#13458](https://github.com/ClickHouse/ClickHouse/issues/13458)。[#13652](https://github.com/ClickHouse/ClickHouse/pull/13652) ([Mike Kot](https://github.com/myrrc)).
* 实现了对 `flow analysis` 很有用的 `sequenceNextNode()` 函数。[#19766](https://github.com/ClickHouse/ClickHouse/pull/19766) ([achimbab](https://github.com/achimbab)).
* 为配置加载器添加了 YAML 配置支持。此更改关闭了 [#3607](https://github.com/ClickHouse/ClickHouse/issues/3607)。[#21858](https://github.com/ClickHouse/ClickHouse/pull/21858) ([BoloniniD](https://github.com/BoloniniD)).
* 添加了 `dateName` 函数。[#23085](https://github.com/ClickHouse/ClickHouse/pull/23085) ([Daniil Kondratyev](https://github.com/dankondr)).
* 添加了 `quantileBFloat16` 聚合函数，以及对应的 `quantilesBFloat16` 和 `medianBFloat16`。这是一个非常简单且快速的分位数估计器，相对误差不超过 0.390625%。此更改关闭了 [#16641](https://github.com/ClickHouse/ClickHouse/issues/16641)。[#23204](https://github.com/ClickHouse/ClickHouse/pull/23204) ([Ivan Novitskiy](https://github.com/RedClusive)).
* `Join` 表引擎现已支持 `ALTER DELETE` 查询。[#23260](https://github.com/ClickHouse/ClickHouse/pull/23260) ([foolchi](https://github.com/foolchi)).
* 添加了一个新的布尔设置 `prefer_global_in_and_join`，默认将所有 IN/JOIN 视为 GLOBAL IN/JOIN。[#23434](https://github.com/ClickHouse/ClickHouse/pull/23434) ([Amos Bird](https://github.com/amosbird)).
* 添加了 `bitpositionToArray` 函数。[#23843](https://github.com/ClickHouse/ClickHouse/pull/23843) ([kevin wan](https://github.com/MaxWk)).
* 添加了聚合函数 `segmentLengthSum`。[#24250](https://github.com/ClickHouse/ClickHouse/pull/24250) ([flynn](https://github.com/ucasfl)).
* 在 Arrow/Parquet/ORC 中支持 structs 和 Map，并在 Arrow 输入/输出格式中支持字典。引入了新设置 `output_format_arrow_low_cardinality_as_dictionary`。[#24341](https://github.com/ClickHouse/ClickHouse/pull/24341) ([Kruglov Pavel](https://github.com/Avogar)).
* AARCH64 现已支持 `compile_expression` 设置。[#24342](https://github.com/ClickHouse/ClickHouse/pull/24342) ([Maksim Kita](https://github.com/kitaisreal)).
* 现在 clickhouse-keeper 支持类似 ZooKeeper 的 `digest` ACL。[#24448](https://github.com/ClickHouse/ClickHouse/pull/24448) ([alesapin](https://github.com/alesapin)).
* 实现了 `h3ToGeo` 函数。[#24867](https://github.com/ClickHouse/ClickHouse/pull/24867) ([Bharat Nallan](https://github.com/bharatnc)).
* 现在 query&#95;log 新增了两个列：initial&#95;query&#95;start&#95;time / initial&#95;query&#95;start&#95;time&#95;microsecond，用于记录分布式查询的开始时间 (如果有) 。[#25022](https://github.com/ClickHouse/ClickHouse/pull/25022) ([Amos Bird](https://github.com/amosbird)).
* 字典现已支持 Array 类型。[#25119](https://github.com/ClickHouse/ClickHouse/pull/25119) ([Maksim Kita](https://github.com/kitaisreal)).
* 添加了 `toJSONString` 函数，用于将列序列化为其 JSON 表示形式。[#25164](https://github.com/ClickHouse/ClickHouse/pull/25164) ([Amos Bird](https://github.com/amosbird)).
* 使用 MaterializeMySQL 创建的 ClickHouse 数据库现在包含被 materialize 的 MySQL 数据库中的所有列注释。[#25199](https://github.com/ClickHouse/ClickHouse/pull/25199) ([Storozhuk Kostiantyn](https://github.com/sand6255)).
* 新增函数 `dateName`。作者 [Daniil Kondratyev] (@dankondr)。[#25372](https://github.com/ClickHouse/ClickHouse/pull/25372) ([Maksim Kita](https://github.com/kitaisreal)).
* 新增函数 `bitPositionsToArray`。关闭 [#23792](https://github.com/ClickHouse/ClickHouse/issues/23792)。作者 [Kevin Wan] (@MaxWk)。[#25394](https://github.com/ClickHouse/ClickHouse/pull/25394) ([Maksim Kita](https://github.com/kitaisreal)).

* 这里将列出我打算在这个 PR 中修复的所有 bug。[#23518](https://github.com/ClickHouse/ClickHouse/pull/23518) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。

* 为主 `clickhouse` binary 新增了独立的 `clickhouse-keeper` 符号链接。现在无需主 ClickHouse server 也可以运行协调服务。[#24059](https://github.com/ClickHouse/ClickHouse/pull/24059) ([alesapin](https://github.com/alesapin)) 。

* 对 `VIEW` 的查询使用全局 settings。修复了查询 `VIEW` 时使用本地 settings 的行为；如果 `CREATE VIEW` 和 `SELECT` 中的 setting 不同，这会导致错误。目前，`VIEW` 不会使用这些修改后的 settings，但你仍然可以在 `CREATE VIEW` 查询的 `SETTINGS` 部分传递额外的 settings。关闭 [#20551](https://github.com/ClickHouse/ClickHouse/issues/20551)。[#24095](https://github.com/ClickHouse/ClickHouse/pull/24095) ([Vladimir C](https://github.com/vdimir)) 。
* 为 MySQL storage engine 新增 settings (`connection_auto_close`/`connection_max_tries`/`connection_pool_size`) 。[#24146](https://github.com/ClickHouse/ClickHouse/pull/24146) ([Azat Khuzhin](https://github.com/azat)) 。
* 修复了 multiline 模式下带有 subqueries 的 FROM clause 中尾随空白的问题，同时还以更便于阅读的方式对查询输出做了小幅调整。[#24151](https://github.com/ClickHouse/ClickHouse/pull/24151) ([Azat Khuzhin](https://github.com/azat)) 。
* 将诸如 `127.0.1.1` 的 IPv4 address 识别为本地地址。这个改动存在争议，并关闭了 [#23504](https://github.com/ClickHouse/ClickHouse/issues/23504)。Michael Filimonov 将测试此功能。[#24316](https://github.com/ClickHouse/ClickHouse/pull/24316) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 修复了 IPv6 address 的解析问题 (即修复 `select * from remote('[::1]', system.one)`) 。[#24319](https://github.com/ClickHouse/ClickHouse/pull/24319) ([Azat Khuzhin](https://github.com/azat)) 。
* 现在，query&#95;log 新增了两列：`initial_query_start_time / initial_query_start_time_microsecond`，用于记录 distributed query (如果存在) 的开始时间。[#24388](https://github.com/ClickHouse/ClickHouse/pull/24388) ([Amos Bird](https://github.com/amosbird)).
* 将更多列 Rewrite 为可能的别名表达式。这可能带来更好的优化效果，例如 projections。[#24405](https://github.com/ClickHouse/ClickHouse/pull/24405) ([Amos Bird](https://github.com/amosbird)).
* 新增一项优化，可将某些函数转换为读取 subcolumns，从而减少读取数据量。例如，statement `col IS NULL` 会被转换为读取 subcolumn `col.null`。可通过设置 `optimize_functions_to_subcolumns` 启用该优化。[#24406](https://github.com/ClickHouse/ClickHouse/pull/24406) ([Anton Popov](https://github.com/CurtizJ)).
* 修复了 Keeper 关闭时的一个 data race 问题。[#24412](https://github.com/ClickHouse/ClickHouse/pull/24412) ([alesapin](https://github.com/alesapin)).
* insert 查询现已支持 Postgres schema。关闭 [#24149](https://github.com/ClickHouse/ClickHouse/issues/24149)。[#24413](https://github.com/ClickHouse/ClickHouse/pull/24413) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 如果 SSDDictionary 是通过 DDL query 创建的，则只能在 user&#95;files 目录内创建。[#24466](https://github.com/ClickHouse/ClickHouse/pull/24466) ([Maksim Kita](https://github.com/kitaisreal)).
* 使 String-to-Int parser 更严格，因此 `toInt64('+')` 将抛出异常。[#24475](https://github.com/ClickHouse/ClickHouse/pull/24475) ([Amos Bird](https://github.com/amosbird)).
* 新增 MergeTree 设置 `max_parts_to_merge_at_once`，用于限制后台一次可 merge 的 parts 数量。不影响 `OPTIMIZE FINAL` 查询。修复了 [#1820](https://github.com/ClickHouse/ClickHouse/issues/1820)。[#24496](https://github.com/ClickHouse/ClickHouse/pull/24496) ([alesapin](https://github.com/alesapin)).
* 避免对 scalar subqueries 隐藏诸如 `Limit for rows or bytes to read exceeded` 之类的错误。[#24545](https://github.com/ClickHouse/ClickHouse/pull/24545) ([nvartolomei](https://github.com/nvartolomei)).
* 新增两个 Replicated*MergeTree settings：`max_replicated_fetches_network_bandwidth` 和 `max_replicated_sends_network_bandwidth`，用于限制表级 replicated fetches/sends 的最大速度。另新增两个 server 级 settings (位于 `default` user profile 中) ：`max_replicated_fetches_network_bandwidth_for_server` 和 `max_replicated_sends_network_bandwidth_for_server`，用于限制所有表的 replication 最大速度。这些 settings 并不会被完全精确地遵循。默认关闭。修复了 [#1821](https://github.com/ClickHouse/ClickHouse/issues/1821)。[#24573](https://github.com/ClickHouse/ClickHouse/pull/24573) ([alesapin](https://github.com/alesapin)).
* 对 `insert_distributed_sync` 也遵循 `max_distributed_connections` (否则在超大 clusters 和同步 insert 的情况下，可能会耗尽 `max_thread_pool_size`) 。[#24754](https://github.com/ClickHouse/ClickHouse/pull/24754) ([Azat Khuzhin](https://github.com/azat)).
* 修复了 `Replicated` database engine 中的一个 bug，该问题在极少数情况下可能导致某个副本跳过已 enqueued 的 DDL query。[#24805](https://github.com/ClickHouse/ClickHouse/pull/24805) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 某些查询需要多轮语义分析。在这种情况下，尝试复用为 `IN` 构建的 Set。[#24874](https://github.com/ClickHouse/ClickHouse/pull/24874) ([Amos Bird](https://github.com/amosbird)).
* 允许在分区 pruning 中使用 `not in` 运算符。[#24894](https://github.com/ClickHouse/ClickHouse/pull/24894) ([Amos Bird](https://github.com/amosbird)).
* 改进了 S3 错误的日志记录，在 key 和 bucket 为空时不再出现双空格。[#24897](https://github.com/ClickHouse/ClickHouse/pull/24897) ([Vladimir Chebotarev](https://github.com/excitoon)).
* 对于分布式查询，当 `optimize_skip_unused_shards=1` 时，允许跳过带有 `(sharding key) IN (one-element-tuple)` 这类条件的 shard。 (此前已支持多元素 Tuple，但单元素 Tuple 不生效，因为它会被解析为字面量) 。[#24930](https://github.com/ClickHouse/ClickHouse/pull/24930) ([Amos Bird](https://github.com/amosbird)).
* 在运行时检测 Linux 版本 (这是让嵌套 epoll 正常工作的必要条件，适用于 `async_socket_for_remote`/`use_hedged_requests`，否则远程查询可能会卡住) 。[#25067](https://github.com/ClickHouse/ClickHouse/pull/25067) ([Azat Khuzhin](https://github.com/azat)).
* 将 background schedule pool 的大小增加到 128 (`background_schedule_pool_size` 设置) 。这样可避免在 ZooKeeper 连接缓慢时 replication queue 卡住。[#25072](https://github.com/ClickHouse/ClickHouse/pull/25072) ([alesapin](https://github.com/alesapin)).
* 修复了 IDN host (例如 `example.рф`) 上的 topLevelDomain()，此前它对这类 host 会返回空字符串。[#25103](https://github.com/ClickHouse/ClickHouse/pull/25103) ([Azat Khuzhin](https://github.com/azat)).
* 在 server 启动时，分区 ID 不正确的 parts 不会被移除，而是始终会被 detached。[#25070](https://github.com/ClickHouse/ClickHouse/issues/25070). [#25166](https://github.com/ClickHouse/ClickHouse/pull/25166) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 修正了 aggregate function `topK` 中的内存跟踪。此更改关闭了 [#25259](https://github.com/ClickHouse/ClickHouse/issues/25259)。[#25260](https://github.com/ClickHouse/ClickHouse/pull/25260) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 为 bridge 进程使用单独的 `clickhouse-bridge` group 和 user。设置 oom&#95;score&#95;adj，使 bridge 成为 OOM killer 的首要目标。并将最大 RSS 设置为 1 GiB。关闭了 [#23861](https://github.com/ClickHouse/ClickHouse/issues/23861)。[#25280](https://github.com/ClickHouse/ClickHouse/pull/25280) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 更新了 `clickhouse-client` 中的提示符，并在重新连接时显示提示消息。此更改关闭了 [#10577](https://github.com/ClickHouse/ClickHouse/issues/10577)。[#25281](https://github.com/ClickHouse/ClickHouse/pull/25281) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增了函数 `if` 对其分支中 Decimal 和 Int 类型的支持。此更改关闭了 [#20549](https://github.com/ClickHouse/ClickHouse/issues/20549)。此更改关闭了 [#10142](https://github.com/ClickHouse/ClickHouse/issues/10142)。[#25283](https://github.com/ClickHouse/ClickHouse/pull/25283) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增设置 `http_max_fields`、`http_max_field_name_size`、`http_max_field_value_size`。[#25296](https://github.com/ClickHouse/ClickHouse/pull/25296) ([Ivan](https://github.com/abyss7)).
* 为 sequenceMatch 和 sequenceCount 函数中的时间条件新增 `==` 运算符支持。例如：sequenceMatch(&#39;(?1)(?t==1)(?2)&#39;)(time, data = 1, data = 2)。[#25299](https://github.com/ClickHouse/ClickHouse/pull/25299) ([Christophe Kalenzaga](https://github.com/mga-chka)).
* 支持在 LowCardinality 中使用 Interval，关闭了 [#21730](https://github.com/ClickHouse/ClickHouse/issues/21730)。[#25410](https://github.com/ClickHouse/ClickHouse/pull/25410) ([Vladimir C](https://github.com/vdimir)).
* Flatbuffers 库已更新至 v.2.0.0。改进列表见 https://github.com/google/flatbuffers/releases/tag/v2.0.0。 [#25474](https://github.com/ClickHouse/ClickHouse/pull/25474) ([Ilya Yatsishin](https://github.com/qoega)).
* 当 internal&#95;replication=true 时，从 dirname 中去掉副本信息 (这样即可从任意数量的副本对带 cluster 的 Distributed 执行 INSERT；此前仅支持 15 个副本，超过后在为异步块创建目录时会因 ENAMETOOLONG 而失败) 。 [#25513](https://github.com/ClickHouse/ClickHouse/pull/25513) ([Azat Khuzhin](https://github.com/azat)).
* 当用户向操作系统请求任意可用端口时，确定实际绑定的端口号。 [#25569](https://github.com/ClickHouse/ClickHouse/pull/25569) ([bnaecker](https://github.com/bnaecker)).
* 改进 Distributed 引擎的启动速度。 [#25663](https://github.com/ClickHouse/ClickHouse/pull/25663) ([Azat Khuzhin](https://github.com/azat)).

  #### 缺陷修复

* 修复了故障转移行为中的缺陷：当同一消费者此前的分配为空时，Engine=Kafka 无法启动消费。关闭 [#21118](https://github.com/ClickHouse/ClickHouse/issues/21118)。[#21267](https://github.com/ClickHouse/ClickHouse/pull/21267) ([filimonov](https://github.com/filimonov))。
* 修复了等待自动删除空 parts 时的问题。该问题可能导致后台线程池耗尽，进而造成复制卡死。[#23315](https://github.com/ClickHouse/ClickHouse/pull/23315) ([Anton Popov](https://github.com/CurtizJ))。
* 修复 join 输出中列的基数与输入不一致的问题，关闭 [#23351](https://github.com/ClickHouse/ClickHouse/issues/23351)，关闭 [#20315](https://github.com/ClickHouse/ClickHouse/issues/20315)。[#24061](https://github.com/ClickHouse/ClickHouse/pull/24061) ([Vladimir C](https://github.com/vdimir))。
* 在分区键中使用取模函数时，改为沿用旧版本的取模函数实现。关闭 [#23508](https://github.com/ClickHouse/ClickHouse/issues/23508)。[#24157](https://github.com/ClickHouse/ClickHouse/pull/24157) ([Kseniia Sumarokova](https://github.com/kssenii))。
* 通过设置 `max_threads = 1` 修复了 StorageMemory 变更失败的问题。关闭 [#24274](https://github.com/ClickHouse/ClickHouse/issues/24274)。[#24275](https://github.com/ClickHouse/ClickHouse/pull/24275) ([flynn](https://github.com/ucasfl))。
* 允许空 HTTP 头部。修复 [#23901](https://github.com/ClickHouse/ClickHouse/issues/23901)。[#24285](https://github.com/ClickHouse/ClickHouse/pull/24285) ([Ivan](https://github.com/abyss7))。
* 修复了通过 `RENAME TABLE` 查询将 materialized view 从 Ordinary 数据库迁移到 Atomic 数据库时的缺陷。现在内部表会随 materialized view 一同迁移到新数据库。修复 [#23926](https://github.com/ClickHouse/ClickHouse/issues/23926)。[#24309](https://github.com/ClickHouse/ClickHouse/pull/24309) ([Alexander Tokmakov](https://github.com/tavplubix))。
* 修复了删除分区时与伪造 parts 相交的问题。在极少数情况下，可能存在变更版本号大于当前块编号的 parts。[#24321](https://github.com/ClickHouse/ClickHouse/pull/24321) ([Amos Bird](https://github.com/amosbird))。
