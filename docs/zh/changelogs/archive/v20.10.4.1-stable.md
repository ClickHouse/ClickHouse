  ### ClickHouse 版本 v20.10.4.1-稳定版本 FIXME (相较于 v20.10.3.30-稳定版本)
</div>

<div id="improvement">
  #### 改进
</div>

* 提供了一种在将 S3 与作为代理的 nginx 服务器配合使用时的变通方案。Nginx 当前不接受路径为空的 URL，例如 [http://domain.com?delete](http://domain.com?delete)，而原生的 aws-sdk-cpp 会生成这种 URL。此次 commit 使用了打过 patch 的 aws-sdk-cpp 版本，使其在这类情况下生成以 &quot;/&quot; 为 path 的 URL，例如 [http://domain.com/?delete](http://domain.com/?delete)。[#16813](https://github.com/ClickHouse/ClickHouse/pull/16813) ([ianton-ru](https://github.com/ianton-ru)).

<div id="bug-fix">
  #### 缺陷修复
</div>

* 已在 [#16492](https://github.com/ClickHouse/ClickHouse/issues/16492) 中回移：修复 MySQL 数据库的 bug。当作为数据库引擎使用的 MySQL 服务器宕机时，某些查询会抛出异常，因为它们会尝试从不可用的服务器获取表，而这其实没有必要。例如，查询 `SELECT ... FROM system.parts` 应当只作用于 MergeTree 表，完全不需要访问 MySQL 数据库。[#16032](https://github.com/ClickHouse/ClickHouse/pull/16032) ([Kruglov Pavel](https://github.com/Avogar)) 。
* 已在 [#16710](https://github.com/ClickHouse/ClickHouse/issues/16710) 中回移：修复了行为不一致的问题：由于用于过滤的集合未创建，返回数据中的一部分可能会被丢弃。[#16308](https://github.com/ClickHouse/ClickHouse/pull/16308) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。
* 已在 [#16505](https://github.com/ClickHouse/ClickHouse/issues/16505) 中回移：修复复制队列中超大条目的处理问题。如果表结构特别大 (接近 1 MB) ，ALTER 查询中可能会出现超大条目。此修复解决了 [#16307](https://github.com/ClickHouse/ClickHouse/issues/16307)。[#16332](https://github.com/ClickHouse/ClickHouse/pull/16332) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 已在 [#16471](https://github.com/ClickHouse/ClickHouse/issues/16471) 中回移：修复 Distributed 的 DROP TABLE 问题 (与 INSERT 存在竞争条件) 。[#16409](https://github.com/ClickHouse/ClickHouse/pull/16409) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#16572](https://github.com/ClickHouse/ClickHouse/issues/16572) 中回移：通过正确收缩 GTID 集合，修复在使用 MySQL Master -&gt; MySQL Slave -&gt; ClickHouse MaterializeMySQL Engine，且 MySQL Slave 上启用了 `slave_parallel_worker` 时元数据快速增长的问题。此修复解决了 [#15951](https://github.com/ClickHouse/ClickHouse/issues/15951)。[#16504](https://github.com/ClickHouse/ClickHouse/pull/16504) ([TCeason](https://github.com/TCeason)) 。
* 已在 [#16551](https://github.com/ClickHouse/ClickHouse/issues/16551) 中回移：现在从输入中解析 AVRO 时，会从类型中移除 LowCardinality。修复了 [#16188](https://github.com/ClickHouse/ClickHouse/issues/16188)。[#16521](https://github.com/ClickHouse/ClickHouse/pull/16521) ([Mike Kot](https://github.com/myrrc)) 。
* 已在 [#16749](https://github.com/ClickHouse/ClickHouse/issues/16749) 中回移：修复了 [#16081](https://github.com/ClickHouse/ClickHouse/issues/16081)。[#16613](https://github.com/ClickHouse/ClickHouse/pull/16613) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)) 。
* 已在 [#16760](https://github.com/ClickHouse/ClickHouse/issues/16760) 中回移：这将修复在 max&#95;threads&gt;0 且 ORDER BY 中包含表达式时，optimize&#95;read&#95;in&#95;order/optimize&#95;aggregation&#95;in&#95;order 的问题。[#16637](https://github.com/ClickHouse/ClickHouse/pull/16637) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#16741](https://github.com/ClickHouse/ClickHouse/issues/16741) 中回移：修复启用 `transform_null_in` 设置时，针对多列和元组的 `IN` 运算符问题。修复了 [#15310](https://github.com/ClickHouse/ClickHouse/issues/15310)。[#16722](https://github.com/ClickHouse/ClickHouse/pull/16722) ([Anton Popov](https://github.com/CurtizJ)) 。
* 已在 [#16893](https://github.com/ClickHouse/ClickHouse/issues/16893) 中回移：修复了一个罕见的静默崩溃问题。当查询分析器启用，并且 ClickHouse 安装在 glibc 版本对某些函数的异步栈展开表 (据称) 存在缺陷的操作系统上时，可能会发生此问题。此修复解决了 [#15301](https://github.com/ClickHouse/ClickHouse/issues/15301) 和 [#13098](https://github.com/ClickHouse/ClickHouse/issues/13098)。[#16846](https://github.com/ClickHouse/ClickHouse/pull/16846) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
