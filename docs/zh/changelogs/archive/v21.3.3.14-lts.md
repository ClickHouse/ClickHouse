<div id="bug-fix">
  #### 缺陷修复
</div>

* 已在 [#21644](https://github.com/ClickHouse/ClickHouse/issues/21644) 中回移：修复了 S3 表在配置更新后仍持有旧凭据的问题。[#21457](https://github.com/ClickHouse/ClickHouse/pull/21457) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)) 。
* 已在 [#21854](https://github.com/ClickHouse/ClickHouse/issues/21854) 中回移：修复了在启用 `optimize_skip_unused_shards` 且未使用任何分片时，可能出现 ` Cannot find column` 错误的问题。[#21579](https://github.com/ClickHouse/ClickHouse/pull/21579) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#21687](https://github.com/ClickHouse/ClickHouse/issues/21687) 中回移：修复了水平 merge 的 `fsync_part_directory` 问题。[#21642](https://github.com/ClickHouse/ClickHouse/pull/21642) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#21796](https://github.com/ClickHouse/ClickHouse/issues/21796) 中回移：修复了在 `async_socket_for_remote=1` 时分布式请求的取消问题 (例如，跨多个分片执行带 limit 的简单 select，即 `select * from remote('127.{2,3}', system.numbers) limit 100`) 。[#21643](https://github.com/ClickHouse/ClickHouse/pull/21643) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#21811](https://github.com/ClickHouse/ClickHouse/issues/21811) 中回移：修复了 ReplicatedMerge 表引擎中的一个缺陷：当 `ALTER MODIFY COLUMN` 查询未改变 decimal 列的类型，且其位宽 (32 bit 或 64 bit) 也未变化时，类型不会被修改。[#21728](https://github.com/ClickHouse/ClickHouse/pull/21728) ([alesapin](https://github.com/alesapin)) 。
* 已在 [#21883](https://github.com/ClickHouse/ClickHouse/issues/21883) 中回移：回退了 S3 连接池。[#21737](https://github.com/ClickHouse/ClickHouse/pull/21737) ([Vladimir Chebotarev](https://github.com/excitoon)) 。
* 已在 [#21874](https://github.com/ClickHouse/ClickHouse/issues/21874) 中回移：修复了当 `WHERE` 或 `HAVING` 条件被下推到 `GROUP BY` 之前时，可能导致查询结果错误 (以及可能崩溃) 的问题。修复了 [#21773](https://github.com/ClickHouse/ClickHouse/issues/21773)。[#21841](https://github.com/ClickHouse/ClickHouse/pull/21841) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
