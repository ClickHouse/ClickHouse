<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 更改共享数据零拷贝标记的 ZooKeeper 路径。修复已重命名 parts 在 ZooKeeper 中删除标记时的问题。[#32061](https://github.com/ClickHouse/ClickHouse/pull/32061) ([ianton-ru](https://github.com/ianton-ru)).
* * 将标量子查询纳入统计。此变更后，标量子查询中读取的行现在会记录到 query&#95;log 中。如果标量子查询已缓存 (重复执行或对多行调用) ，读取的行只会统计一次。此变更还允许在查询执行标量子查询期间对其执行 KILL，并报告执行进度。[#32271](https://github.com/ClickHouse/ClickHouse/pull/32271) ([Raúl Marín](https://github.com/Algunenano)).
* 添加 `left`、`right`、`leftUTF8`、`rightUTF8` 函数。修复 `substringUTF8` 函数在负 OFFSET (即从字符串末尾开始的偏移) 情况下实现中的错误。`left` 和 `right` 函数此前是在解析器中实现的。升级说明：如果集群中包含不同版本的 clickhouse-server，那么未使用别名且包含 `left` 或 `right` 函数的分布式查询可能会抛出异常。如果你正在升级集群并遇到此错误，应完成整个集群的升级，以确保所有节点使用相同版本。你也可以给查询中的列添加别名 (`AS something`) 来避免此问题。[#33407](https://github.com/ClickHouse/ClickHouse/pull/33407) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新特性
</div>

* 实现了稀疏序列化。它可以减少磁盘空间占用，并提升包含大量默认值 (零值) 的列在某些查询中的性能。可通过设置 `ratio_of_defaults_for_sparse_serialization` 启用。如果某列的默认值数量与总值数量的比率高于该阈值，则会为该列动态选择稀疏序列化。每个 part 中每一列的序列化方式 (默认或稀疏) 会固定下来，但不同 parts 之间可能不同。 [#22535](https://github.com/ClickHouse/ClickHouse/pull/22535) ([Anton Popov](https://github.com/CurtizJ)).
* 添加了 grouping sets 函数，类似于 GROUP BY grouping sets (a, b, (a, b)). [#26869](https://github.com/ClickHouse/ClickHouse/pull/26869) ([taylor12805](https://github.com/taylor12805)).
* 新增了在分布式查询期间从一个 shard 内的所有副本读取的能力。要启用此功能，请设置 `allow_experimental_parallel_reading_from_replicas=true`，并将 `max_parallel_replicas` 设为任意数字。此更改解决了 [#26748](https://github.com/ClickHouse/ClickHouse/issues/26748)。 [#29279](https://github.com/ClickHouse/ClickHouse/pull/29279) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 当 hosts 和 ports 配置发生变化时启动和停止服务器。 [#30549](https://github.com/ClickHouse/ClickHouse/pull/30549) ([Kevin Michel](https://github.com/kmichel-aiven)).
* 支持为任意类型的视图添加注释。 ... [#31062](https://github.com/ClickHouse/ClickHouse/pull/31062) ([Vasily Nemkov](https://github.com/Enmk)).
* 实现了 Hive 表引擎，以便从 ClickHouse 访问 Apache Hive。相关 RFC： [#29245](https://github.com/ClickHouse/ClickHouse/issues/29245)。 [#31104](https://github.com/ClickHouse/ClickHouse/pull/31104) ([李扬](https://github.com/taiyang-li)).
* * 通过 Zoo/Keeper 实现自动集群发现。[#31442](https://github.com/ClickHouse/ClickHouse/pull/31442) ([Vladimir C](https://github.com/vdimir)) 。
* 新增了对以 Azure Blob 存储为后端的磁盘的支持，实现方式与此前对以 AWS S3 为后端的磁盘支持类似。当前实现已支持所有基本的磁盘操作。[#31505](https://github.com/ClickHouse/ClickHouse/pull/31505) ([Jakub Kuklis](https://github.com/jkuklis)) 。
* * 新增 &quot;TABLE OVERRIDE&quot; 功能，用于自定义 MaterializedMySQL 表的 schema。[#32325](https://github.com/ClickHouse/ClickHouse/pull/32325) ([Stig Bakken](https://github.com/stigsb)).
* 为输入格式实现 data schema inference。允许在表函数 `file`、`url`、`s3`、`hdfs` 以及 `clickhouse-local` 的参数中省略结构 (或仅写 `auto`) 。允许在针对 `File`、`HDFS`、`S3`、`URL`、`Merge`、`Buffer`、`Distributed` 和 `ReplicatedMergeTree` 表引擎的 CREATE 查询中省略结构 (如果添加了新副本) 。[#32455](https://github.com/ClickHouse/ClickHouse/pull/32455) ([Kruglov Pavel](https://github.com/Avogar)).
* 为 MaterializedPostgreSQL 支持 TABLE OVERRIDE 子句。RFC：[#31480](https://github.com/ClickHouse/ClickHouse/issues/31480)。[#32749](https://github.com/ClickHouse/ClickHouse/pull/32749) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 添加 `EXPLAIN TABLE OVERRIDE` 查询。[#32836](https://github.com/ClickHouse/ClickHouse/pull/32836) ([Stig Bakken](https://github.com/stigsb)).
* 如果通过 `SET` 查询或 HTTP request 中的 query parameters 定义了无效的 setting，error message 将包含与该无效 setting 字符串相似的建议 (如果有) 。[#32946](https://github.com/ClickHouse/ClickHouse/pull/32946) ([Antonio Andelic](https://github.com/antonio2368)).
* 添加 aggregate functions `cramersV`、`cramersVBiasCorrected`、`theilsU` 和 `contingency`。这些函数用于计算分类值之间的依赖关系 (关联性的度量) 。这些函数均通过交叉表 (成对值上的 histogram) 实现。可以将其理解为适用于任意离散值 (不一定是数值) 的相关系数。[#33366](https://github.com/ClickHouse/ClickHouse/pull/33366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 新增函数 `arrayLast`。关闭 [#33390](https://github.com/ClickHouse/ClickHouse/issues/33390)。[#33415](https://github.com/ClickHouse/ClickHouse/pull/33415) ([Maksim Kita](https://github.com/kitaisreal)).
* 添加 MONTHNAME 函数。[#33436](https://github.com/ClickHouse/ClickHouse/pull/33436) ([usurai](https://github.com/usurai)).
* 自动检测文件扩展名。关闭 [#30918](https://github.com/ClickHouse/ClickHouse/issues/30918)。[#33443](https://github.com/ClickHouse/ClickHouse/pull/33443) ([zhongyuankai](https://github.com/zhongyuankai)).
* 新增函数 `arrayLastIndex`。[#33465](https://github.com/ClickHouse/ClickHouse/pull/33465) ([Maksim Kita](https://github.com/kitaisreal)).
* 添加新的 h3 杂项函数：`h3DegsToRads`、`h3RadsToDegs`、`h3HexAreaKm2`、`h3CellAreaM2`、`h3CellAreaRads2`。[#33479](https://github.com/ClickHouse/ClickHouse/pull/33479) ([Bharat Nallan](https://github.com/bharatnc)).
* 在 file/hdfs/s3/url 表函数以及 HDFS/S3/URL 表引擎中，根据文件扩展名检测格式。[#33565](https://github.com/ClickHouse/ClickHouse/pull/33565) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 改动影响不大。在极少数情况下，如果每个副本上的数据分区片段都丢失了，那么在某些数据分区片段合并后，后续查询在进行分区裁剪时可能会少跳过一部分分区。这几乎不会带来任何影响。 [#32220](https://github.com/ClickHouse/ClickHouse/pull/32220) ([Azat Khuzhin](https://github.com/azat)).
* `reinterpret` 函数的性能略有提升。 [#32587](https://github.com/ClickHouse/ClickHouse/pull/32587) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 减少了带有字符串属性的字典的内存占用。 [#33466](https://github.com/ClickHouse/ClickHouse/pull/33466) ([Maksim Kita](https://github.com/kitaisreal)).
* 避免了解析器中的指数级回溯。此更改关闭了 [#20158](https://github.com/ClickHouse/ClickHouse/issues/20158)。 [#33481](https://github.com/ClickHouse/ClickHouse/pull/33481) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
