<div id="clickhouse-release-v208545-lts-fixme-as-compared-to-v208411-lts">
  ### ClickHouse 发布版本 v20.8.5.45-长期支持版 相较于 v20.8.4.11-长期支持版 的 FIXME
</div>

<div id="improvement">
  #### 改进
</div>

* 已在 [#16146](https://github.com/ClickHouse/ClickHouse/issues/16146) 中回移：现在无论集群配置中的 `<internal_replication>` 设置如何，都允许执行 `ALTER ... ON CLUSTER` 查询。[#16075](https://github.com/ClickHouse/ClickHouse/pull/16075) ([alesapin](https://github.com/alesapin)).
* 已在 [#16310](https://github.com/ClickHouse/ClickHouse/issues/16310) 中回移：添加 allow&#95;nondeterministic&#95;optimize&#95;skip&#95;unused&#95;shards (以允许在分片键中使用 rand() 或 dictGet() 等非确定性内容) 。[#16105](https://github.com/ClickHouse/ClickHouse/pull/16105) ([Azat Khuzhin](https://github.com/azat)).

<div id="bug-fix">
  #### 缺陷修复
</div>

* 已在 [#15620](https://github.com/ClickHouse/ClickHouse/issues/15620) 中回移：当向 ReplicatedMergeTree 传入单个参数时，现在会抛出错误，而不是将其忽略。[#15516](https://github.com/ClickHouse/ClickHouse/pull/15516) ([nvartolomei](https://github.com/nvartolomei)).
* 已在 [#16203](https://github.com/ClickHouse/ClickHouse/issues/16203) 中回移：在 detach 只读表时，递减 `ReadonlyReplica` 指标。此修复解决了 [#15598](https://github.com/ClickHouse/ClickHouse/issues/15598)。[#15592](https://github.com/ClickHouse/ClickHouse/pull/15592) ([sundyli](https://github.com/sundy-li)).
* 已在 [#16230](https://github.com/ClickHouse/ClickHouse/issues/16230) 中回移：修复了 S3 表函数中与通配符有关的错误：URL 中的区域未应用到 S3 客户端配置中。[#15646](https://github.com/ClickHouse/ClickHouse/pull/15646) ([Vladimir Chebotarev](https://github.com/excitoon)).
* 已在 [#15871](https://github.com/ClickHouse/ClickHouse/issues/15871) 中回移：修复错误 `Cannot add simple transform to empty Pipe`。当从 `Buffer` 表读取数据，且其结构与目标端表不同，并且目标端表的查询返回空结果时，可能会出现该错误。修复了 [#15529](https://github.com/ClickHouse/ClickHouse/issues/15529)。[#15662](https://github.com/ClickHouse/ClickHouse/pull/15662) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 已在 [#15772](https://github.com/ClickHouse/ClickHouse/issues/15772) 中回移：修复了 `max_replicated_logs_to_keep` 设置默认值过低的问题，这可能导致副本过于频繁地丢失。通过选择最新的副本进行克隆，改进了丢失副本的恢复流程。同时，不再从丢失副本中删除旧的 parts，而是将其 detach。[#15701](https://github.com/ClickHouse/ClickHouse/pull/15701) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 已在 [#15738](https://github.com/ClickHouse/ClickHouse/issues/15738) 中回移：修复了向 `MATERIALIZED VIEW` 插入数据时可能出现的错误 `Cannot find column`，当 `MV` 的查询包含 `ARRAY JOIN` 时会发生该问题。[#15717](https://github.com/ClickHouse/ClickHouse/pull/15717) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 已在 [#15795](https://github.com/ClickHouse/ClickHouse/issues/15795) 中回移：修复了某些只选择虚拟列的查询场景。此前可能会抛出 `Not found column _nothing in block` 异常。修复了 [#12298](https://github.com/ClickHouse/ClickHouse/issues/12298)。[#15756](https://github.com/ClickHouse/ClickHouse/pull/15756) ([Anton Popov](https://github.com/CurtizJ)).
* 已在 [#15900](https://github.com/ClickHouse/ClickHouse/issues/15900) 中回移：修复了在执行 `ALTER MODIFY COLUMN` 查询后，再执行 `SELECT ... ORDER BY DESC` 查询时出现的 `Block structure mismatch` 异常。修复了 [#15800](https://github.com/ClickHouse/ClickHouse/issues/15800)。[#15852](https://github.com/ClickHouse/ClickHouse/pull/15852) ([alesapin](https://github.com/alesapin)).
* 已在 [#15925](https://github.com/ClickHouse/ClickHouse/issues/15925) 中回移：现在，当 `ALTER MODIFY COLUMN ... DEFAULT ...` 中的默认值与列类型不兼容时，会抛出异常。修复了 [#15854](https://github.com/ClickHouse/ClickHouse/issues/15854)。[#15858](https://github.com/ClickHouse/ClickHouse/pull/15858) ([alesapin](https://github.com/alesapin)).
* 已在 [#15920](https://github.com/ClickHouse/ClickHouse/issues/15920) 中回移：修复了 RBAC 中可能出现的死锁问题。[#15875](https://github.com/ClickHouse/ClickHouse/pull/15875) ([Vitaly Baranov](https://github.com/vitlibar)).
* 已在 [#16168](https://github.com/ClickHouse/ClickHouse/issues/16168) 中回移：修复从 `Distributed` 表查询时，如果查询包含 `WHERE`、`PREWHERE` 和 `GLOBAL IN`，会错误返回空结果的问题。修复了 [#15792](https://github.com/ClickHouse/ClickHouse/issues/15792)。[#15933](https://github.com/ClickHouse/ClickHouse/pull/15933) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 已在 [#16355](https://github.com/ClickHouse/ClickHouse/issues/16355) 中回移：修复表在并发重命名时，`DROP TABLE IF EXISTS` 因报错 `Table ... doesn't exist` 而失败的问题 (适用于 atomic database engine) 。修复并发执行某些涉及多张表的 DDL 查询 (如 `DROP DATABASE` 和 `RENAME TABLE`) 时出现的罕见死锁。修复并发执行 `DROP/DETACH TABLE` 时，`DROP/DETACH DATABASE` 因 `Table ... doesn't exist` 而失败的问题。[#15934](https://github.com/ClickHouse/ClickHouse/pull/15934) ([Alexander Tokmakov](https://github.com/tavplubix)) 。
* 已在 [#15968](https://github.com/ClickHouse/ClickHouse/issues/15968) 中回移：修复创建 database 失败时发生崩溃的问题。[#15954](https://github.com/ClickHouse/ClickHouse/pull/15954) ([Winter Zhang](https://github.com/zhang2014)) 。
* 已在 [#16025](https://github.com/ClickHouse/ClickHouse/issues/16025) 中回移：修复 settings profiles 解析中的歧义：`CREATE USER ... SETTINGS profile readonly` 现在会被视为使用名为 `readonly` 的 profile，而不是名为 `profile` 且带有 readonly 约束的 setting。修复了 [#15628](https://github.com/ClickHouse/ClickHouse/issues/15628)。[#15982](https://github.com/ClickHouse/ClickHouse/pull/15982) ([Vitaly Baranov](https://github.com/vitlibar)) 。
* 已在 [#16219](https://github.com/ClickHouse/ClickHouse/issues/16219) 中回移：修复向 MaterializedView 插入数据或从中查询时，并发删除目标表会偶发 segfault 的问题 (适用于 atomic database engine) 。[#15984](https://github.com/ClickHouse/ClickHouse/pull/15984) ([Alexander Tokmakov](https://github.com/tavplubix)) 。
* 已在 [#16029](https://github.com/ClickHouse/ClickHouse/issues/16029) 中回移：避免在一段时间无活动后发生复制错误时，副本卡住 5–10 分钟。[#15987](https://github.com/ClickHouse/ClickHouse/pull/15987) ([filimonov](https://github.com/filimonov)) 。
* 已在 [#16088](https://github.com/ClickHouse/ClickHouse/issues/16088) 中回移：允许对带有 complex key 的字典使用 direct layout。[#16007](https://github.com/ClickHouse/ClickHouse/pull/16007) ([Anton Popov](https://github.com/CurtizJ)) 。
* 已在 [#16360](https://github.com/ClickHouse/ClickHouse/issues/16360) 中回移：修复 collate name 和 charset name 的解析器，并支持 String 类型的 `length = 0`。[#16008](https://github.com/ClickHouse/ClickHouse/pull/16008) ([Winter Zhang](https://github.com/zhang2014)) 。
* 已在 [#16141](https://github.com/ClickHouse/ClickHouse/issues/16141) 中回移：修复 `ReplicatedVersionedCollapsingMergeTree` 的 `ALTER MODIFY ... ORDER BY` 查询卡住的问题。修复了 [#15980](https://github.com/ClickHouse/ClickHouse/issues/15980)。[#16011](https://github.com/ClickHouse/ClickHouse/pull/16011) ([alesapin](https://github.com/alesapin)) 。
* 已在 [#16078](https://github.com/ClickHouse/ClickHouse/issues/16078) 中回移：修复了 [#15780](https://github.com/ClickHouse/ClickHouse/issues/15780) 引入的回归问题，例如 `indexOf([1, 2, 3], toLowCardinality(1))` 现在会被禁止，但其实不应如此。[#16038](https://github.com/ClickHouse/ClickHouse/pull/16038) ([Mike Kot](https://github.com/myrrc)) 。
* 已在 [#16294](https://github.com/ClickHouse/ClickHouse/issues/16294) 中回移：修复 sharding&#95;key 中的 dictGet (以及类似场景，例如函数上下文被永久保存时) 的问题。[#16205](https://github.com/ClickHouse/ClickHouse/pull/16205) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#16233](https://github.com/ClickHouse/ClickHouse/issues/16233) 中回移：修复无视限制仍可能过度分配内存的情况。此修复关闭了 [#14560](https://github.com/ClickHouse/ClickHouse/issues/14560)。[#16206](https://github.com/ClickHouse/ClickHouse/pull/16206) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 已在 [#16325](https://github.com/ClickHouse/ClickHouse/issues/16325) 中回移：修复 `GROUP BY` 使用字符串键时可能出现的内存泄漏，该问题由 `TwoLevelStringHashTable` 实现中的错误导致。[#16264](https://github.com/ClickHouse/ClickHouse/pull/16264) ([Amos Bird](https://github.com/amosbird)) 。
* 已在 [#16375](https://github.com/ClickHouse/ClickHouse/issues/16375) 中回移：修复在 prefer&#95;localhost&#95;replica=0 且启用 internal&#95;replication 时，异步 Distributed INSERT 的问题。[#16358](https://github.com/ClickHouse/ClickHouse/pull/16358) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#16431](https://github.com/ClickHouse/ClickHouse/issues/16431) 中回移：修复在使用 totals/rollup/cube 修饰符并对 GROUP BY 键应用 min/max 函数时的 GROUP BY 问题。修复了 [#16393](https://github.com/ClickHouse/ClickHouse/issues/16393)。[#16397](https://github.com/ClickHouse/ClickHouse/pull/16397) ([Anton Popov](https://github.com/CurtizJ)) 。
* 已在 [#16450](https://github.com/ClickHouse/ClickHouse/issues/16450) 中回移：修复函数 `dictGet` 发生异常时的重复释放问题。如果字典加载时出错，就可能触发此问题。[#16429](https://github.com/ClickHouse/ClickHouse/pull/16429) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
