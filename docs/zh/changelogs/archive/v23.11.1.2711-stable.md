<div id="backward-incompatible-change">
  #### 不向后兼容的变更
</div>

* 函数 `parseDateTime()` 中的格式说明符 `%l`/`%k`/`%c` 现在可以解析不带前导零的小时/月，例如 `select parseDateTime('2023-11-26 8:14', '%F %k:%i')` 现已可正常运行。将 `parsedatetime_parse_without_leading_zeros = 0` 设为 0 可恢复此前必须使用两位数字的行为。函数 `formatDateTime` 现在也可以输出不带前导零的小时/月。该行为由设置 `formatdatetime_format_without_leading_zeros` 控制，但默认关闭，以避免破坏现有用例。[#55872](https://github.com/ClickHouse/ClickHouse/pull/55872) ([Azat Khuzhin](https://github.com/azat)).
* 现在不能再将聚合函数 `avgWeighted` 用于 `Decimal` 类型参数。变通方法：将参数转换为 `Float64`。此变更关闭了 [#43928](https://github.com/ClickHouse/ClickHouse/issues/43928)。此变更关闭了 [#31768](https://github.com/ClickHouse/ClickHouse/issues/31768)。此变更关闭了 [#56435](https://github.com/ClickHouse/ClickHouse/issues/56435)。如果你曾在 materialized views 或 projections 中对 `Decimal` 参数使用过此函数，请联系 support@clickhouse.com。修复了聚合函数 `sumMap` 中的错误，但也使其速度变慢了约 1.5 到 2 倍。不过这无关紧要，因为这个函数本来就很鸡肋。此变更关闭了 [#54955](https://github.com/ClickHouse/ClickHouse/issues/54955)。此变更关闭了 [#53134](https://github.com/ClickHouse/ClickHouse/issues/53134)。此变更关闭了 [#55148](https://github.com/ClickHouse/ClickHouse/issues/55148)。修复了函数 `groupArraySample` 中的一个 bug：当一个查询中生成多个 aggregate state 时，它会使用相同的 random seed。[#56350](https://github.com/ClickHouse/ClickHouse/pull/56350) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 默认的 ClickHouse 服务器配置文件现已默认对 `default` 用户启用 `access_management` (通过 SQL 查询管理用户) 和 `named_collection_control` (通过 SQL 查询管理 named collection) 。此变更关闭了 [#56482](https://github.com/ClickHouse/ClickHouse/issues/56482)。[#56619](https://github.com/ClickHouse/ClickHouse/pull/56619) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对 RESPECT/IGNORE NULLS 进行了多项改进。[#57189](https://github.com/ClickHouse/ClickHouse/pull/57189) ([Raúl Marín](https://github.com/Algunenano)).
* 移除了优化 `optimize_move_functions_out_of_any`。[#57190](https://github.com/ClickHouse/ClickHouse/pull/57190) ([Raúl Marín](https://github.com/Algunenano)).

* 新增对 Keeper 协议中压缩的支持。可通过在 `zookeeper` 中使用标志 `use_compression` 在 ClickHouse 上启用。解决了 [#49507](https://github.com/ClickHouse/ClickHouse/issues/49507)。[#54957](https://github.com/ClickHouse/ClickHouse/pull/54957) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).

* 新增函数 `fromDaysSinceYearZero()`，类似于 MySQL 的 `FROM_DAYS`。例如，`SELECT fromDaysSinceYearZero(739136)` 返回 `2023-09-08`。[#56088](https://github.com/ClickHouse/ClickHouse/pull/56088) ([Joanna Hulboj](https://github.com/jh0x)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 支持窗口函数并行求值。修复了 [#34688](https://github.com/ClickHouse/ClickHouse/issues/34688)。[#39631](https://github.com/ClickHouse/ClickHouse/pull/39631) ([Dmitry Novik](https://github.com/novikd)).
* 将 `max_concurrent_queries` 的默认值从 100 提高到 1000。当存在大量已连接客户端，且它们发送或接收数据的速度较慢，因此 server 不受 CPU 限制，或者当 CPU 核心数超过 100 时，这样做更合理。同时，默认启用并发控制，并将查询处理线程总数设为 CPU 核心数的两倍。这提升了在超大量并发查询场景下的性能。[#46927](https://github.com/ClickHouse/ClickHouse/pull/46927) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了 `Merge` 表引擎按 `IN(...)` 条件过滤的问题。[#54905](https://github.com/ClickHouse/ClickHouse/pull/54905) ([Nikita Taranov](https://github.com/nickitat)).
* 改进了缓存已满且存在大量读取时的性能。[#55158](https://github.com/ClickHouse/ClickHouse/pull/55158) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 新增了为 S3 禁用 checksum 的能力，以避免过度读取输入文件 (可通过 `s3_disable_checksum=true` 启用此新行为) 。[#55559](https://github.com/ClickHouse/ClickHouse/pull/55559) ([Azat Khuzhin](https://github.com/azat)).
* 现在，当数据位于 page cache 中时，我们会像处理本地表一样同步读取远程表。这样更快，无需在线程池内部同步，更敢于在本地文件系统上执行 `seek`，并可减少 CPU 等待。[#55841](https://github.com/ClickHouse/ClickHouse/pull/55841) ([Nikita Taranov](https://github.com/nickitat)).
* ... 此 PR 跟进了 [#55929](https://github.com/ClickHouse/ClickHouse/issues/55929)，将带来约 30% 的性能提升。- 减少预留内存 - 减少 `resize` 调用。[#55957](https://github.com/ClickHouse/ClickHouse/pull/55957) ([lgbo](https://github.com/lgbo-ustc)).
* 在 ICX 设备 (Intel Xeon Platinum 8380 CPU，80 核，160 线程) 上进行的 **OnTime** 性能实验表明，此变更可分别将查询 Q2、Q3、Q4、Q5 和 Q6 的 QPS 提升 **7.4%、5.9%、4.7%、3.0% 和 4.6%**，同时对其他查询没有影响。[#56079](https://github.com/ClickHouse/ClickHouse/pull/56079) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 限制查询 profiler 内部处于忙碌状态的线程数。如果超过该数量，这些线程将跳过 profiling。[#56105](https://github.com/ClickHouse/ClickHouse/pull/56105) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* WindowTransform 减少了 virtual 函数调用次数。[#56120](https://github.com/ClickHouse/ClickHouse/pull/56120) ([Maksim Kita](https://github.com/kitaisreal)).
* 允许在 ORC 中递归进行 Tuple 字段剪枝，以加快扫描速度。[#56122](https://github.com/ClickHouse/ClickHouse/pull/56122) ([李扬](https://github.com/taiyang-li)).
* 此拉取请求为 Npy 数据格式提供了 countRows 支持。现在通过设置 `optimize_count_from_files=1`，像 `select count() from file(data.npy)` 这样的查询会因结果缓存而快得多。[#56304](https://github.com/ClickHouse/ClickHouse/pull/56304) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 带有 aggregation 且流数量较多的查询，在构建 plan 时将占用更少内存。[#57074](https://github.com/ClickHouse/ClickHouse/pull/57074) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 提升了在用户数量较多的用例中执行查询的性能。[#57106](https://github.com/ClickHouse/ClickHouse/pull/57106) ([Andrej Hoos](https://github.com/adikus)).
* 对 ARRAY JOIN 做了小幅优化，复用了一些中间结果。[#57183](https://github.com/ClickHouse/ClickHouse/pull/57183) ([李扬](https://github.com/taiyang-li)).
* 在某些情况下，栈展开的速度较慢。[#57221](https://github.com/ClickHouse/ClickHouse/pull/57221) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 现在，当 `max_streams = 1` 时，从外部存储读取会使用默认读 pool。在启用读取预取时，这样更有利。[#57334](https://github.com/ClickHouse/ClickHouse/pull/57334) ([Nikita Taranov](https://github.com/nickitat)).

* Keeper 改进：通过延迟日志预处理，降低启动期间的内存占用。[#55660](https://github.com/ClickHouse/ClickHouse/pull/55660) ([Antonio Andelic](https://github.com/antonio2368)).
* 修复了在线程附加到查询或用户之前分配的内存统计问题。[#56089](https://github.com/ClickHouse/ClickHouse/pull/56089) ([Nikita Taranov](https://github.com/nickitat)).
* 在 AWS 环境中运行时，ClickHouse Keeper 会在 `/keeper/availability-zone` 路径报告其当前所在的可用区。[#56104](https://github.com/ClickHouse/ClickHouse/pull/56104) ([Jianfei Hu](https://github.com/incfly)).
* 新增对 Arrow 中 LARGE&#95;LIST 的支持。[#56118](https://github.com/ClickHouse/ClickHouse/pull/56118) ([edef](https://github.com/edef1c)).
* 提升了 `file` 和 `hdfs` 存储的 glob 匹配性能。[#56141](https://github.com/ClickHouse/ClickHouse/pull/56141) ([Andrey Zvonov](https://github.com/zvonand)).
* 允许通过 `OPTIMIZE` 查询手动对 `EmbeddedRocksDB` 执行合并整理。[#56225](https://github.com/ClickHouse/ClickHouse/pull/56225) ([Azat Khuzhin](https://github.com/azat)).
* 倒排索引中的倒排列表现已压缩，可将其大小减少 10-30%。[#56226](https://github.com/ClickHouse/ClickHouse/pull/56226) ([Harry Lee](https://github.com/HarryLeeIBM)).
