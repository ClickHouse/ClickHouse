<div id="backward-incompatible-change">
  #### 向后不兼容的更改
</div>

* 修复了带有 `String` 参数的 `min`、`max`、`any*`、`argMin`、`argMax` 聚合函数状态在 (反) 序列化时的向后不兼容问题。该不兼容性由 [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431) 引入，影响 22.9、22.10 和 22.11 分支 (已分别在 22.9.6、22.10.4 和 22.11.2 中修复) 。22.3、22.7 和 22.8 分支的部分次要发行版也受此影响：22.3.13...22.3.14 (已在 22.3.15 中修复) 、22.8.6...22.8.9 (已在 22.8.10 中修复) 、22.7.6 及更高版本 (22.7 中不会修复，建议从 22.7.* 升级到 22.8.10 或更高版本) 。本发行说明不涉及从未使用过受影响版本的用户。不兼容版本在读取上述聚合函数的状态时，会在字符串末尾额外追加 `'\0'`。例如，如果旧版本将 `anyState('foobar')` 的状态保存到 `state_column`，那么不兼容版本在执行 `anyMerge(state_column)` 时会输出 `'foobar\0'`。此外，不兼容版本在写入这些聚合函数的状态时，不会写入末尾的 `'\0'`。较新版本 (即包含此修复的版本) 可以正确读取所有版本写入的数据，包括不兼容版本写入的数据，但有一个边界情况例外：如果某个不兼容版本保存的状态中，字符串本身实际就是以空字符结尾，那么较新版本在读取受影响聚合函数的状态时，会去掉末尾的 `'\0'`。例如，如果不兼容版本将 `anyState('abrac\0dabra\0')` 的状态保存到 `state_column`，那么较新版本在执行 `anyMerge(state_column)` 时会输出 `'abrac\0dabra'`。当不兼容版本与旧版本或较新版本同时在同一集群中运行时，该问题也会影响分布式查询。[#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)) 。

<div id="new-feature">
  #### 新特性
</div>

* 添加 `grace_hash` join&#95;algorithm。[#38191](https://github.com/ClickHouse/ClickHouse/pull/38191) ([BigRedEye](https://github.com/BigRedEye))。
* 如果设置了 `enable_memory_bound_merging_of_aggregation_results`，initiator 上的合并现在会像本地 aggregation 结果合并一样，采用相同的内存受限方案。[#40879](https://github.com/ClickHouse/ClickHouse/pull/40879) ([Nikita Taranov](https://github.com/nickitat))。
* 添加 BSONEachRow 输入/输出格式。在这种格式中，ClickHouse 会将每一行格式化/解析为一个独立的 BSON 文档，并将每一列格式化/解析为一个 BSON field，以列名作为 key。[#42033](https://github.com/ClickHouse/ClickHouse/pull/42033) ([mark-polokhov](https://github.com/mark-polokhov))。
* 已关闭：[#37631](https://github.com/ClickHouse/ClickHouse/issues/37631)。[#42265](https://github.com/ClickHouse/ClickHouse/pull/42265) ([刘陶峰](https://github.com/taofengliu))。
* 新增 `multiplyDecimal` 和 `divideDecimal` 函数，用于定点精度 decimal 运算。[#42438](https://github.com/ClickHouse/ClickHouse/pull/42438) ([Andrey Zvonov](https://github.com/zvonand))。
* 新增 `system.moves` 表，用于列出当前正在移动的 parts。[#42660](https://github.com/ClickHouse/ClickHouse/pull/42660) ([Sergei Trifonov](https://github.com/serxa))。
* Keeper 功能：增加对嵌入式 Prometheus 端点的支持。[#43087](https://github.com/ClickHouse/ClickHouse/pull/43087) ([Antonio Andelic](https://github.com/antonio2368))。
* 新增 age 函数，用于计算两个日期或两个带时间值的日期之间的差值，并以完整单位数表示。已关闭 [#41115](https://github.com/ClickHouse/ClickHouse/issues/41115)。[#43123](https://github.com/ClickHouse/ClickHouse/pull/43123) ([Roman Vasin](https://github.com/rvasin))。
* 添加 settings `max_streams_for_merge_tree_reading` 和 `allow_asynchronous_read_from_io_pool_for_merge_tree`。SETTING `max_streams_for_merge_tree_reading` 用于限制 MergeTree 表的读取流数量。SETTING `allow_asynchronous_read_from_io_pool_for_merge_tree` 用于启用后台 I/O pool 从 `MergeTree` 表读取。如果与 `max_streams_to_max_threads_ratio` 或 `max_streams_for_merge_tree_reading` 搭配使用，这可能会提升受 I/O 限制的 queries 的性能。[#43260](https://github.com/ClickHouse/ClickHouse/pull/43260) ([Nikolai Kochetov](https://github.com/KochetovNicolai))。
* 在 `data_skipping_indices` 系统表中添加索引表达式。[#43308](https://github.com/ClickHouse/ClickHouse/pull/43308) ([Guillaume Tassery](https://github.com/YiuRULE))。
* 新增哈希函数 [xxh3](https://github.com/Cyan4973/xxHash)。此外，得益于库更新，`xxHash32` 和 `xxHash64` 在 arm 上的性能也有所提升。[#43411](https://github.com/ClickHouse/ClickHouse/pull/43411) ([Nikita Taranov](https://github.com/nickitat))。
* * 临时数据 (用于外部排序、聚合和 JOIN) 可能会与远程磁盘的文件系统缓存共享存储空间，并将其驱逐，修复了 [#42158](https://github.com/ClickHouse/ClickHouse/issues/42158)。[#43457](https://github.com/ClickHouse/ClickHouse/pull/43457) ([Vladimir C](https://github.com/vdimir)) 。
* 向系统表 `databases` 新增列 `engine_full`，以便用户可通过系统表访问数据库的完整引擎定义。[#43468](https://github.com/ClickHouse/ClickHouse/pull/43468) ([凌涛](https://github.com/lingtaolf)).
* 为创建新用户新增密码复杂度规则和检查。[#43719](https://github.com/ClickHouse/ClickHouse/pull/43719) ([Nikolay Degterinsky](https://github.com/evillique)).
* 新增函数 concatWithSeparator ，类似 Spark 中的 concat&#95;ws。[#43749](https://github.com/ClickHouse/ClickHouse/pull/43749) ([李扬](https://github.com/taiyang-li)).
* 为 MergeTree 设置新增约束。[#43903](https://github.com/ClickHouse/ClickHouse/pull/43903) ([Sergei Trifonov](https://github.com/serxa)).
* 支持使用 &#95; 作为分隔符的数字字面量。[#43925](https://github.com/ClickHouse/ClickHouse/pull/43925) ([jh0x](https://github.com/jh0x)).
* 新增设置 `input_format_json_read_objects_as_strings`，允许在所有 JSON 输入格式中将嵌套 JSON 对象解析为 String。该设置默认禁用。[#44052](https://github.com/ClickHouse/ClickHouse/pull/44052) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="improvement">
  #### 改进
</div>

* 支持带下划线的数字字面量。关闭 [#28967](https://github.com/ClickHouse/ClickHouse/issues/28967)。 [#39129](https://github.com/ClickHouse/ClickHouse/pull/39129) ([unbyte](https://github.com/unbyte)).
* 添加 `FROM table SELECT column` 语法。 [#41095](https://github.com/ClickHouse/ClickHouse/pull/41095) ([Nikolay Degterinsky](https://github.com/evillique)).
* 此 PR 修改了以下查询删除 parts 的方式：truncate table、alter table drop part、alter table drop partition。现在，这些查询会创建覆盖旧 parts 的空 parts。这样一来，truncate 查询无需独占锁即可执行，也就是说不会阻塞并发 reads。此外，这些查询现在也具备了持久性。如果 request 成功，之后就不会再出现已删除 parts 复活的情况。请注意，atomicity 仅在 transaction 作用域内实现。 [#41145](https://github.com/ClickHouse/ClickHouse/pull/41145) ([Sema Checherinda](https://github.com/CheSema)).
* `SET param_x` 查询不再要求对参数值手动进行字符串 serialization。例如，查询 `SET param_a = '[\'a\', \'b\']'` 现在可以写成 `SET param_a = ['a', 'b']`。 [#41874](https://github.com/ClickHouse/ClickHouse/pull/41874) ([Nikolay Degterinsky](https://github.com/evillique)).
* `filesystemAvailable` 及相关函数支持一个用于指定 disk 名称的可选参数，并将 `filesystemFree` 更名为 `filesystemUnreserved`。关闭 [#35076](https://github.com/ClickHouse/ClickHouse/issues/35076)。 [#42064](https://github.com/ClickHouse/ClickHouse/pull/42064) ([flynn](https://github.com/ucasfl)).
* 将 search&#95;limit 的 default value 提高到 256，并新增 LDAP server config 选项，可将其设置为任意值。关闭： [#42276](https://github.com/ClickHouse/ClickHouse/issues/42276)。 [#42461](https://github.com/ClickHouse/ClickHouse/pull/42461) ([Vasily Nemkov](https://github.com/Enmk)).
* 为 annoy 添加 cosine distance。 [#42778](https://github.com/ClickHouse/ClickHouse/pull/42778) ([Filatenkov Artur](https://github.com/FArthur-cmd)).
* 现在也允许从 exception 消息中移除敏感信息。解决 [#41418](https://github.com/ClickHouse/ClickHouse/issues/41418)。 [#42940](https://github.com/ClickHouse/ClickHouse/pull/42940) ([filimonov](https://github.com/filimonov)).
* Keeper 改进：新增 4lw 命令 `rqld`，可手动将某个节点指定为 leader。 [#43026](https://github.com/ClickHouse/ClickHouse/pull/43026) ([JackyWoo](https://github.com/JackyWoo)).
* 将查询中的 connection timeouts settings 应用于 Distributed async INSERT。 [#43156](https://github.com/ClickHouse/ClickHouse/pull/43156) ([Azat Khuzhin](https://github.com/azat)).
* unhex 函数支持 FixedString 参数。 [issue42369](https://github.com/ClickHouse/ClickHouse/issues/42369)。 [#43207](https://github.com/ClickHouse/ClickHouse/pull/43207) ([DR](https://github.com/freedomDR)).
* 优先删除已完全过期的 Parts，相关 [#42869](https://github.com/ClickHouse/ClickHouse/issues/42869)。 [#43222](https://github.com/ClickHouse/ClickHouse/pull/43222) ([zhongyuankai](https://github.com/zhongyuankai)).
* 对 [https://github.com/ClickHouse/ClickHouse/pull/42484](https://github.com/ClickHouse/ClickHouse/pull/42484) 的后续改进。进一步改进 logs 中敏感信息的屏蔽；同时屏蔽查询 `SHOW CREATE TABLE` 和 `SELECT FROM system.tables` 输出中的 secret 部分。也解决了 [#41418](https://github.com/ClickHouse/ClickHouse/issues/41418)。 [#43227](https://github.com/ClickHouse/ClickHouse/pull/43227) ([Vitaly Baranov](https://github.com/vitlibar)).
* 启用对 marks 和 primary key 的压缩。 [#43288](https://github.com/ClickHouse/ClickHouse/pull/43288) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 解决 issue [#38075](https://github.com/ClickHouse/ClickHouse/issues/38075)。目前 async insert 还不支持去重，因为多个小型 insert 会共存在同一个 part 中，从而对应多个 `block id`。这个方案很直接：变更包括：1. 为每个 chunk 中的每次 insert 标记 offsets 2. 当 sinker 收到一个 chunk 时，计算多个 `block_id` 3. 通过这些 `block_id` 获取 block number lock 3.1. 如果失败，则从块中移除重复的 insert 和重复的 `block_id`，并重新计算 `offsets`。3.2. 如果成功，则将 `block_id` 和其他条目提交到 Keeper a. 如果失败，执行 3.1 b. 如果成功，则全部成功。[#43304](https://github.com/ClickHouse/ClickHouse/pull/43304) ([Han Fei](https://github.com/hanfei1991)).
* 客户端上的 CPU 负载指示现在更精确，响应也更及时。[#43307](https://github.com/ClickHouse/ClickHouse/pull/43307) ([Sergei Trifonov](https://github.com/serxa)).
* 限制在 config 中定义的用户对 named collections 的默认访问权限。必须显式设置 `show_named_collections=1` 才能查看它们。[#43325](https://github.com/ClickHouse/ClickHouse/pull/43325) ([Kseniia Sumarokova](https://github.com/kssenii)).
