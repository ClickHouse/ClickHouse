<div id="clickhouse-release-v20513833-prestable-fixme-as-compared-to-v20413177-prestable">
  ### ClickHouse release v20.5.1.3833-prestable，与 v20.4.1.3177-prestable 相比的 FIXME
</div>

<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 移除 `experimental_use_processors` 设置。该设置默认已启用。[#10924](https://github.com/ClickHouse/ClickHouse/pull/10924) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* `input_format_with_names_use_header` 设置默认已启用。这将影响输入格式 `-WithNames` 和 `-WithNamesAndTypes` 的解析。[#10937](https://github.com/ClickHouse/ClickHouse/pull/10937) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 新增了一项检查，用于检测 user-level setting 是否被配置在错误的位置。user-level settings 应在 `users.xml` 中的特定用户 profile 的 `<profile>` 部分内指定 (默认设置则应在 `<default>` 中指定) 。如果存在此类异常，server 将无法启动，并会在日志中输出异常信息。这修复了 [#9051](https://github.com/ClickHouse/ClickHouse/issues/9051)。如果你想跳过这项检查，可以将设置移到正确的位置，或者在 config.xml 中添加 `<skip_check_for_incorrect_settings>1</skip_check_for_incorrect_settings>`。[#11449](https://github.com/ClickHouse/ClickHouse/pull/11449) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* `COUNT(DISTINCT)` 和 `uniq` aggregate functions 家族现在返回 non-Nullable 结果。如果传入的所有值都是 NULL，则返回 0。这提升了 SQL 兼容性。[#11661](https://github.com/ClickHouse/ClickHouse/pull/11661) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。

* 新增 `direct` 布局，会在每次查询时直接从源加载所有数据，而不进行本地存储或缓存。 [#10622](https://github.com/ClickHouse/ClickHouse/pull/10622) ([Artem Streltsov](https://github.com/kekekekule)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 基于表排序键优化 GROUP BY。[#9113](https://github.com/ClickHouse/ClickHouse/pull/9113) ([Dmitry Rubashkin](https://github.com/dimarub2000)) 。
* 新增一种优化，可将算术运算从聚合函数中提取出来。[#10047](https://github.com/ClickHouse/ClickHouse/pull/10047) ([Ruslan](https://github.com/kamalov-ruslan)) 。
* 此功能会消除 GROUP BY 部分中其他键上的函数调用。[#10051](https://github.com/ClickHouse/ClickHouse/pull/10051) ([Victor Grishanin](https://github.com/xPoSx)) 。
* 添加运行时 CPU 检测，以选择并分派最优的函数实现。新增对多目标代码生成的支持。此变更关闭了 [#1017](https://github.com/ClickHouse/ClickHouse/issues/1017)。[#10058](https://github.com/ClickHouse/ClickHouse/pull/10058) ([DimasKovas](https://github.com/DimasKovas)) 。
* 移除子查询中重复的 ORDER BY 和 DISTINCT。[#10067](https://github.com/ClickHouse/ClickHouse/pull/10067) ([Mikhail Malafeev](https://github.com/demo-99)) 。
* 在 MergeJoin 中对左表中更大的 parts 进行排序。将左侧块缓存在内存中。新增 `partial_merge_join_left_table_buffer_bytes` 设置，用于控制左侧块缓冲区的大小。[#10601](https://github.com/ClickHouse/ClickHouse/pull/10601) ([Artem Zuikov](https://github.com/4ertus2)) 。
* 对于任意读取外部字典的函数，每次调用只获取一次字典并检查一次访问权限。[#10928](https://github.com/ClickHouse/ClickHouse/pull/10928) ([Vitaly Baranov](https://github.com/vitlibar)) 。
* 通过移除一些冗余的数据移动来改进基数排序。[#10981](https://github.com/ClickHouse/ClickHouse/pull/10981) ([Arslan Gumerov](https://github.com/g-arslan)) 。
* 让使用 `sum` 聚合函数且不含 GROUP BY 键的查询运行速度提升数倍。[#10992](https://github.com/ClickHouse/ClickHouse/pull/10992) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 默认对 `clickhouse` 二进制文件启用 mlock。这将防止 ClickHouse 可执行文件在高 IO 负载下被换出到分页空间。[#11139](https://github.com/ClickHouse/ClickHouse/pull/11139) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 提升带有 `ORDER BY` 和较小 `LIMIT` (小于 `max_block_size`) 的查询性能。[#11171](https://github.com/ClickHouse/ClickHouse/pull/11171) ([Provet](https://github.com/Provet)) 。
* 提升通过 INSERT SELECT 或使用 ClickHouse 客户端执行 INSERT 查询时的性能，适用于生成小块的情况 (这是并行解析的典型场景) 。此修复解决了 [#11275](https://github.com/ClickHouse/ClickHouse/issues/11275)。修复了 CONSTRAINTs 对 DEFAULT 字段不起作用的问题。此修复解决了 [#11273](https://github.com/ClickHouse/ClickHouse/issues/11273)。修复了 CONSTRAINTS 在 TEMPORARY 表中被忽略的问题。此修复解决了 [#11274](https://github.com/ClickHouse/ClickHouse/issues/11274)。[#11276](https://github.com/ClickHouse/ClickHouse/pull/11276) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 在交互模式下使用 Pretty formats 时，提升 `clickhouse-client` 的性能。在之前的版本中，计算 UTF-8 字符串的可见宽度可能会耗费大量时间。此变更关闭了 [#11323](https://github.com/ClickHouse/ClickHouse/issues/11323)。[#11323](https://github.com/ClickHouse/ClickHouse/pull/11323) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 新增一种优化，可将所有操作从 &quot;any&quot; 函数中提取出来。[#11529](https://github.com/ClickHouse/ClickHouse/pull/11529) ([Ruslan](https://github.com/kamalov-ruslan)) 。
* 加快 AggregatingMergeTree 中的合并速度。这修复了一年多前在 [#4348](https://github.com/ClickHouse/ClickHouse/issues/4348) (19.3 版本) 中引入的性能回退。[#11534](https://github.com/ClickHouse/ClickHouse/pull/11534) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 允许多个副本并发分配合并、变更、分区删除、移动和替换操作。这修复了 [#10367](https://github.com/ClickHouse/ClickHouse/issues/10367)。[#11639](https://github.com/ClickHouse/ClickHouse/pull/11639) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 此优化会消除 SELECT 子句中针对 GROUP BY 键的 min/max/any 聚合函数。[#11667](https://github.com/ClickHouse/ClickHouse/pull/11667) ([Victor Grishanin](https://github.com/xPoSx)) 。

* 移除了对 `tzdata` 的依赖：如果 `/usr/share/zoneinfo` 目录不存在，也不会报错。请注意，即使系统中未安装 tzdata，ClickHouse 中的所有时区也都能正常工作。[#11827](https://github.com/ClickHouse/ClickHouse/pull/11827) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
