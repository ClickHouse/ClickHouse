  ### ClickHouse 版本 v24.4.1.2088-稳定版本 (6d4b31322d1) FIXME，与 v24.3.1.2672-lts (2c5c589a882) 相比
</div>

<div id="backward-incompatible-change">
  #### 向后不兼容的更改
</div>

* 不再允许将 max&#95;parallel&#95;replicas 设置为 0，因为这样没有意义。将其设为 0 可能会导致异常的 logical error。解决了 [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140)。[#61201](https://github.com/ClickHouse/ClickHouse/pull/61201) ([Kruglov Pavel](https://github.com/Avogar)).
* `clickhouse-odbc-bridge` 和 `clickhouse-library-bridge` 已拆分为两个独立的软件包。此更改解决了 [#61677](https://github.com/ClickHouse/ClickHouse/issues/61677)。[#62114](https://github.com/ClickHouse/ClickHouse/pull/62114) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 移除对 INSERT WATCH 查询的支持 (属于 Experimental LIVE VIEW 功能的一部分) 。[#62382](https://github.com/ClickHouse/ClickHouse/pull/62382) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 移除 optimize&#95;monotonous&#95;functions&#95;in&#95;order&#95;by 设置。[#63004](https://github.com/ClickHouse/ClickHouse/pull/63004) ([Raúl Marín](https://github.com/Algunenano)).

<div id="new-feature">
  #### 新特性
</div>

* 支持同时删除多个表，如 `drop table a,b,c`。 [#58705](https://github.com/ClickHouse/ClickHouse/pull/58705) ([zhongyuankai](https://github.com/zhongyuankai)).
* 现在可以对表引擎授予权限，且不会影响现有用户的行为。 [#60117](https://github.com/ClickHouse/ClickHouse/pull/60117) ([jsc0218](https://github.com/jsc0218)).
* 新增可重写的 S3 disk，支持 `INSERT` 操作，且不需要在本地存储元数据。 [#61116](https://github.com/ClickHouse/ClickHouse/pull/61116) ([Julia Kartseva](https://github.com/jkartseva)).
* 为方便起见，`SELECT * FROM numbers() `现在的行为与 `SELECT * FROM system.numbers` 相同，即不带 limit。 [#61969](https://github.com/ClickHouse/ClickHouse/pull/61969) ([YenchangChan](https://github.com/YenchangChan)).
* 现已支持通过 `ALTER MODIFY SETTING` 修改 Memory 表设置。 `ALTER TABLE memory MODIFY SETTING min_rows_to_keep = 100, max_rows_to_keep = 1000;`. [#62039](https://github.com/ClickHouse/ClickHouse/pull/62039) ([zhongyuankai](https://github.com/zhongyuankai)).
* analyzer 支持递归 CTE。 [#62074](https://github.com/ClickHouse/ClickHouse/pull/62074) ([Maksim Kita](https://github.com/kitaisreal)).
* analyzer 支持 QUALIFY Clause。关闭 [#47819](https://github.com/ClickHouse/ClickHouse/issues/47819)。 [#62619](https://github.com/ClickHouse/ClickHouse/pull/62619) ([Maksim Kita](https://github.com/kitaisreal)).
* HTTP interface 新增了 `role` 查询参数。其工作方式类似于 `SET ROLE x`，会在语句执行前应用该 role。这样就可以绕过 HTTP interface 的限制，因为它不允许多条语句，也无法同时发送 `SET ROLE x` 和语句本身。还可以通过这种方式设置多个 role，例如 `?role=x&role=y``，其等价于 `SET ROLE x, y&#96;。 [#62669](https://github.com/ClickHouse/ClickHouse/pull/62669) ([Serge Klochkov](https://github.com/slvrtrn)).
* 新增 `SYSTEM UNLOAD PRIMARY KEY`。 [#62738](https://github.com/ClickHouse/ClickHouse/pull/62738) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 降低 SELECT 查询中变更操作的开销 (v2) 。[#60856](https://github.com/ClickHouse/ClickHouse/pull/60856) ([Azat Khuzhin](https://github.com/azat)).
* 现在会对 PODArray 中更常调用的函数强制内联。[#61144](https://github.com/ClickHouse/ClickHouse/pull/61144) ([李扬](https://github.com/taiyang-li)).
* 使用等价集合改进 JOIN 过滤器下推。[#61216](https://github.com/ClickHouse/ClickHouse/pull/61216) ([Maksim Kita](https://github.com/kitaisreal)).
* 默认启用快速 Parquet 编码器 (`output_format_parquet_use_custom_encoder`) 。[#62088](https://github.com/ClickHouse/ClickHouse/pull/62088) ([Michael Kolupaev](https://github.com/al13n321)).
* ... 当所有必需字段都已读取后，直接跳过其余所有字段，从而减少大量比较操作。[#62210](https://github.com/ClickHouse/ClickHouse/pull/62210) ([lgbo](https://github.com/lgbo-ustc)).
* 函数 `splitByChar` 和 `splitByRegexp` 的执行速度现已显著提升。[#62392](https://github.com/ClickHouse/ClickHouse/pull/62392) ([李扬](https://github.com/taiyang-li)).
* 改进了从 file/s3/hdfs/url/... 表函数中的文件执行简单 insert select 的性能。新增独立的 `max_parsing_threads` 设置，用于控制并行解析时使用的线程数。[#62404](https://github.com/ClickHouse/ClickHouse/pull/62404) ([Kruglov Pavel](https://github.com/Avogar)).
* 通过设置 `azure_allow_parallel_part_upload`，支持由 AzureBlobStorage 管理的并行写入缓冲区。[#62534](https://github.com/ClickHouse/ClickHouse/pull/62534) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 函数 `to_utc_timestamp` 和 `from_utc_timestamp` 现在的速度约为原来的 2 倍。[#62583](https://github.com/ClickHouse/ClickHouse/pull/62583) ([KevinyhZou](https://github.com/KevinyhZou)).
* 当输入中大多是无法解析的值时，函数 `parseDateTimeOrNull`、`parseDateTimeOrZero`、`parseDateTimeInJodaSyntaxOrNull` 和 `parseDateTimeInJodaSyntaxOrZero` 现在运行速度显著提升 (10x - 1000x) 。[#62634](https://github.com/ClickHouse/ClickHouse/pull/62634) ([LiuNeng](https://github.com/liuneng1994)).
* 当查询缓存包含大量条目时 (例如超过 100,000 个) ，针对 `system.query_cache` 的 SELECT 查询现在明显更快。[#62671](https://github.com/ClickHouse/ClickHouse/pull/62671) ([Robert Schulze](https://github.com/rschu1ze)).
* 如果 JOIN 后的过滤器总是会过滤掉默认值，QueryPlan 现在可将 OUTER JOIN 优化为 INNER JOIN。该优化可通过设置 `query_plan_convert_outer_join_to_inner_join` 控制，且默认启用。[#62907](https://github.com/ClickHouse/ClickHouse/pull/62907) ([Maksim Kita](https://github.com/kitaisreal)).
* 默认启用 `optimize_rewrite_sum_if_to_count_if`。[#62929](https://github.com/ClickHouse/ClickHouse/pull/62929) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### 改进
</div>

* 为 Kafka 配置引入独立的 consumer/producer 标签。这样可避免 librdkafka 发出警告，提示为 producer 实例指定了 consumer 属性，或反之 (例如 `Configuration property session.timeout.ms is a consumer property and will be ignored by this producer instance`) 。关闭：[#58983](https://github.com/ClickHouse/ClickHouse/issues/58983)。[#58956](https://github.com/ClickHouse/ClickHouse/pull/58956) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* 为 `system.text_log` 添加了 `value1`、`value2`、...、`value10` 列。这些列包含用于格式化消息的值。[#59619](https://github.com/ClickHouse/ClickHouse/pull/59619) ([Alexey Katsman](https://github.com/alexkats)).
* 新增设置 `first_day_of_week`，它会影响函数 `toStartOfInterval(..., INTERVAL ... WEEK)` 所采用的一周起始日。这样可与函数 `toStartOfWeek` 保持一致，后者默认将星期日视为一周的第一天。[#60598](https://github.com/ClickHouse/ClickHouse/pull/60598) ([Jordi Villar](https://github.com/jrdi)).
* 新增持久化虚拟列 `_block_offset`，用于存储在 insert 时分配的块内原始行号。可通过设置 `enable_block_offset_column` 启用列 `_block_offset` 的持久化。还新增了虚拟列 `_part_data_version`，其中包含 part 的最小 block 编号或变更版本。持久化虚拟列 `_block_number` 现已不再被视为 Experimental。[#60676](https://github.com/ClickHouse/ClickHouse/pull/60676) ([Anton Popov](https://github.com/CurtizJ)).
* 减少文件系统缓存中的争用 (第 3 部分) ：在尝试预留空间时，可在不加锁的情况下从文件系统中执行移除。[#61163](https://github.com/ClickHouse/ClickHouse/pull/61163) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 函数 `date_diff` 和 `age` 现在按纳秒精度而非微秒精度计算结果。现在还支持将 `nanosecond` (或 `nanoseconds` 或 `ns`) 作为 `unit` 参数的取值。[#61409](https://github.com/ClickHouse/ClickHouse/pull/61409) ([Austin Kothig](https://github.com/kothiga)).
* 现在在 merge 期间不会为 wide parts 加载标记。[#61551](https://github.com/ClickHouse/ClickHouse/pull/61551) ([Anton Popov](https://github.com/CurtizJ)).
* 在重新加载证书时也会重新加载证书链。[#61671](https://github.com/ClickHouse/ClickHouse/pull/61671) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* 加快文件系统缓存的动态调整大小。[#61723](https://github.com/ClickHouse/ClickHouse/pull/61723) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 新增 `TRUNCATE ALL TABLES`。[#61862](https://github.com/ClickHouse/ClickHouse/pull/61862) ([豪肥肥](https://github.com/HowePa)).
* 尝试避免 [#60432](https://github.com/ClickHouse/ClickHouse/issues/60432)：如果某个副本路径上已有活动副本，则不允许附加表。[#61876](https://github.com/ClickHouse/ClickHouse/pull/61876) ([Arthur Passos](https://github.com/arthurpassos)).
* 新增设置 `input_format_json_throw_on_bad_escape_sequence`，禁用后即可在 JSON 输入格式中保存错误的转义序列。[#61889](https://github.com/ClickHouse/ClickHouse/pull/61889) ([Kruglov Pavel](https://github.com/Avogar)).
* 用户态页缓存现已支持静态 web 存储 (`disk(type = web)`) 。可通过客户端设置 `use_page_cache_for_disks_without_file_cache=1` 启用。[#61911](https://github.com/ClickHouse/ClickHouse/pull/61911) ([Michael Kolupaev](https://github.com/al13n321)).
* 为 clickhouse-local 实现了 `input()`。[#61923](https://github.com/ClickHouse/ClickHouse/pull/61923) ([Azat Khuzhin](https://github.com/azat)).
* 修复撤销 quorum 插入事务时的逻辑错误。[#61953](https://github.com/ClickHouse/ClickHouse/pull/61953) ([Han Fei](https://github.com/hanfei1991)).
* strictness 为 `ANY` 的 StorageJoin 在重新加载后保持一致。当插入多行具有相同键的数据时，第一行现在具有更高优先级 (此前会在表加载时随机选择) 。关闭 [#51027](https://github.com/ClickHouse/ClickHouse/issues/51027)。[#61972](https://github.com/ClickHouse/ClickHouse/pull/61972) ([vdimir](https://github.com/vdimir)).
* 自动从 Apache Arrow schema 推断 Nullable 列类型。[#61984](https://github.com/ClickHouse/ClickHouse/pull/61984) ([Maksim Kita](https://github.com/kitaisreal)).
* 允许在 aggregation 期间取消 aggregate states 的并行 merge。示例：`uniqExact`。[#61992](https://github.com/ClickHouse/ClickHouse/pull/61992) ([Maksim Kita](https://github.com/kitaisreal)).
* 不再将 Bool 和数值变体视为 Variant 类型中的可疑项。[#61999](https://github.com/ClickHouse/ClickHouse/pull/61999) ([Kruglov Pavel](https://github.com/Avogar)).
* 使用 `system.keywords` 填充建议项，并在内部所有位置统一使用它们。[#62000](https://github.com/ClickHouse/ClickHouse/pull/62000) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 使用 parsing 改进从 String 到 Variant 的转换。[#62005](https://github.com/ClickHouse/ClickHouse/pull/62005) ([Kruglov Pavel](https://github.com/Avogar)).
* 在 JSONExtract 函数中支持 Variant。[#62014](https://github.com/ClickHouse/ClickHouse/pull/62014) ([Kruglov Pavel](https://github.com/Avogar)).
* 带有 `INVALIDATE_QUERY` 的字典源在启动时不会重复加载两次。[#62050](https://github.com/ClickHouse/ClickHouse/pull/62050) ([vdimir](https://github.com/vdimir)).
* 用于 `ReplicatedMergeTree` 的 `OPTIMIZE FINAL` 现在会等待当前活跃的 merges 完成，然后再次尝试调度 final merge。这使其行为更接近普通 `MergeTree`。[#62067](https://github.com/ClickHouse/ClickHouse/pull/62067) ([Nikita Taranov](https://github.com/nickitat)).
* 读取 Hive text file 中的数据时，系统会根据第一行调整输入字段数；但有时第一行的字段数与 Hive 表定义不一致。例如，Hive 表定义为 3 列，即 `test_tbl(a Int32, b Int32, c Int32)`，但文本文件第一行只有 2 个字段。在这种情况下，输入字段数会被调整为 2；如果下一行有 3 个字段，则第三个字段无法读取，而会被设置为默认值 0，这是不正确的。[#62086](https://github.com/ClickHouse/ClickHouse/pull/62086) ([KevinyhZou](https://github.com/KevinyhZou)).
* CREATE AS 会复制注释。[#62117](https://github.com/ClickHouse/ClickHouse/pull/62117) ([Pablo Marcos](https://github.com/pamarcos)).
* client 中输入时的 syntax highlighting 将基于 syntax 层级工作 (此前基于 lexer 层级) 。[#62123](https://github.com/ClickHouse/ClickHouse/pull/62123) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了这样一个问题：当在涉及主键的布尔表达式后追加冗余的 `= 1` 或 `= 0` 时，主索引不会被使用。例如，`SELECT * FROM <table> WHERE <primary-key> IN (<value>) = 1` 和 `SELECT * FROM <table> WHERE <primary-key> NOT IN (<value>) = 0` 都会执行全表扫描，而实际上可以使用主索引。[#62142](https://github.com/ClickHouse/ClickHouse/pull/62142) ([josh-hildred](https://github.com/josh-hildred)).
* 为 `zookeeper` 表添加查询进度。 [#62152](https://github.com/ClickHouse/ClickHouse/pull/62152) ([JackyWoo](https://github.com/JackyWoo)).
* 新增可在整个服务器范围内启用 trace collector (Real 和 CPU) 的能力。 [#62189](https://github.com/ClickHouse/ClickHouse/pull/62189) ([alesapin](https://github.com/alesapin)).
* 新增设置 `lightweight_deletes_sync` (默认值：2 - 同步等待所有副本) 。该设置与 `mutations_sync` 类似，但仅影响轻量级删除的行为。 [#62195](https://github.com/ClickHouse/ClickHouse/pull/62195) ([Anton Popov](https://github.com/CurtizJ)).
* 在解析自定义设置的配置值时，区分布尔值和整数：`SET custom_a = true; SET custom_b = 1;`。 [#62206](https://github.com/ClickHouse/ClickHouse/pull/62206) ([Vitaly Baranov](https://github.com/vitlibar)).
* 支持通过 AWS Private Link Interface 端点访问 S3。关闭 [#60021](https://github.com/ClickHouse/ClickHouse/issues/60021)、[#31074](https://github.com/ClickHouse/ClickHouse/issues/31074) 和 [#53761](https://github.com/ClickHouse/ClickHouse/issues/53761)。 [#62208](https://github.com/ClickHouse/ClickHouse/pull/62208) ([Arthur Passos](https://github.com/arthurpassos)).
* 客户端必须向服务端发送请求头 &#39;Keep-Alive: timeout=X&#39;。如果客户端从服务端收到带有该请求头的响应，则必须使用服务端提供的值。此外，为避免 connection close 竞争，客户端最好不要使用即将过期的 connection。 [#62249](https://github.com/ClickHouse/ClickHouse/pull/62249) ([Sema Checherinda](https://github.com/CheSema)).
* 为 date&#95;trunc 新增纳秒、微秒和毫秒单位。 [#62335](https://github.com/ClickHouse/ClickHouse/pull/62335) ([Misz606](https://github.com/Misz606)).
* 如果 UDF 目录不存在，则不要在 ClickHouse 客户端中为其创建目录。此更改关闭了 [#59597](https://github.com/ClickHouse/ClickHouse/issues/59597)。 [#62366](https://github.com/ClickHouse/ClickHouse/pull/62366) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 查询缓存现在不再缓存针对系统表 (`system.*`、`information_schema.*`、`INFORMATION_SCHEMA.*`) 的查询结果。 [#62376](https://github.com/ClickHouse/ClickHouse/pull/62376) ([Robert Schulze](https://github.com/rschu1ze)).
* `MOVE PARTITION TO TABLE` 查询可能会被延迟，或抛出 `TOO_MANY_PARTS` 异常，以避免超过 parts 数量限制。其应用的设置和限制与 `INSERT` 查询相同 (参见 `max_parts_in_total`、`parts_to_delay_insert`、`parts_to_throw_insert`、`inactive_parts_to_throw_insert`、`inactive_parts_to_delay_insert`、`max_avg_part_size_for_too_many_parts`、`min_delay_to_insert_ms` 和 `max_delay_to_insert` 设置) 。 [#62420](https://github.com/ClickHouse/ClickHouse/pull/62420) ([Sergei Trifonov](https://github.com/serxa)).
* 为系统表 `blob_storage_log` 补充了缺失的 `hostname` 列。 [#62456](https://github.com/ClickHouse/ClickHouse/pull/62456) ([Jayme Bird](https://github.com/jaymebrd)).
* 将 macOS 上的默认安装目录从 `/usr/bin` 更改为 `/usr/local/bin`。这是必要的，因为 Apple 在 macOS El Capitan (2015) 中引入的 System Integrity Protection 会阻止向 `/usr/bin` 写入，即使使用 `sudo` 也是如此。 [#62489](https://github.com/ClickHouse/ClickHouse/pull/62489) ([haohang](https://github.com/yokofly)).
* 使 transform 始终返回第一个匹配项。 [#62518](https://github.com/ClickHouse/ClickHouse/pull/62518) ([Raúl Marín](https://github.com/Algunenano)).
* 为与其他系统表保持一致，`system.backup_log` 现在新增了 `event_time` 列。[#62541](https://github.com/ClickHouse/ClickHouse/pull/62541) ([Jayme Bird](https://github.com/jaymebrd)).
* 执行 `RESTORE` 时，避免计算表的 DEFAULT 表达式。[#62601](https://github.com/ClickHouse/ClickHouse/pull/62601) ([Vitaly Baranov](https://github.com/vitlibar)).
* `system.remote_data_paths` 现在返回 chunk stream，而不是将整个结果累积到一个大 chunk 中。这样可以减少内存消耗、显示中间进度，并支持取消查询。[#62613](https://github.com/ClickHouse/ClickHouse/pull/62613) ([Alexander Gololobov](https://github.com/davenger)).
* S3 storage 和 backups 也需要使用与 S3 disk 相同的默认 Keep-Alive 设置。[#62648](https://github.com/ClickHouse/ClickHouse/pull/62648) ([Sema Checherinda](https://github.com/CheSema)).
* 表 `system.backup_log` 现在使用“default”排序键，即 `event_date, event_time`，与其他 `_log` 表引擎相同。[#62667](https://github.com/ClickHouse/ClickHouse/pull/62667) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 将 Variant 类型标记为可比较，因此可用于主键。[#62693](https://github.com/ClickHouse/ClickHouse/pull/62693) ([Kruglov Pavel](https://github.com/Avogar)).
* 将 librdkafka 的 client 标识符添加到日志消息中，以便区分同一张表的不同消费者产生的日志消息。[#62813](https://github.com/ClickHouse/ClickHouse/pull/62813) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 允许在 Replicated database 的 ZooKeeper 路径中使用特殊宏 {uuid} 和 {database}。[#62818](https://github.com/ClickHouse/ClickHouse/pull/62818) ([Vitaly Baranov](https://github.com/vitlibar)) 。
* 允许 HTTP 请求中的配额键使用不同的认证方案。[#62842](https://github.com/ClickHouse/ClickHouse/pull/62842) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 移除 Replicated 数据库引擎上的 Experimental 标签。现已进入 Beta 阶段。[#62937](https://github.com/ClickHouse/ClickHouse/pull/62937) ([Justin de Guzman](https://github.com/justindeguzman)).
* 精简 `clickhouse client` 和 `clickhouse local` 中命令行参数 `--help` 的输出；之前的输出现在可通过 `--help --verbose` 生成。[#62973](https://github.com/ClickHouse/ClickHouse/pull/62973) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 如果达到[用户的 `valid_until`](https://clickhouse.com/docs/en/sql-reference/statements/create/user#valid-until-clause)，则关闭 session。[#63046](https://github.com/ClickHouse/ClickHouse/pull/63046) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* MySQL 8.3 已移除 `log_bin_use_v1_row_events`，修复了 [#60479](https://github.com/ClickHouse/ClickHouse/issues/60479)。[#63101](https://github.com/ClickHouse/ClickHouse/pull/63101) ([Eugene Klimov](https://github.com/Slach)).

<div id="buildtestingpackaging-improvement">
  #### 构建/测试/打包改进
</div>
