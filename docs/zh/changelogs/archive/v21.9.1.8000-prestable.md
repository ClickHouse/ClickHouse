<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 修复了这样一个问题：在某些复杂查询中，如果列别名与表达式名称相同，可能会发生错误的类型转换。此修复解决了 [#25447](https://github.com/ClickHouse/ClickHouse/issues/25447) 和 [#26914](https://github.com/ClickHouse/ClickHouse/issues/26914)。该修复可能会引入向后不兼容的变更：如果存在名称相同但实际不同的表达式，将会抛出异常。当设置 `enable_optimize_predicate_expression` 时，这可能会破坏某些少见场景。[#26639](https://github.com/ClickHouse/ClickHouse/pull/26639) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 在 clickhouse-local 中，始终将带端口的本地地址视为远程地址。[#26736](https://github.com/ClickHouse/ClickHouse/pull/26736) ([Raúl Marín](https://github.com/Algunenano))。
* 不允许将带有 `-Merge` 组合器的参数化聚合函数应用到聚合函数状态上，如果该状态是由参数不同的聚合函数生成的。例如，`fooState(42)(x)` 的状态不能用 `fooMerge(s)` 或 `fooMerge(123)(s)` 来完成最终计算，必须显式指定参数，如 `fooMerge(42)(s)`，且参数必须一致。这不会影响某些特殊的聚合函数，例如 `quantile` 和 `sequence*`，因为它们的参数仅用于最终计算。[#26847](https://github.com/ClickHouse/ClickHouse/pull/26847) ([Alexander Tokmakov](https://github.com/tavplubix))。
* 在 `Decimal` 类型的文本表示中不再输出末尾的零。示例：对于标度为 6 的 decimal，将打印 `1.23`，而不是 `1.230000`。这关闭了 [#15794](https://github.com/ClickHouse/ClickHouse/issues/15794)。如果你的应用程序以某种方式依赖这些末尾的零，可能会引入轻微的不兼容性。输出格式中的序列化行为可通过设置 `output_format_decimal_trailing_zeros` 控制。`toString` 的实现以及转换为 String 的行为已无条件更改。[#27680](https://github.com/ClickHouse/ClickHouse/pull/27680) ([Alexey Milovidov](https://github.com/alexey-milovidov))。

<div id="performance-improvement">
  #### 性能提升
</div>

* 编译聚合函数 `groupBitOr`、`groupBitAnd`、`groupBitXor`。[#26161](https://github.com/ClickHouse/ClickHouse/pull/26161) ([Maksim Kita](https://github.com/kitaisreal)).
* 编译 `Enum` 类型的列。[#26237](https://github.com/ClickHouse/ClickHouse/pull/26237) ([Maksim Kita](https://github.com/kitaisreal)).
* * 使用原生表示对 Nullable 整数类型的 SUM 进行向量化。 ([David Manzanares](https://github.com/davidmanzanares), [Raúl Marín](https://github.com/Algunenano)) 。[#26248](https://github.com/ClickHouse/ClickHouse/pull/26248) ([Raúl Marín](https://github.com/Algunenano)).
* 在分析查询时，不再为索引构建集合。[#26365](https://github.com/ClickHouse/ClickHouse/pull/26365) ([Raúl Marín](https://github.com/Algunenano)).
* 降低短查询的延迟，这类查询需要从包含大量列的表中读取数据。[#26371](https://github.com/ClickHouse/ClickHouse/pull/26371) ([Anton Popov](https://github.com/CurtizJ)).
* 在并发读取相同文件时共享文件描述符。在 Linux 上性能差异并不明显，但在典型服务器上，打开的文件数量会显著减少 (10 到 100 倍) ，从而让运维更容易。参见 [#26214](https://github.com/ClickHouse/ClickHouse/issues/26214)。[#26768](https://github.com/ClickHouse/ClickHouse/pull/26768) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 对与日期时间相关的比较进行特化，以获得更好的性能。这修复了 [#27083](https://github.com/ClickHouse/ClickHouse/issues/27083)。[#27122](https://github.com/ClickHouse/ClickHouse/pull/27122) ([Amos Bird](https://github.com/amosbird)).
* 通过减少 `clock_gettime` 系统调用次数，在 `max_execution_time=0` 时提升快速查询的性能。[#27325](https://github.com/ClickHouse/ClickHouse/pull/27325) ([filimonov](https://github.com/filimonov)).
* 减少 `clock_gettime` 系统调用次数，这可能会提升某些类型快速查询的性能。[#27492](https://github.com/ClickHouse/ClickHouse/pull/27492) ([filimonov](https://github.com/filimonov)).

<div id="improvement">
  #### 改进

* 在 Postgres engine 中，将 timestamp 和 timestamptz data types 转换为 DateTime64。[#26234](https://github.com/ClickHouse/ClickHouse/pull/26234) ([jasine](https://github.com/jasine)) 。
* 检查 keys 中的非确定性函数，包括 `now()`、`today()` 这样的常量表达式。这关闭了 [#25875](https://github.com/ClickHouse/ClickHouse/issues/25875)。这关闭了 [#11333](https://github.com/ClickHouse/ClickHouse/issues/11333)。[#26235](https://github.com/ClickHouse/ClickHouse/pull/26235) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。

* 新增 `output_format_avro_string_column_pattern` 设置，用于将指定的 String columns 以 string 而非默认 bytes 的形式写入 Avro。实现了 [#22414](https://github.com/ClickHouse/ClickHouse/issues/22414)。[#26245](https://github.com/ClickHouse/ClickHouse/pull/26245) ([Ilya Golshtein](https://github.com/ilejn)) 。
