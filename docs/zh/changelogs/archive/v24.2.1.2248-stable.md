<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 在嵌套类型中校验可疑/Experimental 类型。此前，我们不会在 Array/Tuple/Map 这类嵌套类型中校验此类类型 (JSON 除外) 。 [#59385](https://github.com/ClickHouse/ClickHouse/pull/59385) ([Kruglov Pavel](https://github.com/Avogar)).
* 排序子句 `ORDER BY ALL` (于 v23.12 引入) 已由 `ORDER BY *` 取代。此前的语法对于包含名为 `all` 的列的表来说过于容易出错。 [#59450](https://github.com/ClickHouse/ClickHouse/pull/59450) ([Robert Schulze](https://github.com/rschu1ze)).
* 将设置 `extract_kvp_max_pairs_per_row` 重命名为 `extract_key_value_pairs_max_pairs_per_row`。该问题 (设置名称中存在不必要的缩写) 是在 https://github.com/ClickHouse/ClickHouse/pull/43606 中引入的。修正了该设置的文档。 [#59683](https://github.com/ClickHouse/ClickHouse/pull/59683) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 将设置 extract&#95;kvp&#95;max&#95;pairs&#95;per&#95;row 重命名为 extract&#95;key&#95;value&#95;pairs&#95;max&#95;pairs&#95;per&#95;row。该问题 (设置名称中存在不必要的缩写) 是在 https://github.com/ClickHouse/ClickHouse/pull/43606 中引入的。修正了该设置的文档。 [#59960](https://github.com/ClickHouse/ClickHouse/pull/59960) ([jsc0218](https://github.com/jsc0218)).
* 为线程数量和块大小添加合理性检查。 [#60138](https://github.com/ClickHouse/ClickHouse/pull/60138) ([Raúl Marín](https://github.com/Algunenano)).



<div id="new-feature">
  #### 新特性
</div>

* 在 QUOTA 中新增了最大连续登录失败次数限制。[#54737](https://github.com/ClickHouse/ClickHouse/pull/54737) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* 新增语法，允许在 View/Materialized View 中指定 definer 用户。这样一来，无需对底层表进行显式授权，也能通过视图执行查询/插入。[#54901](https://github.com/ClickHouse/ClickHouse/pull/54901) ([pufit](https://github.com/pufit)).
* AzureBlobStorage 现已支持 Backup &amp; Restore，解决了 [#50747](https://github.com/ClickHouse/ClickHouse/issues/50747)。[#56988](https://github.com/ClickHouse/ClickHouse/pull/56988) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 实现了将不同类型的 MergeTree 表自动转换为 Replicated 引擎。请在表的数据目录 (`/clickhouse/store/xxx/xxxyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy/`) 中创建空的 `convert_to_replicated` 文件，该表将在下次服务器启动时自动转换。[#57798](https://github.com/ClickHouse/ClickHouse/pull/57798) ([Kirill](https://github.com/kirillgarbar)).
* 新增表函数 `mergeTreeIndex`。它表示 `MergeTree` 表的索引和标记文件内容，可用于查看内部信息。语法：`mergeTreeIndex(database, table, [with_marks = true])`，其中 `database.table` 是使用 `MergeTree` 引擎的现有表。[#58140](https://github.com/ClickHouse/ClickHouse/pull/58140) ([Anton Popov](https://github.com/CurtizJ)).
* 新增函数 `seriesOutliersTukey`，使用 Tukey&#39;s fences 算法检测序列数据中的离群点。[#58632](https://github.com/ClickHouse/ClickHouse/pull/58632) ([Bhavna Jindal](https://github.com/bhavnajindal)).
* 现在用户可以在查询中直接使用 `format_schema_rows_template` 指定模板字符串，作为 `format_template_row` 的替代方案。关闭 [#31363](https://github.com/ClickHouse/ClickHouse/issues/31363)。[#59088](https://github.com/ClickHouse/ClickHouse/pull/59088) ([Shaun Struwig](https://github.com/Blargian)).
* 如果在 `file/s3/hdfs/url/azureBlobStorage` 引擎中进行 schema 推断时文件格式未知，现在会尝试自动检测文件格式。关闭 [#50576](https://github.com/ClickHouse/ClickHouse/issues/50576)。[#59092](https://github.com/ClickHouse/ClickHouse/pull/59092) ([Kruglov Pavel](https://github.com/Avogar)).
* 新增函数 variantType，可为每一行返回一个表示 Variant 类型名称的 Enum。[#59398](https://github.com/ClickHouse/ClickHouse/pull/59398) ([Kruglov Pavel](https://github.com/Avogar)).
* 新增查询 `ALTER TABLE table FORGET PARTITION partition`，用于删除与空分区相关的 ZooKeeper 节点。[#59507](https://github.com/ClickHouse/ClickHouse/pull/59507) ([Sergei Trifonov](https://github.com/serxa)).
* NATS 表引擎现已支持 JWT 凭证文件。[#59543](https://github.com/ClickHouse/ClickHouse/pull/59543) ([Nickolaj Jepsen](https://github.com/nickolaj-jepsen)).
* 新增聚合函数 `groupArrayIntersect`。跟进：[#49862](https://github.com/ClickHouse/ClickHouse/issues/49862)。[#59598](https://github.com/ClickHouse/ClickHouse/pull/59598) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 实现了 system.dns&#95;cache 表，可用于调试 DNS 问题。[#59856](https://github.com/ClickHouse/ClickHouse/pull/59856) ([Kirill Nikiforov](https://github.com/allmazz)).
* 编解码器 `LZ4HC` 现支持新的 2 级，相比此前的最低 3 级速度更快，但压缩率会更低。在之前的版本中，`LZ4HC(2)` 及更低级别与 `LZ4HC(3)` 等同。作者：[Cyan4973](https://github.com/Cyan4973)。[#60090](https://github.com/ClickHouse/ClickHouse/pull/60090) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 新增了 system.dns&#95;cache 表，可用于调试 DNS 问题。新增服务端设置 dns&#95;cache&#95;max&#95;size。[#60257](https://github.com/ClickHouse/ClickHouse/pull/60257) ([Kirill Nikiforov](https://github.com/allmazz)) 。
* `merge` 表函数现支持单参数版本，即 `merge(['db_name', ] 'tables_regexp')`。[#60372](https://github.com/ClickHouse/ClickHouse/pull/60372) ([豪肥肥](https://github.com/HowePa)) 。
* 新增语法，允许在 View/Materialized View 中指定 definer user。这样一来，无需对底层表进行显式授权，也可以通过视图执行 SELECT/INSERT 操作。[#60439](https://github.com/ClickHouse/ClickHouse/pull/60439) ([pufit](https://github.com/pufit)) 。



<div id="performance-improvement">
  #### 性能提升
</div>

* 移除 `SELECT` 部分中对 `GROUP BY` 键使用的 min/max/any/anyLast 聚合器。[#52230](https://github.com/ClickHouse/ClickHouse/pull/52230) ([JackyWoo](https://github.com/JackyWoo)).
* 在向量搜索中使用向量化距离函数。[#58866](https://github.com/ClickHouse/ClickHouse/pull/58866) ([Robert Schulze](https://github.com/rschu1ze)).
* 继续优化结果类型为 float*/decimal*/int* 时 if 函数的分支未命中问题，是对 https://github.com/ClickHouse/ClickHouse/pull/57885 的后续优化。[#59148](https://github.com/ClickHouse/ClickHouse/pull/59148) ([李扬](https://github.com/taiyang-li)).
* 优化输入类型为 Map 时的 if 函数，速度提升约 10 倍。[#59413](https://github.com/ClickHouse/ClickHouse/pull/59413) ([李扬](https://github.com/taiyang-li)).
* 通过实现严格别名提升 Int8 类型的性能。[#59485](https://github.com/ClickHouse/ClickHouse/pull/59485) ([Raúl Marín](https://github.com/Algunenano)).
* 通过减少分支未命中，有条件地优化 bigint 和大 Decimal 类型上 sum/avg 的性能。[#59504](https://github.com/ClickHouse/ClickHouse/pull/59504) ([李扬](https://github.com/taiyang-li)).
* 提升存在活跃变更的 `SELECT` 查询性能。[#59531](https://github.com/ClickHouse/ClickHouse/pull/59531) ([Azat Khuzhin](https://github.com/azat)).
* 使用 AVX2 优化 `isNotNull` 函数。[#59621](https://github.com/ClickHouse/ClickHouse/pull/59621) ([李扬](https://github.com/taiyang-li)).
* 复用 `FunctionFactory::instance().get("isNotNull", context)` 和 `FunctionFactory::instance().get("assumeNotNull", context)` 的结果，确保在 `FunctionCoalesce` 的生命周期内只调用一次。[#59627](https://github.com/ClickHouse/ClickHouse/pull/59627) ([李扬](https://github.com/taiyang-li)).
* 提升已排序或接近已排序数据上的 ASOF JOIN 性能。[#59731](https://github.com/ClickHouse/ClickHouse/pull/59731) ([Maksim Kita](https://github.com/kitaisreal)).
* 主键将占用更少内存。[#60049](https://github.com/ClickHouse/ClickHouse/pull/60049) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 改进主键及某些其他操作的内存使用情况。[#60050](https://github.com/ClickHouse/ClickHouse/pull/60050) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 表的主键将在首次访问时延迟加载到内存中。这由新的 MergeTree 设置 `primary_key_lazy_load` 控制，且默认开启。这有几个优点：- 未使用的表不会被加载；- 如果内存不足，将在首次使用时而不是服务器启动时抛出异常。这也有几个缺点：- 加载主键的延迟会在第一次查询时产生，而不是在接受连接前；理论上这可能会引发惊群问题。此更改关闭了 [#11188](https://github.com/ClickHouse/ClickHouse/issues/11188)。[#60093](https://github.com/ClickHouse/ClickHouse/pull/60093) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 向量化函数 `dotProduct`，对向量搜索很有用。[#60202](https://github.com/ClickHouse/ClickHouse/pull/60202) ([Robert Schulze](https://github.com/rschu1ze)).
* 如图 1 所示，将 &quot;&amp;&amp;&quot; 替换为 &quot;&amp;&quot; 可以生成 SIMD 代码。![image](https://github.com/ClickHouse/ClickHouse/assets/26588299/a5a72ac4-6dc6-4d52-835a-4f512e55f0b9) 图 1. 由 &#39;&amp;&amp;&#39; (左) 和 &#39;&amp;&#39; (右) 编译生成的代码。[#60498](https://github.com/ClickHouse/ClickHouse/pull/60498) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).



<div id="improvement">
  #### 改进
</div>

* 新增对 parameterized view 与 analyzer 的支持，使其不会分析 create parameterized view。同时重构了现有的 parameterized view 逻辑，以避免分析 create parameterized view。[#54211](https://github.com/ClickHouse/ClickHouse/pull/54211) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)) 。
* 即使 projection 损坏，也不再将数据分区片段视为损坏。关闭 [#56593](https://github.com/ClickHouse/ClickHouse/issues/56593)。[#56864](https://github.com/ClickHouse/ClickHouse/pull/56864) ([Kseniia Sumarokova](https://github.com/kssenii)) 。
* 为 `dictGetOrDefault` 函数增加短路能力。关闭 [#52098](https://github.com/ClickHouse/ClickHouse/issues/52098)。[#57767](https://github.com/ClickHouse/ClickHouse/pull/57767) ([jsc0218](https://github.com/jsc0218)) 。
* 现在，在带有 `DEFAULT` 或 `MATERIALIZED` expression 的列上运行 `ALTER COLUMN MATERIALIZE` 会写入正确的值：对于现有 parts 中的默认值，会写入默认值；对于现有 parts 中的非默认值，会写入非默认值。此前，所有现有 parts 都会写入默认值。[#58023](https://github.com/ClickHouse/ClickHouse/pull/58023) ([Duc Canh Le](https://github.com/canhld94)) 。
* 启用了 backoff 逻辑 (例如指数退避) 。这将有助于降低 CPU usage、memory usage 和日志文件大小。[#58036](https://github.com/ClickHouse/ClickHouse/pull/58036) ([MikhailBurdukov](https://github.com/MikhailBurdukov)) 。
* 改进了 InitialQuery 的计数。[#58195](https://github.com/ClickHouse/ClickHouse/pull/58195) ([Unalian](https://github.com/Unalian)) 。
* 支持负数位置参数。关闭 [#57736](https://github.com/ClickHouse/ClickHouse/issues/57736)。[#58292](https://github.com/ClickHouse/ClickHouse/pull/58292) ([flynn](https://github.com/ucasfl)) 。
* 实现了异步插入超时的自动调整。引入了以下 settings：async&#95;insert&#95;poll&#95;timeout&#95;ms、async&#95;insert&#95;use&#95;adaptive&#95;busy&#95;timeout、async&#95;insert&#95;busy&#95;timeout&#95;min&#95;ms、async&#95;insert&#95;busy&#95;timeout&#95;max&#95;ms、async&#95;insert&#95;busy&#95;timeout&#95;increase&#95;rate、async&#95;insert&#95;busy&#95;timeout&#95;decrease&#95;rate。[#58486](https://github.com/ClickHouse/ClickHouse/pull/58486) ([Julia Kartseva](https://github.com/jkartseva)) 。
* 允许在 `storage_configuration` 中定义 `volume_priority`。[#58533](https://github.com/ClickHouse/ClickHouse/pull/58533) ([Andrey Zvonov](https://github.com/zvonand)) 。
* 在 T64 codec 中新增对 Date32 type 的支持。[#58738](https://github.com/ClickHouse/ClickHouse/pull/58738) ([Hongbin Ma (Mahone)](https://github.com/binmahone)) 。
* 支持 `LEFT JOIN`、`ALL INNER JOIN` 以及适用于并行副本的简单 subqueries (仅在使用 analyzer 时) 。新增 setting `parallel_replicas_prefer_local_join`，用于在本地 `JOIN` 执行 (默认) 和 `GLOBAL JOIN` 之间进行选择。`cluster_for_parallel_replicas` 中的所有表都必须存在于每个副本上。新增 settings `min_external_table_block_size_rows` 和 `min_external_table_block_size_bytes`，用于将发送到临时表的小块压缩合并 (仅在使用 analyzer 时) 。[#58916](https://github.com/ClickHouse/ClickHouse/pull/58916) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 允许在包含多个项的 types 中使用尾随逗号。[#59119](https://github.com/ClickHouse/ClickHouse/pull/59119) ([Aleksandr Musorin](https://github.com/AVMusorin)) 。
* 允许 `S3Queue` 表引擎进行并行和分布式处理。对于分布式处理，可使用设置 `s3queue_total_shards_num` (默认值为 `1`) 。此前，设置 `s3queue_processing_threads_num` 不允许用于 ordered 模式，现在已允许。警告：在 ordered 模式下，设置 `s3queue_processing_threads_num` (每个分片的处理线程数) 和 `s3queue_total_shards_num` 会改变元数据的存储方式 (使 `max_processed_file` 节点的数量等于 `s3queue_processing_threads_num * s3queue_total_shards_num`) ，因此它们必须在所有分片上保持一致，并且在至少创建一个分片后不能再更改。[#59167](https://github.com/ClickHouse/ClickHouse/pull/59167) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 允许在 `recoverLostReplica` 期间于 `DatabaseReplicated` 中并发表创建。[#59277](https://github.com/ClickHouse/ClickHouse/pull/59277) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 现在可以在服务器配置文件中为 Distributed 表引擎指定设置 (类似于 MergeTree 的设置) ，例如 `<distributed> <flush_on_detach>false</flush_on_detach> </distributed>`。[#59291](https://github.com/ClickHouse/ClickHouse/pull/59291) ([Azat Khuzhin](https://github.com/azat)).
* 使用 MergeTree 作为默认表引擎。这显著提升了易用性，也更接近 ClickHouse Cloud。[#59316](https://github.com/ClickHouse/ClickHouse/pull/59316) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 读取 `system.zookeeper` 时会重试断开连接和过期会话。这在从 `system.zookeeper` 表读取大量行时特别有帮助，尤其是在存在故障注入导致的断连时。[#59388](https://github.com/ClickHouse/ClickHouse/pull/59388) ([Alexander Gololobov](https://github.com/davenger)).
* 当 `input_format_values_interpret_expressions=0` 时，不再将带前导零的数字解释为八进制数。[#59403](https://github.com/ClickHouse/ClickHouse/pull/59403) ([Joanna Hulboj](https://github.com/jh0x)).
* 在启动时以及配置文件发生更改时，ClickHouse 会更新其总内存跟踪器的硬内存限制。这些限制基于各种服务器设置和 cgroups 限制 (在 Linux 上) 计算得出。此前，`/sys/fs/cgroup/memory.max` (用于 cgroups v2) 是硬编码的。因此，为嵌套组 (层级) 配置的 cgroup v2 内存限制 (例如 `/sys/fs/cgroup/my/nested/group/memory.max`) 会被忽略。该问题现已修复。v1 内存限制的行为保持不变。[#59435](https://github.com/ClickHouse/ClickHouse/pull/59435) ([Robert Schulze](https://github.com/rschu1ze)).
* 新增了 profile events，用于观测 `INSERT` 期间计算 PK/projections/次级索引所花费的时间。[#59436](https://github.com/ClickHouse/ClickHouse/pull/59436) ([Nikita Taranov](https://github.com/nickitat)).
* 允许在创建时通过设置 `s3queue_last_processed_path` 为 ordered 模式的 S3Queue 定义起始点。[#59446](https://github.com/ClickHouse/ClickHouse/pull/59446) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Keeper 改进：仅在内存中缓存一定数量的日志，该数量由 `latest_logs_cache_size_threshold` 和 `commit_logs_cache_size_threshold` 控制。[#59460](https://github.com/ClickHouse/ClickHouse/pull/59460) ([Antonio Andelic](https://github.com/antonio2368)).
* 在 `clickhouse-local` 中，系统表的注释现在也可在 `system.tables` 中获取。[#59493](https://github.com/ClickHouse/ClickHouse/pull/59493) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 默认情况下不再推断使用指数表示法的浮点数。新增设置 `input_format_try_infer_exponent_floats`，可恢复之前的行为 (默认禁用) 。关闭 [#59476](https://github.com/ClickHouse/ClickHouse/issues/59476)。[#59500](https://github.com/ClickHouse/ClickHouse/pull/59500) ([Kruglov Pavel](https://github.com/Avogar)).
* 允许将 alter 操作用括号括起来。是否输出括号可通过 `format_alter_operations_with_parentheses` config 控制。默认情况下，格式化后的查询会输出括号，因为我们会在某些地方将格式化后的 alter 操作存储为 metadata (例如：变更) 。新语法让某些以 alter 操作列表结尾的查询更清晰。例如，`ALTER TABLE x MODIFY TTL date GROUP BY a, b, DROP COLUMN c` 在旧语法下无法被正确解析。而在新语法中，查询 `ALTER TABLE x (MODIFY TTL date GROUP BY a, b), (DROP COLUMN c)` 的含义就很明确。旧版本无法读取新语法，因此如果在同一个 cluster 中混用新旧版本的 ClickHouse，使用新语法可能会引发问题。 [#59532](https://github.com/ClickHouse/ClickHouse/pull/59532) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 此前 `async_insert_max_data_size` 的默认值为 1 MB，事实证明这个值太小。新的默认值将调整为 10 MiB。 [#59536](https://github.com/ClickHouse/ClickHouse/pull/59536) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 以前，整个结果会先在内存中累积，再作为一个大 chunk 返回。此次变更有助于在从 `system.zookeeper` 读取大量行时降低内存占用，支持显示中间 Progress (截至当前已读取多少行) ，并在结果集较大时避免触发连接超时。 [#59545](https://github.com/ClickHouse/ClickHouse/pull/59545) ([Alexander Gololobov](https://github.com/davenger)).
* 现在 dashboard 可以同时识别 URL&#39;s #hash 的 compressed 和 uncompressed 状态 (backward compatibility) 。这是 [#59124](https://github.com/ClickHouse/ClickHouse/issues/59124) 的后续。 [#59548](https://github.com/ClickHouse/ClickHouse/pull/59548) ([Amos Bird](https://github.com/amosbird)).
* 将 Intel QPL (用于 codec `DEFLATE_QPL`) 从 v1.3.1 升级到 v1.4.0。同时还修复了 polling timeout 机制中的一个 bug，因为我们观察到在某些情况下 timeout 不能正常工作；一旦发生 timeout，IAA 和 CPU 可能会并发处理 buffer。目前，我们最好确保 IAA codec status 不是 QPL&#95;STS&#95;BEING&#95;PROCESSED，再回退到 SW codec。 [#59551](https://github.com/ClickHouse/ClickHouse/pull/59551) ([jasperzhu](https://github.com/jinjunzh)).
* Keeper 改进：进一步减小 data node 的大小。 [#59592](https://github.com/ClickHouse/ClickHouse/pull/59592) ([Antonio Andelic](https://github.com/antonio2368)).
* 不再在 ClickHouse Cloud 中显示有关 server 版本的警告，因为 ClickHouse Cloud 会自动处理无缝升级。 [#59657](https://github.com/ClickHouse/ClickHouse/pull/59657) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 自解压后，临时 binary 将移动而不是复制。 [#59661](https://github.com/ClickHouse/ClickHouse/pull/59661) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
