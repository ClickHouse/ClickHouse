  ### ClickHouse 发布版本 v23.1.1.3077-稳定版本 (dcaac477025) FIXME，对比 v22.12.1.1752-稳定版本 (688e488e930)

<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 移除 `SYSTEM RESTART DISK` 查询。[#44647](https://github.com/ClickHouse/ClickHouse/pull/44647) ([alesapin](https://github.com/alesapin)) 。
* 禁止对非 Float32 或 Float64 类型的列使用 Gorilla 压缩。[#45252](https://github.com/ClickHouse/ClickHouse/pull/45252) ([Robert Schulze](https://github.com/rschu1ze)) 。
* 移除 HASHED/SPARSE&#95;HASHED 字典的 PREALLOCATE。[#45388](https://github.com/ClickHouse/ClickHouse/pull/45388) ([Azat Khuzhin](https://github.com/azat)) 。
* 对于使用已弃用语法创建的 `*MergeTree` 表，并行 quorum 插入可能无法正常工作。因此，已完全禁用这类表的并行 quorum 插入支持。这不会影响使用新语法创建的表。[#45430](https://github.com/ClickHouse/ClickHouse/pull/45430) ([Alexander Tokmakov](https://github.com/tavplubix)) 。

<div id="new-feature">
  #### 新特性

* 支持以 Joda datetime 风格格式化 datetime。参见 [https://joda-time.sourceforge.net/apidocs/org/joda/time/format/DateTimeFormat.html](https://joda-time.sourceforge.net/apidocs/org/joda/time/format/DateTimeFormat.html)。[#43818](https://github.com/ClickHouse/ClickHouse/pull/43818) ([李扬](https://github.com/taiyang-li)) 。

* 为 formatDateTime 实现了小数秒格式说明符 (`%f`) 。[#44060](https://github.com/ClickHouse/ClickHouse/pull/44060) ([ltrk2](https://github.com/ltrk2)) 。

* * 在 AsyncMetrics 中新增与 cgroup 相关的总内存和已用内存指标 ([https://github.com/ClickHouse/ClickHouse/issues/37983](https://github.com/ClickHouse/ClickHouse/issues/37983)). [#45301](https://github.com/ClickHouse/ClickHouse/pull/45301) ([sichenzhao](https://github.com/sichenzhao)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 在 HashedDictionary 中新增了分片支持，以支持并行加载 (性能几乎可随分片数量线性扩展) 。[#40003](https://github.com/ClickHouse/ClickHouse/pull/40003) ([Azat Khuzhin](https://github.com/azat)).
* `MergeTree` 表启动时不再加载非活跃 parts。[#42181](https://github.com/ClickHouse/ClickHouse/pull/42181) ([Anton Popov](https://github.com/CurtizJ)).
* * 提升查询解析速度。 [#42284](https://github.com/ClickHouse/ClickHouse/pull/42284) ([Raúl Marín](https://github.com/Algunenano)) 。
* 如果 `expr` 是 `LowCardinality` 列，则始终将 OR 条件链 `expr = x1 OR ... OR expr = xN` 替换为 `expr IN (x1, ..., xN)`。在这种情况下，设置 `optimize_min_equality_disjunction_chain_length` 会被忽略。[#42889](https://github.com/ClickHouse/ClickHouse/pull/42889) ([Guo Wangyang](https://github.com/guowangy)).
* > 原始更新日志 在最初的实现中，`ThreadGroupStatus:: finished&#95;threads&#95;counters&#95;memory` 的内存是通过将其移动到一个临时 `std::vector` 中来释放的，该临时对象很快就会过期并被析构。这种方法虽然可行，但不够直观。为提升代码可读性，此次提交改为先将 vector 的大小调整为 0，再相应收缩其容量，从而释放其中的内存。[#43586](https://github.com/ClickHouse/ClickHouse/pull/43586) ([Zhiguo Zhou](https://github.com/ZhiguoZh)) 。
* 作为 [#42214](https://github.com/ClickHouse/ClickHouse/issues/42214) 的后续工作，此 PR 尝试通过实现自动向量化来优化按列进行的三元逻辑求值。在这个[微基准测试](https://github.com/ZhiguoZh/ClickHouse/blob/20221123-ternary-logic-opt-example/src/Functions/examples/associative_applier_perf.cpp)的性能测试中，我们观察到在 ICX 设备 (Intel Xeon Platinum 8380 CPU) 上，**性能提升**峰值可达 **21x**。[#43669](https://github.com/ClickHouse/ClickHouse/pull/43669) ([Zhiguo Zhou](https://github.com/ZhiguoZh))。
* 改进了从 `S3` 存储和表函数 `s3` 读取大量小文件时的延迟。现在，从 `S3` 存储读取时，设置项 `remote_filesystem_read_method` 和 `remote_filesystem_read_prefetch` 也会生效。[#43726](https://github.com/ClickHouse/ClickHouse/pull/43726) ([Anton Popov](https://github.com/CurtizJ))。
* * 如果可能，应避免在 system.tables 中加读锁。[#43840](https://github.com/ClickHouse/ClickHouse/pull/43840) ([Raúl Marín](https://github.com/Algunenano)) 。
* 在 ICX 设备 (Intel Xeon Platinum 8380 CPU，80 核，160 线程) 上进行的 SSB (Star Schema Benchmark) 性能实验表明，此项变更可将 ThreadPoolImpl::mutex 的锁竞争有效降低 **75%**，从而提高 CPU 利用率，并将整体性能提升 **2.4%**。[#44308](https://github.com/ClickHouse/ClickHouse/pull/44308) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 现在，只有在缓存的 HT 足够大时才会应用该优化 (阈值通过经验确定并硬编码) 。[#44455](https://github.com/ClickHouse/ClickHouse/pull/44455) ([Nikita Taranov](https://github.com/nickitat)).
* ... 目前即使我们只想读取 struct 中的一个字段，也会加载整个 struct 字段。[#44484](https://github.com/ClickHouse/ClickHouse/pull/44484) ([lgbo](https://github.com/lgbo-ustc)).
* 对来自远程文件系统的异步读取做了小幅性能优化。[#44868](https://github.com/ClickHouse/ClickHouse/pull/44868) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 已切换到更快的共享 (RW) mutex 实现。在包含大量线程同步的查询中，或在竞争严重的数据结构上，性能可能会有所提升。[#45007](https://github.com/ClickHouse/ClickHouse/pull/45007) ([Sergei Trifonov](https://github.com/serxa)).
* 为以下情况添加了快速路径：- col like &#39;%%&#39; - col like &#39;%&#39; - col not like &#39;%&#39; - col not like &#39;%&#39; - match(col, &#39;.*&#39;)。[#45244](https://github.com/ClickHouse/ClickHouse/pull/45244) ([李扬](https://github.com/taiyang-li)).
* 待办。[#45289](https://github.com/ClickHouse/ClickHouse/pull/45289) ([Nikita Taranov](https://github.com/nickitat)).

<div id="improvement">
  #### 改进
</div>

* 重构并改进流式引擎 Kafka/RabbitMQ/NATS，增加对所有 format 的支持，并对 format 进行了一些重构：- 修复了在带有 suffixes/prefixes 的行式 format 中生成消息的问题。现在每条消息都会连同所有 delimiters 一起被完整格式化，并且可以使用 input format 重新解析。- 支持 Native、Parquet、ORC 等块式 format。每个块都会被格式化为一条独立消息。一条消息中的行数取决于块大小，因此可以通过设置 `max_block_size` 来控制。- 新增引擎设置 `kafka_max_rows_per_message/rabbitmq_max_rows_per_message/nats_max_rows_per_message`。它们用于控制行式 format 中每条消息格式化的行数。默认值：1。- 修复 NATS 表引擎中的高内存占用问题。- 支持在 NATS producer 中使用任意 binary data (此前仅支持末尾包含 \0 的字符串) - 在文档中补充缺失的 Kafka/RabbitMQ/NATS 引擎设置。- 重构 Kafka/RabbitMQ/NATS 中的生产与消费逻辑，将其与 WriteBuffers/ReadBuffers 语义分离。- 重构 output formats：移除 Kafka/RabbitMQ/NATS 中此前对每一行使用的 callbacks (现在这里不再使用 callbacks) ，允许直接使用 IRowOutputFormat，明确行尾和行间 delimiters，并支持重置 output format 以重新开始 formatting - 在 formatRow 函数中添加正确实现 (这是 format 重构带来的额外收益) 。[#42777](https://github.com/ClickHouse/ClickHouse/pull/42777) ([Kruglov Pavel](https://github.com/Avogar)).
* 在新基础设施中支持 `optimize_or_like_chain`。属于 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) 的一部分。[#42797](https://github.com/ClickHouse/ClickHouse/pull/42797) ([Dmitry Novik](https://github.com/novikd)).
* 改进 Asterisk 和 ColumnMatcher 解析器。属于 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) 的一部分。[#42884](https://github.com/ClickHouse/ClickHouse/pull/42884) ([Nikolay Degterinsky](https://github.com/evillique)).
* 基于 QueryTree 实现 `optimize_redundant_functions_in_order_by`。属于 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) 的一部分。[#42970](https://github.com/ClickHouse/ClickHouse/pull/42970) ([Dmitry Novik](https://github.com/novikd)).
* 在新的 analyzer 架构中支持 `optimize_group_by_function_keys`。另外，新增了对 GROUPING SETS keys 优化的支持。属于 [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648) 的一部分。[#43261](https://github.com/ClickHouse/ClickHouse/pull/43261) ([Dmitry Novik](https://github.com/novikd)).
* 改进在 CustomSeparated/Template format 中读取 CSV field 的能力。关闭 [#42352](https://github.com/ClickHouse/ClickHouse/issues/42352) 关闭 [#39620](https://github.com/ClickHouse/ClickHouse/issues/39620)。[#43332](https://github.com/ClickHouse/ClickHouse/pull/43332) ([Kruglov Pavel](https://github.com/Avogar)).
* 支持在 CapnProto format 中将 `Nested` 表作为 `List` 的 `Struct` 进行读写。将 `Decimal32/64` 读写为 `Int32/64`。关闭 [#43319](https://github.com/ClickHouse/ClickHouse/issues/43319)。[#43379](https://github.com/ClickHouse/ClickHouse/pull/43379) ([Kruglov Pavel](https://github.com/Avogar)).
* * 统一查询耗时的测量方式。[#43455](https://github.com/ClickHouse/ClickHouse/pull/43455) ([Raúl Marín](https://github.com/Algunenano)) 。
* 支持标量子查询缓存。实现：* 向 Context 中添加了一个映射，保存节点 (不含别名) 的哈希值及其求值结果。测试：* 在 02174&#95;cte&#95;scalar&#95;cache.sql 中使用新分析器添加了一个测试用例。 [#43640](https://github.com/ClickHouse/ClickHouse/pull/43640) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 改进了在 select 查询包含虚拟列时，file/hdfs/s3 表函数自动使用插入表结构的能力，修复了可能出现的 `Block structure mismatch` 或 `number of columns mismatch` 错误。 [#43695](https://github.com/ClickHouse/ClickHouse/pull/43695) ([Kruglov Pavel](https://github.com/Avogar)).
* 为 range() 增加了对有符号参数的支持。修复了 [#43333](https://github.com/ClickHouse/ClickHouse/issues/43333)。 [#43733](https://github.com/ClickHouse/ClickHouse/pull/43733) ([sanyu](https://github.com/wineternity)).
