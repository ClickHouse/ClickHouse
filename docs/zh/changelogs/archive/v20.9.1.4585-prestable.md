<div id="clickhouse-release-v20914585-prestable-fixme-as-compared-to-v20814513-prestable">
  ### ClickHouse 发布版本 v20.9.1.4585-prestable FIXME (与 v20.8.1.4513-prestable 相比)
</div>

<div id="backward-incompatible-change">
  #### 向后不兼容的更改
</div>

* 新增了 MergeTree 设置 (`max_replicated_merges_with_ttl_in_queue` 和 `max_number_of_merges_with_ttl_in_pool`) ，用于控制后台线程池和复制队列中带有 TTL 的合并数量。只有在使用删除 TTL 时，此更改才会破坏与旧版本的兼容性；否则，复制仍将保持兼容。你可以通过一次性更新所有分片的副本，或者在所有副本完成更新之前执行 `SYSTEM STOP TTL MERGES`，来避免兼容性问题。如果复制队列中出现不兼容的条目，首先执行 `SYSTEM STOP TTL MERGES`，然后对被分配了不兼容 TTL 合并任务的分区执行 `ALTER TABLE ... DETACH PARTITION ...`。随后在单个副本上将其重新附加回来。[#14490](https://github.com/ClickHouse/ClickHouse/pull/14490) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### 新特性
</div>

* 新增表函数 `view`，可将子查询转换为表对象。这有助于在不同场景中传递查询。例如，可用于 remote/cluster 表函数。[#12567](https://github.com/ClickHouse/ClickHouse/pull/12567) ([Amos Bird](https://github.com/amosbird)).
* 现在可以编写 `select * apply(length) apply(max) from wide_string_table` 来找出所有 String 列的最大长度。同时还提供了以下两种变体：[#14233](https://github.com/ClickHouse/ClickHouse/pull/14233) ([Amos Bird](https://github.com/amosbird)).
* 在 `system.query_log` 和 `system.query_thread_log` 表中新增了 `query_start_time_microseconds` 字段。[#14252](https://github.com/ClickHouse/ClickHouse/pull/14252) ([Bharat Nallan](https://github.com/bharatnc)).
* 新增聚合函数 RankCorrelationSpearman，可直接计算秩相关系数。延续自 [#11769](https://github.com/ClickHouse/ClickHouse/issues/11769)。[#14411](https://github.com/ClickHouse/ClickHouse/pull/14411) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 新增了通过查询工具生成数据库的功能。延续自 [#10973](https://github.com/ClickHouse/ClickHouse/issues/10973)。[#14442](https://github.com/ClickHouse/ClickHouse/pull/14442) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 在启用 optimize&#95;skip&#95;unused&#95;shards 和 optimize&#95;distributed&#95;group&#95;by&#95;sharding&#95;key 时，优化对使用 GROUP BY sharding&#95;key 的 Distributed 表执行的 LIMIT/LIMIT BY/ORDER BY 查询。[#10373](https://github.com/ClickHouse/ClickHouse/pull/10373) ([Azat Khuzhin](https://github.com/azat)) 。

<div id="improvement">
  #### 改进
</div>

* 改进了 StorageRabbitMQ：新增了对连接和通道故障的处理、正确的提交处理、对 insert 失败的处理、改进了 exchange，支持队列持久化和队列恢复，并新增了队列设置。修复了测试。 [#12761](https://github.com/ClickHouse/ClickHouse/pull/12761) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 新增了 Redis `requirepass` 授权。 [#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)).
* 为 DateTime 类型增加了 `precision` 参数。 [#13761](https://github.com/ClickHouse/ClickHouse/pull/13761) ([Winter Zhang](https://github.com/zhang2014)).
* 通过为每个消费者提供独立线程，提升了 Kafka 引擎的性能。并为流式引擎 (如 Kafka) 提供了独立的线程池。 [#13939](https://github.com/ClickHouse/ClickHouse/pull/13939) ([fastio](https://github.com/fastio)).
* 为 `system.part_log` 中的分片增加了默认压缩 codec，名称为 `default_compression_codec`。 [#14116](https://github.com/ClickHouse/ClickHouse/pull/14116) ([alesapin](https://github.com/alesapin)).
* 用来自 [https://github.com/cerevra/int](https://github.com/cerevra/int) 的实现替换了 boost multiprecision 中的宽整数实现。 [#14229](https://github.com/ClickHouse/ClickHouse/pull/14229) ([Artem Zuikov](https://github.com/4ertus2)).
* 在 MaterializeMySQL 中将主键隐式转换为非 NULL (与 MySQL 相同) 。修复了 [#14114](https://github.com/ClickHouse/ClickHouse/issues/14114)。 [#14397](https://github.com/ClickHouse/ClickHouse/pull/14397) ([Winter Zhang](https://github.com/zhang2014)).
* 按照 [#11384](https://github.com/ClickHouse/ClickHouse/issues/11384) 中的提议，新增了设置 `system_events_show_zero_values`。 [#14404](https://github.com/ClickHouse/ClickHouse/pull/14404) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* 现在混淆器已支持 UUID 类型，这是按照 [#13163](https://github.com/ClickHouse/ClickHouse/issues/13163) 中的提议实现的。 [#14409](https://github.com/ClickHouse/ClickHouse/pull/14409) ([Dmitry Rubashkin](https://github.com/dimarub2000)).
* 为多个 `JOIN` 和 `IN` 并行创建 Set。这可能会略微提升包含多个不同 `IN subquery` 表达式的查询性能。 [#14412](https://github.com/ClickHouse/ClickHouse/pull/14412) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 现在，如果 TTL 之前未被 materialized，则会在合并期间应用。 [#14438](https://github.com/ClickHouse/ClickHouse/pull/14438) ([alesapin](https://github.com/alesapin)).
* 对于类似 `SET @@var = value` 的查询，MySQL handler 会返回 `OK`。此类语句会被忽略。之所以需要这样做，是因为某些 MySQL 驱动会在 handshake 后发送 `SET @@` 查询进行 setup [#9336](https://github.com/ClickHouse/ClickHouse/issues/9336)#issuecomment-686222422 。 [#14469](https://github.com/ClickHouse/ClickHouse/pull/14469) ([BohuTANG](https://github.com/BohuTANG)).
* 如果存在正在进行的 S3 请求，则会加快服务器关闭过程。 [#14496](https://github.com/ClickHouse/ClickHouse/pull/14496) ([Pavel Kovalenko](https://github.com/Jokser)).
* 禁止在 `toStartOf*` 类函数中使用空的 `time_zone` 参数。 [#14509](https://github.com/ClickHouse/ClickHouse/pull/14509) ([Bharat Nallan](https://github.com/bharatnc)).
* ... [#14523](https://github.com/ClickHouse/ClickHouse/pull/14523) ([BohuTANG](https://github.com/BohuTANG)).
* 在 ConfigProcessor 中使用 std::filesystem::path 来拼接文件路径。 [#14558](https://github.com/ClickHouse/ClickHouse/pull/14558) ([Bharat Nallan](https://github.com/bharatnc)).

<div id="bug-fix">
  #### 缺陷修复
</div>

* 修复 lambda 中 `arrayJoin()` 的捕获问题 (LOGICAL&#95;ERROR) 。[#13792](https://github.com/ClickHouse/ClickHouse/pull/13792) ([Azat Khuzhin](https://github.com/azat)) 。
* 修复在非全局级别执行 `GRANT ALL` 语句时的问题。[#13987](https://github.com/ClickHouse/ClickHouse/pull/13987) ([Vitaly Baranov](https://github.com/vitlibar)) 。
* 禁止在 `ALIAS` 列类型上使用 `CODEC`。修复了 [#13911](https://github.com/ClickHouse/ClickHouse/issues/13911)。[#14263](https://github.com/ClickHouse/ClickHouse/pull/14263) ([Bharat Nallan](https://github.com/bharatnc)) 。
* 改进了对 SSD 缓存复杂键外部字典中 Tuple 大小的检查。此修复解决了 [#13981](https://github.com/ClickHouse/ClickHouse/issues/13981)。[#14313](https://github.com/ClickHouse/ClickHouse/pull/14313) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 修复带有嵌套解释器的查询中 QueryPlan 的生命周期问题 (用于 `EXPLAIN PIPELINE graph=1`) 。[#14315](https://github.com/ClickHouse/ClickHouse/pull/14315) ([Azat Khuzhin](https://github.com/azat)) 。
* 修复执行带 `REFRESH` 命令的 `ALTER LIVE VIEW` 查询时发生的异常。[#14320](https://github.com/ClickHouse/ClickHouse/pull/14320) ([Bharat Nallan](https://github.com/bharatnc)) 。
* 修复对通过 `AS table_function` 创建的表执行 `ALTER` 查询时发生的崩溃。修复了 [#14212](https://github.com/ClickHouse/ClickHouse/issues/14212)。[#14326](https://github.com/ClickHouse/ClickHouse/pull/14326) ([alesapin](https://github.com/alesapin)) 。
* 如果异常发生在 `PipelineExecutor` 自身内部，则停止执行查询。这可以避免极少数情况下出现查询挂起。[#14334](https://github.com/ClickHouse/ClickHouse/pull/14334) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 如果异常发生在 `PipelineExecutor` 自身内部，则停止执行查询。这可以避免极少数情况下出现查询挂起。是 [#14334](https://github.com/ClickHouse/ClickHouse/issues/14334) 的后续修复。[#14402](https://github.com/ClickHouse/ClickHouse/pull/14402) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 修复了一个缺陷：如果表中某些分区只有单个分片，会导致合并分配错误。[#14444](https://github.com/ClickHouse/ClickHouse/pull/14444) ([alesapin](https://github.com/alesapin)) 。
* 将 SysVinit 的 restart/start/stop/reload 操作代理到 systemd (如果使用的是 systemd) 。[#14460](https://github.com/ClickHouse/ClickHouse/pull/14460) ([Azat Khuzhin](https://github.com/azat)) 。
* 在 `topK` 聚合函数 中增加数组大小溢出检查。没有这项检查时，用户可能会发送带有精心构造参数的查询，从而导致 server 崩溃。此项变更关闭了 [#14452](https://github.com/ClickHouse/ClickHouse/issues/14452)。[#14467](https://github.com/ClickHouse/ClickHouse/pull/14467) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
