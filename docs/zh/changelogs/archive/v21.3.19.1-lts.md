  # 2022 更新日志

<div id="clickhouse-release-v213191-lts-fixme-as-compared-to-v213184-lts">
  ### ClickHouse 发布版 v21.3.19.1-lts FIXME，相较于 v21.3.18.4-lts
</div>

<div id="performance-improvement">
  #### 性能提升
</div>

* 已在 [#31733](https://github.com/ClickHouse/ClickHouse/issues/31733) 中回移：提升 JSON 和 XML 输出格式性能。[#31673](https://github.com/ClickHouse/ClickHouse/pull/31673) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。

<div id="bug-fix">
  #### 缺陷修复
</div>

* 已在 [#31577](https://github.com/ClickHouse/ClickHouse/issues/31577) 中回移：尚未达到配额限制，却被判定为超出限制。此 PR 修复了 [#31174](https://github.com/ClickHouse/ClickHouse/issues/31174)。[#31337](https://github.com/ClickHouse/ClickHouse/pull/31337) ([sunny](https://github.com/sunny19930321)) 。
* 已在 [#32347](https://github.com/ClickHouse/ClickHouse/issues/32347) 中回移：修复了在子查询中移除不必要列时的缺陷。如果查询中存在不带 GROUP BY 的聚合函数，即使它看似不需要，也不要将其移除。[#32289](https://github.com/ClickHouse/ClickHouse/pull/32289) ([dongyifeng](https://github.com/dyf6372)) 。

#### 缺陷修复 (官方稳定版本中用户可见的异常行为

* 已在 [#30913](https://github.com/ClickHouse/ClickHouse/issues/30913) 中回移：修复了在结果集为空且设置了 `TO` 和 `FROM` 时，`ORDER BY ... WITH FILL` 的问题。[#30888](https://github.com/ClickHouse/ClickHouse/pull/30888) ([Anton Popov](https://github.com/CurtizJ)).

<div id="bug-fix-user-visible-misbehaviour-in-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常行为)
</div>

* 已在 [#30750](https://github.com/ClickHouse/ClickHouse/issues/30750) 中回移：在 UTF8 字符串中执行不区分大小写搜索的函数 (如 `positionCaseInsensitiveUTF8` 和 `countSubstringsCaseInsensitiveUTF8`) 可能会找到实际上并不匹配的子字符串，现已修复。[#30663](https://github.com/ClickHouse/ClickHouse/pull/30663) ([Alexander Tokmakov](https://github.com/tavplubix)) 。
* 已在 [#31038](https://github.com/ClickHouse/ClickHouse/issues/31038) 中回移：将 `formatRow` 函数用于非行格式会导致 segfault。现已禁止将该函数用于此类格式 (因为这没有意义) 。[#31001](https://github.com/ClickHouse/ClickHouse/pull/31001) ([Kruglov Pavel](https://github.com/Avogar)) 。
* 已在 [#31519](https://github.com/ClickHouse/ClickHouse/issues/31519) 中回移：从 RPNElement 中移除 not like 函数。[#31169](https://github.com/ClickHouse/ClickHouse/pull/31169) ([sundyli](https://github.com/sundy-li)) 。
* 已在 [#31581](https://github.com/ClickHouse/ClickHouse/issues/31581) 中回移：* 在该优化中的缺陷修复之前，禁用 `partial_merge_join_left_table_buffer_bytes`。参见 [#31009](https://github.com/ClickHouse/ClickHouse/issues/31009)) 。* 移除冗余选项 `partial_merge_join_optimizations`。[#31528](https://github.com/ClickHouse/ClickHouse/pull/31528) ([Vladimir C](https://github.com/vdimir)) 。
* 已在 [#31792](https://github.com/ClickHouse/ClickHouse/issues/31792) 中回移：设置 `input_format_allow_errors_num` 和 `input_format_allow_errors_ratio` 在解析 `IPv4` 等 domain 类型时不起作用，现已修复。修复了 [#31686](https://github.com/ClickHouse/ClickHouse/issues/31686)。[#31697](https://github.com/ClickHouse/ClickHouse/pull/31697) ([Alexander Tokmakov](https://github.com/tavplubix)) 。
* 已在 [#31816](https://github.com/ClickHouse/ClickHouse/issues/31816) 中回移：修复了 JSONEachRowWithProgress 输出格式在输出中混合数据和进度行时出现的竞争问题。[#31736](https://github.com/ClickHouse/ClickHouse/pull/31736) ([Kruglov Pavel](https://github.com/Avogar)) 。
* 已在 [#31758](https://github.com/ClickHouse/ClickHouse/issues/31758) 中回移：修复了 `Buffer` 表引擎与 `Map` 类型配合使用时的问题。修复了 [#30546](https://github.com/ClickHouse/ClickHouse/issues/30546)。[#31742](https://github.com/ClickHouse/ClickHouse/pull/31742) ([Anton Popov](https://github.com/CurtizJ)) 。
* 已在 [#32153](https://github.com/ClickHouse/ClickHouse/issues/32153) 中回移：修复了当类型为 `Nullable` 时，对字典 attribute 使用带类型的 `dictGet` 函数会导致崩溃的问题。修复了 [#30980](https://github.com/ClickHouse/ClickHouse/issues/30980)。[#31800](https://github.com/ClickHouse/ClickHouse/pull/31800) ([Maksim Kita](https://github.com/kitaisreal)) 。
* 已在 [#31894](https://github.com/ClickHouse/ClickHouse/issues/31894) 中回移：修复了 TSKV 格式中可能触发断言 `../src/IO/ReadBuffer.h:58: bool DB::ReadBuffer::next(): Assertion '!hasPendingData()' failed.` 的问题。[#31804](https://github.com/ClickHouse/ClickHouse/pull/31804) ([Kruglov Pavel](https://github.com/Avogar)) 。
* 已在 [#32214](https://github.com/ClickHouse/ClickHouse/issues/32214) 中回移：如果某些副本上禁用了设置 `replicated_can_become_leader`，那么在使用 quorum 插入时，活跃副本数可能会被错误判定。现已修复。[#32157](https://github.com/ClickHouse/ClickHouse/pull/32157) ([Alexander Tokmakov](https://github.com/tavplubix)) 。
