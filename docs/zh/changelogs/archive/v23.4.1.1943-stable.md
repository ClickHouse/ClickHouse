<div id="backward-incompatible-change">
  #### 向后不兼容的更改
</div>

* 如果缓存 configuration 中的 `path` 不为空且不是绝对路径，则会将其放在 `<clickhouse server 数据目录>/caches/<path_from_cache_config>` 中。[#48784](https://github.com/ClickHouse/ClickHouse/pull/48784) ([Kseniia Sumarokova](https://github.com/kssenii))。
* 新增兼容性 setting `parallelize_output_from_storages`，用于启用 [#48727](https://github.com/ClickHouse/ClickHouse/issues/48727) 之前的行为。[#49101](https://github.com/ClickHouse/ClickHouse/pull/49101) ([Igor Nikonov](https://github.com/devcrafter))。

<div id="new-feature">
  #### 新特性
</div>

* 添加 `extractKeyValuePairs` 函数，用于从字符串中提取键值对。输入字符串中可能包含噪声 (例如日志文件 / 不需要 100% 符合键值对格式) ，算法会查找与传给函数的参数相匹配的键值对。目前，该函数接受以下参数：`data_column` (必填) 、`key_value_pair_delimiter` (默认为 `:`) 、`pair_delimiters` (默认为 `\space \, \;`) 和 `quoting_character` (默认为双引号) 。[#43606](https://github.com/ClickHouse/ClickHouse/pull/43606) ([Arthur Passos](https://github.com/arthurpassos)).
* 为后台任务 (merge 和 mutation) 添加 MemoryTracker。引入 `merges_mutations_memory_usage_soft_limit` 和 `merges_mutations_memory_usage_to_ram_ratio` 设置，表示 merge 和 mutation 的软内存限制。如果达到该限制，ClickHouse 将不会调度新的 merge 或 mutation 任务。此外，还引入了 `MergesMutationsMemoryTracking` 指标，用于观测后台任务的当前内存使用情况。关闭 [#45710](https://github.com/ClickHouse/ClickHouse/issues/45710)。[#46089](https://github.com/ClickHouse/ClickHouse/pull/46089) ([Dmitry Novik](https://github.com/novikd)).
* 支持新的聚合函数 quantileGK/quantilesGK，类似于 spark 中的 [approx&#95;percentile](https://spark.apache.org/docs/latest/api/sql/index.html#approx_percentile)。Greenwald-Khanna algorithm 参见 [http://infolab.stanford.edu/~datar/courses/cs361a/papers/quantiles.pdf](http://infolab.stanford.edu/~datar/courses/cs361a/papers/quantiles.pdf)。[#46428](https://github.com/ClickHouse/ClickHouse/pull/46428) ([李扬](https://github.com/taiyang-li)).
* 添加语句 `SHOW COLUMNS`，用于显示从 system.columns 中提炼出的信息。[#48017](https://github.com/ClickHouse/ClickHouse/pull/48017) ([Robert Schulze](https://github.com/rschu1ze)).
* 为 `SYSTEM SYNC REPLICA` 查询添加了 `LIGHTWEIGHT` 和 `PULL` modifier。`LIGHTWEIGHT` 版本仅等待 fetches 和 drop-ranges (忽略 merges 和 mutations) 。`PULL` 版本会从 ZooKeeper 拉取新 entries，但不会等待它们。修复 [#47794](https://github.com/ClickHouse/ClickHouse/issues/47794)。[#48085](https://github.com/ClickHouse/ClickHouse/pull/48085) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 添加 kafkaMurmurHash 函数，以兼容 Kafka DefaultPartitioner。关闭 [#47834](https://github.com/ClickHouse/ClickHouse/issues/47834)。[#48185](https://github.com/ClickHouse/ClickHouse/pull/48185) ([Nikolay Degterinsky](https://github.com/evillique)).
* 允许通过使用 `GRANT CURRENT GRANTS` 轻松创建一个与当前用户拥有相同授权的用户。[#48262](https://github.com/ClickHouse/ClickHouse/pull/48262) ([pufit](https://github.com/pufit)).
* 添加统计聚合函数 `kolmogorovSmirnovTest`。关闭 [#48228](https://github.com/ClickHouse/ClickHouse/issues/48228)。[#48325](https://github.com/ClickHouse/ClickHouse/pull/48325) ([FFFFFFFHHHHHHH](https://github.com/FFFFFFFHHHHHHH)).
* 向 `system.replicas` 表添加了 `lost_part_count` 列。该列的值表示对应表中丢失分片的总数。该值存储在 ZooKeeper 中，可用于替代非持久化的 `ReplicatedDataLoss` profile event 进行监控。[#48526](https://github.com/ClickHouse/ClickHouse/pull/48526) ([Sergei Trifonov](https://github.com/serxa)).
* 添加 soundex 函数。关闭 [#39880](https://github.com/ClickHouse/ClickHouse/issues/39880)。[#48567](https://github.com/ClickHouse/ClickHouse/pull/48567) ([FriendLey](https://github.com/FriendLey)).
* 支持 JSONExtract 的 Map 类型。[#48629](https://github.com/ClickHouse/ClickHouse/pull/48629) ([李扬](https://github.com/taiyang-li)).
* 新增 PrettyJSONEachRow 格式，可输出以换行符分隔并采用 4 空格缩进的美观 JSON。[#48898](https://github.com/ClickHouse/ClickHouse/pull/48898) ([Kruglov Pavel](https://github.com/Avogar)).
* 新增 ParquetMetadata 输入格式，用于读取 Parquet 文件元数据。[#48911](https://github.com/ClickHouse/ClickHouse/pull/48911) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 现在读取 Parquet 格式文件的速度快得多。IO 和解码已实现并行化 (由 `max_threads` 设置控制) ，并且只会读取所需的数据范围。[#47964](https://github.com/ClickHouse/ClickHouse/pull/47964) ([Michael Kolupaev](https://github.com/al13n321)).
* 仅在必要时，才会在应用 `ALTER TABLE` 查询时检查依赖项。[#48062](https://github.com/ClickHouse/ClickHouse/pull/48062) ([Raúl Marín](https://github.com/Algunenano)).
* 优化函数 `mapUpdate`。[#48118](https://github.com/ClickHouse/ClickHouse/pull/48118) ([Anton Popov](https://github.com/CurtizJ)).
* 现在会显式向本地副本发送内部查询，并通过回环接口接收其数据。对于并行副本，`prefer_localhost_replica` 设置将不再生效。这么做是为了获得更好的调度效果，同时也让代码更简洁：发起端只负责协调读取过程和合并结果，并持续响应请求，而所有次级查询负责读取数据。注意：使用回环接口的性能不算高，但否则某些副本可能会因分配不到任务而饥饿，这反而会导致查询执行更慢，并且无法充分利用所有可用资源。协调器的初始化现在也更加惰性。所有传入请求都包含读取算法的信息，因此我们会在第一个请求到达时据此初始化协调器。如果某个副本决定使用不同的算法读取数据，则会抛出异常并中止查询。[#48246](https://github.com/ClickHouse/ClickHouse/pull/48246) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 当带有子查询的 `IN` 子句右侧的 Set 仅用于分析跳过索引，且这些跳过索引已通过设置禁用 (`use_skip_indexes=0`) 时，不再为其构建 Set。此前这可能会影响查询性能。[#48299](https://github.com/ClickHouse/ClickHouse/pull/48299) ([Anton Popov](https://github.com/CurtizJ)).
* 在读取 `FROM file(...)` 后，查询处理会立即并行化。相关内容见 [#38755](https://github.com/ClickHouse/ClickHouse/issues/38755)。[#48525](https://github.com/ClickHouse/ClickHouse/pull/48525) ([Igor Nikonov](https://github.com/devcrafter)).
* 在从数据源读取之后，查询处理会立即并行化。受影响的数据源主要是简单数据源或外部存储，例如表函数 `url`、`file`。[#48727](https://github.com/ClickHouse/ClickHouse/pull/48727) ([Igor Nikonov](https://github.com/devcrafter)).
* 在 `numebers_mt()` 中为计数器使用正确的内存顺序。[#48729](https://github.com/ClickHouse/ClickHouse/pull/48729) ([Igor Nikonov](https://github.com/devcrafter)).
* 降低了 `ThreadPool` 互斥锁的竞争 (在存在大量小作业时可能提升性能) 。[#48750](https://github.com/ClickHouse/ClickHouse/pull/48750) ([Sergei Trifonov](https://github.com/serxa)).
* 简化了预取读取池中粒度近似大小的统计方式。[#49051](https://github.com/ClickHouse/ClickHouse/pull/49051) ([Nikita Taranov](https://github.com/nickitat)).

<div id="improvement">
  #### 改进
</div>

* 支持将配置节 `keeper`/`keeper_server` 用作 `zookeeper` 的替代。关闭 [#34766](https://github.com/ClickHouse/ClickHouse/issues/34766)、[#34767](https://github.com/ClickHouse/ClickHouse/issues/34767)。[#35113](https://github.com/ClickHouse/ClickHouse/pull/35113) ([李扬](https://github.com/taiyang-li)).
* 修复了 ClickHouse 应用程序帮助信息中的许多问题。现在所有工具都会将帮助信息输出到 stdout。调用 `clickhouse help` 时的状态码现在为 0。更新了 `clickhouse-local`、`clickhouse-benchmark`、`clickhouse-client`、`clickhouse hash`、`clickhouse su`、`clickhouse-install` 的帮助信息。[#45819](https://github.com/ClickHouse/ClickHouse/pull/45819) ([Ilya Yatsishin](https://github.com/qoega)).
* 查询缓存中的条目现在会合并到 max&#95;block&#95;size，并进行压缩。[#45912](https://github.com/ClickHouse/ClickHouse/pull/45912) ([Robert Schulze](https://github.com/rschu1ze)).
* 现在可以在 named&#95;collections 中为源为 ClickHouse 表的字典设置 *secure* 标志。处理了 [#38450](https://github.com/ClickHouse/ClickHouse/issues/38450)。[#46323](https://github.com/ClickHouse/ClickHouse/pull/46323) ([Ilya Golshtein](https://github.com/ilejn)).
* 现在，函数 replaceOne()、replaceAll()、replaceRegexpOne() 和 replaceRegexpAll() 可使用非常量的 pattern 和 replacement 参数调用。[#46589](https://github.com/ClickHouse/ClickHouse/pull/46589) ([Robert Schulze](https://github.com/rschu1ze)).
* 将内部 ZSTD 从 1.5.4 升级到 1.5.5。[#46797](https://github.com/ClickHouse/ClickHouse/pull/46797) ([Robert Schulze](https://github.com/rschu1ze)).
* 如果运行带有 IN (subquery) 的变更，例如：`ALTER TABLE t UPDATE col='new value' WHERE id IN (SELECT id FROM huge_table)`，并且表 `t` 有多个 parts，则会为每个 part 在内存中构建一个用于子查询 `SELECT id FROM huge_table` 的 Set。如果 parts 很多，可能会消耗大量内存 (并导致 OOM) 和 CPU。解决方案是引入一个短生命周期的 Set 缓存，用于保存当前由变更任务构建的 Set。如果同一变更的另一个任务并发执行，就可以在缓存中查找该 Set，等待其构建完成并复用。[#46835](https://github.com/ClickHouse/ClickHouse/pull/46835) ([Alexander Gololobov](https://github.com/davenger)).
* 为 Backup 查询中所有与 [Zoo]Keeper 相关的操作添加了可配置的重试机制。[#47224](https://github.com/ClickHouse/ClickHouse/pull/47224) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 添加了到套接字的异步连接和向套接字的异步写入。使跨分片创建 connection 以及发送查询/外部表变为异步。使用 fibers 重构了代码。关闭 [#46931](https://github.com/ClickHouse/ClickHouse/issues/46931)。在此 PR 之后，我们将能够默认增大 `connect_timeout_with_failover_ms` ([https://github.com/ClickHouse/ClickHouse/issues/5188](https://github.com/ClickHouse/ClickHouse/issues/5188)) 。[#47229](https://github.com/ClickHouse/ClickHouse/pull/47229) ([Kruglov Pavel](https://github.com/Avogar)).
* 函数 formatDateTime() 中的格式说明符 &#39;%M&#39; 现在输出的是月份名称，而不是分钟。这使其行为与 MySQL 保持一致。可以使用 setting &quot;formatdatetime&#95;parsedatetime&#95;m&#95;is&#95;month&#95;name = 0&quot; 恢复之前的行为。[#47246](https://github.com/ClickHouse/ClickHouse/pull/47246) ([Robert Schulze](https://github.com/rschu1ze)).
* 数据湖相关的多项改进：- 使 StorageIceberg 可用于非分区数据。- 支持 Iceberg 格式 V2 版本 (此前仅支持 V1) - 支持读取 DeltaLake/Hudi 的分区数据 - 通过使用 Delta 的 checkpoint 文件，加快 DeltaLake metadata 的读取速度 - 修复了 Hudi 读取错误：此前会错误地选择要读取的数据，因此只能正确读取小表 - 使这些引擎能够获取变更数据的更新 (此前状态是在创建表时设置的) - 使用 spark 为 Iceberg/DeltaLake/Hudi 添加了更完善的测试。[#47307](https://github.com/ClickHouse/ClickHouse/pull/47307) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 默认为 S3 启用 `use_environment_credentials`，因此默认会构建完整的提供商链。[#47397](https://github.com/ClickHouse/ClickHouse/pull/47397) ([Antonio Andelic](https://github.com/antonio2368)).
* 目前，JSON&#95;VALUE 函数与 spark 的 get&#95;json&#95;object 函数类似，支持通过 `$.key` 这类路径从 JSON string 中获取值。但两者仍有一些差异 - 1. 在 spark 的 get&#95;json&#95;object 中，如果路径不存在会返回 null，而 JSON&#95;VALUE 会返回空字符串；- 2. 在 spark 的 get&#95;json&#95;object 中，会返回复杂类型的值，例如 JSON object/array 值，而 JSON&#95;VALUE 会返回空字符串。[#47494](https://github.com/ClickHouse/ClickHouse/pull/47494) ([KevinyhZou](https://github.com/KevinyhZou)).
* 在新的 analyzer 中添加了 CNF/约束优化器。[#47617](https://github.com/ClickHouse/ClickHouse/pull/47617) ([Antonio Andelic](https://github.com/antonio2368)).
* 使 use&#95;structure&#95;from&#95;insertion&#95;table&#95;in&#95;table&#95;functions 在将插入表结构传播到 table function 时更加灵活。修复了名称映射和使用 virtual columns 时的问题。不再需要 `auto` 设置。[#47962](https://github.com/ClickHouse/ClickHouse/pull/47962) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* 如果查询已被 killed 或超出限制，则不再继续重试连接到 ZK。[#47985](https://github.com/ClickHouse/ClickHouse/pull/47985) ([Raúl Marín](https://github.com/Algunenano)).
* 添加了用于处理 `Map` 类型列的函数：`mapConcat`、`mapSort`、`mapExists`。[#48071](https://github.com/ClickHouse/ClickHouse/pull/48071) ([Anton Popov](https://github.com/CurtizJ)).
* BSONEachRow 现已支持 Enum 输出/输入，允许所有 map 键类型，并避免输出时的额外计算。[#48122](https://github.com/ClickHouse/ClickHouse/pull/48122) ([Kruglov Pavel](https://github.com/Avogar)).
