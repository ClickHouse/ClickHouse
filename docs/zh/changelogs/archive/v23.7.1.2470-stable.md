<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 添加了 ` NAMED COLLECTION` 访问类型 (别名为 `USE NAMED COLLECTION`、`NAMED COLLECTION USAGE`) 。此 PR 属于向后不兼容变更，因为该访问类型默认处于禁用状态 (其上级访问类型 `NAMED COLLECTION ADMIN` 也同样默认禁用) 。提案见 [#50277](https://github.com/ClickHouse/ClickHouse/issues/50277)。如需授权，请使用 `GRANT NAMED COLLECTION ON collection_name TO user` 或 `GRANT NAMED COLLECTION ON * TO user`；若要授予这些授权，需要在 config 中启用 `named_collection_admin` (此前名为 `named_collection_control`，因此会继续保留为别名) 。[#50625](https://github.com/ClickHouse/ClickHouse/pull/50625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 修复了 `system.parts` 列名 `last_removal_attemp_time` 中的拼写错误。该列现更名为 `last_removal_attempt_time`。[#52104](https://github.com/ClickHouse/ClickHouse/pull/52104) ([filimonov](https://github.com/filimonov)).
* 默认将 distributed&#95;ddl&#95;entry&#95;format&#95;version 提升到 5 (启用 OpenTelemetry 和 initial&#95;query&#95;idd 透传) 。这会导致在**降级**后无法处理现有的 distributed DDL 条目 (但请注意，通常不应存在这类未处理的条目) 。[#52128](https://github.com/ClickHouse/ClickHouse/pull/52128) ([Azat Khuzhin](https://github.com/azat)).
* 现在会像检查普通元数据一样检查 projection 元数据。如果某个表包含无效的 projection，此变更可能会导致服务器无法启动。例如，projection 在 PK 中创建了位置列 (如 `projection p (select * order by 1, 4)`，这在表 PK 中是不允许的，并且可能在 insert/merge 期间导致 crash) 。请在更新前删除此类 projections。修复了 [#52353](https://github.com/ClickHouse/ClickHouse/issues/52353)。[#52361](https://github.com/ClickHouse/ClickHouse/pull/52361) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Experimental 功能 `hashid` 因 bug 已被移除。它的实现质量从一开始就存在疑问，并且始终未脱离 Experimental 状态。此项关闭了 [#52406](https://github.com/ClickHouse/ClickHouse/issues/52406)。[#52449](https://github.com/ClickHouse/ClickHouse/pull/52449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 函数 `toDecimalString` 因实现质量不佳已被移除。此项关闭了 [#52407](https://github.com/ClickHouse/ClickHouse/issues/52407)。[#52450](https://github.com/ClickHouse/ClickHouse/pull/52450) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 默认启用 `move_all_conditions_to_prewhere` 和 `enable_multiple_prewhere_read_steps` 设置。[#46365](https://github.com/ClickHouse/ClickHouse/pull/46365) ([Alexander Gololobov](https://github.com/davenger)).
* 通过调优 allocator 提升了部分查询的性能。[#46416](https://github.com/ClickHouse/ClickHouse/pull/46416) ([Azat Khuzhin](https://github.com/azat)).
* 写入 Parquet 文件的速度提升了 10 倍，现已支持多线程。速度几乎与读取相当。[#49367](https://github.com/ClickHouse/ClickHouse/pull/49367) ([Michael Kolupaev](https://github.com/al13n321)).
* 默认启用对稀疏序列化格式的自动选择。这会提升性能。该格式自 22.1 版本起受支持。此更改后，可能无法再降级到早于 22.1 的版本。你可以为 MergeTree 表设置 `ratio_of_defaults_for_sparse_serialization = 1`，以关闭稀疏序列化格式的使用。[#49631](https://github.com/ClickHouse/ClickHouse/pull/49631) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 现在我们在 `MergeTreePrefetchedReadPool` 中也像 `MergeTreeReadPool` 一样使用固定大小的任务。此外，现已对 S3 请求使用连接池。[#49732](https://github.com/ClickHouse/ClickHouse/pull/49732) ([Nikita Taranov](https://github.com/nickitat)).
* 将更多操作下推到 join 的右侧。[#50532](https://github.com/ClickHouse/ClickHouse/pull/50532) ([Nikita Taranov](https://github.com/nickitat)).
* 通过预留哈希表大小来改进 grace&#95;hash join (重新提交) 。[#50875](https://github.com/ClickHouse/ClickHouse/pull/50875) ([lgbo](https://github.com/lgbo-ustc)).
* 有时在 `OpenedFileCache` 上等待锁会比较明显。我们将其分片为多个子 map (每个都有自己的锁) ，以避免竞争。[#51341](https://github.com/ClickHouse/ClickHouse/pull/51341) ([Nikita Taranov](https://github.com/nickitat)).
* 移除 `functionunixtimestamp64.h` 中重复的条件。[#51857](https://github.com/ClickHouse/ClickHouse/pull/51857) ([lcjh](https://github.com/ljhcage)).
* 其思路是，带有 PK 列的条件很可能会用于 PK 分析，因此对 PREWHERE 过滤的额外帮助不会太大。[#51958](https://github.com/ClickHouse/ClickHouse/pull/51958) ([Alexander Gololobov](https://github.com/davenger)).
* 1. 为旧版和新版 analyzer 均添加重写器。2. 新增设置 `optimize_uniq_to_count`，其默认值为 0。[#52004](https://github.com/ClickHouse/ClickHouse/pull/52004) ([JackyWoo](https://github.com/JackyWoo)) 。
* 在 ICX 设备 (Intel Xeon Platinum 8380 CPU，80 个核心、160 个线程) 上进行的 **OnTime** 性能实验表明，此变更可使查询 **Q8** 的 QPS 提升 **11.6%**，而对其他查询没有影响。[#52036](https://github.com/ClickHouse/ClickHouse/pull/52036) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 默认启用 `allow_vertical_merges_from_compact_to_wide_parts`。这将在 merges 期间节省内存使用。[#52295](https://github.com/ClickHouse/ClickHouse/pull/52295) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 修复了错误的投影分析问题，该问题会导致主键失效。此问题仅在 `query_plan_optimize_primary_key = 1, query_plan_optimize_projection = 1` 时存在。修复了 [#48823](https://github.com/ClickHouse/ClickHouse/issues/48823)。修复了 [#51173](https://github.com/ClickHouse/ClickHouse/issues/51173)。[#52308](https://github.com/ClickHouse/ClickHouse/pull/52308) ([Amos Bird](https://github.com/amosbird)).
* 减少了 FileCache::loadMetadata 中的系统调用数量。[#52435](https://github.com/ClickHouse/ClickHouse/pull/52435) ([Raúl Marín](https://github.com/Algunenano)).
