  ### ClickHouse release v20.8.2.3-stable FIXME，相比 v20.7.1.4310-prestable
</div>

<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 移除对 `ODBCDriver` 输入/输出 format 的支持。这是一种已弃用的 format，曾用于与 ClickHouse ODBC driver 通信，但如今早已被 `ODBCDriver2` format 取代。解决了 [#13629](https://github.com/ClickHouse/ClickHouse/issues/13629)。[#13847](https://github.com/ClickHouse/ClickHouse/pull/13847) ([hexiaoting](https://github.com/hexiaoting)) 。
* 扩展 `parallel_distributed_insert_select` setting，新增可将 `INSERT` 执行到本地表的选项。该 setting 的类型从 `Bool` 更改为 `UInt64`，因此不再支持 `false` 和 `true` 这两个值。如果你在服务器配置中使用了这些值，server 将无法启动。请分别将它们替换为 `0` 和 `1`。[#14060](https://github.com/ClickHouse/ClickHouse/pull/14060) ([Azat Khuzhin](https://github.com/azat)) 。
* 现在，`OPTIMIZE FINAL` 查询不会再为创建 TTL 之前添加的 parts 重新计算生存时间 (TTL)。请执行一次 `ALTER TABLE ... MATERIALIZE TTL` 进行计算，之后 `OPTIMIZE FINAL` 就能正确处理 TTL。此行为对复制表一直都不生效。[#14220](https://github.com/ClickHouse/ClickHouse/pull/14220) ([alesapin](https://github.com/alesapin)) 。



<div id="new-feature">
  #### 新特性
</div>

* 支持 `MaterializeMySQL` 数据库引擎。实现了 [#4006](https://github.com/ClickHouse/ClickHouse/issues/4006)。[#10851](https://github.com/ClickHouse/ClickHouse/pull/10851) ([Winter Zhang](https://github.com/zhang2014))。
* 支持在 Kafka 中使用 Kerberos 身份验证，依赖 `krb5` 和 `cyrus-sasl` 库。[#12771](https://github.com/ClickHouse/ClickHouse/pull/12771) ([Ilya Golshtein](https://github.com/ilejn))。
* 新增类型 `Int128`、`Int256`、`UInt256` 及其相关函数。将 Decimal 扩展至 Decimal256（精度最高支持 76 位）。新类型需通过设置项 `allow_experimental_bigint_types` 启用。[#13097](https://github.com/ClickHouse/ClickHouse/pull/13097) ([Artem Zuikov](https://github.com/4ertus2))。
* 函数 `position` 现已支持可选参数 `start_pos`。[#13237](https://github.com/ClickHouse/ClickHouse/pull/13237) ([Vladimir C](https://github.com/vdimir))。
* 新增 `ALTER SAMPLE BY` 语句，支持修改表的采样子句。[#13280](https://github.com/ClickHouse/ClickHouse/pull/13280) ([Amos Bird](https://github.com/amosbird))。
* 在主配置文件中新增可选节 <user_directories>。[#13425](https://github.com/ClickHouse/ClickHouse/pull/13425) ([Vitaly Baranov](https://github.com/vitlibar))。
* 新增函数 `normalizeQuery`，可将字面量、字面量序列及复杂别名替换为占位符。新增函数 `normalizedQueryHash`，对相似查询返回相同的 64 位哈希值，便于分析查询日志。关闭了 [#11271](https://github.com/ClickHouse/ClickHouse/issues/11271)。[#13816](https://github.com/ClickHouse/ClickHouse/pull/13816) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 新增 `quantileExactLow` 和 `quantileExactHigh` 实现，并分别为 `medianExactLow` 和 `medianExactHigh` 提供对应别名。[#13818](https://github.com/ClickHouse/ClickHouse/pull/13818) ([Bharat Nallan](https://github.com/bharatnc))。
* 新增函数 `defaultValueOfTypeName`，返回指定类型的默认值。[#13877](https://github.com/ClickHouse/ClickHouse/pull/13877) ([hcz](https://github.com/hczhcz))。
* 新增 `date_trunc` 函数，可将日期/时间值截断至指定的日期/时间粒度。[#13888](https://github.com/ClickHouse/ClickHouse/pull/13888) ([vladimir-golovchenko](https://github.com/vladimir-golovchenko))。
* 支持为列指定 `Default` 压缩编解码器，该编解码器将沿用 `config.xml` 中配置的压缩设置。实现了 [#9074](https://github.com/ClickHouse/ClickHouse/issues/9074)。[#14049](https://github.com/ClickHouse/ClickHouse/pull/14049) ([alesapin](https://github.com/alesapin))。
* 新增设置项 `min_index_granularity_bytes`，防止误将 `index_granularity_bytes` 设置为过低的值而创建表。[#14139](https://github.com/ClickHouse/ClickHouse/pull/14139) ([Bharat Nallan](https://github.com/bharatnc))。
* 新增 `countDigits(x)` 函数，用于统计整数列或 Decimal 列中的十进制位数。新增 `isDecimalOverflow(d, [p])` 函数，用于检查 Decimal 列中的值是否超出其自身（或指定）的精度范围。[#14151](https://github.com/ClickHouse/ClickHouse/pull/14151) ([Artem Zuikov](https://github.com/4ertus2))。

<div id="performance-improvement">
  #### 性能提升
</div>

* 执行简单的 `INSERT SELECT` 查询时，会自动将 `max_threads` 设置为 1 或 `max_insert_threads`，并将 `max_block_size` 设置为 `min_insert_block_size_rows`。与 [#5907](https://github.com/ClickHouse/ClickHouse/issues/5907) 相关。[#12195](https://github.com/ClickHouse/ClickHouse/pull/12195) ([flynn](https://github.com/ucasfl)) 。
* 针对 `Array(LowCardinality(T))` 和常量右侧参数，优化了 `has()`、`indexOf()` 和 `countEqual()` 函数。[#12550](https://github.com/ClickHouse/ClickHouse/pull/12550) ([Mike Kot](https://github.com/myrrc)) 。
* 略微提升了按 UInt8/UInt16 键进行聚合时的性能。[#13099](https://github.com/ClickHouse/ClickHouse/pull/13099) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 在扫描 parts 时，如果超出 `max_rows_to_read` 限制，则会快速失败。此更改的目的是：如果已经明确 `max_rows_to_read` 超限，就跳过对所有已选 parts 的 ranges 扫描。对于涉及大量 parts 的查询，此更改效果相当明显。[#13677](https://github.com/ClickHouse/ClickHouse/pull/13677) ([Roman Khavronenko](https://github.com/hagen1778)) 。
* 为 `Null`、`Memory`、`Distributed` 和 `Buffer` 表引擎启用并行 INSERT。[#14120](https://github.com/ClickHouse/ClickHouse/pull/14120) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 略微优化了使用 LowCardinality 的超短查询。[#14129](https://github.com/ClickHouse/ClickHouse/pull/14129) ([Anton Popov](https://github.com/CurtizJ)) 。

* 在之前的版本中，若使用特制参数调用 `lcm` 函数，可能会在 Debug 构建中触发断言失败。此更改修复了 [#13368](https://github.com/ClickHouse/ClickHouse/issues/13368)。[#13510](https://github.com/ClickHouse/ClickHouse/pull/13510) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 添加了 MergeTree 预写日志 (WAL) 转储工具。[#13640](https://github.com/ClickHouse/ClickHouse/pull/13640) ([BohuTANG](https://github.com/BohuTANG)) 。
* 已在 [#14360](https://github.com/ClickHouse/ClickHouse/issues/14360) 中回移：添加了 Redis requirepass 认证。[#13688](https://github.com/ClickHouse/ClickHouse/pull/13688) ([Ivan Torgashov](https://github.com/it1804)) 。
* 避免将数组作为字段处理时出现查询过慢的问题，改为抛出异常。[#13753](https://github.com/ClickHouse/ClickHouse/pull/13753) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 1. 添加 [基于 GTID 的复制](https://dev.mysql.com/doc/refman/5.7/en/replication-gtids-concepts.html)，即使复制拓扑发生变化也能正常工作，并且在 MySQL 5.6/5.7/8.0 中受支持且更推荐使用 2. 添加对 BIT/SET 字段类型的支持 3. 修复 varchar 类型元数据长度 bug。[#13820](https://github.com/ClickHouse/ClickHouse/pull/13820) ([BohuTANG](https://github.com/BohuTANG)) 。
* 修复了 `lgamma` 函数中的数据竞争问题。该竞争问题仅在 `tsan` 中被发现，实际上并未产生任何副作用。[#13842](https://github.com/ClickHouse/ClickHouse/pull/13842) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 当数组元素类型为 Float32/Float64 时，函数 `arrayCompact` 会按位比较 NaN。在之前的版本中，如果数组元素类型为 Float32/Float64，NaN 始终被视为不相等；而如果类型更复杂，例如 Nullable(Float64)，则始终被视为相等。这修复了 [#13857](https://github.com/ClickHouse/ClickHouse/issues/13857)。[#13868](https://github.com/ClickHouse/ClickHouse/pull/13868) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 改进了 TabSeparatedRow format 中空值的报错信息。[#13906](https://github.com/ClickHouse/ClickHouse/pull/13906) ([jiang tao](https://github.com/tomjiang1987)).
* 修复了长查询时错误的报错。对于正确的查询，之前有可能收到 `Max query size exceeded` 之外的语法错误。[#13928](https://github.com/ClickHouse/ClickHouse/pull/13928) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 修复了 AvroConfluent format 中的一个错误：当收到异常小且格式错误的消息时，可能会导致 Kafka table engine 停止处理消息。[#13941](https://github.com/ClickHouse/ClickHouse/pull/13941) ([Gervasio Varela](https://github.com/gervarela)).
* 将 -Resample combinator 的限制提升到 1M。[#13947](https://github.com/ClickHouse/ClickHouse/pull/13947) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* 条件聚合函数 (例如：`avgIf`、`sumIf`、`maxIf`) 在缺少行且使用 Nullable 参数时应返回 `NULL`。[#13964](https://github.com/ClickHouse/ClickHouse/pull/13964) ([Winter Zhang](https://github.com/zhang2014)).
* 如果 `Memory` 表是由大量非常小的块构建而成，其性能会略有提升 (不过这种情况不太常见) 。这个想法的提出者：[Mark Papadakis](https://github.com/markpapadakis)。关闭了 [#14043](https://github.com/ClickHouse/ClickHouse/issues/14043)。[#14056](https://github.com/ClickHouse/ClickHouse/pull/14056) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 现在可以执行 `ALTER TABLE table_name FETCH PARTITION partition_expr FROM 'zk://<host>:<port>/path-in-zookeeper'`。这对于将数据传输到新集群很有用。[#14155](https://github.com/ClickHouse/ClickHouse/pull/14155) ([Amos Bird](https://github.com/amosbird)).
