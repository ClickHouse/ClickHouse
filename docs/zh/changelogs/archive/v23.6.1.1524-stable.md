<div id="clickhouse-release-v23611524-stable-d1c7e13d088-fixme-as-compared-to-v23513174-stable-2fec796e73e">
  ### ClickHouse 发布版本 v23.6.1.1524-stable (d1c7e13d088) FIXME，与 v23.5.1.3174-stable (2fec796e73e) 相比
</div>

<div id="backward-incompatible-change">
  #### 向后不兼容变更
</div>

* 删除 fs cache 中的 `do_not_evict_index_and_mark_files` 功能。该功能只会让情况变得更糟。[#51253](https://github.com/ClickHouse/ClickHouse/pull/51253) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 移除对 Experimental LIVE VIEW 的 ALTER 支持。[#51287](https://github.com/ClickHouse/ClickHouse/pull/51287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 新特性
</div>

* 添加设置 `session_timezone`，在未显式指定时，将其用作会话的默认时区。[#44149](https://github.com/ClickHouse/ClickHouse/pull/44149) ([Andrey Zvonov](https://github.com/zvonand)).
* 新增 overlay database engine，以及将 directory 表示为 database 的能力。此次提交新增了 4 个 database：1. DatabaseOverlay：实现 IDatabase interface。允许组合多个 database，例如 FileSystem 和 Memory。其内部保存了一个包含其他 database 指针的向量，并依次将请求代理给它们，直到成功执行。2. DatabaseFilesystem：允许以只读方式与存储在 file system 中的文件交互。内部会在用户请求该表时，使用 TableFunctionFile 隐式加载文件。TableFunctionFile 的调用结果会缓存在内部，以便快速访问。3. DatabaseS3：允许以只读方式与 S3 storage 交互。它使用 TableFunctionS3 从 S3 隐式加载表。4. DatabaseHDFS：允许与 hdfs storage 交互。它使用 TableFunctionHDFS 从 hdfs 隐式加载表。[#48821](https://github.com/ClickHouse/ClickHouse/pull/48821) ([alekseygolub](https://github.com/alekseygolub)).
* 添加一个名为 `use_mysql_types_in_show_columns` 的新设置，用于修改 `SHOW COLUMNS` SQL 语句，使通过 MySQL compatibility port 连接的客户端显示与 MySQL 对应的类型。[#49577](https://github.com/ClickHouse/ClickHouse/pull/49577) ([Thomas Panetti](https://github.com/tpanetti)).
* 新增选项 `--rename_files_after_processing <pattern>`。这解决了 [#34207](https://github.com/ClickHouse/ClickHouse/issues/34207)。[#49626](https://github.com/ClickHouse/ClickHouse/pull/49626) ([alekseygolub](https://github.com/alekseygolub)).
* 1. 添加 `TableFunctionRedis` 3. 添加 Redis 表引擎 4. 添加 `RedisCommon`，其中包含 Redis 相关工具和类型 5. 支持将 `equals` 和 `in` 过滤器下推到 Redis。[#50150](https://github.com/ClickHouse/ClickHouse/pull/50150) ([JackyWoo](https://github.com/JackyWoo)).
* 允许通过设置 `s3_skip_empty_files`、`hdfs_skip_empty_files`、`engine_file_skip_empty_files`、`engine_url_skip_empty_files`，在 file/s3/url/hdfs table functions 中跳过空文件。[#50364](https://github.com/ClickHouse/ClickHouse/pull/50364) ([Kruglov Pavel](https://github.com/Avogar)).
* 现在调用 ClickHouse 客户端时，可以直接使用 connection，而不必再使用 &quot;--host&quot;、&quot;--port&quot;、&quot;--user&quot; 等参数。[#50689](https://github.com/ClickHouse/ClickHouse/pull/50689) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* 编解码器 DEFLATE&#95;QPL 现在通过 server setting &quot;enable&#95;deflate&#95;qpl&#95;codec&quot; (默认值：false) 控制，而不是通过设置 &quot;allow&#95;experimental&#95;codecs&quot;。这意味着 QPL&#95;DEFLATE 不再属于 Experimental。[#50775](https://github.com/ClickHouse/ClickHouse/pull/50775) ([Robert Schulze](https://github.com/rschu1ze)).



<div id="performance-improvement">
  #### 性能提升
</div>

* 启用 QueryProfiler 时，使用线程本地 `timer_id` 替代全局对象，以提升性能。[#48778](https://github.com/ClickHouse/ClickHouse/pull/48778) ([Jiebin Sun](https://github.com/jiebinn)).
* 重写 CapnProto 输入/输出格式以提升性能。使 Map 列名和 CapnProto 字段支持不区分大小写匹配，并修复嵌套结构字段的读写问题。[#49752](https://github.com/ClickHouse/ClickHouse/pull/49752) ([Kruglov Pavel](https://github.com/Avogar)).
* 优化 Parquet 在并行线程中的写入性能。[#50102](https://github.com/ClickHouse/ClickHouse/pull/50102) ([Hongbin Ma](https://github.com/binmahone)).
* ### 面向用户变更的文档条目 对处理 MATERIALIZED VIEW 和仅包含一个块的 storages 禁用 `parallelize_output_from_storages`。[#50214](https://github.com/ClickHouse/ClickHouse/pull/50214) ([Azat Khuzhin](https://github.com/azat)).
* 合并 PR https://github.com/ClickHouse/ClickHouse/pull/46558 (避免处理已排序数据) 。如果块已经排好序，则在 sort 期间避免对块进行置换。[#50697](https://github.com/ClickHouse/ClickHouse/pull/50697) ([Maksim Kita](https://github.com/kitaisreal)).
* 在之前的 PR ([#50062](https://github.com/ClickHouse/ClickHouse/issues/50062), [#50307](https://github.com/ClickHouse/ClickHouse/issues/50307)) 中，我们曾提出一种优化模式，将包含 toYear/toYYYYMM 的 predicates 转换为等价但无需 converter 的形式。这种转换可为某些 workloads (如 SSB) 带来显著的性能收益。然而，正如 issue [#50628](https://github.com/ClickHouse/ClickHouse/issues/50628) 所指出的，这两个 PR 会引入一些问题，可能导致查询结果不完整，因此已由 [#50629](https://github.com/ClickHouse/ClickHouse/issues/50629) 回退。[#50951](https://github.com/ClickHouse/ClickHouse/pull/50951) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 并行向 ZooKeeper 发起多个 list 请求，以加快从 system.zookeeper 表读取数据的速度。[#51042](https://github.com/ClickHouse/ClickHouse/pull/51042) ([Alexander Gololobov](https://github.com/davenger)).
* 加快时区的 日期时间 lookup 表初始化。这应能缩短 clickhouse client 的启动/连接时间，尤其是在 Debug 构建中，因为这部分开销相当大。[#51347](https://github.com/ClickHouse/ClickHouse/pull/51347) ([Alexander Gololobov](https://github.com/davenger)).



<div id="improvement">
  #### Improvement
</div>

* 支持将 CIDR ::ffff:0:0/96（IPv4 映射地址）的 IPv6 地址转换为 IPv4 地址。[#49759](https://github.com/ClickHouse/ClickHouse/pull/49759) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy))。
* 更新 MongoDB 协议以支持 MongoDB 5.1 及更高版本，同时保留对旧协议版本（<3.6）的支持。关闭 [#45621](https://github.com/ClickHouse/ClickHouse/issues/45621)、[#49879](https://github.com/ClickHouse/ClickHouse/issues/49879)。[#50061](https://github.com/ClickHouse/ClickHouse/pull/50061) ([Nikolay Degterinsky](https://github.com/evillique))。
* 改进了 `ReplicatedMergeTree` 中合并选择与清理任务的调度机制。当没有可合并或清理的内容时，任务不会被过于频繁地触发。新增配置项 `max_merge_selecting_sleep_ms`、`merge_selecting_sleep_slowdown_factor`、`max_cleanup_delay_period` 和 `cleanup_thread_preferred_points_per_iteration`。关闭 [#31919](https://github.com/ClickHouse/ClickHouse/issues/31919)。[#50107](https://github.com/ClickHouse/ClickHouse/pull/50107) ([Alexander Tokmakov](https://github.com/tavplubix))。
* 分析器现支持并行副本。[#50441](https://github.com/ClickHouse/ClickHouse/pull/50441) ([Raúl Marín](https://github.com/Algunenano))。
* 新增配置项 `input_format_max_bytes_to_read_for_schema_inference`，用于限制 schema 推断时读取的字节数上限。关闭 [#50577](https://github.com/ClickHouse/ClickHouse/issues/50577)。[#50592](https://github.com/ClickHouse/ClickHouse/pull/50592) ([Kruglov Pavel](https://github.com/Avogar))。
* schema 推断现可正确遵循 `input_format_as_default` 配置项。[#50602](https://github.com/ClickHouse/ClickHouse/pull/50602) ([Kruglov Pavel](https://github.com/Avogar))。
* 支持过滤条件下推穿越 cross join。[#50605](https://github.com/ClickHouse/ClickHouse/pull/50605) ([Han Fei](https://github.com/hanfei1991))。
* 现已使用实际版本的 lz4。[#50621](https://github.com/ClickHouse/ClickHouse/pull/50621) ([Nikita Taranov](https://github.com/nickitat))。
* 新增配置项 `input_format_csv_skip_trailing_empty_lines`、`input_format_tsv_skip_trailing_empty_lines` 和 `input_format_custom_skip_trailing_empty_lines`，支持跳过 CSV/TSV/CustomSeparated 格式末尾的空行（默认禁用）。关闭 [#49315](https://github.com/ClickHouse/ClickHouse/issues/49315)。[#50635](https://github.com/ClickHouse/ClickHouse/pull/50635) ([Kruglov Pavel](https://github.com/Avogar))。
* 函数 `toDateOrDefault|OrNull()` 和 `accurateCast[OrDefault|OrNull]()` 现已能正确解析数值类型参数。[#50709](https://github.com/ClickHouse/ClickHouse/pull/50709) ([Dmitry Kardymon](https://github.com/kardymonds))。
* 修复了 CSV 输入格式无法解析以空格或 `\t` 作为字段分隔符的 CSV 文件的问题（此类分隔符在 Spark 中受支持）。[#50712](https://github.com/ClickHouse/ClickHouse/pull/50712) ([KevinyhZou](https://github.com/KevinyhZou))。
* 配置项 `number_of_mutations_to_delay` 和 `number_of_mutations_to_throw` 现已默认启用，默认值分别为 500 和 1000。[#50726](https://github.com/ClickHouse/ClickHouse/pull/50726) ([Anton Popov](https://github.com/CurtizJ))。
* Keeper 改进：为 Keeper API 新增功能标志。每个功能标志均可通过在 `keeper_server.feature_flags` 配置项下定义来启用或禁用。例如，若要启用 `CheckNotExists` 请求，需在 Keeper 上将 `keeper_server.feature_flags.check_not_exists` 设置为 `1`。[#50796](https://github.com/ClickHouse/ClickHouse/pull/50796) ([Antonio Andelic](https://github.com/antonio2368))。
* 仪表板现可正确显示缺失值。关闭 [#50831](https://github.com/ClickHouse/ClickHouse/issues/50831)。[#50832](https://github.com/ClickHouse/ClickHouse/pull/50832) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 与 CPU 相关的 CGroups 指标已合并为单一指标 `CGroupMaxCPU`，以提升易用性。设置了 CGroups 限制后，归一化 CPU 使用率指标将以 CGroups 限制为基准进行归一化，而非以 CPU 总数为基准。关闭 [#50836](https://github.com/ClickHouse/ClickHouse/issues/50836)。[#50835](https://github.com/ClickHouse/ClickHouse/pull/50835) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 放宽"parts 过多"的阈值以适应现代场景，并在长时间运行的插入查询期间恢复背压机制。[#50856](https://github.com/ClickHouse/ClickHouse/pull/50856) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 函数 `parseDateTimeBestEffort*()` 和 `parseDateTime64BestEffort*()` 现支持解析 syslog 时间戳格式的日期时间参数。[#50925](https://github.com/ClickHouse/ClickHouse/pull/50925) ([Victor Krasnov](https://github.com/sirvickr))。
* 当目标文件已存在时，提示用户在 `INTO OUTFILE` 中使用 `APPEND` 或 `TRUNCATE`。[#50950](https://github.com/ClickHouse/ClickHouse/pull/50950) ([alekar](https://github.com/alekar))。
* 在独立 Keeper 二进制文件中内嵌 keeper-client。[#50964](https://github.com/ClickHouse/ClickHouse/pull/50964) ([pufit](https://github.com/pufit))。
* clickhouse-client 中的命令行参数 `--password` 现在只能指定一次。[#50966](https://github.com/ClickHouse/ClickHouse/pull/50966) ([Alexey Gerasimchuck](https://github.com/Demilivor))。
* 修复因同步 HEAD 请求导致数据湖访问缓慢的问题（与 Iceberg/Deltalake/Hudi 在文件数量较多时响应迟缓有关）。[#50976](https://github.com/ClickHouse/ClickHouse/pull/50976) ([Kseniia Sumarokova](https://github.com/kssenii))。
* 集群备份期间，使用 `system.parts` 中的 `hash_of_all_files` 校验 parts 的一致性。[#50997](https://github.com/ClickHouse/ClickHouse/pull/50997) ([Vitaly Baranov](https://github.com/vitlibar))。
* 系统表 `zookeeper_connection` 中的 `connected_time` 字段记录连接建立的时间（标准格式）；新增 `session_uptime_elapsed_seconds` 字段，用于记录当前连接会话的持续时长（单位：秒）。[#51026](https://github.com/ClickHouse/ClickHouse/pull/51026) ([郭小龙](https://github.com/guoxiaolongzte))。
* 修复 `system.parts`、`system.projection_parts` 及错误信息中校验和两个半部分的显示顺序。[#51040](https://github.com/ClickHouse/ClickHouse/pull/51040) ([Vitaly Baranov](https://github.com/vitlibar))。
* 当 `Replicated` 数据库仅有一个分片且底层表为 `ReplicatedMergeTree` 时，不再通过该数据库复制 `ALTER PARTITION` 查询和变更操作。[#51049](https://github.com/ClickHouse/ClickHouse/pull/51049) ([Alexander Tokmakov](https://github.com/tavplubix))。
* 改进 file/s3/hdfs/url 表函数的进度条显示：采用源数据的分块大小，并在每个线程中进行增量总大小统计；同时修复了 `*Cluster` 函数的进度条问题。关闭 [#47250](https://github.com/ClickHouse/ClickHouse/issues/47250)。[#51088](https://github.com/ClickHouse/ClickHouse/pull/51088) ([Kruglov Pavel](https://github.com/Avogar))。
* 在 TCP 协议的 Progress 数据包中新增 `total_bytes_to_read` 字段，以改善进度条的显示效果。[#51158](https://github.com/ClickHouse/ClickHouse/pull/51158) ([Kruglov Pavel](https://github.com/Avogar))。
* 改进了对启用文件系统缓存的磁盘上数据 parts 的校验机制。[#51164](https://github.com/ClickHouse/ClickHouse/pull/51164) ([Anton Popov](https://github.com/CurtizJ))。
* 禁用缓存设置 `do_not_evict_index_and_mark_files`（该设置在 `23.5` 中已启用）。[#51222](https://github.com/ClickHouse/ClickHouse/pull/51222) ([Kseniia Sumarokova](https://github.com/kssenii))。
* 修复文件系统缓存中 current_elements_num 有时不正确的问题。[#51242](https://github.com/ClickHouse/ClickHouse/pull/51242) ([Kseniia Sumarokova](https://github.com/kssenii))。
* 在执行合并/变更操作前添加随机等待时间，以便在使用零拷贝复制时将负载更均匀地分散到各副本之间。[#51282](https://github.com/ClickHouse/ClickHouse/pull/51282) ([alesapin](https://github.com/alesapin))。
* 函数 `transform` 以及带值匹配的 `CASE` 现已支持所有数据类型。此更改关闭了 [#29730](https://github.com/ClickHouse/ClickHouse/issues/29730)、[#32387](https://github.com/ClickHouse/ClickHouse/issues/32387)、[#50827](https://github.com/ClickHouse/ClickHouse/issues/50827)、[#31336](https://github.com/ClickHouse/ClickHouse/issues/31336) 和 [#40493](https://github.com/ClickHouse/ClickHouse/issues/40493)。[#51351](https://github.com/ClickHouse/ClickHouse/pull/51351) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 我们在 LLVM 中发现了一个漏洞，导致 `compile_expressions` 设置存在安全风险，该设置现已默认禁用。[#51368](https://github.com/ClickHouse/ClickHouse/pull/51368) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* Issue [#50220](https://github.com/ClickHouse/ClickHouse/issues/50220) 报告了 `grace_hash` join 中的一处崩溃。我们最终在本地复现了该异常，发现问题与创建临时文件失败有关，该问题由 https://github.com/ClickHouse/ClickHouse/pull/49816 和 https://github.com/ClickHouse/ClickHouse/pull/49483 引入。[#51382](https://github.com/ClickHouse/ClickHouse/pull/51382) ([lgbo](https://github.com/lgbo-ustc))。
