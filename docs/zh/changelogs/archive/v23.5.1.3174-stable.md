<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 使本地对象存储与 S3 对象存储的行为保持一致，修复 `append` 的问题 (关闭 [#48465](https://github.com/ClickHouse/ClickHouse/issues/48465)) ，并使其可配置为独立存储。此变更向后不兼容，因为本地对象存储之上的缓存与之前版本不兼容。[#48791](https://github.com/ClickHouse/ClickHouse/pull/48791) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 使 Date&#95;trunc 函数始终返回日期时间类型。[#48851](https://github.com/ClickHouse/ClickHouse/pull/48851) ([Shane Andrade](https://github.com/mauidude)).
* 移除 Experimental 功能“in-memory data parts”。该数据格式仍受支持，但相关设置现在为空操作，系统将改为使用 compact 或 wide parts。这关闭了 [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409)。[#49429](https://github.com/ClickHouse/ClickHouse/pull/49429) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 更改了设置 parallelize&#95;output&#95;from&#95;storages 和 input&#95;format&#95;parquet&#95;preserve&#95;order 的默认值。这使 ClickHouse 在从文件 (例如 CSV 或 Parquet) 读取时可以重排行，从而在许多情况下显著提升性能。若要恢复先前的保序行为，请使用 `parallelize_output_from_storages = 0`、`input_format_parquet_preserve_order = 1`。[#49479](https://github.com/ClickHouse/ClickHouse/pull/49479) ([Michael Kolupaev](https://github.com/al13n321)).
* 使 projections 达到生产可用状态。新增 `optimize_use_projections` 设置，用于控制是否为 SELECT 查询选择 projections。设置 `allow_experimental_projection_optimization` 已废弃且不再生效。[#49719](https://github.com/ClickHouse/ClickHouse/pull/49719) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 将 joinGet() 标记为非确定性 (dictGet 也是如此) 。[#49843](https://github.com/ClickHouse/ClickHouse/pull/49843) ([Azat Khuzhin](https://github.com/azat)).
* 回退“`groupArray` returns cannot be nullable” (因为这会破坏 `Nullable` 类型上 `groupArray`/`groupArrayLast`/`groupArraySample` 的二进制兼容性，很可能导致 `TOO_LARGE_ARRAY_SIZE` 或 `CANNOT_READ_ALL_DATA`) 。[#49971](https://github.com/ClickHouse/ClickHouse/pull/49971) ([Azat Khuzhin](https://github.com/azat)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 默认对标记和主键启用压缩，可显著缩短冷查询时间。升级说明：22.9 版本新增了对压缩标记和主键的支持。如果你启用了压缩标记或主键，或者安装了默认启用压缩标记或主键的 23.5 及以上版本，则无法降级到 22.8 及更早版本。你也可以在 server configuration file 的 `<merge_tree>` 部分中，通过指定 `compress_marks` 和 `compress_primary_key` 设置来显式禁用压缩标记或主键。**升级说明：**如果你从 22.9 之前的版本升级，应一次性升级所有副本，或在升级前禁用压缩，或者先升级到一个支持压缩标记但默认未启用的中间版本，例如 23.3。[#42587](https://github.com/ClickHouse/ClickHouse/pull/42587) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 从多个文件读取时，减少每个文件的并行解析线程数，解决了 [#42192](https://github.com/ClickHouse/ClickHouse/issues/42192)。[#46661](https://github.com/ClickHouse/ClickHouse/pull/46661) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 如果没有插入任何内容，则不要在 `ANY` hash join 中存储块。[#48633](https://github.com/ClickHouse/ClickHouse/pull/48633) ([vdimir](https://github.com/vdimir)).
* 修复了 JIT 编译时 aggregate combinator `-If` 的问题。关闭 [#48120](https://github.com/ClickHouse/ClickHouse/issues/48120)。[#49083](https://github.com/ClickHouse/ClickHouse/pull/49083) ([Igor Nikonov](https://github.com/devcrafter)).
* 对于远程表读取，我们改用更小的任务 (而不是读取整个 part) ，以便 tasks stealing 能够生效 * task size 由待读取 columns 的大小决定 * 从 s3 读取时始终使用 1mb buffers * cache segments 的边界按 1mb 对齐，这样即使任务较小也能保持合理大小，同时也有助于防止碎片化。[#49287](https://github.com/ClickHouse/ClickHouse/pull/49287) ([Nikita Taranov](https://github.com/nickitat)).
* 从本地文件系统读取时，读取缓冲区的默认大小调整为一个略优的值。同时新增了两个设置：`max_read_buffer_size_local_fs` 和 `max_read_buffer_size_remote_fs`。[#49321](https://github.com/ClickHouse/ClickHouse/pull/49321) ([Nikita Taranov](https://github.com/nickitat)).
* 改进了 `SPARSE_HASHED`/`HASHED` 字典的内存使用和速度 (例如，`SPARSE_HASHED` 现在内存占用减少了 2.6 倍，速度约提升 2 倍) 。[#49380](https://github.com/ClickHouse/ClickHouse/pull/49380) ([Azat Khuzhin](https://github.com/azat)).
* 仅在 aggregate projection 读取的粒度少于普通读取时才使用它。这有助于改善查询命中表的 PK、但未命中 projection 的情况。修复 [#49150](https://github.com/ClickHouse/ClickHouse/issues/49150)。[#49417](https://github.com/ClickHouse/ClickHouse/pull/49417) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 优化了 PODArray::resize&#95;fill() 的调用方。[#49459](https://github.com/ClickHouse/ClickHouse/pull/49459) ([Azat Khuzhin](https://github.com/azat)).
* 在适用场景下通过应用 LowCardinality 来优化 system.query&#95;log 和 system.query&#95;thread&#95;log 表。针对这些表的查询会更快。[#49530](https://github.com/ClickHouse/ClickHouse/pull/49530) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 读取本地 Parquet files 时性能更佳 (通过并行读取) 。[#49539](https://github.com/ClickHouse/ClickHouse/pull/49539) ([Michael Kolupaev](https://github.com/al13n321)).
* 在某些场景下，`RIGHT/FULL JOIN` 的性能最高可提升 2 倍，尤其是在连接较小的左表和较大的右表时。[#49585](https://github.com/ClickHouse/ClickHouse/pull/49585) ([lgbo](https://github.com/lgbo-ustc)).
* 通过为 Rust 启用 LTO，BLAKE3 的性能提升了 11%。[#49600](https://github.com/ClickHouse/ClickHouse/pull/49600) ([Azat Khuzhin](https://github.com/azat)).
* 优化 `system.opentelemetry_span_log` 的结构，在合适的地方使用 `LowCardinality`。尽管这个表整体设计得比较糟糕 (即便是常见属性也使用了 `Map` 数据类型) ，但还是会略有改善。[#49647](https://github.com/ClickHouse/ClickHouse/pull/49647) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 尝试为 `grace_hash` join 预留哈希表容量。[#49816](https://github.com/ClickHouse/ClickHouse/pull/49816) ([lgbo](https://github.com/lgbo-ustc)).
* 正如 issue [#49748](https://github.com/ClickHouse/ClickHouse/issues/49748) 中所述，带有日期转换器的谓词 (例如 **toYear, toYYYYMM**) 可以在 AST 层改写为等价的日期 (YYYY-MM-DD) 比较。这种转换能够带来性能提升，因为它避开了开销较高的日期转换器，而日期之间的比较 (或底层表示中的整数比较) 成本相当低。[prototype](https://github.com/ZhiguoZh/ClickHouse/commit/c7f1753f0c9363a19d95fa46f1cfed1d9f505ee0) 显示，在优化所有已识别的日期转换器后，这 13 个查询在 ICX 服务器 (Intel Xeon Platinum 8380 CPU，80 核，160 线程) 上的整体 QPS 提升了 **~11%**。[#50062](https://github.com/ClickHouse/ClickHouse/pull/50062) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 支持并行合并 `uniqExactIf` 状态。关闭 [#49885](https://github.com/ClickHouse/ClickHouse/issues/49885)。[#50285](https://github.com/ClickHouse/ClickHouse/pull/50285) ([flynn](https://github.com/ucasfl)).
* 正如 issue [#49748](https://github.com/ClickHouse/ClickHouse/issues/49748) 中所述，带有日期转换器的谓词 (例如 toYear、toYYYYMM) 可以在 AST 层改写为等价的日期 (YYYY-MM-DD) 比较。这种转换能够带来性能提升，因为它避开了开销较高的日期转换器，而日期之间的比较 (或底层表示中的整数比较) 成本相当低。[#50307](https://github.com/ClickHouse/ClickHouse/pull/50307) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* `uniqExact` 在使用 `-Array`、`-Merge`、`-OrNull`、`-State` 修饰符时支持并行合并。[#50413](https://github.com/ClickHouse/ClickHouse/pull/50413) ([flynn](https://github.com/ucasfl)).
* 为 Arm LZ4 启用 LZ4&#95;FAST&#95;DEC&#95;LOOP，以将解压速度提升 5%。[#50588](https://github.com/ClickHouse/ClickHouse/pull/50588) ([Daniel Kutenin](https://github.com/danlark1)).
