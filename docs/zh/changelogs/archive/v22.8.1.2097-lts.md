<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 使 cache 支持组合使用，允许某些文件 (如 idx、mrk 等) 不被驱逐，并删除旧版 cache。现在可以在 Azure Blob 存储 disk、本地 disk、StaticWeb disk 等之上配置 cache。此 PR 被标记为向后不兼容，因为 cache 配置已发生变化，要让 cache 正常工作，需要更新配置文件。旧 cache 在新配置下仍会继续使用。服务器在旧 cache 配置下仍可正常启动。关闭了 [#36140](https://github.com/ClickHouse/ClickHouse/issues/36140)。关闭了 [#37889](https://github.com/ClickHouse/ClickHouse/issues/37889)。[#36171](https://github.com/ClickHouse/ClickHouse/pull/36171) ([Kseniia Sumarokova](https://github.com/kssenii)) 。
* 现在，所有相关的字典源都遵循 `remote_url_allow_hosts` 设置。此前 HTTP、Cassandra、Redis 已支持该设置，现已新增 ClickHouse、MongoDB、MySQL、PostgreSQL。仅对通过 DDL 创建的字典检查 host。[#39184](https://github.com/ClickHouse/ClickHouse/pull/39184) ([Nikolai Kochetov](https://github.com/KochetovNicolai)) 。
* 扩展了 Date32 和 DateTime64 的范围，使其支持 1900 年到 2299 年的日期。此前版本仅支持 1925 年到 2283 年。该实现采用前推公历 (符合 [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601):2004 (clause 3.2.1 The Gregorian calendar) ) ，而不是考虑从儒略历到公历的历史切换。这一变更会影响超出范围参数的特定实现行为。例如，在之前的版本中，`1899-01-01` 会被钳制为 `1925-01-01`，而在新版本中会被钳制为 `1900-01-01`。如果向 `toStartOfInterval` 传入 `INTERVAL 3 QUARTER`，其舍入行为也会发生变化，最多可能相差一个季度，因为这些时间间隔是从某个特定于实现的时间点开始计算的。关闭了 [#28216](https://github.com/ClickHouse/ClickHouse/issues/28216)，改进了 [#38393](https://github.com/ClickHouse/ClickHouse/issues/38393)。[#39425](https://github.com/ClickHouse/ClickHouse/pull/39425) ([Roman Vasin](https://github.com/rvasin)) 。



<div id="new-feature">
  #### 新特性
</div>

* 新增设置 `exact_rows_before_limit` (0/1)。启用后，ClickHouse 将为 `rows_before_limit_at_least` 统计信息提供精确值，但代价是必须完整读取 limit 之前的数据。此更改关闭了 [#6613](https://github.com/ClickHouse/ClickHouse/issues/6613)。 [#25333](https://github.com/ClickHouse/ClickHouse/pull/25333) ([kevin wan](https://github.com/MaxWk)).
* 为 uncompressed cache 和 marks cache 新增 SLRU cache policy。 [#34651](https://github.com/ClickHouse/ClickHouse/pull/34651) ([alexX512](https://github.com/alexX512)).
* Intel® In-Memory Analytics Accelerator (Intel® IAA) 是即将推出的新一代 Intel® Xeon® Scalable 处理器 (&quot;Sapphire Rapids&quot;) 中提供的一种硬件加速器。其目标是加速 analytics 中的常见操作，例如数据 (解) 压缩和筛选。ClickHouse 新增了 &quot;DeflateQpl&quot; 压缩 codec，它利用 Intel® IAA 卸载技术提供高性能的 DEFLATE 实现。该 codec 使用了 [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl)，对硬件加速器的访问进行了抽象；如果硬件加速器不可用，则会回退到软件实现。总体而言，DEFLATE 通常比 ClickHouse 默认的 LZ4 codec 提供更高的压缩率，因此可减少磁盘 I/O 并降低主内存占用。 [#36654](https://github.com/ClickHouse/ClickHouse/pull/36654) ([jasperzhu](https://github.com/jinjunzh)).
* 新增 concurrent&#95;threads&#95;soft&#95;limit 参数，通过限制所有查询的线程总数，在高 RPS 场景下提升性能。 [#37285](https://github.com/ClickHouse/ClickHouse/pull/37285) ([Roman Vasin](https://github.com/rvasin)).
* 新增并发控制逻辑，用于限制查询创建的并发线程总数。 [#37558](https://github.com/ClickHouse/ClickHouse/pull/37558) ([Sergei Trifonov](https://github.com/serxa)).
* 新增支持对使用 Distributed 和 Replicated 引擎的表执行并行 distributed insert select。 [#34670](https://github.com/ClickHouse/ClickHouse/issues/34670). [#39107](https://github.com/ClickHouse/ClickHouse/pull/39107) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 新增设置以控制从文本 formats 进行 schema 推断： - `input_format_try_infer_dates` - 尝试从字符串推断日期。 - `input_format_try_infer_datetimes` - 尝试从字符串推断日期时间。 - `input_format_try_infer_integers` - 尝试推断为 `Int64` 而不是 `Float64`。 - `input_format_json_try_infer_numbers_from_strings` - 尝试在 JSON formats 中从 json strings 推断数值。 [#39186](https://github.com/ClickHouse/ClickHouse/pull/39186) ([Kruglov Pavel](https://github.com/Avogar)).
* 此功能将在控制台中提供 JSON 格式的日志输出，目的是让在日志分析工具中进行摄取和查询更加便捷。 [#39277](https://github.com/ClickHouse/ClickHouse/pull/39277) ([Mallik Hassan](https://github.com/SadiHassan)).
* Intel® In-Memory Analytics Accelerator (Intel® IAA) 是即将推出的新一代 Intel® Xeon® Scalable 处理器 (&quot;Sapphire Rapids&quot;) 中提供的一种硬件加速器。其目标是加速 analytics 中的常见操作，例如数据 (解) 压缩和筛选。ClickHouse 新增了 &quot;DeflateQpl&quot; 压缩 codec，它利用 Intel® IAA 卸载技术提供高性能的 DEFLATE 实现。该 codec 使用了 [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl)，对硬件加速器的访问进行了抽象；如果硬件加速器不可用，则会回退到软件实现。总体而言，DEFLATE 通常比 ClickHouse 默认的 LZ4 codec 提供更高的压缩率，因此可减少磁盘 I/O 并降低主内存占用。 [#39494](https://github.com/ClickHouse/ClickHouse/pull/39494) ([Robert Schulze](https://github.com/rschu1ze)).
* 添加了函数 `nowInBlock`，可在长时间运行和持续执行的查询期间获取当前时间。关闭 [#39522](https://github.com/ClickHouse/ClickHouse/issues/39522)。注意：没有 `now64InBlock` 或 `todayInBlock` 函数。[#39533](https://github.com/ClickHouse/ClickHouse/pull/39533) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* * 在进度报告 (`X-ClickHouse-Summary`) 中添加 result&#95;rows 和 result&#95;bytes。[#39567](https://github.com/ClickHouse/ClickHouse/pull/39567) ([Raúl Marín](https://github.com/Algunenano)) 。
* 新增了为 `executable()` 表函数指定设置的功能。[#39681](https://github.com/ClickHouse/ClickHouse/pull/39681) ([Constantine Peresypkin](https://github.com/pkit)) 。
* 实现了将数据库引擎从 `Ordinary` 自动转换为 `Atomic`。在 `flags` 目录中创建空的 `convert_ordinary_to_atomic` 文件后，所有 `Ordinary` 数据库都会在 server 下次启动时自动完成转换。修复了 [#39546](https://github.com/ClickHouse/ClickHouse/issues/39546)。[#39933](https://github.com/ClickHouse/ClickHouse/pull/39933) ([Alexander Tokmakov](https://github.com/tavplubix)) 。
* 新增设置 `schema_inference_hints`，允许在 schema inference 中为特定列指定结构提示。关闭了 [#39569](https://github.com/ClickHouse/ClickHouse/issues/39569)。[#40068](https://github.com/ClickHouse/ClickHouse/pull/40068) ([Kruglov Pavel](https://github.com/Avogar)) 。



<div id="performance-improvement">
  #### 性能提升
</div>

* * 修复了复杂查询在执行 analyze 时卡住的问题。[#38185](https://github.com/ClickHouse/ClickHouse/pull/38185) ([Vladimir C](https://github.com/vdimir)).
* 可根据输入流的排序描述推导排序方式。如果输入流已经有序，则跳过排序。[#38719](https://github.com/ClickHouse/ClickHouse/pull/38719) ([Igor Nikonov](https://github.com/devcrafter)).
* 当 `DISTINCT` 列与 `ORDER BY` 列匹配 (或构成其前缀) 时，`DISTINCT` 配合 `ORDER BY` 使用可显著改善内存占用和查询执行时间。[#39432](https://github.com/ClickHouse/ClickHouse/pull/39432) ([Igor Nikonov](https://github.com/devcrafter)).
* 在执行 `cluster` 及类似表函数时，优先使用本地节点获取远程表的结构。[#39440](https://github.com/ClickHouse/ClickHouse/pull/39440) ([Mingliang Pan](https://github.com/liangliangpan)).
* 仅当排序描述适用于 DISTINCT 列时才使用 `DistinctSortedTransform`，否则回退到普通的 DISTINCT 实现。这样可以减少 `DistinctSortedTransform` 执行期间的检查次数。[#39528](https://github.com/ClickHouse/ClickHouse/pull/39528) ([Igor Nikonov](https://github.com/devcrafter)).
* `DistinctSortedTransform` 之前未能利用排序特性，也就是说，它的工作方式与普通 `DISTINCT` 实现相同。该修复可显著降低内存占用。[#39538](https://github.com/ClickHouse/ClickHouse/pull/39538) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector：使用 AVX512VBMI2 compress store 优化过滤操作。[#39633](https://github.com/ClickHouse/ClickHouse/pull/39633) ([Guo Wangyang](https://github.com/guowangy)).
* KeyCondition：优化多线程场景下的 applyFunction。[#39812](https://github.com/ClickHouse/ClickHouse/pull/39812) ([Guo Wangyang](https://github.com/guowangy)).
* 对于支持 AVX512 VBMI2 的系统，此 PR 可将 SSB 基准测试中查询 3.1、3.2 和 3.3 (SF=100) 的性能提升约 6%。测试环境为双路 Intel Icelake Xeon 8380。[#40033](https://github.com/ClickHouse/ClickHouse/pull/40033) ([Robert Schulze](https://github.com/rschu1ze)).
* * 如果未注册任何 UDF，则不再遍历 UDF 的 AST。[#40069](https://github.com/ClickHouse/ClickHouse/pull/40069) ([Raúl Marín](https://github.com/Algunenano)).
* * 优化 CurrentMemoryTracker 的 alloc 和 free。[#40078](https://github.com/ClickHouse/ClickHouse/pull/40078) ([Raúl Marín](https://github.com/Algunenano)).
