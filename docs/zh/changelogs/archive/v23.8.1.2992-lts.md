<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 弃用 metadata cache 功能。该功能处于 Experimental 状态，且我们从未使用过它。这个功能存在风险：[#51182](https://github.com/ClickHouse/ClickHouse/issues/51182)。移除 `system.merge_tree_metadata_cache` 系统表。metadata cache 在此版本中仍可用，但很快会被移除。此项变更关闭了 [#39197](https://github.com/ClickHouse/ClickHouse/issues/39197)。[#51303](https://github.com/ClickHouse/ClickHouse/pull/51303) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 如果动态 disk 包含名称，则应在 disk 函数 argument 中将其指定为 `disk = disk(name = 'disk_name'`, ...)。在之前的版本中，可以写成 `disk = disk_<disk_name>(...)`，但现已不再支持。[#52820](https://github.com/ClickHouse/ClickHouse/pull/52820) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 当以大于 1 的 `--concurrency` 调用时，`clickhouse-benchmark` 将并行建立 connections。此前，如果从欧洲到美国运行 1000 个并发 connections，它几乎不可用。现已修正高 latency connections 的 QPS 计算。向后不兼容的变更：`clickhouse-benchmark` 的 JSON 输出选项已被移除。如果你之前使用过该选项，作为替代方案，也可以从 `system.query_log` 中以 JSON format 提取数据。[#53293](https://github.com/ClickHouse/ClickHouse/pull/53293) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 由于在已有 `event_time_microseconds` 列的情况下它们属于冗余字段，`system.text_log` 中的 `microseconds` 列已被移除，`system.metric_log` 中的 `milliseconds` 列也已被移除。[#53601](https://github.com/ClickHouse/ClickHouse/pull/53601) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 已更改存储 `S3Queue` metadata 的 ZooKeeper 路径。[#54137](https://github.com/ClickHouse/ClickHouse/pull/54137) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 为 AArch64、PowerPC、SystemZ、RISCV 启用 JIT 编译。[#38217](https://github.com/ClickHouse/ClickHouse/pull/38217) ([Maksim Kita](https://github.com/kitaisreal)).
* 此补丁提供了一种在 merge 之前并行处理所有 hashset 的方法。[#50748](https://github.com/ClickHouse/ClickHouse/pull/50748) ([Jiebin Sun](https://github.com/jiebinn)).
* 优化使用 aggregationmethodserialized 时 Nullable String 键的 aggregation 性能。[#51399](https://github.com/ClickHouse/ClickHouse/pull/51399) ([LiuNeng](https://github.com/liuneng1994)).
* 在 ICX 设备 (Intel Xeon Platinum 8380 CPU，80 核，160 线程) 上进行的 **SSB** 性能实验表明，启用 Experimental analyzer 后，此变更可将 **geomean QPS** 提升 **8.5%**。详细信息如下：![image](https://github.com/ClickHouse/ClickHouse/assets/26588299/4e58bf8b-d276-408d-ad45-38c82d3cb918)。[#52091](https://github.com/ClickHouse/ClickHouse/pull/52091) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* Parquet 过滤器下推。也就是说，读取 Parquet 文件时，会根据 WHERE 条件以及各列的最小/最大值跳过某些行组 (文件中的数据块) 。特别是，如果文件大致按某一列排序，那么按该列的一个较小范围进行过滤的查询会快得多。[#52951](https://github.com/ClickHouse/ClickHouse/pull/52951) ([Michael Kolupaev](https://github.com/al13n321)).
* 如果 UniqExactSet 中所有 hashSet 都是 singleLevel，则优化 merge。[#52973](https://github.com/ClickHouse/ClickHouse/pull/52973) ([Jiebin Sun](https://github.com/jiebinn)).
* StorageJoin：不要使用所有列创建克隆的 hash join。[#53046](https://github.com/ClickHouse/ClickHouse/pull/53046) ([Duc Canh Le](https://github.com/canhld94)).
* 在 Parquet 中通过批量处理较小的行组来优化读取。关闭 [#53069](https://github.com/ClickHouse/ClickHouse/issues/53069)。[#53281](https://github.com/ClickHouse/ClickHouse/pull/53281) ([Kruglov Pavel](https://github.com/Avogar)).
* 实现不依赖 Arrow 的原生 ORC 输入格式以提升性能。[#53324](https://github.com/ClickHouse/ClickHouse/pull/53324) ([李扬](https://github.com/taiyang-li)).
* 仪表板将通知服务器对数据进行压缩，这对于在较慢的互联网连接上传输大时间范围的数据很有帮助。例如，一个包含 86400 个点的图表，未压缩时可达 1.5 MB，而使用 `br` 压缩后仅为 60 KB。[#53569](https://github.com/ClickHouse/ClickHouse/pull/53569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 优化大多数输入格式中对文件执行 count 的性能。关闭 [#44334](https://github.com/ClickHouse/ClickHouse/issues/44334)。[#53637](https://github.com/ClickHouse/ClickHouse/pull/53637) ([Kruglov Pavel](https://github.com/Avogar)).
* 更高效地利用用于 BACKUPs&amp;RESTOREs 的线程池。[#53649](https://github.com/ClickHouse/ClickHouse/pull/53649) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 移除无用的客户端性能慢速检查。[#53695](https://github.com/ClickHouse/ClickHouse/pull/53695) ([Raúl Marín](https://github.com/Algunenano)).
