<div id="backward-incompatible-change">
  #### 不兼容的变更
</div>

* 从默认 Prometheus handler 中移除 `status_info` 配置项和字典状态。 [#54090](https://github.com/ClickHouse/ClickHouse/pull/54090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 已从代码库中移除 Experimental 的 parts 元数据缓存。 [#54215](https://github.com/ClickHouse/ClickHouse/pull/54215) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 默认禁用设置 `input_format_json_try_infer_numbers_from_strings`，因此默认情况下不再尝试在 JSON 格式中从字符串推断数值，以避免当样本数据包含看起来像数字的字符串时出现潜在的解析错误。 [#55099](https://github.com/ClickHouse/ClickHouse/pull/55099) ([Kruglov Pavel](https://github.com/Avogar)).
* 2023 年 3 月之前创建的 IPv6 布隆过滤器索引与当前版本不兼容，必须重新构建。 [#54200](https://github.com/ClickHouse/ClickHouse/pull/54200) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).



<div id="new-feature">
  #### 新特性
</div>

* 新增了基于 SSH key 的新型身份验证方式。它仅适用于 Native TCP protocol。[#41109](https://github.com/ClickHouse/ClickHouse/pull/41109) ([George Gamezardashvili](https://github.com/InfJoker)) 。
* 新增了对远程 disk 的 IO Scheduling 支持。`s3`、`s3_plain`、`hdfs` 和 `azure_blob_storage` 这些 disk type 的 Storage configuration 现在可以包含 `read_resource` 和 `write_resource` 元素，用于保存 resource 名称。这些 resource 的 scheduling policies 可在独立的 server configuration 章节 `resources` 中配置。还可以使用 setting `workload` 为查询打标，并通过 server configuration 章节 `workload_classifiers` 对其分类，以实现不同的 resource scheduling 目标。更多详情请参见 docs/en/operations/workload-scheduling.md。[#47009](https://github.com/ClickHouse/ClickHouse/pull/47009) ([Sergei Trifonov](https://github.com/serxa)) 。
* 新增了一列 &#95;block&#95;number，解决了 [#44532](https://github.com/ClickHouse/ClickHouse/issues/44532)。[#47532](https://github.com/ClickHouse/ClickHouse/pull/47532) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)) 。
* 新增选项 `partial_result_update_duration_ms` 和 `max_rows_in_partial_result`，可在查询执行期间实时显示输出表部分结果的更新。[#48607](https://github.com/ClickHouse/ClickHouse/pull/48607) ([Alexey Perevyshin](https://github.com/alexX512)) 。
* RegExpTree 字典现已支持不区分大小写和 dot-all 匹配模式。[#50906](https://github.com/ClickHouse/ClickHouse/pull/50906) ([Johann Gan](https://github.com/johanngan)) 。
* 新增对 `ALTER TABLE MODIFY COMMENT` 的支持。注意：很久以前曾有外部 contributor 添加过类似功能，但该 feature 实际上完全不可用，反而只会让用户感到困惑。此更改关闭了 [#36377](https://github.com/ClickHouse/ClickHouse/issues/36377)。[#51304](https://github.com/ClickHouse/ClickHouse/pull/51304) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 新增了 &quot;GCD&quot; (即 &quot;greatest common denominator&quot;) 这一新的数据压缩 codec。该 codec 会计算所有列值的 GCD，然后将每个值除以该 GCD。GCD codec 是一种数据预处理 codec (类似 Delta 和 DoubleDelta) ，不能单独使用。它适用于整数、小数以及日期/时间类型的数据。GCD codec 的一个可行用例是列值按 GCD 的倍数变化 (增加/减少) ，例如 24 - 28 - 16 - 24 - 8 - 24 (假设 GCD = 4) 。[#53149](https://github.com/ClickHouse/ClickHouse/pull/53149) ([Alexander Nam](https://github.com/seshWCS)) 。
* 新增了两个 type aliases：&quot;DECIMAL(P)&quot; (作为 &quot;DECIMAL(P, 0&quot; 的简写) 和 &quot;DECIMAL&quot; (作为 &quot;DECIMAL(10, 0)&quot; 的简写) 。这让 ClickHouse 与 MySQL 的 SQL dialect 更加兼容。[#53328](https://github.com/ClickHouse/ClickHouse/pull/53328) ([Val Doroshchuk](https://github.com/valbok)) 。
* 新增了一个 system log 表 `backup_log`，用于跟踪所有 `BACKUP` 和 `RESTORE` 操作。[#53638](https://github.com/ClickHouse/ClickHouse/pull/53638) ([Victor Krasnov](https://github.com/sirvickr)) 。
* 新增了一个 format setting &quot;output&#95;format&#95;markdown&#95;escape&#95;special&#95;characters&quot; (默认值：false) 。该 setting 用于控制在 &quot;Markdown&quot; output format 中，是否对诸如 &quot;!&quot;、&quot;#&quot;、&quot;$&quot; 等特殊字符进行转义 (即在前面加上反斜杠) 。[#53860](https://github.com/ClickHouse/ClickHouse/pull/53860) ([irenjj](https://github.com/irenjj)) 。
* 新增函数 `decodeHTMLComponent`。[#54097](https://github.com/ClickHouse/ClickHouse/pull/54097) ([Bharat Nallan](https://github.com/bharatnc)) 。
* 在 query&#95;log 表中添加了 peak&#95;threads&#95;usage。 [#54335](https://github.com/ClickHouse/ClickHouse/pull/54335) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* 为 ClickHouse 客户端添加了 SHOW FUNCTIONS 支持。 [#54337](https://github.com/ClickHouse/ClickHouse/pull/54337) ([Julia Kartseva](https://github.com/wat-ze-hex)).
* 此 PR 改进了从 JSON 格式进行 schema 推断的能力：1) 现在可以在 JSON 格式中通过设置 `input_format_json_try_infer_named_tuples_from_objects`，在不使用实验性 JSON type 的情况下从 JSON object 推断命名元组。此前，如果没有实验性 JSON type，我们只能将 JSON object 推断为 String 或 Map，现在则可以推断为命名元组。生成的 Tuple type 将包含 schema 推断期间数据样本中读取到的对象的所有键。这对于读取不含稀疏对象的结构化 JSON 数据很有帮助。该设置默认启用。2) 允许通过设置 `input_format_json_read_arrays_as_strings` 将 JSON array 解析到类型为 String 的列中。这有助于读取包含不同类型值的数组。3) 允许在样本数据中的 JSON 键具有未知类型 (`null`/`[]`/`{}`) 时，通过设置 `input_format_json_infer_incomplete_types_as_strings` 使用 String 类型。现在，在 JSON 格式中我们可以将任意值读入 String 列，并且可以通过对未知类型使用 String，避免在 schema 推断期间出现错误 `Cannot determine type for column 'column_name' by first 25000 rows of data, most likely this column contains only Nulls or empty Arrays/Maps`，从而成功读取数据。 [#54427](https://github.com/ClickHouse/ClickHouse/pull/54427) ([Kruglov Pavel](https://github.com/Avogar)).
* 添加了函数 &quot;toDaysSinceYearZero&quot; 及其别名 &quot;TO&#95;DAYS()&quot; (用于兼容 MySQL) ，该函数返回自 0001-01-01 以来经过的天数。 [#54479](https://github.com/ClickHouse/ClickHouse/pull/54479) ([Robert Schulze](https://github.com/rschu1ze)).
* 添加了函数 YYYYMMDDtoDate()、YYYYMMDDtoDate32()、YYYYMMDDhhmmssToDateTime() 和 YYYYMMDDhhmmssToDateTime64()。它们将编码为整数的日期或日期时间 (例如 20230911) 转换为原生日期或日期时间。因此，它们提供了与现有函数 YYYYMMDDToDate()、YYYYMMDDToDateTime()、YYYYMMDDhhmmddToDateTime()、YYYYMMDDhhmmddToDateTime64() 相反的功能。 [#54509](https://github.com/ClickHouse/ClickHouse/pull/54509) ([Robert Schulze](https://github.com/rschu1ze)).
* 添加了 &quot;bandwidth&#95;limit&quot; IO 调度节点类型。它允许对经过该节点的流量指定 `max_speed` 和 `max_burst` 约束。更多详情请参见 docs/en/operations/workload-scheduling.md。 [#54618](https://github.com/ClickHouse/ClickHouse/pull/54618) ([Sergei Trifonov](https://github.com/serxa)).
* 函数 `toDaysSinceYearZero()` 现在支持 `DateTime` 和 `DateTime64` 类型的参数。 [#54856](https://github.com/ClickHouse/ClickHouse/pull/54856) ([Serge Klochkov](https://github.com/slvrtrn)).
* 允许在表函数 `s3`、`gcs`、`oss` 中使用 S3 风格的 URL。URL 会自动转换为 HTTP。例如：`'s3://clickhouse-public-datasets/hits.csv'` 会被转换为 `'https://clickhouse-public-datasets.s3.amazonaws.com/hits.csv'`。 [#54931](https://github.com/ClickHouse/ClickHouse/pull/54931) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 添加了多个字符串距离函数，包括 `byteHammingDistance`、`byteJaccardIndex`、`byteEditDistance`。### 面向用户变更的文档条目。 [#54935](https://github.com/ClickHouse/ClickHouse/pull/54935) ([flynn](https://github.com/ucasfl)).
* 添加新设置 `print_pretty_type_names`，用于以更美观的方式显示深层嵌套类型名称，例如 Tuple/Map/Array。[#55095](https://github.com/ClickHouse/ClickHouse/pull/55095) ([Kruglov Pavel](https://github.com/Avogar)) 。



<div id="performance-improvement">

* 提升 Decimal 列的排序性能；当 ORDER BY 包含 Decimal 列时，提升向 MergeTree 插入数据的性能；在数据已排序或接近有序时，提升排序性能。[#35961](https://github.com/ClickHouse/ClickHouse/pull/35961) ([Maksim Kita](https://github.com/kitaisreal)).
* 提升超大查询的查询分析性能。修复 [#51224](https://github.com/ClickHouse/ClickHouse/issues/51224)。[#51469](https://github.com/ClickHouse/ClickHouse/pull/51469) ([frinkr](https://github.com/frinkr)).
* 1. 为新的 analyzer 添加 rewriter。[#52082](https://github.com/ClickHouse/ClickHouse/pull/52082) ([JackyWoo](https://github.com/JackyWoo)).
* 1. 为旧版和新版 analyzer 都添加 rewriter。2. 添加设置 `optimize_uniq_to_count`。[#52645](https://github.com/ClickHouse/ClickHouse/pull/52645) ([JackyWoo](https://github.com/JackyWoo)).
* 移除对 `mmap/mremap/munmap` 的手动调用，并将这些工作全部交给 `jemalloc`。[#52792](https://github.com/ClickHouse/ClickHouse/pull/52792) ([Nikita Taranov](https://github.com/nickitat)).
* 现在会在序列化前优化 roaringBitmaps。[#52842](https://github.com/ClickHouse/ClickHouse/pull/52842) ([UnamedRus](https://github.com/UnamedRus)).
* 优化按常量键进行 group by。在 https://github.com/ClickHouse/ClickHouse/pull/53529 之后，将优化按 `_file/_path` group by 的查询。[#53549](https://github.com/ClickHouse/ClickHouse/pull/53549) ([Kruglov Pavel](https://github.com/Avogar)).
* 默认启用预取，以加快从 S3 读取数据的速度。[#53709](https://github.com/ClickHouse/ClickHouse/pull/53709) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 在不必要时，不再隐式读取孤立 parts 中的 pk 和版本列。[#53919](https://github.com/ClickHouse/ClickHouse/pull/53919) ([Duc Canh Le](https://github.com/canhld94)).
* 修复了使用 NATS 时 CPU 占用过高的问题。[#54399](https://github.com/ClickHouse/ClickHouse/pull/54399) ([Vasilev Pyotr](https://github.com/vahpetr)).
* 由于对带有 datetime 参数的 `toString()` 执行使用了单独的指令，因此可以小幅提升非 datetime 参数的性能，并让部分代码更简洁。这是对 [#53680](https://github.com/ClickHouse/ClickHouse/issues/53680) 的后续改进。[#54443](https://github.com/ClickHouse/ClickHouse/pull/54443) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 此 PR 不再将 json 元素序列化到 `std::stringstream` 中，而是尝试将序列化结果直接写入 `ColumnString`。[#54613](https://github.com/ClickHouse/ClickHouse/pull/54613) ([lgbo](https://github.com/lgbo-ustc)).
* 当表位于视图之后时，启用 ORDER BY 优化，以便从 MergeTree 表中按对应顺序读取数据。[#54628](https://github.com/ClickHouse/ClickHouse/pull/54628) ([Vitaly Baranov](https://github.com/vitlibar)).
* 通过复用 `GeneratorJSONPath` 改进 JSON SQL 函数。由于 `GenerateorJSONPath` 的构造函数中有多个 `make_shared` 调用，性能较差。[#54735](https://github.com/ClickHouse/ClickHouse/pull/54735) ([lgbo](https://github.com/lgbo-ustc)).



<div id="improvement">

* 添加设置 `ignore_access_denied_multidirectory_globs`。[#52839](https://github.com/ClickHouse/ClickHouse/pull/52839) ([Andrey Zvonov](https://github.com/zvonand)).
* 在 HTTP 查询执行期间发生异常时，输出有效的 JSON/XML。添加设置 `http_write_exception_in_output_format` 以启用/禁用此行为 (默认启用) 。[#52853](https://github.com/ClickHouse/ClickHouse/pull/52853) ([Kruglov Pavel](https://github.com/Avogar)).
* Integer 类型推断更加精确，修复了 [#51236](https://github.com/ClickHouse/ClickHouse/issues/51236)。[#53003](https://github.com/ClickHouse/ClickHouse/pull/53003) ([Chen768959](https://github.com/Chen768959)).
* Keeper 会尝试将 flush 请求按批次处理，以提升性能。[#53049](https://github.com/ClickHouse/ClickHouse/pull/53049) ([Antonio Andelic](https://github.com/antonio2368)).
* 为 MaterializedMySQL 中的字符串字面量引入了字符集解析。[#53220](https://github.com/ClickHouse/ClickHouse/pull/53220) ([Val Doroshchuk](https://github.com/valbok)).
* 修复了一个极罕见场景下、较少使用的 `EmbeddedRocksDB` 表引擎中的细微问题：有时 `EmbeddedRocksDB` 表引擎在执行 `DROP TABLE` 后，无法在 NFS 上正确关闭文件。[#53502](https://github.com/ClickHouse/ClickHouse/pull/53502) ([Mingliang Pan](https://github.com/liangliangpan)).
* SQL 函数 &quot;toString(datetime)&quot; 和 &quot;formatDateTime()&quot; 现在支持非常量时区参数。[#53680](https://github.com/ClickHouse/ClickHouse/pull/53680) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* `RESTORE TABLE ON CLUSTER` 必须在各主机上创建 UUID 匹配的复制表。否则，ZooKeeper 路径中的宏 `{uuid}` 在 RESTORE 后将无法正常工作。此 PR 实现了这一点。[#53765](https://github.com/ClickHouse/ClickHouse/pull/53765) ([Vitaly Baranov](https://github.com/vitlibar)).
* 新增恢复设置 `restore_broken_parts_as_detached`：如果为 true，RESTORE 过程中遇到损坏的数据分区片段时不会停止，而是会将所有损坏的数据分区片段复制到 `detached` 文件夹中，并加上前缀 &#96;broken-from-backup&#39;。如果为 false，RESTORE 进程会在遇到第一个损坏的数据分区片段时停止 (如果有) 。默认值为 false。[#53877](https://github.com/ClickHouse/ClickHouse/pull/53877) ([Vitaly Baranov](https://github.com/vitlibar)).
* 现在可以使用设置 `max_threads_for_annoy_index_creation` 并行创建 Annoy 索引。[#54047](https://github.com/ClickHouse/ClickHouse/pull/54047) ([Robert Schulze](https://github.com/rschu1ze)).
* MySQL interface 新增了对预处理语句的基础实现，刚好足以让 Tableau Online 通过 MySQL connector 连接到 ClickHouse。 [#54115](https://github.com/ClickHouse/ClickHouse/pull/54115) ([Serge Klochkov](https://github.com/slvrtrn)).
* 将用于处理 (编码/解码) base64 值的库从 Turbo-Base64 替换为 aklomp-base64。两者都在 x86 和 ARM 上支持 SIMD 加速，但 1. 后者的许可证 (BSD-2) 对 ClickHouse 更友好，而 Turbo64 这期间已切换到 GPL-3；2. aklomp-base64 在 GitHub 上 star 更多，看起来更具长期可持续性；3. aklomp-base64 的 API 略好一些 (当然这多少有些主观) ；4. aklomp-base64 不需要我们通过变通方式绕过 bug (例如非线程安全的初始化) 。注意：aklomp-base64 会拒绝未填充的 base64 值，而 Turbo-Base64 会尽力解码它们。RFC-4648 并未明确填充是否为强制要求，但在某些上下文中，这可能是一个需要注意的行为变化。 [#54119](https://github.com/ClickHouse/ClickHouse/pull/54119) ([Mikhail Koviazin](https://github.com/mkmkme)).
* 为 HTTP 请求头 X-ClickHouse-Progress 和 X-ClickHouse-Summary 添加 elapsed&#95;ns。 [#54179](https://github.com/ClickHouse/ClickHouse/pull/54179) ([joelynch](https://github.com/joelynch)).
* 为 keeper-client 实现了 `reconfig` (https://github.com/ClickHouse/ClickHouse/pull/49450)、`sync` 和 `exists` 命令。 [#54201](https://github.com/ClickHouse/ClickHouse/pull/54201) ([pufit](https://github.com/pufit)).
* &quot;clickhouse-local&quot; 和 &quot;clickhouse-client&quot; 现在允许多次指定 &quot;--query&quot; 参数，例如 &#39;./clickhouse-client --query &quot;SELECT 1&quot; --query &quot;SELECT 2&quot;&#39;。这种语法比 &#96;./clickhouse-client --multiquery &quot;SELECT 1;SELECT2&quot; 略微更直观，也更便于编写脚本 (例如 &quot;queries.push&#95;back(&#39;--query &quot;$q&quot;&#39;)&quot;) ，并且与现有参数 &quot;--queries-file&quot; 的行为更一致 (例如 &quot;./clickhouse client --queries-file queries1.sql --queries-file queries2.sql&quot;) 。 [#54249](https://github.com/ClickHouse/ClickHouse/pull/54249) ([Robert Schulze](https://github.com/rschu1ze)).
* 为 `formatReadableTimeDelta` 添加子秒级精度支持。 [#54250](https://github.com/ClickHouse/ClickHouse/pull/54250) ([Andrey Zvonov](https://github.com/zvonand)).
* 修复 HashedArrayDictionary: 中错误的重新分配问题。 [#54254](https://github.com/ClickHouse/ClickHouse/pull/54254) ([Vitaly Baranov](https://github.com/vitlibar)).
* 默认启用 allow&#95;remove&#95;stale&#95;moving&#95;parts。 [#54260](https://github.com/ClickHouse/ClickHouse/pull/54260) ([vdimir](https://github.com/vdimir)).
