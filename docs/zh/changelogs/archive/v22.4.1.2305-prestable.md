<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 函数 `yandexConsistentHash` (Konstantin &quot;kostik&quot; Oblakov 的一致性哈希算法) 已重命名为 `kostikConsistentHash`。旧名称作为兼容性的别名保留。尽管此更改向后兼容，但我们可能会在后续发行版中移除该别名，因此建议你在应用程序中更新对此函数的用法。 [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 不允许在 INSERT 查询中于 FORMAT 之后使用 SETTINGS (有一个兼容性设置 `allow_settings_after_format_in_insert` 可接受此类查询，但默认处于关闭状态) 。 [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* 更改了缓存文件的哈希路径。 [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 加快 MergeTree 的 parts 加载过程，以加速 clickhouse-server 启动。通过这项改进，在拥有 70 万个 MergeTree parts 的情况下，clickhouse-server 可将启动时间从 75 分钟缩短到 20 秒。[#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* 现在会收集聚合过程中使用的哈希表大小，并将其用于后续查询，以避免哈希表扩容。[#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* 对 ASOF join 性能进行了多项优化 (提速 1.2 - 1.6 倍) 。此外还增加了对大整数的支持。[#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* 如果端点支持 HTTP Range，URL 存储引擎现在会并行下载多个数据块。新增了两个设置：`max_download_threads` 和 `max_download_buffer_size`，分别用于控制单个查询下载文件时可使用的最大线程数，以及每个线程可处理的最大字节数。[#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* 实现了向 S3 storage 进行分段上传的并行化。[#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* 当键为原生整数类型时，提升 ASOF JOIN 的性能。[#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* 新增一项查询计划优化：在可能的情况下，将函数计算推迟到 `ORDER BY` 之后。比如，对于查询 `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5`，函数 `sipHash64` 会在 `ORDER BY` 和 `LIMIT` 之后再计算，从而带来约 20 倍提速。[#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* 缩小 mutex 的作用范围，以解决 setenv LIBHDFS3&#95;CONF 相关问题 [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292)。[#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* 使用针对 SSE 和 AVX2 的特化实现来提升 `hasAll` 函数的性能。作者 @youennL-cs。[#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * 对两个分布式表执行 GLOBAL JOIN 时，EXPLAIN 语句可提速 100 倍：explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2 项优化：- 优化 trivial count hive 查询 - 通过缓存 hive 文件的元数据来加速 hive 查询。[#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
