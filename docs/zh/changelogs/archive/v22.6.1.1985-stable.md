<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* 调整了以 `seconds` 为类型的设置项的解析方式，以支持浮点值 (例如：`max_execution_time=0.5`) 。Infinity 或 NaN 值会抛出异常。[#37187](https://github.com/ClickHouse/ClickHouse/pull/37187) ([Raúl Marín](https://github.com/Algunenano)).
* 更改了实验性 `Object` 类型列的二进制序列化格式。新格式更便于第三方客户端实现。[#37482](https://github.com/ClickHouse/ClickHouse/pull/37482) ([Anton Popov](https://github.com/CurtizJ)).
* 默认启用设置 `output_format_json_named_tuples_as_objects`。它允许在 JSON 格式中将命名元组序列化为 JSON 对象。[#37756](https://github.com/ClickHouse/ClickHouse/pull/37756) ([Anton Popov](https://github.com/CurtizJ)).

<div id="performance-improvement">
  #### 性能提升
</div>

* 在 ORDER BY 中包含多个列时，提升向 MergeTree 执行 insert 的性能。[#35762](https://github.com/ClickHouse/ClickHouse/pull/35762) ([Maksim Kita](https://github.com/kitaisreal)).
* 为 StorageHive 应用 &#39;threadpool&#39; 读取方法。[#36328](https://github.com/ClickHouse/ClickHouse/pull/36328) ([李扬](https://github.com/taiyang-li)).
* 现在会将数据分区片段拆分为多个 layer，并在线程间分配这些 layer，而不是分配整个 parts，从而让带有 `FINAL` 的查询执行具备更好的数据并行性。[#36396](https://github.com/ClickHouse/ClickHouse/pull/36396) ([Nikita Taranov](https://github.com/nickitat)).
* 读取 wide parts 时，只加载必要列的标记。[#36879](https://github.com/ClickHouse/ClickHouse/pull/36879) ([Anton Kozlov](https://github.com/tonickkozlov)).
* 当待读取的所有列都是分区键时，可根据文件的行号构造列，而无需实际读取 hive 文件。[#37103](https://github.com/ClickHouse/ClickHouse/pull/37103) ([lgbo](https://github.com/lgbo-ustc)).
* 修复 `dictGetDescendants` 和 `dictGetChildren` 函数的性能问题：临时的父子层级索引按查询创建，而不是在查询过程中每次函数调用时都创建。还允许为 `HIERARHICAL` 属性指定 `BIDIRECTIONAL`，这样字典会在内存中维护父到子的索引，因此 `dictGetDescendants` 和 `dictGetChildren` 函数将不再为每个查询创建临时索引。关闭 [#32481](https://github.com/ClickHouse/ClickHouse/issues/32481)。[#37148](https://github.com/ClickHouse/ClickHouse/pull/37148) ([Maksim Kita](https://github.com/kitaisreal)).
* 提升从 Native、Protobuf、CapnProto、JSONEachRow、TSKV 以及所有带 WithNames/WithNamesAndTypes 后缀的格式中选择部分列时的性能并降低内存占用。此前，从这些格式的文件中只选择部分列时，仍会读取所有列并将其存储在内存中。现在只会读取所需列。此 PR 还默认启用设置 `input_format_skip_unknown_fields`，否则在只选择部分列时会抛出异常。[#37192](https://github.com/ClickHouse/ClickHouse/pull/37192) ([Kruglov Pavel](https://github.com/Avogar)).
* 提升按单列排序的性能。[#37195](https://github.com/ClickHouse/ClickHouse/pull/37195) ([Maksim Kita](https://github.com/kitaisreal)).
* 支持使用多 disks 缓存 hive 文件。[#37279](https://github.com/ClickHouse/ClickHouse/pull/37279) ([lgbo](https://github.com/lgbo-ustc)).
* 将数组范数和距离函数的性能提升了 2 到 4 倍。[#37394](https://github.com/ClickHouse/ClickHouse/pull/37394) ([Alexander Gololobov](https://github.com/davenger)).
* 使用动态分发提升数值比较函数的性能。[#37399](https://github.com/ClickHouse/ClickHouse/pull/37399) ([Maksim Kita](https://github.com/kitaisreal)).
* 提升带 LIMIT 的 ORDER BY 性能。[#37481](https://github.com/ClickHouse/ClickHouse/pull/37481) ([Maksim Kita](https://github.com/kitaisreal)).
* 使用动态分发基础设施提升 `hasAll` 函数的性能。[#37484](https://github.com/ClickHouse/ClickHouse/pull/37484) ([Maksim Kita](https://github.com/kitaisreal)).
* 提升 `greatCircleAngle`、`greatCircleDistance` 和 `geoDistance` 函数的性能。[#37524](https://github.com/ClickHouse/ClickHouse/pull/37524) ([Maksim Kita](https://github.com/kitaisreal)).
* 优化了 re2 pattern 的内部缓存，例如 LIKE 和 MATCH 函数中使用的 pattern。[#37544](https://github.com/ClickHouse/ClickHouse/pull/37544) ([Robert Schulze](https://github.com/rschu1ze)).
* 使用 avx512 指令整体优化过滤器位掩码生成器函数的性能。[#37588](https://github.com/ClickHouse/ClickHouse/pull/37588) ([yaqi-zhao](https://github.com/yaqi-zhao)).
* 改进了在将稀疏列 (可通过 `MergeTree` 表中的 Experimental 设置 `ratio_of_defaults_for_sparse_serialization` 启用) 用作聚合函数参数时的聚合性能。[#37617](https://github.com/ClickHouse/ClickHouse/pull/37617) ([Anton Popov](https://github.com/CurtizJ)).
* 优化了具有两个参数的函数 `COALESCE`。[#37666](https://github.com/ClickHouse/ClickHouse/pull/37666) ([Anton Popov](https://github.com/CurtizJ)).
* 当 `multiIf` 只有一个条件时，将其替换为 `if`，因为 `if` 函数性能更高。[#37695](https://github.com/ClickHouse/ClickHouse/pull/37695) ([Anton Popov](https://github.com/CurtizJ)).
* 现在聚合状态的析构可以提交到线程池中处理。对于带 LIMIT 且状态较大的查询，这能显著提速，例如 `select uniq(number) from numbers_mt(1e7) group by number limit 100` 现在大约快了 2.5 倍。[#37855](https://github.com/ClickHouse/ClickHouse/pull/37855) ([Nikita Taranov](https://github.com/nickitat)).
* 使用排序队列特化改进了单列排序性能。[#37990](https://github.com/ClickHouse/ClickHouse/pull/37990) ([Maksim Kita](https://github.com/kitaisreal)).
* 修复了在表数量很多时后台 CPU 使用率过高的问题。[#38028](https://github.com/ClickHouse/ClickHouse/pull/38028) ([Maksim Kita](https://github.com/kitaisreal)).
* 通过动态分派提升了 `not` 函数的性能。[#38058](https://github.com/ClickHouse/ClickHouse/pull/38058) ([Maksim Kita](https://github.com/kitaisreal)).
* 为主要库新增了大量 NEON 加速路径。[#38093](https://github.com/ClickHouse/ClickHouse/pull/38093) ([Daniel Kutenin](https://github.com/danlark1)).





<div id="improvement">
  #### Improvement
</div>

* 添加单独的 CLUSTER grant (以及 `access_control_improvements.on_cluster_queries_require_cluster_grant` 配置指令；出于向后兼容性考虑，默认值为 `false`) 。[#35767](https://github.com/ClickHouse/ClickHouse/pull/35767) ([Azat Khuzhin](https://github.com/azat)).
* 添加自解压可执行程序 [#34755](https://github.com/ClickHouse/ClickHouse/issues/34755)。[#35775](https://github.com/ClickHouse/ClickHouse/pull/35775) ([Filatenkov Artur](https://github.com/FArthur-cmd)).
* 为 `hdfsCluster` 添加了 schema inference 支持。[#35812](https://github.com/ClickHouse/ClickHouse/pull/35812) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 添加 `disks` 功能 (`ls` - 列出磁盘上的文件，`C` - 设置配置文件，`list-disks` - 列出磁盘名称，`disk` - 按名称设置要操作的磁盘，`help` - 输出帮助信息，`copy` - 将磁盘上 `from_path` 的数据复制到 `to_path`，`link` - 在磁盘上从 `from_path` 到 `to_path` 创建硬链接，`list` - 列出磁盘上的文件，`move` - 将磁盘上的文件或目录从 `from_path` 移动到 `to_path`，`read` - 将磁盘上的文件 `from_path` 读取到 `to_path` 或 stdout，`remove` - 删除磁盘上的文件或目录及其所有子节点，`write` - 将磁盘上的文件 `from_path` 或 stdin 写入 `to_path`) 。[#36060](https://github.com/ClickHouse/ClickHouse/pull/36060) ([Artyom Yurkov](https://github.com/Varinara)).
* 为 volume 内的 disks (多磁盘配置) 实现 `least_used` 负载均衡算法。[#36686](https://github.com/ClickHouse/ClickHouse/pull/36686) ([Azat Khuzhin](https://github.com/azat)).
* * 修改 HTTP 端点，使其在 `send_progress_in_http_headers=0` 时通过 `X-ClickHouse-Summary` 请求头返回完整的统计信息 (此前会返回全零) 。- 修改 HTTP 端点，使其在此前已发送过进度信息时 (`send_progress_in_http_headers=1`) 返回 `X-ClickHouse-Exception-Code` 请求头 - 修改 HTTP 端点，使其在出现 `TIMEOUT_EXCEEDED` 错误时返回 `HTTP_REQUEST_TIMEOUT` (408)，而不是 `HTTP_INTERNAL_SERVER_ERROR` (500)。[#36884](https://github.com/ClickHouse/ClickHouse/pull/36884) ([Raúl Marín](https://github.com/Algunenano)).
* 允许用户查看已授予角色的授权。[#36941](https://github.com/ClickHouse/ClickHouse/pull/36941) ([nvartolomei](https://github.com/nvartolomei)).
* 不再通过数值方法计算积分，改为使用 CDF 函数。这将提升执行速度并提高精度。此修复解决了 [#36714](https://github.com/ClickHouse/ClickHouse/issues/36714)。[#36953](https://github.com/ClickHouse/ClickHouse/pull/36953) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 为函数中的 Nothing 添加默认实现。现在，大多数函数在某个参数为 Nothing 时，会返回类型为 Nothing 的列。这也解决了 arrayMap/arrayFilter 等函数在参数为空数组时的问题。此前，像 `select arrayMap(x -> 2 * x, []);` 这样的查询会失败，因为 lambda 表达式内部的函数无法处理 `Nothing` 类型；现在，这类查询会返回类型为 `Array(Nothing)` 的空数组。此外，还为 arrayFilter/arrayFill 等函数增加了对 Nullable 类型数组的支持。此前，像 `select arrayFilter(x -> x % 2, [1, NULL])` 这样的查询会失败，现在已可正常工作 (如果 lambda 表达式的结果为 NULL，则该值不会包含在结果中) 。解决了 [#37000](https://github.com/ClickHouse/ClickHouse/issues/37000)。[#37048](https://github.com/ClickHouse/ClickHouse/pull/37048) ([Kruglov Pavel](https://github.com/Avogar)).
* 现在，如果某个分片有本地副本，我们会创建一个本地执行计划，以及一个从所有远程副本读取的执行计划。它们共享同一个发起节点来协调读取。[#37204](https://github.com/ClickHouse/ClickHouse/pull/37204) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 在函数：CompressedWriteBuffer::nextImpl() 中，存在一个不必要的写时复制步骤，在插入数据时会频繁发生。下面展示了此 patch 带来的区别：- 之前：1. 将 &quot;working&#95;buffer&quot; 压缩到 &quot;compressed&#95;buffer&quot; 2. 再复制写入到 &quot;out&quot; - 之后：直接将 &quot;working&#95;buffer&quot; 压缩到 &quot;out&quot;。[#37242](https://github.com/ClickHouse/ClickHouse/pull/37242) ([jasperzhu](https://github.com/jinjunzh)).
* 支持非常量 SQL 函数 (NOT) (I)LIKE 和 MATCH。[#37251](https://github.com/ClickHouse/ClickHouse/pull/37251) ([Robert Schulze](https://github.com/rschu1ze)).
* Client 将依次尝试 DNS 解析返回的每个 IP 地址，直到成功建立连接。[#37273](https://github.com/ClickHouse/ClickHouse/pull/37273) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* * 如果未明确设置配置选项 &quot;mark&#95;cache&#95;size&quot;，将不再中止服务器启动。[#37326](https://github.com/ClickHouse/ClickHouse/pull/37326) ([Robert Schulze](https://github.com/rschu1ze)).
* 允许在 Arrow/Parquet/ORC 格式中使用 String 类型代替 Binary。此 PR 为此引入了 3 个新设置：`output_format_arrow_string_as_string`、`output_format_parquet_string_as_string`、`output_format_orc_string_as_string`。所有设置的默认值均为 `false`。[#37327](https://github.com/ClickHouse/ClickHouse/pull/37327) ([Kruglov Pavel](https://github.com/Avogar)).
* 将设置 `input_format_max_rows_to_read_for_schema_inference` 应用于通配符匹配到的所有文件的总读取行数。此前，设置 `input_format_max_rows_to_read_for_schema_inference` 是对 glob 中的每个文件分别应用的，因此在存在大量 NULL 值的情况下，可能会从每个文件中读取前 `input_format_max_rows_to_read_for_schema_inference` 行却仍然得不到结果。同时将此设置的默认值提高到 25000。[#37332](https://github.com/ClickHouse/ClickHouse/pull/37332) ([Kruglov Pavel](https://github.com/Avogar)).
* 允许在列声明中紧跟类型之后指定 `NULL`/`NOT NULL`。[#37337](https://github.com/ClickHouse/ClickHouse/pull/37337) ([Igor Nikonov](https://github.com/devcrafter)).
* 优化 file segment PARTIALLY&#95;DOWNLOADED 获取读取缓冲区的过程。[#37338](https://github.com/ClickHouse/ClickHouse/pull/37338) ([chen](https://github.com/xiedeyantu)).
* 允许在从 S3 读取时，通过 `_file` 和 `_path` 等虚拟列裁剪文件列表。这是为 [#37174](https://github.com/ClickHouse/ClickHouse/issues/37174) 和 [#23494](https://github.com/ClickHouse/ClickHouse/issues/23494) 提供支持。[#37356](https://github.com/ClickHouse/ClickHouse/pull/37356) ([Amos Bird](https://github.com/amosbird)).
* 尝试改进短路函数的处理，以修复压力测试中的问题。[#37384](https://github.com/ClickHouse/ClickHouse/pull/37384) ([Kruglov Pavel](https://github.com/Avogar)).

* play UI：页面水平滚动时保持控件位置不变。这样即使表很宽并且已经向右滚动很远，编辑操作仍然会更方便。该功能由 CaspianDB 的 Maksym Tereshchenko 提出。[#37470](https://github.com/ClickHouse/ClickHouse/pull/37470) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
