  ### ClickHouse 发布版本 v24.8.1.2684-长期支持版 (161c62fd295) FIXME，相较于 v24.8.1.1-new (3f8b27d7acc)

<div id="backward-incompatible-change">
  #### 向后不兼容的变更
</div>

* `clickhouse-client` 和 `clickhouse-local` 现在默认使用多查询模式 (而非单查询模式) 。例如，`clickhouse-client -q "SELECT 1; SELECT 2"` 现在可以正常工作，而此前用户必须添加 `--multiquery` (或 `-n`) 。`--multiquery/-n` 开关现已废弃。多查询语句中的 INSERT 查询会根据其 FORMAT clause 进行特殊处理：如果 FORMAT 是 `VALUES` (最常见的情况) ，则 INSERT 语句以查询末尾的分号 `;` 作为结束标记。对于所有其他 FORMAT (例如 `CSV` 或 `JSONEachRow`) ，INSERT 语句以查询末尾的两个换行符 `\n\n` 作为结束标记。[#63898](https://github.com/ClickHouse/ClickHouse/pull/63898) ([FFish](https://github.com/wxybear)) 。
* 在之前的版本中，可以通过在 Data type 名称后追加 `WithDictionary` 来使用 `LowCardinality` Data type 的另一种语法。这只是一个早期可用的实现，从未写入文档，也从未对外公开。现在，它已弃用。如果你使用过这种语法，则必须 ALTER 你的表，并将相关 Data type 重命名为 `LowCardinality`。[#66842](https://github.com/ClickHouse/ClickHouse/pull/66842) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 修复了将存储 `Buffer` 与分布式目标表一起使用时的逻辑错误。这是一项向后不兼容的变更：如果某张表在同一查询中出现多次 (例如在 self-join 中) ，那么使用 `Buffer` 且目标表为分布式表的查询可能会停止工作。[#67015](https://github.com/ClickHouse/ClickHouse/pull/67015) ([vdimir](https://github.com/vdimir)) 。
* 在之前的版本中，使用接近零的负 argument 调用基于伽马函数的随机分布函数 (例如 Chi-Squared、Student、Fisher) 会导致计算时间过长或陷入无限循环。在新版本中，使用零或负 argument 调用这些函数将抛出 Exception。这解决了 [#67297](https://github.com/ClickHouse/ClickHouse/issues/67297)。[#67326](https://github.com/ClickHouse/ClickHouse/pull/67326) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 系统表 `text_log` 现已默认启用。这与之前的版本完全兼容，但你可能会注意到本地磁盘的磁盘使用量略有增加 (该系统表只会占用极少量磁盘空间) 。[#67428](https://github.com/ClickHouse/ClickHouse/pull/67428) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 在之前的版本中，如果要求 `arrayWithConstant` 生成非常大的数组，可能会很慢。在新版本中，每个数组的大小被限制为 1 GB。这解决了 [#32754](https://github.com/ClickHouse/ClickHouse/issues/32754)。[#67741](https://github.com/ClickHouse/ClickHouse/pull/67741) ([Alexey Milovidov](https://github.com/alexey-milovidov)) 。
* 修复了 REPLACE modifier 的格式要求 (禁止省略括号) 。[#67774](https://github.com/ClickHouse/ClickHouse/pull/67774) ([Azat Khuzhin](https://github.com/azat)) 。
* 已在 [#68349](https://github.com/ClickHouse/ClickHouse/issues/68349) 中回移：重新实现 Dynamic 类型。现在，当动态 Data type 数量达到上限后，新类型不会再被转换为 String，而是以二进制编码的 Data type 信息，按 binary format 存储在一种特殊的数据结构中。现在，任何曾写入 Dynamic 列的类型，都可以作为 subcolumn 从中读取。[#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Kruglov Pavel](https://github.com/Avogar)) 。

<div id="new-feature">
  #### 新特性
</div>

* 新增实验性的 Kafka 存储引擎，用于将 offsets 存储在 Keeper 中，而不再依赖将其提交到 Kafka。 [#57625](https://github.com/ClickHouse/ClickHouse/pull/57625) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 新增 TimeSeries 表引擎：- 默认方式：`CREATE TABLE tbl ENGINE=TimeSeries` - 或者可指定其内部表所使用的引擎。. [#64183](https://github.com/ClickHouse/ClickHouse/pull/64183) ([Vitaly Baranov](https://github.com/vitlibar)).
* 支持在涉及左右表列的不等条件下使用更多 join strictness (`LEFT/RIGHT SEMI/ANTI/ANY JOIN`) ，例如 t1.y &lt; t2.y (参见 setting `allow_experimental_join_condition`) 。 [#64281](https://github.com/ClickHouse/ClickHouse/pull/64281) ([lgbo](https://github.com/lgbo-ustc)).
* 为 S3 表引擎 新增 `_etag` virtual column。修复了 [#65312](https://github.com/ClickHouse/ClickHouse/issues/65312)。 [#65386](https://github.com/ClickHouse/ClickHouse/pull/65386) ([skyoct](https://github.com/skyoct)).
* 此拉取请求为不同引擎 (`File`、`URL`、`S3`、`AzureBlobStorage`、`HDFS`) 引入了 Hive-style partitioning。Hive-style partitioning 会将数据组织到分区子目录中，从而提高对大型数据集的查询和管理效率。目前，它仅创建具有相应名称和数据的 virtual columns。后续 PR 将引入相应的数据筛选 (性能提升) 。 [#65997](https://github.com/ClickHouse/ClickHouse/pull/65997) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 为兼容 spark 新增函数 printf。 [#66257](https://github.com/ClickHouse/ClickHouse/pull/66257) ([李扬](https://github.com/taiyang-li)).
* 已在 [#68450](https://github.com/ClickHouse/ClickHouse/issues/68450) 中回移：实现新的 JSON data type。 [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Kruglov Pavel](https://github.com/Avogar)).
* 新增一个 server setting：disable&#95;insertion&#95;and&#95;mutation。将其设为 true 后，该节点将拒绝所有 insertions 和 mutations (Alter table delete/update/drop partition) ，包括 async insertion。 [#66519](https://github.com/ClickHouse/ClickHouse/pull/66519) ([Xu Jia](https://github.com/XuJia0210)).
* 新增选项 `restore_replace_external_engines_to_null` 和 `restore_replace_external_table_functions_to_null`，用于将 external engines 和 table&#95;engines 替换为 Null engine，这对测试很有帮助。它应适用于 RESTORE 和显式创建表。 [#66536](https://github.com/ClickHouse/ClickHouse/pull/66536) ([Ilya Yatsishin](https://github.com/qoega)).
* 新增支持使用函数 readWKTLineString 读取 WKT 格式的 MULTILINESTRING Geometry。 [#67647](https://github.com/ClickHouse/ClickHouse/pull/67647) ([Jacob Reckhard](https://github.com/jacobrec)).
* 新增一个 table function `fuzzQuery`。该函数允许通过随机变化修改给定的 query string。Example：`SELECT query FROM fuzzQuery('SELECT 1') LIMIT 5;`。 [#67655](https://github.com/ClickHouse/ClickHouse/pull/67655) ([pufit](https://github.com/pufit)).
* 支持查询 `DROP DETACHED PARTITION ALL`，以删除所有 detached partitions。 [#67885](https://github.com/ClickHouse/ClickHouse/pull/67885) ([Duc Canh Le](https://github.com/canhld94)).
* 为 query cache 新增了标签 (命名空间) 机制。带有不同标签的相同查询在 query cache 中会被视为不同查询。例如：`SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'abc'` 和 `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'def'` 现在会创建不同的 query cache entries。 [#68235](https://github.com/ClickHouse/ClickHouse/pull/68235) ([sakulali](https://github.com/sakulali)).

* 对并行副本采用自适应读取任务大小计算方法 (“自适应”表示其取决于读取列的大小) 。[#60377](https://github.com/ClickHouse/ClickHouse/pull/60377) ([Nikita Taranov](https://github.com/nickitat)).
* 将 `plain_rewritable` 磁盘目录的元数据以 `__meta` 布局存储，并与对象存储中的 MergeTree 数据分离。将 `plain_rewritable` 磁盘调整为扁平目录结构。[#65751](https://github.com/ClickHouse/ClickHouse/pull/65751) ([Julia Kartseva](https://github.com/jkartseva)).
* 默认启用 `compile_expressions` (用于普通 expressions 片段的 JIT compiler) 。此更改解决了 [#51264](https://github.com/ClickHouse/ClickHouse/issues/51264) 和 [#56386](https://github.com/ClickHouse/ClickHouse/issues/56386)。[#66486](https://github.com/ClickHouse/ClickHouse/pull/66486) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 通过为所有 subcolumns 预先分配所需内存，改进 String/Array/Map/Variant/Dynamic 类型的列压缩。[#67043](https://github.com/ClickHouse/ClickHouse/pull/67043) ([Kruglov Pavel](https://github.com/Avogar)).
* 加快系统 flush 日志的速度，并在关闭时 flush 日志。[#67472](https://github.com/ClickHouse/ClickHouse/pull/67472) ([Sema Checherinda](https://github.com/CheSema)).
* 已在 [#68496](https://github.com/ClickHouse/ClickHouse/issues/68496) 中回移：通过减少 merges 调度步骤的开销，提升 merges 的整体性能。[#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* 设置 `optimize_functions_to_subcolumns` 默认已启用。[#68053](https://github.com/ClickHouse/ClickHouse/pull/68053) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### 改进
</div>

* ClickHouse server 现已支持新设置 `max_keep_alive_requests`。对于与 server 建立的 keep-alive HTTP 连接，该设置会与 `keep_alive_timeout` 协同工作：如果空闲超时尚未到期，但某个连接上已完成的 requests 数超过 `max_keep_alive_requests`，该连接将被 server 关闭。[#61793](https://github.com/ClickHouse/ClickHouse/pull/61793) ([Nikita Taranov](https://github.com/nickitat)).
* 由于新版本中会基于表引擎逻辑检查 SOURCES，即使 grant 表引擎默认处于禁用状态，如果某个 source 未被授予权限，反而会弹出表引擎提示，这会造成误导。[#65419](https://github.com/ClickHouse/ClickHouse/pull/65419) ([jsc0218](https://github.com/jsc0218)).
* 新增统计类型 `count_min` (count-min sketch) ，可为 `col = 'val'` 这类等值 predicates 提供选择性估算。支持的数据类型包括 string、date、datetime 和数值类型。[#65521](https://github.com/ClickHouse/ClickHouse/pull/65521) ([JackyWoo](https://github.com/JackyWoo)).
* 不再在镜像中显式传递 keeper 的日志，以便支持覆盖。[#65564](https://github.com/ClickHouse/ClickHouse/pull/65564) ([Azat Khuzhin](https://github.com/azat)).
* 在 `clickhouse-local` 中默认使用 `Atomic` database。解决了 [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647) 中的第 1 和第 5 项问题。关闭 [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817)。[#65860](https://github.com/ClickHouse/ClickHouse/pull/65860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 当启用 `rows_before_aggregation` 时，会将统计信息 `rows_before_aggregation_at_least` 添加到查询响应中。该统计信息表示 aggregation 之前读取的行数。在 distributed query 场景下，使用 `group by` 或 `max` 聚合函数且不带 `limit` 时，`rows_before_aggregation_at_least` 可以反映该查询命中的行数。[#66084](https://github.com/ClickHouse/ClickHouse/pull/66084) ([morning-color](https://github.com/morning-color)).
* 为 `BACKUP` 和 `RESTORE` 查询引入了 `use_same_password_for_base_backup` 设置，从而支持创建和恢复存储于受密码保护归档中的 incremental backups。[#66214](https://github.com/ClickHouse/ClickHouse/pull/66214) ([Samuele](https://github.com/sguerrini97)).
* 对 ATTACH 查询忽略 async&#95;load&#95;databases (此前 ATTACH 可能会在表尚未 attached 时就返回) 。[#66240](https://github.com/ClickHouse/ClickHouse/pull/66240) ([Azat Khuzhin](https://github.com/azat)).
* [Replicated]MergeTreeSink 必须在 `onCancel()` method 中正确取消其 delayed&#95;chunk。[#66279](https://github.com/ClickHouse/ClickHouse/pull/66279) ([Sema Checherinda](https://github.com/CheSema)).
* 为被拒绝连接数 (即资源不足时) 新增了日志和指标。[#66410](https://github.com/ClickHouse/ClickHouse/pull/66410) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 设置 `allow_experimental_analyzer` 已重命名为 `enable_analyzer`。旧名称会以别名形式保留。[#66438](https://github.com/ClickHouse/ClickHouse/pull/66438) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* MongoDB engine 现已支持真正的 UUID 类型。[#66671](https://github.com/ClickHouse/ClickHouse/pull/66671) ([Azat Khuzhin](https://github.com/azat)).
* 新增 `MergeTree` 设置 `deduplicate_merge_projection_mode`，用于在合并期间 (针对特定引擎) 以及 `OPTIMIZE DEDUPLICATE` 查询中控制 projections。支持的选项包括：`throw` (如果 projection 尚未被 *MergeTree engine 完整支持，则抛出异常) 、`drop` (如果 projection 自身无法以一致方式合并，则在合并期间移除 projection) 和 `rebuild` (从头重建 projection，这是一项开销较大的操作) 。 [#66672](https://github.com/ClickHouse/ClickHouse/pull/66672) ([jsc0218](https://github.com/jsc0218)).
* 新增复制延迟和恢复时间指标。[#66703](https://github.com/ClickHouse/ClickHouse/pull/66703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 新增 S3DiskNoKeyErrors 指标。[#66704](https://github.com/ClickHouse/ClickHouse/pull/66704) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 确保 COMMENT 子句适用于所有表引擎。[#66832](https://github.com/ClickHouse/ClickHouse/pull/66832) ([Joe Lynch](https://github.com/joelynch)).
* 在适当情况下，将错误码 `BAD_ARGUMENTS` 和 `ILLEGAL_TYPE_OF_ARGUMENT` 替换为更准确的错误码。[#66851](https://github.com/ClickHouse/ClickHouse/pull/66851) ([Yohann Jardin](https://github.com/yohannj)).
* 函数 `mapFromArrays` 现在接受 `Map(K, V)` 作为第一个参数，例如：`SELECT mapFromArrays(map('a', 4, 'b', 4), ['aa', 'bb'])` 现在可以正常工作，并返回 `{('a',4):'aa',('b',4):'bb'}`。此外，如果第一个参数是 Array，现在也可以是 `Array(Nullable(T))` 或 `Array(LowCardinality(Nullable(T)))` 类型，只要数组中的实际值不是 `NULL`。[#67103](https://github.com/ClickHouse/ClickHouse/pull/67103) ([李扬](https://github.com/taiyang-li)).
* clickhouse-local 现在会从 ~/.clickhouse-local 读取配置。[#67135](https://github.com/ClickHouse/ClickHouse/pull/67135) ([Azat Khuzhin](https://github.com/azat)).
* 将设置 `input_format_orc_read_use_writer_time_zone` 重命名为 `input_format_orc_reader_timezone`，并允许用户设置 reader 时区。[#67175](https://github.com/ClickHouse/ClickHouse/pull/67175) ([kevinyhzou](https://github.com/KevinyhZou)).
* 当 HTTP connection 在建立后立即被对端重置时，降低 &#39;Socket is not connected&#39; 错误的级别，关闭 [#34218](https://github.com/ClickHouse/ClickHouse/issues/34218)。[#67177](https://github.com/ClickHouse/ClickHouse/pull/67177) ([vdimir](https://github.com/vdimir)).
* 加快 `DROP DATABASE` 查询删除表的速度，将 `database_catalog_drop_table_concurrency` 的默认值提高到 16。[#67228](https://github.com/ClickHouse/ClickHouse/pull/67228) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 新增可从 config 为 system.dashboards 加载仪表盘的能力 (设置后会覆盖默认的仪表盘预设) 。[#67232](https://github.com/ClickHouse/ClickHouse/pull/67232) ([Azat Khuzhin](https://github.com/azat)).
* SQL 中的 window functions 传统上使用 snake case。ClickHouse 使用 camelCase，因此新增了别名 `denseRank()` 和 `percentRank()`。这些新函数的调用方式与原始的 `dense_rank()` 和 `percent_rank()` 函数完全相同。snake case 和 camelCase 两种语法仍然都可用。此外，还分别为这两个函数新增了测试。这关闭了 [#67042](https://github.com/ClickHouse/ClickHouse/issues/67042) 。[#67334](https://github.com/ClickHouse/ClickHouse/pull/67334) ([Peter Nguyen](https://github.com/petern48)).
* 如果配置文件格式不是 `.xml`、`.yml` 或 `.yaml`，则自动检测其格式。如果文件以 `&lt;` 开头，则可能是 XML，否则可能是 YAML。对于非普通文件 (如 PIPE: /dev/fd/X) ，则直接按 XML 解析。[#67391](https://github.com/ClickHouse/ClickHouse/pull/67391) ([sakulali](https://github.com/sakulali)).
* 函数 `formatDateTime` 和 `formatDateTimeInJodaSyntax` 现在将其 format 参数设为可选。如果未指定，则默认使用格式字符串 `%Y-%m-%d %H:%i:%s` 和 `yyyy-MM-dd HH:mm:ss`。示例：`SELECT parseDateTime('2021-01-04 23:12:34')` 现在会返回日期时间值 `2021-01-04 23:12:34` (此前会抛出异常) 。[#67399](https://github.com/ClickHouse/ClickHouse/pull/67399) ([Robert Schulze](https://github.com/rschu1ze)).
* 在 KeeperMap 中，如果 Keeper request 因超时或连接丢失而失败，现在会自动重试。[#67448](https://github.com/ClickHouse/ClickHouse/pull/67448) ([Antonio Andelic](https://github.com/antonio2368)).
* 重构了自定义表磁盘的使用方式。[#67684](https://github.com/ClickHouse/ClickHouse/pull/67684) ([Sema Checherinda](https://github.com/CheSema)).
* 对高级仪表板进行了多项改进。此更改关闭了 [#67697](https://github.com/ClickHouse/ClickHouse/issues/67697)。此更改关闭了 [#63407](https://github.com/ClickHouse/ClickHouse/issues/63407)。此更改关闭了 [#51129](https://github.com/ClickHouse/ClickHouse/issues/51129)。此更改关闭了 [#61204](https://github.com/ClickHouse/ClickHouse/issues/61204)。[#67701](https://github.com/ClickHouse/ClickHouse/pull/67701) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 在写入 orc 时，避免为数组列分配过多容量，并进行了一些小幅重构，使代码更整洁。数组列的性能提升了 15%。[#67879](https://github.com/ClickHouse/ClickHouse/pull/67879) ([李扬](https://github.com/taiyang-li)).
* 支持在 Join 表引擎上执行 OPTIMIZE 查询，以降低 Join 表的内存占用。[#67883](https://github.com/ClickHouse/ClickHouse/pull/67883) ([Duc Canh Le](https://github.com/canhld94)).
* 新增复制延迟和恢复时间指标。[#67913](https://github.com/ClickHouse/ClickHouse/pull/67913) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 在 aarch64 Linux 构建中添加 `-no-pie`，以便在 ClickHouse 重启后正确进行内部信息检查并对 stacktraces 执行符号化。[#67916](https://github.com/ClickHouse/ClickHouse/pull/67916) ([filimonov](https://github.com/filimonov)).
* 已在 [#68481](https://github.com/ClickHouse/ClickHouse/issues/68481) 中回移：为 merges 和 mutations 添加了 profile events，以便更好地进行内部信息分析。[#68015](https://github.com/ClickHouse/ClickHouse/pull/68015) ([Anton Popov](https://github.com/CurtizJ)).
* 修复了异步 BACKUP/RESTORE 在 system.processes 中的 settings/current&#95;database 问题。[#68163](https://github.com/ClickHouse/ClickHouse/pull/68163) ([Azat Khuzhin](https://github.com/azat)).
* 移除了不支持复制的 MergeTree 的不必要日志。[#68238](https://github.com/ClickHouse/ClickHouse/pull/68238) ([Daniil Ivanik](https://github.com/divanik)).
* 已在 [#68430](https://github.com/ClickHouse/ClickHouse/issues/68430) 中回移：改进了日期时间的 schema 推断。现在仅当日期时间包含小数部分时才使用 DateTime64，否则使用常规 DateTime。现在对 Date/DateTime 的推断也更加严格，尤其是在 `date_time_input_format='best_effort'` 时，以避免在边界情况下从字符串中推断出日期时间。[#68382](https://github.com/ClickHouse/ClickHouse/pull/68382) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="bug-fix-user-visible-misbehavior-in-an-official-stable-release">
  #### 缺陷修复 (官方稳定版本中用户可见的异常表现)
</div>

* 修复了在使用子查询进行筛选时，某些系统表中出现的 `Not-ready Set` 问题。[#66018](https://github.com/ClickHouse/ClickHouse/pull/66018) ([Michael Kolupaev](https://github.com/al13n321)).
