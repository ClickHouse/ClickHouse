## 描述 {#description}

用于读取和写入 [Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/) 文件的格式。

该格式会从 `deletion-vector-v1` 二进制大对象中提取已删除行的位置。按照 Puffin 规范的要求，其他类型的二进制大对象 (例如 `apache-datasketches-theta-v1`) 会被跳过；如需查看这些对象，请使用 `PuffinMetadata`。
如果一个 puffin 文件包含多个 `deletion-vector-v1` 二进制大对象，该格式会为每个此类二进制大对象输出一行。

固定输出列：

* `referenced_data_file` (`String`) - 删除向量所作用的数据文件的位置 (即二进制大对象的 `referenced-data-file` 属性) 
* `deleted_rows` (`Array(UInt64)`) - 根据删除向量的 roaring bitmap 得出的已删除行位置 (64 位) 

用作输出格式时，输入必须包含与该格式读取时所生成的相同两列：被引用的数据文件 (`String` 或 `LowCardinality(String)`) 以及已删除行的位置 (整数，每行一个位置；或整数数组) 。文件中每个不同的被引用数据文件对应一个 `deletion-vector-v1` 二进制大对象，并按数据文件位置排序，因此包含多个删除向量的 Puffin 文件可以原样复制。被引用数据文件相同的所有行，其位置会合并为一个删除向量，并经过去重和排序；负数位置、超出 Iceberg 删除向量上限的位置以及空的数据文件位置都会被拒绝。二进制大对象元数据的写入方式与 Apache Iceberg 写入删除向量的方式一致：`fields` 为 `[2147483645]` (`_pos` 元数据列的 id) ，`snapshot-id` 和 `sequence-number` 为 `-1`，并设置 `referenced-data-file` 和 `cardinality` 属性。页脚不压缩，因此生成的文件可以作为删除向量删除文件注册到 Iceberg v3 表中，并可被 Apache Spark 等其他引擎读取。对已写入的文件使用 `PuffinMetadata`，即可获取每个二进制大对象的 `offset` 和 `length`，用于填写 manifest 中的 `content_offset` 和 `content_size_in_bytes` 字段。

当设置 `output_format_puffin_blob_type` 为 `apache-datasketches-theta-v1` 时，该格式会改为按照 Apache Iceberg 的方式写入列统计信息：每个输入列都会生成一个 `apache-datasketches-theta-v1` 二进制大对象，其中包含基于该列非 null 值构建的紧凑型 Apache DataSketches Theta sketch (使用默认种子和大小) ，并将 `ndv` 属性设置为估算的不同值数量。值会以该列类型的 Iceberg 单值二进制序列化形式输入 sketch，因此这些 sketch 可以与 Apache Spark 写入的 sketch 合并：`Bool` 对应 `boolean`，`Int8`、`UInt8`、`Int16`、`UInt16` 和 `Int32` 对应 `int`，`UInt32`、`Int64` 和 `UInt64` 对应 `long` (超出 `Int64` 范围的 `UInt64` 值保留原有比特) ，`Float32` 对应 `float`，`Float64` 对应 `double`，`Date` 和 `Date32` 对应 `date`，精度不超过 6 位的 `DateTime` 和 `DateTime64` 对应 `timestamp` (以微秒为单位) ，`String` 对应 `string`，`FixedString` 对应 `fixed`，`UUID` 对应 `uuid`，`Decimal` 对应 `decimal`；这些类型的 `Nullable` 和 `LowCardinality` 形式同样受支持。与 Iceberg 一样，空字符串会被忽略。二进制大对象的 `fields` 取自设置 `output_format_puffin_field_ids`，`snapshot-id` 和 `sequence-number` 分别取自设置 `output_format_puffin_snapshot_id` 和 `output_format_puffin_sequence_number`；这三个设置均为必需，因为读取器会将统计信息关联到它们所指定的列和快照。生成的结果可以注册为 Iceberg 统计信息文件。

请求 `deleted_rows` 时，若删除向量声明的 `cardinality` 超过绝对物化上限，则会被拒绝。页脚中的 `deletion-vector-v1` 属性 (包括 `cardinality` 能否解析为无符号整数) 始终会被校验。仅选择 `referenced_data_file` 时会跳过磁盘上的载荷 I/O，因此也会跳过封装、CRC、roaring 反序列化以及物化上限检查——这是有意为之，以确保仅投影路径时不会读取多达二进制大对象大小上限的数据。

磁盘上的 `deletion-vector-v1` 二进制大对象长度受绝对上限约束 (与 Iceberg 的 2 GiB 内容大小检查保持一致) 。请求 `deleted_rows` 时，读取器会在分配完整载荷之前先探查封装头 (组合长度和 magic) ；CRC 会在有界读取完成后进行校验。

支持 LZ4 压缩和未压缩的 puffin 页脚。在适用情况下，页脚载荷大小 (以及声明的 LZ4 内容大小) 同时受压缩率和绝对上限限制；超大的页脚会在分配前被拒绝。

只能请求部分输出列。在创建该格式时，用户提供的结构若包含不符合预期的列名或类型，将被拒绝。

## 使用示例 {#example-usage}

通过引用的数据文件读取已删除行的位置：

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

将已删除的位置展开为单独的行：

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

使用 `PuffinMetadata` 在读取删除向量前检查页脚 二进制大对象 描述符。

将两个数据文件的删除向量写入同一个 Puffin 文件：

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

将两列的 Theta sketch 写入 Iceberg 统计信息文件：

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
