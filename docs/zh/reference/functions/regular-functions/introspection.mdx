你可以使用本章介绍的函数来查看 [ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format) 和 [DWARF](https://en.wikipedia.org/wiki/DWARF) 的内部信息，以进行查询性能分析。

<Note>
  这些函数速度较慢，并且可能带来安全方面的考虑。
</Note>

要使内部信息函数正常工作：

* 安装 `clickhouse-common-static-dbg` 软件包。

* 将 [allow&#95;introspection&#95;functions](/zh/reference/settings/session-settings/allow#allow_introspection_functions) 设置为 1。

  出于安全原因，默认情况下内部信息函数处于禁用状态。

ClickHouse 会将分析器报告保存到 [trace&#95;log](/zh/reference/system-tables/trace_log) 系统表中。请确保该表和分析器均已正确配置。

## addressToLine {#addressToLine}

引入版本：v20.1.0

将 ClickHouse 主可执行文件中某条指令的地址转换为 ClickHouse 源代码中的文件名和行号。

该地址必须是 ClickHouse 主可执行文件内的偏移量，`system.trace_log`、`system.stack_trace` 和 `system.crash_log` 的 `trace` 列以及 `system.error_log` 的 `last_error_trace` 列中存储的地址即为这种形式。
该函数不接受运行时 (虚拟内存) 地址，因此无法借助它获取服务器进程的内存布局。
主可执行文件之外的栈帧存储为 `0`，函数对这些栈帧返回空结果。

<Note>
  此函数执行较慢，并且可能涉及安全方面的考虑。
</Note>

要启用此内省函数：

* 安装 `clickhouse-common-static-dbg` 软件包。
* 将设置 [`allow_introspection_functions`](/zh/reference/settings/session-settings/allow#allow_introspection_functions) 设为 `1`。

<Note>
  此函数具有非确定性：对于相同参数，它可能返回不同的结果。
</Note>

**语法**

```sql
addressToLine(address_of_binary_instruction)
```

**参数**

* `address_of_binary_instruction` — 指令在 ClickHouse 主可执行文件中的偏移量，即 `system.trace_log` 及类似表的 `trace` 列中存储的值。[`UInt64`](/zh/reference/data-types/int-uint)

**返回值**

返回以冒号分隔的源代码文件名和行号，例如 `/build/obj-x86_64-linux-gnu/../src/Common/ThreadPool.cpp:199`。如果找不到该地址对应的调试信息，则返回二进制文件的名称；如果地址为 `0`，则返回空字符串。[`String`](/zh/reference/data-types/string)

**示例**

```sql title=Query
SET allow_introspection_functions=1;
SELECT * FROM system.trace_log LIMIT 1 FORMAT Vertical;
```

## addressToLineWithInlines {#addressToLineWithInlines}

引入版本：v22.2.0

与 `addressToLine` 类似，但会返回一个包含所有内联函数的 Array。
因此，它比 `addressToLine` 更慢。

该地址必须是 ClickHouse 主可执行文件内的偏移量，即地址在 `system.trace_log`、`system.stack_trace` 和 `system.crash_log` 的 `trace` 列以及 `system.error_log` 的 `last_error_trace` 列中的存储形式。
该函数不接受运行时 (虚拟内存) 地址，因此无法借助它获知服务器进程的内存布局。
主可执行文件之外的栈帧存储为 `0`，对于这些栈帧，该函数返回空结果。

要启用此内省函数：

* 安装 `clickhouse-common-static-dbg` 软件包。
* 将设置 [`allow_introspection_functions`](/zh/reference/settings/session-settings/allow#allow_introspection_functions) 设为 `1`。

<Note>
  此函数为非确定性函数：对于相同的参数，它可能返回不同的结果。
</Note>

**语法**

```sql
addressToLineWithInlines(address_of_binary_instruction)
```

**参数**

* `address_of_binary_instruction` — 指令在 ClickHouse 主可执行文件中的偏移量，即 `system.trace_log` 及类似表的 `trace` 列中存储的值。[`UInt64`](/zh/reference/data-types/int-uint)

**返回值**

返回一个数组：第一个元素是以冒号分隔的源代码文件名和行号；第二、第三等后续元素列出内联函数的源代码文件名、行号和函数名。如果找不到调试信息，则返回仅包含一个元素的数组，该元素为二进制文件名；如果传入 `0`，则返回空数组。[`Array(String)`](/zh/reference/data-types/array)

**示例**

## addressToSymbol {#addressToSymbol}

引入版本：v20.1.0

将 ClickHouse 主可执行文件中某条指令的地址转换为 ClickHouse 目标文件中的符号。

该地址必须是 ClickHouse 主可执行文件内的偏移量，即 `system.trace_log`、`system.stack_trace` 和 `system.crash_log` 的 `trace` 列，以及 `system.error_log` 的 `last_error_trace` 列中存储地址所用的形式。
该函数不接受运行时 (虚拟内存) 地址，以防止其被用于获取服务器进程的内存布局。
主可执行文件之外的栈帧存储为 `0`，函数对这类栈帧返回空结果。

<Note>
  此函数具有非确定性：对于相同参数，它可能返回不同的结果。
</Note>

**语法**

```sql
addressToSymbol(address_of_binary_instruction)
```

* `address_of_binary_instruction` — 指令在 ClickHouse 主可执行文件中的偏移量，即 `system.trace_log` 等表的 `trace` 列中存储的值。[`UInt64`](/zh/reference/data-types/int-uint)

## getQueryProfileEvent {#getQueryProfileEvent}

引入版本：v26.11.0

返回当前查询中某个 [profile event](/zh/reference/system-tables/events) 的当前值。

该值是执行该查询的所有线程上的累计值，计算方式与 `system.query_log` 中的 `ProfileEvents` 列相同。
此函数具有非确定性：在查询执行期间，它会针对每个数据[块](/zh/resources/develop-contribute/introduction/architecture#block)计算一次，
因此同一个块中的所有行会得到相同的值，并且该值会随着查询的进行而不断增长。
可以利用此函数为输出或已插入的数据标注查询进度，例如截至目前已读取的行数或字节数。

在分布式查询中，每个服务器返回的是其自身所执行的那部分查询的值。
某些事件 (例如 `RealTimeMicroseconds` 或 `OSReadBytes`) 仅会定期更新，因此其值可能存在延迟。

<Note>
  此函数具有非确定性：对于相同参数，它可能返回不同的结果。
</Note>
