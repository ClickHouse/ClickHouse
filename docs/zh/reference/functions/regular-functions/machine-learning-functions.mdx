## evalMLMethod {#evalmlmethod}

使用已拟合的回归模型进行预测时，可使用 `evalMLMethod` 函数。请参阅 `linearRegression` 中的链接。

## assignCentroid {#assignCentroid}

引入版本：v26.8.0

返回距离给定向量最近 (L2 距离) 的质心 id。质心可以通过由浮点数数组组成的常量数组给出，此时 id 即为该数组中从 0 开始的下标；也可以通过包含 `cid` 和 `vec` 属性的 `Dictionary` 名称给出，此时 id 即为 `cid`。

<Note>
  该函数是非确定性的：对相同的参数可能返回不同的结果。
</Note>

**语法**

```sql
assignCentroid(vec, centroids | dict_name)
```

**参数**

* `vec` — 待分配的向量。其维度必须与质心的维度一致。非 `Float32` 位宽的类型会被转换为 `Float32`，即打分 kernel 所使用的类型。[`Array(Float32)`](/zh/reference/data-types/array) 或 [`Array(Float64)`](/zh/reference/data-types/array) 或 [`Array(BFloat16)`](/zh/reference/data-types/array)
* `centroids` — 用于打分的质心，必须为常量。可以是由大小相同且非空的浮点数组构成的数组，此时 id 即该数组中从 0 开始的位置；也可以是某个 `Dictionary` 的名称，该字典需包含一个属性 `cid` (类型为可容纳于 `UInt32` 的无符号整数类型) 和一个属性 `vec` (类型为 `Array(Float32)`) ，此时 id 即为 `cid`。该字典只读取一次，并在重新加载前一直保持缓存。[`Array(Array(Float32))`](/zh/reference/data-types/array) 或 [`Array(Array(Float64))`](/zh/reference/data-types/array) 或 [`Array(Array(BFloat16))`](/zh/reference/data-types/array) 或 [`String`](/zh/reference/data-types/string)

**返回值**

最近质心的 id。[`UInt32`](/zh/reference/data-types/int-uint)

**示例**

**内联质心**

```sql title=Query
SELECT assignCentroid([1.0, 2.0]::Array(Float32), [[0.0, 0.0], [1.0, 2.0]]::Array(Array(Float32)))
```

```response title=Response
1
```

## evalMLMethod {#evalMLMethod}

引入版本：v20.1.0

将训练好的机器学习模型应用于输入特征，生成预测结果。

**语法**

```sql
evalMLMethod(model, x1[, x2, ...])
```

**参数**

* `model` — 训练后的机器学习模型。[`AggregateFunctionState`](/zh/reference/data-types/aggregatefunction)
* `x1, x2, ...` — 用于预测的特征值。[`Float*`](/zh/reference/data-types/float) 或 [`(U)Int*`](/zh/reference/data-types/int-uint)

**返回值**

返回基于训练后模型的预测值。[`Float64`](/zh/reference/data-types/float)

**示例**

**使用示例**

```sql title=Query
CREATE TABLE trips (pickup_datetime DateTime('UTC'), trip_distance Float64, total_amount Float64) ENGINE = Memory;

-- A fare of 3, plus 2.5 for every unit of distance.
INSERT INTO trips
SELECT toDateTime('2020-01-01 00:00:00', 'UTC') + number * 60, number % 10 + 1, 2.5 * (number % 10 + 1) + 3
FROM numbers(1000);

-- One model per year of the data.
CREATE TABLE models ENGINE = Memory AS
SELECT
    toYear(pickup_datetime) AS year,
    stochasticLinearRegressionState(0.01, 0.0, 10, 'SGD')(total_amount, trip_distance) AS model
FROM trips
GROUP BY year;

SELECT
    trip_distance,
    round(evalMLMethod(model, trip_distance), 2) AS predicted,
    total_amount
FROM trips
LEFT JOIN models ON year = toYear(pickup_datetime)
ORDER BY pickup_datetime
LIMIT 5
```

```response title=Response
┌─trip_distance─┬─predicted─┬─total_amount─┐
│             1 │      4.05 │          5.5 │
│             2 │      6.79 │            8 │
│             3 │      9.53 │         10.5 │
│             4 │     12.28 │           13 │
│             5 │     15.02 │         15.5 │
└───────────────┴───────────┴──────────────┘
```

## naiveBayesClassifier {#naiveBayesClassifier}

引入版本：v25.11.0

使用 [`NAIVE_BAYES`](/zh/reference/statements/create/dictionary/layouts/naive-bayes) 字典对输入文本进行分类。返回与 `dictGet(dictionary_name, class_attribute, input_text)` 相同的预测类别值，其中 class&#95;attribute 是在字典 [布局](/zh/reference/statements/create/dictionary/layouts/naive-bayes#layout-parameters) 中配置的类别标签属性名称。与 `dictGet` 不同，返回结果的类型始终为 `UInt32`，而不是类别属性的声明类型；并且 `input_text` 必须是 `String` (不进行键类型转换) 。

<Note>
  此函数是非确定性的：对于相同的参数，可能返回不同的结果。
</Note>

**语法**

```sql
naiveBayesClassifier(dictionary_name, input_text)
```

**参数**

* `dictionary_name` — 使用 NAIVE&#95;BAYES 布局的字典名称。[`String`](/zh/reference/data-types/string)
* `input_text` — 待分类的文本。[`String`](/zh/reference/data-types/string)

**返回值**

预测的类别 ID。[`UInt32`](/zh/reference/data-types/int-uint)

**示例**

**文本分类**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT naiveBayesClassifier('sentiment', 'a good and great film') AS class_id;
```

```response title=Response
┌─class_id─┐
│        0 │
└──────────┘
```

## naiveBayesClassifierWithAllProbs {#naiveBayesClassifierWithAllProbs}

引入版本：v26.7.0

使用 [`NAIVE_BAYES`](/zh/reference/statements/create/dictionary/layouts/naive-bayes) 字典对输入文本进行分类，并返回所有类别及其对应的概率，按概率从高到低排列。

<Note>
  此函数是非确定性的：对于相同的参数，可能会返回不同的结果。
</Note>

**语法**

```sql
naiveBayesClassifierWithAllProbs(dictionary_name, input_text)
```

**参数**

* `dictionary_name` — 采用 NAIVE&#95;BAYES 布局的字典名称。[`String`](/zh/reference/data-types/string)
* `input_text` — 待分类的文本。[`String`](/zh/reference/data-types/string)

**返回值**

由 (class&#95;id, probability) Tuple 组成的数组，按概率从高到低排序。[`Array(Tuple(UInt32, Float64))`](/zh/reference/data-types/array)

**示例**

**所有类别的概率**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT arrayMap(p -> (p.1, round(p.2, 4)), naiveBayesClassifierWithAllProbs('sentiment', 'a good and great film')) AS predictions;
```

```response title=Response
┌─predictions─────────────┐
│ [(0,0.9677),(1,0.0323)] │
└─────────────────────────┘
```

## predictXGBoost {#predictXGBoost}

引入版本：v26.10.0

使用 [`XGBOOST`](/zh/reference/statements/create/dictionary/layouts/xgboost) 字典，根据特征向量预测数值型目标值。特征按位置传入，顺序须与该字典声明键列的顺序一致。这是查询 `XGBOOST` 字典的唯一方式：该字典存储的是训练好的模型而非行数据，因此不支持通用的字典接口 (`dictGet`、`dictHas`、`SELECT * FROM dict`) 。XGBoost 集成目前仍处于实验性阶段，因此必须启用 `enable_xgboost` 设置。

**语法**

```sql
predictXGBoost(dictionary_name, feature1[, feature2, ...][, params])
```

**参数**

* `dictionary_name` — 采用 XGBOOST 布局的字典名称。有关如何创建该字典及其支持的训练参数，请参阅 [XGBOOST 字典布局](/zh/reference/statements/create/dictionary/layouts/xgboost)。[`String`](/zh/reference/data-types/string)
* `featureN` — 数值特征值，按字典键的顺序依次按位置传入。值为 NULL 的特征会作为缺失值传给模型，XGBoost 会按照训练时的方式处理缺失值，因此预测结果永远不会为 NULL。[`(U)Int*`](/zh/reference/data-types/int-uint) 或 [`Float*`](/zh/reference/data-types/float) 或 [`Nullable((U)Int*)`](/zh/reference/data-types/nullable) 或 [`Nullable(Float*)`](/zh/reference/data-types/nullable)
* `params` — 可选的 XGBoost 预测参数常量 Map，键为参数名称，值为整数，例如 `map('type', 0, 'iteration_end', 0)`。所有支持的参数均为整数或布尔类型，因此不接受小数值。有关支持的键，请参阅[预测参数](/zh/reference/statements/create/dictionary/layouts/xgboost#prediction-parameters)。[`Map(String, (U)Int8/16/32/64)`](/zh/reference/data-types/map)

**返回值**

模型预测结果，类型为 Float64，每行返回一个值。[`Float64`](/zh/reference/data-types/float)

**示例**

**预测**

```sql title=Query
-- A model trained on the linear target y = 2 * x1 + 3 * x2. The XGBoost integration is experimental.
SET enable_xgboost = 1;

CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO training_data SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y FROM numbers(100);

CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(objective 'reg:squarederror' num_iterations 100 max_depth 6))
LIFETIME(0);

-- The ground truth is 2 * 1 + 3 * 2 = 8.
SELECT round(predictXGBoost('model', 1.0, 2.0), 1) AS prediction;
```

```response title=Response
┌─prediction─┐
│          8 │
└────────────┘
```

**使用参数进行预测**

```sql title=Query
-- The raw margin of the model above, before the objective's transformation. For `reg:squarederror` it is the
-- prediction itself, while for `binary:logistic` it is the log-odds rather than the probability.
SELECT round(predictXGBoost('model', 1.0, 2.0, map('type', 1)), 1) AS margin;
```

```response title=Response
┌─margin─┐
│      8 │
└────────┘
```
