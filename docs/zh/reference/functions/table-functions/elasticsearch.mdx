允许对 [Elasticsearch](https://www.elastic.co/elasticsearch) 中某个索引的文档执行 `SELECT` 查询。每个文档作为一行返回：其 `_source` 以单个 [JSON](/zh/reference/data-types/newjson) 类型的列呈现，文档 ID 和索引名称则以虚拟列的形式提供。该函数为只读函数。

## 语法 {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  Elasticsearch 集成目前处于实验性阶段。可通过 [`enable_elasticsearch`](/zh/reference/settings/session-settings/enable#enable_elasticsearch) 设置启用该功能：

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## 参数 {#arguments}

| 参数             | 描述                                                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | Elasticsearch 集群的基准 URL，例如 `https://localhost:9200`。必须是不含凭证、查询字符串和片段的 `http` 或 `https` URL。                                                                             |
| `index`        | 要读取的索引。也可以是别名、逗号分隔的列表或通配符模式，只要 Elasticsearch 时间点 API 支持即可。若模式未匹配到任何索引，则会报错。                                                                                             |
| `user`         | 用于 HTTP 基本身份验证的用户名 (可选) 。                                                                                                                                               |
| `password`     | 用于 HTTP 基本身份验证的密码 (可选，须同时指定 `user`) 。                                                                                                                                   |
| `query('...')` | JSON 格式的 Elasticsearch [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) 对象，用于筛选要读取的文档 (可选) 。必须位于位置参数之后。默认值：`{"match_all": {}}`。 |

`url`、`index`、`user` 和 `password` 参数也可以采用 `key = value` 形式指定；位置参数按上述顺序依次填入。如果同一参数既以位置参数形式又以键的形式指定 (或同一个键指定了两次) ，则会报错。

以下参数可以采用 `key = value` 形式指定 (也可作为命名集合的键) ：

| 键              | 描述                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `user`         | 用于 HTTP 基本身份验证的用户名。                                                                                                    |
| `password`     | 用于 HTTP 基本身份验证的密码。                                                                                                     |
| `bearer_token` | 以 `Authorization: Bearer <token>` 形式发送的令牌，例如 Elasticsearch 服务账号令牌。                                                     |
| `api_key`      | Elasticsearch API key，以 `Authorization: ApiKey <api_key>` 形式发送。其值为创建 API key 的 API 所返回的、经 Base64 编码的 `id:api_key` 字符串。 |

命名集合中可以包含 `query` 键。如需覆盖该键，请在集合名称之后传入 `query('...')` 或 `query = '...'`。

此外，该表函数还支持：

| 键           | 描述                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------- |
| `structure` | 表结构，格式为 `'name JSON'`。该结构必须有且仅有一个 `JSON` 类型的列；`_id` 和 `_index` 为预留名称。默认值：`'document JSON'`。 |

读取设置 `keep_alive` 和 `page_size` 可以通过末尾的 `SETTINGS` 子句传入，具体说明请参阅 [`Elasticsearch` 表引擎](/zh/reference/engines/table-engines/integrations/elasticsearch#creating-a-table)。

## 身份验证 {#authentication}

最多只能提供一种身份验证方法：

1. **基本身份验证**。传入 `user` 和 `password`。
2. **Bearer 令牌**。传入 `bearer_token`。
3. **API key**。传入 `api_key`。

如果均未提供，请求将以匿名方式发送，仅当 Elasticsearch 禁用了安全功能时才可行。

可将凭证存储在[命名集合](/zh/concepts/features/configuration/server-config/named-collections)中，从而无需在每个查询中重复指定。基于命名集合创建的永久表 (使用 `Elasticsearch` 表引擎或 `CREATE TABLE ... AS elasticsearch(...)` 创建) 会被注册为该集合的依赖项，因此只要该表存在，就无法执行 `DROP NAMED COLLECTION`。

## 虚拟列 {#virtual-columns}

* `_id` — 文档 ID。类型：`String`。
* `_index` — 读取该文档时所用索引的名称。类型：`LowCardinality(String)`。

当查询仅读取虚拟列时，不会向 Elasticsearch 请求文档的 `_source`。对于不存储 `_source` 的索引 (即其映射中已禁用 `_source` 字段) ，只能通过虚拟列读取：如果查询从此类索引中读取 `JSON` 列，将直接报错，而不会返回空文档。

## 示例 {#examples}

统计某个索引中的文档数量：

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

以 `JSON` 列子列的形式读取文档中的字段：

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

在 Elasticsearch 端使用 Query DSL 对象过滤数据，并调整分页大小：

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

使用命名集合：

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## 限制 {#limitations}

* 该函数为只读函数，不支持 `INSERT`。
* 谓词不会被下推。`WHERE` 条件要等文档下载完成后才会在 ClickHouse 中应用；如需在 Elasticsearch 端进行过滤，请使用 `query` 参数。
* 发送 `query` 时会附带一个数据页的 `size`。如果查询结果取决于 `size` (例如未指定 `k` 的 `knn` 查询) ，则返回的文档集合将随 `page_size` 而变化。请显式指定此类参数。
* 每个数据页都是一次独立的搜索请求，Elasticsearch 会在每次请求时重新计算 `query` 中的日期运算表达式 (例如 `now-1h`) 。时间点只会冻结文档，而不会冻结时钟，因此依赖时间的 `query` 可能会在不报错的情况下跳过移动边界附近的文档。请在 `query` 中使用绝对日期。
* 每次读取都会打开一个时间点，通过按 `_shard_doc` 排序的 `search_after` 对结果进行分页遍历，并在结束时关闭该时间点。如果某个数据页请求在任一分片上失败，或在 Elasticsearch 中超时，则会引发错误，而不会返回部分结果。
* 需要 Elasticsearch 7.12 或更高版本：该函数依赖时间点 API 和 `_shard_doc` 排序字段，因此较旧版本以及 OpenSearch 会拒绝第一个请求。
* `page_size` 不能超过 Elasticsearch 的 `index.max_result_window` 索引设置 (默认为 `10000`) 。
