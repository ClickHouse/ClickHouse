## 描述 {#description}

包含各种 blob 存储操作 (如上传和删除) 的日志记录条目。

可以随时安全地对该表执行 TRUNCATE 或 DROP 操作。

## 列 {#columns}

* `hostname` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 执行该查询的服务器主机名。
* `clickhouse_version` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 产生该行的 ClickHouse 服务器版本。
* `system_processor` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 产生该行的 ClickHouse 服务器的 CPU 架构。
* `event_date` ([Date](/zh/reference/data-types/date)) — 事件发生日期。
* `event_time` ([DateTime](/zh/reference/data-types/datetime)) — 事件发生时间。
* `event_time_microseconds` ([DateTime64(6)](/zh/reference/data-types/datetime64)) — 精确到微秒的事件发生时间。
* `event_type` ([Enum8(&#39;Upload&#39; = 1, &#39;Delete&#39; = 2, &#39;MultiPartUploadCreate&#39; = 3, &#39;MultiPartUploadWrite&#39; = 4, &#39;MultiPartUploadComplete&#39; = 5, &#39;MultiPartUploadAbort&#39; = 6, &#39;Read&#39; = 7, &#39;Copy&#39; = 8)](/zh/reference/data-types/enum)) — 事件类型。可能的值：&#39;Upload&#39;、&#39;Delete&#39;、&#39;MultiPartUploadCreate&#39;、&#39;MultiPartUploadWrite&#39;、&#39;MultiPartUploadComplete&#39;、&#39;MultiPartUploadAbort&#39;、&#39;Read&#39;、&#39;Copy&#39;
* `query_id` ([String](/zh/reference/data-types/string)) — 与该事件关联的查询标识符 (如有) 。
* `thread_id` ([UInt64](/zh/reference/data-types/int-uint)) — 执行该操作的线程标识符。
* `thread_name` ([String](/zh/reference/data-types/string)) — 执行该操作的线程名称。
* `disk_name` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 关联磁盘的名称。
* `bucket` ([String](/zh/reference/data-types/string)) — 桶名称。
* `remote_path` ([String](/zh/reference/data-types/string)) — 远程资源的路径。
* `local_path` ([String](/zh/reference/data-types/string)) — 本地系统上引用该远程资源的元数据文件路径。
* `source_bucket` ([String](/zh/reference/data-types/string)) — &#39;Copy&#39; 事件中对象复制来源的桶名称；其他事件中为空。
* `source_remote_path` ([String](/zh/reference/data-types/string)) — &#39;Copy&#39; 事件中数据复制来源对象的路径；其他事件中为空。
* `data_size` ([UInt64](/zh/reference/data-types/int-uint)) — 该操作涉及的数据大小。
* `elapsed_microseconds` ([UInt64](/zh/reference/data-types/int-uint)) — 该操作的耗时，单位为微秒。
* `connection_id` ([UInt64](/zh/reference/data-types/int-uint)) — 承载该操作的 HTTP 连接的标识符，在服务器进程内唯一。如需追踪单个连接，请按此列分组：套接字一旦关闭，OS 就会立即回收端口和套接字 inode，因此无法用它们区分先后建立的连接。若该行无法对应到单个 HTTP 请求，则为 0，具体包括以下情况：该操作未使用 HTTP 连接；该操作使用了多个连接——重试的写入只记录为一行，其耗时涵盖所有尝试，无法用单个连接描述；或该操作与其他行共用同一请求——批量删除会为每个对象写入一行 `Delete`，但仅将连接归属到其中第一行。所有 `connection_*` 列仅在 `connection_id` 不为 0 时才有意义，否则均为 0。
* `connection_local_port` ([UInt16](/zh/reference/data-types/int-uint)) — 该连接的本地 TCP 端口。仅在同一时刻打开的套接字之间唯一；可用于与同一时间采集的抓包数据或 /proc/net/tcp 中的行进行关联。
* `connection_socket_inode` ([UInt64](/zh/reference/data-types/int-uint)) — 该连接的套接字 inode，由 fstat 报告。与端口有相同的限制：仅在套接字打开期间唯一。若 OS 不为套接字提供 inode (如 macOS) ，则为 0。
* `connection_requests` ([UInt32](/zh/reference/data-types/int-uint)) — 该连接在本次请求之前已发送的请求数。在 `connection_id` 不为 0 的前提下，0 表示这是该连接的第一个请求。
* `connection_age_microseconds` ([UInt64](/zh/reference/data-types/int-uint)) — 自该连接的 TCP 套接字建立以来经过的时间。每次重新连接时都会重置，因此衡量的是套接字的存活时长，而非会话对象的存活时长。
* `connection_idle_microseconds` ([UInt64](/zh/reference/data-types/int-uint)) — 该连接被分配给此操作之前，在对象池中处于空闲状态的时长。对于连接的首个请求，该值为 0；当 `connection_id` 为 0 时，该值同样为 0。
* `error_code` ([Int32](/zh/reference/data-types/int-uint)) — 操作的错误代码。若无错误，则为 0。
* `error` ([String](/zh/reference/data-types/string)) — 与该事件关联的错误消息 (如有) 。

## 示例 {#example}

假设某个 blob 存储操作上传了一个文件，并记录了一个事件：

```sql
SELECT * FROM system.blob_storage_log WHERE query_id = '7afe0450-504d-4e4b-9a80-cd9826047972' ORDER BY event_date, event_time_microseconds \G
```

```text
Row 1:
──────
hostname:                clickhouse.eu-central1.internal
event_date:              2023-10-31
event_time:              2023-10-31 16:03:40
event_time_microseconds: 2023-10-31 16:03:40.481437
event_type:              Upload
query_id:                7afe0450-504d-4e4b-9a80-cd9826047972
thread_id:               2381740
disk_name:               disk_s3
bucket:                  bucket1
remote_path:             rrr/kxo/tbnqtrghgtnxkzgtcrlutwuslgawe
local_path:              store/654/6549e8b3-d753-4447-8047-d462df6e6dbe/tmp_insert_all_1_1_0/checksums.txt
data_size:               259
error:
```

在此示例中，上传操作与 ID 为 `7afe0450-504d-4e4b-9a80-cd9826047972` 的 `INSERT` 查询相关联。本地元数据文件 `store/654/6549e8b3-d753-4447-8047-d462df6e6dbe/tmp_insert_all_1_1_0/checksums.txt` 对应于磁盘 `disk_s3` 上 bucket `bucket1` 中的远程路径 `rrr/kxo/tbnqtrghgtnxkzgtcrlutwuslgawe`，大小为 259 字节。
