## 描述 {#description}

包含在后台定期计算的指标。例如，已使用的 RAM 量。

指标要么是标量 (`value` 列中的单个数值) ，要么是键值指标：按实体细分，例如按 CPU 核心、块设备、网络接口或磁盘细分。键值指标以单行形式表示，`key_values` 列中包含一个 [Map](/zh/reference/data-types/map) (例如，`CPUFrequencyMHz` 将每个 CPU 核心编号映射到其频率) ，其 `value` 列为 `非数字`。

在 26.8 版本之前，每个键都是一个独立的标量指标，键名被嵌入指标名称中 (`CPUFrequencyMHz_0`)。[`asynchronous_metrics_key_values_mode`](/zh/reference/settings/server-settings/settings/asynchronous-metrics#asynchronous_metrics_key_values_mode) 服务器设置可切换回该形式 (`legacy_names`)，或在迁移监控时同时显示两种形式 (`both`)。

## 列 {#columns}

{/*AUTOGENERATED_START*/}

* `metric` ([String](/zh/reference/data-types/string)) — 指标名称。
* `value` ([Float64](/zh/reference/data-types/float)) — 指标值。对于键值指标 (按 CPU 核心、块设备、磁盘等细分) ，该值为非数字，实际值位于 `key_values` 列中。
* `key_values` ([Map(LowCardinality(String), Float64)](/zh/reference/data-types/map)) — 键值指标的值，例如以 CPU 核心编号或块设备名称为键。标量指标则为空。
* `description` ([String](/zh/reference/data-types/string) - 指标说明)

{/*AUTOGENERATED_END*/}

## 示例 {#example}

```sql
SELECT metric, value, key_values
FROM system.asynchronous_metrics
WHERE metric IN ('MemoryResident', 'OSUserTime', 'DiskTotal', 'BlockReadBytes', 'NetworkReceiveBytes')
ORDER BY metric
```

```text
┌─metric──────────────┬─────────────value─┬─key_values──────────────────────────────────────┐
│ BlockReadBytes      │               nan │ {'nvme0n1':67420160}                            │
│ DiskTotal           │               nan │ {'backups':34359738368,'default':5199475388416} │
│ MemoryResident      │         970743808 │ {}                                              │
│ NetworkReceiveBytes │               nan │ {'docker0':0,'ens66':334554363}                 │
│ OSUserTime          │ 32.11807291562506 │ {}                                              │
└─────────────────────┴───────────────────┴─────────────────────────────────────────────────┘
```

可以使用 Map 下标提取键值指标中的单个实体：

```sql
SELECT key_values['default'] AS default_disk_total
FROM system.asynchronous_metrics
WHERE metric = 'DiskTotal'
```

cgroup 中已使用的内存量，单位为字节。在 cgroup v2 中，它表示 anon + sock + 不可回收的内核内存；在 cgroup v1 中，它表示 RSS。两种情况下都不包含内核的 OS page cache (基于文件的缓存) 。

### CGroupSystemTime {#cgroupsystemtime}

### CGroupSystemTimeNormalized {#cgroupsystemtimenormalized}

该值与 `CGroupSystemTime` 类似，但会除以可用的 CPU 核心数，因此无论核心数量多少，结果都落在 [0..1] 区间内。这样一来，即使 集群 中各 server 的核心数不一致，你也可以对多个 server 上的该指标值求平均，并仍然得到平均资源利用率指标。如果已指定，则可以使用 Cgroup CPU 配额除以其周期的结果来代替实际的 CPU 核心数；在这种情况下，该指标的值在某些时刻可能会超过 1。

### OSCPUOverload {#oscpuoverload}

### OSGuestNiceTimeCPU {#osguestnicetimecpu}

### OSGuestNiceTimeNormalized {#osguestnicetimenormalized}

### OSIdleTimeNormalized {#osidletimenormalized}
