## 描述 {#description}

此表包含可即时计算并以 Prometheus 格式导出的维度指标，且会始终保持最新状态。

## 指标说明 {#metric_descriptions}

### merge_failures {#merge_failures}

自启动以来所有失败 merge 的数量。

### startup_scripts_failure_reason {#startup_scripts_failure_reason}

按错误类型指示启动脚本失败情况。当启动脚本失败时，该值设为 1，并带有错误名称标记。

### merge_tree_parts {#merge_tree_parts}

MergeTree 数据分区片段的数量，按分区片段状态、分区片段类型以及是否为投影分区片段区分。

### `filesystem_cache_evictions_total` {#filesystem-cache-evictions-total}

从文件系统缓存中逐出的 File 段数量，按缓存名称标记。默认禁用；可通过 `expose_prometheus_eviction_metrics` 启用。

### `filesystem_cache_evicted_bytes_total` {#filesystem-cache-evicted-bytes-total}

从文件系统缓存中被逐出的 File 段总字节数，按缓存名称加标签。默认禁用；可通过 `expose_prometheus_eviction_metrics` 启用。

### `filesystem_cache_evictions_by_user_total` {#filesystem-cache-evictions-by-user-total}

从文件系统缓存中逐出的 File 段数量，按缓存名称和用户 ID 标记。默认禁用；可通过 `expose_prometheus_eviction_metrics` 和 `expose_prometheus_eviction_metrics_per_user` 启用。

### `filesystem_cache_evicted_bytes_by_user_total` {#filesystem-cache-evicted-bytes-by-user-total}

从文件系统缓存中淘汰的 File 段总字节数，按缓存名称和用户 ID 进行标记。默认禁用；可通过 `expose_prometheus_eviction_metrics` 和 `expose_prometheus_eviction_metrics_per_user` 启用。

### `object_storage_queue_failures_total` {#object-storage-queue-failures-total}

按数据库、表、处理阶段 (`read`、`set_processing`、`insert`、`commit`、`after_processing`) 和错误代码标记的 `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 失败次数。对于 `after_processing` 阶段，该值表示 `after_processing` 操作 (删除、打标签或移动) 未能完成的对象数量。

### `object_storage_queue_permanently_failed_files_total` {#object-storage-queue-permanently-failed-files-total}

`ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 在耗尽重试次数后 (或禁用重试时) 永久放弃处理的文件数量，按数据库和表标记。每个此类文件的数据都将永远不会被处理。

### `object_storage_queue_newest_seen_object_timestamp_seconds` {#object-storage-queue-newest-seen-object-timestamp-seconds}

`ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 表截至目前已发现的最新对象的最后修改时间的 Unix 时间戳，按数据库和表标记。当表被删除或分离时，该数据系列会被移除。表重命名后，旧名称对应的数据系列会一直保留，直到服务器重启。

### `object_storage_queue_newest_committed_object_timestamp_seconds` {#object-storage-queue-newest-committed-object-timestamp-seconds}

截至目前由 `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 表完全处理的最新对象的最后修改时间的 Unix 时间戳，按数据库和表标记。表被删除或分离后，该数据系列会被移除。表重命名后，旧名称对应的数据系列会一直保留，直到服务器重启。

### `object_storage_queue_processed_files_total` {#object-storage-queue-processed-files-total}

此 `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 表在此服务器上已提交为已处理的文件数量，按数据库和表标记。

### `object_storage_queue_last_poll_timestamp_seconds` {#object-storage-queue-last-poll-timestamp-seconds}

该服务器上 `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 表的后台流式线程最近一次启动查找待处理文件的轮询周期、或启动该周期中某个批次时的 Unix 时间戳，按以下标签标记：数据库 和 表。该值在周期启动时 (即表已在 Keeper 中将自身注册为活跃之后) 设置，并在该周期的每个批次开始前再次更新，因此即使周期未找到任何文件或执行失败，或处于长时间积压期间，该值也会持续推进。注册失败时，该值不会推进。值为 0 表示该表自启动以来尚未进行过轮询。当表没有处于就绪状态的已附加物化视图、流式处理已停止或已暂停，或服务器上已禁用流式处理时，该值不会推进，因为此时表不会消费数据。同一张表的所有流式线程写入同一个数据系列，因此该值反映的是其中任一线程最新的周期。表被删除或分离时，该数据系列会被移除。表重命名后，旧名称对应的数据系列会一直保留，直到服务器重启。

### `system_log_flushes_total` {#system-log-flushes-total}

将系统日志的内存中缓冲区刷写到其对应表的尝试次数，按系统日志所在的数据库和表以及结果 (`success`、`failure`) 进行标记。

### `system_log_flushed_rows_total` {#system-log-flushed-rows-total}

系统日志成功刷写时已写入的行数，按该系统日志所属的数据库和表进行标记。

### `system_log_dropped_rows_total` {#system-log-dropped-rows-total}

系统日志中丢失的行数，按系统日志所在的数据库和表以及原因进行标记：`queue_full` 表示因内存中缓冲区达到 `max_size_rows` 而未被接收的行 (该值在取出缓冲区进行下一次刷写时更新) ，`flush_failed` 表示刷写失败所涉及的行。

## 列 {#columns}

* `metric` ([String](/zh/reference/data-types/string)) — 指标名称。
* `value` ([Float64](/zh/reference/data-types/float)) — 指标值。
* `description` ([String](/zh/reference/data-types/string)) — 指标说明。
* `labels` ([Map(String, String)](/zh/reference/data-types/map)) — 指标标记。

**别名：**

* `name` — `metric` 的别名。

## 示例 {#example}

您可以使用如下查询，以 Prometheus 格式导出所有维度指标。

```sql
SELECT
  metric AS name,
  toFloat64(value) AS value,
  description AS help,
  labels,
  'gauge' AS type
FROM system.dimensional_metrics
FORMAT Prometheus
```
