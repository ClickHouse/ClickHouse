## 说明 {#description}

`system.delta_lake_metadata_log` 表记录 ClickHouse 读取 Delta Lake 表时的元数据访问和解析事件，提供每个元数据文件的详细信息，可用于调试、审计以及了解 Delta 表结构的演进过程。

该表会记录从 Delta Lake 表读取的每一个元数据文件，帮助用户追踪 ClickHouse 如何解释 Delta 表元数据，并诊断与 schema evolution、snapshot 解析或查询规划相关的问题。

该表主要用于调试目的。

### 控制日志详细程度 {#controlling-log-verbosity}

您可以使用 [`delta_lake_log_metadata`](/zh/reference/settings/session-settings/delta-lake#delta_lake_log_metadata) 设置来控制记录哪些元数据事件。

若要记录当前查询中使用的所有元数据：

```sql
SELECT * FROM my_delta_table SETTINGS delta_lake_log_metadata = 1;

SYSTEM FLUSH LOGS delta_lake_metadata_log;

SELECT *
FROM system.delta_lake_metadata_log
WHERE query_id = '{previous_query_id}';
```

随时都可以安全地对该表执行 TRUNCATE 或 DROP 操作。

## 列 {#columns}

* `hostname` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 执行查询的服务器主机名。
* `clickhouse_version` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 生成该行的 ClickHouse 服务器版本。
* `system_processor` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 生成该行的 ClickHouse 服务器的 CPU 架构。
* `event_date` ([Date](/zh/reference/data-types/date)) — 条目日期。
* `event_time` ([DateTime](/zh/reference/data-types/datetime)) — 事件时间。
* `query_id` ([String](/zh/reference/data-types/string)) — 查询 ID。
* `table_path` ([String](/zh/reference/data-types/string)) — 表路径。
* `file_path` ([String](/zh/reference/data-types/string)) — 文件路径。
* `content` ([String](/zh/reference/data-types/string)) — JSON 格式的内容。
