## 描述 {#description}

包含有关系统中已发生事件数量的信息。例如，在该表中，你可以查看自 ClickHouse server 启动以来已处理的 `SELECT` 查询数量。

## 事件描述 {#event-descriptions}

### ACMEAPIRequests {#acmeapirequests}

发起的 ACME API 请求数。

### ACMECertificateOrders {#acmecertificateorders}

已发出的 ACME 证书订单数量。

### AdaptiveAggregationBucketsRetired {#adaptiveaggregationbucketsretired}

在自身的合并与转换完成后、整个合并尚未结束时，其工作内存 (arena slot、暂存块引用) 即被回收的两级桶数量。

### AdaptiveAggregationDrainedRecords {#adaptiveaggregationdrainedrecords}

自适应聚合在合并时排空到共享表的延迟记录数。

### AdaptiveAggregationGiveUps {#adaptiveaggregationgiveups}

在自适应聚合中，因自身数据流包含的不同键较少而放弃冻结的线程数。

### AdaptiveAggregationLocalFreezes {#adaptiveaggregationlocalfreezes}

自适应聚合在达到冻结阈值时冻结的本地哈希表数量。

### AdaptiveAggregationPressureDrainedRecords {#adaptiveaggregationpressuredrainedrecords}

自适应聚合在内存压力下提前排空的暂存记录数。

### AdaptiveAggregationPressureStandDowns {#adaptiveaggregationpressurestanddowns}

自适应聚合中有多少线程因内存压力超过外部聚合阈值而彻底退出学习阶段，从而使其本地表通过普通的外部聚合方式落盘。

### AdaptiveAggregationPressureSweeps {#adaptiveaggregationpressuresweeps}

自适应聚合因内存压力而提前排空暂存记录的次数。

### AdaptiveAggregationProbeBypasses {#adaptiveaggregationprobebypasses}

在自适应聚合中，因几乎没有行命中而停止探测其已冻结本地表的线程数。

### AdaptiveAggregationResidueReleases {#adaptiveaggregationresiduereleases}

自适应聚合将其共享的排空表写出的次数：当某个已退回基线算法的线程因该表即将落盘时触发。

### AdaptiveAggregationSealedChunks {#adaptiveaggregationsealedchunks}

自适应聚合从缓冲的暂存批次中封存的合并块数量。

### AdaptiveAggregationSealNormalizations {#adaptiveaggregationsealnormalizations}

自适应聚合的 seal 阶段将多少个暂存的参数列从包装表示形式 (Const、Replicated、Sparse、LowCardinality) 归一化为排空阶段所消费的密集形式。

### AdaptiveAggregationSharedTableSpills {#adaptiveaggregationsharedtablespills}

自适应聚合因在内存压力下达到分片上限，而将其共享排空表落盘的次数。

### AdaptiveAggregationSpillBacklogSheds {#adaptiveaggregationspillbacklogsheds}

自适应聚合丢弃暂存积压的次数：当某个运行在基线算法上的线程 (可能是被解冻后重新放回该算法的线程，也可能是自行退出的线程) 即将落盘，而暂存记录仍驻留在内存中时，即会发生此情况。

### AdaptiveAggregationStagedBytes {#adaptiveaggregationstagedbytes}

自适应聚合为合并时排空(drain)暂存的 key 字节数。

### AdaptiveAggregationStagedChunkPiecesOverBound {#adaptiveaggregationstagedchunkpiecesoverbound}

自适应聚合发布的、由暂存块切分而来的分片中，仍然超出该块切分时所要满足的边界的分片数量。块按桶边界切分；若某个桶自身就超出边界，则在桶内逐条记录切分，因此这类分片就是单条记录，其暂存字节本身已超出边界；此类分片只能整体认领，其排空量可能因此超出压力分片相应的幅度。

### AdaptiveAggregationStagedChunkSplits {#adaptiveaggregationstagedchunksplits}

自适应聚合在 publication 时沿桶边界切分暂存块的次数：因为某个块的排空量估计超过了压力分片上限。

### AdaptiveAggregationStagedClaimsClosedAtBound {#adaptiveaggregationstagedclaimsclosedatbound}

adaptive aggregation 的排空过程对暂存块发起的 claim 中，有多少次在遇到某个块之前就已关闭——该块一旦加入，批次就会触及压力分片的界限，因此该块被留给下一次 claim。该界限是针对排空后的批次而言的，因此两个各自刚好不到界限的块 (即一个被切分块的两部分，每部分仅比半个分片多出单条记录) 会被排空到两个表中，而不是一个表；只有单独就已超出界限的首个块才会被无条件 claim。

### AdaptiveAggregationStagedRecords {#adaptiveaggregationstagedrecords}

自适应聚合在去重前暂存的延迟记录数。

### AdaptiveAggregationStagedRecordsMerged {#adaptiveaggregationstagedrecordsmerged}

### AggregationTopKKeysPruned {#aggregationtopkkeyspruned}

有多少被淘汰的分组键同时也从中间哈希表中被删除，且其聚合状态被销毁 (参见 `enable_group_by_top_k_optimization`) 。当聚合方法无法删除键，或仅按键的前缀部分进行排名时，该值会低于 `AggregationTopKKeysEvicted`：此时堆仍会跳过行，但哈希表会保留每一个已接纳的分组。

### AggregationTopKRowsSkipped {#aggregationtopkrowsskipped}

### 合并后数据与副本不同 {#dataaftermergediffersfromreplica}

合并后的数据在字节级别上与其他副本上的数据不完全一致的次数。可能有以下几种原因：

1. 服务器更新后使用了较新版本的压缩库。
2. 使用了另一种压缩方法。
3. 使用了非确定性的压缩算法 (这种情况极不可能) 。
4. 由于代码中的逻辑错误，合并算法表现为非确定性。
5. 由于代码中的 bug，导致内存中的数据损坏。
6. 由于硬件问题，导致内存中的数据损坏。
7. 服务器启动后手动修改了源数据。
8. 手动修改了存储在 ZooKeeper 中的校验和。
9. 与 part 格式相关的设置 (例如 `enable_mixed_granularity_parts`) 在不同副本上不一致。
   服务器已成功检测到这种情况，并将从副本下载合并后的 part，以强制得到字节级别完全一致的结果。
