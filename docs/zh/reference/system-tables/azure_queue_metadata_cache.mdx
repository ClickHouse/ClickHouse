## 描述 {#description}

包含 AzureQueue 元数据的内存状态，以及每个文件当前正在处理的行。

## 列 {#columns}

* `zookeeper_path` ([String](/zh/reference/data-types/string)) — ZooKeeper 中元数据的路径
* `file_path` ([String](/zh/reference/data-types/string)) — 正在处理的文件的文件路径
* `file_name` ([String](/zh/reference/data-types/string)) — 正在处理的文件的文件名
* `rows_processed` ([UInt64](/zh/reference/data-types/int-uint)) — 当前已处理的行数
* `status` ([String](/zh/reference/data-types/string)) — 处理状态：Processed、Processing、Failed，或 None (表示缓存已知但没有对应状态的文件，例如处理状态被重置的文件) 。若 `processing_observed_in_keeper_time` 非空，则表示 `Processing` 状态不是由持有该文件的处理器设置的，而是从 keeper 中读取到的
* `processing_start_time` ([Nullable(DateTime)](/zh/reference/data-types/nullable)) — 开始处理文件的时间
* `processing_end_time` ([Nullable(DateTime)](/zh/reference/data-types/nullable)) — 完成处理文件的时间
* `exception` ([String](/zh/reference/data-types/string)) — 处理期间发生的异常。始终是本服务器最近一次尝试产生的异常，而非 keeper 为该文件存储的异常
* `processing_observed_in_keeper_time` ([Nullable(DateTime)](/zh/reference/data-types/nullable)) — 本服务器的某个处理器未能获取该文件，转而从 keeper 读取到 `Processing` 状态 (而非自行设置该状态) 的时间。通常该文件由另一台服务器持有，但也可能由本服务器上刚刚获取它的某个处理器持有。无论哪种情况，`rows_processed`、`processing_start_time`、`processing_end_time` 和 `exception` 描述的都是本服务器最近一次处理该文件的尝试，而不是当前持有它的那次处理
