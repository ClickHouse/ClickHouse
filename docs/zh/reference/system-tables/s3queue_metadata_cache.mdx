## 描述 {#description}

包含 S3Queue 元数据的内存状态，以及每个文件当前处理中的行。

## 列 {#columns}

* `zookeeper_path` ([String](/zh/reference/data-types/string)) — ZooKeeper 中元数据的路径
* `file_path` ([String](/zh/reference/data-types/string)) — 正在处理的文件的文件路径
* `file_name` ([String](/zh/reference/data-types/string)) — 正在处理的文件的文件名
* `rows_processed` ([UInt64](/zh/reference/data-types/int-uint)) — 当前正在处理的行数
* `status` ([String](/zh/reference/data-types/string)) — 处理状态：Processed、Processing、Failed，或 None (表示 cache 已知该文件但没有对应状态，例如处理已被 reset 的文件) 。若 `processing_observed_in_keeper_time` 非空，则表示 `Processing` 状态并非由持有该文件的处理器设置，而是从 Keeper 中读取到的
* `processing_start_time` ([Nullable(DateTime)](/zh/reference/data-types/nullable)) — 文件开始处理的时间
* `processing_end_time` ([Nullable(DateTime)](/zh/reference/data-types/nullable)) — 文件处理结束的时间
* `exception` ([String](/zh/reference/data-types/string)) — 处理期间发生的异常。始终是本 server 最近一次尝试产生的异常，而非 Keeper 为该文件存储的异常
* `processing_observed_in_keeper_time` ([Nullable(DateTime)](/zh/reference/data-types/nullable)) — 本 server 的某个处理器未能取得该文件、转而从 Keeper 读取 `Processing` 状态 (而非自行设置该状态) 的时间。通常该文件由另一台 server 持有，但也可能由本 server 中刚刚取得它的某个处理器持有。无论哪种情况，`rows_processed`、`processing_start_time`、`processing_end_time` 和 `exception` 描述的都是本 server 最近一次处理该文件的尝试，而非当前持有该文件的处理过程
