## 描述 {#description}

包含表 `system.errors` 中错误值的历史记录，并定期写入磁盘。

可以随时安全地对该表执行 TRUNCATE 或 drop 操作。

## 列 {#columns}

* `hostname` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 执行该查询的服务器主机名。
* `clickhouse_version` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 生成该行的 ClickHouse 服务器版本。
* `system_processor` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 生成该行的 ClickHouse 服务器的 CPU 架构。
* `event_date` ([Date](/zh/reference/data-types/date)) — 事件日期。
* `event_time` ([DateTime](/zh/reference/data-types/datetime)) — 事件时间。
* `code` ([Int32](/zh/reference/data-types/int-uint)) — 错误代码。
* `error` ([LowCardinality(String)](/zh/reference/data-types/lowcardinality)) — 错误名称。
* `value` ([UInt64](/zh/reference/data-types/int-uint)) — 在该时间间隔内发生的错误次数。
* `remote` ([UInt8](/zh/reference/data-types/int-uint)) — 远程异常 (即在某次分布式查询期间接收到的异常) 。
* `last_error_time` ([DateTime](/zh/reference/data-types/datetime)) — 最近一次错误发生的时间。
* `last_error_message` ([String](/zh/reference/data-types/string)) — 最近一次错误的消息。
* `last_error_query_id` ([String](/zh/reference/data-types/string)) — 导致最近一次错误的查询 ID (如果可用) 。
* `last_error_trace` ([Array(UInt64)](/zh/reference/data-types/array)) — 最近一次错误的栈跟踪。在除 FreeBSD 之外的 ELF 平台上，ClickHouse 主二进制文件内部的地址以物理文件偏移量的形式存储，而其外部的栈帧 (共享库、JIT 代码) 则存储为 0。
* `last_error_symbols` ([Array(LowCardinality(String))](/zh/reference/data-types/array)) — 与 last&#95;error&#95;trace 对应的已还原 (demangled) 符号名称。
* `last_error_lines` ([Array(LowCardinality(String))](/zh/reference/data-types/array)) — 与 last&#95;error&#95;trace 对应的文件名及行号。

`last_error_symbols` 和 `last_error_lines` 根据二进制文件的符号表和调试信息解析得出。
只要符号表可用 (Linux 和 macOS 构建) ，就会填充 `last_error_symbols`。
`last_error_lines` 还需要 DWARF 调试信息——在 Linux 上直接从二进制文件中读取，在 macOS 上则从同一目录下的 `.dSYM` 支持包中读取——因此若无法获取该调试信息，该列为空。在不支持内省的平台上 (例如 FreeBSD) ，这两个数组均为空。
