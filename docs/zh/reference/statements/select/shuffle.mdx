`SHUFFLE` 子句以均匀随机的顺序返回查询结果中的行。它用于替代 [ORDER BY](/zh/reference/statements/select/order-by) 子句，且不能与其同时使用。

它返回的结果与 `ORDER BY rand()` 相同，但时间复杂度为 O(n)，而非 O(n * log(n))。

`SHUFFLE` 可以不带 `LIMIT` 使用，以随机打乱所有行的顺序；也可以与 `LIMIT n` 搭配使用，以获取 `n` 行的均匀随机样本 (同样以随机顺序返回) 。使用 `LIMIT n` 时，每个 stream 仅保留 `n` 行，因此无论查询结果包含多少行，内存使用量均为 O(n)。`OFFSET` 和 `LIMIT BY` 的用法与在 `ORDER BY` 中相同。

<Note>
  这是一项实验性功能。请通过设置 [`allow_experimental_shuffle_query`](/zh/reference/settings/session-settings#allow_experimental_shuffle_query) 启用。
</Note>

## 实现细节 {#implementation-details}

随机选择是即时进行的：不会预先为行生成或存储任何随机值。不带 `LIMIT` 时，每一行会被随机发送到 `max_threads` 个 stream 中的某一个，各个 stream 使用 Fisher-Yates 算法并行打乱 (按能放入 CPU 缓存的分块进行) ，最后将各个 stream 拼接起来。带 `LIMIT n` 时，每个 stream 通过蓄水池采样保留 `n` 行的均匀随机样本，该方法会直接跳过不可能进入样本的行，无需查看这些行；随后再合并各个样本：从每个 stream 中取出的行数，按各 stream 的行数以不放回采样的方式抽取。在分布式查询中，远程服务器会打乱各自的数据，并为行附加已排序的随机键，发起服务器则按这些键合并已打乱的 stream，仅需 O(1) 内存。

不带 `LIMIT` 时，`SHUFFLE` 会将所有行保存在内存中。与 `ORDER BY` 不同，它不会将数据溢写到磁盘。

当随机值未在查询的其他任何位置使用且外部排序已禁用时，`ORDER BY rand()` 和 `ORDER BY rand64()` 可以按与 `SHUFFLE` 相同的方式执行 (由设置 `query_plan_use_shuffle_for_order_by_rand` 控制) 。若已配置外部排序，即使指定了有限的 `LIMIT`，该优化也会被禁用，因为样本仍可能超出内存，而 `SHUFFLE` 无法落盘。带有限 limit 的 `ORDER BY rand64()` 仍会执行排序，以保留随机值的所有位。

## 示例 {#examples}

```sql
SET allow_experimental_shuffle_query = 1;

SELECT number FROM numbers(5) SHUFFLE;
```

```text
┌─number─┐
│      3 │
│      0 │
│      4 │
│      1 │
│      2 │
└────────┘
```

随机抽取的三行样本：

```sql
SELECT number FROM numbers(1000000) SHUFFLE LIMIT 3;
```

```text
┌─number─┐
│ 493721 │
│  20857 │
│ 871324 │
└────────┘
```

在 `FROM` 子句之后，`SHUFFLE` 是关键字。若要将 `shuffle` 用作表别名，请写成 `AS shuffle`。
