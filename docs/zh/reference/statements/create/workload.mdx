引入版本：v24.11.0

创建一个工作负载，即层次结构中的一个节点，[工作负载调度](/zh/concepts/features/configuration/server-config/workload-scheduling)借助该层次结构在各工作负载之间共享资源。待调度的资源通过 [`CREATE RESOURCE`](/zh/reference/statements/create/resource) 创建。

## 语法 {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - 替换现有工作负载的定义。不能与 `IF NOT EXISTS` 同时使用。
* `IF NOT EXISTS` - 如果名为 `name` 的工作负载已存在，则该查询不执行任何操作。
* `IN parent_name` - 将该工作负载创建为工作负载 `parent_name` 的子工作负载。未指定 `IN` 的工作负载为根工作负载。工作负载之间若形成环，则会被拒绝。
* `SETTINGS` - 工作负载的调度设置，例如 `weight`、`priority`、`max_concurrent_threads` 或 `max_bytes_per_second`，详见[工作负载层次结构](/zh/concepts/features/configuration/server-config/workload-scheduling#workloads)。带有 `FOR resource_name` 的设置仅作用于该资源，否则作用于所有资源。指定未知设置会报错。

工作负载和资源使用各自独立的命名空间，因此工作负载和资源可以同名。查询会在其 [`workload`](/zh/reference/settings/session-settings/other#workload) 设置所指定的工作负载中运行，参见[工作负载标记](/zh/concepts/features/configuration/server-config/workload-scheduling#workload-markup)。

<Note>
  内存预留调度目前为实验性功能，包括 `MEMORY RESERVATION` 资源以及工作负载设置 `max_memory`、`max_memory_ratio`、`max_memory_before_spill` 和 `max_memory_to_spill_ratio`。参见[内存预留](/zh/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)。
</Note>

## 存储 {#storage}

工作负载存储在磁盘上的 [`workload_path`](/zh/reference/settings/server-settings/settings/workload#workload_path) 中；如果设置了 [`workload_zookeeper_path`](/zh/reference/settings/server-settings/settings/workload#workload_zookeeper_path)，则存储在 ZooKeeper 中的该路径下。使用 ZooKeeper 存储时，`ON CLUSTER` 会被拒绝，因为这些定义会自动以副本形式同步。[在服务器配置中定义的](/zh/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads)工作负载无法通过 SQL 替换或删除。[`system.workloads`](/zh/reference/system-tables/workloads) 表列出了所有工作负载。

## 特权 {#privileges}

执行 `CREATE WORKLOAD` 需要 `CREATE WORKLOAD` 特权。执行 `CREATE OR REPLACE WORKLOAD` 还需要 `DROP WORKLOAD` 特权。

## 示例 {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
