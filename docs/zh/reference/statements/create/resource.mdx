引入版本：v24.11.0

为[工作负载调度](/zh/concepts/features/configuration/server-config/workload-scheduling)创建资源。资源是一种访问类型 (例如磁盘读取或 CPU 时间) ，会在通过 [`CREATE WORKLOAD`](/zh/reference/statements/create/workload) 创建的各个工作负载之间进行调度。

## 语法 {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`、`IF NOT EXISTS` 和 `ON CLUSTER` 的用法与 [`CREATE WORKLOAD`](/zh/reference/statements/create/workload#syntax) 中的相同。

## 访问模式 {#access-modes}

| 访问模式                                          | 受调度的访问                                                                                                   | 引入版本     |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------- | -------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | 读取或写入磁盘 `disk_name`，参见[资源](/zh/concepts/features/configuration/server-config/workload-scheduling#resources) | v24.11.0 |
| `READ ANY DISK`, `WRITE ANY DISK`             | 读取或写入任意磁盘                                                                                                | v24.11.0 |
| `MASTER THREAD`, `WORKER THREAD`              | CPU，参见[CPU 调度](/zh/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)        | v25.4.0  |
| `QUERY`                                       | 查询槽位，参见[查询槽位调度](/zh/concepts/features/configuration/server-config/workload-scheduling#query_scheduling)     | v25.6.0  |
| `MEMORY RESERVATION`                          | 内存，参见[内存预留](/zh/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)      | v26.6.2  |

同一资源的访问模式必须属于同一类型：磁盘、CPU 线程、`QUERY` 或 `MEMORY RESERVATION`。`MASTER THREAD`、`WORKER THREAD`、`QUERY` 和 `MEMORY RESERVATION` 各自最多只能归属于一个资源。`CREATE OR REPLACE RESOURCE` 无法更改资源的类型，如需更改，请先删除该资源再重新创建。

<Note>
  `MEMORY RESERVATION` 为实验性功能，其 SQL 接口和行为可能会在未来的发行版中发生变化。
</Note>

## 存储 {#storage}

资源的存储方式与工作负载相同，详见[存储](/zh/reference/statements/create/workload#storage)。[`system.resources`](/zh/reference/system-tables/resources) 表列出了所有资源。

## 特权 {#privileges}

执行 `CREATE RESOURCE` 需要 `CREATE RESOURCE` 特权。执行 `CREATE OR REPLACE RESOURCE` 还需要 `DROP RESOURCE` 特权。

## 示例 {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
