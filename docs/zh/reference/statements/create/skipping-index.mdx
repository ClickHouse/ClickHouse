引入版本：v22.7.0

为 `MergeTree` 系列的表添加[数据跳过索引](/zh/reference/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-data_skipping-indexes)。它是 [`ALTER TABLE ... ADD INDEX`](/zh/reference/statements/alter/skipping-index#add-index) 的独立形式，所需特权与其相同，均为 `ALTER ADD INDEX`。

## 语法 {#syntax}

```sql
CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [db.]table [ON CLUSTER cluster] expression TYPE type [GRANULARITY value]
```

* `expression` - 要索引的表达式，可以用括号括起来。带括号的列表 `(expr1, expr2, ...)` 会基于其中所有表达式创建一个索引，效果与 `CREATE TABLE` 中的 `INDEX name (expr1, expr2, ...)` 相同。
* `TYPE type [GRANULARITY value]` - 与 `CREATE TABLE` 的 `INDEX` 子句相同，参见[跳过索引类型](/zh/reference/engines/table-engines/mergetree-family/mergetree#skip-index-types)。
* `IF NOT EXISTS` - 如果表中已存在名为 `name` 的索引，则该查询不执行任何操作。

与 `ADD INDEX` 一样，该语句仅修改表的元数据。若要为表中已有的数据构建索引，请运行 [`ALTER TABLE ... MATERIALIZE INDEX`](/zh/reference/statements/alter/skipping-index#materialize-index)。

## SQL 兼容性 {#sql-compatibility}

为了与其他数据库系统兼容：

* 括号列表中各表达式后的 `ASC` 和 `DESC` 会被忽略。
* 除非将 [`create_index_ignore_unique`](/zh/reference/settings/session-settings/create#create_index_ignore_unique) 设为 `1`，否则 `CREATE UNIQUE INDEX` 会被拒绝。设为 `1` 后，`UNIQUE` 会被忽略，并创建一个普通索引。
* 除非将 [`allow_create_index_without_type`](/zh/reference/settings/session-settings/allow#allow_create_index_without_type) 设为 `1`，否则未指定 `TYPE` 的 `CREATE INDEX` 会被拒绝。设为 `1` 后，该查询不会执行任何操作。

## 示例 {#example}

```sql title="Query"
CREATE TABLE t (id UInt64, s String) ENGINE = MergeTree ORDER BY id;
INSERT INTO t SELECT number, toString(number) FROM numbers(1000);
CREATE INDEX idx_s ON t (s) TYPE bloom_filter GRANULARITY 1;
ALTER TABLE t MATERIALIZE INDEX idx_s SETTINGS mutations_sync = 1;
SELECT name, type, expr, granularity FROM system.data_skipping_indices WHERE database = currentDatabase() AND table = 't';
```

```text title="Response"
┌─name──┬─type─────────┬─expr─┬─granularity─┐
│ idx_s │ bloom_filter │ s    │           1 │
└───────┴──────────────┴──────┴─────────────┘
```
