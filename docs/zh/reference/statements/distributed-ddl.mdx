默认情况下，`CREATE`、`DROP`、`ALTER` 和 `RENAME` 查询仅会影响执行它们的当前服务器。在集群环境中，可以通过 `ON CLUSTER` 子句以分布式方式执行这类查询。

例如，以下查询会在 `cluster` 中的每个主机上创建 `all_hits` `Distributed` 表：

```sql
CREATE TABLE IF NOT EXISTS all_hits ON CLUSTER cluster (p Date, i Int32) ENGINE = Distributed(cluster, default, hits)
```

为了让这些查询正确运行，每台主机都必须具有相同的集群定义 (为简化配置同步，你可以使用 ZooKeeper 中的替换) 。它们还必须连接到 ZooKeeper 服务器。

通常情况下，查询的本地版本最终会在集群中的每台主机上执行，即使某些主机当前不可用。不过，这些查询会存放在队列中，而条目在队列中的保留时间受[若干设置](/zh/reference/settings/server-settings/settings/distributed)限制。因此，如果某台主机长时间不可用，那么在它恢复可用后，可能不会再执行该查询。

<Warning>
  只要将 [distributed&#95;ddl.pool&#95;size](/zh/reference/settings/server-settings/settings/distributed#distributed_ddl.pool_size) 设置为 1，就能保证查询在单台主机内按顺序执行。
</Warning>

**语法**

```sql
<query> ... ON CLUSTER cluster ...
```

**相关：** `CREATE`、`DROP`、`ALTER`、`RENAME`、`SYSTEM`
