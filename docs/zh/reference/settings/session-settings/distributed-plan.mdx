## distributed_plan_exchange_compression_method {#distributed_plan_exchange_compression_method}

<ExperimentalBadge />

<SettingsInfoBlock type="String" default_value="LZ4" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "LZ4"},{"label": "新增设置：分布式查询计划的流式数据 exchange 改用 `LZ4` 压缩，不再沿用 `network_compression_method` 所指定的编解码器。"}]}]} />

指定分布式查询计划中各任务之间进行流式数据 exchange 时，用于压缩数据包的编解码器。通过临时 File 进行的 exchange 则使用服务器的默认编解码器。

可选值：

* `''` — 使用 [network&#95;compression&#95;method](/zh/reference/settings/session-settings/network#network_compression_method) 所指定的编解码器。
* `NONE` — 不压缩。
* `LZ4` — 使用 LZ4 编解码器。
* `LZ4HC` — 使用 LZ4HC 编解码器，采用其默认级别 9。压缩速度比 `LZ4` 慢数倍。
* `ZSTD` — 使用 ZSTD 编解码器，压缩级别由 [distributed&#95;plan&#95;exchange&#95;zstd&#95;compression&#95;level](/zh/reference/settings/session-settings/distributed-plan#distributed_plan_exchange_zstd_compression_level) 指定。

## distributed_plan_partial_aggregation_before_shuffle {#distributed_plan_partial_aggregation_before_shuffle}

<BetaBadge />

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1"},{"label": "新增实验性设置：分布式聚合在 shuffle 时传输部分聚合状态，而非输入行。"}]}]} />

在分布式聚合按 `GROUP BY` 键对数据进行 shuffle 之前，先在读取数据的节点上执行部分聚合。这样，shuffle 时每个节点对每个分组只发送一个聚合状态，而无需发送全部输入行；之后每个桶再合并各自键对应的状态。
如果列统计信息表明部分聚合无法将数据量至少减半，基于规则的查询规划器仍会对输入行进行 shuffle。启用 `enable_cascades_optimizer` 时，该设置允许优化器根据代价决定是否在每个桶中采用这种合并方式。
仅在同时设置 `make_distributed_plan = 1` 时生效；若启用了 `distributed_plan_force_shuffle_aggregation` (该设置会对输入行进行 shuffle) ，则此设置不生效。

## distributed_plan_read_in_order {#distributed_plan_read_in_order}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "新增设置，用于在分布式查询计划中为 `ORDER BY` 启用 read-in-order 优化，使按表 sorting key 进行的有序读取可以跳过排序并提前结束。默认关闭：目前仅当读取与排序之间不残留 exchange 的形态下才是安全的。"}]}]} />

允许在分布式查询计划中为 `ORDER BY` 启用 read-in-order 优化，使按表 sorting key 进行的有序读取可以跳过排序并提前结束，而无需先扫描再排序。

默认关闭：将排序分布式化的 rewrite 假定其所包裹的排序不依赖输入本身已经有序，而这类依赖有序输入的排序有可能通过不保序的 exchange 获取行。目前仅当读取与排序之间不残留 exchange 的形态下才是安全的。
