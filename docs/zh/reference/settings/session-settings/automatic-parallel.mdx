## automatic_parallel_replicas_ignore_thresholds {#automatic_parallel_replicas_ignore_thresholds}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新增设置：用于测试，忽略自动并行副本成本模型中的读取线程上限，使小规模读取由比较结果决定，而不是被该上限直接短路。"}]}]} />

用于测试自动并行副本成本模型：忽略单次读取可有效占用的线程数上限 (由 `merge_tree_min_bytes_per_task_for_remote_reading` 推导得出) 。若不忽略该上限，对于规模过小、无法占满 `max_threads` 的读取，它会将比较两侧都限制为同一个值，使比较退化为 `0 > output_bytes / replicas`，导致查询在参考成本模型之前就已被决定。

此设置刻意**不**影响 `automatic_parallel_replicas_min_bytes_per_replica`：如需禁用该启用条件，请将其设为 0，这正是该设置的用途。此设置也不会改变读取任务的资源规模规划，也不会阻止重新收集已发生漂移的统计信息——基于过时统计信息做出的决定，并非由成本模型做出的决定。

## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "如果某个查询有超过一半的读取需要在每个副本上重复执行，自动并行副本现在会拒绝该查询。此前没有任何限制，设为 1 即可保持原有行为。"}]}]} />

在自动并行副本拒绝某个查询之前，该查询的读取量中允许由每个副本各自完整读取 (而非在副本之间拆分) 的部分占总量的最大比例。

只有由并行副本协调的读取会被拆分；同一子树中的其他读取都会在每个副本上完整执行。无论是否启用并行副本，这些读取耗费的挂钟时间都相同，因此成本模型在比较时无法将其纳入考量，但集群为此付出的工作量却是原来的 `max_parallel_replicas` 倍。此设置正是用来限制这种浪费：在默认值 0.5 下，如果某个查询中协调式读取不到其总读取量的一半，那么无论时间比较结果如何，该查询都会继续在单个节点上运行。

设为 1 表示接受任意比例的重复读取，即恢复为仅比较时间的行为。

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "新增设置"}]}]} />

根据已收集的统计信息，启用自动切换为使用并行副本执行。要求 `enable_parallel_replicas = 1`、`parallel_replicas_local_plan = 1`，并提供 `cluster_for_parallel_replicas`。当 `enable_parallel_replicas = 2` 时，将强制使用并行副本，自动模式不会生效。
0 - 禁用，1 - 启用，2 - 仅启用统计信息收集 (不切换为使用并行副本执行) 。

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新增设置。自动并行副本现在会按执行计划记住副本所承担工作部分的边界；此前，每个查询都必须使用并行副本构建执行计划才能确定该边界。"}]}]} />

允许自动并行副本按执行计划记住副本所承担工作部分的结束位置。这样，对于根据统计信息判定不使用并行副本的重复查询，
无需再使用并行副本构建执行计划即可做出决策。

禁用已记住的边界。要对使用并行副本构建执行计划的开销进行基准测试，还需设置
`automatic_parallel_replicas_undecided_retry_after_executions = 0`：无论此设置如何，上次构建结束时未能做出
决策的执行计划都会被跳过。

## automatic_parallel_replicas_statistics_drift_ratio {#automatic_parallel_replicas_statistics_drift_ratio}

<SettingsInfoBlock type="Float" default_value="1.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1.5"},{"label": "新增设置。该比率此前固定为 2 且无法更改；现在数据发生变化时，统计信息会更早地重新收集。"}]}]} />

一次读取所选中的行数，与自动并行副本收集统计信息时该读取所选中的行数之间允许的偏差，以较大值与较小值之比表示。超出该比率后，统计信息将被视为过时并重新收集，而不再据此做出决策。

这里的行是指发起服务器的索引分析所选中的行，因此仅由副本在读取过程中执行的裁剪 (例如借助各副本自身的查询条件缓存) 不会被计入。比率越低，表发生变化时统计信息就越早重新收集。该值应大于 1。

## automatic_parallel_replicas_undecided_retry_after_executions {#automatic_parallel_replicas_undecided_retry_after_executions}

<SettingsInfoBlock type="UInt64" default_value="10" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "10"},{"label": "新增设置。如果某个查询计划的上一次构建未能作出决策，自动并行副本现在会在该查询计划随后的若干次执行中跳过构建带并行副本的执行计划；此前每次执行都会构建。"}]}]} />

在自动并行副本中，如果某个查询计划的上一次构建未能作出决策，该设置决定该查询计划随后有多少次执行会跳过构建带并行副本的执行计划。未能作出决策的情况包括：两个执行计划无法比较；查询规划器在使用并行副本构建的执行计划中实际并未使用并行副本
；执行计划中的某个步骤无法收集统计信息；或收集过程未测得任何数据。并发执行会轮流进行：每 `automatic_parallel_replicas_undecided_retry_after_executions + 1` 次执行中有一次会重新构建该执行计划。
某个查询计划首次出现此类结果后，下一次执行会立即重新构建执行计划，以防第一次执行填充了其他统计信息缓存，从而改变规划决策。

设为 0 表示禁用未决策后的延迟机制。该设置与 `automatic_parallel_replicas_remember_boundary` 相互独立，后者会让基于统计信息作出决策的执行计划免于重复构建。
