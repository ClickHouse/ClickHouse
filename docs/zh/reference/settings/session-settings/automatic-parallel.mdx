## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "如果某个查询有超过一半的读取需要在每个副本上重复执行，自动并行副本现在会拒绝该查询。此前没有任何限制，设为 1 即可保持原有行为。"}]}]} />

在自动并行副本拒绝某个查询之前，该查询的读取量中允许由每个副本各自完整读取 (而非在副本之间拆分) 的部分占总量的最大比例。

只有由并行副本协调的读取会被拆分；同一子树中的其他读取都会在每个副本上完整执行。无论是否启用并行副本，这些读取耗费的挂钟时间都相同，因此成本模型在比较时无法将其纳入考量，但集群为此付出的工作量却是原来的 `max_parallel_replicas` 倍。此设置正是用来限制这种浪费：在默认值 0.5 下，如果某个查询中协调式读取不到其总读取量的一半，那么无论时间比较结果如何，该查询都会继续在单个节点上运行。

设为 1 表示接受任意比例的重复读取，即恢复为仅比较时间的行为。

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.1"},{"label": "1048576"},{"label": "根据测试结果调整后的更优默认值"}]}, {"id": "row-2","items": [{"label": "25.12"},{"label": "0"},{"label": "新增设置"}]}]} />

用于自动启用并行副本的每个副本读取字节数阈值 (仅在 `automatic_parallel_replicas_mode`=1 时适用) 。0 表示不设阈值。
待读取的总字节数会根据已收集的统计信息进行估算。

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "新增设置"}]}]} />

根据已收集的统计信息，启用自动切换为使用并行副本执行。要求 `enable_parallel_replicas = 1`、`parallel_replicas_local_plan = 1`，并提供 `cluster_for_parallel_replicas`。当 `enable_parallel_replicas = 2` 时，将强制使用并行副本，自动模式不会生效。
0 - 禁用，1 - 启用，2 - 仅启用统计信息收集 (不切换为使用并行副本执行) 。

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新增设置。自动并行副本现在会按查询计划记住副本所承担工作部分的边界；此前，每个查询都必须使用并行副本构建查询计划才能确定该边界。"}]}]} />

允许自动并行副本按查询计划记住副本所承担工作部分的结束位置。这样，对于根据统计信息判定不使用并行副本的重复查询，
无需再使用并行副本构建查询计划即可做出决策。

禁用此设置后，每个查询都需承担该决策的全部开销，适用于对该开销进行基准测试等场景。
