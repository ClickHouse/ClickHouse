## cluster_table_function_split_by_split_offsets {#cluster_table_function_split_by_split_offsets}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新增设置。"}]}]} />

当拆分粒度为 `bucket` 时，如果表元数据中记录了文件大小和行组偏移量 (即 Iceberg 中的 `split_offsets`) ，则无需读取文件，直接按这些偏移量将文件截断为若干字节范围；每个任务读取起始位置落在其范围内的行组。在其他情况下，以及命中查询条件缓存时，发起服务器会读取每个文件的页脚。

此设置要求集群中的所有服务器均支持该功能：带有字节范围的任务无法发送到旧版本的服务器。

## cluster_table_function_split_granularity {#cluster_table_function_split_granularity}

<SettingsInfoBlock type="ObjectStorageGranularityLevel" default_value="file" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.11"},{"label": "file"},{"label": "新增设置。"}]}]} />

控制在执行 cluster 表函数 时，如何将数据拆分为任务。

此设置定义了在集群中分发工作的粒度：

* `file` — 每个任务处理整个文件。
* `bucket` — 按文件内部的数据块创建任务 (例如 Parquet 行组) 。

处理少量大文件时，选择更细的粒度 (如 `bucket`) 可以提高并行度。
例如，如果一个 Parquet 文件包含多个行组，启用 `bucket` 粒度后，每个行组都可以由不同的工作线程独立处理。
