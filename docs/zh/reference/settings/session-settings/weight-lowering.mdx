## weight_lowering_cpu_seconds {#weight_lowering_cpu_seconds}

<SettingsInfoBlock type="Double" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "新的查询设置：在 `fair` 工作负载调度器中，查询累计获得的 CPU 秒数达到该阈值后，其权重将被降低。"}]}]} />

适用于 `fair` 工作负载调度器：当查询累计获得的 CPU 秒数达到该值后，其权重将按 `weight_lowering_factor` 降低。此设置作用于 CPU 资源。设置为 `0` (或任意负值) 时将禁用该 CPU 阈值。累计 CPU 指调度器已授予的服务量，在请求被授予时即计入，而不是在实际消耗 CPU 时才计入，因此每个活跃插槽最多会比实际消耗超前一个时间量子 (`cpu_slot_quantum_ns`) 。此设置仅在启用 CPU 插槽抢占 (`cpu_slot_preemption = 1`，即默认值) 时才有意义；若未启用抢占，CPU 插槽按每个插槽的固定开销计费，而非按实际 CPU 时间计费，因此该阈值 (与其他 `fair` CPU 设置一样) 将无法反映实际的 CPU 消耗。

## weight_lowering_factor {#weight_lowering_factor}

<SettingsInfoBlock type="Double" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新增查询设置：在 `fair` 工作负载调度器中，查询一旦超过权重降低阈值，即对其权重应用该系数。"}]}]} />

适用于 `fair` 工作负载调度器：一旦查询超过下方任一 `weight_lowering_*` 阈值，其有效权重就会乘以该系数 (仅乘一次) 。取值在 (0, 1) 之间时会降低权重，使调度偏向较短或较新的查询。各阈值的效果不会叠加——最先触发的阈值即施加全部降幅。设为 `1.0` 表示禁用权重降低。该值会被限制在 `[0, 1]` 范围内，因此该系数只会降低查询的权重，而不会提高权重。

## weight_lowering_io_bytes {#weight_lowering_io_bytes}
