## insert_allow_materialized_columns {#insert_allow_materialized_columns}

<SettingsInfoBlock type="Bool" default_value="0" />

启用后，可以在 `INSERT` 查询的列列表中列出 `MATERIALIZED` 列，插入的值将被直接存储，而不是根据列表达式计算得出。对于分布式表，`MATERIALIZED` 列的值随后也会被发送到各个分片。

禁用后，在 `INSERT` 查询中列出 `MATERIALIZED` 列会抛出异常，此类列的值始终根据其表达式计算得出。

## insert_deduplicate {#insert_deduplicate}

<SettingsInfoBlock type="Bool" default_value="1" />

启用或禁用 `INSERT` 的块去重 (适用于复制表) 。

仅当 [`deduplicate_insert`](/zh/reference/settings/session-settings/deduplicate-insert#deduplicate_insert) 设置为 `backward_compatible_choice` 时，此设置才会生效。

可能的值：

* 0 — 禁用。
* 1 — 启用。

默认情况下，通过 `INSERT` 语句插入到复制表中的块会进行去重 (请参见 [Data Replication](/zh/reference/engines/table-engines/mergetree-family/replication)) 。
对于复制表，默认情况下每个分区仅对最近的 100 个块进行去重 (请参见 [replicated&#95;deduplication&#95;window](/zh/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window)、[replicated&#95;deduplication&#95;window&#95;seconds](/zh/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window_seconds)) 。
对于非复制表，请参见 [non&#95;replicated&#95;deduplication&#95;window](/zh/reference/settings/merge-tree-settings/other#non_replicated_deduplication_window)。

## insert_deduplication_token {#insert_deduplication_token}

该设置允许用户在 MergeTree/ReplicatedMergeTree 中自定义去重语义。
例如，在每条 INSERT 语句中为该设置提供一个唯一值，
即可避免相同的插入数据被去重。

可能的值：

* 任意字符串

只有当 `insert_deduplication_token` 非空时，才会将其用于去重。

对于复制表，默认每个分区仅会对最近 100 次插入进行去重 (参见 [replicated&#95;deduplication&#95;window](/zh/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window)、[replicated&#95;deduplication&#95;window&#95;seconds](/zh/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window_seconds)) 。
对于非复制表，请参见 [non&#95;replicated&#95;deduplication&#95;window](/zh/reference/settings/merge-tree-settings/other#non_replicated_deduplication_window)。

<Note>
  `insert_deduplication_token` 是按分区跟踪的，因此一次 insert 写入的多个分区可以携带相同的 token。若未提供 token，系统默认会基于整个插入块计算内容校验和，因此只有当某次 insert 的全部数据都与之前某次 insert (即重试) 完全一致时，才会被去重；如果只是某个分区中的行恰好与另一条不同的 insert 一致，则不会被去重。
</Note>

示例：

```sql
CREATE TABLE test_table
( A Int64 )
ENGINE = MergeTree
ORDER BY A
SETTINGS non_replicated_deduplication_window = 100;

INSERT INTO test_table SETTINGS insert_deduplication_token = 'test' VALUES (1);

-- the next insert won't be deduplicated because insert_deduplication_token is different
INSERT INTO test_table SETTINGS insert_deduplication_token = 'test1' VALUES (1);

-- the next insert will be deduplicated because insert_deduplication_token
-- is the same as one of the previous
INSERT INTO test_table SETTINGS insert_deduplication_token = 'test' VALUES (2);

SELECT * FROM test_table

┌─A─┐
│ 1 │
└───┘
┌─A─┐
│ 1 │
└───┘
```

## insert_null_as_default {#insert_null_as_default}

<SettingsInfoBlock type="Bool" default_value="1" />

启用或禁用：向非 [Nullable](/zh/reference/data-types/nullable) 数据类型的列中插入数据时，使用 [默认值](/zh/reference/statements/create/table#default_values) 替代 [NULL](/zh/reference/syntax#null)。
如果列类型不是 Nullable 且此设置被禁用，则插入 `NULL` 会导致异常。如果列类型是 Nullable，则无论此设置如何，`NULL` 值都会按原样插入。

此设置适用于 [INSERT ... SELECT](/zh/reference/statements/insert-into#inserting-the-results-of-select) 查询。请注意，`SELECT` 子查询可以使用 `UNION ALL` 子句进行拼接。

可能的值：

* 0 — 向非 Nullable 列插入 `NULL` 会导致异常。
* 1 — 插入列的默认值而不是 `NULL`。

## insert_shard_id {#insert_shard_id}

<SettingsInfoBlock type="UInt64" default_value="0" />

如果不为 `0`，则指定将数据同步插入到 [Distributed](/zh/reference/engines/table-engines/special/distributed) 表中的哪个分片。

如果 `insert_shard_id` 的值不正确，服务器将抛出异常。

要获取 `requested_cluster` 中的分片数量，可以检查服务器配置，或使用以下查询：

```sql
SELECT uniq(shard_num) FROM system.clusters WHERE cluster = 'requested_cluster';
```

可选值：

* 0 — 已禁用。
* 对应的 [Distributed](/zh/reference/engines/table-engines/special/distributed) 表中，从 `1` 到 `shards_num` 之间的任意数字。

**示例**

查询：

```sql
CREATE TABLE x AS system.numbers ENGINE = MergeTree ORDER BY number;
CREATE TABLE x_dist AS x ENGINE = Distributed('test_cluster_two_shards_localhost', currentDatabase(), x);
INSERT INTO x_dist SELECT * FROM numbers(5) SETTINGS insert_shard_id = 1;
SELECT * FROM x_dist ORDER BY number ASC;
```

结果：

```text
┌─number─┐
│      0 │
│      0 │
│      1 │
│      1 │
│      2 │
│      2 │
│      3 │
│      3 │
│      4 │
│      4 │
└────────┘
```

## insert_squashing_max_memory_ratio {#insert_squashing_max_memory_ratio}

<SettingsInfoBlock type="Double" default_value="0.1125" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0.1125"},{"label": "新增设置。此前 `min_insert_block_size_bytes` 受内存限制约束的上限被硬编码为该限制的 0.9 \/ 8；现已改为可配置。"}]}]} />

在 `INSERT` 的各个合并阶段中，将 `min_insert_block_size_bytes` 的上限限制为服务器内存限制 (`max_server_memory_usage`) 乘以此比例。这些阶段包括：目标表的合并、依赖物化视图结果的合并，以及简单 `INSERT ... SELECT` 中 source 的块大小。

一个合并阶段持有的并非单个大小为 `min_insert_block_size_bytes` 的块，而是多个：在拼接前一个块的同时会累积下一个块，拼接后的块仍驻留在数据接收端中；此外，块按逻辑大小计量，而其底层数组的容量会向上取整。在内存较小的服务器上，这可能导致 `INSERT` 因 `MEMORY_LIMIT_EXCEEDED` 而失败。使用默认的 `min_insert_block_size_bytes` 时，只有当内存限制低于约 2.2 GiB 时，该默认值才会真正起到限制作用；设置更低的值 (例如 `0.0625`) 有助于让写入宽表的 `INSERT` 在小型服务器的内存范围内完成。

该上限仅取决于内存限制和此设置，与物化视图或插入流的数量无关。请注意，内存限制可能在运行时发生变化 (参见 `memory_worker_dynamic_hard_limit`) ；当该上限生效时，重试的 `INSERT` 拆分块的方式可能与首次尝试不同。

可选值：`0` 到 `1`。设置为 `0` 可禁用该上限。
