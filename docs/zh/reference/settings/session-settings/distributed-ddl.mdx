## distributed_ddl_entry_format_version {#distributed_ddl_entry_format_version}

<SettingsInfoBlock type="UInt64" default_value="5" />

分布式 DDL (ON CLUSTER) 查询的兼容性版本。使用较低的值可确保集群中较旧的服务器仍能
执行这些查询。

服务器不会执行版本为 `1` 和 `2` 的条目。当设置值为 `1`、`2`
或 `3` 时，较旧的服务器会写入这些版本的条目，因此在升级之前，请在所有服务器上将此设置设为至少 `4`，并等待分布式 DDL
队列处理完毕。

可选值：

* `3` — 与 `4` 相同。条目会以版本 `4` 写入，因为较旧的服务器会拒绝版本为 `3` 的条目。
* `4` — 条目携带会话中更改过的设置以及 OpenTelemetry 追踪上下文，且 `CREATE` 查询会在发起服务器上进行归一化。
* `5` — 额外保留查询的 `initial_query_id`。
* `6` — 额外携带该查询是否属于 `BACKUP` 或 `RESTORE` 操作的信息。
* `7` — 额外携带父表的 UUID，`Replicated` 数据库据此仅在该表存在时才执行查询。
* `8` — 额外携带发起服务器的用户和角色，各主机会结合服务器设置 `distributed_ddl_use_initial_user_and_roles` 使用这些信息。

Cloud 默认值：`6`。

## distributed_ddl_output_mode {#distributed_ddl_output_mode}

<SettingsInfoBlock type="DistributedDDLOutputMode" default_value="throw" />

设置分布式 DDL 查询结果的格式。

可选值：

* `throw` — 返回结果集，其中包含查询已执行完成的所有 hosts 的查询执行状态。如果查询在某些 hosts 上失败，则会重新抛出第一个异常。如果查询在某些 hosts 上尚未完成，并且已超出 [distributed&#95;ddl&#95;task&#95;timeout](/zh/reference/settings/session-settings/distributed-ddl#distributed_ddl_task_timeout)，则会抛出 `TIMEOUT_EXCEEDED` 异常。
* `none` — 类似于 `throw`，但分布式 DDL 查询不返回结果集。
* `null_status_on_timeout` — 如果查询在相应的 hosts 上尚未完成，则在结果集的某些行中返回 `NULL` 作为执行状态，而不是抛出 `TIMEOUT_EXCEEDED`。
* `never_throw` — 如果查询在某些 hosts 上失败，则既不抛出 `TIMEOUT_EXCEEDED`，也不重新抛出异常。
* `none_only_active` - 类似于 `none`，但不会等待 `Replicated` 数据库的非活动副本。注意：在此模式下，无法判断查询是否未在某个副本上执行，而是将在后台执行。
* `null_status_on_timeout_only_active` — 类似于 `null_status_on_timeout`，但不会等待 `Replicated` 数据库的非活动副本
* `throw_only_active` — 类似于 `throw`，但不会等待 `Replicated` 数据库的非活动副本

Cloud 默认值：`none_only_active`。

## distributed_ddl_task_timeout {#distributed_ddl_task_timeout}

<SettingsInfoBlock type="Int64" default_value="180" />

设置集群中所有主机返回 DDL 查询响应的超时时间。如果某个 DDL 请求尚未在所有主机上执行完成，响应中将包含超时错误，并且该请求将以异步模式执行。负值表示无限。

可能的值：

* 正整数。
* 0 — 异步模式。
* 负整数 — 无限超时。
