## use_statistics_for_min_max_aggregation {#use_statistics_for_min_max_aggregation}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "1"},{"label": "新增设置：对于不含 `GROUP BY` 和过滤器的 `min`、`max` 和 `count` 聚合，可直接利用各 part 的列统计信息得出结果（仅限已 materialized 统计信息的 parts），其余 parts 才需读取数据。previous_value=false，因此将 `compatibility` 设置为 26.9 之前的版本时会禁用该优化，恢复原有的执行 plan。"}]}]} />

直接利用各 part 的列统计信息得出 `min`、`max` 和 `count` 聚合结果，而无需读取数据。

启用后，形如 `SELECT min(column), max(column), count() FROM table` 且不含 `GROUP BY` 和过滤器的查询，
对于已 materialized 列统计信息 (例如 MinMax 统计信息，参见 `auto_statistics_types` MergeTree 设置) 的数据 parts，
将直接由列统计信息得出结果，其余 parts 才会被读取。

可能的值：

* 0 — 禁用。
* 1 — 启用。

## use_statistics_for_part_pruning {#use_statistics_for_part_pruning}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "1"},{"label": "在查询执行期间使用统计信息进行 part pruning 的新设置。"}]}]} />

在查询执行期间使用统计信息过滤 parts。

启用后，SELECT 查询中的 pruning 会使用列统计信息 (例如 MinMax 统计信息) ，在读取任何数据之前剔除不可能包含匹配数据的 parts。

可能的值：

* 0 — 已禁用。
* 1 — 已启用。
