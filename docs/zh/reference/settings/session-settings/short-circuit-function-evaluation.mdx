## short_circuit_function_evaluation {#short_circuit_function_evaluation}

<SettingsInfoBlock type="ShortCircuitFunctionEvaluation" default_value="enable" />

允许按照[短路求值](https://en.wikipedia.org/wiki/Short-circuit_evaluation)机制计算 [if](/zh/reference/functions/regular-functions/conditional-functions#if)、[multiIf](/zh/reference/functions/regular-functions/conditional-functions#multiIf)、[and](/zh/reference/functions/regular-functions/logical-functions#and) 和 [or](/zh/reference/functions/regular-functions/logical-functions#or) 函数。这有助于优化这些函数中复杂表达式的执行，并防止可能出现的异常 (例如在不应发生时出现除零) 。

Possible values:

* `enable` — 对适合使用短路求值的函数启用短路函数求值 (可能抛出异常或计算开销较大) 。
* `force_enable` — 对所有函数启用短路函数求值。
* `disable` — 禁用短路函数求值。

## short_circuit_function_evaluation_for_nulls {#short_circuit_function_evaluation_for_nulls}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.1"},{"label": "1"},{"label": "仅在所有参数均为非 NULL 值的行上执行带有 Nullable 参数的函数"}]}]} />

优化对以下函数的求值：只要任一参数为 NULL，就返回 NULL 的函数。当函数参数中的 NULL 值占比超过 short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls&#95;threshold 时，系统会跳过按行求值。相反，它会直接为所有行返回 NULL，从而避免不必要的计算。

此设置仅控制一项优化。对于无法在其参数默认值上执行的函数——例如 `parseDateTime`、`IPv4StringToNum` 或 `intDiv`——无论该设置如何，都会始终跳过包含 NULL 的行，因为 NULL 背后存储的值是该参数类型的默认值，在其上执行会对本来有效的数据抛出异常。

## short_circuit_function_evaluation_for_nulls_threshold {#short_circuit_function_evaluation_for_nulls_threshold}

仅对所有参数均为非 NULL 值的行执行带有 Nullable 参数的函数时，NULL 值所占的比例阈值。仅在启用设置 short&#95;circuit&#95;function&#95;evaluation&#95;for&#95;nulls 时生效。
当包含 NULL 值的行占总行数的比例超过此阈值时，这些包含 NULL 值的行将不再参与计算。

## short_circuit_function_evaluation_reorder_arguments {#short_circuit_function_evaluation_reorder_arguments}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "新增设置。"}]}]} />

在使用[短路求值](/zh/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation)时，只要不改变结果且不会引入异常，允许调整 [and](/zh/reference/functions/regular-functions/logical-functions#and) 和 [or](/zh/reference/functions/regular-functions/logical-functions#or) 函数中各参数的求值顺序。

* 如果第一个参数计算开销较大，而另一个参数开销较小，则先对开销小的参数求值，开销大的参数仅在结果尚未确定的行上求值。例如，对于 `WHERE JSONExtractString(json, 'a') = 'x' AND id < 100`，只会对满足 `id < 100` 的行解析 JSON。
* 对于惰性求值且不会抛出异常的参数，将根据在先前块上测得的“每确定一行结果所需的时间”，按从小到大的顺序求值。对于可能抛出异常的参数，排在它之前的所有参数都会继续保持在它前面。因此，像 `x != 0 AND intDiv(1, x) > 0` 这样的表达式永远不会出现除以零的情况。
