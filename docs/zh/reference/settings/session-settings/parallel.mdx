## parallel_distributed_insert_select {#parallel_distributed_insert_select}

<SettingsInfoBlock type="UInt64" default_value="2" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.7"},{"label": "2"},{"label": "默认启用并行分布式 `INSERT ... SELECT`"}]}]} />

启用并行分布式 `INSERT ... SELECT` 查询。

如果执行 `INSERT INTO distributed_table_a SELECT ... FROM distributed_table_b` 查询，并且两张表使用同一个集群，且两张表要么都是 [复制表](/zh/reference/engines/table-engines/mergetree-family/replication)，要么都是非复制表，那么该查询会在每个分片上本地处理。

可选值：

* `0` — 禁用。
* `1` — `SELECT` 将在每个分片上针对分布式引擎的底层表执行。
* `2` — `SELECT` 和 `INSERT` 都将在每个分片上针对分布式引擎的底层表执行。

从 v25.4 起，源表为 `ReplicatedMergeTree` 或 `SharedMergeTree` 的 `INSERT ... SELECT` 也可以在各副本间并行执行。要启用此功能：

* `parallel_distributed_insert_select = 2`
* `enable_parallel_replicas = 1`

<Note>
  重写后的查询 (包括 `SELECT` 中的所有表达式，如子查询、UDFs 等) 会在各分片上使用集群配置中的凭证执行——这与其他在分片端进行的处理 (例如非 `GLOBAL` `IN` 中的子查询) 采用相同的信任模型。如果分片端的读取必须以调用方用户的身份进行授权，请配置服务器间 secret (即集群配置中的 `secret` 元素) 。
</Note>

## parallel_hash_join_threshold {#parallel_hash_join_threshold}

<SettingsInfoBlock type="UInt64" default_value="100000" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "100000"},{"label": "新增设置"}]}, {"id": "row-2","items": [{"label": "25.4"},{"label": "0"},{"label": "新增设置"}]}, {"id": "row-3","items": [{"label": "25.3"},{"label": "0"},{"label": "新增设置"}]}]} />

对于 `INNER`、`LEFT`、`RIGHT` 或 `FULL` 哈希连接，此阈值决定哈希表的构建方式。
如果右表的估算行数低于该阈值，连接会在单个线程上将哈希表构建为一个分片。
如果估算行数达到或超过该阈值，或者没有估算值，连接会将哈希表拆分为多个分片，由最多 `max_threads` 个线程同时填充 (当 `max_threads = 1` 时为一个线程) 。
设为 `0` 时始终拆分哈希表。
当 `hash_join_layout` 设置为 `serial` 或 `parallel` 时，不使用此阈值：无论估算值如何，连接都会构建单个分片或拆分哈希表。
估算值来自查询计划，或来自同一连接先前运行时收集的统计信息 (参见 `collect_hash_table_stats_during_joins`) 。
对于已知为空的右表 (例如没有数据分区片段的 `MergeTree` 表) ，查询计划估算的行数为 0。
`ASOF` 连接始终没有估算值；当 `query_plan_optimize_join_order_limit = 0` 时，所有连接都没有估算值。

## parallel_non_joined_rows_processing {#parallel_non_joined_rows_processing}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "1"},{"label": "新增设置：启用在 RIGHT/FULL `parallel_hash` JOIN 中并行处理右表未匹配的行。"}]}]} />

允许在 RIGHT 和 FULL JOIN 期间使用多个线程并行处理右表中未匹配的行。
当右表较大且哈希表由多个线程构建时 (参见 `parallel_hash_join_threshold`) ，这可以加快哈希连接中未匹配阶段的处理速度。
禁用后，或者哈希表由单个线程构建时，未匹配的行将由单个线程处理。
无论哪种情况，未匹配行的输出顺序都不固定。如果查询需要稳定的顺序，请使用 `ORDER BY`。
