<div id="timeout_overflow_mode">
  ## timeout_overflow_mode
</div>

<SettingsInfoBlock type="OverflowMode" default_value="throw" />

设置当查询运行时间超过 `max_execution_time`，或预计运行时间超过 `max_estimated_execution_time` 时应采取的操作 (仅在使用 `throw` 时检查预计时间) 。

可选值：

* `throw`：抛出异常 (默认值) 。
* `break`：停止执行查询并返回部分结果，就像源数据已经耗尽一样。某些操作无法安全地返回部分结果，因此不会产生较小的结果，而是在不生成结果的情况下停止。计算单个值的函数会停止而不生成该值；停止是否还会以 `TIMEOUT_EXCEEDED` 错误返回给客户端，还是仅表现为缺少结果，取决于查询在何处被中断。因超时而未完成的 `Memory` 表变更会保持表不变，并报告 `TIMEOUT_EXCEEDED`。`INSERT` 可能会报告 `QUERY_WAS_CANCELLED`。某些等待其他副本或后台工作的操作完全不会在 `max_execution_time` 时停止：法定人数写入会持续等待，直到满足法定人数；如果 `insert_quorum_timeout` 先到期，则报告 `UNKNOWN_STATUS_OF_INSERT`。

<div id="timeout_overflow_mode_leaf">
  ## timeout_overflow_mode_leaf
</div>

<SettingsInfoBlock type="OverflowMode" default_value="throw" />

设置叶子节点上的查询运行时间超过 `max_execution_time_leaf` 时的处理方式。

可能的值：

* `throw`：抛出异常 (默认) 。
* `break`：停止执行查询并返回部分结果，就像
  源数据已经耗尽一样。某些操作无法安全地返回部分结果，因此
  它们会停止且不产生结果，而不是返回较小的结果：计算单个值的函数
  会停止且不产生该值。此类停止是否
  还会以 `TIMEOUT_EXCEEDED` 错误的形式传递给客户端，还是仅表现为缺少
  结果，取决于查询在何处被中断。
