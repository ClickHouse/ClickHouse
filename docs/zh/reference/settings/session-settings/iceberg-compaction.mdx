## iceberg_compaction_data_cleanup {#iceberg_compaction_data_cleanup}

<SettingsInfoBlock type="Seconds" default_value="10800" />

启用 `enable_cleanup_old_data_files_compaction` 时，此设置指定 Iceberg 表的快照被较新快照替代后，
经过多长时间，该快照及仅由其引用的文件会过期。实际生效时间取此设置与 `iceberg_outdated_snapshot_lifetime_seconds` 中的较大值。

## iceberg_compaction_max_bytes_to_merge {#iceberg_compaction_max_bytes_to_merge}

<SettingsInfoBlock type="UInt64" default_value="161061273600" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "161061273600"},{"label": "新增设置。限制单次合并整理（compaction）合并中文件的总大小，作用方式与 `max_bytes_to_merge_at_max_space_in_pool` 之于 `MergeTree` 相同。"}]}]} />

Iceberg 表单次合并整理合并所涉及数据文件的最大总大小，按这些文件在对象存储中的大小总和计算。
其行为与 `MergeTree` 的 `max_bytes_to_merge_at_max_space_in_pool` 相同：当后台线程池中的空闲槽位少于
`number_of_free_entries_in_pool_to_lower_max_size_of_merge` 时，该限制会降低为 `max_bytes_to_merge_at_min_space_in_pool`
(两者均位于 config 的 `merge_tree` 部分) 。
分区中超出该限制的文件将留待后续合并处理。此设置不适用于应用位置删除文件的合并。

## iceberg_compaction_max_rows_to_merge {#iceberg_compaction_max_rows_to_merge}
