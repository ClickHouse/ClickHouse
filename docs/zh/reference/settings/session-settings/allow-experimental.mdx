## allow_experimental_analyzer {#allow_experimental_analyzer}

**别名**：`enable_analyzer`

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "1"},{"label": "该设置已过时：analyzer 为强制启用，旧的查询分析不再受支持。任何会禁用该设置的更改仍会被接受，但会被替换为 `1`；将 `compatibility` 设为低于 24.3 的版本也不会再恢复旧行为。"}]}, {"id": "row-2","items": [{"label": "24.8"},{"label": "1"},{"label": "新增别名 `enable_analyzer`。"}]}, {"id": "row-3","items": [{"label": "24.3"},{"label": "1"},{"label": "默认启用 analyzer 和 planner。"}]}]} />

自 v26.9 起过时：analyzer 已无法禁用。

analyzer 是自 v24.3 起默认启用的查询分析与查询计划基础设施。在 v26.9 中，该设置被固定为唯一受支持的值 `1`，`compatibility` 设置也不再使其恢复旧行为。在 v26.10 中，它原先所切换到的查询分析已被移除。出于向后兼容考虑，将其设为 `0` 仍会被接受，但会被替换为 `1`。因此，仍设置了 `enable_analyzer = 0` 的查询、会话设置、profile 及客户端配置可以继续正常运行，只是实际使用的仍是 analyzer。如需对比查询在旧查询分析下的行为或性能，请使用 v26.9 之前的 ClickHouse 版本。

## allow_experimental_parallel_reading_from_replicas {#allow_experimental_parallel_reading_from_replicas}

**别名**: `enable_parallel_replicas`

<SettingsInfoBlock type="UInt64" default_value="0" />
