## azure_skip_hidden_files {#azure_skip_hidden_files}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新增设置：按通配符列出文件时，跳过非通配符前缀之下含有以 `_` 或 `.` 开头的路径段的二进制大对象，与其他 Hive 生态系统读取器的行为保持一致。设置了 `partition_strategy = 'hive'` 的表始终会跳过此类路径。"}]}]} />

启用或禁用在 [AzureBlobStorage](/zh/reference/engines/table-engines/integrations/azureBlobStorage) 引擎表中按通配符列出文件时跳过隐藏路径。隐藏路径指路径中非通配符前缀之下含有以 `_` 或 `.` 开头的路径段的二进制大对象。包含 `=` 的路径段被视为分区目录 (例如分区列 `_p` 对应的 `_p=1`) ，不属于隐藏路径。Hive 生态系统的写入器 (Hive、Spark、Trino) 会在此类路径下暂存尚未完成的输出并写入标记对象 (`_temporary/`、`.spark-staging-<id>/`、`_SUCCESS`) ，读取这些内容会与写入器的提交形成竞态条件。非通配符前缀内的路径段不做检查。设置了 `partition_strategy = 'hive'` 的表无论此设置取何值，始终会跳过隐藏路径。

可选值：

* 0 — 读取通配符匹配到的所有二进制大对象。
* 1 — 跳过非通配符前缀之下含有隐藏路径段的二进制大对象。

## azure_validate_etag_on_read {#azure_validate_etag_on_read}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "26.9 不包含此校验：该校验已回移到 26.7 和 26.8，但未回移到 26.9。"}]}, {"id": "row-2","items": [{"label": "26.7"},{"label": "1"},{"label": "新增设置：通过 `If-Match` 将每个 `GET` 请求固定到列出时的 `ETag`，并校验响应的 `ETag`，从而检测读取过程中 Azure 二进制大对象是否被并发原地覆盖，作用与 S3 的 `s3_validate_etag_on_read` 相同。将 `compatibility` 设置为更早的版本可恢复先前的行为（不进行校验）。"}]}, {"id": "row-3","items": [{"label": "26.10"},{"label": "1"},{"label": "该校验再次默认启用：26.9 不包含此校验。"}]}]} />

通过 `azureBlobStorage` / `azureBlobStorageCluster` 表函数或 `AzureBlobStorage` 表引擎从 Azure 二进制大对象存储读取二进制大对象时，会在 `If-Match` 中携带该二进制大对象的 `ETag`，将每个 `GET` 请求固定到列出该二进制大对象时所观察到的版本，并校验响应的 `ETag`。读取单个文件会发出多个范围 `GET` 请求；如果二进制大对象在这些请求之间被原地覆盖 (例如外部写入器重写某个固定键) ，读取到的数据就可能由该二进制大对象的两个不同版本拼接而成，最终表现为校验和损坏或解析错误。此外，列出时记录的大小还会用作读取的右边界，因此该大小仅对记录时的版本有效。一旦检测到不匹配，读取将以 `AZURE_OBJECT_CHANGED_DURING_READ` 错误失败，而不会返回不一致的数据。仅当工作负载有意读取正在被覆盖的二进制大对象，且能够容忍不一致的读取结果时，才应禁用此设置。对于无需发出对象元数据请求即可读取的 Iceberg 表文件 (清单文件，以及通过表读取的 Parquet 和 ORC 数据文件) ，此设置不适用，因为这些文件永远不会被覆盖。
