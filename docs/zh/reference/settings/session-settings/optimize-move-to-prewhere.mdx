## optimize_move_to_prewhere {#optimize_move_to_prewhere}

<SettingsInfoBlock type="Bool" default_value="1" />

启用或禁用 [SELECT](/zh/reference/statements/select/index) 查询中的自动 [PREWHERE](/zh/reference/statements/select/prewhere) 优化。

仅对 [*MergeTree](/zh/reference/engines/table-engines/mergetree-family/index) 表生效。

可能的值：

* 0 — 禁用自动 `PREWHERE` 优化。
* 1 — 启用自动 `PREWHERE` 优化。

## optimize_move_to_prewhere_if_final {#optimize_move_to_prewhere_if_final}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "默认对带有 FINAL 的查询启用自动 PREWHERE 优化。仅移动那些只依赖于 sorting key 且在查询内具有确定性的条件，因此不会影响结果。将 `compatibility` 设置为低于 26.10 的版本可恢复先前的行为。"}]}]} />

启用或禁用在带有 [FINAL](/zh/reference/statements/select/from#final-modifier) 修饰符的 [SELECT](/zh/reference/statements/select/index) 查询中自动应用 [PREWHERE](/zh/reference/statements/select/prewhere) 优化。

仅移动那些只依赖于 sorting key 且在查询内具有确定性的条件，
因此不会影响 `FINAL` 的结果。对于 [GraphiteMergeTree](/zh/reference/engines/table-engines/mergetree-family/graphitemergetree)，
`FINAL` 会将同一 path 的相邻行合并为一行。因此，该优化仅移动作用于 path 列的条件，
并且仅在 path 为 sorting key 的第一列时才会生效。

仅适用于 [*MergeTree](/zh/reference/engines/table-engines/mergetree-family/index) 表。

可能的值：

* 0 — 禁用在带有 `FINAL` 修饰符的 `SELECT` 查询中自动应用 `PREWHERE` 优化。
* 1 — 启用在带有 `FINAL` 修饰符的 `SELECT` 查询中自动应用 `PREWHERE` 优化。

## optimize_move_to_prewhere_respect_short_circuit {#optimize_move_to_prewhere_respect_short_circuit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "1"},{"label": "新增设置：自动 PREWHERE 会将可能抛出异常的条件保留在短路求值中先于它执行的那些条件之后。将 `compatibility` 设为低于 26.12 的版本可恢复之前的顺序。"}]}]} />

在将条件从 WHERE 移动到 PREWHERE 时，如果短路求值只会在其前面所写条件筛选后保留的行上对某个可能抛出异常的条件求值，则将该条件保留在这些条件之后。
例如，`a = 'one' AND toDateTime64(s, 3) > '2020-01-01'` 不会在 `a != 'one'` 的行中解析 `s`。
此类条件不会按代价排序。禁用该设置后，条件的排序方式等同于将
[short&#95;circuit&#95;function&#95;evaluation](/zh/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation) 设为 `disable`，此时查询可能会
在已被前面条件排除的行上抛出异常。
