## optimize_if_chain_to_multiif {#optimize_if_chain_to_multiif}

<SettingsInfoBlock type="Bool" default_value="0" />

将 `if(cond1, then1, if(cond2, ...))` 链替换为 multiIf。当前这对数值类型没有益处。

## optimize_if_transform_const_strings_to_lowcardinality {#optimize_if_transform_const_strings_to_lowcardinality}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新增设置，允许将 `if`\/`multiIf`\/`transform` 中常量分支的结果优化为 `LowCardinality`。默认禁用。"}]}]} />

启用后，若 `if`、`multiIf` 和 `transform` 函数的结果分支 (以及默认值) 均为常量字符串，则这些函数将返回 `LowCardinality(String)`，而非 `String`。
此设置默认禁用，原因是当下游不复用该字典时，为每个块构建 `LowCardinality` 字典可能比直接返回普通 `String` 结果更慢。
当整个表达式为常量 (即条件或输入也为常量) 时，不会应用此优化：常量无法从 `LowCardinality` 中获益，同时也能确保要求传入常量 `String` 参数的函数 (例如 `arrayReduce`、`joinGet`、`tupleElement`) 继续正常工作。

所有结果分支都必须是常量，因此像 `if(cond1, 'a', if(cond2, 'b', 'c'))` 这样的嵌套 `if` 链仍返回普通 `String`：外层 `if` 的 else 分支是另一个 `if`，而非常量。若要得到 `LowCardinality(String)`，请改写为 `multiIf(cond1, 'a', cond2, 'b', 'c')`。

当 `optimize_if_transform_strings_to_enum` 处于启用状态时，此设置不生效：`Enum` 重写优先，即使采用上述显式 `multiIf` 写法，结果仍为 `String` (或 `Nullable(String)`) 。

## optimize_if_transform_strings_to_enum {#optimize_if_transform_strings_to_enum}

<SettingsInfoBlock type="Bool" default_value="0" />

将 If 和 Transform 中的 String 类型参数替换为枚举类型。默认禁用，因为这可能会在分布式查询中产生不一致的更改，进而导致查询失败。
