## query_cache_max_entries {#query_cache_max_entries}

<SettingsInfoBlock type="UInt64" default_value="0" />

此限制不适用于磁盘查询缓存 (由设置 `query_cache_on_disk_cache_name` 指定) ，其条目数量转而受底层文件系统缓存大小的限制。

## query_cache_on_disk_cache_name {#query_cache_on_disk_cache_name}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": ""},{"label": "新增设置，用于将查询缓存条目存储到磁盘上指定名称的文件系统缓存中。"}]}]} />

用于在磁盘上存储[查询缓存](/zh/concepts/features/performance/caches/query-cache)条目的文件系统缓存名称 (即服务器配置中 `filesystem_caches` 部分下的某个条目) 。如果指定了名称 (且已启用 [use&#95;query&#95;cache](/zh/reference/settings/session-settings/use-query#use_query_cache)) ，查询结果还会额外缓存到该文件系统缓存中，并可从中读取。与内存查询缓存相比，磁盘查询缓存容量更大，服务器重启后数据依然保留，并且独立于内存查询缓存运行：可通过设置 [enable&#95;reads&#95;from&#95;query&#95;cache&#95;on&#95;disk](/zh/reference/settings/session-settings/enable#enable_reads_from_query_cache_on_disk) 和 [enable&#95;writes&#95;to&#95;query&#95;cache&#95;on&#95;disk](/zh/reference/settings/session-settings/enable#enable_writes_to_query_cache_on_disk) 单独控制磁盘查询缓存，而不影响内存查询缓存。这些条目在文件系统缓存中与普通条目无异：不会受到删除保护，并与缓存中的其他数据遵循相同的淘汰规则。`SYSTEM CLEAR FILESYSTEM CACHE '<name>'` 会将它们与文件系统缓存中的其他所有内容一并清除；而 `SYSTEM CLEAR QUERY CACHE` 只会从该设置指定的文件系统缓存中删除磁盘查询缓存条目，其他数据保持不变。建议为查询结果单独配置专用的文件系统缓存。

可选值：

* 空字符串 - 禁用磁盘查询缓存
* 预先配置的文件系统缓存名称

## query_cache_squash_partial_results {#query_cache_squash_partial_results}

<SettingsInfoBlock type="Bool" default_value="1" />

将部分结果块合并成大小为 [max&#95;block&#95;size](/zh/reference/settings/session-settings/max#max_block_size) 的块。这样会降低向[查询缓存](/zh/concepts/features/performance/caches/query-cache)插入数据的性能，但能提升缓存条目的压缩效果 (参见 [query&#95;cache&#95;compress-entries](/zh/reference/settings/session-settings/query-cache#query_cache_compress_entries)) 。

可能的值：

* 0 - 已禁用
* 1 - 已启用
