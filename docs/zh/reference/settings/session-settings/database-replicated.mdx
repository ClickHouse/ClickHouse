## database_replicated_allow_only_replicated_engine {#database_replicated_allow_only_replicated_engine}

<SettingsInfoBlock type="Bool" default_value="0" />

仅当表会复制其自身存储在磁盘上的数据，或者表本身不在磁盘上存储数据时，才允许在使用 `Replicated` 引擎的数据库中创建该表。

此限制仅适用于表自身拥有的磁盘上的数据，包括远程磁盘上的数据，但不保证 in-memory 数据或由外部系统管理的数据的持久性。

例如，`ReplicatedMergeTree`、`Memory` 和 `Buffer` 等 in-memory 引擎、`Merge` 和 `Alias` 等 metadata-only 引擎，以及 `S3` 和 `AzureBlobStorage` 等外部存储或数据湖引擎均允许使用。在磁盘上存储表数据的非复制引擎 (例如 `MergeTree`、`Log`、`File` 和 `Set`) 则会被拒绝，即使其可写存储策略使用的是远程磁盘也不例外。使用 `SETTINGS persistent = 0` 创建的 `Set` 表和 `Join` 表仅在内存中保存数据，因此允许使用。

`Distributed`、`Remote` 和 `RemoteSecure` 表允许使用。它们可选的本地后台 `INSERT` 队列只是临时的发送缓冲区，并不属于表本身的数据。该队列不会被复制；将 `distributed_foreground_insert` 设置为 `1` 即可避免使用该队列。

Cloud 默认值：`1`。

## database_replicated_always_detach_permanently {#database_replicated_always_detach_permanently}

如果数据库引擎为 Replicated，则以 DETACH TABLE PERMANENTLY 的方式执行 DETACH TABLE

## database_replicated_enforce_synchronous_settings {#database_replicated_enforce_synchronous_settings}

<SettingsInfoBlock type="Bool" default_value="0" />

强制某些查询以同步方式等待 (另请参见 database&#95;atomic&#95;wait&#95;for&#95;drop&#95;and&#95;detach&#95;synchronously、mutations&#95;sync、alter&#95;sync) 。不建议启用这些设置。

## database_replicated_initial_query_timeout_sec {#database_replicated_initial_query_timeout_sec}

<SettingsInfoBlock type="UInt64" default_value="300" />

设置初始 DDL 查询等待 Replicated 数据库 处理之前 DDL 队列 条目的时长 (以秒为单位) 。

* 正整数。
