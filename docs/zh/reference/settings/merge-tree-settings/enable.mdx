## enable_adaptive_codec_selection {#enable_adaptive_codec_selection}

<BetaBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "新增设置"}]}, {"id": "row-2","items": [{"label": "26.11"},{"label": "0"},{"label": "自适应编解码器选择已转为 Beta。"}]}]} />

启用后，对于使用默认编解码器的列 (即未指定 `CODEC` 子句或指定 `CODEC(Default)`) ，合并和变更会为每个块选择编解码器。
候选编解码器包括表的默认编解码器 (请参阅 `default_compression_codec` 设置) 、`NONE` 以及适合该列类型的专用编解码器；每个专用编解码器既会单独作为候选项，当默认编解码器为 `LZ4` 或 `ZSTD` 等通用压缩算法时，也会在其后串联默认编解码器作为候选项。
输出最小的候选项将被选中，无法压缩的块会以原始形式存储。每 `adaptive_codec_selection_period` 个块中仅对其中一个块进行选择，其间的块会沿用该选择结果。
如果某列的默认编解码器包含加密 (例如 `AES_128_GCM_SIV`) ，则不会对其进行自适应选择，因此始终会应用加密。
每个块所使用的编解码器可通过 [`mergeTreeCodecBlockCounts`](/zh/reference/functions/table-functions/index) 表函数查看。

## enable_merge_checkpoints {#enable_merge_checkpoints}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "新增设置，用于持久化合并检查点"}]}]} />

为符合条件的合并保存检查点，使被中断的合并能够从检查点继续执行，而无需从头开始。
目前仅对合并生成的 `Wide` 分片大小不低于 `merge_checkpoints_min_bytes` 的纵向合并保存检查点。
第一个检查点在键列合并完成后保存，后续检查点在每完成一列合并后保存，
且每 `merge_checkpoints_min_interval_seconds` 内最多保存一次。
当某个当前分片覆盖了检查点的结果分片，
或在 `temporary_directories_lifetime` 时间内没有任何合并保存该检查点时，该检查点会被删除。
包含生存时间 (TTL)、投影、二级索引、补丁分片或非自适应标记 (`index_granularity_bytes = 0`) 的合并不会保存检查点。

## enable_mixed_granularity_parts {#enable_mixed_granularity_parts}

<SettingsInfoBlock type="Bool" default_value="1" />

启用或禁用切换为使用 `index_granularity_bytes` 设置来控制粒度大小。在 19.11 版本之前，只有
`index_granularity` 设置可用于限制粒度大小。`index_granularity_bytes`
设置可在从包含大行 (数十到数百 MB) 的表中读取数据时提升 ClickHouse 的性能。
如果你的表中存在大行，可以为这些表启用此设置，
以提高 `SELECT` 查询的效率。

## enable_row_mask_update_coalescing {#enable_row_mask_update_coalescing}

<SettingsInfoBlock type="Bool" default_value="1" />

## enable_vertical_merge_algorithm {#enable_vertical_merge_algorithm}

<SettingsInfoBlock type="UInt64" default_value="1" />

允许符合条件的后台合并使用纵向合并算法。纵向合并逐列处理数据，以降低宽表的峰值内存占用，但可能降低合并速度。将此设置设为 `0` 会强制使用横向合并；非零值仅表示允许使用纵向合并，实际是否采用该算法仍取决于分片格式、表引擎、`TTL` 操作以及 `vertical_merge_algorithm_min_*` 阈值。
