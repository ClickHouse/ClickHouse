## merge_checkpoints_min_bytes {#merge_checkpoints_min_bytes}

<ExperimentalBadge />

<SettingsInfoBlock type="UInt64" default_value="10737418240" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "10737418240"},{"label": "新增设置，用于持久化合并检查点"}]}]} />

启用 `enable_merge_checkpoints` 时，只有源 parts 总大小 (以字节为单位) 不低于该最小值的合并才会创建检查点。
较小的合并不会创建检查点，因为重新执行它们的开销很低。

## merge_checkpoints_min_interval_seconds {#merge_checkpoints_min_interval_seconds}

<ExperimentalBadge />

<SettingsInfoBlock type="Seconds" default_value="60" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "60"},{"label": "新增设置，用于持久化合并检查点"}]}]} />

启用 `enable_merge_checkpoints` 时，同一次合并中两个检查点之间的最小时间间隔。
垂直合并在其键列合并完成后，总会创建一次检查点。此后，每完成一列的合并，仅当距上一个检查点已超过该时长时，才会再次创建检查点。

## merge_total_max_bytes_to_prewarm_cache {#merge_total_max_bytes_to_prewarm_cache}

## merge_use_batch_sorting_queue {#merge_use_batch_sorting_queue}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "新增设置：对普通 `MergeTree` 合并使用批次排序队列。"}]}]} />

合并已排序的流时，使用批次排序队列可减少每行的队列开销。

仅适用于不会改变行的合并，即普通 `MergeTree`
(`Ordinary` 合并模式) 。对于具有合并时语义的引擎，例如 `ReplacingMergeTree`、`CollapsingMergeTree`、
`SummingMergeTree`、`AggregatingMergeTree`、`CoalescingMergeTree`、
`GraphiteMergeTree` 和 `VersionedCollapsingMergeTree`，此设置无效；无论此设置如何，这些引擎都会继续使用
默认队列。

## merge_workload {#merge_workload}

用于调节资源在合并与其他工作负载之间的分配和共享。指定的值将作为此表后台合并的 `workload` 设置值使用。如果未指定 (空字符串) ，则使用服务器级设置 `merge_workload`。
