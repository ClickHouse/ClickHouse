这些设置用于配置 ClickHouse 服务器，并由 ClickHouse 源代码自动生成。

## distributed_cache_apply_throttling_settings_from_client {#distributed_cache_apply_throttling_settings_from_client}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />缓存服务器是否应使用从客户端接收的限流设置。

## distributed_cache_keep_up_free_connections_ratio {#distributed_cache_keep_up_free_connections_ratio}

<SettingsInfoBlock type="Float" default_value="0.1" changeable_without_restart="否" />分布式缓存会尽量保持的空闲活动连接数量的软限制。当空闲连接数低于 distributed&#95;cache&#95;keep&#95;up&#95;free&#95;connections&#95;ratio * max&#95;connections 时，将关闭活动时间最早的连接，直到该数量重新高于此限制。

## distributed_cache_max_request_processing_time_ms {#distributed_cache_max_request_processing_time_ms}

<SettingsInfoBlock type="UInt64" default_value="60000" changeable_without_restart="No" />Distributed Cache 服务器处理某个请求时，若自该请求最近一次 `StartRequest` 或 `ContinueRequest` 起的处理时长达到此毫秒数 (不计等待客户端的时间) ，则会结束该请求；每个新的读取范围都会重新开始计时。服务器一旦能够上报，就会立即结束该请求；若请求始终未能到达可上报的阶段，则其连接会在 `distributed_cache_stuck_request_scan_interval_ms` 之后被关闭。值为 0 表示不设上限。

## distributed_cache_slow_down_min_stuck_requests {#distributed_cache_slow_down_min_stuck_requests}

<SettingsInfoBlock type="UInt64" default_value="10" changeable_without_restart="No" />仅当某个客户端卡住的请求数至少达到该值时，Distributed Cache 服务器才会要求该客户端降速，以免只有少量请求处于处理中的客户端因单个请求卡住就被要求降速。取值为 0 或 1 时，仅由 `distributed_cache_slow_down_stuck_requests_ratio` 决定是否降速。

## distributed_cache_slow_down_stuck_requests_ratio {#distributed_cache_slow_down_stuck_requests_ratio}

<SettingsInfoBlock type="Double" default_value="0.2" changeable_without_restart="No" />当处理中请求里卡住的请求所占比例达到或超过该值时，Distributed Cache 服务器会要求客户端降速；空闲连接不计入其中。值为 0 时，服务器从不发出降速要求。

## distributed_cache_slow_down_window_ms {#distributed_cache_slow_down_window_ms}

<SettingsInfoBlock type="UInt64" default_value="10000" changeable_without_restart="No" />当Distributed Cache 服务器上卡住的请求过多时，该服务器要求客户端暂停访问的时长，单位为毫秒。该值必须不小于 `distributed_cache_stuck_request_scan_interval_ms` 的两倍，以确保只有在扫描未对窗口续期时，窗口才会失效；不允许设置为 0。

## distributed_cache_stuck_request_no_progress_timeout_ms {#distributed_cache_stuck_request_no_progress_timeout_ms}

<SettingsInfoBlock type="UInt64" default_value="10000" changeable_without_restart="No" />如果某个连接上的请求在此设置指定的毫秒数内未交换任何数据 (不计等待客户端的时间) ，Distributed Cache 服务器将关闭该连接。设为 0 表示禁用此限制；仅当 `distributed_cache_max_request_processing_time_ms` 也为 0 时，才会停止对卡住请求的扫描。

## distributed_cache_stuck_request_scan_interval_ms {#distributed_cache_stuck_request_scan_interval_ms}

<SettingsInfoBlock type="NonZeroUInt64" default_value="5000" changeable_without_restart="No" />Distributed Cache 服务器扫描卡住请求的时间间隔 (毫秒) 。

## distributed_cache_temporary_data_background_retry_delay_milliseconds {#distributed_cache_temporary_data_background_retry_delay_milliseconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="30000" changeable_without_restart="No" />在后台重试已提交的临时数据之前的延迟时间 (单位：毫秒) 。

## distributed_cache_temporary_data_cleanup_period_milliseconds {#distributed_cache_temporary_data_cleanup_period_milliseconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="1000" changeable_without_restart="No" />对已提交的临时数据执行过期清理的时间间隔，单位为毫秒。

## distributed_cache_temporary_data_confirmation_retry_delay_milliseconds {#distributed_cache_temporary_data_confirmation_retry_delay_milliseconds}

<SettingsInfoBlock type="UInt64" default_value="500" changeable_without_restart="No" />重试已提交临时数据的发布确认之前的延迟时间 (以毫秒为单位) 。

## distributed_cache_temporary_data_control_hello_timeout_milliseconds {#distributed_cache_temporary_data_control_hello_timeout_milliseconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="2000" changeable_without_restart="No" />已提交的临时数据控制最多可将文件的生命周期延长至“控制连接 hello 的时间 + 此超时 + 生存时间 (TTL)”，单位为毫秒。客户端在发送 hello 后，等待响应的时长也与此相同。客户端使用自身的值，该值在创建已提交文件时读取 (对于后台续订，则在启动时读取) 。即使客户端与分布式缓存服务器上的取值不同，文件的生命周期也不会短于“hello + 生存时间 (TTL)”。

## distributed_cache_temporary_data_max_bytes_per_server {#distributed_cache_temporary_data_max_bytes_per_server}

<SettingsInfoBlock type="UInt64" default_value="1099511627776" changeable_without_restart="No" />单个分布式缓存服务器可保留的已提交临时 File的最大总大小 (以字节为单位) 。已提交的临时 File会被固定在文件缓存中，在释放或过期之前不会被淘汰，因此该限制用于约束它们最多可占用的缓存空间。默认值为 1 TiB。达到该限制后，服务器将拒绝发布新的已提交临时 File。`0` 表示不限制。

## distributed_cache_temporary_data_max_connections_bypassing_pool {#distributed_cache_temporary_data_max_connections_bypassing_pool}

<SettingsInfoBlock type="UInt64" default_value="5000" changeable_without_restart="Yes" />仅在 ClickHouse Cloud 中生效。对于每个分布式缓存服务器，临时 File 绕过连接池可打开的最大连接数。达到该上限后，临时数据会等待池化连接，等待时长为 `distributed_cache_wait_connection_from_pool_milliseconds` 毫秒，超时后则失败。`0` 表示不限制。针对已提交临时数据的简短控制交互 (确认、续订、释放) 始终会打开新连接，且不计入该上限。无需重启即可更改。

## distributed_cache_temporary_data_max_control_batch_ids {#distributed_cache_temporary_data_max_control_batch_ids}

<SettingsInfoBlock type="NonZeroUInt64" default_value="1024" changeable_without_restart="No" />客户端在单个控制请求中可发送的已提交临时数据 ID 的最大数量。超过 65536 的值会被限制为 65536 (即协议上限) 。

## distributed_cache_temporary_data_max_files_per_server {#distributed_cache_temporary_data_max_files_per_server}

<SettingsInfoBlock type="UInt64" default_value="100000" changeable_without_restart="No" />单个分布式缓存服务器可保留的已提交临时 File 的最大数量。默认值设得较高，因为该限制仅作为兜底措施，用于限定跟踪这些文件所占用的内存；容量主要受 `distributed_cache_temporary_data_max_bytes_per_server` 限制。达到该上限后，服务器将拒绝发布新的已提交临时 File。`0` 表示不限制。

## distributed_cache_temporary_data_pool_behaviour_on_limit {#distributed_cache_temporary_data_pool_behaviour_on_limit}

<SettingsInfoBlock type="DistributedCachePoolBehaviourOnLimit" default_value="allocate_bypassing_pool" changeable_without_restart="Yes" />仅在 ClickHouse Cloud 中生效。指定达到连接池上限时，用于临时数据的分布式缓存连接的行为。临时数据没有可回退到的对象存储，因此默认情况下会打开一个绕过连接池的连接，而不是直接报错失败。该设置适用于查询以及后台操作 (合并、备份) 产生的临时 File。针对已提交临时数据的简短控制交换 (确认、续订、释放) 始终会打开新连接，不受此设置影响。设置为 `wait` 时，会在 `distributed_cache_wait_connection_from_pool_milliseconds` 指定的时间内等待池化连接，超时后失败。无需重启即可更改。

## distributed_cache_temporary_data_renewal_period_seconds {#distributed_cache_temporary_data_renewal_period_seconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="900" changeable_without_restart="No" />两次已提交的临时数据所有权续订之间的间隔周期 (以秒为单位) 。

## distributed_cache_temporary_data_ttl_seconds {#distributed_cache_temporary_data_ttl_seconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="3600" changeable_without_restart="No" />已提交的临时 File 的生命周期 (单位：秒) 。

## distributed_cache_warmer_max_bytes_in_queue {#distributed_cache_warmer_max_bytes_in_queue}

<SettingsInfoBlock type="UInt64" default_value="107374182400" changeable_without_restart="No" />仅在 ClickHouse Cloud 中生效。对于未配置本地文件系统缓存的磁盘，缓存预热器在队列中保留的范围的最大总大小；超出该上限时，将丢弃最旧的范围 (若配置了本地缓存，预热器则使用其 `max_size`) 。值为 0 表示不限制。

## distributed_cache_warmer_max_file_segment_size {#distributed_cache_warmer_max_file_segment_size}

<SettingsInfoBlock type="NonZeroUInt64" default_value="33554432" changeable_without_restart="No" />仅在 ClickHouse Cloud 中生效。当数据分片所在的磁盘没有本地文件系统缓存时，缓存预热器会按此大小的范围，将拉取到的数据分片读取到分布式缓存中 (若存在本地缓存，预热器则使用该缓存的 `max_file_segment_size`) 。

## distributed_cache_warmer_max_segments_in_queue {#distributed_cache_warmer_max_segments_in_queue}

<SettingsInfoBlock type="UInt64" default_value="100000" changeable_without_restart="No" />仅在 ClickHouse Cloud 中生效。对于未配置本地文件系统缓存的磁盘，缓存预热器在队列中最多保留的范围数量；超出此上限时，最旧的范围会被丢弃 (若配置了本地缓存，预热器则改用该缓存的 `max_elements`) 。设为 0 表示不限制。

## distributed_cache_warmer_skip_parts_produced_in_current_availability_zone {#distributed_cache_warmer_skip_parts_produced_in_current_availability_zone}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />仅在 ClickHouse Cloud 中生效。当缓存预热器仅预热分布式缓存时 (即该 分片 所在磁盘没有本地文件系统缓存，或读取时已禁用缓存) ，跳过由当前可用区内副本生成的 分片：这些 分片 是通过分布式缓存写入的，因此已存在于该可用区的缓存中。来源未知的 分片 始终会被预热。

## distributed_cache_write_pool_size {#distributed_cache_write_pool_size}

<SettingsInfoBlock type="UInt64" default_value="100" changeable_without_restart="No" />可在后台线程中同时运行的分布式缓存写请求的最大数量 (跨所有查询) 。达到该限制后，将跳过 write-through cache 的写入 (数据仍会写入 object storage) ，因此既不会因等待 slot 而阻塞，也不会创建数量无限增长的线程。临时数据的写入不使用后台线程，因此不受该限制影响。
