## date_time_64_output_format_cut_trailing_zeros_align_to_groups_of_thousands {#date_time_64_output_format_cut_trailing_zeros_align_to_groups_of_thousands}

<SettingsInfoBlock type="Bool" default_value="0" />

动态去除 `DateTime64` 值中末尾的零，将输出标度向上舍入为可保留所有有效数字的下一个
3 的倍数：[0, 3, 6, 9]。如果小数部分全为零，则将其省略。

## date_time_input_format {#date_time_input_format}

<SettingsInfoBlock type="DateTimeInputFormat" default_value="best_effort" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.5"},{"label": "best_effort"},{"label": "可用性更佳"}]}]} />

允许选择日期和时间文本表示的解析器。

此设置不适用于[日期和时间函数](/zh/reference/functions/regular-functions/date-time-functions)。

可能的值：

* `'best_effort'` — 启用扩展解析。

  ClickHouse 可以解析基础的 `YYYY-MM-DD HH:MM:SS` 格式以及所有 [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) 日期和时间格式。例如，`'2018-06-08T01:02:03.000Z'`。

* `'best_effort_us'` — 与 `best_effort` 类似 (差异请参见 [parseDateTimeBestEffortUS](/zh/reference/functions/regular-functions/type-conversion-functions#parseDateTimeBestEffortUS))

* `'basic'` — 使用基础解析器。

  ClickHouse 只能解析基础的 `YYYY-MM-DD HH:MM:SS` 或 `YYYY-MM-DD` 格式。例如，`2019-08-20 10:18:56` 或 `2019-08-20`。

另请参见：

* [DateTime 数据类型。](/zh/reference/data-types/datetime)
* [处理日期和时间的函数。](/zh/reference/functions/regular-functions/date-time-functions)

## date_time_output_format {#date_time_output_format}

<SettingsInfoBlock type="DateTimeOutputFormat" default_value="simple" />

允许为日期和时间的文本表示选择不同的输出格式。

可能的值：

* `simple` - 简单输出格式。

  ClickHouse 以 `YYYY-MM-DD hh:mm:ss` 格式输出日期和时间。例如：`2019-08-20 10:18:56`。其计算依据为数据类型的 time zone (如果存在) 或 server time zone。

* `iso` - ISO 输出格式。

  ClickHouse 以 [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) `YYYY-MM-DDThh:mm:ssZ` 格式输出日期和时间。例如：`2019-08-20T10:18:56Z`。请注意，输出为 UTC (`Z` 表示 UTC) 。

* `unix_timestamp` - Unix timestamp 输出格式。

  ClickHouse 以 [Unix timestamp](https://en.wikipedia.org/wiki/Unix_time) 格式输出日期和时间。例如：`1566285536`。

另请参见：

* [DateTime 数据类型。](/zh/reference/data-types/datetime)
* [用于处理日期和时间的函数。](/zh/reference/functions/regular-functions/date-time-functions)

## date_time_overflow_behavior {#date_time_overflow_behavior}

<SettingsInfoBlock type="DateTimeOverflowBehavior" default_value="ignore" />

定义将 [Date](/zh/reference/data-types/date)、[Date32](/zh/reference/data-types/date32)、[DateTime](/zh/reference/data-types/datetime)、[DateTime64](/zh/reference/data-types/datetime64)、[Time](/zh/reference/data-types/time)、[Time64](/zh/reference/data-types/time64) 或数值 (整数和浮点数) 转换为 `Date`、`Date32`、`DateTime`、`DateTime64`、`Time` 或 `Time64` 时，若该值无法用结果类型表示，系统应采取的行为。`Decimal` 值只能转换为 `DateTime64` 和 `Time64`，这些转换同样遵循此设置；而将 `Decimal` 转换为 `Date`、`Date32`、`DateTime` 或 `Time` 时，无论此设置为何值，都会被拒绝。从文本解析 `Date` 或 `DateTime` 时 (包括通过输入格式解析) ，此设置同样适用。

可选值：

* `ignore` — 静默忽略溢出。对于日期和时间类型之间的转换，结果未定义 (值可能发生回绕) ；对于数值，则会饱和截断到结果类型的范围边界。
* `throw` — 发生溢出时抛出异常。
* `saturate` — 对结果进行饱和处理。如果值小于目标类型可表示的最小值，则结果取可表示的最小值；如果值大于目标类型可表示的最大值，则结果取可表示的最大值。

精确类型转换函数 (`accurateCast`、`accurateCastOrNull`、`accurateCastOrDefault`) 不受此设置影响：对于无法表示的值，它们分别会始终拒绝、返回 `NULL` 或替换为默认值。

此设置适用于由 `CAST` 和转换函数执行的转换，包括 `INSERT ... VALUES` 表达式模板或 `INSERT ... SELECT` 所执行的转换。对于 `Values` 格式在不使用模板的情况下求值的常量表达式 (即由 `input_format_values_interpret_expressions` 启用的回退机制) 以及 `values` 表函数，仅在目标类型为 `DateTime64` 和 `Time64` 时才遵循此设置：在这些场景下，将超出范围的数字写入 `Date`、`Date32`、`DateTime` 或 `Time` 列时不受此设置控制。`values` 表函数会拒绝该值；`Values` 格式同样会拒绝，但如果已启用 `input_format_null_as_default`，则会插入该列的默认值。

默认值：`ignore`。
