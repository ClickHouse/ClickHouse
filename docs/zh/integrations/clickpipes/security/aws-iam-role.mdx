借助 AWS IAM role身份验证，ClickPipes 无需存储 AWS 访问密钥即可访问受支持的 AWS 数据源。您需要在 AWS 账户中创建一个角色，允许 ClickHouse Cloud 服务代入该角色，并为其授予访问数据源所需的权限。

## 开始之前 {#before-you-begin}

* 您的 ClickHouse Cloud 服务必须运行在 AWS 上，才能使用 IAM role 身份验证。
* 您需要在拥有该数据源的 AWS 账户中具备创建和配置 IAM role的权限。
* 如需使用 RDS 或 Aurora 数据库身份验证，您还需要具备启用 IAM 数据库身份验证以及配置数据库用户的权限。

## 工作原理 {#how-it-works}

1. 在 **Settings → Network security information** 下找到您的 ClickHouse Cloud 服务的 **Service role ID (IAM)**。该 ARN 用于标识 ClickPipes 在请求访问时所使用的角色。
2. 在您的 AWS 账户中创建一个角色，并将 ClickHouse 服务角色设为受信任实体，允许其代入该角色。
3. 按照下方对应数据源的设置指南，为该角色授予所需的权限。
4. 将 ClickPipe 配置为使用您所创建角色的 ARN。ClickPipes 在连接数据源时会代入该角色。

## 配置信任策略 {#configure-trust-policy}

在您的 AWS 账户中创建角色时，请使用以下信任策略。将 `{ClickHouse_IAM_ARN}` 替换为您的 ClickHouse Cloud 服务的 **Service role ID (IAM)** ARN：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "{ClickHouse_IAM_ARN}"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

对于 **RDS 和 Aurora IAM 数据库身份验证**，请在 `Action` 字段中同时允许 `sts:AssumeRole` 和 `sts:TagSession`。完整的设置步骤 (包括创建启用 IAM 的数据库用户) 请参阅[对应数据库的 IAM 身份验证指南](/zh/integrations/clickpipes/postgres/auth)。

该角色的**权限策略**以及所有角色命名要求均因数据源而异。请参阅下方对应数据源的指南进行配置。
