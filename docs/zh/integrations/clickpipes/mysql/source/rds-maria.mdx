## 启用二进制日志保留 {#enable-binlog-retention-rds}

二进制日志是一组日志文件，其中包含对 MySQL 服务器实例所做的数据修改信息。复制需要二进制日志文件。必须同时执行以下两个步骤：

<Steps>
  <Step title="通过自动备份启用二进制日志记录" id="enable-binlog-logging-rds">
    MySQL 是否启用二进制日志记录由自动备份功能决定。可以在 AWS 控制台 中进行设置：

    <div className="ch-image-lg">
      <Frame>
        ![在 RDS 中启用自动备份](/images/integrations/data-ingestion/clickpipes/mysql/source/rds/rds-backups.webp)
      </Frame>
    </div>

    建议根据复制用例将备份保留策略设置为足够长的时长。
  </Step>

  <Step title="Binlog 保留时长 (小时)" id="binlog-retention-hours-rds">
    Amazon RDS for MariaDB 设置二进制日志保留时长的方法有所不同。二进制日志保留时长是指包含变更的二进制日志文件会保留多久。如果某些变更在二进制日志文件被删除前尚未被读取，复制将无法继续。二进制日志保留时长 (小时) 的默认值为 NULL，表示不会保留二进制日志。

    要指定某个数据库实例上二进制日志的保留小时数，请使用 `mysql.rds_set_configuration` 存储过程，并将二进制日志保留周期设置得足够长，以确保复制能够进行。ClickPipes 要求至少保留 **72 小时**。如果管道的滞后时间超过保留期限，则必须重新同步。

    ```text
    mysql=> call mysql.rds_set_configuration('binlog retention hours', 72);
    ```
  </Step>
</Steps>

## 在参数组中配置二进制日志设置 {#binlog-parameter-group-rds}

在 RDS 控制台中点击你的 MariaDB 实例，然后进入 `Configurations` 选项卡，即可找到参数组。

<div className="ch-image-lg">
  <Frame>
    ![在 RDS 中查找参数组的位置](/images/integrations/data-ingestion/clickpipes/mysql/parameter_group/rds_config.webp)
  </Frame>
</div>

点击参数组链接后，会进入其详情页面。你会在右上角看到一个编辑按钮：

<div className="ch-image-lg">
  <Frame>
    ![编辑参数组](/images/integrations/data-ingestion/clickpipes/mysql/parameter_group/edit_button.webp)
  </Frame>
</div>

需要按如下方式设置 `binlog_format`、`binlog_row_metadata` 和 `binlog_row_image`：

1. 将 `binlog_format` 设置为 `ROW`。

<div className="ch-image-lg">
  <Frame>
    ![将二进制日志格式设为 ROW](/images/integrations/data-ingestion/clickpipes/mysql/parameter_group/binlog_format.webp)
  </Frame>
</div>

2. 将 `binlog_row_metadata` 设置为 `FULL`

<div className="ch-image-lg">
  <Frame>
    ![将二进制日志行元数据设为 FULL](/images/integrations/data-ingestion/clickpipes/mysql/parameter_group/binlog_row_metadata.webp)
  </Frame>
</div>

3. 将 `binlog_row_image` 设置为 `FULL`

<div className="ch-image-lg">
  <Frame>
    ![将二进制日志行镜像设为 FULL](/images/integrations/data-ingestion/clickpipes/mysql/parameter_group/binlog_row_image.webp)
  </Frame>
</div>

接下来，点击右上角的 `Save Changes`。这些更改可能需要重启实例后才会生效。如果你在 RDS 实例的 Configurations 选项卡中看到参数组链接旁显示 `Pending reboot`，通常就表示需要重启实例。

<br />

<Tip>
  如果你使用的是 MariaDB cluster，则上述参数应位于 [DB Cluster](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/USER_WorkingWithParamGroups.CreatingCluster.html) 参数组中，而不是数据库实例 group 中。
</Tip>

<div id="gtid-mode-rds">
  ## 启用 GTID 模式 {#gtid-mode-rds}
</div>

全局事务标识符 (GTID) 是分配给 MySQL/MariaDB 中每个已提交事务的唯一 ID。它可以简化 binlog 复制，并让故障排查更直接。MariaDB 默认启用 GTID 模式，因此无需用户执行任何操作即可使用。

<div id="configure-database-user-rds">
  ## 配置数据库用户 {#configure-database-user-rds}
</div>

以管理员用户身份连接到您的 RDS MariaDB 实例，并执行以下命令：

1. 为 ClickPipes 创建一个专用用户：

   ```sql
   CREATE USER 'clickpipes_user'@'%' IDENTIFIED BY 'some-password';
   ```

2. 授予 schema 权限。以下示例展示了 `clickpipes` 数据库的权限。对于您要复制的每个数据库和主机，请重复执行这些命令：

   ```sql
   GRANT SELECT ON `clickpipes`.* TO 'clickpipes_user'@'%';
   ```

3. 向该用户授予复制权限。MariaDB 10.5.9 及更高版本还需要 `SLAVE MONITOR` 权限：

   ```sql
   GRANT REPLICATION CLIENT ON *.* TO 'clickpipes_user'@'%';
   GRANT REPLICATION SLAVE ON *.* TO 'clickpipes_user'@'%';
   GRANT SLAVE MONITOR ON *.* TO 'clickpipes_user'@'%';
   ```

4. 允许 ClickPipes 读取二进制日志保留设置：

   ```sql
   GRANT SELECT ON `mysql`.`rds_configuration` TO 'clickpipes_user'@'%';
   ```
