### 初始加载 {#initial-load}

初始加载会将 BigQuery [数据集](https://docs.cloud.google.com/bigquery/docs/datasets-intro)中选定的表复制到 ClickHouse。初始加载既可以单独运行，也可以在完成后接着进行持续复制。加载过程会使用您提供的 Google Cloud Storage (GCS) 桶作为暂存区。仅执行初始加载的 ClickPipe 会在加载完成后停止。

<Note>
  ClickPipes 使用 BigQuery [`EXPORT DATA`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/export-statements) 查询将数据复制到暂存桶。运行这些查询会产生 BigQuery 费用，同时还会产生 GCS 存储费用。
</Note>

### 持续复制 {#cdc}

完成初始加载后，BigQuery ClickPipe 可以轮询新数据并将其写入 ClickHouse。您也可以跳过初始加载，直接启动持续复制。请根据源表的变更方式选择复制方式。以下示例仅展示查询形态；ClickPipes 实际会选取已配置的列以及事件元数据。

| 方式                                                                                                            | 适用场景                                        | ClickPipes 复制的内容                            | 示例查询                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 基于查询                                                                                                          | 每个插入或更新的行都有一个 `TIMESTAMP` 列，且该列的值会随行的变更而递增。 | 水位线值晚于上次已复制值的行。无法检测删除操作。                    | `SELECT * FROM dataset.orders WHERE TIMESTAMP(updated_at) > @start AND TIMESTAMP(updated_at) <= @end`                                                           |
| [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) | 该表只需复制新增的行。                                 | 插入或追加到表中的行，包括通过 `MERGE` 插入的行。不复制更新和删除操作。    | [`SELECT * FROM APPENDS(TABLE dataset.orders, @start, @end)`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) |
| [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) | 插入、更新和删除操作都需要同步到 ClickHouse。                | BigQuery 变更历史记录中报告的变更，包括 `MERGE` 和表截断产生的变更。 | [`SELECT * FROM CHANGES(TABLE dataset.orders, @start, @end)`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) |

使用基于查询的复制时，需要为每个表选择一个水位线列。该列必须是 `TIMESTAMP` 类型，且必须包含在要复制的列中。每次插入或更新行时都应设置该列的值。如果某行发生了变更但水位线值没有更新，ClickPipes 将无法捕获该变更。如需复制删除操作，请使用 [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes)。

两种基于事件的方式都要求使用常规 BigQuery 表。[`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) 无需启用变更历史记录。若要使用 [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes)，请在创建 ClickPipe 之前为每个源表启用变更历史记录：

```sql
ALTER TABLE `project.dataset.table` SET OPTIONS (enable_change_history = TRUE);
```

[`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) 还要求目标表配置 BigQuery 主键或自定义 sorting key。请选择能够唯一标识每一行的列，以便 ClickPipes 将更新和删除操作应用到对应的行。BigQuery 不强制执行主键约束，因此源数据必须保证这些值唯一。

<Note>
  [`APPENDS`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#appends) 和 [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) 只能读取源表在 [BigQuery 时间旅行窗口](https://docs.cloud.google.com/bigquery/docs/time-travel)内发生的变更。该窗口默认为七天，最短可设为两天。如果复制进度超出该窗口，请重新执行初始加载，以恢复完整的数据副本。BigQuery 会对这三种方法产生的查询收费。为 [`CHANGES`](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/time-series-functions#changes) 启用变更历史记录还会增加 BigQuery 存储成本。
</Note>

#### 服务账号凭证 {#service-account-credentials}

ClickPipes 使用[服务账号密钥](https://docs.cloud.google.com/iam/docs/keys-create-delete)对你的 Google Cloud 项目进行身份验证。我们建议创建一个专用的服务账号，并仅授予满足要求的最小[权限](#permissions)，以便 ClickPipes 能够从 BigQuery 导出数据、将其加载到暂存 GCS 存储桶中，并将其读入 ClickHouse。

<div id="permissions">
  ### 权限 {#permissions}
</div>

#### BigQuery {#bigquery}

服务账号需要具备以下 BigQuery 角色：

* [`roles/bigquery.dataViewer`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.dataViewer)
* [`roles/bigquery.jobUser`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.jobUser)

如需持续复制，还必须在 Google Cloud 项目级别授予 [`roles/bigquery.readSessionUser`](https://docs.cloud.google.com/bigquery/docs/access-control#bigquery.readSessionUser) 角色。ClickPipes 使用 [BigQuery Storage Read API](https://docs.cloud.google.com/bigquery/docs/reference/storage#permissions) 创建读取会话并读取 CDC 查询结果。此角色不能在数据集级别授予；源数据集或表上的 `roles/bigquery.dataViewer` 角色仍需保留，以便服务账号读取其中的数据。

为进一步缩小访问范围，我们建议使用 [IAM 条件](https://docs.cloud.google.com/bigquery/docs/conditions) 来限制该角色可访问的资源。例如，你可以将 `dataViewer` 角色限制为仅可访问包含待同步表的特定数据集：

```bash
resource.name.startsWith("projects/<PROJECT_ID>/datasets/<DATASET_NAME>")
```

<div id="cloud-storage">
  #### 云存储 {#cloud-storage}
</div>

服务账号必须具备以下 Cloud Storage 角色：

* [`roles/storage.objectAdmin`](https://docs.cloud.google.com/storage/docs/access-control/iam-roles#storage.objectAdmin)
* [`roles/storage.bucketViewer`](https://docs.cloud.google.com/storage/docs/access-control/iam-roles#storage.bucketViewer)

为进一步收窄访问范围，我们建议使用 [IAM 条件](https://docs.cloud.google.com/bigquery/docs/conditions) 来限制角色可访问的资源。例如，你可以将 `objectAdmin` 和 `bucketViewer` 角色限制为只能访问专门为 ClickPipes 同步创建的存储桶。

```bash
resource.name.startsWith("projects/_/buckets/<BUCKET_NAME>")
```
