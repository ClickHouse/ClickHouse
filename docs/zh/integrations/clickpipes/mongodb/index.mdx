您可以使用 ClickPipes 将 MongoDB 数据库中的数据摄取到 ClickHouse Cloud。源 MongoDB 数据库既可以托管在本地环境中，也可以通过 MongoDB Atlas 等服务托管在云端。

MongoDB ClickPipes 既可以通过 ClickPipes UI 手动部署和管理，也可以通过 [OpenAPI](/zh/integrations/clickpipes/programmatic-access/openapi) 和 [Terraform](/zh/integrations/clickpipes/programmatic-access/terraform) 以编程方式部署和管理。

## 前置条件 {#prerequisites}

开始之前，您首先需要确保 MongoDB 数据库已正确配置复制。具体配置步骤取决于您部署 MongoDB 的方式，因此请按照下方对应的指南进行操作：

1. [MongoDB Atlas](/zh/integrations/clickpipes/mongodb/source/atlas)

2. [通用 MongoDB](/zh/integrations/clickpipes/mongodb/source/generic)

3. [亚马逊 DocumentDB](/zh/integrations/clickpipes/mongodb/source/documentdb)

源 MongoDB 数据库设置完成后，您就可以继续创建 ClickPipe。

#### 配置高级设置 {#advanced-settings}

如有需要，您可以配置高级设置。下面简要介绍各项设置：

* **Sync interval**：指 ClickPipes 轮询源数据库变更的时间间隔。该设置会影响目标端 ClickHouse 服务；对于注重成本的用户，建议将其设为较大的值 (大于 `3600`) 。
* **拉取批次大小**：单个批次中拉取的行数。这是一个尽力而为的设置，因此在某些情况下可能无法严格遵循。
* **Snapshot number of tables in parallel**：指初始快照期间并行拉取的表数量。如果您有大量表，并希望控制并行拉取的表数，此设置会很有用。

### 配置表 {#configure-the-tables}

5. 在此处，您可以为 ClickPipe 选择目标数据库。您可以选择现有数据库，也可以新建一个数据库。

   <div className="ch-image-lg">
     <Frame>
       ![选择目标数据库](/images/integrations/data-ingestion/clickpipes/mongodb/select-destination-db.webp)
     </Frame>
   </div>

6. 您可以从源 MongoDB 数据库中选择要复制的表。选择表时，还可以在目标 ClickHouse 数据库中为这些表重命名。

集合可以通过以下两种模式进行复制：

* **默认摄取**：文档按原样以 JSON 类型摄取到 ClickHouse 中。在这种情况下，目标表会包含一个专用于 `id` 的列，以及一个存放完整文档的 `doc` 列。
* **结构化摄取**：文档会按照该集合的通用 schema，以行的形式摄取到表中。该 schema 是在创建管道时根据样本推断得出的。为集合开启 **Map document to columns** 即可启用此模式。

启用结构化摄取后，**Column settings** 部分会列出样本中发现的字段及其推断出的 ClickHouse 类型。您可以选择将哪些字段作为列进行复制，其中 `_id` 文档键始终包含在内，类型为 `String`。

<div className="ch-image-md">
  <Frame>
    ![集合的结构化摄取设置](/images/integrations/data-ingestion/clickpipes/mongodb/mongodb-structured-ingestion.webp)
  </Frame>
</div>

由于 MongoDB 集合具有多态性 (即同一集合中的文档可以具有不同的 schema) ，结构化摄取需要处理离群记录：

* **缺失字段：** 所有结构化列均以 `Nullable` 类型摄取，因此如果某个文档缺少某个字段，对应列的值将为 `NULL`。

* **额外字段：** 不属于推断 schema 的字段会以 JSON 形式存储在 `_peerdb_malformed_data` 列中，每个字段对应一个键。每个键包含 `"unexpected_field": true`，原始值则存放在 `value` 下：

  ```json
  {
    "rating": {
      "unexpected_field": true,
      "value": 4.5
    }
  }
  ```

  这些数据可以方便地进行查询和分析。例如，列出表中出现的意外字段：

  ```sql
  SELECT DISTINCT arrayJoin(JSONAllPaths(_peerdb_malformed_data)) AS malformed
  FROM movies
  WHERE malformed LIKE '%.unexpected_field';
  ```

  📝 说明：如果您不希望额外字段的值出现在 `_peerdb_malformed_data` 列中，可以为该集合启用 **Hide unexpected values** 选项。

* **字段类型不匹配：** 类型与列类型不匹配的值同样会存储在 `_peerdb_malformed_data` 列中，每个字段对应一个键。每个键包含 `"type_mismatch": true`，原始值则存放在 `value` 下。对应的列会被设为 `NULL`：

  ```json
  {
    "year": {
      "type_mismatch": true,
      "value": "two thousand nineteen"
    }
  }
  ```

  如需读取某个字段 (无论其值是否与预期类型匹配) ，可将该列与其回退值结合使用：

  ```sql
  SELECT name, coalesce(year, _peerdb_malformed_data.year.value)
  FROM movies;
  ```

📝 说明：您可以将 `_peerdb_malformed_data` 中包含的字段视为回退到 JSON 列摄取的离群值。

由于结构化摄取会在创建表之前推断 schema，启用该模式后，即可基于结构化列自定义分区表达式和 sorting key。
所有结构化列均以 `Nullable` 类型摄取，因此在编写分区键表达式或在 sorting key 中使用这些列时，请注意这一点。在这些情况下，目标表创建时会启用 `allow_nullable_key` 设置。

📝 在两种摄取模式下，如果您希望删除事件在目标 ClickHouse 中记录被删除的值，均可开启 **Persist deleted documents** 选项。请注意，这要求源集合已启用 `changeStreamPreAndPostImage`。

## 注意事项 {#caveats}

使用此连接器时，请注意以下几点：

* 需要使用 5.1.0 及以上版本的 MongoDB。
* 我们使用 MongoDB 原生的 Change Streams API 来实现 CDC (变更数据捕获) ，该 API 依赖 MongoDB 的 oplog 捕获实时变更。
* 默认情况下，MongoDB 中的文档会以 JSON 类型复制到 ClickHouse 中。这让 schema 管理更加灵活，并可使用 ClickHouse 丰富的 JSON 操作符进行查询和分析。你可以在[这里](/zh/reference/data-types/newjson)了解有关查询 JSON 数据的更多信息。
