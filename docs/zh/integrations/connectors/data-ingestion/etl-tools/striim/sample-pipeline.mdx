SQL Server 中的业务数据通常是订单、支付和库存的权威数据源，但 SQL Server 并不适合承担繁重的分析查询。在本演练中，您将通过自动化管道把一张 SQL Server 表复制到 ClickHouse：Striim 先加载现有行，随后将每一次插入、更新和删除操作实时流式传输到 ClickHouse。最后，您将在 ClickHouse 中查询结果。

完整演练请参阅 [Introducing Automated Pipelines for Effortless Data Replication](https://www.striim.com/blog/automated-pipelines-5-0/)。

使用 SQL Server CDC (变更数据捕获) 需要订阅 Striim for ClickHouse **Premium** 套餐。

## 构建目标 {#what-you-will-build}

SQL Server (`sales.orders`) &gt; Striim 初始加载，随后进行 CDC (变更数据捕获) &gt; ClickHouse (`sales.orders`，`ReplacingMergeTree`)

## 开始之前 {#before-you-begin}

* 一个正在运行且采用 Premium 套餐的 Striim for ClickHouse 服务 (参见[入门](/zh/integrations/connectors/data-ingestion/etl-tools/striim/get-started)) 。
* 一个可从 Striim 访问的 SQL Server 实例，需已运行 SQL Server Agent，且具有启用变更数据捕获的权限。以下步骤适用于部署在 VM 上的 SQL Server 以及亚马逊 RDS for SQL Server。
* 一个 ClickHouse 服务、一个名为 `sales` 的数据库、一个具备所需特权的 Striim 用户，以及一个 ClickHouse 连接 profile。

## 步骤 1：准备 SQL Server {#step-1-prepare-sql-server}

创建一个数据库，以及一个包含若干行数据的示例表。这些种子数据仅用于演示，方便您复现该示例。

```sql
CREATE DATABASE salesdb;
GO
USE salesdb;
GO
CREATE SCHEMA sales;
GO
CREATE TABLE sales.orders (
  order_id    INT           NOT NULL PRIMARY KEY,
  customer_id INT           NOT NULL,
  status      VARCHAR(20)   NOT NULL,
  total       DECIMAL(10,2) NOT NULL,
  placed_at   DATETIME2     NOT NULL
);
INSERT INTO sales.orders VALUES
  (1, 101, 'NEW',     120.50, SYSDATETIME()),
  (2, 102, 'NEW',      75.00, SYSDATETIME()),
  (3, 103, 'NEW',     310.25, SYSDATETIME());
GO
```

在数据库上启用变更数据捕获，并为 Striim 创建一个用户。应用程序启动时，Striim 会为每个选定的表启用 CDC (变更数据捕获) 。

<Tabs>
  <Tab title="VM 上的 SQL Server" id="enable-cdc-vm">
    ```sql
    USE salesdb;
    EXEC sys.sp_cdc_enable_db;
    ```
  </Tab>

  <Tab title="亚马逊 RDS for SQL Server" id="enable-cdc-rds">
    ```sql
    EXEC msdb.dbo.rds_cdc_enable_db 'salesdb';
    ```
  </Tab>
</Tabs>

在 `salesdb` 中创建 Striim 用户：

```sql
USE salesdb;
CREATE LOGIN striim WITH PASSWORD = '<strong password>';
CREATE USER striim FOR LOGIN striim;
EXEC sp_addrolemember @rolename = db_owner, @membername = striim;
```

必须为 Striim 用户启用 SQL Server 身份验证模式。根据 Striim 文档，读取器用户需要具备 `db_owner` 权限。管道启动后，可以执行 `EXEC sys.sp_cdc_help_change_data_capture` 来确认 CDC (变更数据捕获)  已处于活跃状态。有关 Azure VM 的前置条件以及 Always On 可用性组的说明，请参阅 [Configuring SQL Server to use MS SQL Reader](https://www.striim.com/docs/striimforclickhouse/en/configuring-sql-server-to-use-ms-sql-reader.html)。

## 步骤 2：创建自动化管道 {#step-2-create-the-automated-pipeline}

1. 在 Striim 中，选择 **Apps &gt; Create an App**。
2. 搜索并选择 **SQL Server** 作为源，选择 **ClickHouse** 作为目标。
3. 选择 **Get Started**，然后选择自动化管道 (初始加载 + CDC (变更数据捕获)  ) 。
4. 为管道命名 (例如 `SqlServerToClickHouse`) ，选择一个命名空间，然后选择 **Next**。
5. 输入 SQL Server 连接详情：主机和端口 (`<host>:1433`) 、数据库名称 `salesdb` 以及 `striim` 用户。选择 **Next**，Striim 会验证该连接。如果校验失败，请选择 **Back** 并修正设置；必须通过校验才能继续。
6. 选择要复制的 schema。选择 `sales`，不要选择系统 schema。
7. 从每个 schema 中选择要复制的表。选择 `orders`。
8. 选择您的 ClickHouse 连接 profile，并将 **Table Engine** 设置为 **`ReplacingMergeTree`**。对于在更新时发送完整行镜像的 CDC (变更数据捕获)  源，该引擎十分适用。
9. (可选) 编辑表映射。确认 `sales.orders` 映射到 ClickHouse 中的 `sales.orders`。
10. 检查设置，然后选择 **Save &amp; Start**。

![检查 SQL Server 到 ClickHouse 自动化管道配置](/images/integrations/striim/automated-pipeline-wizard.png)

*向导检查页面示例。在本演练中，请按上文所述使用 `salesdb`、`sales.orders` 和 `ReplacingMergeTree`。*

Striim 会创建两个相互关联的应用程序。它首先执行初始加载，待所有行复制完成后将其静默，随后自动启动 CDC (变更数据捕获)  应用程序，并在变更数据流入时显示事件计数。如果任一阶段出现问题，管道会暂停并给出建议的修复方法。

![监控正在运行的变更数据捕获应用程序](/images/integrations/striim/pipeline-monitoring.png)

<Warning>
  在初始加载运行期间，请勿对源表执行 DDL；同时请确保从初始加载开始直到 CDC (变更数据捕获)  应用程序追上进度为止，SQL Server 始终保留变更数据 (默认保留期限为三天) 。
</Warning>

## 步骤 3：在 ClickHouse 中验证初始加载 {#step-3-verify-the-initial-load-in-clickhouse}

Striim 已使用 `ReplacingMergeTree` 引擎创建了 target table，并添加了两个元数据列。查看该表：

```sql
SHOW CREATE TABLE sales.orders;
```

根据 Striim 的数据类型映射，`order_id` 和 `customer_id` 的类型应为 `Int32`，`status` 应为 `String`，`total` 应为 `Decimal(10, 2)`，`placed_at` 应为 `DateTime64`；此外，表中还应包含 `__STRIIM_VERSION` (`UInt64`) 和 `__STRIIM_ISDELETED` (`UInt8`) 两列，并使用 `ENGINE = ReplacingMergeTree(__STRIIM_VERSION, __STRIIM_ISDELETED)` 和 `ORDER BY order_id`。

```sql
SELECT order_id, customer_id, status, total
FROM sales.orders FINAL
WHERE __STRIIM_ISDELETED = 0
ORDER BY order_id;
```

此时应能看到从 SQL Server 加载的三行数据。

## 步骤 4：流式传输变更 {#step-4-stream-changes}

在 SQL Server 中执行一些数据变更：

```sql
USE salesdb;
UPDATE sales.orders SET status = 'SHIPPED' WHERE order_id = 2;
DELETE FROM sales.orders WHERE order_id = 3;
INSERT INTO sales.orders VALUES (4, 104, 'NEW', 42.00, SYSDATETIME());
```

在 ClickHouse 中再次运行相同的查询。此时应能看到订单 1、2 和 4，其中订单 2 应显示为 `SHIPPED`，而订单 3 应已不存在。删除操作会以软删除行的形式存储。该查询使用 `FINAL` 选取最新版本，并通过 `__STRIIM_ISDELETED = 0` 排除已删除的行。删除标记默认会被保留；仅靠后台合并并不能保证将其物理移除。有关清理行为，请参阅 [`ReplacingMergeTree`](/zh/reference/engines/table-engines/mergetree-family/replacingmergetree#is_deleted)。您还可以在 Striim 监控视图中查看事件计数和目标端的数据新鲜度，或向 Clara 询问当前延迟。

## 使用 Striim Clara 构建相同的管道 {#build-the-same-pipeline-with-striim-clara}

除了使用向导，您还可以在首页上直接描述所需的管道，例如：“Build a pipeline from SQL Server to ClickHouse with initial load and change data capture for the sales.orders table.” (为 sales.orders 表构建一条从 SQL Server 到 ClickHouse 的管道，包含初始加载和变更数据捕获。) Clara 会询问连接详情并生成 TQL 计划，只有在您点击 **Accept TQL** 后才会执行部署。

## 清理 {#clean-up}

* 在 Apps 页面中停止这两个 Striim 应用程序并取消其部署。
* 在使用默认读取器设置的情况下，即使取消部署 Striim 应用程序，SQL Server 仍会继续捕获变更数据。若要停止为本示例捕获数据，请对 `sales.orders` 运行 `sys.sp_cdc_disable_table`；如果数据库中没有其他表需要使用 CDC (变更数据捕获)  ，也可以运行 `sys.sp_cdc_disable_db`。详情请参阅 SQL Server [文档](https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sys-sp-cdc-disable-table-transact-sql)。此外，也可以按照 Striim 的 [Auto Disable Table CDC (变更数据捕获)  流程](https://www.striim.com/docs/striimforclickhouse/en/sql-server-operational-considerations.html)进行操作。
* 删除示例表：在两个系统中分别执行 `DROP TABLE sales.orders;`。
