[Striim for ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/introducing-striim-for-clickhouse.html) 是一款全托管 SaaS 服务，可将数据库、数据仓库、数据湖和 SaaS 应用中的数据导入 ClickHouse，支持 Oracle、Microsoft SQL Server 和 Snowflake 等企业级数据源。它先加载已有记录，再通过 CDC (变更数据捕获) 以流式方式同步插入、更新和删除操作，让 ClickHouse 中的数据始终保持最新，为 AI 工作负载、仪表盘和数据应用提供支撑。

Striim for ClickHouse 托管于 AWS 上的 Striim Cloud，支持自助服务注册，按月根据用量计费，无需签订年度合约。您可以在 striim.com 或通过 AWS Marketplace 注册，开启 14 天免费试用，并通过自然语言提示词、向导或流程设计器构建管道。

## 主要特性 {#key-features}

* **变更数据捕获与初始加载：** 先加载现有数据，再切换为对插入、更新和删除操作的持续实时复制。自动化管道向导可帮助创建并关联这两个阶段，并自动从初始加载过渡到 CDC (变更数据捕获)  复制。
* **ClickHouse 写入器：** 可为每个管道单独选择表引擎 (`MergeTree`、`ReplacingMergeTree`、`CollapsingMergeTree`、`CoalescingMergeTree` 等) 。Striim 会创建目标端表，按所选引擎处理更新和删除，并设置 sorting key。
* **Schema 处理：** 对于受支持的数据源，可根据源端自动创建目标 schema；对于受支持的 CDC (变更数据捕获)  数据源，可同步选定的 DDL 变更 (`CREATE TABLE`、`ADD COLUMN`、`ALTER TABLE ... MODIFY COLUMN`、`DROP COLUMN`、`DROP TABLE` 和 `TRUNCATE TABLE`) 。
* **传输中处理：** 在源端与 ClickHouse 之间对数据进行过滤、补充信息和转换。
* **AI 辅助运维：** Striim Clara AI 是一款对话式 AI 智能体，可根据自然语言描述构建管道、报告延迟和吞吐量，并解释故障原因。部署到生产环境之前，请先审核生成的结果。
* **私有连接：** 支持通过 AWS PrivateLink、SSH 隧道和 IP 白名单限制连接数据源和 ClickHouse。
* **监控与告警：** 内置管道监控功能，并可通过电子邮件、Slack、Microsoft Teams 和 Striim Web UI 发送告警。

## 用例 {#use-cases}

| **用例**      | **Striim for ClickHouse 的作用**                                                            |
| ----------- | ---------------------------------------------------------------------------------------- |
| 实时分析        | CDC (变更数据捕获)  读取器让 ClickHouse 表始终保持最新，交互式仪表盘因此能反映几秒前的活动，而不是上一个批处理周期的数据。                            |
| AI 智能体与 RAG | 让 ClickHouse 表始终保持最新 (包括用于向量搜索或 MCP 服务器的表) ，使智能体能够读取到最新的业务数据。                            |
| 特征存储与模型推理   | 让实体级特征始终保持最新，供欺诈检测、个性化推荐等近实时评分模型使用。                                                      |
| 数据仓储        | 从 Oracle、SQL Server、Snowflake 和 Salesforce 等数据源直接写入 ClickHouse，无需额外的暂存层或流式处理层。           |
| 可观测性        | 将数据库日志和应用日志流式写入存放遥测数据的同一 ClickHouse 实例，以便对二者进行联合查询。可作为 ClickStack 和 OpenTelemetry 摄取的补充。 |

## 运维注意事项 {#operational-considerations}

* 投递语义为至少一次。重启或恢复后，已写入的事件可能会被重复写入。最终的数据记录取决于所用的表引擎 (参见 [数据如何写入 ClickHouse](/zh/integrations/connectors/data-ingestion/etl-tools/striim/get-started#how-data-lands-in-clickhouse)) 。
* 模式演进不支持列重命名或可空性变更，也不适用于目标为 `AggregatingMergeTree`、`Replicated` 或 `Distributed` 的表。不支持 `VersionedCollapsingMergeTree` 和 `GraphiteMergeTree`。
* 部分数据源类型无法映射到 ClickHouse，在自动创建 schema 时会被跳过，例如 `SQL Server GEOGRAPHY`、`GEOMETRY`、`HIERARCHYID` 和 `SQL_VARIANT`；`Oracle BFILE`、`LONG`、`LONG RAW`、`SDO_GEOMETRY` 和 `UROWID`；以及 `MySQL GEOMETRY` 和 `SET`。
