本指南介绍如何将集群中的日志、基础设施指标和 Kubernetes 事件采集到自管理 ClickHouse Observability 中，并在内置的 Kubernetes 仪表板中查看这些数据。

该方案遵循标准的 OpenTelemetry 模式：通过 [OpenTelemetry Helm 图表](https://github.com/open-telemetry/opentelemetry-helm-charts/tree/main/charts/opentelemetry-collector)部署两个采集器，二者均通过 OTLP 将数据转发到您的 ClickStack gateway 采集器。**DaemonSet 守护进程集**运行在每个节点上，负责采集容器日志和 kubelet 节点代理指标；单副本的**部署** (Deployment) 负责采集 Kubernetes 事件和集群级指标。有关 gateway 角色的背景信息，请参阅[采集器角色](/zh/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)。

本指南假定您已完成[设置 OpenTelemetry 采集器](/zh/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)中的步骤，并已有一个正在运行的 ClickStack gateway 采集器。

对于运行在 Kubernetes 中的工作负载，gateway 采集器本身应**部署在同一集群内，使用上游 OpenTelemetry Helm 图表并搭配 ClickStack 采集器镜像**。请按照[部署采集器](/zh/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)中的 Helm 方式完成安装。**请务必记下该 OTLP 端点**。

<Steps>
  <Step title="满足前置条件" id="gather-prerequisites">
    你需要准备：

    * 一个 **Kubernetes 集群** (建议 v1.20+) ，并已配置好指向该集群的 `kubectl`。
    * **[Helm](https://helm.sh/) v3+**。
    * ClickStack gateway 采集器的 **OTLP 端点**，且需能从集群内部访问，例如 `http://clickstack-otel-collector.observability.svc.cluster.local:4318`。采集器应部署在你的各个 DaemonSet 守护进程集和部署都能访问到的位置，通常是同一集群内，或通过 `LoadBalancer` 类型的服务对外暴露。
    * 部署 gateway 采集器时设置的 `OTLP_AUTH_TOKEN` 值。如果你没有为采集器启用安全保护，可以跳过下文创建机密信息的步骤，并从资源清单中删除 `authorization` 请求头。

    <Info>
      **gateway 的运行位置**

      如果在集群本地部署，请在同一集群内以 Kubernetes `Deployment` 或 `StatefulSet` 的形式运行 gateway 采集器，并通过其 in-cluster 服务 DNS 名称进行访问。如果 gateway 运行在集群外部，请使用其可从外部访问的 URL。
    </Info>
  </Step>

  <Step title="创建身份验证机密信息和 ConfigMap" id="create-secret-and-configmap">
    选择用于部署采集器的命名空间，然后创建一个保存 `OTLP_AUTH_TOKEN` 的 Secret，以及一个指向 gateway 的 ConfigMap：

    ```shell
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    export OTEL_COLLECTOR_ENDPOINT="http://clickstack-otel-collector.observability.svc.cluster.local:4318"
    export NAMESPACE=observability

    kubectl create namespace ${NAMESPACE} --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic clickstack-otlp-secret \
      --from-literal=OTLP_AUTH_TOKEN=${OTLP_AUTH_TOKEN} \
      -n ${NAMESPACE}

    kubectl create configmap otel-config-vars \
      --from-literal=YOUR_OTEL_COLLECTOR_ENDPOINT=${OTEL_COLLECTOR_ENDPOINT} \
      -n ${NAMESPACE}
    ```

    下面两个采集器都通过 `extraEnvs` 读取这些值，因此会共用同一个机密信息和 ConfigMap。
  </Step>

  <Step title="添加 OpenTelemetry Helm 仓库" id="add-otel-helm-repo">
    ```shell
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update
    ```
  </Step>

  <Step title="部署集群采集器" id="deploy-cluster-collector">
    这是一个单副本 Deployment，用于采集 **Kubernetes 事件**和**集群级指标** (节点数量、pod (容器组) 阶段、部署状态等) 。运行多个副本会导致数据重复。

    将以下内容保存为 `k8s_deployment.yaml`：

    <Accordion title="k8s_deployment.yaml">
      ```yaml
      # k8s_deployment.yaml
      mode: deployment

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # 此类采集器只需一个——多于一个就会产生重复数据
      replicaCount: 1

      presets:
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        # 通过 k8sobject receiver 采集 Kubernetes 事件。
        kubernetesEvents:
          enabled: true
        # 通过 k8s_cluster receiver 采集集群级指标。
        clusterMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"
        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    执行安装：

    ```shell
    helm install k8s-otel-deployment open-telemetry/opentelemetry-collector \
      -f k8s_deployment.yaml \
      -n ${NAMESPACE}
    ```
  </Step>

  <Step title="部署节点采集器" id="deploy-node-collector">
    这是一个在每个节点上运行的 DaemonSet 守护进程集，用于采集**容器日志**、**主机指标**和 **kubelet 节点代理指标** (即各 pod (容器组) 及各容器的 CPU 与内存相对于 requests 和 limits 的利用率) 。

    将以下内容保存为 `k8s_daemonset.yaml`：

    <Accordion title="k8s_daemonset.yaml">
      ```yaml
      # k8s_daemonset.yaml
      mode: daemonset

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # 使用 kubeletstats 的 cpu/memory 利用率指标时必需
      clusterRole:
        create: true
        rules:
          - apiGroups:
              - ''
            resources:
              - nodes/proxy
            verbs:
              - get

      presets:
        logsCollection:
          enabled: true
        hostMetrics:
          enabled: true
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        kubeletMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        receivers:
          # 额外的 kubelet 指标，以相对于 requests 和 limits 的利用率表示。
          kubeletstats:
            collection_interval: 20s
            auth_type: 'serviceAccount'
            endpoint: '${env:K8S_NODE_NAME}:10250'
            insecure_skip_verify: true
            metrics:
              k8s.pod.cpu_limit_utilization:
                enabled: true
              k8s.pod.cpu_request_utilization:
                enabled: true
              k8s.pod.memory_limit_utilization:
                enabled: true
              k8s.pod.memory_request_utilization:
                enabled: true
              k8s.pod.uptime:
                enabled: true
              k8s.node.uptime:
                enabled: true
              k8s.container.cpu_limit_utilization:
                enabled: true
              k8s.container.cpu_request_utilization:
                enabled: true
              k8s.container.memory_limit_utilization:
                enabled: true
              k8s.container.memory_request_utilization:
                enabled: true
              container.uptime:
                enabled: true

        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"

        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    执行安装：

    ```shell
    helm install k8s-otel-daemonset open-telemetry/opentelemetry-collector \
      -f k8s_daemonset.yaml \
      -n ${NAMESPACE}
    ```

    确认两个 release 均处于健康状态：

    ```shell
    kubectl get pods -n ${NAMESPACE} -l app.kubernetes.io/name=opentelemetry-collector
    ```

    您应能看到 1 个部署 pod (容器组) ，并且每个节点上各有 1 个 DaemonSet 守护进程集 pod (容器组) ，所有 pod 均处于 `Running` 状态。
  </Step>

  <Step title="将 Kubernetes 属性转发到您的应用（推荐）" id="forward-k8s-attributes">
    要将应用日志、指标和链路追踪与 Kubernetes 元数据 (pod (容器组) 名称、命名空间、节点、部署) 关联起来，请通过 `OTEL_RESOURCE_ATTRIBUTES` 将这些元数据传入您的应用程序。随后，DaemonSet 守护进程集的 `k8sattributes` 处理器会根据匹配的 pod (容器组) 和节点属性，为传入的遥测数据补充信息。

    ```yaml
    # my_app_deployment.yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: app-deployment
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: app
      template:
        metadata:
          labels:
            app: app
            service.name: <MY_APP_NAME>
        spec:
          containers:
            - name: app-container
              image: my-image
              env:
                - name: POD_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.name
                - name: POD_UID
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.uid
                - name: POD_NAMESPACE
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.namespace
                - name: NODE_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: spec.nodeName
                - name: DEPLOYMENT_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.labels['deployment']
                - name: OTEL_RESOURCE_ATTRIBUTES
                  value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME),k8s.deployment.name=$(DEPLOYMENT_NAME)
    ```
  </Step>

  <Step title="在 ClickStack 用户界面中确认" id="confirm-in-ui">
    在 [ClickHouse Cloud 控制台](https://console.clickhouse.cloud)中打开您的服务，然后从左侧菜单中选择 **ClickStack**。

    <div className="ch-image-lg">
      <Frame>
        ![启动 ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    在 **搜索** 视图中，将 source 切换为 `Logs`，并将时间范围设置为 **Last 15 minutes**。几秒钟内应能看到来自整个集群的容器日志，这些日志已富化了 `k8s.namespace.name`、`k8s.pod.name` 和 `k8s.node.name` 等属性。

    <div className="ch-image-lg">
      <Frame>
        ![包含 Kubernetes 日志的 ClickStack 搜索视图](/images/use-cases/observability/clickstack-search-with-k8-logs.webp)
      </Frame>
    </div>

    如需结合上下文查看基础设施指标和事件，请依次进入 **Dashboards** -&gt; **Kubernetes**，打开内置的 **Kubernetes** 仪表板。此时 `Pods`、`Nodes` 和 `Namespaces` 选项卡中均应已有数据。

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack Kubernetes 仪表板](/images/use-cases/observability/clickstack-dashboard-kubernetes.webp)
      </Frame>
    </div>

    如果没有显示任何数据：

    * 确认 DaemonSet 守护进程集和部署的 Pod (容器组) 均处于 `Running` 状态，并使用 `kubectl logs -n ${NAMESPACE} <pod>` 实时查看其日志。
    * 确认 `YOUR_OTEL_COLLECTOR_ENDPOINT` 可从集群内部访问 (通过 `kubectl exec` 进入任一采集器 Pod (容器组) ，再用 `curl` 访问该端点) 。
    * 检查机密信息中的 `OTLP_AUTH_TOKEN` 是否与 gateway 采集器上设置的值一致。
  </Step>
