## 图表编辑器中的指标公式 {#metric-formulas-in-the-chart-editor}

*演示者：[@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tSCoW-GGXTU" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

指标图表现在支持算术运算了。在本周之前，同一图表上的两个指标只能是两条独立的线，无法组合计算。

图表中的数据系列依次标记为 `A`、`B`、`C` 等。通过公式行，您可以基于这些引用构建派生数据系列。例如，`A / (A + B + C) * 100` 可以得出队列利用率。同理，您也可以根据采集器的接收计数和发送计数来计算饱和度。

您可以在一个图表中添加多个公式，选择将操作数数据系列与结果一同显示，或仅显示公式结果，还可以混合使用来自不同指标的数据系列。告警同样支持公式。

算术运算本身在 ClickHouse 中执行。每个公式都会从经过校验的 AST 编译进组合后的指标查询，因此 ClickHouse 会在单个查询中完成计算，而不是由应用事后再连接各个结果。每个数据系列对应一个 CTE，公式则在连接后的结果上求值。

缺失的操作数按零计算，因此没有错误的分组会显示为 0%，而不是 N/A。每个除法的分母都会用 `nullif(..., 0)` 包裹，因此分母为零或缺失时会渲染为间断，而不是显示零或报错。

后续的一项改动将 `HAVING`、`ORDER BY` 和 `LIMIT` 移到最终的连接上执行，而不再应用于每个 `UNION` 分支。此前，这些子句所在的作用域中并不存在面向用户的输出名称。这导致每个数据系列在连接之前就被各自独立过滤，而最终的行顺序仍是非确定性的。

目前输入框仅接受字母引用和简单的算术运算，暂不支持任意 SQL。未知的数据系列引用、格式错误的表达式以及仅含常量的表达式，都会实时提示在输入框下方。同样的校验也会阻止保存和运行，因此无效表达式绝不会发送到 ClickHouse。

按位运算符和 ClickHouse 函数暂不支持。这并没有什么深层原因，只是第一个版本做到了这里为止，更广泛的表达式支持可能会是我们接下来添加的功能。

讨论中还提到了两项尚未实现的功能。一是公式无法引用其他公式，因此无法将 `F1` 串联到 `F2` 中。二是针对单个数据系列的显示/隐藏控制会比作用于整个图表的操作数开关更实用：隐藏 `A` 和 `B`，同时仍让它们参与公式计算，这才是用户真正想要的。

另有一个很中肯的问题：连接最多能推进到什么程度，再往后就不再实用？用过 PromQL 除法的人都熟悉这种失败情形：连接没有按预期匹配，并且在没有任何提示的情况下返回空数据。

**相关 PR：** [#2908](https://github.com/hyperdxio/hyperdx/pull/2908) 在组合指标查询中渲染公式，[#2909](https://github.com/hyperdxio/hyperdx/pull/2909) 指标公式的图表编辑器 UI，[#2946](https://github.com/hyperdxio/hyperdx/pull/2946) 将 HAVING/ORDER BY/LIMIT 应用于组合指标连接而非各数据系列分支，[#2952](https://github.com/hyperdxio/hyperdx/pull/2952) 在各 API 接口中支持公式，[#2953](https://github.com/hyperdxio/hyperdx/pull/2953) 为日志/追踪事件 source 提供公式支持

## 依赖型仪表盘变量与宏 {#dependent-dashboard-variables-and-macros}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/Y0CaapNH1Vc" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

上周演示中提出的两项需求现已上线。

过滤器定义现在可以在其 `WHERE` 子句中引用其他变量，从而让一个下拉列表限定另一个下拉列表的取值范围。例如，引用了服务名称过滤器的 severity 过滤器初始为空；选择某个服务后，它只会列出该服务中实际存在的 severity 值。

当被引用的变量未选择任何值时，仍会查询选项。如果希望在这种状态下也能填充值，请使用 `$__filters` 或 `$__conditionalAll`。单纯的 `<expression> IN ($var)` 在 `$var` 有选中值之前不会返回任何结果。现在会通过工具提示说明原因，不再只显示一个空列表而不作任何解释。过滤器弹窗的 `WHERE` 输入框中也支持变量和宏的自动补全。

你可以创建循环依赖，但这不会造成实际危害，因为变量会被替换为其选中值，而不会被递归求值。

宏现在会展开作为参数传入的变量，因此 `$__timeFilter($TimeColumn)` 可以正常工作。通过变量选择一个时间戳列，宏就会基于该列展开为完整的时间戳过滤条件。传给 `$__filter` 和 `$__conditionalAll` 的变量现在必须使用 `$var` 形式。以前也接受不带前缀的 `var`，但这种宽松处理大多只会造成混淆。

外部 API v2 和 MCP 服务器均已支持变量，这也意味着 Terraform 同样支持。agent 可以构建这样的仪表盘：包含变量过滤器和广播过滤器、依赖型下拉列表，以及直接或通过宏引用这些变量的卡片。当变量被用在无法生效的位置时，create、save 和 patch 工具会发出警告。

查询卡片相关工具也接受变量值，因此 agent 可以在交付仪表盘之前自行检查变量替换结果。

**相关 PR：** [#2923](https://github.com/hyperdxio/hyperdx/pull/2923) 支持依赖型变量值查询，[#2937](https://github.com/hyperdxio/hyperdx/pull/2937) 支持嵌套宏以及在宏中引用变量，[#2944](https://github.com/hyperdxio/hyperdx/pull/2944) 在外部 API 中添加仪表盘变量，[#2951](https://github.com/hyperdxio/hyperdx/pull/2951) 在 MCP 服务器中支持仪表盘变量

## 严格客户端可接受的 MCP 工具 schema {#mcp-tool-schemas-that-strict-clients-accept}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/W4dvgYj47ZM" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

有客户反馈，他们的 agent 完全无法使用我们的 MCP 服务器。

某些 agent 框架会先列出可用工具，并在将其发送给模型提供商之前验证每个工具的输入 schema。只要有一个 schema 无效，框架就会拒绝整个工具列表，而不只是出问题的那个工具，导致服务器看起来完全不可用。

许多 agent 框架的容错性更强，但并非全都如此。对于受影响的客户端，只有分离该服务器才能让 agent 恢复正常。

现已新增一项测试，用于断言每个工具的输入 schema 均为有效的 JSON Schema draft 2020-12，确保今后新增的工具不会再以同样的方式导致严格客户端出错。

**相关 PRs：** [#2925](https://github.com/hyperdxio/hyperdx/pull/2925) 生成符合 draft-2020-12 规范的工具输入 schema；[#2971](https://github.com/hyperdxio/hyperdx/pull/2971) 将分位数水平声明为字符串枚举

## 可轮换的个人 API 访问密钥 {#rotatable-personal-api-access-keys}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tHQoaFaVPpY" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

现在可以在“团队设置 → API &amp; Agents”中轮换个人 API 访问密钥。

该密钥用作外部 API v2 和 MCP 服务器的 Bearer 令牌。此前，该密钥仅在创建账户时生成一次，之后无法更改。一旦密钥泄露，唯一的处理办法就是删除该用户。

轮换立即生效，不设宽限期，且浏览器会话会保持登录状态。请注意：该密钥归属于账户而非团队。如果您属于多个团队，则所有团队中使用该密钥的地方都需要更新。

Enterprise 会显示一条警告说明这一点。单团队的开源部署不存在这一问题，因此不会显示该警告。

此功能有两项刻意设定的限制。`PATCH /me/accessKey` 路由不接受用户标识符，因为 ID 取自会话，所以它只能轮换调用方自己的密钥。

此外，该路由不会通过使用 bearer 身份验证的外部 API v2 对外开放。在该 API 中，泄露的密钥本就可以读取自身；如果再允许其执行轮换，他人就可能让所有者无法再使用自己的工具。

**相关 PRs：** [#2926](https://github.com/hyperdxio/hyperdx/pull/2926) 支持轮换个人 API 访问密钥

## Column Values 选项卡中的键按字母顺序排列 {#alphabetical-keys-in-the-column-values-tab}

*演示者 [@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/9RfTL-dtZF0" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

现在，无论是日志还是链路追踪，行侧边面板 Column Values 选项卡中的键在每一级嵌套中都会按字母顺序排序。

此前，JSON 树按照 ClickHouse 的物理存储顺序渲染键，看起来几乎是随机的。像 `ProfileEvents` 这样包含 125 个键的 `Map` 列毫无顺序可循，要查找某个键，只能把整个列表从头看一遍。

另一个不那么明显的问题是：每一级最多只显示 50 行，而截取发生在排序之前。你看到的 50 个键只是一个任意子集，要查看其余的键，只能点击“Expand 75 more properties”。

现在，排序在 `TreeNode` 中进行，且先于列表截取。排序能够识别数字，因此 `key2` 会排在 `key10` 之前。

**相关 PRs：** [#2943](https://github.com/hyperdxio/hyperdx/pull/2943) 按字母顺序对 JSON 查看器中的键进行排序

## 将 Storybook 打造为可浏览的设计系统 {#storybook-as-a-browsable-design-system}

*演示者：[@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/mnHtrsuKsC8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Storybook 现已成为一个可浏览的设计系统，而不再只是组件沙箱。侧边栏依次为 Guidelines → Brand → Icons → Design Tokens → Components。

Guidelines 直接渲染 `agent_docs` 中的 Markdown 文档，因此代码风格、主题设置、页面布局和数据可视化配色都集中在一处。这既是给人看的，也是给 agent 看的。让 agent 参考新团队成员阅读的同一份文档，有助于让生成的组件与现有内容保持一致。

Brand 和 Icons 中包含 HyperDX 与 ClickStack 的徽标以及我们的自定义图标，例如 `IconAiNotebook`。您可以复制或下载这些 SVG，并参考相关指引，了解何时应使用兼容 Tabler 的线性图标，何时应使用品牌标识。

这项工作最初是从图标着手的，因为此前幻灯片里用的都是些看着差不多的图标。如果您需要在演示文稿中使用标识，请从这里获取。

Brand 工具栏用于在 HyperDX 与 ClickStack 之间切换，Theme 工具栏则用于切换浅色与深色主题。新组件在发布前可以在每种组合下逐一检查。此前未分类的组件 story 现已归入 `Components/` 下，图表卡片组件也一并在其中展示。

在此过程中还发现了两个问题。其一，Storybook 的字体 CSS 变量现在定义在 `<html>` 上，与应用保持一致，因此正文文本和通过 portal 渲染的弹出菜单不会再显示为 Times 字体。

其二，我们对 Tabler 图标集的使用并不统一。PromQL 或许需要一个专属图标，而指标和链路追踪目前在不同位置使用的图标也各不相同。今后请以 Storybook 为准。

在本地运行：`yarn workspace @hyperdx/app storybook`。

**相关 PR：** [#2935](https://github.com/hyperdxio/hyperdx/pull/2935) 将 Storybook 打造为可浏览的设计系统

## 直方图图表采用 categorical 调色板 {#categorical-palette-on-histogram-charts}

*演示者：[@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/wybAadS6ms0" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

直方图图表 (包括 Services 仪表盘上的 Request Latency) 此前将颜色硬编码为 `#50FA7B`。这种荧光绿并不在图表调色板中，对比度也不足。此外，工具提示中的“Number of events”同样使用了这一颜色。

现在，该图表通过 `getColorFromCSSToken` 解析 `chart-blue`，其工具提示也改用共享的 `ChartTooltipContainer` 和 `ChartTooltipItem`，使两者与折线图、条形图和饼图保持一致。

工具提示中的 **View events** 链接已移除。内部直方图和工具提示虽然接收 `generateSearchUrl`，但 `DBHistogramChart` 从未将其向下传递，因此该链接在生产环境中从未显示过。

唯一的调用方并没有针对耗时桶的搜索 URL 构建器，而按延迟范围过滤事件属于新功能，并非简单的接线修复。

改动虽小，积少成多。

**相关 PRs：** [#2949](https://github.com/hyperdxio/hyperdx/pull/2949) 在直方图图表上使用 categorical 调色板
