HyperDX 现已推出 AI 生成摘要功能，可用于日志、链路追踪和模式。全新的“生成摘要”按钮可将遥测数据浓缩为简明易读的摘要，无需逐条手动查看，即可快速了解一组事件中发生了什么。

该架构可接入 Anthropic (或类似的) API，并支持后续对话，用户在获得初始摘要后可以继续提问。

事件差异热力图可视化正在迁移到主图表构建器中，届时它将作为一种标准图表类型，与 HyperDX 的其他可视化并列提供。此前，它只能在独立的专用视图中使用；现在，它可以和其他图表类型一样在 Chart Explorer 中使用。

## 针对 schema 改进的基准测试 {#benchmarking-for-schema-improvements}

*演示者：[@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/_B7TmIiXZyM" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Aaron 介绍了 HyperDX 更新后的默认 OpenTelemetry 日志表结构的基准测试结果。此次的关键变更是删除旧版 `timestamp_time` 列 (一个秒级粒度的 32 位 Unix 时间戳) ，改为仅使用 `timestamp`。后者提供纳秒精度，同时也让 schema 少了一列。在大量查询基准测试中，更新后的 schema 几乎在所有场景下都与旧版持平或更优。

最终的 schema 还包含读取顺序优化，在高选择性查询上带来了显著提升。搜索相对罕见的 map 值时，速度约为基线的两倍；高频值查找的提升则更为明显。插入开销略有增加 (需要维护的列更多) ，但查询性能整体持平或有所提升，因此升级起来毫无顾虑。

**相关 PR：** [#2125](https://github.com/hyperdxio/hyperdx/pull/2125) feat: optimized default otel-logs schema

## 自动补全改进 {#improvements-to-autocomplete}

*演示者：[@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/8zDZx49uYQo" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

HyperDX 的自动补全功能正在进行一次大规模重构，以支持更高的基数并加快值的加载速度。新实现基于 rollup 表 (即按 15 分钟时间桶预聚合键值对的 `AggregatingMergeTrees`) ，因此系统无需在每次按键时都查询原始数据，而是从规模小得多的预计算数据集中读取。在针对一个 2.3 亿行暂存实例的现场演示中，自动补全能够快速加载 `hostname` 等 high-cardinality 字段的值，没有明显延迟。

该系统既支持仅含键的 rollup (返回所有键，但不附带值，以降低基数开销) ，也支持完整的键值 rollup。如果只有键 rollup，系统会在值查找步骤回退到现有的拉取值策略。如果完全未检测到 rollup 表，则会平稳回退到当前行为。Aaron 还指出，今后若能提供一个 allow-list UI，用于控制哪些键生成值 rollup，将对数据基数特别高的客户很有帮助。

**相关 PR：** [#2128](https://github.com/hyperdxio/hyperdx/pull/2128) feat: fast and full autocomplete，[#2127](https://github.com/hyperdxio/hyperdx/pull/2127) feat: better autocomplete

## 基于 SQL 的告警功能改进 {#improvements-to-alerting-with-sql}

*演示者 [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/BOk-LC0y2no" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

继上周为原始 SQL 折线图和条形图新增告警功能之后，HyperDX 现在也支持对原始 SQL 数值图设置告警。设置告警时不再强制要求提供时间过滤器参数：省略该参数时会显示警告，但不含任何时间维度的查询现在也完全有效。因此，可以轻松针对不随时间变化的配置值或系统指标设置告警，例如检查 ClickHouse 集群数量是否等于预期值。

此外，还新增了多种阈值类型：不等于、高于、至多、介于和超出范围。团队在表达告警条件时因此拥有了更大的灵活性，不再局限于简单的“大于”比较。最后，告警历史记录现在会直接显示在面板编辑器中：当触发的告警链接到某个仪表板面板时，用户无需离开仪表盘，即可查看完整的历史记录、了解告警的触发原因，并对告警进行确认或静默。

## 告警执行期间的错误 {#errors-during-alert-execution}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/b3G8kFiQiUg" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

告警执行失败时，HyperDX 现在会直接在 UI 中显示相应错误，而不再静默丢弃。此前，用户可能会发现告警历史记录中出现莫名的空缺：既没有错误消息，也无从调试问题所在。现在，针对不同的失败类型 (包括无效查询、Webhook 投递失败，以及 Webhook 设置缺失或配置错误) ，系统会以内联方式显示不同的错误图标。

点击错误图标即可查看诊断和解决问题所需的具体信息，用户无需翻查服务器日志或向技术支持提交请求，就能修复配置有误的告警。这一改进旨在让用户自助处理告警失败：发现错误、理解错误、修复错误。

**相关 PRs：** [#2132](https://github.com/hyperdxio/hyperdx/pull/2132) feat: Show alert execution errors in the UI，[#2136](https://github.com/hyperdxio/hyperdx/pull/2136) fix: Hide potentially-sensitive alert errors
