## ClickCannon 数据生成更新 {#clickcannon-data-generation-update}

*演示者：[@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Zljd07_4uF4" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

[ClickCannon](https://github.com/clickhouse/clickcannon) 是我们内部用于资源规模规划的工具：它在生成大量 OpenTelemetry 数据的同时发起并发查询，以估算客户在特定摄取和查询工作负载下所需的资源。我们在 OpenHouse 上正式对外发布了该工具，Spencer 也演示了它的最新版本。

现在无需预先在磁盘上准备数据，可以直接以内联方式配置生成器：启用生成器后，设置线程数、每个块的行数、每秒总行数以及若干内存限制即可。不必再先在磁盘上准备 2 TB 的测试数据，而这正是该工具此前难以对外共享的原因。

今后我们会推荐更多用户使用 ClickCannon 自行开展资源规模规划。代码仓库地址为 [https://github.com/clickhouse/clickcannon](https://github.com/clickhouse/clickcannon)。

## 全屏卡片的日期输入与按source限定的筛选条件 {#date-input-for-full-screen-tiles-and-source-scoped-filters}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Mop1EYtGwKc" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

本次同时上线了两项相关的仪表盘改进。将单个卡片全屏显示时，现在会提供专用的时间选择器和粒度选择器，且独立于仪表盘自身的时间范围。这样，您就可以针对某个特定指标 (例如 ClickHouse 集群仪表盘上的某个图表) 放大查看较长时间段的历史记录，而不会导致仪表盘上的其他卡片全部随之刷新。此外，仪表盘名称现在也会显示在浏览器标签页的标题中。

第二项改进是为仪表盘筛选条件增加了source作用范围。筛选条件可以限定为仅广播到基于特定source的卡片，而不必全局应用于所有卡片。在混合多种source (例如日志和链路追踪) 的仪表盘上，您可以避免筛选条件作用到与其无关的卡片上。

## 支持识别基于 lower(Body) 的文本索引 {#text-index-recognised-on-lower-body}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/l0GpNBP859o" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

这是一项针对不区分大小写搜索的正确性修复，改动虽小，但切实有效。如果您的 source 在 `lower(Body)` 上定义了文本索引且未指定预处理器参数，查询规划器此前会生成 `hasAllTokens(Body, ...)` 条件。由于该表达式与索引表达式不匹配，文本索引无法生效，查询会退化为扫描。

现在，生成的查询为 `hasAllTokens(lower(Body), ...)`，与索引表达式一致。对于按此方式配置的 source，不区分大小写的搜索现在能够正确利用文本索引加速。

**相关 PRs：** [#2326](https://github.com/hyperdxio/hyperdx/pull/2326) feat: support text index on lower(Body) with no preprocessor

## 更简洁的事件差异体验 {#simpler-event-deltas-experience}

*演示者：[@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/BrIHHFz_Aw8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

以前使用事件差异需要多一个步骤：在热力图上拖动选择区域之前，必须先点击按钮进入比较模式。现在这一步已经取消：页面加载后会立即显示分布条形图；只要在热力图上拖选一个区域，条形图就会切换为“选中区域 vs 背景”的比较模式。点击选中区域以外的位置，即可回到全部 span 视图。

这项改动早在几周前就已合入 OSS，但托管 ClickStack 中还缺少其中一部分。现在这一缺口已经补齐，两个版本的简化流程完全一致。

**相关 PRs：** [#1899](https://github.com/hyperdxio/hyperdx/pull/1899) feat: always-on attribute distribution mode

## 仪表盘目录与批量折叠 {#dashboard-table-of-contents-and-bulk-collapse}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Pojo5zf_hrE" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

当仪表盘的分区多到一定数量后 (这本身是我们所鼓励的，因为分区正是组织大型仪表盘的方式) ，在其中导航就会变得十分麻烦。Tom 新增了一个右侧目录栏，列出所有分区，可直接在各分区之间跳转。此外还新增了批量折叠/展开控件，可一键隐藏所有分区的内容，无需从头滚动到尾，即可快速浏览长仪表盘的整体结构。

该功能目前仍处于草稿阶段，但在我们为 ClickHouse 集群和 Kubernetes 视图提供的多分区仪表盘中已经相当实用。

**相关 PRs：** [#2350](https://github.com/hyperdxio/hyperdx/pull/2350) feat(dashboard): add Table of Contents right rail with bulk collapse/expand

## 列宽调整跨会话持久化 {#column-resize-persisted-across-sessions}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/7l-Rz1tFlq8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

昨天有客户反馈：在结果表中调整列宽后，调整结果应当被保留下来。现在这一点已经实现。调整后的列宽保存在浏览器本地存储中，并以表 ID 为键分别存储，因此不同的表各自维护独立的列布局。即使关闭浏览器、稍后再打开，列仍会保持您上次离开时的样子。此外，在表中添加或移除列，也不会重置其他列的宽度。

**相关 PRs：** [#2327](https://github.com/hyperdxio/hyperdx/pull/2327) fix: persist column widths in search results table
