## 全新的仪表盘和已保存搜索列表页面 {#new-dashboard-and-saved-search-listing-pages}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/dQCkNZElwcg" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

仪表盘和已保存的搜索已从侧边栏移至专门的列表页面。如果您的团队积累了较多仪表盘，原先放在侧边栏的方式很快就会变得难以管理。新页面以卡片视图展示所有内容，按标签分类，并内置名称搜索和标签筛选功能。如果您偏好更紧凑的布局，也可以切换为列表视图。

此外还新增了收藏功能。为仪表盘或已保存的搜索加星标后，它会置顶显示在列表页面中，并重新出现在侧边栏中，方便快速访问。这与之前的使用方式类似，但不会让其他用户的导航栏变得拥挤。列表页面还会在每张卡片上显示告警状态图标以及“创建者 / 更新者”元数据，让您一眼就能看出各项内容归谁所有，以及是否有告警正在触发。

最后，本次还新增了模板库，提供四个预构建仪表板，涵盖 Node.js、Python、Go 和 Java 的 OTel 运行时指标，只需点击几下即可导入。导入时可以编辑标签和目标指标 source，从而直接融入您现有的标签体系。

**相关 PR：** [#1971](https://github.com/hyperdxio/hyperdx/pull/1971) 添加仪表盘列表页面，[#2012](https://github.com/hyperdxio/hyperdx/pull/2012) 添加已保存搜索列表页面，[#2021](https://github.com/hyperdxio/hyperdx/pull/2021) 为仪表盘和已保存的搜索添加收藏功能，[#2033](https://github.com/hyperdxio/hyperdx/pull/2033) 按标签对仪表盘和搜索进行分组，[#2031](https://github.com/hyperdxio/hyperdx/pull/2031) 显示创建/更新元数据，[#2053](https://github.com/hyperdxio/hyperdx/pull/2053) 在仪表盘列表页面添加告警图标，[#2010](https://github.com/hyperdxio/hyperdx/pull/2010) 添加仪表板模板库

## 为筛选条件添加筛选条件 {#filters-for-filters}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Tfe9kJygoEg" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

仪表盘变量筛选条件现在支持设置自身的过滤条件。这一改进的出发点很简单：如果 Node.js 仪表盘上有一个“服务名称”下拉列表，您可能只希望它列出 Node.js 服务，而不是环境中的所有服务。现在，您可以直接在仪表盘变量上配置过滤条件，限定其显示范围。

筛选选择器也已更新，现已支持多选。对于按服务分组的仪表盘，可以在下拉列表中一次选择多个值，进行对比分析也因此便捷得多。

**相关 PRs：** [#1969](https://github.com/hyperdxio/hyperdx/pull/1969) 为仪表盘筛选条件添加条件；支持筛选条件多选

## 预设仪表盘的 RBAC {#rbac-for-predefined-dashboards}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/AZ94-quHEuw" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

基于角色的访问控制现已覆盖 ClickStack 的预设仪表盘。此前，这些内置仪表盘完全不受 RBAC 约束，任何用户无论被分配了何种角色，都能访问它们。这一缺口现已补上。

细粒度的只读权限会按预期生效。如果某个角色仅对特定服务拥有只读访问权限，该角色下的用户就只能看到与这些服务相关的预设仪表盘。这些用户可以查看仪表盘及其筛选条件，但筛选控件会被锁定，无法编辑。演示中展示了一个自定义角色，它拥有限定于某个指定服务的 &quot;services&quot; 只读权限；以该角色登录的用户看到的仪表盘和筛选状态，与其应有的访问权限完全一致。

## 搜索优化 {#optimizations-for-searching}

*演示者：[@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/uVD2FKzoHjM" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickHouse 的“按序读取”优化可以显著加快搜索查询：当 ORDER BY 与表的主键一致时，它会按顺序读取数据，并在达到 LIMIT 后立即停止。然而，基准测试表明，在较大的数据集上，搜索仍然存在过度拉取的问题。问题根源在于需要遍历的 parts 数量：即使该优化已生效，足够大的表仍包含大量 parts，导致 ClickHouse 读取的数据仍多于实际所需。

解决方案是在搜索查询的窗口化查询 array 最前面添加一个 1 分钟的时间窗口。大多数搜索所需的数据本就位于最近一分钟内，因此优先查询该窗口几乎可以即时返回结果。如果该窗口中未找到数据，查询会照常回退到逐步扩大的窗口。此外，ORDER BY 优化此前未能正确应用于 `otel_traces` schema，原因是时间戳列使用的 `toDateTime(Timestamp)` 表达式未能被识别。该问题也已修复。

**相关 PR：** [#2019](https://github.com/hyperdxio/hyperdx/pull/2019) 搜索使用 1 分钟窗口，[#2014](https://github.com/hyperdxio/hyperdx/pull/2014) 修复 otel&#95;traces 的 ORDER BY 优化缺陷

行查看器中新增了“复制为 JSON”按钮，一键即可复制整条日志行。该按钮在完整侧边栏视图中同样可用。您可以将某一行粘贴到 LLM 提示词中，询问这条日志出自代码的哪个位置；也可以直接为事故报告保存完整事件，无需手动选中全部文本。

侧边栏中拉取的筛选键数量现已成为可配置的团队设置，位于“查询设置”下。此前上限固定，在较大的数据集上只能看到一小部分可用的筛选属性。现在，团队可以调高该上限，以显示更多资源属性和日志属性。此次变更还改进了虚拟化处理，即使显示大量筛选分组，筛选面板也能保持快速渲染。

**相关 PRs：** [#2035](https://github.com/hyperdxio/hyperdx/pull/2035) 新增“将行复制为 JSON”按钮，[#2020](https://github.com/hyperdxio/hyperdx/pull/2020) 新增用于设置拉取筛选条件数量的团队设置，[#1979](https://github.com/hyperdxio/hyperdx/pull/1979) 对嵌套筛选分组进行虚拟化

## 仪表盘中的选项卡与分组 {#tabs-and-groups-in-dashboards}

*演示者：[@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/tyumDlJuDTg" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

仪表板面板现在可以按分组进行组织。此前的模型包含两种独立的容器类型 (“sections”和“分组”) ，用户需要事先决定使用哪一种；新的统一分组概念取代了这一模型，使用起来更加简单：分组默认可折叠，可按需显示边框，还可以在其中添加选项卡。每个选项卡包含各自的一组面板，面板可通过拖动手柄在分组之间移动。

演示中展示了一个分组，并切换了其中几项自定义选项：开启或关闭折叠、显示或隐藏边框、启用或禁用选项卡。演示时该 PR 仍在评审中，设计反馈仍在收集。合并之后，相比旧的双容器类型模型，它将为仪表盘作者提供一套更灵活、更清晰的构建组件。

**相关 PRs：** [#1972](https://github.com/hyperdxio/hyperdx/pull/1972) 支持选项卡及可折叠/边框选项的仪表盘分组，[#2015](https://github.com/hyperdxio/hyperdx/pull/2015) 将 section/分组 统一为单一 分组

## ClickStack 命令行客户端 {#clickstack-cli}

*演示者：[@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/9XqJNhstabw" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack 命令行客户端 (`hdx`) 是一款全新的终端 TUI，让您无需离开终端即可搜索、实时跟踪和检查日志与链路追踪。它与浏览器采用相同的 Web 会话机制连接到您的 HyperDX 实例，因此无需另行管理 API key。只需使用实例 URL 和电子邮件执行一次 `hdx auth login`，之后即可一直保持身份验证状态。

TUI 提供的搜索界面与 Web 应用完全一致：相同的查询语法、相同的 source 选择方式，同样可以深入查看单条日志条目。其中一大亮点是链路追踪瀑布视图：点击某条日志条目，即可直接在终端中查看渲染出的完整分布式 trace。该演示还预览了一项关于智能体用法的早期实验：让 AI 智能体读取命令行客户端输出的 schema 内部信息，并允许其通过 ClickHouse 代理运行查询，智能体便能自主排查问题。演示还更进一步，展示了智能体如何借助 Web 会话，通过 Playwright 浏览 HyperDX 用户界面，从渲染出的图表中拉取指标，并与其在日志中的发现进行交叉比对。

**相关 PR：** [#2043](https://github.com/hyperdxio/hyperdx/pull/2043) 新增 @hyperdx/cli 软件包——用于搜索和实时跟踪事件的终端 TUI
