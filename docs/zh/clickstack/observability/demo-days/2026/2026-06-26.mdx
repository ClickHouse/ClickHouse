## 告警异常检测：条形图支持持续推进 {#anomaly-detection-for-alerting-continues-with-bar-charts}

*演示者 [@fleon](https://github.com/fleon)*

<Frame>
  <iframe src="https://www.youtube.com/embed/AeibhN5dGQY" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

该功能目前仍处于非常早期的实验阶段。用于突出显示异常的正态分布区间在折线图上效果很好，但在条形图上却很难呈现。Himanshu 尝试过误差区间，甚至尝试了空心条形图来让区间更加醒目，但效果看起来仍然比较杂乱。将区间以线条形式叠加在实心条形上也存在同样的问题：条形在视觉上占据主导，导致区间难以分辨。

目前，当用户需要查看异常区间时，我们可能会引导他们使用折线图，条形图的设计则留待之后再做考虑。在该功能正式发布之前，Himanshu 希望大家就最佳方案提供反馈。

## 表格的外部点击行为 {#external-onclick-actions-for-tables}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/8CV7ZEbFqhk" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Drew 演示了仪表盘表格的一项小而实用的新功能：可将表格行直接关联到外部工具。

此前，表格行已支持下钻到 Search 页面或其他仪表盘。此次新增了第三个选项“External”，它会根据所选行中的值构建 URL 并将其打开。在演示中，点击产品目录中的某一行，即可将产品名称填入 Google 搜索 URL，以此说明其工作原理。同样的机制也适用于跳转到 Grafana、内部运行手册、工单系统，以及任何支持通过 URL 传递参数的工具。

这项功能虽然简单，却十分重要。ClickStack 不再只是数据的终点，而是融入更广泛的可观测性工作流，让您能够从仪表盘直接跳转到后续调查所需的工具。

## OTel 性能分析 {#otel-profiling}

*演示者：[@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/-yAP8lXA2D8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

性能分析功能正逐步引入 ClickStack，不过显然仍处于雏形阶段。Spencer 演示了一个早期原型，可摄取 OpenTelemetry 性能分析 samples——也就是用于生成火焰图、供 pprof 等工具使用的那类数据。他借助一个以 ClickHouse 为后端的 Grafana 仪表盘，对一个反复排序数据的小程序进行了可视化，并在新的性能分析 samples 持续以流式方式传入的同时，逐层深入查看各个调用栈块。

目前的实现还相当粗糙，查询语句也能看出这一点。每一行都兼具日志和链路追踪的特征，存储着由函数名和地址组成的长数组，用于表示火焰图中的一个 span 或扇区。要还原出 Grafana 所需的格式，需要对这些数组进行连接和聚合；而导出器则需先展开原始的性能分析栈帧，再将其写入 ClickHouse。该 schema 目前仍依赖布隆过滤器，同时新增了全文检索，这也引发了关于兼容性的讨论。由于 ClickHouse Cloud 已支持全文检索，团队讨论了不含全文检索的开源方案还需要继续维护多久。

这项工作目前正在一个开放的 PR 中评审。计划先将核心功能合入开源版本，再集成到 ClickStack 中。

## 仪表盘评估框架 {#eval-framework-for-dashboards}

*演示者：[@brandon-pereira](https://github.com/brandon-pereira)*

<Frame>
  <iframe src="https://www.youtube.com/embed/cg2pYb5rsKU" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

AI 生成的仪表盘质量正在不断提升，但仅凭肉眼评判进展终究有限。Brandon 正在构建一个评估框架，用于衡量仪表盘生成是否真的在进步，同样重要的是，找出它仍有哪些不足。

该评估会通过提示词让模型生成一个刻意覆盖尽可能多功能的仪表盘，包括可折叠分区、选项卡、热力图、饼图、原始 SQL 与基于 source 的卡片混合使用、服务级筛选条件，以及仪表盘之间的下钻链接。

随后，评分环节会验证所有内容是否都按预期渲染并正常运行。在此过程中，它已经发现了一些真实存在的问题，例如 Markdown 磁贴渲染出的高度总是过短。它还会沿着 Drew 新推出的点击行为功能所支持的下钻链接，验证能否正确跳转到第二个 AI 生成的仪表盘。今后新增的仪表盘能力也会陆续纳入评估，从而自动发现回归问题，不再依赖手动测试。Brandon 希望尽快为该框架提交 PR。

## 连接到 Prometheus {#connecting-to-prometheus}

*演示者：[@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/qvM8-6A4two" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Aaron 演示了 ClickStack 与 Prometheus 之间的早期桥接功能。source 的高级设置中新增了“Prometheus compatible”选项，启用后 ClickStack 会将已配置的主机视为 Prometheus API 端点 (演示中为 Thanos) ，而非 ClickHouse 实例。此后，仪表板面板即可直接对该端点执行 PromQL。Aaron 用一个按 Pod (容器组) 分组展示 CPU 使用率的图表演示了这一功能：查询直接发送至 Prometheus，而无需经由 ClickHouse 转换。演示本身规模不大，却引发了围绕用户体验的更广泛讨论。

从长远来看，我们的目标是在 ClickStack 中原生支持 Prometheus。该功能是切实可行的第一步：已依赖 Prometheus 的团队可以在采用 ClickStack 的同时继续使用 Prometheus，而不必从一开始就把所有内容都迁移到 ClickHouse。与此同时，我们也在并行推进 ClickHouse 对 PromQL 的原生支持。

**相关 PRs：** [#2518](https://github.com/hyperdxio/hyperdx/pull/2518) feat: add ability to connect to external prometheus datastore
