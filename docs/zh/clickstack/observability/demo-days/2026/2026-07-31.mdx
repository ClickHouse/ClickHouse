## 指数直方图指标 {#exponential-histogram-metrics}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/w45v3IMcXTY" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

OpenTelemetry 指数直方图指标现已提供初步的查询支持。此前虽然已经可以在 source 上注册此类指标，但无法对其进行查询。现在，计数和分位数均可通过查询构建器进行查询。

指数直方图与显式桶直方图类似，但其桶边界是根据 2 的幂计算得出的，而不是为每个桶单独存储。标度决定使用哪个 2 的幂：标度越高，桶越小；而偏移量则会将边界向更高或更低的倍数移位。每个桶的计数记录了落在该范围内的观测值数量。

与现有的显式直方图实现一致，max、min、sum 和 avg 目前仍不支持。这些字段在 OpenTelemetry 数据模型中是可选的，因此我们不依赖于它们的存在。

如演示所示，生成的 SQL 篇幅较长，也不够美观。其性能尚可，也不会出现内存耗尽的情况，但目前仅提供初步的功能支持。下一步的重点是性能优化，新版 schema 已在开发中，预计可显著提升这些查询的速度。

目前，只有时间序列显示类型能够正确渲染，这与现有的直方图指标类型一致。

## 原始 SQL 图表的校验 {#validation-for-raw-sql-charts}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/zfZsehTqeCQ" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

现在，原始 SQL 图表在缺少预期的宏时会发出警告。这项改进源自一个支持工单：一位用户在构建大量原始 SQL 图表时，屡屡得到令人困惑的结果。

仪表盘查询应包含筛选条件宏和源表宏，时间序列图表还应包含时间范围宏和时间间隔宏。此前，只有在卡片上附加告警之后才会运行这些检查。现在，所有原始 SQL 图表都会运行这些检查，因此一旦删除某个宏，编辑器中就会立即显示警告，而不会等到之后才生成一个令人费解的图表。

校验还会考虑每个宏的依赖项。源表宏和筛选条件宏需要先选择一个 source，尽管原始 SQL 图表本身并不要求选择 source。因此，如果在未选择 source 的情况下使用这两个宏中的任意一个，将产生错误而非警告。

改动虽小，但应能让用户更轻松地发现原始 SQL 中的问题，而无需求助技术支持。

## 通过名称而非 ID 链接到 source {#link-to-sources-by-name-not-id}

*演示者 [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/r2uNmcJXGSM" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

LogHouse 团队希望有一种更稳定的方式来链接到 source。该团队负责运行 ClickHouse Cloud 的日志环境，并通过 infrastructure-as-code 以编程方式预配 source。source 被重新创建后，其 ID 就会改变，而且开发、暂存和生产环境中的 ID 也各不相同，因此任何基于 ID 的链接都很容易失效。由于他们需要从告警系统和 Grafana 链接到 ClickStack，为每个环境分别维护一套 source ID 并不现实。

`source` URL 参数现在既接受 ID，也接受 source 名称。名称在预配 source 时即已确定，因此同一个链接可在所有环境中通用。该功能最初只在搜索页面提供支持，随后的一个 PR 将其扩展到所有带有 source 参数的页面，包括 Chart Explorer、服务地图、会话、服务仪表盘和 Kubernetes 仪表板。

后续讨论主要围绕可发现性展开。这实际上是一个 URL API，用户很难偶然发现它。一种方案是默认使用名称而非 ID，但名称可能重复，这种做法并不安全。其他建议包括通过共享按钮提供链接、让智能体通过 MCP 生成链接，以及为 URL API 编写完善的文档。相对时间范围也同样需要此类文档。

基于名称的引用还可以扩展到仪表盘。这样，infrastructure-as-code 工作流便能预配 source、导入仪表盘，并自动完成所有关联。通过 UI 导入仪表盘时已能按名称匹配 source，因此目前的不足主要集中在编程式工作流上。

**相关 PR：** [#2746](https://github.com/hyperdxio/hyperdx/pull/2746) feat: Accept source names in addition to IDs in URL Params，[#2758](https://github.com/hyperdxio/hyperdx/pull/2758) feat: Support source name deeplinks on additional pages

## 图表显示设置重新设计 {#chart-display-settings-redesign}

*演示者：[@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tO5yFKR-MLQ" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

图表显示设置应该放在哪里，目前仍在探索中。最初的改动将这些设置以内联方式移到了卡片编辑器右侧，不再通过单独的抽屉面板打开。此前，卡片编辑器是一个弹窗，Display Settings 则在其上方的抽屉面板中打开。按一次 Escape 键会把两者同时关闭，而且在弹窗上再叠一层抽屉面板，体验始终不太对。

当数据系列设置也需要叠加到上层时，这个 PR 变得更加复杂，于是我们暂停下来，开始从整体上重新审视这个页面。这项工作目前仍处于线框图阶段。当前设计将设置放在一个停靠面板中，并自动应用更改，让您无需点击“应用”按钮即可实时查看结果。

我们计划先完成重新设计，再将其合并回现有的 PR。目前的实现仅作为原型看待，尤其是因为新设计还会改动仪表盘页面的部分内容。

## 全新探索页面 {#new-explore-page}

*演示者：[@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/E1vEjJBw1gs" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

这是对统一&quot;探索&quot;页面的早期尝试。该页面未来可能取代&quot;搜索&quot;、&quot;保存的搜索&quot;和 Chart Explorer，成为统一的入口点。

此次滚动发布借鉴了 trace 查看器改版的经验。新页面不会一次性改变所有用户的体验，而是先通过功能开关面向一小部分用户推出。我们会利用这段时间发现并修复问题，再逐步扩大推广范围。如果这一设想行不通，它将仅作为一次实验，不会正式发布，而这也完全是可以接受的结果。

使用该页面时，首先要选择信号类型。选择链路追踪、日志或指标后，页面其余部分会随之调整。例如，选择日志后，您将看到列表视图、事件模式、时间序列，以及目前 Chart Explorer 中提供的其他可视化方式。

整个调查过程应无需切换页面即可完成。您可以从列表入手，切换到数值或已分组的表，将结果添加到仪表盘；如需更精细的控制，还可以编写自定义查询。

此外还有若干较小的改进，大多源自用户反馈。查询编辑器的使用方式将更接近 SQL 编辑器，消除两者目前在自动补全行为上的差异。错误和警告会在编辑时即时显示，无需等到运行查询时才出现。

列将配备专门的选择器。至少有一位用户没有意识到，修改 `SELECT` 子句就能控制表中显示哪些列。有了选择器，点击某个字段即可自动更新 SQL，并可按该字段排序。高级用户仍可直接使用 `SELECT` 子句。

已保存的视图也将整合到该页面中。您可以先在不保存的情况下进行探索，再直接在原处保存当前视图。生成的 SQL 将以内联方式显示。

目前仍有不少内容尚未实现，包括 Chart Explorer 现有的部分可视化方式。随着这些功能陆续加入，设计也会不断调整。

## 仪表盘筛选条件联动 {#dashboard-filter-linking}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/IQ4WtnNYS5s" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

仪表盘筛选条件联动功能已合并。几个月前我们曾以草稿形式首次演示该功能，之后为评估其性能影响而暂停了开发。联动会改变仪表盘查询的结构，且未必总能充分利用物化视图，因此该功能将以可选开关的形式发布，默认不启用。

启用联动后，在某个筛选条件中选定一个值，其他筛选条件的可选值范围会随之缩小。例如，选择某个服务后，只保留该服务中出现过的严重级别值；选择某个追踪 ID 后，只保留相关的父级追踪 ID。这样可以避免用户选出不返回任何数据的组合。

后续的一个 PR 让联动能够感知 source。筛选条件按 source 分组，可以相互缩小范围的相邻筛选条件之间会显示链条图标。在包含两个日志筛选条件和两个 trace 筛选条件的仪表盘上，用户应能一眼看出哪些筛选条件会相互影响。

该功能最初的用例是 Kubernetes 仪表板：选择某个 pod (容器组) 后，应只保留包含该 pod (容器组) 的部署和节点。缩小后的值采用延迟拉取的方式，仅在下拉列表打开时才获取，以控制额外查找带来的开销。

讨论中还留下了两个待解决的问题。其一，该设置目前按用户保存在浏览器存储中。会上大家预计，用户最终会希望在仪表盘级别保存该设置。如果是这样，用户级别的偏好设置或许更适合作为临时方案，以免日后与仪表盘级别的行为相冲突。

其二，是依赖型筛选条件在其值加载期间应如何表现。目前选择某个值后，依赖的下拉列表内会显示加载状态，但不会被锁定；不过，存在第二个依赖筛选条件时的行为仍有待验证。大家倾向于在缩小范围的过程中保持筛选条件可用，同时提示列表尚未更新完毕。已经明确知道所需值的用户，不应被迫等待元数据加载。

## 记住上次使用的侧边面板选项卡 {#remember-the-last-side-panel-tab}

*演示者：[@MikeShi42](https://github.com/MikeShi42)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/FlDWN7sGHMo" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

这是本周最小的 PR，但它很好地说明了：有些小烦恼确实值得修复。

以往，行侧边面板总是默认打开 Overview 选项卡，而该选项卡是围绕 OpenTelemetry 日志字段设计的。如果日志不符合 OTel 形态，该选项卡几乎显示不出什么有用信息，结果每次打开一行都得手动切换到 Column Values。

现在，面板会记住您上次使用的选项卡，并在下次打开时直接显示该选项卡，无需任何配置。非 OTel 用户切换到 Column Values 后，之后会一直停留在该选项卡；而使用 Overview 的用户则保持原有行为不变。
