## PromQL 和 Lucene 中的仪表盘变量 {#dashboard-variables-in-promql-and-lucene}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/q5pP20p4nY4" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

仪表盘变量现已可在 PromQL 图表中使用，支持变量引用的自动补全，并会针对缺失的变量或不支持的用法 (例如宏或需要加引号的引用) 显示警告。新增的生成 PromQL 预览与现有的生成 SQL 面板并排显示，展示代入当前所选值后的查询。

Lucene 变量现已支持精确匹配。此前，`ServiceName:$service` 会展开为 `ServiceName:("add" OR "cart")`。未加引号的 Lucene 字段匹配属于子串匹配，因此最终会变成 `ServiceName ILIKE '%add%' OR ServiceName ILIKE '%cart%'`。结果可能是选了两个服务，却返回了四个。

现在，为变量加上引号 (`ServiceName:"$service"`) 会展开为 `(ServiceName:"add" OR ServiceName:"cart")`，对每个选中的值进行精确匹配。这与不含变量时用引号括起的字段匹配的现有行为一致。自动补全也会建议加引号的形式。

从图表工具提示或表格行下钻到搜索页面时，现在会在跳转前先展开变量和宏。搜索页面无法识别变量，因此此前直接传入原始的 `$service` 会导致结果错误或查询报错。未选择任何值的宏会展开为 `(1=1)`。这在搜索页面的 `WHERE` 输入框中看起来不太美观，但能确保查询有效。

筛选条件的选中值现在以变量名称为键，而不再以表达式为键。两个使用相同表达式的筛选条件 (例如来自不同数据源的 `ServiceName`) 不再共享选中值。

采纳 Brandon 的建议，现在编辑筛选条件时按下 Escape 键，会在丢弃更改前先进行确认。此前，本想关闭工具提示，却可能导致全部编辑内容丢失。

仪表盘变量已于本周发布到生产环境。功能开关已移除，[公开文档](https://clickhouse.com/docs/clickstack/features/dashboards/overview#dashboard-variables)介绍了各种引用形式和宏。

## 双向 跨度 链接 {#span-links-in-both-directions}

*演示者：[@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tdK9JU6unoE" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

跨度 链接早已支持查看，但只能从消费者一侧查看。每个链接都显示为一个 “Open trace” 操作，无法从生产者跨度出发，反查链接到它的跨度。有用户在 GitHub 议题中提出了这一需求。

跨度 Links 部分现在会显示每个目标跨度的名称、服务、耗时和时间戳。这样无需逐一打开，就能更轻松地从多个链接中做出选择。当找不到目标跨度时，仍会回退到 “Open trace”。

新增的 “Linked from” 部分会列出所有链接到当前跨度的跨度。现在，您可以顺着消费者的链接跳转到其生产者，并在该部分看到这个消费者。

沿链接跳转到面包屑路径中的上一个跨度时，会直接返回该条目，因此在两个相互链接的跨度之间来回切换时，不会不断添加重复条目。如果两者之间还有其他条目，导航会照常添加新条目。

反向查找会先找出 跨度 链接中包含所选 跨度 ID 的行，再检查追踪 ID 是否匹配。追踪 ID 查找可以利用该列上的布隆过滤器索引，但反向查找需要扫描，因此在比演示环境更大的 traces 表上可能会更慢。如果这成为瓶颈，可以按照代码注释中的建议，为链接 跨度 ID 添加索引。

**相关 PRs：** [#3011](https://github.com/hyperdxio/hyperdx/pull/3011) 新增反向 跨度 链接，显示 跨度 链接详情

## 开箱即用的 LLM 可观测性 {#llm-observability-out-of-the-box}

*演示者：[@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/m49DZ5cuI64" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

许多团队已经将 LLM 和编码 agent 的遥测数据发送到 ClickStack，但此前并没有针对这类数据的专门支持：既没有聊天渲染，也没有 token 或成本跟踪，更没有模型数据分析。

现在，除了现有的 ClickHouse、Kubernetes 和服务预设之外，还新增了 LLM 仪表盘。它涵盖 token 用量、成本、模型调用、工具调用、缓存命中和响应时间；如果存在用户属性，还可以按用户进行细分。

它在查询时读取您现有的链路追踪和日志，无需固定的 schema、专用表或摄取时处理。支持遵循通用约定、OpenLLMetry 或 OpenInference 的遥测数据，包括来自 OpenAI 和 Anthropic SDK、Vercel AI SDK、LangChain、Claude Code 以及 opencode 的数据。对于您已经采集的遥测数据，同样适用。

延迟视图会将 AI 相关的 跨度 置顶显示，让您无需逐一翻查 trace 的其余部分，即可快速定位较慢的模型调用。

会话视图按对话对 跨度 进行分组。打开某个会话即可查看其中的 跨度，选中其中一个即可查看详情；如果记录了提示词，也会一并显示。这在调试 agent 运行时非常有用，您还可以使用相同的会话过滤器搜索日志。

其功能范围有意比 Langfuse 等专用 LLM 可观测性工具更精简，后者还支持评估等更多功能。此功能直接利用 ClickStack 中已有的遥测数据，满足常见的监控需求，包括错误率、成本、token 和延迟。

**相关 PR：** [#2990](https://github.com/hyperdxio/hyperdx/pull/2990) LLM 可观测性仪表盘、跨度 聊天视图和会话

## 在图表编辑器中浏览指标 {#browsing-metrics-in-the-chart-editor}

*演示者：[@MikeShi42](https://github.com/MikeShi42)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/TkFa6Zzq23o" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

以往选择指标时，需要在扁平列表中搜索，每种类型的名称多达 3,000 个。如果您大致知道要找什么，自动补全会有所帮助，但用户已多次反馈希望能够浏览指标。

现在，指标选择框旁新增了“Browse metrics”控件，点击即可打开指标浏览器：左侧为指标目录，右侧为所选指标的详细信息。指标名称会按点号和下划线拆分，形成树状结构。只有一个子节点的分段会合并折叠，以免多余的点击。`Metric`、`Type` 和 `Unit` 列在各级均保持对齐。您可以搜索整个目录，也可以切换为扁平列表。

此前，单位、描述和标签只有在选定指标后，才能在数据系列行下方的折叠面板中查看。借助详情窗格，您可以在选择之前查看这些信息，从而了解您的部署上报了哪些指标，以及可以按哪些标签分组。点击“Use metric”，即可将所选指标应用到当前正在编辑的数据系列。

在该功能稳定之前，入口暂时放在不太显眼的位置。

**相关 PR：** [#3000](https://github.com/hyperdxio/hyperdx/pull/3000) 为图表编辑器添加指标浏览器，[#3025](https://github.com/hyperdxio/hyperdx/pull/3025) 从主索引流式获取指标名称 (未合并) ，[#3054](https://github.com/hyperdxio/hyperdx/pull/3054) 改进指标下拉列表的用户体验

## 在 Grafana 中显示原始 SQL 查询的日志量 {#log-volume-for-raw-sql-queries-in-grafana}

*演示者：[@SpencerTorres](https://github.com/SpencerTorres)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/uehh44q56yE" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

这只是一个很小的视觉改动，实际工作量却超出了预期。

在 Grafana 中，通过查询构建器构建的日志查询会在结果上方显示日志量直方图，因为插件知道该使用哪些列。而同样的查询若在 SQL 编辑器中编写，则不会显示直方图，因为插件无法判断你选择了哪些列。在“探索”中，显示的则是 Grafana 基于行的直方图，它受查询中 `LIMIT` 的限制，也不会随所选时间范围变化。

现在，插件会移除尾随的 `ORDER BY` 和 `LIMIT`，将你的 SQL 包装为派生表，并基于整个时间范围进行聚合。这里移除 `LIMIT` 至关重要：若保留它，计数就只会覆盖原始查询返回的行。

直方图会反映 SQL 中的筛选条件，并在你更改时间范围时随之更新。这既适用于你自行编写的 SQL，也适用于在查询构建器中通过 &quot;Edit as SQL&quot; 打开的查询。

在某些边缘情况下，查询重写可能仍会失效。

**相关 PRs：** [grafana/clickhouse-datasource#2141](https://github.com/grafana/clickhouse-datasource/pull/2141) 为 SQL 编辑器查询显示日志量 (未合并)

## 告警页面中的通知渠道 {#notification-channels-on-the-alerts-pages}

*演示者 [@jordan-simonovski](https://github.com/jordan-simonovski)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/Gr-QkVVWam8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

一个告警最多可以通知十个 Webhook，但告警列表和详情页头部只显示第一个，且统一标记为“Webhook”，而不是显示其名称。原因是这两处读取的仍然是旧版的单渠道字段。

多目标分派本身工作正常，但这种显示方式让人误以为其他渠道没有保存成功。

现在，列表和详情页头部会按名称显示所有已配置的渠道。添加和删除渠道 (包括 Webhook 和 incident.io 集成) 也更加方便。通知时间按目标分别记录，便于定位响应缓慢的集成。

现在会直接向已配置的渠道发送通知。此前，这些渠道会被转换为 Webhook 提及并追加到消息体中，这可能导致通知丢失：如果消息体中已有足够多的临时提及，达到了单个事件的上限，告警中已配置的渠道就会被跳过。

新增控件后，页面变得拥挤。因此，行操作 (包括导出和 Terraform) 现已统一归入一个菜单。

**相关 PR：** [#3001](https://github.com/hyperdxio/hyperdx/pull/3001) 在告警页面显示所有通知目标，[#2991](https://github.com/hyperdxio/hyperdx/pull/2991) 在摘要行显示所有通知渠道，[#2984](https://github.com/hyperdxio/hyperdx/pull/2984) 直接通知已配置的渠道，而非通过提及字符串，[#2961](https://github.com/hyperdxio/hyperdx/pull/2961) 避免失败的提及占用通知槽位，[#3003](https://github.com/hyperdxio/hyperdx/pull/3003) 按目标分别记录告警通知时间，[#3002](https://github.com/hyperdxio/hyperdx/pull/3002) 为告警页面的每一行提供相同的尾随控件，[#3016](https://github.com/hyperdxio/hyperdx/pull/3016) 将告警详情页头部整合到共享的行菜单中

## 渲染数万条告警 {#rendering-1000s-alerts}

告警评估已在 16,000 条并发告警的规模下完成测试，运行稳定。但告警数量达到这一规模时，打开告警页面会导致页面崩溃。

## 将 API 密钥隐藏于“显示”控件之后 {#hiding-api-keys-behind-a-reveal}

*演示者 [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/MNXABmTVEkE" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

此前，应用中多处以明文显示凭证：团队设置页面会显示完整的摄取 API key，MCP 安装代码片段的命令中也包含个人访问密钥。在屏幕共享或截图时，二者都很容易泄露。

现在，密钥默认会被遮蔽，需要时可通过控件显示。摄取密钥、个人访问密钥以及 MCP 安装代码片段 (包括社区贡献的代码片段) 均由同一个共享组件统一处理。

复制时得到的仍是真实值，因此无需显示密钥即可复制。ClickStack Cloud 的 onboarding 流程也即将迎来同样的改动。

**相关 PRs：** [#2988](https://github.com/hyperdxio/hyperdx/pull/2988) 使用共享的 RevealSnippet 遮蔽 API key 和 MCP 安装代码片段中的机密信息

## 产品内的发行说明 {#release-notes-in-the-product}

*演示者：[@jordan-simonovski](https://github.com/jordan-simonovski)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/4vrzXy8JwZY" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

帮助菜单中的“What&#39;s new”面板此前基于各 PR 的 changeset 生成，从中挑选带有 `feat:` 前缀的条目。结果 v2.36.0 中仪表盘变量被列了三次，而该版本的主要变更——公式和告警相关改动——却被遗漏了。

现在，该面板改为读取根目录下的 `CHANGELOG.md`，该文件会在发布 PR 中一并编写和评审。发行说明生成器还会为面板中的每个版本提供标题，标题下方依次列出不兼容变更、新功能、缺陷修复和改进，并附有指向更新日志的链接。

当有未读的发行说明时，帮助按钮会显示闪烁效果，该效果通过 SVG 动画实现，无需 JavaScript。

未读状态的跟踪逻辑也一并做了修复。此前它依据应用的构建版本号判断，因此对于版本号中包含 git 短 SHA 或 CI 构建编号的部署，即使没有新版本发布，每次部署也都会触发闪烁。现在改为依据更新日志中的最新发行版本号。

发行说明的格式也在调整中，后续将有更多相关内容出现在该面板中。
