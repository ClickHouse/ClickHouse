## 面向告警和 MCP 的数据源级筛选条件 {#source-level-filters-for-alerts-and-mcp}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/z0Lbggcy6dU" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Drew 演示了 ClickStack 对数据源筛选条件支持的全面扩展。现在，可以在需要数据源筛选条件的仪表板面板和原始 SQL 面板上配置告警；若缺少筛选条件，或查询中没有可供注入的筛选条件宏，界面会给出清晰的内联提示。已保存的搜索告警同样支持这一行为。

服务地图的整个使用流程现在都会遵循数据源筛选条件，并将所选条件传递到关联的搜索页面和 trace 侧边面板。

MCP 现在也能识别数据源筛选条件。智能体可以发现筛选条件要求、获取可用值，并将筛选条件传入查询工具。筛选条件值之间会进行交叉剪枝，一个筛选条件的选择可以缩小其他筛选条件的兼容值范围。若未提供必填筛选条件，MCP 可以自动选择，并报告实际应用的值。初步评估结果显示，对未使用数据源筛选条件的数据源没有可察觉的影响。

**相关 PR：** [#2459](https://github.com/hyperdxio/hyperdx/pull/2459) feat: show icon on tiles with excluded source-scoped filters，[#2331](https://github.com/hyperdxio/hyperdx/pull/2331) feat: Add source scoping to dashboard filters

创建 source 时，ClickStack 现在会从底层表中推荐候选字段，帮助填充配置表单。推荐项以可点击的标签形式呈现；校验功能则会区分两类字段：不存在的字段，以及有效但需先设置数据源过滤器才能解析的字段。

此外，如果配置了 Body 表达式却未设置隐式列，系统会显示新增的警告进行提示。该功能已基本完成，仅剩少量 UI 细节打磨和校验方面的改进。

这项工作旨在解决对分组后的时间序列进行异常检测时遇到的一个可用性难题：如果同时为所有数据系列显示异常区间，图表很快就会杂乱难读。Himanshu 的方案是在鼠标悬停于图例时显示对应的异常区间；而当仅选中单个数据系列时，仍会直接在图表上渲染异常区间。

## Datadog receiver {#datadog-receiver}

*演示者：[@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/P0VVuN_yL6Q" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Spencer 演示了 Datadog receiver 的多项改进。

此前，Datadog 日志有效载荷在摄取后，大多以非结构化 JSON 的形式存放在消息体中。现在，该接收器会提取追踪 ID、跨度 ID、时间戳以及 HTTP 请求元数据等关键字段，并将其提升为标准的 OpenTelemetry 资源属性和日志属性。

此外，Datadog 的 64 位数值型追踪 ID 也会扩展为 128 位的 OpenTelemetry 格式，从而在 ClickStack 中实现正确的 trace 关联。该接收器预计将纳入 ClickStack 采集器发行版，后续还计划围绕端到端 trace 关联开展进一步测试。

事件模式分析现在可作用于任意字符串列，而不再仅限于 `Body`。新增的列选择器默认选中 `Body`，以保持现有行为不变，同时允许用户选择任何可表示为字符串的列。

## 跨度链接 (开发中) {#span-links} 

*演示者：[@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>

Alex 演示了 ClickStack trace 查看器中跨度链接支持的早期成果。跨度链接是 OpenTelemetry 中的一个概念，允许 span 引用其他 trace 中的相关 span，也是用户呼声很高的追踪功能。

目前的实现会在 trace 面板中直接展示关联的 span 及其相关属性。设计和呈现方式仍在持续打磨，该功能尚处于早期开发阶段。
