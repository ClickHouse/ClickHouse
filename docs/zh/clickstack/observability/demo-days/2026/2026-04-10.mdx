## 可固定的数据源过滤器 {#pinnable-datasource-filters}

*演示者 [@brandon-pereira](https://github.com/brandon-pereira)*

<Frame>
  <iframe src="https://www.youtube.com/embed/j-b1ztSl8IQ" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

团队现在可以固定数据源过滤器，并将其共享给整个团队。点击任意过滤器上的图钉图标，即可选择仅为自己固定，或共享给所有人。共享过滤器会显示在过滤器列表顶部的专属分组中，每位团队成员都能轻松找到并应用，无需知道确切的过滤器名称。

这是社区呼声最高的功能之一。有了它，团队无需再通过带外方式沟通过滤器配置。共享过滤器一经固定即对所有用户可见；除了过滤器键，还可以共享具体的过滤器值，让完整的上下文随过滤器一同传递。

**相关 PRs：** [#2047](https://github.com/hyperdxio/hyperdx/pull/2047) [HDX-2300] 引入共享过滤器，提升过滤器在团队范围内的可见性与可发现性

## 从 ClickStack Cloud 唤醒服务 {#waking-service-from-clickstack-cloud}

*演示者 [@brandon-pereira](https://github.com/brandon-pereira)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Od7X0NOCqY0" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack Cloud 用户现在可以直接在应用内唤醒处于休眠状态的服务。此前，如果服务已停止运行，您会看到“重试”提示，但应用并不会真正为您唤醒服务。您必须先切换到 ClickStack Cloud 手动唤醒服务，再返回应用并自行点击重试。

现在，应用会全程处理这一过程。当服务处于休眠状态时，提示会显示“唤醒服务”，并自动完成整个流程，您无需离开当前页面。这项改动虽小，却能切实提升使用体验，免去了工作流中繁琐的多步操作。如果您在一段时间未使用后重新打开 ClickStack，只想直接查看数据，这一改进尤为实用。

## 统一启用 AI 功能 {#consistent-enabling-of-ai-features}

*演示者：[@brandon-pereira](https://github.com/brandon-pereira)*

<Frame>
  <iframe src="https://www.youtube.com/embed/zS5OekPCzC0" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

现在，ClickStack 中的 AI 功能只能通过 ClickHouse Cloud 控制平面开启或关闭，ClickHouse Cloud 控制平面因此成为唯一的权威数据源。此前存在两个互不关联的复选框：一个位于 ClickStack 控制平面，另一个位于应用内部。启用其中一个并不能保证另一个随之同步，导致用户无法确定 AI 是否真正生效。

现在，ClickStack 内的复选框仅提供指向 ClickHouse Cloud 的链接，本身处于禁用状态。只要在 ClickHouse Cloud 中打开开关，该功能便会自动在 ClickStack 中可用。这让 AI 的启用方式一致且可预期，用户也无需再猜测究竟是哪个设置在实际控制其行为。

## 原始 SQL 告警 {#raw-sql-alerting}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/bYYcYHkyy2E" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

原始 SQL 折线图现已支持告警，在现有原始 SQL 图表功能的基础上，进一步支持基于阈值的通知。如果您的折线图基于自定义 SQL 查询，即可为其附加告警，配置方式与其他图表告警完全相同。由于阈值比较需要同时用到时间间隔和日期范围参数，该功能目前仅适用于折线图和条形图。

这为许多强大的用例打开了大门。演示中的查询会统计当前时间间隔内的错误数，并与之前 30 个时间间隔进行比较，当该值超出历史常态两个标准差以上时予以标记。如今，此类统计异常检测只需编写合适的 SQL 并设置阈值即可实现。告警配置位于图表编辑器的可折叠分区中，在真正需要之前不会占用界面空间，保持 UI 简洁。

## HyperDX TUI 改进 {#hyperdx-tui-improvements}

*演示者：[@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/cIigBpcrYlw" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

HyperDX 终端 UI 越来越容易上手。现在可以通过 `npm install -g @hyperdx/cli` 进行全局安装，然后运行 `hdx` 启动。使用 `--tui` 命令行选项可直接打开交互式终端界面。该二进制文件同样以 `hdx` 的名称通过 `npm` 提供，因此安装好软件包后无需再单独安装。

除安装方面的改进外，本周还上线了两项值得关注的功能。终端中的错误消息现在能够正确高亮并以结构化方式展示，格式化模式与 Web 前端保持一致，无论在浏览器还是 TUI 中，都能获得同样详尽的信息。此外还新增了 SQL 预览，可查看实际执行的底层查询。不仅如此，在事件查看器中按 `Shift+A` 即可打开新的告警页面，无需离开终端就能概览所有已配置的告警及其近期触发历史记录。
