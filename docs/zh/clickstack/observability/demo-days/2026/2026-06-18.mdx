## 数据源过滤器，现已全面支持 {#source-filters-now-everywhere}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Zl5ymdzoM6U" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

数据源过滤器现已在整个 Services 仪表盘中可用。选择配置了服务名称过滤器的 trace 或日志 source 后，仪表盘会等您选定一个值后再运行查询。该过滤器随后会统一应用于每个图表、查询和侧边面板。链路追踪瀑布图的行为与此一致：从搜索页面打开某个跨度时，它会继承搜索页面上的所有数据源过滤器，同时仍允许您添加附加过滤器。Sessions 页面也已更新，数据源过滤器会贯穿侧边栏、trace 面板和嵌套视图。

数据源过滤器的自动补全功能也得到了扩展。此前该功能仅在搜索页面可用，现在凡是支持数据源过滤器的地方 (包括仪表盘) 均可使用。在底层，自动补全现在可以跨多个数据源解析键和值，即使每个 source 各自配置了不同的过滤器也同样适用。原始 SQL 编辑器以及查询构建器中的所有数据源过滤器输入框均同步获得了这些改进。

**相关 PRs：** [#2331](https://github.com/hyperdxio/hyperdx/pull/2331) 为仪表盘筛选条件添加数据源作用域，[#2459](https://github.com/hyperdxio/hyperdx/pull/2459) 在排除了数据源作用域过滤器的内容块上显示图标

## 改进基于自定义 schema 的 AI 生成仪表盘 {#better-ai-generated-dashboards-for-custom-schemas}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/LUi5047F3fs" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

一位用户在基于自定义 schema 使用 AI 构建仪表盘时，遇到了严重的性能问题。根本原因在于：AI 生成的原始 SQL 仪表板面板将时间范围硬编码在查询中，而没有使用仪表盘时间过滤器宏，因此调整仪表盘的时间范围不会产生任何效果。此外，其中一个面板对整数类型时间戳列的过滤方式绕过了主键，导致了全表扫描。

为解决这一问题，原始 SQL 仪表板面板的 MCP schema 现已明确要求智能体使用仪表盘时间过滤器宏。当生成的 SQL 面板缺少这些宏时，ClickStack 用户界面也会发出警告，便于在保存仪表盘之前发现问题。部署这些变更后，重新运行该客户最初的提示词，生成的 SQL 已正确使用相应的宏，仪表盘速度也因此大幅提升。

**相关 PRs：** [#2473](https://github.com/hyperdxio/hyperdx/pull/2473) 引导智能体在原始 SQL 面板中使用宏

## 简化 OTel 指标的哈希计算，以及一个关于主键的设想 {#simpler-hashing-for-otel-metrics-and-a-primary-key-idea}

*演示者：[@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/MjAUdJJbC8M" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

一项社区贡献修复了带有 JSON 属性列的指标的属性哈希问题，但也由此引入了两条不同的代码路径：JSON schema 使用 `cityHash64` 的可变参数形式，而基于 Map 的模式则会先拼接三个 Map 再计算哈希。事实证明，这些额外步骤并无必要。现在两种 schema 类型统一使用同一个 `cityHash64` 实现，既简化了代码，也避免了哈希计算过程中不必要的 Map 内存分配。

这项工作还揭示了 OpenTelemetry 指标 schema 的一个潜在优化点。目前，主键中存储的是完整的属性 Map，而 ClickHouse 会将该 Map 作为索引的一部分常驻内存，从而增加了内存使用量。一种思路是在写入时物化一个属性哈希，并在主键中改用该哈希。目前尚未做出任何改动，但随着 OpenTelemetry schema 的更新重新提上日程，这项优化值得再次探讨。

**相关 PRs：** [#2475](https://github.com/hyperdxio/hyperdx/pull/2475) Unify AttributesHash to variadic cityHash64

## 过滤器标签与数据源体验优化 {#filter-pill-and-data-source-polish}

*演示者：[@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Zi6HPj5_JQg" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

本周上线了两项小而实用的体验改进。有客户反馈，此前的样式让移除按钮难以看清，为此我们优化了排除型过滤器标签，使其更易于辨认。这些标签现在采用更柔和的红色样式，在浅色和深色模式下的对比度均有所提升。

管理大量数据源也变得更加轻松。现在可以为数据源指定一个可选的分组，从而在数据源选择器中按分组归类显示。未设置分组的数据源仍显示在“其他”下，现有配置不受影响。搜索功能也已更新，支持匹配分组名称，即使您只记得数据源所属的分组，也能快速找到相关数据源。该功能目前仅在内部使用，团队正在观察用户通常如何组织数据源，之后再逐步扩大推广范围。

**相关 PRs：** [#2478](https://github.com/hyperdxio/hyperdx/pull/2478) 提升排除型过滤器标签在浅色主题下的可读性，[#2432](https://github.com/hyperdxio/hyperdx/pull/2432) 为数据源添加可选的分组字段，[#2476](https://github.com/hyperdxio/hyperdx/pull/2476) 数据源选择器按分组归类并支持标签式搜索，[#2477](https://github.com/hyperdxio/hyperdx/pull/2477) 在数据源表单中提示已有的分组名称

## 针对 high-cardinality 图表的单图表数据系列数量上限 {#per-chart-series-limits-for-high-cardinality-charts}

*演示者 [@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/xKpHvhbo-PI" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

图表现在可以限制返回的数据系列数量，从而在按 high-cardinality 字段 (例如 HTTP 路由或跨度 ID) 分组时避免出现性能问题。此前，这类查询可能产生数十万个数据系列，导致仪表盘变慢甚至无响应。现在，您可以将图表限制为仅显示前 N 个数据系列，既能缩短渲染时间，又能减少数据传输量。

对于分块查询，要高效地选出排名靠前的数据系列则更为复杂。当前实现会先根据最新的数据块确定前 N 项，再将这组数据系列应用于整个查询，且这一过程在 ClickHouse 中完成，而非在浏览器中。该方案仍在评估中，后续可能会随着更多查询优化的引入而调整。

**相关 PRs：** [#2449](https://github.com/hyperdxio/hyperdx/pull/2449) 将数据系列数量上限改为可选启用，并使其在各数据块之间保持一致；[#2429](https://github.com/hyperdxio/hyperdx/pull/2429) 将 group-by 时间序列限制为前 N 个数据系列，以防止 OOM
