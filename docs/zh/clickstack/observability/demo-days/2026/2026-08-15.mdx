## 仪表盘变量 {#dashboard-variables}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/gY2Kej-EYx4" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

仪表盘变量是本周的主要更新。它基于仪表盘现有的筛选条件模型：任何已有或新建的筛选条件，都可以作为变量使用。

变量默认使用筛选条件的显示名称。如果该名称包含特殊字符，或两个筛选条件的显示名称相同，可以为其指定自定义变量名。即使之后重命名筛选条件，自定义名称也保持不变。配置页面会显示需要引用的名称；启用变量后，该名称也会出现在筛选条件的提示框中。

原始 SQL 图表支持多种使用变量的方式。`$__filter($var)` 会展开单个变量的当前选中值，相当于现有 `$__filters` 宏 (展开所有筛选条件) 的单变量版本。

更值得关注的新增功能是 `$__conditionalAll(condition, $var)`。它的第一个参数是条件，第二个参数是变量。当变量有选中值时，该条件会被加入查询；没有选中值时，整个表达式会变为 `1 = 1`，不影响过滤。

借此可以实现跨数据源映射。仪表盘可以将 trace 状态码映射为 `error` 或 `info`，从而让基于日志表定义的严重级别筛选条件也能过滤 traces 表。在仪表盘级别选择 `error`，trace 查询就会筛选出错误状态。

自动补全会提示所有可用变量及其支持的格式。采纳 Brandon 的建议后，自动补全现在还会根据当前选中值内联显示实际展开结果。宏提示同样会显示展开结果，此外还新增了一个文档章节，说明每个宏的作用。校验功能会检测对不存在变量的引用，以及参数错误的宏调用。

构建器图表的大多数可编辑字段也采用相同的变量替换机制，SQL 和 Lucene 输入均适用。变量可用于 `WHERE`、`GROUP BY`、`HAVING` 和 `ORDER BY`，同样支持自动补全和校验。Lucene 字段支持变量，但不支持宏。SQL 构建器字段仅提供与变量相关的宏，而非原始 SQL 中可用的全部宏。

告警有一条硬性规则：所有变量都按空值求值。如果告警查询引用了变量，编辑器会在保存前发出警告。预览和生成的 SQL (包括告警详情页中) 都会显示空值展开结果，告警任务运行时也会使用这些空值。

变量配置仍由 `NEXT_PUBLIC_ENABLE_DASHBOARD_VARIABLES` 控制。未配置任何变量时，仪表盘行为保持不变。

## 带评估历史记录的告警详情页 {#alert-detail-page-with-evaluation-history}

*演示者：[@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/Y0entaRF-R8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

此前，告警只提供一条历史状态条，几乎没有其他信息。如果想弄清告警实际是如何运行的，能查看的内容十分有限。

新的详情页会列出每一次评估。对于已分组的告警，页面会细分展示是哪个分组触发了告警，以及超过阈值的具体值。每个条目还包含 ClickHouse 查询耗时，并可同时查看该告警的配置。

这里需要特别说明一下“已回填桶”列。当某次评估被错过时，下一次运行会处理缺失的桶以填补空缺。因此，只要出现已回填的桶，就说明该告警的执行已落后于调度计划。现在，缓慢的 ClickHouse 查询会留下明显的痕迹，而不再悄无声息地拖慢后续评估。

图表标记与被评估桶的起始时间对齐，便于查看告警何时触发、何时恢复为 OK。

您还可以直接在详情页中编辑或删除告警，无需再返回已保存搜索弹窗或仪表板面板编辑器。我们仍在探索将更多告警配置项迁移到此页面。

该页面目前仍受 `NEXT_PUBLIC_ENABLE_ALERT_DETAILS` 开关控制。

## 调查告警与 MCP 工具注解 {#investigating-alerts-and-mcp-tool-annotations}

*演示者 [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/942yeJitK4Q" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

**仅限 ClickHouse Observability：** 已触发的告警现在提供 Investigate 按钮。在告警页面或告警详情页点击该按钮，即可启动一次笔记本调查。

最终目标是在告警触发时自动启动调查。该按钮是一个实用的过渡方案，而非最终形态。

此外，ClickStack MCP 服务器上的每个工具现在都带有注解提示。此前，服务器无法表明哪些工具是只读的，哪些工具会修改或删除数据。

添加 `readOnlyHint` 和 `destructiveHint` 后，客户端便有足够的信息来区别处理这些工具：读取操作可以直接执行、不受打断，而破坏性操作则可以等待显式批准。删除告警就是最典型的例子——在执行之前，理应先征得你的确认。

最后一项变更影响的是智能体从一开始会选用哪些工具。随着工具集不断扩充，又缺乏明确的选择策略，`clickstack_sql` 的使用频率逐渐攀升。即使构建器工具更为合适，智能体仍倾向于直接使用原始 SQL。

这不仅关乎查询的正确性。原始 SQL 生成的是静态结果内容块，而构建器工具 `clickstack_table`、`clickstack_timeseries` 和 `clickstack_search` 生成的内容块则支持点击下钻和切换分析维度。

现在，MCP 会引导智能体优先使用这些构建器工具，只有在确实无法用它们表达查询时才使用原始 SQL。此项变更后，评估评分明显提升。

**相关 PR：** [#2838](https://github.com/hyperdxio/hyperdx/pull/2838) 为所有工具添加 MCP 工具注解 (`readOnlyHint` 等) ，[#2840](https://github.com/hyperdxio/hyperdx/pull/2840) 引导智能体使用构建器查询工具而非原始 SQL，[#2870](https://github.com/hyperdxio/hyperdx/pull/2870) 引导仪表盘智能体使用按数据系列设置的内容块筛选条件。Investigate 按钮本身没有可供链接的公开 PR。

## 单个查询生成多数据系列指标图表 {#multi-series-metric-charts-in-a-single-query}

*演示者 [@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/jJKgFrMfGjU" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

过去，要在一个图表中展示多个指标，需要为每个数据系列分别运行一次 ClickHouse 查询，再在 Node 或浏览器中合并结果集。图表包含 N 个数据系列，就会产生 N 个查询。

现在，多数据系列图表会编译为单个 SQL 查询。每个数据系列各自对应一个 CTE，最后由 ClickHouse 统一合并。比率也采用同样的方式：两个数据系列在同一个查询中生成，比率则在最终投影中计算。

最直接的好处是查询数量减少。此外，这种查询形态也为指标公式打下了基础。公式要求所有数据系列都以列的形式存在于同一个 relation 中，才能在最终的 `SELECT` 中表达。而这正是编译器现在生成的结构，公式相关的工作也已紧随其后。

此次变更暴露了一个回归问题：多数据系列内容块在混合使用返回浮点数和整数的聚合时，无法正常渲染。例如，只要将返回 `Float64` 的直方图 `quantile` 与返回 `Int64` 的直方图 `count` 组合使用，就会触发该问题。

组合生成的 `UNION ALL` 和 pivot 会让所有数据系列共用同一列，导致 ClickHouse 将类型扩展为 `Variant(Float64, Int64)`。该问题现已修复。

## Lucene 自动补全与密码要求修复 {#lucene-autocomplete-and-password-requirement-fixes}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/8MODmM5RT6Q" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

在测试仪表盘变量时，我们发现了另一个回归问题：Lucene 自动补全几乎在所有地方都悄然失效，只有搜索页面仍能正常使用。

另一项变更涉及 Join Team 页面，受邀用户会在此页面设置密码。尽管后端会强制校验密码要求，但该页面此前并未展示这些要求。输入无效密码时，页面只会给出一条笼统的“Password is invalid”提示，用户只能自行猜测密码策略。

现在页面上已会显示这些要求。在检查负责展示这些要求的共享组件时，我们还发现它与后端存在两处不一致：一是哪些特殊字符符合要求，二是密码的最大长度。这两处问题均已修正。
