## 拆分 trace 视图与扩展 trace 视图 {#split-trace-view-and-extended-trace-view}

*演示者：[@karl-power](https://github.com/karl-power)*

<Frame>
  <iframe src="https://www.youtube.com/embed/L4sduqf3CR8" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

trace 面板现已支持拆分视图模式：在时间线中逐个点击 span 时，详情面板会直接在右侧更新，而不再像以前那样在所选 span 下方展开。这样，在深入查看单个 span 时，完整的时间线始终可见。

您还可以展开为扩展 trace 视图，使用支持滚动和缩放的全宽时间线。两个面板均可独立打开和关闭，便于在整体概览与 span 细节之间来回切换，且不会丢失当前位置。

## 数据源级必需筛选条件 {#source-level-required-filters}

*演示者：[@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/RcAl8Sl5GFM" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

数据源现在可以声明必需筛选条件，凡是使用该数据源的仪表盘都会自动显示这些筛选条件。您无需再为每个引用该 source 的仪表盘逐一手动添加相同的筛选条件：ClickStack 会自动识别这一要求，并将筛选条件提升到仪表盘级别，且仅作用于实际使用该 source 的卡片。

如果个别卡片需要使用不同的筛选值，可以覆盖仪表盘级别的值。必需筛选条件还会同步到图表编辑器的预览中，让您无需移除这些条件即可验证查询。对于基于 SQL 的图表，必需的数据源筛选条件还可与 SQL 筛选条件宏配合使用；在设置仪表盘之间的关联时，ClickStack 也会自动将其列为关联参数的候选项。

## Y 轴自适应数据 {#fit-y-axis-to-data}

*演示者 [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/cNiGHy1OqhU" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

折线图新增了 &quot;Y 轴自适应数据&quot; 显示设置。默认情况下，Y 轴固定从零开始；当数值较大但波动很小时，可见范围会被压缩，趋势变化难以一眼看出。

启用此选项后，Y 轴范围将根据实际数据范围动态计算，无需手动配置坐标轴范围，即可清晰看到高数值数据系列中的波动。

## 异常告警 {#anomaly-alerts}

*演示者：[@fleon](https://github.com/fleon)*

<Frame>
  <iframe src="https://www.youtube.com/embed/aAgN3ZlQz8M" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Himanshu 展示了我们正在开发的基于 Z-score 检测的异常告警功能。该功能不再使用固定阈值，而是由您设定偏离预期平均值多少个标准差时触发告警。季节性窗口 (按小时或按天) 决定基线的计算方式；告警编辑器会高亮显示本应触发告警的窗口，方便您在保存前调整灵敏度。

这解决了阈值告警的一个常见痛点：用户往往不清楚该设置多大的数值。调整 Z-score 时，潜在告警窗口会实时更新，借此可以轻松找到既能捕获真实峰值、又不会产生过多噪声的阈值。告警可以限定为仅在值超出预期范围时触发 (低于预期范围时不触发) ；还可以通过匹配项设置，要求条件在连续多个数据点上持续满足后才触发。该功能仍在开发中，目前基线采用移动平均计算，后续计划支持指数移动平均。

*演示者：[@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/qsZ-I6FEsNw" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

数值卡片现已同时支持静态颜色选择器和条件颜色规则。图表调色板也改用了人类可读的颜色名称，例如用 &quot;blue&quot; 和 &quot;gray&quot; 取代 &quot;color-1&quot; 和 &quot;color-10&quot;，选择颜色时一目了然。

借助条件着色，您可以定义有序的阈值规则，例如低于目标值时显示绿色、处于警告范围时显示琥珀色、超过临界阈值时显示红色。这样一来，数值卡片就能在仪表盘上真正充当状态指示器，尤其适合错误率或 P99 延迟等指标：无需细看数字，即可获得直观的视觉反馈。

## 模式迁移 {#schema-migrations}

*演示者：[@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/qVV8vQqctfM" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack 现已在设置中新增 模式迁移 选项卡 (Enterprise) ，用于以受控、版本化的方式对数据 schema 执行 DDL 变更。您只需编写迁移并为其指定版本号，后台作业便会自动获取并执行，同时提供重试机制并严格按顺序执行——如果某个迁移失败，依赖它的后续迁移将暂停运行，直到该迁移问题得到解决或被删除。

借助这种版本化模型，ClickHouse 还能向 ClickStack Cloud 团队推送托管的 schema 优化，无需手动执行 ALTER TABLE 操作。团队可以审查待处理的迁移，并按自己的节奏解除阻塞。第一阶段支持增量式变更；主键修改计划在第二阶段推出。

## 开箱即用的浏览器 RUM 仪表盘 {#out-of-the-box-browser-rum-dashboards}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Kmq9qwTnObw" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack 现已内置预构建的浏览器 RUM 仪表盘，全面覆盖各项 Web 性能指标。该仪表盘包含性能概览 (页面浏览量和 P90 加载时间) 以及 Web Vitals 指标 (LCP、INP 和 CLS) ，并配有分级阈值，让您一眼就能看出每项指标处于良好、需要改进还是较差状态。

其他部分还包括页面浏览量趋势、长任务、设备细分、最慢页面、错误最多的会话、JavaScript 错误率以及 API 失败情况。借助自定义行操作，您可以点击表格中的任意行，下钻到相应的会话或链路追踪数据。页面顶部的筛选条件支持按服务、环境、服务版本和页面进行切分。按国家筛选的功能正在开发中，需等待浏览器 SDK 改进后支持上报地理数据。

## 相互依赖的仪表盘筛选条件 {#dependent-dashboard-filters}

*演示者：[@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/nTnBmZ-MvFg" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

仪表盘筛选条件现在可以相互关联：在某个筛选条件中选择一个值后，下游筛选条件的可选项会自动随之缩小范围。Kubernetes 仪表板率先应用了这一功能：选择某个 pod (容器组) 后，部署和节点下拉列表将只显示与该 pod (容器组) 相关的值，而不再列出整个集群中的全部选项。

因此，您再也不会遇到返回空数据的筛选条件组合。该功能现已在 Kubernetes 仪表板模板中上线。
