## 指标体验改进 {#metrics-experience-improvements}

*演示者 [@alex-fedotyev](https://github.com/alex-fedotyev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/rukel6KVmPY" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

本批更新根据一位正从 Datadog 迁移的客户的反馈，改进了指标和仪表盘的编辑体验。该客户有一套设计周全的指标工作流。我们尚未处理完他们的全部反馈，但其中大部分都集中在一个问题上：当仪表盘屏幕上同时有数百条时间序列时，如何绘制图表并开展排查。

有一项改动与指标无关，但同样源自那次对话：编辑时，仪表板面板现在会吸附到可见的网格上。拖动面板或调整其大小时，网格会显示在面板后方，并高亮其当前位置周围的单元格。以前，用户很难判断面板最终会落在哪里，也不知道移动它是否会把其他面板挤开。有了网格，这两点都一目了然。网格与布局引擎采用相同的几何计算，因此参考线与面板的最终位置完全吻合，右边缘和下边缘也不例外。

指标方面的改动主要针对数据系列较多的图表，这种情况在按多个维度分组时很常见。以前，将鼠标悬停在图表上会显示该时间戳下的所有数据系列。在包含 300 条数据系列的图表上，工具提示甚至可能比图表本身还高，而光标下的那条数据系列也往往并不是你需要的。

现在，数据系列超过 10 条的图表只显示离光标最近的那条数据系列，并将其绘制在最上层，其他数据系列则变暗显示。数据系列不超过 10 条的图表仍保留完整的已排序工具提示，行为保持不变。图例更加紧凑，也可以完全隐藏。显示图例时，它还可用作选择和快速搜索控件，方便快速定位到特定数据系列。

最大的改动在全屏模式——用户发现想要排查的异常偏差后，通常会进入全屏查看。现在只需单击工具栏图标即可进入全屏，不必再到更多操作菜单中查找。进入全屏后，图例会切换为更实用的布局，提供摘要信息和搜索框。按数据系列名称中的子串进行筛选，即可将 300 条数据系列缩减到你关注的寥寥几条，随后便可悬停查看和比较。

在那次沟通之后，有一点做了调整：使用单数据系列还是多数据系列工具提示，将改为可配置，而不再依赖固定阈值。当数据系列不多时，在同一时间点比较多条数据系列的绝对值很有帮助，因此应当允许用户根据图表选择合适的行为。

## Trace 查看器改进 {#trace-viewer-improvements}

*演示者：[@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kmparH3U7Jc" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

我们对重新设计的 trace 查看器做了两处小修复，均直接源自用户对新布局的反馈。

跨度详情面板最近移到了瀑布图右侧，但并非所有人都习惯这个位置。现在，面板关闭按钮旁新增了一个开关，可将面板在右侧 (仍为默认位置) 和底部之间切换。面板位于底部时，您可以将其拖动到合适的高度。

在同一反馈讨论中，我们还发现了一个换行缺陷：启用换行后，缺少自然断点的长属性值仍会被截断，例如不含空格、连字符或破折号的 `url.path`。现在，属性值可以在任意字符边界处换行，完整显示全部内容。

## MCP 服务器与评估改进 {#mcp-server-and-eval-improvements}

*演示者：[@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/2NXRdBZcKMw" title="YouTube 视频播放器" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

其中最小的一项改动，可能对推广使用的影响最大。此前，在 ClickHouse Cloud 中启用 MCP 服务器的入口很难找到：用户需要先按照应用内的说明操作，再找到对应的控制平面设置。现在，点击该按钮会直接打开相关的模态框，在其中即可开启该服务器。

Brandon 在[他近期工作](https://clickhouse.com/blog/benchmarking-the-clickstack-mcp-server-with-hdx-evals)的基础上，继续改进 MCP 的评估框架。现在，评估框架可以使用与被评估对象不同的提供商和模型。此前，整个评估流程都必须使用 Anthropic 模型，这意味着模型可能会给自己的输出打分。现在，您可以提供 OpenAI 密钥以及带提供商前缀的评判模型规范，将评分交由 OpenAI 完成。

对比不同的评判模型后，我们发现了一些有价值的差异。有些模型执行评分标准要严格得多，只要某次运行没有使用某个特定的键就判定失败；另一些则会接受足够接近的答案。我们还修复了在此过程中发现的一个评分过时的缺陷：现在，使用不同的评判模型重新评分一批结果时，会真正运行新的评判模型，而不是直接返回之前的结果。

此外，Brandon 询问 MCP 服务器需要什么才能在服务健康状况检查场景中获得更高分数，并据此新增了 `clickstack_emerging_signals` MCP 工具。这是一个基于双窗口的新模式检测器：它分别从基线窗口和当前窗口中挖掘日志和事件模式，再对比这两个集合，报告新出现的、频率显著上升的以及已消失的模式。

这与现有工具有所不同：事件模式描述的是单个窗口内的常见内容，而事件差异展示的是哪些属性发生了变化。新工具使服务健康状况检查得分提高了约 10 分。

另外，应用户通过 skill 配置数据摄取的需求，MCP 还新增了 source 和 Webhook 的 CRUD 工具。智能体现在不仅可以读取数据源和 Webhook，还可以创建、更新和删除它们。

我们正在推进在 CI 中为每个拉取请求自动运行评估，以取代目前手动将分数粘贴到 PR 描述中的做法。S3 种子数据加载已经可以正常工作，剩下的障碍是为 GitHub Action 授予存储桶访问权限。该问题解决后，评估结果的返回速度将大幅提升。
