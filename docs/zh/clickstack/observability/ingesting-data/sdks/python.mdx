使用 ClickStack Python SDK 将日志和链路追踪发送到 ClickHouse Observability。该 SDK 是一个 OpenTelemetry 发行版，以 `hyperdx-opentelemetry` 包名发布，可自动为受支持的 Python 库和框架插桩。

<ClickStackIntegrates signals={['logs', 'traces']} />

## 安装 SDK {#install-the-sdk}

在应用程序的 Python 环境中安装 [ClickStack Python SDK](https://github.com/hyperdxio/hyperdx-py)：

```shell
pip install hyperdx-opentelemetry
opentelemetry-bootstrap -a install
```

bootstrap 命令会为应用程序已安装的依赖项安装插桩。请在安装完这些依赖项后再运行该命令。

## 配置目标端 {#configure-destination}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    在您的服务中打开 **团队设置 → 数据 → Managed Telemetry**，复制 **OTLP HTTP 端点**和 **API key**。请使用包含端口的完整 HTTPS 端点：

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export HYPERDX_API_KEY='Bearer YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-python-app'
    ```
  </Tab>

  <Tab title="自管理">
    使用采集器的 OTLP HTTP 端点和摄取 API key。如果采集器未配置 TLS，请将 `https://` 替换为 `http://`。有关采集器的配置方法，请参阅[使用 OpenTelemetry 进行摄取](/zh/clickstack/observability/ingesting-data/opentelemetry#sending-otel-data-self-configured)。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export HYPERDX_API_KEY='YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-python-app'
    ```
  </Tab>
</Tabs>

## 启动应用程序 {#start-your-application}

启用自动埋点运行应用程序：

```shell
export OTEL_LOG_LEVEL='warning'
export OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION='false'
opentelemetry-instrument python app.py
```

将 `app.py` 替换为您应用程序的入口文件。

`OTEL_LOG_LEVEL` 用于设置 SDK 的日志级别。设置为 `warning` 可捕获下方的测试消息，设置为 `info` 则还可捕获严重级别更低的应用日志。未配置级别时，SDK 默认使用 `ERROR`。

ClickStack SDK 已自带日志导出器。设置 `OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION=false` 可避免 OpenTelemetry 的日志插桩额外添加导出器，从而导致日志记录重复；SDK 仍会正常导出日志。

## 验证数据摄取 {#verify-ingestion}

向您的应用程序发送请求，并输出一条 `WARNING` 及以上级别的 Python 日志消息。在 ClickHouse Observability 中选择最近的时间范围，然后在日志或链路追踪中搜索 `my-python-app` (或您配置的服务名称) 。

## 可选配置 {#optional-configuration}

如需捕获 HTTP 请求头和消息体，请在启动应用程序之前启用高级网络捕获：

```shell
export HYPERDX_ENABLE_ADVANCED_NETWORK_CAPTURE=1
```

请求头和消息体可能包含敏感数据。请仅针对确需收集的数据启用捕获。

## 故障排查 {#troubleshooting}

如果日志缺失，请检查 `OTEL_LOG_LEVEL` 以及应用程序中日志记录器和处理器的级别设置，确保其能够捕获您所需严重级别的消息。

有关插桩和导出器的故障排查，请参阅 [OpenTelemetry Python 故障排查指南](https://opentelemetry.io/docs/zero-code/python/troubleshooting/)。
