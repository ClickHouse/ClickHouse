借助 Deno 内置的 OpenTelemetry 支持，即可将日志、指标和链路追踪发送到 ClickHouse Observability，无需使用 ClickStack Node.js SDK 或旧版 Deno 日志软件包。

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## 设置 OpenTelemetry {#set-up-opentelemetry}

请按照 Deno 官方的 [OpenTelemetry 设置说明](https://docs.deno.com/runtime/fundamentals/open_telemetry/) 为应用程序进行插桩。先配置下方的目标端，然后在启动应用程序时启用 Deno 的内置集成：

```shell
OTEL_DENO=true OTEL_SERVICE_NAME='my-deno-app' deno run app.ts
```

添加应用程序所需的权限。将上游说明中的所有示例目标端或控制台导出器设置替换掉，包括针对特定信号的端点覆盖配置。

## 配置目标端 {#configure-destination}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 产品" />

    在您的服务中打开 **团队设置 → 数据 → Managed Telemetry**，复制 **OTLP HTTP 端点** 和 **API key**。请使用包含端口在内的完整 HTTPS 端点：

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="自管理">
    使用采集器的 OTLP HTTP 端点和摄取 key。如果采集器未配置 TLS，请将 `https://` 替换为 `http://`。有关采集器的设置方法，请参阅[使用 OpenTelemetry 摄取数据](/zh/clickstack/observability/ingesting-data/opentelemetry#self-managed)。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## 验证数据摄取 {#verify-ingestion}

启动应用程序并产生一些活动。在 ClickHouse Observability 中选择最近的时间范围，然后在 日志 或 链路追踪 中查找您应用程序的服务名称。指标需要一段时间才能导出，稍等片刻后再查看 指标。
