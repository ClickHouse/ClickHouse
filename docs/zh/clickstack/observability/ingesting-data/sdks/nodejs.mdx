ClickStack Node.js SDK 基于上游 OpenTelemetry SDK 及其自动插桩构建，并在此基础上新增了控制台输出捕获、未捕获异常捕获，以及在关闭时刷写遥测数据的功能。已配置 OpenTelemetry 的应用程序可以继续沿用现有的 SDK，只需[配置 OTLP 导出](/zh/clickstack/observability/ingesting-data/opentelemetry)即可。

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## 安装 {#install}

请使用 Node.js **22.15 或更高版本**。在应用程序中安装 SDK：

```shell
npm install @clickhouse/clickstack-node
```

该软件包同时支持 ES 模块和 CommonJS。npm 会自动安装其对等依赖 `@opentelemetry/api`。如果您的应用程序直接导入了该软件包，请安装 `@opentelemetry/api@~1.9.1`；1.10 版本不在此 SDK 支持的版本范围内。

## 配置目标端 {#configure-destination}

启动应用程序前，请先设置环境变量。请使用 OTLP HTTP 基础端点，不要包含 `/v1/traces`、`/v1/logs` 或 `/v1/metrics`；导出器会自动追加这些路径。

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版本" />

    打开 **团队设置 → 数据 → Managed Telemetry**，复制 **OTLP HTTP 端点** 和 **API key**。请务必使用该服务所显示的 HTTPS 端点和端口，不要改动：

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```
  </Tab>

  <Tab title="自管理">
    使用采集器的 OTLP HTTP 端点，以及在其 OTLP 接收器中配置的摄取密钥。有关采集器的设置，请参阅[使用 OpenTelemetry 进行摄取](/zh/clickstack/observability/ingesting-data/opentelemetry#self-managed)。

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```

    此端点假定应用程序与采集器运行在同一主机上。如果采集器部署在其他位置，请将其替换为应用程序可访问的地址。
  </Tab>
</Tabs>

## 启动应用程序 {#start-application}

请先预加载 SDK，再让应用程序导入由该 SDK 插桩的库：

```shell
node --import @clickhouse/clickstack-node/register server.js
```

将 `server.js` 替换为您应用程序的入口文件。此命令会在应用程序启动前加载 SDK，并使用上文配置的环境变量。CommonJS 和 ES 模块应用程序均受支持。

现在您可以[验证摄取](#verify-ingestion)。仅当您希望通过 npm 脚本启动，或在代码中配置 SDK 时，才需要使用下面的替代方式。

<Accordion title="其他启动方式">
  也可以使用 `--require`。如果使用 `NODE_OPTIONS`，请将其作用范围限定在应用程序命令内，以免构建工具启动各自的遥测数据管道：

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  或者，也可以创建一个插桩模块并预加载。上一节中的环境变量仍会用于配置导出：

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  该判断可防止工作线程 (例如 Pino transport 工作线程) 启动额外的 SDK 实例。

  软件包的注册入口点与您自己的插桩模块只能二选一，请勿在应用程序中再初始化第二个 SDK。静态 ES 模块导入会先于模块主体执行，因此即使在同一文件中将 `init` 调用置于静态导入之前，也无法保证初始化顺序。
</Accordion>

## 验证摄取 {#verify-ingestion}

启动应用程序，向已插桩的路由发送请求，并输出一条控制台消息。在 ClickHouse Observability 中选择最近的时间范围，然后在 Logs 或 Traces 中搜索 `my-node-app`。检查指标前，请先等待一个指标导出时间间隔。

如果数据缺失，请检查 stderr 中的 SDK 诊断信息、端点和身份验证配置以及网络连通性。确保插桩在应用程序依赖项之前加载。如果打包工具将库内联，这些库将无法被自动插桩；请将 SDK 和已插桩的依赖项保留为外部依赖。有关 TypeScript、ES 模块、框架和打包工具的要求，请参阅 [SDK 兼容性](https://github.com/ClickHouse/clickstack-node#compatibility)。

## 配置插桩 {#configure-instrumentation}

标准 OpenTelemetry 环境变量沿用其上游定义，涵盖采样、批处理、导出器和资源属性等。例如：

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

默认会捕获控制台输出。HTTP 请求正文捕获默认处于禁用状态；请根据您的应用程序所处理数据的性质，仅在合适时启用该功能：

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

捕获的请求正文可能包含个人数据和凭证。SDK 的脱敏仅能尽力而为，必要时请保留采集器端的脱敏处理。有关请求头捕获、请求正文大小限制和数据清洗的说明，请参阅 [SDK 隐私选项](https://github.com/ClickHouse/clickstack-node#privacy)。

### 初始化选项 {#initialization-options}

在插桩模块中将以下选项传给 `init`：

| 选项                           | 默认值                          | 用途                                                                            |
| ---------------------------- | ---------------------------- | ----------------------------------------------------------------------------- |
| `endpoint`                   | `http://localhost:4318`      | OTLP HTTP 基础 URL；会被 `OTEL_EXPORTER_OTLP_ENDPOINT` 覆盖                          |
| `serviceName`                | `unknown_service:` 后接可执行程序名称 | 服务名称；会被 `OTEL_SERVICE_NAME` 或 `OTEL_RESOURCE_ATTRIBUTES` 中的 `service.name` 覆盖 |
| `environment`                | 未设置                          | 设置 `deployment.environment.name`；`OTEL_RESOURCE_ATTRIBUTES` 中的同名键优先           |
| `apiKey`                     | 未设置                          | 授权请求头值；若 `OTEL_EXPORTER_OTLP_HEADERS` 已非空，则忽略此项，即使其中只包含无关的请求头                 |
| `httpBodyCapture`            | `false`                      | 捕获 HTTP 消息体；会被 `CLICKSTACK_CAPTURE_HTTP_BODY` 覆盖                              |
| `instrumentations`           | 上游配置默认值                      | `getNodeAutoInstrumentations` 的配置映射；显式设置的 `enabled` 值会覆盖用于启用/禁用插桩的环境变量        |
| `additionalInstrumentations` | `[]`                         | 为默认插桩集合之外的库提供的附加插桩实例                                                          |

环境变量未设置或为空时，对应选项才会生效。如需禁用控制台捕获，请将 `console` 加入 `OTEL_NODE_DISABLED_INSTRUMENTATIONS`。所有默认值请参阅 [Node.js SDK 参考文档](https://github.com/ClickHouse/clickstack-node#quick-start)。

如需显式退出进程或使用 AWS Lambda 处理器，请参阅 [SDK 生命周期文档](https://github.com/ClickHouse/clickstack-node#lifecycle)。

## 使用上游 SDK {#using-upstream-sdk}

如果您的应用程序已经配置了 OpenTelemetry，或者需要使用 ClickStack SDK 选项之外的自定义处理器或行为，请改用上游的 `NodeSDK`，并为上述目标端配置 OTLP 导出。具体请参考[上游 SDK 设置示例](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly)，其中介绍了所需的额外加载器和生命周期配置。请勿在同一进程中同时初始化这两个 SDK。

## 从 HyperDX Node.js SDK 迁移 {#migration}

将 `@hyperdx/node-opentelemetry` 替换为 `@clickhouse/clickstack-node`，并改用新的注册入口点。将 `HYPERDX_API_KEY` 替换为 `OTEL_EXPORTER_OTLP_HEADERS`，并按照上文中对应目标端的授权格式进行设置。

新 SDK 并未保留 HyperDX 的所有辅助函数和选项。在替换日志记录器集成、错误处理程序、自定义 trace 属性或采样设置之前，请先查阅 [SDK 迁移指南](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md)。
