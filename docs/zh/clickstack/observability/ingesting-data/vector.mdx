    <Note>
      本指南仅适用于**自管理 ClickHouse Observability**。Vector 的 ClickHouse 数据接收端会将数据直接写入由您自行管理的表。全托管 ClickHouse Observability 必须通过 OTLP 进行摄取；有关端点和身份验证设置，请参阅[使用 OpenTelemetry 摄取数据](/zh/clickstack/observability/ingesting-data/opentelemetry#fully-managed)。
    </Note>

    [Vector](https://vector.dev) 是一款高性能、厂商中立的可观测性数据管道，常用于从各类数据源采集、转换和路由日志与指标。凭借灵活性高、资源占用低的特点，它在日志摄取场景中尤为流行。

    在 Self-managed ClickHouse Observability 中使用 Vector 时，用户需要自行定义 schema。这些 schema 可以遵循 OpenTelemetry 约定，也可以完全自定义，以表示用户自定义的事件结构。实际应用中，Vector 摄取最常用于**日志**场景，此时用户希望在数据写入 ClickHouse 之前完全掌控解析和富集过程。

    本指南重点介绍如何使用 Vector 将数据接入 Self-managed ClickHouse Observability。为简明起见，本指南不会深入介绍 Vector 数据源或管道配置，而是重点说明如何配置将数据写入 ClickHouse 的**数据接收端 (sink)&#x20;**，并确保最终生成的 schema 与 Self-managed ClickHouse Observability 兼容。

    该服务唯一的硬性要求是数据中必须包含**时间戳列** (或等价的时间字段) ，可在可观测性 UI 中配置数据源时指定该列。

## 使用 Vector 发送数据 {#sending-data-with-vector-self-configured}

    <br />

    本指南假定您已创建 Self-managed ClickHouse Observability 服务并记录了服务凭证。如果尚未完成，请按照 Self-managed ClickHouse Observability 的[入门指南](/zh/clickstack/self-configured/getting-started/managed)进行操作，直到出现配置 Vector 的提示为止。

    <Steps>
      <Step title="创建数据库和表" id="create-a-database-table-self-configured">
        Vector 要求在数据摄取之前预先定义表和 schema。

        首先创建一个数据库，可以通过 [ClickHouse Cloud 控制台](/zh/products/cloud/features/sql-console-features/sql-console)完成。

        在下面的示例中，我们使用 `logs`：

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        为您的数据创建一张表，其结构应与数据的输出 schema 相匹配。以下示例假定使用经典的 Nginx 结构，请根据您的实际数据进行相应调整，并遵循 [schema 最佳实践](/zh/concepts/best-practices/select-data-type)。我们**强烈建议**您先熟悉[主键的概念](/zh/concepts/core-concepts/primary-indexes)，并按照[此处](/zh/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key)列出的指导原则选择主键。

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Nginx 主键**

          上述主键是基于可观测性 UI 中 Nginx 日志的典型访问模式设计的，在生产环境中可能需要根据您的实际工作负载进行调整。
        </Info>
      </Step>

      <Step title="在 vector 配置中添加 ClickHouse 数据接收端" id="add-clickhouse-sink-to-config-self-configured">
        修改 Vector 配置，添加 ClickHouse 数据接收端，并更新 `inputs` 字段，使其接收来自现有管道的事件。

        此配置假定上游 Vector 管道已**将数据处理为与目标 ClickHouse schema 相匹配的格式**，即所有字段均已完成解析、命名正确，且类型适合插入。有关如何将原始日志行解析并规范化为适用于该服务的 schema 的完整演示，请参阅[**下方的 Nginx 示例**](#example-dataset-with-vector-self-configured)。

        ```yaml
        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - your_input
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        我们默认推荐使用 **`json_each_row`** 格式，该格式将每个事件编码为一个 JSON 对象，每行一个。这是该服务摄取 JSON 数据时的默认及推荐格式，应优先于其他格式 (例如编码为字符串的 JSON 对象) 使用。

        ClickHouse 数据接收端还支持 **Arrow stream 编码** (目前处于 Beta 阶段) 。该编码可提供更高的吞吐量，但存在一些重要约束：由于 schema 仅在启动时拉取一次，数据库和表必须是静态的，且不支持动态路由。因此，Arrow 编码最适用于固定且定义明确的摄取流水线。

        建议查阅 [Vector 文档](https://vector.dev/docs/reference/configuration/sinks/clickhouse)，了解数据接收端可用的配置选项：

        <Note>
          上述示例使用的是 Self-managed ClickHouse Observability 的 default 用户。在生产环境部署中，我们建议[创建专用的摄取用户](/zh/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)，并为其设置适当的权限和限制。
        </Note>
      </Step>

      <Step title="转到可观测性 UI" id="navigate-to-clickstack-ui-self-configured">
        进入您的 Self-managed ClickHouse Observability 服务，然后在左侧菜单中选择 &quot;ClickStack&quot;。如果您已完成 onboarding，系统将在新选项卡中打开可观测性 UI，并自动完成身份验证。如果尚未完成，您可以继续 onboarding 流程，在选择 Vector 作为输入 source 后，点击 “Launch ClickStack”。

        <div className="ch-image-lg">
          <Frame>
            ![为 Vector 启动 ClickStack](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="创建数据源" id="create-a-datasource-managed-self-configured">
        创建日志数据源。如果当前尚无任何数据源，首次登录时系统会提示您创建一个；否则，请前往“团队设置”添加新的数据源。

        <div className="ch-image-lg">
          <Frame>
            ![创建数据源 - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        上述配置假定使用 Nginx 风格的 schema，并以 `time_local` 列作为时间戳。在条件允许时，该列应为主键中声明的时间戳列。此列为必填项。

        我们还建议更新 `Default SELECT`，以显式指定日志视图中返回的列。如果还有其他可用字段 (例如服务名称、日志级别或请求正文列) ，也可以一并配置。如果时间戳显示列与表主键中使用的、即上面已配置的列不同，也可以覆盖该显示列。

        在上面的示例中，数据中并不存在 `Body` 列，而是通过 SQL 表达式定义该列，利用可用字段重建 Nginx 日志行。

        有关其他可用选项，请参阅[配置参考文档](/zh/clickstack/self-configured/managing/config)。
      </Step>

      <Step title="探索数据" id="explore-the-data-managed-self-configured">
        进入日志视图，即可浏览数据并开始使用该服务。

        <div className="ch-image-lg">
          <Frame>
            ![可观测性 UI 中的 Nginx 日志](/images/clickstack/nginx-logs-vector-search.webp)
          </Frame>
        </div>
      </Step>
    </Steps>

## 基于 Vector 的示例数据集 {#example-dataset-with-vector-self-configured}

    下面我们使用一个 **Nginx 日志文件** 作为更完整的示例。

    本指南假定您已创建 Self-managed ClickHouse Observability 服务并记录了服务凭证。如果尚未完成，请按照 Self-managed ClickHouse Observability 的[入门指南](/zh/clickstack/self-configured/getting-started/managed)进行操作，直到提示您配置 Vector 为止。

    <Steps>
      <Step title="安装 Vector" id="installing-vector-self-configured">
        <InstallingVector />
      </Step>

      <Step title="下载样本数据" id="download-the-sample-data-self-configured">
        <VectorSampleData />
      </Step>

      <Step title="创建数据库和表" id="create-database-table-nginx-managed-self-configured">
        Vector 要求在数据摄取之前先定义好表和 schema。

        首先创建一个数据库，可以通过 [ClickHouse Cloud 控制台](/zh/products/cloud/features/sql-console-features/sql-console) 完成。

        创建名为 `logs` 的数据库：

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        为数据创建一张表。

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Nginx 主键**

          上述主键是基于可观测性 UI 中查询 Nginx 日志的典型访问模式设计的，但在生产环境中，可能需要根据您的实际工作负载进行调整。
        </Info>
      </Step>

      <Step title="复制 Vector 配置" id="copy-vector-configuration-self-configured">
        复制 Vector 配置并创建文件 `nginx.yaml`，在其中设置 `CLICKHOUSE_ENDPOINT` 和 `CLICKHOUSE_PASSWORD`。

        ```yaml
        data_dir: ./.vector-data
        sources:
          nginx_logs:
            type: file
            include:
              - access.log
            read_from: beginning

        transforms:
          decode_json:
            type: remap
            inputs:
              - nginx_logs
            source: |
              . = parse_json!(to_string!(.message))
              ts = parse_timestamp!(.time_local, format: "%d/%b/%Y:%H:%M:%S %z")
              # ClickHouse-friendly DateTime format
              .time_local = format_timestamp!(ts, format: "%F %T")

        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - decode_json
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        <Note>
          上述示例使用的是 Self-managed ClickHouse Observability 的 default 用户。在生产环境部署中，建议[创建专用的摄取用户](/zh/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)，并为其配置适当的权限和限制。
        </Note>
      </Step>

      <Step title="启动 Vector" id="start-vector-self-configured">
        先创建用于记录文件偏移量的数据目录，然后使用以下命令启动 Vector。

        ```bash
        mkdir ./.vector-data
        vector --config nginx.yaml
        ```
      </Step>

      <Step title="进入可观测性 UI" id="navigate-to-clickstack-ui-nginx-managed-self-configured">
        进入你的 Self-managed ClickHouse Observability 服务，然后在左侧菜单中选择 &quot;ClickStack&quot;。如果你已完成 onboarding，系统会在新选项卡中打开可观测性 UI，并自动完成身份验证。如果尚未完成，可以继续进行 onboarding，在选择 Vector 作为输入 source 后，点击“Launch ClickStack”。

        <div className="ch-image-lg">
          <Frame>
            ![为 Vector 启动 ClickStack](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="创建数据源" id="create-a-datasource-nginx-managed-self-configured">
        创建日志数据源。如果尚无任何数据源，首次登录时系统会提示您创建一个；否则，请前往团队设置并添加新的数据源。

        <div className="ch-image-lg">
          <Frame>
            ![创建数据源 - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        该配置假定使用 Nginx schema，并以 `time_local` 列作为时间戳。该列是在主键中声明的时间戳列，且为必需列。

        我们还将默认 select 指定为 `time_local, remote_addr, status, request`，用于定义日志视图中返回的列。

        在上述示例中，数据中并不存在 `Body` 列，而是通过以下 SQL 表达式定义：

        ```sql
        concat(
          remote_addr, ' ',
          remote_user, ' ',
          '[', formatDateTime(time_local, '%d/%b/%Y:%H:%M:%S %z'), '] ',
          '"', request, '" ',
          toString(status), ' ',
          toString(body_bytes_sent), ' ',
          '"', http_referer, '" ',
          '"', http_user_agent, '" ',
          '"', http_x_forwarded_for, '" ',
          toString(request_time), ' ',
          toString(upstream_response_time), ' ',
          '"', http_host, '"'
        )
        ```

        这会根据结构化字段重建日志行。

        有关其他可用选项，请参阅[配置参考文档](/zh/clickstack/self-configured/managing/config)。
      </Step>
