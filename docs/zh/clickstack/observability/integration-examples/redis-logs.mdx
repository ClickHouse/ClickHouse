使用 OpenTelemetry 采集器收集 Redis 服务器日志，并将其发送到 ClickHouse Observability。无需安装 Redis，即可使用[演示数据集](#demo-dataset)试用此集成。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 用于运行采集器示例的 Docker，或已部署的 OpenTelemetry Collector Contrib
* 如需采集您自己的日志，需要已安装的 Redis，并具有其日志文件的访问权限

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → Data → Managed Telemetry**，复制您的 OTLP HTTP 端点和 API key。您可以点击 **Copy 连接详情** 复制配置，或点击 **Reveal key** 查看被遮盖的 key。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    为运行下方的 OTLP 导出器示例，请在将要运行采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务中的确切端点 (含端口) 和 API key。请使用不带 `/v1/logs` 后缀的基础 HTTP 端点，导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果您的采集器无需身份验证，请在下方配置中省略导出器的 `headers` 块。有关设置说明，请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

采集器容器必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下方的 Docker 命令已包含该主机映射。

## 与现有 Redis 集成 {#existing-redis}

<Steps>
  <Step title="检查 Redis 日志配置" id="verify-redis">
    检查 Redis 的日志写入位置：

    ```bash
    redis-cli CONFIG GET logfile
    ```

    常见的 Redis 日志位置：

    * **Linux (apt/yum)**：`/var/log/redis/redis-server.log`
    * **macOS (Homebrew)**：`/usr/local/var/log/redis.log` 或 `/opt/homebrew/var/log/redis.log`
    * **Docker**：通常输出到 stdout，但也可以配置为写入 `/data/redis.log`

    如果 Redis 将日志输出到 stdout，请修改 `redis.conf`，将其配置为写入文件：

    ```bash
    # Log to file instead of stdout
    logfile /var/log/redis/redis-server.log

    # Set log level (options: debug, verbose, notice, warning)
    loglevel notice
    ```

    请确保日志目录已存在，且 Redis 对该目录具有写入权限。修改配置后，请使用您安装环境中对应的服务名称重启 Redis：

    ```bash
    # For systemd
    sudo systemctl restart redis

    # For Docker
    docker restart <redis-container>
    ```
  </Step>

  <Step title="配置采集器" id="configure-collector">
    将以下内容保存为 `redis-monitoring.yaml`：

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis/redis-server.log
        start_at: end
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis
          - type: add
            field: resource["service.name"]
            value: redis-service

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, batch]
          exporters: [otlp_http/observability]
    ```

    此配置会解析进程 ID、角色、时间戳、日志级别和消息。它将 `service.name` 设置为 `redis-service`，并将 Redis 日志级别映射到 `SeverityText`，供仪表盘使用。Redis 的 notice 消息 (`*`) 映射为 `info`，警告消息 (`#`) 映射为 `warn`，调试/详细模式消息 (`.` 和 `-`) 映射为 `debug`。

    Redis 日志时间戳不包含时区信息。请将 `location` 设置为 Redis 服务器所在的时区，例如 `America/Chicago`；本示例使用 `UTC`。原始时间戳和日志正文均会保留。设置 `start_at: end` 后，采集器首次打开文件时只读取新写入的条目。
  </Step>

  <Step title="运行采集器" id="run-collector">
    设置[连接变量](#connection-details)，然后在包含 `redis-monitoring.yaml` 的目录中运行以下命令。请根据实际安装情况，调整主机上的日志目录路径以及接收器 `include` 中的文件名：

    ```bash
    docker run --rm --name redis-monitoring-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/redis:/var/log/redis:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    保持此终端处于打开状态，并在 Redis 中执行一些操作，使其写入新的日志条目。采集器必须能够读取已挂载的文件。
  </Step>

  <Step title="检查日志" id="verify-logs">
    打开 **搜索** 页面，选择 **Logs**，并按 `ServiceName:redis-service` 进行过滤。选择能覆盖新日志的时间范围。展开任一条目，查看 `SeverityText` 以及 `LogAttributes` 下已解析的字段。

    <div className="ch-image-lg">
      <Frame>
        ![搜索视图中的 Redis 日志](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

该样本数据包含 10,000 条 Redis 服务器日志条目。开始之前，请先设置[连接变量](#connection-details)。

<Steps>
  <Step title="下载样本数据集" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-server.log
    ```
  </Step>

  <Step title="配置演示采集器" id="configure-demo">
    将以下内容另存为下载目录中的 `redis-demo.yaml`：

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis-demo/redis-server.log
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis-demo
          - type: add
            field: resource["service.name"]
            value: redis-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-28T14:59:22Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      仅用于演示的 `transform/demo_timestamps` 处理器会将样本数据的时间平移至大约过去 24 小时内 (截止于摄取前两分钟) ，同时保留原有的流量模式。原始时间戳属性和日志正文保持不变。处理您自己的 Redis 日志时，请勿使用此处理器。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo">
    在包含 `redis-server.log` 和 `redis-demo.yaml` 的目录下，运行以下命令：

    ```bash
    docker run --rm --name redis-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/redis-server.log:/var/log/redis-demo/redis-server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    验证摄取期间，请保持终端处于打开状态。完成后，按 **Ctrl+C** 停止采集器。由于此示例不会持久化文件偏移量，再次运行该演示时，会以刷新后的时间戳重新摄取样本数据。
  </Step>

  <Step title="验证演示日志" id="verify-demo-logs">
    打开 **搜索** 页面，选择 **Logs**，按 `ServiceName:redis-demo` 进行过滤，并选择 **最近 2 天**。展开任意一条日志条目，即可查看已解析的属性和严重级别。

      <Frame>
        ![搜索视图中的 Redis 日志示例](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### 采集器无法启动 {#collector-fails-to-start}

请查看采集器终端输出中是否有配置错误。确认 YAML 文件已挂载到文档中指定的路径，并确保在运行 Docker 的终端中已设置端点及所有必需的身份验证变量。

### 未显示日志 {#no-logs}

* 检查采集器输出中是否有身份验证错误或导出错误，并核实连接详情。
* 运行 `redis-cli CONFIG GET logfile`，确认 Redis 将日志写入文件。确保采集器能够读取该文件，且其挂载路径与接收器的 `include` 路径一致。
* 如果设置了 `start_at: end`，请在启动采集器之后生成新的日志条目。
* 检查 **Logs** source、服务名称过滤器和时间范围。如使用演示数据，请在管道中加入 `transform/demo_timestamps`，并选择 **最近 2 天**。

### 日志未能正确解析 {#logs-not-parsing}

该接收器要求日志采用 Redis 的标准 `pid:role timestamp level message` 格式。请检查您的日志文件；如果格式不一致，请相应调整正则表达式。此外，请将时间解析器的 `location` 设置为 Redis 服务器所在的时区。
