使用 OpenTelemetry Redis receiver 采集 Redis 指标，并将其发送至 ClickHouse Observability。无需安装 Redis，即可使用[演示数据集](#demo-dataset)体验此集成。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 用于运行采集器示例的 Docker，或已有的 OpenTelemetry Collector Contrib 部署
* 如需采集您自己的指标：一个可从采集器访问的 Redis 实例；如果 Redis 启用了身份验证，还需相应的凭证
* 如需运行演示：使用 `curl` 下载并发送样本数据

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → Data → Managed Telemetry**。复制您的 OTLP HTTP 端点和 API key。您可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看被遮盖的 key。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    为运行下文的 OTLP 导出器示例，请在将要运行采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务中的准确端点 (含端口) 和 API key。请使用不带 `/v1/metrics` 后缀的基础 HTTP 端点，导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    请使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果您的采集器无需身份验证，请在下文配置中省略导出器的 `headers` 块。有关设置说明，请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

采集器容器必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下文的 Docker 命令已包含主机映射。

## 与现有 Redis 集成 {#existing-redis}

<Steps>
  <Step title="验证 Redis 连接" id="verify-redis">
    在可以使用 Redis 命令行客户端的主机上，检查您的 Redis 实例：

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    第一条命令应返回 `PONG`，第二条命令应返回服务器信息。如果 Redis 需要密码，请先在终端中设置 `REDISCLI_AUTH`，再运行这些命令。如果使用 Redis ACL 用户，还需传入 `--user YOUR_REDIS_USER`。
  </Step>

  <Step title="配置采集器" id="configure-collector">
    将以下内容保存为 `redis-metrics.yaml`：

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # 如果 Redis 需要身份验证，请取消注释：
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    该接收器每 10 秒采集一次 Redis 指标，包括内存使用量、客户端、已处理命令数、keyspace 命中与未命中次数，以及已过期或被驱逐的键。resource 处理器会将 `service.name` 设置为 `redis-service`，便于过滤。

    如果 Redis 需要身份验证，请取消注释相应的接收器字段，并设置 `REDIS_USERNAME` 和/或 `REDIS_PASSWORD`。这些凭证用于连接 Redis，而 OTLP authorization 值用于向目标端采集器进行身份验证。如果 Redis 启用了 TLS，请参考 [Redis receiver 文档](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver)配置接收器的 `tls` 设置。
  </Step>

  <Step title="运行采集器" id="run-collector">
    设置[连接变量](#connection-details)，以及采集器容器可访问的 Redis 地址。如果 Redis 运行在本机上：

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    如果是远程 Redis，请使用其主机名和端口。如果 Redis 运行在其他容器中，请使用其容器名称，并在下面的命令中添加 `--network YOUR_NETWORK`。

    在 `redis-metrics.yaml` 所在目录中运行：

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    采集指标期间请保持此终端处于打开状态。请至少等待两个采集时间间隔，再到 UI 中查看。
  </Step>

  <Step title="验证指标" id="verify-metrics">
    导入[仪表盘](#dashboards)，将其图表映射到您的 **Metrics** source，并按 `ServiceName:redis-service` 过滤。选择 **Last 15 minutes** 并运行仪表盘。对于运行正常的 Redis 实例，驱逐数和被拒绝连接数可能始终为零。
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

您可以使用 6,912 个 gauge 和 sum 数据点试用此集成，这些数据点覆盖 24 小时，每五分钟采样一次。该样本保留了原始数据集中的缓存预热、流量突增和内存压力模式。您需要准备 Docker、`curl`，以及目标端采集器的 OTLP HTTP 连接详情。

开始之前，请先设置[连接变量](#connection-details)。

<Steps>
  <Step title="下载示例指标" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="配置演示采集器" id="configure-demo-collector">
    将以下内容保存为 `redis-metrics-demo.yaml`：

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      此 transform 仅用于演示，它会刷新时间戳，同时保留指标值以及每个数据点起止时间戳之间的时间间隔。采集实时 Redis 指标时请去掉它。batch 限制可确保每次上传的数据量足够小，便于目标端采集器处理。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo-collector">
    在配置文件所在目录中运行采集器，并保持此终端打开：

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="发送样本" id="load-metrics">
    打开另一个终端，在下载目录中运行以下命令：

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    如果返回 `{}` 或 `{"partialSuccess":{}}` 之类的响应，说明本地采集器已接受该请求。请在采集器终端中检查是否有导出错误，并等待几秒钟完成转发。确认数据无误后，按 **Ctrl+C** 停止采集器。重复发送样本可能会产生重复的数据点。
  </Step>

  <Step title="验证指标" id="verify-demo-metrics">
    导入[下一节](#dashboards)中的仪表盘，按 `ServiceName:redis-demo` 筛选，并选择 **最近 2 天**。该样本同时包含 gauge 和 sum 指标，无需直接访问数据库。
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### 采集器无法启动 {#collector-fails-to-start}

请查看采集器终端输出中是否有配置错误。确认 YAML 文件已挂载到文档指定的路径，并确认在运行 Docker 的终端中已设置端点和所需的身份验证变量。

### 未显示指标 {#no-metrics}

* 检查采集器输出中是否存在 Redis 连接错误或 OTLP 导出错误。
* 确认采集器容器可以访问 Redis。如果使用容器部署，请检查它们是否位于预期的同一 Docker 网络中。
* 验证 Redis 凭证，并确认该用户有权运行 [Redis receiver](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver) 所需的命令。
* 检查 **Metrics** source、服务名称过滤器和时间范围。对于演示数据，请选择 **最近 2 天**，并确认管道中已包含时间戳变换。
* 对于 managed service，请对照 **Managed Telemetry** 核实 OTLP HTTP 端点和 Bearer API key。对于自管理采集器，请使用其自身的身份验证设置。
