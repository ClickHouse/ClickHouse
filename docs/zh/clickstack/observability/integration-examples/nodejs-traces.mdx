借助 OpenTelemetry 自动埋点采集 Node.js 应用程序的链路追踪数据，并将其发送到 ClickHouse Observability。如需在不对应用程序进行插桩的情况下试用此集成，可使用[演示数据集](#demo-dataset)。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 应用程序：Node.js 22 或更高版本，以及 npm
* 演示：Docker 和 `curl`

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → 数据 → Managed Telemetry**，复制 OTLP HTTP 端点和 API key。您可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看已隐藏的密钥。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    在用于运行应用程序或演示采集器的终端中设置以下连接变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务的实际端点 (含端口) 和 API key。请使用基础 HTTP 端点，不要带 `/v1/traces` 后缀；导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果采集器无需身份验证，请在下文配置中省略导出器的 `headers` 块。具体设置方法请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## 与现有 Node.js 应用程序集成 {#existing-nodejs}

<Steps>
  <Step title="安装 OpenTelemetry" id="install-instrumentation">
    在应用程序目录中安装插桩软件包：

    ```bash
    npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node@0.81.0
    ```

    以下步骤适用于 CommonJS 应用程序，采用 [OpenTelemetry 自动埋点](https://opentelemetry.io/docs/zero-code/js/)。原生 ES 模块则需使用 [ESM 设置](https://github.com/open-telemetry/opentelemetry-js/blob/main/doc/esm-support.md)。每个应用程序只应使用一种插桩方式，以免产生重复的 span。
  </Step>

  <Step title="配置追踪并启动应用程序" id="run-application">
    在已设置连接变量的终端中运行：

    ```bash
    export OTEL_SERVICE_NAME='nodejs-service'
    export OTEL_TRACES_EXPORTER='otlp'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="Authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='none'
    export OTEL_LOGS_EXPORTER='none'

    node --require @opentelemetry/auto-instrumentations-node/register app.js
    ```

    将 `app.js` 替换为应用程序的入口点。预加载机制会在应用程序导入依赖库之前完成插桩初始化。如果使用的是未启用身份验证的自管理端点，请省略导出请求头的 export 语句，并运行 `unset OTEL_EXPORTER_OTLP_HEADERS`。

    应用程序必须能够访问该端点。如果应用程序运行在容器中，`localhost` 指的是该容器本身。
  </Step>

  <Step title="生成流量" id="generate-traffic">
    向应用程序提供的端点发送请求。例如，对于监听端口 `3000` 的应用程序：

    ```bash
    curl http://localhost:3000/
    ```

    稍等几秒，让导出器完成 span 的发送。
  </Step>

  <Step title="验证链路追踪" id="verify-traces">
    打开 **搜索**，选择 **链路追踪**，按 `ServiceName:nodejs-service` 进行过滤，并选择 **Last 15 minutes**。打开任一 trace，即可查看其 span、耗时和属性。
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

该样本包含来自 `nodejs-demo-api` 的 822 个 span，无需运行 Node.js 应用程序。

<Steps>
  <Step title="下载样本数据集" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nodejs/nodejs-traces-sample.json
    ```
  </Step>

  <Step title="配置演示采集器" id="configure-demo-collector">
    将以下内容保存为 `nodejs-traces-demo.yaml`，放在下载目录中：

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T17:59:15Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nodejs-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      `transform/demo_timestamps` 处理器仅用于演示，它会将该样本的时间平移到大约过去 24 小时的范围内，结束时间为摄取前两分钟，同时保留 span 耗时和流量模式。处理您自己的 Node.js 链路追踪时，请去掉此处理器，以保留原始时间戳。重复发送该样本可能会产生重复的 span。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo-collector">
    <Note>
      如果目标采集器运行在本机上，请将 `OTEL_EXPORTER_OTLP_ENDPOINT` 设置为 `http://host.docker.internal:4318`。下面的命令已包含 Docker 主机映射。
    </Note>

    在已设置连接变量的终端中，进入配置文件所在目录，运行 OpenTelemetry Collector Contrib `0.161.0`。请勿关闭此终端：

    ```bash
    docker run --rm --name nodejs-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nodejs-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    本地接收器使用端口 `14318`，以免与端口 `4318` 上已有的采集器冲突。采集器会使用上述身份验证设置，将链路追踪转发到您配置的端点。
  </Step>

  <Step title="发送链路追踪" id="send-traces">
    在另一个终端中，进入下载目录，将原始样本发送到本地采集器：

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nodejs-traces-sample.json
    ```

    如果返回空的成功响应 (例如 `{}` 或 `{"partialSuccess":{}}`) ，说明本地采集器已接受该请求。请检查采集器输出中是否有导出错误，并等待几秒钟，让批次到达您的服务。完成后，按 **Ctrl+C** 停止演示采集器。
  </Step>

  <Step title="验证演示链路追踪" id="verify-demo-traces">
    打开 **搜索**，选择 **链路追踪**，按 `ServiceName:nodejs-demo-api` 筛选，并选择 **最近 2 天**，以涵盖平移后的完整数据集。打开任一 trace 即可查看其 HTTP 属性。

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability 搜索中的 Node.js 演示链路追踪](/images/clickstack/observability-nodejs-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### 未显示应用程序链路追踪 {#no-application-traces}

检查应用程序输出中是否有导出错误，并核实端点、协议和身份验证设置。确保插桩在应用程序库之前加载，然后生成一些请求，并检查服务名称过滤器和时间范围。如果使用原生 ES 模块，请按照链接中的 ESM 设置说明进行配置。

### 演示链路追踪未显示 {#no-demo-traces}

检查演示采集器的输出中是否有身份验证错误或导出错误。`curl` 返回成功响应仅表明数据已被本地接收；数据转发到您的服务可能需要几秒钟。请确保管道中包含 `transform/demo_timestamps`，并选择 **最近 2 天**。重复发送样本数据可能会产生重复记录。
