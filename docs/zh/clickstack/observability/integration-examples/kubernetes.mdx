通过两个 OpenTelemetry 采集器收集容器日志、节点与集群指标以及 Kubernetes 事件：一个是在每个节点上运行的 DaemonSet 守护进程集，另一个是负责采集集群级数据的单实例部署。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 一个包含 Linux 节点的 Kubernetes 集群，且具备创建工作负载、集群角色 (ClusterRole) 和主机路径挂载的权限
* 已针对目标集群配置好 `kubectl`，并已安装 Helm 3
* 采集器可通过网络访问您服务的 OTLP HTTP 端点、Kubernetes API 以及 kubelet 节点代理

这些采集器负责收集基础设施数据。如需发送应用程序指标和链路追踪，请另行对应用程序进行插桩，详见 [OpenTelemetry 集成](/zh/clickstack/observability/ingesting-data/opentelemetry)。

## 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → 数据 → Managed Telemetry**，复制其中的 OTLP HTTP 端点和 API key。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    在终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    请原样使用该端点 (包括端口) ，不要添加 `/v1/logs` 或 `/v1/metrics` 后缀。
  </Tab>

  <Tab title="自管理" id="self-managed">
    使用可从集群访问的采集器 OTLP HTTP 端点及其身份验证设置。如果已禁用身份验证，请将 `OTEL_EXPORTER_OTLP_AUTHORIZATION` 设置为空字符串，并省略下文导出器配置中的 `headers` 块。详见[自管理设置指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## 部署采集器 {#deploy-collectors}

<Steps>
  <Step title="创建命名空间并配置连接设置" id="connection-settings">
    确认 `kubectl` 指向目标集群：

    ```bash
    kubectl config current-context
    kubectl create namespace observability --dry-run=client -o yaml | kubectl apply -f -

    kubectl create configmap observability-connection -n observability \
      --from-literal=endpoint="$OTEL_EXPORTER_OTLP_ENDPOINT" \
      --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic observability-connection -n observability \
      --from-literal=authorization="$OTEL_EXPORTER_OTLP_AUTHORIZATION" \
      --dry-run=client -o yaml | kubectl apply -f -
    ```

    这两个采集器都在 `observability` 命名空间中使用这些设置。
  </Step>

  <Step title="保存共享配置" id="shared-configuration">
    将以下内容保存为 `k8s_common.yaml`：

    ```yaml
    image:
      repository: otel/opentelemetry-collector-contrib
      tag: "0.161.0"
    command:
      name: otelcol-contrib
    resources:
      limits:
        memory: 512Mi
    presets:
      kubernetesAttributes:
        enabled: true
    extraEnvs:
      - name: OTEL_EXPORTER_OTLP_ENDPOINT
        valueFrom:
          configMapKeyRef:
            name: observability-connection
            key: endpoint
      - name: OTEL_EXPORTER_OTLP_AUTHORIZATION
        valueFrom:
          secretKeyRef:
            name: observability-connection
            key: authorization
    service:
      enabled: false
    ports:
      otlp:
        enabled: false
      otlp-http:
        enabled: false
      jaeger-compact:
        enabled: false
      jaeger-thrift:
        enabled: false
      jaeger-grpc:
        enabled: false
      zipkin:
        enabled: false
    config:
      receivers:
        otlp: null
        jaeger: null
        zipkin: null
        prometheus: null
      exporters:
        debug: null
        otlp_http/observability:
          endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
          headers:
            authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
          compression: gzip
      processors:
        batch:
          timeout: 5s
          send_batch_size: 500
          send_batch_max_size: 500
      service:
        pipelines:
          logs:
            receivers: []
            exporters: [otlp_http/observability]
          metrics:
            receivers: []
            exporters: [otlp_http/observability]
          traces: null
    ```

    该 chart 的预设会为每个采集器添加所需的接收器、Kubernetes 元数据处理器、RBAC 规则和挂载。共享配置会将日志和指标转发到您的服务，并禁用未使用的应用程序数据摄取接收器。
  </Step>

  <Step title="配置节点采集" id="daemonset-configuration">
    将以下内容保存为 `k8s_daemonset.yaml`：

    ```yaml
    mode: daemonset
    presets:
      logsCollection:
        enabled: true
        storeCheckpoints: true
      hostMetrics:
        enabled: true
      kubeletMetrics:
        enabled: true
    config:
      receivers:
        kubeletstats:
          insecure_skip_verify: true
    ```

    DaemonSet 守护进程集负责读取容器日志，并采集主机和 kubelet 节点代理的指标。借助检查点，采集器重启后仍能保留日志的读取位置。此预设以 root 身份运行采集器，以便在节点上写入检查点；您集群的 pod (容器组) 安全设置必须允许其挂载主机路径。

    如果集群的 kubelet 证书不受采集器信任，本示例会跳过 kubelet 证书验证。如果您的集群提供受信任的 kubelet 证书，请将 `insecure_skip_verify` 设置为 `false`，并配置相应的 CA。
  </Step>

  <Step title="配置集群数据采集" id="deployment-configuration">
    将以下内容保存为 `k8s_deployment.yaml`：

    ```yaml
    mode: deployment
    replicaCount: 1
    presets:
      kubernetesEvents:
        enabled: true
      clusterMetrics:
        enabled: true
    ```

    仅保留一个副本，以免重复采集集群指标和事件。
  </Step>

  <Step title="安装 Helm 发布实例" id="install-collectors">
    在包含这三个配置文件的目录中运行以下命令。这些示例使用 OpenTelemetry Collector Helm chart `0.175.1` 和 Collector Contrib `0.161.0`：

    ```bash
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update open-telemetry

    helm upgrade --install observability-nodes open-telemetry/opentelemetry-collector \
      --version 0.175.1 --namespace observability \
      -f k8s_common.yaml -f k8s_daemonset.yaml --wait

    helm upgrade --install observability-cluster open-telemetry/opentelemetry-collector \
      --version 0.175.1 --namespace observability \
      -f k8s_common.yaml -f k8s_deployment.yaml --wait
    ```

    检查采集器：

    ```bash
    kubectl get pods -n observability
    kubectl logs -n observability -l app.kubernetes.io/instance=observability-nodes --tail=50
    kubectl logs -n observability -l app.kubernetes.io/instance=observability-cluster --tail=50
    ```

    如果您的节点设置了调度污点 (taint) ，请在 `k8s_daemonset.yaml` 中添加相应的 `tolerations`，以覆盖需要监控的节点。
  </Step>

  <Step title="验证数据" id="verify-data">
    等待几个采集周期后，打开 ClickHouse Observability：

    * 在 **搜索** 中，选择您的 **Logs** source，并将时间范围设为 **Last 15 minutes**。展开一条容器日志，查看 `k8s.namespace.name`、`k8s.pod.name` 和 `k8s.node.name` 等属性。
    * 在 **Chart Explorer** 中，选择您的 **Metrics** source，查找以 `k8s.` 或 `system.` 开头的指标。
    * 在您的 **Logs** source 中查看实时产生的 Kubernetes 事件。事件数量取决于集群的活跃程度。
  </Step>
</Steps>

## 应用程序元数据 {#application-metadata}

对于已插桩的应用程序，请通过 Kubernetes downward API 添加 pod (容器组) 元数据。将此 `env` 列表合并到应用程序容器的现有配置中，并保留已有的全部资源属性：

```yaml
env:
  - name: OTEL_SERVICE_NAME
    value: my-app
  - name: POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
  - name: POD_UID
    valueFrom:
      fieldRef:
        fieldPath: metadata.uid
  - name: POD_NAMESPACE
    valueFrom:
      fieldRef:
        fieldPath: metadata.namespace
  - name: NODE_NAME
    valueFrom:
      fieldRef:
        fieldPath: spec.nodeName
  - name: OTEL_RESOURCE_ATTRIBUTES
    value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME)
```

Kubernetes 元数据处理器会为采集到的容器日志补充工作负载元数据。这些应用程序变量会将 pod (容器组) 身份附加到应用程序 OpenTelemetry SDK 发出的遥测数据上。

## 故障排查 {#troubleshooting}

### 采集器无法启动 {#collectors-not-starting}

使用 `kubectl describe pod -n observability POD_NAME` 查看 pod (容器组)  事件。检查镜像拉取、调度约束和 pod (容器组)  安全限制，并确认 ConfigMap 和 Secret 与相应的 Helm release 位于同一命名空间中。

### 未显示任何日志或指标 {#no-data}

请检查采集器日志中是否存在身份验证错误或导出错误，并确认可以从集群访问目标端端点。如果出现 kubelet 节点代理错误，请检查与端口 `10250` 的连通性、证书设置以及自动生成的 RBAC 权限。采集容器日志需要访问节点上的 `/var/log/pods` 目录；在受限或无服务器节点环境中，可能不支持此类主机挂载。

### 连接设置已更改 {#connection-settings-changed}

更新 ConfigMap 或 Secret 后，请重启采集器，以重新加载其环境变量：

```bash
kubectl rollout restart daemonset -n observability -l app.kubernetes.io/instance=observability-nodes
kubectl rollout restart deployment -n observability -l app.kubernetes.io/instance=observability-cluster
```
