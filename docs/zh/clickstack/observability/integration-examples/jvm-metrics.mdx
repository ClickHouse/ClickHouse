使用 OpenTelemetry Java agent采集 JVM 指标，并发送到 ClickHouse Observability。如需试用此集成，可使用[演示数据集](#demo-dataset)，无需对应用程序进行插桩。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 如需采集您自己应用的指标：一个 Java 8+ 应用程序，且您能够修改其启动命令或运行环境
* 如需运行演示：Docker 和 `curl`

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **Team Settings → Data → Managed Telemetry**，复制 OTLP HTTP 端点和 API key。可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看已隐藏的密钥。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    在将要启动应用程序或演示采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务的实际端点 (含端口) 和 API key。请使用不带 `/v1/metrics` 后缀的基础 HTTP 端点，导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果采集器无需身份验证，请省略 Java agent的 `OTEL_EXPORTER_OTLP_HEADERS`，以及演示采集器中导出器的 `headers` 块。有关设置说明，请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

应用程序必须能够访问该端点。如果使用 Docker 演示，采集器容器也必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下文的 Docker 命令已包含主机映射。

## 与现有 JVM 应用程序集成 {#existing-jvm}

<Steps>
  <Step title="下载 Java agent" id="download-agent">
    下载 OpenTelemetry Java agent `2.22.0`：

    ```bash
    curl -fLO https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/download/v2.22.0/opentelemetry-javaagent.jar
    ```
  </Step>

  <Step title="配置并启动应用程序" id="configure-jvm">
    设置[连接变量](#connection-details)，然后配置agent：

    ```bash
    export OTEL_SERVICE_NAME='jvm-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='otlp'
    export OTEL_LOGS_EXPORTER='none'
    export OTEL_TRACES_EXPORTER='none'

    java -javaagent:./opentelemetry-javaagent.jar -jar my-application.jar
    ```

    将 `my-application.jar` 替换为您的应用程序 JAR 文件，并按需调整agent路径。服务名称应能标识您的应用程序。以上设置仅采集指标。如果您的应用程序已在导出链路追踪或日志，请保留这些信号现有的导出器设置。

    如果应用程序由服务或容器管理，请将agent添加到现有的 JVM 启动参数中，并通过部署配置提供环境变量。详见 [Java agent配置文档](https://opentelemetry.io/docs/zero-code/java/agent/configuration/)。
  </Step>

  <Step title="验证指标" id="verify-metrics">
    请至少等待两分钟，以便agent导出指标。打开 **Chart Explorer**，选择您的 **Metrics** source，然后查找 `jvm.memory.used` 或 `jvm.thread.count`。按 `ServiceName:jvm-service` 进行过滤，并选择 **Last 15 minutes**。
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

该样本包含 6,048 个每五分钟采样一次的 Gauge 数据点，以及原始数据集中全部 412 个垃圾回收事件，涵盖约 24 小时的内存、线程、类、CPU 和 GC 活动。无需 Java 应用程序，也无需直接访问数据库。

开始之前，请先设置[连接变量](#connection-details)。

<Steps>
  <Step title="下载示例指标" id="download-sample">
    [下载演示包](/zh/assets/jvm-metrics-demo.zip)并解压到工作目录中。其中包含 `jvm-metrics-demo.json` 和 `jvm-metrics-dashboard.json`。
  </Step>

  <Step title="配置演示采集器" id="configure-demo-collector">
    将以下内容保存为 `jvm-metrics-demo.yaml`：

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: jvm-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-12-08T14:16:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      此 transform 仅用于演示：它会刷新时间戳，同时保留指标值以及每个数据点起止时间戳之间的时间间隔。采集实时 JVM 指标时请去掉该处理器。批次大小限制可使每次上传的数据量足够小，以便目标端采集器接收。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo-collector">
    在配置文件所在目录中运行采集器，并保持该终端打开：

    ```bash
    docker run --rm --name jvm-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/jvm-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="发送示例数据" id="load-metrics">
    打开另一个终端，在下载目录中运行以下命令：

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @jvm-metrics-demo.json
    ```

    如果返回 `{}` 或 `{"partialSuccess":{}}` 等响应，说明本地采集器已接受该请求。请在采集器终端中检查是否有导出错误，并等待几秒钟以完成转发。确认数据无误后，按 **Ctrl+C** 停止采集器。重复发送示例数据可能会产生重复的数据点。
  </Step>

  <Step title="验证指标" id="verify-demo-metrics">
    导入[下一节](#dashboards)中的仪表盘，按 `ServiceName:jvm-demo` 筛选，并选择 **最近 2 天**。该样本同时包含 Gauge 和 总和 类型的指标，无需直接访问数据库。
  </Step>
</Steps>

    </Note>
  </Step>

## 故障排查 {#troubleshooting}

### Agent 无法启动 {#agent-not-starting}

请检查：agent JAR 文件是否位于 `-javaagent` 所指定的路径下，应用程序是否有权限读取该文件，以及 Java 版本是否为 8 或更高。同时查看应用程序的启动输出，排查与 agent 相关的错误。

### 未显示指标 {#no-metrics}

* 检查应用程序或演示采集器的输出中是否存在身份验证错误或导出错误。
* 确认应用程序或容器可以访问该端点，且协议为 `http/protobuf`。
* 检查 **Metrics** source、服务名称过滤器和时间范围。演示环境请使用 **最近 2 天**。
* 如果使用现有采集器，请确认其指标管道包含 OTLP 接收器和指标导出器。
* 如果演示采集器已接受请求但未收到数据，请检查其终端中是否存在转发错误。
