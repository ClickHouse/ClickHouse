使用 OpenTelemetry PostgreSQL 接收器采集 PostgreSQL 指标，并将其发送到 ClickHouse Observability。借助[演示数据集](#demo-dataset)，无需安装 PostgreSQL 即可试用该集成。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* Docker 和 `curl`
* 如需采集您自己的指标，还需要一个可从采集器访问的 PostgreSQL 14 或更高版本实例，以及一个监控用户

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → Data → Managed Telemetry**，复制您的 OTLP HTTP 端点和 API key。您可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看被隐藏的密钥。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    为配合下文的 OTLP 导出器示例，请在将要运行采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务的准确端点 (含端口) 和 API key。请使用不带 `/v1/metrics` 后缀的基础 HTTP 端点，导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    请使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果您的采集器无需身份验证，请在下文配置中省略导出器的 `headers` 块。有关设置说明，请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

采集器容器必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下文的 Docker 命令已包含该主机映射。

## 与现有 PostgreSQL 集成 {#existing-postgres}

<Steps>
  <Step title="配置监控用户" id="monitoring-permissions">
    以 PostgreSQL 管理员身份创建监控用户 (如尚未创建) ，并授予其访问统计信息的权限：

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    为每个需要监控的数据库授予 `CONNECT` 权限。同时检查网络和 `pg_hba.conf` 设置，确保 PostgreSQL 允许来自采集器的连接。

    在设置 OTLP 连接变量的同一终端中，设置数据库连接变量：

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    如果 PostgreSQL 运行在 Docker 主机上，请使用 `host.docker.internal:5432`。如果容器位于共享的 Docker 网络中，请使用数据库容器的主机名，并在采集器命令中添加 `--network YOUR_NETWORK`。
  </Step>

  <Step title="配置采集器" id="configure-collector">
    将以下内容保存为 `postgres-metrics.yaml`，并将 `databases` 列表替换为您的数据库名称：

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    此配置会启用 TLS 并验证服务器证书。如果使用私有 CA，请设置 `tls.ca_file`，并将 CA 文件挂载到采集器中。对于不使用 TLS 的本地 PostgreSQL 服务器，请设置 `tls.insecure: true`，这将禁用数据库连接的 TLS。详情请参阅 [PostgreSQL 接收器配置](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration)。
  </Step>

  <Step title="运行采集器" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    保持终端打开，并至少等待两个采集时间间隔。测试完成后，按 **Ctrl+C** 停止采集器。
  </Step>

  <Step title="验证指标" id="verify-metrics">
    打开 **Chart Explorer**，选择您的 **Metrics** source，按 `ServiceName:postgresql-service` 筛选，并选择 **Last 15 minutes**。然后查找 `postgresql.backends`、`postgresql.commits` 或 `postgresql.db_size` 指标。
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

该样本包含 8,928 个 gauge 和 sum 数据点，覆盖 24 小时，每五分钟采样一次。它保留了原始数据集中的连接数峰值、缓存活动、回滚和死锁。样本仅包含数据库级别的指标；实时采集还会提供表和索引级别的指标。

开始之前，请先设置[连接变量](#connection-details)。

<Steps>
  <Step title="下载示例指标" id="download-sample">
    [下载示例包](/zh/assets/postgres-metrics-demo.zip) (约 64 KB) ，并将 `postgres-metrics-demo.json` 解压到您的工作目录中。
  </Step>

  <Step title="配置演示采集器" id="configure-demo-collector">
    将以下内容保存为 `postgres-metrics-demo.yaml`：

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      此 transform 仅用于演示，它会刷新时间戳，同时保留指标值以及每个数据点起止时间戳之间的时间间隔。采集实时 PostgreSQL 指标时请勿使用它。批次大小限制可确保每次上传的数据量足够小，以便目标端采集器接收。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo-collector">
    在配置文件所在目录中运行采集器，并保持此终端打开：

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="发送示例数据" id="load-metrics">
    打开另一个终端，在下载目录中运行以下命令：

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    如果返回 `{}` 或 `{"partialSuccess":{}}` 之类的响应，说明本地采集器已接受该请求。请在采集器终端中检查是否有导出错误，并等待几秒钟让数据完成转发。确认数据无误后，按 **Ctrl+C** 停止采集器。重复发送示例数据可能会产生重复的数据点。
  </Step>

  <Step title="验证指标" id="verify-demo-metrics">
    导入[下一节](#dashboards)中的仪表盘，按 `ServiceName:postgresql-demo` 筛选，并选择 **最近 2 天**。该示例同时包含 gauge 和 sum 指标，无需直接访问数据库。
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### 采集器无法启动 {#collector-fails-to-start}

检查采集器的输出中是否有配置错误。确认配置文件已挂载，并确认已在运行 Docker 的终端中设置连接变量。

### 未显示指标 {#no-metrics}

检查采集器输出中是否有数据库连接错误或导出错误。确认容器能够访问数据库主机名、数据库名称正确无误，且 PostgreSQL 允许监控用户建立连接。检查 **Metrics** source、服务名称过滤器和时间范围的设置。

### 身份验证或 TLS 错误 {#authentication-errors}

请确认监控用户已具备 `pg_monitor` 和 `CONNECT` 权限。在可访问 PostgreSQL 的主机上，使用 `psql` 测试数据库凭证：

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

确保接收器的 TLS 设置与服务器一致，并挂载所需的 CA 证书。如遇导出错误，请对照服务的连接详情检查 OTLP 端点和授权信息。
