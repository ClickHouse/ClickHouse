Temporal 提供了一层抽象，可用于构建简单、精巧且具备弹性的应用程序。

<Info>
  **TL;DR**

  借助 OTel Prometheus receiver，在 ClickHouse Observability 中监控 Temporal Cloud 指标，并提供预构建仪表板。
</Info>

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 一个现有的 Temporal Cloud 账户
* 一台已安装 Docker 的主机，且该主机可通过 HTTPS 访问 Temporal Cloud 和您的 OTLP 端点

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **Team Settings → Data → Managed Telemetry**，复制您的 OTLP HTTP 端点和 API key。您可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看被隐藏的密钥。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    为配合下文的 OTLP 导出器示例，请在将要运行采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务的确切端点 (含端口) 和 API key。请使用基础 HTTP 端点，不要带 `/v1/metrics` 后缀；导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    请使用可访问的采集器 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果您的采集器不要求身份验证，请在下文配置中省略导出器的 `headers` 块。有关设置说明，请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

采集器容器必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下文的 Docker 命令已包含主机映射。

## 与现有 Temporal Cloud 集成 {#existing-temporal}

<Steps>
  <Step title="创建 Temporal Cloud 密钥" id="create-temporal-cloud-key">
    按照 [身份验证 指南](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication)，创建一个具有 **指标 Read-Only** 角色的 Temporal Cloud 服务账号，并生成 API key。服务账号和密钥必须由 Account Owner 或 Global Admin 创建。

    <Warning>
      **密钥文件**

      将 Temporal API key 保存到文件 `temporal.key` 中，并将该文件放在与下文所创建配置文件相同的目录下。文件中只存放密钥本身，不要包含 `Bearer` 前缀或首尾空格。该密钥与您的 ClickHouse Observability API key 相互独立。请确保采集器能够读取挂载的文件。
    </Warning>
  </Step>

  <Step title="配置 OTel 采集器" id="custom-otel">
    运行一个独立的 OpenTelemetry 收集器，通过 Prometheus receiver 抓取 Temporal Cloud 的指标，并将其转发到您的服务。

    创建名为 `temporal-metrics.yaml` 的文件，内容如下：

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    此配置会：

    * 连接到 `metrics.temporal.io` 上的 Temporal Cloud
    * 每 60 秒采集一次指标
    * 采集[关键性能指标](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)
    * **按照 [OpenTelemetry 语义约定](https://opentelemetry.io/docs/specs/semconv/resource/#service)设置必需的 `service.name` 资源属性**
    * 通过专用管道将指标发送到您的 OTLP 端点

    如果有多个 Temporal Cloud 账户，可自定义 `service.name` 加以区分 (例如 `temporal-prod` 和 `temporal-dev`) 。
  </Step>

  <Step title="运行采集器" id="run-collector">
    在包含 `temporal-metrics.yaml` 和 `temporal.key` 的目录下，设置[连接变量](#connection-details)并运行：

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    保持终端开启，并留意是否出现抓取或导出错误。Temporal Cloud 指标可能需要几分钟才会显示。测试完成后，按 **Ctrl+C** 停止采集器。
  </Step>

  <Step title="在 ClickHouse Observability 中验证指标" id="verifying-metrics">
    配置完成后，登录 ClickHouse Observability，确认指标已正常流入：

    1. 打开 **Chart Explorer**，选择您的 **指标** source
    2. 按 `ServiceName:temporal` 进行筛选，选择 **Last 15 minutes**，然后搜索以 `temporal` 开头的指标 (例如 `temporal_cloud_v1_workflow_success_count`、`temporal_cloud_v1_poll_timeout_count`)
    3. 您应能看到指标数据点按所配置的采集间隔持续出现

    <div className="ch-image-md">
      <Frame>
        ![Temporal 指标](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### 采集器无法启动 {#collector-fails-to-start}

请检查终端输出中是否有配置错误。确认两个已挂载的文件都存在，且采集器有权限读取 `temporal.key`。确保运行 Docker 的终端中已设置 OTLP 连接变量。

### 未显示指标 {#no-metrics}

查看采集器日志：

```bash
docker logs temporal-metrics-collector
```

检查是否存在抓取、身份验证或导出错误。确认该主机能够访问 `https://metrics.temporal.io/v1/metrics` 以及您的 OTLP 端点。在 **Chart Explorer** 中，检查 **指标** source、`ServiceName:temporal` 过滤器和时间范围是否正确。Temporal 指标可能需要几分钟才会出现，且取决于您账户中的活动情况。

### 身份验证错误 {#auth-errors}

如果出现 Temporal 抓取错误，请确认 `temporal.key` 中包含有效的 API key，且该 API key 对应的服务账号具有 **Metrics Read-Only** 角色。如果出现 OTLP 导出错误，请检查您的 ClickHouse Observability 端点和授权值。这两者是相互独立的凭证。

## 后续步骤 {#next-steps}

* 为关键指标 (工作流失败率、任务积压增长、schedule-to-start 延迟) 设置[告警](/zh/clickstack/observability/features/alerts)
* 针对特定用例创建更多仪表盘 (如命名空间级别监控、各工作流类型的性能)
* 复制接收器配置并指定不同的端点和服务名称，即可监控多个 Temporal Cloud 账户

## 投入生产环境 {#going-to-production}

本指南会运行一个独立的 OpenTelemetry 收集器，并将指标转发到您服务的 OTLP 端点。有关部署方面的指导，请参阅[发送 OpenTelemetry 数据](/zh/clickstack/observability/ingesting-data/opentelemetry)。
