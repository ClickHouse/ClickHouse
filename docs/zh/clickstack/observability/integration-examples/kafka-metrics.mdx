使用 OpenTelemetry JMX Metric Gatherer 采集 Kafka broker 指标，并将其发送到 ClickHouse Observability。即使没有部署 Kafka，也可以通过[演示数据集](#demo-dataset)试用此集成。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 已安装 Docker (含 Docker Compose) 和 `curl`
* 如需采集自有指标，需准备一个已启用远程 JMX 且可从 gatherer 访问的 Kafka broker

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → Data → Managed Telemetry**，复制您的 OTLP HTTP 端点和 API key。您可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看已遮蔽的 key。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    在用于运行 JMX gatherer 或演示采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务的实际端点 (含端口) 和 API key。请使用基础 HTTP 端点，不要带 `/v1/metrics` 后缀；导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理">
    使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果您的采集器无需身份验证，请省略 JMX gatherer 的 `-Dotel.exporter.otlp.headers` 参数和演示采集器的 `headers` 块。设置方法请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

gatherer 或采集器容器必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下文的 Docker 命令已包含该主机映射。

## 与现有 Kafka 部署集成 {#existing-kafka}

<Steps>
  <Step title="检查 broker 的 JMX 端点" id="verify-jmx">
    使用为 broker 配置的远程 JMX 端点。例如，若 broker 在端口 `9999` 上暴露 JMX：

    ```bash
    export KAFKA_JMX_URL='service:jmx:rmi:///jndi/rmi://YOUR_KAFKA_HOST:9999/jmxrmi'
    export KAFKA_BROKER_ID='broker-0'
    ```

    将主机名和 broker ID 替换为您自己的值。broker 通告的 RMI 主机名也必须能从 gatherer 访问。如果 broker 的 registry 端口和 RMI 端口是分开的，需在网络中同时放行这两个端口。gatherer 读取的是 JMX，因此无需开放 Kafka 客户端端口 `9092`。

    如果容器位于共享 Docker 网络中，请使用 broker 的容器主机名。如果 broker 运行在 Docker 宿主机上，请使用 `host.docker.internal`，并将 broker 配置为通告一个容器可访问的主机名。请将 JMX 访问限制在监控网络内，并保留 broker 原有的身份验证和 TLS 设置。
  </Step>

  <Step title="下载 JMX Metric Gatherer" id="download-jmx">
    ```bash
    curl -fL -o opentelemetry-jmx-metrics.jar \
      https://github.com/open-telemetry/opentelemetry-java-contrib/releases/download/v1.32.0/opentelemetry-jmx-metrics.jar
    ```
  </Step>

  <Step title="配置 gatherer" id="configure-gatherer">
    将以下内容保存为 `compose.yaml`，与已下载的 JAR 文件放在同一目录下：

    ```yaml
    services:
      kafka-jmx-gatherer:
        image: eclipse-temurin:11-jre
        extra_hosts:
          - "host.docker.internal:host-gateway"
        environment:
          - KAFKA_JMX_URL
          - KAFKA_BROKER_ID
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        volumes:
          - ./opentelemetry-jmx-metrics.jar:/app/opentelemetry-jmx-metrics.jar:ro
        command:
          - sh
          - -c
          - >-
            exec java
            -Dotel.jmx.service.url="$${KAFKA_JMX_URL}"
            -Dotel.jmx.target.system=kafka
            -Dotel.jmx.interval.milliseconds=10000
            -Dotel.metrics.exporter=otlp
            -Dotel.exporter.otlp.protocol=http/protobuf
            -Dotel.exporter.otlp.endpoint="$${OTEL_EXPORTER_OTLP_ENDPOINT}"
            -Dotel.exporter.otlp.headers="authorization=$${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
            -Dotel.resource.attributes="service.name=kafka-service,kafka.broker.id=$${KAFKA_BROKER_ID}"
            -jar /app/opentelemetry-jmx-metrics.jar
    ```

    如果 broker 位于现有的 Docker 网络中，请在 Compose 配置中将 `kafka-jmx-gatherer` 接入该网络。如果 JMX 需要身份验证，请添加 `otel.jmx.username` 和 `otel.jmx.password` 属性；如果使用 TLS，请配置相应的信任库。详见 [gatherer 的身份验证与 TLS 配置](https://github.com/open-telemetry/opentelemetry-java-contrib/tree/v1.32.0/jmx-metrics#configuration)。
  </Step>

  <Step title="开始采集" id="run-gatherer">
    在当前终端中设置[连接变量](#connection-details)和 broker 变量，然后在 `compose.yaml` 所在目录中运行：

    ```bash
    docker compose up kafka-jmx-gatherer
    ```

    保持终端打开，留意是否出现 JMX 连接错误或 OTLP 导出错误。gatherer 每 10 秒采集一次，请至少等待两个采集周期后再检查您的服务。测试完成后，按 **Ctrl+C** 停止。

    如有多个 broker，请为每个 broker 各运行一个 gatherer，并分别配置其 JMX URL 和 `kafka.broker.id`。
  </Step>

  <Step title="验证指标" id="verify-metrics">
    打开 **Chart Explorer**，选择您的 **Metrics** source，按 `ServiceName:kafka-service` 筛选，并选择 **Last 15 minutes**。查找 `kafka.partition.count`、`kafka.partition.under_replicated` 或 `kafka.message.count`。流量相关的指标需要 broker 有实际活动才能产生有意义的值。
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

该样本包含 6,282 个 Gauge 和 Sum 类型的数据点，每五分钟采样一次，时间跨度约 29 小时。它保留了原始数据集中的流量激增、请求延迟、消费滞后以及分区健康状况等变化模式。无需部署 Kafka，也无需直接访问数据库。

开始之前，请先设置[连接变量](#connection-details)。

<Steps>
  <Step title="下载示例指标" id="download-sample">
    [下载示例包](/zh/assets/kafka-metrics-demo.zip) (约 53 KB) ，并将 `kafka-metrics-demo.json` 解压到工作目录中。
  </Step>

  <Step title="配置演示采集器" id="configure-demo-collector">
    将以下内容保存为 `kafka-metrics-demo.yaml`：

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: kafka-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-06T22:14:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      这个仅用于演示的 transform 会刷新时间戳，同时保留指标值以及每个数据点起止时间戳之间的时间间隔。处理实时 Kafka 指标时，请省略该处理器。批次大小限制可确保每次上传的数据量足够小，便于目标端采集器接收。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo-collector">
    在配置文件所在的目录中运行采集器，并保持该终端处于打开状态：

    ```bash
    docker run --rm --name kafka-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="发送样本" id="load-metrics">
    打开另一个终端，在下载目录中运行以下命令：

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @kafka-metrics-demo.json
    ```

    如果返回 `{}` 或 `{"partialSuccess":{}}` 等响应，则表示本地采集器已接受该请求。请在采集器终端中检查是否有导出错误，并等待几秒钟让数据完成转发。确认数据无误后，按 **Ctrl+C** 停止采集器。重复发送样本可能会产生重复的数据点。
  </Step>

  <Step title="验证指标" id="verify-demo-metrics">
    导入[下一节](#dashboards)中的仪表盘，按 `ServiceName:kafka-demo` 进行筛选，并选择 **最近 2 天**。该样本同时包含 Gauge 和 Sum 类型的指标，无需直接访问数据库。
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### JMX 连接失败 {#jmx-connection-fails}

使用 `docker compose logs kafka-jmx-gatherer` 查看 gatherer 的输出。确认 JMX 已启用，registry 和对外通告的 RMI 端点均可访问，且所配置的 JMX 凭证和信任库与 broker 一致。使用容器主机名时，各容器必须位于预期的同一网络中。

### 未显示任何指标 {#no-metrics}

* 检查 gatherer 或演示采集器的输出，确认是否存在连接、身份验证或导出错误。
* 对照服务的连接详情，核实 OTLP HTTP 端点和身份验证配置。
* 检查 **Metrics** source、服务名称过滤器和时间范围。如使用演示数据，请选择 **最近 2 天**。
* 如使用现有采集器，请确认其指标管道包含 OTLP 接收器和指标导出器。
* 在使用演示仪表盘之前，请先在 **Chart Explorer** 中核实当前实际上报的指标名称。

### Kafka 客户端命令中的 JMX 端口冲突 {#port-conflicts}

如果在 broker 容器内运行 Kafka 客户端命令，请针对该命令清除从 broker 继承的 JMX 设置，以免客户端尝试绑定同一端口：

```bash
env -u JMX_PORT -u KAFKA_JMX_OPTS kafka-topics --list --bootstrap-server YOUR_KAFKA_HOST:9092
```
