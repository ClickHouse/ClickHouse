使用 OpenTelemetry 采集器收集 AWS CloudWatch 日志，并将其发送到 ClickHouse Observability。如需在不配置 AWS 访问权限的情况下试用此集成，可使用[演示数据集](#demo-dataset)。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务
* 用于运行采集器示例的 Docker 和 Docker Compose，或现有的 OpenTelemetry Collector Contrib 部署
* 如需采集您自己的日志：一个包含 CloudWatch 日志组的 AWS 账户、AWS CLI v2，以及具备下列权限的凭证
* 如需运行演示：用于下载样本数据的 `curl`

### 连接详情 {#connection-details}

<Tabs>
  <Tab title="全托管">
    <BetaBadge label="Beta 版服务" />

    打开 ClickHouse Observability，进入 **团队设置 → Data → Managed Telemetry**。复制您的 OTLP HTTP 端点和 API key。您可以点击 **Copy connection details** 复制配置，或点击 **Reveal key** 查看已隐藏的 key。

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 连接详情](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    为配合下文的 OTLP 导出器示例，请在将要运行采集器的终端中设置以下变量：

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    将占位符替换为您服务的确切端点 (含端口) 和 API key。请使用基础 HTTP 端点，不要带 `/v1/logs` 后缀；导出器会自动追加信号路径。
  </Tab>

  <Tab title="自管理" id="self-managed">
    请使用采集器可访问的 OTLP HTTP 端点 (例如 `http://YOUR_COLLECTOR_HOST:4318`) 及相应的身份验证设置。如果您的采集器无需身份验证，请在下文配置中省略导出器的 `headers` 块。有关设置说明，请参阅[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

采集器容器必须能够访问该端点。如果目标端采集器运行在本机上，请使用 `http://host.docker.internal:4318`。下文的 Docker 命令已包含该主机映射。

## 与现有 CloudWatch 日志组集成 {#existing-cloudwatch}

<Steps>
  <Step title="配置 AWS 凭证" id="configure-aws">
    如果使用 AWS SSO，请先登录，然后在将用于启动采集器的终端中导出临时凭证：

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    将 profile 名称和区域替换为您自己的值。如果您已在使用环境凭证，请设置 `AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`，以及用于临时凭证的 `AWS_SESSION_TOKEN`，并同时设置 `AWS_REGION`。这些凭证用于授权读取 AWS 日志，与目标端的 OTLP 凭证相互独立。

    该 IAM 身份需要以下权限。请替换 `YOUR_REGION` 和 `YOUR_ACCOUNT_ID`；如有必要，可将日志组资源的范围限定为您要采集的日志组：

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    列出可用的日志组，从中选择要在配置中使用的名称：

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="配置 CloudWatch 接收器" id="configure-receiver">
    将此文件保存为 `cloudwatch-logs.yaml`。将 `/aws/lambda/my-function` 替换为您账户中的某个日志组；如需添加其他日志组，请将其列在 `named` 下。

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    此配置会先读取最近一小时的日志，之后每分钟轮询一次。修改 `initial_lookback` 即可调整初始时间窗口。如果没有持久化的检查点存储，重启采集器后可能会重新读取该时间窗口内的日志，从而产生重复数据。

    如需改为按前缀发现日志组，请将 `groups` 块替换为：

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    `named` 和 `autodiscover` 二选一即可。如需了解其他选项 (包括持久化检查点) ，请参阅 [CloudWatch 接收器文档](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver)。
  </Step>

  <Step title="启动采集器" id="start-collector">
    将其保存为 `docker-compose.yaml`，并与 `cloudwatch-logs.yaml` 放在同一目录下：

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    在已设置 AWS 凭证和[连接变量](#connection-details)的终端中，启动采集器并查看其输出：

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="验证日志" id="verify-logs">
    在 ClickHouse Observability 中打开 **搜索**，选择您的 **Logs** source，并按 `ServiceName:cloudwatch` 进行过滤。选择 **Last 2 hours**，然后等待一到两个轮询间隔，日志即会出现。

    查找以下资源属性：

    * `aws.region`：AWS 区域
    * `cloudwatch.log.group.name`：日志组
    * `cloudwatch.log.stream`：日志流

    日志消息显示在 `Body` 中。该接收器会保留消息内容，但不会根据消息文本推断严重级别。如需使用基于严重级别的仪表盘面板，您的日志管道必须填充 `SeverityText`。
  </Step>
</Steps>

## 演示数据集 {#demo-dataset}

该样本数据集包含 12,785 条日志，涵盖 24 小时内 Lambda、ECS 和后台作业的活动，其中包括日志组、日志流和严重级别值。采用此方式无需 AWS 凭证，也无需直接访问数据库。

<Steps>
  <Step title="下载样本数据" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="配置演示采集器" id="configure-demo-collector">
    将以下内容保存到下载目录中，文件名为 `cloudwatch-demo.yaml`：

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      该演示配置会读取样本数据中的 ClickHouse 行格式，并还原日志正文、严重级别和属性。时间戳变换会将样本数据平移到大约过去 24 小时的范围内，截止于摄取前两分钟。采集您自己的日志时，请使用上文的 CloudWatch 接收器配置，以保留原始时间戳。
    </Note>
  </Step>

  <Step title="运行演示采集器" id="run-demo-collector">
    设置好[连接变量](#connection-details)后，在下载目录中运行以下命令：

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    在采集器读取并导出文件期间，请勿关闭终端，并留意输出中是否有错误。若再次启动一个新容器，可能会导致样本日志重复。
  </Step>

  <Step title="验证演示日志" id="verify-demo-logs">
    打开 **Search**，选择您的 **日志** source，按 `ServiceName:cloudwatch-demo` 过滤，并选择 **最近 2 天**。展开任意一条日志，查看其正文、严重级别、日志组和日志流。确认数据无误后，按 **Ctrl+C** 停止演示采集器。

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability 中的 CloudWatch 演示日志](/images/clickstack/observability-cloudwatch-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 故障排查 {#troubleshooting}

### 未显示日志 {#no-logs}

* 检查 `docker compose logs otel-collector` 的输出中是否存在 AWS 身份验证错误、访问被拒绝错误或 OTLP 导出错误。
* 确认 `AWS_REGION` 和日志组名称与您的账户一致，并确认这些日志组在 `initial_lookback` 时间范围内有事件，或在启动后有新事件写入。
* 检查是否具备 `logs:DescribeLogGroups` 和 `logs:FilterLogEvents` 的 IAM 权限。
* 对照[连接详情](#connection-details)核实目标端端点和身份验证设置。
* 检查 **日志** source、服务名称过滤器和时间范围。对于演示数据，请选择 **最近 2 天**。

### AWS 凭证已过期 {#expired-credentials}

如果使用 SSO，请重新登录并导出新的凭证，然后重新创建采集器，以便其获取新的环境变量：

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

仅重启现有容器并不会更新其凭证。如果使用的是其他类型的临时凭证，请先刷新访问密钥、私有访问密钥和会话令牌，然后再重新创建该容器。

### 缺少较早的日志 {#older-logs}

该示例默认回溯一小时。可以调大 `logs.initial_lookback`，或改用 `logs.start_from` 并通过 RFC3339 格式的时间戳指定具体的开始时间。请勿同时设置两者。修改采集器配置后需重启采集器；注意，重新读取同一时间窗口可能会产生重复数据。
