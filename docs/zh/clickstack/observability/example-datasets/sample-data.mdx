借助某电商网站的样本日志、会话、链路追踪和指标数据，探索 ClickHouse Observability。两种部署模式使用相同的数据集和调查工作流。

开始之前，请先完成[全托管入门指南](/zh/clickstack/observability/getting-started)或[自管理入门指南](/zh/clickstack/self-configured/getting-started/managed)。

<Steps>
  <Step title="配置连接" id="configure-your-connection">
    选择部署方式，并在将用于加载样本数据的终端中设置以下变量。

    <Tabs>
      <Tab title="全托管">
        <BetaBadge label="Beta 服务" />

        打开 **团队设置 → 数据**，找到 **Managed Telemetry**。在 **OpenTelemetry 收集器** 下，通过 **URL** 选项复制 OTLP HTTP 端点和 API key。选择 **Reveal key** 即可查看完整值。

        设置基准端点时不要包含信号路径 (例如 `/v1/logs`) ，并在授权值中加上 `Bearer` 前缀：

        ```shell
        export CLICKSTACK_OTLP_ENDPOINT='<your-managed-otlp-http-endpoint>'
        export CLICKSTACK_AUTHORIZATION='Bearer <your-api-key>'
        ```

        本示例无需部署采集器。
      </Tab>

      <Tab title="自管理" id="self-managed">
        您需要一个正在运行、且已连接到 ClickHouse Cloud 服务的 ClickStack OpenTelemetry 采集器。请参阅[使用 OpenTelemetry 摄取指南](/zh/clickstack/observability/ingesting-data/opentelemetry#self-managed)配置连接，或参阅[部署指南](/zh/clickstack/self-configured/deployment/managed)启动采集器。

        设置采集器的 OTLP HTTP 端点，该端点须能从运行上传命令的机器访问。请使用不含信号路径 (例如 `/v1/logs`) 的基准 URL：

        ```shell
        export CLICKSTACK_OTLP_ENDPOINT='http://<collector-host>:4318'
        export CLICKSTACK_AUTHORIZATION=''
        ```

        如果采集器需要身份验证，请将 `CLICKSTACK_AUTHORIZATION` 设置为其接收器令牌。对于通过 `OTLP_AUTH_TOKEN` 保护的 ClickStack 采集器，请直接使用该值，无需添加 `Bearer` 前缀。如果接收器不需要身份验证，请将该值留空。请勿在此处使用 ClickHouse 数据库密码。
      </Tab>
    </Tabs>
  </Step>

  <Step title="下载样本数据" id="download-sample-data">
    如需在 UI 中填充样本数据，请下载以下文件：

    [样本数据](https://storage.googleapis.com/hyperdx/sample.tar.gz)

    ```shell
    # curl
    curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
    # or
    # wget https://storage.googleapis.com/hyperdx/sample.tar.gz
    ```

    该文件包含来自我们公开的 [OpenTelemetry Demo](https://github.com/ClickHouse/opentelemetry-demo) 的示例日志、指标和链路追踪数据。该演示是一个基于微服务架构的简易电商商店。请将该文件复制到您指定的目录中。
  </Step>

  <Step title="加载样本数据" id="load-sample-data">
    在 `sample.tar.gz` 所在的目录中，使用 **Bash** 运行以下命令。这些命令会将样本数据发送到上文配置的端点，并仅在需要时添加授权请求头。

    ```bash
    set -eo pipefail

    auth_headers=()
    if [ -n "${CLICKSTACK_AUTHORIZATION:-}" ]; then
      auth_headers=(-H "Authorization: ${CLICKSTACK_AUTHORIZATION}")
    fi

    for filename in $(tar -tf sample.tar.gz); do
      endpoint="${CLICKSTACK_OTLP_ENDPOINT%/}/v1/${filename%.json}"
      echo "loading ${filename%.json}"
      tar -xOf sample.tar.gz "$filename" | while read -r line; do
        printf '%s\n' "$line" | curl --fail-with-body -sS -X POST "$endpoint" \
          -H "Content-Type: application/json" \
          "${auth_headers[@]}" \
          --data-binary @-
      done
    done
    ```

    这将模拟 OTLP 日志、trace 和指标数据源发送数据。在生产环境中，这些数据源可能是应用程序 SDK、agent 或 OpenTelemetry 收集器。

    在 ClickHouse Cloud 控制台中，选择您的服务并打开 ClickHouse Observability。

    返回[搜索](/zh/clickstack/observability/features/search)页面查看已加载的数据。选择 **Logs** source，并将时间范围设置为涵盖样本事件的时间戳。下方截图展示了样本日志陆续进入 **Live Tail** 的情况：

    <div className="ch-image-lg">
      <Frame>
        ![搜索页面显示从电商演示服务加载的样本日志](/images/clickstack/getting-started/observability-sample-data-search.png)
      </Frame>
    </div>

    数据加载需要几分钟时间，请等待加载完成后再执行后续步骤。
  </Step>

  <Step title="探索会话" id="explore-sessions">
    假设我们收到反馈，称用户在购买商品付款时遇到问题。我们可以借助会话回放来查看他们的实际操作过程。

    从左侧菜单中选择 **Client Sessions**，并将时间范围设置为包含已加载样本会话的区间。

    <div className="ch-image-lg">
      <Frame>
        ![Client Sessions 显示样本会话，并突出显示错误计数](/images/clickstack/getting-started/observability-sample-data-sessions.png)
      </Frame>
    </div>

    该视图列出了演示商店中的会话，包括匿名会话以及通过电子邮件地址识别的会话。

    部分会话的错误计数不为零。在本示例中，突出显示的会话有一个错误。

    选择突出显示的会话以打开其回放，然后点击播放器底部的播放按钮观看该会话。

    <div className="ch-image-lg">
      <Frame>
        ![会话回放显示 OpenTelemetry Demo 店面及导航事件](/images/clickstack/getting-started/observability-sample-data-replay.png)
      </Frame>
    </div>

    回放展示了用户浏览网站并将商品加入购物车的过程。您可以直接跳到会话后段，即用户尝试完成付款的部分。

    <Tip>
      错误事件在事件列表中以红色标出。
    </Tip>

    滚动到左侧事件列表底部。突出显示的 `POST /api/checkout` 请求返回了 HTTP `500`，同一时刻还记录了一条控制台错误。

    <div className="ch-image-lg">
      <Frame>
        ![会话回放突出显示发往 /api/checkout 的失败 POST 请求及相关控制台错误](/images/clickstack/getting-started/observability-sample-data-checkout-error.png)
      </Frame>
    </div>

    选择失败的 `POST /api/checkout` 事件，查看该请求及其 trace。
  </Step>

  <Step title="探索链路追踪" id="explore-traces">
    打开 **Trace** 选项卡，查看分布式 trace，其中包括相关的 span 和关联的日志。

    <div className="ch-image-lg">
      <Frame>
        ![链路追踪瀑布图，显示 checkout 请求及其 span、关联的日志和错误](/images/clickstack/getting-started/observability-sample-data-trace.png)
      </Frame>
    </div>

    在该 trace 中向下滚动，选择 `checkout` 服务中的 `oteldemo.PaymentService/Charge` 跨度。

    <div className="ch-image-lg">
      <Frame>
        ![已选中的支付请求跨度，其属性中显示信用卡已过期错误](/images/clickstack/getting-started/observability-sample-data-payment-span.png)
      </Frame>
    </div>

    在 **Overview** 选项卡中查看 **Top Level Attributes**。可以看到 `StatusCode` 为 `Error`，`StatusMessage` 表明信用卡已过期。

    <div className="ch-image-lg">
      <Frame>
        ![概览属性显示 Error 状态以及信用卡已过期的消息](/images/clickstack/getting-started/observability-sample-data-span-attributes.png)
      </Frame>
    </div>

    在该 trace 中，选择支付服务跨度下方的 `payment` 错误日志。该行带有日志图标，可借此与错误跨度事件区分开来。在 **Overview** 中，该日志的 **Body** 确认信用卡已过期。其属性标明了 `payment` 服务和 `error` 严重级别，为 trace 提供了补充上下文。

    <div className="ch-image-lg">
      <Frame>
        ![关联的支付错误日志，显示信用卡已过期的消息及日志属性](/images/clickstack/getting-started/observability-sample-data-correlated-log.png)
      </Frame>
    </div>

    至此，我们已追踪到这次结账失败的原因：支付请求因信用卡已过期而被拒绝。
  </Step>

  <Step title="探索日志" id="explore-logs">
    如需排查其他支付失败问题，请返回 [搜索](/zh/clickstack/observability/features/search)。

    选择 **Logs** 作为 source，并在 **ServiceName** 过滤器中选择 `payment`。所选时间范围需涵盖您排查过的会话。

    <div className="ch-image-lg">
      <Frame>
        ![按 payment 服务过滤后的搜索结果，显示卡已过期错误、Visa 缓存已满错误以及成功的事务](/images/clickstack/getting-started/observability-sample-data-payment-logs.png)
      </Frame>
    </div>

    结果中既有我们排查过的会话中出现的卡已过期错误，也有反复出现的 `Visa cache full: cannot add new item.` 错误。如需了解 payment 服务中错误出现的时间分布，可将这些错误日志按时间绘制成图表。
  </Step>

  <Step title="绘制支付错误图表" id="chart-payment-errors">
    打开 **Chart Explorer**，选择 **Time Series**，并将 **Logs** 设为数据源。聚合方式选择 **Count of Events**。

    在 **Where** 中选择 **Lucene**，然后输入以下过滤条件：

    ```text
    SeverityText:"error" ServiceName:"payment"
    ```

    设置一个覆盖样本数据的时间范围，然后点击 **运行**。

    <div className="ch-image-lg">
      <Frame>
        ![在 Chart Explorer 中使用 Lucene 过滤器按时间统计 payment 服务的错误日志](/images/clickstack/getting-started/observability-sample-data-payment-errors-chart.png)
      </Frame>
    </div>

    该图表显示每个时间间隔内匹配的错误日志数量，涵盖 `payment` 服务的所有错误，包括银行卡已过期和缓存已满等错误。注意，这里统计的是日志事件的计数，而非唯一失败支付的数量。
  </Step>
</Steps>
