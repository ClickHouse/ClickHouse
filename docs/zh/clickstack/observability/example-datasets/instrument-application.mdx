      **TL;DR**

      克隆 [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)，在 `.env` 中填入托管 OTLP HTTP 端点和 API key，然后粘贴 agent 提示词即可。后端代码无需导入任何 OpenTelemetry 依赖；agent 会在进程启动时自动接入 `@hyperdx/node-opentelemetry`。

      所需时间：约 10 分钟
    </Note>

    HackerNews Analyzer 是一个 Node.js 应用，用于查询托管在 ClickHouse 公共演示环境中的 HackerNews 数据集。在仪表盘中进行的交互会向后端发起请求。未命中应用缓存的请求还会查询 ClickHouse，从而在 trace 中新增一个出站 HTTPS 跨度。

    该演示将后端自动插桩、ClickHouse 查询 span 和浏览器会话回放整合到了同一个应用中。

## 前置条件 {#prerequisites}

    * 与 [HackerNews Analyzer 及其依赖项](https://github.com/ClickHouse/hn-news-analyzer#readme) 兼容的 Node.js 和 npm 版本。
    * 已有的全托管 ClickHouse Observability 服务。请参阅[全托管入门指南](/zh/clickstack/observability/getting-started)。
    * 应用服务器和你的浏览器均可通过网络访问托管遥测数据端点。

## 克隆代码仓库 {#clone-the-repository}

    克隆 [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) 仓库，安装依赖项，然后复制 env 模板文件：

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    你将在后续步骤中填写 `.env` 文件，然后在此目录下进行插桩。

      <Step title="配置环境" id="configure-environment">
        打开您的 ClickHouse Observability 服务，进入 **团队设置 → Managed Telemetry**，复制 **OTLP HTTP 端点** 和 **API key**。

        <div className="ch-image-lg">
          <Frame>
            ![团队设置中的 Managed Telemetry 页面，显示已脱敏的 OTLP HTTP 端点和 API key](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        在应用的 `.env` 文件中设置以下配置值，并将其中的端点和 API key 占位符替换为实际值：

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        请保留 `OTEL_EXPORTER_OTLP_ENDPOINT` 中的 `https://` 前缀，且不要追加 `/v1/logs`、`/v1/traces` 或 `/v1/metrics`，SDK 会自动追加各信号对应的路径。将 `OTEL_EXPORTER_OTLP_HEADERS` 设置为 `authorization=<your-api-key>`，不要添加 `Bearer` 前缀；应用还会将该 API key 直接传给浏览器 SDK。

        浏览器 SDK 使用相同的端点和 API key。`vite.config.ts` 会将它们嵌入浏览器打包产物中，访问者可以查看到这些内容。因此，请使用专门用于测试此演示的服务，并确保不要将 `.env` 纳入版本控制。
      </Step>

          <Tab title="手动插桩" id="instrument-manually">
            插桩分为三步：安装 SDK、切换启动命令、启用浏览器 SDK。整个过程不会改动应用程序的业务逻辑。

### 安装 Node SDK {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### 在 run.sh 中启用包装器 {#enable-run-sh-wrapper}

            `run.sh` 末尾有两行 `exec`。注释掉普通的 `node` 那一行，并取消注释插桩版本的那一行：

            ```diff
             # 之前：普通 node，无插桩：
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # 之后：相同源码，由 opentelemetry-instrument 包装：
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            请仍通过 `scripts/entrypoint.js` 启动。该垫片会调用 `require('console')`，使控制台捕获能够包装 `console.log`。如果让 `opentelemetry-instrument` 直接指向 `dist/server/index.js`，链路追踪数据虽能正常发送，日志却会被静默丢弃。

### 启用浏览器 SDK {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            在 `src/web/telemetry.ts` 中，取消注释 import 语句、`HyperDX.init` 代码块以及 `recordAction` 中的 `HyperDX.addAction`：

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` 和 `__OTLP_AUTH_TOKEN__` 是由 `vite.config.ts` 注入的编译期常量，其取值与后端使用的 `OTEL_EXPORTER_OTLP_*` 配置值相同。
          </Tab>

    HackerNews Analyzer 是一个 Node.js 应用，用于查询托管在公共 ClickHouse 演示环境中的 HackerNews 数据集。每个图表、表格和搜索框背后都是一条真实的 ClickHouse 查询，因此每次交互都会生成一条 trace，其主跨度是后端向 ClickHouse 发起的 HTTPS 调用。

    本演示与[会话回放演示](/zh/clickstack/observability/example-datasets/session-replay)的侧重点不同：后者对纯浏览器应用进行插桩，并将遥测数据发送到 ClickHouse Observability；而本演示可在同一个应用中同时获得后端自动插桩、ClickHouse 查询跨度和会话回放。

## 前置条件 {#prerequisites-self-configured}

    * Node 18+ 和 npm
    * 一个现有的自管理 ClickHouse Observability 服务，以及一个正在运行的摄取采集器。
    * 采集器的 OTLP HTTP 端点，且应用服务器和您的浏览器均可访问该端点。仅当采集器与应用运行在同一台机器上时，才使用 `http://localhost:4318`。
    * 采集器的 `OTLP_AUTH_TOKEN` (如已配置) 。将请求头设置为 `authorization=<token>`，无需添加 `Bearer` 前缀。如果采集器不要求身份验证，请将 `authorization=` 留空。这些是采集器的摄取凭证，而非您的 ClickHouse 数据库凭证。
