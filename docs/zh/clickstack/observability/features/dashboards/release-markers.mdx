当延迟或错误突然飙升时，人们首先想知道的通常是：是不是刚上线了什么改动？仪表盘时间图表可以就地给出答案：开启发布标记后，每个卡片都会在服务某个版本首次出现在其遥测数据中的时刻绘制一条垂直虚线。

这些版本信息来自您已在发送的遥测数据，通过卡片 source 上的表达式读取。无需接入任何 CI 集成，部署时也无需额外推送任何内容。

## 开启标记 {#turn-on}

发布标记默认处于关闭状态。打开仪表盘的溢出菜单，选择 **Show release markers**。

<div className="ch-image-sm">
  <Frame>
    ![仪表盘溢出菜单，View 部分下的 Show release markers 选项位于 Show alert annotations 下方](/images/clickstack/dashboards/release-markers-menu.webp)
  </Frame>
</div>

该开关会在仪表盘 URL 中添加 `releaseMarkers=true`，因此您共享的链接打开时标记即已开启。它属于视图状态，而非仪表盘配置：不会随仪表盘一起保存，关闭后该参数也会随之移除。

标记会绘制在 source 为日志或链路追踪数据源的时间序列卡片上。[告警注解](/zh/clickstack/observability/features/alerts)同样在该菜单中开启，并可同时显示——两组标记会叠加绘制，且各自保留自己的标签。

## 配置版本信息的来源 {#version-expression}

默认情况下，ClickHouse Observability 会读取 OpenTelemetry 资源属性 `ResourceAttributes['service.version']`。如果您的服务遵循 [service 资源语义约定](https://opentelemetry.io/docs/specs/semconv/registry/attributes/service/)，则无需任何设置即可使用标记。

如需从其他位置读取版本，请在日志或链路追踪数据源上设置 **Service Version Expression**。可在 **Team Settings → Sources** 下编辑该 source。对于日志 source，该字段需展开 **Configure Optional Fields** 才能看到；对于链路追踪数据源，该字段直接显示在表单中，位于 **Service Name Expression** 下方。

<div className="ch-image-lg">
  <Frame>
    ![日志 source 可选字段中的 Service Version Expression 字段，显示默认占位符 ResourceAttributes\['service.version'\]](/images/clickstack/dashboards/service-version-expression.webp)
  </Frame>
</div>

该值是一个 SQL 表达式，而非属性名称，因此可以涵盖以下两种常见情况：

* **发行版标识位于其他属性中。** 在 GitOps 模式下，用于标识发行版的通常是容器镜像标签，以 `container.image.tag` 的形式上报。将 source 指向 `ResourceAttributes['container.image.tag']`，远比修改整个机群的插桩成本低。
* **同一张表中各服务的属性不一致。** 使用 `coalesce` 在多个属性之间依次回退：

```sql
coalesce(
  nullIf(ResourceAttributes['service.version'], ''),
  nullIf(ResourceAttributes['container.image.tag'], '')
)
```

该字段在 [sources API](/zh/clickstack/observability/api-reference) 中也以 `serviceVersionExpression` 的形式提供，适用于日志和链路追踪数据源，因此通过编程方式预配 source 时也可以设置它。对于自管理部署，请参阅[日志](/zh/clickstack/self-configured/managing/config#logs)和[链路追踪](/zh/clickstack/self-configured/managing/config#traces)的完整 source 设置列表。

## 标记的含义 {#what-a-marker-means}

标记表示某个版本值在可见时间窗口内首次出现在该卡片的数据中。这与部署非常接近，但有意不作同等表述，这也是它们被称为发布标记而非部署标记的原因：

* 如果一次部署没有更改版本字符串，则根本不会产生标记。
* 如果某个服务的空闲时间超过回溯时长，则在其重新扩容时会绘制一个标记。

窗口开始时已在运行的版本会被识别并舍弃，而不会被绘制成一次从未发生过的发布。为此，查询会从窗口起始时间再向前回溯 30 分钟或窗口长度的 10% (取较长者) ，以找出当时正在运行的版本。

## 卡片显示哪些发行版 {#scoping}

发行版查询基于卡片自身的 source 运行，并沿用卡片自身的谓词：其 `WHERE` 子句、每个数据系列的过滤器，以及所有[仪表盘筛选条件](/zh/clickstack/observability/features/dashboards/overview#custom-filters)。卡片显示哪些标记，取决于它绘制的内容：

| 卡片        | 标记                          |
| :-------- | :-------------------------- |
| 筛选为单个服务   | 该服务的发行版                     |
| 按服务分组     | 所有已绘制服务的发行版，每个标记的颜色与其对应的线一致 |
| 跨多个服务的聚合线 | 无，除非该时间窗口内的所有发行版均来自同一服务     |

在第三种情况下，标记所属的服务在图表上没有可对应的线，因此不会显示这些标记。但如果该时间窗口内的所有发行版均来自同一服务，则仍会以默认标记颜色绘制这些标记。

## 在密集的图表上读取标记 {#reading-markers}

将鼠标悬停在标记的标签上，即可列出该时间点的所有发行版，每条均显示发布该版本的服务、版本号及时间。

<div className="ch-image-sm">
  <Frame>
    ![在包含两个服务的图表上，发布标记的悬停工具提示显示服务 frontend、版本 2.0.2 以及该版本首次出现的时间](/images/clickstack/dashboards/release-marker-tooltip.webp)
  </Frame>
</div>

颜色可将标记与其所属的数据系列对应起来，但图表图例最多只显示四个条目，其余条目会折叠为“+N more”，此时屏幕上便无从对照颜色。工具提示会直接给出服务名称，因此无论卡片中绘制了多少个数据系列，都能准确识别。

距离过近、无法单独标注的标记会合并为一个带标签的锚点，显示为 `N releases`；将鼠标悬停在其上即可列出全部发行版。跨越多个服务的标记群组会以中性颜色绘制，而不会沿用其中某个服务的颜色，既能保证计数准确，又不会让人误以为它归属于某个服务。

显示标记时，在绘图区域内横向拖动仍可缩放。

## 限制 {#limitations}

* **仅支持时间序列卡片。** 表格、数值和热力图卡片不会绘制标记。
* **仅支持日志和链路追踪数据源。** 指标 source 会按指标类型分别解析对应的表，因此没有单一的表可供重新聚合，卡片的筛选条件也无法对其产生实际作用。如需为指标数据添加标注，请在同一仪表盘中，在其旁边放置一个日志或 trace 卡片。
* **空版本值会被跳过。** 未上报版本的服务不会产生任何标记。如果某个卡片完全未发现版本变更，UI 会显示 `No releases found`，以免您误以为该功能出现故障。
* **每个窗口最多读取 500 个不同版本。**
