ClickHouse Observability 支持对事件进行可视化，并在 UI 中内置了图表功能。您可以将这些图表添加到仪表盘中，与其他用户共享。

您可以基于链路追踪、指标、日志或任意用户自定义的宽事件 schema 创建可视化。

## 创建可视化 {#creating-visualizations}

借助 **Chart Explorer** 界面，您可以直观呈现指标、链路追踪和日志随时间的变化，快速创建可视化以进行数据分析。创建仪表盘时也会复用此界面。下文将逐步介绍如何使用 Chart Explorer 创建可视化。

每个可视化都需先选择一个**数据源**，再选择一个**指标**，并可按需添加**过滤表达式**和**分组依据**字段。从概念上讲，可视化在底层对应一条 SQL `GROUP BY` 查询——即定义要在所选维度上聚合的指标。

<Tip>
  **AI 驱动的图表和仪表盘生成**

  ClickHouse Observability 还支持通过 [text-to-chart](/zh/clickstack/observability/text-to-chart) 功能，根据自然语言提示创建图表。只需描述您想查看的内容，UI 即可自动生成可视化。如需生成包含多个卡片的完整仪表盘，请使用 [Text-to-Dashboard](/zh/clickstack/observability/text-to-dashboard)。
</Tip>

例如，您可以按服务名称分组，绘制错误数量 (`count()`) 的图表。

以下示例使用 [sql.clickhouse.com](https://sql.clickhouse.com) 上提供的远程数据集。**您也可以访问 [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) 来复现这些示例。**

## 创建仪表盘 {#creating-dashboards}

仪表盘可将相关的可视化组织在一起，便于您并排比较指标、探索模式，进而定位系统中问题的潜在根本原因。仪表盘既可用于即席调查，也可保存下来用于持续监控。

全局筛选器可在仪表盘级别应用，并自动作用于该仪表盘中的所有可视化。这样即可在各图表之间进行一致的下钻，并简化跨服务、跨遥测类型的事件关联分析。

下面我们将使用日志和 trace 数据源，创建一个包含两个可视化的仪表盘。您可以在 [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com) 上复现这些步骤，也可以在本地连接托管于 [sql.clickhouse.com](https://sql.clickhouse.com) 的数据集进行复现。

    添加热力图卡片的步骤如下：

    1. 选择 `Add`。
    2. 从顶部菜单中选择 `Heatmap` 可视化类型。数据源下拉列表仅显示 [source 类型为 `Traces`](/zh/clickstack/observability/managing/config#datasource-settings) 的数据源。日志、指标和会话数据源会被过滤掉，因为热力图需要 span 耗时列，而只有链路追踪数据源提供该列。

    选择数据源后，热力图会自动预填以下内容：

    * **Value**：数据源的 `Duration Expression`，并按当前显示单位进行换算 (例如 `(Duration)/1e6`，将每个事件的跨度耗时从纳秒转换为毫秒)
    * **Count**：`count()`

    4. 设置图表名称，并使用 `Where` 将热力图限定在您希望观察其性能的特定服务或一组操作上。
    5. 根据关注的时段调整时间范围。较宽的范围能够暴露分布偏移和双峰延迟模式，而较短的时间窗口可能会掩盖这些现象。

    如需进一步自定义热力图，请点击 **Display Settings** 打开抽屉面板，配置 **Scale** (Log 或 Linear) 、**Value** 和 **Count** 表达式。完整的选项说明请参阅事件差异页面中的[自定义热力图](/zh/clickstack/observability/features/event-deltas#customize)，两处使用的是同一个抽屉面板。

    点击 `Run` 预览图表，然后点击 `Save`。

        ![热力图编辑器，显示带有 ServiceName 过滤器和 Display Settings 按钮的 payment 服务 span 耗时](/images/clickstack/observability-dashboard-heatmap-editor.png)
      </Frame>
    </div>

    保存后，该卡片会在仪表盘上渲染为热力图。将鼠标悬停在任意单元上，即可查看该桶的范围和事件数量。

### 卡片显示设置 {#tile-display-settings}

每个卡片都有一个 **Display Settings** 抽屉面板，其中的选项用于控制卡片中数值的显示方式。在卡片编辑器中点击 **Display Settings** 即可打开该面板。可用选项因可视化类型而异。

#### 数值卡片颜色 {#number-tile-color}

数值卡片支持从精选的图表调色板中选择静态 **Color**。选中数值卡片后，打开 **Display Settings**，使用 **Color** 控件 (其无障碍标签为 **Number tile color**) 选择色块；若清除所选颜色，则使用默认文本颜色。

颜色以调色板标记而非原始十六进制值的形式存储，因此同一卡片在浅色、深色和 IDE 主题之间切换时都能正确显示。

**分类标记** (用于多数据系列的色相) ：

| 标记                 | 标签  |
| ------------------ | --- |
| `chart-blue`       | 蓝色  |
| `chart-orange`     | 橙色  |
| `chart-red`        | 红色  |
| `chart-cyan`       | 青色  |
| `chart-green`      | 绿色  |
| `chart-pink`       | 粉色  |
| `chart-purple`     | 紫色  |
| `chart-light-blue` | 浅蓝色 |
| `chart-brown`      | 棕色  |
| `chart-gray`       | 灰色  |

**语义标记** (用于表示状态) ：

| 标记              | 标签 |
| --------------- | -- |
| `chart-success` | 成功 |
| `chart-warning` | 警告 |
| `chart-error`   | 错误 |

当数值表示某种状态时，请使用语义标记 (例如用 `chart-error` 显示错误数，用 `chart-success` 显示健康比率) 。如果希望在相关 KPI 卡片之间形成视觉区分，又不想暗示状态，请使用分类标记。

较早的 config 可能仍存储旧版数字标记 (`chart-1` 至 `chart-10`) 。UI 在加载仪表盘时会将其映射为上述以色相命名的标记。

同一抽屉面板中的可选**颜色规则**也使用这套调色板：这些规则是按顺序针对显示值求值的条件 (以最后一个匹配项为准) 。如果没有规则匹配，则应用静态颜色；若未设置静态颜色，则使用默认文本颜色。

#### 数值卡片背景图表 {#number-tile-background-chart}

数值卡片可以显示**背景图表**：在数值后方绘制一条趋势迷你线图，让您一眼看出该数值在所选时间范围内的变化。这对 SLO 和错误预算卡片尤其有用，因为在这类场景中，数值的变化趋势与当前读数同样重要。

选中数值卡片后，打开 **Display Settings**，将 **Background chart** 设置为 **Line** 或 **Area** (设置为 **None** 则关闭) 。迷你线图由卡片查询按时间分桶后的结果生成，因此无需额外配置。默认情况下，它沿用卡片颜色；如需改用调色板中的特定颜色，请设置 **Background color** 进行覆盖。

<div className="ch-image-lg">
  <Frame>
    ![数值卡片的 Display Settings 抽屉面板，其中 Background chart 设置为 Area](/images/clickstack/dashboards/number-tile-background-chart.webp)
  </Frame>
</div>

背景图表适用于通过查询构建器创建的数值卡片。原始 SQL 数值卡片只返回单个值，没有可供分桶的时间维度，因此该选项虽然可见，但处于禁用状态。

表格卡片可以通过 **Alternate Row Background** 为行添加条纹效果，即隔行着色，让宽表更易于扫视。该功能默认关闭。

选中表格卡片后，打开 **Display Settings** 并开启 **Alternate Row Background**。条纹效果仅影响视觉呈现，因此同时适用于查询构建器和原始 SQL 表格卡片。

<div className="ch-image-lg">

此外，表格卡片在滚动时会在表头与数据之间保留分隔线，使列标题始终清晰可辨。

#### 仪表盘 API：数值卡片颜色 {#api-number-tile-color}

通过外部 API (`POST` / `PUT` `/api/v2/dashboards`) 创建或更新仪表盘时，请将构建器数值卡片 config 中的 `color` 设为调色板标记。原始十六进制值将被拒绝。

```json
{
  "name": "Error rate KPIs",
  "tiles": [
    {
      "id": "65f5e4a3b9e77c001a222222",
      "name": "Errors",
      "x": 0,
      "y": 0,
      "w": 6,
      "h": 4,
      "config": {
        "displayType": "number",
        "sourceId": "<SOURCE_ID>",
        "select": [
          {
            "aggFn": "count",
            "where": "SeverityText:error",
            "whereLanguage": "lucene",
            "alias": "Errors"
          }
        ],
        "color": "chart-error",
        "backgroundChart": {
          "type": "area"
        }
      }
    }
  ]
}
```

`color` 可接受上文 categorical 列表和语义列表中的任意标记 (例如 `chart-blue` 或 `chart-success`) 。可选参数 `backgroundChart.color` 使用同一组标记枚举值来覆盖迷你线图的颜色。有关身份验证和基准 URL 的信息，请参阅 [API 参考文档](/zh/clickstack/observability/api-reference)。

## 仪表盘 - 标签 {#tagging}

您可以为仪表盘和保存的搜索添加标签，以便更好地进行组织管理。
标签提供了一种灵活的方式，可按需对内容进行分类和筛选。

#### 标签的工作原理 {#how-tags-work}

* **组织方式**：标签显示在左侧边栏中，仪表盘和保存的搜索会按其分配的标签分组显示
* **多个标签**：您可以为单个条目添加一个或多个标签，便于更好地分类
* **自动创建**：如果您分配的标签尚不存在，系统会自动创建该标签
* **便捷管理**：您可以随时添加或移除标签，灵活调整组织结构

这样，即使条目越来越多，您也能轻松找到相关内容，让工作区始终井然有序。

### 过滤器类型 {#filter-types}

过滤器对话框中的 **类型** 选择器决定过滤器的值从何而来，以及这些值如何传递到各个卡片。

| 类型                                         | 值来源                                            | 广播      | 变量                                              |
| ------------------------------------------ | ---------------------------------------------- | ------- | ----------------------------------------------- |
| [SQL 表达式值](#sql-expression-values-filters) | 从某个 source 中查询出的表达式不同值                         | 可选，默认启用 | 可选                                              |
| [静态值](#static-values-filters)              | 手动编写的列表                                        | 否       | 始终                                              |
| [SQL 查询值](#sql-query-filters)              | SQL 查询结果的第一列                                   | 否       | 始终                                              |
| [PromQL 标签值](#promql-label-filters)        | Prometheus 标签的值                                | 否       | 始终                                              |
| [临时键和值](#adhoc-filters)                    | 基于一个或多个 source 的键和值构建的 `key operator value` 条件 | 始终      | 否                                               |
| [数据源](#data-source-variables)              | 团队的数据源                                         | 否       | 始终，作为 [source 引用](#source-connection-variables) |
| [连接](#connection-variables)                | 团队的 ClickHouse 连接                              | 否       | 始终，作为 [连接引用](#source-connection-variables)      |

#### SQL 表达式值 {#sql-expression-values-filters}

其下拉列表会列出所选**数据源**中**过滤表达式**的不同值，并可通过**下拉列表值过滤器**进一步缩小范围。对于指标数据源，还需选择**指标类型**。SQL 表达式值筛选器可以[广播](#broadcast-filters)其选中值，也可以[作为变量使用](#dashboard-variables)，或两者兼具。

#### 静态值 {#static-values-filters}

其下拉列表中的值由手动输入。在 **选项** 中逐个输入值，每输入一个值后按 Enter。每个筛选条件最多可包含 1000 个选项。

静态值筛选条件始终作为变量使用，不会广播，因此内容块需要引用其变量才能使用它，例如 `$__filter(SeverityText, $severity)`。这适用于未存储在列中的值，或需要使用经过筛选的固定值列表的场景。

#### SQL 查询值 {#sql-query-filters}

其下拉列表会列出 ClickHouse SQL 查询返回的第一列，顺序与查询返回行的顺序一致，最多 10,000 个值。需配置以下各项：

* **连接** — 运行该查询所用的 ClickHouse 连接，或一个[连接变量](#connection-variables)。
* **Source** — 可选。同一连接上的某个 source，或一个[数据源变量](#data-source-variables)。选定 source 后，查询中可以使用 `$__sourceTable` 和 `$__filters`，后者会应用仪表盘中针对该 source 的广播筛选选项，方式与[原始 SQL 卡片](/zh/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro)相同。
* **SQL 查询** — 查询本身。可以使用[时间宏](/zh/clickstack/observability/features/dashboards/sql-visualizations#time-filter-macros)，也可以引用仪表盘中的其他变量。编辑器会预览该查询在仪表盘当前时间范围内返回的值。

例如，以下查询会列出在仪表盘时间范围内有事件记录的服务，并仅限于 `environment` 筛选器中所选的环境：

```sql
SELECT DISTINCT ServiceName
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ResourceAttributes['deployment.environment'], $environment)
ORDER BY ServiceName
```

SQL 查询值过滤器始终作为变量使用，不会进行广播。

#### PromQL 标签值 {#promql-label-filters}

<PrivatePreviewBadge />

此类筛选器的下拉列表会列出某个 Prometheus 标签的所有值。选择一个 PromQL **数据源**，然后输入 **Label**，下拉列表将由该标签的值填充，例如 `job`、`instance` 或 `__name__`。还可以选择填写 **Series matchers**，即一个 Prometheus 数据系列选择器 (例如 `up{job="api"}`) ，用于限定从哪些数据系列中读取这些值。Series matchers 中可以引用仪表盘中的其他变量。

PromQL 标签值筛选器始终作为变量使用，不会进行广播。在 PromQL 卡片中，请在标签匹配器内引用它，例如 `rate(http_requests_total{job=~"$job"}[$__rate_interval])`。有关值的渲染方式，请参阅[引用变量](#referencing-variables)。

#### 临时键和值 {#adhoc-filters}

临时过滤器不提供单一的下拉列表，而是让查看者基于其数据源中的键构建一组 `key operator value` 条件：对于 SQL 数据源，键为列和 map 键；对于 Prometheus 数据源，键为标签。查看者输入时，系统会自动建议可用的键和值。需配置以下内容：

* **来源类型** — SQL (日志、trace 或会话数据源) 或 Prometheus。
* **数据源** — 过滤器从中获取建议键和值的数据源。
* **键和值筛选条件** — 可选，仅适用于 SQL 数据源。一个 SQL 或 Lucene 条件，用于限定从哪些行中提取建议的键和值。可引用仪表盘中的其他变量。
* **应用到的数据源** — 条件要广播到的数据源。留空则广播到所有使用该过滤器任一数据源的卡片。
* **唯一名称** — 用于在[仪表盘 URL](/zh/clickstack/observability/url-parameters#dashboard-filter-values) 中标识该过滤器的条件。

SQL 数据源上的条件支持以下运算符：`=`、`!=`、`=~` (正则表达式) 、`!~` (正则表达式) 、`LIKE`、`NOT LIKE`、`IN`。Prometheus 数据源上的条件支持 `=`、`!=`、`=~` (正则表达式) 、`!~` (正则表达式) 和 `IN`；`LIKE` 和 `NOT LIKE` 仅适用于 SQL。

查看者还可以点击仪表盘上表格、时间序列或搜索卡片中的某个值来添加条件。

临时条件始终会被广播，且不能作为变量引用。对应数据源上的图表构建器卡片和 PromQL 卡片会自动应用这些条件，原始 SQL 卡片则通过 [`$__filters` 宏](/zh/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro)应用它们。

#### 数据源 {#data-source-variables}

数据源变量可让查看者选择卡片查询的 source。设置下拉列表中可供选择的**数据源类型**，例如仅提供日志数据源；也可以将这些数据源限定在某个**连接**下，该连接本身也可以是连接变量。有关内容块和筛选条件如何使用此变量，请参阅[数据源和连接变量](#source-connection-variables)。

#### 连接 {#connection-variables}

连接变量可让查看者选择原始 SQL 卡片、SQL 查询值筛选条件以及数据源变量所使用的 ClickHouse 连接。除名称外，该变量没有其他设置。

### 数据源和连接变量 {#source-connection-variables}

数据源和连接变量代表的是 source 或连接 ID,而不是查询文本中的某个值。凡是支持此类变量的 source 或连接选择器,都会在 **Variables** 分组下列出仪表盘中的变量。选择其中一个变量后,会存储一个 `$name` 引用,该引用会解析为查看者当前所选的值。借助这一点,只需构建一个仪表盘,即可在多个环境的日志之间或多个 ClickHouse 集群之间来回切换。

| 使用位置           | 支持数据源变量                         | 支持连接变量     |
| -------------- | ------------------------------- | ---------- |
| 图表构建器卡片        | Source                          | —          |
| 原始 SQL 卡片      | Source                          | Connection |
| PromQL 卡片      | Source                          | —          |
| SQL 表达式值筛选条件   | Data source、Applies to sources  | —          |
| PromQL 标签值筛选条件 | Data source                     | —          |
| 临时筛选条件         | Data sources、Applies to sources | —          |
| SQL 查询值筛选条件    | Source                          | Connection |
| 数据源变量          | —                               | Connection |

只有当数据源变量至少有一种 source 类型适用时,才会提供该变量。例如,PromQL 卡片只会提供允许 PromQL source 的数据源变量。

数据源和连接变量始终为单选且必填,因为没有 source 或连接,卡片就无法执行查询。在选定值之前,引用该变量的卡片和筛选条件会一直处于等待状态。如需让整个仪表盘都等待,请启用 **Block every tile**。[仪表盘链接](/zh/clickstack/observability/url-parameters#dashboard-filter-values)既可以按 ID,也可以按名称选择 source 或连接。

<Note>
  使用数据源或连接变量的卡片不支持告警。保存此类卡片时,其告警会被移除。
</Note>

### 选择选项 {#filter-selection-options}

SQL 表达式值、静态值、SQL 查询值和 PromQL 标签值这几类筛选条件还提供以下选项：

* **单选** — 每次只能选择一个值。
* **必填** — 通过变量或广播使用该筛选条件的卡片，在筛选条件选定值之前不会加载。
  * **阻止所有卡片** — 在筛选条件选定值之前，阻止仪表盘上的所有卡片加载，而不仅限于使用该筛选条件的卡片。

### 链式筛选器 {#chained-filters}

筛选器自身的配置可以引用仪表盘中的其他变量，使其可选值取决于另一个筛选器的选中项。例如，服务筛选器可以只列出 `environment` 筛选器所选环境中的服务。可在以下位置引用变量：

* SQL 表达式值筛选器的 **Dropdown values filter**，例如 `$__filter(ResourceAttributes['deployment.environment'], $environment)`。
* SQL 查询值筛选器的 **SQL query**。
* PromQL 标签值筛选器的 **Series matchers**，例如 `up{env="$env"}`。
* 临时 (ad hoc) 筛选器的 **Keys and values filter**。
* source 和连接字段，通过[数据源和连接变量](#source-connection-variables)进行引用。

当被引用筛选器的选中项发生变化时，系统会重新查询依赖它的筛选器的值。如果被引用的必填筛选器尚未选择任何内容，依赖它的临时筛选器将无法添加或编辑条件，并会显示其正在等待的筛选器名称。

### 广播 {#broadcast-filters}

SQL 表达式值过滤器可以广播其选中的值，而临时 (ad hoc) 过滤器则始终会广播其条件。在 SQL 表达式值过滤器上启用 **Broadcast filter condition** 后，所选值会作为过滤条件应用到仪表盘的各个卡片上，卡片无需显式引用该过滤器。默认情况下，该条件会作用于所有卡片。可通过 **Applies to sources** 将其限定为仅作用于使用指定数据源的卡片；当过滤器的表达式只适用于仪表盘上的部分数据时，此选项尤为有用。

图表构建器卡片会自动应用广播过滤器。原始 SQL 卡片则必须包含 [`$__filters` 宏](/zh/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro)并选定一个 source，因为 UI 无法推断该条件应放在手写查询中的哪个位置。

### 变量 {#dashboard-variables}

静态值、SQL 查询值和 PromQL 标签值过滤器始终是变量。启用 **Available as variable** 后，SQL 表达式值过滤器会成为变量。变量以 `$variableName` 的形式将过滤器的选中值提供给卡片查询使用。**Variable name** 默认取过滤器的显示名称 (去除其中的非法字符) ，也可以自行覆盖。名称必须以字母开头，且只能包含字母、数字和下划线。

临时过滤器不会成为变量，而数据源变量和连接变量是[对 source 或连接的引用](#source-connection-variables)，而非查询文本中的值。

如果广播 `WHERE` 条件无法满足需求，请改用变量。例如，将该值用于 `SELECT` 表达式、`HAVING` 子句或连接键，或者按过滤器自身表达式以外的其他列来过滤卡片。

#### 引用变量 {#referencing-variables}

变量会展开为其下拉列表中当前选中的值。引用形式决定渲染方式：

| 引用形式                | 展开结果                                                                                    | 未选择时             |
| ------------------- | --------------------------------------------------------------------------------------- | ---------------- |
| `$name`, `${name}`  | 选中的值，根据上下文采用 `sqlstring` 或 `lucene` 格式。当名称后紧跟单词字符时 (如 `${name}_total`) ，需用花括号界定名称。      | `NULL`           |
| `${name:sqlstring}` | 选中的值，用单引号括起、以逗号分隔，并按 SQL 值进行转义，例如 `'a', 'b'`                                            | `NULL`           |
| `${name:csv}`       | 不加引号、以逗号分隔：`a,b`。不进行 SQL 转义。                                                            | 空字符串             |
| `${name:regex}`     | 经过正则转义的正则表达式多选分支：`(a\|b)`。                                                              | `.*`             |
| `${name:lucene}`    | 用 `OR` 连接的带引号词项，用于 Lucene 输入：`("a" OR "b")`。                                            | `("")`           |
| `${name:promql}`    | PromQL 内容块中的默认格式。对于单选过滤器，展开为选中的值，用于 `label="$name"`；否则展开为正则表达式多选分支，用于 `label=~"$name"`。 | `.*` (单选时为空字符串)  |

由于在未选择任何值时 `$name` 会渲染为 `NULL`，因此在需要 SQL 谓词的地方，建议使用以下宏。当对应变量未选择任何值时，这两个宏都会展开为 `1=1`，从而确保查询依然有效：

| 宏                                             | 描述                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | 当 `variable` 已选中值时，展开为 `toString(<filter expression>) IN ($variable)`，否则展开为 `1=1`。 |
| `$__filter(<expression>, $<variable>)`        | 当 `variable` 已选中值时，展开为 `<expression> IN ($variable)`，否则展开为 `1=1`。                  |
| `$__conditionalAll(<condition>, $<variable>)` | 当变量已选中值时，展开为 `<condition>`，否则展开为 `1=1`。                                            |

#### 在图表构建器卡片中使用变量 {#variables-in-builder-tiles}

图表构建器中的每个 SQL 表达式输入框都支持变量引用，包括 `SELECT` 列和各数据系列的表达式、`WHERE`、`GROUP BY` 以及 `HAVING`。编辑器会自动补全仪表盘中的变量，并显示每个引用在当前选择下展开后的内容。

在 SQL 模式下，建议优先使用 `$__filter` 和 `$__conditionalAll` 宏，这样即使变量未选择任何值，查询仍然有效。Lucene 输入框不支持宏，请在其中直接引用原始变量 (例如 `ServiceName:$service`) 。

在 Lucene 输入框中，变量引用本身是否用引号括起，决定了多值选择的匹配方式。假设 `$service` 的选择为 `a,b`：

| 引用                       | 展开为                                    | 匹配行为                                                                  |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------- |
| `ServiceName:$service`   | `ServiceName:("a" OR "b")`             | 子串匹配——转换为 SQL 后为 `ServiceName ILIKE '%a%' OR ServiceName ILIKE '%b%'` |
| `ServiceName:"$service"` | `(ServiceName:"a" OR ServiceName:"b")` | 对每个选中值进行精确匹配                                                          |

如果希望选中的值与 `Field` 精确匹配，而不是按子字符串匹配，请用引号括起变量引用，即 `Field:"$var"`。

#### 在 SQL 卡片中使用变量 {#variables-in-sql-tiles}

原始 SQL 卡片引用变量的方式与此相同，可在查询中的任意位置引用：

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

SQL 卡片可用宏的完整列表，请参阅[基于 SQL 的可视化](/zh/clickstack/observability/features/dashboards/sql-visualizations#dashboard-variables)。

<Note>
  如果卡片引用了仪表盘变量，则该卡片上的告警在评估时会将所有变量视为空值，而不会采用仪表盘上当前选定的值。
</Note>

## 下钻到搜索 {#drilldown-to-search}

仪表板卡片支持下钻到搜索页面。点击可视化中的任一数据点，即可打开包含以下选项的上下文菜单：

* **View All Events** — 跳转到搜索页面，显示所选时间窗口内的所有事件。
* **搜索** (数据系列旁的放大镜图标) — 打开该数据系列对应的搜索页面。
* **Copy label** — 复制该数据系列的标签。
* **Focus** — 在图表中聚焦所选数据系列。

## 预设 {#presets}

UI 内置了开箱即用的仪表盘。

### Services 仪表盘 {#services-dashboard}

Services 仪表盘基于链路追踪数据展示当前活跃的服务。使用前，您需要已采集链路追踪数据，并配置了有效的 Traces 数据源。

服务名称会从链路追踪数据中自动识别，同时提供一系列预置的可视化图表，分布在三个选项卡中：**HTTP Service**、**Database** 和 **Errors**。

可视化图表支持使用 Lucene 或 SQL 语法进行过滤，也可以调整时间窗口，以便进行更有针对性的分析。

### Kubernetes 仪表板 {#kubernetes-dashboard}

Kubernetes 数据分布在三个选项卡中，便于浏览：Pods、Nodes 和 Namespaces。
