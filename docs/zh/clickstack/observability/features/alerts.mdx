ClickHouse Observability 内置告警功能，帮助团队基于日志、指标和链路追踪实时发现并响应问题。

告警可直接在 UI 中创建，并可与 Slack、PagerDuty 等常用通知系统集成。

告警功能可无缝覆盖您的各类可观测性数据，帮助您跟踪系统健康状况、及时发现性能回归问题，并监控关键业务事件。

## 告警类型 {#types-of-alerts}

您可以基于**已保存的搜索**创建告警，也可以直接在 **Chart Explorer** 中创建，还可以基于**已保存仪表盘中的图表**创建。搜索告警统计匹配的事件数，而图表告警则对图表计算出的数值进行评估。

### 搜索告警 {#search-alerts}

搜索告警可根据已保存的搜索的结果触发通知，帮助您发现特定事件或模式的出现频率是否高于 (或低于) 预期。

当指定时间窗口内的匹配结果数量高于或低于设定的阈值时，即会触发告警。

创建搜索告警的步骤如下：

只有已保存的搜索才能创建告警。您既可以为现有的已保存的搜索创建告警，也可以在创建告警的过程中保存搜索。下面的示例假设该搜索尚未保存。

### Chart Explorer 告警 {#chart-explorer-alerts}

可直接在 [Chart Explorer](/zh/clickstack/observability/features/dashboards/overview#navigate-chart-explorer) 中创建告警，无需将图表添加到仪表盘即可对其进行监控。

<Steps>
  <Step title="构建图表" id="build-explorer-alert-chart">
    在侧边栏中选择 **Chart explorer**，并使用 **时间序列** 图表类型。选择数据源，然后配置要监控的聚合、筛选条件和分组。例如，统计错误日志数量并按 `ServiceName` 分组，从而对每个服务分别进行评估。

    选择 **Run**，在配置告警前先检查结果。
  </Step>

  <Step title="配置告警" id="configure-explorer-alert">
    选择 **Add alert**。对于 **Static threshold** 告警，请配置以下内容：

    * **Trigger when value**：选择比较运算符和阈值。
    * **over**：选择评估时间窗口，例如 5 分钟。
    * **Name**：为告警设置一个便于识别的名称。
    * **Send to**：选择电子邮件或 Webhook 目标端。如需创建 Webhook，请参阅[添加 Webhook](#add-webhook)。

    您还可以添加标签和备注，为告警补充上下文信息。

  </Step>

  <Step title="创建和管理告警" id="create-explorer-alert">

    在侧边栏中打开 **告警**，然后选择该告警查看其详细信息，包括触发条件、通知目标端、图表和评估历史记录。

### 服务类型集成 {#integrations}

告警开箱即可与以下服务类型集成：

* **Slack**：通过 Webhook 或 API 将通知直接发送到频道。
* **PagerDuty**：通过 PagerDuty API 将事件路由给值班团队。
* **incident.io**：将告警发送到 incident.io。
* **Generic**：通过通用 Webhook 将告警接入任意自定义系统或工作流。

<Info>
  **仅限 ClickHouse Cloud 的集成**

  Slack API 和 PagerDuty 集成仅在 ClickHouse Cloud 中提供支持。
</Info>

不同的服务类型需要提供不同的信息，具体如下：

**Slack (Webhook URL)**

* Webhook URL。例如：`https://hooks.slack.com/services/<unique_path>`。更多详情请参阅 [Slack 文档](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)。

**Slack (API)**

* Slack 机器人令牌。更多详情请参阅 [Slack 文档](https://docs.slack.dev/authentication/tokens/#bot/)。

**PagerDuty API**

* PagerDuty 集成密钥。更多详情请参阅 [PagerDuty 文档](https://support.pagerduty.com/main/docs/api-access-keys)。

**Generic**

* Webhook URL
* Webhook 请求头 (可选)
* Webhook 请求正文 (可选) 。请求正文是一个 Handlebars 模板。除 `{{title}}`、`{{body}}` 和 `{{link}}` 外，还可以使用描述告警及其触发情况的变量，例如 `{{alertId}}`、`{{status}}`、`{{value}}`、`{{threshold}}` 和 `{{groupKey}}`。完整列表请参阅[告警 Webhook 模板变量](https://github.com/ClickHouse/ClickStack/blob/main/docs/alert-webhook-template-variables.md)。

在左侧边栏中选择 **告警** 即可管理告警。您可以按名称搜索，也可以按状态、source 或类型进行筛选。

<div className="ch-image-lg">
  <Frame>

  </Frame>

该视图还会显示告警的评估历史记录。告警按固定的时间间隔周期性评估 (时间间隔由创建告警时设置的周期/耗时决定) 。每次评估时，服务都会查询您的数据，检查是否满足告警条件：

* **红色条形**：本次评估满足阈值条件，告警已触发 (已发送通知)

## 基于 SQL 的图表告警 {#sql-based-alerts}

借助基于 SQL 的图表告警，您可以编写任意 ClickHouse SQL 来定义告警条件。这样，过滤、聚合和数学运算都完全由您掌控——凡是能用 SQL 表达的逻辑，都可以转化为告警。

### 支持的图表类型 {#supported-chart-types}

基于 SQL 的告警支持以下三种图表显示类型：

| 图表类型      | 行为                                     |
| --------- | -------------------------------------- |
| **线**   | 时间序列告警。查询必须返回按时间分桶的行，每个时间桶都会单独与阈值进行比较。 |
| **堆叠条形图** | 时间序列告警。行为与线相同。                       |
| **数值**    | 单值告警。查询返回单个数值结果，每次评估时将其与阈值比较一次。        |

其他基于 SQL 的图表类型 (表格、饼图、热力图等) 不支持告警。

### 创建 SQL 告警 {#create-sql-based-alert}

要在基于 SQL 的图表上创建告警，请按以下步骤操作：

<Steps>
  <Step title="在仪表盘上创建或打开基于 SQL 的图表" id="open-sql-chart">
    在已保存的仪表盘中，[使用 **SQL** 图表模式创建新图表](/zh/clickstack/observability/features/dashboards/sql-visualizations)，或打开现有的基于 SQL 的图表进行编辑。

    将显示类型设为 **线**、**堆叠条形图** 或 **数值**。

    <div className="ch-image-lg">

    * **Threshold value**：用于比较的数值
    * **时间间隔**：告警的评估频率 (5m、15m、30m、1h、6h、12h 或 1d) ，同时也决定每次评估的时间窗口。

### 查询结果的解读方式 {#sql-result-interpretation}

告警系统会检查 SQL 查询返回的列，以确定将哪些值与阈值进行比较。

* **值列**：`SELECT` 子句中的**最后一个数值列**将用作告警值。如果查询返回多个数值列 (例如 `count, avg_latency, p99_latency`) ，则只有最后一列 (`p99_latency`) 会与阈值进行比较。
* **时间戳列**：对于时间序列图表 (线和堆叠条形图) ，系统会将结果中的 Date/DateTime 列识别为时间桶 (即时间序列图表的 x 轴) 。每个时间桶的值都会单独与阈值进行比较；只要任一时间桶的值超出已配置的阈值，就会触发告警。
* **分组列**：所有非数值、非时间戳的列 (例如 `ServiceName`、`Environment`) 都会被视为分组维度。存在分组时，系统会对每个唯一的分组值组合分别进行跟踪和告警。只要某个分组的值超出已配置的阈值，服务就会为该分组发送一条告警。分组仅适用于时间序列图表。

### 查询参数和宏 {#query-params}

SQL 告警查询支持模板参数和宏，它们会在求值时被自动替换。这些参数和宏与[构建基于 SQL 的图表](/zh/clickstack/observability/features/dashboards/sql-visualizations)时可用的参数和宏相同。

#### 必需参数与推荐参数 {#required-alert-parameters}

用于折线图或堆叠条形图告警的查询**必须**包含间隔参数或宏 (`{intervalSeconds:Int64}`、`{intervalMilliseconds:Int64}`、`$__timeInterval(col)` 或 `$__timeInterval_ms(col)`) 。告警执行时，该参数或宏会被替换为告警所配置的周期。

用于告警的查询**应当**包含时间范围过滤器 (`{startDateMilliseconds:Int64}` 和 `{endDateMilliseconds:Int64}`，或 `$__timeFilter(col)` 等) 。无论查询中是否包含时间范围过滤器，告警查询都会按告警所配置的周期运行。如果没有时间范围过滤器，查询在每次执行时都会读取源表中全部可用时间范围内的数据。

<Warning>
  **告警时间范围**

  通常，告警查询在每个时间间隔内执行一次。但如果因错误或慢查询而跳过了一个或多个时间间隔，下一次执行所用的时间范围将涵盖这些遗漏的时间间隔。此时，查询的间隔参数仍会设为告警所配置的周期，而时间范围参数则会反映更长的时间范围。
</Warning>

### 告警查询示例 {#example-queries}

#### 每个服务的错误率 (时间序列) {#example-error-rate}

当任一服务的错误率达到 5% 及以上，且告警周期内的请求数超过 10 个时触发告警，以避免低流量服务产生过多无效告警。

```sql
WITH error_rates AS (
  SELECT
    $__timeInterval(Timestamp) as ts,
    ServiceName,
    countIf (SpanKind = 'Server') as request_count,
    countIf (
      SpanKind = 'Server'
      and StatusCode = 'Error'
    ) as error_count,
    error_count / request_count * 100 AS error_percent
  FROM $__sourceTable
  WHERE $__timeFilter(Timestamp)
  GROUP BY ts, ServiceName
)
SELECT ts, ServiceName, error_percent
FROM error_rates
WHERE request_count > 10
```

**显示类型**：线或堆叠条形图
**阈值**：`>= 5` (错误率达到 5% 时触发)

在此查询中，`ServiceName` 是一个既非数值也非时间戳的列，因此每个服务都会作为独立的告警分组进行跟踪，告警按服务分别触发。

#### 基于滞后平均值的异常检测 (时间序列) {#example-anomaly-detection}

当错误计数超出滚动平均值两个标准差以上时触发告警。这种方式不依赖固定阈值，而是以近期基线行为为参照来捕获突增。

```sql
WITH buckets AS (
  SELECT
    $__timeInterval(Timestamp) AS ts,
    count() AS bucket_count
  FROM $__sourceTable
  WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
        - toIntervalSecond($__interval_s * 30) -- Fetch 30 intervals back
    AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
    AND SeverityText = 'error'
  GROUP BY ts
  ORDER BY ts
  WITH FILL
    FROM toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
    TO toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
    STEP toIntervalSecond($__interval_s)
),

anomaly_detection AS (
  SELECT
    ts,
    bucket_count,
    avg(bucket_count) OVER (
      ORDER BY ts ROWS BETWEEN 30 PRECEDING AND 1 PRECEDING
    ) AS previous_30_avg,
    stddevPop(bucket_count) OVER (
      ORDER BY ts ROWS BETWEEN 30 PRECEDING AND 1 PRECEDING
    ) AS previous_30_stddev,
    greatest(
      bucket_count - (previous_30_avg + 2 * previous_30_stddev), 0
    ) AS excess_error_count
  FROM buckets
)

SELECT ts, excess_error_count
FROM anomaly_detection
WHERE ts >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND ts < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
```

**显示类型**：线
**阈值**：`> 0` (检测到超出滚动基线的额外错误时触发)

请注意，该查询会在日期范围开始*之前*额外获取 30 个时间间隔的数据，用于为滚动窗口计算提供初始数据，然后再对最终输出进行过滤，仅保留评估窗口内的结果。

## 常见告警场景 {#common-alert-scenarios}

以下是一些可以配置的常见告警场景：

**错误：** 建议为默认的
`All Error Events` 和 `HTTP Status >= 400` 保存的搜索设置告警，以便在
错误过多时及时收到通知。

**慢速操作：** 您可以创建一个用于查找慢速操作的搜索 (例如
`duration:>5000`) ，然后在慢速操作
过多时触发告警。

**用户事件：** 您还可以为面向客户的团队设置告警，以便在
有新用户注册或用户执行关键操作时收到通知。
