<Note>
  **您正在使用自管理方式**

  您已选择通过[自管理体验](/zh/clickstack/self-configured/overview)自行设置 ClickHouse Observability。采用这种方式时，您需要自行运行 OpenTelemetry 采集器、管理向 ClickHouse Cloud 服务的数据摄取、调优 schema，并借助仓库将摄取工作负载与查询工作负载隔离开来。请参阅 [OpenTelemetry 采集器](/zh/clickstack/self-configured/ingesting-data/collector)、[性能调优](/zh/clickstack/self-configured/managing/performance-tuning)以及[隔离读写工作负载](/zh/clickstack/self-configured/managing/isolating-read-write)。

  希望由 ClickHouse 为您处理摄取、schema 和计算资源，获得无服务器体验？请改用默认的 ClickHouse Observability 体验，并按照[使用 OpenTelemetry 为应用程序添加插桩](/zh/clickstack/managed-onboarding/instrument-application-serverless)进行操作。
</Note>

本指南将引导您使用 OpenTelemetry 为一个小型 Node.js 应用程序添加插桩，并通过您自行运行的采集器将其日志、指标、链路追踪和会话回放发送到 ClickHouse Observability。为后端添加插桩时，无需修改应用程序的任何源代码。

[HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) 是一个 Node.js 应用，用于查询托管在公共 ClickHouse 演示环境中的 HackerNews 数据集。每个图表、表格和搜索框背后都是真实的 ClickHouse 查询，因此每次交互都会生成一个链路追踪，其主 span 是后端向 ClickHouse 发起的 HTTPS 调用。

本指南假设您已完成[设置 OpenTelemetry 采集器](/zh/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)，且已有一个正在运行的 ClickStack 采集器，并可从运行此应用程序的机器访问该采集器。**请确保已记下其 OTLP 端点**以及部署时设置的 `OTLP_AUTH_TOKEN`。在添加插桩之前，您需要将这些值填入 `.env`。

## 前置条件 {#prerequisites}

* 可从这台机器访问的 ClickStack 采集器。如果你尚未部署，请先参阅[设置 OpenTelemetry 采集器](/zh/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)。
* 该采集器的 OTLP/HTTP 端点 (通常为端口 `4318`) ，以及你为其设置的 `OTLP_AUTH_TOKEN`。将它们分别用作 `OTEL_EXPORTER_OTLP_ENDPOINT` 和 `OTEL_EXPORTER_OTLP_HEADERS=authorization=<token>`。
* Node 18+ 和 npm。

## 克隆仓库 {#clone-the-repository}

克隆 [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)，安装依赖项，然后复制环境变量模板：

```bash
git clone https://github.com/ClickHouse/hn-news-analyzer.git
cd hn-news-analyzer
npm install
cp .env.example .env
```

接下来的步骤中，你将填写 `.env`，然后在此目录中为应用添加埋点。
