<Info>
  **TL;DR**

  运行一个小型演示应用，使用服务“入门指南”页面中的 AI 提示词或手动修改两处代码对其进行插桩，然后即可看到日志、链路追踪和指标陆续进入 ClickHouse Observability。

  所需时间：约 10 分钟
</Info>

您已创建好 ClickHouse Observability 服务。本指南将带您从一个空服务开始，直到接收来自运行中应用的遥测数据。

ClickHouse Observability 提供托管的 OpenTelemetry 端点，您的应用可将遥测数据直接发送到该端点。无需运行采集器，无需创建 schema，也无需规划数据库容量。摄取、schema、存储、优化和扩缩容均由平台为您处理。

## 演示应用 {#the-demo-application}

为了提供一个贴近真实场景的插桩对象，本指南使用 [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)，这是我们专为此用途提供的演示应用。它是一个基于 Node.js 和 TypeScript 的小型应用，用于查询托管在 ClickHouse 公共演示环境中的 HackerNews 数据集。应用中的每个图表、表格和搜索框背后都对应着一个发往后端的真实请求。未命中应用缓存的请求还会查询 ClickHouse，从而在每个 trace 中增加一个出站 HTTPS 跨度。

该演示应用提供两个版本：

* **未插桩**版本位于 `main` 分支。在本指南中，您将借助 AI 智能体或手动方式自行添加插桩，且无需修改应用的业务逻辑。相同的步骤同样适用于您自己的服务。
* **已插桩**版本位于 `instrumented` 分支。如果您只想快速让遥测数据流转起来并探索 UI，请检出此分支。

## 前置条件 {#prerequisites}

* 一个 ClickHouse Observability 服务。如果尚未创建，请参阅[入门指南](/zh/clickstack/observability/getting-started)。
* Node.js 18 或更高版本，以及 npm。
* 运行演示的机器和您的浏览器均可通过网络访问该服务的遥测数据端点。

### 将演示应用指向您的服务 {#configure-environment}

        打开 `.env` 并设置以下配置值，将其中的端点和 API key 替换为对话框中显示的值：

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        这些都是标准的 OpenTelemetry 导出器变量，应用程序源代码中没有任何硬编码的内容。

        保留 `OTEL_EXPORTER_OTLP_ENDPOINT` 中的 `https://` 前缀，不要在末尾追加 `/v1/logs`、`/v1/traces` 或 `/v1/metrics`，SDK 会自动添加各信号对应的路径。将 `OTEL_EXPORTER_OTLP_HEADERS` 设置为 `authorization=<your-api-key>`，无需添加 `Bearer` 前缀。

        接下来的插桩工作分为三步：安装 SDK、切换启动命令，以及启用浏览器 SDK。整个过程都不会改动应用程序的业务逻辑。

### 安装 Node SDK {#install-node-sdk}

        ```bash
        npm install @hyperdx/node-opentelemetry
        ```

### 在 run.sh 中启用包装器 {#enable-run-sh-wrapper}

        `run.sh` 末尾有两行 `exec`。将直接运行 `node` 的那一行注释掉，并取消注释已插桩的那一行：

        ```diff
         # BEFORE: plain node, no instrumentation:
        -exec node scripts/entrypoint.js
        +# exec node scripts/entrypoint.js

         # AFTER: same source, wrapped by opentelemetry-instrument:
        -# exec npx opentelemetry-instrument scripts/entrypoint.js
        +exec npx opentelemetry-instrument scripts/entrypoint.js
        ```

        请继续通过 `scripts/entrypoint.js` 启动应用。该 shim 会调用 `require('console')`，使控制台捕获能够包装 `console.log`。如果直接将 `opentelemetry-instrument` 指向 `dist/server/index.js`，虽然仍能发送链路追踪数据，但日志会被静默丢弃。

### 启用浏览器 SDK {#enable-browser-sdk}

        ```bash
        npm install @hyperdx/browser
        ```

        在 `src/web/telemetry.ts` 中，取消注释 import 语句、`HyperDX.init` 代码块以及 `recordAction` 中的 `HyperDX.addAction`：

        ```diff
        -// import HyperDX from '@hyperdx/browser';
        +import HyperDX from '@hyperdx/browser';

         export function initTelemetry(): void {
        -  // HyperDX.init({
        -  //   url: __OTLP_ENDPOINT__,
        -  //   apiKey: __OTLP_AUTH_TOKEN__,
        -  //   service: 'hn-analyzer-web',
        -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        -  //   consoleCapture: true,
        -  //   advancedNetworkCapture: true,
        -  // });
        +  HyperDX.init({
        +    url: __OTLP_ENDPOINT__,
        +    apiKey: __OTLP_AUTH_TOKEN__,
        +    service: 'hn-analyzer-web',
        +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        +    consoleCapture: true,
        +    advancedNetworkCapture: true,
        +  });
         }
        ```

        `__OTLP_ENDPOINT__` 和 `__OTLP_AUTH_TOKEN__` 是由 `vite.config.ts` 注入的编译时常量，其值取自后端所用的同一组 `OTEL_EXPORTER_OTLP_*` 配置值。

        <Warning>
          浏览器 SDK 会将端点和 API key 嵌入浏览器打包产物中，任何人只要在 Network 选项卡中查看即可读取。请使用专门用于测试的服务，并确保 `.env` 不纳入版本控制。
        </Warning>

        使用 `./run.sh` 重新启动演示应用。
      </Tab>

      <Tab title="使用已完成插桩的分支" id="use-the-instrumented-branch">
        如需跳过插桩步骤、直接使用已完成插桩的演示应用，请按照“手动插桩”选项卡中的说明，在 `.env` 中设置 `OTEL_EXPORTER_OTLP_*` 变量，然后检出 [`instrumented` 分支](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented)：

        npm install
        ./run.sh

        除非您打算移除这些 SDK，否则请勿在此分支上运行 `./reset.sh`。
      </Tab>
    </Tabs>

## 如果没有显示任何内容 {#if-nothing-shows-up}

* 检查 `.env` 中的配置值。端点必须以 `https://` 开头、以端口 `4318` 结尾，且不能带有 `/v1/...` 后缀。API key 必须填写完整值，可在点击 **Reveal key** 后复制。
* 如果您采用的是手动方式，请确认 `OTEL_EXPORTER_OTLP_HEADERS` 的值为 `authorization=<your-api-key>`，且不带 `Bearer` 前缀；同时确认启动横幅中显示了全部三行 `Health check passed`。
* 确认您在完成插桩后已重启演示应用，并已刷新浏览器选项卡。只有在加载插桩后的 bundle 之后，会话回放才会开始。
* 在 **搜索** 中扩大时间范围，并移除所有筛选条件。默认 source 可能被设置为 **链路追踪** 而非 **日志**。
* 如需排除服务本身的问题，请前往 **团队设置 → Managed Telemetry**，然后使用 **Send a Test Log**。如果该日志出现在 **搜索** 中，则说明服务能够正常接收数据，问题出在演示应用的配置上。

## 后续步骤 {#next-steps}

您的服务现已包含来自真实应用程序的遥测数据。如需对您自己的服务进行插桩，可复用服务中的 **Instrument with AI** 提示词，或使用[已支持的语言 SDK](/zh/clickstack/observability/ingesting-data/sdks/index)，并配合相同的端点和 API key。

如需从基础设施 (而非应用程序代码) 采集数据：

* [监控 Kubernetes](/zh/clickstack/observability/example-datasets/kubernetes)：采集集群日志和指标，并探索 Kubernetes 仪表板。
* [本地日志和指标](/zh/clickstack/observability/example-datasets/local-data)：在 macOS 或 Linux 上采集本地文件和系统指标。

深入了解 UI：

* [搜索](/zh/clickstack/observability/features/search)：使用 Lucene 风格语法或 SQL 查询日志和链路追踪。
* [会话回放](/zh/clickstack/observability/features/session-replay)：功能概览、SDK 选项和隐私控制。
* [示例数据集](/zh/clickstack/observability/example-datasets)：更丰富的数据集和引导式调查。
