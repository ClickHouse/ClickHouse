<Note>
  本页介绍的是 **Self-managed ClickHouse Observability**。如需使用推荐的全托管方案，请参阅[此处](/zh/clickstack/observability/integration-examples/cloudwatch)的文档。
</Note>

本指南介绍如何使用 OpenTelemetry [`awscloudwatch` 接收器](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver)将 AWS CloudWatch 日志转发到 Self-managed ClickHouse Observability，并在 ClickStack 用户界面中查看这些日志。

我们将单独运行一个采集器，通过 AWS API 轮询 CloudWatch，并经由 OTLP 将事件转发到您的 ClickStack 采集器。请将该采集器部署在与日志组相同的 AWS 账户和区域中，以尽可能降低 API 延迟和成本。

本指南假定您已完成[设置 OpenTelemetry 采集器](/zh/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)中的步骤，并且已有一个正在运行的 ClickStack 采集器。

ClickStack 采集器既可以部署为 **Docker 容器** (参见[设置 OpenTelemetry 采集器](/zh/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)) ，也可以在 Kubernetes 中借助上游 OpenTelemetry Helm 图表和 ClickStack 采集器镜像，部署为 **Helm 发行版** (参见[部署采集器](/zh/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)) 。**请务必记下其 OTLP 端点**以及部署时设置的 `OTLP_AUTH_TOKEN`。

<Steps>
  <Step title="满足前置条件" id="gather-prerequisites">
    你需要准备：

    * 一个 **AWS 账户**，其中包含一个或多个 CloudWatch 日志组，以及具备下列 IAM 权限的凭证。
    * 一台已安装 **Docker** 的主机，该主机需能访问 AWS API，并能通过出站网络访问你的 ClickStack 采集器。通常是一台与日志组位于同一 AWS 账户和区域的 EC2 实例。
    * ClickStack 采集器的 **OTLP 端点**，且该端点须可从此主机访问。如果采集器运行在同一台机器上的 Docker 中，请使用 `http://host.docker.internal:4318` (参见[配置 CloudWatch 接收器](#configure-receiver)中的提示框) 。如果是远程采集器，请使用其完整 URL，例如 `https://otel.example.com:4318`。
    * 你在 ClickStack 采集器上设置的 `OTLP_AUTH_TOKEN` 值。如果未对采集器启用安全保护，可以从下面的 config 中删除 `authorization` 请求头。
  </Step>

  <Step title="配置 AWS 凭证" id="configure-aws">
    该接收器会从标准环境变量中读取 AWS 凭证。请在运行采集器的主机上导出这些环境变量。

    **AWS SSO 用户：**

    ```shell
    aws sso login --profile YOUR_PROFILE_NAME
    eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
    aws sts get-caller-identity
    ```

    **使用长期凭证的 IAM 用户：**

    ```shell
    export AWS_ACCESS_KEY_ID="your-access-key-id"
    export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
    export AWS_REGION="us-east-1"
    aws sts get-caller-identity
    ```

    这些凭证需要具备以下 IAM 策略，才能读取 CloudWatch 日志：

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    将 `YOUR_ACCOUNT_ID` 替换为您的 AWS 账户 ID。

    <Info>
      **生产环境凭证**

      在生产环境中，应优先使用绑定到实例的凭证，而非长期密钥，例如 EC2 上的 IAM role、EKS 上的 IRSA，或 ECS 上的任务角色。只要接收器能够通过实例元数据服务获取凭证，下面的采集器 config 无需设置任何凭证环境变量即可直接使用。
    </Info>
  </Step>

  <Step title="配置 CloudWatch 接收器" id="configure-receiver">
    导出 ClickStack 采集器端点和认证令牌，然后创建 `otel-collector-config.yaml` 文件。

    <Info>
      **同主机部署**

      以下示例假定 ClickStack 采集器与此 CloudWatch 采集器运行在同一主机上，因此接收器通过 `host.docker.internal` (即从容器内部访问 Docker 宿主机所用的地址) 连接 ClickStack 采集器。如果您的 ClickStack 采集器位于其他位置 (例如 in-cluster 服务、公网 URL 或私网 IP) ，请将下方 `OTEL_COLLECTOR_ENDPOINT` 中的地址替换为其实际地址。
    </Info>

    ```shell
    export OTEL_COLLECTOR_ENDPOINT="http://host.docker.internal:4318"
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    ```

    <Accordion title="查找账户中可用的日志组">
      在编辑 config 之前，请先列出所在区域中现有的日志组，以便填写真实的名称 (同时确认区域设置无误) ：

      ```shell
      aws logs describe-log-groups --region eu-central-1 \
        --query 'logGroups[].logGroupName' --output table
      ```

      示例输出：

      ```text
      -------------------------------
      |      DescribeLogGroups      |
      +-----------------------------+
      |  /aws-glue/jobs/error       |
      |  /aws-glue/jobs/logs-v2     |
      |  /aws-glue/jobs/output      |
      |  /aws-glue/sessions/error   |
      |  /aws-glue/sessions/output  |
      +-----------------------------+
      ```

      将此列表中的名称直接填入下方示例 1 的 `groups.named` 块中。以上述账户为例，命名日志组部分应改为：

      ```yaml
      groups:
        named:
          /aws-glue/jobs/error:
          /aws-glue/jobs/logs-v2:
          /aws-glue/jobs/output:
          /aws-glue/sessions/error:
          /aws-glue/sessions/output:
      ```

      此外，如果所需的日志组具有相同的前缀 (此处为 `/aws-glue/`) ，也可以改用示例 2 并设置 `prefix: /aws-glue/`，无需逐一列出。
    </Accordion>

    **示例 1：命名日志组 (推荐)&#x20;**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws-glue/jobs/error:
              /aws-glue/jobs/output:
              /aws-glue/sessions/error:

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    **示例 2：按前缀自动发现日志组**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            autodiscover:
              limit: 100
              prefix: /aws-glue/

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    需要调整的关键设置：

    * `region`：设置为日志组所在的区域。
    * `poll_interval` (默认为 `1m`) ：值越小，日志越接近实时，但 AWS API 调用次数也会随之增加。
    * `groups.named`：显式指定日志组列表；也可以使用 `groups.autodiscover.prefix` 自动采集所有匹配指定前缀的日志组。

    有关完整的选项列表，请参阅 [CloudWatch 接收器文档](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver)。

    <Info>
      **仅采集近期日志**

      首次运行时，接收器会以当前时间作为检查点，仅拉取该时间点之后的日志，不会回填历史日志。
    </Info>
  </Step>

  <Step title="启动接收端采集器" id="start-collector">
    在 `otel-collector-config.yaml` 所在目录中创建 `docker-compose.yaml`。`extra_hosts` 条目使容器能够通过 `host.docker.internal` 访问运行在同一主机上的 ClickStack 采集器；采用长格式写法的绑定挂载会在配置文件缺失时明确报错，而不会悄无声息地创建一个空目录：

    ```shell
    cat > docker-compose.yaml <<'EOF'
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:latest
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_COLLECTOR_ENDPOINT
          - OTLP_AUTH_TOKEN
        extra_hosts:
          - "host.docker.internal:host-gateway"
        restart: unless-stopped
    EOF
    ```

    启动采集器：

    ```shell
    docker compose up -d
    ```

    实时跟踪其日志，确认它正在轮询 CloudWatch 并将数据导出到您的 ClickStack 采集器：

    ```shell
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="在 ClickStack 用户界面中确认" id="confirm-in-ui">
    在 [ClickHouse Cloud 控制台](https://console.clickhouse.cloud)中打开您的服务，然后在左侧菜单中选择 **ClickStack**。

    <div className="ch-image-lg">
      <Frame>
        ![启动 ClickStack](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    在 **搜索** 视图中，将 source 切换为 `Logs`，并将时间范围设置为 **Last 15 minutes**。通常经过几个轮询间隔后，CloudWatch 事件就会出现。

    <div className="ch-image-lg">
      <Frame>
        ![包含 CloudWatch 日志的 ClickStack 搜索视图](/images/clickstack/cloudwatch/log-search-view-clickstack.webp)
      </Frame>
    </div>

    每个事件都会将其来源日志组和日志流作为资源属性携带：

    * `ResourceAttributes['aws.region']`：AWS 区域 (例如 `eu-central-1`)
    * `ResourceAttributes['cloudwatch.log.group.name']`：来源日志组
    * `ResourceAttributes['cloudwatch.log.stream']`：来源日志流
    * `Body`：原始日志行

    将搜索修改为 `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body`，即可显示这些属性：

    <div className="ch-image-lg">
      <Frame>
        ![包含 CloudWatch 日志及属性的 ClickStack 搜索视图](/images/clickstack/cloudwatch/log-search-attributes-clickstack.webp)
      </Frame>
    </div>

    选择某个日志条目即可查看其元数据：

    <div className="ch-image-lg">
      <Frame>
        ![日志详情视图中的 CloudWatch 属性](/images/clickstack/cloudwatch/error-log-column-values-clickstack.webp)
      </Frame>
    </div>

    如果没有显示任何数据：

    * 在采集器主机上运行 `aws sts get-caller-identity`，确认凭证有效。
    * 使用 `docker compose logs -f otel-collector` 实时查看采集器日志，留意以下错误：`AccessDeniedException` (IAM 权限问题) 、`security token` 错误 (SSO 凭证已过期) 、`ResourceNotFoundException` (日志组名称拼写错误或区域有误) ，或 `connection refused` (无法从容器内部访问您的 ClickStack 采集器端点，请参阅[配置 CloudWatch 接收器](#configure-receiver)中关于 `host.docker.internal` 的说明) 。
    * 验证能否从容器内部访问 `OTEL_COLLECTOR_ENDPOINT`：`docker compose exec otel-collector wget -qO- ${OTEL_COLLECTOR_ENDPOINT}/v1/logs -S 2>&1 | head -5`。
    * 确认 `OTLP_AUTH_TOKEN` 与您在 ClickStack 采集器上设置的值一致。
  </Step>

      <Frame>

      </Frame>

  </Step>
