<Note>
  本页介绍的是 **Self-managed ClickHouse Observability**。全托管的 ClickHouse Observability 是推荐的默认方案，会自动为您处理数据库 schema 和类型映射。迁移时无需配置这些内部结构，请参阅 [Elasticsearch 迁移指南](/zh/clickstack/observability/migration/elastic) 开始使用。
</Note>

Elasticsearch 和 ClickHouse 都支持丰富的数据类型，但二者的底层存储和查询模型存在根本差异。本节列出常用 Elasticsearch 字段类型在 ClickHouse 中的等价类型 (如有) ，并提供相关背景信息，为迁移提供参考。如果没有等价类型，则会在注释中给出替代方案或说明。

### 说明 {#notes}

* **数组**：在 Elasticsearch 中，所有字段都原生支持数组。在 ClickHouse 中，数组必须显式定义 (例如 `Array(String)`) ，其优势在于可以访问和查询特定位置的元素，例如 `an_array[1]`。
* **多字段 (Multi-fields)&#x20;**：Elasticsearch 允许[以多种方式索引同一字段](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields#_multi_fields_with_multiple_analyzers) (例如同时作为 `text` 和 `keyword`) 。在 ClickHouse 中，这种模式需要通过单独的列或视图来实现。
* **Map 和 JSON 类型** - 在 ClickHouse 中，[`Map`](/zh/reference/data-types/map) 类型常用于建模 `resourceAttributes` 和 `logAttributes` 等动态键值结构。该类型允许在运行时添加任意键，从而实现灵活的无 schema 摄取，其理念与 Elasticsearch 中的 JSON 对象类似。但该类型也存在以下重要限制：

  * **值类型必须统一**：ClickHouse 的 [`Map`](/zh/reference/data-types/map) 列必须使用一致的值类型 (例如 `Map(String, String)`) 。若不进行类型强制转换，则不支持混合类型的值。
  * **性能开销**：访问 [`Map`](/zh/reference/data-types/map) 中的任意键都需要将整个 Map 加载到内存中，可能影响性能。
  * **不支持子列**：与 JSON 不同，[`Map`](/zh/reference/data-types/map) 中的键并不以真正的子列形式存储，这限制了 ClickHouse 高效索引、压缩和查询的能力。

  ClickHouse 的 [`JSON`](/zh/reference/data-types/newjson) 类型可替代 [`Map`](/zh/reference/data-types/map) 来存储动态属性，并解决了上述多项限制：

  * **真正的列式存储**：每个 JSON 路径都作为子列存储，从而支持高效的压缩、过滤和向量化查询执行。
  * **支持混合类型**：不同的数据类型 (例如整数、字符串、数组) 可以在同一路径下共存，无需类型强制转换或类型统一。
  * **文件系统可扩展性**：针对动态键 (`max_dynamic_paths`) 和类型 (`max_dynamic_types`) 的内部限制可防止磁盘上的列文件数量激增，即使键集合基数很高也不例外。
  * **紧凑存储**：null 和缺失值采用稀疏方式存储，避免不必要的开销。

    [`JSON`](/zh/reference/data-types/newjson) 类型尤其适合可观测性工作负载，既具备无 schema 摄取的灵活性，又拥有 ClickHouse 原生类型的性能和可扩展性，是在动态属性字段中替代 [`Map`](/zh/reference/data-types/map) 的理想选择。

    有关 JSON 类型的更多信息，建议参阅 [JSON 指南](/zh/guides/clickhouse/data-formats/json/intro)以及[“How we built a new powerful JSON data type for ClickHouse”](https://clickhouse.com/blog/a-new-powerful-json-data-type-for-clickhouse)。
