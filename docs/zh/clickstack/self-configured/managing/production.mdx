在生产环境中使用 Self-managed ClickHouse Observability 时，请参考以下安全性、稳定性和配置方面的实践。

[Self-managed ClickHouse Observability](/zh/clickstack/self-configured/getting-started/managed) 默认采用行业标准的[安全实践](/zh/products/cloud/features/security)，包括增强的加密、身份验证和连接安全，以及托管的访问控制，同时还具备以下优势：

* 计算资源独立于存储自动扩缩容
* 基于对象存储，数据保留成本低且几乎不受限制
* 可借助仓库[独立隔离读写工作负载](/zh/clickstack/self-configured/managing/isolating-read-write)
* 集成身份验证
* 自动[备份](/zh/products/cloud/features/backups/overview)
* 无缝升级

**使用 Self-managed ClickHouse Observability 时，请遵循这些适用于 ClickHouse Cloud 的[最佳实践](/zh/products/cloud/guides/production-readiness)。**

## 安全摄取 {#secure-ingestion-managed}

默认情况下，在开源发行版之外部署 ClickStack OpenTelemetry 采集器时，采集器未启用安全保护，其 OTLP 端口也无需身份验证。

如需保护摄取，请在部署采集器时通过 `OTLP_AUTH_TOKEN` 环境变量指定身份验证令牌。更多详情请参阅[“保护采集器”](/zh/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)。

### 创建摄取用户 {#create-a-database-ingestion-user-managed}

建议为 OTel collector 创建一个专用用户，用于向 ClickHouse Cloud 摄取数据，并确保摄取的数据写入指定的数据库，例如 `otel`。更多详情请参阅[“创建摄取用户”](/zh/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)。

## 配置生存时间 (TTL) {#configure-ttl-managed}

请确保已为您的 Self-managed ClickHouse Observability 部署[正确配置](/zh/clickstack/self-configured/managing/ttl#modifying-ttl)[生存时间 (TTL)](/zh/clickstack/self-configured/managing/ttl)。该设置决定数据的保留时长，默认值为 30 天，您可能需要按需调整。

### 隔离可观测性工作负载 {#isolating-workloads}

如果您要将 Self-managed ClickHouse Observability 添加到一个已承载其他工作负载 (例如实时应用程序数据分析) 的**现有 ClickHouse Cloud 服务**中，强烈建议对可观测性流量进行隔离。

使用 [**托管仓库**](/zh/products/cloud/features/infrastructure/warehouses) 创建一个可观测性专用的**子服务**。这样可以：

* 将摄取和查询负载与现有应用程序隔离
* 独立扩展可观测性工作负载
* 避免可观测性查询影响生产环境中的数据分析
* 按需在多个服务之间共享相同的底层数据集

这种方式既能确保现有工作负载不受影响，又能让可观测性工作负载随着可观测性数据的增长而独立扩展。

### 隔离读写工作负载 {#isolating-read-write}

借助仓库，还可以将摄取工作负载和查询工作负载分别放到专用的计算资源上：摄取写入读写服务，而可观测性 UI 则运行在只读服务上。对于规模较大的部署，这是推荐的生产环境拓扑。请参阅[“隔离读写工作负载”](/zh/clickstack/self-configured/managing/isolating-read-write)。

如需针对大规模部署的指导或自定义资源规模规划建议，请联系支持团队，以获取更精确的估算。

## 查询用户权限 {#user-permissions}

供外部查询客户端使用的 ClickHouse 用户应设置为 `readonly = 2`。UI 会在每个查询中应用其自身的设置 (例如 `date_time_output_format`) ，而原始 SQL 图表也会设置 `readonly = 2`，因此 `readonly = 1` 的用户在执行这些查询时会失败，并报错 `Cannot modify '...' setting in readonly mode`。设为 `readonly = 2` 后，UI 还可以设置 `max_rows_to_read`、`read_overflow_mode` 和 `cancel_http_readonly_queries_on_client_close`；如果要限制 `max_rows_to_read`，请至少允许 100 万行。`wait_end_of_query` 是 HTTP 接口参数而非设置，因此无需授权。

例如：

```sql
CREATE USER clickstack_ui IDENTIFIED BY '<password>' SETTINGS readonly = 2;
GRANT SELECT ON default.* TO clickstack_ui;
```

默认情况下，ClickHouse Cloud 中的 `default` 用户已具备这些权限，但我们建议另外创建一个专用用户。
