## ClickHouse 核心概念 {#core-concepts}

大多数管理任务都要求熟悉底层的 ClickHouse 数据库。在执行管理或性能相关操作之前，建议先了解以下 ClickHouse 核心概念。

| 概念                 | 描述                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| **表**              | 数据源如何映射到底层的 ClickHouse 表。ClickHouse 表主要使用 [`MergeTree`](/zh/reference/engines/table-engines/mergetree-family/mergetree) 引擎。 |
| **Parts**          | 数据如何以不可变的 parts 形式写入，并随时间推移不断合并。                                                                                         |
| **分区**             | 表数据片段的逻辑分组，可简化数据管理、查询和优化。                                                                                                |
| **合并**             | 将多个 parts 合并的后台过程，可减少查询时涉及的 parts 数量，从而保持性能。                                                                             |
| **粒度**             | 查询执行期间读取和裁剪数据的最小单位。                                                                                                      |
| **主键 (排序键)&#x20;**&#x20;| `ORDER BY` 键如何决定磁盘上的数据布局、压缩效果以及查询裁剪行为。                                                                                   |

这些概念是 ClickHouse 性能的基础，可帮助您在管理 Self-managed ClickHouse Observability 时做出明智的管理决策。
