<Note>
  本页适用于 **Self-managed ClickHouse Observability**。如需使用推荐的全托管方案，请参阅[此处](/zh/clickstack/observability/managing/config)的文档。
</Note>

本指南介绍 Self-managed ClickHouse Observability 的数据源设置、您所运行的采集器，以及数据库 schema 配置。

## 用户界面 {#hyperdx}

### 数据源设置 {#datasource-settings}

UI 要求用户为每一种可观测性数据类型 (支柱) 定义一个 source：

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

打开 **团队设置 → 数据 → 数据源** 即可配置 source。选择 **Configure Optional Fields** 可访问更多设置，下图以日志为例突出显示了该选项：

<div className="ch-image-md">
  <Frame>
    ![日志数据源设置，其中突出显示了 Configure Optional Fields](/images/clickstack/source-settings-optional-fields.png)
  </Frame>
</div>

每个 source 都需要指定一个表并配置列映射，UI 才能查询其数据。OTel 指标数据源为每种指标类型使用单独的表；请选择包含您所采集指标的表。

如果使用 ClickStack 附带的[默认 OpenTelemetry (OTel) schema](/zh/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema)，系统可以为每个 source 自动推断这些列。如果[修改了 schema](#clickhouse) 或使用自定义 schema，则用户需要自行指定并更新这些映射。

<Note>
  ClickStack 采集器通过内置的模式迁移创建默认表。这些 schema 基于 [OTel collector 的 ClickHouse 导出器](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter)和 [OpenTelemetry 数据模型](https://opentelemetry.io/docs/specs/otel/logs/data-model/)构建。
</Note>

下表列出了数据源设置。推断出的值取决于数据库中实际存在的列和表。可选映射用于启用相应功能 (例如 trace 关联) ，保存 source 时并非必需。

#### 物化视图 {#materialized-views-settings}

可以针对日志和链路追踪数据源注册物化视图，使符合条件的聚合查询直接从预聚合视图获取结果，而无需查询源表。有关创建和注册视图的说明，请参阅 [“物化视图”](/zh/clickstack/self-configured/managing/materialized-views)。

每个已注册的视图均需配置以下设置：

| 设置项                      | 描述                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `Database`               | 包含该 materialized view 的 target table 的 ClickHouse 数据库。                                                           |
| `Table`                  | materialized view 的 target table，而非视图本身。                                                                         |
| `Timestamp Column`       | target table 的时间戳列。                                                                                              |
| `Granularity`            | target table 时间戳列的时间桶，例如 `1 minute`。只有当查询自身的时间桶等于或粗于该值时，查询才能使用该视图。                                               |
| `Minimum Date`           | 可选。视图中数据的最早日期和时间。如未指定，ClickStack 会假定视图包含源表中所有日期的数据。                                                              |
| `Dimension Columns`      | 以逗号分隔的列名列表，这些列未经视图预聚合，因此可用于过滤和分组。                                                                                |
| `Pre-aggregated Columns` | 经视图预聚合的列。每个条目将一个聚合函数 (`avg`、`count`、`max`、`min`、`quantile`、`sum` 或 `histogram`) 和一个源表列映射到视图中的对应列。`count` 无需指定源列。 |

选择 target table 后，UI 会尝试根据视图的 schema 推断这些设置。请检查推断出的值，并补全所有缺失字段。

#### 元数据物化视图 {#metadata-materialized-views-settings}

元数据物化视图是一类物化视图，用于加速筛选条件和自动补全中的字段发现。可在日志和链路追踪数据源上配置。

| 设置项                | 描述                             |
| ------------------ | ------------------------------ |
| `Key Rollup Table` | 可选，已弃用。汇总源表中所有键的 rollup 表。     |
| `KV Rollup Table`  | 汇总源表中所有键/值对的 rollup 表。         |
| `Granularity`      | rollup 表使用的时间桶，例如 `15 minute`。 |

#### 突出显示的属性 {#highlighted-attributes}

可以在日志和链路追踪数据源上配置“突出显示的属性”和“突出显示的追踪属性”。

* 突出显示的属性是指在查看日志或跨度详情时，针对每条日志或每个跨度显示的列或表达式。
* 突出显示的追踪属性是指从 trace 中的每条日志或每个跨度查询得到、并显示在链路追踪瀑布图上方的列或表达式。

### 关联来源 {#correlated-sources}

要实现完整的跨数据源关联，必须为日志、链路追踪、指标和会话配置关联来源。这样 UI 便能关联相关数据，并在渲染事件时提供丰富的上下文信息。

* `Logs`：可与链路追踪和指标关联。
* `Traces`：可与日志、会话和指标关联。
* `Metrics`：可与日志关联。
* `Sessions`：可与链路追踪关联。

设置这些关联后，即可启用多项功能。例如，UI 可以在 trace 旁渲染相关日志，并支持在相关数据源之间跳转。此外，关联还依赖于相应的 ID 和属性映射；仅选择某个 source 并不会建立这些关系。

## OpenTelemetry 采集器 {#otel-collector}

更多详情请参见[“ClickStack OpenTelemetry 采集器”](/zh/clickstack/self-configured/ingesting-data/collector)。

* `CLICKHOUSE_ENDPOINT`
  * **默认值：** 对于独立模式采集器镜像，*无 (必填)&#x20;*。
  * **描述：** 导出器使用的 ClickHouse 连接 URL。
  * **建议：**
    * 使用安全的 ClickHouse Cloud 端点，例如 `https://<host>:8443` 或 `tcp://<host>:9440?secure=true`
    * 采集器向 ClickHouse 发送数据时必需

* `CLICKHOUSE_USER`
  * **默认值：** 在迁移工具中为 `default`；对于独立模式采集器需显式设置。
  * **描述：** 用于向 ClickHouse 实例进行身份验证的用户名。
  * **建议：**
    * 该用户需要具有插入遥测数据的权限；如果启用了 schema 创建或迁移，还需要具有创建或修改相关数据库对象的权限
    * 建议创建一个专用于摄取的用户

* `CLICKHOUSE_PASSWORD`
  * **默认值：** *无 (启用身份验证时必填)&#x20;*
  * **描述：** 指定 ClickHouse 用户的密码。
  * **建议：**
    * 如果用户账户设置了密码，则必填
    * 在生产环境部署中，应通过 secret 安全存储

* `HYPERDX_LOG_LEVEL`
  * **默认值：** 取决于具体部署；建议显式设置，例如 `info`。
  * **描述：** 采集器的日志详细级别。
  * **建议：**
    * 可选值包括 `debug`、`info`、`warn`、`error`
    * 故障排查时使用 `debug`

* `OTLP_AUTH_TOKEN`
  * **默认值：** *无*。仅用于独立模式镜像。
  * **描述：** 设置独立模式 OTLP 摄取所需的令牌。当前版本的采集器支持在 `Authorization` 请求头中直接传入该值，也支持加上 `Bearer` 前缀传入。较旧版本的采集器可能只接受不带前缀的令牌。如果配置了 OIDC 身份验证，则忽略此项。
  * **建议：**
    * 在对外暴露采集器之前，请先配置身份验证。如果未配置令牌或 OIDC，独立模式的 OTLP 接收器将接受未经身份验证的请求。

* `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE`
  * **默认值：** 在迁移工具中为 `default`；对于独立模式采集器需显式设置。
  * **描述：** 采集器写入遥测数据的目标 ClickHouse 数据库。
  * **建议：**
    * 如果使用自定义数据库名称，请设置此项
    * 确保指定用户有权访问该数据库

## ClickHouse {#clickhouse}

要有效地调优 ClickHouse，您需要理解关键的存储概念，例如 [parts](/zh/concepts/core-concepts/parts)、[分区](/zh/concepts/core-concepts/partitions)、[分片和副本](/zh/guides/oss/deployment-and-scaling/shards)，以及写入时[合并](/zh/concepts/core-concepts/merges)是如何发生的。建议您了解[主键索引](/zh/concepts/core-concepts/primary-indexes)、[稀疏二级索引](/zh/concepts/features/performance/skip-indexes/skipping-indexes)和数据跳过索引的基础知识，以及[管理数据生命周期](/zh/guides/use-cases/observability/build-your-own/managing-data)的相关技术，例如使用 TTL 管理生命周期。

您可以[自定义 schema](/zh/guides/use-cases/observability/build-your-own/schema-design)：修改列类型、提取新字段 (例如从日志中提取) 、应用编解码器和字典，以及使用投影加速查询。

此外，物化视图可用于[在摄取过程中转换或过滤数据](/zh/guides/use-cases/observability/build-your-own/schema-design#materialized-views)，前提是数据写入该视图的源表，且应用程序从 target table 读取数据。物化视图还可用于在服务中[原生加速查询](/zh/clickstack/self-configured/managing/materialized-views)。

更多详情，请参阅 ClickHouse 文档中有关 schema 设计、索引策略和数据管理最佳实践的内容，其中大部分内容可直接适用于自管理部署。
