<Note>
  本页介绍 **Self-managed ClickHouse Observability**。如需推荐的全托管体验，请参阅[此处](/zh/clickstack/observability/getting-started)的文档。
</Note>

在 ClickHouse Cloud 上部署 Self-managed ClickHouse Observability，通过摄取管道发送一个测试事件，并确认可在可观测性 UI 中查看该事件。

ClickHouse Cloud 负责运维 ClickHouse 后端，而摄取管道和 schema 仍由您掌控。Self-managed ClickHouse Observability 提供：

* 计算资源自动扩缩容，与存储相互独立
* 基于对象存储的低成本、几乎无限期的数据保留
* 借助[仓库](/zh/products/cloud/features/infrastructure/warehouses)实现读写工作负载的相互隔离
* 集成的身份验证
* 自动备份
* 安全与合规功能
* 无缝升级

## 开始之前 {#before-you-begin}

您也可以通过[受支持的集成](/zh/integrations/home)，使用您自己的 schema 将数据直接发送到 ClickHouse。

### 创建 ClickHouse Cloud 服务 {#create-a-managed-clickstack-service}

按照 ClickHouse Cloud 快速入门中的[创建 ClickHouse 服务](/zh/get-started/setup/cloud#1-create-a-clickhouse-service)一节完成操作。继续之前，请先确认该服务已在运行。

  ### 准备摄取环境 {#prepare-your-ingestion-environment}

  * 如需启动新的 [OpenTelemetry 收集器](/zh/clickstack/self-configured/ingesting-data/collector)，请先安装 [Docker](https://docs.docker.com/get-docker/)。如果使用 Kubernetes，请通过 [Helm](/zh/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured) 部署采集器。
  * 如需使用现有采集器，请以 [gateway 角色](/zh/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)运行该采集器，并确保其发行版包含 [ClickHouse 导出器](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter)。本指南后续步骤将介绍如何添加所需配置。

          <Accordion title="创建专用摄取凭证（推荐）">
            在 ClickHouse Cloud 中，打开服务的 SQL 控制台并运行：

            ```sql
            CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
            GRANT SELECT, INSERT, CREATE DATABASE, CREATE TABLE, CREATE VIEW ON default.* TO `clickstack-ingest`;
            ```

            在生成的命令中，将 `CLICKHOUSE_USER="default"` 替换为 `CLICKHOUSE_USER="clickstack-ingest"`，并将 `CLICKHOUSE_PASSWORD` 设置为该专用用户的密码。
          </Accordion>

          如需继续使用 `default` 管理员凭证，请从 **Start Collector** 选项卡中复制命令。UI 会自动填入服务端点。将密码占位符替换为您的服务密码。如果您已不记得该密码，请[获取或重置连接详细信息](/zh/products/cloud/guides/sql-console/connection-details)。

          该命令的格式如下：

          ```shell
          docker run -e CLICKHOUSE_ENDPOINT="https://<host>:8443" \
              -e CLICKHOUSE_USER="default" \
              -e CLICKHOUSE_PASSWORD="<your_password_here>" \
              -p 4317:4317 -p 4318:4318 \
              clickhouse/clickstack-otel-collector:latest
          ```

          将 `<host>` 和 `<your_password_here>` 替换为您 ClickHouse Cloud 服务的对应值，然后运行该命令。

          采集器会在前台运行。请保持此终端打开，并另开一个终端执行本指南中的其余命令。

          <Note>
            此命令暴露的 OTLP 端口未启用身份验证，仅适用于本地评估。在发送生产流量之前，请先[保护采集器](/zh/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)。

  ## 配置 Self-managed ClickHouse Observability {#set-up-managed-clickstack-vector}

  <Steps titleSize="h3">
    <Step title="选择 Vector 并配置数据摄取" id="choose-an-ingestion-source-vector">
      在您的 ClickHouse Cloud 服务中打开 ClickHouse Observability，然后在 **入门指南** 页面上点击 **开始摄取**。

      <div className="ch-image-lg">
        <Frame>
          ![开始摄取](/images/clickstack/getting-started/start_ingestion.webp)
        </Frame>
      </div>

      在 **Choose an ingestion source** 页面中，选择 [Vector](https://vector.dev/)。

      <div className="ch-image-lg">
        <Frame>
          ![选择 Vector 作为摄取来源](/images/clickstack/getting-started/select_source_vector_toggle.webp)
        </Frame>

      [Vector](https://vector.dev) 是一款高性能、厂商中立的可观测性数据管道，凭借灵活性高、资源占用低的特点，在日志摄取场景中尤为流行。

      使用 Vector 时，schema 由您自行定义：既可以遵循 OpenTelemetry 约定，也可以使用您的事件所特有的字段。

      <Info>
        **需要已有的 Vector 管道**

        如果您已在运行带有输入管道的 Vector，请继续阅读本指南。通过该管道发送的数据必须包含**时间戳列**或等价的时间字段，您将在可观测性 UI 中配置数据源时选择该字段。

        以下步骤将为您现有的管道添加一个 ClickHouse 数据接收端。
      </Info>

#### 创建数据库和表 {#create-a-vector-database-and-table}

      在配置 Vector 数据接收端之前，请先创建数据库和表。

      在 ClickHouse Cloud 中，打开服务的 SQL 控制台并创建数据库：

      例如，为日志创建一个数据库：

      ```sql
      CREATE DATABASE IF NOT EXISTS logs
      ```

      然后创建一张表，使其 schema 与你的日志数据结构相匹配。以下示例假设使用经典的 Nginx 访问日志格式：

      ```sql
      CREATE TABLE logs.nginx_logs
      (
          `time_local` DateTime,
          `remote_addr` IPv4,
          `remote_user` LowCardinality(String),
          `request` String,
          `status` UInt16,
          `body_bytes_sent` UInt64,
          `http_referer` String,
          `http_user_agent` String,
          `http_x_forwarded_for` LowCardinality(String),
          `request_time` Float32,
          `upstream_response_time` Float32,
          `http_host` String
      )
      ENGINE = MergeTree
      ORDER BY (toStartOfMinute(time_local), status, remote_addr);
      ```

      表结构必须与 Vector 生成的输出 schema 保持一致。请根据实际数据按需调整 schema，并遵循推荐的 [schema 最佳实践](/zh/concepts/best-practices/select-data-type)。

      我们强烈建议您先了解 ClickHouse 中[主键](/zh/concepts/core-concepts/primary-indexes)的工作原理，并根据您的访问模式选择排序键。有关如何选择主键，请参阅[性能调优](/zh/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key)指南。

#### 配置 ClickHouse 数据接收端 {#configure-the-vector-clickhouse-sink}

      表创建完成后，在 Vector 配置中添加一个 ClickHouse 数据接收端：

      ```yaml
      sinks:
        clickhouse:
          type: clickhouse
          inputs:
            - your_input
          endpoint: "https://<host>:8443"
          database: logs
          table: nginx_logs
          format: json_each_row
          skip_unknown_fields: true
          auth:
            strategy: basic
            user: default
            password: "<your_password_here>"
      ```

      将 `your_input` 替换为现有管道中的输入，并将 `<host>` 和 `<your_password_here>` 替换为您的 ClickHouse Cloud 服务的相应值。如有需要，可更改目标数据库或表。

      <Accordion title="使用专用摄取凭证（推荐）">
        在生产环境中，请创建一个专用用户，并授予其访问 Vector 目标表的权限。在 ClickHouse Cloud 中，打开服务的 SQL 控制台并运行：

        ```sql
        CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
        GRANT SELECT, INSERT ON logs.nginx_logs TO `clickstack-ingest`;
        ```

        在 Vector 数据接收端配置中，将 `default` 替换为 `clickstack-ingest`，并将 `password` 设置为该专用用户的密码。
      </Accordion>

      保存更新后的配置，然后按照您现有的部署流程重新加载或重启 Vector。

      有关使用 Vector 摄取数据的更多示例，请参阅[使用 Vector 摄取数据](/zh/clickstack/observability/ingesting-data/vector)；如需了解高级选项，请参阅 [Vector ClickHouse 数据接收端文档](https://vector.dev/docs/reference/configuration/sinks/clickhouse/)。

#### 创建数据源 {#create-a-vector-data-source}

      为 Vector 管道写入数据的表创建一个数据源。首次登录时，UI 会提示您创建数据源。

      该表单会针对默认的 OpenTelemetry schema 预先填充表达式。对于本指南中创建的 Nginx 表，请按以下值配置该 source：

      | 设置项           | 值                                                                                                               |
      | ------------- | --------------------------------------------------------------------------------------------------------------- |
      | **名称**        | `Nginx logs`                                                                                                    |
      | **源数据类型**     | 日志                                                                                                              |
      | **服务器连接**     | `Default`                                                                                                       |
      | **数据库**       | `logs`                                                                                                          |
      | **表**         | `nginx_logs`                                                                                                    |
      | **时间戳列**      | `time_local`                                                                                                    |
      | **默认 SELECT** | `time_local, remote_addr, status, request`                                                                      |
      | **服务名称表达式**   | `'nginx'`                                                                                                       |
      | **日志级别表达式**   | `multiIf(status >= 500, 'ERROR', status >= 400, 'WARN', 'INFO')`                                                |
      | **日志属性表达式**   | `map('http.remote_addr', toString(remote_addr), 'http.status_code', toString(status), 'http.request', request)` |
      | **资源属性表达式**   | `map('service.name', 'nginx')`                                                                                  |
      | **显示时间戳列**    | `time_local`                                                                                                    |
      | **追踪 ID 表达式** | `''`                                                                                                            |
      | **跨度 ID 表达式** | `''`                                                                                                            |
      | **隐式列表达式**    | `request`                                                                                                       |

      Nginx 表中没有 `Body` 列。请将 **Body Expression** 设置为：

      ```sql
      concat(
        remote_addr, ' ',
        remote_user, ' ',
        '[', formatDateTime(time_local, '%d/%b/%Y:%H:%i:%S %z'), '] ',
        '"', request, '" ',
        toString(status), ' ',
        toString(body_bytes_sent), ' ',
        '"', http_referer, '" ',
        '"', http_user_agent, '" ',
        '"', http_x_forwarded_for, '" ',
        toString(request_time), ' ',
        toString(upstream_response_time), ' ',
        '"', http_host, '"'
      )
      ```

      有关其他 source 设置，请参阅[配置参考文档](/zh/clickstack/self-configured/managing/config)。
    </Step>
