**Self-managed ClickHouse Observability** 是基于开源 ClickStack 构建的可观测性平台，面向 SRE、开发人员及其 AI agent。您可以搜索、查询和关联 OpenTelemetry 日志、链路追踪、指标以及会话回放，同时自主掌控摄取和数据库配置。它适合需要自定义 schema、调优查询性能，或自行决定服务规格与扩缩容方式的团队。

您可以通过 ClickStack 用户界面开展调查，也可以通过 [MCP 服务器](/zh/clickstack/observability/mcp)接入您自己的 agent。日常调查可使用搜索和链路追踪探索功能，也可以使用 SQL 分析遥测数据中的请求详情、自定义属性和业务上下文。

ClickHouse Cloud 负责托管和运维 ClickHouse 及 ClickStack 用户界面。采用自管理方案时，您无需自行托管数据库或 UI，只需运行摄取采集器，并根据自身工作负载管理数据库配置。

对于大多数团队，推荐从[全托管 ClickHouse Observability](/zh/clickstack/observability/overview) 起步：只需将遥测数据发送到托管的 OpenTelemetry 端点，摄取、schema、基础设施和扩缩容均由 ClickHouse 负责。自管理方案提供相同的 ClickStack 调查体验，但数据库调优和容量规划需由您自行负责。如果您需要这种控制能力，并具备相应的运维经验，可以选择该方案。

## 数据流转方式 {#architectural-overview}

应用程序和基础设施将遥测数据发送到您的采集器。采集器处理这些数据后，将其写入您的 ClickHouse Cloud 服务。托管的 ClickStack 用户界面会查询这些数据，用于搜索、可视化和调查。

您可以在 UI 中探索数据，也可以接入兼容 MCP 的 agent。这两种工作流使用的是同一份遥测数据。借助 SQL，您可以关联各类信号、对比历史行为，并调查预定义视图无法覆盖的问题。对应用程序进行插桩以及从您的环境中采集遥测数据，仍需由您自行负责。

有关组件图及详细信息，请参阅[自管理架构](/zh/clickstack/self-configured/architecture)。

## 您需要管理的内容 {#what-you-manage}

* **摄取：** 部署并运维您的 [OpenTelemetry 采集器](/zh/clickstack/self-configured/ingesting-data/collector)，包括其接收器、数据处理、身份验证以及与 ClickHouse Cloud 的连接。
* **schema 与数据源：** 选择您的[表和 schema](/zh/clickstack/self-configured/ingesting-data/schemas)，并配置 UI 中的[数据源](/zh/clickstack/self-configured/managing/config)以便对其进行查询。
* **容量与性能：** [估算资源](/zh/clickstack/self-configured/managing/estimating-resources)，进行资源规模规划并配置扩缩容，同时随着工作负载的变化[调优性能](/zh/clickstack/self-configured/managing/performance-tuning)。
* **保留期限：** 设置[数据保留策略](/zh/clickstack/self-configured/managing/ttl)，在调查需求与存储成本之间取得平衡。

ClickHouse Cloud 负责管理底层基础设施、数据库升级和备份，但您仍需负责数据库调优和容量规划。

## 功能 {#features}

* 通过 [MCP](/zh/clickstack/observability/mcp) 接入您自己的 agent，即可搜索遥测数据、追踪链路、分析模式与变化，以及运行 SQL。
* 搜索并关联日志、链路追踪、指标和会话回放。完整追踪请求路径：从浏览器交互开始，经由后端服务，直至数据库查询。
* 使用[全文搜索和 Lucene 风格的筛选条件](/zh/clickstack/observability/features/search) (例如 `level:err`) 或 SQL，对 high-cardinality 遥测数据执行搜索和聚合。可查询日志和追踪跨度中的 JSON 字段及自定义属性。
* 使用 [AI 笔记本](/zh/clickstack/observability/notebooks)探索遥测数据，并[根据自然语言提问生成图表](/zh/clickstack/observability/text-to-chart)。
* 构建[仪表盘](/zh/clickstack/observability/features/dashboards/overview)、配置[告警](/zh/clickstack/observability/features/alerts)，并通过[深层链接](/zh/clickstack/observability/url-parameters)共享调查视图。
* 借助[事件模式](/zh/clickstack/observability/features/event-patterns)识别反复出现的故障，借助[事件差异](/zh/clickstack/observability/features/event-deltas)调查变化原因，并在新事件到达时实时查看 (live tail) 日志和链路追踪。
* 通过您自行运维的采集器摄取 OpenTelemetry 数据，自主掌控处理流程、表、schema 和数据保留策略。

## 原则 {#principles}

### 自带 agent {#bring-your-own-agents}

通过 MCP 接入您的团队已在使用的 agent 和开发工具。agent 可以基于与 UI 中相同的数据搜索日志、追踪链路，并识别模式和变化。它们还可以运行 SQL 来关联证据，并探究调查工具无法直接解答的问题。

### 易于使用且专为特定用途设计 {#user-friendly-purpose-built}

ClickStack 用户界面集搜索、trace 探索、图表、仪表盘和告警于一体。日常问题可借助 Lucene 风格的筛选条件和可视化查询构建器来解答；如需更精细地控制分析过程，再转用 SQL。

### 端到端可观测性 {#end-to-end-observability}

将前端会话回放与应用日志、分布式链路追踪和指标关联起来，跨整个系统追踪故障。宽事件将请求详情、自定义属性和业务上下文统一保存在日志和追踪跨度中，帮助工程师和 agent 快速定位受影响的请求、服务和客户。

### 专为 ClickHouse 打造 {#built-for-clickhouse}

ClickHouse 的列式存储、压缩和并行查询执行能力，可在海量 high-cardinality 遥测数据上实现快速搜索和聚合。借助并发查询，工程师和 agent 可以并行分析同一份数据。采用自管理部署时，您可以针对自身工作负载调优 schema、排序键和资源。

### OpenTelemetry 原生 {#open-telemetry-native}

通过标准的 OpenTelemetry 插桩、SDK 和采集器发送日志、链路追踪和指标。您负责运行摄取采集器，并配置它在将遥测数据写入 ClickHouse 之前如何处理这些数据。这样，您既可以沿用现有的插桩，又能自行掌控摄取管道。
