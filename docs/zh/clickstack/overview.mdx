**ClickStack** 是基于 ClickHouse 构建的开源可观测性平台，面向 SRE、开发人员及其 AI 智能体。您可以在一个平台中统一搜索、查询和关联日志、链路追踪、指标以及会话回放。

您可以通过 **ClickStack 用户界面**进行调查，也可以通过 [MCP 服务器](/zh/clickstack/mcp)接入自己的智能体。借助团队现有的开发工具，智能体可以搜索遥测数据、跟踪链路追踪，并对您在 UI 中探索的同一份数据执行 SQL。

丰富的日志和追踪跨度以宽事件的形式保留请求详情、自定义属性和业务上下文。ClickHouse 将这些数据与指标和会话数据存储在一起，使工程师和智能体能够跨服务关联证据，调查哪些请求和客户受到了影响。

<Tip>
  由 [ClickHouse Observability](/zh/clickstack/observability) 管理基础设施，您只需专注于调查问题。[注册 ClickHouse Cloud](https://clickhouse.cloud/signUp?loc=docs-clickstack-overview-inline) 即可开始使用。
</Tip>

## 功能 {#features}

* 通过 [MCP](/zh/clickstack/mcp) 接入您自己的智能体，用于搜索遥测数据、调查故障以及管理仪表盘和告警
* 在 ClickStack 用户界面中搜索和关联日志、指标、会话回放和链路追踪
* 与 schema 无关，可直接基于您现有的 ClickHouse schema 运行
* 对 high-cardinality 遥测数据执行快速搜索和聚合
* 使用全文搜索和 Lucene 风格的筛选条件 (例如 `level:err`) ，或使用 SQL 进行更深入的分析
* 只需点击几下即可设置告警
* 无需复杂的查询语言即可将高基数事件可视化
* 原生 JSON 字符串查询
* 实时查看日志和链路追踪的尾部，始终获取最新事件
* 开箱即用支持 OpenTelemetry (OTel)
* 从 HTTP 请求到 DB 查询 (APM) 监控健康状况和性能
* 使用 Event deltas 识别异常和性能回归
* 日志模式识别
* 使用 URL 查询参数通过[深层链接](/zh/clickstack/url-parameters)直接打开 ClickStack 页面

这些组件可以一同部署，构成完全**自管理的 ClickStack 开源版**环境。请参阅[架构指南](/zh/clickstack/architecture)，了解各组件如何协同工作以及应用程序状态的存储方式。

此外，ClickStack 用户界面还提供浏览器托管版本，用户可直接连接到现有的 ClickHouse 部署，无需额外部署 UI 基础设施。

如需开始使用，请先阅读[入门指南](/zh/clickstack/getting-started/oss)，然后加载[样本数据集](/zh/clickstack/example-datasets/index)。您还可以查阅[部署选项](/zh/clickstack/deployment/oss)和[生产环境最佳实践](/zh/clickstack/managing/production)相关文档。

<div id="clickstack-principles">
  ## 原则 {#clickstack-principles}
</div>

### 自带智能体 {#bring-your-own-agents}

AI 辅助调查是 ClickStack 的核心工作流。通过 [MCP 服务器](/zh/clickstack/mcp) 连接您偏好的智能体，无需离开开发环境，即可搜索日志、追踪链路追踪并探索遥测数据。

调查工具可满足常见任务需求，而借助 SQL，智能体还能关联各类证据，探索预定义仪表盘无法覆盖的问题。智能体和模型由您自行选择；ClickStack 则为其提供与您团队同等的遥测数据和调查工具访问权限。

<div id="clickstack-easy-to-setup">
  ### 几分钟内即可轻松完成设置 {#clickstack-easy-to-setup}
</div>

ClickStack 可与任何 ClickHouse 实例和 schema 开箱即用，只需极少配置。无论你是从零开始，还是集成到现有环境中，都能在几分钟内完成部署并开始使用。

### 易于使用且专为特定用途设计 {#user-friendly-purpose-built}

ClickStack 用户界面集搜索、trace 探索、图表、仪表盘和告警于一体。日常问题可借助 Lucene 风格的筛选条件和可视化查询构建器来解决；如需对分析进行更精细的控制，则可改用 SQL。工程师与智能体基于同一份数据开展工作，因此您可以查看每次调查背后的依据。

### 端到端可观测性 {#end-to-end-observability}

将前端会话回放与应用日志、分布式链路追踪和指标关联起来，跨整个系统追踪故障。宽事件将请求详情、自定义属性和业务上下文统一保存在日志和追踪跨度中，帮助您快速定位受影响的请求、服务和客户。

### 专为 ClickHouse 打造 {#built-for-clickhouse}

ClickHouse 的列式存储、压缩和并行查询执行能力，可对海量 high-cardinality 遥测数据进行快速搜索与聚合。借助并发查询，工程师和智能体可以并行调查同一份数据。

<div id="open-telemetry-native">
  ### OpenTelemetry 原生 {#open-telemetry-native}
</div>

ClickStack 与 OpenTelemetry 原生集成，所有数据都通过 OpenTelemetry 收集器端点进行摄取。对于高级用户，它还支持使用原生文件格式、自定义管道或 Vector 等第三方工具，直接将数据摄取到 ClickHouse。

<div id="open-source-and-customizable">
  ### 开源且完全可定制 {#open-source-and-customizable}
</div>

ClickStack 是完全开源的，可部署在任何环境中。schema 灵活且支持用户修改，UI 也经过设计，可适配自定义 schema 而无需变更。所有组件 (包括采集器、ClickHouse 和 UI) 都可以独立扩缩容，以满足摄取、查询或存储需求。
