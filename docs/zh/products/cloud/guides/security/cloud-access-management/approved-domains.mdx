借助已批准域名功能，新用户可以根据其电子邮件域名加入您的 ClickHouse Cloud 组织。验证您拥有的域名后，您可以自动添加匹配的用户或向其发送邀请，并为其分配默认角色。

本指南介绍如何添加和验证域名、配置注册方式，以及管理已批准域名。

## 开始之前 {#before-you-begin}

您需要拥有管理组织设置的权限，并能够在域名的 DNS 设置中添加 TXT 记录。

<Note>
  已批准域名功能适用于未使用 SAML 单点登录或 SCIM 的组织。如果您的组织使用身份提供商，请参阅 [SAML 单点登录设置](/zh/products/cloud/guides/security/cloud-access-management/saml-sso-setup)指南。
</Note>

## 工作原理 {#how-it-works}

用户首次创建 ClickHouse Cloud 账户时，ClickHouse 会将其电子邮件域名与已批准域名进行比对。每个匹配的组织都会应用其已配置的注册方式和默认角色。

| 注册方式                   | 行为                                    |
| ---------------------- | ------------------------------------- |
| **Join automatically** | 用户会被添加到该组织。随后，控制台会提示用户确认其访问权限并打开一个组织。 |
| **Send an invite**     | 用户会收到邀请，必须接受邀请后才能加入该组织。               |

注册仅适用于新账户。如需添加现有用户，请[发送邀请](/zh/products/cloud/guides/security/cloud-access-management/manage-cloud-users)。

电子邮件域名必须完全匹配。例如，`example.com` 可匹配 `user@example.com`，但无法匹配 `user@team.example.com`。子域名需单独添加并验证。

如果多个组织批准了同一域名，则各组织会分别应用各自的注册设置。被自动添加到多个组织的用户可以自行选择要打开的组织。

## 添加并验证域名 {#add-and-verify-a-domain}

<Steps>
  <Step title="打开已批准域名" id="open-approved-domains">
    在 ClickHouse Cloud 控制台中，打开组织设置。在 **已批准域名** 下，点击 **Add domain**。
  </Step>

  <Step title="添加域名" id="add-your-domain">
    输入您的电子邮件域名 (例如 `example.com`) ，然后点击 **Add**。

    每个组织最多可添加 20 个域名，其中包括待验证的域名。公共邮箱域名和一次性邮箱域名 (例如 `gmail.com`) 无法获得批准。
  </Step>

  <Step title="配置注册方式和默认角色" id="configure-enrollment-and-default-roles">
    为该域名选择 **Auto-enrollment** 方式和 **默认角色**。

    新添加的域名默认使用 Send an invite 方式和 Member 角色。域名验证成功后才会开始注册。

    您可以选择一个或多个角色，**包括自定义角色**。列表中仅显示您有权分配的角色。具有组织管理权限的角色 (例如 **Admin**) 不可选择。

    如果所选角色被删除或不再可分配，该角色将从域名配置中移除。如果所选角色均已移除，新用户将获得 Member 角色。
  </Step>

  <Step title="添加 DNS 记录" id="add-the-dns-record">
    按照控制台中显示的值，在您的 DNS 提供商处创建一条 TXT 记录：

    | 字段            | 值                                                         |
    | ------------- | --------------------------------------------------------- |
    | Name/Host     | 显示的 **TXT record name**：`@`，或您的提供商用于表示域名本身的等价写法。          |
    | Value/Content | 完整的 **TXT record value**，以 `clickhouse-verification=` 开头。 |

    添加此记录时，请保留现有的 TXT 记录。
  </Step>

  <Step title="验证域名" id="verify-the-domain">
    返回 ClickHouse Cloud，点击未验证域名旁的刷新图标。验证成功后，其状态将变为 **Verified**。

    DNS 变更可能需要一段时间才能生效。如果验证未能立即成功，请稍候再试。
  </Step>
</Steps>

## 更新注册设置 {#update-enrollment-settings}

打开 **已批准域名**，然后更改该域名的 **默认角色** 或 **Auto-enrollment** 设置。更改会自动保存，并对之后的注册生效。

如需更新现有成员的角色，请参阅[管理用户角色分配](/zh/products/cloud/guides/security/cloud-access-management/manage-cloud-users#manage-role-assignments)。

## 删除域名 {#remove-a-domain}

打开 **已批准域名**，然后点击对应域名旁边的垃圾桶图标。

删除域名后，用户将无法再通过该域名注册。现有成员和邀请不受影响。如有需要，请另行移除成员或取消邀请。

## 限制 {#limitations}

* 注册仅在用户首次创建账户时执行，不会追溯添加现有用户。
* 已离开或被移出组织的用户再次登录时，不会被自动重新添加。
* 不会为现有成员和未过期的邀请创建重复项。
* 组织成员资格限制仍然适用。
* 配置 SAML 单点登录或启用 SCIM 后，基于已批准域的注册将停止。

## 故障排查 {#troubleshooting}

### “已批准域名”不显示或无法编辑 {#approved-domains-missing}

使用 SAML 单点登录的组织不会显示此部分。要编辑已批准域名，您需要具备管理组织设置的权限。

### 域名验证失败 {#domain-verification-fails}

请检查 TXT 记录是否添加在正确的域名上，且其值与控制台中当前显示的值匹配。等待 DNS 传播完成后再重试。

如果控制台提示令牌已过时，请将验证值替换为当前显示的值。如果验证请求已过期，请重新开始验证。

### 域名被拒绝 {#domain-rejected}

请确认该域名不是公共邮箱域名或一次性邮箱域名，并且您的组织中已验证和未验证的域名总数少于 20 个。

### 未能添加用户 {#user-not-added}

请确认以下事项：

* 该用户正在创建新的 ClickHouse Cloud 账户。
* 其电子邮件域名与某个已验证的域完全匹配。
* 该组织未使用 SAML 单点登录或 SCIM。
* 该组织具有邀请成员的权限。

如果选择了 **Send an invite**，用户须先接受邀请才能成为成员。对于已有账户，请通过 **用户和角色** 发送邀请。
