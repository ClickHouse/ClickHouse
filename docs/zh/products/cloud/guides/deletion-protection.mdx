服务删除保护是一项按服务单独配置的设置，开启后，在您将其关闭之前，该服务无法被删除。如果您希望防止某些 ClickHouse Cloud 服务在 Cloud 控制台中、通过 [ClickHouse Cloud API](/zh/cloud/manage/api/api-overview) 或使用 Terraform 时被误删，请为其启用此设置。

<Note>
  此功能适用于 ClickHouse Cloud 服务，不适用于 [ClickHouse Managed Postgres](/zh/cloud/managed-postgres) 服务。
</Note>

删除保护默认处于关闭状态。关闭保护并不会删除服务。受保护的服务会照常运行，查询、扩缩容及其他设置均不受影响。

保护开启期间，所有删除请求都会被拒绝：在您关闭保护之前，`DELETE /v1/organizations/{organizationId}/services/{serviceId}` 会返回 HTTP `409`。此外，服务必须先停止才能删除，随后删除操作将以异步方式执行。

## 谁可以更改 {#who-can-change-it}

开启或关闭保护需要 [`control-plane:service:delete`](/zh/cloud/security/console-roles) 权限。组织管理员拥有此权限。请参阅[控制台角色和权限](/zh/cloud/security/console-roles)。

开启保护还要求该组织支持删除保护功能。ClickHouse Cloud 组织均支持该功能。如果组织不支持，则将 `deletionProtection` 设置为 `true` 的创建或更新请求会返回 HTTP `400`。关闭保护时不会执行该检查：将 `deletionProtection` 设置为 `false` 的请求始终会被接受，即使服务已处于保护状态也是如此。

| 操作                                | 权限                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------ |
| 开启或关闭控制台中的开关                      | 该服务上的 `control-plane:service:delete`                                                       |
| 为现有服务设置 `deletionProtection`      | 该服务上的 `control-plane:service:manage` 和 `control-plane:service:delete`                      |
| 发送与服务当前设置相同的值                     | 仅需 `control-plane:service:manage`。重复发送当前值不需要 `control-plane:service:delete`                |
| 创建 `deletionProtection: true` 的服务 | `control-plane:organization:create-service`，以及针对组织内所有服务已授予的 `control-plane:service:delete` |
| 删除服务                              | 该服务上的 `control-plane:service:delete`。服务必须处于已停止状态，且保护必须已关闭                                  |

ClickStack 服务无法通过云 API 更新，请在控制台中开启或关闭其删除保护。

## 在控制台中开启或关闭保护 {#console}

打开该服务，进入 **设置**，在 **删除保护** 下切换开关即可。更改会立即保存。

凡是对该服务拥有 `control-plane:service:delete` 权限的用户，均可使用此开关。保护开启期间，控制台会拒绝执行删除操作，直至您关闭该开关。

## 通过云 API 设置 {#cloud-api}

服务对象包含一个布尔类型字段 `deletionProtection`。您可以在创建服务 (`POST /v1/organizations/{organizationId}/services`) 或更新服务 (`PATCH /v1/organizations/{organizationId}/services/{serviceId}`) 时设置该字段。获取服务和列出服务的响应中均包含该字段。若响应中没有该字段，则表示该服务未启用保护。

启用保护：

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": true}'
```

要删除受保护的服务，请先关闭保护，再停止该服务，待其完全停止后再删除。使用 `"command": "stop"` 调用 `PATCH .../state` 需要 `control-plane:service:manage` 权限，且该请求会在服务实际停止之前返回。如果服务仍处于 `stopping` 状态，删除请求将被拒绝。对受保护的服务发起删除请求会返回 `409`，服务将保持不变。

关闭保护：

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": false}'
```

发送停止请求：

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID/state" \
  -d '{"command": "stop"}'
```

等待 `result.state` 变为 `stopped` 后，再执行删除：

```bash
while [ "$(curl --silent --user "$KEY_ID:$KEY_SECRET" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  | jq -r '.result.state')" != "stopped" ]; do
  sleep 5
done

curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X DELETE \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID"
```

## Terraform {#terraform}

<Note>
  最新发布的 provider 版本 [v3.43.0](https://github.com/ClickHouse/terraform-provider-clickhouse/releases/tag/v3.43.0) 尚不支持 `deletion_protection`。该属性由 [terraform-provider-clickhouse#799](https://github.com/ClickHouse/terraform-provider-clickhouse/pull/799) 引入，该 PR 已合并，但尚未包含在任何发行版中。在 v3.43.0 上运行下面的示例时，会因参数不受支持而报错。请使用 v3.43.0 之后已包含该属性的 provider 发行版。
</Note>

`clickhouse_service` 资源支持 `deletion_protection` 参数。当其值为 `true` 时，`terraform destroy` 以及任何会导致替换该服务的变更都会失败。如需销毁服务，请先将其设置为 `false` 并单独应用该变更，然后再执行销毁。

从配置中移除 `deletion_protection` 不会改变当前的设置。

```hcl
resource "clickhouse_service" "example" {
  # ...

  deletion_protection = true
}
```

创建服务时若设置 `deletion_protection = true`，所用的 API key 必须有权删除该组织中的所有服务。之后若要更改此设置，则需要拥有该服务的删除权限。
