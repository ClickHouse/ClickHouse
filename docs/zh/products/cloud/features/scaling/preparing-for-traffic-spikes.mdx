<Note>
  **本页适用于 Scale 和 Enterprise 服务。**

  * **基础套餐：** 基础版服务的规格固定，无法扩缩容。如果您使用的是基础版服务且预计会出现流量高峰，请升级您的 [Cloud 层级](/zh/products/cloud/features/cloud-tiers)。
  * **自备 Cloud (BYOC)：** 以下步骤同样适用，但由于您的服务运行在您自己的云账户中，请确保账户具备足够的配额和容量，以应对预期峰值。
</Note>

许多工作负载都存在可预测的高需求时段，例如零售和购物活动、产品发布、季度末报表以及营销活动等。自动扩缩容会随负载变化实时响应，但对于已知即将到来的峰值，通常最好提前扩容。

在整体需求旺盛的时期，各云服务提供商的容量可能比平时更为紧张，较大的实例规格和部分区域尤其如此。提前扩容有助于确保获得所需容量，并留出充足时间在峰值到来前确认服务已准备就绪。

<Note>
  **即将到来的峰值：2026 年 Black Friday 和 Cyber Monday**

  如果您预计 2026 年 11 月 27 日至 30 日前后流量会上升，建议在 **11 月 20 日**前完成扩容，并保持扩容状态至 **12 月 1 日**。如果您计划扩容至超出服务允许的副本数量上限，请在 **11 月 13 日**前联系我们 (参见下文第 3 步) 。
</Note>

## 高峰期之前 {#before-the-peak}

1. 设置监控和告警，以便在高峰期间及时发现任何变化。为扩缩容事件、错误和计费配置电子邮件和/或 Slack [通知](/zh/products/cloud/features/monitoring/notifications)。如果您使用外部监控工具，请通过 [Prometheus 端点](/zh/products/cloud/features/monitoring/prometheus) 接入，并针对 CPU 和内存利用率设置告警。
2. 估算预期负载：查看您的服务在以往高峰期间的表现，并估算查询量和写入量可能的增长幅度。要查看每个副本的历史 CPU 和内存利用率，请访问服务的基础设施仪表盘 (**监控 &gt; 基础设施**) ，或参阅 [应对工作负载峰值](/zh/products/cloud/features/autoscaling/scheduled-scaling#handling-bursty-workloads)。
3. 提前告知大规模扩容计划：如果您计划将服务扩容到超出允许的副本数量，请至少在高峰期前两周联系您的客户团队或 ClickHouse 支持团队。这有助于我们提前与云服务提供商规划容量。请在请求中提供以下信息：

   1. 服务名称和区域
   2. 目标规模 (每个副本的内存和副本数量)
   3. 开始和结束日期

   <Note>
     容量取决于云服务提供商的资源可用性，因此我们无法保证特定规模在指定时间一定可用。尽早告知我们，我们才能最大程度地为您预留所需容量。
   </Note>
4. 提前扩容：请在高峰期前几天完成扩容，而不要等到高峰开始当天。这样您就有时间确认服务在新规模下正常运行，并在必要时进行调整。您可以在 ClickHouse Cloud 控制台的 **Settings &gt; 扩缩容** 中，或通过 [ClickHouse Cloud API](/zh/products/cloud/features/admin-features/api/api-overview) 更改服务的扩缩容设置。
5. 检查自动扩缩容设置：如果您的服务启用了自动扩缩容 (纵向或横向) ，请在高峰期前检查相关上下限：
   1. **提高最小值**，使整个高峰期间都保有充足容量，而不必等待自动扩缩容做出响应。
   2. **提高最大值**，以便在负载超出预估时，自动扩缩容仍有扩展余地。
   3. **检查空闲设置。** 对于延迟敏感型服务，可考虑在高峰期间禁用空闲功能，避免流量到达时还需等待服务唤醒。
   4. **检查所有扩缩容计划。** 扩缩容计划触发时，其优先级高于自动扩缩容设置。请暂停或调整任何会在高峰期间缩容服务的计划，例如周末或夜间的 scale-down。
6. 在新规模下进行测试：服务扩容完成后，请尽可能运行模拟高峰流量的负载测试。这有助于确认新规模足以应对预期的流量激增，并在必要时及时采取纠正措施。

## 高峰过后 {#after-the-peak}

需求恢复正常后，请在控制台中或通过 API 将服务恢复为平时的扩缩容设置。建议为结束日期设置提醒，以免服务维持扩容状态的时间超出实际需要。

对于具有固定每日或每周规律的工作负载 (例如夜间批处理作业或工作时段流量) ，请使用[定时伸缩](/zh/products/cloud/features/autoscaling/scheduled-scaling)自动进行扩容和缩容。

## 计费 {#billing}

服务以扩容后的规格运行期间，将一直按该规格计费。为应对峰值而扩容，会增加您在该时段内的费用。
