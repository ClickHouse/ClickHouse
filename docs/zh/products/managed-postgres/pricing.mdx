ClickHouse Managed Postgres 基于本地 NVMe 存储构建，因此无需承担传统网络附加存储架构带来的额外成本，即可提供 production-grade 性能和原生 ClickHouse 集成。本页介绍该服务的定价模式、可用的实例类型，以及各层级之间的对比。

</Tip>

<div id="price-performance">
  ## 性价比 {#price-performance}
</div>

由于该服务运行在本地 NVMe 存储上，相较于传统的网络附加存储架构，许多工作负载都能实现显著更高的性价比。有关在类似硬件配置下与其他 Postgres 提供商进行基准测试对比的信息，请参阅 [PostgresBench](https://postgresbench.clickhouse.com/)。

对于相当的工作负载，客户所需的计算资源最多可降至原来的 1/2 到 1/4。在比较不同提供商的定价时，应将这些潜在的效率提升考虑在内；不过，实际提升会因工作负载而异，仍需结合您的具体应用进行验证。

<div id="pricing-model">
  ## 定价模式 {#pricing-model}
</div>

该服务运行在本地 NVMe 存储上，因此定价依据完整的 VM 配置——CPU、内存和存储——而不是将 compute 和 disk 分开计费。

提供 50 多种配置，范围从 1 vCPU / 8 GB RAM / 59 GB NVMe 到 96 vCPU / 768 GB RAM / 60 TB NVMe 存储，可灵活满足计算密集型和存储密集型的 Postgres 工作负载需求。

### 实例类型 {#instance-types}

实例配置分为三个类别，便于根据工作负载特征选择合适的基础设施。并非所有区域都提供全部实例类型。GCP 目前处于私有预览阶段。

* **内存优化型：** 专为内存密集型工作负载设计，内存与 CPU 的比率为 1:8。在 AWS 上，支持基于 x86 的 `r8id` 和 `r6id` 家族，以及基于 ARM64 (AWS Graviton) 的 `r8gd` 和 `r6gd` 家族。在 GCP 上，支持基于 x86 的 `n2` 和 `n2d` 家族。最适合大型工作集、高缓存命中率场景以及受内存限制的数据库工作负载。
* **存储优化型：** 专为需要大量本地 NVMe 存储、但无需按比例扩容计算资源的工作负载设计。在 AWS 上，支持基于 ARM64 (AWS Graviton) 的 `i8g` 和 `i8ge` 家族，以及基于 x86 的 `i7i` 和 `i7ie` 家族，部分配置最高可提供 60 TB 本地 NVMe 存储。在 GCP 上，支持基于 x86 的 `z3` 家族。最适合大型数据集、时间序列工作负载、日志与事件存储，以及 storage-heavy 的 OLTP 工作负载。
* **CPU 优化型：** 专为计算密集型工作负载设计，内存与 CPU 的比率为 1:4。在 AWS 上，支持基于 x86 的 `m8id` 和 `m6id` 家族，以及基于 ARM64 (AWS Graviton) 的 `m8gd` 和 `m6gd` 家族。在 GCP 上，支持基于 x86 的 `n2` 和 `n2d` 家族。最适合高并发度的事务性工作负载以及 CPU-bound 查询。

## 云服务提供商定价 {#cloud-provider-pricing}

### AWS 定价 {#aws-pricing}

在 AWS 上，Managed Postgres 已正式可用，自 **2026 年 11 月 9 日**起按以下方式计费：

* **备份：** 包含与已预配磁盘容量相等的备份存储。超出部分的备份存储按您所在区域的 ClickHouse Cloud 存储价格计费，例如在 `us-east-1` 中为每 TB 每月 $25.30。请参阅[备份与恢复](/zh/products/managed-postgres/backup-and-restore)。
* **数据传输：** 按 [ClickHouse Cloud 数据传输费率](/zh/products/cloud/reference/billing/network-data-transfer)计费。如果您的应用程序与 Managed Postgres 位于同一区域，并且 (在使用 ClickPipes 时) Managed Postgres 与 ClickHouse 也位于同一区域，网络费用预计会较低。
* **ClickPipes：** 将数据从 Managed Postgres 复制到 ClickHouse Cloud 所用的计算资源免费。从 Managed Postgres 到 ClickPipes 的出站流量按标准[数据传输费率](/zh/products/cloud/reference/billing/network-data-transfer)计量，因此只要 Managed Postgres 与 ClickHouse Cloud 位于同一区域，就不会产生网络费用。
* **WalShadow：** 私有预览期间，将数据从 Managed Postgres 复制到 ClickHouse Cloud 免费。

<Note>
  数据传输费用依据目标端 IP 是否属于云服务提供商公布的 IP 地址范围来分类。如果目标端 IP 不在您所在区域公布的地址范围内，发往该目标端的流量将按公网出站流量计量，即使该目标端托管在同一云服务提供商上也是如此，例如使用自有 IP 块 (BYOIP) 的 peer。如果您需要连接此类 peer，请联系[技术支持](https://clickhouse.com/support/program)，以便我们核查其分类。
</Note>

### GCP 私有预览定价 {#gcp-private-preview-pricing}

在私有预览期间，GCP 上的 ClickHouse Managed Postgres 可免费使用。私有预览结束后的定价方案仍在制定中。如需进一步了解，请联系我们，以获取最终定价的大致情况。您可以[在此](https://clickhouse.com/cloud/postgres#gcp-waitlist)加入 GCP 私有预览的候补名单。

## 服务停用 {#service-deactivation}

停用托管 Postgres 服务与停止 ClickHouse Cloud 服务类似。当您的组织不再满足计费合规要求时，服务即会被停用，所依据的条款和时间安排与其他 ClickHouse Cloud 服务相同。例如，试用期结束时仍未配置计费方式，或付款失败。具体规则请参阅 [ClickHouse Cloud 计费合规](/zh/products/cloud/reference/billing/billing-compliance)。

服务停用后：

* 现有连接会被阻断。
* 新连接会被阻断。
* 该服务不再计费。
* 您的数据和备份会被保留，不会被删除。有关数据和备份的保留策略，请参阅[计费合规](/zh/products/cloud/reference/billing/billing-compliance)。

要恢复服务运行：

1. 结清组织的未付余额。
2. 打开该服务的 **设置** 选项卡，然后点击 **Start**。请参阅[设置](/zh/products/managed-postgres/settings#service-actions)。

**Start** 按钮仅在服务停用后显示。组织账单未付清期间，该按钮处于禁用状态；账单付清后，该按钮即会启用。点击该按钮即可重新启动服务。

## 定价免责声明 {#pricing-disclaimers}

* 扩缩容和维护操作会在短时间内让新实例与旧实例并行运行，以保持数据库在线——在切换完成前，您可能会看到新旧两个实例的费用同时计费。这一时间窗口的长短会因实例类型和存储容量而异。
* 如果所选实例类型在部分可用区中的容量暂时受限，服务可能会回退到较旧代次中的相近实例类型，以维持所选的高可用性配置。您将按目标实例类型的费率计费。
