本指南介绍如何使用 Helm 图表安装 ClickHouse Operator。

## 前置条件 {#prerequisites}

* Kubernetes 集群 v1.28.0 或更高版本
* Helm v3.0 或更高版本
* 已将 kubectl 配置为与你的 Kubernetes 集群通信

## 安装 Helm {#install-helm}

如果您还没有安装 Helm：

```bash
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
```

验证安装：

```bash
helm version
```

## 安装 ClickHouse Operator {#install-the-operator}

<Note>
  默认情况下，Helm 图表会在启用 webhooks 的情况下部署 ClickHouse Operator，并且要求已安装 cert-manager。
</Note>

```bash
helm install cert-manager oci://quay.io/jetstack/charts/cert-manager -n cert-manager --create-namespace --set crds.enabled=true
```

### 通过 OCI Helm 仓库 {#from-oci-helm-repository}

安装最新版本

```bash
    helm install clickhouse-operator oci://ghcr.io/clickhouse/clickhouse-operator-helm \
       --create-namespace \
       -n clickhouse-operator-system
```

安装特定版本的 Operator

```bash
    helm install clickhouse-operator oci://ghcr.io/clickhouse/clickhouse-operator-helm \
       --create-namespace \
       -n clickhouse-operator-system \
       --set manager.image.tag=<operator version>
```

### 从本地图表安装 {#from-local-chart}

克隆代码仓库，并通过本地图表安装：

```bash
git clone https://github.com/ClickHouse/clickhouse-operator.git
cd clickhouse-operator
helm install clickhouse-operator ./dist/chart
```

### 监视特定命名空间 {#watch-namespaces}

默认情况下，operator 会监视所有命名空间。可通过设置 `controller.watchNamespaces` 来限制监视范围。
其中的各个条目会作为模板进行渲染，因此 `{{ .Release.Namespace }}` 会解析为该 release 所在的命名空间，
还可以与静态命名空间组合使用：

```yaml
controller:
  watchNamespaces:
    - "{{ .Release.Namespace }}"
    - team-a
```

在命令行中，`--set` 会将花括号解析为列表语法，因此请改用 `--set-json` (需要 Helm v3.10 或更高版本) ：
`--set-json 'controller.watchNamespaces=["{{ .Release.Namespace }}"]'`。

如需仅监视 release 所在的命名空间，并使用命名空间级别的 RBAC：

```yaml
controller:
  watchNamespaces:
    - "{{ .Release.Namespace }}"
rbac:
  namespaced: true
```

设置 `rbac.namespaced: true` 后，manager 的权限将以 Role/RoleBinding 的形式创建在 release 所在的命名空间中，
因此，若要监视其他命名空间，则需使用集群范围的 RBAC (即默认配置) 。
