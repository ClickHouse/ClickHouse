## 组件 {#components}

ClickHouse 连接器运行三个守护进程，它们均内置于 `clicklink` 二进制文件中：

* **executor (executor)&#x20;**&#x20;与连接器端点之间保持一条出站命令通道，并执行 ClickHouse Cloud 针对其在你的集群中所管理的服务下发的生命周期命令。这些命令包括创建、扩缩容、停止与启动、重启、备份与删除备份、删除，以及你已批准的平台更新。它执行的每一项操作都是一次 Kubernetes API 调用。它不会与 ClickHouse 建立任何连接，也不持有你的桶或 IAM 凭证。它仅在托管模式下运行。
* **抓取器 (scraper)&#x20;**&#x20;按固定时间间隔读取允许列表中的 ClickHouse 系统表，并将结果缓存在本地，随后连同基础设施元数据与健康状况一并发送至你的连接器端点。
* **故障排查工具 (troubleshooter)&#x20;**&#x20;与连接器端点之间保持一条出站命令通道，并在处于活动状态的[支持会话](/zh/products/bring-your-own-cloud/connector/support-sessions)期间运行只读诊断。在会话之外，它不执行任何操作。

在 Kubernetes 上，`clicklink-connector` Helm 图表会将这些守护进程部署到你指定的命名空间中 (默认为 `clicklink`) 。executor 是一个单副本 Deployment，其命令状态保存在持久卷上。在 Linux VM 上，这些守护进程以 `clicklink-scraper`、`clicklink-troubleshooter` 和 `clicklink-executor` 三个 systemd 单元的形式，在无特权的 `clicklink` 系统用户下运行。

## 连接 {#connections}

连接器发起的所有连接均为出站连接。完整列表如下：

| 目标                                          | 方向           | 协议                 | 身份验证                                                                   | 用途                                                                                                                        |
| ------------------------------------------- | ------------ | ------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 您的连接器端点 (API)                               | 出站           | HTTPS              | mTLS 客户端证书 + HMAC 签名请求                                                 | 发送指标、连接器自身指标和状态；同步服务、基础设施和备份元数据；续订客户端证书                                                                                   |
| 您的连接器端点 (API，由 `clicklink clctl` 发起)        | 出站           | HTTPS              | 连接器的 mTLS 客户端证书 + HMAC 签名请求                                            | 在您运行 `clicklink clctl instances create` (`POST /v1/pcm/instances`) 时提交服务定义                                                |
| 您的连接器端点 (故障排查工具命令通道)                        | 出站           | 基于 TLS 的 WebSocket | mTLS 客户端证书 + HMAC 签名握手                                                 | 仅在 support session 处于活动状态时传输诊断命令                                                                                          |
| 您的连接器端点 (executor 命令通道)                     | 出站           | 基于 TLS 的 WebSocket | mTLS 客户端证书 + HMAC 签名握手                                                 | 传输 managed service 的生命周期命令，并返回其进度和结果；与故障排查工具通道相互独立                                                                        |
| 您的注册端点                                      | 出站           | HTTPS              | 一次性注册令牌 (兑换时) 或 HMAC (首次证书签名时) ；不使用 mTLS                               | 在设置期间兑换令牌并签发首个证书                                                                                                          |
| 您的 ClickHouse 集群                            | 出站，位于您的环境内部  | ClickHouse 原生协议    | 专用只读用户 `pcm_scraper` 和 `pcm_troubleshooter`，以 bcrypt 哈希形式存储            | 读取系统表以进行抓取和会话诊断，以及抓取器刷新日志表。executor 不建立任何 ClickHouse 连接                                                                   |
| Kubernetes API server (所有已配置的部署，两种安装目标均适用)  | 出站，位于您的环境内部  | HTTPS              | 绑定到 Role 的 ServiceAccount；托管模式下为 `pcm-executor` ServiceAccount，受准入策略约束 | 为故障排查工具提供只读工作负载视图；executor 在服务命名空间内执行生命周期写入，并在经批准的平台更新期间于平台命名空间内执行工作负载写入；在 Kubernetes 安装中，守护进程还会将自动续订的客户端证书写回 mTLS Secret |
| Amazon ECR (executor，仅限托管模式)                | 出站           | HTTPS              | 直接平台访问：通过连接器 EC2 VM 的实例配置文件代入只读拉取角色；其他 ECR 图表 registry：使用环境中的 AWS 凭证   | 登录 registry，拉取用于平台同步或创建的图表；在平台更新期间调用 `DescribeImages` 以确认镜像存在                                                             |
| AWS STS (executor，仅限托管模式)                   | 出站           | HTTPS              | 直接平台访问：使用连接器 EC2 VM 的实例配置文件；其他 ECR 图表 registry：使用已配置的 AWS 凭证链          | 代入只读拉取角色，用于直接平台图表登录和镜像检查；也可能为其他 ECR 登录提供凭证。ECR 和 STS 是 executor 仅有的云 API 调用                                               |
| 容器 registry                                 | 出站，由您的集群节点发起 | HTTPS              | 您的节点身份：ClickHouse 向您所注册的节点角色授予的只读拉取角色；或在您导入镜像后使用您自己的 registry          | 为 managed service 和平台组件拉取镜像。由您的集群主动拉取；ClickHouse 不会向其推送任何内容                                                               |
| 您的身份提供商的 JWKS 端点 (仅在启用网关时)                  | 出站           | HTTPS              | 无 (公开签名密钥)                                                             | 验证提交给会话网关的 OIDC ID 令牌                                                                                                     |

每个 API 请求都带有 `Authorization` 标头，其中包含基于请求方法、路径、时间戳和请求体哈希计算的 HMAC-SHA256 签名。因此，即使在 TLS 通道内，请求在传输过程中也无法被重放或篡改。

入站方面，每个守护进程仅开放一个本地健康检查端口：抓取器为 8082，故障排查工具为 8084，executor 为 8086。该端口提供 `/livez`、`/readyz`、`/healthz`，并通过 `/metrics` 提供守护进程的 Prometheus 指标；不另设指标端口。executor 的本地命令 API 仅绑定到回环地址，也没有任何 Service 对外公开它。除此之外，唯一的监听器是需手动启用的会话网关；请参阅 [support sessions](/zh/products/bring-your-own-cloud/connector/support-sessions)。ClickHouse Cloud 绝不会连接上述任何监听端口。

## 证书生命周期 {#certificate-lifecycle}

连接器使用自行获取并维护的客户端证书向你的端点进行身份验证。三个 守护进程 出示的是同一份证书。

* **注册。** `clicklink clctl init` 会在本地生成私钥和证书签名请求 (CSR) 。该 CSR 以你的 organization ID 作为通用名 (CN) ，并以你的端点 host 作为唯一的 DNS SAN。私钥始终不会离开你的环境。
* **首次签发。** `init` 以 HMAC 进行身份验证，将 CSR 提交到 `/v1/pcm/cert/sign` 注册签名端点。如果你的组织已存在未过期的证书，该端点会返回 409 拒绝请求，此时命令行客户端会提示如何沿用现有证书完成流程，或使用 `--force` 将其替换。
* **自动续订。** 三个 守护进程 每 12 小时检查一次证书有效期。当剩余有效期不足 10 天时，它们会通过 `/v1/pcm/cert/renew` (mTLS 加 HMAC) 申请一份有效期为 30 天的续订证书。在 Kubernetes 上，续订后的证书会借助精确名称的 RBAC grant 写回 `clicklink-mtls` Secret；在 VM 上，每个 守护进程 会将其写入 `/etc/clicklink/tls`。续订过程无需 operator 干预。

连接器会对照系统 trust store 校验你的端点所出示的服务器证书。若设置了 `api.tls.ca_file` (VM) 或 `api.tls.caFile` (Helm) ，则会将 enrollment bundle 中的 CA 证书链追加到这些根证书之后。

### 哪些数据会离开您的环境 {#what-leaves}

* **来自允许列表中系统表的指标。** 抓取器默认采集的系统表为 `metric_log`、`asynchronous_metric_log`、`tables`、`warnings` 和 `server_settings`。允许列表需显式配置，抓取器不会读取列表之外的任何内容。
* **基础设施元数据。** 通过 API 同步的服务、基础设施和备份清单。对于托管服务，包括其状态、当前副本数与预期副本数，以及正在运行的服务器版本和配置版本。
* **健康状况与自身指标。** 组件状态以及连接器自身的运行指标。executor 的心跳还会报告其命令通道是否已连接，并附带上一次平台更新的结果、平台组件版本，以及最近一次应用的支持包的摘要。对于 VM 安装，还会报告其 Kubernetes 访问包的状态：`ok`、`expiring`、`expired` 或不存在。
* **命令结果。** executor 运行的每个生命周期命令在收敛过程中的进度，以及最终的成功或失败状态；失败时附带错误信息。
* **您提交的服务定义。** `clicklink clctl instances create` 会发送您的环境 ID、云厂商和区域、服务名称、存储桶名称和 IAM 角色 ARN，以及一个幂等键。此外还会发送 default 用户密码的两个哈希值 (SHA-256 和双重 SHA-1) 。
* **support session 输出。** 在您启用的会话期间运行的只读诊断结果，经脱敏处理后发送。

### 默认情况下绝不外传的内容 {#what-never-leaves}

* **抓取路径上的原始查询文本。** `system.query_log` 未包含在默认抓取集中，因为其查询相关列可能包含字面值，从而携带 PII 或密钥。若要重新加入，需要按部署逐一进行覆盖配置。默认的会话表允许列表中确实包含 `system.processes`，它会显示正在执行的查询文本；如需对其进行裁剪，请参阅[支持会话](/zh/products/bring-your-own-cloud/connector/support-sessions)。
* **你的表数据和备份。** 它们始终保留在你账户下的桶中。执行器不持有访问这些桶的凭据，也无法读取其中的数据。
* **凭据。** `init` 不会将任何凭据写入配置文件。ClickHouse 仅存储连接器用户密码的 bcrypt 哈希，密钥则保存在 Kubernetes Secrets 或主机上仅 root 可读的文件中。托管服务的 default 用户密码在你这一侧生成，且只显示一次；提交的只有其哈希值。抓取路径和同步路径都不会传输任何凭据。
* **未脱敏的故障排查工具输出。** 故障排查工具返回的所有内容在外传之前，都会先经过脱敏规则 (内置规则以及你自定义的规则) 处理。请参阅[支持会话](/zh/products/bring-your-own-cloud/connector/support-sessions)。

## 信任边界 {#trust-boundaries}

* **您的环境即边界。** ClickHouse Cloud 仅接收连接器发送的内容：抓取数据、心跳与状态、命令结果，以及活跃支持会话返回的内容。它从不主动向内发起连接。
* **会话网关归您所有。** 除非您选择通过 Ingress 将其暴露，否则只能在您的环境内部访问它 (在 Kubernetes 上通过 `kubectl port-forward`，在 VM 上则在本地访问) 。ClickHouse Cloud 从不连接它。
* **ClickHouse 访问为只读。** `pcm_scraper` 和 `pcm_troubleshooter` 用户持有按表授予的 `SELECT` 授权、抓取器的 `READ ON REMOTE` (`clusterAllReplicas()` 所需) ，以及一项仅限抓取器的 `SYSTEM FLUSH LOGS` 授权。不存在任何 `INSERT`、DDL 或用户管理授权。executor 没有 ClickHouse 用户。完整列表请参见[特权模型](/zh/products/bring-your-own-cloud/connector/reference/privilege-model)。
* **抓取器和故障排查工具无法更改您的集群。** 它们的 RBAC 来自连接器命名空间和服务命名空间中的角色。这些角色仅授予对工作负载资源的只读操作，以及按确切名称访问连接器自身 Secrets 的权限。不存在 `exec`、`delete` 或 `patch` 权限。
* **executor 以 `pcm-executor` 身份更改服务命名空间中的集群状态。** 它会创建和删除带有服务前缀 (默认为 `ns-`) 的命名空间，并通过删除 pod (容器组) 来重启它们。在这些命名空间内，它会写入 ClickHouseCluster、Backup 和 ScalingOverride 对象，以及服务所需的 Secrets、ServiceAccounts 和 Services。它还会写入为抓取器授予读取权限的角色和 RoleBinding。ValidatingAdmissionPolicy 会拒绝该 ServiceAccount 在前缀范围之外的任何写入。例外情况均位于其所属命名空间内：自身令牌的续期、`clicklink-instance-registry` ConfigMap，以及 (在 Kubernetes 上) mTLS Secret 中续期的客户端证书。策略无法评估时将按失败关闭 (fail closed) 处理。准入不作用于读取操作，因此它对这些资源类型的读取不受前缀限制。
* **executor 仅在您批准的更新期间以 `pcm-platform` 身份更改平台命名空间。** `clicklink clctl platform approve` 会为该身份签发有效期为 2 小时的令牌，且永不续期。凭借该令牌，executor 只能写入 Deployments、Services、ConfigMaps、Secrets、Jobs 和 PodDisruptionBudgets。Namespaces、CRDs、ServiceAccounts、RBAC、webhook 和准入配置、PriorityClasses 以及 StorageClass 均在批准过程中使用您的凭证应用。请参见[平台更新](/zh/products/bring-your-own-cloud/connector/platform-updates)。
* **executor 不持有访问您的桶或 IAM 的凭证。** `clicklink clctl executor prepare` 会为服务创建数据桶、备份桶及其 IAM 角色，`clicklink clctl executor teardown` 则负责删除它们。两者均使用您的凭证运行。该角色仅信任该服务的 pod (容器组) ，因此 executor 和 ClickHouse 都无法代入该角色。executor 仅会调用 Amazon ECR 和 STS 这两项云服务。当平台同步或创建操作需要拉取图表时，它会登录 registry。在平台更新期间，它会以只读拉取角色检查镜像。
* **网络策略。** 在 Kubernetes 上，图表会为每个守护进程渲染一个默认拒绝的 NetworkPolicy。出站流量仅允许发往 DNS、您为连接器端点列出的 CIDR，以及 Kubernetes API 服务器的 CIDR。抓取器和故障排查工具的策略还允许访问 ClickHouse Services，范围限于 executor 所管理的命名空间 (通过其打上的标签进行选择) 或您按名称列出的命名空间。executor 的策略不含 ClickHouse 规则。如果平台包的图表存放在 Amazon ECR 中，请将 ECR 和 STS 的地址范围 (或您的 registry 镜像) 添加到 `allowEgressCIDRs`，否则在强制执行策略的 CNI 下，同步将无法拉取图表。如果 CNI 不强制执行策略，则该策略不起作用。请参见[配置](/zh/products/bring-your-own-cloud/connector/configuration)。
* **VM 上的主机加固。** 各单元以不可登录的系统用户身份运行，并启用 `ProtectSystem=strict`、`NoNewPrivileges`、只读配置路径以及 FIPS 模式。

有关连接器的完整授权和 RBAC 规则，请参见[特权模型](/zh/products/bring-your-own-cloud/connector/reference/privilege-model)参考文档。如果由 ClickHouse 自行预配和运维集群，则信任模型有所不同；请参见 [BYOC 架构](/zh/products/bring-your-own-cloud/overview/architecture)和 [BYOC 特权](/zh/products/bring-your-own-cloud/reference/privilege)页面。
