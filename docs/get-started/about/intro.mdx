ClickHouse® is a high-performance, column-oriented SQL database management system (DBMS) for online analytical processing (OLAP). It is available as both an [open-source software](https://github.com/ClickHouse/ClickHouse) and a [cloud offering](https://clickhouse.com/cloud).

## What are analytics? {#what-are-analytics}

Analytics, also known as OLAP (Online Analytical Processing), refers to SQL queries with complex calculations (e.g., aggregations, string processing, arithmetic) over massive datasets.

Unlike transactional queries (or OLTP, Online Transaction Processing) that read and write just a few rows per query and, therefore, complete in milliseconds, analytics queries routinely process billions and trillions of rows.

In many use cases, [analytics queries must be "real-time"](https://clickhouse.com/engineering-resources/what-is-real-time-analytics), meaning they should return a result in less than one second.

## Row-oriented vs. column-oriented storage {#row-oriented-vs-column-oriented-storage}

Such a level of performance can only be achieved with the right data "orientation".
The difference is best explained with an example query running over 100 million rows of [real-world anonymized web analytics data](/get-started/sample-datasets/anon-web-analytics-metrica).

Databases store data in either a [row-orientation or column-orientation](https://clickhouse.com/engineering-resources/what-is-columnar-database).

In a database, data is stored on disk in chunks called <Tooltip headline="Blocks" tip="Blocks are the smallest units of data read from disk to memory. Usually fixed sizes such as 4 KB or 8 KB." cta="Read more" href="https://en.wikipedia.org/wiki/Block_(data_storage)">blocks</Tooltip>.
When an application or database requests data, the operating system's disk I/O subsystem reads the required blocks from disk into memory.

In a row-oriented database, consecutive table rows are sequentially stored one after the other.
This layout allows the database to retrieve rows quickly, as the column values of each row are stored together, however column operations common in analytical queries such as filters or aggregation are much slower than in a column-oriented database.
Even if only part of a block is needed for the query above, a row-oriented database would read the entire block into memory from disk.

In a column-oriented DBMS like ClickHouse, values of each column are stored sequentially one after the other on disk.
Because the block-wise storage and transfer from disk to memory is aligned with the data access pattern of analytical queries, only the columns required for a query are read from disk, avoiding unnecessary I/O for unused data.
This is [much faster](https://benchmark.clickhouse.com/) compared to row-based storage, where entire rows, including irrelevant columns, are read.

## What features does ClickHouse offer? {#features-clickhouse}

<AccordionGroup>

    <Accordion title="Performance" id="superior-query-performance">
        ClickHouse uses a sparse primary index - just a few megabytes per terabyte - which allows it to scale while pruning data quickly.
        Query caches, and advanced skip indices can be used to further accelerate performance.

        Inserts are streamed row by row or in batches, with writes optimized through part sorting and separation of reads and writes, delivering throughput without slowing queries.
        A parallelized, vectorized engine filters and aggregates data efficiently across a single server or hundreds of nodes using partial states, and there is support for sharding and shared processing across replicas.
    </Accordion>

    <Accordion title="Scalability" id="data-replication-and-integrity">
        ClickHouse scales both vertically and horizontally. It fully uses available machine resources and parallelizes reads at a low level.

        A decentralized architecture with sharding and replication enables horizontal scaling to hundreds of nodes and quadrillions of rows.

        ClickHouse Cloud builds on this foundation with separation of storage and compute: nodes read from a single authoritative copy in object storage, cache data locally, and scale compute dynamically both vertically and horizontally while all reads and writes stay consistent.

    </Accordion>

    <Accordion title="Data operations" id="powerful-data-operations">
        ClickHouse offers advanced features to manipulate, filter, and transform data efficiently.
        [Materialized views](/concepts/features/materialized-views) can be refreshable or incremental, with incremental views shifting compute from query time to insert time and dramatically accelerating repeated queries.

        Projections let you maintain the same data sorted in different ways, enabling ClickHouse to optimize for multiple access patterns and deliver consistently fast queries.
    </Accordion>

    <Accordion title="SQL support" id="sql-support">
        ClickHouse supports a [declarative query language based on SQL](/reference/home) that is identical to the ANSI SQL standard in many cases but massively extends it with [thousands of functions](/reference/functions). Supported query clauses include [`GROUP BY`](/reference/statements/select/group-by), [`ORDER BY`](/reference/statements/select/order-by), subqueries in [`FROM`](/reference/statements/select/from), [`JOIN`](/reference/statements/select/join) clause, [`IN`](/reference/statements/in) operator, [window functions](/reference/functions/window-functions/index) and scalar subqueries.
    </Accordion>

    <Accordion title="Full JOIN support" id="full-join-support">
        ClickHouse fully supports all standard join types and adds powerful non-equality capabilities such as ASOF join.

        Continuous improvements to join algorithms deliver market leading performance, allowing users to query across normalized datasets without extra preprocessing - keeping analytics flexible and removing the need for forced denormalization.
    </Accordion>

    <Accordion title="Full-text search" id="fts">
        ClickHouse delivers fast, scalable token based search through native inverted indexes built directly into the storage engine.

        Inverted indices enable analytics on large unstructured or semi-structured data at petabyte scale. This allows you to filter text precisely, then aggregate and join in the same SQL query in a fast and efficient manner.
    </Accordion>

    <Accordion title="High-reliability" id="fts">
        ClickHouse ensures reliability through its replication model, which uses Raft-based coordination via Keeper and provides either immediate or eventual consistency depending on requirements. This lightweight design enables replication across availability zones or even regions with high latencies, delivering high durability without heavy overhead.
        For long-term protection, backups can be written to object storage, giving teams confidence their data is safe and recoverable.

        Snapshots offer a lightweight means to create a point in time of your data.
    </Accordion>

    <Accordion title="Interoperability" id="integrations">
        ClickHouse offers support for [70+ file formats](/reference/formats) for ingestion and output, and an extensive [ecosystem of integrations](/integrations/home).

        You can read and write open table and lake formats such as Parquet, Iceberg, and Delta, with catalog integrations like AWS Glue and Unity which allows you to bring the performance of ClickHouse's query engine to your data lake.
    </Accordion>

</AccordionGroup>
