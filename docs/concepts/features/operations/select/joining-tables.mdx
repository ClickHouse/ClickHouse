This overview explains JOIN types and strictness. For complete syntax, see the [`JOIN` clause reference](/reference/statements/select/join). For prescriptive optimization guidance and worked examples, see [Minimize and optimize JOINs](/concepts/best-practices/minimize-optimize-joins).

## JOIN types and strictness {#join-types-and-strictness}

Every JOIN has a type and a strictness. The type determines which rows without a match are included in the result. The strictness determines how many matches are returned for each row. Which algorithms can execute a JOIN depends on both. For the complete syntax and the additional `SEMI`, `ANTI`, `CROSS`, and `PASTE` JOINs, see the [`JOIN` clause reference](/reference/statements/select/join#supported-types-of-join).

### `INNER JOIN` {#inner-join}

<Image img="/images/guides/join-algorithms/inner-join.png" size="sm" alt="Venn diagram of an INNER JOIN: only the intersection of left and right table rows with matching JOIN keys is returned, as the Cartesian product of the matching rows"/>

An `INNER JOIN` returns, for each pair of rows with matching JOIN keys, the columns of the left-hand row combined with the columns of the right-hand row. If a row has more than one match, all matches are returned, so the result contains the Cartesian product of the rows with the same key. The `INNER` keyword can be omitted.

### `LEFT`, `RIGHT`, and `FULL OUTER JOIN` {#outer-join}

<Image img="/images/guides/join-algorithms/outer-join.png" size="lg" alt="Venn diagrams of LEFT, RIGHT, and FULL OUTER JOIN: each returns the Cartesian product of matching rows, plus the non-matching rows of the left table, the right table, or both tables"/>

An outer JOIN returns the same rows as an `INNER JOIN` and also returns rows without a match:

- A `LEFT OUTER JOIN` also returns each left-hand row without a match, with default values in the columns of the right-hand table.
- A `RIGHT OUTER JOIN` also returns each right-hand row without a match, with default values in the columns of the left-hand table.
- A `FULL OUTER JOIN` returns the rows without a match from both tables.

The [`join_use_nulls`](/reference/settings/session-settings/join#join_use_nulls) setting makes ClickHouse return `NULL` instead of default values. The `OUTER` keyword can be omitted.

### `ALL` and `ANY` strictness {#all-and-any-strictness}

<Image img="/images/guides/join-algorithms/any-join.png" size="lg" alt="Venn diagrams of LEFT, RIGHT, and INNER ANY JOIN: each returns matching rows without a Cartesian product, plus the non-matching rows of the left table or the right table for LEFT and RIGHT"/>

With `ALL` strictness, a JOIN returns every match, as described for the JOIN types above. With `ANY` strictness, a JOIN returns at most one match for each row and does not produce a Cartesian product:

- A `LEFT ANY JOIN` returns each left-hand row once, combined with one matching right-hand row or with default values.
- A `RIGHT ANY JOIN` returns each right-hand row once, combined with one matching left-hand row or with default values.
- An `INNER ANY JOIN` returns only rows with a match and uses each row of either table at most once.

Which of several matching rows `ANY` returns is not defined. The [`join_any_take_last_row`](/reference/settings/session-settings/join#join_any_take_last_row) setting changes which row is taken. `ANY FULL` JOINs are not supported. When a query does not specify a strictness, the [`join_default_strictness`](/reference/settings/session-settings/join#join_default_strictness) setting applies.

The following query shows a `LEFT ANY JOIN`. The right-hand table contains two rows for each of the keys `2` and `3`:

```sql
WITH
    left_table AS (SELECT * FROM VALUES('c UInt32', 1, 2, 3)),
    right_table AS (SELECT * FROM VALUES('c UInt32', 2, 2, 3, 3, 4))
SELECT
    l.c AS l_c,
    r.c AS r_c
FROM left_table AS l
LEFT ANY JOIN right_table AS r ON l.c = r.c;
```

```response
┌─l_c─┬─r_c─┐
│   1 │   0 │
│   2 │   2 │
│   3 │   3 │
└─────┴─────┘
```

With `ALL` strictness, the same query returns five rows, because the keys `2` and `3` each match two right-hand rows. With `INNER ANY JOIN`, it returns only the rows for the keys `2` and `3`.

### `ASOF JOIN` {#asof-join}

<Image img="/images/guides/join-algorithms/asof-join.png" size="sm" alt="Venn diagram of an ASOF JOIN: rows with non-exactly matching JOIN keys are joined, returning the closest match for each row without a Cartesian product"/>

An `ASOF JOIN` joins rows that have no exact match. In ClickHouse, `ASOF` is a strictness that is combined with an `INNER` or `LEFT` JOIN. The `ON` clause contains equality conditions and exactly one closest-match condition that uses `>`, `>=`, `<`, or `<=`. For each left-hand row, ClickHouse selects, among the right-hand rows that satisfy the equality conditions, the row that is closest according to the closest-match condition. Each left-hand row is joined with at most one right-hand row.

`ASOF JOIN` is typically used for time series. The following query joins each trade with the most recent quote for the same symbol at or before the trade time:

```sql
WITH
    trades AS (SELECT * FROM VALUES('symbol String, volume UInt32, time DateTime',
        ('ABC', 200, '2023-02-22 14:09:05'),
        ('ABC', 300, '2023-02-22 14:09:28'))),
    quotes AS (SELECT * FROM VALUES('symbol String, time DateTime, price Decimal(10, 2)',
        ('ABC', '2023-02-22 14:09:00', 32.11),
        ('ABC', '2023-02-22 14:09:10', 32.12),
        ('ABC', '2023-02-22 14:09:20', 32.15),
        ('ABC', '2023-02-22 14:09:30', 32.20)))
SELECT
    t.symbol,
    t.volume,
    t.time AS trade_time,
    q.time AS closest_quote_time,
    q.price AS quote_price,
    t.volume * q.price AS final_price
FROM trades AS t
ASOF LEFT JOIN quotes AS q ON t.symbol = q.symbol AND t.time >= q.time
ORDER BY trade_time;
```

```response
┌─symbol─┬─volume─┬──────────trade_time─┬──closest_quote_time─┬─quote_price─┬─final_price─┐
│ ABC    │    200 │ 2023-02-22 14:09:05 │ 2023-02-22 14:09:00 │       32.11 │        6422 │
│ ABC    │    300 │ 2023-02-22 14:09:28 │ 2023-02-22 14:09:20 │       32.15 │        9645 │
└────────┴────────┴─────────────────────┴─────────────────────┴─────────────┴─────────────┘
```

The trade at `14:09:05` is joined with the quote at `14:09:00`, and the trade at `14:09:28` is joined with the quote at `14:09:20`. The quotes at `14:09:10` and `14:09:30` are not the closest earlier quote for any trade.

For the column types that the closest-match column supports and the `USING` syntax, see [ASOF JOIN usage](/reference/statements/select/join#asof-join-usage).
