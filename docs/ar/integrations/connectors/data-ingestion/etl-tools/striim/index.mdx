[Striim for ClickHouse](https://www.striim.com/docs/striimforclickhouse/en/introducing-striim-for-clickhouse.html) خدمة SaaS مُدارة بالكامل تنقل البيانات إلى ClickHouse من قواعد البيانات ومستودعات البيانات وبحيرات البيانات وتطبيقات SaaS، بما في ذلك مصادر المؤسسات مثل Oracle وMicrosoft SQL Server وSnowflake. حمّل السجلات الموجودة أولًا، ثم استخدم التقاط تغييرات البيانات (CDC) لبث عمليات الإدراج والتحديث والحذف أولًا بأول، فتبقى بيانات ClickHouse محدَّثة دائمًا لأحمال عمل الذكاء الاصطناعي ولوحات المعلومات وتطبيقات البيانات.

تُستضاف Striim for ClickHouse على Striim Cloud في AWS، وتتيح التسجيل بنظام الخدمة الذاتية مع فوترة شهرية حسب الاستخدام ودون أي التزام سنوي. سجّل عبر striim.com أو من خلال AWS Marketplace، وابدأ فترة تجريبية مجانية مدتها 14 يومًا، ثم أنشئ مسار تنفيذ الاستعلام باستخدام موجّه بلغة طبيعية أو معالج إعداد أو مصمم التدفقات.

## الميزات الرئيسية {#key-features}

* **التقاط تغييرات البيانات والتحميل الأولي:** حمّل البيانات الموجودة، ثم انتقل إلى النسخ المتماثل الآني المستمر لعمليات الإدراج والتحديث والحذف. تساعد معالجات الإعداد المؤتمتة لمسارات تنفيذ الاستعلام على إنشاء المرحلتين وربطهما، ثم الانتقال تلقائيًا من التحميل الأولي إلى النسخ المتماثل عبر CDC.
* **ClickHouse Writer:** اختر محرك الجدول لكل مسار تنفيذ الاستعلام (`MergeTree` و`ReplacingMergeTree` و`CollapsingMergeTree` و`CoalescingMergeTree` وغيرها). يُنشئ Striim الجداول المستهدفة، ويتولى معالجة التحديثات وعمليات الحذف بما يتوافق مع المحرك الذي تختاره، ويضبط مفاتيح الفرز.
* **إدارة المخطط:** إنشاء مخطط الهدف تلقائيًا انطلاقًا من المصدر في حالة المصادر المدعومة، ونقل تغييرات DDL محددة (`CREATE TABLE` و`ADD COLUMN` و`ALTER TABLE ... MODIFY COLUMN` و`DROP COLUMN` و`DROP TABLE` و`TRUNCATE TABLE`) في حالة مصادر CDC المدعومة.
* **المعالجة أثناء النقل:** صفِّ البيانات وأثرِها وحوّلها في أثناء انتقالها من المصدر إلى ClickHouse.
* **عمليات مدعومة بالذكاء الاصطناعي:** يتولى Striim Clara AI، وهو وكيل ذكاء اصطناعي تحاوري، بناء مسارات تنفيذ الاستعلام انطلاقًا من وصف بلغة طبيعية، والإبلاغ عن زمن التأخر ومعدل النقل، وتفسير أسباب الفشل. راجع المخرجات المُنشأة قبل نشرها في بيئة الإنتاج.
* **الاتصال عبر شبكة خاصة:** AWS PrivateLink وأنفاق SSH وقوائم السماح لعناوين IP للوصول إلى المصادر وإلى ClickHouse.
* **المراقبة والتنبيهات:** مراقبة مدمجة لمسارات تنفيذ الاستعلام، وتنبيهات تُرسَل عبر البريد الإلكتروني وSlack وMicrosoft Teams وواجهة مستخدم الويب الخاصة بـ Striim.

## اعتبارات تشغيلية {#operational-considerations}

* يجري التسليم وفق مبدأ &quot;مرة واحدة على الأقل&quot; (at-least-once). فبعد إعادة التشغيل أو الاسترداد، قد تُكتب الأحداث المكتوبة مسبقًا مرة أخرى. وتتوقف سجلات البيانات الناتجة على محرك الجدول (راجع [كيف تصل البيانات إلى ClickHouse](/ar/integrations/connectors/data-ingestion/etl-tools/striim/get-started#how-data-lands-in-clickhouse)).
* لا يدعم تطور المخطط إعادة تسمية الأعمدة ولا تغيير قابليتها لقيم NULL، ولا ينطبق على الأهداف من نوع `AggregatingMergeTree` أو `Replicated` أو `Distributed`. كما أن `VersionedCollapsingMergeTree` و`GraphiteMergeTree` غير مدعومين.
* بعض أنواع المصادر لا تقابلها أنواع في ClickHouse، فتُتجاهَل أثناء الإنشاء التلقائي للمخطط، ومنها `SQL Server GEOGRAPHY` و`GEOMETRY` و`HIERARCHYID` و`SQL_VARIANT`؛ و`Oracle BFILE` و`LONG` و`LONG RAW` و`SDO_GEOMETRY` و`UROWID`؛ و`MySQL GEOMETRY` و`SET`.
