<Info>
  **باختصار**

  شغّل تطبيقًا توضيحيًا صغيرًا، وزوّده بأدوات جمع بيانات الرصد باستخدام موجّه الذكاء الاصطناعي المتوفر في صفحة البدء الخاصة بخدمتك أو بإجراء تعديلين يدويين، ثم تابع وصول السجلات وبيانات التتبّع والمقاييس إلى ClickHouse Observability.

  الوقت المطلوب: نحو 10 دقائق
</Info>

لقد أنشأت خدمة ClickHouse Observability الخاصة بك. يأخذك هذا الدليل من خدمة فارغة إلى استقبال بيانات القياس عن بُعد من تطبيق قيد التشغيل.

يوفّر ClickHouse Observability نقطة نهاية OpenTelemetry مُدارة، يرسل إليها تطبيقك بيانات القياس عن بُعد مباشرةً. فلا حاجة إلى تشغيل جامع بيانات، ولا إلى إنشاء مخطط، ولا إلى تحديد حجم قاعدة بيانات؛ إذ نتولى عنك إدارة الإدخال والمخططات والتخزين والتحسين والتحجيم.

## التطبيق التوضيحي {#the-demo-application}

لكي يكون لديك تطبيق واقعي تزوّده بأدوات جمع بيانات الرصد، يستخدم هذا الدليل [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)، وهو تطبيق توضيحي نوفّره لهذا الغرض تحديدًا. وهو تطبيق صغير مبني باستخدام Node.js وTypeScript، يُجري استعلامات على مجموعة بيانات HackerNews المستضافة في العرض التوضيحي العام لـ ClickHouse. ويستند كل مخطط وجدول ومربع بحث فيه إلى طلب حقيقي يُرسَل إلى الخادم الخلفي. أما الطلبات التي لا تجد نتيجتها في ذاكرة التخزين المؤقت للتطبيق، فتُجري أيضًا استعلامًا على ClickHouse، مما يضيف span صادرًا عبر HTTPS إلى كل تتبّع.

يتوفر التطبيق التوضيحي بنسختين:

* **غير مزوّد بأدوات الرصد** على الفرع `main`. في هذا الدليل، تضيف أدوات الرصد بنفسك، إما باستخدام وكيل ذكاء اصطناعي أو يدويًا، دون تغيير منطق الأعمال الخاص بالتطبيق. وتنطبق الخطوات نفسها على خدماتك الخاصة.
* **مزوّد مسبقًا بأدوات الرصد** على الفرع `instrumented`. انتقل إلى هذا الفرع إذا كنت تريد ببساطة أن تبدأ بيانات القياس عن بُعد بالتدفق سريعًا وأن تستكشف UI.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability. إذا لم تكن لديك خدمة بعد، فاتبع [دليل بدء الاستخدام](/ar/clickstack/observability/getting-started).
* Node.js 18 أو أحدث، بالإضافة إلى npm.
* إمكانية الوصول عبر الشبكة إلى نقطة نهاية بيانات القياس عن بُعد الخاصة بخدمتك، سواء من الجهاز الذي يشغّل العرض التوضيحي أو من متصفحك.

### توجيه التطبيق التوضيحي إلى خدمتك {#configure-environment}

        افتح الملف `.env` واضبط القيم التالية، مع استبدال نقطة النهاية ومفتاح API بالقيم الظاهرة في مربع الحوار:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        هذه متغيرات قياسية للمُصدِّر في OpenTelemetry، ولا توجد أي قيم مُضمَّنة بشكل ثابت في الشيفرة المصدرية للتطبيق.

        احتفظ بالبادئة `https://` في `OTEL_EXPORTER_OTLP_ENDPOINT` ولا تُلحق بها `/v1/logs` أو `/v1/traces` أو `/v1/metrics`، إذ تتولى حزم SDK إضافة مسارات الإشارات. اضبط `OTEL_EXPORTER_OTLP_HEADERS` على `authorization=<your-api-key>` دون البادئة `Bearer`.

        بعد ذلك، تتألف عملية إضافة أدوات الرصد من ثلاث خطوات: تثبيت SDK، وتغيير أمر التشغيل، وتمكين SDK للمتصفح. ولا تُغيّر أيٌّ منها منطق الأعمال في التطبيق.

### تثبيت Node SDK {#install-node-sdk}

        ```bash
        npm install @hyperdx/node-opentelemetry
        ```

### تفعيل الغلاف في run.sh {#enable-run-sh-wrapper}

        يحتوي الجزء السفلي من `run.sh` على سطرين يستخدمان `exec`. حوِّل سطر `node` العادي إلى تعليق، وأزِل علامة التعليق عن السطر المزوّد بأدوات الرصد:

        ```diff
         # BEFORE: plain node, no instrumentation:
        -exec node scripts/entrypoint.js
        +# exec node scripts/entrypoint.js

         # AFTER: same source, wrapped by opentelemetry-instrument:
        -# exec npx opentelemetry-instrument scripts/entrypoint.js
        +exec npx opentelemetry-instrument scripts/entrypoint.js
        ```

        واصل التشغيل عبر `scripts/entrypoint.js`، إذ تستدعي هذه الطبقة الوسيطة `require('console')` كي تتمكّن آلية التقاط مخرجات وحدة التحكم من تغليف `console.log`. أما توجيه `opentelemetry-instrument` إلى `dist/server/index.js` مباشرةً، فيُرسل بيانات التتبّع لكنه يُسقط السجلات دون أي تنبيه.

### تمكين SDK للمتصفح {#enable-browser-sdk}

        ```bash
        npm install @hyperdx/browser
        ```

        في الملف `src/web/telemetry.ts`، أزِل علامات التعليق عن عبارة الاستيراد، وعن كتلة `HyperDX.init`، وعن `HyperDX.addAction` داخل `recordAction`:

        ```diff
        -// import HyperDX from '@hyperdx/browser';
        +import HyperDX from '@hyperdx/browser';

         export function initTelemetry(): void {
        -  // HyperDX.init({
        -  //   url: __OTLP_ENDPOINT__,
        -  //   apiKey: __OTLP_AUTH_TOKEN__,
        -  //   service: 'hn-analyzer-web',
        -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        -  //   consoleCapture: true,
        -  //   advancedNetworkCapture: true,
        -  // });
        +  HyperDX.init({
        +    url: __OTLP_ENDPOINT__,
        +    apiKey: __OTLP_AUTH_TOKEN__,
        +    service: 'hn-analyzer-web',
        +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        +    consoleCapture: true,
        +    advancedNetworkCapture: true,
        +  });
         }
        ```

        إن `__OTLP_ENDPOINT__` و`__OTLP_AUTH_TOKEN__` ثوابت تُحقَن وقت التصريف عبر `vite.config.ts` من قيم `OTEL_EXPORTER_OTLP_*` نفسها التي يستخدمها الخادم الخلفي.

        <Warning>
          يُضمِّن SDK للمتصفح نقطة النهاية ومفتاح API في حزمة المتصفح، ما يتيح لأي شخص يفحص علامة تبويب الشبكة قراءتهما. لذا استخدم خدمة مخصصة للاختبار، واحرص على إبقاء `.env` خارج نظام التحكم في الإصدارات.
        </Warning>

        أعد تشغيل العرض التوضيحي باستخدام `./run.sh`.
      </Tab>

      <Tab title="استخدم فرعًا مزوّدًا مسبقًا بأدوات الرصد" id="use-the-instrumented-branch">
        لتخطي خطوة إضافة أدوات الرصد والبدء مباشرةً بعرض توضيحي مزوّد بأدوات الرصد مسبقًا، اضبط قيم `OTEL_EXPORTER_OTLP_*` في الملف `.env` كما هو موضّح في علامة تبويب إضافة أدوات الرصد يدويًا، ثم انتقل إلى [الفرع `instrumented`](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented):


## إذا لم يظهر أي شيء {#if-nothing-shows-up}

* تحقّق من القيم في `.env`. يجب أن تبدأ نقطة النهاية بـ `https://`، وأن تنتهي بالمنفذ `4318`، وألا تتضمن اللاحقة `/v1/...`. ويجب أن يكون مفتاح API هو القيمة الكاملة، ويمكنك نسخها بعد النقر على **Reveal key**.
* إذا اتبعت المسار اليدوي، فتأكّد من أن قيمة `OTEL_EXPORTER_OTLP_HEADERS` هي `authorization=<your-api-key>` دون البادئة `Bearer`، وأن شعار بدء التشغيل يعرض الأسطر الثلاثة `Health check passed` جميعها.
* تأكّد من أنك أعدت تشغيل العرض التوضيحي بعد تزويده بأدوات جمع بيانات الرصد، وأنك أعدت تحميل علامة تبويب المتصفح؛ إذ لا تبدأ إعادة تشغيل الجلسة إلا بعد تقديم الحزمة المزوّدة بأدوات الرصد.
* وسّع النطاق الزمني في **بحث** وأزِل أي عوامل تصفية، فقد يكون المصدر الافتراضي مضبوطًا على **تتبّعات** بدلًا من **سجلات**.
* للتأكد من أن المشكلة ليست في الخدمة نفسها، انتقل إلى **إعدادات الفريق ← Managed Telemetry** واستخدم **Send a Test Log**. فإذا ظهر هذا السجل في **بحث**، فهذا يعني أن الخدمة تستقبل البيانات وأن المشكلة تكمن في تهيئة العرض التوضيحي.

## الخطوات التالية {#next-steps}

باتت خدمتك تحتوي الآن على بيانات القياس عن بُعد من تطبيق حقيقي. لتزويد خدماتك الخاصة بأدوات جمع بيانات الرصد، أعد استخدام الموجّه **Instrument with AI** من خدمتك، أو استخدم [حزم SDK المدعومة للغات البرمجة](/ar/clickstack/observability/ingesting-data/sdks/index) مع نقطة النهاية ومفتاح API نفسيهما.

لجمع البيانات من البنية التحتية بدلًا من شفرة التطبيق:

* [مراقبة Kubernetes](/ar/clickstack/observability/example-datasets/kubernetes): اجمع سجلات العنقود ومقاييسه، واستكشف لوحة معلومات Kubernetes.
* [السجلات والمقاييس المحلية](/ar/clickstack/observability/example-datasets/local-data): اجمع الملفات المحلية ومقاييس النظام على macOS أو Linux.

* [إعادة تشغيل الجلسة](/ar/clickstack/observability/features/session-replay): نظرة عامة على الميزة، وخيارات SDK، وعناصر التحكم في الخصوصية.
* [مجموعات البيانات النموذجية](/ar/clickstack/observability/example-datasets): مجموعات بيانات أكثر ثراءً وتحقيقات إرشادية خطوة بخطوة.
