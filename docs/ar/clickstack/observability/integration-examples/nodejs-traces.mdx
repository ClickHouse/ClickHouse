التقط بيانات التتبّع من تطبيق Node.js باستخدام التتبّع التلقائي في OpenTelemetry، ثم أرسلها إلى ClickHouse Observability. ويمكنك استخدام [مجموعة البيانات التجريبية](#demo-dataset) لتجربة التكامل دون الحاجة إلى تزويد أي تطبيق بأدوات جمع بيانات الرصد.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* لتطبيقك: Node.js 22 أو إصدار أحدث، وnpm
* للعرض التوضيحي: Docker و`curl`

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="خدمة في المرحلة التجريبية" />

    افتح ClickHouse Observability وانتقل إلى **إعدادات الفريق → البيانات → بيانات القياس عن بُعد المُدارة**. انسخ نقطة نهاية OTLP عبر HTTP ومفتاح API الخاصين بك. يمكنك استخدام **Copy connection details** لنسخ الإعدادات، أو **Reveal key** لإظهار المفتاح المُخفى.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال في صفحة بيانات القياس عن بُعد المُدارة](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    عيّن متغيرات الاتصال التالية في الطرفية التي ستشغّل منها تطبيقك أو جامع البيانات التجريبي:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية الفعلية لخدمتك، بما في ذلك المنفذ، وبمفتاح API الخاص بها. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/traces`؛ إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP عبر HTTP الخاصة بجامع البيانات لديك، على أن يكون الوصول إليها ممكنًا (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب المصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من الإعدادات أدناه. راجع [دليل البدء للنسخة المُدارة ذاتيًا](/ar/clickstack/self-configured/getting-started/managed) للاطلاع على إرشادات الإعداد.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

## التكامل مع تطبيق Node.js قائم {#existing-nodejs}

<Steps>
  <Step title="تثبيت OpenTelemetry" id="install-instrumentation">
    من دليل تطبيقك، ثبّت حزم أدوات الرصد:

    ```bash
    npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node@0.81.0
    ```

    تعتمد هذه الخطوات على [التتبّع التلقائي في OpenTelemetry](https://opentelemetry.io/docs/zero-code/js/) لتطبيقات CommonJS. أما وحدات ES الأصلية فتتطلب [إعداد ESM](https://github.com/open-telemetry/opentelemetry-js/blob/main/doc/esm-support.md). اعتمد إعدادًا واحدًا فقط لأدوات الرصد في كل تطبيق لتجنّب تكرار مقاطع التتبع.
  </Step>

  <Step title="تهيئة التتبّع وتشغيل تطبيقك" id="run-application">
    في الطرفية التي عيّنت فيها متغيرات الاتصال، شغّل ما يلي:

    ```bash
    export OTEL_SERVICE_NAME='nodejs-service'
    export OTEL_TRACES_EXPORTER='otlp'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="Authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='none'
    export OTEL_LOGS_EXPORTER='none'

    node --require @opentelemetry/auto-instrumentations-node/register app.js
    ```

    استبدل `app.js` بنقطة الدخول الخاصة بتطبيقك. يتولى التحميل المسبق تهيئة أدوات الرصد قبل أن يستورد تطبيقك مكتباته. إذا كانت نقطة النهاية مُدارة ذاتيًا ولا تتطلب مصادقة، فاحذف أمر تصدير الترويسات وشغّل `unset OTEL_EXPORTER_OTLP_HEADERS`.

    يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من التطبيق. وإذا كان التطبيق يعمل داخل حاوية، فإن `localhost` يشير إلى تلك الحاوية.
  </Step>

  <Step title="توليد حركة مرور" id="generate-traffic">
    أرسل طلبات إلى نقطة نهاية يوفّرها تطبيقك. فمثلًا، لتطبيق يستمع على المنفذ `3000`:

    ```bash
    curl http://localhost:3000/
    ```

    انتظر بضع ثوانٍ حتى يرسل المُصدِّر مقاطع التتبع.
  </Step>

  <Step title="التحقق من بيانات التتبّع" id="verify-traces">
    افتح **بحث**، واختر **Traces**، وصفِّ النتائج باستخدام `ServiceName:nodejs-service`، ثم اختر **Last 15 minutes**. افتح أحد التتبّعات لفحص مقاطع التتبع الخاصة به وتوقيتاتها وسماتها.
  </Step>
</Steps>

## مجموعة البيانات التجريبية {#demo-dataset}

تحتوي العينة على 822 مقطع تتبع من `nodejs-demo-api`، ولا تحتاج إلى تطبيق Node.js قيد التشغيل.

<Steps>
  <Step title="تنزيل مجموعة البيانات النموذجية" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nodejs/nodejs-traces-sample.json
    ```
  </Step>

  <Step title="تهيئة جامع البيانات التوضيحي" id="configure-demo-collector">
    احفظ ما يلي باسم `nodejs-traces-demo.yaml` في دليل التنزيل:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T17:59:15Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nodejs-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      يُزيح المعالج `transform/demo_timestamps`، المخصص للعرض التوضيحي فقط، هذه العينة لتقع تقريبًا ضمن آخر 24 ساعة، بحيث تنتهي قبل دقيقتين من الاستيعاب، مع الحفاظ على مدد مقاطع التتبع ونمط حركة المرور. احذف هذا المعالج عند إرسال تتبّعات Node.js الخاصة بك كي تحتفظ بطوابعها الزمنية الأصلية. وقد يؤدي إرسال العينة مرة أخرى إلى ظهور مقاطع تتبع مكررة.
    </Note>
  </Step>

  <Step title="تشغيل جامع البيانات التوضيحي" id="run-demo-collector">
    <Note>
      إذا كان جامع البيانات الوجهة يعمل على هذا الحاسوب نفسه، فاضبط `OTEL_EXPORTER_OTLP_ENDPOINT` على `http://host.docker.internal:4318`. يتضمن الأمر أدناه ربط مضيف Docker.
    </Note>

    شغّل OpenTelemetry Collector Contrib `0.161.0` من الدليل الذي يحتوي على ملف الإعدادات، وفي الطرفية نفسها التي ضبطت فيها متغيرات الاتصال. أبقِ هذه الطرفية مفتوحة:

    ```bash
    docker run --rm --name nodejs-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nodejs-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    يستخدم المستقبِل المحلي المنفذ `14318` لتجنّب التعارض مع أي جامع بيانات قائم على المنفذ `4318`. ويُعيد جامع البيانات توجيه التتبّعات إلى نقطة النهاية التي هيّأتها، مستخدمًا إعدادات المصادقة المذكورة أعلاه.
  </Step>

  <Step title="إرسال التتبّعات" id="send-traces">
    في طرفية أخرى، ومن داخل دليل التنزيل، أرسل العينة الأصلية إلى جامع البيانات المحلي:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nodejs-traces-sample.json
    ```

    تدلّ استجابة النجاح الفارغة، مثل `{}` أو `{"partialSuccess":{}}`، على أن جامع البيانات المحلي قد قبل الطلب. راجع مخرجات جامع البيانات بحثًا عن أخطاء في التصدير، وانتظر بضع ثوانٍ حتى تصل الدفعة إلى خدمتك. وعند الانتهاء، أوقف جامع البيانات التوضيحي بالضغط على **Ctrl+C**.
  </Step>

  <Step title="التحقق من التتبّعات التوضيحية" id="verify-demo-traces">
    افتح **بحث**، واختر **Traces**، وصفِّ النتائج باستخدام `ServiceName:nodejs-demo-api`، ثم اختر **آخر يومين** لتشمل مجموعة البيانات المُزاحة بالكامل. افتح أحد التتبّعات لفحص سمات HTTP.

    <div className="ch-image-lg">
      <Frame>
        ![تتبّعات Node.js التوضيحية في صفحة البحث في ClickHouse Observability](/images/clickstack/observability-nodejs-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### لا تظهر بيانات تتبّع التطبيق {#no-application-traces}

افحص مخرجات التطبيق بحثًا عن أخطاء التصدير. وتحقّق من إعدادات نقطة النهاية والبروتوكول والمصادقة. حمّل أدوات الرصد قبل مكتبات التطبيق، ثم أرسل بعض الطلبات، وتحقّق من عامل تصفية اسم الخدمة والنطاق الزمني. أما وحدات ES الأصلية، فاتبع خطوات إعداد ESM الواردة في الرابط.

### لا تظهر بيانات التتبّع التجريبية {#no-demo-traces}

افحص مخرجات جامع البيانات التجريبي بحثًا عن أخطاء في المصادقة أو أخطاء التصدير. تؤكد استجابة `curl` الناجحة أن البيانات قُبلت محليًا، لكن امنحها بضع ثوانٍ حتى تُمرَّر إلى الخدمة الخاصة بك. أضف `transform/demo_timestamps` إلى مسار المعالجة، ثم اختر **آخر يومين**. قد تؤدي إعادة إرسال العينة إلى ظهور بيانات مكررة.
