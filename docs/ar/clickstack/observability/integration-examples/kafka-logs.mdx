اجمع سجلات الوسيط في Kafka باستخدام المستقبِل `filelog` من OpenTelemetry، ثم أرسلها إلى ClickHouse Observability. ويمكنك استخدام [مجموعة البيانات التجريبية](#demo-dataset) لتجربة التكامل دون الحاجة إلى نشر Kafka.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* Docker و`curl`
* لاستخدام سجلاتك الخاصة: إمكانية الوصول إلى ملفات السجل الخاصة بوسيط Kafka، على أن تكون مطابقة للصيغة الموضحة أدناه

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="عرض تجريبي" />

    افتح ClickHouse Observability وانتقل إلى **Team Settings → Data → Managed Telemetry**. انسخ نقطة نهاية OTLP HTTP ومفتاح API الخاصين بك. يمكنك استخدام **Copy connection details** لنسخ التهيئة، أو **Reveal key** لإظهار المفتاح المخفي.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال الخاصة بـ Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    لتشغيل أمثلة مُصدِّر OTLP الواردة أدناه، اضبط هذه المتغيرات في الطرفية التي ستشغّل منها جامع البيانات:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية الفعلية لخدمتك، بما في ذلك رقم المنفذ، وبمفتاح API الخاص بها. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/logs`، إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات، على أن يكون الوصول إليها ممكنًا (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب المصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من التهيئات أدناه. راجع [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed) للاطلاع على إرشادات الإعداد.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من حاوية جامع البيانات. إذا كان جامع البيانات الوجهة يعمل على هذا الحاسوب نفسه، فاستخدم `http://host.docker.internal:4318`. تتضمن أوامر Docker أدناه مطابقة المضيف.

## التكامل مع نشر Kafka قائم {#existing-kafka}

<Steps>
  <Step title="تحقق من إعدادات تسجيل السجلات في Kafka" id="verify-kafka">
    حدِّد مكان سجلات الوسيط لديك. ومن المواقع الشائعة `$KAFKA_HOME/logs` و`/var/log/kafka`، وذلك بحسب طريقة التثبيت وإعدادات تسجيل السجلات لديك:

    ```bash
    ls "$KAFKA_HOME/logs/"
    ls /var/log/kafka/
    ```

    من الملفات الشائعة `server.log` (أحداث الوسيط)، و`controller.log` (أحداث وحدة التحكم)، و`state-change.log` (انتقالات التقسيمات والنسخ المتماثلة). ولا تُنشأ ملفات منفصلة إلا إذا جرت تهيئتها في مُلحِقات التسجيل (appenders) لديك.

    يتوقع المحلل النحوي في هذا الدليل التنسيق النصي التالي لـ Log4j:

    ```text
    [2026-03-09 14:23:45,123] INFO [KafkaServer id=0] started (kafka.server.KafkaServer)
    ```

    إذا كان الوسيط لديك يكتب سجلاته إلى stdout فقط، فهيّئ مُلحِق ملفات (file appender) في إعدادات تسجيل السجلات الخاصة بالوسيط، ثم شارك ذلك الدليل مع جامع البيانات، إذ لا يقرأ المستقبِل `filelog` مخرجات stdout للحاوية مباشرةً. وإذا كان نمط تسجيل السجلات لديك مختلفًا، فعدّل المحلل النحوي وفقًا لذلك.
  </Step>

  <Step title="تهيئة جامع البيانات" id="configure-collector">
    احفظ ما يلي باسم `kafka-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
          - /var/log/kafka/controller.log
          - /var/log/kafka/state-change.log
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka
          - type: add
            field: resource["service.name"]
            value: kafka-service
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, batch]
          exporters: [otlp_http/observability]
    ```

    اضبط `location` على المنطقة الزمنية المستخدمة في سجلات الوسيط لديك؛ ويفترض المثال استخدام UTC. تحتفظ إدخالات السجل متعددة الأسطر بتتبّعات مكدس الاستدعاءات كاملةً. ويقرأ جامع البيانات الإدخالات الجديدة فقط عبر `start_at: end`، ويحوّل نص مستوى الخطورة إلى أحرف صغيرة.
  </Step>

  <Step title="شغّل جامع البيانات" id="run-collector">
    اضبط [متغيرات الاتصال](#connection-details)، ثم شغّل الأمر من دليل التهيئة. عدّل مسار السجلات على المضيف عند الحاجة. وإذا كانت الملفات قابلة للقراءة من قِبل المجموعة، فأضف `--group-add LOG_GROUP_ID` مستخدمًا رقم المجموعة الذي يعرضه الأمر `ls -ln /var/log/kafka`.

    ```bash
    docker run --rm --name kafka-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/kafka:/var/log/kafka:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    اترك الطرفية مفتوحة، ثم أنشئ نشاطًا على الوسيط يكتب إدخالات سجل جديدة. اضغط **Ctrl+C** للإيقاف عند الانتهاء من الاختبار.
  </Step>

  <Step title="تحقّق من السجلات" id="verify-logs">
    افتح صفحة **بحث**، واختر **Logs**، وطبّق عامل تصفية على `ServiceName:kafka-service`، ثم اختر **Last 15 minutes**. من المفترض أن تظهر لك رسائل الوسيط مع الطوابع الزمنية المُحلَّلة ومستوى الخطورة.
  </Step>
</Steps>

## مجموعة البيانات التجريبية {#demo-dataset}

تحتوي العينة على 6,376 إدخالًا من سجلات وسيط Kafka تغطي نحو 24 ساعة. يُحدِّث جامع البيانات الطوابع الزمنية لهذه الإدخالات مع الإبقاء على الرسائل وتتبعات المكدس كما هي.

<Steps>
  <Step title="تنزيل العينة" id="download-sample">
    ```bash
    curl -fL -o server.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/kafka/server.log
    ```
  </Step>

  <Step title="تهيئة جامع البيانات التوضيحي" id="configure-demo">
    احفظ ما يلي باسم `kafka-logs-demo.yaml`:

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka-demo
          - type: add
            field: resource["service.name"]
            value: kafka-demo
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:58.180Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="تشغيل جامع البيانات التوضيحي" id="run-demo">
    اضبط [متغيرات الاتصال](#connection-details)، ثم شغّل الأمر التالي من الدليل الذي يحتوي على الملفين:

    ```bash
    docker run --rm --name kafka-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/server.log:/var/log/kafka/server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    اترك الطرفية مفتوحة ريثما تتحقق من استيعاب البيانات، ثم أوقف التشغيل بالضغط على **Ctrl+C** عند الانتهاء. وعند تشغيل العرض التوضيحي مرة أخرى، يُعاد استيعاب العينة بطوابع زمنية محدَّثة.
  </Step>

  <Step title="التحقق من سجلات العرض التوضيحي" id="verify-demo">
    افتح **Search**، واختر **Logs**، ثم صفِّ النتائج باستخدام `ServiceName:kafka-demo`، واختر **Last 2 days**.

      </Frame>
    </div>
  </Step>
</Steps>

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### عدم ظهور السجلات {#no-logs}

افحص مخرجات جامع البيانات بحثًا عن أخطاء في صلاحيات الملفات أو التحليل النحوي أو المصادقة أو التصدير. تأكد من أن الوسيط يكتب إلى الدليل المربوط، وأن أسماء الملفات تطابق قائمة `include` الخاصة بالمستقبِل. لاحظ أن التهيئة العاملة لا تقرأ إلا العناصر الجديدة.

### عدم تحليل السجلات تحليلًا نحويًا صحيحًا {#parsing-errors}

قارن إدخالًا في سجل الوسيط بالصيغة المتوقعة:

```bash
tail -n 20 /var/log/kafka/server.log
```

عدّل التعبير النمطي ونمط بداية السجلات متعددة الأسطر إذا كانت صيغة التسجيل لديك مختلفة. واضبط قيمة `location` في المحلل النحوي للطابع الزمني على المنطقة الزمنية التي يستخدمها الوسيط في تسجيل السجلات.
