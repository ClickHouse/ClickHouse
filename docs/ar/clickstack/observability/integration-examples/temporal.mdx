توفّر Temporal طبقة تجريد لبناء تطبيقات بسيطة ومتطورة ومرنة.

<Info>
  **باختصار**

  راقب مقاييس Temporal Cloud في ClickHouse Observability باستخدام مستقبِل Prometheus في OTel، مع لوحة معلومات جاهزة مسبقًا.
</Info>

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* حساب قائم على Temporal Cloud
* Docker مثبّت على مضيف يمكنه الوصول عبر HTTPS إلى Temporal Cloud وإلى نقطة نهاية OTLP الخاصة بك

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="خدمة في المرحلة التجريبية" />

    افتح ClickHouse Observability وانتقل إلى **إعدادات الفريق → Data → بيانات القياس عن بُعد المُدارة**. انسخ نقطة نهاية OTLP عبر HTTP ومفتاح API الخاصين بك. يمكنك استخدام **Copy connection details** لنسخ التهيئة، أو **Reveal key** لإظهار المفتاح المحجوب.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال في بيانات القياس عن بُعد المُدارة](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    لاستخدام أمثلة مُصدِّر OTLP أدناه، عيّن المتغيرات التالية في الطرفية التي ستشغّل منها جامع البيانات:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية كما هي تمامًا، بما في ذلك المنفذ، وبمفتاح API الخاص بخدمتك. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/metrics`، إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP عبر HTTP لجامع البيانات لديك، على أن يكون الوصول إليها ممكنًا (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب المصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من التهيئات أدناه. للاطلاع على إرشادات الإعداد، راجع [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من حاوية جامع البيانات. إذا كان جامع البيانات الوجهة يعمل على هذا الحاسوب نفسه، فاستخدم `http://host.docker.internal:4318`. تتضمن أوامر Docker أدناه مطابقة المضيف.

## التكامل مع حساب Temporal Cloud قائم {#existing-temporal}

<Steps>
  <Step title="إنشاء مفتاح Temporal Cloud" id="create-temporal-cloud-key">
    أنشئ حساب خدمة في Temporal Cloud بدور **Metrics Read-Only** ثم أنشئ مفتاح API، باتباع [دليل المصادقة](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication). يجب أن يتولى مالك الحساب (Account Owner) أو المسؤول العام (Global Admin) إنشاء حساب الخدمة والمفتاح.

    <Warning>
      **ملف المفتاح**

      خزّن مفتاح API الخاص بـ Temporal في ملف باسم `temporal.key` داخل الدليل نفسه الذي سيحتوي على ملف الإعداد الذي ستُنشئه أدناه. احفظ المفتاح وحده، دون البادئة `Bearer` ودون أي مسافات قبله أو بعده. هذا المفتاح منفصل عن مفتاح API الخاص بـ ClickHouse Observability. تأكد من أن جامع البيانات قادر على قراءة الملف المربوط.
    </Warning>
  </Step>

  <Step title="تهيئة جامع بيانات OTel" id="custom-otel">
    شغّل مُجمِّع OpenTelemetry مستقلاً مع مستقبِل Prometheus لسحب المقاييس من Temporal Cloud وتمريرها إلى خدمتك.

    أنشئ ملفاً باسم `temporal-metrics.yaml` يتضمن التهيئة التالية:

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    تتولى هذه التهيئة ما يلي:

    * الاتصال بـ Temporal Cloud عبر `metrics.temporal.io`
    * جمع المقاييس كل 60 ثانية
    * جمع [مقاييس الأداء الرئيسية](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)
    * **تعيين attribute المورد المطلوب `service.name`** وفقاً لـ[اصطلاحات OpenTelemetry الدلالية](https://opentelemetry.io/docs/specs/semconv/resource/#service)
    * إرسال المقاييس إلى نقطة نهاية OTLP الخاصة بك عبر مسار مخصص

    إذا كانت لديك عدة حسابات Temporal Cloud، فخصّص قيمة `service.name` للتمييز بينها (مثل `temporal-prod` و`temporal-dev`).
  </Step>

  <Step title="تشغيل جامع البيانات" id="run-collector">
    من الدليل الذي يحتوي على `temporal-metrics.yaml` و`temporal.key`، عيّن [متغيرات الاتصال](#connection-details) ثم شغّل الأمر التالي:

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    أبقِ الطرفية مفتوحة وراقب أي أخطاء في السحب أو التصدير. قد يستغرق ظهور مقاييس Temporal Cloud بضع دقائق. أوقف جامع البيانات بالضغط على **Ctrl+C** بعد الانتهاء من الاختبار.
  </Step>

  <Step title="التحقق من المقاييس في ClickHouse Observability" id="verifying-metrics">
    بعد اكتمال التهيئة، سجّل الدخول إلى ClickHouse Observability وتحقق من وصول المقاييس:

    1. افتح **مستكشف المخططات** واختر مصدر **Metrics** الخاص بك
    2. صفِّ النتائج حسب `ServiceName:temporal`، واختر **Last 15 minutes**، وابحث عن المقاييس التي تبدأ بـ `temporal` (مثل `temporal_cloud_v1_workflow_success_count` و`temporal_cloud_v1_poll_timeout_count`)
    3. من المفترض أن تظهر نقاط بيانات المقاييس وفق فاصل الجمع الزمني الذي هيّأته

    <div className="ch-image-md">
      <Frame>
        ![مقاييس Temporal](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### تعذّر بدء تشغيل جامع البيانات {#collector-fails-to-start}

افحص مخرجات الطرفية بحثًا عن أخطاء في التهيئة. وتأكد من وجود الملفين المربوطين كليهما، ومن أن جامع البيانات قادر على قراءة `temporal.key`. وتحقق كذلك من تعيين متغيرات الاتصال الخاصة بـ OTLP في الطرفية التي يُشغَّل فيها Docker.

### لا تظهر أي مقاييس {#no-metrics}

تحقق من سجلات جامع البيانات:

```bash
docker logs temporal-metrics-collector
```

ابحث عن أخطاء السحب أو المصادقة أو التصدير. وتأكد من أن المضيف يستطيع الوصول إلى `https://metrics.temporal.io/v1/metrics` وإلى نقطة نهاية OTLP الخاصة بك. وفي **مستكشف المخططات**، تحقق من المصدر **Metrics** وعامل التصفية `ServiceName:temporal` والنطاق الزمني. قد تستغرق مقاييس Temporal بضع دقائق حتى تصبح متاحة، كما أن ظهورها يعتمد على النشاط في حسابك.

### أخطاء المصادقة {#auth-errors}

في حال ظهور أخطاء في سحب مقاييس Temporal، تأكد من أن `temporal.key` يحتوي على مفتاح API صالح لحساب خدمة مُسند إليه الدور **Metrics Read-Only**. أما في حال ظهور أخطاء في تصدير OTLP، فتحقق من نقطة نهاية ClickHouse Observability وقيمة التفويض لديك. لاحظ أن هذه بيانات اعتماد منفصلة عن بعضها.

* راقب عدة حسابات Temporal Cloud بتكرار تهيئة المستقبِل مع استخدام نقاط نهاية وأسماء خدمات مختلفة

## الانتقال إلى بيئة الإنتاج {#going-to-production}

يعتمد هذا الدليل على تشغيل مُجمِّع OpenTelemetry منفصل يتولّى إعادة توجيه المقاييس إلى نقطة نهاية OTLP الخاصة بخدمتك. للاطلاع على إرشادات النشر، راجع [إرسال بيانات OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry).
