اجمع ملفات syslog من EC2 باستخدام مُجمِّع OpenTelemetry، وأرسلها إلى ClickHouse Observability مع البيانات الوصفية للمثيل. يمكنك استخدام [مجموعة البيانات التجريبية](#demo-dataset) لتجربة التكامل دون الحاجة إلى مثيل EC2.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* لاستخدام سجلاتك الخاصة: مثيل Linux EC2 يحتوي على ملفات syslog، مع إمكانية الوصول إلى خدمة البيانات الوصفية للمثيل، وصلاحية تثبيت جامع البيانات وتشغيله
* للعرض التوضيحي: Docker
* أداة `curl` لتنزيل جامع البيانات أو العينة

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="عرض تجريبي" />

    افتح ClickHouse Observability وانتقل إلى **إعدادات الفريق ← البيانات ← القياس عن بُعد المُدار**. انسخ نقطة نهاية OTLP HTTP ومفتاح API الخاصين بك. يمكنك استخدام **نسخ بيانات الاتصال** لنسخ التهيئة، أو **إظهار المفتاح** لعرض المفتاح المخفي.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال الخاصة بالقياس عن بُعد المُدار](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    لاستخدام أمثلة مُصدِّر OTLP أدناه، عيّن المتغيرات التالية في الطرفية التي ستشغّل فيها جامع البيانات:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية الدقيقة لخدمتك، بما في ذلك المنفذ، وبمفتاح API الخاص بها. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/logs`؛ إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات لديك، والتي يمكن الوصول إليها (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب مصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من التهيئات أدناه. راجع [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed) للاطلاع على إرشادات الإعداد.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

يجب أن يتمكن مثيل EC2 من الوصول إلى نقطة النهاية. وفي العرض التوضيحي باستخدام Docker، يمكن الوصول إلى جامع البيانات الوجهة الموجود على حاسوبك عبر `http://host.docker.internal:4318`؛ إذ يتضمن أمر العرض التوضيحي مطابقة المضيف.

## التكامل مع مثيل EC2 موجود {#existing-ec2}

نفِّذ هذه الخطوات على مثيل EC2 الذي تريد جمع سجلاته.

<Steps>
  <Step title="تحقق من البيانات الوصفية للمثيل وسجل النظام (syslog)" id="verify-metadata">
    تحقّق من إمكانية الوصول إلى خدمة البيانات الوصفية للمثيل باستخدام IMDSv2:

    ```bash
    TOKEN=$(curl -fsS --connect-timeout 5 -X PUT \
      -H 'X-aws-ec2-metadata-token-ttl-seconds: 300' \
      http://169.254.169.254/latest/api/token)
    curl -fsS --connect-timeout 5 -H "X-aws-ec2-metadata-token: $TOKEN" \
      http://169.254.169.254/latest/meta-data/instance-id
    ```

    يجب أن تتضمّن الاستجابة معرّف المثيل الخاص بك. يستخدم جامع البيانات خدمة البيانات الوصفية هذه لإضافة معرّف المثيل ونوعه ومنطقته ومنطقة التوافر ومعرّف الحساب إلى سجلاتك. لا تجمع التهيئة أدناه وسوم EC2.

    حدّد موقع ملف syslog لديك وتحقّق من صيغته:

    ```bash
    # Ubuntu/Debian
    tail -20 /var/log/syslog

    # Amazon Linux/RHEL
    tail -20 /var/log/messages
    ```

    استخدم المسار الموجود على المثيل لديك. وإذا كان يكتب السجلات إلى systemd journal فقط، فاستخدم [دليل Systemd/Journald](/ar/clickstack/observability/integration-examples/systemd) لجمعها.
  </Step>

  <Step title="تثبيت جامع البيانات" id="install-collector">
    نزّل OpenTelemetry Collector Contrib `0.161.0` المتوافق مع معمارية المثيل لديك:

    ```bash
    case "$(uname -m)" in
      x86_64) ARCH=amd64 ;;
      aarch64) ARCH=arm64 ;;
      *) echo "Unsupported architecture"; exit 1 ;;
    esac
    curl -fLO "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz"
    tar -xzf "otelcol-contrib_0.161.0_linux_${ARCH}.tar.gz" otelcol-contrib
    sudo install -m 755 otelcol-contrib /usr/local/bin/otelcol-contrib
    /usr/local/bin/otelcol-contrib --version
    ```
  </Step>

  <Step title="هيّئ جامع البيانات" id="configure-collector">
    احفظ التهيئة المناسبة باسم `ec2-host-logs.yaml`. اختر التهيئة بحسب صيغة الطابع الزمني في ملفك، وعدّل `include` إذا كان مسار syslog لديك مختلفًا.

    <Tabs>
      <Tab title="طوابع زمنية بصيغة ISO">
        للطوابع الزمنية مثل `2026-10-15T12:34:56.123456+00:00`:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="صيغة syslog التقليدية">
        للطوابع الزمنية مثل `Oct 15 12:34:56`:

        ```yaml
        receivers:
          filelog/ec2:
            include: [/var/log/messages]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: ec2-host-logs
              - type: add
                field: resource["service.name"]
                value: ec2-host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resourcedetection/ec2:
            detectors: [ec2]
            timeout: 5s
            override: false
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/ec2:
              receivers: [filelog/ec2]
              processors: [memory_limiter, resourcedetection/ec2, batch]
              exporters: [otlp_http/observability]
        ```

        لا تتضمن الطوابع الزمنية التقليدية السنة ولا المنطقة الزمنية. يستنتج المحلل النحوي السنة تلقائيًا؛ أما إذا كان مضيفك لا يسجّل بتوقيت UTC، فاضبط `location` على منطقته الزمنية وفق تسمية IANA.
      </Tab>
    </Tabs>

    يحتفظ المستقبِل بسطر السجل الأصلي، ويستخرج منه اسم المضيف والوحدة ومعرّف العملية PID (إن وُجد) والرسالة. ويضيف المعالج `resourcedetection/ec2` سمات موارد EC2. ولجمع وسوم المثيل أيضًا، راجع [تهيئة كاشف EC2](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/processor/resourcedetectionprocessor#aws-ec2) ومتطلبات الصلاحيات الخاصة به.
  </Step>

  <Step title="شغّل جامع البيانات" id="run-collector">
    اضبط [متغيرات الاتصال](#connection-details) في هذه الطرفية، ثم شغّل الأمر من الدليل الذي يحتوي على ملف التهيئة. يحتاج جامع البيانات إلى صلاحية قراءة ملف syslog:

    ```bash
    sudo --preserve-env=OTEL_EXPORTER_OTLP_ENDPOINT,OTEL_EXPORTER_OTLP_AUTHORIZATION \
      /usr/local/bin/otelcol-contrib --config="$(pwd)/ec2-host-logs.yaml"
    ```

    أبقِ الطرفية مفتوحة. يستخدم المستقبِل `start_at: end`، لذا أنشئ نشاطًا جديدًا يكتب إلى ملف syslog بعد بدء التشغيل. ولجمع البيانات بشكل مستمر، هيّئ خدمة ضمن عملية النشر التي تعتمدها، ومرّر متغيرات الاتصال إلى تلك الخدمة.
  </Step>

  <Step title="تحقّق من السجلات" id="verify-logs">
    افتح صفحة **بحث**، واختر مصدر **Logs**، ثم طبّق عامل التصفية `ServiceName:ec2-host-service`، واختر **Last 15 minutes**. وسّع أحد السجلات وتحقّق من وجود `cloud.provider` و`cloud.region` و`cloud.availability_zone` و`host.id` و`host.type` ضمن سمات الموارد الخاصة به.
  </Step>
</Steps>

## مجموعة البيانات التجريبية {#demo-dataset}

تحتوي العينة على 11,658 سطرًا من سجلات syslog تغطي 24 ساعة. يضيف جامع البيانات بيانات وصفية محاكاة لـ EC2 ويُحدّث الطوابع الزمنية، لذا لا حاجة إلى حساب AWS.

<Steps>
  <Step title="نزّل العينة" id="download-sample">
    ```bash
    mkdir -p ec2-demo
    cd ec2-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="تهيئة جامع بيانات العرض التوضيحي" id="configure-demo-collector">
    احفظ هذا الملف باسم `ec2-host-logs-demo.yaml` في دليل التنزيلات:

    ```yaml
    receivers:
      filelog/ec2:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: ec2-demo
          - type: add
            field: resource["service.name"]
            value: ec2-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      resource/ec2_demo:
        attributes:
          - key: cloud.provider
            value: "aws"
            action: insert
          - key: cloud.platform
            value: "aws_ec2"
            action: insert
          - key: cloud.region
            value: "us-east-1"
            action: insert
          - key: cloud.availability_zone
            value: "us-east-1a"
            action: insert
          - key: host.id
            value: "i-0abc123def456789"
            action: insert
          - key: host.type
            value: "t3.medium"
            action: insert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/ec2:
          receivers: [filelog/ec2]
          processors: [memory_limiter, resource/ec2_demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      يُزيح تحويل الطابع الزمني، المخصص للعرض التوضيحي فقط، العينةَ لتقع تقريبًا ضمن الساعات الـ 24 الماضية، بحيث تنتهي قبل دقيقتين من وقت الإدخال. استخدم [تهيئة مثيل EC2](#existing-ec2) مع سجلاتك الخاصة للحفاظ على طوابعها الزمنية الأصلية.
    </Note>
  </Step>

  <Step title="شغّل جامع بيانات العرض التوضيحي" id="run-demo-collector">
    اضبط [متغيرات الاتصال](#connection-details)، ثم شغّل ما يلي من دليل التنزيل:

    ```bash
    docker run --rm --name ec2-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/ec2-host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    أبقِ الطرفية مفتوحة ريثما يُصدِّر جامع البيانات العيّنة التجريبية، وراجِع مخرجاتها بحثًا عن أي أخطاء. قد يؤدي تشغيل حاوية جديدة مرة أخرى إلى تكرار سجلات العيّنة التجريبية.
  </Step>

  <Step title="تحقق من سجلات العرض التوضيحي" id="verify-demo-logs">
    افتح صفحة **بحث**، واختر مصدر **Logs**، وطبّق عامل التصفية `ServiceName:ec2-demo`، ثم اختر **Last 2 days**. وسّع أحد السجلات وتحقّق من سمات الموارد المحاكاة: قيمة `cloud.region` هي `us-east-1`، وقيمة `host.id` هي `i-0abc123def456789`، وقيمة `host.type` هي `t3.medium`. بعد التحقق من البيانات، أوقف جامع البيانات بالضغط على **Ctrl+C**.

      </Frame>
    </div>
  </Step>
</Steps>

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### البيانات الوصفية لـ EC2 مفقودة {#no-metadata}

نفّذ فحص البيانات الوصفية من داخل مثيل EC2. وتأكّد من أن IMDS مفعّل، ومن أن إعدادات جدار الحماية المحلي أو الوكيل تسمح بالطلبات الموجّهة إلى `169.254.169.254`. وإذا كنت تستخدم وكيلًا، فاستثنِ هذا العنوان عبر `NO_PROXY`. وراجِع إخراج جامع البيانات بحثًا عن أخطاء في اكتشاف البيانات الوصفية. علمًا بأن العرض التوضيحي يستخدم بيانات وصفية محاكاة ولا يتصل بـ IMDS.

### لا تظهر أي سجلات {#no-logs}

* تأكد من أن المسار المحدد في `include` موجود وأن جامع البيانات يملك صلاحية قراءته.
* أنشئ إدخالات سجل جديدة بعد بدء التشغيل، إذ يتجاوز الإعداد `start_at: end` المحتوى الموجود مسبقًا.
* راجع مخرجات جامع البيانات بحثًا عن أخطاء في المصادقة أو التصدير، وتأكد من إمكانية الوصول إلى نقطة النهاية من المثيل.
* تحقق من مصدر **Logs** وعامل تصفية اسم الخدمة والنطاق الزمني. استخدم **Last 2 days** في العرض التوضيحي.

### تعذّر التحليل النحوي للسجلات بشكل صحيح {#logs-not-parsing}

قارن الطوابع الزمنية في ملفك بالتهيئة المحددة. أما في syslog التقليدي، فاضبط المنطقة الزمنية الصحيحة للمضيف. واحرص على ألا تجمع إلا الملفات المطابقة للصيغة التي تمت تهيئتها.
