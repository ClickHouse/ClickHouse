اجمع سجلات PostgreSQL بتنسيق CSV باستخدام مُجمِّع OpenTelemetry، ثم أرسلها إلى ClickHouse Observability. ويمكنك استخدام [مجموعة البيانات التجريبية](#demo-dataset) لتجربة التكامل دون الحاجة إلى تثبيت PostgreSQL.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* Docker لتشغيل أمثلة جامع البيانات
* لاستخدام سجلاتك الخاصة: PostgreSQL 14 أو إصدار أحدث، مع إمكانية الوصول إلى ملفات التهيئة وملفات السجل الخاصة به
* للعرض التوضيحي: `curl` لتنزيل العينة

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="خدمة في المرحلة التجريبية" />

    افتح ClickHouse Observability وانتقل إلى **إعدادات الفريق → Data → بيانات القياس عن بُعد المُدارة**. انسخ نقطة نهاية OTLP عبر HTTP ومفتاح API الخاصين بك. يمكنك استخدام **Copy connection details** لنسخ التهيئة، أو **Reveal key** لعرض المفتاح المخفي.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال في قسم بيانات القياس عن بُعد المُدارة](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    لاستخدام أمثلة مُصدِّر OTLP أدناه، عيّن هذه المتغيرات في الطرفية التي ستشغّل منها جامع البيانات:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية الدقيقة لخدمتك، بما فيها المنفذ، وبمفتاح API الخاص بها. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/logs`؛ إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP عبر HTTP الخاصة بجامع البيانات لديك، على أن يكون الوصول إليها ممكنًا (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب المصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من التهيئات أدناه. راجع [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed) للاطلاع على إرشادات الإعداد.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

يجب أن تكون نقطة النهاية قابلة للوصول من حاوية جامع البيانات. إذا كان جامع البيانات الوجهة يعمل على هذا الحاسوب نفسه، فاستخدم `http://host.docker.internal:4318`. تتضمن أوامر Docker أدناه مطابقة المضيف.

## التكامل مع قاعدة بيانات PostgreSQL قائمة {#existing-postgres}

<Steps>
  <Step title="تهيئة التسجيل في PostgreSQL" id="configure-postgres">
    حدِّد موقع ملف التهيئة بتنفيذ استعلام SQL التالي بصفتك مسؤولًا عن قاعدة البيانات:

    ```sql
    SHOW config_file;
    ```

    أضف هذه الإعدادات إلى الملف `postgresql.conf` أو حدّثها فيه:

    ```conf
    logging_collector = on
    log_destination = 'csvlog'
    log_directory = '/var/log/postgresql'
    log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
    log_file_mode = 0640
    log_timezone = 'UTC'
    log_connections = on
    log_disconnections = on
    # Optional: log statements taking more than one second
    # log_min_duration_statement = 1000
    ```

    أنشئ دليل السجلات بملكية وصلاحيات تتيح لـ PostgreSQL الكتابة فيه ولجامع البيانات القراءة منه. وإذا كان PostgreSQL يعمل ضمن حاوية، فاربط ذلك الدليل بحيث يتمكن جامع البيانات من الوصول إلى الملفات نفسها. يستخدم إخراج CSV الامتداد `.csv` حتى وإن كانت قيمة `log_filename` تنتهي بـ `.log`.

    أعد تشغيل PostgreSQL باستخدام آلية النشر المعتمدة لديك، على سبيل المثال:

    ```bash
    sudo systemctl restart postgresql
    # Or, for Docker:
    docker restart <postgres-container>
    ```

    تحقّق من ملف CSV النشط:

    ```sql
    SELECT pg_current_logfile('csvlog');
    ```

    يتوقع المحلل النحوي أدناه [تنسيق CSV الخاص بـ PostgreSQL المكوّن من 26 عمودًا](https://www.postgresql.org/docs/14/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-CSVLOG). أما إصدارات PostgreSQL الأقدم وتنسيقات السجلات الأخرى، فتتطلب محللًا نحويًا مختلفًا.
  </Step>

  <Step title="تهيئة جامع البيانات" id="configure-collector">
    احفظ ما يلي في ملف باسم `postgres-logs-monitoring.yaml`:

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql-*.csv
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql"

          - type: add
            field: resource["service.name"]
            value: "postgresql-service"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    يحلّل المستقبِل إدخالات CSV متعددة الأسطر، ويحتفظ بطوابعها الزمنية ومتونها، ويضيف `service.name` بالقيمة `postgresql-service`. وتبقى حقول مثل `database_name` و`error_severity` و`message` و`query` متاحةً بوصفها سمات للسجل.
  </Step>

  <Step title="شغّل جامع البيانات" id="run-collector">
    من الدليل الذي يحتوي على ملف التهيئة، نفّذ الأمر التالي. عدّل دليل السجلات على المضيف عند الحاجة. إذا كانت ملفات السجل قابلة للقراءة من قِبل المجموعة، فأضف `--group-add LOG_GROUP_ID`، مستخدمًا ID المجموعة الرقمي الذي يظهر في ناتج الأمر `ls -ln /var/log/postgresql`.

    ```bash
    docker run --rm --name postgres-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/postgresql:/var/log/postgresql:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    اترك الطرفية مفتوحة. يستخدم المستقبِل الإعداد `start_at: end`، لذا أنشئ اتصالًا جديدًا بقاعدة البيانات أو نفّذ استعلامًا يُسبّب error بعد تشغيل جامع البيانات:

    ```sql
    SELECT 1 / 0;
    ```
  </Step>

  <Step title="تحقق من السجلات" id="verify-logs">
    افتح **بحث**، واختر **Logs**، وطبّق عامل تصفية على `ServiceName:postgresql-service`، ثم اختر **Last 15 minutes**. وسّع أحد السجلات لفحص سمات PostgreSQL ومستوى الخطورة الخاصين به.
  </Step>
</Steps>

  <Step title="تهيئة جامع بيانات العرض التوضيحي" id="configure-demo">

    ```yaml
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql-demo"

          - type: add
            field: resource["service.name"]
            value: "postgresql-demo"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-10T23:59:47Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    يُزيح معالج الطابع الزمني المخصص للعرض التوضيحي فقط بيانات العينة إلى آخر 24 ساعة، بحيث تنتهي قبل دقيقتين من وقت الإدخال. وتبقى سمات الطابع الزمني الأصلية ومتون السجلات كما هي دون تغيير. احذف هذا المعالج عند استخدام سجلات PostgreSQL الخاصة بك.
  </Step>

  <Step title="شغّل جامع بيانات العرض التوضيحي" id="run-demo">
    من داخل الدليل الذي يحتوي على ملف التهيئة وملف السجل الذي نزّلته، شغّل الأمر التالي:

    ```bash
    docker run --rm --name postgres-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
    ```

    اترك الطرفية مفتوحة أثناء التحقق من إدخال البيانات، ثم أوقف جامع البيانات بالضغط على **Ctrl+C** عند الانتهاء. تؤدي إعادة تشغيل العرض التوضيحي إلى إعادة إدخال بيانات العينة بطوابع زمنية محدَّثة.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### تعذّر بدء تشغيل جامع البيانات {#collector-fails-to-start}

افحص إخراج جامع البيانات للتحقق من وجود أخطاء في التهيئة، ثم تحقّق من ربط ملف التهيئة ومن متغيرات الاتصال في الطرفية التي يعمل فيها Docker.

### لا تظهر أي سجلات {#no-logs}

تحقّق من وجود أخطاء في المصادقة أو أخطاء في التصدير. تأكّد من مسار ملف CSV باستخدام `pg_current_logfile`، وتأكّد من أن الملفات تطابق نمط `include` الخاص بالمستقبِل، وأن جامع البيانات يملك صلاحية قراءتها. عند ضبط `start_at: end`، لا تُجمع إلا السجلات الجديدة. ولأغراض العرض التوضيحي، أضِف معالج الطابع الزمني واختر **آخر يومين**.

### رفض الصلاحية {#permission-denied}

عادةً ما ينشئ PostgreSQL ملفات السجل بحيث لا يصل إليها إلا مالكها. تستخدم التهيئة أعلاه `log_file_mode = 0640` لمنح المجموعة صلاحية القراءة؛ لذا أضف مجموعة الملف إلى حاوية جامع البيانات باستخدام `--group-add`. علمًا بأن الملفات الموجودة مسبقًا تحتفظ بصلاحياتها السابقة. تأكد كذلك من أن الدليل يتيح الوصول للمجموعة.

### أخطاء التحليل النحوي لملفات CSV {#csv-parsing-errors}

يتوقّع المحلل النحوي 26 عمودًا، وهو العدد الذي يُنتجه PostgreSQL 14 أو الإصدارات الأحدث. تأكّد من ضبط `log_destination = 'csvlog'` و`log_timezone = 'UTC'`. عدّل الترويسة إذا كنت تستخدم إصدارات أقدم أو صيغًا مخصصة؛ علمًا بأنه لا يمكن استخدام محلل CSV النحوي هذا مع سجلات stderr أو JSON.
