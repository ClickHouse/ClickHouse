اجمع مقاييس Redis باستخدام مستقبِل Redis في OpenTelemetry، ثم أرسلها إلى ClickHouse Observability. ويمكنك استخدام [مجموعة البيانات التجريبية](#demo-dataset) لتجربة التكامل دون الحاجة إلى تثبيت Redis.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* Docker لتشغيل أمثلة جامع البيانات، أو عملية نشر قائمة لـ OpenTelemetry Collector Contrib
* لمقاييسك الخاصة: مثيل Redis يمكن الوصول إليه من جامع البيانات، إضافةً إلى بيانات الاعتماد إذا كان Redis يتطلب المصادقة
* للعرض التوضيحي: الأداة `curl` لتنزيل العينة وإرسالها

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="خدمة في المرحلة التجريبية" />

    افتح ClickHouse Observability وانتقل إلى **إعدادات الفريق ← Data ← بيانات القياس عن بُعد المُدارة**. انسخ نقطة نهاية OTLP عبر HTTP ومفتاح API الخاصين بك. يمكنك استخدام **Copy connection details** لنسخ التهيئة، أو **Reveal key** لعرض المفتاح المخفي.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال في صفحة بيانات القياس عن بُعد المُدارة](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    لاستخدام أمثلة مُصدِّر OTLP أدناه، عيّن المتغيرات التالية في الطرفية التي ستشغّل منها جامع البيانات:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية الخاصة بخدمتك كما هي تمامًا، بما في ذلك المنفذ، وبمفتاح API الخاص بها. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/metrics`، إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP عبر HTTP الخاصة بجامع البيانات، على أن يكون الوصول إليها ممكنًا (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب مصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من التهيئات أدناه. راجع [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed) للاطلاع على إرشادات الإعداد.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من حاوية جامع البيانات. إذا كان جامع البيانات الوجهة يعمل على هذا الحاسوب نفسه، فاستخدم `http://host.docker.internal:4318`. تتضمن أوامر Docker أدناه مطابقة المضيف.

## التكامل مع Redis قائم {#existing-redis}

<Steps>
  <Step title="التحقق من اتصال Redis" id="verify-redis">
    من مضيف يمكنه الوصول إلى واجهة سطر أوامر Redis، تحقّق من مثيل Redis لديك:

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    يُفترض أن يُرجع الأمر الأول `PONG`، وأن يُرجع الثاني معلومات الخادم. إذا كان Redis يتطلب كلمة مرور، فاضبط `REDISCLI_AUTH` في الطرفية قبل تشغيل هذه الأوامر. وإذا كنت تستخدم مستخدمي Redis ACL، فمرِّر أيضًا `--user YOUR_REDIS_USER`.
  </Step>

  <Step title="تهيئة جامع البيانات" id="configure-collector">
    احفظ ما يلي باسم `redis-metrics.yaml`:

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # أزل التعليق إذا كان Redis يتطلب المصادقة:
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    يجمع المستقبِل مقاييس Redis كل 10 ثوانٍ، ومنها استخدام الذاكرة والعملاء والأوامر المُعالَجة وحالات الإصابة والإخفاق في مساحة المفاتيح، إضافةً إلى المفاتيح المنتهية الصلاحية أو التي جرى إخلاؤها. ويضبط معالج المورد `service.name` على `redis-service` لتسهيل التصفية.

    إذا كان Redis يتطلب المصادقة، فأزل التعليق عن حقول المستقبِل المناسبة واضبط `REDIS_USERNAME` و/أو `REDIS_PASSWORD`. تُستخدم بيانات الاعتماد هذه للاتصال بـ Redis، بينما تُستخدم قيمة التفويض الخاصة بـ OTLP للتحقق من الهوية لدى جامع البيانات في الوجهة. وإذا كان TLS مُفعَّلًا في Redis، فهيّئ إعدادات `tls` الخاصة بالمستقبِل كما هو موضح في [وثائق مستقبِل Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
  </Step>

  <Step title="تشغيل جامع البيانات" id="run-collector">
    اضبط [متغيرات الاتصال](#connection-details) وعنوان Redis الذي يمكن الوصول إليه من حاوية جامع البيانات. إذا كان Redis يعمل على هذا الحاسوب:

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    أما إذا كان Redis بعيدًا، فاستخدم اسم المضيف والمنفذ الخاصين به. وإذا كان يعمل في حاوية أخرى، فاستخدم اسم الحاوية وأضف `--network YOUR_NETWORK` إلى الأمر أدناه.

    من الدليل الذي يحتوي على `redis-metrics.yaml`، شغّل:

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    أبقِ هذه الطرفية مفتوحة طوال مدة جمع المقاييس. وانتظر مرور فاصلَي جمع على الأقل قبل التحقق من الـ UI.
  </Step>

  <Step title="التحقق من المقاييس" id="verify-metrics">
    استورد [لوحة المعلومات](#dashboards)، واربط رسومها البيانية بمصدر **Metrics** لديك، ثم صفِّ النتائج باستخدام `ServiceName:redis-service`. اختر **Last 15 minutes** وشغّل لوحة المعلومات. من الطبيعي أن تبقى قيم عمليات الإخلاء والاتصالات المرفوضة صفرًا في مثيل Redis سليم.
  </Step>
</Steps>

## مجموعة بيانات تجريبية {#demo-dataset}

جرّب التكامل باستخدام 6,912 نقطة بيانات من نوعَي gauge وsum، أُخذت عيّناتها كل خمس دقائق على مدار 24 ساعة. تحافظ العينة على أنماط تسخين ذاكرة التخزين المؤقت، والارتفاعات المفاجئة في حركة المرور، وحالات memory-pressure الموجودة في مجموعة البيانات الأصلية. ستحتاج إلى Docker و`curl` وبيانات اتصال OTLP HTTP الخاصة بجامع البيانات في الوجهة.

اضبط [متغيرات الاتصال](#connection-details) قبل البدء.

<Steps>
  <Step title="تنزيل عينة المقاييس" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="تهيئة جامع البيانات التجريبي" id="configure-demo-collector">
    احفظ ما يلي باسم `redis-metrics-demo.yaml`:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      يُحدِّث التحويل المخصص للعرض التوضيحي فقط الطوابع الزمنية، مع الحفاظ على قيم المقاييس وعلى الفاصل الزمني بين طابعَي البداية والنهاية لكل نقطة. احذفه عند استخدام مقاييس Redis الحية. ويُبقي حدُّ الدفعة حجمَ عمليات الرفع صغيرًا بما يكفي لجامع البيانات في الوجهة.
    </Note>
  </Step>

  <Step title="تشغيل جامع البيانات التجريبي" id="run-demo-collector">
    من الدليل الذي يحتوي على ملف التهيئة، شغّل جامع البيانات واترك هذه الطرفية مفتوحة:

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="إرسال العينة" id="load-metrics">
    في طرفية أخرى، شغّل هذا الأمر من دليل التنزيل:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    تشير استجابة مثل `{}` أو `{"partialSuccess":{}}` إلى أن جامع البيانات المحلي قَبِل الطلب. راجع طرفية جامع البيانات بحثًا عن أخطاء التصدير، وانتظر بضع ثوانٍ حتى تكتمل إعادة التوجيه. وبعد التحقق من البيانات، أوقفه بالضغط على **Ctrl+C**. قد يؤدي إرسال العينة مرة أخرى إلى ظهور نقاط مكررة.
  </Step>

  <Step title="التحقق من المقاييس" id="verify-demo-metrics">
    استورد لوحة المعلومات الواردة في [القسم التالي](#dashboards)، وصفِّ النتائج حسب `ServiceName:redis-demo`، ثم اختر **آخر يومين**. تتضمن العينة مقاييس من نوعَي gauge وsum، ولا حاجة إلى الوصول المباشر إلى قاعدة البيانات.
  </Step>
</Steps>

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### تعذّر بدء تشغيل جامع البيانات {#collector-fails-to-start}

تحقّق من طرفية جامع البيانات بحثًا عن أخطاء في التهيئة. وتأكّد من ربط ملف YAML في المسار المذكور في التوثيق، ومن تعيين متغيرات نقطة النهاية والمصادقة المطلوبة في الطرفية التي تشغّل منها Docker.

### لا تظهر أي مقاييس {#no-metrics}

* افحص إخراج جامع البيانات بحثًا عن أخطاء اتصال Redis أو أخطاء التصدير عبر OTLP.
* تحقّق من إمكانية الوصول إلى Redis من حاوية جامع البيانات. وفي حالة استخدام الحاويات، تأكّد من أنها تتشارك شبكة Docker المقصودة.
* تحقّق من بيانات اعتماد Redis، ومن أن المستخدم يملك صلاحية تنفيذ الأوامر التي يتطلبها [مستقبِل Redis](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver).
* افحص مصدر **Metrics** وعامل تصفية اسم الخدمة والنطاق الزمني. وفي العرض التوضيحي، اختر **آخر يومين** وتأكّد من تضمين تحويل الطابع الزمني في مسار المعالجة.
* في الخدمات المُدارة، طابِق نقطة نهاية OTLP عبر HTTP ومفتاح API من نوع Bearer مع ما يظهر في **بيانات القياس عن بُعد المُدارة**. أما جامعو البيانات المُدارون ذاتيًا، فاستخدم إعدادات المصادقة الخاصة بهم.
