اجمع سجلات AWS CloudWatch باستخدام مُجمِّع OpenTelemetry وأرسلها إلى ClickHouse Observability. استخدم [مجموعة البيانات التجريبية](#demo-dataset) لتجربة التكامل دون الحاجة إلى إعداد صلاحيات الوصول إلى AWS.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability
* Docker مع Docker Compose لتشغيل أمثلة جامع البيانات، أو عملية نشر قائمة لـ OpenTelemetry Collector Contrib
* لاستخدام سجلاتك الخاصة: حساب AWS يتضمن مجموعات سجلات CloudWatch، وAWS CLI v2، وبيانات اعتماد تملك الصلاحيات الموضحة أدناه
* للعرض التوضيحي: الأداة `curl` لتنزيل العينة

### بيانات الاتصال {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="خدمة في المرحلة التجريبية" />

    افتح ClickHouse Observability وانتقل إلى **إعدادات الفريق ← Data ← بيانات القياس عن بُعد المُدارة**. انسخ نقطة نهاية OTLP عبر HTTP ومفتاح API الخاصين بك. يمكنك استخدام **Copy connection details** لنسخ التهيئة، أو **Reveal key** لعرض المفتاح المحجوب.

    <div className="ch-image-lg">
      <Frame>
        ![بيانات الاتصال في صفحة بيانات القياس عن بُعد المُدارة](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    لاستخدام أمثلة مُصدِّر OTLP أدناه، اضبط هذه المتغيرات في الطرفية التي ستشغّل منها جامع البيانات:

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    استبدل العناصر النائبة بنقطة النهاية الفعلية لخدمتك، بما فيها المنفذ، وبمفتاح API الخاص بها. استخدم نقطة نهاية HTTP الأساسية دون اللاحقة `/v1/logs`، إذ يُلحق المُصدِّر مسار الإشارة تلقائيًا.
  </Tab>

  <Tab title="مُدار ذاتيًا" id="self-managed">
    استخدم نقطة نهاية OTLP عبر HTTP الخاصة بجامع البيانات، على أن يكون الوصول إليها ممكنًا (مثل `http://YOUR_COLLECTOR_HOST:4318`)، إلى جانب إعدادات المصادقة. إذا كان جامع البيانات لا يتطلب المصادقة، فاحذف كتلة `headers` الخاصة بالمُصدِّر من التهيئات أدناه. للاطلاع على إرشادات الإعداد، راجع [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed).

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من حاوية جامع البيانات. إذا كان جامع البيانات الوجهة يعمل على هذا الحاسوب نفسه، فاستخدم `http://host.docker.internal:4318`. تتضمن أوامر Docker أدناه مطابقة المضيف.

## التكامل مع مجموعات سجلات CloudWatch الموجودة {#existing-cloudwatch}

<Steps>
  <Step title="تهيئة بيانات اعتماد AWS" id="configure-aws">
    في حال استخدام AWS SSO، سجّل الدخول ثم صدّر بيانات اعتماد مؤقتة كمتغيرات بيئة في الطرفية التي ستشغّل منها جامع البيانات:

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    استبدل اسم ملف التعريف والمنطقة بالقيم الخاصة بك. وإذا كنت تستخدم بيانات اعتماد من متغيرات البيئة، فاضبط `AWS_ACCESS_KEY_ID` و`AWS_SECRET_ACCESS_KEY`، و`AWS_SESSION_TOKEN` في حال استخدام بيانات اعتماد مؤقتة، إضافةً إلى `AWS_REGION`. تمنح بيانات الاعتماد هذه صلاحية قراءة سجلات AWS، وهي مستقلة عن بيانات اعتماد OTLP الخاصة بالوجهة.

    تحتاج هوية IAM إلى الصلاحيات التالية. استبدل `YOUR_REGION` و`YOUR_ACCOUNT_ID`، وحيثما كان ذلك مناسبًا، اقصر مورد مجموعة السجلات على المجموعات التي تنوي جمعها:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    اعرض مجموعات السجلات المتاحة لاختيار الأسماء التي ستستخدمها في التهيئة:

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="تهيئة مستقبِل CloudWatch" id="configure-receiver">
    احفظ هذا الملف باسم `cloudwatch-logs.yaml`. استبدل `/aws/lambda/my-function` بإحدى مجموعات السجلات في حسابك، وأضف مجموعات أخرى ضمن `named` حسب الحاجة.

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    تبدأ هذه التهيئة بسجلات الساعة الأخيرة، ثم تستطلع البيانات كل دقيقة. عدّل قيمة `initial_lookback` لضبط النافذة الأولية. وفي غياب تخزين دائم لنقاط التحقق، قد تؤدي إعادة تشغيل جامع البيانات إلى إعادة قراءة تلك النافذة وإنتاج سجلات مكررة.

    ولاكتشاف المجموعات حسب البادئة بدلاً من ذلك، استبدل كتلة `groups` بما يلي:

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    استخدم إمّا `named` أو `autodiscover`. وللاطلاع على خيارات إضافية، بما فيها نقاط التحقق المحفوظة بشكل دائم، راجع [وثائق مستقبِل CloudWatch](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver).
  </Step>

  <Step title="شغّل جامع البيانات" id="start-collector">
    احفظ هذا الملف باسم `docker-compose.yaml` في المجلد نفسه الذي يحتوي على `cloudwatch-logs.yaml`:

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    في الطرفية التي ضبطت فيها بيانات اعتماد AWS و[متغيرات الاتصال](#connection-details)، شغّل جامع البيانات واطّلع على مخرجاته:

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="تحقق من السجلات" id="verify-logs">
    افتح صفحة **بحث** في ClickHouse Observability، واختر مصدر **Logs**، ثم طبّق عامل التصفية `ServiceName:cloudwatch`. اختر **Last 2 hours** وانتظر مرور فاصل استطلاع أو اثنين حتى تظهر السجلات.

    ابحث عن سمات الموارد التالية:

    * `aws.region`: منطقة AWS
    * `cloudwatch.log.group.name`: مجموعة السجلات
    * `cloudwatch.log.stream`: دفق السجل

    تظهر رسالة السجل في الحقل `Body`. يحتفظ المستقبِل بالرسالة كما هي، لكنه لا يستنتج مستوى الخطورة من نصها. ولكي تعمل لوحات لوحة المعلومات المعتمدة على مستوى الخطورة، يجب أن يعبّئ مسار معالجة السجلات لديك الحقل `SeverityText`.
  </Step>
</Steps>

## مجموعة بيانات تجريبية {#demo-dataset}

تضم العينة 12,785 سجلًا تغطي 24 ساعة من نشاط Lambda وECS والمهام التي تعمل في الخلفية، وتشمل مجموعات السجلات والتدفقات وقيم مستوى الخطورة. ولا يتطلب هذا المسار بيانات اعتماد AWS ولا وصولًا مباشرًا إلى قاعدة البيانات.

<Steps>
  <Step title="تنزيل العينة" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="تهيئة جامع البيانات التجريبي" id="configure-demo-collector">
    احفظ ما يلي باسم `cloudwatch-demo.yaml` في دليل التنزيل:

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      تقرأ التهيئة التجريبية العينةَ بتنسيق صفوف ClickHouse، وتستعيد متن السجل ومستوى الخطورة والسمات. أما تحويل الطابع الزمني فيُزيح العينة لتقع تقريبًا ضمن الساعات الـ 24 الماضية، على أن تنتهي قبل دقيقتين من وقت الاستيعاب. استخدم تهيئة المستقبِل الخاصة بـ CloudWatch الواردة أعلاه مع سجلاتك الفعلية للحفاظ على طوابعها الزمنية الأصلية.
    </Note>
  </Step>

  <Step title="تشغيل جامع البيانات التجريبي" id="run-demo-collector">
    اضبط [متغيرات الاتصال](#connection-details)، ثم شغّل الأمر التالي من دليل التنزيل:

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    أبقِ الطرفية مفتوحة ريثما يقرأ جامع البيانات الملف ويصدّره، وراجع مخرجاته للتأكد من خلوّها من الأخطاء. علمًا بأن تشغيل حاوية جديدة مرة أخرى قد يؤدي إلى تكرار سجلات العينة.
  </Step>

  <Step title="التحقق من السجلات التجريبية" id="verify-demo-logs">
    افتح **Search**، واختر مصدر **Logs** الخاص بك، وصفِّ النتائج باستخدام `ServiceName:cloudwatch-demo`، ثم اختر **آخر يومين**. وسّع أحد السجلات لفحص متنه ومستوى خطورته ومجموعة السجلات والدفق. بعد التحقق من البيانات، أوقف جامع البيانات التجريبي بالضغط على **Ctrl+C**.

      <Frame>
        ![سجلات CloudWatch التجريبية في ClickHouse Observability](/images/clickstack/observability-cloudwatch-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### لا تظهر أي سجلات {#no-logs}

* افحص مخرجات `docker compose logs otel-collector` بحثًا عن أخطاء المصادقة في AWS أو رفض الوصول أو أخطاء تصدير OTLP.
* تأكد من تطابق `AWS_REGION` وأسماء مجموعات السجلات مع حسابك، ومن احتواء المجموعات على أحداث ضمن `initial_lookback` أو على أحداث جديدة بعد بدء التشغيل.
* تحقق من أذونات IAM الخاصة بـ `logs:DescribeLogGroups` و`logs:FilterLogEvents`.
* تحقق من نقطة نهاية الوجهة وإعدادات المصادقة الواردة في [بيانات الاتصال](#connection-details).
* تحقق من مصدر **Logs** وعامل تصفية اسم الخدمة والنطاق الزمني. وفي العرض التوضيحي، اختر **آخر يومين**.

### انتهاء صلاحية بيانات اعتماد AWS {#expired-credentials}

إذا كنت تستخدم SSO، فسجّل الدخول وصدّر بيانات اعتماد جديدة، ثم أعد إنشاء جامع البيانات ليتلقى متغيرات البيئة الجديدة:

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

لا تكفي إعادة تشغيل الحاوية الحالية وحدها لتحديث بيانات اعتمادها. وفي حال استخدام بيانات اعتماد مؤقتة أخرى، جدّد مفتاح الوصول والمفتاح السري ورمز الجلسة (session token) قبل إعادة إنشاء الحاوية.

### السجلات الأقدم مفقودة {#older-logs}

يبدأ المثال بفترة استرجاع مدتها ساعة واحدة. زِد قيمة `logs.initial_lookback`، أو استبدلها بـ `logs.start_from` مع طابع زمني بصيغة RFC3339 لتحديد وقت بدء معين. لا تضبط الخيارين معًا. أعد تشغيل جامع البيانات بعد تغيير تهيئته، علمًا بأن إعادة قراءة نافذة زمنية قد تؤدي إلى سجلات مكررة.

## الخطوات التالية {#next-steps}

* أعدّ [التنبيهات](/ar/clickstack/observability/features/alerts) لرصد الارتفاعات المفاجئة في الأخطاء.
* أنشئ [لوحات المعلومات](/ar/clickstack/observability/features/dashboards/overview) الإضافية.
* في بيئة الإنتاج، استخدم دور IAM على البنية التحتية لجامع البيانات في AWS بدلاً من تصدير بيانات الاعتماد المؤقتة يدويًا. راجع [إرسال بيانات OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry) للاطلاع على إرشادات النشر.
