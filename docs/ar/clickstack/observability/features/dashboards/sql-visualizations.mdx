يدعم ClickHouse Observability التمثيلات المرئية المبنية على استعلامات SQL مباشرة. ويمنحك ذلك تحكمًا كاملًا في منطق الاستعلام، مع الاستفادة في الوقت نفسه من النطاقات الزمنية وعوامل التصفية المحددة على مستوى لوحة المعلومات، ومن آلية تصيير المخططات.

تفيد التمثيلات المرئية القائمة على SQL عندما تحتاج إلى ما يتجاوز إمكانات مستكشف المخططات المدمج، كربط الجداول أو إنشاء عمليات تجميع معقدة لا تدعمها أداة إنشاء المخططات.

## إنشاء تصوّر بياني قائم على SQL {#creating-a-raw-sql-chart}

لإنشاء تصوّر بياني قائم على SQL، افتح محرر بلاطة لوحة المعلومات واختر **SQL**.

<div className="ch-image-lg">
  <Frame>
    ![محرر تصوّر SQL مع تعليمات الاستعلام ووحدات الماكرو](/images/clickstack/observability-sql-editor.png)
  </Frame>
</div>

بعد ذلك:

1. اختر **Connection** (الاتصال) الذي سيُنفَّذ عليه الاستعلام.
2. يمكنك اختياريًا تحديد **Source** (المصدر)، إذ يتيح ذلك تطبيق عوامل التصفية على مستوى لوحة المعلومات على المخطط عبر الماكرو `$__filters`.
3. اكتب استعلام SQL في المحرر، مستعينًا بمعلمات الاستعلام ووحدات الماكرو لربطه بالنطاق الزمني للوحة المعلومات وعوامل التصفية والمتغيرات.
4. انقر على **Run** (تشغيل) لمعاينة النتائج، ثم على **Save** (حفظ) لحفظ التصوّر.

## معلمات الاستعلام {#query-parameters}

تتيح [معلمات الاستعلام](/ar/reference/syntax#defining-and-using-query-parameters) لاستعلامات SQL الإشارة إلى النطاق الزمني الحالي ومستوى التجزئة في لوحة المعلومات. وتعتمد هذه المعلمات صيغة الاستعلامات ذات المعلمات في ClickHouse: `{paramName:Type}`.

### المعلمات المتاحة {#available-parameters}

تختلف المعلمات المتاحة باختلاف نوع المخطط:

**مخططات السلاسل الزمنية (بما فيها المخططات الشريطية المكدّسة):**

| المعلمة                         | النوع | الوصف                                                                   |
| ------------------------------- | ----- | ----------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | بداية نطاق التاريخ في لوحة المعلومات (بالمللي ثانية منذ نقطة بدء الزمن) |
| `{endDateMilliseconds:Int64}`   | Int64 | نهاية نطاق التاريخ في لوحة المعلومات (بالمللي ثانية منذ نقطة بدء الزمن) |
| `{intervalSeconds:Int64}`       | Int64 | حجم الفترة الزمنية بالثواني (وفقًا لمستوى التجزئة)                      |
| `{intervalMilliseconds:Int64}`  | Int64 | حجم الفترة الزمنية بالمللي ثانية (وفقًا لمستوى التجزئة)                 |

**المخططات الجدولية والدائرية والرقمية:**

| المعلمة                         | النوع | الوصف                                                                   |
| ------------------------------- | ----- | ----------------------------------------------------------------------- |
| `{startDateMilliseconds:Int64}` | Int64 | بداية نطاق التاريخ في لوحة المعلومات (بالمللي ثانية منذ نقطة بدء الزمن) |
| `{endDateMilliseconds:Int64}`   | Int64 | نهاية نطاق التاريخ في لوحة المعلومات (بالمللي ثانية منذ نقطة بدء الزمن) |

## الماكرو {#macros}

الماكرو اختصاراتٌ تُستبدَل بتعبيرات ClickHouse SQL الشائعة. تبدأ بالبادئة `$__`، ويجري استبدالها قبل إرسال الاستعلام إلى ClickHouse.

### ماكرو حدود الوقت {#time-boundary-macros}

تُرجِع وحدات الماكرو هذه تعبير ClickHouse يمثّل وقت البدء أو وقت الانتهاء في لوحة المعلومات، ولا تقبل أي وسيطات.

| الماكرو          | يُوسَّع إلى                                                           | نوع العمود |
| ---------------- | --------------------------------------------------------------------- | ---------- |
| `$__fromTime`    | `toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))` | DateTime   |
| `$__toTime`      | `toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))`   | DateTime   |
| `$__fromTime_ms` | `fromUnixTimestamp64Milli({startDateMilliseconds:Int64})`             | DateTime64 |
| `$__toTime_ms`   | `fromUnixTimestamp64Milli({endDateMilliseconds:Int64})`               | DateTime64 |
| `$__interval_s`  | `{intervalSeconds:Int64}`                                             | Int64      |

### وحدات ماكرو عوامل تصفية الوقت {#time-filter-macros}

تُنشئ وحدات الماكرو هذه جزءًا من عبارة `WHERE` يُصفّي column ضمن النطاق الزمني للوحة المعلومات.

| الماكرو                               | الوصف                                                                           |
| ------------------------------------- | ------------------------------------------------------------------------------- |
| `$__timeFilter(column)`               | يُصفّي column من النوع `DateTime` ضمن نطاق لوحة المعلومات                       |
| `$__timeFilter_ms(column)`            | يُصفّي column من النوع `DateTime64` (بدقة الميلي ثانية) ضمن نطاق لوحة المعلومات |
| `$__dateFilter(column)`               | يُصفّي column من النوع `Date` ضمن نطاق لوحة المعلومات                           |
| `$__dateTimeFilter(dateCol, timeCol)` | يُصفّي باستخدام column منفصل لكلٍّ من النوعين `Date` و`DateTime`                |
| `$__dt(dateCol, timeCol)`             | اسم بديل لـ `$__dateTimeFilter`                                                 |

**مثال على توسيع** `$__timeFilter(TimestampTime)`:

```sql
TimestampTime >= toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
AND TimestampTime <= toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
```

### ماكرو الفواصل الزمنية {#time-interval-macros}

تقسّم وحدات الماكرو هذه column الطابع الزمني إلى فواصل زمنية تتوافق مع مستوى التجزئة في لوحة المعلومات. وتُستخدم عادةً في عبارتَي `SELECT` و`GROUP BY` ضمن مخططات السلاسل الزمنية. ولا تتوفر وحدات الماكرو هذه إلا في التمثيلات المرئية من نوع **سلسلة زمنية**، بما في ذلك المخططات الشريطية المكدّسة.

| الماكرو                      | الوصف                                                                                   |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| `$__timeInterval(column)`    | يقسّم column من النوع `DateTime` إلى فواصل زمنية طول كلٍّ منها `intervalSeconds`        |
| `$__timeInterval_ms(column)` | يقسّم column من النوع `DateTime64` إلى فواصل زمنية طول كلٍّ منها `intervalMilliseconds` |

**مثال على توسيع** `$__timeInterval(TimestampTime)`:

```sql
toStartOfInterval(toDateTime(TimestampTime), INTERVAL {intervalSeconds:Int64} second)
```

### ماكرو عامل تصفية لوحة المعلومات {#dashboard-filter-macro}

| الماكرو      | الوصف                                                              |
| ------------ | ------------------------------------------------------------------ |
| `$__filters` | يُستبدَل بشروط التصفية على مستوى لوحة المعلومات (يتطلب تحديد مصدر) |

عند تحديد **مصدر** في المخطط مع وجود عوامل تصفية نشطة على لوحة المعلومات، يُوسَّع `$__filters` إلى شروط `WHERE` المقابلة في SQL. أما عند عدم تحديد أي مصدر أو عدم تطبيق أي عامل تصفية، فيُوسَّع إلى `(1=1)`، ولذلك يمكن تضمينه دائمًا بأمان في عبارة `WHERE`.

لا يطبّق `$__filters` إلا عوامل التصفية التي يكون فيها خيار **بث شرط التصفية** مفعّلًا. أما عوامل التصفية المعروضة كمتغيرات، فيُشار إليها صراحةً كما هو موضح أدناه.

### ماكرو متغيرات لوحة المعلومات {#dashboard-variables}

عندما يكون عامل تصفية لوحة المعلومات [متاحًا كمتغير](/ar/clickstack/observability/features/dashboards/overview#dashboard-variables)، يمكن الإشارة إلى القيم المحددة فيه في أي موضع من الاستعلام. لا تتوفر هذه الماكرو إلا في البطاقات التابعة للوحة معلومات تُعرّف متغيرًا واحدًا على الأقل.

| الماكرو                                       | الوصف                                                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `$__filter($<variable>)`                      | يُستبدل بـ `toString(<filter expression>) IN ($variable)` عند تحديد قيم لـ `variable`، وإلا فبـ `1=1`. |
| `$__filter(<expression>, $<variable>)`        | يُستبدل بـ `<expression> IN ($variable)` عند تحديد قيم لـ `variable`، وإلا فبـ `1=1`.                  |
| `$__conditionalAll(<condition>, $<variable>)` | يُستبدل بـ `<condition>` عند وجود تحديد للمتغير، وإلا فبـ `1=1`.                                       |

يمكن أيضًا إدراج قيم المتغير مباشرةً بالشكل `$name` أو `${name}`، مع صيغة اختيارية: `${name:sqlstring}` (الصيغة الافتراضية)، أو `${name:csv}`، أو `${name:regex}`. في الصيغة الافتراضية، يُصيَّر المرجع المباشر إلى `NULL` قبل تحديد أي قيمة، لذا يُفضَّل استخدام الماكرو المذكورة أعلاه حيثما يُتوقع وجود مسند.

## كيفية عرض نتائج الاستعلام في المخططات {#how-results-are-plotted}

تربط واجهة UI columns النتيجة تلقائيًا بعناصر المخطط استنادًا إلى أنواع الـcolumns، وتختلف قواعد المطابقة باختلاف نوع المخطط.

### مخططات السلاسل الزمنية {#line-and-stacked-bar-charts}

| الدور                   | نوع الـcolumn                                  | الوصف                                                                               |
| ----------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------- |
| **الطابع الزمني**       | أول column من النوع `Date` أو `DateTime`      | يُستخدم بوصفه المحور السيني (x).                                                    |
| **قيمة سلسلة البيانات** | جميع الـcolumns الرقمية                        | يُرسم كل column رقمي بوصفه سلسلة بيانات مستقلة، وتكون هذه القيم عادةً قيمًا مُجمَّعة. |
| **أسماء المجموعات**     | columns من النوع `String` أو `Map` أو `Array` | اختياري. تُرسم الصفوف التي تختلف في قيم المجموعات بوصفها سلاسل بيانات مستقلة.       |

### المخطط الدائري {#pie-chart}

| الدور             | نوع الـcolumn                                  | الوصف                                             |
| ----------------- | ------------------------------------------- | ------------------------------------------------- |
| **قيمة الـslice**  | أول column رقمي                               | تحدد حجم كل slice.                                |
| **تسمية الـslice** | columns من النوع `String` أو `Map` أو `Array` | اختياري. تصبح كل قيمة مميزة تسميةً لإحدى الـslices. |

### مخطط رقمي {#number-chart}

| الدور   | نوع الـcolumn    | الوصف                                                 |
| ------- | ------------- | ----------------------------------------------------- |
| **رقم** | أول column رقمي | تُعرض القيمة الموجودة في الصف الأول من أول column رقمي. |

### المخطط الجدولي {#table-chart}

تُعرض جميع columns النتيجة مباشرةً بوصفها columns في الجدول.

### مخطط السلسلة الزمنية — عدد السجلات بمرور الوقت لكل خدمة {#example-line-chart}

يحسب هذا الاستعلام عدد أحداث السجل لكل خدمة، مع تجميعها في فواصل زمنية تتوافق مع مستوى التجزئة في لوحة المعلومات.

```sql
SELECT
  toStartOfInterval(TimestampTime, INTERVAL {intervalSeconds:Int64} second) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

* يُستخدم `ts` (`DateTime`) طابعًا زمنيًا للمحور السيني.
* يُرسم `count` (رقمي) بوصفه قيمة سلسلة البيانات.
* يُنشئ `ServiceName` (string) خطًا منفصلًا لكل خدمة.

### مخطط السلسلة الزمنية — باستخدام الماكرو {#example-line-chart-macros}

فيما يلي الاستعلام نفسه مكتوبًا باستخدام الماكرو لمزيد من الإيجاز:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  ServiceName,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filters
GROUP BY ServiceName, ts
ORDER BY ts ASC
```

### مخطط السلسلة الزمنية — استخدام متغيرات لوحة المعلومات {#example-line-chart-variables}

لنفترض وجود لوحة معلومات تتضمّن متغير `service` مرتبطًا بالعمود `ServiceName` ومتغير `severity` مرتبطًا بالعمود `SeverityText`؛ عندئذٍ يقصر هذا الاستعلام نطاق المخطط على الخدمة المحددة حاليًا ويستبعد مستويات الخطورة المحددة. ويتوسّع كلا الماكرو إلى `1=1` ما دام المتغير المرتبط به بلا تحديد، لذا يُعرَض المخطط دون أي تصفية إلى أن يختار المستخدم قيمة.

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

### مخطط الأعمدة المتراكم — عدد الأخطاء حسب مستوى الخطورة {#example-stacked-bar}

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  lower(SeverityText),
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND lower(SeverityText) IN ('error', 'warn')
  AND $__filters
GROUP BY SeverityText, ts
ORDER BY ts ASC
```

### مخطط جدولي — أبطأ 10 نقاط نهاية {#example-table}

```sql
SELECT
  SpanName AS endpoint,
  avg(Duration) / 1000 AS avg_duration_ms,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY SpanName
ORDER BY avg_duration_ms DESC
LIMIT 10
```

### مخطط دائري — توزيع الطلبات حسب الخدمة {#example-pie}

```sql
SELECT
  ServiceName,
  count() AS request_count
FROM otel_traces
WHERE $__timeFilter(Timestamp)
  AND $__filters
GROUP BY ServiceName
```

* يحدّد `request_count` (رقمي) حجم كل slice.
* يُستخدم `ServiceName` (string) لتسمية كل slice.

### مخطط رقمي — إجمالي عدد الأخطاء (error) {#example-number}

```sql
SELECT
  count() AS total_errors
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND SeverityText = 'error'
  AND $__filters
```

تُعرض القيمة الرقمية الوحيدة `total_errors` المأخوذة من الصف الأول.

## ملاحظات {#notes}

* تُنفَّذ التمثيلات المرئية القائمة على SQL مع تفعيل وضع `readonly`، لذا لا يُسمح إلا باستعلامات `SELECT`.
* يدعم كل تمثيل مرئي قائم على SQL استعلامًا واحدًا فقط، ولا تُدعم الاستعلامات المتعددة.
* يوفّر محرر SQL اقتراحات الإكمال التلقائي لمعلمات الاستعلام والماكرو على حدٍّ سواء.
* لتطبيق عوامل تصفية لوحة المعلومات على التمثيلات المرئية القائمة على SQL، يجب اختيار مصدر. وينبغي أن يطابق المصدرُ الجدولَ المُستعلَم عنه لضمان دقة التصفية.
* لا تحتاج متغيرات لوحة المعلومات إلى مصدر، إذ تُستمد قيمها من القوائم المنسدلة لعوامل تصفية لوحة المعلومات، لا من مصدر المربع نفسه.
* تُقيَّم التنبيهات المُعرَّفة على مربع SQL يشير إلى أحد متغيرات لوحة المعلومات مع إبقاء جميع المتغيرات في حالتها الفارغة، لا بالقيم المحددة في لوحة المعلومات.
