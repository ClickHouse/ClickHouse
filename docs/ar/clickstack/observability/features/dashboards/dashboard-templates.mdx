يتضمن ClickHouse Observability مكتبة من قوالب لوحات المعلومات pre-built، تساعدك على عرض بيانات القياس عن بُعد الشائعة للبنية التحتية والتطبيقات بصريًا. وتبدأ الرسوم البيانية بعرض البيانات فور تلقّي خدمة ClickHouse لديك بيانات القياس عن بُعد التي يتطلبها القالب.

## تصفّح القوالب المتاحة {#browsing-templates}

لتصفّح مكتبة القوالب المضمّنة، انتقل إلى **Dashboards** وانقر على **تصفّح قوالب لوحات المعلومات**.

## استيراد قالب {#importing-a-template}

في **Step 2: Map Data**، راجِع **Dashboard Name** و**Tags**، ثم تحقَّق من مصدر البيانات في العمود **To** لكل مربع وعامل تصفية. قد تكون المصادر محددة مسبقًا. في المثال أدناه، يربط قالب Node.js Runtime Metrics الرسوم البيانية الخاصة به وعامل تصفية الخدمة بالمصدر **Metrics**. انقر على **إكمال الاستيراد** لإنشاء لوحة المعلومات.

## القوالب pre-built {#pre-built-templates}

### Browser RUM {#browser-rum}

يوفّر قالب **Browser RUM** (مراقبة المستخدمين الفعليين) مؤشرات Core Web Vitals، ومئينات زمن تحميل الصفحات، وتقسيم حركة المرور حسب الفئات، وتتبّع الأخطاء. ويعتمد القالب على جلسات المتصفح المزوّدة بأدوات الرصد عبر SDK للمتصفح من HyperDX، أو عبر أدوات رصد RUM من OpenTelemetry التي تُصدر `rum.sessionId`.

### مقاييس وقت التشغيل في OTel {#otel-runtime-metrics}

صُمِّمت قوالب مقاييس وقت التشغيل في OTel المدمجة للتطبيقات المزوّدة بأدوات رصد [مقاييس وقت التشغيل في OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/runtime/).

| القالب                      | الوصف                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| **.NET Runtime Metrics**    | مقاييس جمع المهملات، وتجزؤ الكومة، والاستثناءات، واستخدام مجمّع الخيوط، وCPU لتطبيقات .NET      |
| **Go Runtime Metrics**      | مقاييس استخدام الذاكرة، وعمليات تخصيص الذاكرة، وأهداف GC، واستخدام CPU، وgoroutines لتطبيقات Go |
| **JVM Runtime Metrics**     | مقاييس ذاكرة الكومة، واستخدام CPU، وخيوط التنفيذ، وGC للتطبيقات المستندة إلى JVM                |
| **Node.js Runtime Metrics** | تأخر حلقة الأحداث، واستخدام الكومة، واستخدام CPU، وذاكرة V8 لتطبيقات Node.js                    |
| **Python Runtime Metrics**  | استخدام CPU، واستخدام الذاكرة، وعمليات جمع GC، وعدد خيوط التنفيذ لتطبيقات بايثون                |

ملاحظات:

* يُهيَّأ كل قالب مع [عامل تصفية مخصص](/ar/clickstack/observability/features/dashboards/overview#custom-filters) يستهدف الخدمات التي تطابق سمة المورد [`telemetry.sdk.language`](https://opentelemetry.io/docs/specs/semconv/registry/attributes/telemetry/#telemetry-sdk-language) فيها بيئةَ التشغيل الخاصة بلوحة المعلومات.
* قد تختلف أسماء المقاييس من إصدار إلى آخر من OpenTelemetry SDK. فإذا كان SDK الذي تستخدمه يُصدر أسماء مقاييس مختلفة، [فعدِّل التمثيلات المرئية](/ar/clickstack/observability/features/dashboards/overview#dashboards-editing-visualizations) بما يتوافق مع بياناتك.

## المخططات المُدارة ذاتيًا {#self-configured-schemas}

في عمليات النشر المُدارة ذاتيًا التي تستخدم مخططات جداول مقاييس مخصصة، عدّل عامل تصفية الخدمة في القالب بحيث يستعلم عن أعمدة اسم الخدمة وسمات المورد المناسبة. أما في أحمال العمل ذات الأحجام الكبيرة، فيُنصح بـ[تجسيد السمات الأكثر استعلامًا](/ar/clickstack/self-configured/managing/performance-tuning#materialize-frequently-queried-attributes)، مثل `ResourceAttributes['telemetry.sdk.language']`، لتقليل أوقات تحميل عوامل التصفية.
