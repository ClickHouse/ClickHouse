أرسِل السجلات والتتبّعات والمقاييس من وكلاء Datadog الحاليين لديك إلى ClickHouse Observability، مع إمكانية استمرار تطبيقاتك في استخدام حِزم SDK الخاصة بـ Datadog. اختر نقطة نهاية مُدارة أو هيّئ مستقبِل Datadog في جامع البيانات الخاص بك، ثم اتّبع خطوات تهيئة الوكيل نفسها الموضّحة أدناه.

## المتطلبات المسبقة {#prerequisites}

* خدمة ClickHouse Observability مُدارة أو مُدارة ذاتيًا.
* وكيل Datadog قيد التشغيل يجمع الإشارات التي تريد ترحيلها. أما بالنسبة إلى التتبّع، فيجب أن يكون تطبيقك مُرسِلًا له مسبقًا إلى ذلك الوكيل عبر Datadog SDK.
* إمكانية الوصول إلى الشبكة من الوكيل إلى نقطة نهاية مستقبِل Datadog الخاص بك.

## إعداد الوجهة {#connection-details}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="عرض تجريبي" />

    افتح خدمتك وانتقل إلى **Team Settings → Data → Managed Telemetry**. انسخ **OTLP HTTP endpoint** و**مفتاح API**.

    <div className="ch-image-lg">
      <Frame>
        ![صفحة Managed Telemetry تعرض نقطة نهاية OTLP HTTP ومفتاح API بشكل مُقنَّع](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    تستخدم نقطة نهاية Datadog اسم المضيف نفسه مع المنفذ `8126`، ولا حاجة إلى جامع بيانات إضافي. استخدم هذه القيم في تهيئة الوكيل (Agent) أدناه:

    | الإعداد                  | القيمة                                       |
    | ------------------------ | -------------------------------------------- |
    | `YOUR_API_KEY`           | مفتاح API المخصّص لاستيعاب البيانات في خدمتك |
    | `YOUR_DATADOG_URL`       | `https://YOUR_OTEL_HOST:8126`                |
    | `YOUR_DATADOG_HOST_PORT` | `YOUR_OTEL_HOST:8126`                        |
    | `logs_no_ssl`            | `false`                                      |
  </Tab>

  <Tab title="مُدار ذاتيًا" id="self-managed">
    يتضمن [مُجمِّع OpenTelemetry الخاص بـ ClickStack](/ar/clickstack/self-configured/ingesting-data/collector) [مستقبِل Datadog](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/datadogreceiver). هيّئ المستقبِل واربطه بمسارات معالجة البيانات الخاصة بالسجلات والتتبّعات والمقاييس.

    احفظ طبقة التهيئة التالية باسم `datadog-collector.yaml`. تضيف هذه الطبقة مستقبِل Datadog إلى مسارات معالجة السجلات والتتبّعات والمقاييس الموجودة في جامع البيانات، مع الإبقاء على مستقبِل OTLP:

    ```yaml
    receivers:
      datadog:
        endpoint: 0.0.0.0:8126

    service:
      pipelines:
        logs/in:
          receivers: [otlp/hyperdx, datadog]
        traces:
          receivers: [otlp/hyperdx, datadog]
        metrics:
          receivers: [otlp/hyperdx, datadog]
    ```

    اضبط تفاصيل اتصال ClickHouse، ثم شغّل جامع البيانات. عند بدء التشغيل العادي، يُنشئ جامع البيانات مخطط بيانات القياس عن بُعد في قاعدة البيانات المحددة في `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE`؛ لذا يحتاج مستخدم ClickHouse إلى صلاحية إنشاء قاعدة البيانات والجداول. وإن كانت لديك قاعدة بيانات قياس عن بُعد بالفعل، فاستخدم اسمها.

    يتطلب هذا المثال Docker، ويستخدم الإصدار `2.40.0` من جامع البيانات، ويقتصر إتاحة مستقبِل Datadog فيه على المضيف المحلي:

    ```shell
    export CLICKHOUSE_ENDPOINT='https://YOUR_CLICKHOUSE_HOST:8443'
    export CLICKHOUSE_USER='YOUR_CLICKHOUSE_USER'
    export CLICKHOUSE_PASSWORD='YOUR_CLICKHOUSE_PASSWORD'
    export HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE='default'

    docker run --rm --name datadog-collector \
      -e CLICKHOUSE_ENDPOINT \
      -e CLICKHOUSE_USER \
      -e CLICKHOUSE_PASSWORD \
      -e HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE \
      -e CUSTOM_OTELCOL_CONFIG_FILE=/etc/datadog-collector.yaml \
      -v "$(pwd)/datadog-collector.yaml:/etc/datadog-collector.yaml:ro" \
      -p 127.0.0.1:18126:8126 \
      clickhouse/clickstack-otel-collector:2.40.0
    ```

    اترك جامع البيانات قيد التشغيل في هذه الطرفية أثناء تهيئة الوكيل (Agent) والتحقق منه، واستخدم طرفية أخرى لتنفيذ بقية الأوامر.

    استخدم هذه القيم إذا كان الوكيل (Agent) يعمل على المضيف نفسه:

    | الإعداد                  | القيمة                                                                       |
    | ------------------------ | ---------------------------------------------------------------------------- |
    | `YOUR_API_KEY`           | قيمة مؤقتة غير فارغة مثل `local-test`؛ إذ لا يتحقق منها هذا المستقبِل المحلي |
    | `YOUR_DATADOG_URL`       | `http://localhost:18126`                                                     |
    | `YOUR_DATADOG_HOST_PORT` | `localhost:18126`                                                            |
    | `logs_no_ssl`            | `true`                                                                       |

    يفصل منفذ المضيف `18126` هذه الوجهة عن مستمع تتبّع التطبيقات الخاص بالوكيل (Agent) على المنفذ `8126`. أما إذا كان الوكيل يعمل داخل حاوية، فاربط الحاويتين بشبكة Docker نفسها، واستخدم `http://datadog-collector:8126` و`datadog-collector:8126` قيمتين للوجهة.

    يستخدم هذا المثال مستمع HTTP بلا مصادقة ومقصورًا على المضيف المحلي. أما للوكلاء (Agents) العاملين على مضيفين آخرين، فوفّر مسار شبكة محميًا، وهيّئ TLS والمصادقة عند نقطة الدخول (ingress) قبل إتاحة المستقبِل. علمًا بأن `OTLP_AUTH_TOKEN` يهيّئ مصادقة OTLP في جامع البيانات، لكنه لا يؤمّن مستمع Datadog هذا.
  </Tab>
</Tabs>

## تهيئة وكيل Datadog {#configure-datadog-agent}

حدّث [ملف التهيئة `datadog.yaml`](https://docs.datadoghq.com/agent/configuration/agent-configuration-files/) الخاص بالوكيل. يوجد هذا الملف عادةً في المسار `/etc/datadog-agent/datadog.yaml` على Linux، وفي المسار `/opt/datadog-agent/etc/datadog.yaml` على macOS.

ادمج الإعدادات التالية في التهيئة الحالية، مستخدمًا قيم الوجهة الواردة في علامة التبويب أعلاه:

```yaml
api_key: "YOUR_API_KEY"

# Metrics destination
dd_url: "YOUR_DATADOG_URL"

# Use the v2 metrics intake.
use_v3_api:
  series:
    enabled: false

# Trace destination
apm_config:
  enabled: true
  apm_dd_url: "YOUR_DATADOG_URL"
  features:
    - disable-convert-traces

# Log destination
logs_enabled: true
logs_config:
  logs_dd_url: "YOUR_DATADOG_HOST_PORT"
  force_use_http: true
  logs_no_ssl: false # Set to true for the local HTTP receiver.

remote_updates: false
remote_configuration:
  enabled: false
```

استبدل `YOUR_DATADOG_URL` بعنوان URL الكامل للوجهة، و`YOUR_DATADOG_HOST_PORT` بقيمة `hostname:port` الخاصة بها، دون نظام المصادقة. اضبط `logs_no_ssl` على القيمة المحددة للوجهة لديك.

<Note>
  يحافظ `disable-convert-traces` على توافق حمولات التتبّع التي يرسلها الوكيل مع مستقبِل Datadog. فعند استخدام وكيل Datadog بالإصدار 7.85.2 وcollector core بالإصدار 0.155.0، كانت الحمولة المفهرسة الافتراضية للوكيل تُقبَل بالاستجابة HTTP 200، لكنها لم تُنتج أي مقاطع تتبع. استخدم الإعداد أعلاه لإعادة توجيه التتبّع، واحتفظ بأي عناصر أخرى في قائمة `apm_config.features` الحالية لديك.
</Note>

احتفظ بتكاملات جمع السجلات وتهيئة تتبّع التطبيقات الحالية لديك. فهذه الإعدادات تغيّر الوجهة التي يرسل إليها الوكيل بيانات القياس عن بُعد فقط؛ ولا تُمكّن جمع السجلات لكل تطبيق على حدة، ولا تضيف أدوات الرصد. إذا كنت تهيّئ الوكيل عبر [متغيرات البيئة](https://docs.datadoghq.com/agent/guide/environment-variables/)، فحدّث الإعدادات المقابلة هناك أيضًا، بما في ذلك `DD_API_KEY`.

تعيد هذه التهيئة توجيه سجلات الوكيل والتتبّع والمقاييس من Datadog إلى ClickHouse Observability. ولتقييمها أولًا، طبّقها على وكيل تجريبي قبل تعميمها على بقية عمليات النشر لديك.

## إعادة التشغيل والتحقق {#restart-and-verify}

أعد تشغيل الوكيل لتطبيق التهيئة. على نظام Linux:

```shell
sudo systemctl restart datadog-agent
sudo datadog-agent status
```

على نظام macOS:

```shell
sudo launchctl kickstart -k system/com.datadoghq.agent
```

بالنسبة إلى الوكيل المُشغَّل داخل حاوية، حدِّث تهيئته ثم أعد نشر الحاوية.

أنشئ نشاطًا جديدًا في التطبيق، ثم افتح ClickHouse Observability واختر نطاقًا زمنيًا حديثًا:

* **السجلات:** اختر مصدر السجلات الخاص بك وصفِّ النتائج حسب قيمة `ServiceName` الخاصة بالتطبيق.
* **التتبّعات:** اختر مصدر التتبعات الخاص بك وصفِّ النتائج حسب قيمة `ServiceName` الخاصة بالتطبيق.
* **المقاييس:** ابحث عن مقياس يُصدره تطبيقك أو الوكيل. ولاختبار DogStatsD، أصدِر مقياسًا من نوع gauge باسم محدد وتحقّق من قيمته.

إذا لم تظهر البيانات، فراجع حالة الوكيل بحثًا عن أخطاء في التسليم. وتحقّق من اسم المضيف والمنفذ ومفتاح API وإعدادات الوصول إلى الشبكة الخاصة بخدمتك. وتأكّد كذلك من أن الوكيل يجمع نوع الإشارة المعني، وأن أي تجاوزات للإعدادات عبر متغيرات البيئة تشير إلى الوجهة نفسها.

بالنسبة إلى التتبّعات، تحقّق من معرّف تتبّع معروف بدلًا من الاكتفاء بعدادات التسليم الناجح في الوكيل. وإذا كان عامل التصفية حسب الخدمة يُخفي التتبّع، فابحث باستخدام `TraceId`؛ إذ قد يستخدم المستقبِل الخدمة الأساسية لأداة التتبّع اسمًا للخدمة على مستوى المورد، مع الإبقاء على تجاوز الخدمة الخاص بكل span في attribute الـ span المسمّى `service.name`. اضبط `DD_SERVICE` في تهيئة التتبّع الخاصة بتطبيقك لتحديد اسم الخدمة الأساسي له.

## الإشارات المدعومة {#supported-signals}

مستقبِل Datadog ميزة تجريبية، إذ يحوّل سجلات Datadog والتتبّع والمقاييس المدعومة إلى نموذج بيانات OpenTelemetry الذي يستخدمه ClickHouse Observability. تعتمد التهيئة الواردة أعلاه على واجهة استقبال المقاييس v2، أما ميزات Datadog الخلفية الأخرى فتقع خارج نطاق مسار الترحيل هذا.

يمكنك الإبقاء على أدوات رصد Datadog الحالية لديك أثناء ترحيل تطبيقاتك إلى OpenTelemetry تدريجيًا.
