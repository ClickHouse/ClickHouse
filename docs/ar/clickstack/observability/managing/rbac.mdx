يتضمن ClickHouse Observability ميزة التحكم في الوصول المستند إلى الأدوار (RBAC)، ما يتيح لك تعريف أدوار مخصصة بصلاحيات دقيقة المستوى على [لوحات المعلومات](/ar/clickstack/observability/features/dashboards/overview)، و[عمليات البحث المحفوظة](/ar/clickstack/observability/features/search)، والمصادر، و[التنبيهات](/ar/clickstack/observability/features/alerts)، وخطافات الويب (webhooks)، ودفاتر الملاحظات. تعمل الصلاحيات على مستويين: الوصول على مستوى المورد (لا يوجد وصول، أو قراءة، أو إدارة لكل نوع من أنواع الموارد)، وقواعد اختيارية دقيقة المستوى تقيّد الوصول إلى موارد بعينها حسب الاسم أو الوسم أو المعرّف (ID). تأتي الخدمة مزوّدة بثلاثة أدوار مدمجة، ويمكنك إنشاء أدوار مخصصة تلائم احتياجات فريقك.

## المتطلبات المسبقة لوصول المستخدمين {#user-access-prerequisites}

تتحقق الخدمة من هوية المستخدمين عبر ClickHouse Cloud. لذا يجب أن ينتمي المستخدمون إلى مؤسستك في ClickHouse Cloud وأن تكون لديهم صلاحية الوصول إلى خدمة Observability. للاطلاع على تفاصيل عضوية المؤسسة، راجع [إدارة مستخدمي السحابة](/ar/products/cloud/guides/security/cloud-access-management/manage-cloud-users).

تقابل مستويات الوصول إلى وحدة تحكم SQL في Cloud مستويات الوصول إلى Observability على النحو التالي:

| الوصول إلى وحدة تحكم SQL في Cloud           | الوصول إلى Observability                                                                       |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **مسؤول وحدة تحكم SQL** (وصول كامل)         | وصول كامل إلى الخدمة، وهو مطلوب لتفعيل [التنبيهات](/ar/clickstack/observability/features/alerts). |
| **وحدة تحكم SQL للقراءة فقط** (للقراءة فقط) | يمكن للمستخدم عرض بيانات إمكانية المراقبة وإنشاء لوحات المعلومات.                              |
| **لا يوجد وصول**                            | لا يمكن للمستخدم الوصول إلى الخدمة.                                                            |

افتح **إعدادات الفريق ← الأعضاء والأدوار** لعرض أعضاء الفريق وأدوارهم الحالية في Observability. ولإدارة عضوية المؤسسة في ClickHouse Cloud، اختر **الإدارة في وحدة التحكم**.

## الأدوار المضمّنة {#built-in-roles}

تتضمن الخدمة ثلاثة أدوار نظام لا يمكن تعديلها أو حذفها. ويُسنَد دور المسؤول افتراضيًا إلى منشئ الفريق.

| الصلاحية                    | مسؤول | عضو | ReadOnly |
| --------------------------- | :---: | :----: | :------: |
| قراءة جميع الموارد          |   ✓   |    ✓   |     ✓    |
| إدارة لوحات المعلومات       |   ✓   |    ✓   |          |
| إدارة عمليات البحث المحفوظة |   ✓   |    ✓   |          |
| إدارة المصادر               |   ✓   |    ✓   |          |
| إدارة التنبيهات             |   ✓   |    ✓   |          |
| إدارة خطافات الويب          |   ✓   |    ✓   |          |
| إدارة دفاتر الملاحظات       |   ✓   |    ✓   |          |
| تحديث إعدادات الفريق        |   ✓   |    ✓   |          |
| إنشاء الفرق وحذفها          |   ✓   |        |          |
| إدارة المستخدمين والدعوات   |   ✓   |        |          |

## تعيين الأدوار لأعضاء الفريق {#assigning-roles}

تعرض علامة التبويب **الأعضاء والأدوار** في **إعدادات الفريق** أعضاء الفريق والدور الحالي لكل منهم. لتغيير الدور، انقر على **تعديل** بجوار اسم المستخدم واختر دورًا جديدًا. يُسنَد إلى كل مستخدم دور واحد فقط.

### الدور الافتراضي للمستخدم الجديد {#default-new-user-role}

من **إعدادات الفريق** → **الأعضاء والأدوار**، استخدم خيار **الدور الافتراضي للمستخدم الجديد** الموجود أسفل قائمة الأدوار لتحديد الدور الذي يُسنَد إلى المستخدمين المنضمين إلى الفريق تلقائيًا. وإذا لم يُحدَّد دور افتراضي، يُمنح المستخدمون الجدد الدور **عضو**.

## صلاحيات الأدوار {#role-permissions}

### صلاحيات الموارد {#resource-permissions}

يمنح كل دور مستوى وصول محددًا لكل نوع من أنواع الموارد. وتتوفر ثلاثة مستويات:

| مستوى الوصول     | ما يتيحه                                                    |
| ---------------- | ----------------------------------------------------------- |
| **لا يوجد وصول** | يُخفى نوع المورد عن الدور تمامًا.                           |
| **قراءة**        | عرض المورد وإعداداته، دون إمكانية إنشائه أو تعديله أو حذفه. |
| **إدارة**        | تحكم كامل — إنشاء موارد هذا النوع وتعديلها وحذفها.          |

أنواع الموارد التي يمكنك التحكم فيها هي:

* **[لوحات المعلومات](/ar/clickstack/observability/features/dashboards/overview)** — تخطيطات لوحات المعلومات المحفوظة والرسوم البيانية.
* **[عمليات البحث المحفوظة](/ar/clickstack/observability/features/search)** — استعلامات السجلات/التتبّعات/الأحداث المحفوظة بشكل دائم.
* **المصادر** — مصادر البيانات المستخدمة للاستعلام عن بيانات إمكانية المراقبة.
* **[التنبيهات](/ar/clickstack/observability/features/alerts)** — قواعد التنبيه وإعدادات الإشعارات الخاصة بها.
* **خطافات الويب** — وجهات الإشعارات الصادرة (مثل Slack وPagerDuty ونقاط نهاية HTTP العامة) التي تُرسل إليها [التنبيهات](/ar/clickstack/observability/features/alerts) إشعاراتها. ولا يُقصد بها واجهة برمجة تطبيقات إمكانية المراقبة.
* **دفاتر الملاحظات** — دفاتر التحقيق التشاركية.

### الصلاحيات الإدارية {#administrative-permissions}

إلى جانب صلاحيات الموارد، يتضمن كل دور إعدادين إداريين:

* **المستخدمون** (لا يوجد وصول · قراءة) — يحدد ما إذا كان بإمكان الدور عرض أعضاء الفريق وأدوارهم. تتم إدارة عضوية المؤسسة عبر **إدارة في وحدة التحكم**.
* **الفريق** (قراءة · إدارة) — يحدد ما إذا كان بإمكان الدور عرض الإعدادات على مستوى الفريق أو تعديلها، مثل سياسات الأمان وتهيئة RBAC.

### قواعد الوصول دقيقة المستوى {#fine-grained-access-rules}

تدعم لوحات المعلومات وعمليات البحث المحفوظة والمصادر ودفاتر الملاحظات ضوابط دقيقة تقيّد الوصول إلى موارد بعينها ضمن الفئة الواحدة. استخدم هذه الضوابط عندما تحتاج إلى حصر صلاحيات دور ما في موارد محددة، بدلًا من منحه وصولًا شاملًا إلى نوع المورد بأكمله.

#### الوصول الافتراضي مقابل الضوابط الدقيقة {#access-control-modes}

لكل نوع من الموارد **وضع للتحكم في الوصول**:

* **الوصول الافتراضي**: يطبّق مستوى وصول واحدًا (لا يوجد وصول، أو قراءة، أو إدارة) على جميع الموارد من هذا النوع.
* **ضوابط دقيقة**: تتيح لك تعريف قواعد وصول تطابق موارد محددة بناءً على شرط معيّن. أما الموارد التي لا تطابق أي قاعدة، فلا يُسمح بالوصول إليها افتراضيًا.

للتبديل بين الوضعين، انقر على السهم لتوسيع نوع المورد في محرر الدور، ثم استخدم مفتاح التبديل الخاص بـ **وضع التحكم في الوصول**.

#### تهيئة قواعد الوصول {#configuring-access-rules}

تتكوّن كل قاعدة وصول من **شرط** و**مستوى وصول**. وتطابق الشروط الموارد بناءً على خصائصها:

<div className="ch-image-md">
  <Frame>
    ![تلميح أداة الشرط: مطابقة الموارد حسب الاسم أو الوسم (المعروض في العنوان) أو حسب المعرّف (الموجود في عنوان URL)](/images/clickstack/rbac/condition-tip.webp)
  </Frame>
</div>

| حقل الشرط | المُعامِلات      | ما يطابقه                                                                                                                                                | مثال                                                                                    |
| --------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Name**  | `is`، `contains` | الاسم المعروض للمورد، مثل عنوان لوحة المعلومات.                                                                                                          | Name contains `production`: يطابق أي لوحة معلومات يتضمن عنوانها &quot;production&quot;. |
| **وسم**   | `is`، `contains` | الوسوم المُسنَدة إلى المورد عبر لوحة الوسوم في الزاوية العلوية اليمنى من عرض المورد. يتوفر للوحات المعلومات وعمليات البحث المحفوظة ودفاتر الملاحظات فقط. | وسم is `critical`: يطابق الموارد الموسومة بـ &quot;critical&quot;.                      |
| **ID**    | `is`، `contains` | معرّف المورد، ويظهر في شريط عنوان URL عند فتح المورد.                                                                                                    | ID is `abc123`: يطابق موردًا واحدًا بعينه.                                              |

تُظهر لقطة الشاشة التالية معرّف لوحة المعلومات مُبرزًا في شريط عنوان URL، والوسم &quot;TESTING&quot; ظاهرًا في لوحة الوسوم (أعلى اليمين).

<div className="ch-image-lg">
  <Frame>
    ![لوحة معلومات تعرض معرّف المورد في شريط عنوان URL ووسمًا في الزاوية العلوية اليمنى](/images/clickstack/rbac/dashboard-id-and-tag-example.webp)
  </Frame>
</div>

يمكنك إضافة عدة قواعد لكل نوع من الموارد. وتُفحص كل قاعدة على حدة وفق منطق OR، أي أن المورد يكون متاحًا إذا طابق **أيًّا** من القواعد، أما الموارد التي لا تطابق أي قاعدة فلا يمكن الوصول إليها.

<div className="ch-image-md">
  <Frame>
    ![تلميح أداة قواعد الوصول مع منطق OR](/images/clickstack/rbac/access-rules-tip.webp)
  </Frame>
</div>

**مثال**: لمنح دورٍ وصولًا للقراءة فقط إلى لوحات معلومات الاختبار، وسّع لوحات المعلومات، ثم بدّل إلى ضوابط دقيقة، وأضف قاعدتين:

* **Name** `contains` `testing` بمستوى الوصول **قراءة**
* **وسم** `is` `testing` بمستوى الوصول **قراءة**

وبذلك تصبح أي لوحة معلومات تطابق إحدى القاعدتين متاحة.

## سياسات الأمان {#security-policies}

ضمن **إعدادات الفريق → الأعضاء والأدوار → سياسات الأمان**، يُخفي الخيار **تعطيل تصدير البيانات** عناصر التحكم في تنزيل بيانات السجلات ونسخها، بما في ذلك تفاصيل الصفوف، عن جميع أعضاء الفريق. ومع ذلك، يظل بإمكان المستخدمين تحديد النص المعروض على الشاشة، كما تواصل واجهة برمجة التطبيقات وخادم MCP إرجاع البيانات. لا يمنع هذا الإعداد الوصول إلى البيانات الأساسية.

توجد عناصر التحكم في الذكاء الاصطناعي التوليدي ضمن **إعدادات الفريق → واجهة برمجة التطبيقات والوكلاء → تهيئة الذكاء الاصطناعي التوليدي**. لمزيد من التفاصيل، راجع [تهيئة الذكاء الاصطناعي التوليدي](/ar/clickstack/observability/managing/config#generative-ai).
