افتح **إعدادات الفريق** في ClickHouse Observability لإدارة الوصول إلى البيانات، واتصالات واجهة برمجة التطبيقات والوكيل، والتكاملات، وإعدادات الاستعلام. تتوافق الأقسام التالية مع علامات التبويب في التطبيق. وتتولى ClickHouse إدارة إدخال البيانات والمخططات والبنية التحتية والتحجيم.

## البيانات {#data}

افتح **إعدادات الفريق ← البيانات** لعرض مصادرك وبيانات الاتصال اللازمة لإرسال بيانات القياس عن بُعد.

### المصادر {#datasource-settings}

يسرد قسم **المصادر** المصادر التي توفرها خدمتك المُدارة:

| المصدر        | البيانات                             |
| ------------- | ------------------------------------ |
| **السجلات**   | أحداث السجل                          |
| **التتبّعات** | مقاطع التتبع الخاصة بالتتبّع الموزّع |
| **المقاييس**  | بيانات المقاييس                      |
| **الجلسات**   | بيانات إعادة تشغيل جلسات المتصفح     |

يعرض كل مصدر اتصال القراءة المرتبط به، واسم الجدول الخاص به عند الاقتضاء. استخدم مفتاح التبديل الموجود على يمين المصدر لتمكينه أو تعطيله. عند تعطيل مصدر، تُحفظ تهيئته، لكنه يُخفى من محددات المصدر ولا يُختار تلقائيًا. ولا يؤدي التعطيل إلى إيقاف إدخال بيانات القياس عن بُعد أو حذف البيانات المخزَّنة. لإتاحة المصدر مجددًا في المحددات، أعد تمكينه.

### بيانات القياس عن بُعد المُدارة {#managed-telemetry}

أسفل **المصادر**، يعرض قسم **بيانات القياس عن بُعد المُدارة** حالة التخزين وحالة مُجمِّع OpenTelemetry، إلى جانب بيانات الاتصال اللازمة لإرسال البيانات إلى خدمتك.

* اختر **URL** أو **إعداد جامع البيانات** أو **متغيرات البيئة** لعرض بيانات الاتصال بالصيغة التي تناسبك.
* استخدم **نسخ بيانات الاتصال** لنسخ التهيئة، واختر **إظهار المفتاح** عند الحاجة إلى عرض بيانات الاعتماد المخفية.
* استخدم **إرسال سجل تجريبي** لإرسال سجل عيّنة إلى الخدمة.

للاطلاع على تعليمات تهيئة تطبيقاتك وجامعي البيانات، راجع [استيعاب البيانات](/ar/clickstack/observability/ingesting-data/overview).

### قائمة الوصول لعناوين IP {#ip-access-list}

ضمن **بيانات القياس عن بُعد المُدارة**، استخدم **قائمة الوصول لعناوين IP ← تعديل** لتحديد عناوين IP أو نطاقات CIDR المسموح لها بالوصول إلى نقاط النهاية الخاصة بجامع البيانات لديك.

### نقاط النهاية الخاصة {#private-endpoints}

استخدم **إعداد نقطة نهاية خاصة** لتهيئة اتصال عبر شبكة خاصة بجامع البيانات لديك. وفي عمليات النشر على AWS، يعتمد ذلك على AWS PrivateLink. ويفتح رابط **نقاط النهاية الخاصة** صفحة نقاط النهاية الخاصة بالمؤسسة في وحدة تحكم ClickHouse Cloud.

### منطقة الخطر {#service-settings}

يؤدي **حذف المستودع** إلى حذف مستودع إمكانية المراقبة وجميع خدماته، إذ تُحذف خدمات القراءة أولاً، ثم الخدمة الرئيسية. لا تستخدم هذا الخيار إلا عندما لا تعود بحاجة إلى المستودع أو بياناته.

## الأعضاء والأدوار {#members-and-roles}

افتح **إعدادات الفريق → الأعضاء والأدوار** لمراجعة أدوار RBAC والدور الافتراضي المُسنَد إلى المستخدمين الجدد. واستخدم **الإدارة في وحدة التحكم** لإدارة عضوية الفريق في ClickHouse Cloud. لمزيد من التفاصيل، راجع [التحكم في الوصول المستند إلى الأدوار](/ar/clickstack/observability/managing/rbac).

## واجهة برمجة التطبيقات والوكلاء {#api-and-agents}

افتح **إعدادات الفريق ← واجهة برمجة التطبيقات والوكلاء** لإدارة مفاتيح استيعاب البيانات، والاطلاع على معرّفات الخدمة، وربط الوكلاء، وتهيئة ميزات الذكاء الاصطناعي.

### مفاتيح API لاستيعاب البيانات {#ingestion-api-keys}

يعرض قسم **مفاتيح API** كلاً من **Team ID** و**معرّف الخدمة** ومفاتيح استيعاب البيانات. تُستخدم مفاتيح استيعاب البيانات للتحقق من هوية بيانات القياس عن بُعد المُرسَلة إلى مُجمِّع OpenTelemetry.

أدخل اسمًا ثم اختر **Create key** لإنشاء مفتاح لمصدر أو بيئة معيّنة. وتتوفر لكل مفتاح موجود عناصر التحكم **إظهار المفتاح** و**Copy key** و**Freeze** و**Revoke**. ويسري مفعول التغييرات في غضون دقيقة تقريبًا.

أما رابط **Manage API Keys** المستقل، فيفتح إعدادات المؤسسة في ClickHouse Cloud لإدارة المفاتيح المستخدمة مع واجهة برمجة تطبيقات الإدارة.

### ربط وكيل {#connect-an-agent}

ضمن **Connect your AI agents**، استخدم **Enable MCP for this service** لتشغيل خادم MCP البعيد أو إيقافه. اختر العميل الذي تستخدمه وانسخ التهيئة المُولَّدة له، إذ تتضمن معرّف الخدمة لكي تُوجَّه طلبات الوكيل إلى خدمتك. ويفتح الخيار **Manage sessions** وحدة تحكم ClickHouse Cloud لمراجعة جلسات MCP. تعتمد نقطة نهاية MCP السحابية على بروتوكول OAuth، لذا سجّل الدخول بحساب ClickHouse Cloud الخاص بك عندما يطلب منك العميل ذلك. راجع [ربط عميل MCP](/ar/clickstack/observability/mcp#managed-connecting-a-client) للاطلاع على تعليمات الإعداد وقائمة العملاء المدعومين.

### استخدام واجهة برمجة التطبيقات {#use-the-api}

استخدم [واجهة برمجة تطبيقات ClickHouse Observability](/ar/clickstack/observability/api-reference) لإدارة لوحات المعلومات والتنبيهات والموارد الأخرى برمجيًا. تُصادَق طلبات API باستخدام معرّف مفتاح API لـ ClickHouse Cloud والسرّ (secret) الخاص به، عبر المصادقة الأساسية لـ HTTP. راجع [مصادقة API](/ar/clickstack/observability/api-reference#authentication) للاطلاع على الصلاحيات المطلوبة وكيفية إعداد المفتاح.

بيانات اعتماد API منفصلة عن API key لاستيعاب البيانات الموجود ضمن **بيانات → بيانات القياس عن بُعد المُدارة**. أما عملاء MCP فيستخدمون بروتوكول OAuth بدلًا من أيٍّ من مفتاحَي API.

### تصدير إلى Terraform {#export-to-terraform}

ميزة **تصدير إلى Terraform** مُصنَّفة على أنها **تجريبي**. اختر أنواع الموارد التي تريد تضمينها، ثم استخدم **Download import file** لإضافتها إلى مشروع Terraform. وتوفّر UI الأمر اللازم لإنشاء تهيئة الموارد باستخدام مزوّد ClickHouse. أما الاتصالات التي تديرها المنصة، فتُصدَّر كمتغيرات محلية (locals) للإشارة إليها فقط.

تُصدَّر التنبيهات المرتبطة بعمليات البحث المحفوظة وبمربعات لوحة المعلومات. ويتطلب الملف الذي يتضمن تنبيهًا على مربع استخدام الإصدار 3.28.0 أو أحدث من موفّر Terraform الخاص بـ ClickHouse. ولا تُصدَّر تنبيهات مستكشف المخططات، ولا تنبيهات المربعات التي لا تحمل اسمًا فريدًا وغير فارغ في لوحة المعلومات التابعة لها. وتضبط التهيئة المُنشأة لتنبيه المربع الحقلين `dashboard_id` و`tile_id` على قيم حرفية، لذا استبدلهما بمراجع إلى المورد `clickhouse_clickstack_dashboard` قبل تطبيقها.

### تهيئة الذكاء الاصطناعي التوليدي {#generative-ai}

استخدم **تهيئة الذكاء الاصطناعي التوليدي** لتمكين ميزات الذكاء الاصطناعي التوليدي في الخدمة أو تعطيلها. وتشمل هذه الميزات مساعد الذكاء الاصطناعي للمخططات في مستكشف المخططات، و[دفاتر ملاحظات الذكاء الاصطناعي](/ar/clickstack/observability/notebooks).

## التكاملات {#integrations}

افتح **إعدادات الفريق → التكاملات** لإدارة الـ webhooks. اختر **Add Webhook** لإضافة تكامل خاص بإشعارات التنبيه. لمعرفة كيفية تهيئة التنبيهات، راجع [التنبيهات](/ar/clickstack/observability/features/alerts).

## إعدادات الاستعلام {#query-settings}

افتح **إعدادات الفريق → إعدادات الاستعلام** لضبط طريقة استعلام التطبيق من ClickHouse. اختر **تعديل** بجوار أي إعداد لتغييره. تحمل علامة التبويب هذه الوسم **تجريبي** في UI.

| الإعداد                                                | الغرض                                                                                                   |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| **حد صفوف البحث**                                      | يحدد عدد الصفوف المُعادة لكل استعلام في صفحة **بحث** وفي لوحات عرض لوحة المعلومات الخاصة بالبحث.        |
| **مهلة الاستعلام (بالثواني)**                          | يضبط الحد الأقصى لوقت تنفيذ الاستعلام.                                                                  |
| **الحد الأقصى للصفوف المقروءة (البيانات الوصفية فقط)** | يحدد عدد صفوف الجدول التي تفحصها استعلامات البيانات الوصفية.                                            |
| **حد جلب مفاتيح عوامل التصفية**                        | يتحكم في عدد مفاتيح عوامل التصفية التي تُجلب عند اختيار **عوامل تصفية إضافية** في صفحة **بحث**.         |
| **استعلامات البيانات الوصفية للحقول**                  | يحدد ما إذا كان التطبيق يجلب البيانات الوصفية للحقول من ClickHouse.                                     |
| **تنفيذ الاستعلامات بالتوازي عند الإمكان**             | يتيح تشغيل الاستعلامات المؤهلة القائمة على النوافذ بالتوازي، وقد يزيد ذلك من ذروة الحمل على ClickHouse. |

تتضمن علامة التبويب أيضاً عناصر للتحكم في عتبة الحظر المرن للمُدرَّج التكراري الخاص بالبحث وفي مدد نوافذ البحث. استخدم **إعادة الضبط إلى الافتراضي** لإعادة إعدادات الاستعلام إلى قيمها الافتراضية.

## ترحيل المخطط {#schema-migrations}

افتح **إعدادات الفريق → ترحيل المخطط** لعرض سجل عمليات الترحيل.

للاطلاع على إعدادات المصدر والمخطط في البيئات المُدارة ذاتيًا، راجع [إعدادات المصدر والمخطط في البيئات المُدارة ذاتيًا](/ar/clickstack/self-configured/managing/config).
