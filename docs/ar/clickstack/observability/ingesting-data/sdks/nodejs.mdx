تُبنى ClickStack Node.js SDK على OpenTelemetry SDK من المصدر الأصلي وعلى أدوات auto-instrumentation الخاصة به، وتضيف إليها التقاط مخرجات وحدة التحكم، والتقاط الاستثناءات غير الملتقطة، وتفريغ بيانات القياس عن بُعد عند إيقاف التشغيل. أما التطبيقات التي سبق أن هيّأت OpenTelemetry، فيمكنها مواصلة استخدام SDK الحالية لديها و[تهيئة تصدير OTLP](/ar/clickstack/observability/ingesting-data/opentelemetry).

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## التثبيت {#install}

استخدم Node.js **الإصدار 22.15 أو أحدث**. ثبّت SDK في تطبيقك:

```shell
npm install @clickhouse/clickstack-node
```

تدعم الحزمة وحدات ES وCommonJS. ويثبّت npm التبعية النظيرة (peer dependency) `@opentelemetry/api` تلقائيًا. وإذا كان تطبيقك يستورد هذه الحزمة مباشرةً، فثبّت `@opentelemetry/api@~1.9.1`؛ إذ يقع الإصدار 1.10 خارج نطاق الإصدارات التي تدعمها حزمة SDK هذه.

## تهيئة الوجهة {#configure-destination}

اضبط متغيرات البيئة قبل تشغيل تطبيقك. استخدم نقطة نهاية OTLP HTTP الأساسية دون `/v1/traces` أو `/v1/logs` أو `/v1/metrics`، إذ تُلحق المُصدِّرات هذه المسارات تلقائيًا.

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="إصدار تجريبي" />

    افتح **إعدادات الفريق ← البيانات ← Managed Telemetry** وانسخ **نقطة نهاية OTLP HTTP** و**مفتاح API**. استخدم نقطة نهاية HTTPS والمنفذ كما يظهران لخدمتك تمامًا:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات، ومفتاح الإدخال المُهيَّأ لمستقبِل OTLP التابع له. لمعرفة كيفية إعداد جامع البيانات، راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```

    تفترض نقطة النهاية هذه أن التطبيق وجامع البيانات يعملان على المضيف نفسه. أما إذا كان جامع البيانات يعمل على مضيف آخر، فاستبدلها بعنوان يمكن الوصول إليه من تطبيقك.

## تشغيل تطبيقك {#start-application}

حمّل SDK مسبقًا قبل أن يستورد تطبيقك المكتبات التي يزوّدها SDK بأدوات جمع بيانات الرصد:

```shell
node --import @clickhouse/clickstack-node/register server.js
```

استبدل `server.js` بملف نقطة الدخول الخاص بتطبيقك. يحمّل هذا الأمر الـ SDK قبل بدء تشغيل تطبيقك، ويستخدم متغيرات البيئة التي تمت تهيئتها أعلاه. وهو يدعم تطبيقات CommonJS وتطبيقات وحدات ES.

يمكنك الآن [التحقق من إدخال البيانات](#verify-ingestion). لا تحتاج إلى البدائل أدناه إلا إذا أردت بدء التشغيل عبر برنامج نصي من npm أو تهيئة الـ SDK داخل الشيفرة.

<Accordion title="طرق بديلة لبدء التشغيل">
  الخيار `--require` مدعوم أيضًا. إذا كنت تستخدم `NODE_OPTIONS`، فاقصر نطاقه على أمر التطبيق حتى لا تُطلق أدوات الإصدار مسارات معالجة بيانات القياس عن بُعد الخاصة بها:

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  أو يمكنك بدلًا من ذلك إنشاء وحدة لإضافة أدوات الرصد وتحميلها مسبقًا. وتظل متغيرات البيئة من القسم السابق هي التي تتولى تهيئة التصدير:

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  يمنع هذا الشرط خيوط التنفيذ العاملة، مثل عمّال النقل في Pino، من تشغيل مثيلات إضافية من الـ SDK.

  استخدم إما نقطة دخول التسجيل الخاصة بالحزمة وإما وحدة إضافة أدوات الرصد الخاصة بك، ولا تُهيّئ SDK ثانيًا داخل التطبيق. تُنفَّذ عمليات الاستيراد الثابتة في وحدات ES قبل متن الوحدة، لذا فإن استدعاء `init` قبل عمليات الاستيراد الثابتة في الملف نفسه لا يضمن ترتيب التهيئة.
</Accordion>

## التحقق من إدخال البيانات {#verify-ingestion}

شغّل تطبيقك، وأرسل طلبات إلى مسار مزوّد بأدوات الرصد، واطبع رسالة في وحدة التحكم. في ClickHouse Observability، اختر نطاقًا زمنيًا حديثًا وابحث في السجلات أو التتبّعات عن `my-node-app`. وقبل التحقق من المقاييس، انتظر حتى ينقضي الفاصل الزمني لتصديرها.

إذا لم تظهر البيانات، فتحقق من رسائل تشخيص SDK على stderr، ومن نقطة النهاية والمصادقة، ومن الاتصال بالشبكة. وتأكد من تحميل أدوات الرصد قبل تبعيات التطبيق. لا يمكن تزويد المكتبات المجمّعة بأدوات الرصد تلقائيًا إذا كانت أداة التجميع تُضمِّنها مباشرةً؛ لذا أبقِ SDK والتبعيات المزوّدة بأدوات الرصد خارجية. راجع [توافق SDK](https://github.com/ClickHouse/clickstack-node#compatibility) للاطلاع على متطلبات TypeScript ووحدات ES وأطر العمل وأدوات التجميع.

## تهيئة إضافة أدوات الرصد {#configure-instrumentation}

تحتفظ متغيرات البيئة القياسية في OpenTelemetry بدلالتها المعتمدة في المصدر الأصلي، بما في ذلك أخذ العينات، والتجميع في دفعات، والمُصدِّرات، وسمات الموارد. على سبيل المثال:

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

يُلتقَط إخراج وحدة التحكم افتراضيًا. أما التقاط متن طلبات HTTP فمعطّل افتراضيًا؛ لذا لا تُمكّنه إلا إذا كان مناسبًا لطبيعة البيانات التي يعالجها تطبيقك:

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

قد تحتوي المتون الملتقطة على بيانات شخصية وبيانات اعتماد. لا يضمن SDK تنقيح البيانات بالكامل، إذ يعمل وفق مبدأ أفضل جهد ممكن؛ لذا أبقِ على التنقيح من جهة جامع البيانات عند الحاجة. راجع [خيارات الخصوصية في SDK](https://github.com/ClickHouse/clickstack-node#privacy) للاطلاع على إعدادات التقاط الترويسات، وحدود حجم المتن، وتنظيف البيانات.

### خيارات التهيئة {#initialization-options}

مرّر هذه الخيارات إلى `init` في وحدة إضافة أدوات الرصد الخاصة بك:

| الخيار                       | القيمة الافتراضية                                    | الغرض                                                                                                                                |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `endpoint`                   | `http://localhost:4318`                              | عنوان URL الأساسي لـ OTLP عبر HTTP؛ ويُستبدَل بقيمة `OTEL_EXPORTER_OTLP_ENDPOINT`                                                    |
| `serviceName`                | `unknown_service:` متبوعًا باسم الملف القابل للتنفيذ | اسم الخدمة؛ ويُستبدَل بقيمة `OTEL_SERVICE_NAME` أو `service.name` في `OTEL_RESOURCE_ATTRIBUTES`                                      |
| `environment`                | غير معيّن                                            | يعيّن `deployment.environment.name`؛ وتكون الأسبقية للمفتاح نفسه في `OTEL_RESOURCE_ATTRIBUTES`                                       |
| `apiKey`                     | غير معيّن                                            | قيمة ترويسة التفويض؛ ويُتجاهَل إذا لم يكن `OTEL_EXPORTER_OTLP_HEADERS` فارغًا بالفعل، حتى لو اقتصر على ترويسات لا علاقة لها بالتفويض |
| `httpBodyCapture`            | `false`                                              | التقاط متن طلبات HTTP؛ ويُستبدَل بقيمة `CLICKSTACK_CAPTURE_HTTP_BODY`                                                                |
| `instrumentations`           | القيم الافتراضية للتهيئة في المصدر الأصلي            | خريطة تهيئة لـ `getNodeAutoInstrumentations`؛ وتتجاوز قيم `enabled` الصريحة متغيرات البيئة الخاصة بتمكين أدوات الرصد أو تعطيلها      |
| `additionalInstrumentations` | `[]`                                                 | مثيلات إضافية لأدوات الرصد خاصة بمكتبات غير مضمّنة في الحزمة الافتراضية                                                              |

عندما تكون متغيرات البيئة غير معيّنة أو فارغة، يسري الخيار المقابل لها. لتعطيل التقاط مخرجات وحدة التحكم، أضف `console` إلى `OTEL_NODE_DISABLED_INSTRUMENTATIONS`. راجع [مرجع Node.js SDK](https://github.com/ClickHouse/clickstack-node#quick-start) للاطلاع على جميع القيم الافتراضية.

أما حالات الإنهاء الصريح للعمليات أو معالجات AWS Lambda، فراجع بشأنها [توثيق دورة حياة SDK](https://github.com/ClickHouse/clickstack-node#lifecycle).

## استخدام SDK من المصدر الأصلي {#using-upstream-sdk}

إذا كان تطبيقك يهيّئ OpenTelemetry مسبقًا، أو كان يحتاج إلى معالجات مخصصة أو سلوك لا توفره خيارات ClickStack SDK، فاستخدم `NodeSDK` من المصدر الأصلي وهيّئ التصدير عبر OTLP إلى الوجهة المذكورة أعلاه. اتبع [مثال إعداد SDK من المصدر الأصلي](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly)، الذي يشرح التهيئة الإضافية الخاصة بالمُحمِّل ودورة الحياة. لا تُهيّئ حزمتَي SDK كلتيهما في العملية نفسها.

## الترحيل من HyperDX Node.js SDK {#migration}

استبدل `@hyperdx/node-opentelemetry` بـ `@clickhouse/clickstack-node`، واستخدم نقطة الدخول الجديدة الخاصة بالتسجيل. واستبدل `HYPERDX_API_KEY` بـ `OTEL_EXPORTER_OTLP_HEADERS`، مع استخدام صيغة التفويض الخاصة بالوجهة التي اخترتها أعلاه.

لا تتضمن حزمة SDK الجديدة جميع الدوال المساعدة أو الخيارات المتوفرة في HyperDX. لذا راجع [دليل ترحيل SDK](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md) قبل استبدال تكاملات مسجّل السجلات، أو معالجات الأخطاء، أو سمات التتبّع المخصصة، أو إعدادات أخذ العينات.
