يعتمد SDK للمتصفح من ClickStack على OpenTelemetry لجمع طلبات المتصفح والأخطاء وبيانات إعادة تشغيل الجلسة. استخدمه لتحليل أحداث الواجهة الأمامية إلى جانب بيانات القياس عن بُعد الخاصة بالواجهة الخلفية في ClickHouse Observability.

<ClickStackIntegrates signals={['logs', 'traces']} />

## التثبيت {#install}

ثبّت الحزمة في تطبيق الواجهة الأمامية لديك:

```shell
npm install @clickhouse/clickstack-browser
```

تستخدم الحزمة وحدات ES. ويثبّت npm تبعيات OpenTelemetry النظيرة (peer dependencies) الخاصة بها تلقائيًا. إذا كان تطبيقك يثبّت `@opentelemetry/api` مباشرةً أيضًا، فاستخدم الإصدار `~1.9.1` واحرص على وجود نسخة واحدة منها فقط؛ إذ يقع الإصدار 1.10 خارج نطاق الإصدارات التي تدعمها حزمة SDK هذه.

## تهيئة الوجهة {#configure-destination}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="إصدار تجريبي" />

    افتح **إعدادات الفريق → البيانات → Managed Telemetry** في خدمتك، وانسخ **نقطة نهاية OTLP HTTP** و**مفتاح API**. استخدم نقطة نهاية HTTPS كاملةً بما فيها المنفذ، ومن دون مسار إشارة مثل `/v1/traces`.

    هيّئ SDK في وحدة الدخول الخاصة بتطبيقك:

    ```javascript
    import { init } from '@clickhouse/clickstack-browser';

    init({
      endpoint: 'https://YOUR_OTEL_ENDPOINT:4318',
      apiKey: 'Bearer YOUR_INGESTION_API_KEY',
      serviceName: 'my-frontend-app',
    });
    ```
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات ومفتاح الإدخال المُهيّأ له. يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من متصفحات مستخدميك. لإعداد جامع البيانات، راجع [استيعاب البيانات باستخدام OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```javascript
    import { init } from '@clickhouse/clickstack-browser';

    init({
      endpoint: 'https://YOUR_COLLECTOR_HOST:4318',
      apiKey: 'YOUR_INGESTION_API_KEY',
      serviceName: 'my-frontend-app',
    });
    ```

    استخدم المفتاح المُهيّأ لمستقبِل OTLP في جامع البيانات. ويجب أن يسمح جامع البيانات بمصدر تطبيقك ضمن تهيئة CORS لمستقبِل HTTP لديه.
  </Tab>
</Tabs>

استدعِ `init` مرة واحدة عند كل تحميل للصفحة، في المستوى الأعلى من وحدة الدخول، مثل `src/main.ts` في Vite أو `instrumentation-client.ts` في Next.js. تجري التهيئة بشكل غير متزامن، لذا قد لا تُلتقط الطلبات المُرسلة فورًا ضمن الدورة نفسها. لا تُجرِ التهيئة داخل React effect، إذ إن عملية التنظيف التي تستدعي `shutdown` توقف بيانات القياس عن بُعد نهائيًا طوال ذلك التحميل للصفحة.

<Note>
  إعدادات المتصفح، بما فيها مفتاح الإدخال، مرئية لكل من يحمّل الصفحة. لإبقاء المفتاح على خادمك، استخدم نقطة نهاية من المصدر نفسه مثل `/otel`، واحذف `apiKey`، ثم هيّئ خادمك لإعادة توجيه طلبات OTLP مع ترويسة التفويض المناسبة.
</Note>

## التحقق من إدخال البيانات {#verify-ingestion}

حمّل تطبيقك، وتفاعل مع الصفحة، وأرسل طلبًا، وأطلق خطأً في وحدة التحكم. في ClickHouse Observability، اختر نطاقًا زمنيًا حديثًا وابحث في السجلات (Logs) أو التتبّعات (Traces) عن `my-frontend-app`. ثم افتح إعادة تشغيل الجلسة (Session replay) لفحص الجلسة المسجّلة.

إذا كانت البيانات مفقودة، فافحص وحدة التحكم في المتصفح وطلبات الشبكة الموجّهة إلى `/v1/traces` و`/v1/logs`. وتحقّق من نقطة النهاية، وترويسة التفويض، وإعدادات CORS، وسياسة أمان المحتوى (Content Security Policy). أما في عمليات النشر المُدارة ذاتيًا، فتأكّد من أن إصدار ClickStack لديك يدعم إعادة التشغيل والـ attribute القياسية `session.id` الخاصة بـ SDK؛ إذ إن استلام السجلات وحده لا يضمن ظهور الجلسات في UI.

## خيارات التهيئة {#initialization-options}

مرّر هذه الخيارات إلى `init`. استخدم `endpoint` لجامع بيانات مشترك، أو حدّد نقطتي النهاية الخاصتين بالإشارتين معاً عندما تكون لبيانات التتبّع والسجلات وجهات منفصلة.

| الخيار               | القيمة الافتراضية                                     | الغرض                                                                                                                                 |
| -------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`           | مطلوب ما لم تُحدَّد نقطتا النهاية الخاصتان بالإشارتين | عنوان URL أساسي لـ OTLP HTTP أو مسار وكيل من المصدر نفسه؛ ويُلحِق الـ SDK به مسارات الإشارات                                          |
| `tracesEndpoint`     | غير محدد                                              | عنوان URL الكامل لبيانات التتبّع، ويُستخدم كما هو بدلاً من عنوان URL المشتق من `endpoint`                                             |
| `logsEndpoint`       | غير محدد                                              | عنوان URL الكامل للسجلات وإعادة التشغيل، ويُستخدم كما هو بدلاً من عنوان URL المشتق من `endpoint`                                      |
| `serviceName`        | مطلوب                                                 | يعيّن `service.name` على جميع بيانات القياس عن بُعد                                                                                   |
| `apiKey`             | غير محدد                                              | قيمة ترويسة `authorization`؛ استخدم الصيغة الخاصة بوجهتك والمذكورة أعلاه                                                              |
| `traceOrigins`       | غير محدد                                              | مصادر الخلفية أو التعبيرات النمطية التي يُرسَل إليها سياق التتبّع                                                                     |
| `replay`             | `true`                                                | تسجيل إعادة تشغيل الجلسة؛ مع القيمة `false` تبقى بيانات القياس عن بُعد للمتصفح مُفعّلة لكن تُعطَّل إعادة التشغيل                      |
| `resourceAttributes` | غير محدد                                              | سمات موارد إضافية، تشمل إعادة التشغيل أيضاً؛ وتكون الأسبقية لـ `serviceName` و`serviceVersion` و`environment` على المفاتيح المطابقة   |
| `maskAllText`        | `true`                                                | إخفاء النصوص في إعادة التشغيل                                                                                                         |
| `maskAllInputs`      | `true`                                                | إخفاء قيم عناصر input وtextarea وselect                                                                                               |
| `console`            | `'error'`                                             | التقاط المستوى `'error'` أو `'warn'` أو `'info'` (بما في ذلك `console.log`) أو `'debug'` وما هو أشد منه خطورة؛ استخدم `false` للتعطيل |
| `serviceVersion`     | غير محدد                                              | تحديد إصدار تطبيقك                                                                                                                    |
| `environment`        | غير محدد                                              | يعيّن `deployment.environment.name`                                                                                                   |
| `sanitizeUrl`        | غير محدد                                              | إعادة كتابة عناوين URL المسجّلة، كإزالة معلمات الاستعلام مثلاً                                                                        |

للاطلاع على واجهة برمجة التطبيقات كاملةً، راجع [مرجع SDK للمتصفح](https://github.com/ClickHouse/clickstack-browser#quick-start).

## إعادة تشغيل الجلسة والخصوصية {#session-replay-and-privacy}

تكون إعادة تشغيل الجلسة مفعّلة افتراضيًا، كما يُخفى النص وقيم الإدخال افتراضيًا.

لا يُخفي إخفاء البيانات حالات مربعات الاختيار ولا حالات أزرار الاختيار، ولا السمات مثل عناوين URL للروابط والعناصر النائبة. استخدم الصنف `rr-block` لاستبعاد العناصر الحساسة. لا يشمل تنقيح عناوين URL العناوينَ الواردة داخل محتوى الصفحة المُعاد تشغيله، ولا تتبّعات مكدس الاستدعاءات، ولا رسائل وحدة التحكم. لا تلتقط من معلومات المستخدمين إلا ما تسمح به سياسة الخصوصية لديك.

لإيقاف إعادة التشغيل مؤقتًا مع مواصلة جمع بيانات القياس عن بُعد من المتصفح:

```javascript
import { pauseReplay } from '@clickhouse/clickstack-browser';

pauseReplay();
```

عندما تكون مستعدًا لاستئناف التسجيل:

```javascript
import { resumeReplay } from '@clickhouse/clickstack-browser';

resumeReplay();
```

## ربط تتبّعات الواجهة الأمامية بتتبعات الخدمات الخلفية {#trace-propagation}

لربط طلبات المتصفح بتتبعات الخدمات الخلفية، أضف `traceOrigins` إلى خيارات `init`، واستبدل القيمة الواردة في المثال بمصدر الواجهة الخلفية لديك:

```javascript
traceOrigins: ['https://api.example.com'],
```

تحمل الطلبات الموجّهة إلى المصدر (origin) الخاص بالصفحة نفسها وإلى الأنظمة الخلفية المطابقة الترويسات `traceparent` و`tracestate` و`baggage`. ويجب أن يكون النظام الخلفي لديك مزوّدًا بأدوات الرصد حتى يواصل هذا السياق.

يجب أن تسمح الأنظمة الخلفية ذات المصدر المختلف (cross-origin) بمرور هذه الترويسات عبر CORS. كما يجب أن يسمح جامع البيانات للقياس عن بُعد بمصدر الواجهة الأمامية. وإذا كان تطبيقك يستخدم سياسة أمان المحتوى (Content Security Policy)، فأضف نقطة نهاية جامع البيانات إلى القائمة المسموح بها في `connect-src`.

## تحديد هوية المستخدمين وتسجيل الأخطاء {#users-and-errors}

عند تسجيل الدخول، استخدم `setUser` لإلحاق معلومات المستخدم بمقاطع التتبع والسجلات اللاحقة:

```javascript
import { setUser } from '@clickhouse/clickstack-browser';

setUser({ id: 'user-123', email: 'user@example.com' });
```

عند تسجيل الخروج، امسح معلومات المستخدم وابدأ session جديدة:

```javascript
import { setUser, startNewSession } from '@clickhouse/clickstack-browser';

setUser(null);
startNewSession();
```

لإرفاق بيانات وصفية خاصة بالتطبيق بمقاطع التتبع والسجلات اللاحقة، استخدم `setAttributes`. يحلّ كل استدعاء محلّ المجموعة السابقة؛ ولمسحها، مرّر `null`:

```javascript
import { setAttributes } from '@clickhouse/clickstack-browser';

setAttributes({ 'app.team.name': 'checkout' });
```

تُلتقط الأخطاء غير المُلتقَطة وحالات الرفض غير المُعالَجة تلقائيًا. كما تُلتقط افتراضيًا الأخطاء التي تُبلِغ عنها حدود الأخطاء (error boundaries) في React عبر `console.error`. استخدم `recordException` للأخطاء المُلتقَطة التي لم تُسجَّل مسبقًا، إذ يؤدي تسجيل الخطأ نفسه عبرها وعبر السجلات معًا إلى إنشاء أحداث مكررة:

```javascript
import { recordException } from '@clickhouse/clickstack-browser';

try {
  await submitCheckout();
} catch (error) {
  recordException(error, { 'app.operation': 'checkout' });
  // Handle the error in your application.
}
```

استبدل `submitCheckout` بعملية التطبيق التي تريد مراقبتها.

## الترحيل من SDK للمتصفح من HyperDX {#migration}

لا تقتصر هذه الترقية على تغيير اسم الحزمة فحسب، إذ يحلّ `endpoint` محل `url`، و`serviceName` محل `service`، و`traceOrigins` محل `tracePropagationTargets`. كما أصبحت القيمة الافتراضية لإخفاء النصوص وحقول الإدخال `true`. استبدل `setGlobalAttributes` بـ `setUser` لتحديد هوية المستخدم، وبـ `setAttributes` للبيانات الوصفية للتطبيق. ولا تحتاج حدود الأخطاء (error boundaries) في React التي تُبلغ عن الأخطاء عبر `console.error` إلى أي خطاف إضافي؛ أما إذا لم يكن الخطأ مُسجَّلًا بالفعل، فاستخدم `recordException`.

راجع [دليل ترحيل SDK](https://github.com/ClickHouse/clickstack-browser/blob/main/docs/migration.md) للاطلاع على الخيارات المُزالة والتغييرات في السمات. وفي حال التثبيت عبر وسم script، أو إذا كان تطبيقك يهيّئ OpenTelemetry مسبقًا، فراجع [ملف README الخاص بـ SDK](https://github.com/ClickHouse/clickstack-browser#readme).

إذا تسبب SDK للمتصفح من ClickStack في مشكلة توافق في تطبيقك، فيمكنك استخدام [SDK للمتصفح القديم من HyperDX](https://github.com/hyperdxio/hyperdx-js/tree/main/packages/browser) ريثما تتحقق من المشكلة. استعد تهيئته واستدعاءات API الخاصة به بالاستعانة بدليل الترحيل المذكور أعلاه؛ فحزمتا SDK غير قابلتين للتبادل، ولا ينبغي تشغيلهما معًا.
