بالنسبة إلى دوال Node.js ذات معالجات الطلبات غير المتزامنة، استخدم ClickStack Node.js SDK. أما بيئات التشغيل الأخرى أو معالجات الطلبات المعتمدة على ردود النداء، فاستخدم طبقات OpenTelemetry Lambda الموضّحة أدناه.

## معالجات الطلبات في Node.js غير المتزامنة {#nodejs-async-handlers}

استخدم بيئة تشغيل Node.js في Lambda تستوفي الحد الأدنى الذي تتطلبه SDK، وهو الإصدار Node.js 22.15. ثبّت SDK وأدرِجها في حزمة النشر:

```shell
npm install @clickhouse/clickstack-node
```

اضبط متغيرات البيئة التالية في Lambda لتهيئة SDK قبل تحميل معالج الطلبات، ولتحديد اسم خدمتك:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

غلِّف معالج الطلبات الخاص بك غير المتزامن باستخدام `withFlush` لضمان تصدير بيانات القياس عن بُعد المخزَّنة مؤقتًا قبل انتهاء الاستدعاء:

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

اضبط معالج الطلبات للدالة على `index.handler`. إذا جمّعت الدالة في حزمة، فأبقِ الـ SDK والتبعيات المزوّدة بأدوات الرصد خارجيةً، وأدرجها في حزمة النشر. ولا تُمكّن كذلك طبقة Lambda الخاصة بـ auto-instrumentation في هذا الإعداد.

اضبط متغيرات الوجهة الواردة أدناه في تهيئة البيئة الخاصة بدالة Lambda. يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من دالتك. يُنهي الـ SDK عملية التفريغ قبل الموعد النهائي للاستدعاء، علمًا بأن معالجات الطلبات المعتمدة على رد النداء غير مدعومة في `withFlush`.

### تهيئة الوجهة {#configure-destination}

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="إصدار تجريبي" />

    افتح **إعدادات الفريق ← البيانات ← Managed Telemetry** في خدمتك، وانسخ **نقطة نهاية OTLP HTTP** و**مفتاح API**. استخدم نقطة نهاية HTTPS كاملةً بما فيها المنفذ:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات لديك ومفتاح الإدخال. وإذا لم يكن TLS مُهيَّأً في جامع البيانات، فاستخدم `http://` بدلًا من `https://`. لمعرفة كيفية إعداد جامع البيانات، راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    ```
  </Tab>
</Tabs>

## بيئات التشغيل ومعالجات الطلبات الأخرى {#other-runtimes-and-handlers}

اتبع [تعليمات auto-instrumentation الرسمية الخاصة بـ Lambda](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/) لاختيار الطبقات المناسبة لبيئة التشغيل والمعمارية ومنطقة AWS لديك، ثم هيّئ غلاف إضافة أدوات الرصد.

أضف [طبقة Lambda لمُجمِّع OpenTelemetry](https://opentelemetry.io/docs/platforms/faas/lambda-collector/) وهيّئها. أبقِ مُصدِّرات SDK في التطبيق موجّهةً إلى جامع البيانات المحلي، كما هو موضّح في المصدر الأصلي. ثم هيّئ الاتصال الصادر لجامع البيانات كما هو موضّح أدناه.

### تهيئة وجهة جامع البيانات في Lambda {#configure-lambda-collector-destination}

اضبط `CLICKHOUSE_OTLP_ENDPOINT` و`CLICKHOUSE_INGESTION_API_KEY` في متغيرات البيئة لدالة Lambda. ثم أضف المُصدِّر التالي إلى تهيئة جامع البيانات لديك.

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="إصدار تجريبي" />

    افتح **إعدادات الفريق → البيانات → Managed Telemetry** في خدمتك، وانسخ **نقطة نهاية OTLP HTTP** و**مفتاح API**. اضبط `CLICKHOUSE_OTLP_ENDPOINT` على نقطة نهاية HTTPS الكاملة بما فيها المنفذ، واضبط `CLICKHOUSE_INGESTION_API_KEY` على قيمة المفتاح.

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "Bearer ${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>

  <Tab title="مُدار ذاتيًا">
    اضبط `CLICKHOUSE_OTLP_ENDPOINT` على نقطة نهاية OTLP HTTP الخاصة بجامع البيانات لديك، واضبط `CLICKHOUSE_INGESTION_API_KEY` على مفتاح الإدخال الخاص به. يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من دالة Lambda. لإعداد جامع البيانات في الوجهة، راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry#self-managed).

    ```yaml
    exporters:
      otlphttp/clickhouse:
        endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
        headers:
          Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
    ```
  </Tab>
</Tabs>

أضف `otlphttp/clickhouse` إلى قائمة `exporters` في مسار تنفيذ الاستعلام لكل إشارة تريد إرسالها. على سبيل المثال، مع المستقبِل `otlp` من المصدر الأصلي:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

ادمج هذه الإعدادات في تهيئة جامع البيانات (جامع البيانات) لديك، مع الإبقاء على إعدادات المستقبِل والمعالج الموجودة فيها. ثم أدرج ملف التهيئة ضمن حزمة دالتك، واضبط `OPENTELEMETRY_COLLECTOR_CONFIG_URI` على مساره، مثل `/var/task/collector.yaml`، وفقًا لتعليمات إعداد جامع البيانات الواردة في المصدر الأصلي.

## التحقق من إدخال البيانات {#verify-ingestion}

انشر الدالة واستدعِها. في ClickHouse Observability، اختر نطاقًا زمنيًا حديثًا وابحث عن اسم الخدمة الخاص بدالتك ضمن Traces. وإذا كانت إضافة أدوات الرصد التي أجريتها تُصدر السجلات والمقاييس أيضًا، فتحقّق منها ضمن Logs وMetrics؛ إذ إن إضافة مسار تنفيذ الاستعلام لا تُفعّل جمعها تلقائيًا.

للاطلاع على تهيئة الطبقة واستكشاف الأخطاء وإصلاحها، راجع [وثائق OpenTelemetry Lambda](https://github.com/open-telemetry/opentelemetry-lambda).
