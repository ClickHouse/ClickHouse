استخدم حزمة ClickStack SDK للغة بايثون لإرسال السجلات وبيانات التتبّع إلى ClickHouse Observability. تُعدّ هذه الحزمة توزيعة من OpenTelemetry منشورة باسم `hyperdx-opentelemetry`، وتزوّد مكتبات بايثون وأطر عملها المدعومة تلقائيًا بأدوات جمع بيانات الرصد.

## تثبيت SDK {#install-the-sdk}

ثبّت [ClickStack بايثون SDK](https://github.com/hyperdxio/hyperdx-py) في بيئة بايثون الخاصة بتطبيقك:

```shell
pip install hyperdx-opentelemetry
opentelemetry-bootstrap -a install
```

يثبّت الأمر `bootstrap` إضافة أدوات الرصد الخاصة بالتبعيات المثبّتة في تطبيقك، لذا شغّله بعد تثبيت هذه التبعيات.

## تهيئة الوجهة {#configure-destination}

    افتح **إعدادات الفريق ← البيانات ← Managed Telemetry** في خدمتك، ثم انسخ **نقطة نهاية OTLP HTTP** و**مفتاح API**. استخدم نقطة نهاية HTTPS كاملةً، بما في ذلك المنفذ:

    export HYPERDX_API_KEY='Bearer YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-python-app'
    ```
  </Tab>

  <Tab title="مُدار ذاتيًا">
    استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات ومفتاح الإدخال. واستخدم `http://` بدلًا من `https://` إذا لم يكن TLS مُهيأً على جامع البيانات. لمعرفة كيفية إعداد جامع البيانات، راجع [استيعاب البيانات باستخدام OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry#sending-otel-data-self-configured).

    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
    export HYPERDX_API_KEY='YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-python-app'
    ```

## تشغيل التطبيق {#start-your-application}

شغّل تطبيقك مع تفعيل إضافة أدوات الرصد التلقائية:

```shell
export OTEL_LOG_LEVEL='warning'
export OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION='false'
opentelemetry-instrument python app.py
```

استبدل `app.py` بملف نقطة الدخول الخاص بتطبيقك.

يحدد `OTEL_LOG_LEVEL` مستوى التسجيل في حزمة SDK. اضبطه على `warning` لالتقاط رسالة الاختبار أدناه، أو على `info` لالتقاط سجلات التطبيقات الأقل خطورة. تستخدم حزمة SDK القيمة الافتراضية `ERROR` إذا لم تتم تهيئة أي مستوى.

تُثبّت حزمة ClickStack SDK مُصدِّرًا للسجلات مسبقًا. ويؤدي ضبط `OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION=false` إلى منع إضافة أدوات الرصد الخاصة بالتسجيل في OpenTelemetry من إضافة مُصدِّر آخر، ومن ثَمّ تجنُّب تكرار إدخالات السجل؛ مع استمرار حزمة SDK في تصدير السجلات.

## التحقق من إدخال البيانات {#verify-ingestion}

أرسل طلبات إلى تطبيقك، وأصدِر رسالة سجل من بايثون بمستوى `WARNING` أو أعلى. بعد ذلك، اختر في ClickHouse Observability نطاقًا زمنيًا حديثًا، وابحث في السجلات (Logs) أو التتبّعات (Traces) عن `my-python-app` (أو اسم الخدمة الذي هيّأته).

## الإعدادات الاختيارية {#optional-configuration}

لالتقاط ترويسات طلبات HTTP ومتونها، فعّل الالتقاط المتقدم لحركة الشبكة قبل تشغيل تطبيقك:

```shell
export HYPERDX_ENABLE_ADVANCED_NETWORK_CAPTURE=1
```

قد تحتوي ترويسات الطلبات ومتونها على بيانات حساسة، لذا لا تُمكِّن الالتقاط إلا للبيانات التي تنوي جمعها فعلًا.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

إذا لم تظهر السجلات، فتحقق من قيمة `OTEL_LOG_LEVEL` ومن مستويات مسجّل السجلات والمعالج في تطبيقك، واضبطها بحيث تلتقط رسائل بمستوى الخطورة الذي تتوقعه.

لاستكشاف أخطاء إضافة أدوات الرصد والمُصدِّر وإصلاحها، راجع [دليل استكشاف الأخطاء وإصلاحها في OpenTelemetry لبايثون](https://opentelemetry.io/docs/zero-code/python/troubleshooting/).
