اجمع السجلات المحلية ومقاييس النظام وأرسلها إلى **ClickHouse Observability** لعرضها مرئيًا وتحليلها.

يستخدم هذا المثال Docker على Linux أو Docker Desktop على macOS. قبل البدء، ثبّت Docker وشغّله، ثم أنشئ خدمة ClickHouse Observability باتباع [دليل البدء للإصدار المُدار بالكامل](/ar/clickstack/observability/getting-started) أو [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed).

## جمع البيانات المحلية {#collect-local-data}

اختر طريقة النشر أدناه لتهيئة جامع البيانات وتشغيله. وبعد الإعداد، تتبع كلتا طريقتي النشر خطوات الاستكشاف نفسها.

<Tabs>
  <Tab title="مُدار بالكامل">
    <BetaBadge label="إصدار تجريبي" />

    في خدمة ClickHouse Observability لديك، افتح **إعدادات الفريق ← البيانات** (Team Settings → Data)، ثم انسخ نقطة نهاية OTLP HTTP ومفتاح API.

    <Steps>
      <Step title="إنشاء تهيئة مخصصة لـ OpenTelemetry" id="create-otel-configuration">
        أنشئ ملفًا باسم `custom-local-config.yaml` يتضمن المحتوى التالي:

        ```yaml
        receivers:
          file_log:
            include:
              - /host/var/log/**/*.log
              - /host/var/log/syslog
              - /host/var/log/messages
            start_at: end
            resource:
              service.name: system-logs

          host_metrics:
            root_path: ${env:HOST_METRICS_ROOT_PATH}
            collection_interval: 30s
            scrapers:
              cpu:
                metrics:
                  system.cpu.utilization:
                    enabled: true
              memory:
                metrics:
                  system.memory.utilization:
                    enabled: true
              filesystem:
              paging:
              disk:
              load:
              network:

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          resource:
            attributes:
              - key: host.name
                value: ${env:HOST_NAME}
                action: upsert
          batch:
            timeout: 5s
            send_batch_size: 1024

        exporters:
          otlp_http:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: "Bearer ${env:OTEL_EXPORTER_OTLP_API_KEY}"

        service:
          pipelines:
            logs:
              receivers: [file_log]
              processors: [memory_limiter, resource, batch]
              exporters: [otlp_http]
            metrics:
              receivers: [host_metrics]
              processors: [memory_limiter, resource, batch]
              exporters: [otlp_http]
        ```

        يتابع المستقبِل `file_log` ملفات السجل المحلية، بينما يجمع المستقبِل `host_metrics` مقاييس النظام. ويُرسل كلا مساري معالجة البيانات البيانات إلى نقطة نهاية بيانات القياس عن بُعد المُدارة الخاصة بك عبر HTTPS.

        <Info>
          يقرأ هذا المثال إدخالات السجل الجديدة فقط (`start_at: end`)، ولا يحلّل الطوابع الزمنية الواردة في متن السجل. إذا كنت بحاجة إلى الحفاظ على وقت الحدث الأصلي، فأضف محللًا نحويًا للطابع الزمني إلى مستقبِل الملفات. ولاستيعاب العناصر الموجودة مسبقًا في الملفات المكتشفة حديثًا أيضًا، استخدم `start_at: beginning`.
        </Info>

        لمزيد من التفاصيل حول بنية تهيئة OpenTelemetry (OTel)، نوصي بالاطلاع على [الدليل الرسمي](https://opentelemetry.io/docs/collector/configuration/).
      </Step>

      <Step title="شغّل مُجمِّع OpenTelemetry" id="start-the-otel-collector">
        اضبط نقطة النهاية ومفتاح API اللذين نسختهما من **إعدادات الفريق ← البيانات**:

        ```shell
        export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
        printf "API key: "
        read -r -s OTEL_EXPORTER_OTLP_API_KEY
        printf "\n"
        export OTEL_EXPORTER_OTLP_API_KEY
        ```

        نقطة النهاية هي عنوان URL الأساسي لبروتوكول OTLP عبر HTTP، دون `/v1/logs` أو `/v1/metrics`، إذ يُلحق جامع البيانات المسار المناسب تلقائيًا.

        <Tabs>
          <Tab title="Linux">
            اربط filesystem المضيف للقراءة فقط حتى يتمكن جامع البيانات من قراءة مقاييس المضيف وملفات السجل:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e OTEL_EXPORTER_OTLP_ENDPOINT \
              -e OTEL_EXPORTER_OTLP_API_KEY \
              -e HOST_NAME="$(hostname)" \
              -e HOST_METRICS_ROOT_PATH=/hostfs \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/config.yaml:ro" \
              -v /:/hostfs:ro \
              -v /var/log:/host/var/log:ro \
              otel/opentelemetry-collector-contrib:0.161.0
            ```
          </Tab>

          <Tab title="macOS (Docker Desktop)">
            اربط دليل السجلات في macOS للقراءة فقط. تصف المقاييس الجهازَ الافتراضي الذي يعمل بنظام Linux ضمن Docker Desktop، ولذلك تستخدم وسم مضيف مطابقًا له:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e OTEL_EXPORTER_OTLP_ENDPOINT \
              -e OTEL_EXPORTER_OTLP_API_KEY \
              -e HOST_NAME="$(hostname)-docker-desktop" \
              -e HOST_METRICS_ROOT_PATH=/ \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/config.yaml:ro" \
              -v /private/var/log:/host/var/log:ro \
              otel/opentelemetry-collector-contrib:0.161.0
            ```

            يجب أن يمتلك Docker Desktop صلاحية مشاركة `/private/var/log`.
          </Tab>
        </Tabs>

        تحقّق من أن جامع البيانات يعمل دون أخطاء في التهيئة أو التصدير:

        ```shell
        docker logs local-otel-collector
        ```

        تُجمع المقاييس كل 30 ثانية، وتظهر السجلات عند إضافة إدخالات جديدة إلى ملف مطابق. أبقِ جامع البيانات قيد التشغيل أثناء استكشاف البيانات في الخطوات التالية.
      </Step>
    </Steps>
  </Tab>

  <Tab title="مُدار ذاتيًا" id="self-managed">
    استخدم بيانات اعتماد الاتصال الخاصة بخدمة ClickHouse Cloud لديك، كما هو موضح في [دليل البدء للإصدار المُدار ذاتيًا](/ar/clickstack/self-configured/getting-started/managed#next-steps).

    <Steps>
      <Step title="إنشاء تهيئة مخصصة لـ OpenTelemetry" id="create-otel-configuration-self-configured">
        أنشئ ملف `custom-local-config.yaml` بالمحتوى التالي:

        ```yaml
        receivers:
          file_log:
            include:
              - /host/var/log/**/*.log        # Linux logs from host
              - /host/var/log/syslog
              - /host/var/log/messages
            start_at: beginning
            resource:
              service.name: "system-logs"

          host_metrics:
            root_path: ${env:HOST_METRICS_ROOT_PATH}
            collection_interval: 1s
            scrapers:
              cpu:
                metrics:
                  system.cpu.time:
                    enabled: true
                  system.cpu.utilization:
                    enabled: true
              memory:
                metrics:
                  system.memory.usage:
                    enabled: true
                  system.memory.utilization:
                    enabled: true
              filesystem:
                metrics:
                  system.filesystem.usage:
                    enabled: true
                  system.filesystem.utilization:
                    enabled: true
              paging:
                metrics:
                  system.paging.usage:
                    enabled: true
                  system.paging.utilization:
                    enabled: true
                  system.paging.faults:
                    enabled: true
              disk:
              load:
              network:
              processes:

        service:
          pipelines:
            logs/local:
              receivers: [file_log]
              processors:
                - memory_limiter
                - batch
              exporters:
                - clickhouse
            metrics/hostmetrics:
              receivers: [host_metrics]
              processors:
                - memory_limiter
                - batch
              exporters:
                - clickhouse
        ```

        تجمع هذه التهيئة سجلات النظام والمقاييس من أنظمة macOS وLinux، وترسل النتائج إلى خدمتك. وتُوسّع هذه التهيئة مُجمِّع ClickStack بإضافة مستقبِلات ومسارات معالجة بيانات جديدة، إذ تُشير إلى المُصدِّر `clickhouse` والمعالجات (`memory_limiter` و`batch`) الموجودة مسبقًا والمُهيَّأة في مُجمِّع ClickStack الأساسي.

        <Info>
          **الطوابع الزمنية عند الإدخال**

          تعدّل هذه التهيئة الطوابع الزمنية أثناء استيعاب البيانات، فتُسنِد قيمة وقت محدَّثة إلى كل حدث. ويُفضَّل أن تُجري [معالجة مسبقة للطوابع الزمنية أو تحليلها](/ar/clickstack/self-configured/ingesting-data/collector#processing-filtering-transforming-enriching-self-configured) في ملفات السجل باستخدام معالجات OTel أو المشغّلات، لضمان الاحتفاظ بوقت الحدث الدقيق.

          في هذا الإعداد التوضيحي، إذا كان المستقبِل أو معالج الملفات مُهيَّأً للبدء من بداية الملف، فستُسنَد إلى جميع إدخالات السجل الموجودة الطابع الزمني المعدَّل نفسه، أي وقت المعالجة بدلًا من وقت الحدث الأصلي. أما الأحداث الجديدة التي تُضاف إلى الملف فستحصل على طوابع زمنية تقارب وقت توليدها الفعلي.

          لتجنّب ذلك، يمكنك ضبط موضع البدء على `end` في تهيئة المستقبِل، مما يضمن استيعاب الإدخالات الجديدة فقط ومنحها طوابع زمنية قريبة من وقت وصولها الفعلي.
        </Info>

        لمزيد من التفاصيل حول بنية تهيئة OpenTelemetry ‏(OTel)، نوصي بالاطلاع على [الدليل الرسمي](https://opentelemetry.io/docs/collector/configuration/).
      </Step>

      <Step title="شغِّل مُجمِّع OpenTelemetry" id="start-the-otel-collector-self-configured">
        شغّل جامع بيانات مستقلًا باستخدام القيم التي صدّرتها لـ `CLICKHOUSE_ENDPOINT` و`CLICKHOUSE_USER` و`CLICKHOUSE_PASSWORD`:

        <Tabs>
          <Tab title="Linux">
            اربط filesystem المضيف للقراءة فقط حتى يتمكن جامع البيانات من قراءة مقاييس المضيف وملفات السجل:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e CUSTOM_OTELCOL_CONFIG_FILE=/etc/otelcol-contrib/custom.config.yaml \
              -e CLICKHOUSE_ENDPOINT \
              -e CLICKHOUSE_USER \
              -e CLICKHOUSE_PASSWORD \
              -e HOST_METRICS_ROOT_PATH=/hostfs \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/custom.config.yaml:ro" \
              -v /:/hostfs:ro \
              -v /var/log:/host/var/log:ro \
              clickhouse/clickstack-otel-collector:latest
            ```
          </Tab>

          <Tab title="macOS (Docker Desktop)">
            اربط دليل السجلات في macOS للقراءة فقط. لاحظ أن المقاييس تخص الجهاز الافتراضي الذي يعمل بنظام Linux ضمن Docker Desktop، وليس مضيف macOS نفسه:

            ```shell
            docker run -d --name local-otel-collector \
              --user 0:0 \
              -e CUSTOM_OTELCOL_CONFIG_FILE=/etc/otelcol-contrib/custom.config.yaml \
              -e CLICKHOUSE_ENDPOINT \
              -e CLICKHOUSE_USER \
              -e CLICKHOUSE_PASSWORD \
              -e HOST_METRICS_ROOT_PATH=/ \
              -v "$(pwd)/custom-local-config.yaml:/etc/otelcol-contrib/custom.config.yaml:ro" \
              -v /private/var/log:/host/var/log:ro \
              clickhouse/clickstack-otel-collector:latest
            ```

            يجب أن يمتلك Docker Desktop صلاحية مشاركة `/private/var/log`.
          </Tab>
        </Tabs>

        تحقّق من أن جامع البيانات يبدأ العمل دون أخطاء في التهيئة أو التصدير:

        ```shell
        docker logs local-otel-collector
        ```

        سيبدأ جامع البيانات فورًا بجمع سجلات النظام ومقاييسه المحلية.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## استكشاف بياناتك {#explore-your-data}

أبقِ جامع البيانات قيد التشغيل أثناء استكشاف البيانات. تعرض لقطات الشاشة واجهتَي البحث ومستكشف المخططات نفسيهما المستخدمتين في كلا نمطَي النشر.

<Steps>
  <Step title="استكشاف سجلات النظام" id="explore-system-logs">
    في وحدة تحكم ClickHouse Cloud، اختر خدمتك وافتح ClickHouse Observability.

    افتح [بحث](/ar/clickstack/observability/features/search) واختر المصدر **السجلات**. اختر نطاقًا زمنيًا يشمل الفترة التي كان فيها جامع البيانات قيد التشغيل، ثم صفِّ الحقل **ServiceName** على القيمة `system-logs`.

    وسِّع أحد الأحداث لفحص سماته. تعرض لقطة الشاشة بيانات توضيحية، وستختلف رسائل السجل وسمات المضيف لديك عنها.

    <div className="ch-image-lg">
      <Frame>
        ![عينة سجل محلي في ClickHouse Observability، تعرض اسم ملف السجل وسمات المضيف](/images/clickstack/observability-local-logs.png)
      </Frame>
    </div>
  </Step>

  <Step title="استكشاف مقاييس النظام" id="explore-system-metrics">
    افتح **مستكشف المخططات** واختر **Time Series** والمصدر **المقاييس**. اختر **Maximum** دالةً للتجميع، ثم اختر `system.memory.utilization`. اترك **Delta** دون تحديد.

    في الحقل **Where**، استخدم `Attributes.state:"used"` لعرض الذاكرة المستخدمة. وإذا كنت تجمع المقاييس من عدة مضيفين، فصفِّ النتائج أيضًا حسب سمة المضيف الموجودة في بياناتك.

    اختر نطاقًا زمنيًا يشمل الفترة التي كان فيها جامع البيانات قيد التشغيل، ثم اختر **Run**. تعرض لقطة الشاشة بيانات توضيحية مصفّاة لمضيف واحد. هذا المقياس نسبة تتراوح بين 0 و1، فالقيمة `0.62` مثلًا تمثل استخدامًا بنسبة 62%.

    <div className="ch-image-lg">
      <Frame>
        ![استخدام الذاكرة مصفّى على الذاكرة المستخدمة لمضيف توضيحي في ClickHouse Observability](/images/clickstack/observability-local-memory-utilization.png)
      </Frame>
    </div>

    لعرض الاستخدام نسبةً مئوية، افتح **إعدادات العرض** واختر **Percentage** من **تنسيق الإخراج**.

    <div className="ch-image-lg">
      <Frame>
        ![إعدادات العرض في مستكشف المخططات مع اختيار Percentage تنسيقًا للإخراج](/images/clickstack/observability-local-memory-display-settings.png)
      </Frame>
    </div>

    اختر **Apply** لتحديث المخطط.

    <div className="ch-image-lg">
      <Frame>
        ![استخدام الذاكرة معروضًا نسبةً مئوية لمضيف توضيحي](/images/clickstack/observability-local-memory-percentage.png)
      </Frame>
    </div>
  </Step>
</Steps>

## إيقاف جمع البيانات {#stop-collection}

عند الانتهاء، أوقف جمع البيانات واحذف الحاوية:

```shell
docker stop local-otel-collector
docker rm local-otel-collector
```
