  **الخلاصة**

  يشرح هذا الدليل كيفية تزويد تطبيق ويب بأدوات جمع بيانات الرصد لإعادة تشغيل الجلسة، وذلك باستخدام SDK للمتصفح مع ClickHouse Observability، سواء أكانت مُدارة بالكامل أم مُدارة ذاتيًا. وبخلاف مجموعات البيانات النموذجية الأخرى التي تحمّل بيانات مُولَّدة مسبقًا، يوفّر هذا العرض التوضيحي تطبيقًا تفاعليًا تُنشئ فيه بيانات الجلسات بنفسك من خلال تفاعلاتك معه.

  الوقت المطلوب: 10-15 دقيقة
</Info>

## نظرة عامة {#overview}

يُعدّ [التطبيق التوضيحي لإعادة تشغيل الجلسة](https://github.com/ClickHouse/clickstack-session-replay-demo) مستكشفًا للوثائق مبنيًا باستخدام JavaScript الخالصة (vanilla JavaScript). ويُبيّن مدى بساطة إضافة أدوات الرصد لإعادة تشغيل الجلسة، إذ يكفي وسم script واحد واستدعاء تهيئة واحد لالتقاط تفاعلات المستخدم تلقائيًا.

يتضمن المستودع فرعين:

* **`main`**: مزوّد بأدوات الرصد بالكامل وجاهز للاستخدام فورًا
* **`pre-instrumented`**: نسخة نظيفة خالية من أدوات الرصد، مع تعليقات في الشيفرة تشير إلى مواضع إضافتها

يبدأ هذا الدليل باستخدام الفرع `main` لمشاهدة إعادة تشغيل الجلسة عمليًا، ثم يشرح شيفرة أدوات الرصد خطوة بخطوة لتتمكن من تطبيق النمط نفسه على تطبيقك.

لمعرفة المزيد عن ماهية إعادة تشغيل الجلسة وموقعها ضمن ClickStack، راجع صفحة ميزة [إعادة تشغيل الجلسة](/ar/clickstack/observability/features/session-replay).

## المتطلبات المسبقة {#prerequisites}

* تثبيت Docker وتشغيله، مع توفر Docker Compose
* أن يكون المنفذ 3000 متاحًا لتطبيق العرض التوضيحي
* خدمة ClickHouse Observability قائمة، سواء أكانت مُدارة بالكامل أم مُدارة ذاتيًا
* الوصول إلى الشبكة من متصفحك إلى نقطة نهاية بيانات القياس عن بُعد التي ستتم تهيئتها أدناه

## تشغيل العرض التوضيحي {#running-the-demo}

<Steps>
  <Step title="استنسخ المستودع" id="clone-repository">
    ```shell
    git clone https://github.com/ClickHouse/clickstack-session-replay-demo
    cd clickstack-session-replay-demo
    ```
  </Step>

  <Step title="تهيئة الاتصال" id="configure-connection">
    اختر نمط النشر:

    <Tabs>
      <Tab title="مُدار بالكامل">
        <BetaBadge label="إصدار تجريبي" />

        تحتاج إلى [خدمة مُدارة بالكامل](/ar/clickstack/observability/getting-started) قائمة. توفّر ClickHouse جامع البيانات المخصّص للإدخال.

        في خدمة ClickHouse Observability لديك، افتح **Team Settings → Data → Managed Telemetry** وانسخ **OTLP HTTP endpoint** و**API key**.

        <div className="ch-image-lg">
          <Frame>
            ![صفحة Managed Telemetry تعرض نقطة نهاية OTLP HTTP ومفتاح API بشكل مُقنَّع](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        اضبط `CLICKSTACK_UI_URL` على عنوان URL لواجهة UI الخاصة بخدمتك المُدارة. لفتح تسجيلات إعادة التشغيل مباشرةً، انسخ عنوان URL من شريط المتصفح في صفحة **Client Sessions**. استبدل العناصر النائبة أدناه ببيانات الاتصال الخاصة بك، ثم شغّل هذه الأوامر في الطرفية:

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
        export CLICKSTACK_API_KEY='Bearer YOUR_API_KEY'
        export CLICKSTACK_UI_URL='YOUR_OBSERVABILITY_UI_URL'
        ```

        أبقِ على البادئة `https://` ولا تُضِف مسارات الإشارات مثل `/v1/traces`. أضف البادئة `Bearer ` عند الإدخال المُدار بالكامل، كما هو موضح أعلاه.

        يتحكم `CLICKSTACK_UI_URL` في روابط **Open Observability** ضمن العرض التوضيحي، وهو مستقل عن نقطة نهاية إدخال بيانات القياس عن بُعد.

        يمرّر الخادم نقطة نهاية بيانات القياس عن بُعد ومفتاح API إلى SDK للمتصفح. ولأن مفتاح الإدخال يظهر في المتصفح، استخدم خدمة اختبارية لهذا العرض التوضيحي.
      </Tab>

      <Tab title="مُدار ذاتيًا">
        تحتاج إلى [خدمة مُدارة ذاتيًا](/ar/clickstack/self-configured/getting-started/managed) قائمة، ومُجمِّع OpenTelemetry الخاص بـ ClickStack يعمل ومتصل بها. راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured) للاطلاع على تعليمات الاتصال، أو [دليل النشر](/ar/clickstack/self-configured/deployment/managed#start-a-collector-existing) لتشغيل جامع البيانات.

        يجب أن يكون الوصول إلى نقطة نهاية OTLP HTTP الخاصة بجامع البيانات ممكنًا من متصفحك، مع إعداد CORS للسماح بـ `http://localhost:3000`. ويجب أن تدعم واجهة UI السمة `session.id` الخاصة بـ SDK الجديد في Client Sessions؛ راجع [متطلبات توافق SDK](https://github.com/ClickHouse/clickstack-browser#clickstack-versions).

        اضبط `CLICKSTACK_OTEL_ENDPOINT` على نقطة نهاية OTLP HTTP الخاصة بجامع البيانات، دون مسار إشارة مثل `/v1/traces`. واضبط `CLICKSTACK_UI_URL` على عنوان URL لصفحة **Client Sessions** المنسوخ من واجهة UI لخدمتك المُدارة ذاتيًا.

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
        export CLICKSTACK_API_KEY='YOUR_COLLECTOR_TOKEN'
        export CLICKSTACK_UI_URL='YOUR_CLIENT_SESSIONS_URL'
        ```

        استخدم رمز المصادقة المُهيّأ على المستقبِل الخاص بجامع البيانات. إذا كان مُجمِّع ClickStack مؤمَّنًا باستخدام `OTLP_AUTH_TOKEN`، فاستخدم تلك القيمة دون البادئة `Bearer`. وإذا كان المستقبِل لا يتطلب المصادقة، فاضبط `CLICKSTACK_API_KEY` على سلسلة فارغة. لا تستخدم كلمة مرور قاعدة بيانات ClickHouse هنا.

        يُمرَّر رمز الإدخال إلى SDK للمتصفح ويظهر في المتصفح، أما بيانات اعتماد قاعدة بيانات ClickHouse الخاصة بجامع البيانات فتبقى على جامع البيانات.
      </Tab>
    </Tabs>
  </Step>

  <Step title="شغّل التطبيق التوضيحي" id="start-demo-app">
    من داخل دليل المستودع، شغّل هذا الأمر في الطرفية نفسها التي صدّرت فيها متغيرات الاتصال:

    ```shell
    docker compose --profile demo up --build --no-deps demo-app
    ```

    يُشغِّل الخيار `--no-deps` التطبيق التوضيحي وحده، مستخدمًا نقطة نهاية بيانات القياس عن بُعد التي هيّأتها. ولا يُشغِّل خدمة ClickStack المحلية المضمّنة في المستودع.

    افتح [http://localhost:3000](http://localhost:3000) في متصفحك وجرّب التطبيق: ابحث عن الموضوعات، وصفِّ النتائج حسب الفئة، واستعرض أمثلة الشيفرة، وأضف العناصر إلى الإشارات المرجعية.

    يلتقط SDK للمتصفح الجلسة ويرسلها إلى نقطة نهاية بيانات القياس عن بُعد التي هيّأتها.
  </Step>

  <Step title="شاهد إعادة تشغيل جلستك" id="view-session-replay">

## إضافة أدوات الرصد {#instrumentation}

يوضّح التطبيق التوضيحي أن تمكين إعادة تشغيل الجلسة لا يتطلب سوى القليل من الشيفرة، إذ تكفي إضافتان فقط إلى التطبيق. تستخدم الأمثلة أدناه SDK للمتصفح الجديدة من ClickStack:

**1. تضمين SDK (`app/public/index.html`):**

```html
<script src="https://cdn.jsdelivr.net/npm/@clickhouse/clickstack-browser@1.0.0/dist/clickstack.iife.js" integrity="sha384-NW4JhbuY4Thx4fMuqFwKvifcPn7ad9dJ7DU/MTxhkoHeadG27i4F38Yo1Gz6y0WA" crossorigin="anonymous"></script>
```

**2. تهيئة SDK للمتصفح (`app/public/js/app.js`):**

```javascript
window.ClickStack.init({
  endpoint: window.CLICKSTACK_CONFIG.endpoint,
  apiKey: window.CLICKSTACK_CONFIG.apiKey,
  serviceName: 'clickhouse-session-replay-demo',
  console: 'debug',
});
```

يوفّر الملف `app/server.js` قيمة `window.CLICKSTACK_CONFIG` من متغيرات البيئة `CLICKSTACK_OTEL_ENDPOINT` و`CLICKSTACK_API_KEY` و`CLICKSTACK_UI_URL`. يستخدم الـ SDK نقطة النهاية ومفتاح API، بينما تستخدم روابط العرض التوضيحي عنوان URL الخاص بالـ UI. ويلتقط الـ SDK إعادة تشغيل الجلسة وسجلات وحدة التحكم وطلبات الشبكة والأخطاء دون أي تعديل على منطق الأعمال في التطبيق.

تُخفى النصوص وقيم الإدخال افتراضيًا. راجع [عناصر التحكم في الخصوصية في SDK للمتصفح](/ar/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy) قبل تغيير إعدادات إخفاء البيانات.

### جرّبه بنفسك {#try-it-yourself}

لتزويد التطبيق بأدوات جمع بيانات الرصد من الصفر، أوقف العرض التوضيحي قيد التشغيل بالضغط على `Ctrl+C`، ثم انتقل إلى الفرع `pre-instrumented`:

```shell
git checkout pre-instrumented
```

يحتوي هذا الفرع على التطبيق نفسه ولكن دون تفعيل SDK للمتصفح. وتوضّح التعليقات في الشيفرة ضمن `app/public/index.html` و`app/public/js/app.js` المواضع التي يجب أن تُضاف فيها الشيفرتان المذكورتان أعلاه. أبقِ على متغيرات الاتصال التي هيّأتها سابقًا، ثم أعد بناء التطبيق وشغّله:

```shell
docker compose --profile demo up --build --no-deps demo-app
```

أعد تحميل العرض التوضيحي في متصفحك وتفاعل معه لإنشاء جلسة جديدة.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

### عدم ظهور الجلسات {#sessions-not-appearing}

1. تحقّق من وجود أخطاء في وحدة التحكم بالمتصفح
2. تأكّد من أن تطبيق العرض التوضيحي قيد التشغيل: `docker compose ps demo-app`
3. تأكّد من تعيين `CLICKSTACK_OTEL_ENDPOINT` و`CLICKSTACK_API_KEY` في الطرفية التي تستخدمها لتشغيل التطبيق. وإذا غيّرت قيمتيهما، فأعد تنفيذ أمر بدء التشغيل ثم أعد تحميل علامة تبويب المتصفح.
4. في البيئات المُدارة ذاتيًا، تحقّق من أخطاء التصدير في جامع البيانات، وتهيئة CORS، ومتطلبات توافق SDK المذكورة أعلاه
5. عدّل النطاق الزمني في عرض جلسات العميل (جرّب **Last 15 minutes**)
6. أجرِ تحديثًا كاملًا للمتصفح: `Cmd+Shift+R` (Mac) أو `Ctrl+Shift+R` (Windows/Linux)

### أخطاء 401 Unauthorized {#401-errors}

لم يُضبط مفتاح API بشكل صحيح. تأكد مما يلي:

1. أنك صدّرت `CLICKSTACK_API_KEY` في الطرفية باستخدام القيمة المناسبة لنمط النشر لديك
2. أنك شغّلت التطبيق التوضيحي في **الطرفية نفسها** التي صدّرته فيها
3. في الخيار المُدار بالكامل، أنك استخدمت API key لاستيعاب البيانات من **إعدادات الفريق ← البيانات ← Managed Telemetry** مع البادئة `Bearer `. أما في الخيار المُدار ذاتيًا، فأنك استخدمت رمز المستقبِل الخاص بجامع البيانات لديك من دون تلك البادئة.

## التنظيف {#cleanup}

أغلق علامات تبويب المتصفح الخاصة بالعرض التوضيحي لإيقاف إرسال بيانات القياس عن بُعد من المتصفح، ثم اضغط `Ctrl+C` في الطرفية التي يعمل فيها التطبيق. ولإيقافه من طرفية أخرى، شغّل الأمر التالي من دليل المستودع:

```bash
docker compose stop demo-app
```

يؤدي هذا إلى إيقاف التطبيق المحلي، أما بيانات القياس عن بُعد التي تم استيعابها مسبقًا في خدمتك فتظل محفوظة فيها.
