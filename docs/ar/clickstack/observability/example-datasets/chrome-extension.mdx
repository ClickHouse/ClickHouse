## نظرة عامة {#overview}

    تحقن [إضافة HyperDX لمتصفح Chrome](https://github.com/kyreddie/hyperdx-chrome-extension) حزمة SDK ‏[@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) في الصفحات التي تزورها. وهي مفيدة عندما تريد تصحيح أخطاء إعادة تشغيل الجلسة أو RUM أو تمرير التتبّع على موقع ما دون تعديل قاعدة الشيفرة المصدرية الخاصة به، كأن يكون تطبيقًا تابعًا لجهة خارجية، أو إصدارًا في بيئة الإنتاج، أو خادم تطوير محليًا يطبّق سياسة أمان محتوى (CSP) صارمة.

    حزمة SDK مُضمَّنة داخل الإضافة (~480 KB)، لذا لا تحتاج الصفحات إلى تحميل نصوص برمجية من شبكة CDN أثناء التشغيل. تحاول الإضافة أولاً حقن البرنامج النصي خارجياً عبر `chrome-extension://`، وتلجأ إلى الحقن المضمّن كبديل عندما تحظر سياسة CSP النصوص البرمجية الصادرة من مصدر الإضافة.

    بخلاف [العرض التوضيحي لإعادة تشغيل الجلسة](/ar/clickstack/observability/example-datasets/session-replay)، الذي يزوّد تطبيقًا توضيحيًا تتحكم فيه بأدوات جمع بيانات الرصد، يزوّد هذا النهج الصفحات المدعومة التي تفتحها في Chrome بهذه الأدوات، علمًا بأن بعض الصفحات تقيّد حقن البرامج النصية. وتُنشئ بيانات الجلسة بالتفاعل مع الموقع كأي مستخدم عادي.

    لمزيد من المعلومات حول إعادة تشغيل الجلسة ودورها ضمن ClickHouse Observability، راجع صفحة ميزة [إعادة تشغيل الجلسة](/ar/clickstack/observability/features/session-replay).

## المتطلبات المسبقة {#prerequisites}

    * متصفح Google Chrome أو متصفح مبني على Chromium (مثل Edge وBrave وغيرهما)
    * خدمة ClickHouse Observability مُدارة بالكامل ومُنشأة مسبقًا. راجع [دليل البدء للإصدار المُدار بالكامل](/ar/clickstack/observability/getting-started).

## تشغيل العرض التوضيحي {#running-the-demo}

    <Steps>
      <Step title="استنساخ مستودع الإضافة" id="clone-extension">
        ```shell
        git clone https://github.com/kyreddie/hyperdx-chrome-extension
        cd hyperdx-chrome-extension
        ```
      </Step>

      <Step title="تثبيت الإضافة" id="install-extension">
        1. افتح Chrome وانتقل إلى `chrome://extensions`.
        2. فعّل **Developer mode** (أعلى اليمين).
        3. انقر على **Load unpacked**.
        4. حدّد المجلد `hyperdx-chrome-extension` الذي استنسخته.

        تظهر الإضافة في شريط الأدوات باسم **HyperDX Browser Extension**.
      </Step>

      <Step title="الحصول على بيانات الاتصال" id="get-connection-details">
        افتح خدمة ClickHouse Observability وانتقل إلى **إعدادات الفريق → Managed Telemetry**. انسخ **OTLP HTTP endpoint** و**مفتاح API** لاستخدامهما في تهيئة الإضافة.

        استخدم نقطة نهاية HTTPS كاملةً كما هي، بما في ذلك المنفذ، دون إضافة `/v1/logs` أو `/v1/traces` إليها.

        <div className="ch-image-lg">
          <Frame>
            ![صفحة Managed Telemetry في إعدادات الفريق تعرض OTLP HTTP endpoint ومفتاح API مُقنَّعَين](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>
      </Step>

      <Step title="تهيئة الإضافة" id="configure-extension">
        انقر على أيقونة **HyperDX Browser Extension** في شريط أدوات Chrome واملأ الإعدادات:

        | الحقل                                | الإعداد في الوضع المُدار بالكامل              | ملاحظات                                                                              |
        | ------------------------------------ | --------------------------------------------- | ------------------------------------------------------------------------------------ |
        | **تمكين مراقبة HyperDX**             | تشغيل                                         | مفتاح التبديل الرئيسي للحقن                                                          |
        | **اسم الخدمة**                       | `my-frontend-app`                             | مطلوب — يعرّف الخدمة في ClickHouse Observability                                     |
        | **مفتاح API**                        | مفتاح API الخاص بـ Managed Telemetry          | مطلوب؛ انسخه من **إعدادات الفريق → Managed Telemetry**                               |
        | **عنوان URL للمجمّع**                | OTLP HTTP endpoint الخاص بـ Managed Telemetry | استبدل عنوان URL الافتراضي في الإضافة بنقطة النهاية الواردة في **Managed Telemetry** |
        | **البيئة**                           | `development`                                 | اختياري — يضبط سمة المورد `deployment.environment`                                   |
        | **أهداف تمرير التتبّع**              | `/api\.myapp\.domain/i, /localhost/i`         | اختياري — تعابير نمطية بلغة JavaScript مفصولة بفواصل لتمرير ترويسات التتبّع          |
        | **الحقن فقط في عناوين URL المطابقة** | إيقاف                                         | فعّله لتحديد المواقع المزوّدة بأدوات الرصد                                           |
        | **التقاط سجلات وحدة التحكم**         | إيقاف                                         | فعّله لإرسال مخرجات وحدة تحكم المتصفح                                                |
        | **الالتقاط المتقدم للشبكة**          | إيقاف                                         | فعّله لالتقاط طلبات الشبكة بالتفصيل                                                  |

        انقر على **Save Configuration**، ثم أعد تحميل علامات التبويب التي تريد تزويدها بأدوات جمع بيانات الرصد.
      </Step>

      <Step title="تصفّح موقع وإنشاء جلسة" id="browse-site">
        افتح أي موقع ويب أو تطبيق محلي في Chrome، مثل [http://localhost:3000](http://localhost:3000) لخادم تطوير الواجهة الأمامية.

        تفاعل مع الصفحة كالمعتاد: انقر على الروابط، وأرسل النماذج، وافتعل بعض الأخطاء، وتنقّل بين العروض. تحقن الإضافة Browser SDK تلقائيًا عند كل تحميل للصفحة متى كانت التهيئة صحيحة.
      </Step>

      <Step title="عرض إعادة تشغيل الجلسة" id="view-session-replay">
        في خدمة ClickHouse Observability، افتح **جلسات العميل** من الشريط الجانبي الأيسر، واختر نطاقًا زمنيًا يشمل فترة تصفّحك.

        ستظهر جلستك في القائمة مع مدتها وعدد أحداثها. انقر على الزر ▶️ لإعادة تشغيلها.

        بدّل بين وضعَي **Highlighted** و**All Events** للتحكم في مستوى التفاصيل المعروضة على المخطط الزمني.
      </Step>
    </Steps>

## تصفية عناوين URL {#url-filtering}

    تحقن الإضافة افتراضيًا حزمة SDK في كل صفحة تزورها طالما كانت المراقبة مفعّلة. ولقصر الحقن على مواقع محددة، فعّل خيار **الحقن فقط في عناوين URL المطابقة** وأضف نمطًا واحدًا في كل سطر (أو افصل بين الأنماط بفواصل):

    | النمط                      | يطابق                                    |
    | -------------------------- | ---------------------------------------- |
    | `http://homedepot.com/*`   | HTTP فقط على النطاق `homedepot.com`      |
    | `*://homedepot.com/*`      | HTTP وHTTPS على `homedepot.com`          |
    | `*://*.homedepot.com/*`    | النطاقات الفرعية مثل `www.homedepot.com` |
    | `https://localhost:3000/*` | خادم تطوير محلي على المنفذ 3000          |

    أعِد تحميل علامة التبويب بعد حفظ أنماط عناوين URL.

## التحقق من الحقن {#verify-injection}

    افتح DevTools في صفحة خاضعة للمراقبة (علامة التبويب **وحدة التحكم**)، ثم أعد تحميل الصفحة وابحث عن:

    ```text
    [HyperDX Extension] Configuration valid, injecting HyperDX
    [HyperDX Extension] Injected via extension scripts
    [HyperDX Extension] HyperDX initialized
    ```

    إذا حظرت سياسة CSP النصوص البرمجية الصادرة من مصدر الإضافة، تسجّل الإضافة رسالة تفيد باللجوء إلى الآلية الاحتياطية، ثم تعيد المحاولة باستخدام الحقن المضمّن.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

    <Accordion title="عدم ظهور الجلسات في ClickHouse Observability">
      1. تحقّق من وحدة التحكم في المتصفح بحثًا عن رسائل السجل أو الأخطاء المسبوقة بـ `[HyperDX Extension]`
      2. تأكّد من تشغيل خيار **تمكين مراقبة HyperDX** ومن تعيين **اسم الخدمة**
      3. تأكّد من أن **عنوان URL للمجمّع** و**مفتاح API** يطابقان القيم الظاهرة في **إعدادات الفريق → Managed Telemetry** في خدمتك
      4. عدّل النطاق الزمني في عرض جلسات العميل (جرّب **Last 15 minutes**)
      5. أجرِ تحديثًا كاملًا للمتصفح: `Cmd+Shift+R` (Mac) أو `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="أخطاء chrome-extension://invalid/">
      أعد تحميل الإضافة من `chrome://extensions`، ثم نفّذ تحديثًا كاملًا لعلامة التبويب. تحدث هذه المشكلة عند تحديث الإضافة أو إعادة تحميلها بينما لا تزال علامات التبويب مفتوحة.
    </Accordion>

    <Accordion title="لا يوجد حقن في الموقع">
      1. تحقّق من أن المراقبة مفعّلة ومن تهيئة اسم الخدمة
      2. إذا كان خيار **الحقن فقط في عناوين URL المطابقة** مفعّلًا، فتأكّد من أن عنوان URL للصفحة الحالية يطابق أحد الأنماط التي حددتها
      3. تحظر بعض المواقع عبر CSP حقن البرامج النصية الصادرة من الإضافة وحقن البرامج النصية المضمّنة على حدٍّ سواء، وقد يتعذّر الحقن في تلك الصفحات
    </Accordion>

    <Accordion title="HyperDX: ‏apiKey مفقود في وحدة التحكم">
      أدخل مفتاح API من **إعدادات الفريق → القياس عن بُعد المُدار**، واحفظ التهيئة، ثم أعد تحميل الصفحة الخاضعة للمراقبة. فهذا المفتاح مطلوب للإدخال المُدار بالكامل.
    </Accordion>

## الخصوصية {#privacy}

    تحقن الإضافة شيفرة إمكانية المراقبة في الصفحات التي تزورها، لذا لا تستخدمها إلا على المواقع المصرَّح لك بتصحيح أخطائها. لا تشارك مفاتيح API مع أحد، ولا تُثبّتها في نظام التحكم في الإصدارات.

## نظرة عامة {#overview-self-configured}

    تحقن [إضافة HyperDX لمتصفح Chrome](https://github.com/kyreddie/hyperdx-chrome-extension) حزمة SDK ‏[@hyperdx/browser](https://github.com/hyperdxio/hyperdx-js) في الصفحات التي تزورها. وهي مفيدة عندما تريد تصحيح أخطاء إعادة تشغيل الجلسة أو RUM أو تمرير التتبّع على موقع ما دون تعديل قاعدة الشيفرة المصدرية الخاصة به، كتطبيق تابع لجهة خارجية، أو إصدار مخصّص لبيئة الإنتاج، أو خادم تطوير محلي يطبّق سياسة أمان محتوى (CSP) صارمة.

    حزمة SDK مُضمَّنة داخل الإضافة (~480 KB)، لذا لا تحتاج الصفحات إلى تحميل نصوص برمجية من CDN أثناء التشغيل. تحاول الإضافة أولاً حقن البرنامج النصي خارجياً عبر `chrome-extension://`، وتلجأ إلى الحقن المضمّن بديلاً عندما تحظر سياسة CSP النصوص البرمجية الصادرة من مصدر الإضافة.

    بخلاف [العرض التوضيحي لإعادة تشغيل الجلسة](/ar/clickstack/observability/example-datasets/session-replay)، الذي يزوّد تطبيقًا توضيحيًا تتحكم فيه بأدوات جمع بيانات الرصد، يعتمد هذا النهج على تزويد الصفحات المدعومة التي تفتحها في Chrome بهذه الأدوات، علمًا بأن بعض الصفحات تقيّد حقن البرامج النصية. وتُنشئ بيانات الجلسة بالتفاعل مع الموقع كأي مستخدم عادي.

    للاطلاع على معلومات أساسية حول إعادة تشغيل الجلسة وآلية عملها، راجع صفحة ميزة [إعادة تشغيل الجلسة](/ar/clickstack/observability/features/session-replay).

## المتطلبات المسبقة {#prerequisites-self-configured}

    * Google Chrome أو متصفح مبني على Chromium (مثل Edge وBrave وغيرهما)
    * خدمة Self-managed ClickHouse Observability قائمة، وجامع بيانات للإدخال قيد التشغيل. إذا لزم الأمر، فاتبع أولًا [دليل إعداد جامع البيانات](/ar/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured).
    * نقطة نهاية OTLP HTTP الخاصة بجامع البيانات، بحيث يمكن الوصول إليها من متصفحك، إلى جانب رمز المصادقة الخاص به إن كانت قد تمت تهيئته.

## تشغيل العرض التوضيحي {#running-the-demo-self-configured}

    <Steps>
      <Step title="استنساخ مستودع الإضافة" id="clone-extension-self-configured">
        ```shell
        git clone https://github.com/kyreddie/hyperdx-chrome-extension
        cd hyperdx-chrome-extension
        ```
      </Step>

      <Step title="تثبيت الإضافة" id="install-extension-self-configured">
        1. افتح Chrome وانتقل إلى `chrome://extensions`.
        2. فعّل **Developer mode** (أعلى اليمين).
        3. انقر على **Load unpacked**.
        4. اختر الدليل `hyperdx-chrome-extension` الذي استنسخته.

        تظهر الإضافة في شريط الأدوات باسم **HyperDX Browser Extension**.
      </Step>

      <Step title="الحصول على تفاصيل الاتصال بجامع البيانات" id="get-api-key-self-configured">
        استخدم نقطة نهاية OTLP HTTP لجامع البيانات قيد التشغيل، مثل `http://localhost:4318` إذا كان جامع البيانات يعمل على الجهاز نفسه الذي يعمل عليه المتصفح. أما إذا كان جامع البيانات بعيدًا، فاستخدم عنوان URL بصيغة HTTPS يمكن الوصول إليه من المتصفح. لا تُضف `/v1/logs` أو `/v1/traces` إلى نهاية العنوان.

        إذا كان جامع البيانات يستخدم `OTLP_AUTH_TOKEN`، فاستخدم هذا الرمز المميز بوصفه **API Key** للإضافة، دون إضافة البادئة `Bearer`. هذه هي بيانات اعتماد استيعاب البيانات الخاصة بجامع البيانات، وليست اسم المستخدم وكلمة المرور لقاعدة بيانات ClickHouse. راجع [تأمين جامع البيانات](/ar/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured).
      </Step>

      <Step title="تهيئة الإضافة" id="configure-extension-self-configured">
        انقر على أيقونة **HyperDX Browser Extension** في شريط أدوات Chrome واملأ الإعدادات التالية:

        | الحقل                            | القيمة في البيئة المُدارة ذاتيًا      | ملاحظات                                                                                                         |
        | -------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
        | **Enable HyperDX Monitoring**    | On                                    | مفتاح التبديل الرئيسي لعملية الحقن                                                                              |
        | **Service Name**                 | `my-frontend-app`                     | مطلوب — يُعرّف الخدمة في ClickHouse Observability                                                               |
        | **API Key**                      | رمز المصادقة الخاص بجامع البيانات     | استخدم قيمة `OTLP_AUTH_TOKEN` إذا كانت مُهيأة                                                                   |
        | **Collector URL**                | نقطة نهاية OTLP HTTP لجامع البيانات   | استبدل عنوان URL الافتراضي للإضافة؛ ولا تستخدم `http://localhost:4318` إلا إذا كان جامع البيانات يعمل على جهازك |
        | **Environment**                  | `development`                         | اختياري — يضبط سمة المورد `deployment.environment`                                                              |
        | **Trace Propagation Targets**    | `/api\.myapp\.domain/i, /localhost/i` | اختياري — تعبيرات نمطية بلغة JavaScript مفصولة بفواصل، تحدد الطلبات التي تُمرَّر إليها ترويسات التتبّع          |
        | **Only inject on matching URLs** | Off                                   | فعّله لتحديد المواقع التي تُزوَّد بأدوات جمع بيانات الرصد                                                       |
        | **Capture console logs**         | Off                                   | فعّله لإرسال مخرجات وحدة تحكم المتصفح                                                                           |
        | **Advanced network capture**     | Off                                   | فعّله لالتقاط تفاصيل طلبات الشبكة                                                                               |

        انقر على **Save Configuration**، ثم أعد تحميل علامات التبويب التي تريد تزويدها بأدوات جمع بيانات الرصد.

          </Frame>
        </div>

        تُظهر لقطة الشاشة أعلاه إعدادًا محليًا نموذجيًا: المراقبة مفعّلة، واسم الخدمة محدد، وجامع البيانات موجّه إلى `http://localhost:4318`، وتمرير التتبّع مقتصر على عناوين URL الخاصة بواجهة برمجة التطبيقات وlocalhost.
      </Step>

      <Step title="تصفّح موقع وإنشاء session" id="browse-site-self-configured">
        افتح أي موقع ويب أو تطبيق محلي في Chrome — مثل [http://localhost:3000](http://localhost:3000) لخادم تطوير الواجهة الأمامية.

        تفاعل مع الصفحة كالمعتاد: انقر على الروابط، وأرسل النماذج، وتسبّب في حدوث أخطاء، وتنقّل بين طرق العرض. تحقن الإضافة Browser SDK تلقائيًا عند كل تحميل للصفحة ما دامت التهيئة صالحة.
      </Step>

      <Step title="عرض إعادة تشغيل الجلسة" id="view-session-replay-self-configured">
        افتح خدمة ClickHouse Observability المُدارة ذاتيًا في ClickHouse Cloud واختر **Client Sessions** من الشريط الجانبي الأيسر. اختر نطاقًا زمنيًا يشمل نشاط التصفح الخاص بك.

        يُفترض أن تظهر جلستك في القائمة مع مدتها وعدد أحداثها. انقر على الزر ▶️ لإعادة تشغيلها.

        بدّل بين وضعي **Highlighted** و**All Events** لضبط مستوى التفاصيل المعروضة على المخطط الزمني.
      </Step>
    </Steps>

## تصفية عناوين URL {#url-filtering-self-configured}

    بشكل افتراضي، تحقن الإضافة حزمة SDK في كل صفحة تزورها ما دامت المراقبة مفعّلة. ولقصر الحقن على مواقع محددة، فعّل **الحقن فقط في عناوين URL المطابقة** وأضف نمطًا واحدًا في كل سطر (أو افصل الأنماط بفواصل):

    | النمط                      | يطابق                                    |
    | -------------------------- | ---------------------------------------- |
    | `http://homedepot.com/*`   | HTTP فقط على النطاق `homedepot.com`      |
    | `*://homedepot.com/*`      | HTTP وHTTPS على `homedepot.com`          |
    | `*://*.homedepot.com/*`    | النطاقات الفرعية مثل `www.homedepot.com` |
    | `https://localhost:3000/*` | خادم تطوير محلي على المنفذ 3000          |

    أعد تحميل علامة التبويب بعد حفظ أنماط عناوين URL.

## التحقق من الحقن {#verify-injection-self-configured}

    افتح أدوات المطوّرين (DevTools) في إحدى الصفحات الخاضعة للمراقبة (علامة التبويب **وحدة التحكم**)، ثم أعد تحميل الصفحة وابحث عن:

    ```text
    [HyperDX Extension] Configuration valid, injecting HyperDX
    [HyperDX Extension] Injected via extension scripts
    [HyperDX Extension] HyperDX initialized
    ```

    إذا حظرت سياسة CSP النصوص البرمجية الصادرة من الإضافة، تسجّل الإضافة رسالة تفيد باللجوء إلى الآلية الاحتياطية، ثم تعيد المحاولة باستخدام الحقن المضمّن.

## استكشاف الأخطاء وإصلاحها {#troubleshooting-self-configured}

    <Accordion title="عدم ظهور الجلسات في واجهة مستخدم ClickStack">
      1. افحص وحدة التحكم في المتصفح بحثًا عن رسائل السجل أو الأخطاء التي تبدأ بالبادئة `[HyperDX Extension]`
      2. تأكّد من تفعيل خيار **تمكين مراقبة HyperDX** ومن تعيين **اسم الخدمة**
      3. تحقّق من أن جامع البيانات قيد التشغيل، وأنه يمكن الوصول إلى نقطة نهاية OTLP HTTP الخاصة به من متصفحك، وأن مفتاح API يطابق رمز المصادقة الخاص به
      4. اضبط النطاق الزمني في عرض جلسات العميل (جرّب **Last 15 minutes**)
      5. أعِد تحميل الصفحة تحميلًا كاملًا في المتصفح: `Cmd+Shift+R` (Mac) أو `Ctrl+Shift+R` (Windows/Linux)
    </Accordion>

    <Accordion title="أخطاء chrome-extension://invalid/">
      أعِد تحميل الإضافة من صفحة `chrome://extensions`، ثم نفّذ تحديثًا كاملًا لعلامة التبويب. تحدث هذه المشكلة عند تحديث الإضافة أو إعادة تحميلها بينما لا تزال علامات التبويب مفتوحة.
    </Accordion>

    <Accordion title="لا يتم الحقن في الموقع">
      1. تحقّق من تفعيل المراقبة ومن تهيئة اسم الخدمة
      2. إذا كان خيار **الحقن فقط في عناوين URL المطابقة** مفعّلًا، فتأكّد من أن عنوان URL للصفحة الحالية يطابق أحد الأنماط التي حدّدتها
      3. تحظر بعض المواقع عبر سياسة أمان المحتوى (CSP) حقنَ البرامج النصية، سواء أكان مصدرها الإضافة أم كانت مضمّنة، لذا قد يتعذّر الحقن في تلك الصفحات
    </Accordion>

    <Accordion title="HyperDX: ‏apiKey مفقود في وحدة التحكم">
      إذا كان جامع البيانات لديك يتطلب المصادقة، فأدخل رمز المصادقة الخاص به في الحقل **API Key**، ثم احفظ التهيئة وأعد تحميل الصفحة الخاضعة للمراقبة. وللتحقق من وجود أخطاء في التصدير، راجع طلبات الشبكة في المتصفح وسجلات جامع البيانات، ولا تكتفِ برسالة الحقن وحدها.
    </Accordion>

## الخصوصية {#privacy-self-configured}

    تحقن الإضافة شيفرة خاصة بإمكانية المراقبة في الصفحات التي تزورها، لذا لا تستخدمها إلا على المواقع المصرّح لك بتصحيح أخطائها. ولا تشارك مفاتيح API مع أحد، ولا تُثبّتها في نظام التحكم في الإصدارات.
