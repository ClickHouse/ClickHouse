      استنسخ مستودع [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)، واملأ ملف `.env` بنقطة نهاية OTLP HTTP المُدارة ومفتاح API الخاص بك، ثم الصق موجّه الوكيل. لا تحتاج الواجهة الخلفية إلى أي عمليات استيراد لـ OpenTelemetry، إذ يتولى الوكيل ربط `@hyperdx/node-opentelemetry` عند بدء تشغيل العملية.

    HackerNews Analyzer هو تطبيق Node.js يستعلم عن مجموعة بيانات HackerNews المستضافة في العرض التوضيحي العام لـ ClickHouse. تُنشئ التفاعلات مع لوحة المعلومات طلبات إلى الخادم الخلفي. أما الطلبات التي لا تجد نتائجها في ذاكرة التخزين المؤقت للتطبيق، فتستعلم أيضًا من ClickHouse، مما يضيف span صادرًا عبر HTTPS إلى التتبّع.

    يجمع هذا العرض التوضيحي بين auto-instrumentation للواجهة الخلفية، ومقاطع التتبع الخاصة باستعلامات ClickHouse، وإعادة تشغيل الجلسة في المتصفح ضمن تطبيق واحد.

## المتطلبات المسبقة {#prerequisites}

    * إصدارات من Node.js وnpm متوافقة مع [HackerNews Analyzer وتبعياته](https://github.com/ClickHouse/hn-news-analyzer#readme).
    * خدمة ClickHouse Observability مُدارة بالكامل قائمة بالفعل. راجع [دليل بدء الاستخدام للإصدار المُدار بالكامل](/ar/clickstack/observability/getting-started).
    * إمكانية الوصول عبر الشبكة إلى نقطة نهاية بيانات القياس عن بُعد المُدارة من خادم التطبيق ومن متصفحك على حدٍّ سواء.

## استنساخ المستودع {#clone-the-repository}

    انسخ مستودع [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)، وثبّت التبعيات، ثم انسخ قالب ملف env:

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    ستملأ الملف `.env` في الخطوات التالية، ثم تُزوّد التطبيق بأدوات جمع بيانات الرصد انطلاقًا من هذا الدليل.

## تزويد التطبيق بأدوات جمع بيانات الرصد {#instrument-the-application}

      </Step>

      <Step title="تهيئة البيئة" id="configure-environment">
        افتح خدمة ClickHouse Observability الخاصة بك وانتقل إلى **إعدادات الفريق → بيانات القياس عن بُعد المُدارة**. انسخ **نقطة نهاية OTLP HTTP** و**مفتاح API**.

        <div className="ch-image-lg">
          <Frame>
            ![صفحة بيانات القياس عن بُعد المُدارة ضمن إعدادات الفريق، وتظهر فيها نقطة نهاية OTLP HTTP ومفتاح API مُقنَّعين](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        اضبط القيم التالية في ملف `.env` الخاص بالتطبيق، مع استبدال العناصر النائبة الخاصة بنقطة النهاية ومفتاح API:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        احتفظ بالبادئة `https://` في `OTEL_EXPORTER_OTLP_ENDPOINT`، ولا تُلحِق بها `/v1/logs` أو `/v1/traces` أو `/v1/metrics`، إذ تتولى حزم SDK إلحاق مسارات الإشارات. اضبط `OTEL_EXPORTER_OTLP_HEADERS` على `authorization=<your-api-key>` من دون البادئة `Bearer`؛ علمًا بأن التطبيق يمرّر هذا المفتاح أيضًا مباشرةً إلى SDK للمتصفح.

        يستخدم SDK للمتصفح نقطة النهاية ومفتاح API نفسيهما. ويُضمّنهما `vite.config.ts` في حزمة المتصفح، حيث يمكن للزوار الاطلاع عليهما. لذا استخدم خدمة مخصّصة لاختبار هذا العرض التوضيحي، واحرص على إبقاء `.env` خارج نظام التحكم في الإصدارات.
      </Step>

            تتكون إضافة أدوات الرصد من ثلاث خطوات: تثبيت حزم SDK، وتغيير أمر التشغيل، وتمكين SDK للمتصفح. ولا يمسّ أيٌّ من ذلك منطق الأعمال في التطبيق.

### تثبيت Node SDK {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### تمكين الغلاف في run.sh {#enable-run-sh-wrapper}

            يحتوي الجزء السفلي من `run.sh` على سطرَي `exec`. حوّل سطر `node` العادي إلى تعليق، وأزل علامة التعليق عن السطر المزوّد بأدوات الرصد:

            ```diff
             # BEFORE: plain node, no instrumentation:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # AFTER: same source, wrapped by opentelemetry-instrument:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            احرص على أن يظل التشغيل عبر `scripts/entrypoint.js`؛ إذ تستدعي هذه الطبقة الوسيطة `require('console')` كي يتمكن التقاط وحدة التحكم من تغليف `console.log`. أما توجيه `opentelemetry-instrument` مباشرةً إلى `dist/server/index.js` فيُرسل التتبّعات لكنه يُسقط السجلات دون أي تنبيه.

### تمكين SDK للمتصفح {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            في `src/web/telemetry.ts`، أزل علامة التعليق عن عبارة الاستيراد، وكتلة `HyperDX.init`، و`HyperDX.addAction` داخل `recordAction`:

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__` و`__OTLP_AUTH_TOKEN__` ثوابت وقت التصريف يحقنها `vite.config.ts` من قيم `OTEL_EXPORTER_OTLP_*` نفسها التي يستخدمها الخادم الخلفي.
          </Tab>

          <Tab title="استخدام فرع مزوّد مسبقًا بأدوات الرصد" id="use-the-instrumented-branch">
            لتخطي إضافة أدوات الرصد والبدء بتطبيق مزوّد بها مسبقًا، انتقل إلى [فرع `instrumented`](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented).

            ```bash
            git checkout instrumented
            npm install
            ```

            لا تشغّل `./reset.sh` على هذا الفرع إلا إذا أردت إزالة حزم SDK.

      <Step title="توليد حركة المرور وعرض بيانات القياس عن بُعد" id="generate-traffic-and-view-telemetry">
        أعد تشغيل التطبيق ليسري مفعول أمر التشغيل الجديد وحزمة المتصفح التي بُنيت حديثًا:

        ```bash
        # Ctrl-C the previous run, then:
        ./run.sh
        ```

        تأكد من أن رسالة بدء التشغيل تعرض ثلاثة أسطر `Health check passed` لكل من `/v1/traces` و`/v1/metrics` و`/v1/logs`. أعد تحميل علامة تبويب المتصفح ليقدّم Vite الحزمة المحدَّثة، ثم بدّل بين السنوات وانقر على القصص لتوليد حركة مرور.

        افتح خدمة ClickHouse Observability الخاصة بك:

        1. انتقل إلى **بحث**، واختر المصدر **Logs**، واضبط النطاق الزمني على **Last 15 minutes**. صفِّ `ServiceName` على القيمة `hn-analyzer-api` لعرض سجلات الواجهة الخلفية.

          <img src="/images/clickstack/getting-started/observability-hackernews-logs.png" alt="صفحة البحث في ClickHouse Observability تعرض سجلات الواجهة الخلفية مصفّاة على hn-analyzer-api" />

        2. اختر المصدر **Traces** وافتح طلبًا من `hn-analyzer-api`. سترى span معالج Express، وspan فرعيًا لطلب HTTP يشير إلى `sql-clickhouse.clickhouse.com` بمدة شبكة فعلية، إضافةً إلى سجلات `console.log` المترابطة ضمن التتبّع نفسه.

        <Frame>
          <img src="/images/clickstack/getting-started/observability-hackernews-traces.png" alt="تتبّع في ClickHouse Observability يعرض طلب المتصفح ومقاطع التتبع في الواجهة الخلفية والسجلات المترابطة وطلب HTTP إلى ClickHouse" />
        </Frame>

        3. افتح **جلسات العميل**، واختر جلسة من `hn-analyzer-web`، ثم افتح **إعادة تشغيل الجلسة** لمراجعة تفاعلات المتصفح.

        <Frame>
          <img src="/images/clickstack/getting-started/observability-hackernews-sessions.png" alt="إعادة تشغيل الجلسة في ClickHouse Observability تعرض HackerNews Analyzer مع أحداث تحديث لوحة المعلومات والبحث" />

        4. افتح **مستكشف المخططات**، واختر **Time Series** والمصدر **Metrics**، ثم اختر مقياسًا يُصدره التطبيق. صفِّ حسب `ResourceAttributes.service.name:"hn-analyzer-api"`، واختر نطاقًا زمنيًا يشمل فترة اختبارك، ثم انقر على **تشغيل** للتحقق من وجود بيانات المقياس.
      </Step>

## المتطلبات المسبقة {#prerequisites-self-configured}

    * Node 18+ و npm
    * خدمة Self-managed ClickHouse Observability قائمة، وجامع بيانات للإدخال قيد التشغيل.
    * نقطة نهاية OTLP HTTP الخاصة بجامع البيانات، على أن يمكن الوصول إليها من خادم التطبيق ومن متصفحك معًا. لا تستخدم `http://localhost:4318` إلا إذا كان جامع البيانات يعمل على الجهاز نفسه.
    * قيمة `OTLP_AUTH_TOKEN` الخاصة بجامع البيانات، إن كانت مُهيّأة. اضبط الترويسات على `authorization=<token>` دون البادئة `Bearer`. وإذا كان جامع البيانات لا يتطلب المصادقة، فاترك `authorization=` فارغة. هذه بيانات اعتماد الإدخال الخاصة بجامع البيانات، وليست بيانات اعتماد قاعدة بيانات ClickHouse الخاصة بك.
