خيارات الإعداد التالية متاحة لكل مكوّن من مكوّنات ClickStack:

<div id="modifying-settings">
  ## إعدادات التوزيعات مفتوحة المصدر {#modifying-settings}
</div>

### Docker {#docker}

إذا كنت تستخدم [الكل في واحد](/ar/clickstack/deployment/all-in-one) أو [واجهة مستخدم ClickStack فقط](/ar/clickstack/deployment/hyperdx-only) أو [محلي](/ar/clickstack/deployment/local-mode-only)، فيكفي تمرير الإعداد المطلوب عبر متغير بيئة، مثلًا.

```shell
docker run -e HYPERDX_APP_PORT=8081 -p 8081:8081 -p 4317:4317 -p 4318:4318 clickhouse/clickstack-all-in-one:latest
```

### Docker Compose {#docker-compose}

إذا كنت تستخدم دليل النشر الخاص بـ [Docker Compose](/ar/clickstack/deployment/docker-compose)، فيمكن استخدام ملف [`.env`](https://github.com/ClickHouse/clickstack/blob/main/.env) لتعديل الإعدادات.

بدلًا من ذلك، يمكنك استبدال الإعدادات صراحةً في ملف [`docker-compose.yml`](https://github.com/ClickHouse/clickstack/blob/main/docker-compose.yml)، على سبيل المثال.

مثال:

```yaml
services:
  app:
    environment:
      HYPERDX_API_KEY: ${HYPERDX_API_KEY}
      HYPERDX_LOG_LEVEL: ${HYPERDX_LOG_LEVEL}
      # ... other settings
```

### Helm {#helm}

اتّبع [دليل النشر عبر Helm](/ar/clickstack/deployment/helm) لتثبيت المشغّلات (operators) ومخطط ClickStack. واسترجِع القيم الحالية للمخطط قبل تخصيص النشر:

```shell
helm show values clickstack/clickstack > values.yaml
```

اضبط بيئة التطبيق وبيئة جامع البيانات كلًّا على حدة باستخدام قيم مخطط Helm، ثم طبّق التهيئة الخاصة بك:

```shell
helm upgrade --install my-clickstack clickstack/clickstack -f values.yaml
```

راجع [تكوين Helm](/ar/clickstack/deployment/helm-configuration) للاطلاع على القيم المدعومة، وإعدادات الدخول والموارد وsecret. أما المخطط الأقدم `hyperdx/hdx-oss-v2` فيعتمد بنية مختلفة للقيم.

## تطبيق واجهة مستخدم ClickStack {#hyperdx}

### الاتصالات {#connection-settings}

هيّئ الاتصال بقاعدة البيانات الذي تستخدمه مصادرك من صفحة إعدادات الفريق.

| الإعداد                    | الوصف                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Connection Name`          | الاسم المستخدم لتعريف هذا الاتصال في إعدادات المصدر.                                                                                                                                                                                                                                                                                                                                                                                     |
| `Host`                     | نقطة نهاية HTTP(S) الخاصة بـ ClickHouse، بما في ذلك المنفذ. وهي مختلفة عن نقطة نهاية التصدير الخاصة بجامع البيانات.                                                                                                                                                                                                                                                                                                                      |
| `Username`                 | اسم مستخدم ClickHouse؛ القيمة الافتراضية هي `default`.                                                                                                                                                                                                                                                                                                                                                                                   |
| `Password`                 | كلمة مرور ClickHouse؛ القيمة الافتراضية فارغة.                                                                                                                                                                                                                                                                                                                                                                                           |
| `Query Log Setting Prefix` | بادئة اختيارية لإعداد ClickHouse مخصص يسجّل البريد الإلكتروني للمستخدم الحالي في سجلات الاستعلامات. يجب إدراج البادئة نفسها في تهيئة `custom_settings_prefixes` الخاصة بـ ClickHouse، وإلا فستُرفض الاستعلامات. لمعرفة لوحة المعلومات أو التنبيه أو غير ذلك من ميزات ClickStack التي أصدرت استعلامًا ما، دون الكشف عن معرّفات المستخدمين، راجع [تحديد مصادر حمل الاستعلامات](/ar/clickstack/managing/performance-tuning#query-attribution). |
| `Prometheus compatible`    | عند توفّره، يُعامَل Host على أنه نقطة نهاية API متوافقة مع Prometheus لاستعلامات PromQL المُمرَّرة عبر الوكيل. ولا يمكن استخدام هذا الاتصال لمصادر السجلات أو التتبّعات أو مقاييس OTel المستندة إلى ClickHouse.                                                                                                                                                                                                                          |

### إعدادات مصدر البيانات {#datasource-settings}

تعتمد واجهة مستخدم ClickStack على أن يحدد المستخدم مصدرًا لكل نوع/ركيزة من أنواع بيانات إمكانية المراقبة:

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

يمكن إجراء هذا الإعداد من داخل التطبيق عبر `Team Settings -> Sources`، كما هو موضح أدناه للسجلات:

<div className="ch-image-md">
  <Frame>
    ![إعداد المصدر في واجهة مستخدم ClickStack](/images/use-cases/observability/hyperdx-25.webp)
  </Frame>
</div>

يحتاج كل مصدر إلى مطابقات للجداول والأعمدة حتى تتمكن واجهة مستخدم ClickStack من الاستعلام عن بياناته. ويمكن لمصادر المقاييس استخدام جداول منفصلة لكل نوع من أنواع المقاييس. يظهر مفتاح التبديل `Enabled` عند تعديل مصدر موجود، وتقبل `Query Settings` على مستوى المصدر ما يصل إلى عشرة أزواج من الاسم والقيمة.

إذا كنت تستخدم [مخطط OpenTelemetry (OTel) الافتراضي](/ar/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema) المرفق مع ClickStack، فيمكن استنتاج هذه الأعمدة تلقائيًا لكل مصدر. أما عند [تعديل المخطط](#clickhouse) أو استخدام مخطط مخصص، فيجب على المستخدمين تحديد هذه المطابقات وتحديثها.

<Note>
  ينشئ جامع البيانات الجداول إما عبر ترحيلات المخطط أو عبر الآلية القديمة لإنشاء المخطط التي يديرها المُصدِّر، وذلك بحسب [تهيئة المخطط](#collector-schema-and-retention) الخاصة به. وتتبع مطابقات الأعمدة اصطلاحات OpenTelemetry، بما في ذلك [نموذج بيانات السجلات](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
</Note>

#### Highlighted Attributes {#highlighted-attributes}

### المصادر المرتبطة {#correlated-sources}

لتمكين الربط الكامل بين المصادر في ClickStack، يجب عليك تكوين مصادر مرتبطة للسجلات والتتبعات والمقاييس والجلسات. يتيح ذلك لواجهة مستخدم ClickStack ربط البيانات ذات الصلة وتوفير سياق غني عند عرض الأحداث.

* `Logs`: يمكن ربطها بالتتبعات والمقاييس.
* `Traces`: يمكن ربطها بالسجلات والجلسات والمقاييس.
* `Metrics`: يمكن ربطها بالسجلات.
* `Sessions`: يمكن ربطها بالتتبعات.

يؤدي إعداد هذه الارتباطات إلى تمكين العديد من الميزات. على سبيل المثال، يمكن لواجهة مستخدم ClickStack عرض السجلات ذات الصلة إلى جانب تتبّع معيّن أو إظهار شذوذات المقاييس المرتبطة بجلسة.

| `Filter Keys Fetch Limit`           | `100`             | عدد مفاتيح عوامل التصفية التي يتم جلبها لكل عمود من نوع map. النطاق: 1–1,000.                             |
| `Field Metadata Queries`            | مفعّل             | يتحكم في جلب البيانات الوصفية للحقول من ClickHouse.                                                       |
| `Parallelize Queries When Possible` | معطّل             | يشغّل الاستعلامات المؤهلة المقسّمة إلى نوافذ زمنية بالتوازي، مما قد يرفع ذروة الحمل على قاعدة البيانات.   |

للاطلاع على الصلاحيات وسياسات الأمان، راجع [التحكم في الوصول المستند إلى الأدوار](/ar/clickstack/managing/rbac). وللاطلاع على وجهات الإشعارات، راجع [التنبيهات](/ar/clickstack/features/alerts).

### إعدادات تهيئة التطبيق {#application-configuration-settings}

تُستخدم متغيرات البيئة هذه لتهيئة ClickStack المستضاف ذاتيًا، ولا يمكن تهيئتها لواجهة مستخدم ClickStack المستضافة في ClickHouse Cloud. تشير القيم الافتراضية أدناه إلى القيم المعتمدة في نقاط الدخول الرسمية للحاوية ما لم يُذكر خلاف ذلك، ويمكن تجاوزها عبر Docker Compose. أعد تشغيل الخدمة المعنية بعد تغيير متغيرات بيئتها.

يُعد `NEXT_PUBLIC_IS_LOCAL_MODE` خيار إصدار الواجهة الأمامية الخاص بـ[توزيعة محلية](/ar/clickstack/deployment/local-mode-only)، وليس مفتاح تبديل عامًا لأغراض التطوير. استخدم التوزيعة المناسبة بدلًا من تعطيل المصادقة في عملية نشر قائمة. أما `IS_LOCAL_MODE` و`IS_OSS` فهما اسما ثابتين في التطبيق، وليسا من متغيرات البيئة التي يجب ضبطها. ويُعد `NEXT_PUBLIC_IS_OSS` إعداد إصدار، وليس مفتاح تبديل لإصدار Enterprise. ولم يعد التطبيق الحالي يستخدم `MINER_API_URL`.

عند استخدام تهيئة الوكيل العكسي المرفقة مع مسار فرعي، اضبط `HYPERDX_BASE_PATH` و`NEXT_PUBLIC_HYPERDX_BASE_PATH` على البادئة نفسها (مثل `/clickstack`)، وأدرج هذه البادئة في `FRONTEND_URL`.

تُقرأ بعض إعدادات الواجهة الأمامية وقت الإصدار. فعلى وجه الخصوص، يتطلب تغيير `NEXT_PUBLIC_HYPERDX_BASE_PATH` (بادئة مسار النشر) أو `NEXT_PUBLIC_NOINDEX` (فهرسة محركات البحث) أو خيارات الوضع الخاصة بالتوزيعة إعادة إصدار الواجهة الأمامية بهذه القيم. أما إعدادات بيئة التشغيل التي تُقرأ عبر `next-runtime-env`، مثل `NEXT_PUBLIC_INSTANCE_LABEL`، فيمكن توفيرها للحاوية عند بدء تشغيلها.

## مُجمِّع OpenTelemetry {#otel-collector}

راجع [مُجمِّع OpenTelemetry الخاص بـ ClickStack](/ar/clickstack/ingesting-data/collector) للاطلاع على تعليمات النشر. اضبط متغيرات جامع البيانات على حاوية جامع البيانات نفسها، لا على حاوية UI وحدها. في Compose، لا يكفي تعريف قيمة في `.env` لتمريرها إلى الحاوية، إذ لا تُمرَّر إليها إلا إذا أشار إليها ملف `docker-compose.yml`.

| `OPAMP_SERVER_URL`                          | غير مضبوطة في الوضع المستقل                        | عنوان URL الخاص بـ OpAMP في واجهة مستخدم ClickStack، وهو عادةً `http://<app>:4320`. عند ضبطه، يستعين جامع البيانات بالمشرف للحصول على التهيئة ومفاتيح استيعاب البيانات الخاصة بالفريق. وإلا فإنه يستخدم التهيئة المستقلة.                  |
| `OTLP_AUTH_TOKEN`                           | غير مضبوطة                                         | رمز حامل ثابت لإدخال OTLP في الوضع المستقل. يُتجاهَل عند اختيار مصادقة OIDC.                                                                                                                                                               |
| `OIDC_ISSUER_URL`                           | غير مضبوطة                                         | يفعّل مصادقة OIDC لإدخال OTLP في الوضع المستقل. وله الأسبقية على `OTLP_AUTH_TOKEN`.                                                                                                                                                        |
| `OIDC_AUDIENCE`                             | غير مضبوطة                                         | الجمهور المستهدف، وهو مطلوب عند ضبط `OIDC_ISSUER_URL`؛ ويفشل بدء التشغيل إذا لم يُحدَّد.                                                                                                                                                   |

في غياب OpAMP أو OIDC أو `OTLP_AUTH_TOKEN`، يعمل مستقبِل OTLP المستقل دون أي مصادقة. ويحتاج حساب ClickHouse إلى صلاحية إدراج بيانات القياس عن بُعد، وكذلك إلى صلاحية إنشاء كائنات قاعدة البيانات المطلوبة أو تعديلها عند تفعيل إنشاء المخطط أو عمليات الترحيل.

### المخطط والاحتفاظ بالبيانات {#collector-schema-and-retention}

| المتغير                                        | القيمة الافتراضية                     | الوصف                                                                                                                                                                                                                                    |
| ---------------------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HYPERDX_OTEL_EXPORTER_CREATE_LEGACY_SCHEMA`   | `false`؛ ويتجاوزها Compose إلى `true` | استخدام الطريقة القديمة لإنشاء المخطط، التي يديرها المُصدِّر، بدلًا من أداة الترحيل.                                                                                                                                                     |
| `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_JSON_ENABLE` | `false`                               | يفعّل وضع JSON في المُصدِّر ويعتمد الطريقة القديمة لإنشاء المخطط. لا يُنصح باستخدام مخططات تستخدم نوع البيانات JSON في أحمال العمل المعتادة لإمكانية المراقبة؛ راجع [Map مقابل نوع JSON](/ar/clickstack/ingesting-data/schema/map-vs-json). |

تنطبق قيم TTL الخاصة بكل نوع إشارة وإعداد التسوية على أداة الترحيل، التي يجري تجاهلها عند تفعيل الطريقة القديمة لإنشاء المخطط.

### TLS لعملية الترحيل {#collector-migration-tls}

تُهيّئ هذه المتغيرات اتصال ClickHouse الخاص بأداة الترحيل، لكنها لا تُهيّئ TLS للمُصدِّر تلقائيًا؛ لذا عليك تهيئة مُصدِّرات جامع البيانات بشكل منفصل عند استخدام شهادات مخصصة.

| المتغير                               | القيمة الافتراضية | الوصف                                                                                             |

| `CLICKHOUSE_TLS_CERT_FILE`            | غير مُعيَّن       | مسار شهادة العميل لاستخدامها مع TLS المتبادل.                                                     |
| `CLICKHOUSE_TLS_KEY_FILE`             | غير مُعيَّن       | مسار المفتاح الخاص بالعميل لاستخدامه مع TLS المتبادل.                                             |

<div id="clickhouse">
  ## ClickHouse {#clickhouse}
</div>

يأتي ClickStack Open Source بإعداد ClickHouse افتراضي مصمم للعمل على نطاق متعدد التيرابايت، لكن يمكن للمستخدمين تعديله وتحسينه بما يناسب عبء العمل لديهم.

لضبط ClickHouse بفعالية، ينبغي فهم مفاهيم التخزين الأساسية مثل [الأجزاء](/ar/concepts/core-concepts/parts)، و[الأقسام](/ar/concepts/core-concepts/partitions)، و[الشظايا والنسخ المتماثلة](/ar/guides/oss/deployment-and-scaling/shards)، وكيف تحدث [عمليات الدمج](/ar/concepts/core-concepts/merges) أثناء الإدراج. ونوصي بمراجعة أساسيات [الفهارس الأولية](/ar/concepts/core-concepts/primary-indexes)، و[الفهارس الثانوية المتناثرة](/ar/concepts/features/performance/skip-indexes/skipping-indexes)، وفهارس تخطي البيانات، إلى جانب تقنيات [إدارة دورة حياة البيانات](/ar/guides/use-cases/observability/build-your-own/managing-data)، مثل استخدام دورة حياة TTL.

يدعم ClickStack [تخصيص المخطط](/ar/guides/use-cases/observability/build-your-own/schema-design) — إذ يمكنك تعديل أنواع الأعمدة، واستخراج حقول جديدة (مثلًا من السجلات)، وتطبيق codecs والقواميس، وتسريع الاستعلامات باستخدام الإسقاطات.

بالإضافة إلى ذلك، يمكن استخدام العروض المادية [لتحويل البيانات أو تصفيتها أثناء الإدخال](/ar/guides/use-cases/observability/build-your-own/schema-design#materialized-columns)، بشرط أن تُكتب البيانات إلى الجدول المصدر للعرض وأن يقرأ التطبيق من الجدول الهدف. ويمكن أيضًا استخدام العروض المادية [لتسريع الاستعلامات مباشرةً](/ar/clickstack/managing/materialized-views) في ClickStack.

لمزيد من التفاصيل، راجع وثائق ClickHouse حول تصميم المخطط، واستراتيجيات الفهرسة، وأفضل ممارسات إدارة البيانات — ومعظمها ينطبق مباشرةً على عمليات نشر ClickStack.
