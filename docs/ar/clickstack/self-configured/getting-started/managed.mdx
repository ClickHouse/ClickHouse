انشر Self-managed ClickHouse Observability على ClickHouse Cloud، ثم أرسل حدثًا تجريبيًا عبر مسار إدخال البيانات لديك، وتحقّق من ظهور الحدث في UI الخاصة بإمكانية المراقبة.

يتولّى ClickHouse Cloud تشغيل الواجهة الخلفية لـ ClickHouse، بينما تظل أنت المتحكّم في مسار الإدخال والمخطط. ويوفّر Self-managed ClickHouse Observability ما يلي:

* التحجيم التلقائي للقدرة الحاسوبية بمعزل عن التخزين
* احتفاظ بالبيانات منخفض التكلفة وغير محدود عمليًا، قائم على التخزين الكائني
* عزل أحمال عمل القراءة والكتابة بعضها عن بعض باستخدام [المستودعات](/ar/products/cloud/features/infrastructure/warehouses)
* مصادقة مدمجة
* نسخ احتياطية تلقائية
* ميزات الأمان والامتثال
* ترقيات سلسة

## قبل أن تبدأ {#before-you-begin}

يمكنك أيضًا إرسال البيانات مباشرةً إلى ClickHouse عبر أحد [التكاملات المدعومة](/ar/integrations/home) باستخدام المخطط الخاص بك.

### إنشاء خدمة ClickHouse Cloud {#create-a-managed-clickstack-service}

أكمل خطوة [إنشاء خدمة ClickHouse](/ar/get-started/setup/cloud#1-create-a-clickhouse-service) الواردة في دليل البدء السريع الخاص بـ ClickHouse Cloud. وقبل المتابعة، تأكد من أن الخدمة قيد التشغيل.

<View title="OpenTelemetry">
  <Tip>
    تعرض هذه الصفحة مسار **OpenTelemetry**. استخدم محدِّد الدليل في أعلى الصفحة للتبديل بين **OpenTelemetry** (الخيار الموصى به) و**Vector**.
  </Tip>

  ### تجهيز بيئة الإدخال {#prepare-your-ingestion-environment}

  * لتشغيل [مُجمِّع OpenTelemetry](/ar/clickstack/self-configured/ingesting-data/collector) جديد، ثبّت [Docker](https://docs.docker.com/get-docker/). أما في Kubernetes، فانشر جامع البيانات باستخدام [Helm](/ar/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured).
  * لاستخدام جامع بيانات قائم، شغّله في [دور البوابة](/ar/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) وتأكّد من أن توزيعته تتضمن [مُصدِّر ClickHouse](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter). ستضيف التهيئة المطلوبة خلال هذا الدليل.

            ```sql
            CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
            ```

          استبدل `<host>` و`<your_password_here>` بالقيم الخاصة بخدمة ClickHouse Cloud لديك، ثم شغّل الأمر.

      عند استخدام Vector، تتولى أنت تحديد المخطط، إذ يمكن أن يتبع اصطلاحات OpenTelemetry أو يستخدم حقولاً خاصة بالأحداث لديك.

      <Info>
        **يلزم وجود مسار Vector قائم**

        تابع هذا الدليل إذا كنت تشغّل Vector بالفعل مع مسار إدخال. يجب أن تتضمن البيانات المُرسلة عبر المسار **عمود طابع زمني** أو حقلاً زمنياً مكافئاً، وهو ما ستختاره عند تهيئة مصدر البيانات في واجهة UI الخاصة بإمكانية المراقبة.

        تضيف الخطوات التالية وجهة بيانات ClickHouse إلى مسارك الحالي.
      </Info>

#### إنشاء قاعدة بيانات وجدول {#create-a-vector-database-and-table}

      أنشئ قاعدة بيانات وجدولًا قبل إعداد وجهة البيانات الخاصة بـ Vector.

      في ClickHouse Cloud، افتح وحدة تحكم SQL الخاصة بخدمتك وأنشئ قاعدة بيانات:

      على سبيل المثال، أنشئ قاعدة بيانات للسجلات:

      ```sql
      CREATE DATABASE IF NOT EXISTS logs
      ```

      بعد ذلك، أنشئ جدولًا يطابق مخططه بنية بيانات السجل لديك. يفترض المثال أدناه تنسيق سجل الوصول التقليدي في Nginx:

      ```sql
      CREATE TABLE logs.nginx_logs
      (
          `time_local` DateTime,
          `remote_addr` IPv4,
          `remote_user` LowCardinality(String),
          `request` String,
          `status` UInt16,
          `body_bytes_sent` UInt64,
          `http_referer` String,
          `http_user_agent` String,
          `http_x_forwarded_for` LowCardinality(String),
          `request_time` Float32,
          `upstream_response_time` Float32,
          `http_host` String
      )
      ENGINE = MergeTree
      ORDER BY (toStartOfMinute(time_local), status, remote_addr);
      ```

      يجب أن يتوافق جدولك مع مخطط الإخراج الذي يُنتجه Vector. عدِّل المخطط حسب الحاجة بما يلائم بياناتك، مع اتباع [أفضل الممارسات الموصى بها لتصميم المخطط](/ar/concepts/best-practices/select-data-type).

      نوصي بشدة بفهم آلية عمل [المفاتيح الأساسية](/ar/concepts/core-concepts/primary-indexes) في ClickHouse واختيار مفتاح ترتيب بناءً على أنماط الوصول لديك. راجع إرشادات [ضبط الأداء](/ar/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key) حول اختيار المفتاح الأساسي.

#### تهيئة وجهة بيانات ClickHouse {#configure-the-vector-clickhouse-sink}

      بعد إنشاء الجدول، أضف وجهة بيانات ClickHouse إلى تهيئة Vector لديك:

      ```yaml
      sinks:
        clickhouse:
          type: clickhouse
          inputs:
            - your_input
          endpoint: "https://<host>:8443"
          database: logs
          table: nginx_logs
          format: json_each_row
          skip_unknown_fields: true
          auth:
            strategy: basic
            user: default
            password: "<your_password_here>"
      ```

      استبدل `your_input` بالإدخال المُستخدَم في مسار البيانات الحالي لديك. واستبدل `<host>` و`<your_password_here>` بالقيم الخاصة بخدمة ClickHouse Cloud لديك. وعند الحاجة، غيّر قاعدة البيانات المستهدفة أو الجدول.

      <Accordion title="استخدم بيانات اعتماد مخصصة للإدخال (يُوصى بذلك)">
        في بيئة الإنتاج، أنشئ مستخدمًا مخصصًا وامنحه أذونات الوصول إلى جدول الهدف الخاص بـ Vector. في ClickHouse Cloud، افتح وحدة تحكم SQL الخاصة بخدمتك ونفّذ ما يلي:

        ```sql
        CREATE USER `clickstack-ingest` IDENTIFIED WITH sha256_password BY '<password>';
        GRANT SELECT, INSERT ON logs.nginx_logs TO `clickstack-ingest`;
        ```

        استبدل `default` بـ `clickstack-ingest` في وجهة البيانات الخاصة بـ Vector، واضبط قيمة `password` على كلمة مرور المستخدم المخصص.
      </Accordion>

      احفظ التهيئة المحدّثة، ثم أعد تحميل Vector أو أعد تشغيله باستخدام عملية النشر الحالية لديك.

      لمزيد من الأمثلة على استيعاب البيانات باستخدام Vector، راجع [استيعاب البيانات باستخدام Vector](/ar/clickstack/observability/ingesting-data/vector)، أو راجع [وثائق وجهة بيانات ClickHouse في Vector](https://vector.dev/docs/reference/configuration/sinks/clickhouse/) للاطلاع على الخيارات المتقدمة.

#### إنشاء مصدر بيانات {#create-a-vector-data-source}

      أنشئ مصدر بيانات للجدول الذي يعبّئه مسار Vector بالبيانات. ستطلب منك واجهة UI إنشاء مصدر عند تسجيل الدخول لأول مرة.

      يملأ النموذج التعبيرات مسبقًا وفقًا لمخطط OpenTelemetry الافتراضي. أما بالنسبة إلى جدول Nginx الذي أنشأناه في هذا الدليل، فهيّئ المصدر باستخدام القيم التالية:

      | الإعداد                        | القيمة                                                                                                          |
      | ------------------------------ | --------------------------------------------------------------------------------------------------------------- |
      | **الاسم**                      | `Nginx logs`                                                                                                    |
      | **نوع بيانات المصدر**          | سجل                                                                                                             |
      | **اتصال الخادم**               | `Default`                                                                                                       |
      | **قاعدة البيانات**             | `logs`                                                                                                          |
      | **الجدول**                     | `nginx_logs`                                                                                                    |
      | **عمود الطابع الزمني**         | `time_local`                                                                                                    |
      | **SELECT الافتراضي**           | `time_local, remote_addr, status, request`                                                                      |
      | **تعبير اسم الخدمة**           | `'nginx'`                                                                                                       |
      | **تعبير مستوى السجل**          | `multiIf(status >= 500, 'ERROR', status >= 400, 'WARN', 'INFO')`                                                |
      | **تعبير سمات السجل**           | `map('http.remote_addr', toString(remote_addr), 'http.status_code', toString(status), 'http.request', request)` |
      | **تعبير سمات المورد**          | `map('service.name', 'nginx')`                                                                                  |
      | **عمود الطابع الزمني المعروض** | `time_local`                                                                                                    |
      | **تعبير معرّف التتبّع**        | `''`                                                                                                            |
      | **تعبير Span ID**              | `''`                                                                                                            |
      | **تعبير العمود الضمني**        | `request`                                                                                                       |

      لا يحتوي جدول Nginx على عمود `Body`. اضبط **Body Expression** على:

      ```sql
      concat(
        remote_addr, ' ',
        remote_user, ' ',
        '[', formatDateTime(time_local, '%d/%b/%Y:%H:%i:%S %z'), '] ',
        '"', request, '" ',
        toString(status), ' ',
        toString(body_bytes_sent), ' ',
        '"', http_referer, '" ',
        '"', http_user_agent, '" ',
        '"', http_x_forwarded_for, '" ',
        toString(request_time), ' ',
        toString(upstream_response_time), ' ',
        '"', http_host, '"'
      )
      ```

      للاطلاع على إعدادات المصدر الأخرى، راجع [مرجع التهيئة](/ar/clickstack/self-configured/managing/config).
    </Step>
