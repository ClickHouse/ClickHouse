بالنسبة إلى دوال Node.js ذات معالجات الطلبات غير المتزامنة، استخدم ClickStack Node.js SDK. أما بيئات التشغيل الأخرى أو معالجات الطلبات القائمة على رد النداء، فاستخدم طبقات OpenTelemetry Lambda الموضحة أدناه.

## معالجات الطلبات غير المتزامنة في Node.js {#nodejs-async-handlers}

استخدم بيئة تشغيل Node.js في Lambda تستوفي الحد الأدنى الذي تتطلبه حزمة SDK، وهو Node.js 22.15. ثبّت حزمة SDK وضمّنها في حزمة النشر:

```shell
npm install @clickhouse/clickstack-node
```

اضبط متغيرات البيئة التالية في Lambda لتهيئة SDK قبل تحميل معالج الطلبات، ولتحديد اسم الخدمة:

```text
NODE_OPTIONS=--import @clickhouse/clickstack-node/register
OTEL_SERVICE_NAME=my-lambda-function
```

غلِّف معالج الطلبات غير المتزامن الخاص بك بالدالة `withFlush` لضمان تصدير بيانات القياس عن بُعد المخزَّنة مؤقتًا قبل انتهاء الاستدعاء:

```javascript
// index.mjs
import { withFlush } from '@clickhouse/clickstack-node';

export const handler = withFlush(async (event) => {
  console.log('request received');
  return { statusCode: 200, body: 'OK' };
});
```

اضبط معالج الطلبات الخاص بالدالة على `index.handler`. إذا جمّعت الدالة في حزمة، فأبقِ الـ SDK والتبعيات المزوّدة بأدوات الرصد خارجية، وضمّنها في حزمة النشر. ولا تُمكّن معها طبقة Lambda خاصة بـ auto-instrumentation في هذا الإعداد.

اضبط متغيرات الوجهة الواردة أدناه في تهيئة البيئة الخاصة بدالة Lambda. يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من دالتك. يُنهي الـ SDK عملية التفريغ قبل الموعد النهائي للاستدعاء، علمًا بأن `withFlush` لا يدعم معالجات الطلبات القائمة على رد النداء.

### تهيئة الوجهة {#configure-destination}

عيّن نقطة نهاية OTLP HTTP ومفتاح الإدخال الخاصين بـ مُجمِّع ClickStack. استخدم `http://` إذا لم يكن TLS مهيأً على جامع البيانات لديك. لمعرفة كيفية إعداد جامع البيانات، راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## بيئات التشغيل ومعالجات الطلبات الأخرى {#other-runtimes-and-handlers}

اتبع [تعليمات auto-instrumentation الرسمية الخاصة بـ Lambda](https://opentelemetry.io/docs/platforms/faas/lambda-auto-instrument/) لاختيار الطبقات المناسبة لبيئة التشغيل والمعمارية ومنطقة AWS لديك، ولتهيئة غلاف إضافة أدوات الرصد.

أضف [طبقة Lambda لمُجمِّع OpenTelemetry](https://opentelemetry.io/docs/platforms/faas/lambda-collector/) ثم هيّئها. أبقِ المُصدِّرات الخاصة بـ SDK التطبيق موجّهةً إلى جامع البيانات المحلي، كما هو موضّح في المصدر الأصلي. ثم هيّئ الاتصال الصادر لجامع البيانات كما هو موضّح أدناه.

### تهيئة وجهة جامع البيانات الخاص بـ Lambda {#configure-lambda-collector-destination}

عيّن `CLICKHOUSE_OTLP_ENDPOINT` و`CLICKHOUSE_INGESTION_API_KEY` في متغيرات البيئة الخاصة بدالة Lambda، ثم أضف المُصدِّر التالي إلى تهيئة جامع البيانات.

عيّن قيمة `CLICKHOUSE_OTLP_ENDPOINT` إلى نقطة نهاية OTLP HTTP الخاصة بمُجمِّع ClickStack، وقيمة `CLICKHOUSE_INGESTION_API_KEY` إلى مفتاح الإدخال الخاص به. يجب أن يكون الوصول إلى نقطة النهاية ممكنًا من دالة Lambda.

```yaml
exporters:
  otlphttp/clickhouse:
    endpoint: ${env:CLICKHOUSE_OTLP_ENDPOINT}
    headers:
      Authorization: "${env:CLICKHOUSE_INGESTION_API_KEY}"
```

استخدم `otlphttp/clickhouse` ضمن قائمة `exporters` في مسار تنفيذ كل إشارة تريد إرسالها. على سبيل المثال، مع المستقبِل `otlp` من المصدر الأصلي:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    metrics:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
    logs:
      receivers: [otlp]
      exporters: [otlphttp/clickhouse]
```

ادمج هذه الإعدادات في تهيئة جامع البيانات (Collector) لديك، مع الإبقاء على إعدادات المستقبِل والمعالج الموجودة فيها. ثم ضمّن ملف التهيئة في حزمة الدالة، واضبط `OPENTELEMETRY_COLLECTOR_CONFIG_URI` على موقعه، مثل `/var/task/collector.yaml`، وفقًا لتعليمات إعداد جامع البيانات (Collector) الواردة في وثائق المصدر الأصلي.

## التحقق من إدخال البيانات {#verify-ingestion}

انشر دالتك ثم استدعِها. في ClickStack، اختر نطاقًا زمنيًا حديثًا وابحث عن اسم الخدمة الخاص بدالتك ضمن Traces. تحقّق كذلك من Logs وMetrics إذا كانت أدوات الرصد التي أضفتها تُصدر هذه الإشارات، إذ إن إضافة مسار تنفيذ لا تُفعّل جمعها تلقائيًا.

لمزيد من المعلومات حول تهيئة الطبقة واستكشاف الأخطاء وإصلاحها، راجع [توثيق OpenTelemetry Lambda](https://github.com/open-telemetry/opentelemetry-lambda).
