يعتمد SDK للمتصفح الخاص بـ ClickStack على OpenTelemetry لجمع طلبات المتصفح والأخطاء وبيانات إعادة تشغيل session. استخدمه لتحليل أحداث الواجهة الأمامية جنبًا إلى جنب مع بيانات القياس عن بُعد الخاصة بالواجهة الخلفية في ClickStack.

## التثبيت {#install}

ثبّت الحزمة في تطبيق الواجهة الأمامية لديك:

```shell
npm install @clickhouse/clickstack-browser
```

تستخدم الحزمة وحدات ES. ويثبّت npm تبعيات النظير (peer dependencies) الخاصة بـ OpenTelemetry تلقائيًا. إذا كان تطبيقك يثبّت `@opentelemetry/api` مباشرةً أيضًا، فاستخدم الإصدار `~1.9.1` واحرص على الإبقاء على نسخة واحدة منها فقط؛ إذ يقع الإصدار 1.10 خارج نطاق الإصدارات التي تدعمها حزمة SDK هذه.

## تهيئة الوجهة {#configure-destination}

استخدم نقطة نهاية OTLP HTTP الخاصة بجامع البيانات لديك، ومفتاح الإدخال الذي جرت تهيئته له. يجب أن تكون نقطة النهاية قابلة للوصول إليها من متصفحات المستخدمين لديك. لمعرفة كيفية إعداد جامع البيانات، راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/ingesting-data/opentelemetry).

```javascript
import { init } from '@clickhouse/clickstack-browser';

init({
  endpoint: 'https://YOUR_COLLECTOR_HOST:4318',
  apiKey: 'YOUR_INGESTION_API_KEY',
  serviceName: 'my-frontend-app',
});
```

استخدم المفتاح الذي تمت تهيئته لمستقبِل OTLP في جامع البيانات لديك. ويجب أن يسمح جامع البيانات بمصدر تطبيقك ضمن تهيئة CORS لمستقبِل HTTP الخاص به.

استدعِ `init` مرة واحدة عند كل تحميل للصفحة، في المستوى الأعلى من وحدة الدخول (entry module)، مثل `src/main.ts` في Vite أو `instrumentation-client.ts` في Next.js. تجري التهيئة بشكل غير متزامن، لذا قد لا تُلتقط الطلبات المُرسلة فورًا ضمن الـ tick نفسه. لا تُجرِ التهيئة داخل React effect، إذ إن دالة التنظيف التي تستدعي `shutdown` توقف بيانات القياس عن بُعد نهائيًا طوال تحميل الصفحة ذاك.

<Note>
  تكون تهيئة المتصفح، بما فيها مفتاح الإدخال، مرئية لكل من يحمّل الصفحة. وللإبقاء على المفتاح في الخادم لديك، استخدم نقطة نهاية من المصدر نفسه مثل `/otel`، واحذف `apiKey`، ثم هيِّئ الخادم لإعادة توجيه طلبات OTLP مع ترويسة التفويض المناسبة.
</Note>

## التحقق من إدخال البيانات {#verify-ingestion}

حمّل تطبيقك، وتفاعل مع الصفحة، وأرسل طلبًا، وأطلق خطأً في وحدة التحكم. في ClickStack، اختر نطاقًا زمنيًا حديثًا وابحث في Logs أو Traces عن `my-frontend-app`. ثم افتح إعادة تشغيل session لفحص session المسجّلة.

إذا كانت البيانات مفقودة، فافحص وحدة تحكم المتصفح وطلبات الشبكة المرسلة إلى `/v1/traces` و`/v1/logs`. وتحقّق من نقطة النهاية، وترويسة التفويض، وإعدادات CORS، وسياسة أمان المحتوى (Content Security Policy). تأكّد كذلك من أن إصدار ClickStack لديك يدعم إعادة التشغيل والـ attribute القياسي `session.id` الخاص بـ SDK؛ فاستلام السجلات وحده لا يضمن ظهور sessions في UI.

## خيارات التهيئة {#initialization-options}

مرّر هذه الخيارات إلى `init`. استخدم `endpoint` لجامع بيانات مشترك، أو حدّد نقطتي النهاية الخاصتين بالإشارتين معاً عندما تكون لبيانات تتبّع والسجلات وجهات منفصلة.

| الخيار               | القيمة الافتراضية                                     | الغرض                                                                                                                                     |
| -------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`           | مطلوب ما لم تُعيَّن نقطتا النهاية الخاصتان بالإشارتين | URL أساسي لـ OTLP عبر HTTP أو مسار وكيل من المصدر نفسه؛ وتُلحِق SDK مسارات الإشارات به                                                    |
| `tracesEndpoint`     | غير معيّن                                             | URL كامل لبيانات تتبّع، يُستخدم كما هو بدلاً من URL المشتق من `endpoint`                                                                |
| `logsEndpoint`       | غير معيّن                                             | URL كامل للسجلات وإعادة التشغيل، يُستخدم كما هو بدلاً من URL المشتق من `endpoint`                                                         |
| `serviceName`        | مطلوب                                                 | تعيين `service.name` على جميع بيانات القياس عن بُعد                                                                                       |
| `apiKey`             | غير معيّن                                             | قيمة ترويسة `authorization`؛ استخدم الصيغة الخاصة بوجهتك الموضّحة أعلاه                                                                   |
| `traceOrigins`       | غير معيّن                                             | مصادر الخوادم الخلفية أو التعبيرات النمطية التي تستقبل سياق التتبّع                                                                       |
| `replay`             | `true`                                                | تسجيل إعادة تشغيل session؛ مع القيمة `false` تُجمَع بيانات القياس عن بُعد من المتصفح لكن تُعطَّل إعادة التشغيل                             |
| `resourceAttributes` | غير معيّن                                             | سمات موارد إضافية تُطبَّق أيضاً على إعادة التشغيل؛ وتكون الأسبقية لـ `serviceName` و`serviceVersion` و`environment` على المفاتيح المطابقة |
| `maskAllText`        | `true`                                                | إخفاء النصوص في إعادة التشغيل                                                                                                             |
| `maskAllInputs`      | `true`                                                | إخفاء قيم عناصر input وtextarea وselect                                                                                                   |
| `console`            | `'error'`                                             | التقاط المستوى `'error'` أو `'warn'` أو `'info'` (بما في ذلك `console.log`) أو `'debug'` وما هو أشد خطورة منه؛ استخدم `false` للتعطيل     |
| `serviceVersion`     | غير معيّن                                             | تحديد إصدار تطبيقك                                                                                                                        |
| `environment`        | غير معيّن                                             | تعيين `deployment.environment.name`                                                                                                       |
| `sanitizeUrl`        | غير معيّن                                             | إعادة كتابة عناوين URL المسجَّلة، على سبيل المثال لإزالة معلمات الاستعلام                                                                 |

للاطلاع على واجهة برمجة التطبيقات كاملةً، راجع [مرجع SDK للمتصفح](https://github.com/ClickHouse/clickstack-browser#quick-start).

## إعادة تشغيل session والخصوصية {#session-replay-and-privacy}

تكون إعادة تشغيل session مفعّلة افتراضيًا، ويُخفى النص وقيم الإدخال افتراضيًا كذلك.

لا يشمل إخفاء البيانات حالات مربعات الاختيار، ولا حالات أزرار الاختيار، ولا السمات مثل عناوين URL للروابط والعناصر النائبة. استخدم الصنف `rr-block` لاستبعاد العناصر الحساسة. ولا يشمل تنقيح عناوين URL العناوينَ الواردة في محتوى الصفحة المُعاد تشغيله، أو في تتبّعات مكدس الاستدعاءات، أو في رسائل وحدة التحكم. لا تلتقط من معلومات المستخدم إلا ما تسمح به سياسة الخصوصية لديك.

لإيقاف إعادة التشغيل مؤقتًا دون إيقاف بيانات القياس عن بُعد الخاصة بالمتصفح:

```javascript
import { pauseReplay } from '@clickhouse/clickstack-browser';

pauseReplay();
```

عندما تكون مستعدًا لاستئناف التسجيل:

```javascript
import { resumeReplay } from '@clickhouse/clickstack-browser';

resumeReplay();
```

## ربط تتبّعات الواجهة الأمامية بتتبّعات الخدمات الخلفية {#trace-propagation}

لربط طلبات المتصفح بتتبّعات الخدمات الخلفية، أضف `traceOrigins` إلى خيارات `init`، واستبدل القيمة الواردة في المثال بمصدر خدمتك الخلفية:

```javascript
traceOrigins: ['https://api.example.com'],
```

تحمل الطلبات المُرسَلة إلى المصدر الخاص بالصفحة نفسها وإلى الخوادم الخلفية المطابقة الترويسات `traceparent` و`tracestate` و`baggage`. ويجب أن يكون الخادم الخلفي لديك مزوّدًا بأدوات الرصد حتى يواصل هذا السياق.

يجب أن تسمح الخوادم الخلفية ذات المصادر المختلفة (cross-origin) بتمرير هذه الترويسات عبر CORS. كما يجب أن يسمح جامع بيانات القياس عن بُعد بمصدر الواجهة الأمامية. وإذا كان تطبيقك يستخدم سياسة أمان المحتوى (Content Security Policy)، فأضِف نقطة نهاية جامع البيانات إلى القائمة المسموح بها في `connect-src`.

## التعرّف على المستخدمين وتسجيل الأخطاء {#users-and-errors}

عند تسجيل الدخول، استخدم `setUser` لإرفاق معلومات المستخدم بمقاطع التتبع والسجلات اللاحقة:

```javascript
import { setUser } from '@clickhouse/clickstack-browser';

setUser({ id: 'user-123', email: 'user@example.com' });
```

عند تسجيل الخروج، امسح معلومات المستخدم وابدأ session جديدة:

```javascript
import { setUser, startNewSession } from '@clickhouse/clickstack-browser';

setUser(null);
startNewSession();
```

لإرفاق بيانات وصفية خاصة بالتطبيق بمقاطع التتبع والسجلات اللاحقة، استخدم `setAttributes`. يحلّ كل استدعاء محلّ المجموعة السابقة؛ ولمسحها، مرّر `null`:

```javascript
import { setAttributes } from '@clickhouse/clickstack-browser';

setAttributes({ 'app.team.name': 'checkout' });
```

تُلتقَط الأخطاء غير المُعالَجة (uncaught errors) وحالات الرفض غير المُعالَجة (unhandled rejections) تلقائيًا. كما تُلتقَط افتراضيًا الأخطاء التي تُبلِّغ عنها حدود الأخطاء (error boundaries) في React عبر `console.error`. استخدم `recordException` للأخطاء المُلتقَطة التي لم تُسجَّل مسبقًا؛ إذ يؤدي تسجيل الخطأ نفسه عبر `recordException` وعبر السجلات معًا إلى إنشاء أحداث مكررة:

```javascript
import { recordException } from '@clickhouse/clickstack-browser';

try {
  await submitCheckout();
} catch (error) {
  recordException(error, { 'app.operation': 'checkout' });
  // Handle the error in your application.
}
```

استبدل `submitCheckout` بعملية التطبيق التي تريد مراقبتها.

## الترحيل من SDK للمتصفح الخاص بـ HyperDX {#migration}

لا تقتصر هذه الترقية على تغيير اسم الحزمة فحسب؛ إذ يصبح `url` هو `endpoint`، ويصبح `service` هو `serviceName`، ويصبح `tracePropagationTargets` هو `traceOrigins`. كما أصبح إخفاء النصوص وحقول الإدخال مفعّلًا افتراضيًا بالقيمة `true`. استبدل `setGlobalAttributes` بـ `setUser` لتحديد هوية المستخدم، وبـ `setAttributes` للبيانات الوصفية الخاصة بالتطبيق. لا تحتاج حدود الأخطاء (error boundaries) في React التي تُبلغ عن الأخطاء عبر `console.error` إلى أي خطاف إضافي؛ أما إذا لم يكن الخطأ مُسجَّلًا مسبقًا، فاستخدم `recordException`.

راجع [دليل ترحيل SDK](https://github.com/ClickHouse/clickstack-browser/blob/main/docs/migration.md) للاطلاع على الخيارات المُزالة والتغييرات في السمات. وفي حال التثبيت عبر وسم script أو إذا كان تطبيقك يُهيّئ OpenTelemetry مسبقًا، فراجع [ملف README الخاص بـ SDK](https://github.com/ClickHouse/clickstack-browser#readme).

إذا تسبب SDK للمتصفح من ClickStack في مشكلة توافق في تطبيقك، فيمكنك استخدام [SDK للمتصفح القديم من HyperDX](https://github.com/hyperdxio/hyperdx-js/tree/main/packages/browser) ريثما تتحقق من المشكلة. استعد تهيئته واستدعاءات API الخاصة به بالاستعانة بدليل الترحيل المذكور أعلاه؛ إذ إن حزمتَي SDK غير قابلتين للتبادل، ولا ينبغي تشغيلهما معًا.
