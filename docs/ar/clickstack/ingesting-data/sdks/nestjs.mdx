استخدم Node.js SDK من ClickStack لجمع بيانات القياس عن بُعد من تطبيق NestJS الخاص بك وإرسالها إلى ClickStack. تتضمن حزمة SDK إضافة أدوات الرصد لطلبات NestJS، كما تلتقط مخرجات وحدة التحكم.

## تثبيت حزمة SDK {#install-sdk}

استخدم Node.js 22.15 أو إصدارًا أحدث:

```shell
npm install @clickhouse/clickstack-node
```

## تهيئة الوجهة {#configure-destination}

حدّد نقطة نهاية OTLP HTTP ومفتاح الإدخال الخاصين بمُجمِّع ClickStack. استخدم `http://` إذا لم يكن TLS مهيّأً على جامع البيانات لديك. لمعرفة كيفية إعداد جامع البيانات، راجع [إدخال البيانات باستخدام OpenTelemetry](/ar/clickstack/ingesting-data/opentelemetry).

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
```

## تشغيل تطبيقك {#start-application}

اضبط `OTEL_SERVICE_NAME` لتحديد هوية تطبيقك. أنشئ إصدارًا من تطبيق NestJS، ثم حمّل SDK مسبقًا قبل نقطة الدخول المُصرَّفة:

```shell
npm run build
OTEL_SERVICE_NAME='my-nestjs-app' node --import @clickhouse/clickstack-node/register dist/main.js
```

عدّل `dist/main.js` بما يتوافق مع مخرجات الإصدار لديك. وإذا كنت تستخدم `ts-node` أو أي مترجم شيفرة آخر يعترض `require`، فاستخدم `--require @clickhouse/clickstack-node/register` بدلًا من ذلك. وإذا كنت تجمّع تطبيقك في حزمة، فاحرص على إبقاء الـ SDK والتبعيات المزوّدة بأدوات الرصد خارج الحزمة.

يمكنك مواصلة استخدام مسجّل السجلات الافتراضي لوحدة التحكم في NestJS. أما إذا أردت مسجّل سجلات مخصصًا، فاستخدم أحد التكاملات المدعومة مثل Winston أو Pino. ولمزيد من التفاصيل حول التهيئة والتوافق، راجع [دليل Node.js](/ar/clickstack/ingesting-data/sdks/nodejs).

## التحقق من إدخال البيانات {#verify-ingestion}

أرسل طلبًا إلى أحد المتحكّمات (controller) في تطبيقك وأصدِر رسالة سجل. في ClickStack، اختر نطاقًا زمنيًا حديثًا وابحث عن اسم الخدمة الخاص بتطبيقك في Logs وTraces. ثم تحقّق من Metrics بعد مرور وقت كافٍ لتصدير البيانات.
