`clickhousectl` (واسمها البديل `chctl`) هي واجهة سطر الأوامر الرسمية لـ ClickHouse، من التطوير المحلي وصولًا إلى ClickHouse Cloud. وهي مصممة لتناسب المستخدمين العاملين على الطرفية، والبرامج النصية، ووكلاء البرمجة على حدٍّ سواء.

باستخدام `clickhousectl` يمكنك:

* تثبيت إصدارات ClickHouse المحلية والتبديل بينها، وتشغيل خوادم محلية معزولة، وتنفيذ استعلامات SQL
* تشغيل Postgres محليًا بالاعتماد على Docker
* إنشاء خدمات ClickHouse Cloud وتهيئتها وتوسيع نطاقها ونسخها احتياطيًا والاستعلام منها
* إنشاء خدمات [ClickHouse Managed Postgres](/ar/products/managed-postgres/overview) ومراقبتها وتهيئتها واستعادتها
* إنشاء ClickPipes وتشغيلها لاستيعاب البيانات من التخزين الكائني وKafka وKinesis وPub/Sub وPostgres وMySQL وMongoDB وBigQuery
* إدارة المصادر ولوحات المعلومات والتنبيهات وخطافات الويب وعمليات البحث المحفوظة والأدوار على خدمة [Managed ClickStack](/ar/clickstack/deployment/managed)
* تطوير الدوال المعرّفة من قِبل المستخدم القابلة للتنفيذ محليًا ونشرها على ClickHouse Cloud
* إدارة أعضاء المؤسسة والدعوات ومفاتيح API والأدوار
* تثبيت حزمة ClickHouse agent skills الرسمية في وكلاء البرمجة

تعرض هذه الصفحة أمثلة نموذجية، بينما يُعدّ `clickhousectl <command> --help` المرجع المعتمد لجميع الأوامر وخياراتها. تنتهي التعليمات المساعدة لمعظم الأوامر بقسم `CONTEXT FOR AGENTS`، ويتضمن هذا القسم في أوامر Cloud أيضًا صلاحيات مفتاح API اللازمة لتنفيذها. للاطلاع على شروحات تفصيلية للمهام، اتبع روابط الأدلة الواردة في كل قسم. وللحصول على نظرة عامة تركّز على Cloud، راجع [واجهة سطر الأوامر لـ ClickHouse](/ar/products/cloud/features/cli).

## التثبيت {#installation}

يعمل `clickhousectl` على نظامَي MacOS وLinux، وعلى معماريتَي ARM64 وx86&#95;64.

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

يثبّت البرنامج النصي الملف `~/.local/bin/clickhousectl` وينشئ الاسم البديل `chctl`. تأكّد من أن المجلد `~/.local/bin` مُدرَج في متغير `PATH` لديك.

يمكنك أيضًا تثبيته باستخدام مدير حزم:

| الأداة                                  | الأمر                           |
| --------------------------------------- | ------------------------------- |
| npm                                     | `npm install -g clickhousectl`  |
| uv                                      | `uv tool install clickhousectl` |
| pipx                                    | `pipx install clickhousectl`    |
| pip                                     | `pip install clickhousectl`     |
| cargo-binstall                          | `cargo binstall clickhousectl`  |
| Cargo، من الشيفرة المصدرية (Rust 1.94+) | `cargo install clickhousectl`   |

لا يُنشئ الاسم البديل `chctl` إلا البرنامج النصي للتثبيت وnpm. لتحديث نسخة مثبّتة مسبقًا، شغّل `clickhousectl update` (راجع [التحديث الذاتي](#self-update)).

## المتطلبات {#requirements}

* Docker، وذلك لتشغيل Postgres محليًا فقط
* لاستخدام أوامر Cloud، تحتاج إلى حساب على [ClickHouse Cloud](https://clickhouse.com/cloud). تعمل أوامر القراءة باستخدام مصادقة OAuth عبر المتصفح (`cloud auth login`)، أما إنشاء الموارد أو تعديلها فيتطلب [مفتاح API](/ar/products/cloud/features/admin-features/api/openapi). راجع [المصادقة](#authentication).

## الوضع المحلي {#local}

تعمل الأوامر المحلية ضمن الدليل الحالي. يحتفظ كل مشروع ببيانات الخادم الخاصة به في `.clickhouse/`، في حين تكون الملفات التنفيذية لـ ClickHouse مشتركة على مستوى النظام في `~/.clickhouse/`. لا تبحث واجهة سطر الأوامر في الأدلة الأم، لذا شغّل الأوامر المحلية من الدليل الجذري لمشروعك. راجع [دليل التطوير المحلي](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/local-development.md) للاطلاع على سير العمل الكامل.

### تثبيت الإصدارات واختيارها {#installing-versions}

```bash
clickhousectl local use latest              # Install the latest ClickHouse and make it the default (recommended)
clickhousectl local install lts             # Install the latest LTS release
clickhousectl local install 26.8            # Latest 26.8.x.x release
clickhousectl local list                    # Installed versions
clickhousectl local list --remote           # Versions available for download
clickhousectl local which                   # Current default
clickhousectl local remove 26.8.1.1760      # Remove an exact installed version
```

| المحدِّد      | المعنى                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------- |
| `latest`      | أحدث إصدار من ClickHouse، يُتحقَّق منه عن بُعد عند كل تثبيت أو استخدام أو تشغيل (موصى به) |
| `stable`      | أحدث إصدار مستقر                                                                          |
| `lts`         | أحدث إصدار ذي دعم طويل الأمد                                                              |
| `26.8`        | أحدث إصدار مطابق                                                                          |
| `26.8.1.1760` | إصدار محدد بعينه                                                                          |

يثبّت الأمر `local use` الإصدار عند الحاجة، ويعيّنه إصدارًا افتراضيًا لعمليات تشغيل الخادم اللاحقة، وينشئ له رابطًا رمزيًا في `~/.local/bin/clickhouse`، بحيث يصبح `clickhouse client` و`clickhouse local` متاحين ضمن `PATH` لديك. مرّر الخيار `--no-global` لتخطي إنشاء الرابط الرمزي. وإذا كان في ذلك المسار ملف عادي بالفعل، فإنه يُترك دون تعديل.

يرفض الأمر `local remove` إزالة الإصدار الافتراضي أو أي إصدار يستخدمه خادم قيد التشغيل في أي مشروع. أما الخيار `--force` فيوقف تلك الخوادم ويزيل الإصدار، ويُلغي تعيين الإصدار الافتراضي ويحذف الرابط الرمزي.

### تهيئة مشروع {#initializing-project}

```bash
clickhousectl local init
```

الأمر `init` اختياري، وهو ينشئ دليل `.clickhouse/` يتجاهله git لتخزين بيانات بيئة التشغيل، إضافةً إلى هياكل SQL أولية يمكنك تثبيتها في المستودع: `clickhouse/` (`tables/`، `materialized_views/`، `queries/`، `seed/`، `udfs/`) و`postgres/` (`tables/`، `views/`، `functions/`، `queries/`، `seed/`). وعند تشغيله مجددًا، لا ينشئ إلا ما هو مفقود.

### تشغيل خوادم محلية {#managing-servers}

```bash
clickhousectl local server start dev --version latest   # Background start; waits for readiness
clickhousectl local server start dev --no-wait          # Return after spawning
clickhousectl local server start dev --foreground       # Run in the foreground
clickhousectl local server start dev --http-port 8124 --tcp-port 9001
clickhousectl local server list                         # Servers in this project
clickhousectl local server list --global                # Servers across all projects
clickhousectl local server stop dev
clickhousectl local server stop-all                     # Stop all ClickHouse and Postgres servers in this project
clickhousectl local server remove dev                   # Permanently delete a stopped server's data
```

لكل خادم مُسمّى بياناته الخاصة في `.clickhouse/servers/<name>/data/`، وعند إيقاف الخادم يُحتفَظ بها حتى التشغيل التالي. وإذا لم يُحدَّد اسم، يُسمّى الخادم الأول `default`؛ أما إذا كان `default` قيد التشغيل بالفعل، فيُنشأ اسم جديد تلقائيًا. المنافذ الافتراضية هي 8123 لبروتوكول HTTP و9000 لبروتوكول TCP، وإذا كانت مشغولة تُسنَد منافذ متاحة بدلًا منها.

يحدّد الخيار `--version` الإصدار المستخدم في عملية التشغيل هذه فقط دون تغيير الإصدار الافتراضي. وعند التشغيل دون تحديد إصدار وفي غياب إصدار افتراضي، يُثبَّت `latest` دون أن يصبح الإصدار الافتراضي؛ لذا نفّذ `local use latest` أولًا لجعله الإصدار الافتراضي.

### تشغيل استعلامات SQL باستخدام العميل المحلي {#running-queries}

```bash
clickhousectl local client dev                                   # Interactive session
clickhousectl local client dev --query "SELECT 1" --query "SELECT 2"
clickhousectl local client dev --queries-file schema.sql seed.sql
clickhousectl local client dev --query "SELECT version()" -- --format JSONEachRow
clickhousectl local client --host localhost --port 9000          # Connect by address
```

يتصل `local client` بخادم مُسمّى باستخدام ملف ClickHouse التنفيذي نفسه الذي يشغّل ذلك الخادم (الاسم الافتراضي: `default`). تُمرَّر الوسيطات التي تلي `--` إلى `clickhouse client` كما هي دون تعديل. ويصدر الإخراج وحالة الخروج عن `clickhouse client`، حتى في وضع JSON، لذا حدِّد تنسيق إخراج SQL بنفسك عند كتابة البرامج النصية.

### تكوين الخادم المخصص {#custom-config-files}

ضع ملف إعداد جزئيًا بصيغة XML أو YAML في المجلد `~/.clickhouse/configs/`، ثم حدّده باسمه عند تشغيل الخادم:

```bash
mkdir -p ~/.clickhouse/configs
cat > ~/.clickhouse/configs/analytics.xml <<'XML'
<clickhouse>
    <profiles>
        <default><max_threads>4</max_threads></default>
    </profiles>
</clickhouse>
XML
clickhousectl local server configs
clickhousectl local server stop dev
clickhousectl local server start dev --config analytics
```

يُطبَّق الملف فوق القيم الافتراضية المضمّنة، لذا يكفي أن يتضمّن الإعدادات التي تريد تغييرها فقط. لا يُحفَظ هذا الاختيار، إذ إن أي تشغيل لاحق دون `--config` يُزيل طبقة الإعدادات الإضافية. وتظل الأولوية دائمًا لمسارات البيانات والمنافذ المُدارة على قيم الإعداد.

### كتابة بيانات الاتصال في ملف dotenv {#dotenv}

```bash
clickhousectl local server dotenv dev                                     # Writes .env
clickhousectl local server dotenv dev --local --user default --database analytics   # Writes .env.local
```

يقرأ الأمر `dotenv` المنافذ الفعلية للخادم قيد التشغيل، ثم يكتب `CLICKHOUSE_HOST` و`CLICKHOUSE_PORT` و`CLICKHOUSE_HTTP_PORT`، إضافةً إلى اسم المستخدم وكلمة المرور وقاعدة البيانات عند تمريرها. أمّا إذا كان الملف موجودًا مسبقًا، فتبقى أسطره الأخرى كما هي. حمِّل الملف باستخدام أداة تحميل dotenv في تطبيقك، ولا تُمرِّر المعاينة المطبوعة إلى `eval` أبدًا.

### Postgres المحلي {#local-postgres}

يعمل Postgres المحلي داخل Docker، لذا يجب أن يكون Docker قيد التشغيل. يدعم النظام الإصدارين 17 و18 من Postgres، بما في ذلك وسوم الصور مثل `18-alpine`؛ وتستخدم المثيلات الجديدة الإصدار 18 افتراضيًا.

```bash
clickhousectl local install postgres@18                 # Optional: pre-pull the image
clickhousectl local postgres start app --version 18
clickhousectl local postgres start app --wait-timeout 120
clickhousectl local postgres client app --query "SELECT version()"
clickhousectl local postgres client app --queries-file pg-schema.sql
clickhousectl local postgres dotenv app --local
clickhousectl local postgres stop app
clickhousectl local postgres remove app                 # Permanently delete the instance and its data
```

يُعرَّف المثيل باسمه وإصداره الرئيسي. عند استئناف مثيل متوقف، يُعاد استخدام منفذه ومستخدمه وكلمة المرور وقاعدة البيانات الأصلية، لذا لا تؤثر خيارات سطر الأوامر الخاصة بالإنشاء في عملية الاستئناف. تُولَّد كلمة مرور عشوائية ما لم تحدد كلمة مرور بنفسك. يحتوي الملف `.env.local` على كلمة المرور، لذا احرص على استبعاده من نظام التحكم في الإصدارات.

### UDFs المحلية {#local-udfs}

ينشر الأمر `local udf` [الدوال المعرّفة من قِبل المستخدم القابلة للتنفيذ](/ar/reference/functions/regular-functions/udf#executable-user-defined-functions) من `clickhouse/udfs/<name>/` إلى خادم محلي، بينما يحمّل الأمر `cloud udf` الدليل نفسه إلى Cloud (راجع [UDFs في Cloud](#cloud-udfs)).

```bash
clickhousectl local udf init my_udf            # udf.json and main.py (python3.11 runtime)
clickhousectl local server start
clickhousectl local udf deploy my_udf
clickhousectl local client --query "SELECT my_udf(1)"
clickhousectl local udf list
clickhousectl local udf remove my_udf
```

يقبل كل أمر باستثناء `init` الخيار `--server <name>` (القيمة الافتراضية هي `default`). يتحقق الأمر `deploy` من صحة `udf.json` بالطريقة نفسها التي يتبعها Cloud. وعند تشغيله على خادم قيد التشغيل، يعيد تحميل الدوال ويتأكد من تحميل الدالة بنجاح. لا يمكن نشر بيئة التشغيل `native` محليًا إلا على مضيفات Linux بمعمارية amd64 أو arm64. راجع [دليل الدوال المعرّفة من قِبل المستخدم](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/user-defined-functions.md).

## المصادقة {#authentication}

تستخدم أوامر Cloud أحد نوعين من بيانات الاعتماد:

| بيانات الاعتماد | الإمكانات                                                                                             | التخزين                                                              |
| --------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Browser OAuth   | هويتك كمستخدم: عمليات Cloud للقراءة فقط واستعلامات SQL للقراءة فقط، في جميع المؤسسات التي تنتمي إليها | `~/.clickhouse/tokens.json`، عام ومشترك بين المشاريع                 |
| مفتاح API       | يقتصر نطاقه على مؤسسة واحدة؛ وتتوقف صلاحيات عمليات القراءة وعمليات الكتابة على أدوار المفتاح          | `.clickhouse/credentials.json` عند حفظه، ويكون محليًا خاصًا بالمشروع |

إذا لم يكن لديك حساب ClickHouse Cloud بعد، فإن `clickhousectl cloud auth signup` يفتح صفحة التسجيل في متصفحك.

### تسجيل الدخول باستخدام OAuth {#oauth-login}

```bash
clickhousectl cloud auth login
```

سيفتح هذا متصفحك لتدفّق أجهزة OAuth. تُحفَظ الرموز المميّزة على مستوى النظام في `~/.clickhouse/tokens.json` ويُجدَّد صلاحيتها تلقائيًا.

<Note>
  إن OAuth **للقراءة فقط**. لإنشاء الموارد أو تعديلها، سجّل الدخول باستخدام [مفتاح API](#api-key).
</Note>

### مفتاح API {#api-key}

[أنشئ مفتاح API](/ar/products/cloud/features/admin-features/api/openapi) بالأدوار التي تتطلبها أوامرك، ثم احفظه. يمنع الموجّه التفاعلي ظهور السر في سجل shell الخاص بك:

```bash
clickhousectl cloud auth login --interactive
clickhousectl cloud auth login --api-key "$KEY_ID" --api-secret "$KEY_SECRET"   # Alternative
```

يتحقق أمر تسجيل الدخول من المفتاح ويعرض الهوية المرتبطة به. وإذا رفضت واجهة برمجة التطبيقات المفتاح، فلن يُحفظ، وينتهي الأمر برمز الخروج 4. أما إذا تعذّر الوصول إلى واجهة برمجة التطبيقات، فيُحفظ المفتاح مع عرض تحذير.

في بيئات CI وغيرها من عمليات الأتمتة، مرّر المفتاح عبر أداة إدارة الأسرار لديك بدلًا من حفظه:

```bash
export CLICKHOUSE_CLOUD_API_KEY=your-api-key
export CLICKHOUSE_CLOUD_API_SECRET=your-api-secret
```

لأغراض التطوير، تقرأ واجهة سطر الأوامر هذه المتغيرات أيضًا من ملف `.env` في الدليل الحالي. احرص على عدم إضافة ملف `.env` إلى نظام التحكم في الإصدارات.

### التحقق من بيانات الاعتماد ومسحها {#auth-status}

```bash
clickhousectl cloud auth whoami          # Verify the active credentials and show the orgs they reach
clickhousectl cloud auth status          # Show configured sources and which one is active
clickhousectl cloud auth logout --oauth  # Clear OAuth tokens only
clickhousectl cloud auth logout --api-keys
clickhousectl cloud auth logout          # Clear both
```

يعمل الأمر `whoami` مع أيٍّ من نوعَي بيانات الاعتماد، وينتهي برمز الخروج 4 إذا رُفضت بيانات الاعتماد. أما الأمر `status` فقد ينتهي برمز الخروج 0 حتى إن لم تنجح أي من بيانات الاعتماد، لذا استخدم `whoami` للتحقق من صلاحية الوصول. لا يؤدي تسجيل الخروج إلى حذف متغيرات البيئة أو تعديل الملف `.env`.

### أسبقية بيانات الاعتماد {#credential-precedence}

يُستخدم أول مصدر متاح وفق الترتيب التالي:

1. خيارا سطر الأوامر `--api-key` و`--api-secret`
2. `.clickhouse/credentials.json`
3. متغيرات البيئة المُصدَّرة
4. المتغيرات المعرَّفة في ملف `.env` ضمن الدليل الحالي
5. رموز OAuth العامة

مرِّر الخيار `--debug` إلى أي أمر من أوامر `cloud` لطباعة مصدر بيانات الاعتماد المُختار وعنوان URL لواجهة برمجة التطبيقات إلى stderr:

```bash
clickhousectl cloud service list --debug
```

### اختيار مؤسسة {#organizations}

لا تحدد الأوامر الخاصة بنطاق المؤسسة المؤسسةَ تلقائيًا إلا إذا كانت بيانات الاعتماد الخاصة بك تتيح الوصول إلى مؤسسة واحدة فقط. وإلا فمرِّر `--org-id`، أو `--org-name` مع الاسم مطابقًا تمامًا:

```bash
clickhousectl cloud org list
clickhousectl cloud service list --org-id <org-id>
clickhousectl cloud service list --org-name "My Org"
```

تقبل معظم أوامر الموارد معرّف ID موضعيًا أو قيمة `--name` مطابقة تمامًا. راجع [المصادقة والوصول](https://github.com/ClickHouse/clickhousectl/blob/main/docs/reference/authentication.md) لمزيد من التفاصيل حول الصلاحيات، والمفاتيح المقيّدة، وتنظيف البيانات عند تسجيل الخروج.

## Cloud {#cloud}

تستدعي أوامر Cloud [واجهة برمجة تطبيقات ClickHouse Cloud](/ar/products/cloud/features/admin-features/api/api-overview). تعود طلبات الإنشاء والتحديث فور قبول واجهة برمجة التطبيقات لها، لذا استطلع `get` بشكل متكرر إلى أن يصل المورد إلى الحالة المطلوبة.

### الخدمات {#services}

```bash
clickhousectl cloud service create --name analytics \
  --provider aws --region us-east-1 --ip-allow '203.0.113.10/32=Office'
clickhousectl cloud service list
clickhousectl cloud service get <service-id>
clickhousectl cloud service start <service-id>
clickhousectl cloud service stop <service-id>
clickhousectl cloud service wake <service-id>             # Wake an idle service
clickhousectl cloud service reset-password <service-id>
clickhousectl cloud service delete <service-id>           # Must be stopped; --force stops it first
```

احفظ كلمة المرور الأولية المعروضة عند الإنشاء، إذ لا تُعرض إلا مرة واحدة. ينتهي أمر الإنشاء قبل اكتمال التجهيز، لذا كرّر تنفيذ `get` إلى أن تصبح الحالة `running`. **عند إغفال `--ip-allow` يُسمح بجميع عناوين IP (`0.0.0.0/0`).** تقبل العناصر الصيغة `IP_OR_CIDR=DESCRIPTION`. يمكنك استعادة نسخة احتياطية إلى خدمة جديدة باستخدام `--backup-id`، أو نشر خدمة في البنية التحتية لـ BYOC باستخدام `--byoc-id`.

تحديث خدمة وتغيير حجمها وتهيئتها:

```bash
clickhousectl cloud service update <service-id> --new-name analytics-prod \
  --add-ip-allow '198.51.100.0/24=VPN' --remove-ip-allow 0.0.0.0/0 --add-tag env=prod
clickhousectl cloud service profile list --region us-east-1
clickhousectl cloud service scale <service-id> \
  --min-replica-memory-gb 8 --max-replica-memory-gb 32 --num-replicas 2
clickhousectl cloud service scale <service-id> --autoscaling-mode horizontal \
  --min-replica-memory-gb 16 --max-replica-memory-gb 16 --min-replicas 2 --max-replicas 6
clickhousectl cloud service settings set <service-id> --setting 'enable_analyzer=1'
clickhousectl cloud service upgrade-window set <service-id> --weekday 0 --start-hour 6
```

تكون الذاكرة لكل نسخة متماثلة من مضاعفات 4 GB، بحد أقصى 120 GB في الخدمات غير المدفوعة و356 GB في الخدمات المدفوعة، وبما يصل إلى 50 نسخة متماثلة. وقد تفرض حدود المؤسسة والمستودع قيمًا أدنى من ذلك. ويتطلب التوسّع الأفقي التلقائي تفعيل الميزة الخاصة به على مستوى المؤسسة. ولا يغيّر الأمر `update` إلا خيارات سطر الأوامر التي تمرّرها.

أما مجموعات أوامر الخدمة الأخرى فهي: `settings` (list وget وschema وset وunset)، و`scaling-schedule`، و`upgrade-window`، و`replica-aware-routing` (تجريبي)، و`snapshot` (تجريبي)، و`private-endpoint`، و`backup-config`، و`prometheus`. راجع [إنشاء خدمة سحابية في Cloud وتشغيلها](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/cloud-service.md).

### واجهة برمجة تطبيقات الاستعلام {#query-api}

ينفّذ الأمر `cloud service query` عبارة SQL واحدة عبر HTTP، دون الحاجة إلى ملف تنفيذي محلي لـ `clickhouse` أو إلى كلمة مرور الخدمة:

```bash
clickhousectl cloud service query <service-id> --query "SELECT version()"
clickhousectl cloud service query <service-id> --queries-file query.sql --format TabSeparated
printf 'INSERT INTO trips FORMAT CSV\n' | cat - data.csv | \
  clickhousectl cloud service query <service-id>
```

* **OAuth** يُشغّل الاستعلام بهويتك، مع صلاحية وصول SQL للقراءة فقط. ولا يُربط أي شيء بالخدمة.
* **مفتاح API:** عند الاستدعاء الأول، يضيف clickhousectl مفتاح API الخاص بك إلى نقطة نهاية واجهة برمجة تطبيقات الاستعلام الخاصة بالخدمة، وينشئ نقطة النهاية بأدوار `sql_console_admin` عند الحاجة. وتُحفظ الأدوار والمصادر وروابط المفاتيح الأخرى الموجودة دون تغيير، ولا يُنشأ أي مفتاح جديد. وعندما تُعدّل واجهة سطر الأوامر نقطة النهاية، تطبع الرسالة `Binding the authenticated API key to the Query API endpoint for service '<name>'...` إلى stderr. مرّر `--no-auto-enable` لتفشل العملية بدلًا من ذلك.

يظل للمفتاح الخاص بخدمة معينة، الذي حفظه إصدار سابق من واجهة سطر الأوامر، الأسبقيةُ لتلك الخدمة. وإذا رفضته واجهة برمجة التطبيقات، يستبدله الأمر `cloud service repair-query-key <service-id>` عن قصد.

تقبل واجهة برمجة تطبيقات الاستعلام عبارة واحدة فقط في كل طلب. وقد تنتهي مهلتها بعد نحو 30 ثانية مع استمرار تنفيذ SQL، لذا تحقّق من النتيجة قبل إعادة محاولة أي عملية كتابة. استخدم `clickhouse client` للبرامج النصية متعددة العبارات وعمليات التحميل المجمّع والاستعلامات الطويلة. تقيّد قائمة السماح لعناوين IP الخاصة بالخدمة الاتصالات المباشرة فقط، ولا تشمل مسار واجهة برمجة تطبيقات الاستعلام المارّ عبر الوكيل. ويؤدي الاستعلام عن خدمة خاملة إلى تنشيطها، أما الخدمة المتوقفة فيجب تشغيلها باستخدام `cloud service start`.

أدِر نقطة نهاية واجهة برمجة تطبيقات الاستعلام الخاصة بالخدمة، ونقاط نهاية SQL المسمّاة، والاستعلامات المحفوظة:

```bash
clickhousectl cloud service query-endpoint get <service-id>
clickhousectl cloud service query-endpoint create <service-id> \
  --role sql_console_read_only --allowed-origins '*'
clickhousectl cloud query-api-endpoint create <service-id> --file endpoint.json
clickhousectl cloud saved-query create <service-id> --name "Order count" \
  --sql 'SELECT count() FROM orders' --database default
```

يستبدل الأمر `query-endpoint create` الأدوار المُسندة إلى كل مفتاح مرتبط بنقطة النهاية. راجع [سلوك SQL وواجهة برمجة تطبيقات الاستعلام](https://github.com/ClickHouse/clickhousectl/blob/main/docs/reference/query-api.md).

### Managed Postgres {#postgres-services}

يتولّى الأمر `cloud postgres` إدارة [ClickHouse Managed Postgres](/ar/products/managed-postgres/overview). لا تزال هذه الأوامر في مرحلة تجريبية، بينما يتوفّر دعم GCP في مرحلة المعاينة الخاصة.

```bash
clickhousectl cloud postgres create --name app-db \
  --provider aws --region us-east-1 --size c6gd.xlarge --pg-version 18 \
  --ip-allow '203.0.113.0/24:5432..6432=office'
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output ca.pem
clickhousectl cloud postgres update <postgres-id> --size c6gd.2xlarge
clickhousectl cloud postgres update <postgres-id> \
  --remove-ip-allow <rule-id> --add-ip-allow '198.51.100.7:5432'
clickhousectl cloud postgres config patch <postgres-id> --set log_min_duration_statement=1000
clickhousectl cloud postgres reset-password <postgres-id> --generate
clickhousectl cloud postgres delete <postgres-id>       # Deletes a running service too
```

تشمل أحجام AWS كلاً من `m6gd.large` و`c6gd.xlarge` و`r6gd.xlarge`. أما على GCP، فمرِّر `--provider gcp` مع منطقة GCP وحجم مثل `c4-standard-lssd-4`.

احفظ كلمة المرور وسلسلة الاتصال اللتين يُعيدهما الأمر `create`، إذ لا تُعيد استجابات `get` اللاحقة بيانات الاعتماد أبداً، ويبقى `reset-password` السبيل الوحيد للحصول على بيانات اعتماد جديدة. اتصل باستخدام `psql` مع `sslmode=verify-full` وملف CA.

**إذا أغفلت خيارات سطر الأوامر الخاصة بالوصول عند الإنشاء، فسيُسمح لجميع عناوين IPv4 وIPv6 بالوصول إلى Postgres (5432) وPgBouncer (6432).** مرِّر خياراً `--ip-allow IP_OR_CIDR:PORTS[=DESCRIPTION]` لكل قاعدة، أو `--block-public-access` إن لم ترغب في أي قواعد. وبمجرد تمرير قاعدة واحدة، لن تُطبَّق سوى القواعد المُدرجة.

المراقبة والاسترداد:

```bash
clickhousectl cloud postgres query <postgres-id> --query "SELECT version()"   # OAuth only, read-only
clickhousectl cloud postgres logs <postgres-id> \
  --from-date 2026-10-01T00:00:00Z --to-date 2026-10-02T00:00:00Z
clickhousectl cloud postgres backup list <postgres-id>
clickhousectl cloud postgres restore <postgres-id> \
  --name restored-app --restore-target 2026-10-01T12:00:00Z
clickhousectl cloud postgres read-replica create <postgres-id> --name app-db-replica
clickhousectl cloud postgres promote <replica-id>
```

لا يقبل `cloud postgres query` سوى OAuth، لذا يفشل ما دام هناك مصدر لمفتاح API ذو أولوية أعلى نشطًا. تتولى الأوامر `metrics` و`slow-queries` و`prometheus` جانب المراقبة. ينسخ `restore` قواعد الوصول الحالية لعناوين IPv4 الخاصة بالمصدر إلى الخدمة المستعادة، ما لم تمرّر `--ip-allow` أو `--block-public-access`. تكتمل عمليات الاستعادة وإنشاء النسخ المتماثلة دون إرجاع كلمة مرور. يعود الأمران `promote` و`switchover` بمجرد قبول الطلب؛ وبعد تنفيذ الترقية، استطلع `postgres get --json` إلى أن تُبلغ النسخة المتماثلة عن `isPrimary: true`. راجع [دليل Managed Postgres](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/managed-postgres.md).

### ClickPipes {#clickpipes}

يتولّى الأمر `cloud clickpipe` استيعاب البيانات من التخزين الكائني وKafka وKinesis وPub/Sub وPostgres وMySQL وMongoDB وBigQuery. ويتطلّب الإنشاء واكتشاف المخطط توفّر مفتاح API وخدمة وجهة قيد التشغيل. ولكل مصدر أمر فرعي خاص به هو `clickpipe create <source>`؛ شغّله مع `--help` لعرض خيارات سطر الأوامر المتاحة له.

حمّل الملفات من S3 باستخدام دور IAM. اكتشف المخطط أولاً، ثم اختر الأعمدة:

```bash
clickhousectl cloud clickpipe schema-discover object-storage <service-id> \
  --storage-type s3 --source-url 'https://example-bucket.s3.amazonaws.com/events/**' \
  --format JSONEachRow --iam-role "$S3_IAM_ROLE_ARN"
clickhousectl cloud clickpipe create object-storage <service-id> \
  --name s3-events --storage-type s3 \
  --source-url 'https://example-bucket.s3.amazonaws.com/events/**' \
  --format JSONEachRow --iam-role "$S3_IAM_ROLE_ARN" \
  --database default --table s3_events \
  --column 'event_id:Int64' --column 'event_type:String'
```

انسخ بيانات Postgres نسخًا متماثلًا باستخدام CDC (التقاط تغييرات البيانات). يجري التحقق من TLS افتراضيًا؛ أما في حالة مصدر Managed Postgres، فصدِّر شهادة CA الخاصة به ومرِّرها:

```bash
clickhousectl cloud postgres certs get <postgres-id> --output pg-ca.pem
clickhousectl cloud clickpipe create postgres <service-id> \
  --name orders-cdc --host "$POSTGRES_HOST" --pg-database postgres \
  --username "$POSTGRES_USERNAME" --password "$POSTGRES_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --replication-mode cdc --destination-database default \
  --table-mapping public.orders:orders
clickhousectl cloud service query <service-id> \
  --query "SELECT id, status FROM default.orders FINAL WHERE _peerdb_is_deleted = 0"
```

يُنشئ `--table-mapping` جداول `ReplacingMergeTree`، لذا اقرأ الحالة الحالية باستخدام `FINAL WHERE _peerdb_is_deleted = 0`. ويتبع مسار استيعاب البيانات من Kafka النمط نفسه: شغّل `clickpipe schema-discover kafka` بخيارات سطر الأوامر نفسها الخاصة بالمصدر، ثم مرّر الأعمدة:

```bash
clickhousectl cloud clickpipe create kafka <service-id> \
  --name kafka-events --brokers 'broker-1.example.com:9092' --topics events \
  --format JSONEachRow --auth SCRAM-SHA-256 \
  --username "$KAFKA_USERNAME" --password "$KAFKA_PASSWORD" \
  --database default --table kafka_events \
  --column 'event_id:Int64' --column 'event_type:String' --start-paused
```

تُنفِّذ مسارات استيعاب البيانات من BigQuery لقطةً بشكل افتراضي. ولاستخدام CDC (التقاط تغييرات البيانات)، مرِّر `--replication-mode cdc` و`--replication-method`، إضافةً إلى عمود للعلامة المائية الزمنية أو دالة أحداث لكل جدول ضمن `--table-mapping-json`؛ ثم حدِّد الجدول الزمني للمزامنة باستخدام `--sync-cron` أو `--sync-interval-seconds`. ولإدارة مسارات استيعاب البيانات الموجودة:

```bash
clickhousectl cloud clickpipe list <service-id>
clickhousectl cloud clickpipe get <service-id> <clickpipe-id>
clickhousectl cloud clickpipe stop <service-id> <clickpipe-id>
clickhousectl cloud clickpipe update <service-id> <clickpipe-id> --file patch.json
clickhousectl cloud clickpipe start <service-id> <clickpipe-id>
clickhousectl cloud clickpipe scale <service-id> <clickpipe-id> --replicas 2
clickhousectl cloud clickpipe settings update <service-id> <clickpipe-id> \
  --streaming-max-insert-wait-ms 5000
clickhousectl cloud clickpipe resync <service-id> <clickpipe-id>   # Postgres and MySQL pipes; re-ingests data
```

يجب أن تكون مسارات استيعاب بيانات CDC في الحالة `Paused` قبل تنفيذ `update`: أوقف مسار استيعاب البيانات، ثم استطلع حالته عبر `get` إلى أن تصبح `Paused`، ثم حدّثه. قد تستأنف الخدمة مسار استيعاب البيانات ضمن عملية التحديث، لذا لا تشغّل `start` إلا إذا كان `get` لا يزال يُظهر الحالة `Paused`. يتوفر الخيار `--start-paused` للتخزين الكائني وKafka وKinesis وPub/Sub. أما مجموعات الأوامر الأخرى فهي `cdc-scaling` و`context get` (جاهزية هوية عبء العمل في GCP والكيان الأمني) و`reverse-private-endpoint`. راجع [دليل ClickPipes](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/clickpipes.md) و[مرجع تهيئة ClickPipe](https://github.com/ClickHouse/clickhousectl/blob/main/docs/reference/clickpipe-configuration.md).

### ClickStack {#clickstack}

يتولّى الأمر `cloud clickstack` إدارة المصادر ولوحات المعلومات والتنبيهات وخطافات الويب وعمليات البحث المحفوظة والأدوار ضمن خدمة [Managed ClickStack](/ar/clickstack/deployment/managed) موجودة. تُعرَّف الموارد في صورة ملفات JSON (عبر `--file`، أو `-` للقراءة من stdin). تدعم عمليات القراءة المصادقة عبر OAuth، في حين تتطلب عمليات الكتابة مفتاح API.

```bash
clickhousectl cloud clickstack source list <service-id>
clickhousectl cloud clickstack dashboard validate <service-id> --file dashboard.json
clickhousectl cloud clickstack dashboard create <service-id> --file dashboard.json
clickhousectl cloud clickstack webhook validate <service-id> --file webhook.json
clickhousectl cloud clickstack alert create <service-id> --file alert.json
clickhousectl cloud clickstack dashboard get <service-id> <dashboard-id> --json > dashboard-before.json
```

**كل عملية تحديث في ClickStack تستبدل المورد بأكمله.** احفظ الحالة الحالية باستخدام `get --json`، ثم أرسل التعريف كاملًا، لا الحقول المُعدَّلة وحدها. راجع [دليل ClickStack](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/clickstack.md).

### UDFs في Cloud {#cloud-udfs}

يتولى الأمر `cloud udf` إدارة الدوال المعرّفة من قِبل المستخدم القابلة للتنفيذ (UDFs) على مستوى المؤسسة، إلى جانب إصداراتها وربطها بالخدمات. أما الأمر `deploy` فيُحمّل الدليل الذي اختبرته باستخدام `local udf`، وينتظر اكتمال الإصدار، ثم يربط هذا الإصدار بالخدمة وينتظر حتى يكتمل نشره:

```bash
clickhousectl cloud udf deploy my_udf --service <service-id>
clickhousectl cloud service query <service-id> --query "SELECT my_udf(1)"
```

لتنفيذ كل خطوة بنفسك، استخدم `udf create` و`udf version create` و`udf attach` (مع `--wake` إذا كانت الخدمة خاملة) و`udf detach` و`udf delete`. تعود هذه الأوامر بمجرد قبول الطلب، لذا استطلع الحالة باستخدام `udf get` و`udf attachment get`. تدعم عمليات القراءة المصادقة عبر OAuth، في حين تتطلب عمليات الكتابة مفتاح API. راجع [دليل الدوال المعرّفة من قِبل المستخدم](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/user-defined-functions.md).

### المؤسسات والوصول {#org-and-access}

```bash
clickhousectl cloud org get --org-id <org-id>
clickhousectl cloud org update --org-id <org-id> --new-name "Renamed Org"
clickhousectl cloud org usage --org-id <org-id> --from-date 2026-09-01 --to-date 2026-09-30
clickhousectl cloud org prometheus discovery --org-id <org-id>
clickhousectl cloud org notifications --org-id <org-id> --severity warning
clickhousectl cloud activity list --from-date 2026-09-01 --to-date 2026-09-30
```

تقبل الأوامر الفرعية لـ `cloud org` الخيار `--org-id`، ولا تقبل أبدًا ID موضعيًا. يغطي `org usage` فترة لا تتجاوز 31 يومًا. يتضمن `org` أيضًا `quota` و`balance` و`notification-types` و`role` (أدوار المؤسسة المخصصة) و`byoc` (البنية التحتية لـ BYOC). الإشعارات ميزة في مرحلة تجريبية.

إدارة الأعضاء والدعوات ومفاتيح API:

```bash
clickhousectl cloud member list
clickhousectl cloud member update <user-id> --role-id <role-id>
clickhousectl cloud invitation create --email dev@example.com --role-id <role-id>
clickhousectl cloud org role list --org-id <org-id>
clickhousectl cloud key create --name ci-key --role-id <role-id> \
  --expires-at 2027-12-31T00:00:00Z --ip-allow '203.0.113.10/32=CI runner'
clickhousectl cloud key list --all
clickhousectl cloud key update <key-id> --new-name ci-key-old --state disabled
```

**يؤدي إغفال `--ip-allow` عند تنفيذ `key create` إلى رفض أي وصول عبر الشبكة**، على خلاف ما يحدث عند إنشاء خدمة. لا يُعرض السر إلا مرة واحدة. يُعيد `key list` صفحة واحدة فقط ما لم تمرّر `--all`. وعند تنفيذ `key update`، تبقى الإعدادات المرتبطة بخيارات سطر الأوامر غير المحددة على حالها، بينما تؤدي `--clear-expiry` و`--clear-roles` و`--clear-ip-allow` إلى إزالتها.

### النسخ الاحتياطية {#backups}

```bash
clickhousectl cloud backup list <service-id>
clickhousectl cloud backup get <service-id> <backup-id>
clickhousectl cloud service create --name restored-analytics \
  --provider aws --region us-east-1 --ip-allow 203.0.113.10/32 --backup-id <backup-id>
clickhousectl cloud service backup-config update <service-id> \
  --backup-period-hours 24 --backup-retention-period-hours 720
clickhousectl cloud backup bucket get <service-id>
```

تُنشئ عملية الاستعادة دائمًا خدمة جديدة. يهيّئ الأمر `cloud backup bucket` (get وcreate وupdate وdelete) حاوية نسخ احتياطي خاصة بك (bring-your-own) استنادًا إلى ملف JSON خاص بكل مزوّد. راجع قسم النسخ الاحتياطي في [دليل الخدمة السحابية](https://github.com/ClickHouse/clickhousectl/blob/main/docs/guides/cloud-service.md#back-up-and-restore).

## إخراج JSON {#json-output}

تقبل الأوامر التي تُرجع بيانات مهيكلة الخيار `--json`، ومنها الأوامر المحلية وأوامر Cloud وأوامر `skills` و`update` و`telemetry`:

```bash
clickhousectl cloud service list --json
clickhousectl cloud key list --all --json
clickhousectl local server list --json
```

عندما تكتشف واجهة سطر الأوامر وكيلَ برمجة (مثل Claude Code أو Cursor أو Codex أو Gemini CLI أو Goose أو Devin، أو أي أداة تضبط المتغير `AI_AGENT`)، فإنها تختار JSON تلقائيًا. أما عملاء SQL والعملاء الأصليون فيحتفظون بصيغهم الخاصة: إذ يُعيد `cloud service query` النتائج بصيغة `JSONEachRow` في وضع JSON، بينما يكون إخراج `local client` دائمًا بالصيغة الأصلية. لذا ينبغي للبرامج النصية التي تحلّل إخراج الاستعلامات أن تمرّر الخيار `--format` صراحةً.

في وضع JSON، تُرسَل أخطاء وقت التشغيل إلى stderr على هيئة كائن يتضمن حقل `code` ثابتًا وحقل `message`:

```json
{"error":{"code":"server_not_found","message":"The selected server was not found"}}
```

اعتمد في منطق التفرّع على `error.code` لا على نص الرسالة. أما أخطاء الاستخدام فتبقى نصية، ويكون رمز الخروج فيها 2. راجع [عقود الأتمتة والإخراج](https://github.com/ClickHouse/clickhousectl/blob/main/docs/reference/automation.md) للاطلاع على أشكال الإخراج ورموز الخطأ.

## رموز الخروج {#exit-codes}

| الرمز | المعنى                                                                            |
| ----- | --------------------------------------------------------------------------------- |
| `0`   | نجاح. في عمليات Cloud غير المتزامنة، يعني ذلك أن الطلب قد قُبل، لا أنه اكتمل      |
| `1`   | خطأ                                                                               |
| `2`   | خطأ في الاستخدام، بما في ذلك القيم غير الصالحة لخيارات سطر الأوامر                |
| `3`   | أُلغيت العملية                                                                    |
| `4`   | المصادقة مطلوبة أو مرفوضة، بما في ذلك محاولات تنفيذ عمليات الكتابة باستخدام OAuth |

تُمرِّر الأوامر `local client` و`local postgres client` وغيرها من الأوامر التي تُسلِّم التنفيذ إلى عملاء أصليين حالةَ الخروج الخاصة بالعميل نفسه كما هي.

## مهارات الوكلاء {#skills}

ثبّت حزمة [ClickHouse agent skills الرسمية](https://github.com/ClickHouse/agent-skills) في وكلاء البرمجة لديك:

```bash
clickhousectl skills                                  # Interactive: choose scope and agents
clickhousectl skills --agent claude --agent codex     # Current project
clickhousectl skills --detected-only --global         # Agents detected in your home directory
clickhousectl skills --all
```

تُثبَّت المهارات افتراضيًا في المشروع الحالي، أو في الدليل الرئيسي للمستخدم عند استخدام `--global`. ويُضمَّن الدليل المشترك `.agents/skills/` دائمًا. وفي حال عدم توفر طرفية، يجب تمرير `--agent` أو `--all` أو `--detected-only`. شغّل الأمر `clickhousectl skills --help` للاطلاع على أسماء الوكلاء المدعومين.

## التحديث الذاتي {#self-update}

```bash
clickhousectl update --check     # Check without installing
clickhousectl update             # Install the latest release
```

تتحقق واجهة سطر الأوامر أيضًا في الخلفية من توفر تحديثات، بمعدل مرة واحدة كل 24 ساعة على الأكثر، وتعرض إشعارًا عند توفر إصدار أحدث.

## بيانات القياس عن بُعد {#telemetry}

يجمع `clickhousectl` بيانات استخدام مجهولة الهوية للاسترشاد بها في التطوير. يعرض التشغيل الأول إشعارًا دون إرسال أي بيانات، ثم يبدأ الجمع اعتبارًا من التشغيل التالي ما لم تُعطِّله.

يتضمن كل حدث ما يلي:

* مسار الأمر و**أسماء** خيارات سطر الأوامر والوسائط المُمرَّرة صراحةً، دون قيمها على الإطلاق
* النتيجة ورمز الخروج
* عند الخطأ في كتابة أمر: اسم الأمر أو خيار سطر الأوامر الذي اقترحته واجهة سطر الأوامر، دون ما كتبته أنت على الإطلاق
* عند الإخفاق أثناء التشغيل: فئات محدودة تشمل مرحلة الإخفاق ونوعه، ورمز حالة HTTP مُدرجًا في قائمة السماح، إضافةً إلى فئات إعادة المحاولة وحالة التجهيز والمدة
* إصدار واجهة سطر الأوامر، ونظام التشغيل والمعمارية، وما إذا كانت تعمل ضمن CI، ووكيل البرمجة المُكتشَف

لا تُسجَّل أبدًا قيم الوسائط، ولا استعلامات SQL، ولا بيانات الاعتماد، ولا معرّفات الموارد، ولا الوسائط الواردة بعد `--`، ولا رسائل الأخطاء. كما لا يوجد أي معرّف للتثبيت أو للجهاز.

لإلغاء الاشتراك:

```bash
clickhousectl telemetry disable     # Persist the preference on this machine
clickhousectl telemetry status
export DO_NOT_TRACK=1               # Disable for an environment, overriding the saved preference
```

اضبط `CHCTL_TELEMETRY_DEBUG=1` لطباعة الحمولة إلى stderr دون إرسال أي بيانات. للمزيد، راجع [تفاصيل بيانات القياس عن بُعد](https://github.com/ClickHouse/clickhousectl/blob/main/docs/reference/telemetry.md).
