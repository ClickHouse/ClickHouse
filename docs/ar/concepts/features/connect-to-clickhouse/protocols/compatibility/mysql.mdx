يدعم ClickHouse بروتوكول الاتصال الشبكي لـ MySQL، مما يتيح لبعض العملاء التي لا تتوفر لها موصلات ClickHouse أصلية الاعتماد على بروتوكول MySQL بدلاً من ذلك. وقد جرى التحقق من صحة هذا الدعم مع أدوات ذكاء الأعمال التالية:

* [Looker Studio](/ar/integrations/connectors/data-visualization/looker-studio-and-clickhouse)
* [Tableau Online](/ar/integrations/connectors/data-visualization/tableau/tableau-online-and-clickhouse)
* [QuickSight](/ar/integrations/connectors/data-visualization/quicksight-and-clickhouse)

إذا كنت تجرّب عملاء أو تكاملات أخرى لم تُختبر بعد، فضع في اعتبارك احتمال وجود القيود التالية:

* قد لا يكون تطبيق SSL متوافقاً بالكامل، وقد تظهر مشكلات في [TLS SNI](https://www.cloudflare.com/learning/ssl/what-is-sni/).
* قد تتطلب أداة معيّنة ميزات خاصة باللهجة (مثل دوال أو إعدادات خاصة بـ MySQL) لم تُنفَّذ بعد.

إذا توفّر مشغّل أصلي (مثل [DBeaver](/ar/integrations/connectors/sql-clients/dbeaver))، فيُفضَّل دائماً استخدامه بدلاً من واجهة MySQL. كما أنه رغم أن معظم مكتبات العملاء للغات البرمجة الخاصة بـ MySQL يُفترض أن تعمل دون مشكلات، فلا يوجد ضمان بأن تكون واجهة MySQL بديلاً مباشراً لقاعدة شيفرة مصدرية تحتوي على استعلامات MySQL قائمة.

إذا كانت حالة الاستخدام لديك تتضمن أداة معيّنة لا يتوفر لها مشغّل ClickHouse أصلي، وترغب في استخدامها عبر واجهة MySQL ثم واجهت بعض حالات عدم التوافق، فيُرجى [إنشاء تذكرة](https://github.com/ClickHouse/ClickHouse/issues) في مستودع ClickHouse.

<Note>
  لتحسين دعم لهجة SQL الخاصة بأدوات ذكاء الأعمال المذكورة أعلاه، تُشغّل واجهة MySQL في ClickHouse استعلامات SELECT ضمنياً مع الإعداد [prefer&#95;column&#95;name&#95;to&#95;alias = 1](/ar/reference/settings/session-settings/prefer#prefer_column_name_to_alias).
  لا يمكن تعطيل هذا السلوك، وقد يؤدي في حالات حدّية نادرة إلى اختلاف النتائج بين الاستعلامات المُرسَلة إلى واجهة الاستعلام العادية في ClickHouse وتلك المُرسَلة إلى واجهة MySQL.
</Note>

## إنشاء عدة مستخدمي MySQL في ClickHouse Cloud {#creating-multiple-mysql-users-in-clickhouse-cloud}

افتراضيًا، يتوفر مستخدم مدمج باسم `mysql4<subdomain>` يستخدم كلمة المرور نفسها التي يستخدمها المستخدم `default`. ويمثّل الجزء `<subdomain>` المقطع الأول من اسم المضيف الخاص بـ ClickHouse Cloud. هذه الصيغة ضرورية للعمل مع الأدوات التي تدعم الاتصال الآمن لكنها لا ترسل [معلومات SNI في مصافحة TLS](https://www.cloudflare.com/learning/ssl/what-is-sni)، مما يتعذّر معه إجراء التوجيه الداخلي دون استدلال إضافي في اسم المستخدم (ومن هذه الأدوات عميل وحدة التحكم الخاص بـ MySQL).

لذلك، *نوصي بشدة* باتباع الصيغة `mysql4<subdomain>_<username>` عند إنشاء مستخدم جديد مخصّص للاستخدام مع واجهة MySQL، حيث يمثّل `<subdomain>` استدلالًا لتحديد الخدمة السحابية الخاصة بك، ويمثّل `<username>` لاحقة تختارها بحرية.

<Tip>
  بالنسبة إلى اسم مضيف ClickHouse Cloud مثل `foobar.us-east1.aws.clickhouse.cloud`، يساوي الجزء `<subdomain>` القيمة `foobar`، ويمكن أن يكون اسم مستخدم MySQL المخصص على غرار `mysql4foobar_team1`.
</Tip>

يمكنك إنشاء مستخدمين إضافيين لاستخدامهم مع واجهة MySQL إذا احتجت، على سبيل المثال، إلى تطبيق إعدادات إضافية.

1. اختياري - أنشئ [ملف تعريف الإعدادات](/ar/reference/statements/create/settings-profile) لتطبيقه على المستخدم المخصص. على سبيل المثال، `my_custom_profile` مع إعداد إضافي يُطبَّق افتراضيًا عند الاتصال بالمستخدم الذي سننشئه لاحقًا:

   ```sql
   CREATE SETTINGS PROFILE my_custom_profile SETTINGS prefer_column_name_to_alias=1;
   ```

   يُستخدم `prefer_column_name_to_alias` هنا على سبيل المثال فقط، ويمكنك استخدام إعدادات أخرى بدلًا منه.

2. [أنشئ مستخدمًا](/ar/reference/statements/create/user) بالصيغة التالية: `mysql4<subdomain>_<username>` ([انظر أعلاه](#creating-multiple-mysql-users-in-clickhouse-cloud)). يجب أن تكون كلمة المرور بصيغة تجزئة SHA1 المزدوجة. على سبيل المثال:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$';
   ```

   أو إذا أردت استخدام ملف تعريف مخصص لهذا المستخدم:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$' SETTINGS PROFILE 'my_custom_profile';
   ```

   حيث `my_custom_profile` هو اسم ملف التعريف الذي أنشأته سابقًا.

3. [امنح](/ar/reference/statements/grant) المستخدم الجديد الصلاحيات اللازمة للتعامل مع الجداول أو قواعد البيانات المطلوبة. على سبيل المثال، إذا أردت منح الوصول إلى `system.query_log` فقط:

   ```sql
   GRANT SELECT ON system.query_log TO mysql4foobar_team1;
   ```

4. استخدم المستخدم الذي أنشأته للاتصال بخدمة ClickHouse Cloud الخاصة بك عبر واجهة MySQL.

### استكشاف الأخطاء وإصلاحها عند استخدام عدة مستخدمين لـ MySQL في ClickHouse Cloud {#troubleshooting-multiple-mysql-users-in-clickhouse-cloud}

إذا أنشأت مستخدم MySQL جديدًا وظهر لك الـ error التالي عند الاتصال عبر عميل واجهة سطر الأوامر لـ MySQL:

```sql
ERROR 2013 (HY000): Lost connection to MySQL server at 'reading authorization packet', system error: 54
```

في هذه الحالة، تأكد من أن اسم المستخدم يتبع الصيغة `mysql4<subdomain>_<username>`، كما هو موضح ([أعلاه](#creating-multiple-mysql-users-in-clickhouse-cloud)).

## تفعيل واجهة MySQL على ClickHouse مُدار ذاتيًا {#enabling-the-mysql-interface-on-self-managed-clickhouse}

أضف الإعداد [mysql&#95;port](/ar/reference/settings/server-settings/settings/mysql#mysql_port) إلى ملف التهيئة الخاص بالخادم. على سبيل المثال، يمكنك تعريف المنفذ في ملف XML جديد داخل [مجلد](/ar/concepts/features/configuration/server-config/configuration-files) `config.d/`:

```xml
<clickhouse>
    <mysql_port>9004</mysql_port>
</clickhouse>
```

شغّل خادم ClickHouse وابحث عن رسالة في السجل مشابهة لما يلي تتضمن العبارة Listening for MySQL compatibility protocol:

```bash
{} <Information> Application: Listening for MySQL compatibility protocol: 127.0.0.1:9004
```

## ربط MySQL بـ ClickHouse {#connect-mysql-to-clickhouse}

يوضح الأمر التالي كيفية توصيل عميل MySQL `mysql` بـ ClickHouse:

```bash
mysql --protocol tcp -h [hostname] -u [username] -P [port_number] [database_name]
```

على سبيل المثال:

```bash
$ mysql --protocol tcp -h 127.0.0.1 -u default -P 9004 default
```

الإخراج عند نجاح الاتصال:

```text
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 4
Server version: 20.2.1.1-ClickHouse

Copyright (c) 2000, 2019, Oracle and/or its affiliates. All rights reserved.

Oracle is a registered trademark of Oracle Corporation and/or its
affiliates. Other names may be trademarks of their respective
owners.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>
```

لضمان التوافق مع جميع عملاء MySQL، يُوصى بتحديد كلمة مرور المستخدم باستخدام [تجزئة SHA1 المزدوجة](/ar/concepts/features/configuration/settings/settings-users#user-namepassword) في ملف التهيئة.
أما إذا حُدِّدت كلمة مرور المستخدم باستخدام [SHA256](/ar/reference/functions/regular-functions/hash-functions#SHA256)، فلن يتمكن بعض العملاء من التحقق من الهوية (مثل mysqljs والإصدارات القديمة من أداتَي سطر الأوامر MySQL وMariaDB).

القيود:

* الاستعلامات المُعدّة مسبقًا (prepared queries) غير مدعومة

* تُرسَل بعض أنواع البيانات على هيئة سلاسل نصية

لإلغاء استعلام يستغرق وقتًا طويلًا، استخدم العبارة `KILL QUERY connection_id` (تُستبدَل أثناء التنفيذ بالعبارة `KILL QUERY WHERE query_id = connection_id`). على سبيل المثال:

```bash
$ mysql --protocol tcp -h mysql_server -P 9004 default -u default --password=123 -e "KILL QUERY 123456;"
```
