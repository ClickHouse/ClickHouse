<div id="description">
  ## الوصف
</div>

يعرض للمستخدم الحالي سجلات استعلاماته في سجل الاستعلامات. يقرأ جدول سجل الاستعلامات المُعدّ عبر إعدادَي الخادم `query_log.database` و`query_log.table` (وهو `system.query_log` افتراضيًا)، ولا يعيد إلا الصفوف التي يطابق فيها المستخدم الذي بدأ الاستعلام `currentUser()` (يُؤخذ هذا المستخدم من `initial_user` إذا كان مُعيَّنًا، وإلا فمن `user`).

على خلاف جدول سجل الاستعلامات نفسه، يمكن قراءة `system.user_query_log` دون أي صلاحيات، ما يتيح للمستخدمين فحص استعلاماتهم الخاصة دون منحهم إمكانية الوصول إلى استعلامات الآخرين.

لا يُدعم ذلك إلا إذا كان سجل الاستعلامات مخزنًا محليًا. إذا جرى إعداد `query_log.engine` كـ `Distributed` أو أي محرك آخر يفوّض عمليات القراءة إلى خادم آخر، يرفض `system.user_query_log` القراءة منه ويطرح استثناءً، إذ لا يمكن فرض فحص الوصول المطلوب عبر حدود خادم يستخدم بروتوكول ClickHouse. في هذه الحالة، عطّل الجدول باستخدام `query_log.enable_user_query_log = 0`.

يمكن تعطيل الجدول عبر إعداد الخادم `query_log.enable_user_query_log`. إذا لم يُعدّ سجل الاستعلامات أو لم يُنشأ جدوله بعد، يكون `system.user_query_log` فارغًا.

تُمرَّر شروط أعمدة التقسيم والمفتاح في سجل الاستعلامات (`event_date` و`event_time` و`query_start_time` و`query_id` و`type` والأعمدة القياسية المشابهة) التي تُقارن بثوابت إلى جدول سجل الاستعلامات الأساسي، لذا تحافظ عمليات البحث العادية، مثل المثال أدناه، على استبعاد الأقسام ولا تفحص السجل المحتفَظ به بالكامل.

<Warning>
  إذا كان هناك جدول باسم `system.user_query_log` أُنشئ قبل الترقية إلى إصدار من ClickHouse يوفّر هذا الجدول، فلن يبدأ الخادم حتى تتم إعادة تسمية الجدول الحالي أو حذفه، أو تعيين `query_log.enable_user_query_log` إلى `0`.
</Warning>
