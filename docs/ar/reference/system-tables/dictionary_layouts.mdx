<div id="description">
  ## الوصف
</div>

يحتوي على قائمة بأنماط تخطيط القواميس التي يدعمها الخادم، إلى جانب الوثائق المضمّنة لكل نمط. يحدّد نمط تخطيط القاموس كيفية تخزين القاموس في الذاكرة (أو على القرص) وكيفية البحث فيه؛ ويُحدَّد في بند `LAYOUT` ضمن استعلام `CREATE DICTIONARY`.

<div id="columns">
  ## الأعمدة
</div>

{/*AUTOGENERATED_START*/}

* `name` ([String](/ar/reference/data-types/string)) — اسم تخطيط القاموس، كما هو محدد في بند `LAYOUT`.
* `is_complex` ([UInt8](/ar/reference/data-types/int-uint)) — ما إذا كان التخطيط يتطلب مفتاحًا مركبًا (مفتاحًا يتكون من عدة سمات أو من نوع غير صحيح).
* `description` ([String](/ar/reference/data-types/string)) — وصف لوظيفة تخطيط القاموس. بالنسبة إلى التخطيطات التي لها صفحة توثيق مخصصة، يحتوي هذا الحقل على كامل نص Markdown لتلك الصفحة؛ أما التخطيطات المتبقية، فيحتوي على ملخص موجز.
* `syntax` ([String](/ar/reference/data-types/string)) — كيفية تحديد التخطيط في بند `LAYOUT` ضمن استعلام CREATE DICTIONARY.
* `examples` ([String](/ar/reference/data-types/string)) — أمثلة على الاستخدام.
* `introduced_in` ([String](/ar/reference/data-types/string)) — إصدار ClickHouse الذي قُدِّم فيه التخطيط لأول مرة، بصيغة major.minor.
* `related` ([Array(String)](/ar/reference/data-types/array)) — أسماء تخطيطات القاموس ذات الصلة.

{/*AUTOGENERATED_END*/}

<div id="example">
  ## مثال
</div>

```sql title="Query"
SELECT name, is_complex, syntax
FROM system.dictionary_layouts
WHERE name IN ('flat', 'hashed', 'complex_key_hashed')
ORDER BY name
```

```text title="Response"
┌─name───────────────┬─is_complex─┬─syntax───────────────────────────────────────────────────┐
│ complex_key_hashed │          1 │ LAYOUT(COMPLEX_KEY_HASHED())                             │
│ flat               │          0 │ LAYOUT(FLAT([INITIAL_ARRAY_SIZE n] [MAX_ARRAY_SIZE n]))  │
│ hashed             │          0 │ LAYOUT(HASHED())                                         │
└────────────────────┴────────────┴──────────────────────────────────────────────────────────┘
```
