تتيح هذه الدالة تنفيذ استعلامات `SELECT` على مستندات فهرس في [Elasticsearch](https://www.elastic.co/elasticsearch). يُعاد كل مستند على هيئة صف واحد، إذ يُعرض الحقل `_source` الخاص به في عمود واحد من النوع [JSON](/ar/reference/data-types/newjson)، في حين يتوفر معرّف المستند واسم الفهرس في صورة أعمدة افتراضية. هذه الدالة للقراءة فقط.

## الصيغة {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  تكامل Elasticsearch ميزة تجريبية. يمكنك تمكينه عبر الإعداد [`enable_elasticsearch`](/ar/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## الوسائط {#arguments}

| الوسيطة        | الوصف                                                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | عنوان URL الأساسي لعنقود Elasticsearch، مثل `https://localhost:9200`. يجب أن يكون عنوان URL من نوع `http` أو `https` دون بيانات اعتماد أو سلسلة استعلام أو جزء.                                                                                   |
| `index`        | الفهرس المراد قراءته. ويمكن أن يكون أيضًا اسمًا مستعارًا، أو قائمة مفصولة بفواصل، أو نمطًا يتضمن أحرف بدل، وفقًا لما تقبله واجهة برمجة تطبيقات النقطة الزمنية (point in time) في Elasticsearch. ويُعدّ النمط الذي لا يطابق أي فهرس خطأً.          |
| `user`         | اسم المستخدم للمصادقة الأساسية عبر HTTP (اختياري).                                                                                                                                                                                                |
| `password`     | كلمة المرور للمصادقة الأساسية عبر HTTP (اختياري، ويتطلب `user`).                                                                                                                                                                                  |
| `query('...')` | كائن [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) خاص بـ Elasticsearch بصيغة JSON يحدد المستندات المراد قراءتها (اختياري). ويجب أن يأتي بعد الوسائط الموضعية. القيمة الافتراضية: `{"match_all": {}}`. |

يمكن أيضًا تمرير الوسائط `url` و`index` و`user` و`password` بالصيغة `key = value`؛ إذ تملأ الوسائط الموضعية هذه الخانات بهذا الترتيب، ويُعدّ تحديد الوسيطة موضعيًا وكمفتاح في آنٍ واحد (أو تحديد المفتاح نفسه مرتين) خطأً.

يمكن تحديد الوسائط التالية بالصيغة `key = value` (أو كمفاتيح لمجموعة مسمّاة):

| المفتاح        | الوصف                                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | اسم المستخدم للمصادقة الأساسية عبر HTTP.                                                                                                                                                    |
| `password`     | كلمة المرور للمصادقة الأساسية عبر HTTP.                                                                                                                                                     |
| `bearer_token` | رمز يُرسَل بالشكل `Authorization: Bearer <token>`، مثل رمز حساب خدمة في Elasticsearch.                                                                                                      |
| `api_key`      | مفتاح API خاص بـ Elasticsearch، يُرسَل بالشكل `Authorization: ApiKey <api_key>`. وقيمته هي السلسلة `id:api_key` المُرمَّزة بترميز base64 التي تُعيدها واجهة برمجة تطبيقات إنشاء مفاتيح API. |

يمكن أن تحتوي المجموعة المسمّاة على المفتاح `query`. ولتجاوز قيمته، مرِّر `query('...')` أو `query = '...'` بعد اسم المجموعة.

علاوة على ذلك، تقبل دالة الجدول ما يلي:

| المفتاح     | الوصف                                                                                                                                                                      |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `structure` | بنية الجدول بالصيغة `'name JSON'`. يجب أن تحتوي البنية على عمود واحد فقط من النوع `JSON`، علمًا بأن الاسمين `_id` و`_index` محجوزان. القيمة الافتراضية: `'document JSON'`. |

يمكن تمرير إعدادَي القراءة `keep_alive` و`page_size` في عبارة `SETTINGS` تُضاف في نهاية الاستعلام؛ راجع [محرك الجدول `Elasticsearch`](/ar/reference/engines/table-engines/integrations/elasticsearch#creating-a-table) للاطلاع على وصفهما.

## المصادقة {#authentication}

لا يمكن تحديد أكثر من طريقة مصادقة واحدة:

1. **المصادقة الأساسية**. مرّر `user` و`password`.
2. **رمز حامل**. مرّر `bearer_token`.
3. **مفتاح API**. مرّر `api_key`.

إذا لم تُحدَّد أيٌّ منها، يُرسَل الطلب دون مصادقة، وهذا لا ينجح إلا إذا كان الأمان معطّلًا في Elasticsearch.

خزّن بيانات الاعتماد في [مجموعة مسمّاة](/ar/concepts/features/configuration/server-config/named-collections) حتى لا تضطر إلى تحديدها في كل استعلام. يُسجَّل أي جدول دائم يُنشأ من مجموعة مسمّاة (باستخدام محرك الجدول `Elasticsearch` أو `CREATE TABLE ... AS elasticsearch(...)`) كتبعيةٍ لتلك المجموعة، ولذلك يُمنَع تنفيذ `DROP NAMED COLLECTION` ما دام الجدول موجودًا.

## الأعمدة الافتراضية {#virtual-columns}

* `_id` — معرّف المستند. النوع: `String`.
* `_index` — اسم الفهرس الذي قُرئ منه المستند. النوع: `LowCardinality(String)`.

عندما يقرأ الاستعلام الأعمدة الافتراضية فقط، لا يُطلب الحقل `_source` الخاص بالمستند من Elasticsearch. أما الفهرس الذي لا يخزّن `_source` (أي الذي يكون فيه الحقل `_source` معطّلًا في المطابقة الخاصة به)، فلا يمكن قراءته إلا عبر الأعمدة الافتراضية؛ إذ يفشل أي استعلام يقرأ عمود `JSON` من فهرس كهذا ويُرجع error بدلًا من إرجاع مستندات فارغة.

## أمثلة {#examples}

حساب عدد المستندات في فهرس:

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

اقرأ حقول المستندات بوصفها أعمدة فرعية في عمود `JSON`:

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

طبّق التصفية من جهة Elasticsearch باستخدام كائن Query DSL، واضبط حجم الصفحة:

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

استخدام مجموعة مسمّاة:

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## القيود {#limitations}

* الدالة للقراءة فقط؛ ولا تدعم `INSERT`.
* لا تُدفع المسندات إلى مستوى أدنى، إذ يُطبَّق شرط `WHERE` في ClickHouse بعد تنزيل المستندات؛ لذا استخدم الوسيطة `query` لإجراء التصفية على جانب Elasticsearch.
* يُرسَل `query` مع قيمة `size` الخاصة بالصفحة. لذا فإن أي استعلام تعتمد نتيجته على `size`، مثل استعلام `knn` بدون `k`، يُعيد مجموعة من المستندات تتوقف على `page_size`. لذلك حدّد مثل هذه المعلمات صراحةً.
* كل صفحة هي طلب بحث مستقل، ويُعيد Elasticsearch تقييم تعبيرات حساب التواريخ مثل `now-1h` في `query` مع كل طلب. فالنقطة الزمنية تُجمّد المستندات لكنها لا تُجمّد الساعة، ولذا قد يتخطى `query` المعتمد على الوقت مستندات قريبة من الحدود المتحركة دون أي تنبيه. استخدم تواريخ مطلقة في `query`.
* تفتح كل عملية قراءة نقطة زمنية، وتتنقل عبر النتائج صفحةً تلو الأخرى باستخدام `search_after` مرتّبةً حسب `_shard_doc`، ثم تُغلق النقطة الزمنية في النهاية. وإذا فشل طلب صفحة على أي مقطع، أو انتهت مهلته في Elasticsearch، فإنه يُثير error بدلًا من إعادة نتائج جزئية.
* يلزم استخدام Elasticsearch 7.12 أو أحدث، إذ تعتمد الدالة على واجهة برمجة تطبيقات النقطة الزمنية وعلى حقل الفرز `_shard_doc`؛ لذا ترفض الإصدارات الأقدم وOpenSearch الطلب الأول.
* لا يمكن أن تتجاوز قيمة `page_size` إعداد الفهرس `index.max_result_window` في Elasticsearch (القيمة الافتراضية `10000`).
