<div id="default_password_type">
  ## default_password_type
</div>

يحدّد نوع كلمة المرور الذي يُعيَّن تلقائيًا في استعلامات مثل `CREATE USER u IDENTIFIED BY 'p'`.

القيم المقبولة هي:

* `plaintext_password`

* `sha256_password`

* `double_sha1_password`

* `bcrypt_password`

* **الافتراضي:** `sha256_password`

```xml
<default_password_type>sha256_password</default_password_type>
```

<div id="default_profile">
  ## default_profile
</div>

ملف تعريف الإعدادات default. توجد ملفات تعريف الإعدادات في الملف المحدد في الإعداد `user_config`.

* **الافتراضي:** `default`

**مثال**

```xml
<default_profile>default</default_profile>
```

مهلة انتهاء الجلسة الافتراضية، بالثواني.

<div id="default_session_user">
  ## default_session_user
</div>

<SettingsInfoBlock type="String" default_value="default" changeable_without_restart="No" />

اسم المستخدم المستخدم للمصادقة عند اتصال عميل من دون تحديد اسم مستخدم: طلب HTTP من دون المعلَمة `user` والترويسة `X-ClickHouse-User`، أو حزمة `Hello` للبروتوكول الأصلي باسم مستخدم فارغ، أو مصافحة MySQL أو PostgreSQL باسم مستخدم فارغ، أو استعلام gRPC من دون `user_name`، أو استدعاء Arrow Flight من دون ترويسة `authorization` (أو ببيانات اعتماد Basic باسم مستخدم فارغ)، أو رسالة WebSocket `auth` في [الطرفية على الويب](/ar/concepts/features/interfaces/web-terminal) يكون فيها الحقل `user` محذوفًا أو فارغًا.

يُحوَّل اسم المستخدم الفارغ إلى هذه القيمة قبل المصادقة، لذا يظل الاتصال خاضعًا لمصادقة المستخدم البديل: تُطبَّق كلمة المرور وفحوصات الشبكة والوصول الأخرى كالمعتاد. اسم المستخدم الفارغ ليس سوى اسم مستعار لاسم المستخدم المُهيأ، وقبوله لا يمنح أي صلاحية وصول إضافية على ما يمنحه تحديد اسم المستخدم نفسه صراحةً. في الإصدارات السابقة لإضافة هذا الإعداد، كان الرجوع من اسم مستخدم فارغ إلى `default` متاحًا فقط عبر مسار معلَمة استعلام HTTP العادي، واستعلامات gRPC، واستدعاءات Arrow Flight، والطرفية على الويب، بينما كانت البروتوكولات الأصلية وMySQL وPostgreSQL ترفض اسم المستخدم الفارغ؛ أما الآن فجميعها تقبله. كذلك، كانت مصادقة HTTP Basic باسم مستخدم فارغ والطلبات التي تحتوي على `X-ClickHouse-Key` من دون `X-ClickHouse-User` ترفض اسم المستخدم الفارغ قبل إضافة هذا الإعداد.

إذا ضُبط على سلسلة فارغة، تُرفض الاتصالات التي لا تحدد اسم مستخدم. تُصادِق معالجات HTTP ذات المستخدم الثابت (المفتاح `user` داخل `handler` في قاعدة `http_handlers`، أو المفتاح `user` داخل `handler` في قاعدة `prometheus.handlers`) باستخدام مستخدمها المُهيأ، ولا تتأثر بهذا الإعداد.

عندما يكون قسم `session_log` مُمكّنًا في تهيئة الخادم، يُسجَّل كل رفض من هذا النوع في [`system.session_log`](/ar/reference/system-tables/session_log) كحدث `LoginFailure` ذي `user` فارغ، بحيث يمكن تدقيق الاتصالات المحظورة التي لا تحدد اسم مستخدم عبر كل واجهة.

لا يُطبَّق مستخدم الجلسة الافتراضي مطلقًا على الاتصالات بين الخوادم: إذ تعرّف عن نفسها بعلامة خاصة بدلًا من اسم المستخدم، وتُصادَق باستخدام secret الخاص بالـ cluster والمستخدم الأولي.

يمكن تجاوز القيمة لنقطة نهاية محددة ضمن بروتوكول قابل للتركيب باستخدام المفتاح `default_session_user` في قسم `protocols`، راجع [البروتوكولات القابلة للتركيب](/ar/concepts/features/configuration/server-config/composable-protocols).
