## insert_allow_materialized_columns {#insert_allow_materialized_columns}

<SettingsInfoBlock type="Bool" default_value="0" />

إذا كان هذا الإعداد مفعّلًا، فيمكن ذكر أعمدة `MATERIALIZED` في قائمة الأعمدة ضمن استعلام `INSERT`، وتُخزَّن القيم المُدرَجة (INSERTed) كما هي بدلًا من حسابها من تعبيرات الأعمدة. وفي جداول `Distributed`، تُرسَل قيم أعمدة `MATERIALIZED` كذلك إلى المقاطع.

أما إذا كان معطّلًا، فإن ذكر عمود `MATERIALIZED` في استعلام `INSERT` يُطلق استثناءً، وتُحسب قيم هذه الأعمدة دائمًا من تعبيراتها.

## insert_deduplicate {#insert_deduplicate}

<SettingsInfoBlock type="Bool" default_value="1" />

يُفعّل أو يعطّل إزالة التكرار للكتل لأمر `INSERT` (في جداول Replicated*).

لا يسري هذا الإعداد إلا عند ضبط [`deduplicate_insert`](/ar/reference/settings/session-settings/deduplicate-insert#deduplicate_insert) على `backward_compatible_choice`.

القيم الممكنة:

* 0 — معطّل.
* 1 — مفعّل.

افتراضيًا، تُزال تكرارات الكتل المُدرجة في الجداول المكررة بواسطة تعليمة `INSERT` (راجع [تكرار البيانات](/ar/reference/engines/table-engines/mergetree-family/replication)).
وبالنسبة إلى الجداول المكررة، تُزال افتراضيًا تكرارات أحدث 100 كتلة فقط لكل partition (راجع [replicated&#95;deduplication&#95;window](/ar/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window)، [replicated&#95;deduplication&#95;window&#95;seconds](/ar/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window_seconds)).
أما الجداول غير المكررة، فراجع [non&#95;replicated&#95;deduplication&#95;window](/ar/reference/settings/merge-tree-settings/other#non_replicated_deduplication_window).

## insert_deduplication_token {#insert_deduplication_token}

يتيح هذا الإعداد للمستخدم تحديد آلية إزالة التكرار الخاصة به في MergeTree/ReplicatedMergeTree.
فعلى سبيل المثال، من خلال تقديم قيمة unique لهذا الإعداد في كل تعليمة INSERT،
يمكن للمستخدم تجنّب إزالة تكرار البيانات inserted نفسها.

القيم الممكنة:

* أي String

يُستخدم `insert_deduplication_token` في إزالة التكرار *فقط* عندما لا تكون قيمته فارغة.

بالنسبة إلى الجداول المكررة، افتراضيًا لا تتم إزالة التكرار إلا لأحدث 100 عملية inserts لكل partition (راجع [replicated&#95;deduplication&#95;window](/ar/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window)، [replicated&#95;deduplication&#95;window&#95;seconds](/ar/reference/settings/merge-tree-settings/replicated-deduplication-window#replicated_deduplication_window_seconds)).
أما الجداول غير المكررة، فراجع [non&#95;replicated&#95;deduplication&#95;window](/ar/reference/settings/merge-tree-settings/other#non_replicated_deduplication_window).

<Note>
  يتم تتبّع `insert_deduplication_token` لكل partition، لذا يمكن لعدة partitions مكتوبة بعملية insert واحدة أن تحمل token نفسه. ومن دون token، يُحتسب checksum الافتراضي للمحتوى على مستوى block inserted بالكامل، لذلك لا تُزال تكرارات عملية insert إلا عندما تتطابق بياناتها بالكامل مع insert سابقة (retry)، وليس عندما تتطابق rows الخاصة بـ partition واحدة فقط مصادفةً مع insert مختلفة.
</Note>

مثال:

```sql
CREATE TABLE test_table
( A Int64 )
ENGINE = MergeTree
ORDER BY A
SETTINGS non_replicated_deduplication_window = 100;

INSERT INTO test_table SETTINGS insert_deduplication_token = 'test' VALUES (1);

-- the next insert won't be deduplicated because insert_deduplication_token is different
INSERT INTO test_table SETTINGS insert_deduplication_token = 'test1' VALUES (1);

-- the next insert will be deduplicated because insert_deduplication_token
-- is the same as one of the previous
INSERT INTO test_table SETTINGS insert_deduplication_token = 'test' VALUES (2);

SELECT * FROM test_table

┌─A─┐
│ 1 │
└───┘
┌─A─┐
│ 1 │
└───┘
```

## insert_null_as_default {#insert_null_as_default}

<SettingsInfoBlock type="Bool" default_value="1" />

يتيح إدراج [القيم الافتراضية](/ar/reference/statements/create/table#default_values) بدلًا من [NULL](/ar/reference/syntax#null) في الأعمدة ذات نوع البيانات غير [Nullable](/ar/reference/data-types/nullable)، أو يعطّله.
إذا كان نوع العمود غير Nullable وكان هذا الإعداد معطّلًا، فإن إدراج `NULL` يؤدي إلى حدوث استثناء. أما إذا كان نوع العمود Nullable، فتُدرج قيم `NULL` كما هي بغضّ النظر عن هذا الإعداد.

ينطبق هذا الإعداد على استعلامات [INSERT ... SELECT](/ar/reference/statements/insert-into#inserting-the-results-of-select). لاحظ أن الاستعلامات الفرعية `SELECT` يمكن ربطها بعبارة `UNION ALL`.

القيم الممكنة:

* 0 — يؤدي إدراج `NULL` في عمود غير Nullable إلى حدوث استثناء.
* 1 — تُدرج القيمة الافتراضية للعمود بدلًا من `NULL`.

## insert_shard_id {#insert_shard_id}

<SettingsInfoBlock type="UInt64" default_value="0" />

إذا لم تكن القيمة `0`، فإنها تحدد الشظية من جدول [Distributed](/ar/reference/engines/table-engines/special/distributed) التي ستُدرج (INSERTed) فيها البيانات بشكل متزامن.

إذا كانت قيمة `insert_shard_id` غير صحيحة، فسيطرح الخادم استثناءً.

لمعرفة عدد الشظايا في `requested_cluster`، يمكنك التحقق من إعدادات الخادم أو استخدام هذا الاستعلام:

```sql
SELECT uniq(shard_num) FROM system.clusters WHERE cluster = 'requested_cluster';
```

القيم الممكنة:

* 0 — معطّل.
* أي رقم من `1` إلى `shards_num` للجدول [Distributed](/ar/reference/engines/table-engines/special/distributed) المقابل.

**مثال**

الاستعلام:

```sql
CREATE TABLE x AS system.numbers ENGINE = MergeTree ORDER BY number;
CREATE TABLE x_dist AS x ENGINE = Distributed('test_cluster_two_shards_localhost', currentDatabase(), x);
INSERT INTO x_dist SELECT * FROM numbers(5) SETTINGS insert_shard_id = 1;
SELECT * FROM x_dist ORDER BY number ASC;
```

النتيجة:

```text
┌─number─┐
│      0 │
│      0 │
│      1 │
│      1 │
│      2 │
│      2 │
│      3 │
│      3 │
│      4 │
│      4 │
└────────┘
```

## insert_squashing_max_memory_ratio {#insert_squashing_max_memory_ratio}

<SettingsInfoBlock type="Double" default_value="0.1125" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0.1125"},{"label": "إعداد جديد. كان الحد الأعلى لـ `min_insert_block_size_bytes` المستند إلى الحد الأقصى للذاكرة مُثبّتًا في الشيفرة بقيمة 0.9 \/ 8 من هذا الحد؛ وأصبح الآن قابلًا للضبط."}]}]} />

يُقيّد `min_insert_block_size_bytes` بهذه النسبة من الحد الأقصى لذاكرة الخادم (`max_server_memory_usage`)
في مراحل الدمج ضمن عملية `INSERT`، وهي: الدمج الخاص بجدول الهدف، ودمج نتائج
العروض المُجسَّدة التابعة، وحجم الكتلة لمصدر عملية `INSERT ... SELECT` البسيطة.

لا تحتفظ مرحلة الدمج بكتلة واحدة بحجم `min_insert_block_size_bytes` بل بعدة كتل: فهي تُراكِم
الكتلة التالية أثناء ضمّ الكتلة السابقة، وتبقى الكتلة المضمومة قائمة في وجهة البيانات، كما تُقاس الكتل
بحجمها المنطقي في حين تُقرِّب المصفوفات المخزِّنة لها سعتَها إلى الأعلى. لذلك قد يؤدي هذا على خادم ذي
ذاكرة محدودة إلى فشل عملية `INSERT` بالخطأ `MEMORY_LIMIT_EXCEEDED`. ومع القيمة الافتراضية لـ
`min_insert_block_size_bytes`، لا يصبح للقيمة الافتراضية لهذا الإعداد أثرٌ مُقيِّد إلا عندما يقل الحد الأقصى للذاكرة عن 2.2 GiB تقريبًا؛ أما
القيمة الأقل مثل `0.0625` فتساعد عملية `INSERT` في جدول عريض على البقاء ضمن حدود ذاكرة خادم صغير.

يعتمد هذا الحد الأعلى على الحد الأقصى للذاكرة وعلى هذا الإعداد فقط، لا على عدد العروض المُجسَّدة أو
تدفقات الإدراج. لاحظ أن الحد الأقصى للذاكرة قد يتغير في أثناء التشغيل (راجع `memory_worker_dynamic_hard_limit`)،
وعندما يصبح هذا الحد مُقيِّدًا، فقد تُقسَّم عملية `INSERT` التي أُعيدت محاولتها إلى كتل على نحو مختلف عن المحاولة الأولى.

القيم الممكنة: من `0` إلى `1`. اضبطه على `0` لتعطيل هذا الحد.
