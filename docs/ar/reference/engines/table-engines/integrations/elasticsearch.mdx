يتيح محرك `Elasticsearch` قراءة المستندات من فهرس في [Elasticsearch](https://www.elastic.co/elasticsearch). يُعاد كل مستند في صورة صف واحد، إذ يُعرض الحقل `_source` الخاص به كعمود واحد من النوع [JSON](/ar/reference/data-types/newjson)، بينما يتوفر معرّف المستند واسم الفهرس كأعمدة افتراضية.

هذا المحرك للقراءة فقط. تُجلب المستندات على صفحات عبر واجهة برمجة التطبيقات `_search`، باستخدام [نقطة زمنية](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results#search-after) تضمن أن يرى الاستعلام لقطة متسقة من الفهرس حتى أثناء تعديله.

يتطلب المحرك الإصدار 7.12 من Elasticsearch أو أحدث، لأنه يعتمد على واجهة برمجة تطبيقات النقطة الزمنية وعلى حقل الفرز `_shard_doc`. أما OpenSearch فغير مدعوم، لأنه لا يحتوي على الحقل `_shard_doc`. وإذا كان الخادم أقدم من ذلك، فسيرفض الطلب الأول ويُرجع خطأً.

## إنشاء جدول {#creating-a-table}

```sql
CREATE TABLE [IF NOT EXISTS] [db.]table_name
[(
    name1 JSON
)]
ENGINE = Elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...])
[SETTINGS keep_alive = 60, page_size = 10000]
```

<Note>
  تكامل Elasticsearch تجريبي. يمكنك تمكينه باستخدام الإعداد [`enable_elasticsearch`](/ar/reference/settings/session-settings/enable#enable_elasticsearch):

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

قائمة الأعمدة اختيارية. فعند حذفها، يحتوي الجدول على عمود واحد هو `document` من النوع `JSON`. أما عند تحديدها، فيجب أن تحتوي على عمود واحد فقط من النوع `JSON`، مع إمكانية إضافة تلميحات النوع ومسارات التخطي. الأعمدة من نوع `MATERIALIZED` و`ALIAS` و`EPHEMERAL` غير مدعومة، والاسمان `_id` و`_index` محجوزان للأعمدة الافتراضية.

**معلمات المحرك**

* `url` — عنوان URL الأساسي لعنقود Elasticsearch، مثل `https://localhost:9200`. يجب أن يكون عنوان URL من نوع `http` أو `https` دون بيانات اعتماد أو سلسلة استعلام أو جزء (fragment).
* `index` — الفهرس المراد قراءته. ويمكن أن يكون أيضًا اسمًا بديلًا، أو تدفق بيانات، أو قائمة مفصولة بفواصل، أو نمطًا يتضمن محارف بدل، أو تعبيرًا للعمليات الحسابية على التواريخ مثل `<logs-{now/d}>`، وفقًا لما تقبله واجهة برمجة النقطة الزمنية (point in time API) في Elasticsearch. القيمة هي الاسم الحرفي ويجب ألا تكون مرمّزة وفق URL. ويُعدّ النمط الذي لا يطابق أي فهرس خطأً.
* `user`، `password` — بيانات اعتماد اختيارية للمصادقة الأساسية عبر HTTP.
* `query('...')` — كائن اختياري بصيغة JSON من [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) في Elasticsearch يحدد المستندات المراد قراءتها. ويجب أن يأتي بعد الوسائط الموضعية. القيمة الافتراضية: `{"match_all": {}}`.

يمكن أيضًا تمرير المعلمات على هيئة [مجموعة مسمّاة](/ar/concepts/features/configuration/server-config/named-collections) مع تجاوزات بصيغة `key = value`. راجع [دالة الجدول `elasticsearch`](/ar/reference/functions/table-functions/elasticsearch#arguments) للاطلاع على القائمة الكاملة للمفاتيح ووصف [طرق المصادقة](/ar/reference/functions/table-functions/elasticsearch#authentication).

**إعدادات المحرك**

| الإعداد      | القيمة الافتراضية | الوصف                                                                                                                                                                                                                                                                                                                                               |
| ------------ | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keep_alive` | `60`              | المدة بالثواني التي يُبقي فيها Elasticsearch النقطة الزمنية مفتوحة بين طلبين متتاليين للصفحات.                                                                                                                                                                                                                                                      |
| `page_size`  | `10000`           | عدد المستندات المطلوبة من Elasticsearch في كل طلب. تتحول كل صفحة إلى كتلة واحدة، لذا يحدد هذا الإعداد أيضًا حجم الكتلة عند القراءة، ولا يكون للإعداد [`max_block_size`](/ar/reference/settings/session-settings/max#max_block_size) أي تأثير. يرفض Elasticsearch القيم التي تتجاوز إعداد الفهرس `index.max_result_window` (القيمة الافتراضية `10000`). |

لا يمكن تغيير هذه الإعدادات باستخدام `ALTER TABLE ... MODIFY SETTING`، ولتغييرها يجب إعادة إنشاء الجدول.

## الأعمدة الافتراضية {#virtual-columns}

* `_id` — معرّف المستند. النوع: `String`.
* `_index` — اسم الفهرس الذي قُرئ منه المستند. النوع: `LowCardinality(String)`.

عندما يقرأ الاستعلام الأعمدة الافتراضية فقط، لا يُطلب الحقل `_source` الخاص بالمستند من Elasticsearch. أما الفهرس الذي لا يخزّن `_source` (أي الذي يكون فيه الحقل `_source` معطّلًا في الـ mapping الخاص به)، فلا يمكن قراءته إلا عبر الأعمدة الافتراضية؛ إذ يفشل أي استعلام يقرأ عمود `JSON` من مثل هذا الفهرس ويُرجع error بدلًا من إرجاع مستندات فارغة.

## مثال على الاستخدام {#usage-example}

```sql
CREATE TABLE logs
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*', 'elastic', 'changeme')
SETTINGS page_size = 5000;

SELECT _index, _id, document.message
FROM logs
WHERE document.level = 'error'
LIMIT 10;
```

صفِّ البيانات من جهة Elasticsearch باستخدام كائن Query DSL:

```sql
CREATE TABLE errors_since_october
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*',
                       query('{"bool": {"filter": [{"term": {"level": "error"}}, {"range": {"@timestamp": {"gte": "2026-10-01T00:00:00Z"}}}]}}'),
                       api_key = '...');
```

استخدم تواريخ مطلقة في `query`: إذ يُعاد تقييم العمليات الحسابية على التواريخ مثل `now-1h` مع كل صفحة، مما قد يؤدي إلى تخطي بعض المستندات. راجع [قيود دالة الجدول `elasticsearch`](/ar/reference/functions/table-functions/elasticsearch#limitations).
