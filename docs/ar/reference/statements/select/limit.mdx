تتحكم عبارة `LIMIT` في عدد الصفوف المُعادة في نتائج الاستعلام. يمكن تحديد الصفوف بالعدد والإزاحة، أو عبر الشروط التي تفتح وتغلق نطاقًا من الصفوف باستخدام [`LIMIT ... AFTER ... UNTIL`](#limit-after-until).

## صيغة أساسية {#basic-syntax}

**اختيار الصفوف الأولى:**

```sql
LIMIT m
```

يعيد أول `m` صفوف من النتيجة، أو كل السجلات إذا كان عددها أقل من `m`.

**صيغة TOP البديلة (متوافقة مع MS SQL Server):**

```sql
-- SELECT TOP number|percent column_name(s) FROM table_name
SELECT TOP 10 * FROM numbers(100);
SELECT TOP 0.1 * FROM numbers(100);
```

وهذا يعادل `LIMIT m`، ويمكن استخدامه للتوافق مع استعلامات Microsoft SQL Server.

**الاختيار مع الإزاحة:**

```sql
LIMIT m OFFSET n
-- or equivalently:
LIMIT n, m
```

يتجاوز أول `n` من الصفوف، ثم يعيد الصفوف `m` التالية.

في كلتا الصيغتين، يجب أن يكون `n` و `m` عددين صحيحين غير سالبين.

**اختيار نطاق حسب الشروط:**

```sql
LIMIT [n] AFTER start_expr [UNTIL end_expr]
LIMIT [n] UNTIL end_expr
```

يعيد الصفوف ابتداءً من أول صف تكون فيه `start_expr` صحيحة، أو من بداية التدفق عند حذف `AFTER`، وحتى أول صف تكون فيه `end_expr` صحيحة، دون تضمينه؛ ويحدد `n` طول ذلك النطاق. يفتح `AFTER start_expr ALL` نطاقًا عند كل صف مطابق. راجع [LIMIT ... AFTER ... UNTIL](#limit-after-until) أدناه.

## الحدود السالبة {#negative-limits}

حدِّد الصفوف من *نهاية* مجموعة النتائج باستخدام قيم سالبة:

| الصيغة               | النتيجة                            |
| -------------------- | ---------------------------------- |
| `LIMIT -m`           | آخر `m` صفوف                       |
| `LIMIT -m OFFSET -n` | آخر `m` صفوف بعد تخطي آخر `n` صفوف |
| `LIMIT m OFFSET -n`  | أول `m` صفوف بعد تخطي آخر `n` صفوف |
| `LIMIT -m OFFSET n`  | آخر `m` صفوف بعد تخطي أول `n` صفوف |

صيغة `LIMIT -n, -m` مكافئة لـ `LIMIT -m OFFSET -n`.

## حدود LIMIT الكسرية {#fractional-limits}

استخدم قيمًا عشرية بين 0 و1 لتحديد نسبة مئوية من الصفوف:

| الصياغة                 | النتيجة                                         |
| ----------------------- | ----------------------------------------------- |
| `LIMIT 0.1`             | أول 10% من الصفوف                               |
| `LIMIT 1 OFFSET 0.5`    | الصف الوسيط                                     |
| `LIMIT 0.25 OFFSET 0.5` | الربيع الثالث (25% من الصفوف بعد تجاوز أول 50%) |

<Note>
  * يجب أن تكون القيم الكسرية من النوع [Float64](/ar/reference/data-types/float)، وأكبر من 0 وأقل من 1.
  * تُقرَّب أعداد الصفوف الكسرية إلى العدد الصحيح التالي.
</Note>

## الجمع بين أنواع LIMIT {#combining-limit-types}

يمكنك الجمع بين الأعداد الصحيحة العادية والإزاحات الكسرية أو السالبة:

```sql
LIMIT 10 OFFSET 0.5    -- 10 rows starting from the halfway point
LIMIT 10 OFFSET -20    -- 10 rows after skipping the last 20
```

لا تُستخدم [صيغة النطاق](#limit-after-until) إلا مع عدد صحيح عادي للصفوف: يأخذ `LIMIT 3 AFTER start_expr` ثلاثة صفوف كحد أقصى من نقطة بدء النطاق. تُرفض `OFFSET` والأعداد الكسرية والسالبة و`WITH TIES` مع `AFTER` أو `UNTIL`. يمكن أن تسبق عبارة [`LIMIT BY`](/ar/reference/statements/select/limit-by) نطاقًا في الاستعلام نفسه، ويظل إعداد [`limit`](/ar/reference/settings/session-settings/other#limit) يقيّد النتيجة.

## LIMIT ... WITH TIES {#limit--with-ties-modifier}

يضمّ المعدِّل `WITH TIES` صفوفًا إضافية تحمل قيم `ORDER BY` نفسها التي يحملها الصف الأخير ضمن الحد. وينطبق على حدود العدد والإزاحة فقط، ولا يمكن دمجه مع [صيغة النطاق](#limit-after-until).

```sql
SELECT * FROM (
    SELECT number % 50 AS n FROM numbers(100)
) ORDER BY n LIMIT 0, 5
```

```response
┌─n─┐
│ 0 │
│ 0 │
│ 1 │
│ 1 │
│ 2 │
└───┘
```

عند استخدام `WITH TIES`، تُدرَج جميع الصفوف التي تطابق القيمة الأخيرة:

```sql
SELECT * FROM (
    SELECT number % 50 AS n FROM numbers(100)
) ORDER BY n LIMIT 0, 5 WITH TIES
```

```response
┌─n─┐
│ 0 │
│ 0 │
│ 1 │
│ 1 │
│ 2 │
│ 2 │
└───┘
```

يُدرج الصف 6 لأنه يحمل القيمة نفسها (`2`) التي في الصف 5.

وينطبق الأمر نفسه عند تحديد الإزاحة باستخدام الكلمة المفتاحية `OFFSET`:

```sql
SELECT * FROM (
    SELECT number % 50 AS n FROM numbers(100)
) ORDER BY n LIMIT 3 OFFSET 2 WITH TIES
```

```response
┌─n─┐
│ 1 │
│ 1 │
│ 2 │
│ 2 │
└───┘
```

يؤدي عادةً تخطي أول صفّين وأخذ 3 إلى إرجاع `1, 1, 2`، لكن أُدرِجت القيمة `2` الثانية أيضًا لأنها مساوية للصف الأخير.

يعمل `WITH TIES` أيضًا مع القيم السالبة في `LIMIT` و`OFFSET`. ويضمّ صفوفًا إضافية تحمل قيم `ORDER BY` نفسها التي يحملها أول صف محدد:

```sql
SELECT number % 3 AS n FROM numbers(15)
ORDER BY n LIMIT -4 OFFSET -3 WITH TIES
```

```response
┌─n─┐
│ 1 │
│ 1 │
│ 1 │
│ 1 │
│ 1 │
│ 2 │
│ 2 │
└───┘
```

من دون `WITH TIES`، ستكون النتيجة `1, 1, 2, 2`. وعند استخدام `WITH TIES`، تُدرَج ثلاثة صفوف إضافية بالقيمة `1` لأنها تتساوى مع أول صف مُحدَّد.

يمكن دمج هذا المُعدِّل مع المُعدِّل [`ORDER BY ... WITH FILL`](/ar/reference/statements/select/order-by#order-by-expr-with-fill-modifier).

## LIMIT ... AFTER ... UNTIL (‏نطاق حسب الـ conditions) {#limit-after-until}

يمكنك حصر النتيجة في *نطاق* من الصفوف يقع بين شرطَي boundary:

```sql
LIMIT [n] AFTER start_expr [UNTIL end_expr]
LIMIT [n] AFTER start_expr ALL [UNTIL end_expr]
LIMIT [n] UNTIL end_expr
```

* `AFTER start_expr`: ابدأ الإخراج من أول صف تكون فيه `start_expr` صحيحة (ويُضمَّن هذا الصف).
* `AFTER start_expr ALL`: أخرج اتحاد جميع النطاقات المطابقة التي تبدأ عند تحقق `start_expr`، من دون تكرار الصفوف عند تداخل النطاقات.
* `UNTIL end_expr`: توقّف قبل أول صف تكون فيه `end_expr` صحيحة (ويُستبعد هذا الصف).
* `n`: عدد صفوف اختياري. من دون `ALL`، يمثّل الحد الأقصى لطول النطاق المفتوح الواحد. مع `AFTER ... ALL`، يمثّل طول *كل* نطاق مفتوح، لذا قد يتجاوز إجمالي النتيجة `n` (على سبيل المثال، قد يعيد `LIMIT 2 AFTER number IN (2, 6) ALL` ما يصل إلى أربعة صفوف). لفرض حد أقصى على إجمالي عدد صفوف النتيجة، استخدم إعداد `limit`، الذي يُطبَّق كحد عام بعد النطاق.

يحدّد ترتيب التدفق (أي ترتيب قراءة الصفوف) المطابقة «الأولى»؛ استخدم `ORDER BY` للتحكم فيه.

من دون `ALL`، إذا ظهرت أول مطابقة لـ `UNTIL` قبل أول مطابقة لـ `AFTER`، تكون النتيجة فارغة. مع `AFTER ... ALL`، يمكن لمطابقات `AFTER` اللاحقة أن تفتح نطاقات جديدة.

**أمثلة:**

أول 3 صفوف بدءًا من أول صف تكون فيه `number >= 3`:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT 3 AFTER number >= 3;
```

```response
┌─number─┐
│      3 │
│      4 │
│      5 │
└────────┘
```

الصفوف بدءًا من أول صف يكون فيه `number >= 2` وحتى (غير شامل) أول صف يكون فيه `number >= 6`:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT 10 AFTER number >= 2 UNTIL number >= 6;
```

```response
┌─number─┐
│      2 │
│      3 │
│      4 │
│      5 │
└────────┘
```

بدون `n`، تُعاد جميع الصفوف بدءًا من تطابق `AFTER` وحتى نهاية الـ stream (أو حتى `UNTIL`):

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT AFTER number >= 7;
```

```response
┌─number─┐
│      7 │
│      8 │
│      9 │
└────────┘
```

بدون `n` ولكن مع `UNTIL`، يمتد النطاق من أول تطابق لـ `AFTER` حتى أول تطابق لـ `UNTIL`:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT AFTER number >= 2 UNTIL number >= 6;
```

```response
┌─number─┐
│      2 │
│      3 │
│      4 │
│      5 │
└────────┘
```

إخراج صفّين بعد كل صف مطابق، دون تكرار التداخلات:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT 2 AFTER number IN (2, 3, 6) ALL;
```

```response
┌─number─┐
│      2 │
│      3 │
│      4 │
│      6 │
│      7 │
└────────┘
```

مع `ALL` و`UNTIL`، ينتهي كل نطاق مفتوح عند بلوغه `n` من الصفوف أو عند أول تطابق تالٍ لـ `UNTIL`، أيهما يحدث أولًا؛ فهنا يُقطع النطاق الذي فُتح عند 6 بفعل `number = 7`:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT 2 AFTER number IN (2, 6) ALL UNTIL number = 7;
```

```response
┌─number─┐
│      2 │
│      3 │
│      6 │
└────────┘
```

بدون `n`، يُغلق تطابق `UNTIL` النطاق الحالي، ويفتح أي تطابق `AFTER` لاحق نطاقًا جديدًا يمتد حتى النهاية إن لم يتبعه تطابق `UNTIL` آخر:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT AFTER number IN (2, 6) ALL UNTIL number = 4;
```

```response
┌─number─┐
│      2 │
│      3 │
│      6 │
│      7 │
│      8 │
│      9 │
└────────┘
```

من دون `n` و`UNTIL`، يمتد كل نطاق مفتوح حتى نهاية الـ stream، لذا يعيد `AFTER start_expr ALL` الصفوف نفسها التي يعيدها `AFTER start_expr`.

<Note>
  * لا يمكن استخدام `WITH TIES` أو `LIMIT`/`OFFSET` الكسري أو السالب أو `OFFSET` مع `AFTER`/`UNTIL`.
  * يُعطَّل pushdown الأولي لـ `LIMIT` عند استخدام `AFTER`/`UNTIL`.
  * لا يُتعرَّف على `AFTER` و`UNTIL` ككلمات مفتاحية إلا إذا تبعهما تعبير حدّي، لذا يظل المعرّف المسمى `after` أو `until` صالحًا كعدد للصفوف (`LIMIT after`، `LIMIT after BY x`). وعندما يكون التفسيران ممكنين، تكون الأولوية للكلمة المفتاحية: يُفسَّر `LIMIT after(2)` على أنه النطاق `LIMIT AFTER (2)`؛ وللاستدعاء دالة باسم `after`، اكتب `LIMIT (after(2))`.
</Note>

يعيد `UNTIL` وحده الصفوف من بداية الـ stream حتى أول صف يتحقق فيه الشرط:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT UNTIL number >= 3;
```

```response
┌─number─┐
│      0 │
│      1 │
│      2 │
└────────┘
```

مع `n`، يُرجع `UNTIL` بمفرده `n` من الصفوف كحدٍّ أقصى بدءًا من بداية الـ stream، مع التوقف عند أول تطابق:

```sql
SELECT number FROM numbers(10) ORDER BY number LIMIT 2 UNTIL number >= 3;
```

```response
┌─number─┐
│      0 │
│      1 │
└────────┘
```

يمكن أن يأتي النطاق بعد [`LIMIT BY`](/ar/reference/statements/select/limit-by)، وعندئذٍ ينطبق على الصفوف التي يُبقيها `LIMIT BY`:

```sql
SELECT number % 4 AS k, number FROM numbers(12) ORDER BY k, number LIMIT 2 BY k LIMIT 3 AFTER k >= 1;
```

```response
┌─k─┬─number─┐
│ 1 │      1 │
│ 1 │      5 │
│ 2 │      2 │
└───┴────────┘
```

## اعتبارات {#considerations}

**نتائج غير حتمية:** من دون عبارة [`ORDER BY`](/ar/reference/statements/select/order-by)، قد تكون الصفوف المُعادة عشوائية وقد تختلف من تنفيذ استعلام إلى آخر.

**حدّ على مستوى الخادم:** يمكن أيضًا أن يتأثر عدد الصفوف المُعادة بإعداد [limit](/ar/reference/settings/session-settings/other#limit).
