أُضيف في: v24.11.0

ينشئ عبء عمل، وهو عقدة في التسلسل الهرمي الذي تستخدمه [جدولة أحمال العمل](/ar/concepts/features/configuration/server-config/workload-scheduling) لتوزيع الموارد بين أحمال العمل. أما الموارد المراد جدولتها فتُنشأ باستخدام [`CREATE RESOURCE`](/ar/reference/statements/create/resource).

## الصيغة {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - يستبدل تعريف عبء عمل موجود. ولا يمكن استخدامه مع `IF NOT EXISTS`.
* `IF NOT EXISTS` - إذا كان هناك عبء عمل باسم `name`، فلن يُنفِّذ الاستعلام أي إجراء.
* `IN parent_name` - ينشئ عبء العمل بوصفه مثيلًا فرعيًا لعبء العمل `parent_name`. ويُعدّ عبء العمل الذي لا يتضمن `IN` عبء عمل جذريًا. وتُرفض أي دورة بين أحمال العمل.
* `SETTINGS` - إعدادات الجدولة لعبء العمل، مثل `weight` أو `priority` أو `max_concurrent_threads` أو `max_bytes_per_second`، وهي موضحة في [التسلسل الهرمي لأحمال العمل](/ar/concepts/features/configuration/server-config/workload-scheduling#workloads). ينطبق الإعداد المقترن بـ `FOR resource_name` على ذلك المورد فقط، وإلا فإنه ينطبق على جميع الموارد. ويُعدّ تحديد إعداد غير معروف خطأً (error).

لأحمال العمل والموارد مساحات أسماء منفصلة، لذا يمكن أن يحمل عبء عمل ومورد الاسم نفسه. يُنفَّذ الاستعلام ضمن عبء العمل المحدد في إعداد [`workload`](/ar/reference/settings/session-settings/other#workload) الخاص به، راجع [وسم عبء العمل](/ar/concepts/features/configuration/server-config/workload-scheduling#workload-markup).

<Note>
  جدولة حجز الذاكرة ميزة تجريبية، وتشمل المورد `MEMORY RESERVATION` وإعدادات عبء العمل `max_memory` و`max_memory_ratio` و`max_memory_before_spill` و`max_memory_to_spill_ratio`. راجع [حجز الذاكرة](/ar/concepts/features/configuration/server-config/workload-scheduling#memory-reservations).
</Note>

## التخزين {#storage}

تُخزَّن أحمال العمل على القرص في [`workload_path`](/ar/reference/settings/server-settings/settings/workload#workload_path)، أو في ZooKeeper ضمن المسار [`workload_zookeeper_path`](/ar/reference/settings/server-settings/settings/workload#workload_zookeeper_path) إذا كان هذا الإعداد مضبوطًا. وعند استخدام التخزين في ZooKeeper، تُرفض عبارة `ON CLUSTER` لأن التعريفات تُنسخ نسخًا متماثلًا تلقائيًا. ولا يمكن استبدال أحمال العمل [المعرَّفة في تكوين الخادم](/ar/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads) أو حذفها باستخدام SQL. ويعرض جدول [`system.workloads`](/ar/reference/system-tables/workloads) قائمة بأحمال العمل.

## الامتيازات {#privileges}

يتطلب `CREATE WORKLOAD` امتياز `CREATE WORKLOAD`. ويتطلب `CREATE OR REPLACE WORKLOAD` أيضًا امتياز `DROP WORKLOAD`.

## مثال {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
