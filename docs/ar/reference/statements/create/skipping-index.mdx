أُضيف في: v22.7.0

يضيف [فهرس تخطي البيانات](/ar/reference/engines/table-engines/mergetree-family/mergetree#table_engine-mergetree-data_skipping-indexes) إلى جدول من عائلة `MergeTree`. وهو صيغة مستقلة من [`ALTER TABLE ... ADD INDEX`](/ar/reference/statements/alter/skipping-index#add-index)، ويتطلب امتياز `ALTER ADD INDEX` ذاته.

## الصيغة {#syntax}

```sql
CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [db.]table [ON CLUSTER cluster] expression TYPE type [GRANULARITY value]
```

* `expression` - التعبير المُفهرَس، ويمكن وضعه اختياريًا بين قوسين. تُنشئ القائمة المحاطة بقوسين `(expr1, expr2, ...)` فهرسًا واحدًا يشمل جميع التعبيرات، تمامًا كما يفعل `INDEX name (expr1, expr2, ...)` في `CREATE TABLE`.
* `TYPE type [GRANULARITY value]` - كما في عبارة `INDEX` ضمن `CREATE TABLE`، راجع [أنواع فهارس التخطي](/ar/reference/engines/table-engines/mergetree-family/mergetree#skip-index-types).
* `IF NOT EXISTS` - إذا كان الجدول يحتوي بالفعل على فهرس باسم `name`، فلن يُنفِّذ الاستعلام أي إجراء.

على غرار `ADD INDEX`، لا تُغيِّر هذه العبارة سوى البيانات الوصفية للجدول. ولبناء الفهرس للبيانات الموجودة مسبقًا في الجدول، نفِّذ [`ALTER TABLE ... MATERIALIZE INDEX`](/ar/reference/statements/alter/skipping-index#materialize-index).

## التوافق مع SQL {#sql-compatibility}

لضمان التوافق مع أنظمة قواعد البيانات الأخرى:

* تُتجاهَل `ASC` و`DESC` الواردتان بعد التعبيرات في قائمة محاطة بأقواس.
* يُرفَض `CREATE UNIQUE INDEX` ما لم تكن قيمة [`create_index_ignore_unique`](/ar/reference/settings/session-settings/create#create_index_ignore_unique) هي `1`، وفي هذه الحالة تُتجاهَل `UNIQUE` ويُنشأ فهرس عادي.
* يُرفَض `CREATE INDEX` بدون `TYPE` ما لم تكن قيمة [`allow_create_index_without_type`](/ar/reference/settings/session-settings/allow#allow_create_index_without_type) هي `1`، وفي هذه الحالة لا يُحدث الاستعلام أي أثر.

## مثال {#example}

```sql title="Query"
CREATE TABLE t (id UInt64, s String) ENGINE = MergeTree ORDER BY id;
INSERT INTO t SELECT number, toString(number) FROM numbers(1000);
CREATE INDEX idx_s ON t (s) TYPE bloom_filter GRANULARITY 1;
ALTER TABLE t MATERIALIZE INDEX idx_s SETTINGS mutations_sync = 1;
SELECT name, type, expr, granularity FROM system.data_skipping_indices WHERE database = currentDatabase() AND table = 't';
```

```text title="Response"
┌─name──┬─type─────────┬─expr─┬─granularity─┐
│ idx_s │ bloom_filter │ s    │           1 │
└───────┴──────────────┴──────┴─────────────┘
```
