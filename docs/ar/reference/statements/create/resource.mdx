أُضيف في: v24.11.0

ينشئ موردًا لـ[جدولة أحمال العمل](/ar/concepts/features/configuration/server-config/workload-scheduling)، أي نوعًا من الوصول، مثل عمليات القراءة من القرص أو وقت CPU، تجري جدولته بين أحمال العمل المُنشأة باستخدام [`CREATE WORKLOAD`](/ar/reference/statements/create/workload).

## الصيغة {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

تعمل `OR REPLACE` و`IF NOT EXISTS` و`ON CLUSTER` بالطريقة نفسها المتبعة في [`CREATE WORKLOAD`](/ar/reference/statements/create/workload#syntax).

## أوضاع الوصول {#access-modes}

| وضع الوصول                                    | الوصول المُجدول                                                                                                                                    | أُضيف في |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `READ DISK disk_name`، `WRITE DISK disk_name` | عمليات القراءة من القرص `disk_name` أو الكتابة إليه، راجع [الموارد](/ar/concepts/features/configuration/server-config/workload-scheduling#resources)  | v24.11.0 |
| `READ ANY DISK`، `WRITE ANY DISK`             | عمليات القراءة من أي قرص أو الكتابة إليه                                                                                                           | v24.11.0 |
| `MASTER THREAD`، `WORKER THREAD`              | CPU، راجع [جدولة وحدة المعالجة المركزية](/ar/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)                        | v25.4.0  |
| `QUERY`                                       | خانات تنفيذ الاستعلامات، راجع [جدولة خانات تنفيذ الاستعلامات](/ar/concepts/features/configuration/server-config/workload-scheduling#query_scheduling) | v25.6.0  |
| `MEMORY RESERVATION`                          | الذاكرة، راجع [حجز الذاكرة](/ar/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)                                | v26.6.2  |

يجب أن تكون أوضاع الوصول الخاصة بالمورد الواحد من نوع واحد فقط: القرص، أو خيوط تنفيذ CPU، أو `QUERY`، أو `MEMORY RESERVATION`. ولا يمكن أن ينتمي أيٌّ من `MASTER THREAD` و`WORKER THREAD` و`QUERY` و`MEMORY RESERVATION` إلى أكثر من مورد واحد. ولا يمكن تغيير نوع المورد باستخدام `CREATE OR REPLACE RESOURCE`، بل يجب حذفه ثم إنشاؤه من جديد.

<Note>
  `MEMORY RESERVATION` ميزة تجريبية، وقد تتغير واجهة SQL الخاصة بها وسلوكها في الإصدارات المستقبلية.
</Note>

## التخزين {#storage}

تُخزَّن الموارد بالطريقة نفسها التي تُخزَّن بها أحمال العمل، راجع [التخزين](/ar/reference/statements/create/workload#storage). ويعرض جدول [`system.resources`](/ar/reference/system-tables/resources) قائمة الموارد.

## الامتيازات {#privileges}

يتطلب `CREATE RESOURCE` امتياز `CREATE RESOURCE`. كما يتطلب `CREATE OR REPLACE RESOURCE` امتياز `DROP RESOURCE`.

## مثال {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
