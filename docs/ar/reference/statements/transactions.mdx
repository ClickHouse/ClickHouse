تُجمِّع عبارات التحكم في المعاملات `BEGIN TRANSACTION` و`COMMIT` و`ROLLBACK` و`SET TRANSACTION SNAPSHOT` عدة استعلامات على جداول `MergeTree` في معاملة واحدة.
تقرأ استعلامات المعاملة لقطة واحدة متسقة من التغييرات التي تُثبِّتها المعاملات الأخرى.
عمليات الكتابة خارج المعاملات غير معزولة: فعملية `INSERT` أو `TRUNCATE TABLE` أو `ALTER TABLE ... DELETE` التي تُنفَّذ خارج معاملة تكون مرئية للاستعلام التالي ضمن معاملة جارية، ولذلك فإن الحصول على عرض مستقر يتطلب أن تستخدم الجهات الكاتبة المعاملات أيضًا، مثلًا عبر [`implicit_transaction`](/ar/reference/settings/session-settings/implicit#implicit_transaction).
ولا ترى المعاملات الأخرى تغييرات المعاملة إلا بعد `COMMIT`، في حين يتجاهلها `ROLLBACK`.
أما الاستعلامات التي تُنفَّذ خارج أي معاملة، فيمكنها رؤية تغييرات معاملة جارية قبل تثبيتها.

<Note>
  هذه العبارات جزء من مجموعة الميزات التجريبية.
  لتمكين الدعم التجريبي للمعاملات، أضف هذا الإعداد إلى [التهيئة](/ar/concepts/features/configuration/server-config/configuration-files) لديك:

  ```xml
  <clickhouse>
      <allow_experimental_transactions>1</allow_experimental_transactions>
  </clickhouse>
  ```

  لمزيد من المعلومات، راجع صفحة [الدعم المعاملاتي (ACID)](/ar/concepts/features/operations/insert/transactions#transactions-commit-and-rollback).
</Note>

## الصيغة {#syntax}

```sql
BEGIN TRANSACTION
START TRANSACTION
COMMIT
ROLLBACK
SET TRANSACTION SNAPSHOT snapshot
```

تنتمي المعاملة إلى session، ولا تضم الـ session الواحدة أكثر من معاملة واحدة.
عبر HTTP، أرسل جميع استعلامات المعاملة باستخدام `session_id` نفسه: فالطلب الذي لا يتضمن `session_id` يُنفَّذ في session مستقلة خاصة به تنتهي بانتهائه.
يجري التراجع (rollback) عن أي معاملة لا تزال قيد التنفيذ عند انتهاء الـ session التابعة لها.

## BEGIN TRANSACTION {#begin-transaction}

يبدأ معاملة في الجلسة الحالية. ويُعدّ `START TRANSACTION` اسمًا بديلًا له، وقد أُضيف في الإصدار v24.3.0.

المعاملات المتداخلة غير مدعومة؛ إذ يؤدي تنفيذ `BEGIN TRANSACTION` داخل معاملة قائمة إلى رفع الاستثناء `INVALID_TRANSACTION`.

## COMMIT {#commit}

يثبّت المعاملة الحالية ويجعل تغييراتها مرئية للمعاملات الأخرى.
يرفع `COMMIT` استثناءً من النوع `INVALID_TRANSACTION` إذا نُفِّذ دون وجود معاملة حالية.

إذا فشل أي استعلام داخل المعاملة، يُتراجع عن المعاملة. أما الاستعلام الذي يتعذر تحليله، كأن يحتوي على خطأ في الصيغة، أو الذي تكون معلمات الاستعلام الخاصة به مفقودة أو غير صالحة، فلا يُنفَّذ ويُبقي المعاملة قيد التشغيل، ومن ثَمّ يظل بإمكان `COMMIT` لاحق تثبيتها.
وإلى أن يُنهي `ROLLBACK` المعاملة التي جرى التراجع عنها، يرفع `COMMIT` وسائر الاستعلامات اللاحقة استثناءً من النوع `INVALID_TRANSACTION`. ولا يظل قابلًا للتنفيذ سوى `ROLLBACK` و`SET TRANSACTION SNAPSHOT` واستعلامات `EXPLAIN` باستثناء `EXPLAIN ANALYZE`.

يتحكم الإعداد [`wait_changes_become_visible_after_commit_mode`](/ar/reference/settings/session-settings/other#wait_changes_become_visible_after_commit_mode) فيما ينتظره `COMMIT`.

## ROLLBACK {#rollback}

يتراجع عن المعاملة الحالية ويُلغي التغييرات التي أجرتها.
يرفع `ROLLBACK` استثناءً من النوع `INVALID_TRANSACTION` عند تنفيذه دون وجود معاملة حالية.

## SET TRANSACTION SNAPSHOT {#set-transaction-snapshot}

يغيّر اللقطة التي تقرأ منها المعاملة الحالية إلى رقم تسلسل التثبيت (CSN) `snapshot`، كأن تكون قيمةً أعادتها الدالة [`transactionLatestSnapshot`](/ar/reference/functions/regular-functions/other-functions#transactionLatestSnapshot) في معاملة سابقة.
وبعد ذلك ترى المعاملة تغييراتها الخاصة، والبيانات المكتوبة خارج المعاملات، وتغييرات المعاملات المُثبَّتة حتى رقم CSN هذا.
ولا تقرأ المعاملة إلا أجزاء البيانات التي لا يزال الخادم يحتفظ بها، كما أنها لا تحميها من الإزالة: فما إن لا تبقى أي معاملة قيد التشغيل بدأت قبل أن تُزيل عملية دمج أو تعديل أو استعلام آخر جزءًا ما، حتى يصبح بإمكان الخادم حذف ذلك الجزء، فتفقد عندئذٍ اللقطة الأقدم صفوفه.
لا تعتمد على `SET TRANSACTION SNAPSHOT` لإجراء قراءات قابلة للتكرار للبيانات التاريخية.
يؤدي تنفيذ `SET TRANSACTION SNAPSHOT` دون وجود معاملة حالية إلى رفع استثناء `INVALID_TRANSACTION`.

القيم من `0` إلى `32` محجوزة وتؤدي إلى رفع استثناء `INVALID_TRANSACTION`، باستثناء قيمتين:
القيمة `1` تجعل البيانات المكتوبة خارج المعاملات وتغييرات المعاملة نفسها هي وحدها المرئية، والقيمة `3` تجعل جميع أجزاء البيانات في الجدول مرئية، بما في ذلك أجزاء المعاملات التي لم تُثبَّت بعد والأجزاء التي أزالتها المعاملات أو تراجعت عنها.

## الاستعلامات داخل المعاملة {#queries-inside-a-transaction}

يمكن تنفيذ استعلامات `SELECT` و`INSERT` و`DELETE` و`OPTIMIZE` و`TRUNCATE TABLE` و`SET` و`EXPLAIN` داخل المعاملة، إضافةً إلى عمليات التعديل `ALTER TABLE` وعمليات التقسيم.
أما الاستعلامات الأخرى، مثل `CREATE TABLE` أو `UPDATE` أو `ALTER TABLE ... ADD COLUMN`، فترفع استثناء `NOT_IMPLEMENTED`، وكذلك الاستعلامات على الجداول التي لا تدعم المعاملات، مثل جداول `ReplicatedMergeTree` أو `Memory`، أو الجدول `system.transactions`.

عمليات الإدراج غير المتزامنة غير مدعومة داخل المعاملة، والإعداد [`async_insert`](/ar/reference/settings/session-settings/async-insert#async_insert) مفعّل افتراضيًا، لذا فإن أي استعلام `INSERT ... VALUES` أو `INSERT ... SELECT` داخل المعاملة يرفع استثناء `NOT_IMPLEMENTED` ما لم يُعطَّل `async_insert`، باستخدام `SET async_insert = 0` مثلًا.

عند ضبط [`throw_on_unsupported_query_inside_transaction`](/ar/reference/settings/session-settings/throw-on#throw_on_unsupported_query_inside_transaction) على `0`، تُنفَّذ بعض هذه الاستعلامات خارج المعاملة بدلًا من رفع استثناء، ومن ثَمّ لا يتراجع عنها `ROLLBACK`، ومن أمثلة ذلك `CREATE TABLE` أو `INSERT` في جدول `Memory`.

عند تفعيل [`implicit_transaction`](/ar/reference/settings/session-settings/implicit#implicit_transaction)، يُنفَّذ كل استعلام يعمل خارج معاملة ضمن معاملة مستقلة خاصة به، تُثبَّت عند نجاح الاستعلام ويُتراجع عنها عند فشله.

## أمثلة {#examples}

التراجع عن عملية إدراج:

```sql title="Query"
CREATE TABLE t (n UInt64) ENGINE = MergeTree ORDER BY n;
SET async_insert = 0;

BEGIN TRANSACTION;
INSERT INTO t VALUES (1);
SELECT count() FROM t;
ROLLBACK;
SELECT count() FROM t;
```

```text title="Response"
┌─count()─┐
│       1 │
└─────────┘
┌─count()─┐
│       0 │
└─────────┘
```

تثبيت عملية إدراج:

```sql title="Query"
BEGIN TRANSACTION;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```text title="Response"
┌─n─┐
│ 2 │
└───┘
```
