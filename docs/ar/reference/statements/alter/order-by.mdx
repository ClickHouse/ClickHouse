```sql
ALTER TABLE [db].name [ON CLUSTER cluster] MODIFY ORDER BY new_expression
```

يغيّر هذا الأمر [مفتاح الفرز](/ar/reference/engines/table-engines/mergetree-family/mergetree) للجدول إلى `new_expression` (تعبير أو tuple من التعبيرات). ويظل المفتاح الأساسي كما هو.

ويُعد هذا الأمر خفيفًا لأنه يغيّر البيانات الوصفية فقط. وللحفاظ على خاصية ترتيب صفوف جزء البيانات وفقًا لتعبير مفتاح الفرز، لا يمكنك إضافة تعبيرات تتضمن أعمدة موجودة بالفعل إلى مفتاح الفرز (يُسمح فقط بالأعمدة التي أُضيفت بواسطة الأمر `ADD COLUMN` ضمن استعلام `ALTER` نفسه، ومن دون قيمة افتراضية للعمود).

وللسبب نفسه، لا يمكنك تغيير اتجاه الفرز (`ASC` أو `DESC`) لعمود من أعمدة مفتاح الفرز يُبقي عليه `new_expression`: إذ تظل الأجزاء الموجودة مفروزة فيزيائيًا وفق الاتجاه الذي كان للعمود وقت كتابتها، ولا يسجّل أي جزء بيانات عادي ذلك الاتجاه. ولاستخدام اتجاه مختلف، أنشئ جدولًا جديدًا بـ `ORDER BY` المطلوب وانسخ البيانات إليه باستخدام `INSERT ... SELECT`.

<Note>
  لا يعمل هذا إلا مع الجداول من عائلة [`MergeTree`](/ar/reference/engines/table-engines/mergetree-family/mergetree) (بما في ذلك الجداول [ذات النسخ المتماثل](/ar/reference/engines/table-engines/mergetree-family/replication)).
</Note>

**جزء من:** `ALTER`

**ذو صلة:** `ALTER`, `CREATE TABLE`, `ALTER TABLE ... MODIFY SAMPLE BY`
