## الوصف {#description}

تجمع صيغة `ProtobufList` الصفوف في رسالة [Protocol Buffers](/ar/reference/formats/Protobuf/Protobuf) واحدة من نوع length-delimited تُسمّى `Envelope`. ويُرمَّز كل صف على هيئة رسالة فرعية رقمُ حقلها 1.

## مثال للاستخدام {#example-usage}

احفظ المخطط التالي باسم `schemafile.proto`. عرِّف الحقل `row` على أنه `repeated` لتتمكن أداة فك ترميز Protobuf التي تستخدم هذا المخطط من قراءة جميع الصفوف في الغلاف.

```capnp title="schemafile.proto"
syntax = "proto3";
message Envelope {
  message MessageType {
    string name = 1;
  }
  repeated MessageType row = 1;
}
```

من الدليل نفسه، شغّل الأوامر التالية لكتابة صفّين في ملف ثم قراءتهما.

```bash
clickhouse local --query "SELECT name FROM values('name String', 'Ada', 'Grace') ORDER BY name
    SETTINGS format_schema = 'schemafile:MessageType' FORMAT ProtobufList" > people.bin

clickhouse local --structure 'name String' --input-format ProtobufList \
    --format_schema 'schemafile:MessageType' --query 'SELECT name FROM table' < people.bin
```

```text
Ada
Grace
```

يُحَلّ نوع الرسالة المحدَّد في `format_schema` بالبحث عنه أولًا باعتباره نوعًا متداخلًا داخل رسالة `Envelope` من المستوى الأعلى. وإذا لم يُعثَر هناك على تطابق — سواء لأن المخطط لا يحتوي على رسالة `Envelope`، أو لأن `Envelope` لا تتضمن رسالة بالاسم المطلوب — فتُستخدم مباشرةً الرسالة من المستوى الأعلى التي تحمل ذلك الاسم.
