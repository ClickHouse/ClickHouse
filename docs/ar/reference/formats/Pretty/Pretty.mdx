## الوصف {#description}

يُخرج التنسيق `Pretty` البيانات على شكل جداول مرسومة بأحرف Unicode،
باستخدام تسلسلات إفلات ANSI لعرض الألوان في الطرفية.
يُرسَم للجدول إطار كامل، ويشغل كل صف سطرين في الطرفية.
تُخرَج كل كتلة من النتائج كجدول منفصل.
وهذا ضروري حتى يمكن إخراج الكتل دون التخزين المؤقت للنتائج (إذ يلزم التخزين المؤقت لحساب العرض المرئي لجميع القيم مسبقًا).

يُخرَج [NULL](/ar/reference/syntax) على هيئة `ᴺᵁᴸᴸ`.

## مثال على الاستخدام {#example-usage}

مثال (بصيغة [`PrettyCompact`](/ar/reference/formats/Pretty/PrettyCompact)):

```sql title="Query"
SELECT * FROM t_null
```

```response title="Response"
┌─x─┬────y─┐
│ 1 │ ᴺᵁᴸᴸ │
└───┴──────┘
```

لا يُطبَّق الإفلات على الصفوف في أيٍّ من صيغ `Pretty`. وبدلًا من ذلك، تُعرض افتراضيًا محارف التحكم غير القابلة للطباعة (محارف التحكم C0 `0x00`-`0x1F` و`DEL` `0x7F`) الموجودة في القيم وفي أسماء الأعمدة على هيئة رموز Unicode &quot;Control Pictures&quot; المقابلة لها (`U+2400`-`U+2421`)، كي تظل مرئية ولا تُخِلّ بشكل الجدول. فعلى سبيل المثال، يُعرض المحرف NUL على هيئة `␀`:

```sql title="Query"
SELECT 'String with a NUL \0 character' AS Escaping_test FORMAT PrettyCompact
```

```response title="Response"
┌─Escaping_test─────────────────┐
│ String with a NUL ␀ character │
└───────────────────────────────┘
```

تُعدّ `TAB` ومحرف line feed و`ESC` استثناءات: إذ تُطبع دائمًا كما هي، لأن الطرفية تفسّرها ولا تتجاهلها؛ فمحرف الجدولة ينقل المؤشر إلى موضع الجدولة التالي، وتسلسل الإفلات ANSI هو ما يتيح للبيانات أن تتضمّن تصورًا. كما يظل محرف line feed يُحدث فاصل سطر: داخل خلية الجدول عند تفعيل [`output_format_pretty_multiline_fields`](/ar/reference/settings/formats#output_format_pretty_multiline_fields)، وكما هو في غير ذلك. أما اسم العمود فهو استثناء من هذا الاستثناء: فالترويسة والتذييل يتكوّنان من سطر واحد، لذا يُستبدل محرف line feed في الاسم كأي محرف تحكّم آخر.

لطباعة محارف التحكّم كما هي بدلًا من ذلك، عطّل الإعداد [`output_format_pretty_display_control_characters`](/ar/reference/settings/formats#output_format_pretty_display_control_characters):

```sql title="Query"
SELECT 'String with a NUL \0 character' AS Escaping_test FORMAT PrettyCompact
SETTINGS output_format_pretty_display_control_characters = 0
```

عندئذٍ تحتوي الاستجابة على بايت `NUL` الخام بدلًا من ذلك. تبتلع الطرفية هذا البايت، فيصبح الحرف غير مرئي ويزيد عرض الصف بموضع واحد عن الإطار الذي قيس له، فينتج الجدول المشوَّه الذي يتفاداه عرض Control Picture.

لتجنّب إخراج كمية كبيرة جدًا من البيانات إلى الطرفية، لا يُطبع سوى أول `10,000` صف.
إذا كان عدد الصفوف أكبر من أو يساوي `10,000`، فستُطبع الرسالة &quot;تم عرض أول 10 000&quot;.

<Note>
  هذه الصيغة مناسبة فقط لإخراج نتيجة استعلام، وليس لتحليل البيانات.
</Note>

تدعم صيغة Pretty إخراج القيم الإجمالية (عند استخدام `WITH TOTALS`) والقيم القصوى (عند ضبط &#39;extremes&#39; على 1).
في هذه الحالات، تُخرَج القيم الإجمالية والقيم القصوى بعد البيانات الرئيسية، في جداول منفصلة.
يوضح المثال التالي ذلك باستخدام صيغة [`PrettyCompact`](/ar/reference/formats/Pretty/PrettyCompact):

```sql title="Query"
SELECT EventDate, count() AS c 
FROM test.hits 
GROUP BY EventDate 
WITH TOTALS 
ORDER BY EventDate 
FORMAT PrettyCompact
```

```response title="Response"
┌──EventDate─┬───────c─┐
│ 2014-03-17 │ 1406958 │
│ 2014-03-18 │ 1383658 │
│ 2014-03-19 │ 1405797 │
│ 2014-03-20 │ 1353623 │
│ 2014-03-21 │ 1245779 │
│ 2014-03-22 │ 1031592 │
│ 2014-03-23 │ 1046491 │
└────────────┴─────────┘

Totals:
┌──EventDate─┬───────c─┐
│ 1970-01-01 │ 8873898 │
└────────────┴─────────┘

Extremes:
┌──EventDate─┬───────c─┐
│ 2014-03-17 │ 1031592 │
│ 2014-03-23 │ 1406958 │
└────────────┴─────────┘
```
