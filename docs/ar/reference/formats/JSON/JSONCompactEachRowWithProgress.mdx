## الوصف {#description}

تجمع هذه الصيغة بين الإخراج المضغوط صفًا بصف الذي توفّره صيغة [`JSONCompactEachRow`](/ar/reference/formats/JSON/JSONCompactEachRow) ومعلومات التقدّم التي تُرسَل بشكل متدفق. يبثّ ClickHouse كل حدث في كائن JSON مستقل، وتحتفظ قيم الأعمدة بأنواع JSON الأصلية الخاصة بها.

تستخدم الصيغة المرتبطة بها `JSONCompactStringsEachRowWithProgress` أنواع الكائنات نفسها في المستوى الأعلى، غير أن قيم الحقول فيها تُسلسَل على هيئة string.

تشترك هذه الصيغة مع [`JSONEachRowWithProgress`](/ar/reference/formats/JSON/JSONEachRowWithProgress) في عقد الدفق نفسه (`writesProgressConcurrently` / `finalizeImpl`)، باستثناء أن حمولات `row` / `totals` / `min` / `max` تكون **مصفوفات** من القيم مرتّبة وفق ترتيب الأعمدة، لا كائنات مسمّاة.

## كائنات الدفق {#stream-objects}

يمثّل كل سطر من الاستجابة كائن JSON واحدًا. وينبغي للعملاء توجيه المعالجة بحسب المفتاح في المستوى الأعلى:

| المفتاح في المستوى الأعلى    | متى يظهر                                                                          | الشكل                                                                                                                |
| ---------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `meta`                       | مرة واحدة، قبل أول `row` (قد يُرسَل كائن `progress` قبله)                         | `{"meta":[{"name":...,"type":...}, ...]}` — أسماء الأعمدة وأنواعها                                                   |
| `row`                        | مرة واحدة لكل صف في النتيجة                                                       | `{"row":[...]}` — قيم الأعمدة بترتيب الترويسة                                                                        |
| `progress`                   | دوريًا أثناء تنفيذ الاستعلام                                                      | `{"progress":{...}}` — عدّادات مثل `read_rows` و`read_bytes` و`total_rows_to_read`                                   |
| `totals`                     | عند وجود إجماليات                                                                 | `{"totals":[...]}` — قيم صف الإجماليات بترتيب الترويسة                                                               |
| `min` / `max`                | عند وجود قيم قصوى                                                                 | `{"min":[...]}` / `{"max":[...]}` — قيم صفَّي القيم القصوى بترتيب الترويسة                                           |
| `rows_before_limit_at_least` | عندما يتضمّن الاستعلام `LIMIT`                                                    | `{"rows_before_limit_at_least":N}` — تقدير أدنى لعدد الصفوف التي كانت ستُعاد لولا `LIMIT` (وليس دليلًا على حذف صفوف) |
| `rows_before_aggregation`    | عندما يُجري الاستعلام عملية تجميع ويكون العدّاد `rows_before_aggregation` مفعّلًا | `{"rows_before_aggregation":N}`                                                                                      |
| `exception`                  | عند فشل الاستعلام، عبر مسار HTTP مع `http_write_exception_in_output_format=1`     | `{"exception":"..."}` — نص الخطأ بوصفه **string في المستوى الأعلى**، لا متداخلًا ضمن `row`                           |

يُرسَل الكائن `rows_before_limit_at_least` عندما يتضمّن الاستعلام `LIMIT`، حتى إن لم يؤدِّ الحدّ إلى حذف أي صفوف. وهو تقدير أدنى لعدد الصفوف التي كانت ستُعاد لولا `LIMIT` (بالمعنى نفسه المستخدم في `JSON`)؛ لذا يجب ألا يعدّه العملاء دليلًا على حذف صفوف.

يُرسَل `meta` مرة واحدة قبل أول `row`، غير أن كائن `progress` قد يصل قبل `meta`. ولا يُرسَل الكائن `exception` في المستوى الأعلى عبر مسار HTTP إلا عند ضبط `http_write_exception_in_output_format=1`؛ وفي غير ذلك يظهر الخطأ عبر طبقة النقل. وعند إرساله، يكون كائنًا مستقلًا في المستوى الأعلى، لا متداخلًا ضمن `row`.

## مثال للاستخدام {#example-usage}

```sql title="Query"
SELECT *
FROM generateRandom('a Array(Int8), d Decimal32(4), c Tuple(DateTime64(3), UUID)', 1, 10, 2)
LIMIT 5
FORMAT JSONCompactEachRowWithProgress
```
