## الوصف {#description}

يطبع كل قيمة في سطر منفصل مع اسم العمود المحدد. يكون هذا التنسيق مناسبًا لطباعة صف واحد أو بضعة صفوف فقط إذا كان كل صف يتكوّن من عدد كبير من الأعمدة.

لاحظ أن [`NULL`](/ar/reference/syntax) يُخرَج بالشكل `ᴺᵁᴸᴸ` لتسهيل التمييز بين القيمة النصية `NULL` وبين عدم وجود قيمة. وتُطبع أعمدة JSON بتنسيق Pretty، كما يُخرَج `NULL` بالشكل `null` لأنه قيمة JSON صالحة ويسهل تمييزها عن `"null"`.

## مثال على الاستخدام {#example-usage}

مثال:

```sql
SELECT * FROM t_null FORMAT Vertical
```

```response
Row 1:
──────
x: 1
y: ᴺᵁᴸᴸ
```

افتراضيًا، تُعرض محارف التحكم غير القابلة للطباعة (محارف التحكم C0 `0x00`–`0x1F` و`DEL` `0x7F`) الموجودة في القيم وفي أسماء الأعمدة على هيئة رموز Unicode &quot;Control Pictures&quot; المقابلة لها (`U+2400`–`U+2421`)، كي تبقى ظاهرة بدلًا من أن تبتلعها الطرفية بصمت. فعلى سبيل المثال، يُعرض المحرف NUL على هيئة `␀`:

```sql
SELECT 'string with a NUL \0 character' AS test FORMAT Vertical
```

```response
Row 1:
──────
test: string with a NUL ␀ character
```

تُستثنى `TAB` ومحرف line feed و`ESC` من ذلك: إذ تُطبع دائمًا كما هي، لأن الطرفية تفسّرها بدلًا من أن تبتلعها؛ فمحرف الجدولة ينقل المؤشر إلى موضع الجدولة التالي، ومحرف line feed يبدأ سطرًا جديدًا، وتسلسل الإفلات ANSI هو ما يتيح للبيانات أن تحمل تصورًا. أما اسم العمود فهو استثناء من هذا الاستثناء: إذ يُعرض على سطر واحد، ولذلك يُستبدل محرف line feed الوارد في الاسم كما يُستبدل أي محرف تحكم آخر.

ولطباعة محارف التحكم كما هي بدلًا من ذلك، عطّل [`output_format_pretty_display_control_characters`](/ar/reference/settings/formats#output_format_pretty_display_control_characters):

```sql
SELECT 'string with a NUL \0 character' AS test
FORMAT Vertical
SETTINGS output_format_pretty_display_control_characters = 0
```

وفي هذه الحالة تحتوي الاستجابة على البايت الخام `NUL` بدلاً من ذلك. وتُسقط الطرفية هذا البايت من العرض، فتبدو القيمة
كأن الحرف غير موجود أصلاً.

هذه الصيغة مناسبة فقط لإخراج نتيجة استعلام، ولا تصلح للتحليل (أي استرجاع البيانات لإدراجها في جدول).
