تتيح واجهة سطر الأوامر لـ ClickHouse (`clickhousectl`، واسمها البديل `chctl`) إدارة ClickHouse Cloud من الطرفية أو عبر برنامج نصي أو وكيل برمجة. تتناول هذه الصفحة الجوانب المتعلقة بـ Cloud في واجهة سطر الأوامر. أما للاطلاع على جميع مجموعات الأوامر، والتطوير المحلي، والتفاصيل الكاملة لسلوك الأداة، فراجع [مرجع clickhousectl](/ar/concepts/features/interfaces/cli).

## ما الذي يمكنك إدارته {#what-you-can-manage}

تشمل أوامر `clickhousectl cloud` ما يلي:

* **الخدمات:** إنشاء خدمات ClickHouse Cloud وتوسيع نطاقها وتشغيلها وإيقافها، وتنفيذ استعلامات SQL عليها عبر واجهة برمجة تطبيقات الاستعلام.
* **[Managed Postgres](/ar/products/managed-postgres/overview) (إصدار تجريبي):** إنشاء خدمات Postgres والنسخ المتماثلة للقراءة وعمليات الاستعادة إلى نقطة زمنية محددة، وتعديل تهيئتها.
* **[ClickPipes](/ar/integrations/clickpipes/home):** استيعاب البيانات من التخزين الكائني وKafka وKinesis وPub/Sub وPostgres وMySQL وMongoDB وBigQuery.
* **[ClickStack](/ar/clickstack/overview):** إدارة المصادر ولوحات المعلومات والتنبيهات وخطافات الويب وعمليات البحث المحفوظة والأدوار في خدمة [Managed ClickStack](/ar/clickstack/deployment/managed).
* **الدوال المعرّفة من قِبل المستخدم:** اختبار الدوال المعرّفة من قِبل المستخدم القابلة للتنفيذ محليًا، ثم نشرها على خدمة Cloud.
* **النسخ الاحتياطية:** عرض النسخ الاحتياطية، وتعديل جدول النسخ الاحتياطي، واستعادة نسخة احتياطية إلى خدمة جديدة.
* **الوصول على مستوى المؤسسة:** المؤسسات والأعضاء والدعوات ومفاتيح API وسجل النشاط.

شغّل `clickhousectl cloud <command> --help` لعرض الخيارات المتاحة لأي أمر وصلاحيات مفتاح API التي يحتاجها.

## التثبيت {#installation}

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

يُثبّت البرنامج النصي `~/.local/bin/clickhousectl` إلى جانب اسم بديل هو `chctl`. تأكّد من إضافة `~/.local/bin` إلى متغير `PATH` لديك. وللاطلاع على طرق التثبيت الأخرى عبر npm وpip وuv وغيرها، راجع [التثبيت](/ar/concepts/features/interfaces/cli#installation).

## المصادقة {#authentication}

يمنح تسجيل الدخول عبر OAuth في المتصفح صلاحية للقراءة فقط. أما إنشاء الموارد أو تعديلها فيتطلب [مفتاح API](/ar/products/cloud/features/admin-features/api/openapi) مرتبطًا بدور يسمح بإجراء هذا التعديل.

```bash
# Read-only: OAuth device flow in your browser
clickhousectl cloud auth login

# Read and write: prompts for the API key and secret, keeping the secret out of shell history
clickhousectl cloud auth login --interactive

# Alternative for scripts
clickhousectl cloud auth login --api-key <key> --api-secret <secret>
```

يتحقق تسجيل الدخول من بيانات الاعتماد ثم يعرض الهوية. ويمكنك التحقق منها في أي وقت باستخدام `clickhousectl cloud auth whoami`. وإذا كنت تنتمي إلى عدة مؤسسات، فأضف `--org-id <org-id>` (أو `--org-name <name>`) إلى أوامر Cloud. أما في بيئة CI، فاضبط `CLICKHOUSE_CLOUD_API_KEY` و`CLICKHOUSE_CLOUD_API_SECRET` بدلاً من تسجيل الدخول. راجع [المصادقة](/ar/concepts/features/interfaces/cli#authentication) للاطلاع على أسبقية بيانات الاعتماد وكيفية تسجيل الخروج.

## أمثلة {#examples}

### إنشاء خدمة والاستعلام عنها {#create-and-query-a-service}

```bash
# Create a service. Save the initial password; it is printed only once.
# Omitting --ip-allow allows all addresses (0.0.0.0/0).
clickhousectl cloud service create --name analytics \
  --provider aws --region us-east-1 \
  --ip-allow '203.0.113.10/32=Office'

# Look up the service ID, then run SQL over the Query API
CH_ID=$(clickhousectl cloud service get --name analytics --json | jq -r .id)
clickhousectl cloud service query "$CH_ID" --query "SELECT version()"
```

يعود أمر الإنشاء قبل أن تصبح الخدمة قيد التشغيل. استطلع حالة الخدمة باستخدام `clickhousectl cloud service get "$CH_ID"` إلى أن تصبح قيمة `state` هي `running`.

عند أول استعلام باستخدام مفتاح API، يضيف clickhousectl مفتاح API الخاص بك إلى نقطة نهاية API للاستعلام الخاصة بالخدمة، وينشئ نقطة النهاية إن لم تكن موجودة، دون إنشاء أي مفتاح جديد. لجعل العملية تفشل بدلاً من ذلك، مرّر الخيار `--no-auto-enable`. وعند استخدام OAuth، لا ينفّذ `service query` سوى عبارات `SELECT` للقراءة فقط. تنتهي مهلة واجهة برمجة تطبيقات الاستعلام بعد نحو 30 ثانية، لذا استخدم `clickhouse client` للاستعلامات الطويلة وعمليات التحميل المجمّع.

### إنشاء خدمة Postgres مُدارة {#create-a-managed-postgres-service}

```bash
clickhousectl cloud postgres create --name app-db \
  --provider aws --region us-east-1 --size c6gd.xlarge --pg-version 18 \
  --ip-allow '203.0.113.10/32:5432=Office'
clickhousectl cloud postgres get <postgres-id>
clickhousectl cloud postgres certs get <postgres-id> --output ca.pem
```

لا يُعيد كلمة المرور وسلسلة الاتصال إلا الأمر `create`، لذا احرص على حفظهما. يؤدي إغفال الخيار `--ip-allow` إلى فتح المنفذين 5432 و6432 أمام جميع العناوين. انتظر حتى تصبح قيمة `state` هي `running`، ثم اتصل عبر `psql` باستخدام شهادة المرجع المصدق.

### فحص ClickPipes وClickStack والنسخ الاحتياطية {#inspect-clickpipes-clickstack-and-backups}

```bash
clickhousectl cloud clickpipe list "$CH_ID"
clickhousectl cloud clickstack source list <clickstack-service-id>
clickhousectl cloud backup list "$CH_ID"
```

تعمل أوامر القراءة هذه مع OAuth. أما إنشاء ClickPipe أو تعديل مورد في ClickStack فيتطلب مفتاح API؛ راجع أدلة المستودع أدناه.

### نشر دالة معرّفة من قبل المستخدم {#deploy-a-user-defined-function}

```bash
# Uploads clickhouse/udfs/my_udf/, waits for the build, then attaches that version to the service
clickhousectl cloud udf deploy my_udf --service "$CH_ID"
```

اختبر الدالة أولاً على خادم محلي باستخدام `clickhousectl local udf deploy my_udf`.

## إخراج JSON ووكلاء البرمجة {#json-output}

تقبل أوامر Cloud الخيار `--json`، كما تعتمد واجهة سطر الأوامر صيغة JSON تلقائيًا عند اكتشاف وكيل برمجة. وفي هذه الحالة يستخدم الأمر `cloud service query` الصيغة `JSONEachRow` افتراضيًا، لذا ينبغي للنصوص البرمجية التي تحلّل إخراجه أن تمرّر الخيار `--format`، مثل `--format TabSeparated`. راجع [إخراج JSON](/ar/concepts/features/interfaces/cli#json-output) و[رموز الخروج](/ar/concepts/features/interfaces/cli#exit-codes). ثبّت ClickHouse agent skills باستخدام `clickhousectl skills`.
