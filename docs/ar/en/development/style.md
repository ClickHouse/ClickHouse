<div id="general-recommendations">
  ## توصيات عامة
</div>

فيما يلي توصيات وليست متطلبات.
إذا كنت تُعدّل الشيفرة، فمن المنطقي الالتزام بتنسيق الشيفرة الحالي.
يلزم اتباع أسلوب موحّد في كتابة الشيفرة لتحقيق الاتساق. فالاتساق يسهّل قراءة الشيفرة، كما يسهّل البحث فيها أيضًا.
كثير من هذه القواعد لا تستند إلى أسباب منطقية، بل تفرضها ممارسات راسخة.

<div id="formatting">
  ## التنسيق
</div>

**1.** يتم تنسيق معظم الكود تلقائيًا عبر `clang-format`.

**2.** المسافات البادئة هي 4 مسافات. اضبط بيئة التطوير لديك بحيث يُضيف مفتاح Tab أربع مسافات.

**3.** يجب أن تكون الأقواس المعقوفة الفاتحة والمغلقة في سطر منفصل.

```cpp
inline void readBoolText(bool & x, ReadBuffer & buf)
{
    char tmp = '0';
    readChar(tmp, buf);
    x = tmp != '0';
}
```

**4.** إذا كان متن الدالة بأكمله عبارة عن `statement` واحدة، يمكن وضعها في سطر واحد. ضع مسافات حول الأقواس المعقوفة (باستثناء المسافة في نهاية السطر).

```cpp
inline size_t mask() const                { return buf_size() - 1; }
inline size_t place(HashValue x) const    { return x & mask(); }
```

**5.** للدوال. لا تضع مسافات حول الأقواس.

```cpp
void reinsert(const Value & x)
```

```cpp
memcpy(&buf[place_value], &x, sizeof(x));
```

**6.** في تعبيرات `if` و`for` و`while` وغيرها، تُضاف مسافة قبل القوس الافتتاحي (خلافًا لاستدعاءات الدوال).

```cpp
for (size_t i = 0; i < rows; i += storage.index_granularity)
```

**7.** أضف مسافات حول العوامل الثنائية (`+`, `-`, `*`, `/`, `%`, ...) والعامل الثلاثي `?:`.

```cpp
UInt16 year = (s[0] - '0') * 1000 + (s[1] - '0') * 100 + (s[2] - '0') * 10 + (s[3] - '0');
UInt8 month = (s[5] - '0') * 10 + (s[6] - '0');
UInt8 day = (s[8] - '0') * 10 + (s[9] - '0');
```

**8.** إذا أُدخل حرف تغذية السطر، ضع المعامل في سطر جديد وزد المسافة البادئة قبله.

```cpp
if (elapsed_ns)
    message << " ("
        << rows_read_on_server * 1000000000 / elapsed_ns << " rows/s., "
        << bytes_read_on_server * 1000.0 / elapsed_ns << " MB/s.) ";
```

**9.** يمكنك استخدام المسافات للمحاذاة داخل السطر عند الحاجة.

```cpp
dst.ClickLogID         = click.LogID;
dst.ClickEventID       = click.EventID;
dst.ClickGoodEvent     = click.GoodEvent;
```

**10.** لا تستخدم مسافات حول العوامل `.`، `->`.

إذا لزم الأمر، يمكن نقل المعامل إلى السطر التالي. في هذه الحالة، تزداد المسافة البادئة أمامه.

**11.** لا تستخدم مسافة للفصل بين العوامل الأحادية (`--`، `++`، `*`، `&`، ...) والوسيط.

**12.** ضع مسافة بعد الفاصلة، لا قبلها. وتسري القاعدة ذاتها على الفاصلة المنقوطة داخل تعبير `for`.

**13.** لا تستخدم مسافات للفصل في المعامل `[]`.

**14.** في تعبير `template <...>`، ضع مسافة بين `template` و`<`؛ ولا مسافات بعد `<` أو قبل `>`.

```cpp
template <typename TKey, typename TValue>
struct AggregatedStatElement
{}
```

**15.** في الفئات والبنى، اكتب `public` و`private` و`protected` على المستوى ذاته مع `class/struct`، وضع مسافة بادئة لبقية الشيفرة.

```cpp
template <typename T>
class MultiVersion
{
public:
    /// Version of object for usage. shared_ptr manage lifetime of version.
    using Version = std::shared_ptr<const T>;
    ...
}
```

**16.** إذا كان نفس `namespace` مستخدمًا في الملف بأكمله ولم يكن ثمة شيء آخر ذو أهمية، فلا حاجة إلى مسافة بادئة داخل `namespace`.

**17.** إذا كانت الكتلة الخاصة بـ `if` أو `for` أو `while` أو أي تعبير آخر تحتوي على جملة `statement` واحدة فقط، فالأقواس المعقوفة اختيارية. ضع جملة `statement` في سطر منفصل عوضاً عن ذلك. تسري هذه القاعدة أيضاً على `if` و`for` و`while` المتداخلة ...

ولكن إذا كانت `statement` الداخلية تحتوي على أقواس معقوفة أو `else`، فيجب كتابة الكتلة الخارجية بأقواس معقوفة.

```cpp
/// Finish write.
for (auto & stream : streams)
    stream.second->finalize();
```

**18.** يجب ألا تكون هناك مسافات في نهايات الأسطر.

**19.** ملفات الشيفرة المصدرية مُرمَّزة بـ UTF-8.

**20.** يمكن استخدام الأحرف غير ASCII في القيم الحرفية النصية.

```cpp
<< ", " << (timer.elapsed() / chunks_stats.hits) << " μsec/hit.";
```

**21.** لا تكتب عدة تعبيرات في سطر واحد.

**22.** اجمع مقاطع الشيفرة داخل الدوال، وافصل بينها بسطر فارغ واحد كحد أقصى.

**23.** افصل بين الدوال والفئات وما إلى ذلك بسطر فارغ واحد أو سطرين فارغين.

**24.** يجب كتابة `A const` (إذا كان مرتبطًا بقيمة) قبل اسم النوع.

```cpp
//correct
const char * pos
const std::string & s
//incorrect
char const * pos
```

**25.** عند التصريح بمؤشر أو مرجع، يجب إحاطة الرمزين `*` و `&` بمسافات من كلا الجانبين.

```cpp
//correct
const char * pos
//incorrect
const char* pos
const char *pos
```

**26.** عند استخدام أنواع القوالب، امنحها أسماءً مستعارة باستخدام الكلمة المحجوزة `using` (إلا في أبسط الحالات).

بعبارة أخرى، لا تُحدَّد معلمات القالب إلا في `using` ولا تُكرَّر في الشيفرة.

يمكن تعريف `using` محليًا، مثلًا داخل دالة.

```cpp
//correct
using FileStreams = std::map<std::string, std::shared_ptr<Stream>>;
FileStreams streams;
//incorrect
std::map<std::string, std::shared_ptr<Stream>> streams;
```

**27.** لا تُصرِّح بعدة متغيرات من أنواع مختلفة في عبارة واحدة.

```cpp
//incorrect
int x, *y;
```

**28.** لا تستخدم تحويلات النمط C.

```cpp
//incorrect
std::cerr << (int)c <<; std::endl;
//correct
std::cerr << static_cast<int>(c) << std::endl;
```

**29.** في الأصناف وبُنى `struct`، اجمع الأعضاء والدوال كلًّا على حدة داخل كل نطاق رؤية.

**30.** في الأصناف وبُنى `struct` الصغيرة، لا يلزم فصل تصريح الطريقة عن تنفيذها.

وينطبق الأمر نفسه على الطرق الصغيرة في أي صنف أو بنية `struct`.

في أصناف وبُنى `Template`، لا تفصل تصريحات الطرق عن تنفيذها (لأنه بخلاف ذلك يجب تعريفها في وحدة الترجمة نفسها).

**31.** يمكنك لفّ الأسطر عند 140 حرفًا بدلًا من 80.

**32.** استخدم دائمًا معاملي الزيادة/الإنقاص السابقة إذا لم تكن الصيغة اللاحقة مطلوبة.

```cpp
for (Names::const_iterator it = column_names.begin(); it != column_names.end(); ++it)
```

<div id="comments">
  ## التعليقات
</div>

**1.** احرص على إضافة تعليقات إلى جميع الأجزاء غير الواضحة من الشيفرة.

هذا مهم جدًا. فقد تساعدك كتابة التعليق على إدراك أن الشيفرة غير ضرورية، أو أن تصميمها غير صحيح.

```cpp
/** Part of piece of memory, that can be used.
  * For example, if internal_buffer is 1MB, and there was only 10 bytes loaded to buffer from file for reading,
  * then working_buffer will have size of only 10 bytes
  * (working_buffer.end() will point to position right after those 10 bytes available for read).
  */
```

**2.** يمكن أن تكون التعليقات مفصلة بالقدر المطلوب.

**3.** ضع التعليقات قبل الشيفرة التي تشرحها. وفي حالات نادرة، يمكن أن تأتي التعليقات بعد الشيفرة في السطر نفسه.

```cpp
/** Parses and executes the query.
*/
void executeQuery(
    ReadBuffer & istr, /// Where to read the query from (and data for INSERT, if applicable)
    WriteBuffer & ostr, /// Where to write the result
    Context & context, /// DB, tables, data types, engines, functions, aggregate functions...
    BlockInputStreamPtr & query_plan, /// Here could be written the description on how query was executed
    QueryProcessingStage::Enum stage = QueryProcessingStage::Complete /// Up to which stage process the SELECT query
    )
```

**4.** يجب أن تكون التعليقات مكتوبة باللغة الإنجليزية فقط.

**5.** إذا كنت تكتب مكتبة، فأضف في الملف الترويسي الرئيسي تعليقاتٍ تفصيلية تشرحها.

**6.** لا تضف تعليقات لا تقدم معلومات إضافية. وعلى وجه الخصوص، لا تترك تعليقات فارغة مثل هذه:

```cpp
/*
* Procedure Name:
* Original procedure name:
* Author:
* Date of creation:
* Dates of modification:
* Modification authors:
* Original file name:
* Purpose:
* Intent:
* Designation:
* Classes used:
* Constants:
* Local variables:
* Parameters:
* Date of creation:
* Purpose:
*/
```

المثال مقتبس من المصدر http://home.tamk.fi/~jaalto/course/coding-style/doc/unmaintainable-code/.

**7.** لا تكتب تعليقات عديمة الفائدة (اسم المؤلف، تاريخ الإنشاء ..) في بداية كل ملف.

**8.** تبدأ التعليقات أحادية السطر بثلاث شرطات مائلة: `///`، وتبدأ التعليقات متعددة الأسطر بـ `/**`. وتُعد هذه التعليقات &quot;توثيقية&quot;.

ملاحظة: يمكنك استخدام Doxygen لإنشاء توثيق من هذه التعليقات. لكن Doxygen لا يُستخدم عمومًا لأنه من الأسهل تصفح الشيفرة داخل بيئة التطوير المتكاملة.

**9.** يجب ألا تحتوي التعليقات متعددة الأسطر على أسطر فارغة في البداية أو النهاية (باستثناء السطر الذي يُغلق التعليق متعدد الأسطر).

**10.** عند تعطيل الشيفرة بالتعليق، استخدم التعليقات العادية، لا التعليقات &quot;التوثيقية&quot;.

**11.** احذف الأجزاء المُعلَّق عليها من الشيفرة قبل تنفيذ commit.

**12.** لا تستخدم ألفاظًا نابية في التعليقات أو الشيفرة.

**13.** لا تستخدم الأحرف الكبيرة. ولا تفرط في استخدام علامات الترقيم.

```cpp
/// WHAT THE FAIL???
```

**14.** لا تستخدم التعليقات لعمل الفواصل.

```cpp
///******************************************************
```

**15.** لا تفتح نقاشات في التعليقات.

```cpp
/// Why did you do this stuff?
```

**16.** لا حاجة إلى كتابة تعليق في نهاية كتلة يشرح ما تتناوله.

```cpp
/// for
```

<div id="names">
  ## الأسماء
</div>

**1.** استخدم الأحرف الصغيرة والشرطة السفلية في أسماء المتغيرات وأعضاء الصنف.

```cpp
size_t max_block_size;
```

**2.** بالنسبة إلى أسماء الدوال (الطرائق)، استخدم صيغة `camelCase` التي تبدأ بحرف صغير.

```cpp
std::string getName() const override { return "Memory"; }
```

**3.** بالنسبة إلى أسماء الأصناف (structs)، استخدم CamelCase بحيث يبدأ بحرف كبير. ولا تُستخدم للواجهات أي بادئات غير I.

```cpp
class StorageMemory : public IStorage
```

**4.** تُسمّى تعليمة `using` بالطريقة نفسها التي تُسمّى بها الأصناف.

**5.** أسماء وسيطات نوع القالب: في الحالات البسيطة، استخدم `T`؛ `T`، `U`؛ `T1`، `T2`.

في الحالات الأكثر تعقيدًا، إمّا اتّباع قواعد تسمية الأصناف، أو إضافة البادئة `T`.

```cpp
template <typename TKey, typename TValue>
struct AggregatedStatElement
```

**6.** أسماء الوسائط الثابتة في القوالب: إمّا أن تتبع قواعد تسمية المتغيرات، أو يُستخدم `N` في الحالات البسيطة.

```cpp
template <bool without_www>
struct ExtractDomain
```

**7.** بالنسبة إلى الأصناف المجرّدة (الواجهات)، يمكنك إضافة البادئة `I`.

```cpp
class IProcessor
```

**8.** إذا كنت تستخدم متغيرًا ضمن النطاق المحلي، فيمكنك استخدام اسمٍ مختصر.

في جميع الحالات الأخرى، استخدم اسمًا يعبّر عن المعنى.

```cpp
bool info_successfully_loaded = false;
```

**9.** تُكتب أسماء `define` والثوابت العامة بصيغة ALL&#95;CAPS مع استخدام الشرطات السفلية.

```cpp
#define MAX_SRC_TABLE_NAMES_TO_STORE 1000
```

**10.** يجب أن تتبع أسماء الملفات النمط نفسه لمحتواها.

إذا كان الملف يحتوي على صنف واحد، فسمِّ الملف بالاسم نفسه المستخدم للصنف (CamelCase).

إذا كان الملف يحتوي على دالة واحدة، فسمِّ الملف بالاسم نفسه المستخدم للدالة (camelCase).

**11.** إذا كان الاسم يحتوي على اختصار، فحينئذٍ:

* في أسماء المتغيرات، يجب أن يُكتب الاختصار بأحرف صغيرة `mysql_connection` (وليس `mySQL_connection`).
* في أسماء الأصناف والدوال، احتفِظ بالأحرف الكبيرة في الاختصار `MySQLConnection` (وليس `MySqlConnection`).

**12.** يجب أن تُسمّى معاملات المُنشئ التي تُستخدم فقط لتهيئة أعضاء الصنف بالاسم نفسه لأعضاء الصنف، ولكن مع إضافة شرطة سفلية في النهاية.

```cpp
FileQueueProcessor(
    const std::string & path_,
    const std::string & prefix_,
    std::shared_ptr<FileHandler> handler_)
    : path(path_),
    prefix(prefix_),
    handler(handler_),
    log(&Logger::get("FileQueueProcessor"))
{
}
```

يمكن حذف اللاحقة underscore إذا لم يُستخدَم المعامل داخل جسم المُنشئ.

**13.** لا يوجد فرق بين أسماء المتغيرات المحلية وأعضاء الصنف (ولا حاجة إلى بادئات).

```cpp
timer (not m_timer)
```

**14.** فيما يخص الثوابت في `enum`، استخدم CamelCase بحيث يبدأ بحرف كبير. ويُعد ALL&#95;CAPS مقبولًا أيضًا. إذا كان `enum` غير محلي النطاق، فاستخدم `enum class`.

```cpp
enum class CompressionMethod
{
    QuickLZ = 0,
    LZ4     = 1,
};
```

**15.** يجب أن تكون جميع الأسماء باللغة الإنجليزية. لا يُسمح بكتابة الكلمات العبرية بحروف لاتينية.

وليس T&#95;PAAMAYIM&#95;NEKUDOTAYIM

**16.** الاختصارات مقبولة إذا كانت شائعة ومعروفة (أي إذا كان بإمكانك بسهولة العثور على معنى الاختصار في Wikipedia أو عبر محرك بحث).

`AST`، `SQL`.

وليس `NVDH` (مجرد أحرف عشوائية)

الكلمات غير المكتملة مقبولة إذا كانت الصيغة المختصرة شائعة الاستخدام.

يمكنك أيضًا استخدام اختصار إذا كان الاسم الكامل مذكورًا بجواره في التعليقات.

**17.** يجب أن تحمل أسماء الملفات التي تحتوي على شيفرة مصدرية بلغة C++ الامتداد `.cpp`. ويجب أن تحمل الملفات الرأسية الامتداد `.h`.

<div id="how-to-write-code">
  ## كيفية كتابة الشيفرة
</div>

**1.** إدارة الذاكرة.

لا يجوز استخدام التحرير اليدوي للذاكرة (`delete`) إلا في شيفرة المكتبات.

في شيفرة المكتبات، لا يجوز استخدام العامل `delete` إلا داخل المُدمِّرات.

في شيفرة التطبيق، يجب أن يحرّر الذاكرةَ الكائنُ الذي يملكها.

أمثلة:

* أسهل طريقة هي وضع كائن على المكدس، أو جعله عضوًا في فئة أخرى.
* عند وجود عدد كبير من الكائنات الصغيرة، استخدم الحاويات.
* للتحرير التلقائي لعدد صغير من الكائنات الموجودة في الكومة، استخدم `shared_ptr/unique_ptr`.

**2.** إدارة الموارد.

استخدم `RAII` وراجع ما سبق.

**3.** معالجة الأخطاء.

استخدم الاستثناءات. في معظم الحالات، يكفي أن ترمي استثناءً، ولا حاجة إلى التقاطه (بفضل `RAII`).

في تطبيقات معالجة البيانات دون اتصال، يكون من المقبول غالبًا عدم التقاط الاستثناءات.

في الخوادم التي تتعامل مع طلبات المستخدمين، يكفي عادةً التقاط الاستثناءات في المستوى الأعلى من معالج الاتصال.

في دوال الخيوط، ينبغي التقاط جميع الاستثناءات والاحتفاظ بها لإعادة رميها في الخيط الرئيسي بعد `join`.

```cpp
/// If there weren't any calculations yet, calculate the first block synchronously
if (!started)
{
    calculate();
    started = true;
}
else /// If calculations are already in progress, wait for the result
    pool.wait();

if (exception)
    exception->rethrow();
```

لا تُخفِ الاستثناءات أبدًا من دون معالجتها. ولا تكتفِ بتسجيل جميع الاستثناءات في السجلّ دون تمييز.

```cpp
//Not correct
catch (...) {}
```

إذا كنت بحاجة إلى تجاهل بعض الاستثناءات، فافعل ذلك فقط مع استثناءات محددة، وأعِد تمرير الباقي.

```cpp
catch (const DB::Exception & e)
{
    if (e.code() == ErrorCodes::UNKNOWN_AGGREGATE_FUNCTION)
        return nullptr;
    else
        throw;
}
```

عند استخدام الدوال مع رموز الاستجابة أو `errno`، تحقّق دائمًا من النتيجة، وارمِ استثناءً عند حدوث خطأ.

```cpp
if (0 != close(fd))
    throw ErrnoException(ErrorCodes::CANNOT_CLOSE_FILE, "Cannot close file {}", file_name);
```

يمكنك استخدام assert للتحقق من ثبات الشروط في الشيفرة.

**4.** أنواع الاستثناءات.

لا حاجة إلى استخدام تسلسل هرمي معقّد للاستثناءات في شيفرة التطبيق. يجب أن يكون نص الاستثناء واضحًا لمسؤول النظام.

**5.** إطلاق الاستثناءات من الدوال المدمّرة.

هذا غير مستحسن، لكنه مسموح.

استخدم الخيارات التالية:

* أنشئ دالة (`done()` أو `finalize()`) تنفّذ مسبقًا كل ما قد يؤدي إلى استثناء. وإذا جرى استدعاء هذه الدالة، فلا ينبغي أن يحدث أي استثناء لاحقًا في الدالة المدمّرة.
* يمكن نقل المهام المعقّدة جدًا (مثل إرسال الرسائل عبر الشبكة) إلى دالة منفصلة يتعيّن على مستخدم الصنف استدعاؤها قبل التدمير.
* إذا حدث استثناء في الدالة المدمّرة، فمن الأفضل تسجيله بدلًا من إخفائه (إذا كان `logger` متاحًا).
* في التطبيقات البسيطة، من المقبول الاعتماد على `std::terminate` (في حالات `noexcept` الافتراضية في C++11) لمعالجة الاستثناءات.

**6.** كتل الشيفرة المجهولة.

يمكنك إنشاء كتلة شيفرة منفصلة داخل دالة واحدة لجعل بعض المتغيرات محلية، بحيث تُستدعى الدوال المدمّرة عند الخروج من الكتلة.

```cpp
Block block = data.in->read();

{
    std::lock_guard<std::mutex> lock(mutex);
    data.ready = true;
    data.block = block;
}

ready_any.set();
```

**7.** تعدد الخيوط.

في برامج معالجة البيانات دون اتصال:

* حاول تحقيق أفضل أداء ممكن على نواة CPU واحدة. وبعد ذلك يمكنك موازاة الشيفرة عند الحاجة.

في تطبيقات الخادم:

* استخدم مجموعة الخيوط لمعالجة الطلبات. حتى الآن، لم نواجه أي مهام تتطلب تبديل السياق في حيّز المستخدم.

لا يُستخدم fork للموازاة.

**8.** مزامنة الخيوط.

غالبًا ما يمكن جعل الخيوط المختلفة تستخدم خلايا ذاكرة مختلفة (والأفضل: أسطرًا مختلفة من ذاكرة التخزين المؤقت)، وألا تستخدم أي مزامنة بين الخيوط (باستثناء `joinAll`).

إذا كانت المزامنة مطلوبة، ففي معظم الحالات يكفي استخدام mutex مع `lock_guard`.

وفي الحالات الأخرى، استخدم بدائيات المزامنة على مستوى النظام. لا تستخدم الانتظار المشغول.

يجب استخدام العمليات الذرية فقط في أبسط الحالات.

لا تحاول تنفيذ بُنى بيانات بلا أقفال ما لم يكن ذلك مجال خبرتك الأساسي.

**9.** المؤشرات مقابل المراجع.

في معظم الحالات، فضّل المراجع.

**10.** `const`.

استخدم المراجع الثابتة، والمؤشرات إلى ثوابت، و`const_iterator`، وطرق `const`.

اعتبر `const` الخيار الافتراضي، ولا تستخدم غير `const` إلا عند الضرورة.

عند تمرير المتغيرات بالقيمة، لا يكون استخدام `const` منطقيًا في العادة.

**11.** unsigned.

استخدم `unsigned` عند الضرورة.

**12.** الأنواع الرقمية.

استخدم الأنواع `UInt8` و`UInt16` و`UInt32` و`UInt64` و`Int8` و`Int16` و`Int32` و`Int64`، بالإضافة إلى `size_t` و`ssize_t` و`ptrdiff_t`.

لا تستخدم هذه الأنواع للأعداد: `signed/unsigned long` و`long long` و`short` و`signed/unsigned char` و`char`.

**13.** تمرير الوسائط.

مرّر القيم المعقّدة بالقيمة إذا كان سيتم نقلها، واستخدم `std::move`؛ ومرّرها بالمرجع إذا كنت تريد تحديث القيمة داخل حلقة.

إذا كانت الدالة تستحوذ على ملكية كائن أُنشئ على الكومة، فاجعل نوع الوسيطة `shared_ptr` أو `unique_ptr`.

**14.** القيم المُعادة.

في معظم الحالات، استخدم `return` فقط. لا تكتب `return std::move(res)`.

إذا كانت الدالة تخصّص كائنًا على الكومة وتعيده، فاستخدم `shared_ptr` أو `unique_ptr`.

في حالات نادرة (مثل تحديث قيمة داخل حلقة)، قد تحتاج إلى إعادة القيمة عبر وسيطة. في هذه الحالة، يجب أن تكون الوسيطة مرجعًا.

```cpp
using AggregateFunctionPtr = std::shared_ptr<IAggregateFunction>;

/** Allows creating an aggregate function by its name.
  */
class AggregateFunctionFactory
{
public:
    AggregateFunctionFactory();
    AggregateFunctionPtr get(const String & name, const DataTypes & argument_types) const;
```

**15.** `namespace`.

لا حاجة إلى استخدام `namespace` منفصل لشيفرة التطبيق.

ولا تحتاج المكتبات الصغيرة إلى ذلك أيضًا.

أما المكتبات المتوسطة والكبيرة، فضع كل شيء داخل `namespace`.

في ملف `.h` الخاص بالمكتبة، يمكنك استخدام `namespace detail` لإخفاء تفاصيل التنفيذ التي لا تحتاجها شيفرة التطبيق.

وفي ملف `.cpp`، يمكنك استخدام `static` أو `namespace` مجهول لإخفاء الرموز.

كذلك، يمكن استخدام `namespace` مع `enum` لمنع انتقال الأسماء المقابلة إلى `namespace` خارجي (لكن من الأفضل استخدام `enum class`).

**16.** التهيئة المؤجلة.

إذا كانت التهيئة تتطلب وسائط، فعادةً لا ينبغي كتابة مُنشئ افتراضي.

وإذا احتجت لاحقًا إلى تأجيل التهيئة، فيمكنك إضافة مُنشئ افتراضي يُنشئ كائنًا غير صالح. أو، إذا كان عدد الكائنات قليلًا، يمكنك استخدام `shared_ptr/unique_ptr`.

```cpp
Loader(DB::Connection * connection_, const std::string & query, size_t max_block_size_);

/// For deferred initialization
Loader() {}
```

**17.** الدوال الافتراضية.

إذا لم يكن الصنف مخصّصًا للاستخدام متعدّد الأشكال، فلا حاجة إلى جعل الدوال `virtual`. وينطبق ذلك أيضًا على المدمّر.

**18.** الترميزات.

استخدم UTF-8 في كل مكان. استخدم `std::string` و `char *`. لا تستخدم `std::wstring` و `wchar_t`.

**19.** التسجيل.

راجع الأمثلة في أنحاء الشيفرة كافة.

قبل إجراء `commit`، احذف كل تسجيلات السجل عديمة المعنى وتسجيلات Debug، وأي أنواع أخرى من مخرجات Debug.

يجب تجنّب التسجيل داخل الحلقات، حتى على مستوى Trace.

يجب أن تكون السجلات قابلة للقراءة عند أي مستوى تسجيل.

ينبغي، في الغالب، استخدام التسجيل في شيفرة التطبيق فقط.

يجب أن تُكتب رسائل السجل باللغة الإنجليزية.

ويُفضَّل أن يكون السجل مفهومًا لمسؤول النظام.

لا تستخدم ألفاظًا نابية في السجل.

استخدم ترميز UTF-8 في السجل. وفي حالات نادرة، يمكنك استخدام محارف غير ASCII في السجل.

**20.** الإدخال والإخراج.

لا تستخدم `iostreams` في الحلقات الداخلية الحسّاسة لأداء التطبيق (ولا تستخدم `stringstream` أبدًا).

استخدم مكتبة `DB/IO` بدلًا من ذلك.

**21.** التاريخ والوقت.

راجع مكتبة `DateLUT`.

**22.** include.

استخدم دائمًا `#pragma once` بدلًا من حواجز التضمين.

**23.** using.

لا يُستخدم `using namespace`. يمكنك استخدام `using` مع عنصر محدّد، لكن اجعله محليًا داخل صنف أو دالة.

**24.** لا تستخدم `trailing return type` للدوال إلا عند الضرورة.

```cpp
auto f() -> void
```

**25.** تصريح المتغيرات وتهيئتها.

```cpp
//right way
std::string s = "Hello";
std::string s{"Hello"};

//wrong way
auto s = std::string{"Hello"};
```

**26.** بالنسبة إلى الدوال الافتراضية، اكتب `virtual` في الفئة الأساسية، لكن اكتب `override` بدلًا من `virtual` في الفئات المشتقة.

<div id="unused-features-of-c">
  ## ميزات C++ غير المستخدمة
</div>

**1.** لا تُستخدم الوراثة الافتراضية.

**2.** التراكيب التي تتوفر لها صياغات مختصرة مريحة في C++ الحديث، مثلًا.

```cpp
// Traditional way without syntactic sugar
template <typename G, typename = std::enable_if_t<std::is_same<G, F>::value, void>> // SFINAE via std::enable_if, usage of ::value
std::pair<int, int> func(const E<G> & e) // explicitly specified return type
{
    if (elements.count(e)) // .count() membership test
    {
        // ...
    }

    elements.erase(
        std::remove_if(
            elements.begin(), elements.end(),
            [&](const auto x){
                return x == 1;
            }),
        elements.end()); // remove-erase idiom

    return std::make_pair(1, 2); // create pair via make_pair()
}

// With syntactic sugar (C++14/17/20)
template <typename G>
requires std::same_v<G, F> // SFINAE via C++20 concept, usage of C++14 template alias
auto func(const E<G> & e) // auto return type (C++14)
{
    if (elements.contains(e)) // C++20 .contains membership test
    {
        // ...
    }

    elements.erase_if(
        elements,
        [&](const auto x){
            return x == 1;
        }); // C++20 std::erase_if

    return {1, 2}; // or: return std::pair(1, 2); // create pair via initialization list or value initialization (C++17)
}
```

**5.** تُكتب الشيفرة لمعمارية CPU ‏x86&#95;64.

ومجموعة تعليمات CPU هي الحد الأدنى المدعوم عبر خوادمنا. وهي حاليًا SSE 4.2.

**6.** استخدم خيارات التصريف `-Wall -Wextra -Werror -Weverything` مع بعض الاستثناءات.

<div id="general-recommendations">
  ## توصيات عامة
</div>

**1.** اكتب أقل قدر ممكن من الشيفرة.

**2.** جرّب أبسط حل ممكن.

**3.** لا تكتب شيفرة قبل أن تعرف كيف ستعمل، وكيف ستعمل الحلقة الداخلية.

**4.** في أبسط الحالات، استخدم `using` بدلًا من الفئات أو البُنى.

**6.** يُشجَّع على تبسيط الشيفرة. قلّل حجمها حيثما أمكن.

<div id="additional-recommendations">
  ## توصيات إضافية
</div>

**1.** التصريح بـ `std::` صراحةً للأنواع الواردة من `stddef.h`

غير موصى به. بمعنى آخر، نوصي بكتابة `size_t` بدلًا من `std::size_t` لأنه أقصر.

ومن المقبول إضافة `std::`.

**2.** التصريح بـ `std::` صراحةً للدوال الواردة من مكتبة C القياسية

غير موصى به. بمعنى آخر، اكتب `memcpy` بدلًا من `std::memcpy`.

والسبب هو وجود دوال مشابهة غير قياسية، مثل `memmem`. ونحن نستخدم هذه الدوال أحيانًا. وهذه الدوال غير موجودة ضمن `namespace std`.

إذا كنت تكتب `std::memcpy` بدلًا من `memcpy` في كل موضع، فسيبدو `memmem` من دون `std::` غريبًا.

ومع ذلك، يمكنك استخدام `std::` إذا كنت تفضّل ذلك.

**3.** استخدام دوال من C عندما تكون الدوال نفسها متاحة في مكتبة C++ القياسية.

هذا مقبول إذا كان أكثر كفاءة.

على سبيل المثال، استخدم `memcpy` بدلًا من `std::copy` لنسخ كتل كبيرة من الذاكرة.

**4.** وسائط الدوال متعددة الأسطر.

أيٌّ من أنماط التفاف الأسطر التالية مسموح به:

```cpp
function(
  T1 x1,
  T2 x2)
```

```cpp
function(
  size_t left, size_t right,
  const & RangesInDataParts ranges,
  size_t limit)
```

```cpp
function(size_t left, size_t right,
  const & RangesInDataParts ranges,
  size_t limit)
```

```cpp
function(size_t left, size_t right,
      const & RangesInDataParts ranges,
      size_t limit)
```

```cpp
function(
      size_t left,
      size_t right,
      const & RangesInDataParts ranges,
      size_t limit)
```
