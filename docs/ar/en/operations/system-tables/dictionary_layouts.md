<div id="description">
  ## الوصف
</div>

تتضمن قائمة بتخطيطات القواميس التي يدعمها الخادم، إلى جانب الوثائق المضمّنة لكل تخطيط. ويحدّد تخطيط القاموس كيفية تخزينه في الذاكرة (أو على القرص) وكيفية البحث فيه؛ ويُحدَّد في عبارة `LAYOUT` ضمن استعلام `CREATE DICTIONARY`.

<div id="columns">
  ## الأعمدة
</div>

{/*AUTOGENERATED_START*/ }

* `name` ([String](/ar/sql-reference/data-types/string)) — اسم تخطيط القاموس، كما هو محدد في عبارة LAYOUT.
* `is_complex` ([UInt8](/ar/sql-reference/data-types/int-uint)) — ما إذا كان التخطيط يتطلب مفتاحًا معقدًا (أي مفتاحًا يتكون من عدة سمات أو من نوع ليس عددًا صحيحًا).
* `description` ([String](/ar/sql-reference/data-types/string)) — وصف عام لوظيفة تخطيط القاموس.
* `syntax` ([String](/ar/sql-reference/data-types/string)) — كيفية تحديد التخطيط في عبارة LAYOUT ضمن استعلام CREATE DICTIONARY.
* `examples` ([String](/ar/sql-reference/data-types/string)) — أمثلة استخدام.
* `introduced_in` ([String](/ar/sql-reference/data-types/string)) — إصدار ClickHouse الذي طُرح فيه هذا التخطيط لأول مرة، بصيغة major.minor.
* `related` ([Array](/ar/sql-reference/data-types/array)([String](/ar/sql-reference/data-types/string))) — أسماء تخطيطات القواميس ذات الصلة.

{/*AUTOGENERATED_END*/ }

<div id="example">
  ## مثال
</div>

```sql title="Query"
SELECT name, is_complex, syntax
FROM system.dictionary_layouts
WHERE name IN ('flat', 'hashed', 'complex_key_hashed')
ORDER BY name
```

```text title="Response"
┌─name───────────────┬─is_complex─┬─syntax───────────────────────────────────────────────────┐
│ complex_key_hashed │          1 │ LAYOUT(COMPLEX_KEY_HASHED())                             │
│ flat               │          0 │ LAYOUT(FLAT([INITIAL_ARRAY_SIZE n] [MAX_ARRAY_SIZE n]))  │
│ hashed             │          0 │ LAYOUT(HASHED())                                         │
└────────────────────┴────────────┴──────────────────────────────────────────────────────────┘
```
