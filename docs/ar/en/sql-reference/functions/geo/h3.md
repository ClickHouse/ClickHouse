<div id="h3-index">
  ## فهرس H3
</div>

‏[H3](https://h3geo.org/) هو نظام فهرسة جغرافية تُقسَّم فيه سطح الأرض إلى شبكة من الخلايا السداسية المتساوية. وهذا النظام ذو تسلسل هرمي، أي إن كل سداسي في المستوى الأعلى (&quot;الأصل&quot;) يمكن تقسيمه إلى سبعة سداسيات أصغر متساوية (&quot;الفروع&quot;)، وهكذا.

يُسمى مستوى هذا التسلسل الهرمي `resolution`، ويمكن أن يأخذ قيمة من `0` إلى `15`، حيث يمثّل `0` المستوى `base` الذي يضم أكبر الخلايا وأقلها دقة.

يمكن تحويل زوج من خط العرض وخط الطول إلى فهرس H3 بطول 64 بت، يحدّد خليةً في الشبكة.

يُستخدم فهرس H3 أساسًا لتجميع المواقع وغيرها من المعالجات الجغرافية المكانية.

يتوفر الوصف الكامل لنظام H3 على [موقع Uber Engineering](https://www.uber.com/blog/h3/).

<div id="h3isvalid">
  ## h3IsValid
</div>

يتحقّق مما إذا كان الرقم يمثّل فهرس [H3](#h3-index) صالحًا.

**البنية**

```sql
h3IsValid(h3index)
```

**المعامل**

* `h3index` — رقم فهرس السداسي. [UInt64](../../data-types/int-uint.md).

**القيم المُعادة**

* 1 — يمثّل الرقم فهرس H3 صالحًا. [UInt8](../../data-types/int-uint.md).
* 0 — لا يمثّل الرقم فهرس H3 صالحًا. [UInt8](../../data-types/int-uint.md).

**مثال**

```sql title="Query"
SELECT h3IsValid(630814730351855103) AS h3IsValid;
```

```text title="Response"
┌─h3IsValid─┐
│         1 │
└───────────┘
```

**الصيغة**


```sql title="Query"
SELECT h3GetResolution(639821929606596015) AS resolution;
```

```text title="Response"
┌─resolution─┐

└────────────┘
```

<div id="geotoh3">
  ## geoToH3
</div>

يُرجع فهرس [H3](#h3-index) للنقطة `(lat, lon)` عند درجة الدقة المحددة.

**الصيغة**

```sql
geoToH3(lat, lon, resolution)
```

**الوسائط**

* `lat` — خط العرض. [Float64](../../data-types/float.md).
* `lon` — خط الطول. [Float64](../../data-types/float.md).
* `resolution` — دقة الفهرس. النطاق: `[0, 15]`. [UInt8](../../data-types/int-uint.md).

**القيم المُعادة**

* رقم فهرس الخلية السداسية. [UInt64](../../data-types/int-uint.md).
* 0 في حال حدوث خطأ. [UInt64](../../data-types/int-uint.md).

ملاحظة: في ClickHouse v25.4 أو الإصدارات الأقدم، تستقبل `geoToH3()` القيم بالترتيب `(lon, lat)`. واعتبارًا من ClickHouse v25.5، تكون قيم الإدخال بالترتيب `(lat, lon)`. ويمكن استعادة السلوك السابق باستخدام الإعداد `geotoh3_argument_order = 'lon_lat'`.

**مثال**

```sql title="Query"
SELECT geoToH3(55.71290588, 37.79506683, 15) AS h3Index;
```

```text title="Response"
┌────────────h3Index─┐
│ 644325524701193974 │
└────────────────────┘
```

<div id="h3togeo">
  ## h3ToGeo
</div>

تعيد خط العرض وخط الطول للمركز الهندسي المقابلين لفهرس [H3](#h3-index) المُقدَّم.

**البنية**

```sql
h3ToGeo(h3Index)
```

**الوسيطات**

* `h3Index` — فهرس H3. [UInt64](../../data-types/int-uint.md).

**القيم المُعادة**

* قيمة من النوع `Tuple` تتكون من قيمتين: `tuple(lat,lon)`. ‏`lat` — خط العرض. [Float64](../../data-types/float.md). ‏`lon` — خط الطول. [Float64](../../data-types/float.md).

ملاحظة: في ClickHouse v24.12 أو الإصدارات الأقدم، تُرجِع `h3ToGeo()` القيم بالترتيب `(lon, lat)`. واعتبارًا من ClickHouse v25.1، أصبحت القيم المُعادة بالترتيب `(lat, lon)`. ويمكن استعادة السلوك السابق باستخدام الإعداد `h3togeo_lon_lat_result_order = true`.

**مثال**

```sql title="Query"
SELECT h3ToGeo(644325524701193974) AS coordinates;
```

```text title="Response"
┌─coordinates───────────────────────────┐
│ (55.71290243145668,37.79506616830252) │
└───────────────────────────────────────┘
```

<div id="h3polygontocells">

</div>

**الوسائط**

  * [Polygon](../../data-types/geo.md#polygon)
  * [MultiPolygon](../../data-types/geo.md#multipolygon)
* `resolution` — دقة الفهرس. النطاق: `[0, 15]`. [UInt8](../../data-types/int-uint.md).

<div id="h3polygontocellswithcontainment">
  ## h3PolygonToCellsWithContainment
</div>

تُرجع الخلايا السداسية (عند مستوى الدقة المحدد) التي تغطي الشكل الهندسي المُدخل، سواء كان من نوع ring أو (multi-)polygon، باستخدام أوضاع الاحتواء التجريبية في H3.

تربط هذه الدالة قيم `flags` بأوضاع الاحتواء في H3:

* `0` — `CONTAINMENT_CENTER`
* `1` — `CONTAINMENT_FULL`
* `2` — `CONTAINMENT_OVERLAPPING`
* `3` — `CONTAINMENT_OVERLAPPING_BBOX`

**الصياغة**

```sql
h3PolygonToCellsWithContainment(geometry, resolution, flags)
```

**الوسيطات**

* يمكن أن تكون `geometry` أحد [أنواع بيانات Geo](../../data-types/geo.md) التالية أو أنواعها الأولية الأساسية:
  * [Ring](../../data-types/geo.md#ring)
  * [Polygon](../../data-types/geo.md#polygon)
  * [MultiPolygon](../../data-types/geo.md#multipolygon)
* `resolution` — دقة الفهرس. النطاق: `[0, 15]`. [UInt8](../../data-types/int-uint.md).
* `flags` — وضع الاحتواء. النطاق: `[0, 3]`. استخدم القيم الحرفية الصحيحة مثل `0` و`1` و`2` و`3`، أو قيم [UInt32](../../data-types/int-uint.md) (على سبيل المثال، `toUInt32(2)`). تُمرَّر القيم إلى واجهة برمجة تطبيقات H3 على أنها `UInt32`. وتُحوَّل أنواع الأعداد الصحيحة الأصلية الأخرى بتحويل نوع دقيق.

**القيم المُعادة**

* مصفوفة من فهارس H3 وفقًا لوضع الاحتواء المحدد. [Array](../../data-types/array.md)([UInt64](../../data-types/int-uint.md)).

**مثال**

```sql title="Query"
SELECT

    h3PolygonToCellsWithContainment([(-122.4089866999972145, 37.813318999983238), (-122.3544736999993603, 37.7198061999978478), (-122.4798767000009008, 37.8151571999998453)], 7, 2) AS overlap_cells;
```

```text title="Response"
1. │ [608692970585063423,608692970719281151,608692970752835583,608692970769612799,608692970819944447,608692971927240703,608692972027903999] │ [608692970249519103,608692970266296319,608692970585063423,608692970601840639,608692970635395071,608692970685726719,608692970719281151,608692970736058367,608692970752835583,608692970769612799,608692970786390015,608692970819944447,608692971927240703,608692971994349567,608692972027903999] │
```

تُعيد `(0,0)` إذا كانت قيمة الإدخال غير صالحة.

```sql title="Query"
 SELECT h3GetIndexesFromUnidirectionalEdge(1248204388774707199) AS indexes;
```
