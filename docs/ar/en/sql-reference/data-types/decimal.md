أعداد موقَّعة ذات فاصلة ثابتة تحافظ على الدقة أثناء عمليات الجمع والطرح والضرب. أمّا في القسمة، فتُهمَل الخانات الأقل أهمية (من دون تقريب).

<div id="parameters">
  ## المعلمات
</div>

* P - دقة. النطاق الصالح: [ 1 : 76 ]. يحدد عدد الخانات العشرية التي يمكن أن يحتويها الرقم (بما في ذلك الجزء الكسري). تكون قيمة دقة افتراضيًا 10.
* S - مقياس. النطاق الصالح: [ 0 : P ]. يحدد عدد الخانات العشرية التي يمكن أن يحتويها الجزء الكسري.

تعادل Decimal(P) الصيغة Decimal(P, 0). وبالمثل، تعادل الصيغة Decimal الصيغة Decimal(10, 0).

اعتمادًا على قيمة المعلمة P، فإن Decimal(P, S) اسم مرادف لـ:

* P من [ 1 : 9 ] - لـ Decimal32(S)
* P من [ 10 : 18 ] - لـ Decimal64(S)
* P من [ 19 : 38 ] - لـ Decimal128(S)
* P من [ 39 : 76 ] - لـ Decimal256(S)

<div id="decimal-value-ranges">
  ## نطاقات قيم Decimal
</div>

* Decimal(P, S) - ( -1 * 10^(P - S), 1 * 10^(P - S) )
* Decimal32(S) - ( -1 * 10^(9 - S), 1 * 10^(9 - S) )
* Decimal64(S) - ( -1 * 10^(18 - S), 1 * 10^(18 - S) )
* Decimal128(S) - ( -1 * 10^(38 - S), 1 * 10^(38 - S) )
* Decimal256(S) - ( -1 * 10^(76 - S), 1 * 10^(76 - S) )

على سبيل المثال، يمكن لـ Decimal32(4) تخزين أعداد تتراوح من ‎-99999.9999 إلى 99999.9999 بخطوة 0.0001.

<div id="internal-representation">
  ## التمثيل الداخلي
</div>

داخليًا، تُمثَّل البيانات على هيئة أعداد صحيحة موقَّعة عادية بعرض البِت المقابل. وتكون نطاقات القيم الفعلية التي يمكن تخزينها في الذاكرة أكبر قليلًا مما هو محدد أعلاه، ولا يُتحقَّق منها إلا عند التحويل من سلسلة نصية.

نظرًا لأن وحدات CPU الحديثة لا تدعم الأعداد الصحيحة ذات 128 بت و256 بت دعمًا أصيلًا، تُحاكى العمليات على Decimal128 وDecimal256. لذلك، يكون Decimal128 وDecimal256 أبطأ بكثير من Decimal32/Decimal64.

<div id="operations-and-result-type">
  ## العمليات ونوع النتيجة
</div>

تؤدي العمليات الثنائية على Decimal إلى نوع نتيجة أوسع (بغضّ النظر عن ترتيب الوسيطات).

* `Decimal64(S1) <op> Decimal32(S2) -> Decimal64(S)`
* `Decimal128(S1) <op> Decimal32(S2) -> Decimal128(S)`
* `Decimal128(S1) <op> Decimal64(S2) -> Decimal128(S)`
* `Decimal256(S1) <op> Decimal<32|64|128>(S2) -> Decimal256(S)`

قواعد المقياس:

* الجمع، الطرح: S = max(S1, S2).
* الضرب: S = S1 + S2.
* القسمة: S = S1.

في العمليات المماثلة بين Decimal والأعداد الصحيحة، تكون النتيجة Decimal بالحجم نفسه مثل الوسيط.

العمليات بين Decimal وFloat32/Float64 غير معرّفة. إذا كنت بحاجة إليها، يمكنك إجراء تحويل نوع صريح لأحد الوسيطات باستخدام الدوال المضمّنة toDecimal32 أو toDecimal64 أو toDecimal128 أو toFloat32 أو toFloat64. ضع في اعتبارك أن النتيجة ستفقد بعض الدقة، وأن تحويل النوع عملية مكلفة حسابيًا.

تعيد بعض الدوال على Decimal النتيجة على هيئة Float64 (على سبيل المثال، var أو stddev). وقد تظل الحسابات الوسيطة تُجرى باستخدام Decimal، مما قد يؤدي إلى اختلاف النتائج بين مُدخلات Float64 وDecimal حتى عند تساوي القيم.

<div id="overflow-checks">
  ## التحقق من تجاوز السعة
</div>

أثناء إجراء العمليات الحسابية على Decimal، قد يحدث تجاوز سعة في الأعداد الصحيحة. تُهمَل الأرقام الزائدة في الجزء الكسري (من دون تقريب). أما الأرقام الزائدة في الجزء الصحيح فتؤدي إلى طرح استثناء.

:::warning
لم يُنفَّذ التحقق من تجاوز السعة لـ Decimal128 وDecimal256. في حال حدوث تجاوز سعة، تُعاد نتيجة غير صحيحة، ولا يُطرَح أي استثناء.
:::

```sql
SELECT toDecimal32(2, 4) AS x, x / 3
```

```text
┌──────x─┬─divide(toDecimal32(2, 4), 3)─┐
│ 2.0000 │                       0.6666 │
└────────┴──────────────────────────────┘
```

```sql
SELECT toDecimal32(4.2, 8) AS x, x * x
```

```text
DB::Exception: Scale is out of bounds.
```

```sql
SELECT toDecimal32(4.2, 8) AS x, 6 * x
```

```text
DB::Exception: Decimal math overflow.
```

تؤدي فحوصات تجاوز السعة إلى إبطاء العمليات. إذا كان من المعروف أن تجاوز السعة غير وارد، فمن المنطقي تعطيل هذه الفحوصات باستخدام الإعداد `decimal_check_overflow`. وعند تعطيل الفحوصات ووقوع تجاوز سعة، ستكون النتيجة غير صحيحة:

```sql
SET decimal_check_overflow = 0;
SELECT toDecimal32(4.2, 8) AS x, 6 * x
```

```text
┌──────────x─┬─multiply(6, toDecimal32(4.2, 8))─┐
│ 4.20000000 │                     -17.74967296 │
└────────────┴──────────────────────────────────┘
```

لا تقتصر عمليات التحقق من تجاوز السعة على العمليات الحسابية فحسب، بل تحدث أيضًا عند مقارنة القيم:

```sql
SELECT toDecimal32(1, 8) < 100
```

```text
DB::Exception: Can't compare.
```
