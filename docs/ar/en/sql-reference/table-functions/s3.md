<div id="s3-table-function">
  # الدالة الجدولية s3
</div>

توفّر واجهة شبيهة بالجداول للاستعلام عن الملفات وإدراجها في [Amazon S3](https://aws.amazon.com/s3/) و[Google Cloud Storage](https://cloud.google.com/storage/). تشبه الدالة الجدولية هذه [دالة hdfs](../../sql-reference/table-functions/hdfs.md)، لكنها توفّر ميزات خاصة بـ S3.

إذا كان لديك عدة نُسخ متماثلة في العنقود، فيمكنك استخدام [الدالة s3Cluster](../../sql-reference/table-functions/s3Cluster.md) بدلًا من ذلك لموازاة عمليات الإدراج.

عند استخدام `s3 table function` مع [`INSERT INTO...SELECT`](../../sql-reference/statements/insert-into#inserting-the-results-of-select)، تُقرأ البيانات وتُدرج بأسلوب تدفقي. لا يبقى في الذاكرة إلا عدد قليل من كتل البيانات، بينما تُقرأ الكتل باستمرار من S3 وتُرسل إلى جدول الوجهة.

<div id="syntax">
  ## الصيغة
</div>

```sql
s3(url [, NOSIGN | access_key_id, secret_access_key, [session_token]] [,format] [,structure] [,compression_method],[,headers], [,extra_credentials], [,partition_strategy], [,partition_columns_in_data_file])
s3(named_collection[, option=value [,..]])
```

:::tip GCS
تتكامل الدالة الجدولية S3 مع Google Cloud Storage باستخدام GCS XML API ومفاتيح HMAC. راجع [مستندات التشغيل البيني من Google](https://cloud.google.com/storage/docs/interoperability) لمزيد من التفاصيل حول نقطة النهاية ومفاتيح HMAC.

بالنسبة إلى GCS، استبدل مفتاح HMAC وسر HMAC الخاصين بك في المواضع التي يظهر فيها `access_key_id` و`secret_access_key`.
:::

**المعاملات**

تدعم الدالة الجدولية `s3` المعاملات البسيطة التالية:

| المعامل                                 | الوصف                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`                                   | URL الخاص بالـ حاوية مع مسار إلى الملف. يدعم أحرف البدل التالية في وضع readonly: `*` و`**` و`?` و`{abc,def}` و`{N..M}`، حيث إن `N` و`M` — أرقام، و`'abc'` و`'def'` — سلاسل نصية. لمزيد من المعلومات، راجع [هنا](../../engines/table-engines/integrations/s3.md#wildcards-in-path).                                                                                                                                                                            |
| `NOSIGN`                                | إذا تم توفير هذه الكلمة المفتاحية بدلًا من بيانات الاعتماد، فلن تُوقَّع أي من الطلبات.                                                                                                                                                                                                                                                                                                                                                                         |
| `access_key_id` and `secret_access_key` | مفاتيح تحدد بيانات الاعتماد المطلوب استخدامها مع نقطة النهاية المحددة. هذا المعامل اختياري.                                                                                                                                                                                                                                                                                                                                                                    |
| `session_token`                         | رمز جلسة لاستخدامه مع المفاتيح المحددة. ويكون اختياريًا عند تمرير المفاتيح.                                                                                                                                                                                                                                                                                                                                                                                    |
| `format`                                | [التنسيق](/ar/sql-reference/formats) الخاص بالملف.                                                                                                                                                                                                                                                                                                                                                                                                                |
| `structure`                             | بنية الجدول. بالتنسيق `'column1_name column1_type, column2_name column2_type, ...'`.                                                                                                                                                                                                                                                                                                                                                                           |
| `compression_method`                    | هذا المعامل اختياري. القيم المدعومة: `none` و`gzip` أو `gz` و`brotli` أو `br` و`xz` أو `LZMA` و`zstd` أو `zst`. افتراضيًا، سيُكتشف أسلوب الضغط تلقائيًا من امتداد الملف.                                                                                                                                                                                                                                                                                       |
| `headers`                               | هذا المعامل اختياري. ويتيح تمرير headers في طلب S3. مرّرها بالتنسيق `headers(key=value)`، مثل: `headers('x-amz-request-payer' = 'requester')`.                                                                                                                                                                                                                                                                                                                 |
| `partition_strategy`                    | هذا المعامل اختياري. القيم المدعومة: `wildcard` أو `hive`. يتطلب `wildcard` وجود `{_partition_id}` في المسار، ويُستبدل بمفتاح partition. أما `hive` فلا يسمح بأحرف البدل، ويفترض أن المسار هو جذر الجدول، ويُنشئ أدلة partition بأسلوب Hive مع Snowflake IDs كأسماء ملفات، وتنسيق الملف كامتداد. تكون القيمة الافتراضية هي الإعداد `file_like_engine_default_partition_strategy` (`wildcard` ضمن إعدادات `compatibility` الأقدم من `26.6`، و`hive` بخلاف ذلك). |
| `partition_columns_in_data_file`        | هذا المعامل اختياري. ولا يُستخدم إلا مع استراتيجية partition `hive`. ويُخبر ClickHouse ما إذا كان ينبغي توقّع كتابة أعمدة partition في ملف البيانات. القيمة الافتراضية هي `false`.                                                                                                                                                                                                                                                                             |
| `extra_credentials`                     | هذا المعامل اختياري. ويُستخدم لتمرير `role_arn` من أجل الوصول المستند إلى الدور في ClickHouse Cloud. راجع [Secure S3](/ar/cloud/data-sources/secure-s3) لمعرفة خطوات الإعداد.                                                                                                                                                                                                                                                                                     |
| `storage_class_name`                    | هذا المعامل اختياري. القيم المدعومة: `STANDARD` أو `INTELLIGENT_TIERING`. ويتيح تحديد [AWS S3 Intelligent Tiering](https://aws.amazon.com/s3/storage-classes/intelligent-tiering/). القيمة الافتراضية هي `STANDARD`.                                                                                                                                                                                                                                           |

:::note GCS
يكون عنوان URL الخاص بـ GCS بهذا التنسيق لأن نقطة النهاية الخاصة بـ Google XML API تختلف عن JSON API:

```text
  https://storage.googleapis.com/<bucket>/<folder>/<filename(s)>
```

وليس ~~https://storage.cloud.google.com~~.
:::

يمكن أيضًا تمرير الوسيطات باستخدام [المجموعات المسماة](/ar/operations/named-collections.md). في هذه الحالة، تعمل `url` و`access_key_id` و`secret_access_key` و`format` و`structure` و`compression_method` بالطريقة نفسها، كما تُدعَم بعض المعلمات الإضافية:

| الوسيطة                       | الوصف                                                                                                                                                                                                                 |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filename`                    | يُضاف إلى عنوان URL إذا تم تحديده.                                                                                                                                                                                    |
| `use_environment_credentials` | مُفعّل افتراضيًا، ويتيح تمرير معلمات إضافية باستخدام متغيرات البيئة `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`, `AWS_CONTAINER_CREDENTIALS_FULL_URI`, `AWS_CONTAINER_AUTHORIZATION_TOKEN`, `AWS_EC2_METADATA_DISABLED`. |
| `no_sign_request`             | مُعطّل افتراضيًا.                                                                                                                                                                                                     |
| `expiration_window_seconds`   | القيمة الافتراضية هي 120.                                                                                                                                                                                             |

  ## القيمة المُعادة

<div id="examples">
  ## أمثلة
</div>

اختيار أول 5 صفوف من الجدول في ملف S3 ‏`https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv`:

```sql
SELECT *
FROM s3(
   'https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv',
   'CSVWithNames'
)
LIMIT 5;
```

```response
┌───────Date─┬────Open─┬────High─┬─────Low─┬───Close─┬───Volume─┬─OpenInt─┐
│ 1984-09-07 │ 0.42388 │ 0.42902 │ 0.41874 │ 0.42388 │ 23220030 │       0 │
│ 1984-09-10 │ 0.42388 │ 0.42516 │ 0.41366 │ 0.42134 │ 18022532 │       0 │
│ 1984-09-11 │ 0.42516 │ 0.43668 │ 0.42516 │ 0.42902 │ 42498199 │       0 │
│ 1984-09-12 │ 0.42902 │ 0.43157 │ 0.41618 │ 0.41618 │ 37125801 │       0 │
│ 1984-09-13 │ 0.43927 │ 0.44052 │ 0.43927 │ 0.43927 │ 57822062 │       0 │
└────────────┴─────────┴─────────┴─────────┴─────────┴──────────┴─────────┘
```

:::note
يستخدم ClickHouse امتدادات أسماء الملفات لتحديد صيغة البيانات. على سبيل المثال، كان بإمكاننا تشغيل الأمر السابق من دون `CSVWithNames`:

```sql
SELECT *
FROM s3(
   'https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv'
)
LIMIT 5;
```

يمكن لـ ClickHouse أيضًا تحديد طريقة ضغط الملف. على سبيل المثال، إذا كان الملف مضغوطًا بامتداد `.csv.gz`، فسيقوم ClickHouse بفك ضغطه تلقائيًا.
:::

:::note
قد تُربك ملفات Parquet التي تحمل أسماء مثل `*.parquet.snappy` أو `*.parquet.zstd` ClickHouse وتتسبب في ظهور الأخطاء `TOO_LARGE_COMPRESSED_BLOCK` أو `ZSTD_DECODER_FAILED`.
ويرجع ذلك إلى أن ClickHouse سيحاول قراءة الملف بالكامل على أنه بيانات مشفّرة باستخدام Snappy أو ZSTD، بينما يطبّق Parquet الضغط فعليًا على مستوى مجموعات الصفوف والأعمدة.

تحدّد بيانات Parquet الوصفية بالفعل إعداد الضغط لكل عمود، لذا يكون امتداد الملف هنا زائدًا عن الحاجة.
يمكنك ببساطة استخدام `compression_method = 'none'` في مثل هذه الحالات:

```sql
SELECT *
FROM s3(
  'https://<my-bucket>.s3.<my-region>.amazonaws.com/path/to/my-data.parquet.snappy',
  compression_format = 'none'
);
```

:::

احسب عدد الصفوف في الملفات التي تنتهي بأرقام من 1 إلى 3:

```sql
SELECT count(*)
FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/my-test-bucket-768/{some,another}_prefix/some_file_{1..3}.csv', 'CSV', 'column1 UInt32, column2 UInt32, column3 UInt32')
```

```text
┌─count()─┐
│      18 │
└─────────┘
```

احسب إجمالي عدد الصفوف في جميع الملفات الموجودة في هذين الدليلين:

```sql
SELECT count(*)
FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/my-test-bucket-768/{some,another}_prefix/*', 'CSV', 'column1 UInt32, column2 UInt32, column3 UInt32')
```

```text
┌─count()─┐
│      24 │
└─────────┘
```

:::tip
إذا كانت قائمة الملفات تحتوي على نطاقات أرقام تبدأ بأصفار بادئة، فاستخدم بنية الأقواس المعقوصة لكل رقم على حدة، أو استخدم `?`.
:::

احسب إجمالي عدد الصفوف في الملفات المسماة `file-000.csv`، `file-001.csv`، ... ، `file-999.csv`:

```sql
SELECT count(*)
FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/my-test-bucket-768/big_prefix/file-{000..999}.csv', 'CSV', 'column1 UInt32, column2 UInt32, column3 UInt32');
```

```text
┌─count()─┐
│      12 │
└─────────┘
```

إدراج البيانات في الملف `test-data.csv.gz`:

```sql
INSERT INTO FUNCTION s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip')
VALUES ('test-data', 1), ('test-data-2', 2);
```

أدرج البيانات في الملف `test-data.csv.gz` من جدول موجود:

```sql
INSERT INTO FUNCTION s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip')
SELECT name, value FROM existing_table;
```

يمكن استخدام glob ** للاجتياز العودي للمجلدات. انظر المثال أدناه، إذ سيجلب جميع الملفات من دليل `my-test-bucket-768` بصورة عودية:

```sql
SELECT * FROM s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/**', 'CSV', 'name String, value UInt32', 'gzip');
```

يسترجع المثال التالي البيانات من جميع ملفات `test-data.csv.gz` الموجودة في أي مجلد داخل الدليل `my-test-bucket` بصورة متكررة:

```sql
SELECT * FROM s3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/**/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip');
```

ملاحظة. يمكن تحديد محوّلات URL مخصصة في ملف تهيئة الخادم. مثال:

```sql
SELECT * FROM s3('s3://clickhouse-public-datasets/my-test-bucket-768/**/test-data.csv.gz', 'CSV', 'name String, value UInt32', 'gzip');
```

سيتم استبدال الـ URL `'s3://clickhouse-public-datasets/my-test-bucket-768/**/test-data.csv.gz'` بـ `'http://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/**/test-data.csv.gz'`

يمكن إضافة مُحوِّل مخصّص إلى `config.xml`:

```xml
<url_scheme_mappers>
   <s3>
      <to>https://{bucket}.s3.amazonaws.com</to>
   </s3>
   <gs>
      <to>https://{bucket}.storage.googleapis.com</to>
   </gs>
   <oss>
      <to>https://{bucket}.oss.aliyuncs.com</to>
   </oss>
</url_scheme_mappers>
```

للاستخدام في بيئات الإنتاج، يُوصى باستخدام [المجموعات المسماة](/ar/operations/named-collections.md). إليك المثال:

```sql

CREATE NAMED COLLECTION creds AS
        access_key_id = '***',
        secret_access_key = '***';
SELECT count(*)
FROM s3(creds, url='https://s3-object-url.csv')
```

<div id="partition-strategy">
  ### استراتيجية التقسيم
</div>

مدعومة فقط لاستعلامات `INSERT`.

`wildcard`: يستبدل الرمز العام `{_partition_id}` في مسار الملف بمفتاح التقسيم الفعلي. يُستخدم افتراضيًا فقط ضمن إعدادات `compatibility` الأقدم من `26.6`؛ وإلا تكون القيمة الافتراضية هي `hive` (راجع الإعداد `file_like_engine_default_partition_strategy`).

يُطبّق `hive` التقسيم بنمط Hive لعمليات القراءة والكتابة. ويُنشئ الملفات باستخدام الصيغة التالية: `<prefix>/<key1=val1/key2=val2...>/<snowflakeid>.<toLower(file_format)>`.

**مثال على استراتيجية التقسيم `hive`**

```sql
INSERT INTO FUNCTION s3(s3_conn, filename='t_03363_function', format=Parquet, partition_strategy='hive') PARTITION BY (year, country) SELECT 2020 as year, 'Russia' as country, 1 as id;
```

```result
SELECT _path, * FROM s3(s3_conn, filename='t_03363_function/**.parquet');

   ┌─_path──────────────────────────────────────────────────────────────────────┬─id─┬─country─┬─year─┐
1. │ test/t_03363_function/year=2020/country=Russia/7351295896279887872.parquet │  1 │ Russia  │ 2020 │
   └────────────────────────────────────────────────────────────────────────────┴────┴─────────┴──────┘
```

**أمثلة على استراتيجية التقسيم `wildcard`**

1. يؤدي استخدام معرّف القسم ضمن المفتاح إلى إنشاء ملفات منفصلة:

```sql
INSERT INTO TABLE FUNCTION
    s3('http://bucket.amazonaws.com/my_bucket/file_{_partition_id}.csv', 'CSV', 'a String, b UInt32, c UInt32')
    PARTITION BY a VALUES ('x', 2, 3), ('x', 4, 5), ('y', 11, 12), ('y', 13, 14), ('z', 21, 22), ('z', 23, 24);
```

ونتيجةً لذلك، تُكتب البيانات في ثلاثة ملفات: `file_x.csv` و`file_y.csv` و`file_z.csv`.

2. يؤدي استخدام معرّف القسم في اسم الحاوية إلى إنشاء ملفات في حاويات مختلفة:

```sql
INSERT INTO TABLE FUNCTION
    s3('http://bucket.amazonaws.com/my_bucket_{_partition_id}/file.csv', 'CSV', 'a UInt32, b UInt32, c UInt32')
    PARTITION BY a VALUES (1, 2, 3), (1, 4, 5), (10, 11, 12), (10, 13, 14), (20, 21, 22), (20, 23, 24);
```

ونتيجةً لذلك، تُكتَب البيانات في ثلاثة ملفات داخل حاويات تخزين مختلفة: `my_bucket_1/file.csv` و`my_bucket_10/file.csv` و`my_bucket_20/file.csv`.

<div id="accessing-public-buckets">
  ## الوصول إلى الحاويات العامة
</div>

يحاول ClickHouse جلب بيانات الاعتماد من أنواع متعددة من المصادر المختلفة.
وقد يتسبب ذلك أحيانًا في حدوث مشكلات عند الوصول إلى بعض الحاويات العامة، ما يؤدي إلى أن يعيد العميل رمز الخطأ `403`.
يمكن تجنب هذه المشكلة باستخدام الكلمة المفتاحية `NOSIGN` لإجبار العميل على تجاهل جميع بيانات الاعتماد وعدم توقيع الطلبات.

```sql
SELECT *
FROM s3(
   'https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv',
   NOSIGN,
   'CSVWithNames'
)
LIMIT 5;
```

<div id="using-s3-credentials-clickhouse-cloud">
  ## استخدام بيانات اعتماد S3 ‏(ClickHouse Cloud)
</div>

بالنسبة إلى الحاويات غير المتاحة للعامة، يمكن للمستخدمين تمرير `aws_access_key_id` و`aws_secret_access_key` إلى الدالة. على سبيل المثال:

```sql
SELECT count() FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/mta/*.tsv', '<KEY>', '<SECRET>','TSVWithNames')
```

يكون هذا مناسبًا لعمليات الوصول لمرة واحدة أو في الحالات التي يمكن فيها تبديل بيانات الاعتماد بسهولة. لكن لا يُنصح به كحل طويل الأجل لعمليات الوصول المتكررة أو عندما تكون بيانات الاعتماد حساسة. في هذه الحالة، نوصي المستخدمين بالاعتماد على التحكم بالوصول المستند إلى الأدوار.

وثائق التحكم بالوصول المستند إلى الأدوار لـ S3 في ClickHouse Cloud متاحة [هنا](/ar/cloud/data-sources/secure-s3).

بعد إعداده، يمكن تمرير `roleARN` إلى الدالة s3 عبر المعامل `extra_credentials`. على سبيل المثال:

```sql
SELECT count() FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/mta/*.tsv','CSVWithNames',extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001'))
```

يمكن أيضًا تمرير `external_id` اختياريًا مع `role_arn`. ويُمرَّر كمعلمة `ExternalId` في استدعاء AWS STS ‏`AssumeRole`، ويتيح لسياسة الثقة الخاصة بالدور اشتراط سرٍّ مشترك، مما يخفف من [مشكلة النائب المرتبك](https://docs.aws.amazon.com/IAM/latest/UserGuide/confused-deputy.html). على سبيل المثال:

```sql
SELECT count() FROM s3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/mta/*.tsv','CSVWithNames',extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001', external_id = 'my-external-id'))
```

يمكنك العثور على المزيد من الأمثلة [هنا](/ar/cloud/data-sources/secure-s3#access-your-s3-bucket-with-the-clickhouseaccess-role)

<div id="working-with-archives">
  ## العمل مع الأرشيفات
</div>

لنفترض أن لدينا عدة ملفات أرشيفية بعناوين URI التالية على S3:

* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-10.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-11.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-12.csv.zip&#39;

يمكن استخراج البيانات من هذه الأرشيفات باستخدام ::. ويمكن استخدام أنماط glob سواء في جزء الـ URL أو في الجزء الذي يلي :: (المسؤول عن اسم الملف داخل الأرشيف).

```sql
SELECT *
FROM s3(
   'https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-1{0..2}.csv.zip :: *.csv'
);
```

:::note
يدعم ClickHouse ثلاثة تنسيقات للأرشيف:
ZIP
TAR
7Z
في حين يمكن الوصول إلى أرشيفات ZIP وTAR من أي موقع تخزين مدعوم، لا يمكن قراءة أرشيفات 7Z إلا من نظام الملفات المحلي المثبَّت عليه ClickHouse.
:::

<div id="inserting-data">
  ## إدراج البيانات
</div>

لاحظ أنه لا يمكن إدراج الصفوف إلا في الملفات الجديدة. ولا توجد دورات دمج أو عمليات تقسيم للملفات. وبمجرد كتابة الملف، ستفشل عمليات الإدراج اللاحقة. راجع المزيد من التفاصيل [هنا](/ar/integrations/s3#inserting-data).

<div id="virtual-columns">
  ## الأعمدة الافتراضية
</div>

* `_path` — مسار الملف. النوع: `LowCardinality(String)`. في حالة الأرشيف، يعرض المسار بالتنسيق التالي: `"{path_to_archive}::{path_to_file_inside_archive}"`
* `_file` — اسم الملف. النوع: `LowCardinality(String)`. في حالة الأرشيف، يعرض اسم الملف داخل الأرشيف.
* `_size` — حجم الملف بالبايت. النوع: `Nullable(UInt64)`. إذا كان حجم الملف غير معروف، تكون القيمة `NULL`. في حالة الأرشيف، يعرض حجم الملف غير المضغوط داخل الأرشيف.
* `_time` — وقت آخر تعديل للملف. النوع: `Nullable(DateTime)`. إذا كان الوقت غير معروف، تكون القيمة `NULL`.

<div id="hive-style-partitioning">
  ## إعداد use_hive_partitioning
</div>

هذا تلميح لـ ClickHouse ليفسّر الملفات المُقسَّمة بأسلوب Hive عند قراءتها. ولا يؤثر في الكتابة. ولتحقيق تماثل بين عمليات القراءة والكتابة، استخدم الوسيط `partition_strategy`.

عند تعيين الإعداد `use_hive_partitioning` إلى القيمة 1، سيكتشف ClickHouse التقسيم بأسلوب Hive في المسار (`/name=value/`) وسيتيح استخدام أعمدة التقسيم كأعمدة افتراضية في الاستعلام. وستحمل هذه الأعمدة الافتراضية الأسماء نفسها الموجودة في مسار التقسيم.

**مثال**

```sql
SELECT * FROM s3('s3://data/path/date=*/country=*/code=*/*.parquet') WHERE date > '2020-01-01' AND country = 'Netherlands' AND code = 42;
```

<div id="accessing-requester-pays-buckets">
  ## الوصول إلى حاويات requester-pays
</div>

للوصول إلى حاوية requester-pays، يجب تمرير الترويسة `x-amz-request-payer = requester` في أي طلب. ويتم ذلك بتمرير المعامل `headers('x-amz-request-payer' = 'requester')` إلى الدالة s3. على سبيل المثال:

```sql
SELECT
    count() AS num_rows,
    uniqExact(_file) AS num_files
FROM s3('https://coiled-datasets-rp.s3.us-east-1.amazonaws.com/1trc/measurements-100*.parquet', 'AWS_ACCESS_KEY_ID', 'AWS_SECRET_ACCESS_KEY', headers('x-amz-request-payer' = 'requester'))

┌───num_rows─┬─num_files─┐
│ 1110000000 │       111 │
└────────────┴───────────┘

1 row in set. Elapsed: 3.089 sec. Processed 1.09 billion rows, 0.00 B (353.55 million rows/s., 0.00 B/s.)
Peak memory usage: 192.27 KiB.
```

<div id="storage-settings">
  ## إعدادات التخزين
</div>

* [s3&#95;truncate&#95;on&#95;insert](/ar/operations/settings/settings.md#s3_truncate_on_insert) - يتيح إفراغ الملف قبل إدراج البيانات فيه. يكون معطّلًا افتراضيًا.
* [s3&#95;create&#95;new&#95;file&#95;on&#95;insert](/ar/operations/settings/settings.md#s3_create_new_file_on_insert) - يتيح إنشاء ملف جديد عند كل عملية insert إذا كان format يتضمن لاحقة. يكون معطّلًا افتراضيًا.
* [s3&#95;skip&#95;empty&#95;files](/ar/operations/settings/settings.md#s3_skip_empty_files) - يتيح تخطي الملفات الفارغة أثناء القراءة. يكون مفعّلًا افتراضيًا.

<div id="nested-avro-schemas">
  ## مخططات Avro المتداخلة
</div>

عند قراءة ملفات Avro التي تحتوي على **سجلات متداخلة** تختلف بنيتها من ملف إلى آخر (على سبيل المثال، إذا كان بعض الملفات يحتوي على حقل إضافي داخل كائن متداخل)، قد يعرض ClickHouse خطأً مثل:

> The number of leaves in record doesn&#39;t match the number of elements in tuple...

يحدث ذلك لأن ClickHouse يتوقع أن تتطابق جميع بنيات السجلات المتداخلة مع المخطط نفسه.
للتعامل مع هذه الحالة، يمكنك:

* استخدام `schema_inference_mode='union'` لدمج مخططات السجلات المتداخلة المختلفة، أو
* محاذاة البنيات المتداخلة يدويًا وتمكين
  `use_structure_from_insertion_table_in_table_functions=1`.

:::note[ملاحظة حول الأداء]
قد يستغرق `schema_inference_mode='union'` وقتًا أطول مع مجموعات بيانات S3 الكبيرة جدًا، لأنه يحتاج إلى فحص كل ملف لاستنتاج المخطط.
:::

**مثال**

```sql
INSERT INTO data_stage
SELECT
    id,
    data
FROM s3('https://bucket-name/*.avro', 'Avro')
SETTINGS schema_inference_mode='union';
```
