يوفّر هذا المحرك تكاملًا مع منظومة [Amazon S3](https://aws.amazon.com/s3/). وهو يشبه محرك [HDFS](/ar/engines/table-engines/integrations/hdfs)، لكنه يوفّر ميزات خاصة بـ S3.

<div id="example">
  ## مثال
</div>

```sql
CREATE TABLE s3_engine_table (name String, value UInt32)
    ENGINE=S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/test-data.csv.gz', 'CSV', 'gzip')
    SETTINGS input_format_with_names_use_header = 0;

INSERT INTO s3_engine_table VALUES ('one', 1), ('two', 2), ('three', 3);

SELECT * FROM s3_engine_table LIMIT 2;
```

```text
┌─name─┬─value─┐
│ one  │     1 │
│ two  │     2 │
└──────┴───────┘
```

<div id="creating-a-table">
  ## إنشاء جدول
</div>

```sql
CREATE TABLE s3_engine_table (name String, value UInt32)
    ENGINE = S3(path [, NOSIGN | aws_access_key_id, aws_secret_access_key,] format, [compression], [partition_strategy], [partition_columns_in_data_file], [extra_credentials])
    [PARTITION BY expr]
    [SETTINGS ...]
```

<div id="parameters">
  ### معلمات المحرك
</div>

* `path` — ‏URL للدلو مع مسار الملف. يدعم محارف البدل التالية في وضع القراءة فقط: `*`, `**`, `?`, `{abc,def}` و `{N..M}`، حيث إن `N` و `M` — أرقام، و`'abc'` و`'def'` — سلاسل نصية. لمزيد من المعلومات، انظر [أدناه](#wildcards-in-path).
* `NOSIGN` - إذا جرى توفير هذه الكلمة المفتاحية بدلًا من بيانات الاعتماد، فلن تُوقَّع أي طلبات.
* `format` — [تنسيق](/ar/sql-reference/formats#formats-overview) الملف.
* `aws_access_key_id`, `aws_secret_access_key` - بيانات اعتماد طويلة الأمد لمستخدم حساب [AWS](https://aws.amazon.com/). يمكنك استخدامها لمصادقة طلباتك. هذه المعلمة اختيارية. إذا لم تُحدَّد بيانات الاعتماد، فسيُستخدم ما هو موجود في ملف التهيئة. لمزيد من المعلومات، انظر [استخدام S3 لتخزين البيانات](../mergetree-family/mergetree.md#table_engine-mergetree-s3).
* `compression` — نوع الضغط. القيم المدعومة: `none`, `gzip/gz`, `brotli/br`, `xz/LZMA`, `zstd/zst`. هذه المعلمة اختيارية. افتراضيًا، سيُكتشَف نوع الضغط تلقائيًا من امتداد الملف.
* `partition_strategy` – الخيارات: `WILDCARD` أو `HIVE`. يتطلب `WILDCARD` وجود `{_partition_id}` في المسار، ويُستبدل بمفتاح التقسيم. لا يسمح `HIVE` بمحارف البدل، ويفترض أن المسار هو جذر الجدول، ويُنشئ أدلة partition بأسلوب Hive مع Snowflake IDs كأسماء ملفات وتنسيق الملف كامتداد. تكون القيمة الافتراضية هي الإعداد `file_like_engine_default_partition_strategy` (`WILDCARD` ضمن إعدادات `compatibility` الأقدم من `26.6`، و`HIVE` خلاف ذلك).
* `partition_columns_in_data_file` - يُستخدم فقط مع استراتيجية التقسيم `HIVE`. يُخبر ClickHouse ما إذا كان ينبغي توقّع كتابة أعمدة partition داخل ملف البيانات. القيمة الافتراضية هي `false`.
* `storage_class_name` - الخيارات: `STANDARD` أو `INTELLIGENT_TIERING`، ويتيح تحديد [AWS S3 Intelligent Tiering](https://aws.amazon.com/s3/storage-classes/intelligent-tiering/).
* `extra_credentials` - اختياري. يُستخدم لتمرير `role_arn` من أجل الوصول المستند إلى الأدوار في ClickHouse Cloud. راجع [تأمين S3](/ar/cloud/data-sources/secure-s3) لمعرفة خطوات الإعداد.

<div id="data-cache">
  ### ذاكرة التخزين المؤقت للبيانات
</div>

يدعم محرك الجدول `S3` التخزين المؤقت للبيانات على القرص المحلي.
اطّلع على خيارات تهيئة ذاكرة التخزين المؤقت لنظام الملفات وكيفية استخدامها في هذا [القسم](/ar/operations/storing-data.md/#using-local-cache).
يتم التخزين المؤقت بالاعتماد على المسار وETag الخاص بكائن التخزين، لذلك لن يقرأ ClickHouse نسخة قديمة من ذاكرة التخزين المؤقت.

لتمكين التخزين المؤقت، استخدم الإعداد `filesystem_cache_name = '<name>'` و`enable_filesystem_cache = 1`.

```sql
SELECT *
FROM s3('http://minio:10000/clickhouse//test_3.csv', 'minioadmin', 'minioadminpassword', 'CSV')
SETTINGS filesystem_cache_name = 'cache_for_s3', enable_filesystem_cache = 1;
```

هناك طريقتان لتعريف ذاكرة التخزين المؤقت في ملف التهيئة.

1. أضِف القسم التالي إلى ملف تهيئة ClickHouse:

```xml
<clickhouse>
    <filesystem_caches>
        <cache_for_s3>
            <path>path to cache directory</path>
            <max_size>10Gi</max_size>
        </cache_for_s3>
    </filesystem_caches>
</clickhouse>
```

2. أعِد استخدام إعدادات التخزين المؤقت (وبالتالي مساحة التخزين المؤقت) من قسم `storage_configuration` في ClickHouse، [كما هو موضح هنا](/ar/operations/storing-data.md/#using-local-cache)

<div id="partition-by">
  ### PARTITION BY
</div>

`PARTITION BY` — اختياري. في معظم الحالات، لا تحتاج إلى مفتاح تقسيم، وحتى إذا احتجت إليه، فعادةً لا تحتاج إلى مفتاح تقسيم أكثر تفصيلاً من التقسيم حسب الشهر. لا يؤدي التقسيم إلى تسريع الاستعلامات (على عكس تعبير `ORDER BY`). ويجب ألّا تستخدم تقسيمًا مفرط التفصيل إطلاقًا. لا تقسّم بياناتك حسب معرّفات العملاء أو الأسماء (وبدلًا من ذلك، اجعل معرّف العميل أو الاسم هو العمود الأول في تعبير `ORDER BY`).

للتقسيم حسب الشهر، استخدم التعبير `toYYYYMM(date_column)`، حيث إن `date_column` هو عمود يحتوي على تاريخ من النوع [Date](/ar/sql-reference/data-types/date.md). وتكون أسماء الأقسام هنا بالتنسيق `"YYYYMM"`.

<div id="partition-strategy">
  #### استراتيجية التقسيم
</div>

`WILDCARD`: يستبدل الرمز الشامل `{_partition_id}` في مسار الملف بمفتاح التقسيم الفعلي. لا يدعم القراءة. يُحدَّد افتراضيًا فقط ضمن إعدادات `compatibility` الأقدم من `26.6`؛ وإلا تكون القيمة الافتراضية هي `HIVE` (راجع الإعداد `file_like_engine_default_partition_strategy`).

ينفّذ `HIVE` التقسيم بنمط Hive لعمليات القراءة والكتابة. وتُنفَّذ القراءة باستخدام نمط glob تكراري، وهو مكافئ لـ `SELECT * FROM s3('table_root/**.parquet')`.
أما الكتابة فتنشئ ملفات بالتنسيق التالي: `<prefix>/<key1=val1/key2=val2...>/<snowflakeid>.<toLower(file_format)>`.

ملاحظة: عند استخدام استراتيجية التقسيم `HIVE`، لا يكون للإعداد `use_hive_partitioning` أي تأثير.

مثال على استراتيجية التقسيم `HIVE`:

```sql

ENGINE = S3(s3_conn, filename = 't_03363_parquet', format = Parquet, partition_strategy='hive')
```

<div id="querying-partitioned-data">
  ### الاستعلام عن البيانات المُقسّمة إلى أقسام
</div>

يستخدم هذا المثال [وصفة Docker Compose](https://github.com/ClickHouse/examples/tree/5fdc6ff72f4e5137e23ea075c88d3f44b0202490/docker-compose-recipes/recipes/ch-and-minio-S3) التي تدمج بين ClickHouse وMinIO. ينبغي أن تتمكن من إعادة تنفيذ الاستعلامات نفسها باستخدام S3 عبر استبدال قيم نقطة النهاية والمصادقة.

لاحظ أن نقطة نهاية S3 في إعداد `ENGINE` تستخدم الرمز `{_partition_id}` للمعلمة كجزء من كائن S3 (اسم الملف)، وأن استعلامات SELECT تستعلم باستخدام أسماء الكائنات الناتجة تلك (على سبيل المثال، `test_3.csv`).

:::note
كما هو موضح في المثال، فإن الاستعلام من جداول S3 المُقسّمة إلى أقسام
غير مدعوم مباشرةً في الوقت الحالي، ولكن يمكن إنجازه من خلال الاستعلام عن الأقسام الفردية
باستخدام دالة الجدول S3.

تتمثل حالة الاستخدام الأساسية لكتابة
البيانات المُقسّمة إلى أقسام في S3 في تمكين نقل تلك البيانات إلى نظام
ClickHouse آخر (على سبيل المثال، الانتقال من الأنظمة المحلية إلى ClickHouse
Cloud). ونظرًا إلى أن مجموعات البيانات في ClickHouse تكون غالبًا كبيرة جدًا، وأن
موثوقية الشبكة ليست مثالية دائمًا، فمن المنطقي نقل مجموعات البيانات
على شكل مجموعات فرعية، ومن هنا تأتي partitioned writes.
:::

<div id="inserting-data">
  ## إدراج البيانات
</div>

لاحظ أنه لا يمكن إدراج الصفوف إلا في الملفات الجديدة. ولا توجد دورات دمج أو عمليات تقسيم للملفات. وبمجرد كتابة ملف، ستفشل أي عمليات إدراج لاحقة. ولتجنّب ذلك، يمكنك استخدام الإعدادين `s3_truncate_on_insert` و`s3_create_new_file_on_insert`. راجع مزيدًا من التفاصيل [هنا](/ar/integrations/s3#inserting-data).

<div id="virtual-columns">
  ## الأعمدة الافتراضية
</div>

* `_path` — مسار الملف. النوع: `LowCardinality(String)`.
* `_file` — اسم الملف. النوع: `LowCardinality(String)`.
* `_size` — حجم الملف بالبايت. النوع: `Nullable(UInt64)`. إذا كان الحجم غير معروف، تكون القيمة `NULL`.
* `_time` — وقت آخر تعديل للملف. النوع: `Nullable(DateTime)`. إذا كان الوقت غير معروف، تكون القيمة `NULL`.
* `_etag` — قيمة ETag للملف. النوع: `LowCardinality(String)`. إذا كانت قيمة ETag غير معروفة، تكون القيمة `NULL`.
* `_tags` — وسوم الملف. النوع: `Map(String, String)`. إذا لم توجد أي وسوم، تكون القيمة خريطة فارغة &#96;{}&#39;.

لمزيد من المعلومات حول الأعمدة الافتراضية، راجع [هنا](../../../engines/table-engines/index.md#table_engines-virtual_columns).

<div id="implementation-details">
  ## تفاصيل التنفيذ
</div>

* يمكن إجراء عمليات القراءة والكتابة بالتوازي
* غير مدعوم:

  * عمليات `ALTER` و`SELECT...SAMPLE`.
  * الفهارس.
  * يمكن استخدام [النسخ المتماثل من دون نسخ](../../../operations/storing-data.md#zero-copy)، لكنه غير مدعوم.

  :::note النسخ المتماثل من دون نسخ غير جاهز لبيئات الإنتاج
  يكون النسخ المتماثل من دون نسخ معطّلًا افتراضيًا في ClickHouse الإصدار 22.8 وما بعده. لا يُنصح باستخدام هذه الميزة في بيئات الإنتاج.
  :::

<div id="wildcards-in-path">
  ## محارف البدل في `path`
</div>

يمكن للوسيطة `path` تحديد عدة ملفات باستخدام أحرف بديلة شبيهة بتلك المستخدمة في bash. ولكي يُعالَج الملف، يجب أن يكون موجودًا وأن يطابق نمط المسار بالكامل. ويُحدَّد سرد الملفات أثناء تنفيذ `SELECT` (وليس عند `CREATE`).

* `*` — يستبدل أي عدد من المحارف باستثناء `/`، بما في ذلك السلسلة الفارغة.
* `**` — يستبدل أي عدد من المحارف، بما في ذلك `/`، بما في ذلك السلسلة الفارغة.
* `?` — يستبدل أي محرف واحد.
* `{some_string,another_string,yet_another_one}` — يستبدل أيًّا من السلاسل `'some_string', 'another_string', 'yet_another_one'`.
* `{N..M}` — يستبدل أي رقم ضمن النطاق من N إلى M، شاملًا الحدّين. ويمكن أن تحتوي N وM على أصفار بادئة، مثل `000..078`.

تتشابه البُنى التي تستخدم `{}` مع دالة الجدول [remote](../../../sql-reference/table-functions/remote.md).

:::note
إذا كان سرد الملفات يتضمن نطاقات أرقام ذات أصفار بادئة، فاستخدم البنية ذات الأقواس المعقوفة لكل رقم على حدة أو استخدم `?`.
:::

**مثال على محارف البدل 1**

أنشئ جدولًا بملفات تحمل الأسماء `file-000.csv`, `file-001.csv`, ... , `file-999.csv`:

```sql
CREATE TABLE big_table (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/my_folder/file-{000..999}.csv', 'CSV');
```

**مثال مع محارف البدل 2**

لنفترض أن لدينا عدة ملفات بتنسيق CSV على S3 بعناوين URI التالية:

* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/some&#95;folder/some&#95;file&#95;1.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/some&#95;folder/some&#95;file&#95;2.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/some&#95;folder/some&#95;file&#95;3.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/another&#95;folder/some&#95;file&#95;1.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/another&#95;folder/some&#95;file&#95;2.csv&#39;
* &#39;https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/another&#95;folder/some&#95;file&#95;3.csv&#39;

هناك عدة طرق لإنشاء جدول يضم الملفات الستة جميعها:

1. حدّد نطاق لواحق أسماء الملفات:

```sql
CREATE TABLE table_with_range (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/{some,another}_folder/some_file_{1..3}', 'CSV');
```

2. خذ جميع الملفات ذات البادئة `some_file_` (يجب ألا توجد ملفات إضافية بهذه البادئة في أيٍّ من المجلدين):

```sql
CREATE TABLE table_with_question_mark (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/{some,another}_folder/some_file_?', 'CSV');
```

3. خذ جميع الملفات الموجودة في كلا المجلدين (يجب أن تستوفي جميع الملفات التنسيق والمخطط الموضحين في الاستعلام):

```sql
CREATE TABLE table_with_asterisk (name String, value UInt32)
    ENGINE = S3('https://clickhouse-public-datasets.s3.amazonaws.com/my-bucket/{some,another}_folder/*', 'CSV');
```

<div id="storage-settings">
  ## إعدادات التخزين
</div>

* [s3&#95;truncate&#95;on&#95;insert](/ar/operations/settings/settings.md#s3_truncate_on_insert) - يسمح باقتطاع الملف قبل الإدراج فيه. يكون معطّلًا افتراضيًا.
* [s3&#95;create&#95;new&#95;file&#95;on&#95;insert](/ar/operations/settings/settings.md#s3_create_new_file_on_insert) - يسمح بإنشاء ملف جديد عند كل عملية إدراج إذا كانت للتنسيق لاحقة. يكون معطّلًا افتراضيًا.
* [s3&#95;skip&#95;empty&#95;files](/ar/operations/settings/settings.md#s3_skip_empty_files) - يسمح بتخطي الملفات الفارغة أثناء القراءة. يكون مفعّلًا افتراضيًا.

<div id="settings">
  ## الإعدادات المرتبطة بـ S3
</div>

يمكن ضبط الإعدادات التالية قبل تنفيذ الاستعلام أو وضعها في ملف التهيئة.

* `s3_max_single_part_upload_size` — الحد الأقصى لحجم الكائن الذي يمكن رفعه إلى S3 باستخدام رفع أحادي الجزء. القيمة الافتراضية هي `32Mb`.
* `s3_min_upload_part_size` — الحد الأدنى لحجم الجزء المراد رفعه أثناء الرفع متعدد الأجزاء إلى [الرفع متعدد الأجزاء في S3](https://docs.aws.amazon.com/AmazonS3/latest/dev/uploadobjusingmpu.html). القيمة الافتراضية هي `16Mb`.
* `s3_max_redirects` — الحد الأقصى لعدد قفزات إعادة التوجيه المسموح بها في S3. القيمة الافتراضية هي `10`.
* `s3_single_read_retries` — الحد الأقصى لعدد المحاولات أثناء القراءة الواحدة. القيمة الافتراضية هي `4`.
* `s3_max_put_rps` — الحد الأقصى لمعدل طلبات PUT في الثانية قبل تطبيق تقييد المعدل. القيمة الافتراضية هي `0` (غير محدود).
* `s3_max_put_burst` — الحد الأقصى لعدد الطلبات التي يمكن إصدارها بالتزامن قبل بلوغ حد الطلبات في الثانية. افتراضيًا (عند القيمة `0`) يساوي `s3_max_put_rps`.
* `s3_max_get_rps` — الحد الأقصى لمعدل طلبات GET في الثانية قبل تطبيق تقييد المعدل. القيمة الافتراضية هي `0` (غير محدود).
* `s3_max_get_burst` — الحد الأقصى لعدد الطلبات التي يمكن إصدارها بالتزامن قبل بلوغ حد الطلبات في الثانية. افتراضيًا (عند القيمة `0`) يساوي `s3_max_get_rps`.
* `s3_upload_part_size_multiply_factor` - يُضرَب `s3_min_upload_part_size` في هذا العامل كلما تم رفع `s3_multiply_parts_count_threshold` جزءًا من عملية كتابة واحدة إلى S3. القيمة الافتراضية هي `2`.
* `s3_upload_part_size_multiply_parts_count_threshold` - في كل مرة يُرفع فيها هذا العدد من الأجزاء إلى S3، يُضرَب `s3_min_upload_part_size` في `s3_upload_part_size_multiply_factor`. القيمة الافتراضية هي `500`.
* `s3_max_inflight_parts_for_one_file` - يقيّد عدد طلبات PUT التي يمكن تشغيلها بالتزامن لكائن واحد. يجب إبقاء هذا العدد ضمن حد معيّن. تعني القيمة `0` عدم وجود حد. القيمة الافتراضية هي `20`. ولكل جزء قيد النقل مخزن مؤقت بحجم `s3_min_upload_part_size` لأول `s3_upload_part_size_multiply_factor` من الأجزاء، ويزداد هذا الحجم عندما يكون الملف كبيرًا بما يكفي؛ راجع `upload_part_size_multiply_factor`. وباستخدام الإعدادات الافتراضية، لا يستهلك الملف المرفوع أكثر من `320Mb` إذا كان حجمه أقل من `8G`. ويكون الاستهلاك أكبر للملفات الأكبر حجمًا.

اعتبارات أمنية: إذا كان بإمكان مستخدم خبيث تحديد عناوين URL عشوائية لـ S3، فيجب ضبط `s3_max_redirects` على الصفر لتجنب هجمات [SSRF](https://en.wikipedia.org/wiki/Server-side_request_forgery)؛ أو بدلًا من ذلك، يجب تحديد `remote_host_filter` في تهيئة الخادم.

<div id="endpoint-settings">
  ## الإعدادات المستندة إلى نقطة النهاية
</div>

يمكن تحديد الإعدادات التالية في ملف التهيئة لنقطة نهاية معيّنة (ستُطابَق باستخدام بادئة URL مطابقة تمامًا):

* `endpoint` — يحدّد بادئة نقطة النهاية. إلزامي.
* `access_key_id` و `secret_access_key` — يحدّدان بيانات الاعتماد المستخدمة مع نقطة النهاية المحددة. اختياري.
* `use_environment_credentials` — إذا ضُبط على `true`، فسيحاول عميل S3 الحصول على بيانات الاعتماد من متغيرات البيئة وبيانات [Amazon EC2](https://en.wikipedia.org/wiki/Amazon_Elastic_Compute_Cloud) الوصفية لنقطة النهاية المحددة. اختياري، والقيمة الافتراضية هي `false`.
* `region` — يحدّد اسم منطقة S3. اختياري.
* `use_insecure_imds_request` — إذا ضُبط على `true`، فسيستخدم عميل S3 طلب IMDS غير آمن عند الحصول على بيانات الاعتماد من بيانات Amazon EC2 الوصفية. اختياري، والقيمة الافتراضية هي `false`.
* `expiration_window_seconds` — فترة سماح للتحقق مما إذا كانت بيانات الاعتماد المستندة إلى انتهاء الصلاحية قد انتهت. اختياري، والقيمة الافتراضية هي `120`.
* `no_sign_request` - يتجاهل جميع بيانات الاعتماد بحيث لا تُوقَّع الطلبات. مفيد للوصول إلى buckets عامة.
* `header` — يضيف ترويسة HTTP محددة إلى طلب مُرسل إلى نقطة النهاية المحددة. اختياري، ويمكن تحديده عدة مرات.
* `access_header` - يضيف ترويسة HTTP محددة إلى طلب مُرسل إلى نقطة النهاية المحددة، في الحالات التي لا تتوفر فيها بيانات اعتماد أخرى من مصدر آخر.
* `server_side_encryption_customer_key_base64` — إذا تم تحديده، فستُضبط الترويسات المطلوبة للوصول إلى كائنات S3 المشفّرة باستخدام SSE-C. اختياري.
* `server_side_encryption_kms_key_id` - إذا تم تحديده، فستُضبط الترويسات المطلوبة للوصول إلى كائنات S3 المشفّرة باستخدام [SSE-KMS encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html). إذا تم تحديد سلسلة فارغة، فسيُستخدم مفتاح S3 المُدار من AWS. اختياري.
* `server_side_encryption_kms_encryption_context` - إذا تم تحديده مع `server_side_encryption_kms_key_id`، فستُضبط ترويسة سياق التشفير المحددة لـ SSE-KMS. اختياري.
* `server_side_encryption_kms_bucket_key_enabled` - إذا تم تحديده مع `server_side_encryption_kms_key_id`، فستُضبط الترويسة اللازمة لتمكين مفاتيح S3 bucket لـ SSE-KMS. اختياري، ويمكن أن تكون قيمته `true` أو `false`، وافتراضيًا لا يتم تعيين أي شيء (ليطابق الإعداد على مستوى bucket).
* `max_single_read_retries` — الحد الأقصى لعدد المحاولات أثناء القراءة الواحدة. القيمة الافتراضية هي `4`. اختياري.
* `max_put_rps`, `max_put_burst`, `max_get_rps` و `max_get_burst` - إعدادات throttling (انظر الوصف أعلاه) المستخدمة لنقطة نهاية محددة بدلًا من أن تكون لكل استعلام. اختياري.

**مثال:**

```xml
<s3>
    <endpoint-name>
        <endpoint>https://clickhouse-public-datasets.s3.amazonaws.com/my-test-bucket-768/</endpoint>
        <!-- <access_key_id>ACCESS_KEY_ID</access_key_id> -->
        <!-- <secret_access_key>SECRET_ACCESS_KEY</secret_access_key> -->
        <!-- <region>us-west-1</region> -->
        <!-- <use_environment_credentials>false</use_environment_credentials> -->
        <!-- <use_insecure_imds_request>false</use_insecure_imds_request> -->
        <!-- <expiration_window_seconds>120</expiration_window_seconds> -->
        <!-- <no_sign_request>false</no_sign_request> -->
        <!-- <header>Authorization: Bearer SOME-TOKEN</header> -->
        <!-- <server_side_encryption_customer_key_base64>BASE64-ENCODED-KEY</server_side_encryption_customer_key_base64> -->
        <!-- <server_side_encryption_kms_key_id>KMS_KEY_ID</server_side_encryption_kms_key_id> -->
        <!-- <server_side_encryption_kms_encryption_context>KMS_ENCRYPTION_CONTEXT</server_side_encryption_kms_encryption_context> -->
        <!-- <server_side_encryption_kms_bucket_key_enabled>true</server_side_encryption_kms_bucket_key_enabled> -->
        <!-- <max_single_read_retries>4</max_single_read_retries> -->
    </endpoint-name>
</s3>
```

<div id="working-with-archives">
  ## العمل مع الأرشيفات
</div>

لنفترض أن لدينا عدة ملفات أرشيفية بعناوين URI التالية على S3:

* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-10.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-11.csv.zip&#39;
* &#39;https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-12.csv.zip&#39;

يمكن استخراج البيانات من هذه الأرشيفات باستخدام ::. ويمكن استخدام أنماط glob سواء في جزء الـ URL أو في الجزء الذي يلي :: (وهو المسؤول عن اسم الملف داخل الأرشيف).

```sql
SELECT *
FROM s3(
   'https://s3-us-west-1.amazonaws.com/umbrella-static/top-1m-2018-01-1{0..2}.csv.zip :: *.csv'
);
```

:::note
يدعم ClickHouse ثلاثة تنسيقات للأرشيف:
ZIP
TAR
7Z
في حين يمكن الوصول إلى أرشيفات ZIP وTAR من أي موقع تخزين مدعوم، لا يمكن قراءة أرشيفات 7Z إلا من نظام الملفات المحلي الذي ثُبّت عليه ClickHouse.
:::

<div id="accessing-public-buckets">
  ## الوصول إلى الـ buckets العامة
</div>

يحاول ClickHouse جلب بيانات الاعتماد من أنواع عديدة ومختلفة من المصادر.
وأحيانًا قد يسبب ذلك مشكلات عند الوصول إلى بعض الـ buckets العامة، ما يؤدي إلى أن يعيد العميل رمز الخطأ `403`.
يمكن تجنب هذه المشكلة باستخدام الكلمة المحجوزة `NOSIGN`، ما يُجبر العميل على تجاهل جميع بيانات الاعتماد وعدم توقيع الطلبات.

```sql
CREATE TABLE big_table (name String, value UInt32)
    ENGINE = S3('https://datasets-documentation.s3.eu-west-3.amazonaws.com/aapl_stock.csv', NOSIGN, 'CSVWithNames');
```

<div id="role-based-access">
  ## الوصول المستند إلى الأدوار
</div>

في ClickHouse Cloud، يمكنك استخدام الوصول المستند إلى الأدوار للمصادقة على S3 بدلًا من استخدام مفاتيح الوصول. راجع [Secure S3](/ar/cloud/data-sources/secure-s3) للاطلاع على خطوات التهيئة.

بعد إتمام التهيئة، يمكن تمرير `roleARN` عبر المعلمة `extra_credentials`:

```sql
CREATE TABLE my_s3_table(name String, value UInt32)
ENGINE = S3('https://my-bucket.s3.amazonaws.com/data/*.csv', extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001'), 'CSV')
```

يمكن أيضًا تمرير `external_id` اختياريًا إلى جانب `role_arn`. ويُمرَّر بوصفه المعلَمة `ExternalId` في استدعاء AWS STS `AssumeRole`، مما يتيح لسياسة الثقة للدور اشتراط سر مشترك للتخفيف من [مشكلة النائب المرتبك](https://docs.aws.amazon.com/IAM/latest/UserGuide/confused-deputy.html):

```sql
CREATE TABLE my_s3_table(name String, value UInt32)
ENGINE = S3('https://my-bucket.s3.amazonaws.com/data/*.csv', extra_credentials(role_arn = 'arn:aws:iam::111111111111:role/ClickHouseAccessRole-001', external_id = 'my-external-id'), 'CSV')
```
