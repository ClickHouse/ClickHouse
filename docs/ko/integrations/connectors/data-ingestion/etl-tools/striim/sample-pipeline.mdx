SQL Server의 운영 데이터는 주문, 결제, 재고에 대한 신뢰할 수 있는 기준 정보인 경우가 많지만, 대규모 분석 쿼리에 적합하도록 설계되지는 않았습니다. 이 가이드에서는 자동화된 파이프라인을 사용하여 SQL Server 테이블을 ClickHouse로 복제합니다. Striim은 먼저 기존 행을 로드한 다음, 발생하는 모든 삽입, UPDATE, 삭제(deletes)를 실시간으로 스트리밍합니다. 그런 다음 ClickHouse에서 결과를 쿼리합니다.

전체 과정은 [Introducing Automated Pipelines for Effortless Data Replication](https://www.striim.com/blog/automated-pipelines-5-0/)을 참조하십시오.

SQL Server CDC(Change Data Capture)를 사용하려면 Striim for ClickHouse **Premium** 플랜이 필요합니다.

## 구축할 내용 {#what-you-will-build}

SQL Server (`sales.orders`) &gt; Striim 초기 적재(initial load) 후 CDC &gt; ClickHouse (`sales.orders`, `ReplacingMergeTree`)

## 시작하기 전에 {#before-you-begin}

* Premium 플랜에서 실행 중인 Striim for ClickHouse 서비스가 필요합니다([시작하기](/ko/integrations/connectors/data-ingestion/etl-tools/striim/get-started) 참조).
* Striim에서 연결할 수 있고 SQL Server Agent가 실행 중인 SQL Server 인스턴스와 변경 데이터 캡처(Change Data Capture)를 활성화할 수 있는 권한(permission)이 필요합니다. 아래 단계는 가상 머신(VM)에서 실행되는 SQL Server와 Amazon RDS for SQL Server 모두에 적용됩니다.
* ClickHouse 서비스, `sales`라는 이름의 데이터베이스, 필요한 권한을 가진 Striim 사용자, ClickHouse 연결(Connection) 프로필이 필요합니다.

## 1단계: SQL Server 준비 {#step-1-prepare-sql-server}

데이터베이스를 만들고 몇 개의 행이 포함된 예제 테이블을 생성하십시오. 이 초기 데이터는 설명을 위한 것으로, 예시를 직접 재현해 볼 수 있도록 제공됩니다.

```sql
CREATE DATABASE salesdb;
GO
USE salesdb;
GO
CREATE SCHEMA sales;
GO
CREATE TABLE sales.orders (
  order_id    INT           NOT NULL PRIMARY KEY,
  customer_id INT           NOT NULL,
  status      VARCHAR(20)   NOT NULL,
  total       DECIMAL(10,2) NOT NULL,
  placed_at   DATETIME2     NOT NULL
);
INSERT INTO sales.orders VALUES
  (1, 101, 'NEW',     120.50, SYSDATETIME()),
  (2, 102, 'NEW',      75.00, SYSDATETIME()),
  (3, 103, 'NEW',     310.25, SYSDATETIME());
GO
```

데이터베이스에서 변경 데이터 캡처(Change Data Capture)를 활성화하고 Striim에서 사용할 사용자를 생성하십시오. Striim은 애플리케이션이 시작될 때 선택한 각 테이블에 대해 CDC를 활성화합니다.

<Tabs>
  <Tab title="가상 머신(VM)의 SQL Server" id="enable-cdc-vm">
    ```sql
    USE salesdb;
    EXEC sys.sp_cdc_enable_db;
    ```
  </Tab>

  <Tab title="Amazon RDS for SQL Server" id="enable-cdc-rds">
    ```sql
    EXEC msdb.dbo.rds_cdc_enable_db 'salesdb';
    ```
  </Tab>
</Tabs>

`salesdb`에 Striim 사용자를 생성하십시오.

```sql
USE salesdb;
CREATE LOGIN striim WITH PASSWORD = '<strong password>';
CREATE USER striim FOR LOGIN striim;
EXEC sp_addrolemember @rolename = db_owner, @membername = striim;
```

Striim 사용자에 대해 SQL Server 인증 모드가 활성화되어 있어야 합니다. Striim 문서에서는 리더(reader) 사용자에게 `db_owner` 권한을 부여하도록 안내합니다. 파이프라인이 시작된 후 `EXEC sys.sp_cdc_help_change_data_capture`를 실행하여 CDC가 활성 상태인지 확인할 수 있습니다. Azure 가상 머신(VM)의 사전 요구 사항과 Always On 가용성 그룹에 대해서는 [Configuring SQL Server to use MS SQL Reader](https://www.striim.com/docs/striimforclickhouse/en/configuring-sql-server-to-use-ms-sql-reader.html)를 참조하십시오.

## 2단계: 자동화 파이프라인 생성 {#step-2-create-the-automated-pipeline}

1. Striim에서 **Apps &gt; Create an App**을 선택합니다.
2. 소스로 **SQL Server**를 검색하여 선택하고, 대상으로 **ClickHouse**를 선택합니다.
3. **Get Started**를 선택하고 자동화 파이프라인(초기 적재(initial load) + CDC)을 선택합니다.
4. 파이프라인 이름(예: `SqlServerToClickHouse`)을 지정하고 네임스페이스를 선택한 다음 **Next**를 선택합니다.
5. SQL Server 연결 정보로 호스트와 포트(`<host>:1433`), 데이터베이스 이름 `salesdb`, `striim` 사용자를 입력한 후 **Next**를 선택합니다. Striim이 연결 유효성 검사를 수행합니다. 유효성 검사에 실패하면 **Back**을 선택하여 설정을 수정하십시오. 유효성 검사를 통과해야 다음 단계로 진행할 수 있습니다.
6. 복제할 스키마(schemas)를 선택합니다. `sales`를 선택하고, 시스템 스키마는 선택하지 마십시오.
7. 각 스키마에서 복제할 테이블(tables)을 선택합니다. 여기서는 `orders`를 선택합니다.
8. ClickHouse 연결 프로필을 선택하고 **Table Engine**을 **`ReplacingMergeTree`**&#xB85C; 설정합니다. 이 엔진은 UPDATE 시 전체 행 이미지를 전송하는 CDC 소스에 적합합니다.
9. 필요한 경우 테이블 매핑을 편집합니다. `sales.orders`가 ClickHouse의 `sales.orders`에 매핑되는지 확인하십시오.
10. 설정을 검토하고 **Save &amp; Start**를 선택합니다.

![SQL Server에서 ClickHouse로의 자동화 파이프라인 구성 검토](/images/integrations/striim/automated-pipeline-wizard.png)

*마법사 검토 화면 예시입니다. 이 실습에서는 위에서 설명한 대로 `salesdb`, `sales.orders`, `ReplacingMergeTree`를 사용하십시오.*

Striim은 서로 연결된 2개의 애플리케이션을 생성합니다. 먼저 초기 적재를 실행하고, 모든 행이 복사되면 이를 정지(quiesce)한 후 CDC 애플리케이션을 자동으로 시작합니다. 변경 사항이 전달되는 동안에는 이벤트 발생 횟수가 표시됩니다. 어느 단계에서든 문제가 발생하면 파이프라인이 중단되고 권장 해결 방법이 표시됩니다.

![실행 중인 변경 데이터 캡처(Change Data Capture) 애플리케이션 모니터링](/images/integrations/striim/pipeline-monitoring.png)

<Warning>
  초기 적재가 진행되는 동안에는 원본 테이블에 DDL을 실행하지 마십시오. 또한 초기 적재가 시작된 시점부터 CDC 애플리케이션이 변경 사항을 모두 따라잡을 때까지 SQL Server에 변경 데이터가 보존되도록 하십시오(기본 보존 기간은 3일입니다).
</Warning>

## 3단계: ClickHouse에서 초기 적재(initial load) 확인 {#step-3-verify-the-initial-load-in-clickhouse}

Striim은 `ReplacingMergeTree` 엔진을 사용하고 메타데이터 컬럼 2개를 포함하는 대상 테이블을 생성했습니다. 다음과 같이 테이블을 확인하십시오:

```sql
SHOW CREATE TABLE sales.orders;
```

Striim 데이터 타입 매핑(type mapping)에 따라 `order_id`와 `customer_id`는 `Int32`, `status`는 `String`, `total`은 `Decimal(10, 2)`, `placed_at`은 `DateTime64`로 생성되어야 합니다. 또한 `__STRIIM_VERSION`(`UInt64`) 및 `__STRIIM_ISDELETED`(`UInt8`) 컬럼과 `ENGINE = ReplacingMergeTree(__STRIIM_VERSION, __STRIIM_ISDELETED)`, `ORDER BY order_id`가 포함되어 있어야 합니다.

```sql
SELECT order_id, customer_id, status, total
FROM sales.orders FINAL
WHERE __STRIIM_ISDELETED = 0
ORDER BY order_id;
```

SQL Server에서 로드된 3개의 행이 표시되어야 합니다.

## 4단계: 변경 사항 스트리밍 {#step-4-stream-changes}

SQL Server에서 데이터를 변경합니다:

```sql
USE salesdb;
UPDATE sales.orders SET status = 'SHIPPED' WHERE order_id = 2;
DELETE FROM sales.orders WHERE order_id = 3;
INSERT INTO sales.orders VALUES (4, 104, 'NEW', 42.00, SYSDATETIME());
```

ClickHouse에서 동일한 쿼리를 다시 실행하십시오. 주문 1, 2, 4가 조회되고, 주문 2는 `SHIPPED`로 표시되며, 주문 3은 조회되지 않아야 합니다. 삭제는 소프트 삭제(soft-delete) 행으로 저장됩니다. 이 쿼리는 `FINAL`을 사용하여 최신 버전을 조회하고, `__STRIIM_ISDELETED = 0` 조건으로 삭제된 행(rows)을 제외합니다. 삭제 마커는 기본적으로 유지되며, 백그라운드 머지만으로는 물리적 삭제가 보장되지 않습니다. 정리 동작은 [`ReplacingMergeTree`](/ko/reference/engines/table-engines/mergetree-family/replacingmergetree#is_deleted) 문서를 참고하십시오. Striim 모니터링 뷰에서 이벤트 발생 횟수와 대상 최신성을 확인하거나, Clara에게 현재 지연을 문의할 수도 있습니다.

## Striim Clara로 동일한 파이프라인 구축하기 {#build-the-same-pipeline-with-striim-clara}

마법사를 사용하는 대신 홈 페이지에서 원하는 파이프라인을 설명하여 구축할 수도 있습니다. 예를 들어 &quot;sales.orders 테이블에 대해 초기 적재(initial load)와 변경 데이터 캡처(Change Data Capture)를 수행하는 SQL Server에서 ClickHouse로의 파이프라인을 구축해 줘.&quot;와 같이 입력합니다. Clara는 연결 정보를 요청하고 TQL 계획을 생성하며, **Accept TQL**을 선택한 경우에만 배포를 진행합니다.

## 정리 {#clean-up}

* Apps 페이지에서 두 Striim 애플리케이션을 중지하고 배포를 해제하십시오.
* 기본 리더 설정을 사용하면 Striim 애플리케이션의 배포를 해제한 후에도 SQL Server가 변경 데이터를 계속 캡처합니다. 이 예제의 데이터 캡처를 중지하려면 `sales.orders`에 대해 `sys.sp_cdc_disable_table`을 실행하십시오. 데이터베이스의 다른 테이블에 CDC가 필요하지 않다면 `sys.sp_cdc_disable_db`를 실행해도 됩니다. 자세한 내용은 SQL Server [문서](https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sys-sp-cdc-disable-table-transact-sql)를 참조하십시오. 또는 Striim의 [Auto Disable Table CDC 절차](https://www.striim.com/docs/striimforclickhouse/en/sql-server-operational-considerations.html)를 따라도 됩니다.
* 두 시스템 모두에서 `DROP TABLE sales.orders;`를 실행하여 예제 테이블을 삭제하십시오.
