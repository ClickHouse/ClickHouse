<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 기본 `schema_inference_make_columns_nullable` 설정이 이제 모든 컬럼을 널 허용(Nullable)로 만드는 대신, Parquet/ORC/Arrow 메타데이터의 컬럼 `Nullable` 정보를 따르도록 변경되었습니다. 텍스트 형식에는 변경이 없습니다. [#71499](https://github.com/ClickHouse/ClickHouse/pull/71499) ([Michael Kolupaev](https://github.com/al13n321)).
* 이 PR에서는 쿼리 결과 캐시가 `log_comment` 설정을 무시하도록 변경하여, 이제 쿼리에서 `log_comment`만 바꿔도 더 이상 캐시 미스가 발생하지 않습니다. 사용자가 `log_comment`를 달리해 의도적으로 캐시를 분리해 두었을 가능성은 작지만 있습니다. 이 변경은 해당 동작을 바꾸므로 이전 버전과 호환되지 않습니다. 이 용도로는 `query_cache_tag` 설정을 사용하십시오. [#79878](https://github.com/ClickHouse/ClickHouse/pull/79878) ([filimonov](https://github.com/filimonov)).
* 이전 버전에서는 연산자의 구현 함수와 같은 이름을 가진 테이블 함수가 포함된 쿼리가 일관되지 않게 포맷되었습니다. [#81601](https://github.com/ClickHouse/ClickHouse/issues/81601) 해소. [#81977](https://github.com/ClickHouse/ClickHouse/issues/81977) 해소. [#82834](https://github.com/ClickHouse/ClickHouse/issues/82834) 해소. [#82835](https://github.com/ClickHouse/ClickHouse/issues/82835) 해소. EXPLAIN SYNTAX 쿼리에서는 연산자를 포맷하지 않습니다. 새로운 동작이 구문 설명의 목적을 더 잘 반영하기 때문입니다. `clickhouse-format`, `formatQuery` 및 유사한 기능은 쿼리에 함수형 형태로 포함된 함수를 연산자로 포맷하지 않습니다. [#82825](https://github.com/ClickHouse/ClickHouse/pull/82825) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* JOIN 키에서 Dynamic 유형을 사용하는 것을 금지합니다. Dynamic 유형을 비Dynamic 유형과 비교하면 예기치 않은 결과가 발생할 수 있기 때문입니다. Dynamic 컬럼을 필요한 유형으로 변환하는 것이 좋습니다. [#86358](https://github.com/ClickHouse/ClickHouse/pull/86358) ([Pavel Kruglov](https://github.com/Avogar)).
* Storage&#95;metadata&#95;write&#95;full&#95;object&#95;key 서버 옵션이 기본적으로 활성화되며, 이제 비활성화할 수 없습니다. 이는 하위 호환되는 변경입니다. 주의를 위해 이 레이블을 사용했습니다. 이 변경은 25.x 릴리스에서만 정방향 호환됩니다. 즉, 새 릴리스를 롤백해야 하는 경우 25.x 릴리스로만 다운그레이드할 수 있습니다. [#87335](https://github.com/ClickHouse/ClickHouse/pull/87335) ([Sema Checherinda](https://github.com/CheSema)).
* 삽입 속도가 낮을 때 ZooKeeper에 저장되는 znode 수를 줄이기 위해 replicated&#95;deduplication&#95;window&#95;seconds를 1주에서 1시간으로 줄였습니다. [#87414](https://github.com/ClickHouse/ClickHouse/pull/87414) ([Sema Checherinda](https://github.com/CheSema)).
* 설정 `query_plan_use_new_logical_join_step`의 이름을 `query_plan_use_logical_join_step`로 변경했습니다. [#87679](https://github.com/ClickHouse/ClickHouse/pull/87679) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 새로운 구문을 통해 토크나이저 매개변수를 더 유연하게 표현할 수 있습니다. [#87997](https://github.com/ClickHouse/ClickHouse/pull/87997) ([Elmi Ahmadov](https://github.com/ahmadov)).
* 기존 함수 `hasToken`과의 일관성을 높이기 위해 함수 `searchAny`와 `searchAll`의 이름을 `hasAnyTokens`와 `hasAllTokens`로 변경했습니다. [#88109](https://github.com/ClickHouse/ClickHouse/pull/88109) ([Robert Schulze](https://github.com/rschu1ze)).
* 파일 시스템 캐시에서 `cache_hits_threshold`를 제거했습니다. 이 기능은 SLRU 캐시 정책이 도입되기 전에 외부 기여자가 추가한 것이며, 이제 SLRU 캐시 정책이 있으므로 둘 다 지원할 필요가 없습니다. [#88344](https://github.com/ClickHouse/ClickHouse/pull/88344) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `min_free_disk_ratio_to_perform_insert` 및 `min_free_disk_bytes_to_perform_insert` 설정의 동작 방식에 두 가지 사소한 변경이 있습니다: - 삽입을 거부할지 판단할 때 available bytes 대신 예약되지 않은 바이트 수를 사용합니다. 백그라운드 머지와 뮤테이션을 위한 예약 공간이 구성된 임계값에 비해 작다면 이것이 아주 중요하지 않을 수도 있지만, 이 방식이 더 올바른 것으로 보입니다. - 이 설정은 시스템 테이블에 적용하지 않습니다. 그 이유는 `query_log` 같은 테이블은 계속 갱신되어야 하기 때문입니다. 이는 디버깅에 큰 도움이 됩니다. 시스템 테이블에 기록되는 데이터는 일반적으로 실제 데이터에 비해 작으므로, 적절한 `min_free_disk_ratio_to_perform_insert` 임계값이 설정되어 있다면 훨씬 더 오랫동안 계속 기록할 수 있어야 합니다. [#88468](https://github.com/ClickHouse/ClickHouse/pull/88468) ([c-end](https://github.com/c-end)).
* Keeper의 내부 복제에 비동기 모드를 활성화합니다. Keeper는 기존과 동일한 동작을 유지하면서 성능이 개선될 수 있습니다. 23.9보다 오래된 버전에서 업데이트하는 경우 먼저 23.9+로 업데이트한 다음 25.10+로 업데이트해야 합니다. 업데이트 전에 `keeper_server.coordination_settings.async_replication`을 0으로 설정하고, 업데이트가 완료된 후 다시 활성화할 수도 있습니다. [#88515](https://github.com/ClickHouse/ClickHouse/pull/88515) ([Antonio Andelic](https://github.com/antonio2368)).





<div id="new-feature">
  #### 새 기능
</div>

* `naiveBayesClassifier` 함수가 추가되어 ngrams를 기반으로 Naive Bayes를 사용해 텍스트를 분류할 수 있습니다. [#78700](https://github.com/ClickHouse/ClickHouse/pull/78700) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Sparse&#95;gram 블룸 필터 인덱스. [#79985](https://github.com/ClickHouse/ClickHouse/pull/79985) ([scanhex12](https://github.com/scanhex12)).
* `--login`을 사용해 Cloud 자격 증명으로 ClickHouse Cloud 인스턴스에 액세스할 수 있습니다. [#82753](https://github.com/ClickHouse/ClickHouse/pull/82753) ([Krishna Mannem](https://github.com/kcmannem)).
* 진법 간 숫자 변환을 위한 새로운 `conv` 함수가 추가되었으며, 현재 `2-36` 진법을 지원합니다. [#83058](https://github.com/ClickHouse/ClickHouse/pull/83058) ([hp](https://github.com/hp77-creator)).
* `LIMIT BY ALL` 구문 지원이 추가되었습니다. `GROUP BY ALL` 및 `ORDER BY ALL`과 유사하게 `LIMIT BY ALL`은 SELECT 절의 모든 비집계 표현식을 LIMIT BY 키로 자동 확장합니다. 예를 들어 `SELECT id, name, count(*) FROM table GROUP BY id LIMIT 1 BY ALL`은 `SELECT id, name, count(*) FROM table GROUP BY id LIMIT 1 BY id, name`와 동일합니다. 이 기능을 사용하면 선택한 모든 비집계 컬럼을 명시적으로 나열하지 않고도 이를 기준으로 제한하는 쿼리를 더 간단하게 작성할 수 있습니다. [#59152](https://github.com/ClickHouse/ClickHouse/issues/59152)를 해결합니다. [#84079](https://github.com/ClickHouse/ClickHouse/pull/84079) ([Surya Kant Ranjan](https://github.com/iit2009046)).
* ClickHouse에서 Apache Paimon을 쿼리할 수 있도록 지원이 추가되었습니다. 이 통합을 통해 ClickHouse 사용자는 Paimon의 데이터 레이크 스토리지와 직접 상호작용할 수 있습니다. [#84423](https://github.com/ClickHouse/ClickHouse/pull/84423) ([JIaQi](https://github.com/JiaQiTang98)).
* `studentTTestOneSample` 집계 함수가 추가되었습니다. [#85436](https://github.com/ClickHouse/ClickHouse/pull/85436) ([Dylan](https://github.com/DylanBlakemore)).
* 히스토그램 버킷의 상한과 누적 값을 인수로 받아, 분위수 위치가 포함된 버킷의 상한과 하한 사이에서 선형 보간을 수행하는 집계 함수 `quantilePrometheusHistogram`이 추가되었습니다. 기존 히스토그램에서 PromQL `histogram_quantile()` 함수와 유사하게 동작합니다. [#86294](https://github.com/ClickHouse/ClickHouse/pull/86294) ([Stephen Chi](https://github.com/stephchi0)).
* `MergeTree` 테이블의 모든 적합한 컬럼에 대해 통계를 자동으로 생성하는 기능이 추가되었습니다. 생성할 통계 타입을 쉼표로 구분해 저장하는 테이블 수준 설정 `auto_statistics_types`도 추가되었습니다(예: `auto_statistics_types = 'minmax, uniq, countmin'`). [#87241](https://github.com/ClickHouse/ClickHouse/pull/87241) ([Anton Popov](https://github.com/CurtizJ)).
* Delta Lake 메타데이터 파일용 system table이 추가되었습니다. [#87263](https://github.com/ClickHouse/ClickHouse/pull/87263) ([scanhex12](https://github.com/scanhex12)).
* ZooKeeper 연결을 강제로 끊었다가 다시 연결하는 SYSTEM RECONNECT ZOOKEEPER 명령이 추가되었습니다 (https://github.com/ClickHouse/ClickHouse/issues/87317). [#87318](https://github.com/ClickHouse/ClickHouse/pull/87318) ([Pradeep Chhetri](https://github.com/chhetripradeep)).
* 설정 `max_named_collection_num_to_warn` 및 `max_named_collection_num_to_throw`를 통해 이름이 지정된 컬렉션 수를 제한합니다. 새로운 메트릭 `NamedCollection`과 오류 `TOO_MANY_NAMED_COLLECTIONS`도 추가되었습니다. [#87343](https://github.com/ClickHouse/ClickHouse/pull/87343) ([Pablo Marcos](https://github.com/pamarcos)).
* `startsWith` 및 `endsWith` 함수에 최적화된 대소문자 비구분 변형이 추가되었습니다: `startsWithCaseInsensitive`, `endsWithCaseInsensitive`, `startsWithCaseInsensitiveUTF8`, `endsWithCaseInsensitiveUTF8`. [#87374](https://github.com/ClickHouse/ClickHouse/pull/87374) ([Guang Zhao](https://github.com/zheguang)).
* 서버 구성 &quot;resources&#95;and&#95;workloads&quot; 섹션을 사용해 SQL에서 WORKLOAD 및 RESOURCE 정의를 지정할 수 있는 기능을 추가합니다. [#87430](https://github.com/ClickHouse/ClickHouse/pull/87430) ([Sergei Trifonov](https://github.com/serxa)).
* `Alias` engine는 다른 테이블에 대한 프록시를 생성합니다. 모든 읽기 및 쓰기 작업은 대상 테이블로 전달되며, alias 자체에는 데이터가 저장되지 않고 대상 테이블에 대한 참조만 유지합니다. [#87965](https://github.com/ClickHouse/ClickHouse/pull/87965) ([Kai Zhu](https://github.com/nauu)).
* 세미콜론이 새 줄이 아니라 마지막 줄에 배치되도록 쿼리 포맷을 지정하는 `--semicolons_inline` 옵션을 추가합니다. [#88018](https://github.com/ClickHouse/ClickHouse/pull/88018) ([Jan Rada](https://github.com/ZelvaMan)).
* 파트가 wide part로 생성되기 위한 최소 수준을 지정할 수 있는 새 테이블 설정 `min_level_for_wide_part`를 추가합니다. [#88179](https://github.com/ClickHouse/ClickHouse/pull/88179) ([Christoph Wurm](https://github.com/cwurm)).
* 음수 `LIMIT` 및 음수 `OFFSET` 지원을 추가합니다. [#28913](https://github.com/ClickHouse/ClickHouse/issues/28913)을 해결합니다. [#88411](https://github.com/ClickHouse/ClickHouse/pull/88411) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Keeper 클라이언트에 `cp`-`cpr` 및 `mv`-`mvr` 명령의 재귀 버전을 추가합니다. [#88570](https://github.com/ClickHouse/ClickHouse/pull/88570) ([Mikhail Artemenko](https://github.com/Michicosun)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 쿼리 조건 캐시(QCC)와 인덱스 분석의 순서 및 통합 방식을 재구성하여 쿼리 성능을 개선했습니다. 이제 QCC 필터링이 프라이머리 키와 스킵 인덱스 분석보다 먼저 적용되어 불필요한 인덱스 계산을 줄입니다. 또한 인덱스 분석이 여러 범위 필터를 지원하도록 확장되었으며, 필터링 결과도 다시 QCC에 저장됩니다. 이에 따라 인덱스 분석이 실행 시간의 대부분을 차지하는 쿼리, 특히 스킵 인덱스(예: 벡터 인덱스 또는 inverted index)에 의존하는 쿼리의 속도가 크게 향상됩니다. [#82380](https://github.com/ClickHouse/ClickHouse/pull/82380) ([Amos Bird](https://github.com/amosbird)).
* 압축을 개선하고 효율적인 서브컬럼 접근을 가능하게 하기 위해 MergeTree 테이블의 최상위 String 컬럼에 선택적 `.size` 서브컬럼 직렬화를 추가했습니다. 또한 직렬화 버전 제어와 빈 문자열에 대한 표현식 최적화를 위한 새로운 MergeTree 설정도 도입했습니다. [#82850](https://github.com/ClickHouse/ClickHouse/pull/82850) ([Amos Bird](https://github.com/amosbird)).
* 작은 쿼리의 속도를 높이기 위해 다양한 미세 최적화를 적용했습니다. [#83096](https://github.com/ClickHouse/ClickHouse/pull/83096) ([Raúl Marín](https://github.com/Algunenano)).
* native protocol에서 로그와 profile events를 압축합니다. 100개 이상의 레플리카가 있는 클러스터에서는 압축되지 않은 profile events가 초당 1..10 MB를 차지하며, 느린 인터넷 연결에서는 진행 표시줄이 굼뜹니다. 이 변경은 [#82533](https://github.com/ClickHouse/ClickHouse/issues/82533)을 해결합니다. [#83586](https://github.com/ClickHouse/ClickHouse/pull/83586) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* [StringZilla](https://github.com/ashvardanian/StringZilla) 라이브러리를 사용하고, 가능한 경우 SIMD CPU 명령어를 활용하여 대소문자를 구분하는 문자열 검색(예: 필터링 작업의 `WHERE URL LIKE '%google%'`) 성능을 개선했습니다. [#84161](https://github.com/ClickHouse/ClickHouse/pull/84161) ([Raúl Marín](https://github.com/Algunenano)).
* `SimpleAggregateFunction(anyLast)` 타입 컬럼이 있는 집계 MergeTree 테이블에서 FINAL과 함께 select할 때 메모리 할당과 메모리 복사를 줄였습니다. [#84428](https://github.com/ClickHouse/ClickHouse/pull/84428) ([Duc Canh Le](https://github.com/canhld94)).
* OR 조건의 JOIN 프레디케이트를 푸시다운하는 로직을 제공합니다. 예시: TPC-H Q7에서 2개의 테이블 n1과 n2에 대한 조건이 `(n1.n_name = 'FRANCE' AND n2.n_name = 'GERMANY') OR (n1.n_name = 'GERMANY' AND n2.n_name = 'FRANCE')`일 때, 각 테이블별로 별도의 부분 필터를 추출합니다. 즉 n1에 대해서는 `n1.n_name = 'FRANCE' OR n1.n_name = 'GERMANY'`, n2에 대해서는 `n2.n_name = 'GERMANY' OR n2.n_name = 'FRANCE'`를 추출합니다. [#84735](https://github.com/ClickHouse/ClickHouse/pull/84735) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
