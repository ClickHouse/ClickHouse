  ### ClickHouse 릴리스 v25.9.2.1-stable (c2a9511f7bc) FIXME v25.9.1.1-new (524fe1daa94)와 비교했을 때

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* IPv4/IPv6에 대한 비합리적인 이항 연산을 비활성화합니다. 정수형이 아닌 타입에 대해 IPv4/IPv6에 plus / minus를 적용하는 연산은 이제 비활성화됩니다. 이전에는 부동소수점 타입과의 연산은 허용되었고, 일부 다른 타입(예: DateTime)에서는 logical error를 발생시켰습니다. [#86336](https://github.com/ClickHouse/ClickHouse/pull/86336) ([Raúl Marín](https://github.com/Algunenano)).
* 설정 `allow_dynamic_metadata_for_data_lakes`는 더 이상 권장되지 않습니다. 이제 모든 Iceberg 테이블은 각 쿼리를 실행하기 전에 스토리지에서 최신 테이블 스키마를 가져오려고 시도합니다. [#86366](https://github.com/ClickHouse/ClickHouse/pull/86366) ([Daniil Ivanik](https://github.com/divanik)).
* 역텍스트 인덱스를 RAM에 모두 적재할 수 없는 데이터셋에도 확장 가능하도록 처음부터 다시 구현했습니다. [#86485](https://github.com/ClickHouse/ClickHouse/pull/86485) ([Anton Popov](https://github.com/CurtizJ)).

<div id="new-feature">

* 쿼리 설정에서 setting 이름만 단독으로 지정된 경우 `1`과 동일하게 처리합니다(예: `SELECT ... SETTINGS use_query_cache`는 `use_query_cache = 1`과 동일합니다). [#85800](https://github.com/ClickHouse/ClickHouse/pull/85800) ([thraeka](https://github.com/thraeka)).
* 새로운 구성 옵션 `logger.startupLevel` 및 `logger.shutdownLevel`을 사용하면 각각 ClickHouse 시작 및 종료 시 로그 레벨을 재정의할 수 있습니다. [#85967](https://github.com/ClickHouse/ClickHouse/pull/85967) ([Lennard Eijsackers](https://github.com/Blokje5)).
* 집계 함수 `timeSeriesChangesToGrid` 및 `timeSeriesResetsToGrid`를 추가했습니다. 이 함수들은 `timeSeriesRateToGrid`와 유사하게 동작하며, 시작 timestamp, 종료 timestamp, 간격, look back window에 대한 매개변수와 timestamps 및 values에 대한 두 개의 인수를 받지만, 각 윈도우에 2개 대신 최소 1개의 sample만 있으면 됩니다. 또한 매개변수로 정의된 time grid의 각 timestamp에 대해, 지정된 윈도우 내에서 sample 값이 변경되거나 감소한 횟수를 세는 PromQL `changes`/`resets`를 계산합니다. 반환 유형은 Array(Nullable(Float64))입니다. [#86010](https://github.com/ClickHouse/ClickHouse/pull/86010) ([Stephen Chi](https://github.com/stephchi0)).
* Iceberg 테이블 엔진에서 `ALTER UPDATE`를 지원합니다. [#86059](https://github.com/ClickHouse/ClickHouse/pull/86059) ([scanhex12](https://github.com/scanhex12)).
* SELECT SQL 문에서 Iceberg metadata files를 조회하기 위한 시스템 테이블 `iceberg_metadata_log`를 추가합니다. [#86152](https://github.com/ClickHouse/ClickHouse/pull/86152) ([scanhex12](https://github.com/scanhex12)).
* 임시 테이블과 동일한 구문으로 임시 뷰를 생성할 수 있습니다. [#86432](https://github.com/ClickHouse/ClickHouse/pull/86432) ([Aly Kafoury](https://github.com/AlyHKafoury)).
* 디스크 구성이 적용된 Iceberg 및 delta lake 테이블을 지원합니다. 이를 통해 기존 디스크를 사용하는 user tables를 지정할 수 있습니다. Iceberg에 사용할 특정 디스크를 허용하는 설정 `allowed_disks_for_table_engines`를 추가합니다. 예시: `CREATE TABLE test ENGINE = Iceberg('path/inside/disk') SETTING datalake_disk_name = '<some_user_disk>';` ### 사용자 대상 변경 사항에 대한 문서 항목입니다. [#86778](https://github.com/ClickHouse/ClickHouse/pull/86778) ([scanhex12](https://github.com/scanhex12)).
* CPU 및 메모리 관련 경고를 `system.warnings` 테이블에 추가했습니다. [#86838](https://github.com/ClickHouse/ClickHouse/pull/86838) ([Bharat Nallan](https://github.com/bharatnc)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* `func(primary_column) = 'xx'` 및 `column in (xxx)`와 같은 조건에 대한 PREWHERE 최적화를 개선했습니다. [#85529](https://github.com/ClickHouse/ClickHouse/pull/85529) ([李扬](https://github.com/taiyang-li)).
* JOIN 재작성 기능을 구현했습니다. 1. 일치한 행 또는 일치하지 않은 행에 대해 filter condition이 항상 false인 경우 `LEFT ANY JOIN` 및 `RIGHT ANY JOIN`을 `SEMI`/`ANTI` JOIN으로 변환합니다. 이 최적화는 새로운 설정 `query_plan_convert_any_join_to_semi_or_anti_join`으로 제어됩니다. 2. 한쪽의 일치하지 않은 행에 대해 filter condition이 항상 false인 경우 `FULL ALL JOIN`을 `LEFT ALL` 또는 `RIGHT ALL` JOIN으로 변환합니다. [#86028](https://github.com/ClickHouse/ClickHouse/pull/86028) ([Dmitry Novik](https://github.com/novikd)).
* 경량한 삭제 실행 후 수직 병합의 성능을 개선했습니다. [#86169](https://github.com/ClickHouse/ClickHouse/pull/86169) ([Anton Popov](https://github.com/CurtizJ)).
* `LEFT/RIGHT` join에 일치하지 않는 행이 많은 경우 `HashJoin` 성능을 소폭 최적화했습니다. [#86312](https://github.com/ClickHouse/ClickHouse/pull/86312) ([Nikita Taranov](https://github.com/nickitat)).
* RadixSort: 컴파일러가 SIMD를 활용하고 CPU가 더 효과적으로 프리페치할 수 있도록 개선했습니다. Intel CPU에서만 소프트웨어 프리페치를 사용하도록 동적 디스패치를 사용합니다. [https://github.com/ClickHouse/ClickHouse/pull/77029](https://github.com/ClickHouse/ClickHouse/pull/77029)에서 @taiyang-li가 진행한 작업을 이어갑니다. [#86378](https://github.com/ClickHouse/ClickHouse/pull/86378) ([Raúl Marín](https://github.com/Algunenano)).
* 이제 join 재정렬에 STATISTICS를 사용합니다. 이 기능은 `allow_statistics_optimize = 1` 및 `query_plan_optimize_join_order_limit = 10`을 설정해 활성화할 수 있습니다. [#86822](https://github.com/ClickHouse/ClickHouse/pull/86822) ([Han Fei](https://github.com/hanfei1991)).
* 테이블에 파트가 많은 경우 빠른 쿼리의 성능을 개선했습니다(`deque` 대신 `devector`를 사용해 `MarkRanges`를 최적화). [#86933](https://github.com/ClickHouse/ClickHouse/pull/86933) ([Azat Khuzhin](https://github.com/azat)).
* join 모드에서 patch 파트 적용 성능을 개선했습니다. [#87094](https://github.com/ClickHouse/ClickHouse/pull/87094) ([Anton Popov](https://github.com/CurtizJ)).

<div id="improvement">
  #### 개선 사항
</div>

* Azure blob storage 기반의 Unity Catalog를 지원합니다. [#80013](https://github.com/ClickHouse/ClickHouse/pull/80013) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 더 나은 성능을 위해 JOIN 순서를 자동으로 재정렬할 수 있는 실험적인 join order 최적화가 추가되었습니다(`query_plan_optimize_join_order_limit` 설정으로 제어됨). 현재 join order 최적화는 통계 지원이 제한적이며, 주로 스토리지 엔진의 행 수 추정치에 의존합니다. 더 정교한 통계 수집과 카디널리티 추정은 향후 릴리스에 추가될 예정입니다. **업그레이드 후 JOIN 쿼리에서 문제가 발생하면**, `SET query_plan_use_new_logical_join_step = 0`을 설정해 새 구현을 일시적으로 비활성화한 뒤 이슈를 등록해 조사할 수 있습니다. **USING 절의 식별자 해석 관련 참고 사항**: `OUTER JOIN ... USING` 절의 병합된 컬럼 해석이 더 일관되도록 변경되었습니다. 이전에는 OUTER JOIN에서 USING 컬럼과 테이블명이 붙은 컬럼(`a, t1.a, t2.a`)을 함께 선택하면, USING 컬럼이 잘못 `t1.a`로 해석되어 왼쪽과 일치하는 행이 없는 오른쪽 테이블의 행에 대해 0/NULL이 표시되었습니다. 이제 USING 절의 식별자는 항상 병합된 컬럼으로 해석되며, 테이블명이 붙은 식별자는 쿼리에 어떤 다른 식별자가 있는지와 관계없이 병합되지 않은 컬럼으로 해석됩니다. 예시: &#96;&#96;&#96;sql SELECT a, t1.a, t2.a FROM (SELECT 1 as a WHERE 0) t1 FULL JOIN (SELECT 2 as a) t2 USING (a) -- 변경 전: a=0, t1.a=0, t2.a=2 (잘못됨 - &#39;a&#39;가 t1.a로 해석됨) -- 변경 후: a=2, t1.a=0, t2.a=2 (정상 - &#39;a&#39;는 병합됨). [#80848](https://github.com/ClickHouse/ClickHouse/pull/80848) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 불필요한 인덱스 읽기를 줄이기 위해 읽기 중에 스킵 인덱스를 사용해 데이터 파트를 필터링할 수 있도록 지원합니다. 새로운 설정 `use_skip_indexes_on_data_read`로 제어되며(기본적으로 비활성화), 이는 [#75774](https://github.com/ClickHouse/ClickHouse/issues/75774)를 해결합니다. 여기에는 [#81021](https://github.com/ClickHouse/ClickHouse/issues/81021)과 공유되는 몇 가지 공통 기반 작업도 포함됩니다. [#81526](https://github.com/ClickHouse/ClickHouse/pull/81526) ([Amos Bird](https://github.com/amosbird)).
* S3 재시도 전략을 구성 가능하게 했고, 구성 XML 파일이 변경되면 S3 디스크 설정을 핫 리로드할 수 있도록 했습니다. [#82642](https://github.com/ClickHouse/ClickHouse/pull/82642) ([RinChanNOW](https://github.com/RinChanNOWWW)).
* 특수 컬럼을 사용해 oneof의 특정 part가 존재하는지 나타낼 수 있습니다. [#82885](https://github.com/ClickHouse/ClickHouse/pull/82885) ([Ilya Golshtein](https://github.com/ilejn)).
* 새로운 Kafka 테이블 엔진에 잘못된 설정이 지정되었을 때 사용자에게 더 명확한 안내를 제공하도록 했습니다. [#83701](https://github.com/ClickHouse/ClickHouse/pull/83701) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 이제 Time 타입에는 시간대를 지정할 수 없습니다. [#84689](https://github.com/ClickHouse/ClickHouse/pull/84689) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* `best_effort` 포맷에서 Time[64] 파싱과 관련된 로직을 단순화해 일부 버그도 방지했습니다. [#84730](https://github.com/ClickHouse/ClickHouse/pull/84730) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* materialized view를 생성할 때 `TO` 뒤에 쿼리 매개변수를 사용할 수 있습니다. 예시: `CREATE MATERIALIZED VIEW mv TO {to_table:Identifier} AS SELECT * FROM src_table`. [#84899](https://github.com/ClickHouse/ClickHouse/pull/84899) ([Diskein](https://github.com/Diskein)).
* jemalloc을 최신 버전으로 업데이트했습니다. jemalloc의 내부 도구를 기반으로 할당 프로파일링을 개선했습니다. 이제 구성 `jemalloc_enable_global_profiler`로 전역 jemalloc 프로파일러를 활성화할 수 있습니다. 샘플링된 전역 allocations 및 deallocations는 구성 `jemalloc_collect_global_profile_samples_in_trace_log`를 활성화하면 `JemallocSample` 유형으로 `system.trace_log`에 저장할 수 있습니다. 이제 설정 `jemalloc_enable_profiler`를 사용해 각 쿼리별로 Jemalloc 프로파일링을 독립적으로 활성화할 수 있습니다. `system.trace_log`에 samples를 저장할지는 설정 `jemalloc_collect_profile_samples_in_trace_log`로 쿼리별로 제어할 수 있습니다. [#85438](https://github.com/ClickHouse/ClickHouse/pull/85438) ([Antonio Andelic](https://github.com/antonio2368)).
* deltaLakeAzureCluster 함수(cluster용 deltaLakeAzure와 유사)와 deltaLakeS3Cluster 함수(deltaLakeCluster의 별칭)를 추가했습니다. [#85358](https://github.com/ClickHouse/ClickHouse/issues/85358)을 해결합니다. [#85547](https://github.com/ClickHouse/ClickHouse/pull/85547) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 일반 복사 작업에도 backup과 동일한 방식으로 azure&#95;max&#95;single&#95;part&#95;copy&#95;size 설정을 적용합니다. [#85767](https://github.com/ClickHouse/ClickHouse/pull/85767) ([Ilya Golshtein](https://github.com/ilejn)).
* S3 객체 스토리지에서 재시도 가능한 오류가 발생하면 S3 클라이언트 스레드의 속도를 늦추도록 했습니다. 이 변경으로 기존 설정 `backup_slow_all_threads_after_retryable_s3_error`가 S3 disk에도 확장되며, 더 일반적인 이름인 `s3_slow_all_threads_after_retryable_error`로 변경됩니다. [#85918](https://github.com/ClickHouse/ClickHouse/pull/85918) ([Julia Kartseva](https://github.com/jkartseva)).
