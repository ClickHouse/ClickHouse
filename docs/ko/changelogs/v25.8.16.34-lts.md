  #### 개선 사항

* [#95144](https://github.com/ClickHouse/ClickHouse/issues/95144)에서 백포트됨: dirty pages 크기와 `max_server_memory_usage`의 비율이 `memory_worker_purge_dirty_pages_threshold_ratio`를 초과하면 jemalloc arena에 대해 purge를 강제 수행합니다. [#93500](https://github.com/ClickHouse/ClickHouse/pull/93500) ([Eduard Karacharov](https://github.com/korowa)).
* [#94727](https://github.com/ClickHouse/ClickHouse/issues/94727)에서 백포트됨: S3 및 Azure Blob Storage용 BACKUP/RESTORE에서 SQL로 정의된 이름이 지정된 컬렉션을 지원합니다. [#94604](https://github.com/ClickHouse/ClickHouse/issues/94604)를 해결합니다. [#94605](https://github.com/ClickHouse/ClickHouse/pull/94605) ([Pablo Marcos](https://github.com/pamarcos)).
* [#95165](https://github.com/ClickHouse/ClickHouse/issues/95165)에서 백포트됨: MemoryWorker의 메인 스레드가 아닌 별도 스레드에서 jemalloc dirty pages의 purge를 실행합니다. purge가 느리면 RSS 사용량 업데이트가 지연되어 프로세스가 메모리 부족으로 강제 종료될 수 있습니다. 총 메모리 사용량 비율을 기준으로 dirty pages의 purge를 시작하는 새로운 구성 `memory_worker_purge_total_memory_threshold_ratio`를 도입했습니다. [#94902](https://github.com/ClickHouse/ClickHouse/pull/94902) ([Antonio Andelic](https://github.com/antonio2368)).
* [#95432](https://github.com/ClickHouse/ClickHouse/issues/95432)에서 백포트됨: 이제 `view_duration_ms`는 그룹 내 스레드 Duration의 합계가 아니라, 그룹이 활성 상태였던 시간을 표시합니다. [#94966](https://github.com/ClickHouse/ClickHouse/pull/94966) ([Sema Checherinda](https://github.com/CheSema)).
