<div id="clickhouse-release-v24712915-stable-a37d2d43da7-fixme-as-compared-to-v24711-new-aa023477a92">
  ### ClickHouse 릴리스 v24.7.1.2915-stable (a37d2d43da7) FIXME v24.7.1.1-new (aa023477a92)와 비교
</div>

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* Variant 데이터 타입의 이진 직렬화가 변경되었습니다. 단일 variant만 있거나 NULL 값만 있는 그래뉼에서 동일한 판별자를 여러 번 기록하지 않도록 `compact` 모드가 추가되었습니다. 기본적으로 활성화되는 MergeTree 설정 `use_compact_variant_discriminators_serialization`도 추가되었습니다. Variant 타입은 여전히 실험적 상태이므로 직렬화의 하위 호환되지 않는 변경도 허용됩니다. [#62774](https://github.com/ClickHouse/ClickHouse/pull/62774) ([Kruglov Pavel](https://github.com/Avogar)).
* 복제된 데이터베이스에서 `CREATE MATERIALIZED VIEW ... ENGINE Replicated*MergeTree POPULATE AS SELECT ...`를 사용하는 것을 금지합니다. [#63963](https://github.com/ClickHouse/ClickHouse/pull/63963) ([vdimir](https://github.com/vdimir)).
* `clickhouse-keeper-client`는 `ls '/hello/world'`와 같은 문자열 리터럴의 경로만 허용하며, `ls /hello/world`와 같은 따옴표 없는 문자열은 허용하지 않습니다. [#65494](https://github.com/ClickHouse/ClickHouse/pull/65494) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 메트릭 `KeeperOutstandingRequets`의 이름이 `KeeperOutstandingRequests`로 변경되었습니다. 이는 [#66179](https://github.com/ClickHouse/ClickHouse/issues/66179)에서 보고된 오타를 수정한 것입니다. [#66206](https://github.com/ClickHouse/ClickHouse/pull/66206) ([Robert Schulze](https://github.com/rschu1ze)).
* `system.functions` 테이블에서 `is_deterministic` 필드가 제거되었습니다. [#66630](https://github.com/ClickHouse/ClickHouse/pull/66630) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 새 기능
</div>

* 쿼리에서 이름이 지정된 Tuple을 생성할 수 있도록 `tuple` 함수를 확장했습니다. 튜플에서 이름을 추출하는 `tupleNames` 함수도 도입했습니다. [#54881](https://github.com/ClickHouse/ClickHouse/pull/54881) ([Amos Bird](https://github.com/amosbird)).
* `full_sorting_join` 알고리즘에서 `ASOF JOIN`을 지원합니다. [#54493](https://github.com/ClickHouse/ClickHouse/issues/54493)를 해결했습니다. [#55051](https://github.com/ClickHouse/ClickHouse/pull/55051) ([vdimir](https://github.com/vdimir)).
* 새로운 테이블 함수 `fuzzQuery,`가 추가되었습니다. 이 함수는 주어진 쿼리 문자열에 무작위 변형을 적용할 수 있습니다. 예시: `SELECT query FROM fuzzQuery('SELECT 1');`. [#62103](https://github.com/ClickHouse/ClickHouse/pull/62103) ([pufit](https://github.com/pufit)).
* 새로운 윈도 함수 `percent_rank`를 추가했습니다. [#62747](https://github.com/ClickHouse/ClickHouse/pull/62747) ([lgbo](https://github.com/lgbo-ustc)).
* `clickhouse-client`에서 JWT 인증을 지원합니다. [#62829](https://github.com/ClickHouse/ClickHouse/pull/62829) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* SQL 함수 `changeYear`, `changeMonth`, `changeDay`, `changeHour`, `changeMinute`, `changeSecond`를 추가했습니다. 예를 들어 `SELECT changeMonth(toDate('2024-06-14'), 7)`는 날짜 `2024-07-14`를 반환합니다. [#63186](https://github.com/ClickHouse/ClickHouse/pull/63186) ([cucumber95](https://github.com/cucumber95)).
* 시작 단계에서 미리 구성된 쿼리를 실행할 수 있는 startup scripts를 도입했습니다. [#64889](https://github.com/ClickHouse/ClickHouse/pull/64889) ([pufit](https://github.com/pufit)).
* 자체 서명된 certificate로 실행 중인 server에 클라이언트가 보안 TCP를 통해 연결할 수 있도록, 클라이언트 구성에서 accept&#95;invalid&#95;certificate를 지원합니다. 이는 해당 `openSSL` 클라이언트 설정 `verificationMode=none` + `invalidCertificateHandler.name=AcceptCertificateHandler`의 축약형으로 사용할 수 있습니다. [#65238](https://github.com/ClickHouse/ClickHouse/pull/65238) ([peacewalker122](https://github.com/peacewalker122)).
* `system.errors` 테이블의 오류 값 이력을 포함하며 주기적으로 디스크에 기록되는 `system.error_log`를 추가했습니다. [#65381](https://github.com/ClickHouse/ClickHouse/pull/65381) ([Pablo Marcos](https://github.com/pamarcos)).
* 집계 함수 `groupConcat`를 추가했습니다. 이는 `arrayStringConcat( groupArray(column), ',')`와 거의 동일합니다. 문자열 구분자와 처리할 요소 수, 총 2개의 매개변수를 받을 수 있습니다. [#65451](https://github.com/ClickHouse/ClickHouse/pull/65451) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* AzureQueue storage를 추가했습니다. [#65458](https://github.com/ClickHouse/ClickHouse/pull/65458) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Parquet files에 page index를 기록하는 기능을 비활성화하거나 활성화하는 새로운 설정을 추가했습니다. [#65475](https://github.com/ClickHouse/ClickHouse/pull/65475) ([lgbo](https://github.com/lgbo-ustc)).
* 시스템 관리자가 `logger.console_log_level`을 구성할 수 있도록 했습니다. [#65559](https://github.com/ClickHouse/ClickHouse/pull/65559) ([Azat Khuzhin](https://github.com/azat)).
* 테이블 함수 `file`에서 directory 경로 끝에 와일드카드 `*`를 자동으로 추가합니다. [#66019](https://github.com/ClickHouse/ClickHouse/pull/66019) ([Zhidong (David) Guo](https://github.com/Gun9niR)).
* 비대화형 모드에서 클라이언트에 `--memory-usage` 옵션을 추가했습니다. [#66393](https://github.com/ClickHouse/ClickHouse/pull/66393) ([vdimir](https://github.com/vdimir)).

<div id="performance-improvement">
  #### 성능 개선 사항
</div>

* `optimize_functions_to_subcolumns`를 기본적으로 활성화했습니다. [#58661](https://github.com/ClickHouse/ClickHouse/pull/58661) ([Anton Popov](https://github.com/CurtizJ)).
* int를 string으로 변환하는 알고리즘을 더 빠른 방식으로 대체했습니다(수정된 amdn/itoa에서 수정된 jeaiii/itoa로). [#61661](https://github.com/ClickHouse/ClickHouse/pull/61661) ([Raúl Marín](https://github.com/Algunenano)).
* 이제 join(`parallel_hash` 알고리즘)으로 생성된 해시 테이블의 크기를 수집해 캐시합니다. 이 정보는 이후 쿼리 실행 시 해시 테이블 공간을 미리 할당하는 데 사용되어, 해시 테이블 크기 조정에 드는 시간을 줄여 줍니다. [#64553](https://github.com/ClickHouse/ClickHouse/pull/64553) ([Nikita Taranov](https://github.com/nickitat)).
* buffering을 사용해 `ORDER BY` 프라이머리 키와 높은 선택도를 갖는 조건이 포함된 `WHERE`를 사용하는 쿼리를 최적화했습니다. 이는 `read_in_order_use_buffering` 설정으로 제어되며(기본적으로 활성화됨), 쿼리의 메모리 사용량을 늘릴 수 있습니다. [#64607](https://github.com/ClickHouse/ClickHouse/pull/64607) ([Anton Popov](https://github.com/CurtizJ)).
* `plain_rewritable` metadata 로딩 성능을 개선했습니다. [#65634](https://github.com/ClickHouse/ClickHouse/pull/65634) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 읽기 전용 디스크의 테이블을 ATTACH할 때 오래된 파트를 로드하지 않도록 하여 리소스 사용량을 줄였습니다. [#65635](https://github.com/ClickHouse/ClickHouse/pull/65635) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Set 인덱스에 minmax hyperrectangle을 지원합니다. [#65676](https://github.com/ClickHouse/ClickHouse/pull/65676) ([AntiTopQuark](https://github.com/AntiTopQuark)).
* 전체 메모리 사용량을 줄이기 위해 오래된 파트의 프라이머리 인덱스를 언로드합니다. [#65852](https://github.com/ClickHouse/ClickHouse/pull/65852) ([Anton Popov](https://github.com/CurtizJ)).
* `replaceRegexpAll` 및 `replaceRegexpOne` 함수는 이제 pattern이 단순한 경우, 즉 메타문자, pattern 클래스, 플래그, 그룹화 문자 등이 포함되지 않은 경우 훨씬 더 빠르게 동작합니다. (Taiyang Li에게 감사드립니다.) [#66185](https://github.com/ClickHouse/ClickHouse/pull/66185) ([Robert Schulze](https://github.com/rschu1ze)).

<div id="improvement">
  #### 개선 사항
</div>

* Keeper의 백엔드 스토리지로 rocksdb를 지원합니다. [#56626](https://github.com/ClickHouse/ClickHouse/pull/56626) ([Han Fei](https://github.com/hanfei1991)).
* `optimize_trivial_insert_select` 설정은 기본적으로 비활성화되어 있습니다. 대부분의 경우 이 설정은 유용합니다. 다만 INSERT SELECT가 더 느려지거나 메모리 사용량이 증가하는 경우에는 이 설정을 다시 활성화하거나 `SET compatibility = '24.6'`를 설정할 수 있습니다. [#58970](https://github.com/ClickHouse/ClickHouse/pull/58970) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `clickhouse-client` 또는 `clickhouse-local`이 비정상 종료되면 stacktrace와 진단 정보를 출력합니다. [#61109](https://github.com/ClickHouse/ClickHouse/pull/61109) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 이전에는 `SHOW INDEX | INDEXES | INDICES | KEYS`의 결과가 프라이머리 키 컬럼 이름 기준으로 정렬되었습니다. 이 방식이 직관적이지 않았기 때문에, 이제 결과는 프라이머리 키 내 프라이머리 키 컬럼의 위치를 기준으로 정렬됩니다. [#61131](https://github.com/ClickHouse/ClickHouse/pull/61131) ([Robert Schulze](https://github.com/rschu1ze)).
* 이 PR은 MV의 중복 제거 동작 방식을 변경합니다. 다음과 같은 여러 경우를 수정했습니다. - 대상 테이블: 데이터가 2개 이상의 block으로 분할되고, 해당 block이 병렬로 삽입될 때 그 block이 중복으로 간주되던 문제입니다. - MV 대상 테이블: 동일한 block이 중복 제거되던 문제입니다. 이는 MV가 집계를 수행하면서 서로 다른 입력 데이터에 대해서도 동일한 결과 데이터를 자주 생성할 때 발생합니다. - MV 대상 테이블: 서로 다른 MV에서 온 동일한 block이 중복 제거되던 문제입니다. [#61601](https://github.com/ClickHouse/ClickHouse/pull/61601) ([Sema Checherinda](https://github.com/CheSema)).
* JSON file을 읽을 때 컬럼 이름을 대소문자를 구분하지 않고 매칭할 수 있도록 지원합니다(`input_format_json_case_insensitive_column_matching`). [#61750](https://github.com/ClickHouse/ClickHouse/pull/61750) ([kevinyhzou](https://github.com/KevinyhZou)).
* 파티션된 DeltaLake 데이터를 읽을 수 있도록 지원합니다. 데이터 대신 metadata를 읽어 DeltaLake 스키마를 추론합니다. [#63201](https://github.com/ClickHouse/ClickHouse/pull/63201) ([Kseniia Sumarokova](https://github.com/kssenii)).
* composable protocols의 TLS 레이어는 `certificateFile` 및 `privateKeyFile` 매개변수만 허용했습니다. [https://clickhouse.com/docs/en/operations/settings/composable-protocols](https://clickhouse.com/docs/en/operations/settings/composable-protocols). [#63985](https://github.com/ClickHouse/ClickHouse/pull/63985) ([Anton Ivashkin](https://github.com/ianton-ru)).
* clickhouse-disks용 대화형 클라이언트를 만들고, 로컬 디렉터리에서 로컬 디스크를 추가할 수 있도록 했습니다. [#56791](https://github.com/ClickHouse/ClickHouse/issues/56791)을 수정합니다. [#64446](https://github.com/ClickHouse/ClickHouse/pull/64446) ([Daniil Ivanik](https://github.com/divanik)).
* 프라이머리 키를 사용해 WHERE 절을 평가하는 SELECT 쿼리 수를 나타내는 프로파일 이벤트 `SelectQueriesWithPrimaryKeyUsage`를 추가했습니다. [#64492](https://github.com/ClickHouse/ClickHouse/pull/64492) ([0x01f](https://github.com/0xfei)).
* `StorageS3Queue` 관련 수정 및 개선 사항입니다. `s3queue_processing_threads_num`의 기본값을 서버의 물리 CPU cores 수에 따라 결정하도록 변경했습니다(이전 기본값 1 대신). `s3queue_loading_retries`의 기본값을 10으로 설정했습니다. `system.s3queue`의 exception 컬럼에 표시될 수 있는 모호한 &quot;Uncaught exception&quot;을 수정했습니다. `MEMORY_LIMIT_EXCEEDED` 예외에서는 retry 횟수를 증가시키지 않습니다. 파일이 실제로 삽입되지 않았는데도 commit되는 일을 방지하기 위해 파일 commit을 테이블 삽입이 완전히 끝난 이후 단계로 옮겼습니다. commit 및 flush 시간을 더 세밀하게 제어할 수 있도록 `s3queue_max_processed_files_before_commit`, `s3queue_max_processed_rows_before_commit`, `s3queue_max_processed_bytes_before_commit`, `s3queue_max_processing_time_sec_before_commit` 설정을 추가했습니다. [#65046](https://github.com/ClickHouse/ClickHouse/pull/65046) ([Kseniia Sumarokova](https://github.com/kssenii)).
* s390x에서 여러 컬럼 집계가 깨지던 문제를 수정했습니다. [#65062](https://github.com/ClickHouse/ClickHouse/pull/65062) ([Harry Lee](https://github.com/HarryLeeIBM)).
* 매개변수화된 뷰 함수에서 별칭을 지원합니다(새 분석기에서만). [#65190](https://github.com/ClickHouse/ClickHouse/pull/65190) ([Kseniia Sumarokova](https://github.com/kssenii)).
* S3에서 쿼리의 재시도 시간을 줄이고 백업의 재시도 횟수를 늘렸습니다. 쿼리는 8.5분 및 재시도 100회, 백업 복원은 1.2시간 및 재시도 1000회입니다. [#65232](https://github.com/ClickHouse/ClickHouse/pull/65232) ([Sema Checherinda](https://github.com/CheSema)).
* azureBlobStorage에서 로그에 account key가 마스킹되도록 업데이트했습니다. [#65273](https://github.com/ClickHouse/ClickHouse/pull/65273) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 필터 표현식이 `PARTITION BY` 표현식의 일부인 경우 `IN` 프레디케이트에 대한 파티션 프루닝을 지원합니다. [#65335](https://github.com/ClickHouse/ClickHouse/pull/65335) ([Eduard Karacharov](https://github.com/korowa)).
* 모든 분리된 테이블에 대한 주요 정보를 담은 시스템 테이블을 추가했습니다. [#65400](https://github.com/ClickHouse/ClickHouse/pull/65400) ([Konstantin Morozov](https://github.com/k-morozov)).
* 사용자 지정 키 병렬 레플리카를 사용할 때 `cluster_for_parallel_replicas`를 지원합니다. 이를 통해 MergeTree 테이블에서 사용자 지정 키와 함께 병렬 레플리카를 사용할 수 있습니다. [#65453](https://github.com/ClickHouse/ClickHouse/pull/65453) ([Antonio Andelic](https://github.com/antonio2368)).
* 쿼리 계획 LIMIT 최적화를 지원합니다. PostgreSQL 스토리지 및 테이블 함수에 대한 LIMIT pushdown도 지원합니다. [#65454](https://github.com/ClickHouse/ClickHouse/pull/65454) ([Maksim Kita](https://github.com/kitaisreal)).
* Arraymin/max를 비교 가능한 모든 데이터 타입에 적용할 수 있습니다. [#65455](https://github.com/ClickHouse/ClickHouse/pull/65455) ([pn](https://github.com/chloro-pn)).
* cgroups v2의 메모리 사용량 계산을 개선해 페이지 캐시가 차지하는 양을 제외하도록 했습니다. [#65470](https://github.com/ClickHouse/ClickHouse/pull/65470) ([Nikita Taranov](https://github.com/nickitat)).
* 청크를 직렬화해 EmbeddedRocksDB 테이블에 삽입할 때 각 행마다 포맷 설정을 생성하지 않도록 했습니다. [#65474](https://github.com/ClickHouse/ClickHouse/pull/65474) ([Duc Canh Le](https://github.com/canhld94)).
* s390x에서 Dwarf5를 파싱할 때 발생하던 범위 초과 예외를 수정했습니다. [#65501](https://github.com/ClickHouse/ClickHouse/pull/65501) ([Harry Lee](https://github.com/HarryLeeIBM)).
