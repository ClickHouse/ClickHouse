<div id="2023-changelog">
  # 2023 변경 로그
</div>

<div id="clickhouse-release-v23611524-stable-d1c7e13d088-fixme-as-compared-to-v23513174-stable-2fec796e73e">
  ### ClickHouse 릴리스 v23.6.1.1524-stable (d1c7e13d088) FIXME, v23.5.1.3174-stable (2fec796e73e) 대비
</div>

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* fs cache에서 `do_not_evict_index_and_mark_files` 기능을 삭제했습니다. 이 기능은 오히려 상황을 악화시키기만 했습니다. [#51253](https://github.com/ClickHouse/ClickHouse/pull/51253) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 실험적 LIVE VIEW에 대한 ALTER 지원을 제거했습니다. [#51287](https://github.com/ClickHouse/ClickHouse/pull/51287) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 새 기능
</div>

* `session_timezone` 설정을 추가했습니다. 명시적으로 지정하지 않은 경우 세션의 기본 시간대로 사용됩니다. [#44149](https://github.com/ClickHouse/ClickHouse/pull/44149) ([Andrey Zvonov](https://github.com/zvonand)).
* overlay 데이터베이스 엔진과 디렉터리를 데이터베이스로 표현하는 기능을 추가했습니다. 이 커밋으로 4개의 데이터베이스가 추가됩니다. 1. DatabaseOverlay: IDatabase 인터페이스를 구현합니다. FileSystem 및 Memory와 같은 여러 데이터베이스를 결합할 수 있습니다. 내부적으로는 다른 데이터베이스 포인터의 벡터를 저장하고, 성공할 때까지 요청을 차례로 프록시합니다. 2. DatabaseFilesystem: 파일 시스템에 저장된 파일과 읽기 전용으로 상호작용할 수 있습니다. 내부적으로는 사용자가 테이블을 요청할 때 파일을 암묵적으로 로드하기 위해 TableFunctionFile을 사용합니다. 빠른 접근을 위해 TableFunctionFile 호출 결과를 내부에 캐시합니다. 3. DatabaseS3: S3 storage와 읽기 전용으로 상호작용할 수 있습니다. S3에서 테이블을 암묵적으로 로드하기 위해 TableFunctionS3를 사용합니다. 4. DatabaseHDFS: HDFS storage와 상호작용할 수 있습니다. HDFS에서 테이블을 암묵적으로 로드하기 위해 TableFunctionHDFS를 사용합니다. [#48821](https://github.com/ClickHouse/ClickHouse/pull/48821) ([alekseygolub](https://github.com/alekseygolub)).
* `use_mysql_types_in_show_columns`라는 새로운 설정을 추가하여, 클라이언트가 MySQL 호환 포트를 통해 연결된 경우 `SHOW COLUMNS` SQL statement가 MySQL 대응 타입을 표시하도록 했습니다. [#49577](https://github.com/ClickHouse/ClickHouse/pull/49577) ([Thomas Panetti](https://github.com/tpanetti)).
* `--rename_files_after_processing <pattern>` 옵션을 추가했습니다. 이로써 [#34207](https://github.com/ClickHouse/ClickHouse/issues/34207)이 해결되었습니다. [#49626](https://github.com/ClickHouse/ClickHouse/pull/49626) ([alekseygolub](https://github.com/alekseygolub)).
* 1. `TableFunctionRedis`를 추가했습니다. 3. Redis 테이블 엔진을 추가했습니다. 4. Redis 관련 도구와 타입을 포함하는 `RedisCommon`을 추가했습니다. 5. Redis에 `equals` 및 `in` 필터 푸시다운을 지원합니다. [#50150](https://github.com/ClickHouse/ClickHouse/pull/50150) ([JackyWoo](https://github.com/JackyWoo)).
* `s3_skip_empty_files`, `hdfs_skip_empty_files`, `engine_file_skip_empty_files`, `engine_url_skip_empty_files` 설정을 사용해 file/s3/url/hdfs 테이블 함수에서 빈 파일을 건너뛸 수 있도록 했습니다. [#50364](https://github.com/ClickHouse/ClickHouse/pull/50364) ([Kruglov Pavel](https://github.com/Avogar)).
* 이제 `clickhouse-client`를 &quot;--host&quot;, &quot;--port&quot;, &quot;--user&quot; 등의 인자 대신 connection으로 호출할 수 있습니다. [#50689](https://github.com/ClickHouse/ClickHouse/pull/50689) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* 이제 코덱 DEFLATE&#95;QPL은 setting &quot;allow&#95;experimental&#95;codecs&quot; 대신 server setting &quot;enable&#95;deflate&#95;qpl&#95;codec&quot;(기본값: false)로 제어됩니다. 이에 따라 QPL&#95;DEFLATE는 더 이상 experimental이 아닙니다. [#50775](https://github.com/ClickHouse/ClickHouse/pull/50775) ([Robert Schulze](https://github.com/rschu1ze)).



<div id="performance-improvement">
  #### 성능 개선
</div>

* 전역 객체 대신 스레드 로컬 `timer_id`를 사용하여 활성화된 QueryProfiler의 성능을 개선했습니다. [#48778](https://github.com/ClickHouse/ClickHouse/pull/48778) ([Jiebin Sun](https://github.com/jiebinn)).
* 성능 향상을 위해 CapnProto 입력/출력 포맷을 재작성했습니다. Map 컬럼 이름과 CapnProto 필드를 대소문자를 구분하지 않고 매핑하도록 했으며, 중첩 구조 필드의 읽기/쓰기를 수정했습니다. [#49752](https://github.com/ClickHouse/ClickHouse/pull/49752) ([Kruglov Pavel](https://github.com/Avogar)).
* 병렬 스레드에서의 Parquet 쓰기 성능을 최적화했습니다. [#50102](https://github.com/ClickHouse/ClickHouse/pull/50102) ([Hongbin Ma](https://github.com/binmahone)).
* ### 사용자 대상 변경 사항에 대한 문서 항목 블록이 하나뿐인 MATERIALIZED VIEW와 스토리지 처리 시 `parallelize_output_from_storages`를 비활성화했습니다. [#50214](https://github.com/ClickHouse/ClickHouse/pull/50214) ([Azat Khuzhin](https://github.com/azat)).
* PR https://github.com/ClickHouse/ClickHouse/pull/46558 을 머지했습니다(이미 정렬된 데이터 처리 방지). 블록이 이미 정렬된 경우 sort 중 블록 순열을 방지합니다. [#50697](https://github.com/ClickHouse/ClickHouse/pull/50697) ([Maksim Kita](https://github.com/kitaisreal)).
* 이전 PR([#50062](https://github.com/ClickHouse/ClickHouse/issues/50062), [#50307](https://github.com/ClickHouse/ClickHouse/issues/50307))에서는 toYear/toYYYYMM이 포함된 프레디케이트를 동등하면서도 컨버터가 없는 형태로 변환하는 최적화 패턴을 제안했습니다. 이 변환은 SSB와 같은 일부 workload에서 상당한 성능 향상을 가져올 수 있었습니다. 그러나 issue [#50628](https://github.com/ClickHouse/ClickHouse/issues/50628)에서 확인된 것처럼, 이 두 PR은 불완전한 쿼리 결과를 초래할 수 있는 문제를 도입했으며, 그 결과 [#50629](https://github.com/ClickHouse/ClickHouse/issues/50629)에서 되돌렸습니다. [#50951](https://github.com/ClickHouse/ClickHouse/pull/50951) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* system.zookeeper 테이블의 읽기 속도를 높이기 위해 ZooKeeper에 여러 list request를 병렬로 수행합니다. [#51042](https://github.com/ClickHouse/ClickHouse/pull/51042) ([Alexander Gololobov](https://github.com/davenger)).
* 시간대용 DateTime lookup table 초기화를 가속화했습니다. 이 변경으로 특히 부담이 큰 debug 빌드에서 clickhouse client의 시작/연결 시간이 줄어들 것입니다. [#51347](https://github.com/ClickHouse/ClickHouse/pull/51347) ([Alexander Gololobov](https://github.com/davenger)).



<div id="improvement">
  #### 개선 사항
</div>

* CIDR ::ffff:0:0/96(IPv4 매핑 주소)에 대해 IPv6를 IPv4 주소로 변환할 수 있도록 지원합니다. [#49759](https://github.com/ClickHouse/ClickHouse/pull/49759) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* MongoDB 5.1 이상 버전을 지원하도록 MongoDB 프로토콜을 업데이트합니다. 구 프로토콜(<3.6) 버전에 대한 지원은 유지됩니다. [#45621](https://github.com/ClickHouse/ClickHouse/issues/45621), [#49879](https://github.com/ClickHouse/ClickHouse/issues/49879) 해결. [#50061](https://github.com/ClickHouse/ClickHouse/pull/50061) ([Nikolay Degterinsky](https://github.com/evillique)).
* `ReplicatedMergeTree`에서 머지 선택 및 정리 작업의 스케줄링을 개선합니다. 머지하거나 정리할 항목이 없을 때 작업이 과도하게 자주 실행되지 않습니다. `max_merge_selecting_sleep_ms`, `merge_selecting_sleep_slowdown_factor`, `max_cleanup_delay_period`, `cleanup_thread_preferred_points_per_iteration` 설정이 추가되었습니다. [#31919](https://github.com/ClickHouse/ClickHouse/issues/31919) 해결 예정. [#50107](https://github.com/ClickHouse/ClickHouse/pull/50107) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 분석기에서 병렬 레플리카를 지원합니다. [#50441](https://github.com/ClickHouse/ClickHouse/pull/50441) ([Raúl Marín](https://github.com/Algunenano)).
* 스키마 추론 시 읽을 바이트 수를 제한하는 `input_format_max_bytes_to_read_for_schema_inference` 설정을 추가합니다. [#50577](https://github.com/ClickHouse/ClickHouse/issues/50577) 해결. [#50592](https://github.com/ClickHouse/ClickHouse/pull/50592) ([Kruglov Pavel](https://github.com/Avogar)).
* 스키마 추론 시 `input_format_as_default` 설정을 준수합니다. [#50602](https://github.com/ClickHouse/ClickHouse/pull/50602) ([Kruglov Pavel](https://github.com/Avogar)).
* 크로스 조인을 통한 필터 푸시다운을 지원합니다. [#50605](https://github.com/ClickHouse/ClickHouse/pull/50605) ([Han Fei](https://github.com/hanfei1991)).
* 이제 실제 lz4 버전이 사용됩니다. [#50621](https://github.com/ClickHouse/ClickHouse/pull/50621) ([Nikita Taranov](https://github.com/nickitat)).
* `input_format_csv_skip_trailing_empty_lines`, `input_format_tsv_skip_trailing_empty_lines`, `input_format_custom_skip_trailing_empty_lines` 설정을 통해 CSV/TSV/CustomSeparated 포맷에서 후행 빈 줄을 건너뛸 수 있습니다(기본값: 비활성화). [#49315](https://github.com/ClickHouse/ClickHouse/issues/49315) 해결. [#50635](https://github.com/ClickHouse/ClickHouse/pull/50635) ([Kruglov Pavel](https://github.com/Avogar)).
* `toDateOrDefault|OrNull()` 및 `accurateCast[OrDefault|OrNull]()` 함수가 이제 숫자 인수를 올바르게 파싱합니다. [#50709](https://github.com/ClickHouse/ClickHouse/pull/50709) ([Dmitry Kardymon](https://github.com/kardymonds)).
* 기존에는 CSV 입력 포맷이 공백 또는 `\t`를 필드 구분자로 사용하는 CSV 파일을 파싱할 수 없었으나, 이러한 구분자는 Spark에서 지원됩니다. [#50712](https://github.com/ClickHouse/ClickHouse/pull/50712) ([KevinyhZou](https://github.com/KevinyhZou)).
* `number_of_mutations_to_delay` 및 `number_of_mutations_to_throw` 설정이 이제 기본적으로 활성화되며, 기본값은 각각 500과 1000입니다. [#50726](https://github.com/ClickHouse/ClickHouse/pull/50726) ([Anton Popov](https://github.com/CurtizJ)).
* Keeper 개선 사항: Keeper API에 기능 플래그를 추가합니다. 각 기능 플래그는 `keeper_server.feature_flags` 설정 하위에 정의하여 활성화하거나 비활성화할 수 있습니다. 예를 들어 `CheckNotExists` 요청을 활성화하려면 Keeper에서 `keeper_server.feature_flags.check_not_exists`를 `1`로 설정해야 합니다. [#50796](https://github.com/ClickHouse/ClickHouse/pull/50796) ([Antonio Andelic](https://github.com/antonio2368)).
* 대시보드에서 누락된 값이 올바르게 표시됩니다. [#50831](https://github.com/ClickHouse/ClickHouse/issues/50831) 해결. [#50832](https://github.com/ClickHouse/ClickHouse/pull/50832) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* CPU 관련 CGroups 메트릭이 사용 편의성 향상을 위해 `CGroupMaxCPU` 단일 메트릭으로 통합됩니다. CGroups 제한이 설정된 경우 `Normalized` CPU 사용량 메트릭은 전체 CPU 수 대신 CGroups 제한을 기준으로 정규화됩니다. [#50836](https://github.com/ClickHouse/ClickHouse/issues/50836) 해결. [#50835](https://github.com/ClickHouse/ClickHouse/pull/50835) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* "파트 수 초과" 임계값을 현대적인 기준에 맞게 완화합니다. 장시간 실행되는 INSERT 쿼리 중 역압(backpressure)을 반환합니다. [#50856](https://github.com/ClickHouse/ClickHouse/pull/50856) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `parseDateTimeBestEffort*()` 및 `parseDateTime64BestEffort*()` 함수에서 syslog 타임스탬프 포맷의 날짜 및 시간 인수를 사용할 수 있는 기능이 추가되었습니다. [#50925](https://github.com/ClickHouse/ClickHouse/pull/50925) ([Victor Krasnov](https://github.com/sirvickr)).
* 파일이 이미 존재하는 경우 `INTO OUTFILE`에 `APPEND` 또는 `TRUNCATE` 사용을 제안합니다. [#50950](https://github.com/ClickHouse/ClickHouse/pull/50950) ([alekar](https://github.com/alekar)).
* 독립 실행형 Keeper 바이너리에 내장 keeper-client를 추가합니다. [#50964](https://github.com/ClickHouse/ClickHouse/pull/50964) ([pufit](https://github.com/pufit)).
* clickhouse-client의 명령줄 매개변수 `--password`는 이제 한 번만 지정할 수 있습니다. [#50966](https://github.com/ClickHouse/ClickHouse/pull/50966) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* 동기식 HEAD 요청으로 인한 데이터 레이크 성능 저하를 수정합니다. (파일 수가 많을 때 Iceberg/Deltalake/Hudi가 느려지는 문제와 관련). [#50976](https://github.com/ClickHouse/ClickHouse/pull/50976) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 클러스터 내 백업 중 파트 동일성 확인을 위해 `system.parts`의 `hash_of_all_files`를 사용합니다. [#50997](https://github.com/ClickHouse/ClickHouse/pull/50997) ([Vitaly Baranov](https://github.com/vitlibar)).
* 시스템 테이블 `zookeeper_connection`의 `connected_time` 필드는 연결이 수립된 시각(표준 포맷)을 나타내며, 수립된 연결 세션의 지속 시간(초 단위)을 나타내는 `session_uptime_elapsed_seconds`가 추가되었습니다. [#51026](https://github.com/ClickHouse/ClickHouse/pull/51026) ([郭小龙](https://github.com/guoxiaolongzte)).
* `system.parts`, `system.projection_parts` 및 오류 메시지에서 체크섬의 두 절반을 올바른 순서로 표시합니다. [#51040](https://github.com/ClickHouse/ClickHouse/pull/51040) ([Vitaly Baranov](https://github.com/vitlibar)).
* `Replicated` 데이터베이스에 샤드가 하나뿐이고 기반 테이블이 `ReplicatedMergeTree`인 경우, `ALTER PARTITION` 쿼리 및 뮤테이션을 해당 데이터베이스를 통해 복제하지 않습니다. [#51049](https://github.com/ClickHouse/ClickHouse/pull/51049) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 소스 데이터의 청크 크기를 활용하고 각 스레드에서 전체 크기를 증분 방식으로 집계하여 file/s3/hdfs/url 테이블 함수의 진행률 표시줄을 개선합니다. `*Cluster` 함수의 진행률 표시줄을 수정합니다. [#47250](https://github.com/ClickHouse/ClickHouse/issues/47250) 해결. [#51088](https://github.com/ClickHouse/ClickHouse/pull/51088) ([Kruglov Pavel](https://github.com/Avogar)).
* 진행률 표시줄 개선을 위해 TCP 프로토콜의 Progress 패킷에 `total_bytes_to_read`를 추가합니다. [#51158](https://github.com/ClickHouse/ClickHouse/pull/51158) ([Kruglov Pavel](https://github.com/Avogar)).
* 파일시스템 캐시가 있는 디스크에서 데이터 파트 검사를 개선합니다. [#51164](https://github.com/ClickHouse/ClickHouse/pull/51164) ([Anton Popov](https://github.com/CurtizJ)).
* 캐시 설정 `do_not_evict_index_and_mark_files`를 비활성화합니다(`23.5`에서 활성화된 설정). [#51222](https://github.com/ClickHouse/ClickHouse/pull/51222) ([Kseniia Sumarokova](https://github.com/kssenii)).
* fs 캐시에서 `current_elements_num`이 간헐적으로 올바르지 않은 값을 반환하는 문제를 수정합니다. [#51242](https://github.com/ClickHouse/ClickHouse/pull/51242) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 제로 카피 복제(zero-copy replication) 환경에서 레플리카 간 부하를 보다 균등하게 분산하기 위해, 머지/뮤테이션 실행 전에 무작위 대기 시간을 추가합니다. [#51282](https://github.com/ClickHouse/ClickHouse/pull/51282) ([alesapin](https://github.com/alesapin)).
* `transform` 함수 및 값 매칭을 사용하는 `CASE` 구문이 모든 데이터 타입을 지원합니다. 관련 이슈: [#29730](https://github.com/ClickHouse/ClickHouse/issues/29730), [#32387](https://github.com/ClickHouse/ClickHouse/issues/32387), [#50827](https://github.com/ClickHouse/ClickHouse/issues/50827), [#31336](https://github.com/ClickHouse/ClickHouse/issues/31336), [#40493](https://github.com/ClickHouse/ClickHouse/issues/40493).
