<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 함수 &quot;toDayOfWeek()&quot;(별칭: &quot;DAYOFWEEK&quot;)를 확장해, 주의 시작 요일이 월요일인지 일요일인지와 계산을 0부터 시작할지 1부터 시작할지를 인코딩하는 mode 인수를 추가했습니다. 다른 date time 함수와의 일관성을 위해 mode 인수는 time 인수와 time zone 인수 사이에 삽입되었습니다. 이로 인해 기존의(이전에는 문서화되지 않았던) 2개 인수 구문 &quot;toDayOfWeek(time, time&#95;zone)&quot; 사용이 호환되지 않게 됩니다. 해결 방법은 함수를 &quot;toDayOfWeek(time, 0, time&#95;zone)&quot;로 재작성하는 것입니다. [#45233](https://github.com/ClickHouse/ClickHouse/pull/45233) ([Robert Schulze](https://github.com/rschu1ze)).
* 설정 `max_query_cache_size`를 `filesystem_cache_max_download_size`로 이름 변경했습니다. [#45614](https://github.com/ClickHouse/ClickHouse/pull/45614) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 클라이언트에서 FORMAT에 설정이 적용되도록 수정했습니다. [#46003](https://github.com/ClickHouse/ClickHouse/pull/46003) ([Azat Khuzhin](https://github.com/azat)).
* `default` 사용자는 기본적으로 접근 유형 `SHOW NAMED COLLECTION`에 대한 권한을 가지지 않습니다(예를 들어, 이제 `default` 사용자는 이전처럼 다른 사용자에게 grant ALL을 수행할 수 없으므로 이 PR은 하위 호환되지 않습니다). [#46010](https://github.com/ClickHouse/ClickHouse/pull/46010) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 설정 `materialized_postgresql_allow_automatic_update` 지원을 제거했습니다(기본적으로 비활성화되어 있었습니다). 통합 테스트도 수정했습니다. [#46106](https://github.com/ClickHouse/ClickHouse/pull/46106) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 실제 데이터셋에서 `countDigits`의 성능을 약간 개선했습니다. 이로써 [#44518](https://github.com/ClickHouse/ClickHouse/issues/44518)이 해결되었습니다. 이전 버전에서는 `countDigits(0)`이 `0`을 반환했지만, 이제는 더 올바르고 기존 문서와도 일치하는 `1`을 반환합니다. [#46187](https://github.com/ClickHouse/ClickHouse/pull/46187) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* AVX-512 명령어를 사용해 lower/upper 함수의 성능을 개선했습니다. [#37894](https://github.com/ClickHouse/ClickHouse/pull/37894) ([yaqi-zhao](https://github.com/yaqi-zhao)).
* 비동기 Linux [io&#95;uring](https://kernel.dk/io_uring.pdf) 서브시스템 기반의 새로운 `local_filesystem_read_method` 메서드 `io_uring`을 추가했습니다. 이 메서드는 기본 `pread` 메서드와 비교해 거의 모든 경우에 읽기 성능을 향상시킵니다. [#38456](https://github.com/ClickHouse/ClickHouse/pull/38456) ([Saulius Valatka](https://github.com/sauliusvl)).
* 코어가 32개 이상이고 SMT가 비활성화된 시스템에서 ClickHouse가 코어의 절반만 사용하던 제한을 제거했습니다. [#44973](https://github.com/ClickHouse/ClickHouse/pull/44973) ([Robert Schulze](https://github.com/rschu1ze)).
* multiIf 함수를 열 지향 방식으로 실행하도록 개선해 성능을 2.3배 높였습니다. [#45296](https://github.com/ClickHouse/ClickHouse/pull/45296) ([李扬](https://github.com/taiyang-li)).
* 테이블 파티션 키와 GROUP BY 키가 호환되는 경우 파티션별로 독립적으로 집계할 수 있는 옵션을 추가했습니다. 이 기능은 `allow_aggregate_partitions_independently` 설정으로 제어합니다. 적용 범위가 제한적이므로 기본적으로 비활성화되어 있습니다(문서를 참조하십시오). [#45364](https://github.com/ClickHouse/ClickHouse/pull/45364) ([Nikita Taranov](https://github.com/nickitat)).
* needle이 비어 있을 때 position 함수에 fast path를 추가했습니다. [#45382](https://github.com/ClickHouse/ClickHouse/pull/45382) ([李扬](https://github.com/taiyang-li)).
* `query_plan_remove_redundant_sorting` 최적화를 기본적으로 활성화했습니다. 이 최적화는 [#45420](https://github.com/ClickHouse/ClickHouse/issues/45420)에서 구현되었습니다. [#45567](https://github.com/ClickHouse/ClickHouse/pull/45567) ([Igor Nikonov](https://github.com/devcrafter)).
* HTTP 인터페이스를 사용하는 대규모 쿼리의 성능을 개선하기 위해 HTTP Transfer Encoding 청크 크기를 늘렸습니다. [#45593](https://github.com/ClickHouse/ClickHouse/pull/45593) ([Geoff Genz](https://github.com/genzgd)).
* `Array`/`Map`/`Nested` 컬럼이 많은 테이블을 읽는 짧은 `SELECT` 쿼리의 성능을 개선했습니다. [#45630](https://github.com/ClickHouse/ClickHouse/pull/45630) ([Anton Popov](https://github.com/CurtizJ)).
* Compact 포맷의 파트에도 수직 병합 알고리즘(Vertical merge algorithm)을 사용할 수 있도록 했습니다. 이를 통해 ClickHouse 서버가 백그라운드 작업에서 훨씬 적은 메모리를 사용할 수 있습니다. 이 변경으로 [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084)가 해결되었습니다. [#45681](https://github.com/ClickHouse/ClickHouse/pull/45681) ([Anton Popov](https://github.com/CurtizJ)).
* 배치 리더를 사용하도록 Parquet 리더를 최적화했습니다. [#45878](https://github.com/ClickHouse/ClickHouse/pull/45878) ([LiuNeng](https://github.com/liuneng1994)).
* 큰 정수 및 Decimal에 대한 ColumnArray::filter의 성능을 개선했습니다. [#45949](https://github.com/ClickHouse/ClickHouse/pull/45949) ([李扬](https://github.com/taiyang-li)).
* 이 변경으로 ColumnNullable(UInt8)에서 filter를 추출하는 오버헤드를 효과적으로 줄이고 전체 쿼리 성능을 개선할 수 있습니다. 이 변경의 영향을 평가하기 위해 TPC-H 벤치마크를 사용하되, 컬럼 타입을 non-nullable에서 nullable로 바꾸고 쿼리의 QPS를 성능 지표로 측정했습니다. [#45962](https://github.com/ClickHouse/ClickHouse/pull/45962) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* `_part` 및 `_partition_id` 가상 컬럼의 타입을 `LowCardinality(String)`으로 변경했습니다. 이 변경으로 [#45964](https://github.com/ClickHouse/ClickHouse/issues/45964)가 해결되었습니다. [#45975](https://github.com/ClickHouse/ClickHouse/pull/45975) ([flynn](https://github.com/ucasfl)).
* scale이 변경되지 않을 때 Decimal 변환 성능을 개선했습니다. [#46095](https://github.com/ClickHouse/ClickHouse/pull/46095) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 새로 도입된 이 로직은 PREWHERE 조건이 여러 조건의 conjunction(cond1 AND cond2 AND ... )으로 이루어진 경우에 동작합니다. 동일한 컬럼을 읽어야 하는 조건들을 단계별로 그룹화합니다. 각 단계가 끝날 때마다 전체 조건 중 해당 부분을 계산하고, 그 결과에 따라 행을 필터링할 수 있습니다. 이렇게 하면 다음 단계에서 더 적은 행을 읽게 되어 IO 대역폭을 절약하고 컴퓨트도 줄일 수 있습니다. 현재는 이 로직이 기본적으로 비활성화되어 있습니다. 회귀가 없다는 점이 확인되면 향후 릴리스 중 하나에서 기본적으로 활성화될 예정이므로, 테스트 목적으로 적극적으로 사용해 보시기를 권장합니다. 이 기능은 2개의 설정, 즉 &quot;enable&#95;multiple&#95;prewhere&#95;read&#95;steps&quot; 및 &quot;move&#95;all&#95;conditions&#95;to&#95;prewhere&quot;로 제어할 수 있습니다. [#46140](https://github.com/ClickHouse/ClickHouse/pull/46140) ([Alexander Gololobov](https://github.com/davenger)).
* read data에 대한 프리페치를 늘릴 수 있도록 했습니다. [#46168](https://github.com/ClickHouse/ClickHouse/pull/46168) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `arrayExists(x -> x = 1, arr) -> has(arr, 1)`로 재작성하여 성능을 1.34배 개선했습니다. [#46188](https://github.com/ClickHouse/ClickHouse/pull/46188) ([李扬](https://github.com/taiyang-li)).
* 비원격 디스크에서 수직 병합의 메모리 사용량이 지나치게 커지는 문제를 수정했습니다. 원격 디스크에 대해서는 `max_insert_delayed_streams_for_parallel_write`를 준수하도록 했습니다. [#46275](https://github.com/ClickHouse/ClickHouse/pull/46275) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* zstd를 v1.5.4로 업데이트했습니다. 이 버전에는 성능과 압축률 측면에서 몇 가지 소규모 개선이 포함되어 있습니다. 서로 다른 버전의 ClickHouse로 레플리카를 실행하는 경우, 설명이 포함된 `Data after merge/mutation is not byte-identical to data on another replicas.`와 같은 적절한 오류 메시지가 표시될 수 있습니다. 이러한 메시지는 정상적인 것이므로 걱정하지 않으셔도 됩니다. [#46280](https://github.com/ClickHouse/ClickHouse/pull/46280) ([Raúl Marín](https://github.com/Algunenano)).
* Compact 포맷의 파트에서도 수직 병합 알고리즘을 사용할 수 있도록 했습니다. 이를 통해 ClickHouse 서버가 백그라운드 작업에서 훨씬 적은 메모리를 사용할 수 있습니다. 이 변경으로 [#46084](https://github.com/ClickHouse/ClickHouse/issues/46084)가 해결되었습니다. [#46282](https://github.com/ClickHouse/ClickHouse/pull/46282) ([Anton Popov](https://github.com/CurtizJ)).
* [#39737](https://github.com/ClickHouse/ClickHouse/issues/39737)로 인해 발생한 성능 저하를 수정했습니다. [#46309](https://github.com/ClickHouse/ClickHouse/pull/46309) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 복제 큐가 큰 경우에도 `replicas_status` handle이 빠르게 응답합니다. [#46310](https://github.com/ClickHouse/ClickHouse/pull/46310) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
