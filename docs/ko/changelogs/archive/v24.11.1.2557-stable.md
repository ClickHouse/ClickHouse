  ### ClickHouse 릴리스 v24.11.1.2557-안정 (1574e794bf9) v24.11.1.1-new (c82cf25b3e5) 대비 FIXME

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 시스템 테이블 `generate_series` 및 `generateSeries`를 제거합니다. 이 테이블들은 여기에서 실수로 추가되었습니다: [#59390](https://github.com/ClickHouse/ClickHouse/issues/59390). [#71091](https://github.com/ClickHouse/ClickHouse/pull/71091) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `StorageExternalDistributed`를 제거합니다. [#70600](https://github.com/ClickHouse/ClickHouse/issues/70600)을 해결합니다. ### 사용자 대상 변경 사항에 대한 문서 항목. [#71176](https://github.com/ClickHouse/ClickHouse/pull/71176) ([flynn](https://github.com/ucasfl)).
* JSON 서브컬럼용 파일에서 이스케이프되지 않은 특수 문자로 인해 발생할 수 있는 `No such file or directory` 오류를 수정합니다. [#71182](https://github.com/ClickHouse/ClickHouse/pull/71182) ([Pavel Kruglov](https://github.com/Avogar)).
* 이제 Kafka, NATS, RabbitMQ 테이블 엔진은 `SOURCES` 계층에서 각각 별도의 권한 부여로 관리됩니다. 이러한 엔진 유형으로 테이블을 생성하는 `default` 이외의 데이터베이스 사용자에게 권한 부여를 추가하십시오. [#71250](https://github.com/ClickHouse/ClickHouse/pull/71250) ([Christoph Wurm](https://github.com/cwurm)).
* 실행 전에 전체 뮤테이션 쿼리(서브쿼리 포함)를 검사합니다. 이렇게 하면 실수로 잘못된 쿼리를 실행하고, 유효한 뮤테이션을 막는 쓸모없는 뮤테이션이 쌓이는 일을 방지할 수 있습니다. [#71300](https://github.com/ClickHouse/ClickHouse/pull/71300) ([Christoph Wurm](https://github.com/cwurm)).
* 파일 시스템 캐시 설정 `skip_download_if_exceeds_query_cache`의 이름을 `filesystem_cache_skip_download_if_exceeds_per_query_cache_write_limit`로 변경합니다. [#71578](https://github.com/ClickHouse/ClickHouse/pull/71578) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `deltaSumTimestamp`에서 `Enum`, `UInt128`, `UInt256` 인수에 대한 지원을 제거합니다. `deltaSumTimestamp`의 두 번째(&quot;timestamp&quot;) 인수에서 `Int8`, `UInt8`, `Int16`, `UInt16`에 대한 지원도 제거합니다. [#71790](https://github.com/ClickHouse/ClickHouse/pull/71790) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 새 기능
</div>

* 새로운 데이터 타입 `BFloat16`이 추가되었습니다. `BFloat16`은 8비트 exponent, 부호, 7비트 가수를 사용하는 16비트 부동소수점 수를 나타냅니다. 이 변경으로 [#44206](https://github.com/ClickHouse/ClickHouse/issues/44206)과 [#49937](https://github.com/ClickHouse/ClickHouse/issues/49937)가 해결되었습니다. [#64712](https://github.com/ClickHouse/ClickHouse/pull/64712) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ~~쿼리 계획에서 내부 테이블 역할을 할 join의 한쪽을 선택하는 옵션이 추가되었습니다. 이는 `query_plan_join_inner_table_selection`으로 제어되며, `auto`로 설정할 수 있습니다. 이 모드에서 ClickHouse는 행 수가 가장 적은 테이블을 선택하려고 시도합니다.~~ [https://github.com/ClickHouse/ClickHouse/pull/71577](https://github.com/ClickHouse/ClickHouse/pull/71577)로 다시 제출되었습니다. [#68682](https://github.com/ClickHouse/ClickHouse/pull/68682) ([Vladimir Cherkasov](https://github.com/vdimir)).
* 현재 사용자/역할에 특정 privilege가 부여되었는지, 그리고 해당 테이블/컬럼이 메모리에 존재하는지 확인하는 `CHECK GRANT` 쿼리가 추가되었습니다. [#68885](https://github.com/ClickHouse/ClickHouse/pull/68885) ([Unalian](https://github.com/Unalian)).
* workload 및 resource 관리를 설명하는 SQL 구문이 추가되었습니다. [https://clickhouse.com/docs/en/operations/workload-scheduling](https://clickhouse.com/docs/en/operations/workload-scheduling). [#69187](https://github.com/ClickHouse/ClickHouse/pull/69187) ([Sergei Trifonov](https://github.com/serxa)).
* system 데이터베이스가 완전히 로드되지 않은 상태에서도 server를 시작할 수 있게 해주는 server setting `async_load_system_database`가 추가되었습니다. system table이 많은 경우 ClickHouse를 더 빠르게 시작하는 데 도움이 됩니다. [#69847](https://github.com/ClickHouse/ClickHouse/pull/69847) ([Sergei Trifonov](https://github.com/serxa)).
* 각 인증 메서드마다 자체 만료일을 설정할 수 있도록 하고, 이를 user 엔터티에서 제거했습니다. [#70090](https://github.com/ClickHouse/ClickHouse/pull/70090) ([Arthur Passos](https://github.com/arthurpassos)).
* 쿼리 실행 시작 노드에서 cluster의 다른 노드로 외부 사용자 역할을 전달합니다. 외부 authenticator(예: LDAP)에 시작 노드만 접근할 수 있는 경우에 유용합니다. [#70332](https://github.com/ClickHouse/ClickHouse/pull/70332) ([Andrey Zvonov](https://github.com/zvonand)).
* String에서 JSON으로의 alter를 지원합니다. 이 PR은 또한 JSON 및 Dynamic 타입의 serialization을 새 버전 V2로 변경합니다. 기존 버전 V1도 설정 `merge_tree_use_v1_object_and_dynamic_serialization`을 활성화하면 계속 사용할 수 있습니다(업그레이드 중 문제 없이 버전을 rollback할 수 있도록 하기 위해 사용할 수 있음). [#70442](https://github.com/ClickHouse/ClickHouse/pull/70442) ([Pavel Kruglov](https://github.com/Avogar)).
* 사용자 인증을 위한 S3 endpoints의 새로운 header 타입(`access_header`)이 추가되었습니다. 이를 통해 가장 낮은 우선순위의 access header를 가져올 수 있으며, 이 값은 다른 source(예: table schema 또는 명명된 컬렉션)의 `access_key_id`에 의해 덮어써질 수 있습니다. [#71011](https://github.com/ClickHouse/ClickHouse/pull/71011) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* 설정 tiers의 초기 구현입니다. [#71145](https://github.com/ClickHouse/ClickHouse/pull/71145) ([Raúl Marín](https://github.com/Algunenano)).
* ORDER BY WITH FILL 연산자에서 staleness 절을 지원합니다. [#71151](https://github.com/ClickHouse/ClickHouse/pull/71151) ([Mikhail Artemenko](https://github.com/Michicosun)).
* JSON string을 통한 serialization/역직렬화를 사용해 Map/Tuple/Object에서 새로운 JSON으로 단순 CAST를 구현했습니다. [#71320](https://github.com/ClickHouse/ClickHouse/pull/71320) ([Pavel Kruglov](https://github.com/Avogar)).
* 집계 함수 `any`에 `anyRespectNulls`, `firstValueRespectNulls`, `anyValueRespectNulls` 별칭을 추가했습니다. 또한 집계 함수 `anyLast`에 `anyLastRespectNulls` 및 `lastValueRespectNulls` 별칭도 추가했습니다. 이제 camel-case와 underscore를 혼용한 구문 대신 더 자연스러운 camel-case 전용 구문을 사용할 수 있습니다. 예를 들어 `anyLast_respect_nullsStateIf` 대신 `SELECT anyLastRespectNullsStateIf`를 사용할 수 있습니다. [#71403](https://github.com/ClickHouse/ClickHouse/pull/71403) ([Peter Nguyen](https://github.com/petern48)).
* 구성 `date_time_utc` 매개변수를 추가하여 JSON 로그 포맷팅에서 RFC 3339/ISO8601 포맷의 UTC 날짜 및 시간을 지원할 수 있게 했습니다. [#71560](https://github.com/ClickHouse/ClickHouse/pull/71560) ([Ali](https://github.com/xogoodnow)).
* 파트에서 세분화 수준이 상수인 경우, 인덱스 세분화 수준(index granularity) 값의 메모리 사용량을 최적화했습니다. 또한 파트에서 항상 상수 세분화 수준을 선택할 수 있는 기능(설정 `use_const_adaptive_granularity`)을 추가하여 메모리 최적화가 항상 적용되도록 했습니다. 이는 대규모 워크로드(공유 스토리지의 수조 개 행)에서 데이터 파트의 메타데이터(인덱스 세분화 수준 값)로 인해 메모리 사용량이 계속 증가하는 문제를 방지하는 데 도움이 됩니다. [#71786](https://github.com/ClickHouse/ClickHouse/pull/71786) ([Anton Popov](https://github.com/CurtizJ)).
* 모든 Experimental / 베타 기능을 비활성화하는 전역 스위치로 `allowed_feature_tier`를 구현했습니다. [#71841](https://github.com/ClickHouse/ClickHouse/pull/71841) ([Raúl Marín](https://github.com/Algunenano)).
* `iceberg[S3;HDFS;Azure]Cluster`, `deltaLakeCluster`, `hudiCluster` 테이블 함수를 추가했습니다. [#72045](https://github.com/ClickHouse/ClickHouse/pull/72045) ([Mikhail Artemenko](https://github.com/Michicosun)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 데이터 블록 내 NULL 값 비율이 지정된 임계값을 초과할 경우 `Nullable` 컬럼에 대해 함수를 단락 평가 방식으로 실행할 수 있도록, 2개의 새로운 설정 `short_circuit_function_evaluation_for_nulls` 및 `short_circuit_function_evaluation_for_nulls_threshold`를 추가했습니다. 즉, 함수는 null이 아닌 값을 가진 행에 대해서만 실행됩니다. 이는 하나 이상의 인수가 NULL인 행에서 NULL 값을 반환하는 함수에만 적용됩니다. [#60129](https://github.com/ClickHouse/ClickHouse/pull/60129) ([李扬](https://github.com/taiyang-li)).
* 이제 `join_algorithm='parallel_hash'`에서 병렬 처리를 위해 입력 블록을 스레드에 분배할 때 입력 블록의 컬럼을 복사하지 않습니다. [#67782](https://github.com/ClickHouse/ClickHouse/pull/67782) ([Nikita Taranov](https://github.com/nickitat)).
* 서로 겹치지 않는 파트에 대해 `Replacing` 머지 알고리즘을 최적화했습니다. [#70977](https://github.com/ClickHouse/ClickHouse/pull/70977) ([Anton Popov](https://github.com/CurtizJ)).
* 메트릭 및 system.detached&#95;parts에는 readonly 및 write-once 디스크의 분리된 파트를 나열하지 않도록 했습니다. [#71086](https://github.com/ClickHouse/ClickHouse/pull/71086) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 기본적으로 heavy asynchronous metrics를 계산하지 않도록 했습니다. 이 기능은 [#40332](https://github.com/ClickHouse/ClickHouse/issues/40332)에서 도입되었지만, 단 한 고객에게만 필요한 무거운 백그라운드 작업을 두는 것은 바람직하지 않습니다. [#71087](https://github.com/ClickHouse/ClickHouse/pull/71087) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 임계 구역을 줄여 system.query&#95;metric&#95;log 수집 인터벌의 성능과 정확도를 개선했습니다. [#71473](https://github.com/ClickHouse/ClickHouse/pull/71473) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="improvement">
  #### 개선 사항
</div>

* 상수 배열과 상수로 캡처한 인수를 사용하는 고차 함수는 상수를 반환합니다. [#58400](https://github.com/ClickHouse/ClickHouse/pull/58400) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 가상 행을 생성하는 read-in-order 최적화가 추가되어, 특히 여러 파트가 있을 때 머지 정렬 중 읽는 데이터가 줄어듭니다. [#62125](https://github.com/ClickHouse/ClickHouse/pull/62125) ([Shichao Jin](https://github.com/jsc0218)).
* 쿼리 계획 단계 이름(`EXPLAIN PLAN json=1`)과 파이프라인 프로세서 이름(`EXPLAIN PIPELINE compact=0,graph=1`)에 이제 접미사로 고유 ID가 추가됩니다. 이를 통해 프로세서 프로파일러 출력과 OpenTelemetry trace를 EXPLAIN 출력에 대응시킬 수 있습니다. [#63518](https://github.com/ClickHouse/ClickHouse/pull/63518) ([qhsong](https://github.com/qhsong)).
* Azure Blob Storage에 쓴 뒤 객체 존재 여부를 확인하는 옵션이 추가되었으며, 이는 `check_objects_after_upload` 설정으로 제어됩니다. [#64847](https://github.com/ClickHouse/ClickHouse/pull/64847) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* HashTable destroyElements의 use-after-dtor 문제를 수정했습니다. [#65279](https://github.com/ClickHouse/ClickHouse/pull/65279) ([cangyin](https://github.com/cangyin)).
* `clickhouse-local`에서 기본적으로 `Atomic` 데이터베이스를 사용합니다. [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647)의 1번과 5번 항목을 해결합니다. [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817)을 해결합니다. [#68024](https://github.com/ClickHouse/ClickHouse/pull/68024) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 쓰기 버퍼는 명시적으로 취소하거나 완료 처리해야 합니다. 예외가 발생하면 오류를 클라이언트에 알리기 위해 HTTP protocol이 중단됩니다. [#68800](https://github.com/ClickHouse/ClickHouse/pull/68800) ([Sema Checherinda](https://github.com/CheSema)).
* replica&#95;dir를 생성하고 DDLWorker에서 레플리카를 활성 상태로 표시하여 실행 중인 DDLWorker 호스트를 보고합니다. [#69658](https://github.com/ClickHouse/ClickHouse/pull/69658) ([tuanpach](https://github.com/tuanpach)).
* 1. `DDLQueryStatusSource` 리팩터링: * `DDLQueryStatusSource`의 이름을 `DistributedQueryStatusSource`로 변경하고, 이를 기반 클래스로 만듭니다 * `DDL On Cluster`와 복제된 데이터베이스의 DDL 작업 상태를 각각 쿼리할 수 있도록 `DDLQueryStatusSource`에서 파생된 두 개의 하위 클래스 `DDLOnClusterQueryStatusSource` 및 `ReplicatedDatabaseQueryStatusSource`를 생성합니다. 2. `DDLOnClusterQueryStatusSource&#96;`에서 오프라인 호스트를 더 이상 기다리지 않고 중지할 수 있도록 지원합니다. [#69660](https://github.com/ClickHouse/ClickHouse/pull/69660) ([tuanpach](https://github.com/tuanpach)).
* 예기치 않은 결과를 초래할 수 있으므로, 기본적으로 ORDER BY/GROUP BY/PARTITION BY/PRIMARY KEY에서 Variant/Dynamic 타입을 허용하지 않습니다. [#69731](https://github.com/ClickHouse/ClickHouse/pull/69731) ([Pavel Kruglov](https://github.com/Avogar)).
* `ON CLUSTER` 백업 및 복원의 오류 처리와 취소 동작을 개선했습니다. - 한 호스트에서 백업 또는 복원이 실패하면 다른 호스트에서도 자동으로 취소됩니다 - 일부 호스트는 실패하고 다른 호스트는 작업을 계속하더라도 이상한 오류가 발생하지 않습니다 - 한 호스트에서 백업 또는 복원이 취소되면 다른 호스트에서도 자동으로 취소됩니다 - `test_disallow_concurrency` 관련 문제를 수정했으며, 이제 동시성 비활성화가 더 잘 동작합니다 - 이제 백업 및 복원은 ZooKeeper 연결 끊김에 훨씬 더 강합니다. [#70027](https://github.com/ClickHouse/ClickHouse/pull/70027) ([Vitaly Baranov](https://github.com/vitlibar)).
* 기본적으로 `parallel_replicas_local_plan`을 활성화했습니다. 쿼리 시작 노드에서 완전한 로컬 계획을 구성하면 더 적은 리소스 사용으로 병렬 레플리카 성능이 향상되며, 더 많은 쿼리 최적화를 적용할 수 있습니다. [#70171](https://github.com/ClickHouse/ClickHouse/pull/70171) ([Igor Nikonov](https://github.com/devcrafter)).
* attach 스레드가 아니라 재시작 스레드에서 ZooKeeper의 metadata&#95;version 레코드를 수정하도록 했습니다. [#70297](https://github.com/ClickHouse/ClickHouse/pull/70297) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* http&#95;handlers(`dynamic_query_handler`/`predefined_query_handler`)에서 사용자 이름/비밀번호를 설정할 수 있는 기능을 추가했습니다. [#70725](https://github.com/ClickHouse/ClickHouse/pull/70725) ([Azat Khuzhin](https://github.com/azat)).
* S3Queue 스토리지의 일부 설정에 대해 `ALTER TABLE ... MODIFY/RESET SETTING ...`을 지원합니다. [#70811](https://github.com/ClickHouse/ClickHouse/pull/70811) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 디렉터리를 나열할 때 비용 비효율이 발생할 수 있으므로 객체 스토리지 API를 호출하지 않습니다. 대신 파일 이름 목록을 메모리에 저장합니다. 그 대가로 초기 적재 시간이 늘어나고 파일 이름 저장에 필요한 메모리 사용량이 증가합니다. [#70823](https://github.com/ClickHouse/ClickHouse/pull/70823) ([Julia Kartseva](https://github.com/jkartseva)).
