  ### ClickHouse 릴리스 v24.10.1.2812-안정 (9cd0a3738d5) v24.10.1.1-new (b12a3677418) 대비 FIXME

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 서브쿼리가 괄호 안에 있는 `UNION` 쿼리 체인에서 이제 `FORMAT` 앞에 `SETTINGS`를 작성할 수 있습니다. 이로써 [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712)가 해결됩니다. 또한 하나의 쿼리에서 SETTINGS 절이 연속으로 두 번 지정된 경우의 동작이 변경됩니다. 해당 서브쿼리에는 가장 가까운 SETTINGS 절이 우선 적용됩니다. 이전 버전에서는 가장 바깥쪽 SETTINGS 절이 안쪽 절보다 우선 적용될 수 있었습니다. [#68614](https://github.com/ClickHouse/ClickHouse/pull/68614) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `[PRE]WHERE` 절의 필터 조건 재정렬이 이제 기본적으로 허용됩니다. 이 동작은 `allow_reorder_prewhere_conditions`를 `false`로 설정하여 비활성화할 수 있습니다. [#70657](https://github.com/ClickHouse/ClickHouse/pull/70657) ([Nikita Taranov](https://github.com/nickitat)).
* `mapKeys`/`mapValues`에서 `LowCardinality` 타입이 유지되도록 하여 `optimize_functions_to_subcolumns` 최적화를 수정했습니다(이전에는 `Invalid column type for ColumnUnique::insertRangeFrom. Expected String, got LowCardinality(String)` 오류가 발생할 수 있었습니다). [#70716](https://github.com/ClickHouse/ClickHouse/pull/70716) ([Azat Khuzhin](https://github.com/azat)).
* 호환되지 않는 라이선스를 가진 `idxd-config` 라이브러리를 제거했습니다. 이에 따라 실험적 Intel DeflateQPL 코덱도 함께 제거됩니다. [#70987](https://github.com/ClickHouse/ClickHouse/pull/70987) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 새 기능
</div>

* MongoDB 통합을 리팩터링했습니다. 지원 중단 예정인 Poco::MongoDB에서 새 드라이버 mongocxx로 마이그레이션하고, 지원 중단 예정인 기존 protocol 지원을 제거했으며, URI를 통한 connection, 모든 MongoDB 타입, MongoDB 측의 WHERE 및 ORDER BY SQL 문을 지원합니다. 또한 MongoDB에서 지원하지 않는 표현식에는 제한을 적용합니다. [#63279](https://github.com/ClickHouse/ClickHouse/pull/63279) ([Kirill Nikiforov](https://github.com/allmazz)).
* clickhouse-client에 새로운 `--progress-table` 옵션을 추가했습니다. 이 옵션은 쿼리 실행 중 변화하는 메트릭을 표로 출력합니다. 새로운 `--enable-progress-table-toggle`은 `--progress-table` 옵션과 함께 사용되며, control 키(Space)를 눌러 진행 표 렌더링을 전환할 수 있습니다. [#63689](https://github.com/ClickHouse/ClickHouse/pull/63689) ([Maria Khristenko](https://github.com/mariaKhr)).
* 와일드카드 프리픽스에 대한 접근 권한을 부여할 수 있습니다. `GRANT SELECT ON db.table_pefix_* TO user`. [#65311](https://github.com/ClickHouse/ClickHouse/pull/65311) ([pufit](https://github.com/pufit)).
* 개별 쿼리별로 메모리와 system.events 테이블의 메트릭 값 이력을 포함하며, 주기적으로 디스크에 플러시되는 system.query&#95;metric&#95;log를 추가했습니다. [#66532](https://github.com/ClickHouse/ClickHouse/pull/66532) ([Pablo Marcos](https://github.com/pamarcos)).
* 계산기 스타일 표현식을 사용할 수 있도록, 암시적 SELECT를 사용해 간단한 SELECT 쿼리를 작성할 수 있습니다. 예: `ch "1 + 2"`. 이는 새로운 설정 `implicit_select`로 제어됩니다. [#68502](https://github.com/ClickHouse/ClickHouse/pull/68502) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 포맷 변환용 단축 기능으로 clickhouse local의 `--copy` 모드를 지원합니다 [#68503](https://github.com/ClickHouse/ClickHouse/issues/68503). [#68583](https://github.com/ClickHouse/ClickHouse/pull/68583) ([Denis Hananein](https://github.com/denis-hananein)).
* `arrayUnion` 함수 지원을 추가했습니다. [#68989](https://github.com/ClickHouse/ClickHouse/pull/68989) ([Peter Nguyen](https://github.com/petern48)).
* 집계 함수 `quantileExactWeightedInterpolated`를 지원합니다. 이 함수는 `quantileExactWeighted`를 기반으로 한 보간 버전입니다. 이미 `quantileExactInterpolatedWeighted`가 있는데 왜 새로운 `quantileExactWeightedInterpolated`가 필요한지 의문이 들 수 있습니다. 새 함수가 기존 함수보다 더 정확하기 때문입니다. 참고로 이 함수는 Apache Gluten의 Spark 호환성을 위한 것입니다. [#69619](https://github.com/ClickHouse/ClickHouse/pull/69619) ([李扬](https://github.com/taiyang-li)).
* `arrayElementOrNull` 함수를 지원합니다. 배열 인덱스가 범위를 벗어나거나 map 키를 찾지 못하면 null을 반환합니다. [#69646](https://github.com/ClickHouse/ClickHouse/pull/69646) ([李扬](https://github.com/taiyang-li)).
* `config.xml` 파일의 새로운 `message_regexp` 및 `message_regexp_negative` field를 통해 정규식을 지정하여 로깅을 필터링할 수 있습니다. 보다 직관적인 개발자 경험을 위해 로깅은 포맷된 비색상 텍스트에 적용됩니다. [#69657](https://github.com/ClickHouse/ClickHouse/pull/69657) ([Peter Nguyen](https://github.com/petern48)).
* 대부분의 함수에서 Dynamic 내부 타입에 대해 함수를 실행하는 방식으로 Dynamic 타입을 지원합니다. [#69691](https://github.com/ClickHouse/ClickHouse/pull/69691) ([Pavel Kruglov](https://github.com/Avogar)).
* 문자열의 RIPEMD-160 암호학적 hash를 계산하는 `RIPEMD160` 함수를 다시 추가했습니다. 예시: `SELECT HEX(RIPEMD160('The quick brown fox jumps over the lazy dog'))`는 `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`를 반환합니다. [#70087](https://github.com/ClickHouse/ClickHouse/pull/70087) ([Dergousov Maxim](https://github.com/m7kss1)).
* 객체 스토리지 테이블 엔진과 데이터 레이크에서 읽은 파일을 캐시할 수 있도록 지원합니다. 이때 ETag + file path의 hash를 cache 키로 사용합니다. [#70135](https://github.com/ClickHouse/ClickHouse/pull/70135) ([Kseniia Sumarokova](https://github.com/kssenii)).
* HDFS의 Iceberg 테이블 읽기를 지원합니다. [#70268](https://github.com/ClickHouse/ClickHouse/pull/70268) ([flynn](https://github.com/ucasfl)).
* 설정 `input_format_binary_read_json_as_string/output_format_binary_write_json_as_string`을 사용하면 RowBinary 포맷에서 JSON 타입을 바이너리 문자열로 읽고 쓸 수 있습니다. [#70288](https://github.com/ClickHouse/ClickHouse/pull/70288) ([Pavel Kruglov](https://github.com/Avogar)).
* Native 형식에서 JSON 컬럼을 단일 String 컬럼으로 직렬화/역직렬화할 수 있습니다. 출력 시에는 설정 `output_format_native_write_json_as_string`을 사용하십시오. 입력 시에는 컬럼 데이터 앞에 serialization version `1`을 사용하십시오. [#70312](https://github.com/ClickHouse/ClickHouse/pull/70312) ([Pavel Kruglov](https://github.com/Avogar)).
* 표준 CTE인 `with insert`를 지원합니다. 이전에는 `insert ... with ...`만 지원했습니다. [#70593](https://github.com/ClickHouse/ClickHouse/pull/70593) ([Shichao Jin](https://github.com/jsc0218)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* `pointInPolygon`에 대해 minmax 인덱스를 지원합니다. [#62085](https://github.com/ClickHouse/ClickHouse/pull/62085) ([JackyWoo](https://github.com/JackyWoo)).
* Parquet 블룸 필터 지원을 추가했습니다. [#62966](https://github.com/ClickHouse/ClickHouse/pull/62966) ([Arthur Passos](https://github.com/arthurpassos)).
* INSERT가 SELECT에 영향을 주지 않도록 파트 잠금으로 인한 문제를 피하는 lock-free 파트 rename을 적용했습니다 (`fsync_part_directory`를 사용하는 일반적인 환경에서 INSERT와 병렬로 실행되는 SELECT의 QPS가 2배 향상되었으며, 고부하에서는 효과가 더 큽니다). 참고로 현재는 `ReplicatedMergeTree`에만 적용됩니다. [#64955](https://github.com/ClickHouse/ClickHouse/pull/64955) ([Azat Khuzhin](https://github.com/azat)).
* `materialize ttl`에서 `ttl_only_drop_parts`를 준수하도록 개선했습니다. TTL을 다시 계산하는 데 필요한 컬럼만 읽고, 파트를 빈 파트로 교체해 삭제합니다. [#65488](https://github.com/ClickHouse/ClickHouse/pull/65488) ([Andrey Zvonov](https://github.com/zvonand)).
* 성능 향상을 위해 `IDisk`와 `IObjectStorage`를 리팩터링했습니다. `plain` 및 `plain_rewritable` 객체 스토리지의 테이블이 더 빠르게 초기화됩니다. [#68146](https://github.com/ClickHouse/ClickHouse/pull/68146) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 잠금 경합을 최소화하도록 ThreadPool의 스레드 생성을 최적화했습니다. 이제 스레드 생성은 임계 구역 밖에서 수행되므로, 고부하 환경에서 작업 스케줄링과 스레드 관리가 지연되는 일을 방지합니다. 그 결과 높은 동시 부하에서도 ClickHouse의 응답성이 크게 향상됩니다. [#68694](https://github.com/ClickHouse/ClickHouse/pull/68694) ([filimonov](https://github.com/filimonov)).
* ORC에서 LowCardinality String 컬럼을 읽을 수 있도록 했습니다. [#69481](https://github.com/ClickHouse/ClickHouse/pull/69481) ([李扬](https://github.com/taiyang-li)).
* 데이터를 희소 컬럼으로 직접 parse할 수 있는 기능을 추가했습니다. [#69828](https://github.com/ClickHouse/ClickHouse/pull/69828) ([Anton Popov](https://github.com/CurtizJ)).
* single-threaded 모드에서 Parquet row group의 병렬 읽기와 row group 프리페치를 지원합니다. [#69862](https://github.com/ClickHouse/ClickHouse/pull/69862) ([LiuNeng](https://github.com/liuneng1994)).
* 누락된 값이 많은 포맷(예: `JSONEachRow`)의 parsing 성능을 개선했습니다. [#69875](https://github.com/ClickHouse/ClickHouse/pull/69875) ([Anton Popov](https://github.com/CurtizJ)).
* `part_log`, `query_views_log`, `filesystem_cache_log`와 같은 system logs에서 `ProfileEvents`에 `LowCardinality`를 사용합니다. [#70152](https://github.com/ClickHouse/ClickHouse/pull/70152) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* FromUnixTimestamp/ToUnixTimestamp 함수의 성능을 개선했습니다. [#71042](https://github.com/ClickHouse/ClickHouse/pull/71042) ([kevinyhzou](https://github.com/KevinyhZou)).

<div id="improvement">
  #### 개선 사항
</div>

* 매개변수화된 SQL 별칭(alias)을 허용합니다. [#50665](https://github.com/ClickHouse/ClickHouse/pull/50665) ([Anton Kozlov](https://github.com/tonickkozlov)).
* [#57616](https://github.com/ClickHouse/ClickHouse/issues/57616)을 수정했습니다. 이 문제는 모든 양의 정수 인수가 자동으로 `uint64` 유형으로 식별되어 `summapfiltered`에서 int 유형 데이터와 일치시킬 수 없기 때문에 발생합니다. 사용자가 `uint64` 매개변수를 직접 지정한 것이 아니므로, 일치하지 않는 문제는 혼란을 줄 수 있습니다. 또한 인수가 `[1,2,3,toint8(-3)]`인 경우에는 `getleastsupertype()` 때문에 이 매개변수들이 모두 `int` 유형으로 처리되어 `'1,2,3'` 역시 `summapfiltered`에서 `uint` 유형 데이터와 일치하지 않게 됩니다. [#58408](https://github.com/ClickHouse/ClickHouse/pull/58408) ([Chen768959](https://github.com/Chen768959)).
* `ALTER TABLE .. REPLACE PARTITION`이 이제 다른 파티션에서 발생하는 뮤테이션/머지를 더 이상 기다리지 않습니다. [#59138](https://github.com/ClickHouse/ClickHouse/pull/59138) ([Vasily Nemkov](https://github.com/Enmk)).
* 이제 갱신 가능 구체화 뷰가 복제된 데이터베이스에서도 지원됩니다. [#60669](https://github.com/ClickHouse/ClickHouse/pull/60669) ([Michael Kolupaev](https://github.com/al13n321)).
* `data/database_name/` 디렉터리의 테이블용 심볼릭 링크는 이제 기본 디스크의 `store/...` 디렉터리가 아니라, 스토리지 정책에 따라 테이블 데이터의 실제 경로를 가리키도록 생성됩니다. [#61777](https://github.com/ClickHouse/ClickHouse/pull/61777) ([Kirill](https://github.com/kirillgarbar)).
* 전역 Context 객체에 구성 업데이트를 적용합니다. 이 변경으로 [#62308](https://github.com/ClickHouse/ClickHouse/issues/62308)과 같은 문제가 수정됩니다. [#62944](https://github.com/ClickHouse/ClickHouse/pull/62944) ([Amos Bird](https://github.com/amosbird)).
* 병렬 레플리카 알고리즘의 동작을 제어하는 설정을 개선했습니다. 간단히 요약하면, ClickHouse에는 여러 레플리카를 포함하는 병렬 읽기를 위한 4가지 알고리즘이 있으며, 이는 `parallel_replicas_mode` 설정에 반영되어 있습니다. 이 설정의 기본값은 `read_tasks`입니다. 또한 토글 스위치 설정 `enable_parallel_replicas`가 추가되었습니다. [#63151](https://github.com/ClickHouse/ClickHouse/pull/63151) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 기본값만 사용되고 사용자 설정값이 적용되지 않던 `ReadSettings` 문제를 수정했습니다. [#65625](https://github.com/ClickHouse/ClickHouse/pull/65625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* JSON에서 Enum 필드를 파싱할 때 정수를 포함한 문자열은 해당 Enum 요소로 해석됩니다. 이로써 [#65119](https://github.com/ClickHouse/ClickHouse/issues/65119)이 해결됩니다. [#66801](https://github.com/ClickHouse/ClickHouse/pull/66801) ([scanhex12](https://github.com/scanhex12)).
* `TRIM`에서 `LEADING` 또는 `TRAILING` 빈 문자열을 no-op으로 처리할 수 있도록 허용합니다. 이로써 [#67792](https://github.com/ClickHouse/ClickHouse/issues/67792)가 해결됩니다. [#68455](https://github.com/ClickHouse/ClickHouse/pull/68455) ([Peter Nguyen](https://github.com/petern48)).
* 쿼리로 테이블을 생성하는 기능인 `CREATE TABLE ... CLONE AS ...`를 지원합니다. 이 기능은 원본 테이블의 스키마를 복제한 다음 새로 생성된 테이블에 모든 파티션을 ATTACH합니다. 이 기능은 `MergeTree` 계열 테이블에서만 지원됩니다. 이로써 [#65015](https://github.com/ClickHouse/ClickHouse/issues/65015)가 해결됩니다. [#69091](https://github.com/ClickHouse/ClickHouse/pull/69091) ([tuanpach](https://github.com/tuanpach)).
* Gluten ClickHouse에서 Spark의 timestamp 유형은 ClickHouse의 datetime64(6) 유형에 매핑됩니다. timestamp &#39;2012-01-01 00:11:22&#39;를 문자열로 CAST하면 Spark는 &#39;2012-01-01 00:11:22&#39;를 반환하지만, Gluten ClickHouse는 &#39;2012-01-01 00:11:22.000000&#39;를 반환합니다. [#69179](https://github.com/ClickHouse/ClickHouse/pull/69179) ([Wenzheng Liu](https://github.com/lwz9103)).
* `enable_analyzer`가 `true`로 설정된 경우 상수 표현식을 계산할 때 항상 새 분석기를 사용하도록 했습니다. 또한 상수 표현식 계산을 위해 `SELECT` 쿼리를 사용하지 않고도 `executable()` 테이블 함수 인수를 계산할 수 있도록 지원합니다. [#69292](https://github.com/ClickHouse/ClickHouse/pull/69292) ([Dmitry Novik](https://github.com/novikd)).
* 안전하지 않은 식별자를 허용하지 않도록 `enable_secure_identifiers`를 추가했습니다. [#69411](https://github.com/ClickHouse/ClickHouse/pull/69411) ([tuanpach](https://github.com/tuanpach)).
* show create 쿼리 결과에서 식별자 인용 방식을 정의하는 `show_create_query_identifier_quoting_rule`을 추가했습니다. 가능한 값: - `user_display`: 식별자가 keyword인 경우. - `when_necessary`: 식별자가 `{"distinct", "all", "table"}` 중 하나이거나 모호성을 일으킬 수 있는 경우(컬럼 이름, 딕셔너리 속성 이름). - `always`: 식별자를 항상 인용합니다. [#69448](https://github.com/ClickHouse/ClickHouse/pull/69448) ([tuanpach](https://github.com/tuanpach)).
* [https://github.com/ClickHouse/ClickHouse/pull/69346](https://github.com/ClickHouse/ClickHouse/pull/69346)의 후속 작업입니다. 해당 문서에 설명된 4번 항목도 이제 작동합니다. [#69563](https://github.com/ClickHouse/ClickHouse/pull/69563) ([Vitaly Baranov](https://github.com/vitlibar)).
