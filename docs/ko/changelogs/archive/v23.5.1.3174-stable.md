<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 로컬 객체 스토리지가 S3 객체 스토리지와 일관되게 동작하도록 하고, 추가 시 발생하던 문제를 수정했으며([#48465](https://github.com/ClickHouse/ClickHouse/issues/48465) 해결), 이를 독립적인 스토리지로 구성할 수 있도록 했습니다. 이 변경은 하위 호환되지 않는데, 로컬 객체 스토리지 위의 캐시가 이전 버전과 호환되지 않기 때문입니다. [#48791](https://github.com/ClickHouse/ClickHouse/pull/48791) ([Kseniia Sumarokova](https://github.com/kssenii)).
* Date&#95;trunc 함수가 항상 DateTime 타입을 반환하도록 변경했습니다. [#48851](https://github.com/ClickHouse/ClickHouse/pull/48851) ([Shane Andrade](https://github.com/mauidude)).
* 실험적 기능 &quot;인메모리 데이터 파트&quot;를 제거했습니다. 데이터 포맷은 계속 지원되지만, 해당 설정은 no-op이며 대신 compact 또는 wide 파트가 사용됩니다. 이로써 [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409)가 해결됩니다. [#49429](https://github.com/ClickHouse/ClickHouse/pull/49429) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 설정 parallelize&#95;output&#95;from&#95;storages 및 input&#95;format&#95;parquet&#95;preserve&#95;order의 기본값을 변경했습니다. 이제 ClickHouse가 파일(예: CSV 또는 Parquet)에서 읽을 때 행 순서를 재정렬할 수 있으므로 많은 경우 성능이 크게 향상됩니다. 순서를 유지하던 이전 동작으로 복원하려면 `parallelize_output_from_storages = 0`, `input_format_parquet_preserve_order = 1`을 사용하십시오. [#49479](https://github.com/ClickHouse/ClickHouse/pull/49479) ([Michael Kolupaev](https://github.com/al13n321)).
* 프로젝션을 프로덕션 환경에서 사용할 수 있도록 했습니다. SELECT 쿼리에 대해 프로젝션을 선택할지 제어하는 `optimize_use_projections` 설정을 추가했습니다. `allow_experimental_projection_optimization` 설정은 더 이상 사용되지 않으며 아무 동작도 하지 않습니다. [#49719](https://github.com/ClickHouse/ClickHouse/pull/49719) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* joinGet()을 결정적이지 않은 것으로 표시했습니다(dictGet도 동일). [#49843](https://github.com/ClickHouse/ClickHouse/pull/49843) ([Azat Khuzhin](https://github.com/azat)).
* &quot;`groupArray` returns cannot be nullable&quot;를 되돌렸습니다(`Nullable` 타입에 대한 `groupArray`/`groupArrayLast`/`groupArraySample`의 바이너리 호환성이 깨져 `TOO_LARGE_ARRAY_SIZE` 또는 `CANNOT_READ_ALL_DATA`로 이어질 가능성이 있기 때문입니다). [#49971](https://github.com/ClickHouse/ClickHouse/pull/49971) ([Azat Khuzhin](https://github.com/azat)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 기본적으로 마크와 프라이머리 키(primary key)를 압축합니다. 이로 인해 콜드 쿼리 시점이 크게 단축됩니다. 업그레이드 참고 사항: 압축된 마크와 프라이머리 키 지원은 버전 22.9에서 추가되었습니다. 압축된 마크 또는 프라이머리 키를 활성화했거나, 이 기능이 기본적으로 활성화되는 버전 23.5 이상을 설치한 경우 버전 22.8 이하로는 다운그레이드할 수 없습니다. 서버 구성 파일의 `<merge_tree>` 섹션에서 `compress_marks` 및 `compress_primary_key` 설정을 지정해 압축된 마크 또는 프라이머리 키를 명시적으로 비활성화할 수도 있습니다. **업그레이드 참고 사항:** 22.9 이전 버전에서 업그레이드하는 경우, 모든 레플리카를 한 번에 업그레이드하거나 업그레이드 전에 압축을 비활성화하거나, 압축된 마크를 지원하지만 기본적으로 활성화하지는 않는 23.3과 같은 중간 버전을 거쳐 업그레이드해야 합니다. [#42587](https://github.com/ClickHouse/ClickHouse/pull/42587) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 여러 파일에서 읽을 때 각 파일별 병렬 파싱 스레드 수를 줄여 [#42192](https://github.com/ClickHouse/ClickHouse/issues/42192)를 해결했습니다. [#46661](https://github.com/ClickHouse/ClickHouse/pull/46661) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 아무것도 삽입되지 않은 경우 `ANY` 해시 조인에 블록을 저장하지 않습니다. [#48633](https://github.com/ClickHouse/ClickHouse/pull/48633) ([vdimir](https://github.com/vdimir)).
* JIT 컴파일 시 집계 조합자 `-If` 관련 문제를 수정했습니다. [#48120](https://github.com/ClickHouse/ClickHouse/issues/48120)을 해결합니다. [#49083](https://github.com/ClickHouse/ClickHouse/pull/49083) ([Igor Nikonov](https://github.com/devcrafter)).
* 원격 테이블에서 읽을 때 작업 스틸링이 가능하도록 전체 파트를 읽는 대신 더 작은 작업을 사용합니다 * 작업 크기는 읽을 컬럼의 크기에 따라 결정됩니다 * s3에서 읽을 때는 항상 1mb 버퍼를 사용합니다 * 캐시 세그먼트 경계를 1mb에 맞춰 정렬해 작은 작업에서도 충분한 크기를 유지합니다. 이는 단편화를 방지하는 데도 도움이 됩니다. [#49287](https://github.com/ClickHouse/ClickHouse/pull/49287) ([Nikita Taranov](https://github.com/nickitat)).
