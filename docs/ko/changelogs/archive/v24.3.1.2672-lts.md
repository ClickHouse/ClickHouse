[#61058](https://github.com/ClickHouse/ClickHouse/pull/61058) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* MySQL과의 호환성을 높이기 위해 이제 함수 `locate`는 기본적으로 인수 `(needle, haystack[, start_pos])`를 받습니다. 이전 동작인 `(haystack, needle, [, start_pos])`는 `function_locate_has_mysql_compatible_argument_order = 0`을 설정하여 복원할 수 있습니다. [#61092](https://github.com/ClickHouse/ClickHouse/pull/61092) ([Robert Schulze](https://github.com/rschu1ze)).
* 구형 인메모리 데이터 파트는 23.5 버전부터 더 이상 권장되지 않았고, 23.10 버전부터는 지원도 중단되었습니다. 이제 남아 있던 관련 코드도 제거되었습니다. [#55186](https://github.com/ClickHouse/ClickHouse/issues/55186) 및 [#45409](https://github.com/ClickHouse/ClickHouse/issues/45409)의 후속 작업입니다. 인메모리 데이터 파트는 23.5 버전 이전에만 사용할 수 있었고, MergeTree 테이블에서 해당 SETTINGS를 지정해 수동으로 활성화해야만 사용할 수 있었으므로 실제로 사용했을 가능성은 낮습니다. 인메모리 데이터 파트가 있는지 확인하려면 다음 쿼리를 실행하십시오: `SELECT part_type, count() FROM system.parts GROUP BY part_type ORDER BY part_type`. 인메모리 데이터 파트 사용을 비활성화하려면 `ALTER TABLE ... MODIFY SETTING min_bytes_for_compact_part = DEFAULT, min_rows_for_compact_part = DEFAULT`를 실행하십시오. 구버전 ClickHouse 릴리스에서 업그레이드하기 전에 먼저 인메모리 데이터 파트가 없는지 확인하십시오. 인메모리 데이터 파트가 있다면 먼저 이를 비활성화하고, 인메모리 데이터 파트가 모두 없어질 때까지 기다린 뒤 업그레이드를 계속하십시오. [#61127](https://github.com/ClickHouse/ClickHouse/pull/61127) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 기본적으로 MergeTree 테이블의 `ORDER BY`에서 `SimpleAggregateFunction` 사용을 금지합니다(`AggregateFunction`이 금지되는 것과 동일한 이유로, 비교할 수 없기 때문입니다). 허용하려면 `allow_suspicious_primary_key`를 사용하십시오. [#61399](https://github.com/ClickHouse/ClickHouse/pull/61399) ([Azat Khuzhin](https://github.com/azat)).
* ClickHouse는 일반적으로 UTF-8로 사용되는 String 데이터 타입에 임의의 바이너리 데이터를 허용합니다. 반면 Parquet/ORC/Arrow의 String은 UTF-8만 지원합니다. 따라서 ClickHouse String 데이터 타입에 대해 Arrow의 어떤 데이터 타입을 사용할지, 즉 String 또는 Binary를 선택할 수 있습니다. 이는 `output_format_parquet_string_as_string`, `output_format_orc_string_as_string`, `output_format_arrow_string_as_string` 설정으로 제어됩니다. 정확성과 호환성 측면에서는 Binary가 더 적절하지만, 대부분의 경우 기본값으로 String을 사용하는 편이 사용자 기대에 더 부합합니다. Parquet/ORC/Arrow는 lz4와 zstd를 포함한 다양한 압축 메서드를 지원합니다. ClickHouse는 이러한 모든 압축 메서드를 지원합니다. 일부 품질이 떨어지는 도구는 더 빠른 `lz4` 압축 메서드를 지원하지 않으므로, 기본값을 `zstd`로 설정했습니다. 이는 `output_format_parquet_compression_method`, `output_format_orc_compression_method`, `output_format_arrow_compression_method` 설정으로 제어됩니다. Parquet와 ORC의 기본값은 `zstd`로 변경했지만 Arrow는 변경하지 않았습니다(Arrow는 저수준 사용 사례가 강조되기 때문입니다). [#61817](https://github.com/ClickHouse/ClickHouse/pull/61817) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 새 ClickHouse 버전에서는 모든 인수가 Float64인 경우 `geoDistance`, `greatCircleDistance`, `greatCircleAngle` 함수의 내부 계산과 반환 타입에 64비트 배정밀도 부동소수점 데이터 타입을 사용합니다. 이로써 [#58476](https://github.com/ClickHouse/ClickHouse/issues/58476)가 해결됩니다. 이전 버전에서는 이 함수들이 항상 Float32를 사용했습니다. `geo_distance_returns_float64_on_float64_arguments`를 `false`로 설정하거나 `compatibility`를 `24.2` 이하로 설정하면 이전 동작으로 전환할 수 있습니다. [#61848](https://github.com/ClickHouse/ClickHouse/pull/61848) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* 여러 개의 [널 허용] 컬럼이 포함된 경우 직렬화된 집계 메서드의 성능을 개선했습니다. 이는 추상화 무결성을 해치지 않는 [#51399](https://github.com/ClickHouse/ClickHouse/issues/51399)의 일반화된 버전입니다. [#55809](https://github.com/ClickHouse/ClickHouse/pull/55809) ([Amos Bird](https://github.com/amosbird)).

* 테이블의 primary key에 대부분 불필요한 컬럼이 포함된 경우, 해당 컬럼을 메모리에 유지하지 않습니다. 이는 새로운 설정 `primary_key_ratio_of_unique_prefix_values_to_skip_suffix_columns`로 제어되며, 기본값은 `0.9`입니다. 의미는 다음과 같습니다. 복합 primary key에서 어떤 컬럼의 값이 전체의 최소 0.9 비율로 변경되면, 그 뒤의 컬럼들은 로드되지 않습니다. * result&#95;type의 기반 타입이 숫자형일 때 multiIf 함수를 열 지향 방식으로 실행합니다. [#60384](https://github.com/ClickHouse/ClickHouse/pull/60384) ([李扬](https://github.com/taiyang-li)).

* 널 허용 숫자형 또는 널 허용 문자열에 대한 insertManyFrom을 최적화했습니다. [#60846](https://github.com/ClickHouse/ClickHouse/pull/60846) ([李扬](https://github.com/taiyang-li)).
* 불필요하고 비용이 큰 메모리 복사를 생략하도록 함수 `dotProduct`를 최적화했습니다. [#60928](https://github.com/ClickHouse/ClickHouse/pull/60928) ([Robert Schulze](https://github.com/rschu1ze)).
* 파일 시스템 캐시 작업이 잠금 경합의 영향을 덜 받도록 개선했습니다. [#61066](https://github.com/ClickHouse/ClickHouse/pull/61066) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* ColumnString::replicate를 최적화하고 memcpySmallAllowReadWriteOverflow15Impl이 내장 memcpy로 최적화되지 않도록 했습니다. [#61074](https://github.com/ClickHouse/ClickHouse/issues/61074)를 종료합니다. x86-64에서 ColumnString::replicate 속도가 2.46배 향상됩니다. [#61075](https://github.com/ClickHouse/ClickHouse/pull/61075) ([李扬](https://github.com/taiyang-li)).
* 256비트 정수 출력 속도가 30배 빨라졌습니다. [#61100](https://github.com/ClickHouse/ClickHouse/pull/61100) ([Raúl Marín](https://github.com/Algunenano)).
* 구문 오류가 있는 쿼리에 정규식을 사용하는 COLUMNS 매처가 포함된 경우, 정규식이 한 번만 컴파일되어야 하는데 파서의 백트래킹 과정에서 매번 컴파일되고 있었습니다. 이는 근본적인 오류였습니다. 컴파일된 정규식은 AST에 들어갔습니다. 하지만 AST의 A는 &quot;abstract&quot;를 뜻하므로, 무거운 객체를 포함해서는 안 됩니다. AST의 일부는 파싱 중에 생성되었다가 버려질 수 있으며, 이 과정에서 대량의 백트래킹이 발생할 수 있습니다. 그 결과 파싱 성능이 저하되고, readonly 사용자가 DoS를 유발할 수 있게 됩니다. 하지만 가장 큰 문제는 이것이 퍼저의 진행을 가로막는다는 점입니다. [#61543](https://github.com/ClickHouse/ClickHouse/pull/61543) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 단일 값으로의 최적화를 수행하는 새로운 분석기 패스를 추가했습니다. [#61564](https://github.com/ClickHouse/ClickHouse/pull/61564) ([LiuNeng](https://github.com/liuneng1994)).
