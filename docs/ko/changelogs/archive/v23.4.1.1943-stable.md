<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항

* cache 구성에서 `path`가 비어 있지 않고 절대 경로가 아니면 `<clickhouse server data directory>/caches/<path_from_cache_config>` 아래에 배치됩니다. [#48784](https://github.com/ClickHouse/ClickHouse/pull/48784) ([Kseniia Sumarokova](https://github.com/kssenii)).
* [#48727](https://github.com/ClickHouse/ClickHouse/issues/48727) 이전의 동작을 활성화하는 호환성 설정 `parallelize_output_from_storages`. [#49101](https://github.com/ClickHouse/ClickHouse/pull/49101) ([Igor Nikonov](https://github.com/devcrafter)).

<div id="new-feature">
  #### 새 기능
</div>

* 문자열에서 키-값 쌍을 추출하는 `extractKeyValuePairs` 함수를 추가했습니다. 입력 문자열에는 노이즈가 포함될 수 있으며(예: 로그 파일 / 키-값 쌍 포맷으로 100% 정확하게 형식화될 필요는 없음), 알고리즘은 함수에 전달된 인수와 일치하는 키-값 쌍을 찾습니다. 현재 이 함수는 다음 인수를 받습니다: `data_column`(필수), `key_value_pair_delimiter`(기본값 `:`), `pair_delimiters`(기본값 `\space \, \;`), `quoting_character`(기본값 큰따옴표). [#43606](https://github.com/ClickHouse/ClickHouse/pull/43606) ([Arthur Passos](https://github.com/arthurpassos)).
* 백그라운드 작업(머지 및 뮤테이션)을 위한 MemoryTracker를 추가했습니다. 머지와 뮤테이션의 소프트 메모리 제한을 나타내는 `merges_mutations_memory_usage_soft_limit` 및 `merges_mutations_memory_usage_to_ram_ratio` 설정을 도입했습니다. 이 제한에 도달하면 ClickHouse는 새로운 머지 또는 뮤테이션 작업을 스케줄하지 않습니다. 또한 백그라운드 작업의 현재 메모리 사용량을 관찰할 수 있도록 `MergesMutationsMemoryTracking` 메트릭을 도입했습니다. [#45710](https://github.com/ClickHouse/ClickHouse/issues/45710)을 종료합니다. [#46089](https://github.com/ClickHouse/ClickHouse/pull/46089) ([Dmitry Novik](https://github.com/novikd)).
* Spark의 [approx&#95;percentile](https://spark.apache.org/docs/latest/api/sql/index.html#approx_percentile)과 유사한 새로운 집계 함수 `quantileGK`/`quantilesGK`를 지원합니다. Greenwald-Khanna 알고리즘은 [http://infolab.stanford.edu/~datar/courses/cs361a/papers/quantiles.pdf](http://infolab.stanford.edu/~datar/courses/cs361a/papers/quantiles.pdf)를 참조하십시오. [#46428](https://github.com/ClickHouse/ClickHouse/pull/46428) ([李扬](https://github.com/taiyang-li)).
* `system.columns`에서 정제된 정보를 보여주는 `SHOW COLUMNS` 구문을 추가했습니다. [#48017](https://github.com/ClickHouse/ClickHouse/pull/48017) ([Robert Schulze](https://github.com/rschu1ze)).
* `SYSTEM SYNC REPLICA` 쿼리에 `LIGHTWEIGHT` 및 `PULL` 수정자를 추가했습니다. `LIGHTWEIGHT` 버전은 fetches와 drop-ranges만 기다리며(merges와 mutations는 무시), `PULL` 버전은 ZooKeeper에서 새 entries를 가져오고 이를 기다리지 않습니다. [#47794](https://github.com/ClickHouse/ClickHouse/issues/47794)를 수정했습니다. [#48085](https://github.com/ClickHouse/ClickHouse/pull/48085) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Kafka DefaultPartitioner와의 호환성을 위해 kafkaMurmurHash 함수를 추가했습니다. [#47834](https://github.com/ClickHouse/ClickHouse/issues/47834)를 종료합니다. [#48185](https://github.com/ClickHouse/ClickHouse/pull/48185) ([Nikolay Degterinsky](https://github.com/evillique)).
* `GRANT CURRENT GRANTS`를 사용해 현재 사용자와 동일한 권한 부여를 가진 사용자를 쉽게 생성할 수 있도록 했습니다. [#48262](https://github.com/ClickHouse/ClickHouse/pull/48262) ([pufit](https://github.com/pufit)).
* 통계 집계 함수 `kolmogorovSmirnovTest`를 추가했습니다. [#48228](https://github.com/ClickHouse/ClickHouse/issues/48228)을 종료합니다. [#48325](https://github.com/ClickHouse/ClickHouse/pull/48325) ([FFFFFFFHHHHHHH](https://github.com/FFFFFFFHHHHHHH)).
* `system.replicas` 테이블에 `lost_part_count` 컬럼을 추가했습니다. 이 컬럼 값은 해당 테이블의 손실된 파트 총개수를 보여줍니다. 값은 ZooKeeper에 저장되며, 모니터링을 위해 비영속적인 `ReplicatedDataLoss` profile event 대신 사용할 수 있습니다. [#48526](https://github.com/ClickHouse/ClickHouse/pull/48526) ([Sergei Trifonov](https://github.com/serxa)).
* soundex 함수를 추가했습니다. [#39880](https://github.com/ClickHouse/ClickHouse/issues/39880)를 종료합니다. [#48567](https://github.com/ClickHouse/ClickHouse/pull/48567) ([FriendLey](https://github.com/FriendLey)).
* JSONExtract에서 맵(Map) 타입을 지원하도록 했습니다. [#48629](https://github.com/ClickHouse/ClickHouse/pull/48629) ([李扬](https://github.com/taiyang-li)).
* 줄바꿈 구분자와 4칸 들여쓰기를 사용해 보기 좋게 JSON을 출력하는 PrettyJSONEachRow 포맷을 추가했습니다. [#48898](https://github.com/ClickHouse/ClickHouse/pull/48898) ([Kruglov Pavel](https://github.com/Avogar)).
* Parquet 파일 메타데이터를 읽는 ParquetMetadata 입력 형식을 추가했습니다. [#48911](https://github.com/ClickHouse/ClickHouse/pull/48911) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 이제 Parquet 포맷 파일 읽기 속도가 훨씬 빨라졌습니다. IO와 디코딩이 병렬화되었으며(`max_threads` 설정으로 제어), 필요한 데이터 범위만 읽습니다. [#47964](https://github.com/ClickHouse/ClickHouse/pull/47964) ([Michael Kolupaev](https://github.com/al13n321)).
* 이제 `ALTER TABLE` 쿼리를 적용할 때 필요한 경우에만 의존성을 확인합니다. [#48062](https://github.com/ClickHouse/ClickHouse/pull/48062) ([Raúl Marín](https://github.com/Algunenano)).
* `mapUpdate` 함수를 최적화했습니다. [#48118](https://github.com/ClickHouse/ClickHouse/pull/48118) ([Anton Popov](https://github.com/CurtizJ)).
* 이제 로컬 레플리카로 보내는 내부 쿼리를 명시적으로 전송하며, 해당 데이터는 루프백 인터페이스를 통해 수신합니다. `prefer_localhost_replica` 설정은 병렬 레플리카에서는 적용되지 않습니다. 이는 더 나은 스케줄링을 위해 필요하며, 코드도 더 단순해집니다. initiator는 읽기 프로세스 조정과 결과 병합만 담당하고, 모든 secondary 쿼리가 데이터를 읽는 동안 요청에 계속 응답합니다. 참고: 루프백 인터페이스 사용은 성능 측면에서 아주 유리하지는 않지만, 이를 사용하지 않으면 일부 레플리카에 작업이 할당되지 않아 쿼리 실행이 오히려 더 느려지고 사용 가능한 리소스를 충분히 활용하지 못할 수 있습니다. 또한 coordinator 초기화는 더욱 지연 실행되도록 변경되었습니다. 들어오는 모든 요청에는 읽기 알고리즘 정보가 포함되며, 첫 번째 요청이 도착하면 그 정보를 사용해 coordinator를 초기화합니다. 어떤 레플리카든 다른 알고리즘으로 읽기를 결정하면 예외가 발생하고 쿼리가 중단됩니다. [#48246](https://github.com/ClickHouse/ClickHouse/pull/48246) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 스킵 인덱스 분석에만 사용되고 해당 인덱스가 설정(`use_skip_indexes=0`)으로 비활성화된 경우에는, 서브쿼리가 있는 `IN` 절 오른쪽에 대해 Set을 빌드하지 않습니다. 이전에는 이로 인해 쿼리 성능이 영향을 받을 수 있었습니다. [#48299](https://github.com/ClickHouse/ClickHouse/pull/48299) ([Anton Popov](https://github.com/CurtizJ)).
* `FROM file(...)`에서 읽은 직후부터 쿼리 처리가 병렬화됩니다. [#38755](https://github.com/ClickHouse/ClickHouse/issues/38755)와 관련이 있습니다. [#48525](https://github.com/ClickHouse/ClickHouse/pull/48525) ([Igor Nikonov](https://github.com/devcrafter)).
* 데이터 소스에서 읽은 직후부터 쿼리 처리가 병렬화됩니다. 영향을 받는 데이터 소스는 주로 테이블 함수 `url`, `file`과 같은 단순한 소스나 외부 스토리지입니다. [#48727](https://github.com/ClickHouse/ClickHouse/pull/48727) ([Igor Nikonov](https://github.com/devcrafter)).
* `numebers_mt()`에서 Counter에 올바른 메모리 순서를 사용하도록 수정했습니다. [#48729](https://github.com/ClickHouse/ClickHouse/pull/48729) ([Igor Nikonov](https://github.com/devcrafter)).
* ThreadPool 뮤텍스의 경합을 줄였습니다(매우 많은 수의 작은 job에서 성능이 향상될 수 있습니다). [#48750](https://github.com/ClickHouse/ClickHouse/pull/48750) ([Sergei Trifonov](https://github.com/serxa)).
* 프리페치된 읽기 풀에서 그래뉼의 대략적인 크기를 계산하는 방식을 단순화했습니다. [#49051](https://github.com/ClickHouse/ClickHouse/pull/49051) ([Nikita Taranov](https://github.com/nickitat)).

<div id="improvement">
  #### 개선 사항
</div>

* `zookeeper`의 대안으로 구성 섹션 `keeper`/`keeper_server`를 지원합니다. [#34766](https://github.com/ClickHouse/ClickHouse/issues/34766), [#34767](https://github.com/ClickHouse/ClickHouse/issues/34767)을 종료합니다. [#35113](https://github.com/ClickHouse/ClickHouse/pull/35113) ([李扬](https://github.com/taiyang-li)).
* ClickHouse 애플리케이션의 도움말에서 여러 문제가 수정되었습니다. 이제 모든 도구에서 도움말이 stdout으로 출력됩니다. `clickhouse help` 호출의 status code는 이제 0입니다. `clickhouse-local`, `clickhouse-benchmark`, `clickhouse-client`, `clickhouse hash`, `clickhouse su`, `clickhouse-install`의 도움말도 업데이트되었습니다. [#45819](https://github.com/ClickHouse/ClickHouse/pull/45819) ([Ilya Yatsishin](https://github.com/qoega)).
* 쿼리 캐시의 엔트리는 이제 max&#95;block&#95;size에 맞게 병합되며 압축됩니다. [#45912](https://github.com/ClickHouse/ClickHouse/pull/45912) ([Robert Schulze](https://github.com/rschu1ze)).
* ClickHouse table 소스를 사용하는 딕셔너리에 대해 named&#95;collections에서 *secure* flag를 설정할 수 있습니다. [#38450](https://github.com/ClickHouse/ClickHouse/issues/38450)을 해결합니다. [#46323](https://github.com/ClickHouse/ClickHouse/pull/46323) ([Ilya Golshtein](https://github.com/ilejn)).
* 이제 replaceOne(), replaceAll(), replaceRegexpOne(), replaceRegexpAll() 함수는 non-const pattern 및 대체 인수로 호출할 수 있습니다. [#46589](https://github.com/ClickHouse/ClickHouse/pull/46589) ([Robert Schulze](https://github.com/rschu1ze)).
* 내부 ZSTD를 1.5.4에서 1.5.5로 올렸습니다. [#46797](https://github.com/ClickHouse/ClickHouse/pull/46797) ([Robert Schulze](https://github.com/rschu1ze)).
* `ALTER TABLE t UPDATE col='new value' WHERE id IN (SELECT id FROM huge_table)`와 같이 IN (subquery)를 사용하는 mutation을 실행할 때 테이블 `t`에 여러 파트가 있으면, 각 파트마다 subquery `SELECT id FROM huge_table`용 Set이 메모리에 생성됩니다. 파트가 많으면 메모리와 CPU를 많이 소모해 OOM이 발생할 수 있습니다. 이를 해결하기 위해 현재 mutation 작업이 생성 중인 Set을 위한 수명이 짧은 캐시를 도입했습니다. 동일한 mutation의 다른 작업이 동시에 실행되면 캐시에서 Set을 lookup하고, 생성이 완료될 때까지 기다린 뒤 재사용할 수 있습니다. [#46835](https://github.com/ClickHouse/ClickHouse/pull/46835) ([Alexander Gololobov](https://github.com/davenger)).
* Backup 쿼리에 대해 [Zoo]Keeper와의 모든 작업에 구성 가능한 retries를 추가했습니다. [#47224](https://github.com/ClickHouse/ClickHouse/pull/47224) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* socket에 대한 비동기 connection과 비동기 쓰기를 추가했습니다. 세그먼트 전반에서 연결 생성과 쿼리/external tables 전송을 비동기로 처리합니다. fibers를 사용해 코드를 리팩터링했습니다. [#46931](https://github.com/ClickHouse/ClickHouse/issues/46931)을 종료합니다. 이 PR 이후에는 기본적으로 `connect_timeout_with_failover_ms`를 늘릴 수 있게 됩니다([https://github.com/ClickHouse/ClickHouse/issues/5188](https://github.com/ClickHouse/ClickHouse/issues/5188)). [#47229](https://github.com/ClickHouse/ClickHouse/pull/47229) ([Kruglov Pavel](https://github.com/Avogar)).
* 이제 formatDateTime() 함수의 Formatter &#39;%M&#39;은 분이 아니라 월 이름을 출력합니다. 이에 따라 동작이 MySQL과 일관되게 되었습니다. 이전 동작은 setting &quot;formatdatetime&#95;parsedatetime&#95;m&#95;is&#95;month&#95;name = 0&quot;을 사용해 복원할 수 있습니다. [#47246](https://github.com/ClickHouse/ClickHouse/pull/47246) ([Robert Schulze](https://github.com/rschu1ze)).
* 데이터 레이크 관련 개선 사항 여러 가지: - StorageIceberg가 파티션되지 않은 데이터에서도 동작하도록 개선했습니다. - Iceberg 포맷 버전 V2를 지원합니다(이전에는 V1만 지원). - DeltaLake/Hudi의 파티션된 데이터 읽기를 지원합니다. - Delta의 checkpoint 파일을 사용해 DeltaLake 메타데이터를 더 빠르게 읽을 수 있도록 했습니다. - 잘못된 Hudi 읽기를 수정했습니다. 이전에는 읽을 데이터를 잘못 선택해 작은 테이블만 올바르게 읽을 수 있었습니다. - 이들 엔진이 변경된 데이터의 업데이트를 반영하도록 했습니다(이전에는 state가 테이블 생성 시 설정되었습니다). - spark를 사용해 Iceberg/DeltaLake/Hudi를 올바르게 테스트하도록 했습니다. [#47307](https://github.com/ClickHouse/ClickHouse/pull/47307) ([Kseniia Sumarokova](https://github.com/kssenii)).
* S3에서 `use_environment_credentials`를 기본값으로 활성화하여 provider 체인 전체가 기본적으로 구성되도록 했습니다. [#47397](https://github.com/ClickHouse/ClickHouse/pull/47397) ([Antonio Andelic](https://github.com/antonio2368)).
* 현재 JSON&#95;VALUE 함수는 spark의 get&#95;json&#95;object 함수와 유사하며, &#39;$.key&#39; 같은 경로를 사용해 JSON string에서 값을 가져올 수 있습니다. 다만 몇 가지 차이가 있습니다. - 1. spark의 get&#95;json&#95;object는 경로가 존재하지 않으면 null을 반환하지만, JSON&#95;VALUE는 빈 문자열을 반환합니다. - 2. spark의 get&#95;json&#95;object는 JSON object/배열 값 같은 복합 타입 값을 반환하지만, JSON&#95;VALUE는 빈 문자열을 반환합니다. [#47494](https://github.com/ClickHouse/ClickHouse/pull/47494) ([KevinyhZou](https://github.com/KevinyhZou)).
* 새 분석기에 CNF/constraint optimizer를 추가했습니다. [#47617](https://github.com/ClickHouse/ClickHouse/pull/47617) ([Antonio Andelic](https://github.com/antonio2368)).
* use&#95;structure&#95;from&#95;insertion&#95;table&#95;in&#95;table&#95;functions에 대해 삽입 테이블 구조가 테이블 함수로 더 유연하게 전파되도록 했습니다. 이름 매핑 및 virtual columns 사용 관련 버그를 수정했습니다. 더 이상 &#39;auto&#39; 설정이 필요하지 않습니다. [#47962](https://github.com/ClickHouse/ClickHouse/pull/47962) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* 쿼리가 killed 상태이거나 제한을 초과한 경우 ZK 연결 재시도를 계속하지 않도록 했습니다. [#47985](https://github.com/ClickHouse/ClickHouse/pull/47985) ([Raúl Marín](https://github.com/Algunenano)).
* `Map` 타입 컬럼을 처리하는 함수 `mapConcat`, `mapSort`, `mapExists`를 추가했습니다. [#48071](https://github.com/ClickHouse/ClickHouse/pull/48071) ([Anton Popov](https://github.com/CurtizJ)).
* BSONEachRow에서 Enum 출력/입력을 지원하고, 모든 맵 key 타입을 허용하며, 출력 시 불필요한 추가 계산을 피하도록 했습니다. [#48122](https://github.com/ClickHouse/ClickHouse/pull/48122) ([Kruglov Pavel](https://github.com/Avogar)).
* ORC/Arrow/Parquet 포맷에서 더 많은 ClickHouse 타입을 지원합니다: Enum(8|16), (U)Int(128|256), Decimal256(ORC용), Int32 값에서 IPv4 읽기를 허용하며(ORC는 IPv4를 Int32로 출력하므로 이전에는 이를 다시 읽을 수 없었습니다), ORC에서 바이너리 데이터로부터 Nullable(IPv6)를 읽는 문제를 수정했습니다.
