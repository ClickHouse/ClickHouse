<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 함수 `yandexConsistentHash`(Konstantin &quot;kostik&quot; Oblakov의 consistent hash 알고리즘)의 이름이 `kostikConsistentHash`로 변경되었습니다. 이전 이름은 호환성을 위해 별칭으로 유지됩니다. 이 변경 사항은 하위 호환되지만, 이후 릴리스에서 이 별칭이 제거될 수 있으므로 앱에서 이 함수를 사용하는 부분을 업데이트할 것을 권장합니다. [#35553](https://github.com/ClickHouse/ClickHouse/pull/35553) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* INSERT 쿼리에서 FORMAT 뒤에 SETTINGS를 허용하지 않습니다(이러한 쿼리를 허용하는 호환성 설정 `allow_settings_after_format_in_insert`가 있지만 기본적으로 OFF입니다). [#35883](https://github.com/ClickHouse/ClickHouse/pull/35883) ([Azat Khuzhin](https://github.com/azat)).
* cache 파일의 해시된 경로가 변경되었습니다. [#36079](https://github.com/ClickHouse/ClickHouse/pull/36079) ([Kseniia Sumarokova](https://github.com/kssenii)).

[#34021](https://github.com/ClickHouse/ClickHouse/issues/34021)을 해결합니다. mode `read_from_filesystem_cache_if_exists_otherwise_bypass_cache`를 추가하여 머지용 캐시 옵션을 추가합니다(기본적으로 머지에 대해 활성화되며, 동일한 이름의 쿼리 설정으로도 활성화할 수 있습니다). 캐시 관련 설정 이름이 변경되었습니다 (`remote_fs_enable_cache -> enable_filesystem_cache` 등). [#35690](https://github.com/ClickHouse/ClickHouse/pull/35690) ([Anton Popov](https://github.com/CurtizJ)).
* 삽입 쿼리 중 기록되는 바이트 수를 제한하기 위해 새로운 quota 유형 `WRITTEN BYTES`를 지원합니다. [#35736](https://github.com/ClickHouse/ClickHouse/pull/35736) ([Anton Popov](https://github.com/CurtizJ)).

* setting throw&#95;if&#95;no&#95;data&#95;to&#95;insert를 추가했습니다. [#36336](https://github.com/ClickHouse/ClickHouse/issues/36336)을 닫습니다. [#36345](https://github.com/ClickHouse/ClickHouse/pull/36345) ([flynn](https://github.com/ucasfl)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* clickhouse-server의 시작 속도를 높이기 위해 MergeTree의 파트 로딩 과정을 가속화했습니다. 이 개선으로 70만 개의 MergeTree 파트가 있는 경우 clickhouse-server의 시작 시간을 75분에서 20초로 줄일 수 있었습니다. [#32928](https://github.com/ClickHouse/ClickHouse/pull/32928) ([李扬](https://github.com/taiyang-li)).
* 집계 중 사용되는 해시 테이블의 크기 정보를 이제 수집해 이후 쿼리에서 활용함으로써 해시 테이블 리사이즈를 방지합니다. [#33439](https://github.com/ClickHouse/ClickHouse/pull/33439) ([Nikita Taranov](https://github.com/nickitat)).
* ASOF JOIN 성능을 개선하기 위한 여러 변경 사항이 적용되었습니다(1.2~1.6배 빨라짐). 또한 큰 정수도 지원합니다. [#34733](https://github.com/ClickHouse/ClickHouse/pull/34733) ([Raúl Marín](https://github.com/Algunenano)).
* 이제 URL 스토리지 엔진은 endpoint가 HTTP Range를 지원하면 여러 청크를 병렬로 다운로드합니다. 또한 `max_download_threads` 및 `max_download_buffer_size`라는 두 가지 설정이 추가되었으며, 이는 단일 쿼리가 파일 다운로드에 사용할 수 있는 최대 스레드 수와 각 스레드가 처리할 수 있는 최대 바이트 수를 제어합니다. [#35150](https://github.com/ClickHouse/ClickHouse/pull/35150) ([Antonio Andelic](https://github.com/antonio2368)).
* S3 스토리지에 대한 멀티파트 업로드 병렬화. [#35343](https://github.com/ClickHouse/ClickHouse/pull/35343) ([Sergei Trifonov](https://github.com/serxa)).
* 키가 네이티브 정수인 경우 ASOF JOIN의 성능을 개선했습니다. [#35525](https://github.com/ClickHouse/ClickHouse/pull/35525) ([Maksim Kita](https://github.com/kitaisreal)).
* 새로운 쿼리 계획 최적화입니다. 가능하면 `ORDER BY` 이후에 함수를 계산합니다. 예를 들어, 쿼리 `SELECT sipHash64(number) FROM numbers(1e8) ORDER BY number LIMIT 5`의 경우 함수 `sipHash64`는 `ORDER BY` 및 `LIMIT` 이후에 계산되므로 약 20배의 속도 향상을 얻을 수 있습니다. [#35623](https://github.com/ClickHouse/ClickHouse/pull/35623) ([Nikita Taranov](https://github.com/nickitat)).
* setenv LIBHDFS3&#95;CONF 관련 이슈 [#35292](https://github.com/ClickHouse/ClickHouse/issues/35292)에서 뮤텍스 범위를 축소했습니다. [#35646](https://github.com/ClickHouse/ClickHouse/pull/35646) ([shuchaome](https://github.com/shuchaome)).
* SSE 및 AVX2용 특수화를 사용해 `hasAll` 함수의 성능을 개선했습니다. 작성자: @youennL-cs. [#35723](https://github.com/ClickHouse/ClickHouse/pull/35723) ([Maksim Kita](https://github.com/kitaisreal)).
* * 두 개의 분산 테이블에 대한 GLOBAL JOIN의 EXPLAIN statement를 최대 100배 빠르게 수행할 수 있습니다: explain plan select ... from t1&#95;dist global join t2&#95;dist on ... explain pipeline select ... from t1&#95;dist global join t2&#95;dist on ... [#36055](https://github.com/ClickHouse/ClickHouse/pull/36055) ([何李夫](https://github.com/helifu)).
* 2가지 최적화: - 사소한 hive count 쿼리 최적화 - hive 파일의 metadata를 캐시해 hive 쿼리 속도 향상. [#36082](https://github.com/ClickHouse/ClickHouse/pull/36082) ([李扬](https://github.com/taiyang-li)).
