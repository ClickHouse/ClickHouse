  ### ClickHouse 릴리스 v23.9.1.1854-stable (8f9a227de1f) FIXME, v23.8.1.2992-lts (ebc7d9a9f3b)와 비교

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 기본 Prometheus handler에서 `status_info` 구성 옵션과 dictionaries status를 제거했습니다. [#54090](https://github.com/ClickHouse/ClickHouse/pull/54090) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 실험적 파트 metadata cache가 codebase에서 제거되었습니다. [#54215](https://github.com/ClickHouse/ClickHouse/pull/54215) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `input_format_json_try_infer_numbers_from_strings` 설정이 기본적으로 비활성화되었습니다. 이에 따라 샘플 데이터에 숫자처럼 보이는 문자열이 포함되어 있을 때 발생할 수 있는 parsing error를 방지하기 위해, 기본적으로 JSON 포맷에서 문자열로부터 숫자를 infer하지 않습니다. [#55099](https://github.com/ClickHouse/ClickHouse/pull/55099) ([Kruglov Pavel](https://github.com/Avogar)).
* 2023년 3월 이전에 생성된 IPv6 블룸 필터 인덱스는 현재 버전과 호환되지 않으므로 다시 빌드해야 합니다. [#54200](https://github.com/ClickHouse/ClickHouse/pull/54200) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).



<div id="new-feature">
  #### 새 기능
</div>

* SSH key 기반의 새로운 인증 유형을 추가했습니다. 이는 Native TCP protocol에서만 작동합니다. [#41109](https://github.com/ClickHouse/ClickHouse/pull/41109) ([George Gamezardashvili](https://github.com/InfJoker)).
* 원격 디스크에 대한 IO scheduling 지원을 추가했습니다. 이제 디스크 유형 `s3`, `s3_plain`, `hdfs`, `azure_blob_storage`용 Storage configuration에 리소스 이름을 담는 `read_resource` 및 `write_resource` 요소를 포함할 수 있습니다. 이러한 리소스에 대한 scheduling policies는 별도의 서버 구성 섹션 `resources`에서 설정할 수 있습니다. 다양한 리소스 scheduling 목표를 달성할 수 있도록 setting `workload`를 사용해 쿼리를 표시하고, 서버 구성 섹션 `workload_classifiers`를 사용해 분류할 수 있습니다. 자세한 내용은 docs/en/operations/workload-scheduling.md를 참조하십시오. [#47009](https://github.com/ClickHouse/ClickHouse/pull/47009) ([Sergei Trifonov](https://github.com/serxa)).
* 새로운 컬럼 &#95;block&#95;number를 추가하여 [#44532](https://github.com/ClickHouse/ClickHouse/issues/44532)를 해결했습니다. [#47532](https://github.com/ClickHouse/ClickHouse/pull/47532) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* 쿼리 실행 중 출력 테이블의 부분 결과 업데이트를 실시간으로 표시할 수 있도록 `partial_result_update_duration_ms` 및 `max_rows_in_partial_result` 옵션을 추가했습니다. [#48607](https://github.com/ClickHouse/ClickHouse/pull/48607) ([Alexey Perevyshin](https://github.com/alexX512)).
* RegExpTree Dictionaries에서 대소문자를 구분하지 않는 일치 모드와 dot-all 일치 모드를 지원합니다. [#50906](https://github.com/ClickHouse/ClickHouse/pull/50906) ([Johann Gan](https://github.com/johanngan)).
* `ALTER TABLE MODIFY COMMENT` 지원을 추가했습니다. 참고: 오래전에 외부 기여자가 유사한 기능을 추가한 적이 있었지만, 해당 기능은 전혀 작동하지 않았고 사용자에게 혼란만 주었습니다. 이 변경으로 [#36377](https://github.com/ClickHouse/ClickHouse/issues/36377)가 해결됩니다. [#51304](https://github.com/ClickHouse/ClickHouse/pull/51304) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 새로운 데이터 압축 코덱으로 &quot;GCD&quot;, 즉 &quot;greatest common denominator&quot;를 추가했습니다. 이 코덱은 모든 컬럼 값의 GCD를 계산한 다음 각 값을 해당 GCD로 나눕니다. GCD 코덱은 데이터 준비 코덱(Delta 및 DoubleDelta와 유사)이며 단독으로는 사용할 수 없습니다. 이 코덱은 정수, Decimal, 날짜/시간 유형 데이터에서 작동합니다. GCD 코덱의 유용한 사용 사례는 컬럼 값이 GCD의 배수만큼 변하는(증가 또는 감소하는) 경우입니다. 예: 24 - 28 - 16 - 24 - 8 - 24 (GCD = 4라고 가정). [#53149](https://github.com/ClickHouse/ClickHouse/pull/53149) ([Alexander Nam](https://github.com/seshWCS)).
* 두 개의 새로운 type alias인 &quot;DECIMAL(P)&quot;(&quot;DECIMAL(P, 0&quot;의 축약형) 및 &quot;DECIMAL&quot;(&quot;DECIMAL(10, 0)&quot;의 축약형)을 추가했습니다. 이로써 ClickHouse가 MySQL의 SQL 방언과 더 호환되게 되었습니다. [#53328](https://github.com/ClickHouse/ClickHouse/pull/53328) ([Val Doroshchuk](https://github.com/valbok)).
* 모든 `BACKUP` 및 `RESTORE` 작업을 추적하기 위한 새로운 system log table `backup_log`를 추가했습니다. [#53638](https://github.com/ClickHouse/ClickHouse/pull/53638) ([Victor Krasnov](https://github.com/sirvickr)).
* 포맷 setting &quot;output&#95;format&#95;markdown&#95;escape&#95;special&#95;characters&quot;를 추가했습니다(기본값: false). 이 setting은 &quot;Markdown&quot; 출력 형식에서 &quot;!&quot;, &quot;#&quot;, &quot;$&quot; 등의 특수 문자를 이스케이프할지(즉, 앞에 백슬래시를 붙일지) 여부를 제어합니다. [#53860](https://github.com/ClickHouse/ClickHouse/pull/53860) ([irenjj](https://github.com/irenjj)).
* 함수 `decodeHTMLComponent`를 추가했습니다. [#54097](https://github.com/ClickHouse/ClickHouse/pull/54097) ([Bharat Nallan](https://github.com/bharatnc)).
* query&#95;log 테이블에 peak&#95;threads&#95;usage를 추가했습니다. [#54335](https://github.com/ClickHouse/ClickHouse/pull/54335) ([Alexey Gerasimchuck](https://github.com/Demilivor)).
* clickhouse-client에 SHOW FUNCTIONS 지원을 추가했습니다. [#54337](https://github.com/ClickHouse/ClickHouse/pull/54337) ([Julia Kartseva](https://github.com/wat-ze-hex)).
* 이 PR은 JSON 포맷의 스키마 추론을 개선합니다. 1) 이제 JSON 포맷에서 설정 `input_format_json_try_infer_named_tuples_from_objects`를 사용하면 실험적 JSON 타입 없이도 JSON 객체로부터 이름이 지정된 Tuple을 추론할 수 있습니다. 이전에는 실험적 JSON 타입 없이 JSON 객체를 String 또는 Map으로만 추론할 수 있었지만, 이제는 named Tuple도 추론할 수 있습니다. 생성되는 Tuple 타입에는 스키마 추론 중 데이터 샘플에서 읽은 객체의 모든 키가 포함됩니다. 이는 희소 객체가 없는 구조화된 JSON 데이터를 읽을 때 유용할 수 있습니다. 이 설정은 기본적으로 활성화되어 있습니다. 2) 설정 `input_format_json_read_arrays_as_strings`를 사용하면 JSON 배열을 String 타입 컬럼으로 파싱할 수 있습니다. 이는 서로 다른 타입의 값을 포함하는 배열을 읽는 데 도움이 될 수 있습니다. 3) 설정 `input_format_json_infer_incomplete_types_as_strings`를 사용하면 샘플 데이터에서 타입을 알 수 없는 JSON 키(`null`/`[]`/`{}`)에 대해 String 타입을 사용할 수 있습니다. 이제 JSON 포맷에서는 어떤 값이든 String 컬럼으로 읽을 수 있으며, 알 수 없는 타입에 String 타입을 사용해 스키마 추론 중 `Cannot determine type for column 'column_name' by first 25000 rows of data, most likely this column contains only Nulls or empty Arrays/Maps` 오류를 피할 수 있으므로 데이터를 성공적으로 읽을 수 있습니다. [#54427](https://github.com/ClickHouse/ClickHouse/pull/54427) ([Kruglov Pavel](https://github.com/Avogar)).
* 0001-01-01 이후 경과한 일 수를 반환하는 함수 &quot;toDaysSinceYearZero&quot;와 그 별칭 &quot;TO&#95;DAYS()&quot;(MySQL 호환용)을 추가했습니다. [#54479](https://github.com/ClickHouse/ClickHouse/pull/54479) ([Robert Schulze](https://github.com/rschu1ze)).
* YYYYMMDDtoDate(), YYYYMMDDtoDate32(), YYYYMMDDhhmmssToDateTime(), YYYYMMDDhhmmssToDateTime64() 함수를 추가했습니다. 이 함수들은 정수로 인코딩된 date 또는 date with time(예: 20230911)을 네이티브 date 또는 date with time으로 변환합니다. 따라서 기존 함수 YYYYMMDDToDate(), YYYYMMDDToDateTime(), YYYYMMDDhhmmddToDateTime(), YYYYMMDDhhmmddToDateTime64()와 반대되는 기능을 제공합니다. [#54509](https://github.com/ClickHouse/ClickHouse/pull/54509) ([Robert Schulze](https://github.com/rschu1ze)).
* &quot;bandwidth&#95;limit&quot; IO 스케줄링 노드 유형을 추가했습니다. 이 유형을 사용하면 이 노드를 통과하는 트래픽에 `max_speed` 및 `max_burst` 제약을 지정할 수 있습니다. 자세한 내용은 docs/en/operations/workload-scheduling.md를 참조하십시오. [#54618](https://github.com/ClickHouse/ClickHouse/pull/54618) ([Sergei Trifonov](https://github.com/serxa)).
* 이제 함수 `toDaysSinceYearZero()`가 `DateTime` 및 `DateTime64` 타입 인수를 지원합니다. [#54856](https://github.com/ClickHouse/ClickHouse/pull/54856) ([Serge Klochkov](https://github.com/slvrtrn)).
* 테이블 함수 `s3`, `gcs`, `oss`에서 S3 스타일 URL을 허용합니다. URL은 자동으로 HTTP로 변환됩니다. 예시: `'s3://clickhouse-public-datasets/hits.csv'`는 `'https://clickhouse-public-datasets.s3.amazonaws.com/hits.csv'`로 변환됩니다. [#54931](https://github.com/ClickHouse/ClickHouse/pull/54931) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 여러 문자열 거리 함수를 추가했습니다. `byteHammingDistance`, `byteJaccardIndex`, `byteEditDistance`가 포함됩니다. ### 사용자 대상 변경 사항에 대한 문서 항목입니다. [#54935](https://github.com/ClickHouse/ClickHouse/pull/54935) ([flynn](https://github.com/ucasfl)).
* Tuple/맵/배열처럼 깊이 중첩된 타입 이름을 읽기 쉽게 출력하는 새로운 설정 `print_pretty_type_names`를 추가했습니다. [#55095](https://github.com/ClickHouse/ClickHouse/pull/55095) ([Kruglov Pavel](https://github.com/Avogar)).



<div id="performance-improvement">
  #### 성능 개선
</div>

* Decimal 컬럼 정렬 성능을 개선했습니다. ORDER BY에 Decimal 컬럼이 포함된 경우 MergeTree에 대한 삽입 성능을 개선했습니다. 데이터가 이미 정렬되어 있거나 거의 정렬된 경우의 정렬 성능도 개선했습니다. [#35961](https://github.com/ClickHouse/ClickHouse/pull/35961) ([Maksim Kita](https://github.com/kitaisreal)).
* 대규모 쿼리 분석 성능을 개선했습니다. [#51224](https://github.com/ClickHouse/ClickHouse/issues/51224)를 수정합니다. [#51469](https://github.com/ClickHouse/ClickHouse/pull/51469) ([frinkr](https://github.com/frinkr)).
* 1. 새로운 분석기를 위한 재작성기를 추가했습니다. [#52082](https://github.com/ClickHouse/ClickHouse/pull/52082) ([JackyWoo](https://github.com/JackyWoo)).
* 1. 기존 분석기와 새로운 분석기 모두를 위한 재작성기를 추가했습니다. 2. `optimize_uniq_to_count` 설정을 추가했습니다. [#52645](https://github.com/ClickHouse/ClickHouse/pull/52645) ([JackyWoo](https://github.com/JackyWoo)).
* `mmap/mremap/munmap`에 대한 수동 호출을 제거하고, 이 작업을 모두 `jemalloc`에 맡기도록 했습니다. [#52792](https://github.com/ClickHouse/ClickHouse/pull/52792) ([Nikita Taranov](https://github.com/nickitat)).
* 이제 roaringBitmaps는 직렬화 전에 최적화됩니다. [#52842](https://github.com/ClickHouse/ClickHouse/pull/52842) ([UnamedRus](https://github.com/UnamedRus)).
* 상수 키에 대한 GROUP BY를 최적화했습니다. https://github.com/ClickHouse/ClickHouse/pull/53529 이후에는 `_file/_path`에 대해 GROUP BY를 사용하는 쿼리도 최적화됩니다. [#53549](https://github.com/ClickHouse/ClickHouse/pull/53549) ([Kruglov Pavel](https://github.com/Avogar)).
* 기본적으로 프리페치를 활성화하여 S3에서의 읽기 속도를 높였습니다. [#53709](https://github.com/ClickHouse/ClickHouse/pull/53709) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 불필요한 경우 단독 파트에서 pk 및 version 컬럼을 암묵적으로 읽지 않도록 했습니다. [#53919](https://github.com/ClickHouse/ClickHouse/pull/53919) ([Duc Canh Le](https://github.com/canhld94)).
* NATS 사용 시 CPU 사용량이 높아지는 문제를 수정했습니다. [#54399](https://github.com/ClickHouse/ClickHouse/pull/54399) ([Vasilev Pyotr](https://github.com/vahpetr)).
* DateTime 인수가 있는 `toString()` 실행에는 별도의 명령어를 사용하므로, DateTime이 아닌 인수에 대해서는 성능을 조금 더 개선하고 코드 일부도 더 깔끔하게 정리할 수 있습니다. [#53680](https://github.com/ClickHouse/ClickHouse/issues/53680)의 후속입니다. [#54443](https://github.com/ClickHouse/ClickHouse/pull/54443) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* json 요소를 `std::stringstream`으로 직렬화하는 대신, 이 PR에서는 직렬화 결과를 직접 `ColumnString`에 저장하도록 개선했습니다. [#54613](https://github.com/ClickHouse/ClickHouse/pull/54613) ([lgbo](https://github.com/lgbo-ustc)).
* 테이블이 뷰 뒤에 있는 경우에도, MergeTree 테이블에서 해당 순서로 데이터를 읽기 위한 ORDER BY 최적화를 활성화했습니다. [#54628](https://github.com/ClickHouse/ClickHouse/pull/54628) ([Vitaly Baranov](https://github.com/vitlibar)).
* `GeneratorJSONPath`를 재사용하여 JSON SQL 함수 성능을 개선했습니다. `GenerateorJSONPath` 생성자에는 여러 개의 `make_shared`가 있어 성능이 좋지 않습니다. [#54735](https://github.com/ClickHouse/ClickHouse/pull/54735) ([lgbo](https://github.com/lgbo-ustc)).

* Integer type inference의 정확도를 높이고 [#51236](https://github.com/ClickHouse/ClickHouse/issues/51236) 문제를 수정했습니다. [#53003](https://github.com/ClickHouse/ClickHouse/pull/53003) ([Chen768959](https://github.com/Chen768959)).
* Keeper가 성능 향상을 위해 요청을 배치로 플러시하려고 시도합니다. [#53049](https://github.com/ClickHouse/ClickHouse/pull/53049) ([Antonio Andelic](https://github.com/antonio2368)).
* MaterializedMySQL의 문자열 리터럴에서 문자 집합을 해석하도록 했습니다. [#53220](https://github.com/ClickHouse/ClickHouse/pull/53220) ([Val Doroshchuk](https://github.com/valbok)).
