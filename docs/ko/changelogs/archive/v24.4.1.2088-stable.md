<div id="2024-changelog">
  # 2024 변경 로그
</div>

<div id="clickhouse-release-v24412088-stable-6d4b31322d1-fixme-as-compared-to-v24312672-lts-2c5c589a882">
  ### ClickHouse 릴리스 v24.4.1.2088-안정 (6d4b31322d1) FIXME v24.3.1.2672-lts (2c5c589a882)와 비교했을 때
</div>

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 의미가 없으므로 max&#95;parallel&#95;replicas를 0으로 설정하는 것은 더 이상 허용되지 않습니다. 이 값을 0으로 설정하면 예기치 않은 논리 오류가 발생할 수 있습니다. [#60140](https://github.com/ClickHouse/ClickHouse/issues/60140)을 해결합니다. [#61201](https://github.com/ClickHouse/ClickHouse/pull/61201) ([Kruglov Pavel](https://github.com/Avogar)).
* `clickhouse-odbc-bridge`와 `clickhouse-library-bridge`는 별도의 패키지입니다. 이 변경으로 [#61677](https://github.com/ClickHouse/ClickHouse/issues/61677)이 해결됩니다. [#62114](https://github.com/ClickHouse/ClickHouse/pull/62114) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* INSERT WATCH 쿼리 지원을 제거합니다(실험적 LIVE VIEW 기능의 일부). [#62382](https://github.com/ClickHouse/ClickHouse/pull/62382) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* optimize&#95;monotonous&#95;functions&#95;in&#95;order&#95;by 설정을 제거합니다. [#63004](https://github.com/ClickHouse/ClickHouse/pull/63004) ([Raúl Marín](https://github.com/Algunenano)).

<div id="new-feature">
  #### 새 기능
</div>

* `drop table a,b,c`처럼 여러 테이블을 동시에 삭제할 수 있습니다. [#58705](https://github.com/ClickHouse/ClickHouse/pull/58705) ([zhongyuankai](https://github.com/zhongyuankai)).
* 이제 테이블 엔진에 권한을 부여할 수 있으며, 기존 사용자의 동작에는 영향을 주지 않습니다. [#60117](https://github.com/ClickHouse/ClickHouse/pull/60117) ([jsc0218](https://github.com/jsc0218)).
* INSERT 작업을 지원하고 로컬에 저장된 메타데이터가 필요 없는, 다시 쓸 수 있는 S3 디스크를 추가했습니다. [#61116](https://github.com/ClickHouse/ClickHouse/pull/61116) ([Julia Kartseva](https://github.com/jkartseva)).
* 편의를 위해 `SELECT * FROM numbers() `도 `SELECT * FROM system.numbers`와 동일하게 limit 없이 동작합니다. [#61969](https://github.com/ClickHouse/ClickHouse/pull/61969) ([YenchangChan](https://github.com/YenchangChan)).
* 이제 `ALTER MODIFY SETTING`을 통해 메모리 테이블 설정을 수정할 수 있습니다. `ALTER TABLE memory MODIFY SETTING min_rows_to_keep = 100, max_rows_to_keep = 1000;`. [#62039](https://github.com/ClickHouse/ClickHouse/pull/62039) ([zhongyuankai](https://github.com/zhongyuankai)).
* 분석기가 재귀 CTE를 지원합니다. [#62074](https://github.com/ClickHouse/ClickHouse/pull/62074) ([Maksim Kita](https://github.com/kitaisreal)).
* 분석기가 QUALIFY 절을 지원합니다. [#47819](https://github.com/ClickHouse/ClickHouse/issues/47819)를 해결합니다. [#62619](https://github.com/ClickHouse/ClickHouse/pull/62619) ([Maksim Kita](https://github.com/kitaisreal)).
* HTTP 인터페이스에 `role` 쿼리 매개변수를 추가했습니다. 이는 `SET ROLE x`와 비슷하게 동작하며, SQL 문이 실행되기 전에 역할을 적용합니다. 이를 통해 여러 SQL 문을 허용하지 않아 `SET ROLE x`와 SQL 문 자체를 동시에 보낼 수 없는 HTTP 인터페이스의 제한을 우회할 수 있습니다. 예를 들어 `?role=x&role=y`처럼 여러 역할을 설정할 수 있으며, 이는 `SET ROLE x, y`와 같습니다. [#62669](https://github.com/ClickHouse/ClickHouse/pull/62669) ([Serge Klochkov](https://github.com/slvrtrn)).
* `SYSTEM UNLOAD PRIMARY KEY`를 추가했습니다. [#62738](https://github.com/ClickHouse/ClickHouse/pull/62738) ([Pablo Marcos](https://github.com/pamarcos)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* SELECT에 대한 뮤테이션 오버헤드를 줄였습니다(v2). [#60856](https://github.com/ClickHouse/ClickHouse/pull/60856) ([Azat Khuzhin](https://github.com/azat)).
* PODArray에서 더 자주 호출되는 함수가 이제 강제 인라인됩니다. [#61144](https://github.com/ClickHouse/ClickHouse/pull/61144) ([李扬](https://github.com/taiyang-li)).
* 동등한 Set을 사용한 JOIN filter push down을 개선했습니다. [#61216](https://github.com/ClickHouse/ClickHouse/pull/61216) ([Maksim Kita](https://github.com/kitaisreal)).
* 빠른 Parquet 인코더(`output_format_parquet_use_custom_encoder`)가 이제 기본적으로 활성화됩니다. [#62088](https://github.com/ClickHouse/ClickHouse/pull/62088) ([Michael Kolupaev](https://github.com/al13n321)).
* ... 필요한 모든 field를 읽은 경우 남아 있는 field를 모두 바로 건너뛰어 비교를 크게 줄일 수 있습니다. [#62210](https://github.com/ClickHouse/ClickHouse/pull/62210) ([lgbo](https://github.com/lgbo-ustc)).
* `splitByChar` 및 `splitByRegexp` 함수의 속도가 크게 향상되었습니다. [#62392](https://github.com/ClickHouse/ClickHouse/pull/62392) ([李扬](https://github.com/taiyang-li)).
* file/s3/hdfs/url/... 테이블 함수에서 파일로부터 수행하는 단순한 insert select를 개선했습니다. 병렬 parsing에 사용되는 스레드 수를 제어하기 위해 별도의 `max_parsing_threads` 설정도 추가했습니다. [#62404](https://github.com/ClickHouse/ClickHouse/pull/62404) ([Kruglov Pavel](https://github.com/Avogar)).
* `azure_allow_parallel_part_upload` 설정으로 제어되는 AzureBlobStorage의 병렬 쓰기 버퍼를 지원합니다. [#62534](https://github.com/ClickHouse/ClickHouse/pull/62534) ([SmitaRKulkarni](https://github.com/SmitaRKulkarni)).
* `to_utc_timestamp` 및 `from_utc_timestamp` 함수가 이제 약 2배 더 빨라졌습니다. [#62583](https://github.com/ClickHouse/ClickHouse/pull/62583) ([KevinyhZou](https://github.com/KevinyhZou)).
* 입력에 parsing할 수 없는 값이 대부분 포함된 경우, `parseDateTimeOrNull`, `parseDateTimeOrZero`, `parseDateTimeInJodaSyntaxOrNull`, `parseDateTimeInJodaSyntaxOrZero` 함수가 이제 훨씬 더 빠르게 실행됩니다(10배~1000배). [#62634](https://github.com/ClickHouse/ClickHouse/pull/62634) ([LiuNeng](https://github.com/liuneng1994)).
* 쿼리 캐시에 entries가 많이 포함된 경우(예: 100,000개 초과), 이제 `system.query_cache`에 대한 SELECT가 눈에 띄게 더 빨라졌습니다. [#62671](https://github.com/ClickHouse/ClickHouse/pull/62671) ([Robert Schulze](https://github.com/rschu1ze)).
* JOIN 이후의 filter가 항상 default value를 걸러내는 경우, 쿼리 계획이 OUTER JOIN을 INNER JOIN으로 변환하는 최적화를 수행합니다. 이 최적화는 `query_plan_convert_outer_join_to_inner_join` 설정으로 제어할 수 있으며 기본적으로 활성화되어 있습니다. [#62907](https://github.com/ClickHouse/ClickHouse/pull/62907) ([Maksim Kita](https://github.com/kitaisreal)).
* `optimize_rewrite_sum_if_to_count_if`가 이제 기본적으로 활성화됩니다. [#62929](https://github.com/ClickHouse/ClickHouse/pull/62929) ([Raúl Marín](https://github.com/Algunenano)).

<div id="improvement">
  #### 개선 사항
</div>

* Kafka 구성에 별도의 consumer/producer 태그를 도입했습니다. 이렇게 하면 producer 인스턴스에 consumer 속성을 지정했거나 그 반대의 경우에 librdkafka에서 발생하던 경고를 방지할 수 있습니다(예: `Configuration property session.timeout.ms is a consumer property and will be ignored by this producer instance`). Closes: [#58983](https://github.com/ClickHouse/ClickHouse/issues/58983). [#58956](https://github.com/ClickHouse/ClickHouse/pull/58956) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* `system.text_log`에 `value1`, `value2`, ..., `value10` 컬럼을 추가했습니다. 이 컬럼에는 메시지 포맷에 사용된 값이 들어 있습니다. [#59619](https://github.com/ClickHouse/ClickHouse/pull/59619) ([Alexey Katsman](https://github.com/alexkats)).
* 함수 `toStartOfInterval(..., INTERVAL ... WEEK)`에서 한 주의 시작일로 간주하는 요일에 영향을 주는 설정 `first_day_of_week`를 추가했습니다. 이를 통해 기본적으로 일요일을 한 주의 시작일로 사용하는 함수 `toStartOfWeek`와의 일관성을 유지할 수 있습니다. [#60598](https://github.com/ClickHouse/ClickHouse/pull/60598) ([Jordi Villar](https://github.com/jrdi)).
* 삽입 시 할당된 block 내 원래 행 번호를 저장하는 영속적 가상 컬럼 `_block_offset`을 추가했습니다. 컬럼 `_block_offset`의 영속성은 설정 `enable_block_offset_column`으로 활성화할 수 있습니다. 파트의 최소 block 번호 또는 mutation 버전을 포함하는 가상 컬럼 `_part_data_version`도 추가했습니다. 영속적 가상 컬럼 `_block_number`는 더 이상 실험적 기능으로 간주되지 않습니다. [#60676](https://github.com/ClickHouse/ClickHouse/pull/60676) ([Anton Popov](https://github.com/CurtizJ)).
* 파일 시스템 캐시의 경합을 줄였습니다(3부): 공간 예약 시도 시 잠금 없이 파일 시스템에서 제거 작업을 수행합니다. [#61163](https://github.com/ClickHouse/ClickHouse/pull/61163) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 함수 `date_diff`와 `age`는 이제 마이크로초 정밀도 대신 나노초 정밀도로 결과를 계산합니다. 또한 `unit` 매개변수에서 사용할 수 있는 값으로 `nanosecond`(또는 `nanoseconds` 또는 `ns`)도 지원합니다. [#61409](https://github.com/ClickHouse/ClickHouse/pull/61409) ([Austin Kothig](https://github.com/kothiga)).
* 이제 머지 중에는 wide 파트의 마크를 로드하지 않습니다. [#61551](https://github.com/ClickHouse/ClickHouse/pull/61551) ([Anton Popov](https://github.com/CurtizJ)).
* 인증서를 다시 로드할 때 인증서 체인도 함께 다시 로드합니다. [#61671](https://github.com/ClickHouse/ClickHouse/pull/61671) ([Pervakov Grigorii](https://github.com/GrigoryPervakov)).
* 파일 시스템 캐시의 동적 크기 조정을 더 빠르게 수행합니다. [#61723](https://github.com/ClickHouse/ClickHouse/pull/61723) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `TRUNCATE ALL TABLES`를 추가했습니다. [#61862](https://github.com/ClickHouse/ClickHouse/pull/61862) ([豪肥肥](https://github.com/HowePa)).
* 해당 레플리카 경로에 활성 레플리카가 있으면 테이블을 ATTACH할 수 없도록 하여 [#60432](https://github.com/ClickHouse/ClickHouse/issues/60432)를 방지하도록 했습니다. [#61876](https://github.com/ClickHouse/ClickHouse/pull/61876) ([Arthur Passos](https://github.com/arthurpassos)).
* 설정 `input_format_json_throw_on_bad_escape_sequence`를 추가했습니다. 이 설정을 비활성화하면 JSON 입력 형식에서 잘못된 이스케이프 시퀀스를 저장할 수 있습니다. [#61889](https://github.com/ClickHouse/ClickHouse/pull/61889) ([Kruglov Pavel](https://github.com/Avogar)).
* 사용자 공간 페이지 캐시가 이제 정적 웹 스토리지(`disk(type = web)`)에서도 작동합니다. 활성화하려면 클라이언트 설정 `use_page_cache_for_disks_without_file_cache=1`을 사용하십시오. [#61911](https://github.com/ClickHouse/ClickHouse/pull/61911) ([Michael Kolupaev](https://github.com/al13n321)).
* clickhouse-local용 `input()`을 구현했습니다. [#61923](https://github.com/ClickHouse/ClickHouse/pull/61923) ([Azat Khuzhin](https://github.com/azat)).
* quorum 삽입 트랜잭션을 되돌릴 때 발생하던 논리 오류를 수정했습니다. [#61953](https://github.com/ClickHouse/ClickHouse/pull/61953) ([Han Fei](https://github.com/hanfei1991)).
* 엄격성 `ANY`를 사용하는 StorageJoin이 다시 로드된 후에도 일관성을 유지합니다. 동일한 key를 가진 여러 행이 삽입되면 첫 번째 행의 우선순위가 가장 높아집니다(이전에는 테이블 로딩 시 무작위로 선택되었습니다). [#51027](https://github.com/ClickHouse/ClickHouse/issues/51027)을 해결했습니다. [#61972](https://github.com/ClickHouse/ClickHouse/pull/61972) ([vdimir](https://github.com/vdimir)).
* Apache Arrow 스키마에서 널 허용 컬럼 타입을 자동으로 추론합니다. [#61984](https://github.com/ClickHouse/ClickHouse/pull/61984) ([Maksim Kita](https://github.com/kitaisreal)).
* 집계 중 aggregate state의 병렬 머지를 취소할 수 있도록 지원합니다. 예시: `uniqExact`. [#61992](https://github.com/ClickHouse/ClickHouse/pull/61992) ([Maksim Kita](https://github.com/kitaisreal)).
* Variant 타입에서 Bool 및 숫자 variant를 의심스러운 것으로 처리하지 않습니다. [#61999](https://github.com/ClickHouse/ClickHouse/pull/61999) ([Kruglov Pavel](https://github.com/Avogar)).
* 제안 항목을 채울 때 `system.keywords`를 사용하고, 내부의 모든 곳에서도 이를 사용하도록 했습니다. [#62000](https://github.com/ClickHouse/ClickHouse/pull/62000) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* parsing을 사용해 String에서 Variant로 변환하는 방식을 개선했습니다. [#62005](https://github.com/ClickHouse/ClickHouse/pull/62005) ([Kruglov Pavel](https://github.com/Avogar)).
* JSONExtract 함수에서 Variant를 지원합니다. [#62014](https://github.com/ClickHouse/ClickHouse/pull/62014) ([Kruglov Pavel](https://github.com/Avogar)).
* `INVALIDATE_QUERY`가 있는 딕셔너리 소스가 시작 시 두 번 다시 로드되지 않도록 했습니다. [#62050](https://github.com/ClickHouse/ClickHouse/pull/62050) ([vdimir](https://github.com/vdimir)).
* 이제 `ReplicatedMergeTree`의 `OPTIMIZE FINAL`은 현재 진행 중인 머지가 끝날 때까지 기다린 다음 final merge 예약을 다시 시도합니다. 이로써 일반적인 `MergeTree` 동작과 더 일치하게 됩니다. [#62067](https://github.com/ClickHouse/ClickHouse/pull/62067) ([Nikita Taranov](https://github.com/nickitat)).
* Hive text file에서 데이터를 읽을 때, 입력 필드 수를 조정하기 위해 파일의 첫 번째 줄을 사용했는데, 이 첫 번째 줄의 필드 수가 정의된 Hive table과 일치하지 않는 경우가 있었습니다. 예를 들어 Hive table이 `test_tbl(a Int32, b Int32, c Int32)`처럼 3개의 컬럼을 갖도록 정의되어 있지만 text file의 첫 번째 줄에는 필드가 2개만 있을 수 있습니다. 이 경우 입력 필드 수가 2개로 조정되고, 다음 줄에 필드가 3개 있더라도 세 번째 필드는 읽히지 않고 기본값 0으로 설정되었는데, 이는 올바르지 않습니다. [#62086](https://github.com/ClickHouse/ClickHouse/pull/62086) ([KevinyhZou](https://github.com/KevinyhZou)).
* CREATE AS가 comment도 복사합니다. [#62117](https://github.com/ClickHouse/ClickHouse/pull/62117) ([Pablo Marcos](https://github.com/pamarcos)).
* 클라이언트에서 입력하는 동안 syntax highlighting이 구문 수준에서 동작하도록 했습니다(이전에는 lexer 수준에서 동작했습니다). [#62123](https://github.com/ClickHouse/ClickHouse/pull/62123) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 프라이머리 key를 포함하는 boolean 표현식 뒤에 불필요한 `= 1` 또는 `= 0`이 추가되면 프라이머리 인덱스가 사용되지 않던 문제를 수정했습니다. 예를 들어 `SELECT * FROM <table> WHERE <primary-key> IN (<value>) = 1` 및 `SELECT * FROM <table> WHERE <primary-key> NOT IN (<value>) = 0`은 프라이머리 인덱스를 사용할 수 있음에도 둘 다 전체 테이블 스캔을 수행했습니다. [#62142](https://github.com/ClickHouse/ClickHouse/pull/62142) ([josh-hildred](https://github.com/josh-hildred)).
* zookeeper 테이블에 쿼리 진행 상황을 추가했습니다. [#62152](https://github.com/ClickHouse/ClickHouse/pull/62152) ([JackyWoo](https://github.com/JackyWoo)).
* 서버 전체에서 trace collector(Real 및 CPU)를 활성화할 수 있는 기능을 추가했습니다. [#62189](https://github.com/ClickHouse/ClickHouse/pull/62189) ([alesapin](https://github.com/alesapin)).
* `lightweight_deletes_sync` 설정을 추가했습니다(기본값: 2 - 모든 레플리카를 동기적으로 대기). 이 설정은 `mutations_sync` 설정과 유사하지만 경량한 삭제의 동작에만 영향을 줍니다. [#62195](https://github.com/ClickHouse/ClickHouse/pull/62195) ([Anton Popov](https://github.com/CurtizJ)).
* 사용자 지정 설정의 값을 파싱할 때 불리언과 정수를 구분하도록 했습니다: `SET custom_a = true; SET custom_b = 1;`. [#62206](https://github.com/ClickHouse/ClickHouse/pull/62206) ([Vitaly Baranov](https://github.com/vitlibar)).
* AWS Private Link Interface 엔드포인트를 통한 S3 액세스를 지원합니다. [#60021](https://github.com/ClickHouse/ClickHouse/issues/60021), [#31074](https://github.com/ClickHouse/ClickHouse/issues/31074), [#53761](https://github.com/ClickHouse/ClickHouse/issues/53761)을 해결했습니다.
