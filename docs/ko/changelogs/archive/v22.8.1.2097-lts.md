<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 캐시를 조합 가능하게 만들고, 특정 파일(idx, mrk 등)은 제거하지 않도록 했으며, 이전 캐시 버전을 삭제했습니다. 이제 Azure blob storage 디스크, Local 디스크, StaticWeb 디스크 등 위에 캐시를 구성할 수 있습니다. 이 PR은 캐시 구성이 변경되었고, 캐시가 동작하려면 구성 파일을 업데이트해야 하므로 하위 호환되지 않는 변경 사항으로 표시되었습니다. 이전 캐시는 새 구성에서도 계속 사용됩니다. 기존 캐시 구성으로도 서버는 정상적으로 시작됩니다. [#36140](https://github.com/ClickHouse/ClickHouse/issues/36140)을 닫습니다. [#37889](https://github.com/ClickHouse/ClickHouse/issues/37889)을 닫습니다. [#36171](https://github.com/ClickHouse/ClickHouse/pull/36171) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 이제 해당하는 모든 딕셔너리 소스가 `remote_url_allow_hosts` 설정을 따릅니다. 이는 HTTP, Cassandra, Redis에는 이미 적용되어 있었습니다. ClickHouse, MongoDB, MySQL, PostgreSQL에도 추가했습니다. 호스트 검사는 DDL로 생성된 딕셔너리에 대해서만 수행합니다. [#39184](https://github.com/ClickHouse/ClickHouse/pull/39184) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* Date32와 DateTime64의 지원 범위를 확장하여 1900년부터 2299년까지의 날짜를 지원합니다. 이전 버전에서는 지원 범위가 1925년부터 2283년까지에 불과했습니다. 구현은 율리우스력에서 그레고리력으로의 역사적 전환을 고려하는 대신 프로렙틱 그레고리력([ISO 8601](https://en.wikipedia.org/wiki/ISO_8601):2004 (절 3.2.1 그레고리력)에 부합)을 사용합니다. 이 변경은 범위를 벗어난 인수에 대한 구현별 동작에 영향을 줍니다. 예를 들어 이전 버전에서 `1899-01-01` 값이 `1925-01-01`로 보정되었다면, 새 버전에서는 `1900-01-01`로 보정됩니다. 인터벌이 구현별 기준 시점부터 계산되므로, `INTERVAL 3 QUARTER`를 전달할 때 `toStartOfInterval`의 반올림 동작이 최대 1분기까지 달라집니다. [#28216](https://github.com/ClickHouse/ClickHouse/issues/28216)을 닫고, [#38393](https://github.com/ClickHouse/ClickHouse/issues/38393)을 개선합니다. [#39425](https://github.com/ClickHouse/ClickHouse/pull/39425) ([Roman Vasin](https://github.com/rvasin)).



<div id="new-feature">
  #### 새 기능

* 설정 `exact_rows_before_limit`(0/1)이 추가되었습니다. 이 설정을 활성화하면 ClickHouse가 `rows_before_limit_at_least` 통계에 정확한 값을 제공하지만, 그 대신 limit 이전의 데이터를 끝까지 모두 읽어야 합니다. 이로써 [#6613](https://github.com/ClickHouse/ClickHouse/issues/6613)이 해결되었습니다. [#25333](https://github.com/ClickHouse/ClickHouse/pull/25333) ([kevin wan](https://github.com/MaxWk)).
* uncompressed cache와 marks cache용 SLRU cache policy를 추가했습니다. [#34651](https://github.com/ClickHouse/ClickHouse/pull/34651) ([alexX512](https://github.com/alexX512)).
* Intel® In-Memory Analytics Accelerator(Intel® IAA)는 차세대 Intel® Xeon® Scalable 프로세서(&quot;Sapphire Rapids&quot;)에서 사용할 수 있는 하드웨어 가속기입니다. 이 가속기의 목적은 데이터 (de)compression 및 filtering과 같은 analytics의 일반적인 작업을 가속하는 것입니다. ClickHouse에 Intel® IAA 오프로딩 기술을 활용해 고성능 DEFLATE 구현을 제공하는 새로운 &quot;DeflateQpl&quot; 압축 코덱이 추가되었습니다. 이 코덱은 하드웨어 가속기에 대한 접근을 추상화하고, 하드웨어 가속기를 사용할 수 없을 때는 소프트웨어 폴백을 제공하는 [Intel® Query Processing Library (QPL)](https://github.com/intel/qpl)을 사용합니다. DEFLATE는 일반적으로 ClickHouse의 기본 LZ4 코덱보다 더 높은 압축률을 제공하므로, 그 결과 디스크 I/O와 주 메모리 사용량을 줄일 수 있습니다. [#36654](https://github.com/ClickHouse/ClickHouse/pull/36654) ([jasperzhu](https://github.com/jinjunzh)).
* 높은 RPS 환경에서 모든 쿼리의 총 스레드 수를 제한해 성능을 높일 수 있도록 concurrent&#95;threads&#95;soft&#95;limit 매개변수를 추가했습니다. [#37285](https://github.com/ClickHouse/ClickHouse/pull/37285) ([Roman Vasin](https://github.com/rvasin)).
* 쿼리가 생성하는 전체 동시 스레드 수를 제한하는 동시성 제어 로직이 추가되었습니다. [#37558](https://github.com/ClickHouse/ClickHouse/pull/37558) ([Sergei Trifonov](https://github.com/serxa)).
* Distributed 및 Replicated 엔진을 사용하는 테이블에 대한 병렬 distributed insert select 지원이 추가되었습니다 [#34670](https://github.com/ClickHouse/ClickHouse/issues/34670). [#39107](https://github.com/ClickHouse/ClickHouse/pull/39107) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* text formats에 대한 스키마 추론을 제어하는 새로운 설정을 추가했습니다: - `input_format_try_infer_dates` - 문자열에서 날짜를 추론합니다. - `input_format_try_infer_datetimes` - 문자열에서 DateTime을 추론합니다. - `input_format_try_infer_integers` - `Float64` 대신 `Int64`를 추론합니다. - `input_format_json_try_infer_numbers_from_strings` - JSON formats의 JSON string에서 숫자를 추론합니다. [#39186](https://github.com/ClickHouse/ClickHouse/pull/39186) ([Kruglov Pavel](https://github.com/Avogar)).
* 이 기능은 console에 JSON 포맷의 로그 출력을 제공합니다. 목적은 로그 분석 도구에서 더 쉽게 수집하고 쿼리할 수 있도록 하는 것입니다. [#39277](https://github.com/ClickHouse/ClickHouse/pull/39277) ([Mallik Hassan](https://github.com/SadiHassan)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* * 복잡한 쿼리에서 analyze가 멈춰 있는 경우 중단하도록 개선했습니다. [#38185](https://github.com/ClickHouse/ClickHouse/pull/38185) ([Vladimir C](https://github.com/vdimir)).
* 입력 스트림의 정렬 설명을 바탕으로 정렬 방식을 추론합니다. 입력 스트림이 이미 정렬된 경우 정렬을 건너뜁니다. [#38719](https://github.com/ClickHouse/ClickHouse/pull/38719) ([Igor Nikonov](https://github.com/devcrafter)).
* `DISTINCT` 컬럼이 `ORDER BY` 컬럼과 일치하거나 그 prefix를 이루는 경우, `ORDER BY`와 함께 사용하는 `DISTINCT`의 memory usage가 크게 개선되고 쿼리 execution time도 단축됩니다. [#39432](https://github.com/ClickHouse/ClickHouse/pull/39432) ([Igor Nikonov](https://github.com/devcrafter)).
* `cluster` 및 유사한 테이블 함수를 실행할 때 원격 테이블의 구조를 가져오기 위해 로컬 node를 최우선으로 사용합니다. [#39440](https://github.com/ClickHouse/ClickHouse/pull/39440) ([Mingliang Pan](https://github.com/liangliangpan)).
* 정렬 설명을 DISTINCT 컬럼에 적용할 수 있을 때만 `DistinctSortedTransform`을 사용하고, 그렇지 않으면 일반 `DISTINCT` 구현으로 폴백됩니다. 이렇게 하면 `DistinctSortedTransform` 실행 중 필요한 검사 횟수를 줄일 수 있습니다. [#39528](https://github.com/ClickHouse/ClickHouse/pull/39528) ([Igor Nikonov](https://github.com/devcrafter)).
* `DistinctSortedTransform`이 정렬의 이점을 활용하지 못하고 일반 `DISTINCT` 구현처럼 동작하던 문제를 수정했습니다. 이 수정으로 memory usage가 크게 줄어듭니다. [#39538](https://github.com/ClickHouse/ClickHouse/pull/39538) ([Igor Nikonov](https://github.com/devcrafter)).
* ColumnVector: AVX512VBMI2 compress store를 사용해 filter를 최적화했습니다. [#39633](https://github.com/ClickHouse/ClickHouse/pull/39633) ([Guo Wangyang](https://github.com/guowangy)).
* KeyCondition: 멀티스레드 시나리오에서 applyFunction을 최적화했습니다. [#39812](https://github.com/ClickHouse/ClickHouse/pull/39812) ([Guo Wangyang](https://github.com/guowangy)).
* AVX512 VBMI2를 지원하는 시스템에서 이 PR은 SSB 벤치마크 쿼리 3.1, 3.2, 3.3(SF=100)의 성능을 약 6% 개선합니다. 테스트는 Intel Icelake Xeon 8380 2소켓 시스템에서 수행했습니다. [#40033](https://github.com/ClickHouse/ClickHouse/pull/40033) ([Robert Schulze](https://github.com/rschu1ze)).
* * 등록된 UDF가 하나도 없으면 UDF의 AST를 순회하지 않습니다. [#40069](https://github.com/ClickHouse/ClickHouse/pull/40069) ([Raúl Marín](https://github.com/Algunenano)).
* * CurrentMemoryTracker의 alloc 및 free를 최적화했습니다. [#40078](https://github.com/ClickHouse/ClickHouse/pull/40078) ([Raúl Marín](https://github.com/Algunenano)).

ON CLUSTER` 쿼리를 먼저 initiator에서 정규화할 수 있습니다. 즉, initiator가 쿼리에서 지정한 클러스터에 속하지 않으면 `ON CLUSTER` 쿼리가 동작하지 않을 수 있습니다. [#35570](https://github.com/ClickHouse/ClickHouse/issues/35570) 관련 - `Replicated` 데이터베이스 엔진 관련 기타 사소한 수정 - `Replicated` 데이터베이스 시작 시 메타데이터 일관성을 확인하고, 로컬 메타데이터와 Keeper의 메타데이터가 일치하지 않으면 레플리카 복구를 시작합니다.
