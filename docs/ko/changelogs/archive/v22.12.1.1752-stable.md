<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* `String` 인수를 사용하는 `min`, `max`, `any*`, `argMin`, `argMax` 집계 함수 상태(state)의 직렬화/역직렬화에서 발생하던 하위 호환성 문제가 수정되었습니다. 이 비호환성은 [https://github.com/ClickHouse/ClickHouse/pull/41431](https://github.com/ClickHouse/ClickHouse/pull/41431)에서 도입되었으며 22.9, 22.10, 22.11 브랜치에 영향을 줍니다(각각 22.9.6, 22.10.4, 22.11.2부터 수정됨). 22.3, 22.7, 22.8 브랜치의 일부 마이너 릴리스도 영향을 받습니다: 22.3.13...22.3.14(22.3.15부터 수정됨), 22.8.6...22.8.9(22.8.10부터 수정됨), 22.7.6 이상(22.7에서는 수정되지 않을 예정이므로 22.7.*에서 22.8.10 이상으로 업그레이드할 것을 권장합니다). 이 릴리스 노트는 영향을 받는 버전을 한 번도 사용한 적이 없는 사용자에게는 해당되지 않습니다. 비호환 버전은 위에 언급된 집계 함수의 상태를 읽을 때 문자열 끝에 추가 `'\0'`를 붙입니다. 예를 들어, 이전 버전이 `anyState('foobar')`의 상태를 `state_column`에 저장한 경우 비호환 버전은 `anyMerge(state_column)`에서 `'foobar\0'`를 출력합니다. 또한 비호환 버전은 집계 함수 상태를 끝의 `'\0'` 없이 기록합니다. 더 최신 버전(수정 사항이 포함된 버전)은 한 가지 예외적인 경우를 제외하면, 비호환 버전을 포함한 모든 버전이 기록한 데이터를 올바르게 읽을 수 있습니다. 비호환 버전이 실제로 null 문자로 끝나는 문자열이 포함된 상태를 저장한 경우, 더 최신 버전은 영향을 받는 집계 함수의 상태를 읽을 때 끝의 `'\0'`를 제거합니다. 예를 들어, 비호환 버전이 `anyState('abrac\0dabra\0')`의 상태를 `state_column`에 저장한 경우 더 최신 버전은 `anyMerge(state_column)`에서 `'abrac\0dabra'`를 출력합니다. 이 문제는 비호환 버전이 이전 버전 또는 더 최신 버전과 함께 하나의 클러스터에서 동작할 때 분산 쿼리에도 영향을 줍니다. [#43038](https://github.com/ClickHouse/ClickHouse/pull/43038) ([Raúl Marín](https://github.com/Algunenano)).

* 이 PR은 다음 쿼리의 파트 삭제 방식을 변경합니다: truncate table, alter table drop part, alter table drop partition. 이제 이러한 쿼리는 기존 파트를 덮는 빈 파트를 생성합니다. 이에 따라 truncate 쿼리가 배타적 잠금 없이 동작하므로 동시 읽기가 잠기지 않습니다. 또한 이러한 모든 쿼리에서 내구성도 확보했습니다. request가 성공하면 이후에 파트가 다시 되살아나는 일이 없습니다. atomicity는 transaction 범위에서만 보장된다는 점에 유의하십시오. [#41145](https://github.com/ClickHouse/ClickHouse/pull/41145) ([Sema Checherinda](https://github.com/CheSema)).
* `SET param_x` 쿼리에서는 더 이상 매개변수 값을 수동으로 문자열 직렬화할 필요가 없습니다. 예를 들어 쿼리 `SET param_a = '[\'a\', \'b\']'`는 이제 `SET param_a = ['a', 'b']`처럼 작성할 수 있습니다. [#41874](https://github.com/ClickHouse/ClickHouse/pull/41874) ([Nikolay Degterinsky](https://github.com/evillique)).

* 이슈 [#38075](https://github.com/ClickHouse/ClickHouse/issues/38075)를 해결했습니다. 현재 async insert는 중복 제거를 지원하지 않습니다. 여러 개의 작은 삽입이 하나의 part에 함께 존재할 수 있으며, 이는 여러 `block id`에 대응하기 때문입니다. 해결 방법은 간단합니다. 변경 사항은 다음과 같습니다. 1. 모든 청크에서 각 삽입의 offsets를 기록합니다. 2. sinker가 청크를 수신하면 여러 개의 `block_id`를 계산합니다. 3. 해당 `block_id`들에 대해 block number 잠금을 획득합니다. 3.1. 실패하면 block에서 중복 삽입과 중복 `block_id`를 제거하고 `offsets`를 다시 계산합니다. 3.2. 성공하면 `block_id`와 기타 항목을 Keeper에 커밋합니다. a. 실패하면 3.1을 수행합니다. b. 성공하면 모두 성공합니다. [#43304](https://github.com/ClickHouse/ClickHouse/pull/43304) ([Han Fei](https://github.com/hanfei1991)).
