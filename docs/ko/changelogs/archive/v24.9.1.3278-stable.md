  ### ClickHouse 릴리스 v24.9.1.3278-안정 (6d058d82a8e) FIXME v24.9.1.1-new (e02b434d2fc) 대비

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 서브쿼리가 괄호 안에 있을 때 `UNION`이 포함된 쿼리 체인에서 `FORMAT` 앞에 `SETTINGS`를 작성할 수 있습니다. 이 변경으로 [#39712](https://github.com/ClickHouse/ClickHouse/issues/39712)가 해결되었습니다. 또한 쿼리에 SETTINGS 절이 순서대로 두 번 지정된 경우의 동작이 변경되었습니다. 해당 서브쿼리에는 가장 가까운 SETTINGS 절이 우선 적용됩니다. 이전 버전에서는 가장 바깥쪽 SETTINGS 절이 안쪽 절보다 우선 적용될 수 있었습니다. [#60197](https://github.com/ClickHouse/ClickHouse/pull/60197) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 복제된 데이터베이스에서 테이블을 생성할 때 UUID를 명시적으로 지정할 수 없습니다. 또한 복제된 데이터베이스의 *MergeTree 테이블에 대해 ZooKeeper 경로와 레플리카 이름을 명시적으로 지정하는 것도 허용되지 않습니다. [#66104](https://github.com/ClickHouse/ClickHouse/pull/66104) ([Alexander Tokmakov](https://github.com/tavplubix)).
* Dynamic 타입을 재구현했습니다. 이제 동적 데이터 타입 한도에 도달하면 새 타입은 `String`으로 CAST되지 않고, 바이너리 인코딩된 데이터 타입과 함께 바이너리 형식 데이터로 특수한 데이터 구조에 저장됩니다. 이제 Dynamic 컬럼에 한 번이라도 삽입된 모든 타입은 subcolumn으로 읽을 수 있습니다. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Pavel Kruglov](https://github.com/Avogar)).
* `a[b].c`와 같은 표현식은 이름이 지정된 Tuple에서 지원되며, `expr().name`처럼 임의의 표현식에 대한 이름 기반 subscript도 지원됩니다. 이는 JSON 처리에 유용합니다. 이 변경으로 [#54965](https://github.com/ClickHouse/ClickHouse/issues/54965)가 해결되었습니다. 이전 버전에서는 `expr().name` 형태의 표현식이 `tupleElement(expr(), name)`으로 parse되었고, 쿼리 분석기는 해당 Tuple 요소가 아니라 `name` 컬럼을 찾았습니다. 새 버전에서는 이것이 `tupleElement(expr(), 'name')`로 변경되었습니다. 대부분의 경우 이전 버전은 제대로 동작하지 않았지만, 이 변경으로 비호환성이 발생할 수 있는 매우 이례적인 시나리오를 상정할 수는 있습니다. 예를 들어 Tuple 요소 이름과 다른 이름을 가진 컬럼이나 alias에 Tuple 요소의 이름을 저장한 경우입니다: `SELECT 'b' AS a, CAST([tuple(123)] AS 'Array(Tuple(b UInt8))') AS t, t[1].a`. 이러한 쿼리를 사용했을 가능성은 매우 낮지만, 이 변경은 잠재적으로 하위 호환되지 않는 변경 사항으로 표시해야 합니다. [#68435](https://github.com/ClickHouse/ClickHouse/pull/68435) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `print_pretty_type_names` 설정이 활성화되면 `SHOW CREATE TABLE` SQL 문, `formatQuery` 함수, 그리고 `clickhouse-client` 및 `clickhouse-local`의 interactive mode에서 `Tuple` 데이터 타입이 보기 좋은 형태로 출력됩니다. 이전 버전에서는 이 설정이 `DESCRIBE` 쿼리와 `toTypeName`에만 적용되었습니다. 이 변경으로 [#65753](https://github.com/ClickHouse/ClickHouse/issues/65753)가 해결되었습니다. [#68492](https://github.com/ClickHouse/ClickHouse/pull/68492) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="new-feature">
  #### 새 기능
</div>

* 함수 `toStartOfInterval()`에 TimescaleDB의 `time_bucket()` 함수와 PostgreSQL의 `date_bin()` 함수를 각각 에뮬레이션하는 새 오버로드가 추가되었습니다. ([#55619](https://github.com/ClickHouse/ClickHouse/issues/55619)). 이를 통해 날짜 또는 timestamp 값을 *고정된* 원점인 0000-01-01 00:00:00.000이 아니라 *임의의* 원점을 기준으로, 지정된 인터벌의 배수에 맞춰 정렬할 수 있습니다. 예를 들어 `SELECT toStartOfInterval(toDateTime('2023-01-01 14:45:00'), INTERVAL 1 MINUTE, toDateTime('2023-01-01 14:35:30'));`는 원점 `2023-01-01 14:35:30`을 기준으로 1분 인터벌의 배수에 해당하는 `2023-01-01 14:44:30`을 반환합니다. [#56738](https://github.com/ClickHouse/ClickHouse/pull/56738) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* `ATTACH PARTITION ALL FROM` 지원이 추가되었습니다. [#61987](https://github.com/ClickHouse/ClickHouse/pull/61987) ([Kirill Nikiforov](https://github.com/allmazz)).
* `input_format_try_infer_variants` 설정이 추가되었습니다. 이 설정을 사용하면 형식에 대해 스키마 추론을 수행할 때 컬럼/배열 요소에 가능한 타입이 둘 이상인 경우 Variant 타입을 추론할 수 있습니다. [#63798](https://github.com/ClickHouse/ClickHouse/pull/63798) ([Shaun Struwig](https://github.com/Blargian)).
* ClickHouse가 metadata, data, progress, totals, statistics를 포함해 각 행을 newline-delimited JSON 객체로 출력하는 JSONCompactWithProgress 포맷이 도입되었습니다. [#66205](https://github.com/ClickHouse/ClickHouse/pull/66205) ([Alexey Korepanov](https://github.com/alexkorep)).
* 새로운 JSON 데이터 타입이 구현되었습니다. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Pavel Kruglov](https://github.com/Avogar)).
* `input_format_json_empty_as_default` 설정이 추가되었습니다. 이 설정을 활성화하면 JSON 입력의 빈 필드를 기본값으로 처리합니다. [#59339](https://github.com/ClickHouse/ClickHouse/issues/59339)을 해결합니다. [#66782](https://github.com/ClickHouse/ClickHouse/pull/66782) ([Alexis Arnaud](https://github.com/a-a-f)).
* 문자열의 일부를 다른 문자열로 대체하는 함수 `overlay`와 `overlayUTF8`가 추가되었습니다. 예시: `SELECT overlay('Hello New York', 'Jersey', 11)`는 `Hello New Jersey`를 반환합니다. [#66933](https://github.com/ClickHouse/ClickHouse/pull/66933) ([李扬](https://github.com/taiyang-li)).
* 새 명령인 파티션 내 경량한 삭제(Lightweight Delete In Partition) `DELETE FROM [db.]table [ON CLUSTER cluster] [IN PARTITION partition_expr] WHERE expr;`가 추가되었습니다. &#96;&#96;&#96; VM-114-29-tos :) select * from ads&#95;app&#95;poster&#95;ip&#95;source&#95;channel&#95;di&#95;replicated&#95;local;. [#67805](https://github.com/ClickHouse/ClickHouse/pull/67805) ([sunny](https://github.com/sunny19930321)).
* `Interval` 데이터 타입 값에 대한 비교가 구현되어, 이제 최소 공통 supertype으로 변환됩니다. [#68057](https://github.com/ClickHouse/ClickHouse/pull/68057) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* CREATE SQL 문에서 기본적으로 IF NOT EXISTS 동작을 사용하도록 create&#95;if&#95;not&#95;exists 설정이 추가되었습니다. [#68164](https://github.com/ClickHouse/ClickHouse/pull/68164) ([Peter Nguyen](https://github.com/petern48)).
* Azure 및 로컬 환경에서 Iceberg 테이블을 읽을 수 있게 되었습니다. [#68210](https://github.com/ClickHouse/ClickHouse/pull/68210) ([Daniil Ivanik](https://github.com/divanik)).
* JSON 컬럼 타입 콘텐츠를 더 잘 내부 검사할 수 있도록 집계 함수 distinctDynamicTypes/distinctJSONPaths/distinctJSONPathsAndTypes가 추가되었습니다. [#68463](https://github.com/ClickHouse/ClickHouse/pull/68463) ([Pavel Kruglov](https://github.com/Avogar)).
* 이제 태그로 쿼리 캐시 엔트리를 삭제할 수 있습니다. 예를 들어 `SELECT 1 SETTINGS use_query_cache = true, query_cache_tag = 'abc'`로 생성한 쿼리 캐시 엔트리는 `SYSTEM DROP QUERY CACHE TAG 'abc'`로 삭제할 수 있습니다(물론 `SYSTEM DROP QUERY CACHE`만 실행해 전체 쿼리 캐시를 비울 수도 있습니다). [#68477](https://github.com/ClickHouse/ClickHouse/pull/68477) ([Michał Tabaszewski](https://github.com/pinsvin00)).
* 명명된 컬렉션에 스토리지 암호화를 추가했습니다. [#68615](https://github.com/ClickHouse/ClickHouse/pull/68615) ([Pablo Marcos](https://github.com/pamarcos)).
* 문자열의 RIPEMD-160 암호학적 해시를 계산하는 `ripeMD160` 함수를 추가했습니다. 예시: `SELECT hex(ripeMD160('The quick brown fox jumps over the lazy dog'))`는 `37F332F68DB77BD9D7EDD4969571AD671CF9DD3B`를 반환합니다. [#68639](https://github.com/ClickHouse/ClickHouse/pull/68639) ([Dergousov Maxim](https://github.com/m7kss1)).
* URL 테이블 엔진에 가상 컬럼 &#95;headers를 추가했습니다. [#65026](https://github.com/ClickHouse/ClickHouse/issues/65026)를 해결합니다. [#68867](https://github.com/ClickHouse/ClickHouse/pull/68867) ([flynn](https://github.com/ucasfl)).
* 사용 가능한 프로젝션을 추적하기 위한 `system.projections` 테이블을 추가했습니다. [#68901](https://github.com/ClickHouse/ClickHouse/pull/68901) ([Jordi Villar](https://github.com/jrdi)).
* 기존 `arrayZip`을 기반으로 길이가 맞지 않는 배열도 허용하는 Spark 호환성 함수(arrays&#95;zip) `arrayZipUnaligned`를 추가했습니다. &#96;&#96;&#96; sql SELECT arrayZipUnaligned([1], [1, 2, 3]). [#69030](https://github.com/ClickHouse/ClickHouse/pull/69030) ([李扬](https://github.com/taiyang-li)).
* HTTP 헤더 `X-ClickHouse-Summary`에 `RealTimeMicroseconds` 메트릭을 추가했습니다. 이를 통해 `system.query_log`를 확인하지 않고도 요청의 CPU time을 알 수 있습니다. [#69032](https://github.com/ClickHouse/ClickHouse/pull/69032) ([Alejandro](https://github.com/alexon1234)).
* 노드를 원자적으로 복사/이동하는 Keeper 클라이언트용 cp/mv 명령을 추가했습니다. [#69034](https://github.com/ClickHouse/ClickHouse/pull/69034) ([Mikhail Artemenko](https://github.com/Michicosun)).
* 정규화 단계를 건너뛸 수 있도록 함수 `arrayAUC`에 인수 `scale`(기본값: `true`)을 추가했습니다(issue [#69609](https://github.com/ClickHouse/ClickHouse/issues/69609)). [#69717](https://github.com/ClickHouse/ClickHouse/pull/69717) ([gabrielmcg44](https://github.com/gabrielmcg44)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 왼쪽 또는 내부 해시 조인에서 왼쪽 테이블의 키 밀도가 높을 때, 오른쪽 테이블(right table)을 키 기준으로 재배치해 조인 성능을 개선했습니다. [#60341](https://github.com/ClickHouse/ClickHouse/pull/60341) ([kevinyhzou](https://github.com/KevinyhZou)).
* 지연 출력(lazy output)을 위해 `AddedColumns`에 `RowRefList` 또는 `RowRef`를 추가하고, `buildOutput`에서 출력 시 `RowRefList`/`RowRef`를 사용하며, `buildOutput`의 for 루프에서 `is_join_get` 조건을 제거해 전체 조인 성능을 개선했습니다. [#63677](https://github.com/ClickHouse/ClickHouse/pull/63677) ([kevinyhzou](https://github.com/KevinyhZou)).
* 재시작 속도를 높이기 위해 부팅 프로세스에서 파일 시스템 캐시 메타데이터를 비동기로 로드하도록 개선했습니다. [#65736](https://github.com/ClickHouse/ClickHouse/pull/65736) ([Daniel Pozo Escalona](https://github.com/danipozo)).
* `array` 및 `map` 함수가 일부 일반적인 경우를 훨씬 더 빠르게 처리하도록 최적화되었습니다. [#67707](https://github.com/ClickHouse/ClickHouse/pull/67707) ([李扬](https://github.com/taiyang-li)).
* 특히 컬럼에 NULL이 없는 경우 ORC 문자열 읽기 성능을 단순한 방식으로 최적화했습니다. [#67794](https://github.com/ClickHouse/ClickHouse/pull/67794) ([李扬](https://github.com/taiyang-li)).
* 머지 스케줄링 단계의 오버헤드를 줄여 머지의 전반적인 성능을 개선했습니다. [#68016](https://github.com/ClickHouse/ClickHouse/pull/68016) ([Anton Popov](https://github.com/CurtizJ)).
* profile이 설정되지 않고 자격 증명이 없으며 IMDS도 사용할 수 없는 경우(예: Cloud 외부의 머신에서 Public 버킷을 쿼리하는 경우) S3 요청 속도를 높였습니다. 이 변경으로 [#52771](https://github.com/ClickHouse/ClickHouse/issues/52771)이 해결되었습니다. [#68082](https://github.com/ClickHouse/ClickHouse/pull/68082) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* consistent hash를 사용해 레플리카 간 마크 분배 단위를 결정하는 새로운 알고리즘을 도입했습니다. 다양한 읽기 패턴에 따라 서로 다른 수의 마크를 선택해 성능을 개선했습니다. [#68424](https://github.com/ClickHouse/ClickHouse/pull/68424) ([Nikita Taranov](https://github.com/nickitat)).
* RowInputFormatWithNamesAndTypes에서 포맷 reader를 devirtualize하여 성능 개선 효과가 있는지 확인하도록 했습니다. [#68437](https://github.com/ClickHouse/ClickHouse/pull/68437) ([李扬](https://github.com/taiyang-li)).
* CPU 활용률을 극대화하기 위해 키 기반 병렬 머지 구현을 추가했습니다. [#68441](https://github.com/ClickHouse/ClickHouse/pull/68441) ([Jiebin Sun](https://github.com/jiebinn)).
* ORC 출력 형식에서 문자열 컬럼에 대해 딕셔너리 인코딩을 활성화할 수 있도록 설정 `output_format_orc_dictionary_key_size_threshold`를 추가했습니다. 이를 통해 출력 ORC 파일 크기를 줄이고 읽기 성능을 크게 높일 수 있습니다. [#68591](https://github.com/ClickHouse/ClickHouse/pull/68591) ([李扬](https://github.com/taiyang-li)).
* hive 파티셔닝 중 필요한 파일만 읽도록 구현했습니다. [#68963](https://github.com/ClickHouse/ClickHouse/pull/68963) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* 노드와 그 하위 트리 전체를 제거하는 새로운 Keeper 요청 RemoveRecursive를 도입했습니다. [#69332](https://github.com/ClickHouse/ClickHouse/pull/69332) ([Mikhail Artemenko](https://github.com/Michicosun)).
* vector similarity index에 데이터를 병렬로 추가해 vector similarity index 사용 시 삽입 성능을 높였습니다. [#69493](https://github.com/ClickHouse/ClickHouse/pull/69493) ([flynn](https://github.com/ucasfl)).
* 이전에는 병렬 레플리카 announcement 처리에서 part 중복 제거 로직의 알고리즘 복잡도가 O(n^2)였기 때문에, part(또는 파티션)가 많은 테이블에서는 눈에 띄는 시간이 걸릴 수 있었습니다. 이 변경으로 복잡도는 O(n*log(n))으로 낮아졌습니다. [#69596](https://github.com/ClickHouse/ClickHouse/pull/69596) ([Alexander Gololobov](https://github.com/davenger)).

<div id="improvement">
  #### 개선 사항
</div>

* 작은 엔터티 파싱과 관련된 codebase 일부를 강화했습니다. 다음과 같은 (경미한) 버그를 발견해 수정했습니다. - `DeltaLake` 테이블이 Bool로 파티션된 경우 파티션 값이 항상 false로 해석되던 문제, - `ExternalDistributed` 테이블이 제공된 주소에서 단 하나의 샤드만 사용하던 문제, `max_threads` 설정 값 및 유사한 값이 `auto(N)`가 아니라 `'auto(N)'`로 출력되던 문제입니다. [#52503](https://github.com/ClickHouse/ClickHouse/pull/52503) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 갱신 가능 구체화 뷰 개선 사항: 전체 테이블을 덮어쓰는 대신 기존 테이블에 행을 추가하는 추가 모드(`... REFRESH EVERY 1 MINUTE APPEND ...`), 재시도(기본적으로 비활성화되며 쿼리의 SETTINGS 섹션에서 구성), 현재 실행 중인 갱신이 끝날 때까지 기다리는 `SYSTEM WAIT VIEW <name>` 쿼리, 그리고 몇 가지 수정 사항이 포함됩니다. [#58934](https://github.com/ClickHouse/ClickHouse/pull/58934) ([Michael Kolupaev](https://github.com/al13n321)).
