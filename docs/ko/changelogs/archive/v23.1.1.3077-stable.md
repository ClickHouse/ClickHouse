  ### ClickHouse 릴리스 v23.1.1.3077-안정 (dcaac477025) FIXME v22.12.1.1752-안정 (688e488e930)와 비교

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* `SYSTEM RESTART DISK` 쿼리를 제거합니다. [#44647](https://github.com/ClickHouse/ClickHouse/pull/44647) ([alesapin](https://github.com/alesapin)).
* Float32 또는 Float64가 아닌 유형의 컬럼에서는 Gorilla Compression을 허용하지 않습니다. [#45252](https://github.com/ClickHouse/ClickHouse/pull/45252) ([Robert Schulze](https://github.com/rschu1ze)).
* HASHED/SPARSE&#95;HASHED Dictionaries에서 PREALLOCATE를 제거합니다. [#45388](https://github.com/ClickHouse/ClickHouse/pull/45388) ([Azat Khuzhin](https://github.com/azat)).
* Deprecated 구문으로 생성된 `*MergeTree` 테이블에서는 병렬 quorum 삽입이 올바르게 동작하지 않을 수 있습니다. 따라서 이러한 테이블에 대한 병렬 quorum 삽입 지원을 완전히 비활성화합니다. 이는 새 구문으로 생성된 테이블에는 영향을 주지 않습니다. [#45430](https://github.com/ClickHouse/ClickHouse/pull/45430) ([Alexander Tokmakov](https://github.com/tavplubix)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* HashedDictionary에 세그먼트 분할 지원이 추가되어 병렬 로드가 가능해졌습니다(세그먼트 수에 거의 선형적으로 비례하는 스케일링). [#40003](https://github.com/ClickHouse/ClickHouse/pull/40003) ([Azat Khuzhin](https://github.com/azat)).
* `MergeTree` 테이블 시작 시 비활성 파트를 로드하지 않습니다. [#42181](https://github.com/ClickHouse/ClickHouse/pull/42181) ([Anton Popov](https://github.com/CurtizJ)).
* * 쿼리 파싱 속도를 개선했습니다. [#42284](https://github.com/ClickHouse/ClickHouse/pull/42284) ([Raúl Marín](https://github.com/Algunenano)).
* `expr`가 `LowCardinality` 컬럼이면 OR 체인 `expr = x1 OR ... OR expr = xN`을 항상 `expr IN (x1, ..., xN)`으로 대체합니다. 이 경우 `optimize_min_equality_disjunction_chain_length` 설정은 무시됩니다. [#42889](https://github.com/ClickHouse/ClickHouse/pull/42889) ([Guo Wangyang](https://github.com/guowangy)).
* > 원본 changelog 원래 구현에서는 ThreadGroupStatus:: finished&#95;threads&#95;counters&#95;memory의 메모리를 임시 std::vector로 이동시켜 해제하며, 이 객체는 곧 수명이 끝나 소멸됩니다. 이 메서드는 유효하지만 충분히 직관적이지는 않습니다. 코드 가독성을 높이기 위해, 이 커밋에서는 먼저 벡터의 크기를 0으로 줄인 다음 그에 맞게 용량을 축소하는 방식으로 메모리를 해제합니다. [#43586](https://github.com/ClickHouse/ClickHouse/pull/43586) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* [#42214](https://github.com/ClickHouse/ClickHouse/issues/42214)의 후속 작업으로, 이 PR에서는 자동 벡터화를 통해 컬럼 단위 3항 논리 평가를 최적화했습니다. 이 [microbenchmark](https://github.com/ZhiguoZh/ClickHouse/blob/20221123-ternary-logic-opt-example/src/Functions/examples/associative_applier_perf.cpp) 성능 테스트에서는 ICX 장치(Intel Xeon Platinum 8380 CPU)에서 최대 **21배**의 **성능 향상**이 관찰되었습니다. [#43669](https://github.com/ClickHouse/ClickHouse/pull/43669) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 작은 파일이 많은 경우 `S3` 스토리지와 테이블 함수 `s3`에서의 읽기 지연 시간이 개선되었습니다. 이제 `S3` 스토리지에서 읽을 때 설정 `remote_filesystem_read_method`와 `remote_filesystem_read_prefetch`가 적용됩니다. [#43726](https://github.com/ClickHouse/ClickHouse/pull/43726) ([Anton Popov](https://github.com/CurtizJ)).
* * 가능하면 system.tables에서 읽기 잠금을 획득하지 않도록 했습니다. [#43840](https://github.com/ClickHouse/ClickHouse/pull/43840) ([Raúl Marín](https://github.com/Algunenano)).
* ICX 장치(Intel Xeon Platinum 8380 CPU, 80코어, 160스레드)에서 수행한 SSB(Star Schema Benchmark) 성능 실험에 따르면, 이 변경으로 ThreadPoolImpl::mutex의 락 경합을 **75%**까지 효과적으로 줄일 수 있으며 CPU 활용률을 높이고 전체 성능을 **2.4%** 개선할 수 있습니다. [#44308](https://github.com/ClickHouse/ClickHouse/pull/44308) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 이제 최적화는 캐시된 HT 크기가 충분히 큰 경우에만 적용됩니다(임계값은 경험적으로 결정되어 하드코딩되었습니다). [#44455](https://github.com/ClickHouse/ClickHouse/pull/44455) ([Nikita Taranov](https://github.com/nickitat)).
* ... 현재는 구조체의 한 필드만 읽으려는 경우에도 구조체 필드 전체를 로드합니다. [#44484](https://github.com/ClickHouse/ClickHouse/pull/44484) ([lgbo](https://github.com/lgbo-ustc)).
* remote fs에서 수행하는 비동기 읽기의 성능이 소폭 개선되었습니다. [#44868](https://github.com/ClickHouse/ClickHouse/pull/44868) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 더 빠른 공유(RW) 뮤텍스 구현으로 전환했습니다. 스레드 동기화가 많은 쿼리나 경합이 심한 데이터 구조에서 성능이 개선될 수 있습니다. [#45007](https://github.com/ClickHouse/ClickHouse/pull/45007) ([Sergei Trifonov](https://github.com/serxa)).
* 다음에 대한 fast path를 추가했습니다: - col like &#39;%%&#39; - col like &#39;%&#39; - col not like &#39;%&#39; - col not like &#39;%&#39; - match(col, &#39;.*&#39;). [#45244](https://github.com/ClickHouse/ClickHouse/pull/45244) ([李扬](https://github.com/taiyang-li)).

* streaming 엔진 Kafka/RabbitMQ/NATS를 리팩터링 및 개선하고, 모든 포맷 지원을 추가했으며 포맷도 일부 리팩터링했습니다: - suffixes/prefixes가 있는 행 기반 포맷에서 메시지 생성 문제를 수정했습니다. 이제 모든 메시지는 모든 구분 기호를 포함한 완전한 형태로 포맷되며, 입력 형식을 사용해 다시 파싱할 수 있습니다. - Native, Parquet, ORC 등의 블록 기반 포맷을 지원합니다. 각 block은 개별 메시지로 포맷됩니다. 하나의 메시지에 포함되는 행 수는 block 크기에 따라 달라지므로 `max_block_size` 설정으로 제어할 수 있습니다. - 새로운 엔진 설정 `kafka_max_rows_per_message/rabbitmq_max_rows_per_message/nats_max_rows_per_message`를 추가했습니다. 이 설정은 행 기반 포맷에서 하나의 메시지에 포맷되는 행 수를 제어합니다. 기본값: 1. - NATS 테이블 엔진의 높은 메모리 사용량 문제를 수정했습니다. - NATS producer에서 임의의 바이너리 데이터를 지원합니다(이전에는 끝에 `\0`이 포함된 문자열에서만 동작했습니다). - 문서에 누락되어 있던 Kafka/RabbitMQ/NATS 엔진 설정을 추가했습니다. - Kafka/RabbitMQ/NATS의 producing 및 consuming을 리팩터링하고, 이를 WriteBuffers/ReadBuffers 시맨틱과 분리했습니다. - 출력 형식을 리팩터링했습니다. Kafka/RabbitMQ/NATS에서 각 행마다 사용되던 callbacks를 제거하고(이제 여기서는 callbacks를 사용하지 않음), IRowOutputFormat을 직접 사용할 수 있게 했으며, 행 끝 구분 기호와 행 사이 구분 기호를 명확히 하고, 다시 포맷을 시작할 수 있도록 출력 형식을 재설정할 수 있게 했습니다. - formatRow 함수에 올바른 구현을 추가했습니다(포맷 리팩터링 후의 보너스). [#42777](https://github.com/ClickHouse/ClickHouse/pull/42777) ([Kruglov Pavel](https://github.com/Avogar)).
* 새로운 인프라에서 `optimize_or_like_chain`을 지원합니다. [#42648](https://github.com/ClickHouse/ClickHouse/issues/42648)의 일부입니다. [#42797](https://github.com/ClickHouse/ClickHouse/pull/42797) ([Dmitry Novik](https://github.com/novikd)).
