<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* ` NAMED COLLECTION` 액세스 유형(별칭: `USE NAMED COLLECTION`, `NAMED COLLECTION USAGE`)이 추가되었습니다. 이 PR은 하위 호환되지 않습니다. 이 액세스 유형이 기본적으로 비활성화되어 있으며(상위 액세스 유형인 `NAMED COLLECTION ADMIN`도 기본적으로 비활성화되어 있음) 그에 따른 변경입니다. [#50277](https://github.com/ClickHouse/ClickHouse/issues/50277)에서 제안되었습니다. 권한을 부여하려면 `GRANT NAMED COLLECTION ON collection_name TO user` 또는 `GRANT NAMED COLLECTION ON * TO user`를 사용하십시오. 이러한 권한 부여를 수행하려면 구성에서 `named_collection_admin`이 필요합니다(이전 이름은 `named_collection_control`이었으며, 별칭으로 계속 유지됩니다). [#50625](https://github.com/ClickHouse/ClickHouse/pull/50625) ([Kseniia Sumarokova](https://github.com/kssenii)).
* `system.parts` 컬럼 이름 `last_removal_attemp_time`의 오타를 수정했습니다. 이제 이름은 `last_removal_attempt_time`입니다. [#52104](https://github.com/ClickHouse/ClickHouse/pull/52104) ([filimonov](https://github.com/filimonov)).
* distributed&#95;ddl&#95;entry&#95;format&#95;version의 기본 버전을 5로 높였습니다(OpenTelemetry 및 initial&#95;query&#95;idd 전달이 활성화됨). 이 변경으로 인해 **downgrade** 후에는 기존 분산 DDL 항목을 처리할 수 없게 됩니다(다만 일반적으로 이런 미처리 항목은 없어야 합니다). [#52128](https://github.com/ClickHouse/ClickHouse/pull/52128) ([Azat Khuzhin](https://github.com/azat)).
* 일반 metadata를 검사하는 것과 동일한 방식으로 프로젝션 metadata도 검사합니다. 이 변경으로 인해 유효하지 않은 프로젝션이 있는 테이블이 존재하면 server가 시작되지 않을 수 있습니다. 예를 들어 PK에 위치 기반 컬럼을 생성하는 프로젝션(예: `projection p (select * order by 1, 4)`)이 이에 해당합니다. 이는 테이블 PK에서는 허용되지 않으며 삽입/머지 중 크래시를 유발할 수 있습니다. 업데이트 전에 이러한 프로젝션을 삭제하십시오. [#52353](https://github.com/ClickHouse/ClickHouse/issues/52353)을 수정합니다. [#52361](https://github.com/ClickHouse/ClickHouse/pull/52361) ([Nikolai Kochetov](https://github.com/KochetovNicolai)).
* 실험적 기능 `hashid`는 bug로 인해 제거되었습니다. 구현 품질이 처음부터 미흡했고, Experimental 상태를 벗어나지 못했습니다. 이로써 [#52406](https://github.com/ClickHouse/ClickHouse/issues/52406)이 종료됩니다. [#52449](https://github.com/ClickHouse/ClickHouse/pull/52449) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 함수 `toDecimalString`은 구현 품질이 충분하지 않아 제거되었습니다. 이로써 [#52407](https://github.com/ClickHouse/ClickHouse/issues/52407)이 종료됩니다. [#52450](https://github.com/ClickHouse/ClickHouse/pull/52450) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* `move_all_conditions_to_prewhere` 및 `enable_multiple_prewhere_read_steps` 설정이 기본적으로 활성화됩니다. [#46365](https://github.com/ClickHouse/ClickHouse/pull/46365) ([Alexander Gololobov](https://github.com/davenger)).
* allocator를 튜닝해 일부 쿼리의 성능을 개선합니다. [#46416](https://github.com/ClickHouse/ClickHouse/pull/46416) ([Azat Khuzhin](https://github.com/azat)).
* Parquet 파일 쓰기 속도가 10배 빨라졌으며, 이제 멀티스레드로 동작합니다. 읽기 속도와도 거의 비슷합니다. [#49367](https://github.com/ClickHouse/ClickHouse/pull/49367) ([Michael Kolupaev](https://github.com/al13n321)).
* 희소 serialization 포맷의 자동 선택이 기본적으로 활성화됩니다. 성능도 향상됩니다. 이 포맷은 버전 22.1부터 지원됩니다. 이 변경 이후에는 22.1보다 오래된 버전으로 다운그레이드하지 못할 수 있습니다. MergeTree 테이블에 `ratio_of_defaults_for_sparse_serialization = 1` 설정을 지정하면 희소 serialization 포맷 사용을 비활성화할 수 있습니다. [#49631](https://github.com/ClickHouse/ClickHouse/pull/49631) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 이제 `MergeTreePrefetchedReadPool`도 `MergeTreeReadPool`과 마찬가지로 고정 크기 작업을 사용합니다. 또한 이제 S3 요청에 연결 풀을 사용합니다. [#49732](https://github.com/ClickHouse/ClickHouse/pull/49732) ([Nikita Taranov](https://github.com/nickitat)).
* join의 오른쪽에 더 많은 pushdown을 적용합니다. [#50532](https://github.com/ClickHouse/ClickHouse/pull/50532) ([Nikita Taranov](https://github.com/nickitat)).
* 해시 테이블 크기를 미리 예약해 `grace_hash` join을 개선합니다(재제출). [#50875](https://github.com/ClickHouse/ClickHouse/pull/50875) ([lgbo](https://github.com/lgbo-ustc)).
* 때로는 `OpenedFileCache`에서 잠금을 기다리는 시간이 눈에 띄게 길어질 수 있었습니다. 경합을 줄이기 위해 이를 여러 하위 맵으로 세그먼트했으며, 각 하위 맵은 자체 잠금을 사용합니다. [#51341](https://github.com/ClickHouse/ClickHouse/pull/51341) ([Nikita Taranov](https://github.com/nickitat)).
* functionunixtimestamp64.h에서 중복 조건을 제거합니다. [#51857](https://github.com/ClickHouse/ClickHouse/pull/51857) ([lcjh](https://github.com/ljhcage)).
* 핵심 아이디어는 PK 컬럼이 포함된 조건은 PK 분석에 사용될 가능성이 높아 PREWHERE 필터링에는 추가적인 기여가 크지 않다는 것입니다. [#51958](https://github.com/ClickHouse/ClickHouse/pull/51958) ([Alexander Gololobov](https://github.com/davenger)).
* 1. 이전 분석기와 새 분석기 모두에 재작성기를 추가합니다. 2. 기본값이 0인 설정 `optimize_uniq_to_count`를 추가합니다. [#52004](https://github.com/ClickHouse/ClickHouse/pull/52004) ([JackyWoo](https://github.com/JackyWoo)).
* ICX 장치(Intel Xeon Platinum 8380 CPU, 80코어, 160스레드)에서 **OnTime**으로 수행한 성능 실험에 따르면, 이 변경으로 다른 쿼리에는 영향 없이 쿼리 **Q8**의 QPS가 **11.6%** 향상될 수 있습니다. [#52036](https://github.com/ClickHouse/ClickHouse/pull/52036) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 기본적으로 `allow_vertical_merges_from_compact_to_wide_parts`를 활성화합니다. 이렇게 하면 머지 중 메모리 사용량을 절감할 수 있습니다. [#52295](https://github.com/ClickHouse/ClickHouse/pull/52295) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 프라이머리 키(primary key)를 무효화하는 잘못된 프로젝션 분석을 수정했습니다. 이 문제는 `query_plan_optimize_primary_key = 1, query_plan_optimize_projection = 1`인 경우에만 발생합니다. 이로써 [#48823](https://github.com/ClickHouse/ClickHouse/issues/48823)를 수정합니다. 이로써 [#51173](https://github.com/ClickHouse/ClickHouse/issues/51173)를 수정합니다. [#52308](https://github.com/ClickHouse/ClickHouse/pull/52308) ([Amos Bird](https://github.com/amosbird)).
* FileCache::loadMetadata의 syscall 수를 줄였습니다. [#52435](https://github.com/ClickHouse/ClickHouse/pull/52435) ([Raúl Marín](https://github.com/Algunenano)).

* 모든 대기 중인 비동기 삽입을 대상 테이블로 플러시하는 쿼리 `SYSTEM FLUSH ASYNC INSERT QUEUE`를 추가했습니다. 정상 종료 시 비동기 삽입 큐를 플러시할지 여부를 결정하는 서버 측 설정 `async_insert_queue_flush_on_shutdown`(기본값: `true`)도 추가했습니다. 이제 `async_insert_threads`도 서버 측 설정입니다. [#49160](https://github.com/ClickHouse/ClickHouse/pull/49160) ([Anton Popov](https://github.com/CurtizJ)).
* `16 EiB`의 여유 공간에 관한 메시지는 의미가 없으므로 logs에 표시하지 않도록 했습니다. 이로써 [#49320](https://github.com/ClickHouse/ClickHouse/issues/49320)이 해결되었습니다. [#49342](https://github.com/ClickHouse/ClickHouse/pull/49342) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `sleepEachRow` 함수의 제한을 올바르게 검사하도록 수정했습니다. `function_sleep_max_microseconds_per_block` 설정을 추가했습니다. 이는 범용 쿼리 퍼저에 필요합니다. [#49343](https://github.com/ClickHouse/ClickHouse/pull/49343) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 두 가지 문제를 수정했습니다: &#96;&#96;&#96; select geohashEncode(120.2, number::Float64) from numbers(10);. [#50066](https://github.com/ClickHouse/ClickHouse/pull/50066) ([李扬](https://github.com/taiyang-li)).
* snapshots와 logs 저장을 위해 Keeper에서 외부 디스크를 지원하도록 추가했습니다. [#50098](https://github.com/ClickHouse/ClickHouse/pull/50098) ([Antonio Andelic](https://github.com/antonio2368)).
* 다중 directory 선택(`{}`) 글롭 패턴을 지원하도록 추가했습니다. [#50559](https://github.com/ClickHouse/ClickHouse/pull/50559) ([Andrey Zvonov](https://github.com/zvonand)).
* 남은 데이터를 백그라운드에서 다운로드해 file segment 크기에 엄격한 하한값을 적용할 수 있도록 했습니다. file segment의 최소 크기(실제 파일 크기가 더 큰 경우)는 cache 구성 설정 `boundary_alignment`로 지정하며, 기본값은 `4Mi`입니다. 백그라운드 스레드 수는 cache 구성 설정 `background_download_threads`로 지정하며, 기본값은 `2`입니다. 또한 이 PR에서 `max_file_segment_size`를 `8Mi`에서 `32Mi`로 늘렸습니다. [#51000](https://github.com/ClickHouse/ClickHouse/pull/51000) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 구성의 `http_forbid_headers` 섹션에서 HTTP headers를 필터링할 수 있도록 했습니다. exact match 필터와 Regexp 필터를 모두 사용할 수 있습니다. [#51038](https://github.com/ClickHouse/ClickHouse/pull/51038) ([Nikolay Degterinsky](https://github.com/evillique)).
