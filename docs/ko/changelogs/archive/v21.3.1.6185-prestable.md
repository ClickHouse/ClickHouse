  # 2022 변경 로그

<div id="clickhouse-release-v21316185-prestable-fixme-as-compared-to-v21215869-prestable">
  ### ClickHouse 릴리스 v21.3.1.6185-prestable FIXME (v21.2.1.5869-prestable 대비)

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 이제 대소문자를 구분하지 않는 모든 함수 이름은 쿼리 분석 과정에서 소문자로 변환됩니다. 이는 PROJECTION 쿼리 라우팅에 필요합니다. [#20174](https://github.com/ClickHouse/ClickHouse/pull/20174) ([Amos Bird](https://github.com/amosbird)).
* 이제 기존 구문에서 table TTL이 포함된 MergeTree 테이블은 생성할 수 없습니다. 해당 구문에서는 table TTL이 단순히 무시되기 때문입니다. 기존 테이블에 대한 ATTACH는 계속 사용할 수 있습니다. [#20282](https://github.com/ClickHouse/ClickHouse/pull/20282) ([alesapin](https://github.com/alesapin)).

<div id="new-feature">
  #### 새 기능
</div>

* 실험적 `Replicated` 데이터베이스 엔진을 추가했습니다. 이 엔진은 여러 호스트 간에 DDL 쿼리를 복제합니다. [#16193](https://github.com/ClickHouse/ClickHouse/pull/16193) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 분산 쿼리 중복 제거는 [#16033](https://github.com/ClickHouse/ClickHouse/issues/16033)의 후속 작업으로, 제안 [#13574](https://github.com/ClickHouse/ClickHouse/issues/13574)를 부분적으로 해결합니다. [#17348](https://github.com/ClickHouse/ClickHouse/pull/17348) ([xjewer](https://github.com/xjewer)).
* DiskS3의 메타데이터 파일을 백업/복원하는 기능을 추가했습니다. [#18377](https://github.com/ClickHouse/ClickHouse/pull/18377) ([Pavel Kovalenko](https://github.com/Jokser)).
* * pull request에 반영되었습니다. [#18508](https://github.com/ClickHouse/ClickHouse/pull/18508) ([PHO](https://github.com/depressed-pho)).
* 파일을 `String`으로 읽는 `file()` 함수를 추가했습니다. 이 변경으로 [#issue:18851](https://github.com/ClickHouse/ClickHouse/issues/18851)이 해결되었습니다. [#19204](https://github.com/ClickHouse/ClickHouse/pull/19204) ([keenwolf](https://github.com/keen-wolf)).
* `MergeTree*` engine을 사용하는 테이블에 이제 쿼리 동시성 제어를 위한 새로운 테이블 수준 설정 2개가 추가되었습니다. 설정 `max_concurrent_queries`는 이 테이블과 관련된 동시 실행 쿼리 수를 제한합니다. 설정 `min_marks_to_honor_max_concurrent_queries`는 쿼리가 최소 이 수만큼의 마크를 읽는 경우에만 앞선 설정을 적용하도록 지정합니다. [#19544](https://github.com/ClickHouse/ClickHouse/pull/19544) ([Amos Bird](https://github.com/amosbird)).
* * [#18454](https://github.com/ClickHouse/ClickHouse/issues/18454)에 언급됨 - 함수 `htmlOrxmlCoarseParse` 추가; - `<script></script>` 파싱 지원; - `<style></style>` 파싱 지원; - `<![CDATA[]]>` 파싱 지원; - 공백 축소 지원; - 모든 `<content>` 포맷 파싱 지원; - HyperScan에서 SIMD 지원; - 모든 처리가 단일 패스로 이루어집니다. [#19600](https://github.com/ClickHouse/ClickHouse/pull/19600) ([zlx19950903](https://github.com/zlx19950903)).
* QUOTA 유형 `QUERY&#95;SELECTS` 및 `QUERY&#95;INSERTS`를 추가했습니다. [#19603](https://github.com/ClickHouse/ClickHouse/pull/19603) ([JackyWoo](https://github.com/JackyWoo)).
* ExecutableDictionarySource에 `implicit&#95;key` 옵션을 추가했습니다. [#14527](https://github.com/ClickHouse/ClickHouse/issues/14527)을 수정했습니다. [#19677](https://github.com/ClickHouse/ClickHouse/pull/19677) ([Maksim Kita](https://github.com/kitaisreal)).
* S3 클라이언트에 서버 측 암호화 고객 키(Server Side Encryption Customer Keys) 지원(`x-amz-server-side-encryption-customer-(key/md5)` 헤더)을 추가했습니다. [링크](https://docs.aws.amazon.com/AmazonS3/latest/dev/ServerSideEncryptionCustomerKeys.html)를 참조하십시오. [#19428](https://github.com/ClickHouse/ClickHouse/issues/19428)을 닫습니다. [#19748](https://github.com/ClickHouse/ClickHouse/pull/19748) ([Vladimir Chebotarev](https://github.com/excitoon)).
* 함수 `reinterpretAs`를 업데이트하여 큰 정수를 지원하도록 했습니다. [#19691](https://github.com/ClickHouse/ClickHouse/issues/19691)을 수정했습니다. [#19858](https://github.com/ClickHouse/ClickHouse/pull/19858) ([Maksim Kita](https://github.com/kitaisreal)).
* 분산 테이블에서 특정 세그먼트에 데이터를 삽입할 수 있도록 `insert_shard_id` 설정을 추가했습니다. [#19961](https://github.com/ClickHouse/ClickHouse/pull/19961) ([flynn](https://github.com/ucasfl)).
* UTC로부터의 오프셋을 초 단위로 반환하는 `timezoneOffset(datetime)` 함수를 추가했습니다. 이로써 [#issue:19850](https://github.com/ClickHouse/ClickHouse/issues/19850)이 해결됩니다. [#19962](https://github.com/ClickHouse/ClickHouse/pull/19962) ([keenwolf](https://github.com/keen-wolf)).
* `system.part_log` 테이블에 새로운 `event_time_microseconds` 컬럼을 추가했습니다. [#20027](https://github.com/ClickHouse/ClickHouse/pull/20027) ([Bharat Nallan](https://github.com/bharatnc)).
* ... 연속된 행 간 차이를 합산하는 집계 함수 `deltaSum`을 추가했습니다. [#20057](https://github.com/ClickHouse/ClickHouse/pull/20057) ([Russ Frank](https://github.com/rf)).
* 비활성 파트가 너무 많을 때 삽입을 지연시키거나 오류를 발생시키는 두 개의 설정을 추가했습니다. 이는 서버가 파트를 충분히 빠르게 정리하지 못할 때 유용합니다. [#20178](https://github.com/ClickHouse/ClickHouse/pull/20178) ([Amos Bird](https://github.com/amosbird)).
* file engine 설정 `engine_file_empty_if_not_exists` 및 `engine_file_truncate_on_insert`를 추가했습니다. [#20620](https://github.com/ClickHouse/ClickHouse/pull/20620) ([M0r64n](https://github.com/M0r64n)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* `do_not_merge_across_partitions_select_final` 설정이 1일 때 `level>0`인 단일 part에 대해 병렬 select final을 추가했습니다. [#19375](https://github.com/ClickHouse/ClickHouse/pull/19375) ([Kruglov Pavel](https://github.com/Avogar)).
* 조인 수행 중 비트맵 컬럼의 성능을 개선했습니다. [#19407](https://github.com/ClickHouse/ClickHouse/pull/19407) ([templarzq](https://github.com/templarzq)).
* 수신 및 송신 데이터의 복사 횟수를 줄이기 위해 HTTP server를 부분적으로 재구현했습니다. 이를 통해 HTTP로 긴 레코드를 삽입할 때 최대 1.5배의 성능 향상을 얻을 수 있습니다. [#19516](https://github.com/ClickHouse/ClickHouse/pull/19516) ([Ivan](https://github.com/abyss7)).
* 더 엄격한 aliasing을 통해 집계 함수의 성능을 개선했습니다. [#19946](https://github.com/ClickHouse/ClickHouse/pull/19946) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* DataType parser에서 지수 시간 복잡도가 발생할 수 있는 문제를 수정했습니다(퍼저가 발견). 이로써 [#20096](https://github.com/ClickHouse/ClickHouse/issues/20096)이 해결되었습니다. [#20132](https://github.com/ClickHouse/ClickHouse/pull/20132) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `Memory` 테이블에 `compress` 설정을 추가했습니다. 이 설정을 활성화하면 테이블의 RAM 사용량이 줄어듭니다. 일부 머신과 데이터셋에서는 SELECT도 더 빠르게 동작할 수 있지만, 항상 그런 것은 아닙니다. 이로써 [#20093](https://github.com/ClickHouse/ClickHouse/issues/20093)이 해결되었습니다. 참고: Memory 테이블이 MergeTree보다 느릴 수 있는 이유는 (1) 압축 부재 (2) 고정된 block 크기 (3) 인덱스와 prewhere 부재 등이 있습니다. [#20168](https://github.com/ClickHouse/ClickHouse/pull/20168) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Memory 테이블에 INSERT SELECT로 삽입할 때 blocks를 지나치게 squash하지 않도록 했습니다. 이전 버전에서는 INSERT SELECT 이후 Memory 테이블에 비효율적인 데이터 표현이 생성되었습니다. 이로써 [#13052](https://github.com/ClickHouse/ClickHouse/issues/13052)가 해결되었습니다. [#20169](https://github.com/ClickHouse/ClickHouse/pull/20169) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 여러 개의 고정 크기 field에 대한 집계 성능을 개선했습니다(미확인). [#20454](https://github.com/ClickHouse/ClickHouse/pull/20454) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 극단적인 경우(`50 GB/sec` 수준의 읽기 속도)에서 `Memory` 테이블 읽기 속도를 높이기 위해 pipeline을 단순화했고, 그 결과 pipeline scheduling에서 잠금 경합도 줄였습니다. [#20468](https://github.com/ClickHouse/ClickHouse/pull/20468) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 여러 개의 고정 크기 key에 대한 GROUP BY 성능을 개선했습니다. [#20472](https://github.com/ClickHouse/ClickHouse/pull/20472) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `distributed_aggregation_memory_efficient` 설정이 기본적으로 활성화됩니다. 이 설정은 메모리 사용량을 줄이고 분산 쿼리의 성능을 개선합니다. [#20599](https://github.com/ClickHouse/ClickHouse/pull/20599) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 집계 관련 code를 약간 개선했습니다. [#20978](https://github.com/ClickHouse/ClickHouse/pull/20978) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 성능 향상을 위해 intDiv/module vectorConstant 특수화를 다시 추가했습니다. 이로써 [#21293](https://github.com/ClickHouse/ClickHouse/issues/21293)이 수정되었습니다. 이 회귀는 [https://github.com/ClickHouse/ClickHouse/pull/18145](https://github.com/ClickHouse/ClickHouse/pull/18145)에서 도입되었습니다. [#21307](https://github.com/ClickHouse/ClickHouse/pull/21307) ([Amos Bird](https://github.com/amosbird)).

<div id="improvement">
  #### 개선 사항
</div>

* `TTL` 표현식이 함수이며 `ORDER BY` 키와 동일한 경우 `TTL`이 생성되지 않던 문제를 수정했습니다. 이제 `GROUP BY`와 함께 `TTL`에서 프라이머리 키 컬럼에 사용자 지정 집계를 설정할 수 있습니다. 하위 호환되지 않는 변경 사항: TTL이 만료될 때 `GROUP BY`에 포함되지 않고 명시적으로 설정되지 않은 프라이머리 키 컬럼에는 이제 `max` 대신 `any` 함수가 적용됩니다. 또한 `WHERE` 또는 `GROUP BY`와 함께 TTL을 사용하는 경우 rolling update 중 merges에서 예외가 발생할 수 있습니다. [#15450](https://github.com/ClickHouse/ClickHouse/pull/15450) ([Anton Popov](https://github.com/CurtizJ)).
* 원격 쿼리를 위한 Hedged Requests를 추가했습니다. `use_hedged_requests` 설정이 활성화되면(기본값) 쿼리 실행을 위해 서로 다른 레플리카에 여러 연결을 설정할 수 있습니다. 기존 연결이 `hedged_connection_timeout` 내에 레플리카에 연결되지 않거나 `receive_data_timeout` 내에 데이터를 받지 못한 경우 새 연결이 활성화됩니다. 쿼리는 비어 있지 않은 progress packet(또는 `allow_changing_replica_until_first_data_packet`이 설정된 경우 data packet)을 먼저 보내는 첫 번째 연결을 사용하고, 다른 연결은 취소됩니다. `max_parallel_replicas > 1`인 쿼리도 지원합니다. [#19291](https://github.com/ClickHouse/ClickHouse/pull/19291) ([Kruglov Pavel](https://github.com/Avogar)).
* 치명적인 스택트레이스에 인라인 프레임을 출력합니다. [#19317](https://github.com/ClickHouse/ClickHouse/pull/19317) ([Ivan](https://github.com/abyss7)).
* 쓰기 오류를 더 이상 조용히 무시하지 않습니다. [#19451](https://github.com/ClickHouse/ClickHouse/pull/19451) ([Azat Khuzhin](https://github.com/azat)).
* 테이블에 row-level security 표현식이 지정된 경우 `PREWHERE`를 지원하도록 추가했습니다. [#19576](https://github.com/ClickHouse/ClickHouse/pull/19576) ([Denis Glazachev](https://github.com/traceon)).
* IStoragePolicy interface를 추가했습니다. [#19608](https://github.com/ClickHouse/ClickHouse/pull/19608) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* 비동기 전송을 위해 대기 중인 바이트 수를 기준으로 Distributed에 대한 INSERT를 제한하는 기능을 추가했습니다(`Distributed` engine에 `bytes_to_delay_insert`/`max_delay_to_insert` 및 `bytes_to_throw_insert` 설정 추가). [#19673](https://github.com/ClickHouse/ClickHouse/pull/19673) ([Azat Khuzhin](https://github.com/azat)).
* JOIN과 관련 없는 조건을 WHERE 절로 이동합니다. [#18720](https://github.com/ClickHouse/ClickHouse/issues/18720). [#19685](https://github.com/ClickHouse/ClickHouse/pull/19685) ([hexiaoting](https://github.com/hexiaoting)).
* Buffer profile용 별도 구성 directive를 추가했습니다. [#19721](https://github.com/ClickHouse/ClickHouse/pull/19721) ([Azat Khuzhin](https://github.com/azat)).
* `system.parts`에 MaterializeMySQL 테이블을 표시합니다. [#19770](https://github.com/ClickHouse/ClickHouse/pull/19770) ([Stig Bakken](https://github.com/stigsb)).
* 재시작 후 MaxDDLEntryID를 마지막 값으로 초기화합니다. 이 PR 이전에는 새 DDLTask가 처리될 때까지 MaxDDLEntryID가 0으로 유지되었습니다. [#19924](https://github.com/ClickHouse/ClickHouse/pull/19924) ([Amos Bird](https://github.com/amosbird)).
* 구조가 일치하지 않는 경우 분산 테이블에 대한 INSERT 시 블록 구조 변환을 추가했습니다. [#19947](https://github.com/ClickHouse/ClickHouse/pull/19947) ([Azat Khuzhin](https://github.com/azat)).
* 사용자가 `JSONExtract` 함수에서 `Float32` 유형을 요청한 경우 결과 유형으로의 부정확한 변환을 허용합니다. 예를 들어 JSON의 숫자 `0.1`은 배정밀도이므로 Float32로 정확히 표현할 수 없지만, 사용자는 여전히 그 값을 얻고자 할 수 있습니다. 이전 버전은 변환이 부정확함을 나타내기 위해 널 허용이 아닌 유형에는 0을, 널 허용 유형에는 NULL을 반환했습니다. 이 로직은 100% 정확했지만 사용자에게는 의외였고 많은 질문을 낳았습니다. 이는 [#13962](https://github.com/ClickHouse/ClickHouse/issues/13962)를 해결합니다. [#19960](https://github.com/ClickHouse/ClickHouse/pull/19960) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 이제 mysql 레플리카의 구성 섹션에 있는 &quot;opt&#95;reconnect&quot; 매개변수로 MYSQL&#95;OPT&#95;RECONNECT 옵션 값을 제어할 수 있습니다. [#19998](https://github.com/ClickHouse/ClickHouse/pull/19998) ([Alexander Kazakov](https://github.com/Akazz)).
* 다른 스토리지 인터페이스와 마찬가지로 IDisk::getType()에서 `String` 대신 `DiskType`을 반환합니다. [#19999](https://github.com/ClickHouse/ClickHouse/pull/19999) ([Ernest Zaslavsky](https://github.com/kreuzerkrieg)).
* 실행형 딕셔너리에서 발생할 수 있던 data race를 수정했습니다. 이 문제는 잘못 사용한 경우에만 발생할 수 있었습니다(스크립트가 입력을 무시하고 데이터를 반환하는 경우). [#20045](https://github.com/ClickHouse/ClickHouse/pull/20045) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `system.tables`에 MaterializeMySQL 테이블의 전체 세부 정보를 표시합니다. [#20051](https://github.com/ClickHouse/ClickHouse/pull/20051) ([Stig Bakken](https://github.com/stigsb)).
* 쿼리에서 system.zookeeper 경로에 대한 IN을 지원합니다. [#20105](https://github.com/ClickHouse/ClickHouse/pull/20105) ([小路](https://github.com/nicelulu)).
* 1. 할당량 계산에서 이제 SHOW TABLES는 2개의 쿼리가 아니라 1개의 쿼리로 간주됩니다. 2. 이제 SYSTEM 쿼리에도 할당량이 적용됩니다. 3. 할당량 사용량 계산에서 인터벌 종료 시점 계산을 수정했습니다. [#20106](https://github.com/ClickHouse/ClickHouse/pull/20106) ([Vitaly Baranov](https://github.com/vitlibar)).
* * DateTime64의 `toDateTime64(toDate()/toDateTime())` 수정 - DateTime 동작에 맞도록 DateTime64 클램핑을 구현합니다. [#20131](https://github.com/ClickHouse/ClickHouse/pull/20131) ([Azat Khuzhin](https://github.com/azat)).
* 이제 시작 시 `CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT`를 지정해 `access_management` 설정을 구성할 수 있습니다. 기본값은 이전과 동일하게 비활성화(`0`)입니다. [#20139](https://github.com/ClickHouse/ClickHouse/pull/20139) ([Marquitos](https://github.com/sonirico)).
