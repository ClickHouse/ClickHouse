<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 유형으로 `seconds`를 사용하는 설정의 파싱 방식이 부동소수점 값을 지원하도록 변경되었습니다(예: `max_execution_time=0.5`). Infinity 또는 NaN 값은 예외를 발생시킵니다. [#37187](https://github.com/ClickHouse/ClickHouse/pull/37187) ([Raúl Marín](https://github.com/Algunenano)).
* 실험적 유형 `Object` 컬럼의 바이너리 직렬화 포맷이 변경되었습니다. 새 포맷은 타사 클라이언트에서 구현하기가 더 편리합니다. [#37482](https://github.com/ClickHouse/ClickHouse/pull/37482) ([Anton Popov](https://github.com/CurtizJ)).
* 설정 `output_format_json_named_tuples_as_objects`가 기본적으로 활성화됩니다. 이를 통해 JSON 포맷에서 이름이 지정된 Tuple을 JSON 객체로 직렬화할 수 있습니다. [#37756](https://github.com/ClickHouse/ClickHouse/pull/37756) ([Anton Popov](https://github.com/CurtizJ)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* ORDER BY에 여러 컬럼이 있는 경우 MergeTree에 대한 삽입 성능을 개선했습니다. [#35762](https://github.com/ClickHouse/ClickHouse/pull/35762) ([Maksim Kita](https://github.com/kitaisreal)).
* StorageHive에 `threadpool` 읽기 메서드를 적용했습니다. [#36328](https://github.com/ClickHouse/ClickHouse/pull/36328) ([李扬](https://github.com/taiyang-li)).
* 이제 `FINAL`이 포함된 쿼리의 실행을 더 높은 데이터 병렬성으로 처리할 수 있도록, 전체 파트가 아니라 데이터 파트를 레이어로 나누어 스레드에 분배합니다. [#36396](https://github.com/ClickHouse/ClickHouse/pull/36396) ([Nikita Taranov](https://github.com/nickitat)).
* 와이드 파트를 읽을 때 필요한 컬럼의 마크만 로드합니다. [#36879](https://github.com/ClickHouse/ClickHouse/pull/36879) ([Anton Kozlov](https://github.com/tonickkozlov)).
* 읽어야 할 모든 컬럼이 파티션 키인 경우, 실제로 hive 파일을 읽지 않고 파일의 행 번호를 기반으로 컬럼을 구성합니다. [#37103](https://github.com/ClickHouse/ClickHouse/pull/37103) ([lgbo](https://github.com/lgbo-ustc)).
* `dictGetDescendants`, `dictGetChildren` 함수의 성능을 개선했습니다. 쿼리 실행 중 함수 호출마다가 아니라 쿼리별로 임시 parent-to-children 계층 인덱스를 생성합니다. 또한 `HIERARHICAL` 속성에 `BIDIRECTIONAL`을 지정할 수 있게 했으며, 이 경우 딕셔너리가 메모리에서 parent-to-children 인덱스를 유지합니다. 따라서 `dictGetDescendants`, `dictGetChildren` 함수가 쿼리마다 임시 인덱스를 생성하지 않습니다. [#32481](https://github.com/ClickHouse/ClickHouse/issues/32481)을 해결했습니다. [#37148](https://github.com/ClickHouse/ClickHouse/pull/37148) ([Maksim Kita](https://github.com/kitaisreal)).
* Native, Protobuf, CapnProto, JSONEachRow, TSKV 포맷과 WithNames/WithNamesAndTypes 접미사가 있는 모든 포맷에서 컬럼 부분 집합을 select할 때의 성능과 메모리 사용량을 개선했습니다. 이전에는 이러한 포맷의 파일에서 일부 컬럼만 선택하더라도 모든 컬럼을 읽어 메모리에 저장했습니다. 이제는 필요한 컬럼만 읽습니다. 또한 이 PR에서는 기본적으로 `input_format_skip_unknown_fields` 설정을 활성화합니다. 그렇지 않으면 컬럼 부분 집합을 select할 때 예외가 발생하기 때문입니다. [#37192](https://github.com/ClickHouse/ClickHouse/pull/37192) ([Kruglov Pavel](https://github.com/Avogar)).
* 단일 컬럼 기준 정렬 성능을 개선했습니다. [#37195](https://github.com/ClickHouse/ClickHouse/pull/37195) ([Maksim Kita](https://github.com/kitaisreal)).
* hive 파일 캐싱을 위해 여러 disks를 지원합니다. [#37279](https://github.com/ClickHouse/ClickHouse/pull/37279) ([lgbo](https://github.com/lgbo-ustc)).
* 배열 norm 및 거리 함수의 성능을 2~4배 개선했습니다. [#37394](https://github.com/ClickHouse/ClickHouse/pull/37394) ([Alexander Gololobov](https://github.com/davenger)).
* dynamic dispatch를 사용해 숫자 비교 함수의 성능을 개선했습니다. [#37399](https://github.com/ClickHouse/ClickHouse/pull/37399) ([Maksim Kita](https://github.com/kitaisreal)).
* LIMIT가 있는 ORDER BY의 성능을 개선했습니다. [#37481](https://github.com/ClickHouse/ClickHouse/pull/37481) ([Maksim Kita](https://github.com/kitaisreal)).
* dynamic dispatch 인프라를 사용해 `hasAll` 함수의 성능을 개선했습니다. [#37484](https://github.com/ClickHouse/ClickHouse/pull/37484) ([Maksim Kita](https://github.com/kitaisreal)).
* `greatCircleAngle`, `greatCircleDistance`, `geoDistance` 함수의 성능을 개선했습니다. [#37524](https://github.com/ClickHouse/ClickHouse/pull/37524) ([Maksim Kita](https://github.com/kitaisreal)).
* 예를 들어 LIKE 및 MATCH 함수에서 사용되는 re2 패턴의 내부 캐싱을 최적화했습니다. [#37544](https://github.com/ClickHouse/ClickHouse/pull/37544) ([Robert Schulze](https://github.com/rschu1ze)).
* avx512 명령어를 사용해 필터 비트마스크 생성 함수를 올인원으로 개선했습니다. [#37588](https://github.com/ClickHouse/ClickHouse/pull/37588) ([yaqi-zhao](https://github.com/yaqi-zhao)).
* 희소 컬럼(`MergeTree` 테이블에서 실험적 설정 `ratio_of_defaults_for_sparse_serialization`으로 활성화 가능)을 집계 함수의 인수로 사용할 때 집계 성능을 개선했습니다. [#37617](https://github.com/ClickHouse/ClickHouse/pull/37617) ([Anton Popov](https://github.com/CurtizJ)).
* 인수가 2개인 `COALESCE` 함수를 최적화했습니다. [#37666](https://github.com/ClickHouse/ClickHouse/pull/37666) ([Anton Popov](https://github.com/CurtizJ)).
* `multiIf`에 조건이 하나만 있는 경우 `if` 함수가 더 빠르므로 `multiIf`를 `if`로 대체합니다. [#37695](https://github.com/ClickHouse/ClickHouse/pull/37695) ([Anton Popov](https://github.com/CurtizJ)).
* 이제 집계 상태의 소멸 처리를 스레드 풀에서 수행할 수 있습니다. LIMIT가 있고 상태가 큰 쿼리에서 상당한 속도 향상을 제공합니다. 예를 들어 `select uniq(number) from numbers_mt(1e7) group by number limit 100`는 약 2.5배 더 빨라졌습니다. [#37855](https://github.com/ClickHouse/ClickHouse/pull/37855) ([Nikita Taranov](https://github.com/nickitat)).
* 정렬 큐 특수화를 사용해 단일 컬럼 정렬 성능을 개선했습니다. [#37990](https://github.com/ClickHouse/ClickHouse/pull/37990) ([Maksim Kita](https://github.com/kitaisreal)).
* 테이블이 많을 때 백그라운드에서 발생하던 과도한 CPU 사용량을 수정했습니다. [#38028](https://github.com/ClickHouse/ClickHouse/pull/38028) ([Maksim Kita](https://github.com/kitaisreal)).
* 동적 디스패치를 사용해 `not` 함수의 성능을 개선했습니다. [#38058](https://github.com/ClickHouse/ClickHouse/pull/38058) ([Maksim Kita](https://github.com/kitaisreal)).
* 주요 라이브러리에 NEON 가속 경로를 다수 추가했습니다. [#38093](https://github.com/ClickHouse/ClickHouse/pull/38093) ([Daniel Kutenin](https://github.com/danlark1)).

* 함수에 Nothing에 대한 기본 구현을 추가합니다. 이제 인수 중 하나가 Nothing이면 대부분의 함수는 Nothing 타입의 컬럼을 반환합니다. 또한 arrayMap/arrayFilter 같은 함수 및 유사한 함수에 빈 배열이 인수로 전달될 때 발생하던 문제도 해결합니다. 이전에는 `select arrayMap(x -> 2 * x, []);` 같은 쿼리가 lambda 내부의 함수가 `Nothing` 타입에서 동작할 수 없어 실패했지만, 이제는 `Array(Nothing)` 타입의 빈 배열을 반환합니다. 또한 arrayFilter/arrayFill 같은 함수에서 널 허용 타입 배열도 지원합니다. 이전에는 `select arrayFilter(x -> x % 2, [1, NULL])` 같은 쿼리가 실패했지만, 이제는 정상적으로 동작합니다(lambda의 결과가 NULL이면 해당 값은 결과에 포함되지 않음). 이로써 [#37000](https://github.com/ClickHouse/ClickHouse/issues/37000)도 해결합니다. [#37048](https://github.com/ClickHouse/ClickHouse/pull/37048) ([Kruglov Pavel](https://github.com/Avogar)).
* 이제 세그먼트에 로컬 레플리카가 있으면 로컬 계획과 모든 원격 레플리카에서 읽기 위한 계획을 생성합니다. 이들은 읽기를 조정하는 공유 initiator를 사용합니다. [#37204](https://github.com/ClickHouse/ClickHouse/pull/37204) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
