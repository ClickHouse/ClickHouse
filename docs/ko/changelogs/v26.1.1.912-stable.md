<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 포매터에서 alias의 잘못된 치환으로 인해 발생하는 일관성 없는 포매팅을 수정하였습니다. [#82833](https://github.com/ClickHouse/ClickHouse/issues/82833), [#82832](https://github.com/ClickHouse/ClickHouse/issues/82832), [#68296](https://github.com/ClickHouse/ClickHouse/issues/68296) 종료. 이 변경 사항은 하위 호환되지 않을 수 있습니다. 분석기가 비활성화된 경우, alias를 참조하는 IN이 포함된 일부 CREATE VIEW 쿼리를 처리할 수 없습니다. 비호환성을 방지하려면 분석기를 활성화하십시오(24.3부터 기본적으로 활성화되어 있습니다). [#82838](https://github.com/ClickHouse/ClickHouse/pull/82838) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 코덱 `DEFLATE_QPL` 및 `ZSTD_QAT`가 제거되었습니다. 업그레이드 전에 `DEFLATE_QPL` 또는 `ZSTD_QAT`로 압축된 기존 데이터를 다른 코덱으로 변환하시기 바랍니다. 참고로, 이 코덱들을 사용하려면 `enable_deflate_qpl_codec` 및 `enable_zstd_qat_codec` 설정이 활성화되어 있어야 했습니다. [#92150](https://github.com/ClickHouse/ClickHouse/pull/92150) ([Robert Schulze](https://github.com/rschu1ze)).
* `system.query_log.exception`에서 stderr 캡처를 활성화하여 UDF 디버깅 문제를 수정하였습니다. 이전에는 UDF의 stderr가 파일에만 기록되고 쿼리 로그에는 노출되지 않아 디버깅이 불가능했습니다. 이제 stderr는 기본적으로 예외를 발생시키며, 예외를 던지기 전에 최대 1MB까지 누적됩니다. 따라서 Python 전체 트레이스백 및 오류 메시지가 `system.query_log.exception`에 표시되어 효과적인 문제 해결이 가능합니다. [#92209](https://github.com/ClickHouse/ClickHouse/pull/92209) ([Xu Jia](https://github.com/XuJia0210)).
* `JOIN USING ()` 절에서 빈 컬럼 목록은 이제 구문 오류로 처리됩니다. 이전에는 쿼리 실행 중 `INVALID_JOIN_ON_EXPRESSION`으로 처리되었으며, `Join` 스토리지와 조인하는 경우 등 일부 상황에서는 `LOGICAL_ERROR`가 발생하였습니다. [#82502](https://github.com/ClickHouse/ClickHouse/issues/82502) 종료. [#92371](https://github.com/ClickHouse/ClickHouse/pull/92371) ([Vladimir Cherkasov](https://github.com/vdimir)).
* JSON에 대한 고급 공유 데이터를 기본적으로 활성화합니다. 이 변경 이후에는 25.8 미만 버전으로 다운그레이드할 수 없습니다. 해당 버전들은 JSON 컬럼이 포함된 새로운 데이터 파트를 읽을 수 없기 때문입니다. 안전한 업그레이드를 위해 `compatibility` 설정을 이전 버전으로 지정하거나, MergeTree 설정 `dynamic_serialization_version='v2', object_serialization_version='v2'`를 지정하는 것을 권장합니다. [#92511](https://github.com/ClickHouse/ClickHouse/pull/92511) ([Pavel Kruglov](https://github.com/Avogar)).
* JSON 타입에서 SKIP REGEXP에 대해 기본적으로 부분 일치를 사용합니다. [#79250](https://github.com/ClickHouse/ClickHouse/issues/79250) 종료. [#92847](https://github.com/ClickHouse/ClickHouse/pull/92847) ([Pavel Kruglov](https://github.com/Avogar)).
* &quot;단순 ALIAS 컬럼에 INSERT 허용&quot;을 되돌립니다(ClickHouse/ClickHouse[#84154](https://github.com/ClickHouse/ClickHouse/issues/84154) 되돌리기). 커스텀 포맷과 호환되지 않으며, 설정으로 보호되어 있지 않습니다. [#92849](https://github.com/ClickHouse/ClickHouse/pull/92849) ([Azat Khuzhin](https://github.com/azat)).
* 데이터레이크 카탈로그가 객체 스토리지에 접근할 수 없는 경우 오류를 발생시키는 설정이 추가되었습니다. [#93606](https://github.com/ClickHouse/ClickHouse/pull/93606) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* `Lazy` 데이터베이스 엔진이 제거되어 더 이상 사용할 수 없습니다. [#91231](https://github.com/ClickHouse/ClickHouse/issues/91231) 종료. [#93627](https://github.com/ClickHouse/ClickHouse/pull/93627) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `metric_log`의 `transposed_with_wide_view` 모드를 제거합니다. 버그로 인해 사용할 수 없는 상태였으며, 이 모드로 `system.metric_log`를 정의하는 것은 더 이상 불가능합니다. [#78412](https://github.com/ClickHouse/ClickHouse/issues/78412)를 부분적으로 되돌립니다. [#93867](https://github.com/ClickHouse/ClickHouse/pull/93867) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 워크로드에 대한 CPU 스케줄링이 이제 기본적으로 선점형(preemptive)으로 동작합니다. `cpu_slot_preemption` 서버 설정을 참조하십시오. [#94060](https://github.com/ClickHouse/ClickHouse/pull/94060) ([Sergei Trifonov](https://github.com/serxa)).
* 손상된 파트를 방지하기 위해 인덱스 파일명을 이스케이프 처리합니다. 이 변경으로 인해 ClickHouse는 이전 버전에서 생성된 비 ASCII 문자가 포함된 인덱스를 로드하지 못합니다. 이를 처리하려면 MergeTree 설정 `escape_index_filenames`를 사용하십시오. [#94079](https://github.com/ClickHouse/ClickHouse/pull/94079) ([Raúl Marín](https://github.com/Algunenano)).
* 포맷 설정 `exact_rows_before_limit`, `rows_before_aggregation`, `cross_to_inner_join_rewrite`, `regexp_dict_allow_hyperscan`, `regexp_dict_flag_case_insensitive`, `regexp_dict_flag_dotall`, `dictionary_use_async_executor`가 이제 일반(비포맷) 설정으로 변경되었습니다. 이는 순수하게 내부적인 변경으로, Iceberg, DeltaLake, Kafka, S3, S3Queue, Azure, Hive, RabbitMQ, Set, FileLog, NATS 테이블 엔진 정의에 이러한 설정을 지정한 경우(가능성은 낮지만)를 제외하면 사용자에게 보이는 부작용이 없습니다. 해당 경우, 이전에는 이 설정들이 무시되었으나 이제는 오류가 발생합니다. [#94106](https://github.com/ClickHouse/ClickHouse/pull/94106) ([Robert Schulze](https://github.com/rschu1ze)).
* `joinGet/joinGetOrNull` 함수는 이제 기반 Join 테이블에 대한 `SELECT` 권한을 강제합니다. 이 변경 이후, `joinGet('db.table', 'column', key)` 실행 시 사용자는 Join 테이블에 정의된 키 컬럼과 조회하는 속성 컬럼 모두에 대해 `SELECT` 권한을 보유해야 합니다. 해당 권한이 없는 쿼리는 `ACCESS_DENIED` 오류로 실패합니다. 마이그레이션을 위해 전체 테이블 접근에는 `GRANT SELECT ON db.join_table TO user`를, 컬럼 수준 접근에는 `GRANT SELECT(key_col, attr_col) ON db.join_table TO user`를 사용하여 필요한 권한을 부여하십시오. 이 변경 사항은 이전에 명시적인 `SELECT` 권한이 구성되지 않은 상태에서 `joinGet`/`joinGetOrNull`에 의존하는 모든 사용자 및 애플리케이션에 영향을 미칩니다. [#94307](https://github.com/ClickHouse/ClickHouse/pull/94307) ([Vladimir Cherkasov](https://github.com/vdimir)).
* `CREATE TABLE ... AS ...` 쿼리에 대해 `SHOW COLUMNS` 권한을 확인합니다. 이전에는 `SHOW TABLES`를 확인하였는데, 이는 해당 유형의 권한 확인에 적절하지 않은 권한이었습니다. [#94556](https://github.com/ClickHouse/ClickHouse/pull/94556) ([pufit](https://github.com/pufit)).

* `<interactive_history_legacy_keymap>true</interactive_history_legacy_keymap>`를 사용하면 이제 CLI 클라이언트가 이전처럼 일반 검색에 Ctrl R을 사용하도록 폴백될 수 있으며, Ctrl T는 퍼지 검색을 수행합니다. [#87785](https://github.com/ClickHouse/ClickHouse/pull/87785) ([Larry Snizek](https://github.com/larry-cdn77)).
* 이제 async insert 중복 제거가 종속된 materialized view와도 함께 작동합니다. block&#95;id 충돌이 발생하면 원래 블록을 필터링해 해당 block&#95;id와 연관된 행을 제거하고, 남은 행에 관련된 모든 materialized view SELECT 쿼리를 적용하여 충돌하는 행이 없는 원래 블록을 다시 구성합니다. [#89140](https://github.com/ClickHouse/ClickHouse/pull/89140) ([Sema Checherinda](https://github.com/CheSema)).
* clickhouse client가 서버에 연결할 때 TLS SNI를 재정의할 수 있는 기능이 추가되었습니다. [#89761](https://github.com/ClickHouse/ClickHouse/pull/89761) ([Matt Klein](https://github.com/mattklein123)).
* Array 컬럼에 대한 text index 지원을 추가했습니다. [#89895](https://github.com/ClickHouse/ClickHouse/pull/89895) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* 새 system table zookeeper&#95;info가 추가되었습니다. [#88014](https://github.com/ClickHouse/ClickHouse/issues/88014)를 수정합니다. [#90809](https://github.com/ClickHouse/ClickHouse/pull/90809) ([Smita Kulkarni](https://github.com/SmitaRKulkarni)).
* 함수에서 variant type을 지원하기 위해 FunctionVariantAdaptor를 구현했습니다. [#90900](https://github.com/ClickHouse/ClickHouse/pull/90900) ([Bharat Nallan](https://github.com/bharatnc)).
* 주로 버전 정보를 담은 `ClickHouse_Info` 메트릭을 Prometheus `/metrics` 엔드포인트에 추가하여, 시간 경과에 따른 상세 버전 정보를 추적하는 차트를 만들 수 있게 했습니다. [#91125](https://github.com/ClickHouse/ClickHouse/pull/91125) ([Christoph Wurm](https://github.com/cwurm)).
* 클러스터 구성을 변경할 수 있는 Keeper용 새로운 네 글자 `rcfg` 명령을 도입했습니다. 이 명령은 표준 `reconfigure` request보다 더 폭넓은 구성 변경 기능을 제공합니다. 이 명령은 `json` 문자열을 인수로 받습니다. TCP interface로 전송되는 전체 바이트 집합은 다음과 같아야 합니다: `rcfg{json_string_length_big_endian}{json_string}`. 명령 예시는 다음과 같습니다: `{"preconditions": {"leaders": [1, 2], "members": [1, 2, 3, 4, 5]}, "actions": [{"transfer_leadership": [3]}, {"remove_members": [1, 2]}, {"set_priority": [{"id": 4, "priority": 100}, {"id": 5, "priority": 100}]}, {"transfer_leadership": [4, 5]}, {"set_priority": [{"id": 3, "priority": 0}]}]}`. [#91354](https://github.com/ClickHouse/ClickHouse/pull/91354) ([alesapin](https://github.com/alesapin)).
* 지정한 구분자로 나뉜 문자열의 부분 문자열 순서를 뒤집는 함수 `reverseBySeparator`를 추가했습니다. [#91463](https://github.com/ClickHouse/ClickHouse/issues/91463)을 해결합니다. [#91780](https://github.com/ClickHouse/ClickHouse/pull/91780) ([Xuewei Wang](https://github.com/Sallery-X)).
* projection 인덱스 기능을 단순화하고 확장하기 위한 새로운 구문과 프레임워크를 도입했습니다. 이는 https://github.com/ClickHouse/ClickHouse/pull/81021의 후속 작업입니다. [#91844](https://github.com/ClickHouse/ClickHouse/pull/91844) ([Amos Bird](https://github.com/amosbird)).
* https://github.com/ClickHouse/ClickHouse/pull/84423에 이어 Paimon REST 카탈로그를 지원합니다. [#92011](https://github.com/ClickHouse/ClickHouse/pull/92011) ([JIaQi Tang](https://github.com/JiaQiTang98)).
* 삽입되는 블록의 형성을 더 세밀하게 제어하는 새로운 설정 `max_insert_block_size_bytes`를 추가했습니다. [#92833](https://github.com/ClickHouse/ClickHouse/pull/92833) ([Kirill Kopnev](https://github.com/Fgrtue)).
* `ignore_on_cluster_for_replicated_database` 설정이 활성화되어 있으면 복제된 데이터베이스에 대해 `ON CLUSTER` 절이 있는 DDL 쿼리를 실행할 수 있습니다. 이 경우 cluster 이름은 무시됩니다. [#92872](https://github.com/ClickHouse/ClickHouse/pull/92872) ([Kirill](https://github.com/kirillgarbar)).
* `mergeTreeAnalyzeIndex()` 함수를 구현했습니다. [#92954](https://github.com/ClickHouse/ClickHouse/pull/92954) ([Azat Khuzhin](https://github.com/azat)).
* 새로운 설정 `use_primary_key`를 추가했습니다. 프라이머리 키 기반의 Granule pruning을 비활성화하려면 이 값을 `false`로 설정하십시오. [#93319](https://github.com/ClickHouse/ClickHouse/pull/93319) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `icebergLocalCluster` 테이블 함수. [#93323](https://github.com/ClickHouse/ClickHouse/pull/93323) ([Anton Ivashkin](https://github.com/ianton-ru)).
* Datalakes prewhere 및 Parquet 리더 v3의 multistage prewhere로 [#89101](https://github.com/ClickHouse/ClickHouse/issues/89101)을 해결했습니다. [#93542](https://github.com/ClickHouse/ClickHouse/pull/93542) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 두 Point 사이의 [cosine distance](https://en.wikipedia.org/wiki/Cosine_similarity#Cosine_distance)를 근사하는 `cosineDistanceTransposed` 함수를 추가했습니다. [#93621](https://github.com/ClickHouse/ClickHouse/pull/93621) ([Raufs Dunamalijevs](https://github.com/rienath)).
* 기존의 캐시 정리 statement인 `SYSTEM DROP [...] CACHE`는 이 statement가 캐시를 비활성화하는 것으로 오해될 여지가 있었습니다. 이제 ClickHouse는 더 명확한 `SYSTEM CLEAR [...] CACHE` statement를 지원합니다. 기존 구문도 계속 사용할 수 있습니다. [#93727](https://github.com/ClickHouse/ClickHouse/pull/93727) ([Pranav Tiwari](https://github.com/pranavt84)).
* 각 data part의 파일 수를 보여주는 files 컬럼을 system.parts 테이블에 추가했습니다. [#94337](https://github.com/ClickHouse/ClickHouse/pull/94337) ([Match](https://github.com/gayanMatch)).
* Concurrency 제어를 위한 max-min fair scheduler를 추가했습니다. 많은 쿼리가 제한된 CPU 슬롯을 두고 경쟁하는 높은 oversubscription 상황에서 더 나은 공정성을 제공합니다. 짧게 실행되는 쿼리는 시간이 지나며 더 많은 슬롯을 누적한 장시간 실행 쿼리로 인해 불이익을 받지 않습니다. `concurrent_threads_scheduler` server setting의 `max_min_fair` 값으로 활성화됩니다. [#94732](https://github.com/ClickHouse/ClickHouse/pull/94732) ([Sergei Trifonov](https://github.com/serxa)).

<div id="performance-improvement">
  #### 성능 개선

* 더 많은 필터를 JOIN으로 푸시다운합니다. [#85556](https://github.com/ClickHouse/ClickHouse/pull/85556) ([Nikita Taranov](https://github.com/nickitat)).

* 외부 필터를 뷰로 푸시다운하여 로컬 및 원격 노드에서 PREWHERE를 적용할 수 있도록 했습니다. [#88189](https://github.com/ClickHouse/ClickHouse/issues/88189)를 해결합니다. [#88316](https://github.com/ClickHouse/ClickHouse/pull/88316) ([Igor Nikonov](https://github.com/devcrafter)).
* 더 많은 함수에 대해 JIT 컴파일을 구현했습니다. [#73509](https://github.com/ClickHouse/ClickHouse/issues/73509)를 종료합니다. [#88770](https://github.com/ClickHouse/ClickHouse/pull/88770) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 소수점 단위의 `LIMIT` 및 `OFFSET`에 대한 성능과 메모리 사용량을 최적화했습니다. [#91167](https://github.com/ClickHouse/ClickHouse/pull/91167) ([Ahmed Gouda](https://github.com/0xgouda)).
