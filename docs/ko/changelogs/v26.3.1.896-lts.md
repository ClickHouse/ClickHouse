<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* 일반 프로젝션의 메타데이터를 수정하여, 다중 컬럼 sorting key를 사용하는 프로젝션을 올바르게 인식하도록 했습니다. [#90429](https://github.com/ClickHouse/ClickHouse/issues/90429)을 기반으로 합니다. [#91352](https://github.com/ClickHouse/ClickHouse/pull/91352) ([Amos Bird](https://github.com/amosbird)).
* 데이터 타입 serialization version을 중첩 데이터 타입에도 전파하도록 했습니다. 예를 들어, 이전에는 String serialization version `with_size_stream`이 최상위 String 컬럼과 Tuple 요소에만 적용되었습니다. 이제는 Array/Map/Variant/JSON 등과 같은 모든 중첩 타입 내부의 모든 String 타입에도 적용됩니다. 이 동작은 MergeTree setting `propagate_types_serialization_versions_to_nested_types`로 제어되며, 이제 기본적으로 활성화되어 있습니다. 이 변경 이후 새로 생성된 data part는 이전 버전에서 읽을 수 없지만, 기존 파트는 새 버전에서도 문제없이 읽을 수 있습니다. 즉, upgrade는 안전하지만 downgrade는 안전하지 않습니다. [#94859](https://github.com/ClickHouse/ClickHouse/pull/94859) ([Pavel Kruglov](https://github.com/Avogar)).
* `hypothesis` 스킵 인덱스 유형을 제거했습니다. 실제 활용도가 제한적인, 잘 사용되지 않던 실험적 기능이었습니다. 이제 `INDEX ... TYPE hypothesis`로 테이블을 생성하면 오류가 발생합니다. [#96874](https://github.com/ClickHouse/ClickHouse/pull/96874) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 스킵 인덱스 파일이 replace&#95;long&#95;file&#95;name&#95;to&#95;hash setting을 따르지 않아, &quot;File name too long&quot; 오류가 발생하고 긴 이름을 가진 인덱스에서 인덱스 읽기가 깨지던 문제를 수정했습니다. 이제 스킵 인덱스 파일 이름은 max&#95;file&#95;name&#95;length를 초과하면 컬럼 파일과 마찬가지로 hash 처리됩니다. 이는 하위 호환됩니다(새 서버는 이전 파트를 읽을 수 있음). 하지만 downgrade하거나 rolling upgrade 중 이전 서버를 사용하는 경우, 이름이 긴 인덱스가 무시될 수 있습니다. [#97128](https://github.com/ClickHouse/ClickHouse/pull/97128) ([Raúl Marín](https://github.com/Algunenano)).
* async insert를 기본적으로 활성화했습니다. 이제 ClickHouse는 작은 삽입을 기본적으로 모두 배칭합니다. 이 setting은 compatibility 아래에서 설정됩니다. `compatibility=<version less than 26.2>`로 설정하면 기본값은 이전과 동일한 `false`가 됩니다. async inserts는 여러 수준에서 끄거나 켤 수 있습니다. 즉, config의 users profiles, session, query 또는 MergeTree table 수준에서 설정할 수 있습니다. [#97590](https://github.com/ClickHouse/ClickHouse/pull/97590) ([Sema Checherinda](https://github.com/CheSema)).
* `NOT` 연산자의 precedence를 SQL 표준에 맞게 수정했습니다. 이제 `NOT`은 `IS NULL`, `BETWEEN`, `LIKE` 및 산술 연산자보다 느슨하게 결합됩니다. 예를 들어, 이제 `NOT (x) IS NULL`은 `(NOT x) IS NULL`이 아니라 `NOT (x IS NULL)`로 파싱됩니다. 이로 인해 이전의 비표준 동작에 의존하던 쿼리 결과가 달라질 수 있습니다. [#97680](https://github.com/ClickHouse/ClickHouse/pull/97680) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `mysql_datatypes_support_level`의 기본값을 빈 값에서 `decimal,datetime64,date2Date32`로 변경하여, 기본적으로 MySQL `DATE`는 `Date32`에, `DECIMAL`/`NUMERIC`은 `Decimal`에, precision이 있는 `DATETIME`/`TIMESTAMP`는 `DateTime64`에 올바르게 매핑되도록 했습니다. 이전에는 MySQL `DATE` 컬럼이 `Date`로 매핑되었는데, `Date`는 1970-01-01 이전 날짜를 표현할 수 없어 데이터 손상을 일으켰습니다. [#97716](https://github.com/ClickHouse/ClickHouse/pull/97716) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `mergeTreeAnalyzeIndexes{,UUID}`에서 regexp 대신 part name 배열을 허용합니다. regexps가 느리기 때문입니다(*실험적 기능*). [#98474](https://github.com/ClickHouse/ClickHouse/pull/98474) ([Azat Khuzhin](https://github.com/azat)).
* 실험적 `detectProgrammingLanguage` 함수를 제거했습니다. [#99567](https://github.com/ClickHouse/ClickHouse/pull/99567) ([Alexey Milovidov](https://github.com/alexey-milovidov)).

* 새로운 설정 `use_partition_pruning`과 별칭 `use_partition_key`를 추가했습니다. 파티션 키 기반 파티션 프루닝을 비활성화하려면 이를 `false`로 설정하십시오. [#97888](https://github.com/ClickHouse/ClickHouse/pull/97888) ([Nihal Z. Miaji](https://github.com/nihalzp)).

* `restore_access_entities_with_current_grants` 서버 설정을 추가했습니다. 활성화하면 복원된 사용자/역할에 부여되는 권한은 `ACCESS_DENIED`로 실패하는 대신, 복원을 수행하는 사용자가 부여할 수 있는 범위로 제한됩니다(`GRANT CURRENT GRANTS`와 동일한 의미). [#98795](https://github.com/ClickHouse/ClickHouse/pull/98795) ([pufit](https://github.com/pufit)).
* 유니코드 대소문자 접기와 분음 부호 제거를 위한 `caseFoldUTF8` 및 `removeDiacriticsUTF8` 함수를 추가했습니다. [#98973](https://github.com/ClickHouse/ClickHouse/pull/98973) ([George Larionov](https://github.com/george-larionov)).
* `SymbolIndex`, `addressToSymbol`, `system.symbols`, `buildId`가 이제 Mach-O 심볼 테이블을 파싱해 macOS에서 동작합니다. [#99014](https://github.com/ClickHouse/ClickHouse/pull/99014) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* NFKC 정규화와 대소문자 접기를 결합한 NFKC&#95;Casefold 유니코드 정규화를 위한 `normalizeUTF8NFKCCasefold` 문자열 함수를 추가했습니다. [#99276](https://github.com/ClickHouse/ClickHouse/pull/99276) ([George Larionov](https://github.com/george-larionov)).
* 전문 검색 인덱스와 `tokens` 함수를 위한 `unicode_word` 토크나이저를 추가했습니다. 이 토크나이저는 유니코드 단어 경계 규칙을 사용해 텍스트를 분할합니다. ASCII 단어는 연결 문자(밑줄, 콜론, 점, 작은따옴표)를 포함해 구성되며, ASCII가 아닌 유니코드 문자는 단일 문자 토큰이 됩니다. 구성 가능한 불용어의 기본값은 일반적인 CJK 문장 부호입니다. [#99357](https://github.com/ClickHouse/ClickHouse/pull/99357) ([Amos Bird](https://github.com/amosbird)).
* `skip_unavailable_shards`가 활성화되었을 때 오류 없이 건너뛸 수 있는 세그먼트 수를 제한하기 위해 `max_skip_unavailable_shards_num` 및 `max_skip_unavailable_shards_ratio` 설정을 추가했습니다. 사용 불가능한 세그먼트의 수 또는 비율이 구성된 임계값을 초과하면, 불완전한 결과를 조용히 반환하는 대신 예외가 발생합니다. [#99369](https://github.com/ClickHouse/ClickHouse/pull/99369) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 이제 사용자는 하위 쿼리 표현식에 `SOME` 키워드를 사용할 수 있습니다. 동작은 `ANY`와 동일합니다. [#99842](https://github.com/ClickHouse/ClickHouse/pull/99842) ([Artem Kytkin](https://github.com/Vinceent)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 대형 다각형에서 `pointInPolygon`의 그래뉼 스키핑을 최적화하고, 기본 키(primary key) 프루닝 중 `pointInPolygon` 인덱스 분석에서 예외가 발생하던 문제를 수정했습니다. [#91633](https://github.com/ClickHouse/ClickHouse/pull/91633) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `levenshteinDistance` 함수의 성능을 개선했습니다. [#94543](https://github.com/ClickHouse/ClickHouse/pull/94543) ([Joanna Hulboj](https://github.com/jh0x)).
* 요소마다 함수를 호출하지 않도록 하여 배치 Decimal 타입 변환을 최적화했습니다. [#95923](https://github.com/ClickHouse/ClickHouse/pull/95923) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 1. Iceberg에 메타데이터를 캐시에 비동기로 미리 채워 넣는 기능이 추가되었습니다. 이 기능은 테이블 생성 시 `iceberg_metadata_async_prefetch_period_ms`를 설정하여 활성화할 수 있습니다. 예시: `CREATE TABLE X (...) ENGINE = Iceberg*(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60_000` 2. 이제 Iceberg 테이블의 SELECT 쿼리는 `iceberg_metadata_staleness_ms` 매개변수를 지정해 실행할 수 있으며, 이를 통해 메타데이터가 지정된 staleness보다 더 최신이면 ClickHouse가 캐시에 저장된 메타데이터 버전을 사용하도록 할 수 있습니다. 그렇지 않으면 요청을 처리하기 위해 최신 메타데이터를 가져오도록 원격 Iceberg catalog를 조회합니다(기존에도 동작 방식은 이와 같았습니다). 이번 변경으로 요청 처리 중 Iceberg catalog 호출을 0까지 줄일 수 있게 되었으며, 이에 따라 눈에 띄는 성능 향상이 기대됩니다. 예시: `SELECT count() FROM {TABLE_NAME} SETTINGS iceberg_metadata_staleness_ms=600000`. [#96191](https://github.com/ClickHouse/ClickHouse/pull/96191) ([Arsen Muk](https://github.com/arsenmuk)).
* S3Queue ordered mode는 전체 prefix 이력을 다시 나열하지 않도록 S3 ListObjectsV2 StartAfter를 사용하여 ListObjects 호출 수를 줄입니다. [#96370](https://github.com/ClickHouse/ClickHouse/pull/96370) ([Venkata  Vineel ](https://github.com/vyalamar)).
* 일반적으로 중복 제거를 위해서는 원본 block이 필요하지만, 동기 삽입에서는 이를 생략해 메모리를 절약할 수 있습니다. [#96661](https://github.com/ClickHouse/ClickHouse/pull/96661) ([Sema Checherinda](https://github.com/CheSema)).
* YTsaurus table engine에서 병렬 읽기를 지원합니다. [#97343](https://github.com/ClickHouse/ClickHouse/pull/97343) ([MikhailBurdukov](https://github.com/MikhailBurdukov)).
* cache line 크기에 하드코딩된 64 대신 아키텍처별 값을 사용합니다. [#97357](https://github.com/ClickHouse/ClickHouse/pull/97357) ([Nikita Taranov](https://github.com/nickitat)).
