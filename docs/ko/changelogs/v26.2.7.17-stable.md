  #### 버그 수정(공식 안정 릴리스에서 사용자에게 보이는 오작동)

* [#101233](https://github.com/ClickHouse/ClickHouse/issues/101233)에 백포트됨: async insert 쿼리가 `query_log`와 클라이언트 출력에서 `written_rows`, `read_rows`, `result_rows`를 0으로 보고하던 문제를 수정했습니다. [#99879](https://github.com/ClickHouse/ClickHouse/pull/99879) ([Sema Checherinda](https://github.com/CheSema)).
* [#100170](https://github.com/ClickHouse/ClickHouse/issues/100170)에 백포트됨: ... [#100024](https://github.com/ClickHouse/ClickHouse/pull/100024) ([Shaohua Wang](https://github.com/tiandiwonder)).
* [#100920](https://github.com/ClickHouse/ClickHouse/issues/100920)에 백포트됨: LowCardinality 요소를 포함하는 Tuple 키에서 PREWHERE/WHERE와 함께 `has()` 함수를 사용할 때 발생하는 server 크래시를 수정했습니다. [#100760](https://github.com/ClickHouse/ClickHouse/pull/100760) ([Groene AI](https://github.com/groeneai)).
* [#101185](https://github.com/ClickHouse/ClickHouse/issues/101185)에 백포트됨: server 종료 중 딕셔너리를 로드할 때 발생하는 null pointer 역참조 segfault를 수정했습니다. `Context::getUserDefinedSQLObjectsStorage`(`user_defined_sql_objects_storage`를 역참조함)는 딕셔너리 스레드에서 호출되고, 동시에 메인 스레드는 `Context::shutdown`(`user_defined_sql_objects_storage`를 null로 설정함)을 호출합니다. `Context::shutdown`를 실행하기 전에 딕셔너리 로더에서 이후 업데이트를 비활성화하고, 현재 실행 중인 딕셔너리 쿼리를 종료하며, 딕셔너리 로딩 스레드를 join해야 합니다. 일반 쿼리에서 처리하는 방식과 유사합니다. [#100839](https://github.com/ClickHouse/ClickHouse/pull/100839) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* [#101089](https://github.com/ClickHouse/ClickHouse/issues/101089)에 백포트됨: 입력에 비ASCII 바이트가 포함될 때 `ULIDStringToDateTime`에서 발생하는 buffer 오버플로우를 수정했습니다. [#100843](https://github.com/ClickHouse/ClickHouse/pull/100843) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* [#101013](https://github.com/ClickHouse/ClickHouse/issues/101013)에 백포트됨: 널 허용 튜플의 배열에서 `intDiv`/`intDivOrZero`가 예외를 발생시키는 문제를 수정했습니다. 예: `SELECT intDiv([divide((1, 2), ... AND NULL)], 2)`. [#100895](https://github.com/ClickHouse/ClickHouse/pull/100895) ([Raúl Marín](https://github.com/Algunenano)).
* [#101248](https://github.com/ClickHouse/ClickHouse/issues/101248)에 백포트됨: `StorageAlias`의 정의를 저장하기 전에 engine 인수를 평가하여 `currentDatabase()`와 같은 표현식이 데이터베이스에 저장되기 전에 리터럴로 확인되도록 했습니다. [#100902](https://github.com/ClickHouse/ClickHouse/pull/100902) ([Nikolay Degterinsky](https://github.com/evillique)).
* [#101124](https://github.com/ClickHouse/ClickHouse/issues/101124)에 백포트됨: 예를 들어 `WHERE (id, str) IN (SELECT (id, str) FROM ...)`처럼 튜플 subquery를 포함한 `IN` 절과 함께 텍스트 검색 인덱스를 사용할 때, 또는 subquery의 컬럼 수가 `IN` 왼쪽 튜플과 일치하지 않을 때 발생하던 크래시를 수정했습니다. [#100959](https://github.com/ClickHouse/ClickHouse/pull/100959) ([Anton Popov](https://github.com/CurtizJ)).
* [#101078](https://github.com/ClickHouse/ClickHouse/issues/101078)에 백포트됨: `Nullable(Tuple)` 도입 이후 하나 이상의 `Nullable` 인수를 가진 `sumCountOrDefault` 집계 함수가 이전에 serialize된 state를 읽지 못하던 문제를 수정했습니다. [#100882](https://github.com/ClickHouse/ClickHouse/issues/100882)를 닫습니다. [#101021](https://github.com/ClickHouse/ClickHouse/pull/101021) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* [#101346](https://github.com/ClickHouse/ClickHouse/issues/101346)에 백포트됨: `list`와 `read` 사이에 원격 객체가 덮어써지면서 이전에는 오래된 객체 메타데이터가 생성되어, 캐시에서 `Having zero bytes, ...` logical error가 발생할 수 있던 문제를 수정했습니다. [#101219](https://github.com/ClickHouse/ClickHouse/pull/101219) ([Kseniia Sumarokova](https://github.com/kssenii)).
