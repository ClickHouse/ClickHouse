  ### ClickHouse 릴리스 v25.11.1.558-안정 (16f22f3d744) FIXME v25.11.1.1-new (ae414ae37fc) 대비
</div>

<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* `Geometry` 타입을 도입했습니다. 이 타입에 대해 `WKB` 및 `WKT` 포맷 읽기를 지원합니다. 이전 버전에서는 `Geometry` 타입이 `String`의 별칭이었지만, 이제는 완전한 기능을 갖춘 타입입니다. [#83344](https://github.com/ClickHouse/ClickHouse/pull/83344) ([scanhex12](https://github.com/scanhex12)).
* 지원 중단된 Object 타입을 제거했습니다. [#85718](https://github.com/ClickHouse/ClickHouse/pull/85718) ([Pavel Kruglov](https://github.com/Avogar)).
* MergeTree 테이블의 Wide data part에서 Variant 타입 서브컬럼용으로 생성되는 파일 이름에 escaping을 적용합니다. 이 변경으로 인해 기존 Variant/Dynamic/JSON 데이터 타입 테이블과의 호환성이 깨집니다. 이 수정은 Variant 내부에 특수 기호가 포함된 타입(예: `\`가 포함된 특정 시간대의 DateTime)의 저장 문제를 해결합니다. escaping은 MergeTree 설정 `escape_variant_subcolumn_filenames`를 변경하여 비활성화할 수 있습니다(호환성을 유지하려면 upgrade 전에 MergeTree 구성에서 이 설정을 비활성화하거나 `compatibility` 설정을 이전 버전으로 지정하십시오). [#69590](https://github.com/ClickHouse/ClickHouse/issues/69590)을 해결합니다. [#87300](https://github.com/ClickHouse/ClickHouse/pull/87300) ([Pavel Kruglov](https://github.com/Avogar)).
* 폐기된 `LIVE VIEW` 기능을 제거했습니다. `LIVE VIEW`를 사용 중인 경우 새 버전으로 upgrade할 수 없습니다. [#88706](https://github.com/ClickHouse/ClickHouse/pull/88706) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 클라이언트가 예외를 더 안정적으로 구문 분석할 수 있도록 HTTP 결과 응답에 exception tagging을 지원합니다. [#75175](https://github.com/ClickHouse/ClickHouse/issues/75175)을 해결합니다. 포맷 간 일관성을 위해 `http_write_exception_in_output_format` 설정은 기본적으로 비활성화되어 있습니다. [#88818](https://github.com/ClickHouse/ClickHouse/pull/88818) ([Kaviraj Kanagaraj](https://github.com/kavirajk)).
* 공유 객체 스토리지 경로 위에 여러 개의 `plain-rewritable` 디스크를 생성하지 못하도록 했습니다. 이는 서로 다른 메타데이터 저장소 트랜잭션이 충돌할 경우 undefined 동작을 초래할 수 있기 때문입니다. [#89038](https://github.com/ClickHouse/ClickHouse/pull/89038) ([Mikhail Artemenko](https://github.com/Michicosun)).
* String 데이터 타입에 대해 with&#95;size&#95;stream serialization format을 기본적으로 활성화합니다. 이 변경은 하위 호환되지만, 새 serialization format은 25.10 버전부터만 지원되므로 25.10 이전 버전으로는 downgrade할 수 없습니다. 25.9 이하 버전으로 downgrade할 가능성을 유지하려면 서버 구성의 merge&#95;tree 섹션에서 serialization&#95;info&#95;version을 basic으로, string&#95;serialization&#95;version을 single&#95;stream으로 구성하십시오. [#89329](https://github.com/ClickHouse/ClickHouse/pull/89329) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* Kafka storage SASL 설정 precedence를 수정했습니다. 이제 CREATE TABLE 쿼리에서 지정한 테이블 수준 SASL 설정이 설정 파일의 consumer/producer별 설정을 올바르게 재정의합니다. [#89401](https://github.com/ClickHouse/ClickHouse/pull/89401) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 요소 크기에 맞게 정렬되지 않은 크기의 데이터를 compressing할 때 발생하던 `Fatal` 문제를 수정했습니다(T64 codec에서). [#89282](https://github.com/ClickHouse/ClickHouse/issues/89282)를 해결합니다. [#89432](https://github.com/ClickHouse/ClickHouse/pull/89432) ([yanglongwei](https://github.com/ylw510)).

<div id="new-feature">
  #### 새 기능
</div>

* 사용자 가장을 지원하기 위해 새로운 SQL 문 `EXECUTE AS`를 추가했습니다. [#39048](https://github.com/ClickHouse/ClickHouse/issues/39048)을 해결했습니다. [#70775](https://github.com/ClickHouse/ClickHouse/pull/70775) ([Shankar](https://github.com/shiyer7474)).
* 배열에서 필요한 수의 차원을 풀고 Tuple 컬럼 내부의 포인터를 서로 바꾸는 `flipCoordinates` 함수를 추가했습니다. [#79469](https://github.com/ClickHouse/ClickHouse/issues/79469)을 해결했습니다. [#79634](https://github.com/ClickHouse/ClickHouse/pull/79634) ([Sachin Kumar Singh](https://github.com/sachinkumarsingh092)).
* 유니코드 문자와 해당 속성 목록을 포함하는 `system.unicode` 테이블을 추가했습니다. [#80055](https://github.com/ClickHouse/ClickHouse/issues/80055)를 해결했습니다. [#80857](https://github.com/ClickHouse/ClickHouse/pull/80857) ([wxybear](https://github.com/wxybear)).
* Prometheus HTTP Query API의 일부를 지원합니다. 이를 활성화하려면 설정 파일의 `<prometheus>` 섹션에 type이 `query_api`인 규칙을 추가하십시오. 지원되는 handler는 `/api/v1/query_range` 및 `/api/v1/query`입니다. [#86132](https://github.com/ClickHouse/ClickHouse/pull/86132) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* `IS NOT DISTINCT FROM` (`<=>`) 연산자를 개선했습니다. 역방향 `IS DISTINCT FROM` 지원과 서로 다른 타입의 호환 가능한 숫자 피연산자(예: `Nullable(UInt32)` 및 `Nullable(Int64)`) 지원을 추가했습니다. [#87581](https://github.com/ClickHouse/ClickHouse/pull/87581) ([yanglongwei](https://github.com/ylw510)).
* 데이터 타입에 지정된 매개변수와 관계없이 머지 후 Wide 파트의 동적 서브컬럼 수를 제한할 수 있도록 새로운 MergeTree 설정 `merge_max_dynamic_subcolumns_in_wide_part`를 추가했습니다. [#87646](https://github.com/ClickHouse/ClickHouse/pull/87646) ([Pavel Kruglov](https://github.com/Avogar)).
* `cume_dist` 윈도 함수 지원을 추가했습니다. [#86920](https://github.com/ClickHouse/ClickHouse/issues/86920)을 수정했습니다. [#88102](https://github.com/ClickHouse/ClickHouse/pull/88102) ([Manuel](https://github.com/raimannma)).
* 이제 텍스트 인덱스 생성 시 새로운 인수 `preprocessor`를 추가할 수 있습니다. 이 인수는 토큰화 전에 각 문서를 변환하는 임의의 표현식입니다. [#88272](https://github.com/ClickHouse/ClickHouse/pull/88272) ([Jimmy Aguilar Mena](https://github.com/Ergus)).
* `X-ClickHouse-Progress` 및 `X-ClickHouse-Summary`에 `memory_usage` 필드를 추가했습니다. 이를 사용하면 클라이언트 측에서 쿼리의 메모리 사용량을 실시간으로 수집할 수 있습니다. [#88393](https://github.com/ClickHouse/ClickHouse/pull/88393) ([Christoph Wurm](https://github.com/cwurm)).
* 테이블의 일부 비율을 선택할 수 있도록 소수점 `LIMIT` 및 `OFFSET` 지원을 추가했습니다. [#81892](https://github.com/ClickHouse/ClickHouse/issues/81892)를 해결했습니다. [#88755](https://github.com/ClickHouse/ClickHouse/pull/88755) ([Ahmed Gouda](https://github.com/0xgouda)).
* 출력 경로가 존재하지 않을 때 오류를 방지하기 위해 INTO OUTFILE용 상위 directories를 자동으로 생성하는 setting into&#95;outfile&#95;create&#95;parent&#95;directories를 추가했습니다. 이로써 쿼리 결과를 중첩된 directories에 기록하는 workflow가 단순해집니다. [#88610](https://github.com/ClickHouse/ClickHouse/issues/88610)을 해결했습니다. [#88795](https://github.com/ClickHouse/ClickHouse/pull/88795) ([Saksham](https://github.com/Saksham10-11)).
* Microsoft OneLake catalog 통합. [#89366](https://github.com/ClickHouse/ClickHouse/pull/89366) ([scanhex12](https://github.com/scanhex12)).
* 임시 테이블에 대해 `CREATE OR REPLACE` 구문을 지원합니다. [#35888](https://github.com/ClickHouse/ClickHouse/issues/35888)를 해결했습니다. [#89450](https://github.com/ClickHouse/ClickHouse/pull/89450) ([Aleksandr Musorin](https://github.com/AVMusorin)).
* 배열 `arr`에서 `elem`과 같은 모든 요소를 제거하는 `arrayRemove(arr, elem)`를 지원합니다. [#52099](https://github.com/ClickHouse/ClickHouse/issues/52099)을 해결합니다. [#89585](https://github.com/ClickHouse/ClickHouse/pull/89585) ([tiwarysaurav](https://github.com/tiwarysaurav)).

[#89621](https://github.com/ClickHouse/ClickHouse/pull/89621) ([Taras Polishchuk](https://github.com/wake-up-neo)).
* 쿼리별로 인접한 part 데이터의 백그라운드 다운로드를 비활성화할 수 있도록 했습니다. [#89524](https://github.com/ClickHouse/ClickHouse/issues/89524)를 수정했습니다. [#89668](https://github.com/ClickHouse/ClickHouse/pull/89668) ([tanner-bruce](https://github.com/tanner-bruce)).
* 평균을 계산하는 `midpoint` 스칼라 함수(scalar function)를 도입했습니다. [#89029](https://github.com/ClickHouse/ClickHouse/issues/89029)를 해결합니다. [#89679](https://github.com/ClickHouse/ClickHouse/pull/89679) ([simonmichal](https://github.com/simonmichal)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* RIGHT 및 FULL JOIN이 이제 ConcurrentHashJoin을 사용합니다. 즉, 이러한 조인 유형이 더 높은 수준의 병렬성으로 실행됩니다. 다양한 RIGHT 및 FULL JOIN 사례에서 성능이 최대 2배까지 향상됩니다. [#78027](https://github.com/ClickHouse/ClickHouse/issues/78027)을 해결합니다. [#78462](https://github.com/ClickHouse/ClickHouse/pull/78462) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* ConstantNode의 큰 값에 대한 최적화입니다. [#72880](https://github.com/ClickHouse/ClickHouse/issues/72880)을 해결합니다. [#81104](https://github.com/ClickHouse/ClickHouse/pull/81104) ([Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)).
* 10K개 이상의 파트를 가진 테이블에서 파티션 프루닝이 많이 적용되는 `SELECT` 쿼리가 최대 8배 더 빨라집니다. [#85535](https://github.com/ClickHouse/ClickHouse/pull/85535) ([James Morrison](https://github.com/jawm)).
* aarch64 및 일부 다른 아키텍처/커널 조합에서 발생할 수 있는 vsdo 문제를 수정했습니다. [#86096](https://github.com/ClickHouse/ClickHouse/pull/86096) ([Tomas Hulata](https://github.com/tombokombo)).
* 쿼리가 집계 상태(작은 정수에 대한 group by)에 fixed hash map을 사용하는 경우, ClickHouse는 쿼리 속도를 높이기 위해 집계 상태를 병렬로 병합합니다. [#63666](https://github.com/ClickHouse/ClickHouse/issues/63666)을 해결합니다. [#87366](https://github.com/ClickHouse/ClickHouse/pull/87366) ([Jianfei Hu](https://github.com/incfly)).
* 분산 실행: 파일이 아니라 row group ID를 기준으로 작업을 더 효율적으로 분할합니다. [#87508](https://github.com/ClickHouse/ClickHouse/pull/87508) ([scanhex12](https://github.com/scanhex12)).
* 코드를 단순화하고 [선택 알고리즘](https://clickhouse.com/blog/lz4-compression-in-clickhouse#how-to-choose-the-best-algorithm)을 조정해 LZ4 압축 해제 속도를 개선했습니다. [#88360](https://github.com/ClickHouse/ClickHouse/pull/88360) ([Raúl Marín](https://github.com/Algunenano)).
* S3는 키 이름 프리픽스를 기준으로 내부적으로 객체를 파티셔닝하며, 각 파티션의 높은 요청률에 맞춰 자동으로 확장됩니다. 이번 변경으로 두 개의 새로운 BACKUP 설정인 data&#95;file&#95;name&#95;generator와 data&#95;file&#95;name&#95;prefix&#95;length가 추가되었습니다. data&#95;file&#95;name&#95;generator=checksum인 경우 백업 데이터 파일은 내용의 hash를 사용해 이름이 지정됩니다. 예시: checksum = `abcd1234ef567890abcd1234ef567890`이고 `data_file_name_prefix_length = 3`이면 결과 경로는 `abc/d1234ef567890abcd1234ef567890`가 됩니다. 이렇게 생성된 키 분포는 S3 파티션 전반의 load balancing을 개선하고 스로틀링 위험을 줄입니다. [#88418](https://github.com/ClickHouse/ClickHouse/pull/88418) ([Julia Kartseva](https://github.com/jkartseva)).
* JOIN 및 ARRAY JOIN에서 지연 실행 컬럼 복제를 구현했습니다. 일부 출력 형식에서 Sparse 및 Replicated와 같은 특수 컬럼 표현을 일반 컬럼으로 변환하지 않도록 했습니다. 이를 통해 메모리에서 불필요한 데이터 복사를 방지합니다. [#88752](https://github.com/ClickHouse/ClickHouse/pull/88752) ([Pavel Kruglov](https://github.com/Avogar)).
* 딕셔너리 블록을 캐싱하고 토큰 lookup에 이진 검색 대신 해시 테이블을 사용해 text index 성능을 개선했습니다. [#88786](https://github.com/ClickHouse/ClickHouse/pull/88786) ([Elmi Ahmadov](https://github.com/ahmadov)).
* Parquet 리더 v3가 기본적으로 활성화됩니다. [#88827](https://github.com/ClickHouse/ClickHouse/pull/88827) ([Michael Kolupaev](https://github.com/al13n321)).
* 이제 쿼리는 optimize&#95;read&#95;in&#95;order와 query&#95;plan&#95;optimize&#95;lazy&#95;materialization의 이점을 동시에 활용할 수 있습니다. [#88767](https://github.com/ClickHouse/ClickHouse/issues/88767)을 해결합니다. [#88866](https://github.com/ClickHouse/ClickHouse/pull/88866) ([Manuel](https://github.com/raimannma)).
* `DISTINCT`가 포함된 쿼리에 aggregate projection을 사용합니다. [#86925](https://github.com/ClickHouse/ClickHouse/issues/86925)를 해결했습니다. [#88894](https://github.com/ClickHouse/ClickHouse/pull/88894) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 포스팅 리스트는 데이터 크기 기준으로 가장 큰 부분이므로, 이를 캐싱하면 연속 실행 시 성능이 향상됩니다. [#88912](https://github.com/ClickHouse/ClickHouse/pull/88912) ([Elmi Ahmadov](https://github.com/ahmadov)).
