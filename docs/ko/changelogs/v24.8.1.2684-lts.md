<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* `clickhouse-client` 및 `clickhouse-local`은 이제 기본적으로 단일 쿼리 모드가 아니라 다중 쿼리 모드로 동작합니다. 예를 들어 이제 `clickhouse-client -q "SELECT 1; SELECT 2"`가 동작하며, 이전에는 `--multiquery`(또는 `-n`)를 추가해야 했습니다. `--multiquery/-n` 스위치는 더 이상 사용되지 않습니다. 다중 쿼리 SQL 문에서 INSERT 쿼리는 FORMAT 절에 따라 특별하게 처리됩니다. FORMAT이 `VALUES`인 경우(가장 일반적인 경우) INSERT SQL 문의 끝은 쿼리 끝의 세미콜론 `;`으로 구분됩니다. 그 외 모든 FORMAT(예: `CSV`, `JSONEachRow`)에서는 INSERT SQL 문의 끝이 쿼리 끝의 두 개 줄바꿈 `\n\n`으로 구분됩니다. [#63898](https://github.com/ClickHouse/ClickHouse/pull/63898) ([FFish](https://github.com/wxybear)).
* 이전 버전에서는 데이터 타입 이름 뒤에 `WithDictionary`를 붙이는 방식으로 `LowCardinality` 데이터 타입의 대체 구문을 사용할 수 있었습니다. 이는 초기 동작 구현이었으며, 문서화되거나 공개된 적이 없었습니다. 이제 이 구문은 더 이상 권장되지 않습니다. 이 구문을 사용했다면 테이블에 ALTER를 수행하여 데이터 타입 이름을 `LowCardinality`로 변경해야 합니다. [#66842](https://github.com/ClickHouse/ClickHouse/pull/66842) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 분산 대상 테이블과 함께 사용하는 storage `Buffer`의 논리 오류를 수정했습니다. 이는 하위 호환되지 않는 변경 사항입니다. 쿼리에서 해당 테이블이 두 번 이상 나타나는 경우(예: self-join) 분산 대상 테이블과 함께 `Buffer`를 사용하는 쿼리가 더 이상 동작하지 않을 수 있습니다. [#67015](https://github.com/ClickHouse/ClickHouse/pull/67015) ([vdimir](https://github.com/vdimir)).
* 이전 버전에서는 감마 함수에 기반한 랜덤 분포 함수(예: Chi-Squared, Student, Fisher)를 0에 가까운 음수 인수로 호출하면 계산이 오래 걸리거나 무한 루프에 빠질 수 있었습니다. 새 버전에서는 이러한 함수를 0 또는 음수 인수로 호출하면 예외가 발생합니다. 이 변경으로 [#67297](https://github.com/ClickHouse/ClickHouse/issues/67297)이 해결됩니다. [#67326](https://github.com/ClickHouse/ClickHouse/pull/67326) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 시스템 테이블 `text_log`가 기본적으로 활성화됩니다. 이는 이전 버전과 완전히 호환되지만, 로컬 디스크의 디스크 사용량이 소폭 증가할 수 있습니다(이 시스템 테이블은 아주 적은 디스크 공간만 사용합니다). [#67428](https://github.com/ClickHouse/ClickHouse/pull/67428) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 이전 버전에서는 `arrayWithConstant`가 매우 큰 배열을 생성할 때 느릴 수 있었습니다. 새 버전에서는 배열당 1 GB로 제한됩니다. 이 변경으로 [#32754](https://github.com/ClickHouse/ClickHouse/issues/32754)가 해결됩니다. [#67741](https://github.com/ClickHouse/ClickHouse/pull/67741) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* REPLACE 수정자의 포맷을 수정했습니다(괄호 생략 금지). [#67774](https://github.com/ClickHouse/ClickHouse/pull/67774) ([Azat Khuzhin](https://github.com/azat)).
* [#68349](https://github.com/ClickHouse/ClickHouse/issues/68349)에 백포트됨: Dynamic 타입을 재구현했습니다. 이제 동적 데이터 타입 수 제한에 도달하면 새 타입이 String으로 캐스팅되지 않고, 바이너리 인코딩된 데이터 타입과 함께 바이너리 형식의 특수한 데이터 구조에 저장됩니다. 이제까지 Dynamic 컬럼에 삽입된 모든 타입은 subcolumn으로 읽을 수 있습니다. [#68132](https://github.com/ClickHouse/ClickHouse/pull/68132) ([Kruglov Pavel](https://github.com/Avogar)).

<div id="new-feature">
  #### 새 기능
</div>

* Kafka에 커밋하는 방식에 의존하지 않고 Keeper에 오프셋을 저장하는 새로운 실험적 Kafka 저장 엔진을 추가했습니다. [#57625](https://github.com/ClickHouse/ClickHouse/pull/57625) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* 새로운 TimeSeries 테이블 엔진을 추가했습니다: - 기본적으로 `CREATE TABLE tbl ENGINE=TimeSeries` - 또는 내부 테이블의 엔진을 지정하여 사용할 수 있습니다. [#64183](https://github.com/ClickHouse/ClickHouse/pull/64183) ([Vitaly Baranov](https://github.com/vitlibar)).
* 왼쪽 테이블과 오른쪽 테이블의 컬럼이 모두 포함된 부등 조건에서 더 많은 join 엄격성(`LEFT/RIGHT SEMI/ANTI/ANY JOIN`)을 지원합니다. 예: t1.y &lt; t2.y (`allow_experimental_join_condition` 설정 참고). [#64281](https://github.com/ClickHouse/ClickHouse/pull/64281) ([lgbo](https://github.com/lgbo-ustc)).
* S3 테이블 엔진에 `_etag` virtual 컬럼을 추가했습니다. [#65312](https://github.com/ClickHouse/ClickHouse/issues/65312)를 수정합니다. [#65386](https://github.com/ClickHouse/ClickHouse/pull/65386) ([skyoct](https://github.com/skyoct)).
* 이 pull request는 여러 엔진(`File`, `URL`, `S3`, `AzureBlobStorage`, `HDFS`)에 Hive-style partitioning을 도입합니다. Hive-style partitioning은 데이터를 파티션된 하위 디렉터리로 구성하여 대규모 데이터셋을 효율적으로 쿼리하고 관리할 수 있게 합니다. 현재는 적절한 이름과 데이터를 가진 virtual 컬럼만 생성합니다. 후속 PR에서는 적절한 데이터 필터링(성능 향상)을 도입할 예정입니다. [#65997](https://github.com/ClickHouse/ClickHouse/pull/65997) ([Yarik Briukhovetskyi](https://github.com/yariks5s)).
* Spark 호환성을 위해 함수 printf를 추가했습니다. [#66257](https://github.com/ClickHouse/ClickHouse/pull/66257) ([李扬](https://github.com/taiyang-li)).
* [#68450](https://github.com/ClickHouse/ClickHouse/issues/68450)에 백포트되었습니다: 새로운 JSON 데이터 타입을 구현했습니다. [#66444](https://github.com/ClickHouse/ClickHouse/pull/66444) ([Kruglov Pavel](https://github.com/Avogar)).
* 새로운 server setting `disable_insertion_and_mutation`을 추가했습니다. 이를 true로 설정하면 이 노드는 모든 삽입과 뮤테이션(Alter table delete/update/drop partition)을 거부합니다. async 삽입도 포함됩니다. [#66519](https://github.com/ClickHouse/ClickHouse/pull/66519) ([Xu Jia](https://github.com/XuJia0210)).
* 테스트에 유용할 수 있도록 외부 엔진과 table&#95;engines를 Null engine으로 대체하는 옵션 `restore_replace_external_engines_to_null` 및 `restore_replace_external_table_functions_to_null`을 추가했습니다. 이는 RESTORE와 명시적인 테이블 생성에서 동작해야 합니다. [#66536](https://github.com/ClickHouse/ClickHouse/pull/66536) ([Ilya Yatsishin](https://github.com/qoega)).
* 함수 readWKTLineString을 사용해 WKT 형식의 MULTILINESTRING geometry를 읽는 기능을 추가했습니다. [#67647](https://github.com/ClickHouse/ClickHouse/pull/67647) ([Jacob Reckhard](https://github.com/jacobrec)).
* 새로운 테이블 함수 `fuzzQuery`를 추가했습니다. 이 함수는 주어진 query string을 무작위 변형으로 수정할 수 있습니다. 예시: `SELECT query FROM fuzzQuery('SELECT 1') LIMIT 5;`. [#67655](https://github.com/ClickHouse/ClickHouse/pull/67655) ([pufit](https://github.com/pufit)).
* 모든 분리된 파티션을 삭제하는 쿼리 `DROP DETACHED PARTITION ALL`을 지원합니다. [#67885](https://github.com/ClickHouse/ClickHouse/pull/67885) ([Duc Canh Le](https://github.com/canhld94)).
* 쿼리 캐시에 대한 태깅(네임스페이스) 메커니즘을 추가했습니다. 태그가 다른 동일한 쿼리는 쿼리 캐시에서 서로 다른 것으로 간주됩니다. 예시: `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'abc'` 및 `SELECT 1 SETTINGS use_query_cache = 1, query_cache_tag = 'def'`는 이제 서로 다른 쿼리 캐시 엔트리를 생성합니다. [#68235](https://github.com/ClickHouse/ClickHouse/pull/68235) ([sakulali](https://github.com/sakulali)).

<div id="improvement">
  #### 개선 사항
</div>

* ClickHouse 서버가 이제 새로운 설정 `max_keep_alive_requests`를 지원합니다. 서버에 대한 keep-alive HTTP 연결에서는 `keep_alive_timeout`과 함께 동작합니다. 즉, idle timeout이 만료되지 않았더라도 해당 연결을 통해 이미 `max_keep_alive_requests`를 초과하는 요청이 처리되었다면 서버가 해당 연결을 종료합니다. [#61793](https://github.com/ClickHouse/ClickHouse/pull/61793) ([Nikita Taranov](https://github.com/nickitat)).
* 새 버전에서는 SOURCES를 테이블 엔진 로직에 따라 검사합니다. grant table engine이 기본적으로 비활성화되어 있더라도 source에 대한 권한이 부여되지 않은 경우에는 대신 테이블 엔진 프롬프트가 표시되어 오해를 불러일으킬 수 있습니다. [#65419](https://github.com/ClickHouse/ClickHouse/pull/65419) ([jsc0218](https://github.com/jsc0218)).
* `count_min` 통계 타입(count-min sketches)이 추가되었습니다. 이 타입은 `col = 'val'`과 같은 동등 프레디케이트에 대한 선택도 추정치를 제공합니다. 지원되는 데이터 타입은 string, date, datetime 및 숫자 타입입니다. [#65521](https://github.com/ClickHouse/ClickHouse/pull/65521) ([JackyWoo](https://github.com/JackyWoo)).
* 재정의를 허용하기 위해 이미지에서 Keeper용 로그를 명시적으로 전달하지 않도록 변경했습니다. [#65564](https://github.com/ClickHouse/ClickHouse/pull/65564) ([Azat Khuzhin](https://github.com/azat)).
* `clickhouse-local`에서 기본적으로 `Atomic` 데이터베이스를 사용합니다. [#50647](https://github.com/ClickHouse/ClickHouse/issues/50647)의 1번과 5번 항목을 해결합니다. [#44817](https://github.com/ClickHouse/ClickHouse/issues/44817)을 종료합니다. [#65860](https://github.com/ClickHouse/ClickHouse/pull/65860) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* `rows_before_aggregation`이 활성화되면 쿼리 응답에 `rows_before_aggregation_at_least` 통계를 추가합니다. 이 통계는 집계 전에 읽은 행 수를 나타냅니다. 분산 쿼리에서 `limit` 없이 `group by` 또는 `max` 집계 함수를 사용하는 경우 `rows_before_aggregation_at_least`는 쿼리가 실제로 접근한 행 수를 반영할 수 있습니다. [#66084](https://github.com/ClickHouse/ClickHouse/pull/66084) ([morning-color](https://github.com/morning-color)).
* `BACKUP` 및 `RESTORE` 쿼리에 `use_same_password_for_base_backup` 설정이 도입되어, 암호로 보호된 아카이브에 대해 증분 백업을 생성하고 해당 아카이브에서 복원할 수 있게 되었습니다. [#66214](https://github.com/ClickHouse/ClickHouse/pull/66214) ([Samuele](https://github.com/sguerrini97)).
* ATTACH 쿼리에서는 async&#95;load&#95;databases를 무시합니다(이전에는 테이블이 attached 상태가 되기 전에 ATTACH가 반환될 수 있었습니다). [#66240](https://github.com/ClickHouse/ClickHouse/pull/66240) ([Azat Khuzhin](https://github.com/azat)).
* [Replicated]MergeTreeSink는 `onCancel()` 메서드에서 지연된 delayed&#95;chunk를 올바르게 취소해야 합니다. [#66279](https://github.com/ClickHouse/ClickHouse/pull/66279) ([Sema Checherinda](https://github.com/CheSema)).
* 거부된 연결(리소스가 부족한 경우)에 대한 로그와 메트릭이 추가되었습니다. [#66410](https://github.com/ClickHouse/ClickHouse/pull/66410) ([Alexander Tokmakov](https://github.com/tavplubix)).
* 설정 `allow_experimental_analyzer`의 이름이 `enable_analyzer`로 변경되었습니다. 기존 이름은 alias 형태로 유지됩니다. [#66438](https://github.com/ClickHouse/ClickHouse/pull/66438) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* MongoDB 엔진에서 실제 UUID 타입을 지원합니다. [#66671](https://github.com/ClickHouse/ClickHouse/pull/66671) ([Azat Khuzhin](https://github.com/azat)).
* 특정 엔진에서 머지 시 프로젝션과 `OPTIMIZE DEDUPLICATE` 쿼리의 동작을 제어하기 위한 새 `MergeTree` 설정 `deduplicate_merge_projection_mode`를 추가했습니다. 지원되는 옵션은 다음과 같습니다. `throw`(프로젝션이 *MergeTree 엔진에서 완전히 지원되지 않는 경우 예외를 발생시킴), `drop`(프로젝션 자체를 일관되게 머지할 수 없는 경우 머지 중에 프로젝션을 제거함), `rebuild`(프로젝션을 처음부터 다시 빌드하며, 비용이 큰 작업임). [#66672](https://github.com/ClickHouse/ClickHouse/pull/66672) ([jsc0218](https://github.com/jsc0218)).
* 복제 지연(replication lag) 및 복구 시간 메트릭을 추가했습니다. [#66703](https://github.com/ClickHouse/ClickHouse/pull/66703) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* S3DiskNoKeyErrors 메트릭을 추가했습니다. [#66704](https://github.com/ClickHouse/ClickHouse/pull/66704) ([Miсhael Stetsyuk](https://github.com/mstetsyuk)).
* 모든 테이블 엔진에서 COMMENT 절이 동작하도록 했습니다. [#66832](https://github.com/ClickHouse/ClickHouse/pull/66832) ([Joe Lynch](https://github.com/joelynch)).
* 적절한 경우 `BAD_ARGUMENTS` 및 `ILLEGAL_TYPE_OF_ARGUMENT` 오류 코드 대신 더 정확한 오류 코드를 사용하도록 업데이트했습니다. [#66851](https://github.com/ClickHouse/ClickHouse/pull/66851) ([Yohann Jardin](https://github.com/yohannj)).
* 이제 함수 `mapFromArrays`는 첫 번째 인수로 `Map(K, V)`를 허용합니다. 예를 들어 `SELECT mapFromArrays(map('a', 4, 'b', 4), ['aa', 'bb'])`가 이제 동작하며 `{('a',4):'aa',('b',4):'bb'}`를 반환합니다. 또한 첫 번째 인수가 Array인 경우 실제 배열 값이 `NULL`이 아니면 `Array(Nullable(T))` 또는 `Array(LowCardinality(Nullable(T)))` 타입도 사용할 수 있습니다.
