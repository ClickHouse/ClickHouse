<div id="backward-incompatible-change">
  #### 하위 호환되지 않는 변경 사항
</div>

* ALTER MODIFY COLUMN은 이제 널 허용 컬럼을 non-nullable 타입으로 변환할 때 명시적인 DEFAULT를 요구합니다. 이전에는 이러한 ALTER가 cannot convert null to not null 오류와 함께 중단될 수 있었지만, 이제 NULL은 컬럼의 기본 표현식으로 대체됩니다. [#5985](https://github.com/ClickHouse/ClickHouse/issues/5985)를 해결합니다. [#84770](https://github.com/ClickHouse/ClickHouse/pull/84770) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Ngram 토크나이저는 이제 설정된 길이 N보다 작은 ngram을 반환하지 않습니다. 검색 토큰이 비어 있으면 Text Search는 어떤 행도 반환하지 않습니다. [#89757](https://github.com/ClickHouse/ClickHouse/pull/89757) ([George Larionov](https://github.com/george-larionov)).
* 컬럼을 `String`에서 `Nullable(String)`으로 ALTER할 때는 데이터에 대해 mutation을 수행하지 않습니다. 하지만 `uniq` 집계 함수는 서로 다른 데이터 구조를 사용합니다. 널 허용 컬럼에는 중첩된 uniq 집계기를 포함한 `AggregateFunctionNull`을 사용합니다. `AggregateFunctionNull`은 추가 bool 플래그를 serialize합니다. 이로 인해 통계 파일이 호환되지 않게 됩니다. 수정 방법은 serialization 중 널 허용 컬럼인지 기록하는 플래그를 추가하는 것입니다. 통계 포맷이 변경되었으므로, 기존 포맷의 통계가 있으면 서버가 크래시합니다. 이 PR [https://github.com/ClickHouse/ClickHouse/pull/90904](https://github.com/ClickHouse/ClickHouse/pull/90904)는 이 크래시를 수정하고, 기존 통계가 legacy 포맷을 사용하는 경우 예외를 발생시킵니다. 예외를 방지하려면 ALTER TABLE [db.]table MATERIALIZE STATISTICS ALL을 실행해 통계를 다시 생성해야 합니다. [#90311](https://github.com/ClickHouse/ClickHouse/pull/90311) ([Han Fei](https://github.com/hanfei1991)).
* 설정 `allow_not_comparable_types_in_order_by`/`allow_not_comparable_types_in_comparison_functions`를 제거했습니다. 비교할 수 없는 타입을 order by 또는 comparison function에서 허용하면 logical error와 예기치 않은 결과가 발생할 수 있습니다. [#90028](https://github.com/ClickHouse/ClickHouse/issues/90028)을 해결합니다. [#90527](https://github.com/ClickHouse/ClickHouse/pull/90527) ([Pavel Kruglov](https://github.com/Avogar)).
* 설정 `check_query_single_value_result`의 기본값을 `true`에서 `false`로 변경했습니다. 이로 인해 `CHECK TABLE`은 집계된 결과(1 = 정상, 0 = 오류 발견) 대신 part별 상세 결과를 반환합니다. 이전 동작과 비교하면, 이는 일반적으로 기대하는 동작에 더 가깝습니다. [#91009](https://github.com/ClickHouse/ClickHouse/pull/91009) ([Robert Schulze](https://github.com/rschu1ze)).
* implicit 인덱스 관련 여러 수정이 포함되었습니다. 표시되거나 저장되는 스키마(keeper 메타데이터)에는 `add_minmax_index_for_numeric_columns` 또는 `add_minmax_index_for_string_columns` 설정으로 생성된 implicit 인덱스가 포함되지 않습니다. 이로 인해 최신 버전에서 ReplicatedMergeTree 테이블을 생성하거나 업데이트할 때, 이전 릴리스의 레플리카가 있으면 메타데이터 오류가 발생할 수 있습니다. 이러한 경우 cluster가 완전히 upgrade될 때까지는 이전 레플리카로 DDL을 전송하십시오. [#91429](https://github.com/ClickHouse/ClickHouse/pull/91429) ([Raúl Marín](https://github.com/Algunenano)).
* `receive_timeout`으로 인해 쿼리 timeout이 발생할 때 clickhouse-client가 0이 아닌 종료 코드(159 - TIMEOUT&#95;EXCEEDED)를 반환하도록 업데이트했습니다. 이전에는 timeout이 종료 코드 0(성공)을 반환했기 때문에 스크립트와 자동화에서 timeout 실패를 감지하기 어려웠습니다. [#91432](https://github.com/ClickHouse/ClickHouse/pull/91432) ([Sav](https://github.com/sberss)).
* 역텍스트 인덱스의 스토리지 레이아웃을 개선하여 객체 스토리지에서 읽을 때 더 효율적으로 동작하도록 했습니다. 역텍스트 인덱스가 있는 테이블의 머지 성능도 개선했습니다. 25.12 이전 버전에서 Experimental text index를 사용했다면, upgrade 전에 해당 인덱스를 drop하고 새 버전에서 다시 빌드해야 합니다. [#91518](https://github.com/ClickHouse/ClickHouse/pull/91518) ([Anton Popov](https://github.com/CurtizJ)).
* 이들 테이블의 머지 동작이 정의되지 않으므로, 이제 빈 `ORDER BY` 키로 특수 `MergeTree` 테이블(`ReplacingMergeTree`, `CollapsingMergeTree` 등)을 생성할 수 없습니다. 이러한 테이블을 계속 생성해야 하는 경우 `allow_suspicious_primary_key` 설정을 활성화하십시오. [#91569](https://github.com/ClickHouse/ClickHouse/pull/91569) ([Anton Popov](https://github.com/CurtizJ)).
* `bitShiftLeft` 및 `bitShiftRight` 함수가 시프트 값이 정확히 해당 유형의 크기와 같을 때 0 또는 빈 값을 반환하도록 수정했습니다. [#91943](https://github.com/ClickHouse/ClickHouse/pull/91943) ([Pablo Marcos](https://github.com/pamarcos)).
* [https://github.com/ClickHouse/ClickHouse/pull/88380](https://github.com/ClickHouse/ClickHouse/pull/88380)의 후속 변경입니다. 이 PR은 프로젝션에서 위치 인수를 비활성화한 것을 하위 호환되지 않는 변경으로 분류합니다. 또한 프로젝션에 위치 인수가 있을 때 안전한 ClickHouse 클러스터 업그레이드가 가능하도록 `enable_positional_arguments_for_projections` 설정을 도입합니다. [#92007](https://github.com/ClickHouse/ClickHouse/pull/92007) ([Dmitry Novik](https://github.com/novikd)).

<div id="new-feature">
  #### 새 기능
</div>

* 이제 S3/Azure Queue 테이블에서 처리된 파일을 이동하거나 태그 지정하도록 구성할 수 있으며, 기존의 파일 유지 또는 제거 옵션에 추가로 사용할 수 있습니다. [#72944](https://github.com/ClickHouse/ClickHouse/issues/72944)를 해결합니다. [#86907](https://github.com/ClickHouse/ClickHouse/pull/86907) ([Murat Khairulin](https://github.com/mxwell)).
* `windowFunnel` 집계 함수에 `allow_reentry` 옵션을 추가했습니다. strict&#95;order와 함께 활성화하면 퍼널 분석을 중단하는 대신 순서를 위반하는 이벤트를 무시합니다. 이를 통해 새로고침이 있는 사용자 여정(A-&gt;A-&gt;B)이나 뒤로 이동(A-&gt;B-&gt;A-&gt;C)이 포함된 경우에도 전환율이 실제보다 낮게 집계되는 문제 없이 처리할 수 있습니다. [#86916](https://github.com/ClickHouse/ClickHouse/pull/86916) ([Lee ChaeRok](https://github.com/LeeChaeRok)).
* 이제 CLI 클라이언트에서 `--no-server-client-version-message` 또는 `false`를 지정해 &#39;ClickHouse server version is older than ClickHouse client. It may indicate that the server is out of date and can be upgraded.&#39; 메시지를 숨길 수 있습니다. [#87784](https://github.com/ClickHouse/ClickHouse/pull/87784) ([Larry Snizek](https://github.com/larry-cdn77)).
* ZooKeeper와의 Keeper 호환성: statistics를 포함한 create를 지원합니다. [#88797](https://github.com/ClickHouse/ClickHouse/pull/88797) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* ClickHouse Keeper에서 ZooKeeper persistent watch를 지원합니다. 후속 작업 Part 2: [https://github.com/ClickHouse/ClickHouse/pull/78207](https://github.com/ClickHouse/ClickHouse/pull/78207). [#88813](https://github.com/ClickHouse/ClickHouse/pull/88813) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* geometry type의 면적과 둘레를 계산하는 Functions입니다. [#89047](https://github.com/ClickHouse/ClickHouse/pull/89047) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* XRay를 사용해 런타임에 instrumentation을 추가하여 production 환경에서 문제를 Debug하고 결정론적으로 프로파일링할 수 있습니다. [#74249](https://github.com/ClickHouse/ClickHouse/issues/74249)를 해결합니다. [#89173](https://github.com/ClickHouse/ClickHouse/pull/89173) ([Pablo Marcos](https://github.com/pamarcos)).
* 지정된 값과 속성이 일치하는 딕셔너리 key를 반환하는 `dictGetKeys` 함수를 구현했습니다. 반복적인 lookup 속도를 높이기 위해 `max_reverse_dictionary_lookup_cache_size_bytes` 설정으로 조정되는 쿼리별 reverse-lookup cache를 사용합니다. [#89197](https://github.com/ClickHouse/ClickHouse/pull/89197) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* `--login`을 사용해 Cloud 자격 증명으로 ClickHouse Cloud instance에 액세스할 수 있습니다. [#89261](https://github.com/ClickHouse/ClickHouse/pull/89261) ([Krishna Mannem](https://github.com/kcmannem)).
* 입력 JSON을 JSON 타입의 명시적 typed path로 CAST할 수 없는 경우, JSON 타입에 대한 삽입/type cast 시 예외를 비활성화하는 설정 `type_json_skip_invalid_typed_paths`를 추가했습니다. 이 경우 typed path의 null/zero 값으로 대체됩니다. [#89886](https://github.com/ClickHouse/ClickHouse/pull/89886) ([Max Justus Spransy](https://github.com/maxjustus)).
* MergeTree 테이블에 대해 `direct`(nested loop) join을 지원합니다. 사용하려면 설정에서 이를 유일한 옵션으로 지정하십시오: `join_algorithm = 'direct'`. [#89920](https://github.com/ClickHouse/ClickHouse/pull/89920) ([Vladimir Cherkasov](https://github.com/vdimir)).
* Iceberg에 대한 `CREATE` 작업에서 `ORDER BY`와 `INSERT`에서의 sorting을 지원합니다. [#89916](https://github.com/ClickHouse/ClickHouse/issues/89916)를 해결합니다. [#90141](https://github.com/ClickHouse/ClickHouse/pull/90141) ([Konstantin Vedernikov](https://github.com/scanhex12)).
* 이 PR에서는 `ALTER TABLE ... ADD PROJECTION`의 새로운 WITH SETTINGS 절을 통해 사용할 수 있는 프로젝션 수준 설정을 도입했습니다. 이 설정을 사용하면 프로젝션별로 특정 MergeTree 스토리지 매개변수(예: index&#95;granularity, index&#95;granularity&#95;bytes)를 재정의할 수 있습니다. [#90158](https://github.com/ClickHouse/ClickHouse/pull/90158) ([Amos Bird](https://github.com/amosbird)).
* 데이터 마스킹 policy 파서를 추가했습니다. [#90552](https://github.com/ClickHouse/ClickHouse/pull/90552) ([pufit](https://github.com/pufit)).
* [#73900](https://github.com/ClickHouse/ClickHouse/issues/73900) 및 [#38775](https://github.com/ClickHouse/ClickHouse/issues/38775)의 일부로 `HMAC(algorithm, message, key)` SQL 함수를 추가했습니다. [#90837](https://github.com/ClickHouse/ClickHouse/pull/90837) ([Mikhail f. Shiryaev](https://github.com/Felixoid)).
* 첫 번째 인수가 상수 배열인 경우 `has()` 함수가 프라이머리 키(primary key)와 데이터 스키핑 인덱스를 사용할 수 있도록 지원을 추가했습니다. [#90980](https://github.com/ClickHouse/ClickHouse/issues/90980)을 해결했습니다. [#91023](https://github.com/ClickHouse/ClickHouse/pull/91023) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 새로운 입력/출력 포맷 `Buffers`를 구현했습니다. 이 포맷은 `Native`와 유사하지만, `Native`와 달리 컬럼 이름, 컬럼 타입 또는 추가 메타데이터를 저장하지 않습니다. [#84017](https://github.com/ClickHouse/ClickHouse/issues/84017)을 해결했습니다. [#91156](https://github.com/ClickHouse/ClickHouse/pull/91156) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* Cluster 테이블 함수에서 파일을 병렬로 읽을 때 사용할 스트림 수를 제어하는 설정 `max_streams_for_files_processing_in_cluster_functions`를 추가했습니다. [#90223](https://github.com/ClickHouse/ClickHouse/issues/90223)을 해결했습니다. [#91323](https://github.com/ClickHouse/ClickHouse/pull/91323) ([Pavel Kruglov](https://github.com/Avogar)).

<div id="experimental-feature">
  #### 실험적 기능
</div>

* `automatic_parallel_replicas_mode` 설정으로 제어되는 새로운 로직이 도입되어 병렬 레플리카를 사용한 쿼리 자동 실행을 지원합니다. 일반적인 단일 노드 실행 중에는 ClickHouse가 이후 계획 단계에서 활용할 통계를 수집합니다. 이 통계에 따르면 병렬 레플리카가 유용할 가능성이 높을 경우, ClickHouse는 해당 쿼리를 병렬 레플리카를 사용해 자동으로 실행합니다. 현재 지원되는 쿼리 범위는 상당히 제한적입니다. [#87541](https://github.com/ClickHouse/ClickHouse/pull/87541) ([Nikita Taranov](https://github.com/nickitat)).

<div id="performance-improvement">
  #### 성능 개선
</div>

* 쿼리가 행 제한에 도달하면 즉시 실패하도록 합니다. [#61872](https://github.com/ClickHouse/ClickHouse/issues/61872)를 해결합니다. [#62804](https://github.com/ClickHouse/ClickHouse/pull/62804) ([Sean Haynes](https://github.com/seandhaynes)).
* 쿼리 계획에서 사용되지 않는 컬럼을 제거하는 최적화를 추가합니다. [#75152](https://github.com/ClickHouse/ClickHouse/issues/75152)를 해결합니다. [#76487](https://github.com/ClickHouse/ClickHouse/pull/76487) ([János Benjamin Antal](https://github.com/antaljanosbenjamin)).
* Https://github.com/clickhouse/clickhouse/pull/84477에서는 병렬 분산 실행을 위해 `insert select from s3cluster()` 쿼리에서 사용할 수 있는 select 쿼리에 제약을 추가했습니다. 이번 변경으로 기존에도 가능했던 WHERE를 사용할 수 있습니다. [#84611](https://github.com/ClickHouse/ClickHouse/pull/84611) ([Igor Nikonov](https://github.com/devcrafter)).
* 해시 테이블 반복 중 키를 프리페치하여 cache miss를 최소화합니다. [#84708](https://github.com/ClickHouse/ClickHouse/pull/84708) ([lgbo](https://github.com/lgbo-ustc)).
* 포인트 배열의 끝부분만 정렬하고 단조 증가 입력에 대해서는 정렬을 건너뛰도록 `AggregateFunctionHistogram`을 최적화해 약 10%의 속도 향상을 달성합니다. [#85760](https://github.com/ClickHouse/ClickHouse/pull/85760) ([MakarDev](https://github.com/MakarDev)).
* 이제 ClickHouse는 `AND`와 `OR`가 혼합된 filter conditions가 있는 WHERE 절에서 스킵 인덱스를 사용해 index analysis를 수행합니다. 이전에는 스킵 인덱스를 활용하려면 WHERE 절이 filter conditions의 conjunction(AND)이어야 했습니다. 새로운 설정 `use_skip_indexes_for_disjunctions`(기본값: on)으로 이 기능을 제어합니다. (issue [#75228](https://github.com/ClickHouse/ClickHouse/issues/75228)). [#87781](https://github.com/ClickHouse/ClickHouse/pull/87781) ([Shankar Iyer](https://github.com/shankar-iyer)).
* 텍스트 인덱스에서 생성한 추가적인 예비 filter를 활용해 `like`, `equals`, `has` 등의 함수가 포함된 프레디케이트의 filtering 성능을 개선했습니다. 이 최적화는 `query_plan_text_index_add_hint` 설정으로 활성화됩니다. `Map` 데이터 타입 컬럼에 대한 텍스트 인덱스 활용도도 개선했습니다. [#88550](https://github.com/ClickHouse/ClickHouse/pull/88550) ([Anton Popov](https://github.com/CurtizJ)).
* 가능한 key values를 미리 계산한 집합에서 더 빠르게 lookup하도록 하여 반복적인 역방향 딕셔너리 lookup을 최적화합니다. [#7968](https://github.com/ClickHouse/ClickHouse/issues/7968)을 종료합니다. [#88971](https://github.com/ClickHouse/ClickHouse/pull/88971) ([Nihal Z. Miaji](https://github.com/nihalzp)).
* 널 허용 타입 컬럼에 대해 sparse serialization을 지원합니다. 이는 [#44539](https://github.com/ClickHouse/ClickHouse/issues/44539)의 후속 작업입니다. [#88999](https://github.com/ClickHouse/ClickHouse/pull/88999) ([Amos Bird](https://github.com/amosbird)).
* `ANTI` 조인에 대해 JOIN Runtime Filters를 지원합니다. 또한 lock contention을 줄이기 위해 runtime filters 구현을 리팩터링했습니다. [#89710](https://github.com/ClickHouse/ClickHouse/pull/89710) ([Dmitry Novik](https://github.com/novikd)).
* LEFT/INNER JOIN operations에서 left table의 읽기 순서를 유지한 채 계속 읽을 수 있도록 지원하며, 이는 후속 단계에서 활용할 수 있습니다. 설정 `query_plan_read_in_order_through_join`으로 비활성화할 수 있습니다. LEFT/INNER JOIN에 대해 읽기 최적화 중 virtual row도 지원합니다(설정 `read_in_order_use_virtual_row` 참조). [#89815](https://github.com/ClickHouse/ClickHouse/pull/89815) ([Vladimir Cherkasov](https://github.com/vdimir)).
