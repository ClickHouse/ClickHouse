<div id="overview">
  ## 개요
</div>

산술 함수는 `UInt8`, `UInt16`, `UInt32`, `UInt64`, `Int8`, `Int16`, `Int32`, `Int64`, `Float32` 또는 `Float64` 유형의 임의의 두 피연산자에 대해 작동합니다.

연산을 수행하기 전에 두 피연산자는 모두 결과 유형으로 형 변환됩니다. 결과 유형은 다음과 같이 결정됩니다(아래 함수 문서에서 별도로
명시한 경우는 제외):

* 두 피연산자가 모두 32비트 이하이면 결과 유형의 크기는 두 피연산자 중 더 큰 유형보다 한 단계 큰 유형의 크기가 됩니다(정수 크기 승격). 예를 들어 `UInt8 + UInt16 = UInt32` 또는 `Float32 * Float32 = Float64`입니다.
* 피연산자 중 하나가 64비트 이상이면 결과 유형의 크기는 두 피연산자 중 더 큰 유형과 동일한 크기가 됩니다. 예를
  들어 `UInt32 + UInt128 = UInt128` 또는 `Float32 * Float64 = Float64`입니다.
* 피연산자 중 하나가 signed이면 결과 유형도 signed가 되며, 그렇지 않으면 unsigned가 됩니다. 예를 들어 `UInt32 * Int32 = Int64` 또는 `UInt32 * UInt32 = UInt64`입니다.

이 규칙은 결과 유형이 가능한 모든 결과를 표현할 수 있는 가장 작은 유형이 되도록 보장합니다. 이로 인해 값 범위의 경계 부근에서
오버플로우가 발생할 위험이 있지만, 계산을 최대 64비트
네이티브 정수 폭으로 빠르게 수행할 수 있습니다. 또한 이러한 동작은 가장 큰 정수
유형으로 64비트 정수(BIGINT)를 제공하는 다른 많은 데이터베이스와의 호환성도 보장합니다.

예시:

```sql
SELECT toTypeName(0), toTypeName(0 + 0), toTypeName(0 + 0 + 0), toTypeName(0 + 0 + 0 + 0)
```

```text
┌─toTypeName(0)─┬─toTypeName(plus(0, 0))─┬─toTypeName(plus(plus(0, 0), 0))─┬─toTypeName(plus(plus(plus(0, 0), 0), 0))─┐
│ UInt8         │ UInt16                 │ UInt32                          │ UInt64                                   │
└───────────────┴────────────────────────┴─────────────────────────────────┴──────────────────────────────────────────┘
```

오버플로우는 C++와 동일한 방식으로 발생합니다.
