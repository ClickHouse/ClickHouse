<div id="common-issues-with-data-conversion">
  ## 데이터 변환 시 자주 발생하는 문제
</div>

ClickHouse는 일반적으로 [C++ 프로그램과 동일한 동작 방식](https://en.cppreference.com/w/cpp/language/implicit_conversion)을 사용합니다.

`to<type>` 함수와 [cast](#CAST)는 일부 경우에 다르게 동작합니다. 예를 들어 [LowCardinality](../data-types/lowcardinality.md)의 경우, [cast](#CAST)는 [LowCardinality](../data-types/lowcardinality.md) 특성을 제거하지만 `to<type>` 함수는 제거하지 않습니다. [Nullable](../data-types/nullable.md)도 마찬가지입니다. 이러한 동작은 SQL 표준과 호환되지 않으며, [cast&#95;keep&#95;nullable](../../operations/settings/settings.md/#cast_keep_nullable) 설정으로 변경할 수 있습니다.

:::note
데이터 타입의 값을 더 작은 데이터 타입으로 변환할 때(예: `Int64`에서 `Int32`로) 또는
서로 호환되지 않는 데이터 타입 간에 변환할 때(예: `String`에서 `Int`로) 데이터가 손실될 수 있으므로 유의하십시오. 결과가 예상대로 나오는지 반드시 주의 깊게 확인하십시오.
:::

예시:

```sql
SELECT
    toTypeName(toLowCardinality('') AS val) AS source_type,
    toTypeName(toString(val)) AS to_type_result_type,
    toTypeName(CAST(val, 'String')) AS cast_result_type

┌─source_type────────────┬─to_type_result_type────┬─cast_result_type─┐
│ LowCardinality(String) │ LowCardinality(String) │ String           │
└────────────────────────┴────────────────────────┴──────────────────┘

SELECT
    toTypeName(toNullable('') AS val) AS source_type,
    toTypeName(toString(val)) AS to_type_result_type,
    toTypeName(CAST(val, 'String')) AS cast_result_type

┌─source_type──────┬─to_type_result_type─┬─cast_result_type─┐
│ Nullable(String) │ Nullable(String)    │ String           │
└──────────────────┴─────────────────────┴──────────────────┘

SELECT
    toTypeName(toNullable('') AS val) AS source_type,
    toTypeName(toString(val)) AS to_type_result_type,
    toTypeName(CAST(val, 'String')) AS cast_result_type
SETTINGS cast_keep_nullable = 1

┌─source_type──────┬─to_type_result_type─┬─cast_result_type─┐
│ Nullable(String) │ Nullable(String)    │ Nullable(String) │
└──────────────────┴─────────────────────┴──────────────────┘
```

<div id="to-string-functions">
  ## `toString` 함수 관련 참고 사항
</div>

`toString` 함수 계열을 사용하면 숫자, 문자열(단, Fixed String 제외), 날짜, 날짜 및 시간 값 사이를 변환할 수 있습니다.
이 함수들은 모두 하나의 인수를 받습니다.

* 문자열로 변환하거나 문자열에서 변환할 때는 TabSeparated 포맷(및 거의 모든 다른 텍스트 형식)과 동일한 규칙에 따라 값을 포맷하거나 파싱합니다. 문자열을 파싱할 수 없으면 예외가 발생하고 요청이 취소됩니다.
* 날짜를 숫자로 변환하거나 그 반대로 변환할 때 날짜는 Unix epoch 시작 시점 이후의 일 수에 해당합니다.
* 날짜 및 시간 값을 숫자로 변환하거나 그 반대로 변환할 때 해당 값은 Unix epoch 시작 시점 이후의 초 수에 해당합니다.
* `DateTime` 인수에 대한 `toString` 함수는 시간대 이름이 포함된 두 번째 String 인수를 받을 수 있습니다. 예를 들어 `Europe/Amsterdam`입니다. 이 경우 시간은 지정된 시간대에 따라 포맷됩니다.

<div id="to-date-and-date-time-functions">
  ## `toDate`/`toDateTime` 함수에 대한 참고 사항
</div>

`toDate`/`toDateTime` 함수의 날짜 및 날짜/시간 포맷은 다음과 같이 정의됩니다:

```response
YYYY-MM-DD
YYYY-MM-DD hh:mm:ss
```

예외적으로, UInt32, Int32, UInt64 또는 Int64 숫자 타입에서 Date로 변환할 때 숫자가 65536 이상이면, 해당 숫자는 일 수가 아니라 Unix timestamp로 해석되며 Date 값으로 반올림됩니다.
이렇게 하면 흔히 사용되는 `toDate(unix_timestamp)`를 지원할 수 있습니다. 그렇지 않으면 오류가 발생하며, 더 번거로운 `toDate(toDateTime(unix_timestamp))`를 작성해야 합니다.

날짜와 시간이 포함된 날짜 간 변환은 자연스러운 방식으로 수행됩니다. 즉, 시간 값이 없는 경우에는 추가하고, 있는 경우에는 시간 부분을 제거합니다.

숫자 타입 간 변환에는 C++에서 서로 다른 숫자 타입 사이의 assignment와 동일한 규칙이 적용됩니다.

**예시**

```sql title="Query"
SELECT
    now() AS ts,
    time_zone,
    toString(ts, time_zone) AS str_tz_datetime
FROM system.time_zones
WHERE time_zone LIKE 'Europe%'
LIMIT 10
```

```response title="Response"
┌──────────────────ts─┬─time_zone─────────┬─str_tz_datetime─────┐
│ 2023-09-08 19:14:59 │ Europe/Amsterdam  │ 2023-09-08 21:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Andorra    │ 2023-09-08 21:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Astrakhan  │ 2023-09-08 23:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Athens     │ 2023-09-08 22:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Belfast    │ 2023-09-08 20:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Belgrade   │ 2023-09-08 21:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Berlin     │ 2023-09-08 21:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Bratislava │ 2023-09-08 21:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Brussels   │ 2023-09-08 21:14:59 │
│ 2023-09-08 19:14:59 │ Europe/Bucharest  │ 2023-09-08 22:14:59 │
```
