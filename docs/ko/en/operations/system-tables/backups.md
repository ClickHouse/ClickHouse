<div id="description">
  ## 설명
</div>

현재 상태와 기타 속성을 포함하여 모든 `BACKUP` 또는 `RESTORE` 작업의 목록을 제공합니다. 이 테이블(table)은 영구적으로 유지되지 않으며, 마지막 server 재시작 이후에 실행된 작업만 표시합니다.

<div id="columns">
  ## 컬럼
</div>

{/*AUTOGENERATED_START*/ }

* `id` ([String](/ko/sql-reference/data-types/string)) — 작업 ID입니다. `SETTINGS id=...`를 통해 전달되거나 무작위로 생성된 UUID일 수 있습니다.
* `name` ([String](/ko/sql-reference/data-types/string)) — 작업 이름입니다. `Disk('backups', 'my_backup')`와 같은 문자열입니다.
* `base_backup_name` ([String](/ko/sql-reference/data-types/string)) — 기준 백업 작업 이름입니다. `Disk('backups', 'my_base_backup')`와 같은 문자열입니다.
* `query_id` ([String](/ko/sql-reference/data-types/string)) — 백업을 시작한 쿼리의 Query ID입니다.
* `status` ([Enum8(&#39;CREATING&#95;BACKUP&#39; = 0, &#39;BACKUP&#95;CREATED&#39; = 1, &#39;BACKUP&#95;FAILED&#39; = 2, &#39;RESTORING&#39; = 3, &#39;RESTORED&#39; = 4, &#39;RESTORE&#95;FAILED&#39; = 5, &#39;BACKUP&#95;CANCELLED&#39; = 6, &#39;RESTORE&#95;CANCELLED&#39; = 7)](/ko/sql-reference/data-types/enum)) — 백업 또는 복원 작업의 상태입니다.
* `error` ([String](/ko/sql-reference/data-types/string)) — 오류가 발생한 경우의 오류 메시지입니다.
* `start_time` ([DateTime64(6)](/ko/sql-reference/data-types/datetime64)) — 작업이 시작된 시각입니다.
* `end_time` ([DateTime64(6)](/ko/sql-reference/data-types/datetime64)) — 작업이 완료된 시각입니다.
* `num_files` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 백업에 저장된 파일 수입니다.
* `total_size` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 백업에 저장된 파일의 총 크기입니다.
* `num_entries` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 백업의 항목 수입니다. 즉, 백업이 폴더로 저장된 경우 해당 폴더 안의 파일 수입니다.
* `uncompressed_size` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 백업의 압축되지 않은 크기입니다.
* `compressed_size` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 백업의 압축된 크기입니다.
* `files_read` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 이 백업에서 RESTORE 중 읽은 파일 수를 반환합니다.
* `bytes_read` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 이 백업에서 RESTORE 중 읽은 파일의 총 크기를 반환합니다.
* `ProfileEvents` ([Map(LowCardinality(String), UInt64)](/ko/sql-reference/data-types/map)) — 이 작업 중 수집된 모든 profile events입니다.
* `settings` ([Map(LowCardinality(String), String)](/ko/sql-reference/data-types/map)) — 이 작업에 실제로 사용된 백업/복원 전용 설정입니다(`SETTINGS` 절의 설정이며 기본값 포함). 민감한 설정은 노출되지 않습니다.
* `engine_settings` ([Map(LowCardinality(String), String)](/ko/sql-reference/data-types/map)) — 백업 engine의 reader/writer가 실제로 사용한 설정입니다(예: S3 `allow_native_copy`). 작업에 평면 맵으로 표현할 수 없는 2개 이상의 engine이 포함되면 비어 있습니다. 예를 들어 증분 백업 및 복원, 경량 snapshot 복원, 내부가 아닌 `ON CLUSTER` 작업이 여기에 해당합니다.

<div id="restore-atomicity">
  ## 복원의 원자성
</div>

`RESTORE`는 트랜잭션 방식으로 동작하지 않으며, 실패해도 롤백되지 않습니다. 각 테이블에서는 선택된 모든 파트가 복사된 뒤에야 ATTACH가 수행되지만, ATTACH 단계 자체는 트랜잭션 방식이 아닙니다. 즉, 파트는 한 번에 하나씩 순차적으로 표시됩니다. 테이블은 서로 독립적으로 처리됩니다.

**테이블은 서로 독립적입니다.** 한 테이블의 복원이 완료되면, 동일한 명령에서 다른 테이블이 나중에 실패하더라도 해당 테이블은 그대로 유지됩니다:

```sql
RESTORE TABLE db.t0, TABLE db.t1
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

이 명령이 `db.t0`가 완전히 복원된 뒤 `db.t1`의 복원이 아직 끝나기 전에 실패하더라도, `db.t0`는 복원된 상태로 유지됩니다.

**`PARTITIONS` 절은 커밋 경계가 아닙니다.** 이 절은 테이블의 어떤 파트를 복원할지 선택할 뿐입니다:

```sql
RESTORE TABLE db.t0 PARTITIONS '2026-06-01', '2026-06-02', '2026-06-03'
FROM S3('<endpoint>', '<access_key>', '<secret_key>')
SETTINGS
    allow_non_empty_tables = true;
```

테이블에서 선택한 모든 파트는 먼저 복사되며, 모두 준비된 후에만 한 번에 ATTACH됩니다. 따라서 이 명령이 복사 단계에서 실패하면(예: 파티션 `2026-06-01`은 완전히 복사되었지만 `2026-06-02` 및 `2026-06-03`은 아직 완료되지 않은 경우) `2026-06-01`은 **커밋되지 않으며**, 이 명령으로 복원된 데이터는 테이블에 전혀 남지 않습니다. 복사 단계가 완료되고 ATTACH 단계가 시작되면 파트는 한 번에 하나씩 커밋되므로, ATTACH 중에 실패하면 롤백 없이 테이블이 부분적으로만 복원된 상태로 남을 수 있습니다.

파티션을 독립적으로 커밋하려면(즉, 완료된 파티션이 이후 실패가 발생해도 유지되고 개별적으로 다시 시도할 수 있도록 하려면), 각 파티션마다 별도의 `RESTORE`를 실행하고 첫 번째 실행 이후에는 `SETTINGS allow_non_empty_tables = true`를 사용하십시오.
