<div id="description">
  ## 설명
</div>

[샘플링 쿼리 프로파일러](../../operations/optimizing-performance/sampling-query-profiler.md)가 수집한 스택 트레이스를 포함합니다.

ClickHouse는 [trace&#95;log](../../operations/server-configuration-parameters/settings.md#trace_log) 서버 구성 섹션이 설정되어 있으면 이 테이블을 생성합니다. 다음 설정도 함께 참조하십시오: [query&#95;profiler&#95;real&#95;time&#95;period&#95;ns](../../operations/settings/settings.md#query_profiler_real_time_period_ns), [query&#95;profiler&#95;cpu&#95;time&#95;period&#95;ns](../../operations/settings/settings.md#query_profiler_cpu_time_period_ns), [memory&#95;profiler&#95;step](../../operations/settings/settings.md#memory_profiler_step),
[memory&#95;profiler&#95;sample&#95;probability](../../operations/settings/settings.md#memory_profiler_sample_probability), [trace&#95;profile&#95;events](../../operations/settings/settings.md#trace_profile_events).

로그를 분석하려면 `addressToLine`, `addressToLineWithInlines`, `addressToSymbol`, `demangle` 인트로스펙션 함수를 사용하십시오.

<div id="columns">
  ## 컬럼
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/ko/sql-reference/data-types/lowcardinality)) — 쿼리를 실행하는 서버의 호스트명입니다.
* `event_date` ([Date](/ko/sql-reference/data-types/date)) — 샘플링 시점의 날짜입니다.
* `event_time` ([DateTime](/ko/sql-reference/data-types/datetime)) — 샘플링 시점의 타임스탬프입니다.
* `event_time_microseconds` ([DateTime64(6)](/ko/sql-reference/data-types/datetime64)) — 마이크로초 정밀도의 샘플링 시점 타임스탬프입니다.
* `timestamp_ns` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 나노초 단위의 샘플링 시점 타임스탬프입니다.
* `revision` ([UInt32](/ko/sql-reference/data-types/int-uint)) — ClickHouse 서버의 build revision입니다. `clickhouse-client`로 서버에 연결하면 `Connected to ClickHouse server version 19.18.1.`과 유사한 문자열이 표시됩니다. 이 필드에는 서버의 `version`이 아니라 `revision`이 들어 있습니다.
* `trace_type` ([Enum8(&#39;Real&#39; = 0, &#39;CPU&#39; = 1, &#39;Memory&#39; = 2, &#39;MemorySample&#39; = 3, &#39;MemoryPeak&#39; = 4, &#39;ProfileEvent&#39; = 5, &#39;JemallocSample&#39; = 6, &#39;MemoryAllocatedWithoutCheck&#39; = 7, &#39;Instrumentation&#39; = 8)](/ko/sql-reference/data-types/enum)) — 트레이스 유형입니다. `Real`은 wall-clock time 기준으로 스택 트레이스를 수집함을 의미합니다. `CPU`는 CPU time 기준으로 스택 트레이스를 수집함을 의미합니다. `Memory`는 메모리 할당이 다음 watermark를 초과할 때 allocations 및 deallocations를 수집함을 의미합니다. `MemorySample`은 무작위 allocations 및 deallocations를 수집함을 의미합니다. `MemoryPeak`은 Peak memory의 업데이트를 수집함을 의미합니다. `ProfileEvent`는 profile events의 증가분을 수집함을 의미합니다. `JemallocSample`은 jemalloc samples를 수집함을 의미합니다. `MemoryAllocatedWithoutCheck`는 메모리 제한을 무시한 상태에서 수행되는 큰 allocations(&gt;16MiB)을 수집함을 의미합니다(ClickHouse 개발자 전용). `Instrumentation`은 XRay를 통해 수행된 instrumentation으로 수집된 traces를 의미합니다.
* `cpu_id` ([UInt64](/ko/sql-reference/data-types/int-uint)) — CPU 식별자입니다.
* `thread_id` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 스레드 식별자입니다.
* `thread_name` ([LowCardinality(String)](/ko/sql-reference/data-types/lowcardinality)) — 스레드 이름입니다.
* `query_id` ([String](/ko/sql-reference/data-types/string)) — query&#95;log system table에서 실행 중이던 쿼리의 상세 정보를 조회하는 데 사용할 수 있는 쿼리 식별자입니다.
* `trace` ([Array(UInt64)](/ko/sql-reference/data-types/array)) — 샘플링 시점의 스택 트레이스입니다. 각 요소는 ClickHouse 서버 프로세스 내부의 가상 메모리 주소입니다.
* `size` ([Int64](/ko/sql-reference/data-types/int-uint)) — trace type이 Memory, MemorySample, MemoryAllocatedWithoutCheck 또는 MemoryPeak인 경우 할당된 메모리 크기이며, 그 외의 trace type에서는 0입니다.
* `ptr` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 할당된 청크의 주소입니다.
* `memory_context` ([Enum8(&#39;Unknown&#39; = -1, &#39;Global&#39; = 0, &#39;User&#39; = 1, &#39;Process&#39; = 2, &#39;Thread&#39; = 3, &#39;Max&#39; = 4)](/ko/sql-reference/data-types/enum)) — Memory Tracker의 Context입니다(Memory/MemoryPeak에만 해당). `Unknown` Context는 이 trace&#95;type에 대해 정의되지 않습니다. `Global`은 서버 Context를 의미합니다. `User`는 사용자/머지 Context를 의미합니다. `Process`는 프로세스(즉, 쿼리) Context를 의미합니다. `Thread`는 스레드(특정 프로세스의 스레드) Context를 의미합니다. `Max`는 memory tracker가 차단되지 않았음을 나타내는 특수 값입니다(`blocked&#95;context` 컬럼용).
* `memory_blocked_context` ([Enum8(&#39;Unknown&#39; = -1, &#39;Global&#39; = 0, &#39;User&#39; = 1, &#39;Process&#39; = 2, &#39;Thread&#39; = 3, &#39;Max&#39; = 4)](/ko/sql-reference/data-types/enum)) — 메모리 tracker가 차단된 Context입니다(ClickHouse 개발자 전용). `Unknown` Context는 이 trace&#95;type에 대해 정의되지 않습니다. `Global`은 server Context를 나타냅니다. `User`는 사용자/머지 Context를 나타냅니다. `Process`는 프로세스(즉, 쿼리) Context를 나타냅니다. `Thread`는 스레드(특정 프로세스의 스레드) Context를 나타냅니다. `Max`는 메모리 tracker가 차단되지 않았음을 의미하는 특수 값입니다(`blocked&#95;context` 컬럼 기준).
* `event` ([LowCardinality(String)](/ko/sql-reference/data-types/lowcardinality)) — trace type이 ProfileEvent인 경우 갱신된 profile event의 이름이며, 다른 trace type에서는 빈 문자열입니다.
* `increment` ([Int64](/ko/sql-reference/data-types/int-uint)) — trace type이 ProfileEvent인 경우 profile event의 증가량이며, 다른 trace type에서는 0입니다.
* `symbols` ([Array(LowCardinality(String))](/ko/sql-reference/data-types/array)) — symbolization이 활성화되어 있으면 `trace`에 해당하는 디맹글된 심볼 이름을 포함합니다. Symbolization은 서버 구성 파일의 `trace_log` 아래 `symbolize` 설정에서 활성화하거나 비활성화할 수 있습니다.
* `lines` ([Array(LowCardinality(String))](/ko/sql-reference/data-types/array)) — symbolization이 활성화되어 있으면 `trace`에 해당하는 파일 이름과 줄 번호가 포함된 문자열을 포함합니다.
* `function_id` ([Nullable(Int32)](/ko/sql-reference/data-types/nullable)) — trace type이 Instrumentation인 경우 elf-binary의 xray&#95;instr&#95;map 섹션에서 함수에 할당된 ID입니다.
* `function_name` ([Nullable(String)](/ko/sql-reference/data-types/nullable)) — trace type이 Instrumentation인 경우 계측된 함수의 이름입니다.
* `handler` ([Nullable(String)](/ko/sql-reference/data-types/nullable)) — trace type이 Instrumentation인 경우 계측된 함수의 handler입니다.
* `entry_type` ([Nullable(Enum8(&#39;Entry&#39; = 0, &#39;Exit&#39; = 1))](/ko/sql-reference/data-types/nullable)) — trace type이 Instrumentation인 경우 계측된 함수의 entry 유형입니다.
* `duration_nanoseconds` ([Nullable(UInt64)](/ko/sql-reference/data-types/nullable)) — trace type이 Instrumentation인 경우 함수가 실행된 시간(나노초)입니다.

**별칭:**

* `build_id` — `'E2EEB60ED9503BFFA825B628D480CCDC40B2D416'`의 별칭입니다.

{/*AUTOGENERATED_END*/ }

심벌화는 서버 설정 파일의 `trace_log` 아래 `symbolize`에서 활성화하거나 비활성화할 수 있습니다.

<div id="chrome-event-trace-format">
  ## Chrome Event Trace Format으로 변환하기
</div>

프로파일링 데이터는 다음 쿼리로 Chrome의 Event Trace Format으로 변환할 수 있습니다. 이 쿼리를 `chrome_trace.sql` 파일로 저장하십시오:

```sql
WITH traces AS (
    SELECT * FROM system.trace_log
    WHERE event_date >= today() AND trace_type = 'Instrumentation' AND handler = 'profile'
    ORDER BY event_time, entry_type
)
SELECT
    format(
        '{{"traceEvents": [{}\n]}}',
        arrayStringConcat(
            groupArray(
                format(
                    '\n{{"name": "{}", "cat": "clickhouse", "ph": "{}", "ts": {}, "pid": 1, "tid": {}, "args": {{"query_id": "{}", "cpu_id": {}, "stack": [{}]}}}},',
                    function_name,
                    if(entry_type = 0, 'B', 'E'),
                    timestamp_ns/1000,
                    toString(thread_id),
                    query_id,
                    cpu_id,
                    arrayStringConcat(arrayMap((x, y) -> concat('"', x, ': ', y, '", '), lines, symbols))
                )
            )
        )
    )
FROM traces;
```

그리고 이를 ClickHouse Client에서 실행해 `trace.json` 파일로 내보내면 [Perfetto](https://ui.perfetto.dev/) 또는 [speedscope](https://www.speedscope.app/)로 가져올 수 있습니다.

```bash
echo $(clickhouse client --query "$(cat chrome_trace.sql)") > trace.json
```

더 간결하지만 정보가 적은 트레이스를 원한다면 스택 부분은 생략할 수 있습니다.
