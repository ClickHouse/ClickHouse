<div id="description">
  ## 설명
</div>

이 테이블에는 [MergeTree](/ko/engines/table-engines/mergetree-family/mergetree.md) 테이블의 [뮤테이션](/ko/sql-reference/statements/alter/index.md#mutations)과 그 진행 상황에 대한 정보가 포함되어 있습니다. 각 뮤테이션 명령은 하나의 행으로 표시됩니다.

<div id="columns">
  ## 컬럼:
</div>

{/*AUTOGENERATED_START*/ }

* `database` ([String](/ko/sql-reference/data-types/string)) — 뮤테이션이 적용된 데이터베이스의 이름입니다.
* `table` ([String](/ko/sql-reference/data-types/string)) — 뮤테이션이 적용된 테이블의 이름입니다.
* `mutation_id` ([String](/ko/sql-reference/data-types/string)) — 뮤테이션 ID입니다. 복제된 테이블에서는 이 ID가 ClickHouse Keeper의 `<table_path_in_clickhouse_keeper>/mutations/` 디렉터리에 있는 znode 이름에 대응합니다. 복제되지 않은 테이블에서는 이 ID가 테이블의 데이터 디렉터리에 있는 파일 이름에 대응합니다.
* `command` ([String](/ko/sql-reference/data-types/string)) — 뮤테이션 명령 문자열입니다(`ALTER TABLE [db.]table` 뒤의 쿼리 부분).
* `create_time` ([DateTime](/ko/sql-reference/data-types/datetime)) — 뮤테이션 명령이 실행되도록 제출된 날짜 및 시간입니다.
* `block_numbers.partition_id` ([Array(String)](/ko/sql-reference/data-types/array)) — 복제된 테이블의 뮤테이션에서는 이 배열에 파티션 ID가 들어 있습니다(파티션당 1개 레코드). 복제되지 않은 테이블의 뮤테이션에서는 이 배열이 비어 있습니다.
* `block_numbers.number` ([Array(Int64)](/ko/sql-reference/data-types/array)) — 복제된 테이블의 뮤테이션에서는 이 배열에 각 파티션별로 1개의 레코드가 들어 있으며, 뮤테이션이 획득한 block 번호를 나타냅니다. 각 파티션에서는 이 번호보다 작은 번호의 block을 포함한 파트만 뮤테이션됩니다. 복제되지 않은 테이블에서는 모든 파티션의 block 번호가 하나의 시퀀스를 이룹니다. 즉, 복제되지 않은 테이블의 뮤테이션에서는 이 컬럼에 뮤테이션이 획득한 단일 block 번호를 담은 레코드 1개가 들어 있습니다.
* `parts_in_progress_names` ([Array(String)](/ko/sql-reference/data-types/array)) — 현재 뮤테이션이 진행 중인 데이터 파트 이름의 배열입니다.
* `parts_to_do_names` ([Array(String)](/ko/sql-reference/data-types/array)) — 뮤테이션이 완료되려면 뮤테이션되어야 하는 데이터 파트 이름의 배열입니다.
* `parts_to_do` ([Int64](/ko/sql-reference/data-types/int-uint)) — 뮤테이션이 완료되려면 뮤테이션되어야 하는 데이터 파트 수입니다. 참고: `parts_to_do` = 0이어도, 새 데이터 파트를 생성 중이며 이후 뮤테이션 대상이 되는 장시간 실행 INSERT 때문에 복제된 테이블의 뮤테이션이 아직 완료되지 않았을 수 있습니다.
* `parts_postpone_reasons` ([Map(String, String)](/ko/sql-reference/data-types/map)) — 파트 이름과 해당 파트가 연기된 이유를 매핑한 맵입니다.
* `is_done` ([UInt8](/ko/sql-reference/data-types/int-uint)) — 뮤테이션 완료 여부를 나타내는 플래그입니다. 가능한 값: 뮤테이션이 완료된 경우 1, 아직 진행 중인 경우 0입니다.
* `is_killed` ([UInt8](/ko/sql-reference/data-types/int-uint)) — 뮤테이션이 중지되었는지 여부를 나타냅니다. ClickHouse Cloud에서만 사용할 수 있습니다. 참고: is&#95;killed=1이라고 해서 반드시 뮤테이션이 완전히 종료되었음을 의미하지는 않습니다. is&#95;killed=1이고 is&#95;done=0인 상태가 오랜 기간 지속될 수 있습니다. 이는 다른 장시간 실행 중인 뮤테이션이 중지된 뮤테이션을 가로막고 있을 때 발생할 수 있습니다. 이는 정상적인 상황입니다.
* `latest_failed_part` ([String](/ko/sql-reference/data-types/string)) — 가장 최근에 뮤테이션하지 못한 파트의 이름입니다.
* `latest_fail_time` ([DateTime](/ko/sql-reference/data-types/datetime)) — 가장 최근 파트 뮤테이션 실패가 발생한 날짜 및 시간입니다.
* `latest_fail_reason` ([String](/ko/sql-reference/data-types/string)) — 가장 최근 파트 뮤테이션 실패를 일으킨 예외 메시지입니다.
* `latest_fail_error_code_name` ([String](/ko/sql-reference/data-types/string)) — 가장 최근 파트 뮤테이션 실패를 일으킨 예외의 오류 코드입니다.

{/*AUTOGENERATED_END*/ }

:::note

* 파트 이름이 `parts_postpone_reasons`에 없고 아직 뮤테이션이 적용되지 않았다면, 해당 파트는 아직 뮤테이션 대상으로 예약되지 않았음을 의미합니다.

* 파트 이름 `all_parts`는 아직 뮤테이션이 적용되지 않은 모든 파트를 나타냅니다.
  :::

* `is_killed` ([UInt8](/ko/sql-reference/data-types/int-uint.md)) — 뮤테이션이 중단되었는지 여부를 나타냅니다. **ClickHouse Cloud에서만 사용할 수 있습니다.**

:::note
`is_killed=1`이라고 해서 뮤테이션이 완전히 종료되었다는 의미는 아닙니다. `is_killed=1`이고 `is_done=0`인 상태가 오랜 기간 유지될 수 있습니다. 이는 장시간 실행 중인 다른 뮤테이션이 중단된 뮤테이션을 가로막고 있을 때 발생할 수 있습니다. 이는 정상적인 상황입니다.
:::

* `is_done` ([UInt8](/ko/sql-reference/data-types/int-uint.md)) — 뮤테이션의 완료 여부를 나타내는 플래그입니다. 가능한 값:
  * 뮤테이션이 완료된 경우 `1`,
  * 뮤테이션이 아직 진행 중인 경우 `0`.

:::note
`parts_to_do = 0`이어도, 뮤테이션이 적용되어야 하는 새 데이터 파트를 생성하는 장시간 실행되는 `INSERT` 쿼리 때문에 복제된 테이블의 뮤테이션이 아직 완료되지 않았을 수 있습니다.
:::

일부 데이터 파트에 뮤테이션을 적용하는 중 문제가 발생한 경우, 다음 컬럼에 추가 정보가 포함됩니다:

* `latest_failed_part` ([String](/ko/sql-reference/data-types/string.md)) — 가장 최근에 뮤테이션을 적용하지 못한 파트의 이름입니다.
* `latest_fail_time` ([DateTime](/ko/sql-reference/data-types/datetime.md)) — 가장 최근 파트 뮤테이션 failure가 발생한 날짜 및 시간입니다.
* `latest_fail_reason` ([String](/ko/sql-reference/data-types/string.md)) — 가장 최근 파트 뮤테이션 failure를 일으킨 예외 메시지입니다.

<div id="monitoring-mutations">
  ## 뮤테이션 모니터링
</div>

`system.mutations` 테이블(table)의 진행 상태를 추적하려면 다음 쿼리를 사용하십시오:

```sql
SELECT * FROM clusterAllReplicas('cluster_name', 'system', 'mutations')
WHERE is_done = 0 AND table = 'tmp';

-- or

SELECT * FROM clusterAllReplicas('cluster_name', 'system.mutations')
WHERE is_done = 0 AND table = 'tmp';
```

참고: 이 작업을 수행하려면 `system.*` 테이블에 대한 읽기 권한이 필요합니다.

:::tip Cloud 사용
ClickHouse Cloud에서는 각 노드의 `system.mutations` 테이블에 클러스터의 모든 뮤테이션이 포함되므로 `clusterAllReplicas`는 필요하지 않습니다.
:::
