<div id="description">
  ## 설명
</div>

이 테이블에는 [`EXPLAIN PIPELINE`](../../sql-reference/statements/explain.md#explain-pipeline)에서 확인할 수 있는 프로세서 수준 프로파일링 정보가 포함되어 있습니다.

<div id="columns">
  ## 컬럼
</div>

{/*AUTOGENERATED_START*/ }

* `hostname` ([LowCardinality(String)](/ko/sql-reference/data-types/lowcardinality)) — 쿼리를 실행하는 서버의 호스트명입니다.
* `event_date` ([Date](/ko/sql-reference/data-types/date)) — 이벤트가 발생한 날짜입니다.
* `event_time` ([DateTime](/ko/sql-reference/data-types/datetime)) — 이벤트가 발생한 날짜와 시각입니다.
* `event_time_microseconds` ([DateTime64(6)](/ko/sql-reference/data-types/datetime64)) — 이벤트가 발생한 날짜와 시각(마이크로초 정밀도)입니다.
* `id` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 프로세서의 ID입니다.
* `parent_ids` ([Array(UInt64)](/ko/sql-reference/data-types/array)) — 상위 프로세서 ID 목록입니다.
* `plan_step` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 이 프로세서를 생성한 쿼리 계획 단계의 ID입니다. 어떤 단계에서도 이 프로세서가 추가되지 않은 경우 값은 0입니다.
* `plan_step_name` ([String](/ko/sql-reference/data-types/string)) — 이 프로세서를 생성한 쿼리 계획 단계의 이름입니다. 어떤 단계에서도 이 프로세서가 추가되지 않은 경우 값은 비어 있습니다.
* `plan_step_description` ([String](/ko/sql-reference/data-types/string)) — 이 프로세서를 생성한 쿼리 계획 단계의 설명입니다. 어떤 단계에서도 이 프로세서가 추가되지 않은 경우 값은 비어 있습니다.
* `plan_group` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 쿼리 계획 단계에 의해 생성된 경우의 프로세서 그룹입니다. 그룹은 동일한 쿼리 계획 단계에서 추가된 프로세서를 논리적으로 구분한 것입니다. 그룹은 EXPLAIN PIPELINE 결과를 보기 좋게 표시하는 데에만 사용됩니다.
* `initial_query_id` ([String](/ko/sql-reference/data-types/string)) — 원본 쿼리의 ID입니다(분산 쿼리 실행용).
* `query_id` ([String](/ko/sql-reference/data-types/string)) — 쿼리의 ID입니다.
* `name` ([LowCardinality(String)](/ko/sql-reference/data-types/lowcardinality)) — 프로세서의 이름입니다.
* `elapsed_us` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 이 프로세서가 실행된 마이크로초 수입니다.
* `input_wait_elapsed_us` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 이 프로세서가 데이터(다른 프로세서로부터)를 기다린 마이크로초 수입니다.
* `output_wait_elapsed_us` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 출력 포트가 가득 차 이 프로세서가 대기한 마이크로초 수입니다.
* `input_rows` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 프로세서가 소비한 행 수입니다.
* `input_bytes` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 프로세서가 소비한 바이트 수입니다.
* `output_rows` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 프로세서가 생성한 행 수입니다.
* `output_bytes` ([UInt64](/ko/sql-reference/data-types/int-uint)) — 프로세서가 생성한 바이트 수입니다.
* `processor_uniq_id` ([String](/ko/sql-reference/data-types/string)) — pipeline 내 프로세서의 고유 ID입니다.
* `step_uniq_id` ([String](/ko/sql-reference/data-types/string)) — 계획 내 단계의 고유 ID입니다.

{/*AUTOGENERATED_END*/ }

<div id="example">
  ## 예시
</div>

```sql title="Query"
EXPLAIN PIPELINE
SELECT sleep(1)
┌─explain─────────────────────────┐
│ (Expression)                    │
│ ExpressionTransform             │
│   (SettingQuotaAndLimits)       │
│     (ReadFromStorage)           │
│     SourceFromSingleChunk 0 → 1 │
└─────────────────────────────────┘

SELECT sleep(1)
SETTINGS log_processors_profiles = 1
Query id: feb5ed16-1c24-4227-aa54-78c02b3b27d4
┌─sleep(1)─┐
│        0 │
└──────────┘
1 rows in set. Elapsed: 1.018 sec.

SELECT
    name,
    elapsed_us,
    input_wait_elapsed_us,
    output_wait_elapsed_us
FROM system.processors_profile_log
WHERE query_id = 'feb5ed16-1c24-4227-aa54-78c02b3b27d4'
ORDER BY name ASC
```

```text title="Response"
┌─name────────────────────┬─elapsed_us─┬─input_wait_elapsed_us─┬─output_wait_elapsed_us─┐
│ ExpressionTransform     │    1000497 │                  2823 │                    197 │
│ LazyOutputFormat        │         36 │               1002188 │                      0 │
│ LimitsCheckingTransform │         10 │               1002994 │                    106 │
│ NullSource              │          5 │               1002074 │                      0 │
│ NullSource              │          1 │               1002084 │                      0 │
│ SourceFromSingleChunk   │         45 │                  4736 │                1000819 │
└─────────────────────────┴────────────┴───────────────────────┴────────────────────────┘
```

여기에서 다음을 확인할 수 있습니다:

* `ExpressionTransform`이 `sleep(1)` 함수를 실행했으므로 `work`는 1e6이 되며, 따라서 `elapsed_us` &gt; 1e6입니다.
* `ExpressionTransform`은 `sleep(1)` 실행 중에는 어떤 데이터도 받지 않으므로 `SourceFromSingleChunk`는 대기해야 합니다. 따라서 1e6 us 동안 `PortFull` 상태가 되며, 그 결과 `output_wait_elapsed_us` &gt; 1e6입니다.
* `LimitsCheckingTransform`/`NullSource`/`LazyOutputFormat`은 결과를 처리하려면 `ExpressionTransform`이 `sleep(1)` 실행을 마칠 때까지 대기해야 하므로 `input_wait_elapsed_us` &gt; 1e6입니다.
