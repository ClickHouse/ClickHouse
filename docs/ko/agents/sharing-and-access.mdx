Agents는 계층형 권한 모델을 사용합니다. 역할은 사용자가 어떤 기능을 사용할 수 있는지 자체를 제어하고, 리소스 수준의 접근 목록은 특정 에이전트나 다른 리소스를 누가 사용할 수 있는지를 제어하며, 관리자 권한은 모든 항목을 누가 관리하는지를 제어합니다.

## 역할 {#roles}

역할은 한 명 이상의 사용자에게 할당되는 기능 권한의 묶음입니다. 기본 역할은 다음과 같습니다.

* **User** - 에이전트를 실행하고 채팅할 수 있습니다. 에이전트 빌드, 스킬 생성, 리소스 공유 등의 가능 여부는 해당 역할의 기능별 토글 설정에 따라 결정됩니다.
* **관리자** - User의 모든 권한과 더불어 사용자 관리, 마켓플레이스 구성, 권한 부여 등 조직 수준의 제어 기능을 사용할 수 있습니다.

관리자는 토글을 개별적으로 설정한 사용자 정의 역할을 생성하여 권한을 보다 세분화하여 제어할 수 있습니다.

## 리소스 공유 {#resource-sharing}

에이전트, 프롬프트, 스킬에는 각각 접근 목록이 있습니다. 주체별로 다음 3가지 액세스 수준을 지정할 수 있습니다.

* **뷰어** - 리소스를 사용할 수 있지만 수정할 수는 없습니다.
* **편집자** - 리소스의 구성(지침, 연결된 도구, 모델 등)을 변경할 수 있습니다.
* **소유자** - 편집자 권한에 더해 리소스를 삭제하거나 공유 설정을 변경할 수 있습니다.

리소스를 생성하면 기본적으로 생성한 사용자가 소유자가 됩니다. 명시적으로 공유하지 않은 리소스는 생성한 사용자만 사용할 수 있는 비공개 상태로 유지됩니다.

## 보안 주체 {#principals}

다음 대상에게 액세스 권한을 부여할 수 있습니다.

* **개별 사용자** - 한 번에 한 명의 사용자에게 부여합니다.
* **그룹** - 팀 또는 조직 단위에 부여합니다. 이후 사용자가 그룹에 추가되거나 그룹에서 제외되면 해당 사용자의 액세스 권한이 자동으로 갱신됩니다.
* **조직 전체** - 조직의 모든 구성원이 리소스를 볼 수 있습니다. 단, 역할 수준에서 이를 허용하는 토글이 활성화되어 있어야 합니다.

리소스를 조직 전체에 공개해야 [마켓플레이스](/ko/agents/marketplace)에서 해당 리소스를 찾을 수 있습니다.

## 에이전트 공유 {#share-an-agent}

에이전트 빌더 하단의 **공유** 아이콘을 클릭하십시오. 아이콘의 배지에는 현재 액세스 권한이 있는 사용자 또는 그룹의 수가 표시됩니다.

공유받은 사용자는 다음에 새로 고침하면 사용 가능한 에이전트 목록에서 해당 에이전트를 확인할 수 있습니다. 액세스 권한을 철회하려면 같은 모달 대화 상자에서 해당 행을 삭제하십시오. 공유받은 사용자는 즉시 액세스 권한을 잃으며, 진행 중인 대화는 끝까지 완료되지만 새 대화는 시작할 수 없습니다.

## 기본 에이전트 {#default-agent}

에이전트 하나를 기본 에이전트로 지정할 수 있습니다. 다른 에이전트를 선택하지 않으면 새 대화는 해당 에이전트로 시작됩니다. 관리자는 기본 에이전트를 직접 지정하지 않은 사용자에게 적용할 조직 전체 기본 에이전트를 설정할 수도 있습니다.

## 관리자 작업 {#admin-operations}

관리자만 수행할 수 있는 작업은 다음과 같습니다.

* 역할 생성 및 편집
* 마켓플레이스 카테고리 구성 및 추천 에이전트 선별
* 조직 수준의 기능 활성화 또는 비활성화(메모리, 웹 검색, 코드 인터프리터, 마켓플레이스 등)
* 다른 사용자에게 관리자 권한 부여

ClickHouse Cloud에서는 조직 관리자가 관리자 패널을 사용할 수 있습니다. 관리자 패널이 표시되지 않으면 조직 관리자 또는 ClickHouse Cloud 지원팀에 액세스 권한을 요청하십시오.

## 주의 사항 {#gotchas}

* **에이전트를 삭제하면 모든 공유가 해제됩니다.** 공유받은 사용자는 액세스 권한을 잃으며, 해당 에이전트와 나눈 저장된 대화는 계속 열람할 수 있지만 이어서 진행할 수는 없습니다.
* **공유된 에이전트를 편집하면 이를 사용하는 모든 사용자에게 영향을 줍니다.** 다른 사용자에게 지장을 주지 않고 실험하려면 복사본을 사용하십시오.
* **사용자의 역할을 회수해도 해당 사용자가 생성한 리소스는 삭제되지 않습니다.** 해당 사용자의 에이전트, 프롬프트, 스킬은 접근 목록에 그대로 남으므로, 완전히 오프보딩하기 전에 소유권을 이전하십시오.
