코드 인터프리터를 사용하면 에이전트가 관리형 샌드박스에서 코드를 실행할 수 있습니다. 계산, 데이터 변환, 포맷 변환, 차트 작성 등 자연어보다 코드로 처리하는 편이 더 적합한 모든 작업에 활용할 수 있습니다.

## 코드 인터프리터 활성화 {#enable-it}

에이전트 빌더의 **Capabilities** 섹션에서 **Run Code**를 활성화한 다음 저장하십시오. 에이전트는 사용자의 요청과 에이전트 지침을 바탕으로 코드 실행 시점을 판단합니다.

## 지원되는 언어 {#supported-languages}

샌드박스는 2개의 범용 런타임과 몇 가지 셸 유틸리티를 갖춘 Unix 환경입니다.

* **Python 3** - 데이터 작업에 기본으로 사용하는 언어입니다.
* **Node.js (JavaScript)** - 에이전트가 해당 작업에 JS를 선호할 때 사용합니다.
* **Bash** 및 **sh** - 명령어를 연쇄 실행하고 간단한 입출력을 처리하는 셸 스크립팅 도구입니다.
* **AWK** 및 **sed** - 줄 단위 텍스트 처리 도구입니다.
* **bc** - 임의 정밀도 연산 도구입니다.

에이전트는 데이터 파싱, 변환, 계산이 필요한 작업에는 우선 Python을 사용합니다.

<Tip>
  셸 도구는 한 줄 명령으로 처리하는 편이 실제로 유리한 작업에만 사용하십시오.
</Tip>

## 파일 {#files}

사용자는 대화에 파일을 업로드할 수 있으며, 코드 인터프리터는 샌드박스 작업 디렉터리에서 해당 파일에 액세스할 수 있습니다. 코드에서 출력 파일(CSV, 플롯, 아카이브 등)을 생성할 수도 있으며, 생성된 파일은 대화에 다운로드 가능한 첨부 파일로 표시됩니다.

## 샌드박스 격리 {#sandbox-isolation}

각 실행은 네트워크 접근과 영구 저장소가 없는 일시적 샌드박스에서 이루어집니다. 세션 간에는 상태가 공유되지 않으므로, 에이전트가 명시적으로 다시 로드하지 않는 한 한 번의 실행에서 생성된 변수와 파일은 다음 실행으로 이어지지 않습니다.

플랜별 리소스 제한(메모리, 실행당 파일 수, 월별 요청 QUOTA)이 적용됩니다. 오류와 stderr는 stdout과 함께 대화에 표시됩니다.

## 사용 시점 {#when-to-use-it}

언어 모델이 추론만으로는 안정적으로 도출할 수 없는 결정적 계산이 필요한 경우에는 코드 인터프리터를 사용하십시오.
대표적인 사용 사례는 다음과 같습니다.

* 사용자가 업로드한 CSV 또는 JSON 파일 파싱
* 요약 통계 계산 또는 간단한 시뮬레이션 실행
* 포맷 간 변환(Parquet, JSON, CSV)
* 쿼리 결과(query results)를 바탕으로 플롯 생성

<Tip>
  모델이 컨텍스트만으로 이미 답할 수 있는 작업에는 사용하지 마십시오.
  코드를 실행하면 지연 시간이 늘어나고 QUOTA가 소비됩니다.
</Tip>
