스킬은 에이전트가 필요할 때 적용할 수 있는 재사용 가능한 지침 묶음입니다. 브랜드 스타일 가이드, 코드 리뷰 체크리스트, 특정 워크플로용 런북처럼 여러 에이전트에서 반복되는 절차는 각 에이전트의 시스템 프롬프트에 같은 지침을 중복으로 작성하지 말고 스킬로 만들어 사용하세요.

## 스킬의 구조 {#anatomy-of-a-skill}

스킬은 짧은 프론트매터 헤더가 포함된 Markdown 파일입니다.

```markdown
---
name: revenue-report
description: Generates the weekly revenue report using our standard segments
always-apply: false
user-invocable: true
---

When asked to generate a revenue report:
1. Filter to the requested period.
2. Apply the standard MRR formula:
     SUM(CASE
       WHEN billing_cycle = 'monthly' THEN amount
       WHEN billing_cycle = 'yearly'  THEN amount / 12
       ELSE 0
     END)
3. Break down by segment: Enterprise, Mid-Market, SMB.
4. Render the result as a Markdown table.
```

가장 중요한 프론트매터 설정 항목은 다음과 같습니다.

* **`name`** - kebab-case 형식의 식별자입니다.
* **`description`** - 모델이 이 스킬을 언제 사용할지 판단할 때 참고하는 짧은 요약입니다. 가장 중요한 필드이므로 구체적으로 작성하십시오. 설명이 모호하면 엉뚱한 스킬이 호출될 수 있습니다.
* **`always-apply`** - `true`로 설정하면 스킬이 선택 과정을 거치지 않고 모든 대화 턴에 미리 포함됩니다. always-apply 스킬은 매 메시지마다 컨텍스트를 소비하므로 꼭 필요한 경우에만 사용하십시오.
* **`user-invocable`** - `true`(기본값)로 설정하면 스킬이 `$` 팝오버에 표시되어 수동으로 선택할 수 있습니다.

`SKILL.md`와 관련 자산을 포함한 `.zip` 파일을 업로드하면 참고 문서, 샘플 쿼리, 간단한 스크립트 등의 보조 파일을 스킬과 함께 묶어 제공할 수 있습니다.

## 스킬 사용 {#use-a-skill}

에이전트가 대화에서 스킬을 사용하는 방식은 세 가지입니다.

* **사용자 호출** - 컴포저에서 `$`를 누르고 팝오버에서 스킬을 선택합니다. 선택한 스킬의 내용이 다음 턴에 미리 로드됩니다.
* **모델 자동 선택** - 에이전트가 스킬의 `description`을 바탕으로 해당 스킬을 언제 적용할지 스스로 판단합니다.
* **Always-apply** - 이 방식으로 구성된 스킬은 매 턴마다 미리 로드됩니다.

## 스킬 관리 {#manage-skills}

클라우드 콘솔의 Skills 패널에서는 스킬을 인라인으로 생성하거나 `.md` 또는 `.zip` 파일을 업로드할 수 있으며, 사용자 계정에서 활성화할 스킬을 관리할 수 있습니다. 직접 소유한 스킬은 기본적으로 활성 상태입니다. 스킬을 비활성화하면 삭제하지 않고도 팝오버와 모델의 카탈로그에서 해당 스킬을 제외할 수 있습니다.

스킬은 다른 사용자와 공유할 수 있습니다([공유 및 접근](/ko/agents/sharing-and-access) 참조).

## 스킬과 지침 비교 {#skills-vs-instructions}

* **에이전트 지침**은 에이전트의 정체성과 전반적인 동작 방식을 정의합니다. 해당 에이전트에는 항상 적용됩니다.
* **스킬**은 상황에 따라 적용됩니다. 필요할 때만 적용되며, 범위는 특정 워크플로로 한정됩니다.

동일한 단계별 지침이 여러 에이전트에서 반복적으로 사용되거나, 매 턴이 아니라 특정 사용자 요청이 있을 때만 트리거되도록 하려면 스킬을 사용하십시오.
