서브에이전트는 부모 에이전트가 독립적인 하위 작업을 맡기기 위해 호출하는 자식 에이전트입니다. 자식 에이전트는 자체 컨텍스트 윈도우와 자체적으로 연결된 도구를 사용해 실행된 후, 간결한 결과를 부모 에이전트에 반환합니다. 부모 에이전트는 자식 에이전트의 중간 단계를 전혀 보지 않고 최종 답변만 받습니다.

서브에이전트를 사용하면 부모 에이전트가 본래 작업에 집중하도록 할 수 있습니다. 장시간에 걸친 리서치 패스, 도구를 많이 사용하는 탐색, 전문적인 검토 단계는 토큰을 많이 소비하는 중간 상태가 부모 에이전트의 컨텍스트에 포함되지 않을 때 더 잘 동작합니다.

## 서브에이전트 활성화 {#enable-subagents}

에이전트 빌더에서 **고급 설정**을 열고 **하위 에이전트** 토글을 켜십시오. 그러면 다음 2개의 컨트롤이 추가로 표시됩니다.

* **Allow self-spawn** - 켜면 에이전트가 병렬 작업을 위해 자신의 복사본을 생성할 수 있습니다. fan-out 패턴(하나의 상위 에이전트와 여러 개의 동일한 worker)에 유용합니다.
* **Additional subagents** - 이 상위 에이전트가 작업을 위임할 수 있는 다른 에이전트를 지정합니다. 상위 에이전트는 런타임에 작업 내용에 따라 어떤 서브에이전트를 호출할지(또는 호출하지 않을지) 결정합니다.

설정을 저장하십시오. 이후 에이전트가 실행되면 서브에이전트를 호출할 수 있는 새 도구가 제공됩니다.

## 서브에이전트가 유용한 경우 {#when-a-subagent-helps}

* **리서치 하위 작업** - 상위 에이전트가 복잡한 질문을 여러 부분으로 나누고, 각 부분을 해당 영역에 특화된 서브에이전트에 맡긴 뒤 응답을 종합합니다.
* **도구 사용이 많은 패스** - 코드 인터프리터 세션, 여러 단계에 걸친 웹 검색 루프 등 중간 도구 출력이 상위 에이전트의 컨텍스트를 차지하게 되는 모든 작업이 여기에 해당합니다.
* **전문 검토** - 한 에이전트가 생성하고 다른 에이전트가 검토하며, 검토 에이전트의 전체 추론 과정은 해당 에이전트의 컨텍스트 윈도우 안에만 유지됩니다.

단순한 호출에는 서브에이전트를 사용하지 마십시오. 작업을 넘기는 과정에서 지연 시간과 토큰이 추가로 발생합니다.

## 서브에이전트와 에이전트 체인 비교 {#subagents-vs-agent-chain}

서브에이전트는 런타임 위임 메커니즘으로, 상위 에이전트가 실행 중에 동적으로 결정합니다. 반면 에이전트 체인은 고정된 순서로 실행되는 에이전트들을 미리 정의해 둔 그래프입니다. 라우팅이 동적이면 서브에이전트를, 라우팅이 고정되어 있으면 체인을 사용하십시오.

## 제한 {#limits}

* 상위 에이전트당 나열할 수 있는 서브에이전트는 최대 **10**개입니다.
* 루트 에이전트로부터의 깊이는 최대 **5**홉입니다.
* 한 번의 실행에서 로드되는 중복 없는 서브에이전트 대상은 최대 **50**개입니다.
* 요청당 확장되는 서브에이전트 구성은 최대 **100**개입니다.

참조하는 서브에이전트는 상위 에이전트를 실행하는 사용자가 볼 수 있어야 합니다. 액세스할 수 없거나 삭제된 에이전트를 가리키는 참조는 별도의 알림 없이 건너뜁니다. 따라서 자식 에이전트가 없는 경우에도 상위 에이전트가 문제없이 동작하도록 설계하십시오.
