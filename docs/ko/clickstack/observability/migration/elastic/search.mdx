## ClickHouse Observability와 Elastic의 검색 {#search-in-clickstack-and-elastic-self-configured}

ClickHouse는 고성능 분석 워크로드를 위해 처음부터 설계된 SQL 네이티브 엔진입니다. 반면 Elasticsearch는 SQL과 유사한 인터페이스를 제공하며, SQL을 내부의 Elasticsearch 쿼리 DSL로 변환합니다. 즉, SQL이 일급 기능으로 지원되지 않으며 [기능 동등성](https://www.elastic.co/docs/explore-analyze/query-filter/languages/sql-limitations)도 제한적입니다.

ClickHouse는 완전한 SQL을 지원할 뿐만 아니라 [`argMax`](/ko/reference/functions/aggregate-functions/argMax), [`histogram`](/ko/reference/functions/aggregate-functions/parametric-functions#histogram), [`quantileTiming`](/ko/reference/functions/aggregate-functions/quantileTiming) 등 관측성에 특화된 다양한 함수로 SQL을 확장하여 구조화된 로그, 메트릭, 트레이스를 더 쉽게 쿼리할 수 있도록 합니다.

간단한 로그 및 트레이스 탐색에는 관측성 UI가 제공하는 [Lucene 스타일 구문](/ko/clickstack/observability/features/search)을 사용할 수 있습니다. 이 구문으로 필드-값 쿼리, 범위, 와일드카드 등을 텍스트 기반으로 직관적으로 필터링할 수 있습니다. 이는 Elasticsearch의 [Lucene 구문](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-query-string-query#query-string-syntax) 및 [Kibana Query Language](https://www.elastic.co/docs/reference/query-languages/kql)의 일부 요소와 유사합니다.

검색 인터페이스는 이러한 익숙한 구문을 지원하면서 내부적으로는 이를 효율적인 SQL `WHERE` 절로 변환합니다. 따라서 Kibana 사용자에게 익숙한 사용 환경을 제공하는 동시에, 필요할 때는 SQL의 강력한 기능을 활용할 수 있습니다. 이를 통해 ClickHouse의 다양한 [문자열 검색 함수](/ko/reference/functions/regular-functions/string-search-functions), [유사도 함수](/ko/reference/functions/regular-functions/string-functions#stringJaccardIndex), [날짜 및 시간 함수](/ko/reference/functions/regular-functions/date-time-functions)를 모두 활용할 수 있습니다.

아래의 검색 구문은 관리형 서비스와 자가 관리형 서비스 모두에 적용됩니다. 필드 이름은 스키마(schema)에 따라 다르며, 예시에서는 가능한 경우 표준 OpenTelemetry 로그 필드를 사용합니다.

## ClickHouse Observability 검색 구문과 Elasticsearch 쿼리 문자열 비교 {#clickstack-vs-elasticsearch-query-string-self-configured}

ClickHouse Observability와 Elasticsearch는 모두 로그와 트레이스를 직관적으로 필터링할 수 있는 유연한 쿼리 언어를 제공합니다. Elasticsearch의 쿼리 문자열은 DSL 및 인덱싱 엔진과 긴밀하게 통합되어 있는 반면, ClickHouse Observability는 내부적으로 ClickHouse SQL로 변환되는 Lucene 기반 구문을 지원합니다. 아래 표는 일반적인 검색 패턴이 두 시스템에서 어떻게 동작하는지 정리한 것으로, 구문상의 유사점과 백엔드 실행 방식의 차이를 함께 보여 줍니다.

| **기능**        | **ClickHouse Observability 구문**    | **Elasticsearch 구문**              | **설명**                                                                                                                                                                                                            |
| ------------- | ---------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 자유 텍스트 검색     | `error`                            | `error`                           | ClickHouse Observability는 소스에 구성된 전체 텍스트 표현식(일반적으로 `Body`)을 검색하며, 기본적으로 대소문자를 구분하지 않는 단어 단위 일치를 사용합니다. 모든 컬럼을 자동으로 검색하지는 않습니다.                                                                                    |
| 필드 일치         | `SeverityText:error`               | `level:error`                     | 스키마(schema)에 정의된 필드 이름을 사용하십시오. ClickHouse Observability에서 인용 부호로 감싸지 않은 문자열 필드 검색은 부분 문자열 일치로 처리됩니다. 정확히 일치하는 값을 찾으려면 `SeverityText:"error"`와 같이 값을 인용 부호로 감싸십시오.                                                |
| 구문 검색         | `"disk full"`                      | `"disk full"`                     | 구성된 전체 텍스트 표현식에서 해당 구문과 일치하는 항목을 찾습니다.                                                                                                                                                                            |
| 필드 구문 일치      | `Body:"disk full"`                 | `message:"disk full"`             | ClickHouse Observability에서 필드 값을 직접 인용 부호로 감싸면 동등 비교가 적용됩니다. 즉, 긴 메시지에 포함된 구문이 아니라 body 전체가 일치해야 합니다.                                                                                                             |
| OR 조건         | `error OR warning`                 | `error OR warning`                | 검색어의 논리 OR입니다. 두 시스템 모두 기본적으로 지원합니다.                                                                                                                                                                              |
| AND 조건        | `error AND db`                     | `error AND db`                    | 두 시스템 모두 교집합으로 변환하며, 사용자 구문에는 차이가 없습니다.                                                                                                                                                                           |
| 부정            | `NOT error` 또는 `-error`            | `NOT error` 또는 `-error`           | 일치하는 이벤트를 제외합니다.                                                                                                                                                                                                  |
| 그룹화           | `(error OR fail) AND db`           | `(error OR fail) AND db`          | 두 시스템 모두 표준 Boolean 그룹화를 사용합니다.                                                                                                                                                                                   |
| 와일드카드         | `error*` 또는 `*fail*`               | `error*`, `*fail*`                | ClickHouse Observability는 자유 텍스트 검색을 포함하여 앞쪽 및 뒤쪽 와일드카드를 지원하지만, `f*ail`과 같은 중간 와일드카드는 지원하지 않습니다. Elasticsearch는 기본적으로 앞쪽 와일드카드를 허용하지만, 비활성화할 수 있으며 비용이 많이 들 수 있습니다.                                               |
| 범위(숫자/날짜)     | `Duration:[100 TO 200]`            | `duration:[100 TO 200]`           | 대괄호는 양쪽 경계를 모두 포함합니다. 스키마(schema)에 정의된 필드 이름과 단위를 사용하십시오.                                                                                                                                                         |
| 무제한 범위(숫자/날짜) | `Duration:>10` 또는 `Duration:>=10`  | `duration:>10` 또는 `duration:>=10` | 비교 연산자(comparison operators)로 한쪽이 열린 범위를 표현합니다.                                                                                                                                                                   |
| 포함/제외         | `Duration:{100 TO 200}`            | `duration:{100 TO 200}`           | 중괄호는 양쪽 경계를 모두 제외합니다.                                                                                                                                                                                             |
| 존재 여부 검사      | `LogAttributes.log.file.path:*`    | `_exists_:user` 또는 `field:*`      | 문자열 값을 갖는 `Map` 속성이면 ClickHouse Observability는 값이 비어 있지 않은지 확인합니다. 값과 관계없이 키 존재 여부를 확인하려면 SQL `mapContains`를 사용하십시오. 자세한 내용은 [스키마(schema) 및 누락된 필드](#empty-value-differences-self-configured)를 참조하십시오.                    |
| 정규식           | `match` 함수                         | `name:/joh?n(ath[oa]n)/`          | 현재 Lucene 구문에서는 지원되지 않습니다. SQL과 [`match`](/ko/reference/functions/regular-functions/string-search-functions#match) 함수 또는 기타 [문자열 검색 함수](/ko/reference/functions/regular-functions/string-search-functions)를 사용할 수 있습니다. |
| 퍼지 일치         | `editDistance('quikc', field) = 1` | `quikc~`                          | 현재 Lucene 구문에서는 지원되지 않습니다. SQL에서 `editDistance('rror', SeverityText) = 1`과 같은 거리 함수 또는 [기타 유사도 함수](/ko/reference/functions/regular-functions/string-functions#jaroSimilarity)를 사용할 수 있습니다.                           |
| 근접 검색         | 지원되지 않음                            | `"fox quick"~5`                   | 현재 Lucene 구문에서는 지원되지 않습니다.                                                                                                                                                                                        |
| 부스팅           | 지원되지 않음                            | `quick^2 fox`                     | 현재 ClickHouse Observability에서는 지원되지 않습니다.                                                                                                                                                                         |
| 필드 와일드카드      | 지원되지 않음                            | `service.*:error`                 | 현재 ClickHouse Observability에서는 지원되지 않습니다.                                                                                                                                                                         |
| 특수 문자 이스케이프   | 예약 문자는 `\`로 이스케이프                  | 동일                                | 예약된 기호는 이스케이프해야 합니다.                                                                                                                                                                                              |

## 스키마(schema)와 누락된 필드 {#empty-value-differences-self-configured}

표준 OpenTelemetry 스키마(schema)는 `Body`, `SeverityText`, `ServiceName`과 같은 필드를 사용하며, 로그 속성과 리소스 속성은 각각 `LogAttributes`와 `ResourceAttributes`에 저장됩니다. Elastic 필드 이름은 수집된 데이터의 해당 필드로 바꾸어 사용하십시오. 예를 들어 `level:error`는 `SeverityText:error`가 됩니다.

NULL을 허용하지 않는 컬럼에서는 생략된 값이 빈 문자열과 같은 컬럼의 기본값으로 표현됩니다. 따라서 `ServiceName`이 비어 있더라도 송신 측이 값을 생략한 것인지, 명시적으로 빈 문자열을 보낸 것인지는 구분할 수 없습니다.

사용자 정의 테이블을 사용하는 자가 관리형 배포에서는 실제 사용하는 컬럼 이름으로 바꾸고, 각 컬럼의 기본값과 NULL 허용 여부를 확인하십시오. [`Nullable`](/ko/reference/data-types/nullable) 컬럼에는 `NULL`이 포함될 수 있습니다.

SQL 쿼리에서는 `ServiceName != ''`로 서비스 이름이 비어 있지 않은지 검사할 수 있습니다. `Map`에 저장된 속성은 최상위 컬럼과 구별됩니다. 값이 비어 있는 경우를 포함하여 속성 키가 존재하는지 확인하려면 `mapContains(LogAttributes, 'log.file.path')`를 사용하십시오.
