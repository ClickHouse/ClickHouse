## bitdrift란? {#what-is-bitdrift}

[bitdrift](https://bitdrift.io/)는 모바일 애플리케이션 전용으로 구축된 동적 관측성 플랫폼입니다. bitdrift는 다음 세 가지 핵심 구성 요소로 이루어져 있습니다.

* **[Capture SDK](https://bitdrift.io/feature/performance-centric)**: Rust로 작성된 경량 크로스 플랫폼 라이브러리로, 플랫폼별로 얇은 래퍼를 제공합니다. 텔레메트리를 즉시 외부로 스트리밍하지 않고 디바이스의 고정 크기 링 버퍼에 기록합니다.
* **컨트롤 플레인**: 모든 클라이언트와 영구적인 양방향 연결을 유지하고 새로운 구성을 실시간으로 푸시하여, 수집할 데이터와 업로드할 데이터를 결정합니다.
* **bitdrift 플랫폼**: 워크플로, 세션 타임라인, 차트, 이슈, 알림을 통해 모바일 원격 측정 데이터에서 실질적인 답을 도출합니다. 웹 UI, CLI, AI 에이전트 및 퍼블릭 API를 통해 액세스할 수 있습니다.

bitdrift는 모바일 원격 측정 데이터를 요청이 있을 때까지 엣지에 보관합니다. 따라서 팀은 미리 샘플링된 고정 시그널 집합에 의존하지 않고, 크래시나 성능 이슈로 이어진 세션 전체를 샘플링 없이 가져올 수 있습니다. bitdrift Capture 플랫폼은 bitdrift가 호스팅하는 SaaS로 이용하거나, AWS 계정에 자체 클라우드(또는 버킷)를 사용하는 BYOC(bring-your-own-cloud) 방식으로 배포할 수 있습니다.

## bitdrift + ClickStack을 사용하는 이유 {#why-bitdrift-clickstack}

ClickStack은 ClickHouse 기반의 관측성 솔루션으로, 엔지니어링 팀은 이를 통해 백엔드 서비스, 웹 프론트엔드, 인프라 전반의 데이터를 수집, 저장, 쿼리할 수 있습니다. bitdrift는 이 기반을 모바일 기기까지 확장합니다. 운영 환경에서 해결하기 가장 까다로운 문제 상당수가 바로 모바일 기기에서 시작됩니다.

* **bitdrift는 기기에서 발생한 일을 보여줍니다**: 사용자 동작, 앱 상태, 네트워크 요청, 로그, 오류, 크래시, 성능 시그널은 물론 관련 세션 컨텍스트까지 확인할 수 있습니다.
* **ClickStack은 요청이 백엔드에 도달한 이후 발생한 일을 보여줍니다**: 분산 trace, 서비스 의존성, 로그, 메트릭, 데이터베이스 연산, 인프라 동작을 확인할 수 있습니다.
* **OpenTelemetry 트레이스 컨텍스트가 이 둘을 연결합니다.**

조사는 bitdrift에서 발견한 체크아웃 실패, 느린 화면 로딩, 인증 오류 또는 크래시에서 시작될 수 있습니다. 엔지니어는 네트워크 요청의 트레이스 ID를 따라 ClickStack UI로 이동해 요청이 백엔드 서비스를 거쳐 가는 과정을 바로 확인할 수 있습니다. 흩어진 타임스탬프를 모아 흐름을 직접 재구성할 필요가 없습니다.

<Tip>
  **핵심 요약**

  * **bitdrift**는 모바일 앱 전반에서 샘플링되지 않은 모바일 네이티브 텔레메트리를 수집하고, 수집된 트레이스 ID를 해당 백엔드 트레이스에 연결합니다.
  * **ClickStack**은 그 결과로 생성된 분산 트레이스를 ClickHouse에 저장하고 쿼리하며, ClickStack UI에 표시합니다.
</Tip>

## 사전 요구 사항 {#prerequisites}

* 백엔드 trace를 수신하는 **ClickHouse Observability** 서비스가 필요합니다. [완전 관리형 ClickHouse Observability 시작하기](/ko/clickstack/observability/getting-started)를 참조하거나, 수집용 collector를 직접 운영하는 경우 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 따르십시오.
* 백엔드 서비스가 **OpenTelemetry**로 계측되어 있고 ClickStack으로 trace를 전송하고 있어야 합니다. [OpenTelemetry를 사용한 데이터 수집](/ko/clickstack/observability/ingesting-data/opentelemetry)을 참조하십시오.
* 모바일 앱에 **bitdrift Capture SDK**가 통합되어 있어야 합니다. 설치 방법은 [bitdrift SDK 문서](https://docs.bitdrift.io/)를 참조하십시오.
* **bitdrift 계정**이 필요하며, 테넌트의 추적 기능을 활성화하려면 [지원](https://bitdrift.io/contact-us)팀에 요청할 수 있어야 합니다(추적은 bitdrift가 테넌트별로 활성화하는 실험적 기능입니다).

## 추적 구성 {#configure-tracing}

구성은 모두 bitdrift 측에서 이루어지며, 다음 세 단계로 진행됩니다.

1. [bitdrift 지원](https://bitdrift.io/contact-us)팀에 **테넌트의 추적 활성화와 ClickStack UI 인스턴스로의 트레이스 딥 링크 구성을 요청하십시오**. 딥 링크 구성을 통해 **트레이스 보기** 링크가 ClickStack UI를 가리키게 됩니다. 이 구성이 없으면 추적 데이터는 수집되지만 **트레이스 보기** 링크는 표시되지 않습니다.
2. 나가는 요청에 추적 헤더가 전파되도록 해당 플랫폼에서 **bitdrift의 네트워크 통합을 활성화하십시오**.
3. 필요한 세션(Sessions)에서 추적이 켜지도록 **Start Tracing 워크플로 액션을 추가하십시오**.

각 단계의 플랫폼별 세부 사항은 bitdrift 문서의 [How bitdrift and ClickStack work together](https://docs.bitdrift.io/product/integration-partners/clickhouse#how-bitdrift-and-clickstack-work-together)를 참조하십시오.

구성이 완료되면 bitdrift 타임라인 로그 행과 스팬 뷰에 **트레이스 보기** 링크가 표시되며, 이 링크를 통해 수집된 트레이스 ID가 ClickStack UI로 전달됩니다.

## 배포 유연성 {#deployment-flexibility}

이 통합은 데이터가 ClickStack에 도달하는 방식을 바꾸지 않으므로, ClickStack을 자가 관리형으로 운영하든 ClickHouse Cloud의 관리형 서비스로 운영하든 관계없이 동작합니다. bitdrift는 모바일 원격 측정 데이터를 ClickStack으로 내보내지 않습니다. 대신 디바이스에서 요청의 OpenTelemetry 트레이스 컨텍스트를 캡처한 뒤, OpenTelemetry로 계측된 자체 서비스가 이미 ClickStack으로 전송하고 있는 백엔드 트레이스와 연결합니다. bitdrift가 **트레이스 보기** 링크를 생성하는 데 필요한 정보는 ClickStack UI 주소뿐이므로, ClickStack 배포나 수집 파이프라인은 변경할 필요가 없습니다.

## 다음 단계 {#next-steps}

* **실제 조사 과정 따라가기**: bitdrift에서 발생한 모바일 크래시나 느린 요청을 출발점으로 ClickStack의 백엔드 트레이스까지 추적합니다
* **대시보드 구축하기**: 모바일 앱이 의존하는 백엔드 서비스를 위한 대시보드를 ClickStack UI에서 만듭니다
* **[bitdrift 샌드박스](https://bitdrift.io/sandbox) 둘러보기**: Capture를 사용한 작업 방식을 직접 체험할 수 있습니다
* **[무료 체험판](https://bitdrift.io/signup) 시작하기**: 모바일 앱에 bitdrift를 추가해 보십시오
