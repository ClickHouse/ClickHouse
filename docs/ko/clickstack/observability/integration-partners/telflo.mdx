## Telflo란? {#what-is-telflo}

{/* vale on */}

Telflo는 OpenTelemetry 수집기를 위한 벤더 중립적인 컨트롤 플레인으로, 플릿 전체의 수집기 설정을 중앙에서 관리할 수 있습니다. 시각적 편집기, 파이프라인 테스트, 구성 원격 배포 기능을 제공하므로 대규모 플릿도 손쉽게 관리할 수 있습니다. Telflo는 표준 업스트림 OpenTelemetry collector 빌드를 관리합니다. Telflo 전용 배포판이나 독점 에이전트가 필요하지 않으므로, 팀에서 이미 운영 중인 collector는 기존 빌드를 그대로 사용할 수 있습니다.

Telflo는 브라우저뿐 아니라 [명령줄 인터페이스](https://docs.telflo.com/docs/cli/)로도 사용할 수 있습니다. 여기에 [ClickStack MCP 서버](/ko/clickstack/observability/mcp)를 함께 활용하면, 텔레메트리를 쿼리하는 에이전트가 그 데이터를 생성한 파이프라인까지 직접 수정할 수 있습니다.

## Telflo + ClickHouse Observability를 선택해야 하는 이유 {#why-telflo-clickstack}

{/* vale on */}

완전 관리형 ClickHouse Observability는 수집, 스키마(schemas), 저장소, 스케일링을 모두 처리합니다. 자체 관리형 ClickHouse Observability에서는 수집과 데이터베이스 구성을 사용자가 직접 제어하고, 기반 인프라는 ClickHouse Cloud가 관리합니다. Telflo는 호스트, 클러스터(Clusters), 리전의 텔레메트리를 두 배포 방식 중 어느 쪽으로든 전송하는 OpenTelemetry 수집기를 관리합니다.

Telflo는 다음 기능을 제공합니다.

* 호스트, 컨테이너, Kubernetes 전반의 OpenTelemetry 수집기 중앙 관리
* 시각적 파이프라인 편집과 전체 플릿 또는 단일 그룹 단위의 통제된 롤아웃
* 운영 환경의 collector에 반영하기 전 표본(sample) 텔레메트리를 통한 변경 사항 검증
* 동일한 텔레메트리를 ClickHouse Observability와 다른 대상으로 동시에 라우팅
* 플릿 가시성: 온라인 상태인 collector, 각 collector에서 실행 중인 항목, 드리프트가 발생한 collector 확인

<Tip>
  **핵심 요약**

  * **ClickHouse Observability는 저장소와 조사 환경을 제공합니다**
  * **Telflo는 ClickHouse Observability로 데이터를 보내는 collector fleet을 운영합니다**
</Tip>

## 사전 요구 사항 {#prerequisites}

* [완전 관리형 ClickHouse Observability 서비스](/ko/clickstack/observability/getting-started) 또는 [자가 관리형 배포](/ko/clickstack/self-configured/getting-started/managed)
* Telflo 계정([telflo.com에서 계정 생성](https://telflo.com))
* collector를 실행할 환경: 가상 머신(VM) 또는 Kubernetes 클러스터
* **완전 관리형**: **팀 설정 → 데이터 → Managed Telemetry**에서 확인할 수 있는 OTLP HTTP 엔드포인트와 수집 API key
* **자가 관리형**: ClickHouse Cloud 서비스 엔드포인트(포트 `8443`)와 [수집 사용자](/ko/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured), 또는 기존 독립형 collector 엔드포인트와 해당 `OTLP_AUTH_TOKEN`
* Telflo에서 관리하는 collector와 대상 엔드포인트 간의 네트워크 연결

## ClickHouse Observability와 Telflo 통합 {#integrate-telflo-clickstack}

{/* vale on */}

<Steps>
  <Step title="수집기 설정 작성" id="build-configuration">
    1. Telflo에 로그인합니다. **Configurations** 목록에서 **New Configuration**을 클릭한 다음 **Blank configuration**을 클릭합니다.
    2. **Name Your Configuration**에 이름을 입력하고 **Create**를 클릭합니다.
    3. 수신기(receiver)를 추가합니다. 수집하는 텔레메트리 유형별로 팔레트에서 수신기를 하나씩 캔버스로 끌어다 놓습니다.
    4. 프로세서(processor)를 추가합니다. **Memory Limiter**와 **Batch**를 추가하고, 데이터가 collector를 떠나기 전에 가공하는 데 필요한 프로세서가 있다면 함께 추가합니다. [Telflo에서 지원하는 전체 프로세서 목록](https://docs.telflo.com/docs/build/components#processors)을 참조하십시오.
  </Step>

  <Step title="익스포터 추가" id="add-exporter">
    배포 환경에 맞는 익스포터를 선택하십시오. 완전 관리형 ClickHouse Observability는 관리형 OTLP 엔드포인트를 통해 텔레메트리를 수신합니다. 자가 관리형 배포에서는 ClickHouse에 직접 쓰거나, 이미 운영 중인 collector로 OTLP를 전송할 수 있습니다.

    <Tabs>
      <Tab title="완전 관리형">
        <BetaBadge label="베타 제공" />

        관리형 OTLP 엔드포인트를 사용하십시오. 수집, 스키마(schemas), 스토리지, 확장은 ClickHouse가 처리하며, Telflo가 관리하는 collector는 사용자 환경에서 텔레메트리를 수집하여 전달합니다.

        1. **OTLP/HTTP** 익스포터를 캔버스로 드래그합니다.
        2. **Endpoint**를 포트 `4318`을 포함한 관리형 OTLP HTTP 엔드포인트로 설정합니다. 예: `https://<service-id>.otel.<region>.aws.clickhouse.com:4318`
        3. **HTTP Headers**에서 **Add header**를 클릭한 다음, **Header name**에 `Authorization`을, **Header value**에 `Bearer ${env:CLICKSTACK_INGESTION_KEY}`를 입력합니다. collector를 설치할 때 Telflo가 환경 변수 값을 요청합니다. `CLICKSTACK_INGESTION_KEY`에는 `Bearer` 접두사 없이 수집 API 키를 입력하십시오.

        완전 관리형 배포에서는 직접 쓰기용 ClickHouse 익스포터가 아닌 OTLP 익스포터를 사용하십시오.
      </Tab>

      <Tab title="자가 관리형">
        자가 관리형 ClickHouse Observability에서는 수집을 직접 관리해야 합니다. ClickHouse 익스포터를 사용한 직접 쓰기는 자가 관리형 배포에만 해당합니다. 여기에서 구성하는 collector는 [수집 게이트웨이](/ko/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) 역할을 합니다. ClickHouse 익스포터와 함께 **OTLP** 수신기를 추가하면 collector가 ClickHouse Cloud 서비스에 데이터를 씁니다. 이후 SDK와 에이전트 collector는 `4318`(HTTP) 또는 `4317`(gRPC) 포트로 이 collector에 OTLP를 전송합니다.

        1. **ClickHouse** 익스포터를 캔버스로 드래그합니다.
        2. **Endpoint**에 ClickHouse Cloud 서비스 엔드포인트(포트 `8443`)를 입력하고, **Database**를 `default`로, **Username**을 수집용 사용자로 설정합니다.
        3. **Password**를 `${env:CLICKHOUSE_PASSWORD}`로 설정합니다. collector를 설치할 때 Telflo가 값을 요청하므로, 구성에 비밀번호를 직접 넣지 않고 환경 변수를 참조하게 됩니다.
        4. **Schema &amp; Tables**: [텔레메트리 테이블](/ko/clickstack/self-configured/ingesting-data/schemas)이 아직 없다면 **Create Schema on Startup**을 켜 둔 상태로 두십시오. 익스포터가 테이블을 생성합니다. 테이블이 생성된 후에는 이 옵션을 끄십시오.

        **Batch**는 익스포터 앞단에 두십시오. ClickHouse는 배치 삽입 시 가장 좋은 성능을 냅니다.

        이미 [독립 실행형 OpenTelemetry collector](/ko/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)를 운영 중이라면 대신 **OTLP/HTTP** 익스포터를 사용하십시오. **Endpoint**를 해당 collector의 OTLP HTTP 주소(포트 `4318`)로 설정하고, 값이 `${env:OTLP_AUTH_TOKEN}`인 `Authorization` 헤더를 추가합니다. Telflo 관리형 collector를 설치할 때 [collector에 구성된 인증 토큰](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)을 입력하십시오. 이 토큰에는 `Bearer` 접두사를 붙이지 마십시오.

        <div className="ch-image-lg">
          <Frame>
            ![ClickHouse 익스포터가 구성된 Telflo 편집기의 자가 관리형 collector 파이프라인](/images/clickstack/telflo/telflo-configuration.webp)
          </Frame>
        </div>
      </Tab>
    </Tabs>

    수신기에서 프로세서를 거쳐 익스포터까지 엣지를 연결하여 신호별로 파이프라인을 하나씩 구성합니다. 상태 행에는 **config valid** 또는 수정해야 할 오류 수가 표시되며, **YAML** 탭에서 생성된 구성을 확인할 수 있습니다.

    배포하기 전에 샘플 텔레메트리를 구성에 흘려보내 출력 결과를 확인할 수 있습니다. 자세한 내용은 [Telflo의 테스트](https://docs.telflo.com/docs/testing/overview)를 참조하십시오. 또는 원하는 작업을 설명하면 툴바의 **AI** 버튼으로 여는 Telflo AI 어시스턴트가 구성을 생성, 검증, 테스트해 줍니다. 자체 에이전트로도 [Telflo CLI](https://docs.telflo.com/docs/cli/)를 통해 같은 작업을 수행할 수 있습니다.
  </Step>

  <Step title="버전 게시" id="publish-version">
    도구 모음에서 **Publish**를 클릭하십시오. 게시된 버전은 읽기 전용이므로, 계속 수정하려면 **Create New Version**을 클릭하십시오.
  </Step>

  <Step title="플릿을 생성하고 배포하십시오" id="deploy-collectors">
    1. **Fleet**으로 이동하여 **New Fleet**를 클릭한 다음, collector를 실행할 환경으로 가상 머신(VM) 또는 Kubernetes 중 하나를 선택하십시오. **Name**을 입력하고 **Create fleet**를 클릭하십시오.
    2. 플릿의 **Deploy Groups** 탭에서 배포할 그룹의 **Assign**을 클릭하고, 발행한 구성과 버전을 선택하십시오. 플릿 전체로 롤아웃하기 전에 소규모 그룹부터 배포하여 수집이 정상적으로 이루어지는지 확인하십시오.
    3. 그룹에서 **Install**을 클릭하고 구성에서 참조하는 각 환경 변수의 값을 입력하십시오. Telflo가 이 값을 설치 명령에 추가합니다. [Telflo의 설치 지침에 따라](https://docs.telflo.com/docs/fleet-management/install-collectors) collector를 실행할 위치에서 해당 명령을 실행하십시오. 이 명령에는 입력한 값과 함께 플릿의 설치 토큰이 포함되므로 민감한 정보로 취급하십시오.
    4. **Collectors** 탭에서 collector의 상태가 **Pending pickup**, **Applying**, **In sync** 순으로 표시됩니다.

    변경 사항을 롤아웃하려면 새 버전을 발행한 후 해당 그룹에 할당하십시오. 롤백하려면 이전에 배포한 버전을 할당하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![롤아웃 후 모든 collector가 동기화된 Telflo 플릿](/images/clickstack/telflo/telflo-fleet.webp)
      </Frame>
    </div>
  </Step>

  <Step title="텔레메트리 확인" id="verify-telemetry">
    ClickHouse Cloud 콘솔에서 해당 서비스의 ClickHouse Observability를 여십시오. **검색** 뷰에서 서비스 중 하나를 검색하고, 메트릭은 **차트 탐색기**에서 확인하십시오. 구성을 나머지 플릿 전체에 배포하기 전에 예상한 로그, 트레이스, 메트릭이 제대로 수신되는지 확인하십시오.
  </Step>
</Steps>

## 고급 구성 {#advanced-configuration}

### 팬아웃 라우팅 {#fan-out-routing}

동일한 텔레메트리를 장기 보관용으로 ClickHouse Observability에, 마이그레이션(migration) 기간에는 다른 플랫폼에, 보안 분석용으로 SIEM에 동시에 보낼 수 있습니다. 캔버스에 익스포터를 추가하고 해당 익스포터로 데이터를 보낼 파이프라인에 연결하거나, [Telflo의 flow 라이브러리](https://telflo.com/flows)에 있는 사전 구성된 파이프라인에서 시작하십시오.

### 압축 및 성능 {#compression-and-performance}

* **OTLP/HTTP 및 OTLP 익스포터**: **압축**은 gzip으로 유지하십시오.
* **ClickHouse 익스포터(자가 관리형 전용)**: **Async Insert**는 켜 둔 상태로 유지하고, **압축**은 lz4로 그대로 두며, 익스포터 앞단에 **Batch** 프로세서를 추가하십시오. 자세한 내용은 [삽입 최적화](/ko/clickstack/self-configured/ingesting-data/collector#optimizing-inserts-self-configured)를 참조하십시오.

## 다음 단계 {#next-steps}

* **대시보드 구축**: ClickHouse Observability에서 로그, 메트릭, 트레이스용 시각화를 만듭니다
* **알림 설정**: ClickHouse Observability에서 주요 조건에 대한 알림을 구성합니다
* **Telflo AI 어시스턴트로 개선**: 파이프라인 조정이나 테스트 제안을 AI 어시스턴트에 요청합니다
* **다른 벤더에서 전환하는 경우**: [flows](https://telflo.com/flows)를 사용하면 전환 과정 전반을 처리할 수 있습니다. 플릿에 이미 배포된 에이전트를 교체하고, 두 백엔드를 비교하는 동안 양쪽 모두로 데이터를 이중 전송합니다
