## Odigos란? {#what-is-odigos}

{/* vale on */}

[Odigos](https://odigos.io/)는 Kubernetes와 VM을 위한 instrumentation 컨트롤 플레인으로, **eBPF**를 사용하여 커널 수준에서 애플리케이션을 계측합니다. 수집이 커널에서 이루어지므로 애플리케이션 오버헤드는 낮게 유지하면서도 높은 가시성을 확보할 수 있습니다. 애플리케이션 코드에 새 에이전트를 추가하거나 모든 서비스의 라이브러리 업그레이드를 기다리지 않고도 프로덕션급 OpenTelemetry trace, 메트릭, 로그, 프로필을 얻을 수 있습니다.

이 eBPF 계층 덕분에 대규모 환경에서도 깊이 있고 일관된 텔레메트리를 수집할 수 있습니다. Odigos는 문제를 디버깅하거나 해결해야 할 때 더 깊은 수준의 instrumentation을 자동으로 활성화하거나 비활성화할 수 있습니다.

* **코드 수준 컨텍스트** — 함수 및 런타임 동작과 연결된 속성
* **HTTP 트래픽** — 서비스 전반의 요청과 응답
* **메시징 시스템** — Kafka 및 유사한 브로커의 페이로드와 메시지
* **상세한 오류 정보** — 장애 발생 시의 스택 trace
* **사용자 정의 instrumentation** — 코드 변경이나 재시작 없이 auto-instrumentation이 미치지 못하는 영역까지 적용 범위 확장

내부적으로 Odigos는 클러스터 전용의 완전한 OpenTelemetry 파이프라인을 생성하고 관리합니다. 여기에는 부하에 따라 확장되는 collector, 선택한 백엔드로의 라우팅, UI에서 제어하는 파이프라인 로직이 포함됩니다. 데이터 양을 관리하는 **샘플링**, 내보내는 데이터에서 민감한 정보를 제외하는 **PII 마스킹(masking)**, 텔레메트리가 클러스터를 벗어나기 전에 필터링, 변환 또는 보강하는 **OTTL 규칙**을 정의할 수 있습니다.

## Odigos와 ClickHouse Observability를 함께 사용하는 이유 {#why-odigos-clickstack}

{/* vale on */}

여러 서비스에 OpenTelemetry를 도입하는 작업은 대개 시간이 많이 걸리며, 그마저도 애플리케이션에 대한 표면적인 가시성만 제공합니다. Odigos는 더 깊은 텔레메트리 수집을 위한 eBPF instrumentation과 Kubernetes 환경의 collector 운영을 담당하고, ClickHouse Observability는 ClickHouse 기반 저장소와 대규모 텔레메트리 쿼리를 위한 ClickStack UI를 제공합니다.

<Tip>
  **핵심 요약**

  * **Odigos**는 재시작 없이 모든 Kubernetes 워크로드를 자동으로 계측하며, OpenTelemetry 파이프라인도 자동으로 관리합니다.
  * **ClickHouse Observability**는 로그, 메트릭, trace를 ClickHouse에 저장하고 ClickStack UI에서 보여 줍니다.
</Tip>

## 사전 요구 사항 {#prerequisites}

* Kubernetes 클러스터에서 연결할 수 있는 ClickHouse Observability 서비스가 필요합니다. [시작하기](/ko/clickstack/observability/getting-started)를 참조하십시오. 자가 관리형 배포는 [자가 관리형 설정](/ko/clickstack/self-configured/deployment/managed)을 참조하십시오.
* **팀 설정 → 데이터 → Managed Telemetry**에서 확인할 수 있는 **OTLP HTTP 엔드포인트**와 수집 API key가 필요합니다. 자가 관리형 배포에서는 독립형 collector 엔드포인트와 `OTLP_AUTH_TOKEN`을 사용하십시오.
* **Kubernetes 클러스터**(eBPF instrumentation을 사용하려면 커널 4.18 이상의 Linux 노드 필요)
* `odigos-system` 네임스페이스에 설치할 수 있는 **Helm**, **kubectl** 및 클러스터 자격 증명
* **Odigos Enterprise on-prem 토큰** — 액세스 권한은 [Odigos 팀](https://odigos.io/)에 문의하십시오.

## ClickHouse Observability와 Odigos 통합 {#integrate-odigos-clickstack}

{/* vale on */}

<Steps>
  <Step title="Helm으로 Odigos 배포" id="deploy-odigos">
    Odigos Enterprise를 사용하려면 on-prem 라이선스 토큰이 필요합니다. 셸에서 이 토큰을 환경 변수로 export하십시오:

    ```bash
    export ODIGOS_ONPREM_TOKEN="<your-enterprise-token>"
    ```

    또는 설치 전에 토큰을 `odigos-pro`라는 이름의 Kubernetes 시크릿에 저장할 수도 있습니다. 자세한 내용은 [Odigos Enterprise 문서](https://enterprise.docs.odigos.io/)(액세스 권한 필요)를 참조하십시오.

    Odigos Helm 리포지토리를 추가한 후 `odigos-system` 네임스페이스에 차트를 설치하십시오:

    ```bash
    helm repo add odigos https://odigos-io.github.io/odigos/
    helm repo update

    helm upgrade --install odigos odigos/odigos \
      --namespace odigos-system \
      --create-namespace \
      --set onPremToken=$ODIGOS_ONPREM_TOKEN
    ```

    `--set` 플래그 또는 사용자 정의 값 파일(`-f`)을 사용하여 추가 구성 재정의를 지정할 수 있습니다. 차트의 기본값을 확인하려면 `helm show values odigos/odigos`를 실행하십시오.

    Odigos 파드가 실행 중인지 확인합니다:

    ```bash
    kubectl get pods -n odigos-system
    ```
  </Step>

  <Step title="Odigos UI에서 소스 추가" id="add-sources">
    1. Odigos UI 서비스를 포트 포워딩합니다:

    ```bash
    kubectl port-forward svc/ui -n odigos-system 3000:3000
    ```

    2. 브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.
    3. **Sources**로 이동하여 계측할 네임스페이스 또는 워크로드(workloads)를 선택합니다.
    4. 계측할 워크로드를 모두 지정한 후 하단의 **Done**을 클릭합니다.
    5. 소스 컬럼에서 워크로드가 정상적으로 계측되었는지 확인합니다.
  </Step>

  <Step title="Odigos UI에서 ClickHouse Observability를 대상으로 추가하십시오" id="add-destination-ui">
    텔레메트리를 전송하려면 Odigos에서 **OTLP HTTP** 대상을 추가하십시오. 아래에서 배포 유형을 선택하십시오.

    <Tabs>
      <Tab title="완전 관리형">
        <BetaBadge label="베타 서비스" />

        ClickHouse Observability는 OTLP 엔드포인트를 제공하며, 수집, 스키마, 컴퓨팅은 ClickHouse가 처리합니다. Odigos가 해당 엔드포인트로 데이터를 보내도록 설정하기만 하면 되며, collector를 직접 배포할 필요가 없습니다.

        1. Odigos UI에서 **Add Destination**을 클릭하고 **OTLP HTTP**를 선택하십시오.
        2. **OTLP HTTP Endpoint**를 ClickHouse Cloud의 HTTPS 엔드포인트로 설정하십시오. 이때 포트 `4318`을 포함해야 합니다. 예: `https://<service-id>.otel.<region>.aws.clickhouse.com:4318`
        3. **Headers**에 다음을 추가하십시오.
           * **Key**: `Authorization`
           * **Value**: `Bearer <YOUR_INGESTION_API_KEY>`
        4. **Logs**, **Metrics**, **Traces**를 활성화하십시오.
        5. 대상을 저장하십시오.
      </Tab>

      <Tab title="자가 관리형">
        <Tip>
          **대안: ClickHouse에 직접 쓰기**

          자가 관리형 배포에서는 Kubernetes 클러스터에서 ClickHouse 서비스에 접근할 수 있다면 OTLP collector를 실행하는 대신 Odigos의 [네이티브 **ClickHouse** 대상](#native-clickhouse-destination)을 사용할 수 있습니다. 완전 관리형 배포에서는 반드시 관리형 OTLP 엔드포인트를 사용해야 합니다.
        </Tip>

        자가 관리형 배포에서는 [ClickStack 배포판 collector를 독립형 모드로](/ko/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured) 직접 실행하고, 컨테이너를 시작할 때 `OTLP_AUTH_TOKEN` 환경 변수로 인증 토큰을 설정하십시오. 그러면 Odigos가 `Authorization` 헤더에 동일한 토큰을 담아 해당 collector로 OTLP HTTP 트래픽을 전송합니다.

        1. ClickStack collector를 독립형 모드로 시작하십시오. 이때 ClickHouse Cloud 서비스를 대상으로 지정하고, 원하는 `OTLP_AUTH_TOKEN` 값으로 보호하십시오.

           ```shell
           export CLICKHOUSE_ENDPOINT=<HTTPS_ENDPOINT>
           export CLICKHOUSE_USER=<CLICKHOUSE_USER>
           export CLICKHOUSE_PASSWORD=<CLICKHOUSE_PASSWORD>
           export OTLP_AUTH_TOKEN="a_very_secure_string"

           docker run \
             -e OTLP_AUTH_TOKEN=${OTLP_AUTH_TOKEN} \
             -e CLICKHOUSE_ENDPOINT=${CLICKHOUSE_ENDPOINT} \
             -e CLICKHOUSE_USER=${CLICKHOUSE_USER} \
             -e CLICKHOUSE_PASSWORD=${CLICKHOUSE_PASSWORD} \
             -p 4317:4317 \
             -p 4318:4318 \
             clickhouse/clickstack-otel-collector:latest
           ```

           TLS, 전용 수집 사용자 및 기타 운영 환경 권장 사항은 [collector 보안 설정](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)을 참조하십시오.
        2. Odigos UI에서 **Add Destination**을 클릭하고 **OTLP HTTP**를 선택하십시오.
        3. **OTLP HTTP Endpoint**를 방금 시작한 독립형 collector 주소로 설정하십시오(예: `http://my-collector.example.com:4318`).
        4. **Headers**에 다음을 추가하십시오.
           * **Key**: `Authorization`
           * **Value**: collector에 설정한 `OTLP_AUTH_TOKEN` 값
        5. **Logs**, **Metrics**, **Traces**를 활성화하십시오.
        6. 대상을 저장하십시오.

        <Info>
          **선택 사항: Kubernetes 매니페스트**

          UI 대신 `Destination` 매니페스트로 동일한 대상을 구성할 수도 있습니다. 고급 구성의 [Kubernetes 매니페스트로 대상 구성하기](#destination-manifest)를 참조하십시오.
        </Info>
      </Tab>
    </Tabs>
  </Step>

  <Step title="ClickHouse Observability에서 텔레메트리 확인" id="verify-telemetry">
    1. ClickStack UI를 엽니다.
       * **자가 관리형**: [ClickHouse Cloud 콘솔](https://console.clickhouse.cloud)에서 서비스를 연 다음 **Launch ClickStack**을 클릭하십시오. 자세한 내용은 [ClickStack UI로 이동하기](/ko/clickstack/self-configured/deployment/managed)를 참조하십시오.
       * **완전 관리형**: ClickHouse Cloud 서비스의 관측성 뷰를 여십시오.
    2. **Logs**, **Metrics**, **Traces**에서 계측된 서비스의 데이터가 수집되는지 확인하십시오.
    3. `odigos.version`으로 트레이스를 필터링하여 엔드투엔드 내보내기가 정상적으로 이루어지는지 검사하십시오.

    데이터가 표시되지 않으면 collector 로그를 확인하십시오: `kubectl logs deploy/odigos-gateway -n odigos-system`
  </Step>
</Steps>

## 고급 구성 {#advanced-configuration}

### 네이티브 ClickHouse 대상 {#native-clickhouse-destination}

네이티브 ClickHouse 대상은 **자가 관리형** 배포에서만 사용할 수 있습니다. **완전 관리형** 배포에서는 관리형 엔드포인트와 함께 **OTLP HTTP** 대상을 사용하십시오.

<Tabs>
  <Tab title="자가 관리형">
    클러스터에서 ClickHouse에 직접 연결할 수 있다면 OTLP HTTP 대신 Odigos의 네이티브 **ClickHouse** 대상을 사용할 수 있습니다. ClickHouse 엔드포인트, 데이터베이스 이름, 스키마(schema) 옵션은 UI 또는 매니페스트에서 구성하십시오. 자세한 내용은 [Odigos ClickHouse 대상](https://docs.odigos.io/backends/clickhouse)을 참조하십시오.

    * **운영 환경 스키마**: `CLICKHOUSE_CREATE_SCHEME`을 `false`로 설정하고 직접 작성한 DDL을 적용하십시오.
    * **TLS / 인증**: `CLICKHOUSE_TLS_ENABLED`와 `CLICKHOUSE_USERNAME`을 사용하고, 비밀번호는 Kubernetes Secret으로 관리하십시오.

    **Kubernetes 매니페스트**

    ```yaml
    apiVersion: odigos.io/v1alpha1
    kind: Destination
    metadata:
      name: clickhouse
      namespace: odigos-system
    spec:
      type: clickhouse
      destinationName: clickhouse
      signals:
        - TRACES
        - METRICS
        - LOGS
      data:
        CLICKHOUSE_ENDPOINT: 'http://clickstack.example.com:8123'
        CLICKHOUSE_DATABASE_NAME: 'otel'
        CLICKHOUSE_CREATE_SCHEME: 'true'
    ```

    매니페스트를 `destination.yaml`로 저장한 후 적용하십시오.

    ```bash
    kubectl apply -f destination.yaml
    ```

#### HyperDX 로그 정규화 도구 {#hyperdx-log-normalizer}

    Odigos의 네이티브 **ClickHouse** 대상을 사용하여 ClickHouse로 직접 내보내는 자가 관리형 배포에서는 **HyperDX 로그 정규화 도구**(`HYPERDX_LOG_NORMALIZER: true`)를 활성화하십시오. 이 기능은 JSON 로그 본문을 파싱하고 속성을 정규화하여 ClickStack UI에서 더 효과적으로 쿼리할 수 있게 합니다. 이 설정은 완전 관리형 OTLP 대상에는 적용되지 않습니다.
  </Tab>
</Tabs>

### Kubernetes 매니페스트로 대상 구성하기 {#destination-manifest}

**OTLP HTTP (ClickStack)**

```yaml
apiVersion: odigos.io/v1alpha1
kind: Destination
metadata:
  name: clickstack
  namespace: odigos-system
spec:
  type: otlphttp
  destinationName: otlphttp
  signals:
    - TRACES
    - METRICS
    - LOGS
  data:
    OTLP_HTTP_ENDPOINT: 'http://clickstack.example.com:4318'
    # Self-managed: OTLP_AUTH_TOKEN
    # ClickHouse Observability: Bearer <YOUR_INGESTION_API_KEY>
    OTLP_HTTP_HEADERS: 'Authorization:<YOUR_AUTHORIZATION_VALUE>'
```

매니페스트를 적용합니다:

```bash
kubectl apply -f destination.yaml
```

### Odigos VM Agent {#odigos-vm-agent}

{/* vale on */}

[Odigos VM Agent](https://docs.odigos.io/vmagent/overview)는 eBPF를 사용하여 Linux 프로세스, systemd 서비스, docker 컨테이너를 계측합니다. 텔레메트리는 클러스터 기반 Odigos와 동일한 대상으로 내보내지며, 여기에는 OTLP HTTP를 통한 ClickHouse Observability도 포함됩니다.

VM Agent는 Odigos Pro에 포함되어 있습니다. 설정, 소스 및 대상 구성에 대한 자세한 내용은 [VM Agent 개요](https://docs.odigos.io/vmagent/overview)를 참조하십시오.

{/* vale off */}

### Odigos Central {#odigos-central}

{/* vale on */}

[Odigos Central](https://docs.odigos.io/central/overview)은 각 클러스터를 개별적으로 구성할 필요 없이, 여러 Kubernetes 클러스터의 instrumentation, 대상, 파이프라인 구성을 하나의 UI에서 관리할 수 있는 중앙 집중식 컨트롤 플레인입니다.

Odigos Central은 Odigos Enterprise에서 사용할 수 있습니다. 다중 클러스터 관리, SSO, 통합 샘플링 규칙에 대한 자세한 내용은 [Central 개요](https://docs.odigos.io/central/overview)를 참조하십시오.

* **자가 관리형 배포에서는** 데이터 보존 기간과 쿼리 패턴(query patterns)에 맞게 **ClickHouse 스키마(schema)와 TTL을 조정하세요**
