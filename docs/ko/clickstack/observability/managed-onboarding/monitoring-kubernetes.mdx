이 가이드에서는 클러스터의 로그, 인프라 메트릭, Kubernetes 이벤트를 자체 관리형 ClickHouse Observability로 수집한 다음 내장 Kubernetes 대시보드에서 확인하는 과정을 안내합니다.

구성 방식은 표준 OpenTelemetry 패턴을 따릅니다. [OpenTelemetry Helm 차트](https://github.com/open-telemetry/opentelemetry-helm-charts/tree/main/charts/opentelemetry-collector)로 collector 2개를 배포하고, 각 collector는 OTLP를 통해 ClickStack gateway collector로 데이터를 전달합니다. **데몬셋(DaemonSet)**&#xC740; 모든 노드에서 실행되며 컨테이너 로그와 큐블릿(kubelet) 메트릭을 수집합니다. 레플리카 1개로 구성된 **배포(Deployment)**&#xB294; Kubernetes 이벤트와 클러스터 전체 메트릭을 수집합니다. gateway 역할에 대한 배경 정보는 [수집기 역할](/ko/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)을 참조하십시오.

이 가이드는 [OpenTelemetry Collector 설정](/ko/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)을 완료했고 ClickStack gateway collector가 실행 중인 상태를 전제로 합니다.

워크로드가 Kubernetes 내부에서 실행된다면 gateway collector 자체도 **동일한 클러스터 내에 업스트림 OpenTelemetry Helm 차트와 ClickStack 수집기 이미지를 사용하여** 배포해야 합니다. [collector 배포](/ko/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)의 Helm 절차에 따라 설치하십시오. **이 OTLP 엔드포인트를 반드시 기록해 두십시오**.

<Steps>
  <Step title="사전 요구 사항 준비" id="gather-prerequisites">
    다음 항목이 필요합니다.

    * `kubectl`이 구성된 **Kubernetes 클러스터**(v1.20 이상 권장)
    * **[Helm](https://helm.sh/) v3 이상**
    * 클러스터 내부에서 연결할 수 있는 ClickStack gateway collector의 **OTLP 엔드포인트**(예: `http://clickstack-otel-collector.observability.svc.cluster.local:4318`). collector는 데몬셋과 배포에서 연결할 수 있는 위치에 배포되어 있어야 합니다. 일반적으로 동일한 클러스터에 배포하거나 `LoadBalancer` 유형의 서비스를 통해 노출합니다.
    * gateway collector를 배포할 때 설정한 `OTLP_AUTH_TOKEN` 값. collector에 보안을 적용하지 않았다면 아래의 시크릿 단계를 건너뛰고 매니페스트에서 `authorization` 헤더를 삭제하면 됩니다.

    <Info>
      **gateway 실행 위치**

      클러스터 로컬로 배포하려면 gateway collector를 동일한 클러스터 내에서 Kubernetes `Deployment` 또는 `StatefulSet`으로 실행하고, 클러스터 내 서비스 DNS로 접근하십시오. gateway가 클러스터 외부에서 실행되는 경우에는 외부에서 연결할 수 있는 URL을 사용하십시오.
    </Info>
  </Step>

  <Step title="인증 시크릿과 ConfigMap을 생성하십시오" id="create-secret-and-configmap">
    collector를 배포할 네임스페이스를 선택한 후, `OTLP_AUTH_TOKEN`을 담은 시크릿과 gateway를 가리키는 ConfigMap을 생성하십시오:

    ```shell
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    export OTEL_COLLECTOR_ENDPOINT="http://clickstack-otel-collector.observability.svc.cluster.local:4318"
    export NAMESPACE=observability

    kubectl create namespace ${NAMESPACE} --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic clickstack-otlp-secret \
      --from-literal=OTLP_AUTH_TOKEN=${OTLP_AUTH_TOKEN} \
      -n ${NAMESPACE}

    kubectl create configmap otel-config-vars \
      --from-literal=YOUR_OTEL_COLLECTOR_ENDPOINT=${OTEL_COLLECTOR_ENDPOINT} \
      -n ${NAMESPACE}
    ```

    아래의 두 collector는 모두 `extraEnvs`를 통해 이 값을 읽으므로, 동일한 시크릿과 ConfigMap을 두 collector에서 함께 사용합니다.
  </Step>

  <Step title="OpenTelemetry Helm 리포지토리 추가" id="add-otel-helm-repo">
    ```shell
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update
    ```
  </Step>

  <Step title="클러스터 collector를 배포하십시오" id="deploy-cluster-collector">
    이 구성은 **Kubernetes 이벤트**와 **클러스터 전체 메트릭**(노드 수, 파드 단계, 배포 상태 등)을 수집하는 단일 레플리카 배포(Deployment)입니다. 레플리카를 2개 이상 실행하면 데이터가 중복으로 수집됩니다.

    다음 내용을 `k8s_deployment.yaml`로 저장하십시오.

    <Accordion title="k8s_deployment.yaml">
      ```yaml
      # k8s_deployment.yaml
      mode: deployment

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # 이 collector는 하나만 실행해야 합니다. 2개 이상이면 중복 데이터가 생성됩니다
      replicaCount: 1

      presets:
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        # k8sobject receiver를 통해 Kubernetes 이벤트를 수집합니다.
        kubernetesEvents:
          enabled: true
        # k8s_cluster receiver를 통해 클러스터 수준 메트릭을 수집합니다.
        clusterMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"
        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    다음 명령으로 설치하십시오.

    ```shell
    helm install k8s-otel-deployment open-telemetry/opentelemetry-collector \
      -f k8s_deployment.yaml \
      -n ${NAMESPACE}
    ```
  </Step>

  <Step title="노드 collector 배포" id="deploy-node-collector">
    이 데몬셋(DaemonSet)은 모든 노드에서 실행되며 **컨테이너 로그**, **호스트 메트릭**, **큐블릿 메트릭**(requests 및 limits 대비 파드별·컨테이너별 CPU 및 메모리 사용률)을 수집합니다.

    다음 내용을 `k8s_daemonset.yaml`로 저장하십시오.

    <Accordion title="k8s_daemonset.yaml">
      ```yaml
      # k8s_daemonset.yaml
      mode: daemonset

      image:
        repository: otel/opentelemetry-collector-contrib
        tag: 0.123.0

      # kubeletstats의 cpu/memory 사용률 메트릭을 사용하는 데 필요합니다
      clusterRole:
        create: true
        rules:
          - apiGroups:
              - ''
            resources:
              - nodes/proxy
            verbs:
              - get

      presets:
        logsCollection:
          enabled: true
        hostMetrics:
          enabled: true
        kubernetesAttributes:
          enabled: true
          extractAllPodLabels: true
          extractAllPodAnnotations: true
        kubeletMetrics:
          enabled: true

      extraEnvs:
        - name: OTLP_AUTH_TOKEN
          valueFrom:
            secretKeyRef:
              name: clickstack-otlp-secret
              key: OTLP_AUTH_TOKEN
              optional: true
        - name: YOUR_OTEL_COLLECTOR_ENDPOINT
          valueFrom:
            configMapKeyRef:
              name: otel-config-vars
              key: YOUR_OTEL_COLLECTOR_ENDPOINT

      config:
        receivers:
          # requests 및 limits 대비 사용률로 나타내는 추가 큐블릿 메트릭입니다.
          kubeletstats:
            collection_interval: 20s
            auth_type: 'serviceAccount'
            endpoint: '${env:K8S_NODE_NAME}:10250'
            insecure_skip_verify: true
            metrics:
              k8s.pod.cpu_limit_utilization:
                enabled: true
              k8s.pod.cpu_request_utilization:
                enabled: true
              k8s.pod.memory_limit_utilization:
                enabled: true
              k8s.pod.memory_request_utilization:
                enabled: true
              k8s.pod.uptime:
                enabled: true
              k8s.node.uptime:
                enabled: true
              k8s.container.cpu_limit_utilization:
                enabled: true
              k8s.container.cpu_request_utilization:
                enabled: true
              k8s.container.memory_limit_utilization:
                enabled: true
              k8s.container.memory_request_utilization:
                enabled: true
              container.uptime:
                enabled: true

        exporters:
          otlphttp:
            endpoint: "${env:YOUR_OTEL_COLLECTOR_ENDPOINT}"
            compression: gzip
            headers:
              authorization: "${env:OTLP_AUTH_TOKEN}"

        service:
          pipelines:
            logs:
              exporters:
                - otlphttp
            metrics:
              exporters:
                - otlphttp
      ```
    </Accordion>

    다음 명령으로 설치하십시오.

    ```shell
    helm install k8s-otel-daemonset open-telemetry/opentelemetry-collector \
      -f k8s_daemonset.yaml \
      -n ${NAMESPACE}
    ```

    두 릴리스가 모두 정상 상태인지 확인하십시오.

    ```shell
    kubectl get pods -n ${NAMESPACE} -l app.kubernetes.io/name=opentelemetry-collector
    ```

    배포 파드 1개와 노드당 데몬셋 파드 1개가 표시되며, 모든 파드가 `Running` 상태여야 합니다.
  </Step>

  <Step title="Kubernetes 속성을 앱에 전달하세요(권장)" id="forward-k8s-attributes">
    애플리케이션 로그, 메트릭, 트레이스를 Kubernetes 메타데이터(파드 이름, 네임스페이스, 노드, 배포)와 연관시키려면 `OTEL_RESOURCE_ATTRIBUTES`를 통해 메타데이터를 애플리케이션에 전달하십시오. 그러면 데몬셋의 `k8sattributes` 프로세서가 수신되는 텔레메트리에 해당 파드 및 노드 속성을 추가하여 보강합니다.

    ```yaml
    # my_app_deployment.yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: app-deployment
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: app
      template:
        metadata:
          labels:
            app: app
            service.name: <MY_APP_NAME>
        spec:
          containers:
            - name: app-container
              image: my-image
              env:
                - name: POD_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.name
                - name: POD_UID
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.uid
                - name: POD_NAMESPACE
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.namespace
                - name: NODE_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: spec.nodeName
                - name: DEPLOYMENT_NAME
                  valueFrom:
                    fieldRef:
                      fieldPath: metadata.labels['deployment']
                - name: OTEL_RESOURCE_ATTRIBUTES
                  value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME),k8s.deployment.name=$(DEPLOYMENT_NAME)
    ```
  </Step>

    [ClickHouse Cloud 콘솔](https://console.clickhouse.cloud)에서 서비스를 열고 왼쪽 메뉴에서 **ClickStack**을 선택하십시오.

    **검색** 뷰에서 소스를 `Logs`로 전환하고 시간 범위를 **Last 15 minutes**로 설정하십시오. 몇 초 안에 클러스터 전체의 컨테이너 로그가 표시되며, 각 로그에는 `k8s.namespace.name`, `k8s.pod.name`, `k8s.node.name` 등의 속성이 보강되어 있습니다.

    인프라 메트릭과 이벤트를 함께 연관 지어 확인하려면 **Dashboards** -&gt; **Kubernetes**로 이동하여 내장 **Kubernetes** 대시보드를 여십시오. `Pods`, `Nodes`, `Namespaces` 탭 모두에 데이터가 표시되어야 합니다.

    아무것도 표시되지 않는다면 다음을 확인하십시오.

    * 데몬셋 및 배포 파드가 `Running` 상태인지 확인하고, `kubectl logs -n ${NAMESPACE} <pod>`로 로그를 살펴보십시오.
    * 클러스터 내부에서 `YOUR_OTEL_COLLECTOR_ENDPOINT`에 연결할 수 있는지 확인하십시오(collector 파드 중 하나에 `kubectl exec`로 접속한 후 `curl`로 요청).
    * 시크릿의 `OTLP_AUTH_TOKEN`이 gateway collector에 설정된 값과 일치하는지 확인하십시오.
  </Step>

  <Step title="추가 참고 자료" id="further-reading">
    * 전체 수신기, 프로세서 및 튜닝 옵션은 [Kubernetes 통합 참고](/ko/clickstack/observability/integration-examples/kubernetes#self-managed)를 참조하십시오.
    * 애플리케이션 측 데이터 보강에 대한 자세한 내용은 [파드로 리소스 태그 전달](/ko/clickstack/observability/integration-examples/kubernetes#application-metadata)을 참조하십시오.
    * OTLP 엔드포인트에 TLS를 적용하고 최소 권한(privilege)만 가진 수집용 사용자를 사용하는 방법은 [collector 보안 설정](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)을 참조하십시오.
    * 예상 처리량에 맞춰 gateway 및 에이전트 배포에 필요한 리소스를 산정하는 방법은 [리소스 산정](/ko/clickstack/self-configured/ingesting-data/collector#estimating-resources-self-configured)을 참조하십시오.
    * 운영 환경으로 전환할 때의 권장 사항은 [프로덕션 환경으로 전환](/ko/clickstack/self-configured/managing/production)을 참조하십시오.
  </Step>
</Steps>
