    ClickHouse Observability에는 로그, 메트릭, trace, 세션 리플레이 데이터를 수신하여 ClickHouse Cloud에 기록하는 **관리형 OpenTelemetry(OTel) collector**가 포함되어 있습니다. 수집 collector, 데이터베이스, ClickStack UI는 ClickHouse Cloud가 운영합니다. 사용자는 애플리케이션을 계측한 다음, 애플리케이션 또는 데이터 수집 에이전트가 관리형 서비스로 텔레메트리를 전송하도록 구성하기만 하면 됩니다.

## 연결 정보 확인 {#connection-details}

    서비스에서 **팀 설정 → 데이터**를 열고 **Managed Telemetry** 섹션을 찾으십시오. 이 섹션에서 서비스로 텔레메트리를 전송하는 데 필요한 OTLP 엔드포인트와 API Key를 확인할 수 있습니다.

    **URL**, **Collector config**, **Env vars** 중 원하는 형식을 선택하여 연결 정보를 확인한 다음 **Copy connection details**를 클릭하여 복사하십시오. 제공된 엔드포인트와 인증 설정으로 SDK 또는 collector를 구성하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![마스킹된 OTLP HTTP 엔드포인트와 API Key가 표시된 Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    자세한 내용은 [Managed Telemetry](/ko/clickstack/observability/managing/config#managed-telemetry)를 참조하십시오. **Send a Test Log**를 사용하면 샘플 로그를 서비스로 전송해 볼 수 있습니다.

## 텔레메트리 전송 방식 선택 {#sending-telemetry}

### 애플리케이션 계측 {#application-instrumentation}

    언어별 SDK는 요청 trace, 애플리케이션 로그 등 애플리케이션 내부에서 발생하는 텔레메트리를 수집합니다. SDK가 OTLP를 사용하여 관리형 엔드포인트로 직접 텔레메트리를 내보내거나, 사용자 환경에서 서비스로 전달하는 collector로 내보내도록 구성하십시오.

    기존 OpenTelemetry instrumentation을 그대로 사용할 수 있습니다. ClickStack SDK는 브라우저 세션 리플레이와 같은 기능도 제공합니다. 관리형 환경의 설정 예시는 [세션 리플레이](/ko/clickstack/observability/features/session-replay)를 참조하십시오.

### 인프라 및 수집 에이전트 {#collection-agents}

    사용자 환경에서 수집 에이전트를 실행하여 호스트 메트릭, 컨테이너 로그, Kubernetes 이벤트 등의 텔레메트리를 수집하십시오. OpenTelemetry collector는 수집 대상에 따라 애플리케이션과 함께 실행하거나, 호스트에서 실행하거나, Kubernetes DaemonSet으로 실행할 수 있습니다.

    서비스의 연결 정보를 사용하여 이러한 에이전트가 관리형 OTLP 엔드포인트로 텔레메트리를 전달하도록 구성하십시오. 애플리케이션 텔레메트리가 이러한 collector를 거치도록 라우팅하면 ClickHouse Observability에 도달하기 전에 처리할 수도 있습니다.

## 수집 확인 {#verify-ingestion}

    애플리케이션 또는 collector를 구성한 후 텔레메트리를 생성하고 [검색](/ko/clickstack/observability/features/search)을 여십시오. **Logs** 또는 **Traces** 소스를 선택하고 새 이벤트가 포함된 시간 범위를 지정한 다음, 서비스 이름으로 검색하여 데이터가 수신되었는지 확인하십시오.

  <Tab title="자가 관리형">
    모든 데이터는 **OpenTelemetry (OTel) collector**를 통해 자체 관리형 ClickHouse Observability로 수집됩니다. 이 collector는 로그, 메트릭, trace, 세션 데이터의 기본 진입점 역할을 합니다.

    애플리케이션에서 보내는 텔레메트리 데이터를 수신하려면 OpenTelemetry Collector를 직접 실행합니다. 자체 관리형 ClickHouse Observability에서는 ClickHouse와 UI를 ClickHouse Cloud에서 호스팅하고 관리하며, 통합 인증과 운영 관리도 함께 제공합니다.

    <div className="ch-image-lg">
      <Frame>
        ![자체 관리형 collector를 거쳐 ClickHouse로 전달되는 OTLP 텔레메트리와 ClickHouse Cloud에서 호스팅되는 ClickStack UI](/images/use-cases/observability/clickstack-self-managed-architecture.svg)
      </Frame>
    </div>

    collector는 두 개의 OTLP 엔드포인트를 노출합니다.

    * **HTTP** - 포트 `4318`
    * **gRPC** - 포트 `4317`

    이 엔드포인트로는 [언어별 SDK](/ko/clickstack/observability/ingesting-data/sdks)에서 직접 데이터를 전송하거나, OTel 호환 데이터 수집 에이전트(예: 인프라 메트릭과 로그를 수집하는 다른 OTel collector)를 통해 데이터를 전송할 수 있습니다.

    구체적으로는 다음과 같습니다.

    * [**언어별 SDK**](/ko/clickstack/observability/ingesting-data/sdks)는 애플리케이션 내부에서 텔레메트리(특히 **trace**와 **로그**)를 수집하고, 이 데이터를 OTLP 엔드포인트를 통해 OpenTelemetry collector로 내보냅니다. 이후 collector가 ClickHouse로의 수집을 처리합니다. 사용 가능한 언어별 SDK에 대한 자세한 내용은 [SDKs](/ko/clickstack/observability/ingesting-data/sdks)를 참조하십시오.

    * **데이터 수집 에이전트**는 서버, Kubernetes 노드 등 엣지에 배포되거나 애플리케이션과 함께 배포되는 에이전트입니다. 이 에이전트는 인프라 텔레메트리(예: 로그, 메트릭)를 수집하거나 SDK로 계측된 애플리케이션에서 이벤트를 직접 수신합니다. 후자의 경우 에이전트는 애플리케이션과 같은 호스트에서 실행되며, 주로 사이드카나 데몬셋 형태로 실행됩니다. 이러한 에이전트는 데이터를 중앙의 ClickStack OTel 수집기로 전달합니다. 이 수집기는 [gateway](/ko/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured) 역할을 하며, 일반적으로 클러스터, 데이터 센터 또는 리전마다 하나씩 배포됩니다. [gateway](/ko/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)는 에이전트나 애플리케이션에서 OTLP 이벤트를 수신하고 ClickHouse로의 수집을 처리합니다. 자세한 내용은 [OTel collector](/ko/clickstack/self-configured/ingesting-data/collector)를 참조하십시오. 이러한 에이전트로는 OTel collector의 다른 인스턴스를 사용할 수도 있고, [Fluentd](https://www.fluentd.org/)나 [Vector](https://vector.dev/) 같은 대체 기술을 사용할 수도 있습니다.

    <Info>
      **OpenTelemetry 호환성**

      ClickStack은 향상된 텔레메트리와 기능을 갖춘 자체 언어별 SDK와 커스텀 OpenTelemetry collector를 제공하지만, 기존 OpenTelemetry SDK와 에이전트도 문제없이 그대로 사용할 수 있습니다.
    </Info>
