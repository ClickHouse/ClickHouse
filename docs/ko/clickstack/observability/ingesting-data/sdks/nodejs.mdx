ClickStack Node.js SDK는 업스트림 OpenTelemetry SDK와 auto-instrumentation을 기반으로 합니다. 여기에 콘솔 출력 capture, 처리되지 않은 예외 capture, 종료 시 텔레메트리 플러시 기능을 더했습니다. 이미 OpenTelemetry를 구성한 애플리케이션은 기존 SDK를 그대로 사용하면서 [OTLP 내보내기를 구성](/ko/clickstack/observability/ingesting-data/opentelemetry)하면 됩니다.

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## 설치 {#install}

Node.js **22.15 이상** 버전을 사용하십시오. 애플리케이션에 SDK를 설치합니다.

```shell
npm install @clickhouse/clickstack-node
```

이 패키지는 ES 모듈과 CommonJS를 모두 지원합니다. 피어 의존성(peer dependency)인 `@opentelemetry/api`는 npm이 자동으로 설치합니다. 애플리케이션에서 이 패키지를 직접 가져오는 경우 `@opentelemetry/api@~1.9.1`을 설치하십시오. 1.10 버전은 이 SDK의 지원 범위에 포함되지 않습니다.

## 대상 구성 {#configure-destination}

애플리케이션을 시작하기 전에 환경 변수를 설정하십시오. OTLP HTTP 엔드포인트는 `/v1/traces`, `/v1/logs`, `/v1/metrics`를 제외한 기본 주소를 사용하십시오. 해당 경로는 익스포터가 자동으로 추가합니다.

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 제공" />

    **Team Settings → Data → Managed Telemetry**를 열고 **OTLP HTTP 엔드포인트**와 **API key**를 복사하십시오. 서비스에 표시된 HTTPS 엔드포인트와 포트를 그대로 사용하십시오.

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```
  </Tab>

  <Tab title="자가 관리형">
    collector의 OTLP HTTP 엔드포인트와 해당 OTLP 수신기에 구성된 수집 키를 사용하십시오. collector 설정 방법은 [OpenTelemetry로 데이터 수집하기](/ko/clickstack/observability/ingesting-data/opentelemetry#self-managed)를 참조하십시오.

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_SERVICE_NAME='my-node-app'
    ```

    이 엔드포인트는 애플리케이션과 collector가 동일한 호스트에서 실행되는 경우를 전제로 합니다. collector가 다른 곳에서 실행되는 경우 애플리케이션에서 연결할 수 있는 주소로 바꾸십시오.
  </Tab>
</Tabs>

## 애플리케이션 시작하기 {#start-application}

애플리케이션이 SDK가 계측하는 라이브러리를 가져오기 전에 SDK를 미리 로드하세요:

```shell
node --import @clickhouse/clickstack-node/register server.js
```

`server.js`를 애플리케이션의 진입 파일로 바꾸십시오. 이 명령은 애플리케이션이 시작되기 전에 SDK를 로드하며, 위에서 구성한 환경 변수를 사용합니다. CommonJS 및 ES 모듈 애플리케이션을 모두 지원합니다.

이제 [수집을 확인](#verify-ingestion)할 수 있습니다. 아래의 대체 방법은 npm 스크립트로 애플리케이션을 시작하거나 코드에서 SDK를 구성하려는 경우에만 필요합니다.

<Accordion title="다른 시작 방법">
  `--require`도 지원됩니다. `NODE_OPTIONS`를 사용한다면 빌드 도구가 자체 텔레메트리 파이프라인을 시작하지 않도록 해당 옵션을 애플리케이션 명령에만 적용하십시오.

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  또는 instrumentation 모듈을 만들어 미리 로드할 수도 있습니다. 이때도 내보내기(export)는 이전 섹션의 환경 변수로 구성됩니다.

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  이 가드는 Pino transport worker와 같은 작업자 스레드에서 SDK 인스턴스가 추가로 시작되는 것을 방지합니다.

  패키지의 등록 진입점과 자체 instrumentation 모듈 중 하나만 사용하십시오. 애플리케이션에서 SDK를 한 번 더 초기화하지 마십시오. 정적 ES 모듈 import는 모듈 본문보다 먼저 실행되므로, 같은 파일에서 `init`을 정적 import보다 위에 두고 호출하더라도 초기화 순서가 보장되지 않습니다.
</Accordion>

## 수집 확인 {#verify-ingestion}

애플리케이션을 시작한 후 계측된 라우트에 요청을 보내고 콘솔 메시지를 출력하십시오. ClickHouse Observability에서 최근 시간 범위를 선택하고 로그(Logs) 또는 트레이스(Traces)에서 `my-node-app`을 검색하십시오. 메트릭은 메트릭 내보내기 인터벌만큼 시간이 지난 후에 확인하십시오.

데이터가 표시되지 않으면 stderr에 출력되는 SDK 진단 정보, 엔드포인트와 인증 설정, 네트워크 연결 상태를 확인하십시오. instrumentation이 애플리케이션 의존성보다 먼저 로드되는지도 확인하십시오. 번들러가 라이브러리를 인라인으로 확장하면 해당 라이브러리는 자동으로 계측되지 않으므로, SDK와 계측 대상 의존성은 외부(external)로 유지하십시오. TypeScript, ES 모듈, 프레임워크 및 번들러 요구 사항은 [SDK 호환성](https://github.com/ClickHouse/clickstack-node#compatibility)을 참조하십시오.

## instrumentation 구성 {#configure-instrumentation}

표준 OpenTelemetry 환경 변수는 샘플링, 일괄 처리, 익스포터, 리소스 속성 관련 변수를 포함하여 업스트림과 동일한 의미를 그대로 유지합니다. 예를 들면 다음과 같습니다.

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

콘솔 출력은 기본적으로 capture됩니다. HTTP body capture는 기본적으로 비활성화되어 있으며, 애플리케이션이 처리하는 데이터에 적합한 경우에만 활성화하십시오:

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

capture된 body에는 개인 데이터와 자격 증명이 포함될 수 있습니다. SDK의 마스킹은 모든 민감 정보의 제거를 보장하지 않으므로(best effort), 필요한 경우 collector 측 마스킹을 계속 적용하십시오. 헤더 capture, body 크기 제한, 데이터 정제(sanitization)에 대해서는 [SDK 개인정보 보호 옵션](https://github.com/ClickHouse/clickstack-node#privacy)을 참조하십시오.

### 초기화 옵션 {#initialization-options}

instrumentation 모듈에서 다음 옵션을 `init`에 전달하십시오.

| 옵션                           | 기본값                                  | 용도                                                                                                        |
| ---------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `endpoint`                   | `http://localhost:4318`              | 기본 OTLP HTTP URL입니다. `OTEL_EXPORTER_OTLP_ENDPOINT`로 재정의됩니다                                                |
| `serviceName`                | `unknown_service:` 뒤에 실행 파일 이름이 붙은 값 | 서비스 이름입니다. `OTEL_SERVICE_NAME` 또는 `OTEL_RESOURCE_ATTRIBUTES`의 `service.name`으로 재정의됩니다                     |
| `environment`                | 설정되지 않음                              | `deployment.environment.name`을 설정합니다. `OTEL_RESOURCE_ATTRIBUTES`에 같은 키가 있으면 그 값이 우선합니다                    |
| `apiKey`                     | 설정되지 않음                              | 인증 헤더 값입니다. `OTEL_EXPORTER_OTLP_HEADERS`가 이미 비어 있지 않으면 관련 없는 헤더만 들어 있더라도 무시됩니다                            |
| `httpBodyCapture`            | `false`                              | HTTP 본문을 capture합니다. `CLICKSTACK_CAPTURE_HTTP_BODY`로 재정의됩니다                                                    |
| `instrumentations`           | 업스트림 구성 기본값                          | `getNodeAutoInstrumentations`에 전달할 구성 맵입니다. 명시적으로 지정한 `enabled` 값은 instrumentation 활성화/비활성화 환경 변수보다 우선합니다 |
| `additionalInstrumentations` | `[]`                                 | 기본 bundle에 포함되지 않은 라이브러리용 추가 instrumentation 인스턴스입니다                                                      |

환경 변수가 설정되지 않았거나 비어 있으면 해당 옵션 값이 적용됩니다. 콘솔 capture를 비활성화하려면 `OTEL_NODE_DISABLED_INSTRUMENTATIONS`에 `console`을 추가하십시오. 전체 기본값은 [Node.js SDK 참고 문서](https://github.com/ClickHouse/clickstack-node#quick-start)를 참조하십시오.

프로세스를 명시적으로 종료하거나 AWS Lambda 핸들러를 사용하는 경우 [SDK 수명 주기 문서](https://github.com/ClickHouse/clickstack-node#lifecycle)를 참조하십시오.

## 업스트림 SDK 사용 {#using-upstream-sdk}

애플리케이션에서 이미 OpenTelemetry를 구성하고 있거나 ClickStack SDK 옵션으로는 지원되지 않는 사용자 정의 프로세서 또는 동작이 필요하다면, 업스트림 `NodeSDK`를 사용하고 위의 대상으로 OTLP 내보내기를 구성하십시오. 추가 로더 및 수명 주기 구성 방법은 [업스트림 SDK 설정 예시](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly)를 참고하십시오. 하나의 프로세스에서 두 SDK를 함께 초기화하지 마십시오.

## HyperDX Node.js SDK에서 마이그레이션 {#migration}

`@hyperdx/node-opentelemetry`를 `@clickhouse/clickstack-node`로 교체하고 새 등록 진입점을 사용하십시오. `HYPERDX_API_KEY` 대신 `OTEL_EXPORTER_OTLP_HEADERS`를 사용하되, 앞에서 설명한 대상별 인증 포맷을 따르십시오.

새 SDK는 HyperDX의 헬퍼와 옵션을 모두 지원하지는 않습니다. 로거 통합, 오류 처리기, 사용자 정의 트레이스 속성 또는 샘플링 설정을 교체하기 전에 [SDK 마이그레이션 가이드](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md)를 확인하십시오.
