    OpenTelemetry SDK 또는 사용자 환경의 collector를 사용하여 로그, 메트릭, trace를 ClickHouse Observability로 전송합니다. 이 서비스에는 OTLP로 텔레메트리를 수신하여 ClickHouse Cloud에 기록하는 관리형 수집 collector가 포함되어 있습니다.

## 연결 정보 확인하기 {#sending-otel-data}

    서비스를 열고 **팀 설정 → 데이터 → Managed Telemetry**로 이동하십시오. **OTLP HTTP 엔드포인트**와 **API Key**를 복사하십시오. **환경 변수** 및 **Collector 구성** 탭에서 해당 서비스용 구성을 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![마스킹된 OTLP HTTP 엔드포인트와 API Key가 표시된 Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Managed Telemetry에 표시된 포트를 포함한 전체 HTTPS 엔드포인트를 사용하십시오. 기본 OTLP HTTP 엔드포인트를 지정할 때는 `/v1/logs`, `/v1/traces`, `/v1/metrics`와 같은 신호 경로를 생략하십시오. 이러한 경로는 익스포터가 자동으로 추가합니다.

## 애플리케이션에서 직접 전송하기 {#sending-data-to-collector-managed}

    애플리케이션 언어에 맞는 OpenTelemetry instrumentation과 OTLP HTTP 익스포터를 설치하고 초기화하십시오. 환경 변수를 통한 구성을 지원하는 SDK라면 애플리케이션을 시작하기 전에 애플리케이션 환경에 다음 값을 설정하십시오.

    ```shell
    export OTEL_SERVICE_NAME='my-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_HEADERS='authorization=Bearer%20YOUR_API_KEY'
    ```

    엔드포인트는 Managed Telemetry에 표시된 값 그대로, `YOUR_API_KEY`는 서비스의 API Key로 대체하십시오. 헤더 환경 변수에서 `%20`은 `Bearer`와 키 사이의 공백을 인코딩한 것입니다.

    환경 변수 지원 여부는 SDK마다 다릅니다. SDK에서 코드로 구성해야 하는 경우에는 동일한 HTTPS 엔드포인트와 OTLP HTTP 프로토콜을 지정하고, 값이 `Bearer YOUR_API_KEY`인 `authorization` 헤더를 추가하십시오. 언어별 지원 현황과 시그널별 재정의는 [OpenTelemetry 익스포터 구성 참고 문서](https://opentelemetry.io/docs/languages/sdk-configuration/otlp-exporter/)를 참조하십시오.

    이 설정은 내보내기만 구성하므로, 텔레메트리를 생성하려면 애플리케이션에 별도로 instrumentation을 적용해야 합니다. 브라우저 세션 녹화는 [세션 리플레이 가이드](/ko/clickstack/observability/features/session-replay)를 참조하십시오.

## collector에서 데이터 전달하기 {#forward-from-a-collector}

    이미 OpenTelemetry collector로 텔레메트리를 수집하고 있다면 OTLP HTTP 익스포터를 구성하여 관리형 엔드포인트로 데이터를 전달하십시오. 데이터 수집과 처리에 사용하던 기존 수신기와 프로세서는 그대로 유지하면 됩니다.

    collector 런타임에 다음 환경 변수를 설정하십시오:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_API_KEY='YOUR_API_KEY'
    ```

    두 자리 표시자를 모두 Managed Telemetry의 값으로 바꾸고, 다음 익스포터를 수집기 설정에 추가하십시오.

    ```yaml
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "Bearer ${env:OTEL_EXPORTER_OTLP_API_KEY}"
    ```

    `service.pipelines` 아래에서 전달하려는 각 로그, 메트릭 또는 트레이스 파이프라인의 `exporters` 목록에 `otlp_http/observability`를 추가하십시오. 이를 기존 구성에 병합한 다음 collector를 재시작하거나 다시 배포하여 변경 사항을 적용하십시오.

    이 예시에서는 현재의 `otlp_http` 익스포터 이름을 사용합니다. 이전 collector 릴리스에서는 `otlphttp`를 사용할 수 있으므로 사용 중인 배포판에서 지원하는 이름을 사용하십시오. 구성 옵션은 [OTLP HTTP 익스포터 문서](https://github.com/open-telemetry/opentelemetry-collector/tree/main/exporter/otlphttpexporter)를 참조하십시오.

    호스트 로그와 메트릭을 수집하는 전체 예시는 [로컬 시스템 로그 및 메트릭](/ko/clickstack/observability/example-datasets/local-data)을 참조하십시오.

## 수집 확인 {#verify-ingestion}

    애플리케이션에서 텔레메트리를 생성한 다음 ClickHouse Observability에서 [검색](/ko/clickstack/observability/features/search)을 여십시오. **Logs** 또는 **Traces**를 선택하고, 새 이벤트가 포함되도록 시간 범위를 지정한 후 서비스 이름으로 검색하십시오.

    데이터가 표시되지 않으면 SDK 또는 collector 로그에서 내보내기 오류가 있는지 확인하십시오. 엔드포인트, 인증 헤더, 프로토콜이 올바른지 점검하고, 애플리케이션 또는 collector가 관리형 엔드포인트에 연결할 수 있는지 확인하십시오. 또한 기본 엔드포인트나 header를 재정의하는 신호별 익스포터 설정이 있는지도 확인하십시오.

    Managed Telemetry의 **Send a Test Log**를 사용하면 표본 로그를 서비스로 전송할 수 있습니다. 다만 애플리케이션의 instrumentation 및 내보내기 구성이 올바른지 확인하려면 애플리케이션의 텔레메트리를 별도로 검증하십시오.

  <Tab title="자가 관리형" id="self-managed">
    자체 관리형 ClickHouse Observability에서는 **OpenTelemetry (OTel) collector**가 로그, 메트릭, trace, 세션 데이터를 수신하여 ClickHouse Cloud에 기록합니다. collector로는 공식 [ClickStack 배포판](#installing-otel-collector-managed-self-configured)을 사용하는 것을 권장합니다.

    [언어별 SDK](/ko/clickstack/observability/ingesting-data/sdks) 또는 인프라 로그와 메트릭을 수집하는 에이전트에서 이 collector로 데이터를 전송하십시오. 여기에는 [에이전트 역할](/ko/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)로 동작하는 OpenTelemetry 수집기, [Fluentd](https://www.fluentd.org/), [Vector](https://vector.dev/) 등이 포함될 수 있습니다. collector를 중앙에서 관리하려면 [Bindplane](/ko/clickstack/observability/integration-partners/bindplane)을 활용할 수 있습니다. Bindplane은 ClickHouse Observability 대상과 함께 텔레메트리를 수집, 처리, 라우팅하는 도구를 제공합니다.

## OpenTelemetry 데이터 전송 {#sending-otel-data-self-configured}

### collector를 ClickHouse Cloud에 연결하기 {#installing-otel-collector-managed-self-configured}

    HTTP 또는 gRPC로 OTLP 데이터를 수신하여 ClickHouse Cloud로 전달하도록 collector를 [gateway 역할](/ko/clickstack/self-configured/ingesting-data/collector#collector-roles-self-configured)로 구성하십시오.

    <Info>
      **ClickStack OpenTelemetry 수집기 사용을 권장합니다**

      ClickStack 배포판은 ClickHouse Observability와 호환되는 처리 방식과 스키마(schemas)를 제공합니다. 기본 스키마(schema)를 사용하면 소스 자동 감지와 사전 구성된 컬럼 매핑이 활성화됩니다.
    </Info>

    ClickHouse Cloud에서 서비스를 열고 [연결 정보를 확인하십시오](/ko/products/cloud/guides/sql-console/connection-details). 그런 다음 ClickStack 배포판 collector의 런타임에서 다음 환경 변수를 구성하십시오:

    ```shell
    CLICKHOUSE_ENDPOINT="https://<host>:8443"
    CLICKHOUSE_USER="<ingestion-user>"
    CLICKHOUSE_PASSWORD="<ingestion-password>"
    ```

    `CLICKHOUSE_ENDPOINT`에는 서비스의 HTTPS 데이터베이스 엔드포인트를 지정하고, 자격 증명으로는 [전용 수집 사용자](/ko/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)의 자격 증명을 사용하십시오. 설정을 적용하려면 collector를 재시작하거나 재배포하십시오. collector는 OTLP를 통해 텔레메트리를 수신하여 ClickHouse Cloud 서비스에 기록합니다.

    다른 collector 배포판을 사용하는 경우 해당 배포판의 ClickHouse 익스포터를 동일한 엔드포인트와 자격 증명으로 구성하십시오. 예시는 [구성 수정](/ko/clickstack/self-configured/ingesting-data/collector#modifying-otel-collector-configuration-managed-self-configured)을 참조하십시오.

    설치 방법은 [collector 배포](/ko/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured)를 참조하십시오. 운영 환경 트래픽을 전송하기 전에 [collector를 보호](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)하십시오. `OTLP_AUTH_TOKEN`을 활성화한 경우 SDK와 전달용 collector가 `authorization` 헤더에 해당 토큰을 포함하여 전송하도록 구성하십시오.

### collector로 데이터 전송하기 {#sending-data-to-collector-managed-self-configured}

    기본 OTLP 포트로 로컬에서 실행 중인 collector를 사용하는 경우, OpenTelemetry instrumentation이 아래 엔드포인트를 가리키도록 설정하십시오. 애플리케이션 또는 에이전트가 다른 호스트나 다른 컨테이너에서 실행된다면 `localhost`를 해당 환경에서 연결할 수 있는 collector 호스트명으로 바꾸십시오:

    * **HTTP (OTLP):** `http://localhost:4318`
    * **gRPC (OTLP):** `localhost:4317`

    환경 변수 구성을 지원하는 [언어별 SDK](/ko/clickstack/observability/ingesting-data/sdks)를 사용하는 경우, 계측된 애플리케이션을 시작하기 전에 엔드포인트와 프로토콜을 설정하십시오:

    ```shell
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    ```

    collector에 인증이 필요한 경우 `OTEL_EXPORTER_OTLP_HEADERS="authorization=<collector-token>"`도 설정하고, `<collector-token>`을 해당 collector의 `OTLP_AUTH_TOKEN` 값으로 바꾸십시오. 완전 관리형 엔드포인트에서 사용하는 `Bearer` 접두사는 추가하지 마십시오. 이 설정은 내보내기만 구성하므로, 애플리케이션에서 텔레메트리를 생성하려면 별도의 instrumentation이 필요합니다.

    [OTel collector의 contrib 배포판](https://github.com/open-telemetry/opentelemetry-collector-contrib)을 사용하는 에이전트는 OTLP로 로그를 전달할 수 있습니다. 아래 예시에서는 이 [구조화된 로그 파일](https://datasets-documentation.s3.eu-west-3.amazonaws.com/http_logs/access-structured.log.gz)을 읽습니다. 에이전트를 시작하기 전에 파일을 다운로드한 후 `include`에 지정된 경로에 압축 해제하십시오. gateway에 인증이 필요하면 gateway의 토큰을 담은 `authorization` 헤더를 에이전트 익스포터에 추가하십시오.

    ```yaml
    # clickhouse-agent-config.yaml
    receivers:
      filelog:
        include:
          - /opt/data/logs/access-structured.log
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.time_local
              layout: '%Y-%m-%d %H:%M:%S'
    exporters:
      # HTTP setup
      otlphttp/hdx:
        endpoint: 'http://localhost:4318'
        compression: gzip

      # gRPC setup (alternative)
      otlp/hdx:
        endpoint: 'localhost:4317'
        compression: gzip
    processors:
      batch:
        timeout: 5s
        send_batch_size: 10000
    service:
      telemetry:
        metrics:
          address: 0.0.0.0:9888 # Modified as 2 collectors running on same host
      pipelines:
        logs:
          receivers: [filelog]
          processors: [batch]
          exporters: [otlphttp/hdx]
    ```
