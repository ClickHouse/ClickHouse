    <Note>
      이 가이드는 **자체 관리형 ClickHouse Observability**에만 적용됩니다. Vector의 ClickHouse 싱크는 사용자가 관리하는 테이블에 데이터를 직접 기록합니다. 완전 관리형 ClickHouse Observability에서는 OTLP 수집을 사용해야 합니다. 엔드포인트 및 인증 설정은 [OpenTelemetry를 사용한 데이터 수집](/ko/clickstack/observability/ingesting-data/opentelemetry#fully-managed)을 참조하십시오.
    </Note>

    [Vector](https://vector.dev)는 고성능의 벤더 중립적인 관측성 데이터 파이프라인입니다. 다양한 소스에서 로그와 메트릭을 수집, 변환 및 라우팅하는 데 널리 사용되며, 유연성과 낮은 리소스 사용량 덕분에 특히 로그 수집 용도로 많이 활용됩니다.

    자체 관리형 ClickHouse Observability에서 Vector를 사용할 때는 사용자가 스키마(schemas)를 직접 정의해야 합니다. 이러한 스키마는 OpenTelemetry 규칙을 따를 수도 있지만, 사용자가 정의한 이벤트 구조를 표현하는 완전한 사용자 정의 스키마일 수도 있습니다. 실제로 Vector를 통한 수집은 **로그**에 가장 많이 사용되며, 이는 데이터가 ClickHouse에 기록되기 전에 파싱과 데이터 보강을 완전히 제어하려는 경우에 해당합니다.

    이 가이드는 Vector를 사용하여 자체 관리형 ClickHouse Observability로 데이터를 온보딩하는 방법을 중점적으로 다룹니다. 내용을 간결하게 유지하기 위해 Vector 소스나 파이프라인 구성은 자세히 설명하지 않습니다. 대신 ClickHouse에 데이터를 기록하는 **싱크**를 구성하는 방법과, 이를 통해 생성되는 스키마(schema)가 자체 관리형 ClickHouse Observability와 호환되도록 하는 방법을 중점적으로 설명합니다.

    서비스의 유일한 필수 요구 사항은 데이터에 **타임스탬프 컬럼**(또는 이와 동등한 시간 필드)이 포함되어야 한다는 것입니다. 이 컬럼은 관측성 UI에서 데이터 소스를 구성할 때 지정할 수 있습니다.

## Vector로 데이터 전송하기 {#sending-data-with-vector-self-configured}

    <br />

    이 가이드는 자체 관리형 ClickHouse Observability 서비스를 이미 생성하고 서비스 자격 증명을 기록해 두었다고 가정합니다. 아직 생성하지 않았다면 Vector를 구성하라는 안내가 나올 때까지 자체 관리형 ClickHouse Observability용 [시작하기](/ko/clickstack/self-configured/getting-started/managed) 가이드를 따르십시오.

    <Steps>
      <Step title="데이터베이스(Database) 및 테이블(Table) 생성" id="create-a-database-table-self-configured">
        Vector를 사용하려면 데이터 수집 전에 테이블과 스키마(schema)를 정의해야 합니다.

        먼저 데이터베이스를 생성하십시오. 데이터베이스는 [ClickHouse Cloud 콘솔](/ko/products/cloud/features/sql-console-features/sql-console)에서 생성할 수 있습니다.

        아래 예시에서는 `logs`를 사용합니다.

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        데이터를 저장할 테이블을 생성하십시오. 이 테이블은 데이터의 출력 스키마(schema)와 일치해야 합니다. 아래 예시는 일반적인 Nginx 구조를 기준으로 합니다. [스키마 권장 사항](/ko/concepts/best-practices/select-data-type)에 따라 데이터에 맞게 조정하십시오. [기본 키(primary keys) 개념](/ko/concepts/core-concepts/primary-indexes)을 숙지한 후 [여기](/ko/clickstack/self-configured/managing/performance-tuning#choosing-a-primary-key)에 설명된 지침에 따라 프라이머리 키를 선택할 것을 **강력히 권장합니다**.

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Nginx 프라이머리 키**

          위 프라이머리 키는 관측성 UI에서 Nginx 로그를 조회할 때의 일반적인 액세스 패턴을 전제로 한 것이므로, 운영 환경의 워크로드에 따라 조정해야 할 수 있습니다.
        </Info>
      </Step>

      <Step title="vector 구성에 ClickHouse 싱크 추가" id="add-clickhouse-sink-to-config-self-configured">
        Vector 구성을 수정하여 ClickHouse 싱크를 추가하고, 기존 파이프라인의 이벤트를 수신하도록 `inputs` 필드를 업데이트하십시오.

        이 구성은 업스트림 Vector 파이프라인에서 이미 **대상 ClickHouse 스키마(schema)에 맞게 데이터를 준비했다고** 가정합니다. 즉, 필드가 파싱되어 있고, 이름이 올바르게 지정되어 있으며, 삽입에 적합한 타입으로 지정되어 있어야 합니다. 원시 로그 행을 파싱하고 정규화하여 서비스에 적합한 스키마로 변환하는 전체 과정은 [**아래 Nginx 예시**](#example-dataset-with-vector-self-configured)를 참조하십시오.

        ```yaml
        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - your_input
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        기본적으로 각 이벤트를 행당 하나의 JSON 객체로 인코딩하는 **`json_each_row`** 포맷 사용을 권장합니다. 이 포맷은 JSON 데이터를 수집할 때 서비스의 기본 포맷이자 권장 포맷이므로, 문자열로 인코딩된 JSON 객체 등 다른 포맷보다 우선적으로 사용하십시오.

        ClickHouse 싱크는 **Arrow 스트림 인코딩**도 지원합니다(현재 베타). 이 방식은 더 높은 처리량을 제공할 수 있지만 중요한 제약 조건이 있습니다. 스키마(schema)를 시작 시 한 번만 가져오므로 데이터베이스와 테이블이 정적이어야 하며, 동적 라우팅은 지원되지 않습니다. 따라서 Arrow 인코딩은 고정되어 있고 명확하게 정의된 수집 파이프라인에 가장 적합합니다.

        [Vector 문서](https://vector.dev/docs/reference/configuration/sinks/clickhouse)에서 사용 가능한 싱크 구성 옵션을 확인하는 것을 권장합니다.

        <Note>
          위 예시에서는 자체 관리형 ClickHouse Observability의 default 사용자를 사용합니다. 운영 환경에 배포할 때는 적절한 권한과 제한을 갖춘 [전용 수집 사용자를 생성](/ko/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)하는 것을 권장합니다.
        </Note>
      </Step>

      <Step title="관측성 UI로 이동하십시오" id="navigate-to-clickstack-ui-self-configured">
        자체 관리형 ClickHouse Observability 서비스로 이동한 후 왼쪽 메뉴에서 &quot;ClickStack&quot;을 선택하십시오. 이미 온보딩을 완료했다면 관측성 UI가 새 탭에서 열리며 자동으로 인증됩니다. 온보딩을 완료하지 않았다면 온보딩을 진행하면서 입력 소스로 Vector를 선택한 후 “Launch ClickStack”을 선택하십시오.

        <div className="ch-image-lg">

            ![Vector용 ClickStack 실행](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="데이터 소스 생성" id="create-a-datasource-managed-self-configured">
        로그 데이터 소스를 생성하십시오. 데이터 소스가 하나도 없으면 처음 로그인할 때 데이터 소스를 생성하라는 안내가 표시됩니다. 데이터 소스가 이미 있다면 팀 설정(Team Settings)으로 이동하여 새 데이터 소스를 추가하십시오.

        <div className="ch-image-lg">
          <Frame>
            ![데이터 소스 생성 - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        위 구성은 `time_local` 컬럼을 타임스탬프로 사용하는 Nginx 스타일 스키마(schema)를 전제로 합니다. 가능하면 프라이머리 키에 선언된 타임스탬프 컬럼을 사용해야 합니다. 이 컬럼은 필수입니다.

        또한 로그 뷰에 반환할 컬럼을 명시적으로 지정하도록 `Default SELECT`를 수정하는 것을 권장합니다. 서비스 이름, 로그 레벨, body 컬럼 등 추가 필드를 사용할 수 있다면 이 항목들도 구성할 수 있습니다. 타임스탬프 표시 컬럼이 테이블의 프라이머리 키에 사용되어 위에서 구성한 컬럼과 다르다면 이 컬럼도 재정의할 수 있습니다.

        위 예시의 데이터에는 `Body` 컬럼이 없습니다. 대신 사용 가능한 필드로 Nginx 로그 행을 재구성하는 SQL 표현식(SQL expression)으로 이 컬럼을 정의합니다.

        그 밖의 옵션은 [구성 참고 문서](/ko/clickstack/self-configured/managing/config)를 참조하십시오.
      </Step>

      <Step title="데이터 탐색" id="explore-the-data-managed-self-configured">

      </Step>

## Vector를 사용한 예제 데이터 세트 {#example-dataset-with-vector-self-configured}

    좀 더 완전한 예시로, 아래에서는 **Nginx 로그 파일**을 사용합니다.

    이 가이드는 자체 관리형 ClickHouse Observability 서비스를 이미 생성하고 서비스 자격 증명을 기록해 두었다고 가정합니다. 아직 생성하지 않았다면 Vector를 구성하라는 안내가 나올 때까지 자체 관리형 ClickHouse Observability용 [시작하기](/ko/clickstack/self-configured/getting-started/managed) 가이드를 따르십시오.

      <Step title="데이터베이스(Database) 및 테이블(Table) 생성" id="create-database-table-nginx-managed-self-configured">
        Vector를 사용하려면 데이터 수집 전에 테이블과 스키마(schema)를 미리 정의해야 합니다.

        먼저 데이터베이스를 생성합니다. 이 작업은 [ClickHouse Cloud 콘솔](/ko/products/cloud/features/sql-console-features/sql-console)에서 수행할 수 있습니다.

        `logs` 데이터베이스를 생성하세요:

        ```sql
        CREATE DATABASE IF NOT EXISTS logs
        ```

        데이터를 저장할 테이블을 생성하십시오.

        ```sql
        CREATE TABLE logs.nginx_logs
        (
            `time_local` DateTime,
            `remote_addr` IPv4,
            `remote_user` LowCardinality(String),
            `request` String,
            `status` UInt16,
            `body_bytes_sent` UInt64,
            `http_referer` String,
            `http_user_agent` String,
            `http_x_forwarded_for` LowCardinality(String),
            `request_time` Float32,
            `upstream_response_time` Float32,
            `http_host` String
        )
        ENGINE = MergeTree
        ORDER BY (toStartOfMinute(time_local), status, remote_addr)
        ```

        <Info>
          **Nginx 프라이머리 키**

          위의 프라이머리 키는 관측성 UI에서 Nginx 로그를 조회할 때의 일반적인 액세스 패턴을 기준으로 한 것이므로, 운영 환경의 워크로드에 따라 조정해야 할 수 있습니다.
        </Info>
      </Step>

      <Step title="Vector 구성 복사" id="copy-vector-configuration-self-configured">
        Vector 구성을 복사하여 `nginx.yaml` 파일을 생성하고, `CLICKHOUSE_ENDPOINT`와 `CLICKHOUSE_PASSWORD`를 설정하십시오.

        ```yaml
        data_dir: ./.vector-data
        sources:
          nginx_logs:
            type: file
            include:
              - access.log
            read_from: beginning

        transforms:
          decode_json:
            type: remap
            inputs:
              - nginx_logs
            source: |
              . = parse_json!(to_string!(.message))
              ts = parse_timestamp!(.time_local, format: "%d/%b/%Y:%H:%M:%S %z")
              # ClickHouse-friendly DateTime format
              .time_local = format_timestamp!(ts, format: "%F %T")

        sinks:
          clickhouse:
            type: clickhouse
            inputs:
              - decode_json
            endpoint: "<CLICKHOUSE_ENDPOINT>"
            database: logs
            format: json_each_row
            table: nginx_logs
            skip_unknown_fields: true
            auth:
              strategy: "basic"
              user: "default"
              password: "<CLICKHOUSE_PASSWORD>"
        ```

        <Note>
          위 예시에서는 자체 관리형 ClickHouse Observability의 default 사용자를 사용합니다. 운영 환경 배포에서는 적절한 권한과 제한이 설정된 [전용 수집 사용자를 생성](/ko/clickstack/self-configured/ingesting-data/collector#creating-an-ingestion-user-self-configured)하는 것을 권장합니다.
        </Note>
      </Step>

      <Step title="Vector 시작" id="start-vector-self-configured">
        파일 오프셋을 기록할 데이터 디렉터리를 먼저 생성한 후, 다음 명령으로 Vector를 시작하십시오.

        ```bash
        mkdir ./.vector-data
        vector --config nginx.yaml
        ```
      </Step>

      <Step title="관측성 UI로 이동하십시오" id="navigate-to-clickstack-ui-nginx-managed-self-configured">
        자체 관리형 ClickHouse Observability 서비스로 이동한 후 왼쪽 메뉴에서 &quot;ClickStack&quot;을 선택하십시오. 이미 온보딩을 완료했다면 관측성 UI가 새 탭에서 열리며 자동으로 인증됩니다. 아직 완료하지 않았다면 온보딩을 진행하면서 입력 소스로 Vector를 선택한 후 “Launch ClickStack”을 선택하십시오.

        <div className="ch-image-lg">
          <Frame>
            ![Vector용 ClickStack 실행](/images/clickstack/launch-clickstack-vector.webp)
          </Frame>
        </div>
      </Step>

      <Step title="데이터 소스 생성" id="create-a-datasource-nginx-managed-self-configured">
        로그 데이터 소스를 생성하십시오. 데이터 소스(data sources)가 하나도 없으면 처음 로그인할 때 데이터 소스를 생성하라는 안내가 표시됩니다. 데이터 소스가 이미 있다면 팀 설정(Team Settings)으로 이동하여 새 데이터 소스를 추가하십시오.

        <div className="ch-image-lg">
          <Frame>
            ![데이터 소스 생성 - vector](/images/clickstack/create-vector-datasource.webp)
          </Frame>
        </div>

        이 구성은 `time_local` 컬럼을 타임스탬프로 사용하는 Nginx 스키마(schema)를 전제로 합니다. 이 컬럼은 프라이머리 키에 선언된 타임스탬프 컬럼이며, 필수 항목입니다.

        또한 기본 조회(Select) 항목을 `time_local, remote_addr, status, request`로 지정했습니다. 이 설정에 따라 로그 뷰에 표시되는 컬럼이 결정됩니다.

        위 예시의 데이터에는 `Body` 컬럼이 존재하지 않습니다. 대신 다음과 같은 SQL 표현식(SQL expression)으로 정의됩니다.

        ```sql
        concat(
          remote_addr, ' ',
          remote_user, ' ',
          '[', formatDateTime(time_local, '%d/%b/%Y:%H:%M:%S %z'), '] ',
          '"', request, '" ',
          toString(status), ' ',
          toString(body_bytes_sent), ' ',
        ```
