ClickHouse Observability의 세션 리플레이(Session Replay)는 웹 애플리케이션에서 발생한 사용자 상호작용을 캡처하고 재구성하여, 사용자가 세션 중에 보고 수행한 내용을 그대로 시각적으로 재생할 수 있게 합니다. SDK는 동영상을 녹화하는 대신 DOM 변경, 마우스 이동, 클릭, 스크롤, 키보드 입력, 콘솔 로그, 네트워크 요청(XHR 및 Fetch), JavaScript 예외를 기록한 다음, 이를 바탕으로 브라우저에서 사용자 경험을 재구성합니다.

세션 다시 보기 데이터는 로그, 트레이스, 메트릭과 함께 ClickHouse에 저장되므로, 사용자 경험을 재생해 보다가 몇 번의 클릭만으로 해당 경험을 처리한 백엔드 트레이스와 데이터베이스 쿼리까지 바로 살펴볼 수 있습니다. 따라서 세션 리플레이는 운영 환경의 이슈 디버깅, 사용자 행동 파악, UX 불편 지점 식별, 지원팀에 보고된 이슈의 시각적 확인에 유용합니다.

## 애플리케이션 계측하기 {#instrumentation}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 제공" />

    ClickHouse Observability는 OpenTelemetry와 완전히 호환되므로 표준 OpenTelemetry JavaScript SDK 또는 [언어별 SDK](/ko/clickstack/observability/ingesting-data/sdks)를 사용하여 브라우저 텔레메트리(trace, 예외)를 전송할 수 있습니다. 단, **세션 리플레이에는 브라우저 SDK**(`@clickhouse/clickstack-browser`)가 필요합니다. 브라우저 SDK는 OpenTelemetry SDK를 확장하여 세션 녹화, 콘솔 캡처, 네트워크 요청 캡처 기능을 제공합니다. 세션 리플레이 없이 trace만 필요하다면 OTel 호환 브라우저 SDK를 어떤 것이든 사용할 수 있습니다.

    아래 예시에서는 브라우저 SDK를 사용합니다. ClickHouse Observability 서비스에서 **Team Settings → Data → Managed Telemetry**를 열고 **OTLP HTTP 엔드포인트**와 **API Key**를 복사하십시오. 그런 다음 예시의 `YOUR_OTEL_ENDPOINT`와 `YOUR_API_KEY`를 이 연결 정보로 바꾸십시오.

    <div className="ch-image-lg">
      <Frame>
        ![마스킹된 OTLP HTTP 엔드포인트와 API Key가 표시된 Managed Telemetry 화면](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    엔드포인트는 Managed Telemetry에 표시된 전체 HTTPS 주소를 그대로 사용하고, `/v1/traces`와 같은 신호 경로는 붙이지 마십시오. API Key는 아래와 같이 `Bearer ` 접두사를 붙여 `apiKey`로 전달하십시오. 이어서 애플리케이션에 SDK를 설치하고 초기화하십시오.

    <Tip>
      SDK는 클라이언트 진입 모듈(예: Vite의 `src/main.ts`, Next.js의 `instrumentation-client.ts`)의 최상위 수준에서 한 번만 초기화하십시오. 초기화는 비동기로 수행되므로 같은 틱에서 `init` 직후에 발생한 요청은 캡처되지 않을 수 있습니다.
    </Tip>

    <Tabs>
      <Tab title="NPM">
        ```shell
        npm install @clickhouse/clickstack-browser
        ```

        ```javascript
        import { init } from '@clickhouse/clickstack-browser';

        init({
          endpoint: 'https://YOUR_OTEL_ENDPOINT:4318',
          apiKey: 'Bearer YOUR_API_KEY',
          serviceName: 'my-frontend-app',
          traceOrigins: ['https://api.myapp.domain'],
          console: 'debug',
        });
        ```
      </Tab>

      <Tab title="Yarn">
        ```shell

        ```

        ```javascript
        init({
          endpoint: 'https://YOUR_OTEL_ENDPOINT:4318',
          apiKey: 'Bearer YOUR_API_KEY',
          serviceName: 'my-frontend-app',
          traceOrigins: ['https://api.myapp.domain'],
          console: 'debug',
        });
        ```
      </Tab>

      <Tab title="스크립트 태그">
        번들러를 사용하지 않는 애플리케이션에서는 스크립트 태그로 SDK를 직접 포함하십시오. 이렇게 하면 `ClickStack` 전역 변수가 노출되며, 이를 NPM 패키지와 동일한 방식으로 사용할 수 있습니다.

        ```html
        <script src="https://cdn.jsdelivr.net/npm/@clickhouse/clickstack-browser@1.0.0/dist/clickstack.iife.js" integrity="sha384-NW4JhbuY4Thx4fMuqFwKvifcPn7ad9dJ7DU/MTxhkoHeadG27i4F38Yo1Gz6y0WA" crossorigin="anonymous"></script>
        <script>
          window.ClickStack.init({
            endpoint: 'https://YOUR_OTEL_ENDPOINT:4318',
            apiKey: 'Bearer YOUR_API_KEY',
            serviceName: 'my-frontend-app',
            traceOrigins: ['https://api.myapp.domain'],
            console: 'debug',
          });
        </script>
        ```
      </Tab>
    </Tabs>

    <Note>
      `traceOrigins` 옵션은 세션 다시 보기를 백엔드 트레이스와 연결하는 핵심 설정입니다. 프론트엔드에서 백엔드까지 전 구간의 분산 추적(distributed tracing)을 활성화하려면 이 옵션을 API 도메인으로 설정하십시오. 개인정보 보호 설정, 오류 보고 등 공통 SDK 옵션은 [브라우저 SDK 참조](/ko/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy)를 확인하십시오. SDK를 초기화할 때는 위에서 확인한 관리형 연결 정보를 사용하십시오.
    </Note>

    브라우저 SDK는 기본적으로 입력값과 텍스트를 마스킹합니다. 개인정보에 민감한 애플리케이션이라면 [개인정보 보호 설정](/ko/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy)을 참고하십시오. UI에서 사용자별로 세션을 검색하고 필터링하려면 [사용자 정보 연결](/ko/clickstack/observability/ingesting-data/sdks/browser#users-and-errors)을 참고하십시오.
  </Tab>

  <Tab title="자가 관리형" id="self-managed">
    자체 관리형 ClickHouse Observability는 OpenTelemetry와 완벽하게 호환되므로, 표준 OpenTelemetry JavaScript SDK 또는 [언어별 SDK](/ko/clickstack/observability/ingesting-data/sdks)를 사용해 브라우저 텔레메트리(trace, 예외)를 전송할 수 있습니다. 다만 **세션 리플레이를 사용하려면 브라우저 SDK가 필요합니다**(`@clickhouse/clickstack-browser`). 브라우저 SDK는 OpenTelemetry SDK를 확장하여 세션 녹화, 콘솔 캡처, 네트워크 요청 캡처 기능을 제공합니다. 세션 리플레이 없이 trace만 필요하다면 OTel 호환 브라우저 SDK라면 어떤 것이든 이 서비스와 함께 사용할 수 있습니다.

    애플리케이션을 계측하기 전에 ClickHouse Cloud 서비스에 연결된 ClickStack OpenTelemetry 수집기가 실행 중이어야 합니다. 연결을 구성하려면 [OpenTelemetry를 사용한 데이터 수집](/ko/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured) 가이드를 참조하고, collector를 시작하려면 [배포 가이드](/ko/clickstack/self-configured/deployment/managed#start-a-collector-existing)를 참조하세요.

    아래 예시의 `http://your-otel-collector:4318` 대신 브라우저에서 액세스할 수 있는 collector의 OTLP HTTP 엔드포인트를 사용하십시오. `apiKey`에는 `Bearer` 접두사 없이 collector의 수집 key를 설정하십시오. 수신기에 인증이 필요하지 않으면 생략해도 됩니다. collector의 CORS 구성에서 애플리케이션의 origin을 허용한 다음, 브라우저 SDK를 설치하고 초기화하십시오.

    <Tip>
      SDK는 클라이언트 진입 모듈의 최상위 수준에서 한 번만 초기화하십시오(예: Vite의 `src/main.ts`, Next.js의 `instrumentation-client.ts`). 초기화는 비동기로 수행되므로, 같은 틱 내에서 `init` 직후에 보낸 요청은 수집되지 않을 수 있습니다.
    </Tip>

        ```javascript
          serviceName: 'my-frontend-app',
          traceOrigins: ['https://api.myapp.domain'],
          console: 'debug',
        });
        ```
      </Tab>

      <Tab title="Yarn">

        ```shell
        yarn add @clickhouse/clickstack-browser @opentelemetry/api@~1.9.1 @opentelemetry/browser-sdk@^0.6.0
        ```

    <Note>
      `traceOrigins` 옵션은 세션 다시 보기를 백엔드 트레이스와 연결하는 핵심 요소입니다. 이 옵션을 API 도메인으로 설정하면 프론트엔드에서 백엔드까지 이어지는 전체 분산 추적(distributed tracing)이 활성화됩니다. 개인정보 보호 관련 설정과 오류 보고를 포함한 전체 SDK 옵션 목록은 [브라우저 SDK 참조](/ko/clickstack/observability/ingesting-data/sdks/browser)를 확인하십시오.
    </Note>

    브라우저 SDK는 기본적으로 입력값과 텍스트를 마스킹합니다. 개인정보 보호가 중요한 애플리케이션은 [개인정보 보호 제어](/ko/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy)를 참조하십시오. 또한 UI에서 사용자별로 세션을 검색하고 필터링하려면 [사용자 정보 연결](/ko/clickstack/observability/ingesting-data/sdks/browser#users-and-errors)을 참조하십시오.

    <Note>
      ClickStack Browser SDK는 표준 `session.id` 속성을 사용합니다. 세션(Sessions) 페이지에서 이 속성을 지원하는 버전의 ClickStack을 사용하십시오. 자세한 내용은 [SDK 호환성 요구 사항](https://github.com/ClickHouse/clickstack-browser#clickstack-versions)을 참조하십시오.
    </Note>

### 세션 데이터가 저장되는 방식 {#data-storage}

    <Note>
      이 저장소 관련 세부 사항은 자체 관리형 ClickHouse Observability에만 적용됩니다. 완전 관리형 서비스에서는 세션 리플레이 저장소와 스키마(schemas)를 자동으로 관리하므로 별도로 구성할 필요가 없습니다.
    </Note>

    세션 리플레이 데이터는 로그 및 trace와 분리되어 ClickHouse의 전용 [`hyperdx_sessions`](/ko/clickstack/self-configured/ingesting-data/schemas#sessions) 테이블에 저장됩니다. 각 세션 이벤트는 이벤트 payload를 담는 `Body` 필드와 이벤트 메타데이터를 저장하는 `LogAttributes` 맵으로 구성된 하나의 행입니다. `Body` 컬럼과 `LogAttributes` 컬럼에는 리플레이 재구성에 사용되는 실제 세션 이벤트의 세부 정보가 함께 저장됩니다.

    전체 테이블 스키마(table schema) 정보는 [테이블 및 스키마](/ko/clickstack/self-configured/ingesting-data/schemas)를 참조하십시오.
  </Tab>
</Tabs>

### 세션에서 트레이스로 {#session-to-trace}

세션 타임라인에서 네트워크 요청이나 오류를 선택한 후 **Trace** 탭으로 이동하면 백엔드 서비스 전반에서 해당 요청을 추적할 수 있습니다. 이를 통해 해당 사용자 상호작용으로 트리거된 관련 로그, 스팬, 데이터베이스 쿼리를 확인할 수 있습니다.

이는 `traceOrigins` 구성이 `traceparent` 헤더를 통해 브라우저 스팬을 서버 스팬에 연결하기 때문에 가능합니다. 그 결과 사용자의 클릭부터 데이터베이스까지 하나로 이어지는 분산 트레이스가 생성됩니다. 프론트엔드와 백엔드를 모두 계측하는 방법을 포함한 실제 적용 과정은 [OpenTelemetry와 ClickStack으로 NextJS 애플리케이션 계측하기](https://clickhouse.com/blog/instrumenting-your-app-with-otel-clickstack)를 참조하십시오.

### 트레이스에서 세션으로 {#trace-to-session}

이 연관 관계는 반대 방향으로도 활용할 수 있습니다. **검색** 뷰에서 트레이스를 클릭하여 트레이스 상세 정보를 연 다음 **세션 리플레이** 탭을 선택하면, 해당 트레이스 시점에 사용자가 실제로 겪은 상황을 정확히 확인할 수 있습니다. 이 기능은 오류나 느린 요청을 조사할 때 특히 유용합니다. 백엔드 문제에서 출발하여 곧바로 사용자 관점에서 상황을 파악할 수 있기 때문입니다.

## 직접 사용해 보기 {#try-it-out}

[세션 리플레이 데모](/ko/clickstack/observability/example-datasets/session-replay)의 안내에 따라 대화형 애플리케이션을 계측하고, 세션 데이터를 ClickHouse Observability 서비스로 전송한 다음, 사용자 상호작용을 재생해 보십시오.
