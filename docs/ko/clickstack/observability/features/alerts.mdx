ClickHouse Observability는 알림 기능을 기본으로 지원하므로, 팀은 로그, 메트릭, 트레이스 전반에서 문제를 실시간으로 감지하고 대응할 수 있습니다.

알림은 사용자 인터페이스에서 직접 생성할 수 있으며, Slack, PagerDuty 등 널리 사용되는 알림 시스템과 연동됩니다.

알림 기능은 모든 관측성 데이터에서 매끄럽게 동작하므로 시스템 상태를 추적하고, 성능 회귀 오류를 조기에 포착하며, 주요 비즈니스 이벤트를 모니터링할 수 있습니다.

## 알림 유형 {#types-of-alerts}

알림은 **저장된 검색**에서 생성하거나, **차트 탐색기**에서 직접 생성하거나, **저장된 대시보드의 차트**에서 생성할 수 있습니다. 검색 알림은 조건에 일치하는 이벤트 수를 집계하고, 차트 알림은 차트에서 계산된 값을 평가합니다.

### 검색 알림 {#search-alerts}

검색 알림을 사용하면 저장된 검색의 결과를 기반으로 알림을 트리거할 수 있습니다. 검색 알림은 특정 이벤트나 패턴이 예상보다 더 자주(또는 덜 자주) 발생하는 상황을 감지하는 데 유용합니다.

정의된 시간 윈도우(time window) 내에서 일치하는 결과의 수가 지정된 임계값을 초과하거나 그 아래로 떨어지면 알림이 트리거됩니다.

검색 알림을 생성하는 방법은 다음과 같습니다.

검색에 대한 알림을 생성하려면 해당 검색이 저장되어 있어야 합니다. 기존의 저장된 검색에 알림을 생성하거나, 알림 생성 과정에서 검색을 저장할 수 있습니다. 아래 예시에서는 검색이 저장되지 않은 상태라고 가정합니다.

<Steps>
  <Step title="알림 생성 대화 상자 열기" id="open-dialog">
    먼저 [검색](/ko/clickstack/observability/features/search)을 입력한 후 `Search` 페이지 오른쪽 상단의 `Alerts` 버튼을 클릭하세요.

    <div className="ch-image-lg">
      <Frame>
        ![알림 버튼이 강조 표시된 검색 뷰](/images/clickstack/observability-alerts-search.png)
      </Frame>
    </div>
  </Step>

  <Step title="알림 생성" id="create-the-alert">
    알림 생성 패널에서 다음 작업을 수행할 수 있습니다.

    * 알림과 연결된 저장된 검색의 이름을 지정합니다.
    * 비교 연산자, 일치하는 이벤트 수, 시간 윈도우를 선택합니다. 예를 들어 5분 내에 일치하는 이벤트가 10개 이상 발생하면 트리거되도록 설정할 수 있습니다.
    * `grouped by` 값을 지정합니다. 이를 통해 `ServiceName` 등을 기준으로 검색 결과를 집계할 수 있으므로, 하나의 검색에서 여러 알림이 트리거되도록 할 수 있습니다.
    * 이메일 또는 웹훅과 같은 알림 대상을 선택합니다. 이 뷰에서 바로 새 웹훅을 추가할 수 있습니다. 자세한 내용은 [웹훅 추가](#add-webhook)를 참조하십시오.

    저장하기 전에 인터페이스에 임계값 조건이 시각화되어 표시되므로, 알림이 예상대로 동작하는지 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![정적 임계값, ServiceName 그룹화, 웹훅 대상이 설정된 검색 알림 구성](/images/clickstack/observability-search-alert.png)
      </Frame>
    </div>
  </Step>
</Steps>

하나의 검색에 여러 알림을 추가할 수 있습니다. 위 과정을 반복하면 알림 편집 대화 상자 상단에 기존 알림이 탭으로 표시되며, 각 알림에는 번호가 부여됩니다.

  </Frame>
</div>

### 차트 탐색기 알림 {#chart-explorer-alerts}

[차트 탐색기](/ko/clickstack/observability/features/dashboards/overview#navigate-chart-explorer)에서 직접 알림을 생성하면 차트를 대시보드에 추가하지 않고도 모니터링할 수 있습니다.

<Steps>
  <Step title="차트 작성" id="build-explorer-alert-chart">
    사이드바에서 **차트 탐색기**를 선택하고 **Time Series** 차트 유형을 사용하십시오. 데이터 소스를 선택한 후 모니터링할 집계, 필터, 그룹화를 구성하십시오. 예를 들어 오류 로그 수를 집계하고 `ServiceName` 기준으로 그룹화하면 서비스별로 개별 평가할 수 있습니다.

    알림을 구성하기 전에 **Run**을 선택하여 결과를 확인하십시오.
  </Step>

  <Step title="알림 구성" id="configure-explorer-alert">
    **Add alert**를 선택합니다. **Static threshold** 알림은 다음 항목을 구성하십시오.

    * **Trigger when value**: 비교 연산자와 임계값을 선택합니다.
    * **over**: 5분 등 평가할 시간 윈도우(time window)를 선택합니다.
    * **Name**: 알림 내용을 알 수 있는 이름을 지정합니다.
    * **Send to**: 이메일 또는 웹훅 대상을 선택합니다. 웹훅을 생성하려면 [웹훅 추가](#add-webhook)를 참조하십시오.

    태그와 메모를 추가하여 알림에 대한 부가 정보를 제공할 수도 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![로그 수 차트와 임계값, 이름, 알림 대상, Create alert 컨트롤이 표시된 알림 패널이 있는 차트 탐색기](/images/clickstack/observability-chart-explorer-alert.png)
      </Frame>
    </div>
  </Step>

  <Step title="알림 생성 및 관리" id="create-explorer-alert">
    **Create alert**를 선택하여 알림을 저장합니다. 대시보드를 먼저 저장할 필요는 없습니다.

    사이드바에서 **알림**을 열고 알림을 선택하면 조건, 알림 대상, 차트, 평가 이력 등 세부 정보를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![알림 상태, 임계값, 평가 인터벌, 알림 대상, 차트, 평가 이력을 보여 주는 차트 탐색기 알림 상세 페이지](/images/clickstack/observability-chart-explorer-alert-details.png)
      </Frame>
    </div>
  </Step>
</Steps>

### 대시보드 차트 알림 {#dashboard-alerts}

대시보드 알림을 사용하면 차트에도 알림을 설정할 수 있습니다.

저장된 대시보드에서 차트 기반 알림을 바로 생성할 수 있으며, 전체 SQL 집계(aggregations)와 ClickHouse 함수를 활용해 고급 계산을 수행할 수 있습니다.

메트릭이 정의된 임계값을 넘으면 알림이 자동으로 트리거되므로, KPI, 지연 시간 등 주요 메트릭을 지속적으로 모니터링할 수 있습니다.

<Note>
  대시보드의 시각화에 알림을 생성하려면 먼저 해당 대시보드를 저장해야 합니다.
</Note>

대시보드 알림을 추가하는 방법은 다음과 같습니다.

알림은 차트를 생성하는 과정이나 대시보드에 차트를 추가할 때 생성할 수 있으며, 기존 차트에 추가할 수도 있습니다. 아래 예시에서는 차트가 이미 대시보드에 있다고 가정합니다.

<Steps>
  <Step title="차트 편집 대화 상자 열기" id="open-chart-dialog">
    차트 도구 모음에서 **Add alert** 종 아이콘을 클릭하여 차트 편집 대화 상자를 엽니다.

    <div className="ch-image-lg">

        ![Add alert 버튼이 강조 표시된 대시보드 차트](/images/clickstack/observability-dashboard-add-alert.png)
      </Frame>
    </div>
  </Step>

  <Step title="알림 추가" id="add-chart-alert">
    **Add alert**를 선택합니다.

    <div className="ch-image-lg">
      <Frame>
        ![Add alert 버튼이 강조 표시된 차트 편집기](/images/clickstack/observability-chart-editor-add-alert.png)

    </div>
  </Step>

  <Step title="알림 조건 정의" id="define-alert-conditions">

    <div className="ch-image-lg">

  </Step>
</Steps>

## 웹훅 추가 {#add-webhook}

알림을 생성할 때 기존 웹훅을 사용하거나 새 웹훅을 생성할 수 있습니다. 한 번 생성한 웹훅은 다른 알림에서도 재사용할 수 있습니다.

웹훅은 Slack, PagerDuty 등 다양한 서비스 유형은 물론 범용 대상에 대해서도 생성할 수 있습니다.

알림 패널에서 **Add New Incoming Webhook**을 선택하여 알림 대상을 생성하십시오.

<div className="ch-image-lg">
  <Frame>
    ![Add New Incoming Webhook이 강조 표시된 알림 패널](/images/clickstack/observability-add-new-webhook.png)
  </Frame>
</div>

웹훅 생성 대화 상자가 열리며, 여기에서 새 웹훅을 생성할 수 있습니다.

<div className="ch-image-md">
  <Frame>
    ![서비스 유형, 이름, URL, 설명 필드가 있는 Add New Webhook 대화 상자](/images/clickstack/observability-add-webhook-dialog.png)
  </Frame>
</div>

웹훅 이름은 필수이며 설명은 선택 사항입니다. 그 밖에 입력해야 하는 설정은 서비스 유형에 따라 다릅니다.

지원되는 알림 서비스는 [서비스 유형별 통합](#integrations)을 참조하십시오.

### 서비스 유형별 통합 {#integrations}

알림은 별도 설정 없이 다음 서비스 유형과 통합됩니다.

* **Slack**: 웹훅 또는 API를 통해 채널로 알림을 직접 전송합니다.
* **PagerDuty**: PagerDuty API를 통해 온콜 팀에 인시던트를 라우팅합니다.
* **incident.io**: incident.io로 알림을 전송합니다.
* **Generic**: 범용 웹훅을 통해 알림을 사용자 정의 시스템이나 워크플로에 연결합니다.

<Info>
  **ClickHouse Cloud 전용 통합**

  Slack API 및 PagerDuty 통합은 ClickHouse Cloud에서만 지원됩니다.
</Info>

서비스 유형에 따라 입력해야 하는 세부 정보가 다르며, 구체적인 내용은 다음과 같습니다.

**Slack (Webhook URL)**

* 웹훅 URL. 예시: `https://hooks.slack.com/services/<unique_path>`. 자세한 내용은 [Slack 문서](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)를 참조하십시오.

**Slack (API)**

* Slack 봇 토큰. 자세한 내용은 [Slack 문서](https://docs.slack.dev/authentication/tokens/#bot/)를 참조하십시오.

**PagerDuty API**

* PagerDuty 통합 키. 자세한 내용은 [PagerDuty 문서](https://support.pagerduty.com/main/docs/api-access-keys)를 참조하십시오.

**Generic**

* 웹훅 URL
* 웹훅 헤더(선택 사항)
* 웹훅 body(선택 사항). body는 Handlebars 템플릿입니다. `{{title}}`, `{{body}}`, `{{link}}` 외에도 `{{alertId}}`, `{{status}}`, `{{value}}`, `{{threshold}}`, `{{groupKey}}` 등 알림 및 알림 발생 정보를 나타내는 변수를 사용할 수 있습니다. 전체 목록은 [알림 웹훅 템플릿 변수](https://github.com/ClickHouse/ClickStack/blob/main/docs/alert-webhook-template-variables.md)를 참조하십시오.

## 알림 관리 {#managing-alerts}

알림을 관리하려면 왼쪽 사이드바에서 **알림**을 선택하십시오. 이름으로 검색하거나 상태, 소스, 유형별로 필터링할 수 있습니다.

<div className="ch-image-lg">
  <Frame>
    ![사이드바에서 알림이 강조 표시된 알림 관리 페이지](/images/clickstack/observability-manage-alerts.png)
  </Frame>
</div>

이 화면에는 알림 평가 이력도 표시됩니다. 알림은 일정한 시간 간격(알림 생성 시 설정한 주기/소요 시간)마다 반복적으로 평가됩니다. 평가할 때마다 서비스는 데이터를 쿼리하여 알림 조건이 충족되었는지 확인합니다.

* **빨간색 막대**: 해당 평가에서 임계값 조건이 충족되어 알림이 발생했습니다(알림 전송됨).
* **녹색 막대**: 알림이 평가되었지만 임계값 조건이 충족되지 않았습니다(알림 전송 안 됨).

각 평가는 독립적으로 수행됩니다. 알림은 해당 시간 윈도우(time window)의 데이터를 확인하며, 그 시점에 조건이 참인 경우에만 발생합니다.

위 예시에서 **Alert 1**은 **OK** 상태이며, 녹색 막대는 임계값 조건이 충족되지 않은 최근 평가 결과를 나타냅니다.

알림을 선택하면 조건, 알림 대상, 평가 이력 등을 확인할 수 있는 상세 페이지가 열립니다.

### 알림 삭제 {#deleting-alerts}

차트 알림을 삭제하려면 차트 편집기를 열고 **Edit alert**를 선택하십시오. 그런 다음 알림 패널 오른쪽 상단의 휴지통 아이콘을 클릭하십시오.

## SQL 기반 차트 알림 {#sql-based-alerts}

SQL 기반 차트 알림에서는 임의의 ClickHouse SQL을 작성하여 알림 조건을 정의할 수 있습니다. 필터링, 집계, 수식 연산을 모두 직접 제어할 수 있으므로 SQL로 표현할 수 있는 것이라면 무엇이든 알림으로 만들 수 있습니다.

### 지원되는 차트 유형 {#supported-chart-types}

SQL 기반 알림은 다음 3가지 차트 표시 유형에서 지원됩니다.

| 차트 유형           | 동작                                                                           |
| --------------- | ---------------------------------------------------------------------------- |
| **선**        | 시계열 알림입니다. 쿼리는 시간 버킷 단위로 구분된 행(rows)을 반환해야 합니다. 각 버킷은 개별적으로 임계값과 비교하여 평가됩니다. |
| **Stacked Bar** | 시계열 알림입니다. 선과 동일하게 동작합니다.                                                 |
| **Number**      | 단일 값 알림입니다. 쿼리는 단일 숫자 결과를 반환하며, 이 결과는 평가할 때마다 한 번씩 임계값과 비교됩니다.               |

그 밖의 SQL 기반 차트 유형(Table, Pie, Heatmap 등)은 알림을 지원하지 않습니다.

### 쿼리 결과(query results) 해석 방식 {#sql-result-interpretation}

알림 시스템은 SQL 쿼리(SQL query)가 반환하는 컬럼을 검사하여 임계값과 비교할 대상을 결정합니다.

* **값 컬럼**: `SELECT` 절의 **마지막 숫자형 컬럼**이 알림 값으로 사용됩니다. 쿼리가 여러 숫자형 컬럼(예: `count, avg_latency, p99_latency`)을 반환하면 마지막 컬럼(`p99_latency`)만 임계값과 비교됩니다.
* **타임스탬프 컬럼**: 시계열 차트(선 및 Stacked Bar)에서는 결과에 포함된 Date/DateTime 컬럼을 시간 버킷(time bucket)(즉, 시계열 차트의 x축)으로 인식합니다. 각 시간 버킷의 값 컬럼은 임계값과 개별적으로 비교되며, 어느 한 시간 버킷의 값이라도 구성된 임계값을 초과하면 알림이 트리거됩니다.
* **그룹 컬럼**: 숫자형도 타임스탬프도 아닌 컬럼(예: `ServiceName`, `Environment`)은 모두 그룹화 차원(dimensions)으로 처리됩니다. 그룹이 있으면 중복 없는 그룹 값 조합별로 각각 추적하고 알림을 발생시킵니다. 서비스는 값이 구성된 임계값을 초과하는 그룹마다 알림을 전송합니다. 그룹은 시계열 차트에서만 사용할 수 있습니다.

### 쿼리 매개변수와 매크로 {#query-params}

SQL 알림 쿼리는 평가 시점에 자동으로 대체되는 템플릿 매개변수와 매크로를 지원합니다. 이는 [SQL 기반 차트를 만들](/ko/clickstack/observability/features/dashboards/sql-visualizations) 때 사용할 수 있는 매개변수 및 매크로와 동일합니다.

#### 필수 및 권장 매개변수 {#required-alert-parameters}

선 차트 또는 누적 막대 차트 알림에 사용하는 쿼리에는 주기 매개변수 또는 매크로(`{intervalSeconds:Int64}`, `{intervalMilliseconds:Int64}`, `$__timeInterval(col)` 또는 `$__timeInterval_ms(col)`)가 **반드시** 포함되어야 합니다. 알림 실행 시 이 값은 알림에 구성된 주기로 대체됩니다.

알림에 사용하는 쿼리에는 시간 범위 필터(filter)(`{startDateMilliseconds:Int64}` 및 `{endDateMilliseconds:Int64}`, 또는 `$__timeFilter(col)` 등)를 포함하는 것이 **좋습니다**. 쿼리에 시간 범위 필터가 있는지와 관계없이 알림 쿼리는 알림에 구성된 주기에 따라 실행됩니다. 시간 범위 필터가 없으면 쿼리는 실행될 때마다 원본 테이블의 전체 시간 범위를 읽습니다.

<Warning>
  **알림 시간 범위**

  일반적으로 알림 쿼리는 인터벌마다 한 번씩 실행됩니다. 그러나 오류나 느린 쿼리로 인해 하나 이상의 인터벌을 건너뛰면, 다음 실행에서는 누락된 인터벌까지 포함하는 시간 범위가 사용됩니다. 이때 쿼리의 시간 간격 매개변수는 그대로 알림에 구성된 주기로 설정되지만, 시간 범위 매개변수에는 더 긴 시간 범위가 반영됩니다.
</Warning>

### 알림 쿼리 예시 {#example-queries}

#### 서비스별 오류율(시계열) {#example-error-rate}

서비스 중 하나라도 오류율이 5% 이상이고 알림 주기 동안 요청이 10건을 초과하면 알림을 보냅니다. 요청 건수 조건을 두면 트래픽이 적은 서비스에서 불필요한 알림이 과도하게 발생하는 것을 방지할 수 있습니다.

```sql
WITH error_rates AS (
  SELECT
    $__timeInterval(Timestamp) as ts,
    ServiceName,
    countIf (SpanKind = 'Server') as request_count,
    countIf (
      SpanKind = 'Server'
      and StatusCode = 'Error'
    ) as error_count,
    error_count / request_count * 100 AS error_percent
  FROM $__sourceTable
  WHERE $__timeFilter(Timestamp)
  GROUP BY ts, ServiceName
)
SELECT ts, ServiceName, error_percent
FROM error_rates
WHERE request_count > 10
```

**표시 유형**: 선 또는 Stacked Bar
**임계값**: `>= 5` (오류율이 5%에 도달하면 알림이 발생합니다)

이 쿼리에서 `ServiceName`은 숫자형도 타임스탬프도 아닌 컬럼이므로 각 서비스가 별도의 알림 그룹으로 추적됩니다. 알림은 서비스마다 독립적으로 발생합니다.

#### 후행 평균을 이용한 이상 탐지(시계열) {#example-anomaly-detection}

오류 발생 횟수가 이동 평균보다 표준편차의 2배 넘게 높으면 알림을 보냅니다. 이 방식은 고정 임계값이 아니라 최근 기준값을 기준으로 급증을 감지합니다.

```sql
WITH buckets AS (
  SELECT
    $__timeInterval(Timestamp) AS ts,
    count() AS bucket_count
  FROM $__sourceTable
  WHERE TimestampTime >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
        - toIntervalSecond($__interval_s * 30) -- Fetch 30 intervals back
    AND TimestampTime < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
    AND SeverityText = 'error'
  GROUP BY ts
  ORDER BY ts
  WITH FILL
    FROM toDateTime(fromUnixTimestamp64Milli({startDateMilliseconds:Int64}))
    TO toDateTime(fromUnixTimestamp64Milli({endDateMilliseconds:Int64}))
    STEP toIntervalSecond($__interval_s)
),

anomaly_detection AS (
  SELECT
    ts,
    bucket_count,
    avg(bucket_count) OVER (
      ORDER BY ts ROWS BETWEEN 30 PRECEDING AND 1 PRECEDING
    ) AS previous_30_avg,
    stddevPop(bucket_count) OVER (
      ORDER BY ts ROWS BETWEEN 30 PRECEDING AND 1 PRECEDING
    ) AS previous_30_stddev,
    greatest(
      bucket_count - (previous_30_avg + 2 * previous_30_stddev), 0
    ) AS excess_error_count
  FROM buckets
)

SELECT ts, excess_error_count
FROM anomaly_detection
WHERE ts >= fromUnixTimestamp64Milli({startDateMilliseconds:Int64})
  AND ts < fromUnixTimestamp64Milli({endDateMilliseconds:Int64})
```

**표시 유형**: 선
**임계값**: `> 0` (이동 기준값을 초과하는 오류가 감지되면 알림이 발생합니다)

이 쿼리는 이동 윈도우 계산의 초기값을 확보하기 위해 날짜 범위 시작 시점 *이전*의 30개 인터벌까지 함께 가져온 다음, 최종 출력에는 평가 윈도우에 해당하는 결과만 남도록 필터링합니다.

## 일반적인 알림 시나리오 {#common-alert-scenarios}

다음은 구성할 수 있는 일반적인 알림 시나리오입니다.

**오류:** 오류가 과도하게 발생할 때 알림을 받을 수 있도록 기본 제공되는
`All Error Events` 및 `HTTP Status >= 400` 저장된 검색에 알림을 설정할 것을 권장합니다.

**느린 연산(Operations):** 느린 연산을 찾는 검색(예:
`duration:>5000`)을 설정한 다음, 느린 연산이 과도하게 발생하면
알림이 전송되도록 구성할 수 있습니다.

**사용자 이벤트:** 신규 사용자가 가입하거나 중요한 사용자 작업이 수행될 때
고객 대응 팀이 알림을 받도록 설정할 수도 있습니다.
