지연 시간이나 오류가 급증하면 대개 가장 먼저 새로 배포된 것이 있는지부터 확인하게 됩니다. 대시보드 시계열 차트에서는 이를 바로 확인할 수 있습니다. 릴리스 마커를 활성화하면 각 타일에서 서비스의 특정 버전이 텔레메트리에 처음 나타난 시점에 점선 세로선이 표시됩니다.

버전 정보는 이미 전송 중인 텔레메트리에서 타일 소스에 구성된 표현식을 통해 읽어 옵니다. 따라서 CI 통합을 따로 연결하거나 배포 시점에 별도의 데이터를 푸시할 필요가 없습니다.

## 표식 켜기 {#turn-on}

릴리스 마커는 기본적으로 꺼져 있습니다. 대시보드의 오버플로 메뉴를 열고 **Show release markers**를 선택하십시오.

<div className="ch-image-sm">
  <Frame>
    ![View 섹션의 Show alert annotations 아래에 Show release markers 항목이 표시된 대시보드 오버플로 메뉴](/images/clickstack/dashboards/release-markers-menu.webp)
  </Frame>
</div>

이 토글을 켜면 대시보드 URL에 `releaseMarkers=true`가 추가되므로, 공유한 링크를 열면 표식이 이미 켜진 상태로 표시됩니다. 이 설정은 대시보드 구성이 아니라 뷰 상태입니다. 따라서 대시보드와 함께 저장되지 않으며, 토글을 끄면 해당 매개변수도 다시 제거됩니다.

표식은 소스가 로그 소스 또는 트레이스 소스인 시계열 타일에 표시됩니다. [알림 어노테이션](/ko/clickstack/observability/features/alerts)도 같은 메뉴에서 켤 수 있으며, 릴리스 마커와 동시에 표시할 수 있습니다. 이 경우 두 종류의 표식이 함께 그려지며, 각각 고유한 레이블이 그대로 유지됩니다.

## 버전을 가져올 위치 구성 {#version-expression}

기본적으로 ClickHouse Observability는 OpenTelemetry 리소스 속성인 `ResourceAttributes['service.version']`을 읽습니다. 서비스가 [서비스 리소스 시맨틱 컨벤션(semantic conventions)](https://opentelemetry.io/docs/specs/semconv/registry/attributes/service/)을 따른다면 별도 설정 없이 표식이 작동합니다.

다른 위치에서 버전을 읽으려면 로그 또는 트레이스 소스에서 **Service Version Expression**을 설정하십시오. 소스는 **Team Settings → Sources**에서 편집할 수 있습니다. 로그 소스에서는 이 필드가 **Configure Optional Fields** 아래에 있고, 트레이스 소스에서는 양식의 **Service Name Expression** 바로 아래에 표시됩니다.

<div className="ch-image-lg">
  <Frame>
    ![로그 소스의 선택 필드에 있는 Service Version Expression 필드로, 기본 플레이스홀더 ResourceAttributes\['service.version'\]이 표시됨](/images/clickstack/dashboards/service-version-expression.webp)
  </Frame>
</div>

이 값은 속성 이름이 아니라 SQL 표현식(SQL expression)이므로, 다음과 같은 두 가지 일반적인 경우에 대응할 수 있습니다.

* **릴리스 식별자가 다른 속성에 있는 경우.** GitOps 환경에서는 보통 컨테이너 이미지 태그로 릴리스를 식별하며, 이 값은 `container.image.tag`로 전달됩니다. 소스가 `ResourceAttributes['container.image.tag']`를 참조하도록 지정하는 편이 플릿 전체의 instrumentation을 변경하는 것보다 비용이 훨씬 적게 듭니다.
* **같은 테이블 안의 서비스들이 서로 다른 속성을 사용하는 경우.** `coalesce`를 사용해 여러 속성을 차례로 확인하여 폴백되도록 하십시오.

```sql
coalesce(
  nullIf(ResourceAttributes['service.version'], ''),
  nullIf(ResourceAttributes['container.image.tag'], '')
)
```

이 필드는 [소스 API](/ko/clickstack/observability/api-reference)에서도 로그 및 트레이스 소스의 `serviceVersionExpression`으로 제공되므로, 프로그래밍 방식으로 소스를 프로비저닝할 때 이 값을 설정할 수 있습니다. 자가 관리형 배포에서는 [로그](/ko/clickstack/self-configured/managing/config#logs) 및 [트레이스](/ko/clickstack/self-configured/managing/config#traces) 소스 설정의 전체 목록을 참고하십시오.

## 표식의 의미 {#what-a-marker-means}

표식은 화면에 표시된 윈도우 범위 안에서 특정 버전 값이 타일의 데이터에 처음 나타났음을 기록합니다. 이는 배포와 비슷하지만 의도적으로 같은 의미로 보지 않으며, 그래서 배포 마커가 아니라 릴리스 마커라고 부릅니다.

* 버전 문자열이 바뀌지 않는 배포에서는 표식이 전혀 생성되지 않습니다.
* 조회 기간(lookback)보다 오래 유휴 상태였던 서비스는 다시 스케일 업될 때 표식이 그려집니다.

윈도우가 시작될 때 이미 실행 중이던 버전은 실제로 일어나지 않은 릴리스로 그려지지 않도록 식별되어 제외됩니다. 이를 위해 쿼리는 윈도우 시작 시점보다 30분 또는 윈도우 길이의 10% 중 더 긴 기간만큼 앞으로 거슬러 올라가 기존 버전을 찾습니다.

## 타일에 표시되는 릴리스 {#scoping}

릴리스 쿼리는 타일 자체의 소스를 대상으로 실행되며, 타일 자체의 프레디케이트, 즉 `WHERE` 절, 각 시계열의 필터, 그리고 모든 [대시보드 필터](/ko/clickstack/observability/features/dashboards/overview#custom-filters)가 적용됩니다. 타일에 표시되는 표식은 타일이 차트로 나타내는 대상에 따라 달라집니다.

| 타일               | 표식                                               |
| :--------------- | :----------------------------------------------- |
| 하나의 서비스로 필터링된 타일 | 해당 서비스의 릴리스                                      |
| 서비스별로 그룹화된 타일    | 차트에 표시된 모든 서비스의 릴리스(각 표식은 해당 서비스의 선과 같은 색상으로 표시) |
| 여러 서비스에 걸친 집계 선  | 없음(시간 범위 내 모든 릴리스가 하나의 서비스에서 나온 경우는 예외)          |

세 번째 경우에는 표식의 서비스에 대응하는 선이 차트에 없으므로 표식이 표시되지 않습니다. 단, 시간 범위 내 모든 릴리스가 단일 서비스에서 나온 경우에는 기본 표식 색상으로 표식이 표시됩니다.

## 복잡한 차트에서 마커 읽기 {#reading-markers}

마커의 레이블에 마우스를 올리면 해당 지점의 모든 릴리스가 나열되며, 각 릴리스를 배포한 서비스와 버전, 시간이 함께 표시됩니다.

<div className="ch-image-sm">
  <Frame>
    ![두 서비스의 차트에서 릴리스 마커에 마우스를 올렸을 때 서비스 frontend, 버전 2.0.2, 해당 버전이 처음 나타난 시간을 표시하는 도구 설명](/images/clickstack/dashboards/release-marker-tooltip.webp)
  </Frame>
</div>

마커는 색상으로 해당 시계열과 연결되지만, 차트 범례는 항목을 최대 4개까지만 표시하고 나머지는 &quot;+N more&quot; 뒤로 접어 둡니다. 이렇게 되면 화면에서 색상을 대조할 기준이 사라집니다. 도구 설명은 서비스 이름을 직접 보여 주므로 타일에 표시되는 시계열이 몇 개이든 상관없이 활용할 수 있습니다.

간격이 너무 좁아 개별적으로 레이블을 붙일 수 없는 마커는 `N releases`라는 레이블이 붙은 하나의 앵커로 축약되며, 여기에 마우스를 올리면 포함된 릴리스가 모두 표시됩니다. 여러 서비스에 걸친 클러스터는 특정 서비스의 색상 대신 중립적인 색상으로 표시되므로, 특정 소유자를 암시하지 않으면서도 개수를 정확하게 나타냅니다.

마커가 표시된 상태에서도 플롯을 가로로 드래그하여 확대할 수 있습니다.

## 제한 사항 {#limitations}

* **시계열 타일에서만 지원됩니다.** 테이블, 숫자, 히트맵 타일에는 표식이 표시되지 않습니다.
* **로그 및 트레이스 소스에서만 지원됩니다.** 메트릭 소스는 메트릭 유형별로 테이블을 결정하므로 다시 집계할 단일 테이블이 없으며, 타일의 필터를 해당 소스에 의미 있게 적용할 방법도 없습니다. 메트릭 데이터에 주석을 표시하려면 같은 대시보드에 로그 또는 트레이스 타일을 함께 배치하십시오.
* **비어 있는 버전 값은 건너뜁니다.** 버전을 내보내지 않는 서비스에는 표식이 생성되지 않습니다. 타일에서 버전 변경을 하나도 찾지 못하면 기능이 고장 난 것인지 혼란스럽지 않도록 UI에 `No releases found`가 표시됩니다.
* 윈도우당 **최대 500개의 고유 버전**을 읽습니다.
