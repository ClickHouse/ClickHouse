ClickHouse Observability는 이벤트 시각화를 지원하며, UI에서 차트를 만드는 기능을 기본으로 제공합니다. 이렇게 만든 차트를 대시보드에 추가하면 다른 사용자와 공유할 수 있습니다.

시각화는 trace, 메트릭, 로그뿐만 아니라 사용자가 정의한 모든 wide 이벤트 스키마(schemas)를 기반으로 생성할 수 있습니다.

## 시각화 생성 {#creating-visualizations}

**차트 탐색기(Chart Explorer)** 인터페이스를 사용하면 메트릭, trace, 로그를 시간 흐름에 따라 시각화할 수 있으므로 데이터 분석용 시각화를 빠르게 만들 수 있습니다. 이 인터페이스는 대시보드를 생성할 때도 동일하게 사용됩니다. 이 섹션에서는 차트 탐색기를 사용하여 시각화를 생성하는 과정을 설명합니다.

모든 시각화는 **데이터 소스**를 선택하고 이어서 **메트릭**을 선택하는 것으로 시작하며, 필요에 따라 **필터 표현식**과 **그룹화(Group By)** 필드를 지정할 수 있습니다. 개념적으로 시각화는 내부적으로 SQL `GROUP BY` 쿼리에 대응합니다. 즉, 선택한 차원별로 집계할 메트릭을 정의하는 것입니다.

<Tip>
  **AI 기반 차트 및 대시보드 생성**

  ClickHouse Observability는 [Text-to-Chart](/ko/clickstack/observability/text-to-chart) 기능을 통해 자연어 프롬프트로 차트를 생성하는 기능도 지원합니다. 보고 싶은 내용을 설명하면 UI가 시각화를 자동으로 생성합니다. 여러 타일로 구성된 대시보드 전체를 생성하려면 [Text-to-Dashboard](/ko/clickstack/observability/text-to-dashboard)를 사용하십시오.
</Tip>

예를 들어, 서비스 이름별 오류 수(`count()`)를 차트로 표시할 수 있습니다.

아래 예시에서는 [sql.clickhouse.com](https://sql.clickhouse.com)에서 제공하는 원격 데이터셋을 사용합니다. **[play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com)에 접속하여 이 예시를 직접 따라 해 볼 수도 있습니다.**

      이처럼 통합된 방식 덕분에 일관되고 유연한 모델로 여러 텔레메트리 타입을 아우르는 대시보드를 구축할 수 있습니다.
    </Note>
  </Step>
</Steps>

## 대시보드 생성 {#creating-dashboards}

대시보드를 사용하면 관련 시각화를 하나로 묶어 메트릭을 비교하고 패턴을 나란히 탐색하면서 시스템 문제의 잠재적인 근본 원인을 파악할 수 있습니다. 대시보드는 애드혹(ad-hoc) 조사에 활용하거나, 저장해 두고 지속적인 모니터링에 사용할 수 있습니다.

Global Filters는 대시보드 수준에서 적용할 수 있으며, 해당 대시보드의 모든 시각화에 자동으로 전파됩니다. 이를 통해 여러 차트에서 일관된 drill-down이 가능하고, 서비스와 텔레메트리 타입 전반의 이벤트 상관 분석이 간편해집니다.

아래에서는 로그 및 트레이스 데이터 소스를 사용하여 두 개의 시각화로 구성된 대시보드를 생성합니다. 이 단계는 [play-clickstack.clickhouse.com](https://play-clickstack.clickhouse.com)에서 따라 하거나, [sql.clickhouse.com](https://sql.clickhouse.com)에 호스팅된 데이터셋에 연결하여 로컬에서 재현할 수 있습니다.

    * Alias: `Count of events`

      </Frame>

  <Step title="스팬 소요 시간을 보여 주는 히트맵 타일을 추가하십시오" id="create-a-tile-heatmap">
    히트맵 타일은 각 (시간, 값) 버킷에 속하는 이벤트 수를 색상 격자로 표시합니다. 평균이나 단일 백분위수가 아니라 시간에 따른 분포의 **형태**를 확인하려면 히트맵을 사용하십시오. 지연 시간 히트맵을 사용하면 Line 차트에서는 평균에 묻혀 사라지는 이중 봉우리(bimodal) 소요 시간 패턴, 느린 꼬리(slow-tail) 클러스터, 갑작스러운 분산 확대 등을 확인할 수 있습니다.

    히트맵 타일을 추가하려면 다음 단계를 따르십시오.

    1. `Add`를 선택합니다.
    2. 상단 메뉴에서 `Heatmap` 시각화 유형을 선택합니다. 데이터 소스 드롭다운에는 [소스 유형이 `Traces`](/ko/clickstack/observability/managing/config#datasource-settings)인 소스만 표시됩니다. 히트맵에는 트레이스 소스에만 있는 스팬 소요 시간 컬럼이 필요하므로 로그, 메트릭, 세션 소스는 목록에서 제외됩니다.
    3. 트레이스 소스 중 하나를 이름으로 선택합니다. 이름은 임의로 지정할 수 있으며, 중요한 것은 유형뿐입니다.

    소스를 선택하면 히트맵에 다음 값이 미리 채워집니다.

    * **Value**: 현재 표시 단위에 맞게 변환된 소스의 `Duration Expression`(예: 각 이벤트의 스팬 소요 시간을 나노초에서 밀리초로 변환하는 `(Duration)/1e6`)
    * **Count**: `count()`

    4. 차트 이름을 설정하고, `Where`를 사용하여 성능을 관찰하려는 특정 서비스 또는 작업 집합으로 히트맵 범위를 좁힙니다.
    5. 관심 있는 기간에 맞게 시간 범위를 조정합니다. 범위를 넓히면 짧은 구간에서는 드러나지 않는 분포 변화와 이중 봉우리 지연 시간 패턴을 확인할 수 있습니다.

    아래 예시는 `payment` 서비스의 스팬 소요 시간을 보여 줍니다. 대부분의 스팬이 1밀리초 부근에 몰려 있고, 그 위쪽에 더 느린 스팬이 흩어져 있습니다.

    히트맵을 더 세부적으로 설정하려면 **Display Settings**를 클릭하여 **Scale**(Log 또는 Linear), **Value**, **Count** 표현식을 설정하는 드로어를 여십시오. 전체 옵션 목록은 Event Deltas 페이지의 [히트맵 사용자 정의](/ko/clickstack/observability/features/event-deltas#customize)에 설명되어 있으며, 동일한 드로어가 사용됩니다.

    `Run`을 클릭하여 차트를 미리 본 다음 `Save`를 클릭하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![ServiceName 필터와 Display Settings 버튼이 있는 payment 서비스 스팬 소요 시간 히트맵 편집기](/images/clickstack/observability-dashboard-heatmap-editor.png)
      </Frame>
    </div>

    저장된 타일은 대시보드에 히트맵으로 렌더링됩니다. 셀 위에 마우스를 올리면 버킷의 최솟값과 최댓값, 이벤트 수를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![payment 스팬 소요 시간 히트맵 타일과 소요 시간 및 이벤트 수를 보여 주는 툴팁이 있는 대시보드](/images/clickstack/observability-dashboard-heatmap-tile.png)
      </Frame>
    </div>

    <Tip>
      **히트맵당 2개의 ClickHouse 쿼리**

      히트맵은 2개의 쿼리를 순차적으로 실행합니다. 먼저 값 범위를 결정하는 작은 **bounds 쿼리**를 실행한 다음, 버킷별 이벤트 수를 집계하는 **heatmap 쿼리**를 실행합니다. 두 쿼리는 편집기의 **Generated SQL**에서 확인하거나 복사할 수 있습니다.
    </Tip>

#### 이벤트 차이(Event Deltas)로 드릴다운 {#heatmap-tile-drilldown}

    렌더링된 히트맵 타일에서 셀을 클릭하면 **View in Event Deltas** 작업이 표시됩니다.

    <div className="ch-image-lg">
      <Frame>
        ![히트맵 셀을 클릭하면 표시되는 View in Event Deltas 작업](/images/clickstack/dashboards/heatmap-tile-drilldown.webp)
      </Frame>
    </div>

    이 작업을 선택하면 타일의 데이터 소스, `Where` 절, 시간 범위가 그대로 적용된 [Event Deltas](/ko/clickstack/observability/features/event-deltas) 뷰가 열립니다. 이 뷰에서는 쿼리를 직접 다시 작성하지 않고도 동일한 분포를 대화형으로 살펴보고, 속성별로 나누어 느린 스팬이 빠른 스팬과 어떻게 다른지 확인하고, 각 셀에 해당하는 개별 스팬을 검사할 수 있습니다.
  </Step>

  <Step title="대시보드 필터링" id="filter-dashboards">
    Lucene 또는 SQL 필터와 시간 범위는 대시보드 수준에서 적용할 수 있으며, 모든 시각화에 자동으로 전파됩니다.

### 타일 표시 설정 {#tile-display-settings}

각 타일에는 값이 렌더링되는 방식을 제어하는 옵션이 모여 있는 **표시 설정** 드로어가 있습니다. 타일 편집기에서 **표시 설정**을 클릭하면 열 수 있습니다. 사용 가능한 옵션은 시각화 유형에 따라 다릅니다.

#### 숫자 타일 색상 {#number-tile-color}

숫자 타일에서는 엄선된 차트 팔레트에서 고정 **Color**를 선택할 수 있습니다. 숫자 타일을 선택한 상태에서 **표시 설정**을 열고 **Color** 컨트롤(접근성을 위해 **Number tile color**라는 레이블이 지정됨)에서 색상 견본을 선택하십시오. 선택을 해제하면 기본 텍스트 색상이 사용됩니다.

색상은 원시 16진수 값이 아닌 팔레트 토큰으로 저장되므로, 동일한 타일이 라이트, 다크, IDE 테마 어디에서나 올바르게 다시 렌더링됩니다.

**범주형 토큰** (다중 시계열 색상):

| 토큰                 | 레이블        |
| ------------------ | ---------- |
| `chart-blue`       | Blue       |
| `chart-orange`     | Orange     |
| `chart-red`        | Red        |
| `chart-cyan`       | Cyan       |
| `chart-green`      | Green      |
| `chart-pink`       | Pink       |
| `chart-purple`     | Purple     |
| `chart-light-blue` | Light Blue |
| `chart-brown`      | Brown      |
| `chart-gray`       | Gray       |

**의미론적 토큰** (상태 표시용):

| 토큰              | 레이블     |
| --------------- | ------- |
| `chart-success` | Success |
| `chart-warning` | Warning |
| `chart-error`   | Error   |

숫자가 상태를 나타낼 때는 의미론적 토큰을 사용하십시오(예: 오류 개수에는 `chart-error`, 정상 비율에는 `chart-success`). 상태를 암시하지 않고 관련 KPI 타일을 시각적으로 구분하려면 범주형 토큰을 사용하십시오.

이전 구성에는 레거시 숫자 토큰(`chart-1`~`chart-10`)이 여전히 저장되어 있을 수 있습니다. UI는 대시보드를 로딩할 때 이 토큰을 위의 색상 이름 토큰으로 매핑합니다.

같은 드로어의 선택 사항인 **색상 규칙**에도 동일한 팔레트가 사용됩니다. 색상 규칙은 표시된 값을 기준으로 순서대로 평가되는 조건이며, 마지막으로 일치한 규칙이 적용됩니다. 일치하는 규칙이 없으면 고정 색상이 적용되고, 고정 색상도 없으면 기본 텍스트 색상이 적용됩니다.

#### 숫자 타일 배경 차트 {#number-tile-background-chart}

숫자 타일에는 **배경 차트**를 표시할 수 있습니다. 배경 차트는 값 뒤에 그려지는 추세 스파크라인으로, 선택한 시간 범위 동안 값이 어떻게 변화했는지 한눈에 파악할 수 있습니다. 현재 값 못지않게 추세가 중요한 SLO 및 오류 예산(error budget) 타일에 특히 유용합니다.

숫자 타일을 선택한 상태에서 **표시 설정**을 열고 **Background chart**를 **Line** 또는 **Area**로 설정하십시오(끄려면 **None**으로 설정합니다). 스파크라인은 타일 쿼리를 시간 단위 버킷으로 집계한 결과에서 생성되므로 별도의 구성이 필요하지 않습니다. 기본적으로 타일 색상을 그대로 사용하며, **Background color**를 설정하면 특정 팔레트 색상으로 재정의할 수 있습니다.

<div className="ch-image-lg">
  <Frame>
    ![Background chart가 Area로 설정된 숫자 타일의 표시 설정 드로어](/images/clickstack/dashboards/number-tile-background-chart.webp)
  </Frame>
</div>

배경 차트는 쿼리 빌더로 만든 숫자 타일에 적용됩니다. 원시 SQL(Raw SQL) 숫자 타일은 버킷으로 나눌 시간 차원이 없는 단일 값을 반환하므로, 해당 옵션이 표시되기는 하지만 비활성화되어 있습니다.

테이블 타일에서는 **Alternate Row Background**를 사용하여 행(rows)에 줄무늬 스트라이프를 적용할 수 있습니다. 한 행씩 번갈아 색을 입혀 와이드 테이블(wide tables)을 더 쉽게 훑어볼 수 있습니다. 이 기능은 기본적으로 꺼져 있습니다.

테이블 타일을 선택한 상태에서 **표시 설정**을 열고 **Alternate Row Background**를 켜십시오. 스트라이프는 시각적 효과일 뿐이므로 쿼리 빌더 테이블 타일과 원시 SQL 테이블 타일 모두에서 동작합니다.

<div className="ch-image-lg">
  <Frame>
    ![Alternate Row Background가 켜진 테이블 타일의 표시 설정 드로어](/images/clickstack/dashboards/table-tile-display-settings.webp)
  </Frame>
</div>

또한 테이블 타일은 스크롤하는 동안에도 헤더 행과 데이터 사이의 구분선을 유지하므로 열 머리글(column header)이 명확하게 구분됩니다.

#### 대시보드 API: 숫자 타일 색상 {#api-number-tile-color}

외부 API(`POST` / `PUT` `/api/v2/dashboards`)로 대시보드를 생성하거나 업데이트할 때는 빌더 숫자 타일 구성의 `color`를 팔레트 토큰으로 지정하십시오. 원시 16진수 값은 거부됩니다.

```json
{
  "name": "Error rate KPIs",
  "tiles": [
    {
      "id": "65f5e4a3b9e77c001a222222",
      "name": "Errors",
      "x": 0,
      "y": 0,
      "w": 6,
      "h": 4,
      "config": {
        "displayType": "number",
        "sourceId": "<SOURCE_ID>",
        "select": [
          {
            "aggFn": "count",
            "where": "SeverityText:error",
            "whereLanguage": "lucene",
            "alias": "Errors"
          }
        ],
        "color": "chart-error",
        "backgroundChart": {
          "type": "area"
        }
      }
    }
  ]
}
```

`color`에는 위의 범주형 및 의미론적 목록에 있는 모든 토큰을 사용할 수 있습니다(예: `chart-blue` 또는 `chart-success`). 선택 사항인 `backgroundChart.color`는 동일한 토큰 enum으로 스파크라인 색상을 재정의합니다. 인증 및 기준 URL은 [API 참조](/ko/clickstack/observability/api-reference)를 참고하십시오.

## 대시보드 - 태그 지정 {#tagging}

대시보드와 저장된 검색에 태그를 추가하여 체계적으로 정리할 수 있습니다.
태그를 활용하면 필요에 맞게 유연하게 분류하고 필터링할 수 있습니다.

#### 태그 작동 방식 {#how-tags-work}

* **정리**: 태그는 왼쪽 사이드바에 표시되며, 대시보드와 저장된 검색은 할당된 태그별로 그룹화됩니다
* **여러 태그**: 하나의 항목에 태그를 하나 이상 추가하여 더 세밀하게 분류할 수 있습니다
* **자동 생성**: 아직 없는 태그를 할당하면 해당 태그가 자동으로 생성됩니다
* **간편한 관리**: 언제든지 태그를 추가하거나 제거하여 분류 체계를 조정할 수 있습니다

따라서 항목이 늘어나더라도 관련 항목을 쉽게 찾고 워크스페이스를 체계적으로 유지할 수 있습니다.

대시보드의 **Tags** 메뉴를 열어 태그를 선택하거나 생성하십시오. 아래와 같이 하나의 대시보드에 여러 태그를 할당할 수 있습니다.

## 사용자 지정 필터 및 변수 {#custom-filters}

모든 대시보드에서 사용할 수 있는 [자유 텍스트 필터](#filter-dashboards) 외에도, 저장된 대시보드는 ClickHouse에서 조회한 데이터로 채워지는 사용자 지정 드롭다운 필터를 지원합니다. 이 필터는 클릭만으로 조작할 수 있는 재사용 가능한 필터 컨트롤을 제공하므로, 대시보드 뷰어는 표현식을 직접 작성하지 않고도 필터링할 수 있습니다.

<div className="ch-image-lg">
  <Frame>
    ![사용 가능한 서비스 이름을 보여주는 Services 드롭다운 필터](/images/clickstack/dashboards/filter-dropdown.webp)
  </Frame>
</div>

뷰어는 각 필터에서 하나 이상의 값을 선택할 수 있으며, 필터는 선택된 값으로 다음 중 하나 또는 두 가지 작업을 모두 수행합니다.

* **브로드캐스트** — 선택한 값을 일치하는 타일에 필터 조건(filter condition)으로 적용합니다. 필터를 참조하도록 타일을 수정할 필요가 없습니다.
* **변수** — 선택한 값을 `$variableName` 형태로 타일 쿼리에 노출하며, 값을 어디에서 어떻게 사용할지는 각 타일이 결정합니다.

필터는 두 가지 중 하나 이상을 수행해야 합니다. 필터를 생성하면 브로드캐스트가 기본적으로 활성화됩니다.

</Note>

### 브로드캐스트 {#broadcast-filters}

**Broadcast filter condition**을 활성화하면 각 타일이 필터를 명시적으로 참조하지 않아도 선택한 값이 대시보드의 타일에 필터 조건(filter condition)으로 적용됩니다. 기본적으로 이 조건은 모든 타일에 적용됩니다. **Applies to sources**를 사용하면 지정한 소스를 사용하는 타일로만 적용 범위를 제한할 수 있습니다. 필터의 표현식이 대시보드 데이터 중 일부에만 의미가 있을 때 유용합니다.

차트 빌더 타일에는 브로드캐스트 필터가 자동으로 적용됩니다. 원시 SQL(Raw SQL) 타일의 경우 직접 작성한 쿼리에서 조건이 들어갈 위치를 UI가 추론할 수 없으므로, [`$__filters` 매크로](/ko/clickstack/observability/features/dashboards/sql-visualizations#dashboard-filter-macro)를 포함하고 소스를 선택해야 합니다.

### 변수 {#dashboard-variables}

**Available as variable**을 활성화하면 필터(filter)에서 선택한 값이 타일 쿼리에도 `$variableName` 형태로 제공됩니다. **Variable name**의 기본값은 필터의 표시 이름에서 허용되지 않는 문자를 제거한 값이며, 재정의할 수 있습니다. 이름은 영문자로 시작해야 하며 영문자, 숫자, 밑줄만 포함할 수 있습니다.

`WHERE` 조건을 브로드캐스트하는 방식이 적합하지 않을 때는 변수를 사용하십시오. 예를 들어 값을 `SELECT` 표현식, `HAVING` 절 또는 조인 키에 사용하려는 경우나, 필터 자체의 표현식이 아닌 다른 컬럼을 기준으로 타일을 필터링하려는 경우에 적합합니다.

#### 변수 참조하기 {#referencing-variables}

변수는 해당 드롭다운에서 현재 선택된 값으로 확장됩니다. 참조 형식에 따라 렌더링 방식이 달라집니다.

| 참조                  | 확장 결과                                                                                                        | 선택 항목이 없을 때 |
| ------------------- | ------------------------------------------------------------------------------------------------------------ | ----------- |
| `$name`, `${name}`  | 선택된 값이며, 컨텍스트에 따라 `sqlstring` 또는 `lucene` 포맷이 적용됩니다. `${name}_total`처럼 이름 뒤에 단어 문자가 이어지면 중괄호로 이름의 경계를 구분합니다. | `NULL`      |
| `${name:sqlstring}` | 선택된 값을 작은따옴표로 감싸고 쉼표로 구분한 뒤 SQL 값으로 이스케이프 처리합니다. 예: `'a', 'b'`                                               | `NULL`      |
| `${name:csv}`       | 따옴표 없이 쉼표로 구분합니다: `a,b`. SQL용 이스케이프 처리는 적용되지 않습니다.                                                           | 빈 문자열       |
| `${name:regex}`     | 정규 표현식용으로 이스케이프 처리된 정규 표현식 대안(alternation)입니다: `(a\|b)`.                                                     | `.*`        |
| `${name:lucene}`    | Lucene 입력용으로, 인용 부호로 감싼 항목들을 `OR`로 결합합니다: `("a" OR "b")`.                                                    | `("")`      |

`$name`은 아무것도 선택되지 않은 상태에서 `NULL`로 렌더링되므로, SQL 프레디케이트가 필요한 곳에서는 다음 매크로를 사용하는 것이 좋습니다. 두 매크로 모두 해당 변수에 선택 항목이 없으면 `1=1`로 확장되므로 쿼리가 항상 유효합니다.

| 매크로                                           | 설명                                                                                        |
| --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `$__filter($<variable>)`                      | `variable`에 선택된 값이 있으면 `toString(<filter expression>) IN ($variable)`로, 없으면 `1=1`로 확장됩니다. |
| `$__filter(<expression>, $<variable>)`        | `variable`에 선택된 값이 있으면 `<expression> IN ($variable)`로, 없으면 `1=1`로 확장됩니다.                  |
| `$__conditionalAll(<condition>, $<variable>)` | 변수에 선택 항목이 있으면 `<condition>`으로, 없으면 `1=1`로 확장됩니다.                                         |

#### 차트 빌더 타일에서 변수 사용하기 {#variables-in-builder-tiles}

차트 빌더의 모든 SQL 표현식(SQL expression) 입력에서 변수를 참조할 수 있습니다. 대상은 `SELECT` 컬럼과 시계열별 표현식, `WHERE`, `GROUP BY`, `HAVING`입니다. 편집기는 대시보드의 변수를 자동 완성하며, 현재 선택된 값을 기준으로 각 참조가 어떤 값으로 확장되는지 보여 줍니다.

SQL 모드에서는 변수 선택이 비어 있어도 쿼리가 유효하도록 `$__filter` 및 `$__conditionalAll` 매크로를 사용하는 것이 좋습니다. Lucene 입력에서는 매크로를 사용할 수 없으므로 원시 변수를 직접 참조하십시오(예: `ServiceName:$service`).

Lucene 입력에서는 변수 참조 자체를 인용 부호로 감싸는지에 따라 다중 값 선택의 일치 방식이 달라집니다. 예를 들어 `$service`에서 `a,b`를 선택한 경우는 다음과 같습니다.

| 참조                       | 확장 결과                                  | 일치 방식                                                                       |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------------- |
| `ServiceName:$service`   | `ServiceName:("a" OR "b")`             | 부분 문자열 일치 — SQL에서 `ServiceName ILIKE '%a%' OR ServiceName ILIKE '%b%'`로 변환됨 |
| `ServiceName:"$service"` | `(ServiceName:"a" OR ServiceName:"b")` | 선택된 각 값과 정확한 일치                                                             |

선택된 값이 부분 문자열이 아니라 `Field`와 정확히 일치해야 한다면 변수 참조를 `Field:"$var"`처럼 인용 부호로 감싸십시오.

#### SQL 타일에서 변수 사용하기 {#variables-in-sql-tiles}

원시 SQL(Raw SQL) 타일에서도 같은 방식으로 쿼리의 어느 위치에서나 변수를 참조할 수 있습니다:

```sql
SELECT
  $__timeInterval(TimestampTime) AS ts,
  count() AS count
FROM otel_logs
WHERE $__timeFilter(TimestampTime)
  AND $__filter(ServiceName, $service)
  AND $__conditionalAll(SeverityText NOT IN ($severity), $severity)
GROUP BY ts
ORDER BY ts ASC
```

SQL 타일에서 사용할 수 있는 전체 매크로 목록은 [SQL 기반 시각화](/ko/clickstack/observability/features/dashboards/sql-visualizations#dashboard-variables)를 참조하십시오.

<Note>
  대시보드 변수를 참조하는 타일의 알림은 대시보드에서 선택한 값이 아니라 모든 변수가 비어 있는 상태를 기준으로 평가됩니다.
</Note>

## 검색으로 드릴다운 {#drilldown-to-search}

대시보드 타일에서 검색 페이지로 드릴다운할 수 있습니다. 시각화에서 데이터 포인트를 클릭하면 다음 옵션이 있는 컨텍스트 메뉴가 열립니다.

* **View All Events** — 선택한 시간 범위의 모든 이벤트를 표시하는 검색 페이지로 이동합니다.
* **Search** (시계열 옆의 돋보기 아이콘) — 해당 시계열의 검색 페이지를 엽니다.
* **Copy label** — 시계열 레이블을 복사합니다.
* **Focus** — 차트에서 선택한 시계열만 집중해서 표시합니다.

## 프리셋 {#presets}

UI에는 바로 사용할 수 있는 기본 대시보드가 포함되어 있습니다.

### Services 대시보드 {#services-dashboard}

Services 대시보드는 trace 데이터를 기반으로 현재 활성 상태인 서비스를 표시합니다. 이 대시보드를 사용하려면 trace를 수집하고 유효한 Traces 데이터 소스를 구성해야 합니다.

서비스 이름은 trace 데이터에서 자동으로 감지되며, 사전 구성된 시각화가 **HTTP Service**, **Database**, **Errors**의 3개 탭으로 나뉘어 제공됩니다.

시각화는 Lucene 또는 SQL 구문으로 필터링할 수 있으며, 특정 구간을 집중적으로 분석하도록 시간 윈도우(time window)를 조정할 수 있습니다.
