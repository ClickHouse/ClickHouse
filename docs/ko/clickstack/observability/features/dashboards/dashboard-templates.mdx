ClickHouse Observability는 일반적인 인프라 및 애플리케이션 텔레메트리를 시각화할 수 있도록 사전 구축된 대시보드 Template 라이브러리를 제공합니다. ClickHouse 서비스에 Template에서 요구하는 텔레메트리가 수신되면 차트에 데이터가 표시됩니다.

## 사용 가능한 Template 둘러보기 {#browsing-templates}

내장 Template 라이브러리를 둘러보려면 **대시보드**로 이동한 후 **Browse 대시보드 Template**를 클릭하십시오.

<div className="ch-image-lg">
  <Frame>
    ![대시보드 Template 둘러보기 버튼](/images/clickstack/observability-browse-dashboard-templates.png)
  </Frame>
</div>

그러면 Template 갤러리가 열리며, Template은 범주별로 정리되어 있습니다. 사용할 Template에서 **Import**를 클릭하십시오.

<div className="ch-image-lg">
  <Frame>
    ![대시보드 Template 갤러리](/images/clickstack/observability-dashboard-template-gallery.png)
  </Frame>
</div>

## 템플릿 가져오기 {#importing-a-template}

**Step 2: Map Data**에서 **Dashboard Name**과 **Tags**를 검토한 다음, 각 타일과 필터(filter)의 **To** 컬럼에서 데이터 소스를 확인하십시오. 소스가 이미 선택되어 있을 수도 있습니다. 아래 예시에서는 Node.js 런타임 메트릭 템플릿의 차트와 서비스 필터가 **Metrics** 소스에 매핑됩니다. **Finish Import**를 클릭하면 대시보드가 생성됩니다.

## 사전 구축된 Template {#pre-built-templates}

### 브라우저 RUM {#browser-rum}

**브라우저 RUM**(real user monitoring, 실사용자 모니터링) 템플릿은 Core Web Vitals, 페이지 로드 백분위수, 트래픽 분류, 오류 추적 기능을 제공합니다. 이 템플릿은 HyperDX 브라우저 SDK 또는 `rum.sessionId`를 내보내는 OpenTelemetry RUM instrumentation으로 계측된 브라우저 세션 데이터를 사용합니다.

### OTel 런타임 메트릭 {#otel-runtime-metrics}

내장 OTel 런타임 메트릭 Template은 [OpenTelemetry 런타임 메트릭](https://opentelemetry.io/docs/specs/semconv/runtime/)으로 계측된 애플리케이션을 위해 설계되었습니다.

| Template                         | 설명                                                                    |
| --------------------------- | --------------------------------------------------------------------- |
| **.NET 런타임 메트릭**    | .NET 애플리케이션의 가비지 컬렉션, 힙 단편화, 예외, 스레드 풀 사용량 및 CPU 메트릭                  |
| **Go 런타임 메트릭**      | Go 애플리케이션의 메모리 사용량(memory usage), 할당, GC 목표치, CPU 사용률 및 goroutine 메트릭 |
| **JVM 런타임 메트릭**     | JVM 기반 애플리케이션의 힙 메모리, CPU 사용률, 스레드 및 GC 메트릭                           |
| **Node.js 런타임 메트릭** | Node.js 애플리케이션의 이벤트 루프 지연, 힙 사용량, CPU 사용률 및 V8 메모리                    |
| **Python 런타임 메트릭**  | Python 애플리케이션의 CPU 사용률, 메모리 사용량, GC 컬렉션 및 스레드 수                       |

참고:

* 각 Template에는 [`telemetry.sdk.language`](https://opentelemetry.io/docs/specs/semconv/registry/attributes/telemetry/#telemetry-sdk-language) 리소스 속성이 대시보드의 런타임과 일치하는 서비스만 표시하는 [사용자 지정 필터](/ko/clickstack/observability/features/dashboards/overview#custom-filters)가 구성되어 있습니다.
* 메트릭 이름은 OpenTelemetry SDK 버전에 따라 다를 수 있습니다. SDK가 다른 메트릭 이름을 내보내는 경우, 데이터에 맞게 [시각화를 편집](/ko/clickstack/observability/features/dashboards/overview#dashboards-editing-visualizations)하십시오.

## 자가 관리형 스키마(schemas) {#self-configured-schemas}

사용자 정의 메트릭 테이블 스키마(table schema)를 사용하는 자가 관리형 배포에서는 템플릿의 서비스 필터가 해당하는 서비스 이름 및 리소스 속성 컬럼을 쿼리하도록 조정하십시오. 대용량 워크로드(workloads)에서는 필터 로드 시간을 줄일 수 있도록 `ResourceAttributes['telemetry.sdk.language']`처럼 [자주 쿼리하는 속성을 구체화(materializing)](/ko/clickstack/self-configured/managing/performance-tuning#materialize-frequently-queried-attributes)하는 방안을 고려하십시오.
