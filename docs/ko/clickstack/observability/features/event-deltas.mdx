이벤트 차이(Event deltas)는 지연 시간 히트맵과 자동 속성 분석을 결합한 기능입니다. 쿼리를 작성하지 않고도 트레이스 데이터의 전반적인 분포를 파악하고, 느린 스팬이 다른 스팬과 어떤 점에서 다른지 찾아낼 수 있습니다. 사용 방법은 다음 세 가지입니다.

* **분포 모드(항상 활성화)**: 히트맵에 선택 영역이 없으면 현재 스팬 데이터 채우기에 대한 모든 속성의 값 분포가 표시됩니다. 지배적인 값이나 비정상적으로 드문 값(카디널리티 이상치)을 찾는 데 유용합니다.
* **비교 모드**: 히트맵에서 직사각형을 드래그하면 영역 내부의 스팬(선택 영역)을 외부의 모든 스팬(배경)과 비교합니다. 편차를 가려내는 데 유용합니다.
* **반복적 드릴다운**: 막대를 클릭하면 해당 값으로 필터링(또는 제외)합니다. 필터링된 스팬 데이터 채우기를 기준으로 히트맵이 다시 렌더링되므로, 원인이 명확해질 때까지 범위를 계속 좁혀 나갈 수 있습니다.

위 스크린샷에서 히트맵의 오른쪽 끝은 오전 내내 유지되던 1 ms 기준값으로 돌아가지 않고 약 10 ms에 머물러 있습니다. 성능 저하가 아직 진행 중이므로, 장애가 진행되는 도중에 이를 포착한 상황입니다.

## 사전 요구 사항 {#prerequisites}

이벤트 차이(Event deltas)를 사용하려면 소요 시간 표현식이 설정된 **Trace** 데이터 소스가 필요합니다. 스팬 데이터를 생성하는 서비스라면 OpenTelemetry로 계측된 어떤 서비스든 사용할 수 있습니다.

## 시작하기 {#getting-started}

1. **데이터 소스** 드롭다운에서 trace가 저장된 소스를 선택하십시오. 소스 이름은 자유롭게 지정할 수 있으며, 중요한 것은 해당 소스가 Trace 유형으로 구성되어 있는지입니다. **이벤트 차이** 탭은 Trace 유형 소스에서만 활성화됩니다.
2. **분석 모드** 섹션에서 **이벤트 차이** 탭을 클릭하십시오.

이벤트 차이는 **결과 테이블(Results Table)**, **이벤트 패턴**과 나란히 제공되는 별도의 분석 모드입니다. 이 모드로 전환하면 화면이 히트맵과 속성 분석 그리드로 바뀌지만, 검색 필터와 시간 범위는 그대로 유지되며 언제든지 이전 모드로 돌아갈 수 있습니다.

## 히트맵 {#the-heatmap}

히트맵은 스팬을 두 개의 차원으로 나타냅니다.

* **X축**: 시간
* **Y축**: 숫자 값(기본값은 밀리초 단위의 스팬 소요 시간, 로그 스케일)

색상의 강도는 버킷당 이벤트 수를 나타내며, 밝을수록 스팬이 많다는 뜻입니다.

히트맵에서는 이봉형(bimodal) 지연 시간, 특정 시점의 지연 시간 급증, 일관되게 느린 스팬이 이루는 띠, 시간이 지나면서 점차 위로 올라가는 느린 띠(서서히 악화되는 회귀 오류) 같은 패턴을 바로 파악할 수 있습니다. 특정 영역을 자세히 살펴보려면 히트맵 위에서 클릭한 채 드래그하여 직사각형을 그리십시오. 해당 영역이 **선택 영역**이 되고, 아래 분석이 비교 모드로 전환됩니다.

## 분포 모드: 카디널리티 이상치 {#distribution-mode}

히트맵에 선택 영역이 없으면 분석 패널에는 일치하는 모든 스팬을 기준으로 계산한 막대 차트가 속성별로 하나씩 표시됩니다. 범례에는 **All spans**가 표시됩니다(위의 개요 스크린샷 참고).

속성은 값이 얼마나 집중되어 있는지에 따라 정렬됩니다. 소수의 값이 대부분을 차지하는 속성이 먼저 표시되고, 값이 균등하게 분포되어 엔트로피가 높은 속성은 뒤로 밀립니다.

데이터의 **카디널리티 분포 형태**를 파악하려면 분포 모드를 사용하세요.

* **상위 값**: 스팬 데이터 채우기의 대부분을 차지하는 서비스, 엔드포인트, 상태 코드 또는 호스트는 무엇입니까? 단일 테넌트, 버전 또는 라우트가 트래픽의 대부분을 처리하고 있다는 사실이 드러나는 경우가 많습니다.
* **하위 값**: 발생은 하지만 드물게 나타나는 값입니다. 전체 스팬의 `0.5%`에서만 나타나는 상태 코드나 거의 보이지 않는 호스트가 가장 주목할 만한 신호일 수 있습니다. 회귀 오류와 악의적인 행위자는 롱테일에 숨어 있습니다.

검색 창과 함께 사용하여 먼저 데이터 채우기를 좁힌 다음(예: 오류 스팬만, 클라이언트 스팬만, 특정 엔드포인트 하나만) 해당 부분 집합의 분포를 확인하세요.

## 비교 모드: 정상 상태와의 편차 {#comparison-mode}

히트맵에서 클릭한 채 드래그하여 직사각형을 그리면 비교 모드로 전환됩니다. 선택된 스팬은 **선택 영역**(주황색 막대)이 되고, 나머지 스팬은 모두 **배경**(초록색 막대)이 됩니다. 이후 각 속성 차트에는 두 데이터 채우기가 나란히 표시되며, 차이가 가장 큰 속성이 먼저 나타나도록 정렬됩니다. 거의 한쪽에만 존재하거나 한쪽에는 아예 없는 값이 차이를 만드는 원인일 가능성이 가장 높은 후보입니다.

어떤 형태로 직사각형을 그리느냐에 따라 묻는 질문이 달라집니다. 자주 사용되는 두 가지 형태는 아래에서 설명합니다.

### 활용 사례 1: 회귀 오류 발생 전후 비교 {#before-vs-after}

히트맵에서 지연 시간이 타임라인을 따라 점차 상승한다면(느린 구간이 두꺼워지거나, 밝은 구간이 위로 올라가거나, 뚜렷한 변곡점을 기준으로 정상 기간과 성능 저하 기간이 구분되는 경우), 상승이 시작되는 변곡점부터 화면 오른쪽 끝까지 직사각형을 드래그하십시오. 비교를 더 정확하게 하려면 직사각형의 아래쪽 경계를 축의 맨 아래가 아닌 정상 기준값에 맞추십시오. 이렇게 하면 같은 시간 범위에 속해 있을 뿐 여전히 정상적으로 빠른 스팬은 제외하고, 성능 저하 구간에서 실제로 평소보다 느린 스팬만 분리할 수 있습니다.

<div className="ch-image-lg">
  <Frame>
    ![payment 서비스에서 상승 변곡점부터 오른쪽 끝까지 직사각형을 그리고 아래쪽 경계를 1 ms 기준값에 맞춘 비교 모드](/images/clickstack/event-deltas/before-after.webp)
  </Frame>
</div>

히트맵 아래의 속성 막대 차트는 차이가 큰 항목부터 정렬됩니다. 이 예시에서는 첫 번째 행의 차트에 가장 강한 시그널이 나타납니다. `SpanKind`, `SpanName`, `ScopeName`은 각각 느린 선택 영역과 정상적인 배경 사이에서 주황색과 녹색이 뚜렷이 갈리는 모습을 보여줍니다. 이들을 종합하면 변곡점에서 무엇이 바뀌었는지 짚어낼 수 있습니다.

&quot;무엇이 바뀌었는가?&quot;를 확인하려면 이러한 형태가 적합합니다. 같은 방식을 더 좁게 적용하는 변형도 있습니다. 대체로 조용한 구간 안에 느린 스팬이 작게 뭉쳐 있다면(오른쪽 끝의 짧은 급증, 안정적인 기간 중간의 클러스터 등) 해당 클러스터만 둘러싸는 작은 박스를 그리십시오. 형태에 따라 질문이 달라집니다. 세로 띠는 *시간에 따라 무엇이 바뀌었는가*를 묻고, 작고 집중된 박스는 *이 클러스터에 어떤 특별한 점이 있는가*를 묻습니다.

### 활용 사례 2: 느린 스팬과 빠른 스팬 비교 {#slow-vs-fast}

히트맵에서 두 지연 시간 데이터 채우기가 소요 시간 축을 따라 명확히 분리되어 나타나면, 전체 시간 범위에 걸치되 명확히 분리된 상단 영역만 포함하도록 넓은 직사각형을 드래그하십시오. 느린 데이터 채우기는 선택 영역이 되고, 대부분을 차지하는 빠른 스팬은 배경이 됩니다.

<div className="ch-image-lg">
  <Frame>
    ![frontend-proxy에서 밀집된 대부분의 스팬과 충분히 떨어져 있는, 명확히 분리된 상단 영역만 직사각형으로 덮은 느린 스팬과 빠른 스팬 비교](/images/clickstack/event-deltas/slow-vs-fast.webp)
  </Frame>
</div>

직사각형은 상단 영역에 딱 맞게 그리되, 밀집된 대부분의 스팬과의 사이에 눈에 보이는 수평 공백이 남도록 하십시오. 직사각형을 느슨하게 그려 빠른 데이터 채우기까지 포함되면 차이가 희석됩니다.

100 s 상한선은 그 자체로도 유용한 정보를 제공합니다. 딱 떨어지는 숫자에 일정하게 그어진 수평선은 고정된 타임아웃의 전형적인 특징입니다. 두 데이터 채우기를 명확히 구분하는 스팬 속성이 없다면 그 역시 유용한 결과입니다. 이는 스팬 속성보다는 호스트 및 런타임 수준의 메트릭(GC 일시 중지, 입출력(IO) 경합, 스케줄러 지연 시간, 콜드 캐시 영향, 노이지 네이버(noisy neighbor) 등)을 살펴봐야 함을 의미합니다.

특정 이상 징후를 쫓기보다 &quot;느린 스팬은 빠른 스팬과 무엇이 다른가?&quot;를 알고 싶을 때 적합한 분석 방식입니다. 차이가 나는 속성은 원인이 코드 경로나 입력에 있음을 가리키고, 차이가 없는 비교 결과는 원인이 시스템 전반에 있음을 가리킵니다.

## 반복적 드릴다운 {#drill-down}

비교 모드와 분포 모드는 연이어 함께 사용할 때 가장 효과적입니다. 막대를 클릭하면 세 가지 작업이 포함된 팝오버가 열립니다.

* **Filter**: 이 값을 가진 스팬만 남깁니다
* **Exclude**: 이 값을 가진 스팬을 제외합니다
* **Copy**: 값을 클립보드에 복사합니다

<div className="ch-image-lg">
  <Frame>
    ![ScopeVersion 막대를 클릭했을 때 선택 영역 대비 배경 비율과 filter, exclude, copy 작업을 표시하는 팝오버](/images/clickstack/event-deltas/drill-down.webp)
  </Frame>
</div>

filter 또는 exclude를 적용하면 히트맵 선택 영역이 해제되고, 히트맵이 새 데이터 채우기를 기준으로 다시 렌더링되며, 분포 모드가 필터링된 집합을 기준으로 다시 실행됩니다. 이때 히트맵의 형태가 어떻게 바뀌는지 살펴보십시오. 필터가 효과적이라면 느린 구간이 눈에 띄게 사라지거나, 이봉형으로 갈라진 분포가 하나로 합쳐지거나, 상승하던 드리프트가 평탄해집니다. 다음 의심 값을 찾아 필터링하고, 새 히트맵과 새 분포를 확인하는 과정을 반복하십시오. 대개 몇 번만 반복하면 회귀 오류의 원인을 한두 개의 속성으로 좁힐 수 있습니다.

<Note>
  빈도가 낮은 값을 하나로 묶은 집계된 **Other (N)** 버킷은 클릭할 수 없습니다. 해당 버킷 안의 특정 값으로 필터링하려면 [검색 바](/ko/clickstack/observability/features/search)를 직접 사용하십시오.
</Note>

데이터 채우기가 충분히 작아지면 **결과 테이블(Results Table)** 탭으로 전환하여 개별 트레이스를 살펴보십시오. 적용한 필터는 그대로 유지됩니다.

## 히트맵 사용자 정의 {#customize}

히트맵 오른쪽 상단의 톱니바퀴 아이콘을 클릭하면 **표시 설정** 드로어가 열립니다.

<div className="ch-image-lg">
  <Frame>
    ![Scale, Value, Count 필드가 있는 표시 설정 드로어](/images/clickstack/event-deltas/settings-drawer.webp)
  </Frame>
</div>

| 매개변수      | 기본값              | 설명                                                                                          |
| --------- | ---------------- | ------------------------------------------------------------------------------------------- |
| **Scale** | Log              | Log는 폭넓은 지연 시간 범위를 다루는 데 적합하고, Linear는 좁고 균등한 분포에 더 적합합니다.                                  |
| **Value** | `(Duration)/1e6` | 응답 크기, 오류율, 사용자 정의 스팬 속성 등 모든 숫자 표현식을 사용할 수 있습니다.                                           |
| **Count** | `count()`        | 색상 표시에 사용할 집계입니다. `avg()`, `sum()`, `p95()` 또는 `countDistinct(field)`와 같은 표현식으로 변경할 수 있습니다. |

**Apply**를 클릭하면 히트맵이 업데이트되고, 아래의 속성 분석에도 함께 반영됩니다.

<Tip>
  **대시보드의 히트맵**

  동일한 히트맵을 [대시보드 타일](/ko/clickstack/observability/features/dashboards/overview#create-a-tile-heatmap)로도 사용할 수 있습니다. 이벤트 차이 drill-down 흐름과 별개로 시간에 따른 분포 형태를 모니터링하려는 경우에 유용합니다.
</Tip>

다음은 이러한 기본값을 변경하는 일반적인 시나리오입니다.

* **지연 시간 대역이 좁은 경우 Scale을 Linear로 변경합니다** (예: 모든 스팬이 5~50 ms 사이에서 실행되는 서비스). Log 스케일을 사용하면 데이터가 없는 상단 영역에 세로 공간이 낭비됩니다.
* **Y축에 소요 시간 이외의 값을 표시합니다.** **Value**를 `SpanAttributes.http.response.size`로 설정하면 느린 *대용량* 응답을 조사할 수 있으며, `if(StatusCode = 'Error', 1, 0)`과 같은 표현식을 사용하면 여러 서비스에 걸친 시간별 오류 빈도를 표시할 수 있습니다.
* **건수 이외의 기준으로 색상을 지정합니다.** **Count**를 `p95(Duration)`으로 설정하면 각 버킷의 색상이 건수가 아닌 테일 지연 시간을 기준으로 지정되므로, 건수 기반 뷰에서는 묻혀 버리는, 드물지만 느린 구간을 찾아낼 수 있습니다. 하나의 트레이스가 많은 스팬을 생성하는 경우 `countDistinct(TraceId)`를 사용하면 트레이스 수와 스팬 수를 구분할 수 있습니다.

## 효과적인 사용을 위한 팁 {#tips}

다음 몇 가지 방법을 따르면 이벤트 차이를 훨씬 더 유용하게 활용할 수 있습니다.

* **먼저 단일 서비스로 필터링하십시오.** 지연 시간은 서비스마다 크게 다르므로 여러 서비스가 섞이면 신호가 흐려집니다. 분석을 시작하기 전에 검색창에서 하나의 `ServiceName`(또는 하나의 엔드포인트)으로 범위를 좁혀, 히트맵과 분포가 비교 가능한 데이터 채우기를 반영하도록 하십시오.
* **시각적 대비가 뚜렷한 선택 영역을 고르십시오.** 비교 모드는 선택 영역 구간이 배경과 확연히 구별될 때 가장 효과적입니다. 예를 들어 특정 시점부터 성능이 저하되기 시작한 기간이나, 대부분의 데이터와 명확히 분리된 느린 꼬리(tail) 구간이 이에 해당합니다. 나머지 데이터와 많이 겹치는 선택 영역은 실제 편차보다는 노이즈를 드러내기 쉽습니다.
* **필터, 히트맵, 필터 순서로 반복하십시오.** 한 번의 선택만으로 원인을 찾는 경우는 드뭅니다. 첫 번째 비교 결과를 가설로 삼아 차이가 가장 큰 값으로 필터링한 다음, 새 히트맵과 분포를 다시 확인하십시오. 보통 두세 번 반복하면 회귀 오류의 원인을 한두 개의 속성으로 좁힐 수 있습니다.
* **아직 대비가 보이지 않으면 선택 영역 없이 분포 모드를 사용하십시오**(이슈가 있는 것은 분명하지만 히트맵이 균등해 보이는 경우). 오류 스팬만, 클라이언트 스팬만, 또는 특정 엔드포인트만 보는 식으로 가설에 따른 필터를 적용한 다음, 직사각형을 그리기 전에 속성 분포에서 영향이 가장 큰 값을 먼저 파악하십시오.

## 문제 해결 {#troubleshooting}

### 이벤트 차이 탭이 표시되지 않는 경우 {#tab-not-visible}

**분석 모드**의 **이벤트 차이** 탭은 소요 시간 표현식이 설정된 **Trace** 소스를 선택한 경우에만 표시됩니다. 데이터 소스가 Trace 유형으로 구성되어 있는지, 그리고 소요 시간 정보가 포함된 스팬 데이터가 있는지 확인하십시오.

### 속성 차트에 결과가 거의 또는 전혀 표시되지 않음 {#few-results}

표본(sample)이 너무 작으면(스팬이 수십 개 미만) 분포가 통계적으로 유의미하지 않을 수 있습니다. 시간 범위를 넓히거나 검색 필터 조건을 완화하세요.
