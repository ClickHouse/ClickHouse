  이 가이드에서는 브라우저 SDK와 완전 관리형 또는 자가 관리형 ClickHouse Observability를 사용하여 웹 애플리케이션에 세션 리플레이용 계측을 적용하는 과정을 안내합니다. 미리 생성된 데이터를 로드하는 다른 샘플 데이터 세트와 달리, 이 데모는 사용자가 직접 상호작용하며 세션 데이터를 생성할 수 있는 대화형 애플리케이션을 제공합니다.

  소요 시간: 10-15분
</Info>

## 개요 {#overview}

[세션 리플레이 데모 애플리케이션](https://github.com/ClickHouse/clickstack-session-replay-demo)은 순수 JavaScript(vanilla JavaScript)로 만든 문서 탐색기입니다. 이 애플리케이션은 세션 리플레이 instrumentation에 필요한 작업이 얼마나 적은지 보여 줍니다. 스크립트 태그 1개와 초기화 호출 1회만으로 사용자 상호작용이 자동으로 수집됩니다.

이 리포지토리에는 두 개의 브랜치가 있습니다.

* **`main`** — instrumentation이 모두 적용되어 있어 바로 사용할 수 있는 버전
* **`pre-instrumented`** — instrumentation이 적용되지 않은 깨끗한 버전으로, instrumentation을 추가할 위치가 코드 주석으로 표시되어 있음

이 가이드에서는 먼저 `main` 브랜치로 세션 리플레이가 실제로 동작하는 모습을 확인한 다음, instrumentation 코드를 단계별로 살펴보며 같은 패턴을 자체 애플리케이션에 적용하는 방법을 설명합니다.

세션 리플레이의 개념과 ClickStack에서의 역할에 대한 배경 정보는 [세션 리플레이](/ko/clickstack/observability/features/session-replay) 기능 페이지를 참조하십시오.

## 사전 요구 사항 {#prerequisites}

* Docker가 설치되어 실행 중이어야 하며, Docker Compose를 사용할 수 있어야 합니다
* 데모 앱에서 사용할 포트 3000이 비어 있어야 합니다
* 완전 관리형 또는 자가 관리형 ClickHouse Observability 서비스가 이미 있어야 합니다
* 브라우저에서 아래에 구성된 텔레메트리 엔드포인트로 네트워크 접근이 가능해야 합니다

## 데모 실행 {#running-the-demo}

<Steps>
  <Step title="리포지토리를 복제하십시오" id="clone-repository">
    ```shell
    git clone https://github.com/ClickHouse/clickstack-session-replay-demo
    cd clickstack-session-replay-demo
    ```
  </Step>

  <Step title="연결 구성" id="configure-connection">
    배포 모드를 선택하십시오.

    <Tabs>
      <Tab title="완전 관리형">
        <BetaBadge label="베타 제공" />

        기존 [완전 관리형 서비스](/ko/clickstack/observability/getting-started)가 필요합니다. 수집용 collector는 ClickHouse에서 제공합니다.

        ClickHouse Observability 서비스에서 **팀 설정 → 데이터 → Managed Telemetry**를 열고 **OTLP HTTP endpoint**와 **API key**를 복사하십시오.

        <div className="ch-image-lg">
          <Frame>
            ![마스킹된 OTLP HTTP 엔드포인트와 API Key가 표시된 Managed Telemetry](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        `CLICKSTACK_UI_URL`을 관리형 서비스의 UI URL로 설정하십시오. 리플레이를 바로 열려면 **클라이언트 세션**에서 브라우저 URL을 복사하십시오. 아래 자리표시자를 연결 정보로 바꾼 다음, 터미널에서 다음 명령을 실행하십시오.

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
        export CLICKSTACK_API_KEY='Bearer YOUR_API_KEY'
        export CLICKSTACK_UI_URL='YOUR_OBSERVABILITY_UI_URL'
        ```

        `https://` 접두사는 그대로 두고 `/v1/traces`와 같은 신호 경로는 생략하십시오. 완전 관리형 수집에서는 위와 같이 `Bearer ` 접두사를 포함해야 합니다.

        `CLICKSTACK_UI_URL`은 데모의 **Open Observability** 링크를 제어하며, 텔레메트리 수집 엔드포인트와는 별개입니다.

        서버는 텔레메트리 엔드포인트와 API Key를 브라우저 SDK에 전달합니다. 수집 키가 브라우저에 노출되므로 이 데모에는 테스트용 서비스를 사용하십시오.
      </Tab>

      <Tab title="자가 관리형">
        기존 [자가 관리형 서비스](/ko/clickstack/self-configured/getting-started/managed)와, 이 서비스에 연결되어 실행 중인 ClickStack OpenTelemetry 수집기가 필요합니다. 연결 방법은 [OpenTelemetry로 데이터 수집하기](/ko/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured)를, collector 시작 방법은 [배포 가이드](/ko/clickstack/self-configured/deployment/managed#start-a-collector-existing)를 참고하십시오.

        collector의 OTLP HTTP 엔드포인트는 브라우저에서 접근할 수 있어야 하며, CORS에서 `http://localhost:3000`을 허용해야 합니다. 또한 UI가 클라이언트 세션에서 새 SDK의 `session.id` 속성을 지원해야 합니다. 자세한 내용은 [SDK 호환성 요구 사항](https://github.com/ClickHouse/clickstack-browser#clickstack-versions)을 참고하십시오.

        `CLICKSTACK_OTEL_ENDPOINT`는 `/v1/traces`와 같은 신호 경로를 제외한 collector의 OTLP HTTP 엔드포인트로 설정하십시오. `CLICKSTACK_UI_URL`은 자가 관리형 서비스의 UI에서 복사한 **클라이언트 세션** URL로 설정하십시오.

        ```shell
        export CLICKSTACK_OTEL_ENDPOINT='https://YOUR_COLLECTOR_HOST:4318'
        export CLICKSTACK_API_KEY='YOUR_COLLECTOR_TOKEN'
        export CLICKSTACK_UI_URL='YOUR_CLIENT_SESSIONS_URL'
        ```

        collector의 수신기에 구성된 인증 토큰을 사용하십시오. ClickStack 수집기를 `OTLP_AUTH_TOKEN`으로 보호하고 있다면 해당 값을 `Bearer` 접두사 없이 사용하십시오. 수신기에 인증이 필요하지 않다면 `CLICKSTACK_API_KEY`를 빈 문자열로 설정하십시오. 여기에는 ClickHouse 데이터베이스 비밀번호를 사용하지 마십시오.

        수집 토큰은 브라우저 SDK에 전달되므로 브라우저에 노출됩니다. 반면 collector의 ClickHouse 데이터베이스 자격 증명은 collector에만 보관됩니다.
      </Tab>
    </Tabs>
  </Step>

  <Step title="데모 애플리케이션 시작" id="start-demo-app">
    연결 변수를 내보낸 터미널에서 리포지토리 디렉터리로 이동한 후 다음 명령을 실행하십시오:


    브라우저에서 [http://localhost:3000](http://localhost:3000)을 열고 앱을 사용해 보십시오. 주제를 검색하거나, 범주별로 필터링하거나, 코드 예시를 살펴보거나, 항목을 북마크할 수 있습니다.

  </Step>

## instrumentation {#instrumentation}

데모 애플리케이션을 보면 세션 리플레이를 활성화하는 데 코드가 얼마나 적게 필요한지 알 수 있습니다. 애플리케이션에 두 가지만 추가하면 됩니다. 아래 예시에서는 새로운 ClickStack Browser SDK를 사용합니다.

**1. SDK 추가 (`app/public/index.html`):**

```html
<script src="https://cdn.jsdelivr.net/npm/@clickhouse/clickstack-browser@1.0.0/dist/clickstack.iife.js" integrity="sha384-NW4JhbuY4Thx4fMuqFwKvifcPn7ad9dJ7DU/MTxhkoHeadG27i4F38Yo1Gz6y0WA" crossorigin="anonymous"></script>
```

**2. 브라우저 SDK 초기화 (`app/public/js/app.js`):**

```javascript
window.ClickStack.init({
  endpoint: window.CLICKSTACK_CONFIG.endpoint,
  apiKey: window.CLICKSTACK_CONFIG.apiKey,
  serviceName: 'clickhouse-session-replay-demo',
  console: 'debug',
});
```

`app/server.js`는 `CLICKSTACK_OTEL_ENDPOINT`, `CLICKSTACK_API_KEY`, `CLICKSTACK_UI_URL` 환경 변수를 기반으로 `window.CLICKSTACK_CONFIG`를 제공합니다. SDK는 엔드포인트와 API Key를 사용하고, 데모 링크는 UI URL을 사용합니다. SDK는 애플리케이션의 비즈니스 로직을 변경하지 않고도 세션 리플레이, 콘솔 로그, 네트워크 요청, 오류를 수집합니다.

텍스트와 입력값은 기본적으로 마스킹(masking)됩니다. 마스킹 설정을 변경하기 전에 [브라우저 SDK 개인정보 보호 설정](/ko/clickstack/observability/ingesting-data/sdks/browser#session-replay-and-privacy)을 참조하십시오.

### 직접 해 보기 {#try-it-yourself}

앱을 처음부터 직접 계측하려면 `Ctrl+C`로 실행 중인 데모를 중지한 다음 `pre-instrumented` 브랜치로 전환하세요.

```shell
git checkout pre-instrumented
```

이 브랜치에는 브라우저 SDK가 활성화되지 않은 상태의 동일한 애플리케이션이 들어 있습니다. 위의 두 스니펫을 추가할 위치는 `app/public/index.html` 및 `app/public/js/app.js`의 코드 주석에 표시되어 있습니다. 앞서 구성한 연결 변수는 그대로 유지한 채 앱을 다시 빌드하고 실행하십시오:

```shell
docker compose --profile demo up --build --no-deps demo-app
```

브라우저에서 데모를 다시 로드한 후 데모를 사용하여 새 세션을 생성하십시오.

## 문제 해결 {#troubleshooting}

### 세션이 표시되지 않는 경우 {#sessions-not-appearing}

1. 브라우저 콘솔에서 오류가 있는지 확인하세요
2. 데모 앱이 실행 중인지 확인하세요: `docker compose ps demo-app`
3. 앱을 시작한 터미널에 `CLICKSTACK_OTEL_ENDPOINT`와 `CLICKSTACK_API_KEY`가 설정되어 있는지 확인하세요. 값을 변경했다면 시작 명령을 다시 실행한 후 브라우저 탭을 새로고침하세요.
4. 자가 관리형 환경에서는 collector 내보내기 오류, CORS 구성, 앞에서 설명한 SDK 호환성 요구 사항을 확인하세요
5. 클라이언트 세션 뷰에서 시간 범위를 조정하세요(**Last 15 minutes** 선택 권장)
6. 브라우저에서 강력 새로고침을 실행하세요: `Cmd+Shift+R`(Mac) 또는 `Ctrl+Shift+R`(Windows/Linux)

### 401 인증되지 않음 오류 {#401-errors}

API Key가 올바르게 설정되지 않았습니다. 다음 사항을 확인하십시오.

1. 터미널에서 사용 중인 배포 모드에 맞는 값으로 `CLICKSTACK_API_KEY`를 내보냈는지 확인하십시오.
2. 값을 내보낸 **동일한 터미널**에서 데모 앱을 시작했는지 확인하십시오.
3. 완전 관리형은 **팀 설정 → 데이터 → Managed Telemetry**에서 확인한 수집 API key를 `Bearer ` 접두사와 함께 사용해야 합니다. 자가 관리형은 이 접두사 없이 collector의 수신기 토큰을 사용해야 합니다.

## 정리 {#cleanup}

브라우저 텔레메트리 전송을 중지하려면 데모 브라우저 탭을 닫고, 앱이 실행 중인 터미널에서 `Ctrl+C`를 누르십시오. 다른 터미널에서 앱을 중지하려면 리포지토리 디렉터리에서 다음 명령을 실행하십시오.

```bash
docker compose stop demo-app
```

이렇게 하면 로컬 앱이 중지되며, 서비스에 이미 수집된 텔레메트리는 그대로 남아 있습니다.
