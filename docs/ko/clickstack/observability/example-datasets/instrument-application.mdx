    HackerNews Analyzer는 퍼블릭 ClickHouse 데모에 호스팅된 HackerNews 데이터셋을 쿼리하는 Node.js 앱입니다. 대시보드를 조작하면 백엔드로 요청이 전송됩니다. 앱 캐시에 적중하지 않은 요청은 ClickHouse에도 쿼리를 보내며, 이에 따라 트레이스에 아웃바운드 HTTPS 스팬이 추가됩니다.

    이 데모는 백엔드 auto-instrumentation, ClickHouse 쿼리(Query) 스팬, 브라우저 세션 리플레이를 하나의 앱에서 모두 제공합니다.

## 사전 요구 사항 {#prerequisites}

    * [HackerNews Analyzer 및 관련 의존성](https://github.com/ClickHouse/hn-news-analyzer#readme)과 호환되는 버전의 Node.js 및 npm
    * 이미 생성된 완전 관리형 ClickHouse Observability 서비스. 자세한 내용은 [완전 관리형 시작 가이드](/ko/clickstack/observability/getting-started)를 참조하십시오.
    * 앱 서버와 브라우저 모두에서 관리형 텔레메트리 엔드포인트에 접근할 수 있는 네트워크 환경

## 리포지토리 클론 {#clone-the-repository}

    [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer) 저장소를 클론하고 의존성을 설치한 다음, env 템플릿 파일을 복사하십시오:

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    다음 단계에서 `.env`를 작성한 후, 이 디렉터리에서 계측을 진행합니다.

        앱의 `.env` 파일에 다음 설정값을 지정하고, 엔드포인트와 API Key 자리표시자를 실제 값으로 바꾸십시오:

        ```bash
        OTEL_SERVICE_NAME=hn-analyzer-api
        OTEL_EXPORTER_OTLP_ENDPOINT=https://YOUR_OTEL_ENDPOINT:4318
        OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
        OTEL_EXPORTER_OTLP_HEADERS=authorization=<your-api-key>
        OTEL_TRACES_EXPORTER=otlp
        OTEL_METRICS_EXPORTER=otlp
        OTEL_LOGS_EXPORTER=otlp
        ```

        `OTEL_EXPORTER_OTLP_ENDPOINT`에는 `https://` 접두사를 그대로 두고 `/v1/logs`, `/v1/traces`, `/v1/metrics`를 덧붙이지 마십시오. 신호별 경로는 SDK가 자동으로 추가합니다. `OTEL_EXPORTER_OTLP_HEADERS`는 `Bearer` 접두사 없이 `authorization=<your-api-key>`로 설정하십시오. 애플리케이션은 이 키를 브라우저 SDK에도 그대로 전달합니다.

        브라우저 SDK도 동일한 엔드포인트와 API Key를 사용합니다. `vite.config.ts`가 이 값들을 브라우저 bundle에 포함하므로 방문자가 이를 확인할 수 있습니다. 따라서 이 데모 테스트 전용 서비스를 사용하고, `.env`는 버전 관리 대상에서 제외하십시오.

            계측은 SDK 설치, 실행 명령 전환, 브라우저 SDK 활성화의 세 단계로 이루어집니다. 이 과정에서 애플리케이션의 비즈니스 로직은 전혀 변경되지 않습니다.

### Node SDK 설치 {#install-node-sdk}

            ```bash
            npm install @hyperdx/node-opentelemetry
            ```

### run.sh에서 래퍼 활성화 {#enable-run-sh-wrapper}

            `run.sh` 하단에는 `exec` 줄이 두 개 있습니다. 일반 `node` 줄을 주석 처리하고 계측된 줄의 주석을 해제하십시오.

            ```diff
             # 변경 전: 계측 없는 일반 node:
            -exec node scripts/entrypoint.js
            +# exec node scripts/entrypoint.js

             # 변경 후: 동일한 소스를 opentelemetry-instrument로 래핑:
            -# exec npx opentelemetry-instrument scripts/entrypoint.js
            +exec npx opentelemetry-instrument scripts/entrypoint.js
            ```

            실행은 계속 `scripts/entrypoint.js`를 통해 하십시오. 이 shim이 `require('console')`을 호출하므로 콘솔 캡처가 `console.log`를 래핑할 수 있습니다. `opentelemetry-instrument`가 `dist/server/index.js`를 직접 실행하도록 지정하면 트레이스는 전송되지만 로그는 아무런 경고 없이 누락됩니다.

### 브라우저 SDK 활성화 {#enable-browser-sdk}

            ```bash
            npm install @hyperdx/browser
            ```

            `src/web/telemetry.ts`에서 import 문, `HyperDX.init` 블록, `recordAction` 내의 `HyperDX.addAction`의 주석을 해제하십시오.

            ```diff
            -// import HyperDX from '@hyperdx/browser';
            +import HyperDX from '@hyperdx/browser';

             export function initTelemetry(): void {
            -  // HyperDX.init({
            -  //   url: __OTLP_ENDPOINT__,
            -  //   apiKey: __OTLP_AUTH_TOKEN__,
            -  //   service: 'hn-analyzer-web',
            -  //   tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            -  //   consoleCapture: true,
            -  //   advancedNetworkCapture: true,
            -  // });
            +  HyperDX.init({
            +    url: __OTLP_ENDPOINT__,
            +    apiKey: __OTLP_AUTH_TOKEN__,
            +    service: 'hn-analyzer-web',
            +    tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
            +    consoleCapture: true,
            +    advancedNetworkCapture: true,
            +  });
             }
            ```

            `__OTLP_ENDPOINT__`와 `__OTLP_AUTH_TOKEN__`은 `vite.config.ts`가 백엔드와 동일한 `OTEL_EXPORTER_OTLP_*` 값을 바탕으로 주입하는 컴파일 타임 상수입니다.
          </Tab>

            계측 과정을 건너뛰고 이미 계측된 애플리케이션으로 시작하려면 [`instrumented` 브랜치](https://github.com/ClickHouse/hn-news-analyzer/tree/instrumented)를 체크아웃하십시오.

            ```bash
            git checkout instrumented
            npm install
            ```

            SDK를 제거하려는 경우가 아니라면 이 브랜치에서 `./reset.sh`를 실행하지 마십시오.

    HackerNews Analyzer는 퍼블릭 ClickHouse 데모에 호스팅된 HackerNews 데이터셋을 쿼리하는 Node.js 앱입니다. 모든 차트, 테이블, 검색 상자가 실제 ClickHouse 쿼리(Query)로 동작하므로, 각 상호작용마다 백엔드에서 ClickHouse로 보내는 HTTPS 호출을 주 스팬으로 하는 트레이스가 생성됩니다.

    이 데모는 브라우저 전용 앱을 계측하여 텔레메트리를 ClickHouse Observability로 전송하는 [세션 리플레이 데모](/ko/clickstack/observability/example-datasets/session-replay)와는 목적이 다릅니다. 이 데모에서는 하나의 앱에서 백엔드 auto-instrumentation, ClickHouse 쿼리 스팬, 세션 리플레이를 모두 확인할 수 있습니다.

## 사전 요구 사항 {#prerequisites-self-configured}

    * Node 18 이상 및 npm
    * 기존 자체 관리형 ClickHouse Observability 서비스와 실행 중인 수집용 collector
    * 앱 서버와 브라우저 모두에서 연결할 수 있는 collector의 OTLP HTTP 엔드포인트. `http://localhost:4318`은 collector가 같은 머신에서 실행되는 경우에만 사용하십시오.
    * collector의 `OTLP_AUTH_TOKEN`(구성되어 있는 경우). header는 `Bearer` 접두사 없이 `authorization=<token>` 형식으로 설정하십시오. collector에 인증이 필요하지 않으면 `authorization=` 값을 비워 두십시오. 이 값은 collector 수집용 자격 증명이며, ClickHouse 데이터베이스(Database) 자격 증명이 아닙니다.

## 리포지토리 클론 {#clone-the-repository-self-configured}

    [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)를 클론하고 의존성을 설치한 다음 env 템플릿을 복사하십시오:

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    다음 단계에서 `.env` 파일을 채운 후, 이 디렉터리에서 애플리케이션을 계측합니다.
