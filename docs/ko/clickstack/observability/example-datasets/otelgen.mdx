<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 제공" />

    [`otelgen`](https://github.com/krzko/otelgen)은 합성 OTLP 로그, 트레이스, 메트릭을 생성하는 경량 Go CLI입니다. 이 도구로 완전 관리형 ClickHouse Observability에 테스트 데이터를 전송하고, 검색 및 차트 탐색기에서 결과를 확인할 수 있습니다.

    <Steps>
      <Step title="사전 요구 사항" id="prerequisites-managed">
        완전 관리형 ClickHouse Observability 서비스가 이미 생성되어 있어야 하며, 해당 서비스의 관리형 텔레메트리 엔드포인트에 네트워크로 접근할 수 있어야 합니다. 자세한 내용은 [완전 관리형 시작 가이드](/ko/clickstack/observability/getting-started)를 참조하십시오.
      </Step>

      <Step title="otelgen 설치" id="install-otelgen-managed">
        Homebrew로 설치합니다.

        ```shell
        brew install krzko/tap/otelgen
        ```

        또는 Go로 설치합니다.

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="환경 변수 설정" id="set-env-vars-managed">
        ClickHouse Observability 서비스를 열고 **팀 설정 → Managed Telemetry**로 이동합니다. **OTLP HTTP endpoint**와 **API key**를 복사합니다.

        <div className="ch-image-lg">
          <Frame>
            ![팀 설정의 Managed Telemetry에 마스킹된 OTLP HTTP 엔드포인트와 API Key가 표시된 화면](/images/clickstack/getting-started/observability-managed-telemetry.png)
          </Frame>
        </div>

        엔드포인트는 `https://` 접두사를 제거하고 호스트와 포트만 지정합니다. 예를 들어 `https://YOUR_OTEL_ENDPOINT:4318`은 `YOUR_OTEL_ENDPOINT:4318`이 됩니다. `/v1/logs`와 같은 신호 경로는 붙이지 마십시오.

        ```shell
        export OTEL_ENDPOINT='YOUR_OTEL_ENDPOINT:4318'
        printf "API key: "
        read -r -s OTEL_API_KEY
        printf "\n"
        export OTEL_API_KEY
        ```

        아래 명령어는 `--insecure` 없이 `--protocol http`를 사용하므로, `otelgen`은 인증서 검증을 거쳐 HTTPS로 연결합니다. 엔드포인트 인수에서 `https://`를 제거하더라도 TLS가 비활성화되지는 않습니다. 각 요청은 관리형 텔레메트리 API Key로 인증됩니다.
      </Step>

      <Step title="트레이스 생성" id="generate-traces-managed">
        여러 스팬으로 구성된 트레이스를 짧은 시간 동안 연속으로 전송합니다.

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate`는 초당 트레이스 수이고, `--duration`은 실행 시간(초)입니다. 인증서 검증을 거친 HTTPS로 연결되도록 `--insecure`는 생략하십시오.
      </Step>

      <Step title="로그 생성" id="generate-logs-managed">
        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          logs multi --duration 10
        ```
      </Step>

      <Step title="메트릭 생성" id="generate-metrics-managed">
        다음 명령을 실행하여 메트릭을 생성하고, 몇 초 후 `Ctrl+C`를 눌러 중지하십시오.

        ```shell
        otelgen --otel-exporter-otlp-endpoint "${OTEL_ENDPOINT}" \
          --header "authorization=Bearer ${OTEL_API_KEY}" \
          --protocol http \
          --rate 2 \
          metrics sum
        ```

        `otelgen`은 `metrics` 아래에 `gauge`, `histogram`, `up-down-counter`, `exponential-histogram` 하위 명령어도 제공합니다.
      </Step>

      <Step title="ClickHouse Observability에서 확인" id="verify-managed">
        ClickHouse Observability 서비스에서 **검색**을 열고 **Logs**와 **Traces** 소스를 번갈아 선택하여 새 이벤트가 들어왔는지 확인합니다. 시간 범위를 **Last 15 minutes**로 설정하고 기본 서비스 이름인 `otelgen`을 찾습니다.

        **차트 탐색기**를 열고 **Metrics**를 선택한 다음, `otelgen.metrics.sum`을 차트로 표시하여 메트릭이 수집되는지 확인합니다.
      </Step>
    </Steps>
  </Tab>

  <Tab title="자가 관리형">
    [`otelgen`](https://github.com/krzko/otelgen)은 합성 OTLP 로그, trace, 메트릭을 생성하는 작은 Go CLI입니다. 이 도구를 사용하면 기존 ClickStack OpenTelemetry 수집기가 데이터를 정상적으로 수신하는지, 그리고 이벤트가 관측성 UI에 표시되는지 확인할 수 있습니다.

    이 가이드는 collector가 이미 실행 중이며 `4317`(gRPC) 및 `4318`(HTTP)에서 OTLP 엔드포인트를 제공하고 있다고 가정합니다.

    <Steps>
      <Step title="사전 요구 사항" id="prerequisites-managed-self-configured">
        이 가이드는 [ClickHouse Observability — 자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 완료했고, `otelgen`을 실행하는 머신에서 OTLP gRPC(`4317`) 및 HTTP(`4318`) 엔드포인트에 접근할 수 있는 OpenTelemetry collector가 실행 중이라고 가정합니다. `OTLP_AUTH_TOKEN`으로 [collector를 보호](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)했다면 해당 값을 미리 준비해 두십시오.
      </Step>

      <Step title="otelgen 설치" id="install-otelgen-managed-self-configured">
        Homebrew로 설치합니다:

        ```shell
        brew install krzko/tap/otelgen
        ```

        또는 Go로 설치합니다:

        ```shell
        go install github.com/krzko/otelgen@latest
        ```
      </Step>

      <Step title="환경 변수 설정" id="set-env-vars-managed-self-configured">
        collector 엔드포인트를 export하고, collector가 보호되어 있다면 인증 토큰도 함께 export하십시오:

        ```shell
        export OTEL_ENDPOINT=<host>:4317
        export OTLP_AUTH_TOKEN=<your_otlp_auth_token>
        ```

        사용 중인 collector의 호스트와 포트를 지정하십시오. collector가 같은 머신에서 실행 중이라면 `localhost:4317`입니다.

        <Info>
          **보호되지 않은 collector**

          ClickStack OpenTelemetry 수집기는 기본적으로 인증을 사용하지 않습니다. [collector 보호하기](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)에 따라 `OTLP_AUTH_TOKEN`을 설정하지 않았다면 여기서 `OTLP_AUTH_TOKEN`은 건너뛰고, 아래 명령어에서 `--header` 플래그를 제거하십시오.
        </Info>
      </Step>

      <Step title="trace 생성" id="generate-traces-managed-self-configured">
        여러 스팬으로 구성된 trace를 짧은 시간 동안 전송합니다:

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          traces multi
        ```

        `--rate`는 초당 trace 수이고 `--duration`은 실행 시간(초)입니다. `--insecure`는 gRPC 연결에서 TLS를 비활성화하는 옵션으로, `otelgen`을 collector의 평문 OTLP 포트로 연결할 때 필요합니다.
      </Step>

      <Step title="로그 생성" id="generate-logs-managed-self-configured">
        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 --duration 10 \
          logs multi
        ```
      </Step>

      <Step title="메트릭 생성" id="generate-metrics-managed-self-configured">
        metrics 하위 명령어는 `--duration`을 지원하지 않습니다. 명령을 실행하고 몇 초 후 `Ctrl+C`를 눌러 중지하십시오.

        ```shell
        otelgen --otel-exporter-otlp-endpoint ${OTEL_ENDPOINT} \
          --header "authorization=${OTLP_AUTH_TOKEN}" \
          --protocol grpc --insecure \
          --rate 2 \
          metrics sum
        ```

        `otelgen`은 `metrics` 아래에 `gauge`, `histogram`, `up-down-counter`, `exponential-histogram` 하위 명령어도 제공합니다.
      </Step>

      <Step title="관측성 UI에서 확인" id="verify-managed-self-configured">
        ClickHouse Cloud 콘솔에서 관측성 UI를 엽니다. `Search` 뷰에서 소스를 `Logs`와 `Traces`로 번갈아 전환하며 새 이벤트를 확인하십시오. 시간 범위는 `Last 15 minutes`로 설정합니다. `Chart Explorer`를 열고 `Metrics`를 선택한 다음, `otelgen`이 생성한 메트릭 이름 중 하나(예: `otelgen.metrics.sum`)로 차트를 만들어 메트릭이 수집되는지 확인하십시오.
      </Step>
    </Steps>
  </Tab>
