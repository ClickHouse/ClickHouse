이커머스 스토어의 표본(sample) 로그, 세션(Sessions), 트레이스, 메트릭을 사용하여 ClickHouse Observability를 살펴봅니다. 두 배포 모드 모두 동일한 데이터셋과 조사 워크플로를 사용합니다.

시작하기 전에 [완전 관리형 시작 가이드](/ko/clickstack/observability/getting-started) 또는 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 먼저 완료하십시오.

<Steps>
  <Step title="연결 구성" id="configure-your-connection">
    배포 방식을 선택하고, 샘플 데이터를 로드할 터미널에서 다음 변수를 설정하십시오.

    <Tabs>
      <Tab title="완전 관리형">
        <BetaBadge label="베타 제공" />

        **팀 설정 → 데이터**를 열고 **Managed Telemetry**를 찾으십시오. **OpenTelemetry Collector** 아래의 **URL** 옵션에서 OTLP HTTP 엔드포인트와 API Key를 복사하십시오. 전체 값을 확인하려면 **Reveal key**를 선택하십시오.

        `/v1/logs`와 같은 신호 경로를 제외한 기본 엔드포인트를 설정하십시오. 인증 값에는 `Bearer` 접두사를 포함해야 합니다.

        ```shell
        export CLICKSTACK_OTLP_ENDPOINT='<your-managed-otlp-http-endpoint>'
        export CLICKSTACK_AUTHORIZATION='Bearer <your-api-key>'
        ```

        이 예시에서는 collector를 배포할 필요가 없습니다.
      </Tab>

      <Tab title="자가 관리형" id="self-managed">
        ClickHouse Cloud 서비스에 연결된 ClickStack OpenTelemetry 수집기가 실행 중이어야 합니다. 연결을 구성하려면 [OpenTelemetry를 사용한 데이터 수집 가이드](/ko/clickstack/observability/ingesting-data/opentelemetry#self-managed)를, collector를 시작하려면 [배포 가이드](/ko/clickstack/self-configured/deployment/managed)를 참고하십시오.

        업로드 명령을 실행하는 머신에서 연결할 수 있는 collector의 OTLP HTTP 엔드포인트를 설정하십시오. `/v1/logs`와 같은 신호 경로를 제외한 기준 URL을 사용해야 합니다.

        ```shell
        export CLICKSTACK_OTLP_ENDPOINT='http://<collector-host>:4318'
        export CLICKSTACK_AUTHORIZATION=''
        ```

        collector에 인증이 필요하면 `CLICKSTACK_AUTHORIZATION`을 해당 수신기의 토큰으로 설정하십시오. `OTLP_AUTH_TOKEN`으로 보호되는 ClickStack 수집기라면 `Bearer` 접두사 없이 해당 값을 그대로 사용하십시오. 인증이 필요 없는 수신기라면 값을 비워 두십시오. 이 값에 ClickHouse 데이터베이스 비밀번호를 사용하면 안 됩니다.
      </Tab>
    </Tabs>
  </Step>

  <Step title="샘플 데이터 다운로드" id="download-sample-data">
    UI에 샘플 데이터를 채우려면 다음 파일을 다운로드하십시오.

    [샘플 데이터](https://storage.googleapis.com/hyperdx/sample.tar.gz)

    ```shell
    # curl
    curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
    # or
    # wget https://storage.googleapis.com/hyperdx/sample.tar.gz
    ```

    이 파일에는 마이크로서비스 기반의 간단한 전자상거래 스토어인 공개 [OpenTelemetry demo](https://github.com/ClickHouse/opentelemetry-demo)에서 수집한 예시 로그, 메트릭, 트레이스가 포함되어 있습니다. 이 파일을 원하는 디렉터리에 복사하십시오.
  </Step>

  <Step title="샘플 데이터 불러오기" id="load-sample-data">
    `sample.tar.gz`가 있는 디렉터리에서 **Bash**로 다음 명령어를 실행하십시오. 이 명령어는 위에서 구성한 엔드포인트로 샘플 데이터를 전송하며, 인증 헤더는 필요한 경우에만 추가합니다.

    ```bash
    set -eo pipefail

    auth_headers=()
    if [ -n "${CLICKSTACK_AUTHORIZATION:-}" ]; then
      auth_headers=(-H "Authorization: ${CLICKSTACK_AUTHORIZATION}")
    fi

    for filename in $(tar -tf sample.tar.gz); do
      endpoint="${CLICKSTACK_OTLP_ENDPOINT%/}/v1/${filename%.json}"
      echo "loading ${filename%.json}"
      tar -xOf sample.tar.gz "$filename" | while read -r line; do
        printf '%s\n' "$line" | curl --fail-with-body -sS -X POST "$endpoint" \
          -H "Content-Type: application/json" \
          "${auth_headers[@]}" \
          --data-binary @-
      done
    done
    ```

    이 과정은 OTLP 로그, 트레이스, 메트릭 소스가 데이터를 전송하는 상황을 시뮬레이션합니다. 운영 환경에서는 애플리케이션 SDK, 에이전트 또는 OpenTelemetry 수집기가 이러한 소스가 될 수 있습니다.

    ClickHouse Cloud 콘솔에서 서비스를 선택한 다음 ClickHouse Observability를 여십시오.

    [검색](/ko/clickstack/observability/features/search) 화면으로 돌아가 로드된 데이터를 확인하십시오. **Logs** 소스를 선택하고, 샘플 이벤트의 타임스탬프가 포함된 시간 범위를 지정하십시오. 아래 스크린샷은 샘플 로그가 **Live Tail**에 수신되는 모습입니다.

    데이터 로딩에는 몇 분 정도 걸립니다. 로딩이 완료될 때까지 기다린 후 다음 단계로 진행하십시오.

  <Step title="세션(Sessions) 탐색" id="explore-sessions">
    사용자들이 상품 결제에 문제를 겪고 있다는 보고를 받았다고 가정해 보겠습니다. 세션 리플레이를 사용하면 사용자가 실제로 어떤 경험을 했는지 확인할 수 있습니다.

    왼쪽 메뉴에서 **클라이언트 세션**을 선택하고, 로드된 샘플 세션이 포함되도록 시간 범위를 설정하세요.

    <div className="ch-image-lg">
      <Frame>
        ![오류 수가 강조 표시된 샘플 세션을 보여주는 클라이언트 세션 화면](/images/clickstack/getting-started/observability-sample-data-sessions.png)
      </Frame>
    </div>

    이 뷰에는 데모 스토어의 세션이 나열되며, 여기에는 익명 세션과 이메일 주소로 식별된 세션이 모두 포함됩니다.

    일부 세션에는 오류가 기록되어 있습니다. 이 예시에서 강조 표시된 세션에는 오류가 1개 있습니다.

    강조 표시된 세션을 선택하여 리플레이를 여세요. 플레이어 하단의 재생 버튼을 눌러 세션을 재생하세요.

    <div className="ch-image-lg">
      <Frame>
        ![OpenTelemetry demo 스토어프런트와 탐색 이벤트를 보여주는 세션 리플레이](/images/clickstack/getting-started/observability-sample-data-replay.png)

      오류 이벤트는 이벤트 목록에서 빨간색으로 표시됩니다.

  <Step title="로그 탐색" id="explore-logs">
    다른 결제 실패를 조사하려면 [검색](/ko/clickstack/observability/features/search)으로 돌아가십시오.

    소스로 **Logs**를 선택하고 **ServiceName** 필터(filter)에서 `payment`를 선택하십시오. 시간 범위는 앞서 조사한 세션이 포함되도록 설정하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![payment 서비스로 필터링된 검색 화면. 성공한 트랜잭션과 함께 카드 만료 오류 및 Visa 캐시 가득 참 오류가 표시됨](/images/clickstack/getting-started/observability-sample-data-payment-logs.png)
      </Frame>
    </div>

    결과에는 앞서 조사한 세션의 카드 만료 오류와 함께 반복적으로 발생하는 `Visa cache full: cannot add new item.` 오류가 포함되어 있습니다. payment 서비스 전반에서 오류가 언제 발생하는지 확인하려면 이러한 오류 로그를 시간 흐름에 따른 차트로 표시하십시오.
  </Step>

  <Step title="결제 오류를 차트로 표시" id="chart-payment-errors">
    **차트 탐색기**를 열고 **시계열**을 선택한 다음, 데이터 소스로 **로그**를 선택하십시오. 집계로는 **Count of Events**를 선택하십시오.

    **Where**에서 **Lucene**을 선택하고 다음 필터를 입력하십시오.

    ```text
    SeverityText:"error" ServiceName:"payment"
    ```

    샘플 데이터가 포함된 시간 범위를 설정한 후 **실행**을 선택하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![Lucene 필터를 사용하여 payment 서비스의 오류 로그 수를 시간대별로 집계하는 차트 탐색기](/images/clickstack/getting-started/observability-sample-data-payment-errors-chart.png)
      </Frame>
    </div>

    이 차트는 각 시간 간격별로 조건과 일치하는 오류 로그 수를 보여줍니다. 카드 만료 오류와 캐시 용량 초과 오류를 비롯하여 `payment` 서비스에서 발생한 모든 오류가 포함됩니다. 이 값은 로그 이벤트 발생 횟수이며, 중복을 제외한 결제 실패 건수가 아닙니다.
  </Step>
</Steps>
