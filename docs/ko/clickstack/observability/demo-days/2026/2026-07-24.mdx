## 메트릭 사용 환경 개선 {#metrics-experience-improvements}

*데모 진행자: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/rukel6KVmPY" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이번 업데이트에서는 Datadog에서 마이그레이션 중인 고객의 피드백을 바탕으로 메트릭 및 대시보드 작성 환경을 개선했습니다. 이 고객은 체계적으로 설계된 메트릭 워크플로를 갖추고 있습니다. 아직 모든 피드백을 반영하지는 못했지만, 피드백의 대부분은 수백 개의 시계열이 표시되는 대시보드에서 차트를 작성하고 분석하는 작업에 관한 것이었습니다.

한 가지 변경 사항은 메트릭과 직접 관련은 없지만 같은 논의에서 나온 것입니다. 이제 대시보드를 작성하는 동안 대시보드 타일이 화면에 표시되는 그리드에 맞춰 배치됩니다. 타일을 드래그하거나 크기를 조정하면 타일 뒤에 그리드가 나타나고 현재 위치 주변의 셀이 강조 표시됩니다. 이전에는 타일이 어디에 놓일지, 타일을 옮기면 다른 타일이 밀려날지 알기 어려웠습니다. 이제 그리드를 통해 두 가지를 모두 확인할 수 있습니다. 그리드는 레이아웃(layout) 엔진과 동일한 기하 구조를 사용하므로, 오른쪽과 아래쪽 가장자리를 포함해 가이드가 타일의 최종 위치와 정확히 일치합니다.

메트릭 관련 변경 사항은 시계열 수가 많은 차트에 초점을 맞췄으며, 이는 여러 차원(dimensions)으로 그룹화할 때 흔히 나타납니다. 이전에는 차트 위에 마우스를 올리면 해당 타임스탬프의 모든 시계열이 표시되었습니다. 시계열이 300개인 차트에서는 도구 설명이 차트보다 길어지기도 했고, 커서 아래의 시계열이 실제로 필요한 시계열인 경우도 드물었습니다.

이제 시계열이 10개를 초과하는 차트에서는 커서에 가장 가까운 시계열만 표시됩니다. 해당 시계열은 맨 위에 그려지고 나머지는 흐리게 표시됩니다. 시계열이 10개 이하인 차트는 기존처럼 전체 시계열이 정렬된 도구 설명을 표시하므로 동작이 바뀌지 않습니다. 범례는 더 간결해졌으며 완전히 숨길 수도 있습니다. 범례를 표시하면 선택 및 빠른 검색 컨트롤로도 사용할 수 있어 특정 시계열로 쉽게 이동할 수 있습니다.

가장 큰 변화는 전체 화면 모드입니다. 사용자는 분석하고 싶은 편차를 발견하면 주로 전체 화면으로 전환합니다. 이제 전체 화면 모드는 케밥 메뉴 대신 툴바 아이콘에서 한 번의 클릭으로 열 수 있습니다. 전체 화면을 열면 범례가 요약 정보와 검색 상자를 갖춘 더 유용한 레이아웃으로 바뀝니다. 시계열 이름의 부분 문자열로 필터링하면 300개의 시계열을 관심 있는 몇 개로 좁혀 바로 마우스를 올려 비교할 수 있습니다.

논의 이후 한 가지 사항이 변경되었습니다. 단일 시계열 도구 설명과 다중 시계열 도구 설명 중 어느 것을 사용할지를 고정된 임계값에 의존하는 대신 직접 구성할 수 있게 될 예정입니다. 시계열이 많지 않을 때는 특정 시점에서 여러 시계열의 절댓값을 비교하는 것이 유용하므로, 사용자가 차트에 맞는 동작을 선택할 수 있어야 하기 때문입니다.

## 트레이스 뷰어 개선 사항 {#trace-viewer-improvements}

*데모 진행자: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kmparH3U7Jc" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

새롭게 디자인된 트레이스 뷰어에 두 가지 작은 수정 사항이 적용되었습니다. 두 가지 모두 새 레이아웃에 대한 피드백을 직접 반영한 것입니다.

최근 스팬 상세 정보 패널이 워터폴 오른쪽으로 옮겨졌는데, 이 위치를 모든 사용자가 선호하지는 않았습니다. 이제 패널의 닫기 버튼 옆에 추가된 컨트롤을 사용하여 패널을 오른쪽(기본값)이나 하단으로 옮길 수 있습니다. 패널을 하단에 두면 드래그하여 원하는 높이로 조정할 수 있습니다.

같은 피드백 스레드에서 줄 바꿈 관련 버그도 발견되었습니다. 줄 바꿈을 활성화해도 자연스럽게 줄을 바꿀 지점이 없는 긴 속성 값은 여전히 잘려서 표시되었습니다. 공백, 하이픈, 대시가 전혀 없는 `url.path`가 대표적인 예입니다. 이제 속성 값이 문자 단위로 줄 바꿈되므로 전체 값을 확인할 수 있습니다.

## MCP 서버 및 평가 개선 사항 {#mcp-server-and-eval-improvements}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/2NXRdBZcKMw" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이번 변경 사항 중 가장 작은 변경이 도입에는 가장 큰 영향을 미칠 수 있습니다. 기존에는 ClickHouse Cloud에서 MCP 서버를 활성화하는 방법을 찾기 어려웠습니다. 사용자는 앱의 안내를 따른 뒤 올바른 컨트롤 플레인 설정을 직접 찾아야 했습니다. 이제 버튼을 누르면 관련 모달이 바로 열리고, 여기서 서버를 활성화할 수 있습니다.

Brandon은 [최근 작업](https://clickhouse.com/blog/benchmarking-the-clickstack-mcp-server-with-hdx-evals)에 이어 MCP 평가 프레임워크를 계속 개선하고 있습니다. 이제 평가 프레임워크에서 평가 대상과 다른 provider 및 모델을 사용할 수 있습니다. 이전에는 전체 평가에 Anthropic 모델을 사용해야 했기 때문에 모델이 자신의 출력을 직접 채점하게 되는 경우가 있었습니다. 이제 OpenAI 키와 provider 접두사가 붙은 심사 모델 명세를 지정하여 채점을 OpenAI로 라우팅할 수 있습니다.

여러 심사 모델을 비교해 보니 유용한 차이가 드러났습니다. 일부 모델은 채점 기준을 훨씬 엄격하게 적용하여 특정 키를 사용하지 않으면 실행을 실패로 처리하는 반면, 다른 모델은 충분히 근접한 답변이면 통과시킵니다. 또한 이 작업 중 발견된, 오래된 채점 결과가 남는 버그도 수정했습니다. 이제 다른 심사 모델로 배치를 다시 채점하면 이전 결과(result)를 반환하지 않고 새 심사 모델이 실행됩니다.

Brandon은 서비스 상태 검사 시나리오에서 더 높은 점수를 얻으려면 무엇이 필요한지 MCP 서버에 직접 물어본 뒤, 새로운 `clickstack_emerging_signals` MCP 도구도 추가했습니다. 이 도구는 두 개의 윈도우를 비교하여 새로운 패턴을 탐지합니다. 기준 윈도우와 현재 윈도우에서 각각 로그 및 이벤트 패턴을 추출한 뒤 두 집합을 비교하고, 새로 나타났거나 빈도가 크게 증가했거나 사라진 패턴을 보고합니다.

이는 기존 도구와 다른 방식입니다. 이벤트 패턴은 하나의 윈도우 안에서 흔히 나타나는 항목을 보여 주고, 이벤트 차이는 어떤 속성이 변경되었는지를 보여 줍니다. 새 도구를 사용하면 서비스 상태 검사 점수가 약 10점 높아집니다.

스킬에서 수집을 설정하고 싶다는 요청에 따라 소스 및 웹훅 CRUD 도구도 MCP에 추가되었습니다. 이제 에이전트는 소스와 웹훅을 읽는 것뿐만 아니라 생성, 업데이트, 삭제도 할 수 있습니다.

현재는 PR 설명에 점수를 수동으로 붙여 넣고 있는데, 이를 대체하기 위해 모든 풀 리퀘스트마다 CI에서 평가를 실행하는 작업이 진행 중입니다. S3 seed 기능은 이미 동작합니다. 남은 걸림돌은 GitHub Action에 버킷 접근 권한을 부여하는 것입니다. 이 문제가 해결되면 평가 결과를 훨씬 빠르게 받아 볼 수 있습니다.
