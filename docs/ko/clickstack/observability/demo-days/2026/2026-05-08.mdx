## 웹훅의 시크릿 처리 개선 {#improved-handling-of-secrets-in-webhooks}

*데모 진행자: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/aD7sT5dc470" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

웹훅 URL과 헤더에는 자격 증명이 그대로 드러난 채 포함되는 경우가 많습니다. Slack 웹훅 URL은 경로에 시크릿 토큰이 들어 있고, HTTP 웹훅은 대개 인증을 위해 Authorization 헤더가 필요합니다. 이번 릴리스 이전까지 HyperDX에서 웹훅 목록 조회 및 편집에 사용하는 내부 API는 요청할 때마다 이러한 정보를 모두 그대로 반환했습니다. 따라서 인증된 팀 멤버라면 누구나 API를 호출하기만 해도 시크릿을 읽을 수 있었습니다.

이번 변경으로 퍼블릭 API에서 이미 사용하던 것과 동일한 마스킹 방식이 적용됩니다. 웹훅 URL은 경로가 `****`로 대체되어 반환되므로 Slack 토큰(또는 경로에 포함된 기타 키)이 서버 밖으로 나가지 않습니다. 헤더도 기본적으로 마스킹됩니다. 어떤 헤더에 시크릿이 담겨 있는지 확실히 판별할 방법이 없으므로 모든 값을 `****`로 대체하고 헤더 이름만 표시합니다.

편집 폼은 마스킹된 값을 &quot;변경 없음&quot;으로 처리합니다. 값을 그대로 두면 저장된 값이 유지되고, 변경하면 새 값이 저장되며, 지우면 해당 필드가 완전히 제거됩니다. 따라서 가장 흔한 경우(필드 하나만 편집)에도 워크플로가 직관적으로 유지되며, 실제 시크릿이 브라우저를 거쳐 왕복되는 일도 없습니다.

**관련 PR:** [#2239](https://github.com/hyperdxio/hyperdx/pull/2239) [HDX-4173] 내부 웹훅 API 응답에서 민감한 필드 마스킹

## 알림의 추가 메타데이터 {#extra-metadata-in-alerts}

*데모 진행자: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/evEd7Cc9e1c" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

커뮤니티 Slack에서 알림에 자유 형식의 컨텍스트를 추가할 수 있게 해 달라는 요청이 있었습니다. 임계값 이력, 런북 링크, 온콜 담당자를 위한 메모 등을 남길 공간이 필요하다는 것이었습니다. 이 기능은 AI 요약의 기준 정보로도 유용합니다. 이제 발생한 알림에 대응하는 LLM은 쿼리만 보고 의도를 추측하지 않고, 운영자가 직접 남긴 판단 근거를 바탕으로 작업할 수 있습니다.

메모 필드는 Markdown 렌더링을 지원하므로 접을 수 있는 섹션, 목록, 링크를 모두 사용할 수 있습니다. 메모는 알림 구성에 저장되며, 알림이 표시되는 모든 곳에 함께 나타납니다. UX는 아직 확정되지 않았습니다. 현재의 Markdown 표시 방식은 출발점일 뿐이며, 렌더링 방식에 대한 피드백을 환영합니다.

이 PR에서는 저장된 검색에서 발생 중인 알림의 UX도 함께 개선했습니다. 알림이 발생하면 알림 버튼의 종 아이콘에 빨간 점이 표시되고, 대화 상자에서는 단순히 링크만 제공하지 않고 어떤 알림이 활성 상태인지 강조 표시합니다. 또한 시각적 표현을 대시보드 타일이 같은 상태에서 이미 사용하는 방식과 일치시켰습니다.

**관련 PR:** [#2210](https://github.com/hyperdxio/hyperdx/pull/2210) [HDX-3044] Add optional note field to 알림

## 테마 추가 가능성 {#possible-themes}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/JZYGz6ZOPf4" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

해커톤에서 진행한 실험으로, IDE에서 착안한 3가지 테마를 ClickStack UI에 도입했습니다. Nord(북극풍 블루), Catppuccin(파스텔), One Dark(Atom 스타일)이며, 각 테마는 라이트 및 다크 버전을 제공합니다. 원본 테마에서 색상 토큰을 생성하는 방식을 시도해 대부분 완성할 수 있었지만, 사이드바 색상과 선 대비 등 일부 다듬어지지 않은 부분은 여전히 정리가 필요했습니다.

결국 이 PR은 머지되지 않고 닫혔습니다. 팀은 현재 단일 테마만 지원하는 ClickUI로 전환하고 있으며, 여러 토큰 세트를 병렬로 유지하면 작업 부담이 계속 발생합니다. 특히 각 조합의 대비를 제대로 검사하기 시작하면 부담은 더욱 커집니다. 이에 따라 ClickUI 자체가 다중 테마를 지원할 때까지 보류하기로 결정했습니다.

다만 이 실험에서 얻은 디자인 원칙 하나는 향후 작업을 재개할 때 참고할 만하다고 판단했습니다. 첫 번째 시안에서는 테마마다 HyperDX 로고의 색상을 바꿨는데, 이 때문에 브랜드 정체성이 사라졌습니다. 더 깔끔한 방식은 라이트 테마에서는 어두운 로고를, 다크 테마에서는 밝은 로고를 표시하고, 녹색 HyperDX 워드마크 자체는 그대로 두는 것입니다.

**관련 PR:** [#2191](https://github.com/hyperdxio/hyperdx/pull/2191) feat: add IDE-inspired themes (Nord, Catppuccin, One Dark)
