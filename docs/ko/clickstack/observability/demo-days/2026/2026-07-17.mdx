## 차트 도구 설명 개선 사항 {#chart-tooltip-improvements}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/EsnGp9RPSKM" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

ClickStack의 차트 도구 설명(tooltip) 사용성이 크게 향상되었습니다. 이제 차트를 클릭하면 마우스를 다른 곳으로 옮겨도 도구 설명이 사라지지 않고 그 자리에 고정되므로, 데이터를 여유 있게 살펴볼 수 있습니다. 고정된 도구 설명에는 시계열의 모든 값이 표시되며, 값이 많으면 잘리지 않고 목록을 스크롤하여 확인할 수 있습니다.

또한 이제 도구 설명에서 값을 바로 복사할 수 있습니다. 이 기능은 고객 피드백을 직접 반영한 것입니다. 이전에는 원하는 데이터를 볼 수는 있어도 가져올 방법이 없었지만, 이제는 값을 클릭하기만 하면 클립보드에 복사됩니다.

이 모든 개선은 Recharts 업그레이드를 기반으로 하며, 도구 설명은 이제 차트 자체의 컨테이너 내부가 아닌 포털(portal)을 통해 렌더링됩니다. 이 변경은 많은 차트가 촘촘하게 배치된 대시보드에서 특히 효과적입니다. 도구 설명이 더 이상 인접한 차트에 가려 찌그러지거나 잘리지 않기 때문입니다.

**관련 풀 리퀘스트:** [#2642](https://github.com/hyperdxio/hyperdx/pull/2642) feat(charts): pin chart tooltip on click with inline drill-down actions

## PR에서 MCP 평가 실행하기 {#running-mcp-evals-from-a-pr}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/YcDm1Mnw-Qc" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 팀은 로컬 환경뿐 아니라 GitHub PR에서도 MCP 평가를 직접 실행할 수 있습니다. 따라서 코드 변경 사항이 머지되기 전에 MCP 품질에 어떤 영향을 주는지 누구나 확인할 수 있습니다. 이번에 처음 도입된 구성으로, 평가 파이프라인을 CI에 연결하여 평가가 자동으로 실행되고 통합된 점수가 PR에 보고되도록 합니다.

ClickStack MCP 평가 프레임워크의 작동 방식에 대한 자세한 내용은 블로그 게시물 [HDX 평가로 ClickStack MCP 서버 벤치마킹하기](https://clickhouse.com/blog/benchmarking-the-clickstack-mcp-server-with-hdx-evals)를 참고하십시오.

**관련 풀 리퀘스트:** [#2628](https://github.com/hyperdxio/hyperdx/pull/2628) feat(evals): M1 CI skeleton — run MCP evals end to end in GitHub Actions

## MCP 서버의 메트릭 지원 {#metrics-support-in-the-mcp-server}

*데모 진행자: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/GqJWQN3P86c" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 MCP 서버는 로그와 트레이스뿐 아니라 메트릭도 이해하며, MCP 서버가 메트릭을 얼마나 잘 활용하는지 측정하는 평가 프레임워크도 함께 제공됩니다. 이번 변경으로 ClickStack이 지원하는 5가지 메트릭 유형(게이지, sum, 히스토그램, 지수 히스토그램, 요약)용 generator가 추가되었습니다. 또한 메트릭이 있어야만 해결할 수 있는 평가 시나리오도 새로 추가되었습니다. 대표적인 예가 JVM 메모리 누수로, 로그와 트레이스만으로는 사실상 원인을 밝혀낼 수 없는 시나리오입니다.

초기 결과에 따르면 메트릭을 인식하는 MCP 서버는 표준 SQL만 사용하는 MCP 서버보다 이러한 시나리오를 눈에 띄게 빠르게 해결합니다. 이는 주로 답에 도달하기까지 필요한 도구 호출 횟수가 더 적기 때문입니다. 아직 조정할 부분은 남아 있지만(일부 시나리오에서는 동일한 메트릭이 서로 다른 표기법으로 나타나 LLM의 패턴 매칭이 혼동을 일으킵니다), 방향성은 분명합니다. 에이전트가 메트릭에 직접 액세스할 수 있게 되면서 이전에는 불가능했던 조사가 가능해졌습니다.

**관련 풀 리퀘스트:** [#2645](https://github.com/hyperdxio/hyperdx/pull/2645) feat(evals): support metric types and seeding

## 소스 선택기 개선 {#source-picker-improvements}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/XTQygZSMUTs" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이전에는 원하는 소스를 선택하려면 목록을 스크롤하며 짐작해야 했습니다. 소스 목록이 긴 인스턴스에서는 드롭다운을 열어도 실제로 어떤 소스가 선택되어 있는지 시각적으로 구분할 방법이 없었습니다. 이번 업데이트에서는 기존 다중 선택 방식과 마찬가지로 현재 선택된 소스 옆에 체크 표시가 나타나므로, 쿼리를 시작하기 전에 어떤 소스가 활성 상태인지 한눈에 확인할 수 있습니다.

작은 변경이지만, 하루 업무 중 반복되던 &quot;지금 어떤 소스를 보고 있는 거지?&quot; 하는 순간을 없애 줍니다.

**관련 풀 리퀘스트:** [#2651](https://github.com/hyperdxio/hyperdx/pull/2651) feat(app): clarify selected source in source picker

## 차트 빌더에서 SQL로 변환 {#chart-builder-to-sql-conversion}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/IBNdi1rgiTc" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이전에는 시각적 쿼리 빌더(query builder)에서 원시 SQL 모드로 전환하면 처음부터 다시 작성해야 했습니다. 빌더에서 필터와 group-by로 쿼리를 구성하다가 빌더로는 표현할 수 없는 상황이 생겨 SQL 모드로 전환하면 빈 편집기만 남았습니다.

이제는 SQL 모드로 전환하면 빌더 쿼리가 차트를 렌더링하는 것과 동일한 파이프라인을 거칩니다. 따라서 하드코딩된 값 대신 적절한 매크로를 사용한 동등한 쿼리가 이미 작성된 상태로 SQL 모드가 열립니다. 반대 방향의 변환(SQL에서 빌더로)은 아직 지원되지 않지만 로드맵에 포함되어 있습니다.

**관련 풀 리퀘스트:** [#2634](https://github.com/hyperdxio/hyperdx/pull/2634) feat: Auto-convert builder charts to Raw SQL, [#2666](https://github.com/hyperdxio/hyperdx/pull/2666) fix(charts): Keep selected source when switching from builder to SQL mode

## 새로운 필터 가져오기 메커니즘 {#new-filter-fetching-mechanism}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/z31cAIJA3B4" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

사용 가능한 필터 값 목록을 가져오는 과정에 더 똑똑한 라우팅 계층이 도입되었습니다. 새로운 시스템은 하나의 고정된 전략 대신 스키마(schema)에서 사용할 수 있는 요소, 특히 텍스트 인덱스(Text indexes)가 있는지를 확인한 후 필터 목록을 구성하는 가장 효율적인 방법을 선택합니다.

텍스트 인덱스를 사용할 수 있으면 ClickStack은 롤업 테이블로 폴백하지 않고 텍스트 인덱스를 직접 쿼리합니다. 따라서 유지 관리해야 할 롤업이 줄어들고, 일부 고객이 기존 방식에서 겪었던 메모리 압력 위험도 낮아집니다. 이 기능을 사용하려면 ClickHouse 26.3이 필요합니다. 아직 해당 버전을 사용하지 않는 환경에서는 업그레이드 전까지 기존의 롤업 기반 방식이 계속 사용되며, 업그레이드하면 새로운 방식이 자동으로 적용됩니다.

**관련 풀 리퀘스트:** [#2643](https://github.com/hyperdxio/hyperdx/pull/2643) feat: rework getAllKeyValues and add filters populated from text indices
