## PromQL 및 Lucene에서의 대시보드 변수 {#dashboard-variables-in-promql-and-lucene}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/q5pP20p4nY4" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 PromQL 차트에서도 대시보드 변수를 사용할 수 있습니다. 변수 참조 시 자동 완성이 제공되며, 누락된 변수나 지원되지 않는 사용 방식(매크로, 따옴표가 필요한 참조 등)에 대해서는 경고가 표시됩니다. 또한 기존의 생성된 SQL 패널 옆에 생성된 PromQL 프리뷰가 추가되어, 현재 선택한 값이 대입된 쿼리를 확인할 수 있습니다.

이제 Lucene 변수에서 정확한 일치를 지원합니다. 이전에는 `ServiceName:$service`가 `ServiceName:("add" OR "cart")`로 확장되었습니다. 따옴표가 없는 Lucene 필드 일치는 부분 문자열 일치로 처리되므로, 이는 `ServiceName ILIKE '%add%' OR ServiceName ILIKE '%cart%'`가 됩니다. 그 결과 서비스 2개를 선택했는데 4개가 반환되는 일이 생길 수 있었습니다.

이제 변수를 `ServiceName:"$service"`처럼 따옴표로 감싸면 `(ServiceName:"add" OR ServiceName:"cart")`로 확장되어, 선택한 각 값과 정확히 일치하는 항목만 찾습니다. 이는 변수 없이 따옴표로 감싼 필드 일치의 기존 동작과 동일합니다. 자동 완성에서도 따옴표로 감싼 형식을 제안합니다.

이제 차트 도구 설명이나 테이블 행에서 검색 페이지로 drill-down하면, 페이지를 이동하기 전에 변수와 매크로가 먼저 확장됩니다. 검색 페이지는 변수를 인식하지 못하기 때문에, 이전에는 `$service`가 그대로 전달되어 잘못된 결과가 나오거나 쿼리 오류가 발생했습니다. 선택된 값이 없는 매크로는 `(1=1)`로 확장됩니다. 검색 페이지의 `WHERE` 입력란에서는 다소 보기 좋지 않지만, 쿼리는 유효하게 유지됩니다.

이제 필터 선택 값은 표현식이 아닌 변수 이름을 키로 저장됩니다. 따라서 서로 다른 소스의 `ServiceName`처럼 동일한 표현식을 사용하는 두 필터가 더 이상 선택 값을 공유하지 않습니다.

Brandon의 제안에 따라, 이제 필터 편집 중에 Escape 키를 누르면 변경 사항을 폐기하기 전에 확인을 요청합니다. 이전에는 도구 설명을 닫으려다가 편집 내용 전체가 사라질 수 있었습니다.

대시보드 변수는 이번 주에 운영 환경에 배포되었습니다. 기능 토글은 제거되었으며, 참조 형식과 매크로에 대한 내용은 [공개 문서](https://clickhouse.com/docs/clickstack/features/dashboards/overview#dashboard-variables)에서 확인할 수 있습니다.

**관련 풀 리퀘스트:** [#2994](https://github.com/hyperdxio/hyperdx/pull/2994) PromQL 차트에서 변수 대입, [#2995](https://github.com/hyperdxio/hyperdx/pull/2995) PromQL 변수 자동 완성 추가, [#2997](https://github.com/hyperdxio/hyperdx/pull/2997) 유효하지 않은 PromQL 변수 사용에 대한 경고 표시, [#2998](https://github.com/hyperdxio/hyperdx/pull/2998) 생성된 PromQL 프리뷰 추가, [#2987](https://github.com/hyperdxio/hyperdx/pull/2987) 정확한 일치 Lucene 변수 참조 분배, [#3008](https://github.com/hyperdxio/hyperdx/pull/3008) drill-down으로 검색 페이지 이동 전 변수 확장, [#2963](https://github.com/hyperdxio/hyperdx/pull/2963) 변수 키 기반 대시보드 필터 값 허용, [#2964](https://github.com/hyperdxio/hyperdx/pull/2964) 변수 키 기반 필터 상태 영구 저장 및 읽기, [#3005](https://github.com/hyperdxio/hyperdx/pull/3005) 필터 편집기를 닫을 때 저장되지 않은 변경 사항 폐기 전 확인, [#3009](https://github.com/hyperdxio/hyperdx/pull/3009) 대시보드 변수 기능 토글 제거

## 양방향 스팬 링크 {#span-links-in-both-directions}

*데모 진행자: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tdK9JU6unoE" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

스팬 링크는 이전부터 확인할 수 있었지만, 컨슈머 측에서만 가능했습니다. 각 링크는 &quot;Open trace&quot; 작업으로만 표시되었고, 프로듀서 스팬에서 출발하여 해당 스팬을 링크하는 스팬을 찾을 방법은 없었습니다. 이에 한 사용자가 GitHub 이슈로 이 기능을 요청했습니다.

이제 Span Links 섹션에 각 대상 스팬의 이름, 서비스, 소요 시간, 타임스탬프가 표시됩니다. 따라서 링크가 여러 개 있어도 하나하나 열어 보지 않고 원하는 링크를 쉽게 고를 수 있습니다. 대상 스팬을 찾을 수 없을 때는 기존처럼 &quot;Open trace&quot;가 폴백으로 사용됩니다.

새로 추가된 &quot;Linked from&quot; 섹션에는 현재 스팬을 링크하는 스팬이 나열됩니다. 이제 컨슈머의 링크를 따라 프로듀서로 이동한 다음, 그곳에서 해당 컨슈머를 확인할 수 있습니다.

브레드크럼 경로상의 바로 이전 스팬으로 향하는 링크를 따라가면 해당 엔트리로 돌아가므로, 링크된 두 스팬 사이를 오가더라도 중복 엔트리가 계속 쌓이지 않습니다. 두 스팬 사이에 다른 엔트리가 있으면 평소처럼 새 엔트리가 추가됩니다.

역방향 조회(lookup)는 스팬 링크에 선택한 스팬 ID가 포함된 행을 찾은 뒤, 트레이스 ID가 일치하는지 검사합니다. 트레이스 ID 조회는 해당 컬럼의 블룸 필터 인덱스를 활용하지만, 역방향 조회는 스캔(Scan)이 필요하므로 데모보다 큰 trace 테이블에서는 더 느릴 수 있습니다. 성능이 문제가 되면 코드 주석에 제안된 대로 링크 스팬 ID에 인덱스를 추가할 수 있습니다.

**관련 풀 리퀘스트:** [#3011](https://github.com/hyperdxio/hyperdx/pull/3011) 역방향 스팬 링크 추가, 스팬 링크 세부 정보 표시

## 기본 제공되는 LLM 관측성 {#llm-observability-out-of-the-box}

*데모 진행자: [@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/m49DZ5cuI64" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이미 많은 팀이 LLM 및 코딩 에이전트의 텔레메트리를 ClickStack으로 전송하고 있지만, 이를 위한 전용 기능은 없었습니다. 채팅 렌더링, 토큰 및 비용 추적, 모델 분석 기능을 모두 사용할 수 없었습니다.

이제 기존 ClickHouse, Kubernetes, 서비스 프리셋과 더불어 LLM 대시보드가 제공됩니다. 이 대시보드는 토큰 사용량, 비용, 모델 호출, 도구 호출, 캐시 적중, 응답 시간을 보여 주며, 사용자 속성이 있으면 사용자별 분류도 제공합니다.

이 기능은 고정된 스키마(schema)나 전용 테이블, 수집 시점 처리 없이 기존 트레이스와 로그를 쿼리 시점에 읽어 들입니다. 일반적인 규칙(convention), OpenLLMetry 또는 OpenInference를 따르는 텔레메트리를 지원하며, OpenAI 및 Anthropic SDK, Vercel AI SDK, LangChain, Claude Code, opencode에서 생성된 데이터도 포함됩니다. 이미 수집된 텔레메트리에도 그대로 적용됩니다.

지연 시간 뷰(view)는 AI 관련 스팬을 상단에 표시하므로, 트레이스 전체를 일일이 살펴보지 않고도 느린 모델 호출을 쉽게 찾을 수 있습니다.

세션(Sessions) 뷰는 스팬을 대화별로 묶어 보여 줍니다. 세션을 열어 스팬을 확인한 다음 스팬 하나를 선택하면 세부 정보를 볼 수 있으며, 프롬프트가 기록된 경우 프롬프트도 함께 표시됩니다. 에이전트 실행을 디버깅할 때 유용하며, 동일한 세션 필터(filter)로 로그를 검색할 수도 있습니다.

이 기능의 범위는 평가 등 훨씬 다양한 기능을 지원하는 Langfuse 같은 전용 LLM 관측성 도구보다 의도적으로 좁게 설정되었습니다. ClickStack에 이미 있는 텔레메트리를 활용하여 오류율, 비용, 토큰, 지연 시간 등 일반적인 모니터링 요구 사항을 충족합니다.

**관련 풀 리퀘스트:** [#2990](https://github.com/hyperdxio/hyperdx/pull/2990) LLM 관측성 대시보드, 스팬 채팅 뷰 및 세션

## 차트 편집기에서 메트릭 탐색하기 {#browsing-metrics-in-the-chart-editor}

*데모 진행자: [@MikeShi42](https://github.com/MikeShi42)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/TkFa6Zzq23o" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

기존에는 메트릭을 선택하려면 종류별로 최대 3,000개에 달하는 이름이 나열된 1차원 목록을 검색해야 했습니다. 찾으려는 항목을 대략 알고 있다면 자동 완성이 도움이 되지만, 목록을 둘러보는 기능이 필요하다는 피드백이 여러 차례 있었습니다.

이제 메트릭 선택 항목 옆의 &quot;Browse metrics&quot; 컨트롤을 누르면 탐색기가 열리며, 왼쪽에는 카탈로그가, 오른쪽에는 선택한 메트릭의 세부 정보가 표시됩니다. 메트릭 이름은 점과 밑줄을 기준으로 분할되어 트리 구조로 표시됩니다. 자식이 하나뿐인 세그먼트는 불필요한 클릭을 줄이도록 하나로 합쳐집니다. `Metric`, `Type`, `Unit` 컬럼은 모든 수준에서 정렬이 유지됩니다. 전체 카탈로그를 검색하거나 1차원 목록으로 전환할 수도 있습니다.

이전에는 단위, 설명, 태그를 메트릭을 선택한 후에야 시계열 행 아래의 접힌 패널에서 확인할 수 있었습니다. 이제 세부 정보 창에서 선택하기 전에 이러한 정보를 미리 살펴볼 수 있으므로, 배포 환경에서 어떤 메트릭이 수집되는지, 어떤 태그로 그룹화할 수 있는지 파악할 수 있습니다. &quot;Use metric&quot;을 클릭하면 편집 중인 시계열에 선택한 메트릭이 적용됩니다.

이 기능은 안정화될 때까지 당분간 눈에 잘 띄지 않는 위치에 배치됩니다.

**관련 풀 리퀘스트:** [#3000](https://github.com/hyperdxio/hyperdx/pull/3000) 차트 편집기에 메트릭 탐색기 추가, [#3025](https://github.com/hyperdxio/hyperdx/pull/3025) 프라이머리 인덱스에서 메트릭 이름 스트리밍(진행 중), [#3054](https://github.com/hyperdxio/hyperdx/pull/3054) 메트릭 드롭다운 UX 개선

## Grafana의 원시 SQL 쿼리에 대한 로그 볼륨 {#log-volume-for-raw-sql-queries-in-grafana}

*데모 진행자: [@SpencerTorres](https://github.com/SpencerTorres)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/uehh44q56yE" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

눈에 보이는 변화는 작지만, 예상보다 많은 작업이 필요했습니다.

Grafana에서 쿼리 빌더(query builder)로 작성한 로그 쿼리는 플러그인이 어떤 컬럼을 사용해야 하는지 알기 때문에 결과 위에 볼륨 히스토그램이 표시됩니다. 반면 SQL 편집기에서 작성한 동일한 쿼리는 플러그인이 어떤 컬럼을 선택했는지 알 수 없어 히스토그램이 표시되지 않았습니다. 탐색에서는 그 대신 Grafana의 행 기반 히스토그램이 표시되었는데, 이 히스토그램은 쿼리의 `LIMIT`에 제한을 받았고 선택한 시간 범위도 반영하지 않았습니다.

이제 플러그인은 끝에 있는 `ORDER BY`와 `LIMIT`을 제거하고, 작성한 SQL을 파생 테이블로 감싼 뒤 전체 시간 범위에 걸쳐 집계합니다. 여기서는 `LIMIT`을 제거하는 것이 중요합니다. `LIMIT`이 남아 있으면 집계 대상이 원래 쿼리가 반환한 행으로 한정되기 때문입니다.

히스토그램에는 SQL 필터가 반영되며, 시간 범위를 변경하면 함께 갱신됩니다. 이 기능은 직접 작성한 SQL뿐 아니라 쿼리 빌더에서 &quot;Edit as SQL&quot;로 연 쿼리에도 적용됩니다.

다만 쿼리 재작성(query rewrite)이 제대로 동작하지 않는 예외적인 경우가 아직 남아 있을 수 있습니다.

**관련 풀 리퀘스트:** [grafana/clickhouse-datasource#2141](https://github.com/grafana/clickhouse-datasource/pull/2141) SQL 편집기 쿼리의 로그 볼륨 표시 (진행 중)

## 알림 페이지의 알림 채널 {#notification-channels-on-the-alerts-pages}

*데모 진행자: [@jordan-simonovski](https://github.com/jordan-simonovski)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/Gr-QkVVWam8" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

알림 하나는 최대 10개의 웹훅으로 통지를 보낼 수 있지만, 알림 목록과 상세 헤더에는 첫 번째 웹훅만 표시되었고 그마저도 웹훅 이름 대신 &quot;Webhook&quot;이라는 레이블로 표시되었습니다. 두 화면 모두 여전히 레거시 단일 채널 필드를 읽고 있었기 때문입니다.

다중 대상 디스패치는 정상적으로 동작했지만, 화면 표시 때문에 추가한 채널이 저장되지 않은 것처럼 보였습니다.

이제 목록과 상세 헤더에 구성된 모든 채널이 이름으로 표시됩니다. 웹훅과 incident.io 통합을 비롯한 채널의 추가 및 제거도 더 쉬워졌습니다. 또한 알림 시간이 대상별로 기록되므로 응답이 느린 통합을 파악할 수 있습니다.

이제 구성된 채널에 알림이 직접 전송됩니다. 이전에는 구성된 채널이 웹훅 멘션으로 변환되어 메시지 본문 끝에 추가되었는데, 이 방식에서는 알림이 누락될 수 있었습니다. 본문에 이미 임시 멘션이 이벤트당 한도에 도달할 만큼 포함되어 있으면 알림에 구성된 채널을 건너뛰었기 때문입니다.

컨트롤이 늘어나면서 페이지가 복잡해졌습니다. 이에 따라 내보내기와 Terraform을 포함한 행 작업을 하나의 메뉴로 묶었습니다.

**관련 풀 리퀘스트:** [#3001](https://github.com/hyperdxio/hyperdx/pull/3001) 알림 페이지에 모든 알림 대상 표시, [#2991](https://github.com/hyperdxio/hyperdx/pull/2991) 요약 줄에 모든 알림 채널 표시, [#2984](https://github.com/hyperdxio/hyperdx/pull/2984) 멘션 문자열 대신 구성된 채널에 직접 알림 전송, [#2961](https://github.com/hyperdxio/hyperdx/pull/2961) 실패한 멘션이 알림 슬롯을 소비하지 않도록 수정, [#3003](https://github.com/hyperdxio/hyperdx/pull/3003) 경보 알림 시간을 대상별로 기록, [#3002](https://github.com/hyperdxio/hyperdx/pull/3002) 알림 페이지의 모든 행 끝에 동일한 컨트롤 제공, [#3016](https://github.com/hyperdxio/hyperdx/pull/3016) 알림 상세 헤더를 공유 행 메뉴로 통합

## API 키를 표시 버튼 뒤에 숨기기 {#hiding-api-keys-behind-a-reveal}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/MNXABmTVEkE" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

기존에는 앱 곳곳에서 자격 증명이 평문으로 표시되었습니다. 팀 설정 페이지에는 수집 API key 전체가 그대로 표시되었고, MCP 설치 스니펫의 명령에는 개인 액세스 키가 포함되어 있었습니다. 두 경우 모두 화면 공유나 스크린샷을 통해 쉽게 노출될 수 있었습니다.

이제 키는 기본적으로 마스킹되며, 필요할 때 키를 표시할 수 있는 컨트롤이 제공됩니다. 수집 키, 개인 액세스 키, 그리고 커뮤니티에서 기여한 스니펫을 포함한 MCP 설치 스니펫은 모두 하나의 공유 구성 요소에서 처리됩니다.

복사하면 여전히 실제 값이 복사되므로, 키를 복사하기 위해 굳이 표시할 필요가 없습니다. 동일한 변경 사항이 ClickStack Cloud 온보딩에도 적용될 예정입니다.

**관련 풀 리퀘스트:** [#2988](https://github.com/hyperdxio/hyperdx/pull/2988) 공유 RevealSnippet을 사용하여 API key 및 MCP 설치 스니펫의 시크릿 마스킹

## 제품 내 릴리스 노트 {#release-notes-in-the-product}

*데모 진행자: [@jordan-simonovski](https://github.com/jordan-simonovski)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/4vrzXy8JwZY" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

기존에는 Help 메뉴의 &quot;What&#39;s new&quot; 패널이 PR별 changeset에서 `feat:` 접두사가 붙은 엔트리를 골라 표시했습니다. 이 때문에 v2.36.0에서는 대시보드 변수가 세 번이나 표시된 반면, 해당 릴리스의 주요 변경 사항이었던 수식(formula)과 알림 관련 작업은 누락되었습니다.

이제 이 패널은 릴리스 PR에서 함께 작성되고 검토되는 루트 `CHANGELOG.md`를 읽습니다. 또한 릴리스 generator가 패널에 표시되는 각 릴리스의 헤드라인을 제공합니다. 헤드라인 아래에는 호환되지 않는 변경 사항, 새로운 기능, 버그 수정 및 개선 사항이 표시되며, 각 항목에서 변경 로그로 바로 이동할 수 있는 링크가 제공됩니다.

이제 읽지 않은 릴리스 노트가 있으면 Help 버튼이 반짝이며, 이 효과는 JavaScript 없이 애니메이션 SVG로 구현되었습니다.

읽지 않음 상태 추적 방식도 수정되었습니다. 기존에는 앱의 빌드 버전을 기준으로 삼았기 때문에, git short SHA나 CI 빌드 번호가 포함된 배포 환경에서는 새 릴리스가 없어도 배포할 때마다 반짝임 효과가 트리거되었습니다. 이제는 변경 로그의 최신 릴리스 버전을 기준으로 합니다.

릴리스 노트 포맷도 개편되고 있으므로, 앞으로 더 많은 내용이 패널에 표시될 예정입니다.
