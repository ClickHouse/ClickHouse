## 새로운 대시보드 및 저장된 검색 목록 페이지 {#new-dashboard-and-saved-search-listing-pages}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/dQCkNZElwcg" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

대시보드와 저장된 검색이 사이드바를 벗어나 전용 목록 페이지로 이동했습니다. 팀에 대시보드가 어느 정도 쌓이면 기존 사이드바 방식은 금세 다루기 번거로워졌습니다. 새 페이지에서는 모든 항목이 태그별로 정리된 카드 보기로 표시되며, 이름 검색과 태그 필터링 기능이 기본으로 제공됩니다. 원하는 경우 더 간결한 목록 보기로 전환할 수도 있습니다.

이제 즐겨찾기 기능도 지원됩니다. 대시보드나 저장된 검색에 별표를 표시하면 목록 페이지 상단에 고정되고, 빠르게 액세스할 수 있도록 사이드바에도 다시 표시됩니다. 이전과 비슷한 방식이지만 다른 사용자의 탐색 메뉴를 어지럽히지 않습니다. 또한 목록 페이지의 각 카드에는 알림 상태 아이콘과 &quot;생성자 / 수정자&quot; 메타데이터가 표시되므로, 각 항목의 소유자와 현재 발생 중인 알림이 있는지를 한눈에 확인할 수 있습니다.

새로운 템플릿 갤러리도 추가되었습니다. Node.js, Python, Go, Java용 OTel 런타임 메트릭을 다루는 4개의 사전 구성된 대시보드를 클릭 몇 번만으로 가져올 수 있습니다. 가져오는 과정에서 태그와 대상 메트릭 소스를 편집할 수 있으므로 기존 태그 체계에 그대로 통합할 수 있습니다.

**관련 풀 리퀘스트:** [#1971](https://github.com/hyperdxio/hyperdx/pull/1971) 대시보드 목록 페이지 추가, [#2012](https://github.com/hyperdxio/hyperdx/pull/2012) 저장된 검색 목록 페이지 추가, [#2021](https://github.com/hyperdxio/hyperdx/pull/2021) 대시보드 및 저장된 검색 즐겨찾기 추가, [#2033](https://github.com/hyperdxio/hyperdx/pull/2033) 대시보드와 검색을 태그별로 그룹화, [#2031](https://github.com/hyperdxio/hyperdx/pull/2031) 생성/수정 메타데이터 표시, [#2053](https://github.com/hyperdxio/hyperdx/pull/2053) 대시보드 목록 페이지에 알림 아이콘 추가, [#2010](https://github.com/hyperdxio/hyperdx/pull/2010) 대시보드 템플릿 갤러리 추가

## 필터를 위한 필터 {#filters-for-filters}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

이제 대시보드 변수 필터에 자체 필터 조건(filter condition)을 지정할 수 있습니다. 도입 배경은 간단합니다. Node.js 대시보드에 &quot;서비스 이름&quot; 드롭다운이 있다면, 이 드롭다운에는 환경 내 모든 서비스가 아니라 Node.js 서비스만 표시되는 편이 바람직합니다. 이제 대시보드 변수에 필터 조건을 직접 구성하여 표시되는 항목의 범위를 좁힐 수 있습니다.

필터 셀렉터도 다중 선택을 지원하도록 업데이트되었습니다. 서비스별로 그룹화하는 대시보드에서는 드롭다운에서 여러 값을 한 번에 선택할 수 있어 비교 작업이 훨씬 수월해집니다.

**관련 풀 리퀘스트:** [#1969](https://github.com/hyperdxio/hyperdx/pull/1969) Add conditions to Dashboard 필터; Support filter multi-select

## 사전 설정 대시보드에 대한 RBAC {#rbac-for-predefined-dashboards}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

이제 ClickStack의 사전 설정 대시보드에도 역할 기반 접근 제어가 적용됩니다. 이전에는 이러한 내장 대시보드에 RBAC가 전혀 적용되지 않아, 할당된 역할과 관계없이 모든 사용자가 대시보드에 액세스할 수 있었습니다. 이번 업데이트로 이 공백이 해소되었습니다.

세분화된 읽기 권한도 의도한 대로 동작합니다. 특정 서비스에 대한 읽기 전용 액세스로 구성된 역할의 사용자는 해당 서비스와 관련된 사전 설정 대시보드만 볼 수 있습니다. 이 역할의 사용자는 대시보드와 필터를 볼 수 있지만, 필터 컨트롤은 잠겨 있어 편집할 수 없습니다. 데모에서는 특정 서비스로 범위가 지정된 &quot;services&quot; 읽기 권한을 가진 custom 역할을 구성하고, 해당 역할로 로그인한 사용자에게 액세스 권한이 있는 대시보드와 필터 상태만 정확히 표시되는 모습을 보여 줍니다.

## 검색 최적화 {#optimizations-for-searching}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/uVD2FKzoHjM" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickHouse의 「정렬된 순서로 읽기(Read in Order)」 최적화는 ORDER BY가 테이블의 프라이머리 키와 일치할 때 데이터를 순차적으로 읽다가 LIMIT에 도달하는 즉시 읽기를 중단하므로 검색 쿼리가 빠르게 실행됩니다. 그러나 벤치마킹 결과, 이 최적화를 적용하더라도 대규모 데이터 세트(datasets)에서는 검색 시 여전히 필요 이상으로 데이터를 가져오는 것으로 나타났습니다. 원인은 순회해야 하는 파트의 수에 있습니다. 최적화가 활성화되어 있더라도 테이블이 충분히 크면 파트 수도 많아지므로 ClickHouse가 필요한 것보다 더 많은 데이터를 읽게 됩니다.

이를 해결하기 위해 검색 쿼리에 사용되는 윈도우 쿼리 배열의 맨 앞에 1분 길이의 시간 윈도우(time window)를 추가했습니다. 대부분의 검색에서 필요한 데이터는 최근 1분 안에 있으므로, 이 윈도우를 먼저 조회하면 거의 즉시 결과가 반환됩니다. 이 윈도우에서 결과를 찾지 못하면 쿼리는 기존과 같이 점차 넓어지는 윈도우로 폴백합니다. 이와 별도로, `otel_traces` 스키마(schema)에서는 타임스탬프 컬럼에 사용된 `toDateTime(Timestamp)` 표현식이 인식되지 않아 ORDER BY 최적화가 올바르게 적용되지 않았습니다. 이 문제도 수정되었습니다.

**관련 풀 리퀘스트:** [#2019](https://github.com/hyperdxio/hyperdx/pull/2019) 검색에 1분 윈도우 사용, [#2014](https://github.com/hyperdxio/hyperdx/pull/2014) otel&#95;traces의 ORDER BY 최적화 문제 수정

## 행 복사 및 필터 크기 구성 {#copy-row-and-configurable-filter-sizes}

이제 행 뷰어에 JSON으로 복사 버튼이 추가되어 로그 행 전체를 클릭 한 번으로 복사할 수 있습니다. 이 버튼은 전체 사이드바 보기에도 표시됩니다. 행을 LLM 프롬프트에 붙여 넣어 해당 로그가 코드의 어느 부분에서 출력되는지 물어보거나, 텍스트 전체를 일일이 선택하지 않고도 인시던트 보고서에 쓸 이벤트 전체를 그대로 담아 둘 때 유용합니다.

사이드바에서 가져오는 필터 키 수를 이제 쿼리 설정(Query Settings)의 팀 설정에서 구성할 수 있습니다. 이전에는 제한이 고정되어 있어 대규모 데이터 세트(datasets)에서는 사용 가능한 필터 속성 중 일부만 표시되었습니다. 이제 팀에서 이 제한을 높여 더 많은 리소스 속성과 로그 속성을 표시할 수 있습니다. 또한 이번 변경에는 필터 그룹이 많이 표시되는 경우에도 필터 패널을 빠르게 렌더링할 수 있도록 가상화 개선 사항이 포함되어 있습니다.

**관련 풀 리퀘스트:** [#2035](https://github.com/hyperdxio/hyperdx/pull/2035) JSON으로 행 복사 버튼 추가, [#2020](https://github.com/hyperdxio/hyperdx/pull/2020) 가져올 필터 수에 대한 새 팀 설정, [#1979](https://github.com/hyperdxio/hyperdx/pull/1979) 중첩된 필터 그룹 가상화

## 대시보드의 탭과 그룹 {#tabs-and-groups-in-dashboards}

*데모 진행자: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/tyumDlJuDTg" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 대시보드 타일을 그룹으로 구성할 수 있습니다. 이 기능은 두 가지 컨테이너 유형(&quot;섹션&quot;과 &quot;그룹&quot;)이 따로 존재하여 사용자가 어떤 컨테이너 유형을 사용할지 미리 정해야 했던 기존 방식을 대체합니다. 단일 그룹 개념으로 통합되면서 구조가 더 단순해졌습니다. 그룹은 기본적으로 접을 수 있으며, 필요에 따라 테두리를 표시할 수 있고, 탭을 추가할 수도 있습니다. 각 탭은 고유한 타일 집합을 가지며, 드래그 핸들을 사용하여 타일을 다른 그룹으로 옮길 수 있습니다.

데모에서는 접기 켜기/끄기, 테두리 표시/숨기기, 탭 사용 여부 등 여러 사용자 정의 옵션을 전환하며 그룹을 보여 줍니다. 데모 시점에 해당 PR은 아직 리뷰 중이었으며 디자인 피드백을 수집하고 있었습니다. 이 PR이 병합되면 대시보드 작성자는 기존의 두 가지 컨테이너 유형 방식보다 더 유연하고 이해하기 쉬운 구성 요소를 사용할 수 있게 됩니다.

**관련 풀 리퀘스트:** [#1972](https://github.com/hyperdxio/hyperdx/pull/1972) 탭 및 접기/테두리 옵션을 지원하는 대시보드 그룹, [#2015](https://github.com/hyperdxio/hyperdx/pull/2015) 섹션/그룹을 단일 그룹으로 통합

## ClickStack CLI {#clickstack-cli}

*데모 진행자: [@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/9XqJNhstabw" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

ClickStack CLI(`hdx`)는 터미널을 벗어나지 않고도 로그와 trace를 검색하고, 실시간으로 추적(tail)하고, 검사할 수 있는 새로운 터미널 TUI입니다. 브라우저와 동일한 웹 세션 메커니즘으로 HyperDX 인스턴스에 연결하므로 별도의 API Key를 관리할 필요가 없습니다. 인스턴스 URL과 이메일로 `hdx auth login`을 한 번만 실행하면 이후에는 인증 상태가 유지됩니다.

TUI는 웹 앱과 동일한 검색 인터페이스를 제공합니다. 쿼리 구문(query syntax)과 소스 선택 방식이 같고, 개별 로그 항목을 자세히 살펴볼 수 있는 기능도 동일합니다. 특히 눈여겨볼 기능은 트레이스 워터폴 뷰로, 로그 항목을 클릭하면 전체 분산 트레이스가 터미널에 바로 렌더링됩니다. 데모에서는 에이전트형 활용에 대한 초기 실험도 함께 소개합니다. AI 에이전트에 CLI의 스키마(schema) 내부 검사 출력에 대한 액세스 권한과 ClickHouse 프록시를 통한 쿼리 실행 권한을 함께 부여하면, 에이전트가 자율적으로 문제를 조사할 수 있습니다. 데모는 한 걸음 더 나아가, 에이전트가 웹 세션을 사용해 Playwright로 HyperDX UI를 탐색하고 렌더링된 차트에서 메트릭을 가져와 로그에서 찾은 내용과 교차 검증하는 모습까지 보여줍니다.

**관련 풀 리퀘스트:** [#2043](https://github.com/hyperdxio/hyperdx/pull/2043) @hyperdx/cli 패키지 추가 — 이벤트 검색 및 실시간 추적을 위한 터미널 TUI
