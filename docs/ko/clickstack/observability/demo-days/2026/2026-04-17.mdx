이제 HyperDX에서 로그, 트레이스, 패턴 전반에 걸쳐 동작하는 AI 요약 기능을 제공합니다. 새로운 요약 버튼은 텔레메트리 데이터를 읽기 쉬운 요약으로 정리해 주므로, 이벤트를 하나하나 직접 확인하지 않고도 일련의 이벤트에서 어떤 일이 일어났는지 빠르게 파악할 수 있습니다.

이 아키텍처는 Anthropic(또는 유사한) API와 연동되도록 설계되었으며, 후속 대화를 지원하므로 사용자는 첫 요약 이후에도 이어서 질문할 수 있습니다.

이벤트 차이(Event Deltas) 히트맵 시각화를 기본 차트 빌더로 옮기는 작업이 진행 중입니다. 이를 통해 HyperDX의 다른 시각화와 마찬가지로 표준 차트 유형으로 사용할 수 있게 됩니다. 기존에는 별도의 전용 뷰에서만 제공되었지만, 이제는 차트 탐색기에서 다른 차트 유형과 함께 사용할 수 있습니다.

작업이 완료되면 사용자는 이벤트 차이 히트맵을 대시보드 타일에 바로 추가할 수 있으며, 다른 차트와 마찬가지로 필드 필터링과 시간 범위 조정 기능을 그대로 사용할 수 있습니다. 현재 작업이 진행 중입니다.

## 스키마(schema) 개선을 위한 벤치마킹 {#benchmarking-for-schema-improvements}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/_B7TmIiXZyM" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Aaron이 HyperDX의 새로운 기본 OpenTelemetry 로그 스키마에 대한 벤치마킹 결과를 소개합니다. 핵심 변경 사항은 레거시 `timestamp_time` 컬럼(초 단위 세분화 수준의 32비트 Unix 타임스탬프)을 삭제하고 `timestamp`만 사용하도록 한 것입니다. `timestamp`는 나노초 정밀도를 제공하며, 이 변경으로 스키마의 컬럼이 하나 줄어듭니다. 다양한 쿼리 벤치마크에서 새 스키마는 거의 모든 경우에 기존 스키마와 동등하거나 더 나은 성능을 보였습니다.

최종 스키마에는 읽기 순서 최적화도 포함되어 있어, 선택도가 높은 쿼리에서 상당한 성능 향상을 보입니다. 비교적 드문 맵 값을 검색할 때는 기준값 대비 약 2배 빠르게 실행되었으며, 자주 등장하는 값에 대한 조회는 그보다 더 크게 개선되었습니다. 삽입 성능(insert performance) 측면의 부담은 약간 늘어나지만(유지해야 할 컬럼이 더 많기 때문), 쿼리 성능(query performance)은 전반적으로 동등하거나 향상되었으므로 부담 없이 적용할 수 있는 업그레이드입니다.

**관련 풀 리퀘스트:** [#2125](https://github.com/hyperdxio/hyperdx/pull/2125) feat: optimized default otel-logs schema

## 자동 완성 개선 사항 {#improvements-to-autocomplete}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/8zDZx49uYQo" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

HyperDX의 자동 완성 기능이 훨씬 높은 카디널리티(cardinality)와 더 빠른 값 로딩을 지원하도록 대대적으로 개편됩니다. 새 구현은 롤업 테이블(key-value 쌍을 15분 단위 시간 버킷(time bucket)으로 사전 집계하는 `AggregatingMergeTrees`)을 기반으로 하므로, 키를 입력할 때마다 원시 데이터를 쿼리하지 않고 미리 계산된 훨씬 작은 데이터셋에서 읽어옵니다. 2억 3천만 행 규모의 스테이징 인스턴스에서 진행한 라이브 데모에서는 `hostname`과 같은 high-cardinality 필드의 값도 눈에 띄는 지연 없이 빠르게 로딩되었습니다.

이 시스템은 키 전용 롤업(카디널리티 오버헤드를 줄이기 위해 모든 키를 반환하되 연결된 값은 반환하지 않음)과 전체 키-값 롤업을 모두 지원합니다. 키 롤업만 있으면 값 조회(lookup) 단계에서 기존의 값 가져오기 전략으로 폴백합니다. 롤업 테이블이 전혀 감지되지 않으면 현재 동작으로 문제없이 폴백합니다. 또한 Aaron은 값 롤업을 적용할 키를 지정하는 allow-list UI가 향후 추가된다면 카디널리티가 특히 높은 데이터를 다루는 고객에게 유용할 것이라고 언급했습니다.

**관련 풀 리퀘스트:** [#2128](https://github.com/hyperdxio/hyperdx/pull/2128) feat: fast and full 자동 완성, [#2127](https://github.com/hyperdxio/hyperdx/pull/2127) feat: better 자동 완성

## SQL 기반 알림 기능 개선 {#improvements-to-alerting-with-sql}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/BOk-LC0y2no" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

지난주 원시 SQL(Raw SQL) 선 차트와 막대 차트에 알림 기능이 추가된 데 이어, 이제 HyperDX에서 원시 SQL(Raw SQL) 숫자 차트에도 알림을 설정할 수 있습니다. 또한 알림을 설정할 때 시간 필터(filter) 매개변수를 더 이상 반드시 지정하지 않아도 됩니다. 생략하면 경고가 표시되지만, 시간 차원이 전혀 없는 쿼리도 이제 정상적으로 사용할 수 있습니다. 따라서 ClickHouse 클러스터 수가 예상값과 일치하는지 확인하는 경우처럼, 시간에 따라 변하지 않는 구성 값이나 시스템 메트릭에 대해서도 손쉽게 알림을 설정할 수 있습니다.

not-equals, is-above, at-most, between, outside 등 새로운 임계값 유형도 여러 개 추가되었습니다. 이에 따라 단순한 초과 비교에 그치지 않고 알림 조건을 훨씬 유연하게 표현할 수 있습니다. 마지막으로, 이제 알림 이력이 타일 편집기에 바로 표시됩니다. 발생한 알림이 특정 대시보드 타일에 연결되어 있다면, 사용자는 대시보드를 벗어나지 않고도 전체 이력을 확인하고 알림이 트리거된 원인을 파악할 수 있으며, 알림을 확인(acknowledge)하거나 무음 처리할 수도 있습니다.

**관련 풀 리퀘스트:** [#2073](https://github.com/hyperdxio/hyperdx/pull/2073) feat: Implement 알림 for 원시 SQL(Raw SQL)-based 대시보드 타일, [#2114](https://github.com/hyperdxio/hyperdx/pull/2114) feat: Support 알림 on 원시 SQL(Raw SQL) Number 차트, [#2122](https://github.com/hyperdxio/hyperdx/pull/2122) feat: Add additional 알림 threshold types, [#2130](https://github.com/hyperdxio/hyperdx/pull/2130) feat: Add between and not-between 알림 thresholds, [#2123](https://github.com/hyperdxio/hyperdx/pull/2123) feat: Add 알림 history + ack to 알림 editor

## 알림 실행 중 오류 {#errors-during-alert-execution}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/b3G8kFiQiUg" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 알림 실행이 실패하면 HyperDX는 해당 오류를 아무 표시 없이 무시하지 않고 UI에 직접 표시합니다. 이전에는 사용자가 알림 이력에서 데이터 공백을 발견하더라도 원인을 알 수 없었습니다. 오류 메시지도 없었고, 무엇이 잘못되었는지 디버깅할 방법도 없었습니다. 이제는 유효하지 않은 쿼리, 웹훅 전송 실패, 누락되었거나 잘못 구성된 웹훅 설정 등 실패 유형별로 서로 다른 오류 아이콘이 인라인으로 표시됩니다.

오류 아이콘을 클릭하면 문제를 진단하고 해결하는 데 필요한 구체적인 정보가 표시되므로, 사용자는 서버 로그를 뒤지거나 지원팀에 문의하지 않고도 잘못 구성된 알림을 바로잡을 수 있습니다. 이 기능의 목표는 오류를 확인하고, 이해하고, 수정하는 과정을 통해 알림 실패를 셀프서비스로 해결할 수 있도록 하는 것입니다.

**관련 풀 리퀘스트:** [#2132](https://github.com/hyperdxio/hyperdx/pull/2132) feat: Show 알림 execution errors in the UI, [#2136](https://github.com/hyperdxio/hyperdx/pull/2136) fix: Hide potentially-sensitive 알림 errors
