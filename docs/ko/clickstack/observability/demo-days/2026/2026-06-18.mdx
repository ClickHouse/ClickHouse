## 이제 모든 곳에서 사용할 수 있는 소스 필터 {#source-filters-now-everywhere}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Zl5ymdzoM6U" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 Services 대시보드 전반에서 소스 필터를 사용할 수 있습니다. 서비스 이름 필터가 설정된 트레이스 또는 로그 소스를 선택하면, 대시보드는 값이 선택될 때까지 쿼리를 실행하지 않고 기다립니다. 이렇게 선택된 필터는 모든 차트, 쿼리, 사이드 패널에 일관되게 적용됩니다. 트레이스 워터폴도 같은 방식으로 동작하여, 스팬을 열면 검색 페이지의 소스 필터를 그대로 상속하면서도 추가 필터를 더할 수 있습니다. 세션(Sessions) 페이지도 업데이트되어 소스 필터가 사이드바, 트레이스 패널, 중첩된 뷰(view)까지 그대로 적용됩니다.

소스 필터의 자동 완성 기능도 확장되었습니다. 이전에는 검색 페이지에서만 사용할 수 있었지만, 이제 대시보드를 포함해 소스 필터를 지원하는 모든 곳에서 동작합니다. 내부적으로는 소스마다 별도의 필터 세트가 있더라도 자동 완성이 여러 소스에 걸쳐 키와 값(keys and values)을 확인합니다. 이 개선 사항은 원시 SQL(Raw SQL) 편집기와 쿼리 빌더(query builder)의 모든 소스 필터 입력란에 동일하게 적용됩니다.

**관련 PR:** [#2331](https://github.com/hyperdxio/hyperdx/pull/2331) 대시보드 필터에 소스 범위 지정 기능 추가, [#2459](https://github.com/hyperdxio/hyperdx/pull/2459) 소스 범위 필터가 제외된 타일에 아이콘 표시

## 사용자 정의 스키마(schemas)를 위한 AI 생성 대시보드 개선 {#better-ai-generated-dashboards-for-custom-schemas}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/LUi5047F3fs" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

사용자 정의 스키마(schema)를 기반으로 AI를 활용해 대시보드를 구축하던 한 사용자가 심각한 성능 문제를 겪었습니다. 근본 원인은 생성된 원시 SQL 타일이 대시보드 시간 필터(filter) 매크로 대신 하드코딩된 시간 범위를 사용했다는 점이었으며, 이 때문에 대시보드의 시간 범위를 변경해도 결과에 반영되지 않았습니다. 또한 한 타일은 정수(integer) 타임스탬프 컬럼을 프라이머리 키를 우회하는 방식으로 필터링하여 전체 테이블 스캔을 유발했습니다.

이 문제를 해결하기 위해 원시 SQL 대시보드 타일의 MCP 스키마(schema)에 에이전트가 대시보드 시간 필터 매크로를 사용해야 한다는 점을 명시했습니다. 또한 생성된 SQL 타일에 해당 매크로가 누락되면 ClickStack UI에 경고가 표시되므로, 대시보드를 저장하기 전에 문제를 더 쉽게 발견할 수 있습니다. 변경 사항을 배포한 후 고객의 원래 프롬프트를 다시 실행한 결과, 올바른 매크로를 사용하는 SQL이 생성되어 대시보드 속도가 크게 향상되었습니다.

**관련 PR:** [#2473](https://github.com/hyperdxio/hyperdx/pull/2473) 원시 SQL 타일에서 에이전트가 매크로를 사용하도록 유도

## OTel 메트릭 해싱 단순화와 프라이머리 키 개선 아이디어 {#simpler-hashing-for-otel-metrics-and-a-primary-key-idea}

*데모 진행자: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/MjAUdJJbC8M" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

커뮤니티 기여로 JSON 속성 컬럼을 사용하는 메트릭의 속성 해싱 문제가 수정되었지만, 이로 인해 코드 경로가 두 갈래로 나뉘었습니다. JSON 스키마(schemas)는 가변 인자 형식의 `cityHash64`를 사용한 반면, Map 기반 스키마(Map-based schemas)는 해싱 전에 3개의 맵을 먼저 연결했습니다. 그런데 확인해 보니 이러한 추가 작업은 필요하지 않았습니다. 이제 두 스키마 타입 모두 동일한 `cityHash64` 구현을 사용하므로 코드가 단순해지고, 해싱 과정에서 불필요한 맵 할당도 발생하지 않습니다.

이 작업을 통해 OpenTelemetry 메트릭 스키마(schema)의 잠재적인 최적화 방안도 확인되었습니다. 현재 프라이머리 키에는 전체 속성 맵이 저장되는데, ClickHouse는 이 맵을 인덱스의 일부로 메모리에 유지하므로 메모리 사용량(memory usage)이 늘어납니다. 한 가지 방안은 삽입 시점(insert time)에 속성 해시를 구체화하고, 프라이머리 키에 맵 대신 이 해시를 사용하는 것입니다. 아직 변경된 사항은 없지만, OpenTelemetry 스키마 갱신(updates)이 다시 논의되기 시작한 만큼 재검토해 볼 만한 최적화입니다.

**관련 PR:** [#2475](https://github.com/hyperdxio/hyperdx/pull/2475) AttributesHash를 가변 인자 cityHash64로 통합

## 필터 필(filter pill) 및 데이터 소스 개선 {#filter-pill-and-data-source-polish}

*데모 진행자: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Zi6HPj5_JQg" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이번 주에는 작지만 유용한 사용성 개선 사항 2가지가 반영되었습니다. 기존 스타일에서는 제거 버튼이 잘 보이지 않는다는 고객 피드백을 반영하여 제외된 필터 필의 가독성을 크게 높였습니다. 이제 제외된 필터 필에는 한층 부드러운 빨간색이 적용되어 라이트 모드와 다크 모드 모두에서 대비가 향상되었습니다.

많은 데이터 소스를 관리하기도 더 쉬워졌습니다. 이제 소스에 섹션(선택 사항)을 할당하여 소스 선택기에서 그룹별로 묶을 수 있습니다. 섹션이 없는 소스는 이전과 같이 &quot;기타&quot; 아래에 표시되므로 기존 설정에는 영향이 없습니다. 검색 기능도 섹션 이름과 일치하는 항목을 찾도록 개선되어, 소스가 속한 그룹만 기억나더라도 관련 소스를 쉽게 찾을 수 있습니다. 이 기능은 현재 내부에서만 사용 중이며, 팀은 정식으로 확대 출시하기 전에 사용자가 소스를 어떤 방식으로 자연스럽게 구성하는지 살펴보고 있습니다.

**관련 PR:** [#2478](https://github.com/hyperdxio/hyperdx/pull/2478) 라이트 테마에서 제외된 필터 필의 가독성 개선, [#2432](https://github.com/hyperdxio/hyperdx/pull/2432) 데이터 소스에 선택 사항인 섹션 필드 추가, [#2476](https://github.com/hyperdxio/hyperdx/pull/2476) 데이터 소스 선택기를 섹션별로 그룹화하고 태그 스타일 검색 지원, [#2477](https://github.com/hyperdxio/hyperdx/pull/2477) 소스 양식에서 기존 섹션 이름 제안

## high-cardinality 차트를 위한 차트별 시계열 제한 {#per-chart-series-limits-for-high-cardinality-charts}

*데모 진행자: [@wrn14897](https://github.com/wrn14897)*

<Frame>
  <iframe src="https://www.youtube.com/embed/xKpHvhbo-PI" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 차트에서 반환하는 시계열 수를 제한할 수 있으므로, HTTP 라우트나 스팬 ID처럼 high-cardinality 필드로 그룹화할 때 발생하는 성능 문제를 방지할 수 있습니다. 이전에는 이러한 쿼리가 수십만 개의 시계열을 생성하여 대시보드가 느려지거나 응답하지 않을 수 있었습니다. 이제 차트에 표시할 시계열을 상위 N개로 제한하여 렌더링 시간과 데이터 전송량을 모두 줄일 수 있습니다.

청크 단위로 실행되는 쿼리에서는 상위 시계열을 효율적으로 선택하기가 더 까다롭습니다. 현재 구현에서는 가장 최근 청크에서 상위 N개를 결정한 뒤 동일한 시계열 집합을 전체 쿼리에 적용하며, 이 작업은 브라우저가 아닌 ClickHouse에서 수행됩니다. 이 방식은 아직 평가 중이며, 쿼리 최적화가 추가로 도입되면 변경될 수 있습니다.

**관련 PR:** [#2449](https://github.com/hyperdxio/hyperdx/pull/2449) 시계열 제한을 옵트인 방식으로 변경하고 청크 간 일관성 유지, [#2429](https://github.com/hyperdxio/hyperdx/pull/2429) OOM 방지를 위해 group-by 시계열을 상위 N개로 제한
