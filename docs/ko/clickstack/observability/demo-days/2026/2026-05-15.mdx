이제 노트북에서 알림을 생성할 수 있습니다. 실행 중에 동적으로 대시보드를 구성하던 기존 노트북 흐름이 이제 알림까지 자동으로 설정해 주므로, 노트북을 벗어나지 않고도 &quot;흥미로운 쿼리를 찾았다&quot;에서 &quot;이 알림이 발생하면 호출해 달라&quot;까지 한 번에 진행할 수 있습니다.

다만 알아 두어야 할 제약이 하나 있습니다. 팀에는 미리 정의된 웹훅이 여러 개 있지만, 현재 노트북은 후속 질문을 하지 않으므로 사용자가 직접 선택하도록 하는 대신 가장 관련성이 높아 보이는 웹훅을 자동으로 선택합니다. 컨텍스트가 부족할 때 노트북이 후속 질문을 할 수 있도록 하는 PR이 이미 처리 중이므로, 이 공백은 곧 해소될 예정입니다.

## materialized view 기반 자동 완성 {#autocomplete-from-materialized-views}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/iQf5EwktBW4" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

얼마 전 검색 창의 속성 자동 완성에 materialized view를 도입하여, 값을 실행 중에 동적으로 계산하지 않고 즉시 표시할 수 있게 되었습니다. 이제 동일한 MV를 사이드 필터에도 활용하므로, 부하가 많은 인스턴스에서도 필터가 훨씬 빠르게 로드됩니다.

한 가지 알아 두어야 할 동작 변경 사항이 있습니다. MV 기반 필터는 현재 쿼리 범위로 한정되지 않고, 현재 시간 범위 내에서 가능한 모든 필터 값을 반환합니다. 토글을 사용하면 검색 범위 필터로 다시 전환할 수 있으며, 이 경우 실시간 결과(result)를 대상으로 더 느린 집계가 실행됩니다. 또한 `filterValueExpandedKeyLimit`의 기본값이 상향되었습니다. MV가 없으면 키 20개, MV가 있으면 키 100개이며, 원하는 값까지 자유롭게 구성할 수 있습니다(1000까지 테스트했습니다).

MV는 유지 관리 비용이 비교적 낮으며, 스테이징 인스턴스에서 대량의 데이터를 대상으로 실행 중인 상태에서도 안정적으로 동작하고 있습니다. 동일한 MV가 속성 자동 완성과 맵 컬럼 확장에도 사용되므로, 한 번 설정해 두면 여러 곳에서 속도 향상 효과를 얻을 수 있습니다. 데모 중에 검색 범위 필터와 전체 필터 간 토글을 설정 메뉴에 두지 않고 필터 패널 상단에 별도의 필(pill) 스위치로 배치해야 하는지에 대한 논의가 있었으며, 이는 후속 작업으로 검토하고 있습니다.

**관련 PR:** [#2272](https://github.com/hyperdxio/hyperdx/pull/2272) feat: filters are not search aware by default; accelerated by MV

## 테이블 컬럼 순서 지정 및 시계열별 서식 지정 {#table-column-ordering-and-per-series-formatting}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/iEn8kzvERE8" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

테이블 관련 개선 사항 몇 가지가 함께 반영되었습니다. 이제 group-by 컬럼이 항상 테이블 오른쪽에 표시되는 대신 왼쪽에 고정되도록 설정할 수 있습니다. 서비스 이름을 따라 위에서 아래로 훑어보는 RED 스타일 대시보드에서는 대개 이 방식이 더 적합합니다. 이 동작은 테이블별 표시 설정으로 제어할 수 있습니다.

시계열별 숫자 포맷도 이제 지원됩니다. 이전에는 테이블 전체에 하나의 숫자 포맷이 적용되었기 때문에, 테이블에 밀리초 포맷의 시계열이 하나라도 있으면 Requests 컬럼까지 `123ms`처럼 표시되었습니다. 이제 컬럼별 또는 시계열별로 포맷을 설정할 수 있으므로, 요청 수는 일반 숫자로 유지하고 지연 시간 컬럼만 소요 시간 형식으로 표시할 수 있습니다.

아울러 포맷 추론도 이제 시계열 단위로 수행됩니다. Trace Duration 필드를 집계하면 해당 시계열만 밀리초로 추론되므로, 한 컬럼이 소요 시간이라는 이유만으로 테이블의 나머지 컬럼까지 밀리초 서식이 적용되는 일은 없습니다.

**관련 PR:** [#2149](https://github.com/hyperdxio/hyperdx/pull/2149) feat: Allow displaying group-by columns on LHS of table, [#2174](https://github.com/hyperdxio/hyperdx/pull/2174) feat: Add per-series number formats

## 사용자 정의 대시보드 연결 {#customizable-dashboard-linking}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Stlz02xES40" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 대시보드 테이블에서 행을 클릭하면 다른 대시보드(또는 검색)로 이동하도록 연결할 수 있으며, 대상과 함께 전달할 필터를 모두 템플릿으로 구성할 수 있습니다. 테이블 타일 구성에 새로운 &quot;행 클릭 동작&quot; 옵션이 추가되었습니다. &quot;대시보드&quot;를 선택하고 연결할 대시보드를 고른 다음, 현재 행의 필터를 대상 대시보드의 필터에 매핑하십시오. 필터 값에는 Handlebars 스타일 템플릿을 사용하므로, 클릭한 행의 어떤 컬럼 값이든 대상 필터나 WHERE 절(SQL 또는 Lucene)에 넣을 수 있습니다. 데모의 예시에서는 서비스 목록을 연결하여, 행을 클릭하면 `service.name`으로 필터링된 상태의 서비스 상세 대시보드로 바로 이동합니다.

특정 대상 대시보드를 선택하는 대신 대시보드 이름 자체를 템플릿으로 지정할 수도 있습니다. 예를 들어 `${service.name} dashboard`와 같은 이름으로 서비스별 대시보드를 만들어 두었다면, 클릭한 행과 일치하는 대시보드로 연결됩니다. 템플릿으로 지정한 대시보드가 존재하지 않을 때를 위한 오류 처리도 갖추고 있어, 깨진 페이지로 이동하는 대신 알림이 표시됩니다.

여러 변수를 지원하므로 클릭한 행의 컬럼을 원하는 대로 조합하여 필터 세트나 템플릿 대시보드 이름에 전달할 수 있습니다. Handlebars에는 동적 헬퍼와 조건부 블록(blocks)이 있지만, 기능 범위를 작고 예측 가능하게 유지하기 위해 현재는 대부분 비활성화되어 있습니다. 가져오기 흐름도 개선되었습니다. ID로 다른 대시보드를 참조하는 대시보드를 가져올 때, 이제 해당 참조를 대상 계정에 있는 대시보드로 다시 매핑할 수 있습니다.
