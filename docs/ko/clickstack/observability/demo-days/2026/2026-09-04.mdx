## 새로운 유형의 대시보드 필터 {#new-types-of-dashboard-filter}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/VnlNxvcvg-g" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이전에는 대시보드 필터에서 제공하는 값의 종류가 ClickHouse 컬럼에서 드롭다운 옵션을 가져오는 쿼리 값 한 가지뿐이었습니다. 이제 필터 및 변수 모달을 열면 두 가지 유형을 추가로 선택할 수 있습니다.

정적 값(Static values)을 사용하면 필터를 생성할 때 옵션을 직접 입력할 수 있습니다. 예를 들어 환경 필터에서 별도의 쿼리 없이 `dev`, `staging`, `prod`만 제공할 수 있습니다. 정적 목록 필터에는 `expression`이 없으므로 변수 모드만 지원하며, 브로드캐스트 모드에서 사용할 SQL 조건으로 변환할 수 없습니다.

PromQL 레이블 값(PromQL label values)은 PromQL 소스의 `<label>/values` 엔드포인트에서 옵션을 조회합니다. 원하는 레이블을 선택한 뒤 필요하면 매처(matcher)로 범위를 좁힐 수 있으며, 이 매처에서 다른 변수를 참조할 수도 있습니다. 따라서 필터 간에 종속 관계를 구성할 수 있습니다. 환경을 선택하면 다음 필터에 표시되는 인스턴스가 그에 맞게 좁혀지고, 선택할 때마다 PromQL 차트도 함께 필터링됩니다.

두 유형 모두 변수로 노출할 수 있으므로 필터를 `WHERE` 절 외의 용도로도 활용할 수 있습니다. 데모에서는 `ServiceName`과 `SeverityText`를 나열한 정적 필터를 차트의 group-by 차원으로 사용합니다. 따라서 드롭다운에서 값을 선택하면 어떤 조합이든 차트의 그룹화 기준이 바뀝니다.

## PromQL 차트용 사용자 정의 범례 템플릿 {#custom-legend-templates-for-promql-charts}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/2rR_kRAEvWw" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Vladimir가 지적했듯이 PromQL 범례는 읽기 어려웠습니다. 기본적으로 메트릭 이름 뒤에 반환된 시계열마다 값이 다른 레이블을 모두 표시하기 때문에, 시계열을 많이 반환하는 쿼리에서는 범례가 긴 문자열이 되어 직접 클릭해 봐야 내용을 파악할 수 있었습니다.

이제 차트의 표시 설정에서 범례 템플릿을 지정할 수 있습니다. 범례 템플릿은 Handlebars 템플릿이므로 실제로 필요한 레이블만 참조하여 범례와 도구 설명 모두에 짧은 시계열 이름을 표시할 수 있습니다.

템플릿에서 존재하지 않는 레이블을 참조하면 해당 부분은 빈 값으로 렌더링됩니다. 결과가 비어 있거나 시계열 간에 고유하지 않으면 시계열을 구분하는 전체 레이블 집합으로 폴백되므로, 서로 구별할 수 없는 시계열이 생기지 않습니다.

**관련 풀 리퀘스트:** [#3055](https://github.com/hyperdxio/hyperdx/pull/3055) PromQL 시계열 범례용 사용자 정의 템플릿 지원

이제 대시보드에서 상대 날짜 범위를 기본값으로 저장할 수 있습니다. 원하는 시간 범위를 설정하고 &quot;Save Query and Filters as default&quot;를 클릭하면, 이후부터 대시보드가 해당 범위로 열립니다.

## 저장된 검색이나 대시보드 타일 없이 사용하는 알림 {#alerts-without-a-saved-search-or-dashboard-tile}

*데모 진행자: [@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/wuK7geV7F94" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이전에는 모든 알림에 기반이 되는 대상이 필요했습니다. 로그에는 저장된 검색이, 메트릭에는 대시보드 타일이 있어야 했습니다. 이 방식으로는 수천 개의 Grafana 알림을 마이그레이션할 때 감당하기 어렵습니다.

인라인 알림을 사용하면 이러한 요구 사항이 사라집니다. 차트 탐색기의 작업 표시줄에 **Create alert** 작업이 추가되어, 메트릭이나 이벤트로 차트를 만든 뒤 아무것도 먼저 저장하지 않고 바로 알림을 설정할 수 있습니다. 알림 페이지에서도 인라인 알림을 생성할 수 있으며, 알림을 저장된 검색이나 대시보드와 연결하고 싶지 않다면 이 방법을 사용하십시오.

인라인 알림은 대시보드 타일이 저장하는 것과 정확히 동일한 형태로 자체 `chartConfig`를 알림 문서에 영구 저장합니다. 따라서 별도의 병렬 경로가 아니라 타일 알림과 동일한 코드 경로를 통해 평가됩니다. `line`, `stacked_bar`, `number` 표시 유형에서 빌더와 원시 SQL을 모두 지원합니다. PromQL은 현재 지원되지 않습니다.

동일한 `source: 'inline'` 형태는 외부 API v2와 MCP `save_alert` 도구에서도 사용할 수 있으며, v2 대시보드와 동일한 타일 구성 방언을 사용하므로 알림을 프로그래밍 방식으로 대규모로 생성할 수 있습니다. 라우터가 대시보드 타일 컨버터를 재사용하므로 두 인터페이스 간에 드리프트가 발생하지 않습니다.

**관련 풀 리퀘스트:** [#3010](https://github.com/hyperdxio/hyperdx/pull/3010) 저장된 검색이나 대시보드 타일 없이 알림 생성 지원(백엔드), [#3069](https://github.com/hyperdxio/hyperdx/pull/3069) 인라인 차트 알림 생성 및 편집 UI, [#3043](https://github.com/hyperdxio/hyperdx/pull/3043) 외부 API v2 및 MCP에서 차트 알림 지원

## 알림 이름과 태그 {#alert-names-and-tags}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/nIJGusSLBuk" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 알림에 고유한 이름과 태그를 지정할 수 있습니다. 대시보드 타일 또는 저장된 검색의 알림 양식에 이름 입력란과 태그 입력란이 추가되었습니다. 새 알림의 이름은 기본적으로 차트 또는 저장된 검색의 이름으로 설정되며, 태그는 알림이 속한 대시보드 또는 저장된 검색의 태그를 상속합니다.

알림 페이지에는 이 이름이 표시되며, 검색과 필터링도 이 이름을 기준으로 수행됩니다. 데이터베이스에 이미 있는 알림 중 이름이 설정되지 않은 알림은 기존처럼 참조하는 저장된 검색 또는 대시보드에서 이름을 가져옵니다.

이제 `team/tags` 엔드포인트가 반환하는 태그에는 대시보드와 저장된 검색의 태그뿐만 아니라 알림 문서의 태그도 포함됩니다. 이 변경이 없으면 알림에서만 사용된 태그는 다음 알림에 태그를 지정할 때 추천 목록에 나타나지 않습니다.

이 작업은 태그 기반 검색과 필터링을 계속 지원하면서 알림 페이지에 페이지 나누기를 적용하기 위한 사전 작업입니다. 이를 위해서는 대시보드 및 저장된 검색 컬렉션과 조인하는 대신 알림 문서 자체에 이름과 태그가 있어야 합니다. 페이지 나누기는 아직 완료되지 않았습니다.

## 탐색 프로토타입 {#an-explore-prototype}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/vlGMKp5Eroc" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

**이 작업은 탐색 단계의 작업이며, 출시가 확정된 것은 아닙니다.**

이 프로토타입은 검색 페이지와 차트 탐색기를 모두 대체하는 단일 탐색 페이지입니다. 현재 HyperDX 저장소에 초안 상태로 올라가 있습니다. 기존 페이지들을 대체할 수도 있고, 세 번째 페이지로 함께 제공될 수도 있으며, 결국 아무 결과로 이어지지 않을 수도 있습니다.

이 프로토타입이 해결하려는 문제는 현재 두 페이지 사이를 오갈 때의 불편함입니다. 고객들은 검색에서 시작한 분석을 차트 탐색기로 이어 가는 과정이 번거롭다고 말합니다. 다른 페이지로 넘어가면 데이터 소스를 다시 선택하고 같은 쿼리를 다시 구성해야 하는 경우가 많기 때문입니다. 탐색에서는 페이지를 옮기는 대신 이벤트, 패턴, 변화량, 차트 사이에서 뷰만 전환하므로 모든 작업을 한 페이지에서 처리할 수 있습니다.

두 번째 주제는 쿼리 언어에 익숙하지 않은 사용자의 진입 장벽을 낮추는 것입니다. 테이블에 컬럼 추가, 정렬, group-by 선택은 드롭다운으로 처리하며, 필요하면 SQL도 그대로 사용할 수 있습니다. group-by는 현재의 한계를 잘 보여 주는 예입니다. 검색 페이지의 히스토그램은 상태 코드로 그룹화되어 있고 이를 변경할 방법이 없으므로, 다른 기준으로 그룹화하려면 차트 탐색기로 이동해야 합니다. 탐색에서는 이벤트 뷰에서 group-by를 설정하고, 작은 히스토그램으로 부족하면 시계열 또는 막대 차트로 전환한 뒤, 집계를 `p99` 등으로 변경하고 결과를 대시보드에 저장할 수 있습니다.

필터 바는 Lucene과 SQL을 모두 추상화한 간단한 쿼리 빌더(query builder)입니다. 필드와 연산자를 선택하고 값을 입력하기만 하면 되며, 고급 사용자는 전체 쿼리 편집기와 매크로를 사용할 수 있습니다. 애초에 쿼리 언어(query language)를 두 가지나 두는 것이 바람직한지는 아직 해결되지 않은 질문 중 하나입니다.

아직 정해지지 않은 부분도 많습니다. PromQL은 아직 지원하지 않으며, 메트릭을 이 페이지에 포함해야 할지, 아니면 한 페이지에 너무 많은 기능을 담게 되는지도 결정되지 않았습니다. 이 프로토타입은 로그와 트레이스 경험에 중점을 두고 있습니다.

이에 대한 많은 피드백을 기다립니다.
