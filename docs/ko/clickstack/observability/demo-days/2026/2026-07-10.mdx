## Map 컬럼 OR 조건 필터의 텍스트 인덱스 문제 수정 {#text-index-fix-for-map-column-disjunction-filters}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/i7SOQ5uSfm8" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Aaron은 Map 컬럼 속성에 대한 쿼리가 예상외로 느리다는 보고를 디버깅하던 중 이 문제를 발견했습니다. 보고한 사용자는 이미 구체화된 컬럼(materialized column)과 블룸 필터를 추가해 직접 문제를 우회한 상태였지만, map 속성에는 이미 최적화가 적용되어 있으므로 원래는 이러한 조치가 필요하지 않아야 했습니다.

확인해 보니, map 속성을 여러 후보 값으로 필터링할 때 사실상 배열 OR 조건 검사인 `hasAny` 함수가 사용되고 있었습니다. 사용자 ID 같은 로그 속성을 값 목록과 비교하는 경우가 그 예입니다. 이 방식은 ClickHouse 26.5 미만 버전에서 텍스트 인덱스를 트리거하지 못했습니다. 이번 수정에서는 해당 OR 조건을 괄호로 묶은 여러 개의 동등 비교를 OR로 연결하는 형태로 재작성하여 인덱스가 올바르게 활성화되도록 했습니다. Aaron은 `EXPLAIN`으로 재작성된 쿼리가 이제 예상대로 스킵 인덱스를 사용하는 것을 확인했습니다.

대부분의 사용자는 이미 26.5 이상 버전을 사용하고 있지만, 아직 업그레이드하지 않은 사용자도 이 수정 덕분에 당분간 해당 쿼리를 빠르게 실행할 수 있습니다.

**관련 풀 리퀘스트:** [#2643](https://github.com/hyperdxio/hyperdx/pull/2643) feat: rework getAllKeyValues and add filters populated from text indices

## ClickCannon의 프로파일링 데이터 {#profiling-data-in-clickcannon}

*데모 진행자: [@SpencerTorres](https://github.com/SpencerTorres)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Fo1XCHsA3rU" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

최근 합성 데이터를 생성하고 ClickHouse를 벤치마킹하는 도구인 [ClickCannon에 대한 블로그 글](https://clickhouse.com/blog/building-clickcannon-a-tool-for-benchmark-clickhouse)을 게시했습니다. 이번에 Spencer는 기존의 로그, 메트릭, trace 지원에 더해 프로파일링 신호를 추가했습니다. 스택 깊이를 설정하여 프로파일링 데이터를 생성할 수 있으며, 데이터는 실행 중에 동적으로 시뮬레이션하거나 디스크에서 읽어올 수 있습니다. 수집 방식도 다른 신호와 동일합니다. ClickCannon이 프로필 테이블을 가리키도록 지정하면 바로 행 생성이 시작됩니다.

프로필 페이로드는 다른 신호보다 훨씬 큰 것으로 확인되어, 표본(sample)당 추가되는 키 수를 조정하고 인스턴스 크기 대비 처리량을 점검하는 작업은 아직 진행 중입니다. 이 데이터를 대량으로 생성할 수 있게 되면서 팀은 스키마(schema) 최적화에 착수하고 이에 대한 기준점을 마련할 수 있게 되었습니다. 이는 ClickStack 전반에서 프로파일링 데이터와 그 시각화를 지원하려는 더 큰 작업의 일환입니다. 또한 Spencer는 ClickStack 로그 뷰에서 프로필 프레임을 렌더링하는 방안도 처음으로 살펴보았습니다.

## 막대 차트 {#bar-charts}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<Frame>
  <iframe src="https://www.youtube.com/embed/JIQJpGMh5tk" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

막대 차트가 추가되었습니다. 몇 달 전에 올라왔다가 리베이스 과정에서 진행이 멈춘 PR에서 착안한 기능입니다. 이제 대시보드, MCP 대시보드 빌더 등 ClickStack에서 차트가 표시되는 모든 곳에서 막대 차트를 사용할 수 있습니다. 기존에 선 차트로 하던 point-in-time 비교를 이제 막대 차트로도 할 수 있으므로, 둘의 구분을 명확히 하기 위해 선 차트의 이름을 시계열로 변경했습니다.

막대 차트는 시계열 제한을 지원하므로 high-cardinality 그룹화(Group By)를 사용할 때 표시되는 막대 수를 조절할 수 있습니다. 또한 사용자 정의 ORDER BY를 지원하므로 기본 정렬 순서 대신 가장 중요한 메트릭을 기준으로 정렬할 수 있습니다.

**관련 풀 리퀘스트:** [#2606](https://github.com/hyperdxio/hyperdx/pull/2606) feat: Add categorical bar chart display type, [#2618](https://github.com/hyperdxio/hyperdx/pull/2618) feat: Allow custom order by on categorical (pie/bar) charts

## 차트의 알림 어노테이션 {#alert-annotations-on-charts}

*데모 진행자: [@teeohhem](https://github.com/teeohhem)*

<Frame>
  <iframe src="https://www.youtube.com/embed/NmEYBvtjpAQ" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이 기능은 알림이 발생할 때 차트에서 어노테이션을 확인하고 싶다는 고객 요청에서 시작되었습니다. 새로 추가된 알림 어노테이션 표시 토글(기본값: 꺼짐)을 켜면 알림이 발생한 시점과 해소된 시점이 차트 위에 정확하게 표시됩니다. 현재 표시 중인 시간 범위 이전부터 알림이 발생 상태였다면 차트 왼쪽 가장자리에 마커가 나타나 해당 구간이 시작되기 전부터 알림이 이미 활성 상태였음을 알려 줍니다. 또한 알림이 발생하고 해소될 때마다 어노테이션이 실시간으로 업데이트됩니다.

Tom은 이 기능을 재사용 가능한 어노테이션 패턴으로 구현했으므로, 향후 릴리스나 Kubernetes 이벤트 같은 새로운 어노테이션 유형도 같은 방식을 기반으로 손쉽게 추가할 수 있습니다.

**관련 풀 리퀘스트:** [#2605](https://github.com/hyperdxio/hyperdx/pull/2605) feat(dashboards): alert firing/recovery annotations on tile charts, [#2616](https://github.com/hyperdxio/hyperdx/pull/2616) fix(dashboards): improve alert annotation visibility on tile charts

## 이벤트 패턴, 타일 개선, 선 시계열 작업 {#event-patterns-tile-polish-and-line-series-actions}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<Frame>
  <iframe src="https://www.youtube.com/embed/Nwo_nt5VZL4" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 이벤트 패턴이 정식 대시보드 타일 유형으로 공식 지원됩니다. 패턴 타일을 생성하고 `WHERE` 절 또는 패턴 표현식(예: 서비스 이름이나 심각도 텍스트를 기준으로 필터링)을 전달하면 반복되는 패턴을 한눈에 파악할 수 있습니다.

Brandon은 작은 타일에서 시각화의 텍스트 줄바꿈도 개선하여, 이제 긴 제목이 어색하게 잘리지 않고 여러 줄로 줄바꿈된 뒤 말줄임표로 표시됩니다. 타일 작업 버튼도 더 깔끔하게 표시됩니다. 작은 타일에서는 CSS 컨테이너 쿼리를 통해 컨텍스트 메뉴로 접히고, 타일 크기를 키우면 다시 타일에 직접 표시됩니다. 또한 타일의 표시 설정을 저장하지 않고 닫으면 변경 사항이 경고 없이 사라질 수 있던 문제도 수정되어, 이제 편집 내용을 잃기 전에 경고가 제대로 표시됩니다.

마지막으로 사용자 피드백을 반영하여, 기존 검색 작업 외에도 선 시계열을 클릭해 해당 값을 복사하거나 해당 선만 집중해서 볼 수 있습니다. 또한 Brandon은 그룹이 많은 테이블에서 도구 설명이 잘리는 문제를 해결하기 위해 Recharts v3로 업그레이드하는 작업을 진행하고 있습니다.

## 대시보드 및 서비스 맵 스타일 개선 {#dashboard-and-service-map-styling}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/yzgjzU8RIz0" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

사용성에 중점을 둔 스타일 개선 사항이 적용되었습니다. 하나하나는 작은 변경이지만, 모두 합쳐져 한층 깔끔해진 사용 경험을 제공합니다. 대시보드에서는 라이트 모드에서 편집 가능한 타일의 헤더 색상이 회색과 흰색으로 제각각이었으나, 이제 일관된 색상으로 표시되며 헤더 아래에 깔끔한 구분선이 추가되었습니다. 또한 마우스를 올렸을 때만 표시되는 타일 작업의 위치를 조정하여 작은 반응형 카드에서 제목과 겹치지 않도록 했으며, 이제 차트에서 확대/축소를 초기화할 수 있습니다.

서비스 맵도 비슷하게 개선되었습니다. 이제 컨트롤이 색상 모드를 인식하여, 항상 검은색으로 표시되던 이전과 달리 라이트 모드에서는 밝게, 다크 모드에서는 어둡게 표시됩니다. 범례에는 지연 시간, 오류율, 처리량이 더 명확하게 표시되며, 서비스를 클릭하면 해당 서비스에 초점이 맞춰지고 다시 클릭하면 초점이 해제되어 전체 보기로 돌아갑니다.
