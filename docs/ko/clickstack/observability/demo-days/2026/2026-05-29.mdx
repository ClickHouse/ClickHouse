## 버전을 인식하는 개선된 스키마 필터링 {#version-aware-improved-schema-filtering}

*데모 진행자: [@knudtty](https://github.com/knudtty)*

<Frame>
  <iframe src="https://www.youtube.com/embed/bAVaBnfJ82Y" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

이제 ClickStack은 ClickHouse 26.2 이상 버전에서만 direct&#95;read 최적화를 적용합니다. 이 버전부터 전문 검색 인덱스가 오픈 소스 스키마(schemas)에 추가된 별칭 컬럼을 제대로 지원하기 때문입니다. 이전에는 이 최적화가 제대로 동작하지 않는 구버전에서도 시도될 수 있었습니다. 버전 검사는 쿼리 시점에 스키마(schema)를 확인하는 방식으로 수행되며, 이제 별칭 컬럼 자체도 오픈 소스 스키마(schemas)에 기본으로 포함됩니다.

이와 함께 자동 완성용 materialized view를 텍스트 인덱스에 대한 직접 쿼리로 대체하는 작업의 진행 상황도 소개되었습니다. 현재는 두 방식이 중복된 작업을 수행하므로 수집 부하가 가중됩니다. 벤치마크를 통해 텍스트 인덱스 쿼리(text index queries)의 성능이 충분한 것으로 확인되면 materialized view를 단순화하거나 제거할 수 있습니다. 또한 Aaron은 향후 ClickHouse 텍스트 인덱스 버전에 도입될 위치 기반 인코딩이 키-값 필터 조회의 정확도를 어떻게 더 높일 수 있는지에 관한 팀의 질문에도 답변했습니다.

**관련 풀 리퀘스트:** [#2341](https://github.com/hyperdxio/hyperdx/pull/2341) feat: adds direct&#95;read optimization by default for logs and traces, [#2405](https://github.com/hyperdxio/hyperdx/pull/2405) feat(common-utils): apply direct&#95;read KV items optimization to SQL filters, [#2376](https://github.com/hyperdxio/hyperdx/pull/2376) feat: use text index to power filters and autocomplete

## 로그 파싱 개선 {#better-log-parsing}

*데모 진행자: [@dhable](https://github.com/dhable)*

<Frame>
  <iframe src="https://www.youtube.com/embed/vhkMlddahu4" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

한 고객의 로그에서 이벤트 body가 `level` 필드를 포함한 JSON 객체였습니다. 심각도 추론 로직은 두 단계로 동작했습니다. 먼저 body를 JSON으로 파싱하여 속성을 추출하고, OTel 수준에서 심각도가 설정되지 않은 경우에는 문자열 매칭으로 폴백했습니다. 그런데 이 문자열 매칭이 body 안에 있는 alert manager 이름에서 &quot;alert&quot;라는 단어를 감지하는 바람에 로그 레벨이 잘못 분류되었습니다.

이번 수정에서는 가드 조건을 추가하여, body가 JSON으로 파싱되고 이미 level 필드를 포함하고 있으면 문자열 추론 단계를 아예 건너뛰도록 했습니다. 약 1년 전에 구축한 스모크 테스트 모음 덕분에 새 테스트 케이스를 추가하는 것만으로 수정 사항을 검증하고 관련 엣지 케이스까지 손쉽게 찾아낼 수 있었습니다. 이것이 바로 이 테스트 모음을 만든 목적입니다.

**관련 풀 리퀘스트:** [#2363](https://github.com/hyperdxio/hyperdx/pull/2363) fix(log-parser): skip string inference when body parses as JSON with a level field

## 새로운 시계열 색상 팔레트 {#new-series-color-palette}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/YzECP3diWvg" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Elizabet은 Alex의 색상 선택기 작업을 뒷받침하기 위해 HyperDX와 ClickStack 테마의 데이터 시각화 색상 팔레트를 하나로 통합하는 작업을 진행했습니다. 기존에는 두 테마가 각각 별도의 팔레트와 예외 규칙을 두고 있어 색상 체계를 이해하기가 불필요하게 복잡했습니다. 목표는 두 테마 모두에서 사용할 수 있는 단일 팔레트를 만드는 것이었습니다.

Elizabet은 색각 시뮬레이션 도구를 사용하여 업계 표준 팔레트(Tableau, Observable, IBM)의 대비와 접근성을 테스트했습니다. ClickHouse 팔레트는 결과가 좋지 않았는데, 특히 녹색이 흰색 배경에서 충분한 대비를 확보하지 못했습니다. Tableau와 Observable은 각각 최소 한 가지 검사를 통과하지 못했고, IBM 팔레트는 모든 검사를 통과했지만 색상이 5개뿐이라 부족했습니다. 전반적으로 Observable 팔레트가 가장 적합했으며, 파란색을 약간 조정한 뒤 이제 두 테마에서 공통으로 사용합니다.

**관련 풀 리퀘스트:** [#2362](https://github.com/hyperdxio/hyperdx/pull/2362) refactor(theme): 차트 팔레트 토큰 이름을 색상 이름으로 변경 및 테마 간 통합

## 스크롤 시 고정되는 헤더를 갖춘 새로운 페이지 레이아웃 {#new-page-layout-with-sticky-header}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/e7d3ocqi4Ac" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

새로운 PageHeader 및 PageLayout 컴포넌트 쌍이 대시보드, 서비스 맵, 클라이언트 세션, Kubernetes, ClickHouse 대시보드 등 모든 주요 페이지에 적용되었습니다. 이제 모든 페이지가 동일한 패딩, 헤더 아래 테두리 선, 제목 구조를 사용합니다. 이전에는 페이지마다 구성이 제각각이어서, 일부 페이지는 왼쪽에 제목, 오른쪽에 컨트롤이 있었고 일부 페이지는 제목이 아예 없었습니다.

스크롤 시 고정 동작은 prop을 통해 선택적으로 활성화할 수 있습니다. 고정 슬롯에 전달한 요소는 스크롤할 때 헤더 아래에 고정되며, 나머지 요소는 평소대로 스크롤됩니다. 아무것도 전달하지 않으면 breadcrumb 또는 페이지 옵션만 자동으로 고정됩니다.

**관련 풀 리퀘스트:** [#2282](https://github.com/hyperdxio/hyperdx/pull/2282) PageHeader/PageLayout 추가 및 Sessions 마이그레이션, [#2345](https://github.com/hyperdxio/hyperdx/pull/2345) 목록 페이지에서 PageHeader 제목 사용, [#2346](https://github.com/hyperdxio/hyperdx/pull/2346) 서비스 맵을 PageLayout으로 마이그레이션, [#2347](https://github.com/hyperdxio/hyperdx/pull/2347) Kubernetes 대시보드를 PageLayout으로 마이그레이션, [#2348](https://github.com/hyperdxio/hyperdx/pull/2348) ClickHouse 대시보드를 PageLayout으로 마이그레이션, [#2364](https://github.com/hyperdxio/hyperdx/pull/2364) feat(dashboard): 스크롤 시 고정되는 쿼리 툴바와 함께 PageLayout으로 마이그레이션, [#2394](https://github.com/hyperdxio/hyperdx/pull/2394) fix(PageHeader): 스크롤 시 고정되는 헤더가 드로어 오버레이 아래에 표시되도록 수정

## 새로운 데이터 소스 선택기와 시계열 색상 선택 기능 {#new-datasource-selector-and-color-picking-for-series}

*데모 진행자: [@alex-fedotyev](https://github.com/alex-fedotyev)*

<Frame>
  <iframe src="https://www.youtube.com/embed/DKfJs9onl50" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />
</Frame>

Alex가 진행한 2가지 UI 개선 사항입니다. 먼저 데이터 소스 선택기가 정리되어, 이제 클릭하면 선택 가능한 데이터 소스만 표시됩니다. 스키마(schema) 보기나 새 소스 생성 같은 관리 작업은 별도의 케밥 메뉴로 옮겨졌습니다. 이로써 선택과 구성이 분리되었으며, 오래전부터 할 일 목록에 있던 이 작업은 팀의 피드백을 반영한 것이기도 합니다.

숫자 타일에도 정적 색상 선택기가 추가되어 메트릭에 특정 색상을 할당할 수 있습니다. 임계값이나 컬럼에 따라 빨간색, 녹색, 노란색으로 바뀌는 조건부 색상 규칙도 현재 작업 중입니다. Elizabet의 통합 팔레트가 반영되면 두 기능 모두 현재의 &quot;color 1, 2, 3&quot; 레이블 대신 제대로 된 색상 이름을 사용하게 됩니다. 이는 Grafana 같은 도구에서 넘어온 사용자에게 의미 있는 개선이 될 것입니다.

**관련 풀 리퀘스트:** [#2365](https://github.com/hyperdxio/hyperdx/pull/2365) feat(source-picker): chip + kebab menu UX, [#2265](https://github.com/hyperdxio/hyperdx/pull/2265) feat(app): number tile static color picker
