## 차트 편집기의 메트릭 수식 {#metric-formulas-in-the-chart-editor}

*데모 진행자 [@wrn14897](https://github.com/wrn14897)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tSCoW-GGXTU" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 메트릭 차트에서 산술 연산을 수행할 수 있습니다. 지난주까지는 같은 차트에 두 메트릭을 표시해도 그저 두 개의 선으로 나타날 뿐, 이를 결합할 방법이 없었습니다.

차트의 시계열에는 `A`, `B`, `C`와 같은 순서로 레이블이 지정됩니다. 수식 행을 사용하면 이 참조를 활용해 파생 시계열을 만들 수 있습니다. 예를 들어 `A / (A + B + C) * 100`으로 큐 사용률을 구할 수 있습니다. 같은 방식으로 collector의 수신 및 송신 발생 횟수를 이용해 포화도를 계산할 수도 있습니다.

하나의 차트에 여러 수식을 추가할 수 있고, 피연산자 시계열을 결과와 함께 표시할지 수식만 표시할지 선택할 수 있으며, 서로 다른 메트릭의 시계열을 섞어 사용할 수도 있습니다. 수식에도 알림을 설정할 수 있습니다.

산술 연산 자체는 ClickHouse에서 수행됩니다. 각 수식은 유효성 검사를 거친 AST에서 합성 메트릭 쿼리로 컴파일되므로, 애플리케이션이 결과를 사후에 조인하는 것이 아니라 ClickHouse가 단일 쿼리 안에서 계산합니다. 각 시계열은 공통 테이블 식(CTE)이 되고, 수식은 조인된 결과를 대상으로 평가됩니다.

누락된 피연산자는 0으로 처리되므로 오류가 없는 그룹은 N/A가 아닌 0%로 표시됩니다. 모든 나눗셈의 분모는 `nullif(..., 0)`로 감싸므로, 분모가 0이거나 누락된 경우 0이나 오류 대신 빈 구간으로 렌더링됩니다.

후속 작업에서는 `HAVING`, `ORDER BY`, `LIMIT`를 각 `UNION` 브랜치에 적용하지 않고 최종 조인에 적용하도록 변경했습니다. 이전에는 이러한 절(clauses)이 사용자에게 표시되는 출력 이름이 존재하지 않는 범위에서 실행되었습니다. 이 때문에 각 시계열이 조인 전에 개별적으로 필터링되었고, 최종 행 순서도 비결정적이었습니다.

현재 입력란에서는 문자 참조와 간단한 산술 연산만 사용할 수 있으며 임의의 SQL은 사용할 수 없습니다. 알 수 없는 시계열 참조, 형식이 잘못된 표현식, 상수로만 이루어진 표현식은 입력란 아래에 실시간으로 표시됩니다. 같은 유효성 검사를 통과하지 못하면 저장과 실행이 차단되므로, 유효하지 않은 표현식이 ClickHouse에 전달되는 일은 없습니다.

비트 단위 연산자(operators)와 ClickHouse 함수는 아직 지원되지 않습니다. 특별한 이유가 있는 것은 아니며, 첫 번째 버전의 구현 범위가 여기까지였을 뿐입니다. 더 폭넓은 표현식 지원은 다음 단계에서 추가할 수 있습니다.

논의 과정에서 제기되었지만 아직 구현되지 않은 사항이 두 가지 있습니다. 첫째, 수식은 다른 수식을 참조할 수 없으므로 `F1`을 `F2`에 연결해 사용할 수 없습니다. 둘째, 차트 전체에 적용되는 피연산자 토글보다 시계열별 표시/숨기기 컨트롤이 더 유용할 것입니다. 사용자가 실제로 원하는 것은 `A`와 `B`를 수식에는 그대로 두고 화면에서만 숨기는 것입니다.

조인을 어디까지 확장해야 유용성을 유지할 수 있는지에 대한 타당한 질문도 있었습니다. PromQL에서 나눗셈을 사용해 본 사용자라면 이러한 실패 유형을 잘 알고 있을 것입니다. 조인이 예상대로 매칭되지 않아 아무런 경고 없이 데이터가 반환되지 않는 경우입니다.

**관련 풀 리퀘스트:** [#2908](https://github.com/hyperdxio/hyperdx/pull/2908) 합성 메트릭 쿼리에서 수식 렌더링, [#2909](https://github.com/hyperdxio/hyperdx/pull/2909) 메트릭 수식용 차트 편집기 UI, [#2946](https://github.com/hyperdxio/hyperdx/pull/2946) HAVING/ORDER BY/LIMIT를 시계열별 브랜치가 아닌 합성 메트릭 조인에 적용, [#2952](https://github.com/hyperdxio/hyperdx/pull/2952) 여러 API 영역에서의 수식 지원, [#2953](https://github.com/hyperdxio/hyperdx/pull/2953) 로그/트레이스 이벤트 소스의 수식 지원

## 종속 대시보드 변수 및 매크로 {#dependent-dashboard-variables-and-macros}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/Y0CaapNH1Vc" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

지난주 데모에서 나온 두 가지 요청 사항이 반영되었습니다.

이제 필터 정의의 `WHERE` 절에서 다른 변수를 참조할 수 있으므로, 한 드롭다운의 선택에 따라 다른 드롭다운의 범위를 좁힐 수 있습니다. 서비스 이름 필터를 참조하는 severity 필터는 처음에는 비어 있습니다. 서비스를 선택하면 해당 서비스에 존재하는 severity 값만 표시됩니다.

참조된 변수에 아무것도 선택되지 않은 상태에서도 옵션 쿼리는 그대로 실행됩니다. 이 상태에서도 값이 채워지도록 하려면 `$__filters` 또는 `$__conditionalAll`을 사용하십시오. 단순한 `<expression> IN ($var)`는 `$var`에서 값을 선택하기 전까지 아무것도 반환하지 않습니다. 이제는 아무 설명 없이 빈 목록만 표시하는 대신, 도구 설명을 통해 그 이유를 안내합니다. 필터 모달의 `WHERE` 입력란에서도 변수와 매크로 자동 완성을 사용할 수 있습니다.

순환 의존성을 만들 수도 있지만, 변수는 재귀적으로 평가되지 않고 선택된 값으로 대체되므로 실질적인 문제는 발생하지 않습니다.

이제 매크로가 인수로 전달된 변수를 확장하므로 `$__timeFilter($TimeColumn)`과 같이 사용할 수 있습니다. 변수에서 타임스탬프 컬럼을 선택하면, 매크로가 해당 컬럼을 기준으로 한 전체 타임스탬프 필터로 확장됩니다. `$__filter` 및 `$__conditionalAll`에 전달하는 변수는 이제 반드시 `$var` 형식을 사용해야 합니다. 이전에는 접두사 없는 `var`도 허용되었지만, 이러한 느슨한 처리는 오히려 혼란만 초래하는 경우가 많았습니다.

외부 API v2와 MCP 서버 모두 변수를 지원하므로 Terraform에서도 변수를 사용할 수 있습니다. 에이전트는 변수 필터와 브로드캐스트 필터, 종속 드롭다운, 그리고 해당 변수를 직접 또는 매크로를 통해 참조하는 타일로 구성된 대시보드를 생성할 수 있습니다. create, save, patch 도구는 변수가 동작하지 않는 위치에서 사용되면 경고를 표시합니다.

쿼리 타일 도구에도 변수 값을 전달할 수 있으므로, 에이전트는 대시보드를 넘겨주기 전에 치환 결과를 직접 확인할 수 있습니다.

**관련 풀 리퀘스트:** [#2923](https://github.com/hyperdxio/hyperdx/pull/2923) 종속 변수 값 쿼리 지원, [#2937](https://github.com/hyperdxio/hyperdx/pull/2937) 중첩 매크로 및 매크로 내 변수 참조 지원, [#2944](https://github.com/hyperdxio/hyperdx/pull/2944) 외부 API에 대시보드 변수 추가, [#2951](https://github.com/hyperdxio/hyperdx/pull/2951) MCP 서버에서 대시보드 변수 지원

## 엄격한 클라이언트에서도 허용되는 MCP 도구 스키마(schemas) {#mcp-tool-schemas-that-strict-clients-accept}

*데모 진행자: [@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/W4dvgYj47ZM" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

한 고객이 자사 에이전트에서 MCP 서버를 전혀 사용할 수 없다고 보고했습니다.

일부 에이전트 프레임워크는 사용 가능한 도구 목록을 가져온 뒤, 모델 provider에 전송하기 전에 모든 입력 스키마(schema)를 검사합니다. 스키마가 하나라도 유효하지 않으면 프레임워크는 문제가 된 도구만이 아니라 도구 목록 전체를 거부하므로, 서버가 완전히 고장 난 것처럼 보입니다.

대부분의 에이전트 하네스는 이보다 관대하지만, 그렇지 않은 경우도 있습니다. 영향을 받은 클라이언트에서는 서버를 분리하는 것 외에는 에이전트를 다시 작동시킬 방법이 없었습니다.

이제 모든 도구의 입력 스키마가 유효한 JSON Schema draft 2020-12인지 확인하는 테스트가 추가되어, 새로 추가되는 도구로 인해 엄격한 클라이언트에서 같은 문제가 다시 발생하지 않습니다.

**관련 풀 리퀘스트:** [#2925](https://github.com/hyperdxio/hyperdx/pull/2925) draft 2020-12에 유효한 도구 입력 스키마 생성, [#2971](https://github.com/hyperdxio/hyperdx/pull/2971) 분위수 수준을 문자열 enum으로 노출

## 교체 가능한 개인 API 액세스 키 {#rotatable-personal-api-access-keys}

*데모 진행자: [@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/tHQoaFaVPpY" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 팀 설정 → API &amp; Agents에서 개인 API 액세스 키를 교체할 수 있습니다.

이 키는 외부 API v2와 MCP 서버의 Bearer 토큰으로 사용됩니다. 이전에는 계정을 만들 때 한 번 생성되면 변경할 수 없었기 때문에, 키가 유출되면 사용자를 삭제하는 것 외에는 대처 방법이 없었습니다.

교체는 유예 기간 없이 즉시 적용되며, 브라우저 세션은 로그인 상태로 유지됩니다. 다만 이 키는 팀이 아닌 계정에 속하므로 주의해야 합니다. 여러 팀에 속해 있다면 모든 팀에서 해당 키를 사용하는 항목을 전부 업데이트해야 합니다.

Enterprise에서는 이 내용을 안내하는 경고가 표시됩니다. 단일 팀으로 운영되는 오픈 소스 설치 환경에서는 경고할 내용이 없으므로 경고가 표시되지 않습니다.

여기에는 의도적인 제한이 두 가지 있습니다. `PATCH /me/accessKey` 라우트는 ID를 세션에서 가져오므로 사용자 식별자를 받지 않습니다. 따라서 호출자 본인의 키만 교체할 수 있습니다.

또한 이 라우트는 bearer 인증 방식의 외부 API v2에는 노출되지 않습니다. 유출된 키로는 이미 그곳에서 해당 키 자체를 조회할 수 있습니다. 여기에 교체까지 허용하면 제3자가 키 소유자를 본인의 도구에서 차단해 버릴 수 있습니다.

**관련 풀 리퀘스트:** [#2926](https://github.com/hyperdxio/hyperdx/pull/2926) 개인 API 액세스 키를 교체 가능하도록 변경

## Column Values 탭의 키 알파벳순 정렬 {#alphabetical-keys-in-the-column-values-tab}

*데모 진행자: [@teeohhem](https://github.com/teeohhem)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/9RfTL-dtZF0" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 행 사이드 패널의 Column Values 탭에 표시되는 키가 로그와 trace 모두에서 모든 중첩 수준에 걸쳐 알파벳순으로 정렬됩니다.

이전에는 JSON 트리가 키를 ClickHouse의 물리적 저장 순서대로 렌더링했기 때문에 사실상 무작위 순서로 표시되었습니다. 예를 들어 키가 125개인 `ProfileEvents` 같은 `Map` 컬럼은 일정한 순서가 없어서, 특정 키 하나를 찾으려면 전체 목록을 일일이 훑어봐야 했습니다.

잘 드러나지 않았던 또 다른 문제는 각 수준에 최대 50개 행만 표시되는데, 이 잘라내기가 정렬보다 먼저 수행되었다는 점입니다. 따라서 화면에 보이는 50개의 키는 임의의 부분 집합이었고, 나머지 키를 확인하려면 &quot;Expand 75 more properties&quot;를 클릭하는 수밖에 없었습니다.

이제 `TreeNode`에서 목록을 잘라내기 전에 정렬이 수행됩니다. 숫자를 인식하는 정렬 방식이므로 `key2`가 `key10`보다 앞에 표시됩니다.

**관련 풀 리퀘스트:** [#2943](https://github.com/hyperdxio/hyperdx/pull/2943) JSON 뷰어 키를 알파벳순으로 정렬

## 탐색 가능한 디자인 시스템으로 거듭난 Storybook {#storybook-as-a-browsable-design-system}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/mnHtrsuKsC8" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 Storybook은 단순한 컴포넌트 샌드박스가 아니라 탐색 가능한 디자인 시스템입니다. 사이드바는 Guidelines → Brand → Icons → Design Tokens → Components 순서로 구성됩니다.

Guidelines는 `agent_docs` Markdown을 직접 렌더링하므로 코드 스타일, 테마 적용, 페이지 레이아웃, 데이터 시각화 색상을 모두 한곳에서 확인할 수 있습니다. 이는 사람뿐 아니라 에이전트를 위한 것이기도 합니다. 새로 합류한 팀원이 읽는 문서를 에이전트에게도 똑같이 제공하면, 에이전트가 생성하는 컴포넌트가 기존 요소와 일관성을 유지하기 쉬워집니다.

Brand와 Icons에는 HyperDX 및 ClickStack 로고와 `IconAiNotebook`을 비롯한 사용자 정의 아이콘이 들어 있습니다. SVG를 복사하거나 다운로드할 수 있으며, Tabler 호환 아웃라인 아이콘과 브랜드 마크를 각각 언제 사용해야 하는지에 대한 가이드도 함께 제공됩니다.

이 작업은 슬라이드에 그럴듯해 보이는 아이콘을 아무거나 가져다 쓰던 문제에서 출발했습니다. 발표 자료에 마크가 필요하다면 여기에서 가져가십시오.

Brand 툴바로 HyperDX와 ClickStack을, Theme 툴바로 라이트 테마와 다크 테마를 전환할 수 있습니다. 따라서 새 컴포넌트를 출시하기 전에 모든 조합에서 확인할 수 있습니다. 분류되지 않은 채 흩어져 있던 컴포넌트 스토리는 이제 `Components/` 아래에 정리되었으며, 차트 카드 컴포넌트도 함께 노출됩니다.

작업 과정에서 두 가지 문제가 드러났습니다. 먼저 Storybook의 폰트 CSS 변수를 앱과 마찬가지로 `<html>`에 정의하도록 변경하여, 본문 텍스트와 포털로 렌더링되는 팝오버가 더 이상 Times 글꼴로 표시되지 않습니다.

또한 Tabler 아이콘 세트가 일관되게 사용되지 않고 있습니다. PromQL에는 전용 아이콘이 필요할 것으로 보이며, 메트릭과 trace는 현재 위치마다 서로 다른 아이콘으로 표시됩니다. 앞으로는 Storybook을 기준으로 삼으십시오.

로컬에서 실행하려면 `yarn workspace @hyperdx/app storybook` 명령을 사용하십시오.

**관련 풀 리퀘스트:** [#2935](https://github.com/hyperdxio/hyperdx/pull/2935) Storybook을 탐색 가능한 디자인 시스템으로 전환

## 히스토그램 차트에 범주형 팔레트 적용 {#categorical-palette-on-histogram-charts}

*데모 진행자: [@elizabetdev](https://github.com/elizabetdev)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/wybAadS6ms0" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

Services 대시보드의 Request Latency를 비롯한 히스토그램 차트는 색상이 `#50FA7B`로 하드코딩되어 있었습니다. 이 네온 그린 색상은 차트 팔레트에 속하지 않을 뿐 아니라 대비도 충분하지 않았습니다. 도구 설명의 &quot;Number of events&quot; 역시 같은 색상으로 렌더링되었습니다.

이제 차트는 `getColorFromCSSToken`을 통해 `chart-blue` 색상을 가져옵니다. 도구 설명은 공용 컴포넌트인 `ChartTooltipContainer`와 `ChartTooltipItem`을 사용하므로, 선 차트, 막대 차트, 파이 차트와 일관된 모습을 갖추게 되었습니다.

도구 설명의 **View events** 링크는 제거되었습니다. 내부 히스토그램과 도구 설명은 `generateSearchUrl`을 받을 수 있었지만 `DBHistogramChart`에서 이 값을 전달한 적이 없어, 운영 환경에서는 이 링크가 한 번도 표시되지 않았습니다.

유일한 호출자에는 소요 시간 버킷에 대한 검색 URL 빌더가 없으며, 이벤트를 지연 시간 범위로 필터링하는 것은 단순한 연결 수정이 아니라 별도의 기능에 해당합니다.

작은 개선이지만, 이런 개선이 모여 큰 차이를 만듭니다.
