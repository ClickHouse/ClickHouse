이 페이지에서는 ClickHouse Observability의 완전 관리형 모드와 자체 관리형 모드를 설명하고, 데이터 수집, 청구, 알림, 대시보드, 메트릭 탐색에 관해 자주 묻는 질문에 답변합니다.

## 배포 및 데이터 수집 {#data-collection}

<Accordion title="완전 관리형 ClickHouse Observability와 자체 관리형 ClickHouse Observability의 차이점은 무엇입니까?">
  **완전 관리형**

  <BetaBadge label="베타 서비스" />

  [완전 관리형 ClickHouse Observability](/ko/clickstack/observability/overview)로 시작하는 것을 권장합니다. 관리형 OpenTelemetry 엔드포인트로 텔레메트리를 전송하기만 하면 수집 collector, 스키마(schemas), 인프라 및 확장은 ClickHouse가 처리합니다.

  **자체 관리형**

  [자체 관리형 ClickHouse Observability](/ko/clickstack/self-configured/overview)를 사용하면 수집, 스키마(schemas), 보존 기간 및 데이터베이스 구성을 직접 제어할 수 있습니다. ClickHouse Cloud가 ClickHouse와 ClickStack UI를 호스팅하고, 사용자는 수집 collector를 운영하며 데이터베이스 튜닝 및 용량을 관리합니다. 자체 관리형은 베타 서비스가 아닙니다.
</Accordion>

<Accordion title="OpenTelemetry collector를 실행해야 합니까?">
  **완전 관리형:** 수집 collector를 배포할 필요가 없습니다. 애플리케이션과 텔레메트리 생성기에서 관리형 OpenTelemetry 엔드포인트로 데이터를 직접 전송할 수 있습니다.

  다만 로그 파일을 읽거나 호스트 및 Kubernetes 메트릭을 수집한 뒤 관리형 collector로 전달하려면 자체 환경에 별도의 collector가 필요할 수 있습니다. 예시는 [로컬 로그 및 메트릭](/ko/clickstack/observability/example-datasets/local-data)과 [Kubernetes 모니터링](/ko/clickstack/observability/example-datasets/kubernetes)을 참조하십시오.

  **자체 관리형:** ClickHouse Cloud 서비스에 연결된 수집 collector가 실행 중이어야 합니다. 애플리케이션과 에이전트가 이 collector로 텔레메트리를 전송하면 collector가 이를 ClickHouse에 기록합니다. ClickStack 배포판 사용을 권장합니다. 연결 방법은 [OpenTelemetry를 사용한 데이터 수집](/ko/clickstack/observability/ingesting-data/opentelemetry#installing-otel-collector-managed-self-configured)을, collector 시작 방법은 [배포 가이드](/ko/clickstack/self-configured/deployment/managed#start-a-collector-existing)를 참조하십시오.
</Accordion>

<Accordion title="텔레메트리 엔드포인트와 API Key는 어디에서 확인할 수 있습니까?">
  **완전 관리형:** ClickHouse Observability 서비스에서 **팀 설정 → 데이터 → Managed Telemetry**로 이동한 후 OTLP 엔드포인트와 수집 API key를 복사하십시오. 이 정보는 SDK, 전달용 collector 또는 텔레메트리 생성기를 구성할 때 사용합니다.

  **자체 관리형:** 직접 운영하는 collector의 OTLP 엔드포인트와, 해당 리시버에 인증 토큰이 구성되어 있다면 그 토큰을 사용하십시오. ClickStack 수집기에서 `OTLP_AUTH_TOKEN`을 활성화한 경우 해당 토큰을 `authorization` 헤더에 담아 전송하십시오. 이 정보는 collector가 데이터를 기록할 때 사용하는 ClickHouse Cloud 데이터베이스 엔드포인트 및 자격 증명과는 별개입니다. 예시는 [OpenTelemetry를 사용한 데이터 수집](/ko/clickstack/observability/ingesting-data/opentelemetry#sending-data-to-collector-managed-self-configured)을 참조하십시오.

  엔드포인트 형식은 사용 중인 도구의 요구 사항에 맞추십시오. [샘플 데이터 및 데모](/ko/clickstack/observability/example-datasets)에서 도구별 구성 예시를 확인할 수 있습니다.
</Accordion>

<Accordion title="ClickHouse Observability 요금은 어떻게 청구됩니까?">
  **완전 관리형:** 컴퓨트와 스토리지가 아니라 전송한 텔레메트리 양에 따라 요금이 부과됩니다. 로그와 트레이스는 압축 전 데이터 양을 기준으로, 메트릭은 시계열 단위가 아닌 데이터 포인트 수를 기준으로 청구됩니다. 퍼블릭 베타 기간에는 데이터가 30일간 보존됩니다. 현재 요금은 [ClickHouse 요금](https://clickhouse.com/pricing)을 참조하십시오.

  **자체 관리형:** ClickHouse Cloud 서비스의 컴퓨트와 스토리지 사용량에 따라 요금이 부과됩니다. 요금은 이 옵션의 이전 명칭인 Managed ClickStack과 동일합니다. 자세한 내용은 [ClickHouse Cloud 요금](/ko/products/cloud/reference/billing/billing-overview)을 참조하십시오.
</Accordion>

## 알림 {#alerting}

<Accordion title="ClickHouse Observability는 어떤 유형의 알림을 지원합니까?">
  ClickHouse Observability는 두 가지 유형의 알림을 지원합니다.

  * [검색 알림](/ko/clickstack/observability/features/alerts#search-alerts): 시간 윈도우(time window) 내에서 일치하는 로그 또는 트레이스 결과의 개수가 임계값보다 많아지거나 적어지면 알림을 보냅니다.
  * [대시보드 차트 알림](/ko/clickstack/observability/features/alerts#dashboard-alerts): 대시보드 타일에 표시된 메트릭이 지정된 임계값을 넘으면 알림을 보냅니다.

  두 유형 모두 구성된 임계값을 기준으로 결과를 평가합니다. 자세한 내용은 [알림](/ko/clickstack/observability/features/alerts)을 참조하십시오.
</Accordion>

<Accordion title="비율, p95/p99, 다중 메트릭 수식과 같은 복잡한 메트릭 조건에 대해 알림을 설정할 수 있습니까?">
  먼저 해당 계산을 대시보드 차트로 구성한 다음, 그 차트에 임계값 알림을 연결하십시오. [차트 빌더](/ko/clickstack/observability/features/dashboards/overview#navigate-chart-explorer)는 비율, 백분위수 등의 계산을 지원합니다.

  SQL이 필요한 계산에는 [SQL 기반 차트 알림](/ko/clickstack/observability/features/alerts#sql-based-alerts)을 사용하십시오. SQL 알림은 선, Stacked Bar, 숫자 차트를 지원합니다. 대시보드를 저장해야 알림이 활성화됩니다.
</Accordion>

## 대시보드 및 드릴다운 {#dashboards-and-drill-downs}

<Accordion title="사전 구축된 대시보드가 제공됩니까?">
  예. **대시보드**를 열면 **Services**, **Kubernetes**, **LLM** 프리셋 대시보드를 확인할 수 있습니다. 이 대시보드들은 관련 텔레메트리가 수집되고 있고, 선택한 시간 범위에 해당 데이터가 포함되어 있을 때 데이터를 표시합니다.

  수집된 로그, 트레이스, 메트릭을 사용하여 사용자 정의 대시보드를 만들 수도 있습니다. 차트를 작성하고 대시보드로 구성하는 방법은 [대시보드](/ko/clickstack/observability/features/dashboards/overview)를 참조하십시오.
</Accordion>

<Accordion title="ClickHouse Observability는 매개변수화된 대시보드나 대시보드 변수를 지원합니까?">
  예. ClickHouse Observability는 ClickHouse에서 조회한 데이터로 채워지는 사용자 지정 필터 및 변수를 통해 매개변수화된 대시보드를 지원합니다. 이러한 필터를 사용하면 대시보드의 일부 또는 전체 타일 범위를 특정 값(예: 서비스 이름, 환경, 호스트)으로 동적으로 한정할 수 있습니다.

  대시보드 생성 및 필터 적용에 대한 자세한 내용은 [대시보드](/ko/clickstack/observability/features/dashboards/overview)를 참조하십시오.
</Accordion>

<Accordion title="어떤 드릴다운 기능을 사용할 수 있습니까?">
  ClickHouse Observability는 다음과 같은 드릴다운 워크플로를 지원합니다.

  * [대시보드 수준 필터링](/ko/clickstack/observability/features/dashboards/overview#filter-dashboards): 대시보드 수준의 Lucene 또는 SQL 필터는 **Apply filters**가 활성화된 타일에 적용됩니다. 대시보드의 시간 범위도 조정할 수 있습니다.
  * 사용자 지정 대시보드 필터: 사용자 정의 대시보드는 데이터의 값으로 채워지는 명시적인 필터 컨트롤을 제공하므로, 쿼리를 직접 작성하지 않고도 필터가 적용되는 타일의 범위를 한정할 수 있습니다.
  * 클릭하여 이벤트 보기: 대시보드 타일의 데이터를 클릭한 후 **View Events**를 선택하면 로그 및 트레이스 데이터에 대한 관련 필터가 적용된 [검색](/ko/clickstack/observability/features/search) 페이지로 이동합니다.
  * [테이블 행 클릭 드릴다운](/ko/clickstack/observability/features/dashboards/row-click-drilldowns): 행을 클릭하면 검색 페이지나 다른 대시보드가 열리고 해당 행의 값이 필터로 전달되도록 테이블 타일을 구성할 수 있습니다. 이를 통해 서비스 목록에서 서비스별 상세 대시보드로 드릴다운하는 등의 다단계 워크플로를 구현할 수 있습니다.

  <Note>
    개별 로그와 트레이스를 살펴보려면 [검색](/ko/clickstack/observability/features/search)을 사용하십시오. 메트릭을 탐색하려면 차트 탐색기를 사용하십시오.
  </Note>
</Accordion>

## 메트릭 탐색 {#metrics-discovery}

<Accordion title="메트릭을 둘러보고 검색할 수 있는 UI가 있습니까?">
  ![메트릭 속성 탐색기](/images/clickstack/faq/metrics-explorer-fully-managed.png)

  메트릭 이름은 [차트 빌더](/ko/clickstack/observability/features/dashboards/overview#navigate-chart-explorer)의 메트릭 이름 드롭다운에서 찾을 수 있습니다. 메트릭을 선택하면 메트릭 속성 탐색기(Metric Attribute Explorer) 패널에 해당 메트릭의 설명, 단위, 사용 가능한 속성 및 각 속성의 값이 표시됩니다. 이 패널에서 속성을 둘러보고 필터나 group-by 필드로 바로 추가할 수 있습니다.

  현재는 로그 검색과 같은 전용 메트릭 검색 페이지가 제공되지 않습니다.
</Accordion>
