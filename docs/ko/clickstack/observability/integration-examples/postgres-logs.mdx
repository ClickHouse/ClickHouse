OpenTelemetry collector로 PostgreSQL CSV 로그를 수집하여 ClickHouse Observability로 전송합니다. PostgreSQL을 설치하지 않고 통합 기능을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* collector 예시를 실행할 Docker
* 자체 로그를 사용하려면 PostgreSQL 14 이상 버전과 해당 구성 및 로그 파일에 대한 액세스 권한
* 데모를 실행하려면 샘플 데이터를 다운로드할 `curl`

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동합니다. OTLP HTTP 엔드포인트와 API Key를 복사합니다. **Copy connection details**를 사용하면 구성을 복사할 수 있고, **Reveal key**를 사용하면 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/logs` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 PostgreSQL과 통합 {#existing-postgres}

<Steps>
  <Step title="PostgreSQL 로깅 구성" id="configure-postgres">
    데이터베이스 관리자 권한으로 다음 SQL을 실행하여 설정 파일의 위치를 확인하십시오:

    ```sql
    SHOW config_file;
    ```

    `postgresql.conf`에 다음 설정을 추가하거나 수정하십시오:

    ```conf
    logging_collector = on
    log_destination = 'csvlog'
    log_directory = '/var/log/postgresql'
    log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
    log_file_mode = 0640
    log_timezone = 'UTC'
    log_connections = on
    log_disconnections = on
    # Optional: log statements taking more than one second
    # log_min_duration_statement = 1000
    ```

    PostgreSQL이 쓰기(write)를 수행하고 collector가 읽을 수 있도록 소유권과 권한을 지정하여 로그 디렉터리를 생성하십시오. PostgreSQL을 컨테이너로 실행하는 경우, collector가 동일한 파일에 액세스할 수 있도록 해당 디렉터리를 마운트하십시오. `log_filename`이 `.log`로 끝나더라도 CSV 출력 파일에는 `.csv` 확장자가 사용됩니다.

    사용 중인 배포 절차에 따라 PostgreSQL을 재시작하십시오. 예를 들면 다음과 같습니다.

    ```bash
    sudo systemctl restart postgresql
    # Or, for Docker:
    docker restart <postgres-container>
    ```

    현재 사용 중인 CSV 파일을 확인하십시오:

    ```sql
    SELECT pg_current_logfile('csvlog');
    ```

    아래 파서는 [26개 컬럼으로 구성된 PostgreSQL CSV 형식](https://www.postgresql.org/docs/14/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-CSVLOG)을 기준으로 합니다. 이전 PostgreSQL 버전이나 다른 로그 형식에는 별도의 파서가 필요합니다.
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `postgres-logs-monitoring.yaml` 파일로 저장하십시오.

    ```yaml
    receivers:
      filelog/postgres:
        include:
          - /var/log/postgresql/postgresql-*.csv
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'
        operators:
          - type: csv_parser
            parse_from: body
            parse_to: attributes
            header: 'log_time,user_name,database_name,process_id,connection_from,session_id,session_line_num,command_tag,session_start_time,virtual_transaction_id,transaction_id,error_severity,sql_state_code,message,detail,hint,internal_query,internal_query_pos,context,query,query_pos,location,application_name,backend_type,leader_pid,query_id'
            lazy_quotes: true

          - type: time_parser
            parse_from: attributes.log_time
            layout: '%Y-%m-%d %H:%M:%S.%L %Z'
            location: UTC

          - type: add
            field: attributes.source
            value: "postgresql"

          - type: add
            field: resource["service.name"]
            value: "postgresql-service"

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/postgres:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "debug") where IsMatch(log.attributes["error_severity"], "^DEBUG")
              - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
              - set(log.severity_text, "warn") where log.attributes["error_severity"] == "WARNING"
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where log.attributes["error_severity"] == "ERROR"
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where log.attributes["error_severity"] == "FATAL" or log.attributes["error_severity"] == "PANIC"
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    수신기는 여러 줄로 된 CSV 항목을 파싱하고 타임스탬프와 본문을 그대로 유지하며, `service.name` 값으로 `postgresql-service`를 추가합니다. `database_name`, `error_severity`, `message`, `query` 등의 필드는 계속 로그 속성으로 사용할 수 있습니다.
  </Step>

  <Step title="collector 실행" id="run-collector">
    구성 파일이 있는 디렉터리에서 다음 명령을 실행하십시오. 필요하면 호스트의 로그 디렉터리 경로를 조정하십시오. 로그 파일에 그룹 읽기 권한이 설정되어 있다면 `ls -ln /var/log/postgresql`에 표시되는 숫자 그룹 ID를 사용하여 `--group-add LOG_GROUP_ID`를 추가하십시오.

    ```bash
    docker run --rm --name postgres-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/postgresql:/var/log/postgresql:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    터미널은 열어 두십시오. 수신기가 `start_at: end`를 사용하므로, collector를 시작한 후 새 데이터베이스 연결(database connection)을 생성하거나 오류를 발생시키는 쿼리를 실행하십시오:

    ```sql
    SELECT 1 / 0;
    ```
  </Step>

  <Step title="로그 확인" id="verify-logs">
    **검색**을 열고 **로그**를 선택한 다음, `ServiceName:postgresql-service`로 필터링하고 **최근 15분**을 선택하십시오. 레코드를 펼치면 PostgreSQL 속성과 심각도를 확인할 수 있습니다.
  </Step>
</Steps>

              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-10T23:59:47Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:

        send_batch_size: 500
        send_batch_max_size: 500

      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/postgres:
          receivers: [filelog/postgres]
          processors: [memory_limiter, transform/postgres, transform/demo_timestamps, batch]

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collector-fails-to-start}

collector 출력에 구성 오류가 있는지 확인하십시오. 또한 Docker를 실행하는 터미널에서 구성 마운트와 연결 변수가 올바른지 확인하십시오.

### 로그가 표시되지 않는 경우 {#no-logs}

인증 오류나 내보내기 오류가 있는지 확인하세요. `pg_current_logfile`로 CSV 경로를 확인하고, 파일이 수신기의 `include` 패턴과 일치하는지, collector가 해당 파일을 읽을 수 있는지 확인하세요. `start_at: end`로 설정하면 새로 추가된 엔트리만 수집됩니다. 데모 환경에서는 타임스탬프 프로세서를 포함하고 **최근 2일**을 선택하세요.

### 권한 거부됨 {#permission-denied}

PostgreSQL은 일반적으로 소유자만 액세스할 수 있는 로그 파일을 생성합니다. 위 구성에서는 `log_file_mode = 0640`을 사용하여 그룹 읽기를 허용합니다. `--group-add`를 사용해 파일의 그룹을 collector 컨테이너에 추가하십시오. 기존 파일에는 이전 권한이 그대로 유지됩니다. 디렉터리에서도 그룹 액세스를 허용하는지 확인하십시오.

### CSV 파싱 오류 {#csv-parsing-errors}

파서는 PostgreSQL 14 이상 버전의 26개 컬럼 구성을 전제로 합니다. `log_destination = 'csvlog'` 및 `log_timezone = 'UTC'`로 설정되어 있는지 확인하십시오. 이전 버전이나 사용자 정의 포맷을 사용하는 경우 헤더를 조정하십시오. stderr 및 JSON 로그에는 이 CSV 파서를 사용할 수 없습니다.
