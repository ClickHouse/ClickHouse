OpenTelemetry `filelog` 수신기로 MongoDB 서버 로그를 수집하여 ClickHouse Observability로 전송합니다. MongoDB를 배포하지 않고 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 사용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* Docker 및 `curl`
* 자체 로그를 사용하려면 JSON 로그 파일에 액세스할 수 있는 자가 관리형 MongoDB 4.4 이상 배포 환경

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동하십시오. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나 **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/logs` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 신호 경로는 익스포터가 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에서 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 MongoDB와 통합 {#existing-mongodb}

<Steps>
  <Step title="MongoDB 로깅 구성 확인" id="verify-mongodb">
    MongoDB 4.4 이상은 구조화된 JSON 형식의 서버 로그를 사용합니다. MongoDB 설정 파일의 `systemLog` 섹션을 확인하십시오. Linux에서 일반적으로 사용하는 로그 경로는 `/var/log/mongodb/mongod.log`입니다.

    MongoDB가 stdout으로만 로그를 출력한다면 `mongod.conf`에서 파일 로깅을 구성하십시오.

    ```yaml
    systemLog:
      destination: file
      path: /var/log/mongodb/mongod.log
      logAppend: true
    ```

    MongoDB는 쓰고 collector는 읽을 수 있도록 권한을 지정하여 디렉터리를 생성하십시오. 컨테이너 기반 배포에서는 로그 디렉터리를 collector와 공유하고, MongoDB가 설정 파일을 로드하는지 확인하십시오.

    사용 중인 배포 방식에 맞게 MongoDB를 재시작하십시오. 예를 들면 다음과 같습니다.

    ```bash
    sudo systemctl restart mongod
    # 또는 Docker의 경우:
    docker restart <mongodb-container>
    ```
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `mongodb-monitoring.yaml`로 저장하십시오.

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb"

          - type: add
            field: resource["service.name"]
            value: "mongodb-service"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, batch]
          exporters: [otlp_http/observability]
    ```

    파서는 MongoDB의 타임스탬프 및 심각도 필드를 읽고, `msg`를 로그 body로 옮기며, `c`, `ctx`, `id`, `attr` 등의 필드는 로그 속성으로 유지합니다. `$$date`는 수정하지 말고 그대로 두십시오. collector가 이스케이프된 달러 기호를 해석하여 MongoDB의 `$date` 필드로 인식합니다. 실시간 수신기는 `start_at: end` 설정에 따라 새로 추가되는 항목만 읽습니다.
  </Step>

  <Step title="collector 실행" id="run-collector">
    [연결 변수](#connection-details)를 설정한 다음 구성 디렉터리에서 실행하십시오. 필요하면 호스트의 로그 경로를 조정하십시오. 그룹 읽기 권한이 설정된 파일이라면 `ls -ln /var/log/mongodb`로 확인한 숫자 그룹 ID를 사용하여 `--group-add LOG_GROUP_ID`를 추가하십시오.

    ```bash
    docker run --rm --name mongodb-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/mongodb:/var/log/mongodb:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    터미널을 열어 둔 채로 서버 활동을 발생시켜 새 로그 항목이 기록되도록 하십시오. 테스트가 끝나면 **Ctrl+C**를 눌러 중지하십시오.
  </Step>

  <Step title="로그 확인" id="verify-logs">
    **검색**을 열고 **Logs**를 선택한 다음 `ServiceName:mongodb-service`로 필터링하고 **Last 15 minutes**를 선택하십시오. 타임스탬프와 심각도가 파싱된 서버 메시지가 표시됩니다.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 표본(sample)에는 약 24시간 동안 기록된 MongoDB 서버 로그 항목 6,956개가 포함되어 있습니다. collector는 메시지와 구조화된 속성은 그대로 유지하면서 타임스탬프만 갱신합니다.

<Steps>
  <Step title="표본 다운로드" id="download-sample">
    ```bash
    curl -fL -o mongod.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/mongodb/mongod.log
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo">
    다음 내용을 `mongodb-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      filelog/mongodb:
        include:
          - /var/log/mongodb/mongod.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.t.$$date
              layout: '2006-01-02T15:04:05.000Z07:00'
              layout_type: gotime
            severity:
              parse_from: attributes.s
              overwrite_text: true
              mapping:
                fatal: F
                error: E
                warn: W
                info: I
                debug:
                  - D1
                  - D2
                  - D3
                  - D4
                  - D5

          - type: move
            from: attributes.msg
            to: body

          - type: add
            field: attributes.source
            value: "mongodb-demo"

          - type: add
            field: resource["service.name"]
            value: "mongodb-demo"
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/mongodb:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:52.193Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/mongodb:
          receivers: [filelog/mongodb]
          processors: [memory_limiter, transform/mongodb, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="데모 collector 실행" id="run-demo">
    [연결 변수](#connection-details)를 설정한 다음, 두 파일이 있는 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    docker run --rm --name mongodb-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/mongodb-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/mongod.log:/var/log/mongodb/mongod.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    수집 여부를 확인하는 동안에는 터미널을 열어 두십시오. 확인이 끝나면 **Ctrl+C**를 눌러 중지하십시오. 데모를 다시 실행하면 타임스탬프가 갱신된 상태로 표본이 다시 수집됩니다.
  </Step>

  <Step title="데모 로그 확인" id="verify-demo">
    **검색**을 열고 **Logs**를 선택한 다음, `ServiceName:mongodb-demo`로 필터링하고 **Last 2 days**를 선택하십시오.

## 문제 해결 {#troubleshooting}

### 로그가 표시되지 않는 경우 {#no-logs}

collector 출력에서 파일 권한, 파싱, 인증 또는 내보내기 오류가 있는지 확인하십시오. 서버가 마운트된 디렉터리에 로그를 기록하는지, 파일 이름이 수신기의 `include` 목록과 일치하는지도 확인하십시오. 현재 실행 중인 구성은 새로 추가된 로그 항목만 읽습니다.

### 로그가 올바르게 파싱되지 않는 경우 {#parsing-errors}

파일의 각 줄에 JSON 객체가 하나씩 들어 있는지 확인하십시오:

```bash
tail -n 1 /var/log/mongodb/mongod.log | python3 -m json.tool
```

이 파서는 MongoDB 4.4+ JSON 로그를 처리하도록 설계되었습니다. 레거시 텍스트 로그를 처리하려면 별도의 파서가 필요합니다. 수집기 설정에서 `$$date` 이스케이프 처리를 그대로 유지하십시오.
