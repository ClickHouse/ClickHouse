OpenTelemetry collector로 호스트의 syslog 파일을 수집하여 ClickHouse Observability로 전송합니다. 자체 호스트에서 로그를 수집하지 않고 통합을 먼저 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* collector 예시를 실행하기 위한 Docker 또는 기존 OpenTelemetry Collector Contrib 배포
* 자체 로그를 사용하려면 syslog 파일과 collector가 해당 파일을 읽을 수 있는 권한(permission)
* 데모를 실행하려면 샘플을 다운로드할 `curl`

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동하십시오. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나, **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    플레이스홀더를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 바꾸십시오. 엔드포인트에는 `/v1/logs` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 신호 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형" id="self-managed">
    collector에서 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 호스트와 통합 {#existing-hosts}

<Steps>
  <Step title="syslog 파일을 찾으십시오" id="locate-syslog">
    일반적으로 Ubuntu/Debian에서는 `/var/log/syslog`, RHEL 기반 시스템에서는 `/var/log/messages`, macOS 텍스트 로그는 `/var/log/system.log`에 위치합니다. 호스트에 실제로 있는 파일을 확인하십시오:

    ```bash
    tail -20 /var/log/syslog
    ```

    필요에 따라 경로를 변경하십시오. Linux 호스트가 systemd 저널에만 로그를 기록한다면 [Systemd/Journald 가이드](/ko/clickstack/observability/integration-examples/systemd)를 참고하십시오. 이 가이드는 텍스트 파일을 읽는 방식이므로 MacOS 통합 로그 저장소(unified log store)는 수집하지 않습니다.
  </Step>

  <Step title="collector 구성" id="configure-collector">
    파일의 타임스탬프 형식에 맞는 구성을 선택하여 `host-logs.yaml`로 저장하십시오. 필요한 경우 `include`를 `/var/log/host/messages` 또는 `/var/log/host/system.log`로 변경하십시오. 다른 파일은 동일한 포맷을 사용하는 경우에만 추가하십시오.

    <Tabs>
      <Tab title="ISO 타임스탬프">
        `2026-10-15T12:34:56.123456+00:00`처럼 타임스탬프로 시작하는 줄에 사용합니다.

        ```yaml
        receivers:
          filelog/host:
            include: [/var/log/host/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: '2006-01-02T15:04:05.999999999Z07:00'
                  location: UTC
              - type: add
                field: attributes.source
                value: host-logs
              - type: add
                field: resource["service.name"]
                value: host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/host:
              receivers: [filelog/host]
              processors: [memory_limiter, batch]
              exporters: [otlp_http/observability]
        ```
      </Tab>

      <Tab title="전통적인 syslog">
        `Oct 15 12:34:56`처럼 타임스탬프로 시작하는 줄에 사용합니다.

        ```yaml
        receivers:
          filelog/host:
            include: [/var/log/host/syslog]
            start_at: end
            operators:
              - type: regex_parser
                regex: '^(?P<timestamp>\w+\s+\d+ \d{2}:\d{2}:\d{2}) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
                timestamp:
                  parse_from: attributes.timestamp
                  layout_type: gotime
                  layout: 'Jan _2 15:04:05'
                  location: UTC
              - type: add
                field: attributes.source
                value: host-logs
              - type: add
                field: resource["service.name"]
                value: host-service
              - type: copy
                from: attributes.hostname
                to: resource["host.name"]

        processors:
          memory_limiter:
            check_interval: 1s
            limit_mib: 256
            spike_limit_mib: 64
          batch:
            timeout: 5s
            send_batch_size: 500
            send_batch_max_size: 500

        exporters:
          otlp_http/observability:
            endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
            headers:
              authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

        service:
          pipelines:
            logs/host:
              receivers: [filelog/host]
              processors: [memory_limiter, batch]
              exporters: [otlp_http/observability]
        ```

        전통적인 형식의 타임스탬프에는 연도와 시간대가 없습니다. 연도는 파서가 추론합니다. 호스트가 UTC로 로그를 기록하지 않는다면 `location`을 호스트의 IANA 시간대(예: `Asia/Seoul`)로 설정하십시오.
      </Tab>
    </Tabs>

    수신기는 `hostname`, `unit`, `pid`(있는 경우), `message`를 추출하고, 원본 줄은 `Body`에 그대로 유지합니다. 또한 `service.name`을 `host-service`로 설정하고 호스트명을 `host.name`에 복사합니다. 이러한 텍스트 형식에는 심각도 필드가 없으므로, 이 구성은 메시지 텍스트에서 심각도를 추론하지 않습니다.
  </Step>

  <Step title="collector 실행" id="run-collector">
    [연결 변수](#connection-details)를 설정하십시오. 그런 다음 `host-logs.yaml` 파일이 있는 디렉터리에서 다음 명령을 실행하십시오:

    ```bash
    docker run --rm --name host-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/host-logs.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log:/var/log/host:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    macOS에서는 `-v /private/var/log:/var/log/host:ro`를 사용하고, Docker Desktop이 해당 디렉터리에 액세스할 수 있도록 허용하십시오. 또한 collector가 선택한 로그 파일을 읽을 수 있는지 확인하십시오.

    이 터미널은 열어 둔 상태로 유지하십시오. `start_at: end`로 설정하면 수신기는 시작 이후에 기록된 새 줄만 수집합니다. 선택한 로그 파일에 로그가 기록되도록 평소와 같은 작업을 수행하십시오.
  </Step>

  <Step title="로그 확인" id="verify-logs">
    **검색**을 열고 **Logs** 소스를 선택한 다음 `ServiceName:host-service`로 필터링하고 **Last 15 minutes**를 선택하십시오. 로그를 펼치면 파싱된 호스트명, 유닛(unit), PID, 메시지를 확인할 수 있습니다.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

샘플에는 24시간 분량의 syslog 11,658줄이 포함되어 있으며, 부팅 메시지, SSH 활동, 방화벽 차단, 예약 작업, 서비스 재시작 기록 등이 담겨 있습니다.

<Steps>
  <Step title="샘플 다운로드" id="download-sample">
    ```bash
    mkdir -p host-demo
    cd host-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/host-logs/journal.log
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다운로드 디렉터리에 다음 내용을 `host-logs-demo.yaml`로 저장하세요.

    ```yaml
    receivers:
      filelog/host:
        include: [/var/log/host/journal.log]
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%dT%H:%M:%S%z'
              location: UTC
          - type: add
            field: attributes.source
            value: host-demo
          - type: add
            field: resource["service.name"]
            value: host-demo
          - type: copy
            from: attributes.hostname
            to: resource["host.name"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T23:59:01Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/host:
          receivers: [filelog/host]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      데모 전용 타임스탬프 변환은 샘플을 대략 최근 24시간 범위로 옮기며, 수집 시점 2분 전에 끝나도록 조정합니다. 실제 로그는 원래 타임스탬프가 유지되도록 [기존 호스트 구성](#existing-hosts)을 사용하십시오.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    [연결 변수](#connection-details)를 설정한 다음, 다운로드 디렉터리에서 다음 명령을 실행하세요.

    ```bash
    docker run --rm --name host-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/host-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/host:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector가 샘플을 내보내는 동안 터미널을 열어 두고, 출력에 오류가 없는지 확인하세요. 새 컨테이너를 다시 시작하면 샘플 로그가 중복 수집될 수 있습니다.
  </Step>

  <Step title="데모 로그 확인" id="verify-demo-logs">
    **검색**을 열고 **Logs** 소스를 선택한 뒤, `ServiceName:host-demo`로 필터링하고 **최근 2일**을 선택하세요. 로그를 펼치면 파싱된 속성을 확인할 수 있습니다. 데이터를 확인했으면 **Ctrl+C**로 collector를 중지하세요.

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability 검색의 호스트 데모 로그](/images/clickstack/observability-host-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collector-fails-to-start}

collector 터미널에 구성 오류가 표시되는지 확인하십시오. 또한 마운트된 경로에 YAML 파일이 있는지, Docker를 실행하는 터미널에 연결 변수가 설정되어 있는지 확인하십시오.

### 로그가 표시되지 않는 경우 {#no-logs}

* 호스트에 파일이 있는지, 그리고 마운트된 경로가 `include`와 일치하는지 확인하십시오.
* 파일 권한을 확인하고, macOS에서는 Docker Desktop의 파일 공유 설정도 확인하십시오.
* 실시간 로그는 collector가 시작된 후 새 엔트리를 생성해야 수집됩니다. `start_at: end` 설정은 기존 내용을 건너뜁니다.
* collector 출력에 인증 오류나 내보내기 오류가 있는지 확인하십시오.
* **Logs** 소스, 서비스 이름 필터, 시간 범위를 확인하십시오. 데모 데이터의 경우 **최근 2일**을 선택하십시오.

### 로그가 올바르게 파싱되지 않는 경우 {#logs-not-parsing}

파일의 한 줄을 선택한 타임스탬프 포맷과 비교하십시오. 해당 포맷에 맞는 구성을 사용하고, 필요하면 기존(traditional) syslog의 시간대를 조정하십시오. 파일 글롭 범위를 너무 넓게 지정하면 관련 없는 애플리케이션 로그 형식까지 수집될 수 있으므로 주의하십시오.
