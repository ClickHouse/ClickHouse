2개의 OpenTelemetry collector로 컨테이너 로그, 노드 및 클러스터 메트릭, Kubernetes 이벤트를 수집합니다. 각 노드에서 실행되는 데몬셋(DaemonSet)과 클러스터 전체 데이터를 수집하는 단일 배포(Deployment)로 구성됩니다.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* Linux 노드로 구성되고, 워크로드, 클러스터 역할(ClusterRole), 호스트 경로 마운트를 생성할 수 있는 권한(permission)이 있는 Kubernetes 클러스터
* 대상 클러스터에 맞게 구성된 `kubectl` 및 Helm 3 설치
* collector에서 서비스의 OTLP HTTP 엔드포인트, Kubernetes API, 큐블릿(kubelet)에 접근할 수 있는 네트워크 연결

이 collector는 인프라 데이터를 수집합니다. 애플리케이션 메트릭과 트레이스를 전송하려면 애플리케이션을 별도로 계측하십시오. 자세한 내용은 [OpenTelemetry 통합](/ko/clickstack/observability/ingesting-data/opentelemetry)을 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```

## collector 배포 {#deploy-collectors}

<Steps>
  <Step title="네임스페이스를 생성하고 연결을 설정하십시오" id="connection-settings">
    `kubectl`이 의도한 클러스터를 가리키고 있는지 확인하세요:

    ```bash
    kubectl config current-context
    kubectl create namespace observability --dry-run=client -o yaml | kubectl apply -f -

    kubectl create configmap observability-connection -n observability \
      --from-literal=endpoint="$OTEL_EXPORTER_OTLP_ENDPOINT" \
      --dry-run=client -o yaml | kubectl apply -f -

    kubectl create secret generic observability-connection -n observability \
      --from-literal=authorization="$OTEL_EXPORTER_OTLP_AUTHORIZATION" \
      --dry-run=client -o yaml | kubectl apply -f -
    ```

    두 collector 모두 `observability` 네임스페이스에서 이 설정을 사용합니다.
  </Step>

  <Step title="공유 구성을 저장하십시오" id="shared-configuration">
    다음 내용을 `k8s_common.yaml` 파일로 저장하십시오:

    ```yaml
    image:
      repository: otel/opentelemetry-collector-contrib
      tag: "0.161.0"
    command:
      name: otelcol-contrib
    resources:
      limits:
        memory: 512Mi
    presets:
      kubernetesAttributes:
        enabled: true
    extraEnvs:
      - name: OTEL_EXPORTER_OTLP_ENDPOINT
        valueFrom:
          configMapKeyRef:
            name: observability-connection
            key: endpoint
      - name: OTEL_EXPORTER_OTLP_AUTHORIZATION
        valueFrom:
          secretKeyRef:
            name: observability-connection
            key: authorization
    service:
      enabled: false
    ports:
      otlp:
        enabled: false
      otlp-http:
        enabled: false
      jaeger-compact:
        enabled: false
      jaeger-thrift:
        enabled: false
      jaeger-grpc:
        enabled: false
      zipkin:
        enabled: false
    config:
      receivers:
        otlp: null
        jaeger: null
        zipkin: null
        prometheus: null
      exporters:
        debug: null
        otlp_http/observability:
          endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
          headers:
            authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
          compression: gzip
      processors:
        batch:
          timeout: 5s
          send_batch_size: 500
          send_batch_max_size: 500
      service:
        pipelines:
          logs:
            receivers: []
            exporters: [otlp_http/observability]
          metrics:
            receivers: []
            exporters: [otlp_http/observability]
          traces: null
    ```

    차트 사전 설정은 각 collector에 필요한 수신기, Kubernetes 메타데이터 프로세서, RBAC 규칙, 마운트를 추가합니다. 공유 구성은 로그와 메트릭을 서비스로 전달하며, 사용하지 않는 애플리케이션 수집용 수신기를 비활성화합니다.
  </Step>

  <Step title="노드 데이터 수집 구성" id="daemonset-configuration">
    다음 내용을 `k8s_daemonset.yaml`로 저장하십시오.

    ```yaml
    mode: daemonset
    presets:
      logsCollection:
        enabled: true
        storeCheckpoints: true
      hostMetrics:
        enabled: true
      kubeletMetrics:
        enabled: true
    config:
      receivers:
        kubeletstats:
          insecure_skip_verify: true
    ```

    데몬셋은 컨테이너 로그를 읽고 호스트 및 큐블릿 메트릭을 수집합니다. 체크포인트를 사용하면 collector가 재시작되더라도 로그 읽기 위치가 유지됩니다. 이 사전 설정은 노드에 체크포인트를 기록하기 위해 collector를 root 권한으로 실행하므로, 클러스터의 파드 보안 설정에서 해당 호스트 마운트를 허용해야 합니다.

    이 예시에서는 collector가 큐블릿 인증서를 신뢰하지 않는 클러스터를 고려하여 큐블릿 인증서 검증을 건너뜁니다. 클러스터에서 신뢰할 수 있는 큐블릿 인증서를 제공하는 경우 `insecure_skip_verify`를 `false`로 설정하고 적절한 인증 기관(CA)을 구성하십시오.
  </Step>

  <Step title="클러스터 데이터 수집 구성" id="deployment-configuration">
    다음 내용을 `k8s_deployment.yaml` 파일로 저장하십시오:

    ```yaml
    mode: deployment
    replicaCount: 1
    presets:
      kubernetesEvents:
        enabled: true
      clusterMetrics:
        enabled: true
    ```

    클러스터 메트릭과 이벤트가 중복으로 수집되지 않도록 레플리카를 1개로 유지하십시오.
  </Step>

  <Step title="Helm 릴리스를 설치하십시오" id="install-collectors">
    설정 파일 3개가 있는 디렉터리에서 실행하십시오. 이 예시에서는 OpenTelemetry Collector 차트 `0.175.1`과 Collector Contrib `0.161.0`을 사용합니다:

    ```bash
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update open-telemetry

    helm upgrade --install observability-nodes open-telemetry/opentelemetry-collector \
      --version 0.175.1 --namespace observability \
      -f k8s_common.yaml -f k8s_daemonset.yaml --wait

    helm upgrade --install observability-cluster open-telemetry/opentelemetry-collector \
      --version 0.175.1 --namespace observability \
      -f k8s_common.yaml -f k8s_deployment.yaml --wait
    ```

    collector 상태를 확인하세요:

    ```bash
    kubectl get pods -n observability
    kubectl logs -n observability -l app.kubernetes.io/instance=observability-nodes --tail=50
    kubectl logs -n observability -l app.kubernetes.io/instance=observability-cluster --tail=50
    ```

    노드에 스케줄링 테인트(taint)가 설정되어 있다면, 모니터링하려는 노드에 맞게 `k8s_daemonset.yaml`에 적절한 `tolerations`를 추가하십시오.
  </Step>

  <Step title="데이터 확인" id="verify-data">
    수집 주기가 몇 차례 지날 때까지 기다린 후 ClickHouse Observability를 여십시오.

    * **검색**에서 **Logs** 소스와 **Last 15 minutes**를 선택하십시오. 컨테이너 로그를 펼쳐 `k8s.namespace.name`, `k8s.pod.name`, `k8s.node.name` 등의 속성을 확인하십시오.
    * **차트 탐색기**에서 **Metrics** 소스를 선택하고 `k8s.` 또는 `system.`으로 시작하는 메트릭을 찾으십시오.
    * **Logs** 소스에서 Kubernetes 이벤트가 발생할 때마다 기록되는지 확인하십시오. 이벤트 양은 클러스터 활동량에 따라 달라집니다.
  </Step>
</Steps>

## 애플리케이션 메타데이터 {#application-metadata}

계측된 애플리케이션에는 Kubernetes downward API를 사용하여 파드 메타데이터를 추가하십시오. 아래 `env` 목록을 애플리케이션 컨테이너의 기존 구성에 병합하되, 기존 리소스 속성은 그대로 유지하십시오:

```yaml
env:
  - name: OTEL_SERVICE_NAME
    value: my-app
  - name: POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
  - name: POD_UID
    valueFrom:
      fieldRef:
        fieldPath: metadata.uid
  - name: POD_NAMESPACE
    valueFrom:
      fieldRef:
        fieldPath: metadata.namespace
  - name: NODE_NAME
    valueFrom:
      fieldRef:
        fieldPath: spec.nodeName
  - name: OTEL_RESOURCE_ATTRIBUTES
    value: k8s.pod.name=$(POD_NAME),k8s.pod.uid=$(POD_UID),k8s.namespace.name=$(POD_NAMESPACE),k8s.node.name=$(NODE_NAME)
```

Kubernetes 메타데이터 프로세서는 수집된 컨테이너 로그를 워크로드 메타데이터로 보강합니다. 이 애플리케이션 변수들은 애플리케이션의 OpenTelemetry SDK가 내보내는 텔레메트리에 파드 식별 정보를 연결합니다.

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collectors-not-starting}

`kubectl describe pod -n observability POD_NAME` 명령으로 파드 이벤트를 확인하십시오. 이미지 가져오기, 스케줄링 제약 조건, 파드 보안 제한 사항을 점검하고 ConfigMap과 Secret이 릴리스와 같은 네임스페이스에 있는지 확인하십시오.

### 로그 또는 메트릭이 표시되지 않음 {#no-data}

collector 로그에 인증 오류나 내보내기 오류가 있는지 확인하십시오. 클러스터에서 대상 엔드포인트에 연결할 수 있는지도 확인하십시오. 큐블릿 오류가 발생하면 포트 `10250` 연결 상태, 인증서 설정, 생성된 RBAC 권한을 확인하십시오. 컨테이너 로그를 수집하려면 노드의 `/var/log/pods` 디렉터리에 액세스할 수 있어야 합니다. 제한된 노드 환경이나 서버리스 노드 환경에서는 이러한 호스트 마운트를 지원하지 않을 수 있습니다.

### 연결 설정이 변경된 경우 {#connection-settings-changed}

ConfigMap 또는 Secret을 업데이트한 후에는 collector를 재시작하여 환경 변수를 다시 로드하세요.

```bash
kubectl rollout restart daemonset -n observability -l app.kubernetes.io/instance=observability-nodes
kubectl rollout restart deployment -n observability -l app.kubernetes.io/instance=observability-cluster
```
