OpenTelemetry collector로 AWS CloudWatch 로그를 수집하여 ClickHouse Observability로 전송합니다. AWS 액세스를 구성하지 않고 통합을 체험해 보려면 [데모 데이터셋](#demo-dataset)을 사용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* collector 예시를 실행하기 위한 Docker 및 Docker Compose, 또는 기존에 배포된 OpenTelemetry Collector Contrib
* 자체 로그를 사용하는 경우: CloudWatch 로그 그룹이 있는 AWS 계정, AWS CLI v2, 아래 권한이 부여된 자격 증명
* 데모를 사용하는 경우: 샘플 데이터를 다운로드할 `curl`

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동합니다. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나 **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    플레이스홀더를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트에는 `/v1/logs` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형" id="self-managed">
    연결할 수 있는 collector의 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 같은 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 CloudWatch 로그 그룹과의 통합 {#existing-cloudwatch}

<Steps>
  <Step title="AWS 자격 증명 구성" id="configure-aws">
    AWS SSO를 사용하는 경우 로그인한 후, collector를 시작할 터미널에서 임시 자격 증명을 export하십시오:

    ```bash
    aws sso login --profile YOUR_PROFILE_NAME
    eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
    export AWS_REGION='us-east-1'
    aws sts get-caller-identity
    ```

    프로필 이름과 리전을 실제 사용하는 값으로 바꾸십시오. 이미 환경 변수 자격 증명을 사용하고 있다면 `AWS_ACCESS_KEY_ID`와 `AWS_SECRET_ACCESS_KEY`를 설정하고(임시 자격 증명을 사용하는 경우 `AWS_SESSION_TOKEN`도 설정), `AWS_REGION`도 함께 지정하십시오. 이 자격 증명은 AWS 로그를 읽을 권한을 부여하는 데 사용되며, 대상의 OTLP 자격 증명과는 별개입니다.

    IAM 자격 증명에는 다음 권한이 필요합니다. `YOUR_REGION`과 `YOUR_ACCOUNT_ID`를 실제 값으로 바꾸고, 필요한 경우 로그 그룹 리소스의 범위를 수집하려는 그룹으로 한정하십시오.

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:YOUR_REGION:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    구성에 사용할 로그 그룹 이름을 정하려면 먼저 사용 가능한 로그 그룹 목록을 조회하세요:

    ```bash
    aws logs describe-log-groups --region "$AWS_REGION" \
      --query 'logGroups[].logGroupName' --output table
    ```
  </Step>

  <Step title="CloudWatch 수신기 구성" id="configure-receiver">
    이 파일을 `cloudwatch-logs.yaml`로 저장하십시오. `/aws/lambda/my-function`을 사용 중인 계정의 로그 그룹으로 바꾸고, 필요하면 `named` 아래에 다른 로그 그룹을 추가하십시오.

    ```yaml
    receivers:
      awscloudwatch:
        region: ${env:AWS_REGION}
        logs:
          initial_lookback: 1h
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws/lambda/my-function:

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/cloudwatch:
        attributes:
          - key: service.name
            value: cloudwatch
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch:
          receivers: [awscloudwatch]
          processors: [memory_limiter, resource/cloudwatch, batch]
          exporters: [otlp_http/observability]
    ```

    이 구성은 최근 1시간 동안의 로그부터 수집을 시작한 다음 1분마다 폴링합니다. 초기 수집 기간을 조정하려면 `initial_lookback` 값을 변경하십시오. 체크포인트를 영구 저장하지 않으면 collector를 재시작할 때 해당 기간을 다시 읽어 중복 데이터가 생성될 수 있습니다.

    접두사를 기준으로 로그 그룹을 발견하려면 `groups` 블록을 다음과 같이 대체하십시오:

    ```yaml
    groups:
      autodiscover:
        limit: 100
        prefix: /aws/lambda/
    ```

    `named`와 `autodiscover` 중 하나만 사용하십시오. 체크포인트 영구 저장을 비롯한 추가 옵션은 [CloudWatch 수신기 문서](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/awscloudwatchreceiver)를 참조하십시오.
  </Step>

  <Step title="collector 시작" id="start-collector">
    다음 내용을 `cloudwatch-logs.yaml`과 같은 디렉터리에 `docker-compose.yaml`로 저장하세요:

    ```yaml
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:0.161.0
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - ./cloudwatch-logs.yaml:/etc/otel-config.yaml:ro
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        mem_limit: 512m
        restart: unless-stopped
        extra_hosts:
          - "host.docker.internal:host-gateway"
    ```

    AWS 자격 증명과 [연결 변수](#connection-details)를 설정한 터미널에서 collector를 시작한 후 출력을 확인하십시오:

    ```bash
    docker compose up -d
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="로그 확인" id="verify-logs">
    ClickHouse Observability에서 **검색**을 열고 **Logs** 소스를 선택한 다음 `ServiceName:cloudwatch`로 필터링하십시오. **Last 2 hours**를 선택하고 로그가 표시될 때까지 폴링 주기 1~2회 정도 기다리십시오.

    다음 리소스 속성을 확인하십시오.

    * `aws.region`: AWS 리전
    * `cloudwatch.log.group.name`: 로그 그룹
    * `cloudwatch.log.stream`: 로그 스트림

    로그 메시지는 `Body`에 표시됩니다. 수신기는 메시지를 그대로 보존하지만, 메시지 텍스트에서 심각도를 추론하지는 않습니다. 심각도 기반 대시보드 패널을 사용하려면 로그 파이프라인에서 `SeverityText` 값을 채워야 합니다.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 샘플에는 Lambda, ECS 및 백그라운드 작업 활동을 24시간 동안 기록한 12,785개의 로그가 포함되어 있으며, 로그 그룹, 스트림, 심각도 값도 함께 들어 있습니다. 이 방법을 사용하면 AWS 자격 증명이나 데이터베이스에 직접 액세스할 필요가 없습니다.

<Steps>
  <Step title="샘플 다운로드" id="download-sample">
    ```bash
    mkdir -p cloudwatch-demo
    cd cloudwatch-demo
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/aws/cloudwatch/cloudwatch-logs.jsonl
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다음 내용을 다운로드 디렉터리에 `cloudwatch-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      filelog/cloudwatch:
        include: [/var/log/cloudwatch/cloudwatch-logs.jsonl]
        start_at: beginning
        operators:
          - type: json_parser
            timestamp:
              parse_from: attributes.Timestamp
              layout_type: gotime
              layout: '2006-01-02 15:04:05.000000000'
              location: UTC
          - type: move
            from: attributes.ResourceAttributes["aws.region"]
            to: resource["aws.region"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.group.name"]
            to: resource["cloudwatch.log.group.name"]
          - type: move
            from: attributes.ResourceAttributes["cloudwatch.log.stream"]
            to: resource["cloudwatch.log.stream"]

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/cloudwatch_demo:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(body, attributes["Body"])
              - set(severity_text, attributes["SeverityText"])
              - set(severity_number, Int(attributes["SeverityNumber"]))
              - set(attributes, attributes["LogAttributes"])
      resource/demo:
        attributes:
          - key: service.name
            value: cloudwatch-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(time, Now() - Duration("2m") - (Time("2025-12-07T23:59:48Z", "%Y-%m-%dT%H:%M:%SZ") - time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        logs/cloudwatch-demo:
          receivers: [filelog/cloudwatch]
          processors: [memory_limiter, transform/cloudwatch_demo, resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      데모 구성은 샘플의 ClickHouse 행 형식을 읽어 로그 body, 심각도, 속성을 복원합니다. 타임스탬프 변환은 샘플 데이터를 수집 시점 2분 전에 끝나는 대략 최근 24시간 범위로 옮깁니다. 실제 로그에는 원래 타임스탬프가 유지되도록 위의 CloudWatch 수신기 구성을 사용하십시오.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    [연결 변수](#connection-details)를 설정한 다음, 다운로드 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    docker run --rm --name cloudwatch-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/cloudwatch-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd):/var/log/cloudwatch:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector가 파일을 읽어 내보내는 동안 터미널을 열어 두고, 출력에 오류가 없는지 확인하십시오. 새 컨테이너를 다시 실행하면 샘플 로그가 중복으로 수집될 수 있습니다.
  </Step>

  <Step title="데모 로그 확인" id="verify-demo-logs">
    **Search**를 열고 **Logs** 소스를 선택한 다음, `ServiceName:cloudwatch-demo`로 필터링하고 **최근 2일**을 선택하십시오. 로그를 펼쳐 body, 심각도, 로그 그룹, 스트림을 확인하십시오. 데이터 확인이 끝나면 **Ctrl+C**를 눌러 데모 collector를 중지하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability의 CloudWatch 데모 로그](/images/clickstack/observability-cloudwatch-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### 로그가 표시되지 않는 경우 {#no-logs}

* `docker compose logs otel-collector`에서 AWS 인증 오류, 액세스 거부 오류 또는 OTLP 내보내기 오류가 있는지 확인하십시오.
* `AWS_REGION`과 로그 그룹 이름이 계정과 일치하는지, 그리고 해당 그룹에 `initial_lookback` 범위 내의 이벤트나 시작 이후 새로 발생한 이벤트가 있는지 확인하십시오.
* `logs:DescribeLogGroups` 및 `logs:FilterLogEvents`에 대한 IAM 권한이 있는지 확인하십시오.
* [연결 정보](#connection-details)를 참고하여 대상 엔드포인트와 인증 설정이 올바른지 확인하십시오.
* **Logs** 소스, 서비스 이름 필터, 시간 범위를 확인하십시오. 데모 데이터를 보려면 **최근 2일**을 선택하십시오.

### AWS 자격 증명 만료 {#expired-credentials}

SSO를 사용하는 경우 다시 로그인하여 새 자격 증명을 export한 다음, collector가 새 환경 변수를 받을 수 있도록 collector를 재생성하십시오:

```bash
aws sso login --profile YOUR_PROFILE_NAME
eval "$(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)"
docker compose up -d --force-recreate otel-collector
```

기존 컨테이너를 재시작하는 것만으로는 자격 증명이 갱신되지 않습니다. 그 밖의 임시 자격 증명을 사용하는 경우에는 컨테이너를 다시 생성하기 전에 액세스 키, 시크릿 키, 세션 토큰을 새로 발급받으십시오.

### 이전 로그가 누락됨 {#older-logs}

이 예시에서는 1시간 전부터 로그를 수집합니다. `logs.initial_lookback` 값을 늘리거나, 특정 시작 시간부터 수집하려면 RFC3339 타임스탬프를 사용하여 `logs.start_from`으로 대체하십시오. 두 설정을 동시에 지정하지 마십시오. 구성을 변경한 후에는 collector를 재시작하십시오. 동일한 시간 윈도우(time window)를 다시 읽으면 중복 데이터가 발생할 수 있습니다.
