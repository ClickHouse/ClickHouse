OpenTelemetry collector로 Nginx의 JSON 액세스 로그를 수집하여 ClickHouse Observability로 전송합니다. Nginx가 설치되어 있지 않더라도 [데모 데이터셋](#demo-dataset)을 사용하여 이 통합을 체험해 볼 수 있습니다.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* 아래 collector 명령어를 실행할 Docker 또는 기존 OpenTelemetry Collector Contrib 배포
* 자체 로그를 사용하는 경우: 기존에 설치된 Nginx, Nginx 구성을 편집할 수 있는 권한(permission), collector에서 Nginx 로그 파일에 대한 액세스

Nginx를 설정하거나 자체 로그를 수집하지 않고 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 사용하십시오. 데모 데이터셋에는 샘플 데이터용 독립형 수집기 설정이 포함되어 있습니다.

### 연결 정보 {#demo-connection-details}

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/logs` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. Docker Desktop 호스트에서 collector를 실행하는 경우 `localhost` 대신 `host.docker.internal`을 사용하십시오. Linux에서는 공유 Docker 네트워크와 대상 컨테이너 이름을 사용하거나, 연결 가능한 다른 호스트 주소를 사용하십시오.

## 기존 Nginx와 통합 {#existing-nginx}

Nginx 액세스 로그를 읽을 수 있는 호스트에서 collector를 실행하십시오. collector는 로그를 파싱하여 서비스의 OTLP HTTP 엔드포인트로 전달합니다.

<Steps>
  <Step title="Nginx 로그 형식 구성" id="configure-nginx">
    `nginx.conf`에서 Nginx가 JSON 형식의 액세스 로그를 기록하도록 구성하십시오.

    `nginx.conf` 파일은 일반적으로 다음 위치에 있습니다.

    * **Linux (apt/yum)**: `/etc/nginx/nginx.conf`
    * **macOS (Homebrew)**: `/usr/local/etc/nginx/nginx.conf` 또는 `/opt/homebrew/etc/nginx/nginx.conf`
    * **Docker**: 구성 파일은 일반적으로 볼륨으로 마운트됩니다

    기존 `http` 블록 안에 다음 지시문을 추가하십시오. 나머지 구성은 그대로 두고, 같은 파일을 대상으로 하는 기존 `access_log` 지시문이 있다면 이를 대체하십시오.

    ```nginx
    log_format json_combined escape=json
    '{'
      '"time_local":"$time_local",'
      '"remote_addr":"$remote_addr",'
      '"remote_user":"$remote_user",'
      '"request":"$request",'
      '"status":$status,'
      '"body_bytes_sent":$body_bytes_sent,'
      '"request_time":$request_time,'
      '"upstream_response_time":"$upstream_response_time",'
      '"http_referer":"$http_referer",'
      '"http_user_agent":"$http_user_agent",'
      '"http_x_forwarded_for":"$http_x_forwarded_for",'
      '"http_host":"$http_host"'
    '}';

    access_log /var/log/nginx/access.log json_combined;
    ```

    이 포맷은 데모 데이터셋과 동일한 필드 이름을 사용하며, 여기에는 메서드, URI, HTTP 버전이 담긴 `request` 필드도 포함됩니다. [Nginx는 여러 개의 업스트림 응답 시간을 보고할 수 있으므로](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#var_upstream_response_time) `upstream_response_time`은 문자열로 유지합니다. 데모 데이터셋에서는 이 필드에 단일 숫자 값이 들어 있습니다.

    `nginx -t`로 구성을 검사한 다음, 배포 환경의 일반적인 절차에 따라 Nginx를 다시 로드하십시오. `server` 또는 `location` 블록에서 `access_log`를 재정의하는 경우, 해당 지시문도 `json_combined`를 사용하도록 수정하십시오.
  </Step>

  <Step title="collector 구성" id="custom-otel">
    [연결 정보](#demo-connection-details)를 확인한 다음, collector를 실행할 터미널에서 엔드포인트 및 API 키 환경 변수를 설정하세요. 아래의 전체 구성을 `nginx-monitoring.yaml` 파일로 저장하세요.

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx/access.log
        start_at: end
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx
          - type: add
            field: resource["service.name"]
            value: nginx

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx:
          receivers: [filelog/nginx]
          processors: [memory_limiter, batch]
          exporters: [otlp_http/observability]
    ```

    이 구성은 새로 추가되는 JSON 액세스 로그 항목을 읽어 원래 타임스탬프를 유지하고, `service.name`을 `nginx`로 설정합니다. 또한 위의 인증 설정을 사용하여 로그를 OTLP HTTP 엔드포인트로 전달합니다. Nginx 오류 로그는 별도의 파서가 필요하므로 여기에 포함되지 않습니다.
  </Step>

  <Step title="collector를 실행하십시오" id="load-custom">
    다음 명령은 Docker 호스트의 로그 디렉터리가 `/var/log/nginx`라고 가정합니다. 파일이 다른 위치에 있다면 로그 마운트의 호스트 측 경로를 수정하십시오. Nginx를 컨테이너로 실행 중이라면 대신 Nginx의 공유 로그 볼륨을 collector에 마운트하십시오.

    `nginx-monitoring.yaml`이 있는 디렉터리에서 다음 명령을 실행하십시오:

    ```bash
    docker run --rm --name nginx-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/nginx:/var/log/nginx:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    collector는 포그라운드에서 실행되며, 마운트된 로그 파일을 읽을 수 있는 권한(permission)이 있어야 합니다. collector를 실행 상태로 유지한 채 다른 터미널이나 브라우저에서 Nginx로 요청을 몇 번 보내 새로운 액세스 로그 항목이 기록되도록 하십시오.
  </Step>

  <Step title="ClickHouse Observability에서 로그 확인" id="verifying-logs">
    1. UI에서 **검색**을 열고 **Logs**를 선택하십시오.
    2. `ServiceName:nginx`로 필터링하고 요청이 발생한 기간을 포함하는 시간 범위를 선택하십시오.
    3. 엔트리를 펼친 후 **Column Values**를 선택하여 `LogAttributes` 아래의 `request`, `request_time`, `upstream_response_time` 등의 필드를 확인하십시오.

    다음 예시는 데모 데이터셋에서 `ServiceName:nginx-demo`로 필터링한 동일한 뷰(view)입니다.

    <div className="ch-image-lg">
      <Frame>
        ![서비스 이름으로 필터링된 Nginx 데모 로그와 파싱된 로그 속성이 표시된 펼쳐진 엔트리](/images/clickstack/observability-nginx-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

샘플 데이터셋에는 성공한 요청, 오류, 업스트림 응답 시간이 담긴 JSON 액세스 로그 엔트리 14,743개가 포함되어 있습니다. Docker와 ClickHouse Observability 서비스가 필요합니다. 시작하기 전에 [연결 환경 변수](#demo-connection-details)를 설정하고, 다운로드한 파일과 구성 파일을 같은 디렉터리에 두십시오.

<Steps>
  <Step title="테스트용 수집기 설정 생성" id="test-config">
    다음 전체 구성을 `nginx-demo.yaml`로 저장하십시오. collector가 다운로드한 액세스 로그를 읽어 OTLP 엔드포인트로 전달합니다.

    ```yaml
    receivers:
      filelog/nginx:
        include:
          - /var/log/nginx-demo/access.log
        start_at: beginning
        operators:
          - type: json_parser
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.time_local
            layout: '%d/%b/%Y:%H:%M:%S %z'
          - type: add
            field: attributes.source
            value: nginx-demo
          - type: add
            field: resource["service.name"]
            value: nginx-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-21T16:34:27Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/nginx-demo:
          receivers: [filelog/nginx]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      데모 전용 `transform/demo_timestamps` 프로세서는 샘플의 트래픽 패턴은 그대로 유지한 채, 타임스탬프를 수집 시점 2분 전에 끝나는 약 24시간 범위로 이동합니다. 원본 `time_local` 속성과 로그 body는 변경되지 않습니다. 자체 Nginx 로그를 사용할 때는 원래 타임스탬프가 유지되도록 이 프로세서를 제외하십시오.
    </Note>

    독립형 collector 예제에는 이 구성을 검증할 때 사용한 버전인 OpenTelemetry Collector Contrib `0.161.0`을 사용합니다.
  </Step>

  <Step title="데모 collector 실행" id="run-demo">
    `access.log`와 `nginx-demo.yaml`이 있는 디렉터리에서 OpenTelemetry Collector Contrib image를 실행하십시오.

    ```bash
    docker run --rm --name nginx-demo-collector \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/access.log:/var/log/nginx-demo/access.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    수집을 확인하는 동안 이 터미널을 열어 두십시오. 마운트한 두 파일 모두 컨테이너에서 읽을 수 있어야 합니다. 로그가 표시되면 **Ctrl+C**를 눌러 데모 collector를 중지하십시오. 이 데모는 파일 오프셋을 저장하지 않으므로, 다시 실행하면 타임스탬프가 새로 이동된 상태로 데이터셋이 다시 수집됩니다.
  </Step>

  <Step title="ClickHouse Observability에서 로그 확인" id="verify-demo-logs">
    collector가 실행되면 다음을 수행하십시오.

    1. UI를 엽니다.
    2. **Search**로 이동하여 **Logs**를 선택하고 `ServiceName:nginx-demo`로 필터링합니다.
    3. 이동된 데이터셋 전체가 포함되도록 시간 범위를 **Last 2 days**로 설정합니다.

    로그 엔트리를 펼치고 **Column Values**를 선택하면 `LogAttributes` 아래의 파싱된 필드를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![서비스 이름으로 필터링된 Nginx 데모 로그와 파싱된 로그 속성을 보여 주는 펼쳐진 엔트리](/images/clickstack/observability-nginx-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#troubleshooting-not-loading}

collector의 터미널 출력에 구성 오류가 있는지 확인하십시오. 마운트된 경로에 YAML 파일이 있는지도 확인하십시오. OTLP 익스포터 구성을 사용한다면 Docker를 실행하는 터미널에 엔드포인트 변수와 필요한 인증 변수가 설정되어 있는지 확인하십시오.

### 로그가 표시되지 않는 경우 {#no-logs}

* collector 출력에 인증 오류나 내보내기 오류가 있는지 확인하십시오. OTLP 익스포터를 사용한다면 [연결 정보](#demo-connection-details)와 대조하여 엔드포인트와 인증 헤더가 올바른지 확인하십시오.
* Nginx가 JSON 액세스 로그를 기록하고 있는지, collector가 해당 로그를 읽을 수 있는지 확인하십시오. `start_at: end`를 사용하는 경우 collector가 시작된 후에 새 요청을 발생시키십시오.
* 선택한 **Logs** 소스와 서비스 이름 필터를 확인하십시오. 데모 데이터셋은 `ServiceName:nginx-demo`, 자체 로그는 `ServiceName:nginx`입니다.
* 로그가 포함되도록 시간 범위를 설정하십시오. 데모를 사용하는 경우 `transform/demo_timestamps`가 파이프라인에 포함되어 있는지 확인하고 **Last 2 days**를 선택하십시오.

자체 Nginx 로그를 사용하는 경우 호스트의 파일을 확인하고 collector 컨테이너의 마운트를 점검하십시오. 대상 경로가 수신기 구성과 일치하는지 확인하십시오. `CONTAINER_NAME`을 collector 컨테이너 이름으로 바꾸고, 필요한 경우 호스트 경로를 조정하십시오:

```bash
tail -f /var/log/nginx/access.log
docker inspect --format '{{json .Mounts}}' CONTAINER_NAME
```
