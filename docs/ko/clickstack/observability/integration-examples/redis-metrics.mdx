OpenTelemetry Redis 수신기로 Redis 메트릭을 수집하여 ClickHouse Observability로 전송합니다. Redis를 설치하지 않고 이 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* collector 예시를 실행할 Docker 또는 기존 OpenTelemetry Collector Contrib 배포
* 자체 메트릭을 수집하려면 collector에서 연결할 수 있는 Redis 인스턴스, 그리고 Redis에 인증이 필요한 경우 자격 증명
* 데모를 실행하려면 샘플 데이터를 다운로드하고 전송할 `curl`

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동합니다. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**를 사용하면 구성을 복사할 수 있고, **Reveal key**를 사용하면 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/metrics` 접미사를 붙이지 않은 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에서 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 Redis와 통합 {#existing-redis}

<Steps>
  <Step title="Redis 연결 확인" id="verify-redis">
    Redis CLI에 액세스할 수 있는 호스트에서 Redis 인스턴스를 확인하십시오:

    ```bash
    redis-cli -h YOUR_REDIS_HOST -p 6379 ping
    redis-cli -h YOUR_REDIS_HOST -p 6379 INFO server
    ```

    첫 번째 명령은 `PONG`을, 두 번째 명령은 서버 정보를 반환해야 합니다. Redis에 비밀번호가 필요하면 이 명령어를 실행하기 전에 터미널에서 `REDISCLI_AUTH`를 설정하십시오. Redis ACL 사용자는 `--user YOUR_REDIS_USER`도 함께 지정하십시오.
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `redis-metrics.yaml`로 저장하십시오:

    ```yaml
    receivers:
      redis:
        endpoint: ${env:REDIS_ENDPOINT}
        collection_interval: 10s
        # Redis에 인증이 필요한 경우 주석을 해제하십시오:
        # username: ${env:REDIS_USERNAME}
        # password: ${env:REDIS_PASSWORD}

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      resource/redis:
        attributes:
          - key: service.name
            value: redis-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/redis:
          receivers: [redis]
          processors: [memory_limiter, resource/redis, batch]
          exporters: [otlp_http/observability]
    ```

    수신기는 메모리 사용량(memory usage), 클라이언트, 처리된 명령어 수, 키스페이스 적중 및 미스, 만료되거나 축출된 키 등의 Redis 메트릭을 10초마다 수집합니다. 리소스 프로세서는 필터링에 활용할 수 있도록 `service.name`을 `redis-service`로 설정합니다.

    Redis에 인증이 필요하면 해당 수신기 필드의 주석을 해제하고 `REDIS_USERNAME`, `REDIS_PASSWORD` 중 필요한 값을 설정하십시오. 이 자격 증명은 Redis 연결에 사용되며, OTLP authorization 값은 대상 collector 인증에 사용됩니다. TLS가 활성화된 Redis는 [Redis 수신기 문서](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver)를 참고하여 수신기의 `tls` 설정을 구성하십시오.
  </Step>

  <Step title="collector 실행" id="run-collector">
    [연결 변수](#connection-details)와 함께, collector 컨테이너에서 접근할 수 있는 Redis 주소를 설정하십시오. Redis가 이 컴퓨터에서 실행 중이라면 다음과 같이 설정합니다:

    ```bash
    export REDIS_ENDPOINT='host.docker.internal:6379'
    ```

    원격 Redis라면 해당 호스트 이름과 포트를 사용하십시오. Redis가 다른 컨테이너에서 실행 중이라면 해당 컨테이너 이름을 사용하고 아래 명령에 `--network YOUR_NETWORK`를 추가하십시오.

    `redis-metrics.yaml`이 있는 디렉터리에서 다음 명령을 실행하십시오:

    ```bash
    docker run --rm --name redis-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e REDIS_ENDPOINT \
      -e REDIS_USERNAME \
      -e REDIS_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    메트릭을 수집하는 동안 이 터미널을 열어 두십시오. UI를 확인하기 전에 수집 인터벌이 최소 두 번 지날 때까지 기다리십시오.
  </Step>

  <Step title="메트릭 확인" id="verify-metrics">
    [대시보드](#dashboards)를 가져와 차트를 **Metrics** 소스에 매핑한 다음 `ServiceName:redis-service`로 필터링하십시오. **Last 15 minutes**를 선택하고 대시보드를 실행하십시오. Redis 인스턴스가 정상이면 축출 및 거부된 연결 수는 0으로 유지될 수 있습니다.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

24시간 동안 5분 간격으로 표본 추출한 6,912개의 게이지 및 sum 데이터 포인트로 통합을 체험해 보십시오. 이 표본에는 원본 데이터세트의 캐시 워밍, 트래픽 급증, 메모리 압력 패턴이 그대로 유지되어 있습니다. Docker, `curl`, 그리고 대상 collector의 OTLP HTTP 연결 정보가 필요합니다.

시작하기 전에 [연결 변수](#connection-details)를 설정하십시오.

<Steps>
  <Step title="샘플 메트릭 다운로드" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-metrics-demo-5m.json
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다음 내용을 `redis-metrics-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: redis-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-10-21T04:59:30Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      데모 전용 transform은 메트릭 값과 각 포인트의 시작 타임스탬프와 종료 타임스탬프 사이의 인터벌을 유지한 채 타임스탬프만 갱신합니다. 실제 Redis 메트릭을 수집할 때는 이 transform을 제외하십시오. 배치 제한은 대상 collector가 처리할 수 있도록 업로드 크기를 작게 유지하는 역할을 합니다.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    구성 파일이 있는 디렉터리에서 collector를 실행하고, 이 터미널은 열어 두십시오.

    ```bash
    docker run --rm --name redis-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="샘플 전송" id="load-metrics">
    다른 터미널을 열고 다운로드 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @redis-metrics-demo-5m.json
    ```

    `{}` 또는 `{"partialSuccess":{}}`와 같은 응답이 반환되면 로컬 collector가 요청을 수락한 것입니다. collector 터미널에서 내보내기 오류가 없는지 확인하고, 데이터가 전달될 때까지 몇 초간 기다리십시오. 데이터를 확인한 후에는 **Ctrl+C**로 collector를 중지하십시오. 샘플을 다시 전송하면 포인트가 중복될 수 있습니다.
  </Step>

  <Step title="메트릭 확인" id="verify-demo-metrics">
    [다음 섹션](#dashboards)의 대시보드를 가져온 후 `ServiceName:redis-demo`로 필터링하고 **최근 2일**을 선택하십시오. 샘플에는 게이지 메트릭과 sum 메트릭이 모두 포함되어 있으며, 데이터베이스에 직접 접근할 필요는 없습니다.
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collector-fails-to-start}

collector 터미널에 구성 오류가 표시되는지 확인하십시오. YAML 파일이 문서에 안내된 경로에 마운트되어 있는지, 그리고 Docker를 실행하는 터미널에 엔드포인트와 필수 인증 변수가 설정되어 있는지 확인하십시오.

### 메트릭이 표시되지 않는 경우 {#no-metrics}

* collector 출력에 Redis 연결 오류나 OTLP 내보내기 오류가 있는지 확인하십시오.
* collector 컨테이너에서 Redis에 연결할 수 있는지 확인하십시오. 컨테이너 환경에서는 두 컨테이너가 의도한 Docker 네트워크를 공유하는지 확인하십시오.
* Redis 자격 증명이 올바른지, 그리고 해당 사용자가 [Redis 수신기](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/redisreceiver)에 필요한 명령어를 실행할 수 있는지 확인하십시오.
* **Metrics** 소스, 서비스 이름 필터, 시간 범위를 확인하십시오. 데모 데이터를 사용하는 경우 **최근 2일**을 선택하고, 타임스탬프 변환이 파이프라인에 포함되어 있는지 확인하십시오.
* 관리형 서비스에서는 OTLP HTTP 엔드포인트와 Bearer API Key가 **Managed Telemetry**에 표시된 값과 일치하는지 확인하십시오. 자가 관리형 collector에서는 해당 collector의 인증 설정을 사용하십시오.

## 다음 단계 {#next-steps}

* 메모리 사용량(memory usage), 연결 제한 또는 캐시 적중률에 대한 [알림](/ko/clickstack/observability/features/alerts)을 설정하십시오.
* [대시보드](/ko/clickstack/observability/features/dashboards/overview)를 추가로 생성하십시오.
* 수집기 설정에 대한 자세한 지침은 [OpenTelemetry 데이터 전송](/ko/clickstack/observability/ingesting-data/opentelemetry)을 참조하십시오.
