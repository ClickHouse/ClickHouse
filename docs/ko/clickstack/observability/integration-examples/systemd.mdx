OpenTelemetry journald 수신기로 systemd 저널 로그를 수집하여 ClickHouse Observability로 전송합니다. Linux 호스트 없이 이 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* 직접 수집한 로그를 사용하려면: systemd를 실행하는 Linux 호스트(`journalctl`이 설치되어 있고 해당 저널을 읽을 수 있는 권한(permission)이 있어야 함)
* `curl`, 그리고 데모용 Docker

### 연결 정보 {#connection-details}

  <Tab title="완전 관리형">

    ClickHouse Observability를 열고 **팀 설정 → 데이터 → Managed Telemetry**로 이동하십시오. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**를 사용하면 구성을 복사할 수 있고, **Reveal key**를 사용하면 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/logs` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 신호 경로는 익스포터가 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    연결할 수 있는 collector의 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 모니터링 대상 호스트 또는 데모 collector에서 연결할 수 있어야 합니다. 대상 collector가 Docker 호스트에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오.

## 기존 시스템과의 통합 {#existing-systems}

<Steps>
  <Step title="저널을 확인하십시오" id="verify-systemd">
    모니터링할 Linux 호스트에서 다음을 수행하세요:

    ```bash
    systemctl --version
    sudo journalctl -n 20
    sudo journalctl --disk-usage
    ```

    수신기는 호스트의 `journalctl`을 사용하여 사용 가능한 저널을 읽습니다. 영구(persistent) 저널 저장소와 휘발성(volatile) 저널 저장소를 모두 지원하므로 저장소 설정을 변경할 필요가 없습니다.
  </Step>

  <Step title="collector 다운로드" id="download-collector">
    모니터링 대상 Linux 호스트에서 다음 명령어를 실행하십시오:

    ```bash
    case "$(uname -m)" in
      x86_64) arch=amd64 ;;
      aarch64|arm64) arch=arm64 ;;
      *) echo "Unsupported architecture"; exit 1 ;;
    esac
    curl -fL -o otelcol-contrib.tar.gz \
      "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_${arch}.tar.gz"
    tar -xzf otelcol-contrib.tar.gz otelcol-contrib
    ```

    collector는 호스트에서 직접 실행되므로 호스트에 설치된 `journalctl`을 사용할 수 있습니다. 표준 Contrib Docker 이미지에는 이 바이너리가 포함되어 있지 않습니다.
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `systemd-monitoring.yaml` 파일로 저장하십시오.

    ```yaml
    receivers:
      journald:
        start_at: end
        priority: info
        convert_message_bytes: true
    processors:
      transform/journald:
        error_mode: ignore
        log_statements:
          - context: log
            statements:
              - merge_maps(log.attributes, log.body, "upsert")
              - set(resource.attributes["host.name"], log.attributes["_HOSTNAME"])
              - set(resource.attributes["service.name"], "systemd-logs")
              - set(log.attributes["unit"], log.attributes["SYSLOG_IDENTIFIER"])
              - set(log.attributes["unit"], log.attributes["_SYSTEMD_UNIT"]) where log.attributes["_SYSTEMD_UNIT"] != nil
              - set(log.attributes["priority"], log.attributes["PRIORITY"])
              - set(log.body, log.attributes["MESSAGE"])
              - set(log.severity_text, "info")
              - set(log.severity_number, SEVERITY_NUMBER_INFO)
              - set(log.severity_text, "warn") where Int(log.attributes["PRIORITY"]) == 4
              - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
              - set(log.severity_text, "error") where Int(log.attributes["PRIORITY"]) == 3
              - set(log.severity_number, SEVERITY_NUMBER_ERROR) where log.severity_text == "error"
              - set(log.severity_text, "fatal") where Int(log.attributes["PRIORITY"]) < 3
              - set(log.severity_number, SEVERITY_NUMBER_FATAL) where log.severity_text == "fatal"
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs:
          receivers: [journald]
          processors: [transform/journald, batch]
          exporters: [otlp_http/observability]
    ```

    저널 필드는 로그 속성으로 유지되고, 메시지는 로그 본문이 되며, 호스트명은 리소스 속성이 됩니다. 수신기는 우선순위가 `info` 이상인 모든 유닛을 수집합니다. 수집 대상을 제한하려면 `journald` 아래에 `units` 목록을 추가하고, `ssh.service`나 `nginx.service`처럼 호스트에 실제로 존재하는 유닛 이름을 지정하십시오.
  </Step>

  <Step title="collector 실행" id="run-collector">
    [연결 변수](#connection-details)를 설정한 다음, 다운로드 디렉터리에서 실행하십시오. 이 명령은 관리자 권한으로 시스템 저널을 읽으며, 두 연결 변수만 유지합니다:

    ```bash
    sudo --preserve-env=OTEL_EXPORTER_OTLP_ENDPOINT,OTEL_EXPORTER_OTLP_AUTHORIZATION \
      ./otelcol-contrib --config=systemd-monitoring.yaml
    ```

    터미널은 열어 둔 채로 두십시오. 다른 터미널에서 저널 엔트리를 생성합니다:

    ```bash
    echo 'ClickHouse Observability journal ingestion test' | systemd-cat -t observability-test -p info
    ```

    테스트를 마치면 **Ctrl+C**를 눌러 collector를 중지하십시오. 지속적으로 수집하려면 collector를 저널 액세스 권한이 있는 systemd 서비스로 실행하고, 재시작 후에도 수집을 재개할 수 있도록 [커서 저장소(cursor storage)](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/journaldreceiver#cursor-tracking)를 구성하십시오.
  </Step>

  <Step title="로그 확인" id="verify-logs">
    **검색**을 열고 **Logs**를 선택한 다음 `ServiceName:systemd-logs`로 필터링하고 **Last 15 minutes**를 선택하십시오. 테스트 메시지와 함께 `unit`, `priority` 등의 속성이 표시되는지 확인하십시오.
  </Step>
</Steps>

## 데모 데이터세트 {#demo-dataset}

이 샘플에는 약 48시간에 걸친 텍스트 로그 엔트리 1,334개가 포함되어 있으며, SSH 활동, 예약된 작업, 서비스 이벤트 등이 담겨 있습니다. `filelog` 수신기를 사용하므로 systemd나 `journalctl`을 설치할 필요가 없습니다. collector는 원본 본문과 이벤트 간 시간 간격은 그대로 유지하면서 타임스탬프를 갱신합니다.

<Steps>
  <Step title="샘플 다운로드" id="download-sample">
    ```bash
    curl -fL -o systemd-demo.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/systemd/systemd-demo.log
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo">
    다음 내용을 `systemd-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      filelog/systemd:
        include:
          - /var/log/demo/systemd-demo.log
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<timestamp>\S+) (?P<hostname>\S+) (?P<unit>\S+?)(?:\[(?P<pid>\d+)\])?: (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout: '%Y-%m-%dT%H:%M:%S%z'
          - type: add
            field: attributes.source
            value: systemd-demo
          - type: add
            field: resource["service.name"]
            value: systemd-demo
    processors:
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(resource.attributes["host.name"], log.attributes["hostname"])
              - set(log.time, Now() - Duration("2m") - (Time("2025-11-16T23:45:00Z", "%Y-%m-%dT%H:%M:%SZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs:
          receivers: [filelog/systemd]
          processors: [transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    텍스트 샘플에는 저널 우선순위 필드가 없으므로, 이 데모에서는 메시지 텍스트로부터 심각도를 지정하지 않습니다.
  </Step>

  <Step title="데모 collector 실행" id="run-demo">
    [연결 변수](#connection-details)를 설정한 다음, 두 파일이 모두 있는 디렉터리에서 다음을 실행하십시오.

    ```bash
    docker run --rm --name systemd-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/systemd-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/systemd-demo.log:/var/log/demo/systemd-demo.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    수집 여부를 확인하는 동안 터미널을 열어 두십시오. 확인이 끝나면 **Ctrl+C**를 눌러 중지하십시오. 데모를 다시 실행하면 타임스탬프가 갱신된 상태로 샘플이 다시 수집됩니다.
  </Step>

  <Step title="데모 로그 확인" id="verify-demo">
    **검색**을 열고 **Logs**를 선택한 다음, `ServiceName:systemd-demo`로 필터링하고 **최근 2일**을 선택하십시오. `unit`, `hostname`, `message` 속성이 포함된 샘플 엔트리가 표시됩니다.

    <div className="ch-image-lg">
      <Frame>
        ![ClickHouse Observability 검색 화면의 Systemd 데모 로그](/images/clickstack/observability-systemd-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### journalctl을 찾을 수 없음 {#journalctl-not-found}

실제 환경의 collector는 `journalctl`이 설치되어 있고 실행 경로(PATH)에서 사용할 수 있는 모니터링 대상 Linux 호스트에서 실행하십시오. 데모는 `filelog`를 사용하므로 `journalctl`이 필요하지 않습니다.

### 로그가 표시되지 않는 경우 {#no-logs}

collector 출력에서 저널 액세스, 인증 또는 내보내기 오류가 있는지 확인하세요. 모니터링 대상 호스트에서 `sudo journalctl -n 20`을 실행하여 항목이 반환되는지 확인하세요. 유닛(unit) 필터를 구성했다면 해당 필터가 서비스 이름과 일치하는지 확인하세요. 수집을 시작한 후에는 새 항목을 생성하세요.

ClickHouse Observability에서 **Logs** 소스, 서비스 이름 필터 및 시간 범위를 확인하세요. 데모에서는 **최근 2일**을 선택하고, 샘플 파일이 구성된 경로에 마운트되어 있는지 확인하세요.
