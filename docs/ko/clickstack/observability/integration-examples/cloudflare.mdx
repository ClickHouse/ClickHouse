## 개요 {#overview-self-configured}

    Cloudflare [Logpush](https://developers.cloudflare.com/logs/about/)는 HTTP 요청 로그를 Amazon S3와 같은 대상으로 내보냅니다. 이러한 로그를 ClickStack으로 전달하면 다음과 같은 작업을 수행할 수 있습니다:

    * 엣지 트래픽, 캐시 성능, 보안 이벤트를 다른 관측성 데이터와 함께 분석합니다
    * ClickHouse SQL로 로그를 쿼리합니다
    * Cloudflare의 기본 보존 기간보다 오래 로그를 보관합니다

    이 가이드에서는 [ClickPipes](/ko/integrations/clickpipes/home)를 사용하여 S3에 저장된 Cloudflare 로그 파일을 ClickHouse로 지속적으로 수집합니다. S3는 Cloudflare와 ClickHouse 사이에서 내구성 있는 버퍼 역할을 하며, 정확히 한 번 처리 의미 체계(exactly-once semantics)와 재적용 기능을 제공합니다.

    <Info>
      **대안: HTTP 직접 수집**

      Cloudflare Logpush는 로그를 [HTTP 엔드포인트](https://developers.cloudflare.com/logs/get-started/enable-destinations/http/)로 직접 푸시하는 기능도 지원합니다. Cloudflare는 로그를 줄바꿈으로 구분된 JSON(NDJSON) 포맷으로 내보내고 ClickHouse는 `JSONEachRow`를 통해 이 포맷을 네이티브로 지원하므로, 다음 엔드포인트 URL 포맷을 사용하여 Logpush가 ClickHouse Cloud HTTP 인터페이스로 직접 전송하도록 설정할 수 있습니다.

      ```text
      https://YOUR_CLICKHOUSE_HOST:8443/?query=INSERT+INTO+cloudflare_http_logs+FORMAT+JSONEachRow&header_Authorization=Basic+BASE64_CREDENTIALS
      ```

      `YOUR_CLICKHOUSE_HOST`는 ClickHouse Cloud 호스트명으로, `BASE64_CREDENTIALS`는 Base64로 인코딩된 자격 증명(`echo -n 'default:YOUR_PASSWORD' | base64`)으로 바꾸십시오.

      이 방식은 S3, SQS, IAM 구성이 필요 없어 설정이 더 간단하지만, Cloudflare Logpush는 전송에 실패하면 [과거 데이터를 백필할 수 없습니다](https://developers.cloudflare.com/logs/logpush/). 따라서 푸시 중에 ClickHouse를 사용할 수 없으면 해당 로그는 영구적으로 손실됩니다.
    </Info>

## 기존 Cloudflare Logpush와 통합 {#existing-cloudflare-self-configured}

    이 섹션에서는 로그를 S3로 내보내도록 Cloudflare Logpush가 구성되어 있다고 가정합니다. 구성되어 있지 않다면 먼저 [Cloudflare의 AWS S3 설정 가이드](https://developers.cloudflare.com/logs/get-started/enable-destinations/aws-s3/)를 따르십시오.

### 사전 요구 사항 {#prerequisites-self-configured}

    * 실행 중인 **ClickHouse Cloud 서비스**(ClickPipes는 Cloud 전용 기능이므로 ClickStack OSS에서는 사용할 수 없습니다)
    * S3 버킷에 로그를 기록하도록 활성화된 Cloudflare Logpush
    * Cloudflare가 로그를 기록하는 S3 버킷의 이름과 리전

    <Steps>
      <Step title="S3 인증 구성" id="configure-auth-self-configured">
        ClickPipes가 S3 버킷에서 데이터를 읽으려면 권한(permission)이 필요합니다. [S3 데이터에 안전하게 액세스하기](/ko/products/cloud/guides/data-sources/accessing-s3-data-securely) 가이드에 따라 IAM 역할 기반 접근 또는 자격 증명 기반 접근을 구성하십시오.

        ClickPipes S3 인증 및 권한에 대한 자세한 내용은 [S3 ClickPipes 참고 문서](/ko/integrations/clickpipes/object-storage/amazon-s3/overview#access-control)를 참조하십시오.
      </Step>

      <Step title="ClickPipes 작업 생성" id="create-clickpipes-self-configured">
        1. ClickHouse Cloud Console → **Data Sources** → **Create ClickPipe**
        2. **Source**: Amazon S3

        <div className="ch-image-lg">
          <Frame>
            ![Clickpipe s3](/images/clickstack/cloudflare/clickpipe-s3.webp)
          </Frame>
        </div>

        **연결(Connection):**

        * **S3 file path**: 파일을 일치시킬 와일드카드를 포함한 Cloudflare 로그 버킷 경로를 입력합니다. Logpush에서 일별 하위 폴더를 활성화한 경우 하위 디렉터리 전체에서 파일을 일치시키려면 `**`를 사용하십시오:
          * 하위 폴더 없음: `https://your-bucket.s3.us-east-1.amazonaws.com/logs/*`
          * 일별 하위 폴더: `https://your-bucket.s3.us-east-1.amazonaws.com/logs/**/*`
        * **Authentication**: 인증 메서드를 선택하고 자격 증명 또는 IAM 역할 ARN을 입력합니다.

        **수집 설정:**

        **Incoming data**를 클릭한 후 다음 항목을 구성합니다:

        * **Continuous ingestion**을 켭니다.
        * **Ordering**: Lexicographical order

        <div className="ch-image-lg">
          <Frame>
            ![지속적인 수집](/images/clickstack/cloudflare/continuous-ingestion.webp)
          </Frame>
        </div>

        Cloudflare Logpush는 날짜 기반 이름(예: `20250127/...`)으로 파일을 기록하므로 파일 이름이 자연스럽게 사전식 순서를 따릅니다. ClickPipes는 30초마다 새 파일을 폴링하며, 마지막으로 처리된 파일보다 사전식 순서상 뒤에 오는 이름의 파일을 모두 수집합니다.

        **스키마 매핑(schema mapping):**

        **Parse information**을 클릭합니다. ClickPipes가 로그 파일을 샘플링하여 스키마를 자동으로 감지합니다. 매핑된 컬럼을 검토하고 필요에 따라 타입을 조정하십시오. 대상 테이블(destination table)의 **Sorting key**를 정의합니다. Cloudflare 로그에는 `(EdgeStartTimestamp, ClientCountry, EdgeResponseStatus)`를 사용하는 것이 좋습니다.

        <div className="ch-image-lg">
          <Frame>
            ![파싱 정보](/images/clickstack/cloudflare/parse-information.webp)
          </Frame>
        </div>

        **Complete Setup**을 클릭합니다.

        <Note>
          ClickPipes는 처음 생성될 때 지속적인 폴링으로 전환하기 전에 지정된 경로의 **모든 기존 파일**에 대해 초기 적재(initial load)를 수행합니다. 버킷에 Cloudflare 로그가 대량으로 쌓여 있다면 초기 적재에 다소 시간이 걸릴 수 있습니다.
        </Note>
      </Step>

      <Step title="ClickStack UI 데이터 소스 구성" id="configure-source-self-configured">
        ClickPipes는 Cloudflare 로그를 Cloudflare의 네이티브 필드 이름을 그대로 유지한 플랫 테이블로 수집합니다. ClickStack UI에서 이 로그를 확인하려면 Cloudflare 컬럼을 ClickStack UI의 로그 뷰에 매핑하는 사용자 지정 데이터 소스를 구성하십시오.

        1. ClickStack UI → **Team Settings** → **Sources**로 이동합니다.

        <div className="ch-image-lg">
          <Frame>
            ![소스 추가](/images/clickstack/cloudflare/add-source.webp)
          </Frame>
        </div>

        2. **Add source**를 클릭한 후 다음 설정을 구성합니다. 모든 필드를 표시하려면 **Configure Optional Fields**를 클릭하십시오.

        <div className="ch-image-lg">
          <Frame>
            ![선택 필드 구성](/images/clickstack/cloudflare/configure-optional-fields.webp)
          </Frame>
        </div>

        | 설정                                 | 값                                                                                                                                                                                                                                                                                                                 |
        | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
        | **Name**                           | `Cloudflare Logs`                                                                                                                                                                                                                                                                                                 |
        | **Source Data Type**               | Log                                                                                                                                                                                                                                                                                                               |
        | **Database**                       | `default`                                                                                                                                                                                                                                                                                                         |
        | **Table**                          | `cloudflare_http_logs`                                                                                                                                                                                                                                                                                            |
        | **Timestamp Column**               | `toDateTime(EdgeStartTimestamp / 1000000000)`                                                                                                                                                                                                                                                                     |
        | **Default Select**                 | `EdgeStartTimestamp, ClientRequestMethod, ClientRequestURI, EdgeResponseStatus, ClientCountry`                                                                                                                                                                                                                    |
        | **Service Name Expression**        | `'cloudflare'`                                                                                                                                                                                                                                                                                                    |
        | **Log Level Expression**           | `multiIf(EdgeResponseStatus >= 500, 'ERROR', EdgeResponseStatus >= 400, 'WARN', 'INFO')`                                                                                                                                                                                                                          |
        | **Body Expression**                | `concat(ClientRequestMethod, ' ', ClientRequestURI, ' ', toString(EdgeResponseStatus))`                                                                                                                                                                                                                           |
        | **Log Attributes Expression**      | `map('http.method', ClientRequestMethod, 'http.status_code', toString(EdgeResponseStatus), 'http.url', ClientRequestURI, 'client.country', ClientCountry, 'client.ip', ClientIP, 'cache.status', CacheCacheStatus, 'bot.score', toString(BotScore), 'cloudflare.ray_id', RayID, 'cloudflare.colo', EdgeColoCode)` |
        | **Resource Attributes Expression** | `map('cloudflare.zone', ClientRequestHost)`                                                                                                                                                                                                                                                                       |
        | **Implicit Column Expression**     | `concat(ClientRequestMethod, ' ', ClientRequestURI)`                                                                                                                                                                                                                                                              |

        3. **Save Source**를 클릭합니다.

        <div className="ch-image-lg">
          <Frame>
            ![소스 저장](/images/clickstack/cloudflare/save-source.webp)
          </Frame>
        </div>

        이 구성은 데이터 변환이나 중복 없이 Cloudflare의 네이티브 컬럼을 ClickStack UI의 로그 뷰어에 직접 매핑합니다. **Body**에는 `GET /api/v1/users 200`과 같은 요청 요약이 표시되며, 모든 Cloudflare 필드를 검색 가능한 속성으로 사용할 수 있습니다.
      </Step>

      <Step title="ClickStack UI에서 데이터 확인" id="verify-hyperdx-self-configured">
        **검색** 뷰로 이동한 후 **Cloudflare Logs** 소스를 선택하십시오. 데이터가 포함되도록 시간 범위를 설정하십시오. 다음과 같은 로그 항목이 표시됩니다.

        * Body 컬럼에 표시되는 요청 요약(예: `GET /api/v1/users 200`)
        * HTTP 상태에 따라 색상으로 구분되는 심각도 수준(2xx는 INFO, 4xx는 WARN, 5xx는 ERROR)
        * `http.status_code`, `client.country`, `cache.status`, `bot.score` 등 검색 가능한 속성

## 데모 데이터세트 {#demo-dataset-self-configured}

    운영 환경의 Cloudflare Logpush를 구성하기 전에 통합을 테스트하려는 사용자를 위해 실제와 유사한 HTTP 요청 로그가 포함된 샘플 데이터셋을 제공합니다.

    <Steps>
      <Step title="데모 데이터셋으로 ClickPipes 시작하기" id="start-demo-self-configured">
        1. ClickHouse Cloud 콘솔 → **Data Sources** → **Create ClickPipe**
        2. **Source**: Amazon S3
        3. **Authentication**: Public
        4. **S3 file path**: `https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/cloudflare/cloudflare-http-logs.json`
        5. **Incoming data**를 클릭하십시오
        6. 포맷으로 **JSON**을 선택하십시오
        7. **Parse information**을 클릭하고 감지된 스키마를 검토하십시오
        8. **Table name**을 `cloudflare_http_logs`로 설정하십시오
        9. **Complete Setup**을 클릭하십시오

        이 데이터셋에는 24시간 동안의 HTTP 요청 로그 항목 5,000개가 포함되어 있으며, 여러 국가에서 유입된 트래픽, 캐시 적중 및 미스, API 및 정적 자산 요청, 오류 응답, 보안 이벤트 등 실제 환경과 유사한 패턴이 반영되어 있습니다.
      </Step>

      <Step title="ClickStack UI 데이터 소스 구성" id="configure-demo-source-self-configured">

## 문제 해결 {#troubleshooting-self-configured}

### ClickHouse에 데이터가 표시되지 않는 경우 {#no-data-self-configured}

    테이블이 생성되었는지, 데이터가 들어 있는지 확인하십시오:

    ```sql
    SHOW TABLES FROM default LIKE 'cloudflare_http_logs';
    SELECT count() FROM cloudflare_http_logs;
    ```

    테이블은 존재하지만 비어 있다면 ClickPipes에서 오류를 확인하십시오: ClickHouse Cloud 콘솔 → **데이터 소스(Data Sources)** → 해당 ClickPipe → **로그**. 프라이빗 버킷의 인증 문제는 [S3 ClickPipes 액세스 제어 문서](/ko/integrations/clickpipes/object-storage/amazon-s3/overview#access-control)를 참조하십시오.

### ClickStack UI에 로그가 표시되지 않는 경우 {#no-hyperdx-self-configured}

    데이터가 ClickHouse에는 있지만 ClickStack UI에 표시되지 않는다면 데이터 소스 구성을 확인하세요:

    * ClickStack UI → **팀 설정** → **소스**에서 `cloudflare_http_logs`용 소스가 있는지 확인하십시오
    * **타임스탬프 컬럼**이 `toDateTime(EdgeStartTimestamp / 1000000000)`으로 설정되어 있는지 확인하십시오. Cloudflare 타임스탬프는 나노초 단위이므로 변환이 필요합니다
    * ClickStack UI의 시간 범위에 해당 데이터가 포함되는지 확인하십시오. 데모 데이터셋을 사용하는 경우 시간 범위를 **2026-02-23 00:00:00 - 2026-02-26 00:00:00**으로 설정하십시오

## 프로덕션 환경으로 전환 {#going-to-production-self-configured}

    이 가이드에서는 퍼블릭 데모 데이터셋을 사용하여 Cloudflare 로그를 수집하는 방법을 보여줍니다. 운영 환경에 배포할 때는 Cloudflare Logpush가 자체 S3 버킷에 데이터를 쓰도록 구성하고, 안전한 액세스를 위해 [IAM role 기반 인증](/ko/products/cloud/guides/data-sources/accessing-s3-data-securely)을 사용하여 ClickPipes를 설정하십시오. 스토리지 비용과 수집량을 줄이려면 필요한 [Logpush 필드](https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/zone/http_requests/)만 선택하십시오. 파일을 더 체계적으로 관리하려면 Logpush에서 일별 하위 폴더를 활성화하고, 하위 디렉터리까지 모두 일치시키려면 ClickPipes 경로 패턴에 `**/*`를 사용하십시오.

    백필 및 순서가 뒤바뀐 파일 처리를 위한 [SQS 기반 unordered 수집](/ko/integrations/clickpipes/object-storage/amazon-s3/overview#continuous-ingestion-any-order) 등 고급 구성 옵션은 [S3 ClickPipes 문서](/ko/integrations/clickpipes/object-storage/amazon-s3/overview)를 참조하십시오.
