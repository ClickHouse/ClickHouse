OpenTelemetry PostgreSQL 수신기로 PostgreSQL 메트릭을 수집하여 ClickHouse Observability로 전송합니다. PostgreSQL을 설치하지 않고 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하세요.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* Docker 및 `curl`
* 자체 메트릭을 수집하려는 경우: collector에서 연결할 수 있는 PostgreSQL 14 이상 버전 및 모니터링용 사용자

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동하십시오. OTLP HTTP 엔드포인트와 API Key를 복사합니다. **Copy connection details**로 구성을 복사하거나 **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트에는 `/v1/metrics` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 신호 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 같은 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 PostgreSQL과의 통합 {#existing-postgres}

<Steps>
  <Step title="모니터링 사용자 구성" id="monitoring-permissions">
    PostgreSQL 관리자 권한으로 모니터링 사용자를 생성하고(아직 없는 경우) 통계에 대한 액세스 권한을 부여하십시오:

    ```sql
    CREATE USER otel_monitor WITH PASSWORD 'REPLACE_WITH_A_STRONG_PASSWORD';
    GRANT pg_monitor TO otel_monitor;
    GRANT CONNECT ON DATABASE postgres TO otel_monitor;
    ```

    모니터링할 각 데이터베이스에 `CONNECT` 권한을 부여하십시오. 또한 네트워크 및 `pg_hba.conf` 설정에서 PostgreSQL이 collector의 연결을 허용하는지 확인하십시오.

    OTLP 연결 변수를 설정한 터미널에서 데이터베이스 연결 변수도 설정하십시오:

    ```bash
    export POSTGRES_ENDPOINT='YOUR_POSTGRES_HOST:5432'
    export POSTGRES_USERNAME='otel_monitor'
    export POSTGRES_PASSWORD='YOUR_MONITORING_PASSWORD'
    ```

    PostgreSQL이 Docker 호스트에서 실행 중이라면 `host.docker.internal:5432`를 사용하십시오. 공유 Docker 네트워크의 컨테이너라면 데이터베이스 컨테이너의 호스트명을 사용하고, collector 실행 명령에 `--network YOUR_NETWORK`를 추가하십시오.
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `postgres-metrics.yaml`로 저장하십시오. `databases` 목록은 실제 데이터베이스 이름으로 바꾸십시오:

    ```yaml
    receivers:
      postgresql:
        endpoint: ${env:POSTGRES_ENDPOINT}
        transport: tcp
        username: ${env:POSTGRES_USERNAME}
        password: ${env:POSTGRES_PASSWORD}
        databases:
          - postgres
        collection_interval: 30s
        tls:
          insecure: false
          insecure_skip_verify: false
    processors:
      resource/postgres:
        attributes:
          - key: service.name
            value: postgresql-service
            action: upsert
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics/postgres:
          receivers: [postgresql]
          processors: [resource/postgres, batch]
          exporters: [otlp_http/observability]
    ```

    이 구성은 TLS를 활성화하고 서버 인증서를 검증합니다. 사설 인증 기관(CA)을 사용한다면 `tls.ca_file`을 설정하고 CA 파일을 collector에 마운트하십시오. TLS를 사용하지 않는 로컬 PostgreSQL 서버라면 `tls.insecure: true`를 설정하십시오. 이 경우 데이터베이스 연결에서 TLS가 비활성화됩니다. 자세한 내용은 [PostgreSQL 수신기 구성](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/receiver/postgresqlreceiver#configuration)을 참조하십시오.
  </Step>

  <Step title="collector 실행" id="run-collector">
    ```bash
    docker run --rm --name postgres-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e POSTGRES_ENDPOINT \
      -e POSTGRES_USERNAME \
      -e POSTGRES_PASSWORD \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    터미널을 열어 둔 상태로 수집 인터벌이 최소 2회 지날 때까지 기다리십시오. 테스트를 마치면 **Ctrl+C**를 눌러 collector를 중지하십시오.
  </Step>

  <Step title="메트릭 확인" id="verify-metrics">
    **차트 탐색기**를 열고 **Metrics** 소스를 선택한 다음, `ServiceName:postgresql-service`로 필터링하고 **Last 15 minutes**를 선택하십시오. `postgresql.backends`, `postgresql.commits` 또는 `postgresql.db_size`가 표시되는지 확인하십시오.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 샘플에는 24시간 동안 5분 간격으로 수집된 gauge 및 sum 데이터 포인트 8,928개가 포함되어 있습니다. 원본 데이터세트의 연결 급증, 캐시 활동, 롤백, 교착 상태(deadlock)가 그대로 보존되어 있습니다. 샘플에는 데이터베이스 수준의 메트릭이 포함되며, 실제 수집 시에는 테이블 및 인덱스 메트릭도 함께 제공됩니다.

시작하기 전에 [연결 변수](#connection-details)를 설정하십시오.

<Steps>
  <Step title="샘플 메트릭 다운로드" id="download-sample">
    [샘플 번들을 다운로드](/ko/assets/postgres-metrics-demo.zip)(약 64 KB)한 후 `postgres-metrics-demo.json`을 작업 디렉터리에 압축 해제하십시오.
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다음 내용을 `postgres-metrics-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: postgresql-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-11T05:55:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      데모 전용 transform은 메트릭 값과 각 포인트의 시작·종료 타임스탬프 사이의 간격을 유지한 채 타임스탬프를 현재 시점으로 갱신합니다. 실제 PostgreSQL 메트릭을 수집할 때는 이 transform을 제외하십시오. 배치 제한은 대상 collector가 처리할 수 있도록 업로드 크기를 작게 유지하는 역할을 합니다.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    구성 파일이 있는 디렉터리에서 collector를 실행하고 이 터미널은 열어 두십시오.

    ```bash
    docker run --rm --name postgres-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/postgres-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="샘플 전송" id="load-metrics">
    다른 터미널을 열고 다운로드 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @postgres-metrics-demo.json
    ```

    `{}` 또는 `{"partialSuccess":{}}`와 같은 응답이 반환되면 로컬 collector가 요청을 수락한 것입니다. collector 터미널에서 내보내기 오류가 없는지 확인하고, 데이터가 전달될 때까지 몇 초간 기다리십시오. 데이터를 확인한 후 **Ctrl+C**로 collector를 중지하십시오. 샘플을 다시 전송하면 포인트가 중복될 수 있습니다.
  </Step>

  <Step title="메트릭 확인" id="verify-demo-metrics">
    [다음 섹션](#dashboards)의 대시보드를 가져온 후 `ServiceName:postgresql-demo`로 필터링하고 **최근 2일**을 선택하십시오. 샘플에는 gauge 메트릭과 sum 메트릭이 모두 포함되어 있으므로 데이터베이스에 직접 접근할 필요가 없습니다.
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collector-fails-to-start}

collector 출력에 구성 오류가 있는지 확인하십시오. 또한 설정 파일이 마운트되어 있는지, Docker를 실행하는 터미널에 연결 변수가 설정되어 있는지 확인하십시오.

### 메트릭이 표시되지 않는 경우 {#no-metrics}

collector 출력에 데이터베이스 연결(database connection) 오류나 내보내기 오류가 있는지 확인하십시오. 컨테이너에서 데이터베이스 호스트명에 연결할 수 있는지, 데이터베이스 이름이 올바른지, PostgreSQL이 모니터링 사용자의 연결을 허용하는지 확인하십시오. **Metrics** 소스, 서비스 이름 필터, 시간 범위도 함께 확인하십시오.

### 인증 또는 TLS 오류 {#authentication-errors}

모니터링 사용자에게 `pg_monitor` 및 `CONNECT` 권한이 있는지 확인하십시오. PostgreSQL에 접근할 수 있는 호스트에서 `psql`로 데이터베이스 자격 증명을 테스트하십시오.

```bash
psql -h YOUR_POSTGRES_HOST -U otel_monitor -d postgres -W -c 'SELECT 1;'
```

수신기의 TLS 설정을 서버에 맞게 구성하고 필요한 CA 인증서를 마운트하십시오. 내보내기 오류가 발생하면 OTLP 엔드포인트와 인증 정보가 서비스의 연결 정보와 일치하는지 확인하십시오.
