OpenTelemetry JMX Metric Gatherer로 Kafka 브로커 메트릭을 수집하여 ClickHouse Observability로 전송합니다. Kafka를 배포하지 않고 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* Docker Compose가 포함된 Docker 및 `curl`
* 자체 메트릭을 수집하려는 경우, 원격 JMX가 활성화되어 있고 gatherer에서 연결할 수 있는 Kafka 브로커

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동하십시오. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나 **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    JMX gatherer 또는 데모 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/metrics` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    연결 가능한 collector의 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 JMX gatherer의 `-Dotel.exporter.otlp.headers` 인수와 데모 collector의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

gatherer 또는 collector 컨테이너에서 엔드포인트에 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 Kafka 배포와의 통합 {#existing-kafka}

<Steps>
  <Step title="브로커의 JMX 엔드포인트 확인" id="verify-jmx">
    브로커에 구성된 원격 JMX 엔드포인트를 사용하십시오. 포트 `9999`에서 JMX를 노출하는 브로커의 예는 다음과 같습니다.

    ```bash
    export KAFKA_JMX_URL='service:jmx:rmi:///jndi/rmi://YOUR_KAFKA_HOST:9999/jmxrmi'
    export KAFKA_BROKER_ID='broker-0'
    ```

    호스트명과 브로커 ID를 실제 값으로 바꾸십시오. 브로커가 광고(advertise)하는 RMI 호스트명도 gatherer에서 연결할 수 있어야 합니다. 브로커가 레지스트리 포트와 RMI 포트를 별도로 사용한다면 네트워크에서 두 포트를 모두 허용하십시오. gatherer는 JMX만 읽으므로 Kafka 클라이언트 포트 `9092`는 필요하지 않습니다.

    컨테이너가 공유 Docker 네트워크에 있다면 브로커의 컨테이너 호스트명을 사용하십시오. 브로커가 Docker 호스트에서 실행 중이라면 `host.docker.internal`을 사용하고, 컨테이너에서 연결할 수 있는 호스트명을 광고하도록 브로커를 구성하십시오. JMX 접근은 모니터링 네트워크로 제한하고, 브로커의 인증 및 TLS 설정은 그대로 유지하십시오.
  </Step>

  <Step title="JMX Metric Gatherer 다운로드" id="download-jmx">
    ```bash
    curl -fL -o opentelemetry-jmx-metrics.jar \
      https://github.com/open-telemetry/opentelemetry-java-contrib/releases/download/v1.32.0/opentelemetry-jmx-metrics.jar
    ```
  </Step>

  <Step title="gatherer 구성" id="configure-gatherer">
    다운로드한 JAR 파일과 같은 위치에 다음 내용을 `compose.yaml`로 저장하십시오.

    ```yaml
    services:
      kafka-jmx-gatherer:
        image: eclipse-temurin:11-jre
        extra_hosts:
          - "host.docker.internal:host-gateway"
        environment:
          - KAFKA_JMX_URL
          - KAFKA_BROKER_ID
          - OTEL_EXPORTER_OTLP_ENDPOINT
          - OTEL_EXPORTER_OTLP_AUTHORIZATION
        volumes:
          - ./opentelemetry-jmx-metrics.jar:/app/opentelemetry-jmx-metrics.jar:ro
        command:
          - sh
          - -c
          - >-
            exec java
            -Dotel.jmx.service.url="$${KAFKA_JMX_URL}"
            -Dotel.jmx.target.system=kafka
            -Dotel.jmx.interval.milliseconds=10000
            -Dotel.metrics.exporter=otlp
            -Dotel.exporter.otlp.protocol=http/protobuf
            -Dotel.exporter.otlp.endpoint="$${OTEL_EXPORTER_OTLP_ENDPOINT}"
            -Dotel.exporter.otlp.headers="authorization=$${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
            -Dotel.resource.attributes="service.name=kafka-service,kafka.broker.id=$${KAFKA_BROKER_ID}"
            -jar /app/opentelemetry-jmx-metrics.jar
    ```

    브로커가 기존 Docker 네트워크에 있다면 Compose 구성에서 `kafka-jmx-gatherer`를 해당 네트워크에 연결하십시오. 인증된 JMX를 사용하려면 `otel.jmx.username` 및 `otel.jmx.password` 속성을 추가하고, TLS를 사용하려면 적절한 신뢰 저장소를 구성하십시오. 자세한 내용은 [gatherer의 인증 및 TLS 구성](https://github.com/open-telemetry/opentelemetry-java-contrib/tree/v1.32.0/jmx-metrics#configuration)을 참조하십시오.
  </Step>

  <Step title="수집 시작" id="run-gatherer">
    이 터미널에서 [연결 변수](#connection-details)와 브로커 변수를 설정한 다음, `compose.yaml`이 있는 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    docker compose up kafka-jmx-gatherer
    ```

    터미널을 열어 둔 채로 JMX 연결 오류나 OTLP 내보내기 오류가 없는지 확인하십시오. gatherer는 10초마다 메트릭을 수집합니다. 서비스를 확인하기 전에 수집 주기가 최소 두 번 지나도록 기다리십시오. 테스트가 끝나면 **Ctrl+C**를 눌러 중지하십시오.

    브로커가 여러 개라면 브로커마다 고유한 JMX URL과 `kafka.broker.id`를 지정하여 gatherer를 하나씩 실행하십시오.
  </Step>

  <Step title="메트릭 확인" id="verify-metrics">
    **차트 탐색기**를 열고 **Metrics** 소스를 선택한 다음, `ServiceName:kafka-service`로 필터링하고 **Last 15 minutes**를 선택하십시오. `kafka.partition.count`, `kafka.partition.under_replicated` 또는 `kafka.message.count`가 있는지 확인하십시오. 트래픽 관련 메트릭은 브로커에 활동이 있어야 의미 있는 값이 표시됩니다.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 샘플에는 약 29시간 동안 5분 간격으로 수집된 6,282개의 게이지 및 sum 데이터 포인트가 포함되어 있습니다. 원본 데이터셋의 트래픽 급증, 요청 지연 시간, 컨슈머 지연, 파티션 상태 패턴이 그대로 유지됩니다. Kafka를 배포하거나 데이터베이스에 직접 액세스할 필요가 없습니다.

시작하기 전에 [연결 변수](#connection-details)를 설정하십시오.

<Steps>
  <Step title="샘플 메트릭 다운로드" id="download-sample">
    [샘플 번들을 다운로드](/ko/assets/kafka-metrics-demo.zip)(약 53 KB)한 후 `kafka-metrics-demo.json`을 작업 디렉터리에 압축 해제하십시오.
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다음 내용을 `kafka-metrics-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: kafka-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-11-06T22:14:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      데모 전용 변환은 메트릭 값과 각 포인트의 시작·종료 타임스탬프 간 간격을 그대로 유지하면서 타임스탬프만 갱신합니다. 실제 Kafka 메트릭을 수집할 때는 이 변환을 제외하십시오. 배치 제한은 대상 collector가 처리할 수 있도록 업로드 크기를 작게 유지합니다.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    구성 파일이 있는 디렉터리에서 collector를 실행하고 이 터미널은 열어 두십시오.

    ```bash
    docker run --rm --name kafka-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="샘플 전송" id="load-metrics">
    다른 터미널에서 다운로드 디렉터리로 이동한 후 다음 명령을 실행하십시오.

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @kafka-metrics-demo.json
    ```

    `{}` 또는 `{"partialSuccess":{}}`와 같은 응답이 반환되면 로컬 collector가 요청을 수락한 것입니다. collector 터미널에서 내보내기 오류가 없는지 확인하고, 데이터가 전달될 때까지 몇 초간 기다리십시오. 데이터를 확인한 후에는 **Ctrl+C**를 눌러 collector를 중지하십시오. 샘플을 다시 전송하면 포인트가 중복될 수 있습니다.
  </Step>

  <Step title="메트릭 확인" id="verify-demo-metrics">
    [다음 섹션](#dashboards)의 대시보드를 가져온 후 `ServiceName:kafka-demo`로 필터링하고 **최근 2일**을 선택하십시오. 샘플에는 게이지 메트릭과 sum 메트릭이 모두 포함되어 있으므로 데이터베이스에 직접 액세스할 필요가 없습니다.
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### JMX 연결 실패 {#jmx-connection-fails}

`docker compose logs kafka-jmx-gatherer`로 gatherer 출력을 확인하십시오. JMX가 활성화되어 있는지, 레지스트리와 advertised RMI 엔드포인트에 모두 연결할 수 있는지, 구성된 JMX 자격 증명과 신뢰 저장소가 브로커 설정과 일치하는지 확인하십시오. 컨테이너 호스트 이름을 사용하는 경우 각 컨테이너가 동일한 대상 네트워크에 연결되어 있어야 합니다.

### 메트릭이 표시되지 않는 경우 {#no-metrics}

* gatherer 또는 데모 collector 출력에 연결, 인증 또는 내보내기 오류가 있는지 확인하십시오.
* OTLP HTTP 엔드포인트와 인증 정보가 서비스의 연결 정보와 일치하는지 확인하십시오.
* **Metrics** 소스, 서비스 이름 필터, 시간 범위를 확인하십시오. 데모에서는 **최근 2일**을 선택하십시오.
* 기존 collector를 사용하는 경우 메트릭 파이프라인에 OTLP 수신기와 메트릭 익스포터가 포함되어 있는지 확인하십시오.
* 데모 대시보드를 사용하기 전에 **차트 탐색기**에서 실제로 수집되고 있는 메트릭 이름을 확인하십시오.

### Kafka 클라이언트 명령어의 JMX 포트 충돌 {#port-conflicts}

브로커 컨테이너 내부에서 Kafka 클라이언트 명령어를 실행할 때는 클라이언트가 동일한 포트에 바인드하려고 시도하지 않도록, 해당 명령어에서 브로커로부터 상속된 JMX 설정을 해제하십시오.

```bash
env -u JMX_PORT -u KAFKA_JMX_OPTS kafka-topics --list --bootstrap-server YOUR_KAFKA_HOST:9092
```
