OpenTelemetry Java 에이전트로 JVM 메트릭을 수집하여 ClickHouse Observability로 전송합니다. 애플리케이션을 계측하지 않고 통합을 체험해 보려면 [데모 데이터셋](#demo-dataset)을 사용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* 자체 메트릭을 수집하는 경우: Java 8 이상 애플리케이션 및 해당 애플리케이션의 시작 명령 또는 실행 환경에 대한 액세스 권한
* 데모를 실행하는 경우: Docker 및 `curl`

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동합니다. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나 **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    애플리케이션 또는 데모 collector를 시작할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    플레이스홀더를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트는 `/v1/metrics` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    연결 가능한 collector의 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 Java 에이전트에서는 `OTEL_EXPORTER_OTLP_HEADERS`를, 데모 collector에서는 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 애플리케이션에서 연결할 수 있어야 하며, Docker 데모에서는 collector 컨테이너에서도 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 JVM 애플리케이션과 통합 {#existing-jvm}

<Steps>
  <Step title="Java 에이전트 다운로드" id="download-agent">
    OpenTelemetry Java 에이전트 `2.22.0`을 다운로드하세요.

    ```bash
    curl -fLO https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/download/v2.22.0/opentelemetry-javaagent.jar
    ```
  </Step>

  <Step title="애플리케이션 구성 및 시작" id="configure-jvm">
    [연결 변수](#connection-details)를 설정한 다음 에이전트를 구성하세요.

    ```bash
    export OTEL_SERVICE_NAME='jvm-service'
    export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=${OTEL_EXPORTER_OTLP_AUTHORIZATION}"
    export OTEL_METRICS_EXPORTER='otlp'
    export OTEL_LOGS_EXPORTER='none'
    export OTEL_TRACES_EXPORTER='none'

    java -javaagent:./opentelemetry-javaagent.jar -jar my-application.jar
    ```

    `my-application.jar`를 실제 애플리케이션 JAR로 바꾸고, 필요하면 에이전트 경로를 조정하세요. 서비스 이름은 애플리케이션을 식별할 수 있는 이름으로 지정하세요. 이 설정은 메트릭만 수집합니다. 애플리케이션에서 이미 트레이스나 로그를 내보내고 있다면 해당 시그널의 기존 익스포터 설정은 그대로 유지하세요.

    서비스나 컨테이너로 관리되는 애플리케이션이라면 기존 JVM 시작 인수에 에이전트를 추가하고, 배포 구성을 통해 환경 변수를 전달하세요. 자세한 내용은 [Java 에이전트 구성 문서](https://opentelemetry.io/docs/zero-code/java/agent/configuration/)를 참조하십시오.
  </Step>

  <Step title="메트릭 확인" id="verify-metrics">
    에이전트가 메트릭을 내보낼 수 있도록 최소 2분 이상 기다리세요. **차트 탐색기**를 열고 **Metrics** 소스를 선택한 다음 `jvm.memory.used` 또는 `jvm.thread.count`를 찾으세요. `ServiceName:jvm-service`로 필터링하고 **Last 15 minutes**를 선택하세요.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 샘플에는 5분 간격으로 샘플링된 게이지 포인트 6,048개와 원본 데이터세트의 가비지 컬렉션 이벤트 412개 전체가 포함되어 있습니다. 약 24시간 분량의 메모리, 스레드, 클래스, CPU, GC 활동 데이터를 담고 있습니다. Java 애플리케이션이나 데이터베이스 직접 액세스는 필요하지 않습니다.

시작하기 전에 [연결 변수](#connection-details)를 설정하십시오.

<Steps>
  <Step title="샘플 메트릭 다운로드" id="download-sample">
    [데모 번들을 다운로드](/ko/assets/jvm-metrics-demo.zip)하여 작업 디렉터리에 압축을 해제하십시오. 번들에는 `jvm-metrics-demo.json`과 `jvm-metrics-dashboard.json`이 포함되어 있습니다.
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다음 내용을 `jvm-metrics-demo.yaml`로 저장하십시오.

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318
    processors:
      resource/demo:
        attributes:
          - key: service.name
            value: jvm-demo
            action: upsert
      transform/demo_timestamps:
        error_mode: propagate
        metric_statements:
          - context: datapoint
            statements:
              - set(cache["interval_ns"], time_unix_nano - start_time_unix_nano)
              - set(time, Now() - Duration("2m") - (Time("2025-12-08T14:16:00Z", "%Y-%m-%dT%H:%M:%SZ") - time))
              - set(start_time_unix_nano, time_unix_nano - cache["interval_ns"])
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/managed:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        metrics:
          receivers: [otlp]
          processors: [resource/demo, transform/demo_timestamps, batch]
          exporters: [otlp_http/managed]
    ```

    <Note>
      데모 전용 transform은 메트릭 값과 각 포인트의 시작·종료 타임스탬프 사이의 인터벌은 그대로 유지하면서 타임스탬프만 현재 시각 기준으로 갱신합니다. 실제 JVM 메트릭을 수집할 때는 이 설정을 제외하십시오. 배치 제한은 대상 collector가 처리할 수 있도록 업로드 크기를 작게 유지하는 역할을 합니다.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    구성 파일이 있는 디렉터리에서 collector를 실행하고, 이 터미널은 열어 둔 상태로 두십시오.

    ```bash
    docker run --rm --name jvm-metrics-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/jvm-metrics-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```
  </Step>

  <Step title="샘플 전송" id="load-metrics">
    다른 터미널을 열고 다운로드 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/metrics \
      -H 'Content-Type: application/json' \
      --data-binary @jvm-metrics-demo.json
    ```

    `{}` 또는 `{"partialSuccess":{}}`와 같은 응답이 반환되면 로컬 collector가 요청을 수락한 것입니다. collector 터미널에서 내보내기 오류가 없는지 확인하고, 데이터가 전달될 때까지 몇 초간 기다리십시오. 데이터를 확인한 후에는 **Ctrl+C**로 collector를 중지하십시오. 샘플을 다시 전송하면 포인트가 중복될 수 있습니다.
  </Step>

  <Step title="메트릭 확인" id="verify-demo-metrics">
    [다음 섹션](#dashboards)의 대시보드를 가져온 후 `ServiceName:jvm-demo`로 필터링하고 **최근 2일**을 선택하십시오. 샘플에는 게이지 메트릭과 sum 메트릭이 모두 포함되어 있으며, 데이터베이스 직접 액세스는 필요하지 않습니다.
  </Step>
</Steps>

    </Note>

## 문제 해결 {#troubleshooting}

### 에이전트가 시작되지 않는 경우 {#agent-not-starting}

`-javaagent`에 지정한 경로에 에이전트 JAR 파일이 있는지, 애플리케이션에 해당 파일의 읽기 권한이 있는지, Java 버전이 8 이상인지 확인하십시오. 또한 애플리케이션 시작 시 출력되는 로그에 에이전트 관련 오류가 있는지 확인하십시오.

### 메트릭이 표시되지 않는 경우 {#no-metrics}

* 애플리케이션 또는 데모 collector의 출력에서 인증 오류나 내보내기 오류가 있는지 확인하십시오.
* 애플리케이션 또는 컨테이너에서 엔드포인트에 연결할 수 있는지, 프로토콜이 `http/protobuf`로 설정되어 있는지 확인하십시오.
* **Metrics** 소스, 서비스 이름 필터, 시간 범위를 확인하십시오. 데모에서는 **최근 2일**을 선택하십시오.
* 기존 collector를 사용한다면 해당 메트릭 파이프라인에 OTLP 수신기와 메트릭 익스포터가 포함되어 있는지 확인하십시오.
* 데모 collector가 요청을 수락했는데도 데이터가 수신되지 않는다면 해당 터미널에 전달 오류가 있는지 확인하십시오.
