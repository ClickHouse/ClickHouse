OpenTelemetry Nginx 모듈로 Nginx의 분산 트레이스를 수집하여 ClickHouse Observability로 전송합니다. Nginx를 설치하지 않고 통합을 체험해 보려면 [데모 데이터셋](#demo-dataset)을 사용하세요.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* 자체 트레이스를 사용하려면 OpenTelemetry 모듈이 포함된 Nginx와 해당 구성을 수정할 수 있는 권한(permission)이 필요합니다. 아래 Docker 예시에서는 `nginx:1.27-otel`을 사용합니다.
* 데모 데이터셋을 사용하려면 `curl`과 Docker가 필요합니다.

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동하십시오. **Copy connection details**로 엔드포인트와 API Key를 복사하거나, **Reveal key**를 선택하여 마스킹된 키를 확인하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    Nginx 모듈은 **OTLP/gRPC**로 데이터를 내보내며, 일반적으로 포트 **4317**을 사용합니다. JSON 데모는 **OTLP/HTTP**를 사용하며, 일반적으로 포트 **4318**을 사용합니다. 각 프로토콜에 맞는 엔드포인트를 사용하고, TLS가 필요하면 `https://`를 포함하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_GRPC_ENDPOINT='https://YOUR_OTEL_HOST:4317'
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 연결 정보로 대체하십시오. HTTP 엔드포인트는 `/v1/traces`를 붙이지 않은 기본 주소를 사용하십시오. 해당 경로는 collector 익스포터가 자동으로 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector의 OTLP 엔드포인트와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 Nginx의 `header authorization` 지시어와 데모 collector의 `headers` 블록을 생략하십시오. 자세한 내용은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_GRPC_ENDPOINT='http://YOUR_COLLECTOR_HOST:4317'
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

Nginx에서 gRPC 엔드포인트에 연결할 수 있어야 합니다. Docker Desktop에서는 `host.docker.internal`을 사용하여 호스트에서 실행 중인 collector에 접근하십시오. 공유 Docker 네트워크에 있는 컨테이너에서는 collector의 컨테이너 이름을 사용하십시오. TLS를 사용하지 않는 로컬 엔드포인트에는 `http://`를 사용하십시오.

## 기존 Nginx와 통합 {#existing-nginx}

<Steps>
  <Step title="OpenTelemetry Nginx 모듈 설치" id="install-module">
    `nginx:1.27-otel` image에는 `ngx_otel_module.so`가 포함되어 있습니다. Docker 외부에 설치하는 경우 [Nginx OpenTelemetry 모듈 문서](https://nginx.org/en/docs/ngx_otel_module.html)에 링크된 설치 지침을 따르십시오.
  </Step>

  <Step title="Nginx 추적 구성" id="configure-nginx">
    다음 Docker 예제는 템플릿을 사용하여 컨테이너 시작 스크립트가 연결 환경 변수를 치환하도록 합니다. 이 내용을 `nginx.conf.template`으로 저장하십시오. `return 200` location은 간단한 스모크 테스트용입니다. 실제 애플리케이션에서는 기존 서버 및 라우팅 구성을 그대로 유지한 채 여기에 표시된 추적 지시어만 추가하십시오.

    ```nginx
    load_module modules/ngx_otel_module.so;

    events {
        worker_connections 1024;
    }

    http {
        otel_exporter {
            endpoint ${OTEL_EXPORTER_OTLP_GRPC_ENDPOINT};
            header authorization "${OTEL_EXPORTER_OTLP_AUTHORIZATION}";
        }

        otel_service_name "nginx-proxy";
        otel_trace on;

        server {
            listen 80;

            location / {
                otel_trace_context propagate;
                otel_span_name "$request_method $uri";
                otel_span_attr http.status_code $status;
                otel_span_attr http.request.method $request_method;
                otel_span_attr http.route $uri;
                return 200 "Nginx tracing is enabled\n";
            }
        }
    }
    ```

    다음 내용을 같은 디렉터리에 `compose.yaml`로 저장하십시오.

    ```yaml
    services:
      nginx:
        image: nginx:1.27-otel
        ports:
          - "8081:80"
        environment:
          OTEL_EXPORTER_OTLP_GRPC_ENDPOINT: ${OTEL_EXPORTER_OTLP_GRPC_ENDPOINT}
          OTEL_EXPORTER_OTLP_AUTHORIZATION: ${OTEL_EXPORTER_OTLP_AUTHORIZATION}
          NGINX_ENVSUBST_OUTPUT_DIR: /etc/nginx
          NGINX_ENVSUBST_FILTER: ^OTEL_EXPORTER_OTLP_
        volumes:
          - ./nginx.conf.template:/etc/nginx/templates/nginx.conf.template:ro
    ```

    치환 필터(filter) 덕분에 `$request_method`, `$uri` 같은 Nginx 변수는 치환되지 않고 그대로 유지됩니다. Nginx는 직접 마운트한 `nginx.conf`의 셸 환경 변수를 자동으로 치환하지 않습니다. Docker 외부에서는 구성을 검사하기 전에 연결 자리표시자를 실제 값으로 바꾸고, 키가 포함된 파일에 대한 접근을 제한하십시오.
  </Step>

  <Step title="Nginx 검사 및 시작" id="run-nginx">
    같은 터미널에서 [연결 변수](#connection-details)를 설정한 후 다음을 실행하십시오.

    ```bash
    docker compose run --rm nginx nginx -t
    docker compose up -d nginx
    curl http://localhost:8081/
    ```

    요청마다 메서드, 경로, 상태 코드, 소요 시간이 담긴 스팬이 생성됩니다. 기존 배포에서는 애플리케이션 URL로 요청을 보내십시오. 템플릿이나 환경 변수를 변경한 후에는 `docker compose up -d --force-recreate nginx`를 실행하여 변경 사항을 적용하십시오.
  </Step>

  <Step title="UI에서 트레이스 확인" id="verifying-traces">
    **검색**을 열고 **Traces**를 선택한 다음 `ServiceName:nginx-proxy`로 필터링하십시오. 요청을 보낸 시점이 포함되도록 시간 범위를 선택하고, 내보내기가 완료될 때까지 몇 초간 기다리십시오. 트레이스를 열면 스팬과 HTTP 속성을 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![검색 뷰의 Nginx 트레이스](/images/clickstack/observability-nginx-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 샘플 데이터에는 9개 엔드포인트에 걸친 Nginx 스팬 1,000개가 포함되어 있으며, 성공한 요청, HTTP 오류, 다양한 지연 시간이 담겨 있습니다. 데이터를 전송하기 전에 [연결 변수](#connection-details)를 설정하십시오.

<Steps>
  <Step title="샘플 데이터셋 다운로드" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/nginx-traces-sample.json
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo-collector">
    다음 내용을 다운로드 디렉터리에 `nginx-traces-demo.yaml`로 저장하십시오:

    ```yaml
    receivers:
      otlp:
        protocols:
          http:
            endpoint: 0.0.0.0:4318

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/demo_timestamps:
        error_mode: propagate
        trace_statements:
          - context: span
            statements:
              - set(cache["duration_ns"], end_time_unix_nano - start_time_unix_nano)
              - >-
                set(start_time,
                  Now() - Duration("2m") -
                  (Time("2025-10-27T19:36:05Z", "%Y-%m-%dT%H:%M:%SZ") - start_time)
                )
              - set(end_time_unix_nano, start_time_unix_nano + cache["duration_ns"])
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        traces/nginx-demo:
          receivers: [otlp]
          processors: [memory_limiter, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      데모 전용 `transform/demo_timestamps` 프로세서는 스팬 소요 시간과 트래픽 패턴은 그대로 유지한 채, 이 샘플의 시간대를 수집 시점 2분 전까지의 최근 약 24시간으로 이동합니다. 실제 Nginx 트레이스를 전송할 때는 원래 타임스탬프가 유지되도록 이 프로세서를 제외하십시오. 샘플을 다시 전송하면 스팬이 중복될 수 있습니다.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo-collector">
    <Note>
      대상 collector가 이 컴퓨터에서 실행 중이라면 `OTEL_EXPORTER_OTLP_ENDPOINT`를 `http://host.docker.internal:4318`로 설정하십시오. 아래 명령에는 Docker 호스트 매핑이 포함되어 있습니다.
    </Note>

    연결 변수를 설정한 터미널에서 구성 파일이 있는 디렉터리로 이동한 후 OpenTelemetry Collector Contrib `0.161.0`을 실행하십시오. 이 터미널은 계속 열어 두십시오:

    ```bash
    docker run --rm --name nginx-traces-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -p 127.0.0.1:14318:4318 \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/nginx-traces-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    로컬 수신기는 포트 `4318`을 사용하는 기존 collector와 충돌하지 않도록 포트 `14318`을 사용합니다. collector는 위의 인증 설정을 사용하여 구성된 엔드포인트로 트레이스를 전달합니다.
  </Step>

  <Step title="트레이스 전송" id="send-traces">
    다른 터미널을 열고 다운로드 디렉터리에서 원본 샘플을 로컬 collector로 전송하십시오:

    ```bash
    curl --fail-with-body -sS http://localhost:14318/v1/traces \
      -H "Content-Type: application/json" \
      --data-binary @nginx-traces-sample.json
    ```

    `{}` 또는 `{"partialSuccess":{}}`와 같은 빈 성공 응답이 반환되면 로컬 collector가 요청을 정상적으로 수락한 것입니다. collector 출력에 내보내기 오류가 없는지 확인하고, 배치가 서비스에 도달할 때까지 몇 초 정도 기다리십시오. 작업을 마친 후에는 **Ctrl+C**를 눌러 데모 collector를 중지하십시오.
  </Step>

  <Step title="데모 트레이스 확인" id="verify-demo-traces">
    **검색**을 열고 **Traces**를 선택한 다음 `ServiceName:nginx-proxy`로 필터링하고, 이동된 데이터셋 전체가 표시되도록 **최근 2일**을 선택하십시오. 트레이스를 열어 HTTP 속성을 확인하십시오.

      <Frame>
        ![검색 뷰의 Nginx 트레이스 예시](/images/clickstack/observability-nginx-demo-traces.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### Nginx가 시작되지 않는 경우 {#nginx-fails-to-start}

`docker compose run --rm nginx nginx -t`를 실행하여 생성된 구성을 검사하십시오. 알 수 없는 `otel_*` 지시어 오류나 모듈 파일 누락 오류가 발생한다면 모듈이 설치되지 않았거나 로드되지 않은 것입니다. `-otel` image를 사용하고 있는지, 템플릿이 문서에 명시된 경로에 마운트되어 있는지 확인하십시오.

### 트레이스가 표시되지 않는 경우 {#no-traces}

* gRPC 엔드포인트와 대상 collector에서 요구하는 인증 정보를 확인하십시오. 관리형 서비스는 `Bearer` 접두사를 사용합니다. Nginx 모듈에는 HTTP 엔드포인트를 사용하지 마십시오.
* Nginx 컨테이너에서 엔드포인트에 연결할 수 있는지, 그리고 엔드포인트의 스킴이 대상의 TLS 구성과 일치하는지 확인하십시오.
* 요청을 보내십시오. 유휴 상태의 Nginx 인스턴스는 요청 스팬을 생성하지 않습니다.
* **Traces**, 서비스 이름 필터, 선택한 시간 범위를 확인하십시오. 데모에서는 `transform/demo_timestamps`가 수집기 파이프라인에 포함되어 있는지 확인하고 **최근 2일**(최근 2일)을 선택하십시오.
* 데모에서는 collector 터미널에 인증 오류나 내보내기 오류가 있는지 확인하십시오. collector의 HTTP 엔드포인트와 authorization 값이 연결 정보와 일치하는지도 확인하십시오.
* `docker compose logs nginx`로 Nginx 오류를 확인하십시오. Docker 외부에서 실행하는 경우에는 Nginx 오류 로그를 확인하십시오.
