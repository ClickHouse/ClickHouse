OpenTelemetry `filelog` 수신기로 Kafka 브로커 로그를 수집하여 ClickHouse Observability로 전송합니다. Kafka를 배포하지 않고 이 통합을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* Docker 및 `curl`
* 자체 로그를 사용하려면 아래 포맷과 일치하는 Kafka 브로커 로그 파일에 대한 액세스 권한

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동한 다음, OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**를 클릭하면 구성을 복사할 수 있고, **Reveal key**를 클릭하면 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 바꾸십시오. 엔드포인트에는 `/v1/logs` 접미사를 붙이지 말고 기본 HTTP 엔드포인트를 그대로 사용하십시오. 시그널 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 같은 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 Kafka와 통합 {#existing-kafka}

<Steps>
  <Step title="Kafka 로깅 구성 확인" id="verify-kafka">
    브로커 로그 위치를 확인하십시오. 설치 방식과 로깅 구성에 따라 다르지만, 일반적으로 `$KAFKA_HOME/logs` 또는 `/var/log/kafka`에 있습니다:

    ```bash
    ls "$KAFKA_HOME/logs/"
    ls /var/log/kafka/
    ```

    주요 로그 파일로는 `server.log`(브로커 이벤트), `controller.log`(컨트롤러 이벤트), `state-change.log`(파티션 및 레플리카 상태 전환)가 있습니다. 이러한 파일은 로깅 어펜더(appender)에서 별도로 구성한 경우에만 분리되어 생성됩니다.

    이 가이드의 파서는 다음과 같은 Log4j 텍스트 형식을 전제로 합니다:

    ```text
    [2026-03-09 14:23:45,123] INFO [KafkaServer id=0] started (kafka.server.KafkaServer)
    ```

    브로커가 로그를 stdout으로만 출력한다면 브로커의 로깅 구성에서 파일 어펜더(file appender)를 구성하고 해당 디렉터리를 collector와 공유하십시오. `filelog` 수신기는 컨테이너의 stdout을 직접 읽지 않습니다. 로깅 패턴이 다르다면 그에 맞게 파서를 조정하십시오.
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `kafka-logs-monitoring.yaml` 파일로 저장하십시오.

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
          - /var/log/kafka/controller.log
          - /var/log/kafka/state-change.log
        start_at: end
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka
          - type: add
            field: resource["service.name"]
            value: kafka-service
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, batch]
          exporters: [otlp_http/observability]
    ```

    `location`을 브로커 로그에서 사용하는 시간대로 설정하십시오. 이 예시는 UTC를 기준으로 합니다. 여러 줄 엔트리는 전체 스택 트레이스를 그대로 유지합니다. collector는 `start_at: end` 설정에 따라 새 엔트리만 읽으며, 심각도 텍스트를 소문자로 정규화합니다.
  </Step>

  <Step title="collector를 실행하십시오" id="run-collector">
    [연결 변수](#connection-details)를 설정한 다음 구성 디렉터리에서 실행하십시오. 필요하면 호스트의 로그 경로를 조정하십시오. 그룹 읽기 권한으로 파일에 접근하는 경우, `ls -ln /var/log/kafka`에 표시되는 숫자 그룹 ID를 사용하여 `--group-add LOG_GROUP_ID`를 추가하십시오.

    ```bash
    docker run --rm --name kafka-logs-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/kafka:/var/log/kafka:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    터미널을 열어 둔 채로 새 로그 항목이 기록되도록 브로커 활동을 발생시키십시오. 테스트를 마치면 **Ctrl+C**를 눌러 중지하십시오.
  </Step>

  <Step title="로그 확인" id="verify-logs">
    **검색**을 열고 **Logs**를 선택한 다음, `ServiceName:kafka-service`로 필터링하고 **Last 15 minutes**를 선택하십시오. 타임스탬프와 심각도가 파싱된 브로커 메시지가 표시됩니다.
  </Step>
</Steps>

## 데모 데이터셋 {#demo-dataset}

이 샘플에는 약 24시간 분량의 Kafka 브로커 로그 항목 6,376개가 포함되어 있습니다. collector는 메시지와 스택 트레이스는 그대로 유지하고 타임스탬프만 갱신합니다.

<Steps>
  <Step title="샘플 다운로드" id="download-sample">
    ```bash
    curl -fL -o server.log \
      https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/kafka/server.log
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo">
    다음 내용을 `kafka-logs-demo.yaml` 파일로 저장하십시오.

    ```yaml
    receivers:
      filelog/kafka:
        include:
          - /var/log/kafka/server.log
        start_at: beginning
        force_flush_period: 1s
        multiline:
          line_start_pattern: '^\[\d{4}-\d{2}-\d{2}'
        operators:
          - type: regex_parser
            regex: '(?s)^\[(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3})\] (?P<severity>\w+) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
            timestamp:
              parse_from: attributes.timestamp
              layout: '%Y-%m-%d %H:%M:%S,%L'
              location: UTC
            severity:
              parse_from: attributes.severity
          - type: move
            from: attributes.message
            to: body
          - type: add
            field: attributes.source
            value: kafka-demo
          - type: add
            field: resource["service.name"]
            value: kafka-demo
    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      transform/kafka:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.severity_text, ToLowerCase(log.severity_text))
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - context: log
            statements:
              - set(log.time, Now() - Duration("2m") - (Time("2026-03-09T23:59:58.180Z", "%Y-%m-%dT%H:%M:%S.%LZ") - log.time))
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}
    service:
      pipelines:
        logs/kafka:
          receivers: [filelog/kafka]
          processors: [memory_limiter, transform/kafka, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```
  </Step>

  <Step title="데모 collector 실행" id="run-demo">
    [연결 변수](#connection-details)를 설정한 다음, 두 파일이 있는 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    docker run --rm --name kafka-logs-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/kafka-logs-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/server.log:/var/log/kafka/server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    수집이 확인될 때까지 터미널을 열어 두십시오. 작업이 끝나면 **Ctrl+C**를 눌러 중지하십시오. 데모를 다시 실행하면 타임스탬프가 갱신된 상태로 샘플이 다시 수집됩니다.
  </Step>

  <Step title="데모 로그 확인" id="verify-demo">
    **검색**을 열고 **로그**를 선택한 다음, `ServiceName:kafka-demo`로 필터링하고 **Last 2 days**를 선택하십시오.

  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### 로그가 표시되지 않는 경우 {#no-logs}

collector 출력에서 파일 권한(permission), 파싱, 인증 또는 내보내기 오류가 있는지 확인하십시오. 브로커가 마운트된 디렉터리에 로그를 기록하는지, 파일 이름이 수신기의 `include` 목록과 일치하는지도 확인하십시오. 현재 적용 중인 구성은 새로 추가되는 로그 항목만 읽습니다.

### 로그가 올바르게 파싱되지 않는 경우 {#parsing-errors}

브로커 로그 항목을 예상 포맷과 비교해 보십시오:

```bash
tail -n 20 /var/log/kafka/server.log
```

사용 중인 로깅 포맷이 다르다면 정규 표현식과 여러 줄 시작 패턴을 그에 맞게 조정하십시오. 타임스탬프 파서의 `location`은 브로커 로깅에 사용되는 시간대로 설정하십시오.
