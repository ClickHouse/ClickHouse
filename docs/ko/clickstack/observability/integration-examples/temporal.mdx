Temporal은 단순하면서도 정교하고 복원력 있는 애플리케이션을 구축할 수 있는 추상화 계층을 제공합니다.

<Info>
  **요약**

  OTel Prometheus 수신기를 사용해 ClickHouse Observability에서 Temporal Cloud 메트릭을 모니터링합니다. 사전 구성된 대시보드가 함께 제공됩니다.
</Info>

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* 기존 Temporal Cloud 계정
* Temporal Cloud 및 OTLP 엔드포인트에 HTTPS로 액세스할 수 있는 호스트에 설치된 Docker

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동하십시오. OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나 **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    자리표시자를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트에는 `/v1/metrics` 접미사 없이 기본 HTTP 엔드포인트를 사용하십시오. 시그널 경로는 익스포터가 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    collector에서 연결할 수 있는 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않으면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 이 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 Temporal Cloud와 통합 {#existing-temporal}

<Steps>
  <Step title="Temporal Cloud 키 생성" id="create-temporal-cloud-key">
    [인증 가이드](https://docs.temporal.io/cloud/metrics/openmetrics/api-reference#authentication)에 따라 **Metrics Read-Only** 역할이 부여된 Temporal Cloud 서비스 계정을 생성하고 API Key를 발급하십시오. 서비스 계정과 키는 Account Owner 또는 Global Admin만 생성할 수 있습니다.

    <Warning>
      **키 파일**

      Temporal API Key는 아래에서 생성할 구성 파일과 같은 디렉터리에 `temporal.key` 파일로 저장하십시오. `Bearer` 접두사나 앞뒤 공백 없이 키 값만 저장해야 합니다. 이 키는 ClickHouse Observability API Key와는 별개입니다. collector가 마운트된 파일을 읽을 수 있는지 확인하십시오.
    </Warning>
  </Step>

  <Step title="OTel collector 구성" id="custom-otel">
    Prometheus 수신기를 사용하는 독립 실행형 OpenTelemetry Collector를 실행하여 Temporal Cloud의 메트릭을 스크레이프하고 서비스로 전달합니다.

    다음 구성으로 `temporal-metrics.yaml` 파일을 생성하십시오.

    ```yaml title="temporal-metrics.yaml"
    receivers:
      prometheus/temporal:
        config:
          scrape_configs:
          - job_name: 'temporal-cloud'
            scrape_interval: 60s
            scrape_timeout: 30s
            honor_timestamps: true
            scheme: https
            authorization:
              type: Bearer
              credentials_file: /etc/otelcol-contrib/temporal.key
            static_configs:
              - targets: ['metrics.temporal.io']
            metrics_path: '/v1/metrics'

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 400
        spike_limit_mib: 100
      batch:
        timeout: 5s
        send_batch_size: 500
        send_batch_max_size: 500
      resource:
        attributes:
          - key: service.name
            value: "temporal"
            action: upsert

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: ${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}

    service:
      pipelines:
        metrics/temporal:
          receivers: [prometheus/temporal]
          processors:
            - memory_limiter
            - resource
            - batch
          exporters:
            - otlp_http/observability
    ```

    이 구성은 다음을 수행합니다.

    * `metrics.temporal.io`의 Temporal Cloud에 연결합니다
    * 60초마다 메트릭을 수집합니다
    * [주요 성능 메트릭](https://docs.temporal.io/cloud/metrics/openmetrics/metrics-reference)을 수집합니다
    * [OpenTelemetry 시맨틱 규칙](https://opentelemetry.io/docs/specs/semconv/resource/#service)에 따라 **필수 `service.name` 리소스 속성을 설정합니다**
    * 전용 파이프라인을 통해 OTLP 엔드포인트로 메트릭을 전송합니다

    Temporal Cloud 계정이 여러 개라면 `service.name`을 계정별로 다르게 지정하여 구분하십시오(예: `temporal-prod`, `temporal-dev`).
  </Step>

  <Step title="collector 실행" id="run-collector">
    `temporal-metrics.yaml`과 `temporal.key`가 있는 디렉터리에서 [연결 변수](#connection-details)를 설정한 후 다음 명령을 실행하십시오.

    ```bash
    docker run --rm --name temporal-metrics-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/temporal-metrics.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/temporal.key:/etc/otelcol-contrib/temporal.key:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    터미널을 열어 둔 채로 스크레이프 또는 내보내기 오류가 발생하는지 확인하십시오. Temporal Cloud 메트릭이 표시되기까지 몇 분 정도 걸릴 수 있습니다. 테스트를 마치면 **Ctrl+C**를 눌러 collector를 중지하십시오.
  </Step>

  <Step title="ClickHouse Observability에서 메트릭 확인" id="verifying-metrics">
    구성을 마쳤으면 ClickHouse Observability에 로그인하여 메트릭이 수집되고 있는지 확인하십시오.

    1. **차트 탐색기**를 열고 **Metrics** 소스를 선택합니다
    2. `ServiceName:temporal`로 필터링하고 **Last 15 minutes**를 선택한 다음, `temporal`로 시작하는 메트릭을 검색합니다(예: `temporal_cloud_v1_workflow_success_count`, `temporal_cloud_v1_poll_timeout_count`)
    3. 구성한 수집 인터벌마다 메트릭 데이터 포인트가 표시되는지 확인합니다

    <div className="ch-image-md">
      <Frame>
        ![Temporal 메트릭](/images/clickstack/temporal/temporal-metrics.webp)
      </Frame>
    </div>
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collector-fails-to-start}

터미널 출력에 구성 오류가 있는지 확인하십시오. 마운트된 두 파일이 모두 존재하는지, collector가 `temporal.key`를 읽을 수 있는지 확인하십시오. 또한 Docker를 실행하는 터미널에 OTLP 연결 변수가 설정되어 있는지 확인하십시오.

### 메트릭이 표시되지 않는 경우 {#no-metrics}

collector 로그를 확인하십시오:

```bash
docker logs temporal-metrics-collector
```

스크레이프, 인증 또는 내보내기 오류가 있는지 살펴보십시오. 호스트에서 `https://metrics.temporal.io/v1/metrics` 및 OTLP 엔드포인트에 접근할 수 있는지 확인하십시오. **차트 탐색기**에서 **Metrics** 소스, `ServiceName:temporal` 필터(filter), 시간 범위가 올바르게 설정되어 있는지 확인하십시오. Temporal 메트릭은 조회 가능해지기까지 몇 분 정도 걸릴 수 있으며, 계정의 활동량에 따라 달라집니다.

### 인증 오류 {#auth-errors}

Temporal 스크레이프 오류가 발생하면 `temporal.key`에 **Metrics Read-Only** 역할이 부여된 서비스 계정의 유효한 API Key가 들어 있는지 확인하십시오. OTLP 내보내기 오류가 발생하면 ClickHouse Observability 엔드포인트와 authorization 값을 확인하십시오. 두 항목은 서로 다른 자격 증명입니다.

## 다음 단계 {#next-steps}

* 주요 메트릭(워크플로 실패율, 작업 백로그 증가율, schedule-to-start 지연 시간)에 대한 [알림](/ko/clickstack/observability/features/alerts)을 설정하세요
* 특정 활용 사례(네임스페이스 수준 모니터링, 워크플로 유형별 성능)에 맞는 대시보드를 추가로 만드세요
* 엔드포인트와 서비스 이름을 달리하여 수신기 구성을 복제하면 여러 Temporal Cloud 계정을 모니터링할 수 있습니다

## 프로덕션 환경으로 전환 {#going-to-production}

이 가이드에서는 별도의 OpenTelemetry Collector를 실행하여 메트릭을 서비스의 OTLP 엔드포인트로 전달합니다. 배포 방법은 [OpenTelemetry 데이터 전송](/ko/clickstack/observability/ingesting-data/opentelemetry)을 참조하십시오.
