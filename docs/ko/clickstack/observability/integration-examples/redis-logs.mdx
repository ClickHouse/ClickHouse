OpenTelemetry collector로 Redis 서버 로그를 수집하여 ClickHouse Observability로 전송합니다. Redis를 설치하지 않고 통합 기능을 사용해 보려면 [데모 데이터셋](#demo-dataset)을 활용하십시오.

## 사전 요구 사항 {#prerequisites}

* ClickHouse Observability 서비스
* collector 예시를 실행하기 위한 Docker 또는 이미 배포된 OpenTelemetry Collector Contrib
* 자체 로그를 사용하려면 기존에 설치된 Redis 및 해당 로그 파일에 대한 액세스 권한

### 연결 정보 {#connection-details}

<Tabs>
  <Tab title="완전 관리형">
    <BetaBadge label="베타 서비스" />

    ClickHouse Observability를 열고 **팀 설정 → Data → Managed Telemetry**로 이동한 뒤 OTLP HTTP 엔드포인트와 API Key를 복사하십시오. **Copy connection details**로 구성을 복사하거나, **Reveal key**로 마스킹된 키를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![Managed Telemetry 연결 정보](/images/clickstack/getting-started/observability-managed-telemetry.png)
      </Frame>
    </div>

    아래 OTLP 익스포터 예시를 사용하려면 collector를 실행할 터미널에서 다음 변수를 설정하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='https://YOUR_OTEL_ENDPOINT:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='Bearer YOUR_API_KEY'
    ```

    플레이스홀더를 서비스의 정확한 엔드포인트(포트 포함)와 API Key로 대체하십시오. 엔드포인트에는 `/v1/logs` 접미사를 붙이지 말고 기본 HTTP 엔드포인트를 그대로 사용하십시오. 시그널 경로는 익스포터가 자동으로 끝에 추가합니다.
  </Tab>

  <Tab title="자가 관리형">
    연결 가능한 collector의 OTLP HTTP 엔드포인트(예: `http://YOUR_COLLECTOR_HOST:4318`)와 인증 설정을 사용하십시오. collector에 인증이 필요하지 않다면 아래 구성에서 익스포터의 `headers` 블록을 생략하십시오. 설정 방법은 [자가 관리형 시작 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT='http://YOUR_COLLECTOR_HOST:4318'
    export OTEL_EXPORTER_OTLP_AUTHORIZATION='YOUR_INGESTION_KEY'
    ```
  </Tab>
</Tabs>

엔드포인트는 collector 컨테이너에서 연결할 수 있어야 합니다. 대상 collector가 같은 컴퓨터에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오. 아래 Docker 명령어에는 호스트 매핑이 포함되어 있습니다.

## 기존 Redis와 통합 {#existing-redis}

<Steps>
  <Step title="Redis 로깅 구성 확인" id="verify-redis">
    Redis가 로그를 기록하는 위치를 확인하세요:

    ```bash
    redis-cli CONFIG GET logfile
    ```

    일반적인 Redis 로그 위치:

    * **Linux (apt/yum)**: `/var/log/redis/redis-server.log`
    * **macOS (Homebrew)**: `/usr/local/var/log/redis.log` 또는 `/opt/homebrew/var/log/redis.log`
    * **Docker**: 대개 stdout으로 로그를 출력하지만, `/data/redis.log`에 기록하도록 구성할 수 있습니다.

    Redis가 stdout으로 로그를 출력하는 경우, `redis.conf`를 수정하여 파일에 기록하도록 구성하십시오:

    ```bash
    # Log to file instead of stdout
    logfile /var/log/redis/redis-server.log

    # Set log level (options: debug, verbose, notice, warning)
    loglevel notice
    ```

    로그 디렉터리가 존재하는지, Redis가 해당 디렉터리에 쓸 수 있는지 확인하십시오. 구성을 변경한 후에는 설치 환경에 맞는 서비스 이름으로 Redis를 재시작하십시오:

    ```bash
    # For systemd
    sudo systemctl restart redis

    # For Docker
    docker restart <redis-container>
    ```
  </Step>

  <Step title="collector 구성" id="configure-collector">
    다음 내용을 `redis-monitoring.yaml` 파일로 저장하세요:

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis/redis-server.log
        start_at: end
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis
          - type: add
            field: resource["service.name"]
            value: redis-service

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, batch]
          exporters: [otlp_http/observability]
    ```

    이 구성은 프로세스 ID, 역할, 타임스탬프, 로그 레벨, 메시지를 파싱합니다. 또한 `service.name`을 `redis-service`로 설정하고, 대시보드에서 활용할 수 있도록 Redis 로그 레벨을 `SeverityText`에 매핑합니다. Redis notice 메시지(`*`)는 `info`로, 경고(`#`)는 `warn`으로, debug/verbose 메시지(`.` 및 `-`)는 `debug`로 매핑됩니다.

    Redis 로그 타임스탬프에는 시간대 정보가 없습니다. `location`을 `America/Chicago`와 같이 Redis 서버의 시간대로 설정하십시오. 예시에서는 `UTC`를 사용합니다. 원본 타임스탬프와 로그 본문은 그대로 유지됩니다. `start_at: end`로 설정하면 collector가 파일을 처음 열 때 새 엔트리만 읽습니다.
  </Step>

  <Step title="collector를 실행하십시오" id="run-collector">
    [연결 변수](#connection-details)를 설정한 다음, `redis-monitoring.yaml`이 있는 디렉터리에서 다음 명령을 실행하십시오. 호스트의 로그 디렉터리 경로와 수신기의 `include` 파일 이름은 설치 환경에 맞게 조정하십시오.

    ```bash
    docker run --rm --name redis-monitoring-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-monitoring.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v /var/log/redis:/var/log/redis:ro \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    이 터미널을 열어 둔 상태에서 새 로그 항목이 기록되도록 Redis 작업을 발생시키십시오. collector가 마운트된 파일을 읽을 수 있어야 합니다.
  </Step>

  <Step title="로그 확인" id="verify-logs">
    **검색**을 열고 **Logs**를 선택한 다음 `ServiceName:redis-service`로 필터링하십시오. 새로 수집된 로그가 포함되도록 시간 범위를 선택하십시오. 엔트리를 펼쳐 `SeverityText`와 `LogAttributes` 아래의 파싱된 필드를 확인하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![검색 뷰의 Redis 로그](/images/clickstack/observability-redis-demo-logs.png)
      </Frame>
    </div>
  </Step>
</Steps>

## 데모 데이터세트 {#demo-dataset}

이 샘플 데이터에는 Redis 서버 로그 항목 10,000개가 포함되어 있습니다. 시작하기 전에 [연결 변수](#connection-details)를 설정하십시오.

<Steps>
  <Step title="샘플 데이터셋 다운로드" id="download-sample">
    ```bash
    curl -fLO https://datasets-documentation.s3.eu-west-3.amazonaws.com/clickstack-integrations/redis/redis-server.log
    ```
  </Step>

  <Step title="데모 collector 구성" id="configure-demo">
    다음 내용을 다운로드 디렉터리에 `redis-demo.yaml`로 저장하십시오:

    ```yaml
    receivers:
      filelog/redis:
        include:
          - /var/log/redis-demo/redis-server.log
        start_at: beginning
        operators:
          - type: regex_parser
            regex: '^(?P<pid>\d+):(?P<role>\w+) (?P<timestamp>\d{2} \w+ \d{4} \d{2}:\d{2}:\d{2}\.\d+) (?P<log_level>[.\-*#]) (?P<message>.*)$'
            parse_from: body
            parse_to: attributes
          - type: time_parser
            parse_from: attributes.timestamp
            layout_type: gotime
            layout: '02 Jan 2006 15:04:05.000'
            location: UTC
          - type: add
            field: attributes.source
            value: redis-demo
          - type: add
            field: resource["service.name"]
            value: redis-demo

    processors:
      memory_limiter:
        check_interval: 1s
        limit_mib: 256
        spike_limit_mib: 64
      transform/redis:
        error_mode: propagate
        log_statements:
          - set(log.severity_text, "debug") where log.attributes["log_level"] == "." or log.attributes["log_level"] == "-"
          - set(log.severity_number, SEVERITY_NUMBER_DEBUG) where log.severity_text == "debug"
          - set(log.severity_text, "info") where log.attributes["log_level"] == "*"
          - set(log.severity_number, SEVERITY_NUMBER_INFO) where log.severity_text == "info"
          - set(log.severity_text, "warn") where log.attributes["log_level"] == "#"
          - set(log.severity_number, SEVERITY_NUMBER_WARN) where log.severity_text == "warn"
      transform/demo_timestamps:
        error_mode: propagate
        log_statements:
          - >-
            set(log.time,
              Now() - Duration("2m") -
              (Time("2025-10-28T14:59:22Z", "%Y-%m-%dT%H:%M:%SZ") - log.time)
            )
      batch:
        timeout: 5s
        send_batch_size: 1024

    exporters:
      otlp_http/observability:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          authorization: "${env:OTEL_EXPORTER_OTLP_AUTHORIZATION}"

    service:
      pipelines:
        logs/redis:
          receivers: [filelog/redis]
          processors: [memory_limiter, transform/redis, transform/demo_timestamps, batch]
          exporters: [otlp_http/observability]
    ```

    <Note>
      데모 전용 `transform/demo_timestamps` 프로세서는 샘플 데이터의 트래픽 패턴을 그대로 유지하면서, 데이터를 수집 시점 2분 전까지의 대략 최근 24시간 범위로 이동합니다. 원래의 타임스탬프 속성과 로그 본문은 변경되지 않습니다. 직접 수집하는 Redis 로그에는 이 프로세서를 사용하지 마십시오.
    </Note>
  </Step>

  <Step title="데모 collector 실행" id="run-demo">
    `redis-server.log` 및 `redis-demo.yaml` 파일이 있는 디렉터리에서 다음 명령을 실행하십시오.

    ```bash
    docker run --rm --name redis-demo-collector \
      --add-host=host.docker.internal:host-gateway \
      --memory=512m \
      -e OTEL_EXPORTER_OTLP_ENDPOINT \
      -e OTEL_EXPORTER_OTLP_AUTHORIZATION \
      -v "$(pwd)/redis-demo.yaml:/etc/otelcol-contrib/config.yaml:ro" \
      -v "$(pwd)/redis-server.log:/var/log/redis-demo/redis-server.log:ro" \
      otel/opentelemetry-collector-contrib:0.161.0 \
      --config=/etc/otelcol-contrib/config.yaml
    ```

    수집을 확인하는 동안에는 터미널을 열어 두십시오. 확인이 끝나면 **Ctrl+C**를 눌러 collector를 중지하십시오. 이 예시는 파일 오프셋을 영구 저장하지 않으므로, 데모를 다시 실행하면 샘플 데이터가 갱신된 타임스탬프와 함께 재수집됩니다.
  </Step>

  <Step title="데모 로그를 확인하십시오" id="verify-demo-logs">
    **검색**을 열고 **로그**를 선택한 다음, `ServiceName:redis-demo`로 필터링하고 **최근 2일**을 선택하세요. 로그 항목을 펼치면 파싱된 속성과 심각도를 확인할 수 있습니다.

  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

### collector가 시작되지 않는 경우 {#collector-fails-to-start}

collector 터미널에 구성 오류가 표시되는지 확인하십시오. YAML 파일이 문서에 안내된 경로에 마운트되어 있는지, 그리고 Docker를 실행하는 터미널에 엔드포인트와 필요한 인증 변수가 모두 설정되어 있는지 확인하십시오.

### 로그가 표시되지 않는 경우 {#no-logs}

* collector 출력에 인증 오류나 내보내기 오류가 있는지 확인하고, 연결 정보가 올바른지 검증하십시오.
* `redis-cli CONFIG GET logfile`을 실행하여 Redis가 로그를 파일에 기록하는지 확인하십시오. 또한 collector가 해당 파일을 읽을 수 있는지, 마운트된 경로가 수신기의 `include` 경로와 일치하는지 확인하십시오.
* `start_at: end`를 사용한다면 collector를 시작한 후에 새 로그 항목을 생성하십시오.
* **Logs** 소스, 서비스 이름 필터, 시간 범위를 확인하십시오. 데모 환경에서는 파이프라인에 `transform/demo_timestamps`를 포함하고 **최근 2일**을 선택하십시오.

### 로그가 올바르게 파싱되지 않는 경우 {#logs-not-parsing}

수신기는 Redis의 표준 로그 포맷인 `pid:role timestamp level message`를 전제로 동작합니다. 로그 파일을 확인한 후, 포맷이 다르면 정규 표현식을 수정하십시오. 또한 시간 파서의 `location`을 Redis 서버의 시간대로 설정하십시오.
