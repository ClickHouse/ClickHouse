ClickHouse Observability를 시작하고, 테스트 이벤트를 전송한 다음, 관측성 UI에서 해당 이벤트가 표시되는지 확인합니다.

이 서비스는 관리형 텔레메트리 엔드포인트를 제공합니다. 애플리케이션, 에이전트 또는 기존 OpenTelemetry Collector에서 이 엔드포인트로 데이터를 전송하십시오.

수집 파이프라인과 스키마(schema)를 직접 관리한다면 [자가 관리형 시작하기 가이드](/ko/clickstack/self-configured/getting-started/managed)를 참조하십시오.

## 시작하기 전에 {#before-you-begin}

완전 관리형 ClickHouse Observability 서비스가 있어야 하며, 해당 서비스의 텔레메트리 엔드포인트와 API Key에 액세스할 수 있어야 합니다.

### 서비스 생성 {#create-a-service}

아직 서비스가 없다면 ClickHouse Cloud 빠른 시작의 [ClickHouse 서비스 생성](/ko/get-started/setup/cloud#1-create-a-clickhouse-service)부터 진행하십시오. 서비스가 실행되면 ClickHouse Observability를 여십시오. 서비스에 아직 데이터가 없으면 **시작하기** 페이지가 자동으로 열립니다. 아래 세 가지 방법 중 하나를 선택하여 텔레메트리를 전송하십시오.

## ClickHouse Observability 설정 {#set-up-clickhouse-observability}

환경에 맞는 방법을 선택하십시오.

<Tabs>
  <Tab title="기존 OpenTelemetry 설정 사용">
    <div className="ch-image-md">
      <Frame>
        ![URL, Collector config, Env vars 옵션과 마스킹된 연결 정보가 표시된 Set up OpenTelemetry 대화 상자](/images/clickstack/getting-started/observability-connection-details.png)
      </Frame>
    </div>

    애플리케이션, 에이전트 또는 collector에서 이미 OpenTelemetry 데이터를 생성하고 있다면 이 방법을 사용하십시오.

    1. 시작하기 페이지에서 **View connection details**를 선택합니다.

    2. 텔레메트리 전송기에 맞는 구성을 복사합니다. 연결 정보는 **URL**, **Collector config**, **Env vars** 옵션으로 제공됩니다.

    3. 제공된 인증 정보를 사용하여 관리형 엔드포인트로 텔레메트리를 내보내도록 전송기를 구성합니다.

    4. 애플리케이션에서 평소와 같이 활동을 발생시킨 후, 해당 데이터가 [검색](/ko/clickstack/observability/features/search)에 표시되는지 확인합니다.

    이 연결 정보는 **Team Settings → Data → Managed Telemetry**에서도 확인할 수 있습니다.

    <Tip>
      간단히 확인해 보려면 시작하기 페이지에서 **send a test log**를 선택하십시오(선택 사항). 이 버튼은 UI에서 즉시 테스트 로그를 전송할 뿐이며, 애플리케이션이나 collector의 구성을 검증하지는 않습니다.
    </Tip>
  </Tab>

  <Tab title="AI로 계측하기">
    <div className="ch-image-md">
      <Frame>
        ![instrumentation 프롬프트와 마스킹된 엔드포인트 및 API Key 환경 변수가 표시된 Set it up with an AI agent 대화 상자](/images/clickstack/getting-started/observability-ai-instrumentation.png)
      </Frame>
    </div>

    애플리케이션 코드가 있고 코딩 도우미를 활용해 OpenTelemetry instrumentation을 추가하려는 경우 이 방법을 사용하십시오.

    1. **AI로 계측하기** 아래에서 **Copy prompt**를 선택하여 **Set it up with an AI agent** 대화 상자를 엽니다.
    2. 대화 상자에서 프롬프트를 복사하여 Cursor, Copilot, Claude Code 등 애플리케이션 코드에 접근할 수 있는 코딩 도우미에 붙여 넣습니다.
    3. 대화 상자에 제공된 값으로 `CLICKSTACK_OTLP_ENDPOINT`와 `CLICKSTACK_API_KEY`를 설정합니다. 이 값은 버전 관리에서 제외된 `.env` 파일이나 시크릿 저장소에 보관하십시오.
    4. 제안된 instrumentation을 검토하고 적용한 다음, 애플리케이션을 실행하여 이벤트를 발생시킵니다.

    이 워크플로를 사용 중인 애플리케이션에 적용하려면 [AI로 계측하기](/ko/clickstack/observability/ingesting-data/sdks/instrument-with-ai)를 참조하십시오.

    애플리케이션 코드와 instrumentation 프롬프트가 포함된 전체 예시는 [HackerNews Analyzer 데모](/ko/clickstack/observability/example-datasets/instrument-application)를 참조하십시오. 이 데모에서는 애플리케이션 로그, 트레이스, 메트릭, 브라우저 세션 리플레이를 관리형 서비스로 전송하는 과정을 단계별로 안내합니다.
  </Tab>

  <Tab title="설정 가이드 따르기">
    <div className="ch-image-md">
      <Frame>
        ![언어, 프레임워크, 인프라, collector별 설정 가이드를 검색할 수 있는 Send data 대화 상자](/images/clickstack/getting-started/observability-setup-guides.png)
      </Frame>
    </div>

    특정 애플리케이션이나 인프라 소스에 대한 안내가 필요한 경우 이 방법을 사용하십시오.

    1. **Browse setup guides**를 선택합니다.
    2. 사용 중인 언어, 프레임워크 또는 인프라에 맞는 가이드를 선택합니다.
    3. 가이드의 instrumentation 및 구성 단계를 따른 후, 해당 소스에서 텔레메트리를 생성합니다.

    관리형 구성 예시를 살펴보려면 [Kubernetes 모니터링](/ko/clickstack/observability/example-datasets/kubernetes), [로컬 로그 및 메트릭](/ko/clickstack/observability/example-datasets/local-data) 또는 [HackerNews Analyzer 애플리케이션](/ko/clickstack/observability/example-datasets/instrument-application)부터 시작하십시오. 애플리케이션을 계측하지 않고 수집을 시험해 보려면 [otelgen](/ko/clickstack/observability/example-datasets/otelgen) 또는 [telemetrygen](/ko/clickstack/observability/example-datasets/telemetrygen)을 사용하십시오.
  </Tab>
</Tabs>

## 수집 확인 및 탐색 시작 {#verify-ingestion}

선택한 경로를 완료한 후 **Start exploring**을 선택하여 [검색](/ko/clickstack/observability/features/search) 페이지를 여십시오. 다음 단계로 넘어가기 전에 생성한 이벤트를 찾아 정상적으로 수집되었는지 확인하십시오.

로그는 **Logs** 소스를 선택하고, 이벤트를 전송한 시점이 포함되도록 시간 범위를 지정하십시오. 아래 예시는 UI의 **send a test log** 버튼으로 전송한 로그로, 서비스 이름은 `example-service`입니다. 이벤트를 펼치면 속성을 확인할 수 있습니다.
