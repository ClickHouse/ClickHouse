**ClickHouse Observability**는 오픈 소스 ClickStack을 기반으로 구축된 관측성 플랫폼으로, SRE와 개발자, 그리고 이들이 활용하는 AI 에이전트를 위해 설계되었습니다. 하나의 플랫폼에서 OpenTelemetry 로그, trace, 메트릭을 세션 다시 보기와 함께 검색하고, 쿼리하고, 연관시킬 수 있습니다.

ClickStack UI에서 직접 조사하거나 [ClickStack MCP 서버](/ko/clickstack/observability/mcp)를 통해 자체 에이전트를 연결할 수 있습니다. 조사 도구로 로그를 검색하고 trace를 따라가며, 더 심층적인 분석에는 SQL을 활용하십시오. 풍부한 로그와 추적 스팬에는 요청 세부 정보, 사용자 정의 속성, 비즈니스 컨텍스트가 기록되므로 장애 원인을 파악하는 데 도움이 됩니다.

ClickHouse가 운영하는 백엔드가 필요하다면 **완전 관리형**을, 팀에서 수집 및 데이터베이스 구성을 직접 제어해야 한다면 **자가 관리형**을 선택하십시오. 두 방식 모두 ClickHouse Cloud에서 실행되며 동일한 ClickStack 조사 경험을 제공합니다.

## 작동 방식 {#how-it-works}

두 제공 방식 모두 애플리케이션을 계측하고 환경에서 텔레메트리를 수집합니다. 수집된 데이터는 ClickStack UI에서 탐색할 수 있으며, MCP 호환 에이전트를 연결하여 로그 검색, trace 추적, SQL 실행을 수행할 수도 있습니다. 두 방식의 차이는 이러한 환경을 뒷받침하는 수집 및 데이터베이스 구성을 누가 관리하느냐에 있습니다.

* **완전 관리형:** 관리형 OpenTelemetry 엔드포인트로 텔레메트리를 전송하거나, 기존 Datadog 에이전트를 사용 중이라면 관리형 Datadog 호환 엔드포인트를 사용합니다. 수집 백엔드는 ClickHouse가 운영하며 스키마(schemas), 컴퓨트, 스케일링, 성능도 ClickHouse가 관리합니다.

### 서비스 비교 {#compare-the-offerings}

두 서비스 모두 애플리케이션 계측과 텔레메트리 수집은 사용자가 직접 수행합니다. 아래 표는 ClickHouse가 대신 관리하는 백엔드 영역을 보여 줍니다. 대시(—)는 사용자가 직접 관리하는 영역을 의미합니다.

| ClickHouse가 관리하는 영역            | 완전 관리형 | 자가 관리형 |
| ------------------------------ | :----: | :----: |
| 수집 백엔드                         |    ✓   |    —   |
| 스키마(schemas), 인덱스(indexes), 압축 |    ✓   |    —   |
| 컴퓨트 용량 산정, 스케일링, 워크로드 격리       |    ✓   |    —   |
| 데이터베이스 성능 튜닝                   |    ✓   |    —   |
| 데이터베이스 인프라, 업그레이드, 백업          |    ✓   |    ✓   |
| ClickStack UI 및 MCP 서버 호스팅     |    ✓   |    ✓   |

## 기능 {#features}

* [MCP](/ko/clickstack/observability/mcp)를 통해 자체 에이전트를 연결하여 텔레메트리 검색, trace 추적, 패턴 및 변경 사항 분석, SQL 실행을 수행할 수 있습니다.
* 로그, trace, 메트릭, 세션 다시 보기를 한곳에서 검색하고 서로 연관시킬 수 있습니다.
* high-cardinality 텔레메트리 전반에서 빠른 검색과 집계(aggregations)를 실행할 수 있습니다.
* `level:err`와 같은 [전문 검색 및 Lucene 스타일 필터](/ko/clickstack/observability/features/search)를 사용하거나, 심층 분석이 필요할 때는 SQL을 사용할 수 있습니다.
* [AI 노트북](/ko/clickstack/observability/notebooks)으로 텔레메트리를 탐색하고 [자연어 질문으로 차트](/ko/clickstack/observability/text-to-chart)를 생성할 수 있습니다.
* [대시보드](/ko/clickstack/observability/features/dashboards/overview)를 만들고 [알림](/ko/clickstack/observability/features/alerts)을 구성할 수 있습니다.
* 로그와 추적 스팬의 JSON 필드 및 사용자 정의 속성을 쿼리할 수 있습니다.
* 브라우저 상호작용부터 백엔드 서비스, 데이터베이스 쿼리에 이르기까지 요청 흐름을 추적할 수 있습니다.
* [이벤트 패턴](/ko/clickstack/observability/features/event-patterns)으로 반복되는 장애를 식별하고 [이벤트 차이](/ko/clickstack/observability/features/event-deltas)로 변경 사항을 조사할 수 있습니다.
* 새 이벤트가 들어오는 즉시 로그와 trace를 실시간으로 확인(live tail)할 수 있습니다.
* 사용 중인 제품 유형에 따라 관리형 엔드포인트 또는 자체 수집 collector를 통해 OpenTelemetry 데이터를 수집할 수 있습니다.
* [딥 링크](/ko/clickstack/observability/url-parameters)로 검색 및 조사 화면을 공유할 수 있습니다.

## 원칙 {#clickstack-principles}

### 자체 에이전트 연결 {#bring-your-own-agents}

팀에서 이미 사용 중인 에이전트와 개발 도구를 MCP로 연결하십시오. 에이전트는 UI에서 제공되는 것과 동일한 텔레메트리를 활용하여 로그를 검색하고, trace를 따라가며, 패턴과 변경 사항을 파악할 수 있습니다. 또한 SQL을 실행하여 근거 데이터를 연관시키고, 조사 도구가 직접 지원하지 않는 질문까지 탐색할 수 있습니다.

### 사용 편의성과 특정 목적에 맞게 설계된 구조 {#user-friendly-purpose-built}

ClickStack UI는 검색, 트레이스 탐색, 차트, 대시보드, 알림 기능을 하나로 통합합니다. 일상적인 질문에는 Lucene 스타일 필터와 시각적 쿼리 빌더(query builder)를 사용하고, 분석을 더 세밀하게 제어해야 할 때는 SQL을 활용하십시오.

### 엔드투엔드 관측성 {#end-to-end-observability}

프론트엔드 세션 다시 보기를 애플리케이션 로그, 분산 trace, 메트릭과 연결하면 시스템 전반에 걸쳐 장애를 추적할 수 있습니다. 와이드 이벤트는 요청 세부 정보, 사용자 정의 속성, 비즈니스 컨텍스트를 로그와 추적 스팬에 함께 담아 두므로, 영향을 받는 요청, 서비스, 고객을 쉽게 파악할 수 있습니다.

### ClickHouse 기반 설계 {#built-for-clickhouse}

ClickHouse의 열 지향 저장소, 압축, 병렬 쿼리 실행(Query Execution) 덕분에 대량의 high-cardinality 텔레메트리 데이터에서도 빠른 검색과 집계(aggregations)가 가능합니다. 또한 동시 쿼리를 지원하므로 엔지니어와 에이전트가 동일한 데이터를 병렬로 조사할 수 있습니다.

### OpenTelemetry 네이티브 {#open-telemetry-native}

표준 OpenTelemetry instrumentation, SDK, collector를 사용하여 텔레메트리를 전송합니다. 관리형 OTLP 엔드포인트나 자체 수집 collector를 사용하면 독자적인 수집 포맷을 도입하지 않고도 기존 instrumentation 그대로 로그, trace, 메트릭을 전송할 수 있습니다.
