**자체 관리형 ClickHouse Observability**는 오픈 소스 ClickStack을 기반으로 구축된 관측성 플랫폼으로, SRE와 개발자, 그리고 이들이 사용하는 AI 에이전트를 위해 설계되었습니다. 수집 및 데이터베이스 구성을 직접 제어하면서 OpenTelemetry 로그, 트레이스, 메트릭을 세션 다시 보기와 함께 검색, 쿼리하고 서로 연관시킬 수 있습니다. 스키마(schemas)를 사용자 정의하거나, 쿼리 성능(query performance)을 튜닝하거나, 서비스의 규모 산정 및 스케일링 방식을 직접 결정해야 하는 팀에 적합합니다.

ClickStack UI에서 조사하거나 [MCP 서버](/ko/clickstack/observability/mcp)를 통해 자체 에이전트를 연결할 수 있습니다. 일상적인 조사에는 검색 및 트레이스 탐색을 사용하고, 텔레메트리에 포함된 요청 세부 정보, 사용자 정의 속성, 비즈니스 컨텍스트를 분석할 때는 SQL을 사용하십시오.

ClickHouse와 ClickStack UI는 ClickHouse Cloud가 호스팅하고 운영합니다. 즉, 자가 관리형에서도 데이터베이스나 UI를 직접 호스팅할 필요는 없습니다. 사용자는 수집용 collector를 실행하고, 워크로드에 맞게 데이터베이스 구성을 관리합니다.

대부분의 팀에는 [완전 관리형 ClickHouse Observability](/ko/clickstack/observability/overview)로 시작하는 것을 권장합니다. 관리형 OpenTelemetry 엔드포인트로 텔레메트리를 전송하기만 하면 수집, 스키마(schemas), 인프라, 스케일링은 ClickHouse가 처리합니다. 자가 관리형은 동일한 ClickStack 조사 경험을 제공하지만, 데이터베이스 튜닝과 용량 계획은 사용자가 직접 책임져야 합니다. 이러한 수준의 제어가 필요하고 이를 운영할 전문성을 갖춘 경우에 선택하십시오.

## 데이터 흐름 {#architectural-overview}

애플리케이션과 인프라는 텔레메트리를 collector로 전송합니다. collector는 이를 처리한 후 ClickHouse Cloud 서비스에 기록합니다. 호스팅되는 ClickStack UI는 이 데이터를 쿼리하여 검색, 시각화, 조사에 활용합니다.

UI에서 데이터를 탐색하거나 MCP 호환 에이전트를 연결할 수 있습니다. 두 워크플로 모두 동일한 텔레메트리를 사용합니다. SQL을 사용하면 시그널을 서로 연관시키고, 과거 동작을 비교하며, 미리 정의된 뷰(view)로는 답할 수 없는 질문까지 조사할 수 있습니다. 단, 애플리케이션을 계측하고 환경에서 텔레메트리를 수집하는 작업은 사용자가 직접 수행해야 합니다.

구성 요소 다이어그램과 자세한 내용은 [자가 관리형 아키텍처](/ko/clickstack/self-configured/architecture)를 참조하십시오.

## 사용자가 관리하는 항목 {#what-you-manage}

* **수집:** 수신기, 처리, 인증, ClickHouse Cloud와의 연결을 포함하여 [OpenTelemetry collector](/ko/clickstack/self-configured/ingesting-data/collector)를 배포하고 운영합니다.
* **스키마(schemas) 및 데이터 소스(data sources):** [테이블(tables)과 스키마(schemas)](/ko/clickstack/self-configured/ingesting-data/schemas)를 선택하고, 이를 쿼리할 수 있도록 UI의 [데이터 소스](/ko/clickstack/self-configured/managing/config)를 구성합니다.
* **용량 및 성능:** 워크로드 변화에 맞춰 [리소스를 추정](/ko/clickstack/self-configured/managing/estimating-resources)하고, 용량 산정 및 스케일링을 구성하며, [성능을 튜닝](/ko/clickstack/self-configured/managing/performance-tuning)합니다.
* **보존 기간:** [데이터 보존 정책](/ko/clickstack/self-configured/managing/ttl)을 설정하여 조사에 필요한 데이터와 스토리지 비용 간의 균형을 맞춥니다.

ClickHouse Cloud는 기반 인프라, 데이터베이스 업그레이드, 백업을 관리합니다. 다만 데이터베이스 튜닝과 용량 계획은 여전히 사용자의 책임입니다.

## 기능 {#features}

* [MCP](/ko/clickstack/observability/mcp)를 통해 자체 에이전트를 연결하여 텔레메트리 검색, 트레이스 추적, 패턴 및 변경 사항 분석, SQL 실행을 수행할 수 있습니다.
* 로그, 트레이스, 메트릭, 세션 다시 보기를 검색하고 서로 연관시킬 수 있습니다. 브라우저 상호작용부터 백엔드 서비스와 데이터베이스 쿼리까지 요청의 흐름을 추적할 수 있습니다.
* [전문 검색 및 Lucene 스타일 필터](/ko/clickstack/observability/features/search)(예: `level:err`) 또는 SQL을 사용하여 high-cardinality 텔레메트리 전반에서 검색과 집계(aggregations)를 실행할 수 있습니다. 로그와 트레이스 스팬의 JSON 필드 및 사용자 정의 속성도 쿼리할 수 있습니다.
* [AI 노트북](/ko/clickstack/observability/notebooks)으로 텔레메트리를 탐색하고, [자연어 질문으로 차트](/ko/clickstack/observability/text-to-chart)를 생성할 수 있습니다.
* [대시보드](/ko/clickstack/observability/features/dashboards/overview)를 구축하고, [알림](/ko/clickstack/observability/features/alerts)을 구성하며, [딥 링크](/ko/clickstack/observability/url-parameters)로 조사 화면을 공유할 수 있습니다.
* [이벤트 패턴](/ko/clickstack/observability/features/event-patterns)으로 반복되는 장애를 식별하고, [이벤트 차이](/ko/clickstack/observability/features/event-deltas)로 변경 사항을 조사하며, 새 이벤트가 들어오는 즉시 로그와 트레이스를 실시간으로 확인(live tail)할 수 있습니다.
* 직접 운영하는 collector를 통해 OpenTelemetry 데이터를 수집하고, 처리 방식, 테이블, 스키마(schemas), 보존 기간을 직접 제어할 수 있습니다.

## 원칙 {#principles}

### 기존 에이전트 활용 {#bring-your-own-agents}

팀에서 이미 사용 중인 에이전트와 개발 도구를 MCP로 연결하십시오. 에이전트는 UI와 동일한 데이터를 기반으로 로그를 검색하고, 트레이스를 따라가며, 패턴과 변경 사항을 식별할 수 있습니다. 또한 SQL을 실행하여 여러 근거를 연관시키고, 조사 도구로는 직접 다룰 수 없는 질문까지 탐색할 수 있습니다.

### 사용하기 쉬우면서도 특정 목적에 맞게 설계됨 {#user-friendly-purpose-built}

ClickStack UI는 검색, 트레이스 탐색, 차트, 대시보드, 알림을 하나로 통합합니다. 일상적인 질문은 Lucene 스타일 필터와 시각적 쿼리 빌더(query builder)로 해결하고, 분석을 더 세밀하게 제어해야 할 때는 SQL을 활용하십시오.

### 엔드투엔드 관측성 {#end-to-end-observability}

프론트엔드 세션 다시 보기를 애플리케이션 로그, 분산 트레이스, 메트릭과 연결하여 시스템 전반에서 발생하는 장애를 추적합니다. 와이드 이벤트는 요청 세부 정보, 사용자 정의 속성, 비즈니스 컨텍스트를 로그와 트레이스 스팬에 함께 담아 두므로, 엔지니어와 에이전트가 어떤 요청, 서비스, 고객이 영향을 받는지 쉽게 파악할 수 있습니다.

### ClickHouse 기반 설계 {#built-for-clickhouse}

ClickHouse의 열 지향 스토리지, 압축, 병렬 쿼리 실행(Query Execution) 덕분에 대량의 high-cardinality 텔레메트리 데이터에서도 빠른 검색과 집계(aggregations)가 가능합니다. 동시 쿼리를 지원하므로 엔지니어와 에이전트가 동일한 데이터를 병렬로 조사할 수 있습니다. 자가 관리형 배포에서는 워크로드에 맞게 스키마(schemas), 정렬 키(ordering key), 리소스를 조정할 수 있습니다.

### OpenTelemetry 네이티브 {#open-telemetry-native}

표준 OpenTelemetry instrumentation, SDK, collector를 사용하여 로그, 트레이스, 메트릭을 전송합니다. 수집 collector는 사용자가 직접 운영하며, ClickHouse에 쓰기 전에 텔레메트리를 처리하는 방식도 직접 구성합니다. 따라서 기존 instrumentation을 그대로 활용하면서 수집 파이프라인을 직접 제어할 수 있습니다.

## 시작하기 {#get-started}

[시작 가이드](/ko/clickstack/self-configured/getting-started/managed)에 따라 서비스를 설정하고 collector를 연결하십시오. 그런 다음 [샘플 데이터셋](/ko/clickstack/observability/example-datasets)을 사용하여 UI를 살펴보십시오. **자가 관리형** 지침이 제공되는 경우 해당 지침을 선택하십시오.

서비스를 운영 환경에서 사용하기 전에 [운영 환경 가이드](/ko/clickstack/self-configured/managing/production)와 [관리 개요](/ko/clickstack/self-configured/managing/overview)를 검토하십시오.
