## ClickHouse 핵심 개념 {#core-concepts}

대부분의 관리 작업을 수행하려면 기반이 되는 ClickHouse 데이터베이스를 잘 알고 있어야 합니다. 관리 또는 성능 관련 작업을 수행하기 전에 아래의 ClickHouse 핵심 개념을 먼저 살펴보시기를 권장합니다.

| 개념                                       | 설명                                                                                                                                              |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **테이블(Tables)**                          | 데이터 소스가 기반 ClickHouse 테이블에 매핑되는 방식입니다. ClickHouse 테이블은 주로 [`MergeTree`](/ko/reference/engines/table-engines/mergetree-family/mergetree) 엔진을 사용합니다. |
| **파트(Parts)**                            | 데이터가 변경 불가능한 파트로 기록되고 시간이 지남에 따라 머지되는 방식입니다.                                                                                                    |
| **파티션(Partitions)**                      | 데이터 관리, 쿼리 실행, 최적화를 단순화하는 테이블 파트(Table Parts)의 논리적 그룹입니다.                                                                                       |
| **머지(Merges)**                           | 파트를 결합하여 쿼리 대상 파트 수를 줄이고 성능을 유지하는 백그라운드 프로세스입니다.                                                                                                |
| **그래뉼(Granules)**                        | 쿼리 실행(Query Execution) 시 읽기 및 프루닝의 대상이 되는 가장 작은 데이터 단위입니다.                                                                                      |
| **프라이머리(정렬) 키(Primary (ordering) keys)** | `ORDER BY` 키가 on-disk 데이터 배치(data layout), 압축, 쿼리 프루닝 동작을 결정하는 방식입니다.                                                                           |

이러한 개념은 ClickHouse 성능의 근간이 되며, 자체 관리형 ClickHouse Observability를 운영할 때 충분한 정보를 바탕으로 관리 결정을 내리는 데 도움이 됩니다.
