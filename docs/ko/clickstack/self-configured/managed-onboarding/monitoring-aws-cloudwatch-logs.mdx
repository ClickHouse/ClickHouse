<Note>
  이 페이지에서는 **자체 관리형 ClickHouse Observability**를 다룹니다. 권장되는 완전 관리형 환경은 [여기](/ko/clickstack/observability/integration-examples/cloudwatch)의 문서를 참조하십시오.
</Note>

이 가이드에서는 OpenTelemetry [`awscloudwatch` 수신기](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver)를 사용하여 AWS CloudWatch 로그를 자체 관리형 ClickHouse Observability로 전달하고 ClickStack UI에서 확인하는 과정을 단계별로 설명합니다.

AWS API로 CloudWatch를 폴링하고 OTLP를 통해 이벤트를 ClickStack 수집기로 전달하는 별도의 collector를 실행합니다. API 지연 시간과 비용을 최소화하려면 이 collector를 로그 그룹과 동일한 AWS 계정 및 리전에서 실행하십시오.

이 가이드는 [OpenTelemetry Collector 설정](/ko/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector)을 완료하여 ClickStack 수집기가 실행 중인 상태를 전제로 합니다.

ClickStack 수집기는 **Docker 컨테이너**로 배포하거나([OpenTelemetry Collector 설정](/ko/clickstack/self-configured/managed-onboarding/setting-up-your-opentelemetry-collector) 참조), 업스트림 OpenTelemetry Helm 차트에 ClickStack 수집기 image를 사용하여 Kubernetes에 **Helm 릴리스**로 배포할 수 있습니다([collector 배포](/ko/clickstack/self-configured/ingesting-data/collector#configuring-the-collector-self-configured) 참조). **수집기의 OTLP 엔드포인트**와 배포 시 설정한 `OTLP_AUTH_TOKEN`을 **반드시 기록해 두십시오**.

<Steps>
  <Step title="사전 요구 사항 준비" id="gather-prerequisites">
    다음 항목이 필요합니다.

    * 하나 이상의 CloudWatch 로그 그룹이 있고, 아래 IAM 권한을 가진 자격 증명이 있는 **AWS 계정**
    * **Docker**가 설치되어 있고, AWS API에 액세스할 수 있으며, ClickStack 수집기로 아웃바운드 네트워크 연결이 가능한 호스트. 일반적으로 로그 그룹과 동일한 AWS 계정 및 리전에 있는 EC2 인스턴스를 사용합니다.
    * 이 호스트에서 연결할 수 있는 ClickStack 수집기의 **OTLP 엔드포인트**. 수집기가 같은 머신의 Docker에서 실행 중이라면 `http://host.docker.internal:4318`을 사용하십시오([CloudWatch 수신기 구성](#configure-receiver)의 강조 상자 참조). 원격 수집기라면 전체 URL을 사용하십시오(예: `https://otel.example.com:4318`).
    * ClickStack 수집기에 설정한 `OTLP_AUTH_TOKEN` 값. 수집기에 보안을 설정하지 않았다면 아래 구성에서 `authorization` 헤더를 삭제해도 됩니다.
  </Step>

  <Step title="AWS 자격 증명 구성" id="configure-aws">
    수신기는 표준 환경 변수에서 AWS 자격 증명을 읽어 옵니다. collector를 실행할 호스트에서 이 환경 변수들을 export하십시오.

    **AWS SSO 사용자:**

    ```shell
    aws sso login --profile YOUR_PROFILE_NAME
    eval $(aws configure export-credentials --profile YOUR_PROFILE_NAME --format env)
    aws sts get-caller-identity
    ```

    **장기 자격 증명을 사용하는 IAM 사용자:**

    ```shell
    export AWS_ACCESS_KEY_ID="your-access-key-id"
    export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
    export AWS_REGION="us-east-1"
    aws sts get-caller-identity
    ```

    CloudWatch 로그를 읽으려면 자격 증명에 다음 IAM 정책이 필요합니다.

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "CloudWatchLogsList",
          "Effect": "Allow",
          "Action": "logs:DescribeLogGroups",
          "Resource": "*"
        },
        {
          "Sid": "CloudWatchLogsRead",
          "Effect": "Allow",
          "Action": "logs:FilterLogEvents",
          "Resource": "arn:aws:logs:*:YOUR_ACCOUNT_ID:log-group:*"
        }
      ]
    }
    ```

    `YOUR_ACCOUNT_ID`를 사용 중인 AWS 계정 ID로 바꾸세요.

    <Info>
      **운영 환경 자격 증명**

      운영 환경에서는 장기 키 대신 인스턴스에 연결된 자격 증명을 사용하는 것이 좋습니다. EC2에서는 IAM role, EKS에서는 IRSA, ECS에서는 작업 역할(task role)을 사용하십시오. 수신기가 인스턴스 메타데이터 서비스에서 자격 증명을 가져올 수 있다면, 아래의 collector 구성은 자격 증명 관련 환경 변수 없이도 그대로 작동합니다.
    </Info>
  </Step>

  <Step title="CloudWatch 수신기 구성" id="configure-receiver">
    ClickStack 수집기 엔드포인트와 인증 토큰을 환경 변수로 내보낸 다음 `otel-collector-config.yaml`을 생성하십시오.

    <Info>
      **동일 호스트 구성**

      아래 예시는 ClickStack 수집기와 이 CloudWatch collector가 동일한 호스트에서 실행된다고 가정합니다. 따라서 수신기는 `host.docker.internal`(컨테이너 내부에서 접근하는 Docker 호스트의 주소)을 통해 ClickStack 수집기에 연결합니다. ClickStack 수집기가 다른 위치(클러스터 내 서비스, 퍼블릭 URL, 사설 IP)에 있다면 아래 `OTEL_COLLECTOR_ENDPOINT`에 해당 주소를 지정하십시오.
    </Info>

    ```shell
    export OTEL_COLLECTOR_ENDPOINT="http://host.docker.internal:4318"
    export OTLP_AUTH_TOKEN="a-strong-shared-secret"
    ```

    <Accordion title="계정에서 사용 가능한 로그 그룹 확인">
      구성을 편집하기 전에 해당 리전에 있는 로그 그룹 목록을 조회하여 실제 이름을 고르고, 리전이 올바른지도 함께 확인하십시오.

      ```shell
      aws logs describe-log-groups --region eu-central-1 \
        --query 'logGroups[].logGroupName' --output table
      ```

      출력 예시:

      ```text
      -------------------------------
      |      DescribeLogGroups      |
      +-----------------------------+
      |  /aws-glue/jobs/error       |
      |  /aws-glue/jobs/logs-v2     |
      |  /aws-glue/jobs/output      |
      |  /aws-glue/sessions/error   |
      |  /aws-glue/sessions/output  |
      +-----------------------------+
      ```

      이 목록에 있는 이름을 아래 예시 1의 `groups.named` 블록에 그대로 사용하십시오. 위 계정이라면 named 그룹 섹션은 다음과 같이 작성됩니다.

      ```yaml
      groups:
        named:
          /aws-glue/jobs/error:
          /aws-glue/jobs/logs-v2:
          /aws-glue/jobs/output:
          /aws-glue/sessions/error:
          /aws-glue/sessions/output:
      ```

      또는 수집하려는 그룹에 공통 접두사(여기서는 `/aws-glue/`)가 있다면, 그룹을 하나씩 나열하는 대신 예시 2에서 `prefix: /aws-glue/`를 사용하십시오.
    </Accordion>

    **예시 1: 이름으로 지정한 로그 그룹(권장)**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            named:
              /aws-glue/jobs/error:
              /aws-glue/jobs/output:
              /aws-glue/sessions/error:

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    **예시 2: 접두사로 로그 그룹 자동 발견**

    ```shell
    cat > otel-collector-config.yaml <<'EOF'
    receivers:
      awscloudwatch:
        region: eu-central-1
        logs:
          poll_interval: 1m
          max_events_per_request: 100
          groups:
            autodiscover:
              limit: 100
              prefix: /aws-glue/

    processors:
      batch:
        timeout: 10s

    exporters:
      otlphttp:
        endpoint: ${OTEL_COLLECTOR_ENDPOINT}
        headers:
          authorization: ${OTLP_AUTH_TOKEN}

    service:
      pipelines:
        logs:
          receivers: [awscloudwatch]
          processors: [batch]
          exporters: [otlphttp]
    EOF
    ```

    조정해야 할 주요 설정은 다음과 같습니다.

    * `region`: 로그 그룹이 위치한 리전과 일치하도록 설정합니다.
    * `poll_interval`(기본값 `1m`): 값을 낮추면 거의 실시간으로 로그를 수집할 수 있지만, 그만큼 AWS API 호출이 늘어납니다.
    * `groups.named`: 로그 그룹을 명시적으로 지정할 때 사용합니다. 특정 접두사와 일치하는 모든 그룹을 수집하려면 `groups.autodiscover.prefix`를 사용하십시오.

    전체 옵션 목록은 [CloudWatch 수신기 문서](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/awscloudwatchreceiver)를 참조하십시오.

    <Info>
      **최근 로그만 수집**

      최초 실행 시 수신기는 현재 시각을 체크포인트로 기록하고, 그 이후의 로그만 가져옵니다. 과거 로그는 백필되지 않습니다.
    </Info>
  </Step>

  <Step title="수신기 collector를 시작하십시오" id="start-collector">
    `otel-collector-config.yaml`과 같은 디렉터리에 `docker-compose.yaml`을 생성하십시오. `extra_hosts` 항목을 사용하면 컨테이너가 `host.docker.internal`을 통해 같은 호스트에서 실행 중인 ClickStack 수집기에 접근할 수 있습니다. 또한 긴 형식(long-form) 바인드 마운트를 사용하면 구성 파일이 없을 때 빈 디렉터리를 아무 경고 없이 생성하지 않고 명시적으로 오류를 발생시킵니다.

    ```shell
    cat > docker-compose.yaml <<'EOF'
    services:
      otel-collector:
        image: otel/opentelemetry-collector-contrib:latest
        command: ["--config=/etc/otel-config.yaml"]
        volumes:
          - type: bind
            source: ./otel-collector-config.yaml
            target: /etc/otel-config.yaml
            read_only: true
        environment:
          - AWS_ACCESS_KEY_ID
          - AWS_SECRET_ACCESS_KEY
          - AWS_SESSION_TOKEN
          - AWS_REGION
          - OTEL_COLLECTOR_ENDPOINT
          - OTLP_AUTH_TOKEN
        extra_hosts:
          - "host.docker.internal:host-gateway"
        restart: unless-stopped
    EOF
    ```

    collector를 시작하십시오:

    ```shell
    docker compose up -d
    ```

    로그를 실시간으로 확인하여 CloudWatch를 폴링하고 ClickStack 수집기로 데이터를 내보내고 있는지 확인하십시오:

    ```shell
    docker compose logs -f otel-collector
    ```
  </Step>

  <Step title="ClickStack UI에서 확인하십시오" id="confirm-in-ui">
    [ClickHouse Cloud 콘솔](https://console.clickhouse.cloud)에서 서비스를 열고 왼쪽 메뉴에서 **ClickStack**을 선택하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 실행](/images/use-cases/observability/clickstack-cloud-v2.webp)
      </Frame>
    </div>

    **검색** 뷰에서 소스를 `Logs`로 전환하고 시간 범위를 **Last 15 minutes**로 설정하십시오. 폴링 주기가 몇 차례 지나면 CloudWatch 이벤트가 표시됩니다.

    <div className="ch-image-lg">
      <Frame>
        ![CloudWatch 로그가 표시된 ClickStack 검색 뷰](/images/clickstack/cloudwatch/log-search-view-clickstack.webp)
      </Frame>
    </div>

    각 이벤트에는 소스 로그 그룹과 스트림이 리소스 속성으로 포함됩니다.

    * `ResourceAttributes['aws.region']`: AWS 리전(예: `eu-central-1`)
    * `ResourceAttributes['cloudwatch.log.group.name']`: 소스 로그 그룹
    * `ResourceAttributes['cloudwatch.log.stream']`: 소스 로그 스트림
    * `Body`: 원본 로그 행

    이러한 속성을 함께 표시하려면 검색을 `Timestamp, SeverityText as level, ResourceAttributes['aws.region'], ResourceAttributes['cloudwatch.log.group.name'], ResourceAttributes['cloudwatch.log.stream'], Body`로 수정하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![CloudWatch 로그와 속성이 표시된 ClickStack 검색 뷰](/images/clickstack/cloudwatch/log-search-attributes-clickstack.webp)
      </Frame>
    </div>

    로그 항목을 선택하면 메타데이터를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![로그 상세 보기의 CloudWatch 속성](/images/clickstack/cloudwatch/error-log-column-values-clickstack.webp)
      </Frame>
    </div>

    아무것도 표시되지 않으면 다음을 확인하십시오.

    * collector 호스트에서 `aws sts get-caller-identity`를 실행하여 자격 증명이 유효한지 확인하십시오.
    * `docker compose logs -f otel-collector`로 collector 로그를 실시간으로 확인하면서 `AccessDeniedException`(IAM), `security token` 오류(SSO 자격 증명 만료), `ResourceNotFoundException`(로그 그룹 이름 오타 또는 잘못된 리전), `connection refused`(컨테이너 내부에서 ClickStack 수집기 엔드포인트에 연결할 수 없음. [CloudWatch 수신기 구성](#configure-receiver)의 `host.docker.internal` 참고 사항 참조)가 있는지 살펴보십시오.
    * 컨테이너 내부에서 `OTEL_COLLECTOR_ENDPOINT`에 연결할 수 있는지 확인하십시오: `docker compose exec otel-collector wget -qO- ${OTEL_COLLECTOR_ENDPOINT}/v1/logs -S 2>&1 | head -5`.
    * `OTLP_AUTH_TOKEN`이 ClickStack 수집기에 설정된 값과 일치하는지 확인하십시오.
  </Step>

  <Step title="추가 참고 자료" id="further-reading">
    * 데모 데이터셋, 전체 문제 해결 방법 및 튜닝 옵션은 [AWS CloudWatch Logs 통합 참고 문서](/ko/clickstack/observability/integration-examples/cloudwatch#self-managed)를 참조하십시오.
    * OTLP 엔드포인트에 TLS를 적용하고 최소 권한(privilege)만 부여된 수집 사용자를 사용하여 [collector를 보호](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)하십시오.
    * collector에서 이벤트를 [처리, 필터링하고 정보를 보강](/ko/clickstack/self-configured/ingesting-data/collector#processing-filtering-transforming-enriching-self-configured)하는 방법을 확인하십시오.
    * 운영 환경으로 전환할 때의 권장 사항은 [프로덕션 환경으로 전환](/ko/clickstack/self-configured/managing/production)을 참조하십시오.
  </Step>
