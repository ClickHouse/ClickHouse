<Note>
  이 페이지는 **자체 관리형 ClickHouse Observability**를 다룹니다. 권장되는 완전 관리형 환경은 [여기](/ko/clickstack/observability/getting-started)의 문서를 참조하십시오.
</Note>

이 가이드에서는 비어 있는 자체 관리형 ClickHouse Observability 서비스에서 시작하여, 실제 애플리케이션의 로그, 메트릭, trace, 세션 다시 보기가 유입되는 단계까지 진행합니다. 서비스에 연결할 새 OpenTelemetry collector를 배포하고(기존 collector가 있다면 이를 조정하여 사용할 수도 있습니다), 비즈니스 로직을 변경하지 않고 샘플 Node.js 애플리케이션을 계측한 다음, ClickStack UI에서 텔레메트리를 탐색합니다.

<Note>
  새 collector를 설정하든 기존 collector를 사용하든, collector는 **gateway**로 실행해야 합니다. 즉, 애플리케이션, SDK, 에이전트 collector가 데이터를 전송하는 단일 OTLP 엔드포인트 역할을 해야 합니다. gateway는 이벤트를 배치로 묶고, 구성된 처리를 적용한 후 [ClickHouse 익스포터](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter)를 통해 ClickHouse에 기록합니다.
</Note>

계측할 애플리케이션은 [HackerNews Analyzer](https://github.com/ClickHouse/hn-news-analyzer)로, 퍼블릭 ClickHouse 데모에 호스팅된 HackerNews 데이터셋을 쿼리하는 Node.js 앱입니다. 모든 차트, 테이블, 검색 상자는 실제 ClickHouse 쿼리(Query)로 동작하므로, 모든 상호작용마다 백엔드에서 ClickHouse로 보내는 HTTPS 호출을 주 스팬으로 하는 트레이스가 생성됩니다.

## 사전 요구 사항 {#prerequisites}

* [ClickHouse Cloud](https://console.clickhouse.cloud)의 **자체 관리형 ClickHouse Observability 서비스**
* 샘플 애플리케이션 실행에 필요한 **Node 18 이상 및 npm**
* **Docker**: 기존 collector가 없어 아래의 새 collector 설정 절차를 따르려는 경우에 필요합니다.

    사용 환경에 맞는 옵션을 선택하십시오.

    <Info>
      **기존 collector**

      기존 OpenTelemetry collector를 사용하는 경우 해당 collector가 이미 **gateway** 역할로 구성되어 있다고 가정합니다. **에이전트** 역할로 동작하는 collector를 재구성할 때는 이 절차를 사용하지 않는 것이 좋습니다.

    <Tabs>
      <Tab title="collector가 없습니다">
        자체 관리형 ClickHouse Observability용으로 사전 구성된 **ClickStack 배포판 OpenTelemetry collector**를 배포하십시오. 아래 예시에서는 편의상 collector를 로컬에서 실행합니다.

        <Note>
          운영 환경에서는 일반적으로 collector를 Kubernetes 클러스터에 배포하거나, OpenTelemetry SDK, 에이전트 및 다른 collector가 접근할 수 있는 가상 머신에 배포합니다. 이렇게 하면 환경 전반의 텔레메트리를 중앙에서 수집하여 ClickStack으로 전달할 수 있습니다.
        </Note>

        collector로 데이터를 전송하는 클라이언트를 인증할 공유 비밀을 정한 다음, 연결 정보 및 `hyperdx_ingest` 사용자용으로 정한 비밀번호와 함께 환경 변수로 내보내십시오:

        ```shell
        export CLICKHOUSE_ENDPOINT=<HTTPS_ENDPOINT>
        export CLICKHOUSE_USER=hyperdx_ingest
        export CLICKHOUSE_PASSWORD=ClickH0u3eRocks123!
        export OTLP_AUTH_TOKEN="a-strong-shared-secret"
        ```

        ClickStack OTel 수집기를 실행하십시오.

        ```shell
        docker run -d \
          -e OTLP_AUTH_TOKEN=${OTLP_AUTH_TOKEN} \
          -e CLICKHOUSE_ENDPOINT=${CLICKHOUSE_ENDPOINT} \
          -e CLICKHOUSE_USER=${CLICKHOUSE_USER} \
          -e CLICKHOUSE_PASSWORD=${CLICKHOUSE_PASSWORD} \
          -e HYPERDX_OTEL_EXPORTER_CLICKHOUSE_DATABASE=otel \
          -p 4317:4317 \
          -p 4318:4318 \
          clickhouse/clickstack-otel-collector:latest
        ```

        이제 collector는 `4317` 포트에서 OTLP gRPC를, `4318` 포트에서 OTLP HTTP를 노출합니다. 애플리케이션, SDK, 에이전트 collector는 요청 헤더에 `authorization: $OTLP_AUTH_TOKEN`을 포함하여 이 포트로 데이터를 전송해야 합니다. 다음 단계에서 애플리케이션이 OTLP 엔드포인트와 `OTLP_AUTH_TOKEN`을 사용하도록 설정하므로, 두 값을 미리 준비해 두십시오.

        <Info>
          **운영 환경 배포**

          운영 환경에서는 OTLP 엔드포인트에 TLS를 활성화하는 것을 권장합니다. 자세한 내용은 [collector 보안 설정](/ko/clickstack/self-configured/ingesting-data/collector#securing-the-collector-self-configured)을 참조하십시오.
        </Info>
      </Tab>

      <Tab title="collector가 있습니다">
        기존 수집기 설정을 확장하여 [ClickHouse 익스포터](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/exporter/clickhouseexporter)를 통해 자체 관리형 ClickHouse Observability로 데이터를 쓰도록 구성하십시오.

        <Info>
          **ClickHouse 익스포터 필요**

          자체 배포판을 사용하는 경우 ClickHouse 익스포터가 포함되어 있는지 확인하십시오. 업스트림 [contrib image](https://github.com/open-telemetry/opentelemetry-collector-contrib)에는 이미 포함되어 있습니다.
        </Info>

        다음은 ClickStack UI에서 요구하는 수신기, 프로세서, 파이프라인과 함께 ClickHouse 익스포터를 사용하는 구성 예시입니다. 이 구성은 세션 리플레이(`rrweb`) 라우팅 경로를 포함하여 ClickStack 배포판과 동일하게 동작합니다. `<clickhouse_cloud_endpoint>`와 `<your_password_here>`를 앞서 생성한 `hyperdx_ingest` 사용자의 자격 증명으로 바꾸십시오.

        ```yaml
        receivers:
          otlp/hyperdx:
            protocols:
              grpc:
                include_metadata: true
                endpoint: "0.0.0.0:4317"
              http:
                cors:
                  allowed_origins: ["*"]
                  allowed_headers: ["*"]
                include_metadata: true
                endpoint: "0.0.0.0:4318"

        processors:
          batch:
          memory_limiter:
            # 80% of maximum memory up to 2G, adjust for low memory environments
            limit_mib: 1500
            # 25% of limit up to 2G, adjust for low memory environments
            spike_limit_mib: 512
            check_interval: 5s

        connectors:
          routing/logs:
            default_pipelines: [logs/out-default]
            error_mode: ignore
            table:
              - context: log
                statement: route() where IsMatch(attributes["rr-web.event"], ".*")
                pipelines: [logs/out-rrweb]

        exporters:
          clickhouse:
            database: otel
            endpoint: <clickhouse_cloud_endpoint>
            username: hyperdx_ingest
            password: <your_password_here>
            ttl: 720h
            timeout: 5s
            retry_on_failure:
              enabled: true
              initial_interval: 5s
              max_interval: 30s
              max_elapsed_time: 300s
          clickhouse/rrweb:
            database: otel
            endpoint: <clickhouse_cloud_endpoint>
            username: hyperdx_ingest
            password: <your_password_here>
            ttl: 720h
            logs_table_name: hyperdx_sessions
            timeout: 5s
            retry_on_failure:
              enabled: true
              initial_interval: 5s
              max_interval: 30s
              max_elapsed_time: 300s

        service:
          pipelines:
            traces:
              receivers: [otlp/hyperdx]
              processors: [memory_limiter, batch]
              exporters: [clickhouse]
            metrics:
              receivers: [otlp/hyperdx]
              processors: [memory_limiter, batch]
              exporters: [clickhouse]
            logs/in:
              receivers: [otlp/hyperdx]
              exporters: [routing/logs]
            logs/out-default:
              receivers: [routing/logs]
              processors: [memory_limiter, batch]
              exporters: [clickhouse]
            logs/out-rrweb:
              receivers: [routing/logs]
              processors: [memory_limiter, batch]
              exporters: [clickhouse/rrweb]
        ```

        몇 가지 참고 사항은 다음과 같습니다.

        * `otlp/hyperdx` 수신기는 gRPC(`4317`)와 HTTP(`4318`)에서 모두 수신 대기합니다. 애플리케이션과 에이전트는 collector 호스트의 이 포트로 데이터를 전송하도록 설정해야 합니다.
        * `clickhouse` 익스포터는 로그, 트레이스, 메트릭을 ClickStack UI가 요구하는 레이아웃에 맞춰 `otel` 데이터베이스에 기록합니다. `clickhouse/rrweb` 익스포터는 `routing/logs` 커넥터가 `otel.hyperdx_sessions`로 라우팅한 세션 리플레이(Session Replay) 이벤트를 처리합니다.
        * OTLP 수신기의 인증은 기존 환경 설정을 따릅니다. 수집 토큰을 요구해야 하는 경우 collector [확장 기능](https://opentelemetry.io/docs/collector/configuration/#extensions)(예: `bearertokenauth`)이나 앞단에서 TLS를 처리하는 리버스 프록시를 통해 구성하십시오.

        새 구성으로 collector를 다시 로드하십시오. 다음 단계에서 애플리케이션이 OTLP 엔드포인트와 인증 헤더를 사용하도록 설정하므로, 해당 엔드포인트와 설정에서 요구하는 인증 헤더를 미리 준비해 두십시오.

        자체 관리형 ClickHouse Observability용 OpenTelemetry 수집기 구성에 대한 자세한 내용은 [OpenTelemetry를 사용한 데이터 수집](/ko/clickstack/observability/ingesting-data/opentelemetry#self-managed)을 참조하십시오.
      </Tab>
    </Tabs>
  </Step>

  <Step title="애플리케이션 복제 및 실행" id="clone-and-run-the-application">
    리포지토리를 클론하고 의존성을 설치한 다음 `.env` 파일을 생성하세요.

    ```bash
    git clone https://github.com/ClickHouse/hn-news-analyzer.git
    cd hn-news-analyzer
    npm install
    cp .env.example .env
    ```

    ClickHouse 데이터 소스(data source)는 기본적으로 퍼블릭 읽기 전용 데모 클러스터를 사용하므로, 별도의 구성 없이 앱을 실행할 수 있습니다. 다음 명령으로 앱을 시작하세요:

    ```bash
    ./run.sh
    ```

    [http://localhost:5001](http://localhost:5001)을 여십시오. 연도 선택기, 요약 통계, 활동 차트, 상위 사용자 및 도메인 테이블, 검색 상자가 표시됩니다. 연도를 바꾸거나 스토리를 자세히 살펴보는 등 자유롭게 클릭해 보십시오.

    <div className="ch-image-lg">
      <Frame>
        ![로컬에서 실행 중인 HackerNews Analyzer 애플리케이션](/images/clickstack/getting-started/hackernews_main.webp)
      </Frame>
    </div>

    현재 애플리케이션은 실행 중이지만 아직 계측되지 않은 상태입니다. ClickStack은 텔레메트리 수신을 기다리고 있으므로 아직 아무 데이터도 표시하지 않습니다. 이것이 계측 &quot;이전&quot; 상태입니다.
  </Step>

  <Step title="애플리케이션을 collector에 연결하십시오" id="connect-the-application">
    애플리케이션이 앞에서 배포한 collector에 연결하려면 다음 두 가지 값이 필요합니다.

    * `OTEL_EXPORTER_OTLP_ENDPOINT`: collector가 노출하는 OTLP 엔드포인트입니다(HTTPS를 통한 OTLP는 일반적으로 포트 `4318` 사용).
    * `OTEL_EXPORTER_OTLP_HEADERS`: 수집 토큰을 담은 인증 헤더이며, `authorization=<ingestion_token>` 형식입니다. 앞에서 collector에 설정한 `OTLP_AUTH_TOKEN`을 사용하거나, 기존 collector에서 요구하는 인증 헤더를 사용하십시오.

    `.env.example`을 `.env`로 복사한 다음 파일을 열어 다음 변수를 설정하십시오.

    ```bash
    OTEL_SERVICE_NAME=hn-analyzer-api
    OTEL_EXPORTER_OTLP_ENDPOINT=https://<your-collector-endpoint>:4318
    OTEL_EXPORTER_OTLP_HEADERS=authorization=<ingestion_token>
    ```

    SDK는 `OTEL_EXPORTER_OTLP_HEADERS`를 사용하여 트레이스, 메트릭, 로그의 세 가지 시그널 모두에 대한 인증 헤더를 설정합니다. collector가 로컬에서 실행되고 인증을 요구하지 않는다면 값을 비워 둘 수 있지만(`OTEL_EXPORTER_OTLP_HEADERS=authorization=`), 변수 자체는 반드시 정의되어 있어야 합니다. 이 변수가 설정되지 않았거나 완전히 비어 있으면 SDK는 초기화를 아예 건너뜁니다. 마지막으로, TLS 미사용 상태로 collector를 실행할 때는 올바른 HTTP 프로토콜을 사용해야 합니다(예: `http://localhost:4318`).
  </Step>

  <Step title="애플리케이션을 계측하십시오" id="instrument-the-application">
    계측(instrumentation)은 SDK 설치, 실행 명령 변경, 브라우저 SDK 활성화의 세 단계로 이루어집니다. 이 과정에서 애플리케이션의 비즈니스 로직은 전혀 변경되지 않습니다.

### SDK 설치 {#install-sdks}

    백엔드용과 브라우저용 OpenTelemetry SDK를 모두 설치하십시오.

    ```bash
    npm install @hyperdx/node-opentelemetry @hyperdx/browser
    ```

### opentelemetry-instrument CLI 사용 {#use-open-telemetry-cli}

    애플리케이션은 `run.sh`로 실행되며, 이 파일 하단에는 `exec` 줄 2개가 있습니다. 하나는 활성화되어 있고 다른 하나는 주석 처리되어 있습니다. Node가 `opentelemetry-instrument`로 래핑되도록 두 줄의 활성 상태를 서로 바꾸십시오:

    ```diff
     # BEFORE: plain node, no instrumentation, collector stays silent:
    -exec node scripts/entrypoint.js
    +# exec node scripts/entrypoint.js

     # AFTER: same source, wrapped by opentelemetry-instrument CLI.
    -# exec npx opentelemetry-instrument scripts/entrypoint.js
    +exec npx opentelemetry-instrument scripts/entrypoint.js
    ```

    백엔드 변경 사항은 이것이 전부입니다. auto-instrumentation은 프로세스가 시작될 때 `opentelemetry-instrument`가 로드합니다.

### 브라우저 SDK 활성화 {#enable-browser-sdk}

    분산 트레이스(브라우저에서 백엔드까지)와 세션 다시 보기를 수집하려면 `src/web/telemetry.ts`에서 브라우저 SDK를 활성화하십시오. import 구문과 `HyperDX.init({...})` 블록의 주석을 해제하십시오.

    ```javascript
    import HyperDX from '@hyperdx/browser';

    export function initTelemetry(): void {
      HyperDX.init({
        url: __OTLP_ENDPOINT__,
        apiKey: __OTLP_AUTH_TOKEN__,
        service: 'hn-analyzer-web',
        tracePropagationTargets: [/localhost:5001/i, /\/api\//i],
        consoleCapture: true,
        advancedNetworkCapture: true,
      });
    }
    ```

    `.env`를 추가로 수정할 필요는 없습니다. `__OTLP_ENDPOINT__`와 `__OTLP_AUTH_TOKEN__`은 `vite.config.ts`가 주입하는 컴파일 타임 상수입니다. 엔드포인트는 `OTEL_EXPORTER_OTLP_ENDPOINT` 값을 사용하고, 토큰은 `OTEL_EXPORTER_OTLP_HEADERS`에서 파싱하여 가져오며, 둘 다 백엔드가 사용하는 값과 동일합니다.

    <Warning>
      수집 토큰은 퍼블릭 브라우저 번들에 그대로 포함되므로, 네트워크 탭을 살펴보면 누구나 확인할 수 있습니다.
    </Warning>
  </Step>

  <Step title="트래픽 생성" id="generate-traffic">
    새 실행 명령과 새로 빌드한 브라우저 번들이 적용되도록 애플리케이션을 재시작하십시오.

    ```bash
    # Ctrl-C the previous run, then:
    ./run.sh
    ```

    Vite가 업데이트된 번들을 제공하도록 브라우저 탭을 다시 로드한 다음, 앱을 몇 차례 새로 고치고 연도를 바꿔 보거나 스토리를 클릭해 트래픽을 발생시키십시오. 상호 작용이 일어날 때마다 로그, 메트릭, 트레이스, 세션 리플레이 이벤트가 collector를 거쳐 ClickStack으로 전송됩니다.
  </Step>

  <Step title="ClickStack을 실행하고 텔레메트리를 탐색하세요" id="launch-clickstack">
    [ClickHouse Cloud 콘솔](https://console.clickhouse.cloud)에서 서비스를 열고 왼쪽 메뉴에서 **ClickStack**을 선택한 다음 **Start Ingestion**을 클릭하세요.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 실행](/images/use-cases/observability/clickstack-cloud-first-time.webp)
      </Frame>
    </div>

    collector는 이미 구성했으므로 다음 단계는 건너뛰어도 됩니다. **Launch ClickStack**을 클릭하여 계속 진행하세요.

    ClickStack이 새 탭에서 열리고 **Getting Started** 페이지로 자동 이동합니다. 자동으로 이동하지 않으면 왼쪽 메뉴에서 **Getting Started**를 선택한 다음 **Start Ingestion**, **Next**를 차례로 클릭하세요.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 수집 시작](/images/use-cases/observability/clickstack-start-ingestion.webp)
      </Frame>
    </div>

    ClickStack이 테이블(tables)과 텔레메트리 데이터를 자동으로 감지하므로 바로 다음 단계로 진행할 수 있습니다. **Start Exploring**을 선택하여 데이터 탐색을 시작하세요.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 탐색 시작](/images/use-cases/observability/clickstack-start-exploring.webp)
      </Frame>
    </div>

    이제 애플리케이션이 생성하는 데이터를 확인해 보겠습니다.

    1. **Search**로 이동하여 최근 5분으로 필터링하세요. `hn-analyzer-api`의 로그가 실시간으로 표시됩니다.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 로그](/images/clickstack/getting-started/instrument_app_clickstack_logs.webp)
      </Frame>
    </div>

    2. 요청을 클릭한 후 트레이스를 상위로 따라가 보세요. Express 핸들러 스팬, 실제 네트워크 소요 시간이 기록된 ClickHouse 클러스터 대상 하위 HTTP 스팬, 그리고 같은 트레이스에 상호 연관된 `console.log` 레코드를 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 트레이스](/images/clickstack/getting-started/instrument_app_clickstack_traces.webp)
      </Frame>
    </div>

    3. **Session Replay**를 열면 트레이스 타임라인과 동기화된 브라우저 세션 영상을 재생하면서 원하는 지점으로 자유롭게 이동할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack 세션](/images/clickstack/getting-started/instrument_app_clickstack_sessions.webp)
      </Frame>
    </div>

    로그, 메트릭, 트레이스, 세션 다시 보기가 모두 하나의 UI에 모이고, 동일한 쿼리 언어(query language)를 사용하며, 자동으로 상호 연관됩니다.

    아무것도 표시되지 않는 경우:

    * `OTEL_EXPORTER_OTLP_HEADERS`에 설정한 인증 헤더 값이 collector에서 요구하는 값과 일치하는지 확인하세요.
    * collector 로그를 tail로 확인하면서 내보내기 오류가 있는지 살펴보세요.
    * collector에 구성된 ClickHouse 엔드포인트에 프로토콜과 포트(`https://...:8443`)가 모두 포함되어 있는지 확인하세요.
  </Step>
