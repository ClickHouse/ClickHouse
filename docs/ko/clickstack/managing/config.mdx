ClickStack의 각 구성 요소에 대해 다음 구성 옵션을 사용할 수 있습니다:

<div id="modifying-settings">
  ## 오픈 소스 배포판 설정 {#modifying-settings}
</div>

### Docker {#docker}

[All in One](/ko/clickstack/deployment/all-in-one), [ClickStack UI only](/ko/clickstack/deployment/hyperdx-only) 또는 [Local Mode](/ko/clickstack/deployment/local-mode-only)를 사용하는 경우에는 예를 들어 환경 변수를 통해 원하는 설정을 전달하십시오.

```shell
docker run -e HYPERDX_APP_PORT=8081 -p 8081:8081 -p 4317:4317 -p 4318:4318 clickhouse/clickstack-all-in-one:latest
```

### Docker Compose {#docker-compose}

[Docker Compose](/ko/clickstack/deployment/docker-compose) 배포 가이드를 사용하는 경우 [`.env`](https://github.com/ClickHouse/clickstack/blob/main/.env) 파일로 설정을 변경할 수 있습니다.

또는 [`docker-compose.yml`](https://github.com/ClickHouse/clickstack/blob/main/docker-compose.yml) 파일에서 설정을 직접 덮어쓸 수 있습니다. 예를 들면 다음과 같습니다.

예시:

```yaml
services:
  app:
    environment:
      HYPERDX_API_KEY: ${HYPERDX_API_KEY}
      HYPERDX_LOG_LEVEL: ${HYPERDX_LOG_LEVEL}
      # ... other settings
```

### Helm {#helm}

[Helm 배포 가이드](/ko/clickstack/deployment/helm)를 참고하여 오퍼레이터와 ClickStack 차트를 설치하십시오. 배포를 사용자 정의하기 전에 현재 차트의 설정값을 먼저 가져오십시오.

```shell
helm show values clickstack/clickstack > values.yaml
```

차트의 설정값으로 애플리케이션 환경과 collector 환경을 각각 설정한 후 구성을 적용하십시오:

```shell
helm upgrade --install my-clickstack clickstack/clickstack -f values.yaml
```

지원되는 설정값, 인그레스, 리소스, 시크릿 구성은 [Helm 구성](/ko/clickstack/deployment/helm-configuration)을 참조하십시오. 이전 `hyperdx/hdx-oss-v2` 차트는 설정값 구조가 다릅니다.

### 연결 {#connection-settings}

팀 설정에서 소스가 사용하는 데이터베이스 연결(database connection)을 구성하십시오.

| 설정                         | 설명                                                                                                                                                                                                                                                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Connection Name`          | 소스 설정에서 이 연결을 식별하는 데 사용하는 이름입니다.                                                                                                                                                                                                                                                                          |
| `Host`                     | 포트를 포함한 ClickHouse HTTP(S) 엔드포인트입니다. collector의 내보내기 엔드포인트와는 별개입니다.                                                                                                                                                                                                                                       |
| `Username`                 | ClickHouse 사용자 이름입니다. 기본값은 `default`입니다.                                                                                                                                                                                                                                                                  |
| `Password`                 | ClickHouse 비밀번호입니다. 기본값은 빈 값입니다.                                                                                                                                                                                                                                                                          |
| `Query Log Setting Prefix` | 현재 사용자의 이메일을 쿼리 로그(query logs)에 기록하는 사용자 정의 ClickHouse 설정의 접두사입니다(선택 사항). ClickHouse의 `custom_settings_prefixes` 구성에도 동일한 접두사를 포함해야 하며, 그렇지 않으면 쿼리가 거부됩니다. 사용자 식별자 없이 어떤 대시보드, 알림 또는 기타 ClickStack 기능이 쿼리를 실행했는지 확인하려면 [쿼리 부하의 원인 찾기](/ko/clickstack/managing/performance-tuning#query-attribution)를 참조하십시오. |
| `Prometheus compatible`    | 사용 가능한 경우 Host를 PromQL 쿼리 프록시용 Prometheus 호환 API 엔드포인트로 취급합니다. 이 연결은 ClickHouse 기반 로그, 트레이스 또는 OTel 메트릭 소스에는 사용할 수 없습니다.                                                                                                                                                                                  |

<div id="datasource-settings">
  ### 데이터 소스 설정 {#datasource-settings}
</div>

ClickStack UI에서는 각 관측성 데이터 타입/축에 대해 사용자가 소스를 정의해야 합니다:

* `Logs`
* `Traces`
* `Metrics`
* `Sessions`

이 구성은 애플리케이션의 `Team Settings -> Sources`에서 수행할 수 있으며, 아래는 로그에 대한 예시입니다:

<div className="ch-image-md">
  <Frame>
    ![ClickStack UI 소스 구성](/images/use-cases/observability/hyperdx-25.webp)
  </Frame>
</div>

ClickStack UI가 데이터를 쿼리할 수 있도록 각 소스에는 테이블 및 컬럼 매핑이 필요합니다. 메트릭 소스는 메트릭 유형별로 별도의 테이블을 사용할 수 있습니다. `Enabled` 토글은 기존 소스를 편집할 때 표시되며, 소스 수준의 `Query Settings`에는 이름/값 쌍을 최대 10개까지 지정할 수 있습니다.

ClickStack과 함께 제공되는 [기본 OpenTelemetry (OTel) 스키마](/ko/guides/use-cases/observability/build-your-own/integrating-opentelemetry#out-of-the-box-schema)를 사용하는 경우, 이러한 컬럼은 각 소스별로 자동 추론할 수 있습니다. [스키마를 수정](#clickhouse)하거나 사용자 지정 스키마를 사용하는 경우에는 이러한 매핑을 직접 지정하고 업데이트해야 합니다.

<Note>
  collector는 [스키마 구성](#collector-schema-and-retention)에 따라 스키마 마이그레이션(schema migration) 또는 레거시 방식인 익스포터 관리형 스키마 생성을 통해 테이블을 생성합니다. 컬럼 매핑은 [로그 데이터 모델](https://opentelemetry.io/docs/specs/otel/logs/data-model/)을 포함한 OpenTelemetry 규약을 따릅니다.
</Note>

각 소스에 대해 다음 설정을 사용할 수 있습니다:

<div id="materialized-views-settings">
  #### Materialized views {#materialized-views-settings}
</div>

Materialized view를 Log 및 Trace 데이터 소스에 등록하면, 조건에 맞는 집계 쿼리는 원본 테이블이 아닌 사전 집계된 뷰에서 결과를 가져옵니다. 뷰 생성 및 등록 방법은 [&quot;Materialized views&quot;](/ko/clickstack/managing/materialized-views)를 참조하십시오.

등록된 각 뷰에는 다음 설정을 지정합니다.

| 설정                       | 설명                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Database`               | materialized view의 대상 테이블이 포함된 ClickHouse 데이터베이스입니다.                                                                                                   |
| `Table`                  | 뷰 자체가 아닌 materialized view의 대상 테이블입니다.                                                                                                                 |
| `타임스탬프 컬럼`       | 대상 테이블의 timestamp 컬럼입니다.                                                                                                                               |
| `Granularity`            | 대상 테이블 timestamp 컬럼의 시간 버킷입니다(예: `1 minute`). 쿼리의 시간 버킷이 이 값과 같거나 더 큰 경우에만 뷰를 사용할 수 있습니다.                                                              |
| `Minimum Date`           | 선택 사항입니다. 뷰에 데이터가 포함된 가장 이른 날짜와 시간입니다. 지정하지 않으면 ClickStack은 원본 테이블에 데이터가 있는 모든 날짜에 대해 뷰에도 데이터가 있다고 가정합니다.                                              |
| `Dimension Columns`      | 뷰에서 사전 집계되지 않으므로 필터링 및 그룹화에 사용할 수 있는 컬럼의 쉼표로 구분된 목록입니다.                                                                                                |
| `Pre-aggregated Columns` | 뷰에서 사전 집계된 컬럼입니다. 각 항목은 집계 함수(`avg`, `count`, `max`, `min`, `quantile`, `sum` 또는 `histogram`)와 원본 테이블 컬럼을 뷰의 해당 컬럼에 매핑합니다. `count`에는 원본 컬럼이 필요하지 않습니다. |

이러한 설정 대부분은 대상 테이블을 선택하면 뷰의 스키마에서 자동으로 추론됩니다.

메타데이터 materialized view는 필터 및 자동 완성을 위한 필드 디스커버리를 가속합니다. Log 및 Trace 데이터 소스에 구성할 수 있습니다.

| 설정                 | 설명                                                 |
| ------------------ | -------------------------------------------------- |
| `Key Rollup Table` | 선택 사항이며 더 이상 사용되지 않습니다. 원본 테이블에 있는 key의 롤업 테이블입니다. |

| `Granularity`      | 롤업 테이블에서 사용하는 시간 버킷입니다. 예: `15 minute`.            |

#### 강조 속성 {#highlighted-attributes}

강조 속성과 강조 트레이스 속성은 Log 및 트레이스 데이터 소스에서 구성할 수 있습니다.

* 강조 속성은 로그 또는 스팬 세부 정보를 볼 때 각 로그 또는 스팬에 표시되는 컬럼 또는 표현식입니다.
* 강조 트레이스 속성은 트레이스 내 각 로그 또는 스팬에서 조회되어 트레이스 워터폴 위에 표시되는 컬럼 또는 표현식입니다.

이러한 속성은 소스 구성에서 정의되며, 임의의 SQL 표현식으로 지정할 수 있습니다. SQL 표현식이 URL 포맷의 값을 반환하면 해당 속성은 링크로 표시됩니다. 빈 값은 표시되지 않습니다.

각 속성은 다음 설정으로 구성됩니다.

| 설정                  | 설명                                                  |
| ------------------- | --------------------------------------------------- |
| `SQL Expression`    | 조회할 컬럼 또는 임의의 SQL 표현식입니다. 필수입니다.                    |
| `Alias`             | 선택 사항입니다. SQL 표현식 대신 속성에 표시되는 레이블입니다.               |
| `Lucene Expression` | 선택 사항입니다. 이 속성 값을 검색할 때 사용하는 SQL 표현식의 Lucene 버전입니다. |

예를 들어, 이 트레이스 소스는 강조 속성과 강조 트레이스 속성으로 구성되어 있습니다.

### 상관관계 소스 {#correlated-sources}

ClickStack에서 소스 간 전체 상호 연관을 사용하려면 로그, 트레이스, 메트릭, 세션에 대한 상관관계 소스를 구성해야 합니다. 그러면 ClickStack UI가 관련 데이터를 서로 연관시키고 이벤트를 렌더링할 때 더 풍부한 맥락을 제공할 수 있습니다.

* `Logs`: 트레이스 및 메트릭과 연관시킬 수 있습니다.
* `Traces`: 로그, 세션 및 메트릭과 연관시킬 수 있습니다.
* `Metrics`: 로그와 연관시킬 수 있습니다.
* `Sessions`: 트레이스와 연관시킬 수 있습니다.

이러한 연관 관계를 설정하면 여러 기능을 활용할 수 있습니다. 예를 들어 ClickStack UI는 트레이스와 함께 관련 로그를 렌더링하거나 세션과 연결된 메트릭 이상 징후를 표시할 수 있습니다.

### ClickHouse 클라이언트 설정 {#clickhouse-client-settings}

팀 설정의 **ClickHouse 클라이언트 설정** 섹션에서는 팀의 쿼리 동작을 제어합니다.

| 설정                                  | 기본값       | 설명                                                             |
| ----------------------------------- | --------- | -------------------------------------------------------------- |
| `Search Row Limit`                  | `200`     | 검색 페이지와 검색 대시보드 타일에서 쿼리당 반환되는 행 수입니다. 범위: 1–100,000.           |
| `Query Timeout (seconds)`           | `60`      | 쿼리의 최대 실행 시간입니다. `0`은 무제한을 의미합니다.                              |
| `Max Rows to Read (METADATA ONLY)`  | `3000000` | 메타데이터 쿼리에서 읽을 수 있는 최대 행 수입니다. `0`은 무제한을 의미합니다.                 |
| `Filter Keys Fetch Limit`           | `100`     | 맵 컬럼당 가져오는 필터 키 수입니다. 범위: 1–1,000.                             |
| `Field Metadata Queries`            | 활성화됨      | ClickHouse에서 필드 메타데이터를 가져올지 여부를 제어합니다.                         |
| `Parallelize Queries When Possible` | Disabled  | 병렬 처리가 가능한 윈도우 쿼리를 병렬로 실행합니다. 이로 인해 데이터베이스의 최대 부하가 증가할 수 있습니다. |

권한 및 보안 정책에 대해서는 [역할 기반 접근 제어](/ko/clickstack/managing/rbac)를 참조하십시오. 알림 대상에 대해서는 [알림](/ko/clickstack/features/alerts)을 참조하십시오.

### 애플리케이션 구성 설정 {#application-configuration-settings}

다음 환경 변수는 자체 호스팅 ClickStack을 구성하는 데 사용됩니다. ClickHouse Cloud에서 호스팅되는 ClickStack UI에서는 이 환경 변수를 구성할 수 없습니다. 별도로 명시하지 않는 한 아래 기본값은 공식 컨테이너 진입점을 기준으로 하며, Docker Compose에서 재정의할 수 있습니다. 환경 변수를 변경한 후에는 해당 서비스를 재시작하십시오.

#### 네트워크 및 스토리지 {#network-and-storage}

| 변수                            | 기본값                                | 설명                                                                                                                           |
| ----------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `HYPERDX_API_PORT`            | `8000`                             | 애플리케이션 컨테이너 내부의 API 서버 포트입니다. 이 값을 변경하는 경우 Docker 포트 매핑도 함께 수정하십시오.                                                          |
| `HYPERDX_APP_PORT`            | `8080`                             | 애플리케이션 컨테이너 내부의 프론트엔드 포트입니다. 이 값을 변경하는 경우 Docker 포트 매핑도 함께 수정하십시오.                                                           |
| `HYPERDX_APP_URL`             | `http://localhost`                 | 포트를 제외한 퍼블릭 프론트엔드 오리진(origin)입니다. `HYPERDX_APP_PORT`와 함께 `FRONTEND_URL`을 구성하는 데 사용됩니다.                                       |
| `FRONTEND_URL`                | `HYPERDX_APP_URL:HYPERDX_APP_PORT` | 리디렉션에 사용되는 전체 퍼블릭 프론트엔드 URL입니다. 리버스 프록시 또는 HTTPS를 사용하는 경우 명시적으로 설정하십시오.                                                      |
| `HYPERDX_APP_LISTEN_HOSTNAME` | `0.0.0.0`                          | UI 전용 컨테이너에서 프론트엔드가 수신 대기하는 주소입니다.                                                                                           |
| `HYPERDX_OPAMP_PORT`          | `4320`                             | collector가 구성과 수집 키를 가져올 때 사용하는 OpAMP 서버 포트입니다. 컨테이너는 이 값을 `OPAMP_PORT`에 매핑합니다.                                              |
| `MONGO_URI`                   | 배포 방식에 따라 다름                       | MongoDB 연결 문자열(Connection String)입니다. Compose 및 올인원 배포에서는 `mongodb://db:27017/hyperdx`를 사용합니다. 올인원 배포에서는 진입점이 이 값을 직접 설정합니다. |
| `SERVER_URL`                  | 배포 방식에 따라 다름                       | 프론트엔드 서버가 사용하는 내부 API URL입니다. Compose 및 올인원 배포에서는 로컬 API 포트를 가리키도록 설정됩니다.                                                    |

컨테이너 진입점을 사용하지 않고 API를 직접 실행하는 경우, API 리스너와 OpAMP 리스너용으로 각각 `PORT`와 `OPAMP_PORT`를 설정하십시오. `HYPERDX_*_PORT` 변수는 컨테이너 및 배포 환경에서 편의를 위해 제공되는 변수입니다.

#### 인증 및 보안 {#authentication-and-security}

| 변수                                | 기본값                       | 설명                                                                                                                                             |

| `EXTERNAL_API_RATE_LIMIT_MAX`     | `100`                     | API Key당 분당 외부 API v2 요청 수를 제한하는 양의 정수입니다.                                                                                                     |

| `ENABLE_SWAGGER`                  | `false`                   | `NODE_ENV`가 `production`이 아닌 경우에만 API 문서를 활성화합니다. 배포된 운영 환경 image에서는 적용되지 않습니다.                                                                |

| `BETA_CH_OTEL_JSON_SCHEMA_ENABLED` | `false` | 올인원 진입점에서 JSON 호환 기본 소스 매핑을 사용하도록 선택합니다. collector의 `HYPERDX_OTEL_EXPORTER_CLICKHOUSE_JSON_ENABLE`과 함께 사용하십시오.                  |

`NEXT_PUBLIC_IS_LOCAL_MODE`는 [Local Mode 배포판](/ko/clickstack/deployment/local-mode-only)용 프론트엔드 빌드 플래그이며, 범용 개발 스위치가 아닙니다. 기존 배포에서 인증을 비활성화하지 말고 용도에 맞는 배포판을 사용하십시오. `IS_LOCAL_MODE`와 `IS_OSS`는 애플리케이션 상수 이름일 뿐, 설정 대상 환경 변수가 아닙니다. `NEXT_PUBLIC_IS_OSS`는 빌드 설정이며, Enterprise 에디션 전환용 스위치가 아닙니다. `MINER_API_URL`은 현재 애플리케이션에서 더 이상 사용되지 않습니다.

제공된 리버스 프록시 구성을 하위 경로에 사용하는 경우, `HYPERDX_BASE_PATH`와 `NEXT_PUBLIC_HYPERDX_BASE_PATH`를 동일한 접두사(예: `/clickstack`)로 설정하고 `FRONTEND_URL`에도 해당 접두사를 포함하십시오.

일부 프론트엔드 설정은 빌드 시점에 읽힙니다. 특히 `NEXT_PUBLIC_HYPERDX_BASE_PATH`(배포 경로 접두사), `NEXT_PUBLIC_NOINDEX`(검색 엔진 인덱싱) 또는 배포판의 모드 플래그를 변경하려면 해당 값을 적용해 프론트엔드를 다시 빌드해야 합니다. 반면 `NEXT_PUBLIC_INSTANCE_LABEL`처럼 `next-runtime-env`를 통해 읽히는 런타임 설정은 컨테이너 시작 시 제공할 수 있습니다.

## OpenTelemetry collector {#otel-collector}

배포 지침은 [ClickStack OpenTelemetry 수집기](/ko/clickstack/ingesting-data/collector)를 참조하십시오. collector 변수는 UI 컨테이너뿐만 아니라 collector 컨테이너에도 설정해야 합니다. Compose에서는 `.env`에 값을 선언하더라도 `docker-compose.yml`에서 해당 값을 참조해야만 컨테이너에 전달됩니다.

### 연결 및 인증 {#collector-connection-and-authentication}

| 변수                                          | 기본값                         | 설명                                                                                                                                                                                                     |
| ------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `CLICKHOUSE_ENDPOINT`                       | 배포 환경에 따라 다름                | ClickHouse 익스포터 연결 URL입니다. Compose 및 올인원 배포에서는 `tcp://ch-server:9000?dial_timeout=10s`를 사용합니다. ClickHouse Cloud에서는 보안 네이티브 엔드포인트(예: `tcp://<host>:9440?secure=true`)를 사용하십시오. HTTPS만 사용할 수 있는 것은 아닙니다. |
| `CLICKHOUSE_USER`                           | 마이그레이션 도구에서는 `default`      | ClickHouse 사용자 이름입니다. 독립형 collector에서는 마이그레이션과 익스포터가 모두 의도한 계정을 사용하도록 명시적으로 설정하십시오.                                                                                                                    |

| `OPAMP_SERVER_URL`                          | 독립형 모드에서는 설정되지 않음           | ClickStack UI의 OpAMP URL로, 일반적으로 `http://<app>:4320`입니다. 설정하면 collector가 슈퍼바이저를 통해 구성과 팀 수집 키를 가져옵니다. 설정하지 않으면 독립형 구성을 사용합니다.                                                                          |

<div id="clickhouse">
  ## ClickHouse {#clickhouse}
</div>

ClickStack Open Source에는 멀티 테라바이트 규모에 맞게 설계된 기본 ClickHouse 구성이 포함되어 있지만, 워크로드에 맞게 자유롭게 수정하고 최적화할 수 있습니다.

ClickHouse를 효과적으로 튜닝하려면 [파트](/ko/concepts/core-concepts/parts), [파티션](/ko/concepts/core-concepts/partitions), [세그먼트 및 레플리카](/ko/guides/oss/deployment-and-scaling/shards)와 같은 핵심 스토리지 개념과 [머지](/ko/concepts/core-concepts/merges)가 삽입 시점에 어떻게 발생하는지 이해해야 합니다. 또한 [프라이머리 인덱스](/ko/concepts/core-concepts/primary-indexes), [희소 세컨더리 인덱스](/ko/concepts/features/performance/skip-indexes/skipping-indexes), 데이터 스키핑 인덱스의 기초와 TTL 수명 주기 사용과 같은 [데이터 수명 주기 관리](/ko/guides/use-cases/observability/build-your-own/managing-data) 기법도 함께 검토할 것을 권장합니다.

ClickStack은 [스키마 사용자 지정](/ko/guides/use-cases/observability/build-your-own/schema-design)을 지원합니다. 컬럼 타입을 수정하고, 새 필드(예: 로그에서)를 추출하고, 코덱과 딕셔너리를 적용하고, 프로젝션을 사용해 쿼리를 가속할 수 있습니다.

또한 materialized view는 데이터가 view의 원본 테이블에 기록되고 애플리케이션이 대상 테이블에서 읽는 경우 [수집 중 데이터를 변환하거나 필터링하는 데](/ko/guides/use-cases/observability/build-your-own/schema-design#materialized-columns) 사용할 수 있습니다. materialized view는 ClickStack에서 [쿼리를 네이티브 방식으로 가속하는 데](/ko/clickstack/managing/materialized-views)도 사용할 수 있습니다.

자세한 내용은 스키마 설계, 인덱싱 전략, 데이터 관리 모범 사례에 관한 ClickHouse 문서를 참조하십시오. 이들 대부분은 ClickStack 배포에 직접 적용됩니다.
