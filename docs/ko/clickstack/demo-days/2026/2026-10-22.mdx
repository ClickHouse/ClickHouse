## 임시 대시보드 필터로 테이블 및 시간 차트에서 클릭하여 필터링 {#click-to-filter-tables-time-charts}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 임시(ad hoc) 대시보드 필터에서 테이블 타일과 시간 차트를 클릭하여 필터링할 수 있습니다. 이전에는 검색 타일에서만 이 기능을 사용할 수 있었습니다. 이제 쿼리가 빌더, 원시 SQL, PromQL 중 어느 방식을 사용하든 테이블, 선 차트, Stacked Bar, 누적 선 차트의 값을 클릭하여 필터 조건(Filter Conditions)을 추가할 수 있습니다.

테이블에서는 검색 테이블에서와 마찬가지로 필터링 가능한 셀 위에 마우스를 올린 다음 포함 또는 제외를 선택하면 됩니다. group-by 컬럼은 필터링할 수 있지만, 집계된 컬럼은 다른 타일에서 동일한 집계를 사용할 가능성이 낮으므로 필터링할 수 없습니다. 또한 조건에는 별칭 대신 원래 표현식이 사용되므로 여러 타일에 걸쳐 적용할 수 있습니다.

group-by 컬럼을 식별하는 방식은 쿼리 유형에 따라 다릅니다.

* 빌더 테이블은 결과 메타데이터에서 각 컬럼의 위치를 기준으로 합니다. ClickHouse가 별칭이 없는 표현식을 정규화하기 때문입니다.
* 원시 SQL 쿼리는 매크로와 변수를 치환한 후 `node-sql-parser`로 파싱합니다. `GROUP BY`에서 별칭, 이름, 정규화된 표현식 또는 위치(예: `GROUP BY 2`)로 참조되는 컬럼은 필터링할 수 있습니다.
* PromQL 테이블은 시간 컬럼을 제외한 숫자가 아닌 컬럼을 레이블로 처리합니다.

클릭하여 필터링하는 기능은 아직 `DateTime`, `Map`, `Array` 컬럼을 지원하지 않습니다. 이러한 컬럼에는 별도의 로직이 필요합니다.

원시 SQL 차트에는 아직 몇 가지 미흡한 부분이 있습니다. `node-sql-parser`는 파라메트릭 함수, `ARRAY JOIN`, 일부 조인 구문 등 ClickHouse 방언 전체를 지원하지는 않습니다. 파싱에 실패하거나, 쿼리에 `GROUP BY`가 없거나, `GROUP BY ALL`을 사용하거나, `SELECT *`가 포함된 경우에는 대신 `String` 컬럼을 필터링 가능한 컬럼으로 처리합니다.

이 폴백은 완벽하지 않습니다. 일부 컬럼은 클릭할 수 없고, 일부 컬럼은 다른 타일에 존재하지 않는 필터 키를 추가할 수 있습니다. CTE에서 가져온 컬럼도 다른 타일에는 정의되어 있지 않을 수 있으므로 같은 문제가 발생할 수 있습니다. 이 경우 해당 조건을 제거하면 됩니다. 이를 개선하기 위해 향후 완전한 ClickHouse SQL 파서를 추가할 계획입니다.

시간 차트에서는 이제 시계열 도구 설명에서 클릭 한 번으로 해당 시계열의 모든 레이블로 필터링할 수 있습니다. 예를 들어 차트가 서비스 이름과 심각도로 그룹화되어 있으면 시계열을 클릭할 때 두 조건이 모두 추가됩니다. **제외**는 레이블이 하나일 때만 사용할 수 있습니다. 예를 들어 `service = 'checkout'`과 `severity = 'error'`를 각각 제외하면 checkout 오류만 숨겨지는 것이 아니라 모든 checkout 로그와 모든 서비스의 오류가 숨겨지기 때문입니다. PromQL 선 차트는 Prometheus가 반환한 레이블 중 `__name__`을 제외한 레이블을 사용합니다.

**관련 PR:** [#3389](https://github.com/hyperdxio/hyperdx/pull/3389) 테이블 차트에 클릭하여 임시 필터 추가 기능 추가, [#3405](https://github.com/hyperdxio/hyperdx/pull/3405) 시간 차트 시계열을 임시 대시보드 필터로 필터링

## 선 보간 표시 설정 {#line-interpolation-display-setting}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=149" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 표시 설정의 **Smooth**, **Linear**, **Step** 보간 옵션으로 선 차트에서 점을 연결하는 방식을 선택할 수 있습니다. 이전에는 일반 선 차트는 항상 부드러운 곡선으로, 누적 선 차트는 직선 구간으로 점을 연결했습니다. 이 방식은 기본값으로 유지되지만, 이제 데이터 특성에 맞게 변경하거나 차트 간 일관성을 맞추도록 설정할 수 있습니다.

이 설정은 차트 편집기, 외부 API, MCP에서 사용할 수 있습니다. 또한 편집기에서 Stacked Bar 또는 누적 선 차트로 전환해도 저장된 타일의 표시 유형이 업데이트되지 않던 버그를 수정했습니다.

## 검색 페이지 히스토그램의 그룹화(Group By) {#search-page-histogram-group-by}

*데모 진행자: [@pulpdrew](https://github.com/pulpdrew)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=194" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 검색 히스토그램을 원하는 필드 기준으로 그룹화할 수 있습니다. 이전에는 소스에 따라 항상 심각도(severity) 또는 상태 코드 기준으로만 분할되었습니다. [@elizabetdev](https://github.com/elizabetdev)의 디자인을 반영해 새로 추가된 **그룹화(Group By)** 컨트롤에서는 필터 사이드바와 동일한 목록에서 여러 필드와 맵 키를 선택할 수 있습니다.

필드를 선택하고 적용하면 히스토그램이 다시 그룹화되며, 각 그룹을 나타내는 범례도 함께 표시됩니다. 소스의 기본값으로 초기화하거나, 그룹화를 해제하여 단순 이벤트 발생 횟수를 확인할 수도 있습니다. 원하는 필드가 목록에 없거나 계산된 값으로 그룹화하려면 SQL을 직접 입력하면 됩니다.

소스를 전환해도 호환되는 그룹화(Group By)는 선택된 상태로 유지됩니다. 예를 들어, 두 소스 모두에서 사용할 수 있는 `ServiceName` 필드나 맵 키는 그대로 유지됩니다. 호환되지 않는 경우 히스토그램은 새 소스의 기본값으로 초기화되며, 이때 소스 전환 시 호환되는 필터를 유지하는 것과 동일한 로직이 적용됩니다.

이어서 [@elizabetdev](https://github.com/elizabetdev)의 후속 작업으로 이 컨트롤이 공용 분할 버튼으로 옮겨져, 레이블과 선택된 값이 나란히 표시됩니다.

**관련 PR:** [#3407](https://github.com/hyperdxio/hyperdx/pull/3407) 검색 페이지 히스토그램에 그룹화(Group By) 추가, [#3430](https://github.com/hyperdxio/hyperdx/pull/3430) 그룹화(Group By) 분할 버튼 공용화

## 대시보드 타일 설명 {#descriptions-on-dashboard-tiles}

*데모 진행자: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=318" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 대시보드 타일에 설명을 추가할 수 있습니다. 차트가 무엇을 나타내는지, 또는 차트를 어떻게 읽어야 하는지 설명할 때 유용합니다. 타일 이름 옆의 정보 아이콘에 마우스를 올리면 설명이 표시됩니다. 설명이 없는 타일은 이전과 동일하게 표시됩니다.

외부 대시보드 API에 설명 기능을 추가해 주신 [@felipe-carvalho12](https://github.com/felipe-carvalho12)께 감사드립니다. 덕분에 대시보드를 코드로 관리할 때도 설명을 설정할 수 있습니다. 또한 타일 편집기의 **Chart Name** 옆에 **Description** 입력란을 추가했습니다. 설명은 최대 1,024자까지 입력할 수 있습니다.

후속 변경에서는 설명을 타일의 차트 구성으로 옮겨 `name`과 함께 두었으며, 이를 통해 편집기가 나머지 구성과 함께 설명을 저장합니다. 또한 외부 API를 통해 `series`가 포함된 상태로 제출된 타일에서 설명이 누락되던 버그도 수정했습니다.

**관련 PR:** [#3352](https://github.com/hyperdxio/hyperdx/pull/3352) 선택 사항인 타일 설명을 도구 설명으로 표시, [#3403](https://github.com/hyperdxio/hyperdx/pull/3403) 타일 편집기에 설명 필드 추가

## 사용자 환경설정의 시간대 선택 {#time-zone-selection}

*데모 진행자: [@karl-power](https://github.com/karl-power)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=358" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 ClickStack에서 시간대를 직접 선택할 수 있습니다. 이전에는 사용자 환경설정의 **Use UTC time** 스위치로 UTC와 브라우저의 로컬 시간대 중 하나만 선택할 수 있었습니다. 이제 이 항목은 검색 가능한 셀렉터로 바뀌었으며, **Local**과 **UTC**가 상단에 고정되고 그 아래에 브라우저가 지원하는 모든 시간대가 표시됩니다. 각 시간대에는 현재 오프셋이 함께 표시되며 검색도 가능합니다. 예를 들어 &#39;los angeles&#39;를 입력하면 `America/Los_Angeles`를 찾을 수 있습니다.

선택한 시간대는 검색 페이지와 대시보드에 적용됩니다. 사이드바 배지와 타임스탬프 컬럼의 열 머리글(column header)에는 `PDT`와 같은 약칭이 표시되며, 미국식 약칭이 없는 시간대는 `UTC+9`와 같은 UTC 오프셋으로 표시됩니다. ClickStack은 IANA 이름을 저장하며, 브라우저가 이를 인식하지 못하면 로컬 시간으로 폴백합니다.

다만 한 번의 조사를 위해 매번 환경설정에서 시간대를 바꾸는 것은 여전히 다소 번거롭습니다. 이번 변경은 검색별·대시보드별 재정의 기능의 토대가 되며, 향후에는 기본 설정을 로컬 또는 UTC로 유지한 채 고객의 데이터를 해당 고객의 시간대로 살펴볼 수 있게 됩니다. 이러한 재정의 기능은 아직 구현되지 않았습니다.

**관련 PR:** [#3445](https://github.com/hyperdxio/hyperdx/pull/3445) 표시 시간대 기준으로 시간 선택기 범위 읽기, [#3447](https://github.com/hyperdxio/hyperdx/pull/3447) 시간 표시 설정을 시간대로 저장, [#3449](https://github.com/hyperdxio/hyperdx/pull/3449) 사용자 환경설정에 시간대 셀렉터 추가

## MCP 서비스 상태 도구 {#mcp-service-health-tool}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=463" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

이제 MCP 서버에 `clickstack_service_health` 도구가 추가되었습니다. 에이전트가 작성하는 원시 SQL(Raw SQL)의 상당 부분이 서비스 상태 점검용이라는 점에 착안하여 이 작업을 위한 전용 도구를 만들었습니다. 이전에는 에이전트가 `clickstack_table` 및 `clickstack_timeseries`를 여러 번 호출하여 결과를 조합한 뒤, 어떤 변화에 주의를 기울여야 하는지 직접 판단해야 했습니다.

이 도구는 트레이스 소스의 각 서비스에 대해 처리량, 오류율, p50/p95/p99 지연 시간, 상위 오류 그룹을 반환하고, 이를 이전 윈도우와 비교합니다. 기본 비교 대상은 전날 같은 시간대이지만, 에이전트는 직전 15분이나 지난주 같은 시간대 등 다른 윈도우를 선택할 수도 있습니다. 가장 주의가 필요한 서비스가 맨 위에 표시되며, `critical`, `degraded`, `healthy` 상태와 함께 그 이유를 나타내는 `error_rate_up`, `latency_up`, `traffic_drop` 등의 플래그가 제공됩니다. 고정 임계값을 적용하므로 일상적인 변동이 회귀 오류로 잘못 표시되지 않습니다.

새로 발생했거나 증가 중인 오류 그룹이 먼저 표시되며, 최초 및 최종 발생 시간이 함께 제공되므로 현재 진행 중인 이슈인지 이미 멈춘 일시적 급증인지 쉽게 구분할 수 있습니다. 비교 윈도우에 트래픽이 없던 연산(Operations)은 롤아웃일 가능성이 높은 것으로 표시되며, 해당 연산의 오류는 새 오류로 집계되지 않습니다. 이 도구는 기본적으로 서버 스팬만 집계하며, `spanKind: "all"`을 지정하면 모든 스팬이 포함됩니다. 보존 기간을 벗어나는 등의 이유로 비교 윈도우에 데이터가 없으면 그 이전 기간으로 다시 시도하고, 그래도 없으면 비교 없이 결과를 보고하는 방식으로 폴백합니다.

**관련 PR:** [#3411](https://github.com/hyperdxio/hyperdx/pull/3411) clickstack&#95;service&#95;health 도구 추가

## MCP 품질 점수 개선 사항 {#mcp-quality-score-improvements}

*데모 진행자 [@brandon-pereira](https://github.com/brandon-pereira)*

ClickStack MCP 서버를 검사하는 데 [Manufact](https://manufact.com)의 MCP Quality Score를 사용해 왔으며, MCP 서버를 운영 중이라면 한번 사용해 보시기를 권장합니다. 세 가지 변경으로 점수가 80점에서 94점으로 올랐습니다.

이제 서버는 기존 `name`, `version`과 함께 제목, 설명, 웹사이트 URL, 아이콘을 `serverInfo`에 포함합니다. 아이콘으로는 앱 로고 SVG를 사용합니다. 아이콘 URL은 절대 경로여야 하므로 `FRONTEND_URL`이 설정되지 않으면 아이콘은 생략됩니다.

이제 모든 도구가 `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`의 네 가지 동작 힌트를 모두 선언합니다. 이전에는 도구마다 하나씩만 선언했습니다. 읽기 전용 도구, 업서트 도구, 그리고 `delete_*`, `patch_dashboard`처럼 멱등성을 갖는 파괴적 도구에 각각 하나씩, 총 세 가지 프리셋을 사용합니다. 업서트 도구는 `id` 없이 호출하면 매번 새 객체를 생성하므로 멱등성을 갖지 않습니다. 도구는 팀 자체의 메타데이터와 ClickHouse 데이터에만 액세스하므로 `openWorldHint`는 모든 도구에서 `false`입니다. 이제 등록 유형에서 네 가지 힌트를 모두 필수로 요구하므로, 하나라도 누락되면 컴파일 오류가 발생합니다.

도구 설명도 정리했습니다. 이제 모든 입력에 설명이 있으며, Claude Code의 2048바이트 잘림 제한을 초과하던 도구 설명 4개를 줄였습니다. 예를 들어 `clickstack_event_deltas`는 3318바이트에서 1796바이트로 줄었습니다. 스키마(schema) 제약 조건을 그대로 반복하던 텍스트를 제거하고, ID 필드에는 해당 ID를 어느 도구에서 얻을 수 있는지 명시했으며, 저장 도구의 부수 효과를 문서화했습니다. 여기에는 새 구성이 알림을 지원할 수 없을 때 `patch_dashboard`가 타일의 알림을 삭제하는 동작도 포함됩니다.

남은 6점은 `outputSchema` 항목입니다. 현재 도구는 `structuredContent` 대신 JSON을 텍스트로 반환하므로, 이 부분은 추후 과제로 남겨 두었습니다.

## MCP 서버의 배치 SQL 쿼리 {#mcp-batch-sql-queries}

*데모 진행자: [@brandon-pereira](https://github.com/brandon-pereira)*

<iframe width="768" height="432" src="https://www.youtube.com/embed/kg0cIe4jgVE?start=588" title="YouTube 동영상 플레이어" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen />

에이전트가 원시 SQL(Raw SQL)을 사용해야 할 때, 이제 `clickstack_sql`은 쿼리마다 별도로 왕복 요청을 보내지 않고 한 번의 호출로 여러 쿼리를 실행할 수 있습니다. 기존처럼 단일 `sql` 쿼리를 전달하거나, 최대 10개의 엔트리로 구성된 `queries` 배열을 전달하면 됩니다. 각 엔트리에는 고유한 `sql`과 선택 사항인 `id`, `connectionId`, `sourceId`가 포함됩니다. 모든 쿼리는 `startTime`과 `endTime`을 공유합니다.

쿼리는 한 번에 5개씩 실행되며, 배치 전체에 60초의 제한 시간이 적용됩니다. 제한 시간이 지났을 때 아직 큐에 남아 있는 쿼리는 ClickHouse로 전송되지 않습니다. 결과는 입력 순서대로 `ok`, `error`, `timeout` 상태와 함께 반환되므로, 쿼리 하나가 실패해도 배치 전체가 실패하지 않습니다. `isError`는 모든 쿼리가 실패한 경우에만 설정됩니다. 배치 전체의 응답 한도는 100k자이며, 기존 단일 쿼리 제한에 맞춰 쿼리당 최대 50k자로 제한됩니다.

호출에는 `sql` 또는 `queries` 중 하나만 포함해야 하며, 둘을 함께 포함할 수는 없습니다. 이제 `sql`이 항상 필수인 것은 아니므로, 도구의 required 목록이 아닌 핸들러에서 이 조건을 검사합니다.

MCP 작업(tasks)도 검토했지만 당분간 보류하기로 했습니다. SDK API가 아직 실험적 단계이고, `2026-07-28` 명세에서는 작업이 별도의 확장 기능으로 분리되었지만 서버 SDK가 아직 이를 지원하지 않기 때문입니다. 이 변경 사항은 아직 머지되지 않았습니다.
