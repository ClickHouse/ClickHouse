이 가이드에서는 샘플 데이터 세트를 사용해 ClickStack Open Source를 시연합니다.

다음 예시는 [all-in-one 이미지](/ko/clickstack/getting-started/oss)로 ClickStack Open Source를 시작하고 [수집 API key](/ko/clickstack/getting-started/oss#copy-ingestion-api-key)를 복사해 두었다고 가정합니다.

<Steps>
  <Step title="ClickStack UI로 이동하십시오" id="navigate-to-the-hyperdx-ui">
    ClickStack UI에 액세스하려면 [http://localhost:8080](http://localhost:8080)에 접속하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack UI](/images/use-cases/observability/hyperdx.webp)
      </Frame>
    </div>
  </Step>

  <Step title="수집 API key 복사" id="copy-ingestion-api-key">
    [`Team Settings`](http://localhost:8080/team)로 이동한 다음 `API Keys` 섹션에서 `Ingestion API Key`를 복사하십시오. 이 API Key를 사용하면 OpenTelemetry collector를 통한 데이터 수집을 안전하게 보호할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![API Key 복사](/images/use-cases/observability/copy_api_key.webp)
      </Frame>
    </div>
  </Step>

  <Step title="샘플 데이터 다운로드" id="download-sample-data">
    UI에 샘플 데이터를 채우려면 다음 파일을 다운로드하십시오.

    [샘플 데이터](https://storage.googleapis.com/hyperdx/sample.tar.gz)

    ```shell
    # curl
    curl -O https://storage.googleapis.com/hyperdx/sample.tar.gz
    # or
    # wget https://storage.googleapis.com/hyperdx/sample.tar.gz
    ```

    이 파일에는 마이크로서비스로 구성된 간단한 전자상거래 스토어인 공개 [OpenTelemetry demo](https://github.com/ClickHouse/opentelemetry-demo)에서 수집한 예시 로그, 메트릭, 트레이스가 포함되어 있습니다. 이 파일을 원하는 디렉터리에 복사하세요.
  </Step>

  <Step title="샘플 데이터 불러오기" id="load-sample-data">
    이 데이터를 로드하려면 배포된 OpenTelemetry(OTel) collector의 HTTP 엔드포인트로 데이터를 전송하기만 하면 됩니다.

    먼저 위에서 복사한 API Key를 환경 변수로 export하십시오.

    ```shell
    # export API key
    export CLICKSTACK_API_KEY=<YOUR_INGESTION_API_KEY>
    ```

    다음 명령을 실행하여 데이터를 OTel collector로 전송하십시오.

    ```shell
    for filename in $(tar -tf sample.tar.gz); do
      endpoint="http://localhost:4318/v1/${filename%.json}"
      echo "loading ${filename%.json}"
      tar -xOf sample.tar.gz "$filename" | while read -r line; do
        printf '%s\n' "$line" | curl -s -o /dev/null -X POST "$endpoint" \
        -H "Content-Type: application/json" \
        -H "authorization: ${CLICKSTACK_API_KEY}" \
        --data-binary @-
      done
    done
    ```

    이는 OTLP 로그, 트레이스, 메트릭 소스가 OTel collector로 데이터를 전송하는 상황을 시뮬레이션합니다. 운영 환경에서는 이러한 소스가 언어 클라이언트일 수도 있고, 다른 OTel collector일 수도 있습니다.

    `Search` 뷰로 돌아가면 데이터가 로드되기 시작한 것을 확인할 수 있습니다(데이터가 표시되지 않으면 시간 범위를 `Last 1 hour`로 조정하십시오).

    <div className="ch-image-lg">
      <Frame>
        ![ClickStack UI 검색](/images/use-cases/observability/hyperdx-10.webp)
      </Frame>
    </div>

    데이터 로딩에는 몇 분 정도 소요됩니다. 로딩이 완료된 후 다음 단계로 진행하십시오.
  </Step>

  <Step title="세션(Sessions) 탐색" id="explore-sessions">
    사용자들이 상품 결제에 문제를 겪고 있다는 보고가 접수되었다고 가정해 보겠습니다. ClickStack UI의 세션 리플레이 기능을 사용하면 사용자의 경험을 직접 확인할 수 있습니다.

    왼쪽 메뉴에서 [`Client Sessions`](http://localhost:8080/sessions?from=1747312320000\&to=1747312920000\&sessionSource=l1324572572)를 선택하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![세션](/images/use-cases/observability/hyperdx-11.webp)
      </Frame>
    </div>

    이 뷰에서는 전자상거래 스토어의 프런트엔드 세션을 확인할 수 있습니다. 세션은 사용자가 체크아웃하여 구매를 완료하려고 시도하기 전까지 익명(Anonymous) 상태로 유지됩니다.

    이메일이 있는 일부 세션에는 관련 오류가 있으며, 이는 트랜잭션 실패 보고를 뒷받침하는 단서일 수 있습니다.

    실패가 발생했고 이메일이 연결된 트레이스를 선택하십시오. 이어서 표시되는 뷰에서 사용자의 세션을 리플레이하며 문제를 살펴볼 수 있습니다. 실행 버튼을 눌러 세션을 재생하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![세션 리플레이](/images/use-cases/observability/hyperdx-12.webp)
      </Frame>
    </div>

    리플레이에는 사용자가 사이트를 탐색하며 장바구니에 상품을 담는 모습이 표시됩니다. 사용자가 결제를 시도하는 세션 후반부로 바로 건너뛰어도 됩니다.

    <Tip>
      모든 오류는 타임라인에 빨간색으로 표시됩니다.
    </Tip>

    사용자는 뚜렷한 오류 메시지 없이 주문을 완료하지 못했습니다. 사용자 브라우저의 네트워크 및 콘솔 이벤트가 표시되는 왼쪽 패널 하단으로 스크롤하십시오. `/api/checkout` 호출 시 500 오류가 발생한 것을 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![세션 내 오류](/images/use-cases/observability/hyperdx-13.webp)
      </Frame>
    </div>

    이 `500` 오류를 선택하십시오. `Overview`와 `Column Values` 어디에서도 예기치 않은 오류로 인해 `Internal Error`가 발생했다는 사실 외에는 문제의 원인을 파악할 수 없습니다.
  </Step>

  <Step title="trace 탐색" id="explore-traces">
    `Trace` 탭으로 이동하여 전체 분산 트레이스를 확인하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![세션 트레이스](/images/use-cases/observability/hyperdx-14.webp)
      </Frame>
    </div>

    트레이스를 아래로 스크롤하면 오류의 시작점인 `checkout` 서비스 스팬을 확인할 수 있습니다. `Payment` 서비스 스팬을 선택하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![스팬](/images/use-cases/observability/hyperdx-15.webp)
      </Frame>
    </div>

    `Column Values` 탭을 선택하고 아래로 스크롤하십시오. 이 문제가 캐시가 가득 찬 것과 관련되어 있음을 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![열 값](/images/use-cases/observability/hyperdx-16.webp)
      </Frame>
    </div>

    다시 위로 스크롤하여 트레이스로 돌아가면, 앞서 설정한 구성 덕분에 로그가 스팬과 상호 연관되어 있음을 확인할 수 있습니다. 이 로그를 통해 추가적인 컨텍스트를 파악할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![상호 연관된 로그](/images/use-cases/observability/hyperdx-17.webp)
      </Frame>
    </div>

    이를 통해 payment 서비스의 캐시가 가득 차면서 결제가 완료되지 못하고 있다는 사실을 확인했습니다.
  </Step>

  <Step title="로그 탐색" id="explore-logs">
    자세한 내용은 [`Search` 뷰](http://localhost:8080/search)로 돌아가서 확인할 수 있습니다.

    소스 목록에서 `Logs`를 선택하고 `payment` 서비스에 필터(filter)를 적용하십시오.

    <div className="ch-image-lg">
      <Frame>
        ![로그](/images/use-cases/observability/hyperdx-18.webp)
      </Frame>
    </div>

    문제가 발생한 지 얼마 되지 않았지만 영향을 받은 결제 건수가 많다는 것을 알 수 있습니다. 또한 Visa 결제와 관련된 캐시가 문제를 일으키고 있는 것으로 보입니다.
  </Step>

  <Step title="차트 메트릭" id="chart-metrics">
    코드에 오류가 유입된 것은 분명하지만, 메트릭을 사용하면 캐시 크기를 확인할 수 있습니다. `Chart Explorer` 뷰로 이동하십시오.

    데이터 소스로 `Metrics`를 선택하십시오. 차트 빌더에서 `visa_validation_cache.size (Gauge)`의 `Maximum`을 표시하도록 설정한 후 실행 버튼을 누르십시오. 캐시가 최대 크기에 도달할 때까지 꾸준히 증가했으며, 그 이후부터 오류가 발생했음을 확인할 수 있습니다.

    <div className="ch-image-lg">
      <Frame>
        ![메트릭](/images/use-cases/observability/hyperdx-19.webp)
      </Frame>
    </div>
  </Step>
</Steps>
