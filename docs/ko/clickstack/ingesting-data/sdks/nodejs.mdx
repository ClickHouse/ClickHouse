ClickStack Node.js SDK는 업스트림 OpenTelemetry SDK와 auto-instrumentation을 기반으로 하며, 여기에 콘솔 출력 캡처, 처리되지 않은 예외 캡처, 종료 시 텔레메트리 플러시 기능을 더합니다. 이미 OpenTelemetry를 구성해 사용 중인 애플리케이션은 기존 SDK를 그대로 유지하면서 [OTLP 내보내기를 구성](/ko/clickstack/ingesting-data/opentelemetry)할 수 있습니다.

<ClickStackIntegrates signals={['logs', 'metrics', 'traces']} />

## 설치 {#install}

Node.js **22.15 이상** 버전을 사용하십시오. 애플리케이션에 SDK를 설치합니다:

```shell
npm install @clickhouse/clickstack-node
```

이 패키지는 ES 모듈과 CommonJS를 모두 지원합니다. 피어 의존성(peer dependency)인 `@opentelemetry/api`는 npm이 자동으로 설치합니다. 애플리케이션에서 이 패키지를 직접 가져오는 경우 `@opentelemetry/api@~1.9.1`을 설치하십시오. 1.10 버전은 이 SDK의 지원 범위에 포함되지 않습니다.

## 대상 구성 {#configure-destination}

애플리케이션을 시작하기 전에 환경 변수를 설정하십시오. 기본 OTLP HTTP 엔드포인트는 `/v1/traces`, `/v1/logs`, `/v1/metrics`를 제외한 형태로 지정하십시오. 해당 경로는 익스포터가 자동으로 추가합니다.

collector의 OTLP HTTP 엔드포인트와 해당 collector의 OTLP 수신기에 구성된 수집 키를 사용하십시오. collector 설정 방법은 [OpenTelemetry로 데이터 수집하기](/ko/clickstack/ingesting-data/opentelemetry)를 참조하십시오.

```shell
export OTEL_EXPORTER_OTLP_ENDPOINT='http://localhost:4318'
export OTEL_EXPORTER_OTLP_HEADERS='authorization=YOUR_INGESTION_API_KEY'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
export OTEL_SERVICE_NAME='my-node-app'
```

이 엔드포인트는 애플리케이션과 collector가 동일한 호스트에서 실행된다고 가정합니다. collector가 다른 곳에서 실행된다면 애플리케이션에서 연결할 수 있는 주소로 바꾸십시오.

## 애플리케이션 시작하기 {#start-application}

애플리케이션이 계측 대상 라이브러리를 가져오기 전에 SDK를 미리 로드하십시오:

```shell
node --import @clickhouse/clickstack-node/register server.js
```

`server.js`를 애플리케이션의 엔트리 파일로 바꾸십시오. 이 명령은 애플리케이션이 시작되기 전에 SDK를 로드하며, 위에서 구성한 환경 변수를 사용합니다. CommonJS 및 ES 모듈 애플리케이션을 모두 지원합니다.

이제 [수집을 확인](#verify-ingestion)할 수 있습니다. 아래의 대체 방법은 npm 스크립트를 통해 시작하거나 코드에서 SDK를 구성하려는 경우에만 필요합니다.

<Accordion title="대체 시작 방법">
  `--require`도 지원됩니다. `NODE_OPTIONS`를 사용하는 경우, 빌드 도구가 자체 텔레메트리 파이프라인을 시작하지 않도록 해당 옵션의 적용 범위를 애플리케이션 명령으로 한정하십시오:

  ```shell
  NODE_OPTIONS='--import @clickhouse/clickstack-node/register' npm start
  ```

  또는 instrumentation 모듈을 생성하여 미리 로드할 수도 있습니다. 이 경우에도 내보내기는 이전 섹션의 환경 변수로 구성됩니다:

  ```javascript
  // instrumentation.mjs
  import { isMainThread } from 'node:worker_threads';
  import { init } from '@clickhouse/clickstack-node';

  if (isMainThread) {
    init();
  }
  ```

  ```shell
  node --import ./instrumentation.mjs server.mjs
  ```

  이 가드 조건은 Pino transport worker와 같은 작업 스레드에서 SDK 인스턴스가 추가로 시작되는 것을 방지합니다.

  패키지의 등록 진입점과 직접 작성한 instrumentation 모듈 중 하나만 사용하십시오. 애플리케이션에서 SDK를 중복으로 초기화하지 마십시오. 정적 ES 모듈 import는 모듈 body보다 먼저 실행되므로, 같은 파일에서 정적 import 위쪽에 `init` 호출을 배치하더라도 초기화 순서는 보장되지 않습니다.
</Accordion>

## 수집 확인 {#verify-ingestion}

애플리케이션을 시작하고 계측된 라우트에 요청을 보낸 다음 콘솔 메시지를 출력하십시오. ClickStack에서 최근 시간 범위를 선택한 후 Logs 또는 Traces에서 `my-node-app`을 검색하십시오. 메트릭은 메트릭 내보내기 인터벌만큼 시간이 지난 후에 확인하십시오.

데이터가 표시되지 않으면 stderr에 출력되는 SDK 진단 정보, 엔드포인트와 인증 설정, 네트워크 연결 상태를 확인하십시오. instrumentation은 애플리케이션 의존성보다 먼저 로드되어야 합니다. 번들러가 라이브러리를 인라인으로 포함하면 해당 라이브러리는 자동으로 계측되지 않으므로, SDK와 계측 대상 의존성은 외부(external)로 유지하십시오. TypeScript, ES 모듈, 프레임워크, 번들러 관련 요구 사항은 [SDK 호환성](https://github.com/ClickHouse/clickstack-node#compatibility)을 참조하십시오.

## instrumentation 구성 {#configure-instrumentation}

샘플링, 일괄 처리, 익스포터, 리소스 속성을 비롯한 표준 OpenTelemetry 환경 변수는 업스트림에서와 동일한 의미를 그대로 유지합니다. 예를 들면 다음과 같습니다.

```shell
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
```

콘솔 출력은 기본적으로 수집됩니다. HTTP body 수집은 기본적으로 비활성화되어 있습니다. 애플리케이션이 처리하는 데이터를 고려하여 적절한 경우에만 활성화하십시오:

```shell
export CLICKSTACK_CAPTURE_HTTP_BODY='true'
```

캡처된 body에는 개인 데이터와 자격 증명이 포함될 수 있습니다. SDK의 마스킹은 모든 민감 정보의 제거를 보장하지 않으므로(best effort), 필요한 경우 collector 측 마스킹을 계속 사용하십시오. 헤더 캡처, body 크기 제한, 데이터 정제(sanitization)에 대한 내용은 [SDK 개인정보 보호 옵션](https://github.com/ClickHouse/clickstack-node#privacy)을 참조하십시오.

### 초기화 옵션 {#initialization-options}

instrumentation 모듈에서 `init`에 다음 옵션을 전달하십시오.

| 옵션                           | 기본값                                  | 용도                                                                                            |
| ---------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------- |
| `endpoint`                   | `http://localhost:4318`              | 기본 OTLP HTTP URL입니다. `OTEL_EXPORTER_OTLP_ENDPOINT`로 재정의됩니다                                    |
| `serviceName`                | `unknown_service:` 뒤에 실행 파일 이름을 붙인 값 | 서비스 이름입니다. `OTEL_SERVICE_NAME` 또는 `OTEL_RESOURCE_ATTRIBUTES`의 `service.name`으로 재정의됩니다         |
| `environment`                | 설정되지 않음                              | `deployment.environment.name`을 설정합니다. `OTEL_RESOURCE_ATTRIBUTES`에 같은 키가 있으면 해당 값이 우선합니다       |
| `apiKey`                     | 설정되지 않음                              | 인증 헤더 값입니다. `OTEL_EXPORTER_OTLP_HEADERS`가 이미 비어 있지 않으면, 관련 없는 헤더만 들어 있더라도 무시됩니다               |
| `httpBodyCapture`            | `false`                              | HTTP 본문을 캡처합니다. `CLICKSTACK_CAPTURE_HTTP_BODY`로 재정의됩니다                                        |
| `instrumentations`           | 업스트림 구성 기본값                          | `getNodeAutoInstrumentations`에 전달하는 구성 맵입니다. 명시적으로 지정한 `enabled` 값은 instrumentation 활성화/비활성화 환경 변수보다 우선합니다 |
| `additionalInstrumentations` | `[]`                                 | 기본 번들에 포함되지 않은 라이브러리용 추가 instrumentation 인스턴스입니다                                                           |

환경 변수가 설정되지 않았거나 비어 있으면 해당 옵션 값이 적용됩니다. 콘솔 캡처를 비활성화하려면 `OTEL_NODE_DISABLED_INSTRUMENTATIONS`에 `console`을 추가하십시오. 전체 기본값은 [Node.js SDK 참고 문서](https://github.com/ClickHouse/clickstack-node#quick-start)를 참조하십시오.

프로세스를 명시적으로 종료하거나 AWS Lambda 핸들러를 사용하는 경우 [SDK 수명 주기 문서](https://github.com/ClickHouse/clickstack-node#lifecycle)를 참조하십시오.

## 업스트림 SDK 사용 {#using-upstream-sdk}

애플리케이션에서 이미 OpenTelemetry를 구성하고 있거나, ClickStack SDK 옵션으로는 지원되지 않는 사용자 정의 프로세서나 동작이 필요하다면 업스트림 `NodeSDK`를 사용하고 위에서 설명한 대상으로 OTLP 내보내기를 구성하십시오. 추가 로더 및 수명 주기 구성에 대한 설명은 [업스트림 SDK 설정 예시](https://github.com/ClickHouse/clickstack-node#using-the-upstream-sdk-directly)를 참고하십시오. 동일한 프로세스에서 두 SDK를 함께 초기화하지 마십시오.

## HyperDX Node.js SDK에서 마이그레이션 {#migration}

`@hyperdx/node-opentelemetry`를 `@clickhouse/clickstack-node`로 교체하고 새 등록 진입점을 사용하십시오. `HYPERDX_API_KEY` 대신 `OTEL_EXPORTER_OTLP_HEADERS`를 사용하되, 위에서 설명한 대상별 인증 포맷을 따르십시오.

새 SDK는 기존 HyperDX의 보조 기능과 옵션을 모두 지원하지는 않습니다. 로거 통합, 오류 처리기, 사용자 정의 트레이스 속성 또는 샘플링 설정을 교체하기 전에 [SDK 마이그레이션 가이드](https://github.com/ClickHouse/clickstack-node/blob/main/docs/migration.md)를 확인하십시오.
