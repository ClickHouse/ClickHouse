### ClickHouse Cloud에서 Backup이 작동하는 방식 {#how-backups-work-in-clickhouse-cloud}

ClickHouse Cloud Backup은 &quot;전체&quot; Backup과 &quot;증분&quot; Backup을 조합해 하나의 Backup 체인을 구성합니다. 체인은 전체 Backup으로 시작되며, 이후 예약된 여러 시점에 걸쳐 증분 Backup이 수행되어 연속된 Backup 시퀀스가 만들어집니다. Backup 체인이 일정 길이에 도달하면 새 체인이 시작됩니다. 필요할 경우 이 Backup 체인 전체를 사용해 데이터를 새 서비스로 복원할 수 있습니다. 특정 체인에 포함된 모든 Backup이 서비스에 설정된 보존 기간(보존에 대한 자세한 내용은 아래 참고)을 지나면 해당 체인은 폐기됩니다.

복원 가능한 시점의 수는 물리적 Backup 객체의 수와 일치하지 않습니다. 각 복원 시점이 의존하는 전체 Backup과 증분 Backup은 하나의 체인으로 묶여 함께 보존됩니다.

아래 스크린샷에서 실선 사각형은 전체 Backup을, 점선 사각형은 체인에 포함된 증분 Backup을 나타냅니다.

1일 차에는 Backup 체인을 시작하기 위해 전체 Backup이 수행됩니다. 2일 차에는 증분 Backup이 수행되며, 전체 Backup과 증분 Backup 모두에서 복원할 수 있습니다. 7일 차가 되면 체인에는 전체 Backup 1개와 증분 Backup 6개가 있으며, 모두 표시되고 복원에 사용할 수 있습니다. 8일 차에는 새 전체 Backup이 수행되고, 9일 차에는 새 체인에 Backup 2개가 쌓이면 이전 체인이 폐기됩니다.

  ### 기본 백업 정책 {#default-backup-policy}

백업은 Basic, Scale, Enterprise 티어에서 스토리지와 별도로 사용량이 측정되며 청구됩니다.
현재 서비스는 기본적으로 24시간 보존 기간의 하루 1회 백업으로 설정됩니다. 백업 구성은 서비스 및 계약에 따라 달라질 수 있습니다.

자세한 내용은 [&quot;백업 검토 및 복원&quot;](/ko/products/cloud/guides/backups/review-and-restore-backups)을 참조하십시오.

## 설정 가능한 Backup {#configurable-backups}

<ScalePlanFeatureBadge feature="Configurable Backups" linking_verb_are="True" />

ClickHouse Cloud에서는 **Scale** 및 **Enterprise** 티어 서비스의 Backup 일정을 설정할 수 있습니다. Backup은 비즈니스 요구 사항에 따라 다음 항목을 기준으로 설정할 수 있습니다.

* **보존 기간**: 각 Backup을 보관할 기간(일)입니다. 보존 기간은 최소 1일부터 최대 45일까지 지정할 수 있으며, 그 사이에서 여러 값을 선택할 수 있습니다.
* **빈도**: 빈도를 사용하면 연속된 Backup 사이의 시간 간격을 지정할 수 있습니다. 예를 들어 &quot;12시간마다&quot;로 설정하면 Backup은 12시간 간격으로 수행됩니다. 빈도는 &quot;6시간마다&quot;부터 &quot;48시간마다&quot;까지 지정할 수 있으며, 선택 가능한 시간별 간격은 다음과 같습니다: `6`, `8`, `12`, `16`, `20`, `24`, `36`, `48`.
* **시작 시간**: 매일 Backup을 예약할 시작 시간입니다. 시작 시간을 지정하면 Backup &quot;빈도&quot;는 기본적으로 24시간마다 1회로 설정됩니다. ClickHouse Cloud는 지정된 시작 시간으로부터 1시간 이내에 Backup을 시작합니다.

보존 기간은 Backup 데이터를 얼마나 오래 보관할지를 결정하고, 빈도는 가장 최근 복원 지점이 얼마나 오래되었는지, 즉 복구 시점 목표(RPO)를 결정합니다. 예를 들어 보존 기간을 1일, 빈도를 48시간으로 설정하면 일반적으로 복원 가능한 Backup이 최소 1개 이상 존재합니다. 가장 최근의 복원 가능한 Backup은 생성된 지 48시간 가까이 지났을 수 있으며, 서비스에는 복원에 필요한 Backup 체인이 유지되면서 복원 가능한 지점이 1개 또는 2개 존재할 수 있습니다.

<Note>
  사용자 지정 일정은 해당 서비스에 적용되는 ClickHouse Cloud의 기본 Backup 정책보다 우선합니다.

  드문 경우 Backup 스케줄러가 Backup에 지정된 **시작 시간**을 따르지 않을 수 있습니다. 구체적으로는 현재 예약된 Backup 시점으로부터 24시간 이내에 성공한 Backup이 트리거된 경우 이런 현상이 발생합니다. 이는 Backup에 적용되는 재시도 메커니즘 때문에 발생할 수 있습니다. 이런 경우 스케줄러는 해당 날짜의 Backup을 건너뛰고, 다음 날 예약된 시간에 Backup을 다시 시도합니다.
</Note>

Backup 설정 단계는 [&quot;Backup 일정 설정&quot;](/ko/products/cloud/guides/backups/configurable-backups)을 참조하십시오.

## Bring Your Own Bucket (BYOB) 백업 {#byob}

ClickHouse Cloud에서는 자체 클라우드 서비스 제공업체(CSP) 계정의 스토리지(AWS S3, Google Cloud Storage 또는 Azure Blob Storage)로 백업을 내보낼 수 있습니다.
자체 버킷으로 백업하도록 구성하면 ClickHouse Cloud는 기본적으로 자체 백업도 계속 생성합니다.
백업 보존 설정은 사용자 버킷에 기록되는 백업에 적용됩니다. ClickHouse Cloud가 관리하는 백업에는 기본 보존 정책이 적용됩니다.

ClickHouse Cloud 백업의 동작 방식에 대한 자세한 내용은 [백업](/ko/products/cloud/guides/backups/review-and-restore-backups) 문서를 참조하십시오.

이 가이드에서는 AWS, GCP, Azure 객체 스토리지로 백업을 내보내는 방법과, 계정에 있는 해당 백업을 새로운 ClickHouse Cloud 서비스로 복원하는 방법을 안내합니다.
또한 백업을 사용자 버킷으로 내보내고 이를 복원할 수 있는 백업 / 복원 명령도 제공합니다.

<Info>
  **리전 간 백업**

  동일한 클라우드 제공업체 내에서
  다른 리전으로 백업을 내보내는 경우에는 [데이터 전송](/ko/products/cloud/reference/billing/network-data-transfer)
  요금이 부과됩니다.

  현재 [Transparent Data Encryption (TDE)](/ko/products/cloud/guides/security/cmek#transparent-data-encryption-tde)를 사용하는 서비스나 규제 대상 서비스에 대해서는 백업 / 복원을 지원하지 않습니다.
</Info>

AWS, GCP, Azure 객체 스토리지에 전체 백업 및 증분 백업을 수행하는 방법과 백업에서 복원하는 방법에 대한 예시는 [&quot;자체 Cloud 계정으로 백업 내보내기&quot;](/ko/products/cloud/guides/backups/bring-your-own-backup/export-backups-to-own-cloud-account)를 참조하십시오.

### Backup 옵션 {#backup-options}

자체 클라우드 계정으로 백업을 내보내는 방법은 두 가지입니다:

<Steps>
  <Step title="Cloud Console UI를 통해" id="via-ui">
    외부 백업은 [UI에서 구성할 수 있습니다](/ko/products/cloud/guides/backups/bring-your-own-backup/backup-restore-from-ui).
    기본적으로 백업은 [기본 백업 정책](/ko/products/cloud/features/backups/overview#default-backup-policy)에 지정된 대로 매일 수행됩니다.
    또한 자체 클라우드 계정으로 내보내는 [설정 가능한](/ko/products/cloud/guides/backups/configurable-backups) 백업도 지원하므로, 사용자 지정 일정을 설정할 수 있습니다.
    버킷으로 내보내는 모든 백업은 이전 또는 이후의 다른 백업과 연결되지 않은 전체 백업이라는 점에 유의하십시오.
  </Step>

  <Step title="SQL 명령 사용" id="using-commands">
    [SQL 명령](/ko/products/cloud/guides/backups/bring-your-own-backup/backup-restore-using-commands)을 사용하여 버킷으로 백업을 내보낼 수 있습니다.
  </Step>
</Steps>

<Warning>
  ClickHouse Cloud는 SQL 명령으로 내보낸 백업의 수명 주기를 관리하지 않습니다.
  고객은 컴플라이언스 기준 준수와 비용 관리를 위해 이러한 백업을 적절히 관리할 책임이 있습니다.
  백업이 손상되면 복원할 수 없습니다.
</Warning>
