서비스 삭제 보호는 서비스별 설정으로, 해제하기 전까지 서비스 삭제를 차단합니다. 클라우드 콘솔, [ClickHouse Cloud API](/ko/cloud/manage/api/api-overview) 또는 Terraform에서 실수로 삭제되는 일이 없어야 하는 ClickHouse Cloud 서비스에 이 설정을 사용하십시오.

<Note>
  이 설정은 ClickHouse Cloud 서비스에 적용되며, [ClickHouse Managed Postgres](/ko/cloud/managed-postgres) 서비스에는 적용되지 않습니다.
</Note>

보호 기능은 기본적으로 해제되어 있습니다. 보호 기능을 해제해도 서비스가 삭제되지는 않습니다. 보호된 서비스도 정상적으로 계속 실행되며, 쿼리, 스케일링 및 기타 설정은 그대로 유지됩니다.

보호 기능이 켜져 있는 동안에는 삭제 요청이 거부됩니다. 보호 기능을 해제하기 전까지 `DELETE /v1/organizations/{organizationId}/services/{serviceId}`는 HTTP `409`를 반환합니다. 또한 서비스를 삭제하려면 먼저 서비스를 중지해야 하며, 삭제는 비동기로 진행됩니다.

## 변경 권한(permission) {#who-can-change-it}

보호 기능을 켜거나 끄려면 [`control-plane:service:delete`](/ko/cloud/security/console-roles) 권한(permission)이 필요합니다. 조직 관리자에게는 이 권한(permission)이 있습니다. 자세한 내용은 [콘솔 역할 및 권한(permission)](/ko/cloud/security/console-roles)을 참조하십시오.

보호 기능을 켜려면 해당 조직에서 삭제 보호(deletion protection) 기능도 사용할 수 있어야 합니다. ClickHouse Cloud 조직에서는 이 기능을 사용할 수 있습니다. 조직에서 이 기능을 사용할 수 없으면 `deletionProtection`을 `true`로 설정하는 생성 또는 업데이트 요청은 HTTP `400`을 반환합니다. 보호 기능을 끌 때는 이 검사를 거치지 않습니다. `deletionProtection`을 `false`로 설정하는 요청은 이미 보호된 서비스에 대한 요청을 포함하여 모두 허용됩니다.

| 작업                                 | 권한(permission)                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 콘솔 스위치 켜기 또는 끄기                    | 서비스에 대한 `control-plane:service:delete`                                                               |
| 기존 서비스에 `deletionProtection` 설정    | 서비스에 대한 `control-plane:service:manage` 및 `control-plane:service:delete`                              |
| 서비스에 이미 설정된 값 전송                   | `control-plane:service:manage`만 필요합니다. 현재 값을 그대로 다시 전송할 때는 `control-plane:service:delete`가 필요하지 않습니다 |
| `deletionProtection: true`로 서비스 생성 | `control-plane:organization:create-service` 및 조직의 모든 서비스에 대해 부여된 `control-plane:service:delete`      |
| 서비스 삭제                             | 서비스에 대한 `control-plane:service:delete`. 서비스가 중지되어 있고 보호 기능이 꺼져 있어야 합니다                               |

ClickStack 서비스는 클라우드 API로 업데이트할 수 없습니다. ClickStack 서비스의 삭제 보호는 콘솔에서 켜거나 끄십시오.

## 콘솔에서 보호 기능 켜기/끄기 {#console}

서비스를 열고 **설정**으로 이동하십시오. **삭제 보호** 항목에서 스위치를 켜거나 끄십시오. 변경 사항은 즉시 저장됩니다.

해당 서비스에 대한 `control-plane:service:delete` 권한이 있는 사용자는 누구나 이 스위치를 사용할 수 있습니다. 보호 기능이 켜져 있는 동안에는 스위치를 끌 때까지 콘솔에서 삭제 작업을 수행할 수 없습니다.

## 클라우드 API로 설정하기 {#cloud-api}

서비스 객체에는 불리언 필드인 `deletionProtection`이 있습니다. 서비스를 생성하거나(`POST /v1/organizations/{organizationId}/services`) 업데이트할 때(`PATCH /v1/organizations/{organizationId}/services/{serviceId}`) 이 필드를 설정하십시오. 조회(get) 및 목록(list) 응답에도 이 필드가 포함됩니다. 이 필드가 없으면 해당 서비스는 보호되지 않습니다.

보호 기능 활성화:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": true}'
```

보호된 서비스를 삭제하려면 보호를 해제하고 서비스를 중지한 다음, 서비스가 완전히 중지될 때까지 기다린 후 삭제하십시오. `"command": "stop"`을 지정한 `PATCH .../state` 요청에는 `control-plane:service:manage` 권한이 필요하며, 이 요청은 서비스가 중지되기 전에 응답을 반환합니다. 서비스가 아직 `stopping` 상태일 때 삭제를 요청하면 거부됩니다. 보호된 서비스에 삭제를 요청하면 `409`가 반환되며 서비스는 삭제되지 않고 그대로 유지됩니다.

보호 해제:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  -d '{"deletionProtection": false}'
```

다음과 같이 중지를 요청하십시오:

```bash
curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X PATCH \
  -H "Content-Type: application/json" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID/state" \
  -d '{"command": "stop"}'
```

`result.state`가 `stopped`가 될 때까지 기다린 후 삭제하십시오:

```bash
while [ "$(curl --silent --user "$KEY_ID:$KEY_SECRET" \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID" \
  | jq -r '.result.state')" != "stopped" ]; do
  sleep 5
done

curl --silent --user "$KEY_ID:$KEY_SECRET" \
  -X DELETE \
  "https://api.clickhouse.cloud/v1/organizations/$ORG_ID/services/$SERVICE_ID"
```

## Terraform {#terraform}

<Note>
  `deletion_protection`은 최신 릴리스된 provider인 [v3.43.0](https://github.com/ClickHouse/terraform-provider-clickhouse/releases/tag/v3.43.0)에는 포함되어 있지 않습니다. 이 속성은 [terraform-provider-clickhouse#799](https://github.com/ClickHouse/terraform-provider-clickhouse/pull/799)에서 추가되었으며, 해당 PR은 머지되었지만 아직 릴리스에는 포함되지 않았습니다. 아래 예시를 v3.43.0에서 실행하면 지원되지 않는 인수 오류가 발생합니다. 이 속성이 포함된 v3.43.0 이후의 provider 릴리스를 사용하십시오.
</Note>

`clickhouse_service` 리소스는 `deletion_protection`을 지원합니다. 이 값이 `true`로 설정되어 있는 동안에는 `terraform destroy`와 서비스 교체를 유발하는 모든 변경이 실패합니다. 서비스를 삭제하려면 먼저 이 값을 `false`로 설정하고 이 변경만 단독으로 적용한 다음 서비스를 삭제하십시오.

구성에서 `deletion_protection`을 제거해도 현재 설정은 그대로 유지됩니다.

```hcl
resource "clickhouse_service" "example" {
  # ...

  deletion_protection = true
}
```

서비스를 생성할 때 `deletion_protection = true`를 설정하려면 조직 내 모든 서비스를 삭제할 수 있는 API Key가 필요합니다. 생성 후 이 값을 변경하려면 해당 서비스에 대한 삭제 권한(permission)이 필요합니다.
