<Note>
  승인된 도메인(Approved domains) 기능은 현재 공개 미리 보기 단계입니다. 액세스를 요청할 필요 없이 [조직에서 직접 활성화할 수 있습니다.](/ko/products/cloud/features/self-service-previews)
</Note>

승인된 도메인을 사용하면 새 사용자가 이메일 도메인을 기준으로 ClickHouse Cloud 조직에 참여할 수 있습니다. 소유한 도메인을 인증한 후에는 도메인이 일치하는 사용자를 자동으로 추가하거나 초대를 보낼 수 있으며, 기본 역할도 할당할 수 있습니다.

이 가이드에서는 도메인을 추가하고 인증하는 방법, 등록을 구성하는 방법, 승인된 도메인을 관리하는 방법을 설명합니다.

## 시작하기 전에 {#before-you-begin}

조직 설정을 관리할 수 있는 권한(permission)과 도메인의 DNS 설정에 TXT 레코드를 추가할 수 있는 권한이 필요합니다.

<Note>
  승인된 도메인 기능은 SAML SSO 또는 SCIM을 사용하지 않는 조직에서 사용할 수 있습니다. IdP(Identity Provider)를 사용하는 조직은 [SAML SSO 설정](/ko/products/cloud/guides/security/cloud-access-management/saml-sso-setup) 가이드를 참고하십시오.
</Note>

## 작동 방식 {#how-it-works}

사용자가 ClickHouse Cloud 계정을 처음 생성하면 ClickHouse는 해당 사용자의 이메일 도메인을 승인된 도메인과 대조합니다. 도메인이 일치하는 각 조직에서는 구성된 등록 방식과 기본 역할이 적용됩니다.

| 등록 방식      | 동작                                                        |
| ---------- | --------------------------------------------------------- |
| **자동 참여**  | 사용자가 조직에 추가됩니다. 이후 콘솔에서 사용자에게 액세스 권한을 확인하고 조직을 열도록 안내합니다. |
| **초대 보내기** | 사용자에게 초대가 발송되며, 조직에 참여하려면 초대를 수락해야 합니다.                   |

등록은 신규 계정에만 적용됩니다. 기존 사용자를 추가하려면 [초대를 보내십시오](/ko/products/cloud/guides/security/cloud-access-management/manage-cloud-users).

이메일 도메인은 정확히 일치해야 합니다. 예를 들어 `example.com`은 `user@example.com`과는 일치하지만 `user@team.example.com`과는 일치하지 않습니다. 하위 도메인은 별도로 추가하고 검증하십시오.

여러 조직이 동일한 도메인을 승인한 경우 각 조직의 등록 설정이 개별적으로 적용됩니다. 여러 조직에 자동으로 추가된 사용자는 열 조직을 선택할 수 있습니다.

## 도메인 추가 및 확인 {#add-and-verify-a-domain}

<Steps>
  <Step title="승인된 도메인 열기" id="open-approved-domains">
    ClickHouse Cloud 콘솔에서 조직 설정을 엽니다. **승인된 도메인**에서 **Add domain**을 클릭하십시오.
  </Step>

  <Step title="도메인 추가" id="add-your-domain">
    `example.com`과 같은 이메일 도메인을 입력하고 **Add**를 클릭하십시오.

    조직당 확인 대기 중인 도메인을 포함하여 최대 20개의 도메인을 등록할 수 있습니다. `gmail.com`과 같은 퍼블릭 이메일 도메인 및 일회용 이메일 도메인은 승인할 수 없습니다.
  </Step>

  <Step title="등록 및 기본 역할 구성" id="configure-enrollment-and-default-roles">
    도메인의 **자동 등록** 방식과 **기본 역할**을 선택하십시오.

    새 도메인의 기본값은 Send an invite 방식과 Member 역할입니다. 등록은 확인이 완료된 후에 시작됩니다.

    **사용자 정의 역할을 포함하여** 하나 이상의 역할을 선택할 수 있습니다. 목록에는 할당 권한이 있는 역할만 표시됩니다. **Admin**과 같이 조직을 관리할 수 있는 역할은 선택할 수 없습니다.

    선택한 역할이 삭제되거나 더 이상 할당할 수 없게 되면 해당 역할은 도메인에서 제거됩니다. 선택된 역할이 하나도 남지 않으면 신규 사용자에게는 Member 역할이 부여됩니다.
  </Step>

  <Step title="DNS 레코드 추가" id="add-the-dns-record">
    콘솔에 표시된 값을 사용하여 DNS provider에서 TXT 레코드를 생성하십시오.

    | 필드            | 값                                                                |
    | ------------- | ---------------------------------------------------------------- |
    | Name/Host     | 표시된 **TXT record name**: `@` 또는 도메인 자체를 나타내는 provider별 동등한 값입니다. |
    | Value/Content | `clickhouse-verification=`으로 시작하는 전체 **TXT record value**입니다.    |

    기존 TXT 레코드는 그대로 두고 이 레코드를 추가하십시오.
  </Step>

  <Step title="도메인 확인" id="verify-the-domain">
    ClickHouse Cloud로 돌아가 확인되지 않은 도메인 옆의 갱신 아이콘을 클릭하십시오. 확인이 완료되면 상태가 **Verified**로 변경됩니다.

    DNS 변경 사항이 전파되기까지 시간이 걸릴 수 있습니다. 확인이 바로 완료되지 않으면 잠시 기다린 후 다시 시도하십시오.
  </Step>
</Steps>

## 등록 설정 업데이트 {#update-enrollment-settings}

**승인된 도메인**을 열고 해당 도메인의 **기본 역할** 또는 **자동 등록** 설정을 변경하십시오. 변경 사항은 자동으로 저장되며 이후의 등록부터 적용됩니다.

기존 멤버의 역할을 변경하려면 [사용자 역할 할당 관리](/ko/products/cloud/guides/security/cloud-access-management/manage-cloud-users#manage-role-assignments)를 참고하십시오.

## 도메인 제거 {#remove-a-domain}

**승인된 도메인**을 열고 해당 도메인 옆의 휴지통 아이콘을 클릭하십시오.

도메인을 제거하면 이후 해당 도메인을 통한 등록이 더 이상 이루어지지 않습니다. 기존 멤버와 초대는 그대로 유지됩니다. 필요한 경우 멤버 제거 또는 초대 취소를 별도로 진행하십시오.

## 제한 사항 {#limitations}

* 등록은 사용자가 처음 계정을 생성할 때만 이루어집니다. 기존 사용자는 소급하여 추가되지 않습니다.
* 조직을 떠났거나 조직에서 제거된 사용자는 다시 로그인해도 자동으로 추가되지 않습니다.
* 이미 존재하는 멤버와 만료되지 않은 초대는 중복 생성되지 않습니다.
* 조직 멤버십 제한 사항은 그대로 적용됩니다.
* SAML SSO를 구성하거나 SCIM을 활성화하면 승인된 도메인 기반 등록이 중단됩니다.

## 문제 해결 {#troubleshooting}

### 승인된 도메인이 표시되지 않거나 편집할 수 없는 경우 {#approved-domains-missing}

SAML SSO를 사용하는 조직에서는 이 섹션이 표시되지 않습니다. 승인된 도메인을 편집하려면 조직 설정을 관리할 수 있는 권한(permission)이 필요합니다.

### 도메인 확인 실패 {#domain-verification-fails}

TXT 레코드가 올바른 도메인에 등록되어 있고 콘솔에 표시된 현재 값과 일치하는지 확인하십시오. DNS 전파가 완료될 때까지 기다린 후 다시 시도하십시오.

콘솔에 토큰이 오래되었다고 표시되면 확인 값을 현재 표시된 값으로 바꾸십시오. 확인 요청이 만료되었다면 확인 절차를 처음부터 다시 시작하십시오.

### 도메인이 거부되는 경우 {#domain-rejected}

해당 도메인이 공개 이메일 도메인 또는 일회용 이메일 도메인이 아닌지, 그리고 조직의 인증된 도메인과 인증되지 않은 도메인을 합쳐 20개 미만인지 확인하십시오.

### 사용자가 추가되지 않은 경우 {#user-not-added}

다음 사항을 확인하십시오.

* 사용자가 새 ClickHouse Cloud 계정을 생성하고 있는지 여부
* 사용자의 이메일 도메인이 인증된 도메인과 정확히 일치하는지 여부
* 조직에서 SAML SSO 또는 SCIM을 사용하지 않는지 여부
* 조직에서 멤버 초대가 허용되어 있는지 여부

**Send an invite**를 선택한 경우 사용자가 초대를 수락해야 멤버가 됩니다. 기존 계정의 경우 **Users and roles**에서 초대를 보내십시오.
