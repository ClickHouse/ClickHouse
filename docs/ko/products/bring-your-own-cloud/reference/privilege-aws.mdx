이 페이지에서는 ClickHouse BYOC가 AWS 계정에서 사용하는 각 IAM 정책과 역할(role)의 권한, 범위, 목적을 설명합니다. BYOC 권한(permission) 모델의 개요는 [BYOC 권한(privilege)](/ko/products/bring-your-own-cloud/reference/privilege)을 참조하십시오.

## 부트스트랩 IAM role {#bootstrap-iam-role}

다음 표는 부트스트랩 IAM role인 `ClickHouseManagementRole`의 각 정책을 설명합니다.

| 정책                                               | 권한                                                                                                                                                  | 범위                                                                                                                                                                                                                                                                                                     | 목적                                                                                                                                                              |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BasePolicy` (인라인)                               | 호출자의 아이덴티티를 조회합니다. 서비스 쿼터와 AWS 기본 서비스 쿼터를 조회합니다.                                                                                                    | 모든 리소스. 읽기 전용.                                                                                                                                                                                                                                                                                         | 프로비저닝 전 상태 및 쿼터 확인                                                                                                                                              |
| `ClickHouse-IAM-Base-Policy`                     | IAM 역할, 정책 및 인스턴스 프로파일을 조회합니다. AWS 서비스에 역할(role)을 전달합니다. 서비스 연결 역할을 생성합니다. 클러스터의 OpenID Connect(OIDC) 공급자를 생성하고, 태그를 지정하고, 삭제합니다.                   | 읽기: 모든 IAM 역할 및 정책(Policies). 역할 전달: BYOC 역할(role) 이름(예: `*-k8s-worker`, `*-karpenter-node`, `*-CH-S3-Role`)으로만 제한되며, EKS, EKS Pod Identity, EC2에만 전달할 수 있습니다. 서비스 연결 역할: EKS, EKS 노드 그룹, VPC Lattice용으로만 제한됩니다. OIDC 공급자: `clickhouse-byoc=true` 태그로 제한되며, 이 역할(role)은 모든 OIDC 공급자에 이 태그를 추가할 수 있습니다. | IAM 상태를 조회합니다. BYOC 역할을 EKS와 EC2에 전달합니다.                                                                                                                        |
| `ClickHouse-IAM-Extended-Policy` (선택 사항, 기본 활성화) | IAM 역할, 정책, 인스턴스 프로파일을 생성, 변경 및 삭제합니다.                                                                                                              | `clickhouse-byoc=true` 태그가 지정된 리소스로 제한되며, 이 역할(role)은 모든 역할(role), 정책, 인스턴스 프로파일에 이 태그를 추가할 수 있습니다. 제한 없음: 인스턴스 프로파일에서 역할(role) 삭제.                                                                                                                                                                    | 추가 역할을 생성합니다(자세한 내용은 다음 섹션 참조). [자체 IAM 역할을 사용](/ko/products/bring-your-own-cloud/onboarding/customization-aws#customer-managed-iam-roles)하는 경우에는 이 정책이 필요하지 않습니다. |
| `ClickHouse-S3-Policy`                           | 버킷을 생성합니다. 버킷 구성(태그, 수명 주기, 암호화, 소유권, 퍼블릭 액세스 차단, 메트릭)을 조회하고 설정합니다. 버킷 내 객체 목록을 조회합니다. 객체 읽기 및 쓰기는 허용되지 않습니다. 버킷 삭제는 허용되지 않습니다.                     | 이름이 `*.*.aws.clickhouse.cloud-shared`, `*.*.aws.clickhouse.cloud-backup`, `*.*.aws.clickhouse.cloud-monitoring`인 버킷으로 한정                                                                                                                                                                               | ClickHouse 테이블(table) 데이터, 백업 및 모니터링 데이터를 저장하는 버킷을 관리합니다                                                                                                        |
| `ClickHouse-EKS-Policy`                          | EKS 클러스터, 추가 기능, 노드 그룹 및 파드 아이덴티티 연결을 생성, 변경, 삭제합니다. 모든 EKS 리소스를 읽습니다.                                                                              | 쓰기: 이름이 `clickhouse-cloud-`로 시작하는 리소스만 해당합니다. 읽기: 모든 EKS 리소스에 해당합니다.                                                                                                                                                                                                                                   | EKS 클러스터와 해당 클러스터의 추가 기능 및 노드 그룹을 관리합니다                                                                                                                         |
| `ClickHouse-EC2-Policy`                          | EC2, Elastic Load Balancing 및 Auto Scaling 정보를 조회합니다. 인스턴스를 시작합니다. 시작 템플릿, 네트워크 인터페이스, 보안 그룹, 탄력적 IP 및 태그를 관리합니다. 인스턴스, 네트워크 인터페이스 및 볼륨의 속성을 변경합니다. | 보안 그룹: `clickhouse-byoc=true` 태그 또는 `aws:eks:cluster-name` = `clickhouse-cloud-*`. Elastic IP 및 태그 변경: `clickhouse-byoc=true` 태그(해당 역할(role)이 모든 리소스에 추가할 수 있음). 범위 제한 없음: 인스턴스, 시작 템플릿, 네트워크 인터페이스, 볼륨.                                                                                               | 클러스터의 네트워크 액세스를 제어하는 노드와 보안 그룹을 관리합니다                                                                                                                           |
| `ClickHouse-VPCWrite-Policy` (선택 사항, 기본적으로 활성화)  | VPC, 서브넷, NAT 게이트웨이, 인터넷 게이트웨이, 라우트 테이블 및 VPC 엔드포인트 생성, 변경 및 삭제                                                                                     | `clickhouse-byoc=true` 태그가 지정된 리소스로 한정                                                                                                                                                                                                                                                                 | BYOC VPC용입니다. [자체 VPC를 사용](/ko/products/bring-your-own-cloud/onboarding/customization-aws#customer-managed-vpc-aws)하는 경우 이 정책은 필요하지 않습니다.                          |
| `ClickHouse-VPCPrivateLink-Policy`               | VPC 엔드포인트 서비스 생성, 변경 및 삭제                                                                                                                           | `clickhouse-byoc=true` 태그가 지정된 리소스로 한정                                                                                                                                                                                                                                                                 | 서비스용 AWS PrivateLink 엔드포인트                                                                                                                                      |
| `ClickHouse-VPCLattice-Policy`                   | VPC Lattice 리소스 게이트웨이와 리소스 구성, AWS RAM 리소스 공유를 생성, 변경, 삭제합니다. VPC Lattice 및 AWS RAM 리소스를 조회합니다.                                                     | 쓰기: `clickhouse-byoc=true` 태그가 지정된 리소스로 한정됩니다. 읽기: 모든 VPC Lattice 및 AWS RAM 리소스가 대상입니다.                                                                                                                                                                                                                | EKS API에 대한 프라이빗 액세스                                                                                                                                            |
| `ClickHouse-CloudWatch-Policy`                   | CloudWatch Logs를 조회합니다. 로그 그룹을 생성합니다. 로그 그룹에 태그를 지정하고 보존 기간을 설정합니다.                                                                                 | 생성: `clickhouse-byoc=true` 태그가 지정된 경우에만 허용됩니다. 태그 지정 및 보존 기간 설정: `/aws/eks/clickhouse-cloud-*` 로그 그룹에만 허용됩니다. 읽기: 모든 로그 그룹.                                                                                                                                                                            | EKS 컨트롤 플레인 로그                                                                                                                                                  |
| `ClickHouse-KMS-Policy` (선택 사항, 기본값: 비활성화)       | 키 세부 정보를 조회합니다. 키에 대한 권한 부여를 생성합니다.                                                                                                                 | ClickHouse BYOC AWS 계정의 KMS 키만 해당                                                                                                                                                                                                                                                                      | EKS 시크릿 암호화                                                                                                                                                     |
| `ClickHouse-KMSTDE-Policy` (선택 사항, 기본값은 비활성화)    | KMS 키를 생성합니다. 키와 키 정책을 조회합니다. 키 순환을 활성화합니다. 키에 태그를 지정합니다. 암호화, 복호화, 키 정책 변경 또는 키 삭제는 허용하지 않습니다.                                                     | `clickhouse-byoc=true` 태그(키 정책에서 허용하는 경우 이 역할(role)이 어떤 키에든 추가할 수 있음)                                                                                                                                                                                                                                  | 투명한 데이터 암호화(Transparent Data Encryption, TDE)용 키                                                                                                                |

정확한 정책 문서는 [Terraform 모듈](https://github.com/ClickHouse/terraform-byoc-onboarding/blob/main/modules/aws/main.tf) 또는 [CloudFormation 템플릿](https://s3.us-east-2.amazonaws.com/clickhouse-public-resources.clickhouse.cloud/cf-templates/byoc_v2.yaml)에서 확인하십시오.

## 컨트롤러가 생성하는 추가 IAM 역할(role) {#additional-iam-roles-created-by-the-controller}

CloudFormation 또는 Terraform으로 생성되는 `ClickHouseManagementRole` 외에도, 컨트롤러는 BYOC 인프라마다 여러 개의 추가 역할(role)을 생성합니다.
각 역할(role)에는 `<infra>-<region>-` 접두사가 붙습니다. `<infra>`는 BYOC 인프라의 이름이고, `<region>`은 AWS 리전입니다.

| 역할(role)                               | 권한                                                                                                                                                                      | 용도                                         |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `data-plane-mgmt`                | EKS 읽기. BYOC 버킷의 객체 나열 및 삭제, 암호화·버전 관리·수명 주기 설정. 로드 밸런서 및 Auto Scaling 그룹 읽기. ClickHouse 관리 서비스가 사용자의 external ID를 사용하여 이 역할(role)을 수임합니다.                                    | ClickHouse 서비스 및 클러스터의 일상적인 관리             |
| `k8s-control-plane`              | AWS 관리형 `AmazonEKSClusterPolicy`, `AmazonEKSServicePolicy`, `AmazonEKSVPCResourceController`. EKS만 이 역할(role)을 수임할 수 있습니다.                                                    | EKS 클러스터 역할(role)                                |
| `k8s-worker`                     | AWS 관리형 `AmazonEKSWorkerNodePolicy`, `AmazonEKS_CNI_Policy`, `AmazonEC2ContainerRegistryReadOnly`. ClickHouse 컨테이너 이미지를 가져오기 위해 읽기 전용 역할(role)을 수임합니다. EC2만 이 역할(role)을 수임할 수 있습니다. | 시스템 노드용 노드 역할(role)                              |
| `karpenter-node` (역할(role) 및 인스턴스 프로필) | `k8s-worker`와 동일하며, `AmazonSSMManagedInstanceCore`가 추가됩니다. EC2만 이 역할(role)을 수임할 수 있습니다.                                                                                       | ClickHouse 서버 및 Keeper 노드용 노드 역할(role)           |
| `karpenter-controller`           | 이 클러스터의 태그가 지정된 EC2 인스턴스 시작 및 종료. BYOC 리전의 EC2 읽기. `karpenter-node` 역할(role)만 전달 가능. 가격 및 EKS AMI 파라미터 읽기.                                                                    | Karpenter: ClickHouse용 노드 추가 및 제거          |
| `cluster-autoscaler`             | Auto Scaling 그룹 읽기. Auto Scaling 그룹의 희망 용량 설정 및 인스턴스 종료.                                                                                                                | 시스템 노드 그룹 스케일링                             |
| `load-balancer-controller`       | AWS가 게시한 AWS Load Balancer Controller 정책. 로드 밸런서 및 대상 그룹을 변경하려면 클러스터의 `elbv2.k8s.aws/cluster` 태그가 있어야 합니다(클러스터 무관). 범위 제한 없음: 리스너, 규칙, 대상 등록, 태그.                       | 서비스 엔드포인트용 Network Load Balancer 생성        |
| `ebs-csi-driver`                 | AWS가 게시한 EBS CSI 드라이버 정책. 볼륨 및 스냅샷을 삭제하려면 드라이버 태그가 있어야 합니다.                                                                                                             | ClickHouse 및 Keeper용 디스크                   |
| `CH-S3-Role`                     | BYOC 공유 버킷 및 백업 버킷의 ClickHouse 접두사 아래에서만 모든 S3 작업 허용. ClickHouse S3 액세스를 위해 사용자가 설정한 역할(role) 수임. ClickHouse로 사용량 데이터를 전송하기 위한 역할(role) 수임.                                         | ClickHouse 서버 파드의 ID. 테이블 데이터와 백업을 읽고 씁니다. |
| `thanos`                         | BYOC 모니터링 버킷의 객체 나열, 읽기, 쓰기, 삭제                                                                                                                                         | 모니터링용 메트릭 저장                               |
| `state-exporter`                 | ClickHouse 역할(role) 수임. 그 외 권한 없음.                                                                                                                                            | 인프라 상태를 ClickHouse로 전송                     |
| `clickhouse-scraper`             | ClickHouse 역할(role) 수임. 그 외 권한 없음.                                                                                                                                            | 과금용 사용량 데이터를 ClickHouse로 전송                |
| `kube-metric-forwarder-asc`      | ClickHouse 역할(role) 수임. 그 외 권한 없음.                                                                                                                                            | 자동 확장을 위해 Kubernetes 메트릭을 ClickHouse로 전송   |

정확한 정책 문서는 [Terraform 모듈](https://github.com/ClickHouse/terraform-byoc-onboarding/blob/main/modules/aws-per-infra-iam/main.tf)을 참조하십시오.
