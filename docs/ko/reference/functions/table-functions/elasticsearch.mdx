[Elasticsearch](https://www.elastic.co/elasticsearch) 인덱스에 저장된 문서(document)를 대상으로 `SELECT` 쿼리를 실행할 수 있습니다. 각 문서는 하나의 행으로 반환됩니다. 문서의 `_source`는 [JSON](/ko/reference/data-types/newjson) 타입의 단일 컬럼으로 제공되며, 문서 ID와 인덱스 이름은 가상 컬럼(virtual columns)으로 조회할 수 있습니다. 이 함수는 읽기 전용입니다.

## 구문 {#syntax}

```sql
elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
elasticsearch(named_collection[, query('...')][, key = value, ...][, structure = 'document JSON'][, SETTINGS ...])
```

<Note>
  Elasticsearch 통합은 실험적 기능입니다. [`enable_elasticsearch`](/ko/reference/settings/session-settings/enable#enable_elasticsearch) 설정을 사용하여 활성화하십시오:

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

## 인수 {#arguments}

| 인수             | 설명                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | Elasticsearch 클러스터의 기준 URL입니다(예: `https://localhost:9200`). 자격 증명, 쿼리 문자열, 프래그먼트가 포함되지 않은 `http` 또는 `https` URL이어야 합니다.                                                                |
| `index`        | 읽을 인덱스입니다. Elasticsearch 특정 시점(point in time) API에서 허용하는 형식에 따라 별칭, 쉼표로 구분된 목록, 와일드카드 패턴도 지정할 수 있습니다. 일치하는 인덱스가 없는 패턴을 지정하면 오류가 발생합니다.                                                 |
| `user`         | HTTP 기본 인증에 사용할 사용자 이름입니다(선택 사항).                                                                                                                                                      |
| `password`     | HTTP 기본 인증에 사용할 비밀번호입니다(선택 사항이며, `user`와 함께 지정해야 합니다).                                                                                                                                 |
| `query('...')` | 읽을 문서를 선택하는 JSON 형식의 Elasticsearch [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) 객체입니다(선택 사항). 위치 인수 뒤에 지정해야 합니다. 기본값: `{"match_all": {}}`. |

`url`, `index`, `user`, `password` 인수는 `key = value` 형식으로도 지정할 수 있습니다. 위치 인수는 이 순서대로 값이 할당되며, 같은 인수를 위치 인수와 키로 동시에 지정하거나 같은 키를 두 번 지정하면 오류가 발생합니다.

다음 인수는 `key = value` 형식(또는 명명된 컬렉션의 키)으로 지정할 수 있습니다.

| 키(Key)         | 설명                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `user`         | HTTP 기본 인증에 사용할 사용자 이름입니다.                                                                                                      |
| `password`     | HTTP 기본 인증에 사용할 비밀번호입니다.                                                                                                        |
| `bearer_token` | `Authorization: Bearer <token>` 형식으로 전송되는 토큰입니다(예: Elasticsearch 서비스 계정 토큰).                                                    |
| `api_key`      | `Authorization: ApiKey <api_key>` 형식으로 전송되는 Elasticsearch API Key입니다. 값은 API Key 생성 API가 반환하는 Base64로 인코딩된 `id:api_key` 문자열입니다. |

명명된 컬렉션에는 `query` 키를 포함할 수 있습니다. 이를 재정의하려면 컬렉션 이름 뒤에 `query('...')` 또는 `query = '...'`를 지정하십시오.

이 외에도 테이블 함수에서는 다음 키를 사용할 수 있습니다.

| 키(Key)      | 설명                                                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `structure` | `'name JSON'` 형식의 테이블 구조(table structure)입니다. 구조에는 `JSON` 타입 컬럼이 정확히 하나만 포함되어야 하며, `_id`와 `_index`는 예약된 이름입니다. 기본값: `'document JSON'`. |

읽기 설정인 `keep_alive`와 `page_size`는 맨 끝의 `SETTINGS` 절로 전달할 수 있습니다. 각 설정에 대한 설명은 [`Elasticsearch` 테이블 엔진](/ko/reference/engines/table-engines/integrations/elasticsearch#creating-a-table)을 참고하십시오.

## 인증 {#authentication}

인증 메서드는 최대 1개만 지정할 수 있습니다.

1. **기본 인증**. `user`와 `password`를 전달합니다.
2. **Bearer 토큰**. `bearer_token`을 전달합니다.
3. **API Key**. `api_key`를 전달합니다.

이 중 아무것도 지정하지 않으면 요청은 익명으로 전송되며, 이 방식은 Elasticsearch에서 보안이 비활성화된 경우에만 동작합니다.

쿼리마다 자격 증명을 지정하지 않으려면 [명명된 컬렉션](/ko/concepts/features/configuration/server-config/named-collections)에 자격 증명을 저장하십시오. 명명된 컬렉션을 사용해 생성한 영구 테이블(`Elasticsearch` 테이블 엔진 또는 `CREATE TABLE ... AS elasticsearch(...)` 사용)은 해당 컬렉션의 종속 항목으로 등록됩니다. 따라서 이 테이블이 존재하는 동안에는 `DROP NAMED COLLECTION`을 실행할 수 없습니다.

## 가상 컬럼 {#virtual-columns}

* `_id` — 문서 ID입니다. 유형: `String`.
* `_index` — 문서를 읽어 온 인덱스의 이름입니다. 유형: `LowCardinality(String)`.

쿼리가 가상 컬럼(virtual columns)만 읽으면 Elasticsearch에 문서의 `_source`를 요청하지 않습니다. `_source`를 저장하지 않는 인덱스(매핑에서 `_source` 필드가 비활성화된 인덱스)는 가상 컬럼으로만 읽을 수 있습니다. 이러한 인덱스에서 `JSON` 컬럼을 읽는 쿼리는 빈 문서를 반환하지 않고 오류를 발생시키며 실패합니다.

## 예시 {#examples}

인덱스의 문서 수를 셉니다:

```sql
SELECT count()
FROM elasticsearch('https://localhost:9200', 'logs', 'elastic', 'changeme');
```

문서의 필드를 `JSON` 컬럼의 서브컬럼으로 읽습니다.

```sql
SELECT _id, document.timestamp, document.message
FROM elasticsearch('https://localhost:9200', 'logs', api_key = '...')
ORDER BY document.timestamp DESC
LIMIT 10;
```

Query DSL 객체를 사용해 Elasticsearch 측에서 데이터를 필터링하고 페이지 크기를 조정합니다:

```sql
SELECT _id
FROM elasticsearch('https://localhost:9200', 'logs',
                   query('{"term": {"level": "error"}}'),
                   bearer_token = '...',
                   SETTINGS page_size = 1000);
```

명명된 컬렉션 사용:

```xml
<clickhouse>
    <named_collections>
        <my_elasticsearch>
            <url>https://localhost:9200</url>
            <user>elastic</user>
            <password>changeme</password>
        </my_elasticsearch>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM elasticsearch(my_elasticsearch, index = 'logs');
```

## 제한 사항 {#limitations}

* 이 함수는 읽기 전용이며 `INSERT`는 지원되지 않습니다.
* 프레디케이트는 푸시다운되지 않습니다. `WHERE` 조건은 문서를 다운로드한 후 ClickHouse에서 적용되므로, Elasticsearch 측에서 필터링하려면 `query` 인수를 사용하십시오.
* `query`는 페이지의 `size`와 함께 전송됩니다. 따라서 `k`가 없는 `knn` 쿼리처럼 결과가 `size`에 따라 달라지는 쿼리는 `page_size`에 따라 다른 문서 집합을 반환합니다. 이러한 매개변수는 명시적으로 지정하십시오.
* 각 페이지는 별도의 검색 요청으로 전송되며, Elasticsearch는 `query`에 포함된 `now-1h`와 같은 날짜 연산을 요청마다 새로 평가합니다. 특정 시점은 문서는 고정하지만 시계는 고정하지 않으므로, 시간에 의존하는 `query`는 계속 이동하는 경계 부근의 문서를 아무런 경고 없이 누락할 수 있습니다. `query`에는 절대 날짜를 사용하십시오.
* 각 읽기 작업은 특정 시점을 연 뒤, `_shard_doc` 기준으로 정렬된 `search_after`를 사용해 결과를 페이지 단위로 순회하고, 마지막에 특정 시점을 닫습니다. 페이지 요청이 하나의 세그먼트에서라도 실패하거나 Elasticsearch에서 시간 초과되면, 부분 결과를 반환하지 않고 오류가 발생합니다.
* Elasticsearch 7.12 이상이 필요합니다. 이 함수는 특정 시점 API와 `_shard_doc` 정렬 필드를 사용하므로, 이전 버전의 Elasticsearch와 OpenSearch는 첫 번째 요청을 거부합니다.
* `page_size`는 Elasticsearch의 `index.max_result_window` 인덱스 설정값(기본값 `10000`)을 초과할 수 없습니다.
