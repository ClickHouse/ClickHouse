Amazon S3, Azure, HDFS 또는 로컬에 저장된 Apache [Paimon](https://paimon.apache.org/) 테이블에 읽기 전용 테이블과 유사한 인터페이스를 제공합니다.

## 구문 {#syntax}

```sql
paimon(url [,access_key_id, secret_access_key] [,format] [,structure] [,compression] [,extra_credentials])

paimonS3(url [,access_key_id, secret_access_key] [,format] [,structure] [,compression] [,extra_credentials])

paimonAzure(connection_string|storage_account_url, container_name, blobpath, [,account_name], [,account_key] [,format] [,compression_method])

paimonHDFS(path_to_table, [,format] [,compression_method])

paimonLocal(path_to_table, [,format] [,compression_method])
```

## 인수 {#arguments}

인수 설명은 각각 테이블 함수 `s3`, `azureBlobStorage`, `HDFS`, `file`의 인수 설명과 동일합니다.
`format`은 Paimon 테이블의 데이터 파일 포맷을 나타냅니다.

`paimonS3`에서는 선택적 `extra_credentials` 매개변수를 사용해 ClickHouse Cloud에서 역할 기반 접근을 위한 `role_arn`을 전달할 수 있습니다. 구성 단계는 [Secure S3](/ko/products/cloud/guides/data-sources/accessing-s3-data-securely)를 참조하십시오.

### 반환 값 {#returned-value}

지정된 Paimon 테이블의 데이터를 읽기 위한, 지정된 구조의 테이블입니다.

## 제한 사항 {#limitations}

읽기 시 병합(merge-on-read)이 구현되지 않아 기본 키 테이블은 Paimon이 병합 없이 읽는 경우에만 읽을 수 있습니다. 버킷의 모든 데이터 파일이
레벨 0보다 높은 레벨에 있고, retract 행이 없는 것으로 확인되며, 모두 같은 레벨에 있으면 해당 버킷을 읽습니다.
`deletion-vectors.enabled` 또는 `'merge-engine' = 'first-row'`를 사용하면 파일이 여러 레벨에 걸쳐 있어도 되며,
`batch-scan-mode`를 `none` 이외의 모드로 설정하지 않는 한 레벨 0 파일은 Paimon과 마찬가지로 컴팩션되기 전까지 읽지 않습니다.
그 외의 버킷을 읽으면 예외가 발생합니다. Paimon에서 전체 컴팩션(`compact_strategy => 'full'`)을 수행하면 읽을 수 있게 됩니다.

삭제 벡터(deletion vectors)가 적용되지 않으므로 **삭제 벡터가 있는 스냅샷은 읽을 수 없습니다**. 이후 `DELETE` 및 `UPDATE` SQL 문으로
제거된 행이 결과에 그대로 남기 때문입니다. 따라서 인덱스 매니페스트에 삭제 벡터가 나열된 스냅샷을 읽으면
`deletion-vectors.enabled`를 비활성화한 후에도 예외가 발생합니다.
Paimon에서 전체 컴팩션(`compact_strategy => 'full'`)을 수행하면 삭제 벡터가 적용되며, 그 이후에 생성된 스냅샷은
다시 읽을 수 있습니다.

각 데이터 파일은 기록될 당시의 스키마로 읽히며, 최상위 컬럼은 Paimon 필드 id를 기준으로 현재 스키마와 매칭됩니다. 따라서
이름이 변경된 컬럼이나 삭제된 후 같은 이름으로 다시 추가된 컬럼도 Spark와 동일하게 읽힙니다.

`ROW` 컬럼 내부의 필드는 Paimon 필드 id가 아닌 이름으로 데이터 파일과 매칭되므로, **`ROW` 내부 필드의 이름이 변경되기 전에, 또는
해당 필드가 삭제되고 같은 이름(대소문자를 구분하지 않고 비교)의 다른 필드가 추가되기 전에 기록된 데이터 파일은 읽을 수 없습니다**.
결과에서 이름이 변경된 필드는 `NULL`로, 다시 추가된 필드는 삭제된 필드의 값으로 채워지기 때문입니다. 따라서 이러한 데이터 파일을 읽으면 예외가 발생합니다. 필드 추가 및 삭제는 지원됩니다.
Paimon에서 현재 스키마로 테이블을 다시 쓰면(예: `INSERT OVERWRITE <table> SELECT * FROM <table>`)
그 이후에 생성된 스냅샷을 읽을 수 있습니다.

## 명명된 컬렉션 정의 {#defining-a-named-collection}

다음은 URL과 자격 증명을 저장할 명명된 컬렉션을 구성하는 예시입니다:

```xml
<clickhouse>
    <named_collections>
        <paimon_conf>
            <url>http://test.s3.amazonaws.com/clickhouse-bucket/</url>
            <access_key_id>test</access_key_id>
            <secret_access_key>test</secret_access_key>
            <format>auto</format>
            <structure>auto</structure>
        </paimon_conf>
    </named_collections>
</clickhouse>
```

```sql
SELECT * FROM paimonS3(paimon_conf, filename = 'test_table')
DESCRIBE paimonS3(paimon_conf, filename = 'test_table')
```

## 별칭 {#aliases}

테이블 함수 `paimon`은 이제 `paimonS3`의 별칭으로 사용됩니다.

## 가상 컬럼 {#virtual-columns}

* `_path` — 파일 경로. 유형: `LowCardinality(String)`.
* `_file` — 파일 이름. 유형: `LowCardinality(String)`.
* `_size` — 파일 크기(바이트). 유형: `Nullable(UInt64)`. 파일 크기를 알 수 없으면 값은 `NULL`입니다.
* `_time` — 파일의 마지막 수정 시각. 유형: `Nullable(DateTime)`. 시각을 알 수 없으면 값은 `NULL`입니다.
* `_etag` — 파일의 etag 값. 유형: `LowCardinality(String)`. etag를 알 수 없으면 값은 `NULL`입니다.
