임시 [Merge](/ko/reference/engines/table-engines/special/merge) 테이블을 생성합니다.
테이블 스키마(schema)는 기반 테이블의 컬럼 합집합과 공통 타입을 바탕으로 결정됩니다.
[Merge](/ko/reference/engines/table-engines/special/merge) 테이블 엔진에서와 동일한 가상 컬럼을 사용할 수 있습니다.

## 구문 {#syntax}

```sql
merge(['db_name',] 'tables_regexp')
```

## 인수 {#arguments}

| 인수              | 설명                                                                                                                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `db_name`       | 가능한 값(선택 사항, 기본값은 `currentDatabase()`):<br />    - 데이터베이스 이름,<br />    - 데이터베이스 이름을 문자열로 반환하는 상수 표현식(예: `currentDatabase()`),<br />    - `REGEXP(expression)`, 여기서 `expression`은 DB 이름과 일치하는 정규식입니다. |
| `tables_regexp` | 지정된 DB 또는 여러 DB의 테이블 이름과 일치하는 정규식입니다.                                                                                                                                                                |

## 접근 권한 {#access-rights}

패턴과 일치하는 테이블은 [Merge](/ko/reference/engines/table-engines/special/merge#access-rights) 테이블 엔진과 동일한 접근 규칙에 따라 읽습니다. 데이터는 일치하는 테이블 중 현재 사용자가 볼 수 있는 테이블, 즉 [`SHOW TABLES`](/ko/reference/statements/grant#show) 권한(privilege)이 있는 테이블에서만 읽으며, 테이블 스키마(table schema)도 이 테이블들로부터만 도출됩니다. 일치하는 테이블 중 사용자가 볼 수 없는 테이블은 오류 없이 건너뜁니다. 스키마를 도출하려면 도출 대상 테이블에 대한 [`SHOW COLUMNS`](/ko/reference/statements/grant#show) 권한(privilege)이 필요합니다. 사용자가 볼 수 있는 일치 테이블을 읽으려면 쿼리가 읽는 컬럼에 대한 [`SELECT`](/ko/reference/statements/grant#select) 권한(privilege)이 필요하며, 이 권한(privilege)이 없으면 쿼리가 `ACCESS_DENIED` 오류로 실패합니다.
