## evalMLMethod {#evalmlmethod}

적합된 회귀 모델을 사용한 예측에는 `evalMLMethod` 함수를 사용합니다. 자세한 내용은 `linearRegression`의 링크를 참조하십시오.

## stochasticLinearRegression {#stochasticlinearregression}

[stochasticLinearRegression](/ko/reference/functions/aggregate-functions/stochasticLinearRegression) 집계 함수는 선형 모델과 MSE 손실 함수를 사용한 확률적 경사 하강법을 구현합니다. 새 데이터 예측에는 `evalMLMethod`를 사용합니다.

## stochasticLogisticRegression {#stochasticlogisticregression}

[stochasticLogisticRegression](/ko/reference/functions/aggregate-functions/stochasticLogisticRegression) 집계 함수는 이진 분류 문제를 위한 확률적 경사 하강법을 구현합니다. 새 데이터 예측에는 `evalMLMethod`를 사용합니다.

## assignCentroid {#assignCentroid}

도입 버전: v26.8.0

벡터에 가장 가까운 (L2) 센트로이드의 id를 반환합니다. 센트로이드는 배열로 이루어진 상수 배열(배열의 배열)로 지정할 수 있으며, 이 경우 id는 해당 배열에서 0부터 시작하는 위치입니다. 또는 `cid`와 `vec` 속성을 가진 `Dictionary`의 이름으로 지정할 수 있으며, 이 경우 id는 `cid` 값입니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해 서로 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
assignCentroid(vec, centroids | dict_name)
```

**인수**

* `vec` — 할당할 벡터입니다. 차원이 센트로이드의 차원과 일치해야 합니다. `Float32` 이외의 원소 타입은 스코어링 커널이 사용하는 `Float32`로 변환됩니다. [`Array(Float32)`](/ko/reference/data-types/array) 또는 [`Array(Float64)`](/ko/reference/data-types/array) 또는 [`Array(BFloat16)`](/ko/reference/data-types/array) 또는 [`Array(Int8)`](/ko/reference/data-types/array) 또는 [`Array(UInt8)`](/ko/reference/data-types/array)
* `centroids` — 점수를 계산할 대상 센트로이드이며, 상수여야 합니다. 크기가 동일하고 비어 있지 않은 배열들의 배열로 지정하며, 각 배열의 원소 타입은 `vec`에 허용되는 타입 중 어느 것이든 가능합니다(반드시 동일할 필요는 없음). 이 경우 id는 해당 배열에서 0부터 시작하는 위치가 됩니다. 또는 `UInt32`에 들어맞는 unsigned integer 타입의 `cid` 속성과 `Array(Float32)` 타입의 `vec` 속성을 가진 `Dictionary`의 이름으로 지정하며, 이 경우 id는 `cid`가 됩니다. 딕셔너리(dictionary)는 한 번만 읽히며 다시 로드될 때까지 캐시됩니다. [`Array(Array(Float32))`](/ko/reference/data-types/array) 또는 [`Array(Array(Float64))`](/ko/reference/data-types/array) 또는 [`Array(Array(BFloat16))`](/ko/reference/data-types/array) 또는 [`Array(Array(Int8))`](/ko/reference/data-types/array) 또는 [`Array(Array(UInt8))`](/ko/reference/data-types/array) 또는 [`String`](/ko/reference/data-types/string)

**반환 값**

가장 가까운 센트로이드 id입니다. [`UInt32`](/ko/reference/data-types/int-uint)

**예시**

**Inline 센트로이드**

```sql title=Query
SELECT assignCentroid([1.0, 2.0]::Array(Float32), [[0.0, 0.0], [1.0, 2.0]]::Array(Array(Float32)))
```

```response title=Response
1
```

## evalMLMethod {#evalMLMethod}

도입 버전: v20.1.0

학습된 머신러닝 모델을 입력 피처에 적용해 예측값을 생성합니다.

**구문**

```sql
evalMLMethod(model, x1[, x2, ...])
```

**인수**

* `model` — 학습된 머신러닝 모델입니다. [`AggregateFunctionState`](/ko/reference/data-types/aggregatefunction)
* `x1, x2, ...` — 예측에 사용할 특성 값입니다. [`Float*`](/ko/reference/data-types/float) 또는 [`(U)Int*`](/ko/reference/data-types/int-uint)

**반환 값**

학습된 모델을 기반으로 한 예측 값을 반환합니다. [`Float64`](/ko/reference/data-types/float)

**예시**

**사용 예시**

```sql title=Query
CREATE TABLE trips (pickup_datetime DateTime('UTC'), trip_distance Float64, total_amount Float64) ENGINE = Memory;

-- A fare of 3, plus 2.5 for every unit of distance.
INSERT INTO trips
SELECT toDateTime('2020-01-01 00:00:00', 'UTC') + number * 60, number % 10 + 1, 2.5 * (number % 10 + 1) + 3
FROM numbers(1000);

-- One model per year of the data.
CREATE TABLE models ENGINE = Memory AS
SELECT
    toYear(pickup_datetime) AS year,
    stochasticLinearRegressionState(0.01, 0.0, 10, 'SGD')(total_amount, trip_distance) AS model
FROM trips
GROUP BY year;

SELECT
    trip_distance,
    round(evalMLMethod(model, trip_distance), 2) AS predicted,
    total_amount
FROM trips
LEFT JOIN models ON year = toYear(pickup_datetime)
ORDER BY pickup_datetime
LIMIT 5
```

```response title=Response
┌─trip_distance─┬─predicted─┬─total_amount─┐
│             1 │      4.05 │          5.5 │
│             2 │      6.79 │            8 │
│             3 │      9.53 │         10.5 │
│             4 │     12.28 │           13 │
│             5 │     15.02 │         15.5 │
└───────────────┴───────────┴──────────────┘
```

## naiveBayesClassifier {#naiveBayesClassifier}

도입 버전: v25.11.0

[`NAIVE_BAYES`](/ko/reference/statements/create/dictionary/layouts/naive-bayes) 딕셔너리를 사용해 입력 텍스트를 분류합니다. `dictGet(dictionary_name, class_attribute, input_text)`와 동일한 예측 클래스 값을 반환합니다. 여기서 class&#95;attribute는 딕셔너리 [레이아웃](/ko/reference/statements/create/dictionary/layouts/naive-bayes#layout-parameters)에 구성된 클래스 레이블 속성의 이름입니다. `dictGet`와 달리 반환 유형은 클래스 속성에 선언된 유형이 아니라 항상 `UInt32`이며, `input_text`는 반드시 `String`이어야 합니다(키 유형 변환은 적용되지 않습니다).

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해서도 서로 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
naiveBayesClassifier(dictionary_name, input_text)
```

**인수**

* `dictionary_name` — NAIVE&#95;BAYES 레이아웃의 딕셔너리 이름입니다. [`String`](/ko/reference/data-types/string)
* `input_text` — 분류할 텍스트입니다. [`String`](/ko/reference/data-types/string)

**반환 값**

예측된 클래스 ID입니다. [`UInt32`](/ko/reference/data-types/int-uint)

**예시**

**텍스트 분류**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT naiveBayesClassifier('sentiment', 'a good and great film') AS class_id;
```

```response title=Response
┌─class_id─┐
│        0 │
└──────────┘
```

## naiveBayesClassifierWithAllProbs {#naiveBayesClassifierWithAllProbs}

도입 버전: v26.7.0

[`NAIVE_BAYES`](/ko/reference/statements/create/dictionary/layouts/naive-bayes) 딕셔너리를 사용하여 입력 텍스트를 분류하고, 가장 확률이 높은 클래스부터 낮은 클래스까지 각 확률과 함께 모두 반환합니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해서도 서로 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
naiveBayesClassifierWithAllProbs(dictionary_name, input_text)
```

**인수**

* `dictionary_name` — NAIVE&#95;BAYES 레이아웃을 사용하는 딕셔너리 이름입니다. [`String`](/ko/reference/data-types/string)
* `input_text` — 분류할 텍스트입니다. [`String`](/ko/reference/data-types/string)

**반환 값**

확률이 높은 순서부터 낮은 순서로 정렬된 (class&#95;id, probability) 튜플 배열입니다. [`Array(Tuple(UInt32, Float64))`](/ko/reference/data-types/array)

**예시**

**모든 클래스의 확률**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))
LIFETIME(0);

SELECT arrayMap(p -> (p.1, round(p.2, 4)), naiveBayesClassifierWithAllProbs('sentiment', 'a good and great film')) AS predictions;
```

```response title=Response
┌─predictions─────────────┐
│ [(0,0.9677),(1,0.0323)] │
└─────────────────────────┘
```

## naiveBayesClassifierWithProb {#naiveBayesClassifierWithProb}

도입 버전: v26.7.0

[`NAIVE_BAYES`](/ko/reference/statements/create/dictionary/layouts/naive-bayes) 딕셔너리를 사용해 입력 텍스트를 분류하고, 예측된 클래스와 해당 확률을 반환합니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해서도 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
naiveBayesClassifierWithProb(dictionary_name, input_text)
```

**인수**

* `dictionary_name` — NAIVE&#95;BAYES 레이아웃을 사용하는 딕셔너리 이름입니다. [`String`](/ko/reference/data-types/string)
* `input_text` — 분류할 텍스트입니다. [`String`](/ko/reference/data-types/string)

**반환 값**

(class&#95;id, probability) 형태의 튜플입니다. [`Tuple(UInt32, Float64)`](/ko/reference/data-types/tuple)

**예시**

**확률과 함께 분류하기**

```sql title=Query
-- A dictionary built from the token counts of two classes: 0 for a positive review, 1 for a negative one.
CREATE TABLE review_tokens (ngram String, class_id UInt32, count UInt64) ENGINE = Memory;
INSERT INTO review_tokens VALUES ('good', 0, 5), ('great', 0, 4), ('excellent', 0, 3), ('bad', 1, 5), ('awful', 1, 4), ('terrible', 1, 3);

CREATE DICTIONARY sentiment (ngram String, class_id UInt32 DEFAULT 0, count UInt64 DEFAULT 0)
PRIMARY KEY ngram
SOURCE(CLICKHOUSE(TABLE 'review_tokens'))
LAYOUT(NAIVE_BAYES(class_attribute 'class_id' n 1 mode 'token'))

WITH naiveBayesClassifierWithProb('sentiment', 'a good and great film') AS p

```

```response title=Response

└────────────┘
```

## predictXGBoost {#predictXGBoost}

도입 버전: v26.10.0

[`XGBOOST`](/ko/reference/statements/create/dictionary/layouts/xgboost) 딕셔너리를 사용하여 기능 벡터의 수치형 대상 값을 예측합니다. 기능은 딕셔너리의 키 열(Key Columns)이 선언된 순서대로 위치 기반으로 전달됩니다. `XGBOOST` 딕셔너리는 이 함수로만 쿼리할 수 있습니다. 이 딕셔너리는 행(rows)이 아닌 학습된 모델을 저장하므로 일반적인 딕셔너리 인터페이스(`dictGet`, `dictHas`, `SELECT * FROM dict`)는 지원되지 않습니다. XGBoost 통합은 실험적 기능이므로 `enable_xgboost` 설정을 활성화해야 합니다.

**구문**

```sql
predictXGBoost(dictionary_name, feature1[, feature2, ...][, params])
```

**인수**

* `dictionary_name` — XGBOOST 레이아웃(layout)을 사용하는 딕셔너리의 이름입니다. 생성 방법과 지원되는 학습 매개변수는 [XGBOOST 딕셔너리 레이아웃](/ko/reference/statements/create/dictionary/layouts/xgboost)을 참조하십시오. [`String`](/ko/reference/data-types/string)
* `featureN` — 숫자형 기능 값으로, 딕셔너리의 키 순서에 따라 위치 기반으로 전달합니다. NULL 기능은 결측값으로 모델에 전달되며, XGBoost는 학습 시와 동일한 방식으로 이를 처리하므로 예측 결과가 NULL이 되는 경우는 없습니다. [`(U)Int*`](/ko/reference/data-types/int-uint) 또는 [`Float*`](/ko/reference/data-types/float) 또는 [`Nullable((U)Int*)`](/ko/reference/data-types/nullable) 또는 [`Nullable(Float*)`](/ko/reference/data-types/nullable)
* `params` — 선택 사항입니다. 매개변수 이름을 정수 값에 매핑하는 XGBoost 예측 매개변수의 상수 Map입니다(예: `map('type', 0, 'iteration_end', 0)`). 지원되는 매개변수는 모두 정수 또는 불리언이므로 소수 값은 허용되지 않습니다. 사용 가능한 키는 [예측 매개변수](/ko/reference/statements/create/dictionary/layouts/xgboost#prediction-parameters)를 참조하십시오. [`Map(String, (U)Int8/16/32/64)`](/ko/reference/data-types/map)

**반환 값**

각 행에 대한 모델 예측 값을 Float64로 반환합니다. [`Float64`](/ko/reference/data-types/float)

**예시**

**예측**

```sql title=Query
-- A model trained on the linear target y = 2 * x1 + 3 * x2. The XGBoost integration is experimental.
SET enable_xgboost = 1;

CREATE TABLE training_data (x1 Float64, x2 Float64, y Float64) ENGINE = MergeTree ORDER BY tuple();
INSERT INTO training_data SELECT number AS x1, number * 2 AS x2, 2 * x1 + 3 * x2 AS y FROM numbers(100);

CREATE DICTIONARY model (x1 Float64, x2 Float64, y Float64)
PRIMARY KEY (x1, x2)
SOURCE(CLICKHOUSE(TABLE 'training_data'))
LAYOUT(XGBOOST(objective 'reg:squarederror' num_iterations 100 max_depth 6))
LIFETIME(0);

-- The ground truth is 2 * 1 + 3 * 2 = 8.
SELECT round(predictXGBoost('model', 1.0, 2.0), 1) AS prediction;
```

```response title=Response
┌─prediction─┐
│          8 │
└────────────┘
```

**매개변수를 사용한 예측**

```sql title=Query
-- The raw margin of the model above, before the objective's transformation. For `reg:squarederror` it is the
-- prediction itself, while for `binary:logistic` it is the log-odds rather than the probability.
SELECT round(predictXGBoost('model', 1.0, 2.0, map('type', 1)), 1) AS margin;
```

```response title=Response
┌─margin─┐
│      8 │
└────────┘
```
