이 장에 설명된 함수를 사용하면 쿼리 프로파일링을 위해 [ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format)와 [DWARF](https://en.wikipedia.org/wiki/DWARF)를 검사할 수 있습니다.

<Note>
  이 함수는 느리며 보안 측면에서 고려가 필요할 수 있습니다.
</Note>

인트로스펙션 함수가 제대로 작동하려면 다음이 필요합니다.

* `clickhouse-common-static-dbg` 패키지를 설치합니다.

* [allow&#95;introspection&#95;functions](/ko/reference/settings/session-settings/allow#allow_introspection_functions) 설정을 1로 지정합니다.

  보안상의 이유로 인트로스펙션 함수는 기본적으로 비활성화되어 있습니다.

ClickHouse는 프로파일러 보고서를 [trace&#95;log](/ko/reference/system-tables/trace_log) 시스템 테이블에 저장합니다. 테이블과 프로파일러가 올바르게 구성되어 있는지 확인하십시오.

## addressToLine {#addressToLine}

도입 버전: v20.1.0

ClickHouse 메인 실행 파일 내부의 명령어 주소를 ClickHouse 소스 코드의 파일 이름과 줄 번호로 변환합니다.

주소는 ClickHouse 메인 실행 파일 내부의 오프셋(offset)이어야 합니다. 이는 `system.trace_log`, `system.stack_trace`, `system.crash_log`의 `trace` 컬럼과 `system.error_log`의 `last_error_trace` 컬럼에 주소가 저장되는 형식입니다.
런타임(가상 메모리) 주소는 허용되지 않으므로, 이 함수로 서버 프로세스의 메모리 레이아웃을 파악할 수는 없습니다.
메인 실행 파일 외부의 프레임은 `0`으로 저장되며, 함수는 이러한 프레임에 대해 빈 결과를 반환합니다.

<Note>
  이 함수는 실행 속도가 느리며 보안상 고려할 사항이 있을 수 있습니다.
</Note>

이 인트로스펙션 함수를 활성화하려면 다음을 수행하십시오.

* `clickhouse-common-static-dbg` 패키지를 설치합니다.
* [`allow_introspection_functions`](/ko/reference/settings/session-settings/allow#allow_introspection_functions) 설정을 `1`로 지정합니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해서도 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
addressToLine(address_of_binary_instruction)
```

**인수**

* `address_of_binary_instruction` — 메인 ClickHouse 실행 파일 내 명령어의 오프셋으로, `system.trace_log` 및 이와 유사한 테이블의 `trace` 컬럼에 저장된 값입니다. [`UInt64`](/ko/reference/data-types/int-uint)

**반환 값**

콜론으로 구분된 소스 코드 파일 이름과 줄 번호를 반환합니다(예: `/build/obj-x86_64-linux-gnu/../src/Common/ThreadPool.cpp:199`). 해당 주소에 대한 디버그 정보를 찾을 수 없으면 바이너리 이름을 반환하고, 주소가 `0`이면 빈 문자열을 반환합니다. [`String`](/ko/reference/data-types/string)

**예시**

## addressToLineWithInlines {#addressToLineWithInlines}

도입 버전: v22.2.0

`addressToLine`과 유사하지만, 모든 인라인 함수가 포함된 배열을 반환합니다.
이 때문에 `addressToLine`보다 더 느립니다.

주소는 ClickHouse 메인 실행 파일 내부의 오프셋이어야 하며, 이는 `system.trace_log`, `system.stack_trace`, `system.crash_log`의 `trace` 컬럼과 `system.error_log`의 `last_error_trace` 컬럼에 주소가 저장되는 형식입니다.
이 함수로 서버 프로세스의 메모리 레이아웃을 알아낼 수 없도록 런타임(가상 메모리) 주소는 허용되지 않습니다.
메인 실행 파일 외부의 프레임은 `0`으로 저장되며, 함수는 이러한 프레임에 대해 빈 결과를 반환합니다.

이 인트로스펙션 함수를 활성화하려면 다음을 수행하십시오.

* `clickhouse-common-static-dbg` 패키지를 설치합니다.
* [`allow_introspection_functions`](/ko/reference/settings/session-settings/allow#allow_introspection_functions) 설정을 `1`로 지정합니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해 서로 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
addressToLineWithInlines(address_of_binary_instruction)
```

**인수**

* `address_of_binary_instruction` — 메인 ClickHouse 실행 파일 내 명령어의 오프셋으로, `system.trace_log` 및 유사한 테이블의 `trace` 컬럼에 저장된 값입니다. [`UInt64`](/ko/reference/data-types/int-uint)

**반환 값**

첫 번째 요소가 콜론으로 구분된 소스 코드 파일 이름과 줄 번호인 배열을 반환합니다. 두 번째, 세 번째 이후의 요소에는 인라인 함수의 소스 코드 파일 이름, 줄 번호, 함수 이름이 나열됩니다. 디버그 정보를 찾을 수 없으면 바이너리 이름만 포함된 단일 요소 배열이 반환되며, `0`이 주어지면 빈 배열이 반환됩니다. [`Array(String)`](/ko/reference/data-types/array)

## addressToSymbol {#addressToSymbol}

도입 버전: v20.1.0

메인 ClickHouse 실행 파일 내부의 명령어 주소를 ClickHouse 목적 파일의 심볼로 변환합니다.

주소는 메인 ClickHouse 실행 파일 내부의 오프셋이어야 합니다. 이는 `system.trace_log`, `system.stack_trace`, `system.crash_log`의 `trace` 컬럼과 `system.error_log`의 `last_error_trace` 컬럼에 주소가 저장되는 형식입니다.
런타임(가상 메모리) 주소는 허용되지 않으므로, 이 함수로 서버 프로세스의 메모리 레이아웃을 파악할 수 없습니다.
메인 실행 파일 외부의 프레임은 `0`으로 저장되며, 함수는 이러한 프레임에 대해 빈 결과를 반환합니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해서도 서로 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
addressToSymbol(address_of_binary_instruction)
```

**인수**

* `address_of_binary_instruction` — `system.trace_log` 및 유사한 테이블의 `trace` 컬럼에 저장된, 메인 ClickHouse 실행 파일 내 명령어의 오프셋입니다. [`UInt64`](/ko/reference/data-types/int-uint)

**반환 값**

ClickHouse 목적 파일의 심볼을 반환합니다. 주소가 유효하지 않거나 `0`이면 빈 문자열을 반환합니다. [`String`](/ko/reference/data-types/string)

## demangle {#demangle}

도입 버전: v20.1.0

심볼을 C++ 함수 이름으로 변환합니다.
이 심볼은 일반적으로 `addressToSymbol` 함수가 반환합니다.

**구문**

```sql
demangle(symbol)
```

## getQueryProfileEvent {#getQueryProfileEvent}

도입 버전: v26.11.0

현재 쿼리에 대한 [프로파일 이벤트(Profile Event)](/ko/reference/system-tables/events)의 현재 값을 반환합니다.

이 값은 `system.query_log`의 `ProfileEvents` 컬럼과 동일한 방식으로, 쿼리를 실행하는 모든 스레드에 걸쳐 누적됩니다.
이 함수는 비결정적입니다. 쿼리 실행(Query Execution) 중 데이터 [블록](/ko/resources/develop-contribute/introduction/architecture#block)마다 한 번씩 평가되므로,
하나의 블록에 속한 모든 행은 동일한 값을 가지며, 쿼리가 진행됨에 따라 값이 증가합니다.
이를 활용하면 지금까지 읽은 행 수나 바이트 수 등 쿼리의 진행 상황을 출력이나 삽입된 데이터에 기록할 수 있습니다.

분산 쿼리(Distributed Query)에서는 각 서버가 쿼리 중 자신이 담당한 부분의 값을 반환합니다.
`RealTimeMicroseconds`나 `OSReadBytes` 같은 일부 이벤트는 주기적으로만 갱신되므로 값이 실제보다 늦게 반영될 수 있습니다.

<Note>
  이 함수는 비결정적입니다. 동일한 인수에 대해 서로 다른 결과를 반환할 수 있습니다.
</Note>

**구문**

```sql
getQueryProfileEvent(event_name)
```

**인수**

* `event_name` — `system.events`에 나오는 프로파일 이벤트(Profile Event)의 이름입니다. [`const String`](/ko/reference/data-types/string)

**반환 값**

현재 쿼리의 프로파일 이벤트 현재 값입니다. [`UInt64`](/ko/reference/data-types/int-uint)

**예시**

**읽기 진행 상황**

```sql title=Query
FROM numbers_mt(10)
SETTINGS max_block_size = 3, max_threads = 1
```
