<div id="description">
  ## 설명
</div>

drop table이 실행되었으나 아직 데이터 정리가 수행되지 않은 테이블에 대한 정보를 포함합니다.

<div id="columns">
  ## 컬럼
</div>

{/*AUTOGENERATED_START*/}

* `index` ([UInt32](/ko/reference/data-types/int-uint)) — marked&#95;dropped&#95;tables 큐의 인덱스입니다.
* `database` ([String](/ko/reference/data-types/string)) — 데이터베이스 이름입니다.
* `table` ([String](/ko/reference/data-types/string)) — 테이블 이름입니다.
* `uuid` ([UUID](/ko/reference/data-types/uuid)) — 테이블 UUID입니다.
* `engine` ([String](/ko/reference/data-types/string)) — 테이블 엔진 이름입니다.
* `metadata_dropped_path` ([String](/ko/reference/data-types/string)) — metadata&#95;dropped 디렉터리에 있는 테이블 메타데이터 파일의 경로입니다.
* `table_dropped_time` ([DateTime](/ko/reference/data-types/datetime)) — 테이블 데이터 삭제를 위한 다음 시도가 예정된 시간입니다. 일반적으로 테이블 삭제 시간에 `database_atomic_delay_before_drop_table_sec`를 더한 값입니다.

{/*AUTOGENERATED_END*/}

이 테이블에는 `Atomic` 데이터베이스에서 삭제된 테이블만 나열됩니다. 이러한 테이블의 `table_dropped_time`은 일반적으로 [`database_atomic_delay_before_drop_table_sec`](/ko/reference/settings/server-settings/settings/other#database_atomic_delay_before_drop_table_sec)를 기준으로 결정됩니다. ClickHouse Cloud의 `Shared` 데이터베이스에서는 [`database_shared_drop_table_delay_seconds`](/ko/reference/settings/session-settings/database#database_shared_drop_table_delay_seconds)가 복구 기간을 제어하며, 기본값은 8시간입니다. `Shared` 데이터베이스에서 삭제된 테이블은 `system.dropped_tables`에 표시되지 않습니다.

<div id="example">
  ## 예시
</div>

다음 예시는 `dropped_tables` 정보를 가져오는 방법을 보여줍니다.

```sql
SELECT *
FROM system.dropped_tables\G
```

```text
Row 1:

table_dropped_time:    2023-03-16 23:43:31
```
