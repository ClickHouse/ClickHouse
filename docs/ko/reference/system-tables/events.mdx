## 설명

시스템에서 발생한 이벤트 개수에 관한 정보를 담고 있습니다. 예를 들어, 이 테이블에서는 ClickHouse 서버가 시작된 이후 처리된 `SELECT` 쿼리가 몇 건인지 확인할 수 있습니다.

## 이벤트 설명

### ACMEAPIRequests

전송된 ACME API 요청 수입니다.

### ACMECertificateOrders

발급된 ACME 인증서 주문 건수입니다.

### AdaptiveAggregationBucketsRetired

전체 머지가 완료되기 전에, 해당 버킷의 머지 및 변환이 끝난 직후 작업 메모리(arena 슬롯, 스테이지된 청크 참조)가 해제된 two-level 버킷의 수입니다.

### AdaptiveAggregationDrainedRecords

적응형(adaptive) 집계가 머지 시점에 공유 테이블로 내보낸 지연 레코드 수입니다.

### AdaptiveAggregationGiveUps

스트림에 포함된 고유 키가 적어 적응형(adaptive) 집계에서 프리징(freezing)을 포기한 스레드 수입니다.

### AdaptiveAggregationLocalFreezes

적응형(adaptive) 집계가 동결(freeze) 임계값에서 동결한 로컬 해시 테이블의 개수입니다.

### AdaptiveAggregationPressureDrainedRecords

메모리 부족(memory pressure) 상황에서 적응형 집계가 조기에 비운 스테이징 레코드 수입니다.

### AdaptiveAggregationPressureStandDowns

적응형 집계에서 memory pressure가 external aggregation threshold를 넘어서면서 학습 단계를 영구적으로 벗어난 스레드의 수입니다. 이후 해당 스레드의 로컬 테이블은 일반적인 external aggregation 방식으로 디스크에 spill됩니다.

### AdaptiveAggregationPressureSweeps

적응형 집계가 memory pressure로 인해 스테이징된 레코드를 조기에 비운 횟수입니다.

### AdaptiveAggregationProbeBypasses

적응형 집계에서 행이 거의 적중하지 않아 고정된(frozen) 로컬 테이블에 대한 probe를 중단한 스레드 수입니다.

### AdaptiveAggregationResidueReleases

기준(baseline) 알고리즘으로 되돌아간 스레드가 이로 인해 디스크로 spill할 상황이 되어, 적응형 집계가 공유 드레인 테이블을 기록해 내보낸 횟수입니다.

### AdaptiveAggregationSealedChunks

적응형 집계가 버퍼링된 스테이징 배치에서 병합하여 확정(seal)한 청크의 수입니다.

### AdaptiveAggregationSealNormalizations

적응형 집계 seal이 래핑된 표현(Const, Replicated, Sparse, LowCardinality)을 drain이 소비하는 밀집(dense) 형태로 정규화한 스테이징 인수 컬럼의 개수입니다.

### AdaptiveAggregationSharedTableSpills

적응형 집계가 메모리 압박 상황에서 파트 경계에 도달하여 공유 드레인 테이블을 디스크에 기록한 횟수입니다.

### AdaptiveAggregationSpillBacklogSheds

스테이징된 레코드가 아직 메모리에 남아 있는 상태에서 baseline 알고리즘으로 동작하던 스레드(thaw로 다시 되돌려진 스레드 또는 스스로 물러난 스레드)가 spill을 시도하려 했기 때문에, 적응형 집계가 스테이징된 백로그를 버린 횟수입니다.

### AdaptiveAggregationStagedBytes

적응형 집계가 머지 시점 드레인을 위해 스테이징한 키 바이트 수입니다.

### AdaptiveAggregationStagedChunkPiecesOverBound

적응형 집계가 분할한 스테이징 청크의 조각 중, 맞추려던 경계를 여전히 초과한 채로 발행된 조각의 수입니다. 청크는 버킷 경계를 따라 분할되며, 그 자체만으로 경계를 초과하는 버킷 내부에서는 레코드 단위로 분할됩니다. 따라서 이 값은 스테이징된 바이트만으로도 경계를 초과하는 단일 레코드에 해당합니다. 이러한 조각은 통째로 클레임되므로, 드레인 과정에서 압력 파트를 그만큼 초과할 수 있습니다.

### AdaptiveAggregationStagedChunkSplits

한 청크의 드레인이 압력 파트 경계를 초과할 것으로 추정되어, 적응형 집계가 publication 시점에 버킷 경계를 따라 분할한 스테이징 청크의 수입니다.

### AdaptiveAggregationStagedClaimsClosedAtBound

적응형 집계의 드레인이 스테이징된 청크에 대해 수행한 클레임 중, 추가할 경우 배치가 pressure 파트 경계에 도달하게 되는 청크 직전에 종료되어 그 청크를 다음 클레임으로 넘긴 횟수입니다. 이 경계는 드레인된 상태의 배치를 기준으로 적용되므로, 각각 경계에 아주 근접한 두 청크(절반 파트를 단 몇 레코드만 초과하는, 잘린 청크의 두 조각)는 하나가 아닌 두 개의 테이블로 드레인됩니다. 첫 번째 청크가 단독으로 경계를 초과하는 경우에만 무조건 클레임됩니다.

### AdaptiveAggregationStagedRecords

적응형 집계가 중복 제거 전에 스테이징한 지연 레코드 수입니다.

### AdaptiveAggregationStagedRecordsMerged

적응형 집계가 publish 시점과 seal 시점에 중복 키로 판단하여 머지로 제거한 스테이징된 레코드 수입니다.

### AdaptiveAggregationThaws

스테이징된 스트림이 반복 값 위주로 확인되어 적응형 집계가 로컬 테이블을 해제(thaw)한 횟수입니다.

top-K 집계 힙이 동결되어 일반 집계로 폴백된 횟수입니다. 힙이 관측 윈도우 내에서 거의 아무것도 거부하지 않았거나(예: 서로 다른 그룹화 키의 개수가 LIMIT을 초과하지 않는 경우), 힙의 경계에 있는 동순위 집합(tie-set)이 힙보다 커진 경우에 발생합니다. 이 동순위 집합은 절대 evict되지 않습니다(`enable_group_by_top_k_optimization` 참조).

### AggregationTopKKeysEvicted

### AggregationTopKKeysPruned

### DataAfterMergeDiffersFromReplica

1. 서버 업데이트 후 더 최신 버전의 압축 라이브러리를 사용하는 경우
2. 다른 압축 방식을 사용하는 경우
3. 비결정적 압축 알고리즘을 사용하는 경우(발생 가능성은 매우 낮음)
4. 코드의 논리 오류로 인해 머지 알고리즘이 비결정적으로 동작하는 경우
5. 코드 버그로 인해 메모리에서 데이터 손상이 발생한 경우
6. 하드웨어 문제로 인해 메모리에서 데이터 손상이 발생한 경우
7. 서버 시작 후 원본 데이터를 수동으로 수정한 경우
8. ZooKeeper에 저장된 체크섬을 수동으로 수정한 경우
9. &#39;enable&#95;mixed&#95;granularity&#95;parts&#39;와 같은 파트 포맷 관련 설정이 레플리카마다 다른 경우
