<div id="description">
  ## 설명
</div>

각 분리된 테이블의 정보를 포함합니다.

<div id="columns">
  ## 컬럼
</div>

{/*AUTOGENERATED_START*/}

* `database` ([String](/ko/reference/data-types/string)) — 테이블이 속한 데이터베이스 이름입니다.
* `table` ([String](/ko/reference/data-types/string)) — 테이블 이름입니다.
* `uuid` ([UUID](/ko/reference/data-types/uuid)) — 테이블 UUID입니다(Atomic 데이터베이스).
* `metadata_path` ([String](/ko/reference/data-types/string)) — 파일 시스템에서 테이블 메타데이터의 경로입니다.
* `is_permanently` ([UInt8](/ko/reference/data-types/int-uint)) — 테이블이 영구적으로 분리되었습니다.

{/*AUTOGENERATED_END*/}

<div id="notes">
  ## 참고
</div>

`DatabaseMySQL` 및 `DatabasePostgreSQL`은 기본 데이터를 직접 소유하지 않으며, 데이터는 원격 MySQL/PostgreSQL 서버에 저장됩니다. 따라서 이러한 데이터베이스 엔진의 테이블에 대한 `DROP TABLE`은 내부적으로 `detachTablePermanently`로 구현됩니다. 즉, ClickHouse의 로컬 테이블 추적 정보만 제거하며, 명시적으로 `DETACH TABLE PERMANENTLY`를 실행한 경우와 마찬가지로 테이블은 `is_permanently = 1` 상태로 `system.detached_tables`에 표시됩니다. 원격 데이터 자체는 변경되지 않습니다. 영구 MySQL/PostgreSQL 데이터베이스에서는 분리 상태가 서버 재시작 및 재연결 후에도 유지됩니다. `DatabaseMySQL`은 메타데이터 디렉터리에 `.remove_flag` 마커를 저장하고, `DatabasePostgreSQL`은 `.removed` 마커를 저장합니다. 두 마커 모두 시작 시 `loadStoredObjects`에서 다시 로드됩니다. 이전 메타데이터 디렉터리 없이 새 외부 데이터베이스 매핑을 생성한 경우에만 테이블이 다시 나타납니다. 예를 들어 메타데이터를 제거하거나 다른 이름으로 데이터베이스를 생성한 경우입니다.

<div id="example">
  ## 예시
</div>

```sql
SELECT * FROM system.detached_tables FORMAT Vertical;
```

```text
Row 1:
──────

is_permanently:             1
```
