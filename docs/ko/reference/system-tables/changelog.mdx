## 설명 {#description}

선별해 정리한 ClickHouse 변경 로그(리포지토리의 `CHANGELOG.md`)의 엔트리를 담고 있으며, 각 기능 릴리스의 엔트리 하나당 1개의 행으로 구성되므로 release notes를 SQL로 조회할 수 있습니다.

## 컬럼 {#columns}

* `version` ([Tuple(major UInt16, minor UInt8, patch UInt16)](/ko/reference/data-types/tuple)) — 엔트리가 속한 릴리스의 버전이며, 비교 가능한 튜플 형태입니다. 선별된 변경 로그는 기능 릴리스만 다루므로 `patch`는 항상 0입니다.
* `release_date` ([Date](/ko/reference/data-types/date)) — 릴리스 날짜입니다.
* `is_lts` ([UInt8](/ko/reference/data-types/int-uint)) — 장기 지원(long-term support) 릴리스이면 1입니다.
* `category` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 엔트리가 속한 변경 로그 섹션입니다(예: &#39;New Feature&#39;, &#39;Performance Improvement&#39;, &#39;Bug Fix&#39;).
* `description` ([String](/ko/reference/data-types/string)) — 변경 로그 엔트리의 본문입니다.
* `pull_requests` ([Array(UInt32)](/ko/reference/data-types/array)) — 엔트리가 참조하는 풀 리퀘스트 번호입니다.
* `authors` ([Array(String)](/ko/reference/data-types/array)) — 참조된 풀 리퀘스트의 작성자입니다.

## 예시 {#example}

JSON 관련 최근 변경 사항을 최신 릴리스부터 순서대로 조회합니다:

```sql
SELECT version, category, description
FROM system.changelog
WHERE description ILIKE '%JSON%' AND version >= (26, 1, 0)
ORDER BY version DESC
LIMIT 3
```
