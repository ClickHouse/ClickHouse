## 설명 {#description}

`system.errors` 테이블의 오류 값 이력을 포함합니다. 이 데이터는 주기적으로 디스크에 플러시됩니다.

이 테이블은 언제든지 TRUNCATE하거나 삭제해도 안전합니다.

## 컬럼 {#columns}

* `hostname` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 쿼리를 실행하는 서버의 호스트명입니다.
* `clickhouse_version` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 해당 행을 생성한 ClickHouse 서버의 버전입니다.
* `system_processor` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 해당 행을 생성한 ClickHouse 서버의 CPU 아키텍처입니다.
* `event_date` ([Date](/ko/reference/data-types/date)) — 이벤트 날짜입니다.
* `event_time` ([DateTime](/ko/reference/data-types/datetime)) — 이벤트 시간입니다.
* `code` ([Int32](/ko/reference/data-types/int-uint)) — 오류 코드입니다.
* `error` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 오류 이름입니다.
* `value` ([UInt64](/ko/reference/data-types/int-uint)) — 일정 시간 인터벌 동안 발생한 오류 수입니다.
* `remote` ([UInt8](/ko/reference/data-types/int-uint)) — 원격 예외입니다(즉, 분산 쿼리 중 하나에서 수신된 예외).
* `last_error_time` ([DateTime](/ko/reference/data-types/datetime)) — 마지막 오류가 발생한 시간입니다.
* `last_error_message` ([String](/ko/reference/data-types/string)) — 마지막 오류 메시지입니다.
* `last_error_query_id` ([String](/ko/reference/data-types/string)) — 마지막 오류를 일으킨 쿼리의 ID입니다(사용 가능한 경우).
* `last_error_trace` ([Array(UInt64)](/ko/reference/data-types/array)) — 마지막 오류의 스택 트레이스입니다. FreeBSD를 제외한 ELF 플랫폼에서는 메인 ClickHouse 바이너리 내부의 주소가 물리적 파일 오프셋으로 저장되며, 바이너리 외부의 프레임(공유 라이브러리, JIT 코드)은 0으로 저장됩니다.
* `last_error_symbols` ([Array(LowCardinality(String))](/ko/reference/data-types/array)) — last&#95;error&#95;trace에 대응하는 디맹글링된 심볼 이름입니다.
* `last_error_lines` ([Array(LowCardinality(String))](/ko/reference/data-types/array)) — last&#95;error&#95;trace에 대응하는 파일 이름과 줄 번호입니다.

`last_error_symbols`와 `last_error_lines`는 바이너리의 심볼 테이블과 디버그 정보를 바탕으로 해석됩니다.
`last_error_symbols`는 심볼 테이블을 사용할 수 있는 환경(Linux 및 macOS 빌드)이라면 어디서든 채워집니다.
`last_error_lines`에는 DWARF 디버그 정보가 추가로 필요합니다. 이 정보는 Linux에서는 바이너리에서 직접 읽고, macOS에서는 같은 위치에 있는 `.dSYM` bundle에서 읽습니다. 따라서 디버그 정보를 사용할 수 없으면 이 컬럼은 비어 있습니다. 내부 검사를 지원하지 않는 플랫폼(예: FreeBSD)에서는 두 배열 모두 비어 있습니다.
