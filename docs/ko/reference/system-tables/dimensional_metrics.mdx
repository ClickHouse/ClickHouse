## 설명 {#description}

이 테이블(table)에는 즉시 계산하여 Prometheus 포맷으로 내보낼 수 있는 차원형 메트릭이 포함되어 있습니다. 이 테이블은 항상 최신 상태입니다.

## 메트릭 설명 {#metric_descriptions}

### merge_failures {#merge_failures}

시작 후 지금까지 실패한 모든 머지의 수입니다.

### startup_scripts_failure_reason {#startup_scripts_failure_reason}

오류 유형별로 시작 스크립트 실패를 나타냅니다. 시작 스크립트가 실패하면 값이 1로 설정되며, 오류 이름으로 레이블이 지정됩니다.

### merge_tree_parts {#merge_tree_parts}

파트 상태, 파트 유형, 프로젝션 파트 여부를 레이블로 구분한 MergeTree 데이터 파트 수입니다.

### `filesystem_cache_evictions_total` {#filesystem-cache-evictions-total}

파일 시스템 캐시에서 축출된 파일 세그먼트 수로, 캐시 이름별로 레이블이 지정됩니다. 기본적으로 비활성화되어 있으며, `expose_prometheus_eviction_metrics`를 사용해 활성화할 수 있습니다.

### `filesystem_cache_evicted_bytes_total` {#filesystem-cache-evicted-bytes-total}

파일 시스템 캐시에서 축출된 파일 세그먼트의 총 바이트 수이며, 캐시 이름별로 레이블이 지정됩니다. 기본적으로 비활성화되어 있으며 `expose_prometheus_eviction_metrics`로 활성화할 수 있습니다.

### `filesystem_cache_evictions_by_user_total` {#filesystem-cache-evictions-by-user-total}

파일 시스템 캐시에서 축출된 파일 세그먼트 수를 나타내는 메트릭으로, 캐시 이름과 사용자 ID별로 레이블이 지정됩니다. 기본적으로 비활성화되어 있으며, `expose_prometheus_eviction_metrics` 및 `expose_prometheus_eviction_metrics_per_user`를 사용해 활성화할 수 있습니다.

### `filesystem_cache_evicted_bytes_by_user_total` {#filesystem-cache-evicted-bytes-by-user-total}

파일 시스템 캐시에서 축출된 파일 세그먼트의 총 바이트 수로, 캐시 이름과 사용자 ID를 레이블로 구분합니다. 기본적으로 비활성화되어 있으므로 `expose_prometheus_eviction_metrics` 및 `expose_prometheus_eviction_metrics_per_user`를 사용해 활성화하십시오.

### `object_storage_queue_failures_total` {#object-storage-queue-failures-total}

데이터베이스, 테이블, 처리 단계(`read`, `set_processing`, `insert`, `commit`, `after_processing`), 오류 코드별 `ObjectStorageQueue`(`S3Queue`/`AzureQueue`) 실패 횟수입니다. `after_processing` 단계에서는 `after_processing` 작업(삭제, 태그 지정 또는 이동)이 완료되지 않은 객체의 수가 값이 됩니다.

### `object_storage_queue_permanently_failed_files_total` {#object-storage-queue-permanently-failed-files-total}

재시도 횟수를 모두 소진했거나 재시도가 비활성화되어 영구적으로 포기된 `ObjectStorageQueue` (`S3Queue`/`AzureQueue`) 파일 수입니다. 데이터베이스와 테이블별로 레이블이 지정되며, 각각의 파일에 포함된 데이터는 더 이상 처리되지 않습니다.

### `object_storage_queue_newest_seen_object_timestamp_seconds` {#object-storage-queue-newest-seen-object-timestamp-seconds}

`ObjectStorageQueue`(`S3Queue`/`AzureQueue`) 테이블에서 현재까지 확인된 가장 최신 객체의 마지막 수정 시각을 나타내는 Unix 타임스탬프입니다. 데이터베이스와 테이블별로 레이블이 지정됩니다. 테이블이 삭제되거나 분리되면 해당 시계열도 제거됩니다. 테이블 이름을 변경하면 이전 이름의 시계열은 서버가 재시작될 때까지 유지됩니다.

### `object_storage_queue_newest_committed_object_timestamp_seconds` {#object-storage-queue-newest-committed-object-timestamp-seconds}

데이터베이스와 테이블을 레이블로 지정한 `ObjectStorageQueue`(`S3Queue`/`AzureQueue`) 테이블에서 지금까지 완전히 처리된 가장 최신 객체의 마지막 수정 시각을 나타내는 Unix 타임스탬프입니다. 이 시계열은 테이블이 삭제되거나 분리되면 제거됩니다. 테이블 이름을 변경한 후에는 서버가 재시작될 때까지 이전 이름의 시계열이 유지됩니다.

### `object_storage_queue_processed_files_total` {#object-storage-queue-processed-files-total}

이 서버에서 해당 `ObjectStorageQueue`(`S3Queue`/`AzureQueue`) 테이블이 처리 완료로 커밋한 파일 수입니다. 데이터베이스와 테이블별로 레이블이 지정됩니다.

### `object_storage_queue_last_poll_timestamp_seconds` {#object-storage-queue-last-poll-timestamp-seconds}

이 서버에 있는 `ObjectStorageQueue`(`S3Queue`/`AzureQueue`) 테이블의 백그라운드 스트리밍 스레드가 처리할 파일을 찾는 사이클을 마지막으로 시작했거나 해당 사이클의 배치를 마지막으로 시작한 시점의 Unix 타임스탬프이며, 데이터베이스와 테이블을 레이블로 가집니다. 이 값은 테이블이 Keeper에 자신을 활성 상태로 등록한 후 사이클이 시작될 때 설정되고, 사이클의 각 배치 직전에 다시 설정됩니다. 따라서 사이클에서 파일을 찾지 못하거나 사이클이 실패해도 값이 증가하며, 백로그가 오래 쌓여 있는 동안에도 마찬가지입니다. 등록에 실패하면 값이 증가하지 않습니다. 값이 0이면 테이블이 시작된 이후 아직 폴링하지 않았음을 의미합니다. 테이블에 준비된 attached 상태인 materialized view가 없는 동안, 스트리밍이 중지되었거나 일시 중지된 동안, 또는 서버에서 스트리밍이 비활성화된 동안에는 테이블이 데이터를 소비하지 않으므로 값이 증가하지 않습니다. 테이블의 모든 스트리밍 스레드가 동일한 시계열에 기록하므로, 이 메트릭은 그중 가장 최근 사이클을 나타냅니다. 테이블이 삭제되거나 분리되면 해당 시계열도 제거됩니다. 테이블 이름을 변경하면 서버가 재시작될 때까지 이전 이름의 시계열이 남아 있습니다.

### `system_log_flushes_total` {#system-log-flushes-total}

시스템 로그의 인메모리 버퍼를 해당 테이블로 플러시하려고 시도한 횟수입니다. 시스템 로그의 데이터베이스 및 테이블과 결과(result)(`success`, `failure`)를 기준으로 레이블이 지정됩니다.

### `system_log_flushed_rows_total` {#system-log-flushed-rows-total}

시스템 로그의 플러시(flushes)가 성공적으로 완료되어 기록된 행(rows)의 수입니다. 시스템 로그의 데이터베이스와 테이블이 레이블로 연결됩니다.

### `system_log_dropped_rows_total` {#system-log-dropped-rows-total}

유실된 시스템 로그 행(rows)의 수입니다. 시스템 로그의 데이터베이스와 테이블, 그리고 사유별로 레이블이 지정됩니다. `queue_full`은 인메모리 버퍼가 `max_size_rows`에 도달하여 수락되지 않은 행을 나타내며(다음 플러시를 위해 버퍼를 가져갈 때 갱신됨), `flush_failed`는 플러시에 실패한 행을 나타냅니다.

## 컬럼 {#columns}

* `metric` ([String](/ko/reference/data-types/string)) — 메트릭 이름입니다.
* `value` ([Float64](/ko/reference/data-types/float)) — 메트릭 값입니다.
* `description` ([String](/ko/reference/data-types/string)) — 메트릭 설명입니다.
* `labels` ([Map(String, String)](/ko/reference/data-types/map)) — 메트릭 레이블입니다.

**별칭:**

* `name` — `metric`의 별칭입니다.

## 예시 {#example}

다음과 같은 쿼리를 사용하면 모든 차원형 메트릭을 Prometheus 포맷으로 내보낼 수 있습니다.

```sql
SELECT
  metric AS name,
  toFloat64(value) AS value,
  description AS help,
  labels,
  'gauge' AS type
FROM system.dimensional_metrics
FORMAT Prometheus
```
