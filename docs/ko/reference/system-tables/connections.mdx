## 설명 {#description}

네이티브 TCP 및 HTTP 쿼리 인터페이스에서 열려 있는 클라이언트 연결을 표시합니다.
쿼리가 실행 중인 연결은 `active` 상태이고, 다음 쿼리를 기다리는 연결은 `idle` 상태입니다.

이 테이블에는 다음 연결이 표시되지 않습니다.

* 다른 프로토콜의 연결(예: MySQL, PostgreSQL, gRPC)
* 서버 간 연결
* 쿼리를 실행하지 않은 HTTP 연결(예: `/ping` 및 Prometheus 연결)

서버는 서버 설정 `collect_connection_metrics`가 `true`인 경우에만 연결 정보를 수집합니다. 이 설정이 `false`이면 테이블은 비어 있습니다.
이 설정은 재시작 없이 변경할 수 있습니다(`SYSTEM RELOAD CONFIG`).

* 설정을 `false`로 변경하면 테이블이 비워지고 서버는 새 연결을 더 이상 등록하지 않습니다.
* 설정을 `true`로 변경하면 이미 열려 있는 연결은 다음 쿼리를 실행할 때 테이블에 표시됩니다.

서버는 TCP 연결을 인증이 완료된 후 테이블에 추가하고, 연결이 닫히면 제거합니다.
HTTP 연결은 첫 번째 쿼리 시점에 테이블에 추가하고, 소켓이 닫히면 제거합니다.
따라서 HTTP keep-alive 연결은 요청과 요청 사이에 `idle`로 표시됩니다.

`SHOW CONNECTIONS` 권한(privilege)이 없는 사용자는 자신의 연결만 볼 수 있습니다.
이 검사는 이름이 아닌 사용자 ID를 기준으로 합니다. 따라서 이름이 변경된 사용자는 자신의 연결을 그대로 볼 수 있으며, 이전 이름으로 새로 생성된 사용자는 해당 연결을 볼 수 없습니다.

`connection_id`는 무작위 UUID입니다. 따라서 서버 간에 고유하므로 `clusterAllReplicas` 등을 사용해 여러 레플리카의 테이블을 결합할 수 있습니다.

`connected_time`은 TCP와 HTTP에서 동일한 의미를 가지며, 서버가 소켓 처리를 시작한 시각을 나타냅니다.
이 시각은 TCP 핸드셰이크, 인증, 첫 번째 쿼리보다 앞서므로 연결이 테이블에 표시된 시각보다 이를 수 있습니다.

## 컬럼 {#columns}

* `connection_id` ([UUID](/ko/reference/data-types/uuid)) — 연결의 고유 식별자로, 무작위로 생성된 UUID입니다. `clusterAllReplicas` 등을 사용할 때에도 서버 간에 고유합니다. TCP 연결은 인증 후에 식별자가 부여되고, HTTP 연결은 첫 번째 쿼리 시점에 식별자가 부여됩니다.
* `protocol` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 연결의 프로토콜로, TCP(native protocol) 또는 HTTP입니다.
* `client_address` ([IPv6](/ko/reference/data-types/ipv6)) — 클라이언트의 IP 주소입니다. 프록시를 거치는 경우, 서버가 PROXY 프로토콜 또는 `X-Forwarded-For` 헤더를 신뢰하면 실제 클라이언트의 주소가 표시됩니다. HTTP에서는 마지막 요청의 주소입니다.
* `client_port` ([UInt16](/ko/reference/data-types/int-uint)) — 클라이언트의 TCP 포트입니다. 프록시를 거치는 경우, 서버가 PROXY 프로토콜 또는 `X-Forwarded-For` 헤더를 신뢰하면 여기에서 얻은 포트가 표시됩니다. HTTP에서는 마지막 요청의 포트입니다.
* `server_port` ([UInt16](/ko/reference/data-types/int-uint)) — 연결을 수락한 서버 포트입니다.
* `user` ([String](/ko/reference/data-types/string)) — 인증된 사용자의 이름입니다. HTTP 연결에서는 마지막 요청의 사용자입니다. keep-alive 연결에서는 요청마다 별도로 인증이 이루어집니다. 사용자 이름이 변경되면 다음 인증 전까지 이 컬럼에는 이전 이름이 표시됩니다. 액세스 검사에는 이름이 아닌 사용자 ID가 사용됩니다.
* `status` ([LowCardinality(String)](/ko/reference/data-types/lowcardinality)) — 연결의 상태입니다. `active`: 현재 쿼리가 실행 중입니다. `idle`: 연결이 열린 상태로 다음 쿼리 또는 다음 HTTP 요청을 기다리고 있습니다.
* `query_id` ([String](/ko/reference/data-types/string)) — 현재 실행 중인 쿼리의 식별자입니다. 연결이 유휴 상태이면 비어 있습니다.
* `client_name` ([String](/ko/reference/data-types/string)) — 클라이언트 애플리케이션의 이름입니다. TCP 클라이언트는 핸드셰이크 과정에서 이 이름을 전송합니다. HTTP에서는 마지막 요청의 `User-Agent` 헤더 값입니다.
* `client_version_major` ([UInt64](/ko/reference/data-types/int-uint)) — TCP 핸드셰이크에서 전달받은 클라이언트의 주 버전입니다. HTTP 연결에서는 0입니다.
* `client_version_minor` ([UInt64](/ko/reference/data-types/int-uint)) — TCP 핸드셰이크에서 전달받은 클라이언트의 마이너 버전입니다. HTTP 연결에서는 0입니다.
* `client_version_patch` ([UInt64](/ko/reference/data-types/int-uint)) — TCP 핸드셰이크에서 전달받은 클라이언트의 패치 버전입니다. HTTP 연결에서는 0입니다.
* `connected_time` ([DateTime](/ko/reference/data-types/datetime)) — 서버가 소켓 처리를 시작한 시간입니다. TCP와 HTTP 모두 동일하게 핸드셰이크, 인증, 첫 번째 쿼리보다 앞선 시점입니다.
* `last_query_time` ([Nullable(DateTime)](/ko/reference/data-types/nullable)) — 이 연결에서 실행된 마지막 쿼리의 시작 시간입니다. 연결에서 쿼리가 한 번도 실행되지 않았으면 NULL입니다.

## 예시 {#examples}

```sql
SELECT connection_id, protocol, user, status, query_id, client_name, connected_time, last_query_time
FROM system.connections
FORMAT Vertical;
```

```sql
SELECT hostName(), protocol, status, count()
FROM clusterAllReplicas(default, system.connections)
GROUP BY ALL;
```
