서브쿼리의 `MergeTree` 테이블 파티션 표현식이 서브쿼리 출력 컬럼의 결정론적 함수인 경우, `IN (subquery)`용 Set을 생성할 때 서브쿼리 결과를 파티션별로 병렬 사전 중복 제거하도록 활성화합니다. 각 파티션은 별도의 스트림으로 읽고 독립적으로 중복 제거하므로, 단일 Set 채우기 변환에서는 고유한 행만 해시합니다. `FINAL`, 병렬 레플리카 또는 `GLOBAL IN`에서는 적용되지 않습니다. 데이터에 파티션이 2개 이상 있고 가장 큰 파티션의 행 수가 평균 파티션 행 수의 2배 이하일 때만 최적화가 파티션별 읽기를 요청합니다(편향 검사를 건너뛰려면 [force&#95;creating&#95;set&#95;partitions&#95;independently](/ko/reference/settings/session-settings/force#force_creating_set_partitions_independently)를 참조하십시오). 다른 파티션별 기능이 스트림을 분할하여 이미 파티션 간에 겹치지 않는 경우(예: 파티션별 `LIMIT BY`)에는 읽기 레이아웃이 이미 고정되어 있으므로, 사전 중복 제거는 이 조건과 관계없이 적용됩니다. Set을 생성하는 동안 스트림별 중복 제거 테이블은 합쳐서 고유 키의 복사본을 약 1개 더 보유합니다.

</div>

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "파티션 표현식이 `DISTINCT` 컬럼의 결정론적 함수일 때 파티션별 `DISTINCT`를 독립적으로 평가할 수 있도록 하는 새로운 설정입니다."}]}]} />

파티션 표현식이 `DISTINCT` 컬럼의 결정론적 함수인 경우, 스트림 간 머지를 생략하고 별도 스레드에서 파티션별 `DISTINCT`를 독립적으로 평가하도록 합니다. 파티션 수가 코어 수와 비슷하고 파티션 크기가 대략 동일할 때 유용합니다. 그렇지 않은 경우 비용 휴리스틱에 따라 이 최적화가 적용되지 않습니다. [max&#95;rows&#95;in&#95;distinct](/ko/reference/settings/session-settings/max-rows#max_rows_in_distinct) 또는 [max&#95;bytes&#95;in&#95;distinct](/ko/reference/settings/session-settings/max-bytes#max_bytes_in_distinct)가 설정된 경우에도 적용되지 않습니다. 이러한 제한은 전체 머지 결과를 확인하는 단일 `DISTINCT` 변환에서 적용되므로, 제한의 전역적 의미를 유지하기 위해 스트림 간 머지를 유지합니다.

`coalesce(a_1, ..., a_N) <op> const` 형태의 프레디케이트(및 이에 해당하는 `ifNull`, 또는 상수가 왼쪽에 있는 동일한 형태)를 인덱스 분석 전에 `(a_1 <op> const) OR (a_1 IS NULL AND a_2 <op> const) OR ... OR (a_1 IS NULL AND ... AND a_{N-1} IS NULL AND a_N <op> const)` 논리합으로 재작성하여 각 `a_i`의 컬럼별 프라이머리 키와 스킵 인덱스를 사용할 수 있도록 합니다. `coalesce(a, 42, b)` 및 `coalesce(a, b, 42)`와 같은 일부 상수 형태도 처리합니다. 인수 목록은 `coalesce` 자체와 마찬가지로 정규화됩니다(`NULL` 리터럴은 제거되고, 첫 번째 비`Nullable` 인수 뒤의 인수는 제거됩니다). 후행 비`NULL` 상수가 있으면 최종 분기로 생성됩니다. 이 재작성은 인덱스 프루닝에만 추가로 적용되며, 런타임 필터링은 계속 원래 프레디케이트를 사용합니다.
또한 `nullIf(key, sentinel) = const` 형태의 정확한 동등 프레디케이트(`sentinel != const`이고 타입이 정확히 일치하는 경우)는 `key = const`로 재작성되어 `key`의 프라이머리 키, 파티션 및 스킵 인덱스가 그래뉼을 직접 프루닝할 수 있습니다. 범위 조건 및 논리합 형태의 `nullIf` 프루닝은 지원되지 않습니다.

`MergeTree` 테이블의 파티션 표현식이 윈도우 `PARTITION BY` 컬럼의 결정론적 함수인 경우, 별도 스레드에서 파티션별로 윈도우 함수를 독립적으로 평가하도록 설정합니다. 각 파티션은 별도의 스트림으로 읽고, 윈도우 정렬 설명에 따라 독립적으로 정렬한 후 자체 윈도우 변환으로 처리합니다. 이때 일반적으로 모든 행을 스레드 간에 재분배하는 해시 스캐터를 건너뜁니다. 파티션 수가 코어 수와 비슷하고 파티션 크기가 대체로 동일할 때 유용합니다. 그렇지 않으면 비용 휴리스틱에 따라 이 최적화를 건너뜁니다. [max&#95;number&#95;of&#95;partitions&#95;for&#95;independent&#95;window](/ko/reference/settings/session-settings/max-number#max_number_of_partitions_for_independent_window) 및 [force&#95;window&#95;partitions&#95;independently](/ko/reference/settings/session-settings/force#force_window_partitions_independently)를 참조하십시오. `FINAL` 또는 병렬 레플리카와 함께 사용할 때는 적용되지 않습니다.
