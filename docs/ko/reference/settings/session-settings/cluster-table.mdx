## cluster_table_function_split_by_split_offsets {#cluster_table_function_split_by_split_offsets}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "새 설정입니다."}]}]} />

분할 세분화 수준이 `bucket`일 때 테이블 메타데이터에 파일 크기와 행 그룹(row groups) 오프셋(Iceberg의 `split_offsets`)이 기록되어 있으면, 파일을 읽지 않고 이 오프셋을 기준으로 파일을 바이트 범위로 잘라냅니다. 각 작업은 자신의 범위 안에서 시작하는 행 그룹(row groups)을 읽습니다. 그 외의 경우, 그리고 쿼리 조건 캐시에 적중한 경우에는 initiator가 모든 파일의 바닥글을 읽습니다.

클러스터의 모든 서버가 이 기능을 지원해야 합니다. 바이트 범위가 지정된 작업은 이전 버전의 서버로 전송할 수 없습니다.

## cluster_table_function_split_granularity {#cluster_table_function_split_granularity}

<SettingsInfoBlock type="ObjectStorageGranularityLevel" default_value="file" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.11"},{"label": "file"},{"label": "새 설정입니다."}]}]} />

CLUSTER TABLE FUNCTION 실행 시 데이터를 작업으로 분할하는 방식을 제어합니다.

이 설정은 클러스터 전체에 작업을 분산할 때의 세분화 수준을 정의합니다.

* `file` — 각 작업이 파일 전체를 처리합니다.
* `버킷` — 파일 내부의 각 데이터 블록 단위로 작업이 생성됩니다(예: Parquet row groups).

`버킷`처럼 더 세밀한 세분화 수준을 선택하면, 적은 수의 대용량 파일을 처리할 때 병렬성을 높일 수 있습니다.
예를 들어 Parquet 파일에 여러 row group이 포함된 경우, `버킷` 세분화 수준을 사용하면 각 그룹을 서로 다른 워커가 독립적으로 처리할 수 있습니다.
