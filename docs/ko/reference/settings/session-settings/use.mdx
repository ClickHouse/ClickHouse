## use_columns_cache {#use_columns_cache}

<ExperimentalBadge />

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "MergeTree 테이블에서 컬럼 캐시를 활성화하는 새 실험적 설정이며, 기본적으로 비활성화되어 있습니다."}]}]} />

컬럼 캐시 사용 여부를 지정합니다. 0 또는 1을 사용할 수 있으며, 기본값은 0(비활성화)입니다.
컬럼 캐시는 `MergeTree` 테이블에서 역직렬화된 컬럼을 저장하므로, 자주 사용되는 데이터를 반복해서 압축 해제하고 역직렬화하는 작업이 사라집니다. 따라서 동일한 데이터에 반복적으로 실행되는 쿼리의 지연 시간을 크게 줄일 수 있습니다. 캐시는 테이블 UUID, 데이터 파트 이름, 컬럼명, 그리고 약 65536개 행으로 구성된 연속 그래뉼의 스트라이프(stripe)를 키로 사용합니다.

엔트리는 테이블 UUID를 키로 사용하므로, 캐시는 `Atomic`, `Replicated`, `Shared`(ClickHouse Cloud의 기본 데이터베이스 엔진)처럼 UUID를 할당하는 데이터베이스의 테이블에서만 동작합니다. 레거시 `Ordinary` 데이터베이스의 `MergeTree` 테이블은 UUID가 nil이므로 별도의 알림 없이 이 설정을 무시합니다.

현재 캐시는 wide 파트에만 적용됩니다. compact 파트의 데이터는 컬럼 캐시에서 읽거나 컬럼 캐시에 기록하지 않으므로, 읽기 가속 여부는 파트 포맷에 따라 달라집니다.

하나의 엔트리에는 한 스트라이프 내의 연속된 그래뉼 범위가 저장됩니다. 그래뉼은 첫 번째 행부터 마지막 행까지 모두 읽힌 후에만 캐시에 저장되고, 읽기는 그래뉼 단위로 캐시에서 처리되며, 서로 다른 읽기가 기록한 범위는 하나로 머지됩니다. 따라서 파트를 서로 다른 마크 범위로 나누어 읽더라도 엔트리를 공유할 수 있습니다.

## use_constant_folding_in_index_analysis {#use_constant_folding_in_index_analysis}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.7"},{"label": "0"},{"label": "MergeTree 인덱스 분석 중 파트별 필터 프레디케이트에 파티션 수준 상수 폴딩을 적용하여, 분기가 파티션 값에 따라 달라지는 필터의 프루닝을 개선하는 새로운 설정입니다."}]}]} />

파트별 프라이머리 키와 스킵 인덱스를 분석할 때 파티션 수준 상수를 필터 프레디케이트에 대입합니다.

파티션 키가 필터에서 프라이머리 키 또는 스킵 인덱스 컬럼과 함께 사용되면, 인덱스 분석 시 각 파트 내에서 파티션 값을 개별적으로 폴딩할 수 있습니다. 이는 분기가 서로 다른 파티션을 대상으로 하는 논리합 필터에서 특히 유용합니다. 예를 들어, `PARTITION BY a`와 `ORDER BY b`가 있는 경우:

```sql
SELECT * FROM t WHERE (a = 1 AND b >= 1) OR (a = 2 AND b > 10) OR (a = 3 AND b > 10)
```

파티션 `a = 1`의 파트에서는 조건이 `b >= 1`로 축약되고, 파티션 `a = 2` 및 `a = 3`에서는 `b > 10`으로 축약되므로, 각 파트는 실제로 적용되는 프레디케이트를 기준으로 분석됩니다.

가능한 값:

* 0 — 비활성화됨.
* 1 — 활성화됨.

## use_hedged_requests {#use_hedged_requests}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "21.9"},{"label": "1"},{"label": "기본적으로 Hedged Requests 기능을 활성화합니다"}]}]} />

원격 쿼리에 대한 hedged requests 로직을 활성화합니다. 이를 통해 하나의 쿼리에 대해 서로 다른 레플리카로 여러 연결을 설정할 수 있습니다.

다른 연결은 취소됩니다. `max_parallel_replicas > 1`인 쿼리도 지원됩니다.

MergeTree 읽기 풀 내에서 데이터 읽기 시점에 평가된 인덱스를 적용합니다. 스킵 인덱스(`use_skip_indexes_on_data_read` 참조) 또는 프로젝션 인덱스(`optimize_use_projection_filtering` 참조)에 의해 완전히 필터링된 마크 범위는 읽는 동안 그래뉼 단위로 건너뛰는 대신, 해당 범위에 대한 읽기 작업을 생성하기 전에 제거됩니다.

## use_strict_insert_block_limits {#use_strict_insert_block_limits}

* 최소 임계값(AND): min&#95;insert&#95;block&#95;size&#95;rows AND min&#95;insert&#95;block&#95;size&#95;bytes에 모두 도달한 경우입니다.

비활성화하면 다음과 같은 경우 블록이 생성됩니다:

* 최소 임계값(OR): min&#95;insert&#95;block&#95;size&#95;rows OR min&#95;insert&#95;block&#95;size&#95;bytes 중 하나에 도달한 경우입니다.

**참고**: max 설정이 min 설정보다 작으면 max 한계가 우선하며, 최소 임계값에 도달하기 전에 블록이 생성됩니다.

**참고**: 이 설정은 async inserts에 대해서는 자동으로 비활성화됩니다. async inserts는 항목별 중복 제거 토큰을 연결하는데, 이는 엄격한 한계 적용에 필요한 블록 분할과 호환되지 않기 때문입니다.

기본적으로 비활성화되어 있습니다.

## use_uncompressed_cache {#use_uncompressed_cache}

<SettingsInfoBlock type="Bool" default_value="0" />

압축 해제된 블록의 캐시를 사용할지 여부를 지정합니다. 0 또는 1을 사용할 수 있습니다. 기본값은 0(비활성화)입니다.
