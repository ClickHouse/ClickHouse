## enable_join_runtime_filters_index_analysis {#enable_join_runtime_filters_index_analysis}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.9"},{"label": "0"},{"label": "JOIN 런타임 필터가 Production 티어 기능이 되었습니다."}]}, {"id": "row-2","items": [{"label": "26.7"},{"label": "0"},{"label": "동적 인덱스 분석을 사용한 조인 필터링을 활성화하는 새로운 설정"}]}, {"id": "row-3","items": [{"label": "26.10"},{"label": "1"},{"label": "빌드(오른쪽) 측에서 수집한 런타임 필터로 JOIN의 프로브(왼쪽) 측 그래뉼 프루닝을 활성화합니다."}]}]} />

빌드 측에서 수집한 런타임 필터를 사용하여 JOIN의 프로브 측 그래뉼을 프루닝합니다. `enable_join_runtime_filters`를 참조하십시오.
`use_skip_indexes_on_data_read = 1`인 경우에만 적용됩니다.
프로브 측의 프라이머리 키 컬럼이거나 `minmax`, `set` 또는 `bloom_filter` 스킵 인덱스가 적용된 조인 키만 프루닝할 수 있습니다.
런타임 필터가 정확한 키 값을 유지한 경우 프루닝 프레디케이트는 해당 값들로 이루어진 `IN` 집합이 되고, 그렇지 않으면 키의 최솟값/최댓값 범위가 사용됩니다(이 경우 프루닝 효과가 더 낮습니다).

병렬 레플리카(`enable_parallel_replicas = 1`)에서도 동작합니다. 각 레플리카는 직접 구성한 필터로 자신이 읽는 그래뉼을 프루닝합니다. 이 필터는 일부만 포함할 수 있습니다. `RIGHT` 조인에서는 빌드 측이 레플리카 간에 분할되므로, 각 레플리카의 필터에는 자신이 담당하는 부분만 포함됩니다. 하지만 조인의 어느 한쪽만 분할되고, 일치하는 모든 행 쌍은 정확히 하나의 레플리카에서 만나며, 각 레플리카는 결과 중 서로 겹치지 않는 부분을 출력하므로 결과는 여전히 올바릅니다.

분산 쿼리 계획(`make_distributed_plan = 1`)을 사용하면 그래뉼 프루닝이 수행되지 않습니다. 이 경우 이 설정은 아무런 효과가 없습니다. 쿼리는 동일한 결과를 반환하고 JOIN 런타임 필터 자체도 이 설정을 비활성화했을 때와 똑같이 동작하며, 그래뉼 프루닝만 적용되지 않을 뿐입니다.

`FINAL`로 읽는 프로브 측(`FINAL` 읽기에는 프루닝이 구현되어 있지 않으며, `optimizeLazyFinal`은 이러한 읽기를 디스크립터 없이 재구성합니다)과 대기 중인 데이터, `ALTER` 뮤테이션 또는 패치 파트가 있는 테이블에서도 그래뉼 프루닝은 수행되지 않습니다. 이러한 경우에도 마찬가지로 이 설정은 아무런 효과가 없습니다.

## enable_join_seal_gated_reading {#enable_join_seal_gated_reading}

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0"},{"label": "해시 JOIN의 프로브 측 읽기를 빌드 측 런타임 필터(runtime filter)가 완료될 때까지 대기시키고, 이 필터로 읽기 범위를 프루닝하는 새 실험적 설정입니다."}]}]} />

해시 JOIN의 프로브 측 읽기를 빌드 측 런타임 필터(runtime filter)가 완료될 때까지 대기시킵니다(`enable_join_runtime_filters` 참조). 필터가 완료될 때까지 프로브 측에서는 아무것도 읽지 않으며, 필터가 완료되면 일반적인 행 수준(row-level) 필터링과 더불어, 읽기 작업이 생성되기 전에 이 필터를 사용해 프라이머리 키 기준으로 마크 범위 전체를 프루닝합니다. 이러한 대기 조건은 쿼리 파이프라인(query pipeline)의 엣지(edge)로 표현됩니다. 대기 조건이 적용된 읽기에서는 동일한 런타임 필터에 대한 읽기 시점 인덱스 분석(Index Analysis)(`enable_join_runtime_filters_index_analysis` 참조)이 중복으로 간주되어 생략됩니다.

실험적 기능입니다. single-threaded 읽기와 순차(in-order) 읽기를 포함한 로컬 읽기에는 대기 조건이 적용됩니다. FINAL을 사용하는 읽기, 병렬 레플리카에서의 읽기, 또는 프라이머리 키 범위로 세그먼트 분할된 조인에서의 읽기는 대기 조건 없이 행 수준 필터링만 사용하는 읽기로 폴백됩니다.
