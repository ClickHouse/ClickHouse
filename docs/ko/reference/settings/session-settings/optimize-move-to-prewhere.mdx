## optimize_move_to_prewhere {#optimize_move_to_prewhere}

<SettingsInfoBlock type="Bool" default_value="1" />

[SELECT](/ko/reference/statements/select/index) 쿼리에서 자동 [PREWHERE](/ko/reference/statements/select/prewhere) 최적화의 사용 여부를 설정합니다.

[*MergeTree](/ko/reference/engines/table-engines/mergetree-family/index) 테이블에서만 작동합니다.

가능한 값:

* 0 — 자동 `PREWHERE` 최적화가 비활성화됩니다.
* 1 — 자동 `PREWHERE` 최적화가 활성화됩니다.

## optimize_move_to_prewhere_if_final {#optimize_move_to_prewhere_if_final}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "FINAL이 포함된 쿼리에서 자동 PREWHERE 최적화를 기본적으로 활성화합니다. 정렬 키에만 의존하면서 쿼리 내에서 결정적인 조건만 이동하므로 결과에는 영향이 없습니다. `compatibility`를 26.10 미만으로 설정하면 이전 동작으로 돌아갑니다."}]}]} />

[FINAL](/ko/reference/statements/select/from#final-modifier) 수정자가 있는 [SELECT](/ko/reference/statements/select/index) 쿼리에서 자동 [PREWHERE](/ko/reference/statements/select/prewhere) 최적화의 사용 여부를 설정합니다.

정렬 키에만 의존하면서 쿼리 내에서 결정적인 조건만 이동하므로,
`FINAL`의 결과에는 영향이 없습니다. [GraphiteMergeTree](/ko/reference/engines/table-engines/mergetree-family/graphitemergetree)에서는
`FINAL`이 동일한 경로의 인접한 행을 하나의 행으로 머지합니다. 따라서 이 최적화는 경로가 정렬 키의 첫 번째 컬럼인 경우에만,
경로 컬럼에 대한 조건만 이동합니다.

[*MergeTree](/ko/reference/engines/table-engines/mergetree-family/index) 테이블에서만 작동합니다.

가능한 값:

* 0 — `FINAL` 수정자가 있는 `SELECT` 쿼리에서 자동 `PREWHERE` 최적화가 비활성화됩니다.
* 1 — `FINAL` 수정자가 있는 `SELECT` 쿼리에서 자동 `PREWHERE` 최적화가 활성화됩니다.

## optimize_move_to_prewhere_respect_short_circuit {#optimize_move_to_prewhere_respect_short_circuit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "1"},{"label": "새로운 설정: 자동 PREWHERE는 예외를 발생시킬 수 있는 조건을 단락 평가에서 그보다 먼저 적용되는 조건들 뒤에 유지합니다. `compatibility`를 26.12 미만으로 설정하면 이전 순서로 복원됩니다."}]}]} />

조건을 WHERE에서 PREWHERE로 이동할 때, 예외를 발생시킬 수 있는 조건이 단락 평가(short-circuit evaluation)에 따라 앞에 작성된 조건들을 통과한 행에서만 평가된다면 해당 조건을 앞의 조건들 뒤에 그대로 유지합니다.
예를 들어 `a = 'one' AND toDateTime64(s, 3) > '2020-01-01'`은 `a != 'one'`인 행에서는 `s`를 파싱하지 않습니다.
이러한 조건은 비용 기준으로 정렬되지 않습니다. 이 설정을 비활성화하면 조건은
[short&#95;circuit&#95;function&#95;evaluation](/ko/reference/settings/session-settings/short-circuit-function-evaluation#short_circuit_function_evaluation)이 `disable`인 것처럼 정렬되므로, 앞선 조건에서 제외되는 행에서도
쿼리가 예외를 발생시킬 수 있습니다.
