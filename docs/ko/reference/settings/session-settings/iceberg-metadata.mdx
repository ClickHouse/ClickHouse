## iceberg_metadata_log_level {#iceberg_metadata_log_level}

<SettingsInfoBlock type="IcebergMetadataLogLevel" default_value="none" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.9"},{"label": "none"},{"label": "새 설정입니다."}]}]} />

Iceberg 테이블의 메타데이터 로깅 수준을 `system.iceberg_metadata_log`에 기록할지 제어합니다.
이 설정은 일반적으로 디버깅 목적으로 수정할 수 있습니다.

가능한 값:

* none - 메타데이터 로그를 기록하지 않습니다.
* metadata - 루트 metadata.json 파일입니다.
* manifest&#95;list&#95;metadata - 위의 모든 항목 + 스냅샷에 해당하는 avro manifest 목록의 메타데이터입니다.
* manifest&#95;list&#95;entry - 위의 모든 항목 + avro manifest 목록의 항목입니다.
* manifest&#95;file&#95;metadata - 위의 모든 항목 + 탐색한 avro manifest 파일의 메타데이터입니다.
* manifest&#95;file&#95;entry - 위의 모든 항목 + 탐색한 avro manifest 파일의 항목입니다.

## iceberg_metadata_previous_versions_max {#iceberg_metadata_previous_versions_max}

<SettingsInfoBlock type="NonZeroUInt64" default_value="100" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "100"},{"label": "새 설정입니다. 이전에는 커밋할 때마다 계속 늘어나던 `metadata-log`를 이제 Iceberg 테이블에 대한 쓰기 작업에서 제한합니다."}]}]} />

쓰기(write) 시 Iceberg 테이블의 `metadata-log`에 유지하는 엔트리의 최대 개수이며, 해당 쓰기에서 작성하는 메타데이터 파일의 엔트리도 포함됩니다. 쓰기로 인해 엔트리 수가 제한을 초과하면 가장 오래된 엔트리부터 제거됩니다. 메타데이터 파일 자체는 삭제되지 않습니다.

Iceberg 테이블 속성 `write.metadata.previous-versions-max`가 이 설정보다 우선합니다. Java 구현과 마찬가지로 이 속성은 이전 메타데이터 파일의 개수를 나타내며 최솟값은 1이므로, `metadata-log`에는 속성 값보다 1개 많은 엔트리가 유지됩니다.

REST 카탈로그(REST catalog)처럼 메타데이터 파일을 직접 작성하는 카탈로그(Catalog)에 속한 테이블에는 이 설정이 적용되지 않습니다. 이 경우 카탈로그가 자체 구성과 테이블 속성에 따라 `metadata-log`를 관리합니다.

## iceberg_metadata_staleness_ms {#iceberg_metadata_staleness_ms}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.3"},{"label": "0"},{"label": "원격 카탈로그(Catalog)에서 가져오는 것을 방지하기 위해 READ 작업에서 캐시된 메타데이터 버전을 사용할 수 있도록 하는 새로운 설정"}]}]} />

0이 아닌 경우, 지정된 staleness 윈도우보다 최신인 캐시된 메타데이터가 있으면 최신 Iceberg 메타데이터 버전을 가져오지 않습니다(원격 카탈로그(Catalog)에서 가져오는 경우, `iceberg_use_version_hint` 사용 시 `metadata/version-hint.text`에서 가져오는 경우, 메타데이터 파일 목록 조회를 통해 가져오는 경우 모두 해당). 0이면 항상 최신 메타데이터 버전을 가져옵니다. 이 값을 0이 아닌 값으로 설정하면 staleness를 감수하는 대신 읽기 작업의 지연 시간을 줄일 수 있습니다.
