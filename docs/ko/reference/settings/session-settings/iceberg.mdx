## iceberg_list_only_v_prefixed_metadata_files {#iceberg_list_only_v_prefixed_metadata_files}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "경로로 읽는 Iceberg 테이블의 최신 메타데이터 파일을 찾을 때 `metadata\/v` 키 접두사만 목록 조회하는 새로운 설정입니다."}]}]} />

S3 또는 Azure에서 경로로 읽는 Iceberg 테이블(Iceberg table)의 최신 메타데이터 파일을 찾을 때 키 접두사 `metadata/v`만 목록 조회하므로, 같은 `metadata` 디렉터리에 저장된 매니페스트는 목록 조회 대상에서 제외됩니다. 해당 접두사 아래에 `.metadata.json` 파일이 있으면 그 파일들만 후보가 되고, 없으면 디렉터리 전체를 목록 조회합니다. `iceberg_use_version_hint`, `iceberg_metadata_file_path`, `iceberg_metadata_table_uuid` 또는 `iceberg_recent_metadata_file_by_last_updated_ms_field`와 함께 사용할 때는 적용되지 않으며, 데이터 레이크 카탈로그 데이터베이스의 테이블에도 적용되지 않습니다.

모든 메타데이터 파일 이름이 `v<N>...` 형식인 테이블(ClickHouse 및 Hadoop 카탈로그(catalogs)가 사용하는 명명 방식)에서만 활성화하십시오. `<N>-<uuid>.metadata.json` 파일이 함께 있는 디렉터리에서는 이 파일들이 후보에서 제외되므로, 해당 파일을 작성한 writer의 커밋이 반영되지 않습니다.

`ALTER TABLE ... EXECUTE remove_orphan_files`가 Iceberg 테이블(Iceberg table)에서 삭제할 수 있는 파일의 최소 경과 시간(초)입니다. `older_than` 값(명시적으로 지정했거나 `iceberg_orphan_files_older_than_seconds`에서 도출된 값)이 현재 시점으로부터 이 값보다 가까우면 거부됩니다. 아직 커밋되지 않은 쓰기 작업의 파일은 테이블 메타데이터에서 참조되지 않으므로 삭제 대상이 될 수 있으며, 이 경우 해당 쓰기 작업이 커밋될 때 테이블이 손상됩니다. 이 값은 테이블 쓰기 작업이 커밋되기까지 걸릴 수 있는 최대 시간보다 크게 설정하십시오. 0으로 설정하면 이 검사가 비활성화됩니다.

## iceberg_tolerate_conflicting_manifest_schemas {#iceberg_tolerate_conflicting_manifest_schemas}

활성화하면 Iceberg 매니페스트 파일의 schema-id가 metadata.json에서 이미 등록된 경우 metadata.json의 스키마를 사용하고, 매니페스트 파일 헤더의 `schema` 키에 있는 사본은 비교하지 않고 무시합니다. 비활성화하면 매니페스트 헤더의 사본을 metadata.json의 스키마와 비교하며, 충돌이 있으면 ICEBERG&#95;SPECIFICATION&#95;VIOLATION 오류와 함께 쿼리가 실패합니다.

매니페스트 헤더 스키마는 매니페스트가 기록된 시점의 테이블 스키마 사본일 뿐이며, 일부 writer(예: AWS S3 Tables 유지 관리 작업)가 저하된 사본을 여기에 저장하는 사례가 관찰되었습니다. 다른 쿼리 엔진은 metadata.json에서 스키마를 확인하고 서로 다른 헤더 사본은 무시하므로 기본값도 이를 따릅니다. metadata.json 스키마 정의 두 개 간의 충돌은 여전히 항상 쿼리를 실패시킵니다.
