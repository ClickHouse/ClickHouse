## text_index_like_min_pattern_length {#text_index_like_min_pattern_length}

<SettingsInfoBlock type="UInt64" default_value="4" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.4"},{"label": "4"},{"label": "새로운 설정"}]}]} />

딕셔너리 스캔을 통한 텍스트 인덱스 LIKE 평가를 사용하려면 LIKE/ILIKE 패턴에 포함된 영숫자 검색 문자열 또는 `startsWith`/`endsWith`의 검색 문자열의 최소 길이가 이 값 이상이어야 합니다.
이 임계값보다 짧은 패턴은 너무 많은 딕셔너리 토큰과 일치하므로, 비용이 큰 스캔을 방지하기 위해 건너뜁니다.

모든 패턴이 조건을 충족하는 `array` 토크나이저에서는 임계값이 전체 패턴에서 와일드카드가 아닌 문자의 개수와 비교됩니다.

`use_text_index_like_evaluation_by_dictionary_scan`이 활성화되어 있어야 합니다.

## text_index_posting_list_apply_mode {#text_index_posting_list_apply_mode}

<SettingsInfoBlock type="TextIndexPostingListApplyMode" default_value="lazy" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "lazy"},{"label": "텍스트 인덱스 쿼리는 이제 포스팅 리스트를 Roaring Bitmap으로 구체화하는 대신 커서를 사용해 필요할 때 디코딩하므로, 선택적 쿼리의 메모리 사용량과 CPU 시간이 감소합니다."}]}, {"id": "row-2","items": [{"label": "26.6"},{"label": "materialize"},{"label": "지연 포스팅 리스트 적용 모드를 위한 새로운 설정"}]}]} />

텍스트 인덱스 쿼리에서 포스팅 리스트를 적용하는 방식을 제어합니다.
&#39;materialize&#39;는 포스팅 리스트를 Roaring Bitmap으로 즉시 디코딩합니다.
&#39;lazy&#39;(기본값)는 커서 기반의 필요 시점 디코딩을 사용합니다(직렬화된 코덱이 있는 인덱스 포맷이 필요합니다).
&#39;lazy&#39;는 지원되는 경우에만 적용됩니다. 패턴(예: `LIKE`)이 있는 쿼리와 이전 버전에서 작성된 인덱스가 있는 파트는 &#39;materialize&#39;로 폴백됩니다.

## text_index_postings_intersection_algorithm {#text_index_postings_intersection_algorithm}

<SettingsInfoBlock type="TextIndexPostingsIntersectionAlgorithm" default_value="auto" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "auto"},{"label": "`text_index_lazy_intersection_density_threshold`를 대체하는 새로운 설정입니다. 지연 포스팅 리스트 적용 모드(lazy posting list apply mode)에서 사용할 포스팅 리스트 교집합 알고리즘을 선택합니다. `auto`는 이전 기본 동작을 그대로 유지하므로 `compatibility` 설정으로 이 값이 변경되어서는 안 됩니다."}]}]} />

지연 포스팅 리스트 적용 모드(`text_index_posting_list_apply_mode = 'lazy'`)에서 포스팅 리스트의 교집합을 구하는 알고리즘을 선택합니다.

* `auto` (기본값): 가장 희소한 포스팅 리스트로 가장 밀집된 포스팅 리스트의 패킹된 블록을 통째로 건너뛸 수 있는 경우에만 leapfrog를 사용하고, 그 외에는 전수 비교(brute-force) 방식의 비트맵 교집합을 사용합니다.
* `bruteforce`: 항상 전수 비교(brute-force) 방식의 비트맵 교집합을 사용합니다.
* `leapfrog`: 항상 leapfrog 교집합을 사용합니다.

토큰이 256개 이상인 교집합 연산에는 항상 leapfrog가 사용됩니다.
