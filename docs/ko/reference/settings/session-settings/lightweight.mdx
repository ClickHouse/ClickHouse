## lightweight_delete_mode {#lightweight_delete_mode}

<SettingsInfoBlock type="LightweightDeleteMode" default_value="alter_update" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.5"},{"label": "alter_update"},{"label": "새로운 설정"}]}]} />

경량한 삭제의 일부로 실행되는 내부 업데이트 쿼리의 모드입니다.

가능한 값:

* `alter_update` - heavyweight 뮤테이션을 생성하는 `ALTER UPDATE` 쿼리를 실행합니다.
* `lightweight_update` - 가능하면 경량 업데이트를 실행하고, 그렇지 않으면 `ALTER UPDATE`를 실행합니다.
* `lightweight_update_force` - 가능하면 경량 업데이트를 실행하고, 그렇지 않으면 예외를 발생시킵니다.

`DELETE FROM ... ON CLUSTER`에서는 쿼리를 실행하는 각 호스트가 자신의 설정에 따라 모드를 결정합니다. 따라서
프로필에 서로 다른 기본값이 설정된 호스트들은 각기 다른 모드로 삭제를 실행할 수 있습니다. 복제된
세그먼트는 하나의 레플리카에서만 실행되므로, 이때는 해당 레플리카의 설정에 따라 모드가 결정됩니다. 최초 쿼리의
세션에서 이 설정을 지정하면 이러한 동작을 재정의할 수 있습니다. 분산 DDL 엔트리는 `distributed_ddl_entry_format_version` 2 이상에서
세션 변경 사항을 함께 전달하며, 기본값은 이 조건을 충족합니다.
단, 이 설정에 제약을 둔 호스트에서는 값이 제약 범위 내로 다시 조정됩니다.

## lightweight_deletes_sync {#lightweight_deletes_sync}

<SettingsInfoBlock type="UInt64" default_value="2" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "24.4"},{"label": "2"},{"label": "'mutation_sync'와 동일하지만 경량한 삭제 실행만 제어합니다"}]}]} />

[`mutations_sync`](/ko/reference/settings/session-settings/mutations#mutations_sync)와 동일하지만 경량한 삭제 실행만 제어합니다.

가능한 값:

| 값   | 설명                                                          |
| --- | ----------------------------------------------------------- |
| `0` | 뮤테이션이 비동기로 실행됩니다.                                           |
| `1` | 쿼리는 현재 서버에서 경량한 삭제가 완료될 때까지 대기합니다.                          |
| `2` | 쿼리는 모든 레플리카(있는 경우)에서 경량한 삭제가 완료될 때까지 대기합니다.                 |
| `3` | 쿼리는 활성 레플리카에 대해서만 대기합니다. 비활성 레플리카는 활성 상태가 되면 경량한 삭제를 적용합니다. |

Cloud 기본값: `1`.
