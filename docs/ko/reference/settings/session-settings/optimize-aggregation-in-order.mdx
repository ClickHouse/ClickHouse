## optimize_aggregation_in_order {#optimize_aggregation_in_order}

<SettingsInfoBlock type="Bool" default_value="0" />

[MergeTree](/ko/reference/engines/table-engines/mergetree-family/mergetree) 테이블에서 정렬 순서에 맞춰 데이터를 집계하는 [SELECT](/ko/reference/statements/select/index) 쿼리의 [GROUP BY](/ko/reference/statements/select/group-by) 최적화를 활성화합니다.

이 설정은 해당 인수 기준으로 정렬된 테이블에서 `GROUP BY` 없이 단일 `uniqExact`(또는 `count(DISTINCT)`)를 사용하는 경우에도 적용됩니다. 이때 고유 값(distinct values)은 순서대로 들어오는 즉시 계산되므로 메모리에 보관되지 않습니다. 스레드가 여러 개이면 읽기 작업이 정렬 키 범위 단위로 분할되어 병렬로 계산됩니다. 분할할 수 없는 경우(예: floating-point 인수이거나 정렬 키에 함수를 적용한 경우)에는 일반 집계 방식이 사용됩니다.

프로젝션은 집계 순서보다 먼저 결정됩니다. [프로젝션(projection)](/ko/reference/engines/table-engines/mergetree-family/mergetree#projections)이 테이블보다 적은 수의 그래뉼을 읽는다면 `GROUP BY` 키 기준으로 정렬되어 있지 않더라도 해당 프로젝션이 사용되며, 이 경우 순서대로 집계하지 않고 모든 그룹을 메모리에 유지한 채 집계합니다.

가능한 값:

* 0 — `GROUP BY` 최적화가 비활성화됩니다.
* 1 — `GROUP BY` 최적화가 활성화됩니다.

## optimize_aggregation_in_order_limit {#optimize_aggregation_in_order_limit}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.7"},{"label": "1"},{"label": "`ORDER BY`가 `GROUP BY` 정렬 지정의 접두사인 경우, 충분한 그룹이 생성되면 조기에 종료할 수 있도록 `LIMIT`을 aggregation-in-order에 푸시하는 새로운 설정입니다."}]}]} />

활성화되어 있고 aggregation in order가 사용 중이면, 충분한 그룹이 생성된 후 조기에 종료할 수 있도록 `LIMIT`을 집계 단계에 푸시합니다. 이렇게 하면 ORDER BY가 GROUP BY 키 접두사와 일치할 때 읽는 데이터 양을 줄일 수 있습니다. `rows_before_limit_at_least`에 보고되는 값이 줄어들 수 있으므로, 정확한 개수가 필요하면 `exact_rows_before_limit`를 사용하십시오.
