## use_query_cache {#use_query_cache}

<SettingsInfoBlock type="Bool" default_value="0" />

이 설정을 활성화하면 `SELECT` 쿼리에서 [쿼리 캐시](/ko/concepts/features/performance/caches/query-cache)를 사용할 수 있습니다. 매개변수 [enable&#95;reads&#95;from&#95;query&#95;cache](/ko/reference/settings/session-settings/enable#enable_reads_from_query_cache)
및 [enable&#95;writes&#95;to&#95;query&#95;cache](/ko/reference/settings/session-settings/enable#enable_writes_to_query_cache)는 캐시 사용 방식을 더 세부적으로 제어합니다.

가능한 값:

* 0 - 비활성화됨
* 1 - 활성화됨

## use_query_condition_cache {#use_query_condition_cache}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.4"},{"label": "1"},{"label": "새로운 최적화"}]}, {"id": "row-2","items": [{"label": "25.3"},{"label": "0"},{"label": "새 설정입니다."}]}]} />

[쿼리 조건 캐시](/ko/concepts/features/performance/caches/query-condition-cache)를 활성화합니다. 이 캐시는 `WHERE` 절의 조건을 만족하지 않는 데이터 파트(data part)의 그래뉼 범위를 저장하고,
이 정보를 후속 쿼리에서 임시 인덱스로 재사용합니다.

가능한 값:

* 0 - 비활성화됨
* 1 - 활성화됨

## use_query_condition_cache_for_time_conditions {#use_query_condition_cache_for_time_conditions}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "시간 상수를 그리드에 맞춰 반올림한 결정적 조건을 도출하여, 쿼리 조건 캐시가 현재 시간이 포함된 조건(예: `WHERE time >= now() - INTERVAL 10 DAY`)도 처리할 수 있도록 하는 새로운 설정입니다. 기본적으로 활성화되어 있습니다. previous_value=false이므로 `compatibility`를 이전 버전으로 설정하면 이러한 조건은 기존과 같이 캐시되지 않습니다."}]}]} />

`MergeTree` 테이블에서 읽을 때 현재 시간이 포함된 조건(예: `WHERE time >= now() - INTERVAL 10 DAY`)에 대해 [쿼리 조건 캐시](/ko/concepts/features/performance/caches/query-condition-cache)를 활성화합니다. 파일 및 객체 스토리지(`file`, `s3` 등)에서 읽을 때는 결정적 조건에 대해서만 쿼리 조건 캐시를 사용하며, 이 설정의 영향을 받지 않습니다.

이러한 조건은 시각에 따라 달라지는 비결정적 조건이므로 그대로 캐시할 수 없습니다. 대신 상수로 폴딩된 현재 시간 값을 시간 격자에 맞춰 반올림하여 결정적 조건을 도출합니다. 예를 들어 `WHERE time >= '2026-08-09 12:34:56'`은 `WHERE time >= '2026-08-09 00:00:00'`이 됩니다(캐시 읽기에서는 내림, 캐시 쓰기에서는 올림을 적용하여 캐시의 정확성을 보장합니다). 그리드 간격은 상수와 현재 시간 사이의 차이에 비례하며([`query_condition_cache_time_condition_grid_factor`](/ko/reference/settings/session-settings/other#query_condition_cache_time_condition_grid_factor) 참조), 1초에서 1일 사이로 제한됩니다.

상수가 이미 그리드에 정렬되어 있으면(예: `WHERE time >= today() - 10` 또는 `WHERE time >= toStartOfDay(now())`) 캐시는 해당 그리드 셀 전체에 걸쳐, 예를 들어 그날이 끝날 때까지 유효합니다. 그렇지 않으면 캐시는 `WHERE time >= now() - INTERVAL 10 DAY`처럼 시간의 하한 경계에 대해서만 재사용됩니다. 즉, 한 그리드 셀에서 기록된 캐시 엔트리는 다음 셀에서 사용됩니다. `WHERE time < now()`처럼 정렬되지 않은 상한은 단독으로 쓰이든 `WHERE time >= now() - INTERVAL 10 DAY AND time < now()`와 같은 슬라이딩 윈도우의 일부로 쓰이든 이후 쿼리에서 재사용되지 않습니다. 이후 쿼리의 조건이 이전 쿼리의 조건에 포함되지 않기 때문입니다.

이 설정은 `use_query_condition_cache`도 활성화되어 있어야 적용됩니다.

가능한 값:

* 0 - 비활성화됨
* 1 - 활성화됨

## use_query_condition_cache_for_top_k {#use_query_condition_cache_for_top_k}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "`ORDER BY ... LIMIT n` (TopK) 읽기에 쿼리 조건 캐시를 적용하기 위한 새로운 설정입니다. 기본적으로 활성화되어 있습니다. 이 기능은 26.7에서 비활성화되어 있으므로, 이전 버전과의 `compatibility`를 설정하면 비활성화된 상태가 유지됩니다."}]}]} />

`ORDER BY <column> LIMIT n` (TopK) 최적화(동적 필터링 또는 스킵 인덱스 기반)를 사용하는 쿼리에 [쿼리 조건 캐시](/ko/concepts/features/performance/caches/query-condition-cache)를 활성화합니다. 비활성화하면 이러한 읽기는 캐시를 조회하거나 캐시에 데이터를 채우지 않습니다.

이러한 쿼리는 실행 중 런타임 임계값에 따라 그래뉼을 제외할 수 있으므로, 캐시 엔트리는 TopK 계획 매개변수와 읽은 파트 집합(`File` 테이블은 읽은 파일 집합과 해당 파일의 버전, 데이터 레이크 테이블은 해당 스냅샷)을 기준으로 분할됩니다. `use_query_condition_cache`도 활성화하지 않으면 이 설정은 효과가 없습니다.

가능한 값:

* 0 - 비활성화됨
* 1 - 활성화됨
