## distributed_ddl_entry_format_version {#distributed_ddl_entry_format_version}

<SettingsInfoBlock type="UInt64" default_value="5" />

분산 DDL(ON CLUSTER) 쿼리의 호환성 버전입니다. 클러스터 내 이전 버전 서버에서도 쿼리를 실행할 수 있도록 하려면 더 낮은 값을
사용하십시오.

서버는 버전 `1` 및 `2`의 엔트리를 실행하지 않습니다. 이전 버전 서버는 설정값이 `1`, `2`, `3`일 때 이러한 버전으로 엔트리를 기록하므로,
업그레이드하기 전에 모든 서버에서 이 설정을 `4` 이상으로 지정하고 분산 DDL
큐가 모두 처리될 때까지 기다리십시오.

가능한 값:

* `3` — `4`와 동일합니다. 이전 버전 서버는 버전 `3`의 엔트리를 거부하므로 `4`로 기록됩니다.
* `4` — 엔트리에 세션에서 변경된 설정과 OpenTelemetry 추적 컨텍스트가 포함되며, `CREATE` 쿼리는 initiator에서 정규화됩니다.
* `5` — 쿼리의 `initial_query_id`도 함께 보존합니다.
* `6` — 쿼리가 `BACKUP` 또는 `RESTORE`의 일부인지 여부도 함께 포함합니다.
* `7` — 상위 테이블의 UUID도 함께 포함합니다. `Replicated` 데이터베이스는 이 값을 사용하여 해당 테이블이 존재하는 경우에만 쿼리를 실행합니다.
* `8` — initiator의 사용자와 역할도 함께 포함합니다. 호스트는 서버 설정 `distributed_ddl_use_initial_user_and_roles`가 활성화된 경우 이 정보를 사용합니다.

Cloud 기본값: `6`.

## distributed_ddl_output_mode {#distributed_ddl_output_mode}

<SettingsInfoBlock type="DistributedDDLOutputMode" default_value="throw" />

분산 DDL 쿼리 결과의 포맷을 설정합니다.

가능한 값:

* `throw` — 쿼리가 완료된 모든 호스트의 쿼리 실행 상태가 포함된 결과 집합(result set)을 반환합니다. 일부 호스트에서 쿼리가 실패한 경우 첫 번째 Exception을 다시 발생시킵니다. 일부 호스트에서 아직 쿼리가 완료되지 않았고 [distributed&#95;ddl&#95;task&#95;timeout](/ko/reference/settings/session-settings/distributed-ddl#distributed_ddl_task_timeout)을 초과한 경우 `TIMEOUT_EXCEEDED` Exception을 발생시킵니다.
* `none` — `throw`와 비슷하지만, 분산 DDL 쿼리는 결과 집합을 반환하지 않습니다.
* `null_status_on_timeout` — 해당 호스트에서 쿼리가 아직 완료되지 않은 경우 `TIMEOUT_EXCEEDED`를 발생시키는 대신, 결과 집합의 일부 행에서 실행 상태로 `NULL`을 반환합니다.
* `never_throw` — 일부 호스트에서 쿼리가 실패하더라도 `TIMEOUT_EXCEEDED`를 발생시키지 않으며 Exception도 다시 발생시키지 않습니다.
* `none_only_active` - `none`과 비슷하지만 `Replicated` 데이터베이스의 비활성 레플리카는 기다리지 않습니다. 참고: 이 모드에서는 일부 레플리카에서 쿼리가 실행되지 않았고 백그라운드에서 실행될 예정인지 확인할 수 없습니다.
* `null_status_on_timeout_only_active` — `null_status_on_timeout`과 비슷하지만 `Replicated` 데이터베이스의 비활성 레플리카는 기다리지 않습니다.
* `throw_only_active` — `throw`와 비슷하지만 `Replicated` 데이터베이스의 비활성 레플리카는 기다리지 않습니다.

Cloud 기본값: `none_only_active`.

## distributed_ddl_task_timeout {#distributed_ddl_task_timeout}

<SettingsInfoBlock type="Int64" default_value="180" />

클러스터의 모든 호스트에서 DDL 쿼리 응답을 기다리는 timeout을 설정합니다. DDL request가 모든 호스트에서 수행되지 않으면, 응답에 timeout 오류가 포함되며 request는 async 모드로 실행됩니다. 음수 값은 무한대를 의미합니다.

가능한 값:

* 양의 정수.
* 0 — Async 모드.
* 음의 정수 — 무한 timeout.
