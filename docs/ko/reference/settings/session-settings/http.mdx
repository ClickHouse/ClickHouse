## http_allow_database_as_path {#http_allow_database_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "HTTP 요청의 URL 경로에서 데이터베이스 이름을 인식하는 새로운 설정."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "기본적으로 활성화됨: HTTP 인터페이스는 URL 경로의 `\/database\/` 구성 요소를 현재 데이터베이스로 해석합니다."}]}]} />

활성화하면 HTTP 인터페이스는 URL 경로의 `/database/` 구성 요소를 인식하여 현재 데이터베이스로 사용합니다.

이 설정은 경로 스타일로 라우팅된 요청을 해석할지 여부를 제어하는 사용자별 설정입니다. 라우팅 자체는 서버 수준의 `http_allow_path_requests` 구성 설정(기본적으로 활성화됨)에 의해 전역적으로 제어됩니다. HTTP 인터페이스가 경로 스타일 요청(예: `/my_db/my_table.csv`)을 쿼리 핸들러로 라우팅하려면 이 설정을 활성화해야 합니다. 라우팅 여부는 요청 인증 전에 결정되므로 사용자별 설정에 따라 달라질 수 없습니다. `http_allow_path_requests`가 비활성화되어 있으면 알 수 없는 경로는 일반 `404`를 반환합니다. 라우팅 후에는 인증된 사용자의 유효 설정을 기준으로 이 설정을 다시 확인하므로 사용자, 역할 또는 프로필별로 선택적으로 비활성화할 수 있습니다.

## http_allow_filters_as_path {#http_allow_filters_as_path}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "HTTP 요청의 URL 경로에서 Hive 스타일의 `name=value` 필터를 인식하는 새로운 설정입니다."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "기본적으로 활성화됨: HTTP 인터페이스는 `\/name=value\/` 경로 구성 요소를 `AND`로 결합된 필터로 해석합니다."}]}]} />

활성화하면 HTTP 인터페이스는 경로의 `/name=value/` 구성 요소(Hive 파티셔닝 스타일)를 인식하고 AND로 결합된 필터로 변환합니다. 연산자 `>`, `<`, `>=`, `<=`, `!=`, `<>`도 인식합니다.

[`http_allow_database_as_path`](/ko/reference/settings/session-settings/http#http_allow_database_as_path)와 마찬가지로 사용자별 설정입니다. 경로 스타일 요청의 라우팅은 서버 수준의 `http_allow_path_requests` 구성 설정에 따라 전역적으로 제어됩니다(라우팅은 인증 전에 수행됨).

## http_allow_filters_as_unrecognized_url_parameters {#http_allow_filters_as_unrecognized_url_parameters}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "0"},{"label": "인식되지 않는 URL 매개변수를 HTTP 요청의 필터 표현식으로 처리하는 새로운 설정입니다."}]}]} />

활성화하면 알려진 매개변수, 설정 또는 `param_*` 접두사로 인식되지 않는 모든 URL 매개변수가 필터로 처리되며 AND로 결합됩니다. 다음 두 가지 형식을 사용할 수 있습니다:

* 일반적인 `name=value` 형식은 동등 비교 `` `name` = 'value' ``로 변환됩니다(식별자는 역따옴표로 묶고 값은 문자열 리터럴로 묶습니다).
* 비교 연산자(`!=`, `>`, `<`, `>=`, `<=`, `<>`)가 있으면 비교 표현식으로 처리됩니다. 매개변수에 걸쳐 분리해 작성하거나(`?a!=2`, `?a>=2`), URL에 분리할 `=`가 없을 때 인라인으로 작성할 수 있습니다(`?a<>2`, `?f(x)>3`). 이 경우 다시 조합된 `name[=value]`는 완전한 SQL 표현식으로 구문 분석됩니다.

다른 `http_allow_*` 설정과 달리 기본적으로 비활성화되어 있습니다. 이 설정은 `/?query=...` 엔드포인트를 포함한 HTTP 인터페이스의 모든 요청에 적용되므로, 활성화하면 클라이언트가 덧붙이는 인식되지 않는 URL 매개변수(요청 ID, 서명, 캐시 무효화 값 등)가 모두 쿼리의 필터로 변환됩니다. 이 경우 철자가 잘못된 설정 이름은 더 이상 `UNKNOWN_SETTING`으로 보고되지 않고 `UNKNOWN_IDENTIFIER` 오류로 실패하며(이름이 우연히 컬럼과 일치하면 아무런 알림 없이 결과가 필터링됩니다), 매개변수 값은 쿼리 텍스트에 포함되므로 로그의 `Request URI`와 달리 마스킹되지 않습니다.

## http_allow_table_as_file {#http_allow_table_as_file}

<SettingsInfoBlock type="Bool" default_value="1" />

활성화하면 HTTP 인터페이스는 URL 경로의 마지막 구성 요소를 `table`, `table.format` 또는 `table.format.compression` 형식의 테이블 이름으로 인식합니다. 이 경로는 `SELECT * FROM table`로 해석됩니다.

[`http_allow_database_as_path`](/ko/reference/settings/session-settings/http#http_allow_database_as_path)와 마찬가지로 사용자별 설정입니다. 경로 스타일 요청의 라우팅은 서버 수준의 `http_allow_path_requests` 구성 설정으로 전역적으로 제어됩니다(라우팅은 인증 전에 수행됨).

## http_make_head_request {#http_make_head_request}

<SettingsInfoBlock type="Bool" default_value="1" />

`http_make_head_request` 설정을 사용하면 HTTP에서 데이터를 읽는 동안 `HEAD` 요청을 실행하여 크기와 같은 읽을 파일 정보를 가져올 수 있습니다. 이 설정은 기본적으로 활성화되어 있으므로, server가 `HEAD` 요청을 지원하지 않는 경우에는 이 설정을 비활성화하는 것이 좋습니다.

## http_native_compression_disable_checksumming_on_decompress {#http_native_compression_disable_checksumming_on_decompress}

<SettingsInfoBlock type="Bool" default_value="0" />

* 0 — 비활성화됨.
* 1 — 활성화됨.

## http_x_clickhouse_format_overrides_output_format {#http_x_clickhouse_format_overrides_output_format}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.8"},{"label": "1"},{"label": "`X-ClickHouse-Format` HTTP 헤더를 26.8 이후처럼 `output_format`(쿼리의 `FORMAT` 절을 재정의)의 별칭으로 사용할지, 26.8 이전처럼 `default_format`의 별칭으로 사용할지를 제어합니다. 이 엔트리는 26.8의 변경 사항을 소급하여 문서화한 것으로, 26.8 이전 버전으로 `compatibility`를 설정하면 이전의 헤더 동작이 복원됩니다."}]}, {"id": "row-2","items": [{"label": "26.10"},{"label": "1"},{"label": "26.8에 반영된 `X-ClickHouse-Format` HTTP 헤더 변경을 제어하기 위해 26.10에 새로 추가된 설정입니다. 실질적인 의미론적 변경은 26.8 블록에 등록되어 있으므로 `compatibility = '26.7'`은 이를 되돌리고, `compatibility = '26.8'` 및 `'26.9'`는 해당 릴리스의 동작을 유지합니다. 이 엔트리는 업그레이드 검사에서 새로 도입된 이름을 허용하기 위한 것입니다."}]}]} />

`X-ClickHouse-Format` HTTP 헤더가 어떤 설정에 매핑될지를 제어합니다.

활성화하면(기본값) 헤더는 `output_format` 설정의 별칭이 됩니다. 즉, 응답 포맷을 명시적으로 재정의하며, 쿼리의 `FORMAT` 절과 URL 경로의 파일 확장자보다 우선합니다.

비활성화하면 헤더는 버전 26.8 이전과 마찬가지로 `default_format` 설정의 별칭이 됩니다. 즉, 쿼리에 `FORMAT` 절이 없고 다른 포맷 재정의도 적용되지 않을 때 사용할 포맷만 지정합니다.

어느 경우든 헤더는 같은 이름의 URL 매개변수(각각 `output_format` 또는 `default_format`)보다 우선하며, `INSERT` 요청 본문의 파싱 방식에는 영향을 주지 않습니다.

이 설정은 HTTP 인터페이스용 compatibility 설정입니다. 헤더는 쿼리가 파싱되기 전에 처리되므로, 쿼리 내 `SETTINGS` 절이 아니라 URL 매개변수나 사용자 프로필을 통해 지정해야 합니다. `output_format` 및 `default_format`과 마찬가지로 읽기 전용 모드(`readonly = 1`)에서도 언제든 변경할 수 있으므로, 읽기 전용 사용자도 URL 매개변수로 전달할 수 있습니다.

## http_zlib_compression_level {#http_zlib_compression_level}

<SettingsInfoBlock type="Int64" default_value="3" />

[enable&#95;http&#95;compression = 1](/ko/reference/settings/session-settings/enable#enable_http_compression)일 때 HTTP 요청에 대한 응답의 데이터 압축 수준을 설정합니다.

가능한 값: 1~~12의 숫자입니다. `9`를 초과하는 수준은 `libdeflate`가 포함된 기본 빌드가 필요합니다. `libdeflate`가 없는 빌드는 1~~9 수준만 지원합니다.
