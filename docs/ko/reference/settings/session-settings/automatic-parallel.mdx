## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "이제 자동 병렬 레플리카는 읽기의 절반 이상을 모든 레플리카에서 반복하게 되는 쿼리를 거부합니다. 이전에는 제한이 없었으며, 값을 1로 설정하면 지금도 이전과 같이 동작합니다."}]}]} />

쿼리의 전체 읽기 양 중 레플리카 간에 분할되지 않고 모든 레플리카에서 각각 읽힐 수 있는 부분의 최대 비율을
지정합니다. 이 비율을 초과하면 자동 병렬 레플리카가 해당 쿼리를 거부합니다.

병렬 레플리카가 조정하는 읽기만 분할되며, 동일한 하위 트리의 나머지 읽기는 모두 각
레플리카에서 전체가 실행됩니다. 이러한 읽기는 어느 방식이든 실제 경과 시간이 같으므로 비용 모델 비교에서는 드러나지 않지만,
클러스터 입장에서는 이 읽기에 `max_parallel_replicas`배의 작업을 수행하게 됩니다. 이 설정은 이러한 낭비의 상한을
정합니다. 기본값 0.5에서는 조정된 읽기가 전체 읽기의 절반 미만인 쿼리는 시간 비교 결과와 관계없이
하나의 노드에서 계속 실행됩니다.

1로 설정하면 중복 읽기의 양과 관계없이 모두 허용하며, 시간만 비교하던 이전 동작이 복원됩니다.

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

병렬 레플리카를 자동으로 활성화하기 위한 레플리카당 읽기 바이트 수의 임계값입니다(`automatic_parallel_replicas_mode`=1인 경우에만 적용됨). 0은 임계값이 없음을 의미합니다.
읽을 총 바이트 수는 수집된 통계를 바탕으로 추정됩니다.

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "새로운 설정"}]}]} />

수집된 통계를 기반으로 병렬 레플리카를 사용하는 실행으로 자동 전환할지 설정합니다. `enable_parallel_replicas = 1`, `parallel_replicas_local_plan = 1`이 필요하며, `cluster_for_parallel_replicas`도 지정해야 합니다. `enable_parallel_replicas = 2`이면 병렬 레플리카 사용이 강제되며 자동 모드는 적용되지 않습니다.
0 - 비활성화, 1 - 활성화, 2 - 통계 수집만 활성화(병렬 레플리카를 사용하는 실행으로의 전환은 비활성화).

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "새 설정입니다. 이제 자동 병렬 레플리카는 쿼리 실행 계획(query plan)별로 레플리카가 담당하는 작업 범위의 경계를 기억합니다. 이전에는 이 경계를 찾기 위해 모든 쿼리가 병렬 레플리카를 사용하는 계획을 빌드했습니다."}]}]} />

자동 병렬 레플리카가 쿼리 실행 계획(query plan)별로 레플리카가 담당하는 작업 범위가 끝나는 지점을 기억하도록 합니다. 이를 통해 통계상 병렬 레플리카를 사용하지 않는 것으로 판단되는 반복 쿼리는 병렬
레플리카를 사용하는 계획을 빌드하지 않고도 사용 여부가 결정됩니다.

모든 쿼리가 이 결정에 드는 전체 비용을 부담하게 하려면(예: 해당 비용을 벤치마킹하는 경우) 이 설정을 비활성화하십시오.
