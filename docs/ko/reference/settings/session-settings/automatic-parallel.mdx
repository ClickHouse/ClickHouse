## automatic_parallel_replicas_ignore_thresholds {#automatic_parallel_replicas_ignore_thresholds}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "새로운 설정: 테스트용으로 자동 병렬 복제본(Automatic Parallel Replicas) 비용 모델(Cost Model)의 읽기 스레드 상한을 무시하여, 작은 읽기가 상한에 의해 단락 평가되지 않고 비교를 통해 결정되도록 합니다."}]}]} />

자동 병렬 복제본(Automatic Parallel Replicas) 비용 모델(Cost Model)을 테스트하기 위한 설정으로, 하나의 읽기가 유효하게 사용할 수 있는 스레드 수의 상한(`merge_tree_min_bytes_per_task_for_remote_reading`에서 도출됨)을 무시합니다. 이 상한이 적용되면 `max_threads`를 모두 사용하기에는 너무 작은 읽기의 경우 비교의 양쪽 값이 같은 값으로 제한됩니다. 그 결과 비교식이 `0 > output_bytes / replicas`로 축소되어, 비용 모델(Cost Model)을 참조하기도 전에 쿼리 처리 방식이 결정됩니다.

이 설정은 의도적으로 `automatic_parallel_replicas_min_bytes_per_replica`에는 영향을 주지 않습니다. 해당 게이트를 비활성화하려면 그 설정을 0으로 지정하십시오. 그 설정은 바로 이러한 용도로 존재합니다. 또한 읽기 작업의 용량 산정을 변경하거나, 드리프트가 발생한 통계의 재수집을 막지도 않습니다. 오래된 통계를 기반으로 내린 결정은 비용 모델(Cost Model)이 내린 결정으로 볼 수 없기 때문입니다.

## automatic_parallel_replicas_max_duplicated_read_ratio {#automatic_parallel_replicas_max_duplicated_read_ratio}

<SettingsInfoBlock type="Float" default_value="0.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "0.5"},{"label": "이제 자동 병렬 레플리카는 읽기의 절반 이상을 모든 레플리카에서 반복하게 되는 쿼리를 거부합니다. 이전에는 제한이 없었으며, 값을 1로 설정하면 지금도 이전과 같이 동작합니다."}]}]} />

쿼리의 전체 읽기 양 중 레플리카 간에 분할되지 않고 모든 레플리카에서 각각 읽힐 수 있는 부분의 최대 비율을
지정합니다. 이 비율을 초과하면 자동 병렬 레플리카가 해당 쿼리를 거부합니다.

병렬 레플리카가 조정하는 읽기만 분할되며, 동일한 하위 트리의 나머지 읽기는 모두 각
레플리카에서 전체가 실행됩니다. 이러한 읽기는 어느 방식이든 실제 경과 시간이 같으므로 비용 모델 비교에서는 드러나지 않지만,
클러스터 입장에서는 이 읽기에 `max_parallel_replicas`배의 작업을 수행하게 됩니다. 이 설정은 이러한 낭비의 상한을
정합니다. 기본값 0.5에서는 조정된 읽기가 전체 읽기의 절반 미만인 쿼리는 시간 비교 결과와 관계없이
하나의 노드에서 계속 실행됩니다.

1로 설정하면 중복 읽기의 양과 관계없이 모두 허용하며, 시간만 비교하던 이전 동작이 복원됩니다.

## automatic_parallel_replicas_min_bytes_per_replica {#automatic_parallel_replicas_min_bytes_per_replica}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.1"},{"label": "1048576"},{"label": "테스트 결과를 바탕으로 도출한 더 나은 기본값"}]}, {"id": "row-2","items": [{"label": "25.12"},{"label": "0"},{"label": "새로운 설정"}]}]} />

병렬 레플리카를 자동으로 활성화하기 위한 레플리카당 읽기 바이트 수의 임계값입니다(`automatic_parallel_replicas_mode`=1인 경우에만 적용됨). 0은 임계값이 없음을 의미합니다.
읽을 총 바이트 수는 수집된 통계를 바탕으로 추정됩니다.

## automatic_parallel_replicas_mode {#automatic_parallel_replicas_mode}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "0"},{"label": "새로운 설정"}]}]} />

수집된 통계를 기반으로 병렬 레플리카를 사용하는 실행으로 자동 전환할지 설정합니다. `enable_parallel_replicas = 1`, `parallel_replicas_local_plan = 1`이 필요하며, `cluster_for_parallel_replicas`도 지정해야 합니다. `enable_parallel_replicas = 2`이면 병렬 레플리카 사용이 강제되며 자동 모드는 적용되지 않습니다.
0 - 비활성화, 1 - 활성화, 2 - 통계 수집만 활성화(병렬 레플리카를 사용하는 실행으로의 전환은 비활성화).

## automatic_parallel_replicas_remember_boundary {#automatic_parallel_replicas_remember_boundary}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.10"},{"label": "1"},{"label": "새 설정입니다. 이제 자동 병렬 복제본(Parallel replicas)은 쿼리 실행 계획(query plan)별로 레플리카가 담당하는 작업 범위의 경계를 기억합니다. 이전에는 이 경계를 찾기 위해 모든 쿼리가 병렬 복제본(Parallel replicas)을 사용하는 계획을 빌드했습니다."}]}]} />

자동 병렬 복제본(Parallel replicas)이 쿼리 실행 계획(query plan)별로 레플리카가 담당하는 작업 범위가 끝나는 지점을 기억하도록 합니다. 이를 통해 통계상 병렬 복제본(Parallel replicas)을 사용하지 않는 것으로 판단되는 반복 쿼리는 병렬
복제본(Parallel replicas)을 사용하는 계획을 빌드하지 않고도 사용 여부가 결정됩니다.

비활성화하면 기억된 경계를 사용하지 않습니다. 병렬 복제본(Parallel replicas)을 사용하는 계획의 빌드 비용을 벤치마킹하려면
`automatic_parallel_replicas_undecided_retry_after_executions = 0`도 함께 설정하십시오. 마지막 빌드에서 결정을 내리지 못한 계획은
이 설정과 관계없이 건너뛰기 때문입니다.

## automatic_parallel_replicas_statistics_drift_ratio {#automatic_parallel_replicas_statistics_drift_ratio}

<SettingsInfoBlock type="Float" default_value="1.5" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "1.5"},{"label": "새 설정입니다. 이전에는 비율이 2로 고정되어 변경할 수 없었으며, 이제는 데이터가 변경될 때 통계를 더 빨리 다시 수집합니다."}]}]} />

자동 병렬 복제본(Automatic Parallel Replicas)이 통계를 수집할 당시 읽기에서 선택된 행 수와 현재 읽기에서 선택되는 행 수 사이에 허용되는 차이를 큰 값을 작은 값으로 나눈 비율로 지정합니다. 이 비율을 초과하면 통계를 오래된 것으로 간주하여, 해당 통계를 근거로 결정하지 않고 통계를 다시 수집합니다.

여기서 행은 initiator의 인덱스 분석(Index Analysis)에서 선택된 행을 의미합니다. 따라서 레플리카가 읽는 과정에서만 수행하는 프루닝(예: 각 레플리카의 쿼리 조건 캐시를 통한 프루닝)은 반영되지 않습니다. 비율을 낮게 설정할수록 테이블이 변경될 때 통계를 더 빨리 다시 수집합니다. 값은 1보다 커야 합니다.

## automatic_parallel_replicas_undecided_retry_after_executions {#automatic_parallel_replicas_undecided_retry_after_executions}

<SettingsInfoBlock type="UInt64" default_value="10" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.12"},{"label": "10"},{"label": "새 설정입니다. 이제 자동 병렬 복제본(Parallel replicas)은 마지막 빌드가 결정 없이 끝난 쿼리 실행 계획(query plan)에 대해, 일정 횟수의 실행 동안 병렬 복제본(Parallel replicas)을 사용하는 계획의 빌드를 건너뜁니다. 이전에는 실행할 때마다 이 계획을 빌드했습니다."}]}]} />

자동 병렬 복제본(Parallel replicas)에서 쿼리 실행 계획(query plan)의 마지막 빌드가 결정 없이 끝난 후, 병렬 복제본(Parallel replicas)을 사용하는 계획의 빌드를 건너뛸 실행 횟수입니다. 결정 없이 끝나는 경우는 두 계획을 비교할 수 없을 때, 병렬 복제본(Parallel replicas)을 사용하여 빌드한 계획에서 플래너가 병렬 복제본(Parallel replicas)을 사용하지 않았을 때,
계획의 특정 단계가 통계를 수집할 수 없을 때, 또는 수집했지만 아무것도 측정되지 않았을 때입니다. 동시 실행은 순서를 번갈아 가며, `automatic_parallel_replicas_undecided_retry_after_executions + 1`회 실행 중 한 번 계획을 다시 빌드합니다.
쿼리 실행 계획에서 이러한 결과가 처음 발생한 경우에는, 첫 번째 실행이 다른 통계 캐시(statistics cache)를 채워 계획 결정이 달라질 가능성에 대비하여 다음 실행에서 즉시 계획을 다시 빌드합니다.

0으로 설정하면 결정되지 않은 결과 이후의 지연을 비활성화합니다. 이 설정은 통계를 기반으로 결정된 계획의 빌드를 생략하는 `automatic_parallel_replicas_remember_boundary`와 독립적으로 동작합니다.
