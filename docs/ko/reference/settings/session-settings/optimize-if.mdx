## optimize_if_transform_const_strings_to_lowcardinality {#optimize_if_transform_const_strings_to_lowcardinality}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "`if`\/`multiIf`\/`transform`의 상수 분기 결과를 `LowCardinality`로 최적화할 수 있도록 하는 새로운 설정입니다. 기본적으로 비활성화되어 있습니다."}]}]} />

활성화하면 결과 분기(및 기본값)가 상수 문자열인 `if`, `multiIf`, `transform` 함수가 `String` 대신 `LowCardinality(String)`을 반환합니다.
블록마다 `LowCardinality` 딕셔너리를 구성하면, 후속 단계에서 해당 딕셔너리가 재사용되지 않을 때 일반 `String` 결과보다 느릴 수 있으므로 기본적으로 비활성화되어 있습니다.
전체 표현식이 상수인 경우(조건 또는 입력도 상수인 경우)에는 이 최적화가 적용되지 않습니다. 상수는 `LowCardinality`로 얻는 이점이 없으며, 이렇게 하면 상수 `String` 인수를 요구하는 함수(예: `arrayReduce`, `joinGet`, `tupleElement`)도 계속 정상적으로 동작합니다.

모든 결과 분기가 상수여야 하므로, `if(cond1, 'a', if(cond2, 'b', 'c'))`와 같은 중첩된 `if` 연쇄는 일반 `String`을 그대로 반환합니다. 바깥쪽 `if`의 else 분기가 상수가 아니라 또 다른 `if`이기 때문입니다. `LowCardinality(String)`을 얻으려면 `multiIf(cond1, 'a', cond2, 'b', 'c')` 형태로 작성하십시오.

`optimize_if_transform_strings_to_enum`이 활성화되어 있으면 이 설정은 효과가 없습니다. `Enum` 재작성(Rewrite)이 우선 적용되므로, 위의 명시적인 `multiIf` 형태에서도 결과는 `String`(또는 `Nullable(String)`)으로 유지됩니다.

## optimize_if_transform_strings_to_enum {#optimize_if_transform_strings_to_enum}

<SettingsInfoBlock type="Bool" default_value="0" />

If 및 Transform의 String 유형 인수를 enum으로 대체합니다. 분산 쿼리에서 일관되지 않은 변경이 발생해 실패할 수 있으므로 기본적으로 비활성화되어 있습니다.
