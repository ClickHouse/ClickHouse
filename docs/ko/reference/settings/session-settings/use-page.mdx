## use_page_cache_for_local_disks {#use_page_cache_for_local_disks}

<SettingsInfoBlock type="Bool" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "0"},{"label": "로컬 디스크에 사용자 공간 페이지 캐시를 사용하는 새로운 설정"}]}]} />

로컬 디스크에서 읽을 때 사용자 공간 페이지 캐시를 사용합니다. 테스트용으로 사용되며, 실제 환경에서 성능이 향상될 가능성은 낮습니다. `local_filesystem_read_method = 'pread'` 또는 `'read'`가 필요합니다. 이 설정은 OS 페이지 캐시를 비활성화하지 않으며, 이를 위해서는 `min_bytes_to_use_direct_io`를 사용할 수 있습니다. 일반 테이블에만 영향을 미치며, file() 테이블 함수 또는 File() 테이블 엔진에는 영향을 주지 않습니다.

## use_page_cache_for_object_storage {#use_page_cache_for_object_storage}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.2"},{"label": "0"},{"label": "객체 스토리지 테이블 함수에서 사용자 공간 페이지 캐시를 사용하기 위한 새로운 설정"}]}, {"id": "row-2","items": [{"label": "26.12"},{"label": "1"},{"label": "서버에 페이지 캐시가 구성되어 있으면 객체 스토리지 테이블 엔진과 테이블 함수에서 기본적으로 사용자 공간 페이지 캐시를 사용합니다."}]}]} />

객체 스토리지 테이블 함수(s3, azure, hdfs, Iceberg, Delta Lake 등)와 테이블 엔진(S3, Azure, HDFS, Iceberg, Delta Lake 등)에서 데이터를 읽을 때 사용자 공간 페이지 캐시(사용자 공간 페이지 캐시)를 사용합니다. 이 설정은 서버에 사용자 공간 페이지 캐시가 구성되어 있을 때(`page_cache_max_size`)만 적용되며, 강한 ETag가 있는 객체 또는 테이블 레코드에서 가져온 변경 불가능한 아이덴티티가 있는 객체(Iceberg 및 Delta Lake의 데이터 파일)에만 적용됩니다. 파일 시스템 캐시와는 함께 사용되지 않습니다. Distributed Cache와 함께 사용하려면 `use_page_cache_with_distributed_cache`도 활성화되어 있어야 합니다.

## use_page_cache_lookahead_for_text_index {#use_page_cache_lookahead_for_text_index}

파일 순서대로 읽히지 않는 텍스트 인덱스 파일(딕셔너리(dictionary), 포스팅 목록(postings), 위치(positions))은 기본적으로 사용자 공간 페이지 캐시를 통해 1개 블록 단위의 선행 읽기(lookahead)로 읽히므로, 매번 읽은 후 원격 연결을 재사용할 수 있습니다. 이 설정을 활성화하면 해당 파일들도 다른 파일과 마찬가지로 `page_cache_lookahead_blocks`를 사용합니다.
