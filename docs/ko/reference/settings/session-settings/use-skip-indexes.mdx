## use_skip_indexes_for_disjunctions {#use_skip_indexes_for_disjunctions}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.12"},{"label": "1"},{"label": "새로운 설정"}]}]} />

스킵 인덱스를 사용해 AND와 OR 조건이 혼합된 WHERE 필터를 평가합니다. 예시: WHERE A = 5 AND (B = 5 OR C = 5).
비활성화되어도 스킵 인덱스는 WHERE 조건 평가에 계속 사용되지만, AND로 연결된 절만 포함할 수 있습니다.

가능한 값:

* 0 — 비활성화됨.
* 1 — 활성화됨.

## use_skip_indexes_for_disjunctions_max_rpn_elements {#use_skip_indexes_for_disjunctions_max_rpn_elements}

<SettingsInfoBlock type="UInt64" default_value="128" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "128"},{"label": "새로운 설정입니다. 이전에는 제한이 32로 하드코딩되어 있었습니다"}]}]} />

`use_skip_indexes_for_disjunctions`가 적용되는 WHERE 필터(filter)의 내부 표현(RPN)에 포함될 수 있는 원소의 최대 개수입니다.
대략적으로 각 조건과 각 `AND`, `OR`, `NOT`이 하나의 원소로 계산됩니다. 예를 들어 `A = 5 OR B = 5 OR C = 5`는 원소가 5개입니다.
원소 개수는 인덱스 분석(Index Analysis)을 위해 필터가 재작성된 후에 계산됩니다. 예를 들어 `A = 1 OR A = 2 OR A = 3`은 `A IN (1, 2, 3)`으로 변환되어 하나의 원소가 되며(`optimize_min_equality_disjunction_chain_length` 참조), `coalesce(A, B) = 5`는 여러 조건으로 확장됩니다(`allow_key_condition_coalesce_rewrite` 참조).
원소가 이보다 많은 필터에서는 각 스킵 인덱스가 개별적으로 평가되므로, `OR`로 연결된 서로 다른 컬럼에 대한 조건으로는 그래뉼을 건너뛸 수 없습니다.
인덱스 분석 중 부분 결과는 각 데이터 파트(data part)의 그래뉼마다 원소당 1비트를 차지하며, 이를 결합하는 데에는 그래뉼마다 원소 개수에 비례하는 시간이 소요됩니다. 0(제한 없음)으로 설정할 때는 이 점에 유의하십시오.

가능한 값:

* 0 — 제한 없음.
* 양의 정수 — 원소의 최대 개수.

## use_skip_indexes_for_top_k {#use_skip_indexes_for_top_k}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.5"},{"label": "1"},{"label": "기본적으로 TopK 필터링에 데이터 스키핑 인덱스를 사용하도록 설정합니다"}]}, {"id": "row-2","items": [{"label": "25.12"},{"label": "0"},{"label": "새 설정입니다."}]}]} />

TopK 필터링에 데이터 스키핑 인덱스를 사용하도록 설정합니다.

활성화하면 `ORDER BY <column> LIMIT n` 쿼리의 컬럼에 minmax 스킵 인덱스가 있는 경우, 옵티마이저는 최종 결과와 관련 없는 그래뉼을 건너뛰기 위해 minmax 인덱스를 사용하려고 시도합니다. 이렇게 하면 쿼리 지연 시간을 줄일 수 있습니다.

가능한 값:

* 0 — 비활성화됩니다.
* 1 — 활성화됩니다.

## use_skip_indexes_if_final {#use_skip_indexes_if_final}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.6"},{"label": "1"},{"label": "설정 기본값 변경"}]}]} />

FINAL 수정자를 사용한 쿼리를 실행할 때 스킵 인덱스를 사용할지 제어합니다.

스킵 인덱스는 최신 데이터가 포함된 행(그래뉼)을 제외할 수 있으므로, FINAL 수정자를 사용하는 쿼리에서 잘못된 결과가 나올 수 있습니다. 이 설정을 활성화하면 FINAL 수정자를 사용하더라도 스킵 인덱스가 적용되어 성능이 향상될 수 있습니다. 정확한 결과는 기본적으로 활성화되어 있으며 스킵 인덱스가 반환한 범위와 겹치는 추가 파트를 스캔하는 use&#95;skip&#95;indexes&#95;if&#95;final&#95;exact&#95;mode 설정에 따라 달라집니다. 최근 UPDATE가 누락될 위험은 해당 설정이 비활성화된 경우에만 있습니다.

가능한 값:

* 0 — 비활성화.
* 1 — 활성화.

## use_skip_indexes_if_final_exact_mode {#use_skip_indexes_if_final_exact_mode}

<SettingsInfoBlock type="Bool" default_value="1" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "25.6"},{"label": "1"},{"label": "설정 기본값 변경"}]}, {"id": "row-2","items": [{"label": "25.5"},{"label": "0"},{"label": "이 설정은 FINAL 쿼리가 스킵 인덱스와 함께 올바른 결과를 반환하도록 돕기 위해 도입되었습니다"}]}]} />

이 설정은 FINAL 수정자를 사용한 쿼리 실행 시 올바른 결과를 반환할 수 있도록, 스키핑 인덱스가 반환한 그래뉼을 더 새로운 파트에서 확장할지 여부를 제어합니다.

스킵 인덱스를 사용하면 최신 데이터를 포함한 행이 있는 그래뉼이 제외될 수 있으며, 이로 인해 잘못된 결과가 나올 수 있습니다. 이 설정을 사용하면 스킵 인덱스가 반환한 범위와 겹치는 더 새로운 파트를 스캔하여 올바른 결과를 보장할 수 있습니다. 이 설정은 스킵 인덱스 조회 기반의 근사 결과로도 애플리케이션에 문제가 없는 경우에만 비활성화해야 합니다.

가능한 값:

* 0 — 비활성화됨.
* 1 — 활성화됨.

* 0 — 비활성화됨.
* 1 — 활성화됨.
