## max_bytes_to_buffer_for_packed_part {#max_bytes_to_buffer_for_packed_part}

<SettingsInfoBlock type="UInt64" default_value="0" />

<VersionHistory rows={[{"id": "row-1","items": [{"label": "26.11"},{"label": "0"},{"label": "새 설정입니다. 기록 중인 패킹 파트의 버퍼에 저장된 데이터를 임시 데이터로 이동하여 해당 데이터가 차지하는 메모리를 제한합니다. 0이면 이전과 같이 모든 데이터를 메모리에 유지합니다."}]}]} />

삽입, 머지 또는 뮤테이션으로 패킹 데이터 파트(part)를 기록하는 동안 버퍼에 저장된 데이터가 차지할 수 있는 메모리의 최댓값입니다.
패킹 파트는 파트가 완료될 때까지 모든 파일의 데이터를 메모리에 유지합니다.
버퍼에 저장된 데이터가 이 제한을 초과하면 가장 큰 파일들의 데이터가
서버 임시 저장소(`tmp_path`, `tmp_policy` 또는
`temporary_data_in_cache`)의 임시 파일로 이동되고, 완료 시점에 다시 읽어 들입니다. 임시 파일 사용량은
`max_temporary_data_on_disk_size_for_query` 및 `max_temporary_data_on_disk_size_for_user`에 반영됩니다.
아직 기록 중인 각 파일의 마지막 블록(최대 64 KiB)은 이동할 수 없으므로, 컬럼이 많은 wide 파트처럼
여러 파일을 동시에 기록하는 파트는 메모리를 더 많이 사용할 수 있습니다.
파트의 데이터는 하나의 임시 파일로 이동되며, 이 파일의 쓰기 버퍼(기본
`temporary_files_buffer_size` 기준 약 2 MiB)는 파트가 완료될 때까지 메모리에 남아 있습니다.
이 제한은 파트와 해당 파트의 각 프로젝션에 개별적으로 적용됩니다. 0은 무제한을 의미합니다.

## max_bytes_to_merge_at_max_space_in_pool {#max_bytes_to_merge_at_max_space_in_pool}

<SettingsInfoBlock type="UInt64" default_value="161061273600" />

사용 가능한 리소스가 충분할 때 여러 파트를 하나의 파트로 머지할 수 있는 최대 총 파트 크기(바이트)입니다. 자동 백그라운드 머지로 생성될 수 있는 최대 파트 크기에 대략 해당합니다. (0은 머지가 비활성화됨을 의미합니다)

Possible values:

* 0 이상의 모든 정수.

머지 스케줄러는 주기적으로 파티션 내 파트의 크기와 개수를 분석하고, 풀에 충분한 여유 리소스가 있으면 백그라운드 머지를 시작합니다. 머지는 소스 파트들의 총 크기가 `max_bytes_to_merge_at_max_space_in_pool`보다 커질 때까지 수행됩니다.

[OPTIMIZE FINAL](/ko/reference/statements/optimize)로 시작된 머지는 `max_bytes_to_merge_at_max_space_in_pool`를 무시합니다(여유 디스크 공간만 고려됩니다).

## max_bytes_to_merge_at_min_space_in_pool {#max_bytes_to_merge_at_min_space_in_pool}

<SettingsInfoBlock type="UInt64" default_value="1048576" />

background 풀에서 사용 가능한 리소스가 최소일 때,
하나의 파트로 머지할 수 있는 최대 총 파트 크기(바이트)입니다.

가능한 값:

* 양의 정수 아무 값이나 가능합니다.

`max_bytes_to_merge_at_min_space_in_pool`는 디스크 공간이 부족한 경우에도
머지할 수 있는 파트의 최대 총 크기(풀 내)를 정의합니다.
이는 작은 파트 수를 줄이고 `Too many parts` 오류가 발생할 가능성을 낮추기 위해 필요합니다.
머지 작업은 머지되는 전체 파트 크기의 2배에 해당하는 디스크 공간을 예약합니다.
따라서 디스크의 여유 공간이 적으면,
여유 공간이 있더라도 그 공간이 이미 진행 중인 큰 머지 작업에 예약되어 있어
다른 머지 작업을 시작할 수 없고, 삽입할 때마다 작은 파트 수가 늘어나는
상황이 발생할 수 있습니다.
