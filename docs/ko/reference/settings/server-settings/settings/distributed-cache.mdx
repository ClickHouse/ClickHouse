이 설정은 ClickHouse 서버를 구성하기 위한 항목이며, ClickHouse 소스에서 자동으로 생성됩니다.

## distributed_cache_apply_throttling_settings_from_client {#distributed_cache_apply_throttling_settings_from_client}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />캐시 서버가 클라이언트로부터 전달받은 스로틀링 설정을 적용할지 여부입니다.

## distributed_cache_keep_up_free_connections_ratio {#distributed_cache_keep_up_free_connections_ratio}

<SettingsInfoBlock type="Float" default_value="0.1" changeable_without_restart="No" />Distributed Cache가 유휴 상태로 유지하려는 활성 연결 수의 소프트 리밋입니다. 사용 가능한 연결 수가 distributed&#95;cache&#95;keep&#95;up&#95;free&#95;connections&#95;ratio * max&#95;connections 아래로 내려가면, 연결 수가 다시 이 리밋을 넘을 때까지 가장 오래 활동이 없었던 연결부터 닫힙니다.

## distributed_cache_max_request_processing_time_ms {#distributed_cache_max_request_processing_time_ms}

<SettingsInfoBlock type="UInt64" default_value="60000" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server)는 요청의 마지막 `StartRequest` 또는 `ContinueRequest` 이후 처리 시간이 이 값(밀리초)에 도달한 요청을 종료합니다. 클라이언트를 기다리는 데 소요된 시간은 포함되지 않으며, 새로운 읽기 범위가 시작되면 처리 시간 한도가 다시 적용됩니다. 요청은 서버가 이를 보고할 수 있는 시점에 즉시 종료되며, 그 시점에 도달하지 못한 요청은 `distributed_cache_stuck_request_scan_interval_ms`만큼 시간이 지난 후 연결이 종료됩니다. 값이 0이면 제한이 없습니다.

## distributed_cache_slow_down_min_stuck_requests {#distributed_cache_slow_down_min_stuck_requests}

<SettingsInfoBlock type="UInt64" default_value="10" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server)는 클라이언트의 요청 중 멈춘 요청이 이 개수 이상일 때에만 해당 클라이언트에 속도를 늦추도록 요청합니다. 따라서 처리 중인 요청이 몇 개뿐인 클라이언트는 요청 하나가 멈췄다는 이유만으로 속도 저하 요청을 받지 않습니다. 값이 0 또는 1이면 판단을 `distributed_cache_slow_down_stuck_requests_ratio`에만 맡깁니다.

## distributed_cache_slow_down_stuck_requests_ratio {#distributed_cache_slow_down_stuck_requests_ratio}

<SettingsInfoBlock type="Double" default_value="0.2" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server)는 처리 중인 요청 가운데 멈춘 요청의 비율이 이 값 이상이 되면 클라이언트에 속도를 늦추도록 요청합니다. 유휴 상태의 연결은 계산에 포함되지 않습니다. 값을 0으로 설정하면 속도 저하를 요청하지 않습니다.

## distributed_cache_slow_down_window_ms {#distributed_cache_slow_down_window_ms}

<SettingsInfoBlock type="UInt64" default_value="10000" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server)에서 처리가 멈춘 요청이 너무 많아졌을 때, 해당 서버가 클라이언트에게 접근을 자제하도록 요청하는 시간(밀리초)입니다. 스캔(Scan)으로 윈도우가 갱신되지 않을 때에만 윈도우가 만료되도록 `distributed_cache_stuck_request_scan_interval_ms`의 2배 이상이어야 합니다. 값 0은 허용되지 않습니다.

## distributed_cache_stuck_request_no_progress_timeout_ms {#distributed_cache_stuck_request_no_progress_timeout_ms}

<SettingsInfoBlock type="UInt64" default_value="10000" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server)는 요청이 이 설정값(밀리초) 동안 데이터를 전혀 주고받지 않으면 해당 요청의 연결을 닫습니다. 이때 클라이언트를 기다리는 데 소요된 시간은 포함하지 않습니다. 값을 0으로 설정하면 이 제한이 비활성화됩니다. 단, 멈춘 요청에 대한 스캔(Scan)은 `distributed_cache_max_request_processing_time_ms`도 0인 경우에만 중지됩니다.

## distributed_cache_stuck_request_scan_interval_ms {#distributed_cache_stuck_request_scan_interval_ms}

<SettingsInfoBlock type="NonZeroUInt64" default_value="5000" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server)가 멈춘 요청을 스캔(Scan)하는 인터벌(밀리초)입니다.

## distributed_cache_temporary_data_background_retry_delay_milliseconds {#distributed_cache_temporary_data_background_retry_delay_milliseconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="30000" changeable_without_restart="No" />커밋된 임시 데이터에 대한 백그라운드 재시도를 수행하기 전의 지연 시간(밀리초)입니다.

## distributed_cache_temporary_data_cleanup_period_milliseconds {#distributed_cache_temporary_data_cleanup_period_milliseconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="1000" changeable_without_restart="No" />커밋된 임시 데이터 중 만료된 데이터를 정리하는 작업의 실행 주기(밀리초)입니다.

## distributed_cache_temporary_data_confirmation_retry_delay_milliseconds {#distributed_cache_temporary_data_confirmation_retry_delay_milliseconds}

<SettingsInfoBlock type="UInt64" default_value="500" changeable_without_restart="No" />커밋된 임시 데이터의 발행(publication) 확인을 재시도하기 전까지의 대기 시간(밀리초)입니다.

## distributed_cache_temporary_data_control_hello_timeout_milliseconds {#distributed_cache_temporary_data_control_hello_timeout_milliseconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="2000" changeable_without_restart="No" />커밋된 임시 데이터 제어는 파일의 수명을 최대 「제어 연결의 hello 시점 + 이 타임아웃 + TTL」까지 연장합니다. 단위는 밀리초입니다. 클라이언트는 hello 이후 같은 시간 동안 응답을 기다립니다. 클라이언트는 커밋된 파일이 생성될 때(백그라운드 갱신은 시작 시) 읽어 들인 자체 값을 사용합니다. 클라이언트와 분산 캐시 서버(Distributed Cache server)의 값이 서로 다르더라도 파일의 수명이 hello + TTL보다 짧아지지는 않습니다.

## distributed_cache_temporary_data_max_bytes_per_server {#distributed_cache_temporary_data_max_bytes_per_server}

<SettingsInfoBlock type="UInt64" default_value="1099511627776" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server) 하나가 보관하는 커밋된 임시 파일의 최대 총 크기(바이트)입니다. 커밋된 임시 파일은 파일 캐시(File Cache)에 고정되어 해제되거나 만료될 때까지 축출되지 않으므로, 이 제한을 통해 해당 파일이 캐시에서 차지할 수 있는 용량의 상한을 정합니다. 기본값은 1 TiB입니다. 제한에 도달하면 서버는 새로운 커밋된 임시 파일의 발행(publication)을 거부합니다. `0`은 무제한을 의미합니다.

## distributed_cache_temporary_data_max_connections_bypassing_pool {#distributed_cache_temporary_data_max_connections_bypassing_pool}

<SettingsInfoBlock type="UInt64" default_value="5000" changeable_without_restart="Yes" />ClickHouse Cloud에서만 적용됩니다. 임시 파일이 연결 풀을 거치지 않고 분산 캐시 서버(Distributed Cache server)당 열 수 있는 최대 연결 수입니다. 이 제한에 도달하면 임시 데이터는 `distributed_cache_wait_connection_from_pool_milliseconds` 동안 풀링된 연결(Pooled Connection)을 기다린 후 실패합니다. `0`은 무제한을 의미합니다. 커밋된 임시 데이터에 대한 짧은 제어 교환(확인, 갱신, 해제)은 항상 새 연결을 열며 이 수에 포함되지 않습니다. 재시작 없이 변경할 수 있습니다.

## distributed_cache_temporary_data_max_control_batch_ids {#distributed_cache_temporary_data_max_control_batch_ids}

<SettingsInfoBlock type="NonZeroUInt64" default_value="1024" changeable_without_restart="No" />클라이언트가 한 번의 제어 요청으로 전송하는 커밋된 임시 데이터 ID의 최대 개수입니다. 65536보다 큰 값은 65536(프로토콜 상한)으로 제한됩니다.

## distributed_cache_temporary_data_max_files_per_server {#distributed_cache_temporary_data_max_files_per_server}

<SettingsInfoBlock type="UInt64" default_value="100000" changeable_without_restart="No" />분산 캐시 서버(Distributed Cache server) 하나가 보관하는 커밋된 임시 파일의 최대 개수입니다. 이 제한은 파일 추적에 사용되는 메모리를 제한하기 위한 최후의 안전장치일 뿐이므로 기본값이 높게 설정되어 있으며, 실제 용량은 주로 `distributed_cache_temporary_data_max_bytes_per_server`로 제한됩니다. 이 제한에 도달하면 서버는 커밋된 임시 파일의 새로운 발행(publication)을 거부합니다. `0`은 무제한을 의미합니다.

## distributed_cache_temporary_data_pool_behaviour_on_limit {#distributed_cache_temporary_data_pool_behaviour_on_limit}

<SettingsInfoBlock type="DistributedCachePoolBehaviourOnLimit" default_value="allocate_bypassing_pool" changeable_without_restart="Yes" />ClickHouse Cloud에서만 적용됩니다. 연결 풀 제한에 도달했을 때 임시 데이터용 Distributed Cache 연결의 동작을 지정합니다. 임시 데이터는 폴백할 객체 스토리지가 없으므로, 기본적으로 실패하지 않고 풀을 우회하는 연결을 엽니다. 이 설정은 쿼리 및 백그라운드 작업(머지, 백업)의 임시 파일에 적용됩니다. 커밋된 임시 데이터에 대한 짧은 제어 교환(확인, 갱신, 해제)은 항상 새 연결을 열며 이 설정의 영향을 받지 않습니다. `wait`로 설정하면 `distributed_cache_wait_connection_from_pool_milliseconds` 동안 풀링된 연결(Pooled Connection)을 기다린 후 실패합니다. 재시작 없이 변경할 수 있습니다.

## distributed_cache_temporary_data_renewal_period_seconds {#distributed_cache_temporary_data_renewal_period_seconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="900" changeable_without_restart="No" />커밋된 임시 데이터의 소유권을 갱신하는 주기(초 단위)입니다.

## distributed_cache_temporary_data_ttl_seconds {#distributed_cache_temporary_data_ttl_seconds}

<SettingsInfoBlock type="NonZeroUInt64" default_value="3600" changeable_without_restart="No" />커밋된 임시 파일의 수명(초 단위)입니다.

## distributed_cache_warmer_max_bytes_in_queue {#distributed_cache_warmer_max_bytes_in_queue}

<SettingsInfoBlock type="UInt64" default_value="107374182400" changeable_without_restart="No" />ClickHouse Cloud에서만 적용됩니다. 로컬 파일 시스템 캐시가 없는 디스크에서 캐시 워머(cache warmer)가 큐에 보관하는 범위의 최대 총 크기입니다. 이 크기를 초과하면 가장 오래된 범위부터 삭제됩니다(로컬 캐시가 있으면 워머는 해당 캐시의 `max_size`를 사용합니다). 0이면 제한이 없습니다.

## distributed_cache_warmer_max_file_segment_size {#distributed_cache_warmer_max_file_segment_size}

<SettingsInfoBlock type="NonZeroUInt64" default_value="33554432" changeable_without_restart="No" />ClickHouse Cloud에서만 적용됩니다. 파트가 위치한 디스크에 로컬 파일 시스템 캐시가 없을 때 캐시 워머(cache warmer)가 가져온 파트를 Distributed Cache로 읽어 들이는 범위의 크기입니다(로컬 캐시가 있으면 워머는 해당 캐시의 `max_file_segment_size`를 사용합니다).

## distributed_cache_warmer_max_segments_in_queue {#distributed_cache_warmer_max_segments_in_queue}

<SettingsInfoBlock type="UInt64" default_value="100000" changeable_without_restart="No" />ClickHouse Cloud에서만 적용됩니다. 로컬 파일 시스템 캐시가 없는 디스크에서 캐시 워머가 큐에 보관할 수 있는 범위의 최대 개수입니다. 이 값을 초과하면 가장 오래된 범위부터 삭제됩니다(로컬 캐시가 있으면 워머는 해당 캐시의 `max_elements`를 사용합니다). 0으로 설정하면 무제한입니다.

## distributed_cache_warmer_skip_parts_produced_in_current_availability_zone {#distributed_cache_warmer_skip_parts_produced_in_current_availability_zone}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />ClickHouse Cloud에서만 적용됩니다. 캐시 워머가 Distributed Cache만 워밍하는 경우(파트의 디스크에 로컬 파일 시스템 캐시가 없거나 읽기 시 캐시가 비활성화된 경우), 현재 가용 영역의 레플리카가 생성한 파트는 건너뜁니다. 이러한 파트는 Distributed Cache를 통해 기록되었으므로 이미 이 영역의 캐시에 있습니다. 시작점을 알 수 없는 파트는 항상 워밍됩니다.

## distributed_cache_write_pool_size {#distributed_cache_write_pool_size}

<SettingsInfoBlock type="UInt64" default_value="100" changeable_without_restart="No" />동시에 백그라운드 스레드에서 실행할 수 있는 Distributed Cache 쓰기 요청의 최대 수입니다(모든 쿼리 전체 기준). 한도에 도달하면 write-through 캐시 쓰기는 건너뛰므로(데이터는 여전히 객체 스토리지에 기록됩니다), 슬롯을 기다리며 차단되지 않고 스레드 수가 무제한으로 늘어나지도 않습니다. 임시 데이터의 쓰기는 백그라운드 스레드를 사용하지 않으며 이 한도의 영향을 받지 않습니다.
