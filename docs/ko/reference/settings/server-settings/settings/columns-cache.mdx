이 설정은 ClickHouse 서버 구성에 사용되며, ClickHouse 소스 코드에서 자동으로 생성됩니다.

## columns_cache_free_memory_ratio {#columns_cache_free_memory_ratio}

<SettingsInfoBlock type="Double" default_value="0.15" changeable_without_restart="No" />

컬럼 캐시(columns cache)가 쿼리(query)를 위해 비워 두는 메모리의 비율입니다. 서버 메모리 제한(`max_server_memory_usage`)을 기준으로 합니다.

캐시 메모리와 쿼리 메모리는 동일한 제한을 공유하므로, 서버의 다른 구성 요소가 사용하는 메모리가
`max_server_memory_usage * (1 - columns_cache_free_memory_ratio) - columns_cache_size`를 초과하면 실제로 적용되는 캐시 크기가 줄어들고,
해당 사용량이 감소하면 다시 `columns_cache_size`에 가까워지도록 늘어납니다. 메모리 할당으로 제한을 초과하게 될 때도 쿼리를 중단하기 전에
캐시에서 항목을 제거합니다. `page_cache_free_memory_ratio`와 유사하게 동작합니다.

실제로 적용되는 제한은 `CurrentMetrics.ColumnsCacheSizeLimit`에 보고되며, `system.server_settings`는 계속
설정된 `columns_cache_size`를 보고합니다.

## columns_cache_history_window_ms {#columns_cache_history_window_ms}

<SettingsInfoBlock type="UInt64" default_value="1000" changeable_without_restart="No" />

컬럼 캐시는 사용 가능한 메모리 양을 결정할 때, 지정된 밀리초 동안(및 그 직전의 동일한 길이의 윈도우 동안) 서버의 나머지 구성 요소가 사용한 최대 메모리 사용량(peak memory usage)을 기준으로 삼습니다. 이를 통해 메모리 사용량이 일시적으로 줄어들었을 때 캐시가 커졌다가 잠시 후 다시 축출되는 상황을
방지합니다. `page_cache_history_window_ms`와 유사합니다.

## columns_cache_policy {#columns_cache_policy}

<SettingsInfoBlock type="String" default_value="SLRU" changeable_without_restart="No" />컬럼 캐시 정책 이름입니다.

## columns_cache_size {#columns_cache_size}

<SettingsInfoBlock type="UInt64" default_value="2147483648" changeable_without_restart="Yes" />

MergeTree 테이블(table)에서 역직렬화한 컬럼(column)을 저장하는 컬럼 캐시(cache)의 최대 크기(바이트)입니다.

컬럼 캐시는 자주 액세스하는 컬럼의 압축 해제와 역직렬화를 반복할 필요가 없도록 합니다.
쿼리 수준 옵션 `use_columns_cache`가 활성화되어 있으면 캐시가 사용됩니다.

서버 구성에 이 설정이 없으면 캐시 크기는 서버에서 사용할 수 있는 메모리에 `columns_cache_size_to_ram_ratio`
비율(기본값 10%)을 적용한 크기로 설정됩니다. 따라서 메모리가 많은 서버에는 부하가 큰 쿼리의 작업 집합을 담을 수 있을 만큼
큰 캐시가 할당됩니다. 이 설정의 내장 값은 메모리 용량을
확인할 수 없을 때만 사용됩니다. 다른 캐시와 마찬가지로 크기는 `cache_size_to_ram_max_ratio`로 제한됩니다.

이 한도는 캐시가 보유하는 메모리에 적용됩니다. 각 엔트리의 메모리 사용량은 해당 컬럼에 할당된 크기에
엔트리별 소량의 오버헤드를 더해 계산됩니다. 컬럼에 할당된 크기는 그 안에 있는 행(row)의 논리적 크기를 초과할 수 있습니다. `system.columns_cache`는
엔트리별로 동일한 사용량을 보고하고, `CurrentMetrics.ColumnsCacheBytes`는 그 합계를 보고합니다.

`system.server_settings`는 이 설정에 구성된 값을 보고합니다. 서버의
다른 구성 요소에서 메모리가 부족하면 실제 적용되는 한도는 더 낮아질 수 있습니다. `columns_cache_free_memory_ratio`를 참조하십시오. 실제 한도 값은 별도로
`CurrentMetrics.ColumnsCacheSizeLimit`에 표시됩니다.

<Note>
  값이 `0`이면 캐시가 비활성화됩니다.

  이 설정은 런타임에 변경할 수 있으며 변경 사항은 즉시 적용됩니다.
</Note>

## columns_cache_size_ratio {#columns_cache_size_ratio}

<SettingsInfoBlock type="Double" default_value="0.5" changeable_without_restart="No" />SLRU 정책을 사용할 때 컬럼(column) 캐시(cache)의 전체 크기에서 보호 큐가 차지하는 비율입니다.

## columns_cache_size_to_ram_ratio {#columns_cache_size_to_ram_ratio}

<SettingsInfoBlock type="Double" default_value="0.1" changeable_without_restart="No" />

서버가 사용할 수 있는 메모리 대비 컬럼 캐시 크기의 비율입니다. 이 설정은 서버 구성에 `columns_cache_size`가
지정되지 않은 경우에 사용됩니다. 이때 캐시 크기는 RAM에 이 비율을 곱한 값으로 정해지며(`cache_size_to_ram_max_ratio` 상한 적용),
그 결과 대규모 서버는 무거운 쿼리의 작업 집합을 담을 수 있을 만큼 큰 캐시를 확보하고,
소규모 서버는 메모리의 작은 일부만 캐시에 내어 주게 됩니다. 메모리는 필요할 때만 할당되며,
그것도 `use_columns_cache`를 활성화한 상태로 쿼리를 실행할 때에만 할당됩니다.

값을 `0`으로 지정하면 `columns_cache_size`를 명시적으로 설정하지 않는 한 캐시가 비활성화됩니다.
