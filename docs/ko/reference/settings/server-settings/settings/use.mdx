이 설정은 ClickHouse 서버를 구성하는 항목이며 ClickHouse 소스에서 자동 생성됩니다.

## use_minimalistic_part_header_in_zookeeper {#use_minimalistic_part_header_in_zookeeper}

더 이상 사용되지 않는 설정으로, 아무런 효과가 없습니다. [복제된](/ko/reference/engines/table-engines/mergetree-family/replication) 테이블은 항상 데이터 파트의 헤더를 단일 `znode`에 간결한 형태로 저장합니다. 이전 버전에서 별도의 `columns` 및 `checksums` 하위 `znodes`로 기록한 파트 헤더도 계속 읽을 수 있습니다.

## use_separate_cache_arena {#use_separate_cache_arena}

<SettingsInfoBlock type="Bool" default_value="1" changeable_without_restart="No" />

캐시 할당에 사용할 전용 jemalloc arena를 활성화합니다(마크 캐시, 압축 해제 캐시, 페이지 캐시).
캐시 데이터를 쿼리 처리 중의 메모리 할당과 분리하여 메모리 단편화를 줄입니다.

## use_shared_merge_tree_log_pipeline {#use_shared_merge_tree_log_pipeline}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="No" />

ClickHouse Cloud에서만 사용할 수 있습니다. 활성화하면 시스템 로그가 `SharedMergeTree` 파이프라인을 통해 기록되고
`system` 데이터베이스가 공유 데이터베이스(Shared database)로 전환되므로, 모든 레플리카에서 동일한 로그 테이블(Log Tables)을 볼 수 있습니다.

로그를 플러시할 때마다 `s3`(또는 `azureBlobStorage`) 테이블 함수를 사용하여 `Native` 파일이 해당 로그의 생성(generation) 폴더에 기록됩니다.
생성은 로그의 컬럼과 키에 대한 해시로 결정됩니다. 파이프라인은 생성마다 해당 폴더를 읽는 큐 `system._<log>_s3queue_<hash>`,
materialized view `system._<log>_mv_<hash>`, 그리고 `SharedMergeTree` 테이블 `system.<log>_<hash>`를 유지합니다.
`system.<log>`는 여러 생성을 아우르는 `Merge` 테이블입니다. 스키마(schema)가 바뀌면 새 생성이 만들어집니다. 설정, TTL, 인덱스(indices)는
로그 구성의 `smt_settings`, `smt_ttl`, `smt_indices` 키에서 가져오며, 변경 시 기존 객체에 바로 반영됩니다.
객체는 로그를 처음 플러시할 때 생성되며, `prepare_system_log_tables_on_startup`을 사용하면 시작 시 생성됩니다.
테이블의 정렬 키는 로그의 키 앞에 `hostname`을 추가한 것이므로, 각 레플리카의 행을 이 키를 기준으로 읽을 수 있습니다.
로그 구성의 `smt_order_by` 및 `smt_partition_by` 키는 테이블의 키를 대체합니다.

이 설정이 활성화되어 있는 동안 로컬 `system` 데이터베이스의 이름은 `system_local`로 변경됩니다. 서버 구성에 `shared_database_catalog`
및 `<shared_log_pipeline><endpoint>`가 있어야 합니다.
관련 항목: `shared_log_pipeline.enable_sync_flush`, `shared_log_pipeline.flush_timeout_seconds`.
