이 설정들은 ClickHouse 서버를 구성하며, ClickHouse 소스 코드에서 자동으로 생성됩니다.

## workloads_respect_server_cpu_limit {#workloads_respect_server_cpu_limit}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Yes" />

활성화하면 서버 전체의 CPU 동시성 제한이 워크로드 스케줄러를 통해 적용됩니다. 두 역할 중 어느 쪽에도 리소스가 정의되어 있지 않으면 CPU 리소스 `__server_cpu__`(`MASTER THREAD` 및 `WORKER THREAD`용)가 암묵적으로 생성되며, 루트 워크로드(이름이 비어 있는 워크로드)의 `max_concurrent_threads`는 `concurrent_threads_soft_limit_num` 및 `concurrent_threads_soft_limit_ratio_to_cores` 값을 기준으로 정해집니다. 따라서 모든 워크로드가 이 설정들에서 산출된 하나의 CPU 슬롯 예산을 공유합니다. 이후 CPU 스케줄링은 내장 동시성 제어 대신 워크로드 스케줄러가 담당합니다.

이 설정을 사용할 때는 `implicit_default_workload`도 함께 활성화하십시오(또는 `default` 워크로드를 정의하십시오). 이 예산의 제한을 받는 것은 워크로드로 분류된 쿼리뿐입니다. `default` 워크로드가 없으면 기본 `workload` 설정 값을 사용하는 쿼리와 기본 워크로드를 사용하는 백그라운드 병합 및 뮤테이션(background merges and mutations)은 CPU 제한을 전혀 받지 않으며, 내장 동시성 제어(`concurrent_threads_soft_limit_num`)도 더 이상 적용되지 않습니다. `throw_on_unknown_workload = 1`인 경우에는 이러한 쿼리가 실패합니다.

런타임에 변경할 수 있습니다. 기본적으로 비활성화되어 있습니다.

**예시**

```xml
<workloads_respect_server_cpu_limit>true</workloads_respect_server_cpu_limit>
```

## workloads_respect_server_memory_limit {#workloads_respect_server_memory_limit}

<SettingsInfoBlock type="Bool" default_value="0" changeable_without_restart="Yes" />

활성화하면 서버 전체 메모리 제한이 워크로드 스케줄러를 통해 메모리 예약(memory reservation) 예산으로 적용됩니다. 정의된 리소스가 없으면 `MEMORY RESERVATION` 리소스 `__server_memory__`가 암묵적으로 생성되며, 루트 워크로드(이름이 비어 있는 워크로드)의 `max_memory`는 `max_server_memory_usage`(및 해당 RAM 비율)에서 산출됩니다. 따라서 모든 워크로드는 이 설정에서 가져온 하나의 메모리 예약 예산을 공유합니다. 이 예산은 예약 어드미션용 예산이며, 프로세스 전체 메모리 제한을 대체하지 않고 해당 제한도 계속 적용됩니다. 예산은 구성이 로드되거나 다시 로드될 때 구성된 `max_server_memory_usage` 값을 기준으로 정해집니다. `memory_worker_dynamic_hard_limit`가 런타임에 프로세스 전체 제한을 조정하더라도 이는 반영되지 않으므로, 다시 로드하기 전까지는 예산이 실제 적용 중인 제한보다 클 수 있습니다.

이 설정과 함께 `implicit_default_workload`를 활성화하십시오(또는 `default` 워크로드를 정의하십시오). 워크로드로 분류된 쿼리만 이 예산에서 메모리를 예약합니다. `default` 워크로드가 없으면 기본 `workload` 설정 값을 사용하는 쿼리는 이 예산에서 예약하지 않으며, `throw_on_unknown_workload = 1`이면 해당 쿼리는 실패합니다. 백그라운드 병합 및 뮤테이션(background merges and mutations)은 워크로드에서 메모리를 예약하지 않으므로, 이들이 사용하는 메모리는 어떤 경우에도 이 예산에 포함되지 않습니다.

런타임에 변경할 수 있습니다. 기본적으로 비활성화되어 있습니다.

**예시**

```xml
<workloads_respect_server_memory_limit>true</workloads_respect_server_memory_limit>
```
