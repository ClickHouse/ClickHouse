여러 SQL 문을 병렬로 실행할 수 있도록 합니다.

## 구문 {#syntax}

```sql
statement1 PARALLEL WITH statement2 [PARALLEL WITH statement3 ...]
```

SQL 문 `statement1`, `statement2`, `statement3`, ...을 서로 병렬로 실행합니다. 결과 집합을 반환하지 않고 입력 데이터도 받지 않는 SQL 문만 함께 결합할 수 있습니다. 자세한 내용은 [제한 사항](#restrictions)을 참조하십시오.

많은 경우 SQL 문을 병렬로 실행하면 동일한 SQL 문을 단순히 순차적으로 실행하는 것보다 더 빠를 수 있습니다. 예를 들어, `statement1 PARALLEL WITH statement2 PARALLEL WITH statement3`는 `statement1; statement2; statement3`보다 더 빠를 가능성이 큽니다.

## 예시 {#examples}

두 개의 테이블을 병렬로 생성합니다:

```sql
CREATE TABLE table1(x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2(y String) ENGINE = MergeTree ORDER BY tuple();
```

두 테이블을 병렬로 삭제합니다:

```sql
DROP TABLE table1
PARALLEL WITH
DROP TABLE table2;
```

## 제한 사항 {#restrictions}

`SELECT`처럼 결과 집합을 반환하거나 입력 데이터를 받는 SQL 문은 `INCORRECT_QUERY` 오류와 함께 거부됩니다.

[`ON CLUSTER`](/ko/reference/statements/distributed-ddl)로 실행되거나 [`Replicated`](/ko/reference/engines/database-engines/replicated) 데이터베이스의 DDL 로그를 통해 실행되는 DDL은 상태 테이블을 반환하므로 마찬가지로 거부됩니다. 다만 이 거부는 DDL이 호스트로 전송된 후에 이루어지므로, 호스트에서는 해당 DDL이 그대로 실행됩니다. [`distributed_ddl_output_mode`](/ko/reference/settings/session-settings/distributed-ddl#distributed_ddl_output_mode)가 `none` 또는 `none_only_active`이면 결합할 수 있습니다:

```sql
SET distributed_ddl_output_mode = 'none';

CREATE TABLE table1 ON CLUSTER default (x Int32) ENGINE = MergeTree ORDER BY tuple()
PARALLEL WITH
CREATE TABLE table2 ON CLUSTER default (y String) ENGINE = MergeTree ORDER BY tuple();
```

## 설정 {#settings}

[max&#95;threads](/ko/reference/settings/session-settings/max-threads#max_threads) 설정은 생성할 스레드 수를 제어합니다.

## UNION과의 비교 {#comparison-with-union}

`PARALLEL WITH` 절은 피연산자를 병렬로 실행한다는 점에서 [UNION](/ko/reference/statements/select/union)과 다소 유사합니다. 하지만 몇 가지 차이점이 있습니다.

* `PARALLEL WITH`는 피연산자 실행 결과를 반환하지 않으며, 예외가 발생한 경우 해당 예외를 다시 발생시킬 수만 있습니다.
* `PARALLEL WITH`는 결과 집합을 반환하지 않고 입력 데이터도 받지 않는 SQL 문을 결합하는 반면, `UNION`은 `SELECT` 쿼리를 결합합니다.
