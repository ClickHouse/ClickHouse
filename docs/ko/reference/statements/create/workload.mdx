도입 버전: v24.11.0

워크로드를 생성합니다. 워크로드는 [워크로드 스케줄링](/ko/concepts/features/configuration/server-config/workload-scheduling)에서 워크로드(workloads) 간에 리소스를 공유하는 데 사용하는 계층 구조의 노드입니다. 스케줄링할 리소스는 [`CREATE RESOURCE`](/ko/reference/statements/create/resource)로 생성합니다.

## 구문 {#syntax}

```sql
CREATE [OR REPLACE] WORKLOAD [IF NOT EXISTS] name [ON CLUSTER cluster] [IN parent_name] [SETTINGS setting = value [FOR resource_name] [, ...]]
```

* `OR REPLACE` - 기존 워크로드의 정의를 대체합니다. `IF NOT EXISTS`와 함께 사용할 수 없습니다.
* `IF NOT EXISTS` - 이름이 `name`인 워크로드가 이미 있으면 쿼리는 아무 작업도 수행하지 않습니다.
* `IN parent_name` - 워크로드를 `parent_name` 워크로드의 자식으로 생성합니다. `IN`이 없는 워크로드는 루트 워크로드입니다. 워크로드(workloads) 간에 사이클이 생기면 거부됩니다.
* `SETTINGS` - 워크로드의 스케줄링 설정으로, `weight`, `priority`, `max_concurrent_threads`, `max_bytes_per_second` 등이 있습니다. 자세한 내용은 [워크로드 계층 구조](/ko/concepts/features/configuration/server-config/workload-scheduling#workloads)를 참고하십시오. `FOR resource_name`이 지정된 설정은 해당 리소스에만 적용되고, 지정되지 않으면 모든 리소스에 적용됩니다. 알 수 없는 설정은 오류로 처리됩니다.

워크로드(workloads)와 리소스는 네임스페이스가 서로 분리되어 있으므로 워크로드와 리소스에 같은 이름을 사용할 수 있습니다. 쿼리는 [`workload`](/ko/reference/settings/session-settings/other#workload) 설정에 지정된 워크로드에서 실행됩니다. 자세한 내용은 [워크로드 마크업](/ko/concepts/features/configuration/server-config/workload-scheduling#workload-markup)을 참고하십시오.

<Note>
  메모리 예약 스케줄링은 Experimental 기능입니다. 여기에는 `MEMORY RESERVATION` 리소스와 워크로드 설정 `max_memory`, `max_memory_ratio`, `max_memory_before_spill`, `max_memory_to_spill_ratio`가 포함됩니다. 자세한 내용은 [메모리 예약](/ko/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)을 참고하십시오.
</Note>

## 저장소 {#storage}

워크로드(workloads)는 디스크의 [`workload_path`](/ko/reference/settings/server-settings/settings/workload#workload_path)에 저장되며, [`workload_zookeeper_path`](/ko/reference/settings/server-settings/settings/workload#workload_zookeeper_path)가 설정되어 있으면 ZooKeeper의 해당 경로에 저장됩니다. ZooKeeper 저장소를 사용하면 정의가 자동으로 복제되므로 `ON CLUSTER`를 사용할 수 없습니다. [서버 구성에 정의된](/ko/concepts/features/configuration/server-config/workload-scheduling#config_based_workloads) 워크로드(workloads)는 SQL로 대체하거나 삭제할 수 없습니다. 워크로드(workloads) 목록은 [`system.workloads`](/ko/reference/system-tables/workloads) 테이블에서 확인할 수 있습니다.

## 권한 {#privileges}

`CREATE WORKLOAD`를 실행하려면 `CREATE WORKLOAD` 권한(privilege)이 필요합니다. `CREATE OR REPLACE WORKLOAD`를 실행하려면 `DROP WORKLOAD` 권한(privilege)도 필요합니다.

## 예시 {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE WORKLOAD all SETTINGS max_concurrent_threads = 16;
CREATE WORKLOAD production IN all SETTINGS weight = 3;
CREATE WORKLOAD development IN all;
SELECT name, parent, create_query FROM system.workloads ORDER BY name;
```

```text title="Response"
┌─name────────┬─parent─┬─create_query───────────────────────────────────────────────┐
│ all         │        │ CREATE WORKLOAD `all` SETTINGS max_concurrent_threads = 16 │
│ development │ all    │ CREATE WORKLOAD development IN `all`                       │
│ production  │ all    │ CREATE WORKLOAD production IN `all` SETTINGS weight = 3    │
└─────────────┴────────┴────────────────────────────────────────────────────────────┘
```
