도입 버전: v24.11.0

[워크로드 스케줄링](/ko/concepts/features/configuration/server-config/workload-scheduling)에 사용할 리소스를 생성합니다. 리소스는 디스크 읽기나 CPU 시간과 같은 액세스 유형으로, [`CREATE WORKLOAD`](/ko/reference/statements/create/workload)로 생성한 워크로드(workloads) 간에 스케줄링됩니다.

## 구문 {#syntax}

```sql
CREATE [OR REPLACE] RESOURCE [IF NOT EXISTS] name [ON CLUSTER cluster] (access_mode [, ...])
```

`OR REPLACE`, `IF NOT EXISTS`, `ON CLUSTER`는 [`CREATE WORKLOAD`](/ko/reference/statements/create/workload#syntax)에서와 동일하게 동작합니다.

## 액세스 모드 {#access-modes}

| 액세스 모드                                        | 스케줄링 대상 액세스                                                                                                                                          | 도입 버전    |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `READ DISK disk_name`, `WRITE DISK disk_name` | 디스크 `disk_name`에 대한 읽기 또는 쓰기 작업. [리소스](/ko/concepts/features/configuration/server-config/workload-scheduling#resources)를 참조하십시오                         | v24.11.0 |
| `READ ANY DISK`, `WRITE ANY DISK`             | 모든 디스크에 대한 읽기 또는 쓰기 작업                                                                                                                               | v24.11.0 |
| `MASTER THREAD`, `WORKER THREAD`              | CPU. [CPU 스케줄링](/ko/concepts/features/configuration/server-config/workload-scheduling#cpu_scheduling)을 참조하십시오                                           | v25.4.0  |
| `QUERY`                                       | 쿼리 슬롯(Query slots). [쿼리 슬롯 스케줄링(Query slot scheduling)](/ko/concepts/features/configuration/server-config/workload-scheduling#query_scheduling)을 참조하십시오 | v25.6.0  |
| `MEMORY RESERVATION`                          | 메모리. [메모리 예약](/ko/concepts/features/configuration/server-config/workload-scheduling#memory-reservations)을 참조하십시오                                        | v26.6.2  |

하나의 리소스에 속한 액세스 모드는 디스크, CPU 스레드, `QUERY`, `MEMORY RESERVATION` 중 한 가지 유형이어야 합니다. `MASTER THREAD`, `WORKER THREAD`, `QUERY`, `MEMORY RESERVATION`은 각각 최대 하나의 리소스에만 속할 수 있습니다. `CREATE OR REPLACE RESOURCE`로는 리소스의 유형을 변경할 수 없으므로, 리소스를 삭제한 후 다시 생성하십시오.

<Note>
  `MEMORY RESERVATION`은 실험적 기능입니다. SQL 인터페이스와 동작은 향후 릴리스에서 변경될 수 있습니다.
</Note>

## 저장소 {#storage}

리소스는 워크로드(workloads)와 같은 방식으로 저장됩니다. 자세한 내용은 [저장소](/ko/reference/statements/create/workload#storage)를 참조하십시오. [`system.resources`](/ko/reference/system-tables/resources) 테이블에서 리소스 목록을 확인할 수 있습니다.

## 권한(privilege) {#privileges}

`CREATE RESOURCE`를 실행하려면 `CREATE RESOURCE` 권한(privilege)이 필요합니다. `CREATE OR REPLACE RESOURCE`를 실행하려면 `DROP RESOURCE` 권한(privilege)도 추가로 필요합니다.

## 예시 {#example}

```sql title="Query"
CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD);
CREATE RESOURCE local_io (READ DISK default, WRITE DISK default);
SELECT name, read_disks, write_disks, unit, create_query FROM system.resources ORDER BY name;
```

```text title="Response"
┌─name─────┬─read_disks──┬─write_disks─┬─unit──────────┬─create_query─────────────────────────────────────────────────────┐
│ cpu      │ []          │ []          │ CPUNanosecond │ CREATE RESOURCE cpu (MASTER THREAD, WORKER THREAD)               │
│ local_io │ ['default'] │ ['default'] │ IOByte        │ CREATE RESOURCE local_io (READ DISK default, WRITE DISK default) │
└──────────┴─────────────┴─────────────┴───────────────┴──────────────────────────────────────────────────────────────────┘
```
