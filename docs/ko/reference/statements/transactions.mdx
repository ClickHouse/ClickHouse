트랜잭션 제어 SQL 문인 `BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK`, `SET TRANSACTION SNAPSHOT`은 `MergeTree` 테이블을 대상으로 하는 여러 쿼리를 하나의 트랜잭션(transaction)으로 묶습니다.
트랜잭션 내의 쿼리는 다른 트랜잭션이 커밋한 변경 사항에 대해 일관된 하나의 스냅샷을 읽습니다.
트랜잭션 외부의 쓰기 작업은 격리되지 않습니다. 트랜잭션 외부에서 실행된 `INSERT`, `TRUNCATE TABLE` 또는 `ALTER TABLE ... DELETE`는 실행 중인 트랜잭션의 다음 쿼리에 그대로 반영됩니다. 따라서 일관된 뷰를 보장하려면 쓰기를 수행하는 쪽에서도 트랜잭션을 사용해야 합니다(예: [`implicit_transaction`](/ko/reference/settings/session-settings/implicit#implicit_transaction) 사용).
트랜잭션의 변경 사항은 `COMMIT` 이후에야 다른 트랜잭션에서 볼 수 있으며, `ROLLBACK`을 실행하면 폐기됩니다.
트랜잭션 외부에서 실행되는 쿼리는 실행 중인 트랜잭션이 커밋되기 전에도 해당 변경 사항을 볼 수 있습니다.

## 구문 {#syntax}

```sql
BEGIN TRANSACTION
START TRANSACTION
COMMIT
ROLLBACK
SET TRANSACTION SNAPSHOT snapshot
```

트랜잭션(transaction)은 세션에 속하며, 하나의 세션에는 최대 하나의 트랜잭션만 존재할 수 있습니다.
HTTP를 사용할 때는 트랜잭션의 모든 쿼리를 동일한 `session_id`로 전송하십시오. `session_id`가 없는 요청은 자체 세션에서 실행되며, 이 세션은 해당 요청이 끝나면 함께 종료됩니다.
세션이 종료될 때 아직 실행 중인 트랜잭션은 롤백됩니다.

## BEGIN TRANSACTION {#begin-transaction}

현재 세션(current session)에서 트랜잭션(transaction)을 시작합니다. `START TRANSACTION`은 이 문의 별칭이며, v24.3.0에서 도입되었습니다.

중첩된 트랜잭션은 지원되지 않습니다. 트랜잭션 내에서 `BEGIN TRANSACTION`을 실행하면 `INVALID_TRANSACTION` 예외가 발생합니다.

## COMMIT {#commit}

현재 트랜잭션(transaction)을 커밋하고 그 변경 사항을 다른 트랜잭션에서 볼 수 있도록 합니다.
현재 트랜잭션이 없는 상태에서 `COMMIT`을 실행하면 `INVALID_TRANSACTION` 예외가 발생합니다.

트랜잭션 내부의 쿼리가 실패하면 트랜잭션은 롤백됩니다. 구문 오류 등으로 파싱할 수 없는 쿼리나 쿼리 매개변수가 누락되었거나 유효하지 않은 쿼리는 실행되지 않으며, 트랜잭션은 실행 중인 상태로 유지됩니다. 따라서 이후에 `COMMIT`을 실행하면 해당 트랜잭션은 정상적으로 커밋됩니다.
롤백된 트랜잭션을 `ROLLBACK`으로 종료하기 전까지는 `COMMIT`을 비롯한 이후의 쿼리에서 `INVALID_TRANSACTION` 예외가 발생합니다. 이 상태에서는 `ROLLBACK`, `SET TRANSACTION SNAPSHOT`, 그리고 `EXPLAIN ANALYZE`를 제외한 `EXPLAIN` 쿼리만 실행할 수 있습니다.

[`wait_changes_become_visible_after_commit_mode`](/ko/reference/settings/session-settings/other#wait_changes_become_visible_after_commit_mode) 설정으로 `COMMIT`이 무엇을 기다릴지 제어할 수 있습니다.

## ROLLBACK {#rollback}

현재 트랜잭션(transaction)을 롤백하고 변경 사항을 모두 폐기합니다.
진행 중인 트랜잭션이 없는 상태에서 `ROLLBACK`을 실행하면 `INVALID_TRANSACTION` 예외가 발생합니다.

## SET TRANSACTION SNAPSHOT {#set-transaction-snapshot}

현재 트랜잭션(transaction)이 읽는 스냅샷을 커밋 시퀀스 번호(CSN) `snapshot`으로 변경합니다. 예를 들어 이전 트랜잭션에서 [`transactionLatestSnapshot`](/ko/reference/functions/regular-functions/other-functions#transactionLatestSnapshot)이 반환한 값을 지정할 수 있습니다.
이후 해당 트랜잭션에서는 자체 변경 사항, 트랜잭션 외부에서 기록된 데이터, 그리고 해당 CSN까지 커밋된 트랜잭션의 변경 사항이 보입니다.
이 트랜잭션은 서버가 아직 보관하고 있는 파트만 읽으며, 해당 파트가 삭제되지 않도록 보호하지는 않습니다. 머지, 뮤테이션 또는 다른 쿼리가 파트를 제거하기 전에 시작되어 아직 실행 중인 트랜잭션이 더 이상 없으면 서버는 해당 파트를 삭제할 수 있으며, 그러면 이전 스냅샷에서는 해당 파트의 행이 누락됩니다.
과거 데이터를 반복 읽기(repeatable read)하는 용도로 `SET TRANSACTION SNAPSHOT`을 사용하지 마십시오.
현재 트랜잭션이 없는 상태에서 `SET TRANSACTION SNAPSHOT`을 실행하면 `INVALID_TRANSACTION` 예외가 발생합니다.

`0`부터 `32`까지의 값은 예약되어 있어 `INVALID_TRANSACTION` 예외가 발생합니다. 단, 다음 두 값은 예외입니다.
`1`을 지정하면 트랜잭션 외부에서 기록된 데이터와 해당 트랜잭션 자체의 변경 사항만 보이고, `3`을 지정하면 아직 커밋되지 않은 트랜잭션의 파트와 트랜잭션이 제거했거나 롤백한 파트를 포함하여 테이블의 모든 파트가 보입니다.

## 트랜잭션 내부의 쿼리 {#queries-inside-a-transaction}

트랜잭션(transaction) 안에서는 `SELECT`, `INSERT`, `DELETE`, `OPTIMIZE`, `TRUNCATE TABLE`, `SET`, `EXPLAIN` 쿼리와 `ALTER TABLE` 뮤테이션 및 파티션 연산을 실행할 수 있습니다.
그 외의 쿼리(예: `CREATE TABLE`, `UPDATE`, `ALTER TABLE ... ADD COLUMN`)는 `NOT_IMPLEMENTED` 예외를 발생시키며, 트랜잭션을 지원하지 않는 테이블(예: `ReplicatedMergeTree` 또는 `Memory` 테이블, `system.transactions`)에 대한 쿼리도 마찬가지입니다.

비동기 삽입(asynchronous inserts)은 트랜잭션 내부에서 지원되지 않으며, [`async_insert`](/ko/reference/settings/session-settings/async-insert#async_insert)는 기본적으로 활성화되어 있습니다. 따라서 `SET async_insert = 0` 등으로 `async_insert`를 비활성화하지 않으면 트랜잭션 내부의 `INSERT ... VALUES` 또는 `INSERT ... SELECT`는 `NOT_IMPLEMENTED` 예외를 발생시킵니다.

[`throw_on_unsupported_query_inside_transaction`](/ko/reference/settings/session-settings/throw-on#throw_on_unsupported_query_inside_transaction)을 `0`으로 설정하면 이러한 쿼리 중 일부는 예외를 발생시키지 않고 트랜잭션 외부에서 실행되므로 `ROLLBACK`으로 되돌릴 수 없습니다. `CREATE TABLE`이나 `Memory` 테이블에 대한 `INSERT`가 그 예입니다.

[`implicit_transaction`](/ko/reference/settings/session-settings/implicit#implicit_transaction)을 활성화하면 트랜잭션 외부에서 실행되는 각 쿼리가 개별 트랜잭션으로 실행되며, 쿼리가 성공하면 커밋되고 실패하면 롤백됩니다.

## 예시 {#examples}

삽입 작업을 롤백합니다:

```sql title="Query"
CREATE TABLE t (n UInt64) ENGINE = MergeTree ORDER BY n;
SET async_insert = 0;

BEGIN TRANSACTION;
INSERT INTO t VALUES (1);
SELECT count() FROM t;
ROLLBACK;
SELECT count() FROM t;
```

```text title="Response"
┌─count()─┐
│       1 │
└─────────┘
┌─count()─┐
│       0 │
└─────────┘
```

삽입 커밋:

```sql title="Query"
BEGIN TRANSACTION;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```text title="Response"
┌─n─┐
│ 2 │
└───┘
```
