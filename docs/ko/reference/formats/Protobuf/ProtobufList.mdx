<div id="description">
  ## 설명 {#description}
</div>

`ProtobufList` 포맷은 행을 `Envelope`라는 하나의 length-delimited [Protocol Buffers](/ko/reference/formats/Protobuf/Protobuf) 메시지로 묶습니다. 각 행은 필드 번호가 1인 하위 메시지로 인코딩됩니다.

## 사용 예시 {#example-usage}

다음 스키마를 `schemafile.proto`로 저장하십시오. 이 스키마를 사용하는 Protobuf 디코더가 엔벌로프에 포함된 모든 행을 읽을 수 있도록 `row` 필드를 `repeated`로 선언하십시오.

```capnp title="schemafile.proto"
syntax = "proto3";
message Envelope {
  message MessageType {
    string name = 1;
  }
  repeated MessageType row = 1;
}
```

같은 디렉터리에서 다음 명령어를 실행하여 파일에 2개의 행을 쓴 다음 다시 읽어 오십시오.

```bash
clickhouse local --query "SELECT name FROM values('name String', 'Ada', 'Grace') ORDER BY name
    SETTINGS format_schema = 'schemafile:MessageType' FORMAT ProtobufList" > people.bin

clickhouse local --structure 'name String' --input-format ProtobufList \
    --format_schema 'schemafile:MessageType' --query 'SELECT name FROM table' < people.bin
```

```text
Ada
Grace
```

`format_schema`에 지정된 메시지 유형은 먼저 최상위 `Envelope` 메시지 안의 중첩 유형으로 해석됩니다. 여기서 일치하는 항목을 찾지 못하면 — 스키마에 `Envelope` 메시지가 없거나 `Envelope`에 요청한 이름의 메시지가 없는 경우 — 해당 이름의 최상위 메시지를 직접 사용합니다.
