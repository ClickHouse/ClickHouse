## 설명 {#description}

[Apache ORC](https://orc.apache.org/)는 [Hadoop](https://hadoop.apache.org/) 생태계에서 널리 사용되는 열 지향 스토리지 포맷입니다.

## 데이터 타입 매핑 {#data-types-matching-orc}

아래 표는 `INSERT` 및 `SELECT` 쿼리에서 지원되는 ORC 데이터 타입과, 이에 대응하는 ClickHouse [데이터 타입](/ko/reference/data-types/index)을 비교합니다.

| ORC 데이터 타입 (`INSERT`)         | ClickHouse 데이터 타입                                                                   | ORC 데이터 타입 (`SELECT`) |
| ----------------------------- | ----------------------------------------------------------------------------------- | --------------------- |
| `Boolean`                     | [Bool](/ko/reference/data-types/boolean)                                               | `Boolean`             |
| `Tinyint`                     | [Int8/UInt8](/ko/reference/data-types/int-uint)/[Enum8](/ko/reference/data-types/enum)    | `Tinyint`             |
| `Smallint`                    | [Int16/UInt16](/ko/reference/data-types/int-uint)/[Enum16](/ko/reference/data-types/enum) | `Smallint`            |
| `Int`                         | [Int32/UInt32](/ko/reference/data-types/int-uint)                                      | `Int`                 |
| `Bigint`                      | [Int64/UInt64](/ko/reference/data-types/int-uint)                                      | `Bigint`              |
| `Float`                       | [Float32](/ko/reference/data-types/float)                                              | `Float`               |
| `Double`                      | [Float64](/ko/reference/data-types/float)                                              | `Double`              |
| `Decimal`                     | [Decimal](/ko/reference/data-types/decimal)                                            | `Decimal`             |
| `Date`                        | [Date32](/ko/reference/data-types/date32)                                              | `Date`                |
| `Timestamp`                   | [DateTime64](/ko/reference/data-types/datetime64)                                      | `Timestamp`           |
| `String`, `Varchar`, `Binary` | [String](/ko/reference/data-types/string)                                              | `String`              |
| `Char`                        | [FixedString](/ko/reference/data-types/fixedstring)                                    | `String`              |
| `List`                        | [배열](/ko/reference/data-types/array)                                                | `List`                |
| `Struct`                      | [Tuple](/ko/reference/data-types/tuple)                                                | `Struct`              |
| `Map`                         | [Map](/ko/reference/data-types/map)                                                    | `Map`                 |
| `Int`                         | [IPv4](/ko/reference/data-types/int-uint)                                              | `Int`                 |
| `Binary`                      | [IPv6](/ko/reference/data-types/ipv6)                                                  | `Binary`              |
| `Binary`                      | [Int128/UInt128/Int256/UInt256](/ko/reference/data-types/int-uint)                     | `Binary`              |
| `Binary`                      | [Decimal256](/ko/reference/data-types/decimal)                                         | `Binary`              |
| `Union`                       | [Variant](/ko/reference/data-types/variant)                                            | `Union`               |

* 기타 타입은 지원되지 않습니다.
* ORC `Union` 컬럼은 Union의 브랜치 타입을 포함하는 [Variant](/ko/reference/data-types/variant)로 읽히며, `Variant` 컬럼은 브랜치 타입을 포함하는 ORC `Union`으로 작성됩니다. `Variant`는 브랜치 타입을 정렬하므로 브랜치 순서가 ORC 파일과 다를 수 있습니다. 중복된 브랜치 타입이 있는 Union(예: `uniontype<int,int>`)은 지원되지 않습니다.
* 배열은 중첩할 수 있으며, 인수로 `Nullable` 타입 값을 사용할 수 있습니다. `Tuple` 및 `Map` 타입도 중첩할 수 있습니다.
* ClickHouse 테이블 컬럼의 데이터 타입은 해당 ORC 데이터 필드와 일치할 필요가 없습니다. 데이터를 삽입할 때 ClickHouse는 위 표에 따라 데이터 타입을 해석한 다음, 이를 ClickHouse 테이블 컬럼에 설정된 데이터 타입으로 [형 변환](/ko/reference/functions/regular-functions/type-conversion-functions#CAST)합니다.
* `1969-12-31 23:59:59.001`과 `1969-12-31 23:59:59.999999999`(UTC) 사이의 `DateTime64` 값은 `1970-01-01 00:00:00`으로 기록됩니다. 이는 [ORC 명세](https://orc.apache.org/specification/ORCv1/#timestamp-columns)의 허점 때문입니다. ORC 명세는 타임스탬프를 초와 나노초로 나누어 저장하며, 나노초는 음수가 될 수 없습니다. 참조 구현에서는 writer가 999999나노초를 초과하는 음수 타임스탬프에 1초를 더하고 리더가 이를 다시 빼지만, 이렇게 하면 -1초와 0초 사이의 타임스탬프는 0초로 저장되어 epoch 이후의 값으로 읽히게 됩니다. 이러한 타임스탬프를 기록하는 방식은 구현마다 다릅니다. Apache ORC의 Java 및 C++ writer는 1초 늦은 값으로 읽히도록 기록하고, Arrow ORC 어댑터(PyArrow)는 음수 나노초를 기록합니다. 그러나 음수 나노초는 명세에서 허용되지 않으며 Java 리더는 이를 거부합니다. ClickHouse는 대신 epoch를 기록하므로 모든 리더가 이 값을 동일하게 읽습니다.
* 타임스탬프의 writer 시간대와 리더 시간대가 다르면, Apache ORC의 Java 리더와 ClickHouse는 writer가 1초를 더하는 방식에 맞추어 시간대를 변환하기 전에 해당 1초를 빼는 반면, Apache ORC의 C++ 리더(PyArrow에서도 사용)는 변환한 후에 이를 뺍니다. 따라서 C++ 리더는 어떤 writer가 기록한 파일이든 epoch로부터 시간대 오프셋 이내에 있는 1970년 이전 타임스탬프를 1초 어긋나게 읽을 수 있습니다.

## 사용 예시 {#example-usage}

### 데이터 삽입 {#inserting-data}

다음 데이터가 들어 있는 `football.orc`라는 ORC 파일을 사용합니다:

```text

 1. │ 2022-04-30 │   2021 │ Sutton United         │ Bradford City       │               1 │               4 │
 2. │ 2022-04-30 │   2021 │ Swindon Town          │ Barrow              │               2 │               1 │
 3. │ 2022-04-30 │   2021 │ Tranmere Rovers       │ Oldham Athletic     │               2 │               0 │
 4. │ 2022-05-02 │   2021 │ Port Vale             │ Newport County      │               1 │               2 │
 5. │ 2022-05-02 │   2021 │ Salford City          │ Mansfield Town      │               2 │               2 │
 6. │ 2022-05-07 │   2021 │ Barrow                │ Northampton Town    │               1 │               3 │
 7. │ 2022-05-07 │   2021 │ Bradford City         │ Carlisle United     │               2 │               0 │
 8. │ 2022-05-07 │   2021 │ Bristol Rovers        │ Scunthorpe United   │               7 │               0 │
```

데이터를 삽입하세요:

```sql
INSERT INTO football FROM INFILE 'football.orc' FORMAT ORC;
```

### 데이터 읽기 {#reading-data}

`ORC` 포맷을 사용해 데이터를 읽습니다:

```sql
SELECT *
FROM football
INTO OUTFILE 'football.orc'
FORMAT ORC
```

<Tip>
  ORC는 터미널에서 사람이 읽을 수 있는 형태로 표시되지 않는 바이너리 형식입니다. ORC 파일로 출력하려면 `INTO OUTFILE`을 사용하세요.
</Tip>

| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------- |
| [`output_format_orc_string_as_string`](/ko/reference/settings/formats/output-format#output_format_orc_string_as_string)                                                                            | String 컬럼에 Binary 대신 ORC String 타입을 사용합니다.         | `true`  |
| [`output_format_orc_compression_method`](/ko/reference/settings/formats/output-format#output_format_orc_compression_method)                                                                        | 출력 ORC 포맷에서 사용하는 압축 방식입니다.                         | `zstd`  |
| [`input_format_orc_case_insensitive_column_matching`](/ko/reference/settings/formats/input-format#input_format_orc_case_insensitive_column_matching)                                               | ORC 컬럼을 ClickHouse 컬럼과 매칭할 때 대소문자를 구분하지 않습니다.      | `false` |
| [`input_format_orc_allow_missing_columns`](/ko/reference/settings/formats/input-format#input_format_orc_allow_missing_columns)                                                                     | ORC 데이터를 읽을 때 누락된 컬럼을 허용합니다.                       | `true`  |
| [`input_format_orc_skip_columns_with_unsupported_types_in_schema_inference`](/ko/reference/settings/formats/input-format#input_format_orc_skip_columns_with_unsupported_types_in_schema_inference) | ORC 포맷의 스키마 추론 중 지원되지 않는 타입의 컬럼을 스키핑할 수 있도록 허용합니다. | `false` |
