## 설명 {#description}

[Apache Iceberg Puffin](https://iceberg.apache.org/puffin-spec/) 파일을 읽고 쓰기 위한 포맷입니다.

이 포맷은 `deletion-vector-v1` 블롭에 담긴 삭제된 행의 위치를 제공합니다. `apache-datasketches-theta-v1`과 같은 다른 유형의 블롭은 Puffin 사양에 따라 건너뛰며, 이러한 블롭을 확인하려면 `PuffinMetadata`를 사용하십시오.
Puffin 파일에 `deletion-vector-v1` 블롭이 여러 개 포함된 경우, 이 포맷은 블롭마다 하나의 행을 출력합니다.

고정 출력 컬럼:

* `referenced_data_file` (`String`) - 삭제 벡터가 적용되는 데이터 파일의 위치(`referenced-data-file` 블롭 속성)
* `deleted_rows` (`Array(UInt64)`) - 삭제 벡터의 roaring bitmap에 따라 삭제된 64비트 행 위치

출력 포맷으로 사용할 경우, 입력에는 이 포맷이 읽기 시 생성하는 것과 동일한 두 컬럼이 있어야 합니다. 즉, 참조되는 데이터 파일(`String` 또는 `LowCardinality(String)`)과 삭제된 행의 위치(행당 위치 하나를 나타내는 정수(integer) 또는 정수 배열)입니다. 파일에는 고유한 참조 데이터 파일마다 `deletion-vector-v1` 블롭이 하나씩 데이터 파일 위치 순으로 포함되므로, 삭제 벡터가 여러 개인 Puffin 파일도 그대로 복사할 수 있습니다. 참조 데이터 파일이 같은 모든 행의 위치는 하나의 삭제 벡터로 머지되고, 중복이 제거된 후 정렬됩니다. 음수 위치, Iceberg 삭제 벡터 한도를 초과하는 위치, 비어 있는 데이터 파일 위치는 거부됩니다. 블롭 메타데이터는 Apache Iceberg가 삭제 벡터를 기록하는 방식과 동일하게 기록됩니다. `fields`는 `[2147483645]`(`_pos` 메타데이터 컬럼 id)이고, `snapshot-id`와 `sequence-number`는 `-1`이며, `referenced-data-file` 및 `cardinality` 속성이 설정됩니다. 바닥글은 압축되지 않으므로, 생성된 파일을 Iceberg v3 테이블에 삭제 벡터 delete 파일로 등록하고 Apache Spark 등 다른 엔진에서 읽을 수 있습니다. 기록된 파일에 `PuffinMetadata`를 사용하면 manifest 필드 `content_offset` 및 `content_size_in_bytes`에 지정할 각 블롭의 `offset`과 `length`를 확인할 수 있습니다.

`output_format_puffin_blob_type` 설정을 `apache-datasketches-theta-v1`로 지정하면, 이 포맷은 삭제 벡터 대신 Apache Iceberg와 동일한 방식으로 컬럼 통계를 기록합니다. 각 입력 컬럼은 해당 컬럼의 non-null 값에 대한 compact Apache DataSketches Theta 스케치(기본 seed 및 크기)를 담은 `apache-datasketches-theta-v1` 블롭 하나가 되며, `ndv` 속성에는 추정된 고유 값 개수가 설정됩니다. 값은 컬럼 타입에 따른 Iceberg 단일 값 바이너리 직렬화 형태로 스케치에 입력되므로, Apache Spark가 기록한 스케치와 머지할 수 있습니다. `Bool`은 `boolean`, `Int8`, `UInt8`, `Int16`, `UInt16`, `Int32`는 `int`, `UInt32`, `Int64`, `UInt64`는 `long`(`Int64` 범위를 초과하는 `UInt64` 값은 비트를 그대로 유지), `Float32`는 `float`, `Float64`는 `double`, `Date`와 `Date32`는 `date`, 정밀도 6자리 이하의 `DateTime`과 `DateTime64`는 `timestamp`(마이크로초 단위), `String`은 `string`, `FixedString`은 `fixed`, `UUID`는 `uuid`, `Decimal`은 `decimal`로 처리됩니다. 이 타입들의 `Nullable` 및 `LowCardinality`도 지원됩니다. Iceberg와 마찬가지로 빈 문자열은 무시됩니다. 블롭의 `fields`는 `output_format_puffin_field_ids` 설정에서, `snapshot-id`와 `sequence-number`는 각각 `output_format_puffin_snapshot_id` 및 `output_format_puffin_sequence_number` 설정에서 가져옵니다. 리더는 이 값들이 가리키는 컬럼과 스냅샷에 통계를 연결하므로 세 설정 모두 필수입니다. 결과 파일은 Iceberg 통계 파일로 등록할 수 있습니다.

`deleted_rows`를 요청하면, 선언된 `cardinality`가 머티리얼라이즈 절대 상한을 초과하는 삭제 벡터는 거부됩니다. 바닥글의 `deletion-vector-v1` 속성(`cardinality`가 부호 없는 정수로 파싱되는지 여부 포함)은 항상 검증됩니다. `referenced_data_file`만 선택하면 on-disk payload 입출력(IO)을 건너뛰므로 엔벌로프, CRC, roaring 역직렬화, 머티리얼라이즈 상한 검사도 함께 건너뜁니다. 이는 경로만 조회하는 프로젝션이 블롭 크기 상한까지 읽지 않도록 의도된 동작입니다.

On-disk `deletion-vector-v1` 블롭 길이는 절대 상한(Iceberg의 2 GiB 콘텐츠 크기 검사와 동일)으로 제한됩니다. `deleted_rows`를 요청하면 리더는 전체 payload를 할당하기 전에 엔벌로프 헤더(결합 길이 및 매직 값)를 먼저 확인하며, CRC는 제한된 읽기를 마친 후 검증합니다.

LZ4로 압축된 puffin 바닥글과 비압축 puffin 바닥글을 모두 지원합니다. 바닥글 payload 크기(및 선언된 LZ4 콘텐츠 크기)는 해당하는 경우 압축률과 절대 상한으로 제한되며, 크기가 너무 큰 바닥글은 할당 전에 거부됩니다.

출력 컬럼의 부분 집합만 요청할 수 있습니다. 포맷 생성 시 예상치 못한 컬럼명이나 타입이 포함된 사용자 제공 구조는 거부됩니다.

## 사용 예시 {#example-usage}

참조된 데이터 파일에서 삭제된 행 위치를 읽습니다:

```sql
SELECT referenced_data_file, deleted_rows
FROM file(deletes.puffin, Puffin);
```

삭제된 위치를 개별 행으로 펼칩니다:

```sql
SELECT referenced_data_file, row_number
FROM file(deletes.puffin, Puffin)
ARRAY JOIN deleted_rows AS row_number
ORDER BY referenced_data_file, row_number;
```

삭제 벡터를 읽기 전에 `PuffinMetadata`를 사용하여 바닥글 블롭 디스크립터를 확인합니다.

2개의 데이터 파일에 대한 삭제 벡터를 하나의 Puffin 파일에 씁니다:

```sql
INSERT INTO FUNCTION file('deletes.puffin', Puffin)
SELECT * FROM values('referenced_data_file String, deleted_rows Array(UInt64)',
    ('s3://bucket/warehouse/db/table/data/00000-0-data.parquet', [2, 5, 7]),
    ('s3://bucket/warehouse/db/table/data/00001-0-data.parquet', [100, 65536]));
```

두 컬럼의 Theta 스케치를 Iceberg 통계 파일로 씁니다:

```sql
INSERT INTO FUNCTION file('stats.puffin', Puffin)
SETTINGS output_format_puffin_blob_type = 'apache-datasketches-theta-v1', output_format_puffin_field_ids = '1,2',
    output_format_puffin_snapshot_id = 3051729675574597004, output_format_puffin_sequence_number = 1
SELECT number AS id, toString(number % 10) AS name FROM numbers(1000);

SELECT fields, properties['ndv'] FROM file('stats.puffin', PuffinMetadata);
```
