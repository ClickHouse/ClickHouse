## 설명 {#description}

[`JSONCompactEachRow`](/ko/reference/formats/JSON/JSONCompactEachRow)의 간결한 행(row) 단위 출력에 스트리밍 진행 상황 정보를 결합합니다. ClickHouse는 각 이벤트를 별도의 JSON 객체로 스트리밍하며, 컬럼(column) 값은 원래의 JSON 타입을 유지합니다.

관련 포맷인 `JSONCompactStringsEachRowWithProgress`는 동일한 최상위 객체 종류를 사용하며, 필드 값은 문자열로 직렬화됩니다.

[`JSONEachRowWithProgress`](/ko/reference/formats/JSON/JSONEachRowWithProgress)와 동일한 스트림 규약(`writesProgressConcurrently` / `finalizeImpl`)을 따릅니다. 단, `row` / `totals` / `min` / `max` payload는 이름으로 값을 구분하는 객체가 아니라 컬럼 순서대로 값이 나열된 **배열**입니다.

## 스트림 객체 {#stream-objects}

응답의 각 줄은 하나의 JSON 객체입니다. 클라이언트는 최상위 키에 따라 처리를 분기해야 합니다.

| 최상위 키                        | 출력 시점                                                                      | 구조                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `meta`                       | 첫 번째 `row` 이전에 한 번 (`progress` 객체가 그보다 먼저 출력될 수 있음)                        | `{"meta":[{"name":...,"type":...}, ...]}` — 컬럼명(column names)과 타입(types)               |
| `row`                        | 결과 행(row)마다 한 번                                                            | `{"row":[...]}` — 헤더 순서로 나열된 컬럼 값                                                      |
| `progress`                   | 쿼리(query) 실행 중 주기적으로                                                       | `{"progress":{...}}` — `read_rows`, `read_bytes`, `total_rows_to_read` 등의 카운터          |
| `totals`                     | 합계가 있을 때                                                                   | `{"totals":[...]}` — 헤더 순서로 나열된 합계 행의 값                                                |
| `min` / `max`                | 극값이 있을 때                                                                   | `{"min":[...]}` / `{"max":[...]}` — 헤더 순서로 나열된 극값 행의 값                                 |
| `rows_before_limit_at_least` | 쿼리에 `LIMIT`가 포함될 때                                                         | `{"rows_before_limit_at_least":N}` — `LIMIT`가 없었다면 반환되었을 행 수의 하한 추정치(행이 제외되었다는 증거는 아님) |
| `rows_before_aggregation`    | 쿼리가 집계(aggregation)를 수행하고 `rows_before_aggregation` 카운터가 활성화되어 있을 때        | `{"rows_before_aggregation":N}`                                                        |
| `exception`                  | HTTP를 통한 요청에서 `http_write_exception_in_output_format=1`이 설정되어 있고 쿼리가 실패할 때 | `{"exception":"..."}` — `row` 내부에 중첩되지 않고 **최상위 문자열**로 제공되는 오류 텍스트                     |

`rows_before_limit_at_least` 객체는 쿼리에 `LIMIT`가 포함되어 있으면 제한으로 인해 제외된 행이 없더라도 출력됩니다. 이 값은 `LIMIT`가 없었다면 반환되었을 행 수의 하한 추정치이며, `JSON`에서와 의미가 같습니다. 클라이언트는 이를 행이 제외되었다는 증거로 간주해서는 안 됩니다.

`meta`는 첫 번째 `row` 이전에 한 번 출력되지만, `progress` 객체가 `meta`보다 먼저 도착할 수 있습니다. 최상위 `exception` 객체는 HTTP를 통한 요청에서 `http_write_exception_in_output_format=1`이 설정된 경우에만 출력됩니다. 그렇지 않으면 오류는 전송 계층을 통해 전달됩니다. 이 객체는 출력 시 `row` 내부에 중첩되지 않고 별도의 최상위 객체로 제공됩니다.

## 사용 예시 {#example-usage}

```sql title="Query"
SELECT *
FROM generateRandom('a Array(Int8), d Decimal32(4), c Tuple(DateTime64(3), UUID)', 1, 10, 2)
LIMIT 5
FORMAT JSONCompactEachRowWithProgress
```
