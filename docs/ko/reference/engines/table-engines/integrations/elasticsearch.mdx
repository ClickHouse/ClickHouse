`Elasticsearch` 엔진을 사용하면 [Elasticsearch](https://www.elastic.co/elasticsearch)의 인덱스에서 문서를 읽을 수 있습니다. 각 문서는 하나의 행으로 반환됩니다. 문서의 `_source`는 [JSON](/ko/reference/data-types/newjson) 타입의 단일 컬럼으로 노출되며, 문서 ID와 인덱스 이름은 가상 컬럼(virtual columns)으로 제공됩니다.

이 엔진은 읽기 전용입니다. 문서는 `_search` API를 통해 페이지 단위로 가져옵니다. 이때 [특정 시점(point in time)](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results#search-after)을 사용하므로, 인덱스가 수정되는 중에도 쿼리는 인덱스의 일관된 스냅샷을 조회합니다.

이 엔진은 특정 시점 API와 `_shard_doc` 정렬 필드를 사용하므로 Elasticsearch 7.12 이상이 필요합니다. OpenSearch에는 `_shard_doc` 필드가 없으므로 지원되지 않습니다. 이보다 이전 버전의 서버는 첫 번째 요청부터 오류를 반환하며 거부합니다.

## 테이블 생성 {#creating-a-table}

```sql
CREATE TABLE [IF NOT EXISTS] [db.]table_name
[(
    name1 JSON
)]
ENGINE = Elasticsearch('url', 'index'[, 'user', 'password'][, query('...')][, key = value, ...])
[SETTINGS keep_alive = 60, page_size = 10000]
```

<Note>
  Elasticsearch 통합은 실험적 기능입니다. [`enable_elasticsearch`](/ko/reference/settings/session-settings/enable#enable_elasticsearch) 설정으로 활성화하십시오.

  ```sql
  SET enable_elasticsearch = 1;
  ```
</Note>

컬럼 목록(column list)은 선택 사항입니다. 생략하면 테이블에는 `JSON` 타입의 컬럼 `document` 하나만 생성됩니다. 지정하는 경우 정확히 1개의 컬럼만 포함해야 하며, 해당 컬럼의 타입은 `JSON`이어야 합니다. 이때 타입 힌트와 skip path를 선택적으로 지정할 수 있습니다. `MATERIALIZED`, `ALIAS`, `EPHEMERAL` 컬럼은 지원되지 않으며, `_id`와 `_index`라는 이름은 가상 컬럼(virtual columns)용으로 예약되어 있습니다.

**엔진 매개변수**

* `url` — Elasticsearch 클러스터의 기본 URL입니다(예: `https://localhost:9200`). 자격 증명, 쿼리 문자열, 프래그먼트가 포함되지 않은 `http` 또는 `https` URL이어야 합니다.
* `index` — 읽을 인덱스입니다. Elasticsearch 특정 시점(point in time) API에서 허용하는 형식이라면 별칭, 데이터 스트림, 쉼표로 구분된 목록, 와일드카드 패턴, 또는 `<logs-{now/d}>`와 같은 날짜 연산 표현식도 사용할 수 있습니다. 값은 리터럴 이름 그대로 지정해야 하며 URL 인코딩하면 안 됩니다. 일치하는 인덱스가 없는 패턴을 지정하면 오류가 발생합니다.
* `user`, `password` — HTTP 기본 인증에 사용하는 자격 증명입니다(선택 사항).
* `query('...')` — 읽을 문서를 선택하는 JSON 형식의 Elasticsearch [Query DSL](https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl) 객체입니다(선택 사항). 위치 인수 뒤에 지정해야 합니다. 기본값: `{"match_all": {}}`.

매개변수는 [명명된 컬렉션](/ko/concepts/features/configuration/server-config/named-collections)으로 전달할 수도 있으며, 이때 `key = value` 형식으로 값을 재정의할 수 있습니다. 전체 키 목록과 [인증 방식](/ko/reference/functions/table-functions/elasticsearch#authentication)에 대한 설명은 [`elasticsearch` 테이블 함수](/ko/reference/functions/table-functions/elasticsearch#arguments)를 참조하십시오.

**엔진 설정**

| 설정           | 기본값     | 설명                                                                                                                                                                                                                                                                        |
| ------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keep_alive` | `60`    | 연속된 두 페이지 요청 사이에 Elasticsearch가 특정 시점(point in time)을 유지하는 시간(초)입니다.                                                                                                                                                                                                      |
| `page_size`  | `10000` | 한 번의 요청으로 Elasticsearch에서 가져오는 문서 수입니다. 각 페이지는 하나의 블록이 되므로 이 설정이 읽기 작업의 블록 크기도 결정하며, [`max_block_size`](/ko/reference/settings/session-settings/max#max_block_size)는 적용되지 않습니다. Elasticsearch의 `index.max_result_window` 인덱스 설정(기본값 `10000`)을 초과하는 값은 Elasticsearch에서 거부됩니다. |

이 설정은 `ALTER TABLE ... MODIFY SETTING`으로 변경할 수 없습니다. 변경하려면 테이블을 다시 생성하십시오.

## 가상 컬럼 {#virtual-columns}

* `_id` — 문서 ID입니다. 유형: `String`.
* `_index` — 문서를 읽어 온 인덱스의 이름입니다. 유형: `LowCardinality(String)`.

쿼리가 가상 컬럼(virtual columns)만 읽는 경우에는 Elasticsearch에 문서의 `_source`를 요청하지 않습니다. `_source`를 저장하지 않는 인덱스(매핑에서 `_source` 필드가 비활성화된 인덱스)는 가상 컬럼으로만 읽을 수 있습니다. 이러한 인덱스에서 `JSON` 컬럼(column)을 읽는 쿼리는 빈 문서를 반환하는 대신 오류를 내며 실패합니다.

## 사용 예시 {#usage-example}

```sql
CREATE TABLE logs
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*', 'elastic', 'changeme')
SETTINGS page_size = 5000;

SELECT _index, _id, document.message
FROM logs
WHERE document.level = 'error'
LIMIT 10;
```

Query DSL 객체를 사용하여 Elasticsearch 측에서 필터링합니다:

```sql
CREATE TABLE errors_since_october
ENGINE = Elasticsearch('https://localhost:9200', 'logs-*',
                       query('{"bool": {"filter": [{"term": {"level": "error"}}, {"range": {"@timestamp": {"gte": "2026-10-01T00:00:00Z"}}}]}}'),
                       api_key = '...');
```

`query`에는 절대 날짜를 사용하십시오. `now-1h`와 같은 날짜 연산은 페이지마다 새로 계산되므로 일부 문서가 누락될 수 있습니다. 자세한 내용은 [`elasticsearch` 테이블 함수의 제한 사항](/ko/reference/functions/table-functions/elasticsearch#limitations)을 참조하십시오.
