SQL로 생성된 [이름이 지정된 컬렉션(named collection)](/ko/concepts/features/configuration/server-config/named-collections)은
`system.named_collections` 테이블을 통해 백업(backup)으로 내보내고 백업에서 복원할 수 있습니다.
내보낸 컬렉션에는 비밀 값을 포함한 모든 값이 담기므로, 컬렉션의 백업과 복원은 전용 권한과 설정으로 제어됩니다.
이 페이지에서는 이러한 권한과 설정을 설명합니다.

서버 설정 파일에 정의된 컬렉션은 설정을 기반으로 렌더링되며 백업에 포함되지 않습니다.
백업된 컬렉션을 복원하더라도 설정 파일에 정의된 같은 이름의 컬렉션은 덮어쓰지 않습니다.

## 컬렉션 선택 {#selecting-the-collections}

`BACKUP` 쿼리가 `system.named_collections`
테이블을 선택하면 이름이 지정된 컬렉션(named collections)을 내보냅니다.

* 명시적 선택: `BACKUP TABLE system.named_collections`. 이 경우 필요한 권한(아래 참조)이
  반드시 있어야 합니다.
* 암시적 선택: `DATABASE system` 또는 `ALL` 원소를 통해 선택합니다. 기본적으로 이러한 백업은 사용자가 컬렉션의 값을 읽을 수 있는 경우에만
  컬렉션을 내보내고, 그렇지 않으면 경고를 표시하고 건너뜁니다. 따라서
  모든 항목을 백업할 수는 있지만 값은 읽을 수 없는 사용자도 `BACKUP ALL`을 문제없이
  계속 사용할 수 있습니다.

테이블 데이터를 제외하는 선택(`BACKUP TABLE system.named_collections EXCEPT DATA FROM
TABLE system.named_collections` 또는 `EXCEPT DATA FROM TABLES
system.named_collections`를 지정한 와일드카드 원소)은 백업에 테이블 정의만 남깁니다. 이 경우
컬렉션은 하나도 내보내지 않으며 아래 권한도 전혀 필요하지 않습니다.

## 필수 권한 {#required-privileges}

컬렉션을 내보내면 해당 값이 백업에 기록되므로, `system.named_collections`에서 값을 읽을 때와 동일한 권한이
필요합니다:
[`SHOW NAMED COLLECTIONS`](/ko/reference/statements/grant#named-collection-admin),
`SHOW NAMED COLLECTIONS SECRETS` 및
[`displaySecretsInShowAndSelect`](/ko/reference/statements/grant#displaysecretsinshowandselect).
이는 이름이 지정된 컬렉션(named collections) 저장소가 암호화된 경우에도 마찬가지입니다. 엔트리는 암호문으로 복사되지만,
동일한 개인 키(Key)를 보유한 서버라면 이를 복원할 수 있고, 복원된 컬렉션의 값은 읽을 수 있습니다.

컬렉션을 복원하려면
[`CREATE NAMED COLLECTION`](/ko/reference/statements/grant#named-collection-admin) 권한이 필요하며, 위에 나열된
권한은 필요하지 않습니다. 즉, 운영자는 백업 내용을 읽을 수 없더라도 복원할 수 있으며, 이러한 복원 과정의 오류와 로그에는
컬렉션 이름이 전혀 표시되지 않습니다.

`BACKUP ON CLUSTER` 및 `RESTORE ON CLUSTER`에서는 쿼리가 다른 호스트로 전달되기 전에, 쿼리를 시작한 호스트에서
쿼리를 시작한 사용자를 기준으로 권한을 검사합니다. 롤링 업그레이드 중에 이 기능이 포함된 버전을 실행하는 호스트는
이 기능이 없는 버전을 실행하는 initiator로부터 전달된 쿼리에 대해서는 컬렉션을 내보내거나 복원하지 않습니다.
이러한 initiator는 권한을 검사할 수 없기 때문입니다. 이 경우 내보내기는 건너뛰고(명시적으로 선택한 경우에는 거부되고),
컬렉션 엔트리 복원은 거부됩니다.

## `backup_named_collections` {#backup-named-collections}

유형: `Bool`. 선택 사항이며, 기본적으로 설정되어 있지 않습니다.

`BACKUP` 쿼리가 이름이 지정된 컬렉션(named collections)을 백업에 포함할지 여부를 제어합니다.

* 설정되지 않음(기본값): `TABLE system.named_collections` 원소를 명시적으로 지정하면 컬렉션을 백업에 포함하며
  관련 권한이 필요합니다. `DATABASE system` 또는 `ALL` 원소는 사용자가 권한을 보유한 경우에만
  컬렉션을 포함하고, 그렇지 않으면 경고를 출력하고 건너뜁니다.
* `true`: 쿼리 대상에 해당 테이블이 포함될 때마다 컬렉션을 백업에 포함하며, 암시적으로 포함된 경우에도
  권한이 없으면 오류가 발생합니다.
* `false`: `system.named_collections` 테이블을 명시적으로 지정하더라도 컬렉션을 백업에
  포함하지 않으며, 어떠한 권한도 필요하지 않습니다.

```sql
-- Fails instead of skipping the collections when the privileges are missing:
BACKUP ALL TO Disk('backups', 'everything') SETTINGS backup_named_collections = 1

-- Never exports the collections:
BACKUP ALL TO Disk('backups', 'no_collections') SETTINGS backup_named_collections = 0
```

## `restore_named_collections` {#restore-named-collections}

유형: `Bool`. 기본값: `true`.

`RESTORE` 쿼리 실행 시 백업에 포함된 이름이 지정된 컬렉션(named collections)을 복원할지 여부를 지정합니다.
[`restore_table_data`](/ko/concepts/features/backup-restore/restore-settings) 등 관련 설정과 달리, `structure_only`에서도 기본값이
`true`로 유지됩니다. 컬렉션은 정의에 해당하며, 엔진에서 컬렉션을 참조하는 테이블(예: `ENGINE = URL(collection)`)은 해당 컬렉션 없이는 생성할 수 없기 때문입니다.

```sql
-- Restores everything except the named collections:
RESTORE ALL FROM Disk('backups', 'everything') SETTINGS restore_named_collections = 0
```

## `create_named_collection` {#create-named-collection}

유형: `String`. 기본값: `'if-not-exists'`.

`RESTORE` 시 동일한 명명된 컬렉션(named collection)이 이미 존재하는 경우의 처리 방식입니다.

* `'if-not-exists'` (기본값): 기존 컬렉션을 유지하고 백업된 컬렉션은
  건너뜁니다.
* `'create'`: 기존 컬렉션이 있으면 복원이 실패합니다.
* `'replace'`: 기존 컬렉션을 백업된 컬렉션으로 대체합니다.
  서버 구성에 정의된 컬렉션은 대체할 수 없으므로 복원이 실패합니다.

```sql
RESTORE TABLE system.named_collections FROM Disk('backups', 'everything')
SETTINGS create_named_collection = 'replace'
```

## 암호화된 이름이 지정된 컬렉션 저장소 {#encrypted-storage}

[이름이 지정된 컬렉션용 암호화된 저장소](/ko/concepts/features/configuration/server-config/named-collections)
(`local_encrypted` 또는 `zookeeper_encrypted`)를 사용하면, 엔트리는 저장소에 보관된 암호문 그대로
백업에 복사되고 그 뒤에 인증 코드가 붙습니다. 따라서 백업 어디에도 평문 값이 남지 않으며,
엔트리가 변조된 경우 복호화가 시작되기 전에 복원이 실패합니다.

이러한 백업을 복원하려면 이름이 지정된 컬렉션 저장소가 마찬가지로 암호화되어 있고, 컬렉션 암호화에 사용된
키(Key)를 보유한 서버가 필요합니다. 복원된 엔트리는 복원을 수행하는 서버의 키(Key)로 다시 암호화됩니다.
암호화된 엔트리가 포함된 백업은 암호화되지 않은 저장소로 복원할 수 없습니다. 해당 키(Key)를 보유한
암호화된 저장소를 구성하거나, `restore_named_collections = 0`을 설정하여 컬렉션 복원을 건너뛰십시오.
