ClickHouse는 MySQL 와이어 프로토콜을 지원합니다. 따라서 네이티브 ClickHouse 커넥터가 없는 일부 클라이언트도 MySQL 프로토콜을 통해 연결할 수 있습니다. 다음 BI 도구에서 호환성이 검증되었습니다.

* [Looker Studio](/ko/integrations/connectors/data-visualization/looker-studio-and-clickhouse)
* [Tableau Online](/ko/integrations/connectors/data-visualization/tableau/tableau-online-and-clickhouse)
* [QuickSight](/ko/integrations/connectors/data-visualization/quicksight-and-clickhouse)

검증되지 않은 다른 클라이언트나 통합을 사용할 때는 다음과 같은 제한 사항이 있을 수 있으므로 유의하십시오.

* SSL 구현이 완전히 호환되지 않아 [TLS SNI](https://www.cloudflare.com/learning/ssl/what-is-sni/) 관련 문제가 발생할 수 있습니다.
* 특정 도구에서 아직 구현되지 않은 방언 기능(예: MySQL 전용 함수 또는 설정)을 요구할 수 있습니다.

네이티브 드라이버를 사용할 수 있다면(예: [DBeaver](/ko/integrations/connectors/sql-clients/dbeaver)) 항상 MySQL 인터페이스보다 네이티브 드라이버를 사용하는 것이 좋습니다. 또한 대부분의 MySQL 언어 클라이언트는 정상적으로 작동할 것으로 예상되지만, 기존 MySQL 쿼리를 사용하는 코드베이스에서 별도의 수정 없이 MySQL 인터페이스로 대체할 수 있다고 보장하지는 않습니다.

네이티브 ClickHouse 드라이버가 없는 특정 도구를 MySQL 인터페이스를 통해 사용하다가 호환성 문제를 발견하면 ClickHouse 리포지토리에 [이슈를 등록해 주십시오](https://github.com/ClickHouse/ClickHouse/issues).

<Note>
  위 BI 도구의 SQL 방언(SQL dialect)을 더 잘 지원하기 위해 ClickHouse의 MySQL 인터페이스는 SELECT 쿼리를 실행할 때 [prefer&#95;column&#95;name&#95;to&#95;alias = 1](/ko/reference/settings/session-settings/prefer#prefer_column_name_to_alias) 설정을 암묵적으로 적용합니다.
  이 동작은 비활성화할 수 없으며, 드문 예외 상황에서는 ClickHouse의 일반 쿼리 인터페이스와 MySQL 쿼리 인터페이스로 전송된 쿼리의 동작이 달라질 수 있습니다.
</Note>

## ClickHouse Cloud에서 여러 MySQL 사용자 생성하기 {#creating-multiple-mysql-users-in-clickhouse-cloud}

기본적으로 `default` 사용자와 동일한 비밀번호를 사용하는 내장 `mysql4<subdomain>` 사용자가 제공됩니다. `<subdomain>` 부분은 ClickHouse Cloud 호스트명의 첫 번째 세그먼트입니다. 이 포맷은 보안 연결을 구현하지만 [TLS 핸드셰이크에서 SNI 정보](https://www.cloudflare.com/learning/ssl/what-is-sni)를 제공하지 않는 도구와 함께 사용하기 위해 필요합니다. 이러한 도구에서는 사용자 이름에 추가 힌트가 없으면 내부 라우팅을 수행할 수 없습니다(MySQL 콘솔 클라이언트가 대표적인 예입니다).

따라서 MySQL 인터페이스에서 사용할 새 사용자를 생성할 때는 `mysql4<subdomain>_<username>` 포맷을 따르는 것을 *강력히 권장*합니다. 여기서 `<subdomain>`은 Cloud 서비스를 식별하기 위한 힌트이며, `<username>`은 임의로 지정하는 접미사입니다.

<Tip>
  ClickHouse Cloud 호스트명이 `foobar.us-east1.aws.clickhouse.cloud`라면 `<subdomain>` 부분은 `foobar`이며, 사용자 정의 MySQL 사용자 이름은 `mysql4foobar_team1`과 같은 형태가 될 수 있습니다.
</Tip>

추가 설정을 적용해야 하는 경우 등에는 MySQL 인터페이스에서 사용할 사용자를 추가로 생성할 수 있습니다.

1. 선택 사항 - 사용자 정의 사용자에게 적용할 [설정 프로파일(Settings Profile)](/ko/reference/statements/create/settings-profile)을 생성합니다. 예를 들어, 이후에 생성할 사용자로 연결할 때 기본으로 적용될 추가 설정을 포함한 `my_custom_profile`을 생성합니다:

   ```sql
   CREATE SETTINGS PROFILE my_custom_profile SETTINGS prefer_column_name_to_alias=1;
   ```

   `prefer_column_name_to_alias`는 예시일 뿐이며, 다른 설정을 사용할 수도 있습니다.

2. `mysql4<subdomain>_<username>` 포맷([위 참조](#creating-multiple-mysql-users-in-clickhouse-cloud))으로 [사용자를 생성](/ko/reference/statements/create/user)합니다. 비밀번호는 이중 SHA1 포맷이어야 합니다. 예시:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$';
   ```

   이 사용자에게 사용자 정의 프로필을 적용하려면 다음과 같이 합니다:

   ```sql
   CREATE USER mysql4foobar_team1 IDENTIFIED WITH double_sha1_password BY 'YourPassword42$' SETTINGS PROFILE 'my_custom_profile';
   ```

   여기서 `my_custom_profile`은 앞서 생성한 프로필의 이름입니다.

3. 새 사용자에게 대상 테이블 또는 데이터베이스를 사용하는 데 필요한 권한을 [부여](/ko/reference/statements/grant)합니다. 예를 들어 `system.query_log`에 대한 액세스 권한만 부여하려면 다음과 같이 합니다:

   ```sql
   GRANT SELECT ON system.query_log TO mysql4foobar_team1;
   ```

4. 생성한 사용자로 MySQL 인터페이스를 통해 ClickHouse Cloud 서비스에 연결합니다.

### ClickHouse Cloud에서 여러 MySQL 사용자 관련 문제 해결 {#troubleshooting-multiple-mysql-users-in-clickhouse-cloud}

새 MySQL 사용자를 생성한 후 MySQL CLI 클라이언트로 연결할 때 다음과 같은 오류가 발생하는 경우:

```sql
ERROR 2013 (HY000): Lost connection to MySQL server at 'reading authorization packet', system error: 54
```

이때 사용자 이름이 [위](#creating-multiple-mysql-users-in-clickhouse-cloud)에서 설명한 `mysql4<subdomain>_<username>` 형식을 따르는지 확인하십시오.

## 자체 관리형 ClickHouse에서 MySQL 인터페이스 활성화 {#enabling-the-mysql-interface-on-self-managed-clickhouse}

서버 설정 파일에 [mysql&#95;port](/ko/reference/settings/server-settings/settings/mysql#mysql_port) 설정을 추가하십시오. 예를 들어 `config.d/` [폴더](/ko/concepts/features/configuration/server-config/configuration-files)에 새 XML 파일을 만들고 해당 파일에서 포트를 정의할 수 있습니다:

```xml
<clickhouse>
    <mysql_port>9004</mysql_port>
</clickhouse>
```

ClickHouse 서버를 시작한 후, 다음과 같이 Listening for MySQL compatibility protocol이 포함된 로그 메시지가 출력되는지 확인하십시오:

```bash
{} <Information> Application: Listening for MySQL compatibility protocol: 127.0.0.1:9004
```

## MySQL을 ClickHouse에 연결하기 {#connect-mysql-to-clickhouse}

다음 명령은 MySQL 클라이언트 `mysql`을 ClickHouse에 연결하는 방법을 보여줍니다.

```bash
mysql --protocol tcp -h [hostname] -u [username] -P [port_number] [database_name]
```

예를 들면 다음과 같습니다:

```bash
$ mysql --protocol tcp -h 127.0.0.1 -u default -P 9004 default
```

연결에 성공했을 때의 출력:

```text
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 4
Server version: 20.2.1.1-ClickHouse

Copyright (c) 2000, 2019, Oracle and/or its affiliates. All rights reserved.

Oracle is a registered trademark of Oracle Corporation and/or its
affiliates. Other names may be trademarks of their respective
owners.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>
```

모든 MySQL 클라이언트와의 호환성을 위해 설정 파일에서 사용자 비밀번호를 [이중 SHA1](/ko/concepts/features/configuration/settings/settings-users#user-namepassword)로 지정할 것을 권장합니다.
사용자 비밀번호를 [SHA256](/ko/reference/functions/regular-functions/hash-functions#SHA256)으로 지정하면 일부 클라이언트(mysqljs 및 이전 버전의 MySQL, MariaDB 명령줄 도구)에서 인증할 수 없습니다.

제한 사항:

* prepared 쿼리(prepared query)는 지원되지 않습니다

* 일부 데이터 타입은 문자열로 전송됩니다

장시간 실행되는 쿼리를 취소하려면 `KILL QUERY connection_id` SQL 문을 사용하십시오(이 SQL 문은 처리 과정에서 `KILL QUERY WHERE query_id = connection_id`로 대체됩니다). 예시:

```bash
$ mysql --protocol tcp -h mysql_server -P 9004 default -u default --password=123 -e "KILL QUERY 123456;"
```
