웹 SQL UI (Play)는 ClickHouse에 내장된 브라우저 기반 쿼리(query) 인터페이스입니다. ClickHouse의 모든 HTTP 포트에서 `/play` 경로로 접근할 수 있습니다(예: `http://localhost:8123/play`). 쿼리를 작성하고 실행하며, 결과(result)를 테이블(table)이나 차트로 확인하고, URL을 복사하여 쿼리를 공유할 수 있습니다.

전체 인터페이스는 `programs/server/play.html`이라는 단일 self-contained 페이지에 포함되어 있으며, 프레임워크나 빌드 단계 없이 ClickHouse 바이너리에서 직접 제공됩니다. 단, 차트 렌더링은 예외입니다. 결과를 처음 차트로 표시할 때 타사 CDN에서 `uPlot` 차트 라이브러리를 지연 로드하므로, 오프라인 환경이나 아웃바운드 트래픽이 제한된 배포 환경에서는 차트를 사용할 수 없습니다.

## 쿼리 탭 {#query-tabs}

탭을 사용하면 하나의 편집기에서 여러 쿼리를 번갈아 다루거나 브라우저 이력에 의존할 필요 없이 여러 쿼리를 나란히 열어 둘 수 있습니다.

각 탭에는 별도의 쿼리 텍스트(query text), 제목, 쿼리 매개변수, 마지막 실행 결과(result)가 있습니다. 연결(connection) 설정(URL, 사용자, 비밀번호)은 모든 탭에 공통으로 적용됩니다.

### 탭 표시줄이 나타나는 시점 {#when-the-tab-bar-appears}

탭 표시줄은 쿼리를 한 번 실행했거나 탭이 2개 이상일 때 나타납니다. 결과가 없는 탭이 하나뿐이면 탭 기능이 도입되기 전의 페이지와 똑같이 표시되므로, 탭 표시줄은 필요할 때까지 보이지 않습니다.

활성 탭은 페이지와 시각적으로 자연스럽게 이어집니다. 활성 탭의 배경은 쿼리별 해시 색상(페이지 배경에 이미 사용되는 색상과 동일)을 따르며, 라이트 테마에서는 위쪽으로 갈수록 채도가 높아지고 다크 테마에서는 위쪽으로 갈수록 밝아지는 그라데이션이 적용됩니다. 비활성 탭은 각 탭의 쿼리 텍스트(query text) 해시에 따라 색조가 정해지므로, 탭마다 색상이 자동으로 구분됩니다.

### 탭 생성, 닫기 및 이름 변경 {#creating-closing-and-renaming-tabs}

* 탭 목록 오른쪽에 있는 `[+]` 버튼을 클릭하면 새 탭이 생성됩니다.
* 탭에 있는 `x` 아이콘을 클릭하면 탭이 닫힙니다.
* 새 탭에는 `Query A`, `Query B`와 같은 순서로 기본 이름이 지정됩니다.
* 활성 탭의 제목을 클릭하면 인라인으로 편집할 수 있으며, 편집 필드는 입력한 텍스트 길이에 맞게 늘어납니다.

### 탭 전환 {#switching-tabs}

* 비활성 탭을 클릭하여 해당 탭으로 전환하십시오.
* 탭 패널 위에서 마우스 휠을 스크롤하여 탭을 전환하십시오. 위로 스크롤하면 왼쪽 탭으로, 아래로 스크롤하면 오른쪽 탭으로 이동합니다(해당 방향에 탭이 있는 경우). 세로 및 가로 방향 휠 스크롤을 모두 사용할 수 있습니다.

탭 표시줄은 가로 스크롤 시 고정됩니다. 페이지를 가로로 스크롤해도 하단의 ClickHouse 로고처럼 왼쪽에 고정되어 있으며, 세로로 스크롤하면 페이지의 다른 콘텐츠와 함께 화면 밖으로 이동합니다.

### 영속화 및 브라우저 이력 {#persistence-and-browser-history}

워크스페이스의 탭, 탭 제목, 활성 탭, 탭 순서, 간략한 결과(result) 스냅샷(snapshot)은 IndexedDB에 영구 저장되며, 페이지를 다시 로드하면 복원됩니다. 영속화는 가능한 범위 내에서 수행됩니다. IndexedDB를 사용할 수 없으면 워크스페이스는 현재 세션(current session)에서만 유지되는 메모리 내 상태로 전환됩니다.

탭은 브라우저의 History API 및 URL과도 연동됩니다.

* 이력 상태에 활성 탭 정보가 포함되므로 브라우저의 뒤로 및 앞으로 버튼으로 탭을 전환할 수 있습니다.
* URL에 `tab=<name>` 매개변수가 추가됩니다. 페이지를 로드하면 URL의 쿼리(query)와 `tab` 매개변수를 저장된 탭과 대조하여 반영합니다. 해당 이름의 탭이 있으면 기존 탭을 재사용하고 그 탭의 쿼리를 URL의 쿼리로 교체합니다. 해당 이름의 탭이 없거나 이름이 지정되지 않았으면 새 탭을 만듭니다. 따라서 저장된 탭을 유지하면서 새 쿼리가 포함된 URL을 열 수 있습니다.

## 노트북 모드 {#notebook-mode}

결과(result) 아래에 표시되는 `[+]` 버튼으로 셀을 추가하면 탭을 노트북으로 전환할 수 있습니다. 노트북은 쿼리 셀과 텍스트 셀이 순서대로 이어진 시퀀스입니다. 노트북 모드는 탭마다 개별적으로 적용됩니다.
자세한 내용은 [웹 UI 노트북 모드](/ko/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/notebook)를 참조하십시오.

### 제한 사항 {#limitations}

쿼리는 다른 탭으로 전환해도 계속 실행됩니다. 쿼리의 진행 상황 및 리소스 미터는 백그라운드에서 계속
누적되며, 탭을 다시 열면 진행 중인 상태를 그대로 이어받습니다. 따라서 미터는 0 근처에서 다시 시작하지 않고
현재 값에서 계속 이어집니다. 단, 탭을 닫거나 뒤로 또는 앞으로 이동하여 다른 이력 엔트리로 넘어가면
쿼리가 중지됩니다.

복원용 스냅샷은 크기가 작은 결과(result)에 대해서만 생성됩니다. 큰 결과(스냅샷 크기 제한 초과)나 이미지 결과는 영구 저장되지 않습니다. 탭을 전환하거나 페이지를 다시 로드하면 탭에 쿼리는 남아 있지만 렌더링된 결과는 사라지며, 쿼리를 다시 실행하면 결과가 다시 생성됩니다. 이는 단일 쿼리 결과뿐만 아니라 &quot;Run all&quot;(다중 쿼리) 실행으로 생성된 통합된 출력에도 동일하게 적용됩니다.
