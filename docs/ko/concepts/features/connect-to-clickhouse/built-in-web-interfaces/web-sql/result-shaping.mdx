내장 웹 SQL UI(`play.html`, 모든 ClickHouse HTTP 포트의 [`/play`](/ko/concepts/features/connect-to-clickhouse/protocols/http) 경로에서 제공)에서는 쿼리를 편집하지 않고도 결과(result)를 컬럼 기준으로 정렬하고, 컬럼 값으로 필터링하며, 페이지 단위로 탐색할 수 있습니다.

이러한 작업은 브라우저에서 처리되지 않습니다. 설정을 변경할 때마다 해당 쿼리 구성 설정(query-construction setting)을 적용하여 쿼리가 다시 실행되며, 서버는 쿼리를 파생 테이블로 감싸고 외부에 `ORDER BY`, `WHERE`, `LIMIT`을 적용하는 방식으로 이를 구체화합니다. 따라서 화면에 표시되는 결과는 현재 페이지에 있던 행(rows)을 재배열한 것이 아니라, 전체 쿼리 결과를 정렬, 필터링하고 페이지로 나눈 결과입니다.

## 정렬(Sorting) {#sorting}

모든 열 머리글(column header)의 오른쪽에는 화살표 두 개가 표시됩니다. ▲는 해당 컬럼을 기준으로 결과(result)를 오름차순으로 정렬하고, ▼는 내림차순으로 정렬합니다. 화살표를 클릭하면 해당 정렬이 활성화되고 쿼리가 다시 실행됩니다. 이미 활성화된 방향의 화살표를 클릭하면 정렬이 해제되고, 반대 방향의 화살표를 클릭하면 그 방향으로 전환됩니다. 화살표는 실제 버튼이므로 키보드 사용자도 Tab 키로 화살표에 이동한 뒤 키보드로 활성화할 수 있으며, 각 화살표는 보조 기술에 자신의 상태를 전달합니다(머리글 자체에는 `aria-sort`가 지정됩니다).

호버가 가능한 포인터(마우스)를 사용하는 기기에서는 머리글에 마우스를 올리거나 화살표에 포커스가 있을 때만 화살표가 표시되므로, 평소에는 화면을 가리지 않습니다. 호버 기능이 없는 터치 기기 및 기타 정밀도가 낮은 포인터 기기에서는 화살표를 바로 탭할 수 있도록 항상 표시됩니다. 정렬에 사용 중인 컬럼은 마우스를 올리지 않아도 두 화살표가 모두 표시됩니다. 하나는 정렬 상태를 한눈에 파악할 수 있도록 하기 위함이고, 다른 하나는 정렬 방향을 반대로 바꾸는 것이 다음에 수행할 가능성이 가장 높은 작업이기 때문입니다.

열 머리글의 모든 아이콘은 어떤 기능을 제어하든 동일한 규칙으로 표시됩니다. 해당 기능이 컬럼에 적용되지 않은 동안에는 흐리게 표시되고, 적용되면 적용 중인 컨트롤 전용 색상(라이트 테마에서는 마젠타, 다크 테마에서는 노란색)으로 표시되며, 이때부터는 마우스를 올리지 않아도 계속 표시됩니다. 흐리게 표시할 때는 투명도를 낮추지 않고 색상만 제거하므로, 컬럼명이나 셀의 색상 코딩 위에서 아이콘이 바래 보이는 일이 없습니다.

### 여러 컬럼으로 정렬하기 {#sorting-by-several-columns}

정렬을 활성화하면 현재 정렬이 대체됩니다. 즉, 이전에 정렬된 컬럼은 비활성화되고 클릭한 컬럼이 유일한 정렬 키가 됩니다. <kbd>Shift</kbd> 키를 누른 채 클릭하면 이미 적용된 정렬 키는 그대로 두고 해당 컬럼을 그 뒤에 추가합니다. 이는 `ORDER BY`가 사용하는 순서와 같습니다. 첫 번째 키가 순서를 결정하고, 이후의 각 키는 앞선 키들의 값이 같을 때 순서를 결정합니다. 정렬 키가 둘 이상이면 활성화된 각 화살표에 해당 컬럼의 정렬 순서가 위 첨자로 함께 표시됩니다(▼¹, ▲², …).

이미 정렬 키로 지정된 컬럼을 <kbd>Shift</kbd> 키를 누른 채 클릭하면 정렬 방향만 바뀌고 정렬 순서는 유지됩니다. 컬럼을 비활성화하면 해당 컬럼만 정렬에서 제외되고 나머지 키는 그대로 유지됩니다.

## 필터링 {#filtering}

### 열 머리글(column header)에서 필터링 {#filtering-from-a-column-header}

모든 열 머리글에는 정렬 화살표 옆에 깔때기 아이콘이 있으며, 정렬 화살표와 같은 방식으로 나타납니다. 이 아이콘을 클릭하면 해당 컬럼에 대한 프레디케이트를 입력할 수 있는 입력란이 열리고, 입력란 바로 오른쪽에 적용 버튼(▶)이 붙어 있습니다. 플레이스홀더에는 컬럼 유형에 맞는 프레디케이트 형태가 예시로 표시됩니다. 숫자 컬럼에는 `> 10`, 문자열 컬럼에는 `LIKE '%test%'`가 표시됩니다. 입력란은 머리글 셀 안에서 열리며, 입력란이 들어갈 수 있도록 셀에 두 번째 줄이 추가됩니다. 이 줄은 필터가 설정된 후 필터가 표시되는 줄과 같으므로, 필터를 표시되는 자리에서 바로 편집할 수 있습니다. 입력한 내용은 컬럼명 뒤에 붙는 부분이므로 `> 10`은 `WHERE column > 10`이 되며, 서버가 이 위치에서 허용하는 표현식이라면 무엇이든 사용할 수 있습니다(예: `BETWEEN 1 AND 5`, `IN (1, 2, 3)`, `IS NOT NULL`, `% 2 = 0`).

적용 버튼이나 <kbd>Enter</kbd>를 누르면 필터가 적용되고 쿼리가 다시 실행됩니다. <kbd>Esc</kbd>를 누르거나 다른 곳을 클릭하거나 Tab 키로 포커스를 옮기면 편집이 취소되고 입력란이 닫힙니다. 필터가 없는 컬럼에서 입력란이 비어 있는 경우처럼 적용할 내용이 없으면 적용 버튼이 비활성화됩니다. 반면 필터가 있는 컬럼에서는 입력란이 비어 있어도 버튼이 활성 상태로 유지됩니다. 입력란을 비운 뒤 적용하면 필터가 제거되기 때문입니다. 여러 컬럼에 설정한 필터는 `AND`로 결합됩니다.

### 셀에서 필터링 {#filtering-from-a-cell}

컬럼이 해당 값에 대한 필터를 지원하면, 셀을 선택할 때 복사 아이콘 옆에 깔때기 아이콘도 함께 표시됩니다. 이 아이콘을 클릭하면 값에 맞는 비교 연산이 제공됩니다.

| 값                                                    | 제공되는 연산                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------- |
| 숫자                                                   | `=`, `!=`, `>`, `<`, `>=`, `<=`                               |
| 날짜 또는 시간(`Date`, `Date32`, `DateTime`, `DateTime64`) | `=`, `!=`, `>`, `<`, `>=`, `<=`                               |
| 100자 이하의 문자열                                         | `=`, `!=`, `contains` — 빈 문자열은 모든 문자열에 포함되므로 `=`와 `!=`만 제공됩니다 |
| `Bool`                                               | `true`, `false` — 이 셀의 값과 비교하는 대신 두 값 자체가 제공됩니다               |
| `Enum`                                               | `=`, `!=` — 정해진 이름 집합에서는 부분 일치가 유용한 필터가 되지 않습니다               |
| `NULL`                                               | `IS NULL`, `IS NOT NULL`                                      |

항목을 선택하면 즉시 적용됩니다. 날짜, 시간, enum은 서버가 렌더링한 텍스트 그대로와 비교되며, ClickHouse는 이 텍스트를 컬럼 자체의 유형으로 다시 파싱합니다(enum은 값의 이름). `contains`는 값에 포함된 `%`와 `_`를 이스케이프 처리한 `LIKE` 패턴으로 변환되므로, 값과 문자 그대로 일치하는 항목을 찾습니다. 값이 위 항목 중 어디에도 해당하지 않는 셀(배열, 튜플, 맵, 긴 텍스트)에는 메뉴가 표시되지 않지만, 해당 컬럼은 헤더 입력란에서 계속 필터링할 수 있습니다.

### 적용 중인 필터 {#the-filter-in-effect}

필터링 중인 컬럼에는 필터가 설정되어 있는 동안 컬럼 이름 아래에 프레디케이트가 표시되므로, 화면에 보이는 행(rows)이 결과(result)의 부분 집합이라는 사실을 놓치지 않습니다. 이때 깔때기 아이콘은 그 옆으로 내려가 헤더의 왼쪽 아래 모서리에 표시됩니다. 프레디케이트를 클릭하면 그 자리에서 입력란이 다시 열립니다. 옆의 ✕를 클릭하면 필터가 제거되며, 빈 입력을 적용해도 필터가 제거됩니다. 두 경우 모두 쿼리가 다시 실행됩니다.

필터는 어디에서 설정했는지와 관계없이 컬럼당 하나만 존재합니다. 셀에서 필터를 설정하면 헤더 입력란에서 설정한 필터가 대체되며, 헤더에는 항상 현재 적용 중인 필터가 표시됩니다.

필터링된 결과가 비어 있으면 (빈 결과에 보통 사용되는 세로 레이아웃 대신) 열 머리글(column header)이 그대로 유지됩니다. 따라서 일치 항목이 없는 필터를 확인하고 다시 제거할 수 있습니다.

## 페이지 나누기 {#pagination}

결과(result)는 일정 한도까지만 표시됩니다. 한도는 1000개 행(rows)이며, 열이 매우 많은 결과는 이보다 적습니다. 결과가 이 한도에서 잘리면 아직 확인할 내용이 더 남아 있는 것이며, 이때 테이블 아래에 페이지 탐색 컨트롤이 나타납니다:

```text
Page: 1 2 …   Per page: 1000
```

페이지 번호를 클릭하면 페이지 크기가 표시 제한으로 설정되고 해당 페이지가 [`page`](/ko/reference/settings/session-settings/other#page) 설정에 지정된 뒤 쿼리가 다시 실행됩니다. 서버는 이 페이지를 그에 해당하는 `OFFSET`으로 변환합니다. 이후 페이지 탐색 컨트롤은 결과가 페이지 단위로 나뉘어 있는 동안 계속 표시됩니다. 각 페이지가 정확히 가득 차서 더 이상 잘린 것처럼 보이지 않더라도 마찬가지입니다.

전체 페이지 수는 알 수 없으므로 표시되지 않습니다. 결과의 행 수를 세려면 쿼리를 한 번 더 실행해야 하기 때문입니다. 페이지 탐색 컨트롤에는 현재 페이지 앞의 10개 페이지, 현재 페이지, 다음 페이지가 차례로 표시되고 그 뒤에 `…`가 표시됩니다. `…`를 클릭하면 원하는 페이지 번호를 입력할 수 있는 입력 필드로 바뀌며, 입력 필드에서 포커스가 벗어나면 입력한 값이 적용됩니다(<kbd>Enter</kbd>를 눌러도 적용됩니다).

다음 페이지는 현재 페이지가 가득 찬 경우에만 제공됩니다. 페이지에 들어갈 수 있는 것보다 적은 행이 반환된 페이지는 결과의 마지막 페이지이므로 그 뒤에는 페이지가 없습니다. (결과 길이가 공교롭게도 페이지 크기의 정확한 배수이면 페이지가 하나 더 제공되며, 이 페이지는 빈 상태로 반환됩니다. 이 경우를 구분하려면 역시 행 수를 세야 하기 때문입니다.)

`Per page`는 한 페이지에 포함되는 행 수를 나타내며, 편집 방법도 같습니다. 값을 클릭한 후 다른 값을 입력하십시오. 이 값은 결과에서 한 번에 표시할 수 있는 수를 초과할 수 없습니다. 페이지가 더 크면 테이블에서 잘려 나갈 행까지 반환되는데, 다음 페이지는 그 행들 다음부터 시작하므로 페이지를 넘기면 표시되지 못한 행이 아무런 알림 없이 건너뛰어집니다. 더 큰 숫자를 입력하면 최댓값으로 적용되고, 이후 그 최댓값이 표시됩니다. 이 값을 변경하면 첫 번째 페이지부터 다시 시작합니다. 크기가 달라지면 각 페이지에 포함되는 행도 달라지기 때문입니다.

정렬이나 필터(filter)를 변경하면 첫 번째 페이지로 돌아갑니다. 두 작업 모두 결과에 포함되는 행이나 그 순서를 바꾸므로, 사용자가 보던 페이지가 더 이상 결과의 같은 부분을 가리키지 않기 때문입니다.

## 적용 방식 {#how-it-is-applied}

구조적 형태(Shape)는 [`order`](/ko/reference/settings/session-settings/other#order), [`filter`](/ko/reference/settings/session-settings/other#filter), [`limit`](/ko/reference/settings/session-settings/other#limit), [`page`](/ko/reference/settings/session-settings/other#page) 쿼리 구성 설정(query-construction setting)으로 전송됩니다. 서버는 이 설정을 쿼리 텍스트가 아닌 구문 분석된 쿼리(parsed query)에 적용하므로, 기존 쿼리가 어떤 형태이든 그대로 결합됩니다. `UNION`, 끝에 있는 `FORMAT` 절, 쿼리 자체의 `ORDER BY`와 `LIMIT`도 모두 정상적으로 동작하며, 편집기의 쿼리는 재작성되지 않습니다.

컬럼 이름(Column Names)은 인용 부호로 감싼 식별자(identifiers)로 전달됩니다. 따라서 이름이 표현식(`count()`)이거나 공백이 포함된 결과(result) 컬럼도 정렬 키나 필터(filter) 키로 사용할 수 있습니다.

## 사용 가능한 경우 {#when-it-is-available}

형태 지정(Shaping)은 해당 설정이 결과 형태를 지정할 수 있는 SQL 문, 즉 `SELECT` 및 `UNION` 쿼리(`WITH` 절이나 `FROM`으로 시작하는 쿼리 포함)에만 제공됩니다. `SHOW`, `DESCRIBE`, `EXISTS`, `EXPLAIN`에는 제공되지 않습니다. 이들 SQL 문도 테이블 형태의 결과를 반환하지만 설정이 적용되지 않으므로, 여기에 컨트롤을 제공하면 실제 행에 반영되지 않는 결과를 약속하는 셈이 됩니다.

구조적 형태(Shape)는 단일 SQL 문의 결과에 적용되므로, 「모두 실행」으로 여러 SQL 문을 실행할 때는 제공되지 않습니다. 이때 각 SQL 문은 서로 다른 컬럼을 가진 별개의 쿼리이기 때문입니다.

첫 페이지의 행이 1개 이하인 결과에도 제공되지 않습니다. 행이 하나뿐이면 어떤 순서로 정렬해도 결과가 같고, 필터(filter)는 해당 행을 유지하거나 제외하는 것밖에 할 수 없으므로, 컨트롤은 같은 행을 얻기 위해 쿼리를 다시 실행하는 것 외에는 아무 역할도 하지 못합니다. 빈 결과에는 제외할 행조차 없습니다. 같은 이유로 이 경우 [색상 코딩](/ko/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/color-coding) 토글도 숨겨집니다. 행이 1개 이하이면 비교할 대상이 없기 때문입니다.

다만 다음 두 가지 단일 행 결과에서는 컨트롤이 유지됩니다. 이 경우 컨트롤이 이전 상태로 되돌아갈 수 있는 유일한 수단이기 때문입니다.

* 이미 정렬 또는 필터링된 결과: 정렬은 되돌릴 수 있어야 하고 필터는 해제할 수 있어야 합니다. 긴 결과가 짧아지는 경우가 바로 필터가 단일 행과 일치할 때이며, 이때 컨트롤까지 없애면 사용자는 필터가 적용된 상태에서 벗어날 수 없게 됩니다.
* 표시 제한에 걸려 잘린 결과: 이는 더 긴 결과의 첫 페이지입니다. 페이지 크기는 테이블이 한 번에 표시할 수 있는 셀 수로 제한되므로, 컬럼이 매우 많은 결과는 단일 행으로 잘릴 수 있습니다. 그 뒤에 이어지는 행이야말로 정렬과 페이징으로 접근해야 하는 대상입니다.

구조적 형태(Shape)는 해당 구조적 형태(Shape)가 만들어진 SQL 문에 종속됩니다. 쿼리를 편집하거나 다중 SQL 문 편집기에서 커서(Cursor)를 다른 SQL 문으로 옮겨 다른 SQL 문을 실행하면, 새 SQL 문에 없을 수도 있는 컬럼에 `ORDER BY`나 `WHERE`를 적용하는 대신 구조적 형태(Shape)가 삭제됩니다.

구조적 형태(Shape)는 해당 SQL 문이 실행된 컨텍스트에도 종속됩니다. 즉, 선택된 데이터베이스, 쿼리를 전송한 서버와 사용자, 쿼리 매개변수의 값이 이에 해당합니다. 이 중 하나라도 바뀌면 같은 텍스트라도 다른 컬럼을 가리키게 됩니다. 데이터베이스를 전환한 후의 `SELECT * FROM events`나 매개변수를 편집한 후의 `SELECT * FROM {tbl:Identifier}`가 그 예입니다. 따라서 이 경우에도 구조적 형태(Shape)가 삭제되며, 다음 실행에서는 가공되지 않은 결과가 반환됩니다.

## 다운로드 및 복사 {#downloading-and-copying}

다운로드 시에는 결과를 생성한 쿼리를 동일한 구조적 형태(Shape)로 다시 실행하므로, 내보낸 파일에는 화면에 표시된 결과(result)와 같은 행(rows)이 같은 순서로 저장됩니다. 복사 시에는 렌더링된 결과를 그대로 사용하므로 복사한 내용 역시 화면의 결과와 일치합니다.

## 영속화 {#persistence}

구조적 형태(Shape)는 페이지 URL(`sort_columns`, `filters`, `page`, `page_size`), 브라우저 이력, 그리고 해당 구조적 형태(Shape)가 속한 셀의 결과 스냅샷에 기록됩니다. 따라서 페이지를 다시 로드하거나, 링크를 공유하거나, 뒤로 가기 및 앞으로 가기로 이동해도 구조적 형태(Shape)가 유지됩니다. 구조적 형태(Shape)는 표시 방식뿐 아니라 어떤 행이 반환되는지도 결정하므로, 쿼리를 자동 실행하는 공유 링크(`run=1`)는 동일한 구조적 형태(Shape)로 쿼리를 다시 실행하여 결과 자체를 재현합니다. URL과 이력 상태를 간결하게 유지하기 위해 활성 구조적 형태(Shape)만 저장되며, 가공되지 않은 결과는 URL이나 이력 상태에 아무것도 추가하지 않습니다.

앞에서 설명한 것처럼, 복원된 결과의 구조적 형태(Shape)는 해당 결과를 생성한 컨텍스트에 계속 묶여 있습니다. 스냅샷에는 행을 생성할 때 사용된 데이터베이스, 연결, 매개변수 값이 기록되므로, 이 중 하나라도 변경한 후 SQL 문을 다시 실행하면 구조적 형태(Shape)는 다른 결과에 적용되지 않고 폐기됩니다.

[색상 코딩 모드](/ko/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/color-coding) 및 [고정 열(Pinned Column)](/ko/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/pinned-columns)과 마찬가지로, 구조적 형태(Shape)는 자신이 적용되는 결과에 속합니다. 즉, 구조적 형태(Shape)는 쿼리 탭에 속하며, [노트북](/ko/concepts/features/connect-to-clickhouse/built-in-web-interfaces/web-sql/notebook) 탭에서는 개별 셀에 속합니다. 따라서 한 결과를 정렬하거나 필터링해도 다른 탭이나 다른 셀의 결과는 변경되거나 다시 실행되지 않으며, 셀의 결과에 구조적 형태(Shape)를 지정하면 해당 셀만 다시 실행됩니다.

## 제한 사항 {#limitations}

* 서버가 적용할 수 없는 구조적 형태(Shape)가 있으면 쿼리가 실패하며, 이 오류는 다른 실패한 쿼리와 동일하게 표시됩니다. 실패한 실행에서는 구조적 형태(Shape)를 해제하는 데 필요한 헤더와 페이지 탐색 컨트롤이 렌더링되지 않으므로, 해당 구조적 형태(Shape)는 삭제됩니다.
* 정렬(sorting)과 필터링은 결과(result)에 표시된 컬럼명으로 컬럼을 식별합니다. 결과에 같은 이름이 두 번 나타날 수 있는데(`SELECT 1 AS x, 2 AS x`, 컬럼 이름(Column Names)이 겹치는 테이블 간의 조인 등), 이러한 컬럼은 이름으로 구분할 수 없으므로 정렬 및 필터 컨트롤이 제공되지 않습니다. 같은 결과에서 이름이 고유한 컬럼은 컨트롤이 그대로 유지됩니다.
* 다중 컬럼 정렬은 <kbd>Shift</kbd> 키가 필요하므로 터치 기기에서는 사용할 수 없습니다. 단, 단일 컬럼 정렬은 사용할 수 있습니다.
* 단일 행 결과의 세로(전치) 레이아웃에는 열 머리글(column header)이 없으므로 컨트롤도 제공되지 않습니다. 이 때문에 사용자가 이미 구조적 형태(Shape)를 적용한 결과는 가로 레이아웃을 유지합니다.
