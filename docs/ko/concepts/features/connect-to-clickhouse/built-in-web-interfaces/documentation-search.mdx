문서 검색 페이지는 내장된 참고 문서를 즉시 검색할 수 있는 작은 self-contained 웹 UI입니다. 모든 ClickHouse HTTP 포트의 `/docs` 경로에서 제공됩니다.

이 페이지를 열려면 아무 ClickHouse HTTP 포트에서나 `/docs`(예: `http://localhost:8123/docs`)로 접속하십시오.

## 기능 {#what-it-does}

이 페이지는 검색어를 입력하는 동안 HTTP를 통해 [`system.documentation`](/ko/reference/system-tables/documentation) 테이블을 쿼리하고, 선택한 엔터티의 Markdown을 렌더링합니다. `system.documentation`을 읽기 때문에 이 테이블이 제공하는 모든 엔터티(함수, 집계 함수(aggregate functions), 테이블 함수(table functions), 테이블 엔진, 데이터베이스 엔진, 데이터 타입, 설정, 포맷, 압축 코덱(compression codecs), 프로파일 이벤트(profile events), 메트릭, 시스템 테이블 자체 등)를 다루며, 항상 실행 중인 서버에 내장된 문서와 일치합니다.

검색 상자에 입력하면 일치 항목이 유형별로 색상이 구분된 목록에 표시되고, 일치 항목을 선택하면 해당 문서가 렌더링됩니다. 렌더링되는 요소는 다음과 같습니다.

* 엔터티 제목 옆의 연필 링크: `system.documentation`의 `source` 컬럼 값을 기반으로 GitHub의 소스 파일을 엽니다.
* [`/play`](/ko/concepts/features/connect-to-clickhouse/protocols/http) UI와 동일한 내장 어휘 분석기(`Lexer.wasm`)를 사용한 코드 블록의 ClickHouse SQL 구문 강조
* [KaTeX](https://katex.org/)를 통한 TeX 수식 렌더링(예: `corr` 페이지의 수식)
* `:::note`/`:::tip`/… 안내 상자, 공유 가능한 링크가 포함된 제목 앵커, 코드 블록에 마우스를 올리면 나타나는 &quot;Copy&quot; 버튼
* 상대 링크 해석: 문서화된 다른 엔터티가 있으면 앱 내 해당 엔터티로, 없으면 `https://clickhouse.com/docs`로 연결되며, &quot;Related&quot; 및 &quot;Alias of&quot; 참조는 앱 내 링크로 변환됩니다.

현재 검색어, 열려 있는 엔터티와 섹션은 URL 프래그먼트에 반영되므로 특정 페이지나 섹션으로 바로 연결되는 링크를 만들 수 있으며, 브라우저의 뒤로/앞으로 이동 시에도 상태가 복원됩니다. 라이트/다크 테마 전환 기능(자동 감지 지원)은 `/play`와 동일하게 동작합니다.

## 연결 {#connecting}

헤더에는 `/play`와 마찬가지로 `URL`, `user`, `password` 입력 필드가 있습니다. 페이지를 ClickHouse에서 제공하는 경우 `URL`의 기본값은 현재 오리진(origin)이며, 페이지를 로컬 파일로 여는 경우 기본값은 `http://localhost:8123/`입니다. 따라서 페이지를 로컬에서 열어 원격 서버에 연결할 수도 있습니다. 연결이 변경되면 교차 링크 이름 캐시가 자동으로 재구축됩니다.

## 자산 {#assets}

페이지가 HTTP로 제공될 때는 Markdown 렌더러([Marked](https://marked.js.org/)), 수식 렌더러(KaTeX 및 관련 글꼴), SQL 어휘 분석기를 비롯한 모든 자산이 ClickHouse 바이너리 자체에서 제공됩니다. ClickHouse HTTP 오리진에서는 타사 CDN을 전혀 로드하지 않습니다. 따라서 이 페이지는 self-contained 방식으로 동작하고 오프라인에서도 작동하며, 페이지에서 다루는 자격 증명과 함께 타사 네트워크 코드가 실행되는 일이 없습니다.

## 보안 고려 사항 {#security}

이 페이지는 헤더에 입력된 자격 증명으로 ClickHouse HTTP 엔드포인트에 쿼리를 전송하므로, HTTP 프로토콜에 적용되는 주의 사항이 여기에도 동일하게 적용됩니다.

* 신뢰할 수 없는 환경에서는 자격 증명을 보호하기 위해 항상 HTTPS로 `/docs`를 제공하십시오.
* HTTP 프로토콜에 대한 액세스를 제한할 때와 같은 방식으로 네트워크 수준(방화벽, 리버스 프록시 또는 `listen_host` 구성)에서 액세스를 제한하십시오.

`system.documentation`에는 서버에 내장된 정적 참고 문서만 포함되어 있으므로, 이 페이지를 통해 사용자 테이블의 데이터가 노출되지 않습니다.
