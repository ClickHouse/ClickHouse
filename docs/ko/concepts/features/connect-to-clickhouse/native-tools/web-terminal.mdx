웹 터미널은 WebSocket을 통해 대화형 `clickhouse-client` 세션을 제공하는 브라우저 기반 인터페이스입니다. 모든 ClickHouse HTTP 포트의 `/webterminal` 경로에서 제공됩니다.

터미널을 열려면 아무 ClickHouse HTTP 포트에서나 `/webterminal`에 접속하십시오(예: `http://localhost:8123/webterminal`).

## 기능 활성화 및 비활성화 {#enabling-the-feature}

`/webterminal` 엔드포인트는 기본적으로 활성화되어 있으며 `enable_webterminal` 서버 설정으로 제어됩니다. 비활성화하려면 이 설정을 `false`로 지정하십시오. 그러면 `/webterminal`에 대한 요청은 HTTP 상태 코드 `403 Forbidden`을 반환합니다.

```xml
<clickhouse>
    <enable_webterminal>false</enable_webterminal>
</clickhouse>
```

<Note>
  `enable_webterminal`은 기존 `allow_experimental_webterminal` 설정을 대체합니다. `enable_webterminal`이 설정되어 있지 않으면 이전 버전과의 호환성을 위해 기존 설정 이름도 계속 적용됩니다.
</Note>

## 인증 {#authentication}

웹 터미널은 HTTP 프로토콜과 동일한 `Session` 및 액세스 제어 검사를 통해 사용자를 인증합니다. 다만 자격 증명은 HTTP 업그레이드 요청이 아닌, 이미 수립된 WebSocket 연결 내에서 인밴드 방식으로 교환됩니다. WebSocket 핸드셰이크가 완료되면 브라우저는 첫 번째 메시지를 JSON으로 전송합니다.

```json
{"type": "auth", "user": "<user>", "password": "<password>"}
```

`user` 필드는 선택 사항입니다. 생략되거나 비어 있으면 사용자 이름은 `default_session_user` [서버 설정](/ko/reference/settings/server-settings/settings)(또는 [조합 가능한 프로토콜](/ko/concepts/features/configuration/server-config/composable-protocols) 구성의 엔드포인트별 재정의 값)으로 폴백하며, 별도로 구성하지 않은 경우 `default`가 사용됩니다. `default_session_user`를 빈 문자열로 설정하면 사용자 이름이 없는 연결은 허용되지 않습니다. 즉, `user`가 생략되었거나 비어 있는 `auth` 메시지는 인증에 실패하고, 서버는 코드 `1008`로 WebSocket을 닫습니다. 또한 서버 구성에서 `session_log` 섹션이 활성화되어 있으면 해당 거부는 [`system.session_log`](/ko/reference/system-tables/session_log)에 `user`가 비어 있는 `LoginFailure` 이벤트로 기록됩니다.

이 방식은 업그레이드 요청에 포함되는 URL 쿼리 매개변수나 `Authorization` header에 자격 증명을 넣지 않기 위한 것입니다. 이러한 위치에 자격 증명을 넣으면 브라우저 이력, 서버 액세스 로그, 리버스 프록시 로그에 남을 수 있습니다. `/webterminal`은 업그레이드 요청의 URL 매개변수, HTTP Basic, `X-ClickHouse-User`/`X-ClickHouse-Key` header를 의도적으로 참조하지 **않습니다**.

자격 증명이 유효하지 않으면 서버는 코드 `1008`로 WebSocket을 닫고, 브라우저 UI는 자격 증명을 다시 요청합니다.

## 세션 구성 {#session}

인증이 완료되면 서버는 의사 터미널에 연결된 `clickhouse-client`를 실행하고 WebSocket을 통해 입출력을 전달합니다. 세션에서는 다음을 비롯한 `clickhouse-client`의 모든 기능을 사용할 수 있습니다.

* 구문 강조.
* 자동 완성.
* 여러 줄 쿼리.
* 명령 이력(세션이 유지되는 동안 서버 측에 저장됨).

터미널은 화면 렌더링에 [xterm.js](https://xtermjs.org/)를 사용합니다. 모든 자산은 ClickHouse 바이너리 자체에서 제공되며, 타사 CDN에서는 어떤 자산도 로드하지 않습니다.

## `/play`와의 통합 {#play-integration}

[`/play`](/ko/concepts/features/connect-to-clickhouse/protocols/http) 웹 SQL UI에는 웹 터미널이 도킹 가능한 패널로 내장되어 있습니다. 사이드바의 터미널 아이콘을 클릭하거나, 쿼리 편집기가 비어 있을 때 `~` 키를 눌러 웹 터미널을 열거나 닫을 수 있습니다. `/play` 페이지는 로드 시점에 `/webterminal`을 사용할 수 있는지 확인하며, 엔드포인트를 사용할 수 없으면(예: `enable_webterminal`이 `false`로 설정된 경우) 터미널 컨트롤을 숨깁니다.

## 문서 웹사이트와의 통합 {#docs-integration}

이 문서 웹사이트에는 동일한 터미널이 페이지 하단의 좁은 개발자 트레이 형태로 내장되어 있습니다. 이 터미널은 [ClickHouse playground](https://play.clickhouse.com)에 읽기 전용 `play` 사용자로 연결되어 있으므로, 어느 페이지에서든 페이지를 벗어나지 않고 예시를 바로 실행해 볼 수 있습니다. 고정된 트레이는 페이지 끝에 그만큼의 공간을 확보하므로 바닥글 컨트롤을 가리지 않습니다. 터미널이 열려 있는 동안에는 문서 페이지가 잠기고 스크롤바가 숨겨집니다. 터미널 위에서 스크롤하면 터미널의 스크롤백 안에서만 스크롤되며, 뒤에 있는 문서 페이지는 움직이지 않습니다. &quot;ClickHouse terminal&quot; 막대를 클릭하거나 `~` 키를 누르면 막대 위로 여백이 있는 패널이 열립니다. 패널을 접으려면 막대를 다시 클릭하거나, 막대의 셰브론을 클릭하거나, `~` 또는 `Escape` 키를 누르거나, 패널의 위쪽 모서리를 아래로 드래그하십시오. 위쪽 모서리를 드래그하여 패널 크기를 조정할 수도 있습니다. `exit` 또는 `Ctrl+D`로 세션을 종료해도 패널이 접힙니다.

패널을 닫아도 세션과 스크롤백은 유지되므로, 터미널을 다시 열면 같은 프롬프트로 돌아갑니다. 세션은 페이지 내에서 유지되므로 문서 페이지 간에 이동해도 그대로 남아 있지만, 브라우저 탭을 다시 로드하면 사라집니다. 다시 로드한 후에는 새 세션과 함께 패널이 다시 나타납니다.

터미널 트레이는 웹사이트의 데스크톱 레이아웃에 포함된 요소이므로, 좁은 뷰포트에서는 사용할 수 없습니다.

## 보안 고려 사항 {#security}

웹 터미널은 ClickHouse HTTP 엔드포인트에서 인증할 수 있는 모든 사용자에게 셸과 유사한 대화형 세션을 제공하므로, HTTP 프로토콜에 적용되는 주의 사항이 여기에도 동일하게 적용됩니다.

* 신뢰할 수 없는 환경에서는 자격 증명과 세션 트래픽을 보호하기 위해 항상 HTTPS를 통해 `/webterminal`을 제공하십시오.
* HTTP 프로토콜에 대한 액세스를 제한할 때와 동일한 방식으로 네트워크 수준(방화벽, 리버스 프록시 또는 `listen_host` 구성)에서 액세스를 제한하십시오.
* 엔드포인트는 교차 출처 WebSocket 하이재킹을 완화하기 위해 `Origin` 헤더를 `Host`와 대조하여 검사합니다. TLS를 외부에서 종료하는 경우 리버스 프록시를 이에 맞게 구성하십시오.
* TLS를 종료하는 리버스 프록시 뒤에서는 브라우저가 `https`를 사용하더라도 ClickHouse로 향하는 업스트림 연결은 일반 `http`이므로, 엄격한 동일 출처 검사로 인해 정상적인 연결이 거부됩니다. 이러한 배포 환경에서는 WebSocket 세션을 열 수 있도록 허용할 전체 출처(origin)를 쉼표로 구분한 목록으로 `webterminal_allowed_origins`를 설정하십시오. 이 설정이 비어 있지 않으면 기본 동일 출처 검사를 대체합니다. 예시: `<webterminal_allowed_origins>https://example.com,https://app.example.com:8443</webterminal_allowed_origins>`.

## 세션 제한 {#session-limits}

각 웹 터미널 세션은 전용 스레드와 의사 터미널에서 내장 `clickhouse-client`를 실행합니다. 따라서 서버는 인증된 사용자의 설정에 따라 다른 인터페이스의 세션과 동일한 제한을 적용합니다.

* [`max_sessions_for_user`](/ko/reference/settings/session-settings/max#max_sessions_for_user)는 사용자의 동시 세션 수를 제한합니다. 제한을 초과하는 세션은 내장 클라이언트가 시작되기 전에 거부되며, 서버는 코드 `1008`로 WebSocket 연결을 종료합니다.
* [`idle_connection_timeout`](/ko/reference/settings/session-settings/other#idle_connection_timeout)은 native protocol과 마찬가지로, 내장 클라이언트가 다음 쿼리를 기다리는 동안 어느 방향으로도 트래픽이 없는 상태가 지정된 시간(초) 동안 지속되면 세션을 종료합니다. 실행 중인 쿼리는 출력이 없더라도 이 타임아웃으로 중단되지 않습니다.
* [`receive_timeout`](/ko/reference/settings/session-settings/receive#receive_timeout)과 [`send_timeout`](/ko/reference/settings/session-settings/send#send_timeout)은 각각 클라이언트에서 WebSocket 프레임을 읽는 데 걸리는 시간과 클라이언트로 데이터를 보내는 데 걸리는 시간을 제한합니다. 값이 `0`이면 타임아웃이 비활성화됩니다.

터미널에서 `SET` 쿼리로 이러한 설정을 변경하면, 쿼리가 완료되고 내장 클라이언트가 프롬프트로 돌아온 후에 변경 사항이 적용됩니다.

이러한 세션도 다른 인터페이스의 연결과 함께 서버 전체의 [`max_connections`](/ko/reference/settings/server-settings/settings/max#max_connections) 제한에 포함됩니다.

핸들러는 RFC 6455에 명시된 WebSocket 프로토콜 준수 요건도 적용합니다. 마스킹되지 않은 클라이언트 프레임, 예약된 연산 코드, 크기 제한을 초과하거나 단편화된 제어 프레임, 예약된 RSV 비트가 감지되면 프로토콜 오류를 나타내는 종료 코드로 연결을 종료합니다.

## 플랫폼 가용성 {#platform}

핸들러는 ClickHouse가 지원하는 모든 플랫폼에서 컴파일됩니다. 내장된 `clickhouse-client` 실행기가 사용하는 의사 터미널 계층은 이식 가능한 POSIX 기본 요소(`posix_openpt`/`grantpt`/`unlockpt`)를 기반으로 구현되며, Linux 전용 코드 경로에서는 thread-safe 함수인 `ptsname_r`을 사용합니다. 엔드포인트를 사용할 수 없으면(예: `enable_webterminal`이 `false`로 설정된 경우) ClickHouse 시작 페이지와 `/play`에 있는 `/webterminal` 링크가 자동으로 숨겨집니다.
