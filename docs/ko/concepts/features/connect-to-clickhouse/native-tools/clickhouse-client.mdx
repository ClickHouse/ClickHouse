ClickHouse는 ClickHouse 서버에서 SQL 쿼리를 직접 실행할 수 있는 네이티브 command-line client를 제공합니다.
이 클라이언트는 interactive mode(실시간 쿼리 실행용)와 배치 모드(스크립트 작성 및 자동화용)를 모두 지원합니다.
쿼리 결과(query results)는 터미널에 표시하거나 파일로 내보낼 수 있으며, Pretty, CSV, JSON 등 모든 ClickHouse 출력 [포맷](/ko/reference/formats/index)을 지원합니다.

클라이언트는 진행 상황 표시줄과 함께 읽은 행 수, 처리된 바이트 수, 쿼리 실행 시간을 표시하여 쿼리 실행(Query Execution) 상황을 실시간으로 보여 줍니다.
또한 [명령줄 옵션](#command-line-options)과 [설정 파일](#configuration_files)을 모두 지원합니다.

## 설치 {#install}

ClickHouse를 다운로드하려면 다음 명령을 실행하십시오.

```bash
curl https://clickhouse.com/ | sh
```

함께 설치하려면 다음 명령을 실행하십시오.

```bash
sudo ./clickhouse install
```

다른 설치 옵션은 [ClickHouse 설치](/ko/get-started/setup/install)를 참조하십시오.

클라이언트와 서버의 버전이 달라도 서로 호환되지만, 이전 버전의 클라이언트에서는 일부 기능을 사용하지 못할 수 있습니다. 클라이언트와 서버는 동일한 버전을 사용하는 것을 권장합니다.

## 실행 {#run}

<Note>
  ClickHouse를 다운로드만 하고 설치하지 않았다면 `clickhouse-client` 대신 `./clickhouse client`를 사용하십시오.
</Note>

ClickHouse 서버에 연결하려면 다음 명령을 실행하십시오:

```bash
$ clickhouse-client --host server

ClickHouse client version 24.12.2.29 (official build).
Connecting to server:9000 as user default.
Connected to ClickHouse server version 24.12.2.

:)
```

필요에 따라 추가 연결 정보를 지정하십시오:

| 옵션                               | 설명                                                                                                                                                                                                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--port <port>`                  | ClickHouse 서버가 연결을 수신하는 포트입니다. 기본 포트는 9440(TLS)과 9000(TLS 미사용)입니다. `--port`와 `--secure`를 모두 지정하지 않으면 두 기본 포트에 동시에 연결을 시도하여 먼저 응답하는 포트를 사용합니다. 따라서 둘 중 한 포트에서만 수신하는 서버라도 다른 포트의 연결 타임아웃을 기다리지 않고 바로 연결됩니다. ClickHouse Client는 HTTP(S)가 아닌 native protocol을 사용한다는 점에 유의하십시오. |
| `-s [ --secure ]`                | TLS 사용 여부입니다(일반적으로 자동 감지됨).                                                                                                                                                                                                                                                |
| `-u [ --user ] <username>`       | 연결에 사용할 데이터베이스 사용자(database user)입니다. 기본값은 `default` 사용자입니다.                                                                                                                                                                                                               |
| `--password <password>`          | 데이터베이스 사용자의 비밀번호입니다. 연결에 사용할 비밀번호는 설정 파일에서 지정할 수도 있습니다. 비밀번호를 지정하지 않으면 클라이언트가 비밀번호 입력을 요청합니다.                                                                                                                                                                              |
| `-c [ --config ] <path-to-file>` | ClickHouse Client 설정 파일이 기본 위치에 있지 않을 때 지정하는 해당 파일의 위치입니다. [설정 파일](#configuration_files)을 참조하십시오.                                                                                                                                                                          |
| `--connection <name>`            | [설정 파일](#connection-credentials)에 미리 구성해 둔 연결 정보의 이름입니다.                                                                                                                                                                                                                   |

전체 명령줄 옵션 목록은 [명령줄 옵션](#command-line-options)을 참조하십시오.

### 설정 파일에 연결 정보 저장하기 {#connection-credentials}

하나 이상의 ClickHouse 서버에 대한 연결 정보를 [설정 파일](#configuration_files)에 저장할 수 있습니다.

포맷은 다음과 같습니다.

```xml
<config>
    <connections_credentials>
        <connection>
            <name>default</name>
            <hostname>hostname</hostname>
            <port>9440</port>
            <secure>1</secure>
            <user>default</user>
            <password>password</password>
            <!-- <history_file></history_file> -->
            <!-- <history_max_entries></history_max_entries> -->
            <!-- <accept-invalid-certificate>false</accept-invalid-certificate> -->
            <!-- <prompt></prompt> -->
        </connection>
    </connections_credentials>
</config>
```

자세한 내용은 [설정 파일 섹션](#configuration_files)을 참조하십시오.

<Note>
  쿼리 구문(query syntax)에 집중할 수 있도록 이후 예시에서는 연결 정보(`--host`, `--port` 등)를 생략합니다. 명령어를 사용할 때는 이 정보를 잊지 말고 추가하십시오.
</Note>

## Interactive mode {#interactive-mode}

### interactive mode 사용하기 {#using-interactive-mode}

ClickHouse를 interactive mode로 실행하려면 다음 명령을 실행하면 됩니다:

```bash
clickhouse-client
```

이 명령을 실행하면 SQL 쿼리를 대화형으로 입력할 수 있는 REPL(Read-Eval-Print Loop)이 열립니다.
연결되면 쿼리를 입력할 수 있는 프롬프트가 표시됩니다.

```bash
ClickHouse client version 25.x.x.x
Connecting to localhost:9000 as user default.
Connected to ClickHouse server version 25.x.x.x

hostname :)
```

interactive mode에서 기본 출력 포맷은 `PrettyCompact`입니다.
쿼리의 `FORMAT` 절이나 `--format` 명령줄 옵션으로 포맷을 변경할 수 있습니다.
Vertical 포맷을 사용하려면 `--vertical`을 사용하거나 쿼리 끝에 `\G`를 지정하십시오.
이 포맷에서는 각 값이 별도의 줄에 출력되므로 와이드 테이블(wide tables)을 조회할 때 편리합니다.

interactive mode에서는 기본적으로 `Enter`를 누르면 입력한 내용이 실행됩니다.
쿼리 끝에 세미콜론을 입력할 필요는 없습니다.

`-m, --multiline` 매개변수를 지정하여 클라이언트를 시작할 수 있습니다.
여러 줄 쿼리를 입력하려면 줄 바꿈 앞에 백슬래시 `\`를 입력하십시오.
`Enter`를 누르면 쿼리의 다음 줄을 입력하라는 메시지가 표시됩니다.
쿼리를 실행하려면 쿼리 끝에 세미콜론을 입력한 뒤 `Enter`를 누르십시오.

ClickHouse Client는 `replxx`(`readline`과 유사)를 기반으로 하므로 익숙한 키보드 단축키를 그대로 사용할 수 있으며 입력 이력도 저장됩니다.
이력은 기본적으로 `~/.clickhouse-client-history`에 기록됩니다.

클라이언트를 종료하려면 `Ctrl+D`를 누르거나, 쿼리 대신 다음 중 하나를 입력하십시오.

* `exit` 또는 `exit;`
* `quit` 또는 `quit;`
* `q`, `Q` 또는 `:q`
* `logout` 또는 `logout;`

### 도움말 보기 {#getting-help}

클라이언트를 벗어나지 않고도 함수, 테이블 엔진, 데이터 타입, 포맷, 설정 등 시스템의 모든 구성 요소에 대한 문서를 조회할 수 있습니다. `help` 뒤에 이름을 입력하십시오(동등한 형식인 `/help`, `man`, `/man`도 사용할 수 있습니다):

```text
help domainWithoutWWW
```

조회(lookup)는 대소문자를 구분하지 않으며 [`system.documentation`](/ko/reference/system-tables/documentation) 테이블을 쿼리합니다. 일치하는 문서는 Markdown 형식으로 렌더링되어 터미널에 표시되며, 굵게/기울임꼴 텍스트, 테이블, 구문 강조된 코드 블록이 함께 표시됩니다. 여러 구성 요소가 같은 이름을 사용하는 경우(예: 함수이면서 테이블 엔진이기도 한 `file`) 해당하는 항목이 모두 표시됩니다.

정확히 일치하는 항목이 없으면 클라이언트는 유사한 이름(오타 허용)과 해당 단어가 문서에 언급된 구성 요소를 나열합니다:

```text
help maxx_threads
```

`help`만 입력하면 간단한 사용법 요약이 출력됩니다.

### 명령어 {#slash-commands}

클라이언트는 `/`로 시작하는 몇 가지 명령어를 서버로 보내지 않고 직접 실행합니다.

| 명령어                                                   | 설명                                                                                       |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `/help <name>`, `/man <name>`                         | `<name>`의 문서를 표시합니다. 위의 `help`와 동일합니다                                                    |
| `/clear`                                              | 터미널 화면을 지웁니다                                                                             |
| `/dialect <name>`, `/lang <name>`, `/language <name>` | SQL 방언(SQL dialect)을 전환하거나, 인수 없이 입력하면 현재 방언을 출력합니다([아래](#switching-the-sql-dialect) 참조) |

입력 맨 앞에 `/`를 입력하면 명령어 목록이 [힌트](#command-line-options-formatting)로 표시되며, 이름을 더 입력할수록 목록이 좁혀집니다. `Tab`을 누르면 입력 중인 명령어가 자동 완성되며, 힌트가 비활성화된 경우에도 이 방식으로 명령어를 완성할 수 있습니다. `/`만 단독으로 입력하면 명령어로 처리되지 않으며, Oracle SQL*Plus와 마찬가지로 마지막 입력을 다시 실행합니다. 명령어 이름을 잘못 입력하면 쿼리로 실행되지 않고, 잘못된 명령어라는 메시지와 함께 의도했을 가능성이 있는 명령어를 제안합니다.

```text
:) /hepl

Exception on client:
Code: 36. DB::Exception: Unknown command `/hepl`. Maybe you meant: ['/help']. Type `/` at the beginning of the line to see all the commands. (BAD_ARGUMENTS)
```

### SQL 방언(SQL dialect) 전환하기 {#switching-the-sql-dialect}

클라이언트는 여러 방언으로 쿼리를 파싱할 수 있습니다([`dialect`](/ko/reference/settings/session-settings/other#dialect) 설정 참고). 방언을 전환하려면 `/dialect` 뒤에 방언 이름을 입력하십시오. 동등한 형식인 `/language`나 `/lang`도 사용할 수 있습니다.

```text
/dialect polyglot
```

이 명령은 `SET dialect = 'polyglot'`와 동등하지만, `SET` 쿼리와 달리 현재 방언으로 파싱될 필요가 없습니다. 따라서 현재 방언으로 해당 쿼리를 표현할 수 없는 경우(예: PromQL에는 `SET` 문이 없음)에도 작동합니다. 기본값이 아닌 방언이 활성화되어 있으면 프롬프트의 서버 표시 이름 뒤에 해당 방언이 표시됩니다:

```text
clickhouse-cloud (polyglot) :)
```

사용자 정의 프롬프트(`--prompt` 옵션 참조)에 `{display_name}` 플레이스홀더를 반드시 포함할 필요는 없습니다. 플레이스홀더가 없으면 방언이 프롬프트 끝에 추가됩니다.

`/dialect`만 단독으로 입력하면 현재 방언이 출력됩니다.

이 명령은 interactive mode에서만 인식됩니다. 비대화형 스크립트는 처음부터 끝까지 SQL로 파싱되며, 이때 방언은 `--dialect` 옵션이나 `SET dialect = ...` SQL 문으로 지정합니다. `clickhouse-local`의 쿼리 텍스트(query text) 전체가 이 명령으로만 이루어진 경우(예: `clickhouse-local -q '/dialect kusto'`), 이 명령은 interactive mode에서만 사용할 수 있다는 메시지와 함께 거부됩니다. 더 긴 스크립트 안에서는 이 명령이 아예 인식되지 않으며, 다른 텍스트와 마찬가지로 스크립트의 일부로 파싱됩니다.

### 쿼리 처리(query processing) 정보 {#processing-info}

쿼리를 처리하는 동안 클라이언트는 다음 정보를 표시합니다.

1. 진행 상황: 기본적으로 초당 최대 10회까지 갱신됩니다.
   빠르게 끝나는 쿼리는 진행 상황이 표시되기 전에 완료될 수 있습니다.
2. 디버깅을 위해 파싱 후 서식이 지정된 쿼리.
3. 지정된 형식으로 출력된 결과(result).
4. 결과의 행 수, 경과 시간, 평균 쿼리 처리 속도.
   모든 데이터 양은 비압축 데이터를 기준으로 합니다.

오래 실행되는 쿼리는 `Ctrl+C`를 눌러 취소할 수 있습니다.
다만 서버가 요청을 중단할 때까지 잠시 기다려야 합니다.
일부 스테이지에서는 쿼리를 취소할 수 없습니다.
기다리지 않고 `Ctrl+C`를 한 번 더 누르면 클라이언트가 종료됩니다.

ClickHouse Client에서는 쿼리에 외부 데이터(외부 임시 테이블)를 전달할 수 있습니다.
자세한 내용은 [쿼리 처리를 위한 외부 데이터](/ko/reference/engines/table-engines/special/external-data) 섹션을 참고하십시오.

### 별칭(Aliases) {#cli_aliases}

REPL 내에서 다음 별칭을 사용할 수 있습니다.

* `\l` - `SHOW DATABASES`
* `\d` - `SHOW TABLES`
* `\d <TABLE>` - `DESCRIBE TABLE <TABLE>`
* `\c <DATABASE>` - `USE <DATABASE>`
* `.` - 마지막 쿼리 반복

`\d FROM system` 또는 `\d LIKE 'hits%'`처럼 `\d`의 인수가 테이블 이름을 지정하지 않고 `SHOW TABLES` 쿼리를 이어 가는 경우에는 테이블 목록 조회 동작이 그대로 유지됩니다. 이러한 절(clauses) 중 하나와 이름이 같은 테이블은 인용 부호로 감싸야 합니다: `` \d `format` ``.

### 키보드 단축키 {#keyboard_shortcuts}

* `Alt (Option) + Shift + e` - 현재 쿼리(query)를 편집기에서 엽니다. 환경 변수 `EDITOR`로 사용할 편집기를 지정할 수 있습니다. 기본적으로 `vim`을 사용합니다.
* `Alt (Option) + #` - 현재 줄을 주석 처리합니다.
* `Ctrl + r` - 이력에서 퍼지 검색을 수행합니다.

사용 가능한 모든 키보드 단축키는 [replxx](https://github.com/AmokHuginnsson/replxx/blob/1f149bf/src/replxx_impl.cxx#L262)에서 확인할 수 있습니다.

<Tip>
  MacOS에서 메타 키(Option)가 올바르게 작동하도록 하려면 다음과 같이 구성하십시오.

  iTerm2: Preferences -&gt; Profile -&gt; Keys -&gt; Left Option key로 이동하여 Esc+를 클릭하십시오.
</Tip>

### Vim 모드 {#vim-mode}

`--vim` 매개변수를 지정하여 클라이언트를 시작하면 `vim` 방식의 키로 쿼리를 편집할 수 있습니다.
입력은 삽입 모드에서 시작하며, `Esc`를 누르면 일반 모드로 전환됩니다. 일반 모드에서는 이동 명령(`h`, `j`, `k`, `l`, `w`, `b`, `e`, `0`, `$`, `f`, `t`, `%`, `gg`, `G`, ...), 반복 횟수를 함께 쓸 수 있는 연산자(operators)(`d`, `c`)와 텍스트 객체(`iw`, `aw`, `i(`, `a(`, ...), 그리고 `x`, `r`, `s`, `o`, `A`, `I`, `D`, `C` 등의 명령어를 사용할 수 있습니다.
vim 모드에서 `Enter`를 누르면 삽입 모드에서는 새 줄이 삽입되고, 일반 모드에서는 다음 줄로 이동합니다. 쿼리를 제출하려면 `Ctrl + j`를 누르십시오.
일반 모드에서 `v`를 누르면 현재 쿼리가 편집기에서 열립니다(내장 클라이언트에서는 사용할 수 없습니다).
이력 검색 단축키(`Ctrl + r`, `Ctrl + s`, `Ctrl + t`, `Alt + r`)와 `Alt + #`도 일반 모드에서 동일하게 동작합니다.

## 배치 모드 {#batch-mode}

### 배치 모드 사용 {#using-batch-mode}

ClickHouse Client를 대화형으로 사용하는 대신 배치 모드로 실행할 수 있습니다.
배치 모드에서는 ClickHouse가 단일 쿼리(query)를 실행한 후 즉시 종료되며, 대화형 프롬프트나 입력을 반복해서 받는 루프가 없습니다.

다음과 같이 단일 쿼리를 지정할 수 있습니다:

```bash
$ clickhouse-client "SELECT sum(number) FROM numbers(10)"
45
```

`--query` 명령줄 옵션을 사용할 수도 있습니다.

```bash
$ clickhouse-client --query "SELECT uniq(number) FROM numbers(10)"
10
```

`stdin`으로 쿼리(query)를 전달할 수 있습니다:

```bash
$ echo "SELECT avg(number) FROM numbers(10)" | clickhouse-client
4.5
```

`messages` 테이블이 있다고 가정하면, 명령줄에서 데이터를 삽입할 수도 있습니다:

```bash
$ echo "Hello\nGoodbye" | clickhouse-client --query "INSERT INTO messages FORMAT CSV"
```

`--query`를 지정하면 모든 입력이 줄 바꿈 다음에 요청 끝에 추가됩니다.

### 원격 ClickHouse 서비스에 CSV 파일 삽입하기 {#cloud-example}

이 예시에서는 샘플 데이터셋 CSV 파일인 `cell_towers.csv`를 `default` 데이터베이스에 있는 기존 테이블 `cell_towers`에 삽입합니다.

```bash
clickhouse-client --host HOSTNAME.clickhouse.cloud \
  --port 9440 \
  --user default \
  --password PASSWORD \
  --query "INSERT INTO cell_towers FORMAT CSVWithNames" \
  < cell_towers.csv
```

### 명령줄에서 데이터 삽입(inserting) 예시 {#more-examples}

명령줄에서 데이터를 삽입하는 방법은 여러 가지입니다.
아래 예시는 배치 모드를 사용하여 CSV 데이터 2개 행(rows)을 ClickHouse 테이블(table)에 삽입하는 방법을 보여 줍니다:

```bash
echo -ne "1, 'some text', '2016-08-14 00:00:00'\n2, 'some more text', '2016-08-14 00:00:01'" | \
  clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
```

아래 예시에서 `cat <<_EOF`는 Heredoc을 시작합니다. 이 Heredoc은 `_EOF`가 다시 나타날 때까지 모든 내용을 읽은 다음 출력합니다:

```bash
cat <<_EOF | clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
3, 'some text', '2016-08-14 00:00:00'
4, 'some more text', '2016-08-14 00:00:01'
_EOF
```

아래 예시에서는 `cat`을 사용하여 file.csv의 내용을 stdout으로 출력한 뒤, 파이프로 `clickhouse-client`에 입력으로 전달합니다.

```bash
cat file.csv | clickhouse-client --database=test --query="INSERT INTO test FORMAT CSV";
```

배치 모드에서 기본 데이터 [포맷](/ko/reference/formats/index)은 `TabSeparated`입니다.
위 예시와 같이 쿼리의 `FORMAT` 절에서 포맷을 지정할 수 있습니다.

## 매개변수가 있는 쿼리 {#cli-queries-with-parameters}

쿼리에 매개변수를 지정하고 명령줄 옵션으로 값을 전달할 수 있습니다.
이렇게 하면 클라이언트 측에서 특정 동적 값을 넣어 쿼리 서식을 지정할 필요가 없습니다.
예시:

```bash
$ clickhouse-client --param_parName="[1, 2]" --query "SELECT {parName: Array(UInt16)}"
[1,2]
```

[대화형 세션](#interactive-mode)에서도 매개변수를 설정할 수 있습니다.

```text highlight={4,14}
$ clickhouse-client

:) SET param_parName='[1, 2]';

SET param_parName = '[1, 2]'

Query id: 7ac1f84e-e89a-4eeb-a4bb-d24b8f9fd977

Ok.

0 rows in set. Elapsed: 0.000 sec.

:) SELECT {parName:Array(UInt16)}

SELECT {parName:Array(UInt16)}

Query id: 0358a729-7bbe-4191-bb48-29b063c548a7

   ┌─_CAST([1, 2]⋯y(UInt16)')─┐
1. │ [1,2]                    │
   └──────────────────────────┘

1 row in set. Elapsed: 0.006 sec.
```

### 쿼리 구문(query syntax) {#cli-queries-with-parameters-syntax}

쿼리에서 명령줄 매개변수로 지정할 값을 다음 형식에 맞게 중괄호로 묶으십시오:

```sql
{<name>:<data type>}
```

| 매개변수(Parameter) | 설명                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | 플레이스홀더의 식별자입니다. 해당 명령줄 옵션은 `--param_<name> = value`입니다.                                                                                                                                                                                                                                                                                                                                     |
| `data type`     | 매개변수의 [데이터 타입(data type)](/ko/reference/data-types/index)입니다. <br /><br />예를 들어, `(integer, ('string', integer))`와 같은 데이터 구조는 `Tuple(UInt8, Tuple(String, UInt8))` 데이터 타입으로 표현할 수 있습니다(다른 [정수(integer)](/ko/reference/data-types/int-uint) 타입도 사용할 수 있습니다). <br /><br />테이블 이름(table name), 데이터베이스 이름(Database name), 컬럼 이름(Column Names)도 매개변수로 전달할 수 있습니다. 이때는 데이터 타입으로 `Identifier`를 사용해야 합니다. |

### 예시 {#cli-queries-with-parameters-examples}

```bash
$ clickhouse-client --param_tuple_in_tuple="(10, ('dt', 10))" \
    --query "SELECT * FROM table WHERE val = {tuple_in_tuple:Tuple(UInt8, Tuple(String, UInt8))}"

$ clickhouse-client --param_tbl="numbers" --param_db="system" --param_col="number" --param_alias="top_ten" \
    --query "SELECT {col:Identifier} as {alias:Identifier} FROM {db:Identifier}.{tbl:Identifier} LIMIT 10"
```

## AI 기반 SQL 생성 {#ai-sql-generation}

ClickHouse Client에는 자연어 설명을 바탕으로 SQL 쿼리를 생성하는 AI 지원 기능이 내장되어 있습니다. 이 기능을 사용하면 SQL을 깊이 알지 못해도 복잡한 쿼리를 작성할 수 있습니다.

`OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY` 환경 변수 중 하나가 설정되어 있으면 별도 설정 없이 AI 지원 기능을 바로 사용할 수 있습니다. 고급 구성은 [구성](#ai-sql-generation-configuration) 섹션을 참조하십시오.

### 사용 방법 {#ai-sql-generation-usage}

AI SQL 생성 기능을 사용하려면 자연어 쿼리 앞에 `??`를 붙이십시오.

```bash
:) ?? show all users who made purchases in the last 30 days
```

AI는 다음 작업을 수행합니다:

1. 데이터베이스 스키마(database schema)를 자동으로 탐색합니다
2. 확인된 테이블(tables)과 컬럼(columns)을 바탕으로 적절한 SQL을 생성합니다
3. 생성된 쿼리(query)를 즉시 실행합니다

### 예시 {#ai-sql-generation-example}

```bash
:) ?? count orders by product category

Starting AI SQL generation with schema discovery...
──────────────────────────────────────────────────

🔍 list_databases
   ➜ system, default, sales_db

🔍 list_tables_in_database
   database: sales_db
   ➜ orders, products, categories

🔍 get_schema_for_table
   database: sales_db
   table: orders
   ➜ CREATE TABLE orders (order_id UInt64, product_id UInt64, quantity UInt32, ...)

✨ SQL query generated successfully!
──────────────────────────────────────────────────

SELECT
    c.name AS category,
    COUNT(DISTINCT o.order_id) AS order_count
FROM sales_db.orders o
JOIN sales_db.products p ON o.product_id = p.product_id
JOIN sales_db.categories c ON p.category_id = c.category_id
GROUP BY c.name
ORDER BY order_count DESC
```

### 구성 {#ai-sql-generation-configuration}

AI SQL 생성을 사용하려면 ClickHouse Client 설정 파일에서 AI 프로바이더를 구성해야 합니다. OpenAI, Anthropic 또는 OpenAI 호환 API 서비스 중 원하는 것을 사용할 수 있습니다.

#### 환경 변수 기반 폴백 {#ai-sql-generation-fallback}

구성 파일에 AI 설정이 없으면 ClickHouse Client는 자동으로 다음 순서에 따라 환경 변수를 사용하려고 시도합니다.

1. 먼저 `OPENAI_API_KEY` 환경 변수가 있는지 확인합니다
2. 없으면 `ANTHROPIC_API_KEY` 환경 변수가 있는지 확인합니다
3. 둘 다 없으면 AI 기능이 비활성화됩니다

이 방식으로 설정 파일 없이도 빠르게 설정할 수 있습니다.

```bash
# Using OpenAI
export OPENAI_API_KEY=your-openai-key
clickhouse-client

# Using Anthropic
export ANTHROPIC_API_KEY=your-anthropic-key
clickhouse-client
```

#### 설정 파일 {#ai-sql-generation-configuration-file}

AI 설정을 더 세밀하게 제어하려면 다음 위치의 ClickHouse Client 설정 파일에서 설정을 구성하십시오.

* `$XDG_CONFIG_HOME/clickhouse/config.xml` (`XDG_CONFIG_HOME`이 설정되지 않은 경우 `~/.config/clickhouse/config.xml`) (XML 포맷)
* `$XDG_CONFIG_HOME/clickhouse/config.yaml` (`XDG_CONFIG_HOME`이 설정되지 않은 경우 `~/.config/clickhouse/config.yaml`) (YAML 포맷)
* `~/.clickhouse-client/config.xml` (XML 포맷, 이전 위치)
* `~/.clickhouse-client/config.yaml` (YAML 포맷, 이전 위치)
* 또는 `--config-file`로 다른 위치를 지정하십시오.

### 매개변수 {#ai-sql-generation-parameters}

<Accordion title="필수 매개변수">
  * `api_key` - AI 서비스의 API Key입니다. 다음 환경 변수로 설정한 경우 생략할 수 있습니다:
    * OpenAI: `OPENAI_API_KEY`
    * Anthropic: `ANTHROPIC_API_KEY`
    * 참고: 구성 파일에 설정된 API Key가 환경 변수보다 우선합니다
  * `provider` - AI 프로바이더: `openai` 또는 `anthropic`
    * 생략하면 사용 가능한 환경 변수를 기반으로 자동 폴백을 수행합니다
</Accordion>

<Accordion title="모델 구성">
  * `model` - 사용할 모델입니다(기본값: provider에 따라 다름)
    * OpenAI: `gpt-4o`, `gpt-4`, `gpt-3.5-turbo` 등
    * Anthropic: `claude-3-5-sonnet-20241022`, `claude-3-opus-20240229` 등
    * OpenRouter: `anthropic/claude-3.5-sonnet`과 같은 OpenRouter의 모델 이름 형식을 사용하십시오
</Accordion>

<Accordion title="연결 설정">
  * `base_url` - OpenAI 호환 서비스에 사용할 사용자 지정 API 엔드포인트입니다(선택 사항)
  * `timeout_seconds` - 초 단위의 요청 타임아웃입니다(기본값: `30`)
</Accordion>

<Accordion title="스키마 탐색">
  * `enable_schema_access` - AI가 데이터베이스 스키마(schemas)를 탐색할 수 있도록 허용합니다(기본값: `true`)
  * `max_steps` - 스키마(schema) 탐색 시 도구를 호출할 수 있는 최대 단계 수입니다(기본값: `10`)
</Accordion>

<Accordion title="생성 매개변수">
  * `temperature` - 출력의 무작위성을 제어합니다. 0.0은 결정적인 출력을, 1.0은 창의적인 출력을 생성합니다. 일부 모델은 이 매개변수를 허용하지 않으므로 기본적으로 생략되며, 명시적으로 설정한 경우에만 모델에 전송됩니다.
  * `max_tokens` - 토큰 단위의 최대 응답 길이입니다(기본값: `1000`)
  * `system_prompt` - AI에 제공할 사용자 지정 지침입니다(선택 사항)
</Accordion>

### 작동 방식 {#ai-sql-generation-how-it-works}

AI SQL 생성기는 다음 단계에 따라 작동합니다:

1. **스키마 탐색(schema discovery)**

AI는 내장 도구를 사용하여 데이터베이스를 탐색합니다

* 사용 가능한 데이터베이스 목록을 조회합니다
* 관련 데이터베이스에서 테이블(tables)을 찾습니다
* `CREATE TABLE` SQL 문을 통해 테이블 구조(table structure)를 확인합니다

2. **쿼리 생성**

AI는 탐색한 스키마(schema)를 바탕으로 다음 조건을 충족하는 SQL을 생성합니다:

* 자연어로 표현한 의도에 부합합니다
* 올바른 테이블 및 컬럼 이름(Column Names)을 사용합니다
* 적절한 조인(join)과 집계(aggregations)를 적용합니다

3. **실행**

생성된 SQL이 자동으로 실행되고 결과(result)가 표시됩니다

### 제한 사항 {#ai-sql-generation-limitations}

* 활성 인터넷 연결이 필요합니다
* API 사용 시 AI 프로바이더의 요청 빈도 제한이 적용되며 비용이 발생합니다
* 복잡한 쿼리(query)는 여러 차례 수정해야 할 수 있습니다
* AI는 스키마(schema) 정보에만 읽기 전용으로 액세스할 수 있으며, 실제 데이터에는 액세스할 수 없습니다

### 보안 {#ai-sql-generation-security}

* API 키는 ClickHouse 서버로 절대 전송되지 않습니다
* AI는 스키마(schema) 정보(테이블/컬럼 이름(Column Names) 및 타입)만 확인하며, 실제 데이터는 확인하지 않습니다
* 생성된 모든 쿼리는 기존 데이터베이스 권한을 준수합니다

## 연결 문자열(Connection String) {#connection_string}

### 사용법 {#connection-string-usage}

ClickHouse Client는 [MongoDB](https://www.mongodb.com/docs/manual/reference/connection-string/), [PostgreSQL](https://www.postgresql.org/docs/current/libpq-connect.html#LIBPQ-CONNSTRING), [MySQL](https://dev.mysql.com/doc/refman/8.0/en/connecting-using-uri-or-key-value-pairs.html#connecting-using-uri)와 비슷한 방식으로 연결 문자열(Connection String)을 사용해 ClickHouse 서버에 연결할 수도 있습니다. 구문은 다음과 같습니다:

```text
clickhouse:[//[user[:password]@][hosts_and_ports]][/database][?query_parameters]
```

| 구성 요소(모두 선택 사항)    | 설명                                                                                                              | 기본값              |
| ------------------ | --------------------------------------------------------------------------------------------------------------- | ---------------- |
| `user`             | 데이터베이스(database) 사용자 이름입니다.                                                                                     | `default`        |
| `password`         | 데이터베이스 사용자(database user)의 비밀번호입니다. `:`이 지정되어 있고 비밀번호가 비어 있으면 클라이언트가 사용자에게 비밀번호 입력을 요청합니다.                      | -                |
| `hosts_and_ports`  | `host[:port] [, host:[port]], ...` 형식의 호스트 및 포트 목록입니다. 포트는 생략할 수 있습니다.                                          | `localhost:9000` |
| `database`         | 데이터베이스 이름(Database name)입니다.                                                                                    | `default`        |
| `query_parameters` | `param1=value1[,&param2=value2], ...` 형식의 key-value 쌍 목록입니다. 일부 매개변수는 값을 지정하지 않아도 됩니다. 매개변수 이름과 값은 대소문자를 구분합니다. | -                |

### 참고 {#connection-string-notes}

연결 문자열(Connection String)에 사용자 이름, 비밀번호 또는 데이터베이스(database)를 지정한 경우, `--user`, `--password` 또는 `--database`로 같은 항목을 지정할 수 없습니다(반대의 경우도 마찬가지입니다).

호스트 부분에는 호스트명, IPv4 주소 또는 IPv6 주소를 사용할 수 있습니다.
IPv6 주소는 `[]`로 감싸야 합니다:

```text
clickhouse://[2001:db8::1234]
```

연결 문자열(Connection Strings)에는 여러 호스트를 지정할 수 있습니다.
ClickHouse Client는 이 호스트에 순서대로(왼쪽에서 오른쪽으로) 연결을 시도합니다.
연결이 설정되면 나머지 호스트에는 연결을 시도하지 않습니다.

연결 문자열(Connection String)은 `clickhouse-client`의 첫 번째 인수로 지정해야 합니다.
연결 문자열은 `--host`와 `--port`를 제외한 다른 [명령줄 옵션](#command-line-options)과 개수 제한 없이 함께 사용할 수 있습니다.

`query_parameters`에는 다음 명령줄 옵션을 사용할 수 있습니다.

| 키(Key)            | 설명                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------ |
| `secure` (또는 `s`) | 지정하면 클라이언트가 보안 연결(TLS)을 통해 서버에 연결합니다. [명령줄 옵션](#command-line-options)의 `--secure`를 참조하십시오. |

**퍼센트 인코딩**

다음 매개변수에 포함된 US ASCII 범위 밖의 문자, 공백 및 특수 문자는 [percent-encoded](https://en.wikipedia.org/wiki/URL_encoding) 형식으로 인코딩해야 합니다.

* `user`
* `password`
* `hosts`
* `database`
* `query parameters`

### 예시 {#connection_string_examples}

`localhost`의 9000 포트에 연결하고 `SELECT 1` 쿼리를 실행합니다.

```bash
clickhouse-client clickhouse://localhost:9000 --query "SELECT 1"
```

사용자 이름 `john`, 비밀번호 `secret`, 호스트 `127.0.0.1`, 포트 `9000`을 사용하여 `localhost`에 연결합니다.

```bash
clickhouse-client clickhouse://john:secret@127.0.0.1:9000
```

`default` 사용자로 `localhost`에 연결합니다. 호스트의 IPv6 주소는 `[::1]`이고 포트는 `9000`입니다.

```bash
clickhouse-client clickhouse://[::1]:9000
```

여러 줄 모드로 `localhost`의 9000번 포트에 연결합니다.

```bash
clickhouse-client clickhouse://localhost:9000 '-m'
```

`default` 사용자로 `localhost`의 9000 포트에 연결하십시오.

```bash
clickhouse-client clickhouse://default@localhost:9000

# equivalent to:
clickhouse-client clickhouse://localhost:9000 --user default
```

`localhost`의 9000번 포트에 연결하고 `my_database`를 기본 데이터베이스(database)로 사용합니다.

```bash
clickhouse-client clickhouse://localhost:9000/my_database

# equivalent to:
clickhouse-client clickhouse://localhost:9000 --database my_database
```

`localhost`의 포트 9000에 연결하며, 연결 문자열(Connection String)에 지정된 `my_database`를 기본 데이터베이스로 사용하고 축약형 매개변수 `s`로 보안 연결을 설정합니다.

```bash
clickhouse-client clickhouse://localhost/my_database?s

# equivalent to:
clickhouse-client clickhouse://localhost/my_database -s
```

기본 포트, default 사용자 및 기본 데이터베이스(Default Database)를 사용하여 기본 호스트에 연결하십시오.

```bash
clickhouse-client clickhouse:
```

기본 포트를 사용하여 기본 호스트에 `my_user` 사용자로 비밀번호 없이 연결합니다.

```bash
clickhouse-client clickhouse://my_user@

# Using a blank password between : and @ means to asking the user to enter the password before starting the connection.
clickhouse-client clickhouse://my_user:@
```

이메일 주소를 사용자 이름으로 사용하여 `localhost`에 연결하십시오. `@` 기호는 `%40`으로 퍼센트 인코딩됩니다.

```bash
clickhouse-client clickhouse://some_user%40some_mail.com@localhost:9000
```

두 호스트 `192.168.1.15`, `192.168.1.25` 중 하나에 연결하십시오.

```bash
clickhouse-client clickhouse://192.168.1.15,192.168.1.25
```

## 쿼리 ID(query ID) 포맷 {#query-id-format}

ClickHouse Client는 interactive mode에서 각 쿼리의 쿼리 ID를 표시합니다. 기본적으로 ID는 다음 포맷으로 표시됩니다:

```sql
Query id: 927f137d-00f1-4175-8914-0dd066365e96
```

설정 파일의 `query_id_formats` 태그 안에 사용자 정의 포맷을 지정할 수 있습니다. 포맷 문자열의 `{query_id}` 플레이스홀더는 쿼리 ID(query ID)로 대체됩니다. 태그 안에 여러 포맷 문자열을 지정할 수 있습니다.
이 기능을 사용하면 쿼리(query)를 더 쉽게 프로파일링할 수 있도록 URL을 생성할 수 있습니다.

**예시**

```xml
<config>
  <query_id_formats>
    <speedscope>http://speedscope-host/#profileURL=qp%3Fid%3D{query_id}</speedscope>
  </query_id_formats>
</config>
```

위 구성을 적용하면 쿼리(query) ID가 다음 포맷으로 표시됩니다.

```response
speedscope:http://speedscope-host/#profileURL=qp%3Fid%3Dc8ecc783-e753-4b38-97f1-42cddfb98b7d
```

## 설정 파일 {#configuration_files}

ClickHouse Client는 다음 목록의 순서대로 파일을 확인하여 가장 먼저 발견한 파일을 사용합니다.

* `-c [ -C, --config, --config-file ]` 매개변수로 지정한 파일.
* `./clickhouse-client.[xml|yaml|yml]`
* `$XDG_CONFIG_HOME/clickhouse/config.[xml|yaml|yml]` (`XDG_CONFIG_HOME`이 설정되지 않은 경우 `~/.config/clickhouse/config.[xml|yaml|yml]`)
* `~/.clickhouse-client/config.[xml|yaml|yml]`
* `/etc/clickhouse-client/config.[xml|yaml|yml]`

ClickHouse 리포지토리에 있는 예제 설정 파일을 참조하십시오: [`clickhouse-client.xml`](https://github.com/ClickHouse/ClickHouse/blob/master/programs/client/clickhouse-client.xml)

<Tabs>
  <Tab title="XML">
    ```xml
    <config>
        <user>username</user>
        <password>password</password>
        <secure>true</secure>
        <openSSL>
          <client>
            <caConfig>/etc/ssl/cert.pem</caConfig>
          </client>
        </openSSL>
    </config>
    ```
  </Tab>

  <Tab title="YAML">
    ```yaml
    user: username
    password: 'password'
    secure: true
    openSSL:
      client:
        caConfig: '/etc/ssl/cert.pem'
    ```
  </Tab>
</Tabs>

## 환경 변수 옵션 {#environment-variable-options}

사용자 이름, 비밀번호, 호스트는 각각 환경 변수 `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`, `CLICKHOUSE_HOST`로 설정할 수 있습니다.
명령줄 인수 `--user`, `--password`, `--host` 또는 [연결 문자열(Connection String)](#connection_string)이 지정되면 환경 변수보다 우선 적용됩니다.

| `--ssh-key-passphrase <value>`       | `--ssh-key-file`로 지정한 SSH 개인 키의 패스프레이스입니다. <br /><br />패스프레이스를 지정하지 않았고 개인 키 파일이 암호화되어 있으면 대화형으로 패스프레이스 입력을 요청합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | *                                                                                                                                                                                         |
| `--tls-sni-override <server name>`   | TLS 사용 시 핸드셰이크 과정에서 전달할 서버 이름(SNI)입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `-h` 또는 `--host`로 지정한 호스트.                                                                                                                                                                |
| `-u [ --user ] <username>`           | 연결에 사용할 데이터베이스 사용자(database user)입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `default`                                                                                                                                                                                 |

<Note>
  클라이언트에서는 `--host`, `--port`, `--user`, `--password` 옵션 대신 [연결 문자열(Connection Strings)](#connection_string)을 사용할 수도 있습니다.
</Note>

### 쿼리 옵션 {#command-line-options-query}

| 옵션                              | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--param_<name>=<value>`        | [매개변수가 있는 쿼리](#cli-queries-with-parameters)의 매개변수에 사용할 치환 값입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `-q [ --query ] <query>`        | 배치 모드에서 실행할 쿼리입니다. 여러 번 지정하거나(`--query "SELECT 1" --query "SELECT 2"`), 세미콜론으로 구분한 여러 쿼리를 한 번에 지정할 수 있습니다(`--query "SELECT 1; SELECT 2;"`). 후자는 `VALUES` 이외의 포맷을 사용하는 `INSERT` 쿼리를 빈 줄로 구분해야 합니다. <br /><br />단일 쿼리는 매개변수 없이 지정할 수도 있습니다: `clickhouse-client "SELECT 1"` <br /><br />`--queries-file`과 함께 사용할 수 없습니다.                                                                                                                                                                                                |
| `--queries-file <path-to-file>` | 쿼리가 포함된 파일의 경로입니다. `--queries-file`은 여러 번 지정할 수 있습니다. 예: `--queries-file queries1.sql --queries-file queries2.sql`. <br /><br />`--query`와 함께 사용할 수 없습니다.                                                                                                                                                                                                                                                                                                                                                            |
| `-m [ --multiline ]`            | 지정하면 여러 줄 쿼리를 허용합니다(Enter를 눌러도 쿼리를 전송하지 않습니다). 쿼리는 세미콜론으로 끝날 때만 전송됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `--ignore-error`                | 쿼리가 실패해도 중지하지 않고 `stderr`에 오류를 출력한 후 다음 쿼리를 실행합니다. 오류를 무시하므로 일부 쿼리가 실패해도 프로세스는 성공 코드로 종료됩니다. 배치 모드에서만 적용됩니다.                                                                                                                                                                                                                                                                                                                                                                                                         |
| `--inline-insert-data`          | 데이터를 Native 형식의 블록(blocks)으로 변환하지 않고 `INSERT ... VALUES`(및 기타 인라인 포맷)를 쿼리 텍스트(query text)에 있는 그대로 전송합니다. 서버가 인라인 데이터를 직접 파싱하므로 테이블 구조(table structure)와 컬럼(column) 기본값을 클라이언트로 다시 보내기 위한 왕복 통신이 필요하지 않습니다. 이를 통해 native protocol로 소량의 데이터를 여러 번 삽입할 때 성능을 개선할 수 있습니다. [`send_table_structure_on_insert_with_inline_data`](/ko/reference/settings/session-settings/send#send_table_structure_on_insert_with_inline_data)를 자동으로 `0`으로 설정합니다. 인라인 데이터와 외부 데이터(stdin 또는 `INFILE`에서 가져온 데이터)를 함께 사용하는 경우에는 이 옵션을 사용할 수 없습니다. |

### 쿼리 설정(query settings) {#command-line-options-query-settings}

쿼리 설정(query settings)은 다음 예시처럼 클라이언트의 명령줄 옵션으로 지정할 수 있습니다:

```bash
$ clickhouse-client --max_threads 1
```

설정 목록은 [설정](/ko/reference/settings/session-settings)을 참조하십시오.
