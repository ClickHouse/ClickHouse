ClickHouse ODBC 드라이버는 ODBC 호환 애플리케이션을 ClickHouse에 연결하기 위한 표준 준수 인터페이스를
제공합니다. 이 드라이버는 ODBC API를 구현하므로 애플리케이션, BI 도구, 스크립팅 환경에서 익숙한 방식으로 SQL
쿼리를 실행하고, 결과를 조회하고, ClickHouse와 상호 작용할 수 있습니다.

드라이버는 모든 ClickHouse 배포 환경에서 지원되는 기본 프로토콜인 [HTTP 프로토콜](/ko/concepts/features/connect-to-clickhouse/protocols/http)을 사용하여 ClickHouse 서버와
통신합니다. 따라서 로컬 설치 환경, 클라우드 관리형 서비스, HTTP 기반 액세스만 허용되는 환경 등
다양한 환경에서 일관되게 동작합니다.

드라이버의 소스 코드는
[ClickHouse-ODBC GitHub 리포지토리](https://github.com/ClickHouse/clickhouse-odbc)에서 확인할 수 있습니다.

<Tip>
  호환성을 높이려면 ClickHouse 서버를 버전 24.11 이상으로 업데이트할 것을 강력히 권장합니다.
</Tip>

<Note>
  이 드라이버는 현재 활발히 개발 중이며, 일부 ODBC 기능은 아직 완전히 구현되지 않았을 수 있습니다. 현재 버전은
  필수 연결 기능과 핵심 ODBC 기능 제공에 중점을 두고 있으며, 추가 기능은 향후 릴리스에서 제공될
  예정입니다.

  사용자 피드백은 새로운 기능과 개선 사항의 우선순위를 정하는 데 큰 도움이 됩니다. 제한 사항,
  누락된 기능 또는 예기치 않은 동작을 발견하면 다음 이슈 트래커를 통해 관찰 내용이나 기능 요청을
  공유해 주십시오:
  [https://github.com/ClickHouse/clickhouse-odbc/issues](https://github.com/ClickHouse/clickhouse-odbc/issues)
</Note>

## Windows에 설치 {#installation-on-windows}

최신 버전의 드라이버는
[https://github.com/ClickHouse/clickhouse-odbc/releases/latest](https://github.com/ClickHouse/clickhouse-odbc/releases/latest)에서 받을 수 있습니다.
이 페이지에서 MSI 설치 프로그램을 다운로드해 실행한 다음, 안내에 따라 간단한 설치 단계를 진행하십시오.

## 테스트 {#testing}

다음 간단한 PowerShell 스크립트를 실행하여 드라이버를 테스트할 수 있습니다. 아래 텍스트를 복사하여 URL, 사용자 이름, 비밀번호를 설정한 다음,
PowerShell 명령 프롬프트에 붙여 넣으세요. `$reader.GetValue(0)`을 실행하면 ClickHouse
서버 버전(server version)이 표시됩니다.

```powershell
$url = "http://127.0.0.1:8123/"
$username = "default"
$password = ""
$conn = New-Object System.Data.Odbc.OdbcConnection("`
    Driver={ClickHouse ODBC Driver (Unicode)};`
    Url=$url;`
    Username=$username;`
    Password=$password")
$conn.Open()
$cmd = $conn.CreateCommand()
$cmd.CommandText = "select version()"
$reader = $cmd.ExecuteReader()
$reader.Read()
$reader.GetValue(0)
$reader.Close()
$conn.Close()
```

## 구성 매개변수 {#configuration-parameters}

아래 매개변수는 ClickHouse ODBC
드라이버로 연결을 설정할 때 가장 일반적으로 사용되는 설정입니다. 필수적인 인증, 연결 동작 및 데이터 처리 옵션을 다룹니다. 지원되는
매개변수의 전체 목록은 프로젝트 GitHub 페이지
[https://github.com/ClickHouse/clickhouse-odbc](https://github.com/ClickHouse/clickhouse-odbc)에서 확인할 수 있습니다.

* `Url`: ClickHouse 서버의 전체 HTTP(S) 엔드포인트를 지정합니다. 프로토콜, 호스트, 포트 및
  선택적 경로를 포함합니다.
* `Username`: ClickHouse 서버 인증에 사용하는 사용자 이름입니다.
* `Password`: 지정한 사용자 이름에 해당하는 비밀번호입니다. 지정하지 않으면 드라이버는 비밀번호
  인증 없이 연결합니다.
* `Database`: 연결에 사용할 기본 데이터베이스(Default Database)입니다.
* `Timeout`: 드라이버가 요청을 중단하기 전까지 서버 응답을 기다리는 최대 시간(초)입니다.
* `ClientName`: 클라이언트 메타데이터의 일부로 ClickHouse 서버에 전송되는 사용자 지정 식별자입니다. 여러 애플리케이션의 트래픽을 추적하거나
  구분할 때 유용합니다. 이 매개변수는 드라이버가 생성하는 HTTP
  요청의 User-Agent 헤더에 포함됩니다.
* `Compression`: 요청 및 응답 페이로드의 HTTP 압축을 활성화하거나 비활성화합니다. 활성화하면
  대역폭 사용량을 줄이고 대용량 결과 집합을 처리할 때 성능을 향상시킬 수 있습니다.
* `SqlCompatibilitySettings`: ClickHouse가 기존 관계형
  데이터베이스처럼 동작하도록 하는 쿼리 설정(query settings)을 활성화합니다. Power BI와 같은 타사 도구가 쿼리를 자동으로 생성할 때 유용합니다. 이러한
  도구는 대개 ClickHouse 전용 동작을 인식하지 못하므로 오류가 발생하거나
  예기치 않은 결과를 반환하는 쿼리를 생성할 수 있습니다. 자세한 내용은 [SqlCompatibilitySettings 구성 매개변수에서 사용하는 ClickHouse 설정
  ](#sql-compatibility-settings)을 참조하십시오.

다음은 연결을 설정할 때 드라이버에 전달하는 전체 연결 문자열(Connection String)의 예시입니다.

* WSL 인스턴스에 로컬로 설치된 ClickHouse 서버

```plaintext
Driver={ClickHouse ODBC Driver (Unicode)};Url=http://localhost:8123/;Username=default
```

* ClickHouse Cloud 인스턴스

```plaintext
Driver={ClickHouse ODBC Driver (Unicode)};Url=https://you-instance-url.gcp.clickhouse.cloud:8443/;Username=default;Password=your-password
```

## Microsoft Power BI 통합 {#powerbi-integration}

ODBC 드라이버를 사용하여 Microsoft Power BI를 ClickHouse 서버에 연결할 수 있습니다. Power BI는 일반 ODBC 커넥터와 ClickHouse Connector라는 두 가지 연결
옵션을 제공하며, 두 커넥터 모두 Power BI 표준 설치에 기본으로 포함되어 있습니다.

두 커넥터 모두 내부적으로 ODBC를 사용하지만, 지원하는 기능에는 차이가 있습니다.

* ClickHouse Connector (권장)
  내부적으로 ODBC를 사용하면서도 DirectQuery 모드를 지원합니다. 이 모드에서는 Power BI가 SQL 쿼리를 자동으로 생성하여
  각 시각화 또는 필터(filter) 작업에 필요한 데이터만 가져옵니다.

* ODBC 커넥터
  Import 모드만 지원합니다. Power BI는 사용자가 입력한 쿼리를 실행하거나 테이블 전체를 조회한 뒤, 전체
  결과 집합을 Power BI로 가져옵니다. 이후 갱신할 때마다 전체 데이터셋을 다시 가져옵니다.

활용 사례에 맞는 커넥터를 선택하십시오. DirectQuery는 대용량 데이터 세트(datasets)를 다루는 대화형 대시보드에 가장 적합합니다.
데이터 전체를 로컬에 복사해 두어야 한다면 Import 모드를 선택하십시오.

Microsoft Power BI와 ClickHouse 통합에 대한 자세한 내용은 [Power
BI 통합에 관한 ClickHouse 문서](/ko/integrations/connectors/data-visualization/powerbi-and-clickhouse)를 참조하십시오.

## SQL 호환성 설정 {#sql-compatibility-settings}

ClickHouse는 고유한 SQL 방언(SQL dialect)을 사용하며, 경우에 따라 MS SQL
Server, MySQL, PostgreSQL 등 다른 데이터베이스와 다르게 동작합니다. 이러한 차이는 대개 장점으로 작용합니다. ClickHouse 기능을
더 쉽게 사용할 수 있도록 개선된 구문을 제공하기 때문입니다.

그러나 ODBC 드라이버는 사용자가 직접 작성한 쿼리가 아니라 Power
BI와 같은 타사 도구가 생성한 쿼리를 실행하는 환경에서 자주 사용됩니다. 이러한 쿼리는 대개 SQL 표준의 최소한의 부분 집합만 사용합니다. 이런 환경에서는
ClickHouse가 SQL 표준과 다르게 동작하는 부분이 예상대로 작동하지 않아 예기치 않은 결과나 오류가 발생할 수 있습니다.
이를 위해 ODBC 드라이버는 추가 구성 매개변수인 `SqlCompatibilitySettings`를 제공합니다. 이 매개변수는 특정 쿼리
설정을 활성화하여 ClickHouse의 동작을 표준 SQL에 더 가깝게 맞춥니다.

### SqlCompatibilitySettings 구성 매개변수로 활성화되는 ClickHouse 설정 {#sql-compatibility-settings-list}

이 섹션에서는 ODBC 드라이버가 변경하는 설정과 그 이유를 설명합니다.

**[cast&#95;keep&#95;nullable](/ko/reference/settings/session-settings/cast#cast_keep_nullable)**

기본적으로 ClickHouse는 NULL 허용 타입을 NULL 비허용 타입으로 변환할 수 없습니다. 그러나 많은 BI 도구는 타입 변환을 수행할 때
NULL 허용 타입과 NULL 비허용 타입을 구분하지 않습니다. 따라서 BI 도구가 다음과 같은 쿼리를 생성하는 경우를
드물지 않게 볼 수 있습니다:

```sql
SELECT sum(CAST(value, 'Int32'))
FROM values
```

기본적으로 `value` 컬럼이 NULL 허용 컬럼이면 이 쿼리는 다음 메시지를 출력하며 실패합니다:

```plaintext
DB::Exception: Cannot convert NULL value to non-Nullable type: while executing 'FUNCTION CAST(__table1.value :: 2,
'Int32'_String :: 1) -> CAST(__table1.value, 'Int32'_String) Int32 : 0'. (CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN)
```

`cast_keep_nullable`을 활성화하면 `CAST`가 인수의 NULL 허용 여부를 그대로 유지하도록 동작이 바뀝니다. 따라서
이러한 변환에서 ClickHouse의 동작이 다른 데이터베이스 및 SQL 표준에 더 가까워집니다.

**[prefer&#95;column&#95;name&#95;to&#95;alias](/ko/reference/settings/session-settings/prefer#prefer_column_name_to_alias)**

ClickHouse에서는 동일한 `SELECT` 목록 안의 표현식을 별칭으로 참조할 수 있습니다. 예를 들어, 다음 쿼리는 반복을 줄일 수 있어
작성하기가 더 쉽습니다.

```sql
SELECT
    sum(value) AS S,
    count() AS C,
    S / C
FROM test
```

이 기능은 널리 사용되지만, 다른 데이터베이스에서는 일반적으로 동일한 `SELECT` 목록 안에서 별칭을 이런 방식으로 해석하지 않으므로
이러한 쿼리는 오류가 발생합니다. 이 문제는 별칭이 컬럼과 같은 이름일 때 가장 두드러집니다. 예를 들면 다음과 같습니다:

```sql
SELECT
    sum(value) AS value,
    avg(value)
FROM test
```

`avg(value)`는 어떤 `value`를 집계해야 할까요? 기본적으로 ClickHouse는 별칭을 우선하므로, 사실상 이 식은
중첩된 집계가 됩니다. 이는 대부분의 도구가 기대하는 동작이 아닙니다.

이것만으로 문제가 되는 경우는 드물지만, 일부 BI 도구는 컬럼 별칭을 재사용하는 서브쿼리가 포함된 쿼리를 생성합니다.
예를 들어 Power BI는 다음과 같은 쿼리를 자주 생성합니다.

```sql
SELECT
    sum(C1) AS C1,
    count(C1) AS C2
FROM
(
    SELECT sum(value) AS C1
    FROM test
    GROUP BY group_index
) AS TBL
```

`C1`을 참조하면 다음과 같은 오류가 발생할 수 있습니다.

```plaintext
Code: 184. DB::Exception: Received from localhost:9000. DB::Exception: Aggregate function sum(C1) AS C1 is found
inside another aggregate function in query. (ILLEGAL_AGGREGATION)
```

다른 데이터베이스는 일반적으로 이처럼 같은 수준에서 별칭을 해석하지 않으며, `C1`을
서브쿼리의 컬럼으로 처리합니다. ClickHouse에서도 이와 유사하게 동작하고 이러한 쿼리가 오류 없이 실행되도록 ODBC 드라이버는
`prefer_column_name_to_alias`를 활성화합니다.

대부분의 경우 이러한 설정을 활성화해도 문제가 되지 않습니다. 그러나 readonly 설정이 `1`인 사용자는
`SELECT` 쿼리에서도 설정을 전혀 변경할 수 없습니다. 이러한 사용자에게 `SqlCompatibilitySettings`를 활성화하면
오류가 발생합니다. 다음 섹션에서는 읽기 전용 사용자도 이 구성 매개변수를 사용할 수 있도록 하는 방법을 설명합니다.

## 읽기 전용 사용자에게 SQL 호환성 설정 적용하기 {#readonly-users}

`SqlCompatibilitySettings` 매개변수를 활성화한 상태로 ODBC 드라이버를 통해 ClickHouse에 연결하면, readonly 설정이 `1`인 사용자는
드라이버가 쿼리 설정(query settings)을 변경하려고 시도하므로 다음과 같은 오류가 발생합니다:

```plaintext
Code: 164. DB::Exception: Cannot modify 'cast_keep_nullable' setting in readonly mode. (READONLY)
Code: 164. DB::Exception: Cannot modify 'prefer_column_name_to_alias' setting in readonly mode. (READONLY)
```

이는 읽기 전용 모드(read-only mode)의 사용자는 개별 `SELECT` 쿼리에 대해서도 설정을 변경할 수 없기 때문입니다.
이 문제는 여러 가지 방법으로 해결할 수 있습니다.

**옵션 1. `readonly`를 `2`로 설정**

가장 간단한 방법입니다. `readonly`를 `2`로 설정하면 사용자를 읽기 전용
모드로 유지하면서도 설정을 변경할 수 있습니다.

```sql
ALTER USER your_odbc_user MODIFY SETTING
    readonly = 2
```

대부분의 경우 `readonly`를 2로 설정하는 것이 이 문제를 해결하는 가장 쉬우면서도 권장되는 방법입니다. 이
방법을 사용할 수 없다면 두 번째 옵션을 사용하십시오.

**옵션 2. ODBC 드라이버가 지정하는 설정과 일치하도록 사용자 설정 변경**

이 방법도 간단합니다. ODBC 드라이버가 지정하려는 값과 처음부터 일치하도록 사용자 설정을 변경하면 됩니다.

```sql
ALTER USER your_odbc_user MODIFY SETTING
    cast_keep_nullable = 1,
    prefer_column_name_to_alias = 1
```

이렇게 변경하면 ODBC 드라이버가 여전히 설정 적용을 시도할 수는 있지만, 값이 이미 일치하므로 실제로는 아무것도 변경되지 않으며
오류도 발생하지 않습니다.

이 옵션 역시 간단하지만 지속적인 관리가 필요합니다. 새 드라이버 버전에서는 호환성을 위해 설정 목록이 변경되거나
새로운 설정이 추가될 수 있습니다. ODBC 사용자에 이러한 설정을 하드코딩해 두었다면,
ODBC 드라이버가 추가 설정을 적용할 때마다 해당 설정을 함께 업데이트해야 할 수 있습니다.
