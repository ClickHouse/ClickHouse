---
title: رفع ملف CSV عبر سطر الأوامر
---

تتناول هذه الصفحة رفع ملف محلي (ملف CSV على سبيل المثال) إلى جدول في خدمة ClickHouse Cloud من سطر الأوامر باستخدام [واجهة سطر الأوامر لـ ClickHouse](/ar/concepts/features/interfaces/cli) (`clickhousectl`). ويحاكي هذا المسار معالج رفع الملفات في Console: فحص schema الملف، وإنشاء destination جدول، ثم إدراج الملف عبر HTTP باستخدام واجهة برمجة تطبيقات الاستعلام — دون الحاجة إلى ملف تنفيذي لـ `clickhouse` أو إلى كلمة المرور الخاصة بالخدمة.

## المتطلبات المسبقة {#cli-prerequisites}

ثبّت واجهة سطر الأوامر لـ ClickHouse:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

يثبّت البرنامج النصي الملف `~/.local/bin/clickhousectl` إضافةً إلى اسم بديل هو `chctl`. تأكّد من إدراج `~/.local/bin` في متغير `PATH` لديك.

تحتاج أيضاً إلى الأداة `jq`.

تتطلّب عمليات الكتابة [مفتاح API](/ar/products/cloud/features/admin-features/api/openapi) يملك دوره صلاحية إدارة نقاط نهاية API للاستعلامات؛ أما تسجيل الدخول عبر المتصفح (`clickhousectl cloud auth login`) فيمنح وصولاً للقراءة فقط. ويعرض الأمر `clickhousectl cloud service query --help` الصلاحيات المطلوبة. سجّل الدخول باستخدام المفتاح؛ إذ يطلب منك الخيار `--interactive` إدخال المفتاح والـ secret، فلا يُحفَظ الـ secret في سجل shell لديك:

```bash
clickhousectl cloud auth login --interactive
```

بدلاً من ذلك، يمكنك تمرير `--api-key` و`--api-secret`، أو تعيين متغيرات البيئة `CLICKHOUSE_CLOUD_API_KEY` و`CLICKHOUSE_CLOUD_API_SECRET`؛ ويُفضَّل أن يعتمد وكيل البرمجة أو البرنامج النصي على متغيرات البيئة. يتحقق تسجيل الدخول من صحة المفتاح ويعرض الهوية المرتبطة به، ويمكنك التحقق من بيانات الاعتماد النشطة في أي وقت باستخدام `clickhousectl cloud auth whoami`. إذا كنت تنتمي إلى أكثر من مؤسسة، فأضف `--org-id <org-id>` (أو `--org-name <name>`) إلى كل أمر `cloud service` في هذا الدليل.

## اختر خدمة {#pick-a-service}

يفترض هذا الدليل أن لديك بالفعل خدمة. إذا لم يكن الأمر كذلك، فراجع [Cloud quick start](/ar/get-started/setup/cloud) لإنشاء واحدة عبر واجهة سطر الأوامر. ابحث عن الـ ID الخاص بالخدمة الخاصة بك عن طريق الاسم:

```bash
CH_ID=$(clickhousectl cloud service get --name my-service --json | jq -r .id)
```

تستيقظ الخدمة الخاملة تلقائيًا عند أول استعلام، أما الخدمة المتوقفة فلا: شغّلها باستخدام `clickhousectl cloud service start "$CH_ID"` وانتظر حتى يُعيد الأمر `clickhousectl cloud service get "$CH_ID" --json | jq -r .state` القيمة `running`.

## تحضير الملف {#prepare-the-file}

لنفترض أن النص التالي موجود في ملف CSV يُسمى `data.csv`. السطر الأول هو صف العناوين، وبالتالي فإن صيغة الإدخال المطابقة هي `CSVWithNames`:

```text title="data.csv"
user_id,url,visited_at,duration_ms
101,https://clickhouse.com/docs,2026-08-14 09:15:32,4210
102,https://clickhouse.com/pricing,2026-08-14 09:16:01,1830
101,https://clickhouse.com/cloud,2026-08-14 09:17:45,2650
103,https://clickhouse.com/blog,2026-08-15 11:02:10,980
102,https://clickhouse.com/docs/cloud,2026-08-15 11:05:44,3120
```

## فحص الـ schema {#inspect-the-schema}

بينما يعرض لك معالج الـ Console النوع المُستنتَج لكل حقل من حقول الـ source، فإن ما يكافئ ذلك في واجهة سطر الأوامر هو تنفيذ `DESCRIBE` على دالة جدول [`format`](/ar/reference/functions/table-functions/format) مع تضمين عيّنة من الملف بشكل Inline:

```bash
clickhousectl cloud service query "$CH_ID" --format PrettyCompact \
  --query "DESCRIBE format(CSVWithNames, '$(head -n 3 data.csv)')"
```

عند أول استدعاء لـ `query`، يضيف clickhousectl مفتاح API الخاص بك إلى نقطة نهاية واجهة برمجة تطبيقات الاستعلام الخاصة بالخدمة، وينشئ نقطة النهاية عند الحاجة؛ ولا يُنشأ أي مفتاح جديد. مرّر `--no-auto-enable` لجعل الأمر يفشل بدلًا من ذلك. وعندما تُغيّر واجهة سطر الأوامر نقطة النهاية، فإنها تطبع السطر الأول أدناه إلى stderr:

```text
Binding the authenticated API key to the Query API endpoint for service 'my-service'...
   ┌─name────────┬─type───────────────┬─default_type─┬─default_expression─┬─comment─┬─codec_expression─┬─ttl_expression─┐
1. │ user_id     │ Nullable(Int64)    │              │                    │         │                  │                │
2. │ url         │ Nullable(String)   │              │                    │         │                  │                │
3. │ visited_at  │ Nullable(DateTime) │              │                    │         │                  │                │
4. │ duration_ms │ Nullable(Int64)    │              │                    │         │                  │                │
   └─────────────┴────────────────────┴──────────────┴────────────────────┴─────────┴──────────────────┴────────────────┘
```

تُدرَج العينة ضمن قيمة حرفية نصية في SQL، لذا يجب ألا تحتوي على علامات تنصيص مفردة أو شرطات مائلة عكسية؛ أما الملفات التي تحتوي عليها، فقم بإفلاتها أو اكتب `CREATE TABLE` يدويًا.

## إنشاء الجدول {#create-the-table}

كل ما تتيحه خطوة &quot;Configure table&quot; في المعالج — من تعديل الأنواع المستنتجة، وقابلية القيم لأن تكون NULL، والقيم الافتراضية، والحقول المستبعدة، ومحرك الجدول، وتعبيرات الفرز والتقسيم والمفتاح الأساسي — ليس سوى عبارة [`CREATE TABLE`](/ar/reference/statements/create/table) عادية هنا. على سبيل المثال، لتضييق الأنواع المستنتجة واختيار مفتاح فرز:

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "CREATE TABLE default.website_visits (
    user_id UInt32,
    url String,
    visited_at DateTime,
    duration_ms UInt32
  ) ENGINE = MergeTree
  ORDER BY (user_id, visited_at)"
```

يطبع الأمر `OK` على stderr. أما إذا كنت تريد التحميل إلى جدول موجود بالفعل، فتخطَّ هذه الخطوة.

## رفع الملف {#upload-the-file}

يقرأ `INSERT ... FORMAT` البيانات من stdin، لذا مرِّر الاستعلام والملف معًا عبر أنبوب (pipe):

```bash
printf 'INSERT INTO default.website_visits FORMAT CSVWithNames\n' | cat - data.csv \
  | clickhousectl cloud service query "$CH_ID"
```

يطبع الأمر `OK`.

<Warning>
  **مرّر الاستعلام والبيانات معًا عبر الأنبوب**

  تمرير `INSERT` عبر `--query` مع إعادة توجيه الملف أو تمريره عبر أنبوب إلى stdin (‏`--query "INSERT ..." < data.csv`‎) لا يعمل: فالخيار `--query` لا يقرأ stdin مطلقًا، وبالتالي لن تصل البيانات إلى أي وجهة. ترفض واجهة سطر الأوامر هذا الدمج صراحةً بدلًا من أن تُنهي العملية دون إدراج أي شيء بصمت — إذ تخرج بالرمز `1`، ولا تدرج أي صفوف، وتطبع:

  ```text
  Error: --query cannot be combined with SQL or data on stdin. The Query API sends one request body, so redirected data is never read. Pipe the statement and its data together on stdin instead: printf 'INSERT INTO t FORMAT CSV\n' | cat - data.csv | clickhousectl cloud service query --id <id>. Or read a whole statement from stdin with --queries-file -.
  ```

  أرسل الاستعلام والبيانات دائمًا عبر stdin كتدفق واحد، كما هو موضّح أعلاه. ولا يتعارض مع `--query` سوى stdin الذي يحمل بيانات فعلية، لذا يظل `--query` وحده صالحًا للعمل في البرامج النصية والـ pipelines التي لا يكون فيها stdin هو الـ terminal.
</Warning>

تحقّق من وصول الصفوف:

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT count() FROM default.website_visits"
```

```text
{"count()":5}
```

```bash
clickhousectl cloud service query "$CH_ID" --format PrettyCompact \
  --query "SELECT * FROM default.website_visits ORDER BY visited_at"
```

```text
   ┌─user_id─┬─url───────────────────────────────┬──────────visited_at─┬─duration_ms─┐
1. │     101 │ https://clickhouse.com/docs       │ 2026-08-14 09:15:32 │        4210 │
2. │     102 │ https://clickhouse.com/pricing    │ 2026-08-14 09:16:01 │        1830 │
3. │     101 │ https://clickhouse.com/cloud      │ 2026-08-14 09:17:45 │        2650 │
4. │     103 │ https://clickhouse.com/blog       │ 2026-08-15 11:02:10 │         980 │
```

## تحميل الملفات الكبيرة {#upload-large-files}

تتوقف واجهة برمجة تطبيقات الاستعلام عن الانتظار بعد نحو 30 ثانية. وقد يكون أمر `INSERT` الذي انتهت مهلته قد نُفِّذ فعلًا، لذا تحقّق من عدد الصفوف قبل إعادة المحاولة. أما الملفات الكبيرة، فنفّذ إدراجها بدلًا من ذلك عبر البروتوكول الأصلي باستخدام [`clickhouse client`](/ar/concepts/features/interfaces/client)، الذي يقرأ البيانات من stdin. يثبّت الأمر `clickhousectl local use latest` أحدث إصدار من ClickHouse وينشئ له رابطًا رمزيًا في `~/.local/bin/clickhouse`. اضبط `CH_PASSWORD` على كلمة مرور المستخدم `default` (وإن فقدتها، فيمكنك إنشاء كلمة مرور جديدة بالأمر `clickhousectl cloud service reset-password "$CH_ID"`)، ثم ابحث عن المضيف `nativesecure`، ونفّذ الإدراج:

```bash
clickhousectl local use latest
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol == "nativesecure") | .host')
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query 'INSERT INTO default.website_visits FORMAT CSVWithNames' < data.csv
```

يجب أن تتوافق الاتصالات المباشرة مع قائمة الوصول لعناوين IP الخاصة بالخدمة.

## تنسيقات الملفات الأخرى {#other-file-formats}

ينطبق النمط نفسه على أي [صيغة الإدخال](/ar/reference/formats/index) يدعمه ClickHouse — بما في ذلك جميع التنسيقات التي يقبلها معالج الرفع في Console، مثل `CSV` و`JSONEachRow` و`TabSeparatedWithNames`. ولاستخدام تنسيق آخر، غيّر اسم التنسيق بشكل متسق في كل من خطوة استنتاج الـ schema عبر `DESCRIBE format(...)` وفي عبارة `INSERT ... FORMAT`، واستخدم ملف عينة يطابق ذلك التنسيق (عينة بتنسيق TSV لـ `TabSeparatedWithNames`، وعينة بتنسيق أسطر JSON لـ `JSONEachRow`، وهكذا). على سبيل المثال، تصبح خطوة الرفع لملف TSV كما يلي:

```bash
printf 'INSERT INTO default.website_visits FORMAT TabSeparatedWithNames\n' | cat - data.tsv \
  | clickhousectl cloud service query "$CH_ID"
```

## التنظيف {#cleanup}

إذا كان هذا مجرد تشغيل تجريبي، فاحذف الجدول لإزالة البيانات المستوردة:

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "DROP TABLE default.website_visits"
```
