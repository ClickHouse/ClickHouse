title: البدء السريع مع واجهة سطر أوامر Cloud
---

تغطي هذه الصفحة تجهيز خدمة ClickHouse Cloud والاتصال بها وتحميل البيانات، وكل ذلك من سطر الأوامر باستخدام [واجهة سطر أوامر ClickHouse](/ar/concepts/features/interfaces/cli) (`clickhousectl`). الأوامر غير تفاعلية، باستثناء تسجيل الدخول الاختياري عبر `--interactive`. ويُخرج `clickhousectl` بيانات JSON عند استخدام `--json`، كما يُخرجها تلقائيًا عندما يشغّله وكيل برمجة.

## المتطلبات المسبقة {#prerequisites}

ثبّت واجهة سطر الأوامر لـ ClickHouse:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

يثبّت البرنامج النصي `~/.local/bin/clickhousectl` واسمًا بديلًا له هو `chctl`. تأكّد من إضافة `~/.local/bin` إلى متغير `PATH` لديك.

ستحتاج أيضًا إلى `jq`.

ستحتاج كذلك إلى حساب ClickHouse Cloud. وإن لم يكن لديك حساب بعد، فإن الأمر `clickhousectl cloud auth signup` يفتح صفحة التسجيل في متصفحك.

يمنح تسجيل الدخول عبر المتصفح (`clickhousectl cloud auth login`) صلاحية القراءة فقط. أما إنشاء خدمة وحذفها، وتشغيل استعلامات SQL عبر واجهة برمجة تطبيقات الاستعلام، فيتطلّب [مفتاح API](/ar/products/cloud/features/admin-features/api/openapi) يملك دوره صلاحية إنشاء الخدمات وإدارة نقاط نهاية API للاستعلامات؛ ويعرض الخيار `--help` لكل أمر الصلاحيات التي يحتاجها. سجّل الدخول باستخدام المفتاح؛ إذ يطالبك الخيار `--interactive` بإدخال المفتاح والـ secret، فلا يُحفَظ الـ secret في سجل الـ shell لديك:

```bash
clickhousectl cloud auth login --interactive
```

بدلاً من ذلك، يمكنك تمرير `--api-key` و`--api-secret`، أو ضبط متغيرات البيئة `CLICKHOUSE_CLOUD_API_KEY` و`CLICKHOUSE_CLOUD_API_SECRET`. ويُفضَّل أن يعتمد وكيل البرمجة أو البرنامج النصي على متغيرات البيئة. يتحقق تسجيل الدخول من صحة المفتاح ويعرض الهوية المرتبطة به، ويمكنك التحقق من بيانات الاعتماد النشطة في أي وقت باستخدام `clickhousectl cloud auth whoami`. إذا كنت تنتمي إلى أكثر من مؤسسة، فأضف `--org-id <org-id>` (أو `--org-name <name>`) إلى كل أمر `cloud` في هذا الدليل.

## أنشئ خدمة ClickHouse {#create-service}

أنشئ الخدمة واحفظ الاستجابة؛ إذ لا تُعرض كلمة مرور المستخدم `default` إلا مرة واحدة:

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json
```

تتضمن الاستجابة معرّف الخدمة ونقاط النهاية وكلمة المرور المُنشأة (اقتُصرت هنا؛ إذ تتضمن الاستجابة الكاملة أيضًا إعدادات التوسعة وقائمة الوصول عبر IP والوسوم):

```json
{
  "password": "dK7mPq2x_-TzrL9vNw0s",
  "service": {
    "id": "4f7b92f3-4163-403a-b538-b9bc6e2e8f66",
    "name": "quickstart-ch",
    "provider": "aws",
    "region": "us-east-1",
    "state": "provisioning",
    "endpoints": [
      {
        "host": "quickstart-abc123.us-east-1.aws.clickhouse.cloud",
        "port": 9440,
        "protocol": "nativesecure"
      },
      {
        "host": "quickstart-abc123.us-east-1.aws.clickhouse.cloud",
        "port": 8443,
        "protocol": "https"
      }
    ],
    "numReplicas": 3,
    "minReplicaMemoryGb": 16.0,
    "maxReplicaMemoryGb": 120.0
  }
}
```

استخرج المتطلبات اللازمة لبقية هذا الدليل:

```bash
CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
CH_HOST=$(jq -r '.service.endpoints[] | select(.protocol=="nativesecure") | .host' ch.json)
```

إذا فقدت كلمة المرور، أنشئ كلمة مرور جديدة باستخدام `clickhousectl cloud service reset-password "$CH_ID"`.

تُنشأ الخدمات باستخدام `clickhousectl` افتراضيًا مع قائمة وصول لعناوين IP تسمح بالوصول من جميع العناوين (`0.0.0.0/0`). لتقييد الوصول، مرّر `--ip-allow` عند إنشاء الخدمة؛ راجع [&quot;إعداد عوامل تصفية IP&quot;](/ar/products/cloud/guides/security/connectivity/setting-ip-filters).

## انتظر حتى تكتمل تهيئة الخدمة {#wait-for-provisioning}

تستغرق التهيئة نحو دقيقة. تحقّق دوريًا حتى تصبح الحالة `running`:

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

## تشغيل SQL باستخدام واجهة برمجة تطبيقات الاستعلام {#run-sql}

يُشغّل الأمر `clickhousectl cloud service query` استعلامات SQL عبر HTTP، دون الحاجة إلى ملف تنفيذي محلي لـ `clickhouse` أو إلى كلمة مرور الخدمة. عند الاستدعاء الأول، يضيف clickhousectl مفتاح API الخاص بك إلى نقطة نهاية API للاستعلام الخاصة بالخدمة، وينشئ نقطة النهاية إن لم تكن موجودة، دون إنشاء أي مفتاح جديد. ولجعل الأمر يفشل بدلاً من ذلك، مرّر الخيار `--no-auto-enable`:

```bash
clickhousectl cloud service query "$CH_ID" --json --query "SHOW databases"
```

يُوجَّه السطر الأول من الإخراج أدناه إلى stderr، ولا يظهر إلا عندما تُغيّر واجهة سطر الأوامر نقطة النهاية:

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
{"name":"INFORMATION_SCHEMA"}
{"name":"default"}
{"name":"information_schema"}
{"name":"system"}
```

يكون الإخراج افتراضيًا بصيغة `PrettyCompact` عند العرض في طرفية، وبصيغة `TabSeparated` عند توجيهه عبر أنبوب (pipe)، وبصيغة `JSONEachRow` عندما يشغّل وكيل برمجة الأمر. يختار الخيار `--json` المستخدم أعلاه صيغة `JSONEachRow`؛ أما لأي صيغة أخرى، فمرّر `--format` بدلًا منه (لا يمكن الجمع بين `--json` و`--format`). ولذلك ينبغي لأي برنامج نصي يحلّل الإخراج أن يمرّر أحدهما دائمًا.

## إنشاء قاعدة بيانات وجدول {#create-database-and-table}

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "CREATE DATABASE IF NOT EXISTS helloworld"

clickhousectl cloud service query "$CH_ID" \
  --query "CREATE TABLE helloworld.my_first_table (
    user_id UInt32,
    message String,
    timestamp DateTime,
    metric Float32
  ) ENGINE = MergeTree()
  PRIMARY KEY (user_id, timestamp)"
```

يطبع كل أمر `OK` على stderr. أدرج بضعة صفوف:

```bash
clickhousectl cloud service query "$CH_ID" <<'SQL'
INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
  (101, 'Hello, ClickHouse!', now(), -1.0),
  (102, 'Insert a lot of rows per batch', yesterday(), 1.41421),
  (102, 'Sort your data based on your commonly-used queries', today(), 2.718),
  (101, 'Granules are the smallest chunks of data read', now() + 5, 3.14159)
SQL
```

تحقّق من نجاح العملية:

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT * FROM helloworld.my_first_table ORDER BY timestamp"
```

```text
{"user_id":102,"message":"Insert a lot of rows per batch","timestamp":"2026-08-26 00:00:00","metric":1.41421}
{"user_id":102,"message":"Sort your data based on your commonly-used queries","timestamp":"2026-08-27 00:00:00","metric":2.718}
{"user_id":101,"message":"Hello, ClickHouse!","timestamp":"2026-08-27 10:41:28","metric":-1}
{"user_id":101,"message":"Granules are the smallest chunks of data read","timestamp":"2026-08-27 10:41:33","metric":3.14159}
```

تعتمد الطوابع الزمنية على وقت تنفيذ عملية insert، لذا ستختلف القيم لديك.

## تحميل ملف CSV {#load-csv-file}

افترض أن النص التالي موجود في ملف CSV باسم `data.csv`:

```text title="data.csv"
102,This is data in a file,2022-02-22 10:43:28,123.45
101,It is comma-separated,2022-02-23 00:00:00,456.78
103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
```

تقرأ `INSERT ... FORMAT` البيانات من stdin، لذا مرّر الاستعلام والملف معًا عبر pipe:

```bash
printf 'INSERT INTO helloworld.my_first_table FORMAT CSV\n' | cat - data.csv \
  | clickhousectl cloud service query "$CH_ID"
```

تتوقف واجهة برمجة تطبيقات الاستعلام عن الانتظار بعد نحو 30 ثانية، وقد يكون أمر `INSERT` الذي انتهت مهلته قد نُفِّذ فعلًا، لذا افحص عدد الصفوف قبل إعادة المحاولة. أما الملفات الكبيرة، فاستخدم لها [`clickhouse client`](#native-client) بدلًا من ذلك.

تحقّق من إدراج الصفوف الجديدة:

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT count() FROM helloworld.my_first_table"
```

```text
{"count()":7}
```

## الاتصال باستخدام clickhouse client {#native-client}

يمكنك أيضًا الاتصال عبر البروتوكول الأصلي باستخدام [**clickhouse client**](/ar/concepts/features/interfaces/client). تتولى واجهة سطر أوامر ClickHouse إدارة الملف التنفيذي `clickhouse` نيابةً عنك، لذا لا تحتاج إلى تثبيت عميل منفصل:

```bash
clickhousectl local use latest
```

يثبّت هذا أحدث إصدار من ClickHouse وينشئ رابطًا رمزيًا له في `~/.local/bin/clickhouse`، بحيث يمكنك تشغيل أمر `clickhouse` مباشرةً بمجرد أن يكون `~/.local/bin` ضمن `PATH` (يطبع الأمر ملاحظة إذا لم يكن كذلك).

بعد ذلك، اتصل باستخدام اسم المضيف وكلمة المرور الواردين في استجابة الإنشاء. عند استخدام `--query`، تُطبع النتيجة ثم ينهي العميل عمله؛ أما بدونه، فستظهر لك موجّه الأوامر التفاعلي (`:)`) الذي يمكنك الخروج منه باستخدام `exit`:

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query "SELECT * FROM helloworld.my_first_table ORDER BY timestamp FORMAT TabSeparated"
```

```text
103	Use FORMAT to specify the format	2022-02-21 10:43:30	678.9
102	This is data in a file	2022-02-22 10:43:28	123.45
101	It is comma-separated	2022-02-23 00:00:00	456.78
102	Insert a lot of rows per batch	2026-08-26 00:00:00	1.41421
102	Sort your data based on your commonly-used queries	2026-08-27 00:00:00	2.718
101	Hello, ClickHouse!	2026-08-27 10:41:28	-1
101	Granules are the smallest chunks of data read	2026-08-27 10:41:33	3.14159
```

يتيح نموذج الأمر نفسه تحميل الملفات. ولا يخضع لمهلة واجهة برمجة تطبيقات الاستعلام، لذا استخدمه مع الملفات الكبيرة:

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
```

تُزيل ClickHouse Cloud التكرارات من الكتل المُدرَجة المتطابقة، لذا فإن تحميل الملف `data.csv` نفسه مرة أخرى لن يضيف أي صفوف.

## التنظيف {#cleanup}

يؤدي حذف الخدمة إلى إزالة جميع بياناتها نهائيًا. يوقف الخيار `--force` الخدمة قيد التشغيل أولًا وينتظر اكتمال إيقافها، وقد يستغرق ذلك عدة دقائق:

```bash
clickhousectl cloud service delete "$CH_ID" --force
```

للاحتفاظ بالبيانات مع إيقاف تكاليف الحوسبة، أوقف الخدمة باستخدام `clickhousectl cloud service stop "$CH_ID"` بدلًا من ذلك.
