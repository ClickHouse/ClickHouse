تتناول هذه الصفحة تجهيز ClickHouse Managed Postgres، وتحميل البيانات، ونسخها إلى ClickHouse، والاستعلام عنها، وكل ذلك من خلال سطر الأوامر باستخدام [clickhousectl](/ar/concepts/features/interfaces/cli) و`psql`. الأوامر غير تفاعلية، باستثناء تسجيل الدخول الاختياري عبر `--interactive`. ويُخرج `clickhousectl` مخرجات JSON مع `--json`، وكذلك تلقائيًا عند اكتشافه وكيلَ برمجة؛ مرِّر `--format` إلى `cloud service query` للحصول على القيم بصيغة نصية بسيطة.

## المتطلبات المسبقة {#prerequisites}

ثبّت clickhousectl:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

يثبّت البرنامج النصي الملف `~/.local/bin/clickhousectl` ومعه الاسم البديل `chctl`. تأكّد من أن `~/.local/bin` مُدرَج في متغير `PATH` لديك.

تحتاج أيضًا إلى `psql` (أدوات عميل PostgreSQL؛ على macOS نفّذ `brew install libpq`) وإلى `jq`.

تتطلّب عمليات الكتابة (الإنشاء والحذف) [مفتاح API](/ar/products/cloud/features/admin-features/api/openapi)، أمّا تسجيل الدخول عبر OAuth (أي تنفيذ `clickhousectl cloud auth login` دون أي خيارات سطر أوامر) فيمنح صلاحية القراءة فقط. سجّل الدخول باستخدام مفتاحك؛ إذ يطلب منك الخيار `--interactive` إدخال المفتاح والسرّ، فلا يُحفَظ السرّ في سجل shell لديك:

```bash
clickhousectl cloud auth login --interactive
```

أو مرِّر المفتاح والسر إلى `clickhousectl cloud auth login` باستخدام `--api-key` و`--api-secret`، أو اضبط متغيرات البيئة `CLICKHOUSE_CLOUD_API_KEY` و`CLICKHOUSE_CLOUD_API_SECRET`. يتحقق أمر تسجيل الدخول من بيانات الاعتماد ويعرض الهوية، ويمكنك لاحقًا التحقق منها مجددًا باستخدام الأمر `clickhousectl cloud auth whoami`. إذا كنت تنتمي إلى أكثر من مؤسسة، فأضف `--org-id <id>` (أو `--org-name <name>`) إلى كل أمر.

## الجزء 1: إنشاء Postgres وتحميل البيانات {#part-1-create-and-load}

### إنشاء خدمة Postgres {#create-postgres-service}

أنشئ الخدمة واحفظ الاستجابة، إذ لا تُعرض كلمة المرور إلا مرة واحدة:

```bash
clickhousectl cloud postgres create \
  --name quickstart-pg \
  --region us-east-1 \
  --size m6gd.large \
  --pg-version 18 \
  --json > pg.json
```

يُعدّ AWS المزوّد الافتراضي. أما GCP فهو في مرحلة المعاينة الخاصة؛ ولاستخدامه، مرّر `--provider gcp` مع منطقة وحجم خاصين بـ GCP، مثل `--region us-central1 --size c4-standard-lssd-4`.

إذا لم تُمرَّر خيارات سطر الأوامر الخاصة بالوصول، فستقبل الخدمة الاتصالات من أي عنوان IPv4 أو IPv6 على Postgres (5432) وPgBouncer (6432). ولتقييد الوصول، مرّر قاعدة `--ip-allow` واحدة لكل CIDR ونطاق منافذ، مثل `--ip-allow '203.0.113.0/24:5432..6432=office'`. وبمجرد تمرير أي قاعدة، لن تُطبَّق سوى القواعد المُدرجة. ولتعديل القواعد لاحقًا، شغّل `clickhousectl cloud postgres update <postgres-id>` مع `--add-ip-allow <rule>` أو `--remove-ip-allow <rule-id>`؛ ويمكنك عرض معرّفات القواعد باستخدام الأمر `cloud postgres get`.

استخرج القيم التي ستحتاج إليها في بقية هذا الدليل:

```bash
PG_ID=$(jq -r .id pg.json)
PG_URL="$(jq -r .connectionString pg.json | sed 's/sslmode=require/sslmode=verify-full/')&sslrootcert=pg-ca.pem"
```

يؤدي تغيير `sslmode` إلى `verify-full` وإضافة `sslrootcert` إلى أن يتحقق `psql` من شهادة الخادم باستخدام شهادة CA التي ستنزّلها أدناه. أما مع الإعداد الافتراضي `sslmode=require`، فإن `psql` يشفّر الاتصال دون أن يتحقق من هوية الخادم.

إذا فقدت كلمة المرور، فأنشئ كلمة مرور جديدة باستخدام `clickhousectl cloud postgres reset-password "$PG_ID" --generate`.

### انتظر حتى يكتمل تجهيز الخدمة {#wait-for-provisioning}

تستغرق عملية التجهيز بضع دقائق. تحقّق دوريًا حتى تصبح الحالة `running`:

```bash
while [ "$(clickhousectl cloud postgres get "$PG_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

### تنزيل شهادة المرجع المصدق {#download-ca-certificate}

لكل مثيل من ClickHouse Managed Postgres مرجع مصدق (CA) خاص به، وهو غير موثوق به علنيًا. احفظ شهادته في ملف؛ إذ يستخدمها كلٌّ من `psql` وClickPipe في الجزء 2 للتحقق من اتصال TLS:

```bash
clickhousectl cloud postgres certs get "$PG_ID" --output pg-ca.pem
```

### تحميل بيانات نموذجية {#load-sample-data}

أنشئ جدولين ونفّذ إدراجًا لمليون حدث عبر `psql`:

```bash
psql "$PG_URL" <<'SQL'
\timing

   event_id SERIAL PRIMARY KEY,
   event_name VARCHAR(255) NOT NULL,
   event_type VARCHAR(100),
   event_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   event_data JSONB,
   user_id INT,
   user_ip INET,
   is_active BOOLEAN DEFAULT TRUE,
   created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
   user_id SERIAL PRIMARY KEY,
   name VARCHAR(100),
   country VARCHAR(50),
   platform VARCHAR(50)
);

INSERT INTO events (event_name, event_type, event_timestamp, event_data, user_id, user_ip)
SELECT
   'Event ' || gs::text AS event_name,
   CASE
       WHEN random() < 0.5 THEN 'click'
       WHEN random() < 0.75 THEN 'view'
       WHEN random() < 0.9 THEN 'purchase'
       WHEN random() < 0.98 THEN 'signup'
       ELSE 'logout'
   END AS event_type,
   NOW() - INTERVAL '1 day' * (gs % 365) AS event_timestamp,
   jsonb_build_object('key', 'value' || gs::text, 'additional_info', 'info_' || (gs % 100)::text) AS event_data,
   GREATEST(1, LEAST(1000, FLOOR(POWER(random(), 2) * 1000) + 1)) AS user_id,
   ('192.168.1.' || ((gs % 254) + 1))::inet AS user_ip
FROM
   generate_series(1, 1000000) gs;

SELECT
    first_names[first_idx] || ' ' || last_names[last_idx] AS name,
```

## الجزء 2: النسخ إلى ClickHouse {#part-2-replicate}

### أنشئ خدمة ClickHouse {#create-clickhouse-service}

أنشئ خدمة في المنطقة نفسها واحفظ الاستجابة؛ إذ لا تظهر كلمة المرور إلا في استجابة الإنشاء:

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json

CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
```

انتظر حتى يصبح قيد التشغيل؛ إذ يتطلب ClickPipe وجهةً قيد التشغيل:

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

لاستخدام خدمة موجودة بدلًا من ذلك، عيّن `CH_ID` من `clickhousectl cloud service list` وعيّن `CH_PASSWORD` إلى كلمة مرور المستخدم `default` الخاصة بها، والتي تحتاجها خطوة `pg_clickhouse`.

### نسخ الجداول نسخًا متماثلًا إلى ClickHouse {#replicate-to-clickhouse}

أنشئ ClickPipe لـ Postgres CDC على خدمة ClickHouse، وأشِر به إلى اسم المضيف الخاص بـ ClickHouse Managed Postgres. ينسخ مسار استيعاب البيانات الصفوف الموجودة أولًا، ثم يُبقي ClickHouse متزامنًا مع التغييرات الجارية. تتحقق ClickPipes افتراضيًا من شهادة المصدر، لذا مرِّر شهادة CA التي نزّلتها في الجزء 1 باستخدام `--ca-certificate`:

```bash
PG_HOST=$(jq -r .hostname pg.json)
PG_PASSWORD=$(jq -r .password pg.json)

clickhousectl cloud clickpipe create postgres "$CH_ID" \
  --name quickstart-sync \
  --host "$PG_HOST" \
  --pg-database postgres \
  --username postgres \
  --password "$PG_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --table-mapping public.events:public_events \
  --table-mapping public.users:public_users \
  --json > pipe.json

PIPE_ID=$(jq -r .id pipe.json)
```

ملاحظات:

* تُنشأ الجداول المتماثلة في قاعدة البيانات `default` على خدمة ClickHouse، وتحمل الأسماء المحددة في أهداف `--table-mapping`. مرّر `--destination-database <name>` لاستخدام قاعدة بيانات أخرى
* يُنشئ `--table-mapping` جداول `ReplacingMergeTree`. تصل التحديثات وعمليات الحذف في صورة إصدارات جديدة من الصفوف، لذا اقرأ الحالة الحالية باستخدام `FINAL` و`WHERE _peerdb_is_deleted = 0`، كما في الاستعلامات أدناه
* يُنشأ المنشور وفتحة النسخ المتماثل تلقائيًا، ويقتصر نطاق المنشور على الجداول المُطابَقة؛ مرّر `--publication-name` إذا أردت استخدام منشور تديره بنفسك
* استخدم اسم المضيف المباشر لـ Postgres؛ إذ إن replication غير مدعومة عبر PgBouncer

### انتظر حتى يصل مسار استيعاب البيانات إلى `Running` {#wait-for-pipe}

ينتقل مسار استيعاب البيانات عبر `Provisioning` و`Setup` و(بالنسبة إلى الجداول الأكبر) `Snapshot` قبل أن يصل إلى `Running`، ويستغرق ذلك نحو 4 دقائق لأول مسار استيعاب البيانات في خدمة. وتُعد حالتا `Failed` و`InternalError` نهائيتين:

```bash
while :; do
  STATE=$(clickhousectl cloud clickpipe get "$CH_ID" "$PIPE_ID" --json | jq -r .state)
  case "$STATE" in
    Running) break ;;
    Failed|InternalError) echo "ClickPipe entered terminal state: $STATE" >&2; break ;;
  esac
  sleep 15
done
```

### استعلِم عن البيانات المتماثلة في ClickHouse {#query-clickhouse}

نفّذ استعلامات SQL على خدمة ClickHouse مباشرةً من خلال CLI. عند أول استدعاء، يضيف clickhousectl مفتاح API الخاص بك إلى نقطة نهاية API للاستعلام الخاصة بالخدمة، وينشئ نقطة النهاية عند الحاجة؛ دون إنشاء أي مفتاح جديد. مرِّر `--no-auto-enable` إذا أردت أن تفشل العملية بدلًا من ذلك. يطبع `--format TabSeparated` القيمة المجرّدة، وهي ما تعتمد عليه المقارنة أدناه:

```bash
clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0"
```

يُكتَب السطر الأول إلى stderr، ولا يظهر إلا عندما يغيّر clickhousectl نقطة النهاية:

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
1000000
```

تُنسَخ عمليات الكتابة الجديدة في Postgres باستمرار. أدرِج صفًا وأجرِ poll حتى يصل العدد إلى 1,000,001 (عادةً خلال أقل من دقيقة):

```bash
psql "$PG_URL" -c "INSERT INTO events (event_name, event_type, user_id, user_ip) VALUES ('cdc-test', 'click', 42, '10.0.0.1');"

while [ "$(clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0")" != "1000001" ]; do
  sleep 10
done
```

### الاستعلام عن ClickHouse من Postgres {#query-clickhouse-from-postgres}

يتيح الامتداد [`pg_clickhouse`](/ar/products/managed-postgres/extensions/pg_clickhouse/introduction) لـ Postgres العمل كطبقة استعلام موحّدة لكلٍّ من البيانات المعاملاتية والتحليلية. احصل على اسم مضيف ClickHouse عبر HTTPS، ثم أعدّ الامتداد باستخدام `psql`:

```bash
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol=="https") | .host')

psql "$PG_URL" <<SQL
CREATE EXTENSION pg_clickhouse;
CREATE SERVER ch FOREIGN DATA WRAPPER clickhouse_fdw
       OPTIONS(driver 'http', host '$CH_HOST', dbname 'default', port '8443');
CREATE USER MAPPING FOR CURRENT_USER SERVER ch
       OPTIONS (user 'default', password '$CH_PASSWORD');
CREATE SCHEMA organization;
IMPORT FOREIGN SCHEMA "default" FROM SERVER ch INTO organization;
SQL
```

تم ترك Heredoc بدون علامات اقتباس عمدًا، لكي يستبدل مفسّر الأوامر `$CH_HOST` و`$CH_PASSWORD` قبل أن يصل SQL إلى Postgres. أصبحت الجداول المُكرَّرة الآن مرئية كجداول خارجية في مخطط `organization`؛ وتُنفَّذ الاستعلامات عليها في ClickHouse.

عند القياس على `m6gd.large` باستخدام مجموعة البيانات هذه، تعمل الاستعلامات التحليلية أسرع بمقدار 6–9 مرات عبر الجداول الخارجية (على سبيل المثال، GROUP BY مع 5 عمليات تجميع: ‏176 مللي ثانية عبر ClickHouse مقابل 1,133 مللي ثانية محليًا؛ وJOIN مع عمليات تجميع: ‏298 مللي ثانية مقابل 2,764 مللي ثانية).

## التنظيف {#cleanup-resources}

احذف ClickPipe أولًا، ثم خدمة Postgres. يؤدي حذف الخدمة إلى إزالة جميع بياناتها نهائيًا. يمكن حذف خدمة Postgres وهي قيد التشغيل:

```bash
clickhousectl cloud clickpipe delete "$CH_ID" "$PIPE_ID"
clickhousectl cloud postgres delete "$PG_ID"
```

لا يمكن حذف خدمة ClickHouse وهي قيد التشغيل مباشرةً. يعمل الخيار `--force` على إيقافها، ثم ينتظر حتى يكتمل الإيقاف، ثم يحذفها:

```bash
clickhousectl cloud service delete "$CH_ID" --force
```
