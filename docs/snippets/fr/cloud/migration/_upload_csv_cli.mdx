---
title: Téléverser un CSV via la CLI
---

Cette page explique comment téléverser un fichier local (par exemple un CSV) dans une table d&#39;un service ClickHouse Cloud depuis la ligne de commande avec l’[Interface en ligne de commande de ClickHouse](/fr/concepts/features/interfaces/cli) (`clickhousectl`). Le déroulement reprend celui de l&#39;assistant de téléversement de fichiers de la console : inspecter le schéma du fichier, créer la table de destination, puis insérer le fichier via HTTP avec l’API de requête — sans avoir besoin du binaire `clickhouse` ni du password du service.

## Prérequis {#cli-prerequisites}

Installez l&#39;interface en ligne de commande de ClickHouse :

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

Le script installe `~/.local/bin/clickhousectl` ainsi qu’un alias `chctl`. Assurez-vous que `~/.local/bin` figure dans votre `PATH`.

Vous aurez également besoin de `jq`.

Les opérations d’écriture nécessitent une [API key](/fr/products/cloud/features/admin-features/api/openapi) dont le rôle permet de gérer les points de terminaison de l’API de requêtes ; la connexion via le navigateur (`clickhousectl cloud auth login`) n’offre qu’un accès en lecture seule. La commande `clickhousectl cloud service query --help` indique les autorisations requises. Connectez-vous avec la clé ; l’option `--interactive` vous invite à saisir la clé et le secret, ce qui évite que le secret ne se retrouve dans l’historique de votre interpréteur de commandes :

```bash
clickhousectl cloud auth login --interactive
```

Vous pouvez également passer `--api-key` et `--api-secret`, ou définir les variables d’environnement `CLICKHOUSE_CLOUD_API_KEY` et `CLICKHOUSE_CLOUD_API_SECRET` ; un agent de codage ou un script doit privilégier les variables d’environnement. La connexion vérifie la clé et affiche l’identité associée ; vous pouvez vérifier à tout moment les identifiants actifs avec `clickhousectl cloud auth whoami`. Si vous appartenez à plusieurs organisations, ajoutez `--org-id <org-id>` (ou `--org-name <name>`) à chaque commande `cloud service` de ce guide.

## Choisir un service {#pick-a-service}

Ce guide suppose que vous disposez déjà d&#39;un service. Si ce n&#39;est pas le cas, consultez le [Quick Start Cloud](/fr/get-started/setup/cloud) pour en créer un depuis la CLI. Récupérez l&#39;ID de votre service à partir de son nom :

```bash
CH_ID=$(clickhousectl cloud service get --name my-service --json | jq -r .id)
```

Un service inactif se réveille dès la première requête. Ce n&#39;est pas le cas d&#39;un service arrêté : démarrez-le avec `clickhousectl cloud service start "$CH_ID"`, puis attendez que `clickhousectl cloud service get "$CH_ID" --json | jq -r .state` renvoie `running`.

## Préparer le fichier {#prepare-the-file}

Supposons que le texte suivant se trouve dans un fichier CSV nommé `data.csv`. La première ligne étant une ligne d&#39;en-tête, le format d&#39;entrée correspondant est `CSVWithNames` :

```text title="data.csv"
user_id,url,visited_at,duration_ms
101,https://clickhouse.com/docs,2026-08-14 09:15:32,4210
102,https://clickhouse.com/pricing,2026-08-14 09:16:01,1830
101,https://clickhouse.com/cloud,2026-08-14 09:17:45,2650
103,https://clickhouse.com/blog,2026-08-15 11:02:10,980
102,https://clickhouse.com/docs/cloud,2026-08-15 11:05:44,3120
```

## Inspecter le schéma {#inspect-the-schema}

Là où l&#39;assistant de la console affiche le type inféré de chaque champ de la source, l&#39;équivalent en CLI consiste à exécuter `DESCRIBE` sur la fonction de table [`format`](/fr/reference/functions/table-functions/format) avec un échantillon du fichier intégré :

```bash
clickhousectl cloud service query "$CH_ID" --format PrettyCompact \
  --query "DESCRIBE format(CSVWithNames, '$(head -n 3 data.csv)')"
```

Lors du premier appel `query`, clickhousectl ajoute votre API key au point de terminaison de l’API de requêtes du service, en créant l&#39;endpoint si nécessaire ; aucune nouvelle clé n&#39;est créée. Passez `--no-auto-enable` pour que la commande échoue plutôt. Lorsque la CLI modifie l&#39;endpoint, elle affiche la première ligne ci-dessous sur stderr :

```text
Binding the authenticated API key to the Query API endpoint for service 'my-service'...
   ┌─name────────┬─type───────────────┬─default_type─┬─default_expression─┬─comment─┬─codec_expression─┬─ttl_expression─┐
1. │ user_id     │ Nullable(Int64)    │              │                    │         │                  │                │
2. │ url         │ Nullable(String)   │              │                    │         │                  │                │
3. │ visited_at  │ Nullable(DateTime) │              │                    │         │                  │                │
4. │ duration_ms │ Nullable(Int64)    │              │                    │         │                  │                │
   └─────────────┴────────────────────┴──────────────┴────────────────────┴─────────┴──────────────────┴────────────────┘
```

L&#39;échantillon est inséré dans un littéral de chaîne SQL : il ne doit donc contenir ni single quotes ni backslashes ; pour les fichiers qui en contiennent, échappez-les ou écrivez tout simplement le `CREATE TABLE` à la main.

## Créer la table {#create-the-table}

Tout ce que propose l&#39;étape « Configure table » de l&#39;assistant — ajuster les types inférés, la nullabilité, les valeurs par défaut, les champs exclus, le table engine, ainsi que les expressions de sorting, de partitioning et de primary key — revient ici à un simple [`CREATE TABLE`](/fr/reference/statements/create/table). Par exemple, pour affiner les types inférés et choisir une sorting key :

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "CREATE TABLE default.website_visits (
    user_id UInt32,
    url String,
    visited_at DateTime,
    duration_ms UInt32
  ) ENGINE = MergeTree
  ORDER BY (user_id, visited_at)"
```

La commande affiche `OK` sur stderr. Si vous préférez charger les données dans une table existante, ignorez cette étape.

## Téléverser le fichier {#upload-the-file}

`INSERT ... FORMAT` lit les données depuis stdin ; il faut donc rediriger la requête et le fichier ensemble via un pipe :

```bash
printf 'INSERT INTO default.website_visits FORMAT CSVWithNames\n' | cat - data.csv \
  | clickhousectl cloud service query "$CH_ID"
```

La commande affiche `OK`.

<Warning>
  **Transmettez la requête et les données ensemble**

  Passer l&#39;`INSERT` via `--query` puis rediriger ou piper le fichier vers stdin (`--query "INSERT ..." < data.csv`) ne fonctionne pas : `--query` ne lit jamais stdin, les données ne vont donc nulle part. La CLI refuse d&#39;emblée cette combinaison plutôt que de n&#39;insérer silencieusement aucune donnée — elle se termine avec le code `1`, n&#39;insère aucune ligne et affiche :

  ```text
  Error: --query cannot be combined with SQL or data on stdin. The Query API sends one request body, so redirected data is never read. Pipe the statement and its data together on stdin instead: printf 'INSERT INTO t FORMAT CSV\n' | cat - data.csv | clickhousectl cloud service query --id <id>. Or read a whole statement from stdin with --queries-file -.
  ```

  Envoyez toujours la requête et les données via stdin en un seul flux, comme illustré ci-dessus. Seul un stdin transportant effectivement des données entre en conflit avec `--query` : `--query` seul continue donc de fonctionner dans les scripts et les pipelines où stdin n&#39;est pas un terminal.
</Warning>

Vérifiez que les lignes ont bien été insérées :

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT count() FROM default.website_visits"
```

```text
{"count()":5}
```

```bash
clickhousectl cloud service query "$CH_ID" --format PrettyCompact \
  --query "SELECT * FROM default.website_visits ORDER BY visited_at"
```

```text
   ┌─user_id─┬─url───────────────────────────────┬──────────visited_at─┬─duration_ms─┐
1. │     101 │ https://clickhouse.com/docs       │ 2026-08-14 09:15:32 │        4210 │
2. │     102 │ https://clickhouse.com/pricing    │ 2026-08-14 09:16:01 │        1830 │
3. │     101 │ https://clickhouse.com/cloud      │ 2026-08-14 09:17:45 │        2650 │
4. │     103 │ https://clickhouse.com/blog       │ 2026-08-15 11:02:10 │         980 │
5. │     102 │ https://clickhouse.com/docs/cloud │ 2026-08-15 11:05:44 │        3120 │
   └─────────┴───────────────────────────────────┴─────────────────────┴─────────────┘
```

## Téléverser des fichiers volumineux {#upload-large-files}

L&#39;API de requête cesse d&#39;attendre au bout d&#39;environ 30 secondes. Une requête `INSERT` ayant expiré peut malgré tout avoir été exécutée : vérifiez donc le nombre de lignes avant toute nouvelle tentative. Pour les fichiers volumineux, effectuez plutôt l&#39;insertion via le protocole natif avec [`clickhouse client`](/fr/concepts/features/interfaces/client), qui lit les données depuis stdin. `clickhousectl local use latest` installe la dernière version de ClickHouse et crée un lien symbolique vers `~/.local/bin/clickhouse`. Définissez `CH_PASSWORD` avec le mot de passe de l&#39;utilisateur `default` (`clickhousectl cloud service reset-password "$CH_ID"` en génère un nouveau en cas de perte), récupérez l&#39;hôte `nativesecure`, puis lancez l&#39;insertion :

```bash
clickhousectl local use latest
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol == "nativesecure") | .host')
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query 'INSERT INTO default.website_visits FORMAT CSVWithNames' < data.csv
```

Les connexions directes doivent être autorisées par la liste d’accès IP du service.

## Autres formats de fichier {#other-file-formats}

Le même principe s&#39;applique à tout [format d&#39;entrée](/fr/reference/formats/index) pris en charge par ClickHouse — y compris tous les formats acceptés par l&#39;assistant de téléversement de la console, tels que `CSV`, `JSONEachRow` et `TabSeparatedWithNames`. Pour un autre format, veillez à modifier le nom du format de façon cohérente à la fois dans l&#39;étape d&#39;inférence de schéma `DESCRIBE format(...)` et dans l&#39;instruction `INSERT ... FORMAT`, et utilisez un fichier d&#39;exemple correspondant à ce format (un exemple TSV pour `TabSeparatedWithNames`, un exemple JSON-lines pour `JSONEachRow`, etc.). Par exemple, l&#39;étape de téléversement d&#39;un fichier TSV devient :

```bash
printf 'INSERT INTO default.website_visits FORMAT TabSeparatedWithNames\n' | cat - data.tsv \
  | clickhousectl cloud service query "$CH_ID"
```

## Nettoyage {#cleanup}

S&#39;il s&#39;agissait d&#39;un simple essai, supprimez la table pour effacer les données importées :

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "DROP TABLE default.website_visits"
```
