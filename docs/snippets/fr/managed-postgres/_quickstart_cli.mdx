---
title: Guide de démarrage rapide CLI
---

Cette page explique comment provisionner ClickHouse Managed Postgres, charger des données, les répliquer vers ClickHouse et exécuter des requêtes sur celles-ci, le tout depuis la ligne de commande avec [clickhousectl](/fr/concepts/features/interfaces/cli) et `psql`. À l’exception de la connexion facultative avec `--interactive`, les commandes s’exécutent en mode non interactif. `clickhousectl` renvoie du JSON avec `--json`, ou automatiquement lorsqu’il détecte un agent de code ; passez `--format` à `cloud service query` pour obtenir des valeurs brutes.

## Prérequis {#prerequisites}

Installez clickhousectl :

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

Le script installe `~/.local/bin/clickhousectl` ainsi qu&#39;un alias `chctl`. Assurez-vous que `~/.local/bin` figure dans votre `PATH`.

Vous aurez également besoin de `psql` (outils client PostgreSQL ; sur macOS, `brew install libpq`) et de `jq`.

Les opérations d&#39;écriture (création, suppression) nécessitent une [API key](/fr/products/cloud/features/admin-features/api/openapi) ; la connexion OAuth (`clickhousectl cloud auth login` sans indicateur) ne donne qu&#39;un accès en lecture seule. Connectez-vous avec votre clé ; l&#39;option `--interactive` vous invite à saisir la clé et le secret, ce qui évite que le secret n&#39;apparaisse dans l&#39;historique de votre interpréteur de commandes :

```bash
clickhousectl cloud auth login --interactive
```

Vous pouvez également transmettre la clé et le secret à `clickhousectl cloud auth login` via `--api-key` et `--api-secret`, ou définir les variables d’environnement `CLICKHOUSE_CLOUD_API_KEY` et `CLICKHOUSE_CLOUD_API_SECRET`. La connexion vérifie les identifiants et affiche l’identité associée ; vous pourrez la revérifier plus tard avec `clickhousectl cloud auth whoami`. Si vous appartenez à plusieurs organisations, ajoutez `--org-id <id>` (ou `--org-name <name>`) à chaque commande.

## Partie 1 : Créer Postgres et charger les données {#part-1-create-and-load}

### Créer un service Postgres {#create-postgres-service}

Créez le service et conservez la réponse, car le mot de passe n&#39;est affiché qu&#39;une seule fois :

```bash
clickhousectl cloud postgres create \
  --name quickstart-pg \
  --region us-east-1 \
  --size m6gd.large \
  --pg-version 18 \
  --json > pg.json
```

AWS est le fournisseur par défaut. GCP est en aperçu privé ; pour l’utiliser, passez `--provider gcp` avec une région et une taille GCP, par exemple `--region us-central1 --size c4-standard-lssd-4`.

Sans indicateur d’accès, le service accepte les connexions depuis n’importe quelle adresse IPv4 ou IPv6 sur Postgres (5432) et PgBouncer (6432). Pour restreindre l’accès, passez une règle `--ip-allow` par CIDR et par plage de ports, par exemple `--ip-allow '203.0.113.0/24:5432..6432=office'`. Dès que vous définissez une règle, seules les règles indiquées s’appliquent. Pour modifier les règles par la suite, exécutez `clickhousectl cloud postgres update <postgres-id>` avec `--add-ip-allow <rule>` ou `--remove-ip-allow <rule-id>` ; la commande `cloud postgres get` affiche les ID des règles.

Récupérez les informations dont vous aurez besoin pour la suite de ce guide :

```bash
PG_ID=$(jq -r .id pg.json)
PG_URL="$(jq -r .connectionString pg.json | sed 's/sslmode=require/sslmode=verify-full/')&sslrootcert=pg-ca.pem"
```

Passer `sslmode` à `verify-full` et ajouter `sslrootcert` permet à `psql` de vérifier le certificat serveur à l&#39;aide de l&#39;AC que vous téléchargerez ci-dessous. Avec la valeur par défaut `sslmode=require`, `psql` chiffre la connexion, mais ne vérifie pas l&#39;identité du serveur.

En cas de perte du mot de passe, générez-en un nouveau avec `clickhousectl cloud postgres reset-password "$PG_ID" --generate`.

### Attendez que le service soit provisionné {#wait-for-provisioning}

Le provisionnement prend quelques minutes. Vérifiez régulièrement jusqu’à ce que l’état soit `running` :

```bash
while [ "$(clickhousectl cloud postgres get "$PG_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

### Télécharger le certificat de CA {#download-ca-certificate}

Chaque instance ClickHouse Managed Postgres dispose de sa propre AC, qui n&#39;est pas reconnue publiquement. Enregistrez son certificat dans un fichier ; `psql` et le ClickPipe de la Partie 2 s&#39;en servent tous deux pour la vérification TLS :

```bash
clickhousectl cloud postgres certs get "$PG_ID" --output pg-ca.pem
```

### Charger des données d’exemple {#load-sample-data}

Créez deux tables, puis insérez 1 million d’événements avec `psql` :

```bash
psql "$PG_URL" <<'SQL'
\timing
CREATE TABLE events (
   event_id SERIAL PRIMARY KEY,
   event_name VARCHAR(255) NOT NULL,
   event_type VARCHAR(100),
   event_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   event_data JSONB,
   user_id INT,
   user_ip INET,
   is_active BOOLEAN DEFAULT TRUE,
   created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
   user_id SERIAL PRIMARY KEY,
   name VARCHAR(100),
   country VARCHAR(50),
   platform VARCHAR(50)
);

INSERT INTO events (event_name, event_type, event_timestamp, event_data, user_id, user_ip)
SELECT
   'Event ' || gs::text AS event_name,
   CASE
       WHEN random() < 0.5 THEN 'click'
       WHEN random() < 0.75 THEN 'view'
       WHEN random() < 0.9 THEN 'purchase'
       WHEN random() < 0.98 THEN 'signup'
       ELSE 'logout'
   END AS event_type,
   NOW() - INTERVAL '1 day' * (gs % 365) AS event_timestamp,
   jsonb_build_object('key', 'value' || gs::text, 'additional_info', 'info_' || (gs % 100)::text) AS event_data,
   GREATEST(1, LEAST(1000, FLOOR(POWER(random(), 2) * 1000) + 1)) AS user_id,
   ('192.168.1.' || ((gs % 254) + 1))::inet AS user_ip
FROM
   generate_series(1, 1000000) gs;

INSERT INTO users (name, country, platform)
SELECT
    first_names[first_idx] || ' ' || last_names[last_idx] AS name,
    CASE
        WHEN random() < 0.25 THEN 'India'
        WHEN random() < 0.5 THEN 'USA'
        WHEN random() < 0.7 THEN 'Germany'
        WHEN random() < 0.85 THEN 'China'
        ELSE 'Other'
    END AS country,
    CASE
        WHEN random() < 0.2 THEN 'iOS'
        WHEN random() < 0.4 THEN 'Android'
        WHEN random() < 0.6 THEN 'Web'
        WHEN random() < 0.75 THEN 'Windows'
        WHEN random() < 0.9 THEN 'MacOS'
        ELSE 'Linux'
    END AS platform
FROM
    generate_series(1, 1000) AS seq
    CROSS JOIN LATERAL (
        SELECT
            array['Alice', 'Bob', 'Charlie', 'Diana', 'Eve', 'Frank', 'Grace', 'Hank', 'Ivy', 'Jack', 'Liam', 'Olivia', 'Noah', 'Emma', 'Sophia', 'Benjamin', 'Isabella', 'Lucas', 'Mia', 'Amelia', 'Aarav', 'Riya', 'Arjun', 'Ananya', 'Wei', 'Li', 'Huan', 'Mei', 'Hans', 'Klaus', 'Greta', 'Sofia'] AS first_names,
            array['Smith', 'Johnson', 'Williams', 'Brown', 'Jones', 'Garcia', 'Miller', 'Davis', 'Martinez', 'Taylor', 'Anderson', 'Thomas', 'Jackson', 'White', 'Harris', 'Martin', 'Thompson', 'Moore', 'Lee', 'Perez', 'Sharma', 'Patel', 'Gupta', 'Reddy', 'Zhang', 'Wang', 'Chen', 'Liu', 'Schmidt', 'Müller', 'Weber', 'Fischer'] AS last_names,
            1 + (seq % 32) AS first_idx,
            1 + ((seq / 32)::int % 32) AS last_idx
    ) AS names;
SQL
```


L’insertion de 1 M de lignes prend environ 20 secondes sur `m6gd.large` (l’une des plus petites tailles), grâce au stockage NVMe. Vérifiez-le avec une requête ; le nombre de lignes varie d’une exécution à l’autre, car les données sont générées avec `random()` :

```bash
psql "$PG_URL" -c "SELECT event_type, COUNT(*) FROM events GROUP BY event_type ORDER BY 2 DESC;"
```

## Partie 2 : Répliquer dans ClickHouse {#part-2-replicate}

### Créer un service ClickHouse {#create-clickhouse-service}

Créez un service dans la même région et enregistrez la réponse ; le mot de passe n’apparaît que dans la réponse de création :

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json

CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
```

Attendez qu’il soit actif ; le ClickPipe nécessite une destination active :

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

Pour utiliser plutôt un service existant, définissez `CH_ID` à partir de `clickhousectl cloud service list` et `CH_PASSWORD` sur le mot de passe de l’utilisateur `default`, requis à l’étape `pg_clickhouse`.

### Répliquer les tables vers ClickHouse {#replicate-to-clickhouse}

Créez un ClickPipe CDC Postgres sur le service ClickHouse, en le faisant pointer vers le nom d’hôte de ClickHouse Managed Postgres. Le pipeline d’ingestion copie les lignes existantes, puis maintient ClickHouse synchronisé au fil des modifications. Par défaut, ClickPipes vérifie le certificat de la source : transmettez donc l’AC téléchargée dans la Partie 1 à l’aide de l’option `--ca-certificate` :

```bash
PG_HOST=$(jq -r .hostname pg.json)
PG_PASSWORD=$(jq -r .password pg.json)

clickhousectl cloud clickpipe create postgres "$CH_ID" \
  --name quickstart-sync \
  --host "$PG_HOST" \
  --pg-database postgres \
  --username postgres \
  --password "$PG_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --table-mapping public.events:public_events \
  --table-mapping public.users:public_users \
  --json > pipe.json

PIPE_ID=$(jq -r .id pipe.json)
```

Notes :

* Les tables répliquées sont créées dans la base de données `default` du service ClickHouse, sous les noms définis par les cibles de `--table-mapping`. Passez `--destination-database <name>` pour utiliser une autre base de données
* `--table-mapping` crée des tables `ReplacingMergeTree`. Les mises à jour et les suppressions arrivent sous forme de nouvelles versions de ligne : lisez donc l&#39;état courant avec `FINAL` et `WHERE _peerdb_is_deleted = 0`, comme le font les requêtes ci-dessous
* La publication et le slot de réplication sont créés automatiquement, la publication étant limitée aux tables mappées ; passez `--publication-name` pour utiliser une publication que vous gérez vous-même
* Utilisez directement le nom d’hôte Postgres ; la réplication n&#39;est pas prise en charge via PgBouncer

### Attendez que le pipeline d’ingestion passe à l’état `Running` {#wait-for-pipe}

Le pipeline d’ingestion passe par `Provisioning`, `Setup` et (pour les tables plus volumineuses) `Snapshot` avant de passer à l’état `Running`, ce qui prend environ 4 minutes pour le premier pipeline d’ingestion sur un service. `Failed` et `InternalError` sont des états terminaux :

```bash
while :; do
  STATE=$(clickhousectl cloud clickpipe get "$CH_ID" "$PIPE_ID" --json | jq -r .state)
  case "$STATE" in
    Running) break ;;
    Failed|InternalError) echo "ClickPipe entered terminal state: $STATE" >&2; break ;;
  esac
  sleep 15
done
```

### Interroger les données répliquées dans ClickHouse {#query-clickhouse}

Exécutez des requêtes SQL sur le service ClickHouse directement depuis la CLI. Lors du premier appel, clickhousectl ajoute votre API key à l&#39;endpoint Query API du service, en créant cet endpoint si nécessaire ; aucune nouvelle clé n&#39;est créée. Passez `--no-auto-enable` pour que la commande échoue plutôt. `--format TabSeparated` affiche la valeur brute, sur laquelle s&#39;appuie la comparaison ci-dessous :

```bash
clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0"
```

La première ligne est écrite sur stderr et n’apparaît que lorsque clickhousectl modifie l’endpoint :

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
1000000
```

Les nouvelles écritures dans Postgres sont répliquées en continu. Insérez une ligne, puis interrogez régulièrement jusqu’à ce que le nombre atteigne 1 000 001 (généralement en moins d’une minute) :

```bash
psql "$PG_URL" -c "INSERT INTO events (event_name, event_type, user_id, user_ip) VALUES ('cdc-test', 'click', 42, '10.0.0.1');"

while [ "$(clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0")" != "1000001" ]; do
  sleep 10
done
```

### Interroger ClickHouse depuis Postgres {#query-clickhouse-from-postgres}

L’extension [`pg_clickhouse`](/fr/products/managed-postgres/extensions/pg_clickhouse/introduction) permet à Postgres de servir de couche de requête unifiée pour les données transactionnelles et analytiques. Récupérez le nom d’hôte HTTPS de ClickHouse, puis configurez l’extension via `psql` :

```bash
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol=="https") | .host')

psql "$PG_URL" <<SQL
CREATE EXTENSION pg_clickhouse;
CREATE SERVER ch FOREIGN DATA WRAPPER clickhouse_fdw
       OPTIONS(driver 'http', host '$CH_HOST', dbname 'default', port '8443');
CREATE USER MAPPING FOR CURRENT_USER SERVER ch
       OPTIONS (user 'default', password '$CH_PASSWORD');
CREATE SCHEMA organization;
IMPORT FOREIGN SCHEMA "default" FROM SERVER ch INTO organization;
SQL
```

Le heredoc est volontairement non guillemeté, afin que le shell substitue `$CH_HOST` et `$CH_PASSWORD` avant que le SQL n&#39;arrive à Postgres. Les tables répliquées sont désormais visibles comme des tables étrangères dans le schéma `organization` ; les requêtes qui les ciblent s&#39;exécutent dans ClickHouse.

Mesurées sur `m6gd.large` avec ce jeu de données, les requêtes analytiques s&#39;exécutent 6 à 9 fois plus vite via les tables étrangères (par exemple, un GROUP BY avec 5 agrégations : 176 ms via ClickHouse contre 1 133 ms en local ; un JOIN avec agrégations : 298 ms contre 2 764 ms).

## Nettoyage {#cleanup-resources}

Supprimez d’abord le ClickPipe, puis le service Postgres. La suppression d’un service entraîne la suppression définitive de toutes ses données. Un service Postgres peut être supprimé pendant qu’il est en cours d’exécution :

```bash
clickhousectl cloud clickpipe delete "$CH_ID" "$PIPE_ID"
clickhousectl cloud postgres delete "$PG_ID"
```

Un service ClickHouse en cours d’exécution ne peut pas être supprimé directement. `--force` l’arrête, attend la fin de l’arrêt, puis le supprime :

```bash
clickhousectl cloud service delete "$CH_ID" --force
```
