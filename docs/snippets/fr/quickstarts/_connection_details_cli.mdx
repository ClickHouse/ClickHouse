---
title: "Informations de connexion en CLI"
---

Cette page explique comment retrouver les informations de connexion d&#39;un service ClickHouse Cloud existant — hostname, numéros de port, nom d’utilisateur et mot de passe — depuis la ligne de commande, à l&#39;aide de l’[Interface en ligne de commande de ClickHouse](/fr/concepts/features/interfaces/cli) (`clickhousectl`). Hormis l&#39;authentification, les commandes sont non interactives. `clickhousectl` produit du JSON avec `--json`, ou automatiquement lorsqu&#39;il est exécuté par un agent de code.

## Prérequis {#prerequisites}

Installez l&#39;interface en ligne de commande de ClickHouse :

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

Le script installe `~/.local/bin/clickhousectl` ainsi qu&#39;un alias `chctl`. Assurez-vous que `~/.local/bin` figure dans votre `PATH`.

Vous avez également besoin de `jq`.

Pour les étapes en lecture seule (`service list`, `service get`), une connexion via le navigateur suffit. Comme elle ouvre un navigateur, une intervention humaine est nécessaire pour la mener à bien :

```bash
clickhousectl cloud auth login
```

La connexion via le navigateur est en lecture seule. Les étapes d’écriture ci-dessous nécessitent une [API key](/fr/products/cloud/features/admin-features/api/openapi) : `cloud service start` ou `cloud service wake` (uniquement si votre service est à l’état `stopped` ou `idle`) et `reset-password`. Pour vous connecter avec une clé, exécutez `clickhousectl cloud auth login --interactive` : la commande vous invite à saisir la clé et le secret, et évite que le secret n’apparaisse dans l’historique de votre interpréteur de commandes. Vous pouvez aussi passer les options `--api-key` et `--api-secret`, ou définir les variables d’environnement `CLICKHOUSE_CLOUD_API_KEY` et `CLICKHOUSE_CLOUD_API_SECRET` ; un agent de code ou un script doit utiliser les variables d’environnement.

La connexion vérifie les identifiants et affiche l’identity associée, que vous pouvez consulter à tout moment avec `clickhousectl cloud auth whoami`. Si vous appartenez à plusieurs organisations, ajoutez `--org-id <org-id>` (ou `--org-name <name>`) à chaque commande `cloud service` de ce guide.

Vous devez également disposer d’un service ClickHouse Cloud existant dont vous récupérerez les informations de connexion, par exemple un service créé en suivant le [Démarrage rapide Cloud](/fr/get-started/setup/cloud).

## Trouver votre service {#find-your-service}

Listez les services de votre organisation et notez l&#39;ID de celui auquel vous souhaitez vous connecter :

```bash
clickhousectl cloud service list --json | jq -r '.[] | [.id, .name, .state] | @tsv'
```

```text
9c2d4e61-7a35-49c8-8f0e-2b5a1d7c3e90	my-first-service	running
```

Conservez l&#39;ID du service : toutes les autres commandes de ce guide le prennent en argument. Pour le retrouver par son nom :

```bash
CH_ID=$(clickhousectl cloud service get --name my-first-service --json | jq -r .id)
```

Le service doit être en cours d&#39;exécution pour pouvoir vérifier la connectivité à une étape ultérieure. Si son state est `stopped`, démarrez-le et interrogez-le jusqu&#39;à ce qu&#39;il passe à `running` :

```bash
clickhousectl cloud service start "$CH_ID"
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

Un service `idle` du fait de l&#39;idle scaling se réveille automatiquement à la première connexion : aucune action n&#39;est donc nécessaire ici. Pour le réveiller à l&#39;avance, exécutez `clickhousectl cloud service wake "$CH_ID"` et interrogez-le de la même manière.

## Récupérer vos détails de connexion {#get-your-connection-details}

`clickhousectl cloud service get` renvoie l&#39;ensemble des détails du service, dont un endpoint par protocole exposé. Enregistrez la réponse et extrayez-en les éléments dont vous avez besoin :

```bash
clickhousectl cloud service get "$CH_ID" --json > service.json
jq '.endpoints' service.json
```

```json
[
  {
    "host": "abc123.us-east-1.aws.clickhouse.cloud",
    "port": 9440,
    "protocol": "nativesecure"
  },
  {
    "host": "abc123.us-east-1.aws.clickhouse.cloud",
    "port": 8443,
    "protocol": "https"
  }
]
```

Voici les deux principaux protocoles réseau de ClickHouse Cloud, chacun sur son propre port :

* **Protocole natif (`nativesecure`, port 9440)** — un protocole binaire utilisé par `clickhouse-client`, `clickhouse-local` et la plupart des drivers propres à un langage. C&#39;est l&#39;option la plus rapide et elle prend en charge toutes les fonctionnalités de ClickHouse. TLS est obligatoire sur Cloud.
* **Protocole HTTPS (`https`, port 8443)** — une interface basée sur HTTP, utile pour les clients REST, `curl`, les outils web et les drivers qui privilégient HTTP. Requiert également TLS sur Cloud.

Les deux protocoles exigent le chiffrement TLS pour se connecter à ClickHouse Cloud : la connexion en plaintext est impossible. La plupart des outils s&#39;en chargent automatiquement dès lors que vous indiquez le bon port, mais il peut être nécessaire de passer un flag `--secure` ou de définir `ssl=true`, selon le client. Pour la plupart des quickstarts et des workflows CLI de cette série, vous utiliserez le **protocole natif sur le port 9440**.

Extrayez le hostname et les ports :

```bash
CH_HOST=$(jq -r '.endpoints[] | select(.protocol == "nativesecure") | .host' service.json)
CH_NATIVE_PORT=$(jq -r '.endpoints[] | select(.protocol == "nativesecure") | .port' service.json)
CH_HTTPS_PORT=$(jq -r '.endpoints[] | select(.protocol == "https") | .port' service.json)
```

Le nom d&#39;utilisateur est `default`, sauf si vous avez créé d&#39;autres utilisateurs de base de données.

## Obtenir un mot de passe {#get-a-password}

Le mot de passe de l&#39;utilisateur `default` n&#39;est renvoyé qu&#39;une seule fois, par `clickhousectl cloud service create` — aucun appel d&#39;API ou de CLI ne permet de le récupérer par la suite. Si vous l&#39;avez conservé au moment de la création, affectez-le à la variable utilisée dans les étapes suivantes et passez la réinitialisation :

```bash
CH_PASSWORD='<your saved password>'
```

En cas de perte, générez-en un nouveau :

```bash
CH_PASSWORD=$(clickhousectl cloud service reset-password "$CH_ID" --json | jq -r .password)
```

<Warning>
  `reset-password` remplace le mot de passe de l&#39;utilisateur `default`. La modification met quelques secondes à s&#39;appliquer : d&#39;ici là, le nouveau mot de passe est refusé et l&#39;ancien fonctionne toujours ; relancez donc la première connexion pendant quelques instants si elle échoue. Ensuite, tout client encore configuré avec l&#39;ancien mot de passe ne parvient plus à s&#39;authentifier. Si le service appartient à un [warehouse](/fr/products/cloud/features/infrastructure/warehouses), les utilisateurs de base de données sont partagés entre tous les services de ce warehouse : la réinitialisation change donc aussi le mot de passe de tous les services associés. Comme le mot de passe initial, le nouveau mot de passe n&#39;est affiché qu&#39;une seule fois : conservez-le en lieu sûr.
</Warning>

## Enregistrez vos détails de connexion pour les réutiliser {#save-your-connection-details-for-reuse}

Vous utiliserez fréquemment ces détails de connexion tout au long des quickstarts. Pour éviter de les ressaisir à chaque fois, vous pouvez les exporter sous forme de variables d&#39;environnement dans votre session de terminal :

```bash
export CLICKHOUSE_HOST=$CH_HOST
export CLICKHOUSE_USER=default
export CLICKHOUSE_PASSWORD=$CH_PASSWORD
```

<Warning>
  Ces variables d&#39;environnement ne persistent que le temps de votre session de terminal en cours. Ne stockez pas de mots de passe dans les fichiers de profil du shell (`.bashrc`, `.zshrc`) et ne les intégrez pas à un système de contrôle de version.
</Warning>

## Vérifier la connectivité {#verify-connectivity}

Vérifiez l&#39;interface HTTPS (port 8443) avec `curl` :

```bash
curl --user "$CLICKHOUSE_USER:$CLICKHOUSE_PASSWORD" \
  "https://$CLICKHOUSE_HOST:8443/?query=SELECT%201"
```

```text
1
```

Vérifiez le protocole natif (port 9440) avec [**clickhouse client**](/fr/concepts/features/interfaces/client). L’Interface en ligne de commande de ClickHouse gère le binaire `clickhouse` pour vous : si vous ne l&#39;avez pas encore, `clickhousectl local use latest` installe la dernière version de ClickHouse et crée un lien symbolique vers `~/.local/bin/clickhouse`. Ensuite :

```bash
clickhouse client --host "$CLICKHOUSE_HOST" --secure --port 9440 \
  --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --query "SELECT concat('Connected to ClickHouse ', version(), ' as ', currentUser())"
```

```text
Connected to ClickHouse 26.2.1.558 as default
```

## Nettoyage {#cleanup}

Ce guide se contente de lire les metadata du service et (éventuellement) de réinitialiser un mot de passe — il ne crée aucune nouvelle cloud resource, il n&#39;y a donc rien à nettoyer.

Une exception : si votre service était `stopped` et que vous l&#39;avez démarré uniquement pour vérifier la connectivité, il reste désormais actif et le compute est facturé. Arrêtez-le de nouveau si vous n&#39;avez pas encore besoin qu&#39;il soit en cours d&#39;exécution :

```bash
clickhousectl cloud service stop "$CH_ID"
```
