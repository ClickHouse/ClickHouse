This page covers creating your first ClickHouse Cloud service and loading the UK Property Price Paid example dataset, all from the command line with the [ClickHouse CLI](/products/cloud/features/cli) (`clickhousectl`). Commands are non-interactive; `clickhousectl` emits JSON with `--json`.

## Prerequisites {#cli-prerequisites}

Install the ClickHouse CLI:

```bash
curl https://clickhouse.com/cli | sh
```

You also need `jq`.

You need a ClickHouse Cloud account. If you don't have one yet, `clickhousectl cloud auth signup` opens the sign-up page in your browser. No credit card is required - the free trial gives you $300 in credits and 30 days to explore ClickHouse Cloud.

Write operations (create, delete) require [API key authentication](/products/cloud/features/admin-features/api/openapi); OAuth login is read-only:

```bash
clickhousectl cloud auth login --api-key <YOUR_KEY> --api-secret <YOUR_SECRET>
```

Alternatively, set the `CLICKHOUSE_CLOUD_API_KEY` and `CLICKHOUSE_CLOUD_API_SECRET` environment variables. Verify with `clickhousectl cloud auth status`; expect an entry with scope `read/write`.

## Create a service {#cli-create-a-service}

The console's service creation form maps directly to flags on `clickhousectl cloud service create`: pick a name, a cloud provider (`aws`, `gcp`, or `azure`), a region close to you, and a size. The equivalent of the **Mini 12GB** (1 replica) option recommended for this quickstart is one replica with memory fixed at 12 GB.

Create the service and save the response; the password for the `default` user is shown only once:

```bash
clickhousectl cloud service create \
  --name my-first-service \
  --provider aws \
  --region us-east-1 \
  --num-replicas 1 \
  --min-replica-memory-gb 12 \
  --max-replica-memory-gb 12 \
  --json > ch.json
```

The response includes the service ID, endpoints, and the generated password (trimmed here; the full response also contains scaling settings, the IP access list, and tags):

```json
{
  "password": "mX4nRq8w_-KvzT2sLp1d",
  "service": {
    "id": "8c3f52a1-9e2d-4b7a-a1c4-d5e6f7a8b9c0",
    "name": "my-first-service",
    "provider": "aws",
    "region": "us-east-1",
    "state": "provisioning",
    "endpoints": [
      {
        "host": "firstsvc-x7k2p9.us-east-1.aws.clickhouse.cloud",
        "port": 9440,
        "protocol": "nativesecure"
      },
      {
        "host": "firstsvc-x7k2p9.us-east-1.aws.clickhouse.cloud",
        "port": 8443,
        "protocol": "https"
      }
    ],
    "numReplicas": 1,
    "minReplicaMemoryGb": 12.0,
    "maxReplicaMemoryGb": 12.0
  }
}
```

Extract what the rest of this guide needs:

```bash
CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
CH_HOST=$(jq -r '.service.endpoints[] | select(.protocol=="nativesecure") | .host' ch.json)
```

If the password is lost, generate a new one with `clickhousectl cloud service reset-password "$CH_ID"`.

Services created with `clickhousectl` default to an IP access list that allows all (`0.0.0.0/0`). To restrict access, pass `--ip-allow` when creating the service; see ["Setting IP filters"](/products/cloud/guides/security/connectivity/setting-ip-filters).

## Wait for the service to provision {#cli-wait-for-provisioning}

Provisioning typically takes under a minute. Poll until the state is `running`:

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

## Load the example dataset {#cli-load-the-example-dataset}

The console's **UK Property Price Paid** sample import creates a table named `pp_complete` in the `default` database and fills it with about 30 million rows of property sales. From the CLI, create the same table and load it from the public source file with a `url`-based `INSERT ... SELECT`.

`clickhousectl cloud service query` runs SQL over HTTP - no local `clickhouse` binary or service password required. The first call provisions a Query API endpoint and a service-scoped API key automatically:

```bash
clickhousectl cloud service query --id "$CH_ID" \
  --query "CREATE TABLE pp_complete
(
    price UInt32,
    date Date,
    postcode1 LowCardinality(String),
    postcode2 LowCardinality(String),
    type Enum8('terraced' = 1, 'semi-detached' = 2, 'detached' = 3, 'flat' = 4, 'other' = 0),
    is_new UInt8,
    duration Enum8('freehold' = 1, 'leasehold' = 2, 'unknown' = 0),
    addr1 String,
    addr2 String,
    street LowCardinality(String),
    locality LowCardinality(String),
    town LowCardinality(String),
    district LowCardinality(String),
    county LowCardinality(String)
)
ENGINE = MergeTree
ORDER BY (postcode1, postcode2, addr1, addr2)"
```

```text
Provisioning Query API endpoint + key for service 'my-first-service'...
OK
```

The default output format is `PrettyCompact` on a TTY and `TabSeparated` when piped; pass `--format` (or `--json` for `JSONEachRow`) to pick another.

The source data is a single CSV published by the UK Land Registry. The `INSERT` streams it into the table with the `url` function, preprocessing along the way: it splits the postcode in two, converts the timestamp to a `Date`, turns single-letter codes into readable `Enum` values, and drops columns that aren't useful for analysis (see the [UK property prices dataset](/getting-started/example-datasets/uk-price-paid) for details).

The load runs for a couple of minutes, which is longer than the Query API's request timeout of about 30 seconds, so run this one statement over the native protocol with [`clickhouse client`](/concepts/features/interfaces/client) instead - it waits for the query to finish. The ClickHouse CLI manages the `clickhouse` binary for you:

```bash
clickhousectl local use latest
```

This installs the latest `clickhouse` binary and symlinks it to `~/.local/bin/clickhouse`, so the plain `clickhouse` command is available globally on your `PATH`. Then run the load, using the hostname and password extracted from the create response:

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query "INSERT INTO pp_complete
SELECT
    toUInt32(price_string) AS price,
    parseDateTimeBestEffortUS(time) AS date,
    splitByChar(' ', postcode)[1] AS postcode1,
    splitByChar(' ', postcode)[2] AS postcode2,
    transform(a, ['T', 'S', 'D', 'F', 'O'], ['terraced', 'semi-detached', 'detached', 'flat', 'other']) AS type,
    b = 'Y' AS is_new,
    transform(c, ['F', 'L', 'U'], ['freehold', 'leasehold', 'unknown']) AS duration,
    addr1,
    addr2,
    street,
    locality,
    town,
    district,
    county
FROM url(
    'http://prod1.publicdata.landregistry.gov.uk.s3-website-eu-west-1.amazonaws.com/pp-complete.csv',
    'CSV',
    'uuid_string String,
    price_string String,
    time String,
    postcode String,
    a String,
    b String,
    c String,
    addr1 String,
    addr2 String,
    street String,
    locality String,
    town String,
    district String,
    county String,
    d String,
    e String'
) SETTINGS max_http_get_redirects=10"
```

When it returns, verify the data landed:

```bash
clickhousectl cloud service query --id "$CH_ID" --format PrettyCompact \
  --query "SELECT formatReadableQuantity(count()) AS rows FROM pp_complete"
```

```text
   ┌─rows──────────┐
1. │ 31.43 million │
   └───────────────┘
```

The dataset grows over time, so your exact row count will differ.

## Query the data {#cli-query-the-data}

Try a few queries to explore the UK property price data.

Find the most expensive properties ever sold:

```bash
clickhousectl cloud service query --id "$CH_ID" --format PrettyCompact \
  --query "SELECT town, district, county, price, date
FROM pp_complete
ORDER BY price DESC
LIMIT 5"
```


Find the average sale price by year:

```bash
clickhousectl cloud service query --id "$CH_ID" --format PrettyCompact \
  --query "SELECT
    toYear(date) AS year,
    round(avg(price)) AS avg_price,
    formatReadableQuantity(count()) AS sales
FROM pp_complete
GROUP BY year
ORDER BY year DESC"
```

## Next steps {#cli-next-steps}

You now have a running ClickHouse Cloud service with about 30 million rows of real data loaded. This service and dataset are used throughout the rest of the quickstart series, starting with [obtaining your Cloud connection details](/get-started/quickstarts/obtain-your-cloud-connection-details).

## Cleanup {#cleanup}

Keep the service if you're continuing with the quickstart series. When you're done with it, deleting the service removes all of its data permanently. `--force` stops a running service first:

```bash
clickhousectl cloud service delete "$CH_ID" --force
```

To keep the data but stop paying for compute, idle the service with `clickhousectl cloud service stop "$CH_ID"` instead.
