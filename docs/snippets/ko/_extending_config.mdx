### collector 구성 확장하기 {#extending-collector-config}

ClickStack에서 제공하는 OTel collector 배포판은 사용자 지정 설정 파일을 마운트하고 환경 변수를 설정하여 기본 구성을 확장할 수 있습니다.

사용자 지정 수신기, 프로세서 또는 파이프라인을 추가하려면 다음을 수행하세요:

1. 추가 구성이 포함된 사용자 지정 설정 파일을 생성합니다
2. 파일을 `/etc/otelcol-contrib/custom.config.yaml`에 마운트합니다
3. 환경 변수 `CUSTOM_OTELCOL_CONFIG_FILE=/etc/otelcol-contrib/custom.config.yaml`를 설정합니다

**예시 사용자 지정 구성:**

```yaml
receivers:
  # Collect logs from local files
  filelog:
    include:
      - /var/log/**/*.log
      - /var/log/syslog
      - /var/log/messages
    start_at: beginning

  # Collect host system metrics
  hostmetrics:
    collection_interval: 30s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization:
            enabled: true
      memory:
        metrics:
          system.memory.utilization:
            enabled: true
      disk:
      network:
      filesystem:
        metrics:
          system.filesystem.utilization:
            enabled: true

service:
  pipelines:
    # Logs pipeline
    logs/host:
      receivers: [filelog]
      processors:
        - memory_limiter
        - transform
        - batch
      exporters:
        - clickhouse
    
    # Metrics pipeline
    metrics/hostmetrics:
      receivers: [hostmetrics]
      processors:
        - memory_limiter
        - batch
      exporters:
        - clickhouse
```

**독립 실행형 collector로 배포:**

```bash
docker run -d \
  -e CUSTOM_OTELCOL_CONFIG_FILE=/etc/otelcol-contrib/custom.config.yaml \
  -e CLICKHOUSE_ENDPOINT=${CLICKHOUSE_ENDPOINT} \
  -e CLICKHOUSE_USER=default \
  -e CLICKHOUSE_PASSWORD=${CLICKHOUSE_PASSWORD} \
  -v "$(pwd)/custom-config.yaml:/etc/otelcol-contrib/custom.config.yaml:ro" \
  -p 4317:4317 -p 4318:4318 \
  clickhouse/clickstack-otel-collector:latest
```

OpAMP를 통해 collector를 관리하려면 `-e OPAMP_SERVER_URL=${OPAMP_SERVER_URL}`도 함께 전달하십시오.

<Note>
  사용자 지정 구성에서는 새 수신기, 커넥터, 프로세서, 파이프라인만 정의해야 합니다. 기본 프로세서(`memory_limiter`, `batch`)와 익스포터(`clickhouse`)는 이미 정의되어 있으므로 이름으로 참조하십시오. 사용자 지정 구성은 기본 구성과 병합되며, 기존 구성 요소를 재정의할 수 없습니다.

  사용자 지정 구성으로 기본 파이프라인의 `processors` 목록을 대체할 수 있습니다. 버전 2.44.0부터는 기본 trace 및 로그 파이프라인의 프로세서 목록에 `transform/session_id`를 반드시 남겨 두십시오. 그렇지 않으면 이전 버전의 브라우저 SDK에서 전송된 이벤트에 `session.id`가 설정되지 않습니다.

  OpAMP 환경(all-in-one 이미지 또는 `OPAMP_SERVER_URL`이 설정된 모든 collector)에서는 기본 파이프라인에 추가한 수신기, 익스포터, 커넥터가 오류 없이 삭제됩니다. 아래 예시처럼 별도의 이름을 지정한 파이프라인에 추가하십시오.
</Note>

더 복잡한 구성이 필요하면 [기본 ClickStack 수집기 구성](https://github.com/hyperdxio/hyperdx/blob/main/docker/otel-collector/config.yaml)과 [ClickHouse exporter 문서](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/exporter/clickhouseexporter/README.md#configuration-options)를 참조하십시오.

#### StatsD 메트릭 수신 {#statsd-receiver}

버전 2.40.0부터 ClickStack 수집기에 [StatsD 수신기](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/statsdreceiver)가 포함되어 있으므로, StatsD 또는 DogStatsD 메트릭을 내보내는 애플리케이션은 해당 메트릭을 collector로 전송할 수 있습니다. `|#env:prod,team:payments`와 같은 DogStatsD `key:value` 태그는 메트릭 속성으로 변환됩니다.

이 수신기는 기본적으로 비활성화되어 있습니다. 사용자 지정 구성을 사용하여 별도의 이름을 가진 파이프라인에 추가하십시오.

```yaml
receivers:
  statsd:
    endpoint: 0.0.0.0:8125

service:
  pipelines:
    metrics/statsd:
      receivers: [statsd]
      processors:
        - memory_limiter
        - batch
      exporters:
        - clickhouse
```

collector 컨테이너에서 UDP 포트 `8125`를 게시하십시오(예: `-p 8125:8125/udp`). StatsD 메트릭에는 `service.name`이 없으므로 서비스 기준 필터(filter)로는 찾을 수 없습니다. 수신기는 collector 프로세스 내에서 메트릭을 집계하므로 각 메트릭은 하나의 collector 인스턴스로만 전송하십시오. 그렇지 않으면 값이 여러 복제본(replicas)에 분할됩니다.

#### 스팬에서 메트릭 도출하기 {#span-metrics}

버전 2.39.0부터 ClickStack 수집기에는 [span metrics connector](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/connector/spanmetricsconnector)가 포함되어 있습니다. 이 커넥터는 collector가 수신한 스팬을 바탕으로 호출 횟수와 소요 시간 히스토그램을 생성하므로, 메트릭 instrumentation을 별도로 구성하지 않아도 서비스별 요청, 오류, 소요 시간 메트릭을 얻을 수 있습니다.

이 커넥터는 기본적으로 비활성화되어 있으므로 사용자 지정 구성으로 추가해야 합니다. trace 파이프라인은 스팬을 커넥터로 내보내고, 메트릭 파이프라인은 커넥터가 생성한 메트릭을 수신합니다. 두 파이프라인에는 각각 고유한 이름을 지정하십시오.

```yaml
connectors:
  span_metrics:
    namespace: traces.span.metrics
    aggregation_temporality: AGGREGATION_TEMPORALITY_DELTA
    histogram:
      exponential:
        max_size: 160
    aggregation_cardinality_limit: 10000
    series_expiration: 5m

service:
  pipelines:
    traces/spanmetrics:
      receivers: [otlp/hyperdx]
      processors:
        - memory_limiter
      exporters: [span_metrics]
    metrics/spanmetrics:
      receivers: [span_metrics]
      processors:
        - memory_limiter
        - batch
      exporters:
        - clickhouse
```

collector는 호출 횟수를 `traces.span.metrics.calls`로, 소요 시간을 `traces.span.metrics.duration`으로 기록합니다. `aggregation_temporality`, `aggregation_cardinality_limit`, `series_expiration`은 그대로 유지하십시오. 이 설정들은 `memory_limiter`로는 보호되지 않는 커넥터의 메모리 사용량을 제한하고, 오래된 시계열이 축출되더라도 발생 횟수가 정확하게 유지되도록 합니다.

Datadog 에이전트의 trace도 포함하려면 `traces/spanmetrics`의 `receivers`에 `datadog`을 추가하십시오. 이때 `datadog` 수신기가 반드시 정의되어 있어야 하며, 그렇지 않으면 collector가 구성을 거부합니다. OpAMP를 사용한다면 collector 구성을 생성하는 ClickStack UI에 `ENABLE_DATADOG_RECEIVER=true` 환경 변수를 설정하십시오. OpAMP를 사용하지 않는다면 사용자 지정 구성에 `datadog` 수신기를 정의하십시오.

#### 구성 구조 {#configuration-structure}

[`receivers`](https://opentelemetry.io/docs/collector/transforming-telemetry/), [`operators`](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/pkg/stanza/docs/operators/README.md), [`processors`](https://opentelemetry.io/docs/collector/configuration/#processors)를 포함해 OTel collector 구성에 대한 자세한 내용은 [OpenTelemetry collector 공식 문서](https://opentelemetry.io/docs/collector/configuration)를 참조하십시오.
