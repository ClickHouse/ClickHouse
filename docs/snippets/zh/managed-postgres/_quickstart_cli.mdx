本页介绍如何仅通过命令行，使用 [clickhousectl](/zh/concepts/features/interfaces/cli) 和 `psql` 完成 ClickHouse Managed Postgres 的预配、数据加载、将数据复制到 ClickHouse 以及查询。除可选的 `--interactive` 登录外，命令均为非交互式。`clickhousectl` 可通过 `--json` 输出 JSON，在检测到 coding agent 时也会自动输出 JSON；为 `cloud service query` 指定 `--format` 即可获取纯文本值。

## 前置条件 {#prerequisites}

安装 clickhousectl：

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

该脚本会安装 `~/.local/bin/clickhousectl` 以及别名 `chctl`。请确保 `~/.local/bin` 已加入您的 `PATH`。

您还需要安装 `psql` (PostgreSQL 客户端工具；在 macOS 上可运行 `brew install libpq` 安装) 和 `jq`。

写操作 (创建、删除) 需要 [API key](/zh/products/cloud/features/admin-features/api/openapi)；OAuth 登录 (不带任何标志运行 `clickhousectl cloud auth login`) 仅具有只读权限。请使用您的 API key 登录；使用 `--interactive` 时会提示您输入 key 和 secret，这样 secret 就不会留在命令行环境的历史记录中：

```bash
clickhousectl cloud auth login --interactive
```

或者，通过 `--api-key` 和 `--api-secret` 将 API 密钥和密钥 secret 传给 `clickhousectl cloud auth login`，也可以设置 `CLICKHOUSE_CLOUD_API_KEY` 和 `CLICKHOUSE_CLOUD_API_SECRET` 环境变量。登录时会验证凭证并输出当前身份；之后可随时运行 `clickhousectl cloud auth whoami` 再次确认。如果您属于多个组织，请在每条命令中添加 `--org-id <id>` (或 `--org-name <name>`) 。

## 第 1 部分：创建 Postgres 并加载数据 {#part-1-create-and-load}

### 创建 Postgres 服务 {#create-postgres-service}

创建服务并保存返回的响应；密码仅显示一次：

```bash
clickhousectl cloud postgres create \
  --name quickstart-pg \
  --region us-east-1 \
  --size m6gd.large \
  --pg-version 18 \
  --json > pg.json
```

AWS 是默认的提供商。GCP 目前处于私有预览阶段；如需使用，请传入 `--provider gcp`，并指定 GCP 区域和规格，例如 `--region us-central1 --size c4-standard-lssd-4`。

如果未传入访问控制标志，该服务将在 Postgres (5432) 和 PgBouncer (6432) 端口上接受来自任意 IPv4 或 IPv6 地址的连接。如需限制访问，请针对每个 CIDR 和端口范围各传入一条 `--ip-allow` 规则，例如 `--ip-allow '203.0.113.0/24:5432..6432=office'`。传入规则后，仅所列规则生效。之后如需更改规则，请运行 `clickhousectl cloud postgres update <postgres-id>`，并附带 `--add-ip-allow <rule>` 或 `--remove-ip-allow <rule-id>`；可通过 `cloud postgres get` 查看规则 ID。

提取本指南后续步骤所需的信息：

```bash
PG_ID=$(jq -r .id pg.json)
PG_URL="$(jq -r .connectionString pg.json | sed 's/sslmode=require/sslmode=verify-full/')&sslrootcert=pg-ca.pem"
```

将 `sslmode` 改为 `verify-full` 并添加 `sslrootcert` 后，`psql` 会使用下文下载的 CA 来验证服务器证书。在默认的 `sslmode=require` 设置下，`psql` 只会加密连接，而不会检查服务器的身份。

如果密码丢失，可以运行 `clickhousectl cloud postgres reset-password "$PG_ID" --generate` 生成新密码。

### 等待服务预配完成 {#wait-for-provisioning}

预配需要几分钟。持续轮询，直到状态变为 `running`：

```bash
while [ "$(clickhousectl cloud postgres get "$PG_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

### 下载 CA 证书 {#download-ca-certificate}

每个 ClickHouse Managed Postgres 实例都有自己的 CA，该 CA 并非公开受信任的 CA。请将其保存到文件中，`psql` 和第 2 部分中的 ClickPipe 都会用它来验证 TLS：

```bash
clickhousectl cloud postgres certs get "$PG_ID" --output pg-ca.pem
```

### 加载示例数据 {#load-sample-data}

创建两个表，并通过 `psql` 插入 100 万条事件：

```bash
psql "$PG_URL" <<'SQL'
\timing
CREATE TABLE events (
   event_id SERIAL PRIMARY KEY,
   event_name VARCHAR(255) NOT NULL,
   event_type VARCHAR(100),
   event_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   event_data JSONB,
   user_id INT,
   user_ip INET,
   is_active BOOLEAN DEFAULT TRUE,
   created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
   user_id SERIAL PRIMARY KEY,
   name VARCHAR(100),
   country VARCHAR(50),
   platform VARCHAR(50)
);

INSERT INTO events (event_name, event_type, event_timestamp, event_data, user_id, user_ip)
SELECT
   'Event ' || gs::text AS event_name,
   CASE
       WHEN random() < 0.5 THEN 'click'
       WHEN random() < 0.75 THEN 'view'
       WHEN random() < 0.9 THEN 'purchase'
       WHEN random() < 0.98 THEN 'signup'
       ELSE 'logout'
   END AS event_type,
   NOW() - INTERVAL '1 day' * (gs % 365) AS event_timestamp,
   jsonb_build_object('key', 'value' || gs::text, 'additional_info', 'info_' || (gs % 100)::text) AS event_data,
   GREATEST(1, LEAST(1000, FLOOR(POWER(random(), 2) * 1000) + 1)) AS user_id,
   ('192.168.1.' || ((gs % 254) + 1))::inet AS user_ip
FROM
   generate_series(1, 1000000) gs;

INSERT INTO users (name, country, platform)
SELECT
    first_names[first_idx] || ' ' || last_names[last_idx] AS name,
    CASE
        WHEN random() < 0.25 THEN 'India'
        WHEN random() < 0.5 THEN 'USA'
        WHEN random() < 0.7 THEN 'Germany'
        WHEN random() < 0.85 THEN 'China'
        ELSE 'Other'
    END AS country,
    CASE
        WHEN random() < 0.2 THEN 'iOS'
        WHEN random() < 0.4 THEN 'Android'
        WHEN random() < 0.6 THEN 'Web'
        WHEN random() < 0.75 THEN 'Windows'
        WHEN random() < 0.9 THEN 'MacOS'
        ELSE 'Linux'
    END AS platform
FROM
    generate_series(1, 1000) AS seq
    CROSS JOIN LATERAL (
        SELECT
            array['Alice', 'Bob', 'Charlie', 'Diana', 'Eve', 'Frank', 'Grace', 'Hank', 'Ivy', 'Jack', 'Liam', 'Olivia', 'Noah', 'Emma', 'Sophia', 'Benjamin', 'Isabella', 'Lucas', 'Mia', 'Amelia', 'Aarav', 'Riya', 'Arjun', 'Ananya', 'Wei', 'Li', 'Huan', 'Mei', 'Hans', 'Klaus', 'Greta', 'Sofia'] AS first_names,
            array['Smith', 'Johnson', 'Williams', 'Brown', 'Jones', 'Garcia', 'Miller', 'Davis', 'Martinez', 'Taylor', 'Anderson', 'Thomas', 'Jackson', 'White', 'Harris', 'Martin', 'Thompson', 'Moore', 'Lee', 'Perez', 'Sharma', 'Patel', 'Gupta', 'Reddy', 'Zhang', 'Wang', 'Chen', 'Liu', 'Schmidt', 'Müller', 'Weber', 'Fischer'] AS last_names,
            1 + (seq % 32) AS first_idx,
            1 + ((seq / 32)::int % 32) AS last_idx
    ) AS names;
SQL
```


得益于 NVMe 存储，在 `m6gd.large` (最小规格之一) 上插入 100 万行数据大约需要 20 秒。可通过查询验证；由于数据是用 `random()` 生成的，每次运行得到的行数可能会有所不同：

```bash
psql "$PG_URL" -c "SELECT event_type, COUNT(*) FROM events GROUP BY event_type ORDER BY 2 DESC;"
```

## 第 2 部分：复制到 ClickHouse {#part-2-replicate}

### 创建 ClickHouse 服务 {#create-clickhouse-service}

在同一区域创建一个服务并保存响应；密码仅会显示在创建时返回的响应中：

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json

CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
```

等待其进入运行状态；ClickPipe 需要一个处于运行状态的目标端：

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

若要改用现有服务，请将 `CH_ID` 设置为 `clickhousectl cloud service list` 中显示的值，并将 `CH_PASSWORD` 设置为该服务 `default` 用户的密码，`pg_clickhouse` 步骤需要用到它。

### 将表复制到 ClickHouse {#replicate-to-clickhouse}

在 ClickHouse 服务上创建一个 Postgres CDC ClickPipe，并将其指向 ClickHouse Managed Postgres 的主机名。该管道会先复制现有行，随后持续将新的变更同步到 ClickHouse。ClickPipes 默认会验证源端证书，因此请使用 `--ca-certificate` 传入您在第 1 部分中下载的 CA：

```bash
PG_HOST=$(jq -r .hostname pg.json)
PG_PASSWORD=$(jq -r .password pg.json)

clickhousectl cloud clickpipe create postgres "$CH_ID" \
  --name quickstart-sync \
  --host "$PG_HOST" \
  --pg-database postgres \
  --username postgres \
  --password "$PG_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --table-mapping public.events:public_events \
  --table-mapping public.users:public_users \
  --json > pipe.json

PIPE_ID=$(jq -r .id pipe.json)
```

说明：

* 复制表会写入 ClickHouse 服务上的 `default` 数据库，表名由 `--table-mapping` 中指定的目标决定。如需使用其他数据库，请传入 `--destination-database <name>`
* `--table-mapping` 会创建 `ReplacingMergeTree` 表。更新和删除会以新的行版本写入，因此请参照下方查询，使用 `FINAL` 和 `WHERE _peerdb_is_deleted = 0` 读取当前状态
* publication 和 replication slot 会自动创建，且 publication 的作用范围仅限于已映射的表；如需使用自行管理的 publication，请传入 `--publication-name`
* 请使用 Postgres 的直连主机名；不支持通过 PgBouncer 进行复制

### 等待管道进入 Running 状态 {#wait-for-pipe}

管道在进入 `Running` 之前，会依次经过 `Provisioning`、`Setup`，以及 (对于较大的表) `Snapshot` 状态。在一个服务上创建的第一个管道通常需要约 4 分钟。`Failed` 和 `InternalError` 为终态：

```bash
while :; do
  STATE=$(clickhousectl cloud clickpipe get "$CH_ID" "$PIPE_ID" --json | jq -r .state)
  case "$STATE" in
    Running) break ;;
    Failed|InternalError) echo "ClickPipe entered terminal state: $STATE" >&2; break ;;
  esac
  sleep 15
done
```

### 在 ClickHouse 中查询复制的数据 {#query-clickhouse}

直接通过命令行客户端向 ClickHouse 服务执行 SQL。首次调用时，clickhousectl 会将您现有的 API key 添加到该服务的查询 API 端点 (如该端点尚不存在，则会先行创建) ，而不会新建 key。如果希望此时直接报错，请传入 `--no-auto-enable`。`--format TabSeparated` 仅输出纯值，下方的比较正是基于这一点：

```bash
clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0"
```

第一行输出到 stderr，且仅在 clickhousectl 更改端点时才会出现：

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
1000000
```

Postgres 中的新写入会持续复制。插入一行，然后轮询，直到计数达到 1,000,001 (通常不到一分钟) ：

```bash
psql "$PG_URL" -c "INSERT INTO events (event_name, event_type, user_id, user_ip) VALUES ('cdc-test', 'click', 42, '10.0.0.1');"

while [ "$(clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0")" != "1000001" ]; do
  sleep 10
done
```

### 从 Postgres 查询 ClickHouse {#query-clickhouse-from-postgres}

[`pg_clickhouse`](/zh/products/managed-postgres/extensions/pg_clickhouse/introduction) 扩展可让 Postgres 作为事务型数据和分析型数据的统一查询层。获取 ClickHouse 的 HTTPS 主机名，然后通过 `psql` 配置该扩展：

```bash
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol=="https") | .host')

psql "$PG_URL" <<SQL
CREATE EXTENSION pg_clickhouse;
CREATE SERVER ch FOREIGN DATA WRAPPER clickhouse_fdw
       OPTIONS(driver 'http', host '$CH_HOST', dbname 'default', port '8443');
CREATE USER MAPPING FOR CURRENT_USER SERVER ch
       OPTIONS (user 'default', password '$CH_PASSWORD');
CREATE SCHEMA organization;
IMPORT FOREIGN SCHEMA "default" FROM SERVER ch INTO organization;
SQL
```

这里特意不给 heredoc 加引号，这样 shell 就会在 SQL 到达 Postgres 之前先替换 `$CH_HOST` 和 `$CH_PASSWORD`。现在，这些复制表会在 `organization` schema 中显示为 foreign tables；对它们发起的查询实际上会在 ClickHouse 中执行。

在使用该数据集的 `m6gd.large` 上测得，通过 foreign tables 运行分析查询的速度可提升 6-9 倍 (例如，一个包含 5 个聚合的 GROUP BY：通过 ClickHouse 为 176 ms，本地执行为 1,133 ms；一个带聚合的 JOIN：298 ms，而本地为 2,764 ms) 。

## 清理 {#cleanup-resources}

请先删除 ClickPipe，再删除 Postgres 服务。删除服务会永久清除其中的所有数据。Postgres 服务在运行状态下也可以直接删除：

```bash
clickhousectl cloud clickpipe delete "$CH_ID" "$PIPE_ID"
clickhousectl cloud postgres delete "$PG_ID"
```

运行中的 ClickHouse 服务无法直接删除。使用 `--force` 会先将其停止，等待停止完成，然后再删除：

```bash
clickhousectl cloud service delete "$CH_ID" --force
```
