На этой странице описаны подготовка ClickHouse Managed Postgres, загрузка данных, их репликация в ClickHouse и выполнение запросов к ним — всё из командной строки с помощью [clickhousectl](/ru/concepts/features/interfaces/cli) и `psql`. Все команды, кроме необязательного входа с `--interactive`, выполняются в неинтерактивном режиме. `clickhousectl` выводит JSON при указании `--json`, а также автоматически, если обнаруживает ИИ-агента для написания кода; чтобы получить значения в виде обычного текста, передайте `--format` команде `cloud service query`.

## Предварительные требования {#prerequisites}

Установите clickhousectl:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

Скрипт устанавливает `~/.local/bin/clickhousectl` и псевдоним `chctl`. Убедитесь, что каталог `~/.local/bin` добавлен в переменную `PATH`.

Также потребуются `psql` (клиентские инструменты PostgreSQL; на macOS — `brew install libpq`) и `jq`.

Для операций записи (создание, удаление) необходим [ключ API](/ru/products/cloud/features/admin-features/api/openapi); вход через OAuth (`clickhousectl cloud auth login` без флагов) даёт доступ только для чтения. Войдите с помощью своего ключа: с флагом `--interactive` ключ и секрет запрашиваются интерактивно, поэтому секрет не попадает в историю командной оболочки:

```bash
clickhousectl cloud auth login --interactive
```

Либо передайте ключ и секрет команде `clickhousectl cloud auth login` через параметры `--api-key` и `--api-secret`, либо задайте переменные окружения `CLICKHOUSE_CLOUD_API_KEY` и `CLICKHOUSE_CLOUD_API_SECRET`. При входе команда проверяет учётные данные и выводит идентичность; позже её можно проверить повторно командой `clickhousectl cloud auth whoami`. Если вы состоите в нескольких организациях, добавляйте `--org-id <id>` (или `--org-name <name>`) к каждой команде.

## Часть 1: Создайте Postgres и загрузите данные {#part-1-create-and-load}

### Создайте сервис Postgres {#create-postgres-service}

Создайте сервис и сохраните ответ — пароль отображается только один раз:

```bash
clickhousectl cloud postgres create \
  --name quickstart-pg \
  --region us-east-1 \
  --size m6gd.large \
  --pg-version 18 \
  --json > pg.json
```

AWS используется в качестве провайдера по умолчанию. GCP доступен в закрытой предварительной версии (Private Preview); чтобы использовать его, укажите `--provider gcp`, а также регион и размер GCP, например `--region us-central1 --size c4-standard-lssd-4`.

Если флаги доступа не указаны, сервис принимает соединения с любого IPv4- или IPv6-адреса на портах Postgres (5432) и PgBouncer (6432). Чтобы ограничить доступ, укажите по одному правилу `--ip-allow` для каждого CIDR и диапазона портов, например `--ip-allow '203.0.113.0/24:5432..6432=office'`. Если задано хотя бы одно правило, действуют только явно перечисленные правила. Чтобы впоследствии изменить правила, выполните `clickhousectl cloud postgres update <postgres-id>` с параметром `--add-ip-allow <rule>` или `--remove-ip-allow <rule-id>`; идентификаторы правил можно получить с помощью команды `cloud postgres get`.

Ответ содержит идентификатор сервиса, имя хоста и готовую к использованию строку подключения (в сокращённом виде):

Сохраните значения, которые понадобятся далее в этом руководстве:

```bash
PG_ID=$(jq -r .id pg.json)
PG_URL="$(jq -r .connectionString pg.json | sed 's/sslmode=require/sslmode=verify-full/')&sslrootcert=pg-ca.pem"
```

Если переключить `sslmode` на `verify-full` и добавить `sslrootcert`, `psql` будет проверять сертификат сервера с помощью CA, который вы скачаете ниже. При значении по умолчанию `sslmode=require` `psql` шифрует соединение, но не проверяет идентичность сервера.

Если пароль утерян, сгенерируйте новый командой `clickhousectl cloud postgres reset-password "$PG_ID" --generate`.

### Дождитесь, пока сервис будет создан {#wait-for-provisioning}

Подготовка занимает несколько минут. Проверяйте состояние, пока оно не станет `running`:

```bash
while [ "$(clickhousectl cloud postgres get "$PG_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

### Скачайте CA‑сертификат {#download-ca-certificate}

У каждого инстанса ClickHouse Managed Postgres есть собственный CA, который не входит в число общедоверенных. Сохраните его в файл: и `psql`, и ClickPipe из части 2 используют его для проверки TLS:

```bash
clickhousectl cloud postgres certs get "$PG_ID" --output pg-ca.pem
```

### Загрузите пример данных {#load-sample-data}

Создайте две таблицы и вставьте 1 миллион событий через `psql`:

```bash
psql "$PG_URL" <<'SQL'
\timing
CREATE TABLE events (
   event_id SERIAL PRIMARY KEY,
   event_name VARCHAR(255) NOT NULL,
   event_type VARCHAR(100),
   event_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   event_data JSONB,
   user_id INT,
   user_ip INET,
   is_active BOOLEAN DEFAULT TRUE,
   created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
   user_id SERIAL PRIMARY KEY,
   name VARCHAR(100),
   country VARCHAR(50),
   platform VARCHAR(50)
);

INSERT INTO events (event_name, event_type, event_timestamp, event_data, user_id, user_ip)
SELECT
   'Event ' || gs::text AS event_name,
   CASE
       WHEN random() < 0.5 THEN 'click'
       WHEN random() < 0.75 THEN 'view'
       WHEN random() < 0.9 THEN 'purchase'
       WHEN random() < 0.98 THEN 'signup'
       ELSE 'logout'
   END AS event_type,
   NOW() - INTERVAL '1 day' * (gs % 365) AS event_timestamp,
   jsonb_build_object('key', 'value' || gs::text, 'additional_info', 'info_' || (gs % 100)::text) AS event_data,
   GREATEST(1, LEAST(1000, FLOOR(POWER(random(), 2) * 1000) + 1)) AS user_id,
   ('192.168.1.' || ((gs % 254) + 1))::inet AS user_ip
FROM
   generate_series(1, 1000000) gs;

INSERT INTO users (name, country, platform)
SELECT
    first_names[first_idx] || ' ' || last_names[last_idx] AS name,
    CASE
        WHEN random() < 0.25 THEN 'India'
        WHEN random() < 0.5 THEN 'USA'
        WHEN random() < 0.7 THEN 'Germany'
        WHEN random() < 0.85 THEN 'China'
        ELSE 'Other'
    END AS country,
    CASE
        WHEN random() < 0.2 THEN 'iOS'
        WHEN random() < 0.4 THEN 'Android'
        WHEN random() < 0.6 THEN 'Web'
        WHEN random() < 0.75 THEN 'Windows'
        WHEN random() < 0.9 THEN 'MacOS'
        ELSE 'Linux'
    END AS platform
FROM
    generate_series(1, 1000) AS seq
    CROSS JOIN LATERAL (
        SELECT
            array['Alice', 'Bob', 'Charlie', 'Diana', 'Eve', 'Frank', 'Grace', 'Hank', 'Ivy', 'Jack', 'Liam', 'Olivia', 'Noah', 'Emma', 'Sophia', 'Benjamin', 'Isabella', 'Lucas', 'Mia', 'Amelia', 'Aarav', 'Riya', 'Arjun', 'Ananya', 'Wei', 'Li', 'Huan', 'Mei', 'Hans', 'Klaus', 'Greta', 'Sofia'] AS first_names,
            array['Smith', 'Johnson', 'Williams', 'Brown', 'Jones', 'Garcia', 'Miller', 'Davis', 'Martinez', 'Taylor', 'Anderson', 'Thomas', 'Jackson', 'White', 'Harris', 'Martin', 'Thompson', 'Moore', 'Lee', 'Perez', 'Sharma', 'Patel', 'Gupta', 'Reddy', 'Zhang', 'Wang', 'Chen', 'Liu', 'Schmidt', 'Müller', 'Weber', 'Fischer'] AS last_names,
            1 + (seq % 32) AS first_idx,
            1 + ((seq / 32)::int % 32) AS last_idx
    ) AS names;
SQL
```


Вставка 1 млн строк выполняется примерно за 20 секунд на `m6gd.large` (одном из самых маленьких типоразмеров) благодаря NVMe-хранилищу. Проверьте это запросом; количество строк от запуска к запуску различается, потому что данные генерируются с помощью `random()`:

```bash
psql "$PG_URL" -c "SELECT event_type, COUNT(*) FROM events GROUP BY event_type ORDER BY 2 DESC;"
```

## Часть 2: Репликация данных в ClickHouse {#part-2-replicate}

### Создайте сервис ClickHouse {#create-clickhouse-service}

Создайте сервис в том же регионе и сохраните ответ; пароль отображается только в ответе на создание:

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json

CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
```

Подождите, пока он не заработает; для ClickPipe требуется работающий пункт назначения:

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

Чтобы использовать существующий сервис, задайте `CH_ID`, взяв его из вывода `clickhousectl cloud service list`, а в `CH_PASSWORD` укажите пароль пользователя `default`, который потребуется на этапе `pg_clickhouse`.

### Репликация таблиц в ClickHouse {#replicate-to-clickhouse}

Создайте Postgres CDC ClickPipe в сервисе ClickHouse, указав имя хоста ClickHouse Managed Postgres. Пайп копирует существующие строки, а затем синхронизирует ClickHouse с текущими изменениями. По умолчанию ClickPipes проверяет сертификат источника, поэтому передайте сертификат CA, скачанный в Части 1, с помощью `--ca-certificate`:

```bash
PG_HOST=$(jq -r .hostname pg.json)
PG_PASSWORD=$(jq -r .password pg.json)

clickhousectl cloud clickpipe create postgres "$CH_ID" \
  --name quickstart-sync \
  --host "$PG_HOST" \
  --pg-database postgres \
  --username postgres \
  --password "$PG_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --table-mapping public.events:public_events \
  --table-mapping public.users:public_users \
  --json > pipe.json

PIPE_ID=$(jq -r .id pipe.json)
```

Примечания:

* Реплицируемые таблицы создаются в базе данных `default` сервиса ClickHouse; их имена задаются целевыми значениями `--table-mapping`. Чтобы использовать другую базу данных, передайте `--destination-database <name>`
* `--table-mapping` создаёт таблицы `ReplacingMergeTree`. Обновления и удаления поступают в виде новых версий строк, поэтому для чтения текущего состояния используйте `FINAL` и `WHERE _peerdb_is_deleted = 0`, как в запросах ниже
* Публикация и слот репликации создаются автоматически, причём публикация охватывает только сопоставленные таблицы. Чтобы использовать собственную публикацию, передайте `--publication-name`
* Указывайте прямое имя хоста Postgres: репликация через PgBouncer не поддерживается

### Дождитесь, пока пайп не перейдёт в состояние `Running` {#wait-for-pipe}

Пайп проходит состояния `Provisioning`, `Setup` и (для больших таблиц) `Snapshot`, прежде чем перейти в `Running`; для первого пайпа в сервисе это занимает около 4 минут. `Failed` и `InternalError` — конечные состояния:

```bash
while :; do
  STATE=$(clickhousectl cloud clickpipe get "$CH_ID" "$PIPE_ID" --json | jq -r .state)
  case "$STATE" in
    Running) break ;;
    Failed|InternalError) echo "ClickPipe entered terminal state: $STATE" >&2; break ;;
  esac
  sleep 15
done
```

### Выполните запрос к реплицированным данным в ClickHouse {#query-clickhouse}

Выполняйте SQL-запросы к сервису ClickHouse напрямую из CLI. При первом вызове clickhousectl добавляет ваш ключ API к конечной точке API запросов сервиса и при необходимости создаёт эту конечную точку; новый ключ при этом не создаётся. Чтобы вместо этого команда завершалась с ошибкой, передайте флаг `--no-auto-enable`. С `--format TabSeparated` выводится только само значение — на этом основано приведённое ниже сравнение:

```bash
clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0"
```

Первая строка выводится в stderr и появляется, только когда clickhousectl изменяет конечную точку:

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
1000000
```

Новые данные, записываемые в Postgres, реплицируются непрерывно. Вставьте строку и выполняйте опрос, пока количество строк не достигнет 1 000 001 (обычно это занимает меньше минуты):

```bash
psql "$PG_URL" -c "INSERT INTO events (event_name, event_type, user_id, user_ip) VALUES ('cdc-test', 'click', 42, '10.0.0.1');"

while [ "$(clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0")" != "1000001" ]; do
  sleep 10
done
```

### Запросы к ClickHouse из Postgres {#query-clickhouse-from-postgres}

Расширение [`pg_clickhouse`](/ru/products/managed-postgres/extensions/pg_clickhouse/introduction) позволяет Postgres выступать в качестве единого слоя для запросов как к транзакционным, так и к аналитическим данным. Получите HTTPS-имя хоста ClickHouse, затем настройте расширение через `psql`:

```bash
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol=="https") | .host')

psql "$PG_URL" <<SQL
CREATE EXTENSION pg_clickhouse;
CREATE SERVER ch FOREIGN DATA WRAPPER clickhouse_fdw
       OPTIONS(driver 'http', host '$CH_HOST', dbname 'default', port '8443');
CREATE USER MAPPING FOR CURRENT_USER SERVER ch
       OPTIONS (user 'default', password '$CH_PASSWORD');
CREATE SCHEMA organization;
IMPORT FOREIGN SCHEMA "default" FROM SERVER ch INTO organization;
SQL
```

Heredoc намеренно оставлен без кавычек, чтобы оболочка подставила `$CH_HOST` и `$CH_PASSWORD` до того, как SQL попадёт в Postgres. Реплицированные таблицы теперь видны как внешние таблицы в схеме `organization`; запросы к ним выполняются в ClickHouse.

По результатам измерений на `m6gd.large` с этим набором данных аналитические запросы через внешние таблицы выполняются в 6–9 раз быстрее (например, `GROUP BY` с 5 агрегациями: 176 мс через ClickHouse против 1 133 мс локально; JOIN с агрегациями: 298 мс против 2 764 мс).

## Очистка {#cleanup-resources}

Сначала удалите ClickPipe, затем сервис Postgres. При удалении сервиса все его данные удаляются без возможности восстановления. Сервис Postgres можно удалить, не останавливая его:

```bash
clickhousectl cloud clickpipe delete "$CH_ID" "$PIPE_ID"
clickhousectl cloud postgres delete "$PG_ID"
```

Нельзя удалить работающий сервис ClickHouse напрямую. Флаг `--force` останавливает его, дожидается завершения остановки, а затем удаляет:

```bash
clickhousectl cloud service delete "$CH_ID" --force
```
