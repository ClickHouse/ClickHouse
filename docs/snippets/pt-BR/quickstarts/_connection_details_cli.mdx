---
title: Detalhes de conexão pela CLI
---

Esta página explica como localizar os detalhes de conexão de um serviço do ClickHouse Cloud existente — hostname, números de porta, nome de usuário e senha — pela linha de comando com a [CLI do ClickHouse](/pt-BR/concepts/features/interfaces/cli) (`clickhousectl`). Com exceção do login, os comandos são não interativos. O `clickhousectl` retorna JSON com `--json` e também automaticamente quando é executado por um agente de programação.

## Pré-requisitos {#prerequisites}

Instale a CLI do ClickHouse:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

O script instala `~/.local/bin/clickhousectl` e um alias `chctl`. Certifique-se de que `~/.local/bin` esteja no seu `PATH`.

Você também vai precisar do `jq`.

Para as etapas read-only (`service list`, `service get`), basta o login pelo navegador. Como ele abre um navegador, uma pessoa precisa concluí-lo:

```bash
clickhousectl cloud auth login
```

O login pelo navegador é read-only. As etapas de escrita abaixo exigem uma [chave de API](/pt-BR/products/cloud/features/admin-features/api/openapi): `cloud service start` ou `cloud service wake` (somente se o seu serviço estiver `stopped` ou `idle`) e `reset-password`. Para fazer login com uma chave, execute `clickhousectl cloud auth login --interactive`, que solicita a chave e o secret e evita que o secret fique registrado no histórico do seu shell. Como alternativa, informe `--api-key` e `--api-secret` ou defina as variáveis de ambiente `CLICKHOUSE_CLOUD_API_KEY` e `CLICKHOUSE_CLOUD_API_SECRET`. Agentes de programação e scripts devem usar as variáveis de ambiente.

O login valida as credenciais e exibe a identidade autenticada, que você pode conferir a qualquer momento com `clickhousectl cloud auth whoami`. Se você pertencer a mais de uma organização, adicione `--org-id <org-id>` (ou `--org-name <name>`) a cada comando `cloud service` deste guia.

Você também precisa ter um Serviço do ClickHouse Cloud do qual obter os detalhes de conexão, como um criado no [Início Rápido do Cloud](/pt-BR/get-started/setup/cloud).

## Encontre seu serviço {#find-your-service}

Liste os serviços da sua organização e anote o ID daquele ao qual você deseja se conectar:

```bash
clickhousectl cloud service list --json | jq -r '.[] | [.id, .name, .state] | @tsv'
```

```text
9c2d4e61-7a35-49c8-8f0e-2b5a1d7c3e90	my-first-service	running
```

Salve o ID do serviço; todos os demais comandos deste guia o recebem como argumento. Para consultá-lo pelo nome:

```bash
CH_ID=$(clickhousectl cloud service get --name my-first-service --json | jq -r .id)
```

Você precisará do serviço em execução para verificar a conectividade em uma etapa posterior. Se o state dele for `stopped`, inicie-o e faça poll até que fique `running`:

```bash
clickhousectl cloud service start "$CH_ID"
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

Um serviço que esteja `idle` devido ao idle scaling é ativado automaticamente na primeira conexão, portanto não requer nenhuma ação aqui. Para ativá-lo antecipadamente, execute `clickhousectl cloud service wake "$CH_ID"` e faça poll da mesma forma.

## Obtenha os detalhes de conexão {#get-your-connection-details}

`clickhousectl cloud service get` retorna os detalhes completos do serviço, incluindo um endpoint por protocolo exposto. Salve a resposta e extraia as informações necessárias:

```bash
clickhousectl cloud service get "$CH_ID" --json > service.json
jq '.endpoints' service.json
```

```json
[
  {
    "host": "abc123.us-east-1.aws.clickhouse.cloud",
    "port": 9440,
    "protocol": "nativesecure"
  },
  {
    "host": "abc123.us-east-1.aws.clickhouse.cloud",
    "port": 8443,
    "protocol": "https"
  }
]
```

Estes são os dois principais protocolos de rede do ClickHouse Cloud, cada um em sua própria porta:

* **Protocolo nativo (`nativesecure`, porta 9440)** — Um protocolo binário usado pelo `clickhouse-client`, pelo `clickhouse-local` e pela maioria dos drivers específicos de linguagem. É a opção mais rápida e oferece suporte a todos os recursos do ClickHouse. O TLS é obrigatório no Cloud.
* **Protocolo HTTPS (`https`, porta 8443)** — Uma interface baseada em HTTP, útil para clientes REST, `curl`, ferramentas web e drivers que preferem HTTP. Também exige TLS no Cloud.

Ambos os protocolos exigem criptografia TLS na conexão com o ClickHouse Cloud — não é possível conectar-se em plaintext. A maioria das ferramentas cuida disso automaticamente quando você especifica a porta correta, mas pode ser necessário passar o flag `--secure` ou definir `ssl=true`, dependendo do client. Na maioria dos guias de início rápido e workflows de CLI desta série, você usará o **protocolo nativo na porta 9440**.

Extraia o hostname e as portas:

```bash
CH_HOST=$(jq -r '.endpoints[] | select(.protocol == "nativesecure") | .host' service.json)
CH_NATIVE_PORT=$(jq -r '.endpoints[] | select(.protocol == "nativesecure") | .port' service.json)
CH_HTTPS_PORT=$(jq -r '.endpoints[] | select(.protocol == "https") | .port' service.json)
```

O nome de usuário é `default`, a menos que você tenha criado outros usuários de banco de dados.

## Obter uma senha {#get-a-password}

A senha do usuário `default` é retornada uma única vez, pelo comando `clickhousectl cloud service create` — nenhuma chamada de API ou CLI é capaz de recuperá-la depois. Se você a salvou no momento da criação, atribua-a à variável usada nos passos seguintes e pule a redefinição:

```bash
CH_PASSWORD='<your saved password>'
```

Se ela for perdida, gere uma nova:

```bash
CH_PASSWORD=$(clickhousectl cloud service reset-password "$CH_ID" --json | jq -r .password)
```

<Warning>
  `reset-password` substitui a senha do usuário `default`. A alteração leva alguns segundos para ser aplicada: até lá, a nova senha é rejeitada e a antiga continua funcionando, portanto, tente novamente a primeira conexão por alguns instantes. Depois disso, qualquer Client ainda configurado com a senha antiga deixa de autenticar. Se o serviço fizer parte de um [warehouse](/pt-BR/products/cloud/features/infrastructure/warehouses), os usuários de banco de dados são compartilhados por todos os serviços daquele warehouse, portanto a redefinição também rotaciona a senha de todos os serviços irmãos. Assim como a original, a nova senha é exibida apenas uma vez, então guarde-a em um local seguro.
</Warning>

## Salve seus detalhes de conexão para reutilização {#save-your-connection-details-for-reuse}

Você usará esses detalhes de conexão com frequência nos guias de início rápido. Para não precisar digitá-los toda vez, exporte-os como variáveis de ambiente na sessão do seu terminal:

```bash
export CLICKHOUSE_HOST=$CH_HOST
export CLICKHOUSE_USER=default
export CLICKHOUSE_PASSWORD=$CH_PASSWORD
```

<Warning>
  Essas variáveis de ambiente persistem apenas durante a sessão atual do terminal. Não armazene senhas em arquivos de profile do shell (`.bashrc`, `.zshrc`) nem faça commit delas no controle de versão.
</Warning>

## Verificar a conectividade {#verify-connectivity}

Verifique a interface HTTPS (porta 8443) com `curl`:

```bash
curl --user "$CLICKHOUSE_USER:$CLICKHOUSE_PASSWORD" \
  "https://$CLICKHOUSE_HOST:8443/?query=SELECT%201"
```

```text
1
```

Verifique o protocolo nativo (porta 9440) com o [**clickhouse client**](/pt-BR/concepts/features/interfaces/client). A CLI do ClickHouse gerencia o binary `clickhouse` para você, então, caso ainda não o tenha, o comando `clickhousectl local use latest` instala a versão mais recente do ClickHouse e cria um link simbólico em `~/.local/bin/clickhouse`. Em seguida:

```bash
clickhouse client --host "$CLICKHOUSE_HOST" --secure --port 9440 \
  --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --query "SELECT concat('Connected to ClickHouse ', version(), ' as ', currentUser())"
```

```text
Connected to ClickHouse 26.2.1.558 as default
```

## Limpeza {#cleanup}

Este guia apenas lê os metadados do service e (opcionalmente) redefine uma senha — ele não cria nenhum recurso de nuvem novo, portanto não há nada a limpar.

Há uma exceção: se o seu service estava `stopped` e você o iniciou apenas para verificar a conectividade, ele continuará em execução e gerando cobrança de compute. Pare-o novamente caso ainda não precise dele em execução:

```bash
clickhousectl cloud service stop "$CH_ID"
```
