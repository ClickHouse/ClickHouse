Por padrão, as consultas `CREATE`, `DROP`, `ALTER` e `RENAME` afetam apenas o servidor atual em que são executadas. Em uma configuração de cluster, é possível executar essas consultas de forma distribuída com a cláusula `ON CLUSTER`.

Por exemplo, a consulta a seguir cria a tabela `all_hits` do tipo `Distributed` em cada host no `cluster`:

```sql
CREATE TABLE IF NOT EXISTS all_hits ON CLUSTER cluster (p Date, i Int32) ENGINE = Distributed(cluster, default, hits)
```

Para executar essas consultas corretamente, cada host deve ter a mesma definição de cluster (para simplificar a sincronização das configurações, você pode usar substituições do ZooKeeper). Todos eles também devem se conectar aos servidores ZooKeeper.

Em geral, a versão local da consulta acabará sendo executada em cada host do cluster, mesmo que alguns hosts não estejam disponíveis no momento. No entanto, essas consultas são armazenadas em uma fila, e o tempo que um item permanece na fila é limitado por [várias configurações](/pt-BR/reference/settings/server-settings/settings/distributed). Por isso, se um host ficar indisponível por tempo suficiente, ele pode não executar a consulta quando voltar a ficar disponível.

<Warning>
  A ordem de execução das consultas em um único host é garantida desde que [distributed&#95;ddl.pool&#95;size](/pt-BR/reference/settings/server-settings/settings/distributed#distributed_ddl.pool_size) esteja definido como 1.
</Warning>
