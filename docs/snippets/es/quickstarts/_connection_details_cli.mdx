---
title: Datos de conexión desde la CLI
---

Esta página explica cómo obtener los datos de conexión de un servicio de ClickHouse Cloud existente —el hostname, los números de puerto, el nombre de usuario y la contraseña— desde la línea de comandos con la [CLI de ClickHouse](/es/concepts/features/interfaces/cli) (`clickhousectl`). Salvo el inicio de sesión, los comandos no son interactivos. `clickhousectl` devuelve JSON con `--json`, y también lo hace automáticamente cuando lo ejecuta un agente de programación.

## Requisitos previos {#prerequisites}

Instale la CLI de ClickHouse:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

El script instala `~/.local/bin/clickhousectl` y un alias `chctl`. Asegúrese de que `~/.local/bin` esté incluido en su `PATH`.

También necesita `jq`.

Para los pasos de solo lectura (`service list`, `service get`), basta con iniciar sesión a través del navegador. Como este proceso abre un navegador, debe completarlo una persona:

```bash
clickhousectl cloud auth login
```

El inicio de sesión mediante el navegador es de solo lectura. Los pasos de escritura que se indican a continuación requieren una [clave de API](/es/products/cloud/features/admin-features/api/openapi): `cloud service start` o `cloud service wake` (solo si su servicio está en estado `stopped` o `idle`) y `reset-password`. Para iniciar sesión con una clave, ejecute `clickhousectl cloud auth login --interactive`, que le pide la clave y el secret y evita que el secret quede en el historial de su shell. También puede pasar `--api-key` y `--api-secret`, o definir las variables de entorno `CLICKHOUSE_CLOUD_API_KEY` y `CLICKHOUSE_CLOUD_API_SECRET`; si se trata de un agente de programación o un script, debe usar las variables de entorno.

El inicio de sesión verifica las credenciales y muestra la identity; puede comprobarla en cualquier momento con `clickhousectl cloud auth whoami`. Si pertenece a más de una organización, añada `--org-id <org-id>` (o `--org-name <name>`) a cada comando `cloud service` de esta guía.

También necesita un servicio de ClickHouse Cloud existente del que obtener los datos de conexión, por ejemplo, uno creado en el [Inicio Rápido de Cloud](/es/get-started/setup/cloud).

## Encuentra tu servicio {#find-your-service}

Enumera los servicios de tu organización y anota el ID de aquel al que quieras conectarte:

```bash
clickhousectl cloud service list --json | jq -r '.[] | [.id, .name, .state] | @tsv'
```

```text
9c2d4e61-7a35-49c8-8f0e-2b5a1d7c3e90	my-first-service	running
```

Guarde el ID del servicio; todos los demás comandos de esta guía lo reciben como argument. Para buscarlo por name:

```bash
CH_ID=$(clickhousectl cloud service get --name my-first-service --json | jq -r .id)
```

Necesitarás el servicio en ejecución para verificar la conectividad en un paso posterior. Si su estado es `stopped`, inícielo y consulte su estado hasta que sea `running`:

```bash
clickhousectl cloud service start "$CH_ID"
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

Un servicio que está `idle` por el escalado en reposo se activa automáticamente en la primera connection, por lo que aquí no requiere ninguna acción. Para activarlo de antemano, ejecute `clickhousectl cloud service wake "$CH_ID"` y consulte su estado de la misma manera.

## Obtener los detalles de conexión {#get-your-connection-details}

`clickhousectl cloud service get` devuelve los detalles completos del servicio, incluido un endpoint por cada protocolo expuesto. Guarde la respuesta y extraiga los datos que necesite:

```bash
clickhousectl cloud service get "$CH_ID" --json > service.json
jq '.endpoints' service.json
```

```json
[
  {
    "host": "abc123.us-east-1.aws.clickhouse.cloud",
    "port": 9440,
    "protocol": "nativesecure"
  },
  {
    "host": "abc123.us-east-1.aws.clickhouse.cloud",
    "port": 8443,
    "protocol": "https"
  }
]
```

Estos son los dos protocolos de red principales de ClickHouse Cloud, cada uno en su propio puerto:

* **Protocolo nativo (`nativesecure`, puerto 9440)**: protocolo binario utilizado por `clickhouse-client`, `clickhouse-local` y la mayoría de los drivers específicos de cada lenguaje. Es la opción más rápida y admite todas las funcionalidades de ClickHouse. En Cloud se requiere TLS.
* **Protocolo HTTPS (`https`, puerto 8443)**: interfaz basada en HTTP, útil para clients REST, `curl`, herramientas web y drivers que prefieren HTTP. También requiere TLS en Cloud.

Ambos protocolos requieren cifrado TLS para conectarse a ClickHouse Cloud: no es posible hacerlo en plaintext. La mayoría de las herramientas se encargan de esto automáticamente cuando se especifica el puerto correcto, pero es posible que deba pasar el indicador `--secure` o establecer `ssl=true`, según el client. Para la mayoría de las guías de inicio rápido y los workflows de CLI de esta serie, utilizará el **protocolo nativo en el puerto 9440**.

Extraiga el hostname y los puertos:

```bash
CH_HOST=$(jq -r '.endpoints[] | select(.protocol == "nativesecure") | .host' service.json)
CH_NATIVE_PORT=$(jq -r '.endpoints[] | select(.protocol == "nativesecure") | .port' service.json)
CH_HTTPS_PORT=$(jq -r '.endpoints[] | select(.protocol == "https") | .port' service.json)
```

El nombre de usuario es `default`, a menos que haya creado usuarios de base de datos adicionales.

## Obtener una contraseña {#get-a-password}

La contraseña del usuario `default` se devuelve una sola vez, al ejecutar `clickhousectl cloud service create`: ninguna llamada a la API ni a la CLI permite recuperarla más adelante. Si la guardaste en el momento de la creación, asígnala a la variable que utilizan los pasos posteriores y omite el restablecimiento:

```bash
CH_PASSWORD='<your saved password>'
```

Si se pierde, genere una nueva:

```bash
CH_PASSWORD=$(clickhousectl cloud service reset-password "$CH_ID" --json | jq -r .password)
```

<Warning>
  `reset-password` reemplaza la contraseña del usuario `default`. El cambio tarda unos segundos en aplicarse: hasta entonces, la nueva contraseña se rechaza y la antigua sigue funcionando, así que reintente la primera conexión durante unos instantes. A partir de ese momento, cualquier client que siga configurado con la contraseña antigua dejará de autenticarse. Si el servicio forma parte de un [warehouse](/es/products/cloud/features/infrastructure/warehouses), los usuarios de base de datos se comparten entre todos los servicios de ese warehouse, por lo que el restablecimiento también rota la contraseña de los demás servicios del mismo warehouse. Al igual que la original, la nueva contraseña se muestra una sola vez, así que guárdela en un lugar seguro.
</Warning>

## Guarde sus datos de conexión para reutilizarlos {#save-your-connection-details-for-reuse}

Utilizará estos datos de conexión con frecuencia a lo largo de las guías de inicio rápido. Para no tener que volver a escribirlos cada vez, puede exportarlos como variables de entorno en su sesión de terminal:

```bash
export CLICKHOUSE_HOST=$CH_HOST
export CLICKHOUSE_USER=default
export CLICKHOUSE_PASSWORD=$CH_PASSWORD
```

<Warning>
  Estas variables de entorno solo persisten durante la sesión actual de la terminal. No almacene contraseñas en los archivos de perfil del shell (`.bashrc`, `.zshrc`) ni haga commit de ellas en el control de versiones.
</Warning>

## Verificar la conectividad {#verify-connectivity}

Verifique la interfaz HTTPS (puerto 8443) con `curl`:

```bash
curl --user "$CLICKHOUSE_USER:$CLICKHOUSE_PASSWORD" \
  "https://$CLICKHOUSE_HOST:8443/?query=SELECT%201"
```

```text
1
```

Verifique el protocolo nativo (puerto 9440) con [**clickhouse client**](/es/concepts/features/interfaces/client). La CLI de ClickHouse gestiona el binario `clickhouse` por usted, por lo que si aún no lo tiene, `clickhousectl local use latest` instala la versión más reciente de ClickHouse y crea un enlace simbólico en `~/.local/bin/clickhouse`. A continuación:

```bash
clickhouse client --host "$CLICKHOUSE_HOST" --secure --port 9440 \
  --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --query "SELECT concat('Connected to ClickHouse ', version(), ' as ', currentUser())"
```

```text
Connected to ClickHouse 26.2.1.558 as default
```

## Limpieza {#cleanup}

Esta guía solo lee los metadatos del servicio y (opcionalmente) restablece una contraseña: no crea recursos nuevos en la nube, por lo que no hay nada que limpiar.

Una excepción: si su servicio estaba `stopped` y lo inició únicamente para comprobar la conectividad, seguirá en ejecución y generando cargos por compute. Vuelva a detenerlo si todavía no necesita tenerlo en ejecución:

```bash
clickhousectl cloud service stop "$CH_ID"
```
