---
title: Guía de inicio rápido de Cloud CLI
---

En esta página se explica cómo aprovisionar un servicio de ClickHouse Cloud, conectarse a él y cargar datos desde la línea de comandos con [CLI de ClickHouse](/es/concepts/features/interfaces/cli) (`clickhousectl`). Salvo el inicio de sesión opcional con `--interactive`, los comandos no son interactivos. `clickhousectl` genera JSON con `--json`, y también de forma automática cuando lo ejecuta un agente de programación.

## Requisitos previos {#prerequisites}

Instale la CLI de ClickHouse:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

El script instala `~/.local/bin/clickhousectl` y un alias `chctl`. Asegúrese de que `~/.local/bin` esté en su `PATH`.

También necesita `jq`.

Necesita una cuenta de ClickHouse Cloud. Si aún no tiene una, `clickhousectl cloud auth signup` abre la página de registro en su navegador.

El inicio de sesión mediante el navegador (`clickhousectl cloud auth login`) es de solo lectura. Para crear y eliminar un servicio, así como para ejecutar SQL con la API de consultas, se necesita una [clave de API](/es/products/cloud/features/admin-features/api/openapi) cuyo rol tenga permisos para crear servicios y administrar los endpoints de la API de consultas; la opción `--help` de cada comando indica los permisos que requiere. Inicie sesión con la clave; `--interactive` le pide la clave y el secreto de forma interactiva, lo que evita que el secreto quede registrado en el historial de su shell:

```bash
clickhousectl cloud auth login --interactive
```

Como alternativa, pase `--api-key` y `--api-secret`, o defina las variables de entorno `CLICKHOUSE_CLOUD_API_KEY` y `CLICKHOUSE_CLOUD_API_SECRET`. Si utiliza un agente de programación o un script, debe usar las variables de entorno. Al iniciar sesión, se verifica la clave y se muestra la identity asociada; puede comprobar las credenciales activas en cualquier momento con `clickhousectl cloud auth whoami`. Si pertenece a más de una organización, añada `--org-id <org-id>` (o `--org-name <name>`) a cada comando `cloud` de esta guía.

## Cree un servicio de ClickHouse {#create-service}

Cree el servicio y guarde la respuesta; la contraseña del usuario `default` se muestra solo una vez:

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json
```

La respuesta incluye el ID del servicio, los endpoints y la contraseña generada (truncada aquí; la respuesta completa también incluye la configuración de escalado, la lista de acceso de IP y las etiquetas):

```json
{
  "password": "dK7mPq2x_-TzrL9vNw0s",
  "service": {
    "id": "4f7b92f3-4163-403a-b538-b9bc6e2e8f66",
    "name": "quickstart-ch",
    "provider": "aws",
    "region": "us-east-1",
    "state": "provisioning",
    "endpoints": [
      {
        "host": "quickstart-abc123.us-east-1.aws.clickhouse.cloud",
        "port": 9440,
        "protocol": "nativesecure"
      },
      {
        "host": "quickstart-abc123.us-east-1.aws.clickhouse.cloud",
        "port": 8443,
        "protocol": "https"
      }
    ],
    "numReplicas": 3,
    "minReplicaMemoryGb": 16.0,
    "maxReplicaMemoryGb": 120.0
  }
}
```

Extraiga lo que necesitará para el resto de esta guía:

```bash
CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
CH_HOST=$(jq -r '.service.endpoints[] | select(.protocol=="nativesecure") | .host' ch.json)
```

Si se pierde la contraseña, genere una nueva con `clickhousectl cloud service reset-password "$CH_ID"`.

De forma predeterminada, los servicios creados con `clickhousectl` incluyen una lista de acceso por IP que permite todas las direcciones (`0.0.0.0/0`). Para restringir el acceso, especifique `--ip-allow` al crear el servicio; consulte [&quot;Configuración de filtros de IP&quot;](/es/products/cloud/guides/security/connectivity/setting-ip-filters).

## Espere a que se aprovisione el servicio {#wait-for-provisioning}

El aprovisionamiento tarda aproximadamente un minuto. Consulte el estado periódicamente hasta que sea `running`:

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

## Ejecutar SQL con la API de consultas {#run-sql}

`clickhousectl cloud service query` ejecuta SQL a través de HTTP, sin necesidad de un binario `clickhouse` local ni de la contraseña del servicio. En la primera llamada, clickhousectl añade su clave de API al Endpoint de la API de Consultas del servicio y, si es necesario, crea dicho endpoint; no se crea ninguna clave nueva. Si prefiere que la operación falle en ese caso, pase `--no-auto-enable`:

```bash
clickhousectl cloud service query "$CH_ID" --json --query "SHOW databases"
```

La primera línea de la siguiente salida se envía a stderr y solo aparece cuando la CLI cambia el endpoint:

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
{"name":"INFORMATION_SCHEMA"}
{"name":"default"}
{"name":"information_schema"}
{"name":"system"}
```

De forma predeterminada, la salida usa `PrettyCompact` en una terminal, `TabSeparated` cuando se redirige mediante una tubería y `JSONEachRow` cuando un agente de programación ejecuta el comando. La opción `--json`, utilizada anteriormente, selecciona `JSONEachRow`; para cualquier otro formato, utilice `--format` en su lugar (`--json` y `--format` no se pueden combinar). Un script que analice la salida siempre debería especificar una de las dos.

## Cree una base de datos y una tabla {#create-database-and-table}

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "CREATE DATABASE IF NOT EXISTS helloworld"

clickhousectl cloud service query "$CH_ID" \
  --query "CREATE TABLE helloworld.my_first_table (
    user_id UInt32,
    message String,
    timestamp DateTime,
    metric Float32
  ) ENGINE = MergeTree()
  PRIMARY KEY (user_id, timestamp)"
```

Cada comando muestra `OK` en stderr. Inserte algunas filas:

```bash
clickhousectl cloud service query "$CH_ID" <<'SQL'
INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
  (101, 'Hello, ClickHouse!', now(), -1.0),
  (102, 'Insert a lot of rows per batch', yesterday(), 1.41421),
  (102, 'Sort your data based on your commonly-used queries', today(), 2.718),
  (101, 'Granules are the smallest chunks of data read', now() + 5, 3.14159)
SQL
```

Verifica que haya funcionado:

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT * FROM helloworld.my_first_table ORDER BY timestamp"
```

```text
{"user_id":102,"message":"Insert a lot of rows per batch","timestamp":"2026-08-26 00:00:00","metric":1.41421}
{"user_id":102,"message":"Sort your data based on your commonly-used queries","timestamp":"2026-08-27 00:00:00","metric":2.718}
{"user_id":101,"message":"Hello, ClickHouse!","timestamp":"2026-08-27 10:41:28","metric":-1}
{"user_id":101,"message":"Granules are the smallest chunks of data read","timestamp":"2026-08-27 10:41:33","metric":3.14159}
```

Los timestamps dependen de cuándo ejecutaste el insert, por lo que los tuyos serán distintos.

## Cargar un archivo CSV {#load-csv-file}

Supongamos que el siguiente texto está en un archivo CSV llamado `data.csv`:

```text title="data.csv"
102,This is data in a file,2022-02-22 10:43:28,123.45
101,It is comma-separated,2022-02-23 00:00:00,456.78
103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
```

`INSERT ... FORMAT` lee los datos de stdin, por lo que debes canalizar la consulta y el archivo juntos:

```bash
printf 'INSERT INTO helloworld.my_first_table FORMAT CSV\n' | cat - data.csv \
  | clickhousectl cloud service query "$CH_ID"
```

La API de consultas deja de esperar tras unos 30 segundos, y un `INSERT` que haya agotado el tiempo de espera podría haberse ejecutado igualmente, así que compruebe el número de filas antes de reintentarlo. Para archivos grandes, utilice [`clickhouse client`](#native-client) en su lugar.

Verifique que se hayan cargado las nuevas filas:

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT count() FROM helloworld.my_first_table"
```

```text
{"count()":7}
```

## Conectarse con clickhouse client {#native-client}

También puede conectarse mediante el protocolo nativo con [**clickhouse client**](/es/concepts/features/interfaces/client). La CLI de ClickHouse gestiona el binario `clickhouse`, por lo que no necesita instalar un cliente por separado:

```bash
clickhousectl local use latest
```

Esto instala la versión más reciente de ClickHouse y crea un enlace simbólico a `~/.local/bin/clickhouse`, de modo que puedes ejecutar directamente el comando `clickhouse` una vez que `~/.local/bin` esté en tu `PATH` (si no lo está, el comando muestra un aviso).

A continuación, conéctate usando el hostname y la contraseña de la respuesta de creación. Con `--query`, se muestra el resultado y el client se cierra; sin esta opción, accedes al prompt interactivo (`:)`), del que puedes salir con `exit`:

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query "SELECT * FROM helloworld.my_first_table ORDER BY timestamp FORMAT TabSeparated"
```

```text
103	Use FORMAT to specify the format	2022-02-21 10:43:30	678.9
102	This is data in a file	2022-02-22 10:43:28	123.45
101	It is comma-separated	2022-02-23 00:00:00	456.78
102	Insert a lot of rows per batch	2026-08-26 00:00:00	1.41421
102	Sort your data based on your commonly-used queries	2026-08-27 00:00:00	2.718
101	Hello, ClickHouse!	2026-08-27 10:41:28	-1
101	Granules are the smallest chunks of data read	2026-08-27 10:41:33	3.14159
```

El mismo formato de comando permite cargar archivos. No está sujeto al tiempo de espera de la API de consultas, así que úsalo para archivos grandes:

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
```

ClickHouse Cloud elimina los duplicados de bloques insertados idénticos, por lo que, si carga el mismo `data.csv` por segunda vez, no se añade ninguna fila.

## Limpieza {#cleanup}

Al eliminar un servicio, se eliminan permanentemente todos sus datos. `--force` detiene primero un servicio en ejecución y espera a que se complete la detención, lo que puede tardar varios minutos:

```bash
clickhousectl cloud service delete "$CH_ID" --force
```

Para conservar los datos sin seguir pagando por capacidad de procesamiento, detenga el servicio con `clickhousectl cloud service stop "$CH_ID"`.
