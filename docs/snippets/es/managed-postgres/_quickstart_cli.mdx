title: Inicio rápido de la CLI
---

En esta página se explica el aprovisionamiento de ClickHouse Managed Postgres, la carga de datos, su replicación a ClickHouse y la ejecución de consultas, todo desde la línea de comandos con [clickhousectl](/es/concepts/features/interfaces/cli) y `psql`. Salvo el inicio de sesión opcional con `--interactive`, los comandos no son interactivos. `clickhousectl` genera JSON con `--json`, y también de forma automática cuando detecta un agente de programación; pase `--format` a `cloud service query` para obtener valores sin formato.

## Requisitos previos {#prerequisites}

Instale clickhousectl:

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

El script instala `~/.local/bin/clickhousectl` y un alias `chctl`. Asegúrese de que `~/.local/bin` esté incluido en su `PATH`.

También necesita `psql` (herramientas de cliente de PostgreSQL; en macOS, `brew install libpq`) y `jq`.

Las operaciones de escritura (crear, eliminar) requieren una [clave de API](/es/products/cloud/features/admin-features/api/openapi); el inicio de sesión mediante OAuth (`clickhousectl cloud auth login` sin indicadores) es de solo lectura. Inicie sesión con su clave; `--interactive` le solicita la clave y el secreto, lo que evita que el secreto quede guardado en el historial de su shell:

```bash
clickhousectl cloud auth login --interactive
```

O bien, pase la clave y el secreto a `clickhousectl cloud auth login` con `--api-key` y `--api-secret`, o defina las variables de entorno `CLICKHOUSE_CLOUD_API_KEY` y `CLICKHOUSE_CLOUD_API_SECRET`. El inicio de sesión verifica las credenciales y muestra la identity; con `clickhousectl cloud auth whoami` puede volver a comprobarla más adelante. Si pertenece a más de una organización, agregue `--org-id <id>` (o `--org-name <name>`) a cada comando.

## Parte 1: Crear Postgres y cargar datos {#part-1-create-and-load}

### Crear un servicio de Postgres {#create-postgres-service}

Cree el servicio y guarde la respuesta; la contraseña solo se muestra una vez:

```bash
clickhousectl cloud postgres create \
  --name quickstart-pg \
  --region us-east-1 \
  --size m6gd.large \
  --pg-version 18 \
  --json > pg.json
```

AWS es el provider predeterminado. GCP está en vista previa privada; para usarlo, pase `--provider gcp` junto con una región y un tamaño de GCP, por ejemplo, `--region us-central1 --size c4-standard-lssd-4`.

Si no se especifican indicadores de acceso, el servicio acepta conexiones desde cualquier dirección IPv4 o IPv6 en Postgres (5432) y PgBouncer (6432). Para restringir el acceso, pase una regla `--ip-allow` por cada CIDR y rango de puertos, por ejemplo, `--ip-allow '203.0.113.0/24:5432..6432=office'`. En cuanto pase una regla, solo se aplicarán las reglas indicadas. Para modificar las reglas más adelante, ejecute `clickhousectl cloud postgres update <postgres-id>` con `--add-ip-allow <rule>` o `--remove-ip-allow <rule-id>`; `cloud postgres get` muestra los ID de las reglas.

Extraiga los datos que necesitará en el resto de esta guía:

```bash
PG_ID=$(jq -r .id pg.json)
PG_URL="$(jq -r .connectionString pg.json | sed 's/sslmode=require/sslmode=verify-full/')&sslrootcert=pg-ca.pem"
```

Al cambiar `sslmode` a `verify-full` y añadir `sslrootcert`, `psql` verifica el certificado del servidor con la CA que descargará más adelante. Con el valor predeterminado, `sslmode=require`, `psql` cifra la conexión, pero no comprueba la identidad del servidor.

Si pierde la contraseña, genere una nueva con `clickhousectl cloud postgres reset-password "$PG_ID" --generate`.

### Espera a que finalice el aprovisionamiento del servicio {#wait-for-provisioning}

El aprovisionamiento tarda unos minutos. Consulta periódicamente hasta que el estado sea `running`:

```bash
while [ "$(clickhousectl cloud postgres get "$PG_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

### Descargar el certificado de CA {#download-ca-certificate}

Cada instancia de ClickHouse Managed Postgres tiene su propia CA, que no es de confianza pública. Guarde el certificado en un archivo; tanto `psql` como el ClickPipe de la Parte 2 lo utilizan para verificar la conexión TLS:

```bash
clickhousectl cloud postgres certs get "$PG_ID" --output pg-ca.pem
```

### Cargar datos de muestra {#load-sample-data}

Cree dos tablas e inserte 1 millón de eventos con `psql`:

   event_id SERIAL PRIMARY KEY,
   event_name VARCHAR(255) NOT NULL,
   event_type VARCHAR(100),
   event_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   event_data JSONB,
   user_id INT,
   user_ip INET,
   is_active BOOLEAN DEFAULT TRUE,
   created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
   user_id SERIAL PRIMARY KEY,
   name VARCHAR(100),
   country VARCHAR(50),
   platform VARCHAR(50)
);

INSERT INTO events (event_name, event_type, event_timestamp, event_data, user_id, user_ip)
SELECT
   'Event ' || gs::text AS event_name,
   CASE
       WHEN random() < 0.5 THEN 'click'
       WHEN random() < 0.75 THEN 'view'
       WHEN random() < 0.9 THEN 'purchase'
       WHEN random() < 0.98 THEN 'signup'
       ELSE 'logout'
   END AS event_type,
   NOW() - INTERVAL '1 day' * (gs % 365) AS event_timestamp,
   jsonb_build_object('key', 'value' || gs::text, 'additional_info', 'info_' || (gs % 100)::text) AS event_data,
   GREATEST(1, LEAST(1000, FLOOR(POWER(random(), 2) * 1000) + 1)) AS user_id,
   ('192.168.1.' || ((gs % 254) + 1))::inet AS user_ip

   generate_series(1, 1000000) gs;

INSERT INTO users (name, country, platform)

    first_names[first_idx] || ' ' || last_names[last_idx] AS name,

        WHEN random() < 0.75 THEN 'Windows'

psql "$PG_URL" -c "SELECT event_type, COUNT(*) FROM events GROUP BY event_type ORDER BY 2 DESC;"

## Parte 2: Replicar en ClickHouse {#part-2-replicate}

### Crear un servicio de ClickHouse {#create-clickhouse-service}

Cree un servicio en la misma región y guarde la respuesta; la contraseña solo aparece en la respuesta de creación:

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json

CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
```

Espere hasta que esté en ejecución; ClickPipe requiere que el destino esté en ejecución:

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

Para usar un servicio existente, configure `CH_ID` con el valor de `clickhousectl cloud service list` y `CH_PASSWORD` con la contraseña del usuario `default`, que necesita el paso `pg_clickhouse`.

### Replicar las tablas en ClickHouse {#replicate-to-clickhouse}

Cree un ClickPipe de CDC de Postgres en el servicio de ClickHouse que apunte al nombre del host de ClickHouse Managed Postgres. La canalización copia las filas existentes y, a continuación, mantiene ClickHouse sincronizado con los cambios que se vayan produciendo. ClickPipes verifica de forma predeterminada el certificado del origen, así que pase con `--ca-certificate` la CA que descargó en la Parte 1:

```bash
PG_HOST=$(jq -r .hostname pg.json)
PG_PASSWORD=$(jq -r .password pg.json)

clickhousectl cloud clickpipe create postgres "$CH_ID" \
  --name quickstart-sync \
  --host "$PG_HOST" \
  --pg-database postgres \
  --username postgres \
  --password "$PG_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --table-mapping public.events:public_events \
  --table-mapping public.users:public_users \
  --json > pipe.json

PIPE_ID=$(jq -r .id pipe.json)
```

Notas:

* Las tablas replicadas se crean en la base de datos `default` del servicio de ClickHouse, con los nombres indicados por los destinos de `--table-mapping`. Pase `--destination-database <name>` para usar otra base de datos
* `--table-mapping` crea tablas `ReplacingMergeTree`. Las actualizaciones y eliminaciones llegan como nuevas versiones de fila, por lo que debe leer el estado actual con `FINAL` y `WHERE _peerdb_is_deleted = 0`, tal como hacen las consultas siguientes
* La publicación y la ranura de replicación se crean automáticamente, y la publicación se limita a las tablas asignadas; pase `--publication-name` si desea usar una publicación que administre usted mismo
* Use el nombre del host directo de Postgres; la replicación a través de PgBouncer no es compatible

### Espera a que la canalización llegue a Running {#wait-for-pipe}

La canalización pasa por `Provisioning`, `Setup` y, en el caso de tablas más grandes, `Snapshot` antes de llegar a `Running`, lo que suele tardar unos 4 minutos en el caso de la primera canalización de un servicio. `Failed` e `InternalError` son estados terminales:

```bash
while :; do
  STATE=$(clickhousectl cloud clickpipe get "$CH_ID" "$PIPE_ID" --json | jq -r .state)
  case "$STATE" in
    Running) break ;;
    Failed|InternalError) echo "ClickPipe entered terminal state: $STATE" >&2; break ;;
  esac
  sleep 15
done
```

### Consultar los datos replicados en ClickHouse {#query-clickhouse}

Ejecuta consultas SQL directamente desde la CLI en el servicio de ClickHouse. En la primera llamada, clickhousectl añade tu clave de API al endpoint de Query API del servicio y crea el endpoint si aún no existe; no se crea ninguna clave nueva. Pasa `--no-auto-enable` para que, en su lugar, la operación falle. `--format TabSeparated` imprime solo el valor, sin formato adicional, del que depende la comparación siguiente:

```bash
clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0"
```

La primera línea se envía a stderr y solo aparece cuando clickhousectl cambia el endpoint:

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
1000000
```

Las nuevas operaciones de escritura en Postgres se replican de forma continua. Inserte una fila y consulte repetidamente hasta que el recuento alcance 1.000.001 (normalmente, en menos de un minuto):

```bash
psql "$PG_URL" -c "INSERT INTO events (event_name, event_type, user_id, user_ip) VALUES ('cdc-test', 'click', 42, '10.0.0.1');"

while [ "$(clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0")" != "1000001" ]; do
  sleep 10
done
```

### Consultar ClickHouse desde Postgres {#query-clickhouse-from-postgres}

La extensión [`pg_clickhouse`](/es/products/managed-postgres/extensions/pg_clickhouse/introduction) permite que Postgres actúe como una capa de consulta unificada para datos transaccionales y analíticos. Obtén el nombre de host HTTPS de ClickHouse y, a continuación, configura la extensión con `psql`:

```bash
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol=="https") | .host')

psql "$PG_URL" <<SQL
CREATE EXTENSION pg_clickhouse;
CREATE SERVER ch FOREIGN DATA WRAPPER clickhouse_fdw
       OPTIONS(driver 'http', host '$CH_HOST', dbname 'default', port '8443');
CREATE USER MAPPING FOR CURRENT_USER SERVER ch
       OPTIONS (user 'default', password '$CH_PASSWORD');
CREATE SCHEMA organization;
IMPORT FOREIGN SCHEMA "default" FROM SERVER ch INTO organization;
SQL
```

El heredoc se deja sin comillas a propósito, para que el shell sustituya `$CH_HOST` y `$CH_PASSWORD` antes de que el SQL llegue a Postgres. Las tablas replicadas ahora aparecen como tablas externas en el esquema `organization`; las consultas contra ellas se ejecutan en ClickHouse.

Medido en `m6gd.large` con este conjunto de datos, las consultas analíticas se ejecutan entre 6 y 9 veces más rápido mediante las tablas externas (por ejemplo, un GROUP BY de 5 agregaciones: 176 ms vía ClickHouse frente a 1.133 ms localmente; un JOIN con agregaciones: 298 ms frente a 2.764 ms).

## Limpieza {#cleanup-resources}

Elimina primero el ClickPipe y luego el servicio de Postgres. Al eliminar un servicio, todos sus datos se borran de forma permanente. Un servicio de Postgres se puede eliminar aunque esté en ejecución:

```bash
clickhousectl cloud clickpipe delete "$CH_ID" "$PIPE_ID"
clickhousectl cloud postgres delete "$PG_ID"
```

No se puede eliminar directamente un servicio de ClickHouse en ejecución. `--force` lo detiene, espera a que se complete la detención y luego lo elimina:

```bash
clickhousectl cloud service delete "$CH_ID" --force
```
