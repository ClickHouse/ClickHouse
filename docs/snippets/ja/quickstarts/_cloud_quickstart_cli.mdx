このページでは、[ClickHouse CLI](/ja/concepts/features/interfaces/cli) (`clickhousectl`) を使用して、コマンドラインから ClickHouse Cloud サービスのプロビジョニング、接続、データの読み込みを行う方法を説明します。任意で使用できる `--interactive` ログインを除き、コマンドは非対話型です。`clickhousectl` は `--json` を指定すると JSON を出力します。また、コーディングエージェントから実行された場合は、自動的に JSON で出力します。

## 前提条件 {#prerequisites}

ClickHouse CLI をインストールします。

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

このスクリプトは `~/.local/bin/clickhousectl` と、その別名である `chctl` をインストールします。`~/.local/bin` が `PATH` に含まれていることを確認してください。

`jq` も必要です。

ClickHouse Cloud のアカウントが必要です。まだお持ちでない場合は、`clickhousectl cloud auth signup` を実行するとブラウザでサインアップページが開きます。

ブラウザでのログイン (`clickhousectl cloud auth login`) では読み取り専用の操作しか行えません。サービスの作成・削除や、クエリ API を使用した SQL の実行には、サービスの作成とクエリ API エンドポイントの管理が可能なロールを持つ [APIキー](/ja/products/cloud/features/admin-features/api/openapi) が必要です。各コマンドに必要なアクセス許可は、そのコマンドの `--help` で確認できます。このキーを使用してログインしてください。`--interactive` を指定するとキーとシークレットの入力を求められるため、シークレットがシェルの履歴に残りません。

```bash
clickhousectl cloud auth login --interactive
```

または、`--api-key` と `--api-secret` を指定するか、環境変数 `CLICKHOUSE_CLOUD_API_KEY` と `CLICKHOUSE_CLOUD_API_SECRET` を設定することもできます。コーディングエージェントやスクリプトから実行する場合は、環境変数を使用してください。ログイン時にはキーが検証され、そのキーに対応するアイデンティティが表示されます。現在有効な認証情報は、`clickhousectl cloud auth whoami` でいつでも確認できます。複数の組織に所属している場合は、このガイドに記載されている各 `cloud` コマンドに `--org-id <org-id>`(または `--org-name <name>`)を追加してください。

## ClickHouse サービスを作成する {#create-service}

サービスを作成してレスポンスを保存します。`default` USER のパスワードは一度しか表示されません。

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json
```

レスポンスには、サービス ID、エンドポイント、生成されたパスワードが含まれます (ここでは一部を省略しています。完全なレスポンスには、スケーリング設定、IP アクセスリスト、タグも含まれます) 。

```json
{
  "password": "dK7mPq2x_-TzrL9vNw0s",
  "service": {
    "id": "4f7b92f3-4163-403a-b538-b9bc6e2e8f66",
    "name": "quickstart-ch",
    "provider": "aws",
    "region": "us-east-1",
    "state": "provisioning",
    "endpoints": [
      {
        "host": "quickstart-abc123.us-east-1.aws.clickhouse.cloud",
        "port": 9440,
        "protocol": "nativesecure"
      },
      {
        "host": "quickstart-abc123.us-east-1.aws.clickhouse.cloud",
        "port": 8443,
        "protocol": "https"
      }
    ],
    "numReplicas": 3,
    "minReplicaMemoryGb": 16.0,
    "maxReplicaMemoryGb": 120.0
  }
}
```

このガイドの続きで必要な情報を抽出します。

```bash
CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
CH_HOST=$(jq -r '.service.endpoints[] | select(.protocol=="nativesecure") | .host' ch.json)
```

パスワードを紛失した場合は、`clickhousectl cloud service reset-password "$CH_ID"` で新しいパスワードを生成します。

`clickhousectl` で作成されたサービスでは、デフォルトで、すべてのアクセス元 (`0.0.0.0/0`) を許可する IP アクセスリストが設定されます。アクセスを制限するには、サービスの作成時に `--ip-allow` を指定してください。詳細は[&quot;IP フィルタの設定&quot;](/ja/products/cloud/guides/security/connectivity/setting-ip-filters)を参照してください。

## サービスのプロビジョニングが完了するまで待機する {#wait-for-provisioning}

プロビジョニングには約1分かかります。状態が `running` になるまでポーリングします。

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

## クエリ API で SQL を実行する {#run-sql}

`clickhousectl cloud service query` は HTTP 経由で SQL を実行します。ローカルの `clickhouse` バイナリやサービスのパスワードは必要ありません。初回の呼び出し時、clickhousectl はお使いの APIキーをサービスのクエリ API エンドポイントに追加します (エンドポイントが存在しない場合は作成します) 。新しいキーが作成されることはありません。この自動設定を行わずにエラーで終了させるには、`--no-auto-enable` を指定します：

```bash
clickhousectl cloud service query "$CH_ID" --json --query "SHOW databases"
```

以下の出力のうち 1 行目は stderr に出力されるもので、CLI がエンドポイントを切り替えた場合にのみ表示されます。

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
{"name":"INFORMATION_SCHEMA"}
{"name":"default"}
{"name":"information_schema"}
{"name":"system"}
```

出力フォーマットのデフォルトは、端末上では `PrettyCompact`、パイプ経由では `TabSeparated`、コーディングエージェントがコマンドを実行する場合は `JSONEachRow` です。上記で使用している `--json` を指定すると `JSONEachRow` が選択されます。それ以外のフォーマットを使用する場合は、代わりに `--format` を指定してください (`--json` と `--format` は併用できません) 。出力をパースするスクリプトでは、必ずどちらかを指定してください。

## データベースとテーブルを作成する {#create-database-and-table}

```bash
clickhousectl cloud service query "$CH_ID" \
  --query "CREATE DATABASE IF NOT EXISTS helloworld"

clickhousectl cloud service query "$CH_ID" \
  --query "CREATE TABLE helloworld.my_first_table (
    user_id UInt32,
    message String,
    timestamp DateTime,
    metric Float32
  ) ENGINE = MergeTree()
  PRIMARY KEY (user_id, timestamp)"
```

各コマンドは stderr に `OK` を出力します。数行を挿入します。

```bash
clickhousectl cloud service query "$CH_ID" <<'SQL'
INSERT INTO helloworld.my_first_table (user_id, message, timestamp, metric) VALUES
  (101, 'Hello, ClickHouse!', now(), -1.0),
  (102, 'Insert a lot of rows per batch', yesterday(), 1.41421),
  (102, 'Sort your data based on your commonly-used queries', today(), 2.718),
  (101, 'Granules are the smallest chunks of data read', now() + 5, 3.14159)
SQL
```

正常に動作したことを確認します。

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT * FROM helloworld.my_first_table ORDER BY timestamp"
```

```text
{"user_id":102,"message":"Insert a lot of rows per batch","timestamp":"2026-08-26 00:00:00","metric":1.41421}
{"user_id":102,"message":"Sort your data based on your commonly-used queries","timestamp":"2026-08-27 00:00:00","metric":2.718}
{"user_id":101,"message":"Hello, ClickHouse!","timestamp":"2026-08-27 10:41:28","metric":-1}
{"user_id":101,"message":"Granules are the smallest chunks of data read","timestamp":"2026-08-27 10:41:33","metric":3.14159}
```

タイムスタンプは挿入を実行した時刻に依存するため、実際の値は異なります。

## CSVファイルを読み込む {#load-csv-file}

次のテキストが、`data.csv`という名前のCSVファイルに含まれているとします。

```text title="data.csv"
102,This is data in a file,2022-02-22 10:43:28,123.45
101,It is comma-separated,2022-02-23 00:00:00,456.78
103,Use FORMAT to specify the format,2022-02-21 10:43:30,678.90
```

`INSERT ... FORMAT` はstdinからデータを読み込むため、クエリとファイルをパイプで連結します。

```bash
printf 'INSERT INTO helloworld.my_first_table FORMAT CSV\n' | cat - data.csv \
  | clickhousectl cloud service query "$CH_ID"
```

クエリ API は約30秒で応答の待機を打ち切ります。タイムアウトした `INSERT` も実際には実行されている可能性があるため、再試行する前に行数を確認してください。大きなファイルを扱う場合は、代わりに [`clickhouse client`](#native-client) を使用してください。

新しい行が取り込まれたことを確認します。

```bash
clickhousectl cloud service query "$CH_ID" --json \
  --query "SELECT count() FROM helloworld.my_first_table"
```

```text
{"count()":7}
```

## clickhouse Client で接続する {#native-client}

[**clickhouse Client**](/ja/concepts/features/interfaces/client) を使用すると、ネイティブプロトコル経由でも接続できます。ClickHouse CLI が `clickhouse` バイナリを管理するため、クライアントを別途インストールする必要はありません。

```bash
clickhousectl local use latest
```

これにより最新バージョンの ClickHouse がインストールされ、`~/.local/bin/clickhouse`へのシンボリックリンクが作成されます。`~/.local/bin`が`PATH`に含まれていれば、`clickhouse`コマンドをそのまま実行できます (含まれていない場合は、その旨がコマンドの出力に表示されます)。

次に、作成レスポンスのhostnameとパスワードを使用して接続します。`--query`を指定すると結果が出力され、Clientは終了します。指定しない場合は対話型プロンプト (`:)`) が表示され、`exit`で終了します。

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query "SELECT * FROM helloworld.my_first_table ORDER BY timestamp FORMAT TabSeparated"
```

```text
103	Use FORMAT to specify the format	2022-02-21 10:43:30	678.9
102	This is data in a file	2022-02-22 10:43:28	123.45
101	It is comma-separated	2022-02-23 00:00:00	456.78
102	Insert a lot of rows per batch	2026-08-26 00:00:00	1.41421
102	Sort your data based on your commonly-used queries	2026-08-27 00:00:00	2.718
101	Hello, ClickHouse!	2026-08-27 10:41:28	-1
101	Granules are the smallest chunks of data read	2026-08-27 10:41:33	3.14159
```

同じ形式のコマンドでファイルをアップロードできます。この方法にはクエリ API のようなタイムアウトがないため、大きなファイルのアップロードに適しています。

```bash
clickhouse client --host "$CH_HOST" --secure --port 9440 \
  --user default --password "$CH_PASSWORD" \
  --query='INSERT INTO helloworld.my_first_table FORMAT CSV' < data.csv
```

ClickHouse Cloud は挿入された同一のブロックの重複を排除するため、同じ `data.csv` を再度読み込んでも行は追加されません。

## クリーンアップ {#cleanup}

サービスを削除すると、そのすべてのデータが完全に失われます。`--force` を指定すると、実行中のサービスを先に停止し、停止が完了するまで待機します。これには数分かかる場合があります。

```bash
clickhousectl cloud service delete "$CH_ID" --force
```

データを保持したままコンピュート料金の発生を止めるには、代わりに `clickhousectl cloud service stop "$CH_ID"` でサービスを停止します。
