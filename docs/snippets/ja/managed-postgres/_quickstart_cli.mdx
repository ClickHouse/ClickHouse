このページでは、[clickhousectl](/ja/concepts/features/interfaces/cli) と `psql` を使って、ClickHouse Managed Postgres のプロビジョニング、データの読み込み、ClickHouse へのレプリケーション、クエリの実行を、すべてコマンドラインから行う方法を説明します。任意の `--interactive` ログインを除き、コマンドは非対話型です。`clickhousectl` は `--json` を指定すると JSON を出力するほか、コーディングエージェントを検出した場合にも自動的に JSON を出力します。プレーンな値を取得するには、`cloud service query` に `--format` を指定してください。

## 前提条件 {#prerequisites}

clickhousectl をインストールします。

```bash
curl -fsSL https://clickhouse.com/cli | sh
```

このスクリプトは `~/.local/bin/clickhousectl` と、その別名である `chctl` をインストールします。`~/.local/bin` が `PATH` に含まれていることを確認してください。

また、`psql`(PostgreSQLクライアントツール。macOS では `brew install libpq` でインストール可能)と `jq` も必要です。

書き込み操作(作成、削除)には [APIキー](/ja/products/cloud/features/admin-features/api/openapi) が必要です。OAuth ログイン(フラグを指定しない `clickhousectl cloud auth login`)では読み取り専用となります。APIキーを使用してログインしてください。`--interactive` を指定するとキーとシークレットの入力を求めるプロンプトが表示されるため、シークレットがシェルの履歴に残りません:

```bash
clickhousectl cloud auth login --interactive
```

または、`--api-key` と `--api-secret` を使ってキーとシークレットを `clickhousectl cloud auth login` に渡すか、環境変数 `CLICKHOUSE_CLOUD_API_KEY` と `CLICKHOUSE_CLOUD_API_SECRET` を設定します。ログイン時に認証情報が検証され、アイデンティティが表示されます。後から改めて確認するには `clickhousectl cloud auth whoami` を使用します。複数の組織に所属している場合は、各コマンドに `--org-id <id>` (または `--org-name <name>`) を追加してください。

## 第1部: Postgresを作成し、データを読み込む {#part-1-create-and-load}

### Postgresサービスを作成する {#create-postgres-service}

サービスを作成し、レスポンスを保存します。パスワードは一度しか表示されません。

```bash
clickhousectl cloud postgres create \
  --name quickstart-pg \
  --region us-east-1 \
  --size m6gd.large \
  --pg-version 18 \
  --json > pg.json
```

デフォルトのプロバイダーは AWS です。GCP はプライベートプレビュー段階です。GCP を使用するには、`--provider gcp` を指定し、あわせて GCP のリージョンとサイズを渡します (例: `--region us-central1 --size c4-standard-lssd-4`)。

アクセス用のフラグを指定しない場合、サービスは Postgres (5432) と PgBouncer (6432) で、任意の IPv4 アドレスまたは IPv6アドレスからの接続を受け付けます。アクセスを制限するには、CIDR とポート範囲の組み合わせごとに `--ip-allow` ルールを 1 つずつ指定します (例: `--ip-allow '203.0.113.0/24:5432..6432=office'`)。ルールを 1 つでも指定すると、指定したルールのみが適用されます。後からルールを変更するには、`clickhousectl cloud postgres update <postgres-id>` に `--add-ip-allow <rule>` または `--remove-ip-allow <rule-id>` を付けて実行します。ルール ID は `cloud postgres get` で一覧表示できます。

応答には、サービス ID、ホスト名、そのまま使える接続文字列が含まれます (一部省略):

このガイドの以降の手順で必要となる情報を取得します。

```bash
PG_ID=$(jq -r .id pg.json)
PG_URL="$(jq -r .connectionString pg.json | sed 's/sslmode=require/sslmode=verify-full/')&sslrootcert=pg-ca.pem"
```

`sslmode` を `verify-full` に変更して `sslrootcert` を追加すると、`psql` は後述の手順でダウンロードする CA を使ってサーバー証明書を検証します。デフォルトの `sslmode=require` では、`psql` は接続を暗号化しますが、サーバーのアイデンティティは検証しません。

パスワードを紛失した場合は、`clickhousectl cloud postgres reset-password "$PG_ID" --generate` を実行して新しいパスワードを生成してください。

### サービスの Provisioning が完了するまで待機する {#wait-for-provisioning}

Provisioning には数分かかります。状態が `running` になるまでポーリングしてください:

```bash
while [ "$(clickhousectl cloud postgres get "$PG_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

### CA 証明書をダウンロードする {#download-ca-certificate}

各 ClickHouse Managed Postgres インスタンスには独自の CA があり、この CA は公的に信頼されたものではありません。CA 証明書をファイルに保存してください。`psql` と第2部で作成する ClickPipe は、どちらもこの証明書を使用して TLS を検証します。

```bash
clickhousectl cloud postgres certs get "$PG_ID" --output pg-ca.pem
```

### サンプルデータを読み込む {#load-sample-data}

2 つのテーブルを作成し、`psql` を使って 100 万件のイベントを挿入します:

```bash
psql "$PG_URL" <<'SQL'
\timing
CREATE TABLE events (
   event_id SERIAL PRIMARY KEY,
   event_name VARCHAR(255) NOT NULL,
   event_type VARCHAR(100),
   event_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   event_data JSONB,
   user_id INT,
   user_ip INET,
   is_active BOOLEAN DEFAULT TRUE,
   created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
   updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
   user_id SERIAL PRIMARY KEY,
   name VARCHAR(100),
   country VARCHAR(50),
   platform VARCHAR(50)
);

INSERT INTO events (event_name, event_type, event_timestamp, event_data, user_id, user_ip)
SELECT
   'Event ' || gs::text AS event_name,
   CASE
       WHEN random() < 0.5 THEN 'click'
       WHEN random() < 0.75 THEN 'view'
       WHEN random() < 0.9 THEN 'purchase'
       WHEN random() < 0.98 THEN 'signup'
       ELSE 'logout'
   END AS event_type,
   NOW() - INTERVAL '1 day' * (gs % 365) AS event_timestamp,
   jsonb_build_object('key', 'value' || gs::text, 'additional_info', 'info_' || (gs % 100)::text) AS event_data,
   GREATEST(1, LEAST(1000, FLOOR(POWER(random(), 2) * 1000) + 1)) AS user_id,
   ('192.168.1.' || ((gs % 254) + 1))::inet AS user_ip
FROM
   generate_series(1, 1000000) gs;

INSERT INTO users (name, country, platform)
SELECT
    first_names[first_idx] || ' ' || last_names[last_idx] AS name,
    CASE
        WHEN random() < 0.25 THEN 'India'
        WHEN random() < 0.5 THEN 'USA'
        WHEN random() < 0.7 THEN 'Germany'
        WHEN random() < 0.85 THEN 'China'
        ELSE 'Other'
    END AS country,
    CASE
        WHEN random() < 0.2 THEN 'iOS'
        WHEN random() < 0.4 THEN 'Android'
        WHEN random() < 0.6 THEN 'Web'
        WHEN random() < 0.75 THEN 'Windows'
        WHEN random() < 0.9 THEN 'MacOS'
        ELSE 'Linux'
    END AS platform
FROM
    generate_series(1, 1000) AS seq
    CROSS JOIN LATERAL (
        SELECT
            array['Alice', 'Bob', 'Charlie', 'Diana', 'Eve', 'Frank', 'Grace', 'Hank', 'Ivy', 'Jack', 'Liam', 'Olivia', 'Noah', 'Emma', 'Sophia', 'Benjamin', 'Isabella', 'Lucas', 'Mia', 'Amelia', 'Aarav', 'Riya', 'Arjun', 'Ananya', 'Wei', 'Li', 'Huan', 'Mei', 'Hans', 'Klaus', 'Greta', 'Sofia'] AS first_names,
            array['Smith', 'Johnson', 'Williams', 'Brown', 'Jones', 'Garcia', 'Miller', 'Davis', 'Martinez', 'Taylor', 'Anderson', 'Thomas', 'Jackson', 'White', 'Harris', 'Martin', 'Thompson', 'Moore', 'Lee', 'Perez', 'Sharma', 'Patel', 'Gupta', 'Reddy', 'Zhang', 'Wang', 'Chen', 'Liu', 'Schmidt', 'Müller', 'Weber', 'Fischer'] AS last_names,
            1 + (seq % 32) AS first_idx,
            1 + ((seq / 32)::int % 32) AS last_idx
    ) AS names;
SQL
```


NVMeストレージにより、100万行の 挿入 は `m6gd.large` (最小クラスのサイズの1つ) で約20秒で完了します。クエリで確認してください。データは `random()` で生成されるため、行数は実行のたびに異なります。

```bash
psql "$PG_URL" -c "SELECT event_type, COUNT(*) FROM events GROUP BY event_type ORDER BY 2 DESC;"
```

## 第2部: ClickHouse にレプリケートする {#part-2-replicate}

### ClickHouse サービスを作成する {#create-clickhouse-service}

同じリージョンにサービスを作成し、レスポンスを保存します。パスワードは作成時のレスポンスにのみ表示されます。

```bash
clickhousectl cloud service create \
  --name quickstart-ch \
  --region us-east-1 \
  --json > ch.json

CH_ID=$(jq -r .service.id ch.json)
CH_PASSWORD=$(jq -r .password ch.json)
```

稼働状態になるまで待機してください。ClickPipe には稼働中の宛先が必要です：

```bash
while [ "$(clickhousectl cloud service get "$CH_ID" --json | jq -r .state)" != "running" ]; do
  sleep 15
done
```

代わりに既存のサービスを使用する場合は、`clickhousectl cloud service list` で取得した `CH_ID` を設定し、`CH_PASSWORD` にはその `default` ユーザーのパスワードを設定します。これは `pg_clickhouse` のステップで必要です。

### テーブルを ClickHouse に複製する {#replicate-to-clickhouse}

ClickHouse サービス上で、ClickHouse Managed Postgres のホスト名を接続先とする Postgres CDC ClickPipe を作成します。このパイプは既存の行をコピーした後、以降の変更を継続的に反映し、ClickHouse を同期された状態に保ちます。ClickPipes はデフォルトでソースの証明書を検証するため、第1部でダウンロードした CA を `--ca-certificate` で指定してください。

```bash
PG_HOST=$(jq -r .hostname pg.json)
PG_PASSWORD=$(jq -r .password pg.json)

clickhousectl cloud clickpipe create postgres "$CH_ID" \
  --name quickstart-sync \
  --host "$PG_HOST" \
  --pg-database postgres \
  --username postgres \
  --password "$PG_PASSWORD" \
  --ca-certificate pg-ca.pem \
  --table-mapping public.events:public_events \
  --table-mapping public.users:public_users \
  --json > pipe.json

PIPE_ID=$(jq -r .id pipe.json)
```

注記:

* レプリケートテーブルは ClickHouse サービス上の `default` データベースに作成され、テーブル名は `--table-mapping` で指定した移行先の名前になります。別のデータベースを使用するには `--destination-database <name>` を指定してください
* `--table-mapping` は `ReplacingMergeTree` テーブルを作成します。更新と削除は新しいバージョンの行として届くため、以下のクエリのように `FINAL` と `WHERE _peerdb_is_deleted = 0` を使用して現在のステートを読み取ってください
* パブリケーションとレプリケーションスロットは自動的に作成され、パブリケーションのスコープはマッピング対象のテーブルに限定されます。自身で管理するパブリケーションを使用するには `--publication-name` を指定してください
* Postgres のホスト名は直接接続用のものを使用してください。PgBouncer 経由のレプリケーションはサポートされていません

### パイプが`Running`になるまで待機します {#wait-for-pipe}

パイプは`Running`に到達するまでに、`Provisioning`、`Setup`、 (大きなテーブルの場合は) `Snapshot`を経由します。サービス上の最初のパイプでは、これに約4分かかります。`Failed`と`InternalError`は終端状態です:

```bash
while :; do
  STATE=$(clickhousectl cloud clickpipe get "$CH_ID" "$PIPE_ID" --json | jq -r .state)
  case "$STATE" in
    Running) break ;;
    Failed|InternalError) echo "ClickPipe entered terminal state: $STATE" >&2; break ;;
  esac
  sleep 15
done
```

### ClickHouse でレプリケートされたデータにクエリを実行する {#query-clickhouse}

CLI から ClickHouse サービスに直接 SQL を実行します。最初の呼び出し時に、clickhousectl はお使いの APIキーをサービスのクエリ API エンドポイントに追加します (エンドポイントが存在しない場合は作成します)。新しいキーは作成されません。この処理を行わずにエラーで終了させるには、`--no-auto-enable` を指定してください。`--format TabSeparated` を指定すると値のみが出力されます。以下の比較はこの出力形式を前提としています:

```bash
clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0"
```

最初の行は stderr に出力され、clickhousectl がエンドポイントを変更した場合にのみ表示されます:

```text
Binding the authenticated API key to the Query API endpoint for service 'quickstart-ch'...
1000000
```

Postgres への新しい書き込みは継続的にレプリケートされます。1 行を挿入し、件数が 1,000,001 に達するまでポーリングしてください (通常は 1 分未満です) :

```bash
psql "$PG_URL" -c "INSERT INTO events (event_name, event_type, user_id, user_ip) VALUES ('cdc-test', 'click', 42, '10.0.0.1');"

while [ "$(clickhousectl cloud service query "$CH_ID" --format TabSeparated \
  --query "SELECT count() FROM public_events FINAL WHERE _peerdb_is_deleted = 0")" != "1000001" ]; do
  sleep 10
done
```

### Postgres から ClickHouse をクエリする {#query-clickhouse-from-postgres}

[`pg_clickhouse`](/ja/products/managed-postgres/extensions/pg_clickhouse/introduction) 拡張機能を使うと、Postgres をトランザクションデータと分析データの両方に対応する統合クエリレイヤーとして利用できます。ClickHouse の HTTPS ホスト名を取得し、`psql` でこの拡張機能を設定します。

```bash
CH_HOST=$(clickhousectl cloud service get "$CH_ID" --json \
  | jq -r '.endpoints[] | select(.protocol=="https") | .host')

psql "$PG_URL" <<SQL
CREATE EXTENSION pg_clickhouse;
CREATE SERVER ch FOREIGN DATA WRAPPER clickhouse_fdw
       OPTIONS(driver 'http', host '$CH_HOST', dbname 'default', port '8443');
CREATE USER MAPPING FOR CURRENT_USER SERVER ch
       OPTIONS (user 'default', password '$CH_PASSWORD');
CREATE SCHEMA organization;
IMPORT FOREIGN SCHEMA "default" FROM SERVER ch INTO organization;
SQL
```

ヒアドキュメントは意図的にクォートしていないため、SQL が Postgres に届く前に、シェルが `$CH_HOST` と `$CH_PASSWORD` を展開します。これで、レプリケートテーブルが `organization` スキーマ内の外部テーブルとして参照できるようになり、それらに対するクエリは ClickHouse で実行されます。

このデータセットを `m6gd.large` で測定したところ、分析クエリは外部テーブル経由のほうが 6～9 倍高速でした (たとえば、5 つの集計を含む GROUP BY は ClickHouse 経由で 176 ms、ローカルでは 1,133 ms、集計を伴う JOIN は 298 ms、ローカルでは 2,764 ms) 。

## クリーンアップ {#cleanup-resources}

まず ClickPipe を削除し、次に Postgres サービスを削除します。サービスを削除すると、そのサービス内のすべてのデータが完全に削除されます。Postgres サービスは稼働中のままでも削除できます。

```bash
clickhousectl cloud clickpipe delete "$CH_ID" "$PIPE_ID"
clickhousectl cloud postgres delete "$PG_ID"
```

稼働中の ClickHouse サービス は直接削除できません。`--force` を指定すると、サービスを停止し、停止が完了するのを待ってから削除します。

```bash
clickhousectl cloud service delete "$CH_ID" --force
```
