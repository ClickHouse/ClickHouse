# Native x86 unwind validation

The x86 post-pass regenerates `.eh_frame` for the final instruction layout,
including specialized configurations and duplicated tails. The compiler uses
`-fno-omit-frame-pointer -momit-leaf-frame-pointer -fasynchronous-unwind-tables`;
the post-pass `frame` optimization stays disabled. Unsupported CFI and changed
compiler frame effects fail archive generation.

Review: https://github.com/ClickHouse/ClickHouse/pull/130343#discussion_r4514541938

## Initial unwind repair: native contracts

Validation ran on 2026-11-10 on an Intel Xeon Platinum 8175M using Clang 22.1.8.
The library commit is `86a388271b504b8a8988fd65b347c7583be7cd68`.
The final prefixed archive has SHA256
`94d2ce6b31a3d806d4d2cfc058777576a7c424858f6f6467fd9b70b349d943aa`;
the public archive has SHA256
`0ee4a15cb42850bf32638611ca130036347cc5cb4d7d38554ea751a273ee2198`.

All six actual compiler objects pass the exact code, relocation and symbol
roundtrip. Independent LLVM decoding checks 354 final FDEs and 230,802 concrete
recovery comparisons; eleven negative controls reject invalid transformations.
The same final archive passed all six configurations plus dispatched selection in the full API
test, all 200 one-slot mixes
(1,237,671,400 checks), public-entry checks, 516,364 cached-boundary calls and
publication with an earlier constructor worker.

A separate asynchronous signal test links the actual ClickHouse LLVM unwinder.
Across four configurations admitted by the original full-needs filter and seven
exercised paths per configuration,
the repaired archive recovers both the interrupted routine and the expected
standalone caller in all 2,882 observed provider samples. A same-code control
without regenerated CFI recovers neither in 2,899 provider samples. Each executable
receives 3,584 timer deliveries; deliveries outside provider code are kept separate.

## Attribution and limits

Positive attribution requires the first raw trace slot to be nonzero and inside
an actual archive-matched provider function. A provider found deeper in a stack
does not establish that it was interrupted. Leading-zero traces are retained
without provider attribution because external-object frames are stored as zero.
Runtime image identity, executable mappings, body bytes and supported linker
relaxations are checked separately.

`TraceLog::appendToBlock` stores main-executable ELF virtual addresses through
`StackTrace::resolveAddressForStorage`. The first offline analyzer incorrectly
subtracted the runtime load bias again; its rejected result is preserved.
The corrected analysis uses the same immutable 204-request capture, compares
stored PCs directly with ELF ranges and strengthens the first-slot check.
No query was rerun to obtain a favorable result.

The profile state is identified by SHA256
`f36adcadc239f10a719c7c853da1557cebde0b1b98c3176ac09f58dcc12c9a65`;
the 155-payload evidence index by
`7a4a57c315a3ad76bb15174d183866035cca5b0a6adf1af17475455a5635b9b6`;
the independently checked cleanup witness by
`1c34ee7ce6eac971caa0352889371db1f2b440456de5ec9bbc8a3933e375c218`.
Both owned servers stopped, all ten private ports were unbound and binary hashes
were unchanged. Missing profiler error counters remain unavailable, rather than
being reported as zero.

Sampling validates the observed PCs and dynamic stacks. It does not provide
every-PC runtime coverage, certify all libc contracts, establish SQL result
equivalence or isolate a performance effect. The offline CFI checks depend on
the compiler's original rules and the supported frame/control-flow model.
